# F-960363c07b32

## Purpose

F-960363c07b32 reads four 32-bit integer fields from a caller-supplied memory region and writes four 32-bit integer fields to a caller-supplied output region. On normal completion, the first two output fields are zero. The third and fourth fields are differences between selected input fields.

The apparent intent is to convert two coordinate pairs into an origin-relative representation: a zero origin followed by two extents. That interpretation is inferred, not established. The supplied evidence identifies neither a coordinate system nor any requirement that the resulting differences be positive.

This contract describes ordinary, accessible memory and arithmetic whose results are representable as signed 32-bit integers. Behavior outside those conditions is documented as uncertain rather than assigned an unsupported fallback.

## Behavior

### Source acquisition

The source reads occur in a specific order:

1. The 32-bit field at source offset `0x84` is read.
2. The field at offset `0x88` is read.
3. The field at offset `0x8C` is read.
4. The field at offset `0x80` is read as the value for the first destination write.

Consequently, all four source values have been acquired before the first destination write takes effect.

This is not evidence of an atomic four-field snapshot. For example, if another actor changes source memory between reads, the acquired values need not describe a single consistent source state. No locking, retry, or consistency check is present.

### Destination population

The function first writes the acquired source values into the destination in this order:

| Write order | Destination byte offset | Written value |
|---|---|---|
| 1 | `0x00` | A |
| 2 | `0x04` | B |
| 3 | `0x08` | C |
| 4 | `0x0C` | D |

The destination therefore temporarily contains all four original values. Those intermediate writes are part of the supplied access sequence, even though two values are subsequently replaced by zero.

### Difference calculation

After populating all four destination fields, the function updates the third destination field to its current value minus the current first field. It then updates the fourth field to its current value minus the current second field.

Under the stated ordinary-memory preconditions, these updates produce C − A and D − B, respectively.

The calculations read destination memory; they are not described solely as arithmetic on the previously acquired source values. This distinction matters for unusual memory, externally modified destinations, or environments where individual accesses have effects. Such environments are not fully specified by the supplied evidence.

Within either subtraction, the evidence does not establish which operand is read first. It does establish that the third-field update precedes the fourth-field update.

### Origin clearing

After both differences have been stored:

1. The first destination field is overwritten with zero.
2. The second destination field is overwritten with zero.

The function then returns without an explicit result value.

There is no conditional branch for negative differences, zero differences, reversed endpoints, or identical endpoints. In particular, the function does not take absolute values, swap fields, clamp values, or reject negative extents.

### Integer arithmetic

The accessed fields are 32-bit integers interpreted as signed by the supplied representation. The signed 32-bit range is −2,147,483,648 through 2,147,483,647.

Each subtraction must be considered separately. Valid input fields do not guarantee representable differences: subtracting a negative value from a large positive value can exceed the maximum, and subtracting a positive value from a large negative value can fall below the minimum.

## Side effects

The explicitly addressed output region is 16 bytes long. On the complete normal path, the supplied sequence performs eight 32-bit destination writes:

- Four writes copying the acquired source values.
- Two writes storing the differences.
- Two writes clearing the first two fields.

Each destination field is written twice. The sequence also reads destination fields as operands for the two subtractions.

No explicit write targets the source base independently of the destination. However, source storage can change if the caller supplies an overlapping destination.

All four source values are acquired before destination writes begin. Thus, under ordinary-memory assumptions and valid access semantics, overlap does not cause a later source read to consume a value overwritten by this function. This establishes a useful overlap property, not preservation of the source: overlapping destination writes can still replace the source fields.

No allocation, deallocation, ownership transfer, callback, or external function call appears in the supplied body. The function does not explicitly release either supplied region. The caller must keep the required storage accessible throughout the operation.

The write sequence is not transactional. The function contains no rollback or error-reporting path. If an access faults or execution is interrupted, the evidence provides no guarantee that destination memory remains unchanged or contains a complete result.

The listed read and write order describes the supplied access sequence. It does not establish cross-thread visibility, atomicity, memory barriers, or an exact hardware access trace after compilation.
