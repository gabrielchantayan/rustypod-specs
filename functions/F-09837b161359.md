# F-09837b161359

## Purpose

F-09837b161359 executes an ordered sequence of indirect invocations, derives 32-bit quantities from dependency results, performs interleaved memory reads and writes, and finally invokes an unresolved target with four represented arguments.

The supplied static material does not establish an application-level purpose. Character-like constants, repeated offsets, and self-referential stores do not establish text formatting, object construction, hardware initialization, or collection management.

This contract distinguishes:

- **Established static evidence:** represented data dependencies, access widths, and ordering.
- **[INFERENCE]:** interpretations requiring assumptions beyond that representation.
- **documented_only:** unresolved behavior without an executable acceptance requirement.

All behavioral requirements are conditional on execution reaching the relevant operation. No runtime tests have been performed.

## Behavior

The represented call order is significant. Calls with unused results remain potentially observable, and calls without displayed arguments are not established to lack implicit inputs. No represented error branch conditionally bypasses the remaining prefix.

### Entry into explicit memory updates

Several retained quantities organize the memory suffix:

- The **shifted base** is a retained primary result shifted left by 25 bits.
- The **scaled base** is a different retained result multiplied by 2²⁵.
- The **saved shifted value** is another retained primary result shifted left by eight bits.
- The **small value** is formed by shifting a result left eight bits, masking with 0x7FFF, and logically shifting right six bits.
- The **small base** is twice the small value.

These are descriptive contract terms, not validated pointer types.

The final prefix invocation supplies low and high 32-bit components. The suffix first stores the shifted base as a 32-bit quantity at the high component plus 0x14, then writes the high component’s low byte at the shifted base plus 9. A 32-bit store of the scaled base follows at the low component multiplied by 256, plus 0x54. The byte at the shifted base plus 9 is then overwritten with the shifted base’s low byte.

The next access group clears the scaled base plus 0x14, reads a byte at the scaled base plus 5, clears the small base plus 0x14, and publishes the zero-extended byte at the scaled base plus 0x34. Only then does it read a 32-bit quantity at the scaled base plus 0x14.

That read is not unconditionally zero: intervening accesses may alias it, and external memory behavior is unknown. Its low byte is subsequently written twice to the small base plus 0x15, after another 32-bit clear at the small base plus 0x14.

### Linked and scaled updates

A byte read from fixed address 5 is zero-extended and used as an address-bearing value. The following updates include a byte write at fixed address 1 and a byte write at the byte-derived base plus 0x15.

At the scaled base plus 0x11, the function writes the saved shifted value’s low byte, performs an intervening 32-bit store through the earlier loaded quantity at offset 0x54, and then clears that byte.

A 32-bit value is read at the byte-derived base plus 0x54 before that location is overwritten. Call the saved value the **link seed**. Subsequent operations use the link seed as both data and an address-bearing quantity.

The represented updates include these constraints:

- A read at the scaled base plus 0x74 supplies a base for later writes.
- A nested update reads the small base plus 0x74 twice: once for a destination and once for the stored value. It is not established that both reads return the same value. Their relative evaluation order within that expression is not independently resolved.
- The link seed is stored twice at its own address plus 0x24, with other stores between those publications.
- Fixed address 0x54 receives a 32-bit quantity formed by shifting the link seed left one bit.
- The small base plus 0x14 receives successive 32-bit values, including repeated stores of the link seed.
- Fixed address 0x15 receives a byte derived from the small base.
- Two-, four-, and eight-times-scaled forms participate in later addresses and stored values.

The suffix also follows byte-derived reference chains. An unsigned byte read at offset 5 becomes the base of a 32-bit read at offset 0x74; the resulting quantity is then used for writes at offset 0x44. Later, another byte read through a loaded base feeds another offset-0x74 read.

No bounds, null, or validity checks are represented for these promotions. Repeated reads at similar offsets are separate access events, not cached lookups.

### Constant writes and repeated publication

A value obtained through the later byte-derived chain supplies three destinations for 0x3A. In represented order, these are an 8-bit store through its four-times-scaled address, a 16-bit store through its eight-times-scaled address, and a 32-bit store at offset 0x20 from its four-times-scaled address.

For the following publication operations, define the **adjusted scale** as four times the link seed minus 0x96, and the **publication base** as four times that adjusted scale. These descriptions preserve represented arithmetic; they do not impose portable signed-overflow behavior.

At the publication base plus 0x20, the observable sequence is:

- A 32-bit store of 0x20.
- A 32-bit store of 0x2F.
- A byte read at the publication base plus 4, followed by a 32-bit store of its zero-extended value.
- A 32-bit store of 0x20.

**After this sequence, the function reads the global 32-bit value used as the repeated-publication base. It then stores the 32-bit value 0x20 at fixed address 0x60. The first repeated-publication store occurs only after that fixed-address store.**

The saved global-derived base is therefore obtained before the fixed-address write. Neither independence nor non-overlap of those locations is established. Moving the global read after the write changes the represented behavior if the locations overlap or access side effects matter.

Each publication group contains, in order:

1. A 32-bit store at a scaled destination plus 0x54.
2. A byte store at the saved global-derived base plus 0x19, using the publication base’s low byte.
3. A byte store at the publication base plus 0x11, using the saved global-derived base’s low byte.
4. A 32-bit store at the saved global-derived base plus 0x34.

The first group uses eight times the link seed for its scaled destination and final stored value. Later groups use eight times the adjusted scale. The first word store in each group publishes the four-times-scaled chain result used for the earlier 0x3A stores.

The global-derived base is saved, not reread for each group. Repeated writes remain separate effects even when their values match. The representation contains a finite explicit repetition, not an indefinite loop. Its exact multiplicity is documented_only in this contract rather than assigned an unverified count.

**The byte write at fixed address 0x3A precedes the last two reads.** It cannot be moved after them on an assumption of independent memory.

The offset-0x14 value is saved for the third final argument. The offset-4 value is also retained for a later store.

The next edits write low-byte projections at offsets 0x0D and 9, write byte 0x6C at the publication base plus 8, and write a self-referential 32-bit quantity at the twice-scaled chain result plus 0x54. Fixed address 0x67 then receives the low byte of the earlier fixed-address 0xA9 read.

Further writes use the newly loaded quantity, including a byte store at the publication base plus 0x10 and successive 32-bit stores at the global-derived base plus 0x54.

## Acceptance examples

These examples are conditional specification cases, not executed tests.

### Small-value arithmetic

Under 32-bit bit-vector shifts, the small value is a multiple of four from 0 through 508. The small base is a multiple of eight from 0 through 1016. Adding offset 0x14 therefore gives addresses from 20 through 1036.

Treating this calculation as an unconstrained heap pointer would not preserve the represented arithmetic.

### Width preservation

A byte store supplied 0x123456AB writes 0xAB. An unsigned byte read of 0xE1, when published as a 32-bit quantity, yields 0x000000E1.

With valid distinct destinations, the three 0x3A stores affect one, two, and four bytes. Replacing all three with byte stores violates the width contract.

### Intermediate publication

For an observable publication-base-plus-0x20 destination, the trace includes 0x20, 0x2F, the zero-extended byte read, and 0x20. Preserving only the final value does not preserve this behavior.

### Global read before fixed-address write

Suppose the global word read for publication overlaps fixed address 0x60, and its read initially yields 0x11223344. If accesses complete, the function retains that read result before storing 0x00000020 at fixed address 0x60.

The publication groups use the retained base; they do not obtain their base by rereading after the fixed-address store. This example is conditional on a mapping that supports the resulting accesses.

### Final-phase interleaving

An access observer at the beginning of the final phase must see the fixed-address 0xA9 word read, the computed offset-0x74 word read, the fixed-address 0x3A byte write, and then the offset-0x14 and publication-base-plus-4 word reads.

If the byte write overlaps either later read, that read consumes memory after the write, subject to the environment’s memory semantics. Hoisting both reads above the byte write is not equivalent.

### Dependency mutation and failure

If a prefix dependency changes a global later read by this function, that later read consumes the then-current state. Entry-state preservation cannot be assumed.

If a nested access faults, final dispatch is not guaranteed, and earlier stores are not specified to be undone.

### Final arguments

If every preceding operation succeeds, the final target receives 0x72, the terminal-base-plus-0x64 result, the saved final-phase offset-0x14 result, and the terminal-base-plus-0x74 result, in that order. No success result is established.
