# F-4ed041adc902

## Purpose

F-4ed041adc902 describes an unconditional, repeating sequence of indirect calls and memory accesses. Dependency results, incoming state, selector bytes, and a global word determine subsequent addresses, stored values, and next-iteration state.

No application-level purpose is established. In particular, the supplied representation does not establish that the addresses identify allocated objects, hardware registers, tables, queues, or valid storage.

This contract specifies the visible sequencing and data dependencies. Arithmetic consequences are conditional on the 32-bit model defined below; successful execution is not established.

### Additional consumed state

The representation also consumes:

- A 32-bit address-bearing entry value.
- An 8-bit entry value.
- An incoming control value used to derive the first indirect-call target.
- An auxiliary 32-bit result-register value consumed after an early call sequence.

The first three participate in loop-carried state. Their initial values are not established. The auxiliary value’s producer and calling-convention meaning remain unresolved.

One global 32-bit location is explicitly read during each completed iteration. Its initial contents and relationship to other accessed addresses are unknown.

### Access and arithmetic conventions

A **byte access** transfers eight bits. Byte reads used as selectors are unsigned and zero-extended. A **word access** transfers 32 bits.

A **selected-byte write using a base** means:

- Read the unsigned byte at base plus 1.
- Write one byte at the selector’s numerical value plus 17.

The destination is therefore between 17 and 272 inclusive. The original base is not added to that destination.

Unless stated otherwise, arithmetic descriptions below use 32-bit bit vectors: additions, multiplications, and left shifts retain their low 32 bits. Right shifts of unsigned values are logical. Byte stores retain only the low eight bits.

This is a conditional interpretation of the apparent machine operations. The supplied representation includes signed arithmetic and signed left shifts for which overflow or negative operands prevent a general claim of portable language-level behavior.

### Execution requirements

Uninterrupted progress requires every reached memory access to be supported and every indirect target to be callable with the actual machine state at that boundary.

No visible validation establishes those conditions. There are no explicit bounds, mapping, alignment, allocation, or dependency-success checks.

## Behavior

### Sequencing model

R1 through R26 are contract labels for selected dependency results, not implementation identifiers. Unless identified as 64-bit, they denote 32-bit results. For a 64-bit result, “low” and “high” denote its low and high 32-bit halves.

Calls described as having no explicit arguments have no argument expressions in the supplied representation. This does not establish an absence of machine-level inputs or side effects.

The phases below preserve the visible order. Intervening calls cannot be treated as pure or assumed to preserve selectors, the global location, or other shared memory.

### Entry and fourth-argument selection

Each iteration begins with a byte write of the carried entry value at the carried entry address plus 17.

The first indirect call receives the current first argument. Four further calls follow; the last produces R1.

The current fourth argument multiplied by four becomes the first selection base. A selected-byte write using this base stores zero.

A dependency then receives the fourth argument shifted left by 10. Another call supplies a 32-bit result, which is passed to a subsequent dependency together with the third argument shifted left by 28, in that order. Four further calls produce R2.

A second selected-byte write using the same base stores zero. Its selector is read again rather than retained from the first write.

### First word pair

A dependency receives R2 shifted left by two. Four calls follow before the first word write.

Define the retained first word value as R1 shifted left by 14. That value is written at R1 multiplied by \(2^{14}\), plus 20.

A dependency receives R1 shifted left by 16. After another call, a dependency receives the retained first word value shifted left by 28, followed by the unresolved auxiliary 32-bit result-register value. Under the stated bit-vector model, the first argument is zero: the two successive shifts discard all original bits.

Four further calls produce R3. The retained first word value is written at R3 multiplied by four, plus 20.

A dependency receives R3 multiplied by four. Four further calls produce R4.

### Fourth-argument byte updates and second word pair

A fresh selector read from the fourth-argument-derived base selects a byte destination. The stored byte is the low byte of

\[
((R1\ll14)\mathbin{\&}\mathtt{0x3fffffff})\gg20.
\]

The value comes from the retained computation, not from rereading either preceding word destination.

A dependency receives R1 shifted left by 26. Another supplies a 32-bit result, which is passed onward first, with R4 shifted left by 30 second.

The next dependency returns 64 bits. Its low and high halves are passed, low first, to the following dependency. Two additional calls produce R5.

A fourth selected-byte write using the fourth-argument-derived base stores zero. A dependency receives R5 shifted left by two; four calls produce R6.

The next word pair stores R6 multiplied by four:

- First at R4 multiplied by \(2^{14}\), plus 20.
- Later at R7 multiplied by four, plus 20.

Between those writes, one dependency receives four arguments, in order:

1. R4 multiplied by \(2^{12}\).
2. R4 multiplied by \(2^{12}\) again.
3. R4 shifted left by 14.
4. R6 multiplied by four.

Four subsequent calls produce R7. Only the first two positions of this four-argument call are necessarily repetitions.

### Two replicated-value word pairs

A dependency receives R9 multiplied by four; four further calls produce R10.

A dependency receives three copies of R10 multiplied by four. Four further calls produce R11. The retained word value is written at R11 multiplied by four, plus 20.

A dependency receives R11 multiplied by four; four further calls produce R12.

### Direct byte clears and derived word read

A dependency receives R12 shifted left by two. Another returns a 32-bit result, which is passed to the next dependency. Four further calls produce R13.

The two direct byte clears are repeated, again at base plus 17 before base plus 1.

A dependency receives R13 shifted left by two; four further calls produce R14.

A selected-byte write using the retained R10-derived base stores the low byte of R17 shifted left by two.

A dependency receives R17 shifted left by two. Another supplies a 32-bit value, which is passed onward first, with R17 shifted left by 30 second. Four further calls produce R18.

The next word write stores R15 shifted left by two at the **cached selector plus 20**. There is no selector reread for this word write. Changes to the selector during the intervening calls do not change that retained destination in the supplied representation.

### Global snapshot and remaining retained-base writes

Immediately after the cached-selector word write, the function reads the global 32-bit location and retains a snapshot.

A dependency receives R14 multiplied by four. Four further calls produce the 64-bit result R19. Its low half shifted left by two is retained for later address calculations.

A fresh selected-byte write using the R10-derived base stores the low byte of the global snapshot logically shifted right by 22. It uses the earlier snapshot even if an intervening dependency changed the global.

A dependency receives the high half of R19. Another supplies a 32-bit result, which is passed onward first, with the low half of R19 shifted left by 30 second. Four further calls produce R20.

Another fresh selected-byte write using the retained base stores zero.

A dependency receives R20 shifted left by two; four further calls produce R21. A dependency then receives two copies of R21 shifted left by two; four further calls produce R22.

A dependency receives the low half of R19 shifted left by 16. Four further calls produce R23.

The same retained R22-derived word is written at R23 multiplied by four, plus 20.

A dependency receives R23 multiplied by four. Four further calls produce the 64-bit result R24. Its low half shifted left by two replaces the current fourth argument.

A selector byte is then read at

\[
(\operatorname{low}(R19)\ll2)\times16384+1.
\]

At that selector plus 17, the function writes the low byte of

\[
((R22\ll2)\mathbin{\&}\mathtt{0x3fffffff})\gg20.
\]

A dependency receives the high half of R24. Another returns a 32-bit value, which is passed to the next dependency. The following dependency produces the 64-bit result R25.

The carried entry byte is set to zero. R25’s low and high halves are passed, low first, to another dependency. Two further calls produce R26. R26 shifted left by two replaces the current first argument.

The next carried entry address is obtained by reading an unsigned byte at the current fourth argument multiplied by \(2^{28}\), plus 1. Under the bit-vector model, that read address is

\[
((\operatorname{low}(R24)\mathbin{\&}3)\ll30)+1.
\]

Its possible values are **0x00000001, 0x40000001, 0x80000001, and 0xc0000001**. It is not always address 1.

The incoming control value for the first call is replaced by a fixed continuation value. Execution repeats unconditionally. The third argument remains R15 until replaced during the next iteration.

## Acceptance examples

These are conditional static consequences, not executed tests. They assume the stated arithmetic model and that preceding calls and accesses permit execution to reach the relevant operation.

1. **Selected-byte addressing.** A selector value of 7 selects byte address 24, independently of the base from which the selector was read.

2. **Fresh selector reads.** If the first fourth-argument-derived selector is 7 and the second is 9, the two zero writes target addresses 24 and 26. The first destination is not cached for the second write.

3. **Cached selector.** If the selector cached after R18 is 7, the later R15-derived word write targets address 27. An intervening selector change to 9 does not move that write.

4. **Successive-shift truncation.** The retained R1 value shifted left by 14 and then left by 28 produces a zero 32-bit argument, regardless of R1.

5. **Byte versus word width.** If R17 is 64, its left shift by two yields the 32-bit value 256. The selected-byte write stores zero, while the explicit shifted call argument remains 256.

6. **Unaligned derived access.** If the R12-derived masked offset is 1, the ordinary word read targets address 21. Success depends on the memory environment.

7. **Global snapshot.** If the global snapshot is 0x00400000 and a later dependency changes the global to zero, the snapshot-derived byte value is still 1.

8. **Final selector-read addresses.** Low halves of R24 equal to 0, 1, 2, and 3 respectively yield final read addresses 0x00000001, 0x40000001, 0x80000001, and 0xc0000001. Higher bits do not affect this address.

9. **Next entry write.** If the final selector read returns 5, the next iteration begins by writing zero at address 22, provided execution continues to that iteration.

10. **Argument repetition.** If R4 is 1 and R6 is 2, the four-argument boundary receives 4096, 4096, 16384, and 8. Four identical arguments are not required.

11. **Interrupted progress.** If an intervening dependency never returns, subsequent visible accesses do not occur. No recovery path is established.
