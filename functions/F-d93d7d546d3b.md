# F-d93d7d546d3b

## Purpose

F-d93d7d546d3b selects a four-byte result from one of two fields in a caller-supplied memory region or from an indirect dependency. Two one-byte fields control that selection.

The established selection priority is:

1. A nonzero byte at offset `0x52C` selects the four-byte value at offset `0x528`.
2. Otherwise, a nonzero byte at offset `0x51A` selects the four-byte value at offset `0x51C`.
3. If both bytes are zero, the function invokes an indirectly selected dependency and returns its result.

This is a priority selection, not a combination of results. In particular, the first nonzero flag prevents examination of the second flag.

Interpreting the fields as cached results, overrides, readiness indicators, or object properties is **inferred intent**, not established behavior. The contract therefore describes them by offset and width rather than assigning application-specific meanings.

## Behavior

### Primary selection

The first observable data read established by the supplied body is the one-byte read at offset `0x52C`.

If that byte is nonzero, the function reads the four-byte field at offset `0x528` and returns it immediately.

On this path:

- The secondary flag is not examined.
- The secondary result is not read.
- The pointer at offset `0x888` is not read.
- No indirect dependency is invoked.

The test distinguishes zero from nonzero, not zero from one. Every nonzero byte representation selects this path. Whether the byte type is signed does not affect that distinction.

### Secondary selection

If the primary flag is zero, the function next reads the one-byte field at offset `0x51A`.

If that byte is nonzero, the function reads the four-byte field at offset `0x51C` and returns it.

On this path:

- The primary result at offset `0x528` is not read.
- The indirect-dispatch pointer is not read.
- No indirect dependency is invoked.

As with the primary flag, every nonzero byte representation selects the corresponding result. The secondary flag need not equal one.

### Indirect selection

If both observed flag bytes are zero, the function resolves an indirect target:

1. It reads the pointer stored at base offset `0x888`.
2. Through that pointer, it reads the pointer stored at the beginning of the referenced object.
3. It reads the callable entry at byte offset `0x17C` from that second pointer.
4. It transfers control to that entry.

This is a pointer chain. The table is not established to reside directly at base offset `0x888`, and `0x17C` is a byte displacement rather than an entry index.

The supplied call representation shows no explicit arguments. It does not establish that the real machine-level call has no implicit receiver, register-carried context, or other calling-convention inputs.

If the dependency returns normally, its four-byte result becomes this function’s result. There is no visible result-field update, flag update, retry, or second dispatch afterward.
