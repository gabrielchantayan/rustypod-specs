# F-76e436ed0585

This contract distinguishes:

1. **Entry shift.** Under 32-bit bit-pattern interpretation, a third input of one supplies `0x04000000` to the first call; an input of 64 supplies zero.

2. **Byte truncation.** If the first byte value is 65, its four-times value is 260, but the first byte store writes `0x04`.

3. **Selector-directed destination.** A selector of `0xFF` produces destination address `0x110`, not an offset within an inferred object.

4. **Zero-byte source.** If the byte at address one is `0x20` when the zero update executes, the function writes zero at address `0x31`. No instruction-address-derived selector source is involved.

5. **Unsigned extraction.** If the second secondary value is `0xFFFFFFFF`, shifting right by 22 gives `0x3FF`; its byte store writes `0xFF`.

6. **Split result.** If the high half is three and the low half is zero, the immediate word store writes zero at address `0x20`. The later scaled-low-half store targets `0x14` and writes zero.

7. **Retained-index arguments.** Under conditional wrapping, a retained index of two gives the fifth expanded-slot call a first argument of `0x00020000` and a third argument of `0x80000000`. A retained index of four instead gives a third argument of zero.

8. **Final selector address.** Under conditional wrapping, retained indices two and eighteen both produce final selector-source address `0x20000001`. A low nibble of `0xF` produces `0xF0000001`; that address is not universal.

9. **Same address, different selectors.** If the two final reads at the common source address yield `0x10` and `0x20`, their stores target `0x21` and `0x31`, respectively. Caching the first selector would not preserve this behavior.

10. **Completion boundary.** If every preceding operation completes, the represented path reaches the bad-instruction marker. An ordinary successful return is not an established outcome.
