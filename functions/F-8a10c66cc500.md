# F-8a10c66cc500

## Purpose

F-8a10c66cc500 performs a signed-index lookup through a table obtained from F-ecd921e533b1. It returns either the selected table entry’s 32-bit value or zero.

The established selection rule is:

- Reject negative indices.
- For nonnegative indices, read a signed 32-bit bound from the returned context.
- Reject indices greater than or equal to that bound.
- Otherwise, read the table pointer and return the entry at the requested index.

This resembles access to a context-owned array whose bound is its element count. That interpretation is inferred intent. The observable behavior establishes an exclusive signed bound and a four-byte entry stride, but does not establish the table’s allocation size, element type, ownership, or lifetime.

Zero is not a distinct error indicator: a valid table entry may itself contain zero.

## Behavior

### Dependency invocation comes first

The function invokes F-ecd921e533b1 before rejecting any index, including a negative one.

Consequently, an invalid index does not bypass that dependency’s effects. If the dependency changes state, blocks, fails to return, or otherwise prevents ordinary completion, this function does not independently produce a rejection result.

Only one dependency invocation is visible.

### Negative indices

For any negative input, the function returns zero after the dependency returns.

This path performs no visible dereference of:

- The context’s bound field.
- The context’s table-address field.
- Any table entry.

Address formation associated with the context does not itself constitute a memory read. Thus, a negative index does not require readable context metadata for the accesses shown here. This does not remove any requirements imposed internally by the dependency.

### Nonnegative indices

For every nonnegative input, including zero, the function reads the signed 32-bit value at context offset 0xAC.

The acceptance condition is that the index is strictly less than this signed bound.

Accordingly:

- An index equal to the bound is rejected.
- An index greater than the bound is rejected.
- A zero bound rejects every nonnegative index.
- A negative bound also rejects every nonnegative index.
- A positive bound permits indices from zero through one less than the bound.

The comparison is signed. A bound whose high bit is set is negative; it is not treated as a large unsigned capacity.

On rejection, the result is zero. The function does not first read the table-address field.

### Accepted lookup

When a nonnegative index is strictly below the bound, the function:

1. Reads the 32-bit table address from context offset 0xA8.
2. Reads the 32-bit entry at the address selected by the index and four-byte stride.
3. Returns that entry’s bits.

There is no visible null check on the table address, no validation of the selected entry, and no secondary bound check.

In particular, the stored bound is trusted as sufficient to permit the indexed access. Passing the comparison does not prove that the backing allocation contains the requested entry.

| Path | Reads after the dependency returns |
|---|---|
| Negative index | None |
| Nonnegative rejected index | Bound |
| Accepted index | Bound, then table address, then selected entry |

The bound is read once. The table address and selected entry are each read once on the accepted path.

The bound and table address are not read as an atomic pair. No retry, consistency check, lock, or metadata revalidation is visible. Concurrent mutation could therefore affect which values are observed; the supplied material does not define a concurrent-access contract.
