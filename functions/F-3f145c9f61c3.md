# F-3f145c9f61c3

## Purpose

F-3f145c9f61c3 performs a fixed, ordered sequence of memory updates using implicit incoming machine state, a value loaded from a global cell, and several subsequently loaded addresses. It then invokes an unresolved indirect dependency with four arguments.

The supplied static evidence establishes memory accesses and data propagation, not a reliable application-level purpose. The repeated writes might represent device interaction, generated operations, or imperfect recovery of executable behavior. None of those interpretations is established.

This contract describes the visible access sequence without treating repeated writes as redundant, assuming that addressed memory is ordinary RAM, or assigning ownership semantics to stored addresses.

## Interface

### Entry state

No explicit parameters or result are declared in the supplied representation. Nevertheless, execution depends on four incoming machine-state values. This document assigns them descriptive names:

| Name | Visible use |
|---|---|
| Primary base | Unsigned 32-bit value used as an address, a doubled address operand, a stored word, and a source of low-order bytes. |
| Anchor base | 32-bit value used as an address and written into its own offset-0x40 field. |
| Secondary base | 32-bit value used as an address, a doubled address operand, and a stored word. Signed arithmetic appears in its represented calculations. |
| Initial selector | 32-bit value whose doubled value supplies an initial destination and an initial stored word. Signed arithmetic appears in its represented calculation. |

A separate global **base-source cell** supplies the **shared base**, a 32-bit address-like value. Its storage address and initialization requirements are not established here.

These descriptive names are specification notation, not recovered interface names. Their calling-convention locations and how callers establish them are unknown.

### Widths and accessed layout

The evidence distinguishes 8-bit, 16-bit, and 32-bit accesses. Offsets are byte offsets.

Relevant primary-base offsets are:

- 0x04, 0x14, 0x40, and 0x54: 32-bit reads.
- 0x20 and 0x44: 32-bit writes.
- 0x08, 0x09, 0x0D, 0x10, and 0x11: 8-bit writes.
- 0x10: also the start of a later 32-bit write, overlapping earlier byte-written locations.

Relevant secondary-base offsets are:

- 0x04, 0x14, 0x44, and 0x64: 32-bit reads.
- 0x54: multiple 32-bit writes.
- 0x01, 0x09, 0x0D, and 0x11: 8-bit writes.

Relevant shared-base offsets are:

- 0x19: repeated 8-bit writes.
- 0x34, 0x44, 0x54, and 0x74: 32-bit writes.

The anchor base has a 32-bit write at offset 0x40.

Additional addresses are formed by doubling incoming or loaded values. Others are obtained through pointer-like loads. These accesses do not establish array boundaries, object types, allocation sizes, or alignment guarantees.

### Output and completion

There is no established explicit return value. Observable results consist of:

- Memory writes and their ordering.
- Reads whose timing can matter under aliasing or device-memory semantics.
- An indirect invocation with four ordered arguments.
- A represented return if that invocation returns normally.

No status code, validation result, exception translation, or rollback mechanism is visible.

### Preconditions

For normal completion, all reached accesses must be valid under the actual execution environment, and the indirect target must be valid and callable. The visible body does not check these conditions.

The contract does not require distinct bases. Aliasing is possible and can change subsequent reads. Concrete examples below impose non-overlap only where expressly stated.

## Behavior

### Initial state establishment

Before loading the shared base, the function writes:

- The anchor-base value as a 32-bit word at anchor base plus 0x40.
- The 32-bit constant 0x20 at primary base plus 0x20.

It then reads the base-source cell once to obtain the shared base. Therefore, an earlier write that overlaps that cell can affect the shared base selected for the remainder of execution.

After that load, it writes the 32-bit constant 0x20 at absolute address 0x60.

The shared base is retained as a value; the visible body does not reload the base-source cell later.

### Repeated publication region

The repeated region uses three derived quantities:

- Twice the secondary-base value.
- The low eight bits of the primary-base value.
- The low eight bits of the shared-base value.

First, the doubled secondary-base value is written as a 32-bit word to the address obtained by doubling the initial selector and adding 0x54. The function then publishes the primary-base low byte at shared base plus 0x19, publishes the shared-base low byte at primary base plus 0x11, and writes the doubled initial selector at shared base plus 0x34.

The remaining repeated region uses the primary base instead of the initial selector for both doubled-address selection and the word published at shared base plus 0x34. Each complete repeated group has this observable order:

1. A 32-bit write of the doubled secondary-base value to twice the primary base plus 0x54.
2. An 8-bit write of the primary-base low byte to shared base plus 0x19.
3. An 8-bit write of the shared-base low byte to primary base plus 0x11.
4. A 32-bit write of twice the primary base to shared base plus 0x34.

These groups form a fixed straight-line sequence in the supplied representation. No input-dependent repetition condition or early exit is shown. The region ends after the shared-base offset-0x34 publication, not after an additional doubled-address write.

**documented_only:** This contract does not assign a verified numerical count to the repeated groups. Their exact multiplicity remains an acceptance limitation for environments where every store matters. It must not be replaced by a guessed count or assumed to be one.

### Captured state and byte publication

After the repeated region, the function captures a 32-bit value from absolute address 0xA9, followed by a 32-bit value from twice the secondary base plus 0x74.

Next, it writes one byte at absolute address 0x3A. That byte is the low eight bits of twice the primary-base low byte plus 0x30. This is arithmetic byte formation, not an established digit conversion; values outside a decimal-digit range are not rejected.

It then captures, in order:

- The 32-bit word at secondary base plus 0x14.
- The 32-bit word at primary base plus 0x04.

These captures precede the following writes:

- The primary-base low byte at secondary base plus 0x0D.
- Byte 0x6C at primary base plus 0x08.
- The shared-base low byte at primary base plus 0x0D and then plus 0x09.
- The secondary-base value as a 32-bit word at secondary base plus 0x54.
- The low byte of the captured absolute-address-0xA9 value at absolute address 0x67.

The captured values remain the argument or publication sources described below even if later writes alter their original memory locations.

### Intermediate word transfer and overlapping updates

The function next reads a 32-bit word from secondary base plus 0x44. This word becomes the **shift-source word**.

After that read, it copies the byte at absolute address 0x67 to absolute address 0x21. It then:

- Publishes the shift-source word’s low byte at primary base plus 0x10.
- Writes the complete shift-source word at shared base plus 0x54.
- Writes a byte derived by right-shifting the shift-source word to secondary base plus 0x01.
- Overwrites shared base plus 0x54 with the primary-base value.

The represented shift count is the primary-base low byte. Signed right-shift behavior and counts of 32 or greater are not fully established; see **Uncertainties**.

The function then reads a 32-bit word from primary base plus 0x40. After that read:

- The earlier captured word from primary base plus 0x04 is written at shared base plus 0x74.
- The newly read word is written at primary base plus 0x10.
- The secondary-base value is written at shared base plus 0x44.
- The current byte at absolute address 0x67 is written at primary base plus 0x09.
- The primary-base low byte is written at secondary base plus 0x09.
- The captured word from absolute address 0xA9 is written at primary base plus 0x44.

The 32-bit write beginning at primary base plus 0x10 overlaps the earlier byte writes at offsets 0x10 and 0x11. Its byte-level result depends on target byte order. It is not merely a write to an independent field.

### Loaded-address updates

The function reads the 32-bit word at primary base plus 0x54 and treats it as a **first loaded base**.

It then repeats the publication of the current byte at absolute address 0x67 to primary base plus 0x09. This is a separate read-and-write occurrence, not a guarantee that the byte still equals the value initially written to address 0x67.

Subsequent operations establish:

- The low byte of the earlier captured word from twice the secondary base plus 0x74 at first loaded base plus 0x0D.
- The earlier captured word from secondary base plus 0x14 at secondary base plus 0x54.

Only after these writes does the function read the 32-bit word at primary base plus 0x14. That captured word supplies a later byte write.

Next, it writes:

- The same captured doubled-secondary-location low byte at secondary base plus 0x11.
- The first loaded base’s low byte at primary base plus 0x09.
- The first loaded base as a 32-bit word at primary base plus 0x44.

These operations can affect subsequent reads if their destinations overlap secondary-base fields.

### Final linked-address operations and invocation

The function reads a 32-bit **second loaded base** from secondary base plus 0x04. It writes the 16-bit value 0x0065 at twice that loaded base, then reads a 32-bit **link value** from second loaded base plus 0x64.

After that link read:

- The low byte of the captured primary-base offset-0x14 word is written at first loaded base plus 0x11.
- The 32-bit value 100, hexadecimal 0x64, is written at first loaded base plus 0x54.

The function then reads, in order:

- A 32-bit **final payload** from second loaded base plus 0x74.
- A 32-bit **third loaded base** from secondary base plus 0x64.

Finally, before invoking its dependency, it writes:

- The second loaded base’s low byte at secondary base plus 0x09.
- The link value at third loaded base plus 0x54.
- The third loaded base at twice the link value.

The unresolved indirect dependency receives four arguments in this order:

| Position | Value |
|---|---|
| 1 | Constant 0x72 |
| 2 | Link value captured from second loaded base plus 0x64 |
| 3 | Word captured earlier from secondary base plus 0x14 |
| 4 | Final payload captured from second loaded base plus 0x74 |

No further explicit memory operations are shown after the invocation.

## Side effects

The function mutates caller-reachable memory, absolute-address storage, and memory reached through loaded values. It performs no visible allocation, deallocation, ownership acquisition, or ownership release.

Storing an address-like value does not establish an ownership transfer. Likewise, neither the indirect dependency’s arguments nor its invocation establish whether it retains references, releases resources, modifies globals, or returns.

Repeated stores and overwritten intermediate values remain part of the visible behavior. Collapsing them into final-state assignments is not justified for device memory, externally observed memory, or alias-sensitive execution.

The access order described here is the order in the supplied static representation. Hardware transaction widths, atomicity, memory barriers, and cross-thread visibility are not established. A represented 32-bit write is not proof of an atomic 32-bit external transaction.

Failures have no visible recovery path. If an access or invocation fails, earlier side effects are not shown being reversed.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Ordinary-memory final state

Assume all required addresses are accessible, distinct described regions do not overlap, arithmetic is valid, and the dependency returns normally.

Before the indirect invocation:

- Anchor base plus 0x40 contains the anchor-base value.
- Primary base plus 0x20 and absolute address 0x60 contain 32-bit 0x20.
- Shared base plus 0x34 contains twice the primary base.
- Shared base plus 0x54 contains the primary-base value, not the earlier shift-source word.
- Secondary base plus 0x54 contains the word captured from secondary base plus 0x14, not the temporary secondary-base self-reference.
- Primary base plus 0x44 contains the first loaded base, not the earlier captured absolute-address-0xA9 word.

These assertions concern state before the dependency; they do not constrain what it may subsequently change.

### Byte truncation

Assume the primary-base low byte is 0xF0 and the relevant accesses are valid.

The byte formed at absolute address 0x3A is 0x10: twice 0xF0 plus 0x30 is 0x210, whose low eight bits are 0x10. No range error or decimal adjustment is visible.

If the shared-base low byte is 0xAB, its early publications use byte 0xAB rather than the complete shared-base value.

### Captured argument stability

Assume the word captured from secondary base plus 0x14 is 0x12345678. A later aliasing write changes that original memory location before invocation.

The third argument remains the captured word 0x12345678. It is not reloaded at the call boundary.

### Overlapping field writes

Assume ordinary memory and no unrelated aliasing. The 32-bit write at primary base plus 0x10 replaces bytes at offsets 0x10 through 0x13, including the earlier offset-0x11 publication. Acceptance must account for that overlapping write and the target’s byte order.

### Failure before invocation

Assume the halfword destination at twice the second loaded base is inaccessible and execution faults there.

The visible sequence supplies no rollback or explicit error result. Earlier writes may remain observable, while later reads, writes, and the indirect invocation have not yet been reached.
