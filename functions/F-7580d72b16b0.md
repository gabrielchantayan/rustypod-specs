# F-7580d72b16b0

## Purpose

F-7580d72b16b0 performs an ordered preparation sequence of indirect invocations, derives address-like and data values from their results and other machine state, updates memory, and reaches a terminal indirect invocation with four represented arguments. The terminal invocation’s first argument is 0x72.

A domain-level purpose is not established. Constants that also denote characters do not establish formatting, string construction, serialization, or output emission.

This contract distinguishes:

- **Established static evidence:** represented operations, explicit value conversions, explicitly typed memory accesses, and ordering.
- **[INFERENCE]:** conclusions requiring a stated arithmetic or memory model.
- **documented_only:** unresolved behavior that is recorded but not assigned an executable requirement.

No runtime tests have been performed.

### Initial direct memory updates

The following descriptive roles identify retained values without implying object types:

- **Scaled base:** a dependency-produced signed word multiplied by 2²⁵.
- **Shifted base:** a retained lower result word shifted left by 25.
- **Small index:** another word shifted left by eight, masked to 0x7FFF, then unsigned-right-shifted by six.
- **Small base:** twice the small index.
- **Final preparation halves:** the lower and upper words of the last represented 64-bit preparation result.

**[INFERENCE]** Under 32-bit bitvector shifts, the small index is a multiple of four from 0 through 508. The small base is a multiple of eight from 0 through 1016.

The first updates comprise a word store of the shifted base at the final upper half + 0x14; a byte store of that upper half’s low-byte representation at shifted base + 9; a word store of the scaled base at 256 times the final lower half + 0x54; and a second byte store at shifted base + 9 using the shifted base’s low byte.

The following access group preserves an important read-after-write relationship:

- A zero word store at scaled base + 0x14 precedes an unsigned byte read at scaled base + 5.
- A zero word store at small base + 0x14 intervenes before the loaded byte is widened and stored as a word at scaled base + 0x34.
- The word at scaled base + 0x14 is then reloaded.
- Another zero word store at small base + 0x14 precedes two separate byte stores at small base + 0x15 using the reload’s low-byte representation.

**[INFERENCE]** In ordinary stable memory, without external or access-induced changes and with ordinary nonwrapping addressing, that reload returns zero. An overlapping zero store cannot introduce a nonzero bit into an already-zero word. The store at scaled base + 0x34 is disjoint from the word at scaled base + 0x14 under those assumptions.

This zero conclusion does not extend to device-like or externally changing memory without additional evidence.

### Link propagation and nested addressing

A word at the 0x05-derived base + 0x54 is saved before that location is overwritten. This **saved link** remains a retained read result: later writes do not implicitly refresh it.

A linked word read from scaled base + 0x74 supplies another base. The small base + 0x74 participates in a self-referential word update through two distinct reads: one supplies the destination base, the other the stored value. Their equality is not guaranteed, and their relative evaluation order within that update is unresolved.

Later nested addressing explicitly reads an unsigned byte and uses its 0–255 value as the base of a word read at offset 0x74. This bounded-base property follows from the typed byte read, not from the unrelated global read at 0x05.

The phase includes repeated self-link word stores, repeated plus-9 and plus-0x15 byte stores, and the named-global assignments at 0x54 and 0x15. Their repetitions must not be reduced to final-state descriptions when accesses are observable.

### Literal sequence and repeated publication

A nested word-derived address receives numeric 0x3A through three explicitly typed stores: a byte at its fourfold address, a halfword at its eightfold address, and a word at the fourfold address + 0x20.

The **adjusted input** is four times the saved link minus 0x96. The **adjusted base** is four times that adjusted input.

At adjusted base + 0x20, four word stores occur in order: 0x20, 0x2F, a freshly read unsigned byte from adjusted base + 4 widened to 32 bits, and 0x20 again. The byte read occurs after the 0x2F store and before the word store of its widened result.

The publication boundary has this order:

1. The complete four-store literal sequence finishes.
2. The fixed-state global is read and retained as the **state-derived base**.
3. Numeric 0x20 is assigned to the global at 0x60.
4. Repeated publication stores begin.

The fixed-state read and the 0x60 assignment have unresolved storage widths. Their represented ordering is nevertheless established. The 0x60 assignment cannot be treated as a proven 32-bit store or moved across the fixed-state read merely because its assigned value fits in 32 bits.

Each publication group contains four explicitly typed, ordered stores:

- A word at eight times the group’s scaling input + 0x54, carrying a retained fourfold nested-address value.
- A byte at state-derived base + 0x19, carrying the adjusted base’s low eight bits.
- A byte at adjusted base + 0x11, carrying the state-derived base’s low eight bits.

The first group uses the saved link as scaling input. Subsequent groups use the adjusted input.

This is finite straight-line repetition, with no intervening dependency invocation and no represented runtime loop. The exact repetition count remains **documented_only** in this contract; that limitation does not authorize collapsing the repeated accesses.

After publication, the global at 0xA9 is read once and its value retained in a 32-bit quantity. Computed-address word reads then obtain additional retained values before the named-global assignment at 0x67.

Other final effects include:

One computed-address byte store uses the result of a signed right shift whose count is the adjusted base’s low eight bits. Counts outside 0–31 and negative-operand behavior remain **documented_only**; no shift-count masking rule is established.

The assignment to the global at 0x67 explicitly converts the saved 0xA9 value to eight bits. This establishes the supplied value representation, not a byte-sized storage write.

Three distinct reads of 0x67 follow:

- The first supplies the assignment to the global at 0x21.
- The second supplies a byte store at adjusted base + 9.
- The third supplies another byte store at adjusted base + 9.

The latter two destination accesses are explicitly eight bits. Their source-global storage reads have unknown widths.

A doubled-link-base + 0x44 word read intervenes between the assignment to 0x67 and the first read. Numerous computed-address stores precede the second read. Between the second and third reads are a byte store at doubled-link base + 9, a word store of the retained 0xA9 value at adjusted base + 0x44, and a word read at adjusted base + 0x54.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Input derivatives.** With fourth argument 1 and 32-bit bitvector shifts, its seven-position derivative is 0x80 and is supplied twice to the relevant early invocation. Its 25-position derivative is 0x02000000.

2. **Discarded bits.** Under that model, a 25-position left shift followed by a seven-position left shift yields zero. An unbounded intermediate is not equivalent.

3. **Explicit byte widening.** If the typed byte read at scaled base + 5 returns 0xFE, the following word store at scaled base + 0x34 receives 0x000000FE.

4. **Unbounded 0x05-derived base.** If conversion of the global value at 0x05 produces 0x00000123, the later base is 0x123, not 0x23. This is conditional on that global value being representable under its unresolved declaration; no byte-read requirement follows.

5. **Zero reload.** In ordinary stable memory with the stated nonwrapping relationships, the scaled base + 0x14 reload returns zero. An overlapping zero store does not defeat that conclusion.

6. **Publication boundary.** A represented access trace places the final literal word store before the fixed-state read, that read before the 0x60 assignment, and that assignment before publication. It need not label the undeclared-global accesses as 32-bit transfers.

7. **Distinct 0x67 values.** If its three reads evaluate to 0x12, 0x34, and 0x56, the 0x21 assignment receives the first value; the later explicit byte destinations receive 0x34 and 0x56. This imposes no source-global read width or 0x21 storage width.

8. **Explicit truncation, unresolved extent.** If the retained 0xA9 value is 0x123456AB, the value explicitly converted for assignment to 0x67 has eight-bit representation 0xAB. The extent of that global assignment remains unresolved.

9. **Terminal retention.** Later aliasing writes do not authorize refreshing the saved third terminal argument. The first argument remains 0x72.

10. **Interrupted execution.** A faulting access does not guarantee terminal invocation or restoration of preceding effects.
