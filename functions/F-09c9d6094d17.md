# F-09c9d6094d17

## Purpose

F-09c9d6094d17 performs an unconditional repeating sequence of indirect calls, memory reads, memory writes, address calculations, and a software-breakpoint operation.

The supplied static representation establishes no normal return, explicit termination condition, or recoverable error path. Each completed iteration proceeds directly to the next. This does not establish that an iteration actually completes: an indirect call, memory access, or breakpoint may prevent further execution.

The operation’s application-level purpose is unknown. Several accesses resemble updates to structured records or indexed storage, but the evidence does not establish record types, device semantics, allocation behavior, or ownership transfer.

This contract describes the supplied representation rather than asserting that its recovered calling conventions and frame handling are complete.

## Behavior

### 1. Initial calls and first record updates

Every iteration begins by setting an internal byte value to zero. A second byte used in an early arithmetic expression is also zero.

The following order is established:

1. Invoke F-U01 with two explicit zero arguments. Its target is derived from the current continuation-address value plus `0xffe`.
2. Invoke F-U02, then F-U03.
3. Read Global A as a word-sized address.
4. Invoke F-U04.
5. Invoke F-U05 and retain its pair result.
6. Invoke F-U06 with:
   - The low word of that pair.
   - The word-sized sum of its high word, its low word, and the zero-valued byte.
7. Write one byte from a secondary output associated with F-U06 to the saved Global A address plus `0x11`.
8. Invoke F-U07.
9. Write the internal zero byte to the same saved address plus `0x15`.
10. Invoke F-U08. Write its halfword result to an address supplied through a secondary output of that call, plus `0x0c`.

Global A is read before F-U04. The two byte writes use the saved address; the representation does not reload Global A after intervening calls. A dependency may nevertheless alter Global A or the pointed-to memory.

The source of the byte written at offset `0x11` is not F-U06’s ordinary declared return value. Its precise calling-convention meaning is unknown.

### 2. Pair-derived clearing and shifted stores

Invoke F-U09 and retain its pair result. Then, in order:

1. Write a zero halfword at the pair’s high word plus `0x2c`.
2. Write the low word logically shifted right by 26 bits to the current frame-like base plus `0x26c`.
3. Establish the fixed word value `0x21c48960` for later address calculations.
4. Invoke F-U10.
5. Read a word-sized destination address from the frame-like base plus `0x320`.
6. Invoke F-U11, then F-U12.
7. Write the low word of F-U09’s result shifted left by two bits to the saved destination plus `0x54`.
8. Invoke F-U13, F-U14, F-U15, F-U16, and F-U17, in that order.

The right-shifted store can contain only values from 0 through 63. The left-shifted store discards the original top two bits. Neither operation validates whether the original low word represents an address, count, or encoded field.

The destination read at frame offset `0x320` precedes F-U11 and F-U12. Those calls are not assumed to preserve the destination memory.

### 3. Fixed-root read, indexed call, and breakpoint

Next:

2. Invoke F-U18.
3. Read a word from the current frame-like base plus `0x280`, and pass it to F-U19.
4. Retain F-U19’s word-sized result.
5. Execute a software breakpoint with immediate value `0x92`.

The breakpoint occurs after F-U19 and before all remaining operations in the iteration. The representation contains no branch around it.

If execution continues, form two word-sized quantities:

- An indexed displacement equal to F-U19’s result shifted left by two.
- A fixed displacement equal to `0x21c48960` logically shifted right by 18, then multiplied by four. This equals `0x21c4`.

Read a word-sized address from the earlier zero-extended halfword plus `0x44`. This saved address is used for several later writes.

The halfword-derived address is not automatically interpreted relative to the fixed root. Its zero-extended numeric value is itself used as the address contribution.

### 5. Frame change and record writes

1. Invoke F-U29.
2. Write the unsigned halfword obtained from F-U28’s high-word address as a zero-extended word to the saved record address from section 3 plus `0x54`.
3. Invoke F-U30.
4. Write that same zero-extended word to the saved record address plus `0x64`.

The writes at offsets `0x54` and `0x64` are separate operations with F-U30 between them. They are not an atomic paired update. The representation does not establish that F-U30 leaves either location unchanged.

### 6. Byte transfer and final call

Let the unsigned halfword read immediately before F-U28 be the **index halfword**, and the unsigned halfword read through F-U28’s high word be the **payload halfword**.

The final sequence is:

1. Invoke F-U32, then F-U33.
2. Read one byte at five times the index halfword. This is the sum of the index halfword and its fourfold product; no additional base is shown.
3. Invoke F-U34.
4. Write the byte just read to the sum of:
   - The zero-extended payload halfword.
   - The incoming register-held address contribution.
   - `0x19`.
5. Invoke F-U35.
6. Write F-U28’s high word multiplied by four to the saved record address plus `0x44`.
7. Invoke F-U36.
8. Set the continuation-address value to the represented continuation constant.
9. Read a word at F-U28’s high word multiplied by four, plus `0x44`.
10. Invoke F-U37 with that word.

The next iteration begins unconditionally if F-U37 returns.

The final word passed to F-U37 is a fresh read after F-U36. It is not necessarily the value just written to the saved record’s offset `0x44`; those addresses coincide only under additional conditions.

### 7. Repetition

Each iteration resets the internal byte used for the zero write. The byte read near the end of an iteration does not become the next iteration’s initialization value.

The continuation-address value is explicitly replaced before F-U37. Consequently, the first call of a subsequent iteration is derived from that replacement value, rather than necessarily from the original incoming continuation address.

The frame-like base is not restored anywhere in the supplied body. The representation therefore shows a repeated decrease of `0xf4` per completed iteration. Whether this reflects actual persistent stack movement or incomplete recovery of surrounding execution is unknown.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Shift boundaries.** If F-U09 supplies low word `0xffffffff`, the frame-offset `0x26c` write contains 63, and the later destination-offset `0x54` write contains `0xfffffffc`, provided execution reaches both writes.

2. **Saved Global A address.** If Global A contains address A when read, and F-U04 later changes Global A to B, the direct byte writes still target A plus `0x11` and A plus `0x15`.

3. **Halfword address interpretation.** If the first fixed-root halfword read yields `0xffff`, the subsequent record-address read is at `0x10043`. It is not at the fixed root plus `0xffff + 0x44`, and the halfword is not sign-extended.

4. **Global B truncation.** If the saved Global B address is `0x12345678` and F-U19 returns 3, the halfword write targets `0x12345684` and stores `0x5678`.

5. **Payload zero extension.** If the payload halfword is `0xffff`, the direct word writes at saved-record offsets `0x54` and `0x64` each request `0x0000ffff`, not `0xffffffff`. Intervening calls may alter the eventual observed contents.

6. **Index scaling.** If the index halfword is 7, the low word from F-U28 is written at address `0x90`, and the later source-byte read is at address `0x23`, subject to those addresses being valid.

7. **Breakpoint interruption.** If breakpoint `0x92` does not resume, no operation listed after it is reached in that iteration.

8. **Frame ordering.** For a represented frame base S on entry to the F-U28 result handling, the low-word frame store targets S plus `0x258`. The represented base subsequently becomes S minus `0xf4`.

9. **Fresh final read.** If F-U36 changes the word at four times F-U28’s high word plus `0x44`, F-U37 receives the value read after that change, assuming no other interference.
