# F-8a6756c94146

## Purpose

F-8a6756c94146 converts a byte-counted sequence of 16-bit input units into a variable-length byte representation, optionally replacing each input unit with the result of dependency F-0ec8efa9c769.

The emitted representation resembles UTF-8 for nonzero values in the 16-bit range, but it is not a general Unicode-to-UTF-8 conversion contract:

- Zero is encoded as two bytes, `C0 80`, rather than as a single zero byte.
- Each input unit is handled independently. There is no surrogate-pair recognition or combination.
- Values returned by the dependency are treated as unsigned 32-bit values and can exceed the 16-bit input range. Even those values use at most three output bytes, with truncation described below.
- Surrogate values are not rejected.

The function stops after all counted input units have been processed or before an encoded unit that will not fit. It reports the number of payload bytes produced and, unless disabled by a flag, appends a zero byte.

These are established properties of the supplied static representation. The intended character set, public API meaning, and behavior of the dependency are not established.

## Interface

| Position | Input | Established interpretation |
|---|---|---|
| 1 | Input pointer | Pointer to 16-bit unsigned units. |
| 2 | Input extent | Unsigned 32-bit byte count. The number of units considered is this value divided by two, rounding down. |
| 3 | Output pointer | Pointer to the first byte of writable output storage. |
| 4 | Output-count pointer | Pointer to a writable 32-bit signed-integer object receiving the payload byte count. |
| 5 | Output extent | Signed 32-bit value used in computing the output boundary. |
| 6 | Opaque value | A 32-bit argument with no visible use. |
| 7 | Flags | Unsigned 32-bit value controlling dependency invocation and termination. |

The flag meanings established by the body are:

| Flag bit | Clear | Set |
|---|---|---|
| Bit 0 | Encode the directly read 16-bit input value. | Invoke F-0ec8efa9c769 for each attempted unit and encode its 32-bit result instead. |
| Bit 1 | Reserve one output byte for a trailing zero and write that zero at finalization. | Do not reserve or write a trailing zero. |

The return value is:

- `0` when all counted units have been processed.
- `63`, hexadecimal `0x3F`, when the next encoded unit does not fit.

There is no separate return status for malformed text, surrogate values, unsupported code points, odd input byte counts, or dependency-produced values outside the Unicode range.

The function performs no visible pointer, alignment, extent, or overlap validation.

For ordinary bounded-buffer use:

- The input pointer must support the 16-bit reads that execution reaches.
- The output-count pointer must support a 32-bit store.

## Behavior

### Input extent and initial boundary

The function derives the number of input units by shifting the unsigned input extent right by one bit. Consequently:

- Extents `0` and `1` both specify no units.
- An odd extent ignores its final unmatched byte.
- The largest possible unit count is `2,147,483,647`.

The derived count cannot initially have its sign bit set. Although the loop’s exhaustion check is expressed as a signed comparison, every nonzero initial count is positive under that interpretation.

The output cursor initially points to the start of the output buffer.

When termination is disabled, the payload boundary is the output pointer plus the output extent. When termination is enabled, the payload boundary is one byte earlier. For normal nonnegative extents, this reserves space for the trailing zero.

The initial return status is zero.

### Per-unit read and dependency order

For each unit that the loop attempts, the visible order is:

1. Read a 16-bit unsigned value from the current input position.
2. If flag bit 0 is set, invoke F-0ec8efa9c769 and replace the working value with its unsigned 32-bit result.
3. Determine the encoded width from that working value.
4. Check whether the entire encoded unit fits.
5. If it fits, write its bytes, advance the output cursor, and advance the input position by one 16-bit unit.

Thus the source read occurs before the capacity decision. With bit 0 set, the dependency invocation also occurs before that decision. A unit that ultimately fails for lack of output space can therefore cause both an input read and a dependency invocation.

No dependency invocation occurs when the counted input is empty.

The supplied representation shows no explicit argument passed to F-0ec8efa9c769. It does not establish whether an underlying calling convention or hidden state supplies information to that dependency.

### Encoding rules

The working value is unsigned and 32 bits wide.

**Values from 1 through 127**

Emit one byte equal to the value.

**Zero, and values from 128 through 2,047**

Emit two bytes:

- First byte: the low eight bits of the value shifted right by six, combined with `C0` by bitwise OR.
- Second byte: the value’s low six bits, combined with `80` by bitwise OR.

For this branch’s actual value range, those operations produce the familiar two-byte pattern, except that zero becomes the overlong sequence `C0 80`.

**Values from 2,048 through 4,294,967,295**

Emit three bytes:

- First byte: the low eight bits of the value shifted right by twelve, combined with `E0` by bitwise OR.
- Second byte: bits 6–11 of the value, combined with `80` by bitwise OR.
- Third byte: bits 0–5 of the value, combined with `80` by bitwise OR.

For values no greater than `FFFF`, this produces the usual three-byte bit pattern, including patterns representing surrogate code units.

For larger dependency results, it is not a valid general-purpose UTF-8 encoding rule. The first byte retains only the low eight bits of the shifted value before the OR operation. Bits above bit 19 do not contribute to emitted byte contents. They can nevertheless affect branch selection because the width decision examines the full 32-bit value.

There is no four-byte encoding branch.

### Capacity checks and partial completion

Capacity is checked separately for each encoded unit. The function never deliberately writes only part of an encoded unit because that unit does not fit.

For ordinary valid buffer geometry, the unit fits exactly when the remaining payload capacity is at least its encoded width:

- One byte for nonzero values below `80`.
- Two bytes for zero and values from `80` through `7FF`.
- Three bytes for values at least `800`.

If the next unit will not fit:

- The status becomes `63`.
- No byte of that unit is written.
- No later input unit is attempted.
- Previously written payload remains in place.
- Finalization still occurs.

A successful capacity check is followed by individual byte stores, not an atomic multi-byte update. Concurrent observers or aliased memory could observe intermediate stores.

### Finalization

Both exhaustion and capacity failure use the same finalization sequence:

1. Store the number of payload bytes produced through the output-count pointer.
2. If termination is enabled, store a zero byte at the current output cursor.
3. Return the status.

The count excludes the trailing zero.

The count store occurs before the trailing-zero store. If those destinations overlap, the trailing-zero store can modify the count representation after it has been written.

There is no input-consumed output parameter. The byte count alone does not necessarily identify how many source units were processed.

## Side effects

### Direct memory effects

The body visibly performs:

- One 16-bit input read per attempted unit.
- Payload-byte writes for completed units.
- One 32-bit output-count store on every normal return path.
- One trailing-zero byte store when flag bit 1 is clear.

For a two-byte encoding, stores occur in output order: first byte, then second byte. For a three-byte encoding, stores occur first byte, second byte, then third byte.

The output-count object is not visibly updated incrementally.

With empty input, the body performs no input read and no dependency call, but it still writes the count and, when enabled, the trailing zero.

### Aliasing and mutation

No overlap handling or source snapshot is visible.

If output writes overlap unread input, later input reads can observe modified data. A capacity failure can also follow a dependency call that has changed memory or other state. The final count store can overwrite source or output memory if the caller aliases those regions.

The direct encoding body shows no allocation, deallocation, or ownership transfer. That observation does not establish the memory behavior of F-0ec8efa9c769.

### Global and external state

The visible body contains no explicit global-memory access. With flag bit 0 set, the dependency’s global and external effects are unknown. The contract does not assume that it preserves globals, preserves pointed-to storage, or refrains from acquiring or releasing resources.

## Acceptance examples

These examples are conditional static acceptance criteria, not observed runtime results. Unless stated otherwise, all memory is valid and nonoverlapping, address arithmetic is ordinary, and flag bit 0 is clear.

### Empty input with termination

Given an input extent of `0`, output extent `1`, and flags `0`:

- Return `0`.
- Store output count `0`.
- Write one zero byte at the output start.
- Perform no input read.

An input extent of `1` has the same result because it specifies zero complete 16-bit units.

### Single-byte value at exact capacity

Given one input unit `0041`, input extent `2`, output extent `2`, and flags `0`:

- Emit `41 00`.
- Report payload count `1`.
- Return `0`.

With output extent `1` instead:

- Emit only the trailing `00`.
- Report payload count `0`.
- Return `63`.

The source unit is read before the insufficient-capacity result.

### Termination disabled

Given one input unit `0041`, input extent `2`, output extent `1`, and flags `2`:

- Emit `41`.
- Report count `1`.
- Return `0`.
- Do not write a trailing zero.

### Zero input unit

Given one input unit `0000`, input extent `2`, output extent `3`, and flags `0`:

- Emit `C0 80 00`.
- Report payload count `2`.
- Return `0`.

The zero input unit does not terminate processing.

### Width boundaries

With sufficient capacity and termination disabled:

| Input unit | Payload |
|---|---|
| `007F` | `7F` |
| `0080` | `C2 80` |
| `07FF` | `DF BF` |
| `0800` | `E0 A0 80` |

### Capacity failure after a prefix

Given input units `0041, 0800`, input extent `4`, output extent `4`, and flags `0`:

- Emit payload `41`.
- Reject the three-byte encoding of the second unit because only two payload bytes remain.
- Write the trailing zero immediately after `41`.
- Report payload count `1`.
- Return `63`.

Unused bytes beyond that trailing zero are not written by this path.

### Odd input extent

Given input extent `3`, only the first 16-bit unit is considered. The unmatched third byte is not independently encoded or validated.

### Dependency result outside the 16-bit range

With bit 0 set, if F-0ec8efa9c769 returns `00010000` and enough capacity is available:

- Emit `F0 80 80`.
- Consume one counted input unit after writing those bytes.
- Do not emit a fourth byte.

This illustrates truncating three-byte construction, not valid UTF-8 for that value.

### Dependency call despite insufficient space

Given one counted input unit, flags `3`, and output extent `0`, with otherwise valid memory:

- Read the input unit.
- Invoke F-0ec8efa9c769.
- Reject the resulting encoding for insufficient capacity.
- Store count `0`.
- Return `63`.
- Write no trailing zero.
