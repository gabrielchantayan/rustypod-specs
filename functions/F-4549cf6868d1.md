# F-4549cf6868d1

## Purpose

F-4549cf6868d1 obtains a descriptor through a dependency, selects a five-byte record using a caller-supplied integer and a dependency-provided reference value, and copies the record’s first byte to caller-provided storage. If optional result storage is supplied, it also obtains a four-byte value from a dependency given the address immediately following that byte.

After processing the record, the function invokes a descriptor-finalization dependency and classifies the byte currently in the caller’s byte-output storage. It returns zero when that byte is in the inclusive range 0–5, and decimal 11 otherwise. If descriptor lookup returns a nonzero status, the function instead returns that status without entering the record-processing path.

These are established static behaviors. The meanings of the record byte, optional four-byte value, caller integer, and descriptor are not established. Describing the records as entries in a table is a structural interpretation, not an established domain meaning.

## Interface

The supplied representation exposes four inputs and an integer return value:

| Input | Representation | Role established by the visible operations |
|---|---|---|
| Context storage | Pointer to four-byte words | Its first four-byte word is passed to descriptor lookup. The pointer itself is later passed to the reference-value dependency. |
| Requested position | 32-bit integer | Participates in the record-displacement calculation and is passed to the reference-value dependency. |
| Byte-output storage | Pointer to an unsigned eight-bit byte | Receives the selected record’s first byte on successful descriptor lookup. Its contents are read again after descriptor finalization to determine the return status. |
| Optional word-output storage | Pointer to four-byte words, or null | Its pointer value initially seeds a descriptor-pointer slot passed to lookup. If non-null, its first four-byte word later receives the optional dependency result. |

The return value is represented as a 32-bit integer:

- A nonzero lookup status is propagated unchanged.
- After successful lookup and completion of the subsequent operations, the return value is either zero or decimal 11.

The four-byte values passed through this function are opaque. The visible operations do not establish whether they represent integers, addresses, handles, or other encoded values.

### Storage requirements

The function performs no visible null, bounds, alignment, or lifetime validation.

For an execution to complete safely:

- Byte-output storage must support a one-byte write and the later one-byte read on the successful-lookup path.
- If optional word-output storage is non-null, it must support a four-byte write when that path is reached.

## Behavior

### 1. Seed the descriptor-pointer slot

The function creates a mutable pointer slot whose initial value is exactly the optional word-output pointer, including null if null was supplied.

This initialization does not read the contents of optional word-output storage. The pointer value itself becomes an input to lookup through the address of the mutable slot.

Consequently, the optional pointer has two distinct roles:

1. It supplies the initial descriptor-slot value.
2. If non-null, it identifies the destination for the optional four-byte result.

The visible function does not explain why these roles share one argument.

### 2. Obtain the lookup selector

The function calls F-c76bdec3f9e1 with no explicit arguments and retains its four-byte result.

This call precedes the visible read of the first context word. Therefore, the lookup receives the context word as read after this dependency returns. No guarantee that the dependency preserves relevant shared state is established.

### 3. Perform descriptor lookup

The function reads the first four-byte context word and calls F-133a6620fb39 with:

1. That context word.
2. The selector returned by the preceding dependency call.
3. The address of the mutable descriptor-pointer slot.
4. An integer zero.

Lookup can modify the pointer slot.

If lookup returns a nonzero status, F-4549cf6868d1 returns that status immediately. On this branch, the enclosing function performs no record read, byte-output write, optional-result call, optional-word write, or descriptor-finalization call.

This does not establish that lookup leaves caller storage or global state unchanged. Its effects are unknown.

### 4. Read the record-storage address

If lookup returns zero, the function reads descriptor word index 13 from the descriptor pointer then held in the mutable slot.

With four-byte words, this read starts at byte offset 52 from the descriptor address. The word is subsequently used as the base address for record access.

The visible code does not check whether the descriptor is non-null or whether this word denotes valid record storage. Lookup success is therefore insufficient, by itself, to establish memory safety without the lookup dependency’s contract.

### 5. Obtain the reference value and calculate the displacement

The function calls F-c76bdec3f9e1 again, this time with:

1. The context-storage pointer.
2. The requested position.

The second result is treated as a 32-bit integer reference value.

For values whose intermediate arithmetic is representable, the byte displacement is:

\[
d = 5 \times (\text{requested position} - \text{reference value} - 1)
\]

The selected record address is the previously read record-storage base plus this displacement.

This establishes a five-byte stride. It does not establish a record count, a valid position range, or the meanings of the five bytes.

For example, where arithmetic and memory access remain valid:

- Requested position equal to reference value plus one selects displacement zero.
- Requested position equal to reference value plus two selects displacement five.
- Requested position equal to reference value selects displacement negative five.

No check rejects negative displacements or positions beyond the available records.

The record-storage base is read before the second dependency call. The function does not visibly reload descriptor word 13 afterward. If that dependency changes the descriptor field, the previously obtained base remains the value used by the visible calculation.

### 6. Write the selected byte

The function reads one unsigned byte at the selected record address and writes it to byte-output storage.

This write occurs before optional-result processing and before descriptor finalization. The byte is not validated before being exposed to the caller’s storage.

### 7. Produce the optional four-byte result

If the original optional word-output pointer is non-null, the function calls F-d1e995cfb2d3 with the selected record address plus one byte.

It writes the dependency’s four-byte return value into the first word of optional word-output storage.

The visible behavior does not establish that the dependency merely loads the next four record bytes. It may interpret or access memory differently according to its own contract. No endianness, decoding rule, ownership transfer, or allocation behavior is established here.

If the optional pointer is null, this dependency call and the four-byte output write are both skipped.

### 8. Finalize the descriptor

The function calls F-44d249c54e70 with the descriptor pointer held in the mutable slot.

The call occurs after the selected byte has been written and, when requested, after the optional word has been written. Its result is not used to select the enclosing function’s return status.

This is a finalization-shaped call, but the visible evidence does not establish whether it frees memory, decrements a reference count, unlocks an object, or performs another operation.

### 9. Classify the current output byte

After finalization returns, the function reads byte-output storage again.

Under the integer types shown, the byte is promoted to an integer before subtracting one. The condition is that this difference is less than five. Because an unsigned eight-bit byte has values 0–255, the accepted values are exactly:

\[
0 \leq \text{current output byte} \leq 5
\]

In particular, zero is accepted: its promoted value minus one is negative one, which is less than five. The condition is not a 1–5-only check.

The function returns:

- Zero for current output-byte values 0–5.
- Decimal 11 for current output-byte values 6–255.

The decision uses the byte reread after finalization, not a preserved copy of the byte originally fetched from the record.

## Side effects

The successful-lookup path has the following visible sequence:

1. Read descriptor word 13.
2. Call the reference-value dependency.
3. Read the selected record byte.
4. Write byte-output storage.
5. If optional storage is non-null, call the optional-value dependency.
6. If optional storage is non-null, write the optional four-byte result.
7. Call descriptor finalization.
8. Read byte-output storage again.
9. Return the classified status.

There is no rollback of either output when the final status is 11.

The function does not visibly allocate memory. It also does not establish ownership of the descriptor, the record storage, or any object represented by the optional output value. A call resembling release is not sufficient evidence of an ownership contract.

### Aliasing

No visible check requires the input and output regions to be disjoint.

Aliasing can make the write order observable. For example, if byte-output storage overlaps optional word-output storage, the later four-byte write can replace the byte used for final classification. The result then depends on the byte present after that write and after finalization, rather than solely on the original record byte.

Likewise, output writes may affect descriptor or record storage if those regions overlap. The function does not reload the record base after its initial descriptor-field read, but dependencies may access overlapping storage independently.

Aliasing is not guaranteed to be valid: alignment, lifetime, and dependency constraints remain unknown.

## Acceptance examples

The following are conditional acceptance examples, not executed tests. They assume valid accesses, defined arithmetic, and dependency behavior as specified in each example.

1. **Lookup failure is propagated.**  
   If F-133a6620fb39 returns a nonzero status, the function returns that same status. No subsequent dependency is called by this function, and this function performs no output write.

2. **The first record is selected relative to the reference value.**  
   If the requested position is 21 and the reference-value result is 20, displacement is zero. With a selected byte of 3, null optional output, and no later modification of byte-output storage, the output byte becomes 3 and the return value is zero.

3. **Zero is accepted.**  
   If the selected record byte is zero and remains zero through finalization, the function returns zero.

4. **The upper accepted boundary is five.**  
   A final output byte of 5 produces zero. A final output byte of 6 produces decimal 11.

5. **Invalid classification does not undo outputs.**  
   If the selected byte is 200 and the optional dependency returns an opaque four-byte value, both outputs are written before finalization. If the byte remains 200 afterward, the return value is 11 and those writes are not rolled back.

6. **Negative displacement is not rejected locally.**  
   If the requested position equals the reference value, the selected address is five bytes before the record-storage base. If that access is valid under the surrounding storage contract, processing continues normally. Otherwise, this function supplies no defined bounds-error return.

7. **Final classification observes later changes.**  
   If the selected byte is 2 but an intervening permitted write changes byte-output storage to 9 before the final read, the function returns 11. Conversely, a selected byte of 9 followed by a change to 2 produces zero.

8. **Null optional output skips only optional-result production.**  
   Null optional storage seeds the descriptor slot with null and suppresses the optional-value call and word write. It does not suppress lookup, the selected-byte write, descriptor finalization, or final classification when lookup succeeds.
