# F-289a082c628b

## Purpose

F-289a082c628b conditionally reads a two-word prefix from a caller-supplied memory region. It checks a preliminary dependency result, recognizes the first word against two external comparison values, exposes a selector derived from that recognition, and transforms the second word through another dependency.

The function returns a 32-bit status value. Rejection is not transactional: some failure paths leave the cursor, consumed-byte count, and selector partially updated.

**Established static evidence:** The function checks an address, invokes a preliminary dependency, reads up to two 32-bit words, updates caller-provided output storage, and optionally invokes a transformation dependency.

**Inferred intent:** The two recognized first-word values may distinguish input formats or byte orders. Neither interpretation is established. The selector is therefore described only by its observable comparison rule.

## Behavior

### 1. Input-address gate

The function first checks that the input address is nonzero and that its low two address bits are zero.

If either check fails:

- It returns **1**.
- It does not invoke either dependency.
- It performs no explicit access to the input words or output slots.

No length or output-pointer validation precedes this return.

### 2. Preliminary dependency gate

For a nonnull, four-byte-aligned input address, the function calls F-1cb585febd84 with the opaque second argument.

Its result is interpreted as an unsigned 32-bit value and compared with 512:

- Values from 0 through 512 permit further processing.
- Values greater than 512 cause an immediate return of **6**.

The function itself has not initialized its output slots before this call or before the return of 6. This does **not** establish that caller-visible state is unchanged: F-1cb585febd84 may have side effects that are not described by the available evidence.

### 3. Initialization and first-word admission

After an accepted preliminary result, the function writes:

1. Zero to the consumed-count slot.
2. The input address to the cursor slot.

It then reads the consumed-count slot and tests whether its value plus four is less than or equal to the signed available byte count.

For ordinary nonoverlapping storage, this is the test **4 ≤ available byte count**. If the comparison fails, the function returns **1**, leaving the initialized cursor and count in place.

If the comparison passes, the function:

1. Reads a signed 32-bit word directly from the original input address.
2. Writes the address four bytes beyond the original input address to the cursor slot.
3. Reads the current consumed count, adds four, and writes the result back.

The first input read uses the original input argument, not the stored cursor. Its value is retained for the subsequent comparisons.

Under the ordinary storage assumptions, the cursor now points to the second word and the consumed count is four.

### 4. Recognition and selector publication

The first word is compared with two external 32-bit comparison values, designated here as **comparison value A** and **comparison value B**.

Recognition evaluates the comparison with A first. The comparison with B is needed only if the comparison with A fails.

If neither comparison succeeds:

- The function returns **1**.
- The selector and result slots have not been explicitly written by this function.
- The first-word cursor and count updates remain visible.

If either comparison succeeds, the function writes the selector:

- **1** if a subsequent comparison of the retained first word with comparison value A succeeds.
- **0** otherwise.

The selector computation uses another reference to comparison value A; the evidence does not establish that the earlier value is cached or that the external comparison storage cannot change.

When both comparison values are stable and equal, a matching first word produces selector 1. The behavior does not require the two comparison values to be distinct.

### 5. Second-word admission and publication

Only after writing the selector does the function test whether the current consumed count plus four is less than or equal to the available byte count.

For ordinary nonoverlapping storage, the consumed count is four, so this is the test **8 ≤ available byte count**.

If the comparison fails, the function returns **1**. The selector remains published despite failure, and the result slot has not been explicitly written.

If the comparison passes, the function performs these effects in order:

1. Reads a 32-bit word from the address currently stored in the cursor slot.
2. Writes that raw word to the result slot.
3. Increments the address currently stored in the cursor slot by four and writes it back.
4. Increments the current consumed count by four and writes it back.

For distinct storage, the raw word comes from input bytes four through seven, the cursor becomes the input address plus eight, and the count becomes eight.

The reads are native 32-bit memory accesses. No byte assembly or explicit byte-order conversion is visible before the transformation dependency.

### 6. Transformation and success

The function calls F-4e1ee8e86ebb with:

- The selector currently stored in the selector slot.
- The value currently stored in the result slot.

The relative evaluation order of these two argument reads is not established.

After the dependency returns, the function writes its 32-bit return value to the result slot and returns **0**. It does not interpret the dependency’s result as an error code or perform another validation step.

The result slot therefore has two distinct writes on this path: the raw second word before the call, and the dependency result afterward. The dependency call occurs after the cursor and consumed-count advances.

### Arithmetic and aliasing boundaries

With distinct output slots, the consumed count progresses through zero, four, and eight. Its additions do not overflow, and negative available counts fail the first admission test.

Cursor storage is unsigned 32-bit. The second cursor increment uses unsigned addition by four. The first cursor advance is expressed as advancing the original word pointer by one element. Valid backing storage and valid address arithmetic are preconditions; the evidence does not justify treating a boundary-crossing pointer as a readable wrapped address.

Overlapping outputs can invalidate the ordinary progression. For example, the cursor initialization occurs after the count initialization, so overlap between those slots can replace the zero before the first length comparison. Overlap with input can change a word before it is read. Later count arithmetic also rereads caller storage rather than relying on a private zero/four/eight progression.

Signed overflow caused by such interference is **documented_only**: no portable overflow outcome is established.

## Side effects

The function’s explicit writes are path-dependent:

| Path | Explicit writes by this function |
|---|---|
| Null or misaligned input address | None |
| Preliminary result greater than 512 | None |
| First-word admission fails | Count initialization, then cursor initialization |
| Unrecognized first word | Initialization, then first-word cursor and count updates |
| Recognized first word, second-word admission fails | All preceding updates, then selector |

This table excludes dependency side effects and assumes execution completes the listed accesses without a fault.

There is no rollback. In particular:

- Status 1 does not imply unchanged outputs.

- The raw second word is stored before transformation.
- The function does not restore cursor, count, or selector after F-4e1ee8e86ebb returns.

Dependencies must not be assumed to preserve external comparison storage or caller-visible memory. No synchronization, atomic publication, or concurrent-access guarantee is established.
