# F-b8ef0b052653

## Purpose

The established behavior has two mutually exclusive paths:

- When the record’s first word is nonzero, invoke F-0686209af311, then, if that invocation returns, invoke F-feee9156a257. The supplied static representation identifies the latter invocation as non-returning.
- When the first word is zero, explicitly store zero to that word, collect the values needed for subsequent calls, invoke four dependencies in sequence, and return without a result value.

## Behavior

### Nonzero-entry path

The first operation is a four-byte read of the guard word.

If its value is nonzero:

1. Invoke F-0686209af311 with no explicit arguments.
2. If that invocation returns normally, invoke F-feee9156a257 with no explicit arguments.

The supplied static representation marks F-feee9156a257 as non-returning. Consequently, ordinary return from F-b8ef0b052653 is not established for this branch.

Before those calls, this function does not explicitly clear the guard, read the record’s context address, read the separate global value, traverse the linked storage, or invoke the four dependencies used by the zero-entry path.

The guard is not rechecked between the two calls. A change to the guard by F-0686209af311 does not alter the represented decision to call F-feee9156a257 if the first call returns.

The effects of either dependency remain unknown. “No explicit write by this function” does not mean that the input record or global state remains unchanged across these calls.

### Zero-entry path

If the initial guard value is zero, the following explicit accesses and calls occur in order, provided each preceding operation completes:

1. Store a four-byte zero to the guard word. This store occurs even though the tested value was already zero.
2. Read and retain the separate four-byte global value.
3. Read and retain the context address from record offset 4.
4. Read the first linked address at context offset 16.
5. Read the second linked address at offset 12 from the first linked address.
6. Read and retain the four-byte payload at offset 28 from the second linked address.
7. Invoke F-a66a9be680df with no explicit arguments.
8. Invoke F-c5a232e4455b with two arguments: the preceding call’s returned value, followed by the numeric constant 12.
9. Invoke F-afb630a7107c with five arguments: the preceding call’s returned value, the captured global value, zero, zero, and zero.
10. Invoke F-9a5c97dc580d with five arguments: the preceding call’s returned value, the captured context address, zero, the captured payload value, and zero.
11. Return without an explicit result.

The capture order is significant. Both the global value and the linked payload are read before F-a66a9be680df is invoked. The context address is also captured before that call. No explicit reread of these values appears after dependency execution begins.

Thus, if a dependency changes the global storage, the original record’s context field, or the linked payload storage, the later arguments remain the already captured values. This does not establish that memory reachable through those values is immutable or remains valid.
