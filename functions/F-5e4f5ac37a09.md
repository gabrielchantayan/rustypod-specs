# F-5e4f5ac37a09

## Purpose

The established behavior is an ordered sequence of unresolved dependency invocations, computed memory reads, and byte or 32-bit writes. The supplied representation does not establish an application-level purpose.

This contract describes the visible sequence, including calls whose results are discarded. It does not establish normal completion, an intended final object state, or a meaningful return value. The representation reports invalid instruction data and terminates at a truncated control-flow boundary.

All behavior below is conditional on the represented operations accurately describing executable behavior. No runtime tests have been performed.

2. As a scaled word-store destination and then a dependency argument.
3. After logical right shift by three, as a dependency argument.

These are not established entry inputs. Their exact producing calls, availability rules, and calling convention are **documented_only**. This contract identifies them by their visible use, without assigning them to a particular preceding call.

### Outputs and widths

No return value is declared. Observable outputs consist of dependency interactions, memory mutations, and any dependency-induced effects.

A **byte** is 8 bits; a **word** is 32 bits. A **paired result** is represented as 64 bits, divided into low and high 32-bit halves. Byte stores retain the low eight bits.

Unsigned 32-bit arithmetic wraps modulo \(2^{32}\). Some represented signed multiplications and left shifts do not independently establish overflow semantics. Descriptions using their low 32-bit results are conditional on machine-width bit-vector execution. Explicit unsigned right shifts are logical.

Endianness, alignment requirements, and address-space interpretation are unresolved.

## Behavior

### Reading conventions

A **bare call** below means an invocation for which the representation lists no explicit arguments. It does not establish absence of register inputs or side effects. A count of bare calls denotes that many separate, ordered invocations.

All calls belong to the unresolved dependency set **F-D001**. Membership does not mean that different occurrences call the same function.

Repeated selector expressions are fresh byte reads. A selector is zero-extended before adding 17, so selector-directed writes address decimal locations 17–272. No null-selector check is visible.

The following phases are sequential. Named retained values describe visible data relationships, not ownership, structure types, or guarantees about dependency behavior.

### 1. Initial calls and fourth-argument writes

A byte is then read at inherited-address-plus-1. At that byte’s value plus 17, the operation writes the low byte of the unsigned entry value shifted right by 22.

A call receives four times the early result. Four bare calls follow, the last producing the **initial payload**. Its left-shift-by-two low byte is written first at fourth-argument-plus-15, then through a selector freshly read at fourth-argument-times-1024-plus-1.

The **derived value** retains the fourth argument’s low 22 bits and shifts them left by eight.

Three bare calls follow, the last producing a forwarding result. The fourth-argument-times-1024 selector is read again; its selected destination receives the low byte of the initial payload masked to 30 bits and shifted right by 20.

A call receives four times the forwarding result. Four bare calls follow. A selector at derived-value-times-\(2^{19}\)-plus-1 is then read, and its selected byte at offset 17 is cleared.

### 2. Derived selectors and initial word copies

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Byte truncation.** If the initial payload is hexadecimal 1234567F, its left-shift-by-two low byte is FC. Both initial stores using that byte retain FC.

2. **Different extracted bits.** For the same payload, masking to 30 bits and shifting right by 20 yields a low byte of 23. The later selected write stores 23, not FC.

3. **Fresh selectors.** If successive reads of the same selector expression return 5 and 9, their offset-17 destinations are decimal addresses 22 and 26. The earlier selector must not be reused.

4. **Zero selector.** A selector of zero targets absolute address hexadecimal 11. No visible check suppresses the write.

5. **Address wraparound.** For fourth argument hexadecimal 00000020, the derived value is 00002000. Its unsigned multiplication by \(2^{19}\) wraps to zero, making the associated selector read target address 1.

6. **Captured word survives later memory changes.** If the copied word in phase 4 is A1B2C3D4, its immediate byte copy stores D4. Conditional on reaching the later store, the secondary-selected offset-20 write uses the captured A1B2C3D4, not a fresh read of its original location.

7. **Fresh leading call argument.** If the bare call after forwarding the second secondary-register value returns 7 and the shifted capture is 3, the following explicit arguments are 7, hexadecimal 00600000, and hexadecimal 00600000.

8. **Distinct related invocations.** Under 32-bit bit-vector semantics, a duplicated-argument result of 5 makes the phase-6 two-argument call receive 20 twice. If the following bare call returns 40, the next call receives 40 and 5. These are distinct invocations with distinct result provenance.

9. **Ordered overwrites.** At the offset-52 destination, the shifted word-producing result is stored before the paired high word. Likewise, absolute address hexadecimal 0D receives the retained selector before C0. Neither earlier write is omitted merely because a later write overwrites it.
