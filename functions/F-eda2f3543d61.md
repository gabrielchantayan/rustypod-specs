# F-eda2f3543d61

## Purpose

F-eda2f3543d61 conditionally transforms a value associated with a caller-supplied object and returns a 32-bit result.

The established behavior has three main paths:

- If an initial lookup produces a null address, return zero without an explicit object write.
- If a selected two-word quantity is zero or negative under a signed 64-bit interpretation, return the 32-bit negation of its low word without invoking the subsequent dependencies.
- If that quantity is positive, compute a two-word result through two dependencies, then use a third dependency to choose between two object-state updates.

The meanings of the object, the computed value, and the state encodings are not established. In particular, the evidence does not establish that the computation is integer arithmetic, floating-point arithmetic, normalization, or conversion. Those interpretations must not be prerequisites for conformance.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Input

The function has one explicit 32-bit input, interpreted as the address of a caller-associated object.

The input is first passed to F-ee46d7dc6aa5 together with a second argument of zero. There is no explicit null check or object validation before that call.

When execution reaches an object-update path, the following locations relative to the input address are accessed:

| Offset | Width | Access |
|---|---:|---|
| +16 | 8 bytes | Written on the zero-decision path |
| +36 | 2 bytes | Written on both update paths; also read on the nonzero-decision path |
| +38 | 1 byte | Written on both update paths |

On the nonzero-decision path, the returned address is the input address plus eight bytes. The function does not explicitly read or write the object at that returned address.

No complete object size, alignment requirement, allocation origin, or public type is supplied. Validity of the particular accesses reached during execution is a precondition for defined operation; invalid-access recovery is not established.

### Lookup result

F-ee46d7dc6aa5 returns either a null address or an address through which the function reads 32-bit words.

The relevant layout is:

| Offset from lookup result | Width | Role |
|---|---:|---|
| +0 | 4 bytes | First word supplied to F-596e18a33aec |
| +4 | 4 bytes | Second word supplied to F-596e18a33aec |
| +16 | 4 bytes | Low word of the branch-selection quantity |
| +20 | 4 bytes | High word of the branch-selection quantity |

The minimum directly accessed extent is therefore 24 bytes, although not every byte in that extent is read.

The lookup result is not necessarily distinct from the input object. Aliasing, storage duration, and ownership are unknown.

### Output

The return value is a 32-bit result with path-dependent meaning:

| Condition | Return |
|---|---|
| Lookup returns null | Zero |
| Branch-selection quantity is nonpositive | Negation of its initially read low word, modulo \(2^{32}\) |
| Quantity is positive and F-c87e8125aeb8 returns zero | Integer value two |
| Quantity is positive and F-c87e8125aeb8 returns nonzero | Input address plus eight bytes, represented in the 32-bit result |

These alternatives are not guaranteed to be numerically disjoint. Zero is not an unambiguous lookup-failure indication: the nonpositive path also returns zero whenever its low word is zero.

Likewise, the address-shaped result is not guaranteed to be positive when interpreted as a signed 32-bit integer.

## Behavior

### 1. Resolve the associated record

Call F-ee46d7dc6aa5 with:

1. The original input value.
2. A 32-bit zero.

If its result is null, return zero immediately.

There are no explicit object writes on this path. This does not imply that the dependency itself has no side effects.

### 2. Read and classify the two-word quantity

For a nonnull lookup result, read the 32-bit words at offsets +16 and +20.

For specifying the branch, let:

- \(L\) be the initially read low word, interpreted as unsigned.
- \(H\) be the initially read high word, interpreted as signed.
- \(Q = H \times 2^{32} + L\).

The branch condition is equivalent to \(Q > 0\). More explicitly:

- A positive signed high word selects the computation path.
- A zero high word selects the computation path exactly when the low word is nonzero.
- A negative signed high word selects the nonpositive path, regardless of the low word.

The supplied expression accounts for signed overflow when testing the sign of a multiword subtraction. It must not be simplified into an ordinary signed 32-bit test of the negated high word alone.

The two reads do not establish an atomic 64-bit snapshot. Concurrent mutation and synchronization behavior are not specified.

### 3. Handle a nonpositive quantity

If \(Q \leq 0\), return the 32-bit two’s-complement negation of the initially read low word.

The high word affects branch selection but is not included in this returned negation.

Consequences include:

- A zero quantity returns zero.
- A negative quantity with a zero low word also returns zero.
- A low word of `0x80000000` produces the same returned bit pattern, `0x80000000`.
- The operation is not specified as a full-width 64-bit negation followed by a numerical range check.

No additional dependency calls or explicit object writes occur on this path.

### 4. Compute a candidate result for a positive quantity

If \(Q > 0\), perform the following dependency calls in order.

First, call F-8d7acd353fe6 with the words at lookup-result offsets +16 and +20, in low-word/high-word order.

These are fresh argument reads in the supplied representation. They are not explicitly required to reuse the words previously loaded for branch selection. In stable memory the values agree; agreement is not guaranteed by the function if the record changes between accesses.

F-8d7acd353fe6 produces a 64-bit result represented by two 32-bit words.

Next, call F-596e18a33aec with four arguments:

1. The word at lookup-result offset +0.
2. The word at lookup-result offset +4.
3. The low word returned by F-8d7acd353fe6.
4. The high word returned by F-8d7acd353fe6.

The record reads for this call occur after F-8d7acd353fe6 returns. Therefore, if that dependency modifies the record or shared state that backs it, the later reads can observe those changes. This contract does not assume preservation of that memory.

F-596e18a33aec produces another 64-bit result. This is the candidate value used for the subsequent decision and, on one branch, written to the input object.

### 5. Obtain a decision

Call F-c87e8125aeb8 with the candidate’s low and high words repeated twice as the first four represented arguments:

1. Candidate low word.
2. Candidate high word.
3. Candidate low word.
4. Candidate high word.

The supplied call representation also contains four trailing 32-bit values obtained from incoming machine state, rather than initialized from the explicit input in this body. Their semantic role and whether they are genuine formal parameters are unknown.

The dependency’s result is tested only for equality to zero. No particular meaning is assigned to any individual nonzero result.

The repeated candidate pair does not by itself establish equality testing, numeric classification, or any particular comparison semantics.

### 6. Apply the zero-decision update

If F-c87e8125aeb8 returns zero:

1. Call F-74b5a05d0094, with no explicit arguments shown.
2. Write the 64-bit candidate to the input object at offset +16.
3. Write the 16-bit value eight at offset +36.
4. Write the 8-bit value two at offset +38.
5. Return the 32-bit integer two.

The candidate written is the result retained from F-596e18a33aec. It is not recomputed after F-74b5a05d0094.

The explicit writes occur after that dependency returns. If it invalidates the input object, subsequent behavior is not made safe by this function.

The 64-bit assignment establishes the value written, not an atomic eight-byte transaction or a particular order of constituent machine stores.

### 7. Apply the nonzero-decision update

If F-c87e8125aeb8 returns nonzero:

1. Read the 16-bit field at input offset +36.
2. Clear its low five bits and set bit zero.
3. Write the resulting 16-bit field back to offset +36.
4. Write the 8-bit value five at offset +38.
5. Return the input address plus eight bytes.

The 16-bit transformation is:

\[
\text{new field} = (\text{old field} \mathbin{\&} \texttt{0xFFE0}) \mathbin{|} 1.
\]

Thus, bits 5 through 15 are preserved from the value read at this point. Bits 1 through 4 become zero, and bit 0 becomes one.

There is no explicit write of the candidate at offset +16 on this branch. Any changes a dependency makes there remain outside this function’s explicit update guarantee.

## Side effects

The explicit memory effects are limited to the reads and writes described above. The dependencies may have additional effects; none is established to be pure.

Important ordering guarantees are:

- Lookup precedes all direct reads through its result.
- Branch-selection reads precede the computation dependencies.
- F-8d7acd353fe6 precedes the record reads used for F-596e18a33aec.
- F-596e18a33aec precedes F-c87e8125aeb8.
- On the zero-decision branch, F-74b5a05d0094 precedes all three explicit object writes.
- On either update branch, the offset +36 update precedes the offset +38 write.

Within the argument preparation for a single call, the supplied representation does not establish a more detailed ordering between separate memory reads.

No allocation, release, reference-count change, ownership transfer, or explicit global write appears directly in this body. None of those effects can be ruled out inside dependencies.

The function does not establish transactional updates. If a fault or nonlocal exit interrupts the sequence, rollback is not shown.

## Acceptance examples

These are conditional static acceptance cases, not reports of executed tests. Cases involving object writes assume valid writable storage and normal dependency returns.

1. **Null lookup**

   If F-ee46d7dc6aa5 returns null, the function returns zero. None of the other four dependencies is called, and no explicit object update occurs.

2. **Zero branch-selection quantity**

   With initial high and low words both zero, the function returns zero after the lookup and classification reads. It does not enter the computation path.

3. **Negative quantity with nonzero low word**

   With initial high word `0xFFFFFFFF` and low word `0x00000001`, the quantity is negative. The return bit pattern is `0xFFFFFFFF`. No computation dependency is called.

4. **Negative quantity with zero low word**

   With initial high word `0xFFFFFFFF` and low word zero, the return is zero despite the quantity being nonzero and negative.

5. **Minimum signed 64-bit quantity**

   With initial high word `0x80000000` and low word zero, the function takes the nonpositive path and returns zero. Overflow-sensitive sign handling must not incorrectly classify this input as positive.

6. **Positive quantity with a high low-word bit**

   With initial high word zero and low word `0x80000000`, the quantity is positive. The function enters the computation path even though the low word alone would be negative as a signed 32-bit value.

7. **Zero decision**

   For a positive initial quantity, suppose the computation produces a candidate and F-c87e8125aeb8 returns zero. After F-74b5a05d0094 returns, the candidate is written at +16, the field at +36 becomes eight, and the byte at +38 becomes two. The return is two.

8. **Nonzero decision preserves upper field bits**

   For a positive initial quantity, suppose F-c87e8125aeb8 returns nonzero and the field at +36 is `0xABDF` when read. The updated field is `0xABC1`, the byte at +38 becomes five, and the return is the input address plus eight. No candidate store is explicitly performed.

9. **Inter-call record mutation**

   If F-8d7acd353fe6 changes the record words at +0 and +4, F-596e18a33aec receives their post-call values. Substituting values cached before that dependency would not preserve the represented access sequence.
