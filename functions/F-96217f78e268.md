# F-96217f78e268

## Purpose

F-96217f78e268 derives a four-word output record from a source object, two dependency-produced records, a mode byte, and a size policy.

Its defining behavior is **staged publication**: after an associated-object check succeeds, it writes an initial four-word record, performs further calculations and conditional dependency calls, and then overwrites some output words. These writes are not an atomic replacement.

The words resemble geometric bounds, and one sizing branch resembles proportional sizing. Those interpretations are **inferred intent**, not established semantics. The contract below uses record positions and numerical relationships without requiring coordinate, border, or indicator meanings.

An absent associated object prevents direct output writes, but does not prevent the initial dependency call or undo its effects.

## Interface

### Arguments and result

The function accepts:

- An **output address**, used for four consecutive 32-bit words at byte offsets 0, 4, 8, and 12.
- A **source-object address**, used to read configuration and an associated-object address.

There is no explicit return value or status result. Observable results are memory writes, dependency invocations, and any effects those dependencies produce.

The supplied representation uses 32-bit integers and 32-bit address-bearing values. It does not establish a portable interface for a different address width.

### Source layout

| Source offset | Width | Interpretation established here |
|---|---:|---|
| `0x48` | 32 bits | Policy word; only bit `0x02000000` affects this function. |
| `0xB4` | 32 bits | Associated-object address. |
| `0xB8` | 8 bits | Unsigned mode, observed twice on a continuing execution. |
| `0x2E0` | 32 bits | Signed configured size or threshold. |

The associated object supplies two signed 32-bit values:

| Associated-object offset | Role |
|---|---|
| `0x80` | Lower operand of an extent subtraction. |
| `0x88` | Upper operand of that subtraction; also retained for modes above 2. |

The **object extent** is the upper operand minus the lower operand. Neither operand is validated, and their order is not constrained.

### Dependency-produced storage

F-960363c07b32 receives the source object and temporary storage. Four consecutive 32-bit words in that storage are subsequently consumed. They are called the **first**, **second**, **third**, and **fourth producer words** below.

F-756b664b4a2c receives an associated-object address and separate temporary storage. This function consumes the 32-bit words at offsets 0 and 8 of that storage. Their signed difference, offset 8 minus offset 0, is the **geometry extent**. The intervening word is not used by the visible calculation.

These descriptions specify consumed positions, not complete dependency output schemas.

### Preconditions and ownership

Ordinary completion requires every reached memory access to be valid, all consumed temporary values to have been initialized, and each invoked dependency to return normally.

The function performs no explicit allocation, release, reference-count operation, or ownership transfer. No equivalent claim is established for its dependencies.

Neither argument is explicitly validated. A null output address is not directly dereferenced on the absent-associated-object path, but that does not establish that dependencies cannot affect or access related memory.

No nonoverlap requirement is checked. Output overlapping the source or associated object can change later reads. The ordinary numerical examples assume nonoverlapping storage.

## Behavior

### Observation and publication boundaries

The following ordering constraints are externally significant:

1. F-960363c07b32 runs before the policy word or associated-object field is read.
2. The policy bit is captured. The second and fourth producer words are then retained for final publication.
3. The associated-object field is checked for zero.
4. If the check succeeds, F-756b664b4a2c runs before associated-object endpoint reads and mode observations.
5. The object extent is obtained, the first mode observation occurs, and the geometry extent is calculated.
6. All four initial output words are written before the second mode observation.
7. Size selection completes before the optional offset dependency runs.
8. Final output writes follow that dependency, if it is called.

These boundaries matter if dependencies alter state or output overlaps later-read storage. They do not imply synchronization with concurrent activity.

### Associated-object check and repeated address reads

A zero associated-object value at the initial check causes an immediate return. No direct output write has occurred.

A successful check does not establish a stable associated-object address. The field is read again for F-756b664b4a2c and again for each subsequent associated-object endpoint access. Consequently:

- The dependency need not receive the same address that passed the check.
- The two endpoint operands need not come from the same object if the field changes.
- A later zero or invalid address is not rejected by another validation branch.

The value at associated offset `0x88` is obtained before the value at offset `0x80`. Their difference is computed before the first mode observation.

### Retained values versus the initial publication

The second and fourth producer words are retained before the associated-object check. The retained second word is conditionally adjusted using the **first** mode observation:

- Modes 0 and 1 increase it by one.
- Modes 2 through 255 leave it unchanged.

This adjustment is unsigned 32-bit arithmetic: incrementing `0xFFFFFFFF` produces the bit pattern `0x00000000`.

The initial output publication is different from those retained values. It reads the producer record and writes its four words to output in increasing word order. The adjusted second-word snapshot is not used for this initial publication.

Thus, even without overlap, the output initially receives the unadjusted producer second word. Later it receives the retained, possibly incremented value.

The producer record is passed by address to F-960363c07b32. The supplied evidence does not establish whether that address can escape or whether another dependency can alter its contents. Equality between the early snapshots and later producer-record reads therefore requires a preservation assumption. Under ordinary stable-temporary assumptions, they are observations of the same record; that equality is not an unconditional dependency guarantee.

### Two independent mode observations

Both mode reads interpret the source byte as an unsigned value from 0 through 255.

The first observation controls only the retained second-word increment. The second controls working bounds and final endpoint publication. There is no requirement that the observations agree.

Because all four initial output writes precede the second observation, output aliasing the source mode field can change the second mode without changing the already-completed first observation.

### Working bounds

For the second mode observation:

| Mode | Working base | Working upper value |
|---|---|---|
| 0 or 1 | First producer word plus 1 | Third producer word minus 2 |
| 2 | First producer word plus 2 | Third producer word minus 2 |
| 3–255 | Address of the producer record’s first word, interpreted as a 32-bit integer | Previously obtained associated value at `0x88` |

The last row is established behavior, not an ordinary-coordinate interpretation. No validation rejects these modes.

When the captured policy bit is set, the **available interval** is the working upper value minus the integer-valued working base. This subtraction is not performed for size selection when the policy bit is clear.

### Size policy

The policy decision uses the bit captured before the associated-object check. Later changes to the policy word do not change that decision.

**Policy bit clear.** The selected size is one signed 32-bit read at source offset `0x2E0`. There is no positivity check, extent-based restriction, or interval cap.

**Policy bit set.** Size selection has two distinct stages:

- If the signed geometry extent is less than 1, the candidate size is zero.
- Otherwise, F-870c4fcf7295 receives the signed 32-bit product of object extent and available interval, followed by the geometry extent. Its signed return becomes the candidate.

The product has no established widening to 64 bits. The dependency’s identity does not establish division, rounding, saturation, or error behavior.

The candidate is then compared, using signed interpretation, with a read of source offset `0x2E0`:

- If the candidate is smaller, the field is read again and that second value becomes the selected size. The available-interval cap is bypassed.
- Otherwise, the selected size is the smaller of the candidate and the available interval.

This is not a conventional lower-and-upper clamp. Threshold replacement can exceed the available interval, while the interval cap can produce a result below the threshold. Negative thresholds, intervals, candidates, and selected sizes are not separately rejected.

The comparison and replacement reads are distinct. No equality between their results is guaranteed.

### Offset selection

The signed geometry extent is compared with the previously computed object extent.

- Equal extents produce offset zero without another dependency call.
- Unequal extents cause F-d7be9cfb4000 to be called with no explicit arguments. Its signed return is the offset.

This decision is independent of the mode and selected size. Modes above 2 still take this call when the extents differ.

### Final output

For second modes 0 and 1, final endpoint values are:

- First output word: working base plus offset, then minus 1.
- Third output word: working base plus offset plus selected size, then plus 2.

For second mode 2:

- First output word: working base plus offset.
- Third output word: working base plus offset plus selected size.

In these modes, the first endpoint write precedes the third-word write.

For second modes 3–255, neither endpoint is directly written again. Nevertheless, the base-plus-offset and base-plus-offset-plus-size calculations still occur. The absence of endpoint publication does not eliminate their arithmetic requirements.

Every continuing path ends by writing the retained second word and then the retained fourth word. These writes occur even when the second mode is above 2.

With stable producer contents and supported intermediate arithmetic, modes 0 and 1 therefore produce a first endpoint equal to the original first word plus offset, and a third endpoint equal to the original first word plus offset plus selected size plus 3. These simplified relationships do not remove intermediate overflow constraints.

## Side effects

### Direct writes

The successful associated-object-check path performs:

- Four initial output writes, in word order.
- Two endpoint writes if the second mode is 0, 1, or 2.
- Two final writes, to the second and fourth words in that order.

Thus there are eight direct output writes for second modes 0–2 and six for second modes 3–255.

No direct source or associated-object write is explicit, except through output aliasing. Intermediate output states are observable in principle; publication is neither atomic nor transactional.

A fault or nonreturning dependency after initial publication can leave a partially updated record. There is no rollback.

### Indirect effects and errors

Dependency effects are not restricted to the supplied temporary records. In particular, global-state preservation, source preservation, output preservation, ownership behavior, and determinism are not established.

There is no explicit error result, retry, recovery branch, or dependency-status check. Invalid memory, uninitialized dependency output, unsupported arithmetic, and abnormal dependency termination have no defined recovery behavior in the available evidence.

- F-870c4fcf7295 is not called.

### Unsigned second-word boundary

If the retained producer second word is `0xFFFFFFFF` and the first mode is 0 or 1, the final second output word is **`0x00000000`**. This increment is unsigned and does not depend on an unresolved signed-overflow rule.

### Mode above 2

With stable mode 3, the final record equals the producer record under the stated preservation assumptions. Size selection and conditional offset calculation still occur.

Even with clear policy, address-derived endpoint arithmetic is reached. This example is conditional on that arithmetic being supported; unchanged endpoint output does not prove harmless execution.
