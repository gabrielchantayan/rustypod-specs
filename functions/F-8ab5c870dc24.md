# F-8ab5c870dc24

## Purpose

F-8ab5c870dc24 requests a header and payload, conditionally processes the payload, optionally emits individual units, selects an output operation, and invokes a notification sequence when output returns zero.

The contract establishes observable calls, memory accesses, arithmetic, branches, and status propagation. Representation tags 1 and 2 receive special handling, but their encoding meanings are not established. “Conversion,” “workspace,” “iterator,” and “consumer” describe inferred roles, not dependency guarantees.

Processing is not transactional. Reads, transformations, workspace operations, and emissions can occur before a later failure. Output selection can recheck the header tag after dependency calls; it is not always determined by the tag that selected initial processing.

## Interface

The represented interface has nine 32-bit argument words. Address-valued arguments are represented by 32-bit words.

| Position | Role |
|---|---|
| 1 | Mutable context address; also the payload destination and default output data address. |
| 2 | Output selector. Values 1 and 2 enable particular output branches. |
| 3 | Mode selector. Only equality to 2 matters locally. |
| 4 | Not inspected or forwarded by this body. |
| 5 | Opaque output target, forwarded to the selected output dependency. |
| 6 | Opaque output option, forwarded to the selected output dependency. |

The result is a 32-bit status. Nonzero statuses from either input request, either checked workspace request, or the selected output operation are returned unchanged. Output status zero remains the return value after notification. No additional local error status is established.

### Header and context layout

A 16-byte read is requested into invocation-local header storage.

| Header offset | Width | Interpretation in this function |
|---|---:|---|
| 0 | 32 bits | Representation tag. |
| 4 | 32 bits | Unsigned payload byte count. |
| 8 | 8 bits | Zero enables additional representation-1 processing. |
| 9–15 | 7 bytes | No explicit interpretation. |

The header address is passed to dependencies. Consequently, later field reads are not contractually equivalent to a single immutable header snapshot.

The following context-relative locations are used:

| Context offset | Width | Use |
|---|---:|---|
| 0 | Variable | Payload destination and data input. |
| `0x400e3` | 8 bits | Enables header and representation-1 payload transformations when nonzero. |
| `0x400e4` | 32 bits | Opaque conversion argument. |
| `0x400e8` | 32 bits | Workspace address. |
| `0x40108` | 32 bits | Per-unit consumer handle. |

These accesses do not establish a complete context layout.

Representation-2 emission uses temporary state with three consecutive 32-bit words: an opaque descriptor at offset 0, a state word at offset 4, and a context/cursor word at offset 8. A separate output path supplies a 512-byte temporary buffer.

### Preconditions and ownership

The context and all reached addresses must support the accesses and dependency operations on the selected path. No local context-capacity check precedes the payload request. No null check protects the workspace pointer.

Because the payload destination starts at the context address, a sufficiently large payload write can overlap later-used context fields. Their pre-read values must not be presumed preserved.

Temporary storage belongs to this invocation. Passing its address does not establish safe retention beyond the invocation. Dependency retention, allocation, release, and ownership transfer remain unknown unless separately specified.

## Behavior

### Header request and transformation

F-ccb28d079bbc receives the context, the temporary header address, and length 16.

If it returns nonzero, that status is returned immediately. No subsequent operation described below occurs.

After success, the byte at context offset `0x400e3` is read. If nonzero, F-6fa3c138a734 receives the header address. Its result is not checked. Subsequent header accesses use the storage as it exists after this call; the transformation’s coverage and byte-order effects are unknown.

### Payload request and first descriptor snapshot

F-ccb28d079bbc is called again with the context as both its first argument and destination, and the currently read header byte count as requested length.

Immediately after this call returns, the function reads a 32-bit opaque global descriptor and saves its value. **This read precedes examination of the payload-request status and occurs even when that status is nonzero.**

A nonzero payload-request status is then returned unchanged. Otherwise, representation-specific processing begins.

Neither request’s exact-length behavior, partial-write behavior, or zero-length semantics is established here.

### Initial representation dispatch

The function first tests the header tag for equality to 1. If that test fails, it tests for equality to 2.

- Tag 1 enters representation-1 processing.
- Tag 2 enters representation-2 processing.
- Other tags skip both processing paths and use general output with the context address and the count captured on that path.

No local rejection of an unrecognized tag occurs.

### Representation-1 processing

The context flag at `0x400e3` is read again. If nonzero, F-d8ccff4dc252 receives the context and the current header count shifted right by one.

This flag access is separate from the earlier header-transformation decision. The values need not match.

The header byte at offset 8 is then tested. If zero, additional processing occurs:

1. F-97be51169a0a receives the context and the current header count plus 2, with addition modulo \(2^{32}\).
2. A nonzero result is returned immediately.
3. After success, the workspace address is loaded from context offset `0x400e8`.
4. F-a73f00145244 receives the context, the header count read **after** the workspace request and shifted right by one, and the loaded workspace address.
5. The first unsigned 16-bit workspace value is read. F-70a021fc7c24 receives the workspace address advanced by two bytes, the context address, and twice that value.
6. The first unsigned 16-bit workspace value is read again. Twice this second value is assigned to the header count.

The count supplied to F-a73f00145244 is not necessarily the count used to form the workspace request: the intervening dependency must not be assumed to preserve exposed header storage.

The workspace address loaded in step 3 remains the address used for both prefix reads and the intervening calls. A later context-pointer mutation does not itself reload that saved address. The two prefix reads are nevertheless distinct and may return different values.

Doubling either unsigned 16-bit prefix produces a value from 0 through 131070 without 32-bit overflow. F-70a021fc7c24’s argument order is established; its copy direction is not.

### Emission condition

Both recognized representations use this condition:

- argument 8 is nonzero; and
- argument 9 is zero, or argument 3 is not 2.

No emission occurs for other initial representation tags.

#### Representation-1 emission

When enabled, the iteration count is captured once as the current header count shifted right by one.

For increasing indices from zero to one less than that count, F-008d77a63c85 receives:

- the current 32-bit consumer handle from context offset `0x40108`;
- the 16-bit payload unit at context offset twice the index;
- the constant 1.

The payload-unit read and consumer-handle read are argument evaluations of the same call. **Their relative evaluation order is not established.** Both occur for each iteration; neither is a collection-wide snapshot.

Emission results are ignored. Dependencies may affect values observed by later iterations, but the captured iteration count is not recomputed. An odd trailing payload byte does not produce an emission.

Representation-1 processing reaches the tag-rechecking output-selection block whether emission was enabled or disabled.

#### Representation-2 emission

When enabled, temporary state is prepared in this order:

1. Its state word is set to zero.
2. A **second read** of the opaque descriptor global initializes its leading word.
3. Its context/cursor word is set to the context address.

This initialization read is distinct from the snapshot taken immediately after the payload request.

F-e365af86ca86 receives the temporary-state address, context, and current header count. F-d8cbf9aa79a9 then receives the current state word, and its unsigned 32-bit result becomes the fixed iteration count.

For each iteration:

- F-2be305f439e7 receives the address of the context/cursor word and produces a 32-bit value.
- After that call, the current consumer handle is read and F-008d77a63c85 receives that handle, the extracted value, and 1.

After all iterations, the temporary state’s leading descriptor is overwritten with the **first snapshot**, taken after the payload request—not necessarily the value used during initialization. F-22abefe7f288 then receives the temporary-state address.

This path proceeds to tag-rechecking output selection. If representation-2 emission is disabled, neither temporary-state processing nor finalization occurs; control instead enters the tag-2 output block directly.

### Output selection and tag rechecks

The following control-flow distinction is part of the contract:

- Representation-1 processing and representation-2 processing **with emission** reach a block that reads the header tag again.
- Representation-2 processing **without emission** directly enters the tag-2 output block, without that later tag recheck.
- Unrecognized initial tags use general output directly.

In the rechecking block, equality to 2 selects the tag-2 output block. Otherwise, equality to 1, together with selector 2, selects the representation-1 conversion output path. Other cases use general output.

Thus, if dependencies modify exposed header storage, initial tag 1 can later select tag-2 temporary-buffer output, and initial tag 2 with emission can later select tag-1 conversion output. Fixed representation-based descriptions are valid only when the relevant tag reads remain stable.

#### Tag-2 output block

The current header count is captured for possible general output.

If argument 2 equals 1:

- A temporary 32-bit word is set to zero.
- F-ba5b7e810055 receives the context, a current header count read, the 512-byte temporary-buffer address, and numeric limit 255.
- F-b9f19a3ec83a receives argument 5, the temporary-buffer address, and argument 6.

The latter call supplies the output status. The preparation result is not checked. No length is passed to this output operation. Buffer termination, initialized extent, and the meaning of 255 are unknown.

For other selectors, general output receives the context address and the captured count.

#### Tag-1 conversion output path

This path requires a tag read equal to 1 in the rechecking block and argument 2 equal to 2.

The current header count is compared with an unsigned global cap. If larger, the cap is assigned to the header count.

F-97be51169a0a receives the context and workspace size

**3 × (current count >> 1), with multiplication evaluated modulo \(2^{32}\).**

The shift occurs before multiplication. This is not equivalent to multiplying the count by 3 and then shifting.

A nonzero workspace-request result is returned immediately. Otherwise, F-881e6ad5fded receives the context, the workspace pointer currently read from `0x400e8`, and the opaque word currently read from `0x400e4`. No relative evaluation order between those argument reads is established.

The conversion result is used as an unsigned 32-bit output length. After conversion returns, the workspace pointer is loaded again; this newly loaded address becomes the output data address.

F-7834b08494a4 receives argument 5, that address, the conversion result, and argument 6.

Emission precedes capping and conversion. It can therefore process more units than the capped input count represents. The workspace dependency and conversion dependency must not be assumed to preserve the capped count.

#### General output

Where no specialized output operation applies, F-7834b08494a4 receives argument 5, the context address, the count captured for that path, and argument 6.

### Post-output notification

After the selected output call returns, the function reads and captures the current header count, even if output returned nonzero.

If output status is zero:

1. F-c4233718c9d6 is called without arguments.
2. F-58d31195950e receives its result, argument 7, the context address, and the captured count.

The count is captured before F-c4233718c9d6. Later header mutation by that dependency does not change the supplied notification count.

Notification results do not replace the output status. In particular, notification count is not inherently the output length. With preserved header storage, conversion output notifies using the capped input count; without that preservation assumption, it uses the count observed after output.

## Side effects

Observable effects include input requests, context writes requested by those dependencies, conditional transformations, workspace operations, per-unit emissions, one selected output call, and success-only notification.

There is no rollback:

- A failed payload request can follow a successful header request and header transformation.
- Emission can precede a failed conversion workspace request.
- Output failure suppresses notification but does not reverse preceding effects.
- Ignored dependency results do not introduce local failure branches.

The body performs no explicit free operation. Finalization must not be equated with guaranteed deallocation. Unknown dependencies may mutate globals, context fields, or previously exposed temporary storage; their preservation and ownership behavior are not established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Header failure:** If the first request returns nonzero, that exact status is returned. The payload request and descriptor-global reads do not occur.

2. **Payload failure ordering:** If the second request returns nonzero, the first descriptor-global snapshot still occurs before that status is returned. No representation processing follows.

3. **Descriptor snapshots:** If the post-payload snapshot yields A and representation-2 state initialization later reads B, initialization uses B. Before finalization, the leading descriptor is overwritten with A.

4. **Emission suppression:** With argument 8 nonzero, argument 9 nonzero, and argument 3 equal to 2, neither recognized representation emits. Changing argument 3 to another value enables emission.

5. **Odd count and fixed loop bound:** If representation-1 emission captures count 5, exactly two iterations are scheduled. Each accesses a 16-bit unit at offset 0 or 2 and the current handle, without an established relative order between those two reads.

6. **Post-workspace count change:** If additional processing requests workspace using count 8, and that dependency changes the exposed header count to 10 before returning success, F-a73f00145244 receives unit count 5, not 4.

7. **Repeated workspace prefix:** If the prefix is 3 before F-70a021fc7c24 and 4 afterward, that dependency receives length 6, and the assigned header count becomes 8.

8. **Tag change after representation-1 processing:** If processing starts with tag 1 but an intervening dependency changes the exposed tag to 2 before output rechecking, selector 1 chooses temporary-buffer output.

9. **Tag change during representation-2 emission:** If processing starts with tag 2, emission runs, and a dependency changes the tag to 1 before output rechecking, selector 2 chooses conversion output. The no-emission path instead enters the tag-2 output block directly.

10. **Shift before multiplication:** With count 5 surviving the cap, conversion workspace size is 6, not 7. With count `0xfffffffe`, the size is `0x7ffffffd` after unsigned multiplication wraps.

11. **Cap, output length, and notification:** With stable header storage, pre-cap count 20, cap 10, and conversion result 13, workspace size is 15, output length is 13, and successful-output notification count is 10. If a dependency instead changes the header count to 7 before the post-output capture, notification receives 7.

12. **Addition wrap:** Additional representation-1 processing with count `0xffffffff` requests workspace size 1. No local overflow error is generated.

## Uncertainties

The following remain **documented_only**:

- Descriptor-global values and the conversion cap.
- Header byte order and transformation semantics.
- Actual representation encodings and malformed-input behavior.
- Read completeness, partial writes, stream state, and zero-length behavior.
- Workspace capacity, allocation, ownership, and release guarantees.
- F-70a021fc7c24’s transfer direction and aliasing behavior.
- Temporary-buffer termination and initialized extent.
- Iterator extraction bounds and finalization ownership.
- Dependency retention or mutation of exposed storage and globals.
- Relative evaluation order of arguments where not otherwise sequenced.
- Downstream validation of counts or addresses.

Halving an unsigned count discards its low bit. Addition and multiplication described above can wrap without a local error. These arithmetic facts do not establish that the resulting memory operations are safe.
