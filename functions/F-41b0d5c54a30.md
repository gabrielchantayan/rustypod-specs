# F-41b0d5c54a30

## Purpose

The supplied static representation describes a call-driven sequence of 8-bit and 32-bit memory updates. It derives addresses and stored values from indirect-call results, one explicit input, and additional machine-entry state.

The observable pattern includes:

- Storing a right-shifted input word.
- Scaling dependency results into addresses and word values.
- Reading byte selectors and using them to address low memory.
- Writing selected bytes, including repeated zeroing.
- Clearing several word locations and repeatedly clearing the word at address `0x24`.
- Continuing through further indirect calls before reaching an invalid-instruction boundary.

No application-level purpose is established. Terms such as allocation, initialization, serialization, device control, and cleanup would imply semantics not supported by the available evidence.

This is a **conditional static contract**, not a claim that the represented path is executable as shown. The supplied representation explicitly reports unreliable instruction recovery and overlapping global symbols. No runtime tests have been performed.

### Width and arithmetic conventions

The following notation describes the represented dataflow without assigning application semantics:

- **Word** means 32 bits; **byte** means 8 bits.
- **Byte reduction** means retaining the low eight bits of a computed value.
- **Packed fragment** of a word means masking with `0x3fffffff`, logically shifting right by 20, and then reducing to a byte for a byte store.

- **Selector write** means reading an unsigned byte at a specified address, then writing one byte at that byte’s value plus `0x11`.

A selector is not a pointer-width load. Its destination is in the inclusive address range `0x11` through `0x110`.

Their source-language overflow semantics are not established. ## Acceptance examples

These are conditional specification examples, not executed tests.

1. **Input shifting.** If the fourth argument is `0xffffffff`, the first visible word store receives `0x1fffffff`. For fourth-argument values zero through seven, it receives zero. The destination still depends on a dependency result.

2. **Byte truncation.** If the early value is `0x12345678`, its four-times value has low byte `0xe0`. The initial selector-directed store writes that byte. Its packed fragment is `0x23`, so the later packed-fragment store writes `0x23` at the destination selected by the second byte read.

3. **Fresh selector observation.** If the first incoming-base selector read returns `0x20` and the second returns `0x30`, the two early byte destinations are `0x31` and `0x41`. Reusing the first selector for both is inconsistent with the represented reads.

4. **Selector-range boundary.** A selector byte of zero selects address `0x11`; a selector byte of `0xff` selects `0x110`. It does not select an address loaded as a full-width pointer.

5. **Sparse selector placement.** A retained selector of seven selects word address `0x24` for the sparse placement store. A retained selector of eight selects `0x80024`. This store writes the selector value, not an unconditional zero.

6. **Separate anchor locations.** If the anchor value is one, the anchor scaled word is four. Its initial store is at `0x24`, while the subsequent argument-producing word read is at `0x18`. Substituting the stored word for that read is not justified.

7. **Repeated clearing.** If a dependency changes `0x24` between two explicit clears, the later clear still occurs. Collapsing the four clear stores into one would remove observable behavior.

8. **Conditional prefix.** If a dependency fails before a later selector read, this contract does not require that read or any subsequent store to occur. It specifies no rollback of the completed prefix.
