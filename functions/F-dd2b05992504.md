# F-dd2b05992504

## Purpose

F-dd2b05992504 coordinates byte-oriented formatting into a caller-provided destination. It scans a format, requests literal copies, parses percent-led directives, selects directive-dependent widths, and delegates directive output. A preliminary substitution can replace part of the format before ordinary processing.

Its unsigned 32-bit result is an **accumulated, reported output count**, or zero on specified failure paths. The count combines literal lengths and dependency-reported results using 32-bit arithmetic. The function does not verify that those values equal bytes actually written, that generated output contains no earlier NUL, or that the count has not wrapped.

On normal loop completion, the function directly writes a NUL at its current destination cursor. Interpreting the result as the actual string length requires additional dependency contracts, valid memory accesses, consistent accounting, and absence of intervening modifications.

Directive letters and table geometry suggest date/time formatting. This is **inferred intent**, not an established compatibility claim. Actual directive rendering and complete recursive arguments remain unresolved.

This contract describes static evidence only. No runtime tests have been performed.

The fourth input requires an address-like interpretation for the apparent copy operation, but its supplied type alone does not establish pointer semantics.

### Result

The result is unsigned 32-bit. Normal completion returns the accumulated count only if it is no greater than the original capacity minus one, evaluated as unsigned 32-bit arithmetic.

Visible zero-return paths are:

- Capacity is zero.
- A nonempty literal span has a reported length greater than remaining capacity.
- An ordinary directive-output dependency returns zero.
- A recursive directive invocation returns zero.
- The final accumulated count exceeds the original capacity minus one.

A successful empty result also returns zero. There is no distinct error status, required-size result, or truncation indicator.

An early failure need not write a terminating NUL. A final-check failure occurs **after** the direct terminating write.

### Memory and ownership preconditions

Safe execution requires all accesses actually taken to address valid storage. Depending on the path, this includes:

- A writable destination covering every direct and delegated write.
- A readable, suitably terminated format throughout scanning and parsing.
- A readable record source if the preparation operation performs the apparent copy.
- Valid indexed table addresses and readable strings where length-like operations require them.
- A valid preprocessing object and dispatch structure when returned.
- Dependency-specific requirements, including valid parser results and any missing recursive arguments.

No explicit validation establishes these conditions. Negative capacities, invalid indices, overlap, oversized preprocessing expansions, malformed descriptors, and nonprogressing parser results are not explicitly rejected.

The body contains no explicit allocation, release, or ownership transfer. Dependency implementations may have additional ownership and global-state effects; none are established here.

## Behavior

### Entry and preparation

Capacity zero returns zero immediately, without a visible dependency call or memory dereference.

For every nonzero capacity, the function:

1. Initializes remaining capacity to the original capacity minus one using unsigned 32-bit arithmetic.
2. Calls an unnamed external operation with a local record destination, the fourth input, and size 36.
3. Calls another unnamed external operation with a 256-byte local scratch region and size 256.
4. Begins scanning the current format for a preprocessing trigger.

The first operation appears intended to copy the record; the second appears intended to clear the scratch region. Their signatures and call sites do not independently establish these effects or preservation of other memory.

These calls occur even for an initially empty or literal-only format. Subsequent format reads observe memory as it exists after preparation, not necessarily its entry contents.

For positive capacity, the accounting initially reserves one byte for the terminator. Negative capacity is not rejected and generally produces a large unsigned allowance. This is not an established safe capacity mode.

### Preliminary substitution

The scan reads successive bytes until NUL or the first triggering `T`. It maintains an armed state:

- `%` arms the state, including when already armed.
- While armed, `-`, `_`, and `0` retain the state.
- An armed `T` triggers substitution.
- Other non-percent bytes clear the state, except the three retaining bytes above.

Consequently, this scan is not established as an escaped-percent parser. For example, repeated percent bytes retain rather than cancel the armed state.

At the first trigger, the function performs this sequence:

1. Requests a byte-span copy into scratch from the original format, with length equal to the triggering `T`’s offset minus one.
2. Calls F-9d0ecc5f6adf.
3. If its result is non-null, reads the returned object’s dispatch-table address and invokes the method at dispatch-table byte offset 20, passing the object and 128.
4. Calls F-9b45bb70831a.
5. Calls F-42999360227b with scratch and an address 1,071 bytes beyond that result.
6. Calls F-42999360227b again with scratch and the original suffix beginning immediately after the triggering `T`.
7. Selects scratch as the format and stops preliminary scanning.

The copy length excludes the byte immediately before `T`, not necessarily the percent that armed the scan. Under copy-like behavior, `%T` contributes an empty prefix, whereas `%--T` contributes `%-`.

Only one preliminary substitution is attempted per invocation. The selected scratch format enters ordinary processing without another preliminary scan in that invocation.

The visible caller does not check the requested prefix length or either combination operation against the 256-byte scratch extent. Nor does it inspect the combination operations’ return values. Successful, bounded substitution depends on external behavior and input sizes. Calling these operations does not itself prove that scratch becomes a valid concatenated string.

### Literal processing and parsing order

After preprocessing, the accumulated count is initialized to zero. While the current format byte is nonzero, F-e4753b656f0b receives the current format address and byte value 37.

If that dependency returns zero:

- F-1cb585febd84 receives the current format address.
- A nonzero returned length is compared with remaining capacity.
- If too large, the function returns zero before requesting that copy.
- Otherwise, a byte-span copy is requested, and the destination cursor and count advance by the reported length.
- Processing then leaves the loop.

Remaining capacity is **not** reduced for this terminal suffix. The final accumulated-count comparison still applies.

If F-e4753b656f0b returns nonzero:

- The difference between its result and the current format address becomes an unsigned 32-bit literal length.
- A nonzero length is checked against remaining capacity.
- If too large, the function returns zero before requesting that copy.
- Otherwise, the caller requests the copy, advances the destination and count, and subtracts the length from remaining capacity.
- F-d6ef21803e34 receives the reported percent address and a local descriptor address.
- Its result becomes the next format address.
- The descriptor selects the output path.

The caller does not verify that the search result identifies a percent within the format. It also does not verify parser success, next-address validity, or forward progress. Those properties require dependency contracts.

Copy requests and accounting updates are separate facts: the caller advances according to the requested or reported length without inspecting destination bytes.

### Ordinary directive output

Every nonrecursive directive reaches F-1b0f58ad865f with:

- The current destination address.
- The selected width.
- The address of the local remaining-capacity field.

Before that call:

- `I` and `J` call F-870c4fcf7295 with the record field at offset 8 and the value 12.
- `y` calls F-870c4fcf7295 with the record field at offset 20 and the value 100.

No assignment or explicit onward argument carries the numeric helper’s result into the output call in the supplied representation. The output call likewise exposes no explicit directive, selected table string, or record argument.

Therefore, numeric conversion, padding, case, text selection, and actual generated bytes are `documented_only`. Even conventional interpretations of familiar directive letters are not guaranteed.

A zero output-helper result causes immediate return of zero. For any nonzero result, the caller adds that result to its count and advances its destination cursor accordingly.

Remaining-capacity changes are delegated through the pointer argument. The caller does not independently subtract ordinary directive results or verify consistency between reported progress, writes, and capacity mutation.

### Recursive directives

`c`, `x`, and `X` invoke F-dd2b05992504 recursively. The supplied call representation shows only:

- The current destination.
- Remaining capacity plus one.

The enclosing interface has five inputs. The nested format, record source, and table base are not recoverable from the supplied call.

After the recursive result is obtained, the caller subtracts it from remaining capacity **before** checking for zero. Zero then causes immediate failure. A nonzero result advances the accumulated count and destination.

A recursive empty-success result is indistinguishable from failure. No recursion-depth limit or termination guarantee is visible.

### Completion and arithmetic

Normal loop completion directly writes a NUL at the current destination cursor. Only afterward does the function compare its accumulated count with the original capacity minus one.

The count is not derived by inspecting destination contents. Generated data may contain earlier NUL bytes. Reported progress may differ from actual writes. A wrapped count may pass the final comparison without representing the mathematical total.

Capacity accounting, widths, literal lengths, and the returned count are 32-bit. Directive results are consumed through signed 32-bit intermediates, but only zero is rejected. A negative nonzero result is not explicitly rejected; count and remaining-capacity arithmetic incorporate its 32-bit representation, while cursor movement follows the supplied signed result.

Address differences, indexed address construction, additions, and subtractions have no visible overflow checks. In particular, remaining capacity plus one can wrap before recursion. The final comparison does not validate earlier writes or repair inconsistent dependency accounting.

## Side effects

The caller visibly orders preparation before preprocessing, preprocessing before ordinary formatting, and final termination before the final capacity check.

Potential externally observable effects include:

- Preparation operations receiving local destinations and the record source.
- Format-byte reads during scanning and ordinary processing.
- Indexed table-address calculations and the direct byte read for `p`.
- Object and dispatch-table reads followed by an indirect method call.
- Literal-copy requests and directive-output calls.
- Mutation of remaining capacity through F-1b0f58ad865f.
- A direct final NUL write on normal loop completion.

Failure is not transactional. The caller performs no rollback of earlier copy requests, output calls, or dependency side effects.

This does **not** guarantee preservation of an earlier literal prefix. An intervening dependency may modify destination bytes. After a helper returns zero, the caller merely returns zero without an additional rollback or terminating write.

The body does not directly write through the original format, record-source, or table arguments. Aliasing and dependency effects can nevertheless change later-observed input or output memory. No general memory-preservation or global-state-preservation guarantee is established.

## Acceptance examples

These are conditional static acceptance criteria, not runtime observations. Assumptions are local to each example; unknown dependency effects must not silently become preservation guarantees.

1. **Zero capacity.** For capacity zero, return zero without visible dependency calls or dereferences of the input addresses. No external-operation assumption is needed for this branch.

2. **Empty format.** Given positive capacity, a valid destination, preparation operations that complete safely, and a format that remains empty through preparation, write a NUL at the destination start and return zero. Entry-time emptiness alone is insufficient if preparation can alter the format.

3. **Literal exact fit.** Given format `abc`, capacity 4, valid memory, preparation preserving that format, search and length dependencies reporting no percent and length 3, and a copy operation that writes those bytes without disturbing the relevant state, write the final NUL after them and return 3. Calling this the actual string length additionally requires that no operation introduces an earlier NUL or modifies the copied bytes.

4. **Terminal literal too large.** If processing reaches a terminal suffix whose length dependency reports 4 while remaining capacity is 3, return zero before requesting its copy. Prior dependency effects remain possible; destination contents and termination are not otherwise guaranteed.

5. **Failure after a prefix.** If a fitting literal prefix has already caused a copy request and a later ordinary output helper returns zero, the caller returns zero without rollback or a caller-issued final NUL. Whether the prefix bytes remain present depends on the copy and intervening dependencies.

6. **Conditional numeric width.** If parsing produces `Y`, width zero, and a nonzero mode byte, the ordinary output call receives width 4. With mode byte zero, it receives width zero. These conditions specify the argument, not rendered digits.

7. **Explicit table width.** If parsing produces `A` with nonzero width, the caller bypasses its default table-length call. With width zero and valid record/table state, it calls F-1cb585febd84 at the specified 32-byte-stride address and uses its result as width.

8. **Unknown directive.** For a parsed directive outside the recognized set, the caller passes width 2 to ordinary output regardless of parsed width. Actual bytes remain dependency-defined.

9. **Direct preprocessing.** If preparation preserves `%Trest`, scratch clearing, prefix copying, and combination operations perform their apparent roles, all accesses fit, and intervening calls preserve the necessary strings and scratch, preprocessing constructs replacement data followed by `rest`. Without those conditions, only the call sequence, addresses, and zero-length prefix request are established.

10. **Modifier-sensitive preprocessing.** Under the same operation and preservation assumptions, `%--Trest` contributes `%-` before the replacement and `rest` afterward. The caller’s prefix length does not remove the entire apparent directive.

11. **Recursive zero.** If a recursive path is reached and its invocation returns zero, the caller performs the remaining-capacity subtraction and returns zero. No destination-preservation claim follows, even if the nested zero represents empty success.

12. **Report versus actual length.** If an output helper reports 3 but writes fewer bytes or an earlier NUL, the caller still adds 3 and advances by that reported amount. Assuming subsequent execution remains valid, the final comparison uses the accumulated count, not inspected string length.
