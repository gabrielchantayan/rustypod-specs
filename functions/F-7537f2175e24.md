### Widths, addressing, and layout

The representation distinguishes:

- 8-bit writes.

The recurring word destination is an index multiplied by four, followed by an offset of 20 bytes. This is not sufficient evidence for an array element size or an object-field definition: other destinations multiply indices by 16 or much larger powers of two.

Byte-directed writes use a different layout:

1. Read an unsigned byte from a calculated address, usually a scaled value plus one.
2. Zero-extend that byte.
3. Add 17.
4. Write one byte to the resulting address.

Thus these byte-write destinations lie between addresses 17 and 272 inclusive, if the displayed addressing is literal. The source byte is used directly as an address component; it is not visibly an offset relative to an object base.

Endianness is not established. Word alignment requirements and address-space mappings are also unknown.

### Arithmetic interpretation

Unsigned 32-bit expressions retain their low 32 bits. Byte stores retain only the low eight bits of their source value. Unsigned right shifts insert zeros.

Several address calculations and left shifts are displayed using signed 32-bit intermediates. Their overflow behavior is not a portable language-level guarantee. Whenever this contract discusses their wrapped values, it explicitly assumes a 32-bit machine-bitvector interpretation. Instruction-level confirmation would be required to make that interpretation unconditional.

## Behavior

The visible prefix is linear: no conditional branch, loop, validation check, or retry appears. Dependencies may nevertheless branch, fault, modify memory, alter ambient state, or fail to return.

The operations below describe ordered behavioral phases, not an implementation recipe. Intervening dependency calls are significant boundaries. Memory must not be assumed unchanged across them.

A value explicitly captured before a call is reused later in the displayed dataflow. Conversely, a later memory read is a new observation, even when its address matches an earlier read.

After that store, it reads a 32-bit word from the ambient base plus 20. Call this the **initial reference**. Four times the initial reference becomes a recurring address component.

A subsequent dependency sequence receives the earlier secondary-register value and eventually yields another index. The function stores the original input shifted right by 12 at four times that returned index plus 20, then passes the scaled index to another dependency.

A further call sequence supplies the **first payload**. The function:

- Reads a byte at four times the initial reference plus one.
- Writes the low byte of four times the first payload at the selected byte’s value plus 17.
- Calls a dependency with bits 10 through 29 of the initial reference, right-aligned.

After additional calls, it rereads the selector byte at four times the initial reference plus one. It writes the low byte of the first payload masked to 30 bits and shifted right by 20 at that selector plus 17.

This second write captures payload bits 20 through 27. It does not preserve bits 28 and 29, because the destination is one byte wide.

The second selector is retained for a later two-argument dependency call together with four times another returned value. It need not match the selector used for the first byte write.

After another call, the function reads a selector byte at the multiplied result plus one and writes zero at that selector plus 17.

It then calls a dependency with three arguments:

**Conditional arithmetic consequence:** under 32-bit wraparound, multiplying a value already shifted left by 26 by 1024 produces zero. Under that interpretation, the selector reads in this portion are from address one. This simplification is conditional, not evidence that address one is valid or intended.

## Acceptance examples

These are conditional review examples, not executed tests.

1. **Input extraction:** If the explicit input is `0xABCDEF12` and execution reaches the initial extraction store, its 32-bit stored value is `0x000ABCDE`, independently of which destination index the dependency supplies.

2. **Byte truncation:** If the first payload is `0x123456FF`, the first payload-derived byte store writes `0xFC`. Its later masked, right-shifted byte store writes `0x23`, not the full intermediate `0x123`.

3. **Selector rereading:** If a selector initially reads as five but changes to nine during intervening calls, the earlier byte write targets address 22 and the later write targets address 26. Reusing the first selector for both writes would violate the visible reread behavior.

4. **Paired reads:** If a dependency call’s two word-read argument occurrences observe different values because of the execution environment, the contract does not require equality. Their relative argument-evaluation order remains unspecified.

5. **Wrapped shifted reference:** Under 32-bit bitvector arithmetic, the shifted-reference value multiplied by 1024 is zero. The associated selector source is therefore address one. This example does not establish that accessing address one succeeds.

6. **Split result:** If the represented 64-bit result has high word three and low word one, the first split-result publication stores zero at address 32. The later large-scale publication stores `0x04000000` at address `0x10000014`, assuming ordinary 32-bit address arithmetic and successful intervening execution.

7. **Snapshot preservation:** If the fourth scaled-value publication’s subsequent word read observes `0x12345000`, its later shifted publication stores `0x00012345`. 8. **Partial execution:** If a dependency does not return after an earlier publication, later publications are not required to occur. No rollback of the earlier publication is established.
