# F-71acbb721a39

## Purpose

F-71acbb721a39 conditionally requests adjustments along two coordinate axes using four signed integer fields from an object and a caller-supplied four-field region.

The established behavior is a two-stage dependency sequence followed, when necessary, by up to two indirect object-method calls. The first dependency produces a four-field result used for an equality gate. If that result equals the caller’s region field for field, this function performs no further calls. Otherwise, a second dependency runs, and the function independently evaluates a horizontal adjustment and then a vertical adjustment.

Interpreting the fields as rectangle boundaries and the indirect calls as scrolling or repositioning is inferred intent. The observable contract is the field comparisons, arithmetic, dependency calls, and indirect-call arguments described below. The meanings of the dependencies and the indirect method are not established.

## Interface

The function accepts two pointer arguments and has no returned value:

- **Object pointer:** References an object whose first field supplies an indirect-method table reference. Four additional integer fields are read at integer indices 32 through 35.
- **Region pointer:** References four consecutive integer fields. The function itself only reads these fields, but passes their address to dependencies without a visible read-only restriction.

For this contract, the region fields are named:

| Field | Integer index | Byte offset under a 32-bit integer layout | Geometric interpretation |
|---|---:|---:|---|
| Left | 0 | 0 | First-axis starting boundary |
| Top | 1 | 4 | Second-axis starting boundary |
| Right | 2 | 8 | First-axis ending boundary |
| Bottom | 3 | 12 | Second-axis ending boundary |

The object’s corresponding four fields occur at integer indices 32, 33, 34, and 35: byte offsets 128, 132, 136, and 140 under that layout.

These names describe the apparent coordinate arrangement, not verified domain semantics. The function does not validate that right is greater than or equal to left, or that bottom is greater than or equal to top.

The supplied representation uses signed `int` operations. A 32-bit signed integer layout is the working interpretation of the offsets and arithmetic. Exact machine-level overflow behavior and pointer width are not independently established by the supplied material.

Required conditions for ordinary completion include:

- The object’s four source fields are readable.
- The region fields are readable whenever a reached comparison requires them.
- Both dependencies accept the supplied addresses and leave sufficient initialized state for subsequent reads.
- Whenever an adjustment is selected, the object’s current method-table reference and the entry at byte offset 324 are valid for the indicated call.
- Arithmetic is meaningful under the execution environment’s signed-integer rules.

No null checks, bounds checks, extent validation, or explicit error result are present.

## Behavior

### 1. Capture four object fields

The function reads the object’s fields at integer indices 32 through 35, in that order, into four temporary integer fields. These form a **baseline region**.

This initial capture occurs before either dependency call. Later object-field changes do not automatically refresh this baseline.

The baseline is not necessarily immutable: its address is passed to both dependencies. All subsequent descriptions of baseline values mean the values present in that temporary storage at the time of use, including any dependency modifications.

A separate four-field temporary area forms the **working region**. Its address is supplied to the dependencies as an output-capable argument.

### 2. Invoke the first dependency

F-e57b05520b65 is called with three arguments, in this order:

1. Address of the working region.
2. The caller’s region pointer.
3. Address of the baseline region.

No return value from this dependency is used.

The supplied function does not establish whether this dependency computes an intersection, clips coordinates, copies a region, or performs another operation. Such interpretations must not replace the observed three-argument relationship.

### 3. Compare the working region with the caller’s region

After the first dependency returns, the function tests whether the four working fields equal the corresponding caller-region fields.

The comparison is short-circuiting and ordered:

1. The caller’s left field is read and compared with working left.
2. Only if those match is caller top read and compared with working top.
3. Only if both preceding fields match is caller right read and compared with working right.
4. Only if the first three fields match is caller bottom read and compared with working bottom.

If all four match, the function returns without invoking the second dependency or the indirect method.

This is equality against the caller-region storage after the first dependency returns, not necessarily against its entry-time contents. The function does not make an initial snapshot of the caller’s region.

### 4. Invoke the second dependency when equality fails

If any field differs, F-9ba16c1c2031 is called with the same three addresses, in the same order:

1. Working-region address.
2. Caller-region pointer.
3. Baseline-region address.

No return value is used.

The function then evaluates adjustments using the temporary values present after this call. It does not require the second dependency to preserve the first dependency’s working result or the original baseline.

### 5. Evaluate the horizontal adjustment

The horizontal decision first compares two signed differences:

- Working right minus working left.
- Baseline right minus baseline left.

If those differences are equal, no horizontal method call occurs, regardless of whether the boundaries themselves differ.

If the differences are unequal, the function selects at most one boundary pair, using this priority:

1. **Baseline width smaller than caller width.**  
   Compare baseline right minus baseline left with caller right minus caller left. If the baseline difference is smaller, select the baseline left and working left boundaries. No additional left-boundary inequality is required.

2. **Otherwise, working right beyond baseline right.**  
   If baseline right is less than working right, select the baseline right and working right boundaries.

3. **Otherwise, working left before baseline left.**  
   If working left is less than baseline left, select the baseline left and working left boundaries.

4. **Otherwise, no horizontal adjustment.**

When a pair is selected, the signed adjustment is the selected baseline boundary minus the selected working boundary.

The function resolves the object’s method-table entry at byte offset 324 and calls it with five arguments:

1. The object pointer.
2. Zero.
3. The horizontal adjustment.
4. One.
5. Zero.

A selected adjustment can be zero. The function does not suppress a method call merely because the computed adjustment is zero.

### 6. Evaluate the vertical adjustment

Vertical evaluation occurs after the horizontal decision and after any horizontal method call has returned.

The vertical rule has the same structure, using top and bottom:

- First compare working bottom minus working top with baseline bottom minus baseline top.
- If equal, perform no vertical call.
- If unequal, select the first applicable case:
  1. Baseline height is smaller than caller height: select baseline top and working top.
  2. Otherwise, baseline bottom is less than working bottom: select baseline bottom and working bottom.
  3. Otherwise, working top is less than baseline top: select baseline top and working top.
  4. Otherwise, perform no vertical call.

The adjustment is the selected baseline boundary minus the selected working boundary.

For a selected vertical adjustment, the indirect method receives:

1. The object pointer.
2. The vertical adjustment.
3. Zero.
4. One.
5. Zero.

The method-table entry is resolved again for this call. A horizontal call can therefore affect which method is invoked vertically if it changes the object’s method-table reference or its relevant entry.

The caller-region height is evaluated during the vertical decision, not captured before the horizontal call. Changes to caller-region storage caused by that call, including changes through aliases, can affect the vertical result.

- F-e57b05520b65, which always runs after the initial object-field capture.

## Acceptance examples

These examples are conditional acceptance scenarios, not runtime observations. Unless stated otherwise, assume signed differences are representable and callees preserve the values needed by the example.

### Equality suppresses further work

If F-e57b05520b65 leaves the working region equal to the caller region in all four fields, the function must skip F-9ba16c1c2031 and make no indirect calls. The baseline may differ from both regions.

### Equal extents suppress adjustment despite displacement

Suppose the second dependency is reached and leaves:

- Baseline: left 0, top 0, right 100, bottom 100.
- Working: left 20, top 30, right 120, bottom 130.

Both axis differences equal their baseline counterparts. No indirect call occurs, despite different boundary positions.

### A larger caller width gives the left pair priority

Suppose after the second dependency:

- Baseline horizontal boundaries are 0 and 100.
- Working horizontal boundaries are −20 and 130.
- Caller horizontal boundaries are −50 and 150.

The working and baseline widths differ, and baseline width is smaller than caller width. The horizontal adjustment is 20, from baseline left minus working left. The indirect arguments are the object, 0, 20, 1, 0.

This left-pair selection takes priority even though working right also exceeds baseline right.

### Right overflow takes priority over left overflow

Suppose:

- Baseline horizontal boundaries are 0 and 100.
- Working horizontal boundaries are −10 and 120.
- Caller width is 80.

The widths differ, baseline width is not smaller than caller width, and working right exceeds baseline right. The selected adjustment is −20. The left overflow does not override that selection.

### Unequal extents alone do not require a call

Suppose:

- Baseline horizontal boundaries are 0 and 100.
- Working horizontal boundaries are 10 and 90.
- Caller width is 80.

The widths differ, but none of the three selection cases applies. No horizontal call occurs.

### Zero adjustment remains observable

Suppose:

- Baseline horizontal boundaries are 0 and 100.
- Working horizontal boundaries are 0 and 150.
- Caller width is 200.

The caller-width condition selects the left pair. Its difference is zero, but the method is still called with the object, 0, 0, 1, 0.

### Two selected axes produce ordered calls

If the horizontal decision selects an adjustment of −20 and the subsequent vertical decision selects 15, the method calls are ordered:

1. Object, 0, −20, 1, 0.
2. Object, 15, 0, 1, 0.

The second result is conditional on state after the first call; it is not guaranteed to have been predetermined before that call.
