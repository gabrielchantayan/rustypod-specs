## Behavior

### Entry effects

2. Stores the same 16-bit value 14 bytes beyond that address.
3. Stores 16-bit `0x0010` at the address formed by clearing the entry word’s top bit and shifting right by one.
4. Forms the initial **word-read pointer** from the stack anchor shifted left by four.
5. Stores the low byte of the stack anchor shifted right by 12 at `0x0000000B`.
6. Stores 16-bit `0xED38` six bytes beyond the stack anchor shifted right by 12.
7. Reads the fixed cell associated with `0x0897EDE0`, retaining its value for a possible post-call pointer calculation.
8. Writes the address value `0x97ED3800` into overlapping global storage beginning at `0x97ED3800`. The undeclared destination’s exact storage width is not independently supplied.

- Accumulator: `0xFFFFFF0B`.
- Byte-address base: `0x97ED3800`.

- Entry-derived address contribution: entry word shifted left by 14.

### Conditional setup

This path is selected exactly when the entry word’s low 15 bits are nonzero.

The routine then:

1. Writes `0x10` to global storage at `0x225FB880`.
2. Writes `0x18` to the interrupt-labelled global.
3. Reads the fixed cell associated with `0x0897EDE0` again.
4. Uses this second reading as the byte index from `0x97ED3800`, and stores byte `0xCE` there.
5. Reads the global associated with `0x0CE00026`, converts its value to unsigned 32-bit form, and replaces the accumulator with that result.
6. Clears the global storage at `0x0CE00000`.
7. Calls F-U01 with three displayed arguments: the entry word’s low 15 bits shifted right by one, `0xC0`, and address `0x0CE00000`.

The two readings of the cell at `0x0897EDE0` are distinct. The first is retained for later pointer formation; the second supplies the byte-store index. Intervening writes must not be assumed unable to affect that cell.

The read associated with `0x0CE00026` is **not established as a 16-bit read or zero extension**. The representation supplies conversion to unsigned 32-bit form, but no declaration establishing the global’s storage width or signedness. Its value therefore cannot be constrained to `0x0000FFFF` from the supplied evidence.

After F-U01 returns:

1. The word-read pointer becomes twice the value retained from the first `0x0897EDE0` reading.
2. The byte-address base becomes `0x0897ECA0`.
3. The fixed cell associated with `0x0897ECA4` is read and multiplied by `0x20`.
4. A 16-bit `0xECA0` is stored at four times the post-call register value.
5. The descriptor base becomes zero.
6. Another 16-bit `0xECA0` is stored six bytes beyond the fixed-cell product.
7. The store selector becomes `0x10`, and the entry-derived address contribution becomes zero.

The post-call register value is a separate effective dependency output. It must not be equated with an argument or an earlier value.

When the branch condition is false, all conditional operations, including the second fixed-cell read and F-U01, are skipped.

### Common setup

1. Store the low 16 bits of the entry-derived address contribution at that contribution plus `0x30`.
2. Multiply the store selector by `0x02000000`, and store the resulting 32-bit value at that result plus `0x40`.
3. Clear one byte at the descriptor base.
4. Store the 32-bit accumulator at the descriptor base.
5. Store 32-bit `0x40` at descriptor offset `0x28`.
6. Store the descriptor base as a 32-bit value at offset `0x2C`.
7. Replace the accumulator with its bitwise AND with the byte-address base.
8. Form an **address-like value** as eight times the byte-address base minus two.
9. Add the word-read pointer, the incoming stack-slot value, and eight; store this 32-bit sum at twice the sum.
10. Form the initial destination by multiplying the byte-address base by `0x01000000`.
11. Store the byte-address base as a 32-bit value at descriptor offset four.

### Repeating store stage

At each entry to this stage, the routine:

1. Clears one byte at the first destination.
2. Stores the low 16 bits of the address-like value at that destination.
3. Stores the 32-bit payload at that destination.
4. Adds the shared word/increment state to the accumulator.
5. Stores the resulting 32-bit accumulator at the second destination.

On the first entry, both destinations coincide. Four successive writes therefore target the same address: byte clear, halfword store, payload store, and updated-accumulator store.

On later entries, the destinations can differ.

### Repeating call-and-read stage

After the store stage, the loop-control argument is set to zero. Each inner iteration proceeds as follows:

1. Capture the low byte of the current shared word/increment state.
2. Invoke F-U02 with the current loop-control argument.
3. Treat F-U02’s lower result half as an address and store its own low 16 bits there.
4. Multiply the address-like value by `0x40`, and store that 32-bit product at its own address.
5. Read a 32-bit word through the current word-read pointer, replacing the shared word/increment state with that word.
6. Store the low 16 bits of the old word-read pointer plus four at the address-like value plus four.
7. Load a replacement 32-bit word-read pointer from F-U02’s upper result half plus `0x50`.
8. Invoke F-U03, then F-U04, with no displayed arguments.
9. Invoke F-U05 with the word captured in step 5.
10. Invoke F-U06 with that word logically shifted right by three.
11. Retain F-U06’s upper result half as a destination pointer.
12. Multiply F-U06’s lower result half by `0x20`, retaining 32 bits, and store that product at its own address.
13. Compare the product unsigned against `0x14`.

The word read in step 5 does not merely supply call arguments: it overwrites the same state previously used as the running increment.

Because the product’s low five bits are zero under 32-bit truncation, “less than `0x14`” is equivalent to a zero product.

For a zero product, execution leaves the inner iteration and enters another call-and-read iteration with loop-control argument zero. It does **not** repeat the store stage. The shared word/increment remains the word read in step 5, so the next iteration captures that word’s low byte.

### Nonzero-product continuation

For a nonzero product, execution continues:

1. Store the 32-bit address-like value at product plus `0x58`.
2. Store the low 16 bits of the replacement word-read pointer at the address-like value plus `0x0E`.
3. Replace the shared word/increment state with the address-like value shifted left by two.
4. Write the byte captured before F-U02 to the reset-labelled global.
5. Invoke F-U07 with the replacement word-read pointer logically shifted right by two.
6. Invoke F-U08 without displayed arguments.

F-U08’s represented 64-bit result then supplies the second destination from its upper half and an eight-byte-store base from its lower half. The routine:

1. Stores the captured byte at twice that lower-half base.
2. Stores the low byte of the upper half at base plus eight.
3. Stores F-U06’s upper-half pointer as a 32-bit value at twice the current accumulator.
4. Stores the complete eight-byte F-U08 result at the lower-half base.
5. Replaces the accumulator with F-U06’s upper-half pointer shifted left by two.
6. Replaces the address-like value with the current word-read pointer shifted left by eight.
7. Writes three consecutive 32-bit words through F-U06’s upper-half pointer: the shared word/increment state, the updated address-like value, and the current word-read pointer.
8. Sets the next payload to the shared word/increment state multiplied by `0x100`.
9. Sets the next first destination to zero.

No allocation or eight-byte object extent is established. In particular, the byte at base plus eight lies immediately beyond the eight-byte store region.

The subsequent selector calculation includes interpreting the word-read pointer as signed 32-bit, shifting left by 31, shifting that signed result right by 32, converting to unsigned 32-bit, and shifting logically right by 20. Its meaning is **documented_only**: signed-shift issues and a shift count equal to the operand width prevent a justified normalized result.

If the selector is zero, execution returns directly to the store stage.

If nonzero, the routine stores the 32-bit selector at payload plus `0x20`, derives the next loop-control argument by signed right shift of the payload by 29, and executes software breakpoint 4. If execution continues, the address-like value becomes the signed interpretation of the second destination shifted right by 18, converted to its 32-bit stored form. Execution proceeds to another inner iteration without repeating the store stage or resetting that loop-control argument.
