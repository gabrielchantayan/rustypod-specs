# F-9ac3b87b26f9

## Purpose

F-9ac3b87b26f9 selectively applies request fields to a destination object. A 32-bit request mask selects the fields. A non-null force indicator enables application despite equal comparison values, except that the first field has additional eligibility requirements.

The operation optionally produces three 32-bit reporting masks:

- Category A and category B, stored as two consecutive words.
- An applied-request mask identifying application branches that executed.

These reports describe application, not independently verified changes in destination values. Forced writes, narrowing, normalization, helper behavior, and an unconditional transformation can produce nonzero reports even when destination values remain unchanged.

**Inferred intent:** selective object updates with categorized change reporting and one notification operation. Domain-specific meanings of the fields and categories are not established.

## Interface

The function accepts five arguments and has no return value.

| Argument | Required behavior |
|---|---|
| Request | Address of a record whose first 32-bit word is the selection mask. Additional fields occur at the offsets specified below. |
| Destination | Address of mutable storage. Its first 32-bit word supplies an embedded address used by several dependencies. |
| Force indicator | Null disables forced application; any non-null value enables it. This function does not dereference the indicator. |
| Category output | Optional address of two writable, consecutive 32-bit words. |
| Applied output | Optional address of one writable 32-bit word. |

All offsets below are byte offsets. Words, halfwords, and bytes are respectively 32, 16, and 8 bits. Mask operations use 32-bit bit patterns. Narrow stores retain the low-order bits unless normalization is specified.

Request and destination storage must be valid for every reached access. Embedded-address operations require valid storage at the resulting interior addresses. Supplied outputs must be writable. There are no visible request or destination null checks, bounds checks, address-overflow checks, or error returns.

The highest directly accessed request word starts at `0x1254`; helper data is also passed by address at `0x1258`. The highest directly accessed destination word starts at `0x0098`. These are not complete size requirements: helper-accessed extents remain unknown.

The interface establishes no non-aliasing guarantee. The request mask is reread before successive field branches, rather than captured for the entire invocation. Earlier writes or dependency effects can therefore alter later selections or values.

## Behavior

### Processing and reporting rules

Category A, category B, and the applied-request mask initially contain zero. Fields are processed in the order presented below.

An application adds its request bit to the applied-request mask and its designated category bits to the category masks. Contributions accumulate by bitwise OR.

For ordinary direct fields, application occurs when the field is selected and its comparison differs, or when selected and forced. Force does not generally eliminate the comparison-side reads: direct-field conditions evaluate comparisons before considering force.

For helper-mediated fields, force instead bypasses the retrieval and comparison calls entirely. Without force, only an exactly zero comparison result permits application. Any nonzero result, including `0xFFFFFFFF`, suppresses it.

Application-dependency return values are not checked. When such a call returns normally, its branch reports application without establishing that the dependency changed storage or succeeded according to any external convention.

### Paired halfword fields

Request bit `0x00000040` selects this operation:

- Compare unsigned destination halfword `0x0084` against the full request word `0x1008`.
- Only if equal, compare unsigned destination halfword `0x0086` against the full request word `0x100C`.
- If either comparison differs, or force is enabled, store the low halfword of the captured first request word at destination `0x0084`.
- After that store, read request word `0x100C` again. If its unsigned 32-bit value is below the low halfword of the captured first word, replace it with zero.
- Store the resulting low halfword at destination `0x0086`.

Application contributes category A `0x00000200`. The full-width comparisons precede narrowing and normalization. A request with nonzero upper bits can consequently trigger application despite identical stored low halfwords.

Request bit `0x00800000` selects a second pair:

- Compare unsigned destination halfword `0x0088` against the low halfword of request word `0x1248`.
- Only if equal, compare destination halfword `0x008A` against request halfword `0x124A`.
- On application, store the captured first requested halfword at `0x0088`.
- Then reread request halfword `0x124A`. Replace it with zero if it is below the captured first halfword.
- Store the resulting halfword at `0x008A`.

Application contributes category B `0x00000001`.

For both pairs, the first store precedes the second requested-value read. Aliasing can therefore affect the second value. Comparisons occur before normalization, so application can be reported even when the normalized pair equals the existing pair.

### Masked and byte-sized fields

Three final update branches follow.

**Bit `0x00020000`: masked word merge.** Request word `0x103C` supplies desired bits; request word `0x1040` selects which bits to replace in destination word `0x001C`. The candidate retains destination bits outside that mask and takes requested bits inside it. The complete candidate is compared with the destination and stored when different or forced. Application contributes category A `0x01000000`.

The representation references the request mask twice while forming the candidate. It does not establish a single captured mask or a total order for the expression’s operand reads.

**Bit `0x00400000`: single destination flag.** Compare the low byte of request word `0x1244` against the Boolean value of destination byte `0x0015`, bit `0x02`. On application, reread the destination byte, preserve its other bits, and set bit `0x02` from the requested byte’s low bit. Application contributes category A `0x80000000`.

The comparison uses the entire requested byte, but storage uses only its low bit. A requested byte of `2` differs from both Boolean comparison values and stores a clear flag.

**Bit `0x01000000`: capped byte.** Read unsigned request halfword `0x1246` and cap it at 100. Compare the capped value against the sign-extended destination byte `0x007E`. Store when different or forced. Application contributes category B `0x00000002`.

Requests above 100 become 100, not zero. A destination byte whose signed interpretation is negative differs from every allowed candidate.

### Final reporting writes

After all field branches and dependency calls:

1. If category output is non-null, write category A to its first word.
2. Write category B to its second word.
3. If applied output is non-null, write the applied-request mask.

Existing output contents are replaced, not merged. An invocation in which no application branch executes writes zero to every supplied reporting word.

An invocation that leaves destination values unchanged may nevertheless write nonzero reports. Output aliasing is resolved by the stated write order; no later request-field processing follows these writes.

## Side effects

Direct effects comprise destination writes, the first branch’s explicit flag clearing, optional output writes, dependency calls, and the notification-argument global read.

No allocation, deallocation, or global-addressed write is directly visible. This does not establish their absence inside dependencies. An aliased destination or output can also modify storage used elsewhere, including request or global storage.

The operation is not established as atomic or transactional. There is no visible rollback or function-level error conversion. If a dependency does not return normally, later stores and reports are not guaranteed to occur.

No ownership transfer is established. Dependencies receive request addresses, destination addresses, temporary storage, and transformation results, but their retention, copying, allocation, release, and consumption rules are unknown. In particular, F-2cc81f862671 must not be assumed to preserve or release either argument.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless otherwise stated, assume valid non-overlapping storage, stable inputs, and dependencies that return normally without unrelated mutations.

1. **Empty selection.** A zero request mask produces no field dependency calls or direct destination writes. Supplied reports receive three zero words.

2. **Forced helper.** Selecting only `0x00000004` with force enabled invokes F-a25208a91ecc but neither F-d84a46f01e0d nor F-1a331ff73558. Applied output is `0x00000004`; category A is `0x08000004`.

3. **First-field restrictions.** With `0x00000001` selected, force does not permit application if the low request halfword at `0x0008` is zero or destination byte `0x0014` has bit `0x10` set.

4. **Helper suppression.** Without force, comparison results `1` and `0xFFFFFFFF` both suppress application. Zero permits it.

5. **Ordered normalization.** Selecting `0x00000800` and `0x00001000`, with requested limit 10 and dependent value 11, makes the dependent candidate zero after processing the limit. Its applied bit is set only if its destination differs from zero or force is enabled.

6. **Unchanged normalized pair.** For `0x00000040`, destination pair `(5, 0)` and full-width request pair `(5, 3)` trigger application but leave the pair `(5, 0)`. Reports include applied `0x00000040` and category A `0x00000200`.

7. **Repeated transformation.** Selecting only `0x00010000` invokes F-00b046cf541b and F-f2b8ff34d9f0 twice each, and F-2cc81f862671 once. Equal old and final values do not suppress reporting.

8. **Masked no-op.** A zero merge mask preserves the destination word. Without force, no application is reported; with force, the preserved value is written and application reported.

9. **Noncanonical flag.** Request byte `2` with an already-clear destination flag triggers application, leaves the flag clear, and contributes category A `0x80000000`.

10. **Notification global read.** If an earlier dependency changes the notification’s global argument storage and it remains unchanged afterward, a later executed notification branch receives that updated value. The function does not use an entry-time snapshot.

11. **Output overlap.** If applied output addresses the first category-output word, that word finally contains the applied mask because it is written last.
