# F-9d6b3812132d

## Purpose

F-9d6b3812132d coordinates an initial dependency operation, a primary two-input operation, an optional follow-up operation, and a conditional transfer of a 16-bit field.

Its externally visible result is the 32-bit value returned by the primary operation, F-a3c410f12096. Subsequent dependency calls and the conditional field transfer do not replace that result.

The field transfer is gated by three observations: the field at offset 0xE6 from the first input is nonzero, the second input is nonzero, and a field at offset 0x80 from a subsequently obtained address is zero. When those conditions hold, another address is obtained and a freshly read 16-bit source value is stored at offset 0x80 from that address.

This description establishes sequencing and data movement. It does not establish the application-level meaning of either field, the role of the dependency-provided addresses, or whether successive address-producing calls return the same object.

The function takes two inputs represented as 32-bit integer values in the supplied static representation:

- **Control value:** The second input is forwarded unchanged to F-a3c410f12096. Within this function, it is tested only for equality or inequality with zero.

The control value is not normalized before forwarding. Any nonzero value satisfies this function’s nonzero tests, but different nonzero values may have different meanings to F-a3c410f12096.

The object address is not merely an opaque integer: a normal completion requires a readable two-byte field at its offset 0xE6. That read occurs even when the control value is zero.

### Optional follow-up operation

If the control value is nonzero, the function invokes F-5c5958cfd5fe with no explicit arguments.

This call occurs after F-a3c410f12096 returns and before the source field is examined for the conditional transfer. Its return value is not used.

The function does not condition this call on the primary operation’s result.

### Transfer eligibility

After the optional follow-up operation, the function reads the 16-bit field at the object address plus 0xE6.

The conditions are evaluated in the following order:

1. The newly read source field must be nonzero.
2. The control value must be nonzero.
3. A further F-fdd8589eca2d invocation must return an address whose 16-bit field at offset 0x80 is zero.

Consequently:

- A zero control value does not prevent the source-field read.
- A zero source field prevents the second F-fdd8589eca2d invocation.
- A nonzero source field combined with a zero control value also prevents that invocation.
- The destination-field read is reached only when both earlier conditions pass.

The source-field observation occurs after all preceding calls. It is not a snapshot taken on function entry.

### Conditional transfer

When the destination-field observation is zero, the function invokes F-fdd8589eca2d once more.

After that invocation returns, the function rereads the 16-bit field at the original object address plus 0xE6 and writes those 16 bits to offset 0x80 from the newly returned address.

Two distinctions are essential:

- **The write address is newly obtained.** The function does not reuse the address whose field was checked for zero.
- **The source value is newly read.** The function does not reuse the nonzero value that originally enabled the transfer.

No zero check is performed on the final write destination. No second nonzero check is performed on the freshly read source value.

Therefore, if an intervening dependency changes the source field to zero, the function can write zero. If the last address-producing call returns a different object, the function can write an object other than the one whose field was checked.

The established final direct-access order is: obtain the final address, read the source field, then write the destination field.

### Completion

On normal completion, the function returns the retained 32-bit result from F-a3c410f12096.

There is no explicit early return, retry, rollback, or alternate result for any of the transfer conditions.

## Acceptance examples

These are conditional contract examples, not runtime test results. Each assumes valid reached accesses and normally returning dependencies.

This outcome depends on address stability; the function does not enforce it.
