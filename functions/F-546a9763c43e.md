# F-546a9763c43e

## Purpose

F-546a9763c43e updates a caller-supplied object, conditionally performs an activation sequence, and may insert an embedded record into a global singly linked list.

The established behavior includes several early returns. Every invocation first sets two object bytes to one, including invocations that perform no further work. Later paths can clear another byte, initialize an embedded record, copy global state into the object, and link that record into the list.

**Inferred intent:** the embedded record appears to represent a scheduled activity. One field is multiplied by 1,000 and added to a value returned by a clock-like dependency; a comparator determines list placement. The source does not establish the units, clock semantics, comparator ordering, or synchronization guarantees. These interpretations are not requirements.

## Behavior

### 1. Unconditional byte updates and classification gates

The first observable writes are:

1. Store byte value one at object offset `0x69`.
2. Store byte value one at object offset `0x6A`.

The function then reads the four-byte field at `0xD0` and passes it to F-342542431c39.

- If that call returns `0x6038`, the function returns immediately.
- Otherwise, the function reads `0xD0` again and calls F-342542431c39 again.
- If the second call returns `0x603B`, the function returns immediately.

These are two separate calls with separately read arguments. The function does not cache either the argument or the first result. A dependency may change the object or global state between calls.

The comparisons are asymmetric: `0x603B` from the first call does not itself cause a return, and `0x6038` from the second call does not itself cause a return.

### 2. Initial action sequence

If neither classification gate returns, the following actions occur in order:

1. Call F-unknown-01 with the object address and two scalar arguments, both one.
2. Call F-unknown-02 with scalar arguments zero and `0x20`.
3. Call F-unknown-03 without explicit arguments.
4. Store byte value zero at object offset `0x68`.
5. Call F-c60499d3eebf without explicit arguments.

If F-c60499d3eebf returns any nonzero value, the function returns. In particular, this path has already cleared `0x68`, but it has not reached the visible embedded-record initialization or either global-value copy.

### 3. Embedded-record initialization and membership gate

If F-c60499d3eebf returns zero:

1. Read the 32-bit default value G2.
2. Read the address held by G1, then read one byte through that address.
3. Select 200 instead of the default if and only if that byte equals one.
4. Call F-6904f7699031 with the embedded-record address, object offset `0x6C`, and the selected 32-bit value.
5. Call F-936a8728139d without explicit arguments.
6. Read G3 and store it as four bytes at object offset `0x8C`.
7. Read the four-byte field at object offset `0x88`.

If the last field is nonzero, the function returns.

The mode test is exact equality with one, not a general nonzero test. Values such as two or `0xFF` select G2.

The membership gate observes the field after both dependencies and the `0x8C` store. Its value need not match the value present on entry. The initializer may also change the scheduling quantity subsequently read at `0x70`; that behavior is not established here.

### 4. Preparation and optional list insertion

If the membership gate observes zero:

1. Read the address-valued content of G4 and pass it to F-338d16f9ce72.
2. Call F-add44d4e9aaa with the embedded-record address.
3. Read the four-byte scheduling quantity at object offset `0x70`.

If that quantity is zero, the function skips list insertion and proceeds to the post-list phase. It does not itself write the calculated ordering value, the `0x84` field, the membership field, or the record’s next link on this branch. Earlier dependencies may have written them.

If the quantity is nonzero:

1. Call F-unknown-04 without explicit arguments and retain its 32-bit result.
2. Read from G5 the address of the list-head cell.
3. Calculate the ordering value from the retained scheduling quantity multiplied by 1,000, plus the result of F-unknown-04.
4. Store the four-byte calculated value at object offset `0x74`.
5. Read G6 and store its four-byte value at object offset `0x84`.
6. Read the first node address from the captured list-head cell.
7. Traverse the list to select an insertion position.
8. Publish and complete the insertion using the write order below.

The scheduling quantity is retained across F-unknown-04; the function does not reread `0x70` after that call. Conversely, G5 is read after that call. The captured list-head-cell address remains the destination for a possible head insertion even if later comparator calls change G5.

### 5. Traversal rule

Traversal begins with the first node and no predecessor.

For each non-null candidate node, call F-0d70d6f9010c with:

- The address eight bytes beyond the candidate node’s address.
- The address of the new record’s calculated ordering value, object offset `0x74`.

If the comparator returns nonzero, stop at that candidate.

If it returns zero, read the candidate’s four-byte next link, retain the candidate as predecessor, and continue with the next node.

Reaching a null candidate also stops traversal. No comparator call is made for null.

Consequently, insertion occurs immediately before the first candidate producing a nonzero comparator result, or at the end if every result is zero. No stronger ascending, descending, equality, or stability rule can be assigned without the comparator’s contract.

### 6. Insertion write order

After traversal stops:

1. If there is no predecessor, store the embedded-record address in the captured list-head cell. Otherwise, store that address in the predecessor’s next-link field.
2. Store four-byte value one at object offset `0x88`.
3. Store the stopping candidate address, possibly null, in the new record’s next-link field at object offset `0x6C`.

The incoming link is therefore published **before** the new record’s next link is finalized. An observer able to interleave with these writes could encounter a partially updated list. The visible function does not establish whether external synchronization prevents such observation.

### 7. Post-list phase and terminal dispatch

Both the zero-quantity branch and the completed-insertion branch continue as follows:

1. Read G7 and call F-5bcae2eff9a7 with that value.
2. Independently reload the address held by G4.
3. Read a four-byte pointer through that address.

5. Otherwise, read the first four bytes at that pointer.

7. Otherwise, invoke the indirect target G8 without explicit arguments.

The pointer read through G4 is not necessarily the pointer value involved in the earlier F-338d16f9ce72 call. Intervening dependencies may change G4 or its referent.

No further local processing is visible after the indirect invocation.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, dependencies return normally and do not introduce additional mutations.

1. **First classification match.**  
   If the first F-342542431c39 result is `0x6038`, the function performs the two initial byte stores and returns. It makes no second classification call.

2. **Distinct second classification observation.**  
   If the first result is `0x603B` and the second result is `0x6038`, neither classification gate returns. The initial action sequence follows.

3. **Gate after byte clearing.**  
   If both classification gates pass and F-c60499d3eebf returns a negative nonzero 32-bit value, `0x68` has already been cleared. Embedded-record initialization is not reached.

4. **Exact mode-byte selection.**  
   If G2 is 500 and the byte reached through G1 is one, F-6904f7699031 receives 200. If that byte is two, it receives 500.

5. **Membership established during initialization.**  
   If initialization or F-936a8728139d leaves `0x88` nonzero, the G3 copy still occurs, but F-338d16f9ce72 and list processing do not.

6. **Zero scheduling quantity.**  
   If the membership gate passes and the quantity read after F-add44d4e9aaa is zero, there is no call to F-unknown-04 or the comparator. F-5bcae2eff9a7 and the terminal pointer checks still occur.

7. **Empty-list insertion.**  
   If the quantity is three, F-unknown-04 returns 10,000, and the captured list is empty, the stored ordering value is 13,000. The record becomes the head, its membership field becomes one, and its next link becomes null, in that order.

8. **Insertion between two candidates.**  
   If the comparator returns zero for the first node and nonzero for the second, the first node’s next link is changed to the new record. The new record’s next link is subsequently set to the second node.

9. **Terminal dispatch suppression.**  
   After F-5bcae2eff9a7, either a null pointer read through G4 or a zero first word at the pointed-to object suppresses the indirect invocation. A non-null pointer with a nonzero first word reaches it.
