# F-2f08c319482d

## Purpose

F-2f08c319482d conditionally updates selected fields of a supplied record. It accepts a mode, a format selector, a size-like value, and an auxiliary value. On success, it stores the supplied configuration, derives an effective size when the supplied size is zero, and copies an existing record field into another field.

On failure, it may record a selected value in the record’s first integer slot, but only when that slot is zero. It does not clear an existing first-slot value on success.

“Mode,” “format,” “size,” and “error-like value” describe observable roles, not established application semantics. The contract below separates behavior established by the supplied body from conditional interpretations and unresolved execution details.

## Behavior

### Unconditional selector preparation

Before either recognition check, the function performs these source-level operations in order:

1. Read the base selector and retain that value plus 10.
2. Read the base selector again and retain that value plus 4.

These are separate reads, not an expressly preserved snapshot. Both occur even when the format is the fixed selector 5120.

The additions are signed-integer expressions in the supplied representation. No overflow check is present. Ordinary behavior described here requires those additions to be defined; modular wraparound is not established.

### First recognition check

The first check recognizes a format through these alternatives, in order:

1. Format equals 5120.
2. Otherwise, format equals a newly read base selector.
3. Otherwise, format equals the retained plus-10 selector.
4. Otherwise, format equals the retained plus-4 selector.

The direct base-selector read occurs **only if the format is not 5120**. A match against 5120 short-circuits that read. For every other format, the direct base read occurs before either retained-selector comparison, even when a retained selector will match.

If none of the alternatives matches, the working mode becomes 1280. Otherwise, it remains the supplied mode.

No destination access occurs during this check.

### Second recognition check

The function independently repeats the same recognition alternatives:

1. Format equals 5120.
2. Otherwise, format equals another newly read base selector.
3. Otherwise, format equals the retained plus-10 selector.
4. Otherwise, format equals the retained plus-4 selector.

Again, the direct base-selector read occurs exactly when the format is not 5120. This read is independent of the first recognition check’s direct read.

If this check rejects the format, the function proceeds to failure handling with the **current working mode** as its selected value. It does not read the global failure value.

If this check accepts the format, the function reads the global failure value before checking the working mode or size. That read occurs even when the update subsequently succeeds.

### Mode and size eligibility

After the second check accepts the format:

- The working mode must be 2, 3, or 4.
- The size must be nonnegative.

The mode test uses unsigned subtraction by 2 followed by comparison with 3. Under the ordinary corresponding signed/unsigned integer interpretation, it accepts exactly 2, 3, and 4. It does not require a potentially overflowing signed subtraction.

The size comparison is reached only if the mode test passes.

If either eligibility condition fails, the previously read global failure value is used for failure handling.

An unsuccessful first recognition check prevents success: it replaces the working mode with 1280, which cannot pass the mode test, even if the second recognition check later accepts the format.

### Effective-size selection

Once recognition, mode, and size permit success:

- A positive size becomes the effective size unchanged.
- A zero size is derived using the following precedence.

| Zero-size condition, in order | Effective size |
|---|---:|
| Format equals 5120 | Working mode |
| Otherwise, format equals a newly read base selector | Twice the working mode |
| Otherwise, format equals either retained derived selector | Four times the working mode |
| Otherwise | Zero |

The base-selector read in this derivation occurs **only on a successful path with size zero and format other than 5120**. There is no derivation-time base read for a positive size, for format 5120, or on a failed update.

The retained-selector comparisons in this derivation check the plus-4 selector before the plus-10 selector. Both produce the same effective size.

The final zero case is reachable if changing base-selector values allowed recognition through a direct base match but the derivation-time read no longer matches, and neither retained selector matches. Success is not revoked in that case: the function stores an effective size of zero.

With stable base-selector values and defined preparation arithmetic, every recognized format matches one of the first three derivation cases. The possible derived values are then:

- Fixed selector: 2, 3, or 4.
- Base selector: 4, 6, or 8.
- Either derived selector: 8, 12, or 16.

The multiplication-by-two and multiplication-by-four operations are expressed as shifts, reached only for modes 2 through 4. Their results fit the ordinary integer interpretations relevant to the supplied representation.

A positive size is not checked against the derived value. No additional minimum, alignment, or format-specific size constraint appears.

### Successful record accesses

2. Write the supplied format to slot 85.
3. Write the auxiliary value to slot 86.
4. Write the effective size to slot 91.
5. Read slot 694.

The source field is read after the four configuration writes; its copied value is not an entry-time snapshot.

Success neither reads nor writes slot 0. A previously recorded nonzero value there remains unchanged.

### Failure selection and sticky recording

The selected failure value depends on how evaluation stops:

| Condition | Selected value |
|---|---|
| Second recognition check rejects | Current working mode |
| Second recognition accepts, but mode or size fails | Global failure value read after recognition |

With a stable base selector, this simplifies to:

| Stable-base failure condition | Selected value |
|---|---|
| Unrecognized format | 1280 |
| Recognized format with invalid mode | Global failure value |
| Recognized format with valid mode and negative size | Global failure value |

The more general rule matters when repeated base reads differ. If the first check accepts but the second rejects, the selected value is the original supplied mode, which may be positive, negative, or zero.

Recording then follows these rules:

- A selected value of zero causes return without any destination access.
- A nonzero selected value causes a read of slot 0.
- If slot 0 is zero, the selected value is written there.
- If slot 0 is nonzero, it is preserved.

Negative selected values are treated as nonzero and can be recorded. Failure writes none of the successful-update fields.

No explicit return status distinguishes success, a newly recorded failure, preservation of an earlier failure, or failure without a destination access.
