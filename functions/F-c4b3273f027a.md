## Behavior

### 1. Establish the offset basis

The first input byte is read and interpreted as an unsigned value.

If that byte is at most 127, its value directly becomes the offset basis. No first-stage dependency call occurs, and the fourth input has no further direct role.

If the first byte is greater than 127:

- A writable 32-bit offset slot is initialized with the fourth input.
- F-887200f76f20 is invoked with the original input pointer and the address of that slot.
- After the call returns, the slot’s current value becomes the offset basis.

The first-stage dependency’s return value is not used. Communication back to this function occurs through the writable slot.

There is no requirement in the supplied body that the dependency actually modify the slot. If it leaves the slot unchanged, the fourth input remains the offset basis. There is also no validation that a modified value is positive, small, or within accessible storage.

### 2. Select the terminal address

The function subtracts one from the offset basis using unsigned 32-bit arithmetic and uses the result as a byte displacement from the original input pointer.

This means:

- An offset basis of 1 selects the first byte.
- An offset basis of 2 selects the second byte.
- An offset basis of 127 selects the byte at displacement 126.
- An offset basis of 0 produces the unsigned displacement 4,294,967,295.

The zero case is not checked or rejected. It must not be silently interpreted as an ordinary signed displacement of negative one. Whether the resulting address can be formed or read depends on the execution environment and valid storage; neither is established here.

A large value produced by the first dependency is likewise used without a range check.

### 3. Obtain a candidate and decide whether to invoke the second stage

At the selected terminal address, the supplied body contains two byte-value evaluations in this order:

1. A byte is read, converted to unsigned form, and retained as the direct candidate.
2. The byte at the same selected address is evaluated for comparison against 127.

If the second evaluation is at most 127, no second-stage dependency call occurs. The retained candidate from the first evaluation becomes the final value.

If the second evaluation is greater than 127:

- F-887200f76f20 is invoked with the selected terminal address.
- Its second argument points to a separate writable 32-bit value slot initialized with the third input.
- After the dependency returns, the current contents of that slot become the final value, replacing the direct candidate.

The first dependency call, when present, receives the offset slot. The second dependency call, when present, receives the value slot. They are distinct slots with different initial values and different subsequent uses.
