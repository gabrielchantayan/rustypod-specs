# F-6f94a635d8a0

## Purpose

F-6f94a635d8a0 coordinates preparation, two status-producing operations, a numeric notification, and conditional replacement of a pair of callback-related values in nested object state.

Two distinct decisions govern its behavior:

- If either status-producing operation returns a nonzero 32-bit result, the function performs three indirect calls and emits a fixed numeric event. This path also replaces the callback-related values subsequently considered for installation.
- Independently of that status decision, the function compares the effective pair against stored state. It writes both members and invokes a state notification dependency only when the comparison detects a difference.

The preparation and numeric notification occur even when the stored pair ultimately requires no update.

These are established structural behaviors. The meanings of the statuses, numeric notification, event, and callback pair are not established. In particular, the nonzero-status path must not be characterized as successful recovery, fatal failure, or an exception without additional evidence.

## Interface

### Inputs

The function receives four arguments:

1. **Object reference.** A reference to an object containing:
   - At byte offset `0x00`, a reference to an indirect-call table.
   - At byte offset `0x5C`, a 32-bit value supplied to several dependencies.
   - At byte offset `0xA8`, a reference or address-like value used to reach another structure.

2. **Operation value.** An opaque 32-bit value passed to F-35a07fb3384a.

3. **First callback-related value.** Represented as a function address. In the ordinary path, it is compared with and potentially stored in the second member of a nested pair.

4. **Second callback-related value.** Also represented as a function address. In the ordinary path, it is compared with and potentially stored in the first member of that pair.

The ordering is significant: the fourth argument corresponds to the stored member at offset `0xB7C`; the third argument corresponds to the member at offset `0xB80`.

### Referenced layouts

The indirect-call table is accessed at byte offset `0x58`. That entry is invoked on the nonzero-status path.

The structure referenced through object offset `0xA8` contains another reference at byte offset `0xF00`. The structure reached through that reference contains the pair:

| Offset | Observed role |
|---|---|
| `0xB7C` | First stored callback-related value |
| `0xB80` | Second stored callback-related value |

The supplied representation uses four-byte object slots and address-sized values consistent with a 32-bit environment. This contract does not establish equivalent behavior for a different pointer width or object layout.

### Output

No explicit result value is returned. Observable results consist of dependency calls, indirect calls, and possible writes to the stored pair.

### Preconditions

For a defined execution of the displayed accesses:

- The object and every dereferenced structure must be accessible with the indicated layout.
- The nested pair must be readable and, when changed, writable.
- Any indirect-call entry actually invoked must identify a callable target compatible with the arguments supplied at that invocation.

The function performs no explicit null checks or accessibility checks. A zero callback-related value is not directly rejected; this function stores and compares such values rather than invoking the incoming callback arguments.

## Behavior

### 1. Preparation and status collection

The function first reads the value at object offset `0x5C` and passes it to F-6134d252a6a2. No result from that call is used.

It then performs the following operations in order:

1. Reads the value at object offset `0xA8` and calls F-35a07fb3384a with that value and the operation value. Its 32-bit result is retained.
2. Reads the value at object offset `0x5C` and calls F-ff7fc0e24b4c.
3. Calls F-77a61791e17c with the object’s `0xA8` value and the result of the preceding call. Its 32-bit result is retained.

The object fields are read for their respective uses; there is no established snapshot of both fields for this entire phase. Earlier dependencies may therefore affect values observed by later reads.

Both retained status-producing calls occur before the function tests whether either result is nonzero. A nonzero result from the first does not bypass the second.

### 2. Numeric notification

The function next:

1. Reads the object’s `0x5C` value and calls F-8eca0b4255c0, interpreting the obtained value as a signed 16-bit quantity.
2. Reads the object’s `0x5C` value again and calls F-ff7fc0e24b4c a second time.
3. Selects the 32-bit value `0x3C` if this second F-ff7fc0e24b4c result is nonzero, or zero otherwise.
4. Calls F-80acfbd3a2c5 with:
   - The signed 16-bit quantity, sign-extended to a 32-bit integer.
   - The selected zero-or-`0x3C` value.

The two calls to F-ff7fc0e24b4c are separate observations. The first result feeds F-77a61791e17c. The second controls the numeric notification. Their results need not agree.

For the signed conversion, a 16-bit representation of `0xFFFF` produces a first notification argument of −1, not 65535. The second argument is exactly zero or decimal 60; it is not a scaled form of the dependency result.

### 3. Conditional indirect-call sequence

After the numeric notification returns, the function captures one global 32-bit value. Call this **G-base**. The labels here describe observed roles only, not application semantics.

If both retained status results are zero, the indirect-call sequence is skipped and the original callback-related arguments remain the effective pair.

If either result is nonzero, the function performs this sequence:

1. Resolves the object’s indirect-call entry at table offset `0x58` and calls it with:
   - The object reference.
   - A read of the G-base global.
   - A read of a separate global, **G-first**.

2. Resolves the entry at offset `0x58` again and calls it with:
   - The object reference.
   - The previously captured G-base value.
   - A read of another global, **G-second**.

3. Resolves the entry at offset `0x58` again and makes that target the effective fourth argument.
4. Reads a further global, **G-replacement**, and makes it the effective third argument.
5. Calls the effective fourth argument with only:
   - The object reference.
   - The previously captured G-base value.

6. Calls F-416575e983b4 with the 32-bit constant `0x60000004`.

The third indirect invocation has two explicitly supplied arguments, whereas the first two have three. G-replacement is assigned as a callback-related value; it is not explicitly supplied as a third argument to that invocation.

The target is resolved separately for all three indirect calls. A preceding call can therefore change which target a later invocation uses. The effective fourth argument is the target selected for the third invocation, not necessarily the target used by the first or second invocation.

The captured G-base value is reused by the second and third calls. The first call instead contains a separate read of the same global. No dependency call appears between the initial capture and that first invocation, but concurrent mutation and other external behavior are not specified.

The function does not explicitly return after F-416575e983b4. If that dependency returns normally, execution continues into pair comparison. Whether it returns, terminates execution, or transfers control elsewhere is unknown.

### 4. Pair comparison

After any conditional sequence, the function reads the object’s `0xA8` field and retains that structure reference for the final phase.

It then calls F-08fb88178805 with two addresses into caller-local stack storage. The meanings and precise identities of those stack locations are not established by the supplied evidence. This call precedes the nested-state lookup and comparison.

The function reads the nested reference at offset `0xF00` from the retained structure and examines the pair:

- It first reads the member at `0xB7C` and compares it with the effective fourth argument.
- Only if that comparison is equal does it read the member at `0xB80` and compare it with the effective third argument.

If the first member differs, the second member is not read for comparison.

The ordinary interpretation is that the effective values are the incoming pair on the zero-status path, or the replacement pair selected on the nonzero-status path. Effects of F-08fb88178805 on the passed stack storage remain an explicit uncertainty; its behavior must not be assumed to be inert.

### 5. Conditional writes and notification

If both comparisons establish equality, the function performs no explicit pair writes and does not call F-e0ba31379901.

If either compared member differs, the function:

1. Writes the effective fourth argument at offset `0xB7C` in the nested structure already obtained for comparison.
2. Re-reads the nested reference at offset `0xF00` from the retained outer structure.
3. Writes the effective third argument at offset `0xB80` in the structure reached by that re-read.
4. Re-reads the nested reference at offset `0xF00` again.
5. Calls F-e0ba31379901 with the value obtained by the final re-read.

Both writes occur on the update path, even if only the second comparison found a difference. The first write may therefore rewrite an already-equal member.

The nested reference is not held constant across comparison, both writes, and notification. Under stable memory, these operations address the same nested structure. If the reference changes through aliasing or external activity, that identity is not guaranteed.

## Acceptance examples

These are conditional expectations derived from static evidence, not results of executed tests. They assume normal dependency returns, valid memory, and no unmentioned mutation.

- Preparation and numeric notification still occur.
- No conditional indirect calls occur.
- F-08fb88178805 is called.
- Both pair members are read for comparison.

- Both pair members are written, in first-member then second-member order.
- F-e0ba31379901 is called after the writes with a freshly read nested reference.

### Only the second member differs

- Both members are written, including the already-equal first member.
- One call to F-e0ba31379901 follows the writes.
