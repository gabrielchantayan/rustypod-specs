# F-07fdf92fa582

## Purpose

F-07fdf92fa582 conditionally invokes two update dependencies for an object obtained from F-7fba0909c452. Three flag bits select the operations. An object-resident mode selector changes the order of two transformations and the context used for dispatch.

The established behavior includes:

- Acquiring an object and capturing a signed 32-bit scaling global.
- Returning early if the object or its initial handle is zero.
- Rejecting flags outside the permitted mask, with a conditional fallback write to the object's first word.
- Optionally passing two local slots through transformation dependencies and a first dispatch.
- Optionally computing a scaled argument and performing a second dispatch.

The application meanings of the object, handle, fields, and updates are unknown. “Handle,” “mode,” and “scaling” describe their observable roles rather than established domain semantics.

This is a static behavioral contract. Acceptance examples are conditional expectations, not executed tests.

## Behavior

### Acquisition and early exits

F-7fba0909c452 is called first, without explicit arguments. Its return supplies the object address.

The scaling global is then read and captured. This read occurs even when acquisition returns null. Later changes to that global do not replace the captured operand.

If the object is null, the function returns without accessing object storage.

Otherwise, the handle at `0xAE0` is read. A zero initial handle causes an immediate return. This precedes flag validation: invalid flags do not cause fallback initialization when the initial handle is zero.

### Flag validation and fallback write

With a nonzero initial handle, the flag word is accepted exactly when no bits outside `0x4500` are set. Equivalently, its intersection with `0xFFFFBAFF` must be zero.

The permitted bits are:

- `0x4000`: first-stage transformations and dispatch.
- `0x0100`: second dispatch, with a conditional Boolean-source read.
- `0x0400`: second dispatch, with a conditional scalar-source read.

All eight combinations of these three bits, including zero flags, pass validation.

For invalid flags, the first 32-bit object word is read:

- If nonzero, it remains unchanged.
- If zero, the fallback global is read and its value is written to that word.

The function then returns. None of the transformation or dispatch dependencies is called on this path. The fallback value may itself be zero; the write does not guarantee a nonzero first word.

### Local initialization and mode selection

For valid flags, the scalar and pointer inputs are copied into separate local slots. The 32-bit word at `0x130` is then read and converted to a character value for the zero comparison.

Under the represented low-eight-bit selection:

- Low eight bits zero: zero mode.
- Low eight bits nonzero: nonzero mode.

Nonzero upper bits alone do not select nonzero mode. This distinction does not reduce the established memory access to one byte.

Mode is selected once. Subsequent dependency changes to the selector do not cause the invocation to switch branches.

### First stage: `0x4000`

When `0x4000` is clear, both transformations and F-391a60182a2f are skipped.

When it is set, the two modes differ as follows.

**Zero mode:**

1. F-82d66b0ecdc1 receives the address of the local pointer slot and the object-relative address `0x8A4`.
2. F-2b0e3ae2b483 receives the address of the local scalar slot and the object-relative address `0x944`.
3. F-391a60182a2f receives, in order:
   - The initial handle snapshot.
   - The address of the local pointer slot.
   - The address of the local scalar slot.
   - The initial handle plus `0x8C`.

The first and fourth dispatch arguments use the initial handle even if either transformation changes the object's handle field.

**Nonzero mode:**

1. F-2b0e3ae2b483 receives the address of the local scalar slot and the object-relative address `0x944`.
2. F-82d66b0ecdc1 receives the address of the local pointer slot and the object-relative address `0x8A4`.
3. F-391a60182a2f receives, in order:
   - The handle read from `0xAE0` after both transformations.
   - The address of the local pointer slot.
   - The address of the local scalar slot.
   - The object-relative address `0x118`.

There is no additional zero check on this reloaded handle. A transformation can therefore cause the first dispatch in nonzero mode to receive zero, provided execution remains otherwise valid.

### Second-stage selection and arithmetic

After the optional first stage, the function returns if both `0x0100` and `0x0400` are clear.

Otherwise, it reads the signed 32-bit multiplicand at `0x8A0` and multiplies it by the captured signed 32-bit scaling value. Both operands are widened to signed 64-bit values before multiplication. Their product fits in signed 64 bits.

Consequently:

- A first-stage change to the scaling global does not change the captured scaling operand.
- A first-stage change to the multiplicand can affect the product because that field is read afterward.

The visible bit assembly targets a 32-bit result consisting of product bits 16 through 47. In the intended 32-bit bit-pattern interpretation, this corresponds to discarding the lowest 16 bits and retaining the next 32. There is no explicit rounding adjustment or saturation.

The source expresses part of this assembly with a signed left shift. Its strict language-level behavior for every operand is not established merely by the apparent bit-selection intent; that portability limitation is retained under Uncertainties.

### Second-stage ordering: zero mode

The body performs these accesses and local updates in order:

1. Read the multiplicand and process the product into the scaled argument.
2. If `0x0100` is set, read the unsigned byte at `0x9C4`.
3. Determine the Boolean: false when `0x0100` is clear; otherwise true exactly when the byte read is nonzero.
4. Overwrite the scalar slot with zero.
5. If `0x0400` is set, read the 32-bit word at `0x9E4` and overwrite the scalar slot with it.
6. Read the 32-bit value at `0x8B4`.
7. Reload the handle from `0xAE0`, without a zero check.
8. Overwrite the pointer slot with the reloaded handle plus `0x8C`.
9. Mask the scalar slot to its low 16 bits.
10. Invoke the second dispatch.

In particular, the pointer-slot overwrite follows the final handle reload in zero mode.

### Second-stage ordering: nonzero mode

The corresponding order is different:

1. Read the multiplicand and form the 64-bit product.
2. During product processing, **overwrite the pointer slot with the object-relative address `0x118`**.
3. Complete the scaled-argument bit assembly.
4. If `0x0100` is set, read the unsigned byte at `0x9C4`.
5. Determine the Boolean using the same rule as zero mode.
6. Overwrite the scalar slot with zero.
7. If `0x0400` is set, read the 32-bit word at `0x9E4` and overwrite the scalar slot with it.
8. Read the 32-bit value at `0x8B4`.
9. Reload the handle from `0xAE0`, without a zero check.
10. Mask the scalar slot to its low 16 bits.
11. Invoke the second dispatch.

Thus, in nonzero mode the pointer-slot overwrite precedes the optional Boolean-source read, both scalar-slot assignments, the optional scalar-source read, and both final field reads. It is not deferred until after handle reload.

### Second dispatch

F-0ee5f658b680 receives four explicit arguments:

1. The handle reloaded during the second stage.
2. The 32-bit scaled bit pattern.
3. The Boolean selected by `0x0100` and, when enabled, the byte at `0x9C4`.
4. The 32-bit value read from `0x8B4`.

The function returns after this dependency returns.

Neither the masked scalar slot nor the overwritten pointer slot is an explicit argument of this call. In particular, `0x0400` does not establish a separate 16-bit argument to F-0ee5f658b680. It selects the second stage and a conditional field read followed by local-slot updates.

## Side effects

The only direct object-storage write visible in this body is the conditional write to `0x000` for invalid flags.

The local scalar and pointer slots are also written. Their addresses escape to dependencies when `0x4000` is selected. Later slot writes therefore cannot automatically be dismissed as unobservable, although the legality and effects of retained aliases are unknown. The different pointer-overwrite positions in the two modes are part of the established ordering.

No direct allocation, release, ownership transfer, or write through the initial pointer is shown. Passing local-slot addresses does not establish permission to retain them after return or extend their lifetime.

Dependencies may modify accessible object fields, globals, or other storage; preservation cannot be assumed. The body nevertheless continues using the original object address. No recovery is shown for dependency-induced invalidation.

No explicit status handling, exception handling, rollback, or retry protocol appears. Abnormal dependency termination or invalid memory access need not reach the normal return paths described here.

## Acceptance examples

These are static acceptance conditions. Unless stated otherwise, assume accessible storage, normally returning dependencies, and no relevant dependency mutation. Arithmetic examples use the represented 32-bit bit-assembly interpretation.

1. **Null acquisition:** Acquisition returns null. The scaling global is still read, but no object field is accessed and no later dependency is invoked.

2. **Zero initial handle:** The object exists and its handle is zero. Even with invalid flags and a zero first word, no fallback read or write occurs.

3. **Invalid flags:** With a nonzero initial handle and flags containing `0x0001`, a zero first word is replaced by the fallback global's current value. A nonzero first word is preserved. Neither dispatch occurs.

4. **Empty valid flags:** Flags are zero and the initial handle is nonzero. The slots are initialized and the 32-bit mode word is read, but neither stage is dispatched.

5. **Mode selection width:** A mode word of `0x00000100` selects zero mode under the low-eight-bit conversion. A word of `0x00000001` selects nonzero mode. Both cases involve a 32-bit selector read, not an established byte load.

6. **First-stage order:** With `0x4000`, zero mode transforms the pointer slot before the scalar slot. Nonzero mode reverses that order.

7. **Changed handle:** With `0x4100`, a transformation changes the object handle. Zero mode's first dispatch still uses the initial handle; nonzero mode's first dispatch uses the changed handle. Both modes' second dispatch uses the later reload, including zero if that is the stored value.

8. **Positive scale:** With `0x0100`, a captured scale of `65536`, multiplicand `3`, and Boolean-source byte `7`, the second dispatch receives scaled value `3` and Boolean true.

9. **Negative extraction:** A captured scale of `-1` and multiplicand `1` yield `0xFFFFFFFF` under the represented bit extraction, rather than rounding toward zero. A strictly portable execution claim remains subject to the signed-shift uncertainty.

10. **Only `0x0400`:** The second dispatch occurs with Boolean false and no read at `0x9C4`. A scalar-source word of `0x12345678` ultimately leaves `0x5678` in the scalar slot, not in an additional explicit dispatch argument.

11. **Nonzero-mode overwrite order:** With a selected second stage, the pointer slot becomes the object-relative address `0x118` during product processing, before any optional read at `0x9C4` or `0x9E4`, and before reads at `0x8B4` and `0xAE0`.

12. **Zero-mode overwrite order:** The pointer slot retains its earlier value through the second-stage field reads, then becomes the reloaded handle plus `0x8C` before the scalar mask and final dispatch.
