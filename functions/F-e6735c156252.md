# F-e6735c156252

## Purpose

F-e6735c156252 conditionally dispatches a seven-argument operation through one of two indirect call targets associated with an object-like input. It applies a fixed eligibility check, selects a target using a byte in a secondary structure, adjusts one argument using a value stored in the primary structure, and constructs a 64-bit result.

The established behavior is mechanical dispatch and result packaging. The supplied evidence does not establish the application-level meaning of the operation, its arguments, the selector byte, or the two targets. Describing the operation as a transfer, rendering operation, allocation, or other domain-specific action would be speculative.

The eligibility check is independent of the object’s contents. A rejected invocation returns without dereferencing the object or invoking either target.

## Behavior

### Eligibility and rejection

Dispatch is eligible only when both conditions hold:

- Gate is not zero.
- Extent is less than or equal to 256 under an unsigned 32-bit comparison.

An Extent of zero is eligible. An Extent of 256 is eligible. An Extent of 257 is not eligible.

Gate is tested for nonzero, not for positivity. Negative signed Gate values therefore satisfy this part of the eligibility check.

If either condition fails:

- No object storage is read.
- Neither dispatch-table entry is read.
- Neither indirect target is invoked.
- The result has lower word `0xffffffff` and upper word equal to Gate’s original 32-bit representation.
- Payload A does not determine the upper word on this path.

Thus, a null or otherwise unreadable Object does not cause an object access within this function when the eligibility check rejects the invocation. This observation does not establish any broader calling convention requirement permitting invalid pointer values.

No diagnostic, exception translation, or separate status output is shown for rejection.

### Target selection

For an eligible invocation, the function uses the address stored at Object byte offset 16 to reach the selector byte at secondary-structure byte offset 92.

Selection depends only on whether that byte equals zero:

- Zero selects the entry at dispatch-table byte offset 160.
- Any nonzero value selects the entry at dispatch-table byte offset 164.

The sign interpretation of the byte does not affect the zero-versus-nonzero decision. In particular, a byte with bit pattern `0x80` or `0xff` takes the nonzero branch.

After determining the branch, the function obtains the dispatch-table address from Object byte offset 0 and reads the selected target entry. The supplied body does not read both entries and then choose between them.

The selection mechanism is structurally consistent with object-associated dispatch, but the source does not establish a class model, inheritance relationship, or semantic distinction between the two operations.

### Adjusted argument

Before invoking the selected target, the function reads the signed 32-bit adjustment value at Object byte offset 24 and combines it with Displacement by addition.

For sums representable as signed 32-bit integers, the forwarded value is that sum. Examples include:

- Adjustment 20 and Displacement −3 produce 17.
- Adjustment −20 and Displacement 3 produce −17.
- Adjustment zero leaves Displacement unchanged.

The visible expression is a signed 32-bit addition. The supplied evidence does not independently resolve behavior when the mathematical sum lies outside the signed 32-bit range. A modulo-\(2^{32}\) wraparound rule must not be assumed as an unconditional contract.

### Indirect invocation

Exactly one selected target is invoked if execution reaches the call. Its seven arguments, in order, are:

1. The original Object pointer.
2. Gate, unchanged.
3. The adjusted displacement.
4. Extent, unchanged.
5. Payload A, unchanged.
6. Payload B, unchanged.
7. Payload C, unchanged.

The target result is observed as a 32-bit value. If the target returns normally, that value becomes the lower word of the function’s 64-bit result, and Payload A becomes the upper word.

The wrapper does not interpret the target result, check it for success, retry the operation, invoke the other target, or normalize particular result values. A target result of `0xffffffff` remains `0xffffffff`; it is not converted into another status.

There is no visible post-call reread of the object, selector, dispatch table, or adjustment value. Changes made by the target to those locations do not trigger a second selection or dispatch within this invocation.

## Acceptance examples

These are conditional expectations derived from static evidence. They are not executed tests.

1. **Zero Gate rejects without object access.**  
   Given Gate zero, Extent 10, and any Payload A, the result is `0x00000000ffffffff`. No selector, table, or adjustment read occurs.

2. **Oversized Extent rejects independently of Object.**  
   Given Gate 7 and Extent 257, the result is `0x00000007ffffffff`. Neither dependency is invoked.

3. **Negative Gate remains eligible.**  
   Given Gate −1, Extent 1, valid reached storage, and a callable selected target, dispatch occurs. Gate is forwarded as −1. It is not rejected for being negative.

4. **Unsigned Extent interpretation matters.**  
   An Extent bit pattern of `0xffffffff` represents 4,294,967,295 and rejects. It is not treated as a small negative extent.

5. **Both extent boundaries are accepted.**  
   With nonzero Gate and otherwise valid accepted-path inputs, Extent zero and Extent 256 each permit dispatch. This does not establish that the selected dependency treats either value as valid for its own operation.

6. **Zero selector selects only the first dependency position.**  
   Given a zero selector, adjustment 100, Displacement −7, and representable arithmetic, F-9a8c7d6e5101 receives adjusted displacement 93. F-9a8c7d6e5102 is not invoked.

7. **Every nonzero selector selects the second position.**  
   With all other conditions equal, selector values 1 and `0xff` both select F-9a8c7d6e5102. The wrapper assigns no separate meaning to those nonzero values.

8. **Successful return packaging preserves both words.**  
   If the selected target returns `0x89abcdef` and Payload A is `0x12345678`, the final result is `0x1234567889abcdef`.

9. **An all-ones lower word does not prove rejection.**  
   If an accepted target returns `0xffffffff` and Payload A is 3, the result is `0x00000003ffffffff`. A rejected invocation with Gate 3 produces the same bit pattern. The returned bits alone therefore need not distinguish these paths.

10. **Overflow expectations remain conditional.**  
    Adjustment 2,147,483,647 plus Displacement 1 exceeds the signed 32-bit range. This contract does not prescribe the forwarded value or a normal outcome for that case.
