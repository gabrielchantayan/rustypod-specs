# F-7d76b30e06c5

## Purpose

F-7d76b30e06c5 repeatedly obtains a 32-bit control word, classifies it by its low 24 bits, and selects one of three behaviors:

- Recognize a terminating control word and return success.
- Obtain a 32-bit value and pass its address to a processing dependency.
- Invoke a separate advancement dependency.

Errors reported by the control-word acquisition, value acquisition, or advancement dependencies are returned immediately and without translation.

The established behavior is a control-driven processing loop. Interpreting its inputs as a stream, its control words as record types, or its processed values as objects is inferred intent, not an established interface guarantee.

## Interface

### Inputs

The function accepts four arguments in this order:

| Argument | Represented width | Established use |
|---|---:|---|
| First argument | 32 bits | Passed unchanged to F-15b1f69cb9c9 whenever processing occurs. |
| Second argument | 32 bits | Passed unchanged to F-4b3a084696b2, F-fa92e3e1239e, and F-7d397109ac66. |
| Third argument | 32 bits | Initial contents of a writable, invocation-local value slot. |
| Fourth argument | 32-bit unsigned word | Initial contents of a separate writable, invocation-local control slot. |

The representation establishes four-byte argument values; it does not establish whether the first three arguments denote integers, addresses, handles, or another encoded representation.

The first and second arguments are forwarded as values. This function does not directly dereference either argument. Dependencies may interpret them in ways not established here.

### Invocation-local storage

Two distinct four-byte slots exist for the duration of the invocation:

- **Value slot:** initialized from the third argument.
- **Control slot:** initialized from the fourth argument.

F-4b3a084696b2 receives the address of the control slot. F-7d397109ac66 and F-15b1f69cb9c9 receive the address of the same value slot.

Both slots retain their current contents between calls unless a dependency changes them. Neither slot is reinitialized on subsequent loop iterations.

### Output

The represented return type is a 32-bit signed integer status. The function returns:

- Zero when successful control acquisition leaves the control slot equal to `0xC0000010`.
- The exact nonzero status returned by F-4b3a084696b2.
- The exact nonzero status returned by F-fa92e3e1239e.
- The exact nonzero status returned by F-7d397109ac66.

There is no independently computed error code, status normalization, or direct return derived from F-15b1f69cb9c9.

### Preconditions

Dependencies must accept the forwarded argument representations and the supplied addresses of writable four-byte slots.

Any additional requirements on external objects, address validity, alignment beyond that supplied by the invocation-local storage, or dependency initialization are undocumented. This function performs no visible validation before making its first dependency call.

## Behavior

### Initialization and first observable call

Before any dependency invocation, the function initializes the value slot from the third argument and the control slot from the fourth argument.

The first dependency called is always F-4b3a084696b2, with:

1. The second argument.
2. The address of the control slot.

Consequently, the initial fourth argument is not classified before this first call. Even if that argument is already `0xC0000010`, successful termination depends on the control-slot contents after F-4b3a084696b2 returns successfully.

The initialized slot contents are available to dependencies through their addresses. The function does not require that these dependencies treat the slots as output-only storage.

### Control acquisition and error precedence

Each processing cycle begins with F-4b3a084696b2.

If it returns a nonzero status, F-7d76b30e06c5 returns that status immediately. It does not classify the control slot or invoke another dependency on that path.

This precedence applies even if F-4b3a084696b2 also writes a terminating control word before returning the nonzero status.

If it returns zero, classification uses the control slot’s current contents.

### Control-word layout

The control word is divided logically into:

| Bit range | Width | Role in local classification |
|---|---:|---|
| Bits 0–23 | 24 bits | Select the primary branch. |
| Bits 24–31 | 8 bits | Distinguish termination from continuation only when the low 24 bits equal `0x000010`. |

These are bit positions within a 32-bit word, not a byte-stream layout. Byte order is not established by the available evidence.

No addition, subtraction, increment, sign extension, or narrowing conversion is used to classify the control word. Classification is by masks and equality comparisons.

### Low 24 bits equal `0x000010`

When the low 24 bits equal `0x000010`, the function examines the high byte.

- If the high byte is `0xC0`, it returns zero immediately.
- For every other high-byte value, it begins another control acquisition.

Thus the successful terminator is exactly the 32-bit word `0xC0000010`.

A nonterminating word in this class does not trigger advancement, value acquisition, or processing. It causes another call to F-4b3a084696b2 using the same control-slot address.

There is no local limit on consecutive words in this class.

### Low 24 bits equal `0x000011`

When the low 24 bits equal `0x000011`, the high byte does not affect the local branch decision.

The function calls F-7d397109ac66 with:

1. The second argument.
2. The address of the value slot.

If this dependency returns a nonzero status, that status is returned immediately. F-15b1f69cb9c9 is not called on this path.

If it returns zero, the function calls F-15b1f69cb9c9 with:

1. The first argument.
2. The address of the value slot.

After F-15b1f69cb9c9 returns normally, the function begins another control acquisition.

No result from F-15b1f69cb9c9 is checked or propagated. This does not establish that the dependency cannot fail, affect global state, or terminate execution through mechanisms outside ordinary return.

### All other low-24-bit values

For every low-24-bit value other than `0x000010` and `0x000011`, the function calls F-fa92e3e1239e with the second argument.

- A nonzero result is returned immediately.
- A zero result causes another control acquisition.

There is no processing call on this branch. The function does not pass the control word explicitly to F-fa92e3e1239e.

The high byte does not affect this branch decision.

### Persistence across iterations

Neither local slot is cleared between iterations.

In particular:

- The next control acquisition receives the same control slot, with whatever contents remain from earlier dependency activity.
- The next value acquisition receives the same value slot used by earlier acquisitions and processing calls.
- If F-15b1f69cb9c9 changes the value slot, those contents remain available to a later F-7d397109ac66 call.
- A dependency’s zero return does not, by itself, prove that it wrote its supplied slot.

The initial third argument can therefore remain relevant if value acquisition returns zero without replacing the value slot. Likewise, the initial fourth argument can affect classification if the first successful control acquisition leaves the control slot unchanged.

### Termination and progress

There is no local iteration bound or progress counter.

Normal termination requires either:

- A nonzero status from one of the three status-bearing dependencies; or
- Successful control acquisition followed by the exact terminating control word.

Repeated successful calls that leave the function on continuation paths may keep it running indefinitely. The implementation does not independently detect a stalled input source, repeated control word, or absence of progress.

## Acceptance examples

These examples are conditional static acceptance criteria, not reported executions. Each assumes that dependencies return normally and have only the effects explicitly stated in that example.

1. **Immediate successful termination.**  
   The first F-4b3a084696b2 call returns zero and writes `0xC0000010`. The function returns zero. No advancement, value acquisition, or processing call occurs.

2. **Control-acquisition error overrides slot contents.**  
   F-4b3a084696b2 writes `0xC0000010` but returns `-7`. The function returns `-7`, not zero.

3. **Nonterminating control marker.**  
   Successful control acquisition writes `0x00000010`. The next dependency call is another F-4b3a084696b2 call. F-fa92e3e1239e is not called between them.

4. **High-byte distinction within the marker class.**  
   `0xBF000010` and `0xC1000010` both continue acquisition. Only `0xC0000010` terminates successfully.

5. **High byte ignored for value acquisition.**  
   Successful acquisition of either `0x00000011` or `0xC0000011` selects F-7d397109ac66. If that call returns zero, F-15b1f69cb9c9 follows.

6. **Value-acquisition failure suppresses processing.**  
   After classification as `0x000011` in the low 24 bits, F-7d397109ac66 returns `9`. The function returns `9` without calling F-15b1f69cb9c9.

7. **Other bits within the low 24 bits remain significant.**  
   Successful acquisition writes `0xC0010010`. Its low 24 bits are `0x010010`, not `0x000010`; the function calls F-fa92e3e1239e rather than terminating.

8. **Advancement error is propagated.**  
   A control word selects the other-values branch, and F-fa92e3e1239e returns `12`. The function returns `12` without acquiring another control word.

9. **Initial control-slot contents remain observable if not replaced.**

10. **Value-slot persistence.**
