# F-e76882e92795

## Purpose

F-e76882e92795 conditionally updates a 16-bit field in an indirectly referenced object and, when the comparison indicates a difference, invokes two downstream operations. The final operation receives only the low eight bits of a working 32-bit value.

The established behavior is not simply “update when the new 16-bit value differs.” The comparison uses the entire working 32-bit value against a zero-extended 16-bit field. Consequently, nonzero upper bits can trigger the update path even when storing the low 16 bits leaves the field unchanged.

A plausible intent is to normalize an input value, synchronize a stored selection or setting, and notify another component. Those domain meanings are inferred, not established. This contract uses structural descriptions rather than assigning a semantic name to the field.

## Behavior

### Preparation and initial dependency call

The function first initializes a local unsigned 32-bit working value from the fourth input.

It then invokes F-1a1ecaac8aad with:

- the second input; and
- the address of the local working value.

This dependency call precedes the visible read of the container’s object-reference slot. Therefore, mutations performed by this dependency can affect the later comparison and object selection. The dependency’s return value, if any, is not used.

The comparison uses the working value after this call, not necessarily the original fourth input. No normalization rule, permissible range, or success condition for F-1a1ecaac8aad is known.

### Comparison

After the initial dependency returns, the function reads the 32-bit object reference at container offset `0xF00`. It reads the 16-bit field at offset `0xB64` within that object.

The field is interpreted as an unsigned value between 0 and 65,535 and compared with the full unsigned 32-bit working value.

Two consequences are essential:

- Equality is possible only when the working value is at most 65,535.
- A working value greater than 65,535 always takes the unequal path, regardless of whether its low 16 bits match the field.

This is not a signed 16-bit comparison. A stored field with bit pattern `0xFFFF` compares equal to the 32-bit value `0x0000FFFF`, not to `0xFFFFFFFF`.

### Equal path

If the comparison is equal:

- No field write is performed by the visible body.
- F-e0ba31379901 is not called.
- F-87be4aa684d1 is not called.
- No indirect dispatch occurs.
- The function returns 32-bit zero.

The initial call to F-1a1ecaac8aad has already occurred. Equality therefore does not establish that the overall invocation was free of side effects.

### Unequal path

If the comparison is unequal, the function performs these operations in order:

1. It obtains the object reference from the container’s `0xF00` slot for the field write.
2. It writes the low 16 bits of the working value to offset `0xB64` in that object.
3. It obtains the object reference from the same container slot for the next dependency call.
4. It invokes F-e0ba31379901 with that object reference.
5. It invokes F-87be4aa684d1 without explicit arguments and uses its result as an object reference.
6. It reads that object’s dispatch-table reference and the callable entry at table offset `0xA0`.
7. It invokes the selected target with the returned object and the working value masked to eight bits.
8. If the invocation returns normally, it returns 32-bit zero.

The field write precedes both downstream calls. There is no visible rollback if a later operation fails or does not return.

The write is a 16-bit truncation. It does not establish saturation, rejection of out-of-range values, or preservation of an arithmetic sign.

The final argument is restricted to the range 0 through 255 by an explicit low-eight-bit selection. This does not prove the callee’s formal parameter is eight bits wide; it establishes the numeric value supplied by this function.
