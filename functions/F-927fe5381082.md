# F-927fe5381082

## Purpose

F-927fe5381082 dispatches an operation according to a descriptor’s kind byte. Established behaviors include direct delegation, two-pass collection processing, selection of one collection entry, and invocation of descriptor-associated operations.

The collection path obtains per-entry results, accumulates them, and optionally performs header processing followed by another pass with output enabled. A sizing-and-emission purpose is inferred from this arrangement; the actual format, units, and protocol are unknown.

The result contains two 32-bit words. The low word carries a dependency result, an accumulated working value, or zero. The high word depends on the branch and can contain the output-context address, the auxiliary argument, or zero. It is not established as a uniform status code.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments

| Position | Role | Established representation and use |
|---|---|---|
| 1 | Object reference | Address of a 32-bit object value. Usually forwarded as an address; kind 3 passes the value read through it. |
| 2 | Output context | Nullable address of a 32-bit cell. Forwarded to applicable dependencies. Kind 3 also interprets its contents as a byte address. |
| 3 | Descriptor | Address of storage containing a kind byte and several 32-bit fields. |
| 4 | Mode | 32-bit value. The all-ones pattern is treated as signed −1 in relevant comparisons. |
| 5 | Auxiliary argument | 32-bit pointer-shaped value. Used as a return high word and, for kind 3, as low-byte flag bits. No direct dereference is established. |

| 12 | 32 bits | Signed collection count or selection bound |
| 16 | 32 bits | Associated operation-table address |

Collection entries are addressed at 20-byte intervals. This function does not establish their internal layout.

The associated operation table has these observed slots:

| Byte offset | Width | Established use |
|---|---:|---|
| 12 | 32 bits | Required kind-3 operation address |

These accesses do not establish complete structure sizes.

### Return value

The visible 64-bit result consists of:

- Bits 0–31: low result word.
- Bits 32–63: high result word.

A dependency result used as the low word contributes its 32-bit representation. Pointer-shaped high-word values likewise contribute 32 bits.

A zero low word is ambiguous: explicit rejection returns zero, but dependency results and successful accumulated results can also be zero.

### Preconditions

The descriptor must permit the initial 32-bit read at offset 16 and the kind-byte reads.

For every nonzero kind, the object reference must permit a 32-bit read before dispatch. A zero object value causes immediate rejection. Kind 0 bypasses this read, although its dependencies can impose their own requirements.

After that rejection check, a nonzero operation-table address requires a readable callback slot at offset 16, including for kinds that never invoke the callback.

Kinds 3 and 4 require accessible, callable entries at their respective operation slots. Neither required invocation is protected by a null check.

Other memory requirements are conditional on the accesses described below. No general validation, bounds enforcement, or invalid-address recovery is established.

## Behavior

### Entry and common rejection

The established entry sequence is:

1. Read the operation-table address from descriptor offset 16.
2. Read the kind byte for the object-presence check.
3. If that byte is nonzero, read the 32-bit object value. If it is zero, return low word zero and the incoming output-context address as the high word.
4. If the captured operation-table address is nonzero, read its callback slot at offset 16. Otherwise, select no callback.
5. Initialize a local 32-bit working cell from the incoming mode.
6. Read the kind byte for dispatch.

There is no dependency call between the two kind-byte reads. The callback address, once selected, is retained rather than reloaded after dependency calls.

Unsupported kinds return low word zero and the incoming output-context address as the high word, after the applicable entry accesses.

### Kind 0: direct delegation or fallback

Read descriptor offset 8.

If its value is nonzero, call F-af67321405c4 with:

1. Object-reference address.
2. Incoming output context.
3. The value read from descriptor offset 8.

Return the dependency’s result as the low word and the incoming output-context address as the high word.

If the offset-8 value is zero, call F-d46f1a314a3f with the object reference, output context, descriptor, and incoming mode. Return its result as the low word and the incoming auxiliary argument as the high word.

Neither branch invokes the lifecycle callback.

### Kind 1: shortcut and two-pass collection processing

First call F-1893537ad0a2 with:

1. Address of the local working cell, initially containing the incoming mode.
2. Output context.
3. Object reference.
4. Descriptor.

Interpret its 32-bit result as signed:

- Negative: return low word zero and the output-context address as the high word.
- Positive: return the current working-cell value as the low word and the output-context address as the high word.
- Zero: continue.

On continuation, reset the working cell to zero. If the incoming mode is −1, replace the effective mode with 16 and the effective auxiliary argument with zero. Otherwise, retain both incoming values.

If a lifecycle callback exists, invoke it with event 6, the object reference, and the descriptor. A zero result rejects processing, returning low word zero and the output-context address as the high word. Any nonzero result permits continuation.

#### First pass

Read the table address from descriptor offset 8. Begin with signed index zero.

Before each iteration, read the signed count at descriptor offset 12. Continue only while the index is strictly less than that count. Thus a stable zero or negative count produces no iterations.

For each entry:

1. Call F-23eebec8340f with the object reference, current entry address, and constant 1.
2. If its result is zero, return immediately with low word zero and the output-context address as the high word.
3. Call F-50a87c4da87c with the object reference and the nonzero resolver result.
4. Call F-af67321405c4 with that derived value, a null output context, and the resolver result.
5. Accumulate its 32-bit result into the working total.
6. Move to the next entry, 20 bytes later, and increment the index.

The table base is captured once for this pass. The count is reread at every loop condition, including the terminating condition. Dependency mutations can therefore affect the number of iterations without replacing the locally advanced entry address.

After the pass, call F-1393b2e3d099 with constant 1, the working total, and the effective mode. Retain its 32-bit result.

If the output context is null, return that retained result with high word zero. Do not perform header processing, a second pass, or event 7.

#### Output-enabled pass

With a nonnull output context:

1. Call F-208392f0520a with the output context, constant 1, working total, and effective mode.
2. Read the table address again from descriptor offset 8.
3. Select the effective auxiliary argument as the prospective return high word.
4. Traverse entries again, beginning at index zero and rereading the signed count at every loop condition.

For each second-pass entry, call F-23eebec8340f and then F-50a87c4da87c with the same argument roles as in the first pass. A zero resolver result immediately returns low word zero and the effective auxiliary argument as the high word.

Call F-af67321405c4 with the derived value, the actual output context, and the resolved descriptor. Ignore its result during this pass.

After traversal, invoke an existing lifecycle callback with event 7, the object reference, and the descriptor:

- Zero callback result: return low word zero.
- Nonzero callback result, or no callback: return the retained F-1393b2e3d099 result.

The high word is the effective auxiliary argument in either case. No local rollback of header or field output occurs.

### Kind 2: select one entry

If a lifecycle callback exists, invoke event 6 with the object reference and descriptor. A zero result returns immediately with low word zero and the output-context address as the high word.

Otherwise, call F-7eb30049adbd with the object reference and descriptor. Its result is 64 bits. Selection uses only its low 32-bit word interpreted as signed.

The count access is conditional:

- A negative selection is rejected without reading descriptor offset 12.
- For a nonnegative selection, read the signed count at descriptor offset 12. Accept exactly when the selection is strictly less than that count.

Consequently, the accepted interval is **zero through count minus one**, provided the count is positive. Count 1 accepts selection zero. Counts zero or below accept no selection.

For an accepted selection:

1. Read the table address from descriptor offset 8.
2. Form the selected entry address using that base plus 20 times the selection.
3. Call F-50a87c4da87c with the original object reference and selected entry address.
4. Call F-af67321405c4 with the derived value, incoming output context, and selected entry address.
5. Return its result as the low word and the incoming output-context address as the high word.

Selection zero therefore processes the base entry. Accepted selections do not invoke event 7. This path does not call F-23eebec8340f.

For a rejected selection, invoke an existing lifecycle callback with event 7 and the object reference. This invocation does not explicitly supply a descriptor argument. Ignore its result and return low word zero with the output-context address as the high word.

The selection dependency’s high result word does not change acceptance or the final return value.

### Kind 3: indirect operation and conditional byte rewrite

If the output context is nonnull, first read its 32-bit contents and retain that value as a byte address.

Invoke the operation at offset 12 of the initially captured operation table with:

1. The 32-bit value read through the object reference for this invocation.
2. The incoming output context.

The object value supplied to this operation is read again; it is not specified as a saved copy of the entry-check read. The relative evaluation order of the operation-slot read and the object-value read is not independently established.

Retain the operation’s result as the low return word.

If the output context is nonnull and the mode is not −1, read the byte at the previously saved address and replace it with the bitwise union of:

- The byte’s existing hexadecimal 20 bit.
- The mode’s low eight bits.
- The auxiliary argument’s low eight bits.

Existing byte bits other than hexadecimal 20 are cleared unless supplied by the argument bits. The argument bits can also set hexadecimal 20.

The byte address is captured before the operation, but the byte is read afterward. A change to the output-context cell during the operation does not redirect the rewrite.

Return the operation result as the low word and the incoming output-context address as the high word. Null output or mode −1 suppresses the rewrite, not the indirect operation.

### Kind 4: extended indirect operation

Invoke operation-table slot 20 with six argument positions:

1. Object reference.
2. Output context.
3. Descriptor.
4. Incoming mode.
5. Incoming auxiliary argument.
6. Descriptor again.

Return the operation result as the low word and the incoming auxiliary argument as the high word. Do not invoke the lifecycle callback.

### Kind 5: forced fallback

Call F-d46f1a314a3f with the object reference, output context, descriptor, and mode −1.

Return its result as the low word and zero as the high word, regardless of the incoming mode and auxiliary argument.

## Side effects

The only established direct write to caller-related storage is the conditional kind-3 byte replacement. The function also updates local state and supplies the address of its working cell to F-1893537ad0a2.

Dependencies receive references through which they may mutate objects, descriptors, output storage, or other state. Their allocation, release, retention, and ownership behavior are unknown.

Material ordering properties include:

- The operation-table address is read before the object-presence rejection.
- The optional callback address is selected before kind-specific dependency calls.
- Kind 1 completes the first pass before its result-construction dependency and optional header processing.
- Header processing precedes second-pass field processing.
- Each kind-1 pass captures its table base separately; each loop condition rereads the count.
- Kind 2 skips the count read for negative selections.
- Kind 3 captures its byte address before the operation and reads and writes the byte afterward.

No direct allocation, release, reference-count operation, or ownership transfer is established.

Lifecycle events are not generally paired. Event 6 can be followed by an early failure, null-output completion, or accepted kind-2 selection without event 7. Rejection after output begins does not cause local restoration.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Absent object:** For a nonzero kind and an object reference containing zero, return low word zero and the output-context address as the high word. The descriptor offset-16 read has already occurred; no dependency is called.

2. **Shortcut completion:** If F-1893537ad0a2 writes 37 to the working cell and returns a positive signed value, return low word 37 and the output-context address as the high word. No collection pass occurs.

3. **Empty collection:** Given continuation permission, null output, and a count that remains zero, make no per-entry calls. Call F-1393b2e3d099 with total zero and return its result with high word zero.

4. **Default collection mode:** Given kind-1 continuation and incoming mode −1, both result construction and any header processing receive mode 16. Output-enabled completion uses high word zero.

5. **Second-pass rejection:** If a second-pass resolver returns zero after header processing, return low word zero and the effective auxiliary argument as the high word. Earlier output is not locally undone.

6. **Selection boundaries:** With a count of 4 at the conditional count read, selections 0, 1, 2, and 3 are eligible; −1, 4, and 5 are rejected. Selection zero uses the table base and does not invoke event 7.

7. **Single-entry selection:** With count 1, selection zero is accepted. With count zero or negative, no nonnegative selection is accepted. A negative selection skips the count read entirely.

8. **Rejected-selection callback:** If event 6 permits kind-2 processing and selection is rejected, an existing callback receives event 7 and the object reference, without an explicitly supplied descriptor argument. Its return value does not affect the zero result.

9. **Byte replacement:** If the saved byte contains hexadecimal A5 after the kind-3 operation, mode has low byte 02, and the auxiliary argument has low byte 08, write hexadecimal 2A. Preserve the operation result as the low return word.

10. **Rewrite suppression:** Kind 3 with mode −1 still invokes its operation, but performs no post-call byte read or write. With nonnull output, the earlier output-cell read still occurs.

11. **Forced fallback:** Kind 5 supplies mode −1 to F-d46f1a314a3f and returns its result with high word zero.

## Evidence

Established claims derive from the supplied static representation: argument uses, access widths and offsets, branch conditions, dependency order, repeated count reads, 20-byte addressing, return-word composition, and conditional byte replacement.

In particular, kind-2 acceptance combines a nonnegative signed selection with a count comparison that excludes equality. The count is loaded only for nonnegative selections.
