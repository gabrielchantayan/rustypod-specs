# F-a20bc54143b2

## Purpose

F-a20bc54143b2 rearranges four-byte elements in caller-supplied storage. Beginning at a supplied index, it promotes selected descendants into successive vacancies, then inserts a separately supplied four-byte value by moving qualifying parents downward.

**Established static behavior:** descendant selection and parent movement depend on whether a supplied callback returns zero or nonzero. Selected source slots are read again after callback return, so callback mutations can affect the values subsequently copied.

**Inferred intent:** the index relationships describe adjustment within a zero-based binary heap. This interpretation explains the downward and upward phases, but does not establish a caller contract or a heap-ordering guarantee. The function does not validate the input structure or require a coherent comparison relation.

## Interface

The function has five inputs and no explicit return value.

| Input | Representation and meaning |
|---|---|
| Storage base | An integer-form address used as the base of contiguous four-byte slots. The supplied representation presents this input as a 32-bit integer; the actual address ABI is not independently established. |
| Starting index | A signed 32-bit index identifying the initial vacancy and the upper boundary of upward movement. |
| End bound | A signed 32-bit bound used as an exclusive element limit during downward selection. |
| Insertion value | A four-byte representation supplied by value and eventually written into the final vacancy. |
| Callback | A dynamically supplied callable, identified here as **F-d001**, receiving two four-byte values and returning an integer tested for zero versus nonzero. |

Slot \(i\) is addressed at the storage base plus \(4i\). There is no visible stride parameter, element header, auxiliary key array, or per-element allocation.

The insertion value is supplied independently; the function does not obtain it by reading the starting slot.

Before the first downward callback, the function itself does not directly read the starting slot. **This does not establish behavioral independence from that slot’s contents.** F-d001 may access the starting slot through externally available storage and use its contents to determine a return value or other side effect. Independence requires an additional callback assumption excluding such influence.

- Every accessed slot is readable or writable as required.

These are conditions on use, not checks performed by the function. The end bound does not independently protect against an invalid starting index.

## Behavior

### Initial vacancy and saved value

The starting index becomes the current vacancy. The insertion value remains the supplied four-byte argument throughout the visible computation.

There is no direct element read merely to initialize the vacancy. This direct-access observation places no restriction on what F-d001 may subsequently inspect through external references.

### Downward selection with two children

For a current vacancy at index \(h\), the prospective right-child index is:

\[
r = 2h+2.
\]

When \(r\) is strictly below the end bound, the function treats indices \(r-1\) and \(r\) as the left and right children.

F-d001 receives:

1. The four-byte value from the right-child slot.
2. The four-byte value from the left-child slot.

The supplied representation establishes argument positions, but not the relative order of these two memory reads. Both argument values are obtained before callback entry.

Selection is determined solely by the returned integer’s zero/nonzero classification:

| Callback result | Selected child |
|---|---|
| Nonzero, including negative values | Left child |
| Zero | Right child |

After callback return, the selected child’s slot is read again. That newly read value is written into the current vacancy. The selected child becomes the new vacancy, and downward selection repeats.

The reread matters: if F-d001 changes the selected slot, the promoted value is its post-callback content, not necessarily the argument previously supplied to F-d001.

The selected source slot is not cleared. The callback may also have made other writes; those writes are not undone by this step except where subsequent direct writes overwrite them.

### Downward termination and the sole-left-child case

Downward comparison ends when the prospective right-child index is greater than or equal to the end bound.

- **Equality:** the immediately preceding slot is treated as a sole left child. Its four-byte value is copied into the current vacancy without a callback. That left-child index becomes the vacancy.
- **Greater than:** no additional downward copy occurs.

The equality case performs one copy and then proceeds to upward insertion; it does not resume downward comparison.

The insertion value is not passed to F-d001 during descent. Descendant promotion therefore occurs before any direct comparison involving that value, even when an intended ordering would ultimately leave it at the starting index.

This does not exclude indirect callback access to externally available data associated with the insertion value or the starting slot.

### Upward insertion

For a vacancy at index \(h\), the prospective parent index is:

\[
p = \operatorname{trunc}\!\left(\frac{h-1}{2}\right),
\]

where the represented signed division truncates toward zero.

The parent-index calculation occurs before testing whether upward movement is permitted. A parent-slot read occurs only when the vacancy is strictly greater than the original starting index.

While that boundary condition holds, F-d001 receives:

1. The four-byte value read from the parent slot.
2. The original insertion value.

The callback result controls the next action:

- **Zero:** stop upward movement.
- **Nonzero:** read the parent slot again, copy its current value into the vacancy, and make the parent index the new vacancy.

After a nonzero result, the parent-index calculation and boundary test repeat.

As during descent, callback mutation can change the value copied after return. The parent argument and the later copied value need not match.

Once the vacancy reaches the starting index, no upward callback is made and no parent slot above that boundary is directly read.

### Final insertion

When upward movement stops, the function writes the insertion value into the current vacancy.

This write occurs even if neither phase moved an element. Its destination may be the starting slot or a descendant slot.

For ordinary valid nonnegative indices and representable arithmetic, direct movement follows one downward path and then ascends along that path, without crossing above the starting index. Callback accesses are not restricted to that path.

### Interpretation of callback results

The callback is not used as a conventional three-way comparator. Positive and negative results have the same effect because both are nonzero.

For example, if F-d001 returns nonzero exactly when its first numeric argument is greater than its second:

- Descent selects the smaller child.
- Ascent shifts a parent downward when that parent is greater than the insertion value.

If equal arguments produce zero:

- Equal children cause descent to select the right child.
- Equality between a parent and the insertion value stops ascent.

These are conditional branch properties, not evidence of stability or an unconditional ordering guarantee.

## Side effects

### Direct storage accesses

The function directly writes only four-byte slot representations:

1. A selected child into the current vacancy after each two-child comparison.
2. A sole left child into the vacancy when the right-child index equals the bound.
3. A qualifying parent into the vacancy after a nonzero upward comparison.
4. The insertion value into the final vacancy.

For each direct copy, the source value is obtained before the destination write.

The function does not visibly swap pairs, clear moved-from slots, resize storage, or restore prior contents. Intermediate duplicate representations can exist and can be observed by later callbacks.

The initial starting-slot content is not a direct input to the first downward comparison’s argument loads. It can nevertheless influence that comparison through F-d001’s external reads.

### Callback-visible ordering

A downward callback runs before its associated promotion. It can observe direct writes completed in earlier iterations.

The first upward callback runs after all downward promotions. Each later upward callback runs after the preceding parent promotion.

There is no visible isolation or rollback of callback effects. No guarantee is established that F-d001 preserves unrelated globals, element contents, storage validity, or external resources.

### Ownership and lifetime

The function visibly requests no allocation and performs no explicit release. Four-byte values are copied without visible interpretation as owned objects.

If a value represents a pointer, handle, or resource reference, copying it does not establish ownership transfer, reference-count adjustment, destruction, retention, or release.

The insertion value is passed by value. Changing an array slot that originally contained identical bits does not itself replace that saved argument. This does not establish any lifetime guarantee for a resource represented by those bits.

### Failure behavior

There is no explicit range check, callback-null check, error result, recovery path, or rollback.

If an invalid access or callback failure interrupts execution, earlier writes may already have occurred. Whether execution traps, unwinds, terminates, or behaves otherwise is not established by the supplied material.

## Acceptance examples

These are statically derived, conditional scenarios, not runtime test results. Unless stated otherwise, they assume valid storage, representable arithmetic, normal callback return, and no callback mutations or external influences beyond the stated callback behavior. Array entries represent four-byte values.

### Single-slot range

With starting index 0, end bound 1, and insertion value \(T\):

- No child is copied.
- No callback is invoked.
- Slot 0 is overwritten with \(T\).

The function does not directly read the previous slot value.

### Sole left child, insertion remains below it

Given storage `[X, 3]`, starting index 0, end bound 2, insertion value 5, and a callback returning nonzero exactly when its first numeric argument exceeds its second:

- Slot 1 is copied to slot 0 without a callback.
- The upward callback receives `(3, 5)` and returns zero.
- Final storage is `[3, 5]`.

### Sole left child, insertion reaches the starting boundary

With the same storage and bounds, but insertion value 2:

- Slot 1 is copied to slot 0.
- The upward callback receives `(3, 2)` and returns nonzero.
- The parent is copied back into slot 1.
- The insertion value is written at slot 0.

Final storage is `[2, 3]`. The initial downward copy occurs even though insertion ultimately returns to the starting index.

### Descent followed by partial ascent

Given `[X, 4, 7, 8, 9, 10, 11]`, starting index 0, end bound 7, insertion value 6, and the same greater-than predicate:

- Downward callbacks receive `(7, 4)` and `(9, 8)`.
- Nonzero results select indices 1 and 3, promoting 4 and 8.
- Upward callback `(8, 6)` returns nonzero, moving 8 back down.
- Upward callback `(4, 6)` returns zero.

Final storage is `[4, 6, 7, 8, 9, 10, 11]`.

### Zero results select right children

Given `[A, B, C, D, E, F, G]`, starting index 0, end bound 7, insertion value \(T\), and a callback that always returns zero without side effects:

- Descent selects indices 2 and 6.
- The upward callback returns zero.
- Final storage is `[C, B, G, D, E, F, T]`.

No ordering property is implied.

### Callback mutation changes the promoted value

Given `[A, L, R]`, starting index 0, end bound 3, and insertion value \(T\):

- The first callback receives `(R, L)`.
- It changes slot 2 to \(Q\) and returns zero.
- The function rereads slot 2 and promotes \(Q\) into slot 0.
- The upward callback receives \((Q,T)\).

If that second call returns zero and makes no further changes, final storage is \([Q,L,T]\).

### Starting-slot contents can influence initial selection indirectly

Consider two invocations with starting index 0, end bound 3, insertion value 15, and initial storage respectively:

- `[1, 10, 20]`
- `[2, 10, 20]`

In both invocations, F-d001 ignores its arguments, reads slot 0 through an external reference, and returns nonzero exactly when that slot contains 1. It makes no writes.

Both first downward callbacks receive `(20, 10)`, but their results differ:

- With initial slot 0 equal to 1, the left child is selected and 10 is promoted. The upward callback then observes slot 0 equal to 10 and returns zero. Final storage is `[10, 15, 20]`.
- With initial slot 0 equal to 2, the right child is selected and 20 is promoted. The upward callback then returns zero. Final storage is `[20, 10, 15]`.

Thus, absence of a direct starting-slot read does not imply independence from its initial contents.

### Empty bound does not suppress the final write

With starting index 0, end bound 0, and writable slot 0:

- No callback is invoked.
- The insertion value is written to slot 0.

This is not an empty-array safety guarantee. It demonstrates that the bound alone does not suppress insertion.
