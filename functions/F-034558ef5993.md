# F-034558ef5993

## Purpose

F-034558ef5993 performs two ordered indexed scans through an object obtained from dependencies. For each index, it requests a record into a temporary buffer and evaluates that buffer through a shared predicate dependency. Nonzero predicate results trigger a call associated with the corresponding global destination.

The two scans are observably asymmetric:

- The first scan supplies its destination dependency with both a global destination value and the address of a 32-bit index.
- The second scan supplies the same dependency with only its global destination value. Although it also assigns the current index to local storage, the supplied evidence does not show that storage being passed.

The routine finishes by conditionally invoking an object-associated final operation. Its meaning—release, destruction, reference-count adjustment, or another action—is not established.

The apparent intent is to rebuild two collections of selected indices. That interpretation is **inferred**, not established: neither the destination dependencies’ semantics nor the second scan’s missing explicit index argument is resolved by the available evidence.

## Behavior

### 1. Acquire the working object

The routine calls F-8157a180d901 with the constant 72.

It then passes that dependency’s 32-bit result to F-df2422ba76c2, followed by two zero-valued arguments. The result of F-df2422ba76c2 is retained as the working object pointer.

No explicit validation of either dependency result occurs before the first destination operation or the first object dispatch.

The routine does not establish whether the first dependency produces memory, an identifier, a handle, or another value. Likewise, it does not establish whether the second dependency takes ownership of that value.

### 2. Prepare destination A

The routine reads destination slot A and passes its current value as the sole explicit argument to F-7a304fc4cb8d.

This call occurs after object acquisition and before the first count query.

The source establishes the call, but not whether it clears, initializes, resets, or otherwise modifies the destination. In particular, the contract does not require that destination A be empty afterward.

### 3. Capture the first scan bound

The routine reads the working object’s dispatch-table reference and calls the entry at byte offset 0x1AC.

No explicit arguments are shown for this count operation. An implicit receiver or other calling-convention state cannot be determined from the supplied representation.

The result is captured as an unsigned 32-bit scan bound. The routine does not query this bound again during the first scan.

### 4. Perform the first scan

The first scan begins at unsigned index zero and continues while the index is strictly less than the captured first bound.

Each iteration performs these operations in order:

1. Read the working object’s dispatch-table reference and obtain the entry at byte offset 0x27C.
2. Invoke that entry with the workspace address, the working object pointer, and the current unsigned 32-bit index, in that explicit argument order.
3. Call F-0763bbe10778 with the workspace address.
4. If the predicate result is nonzero, store the current index in the addressable 32-bit temporary.
5. For that nonzero result, read destination slot A and call F-84652ce813be with the resulting destination value and the temporary’s address.
6. Increment the unsigned index by one.

A zero predicate result suppresses only the destination call and the index-temporary assignment for that iteration. It does not stop the scan or change its captured bound.

Both positive and negative nonzero predicate results select the iteration.

The address passed on a selected iteration refers to the same local temporary reused by later selected iterations. It is not established that F-84652ce813be copies the integer synchronously or avoids retaining its address.

### 5. Prepare destination B

After the first scan completes, the routine reads destination slot B and calls F-7a304fc4cb8d with its current value as the sole explicit argument.

This happens even if the first bound was zero or every first-scan predicate result was zero, provided preceding operations returned normally.

Destination B is not prepared before the first scan.

### 6. Capture the second scan bound

The routine reads the working object’s dispatch-table reference and invokes the entry at byte offset 0x1C4.

As with the first count operation, no explicit arguments are shown. The result is captured as an unsigned 32-bit value and is not refreshed within this scan.

The second bound is independent of the first bound. No equality, ordering, or shared index-domain relationship is established.

### 7. Perform the second scan

The second scan restarts its unsigned index at zero and continues while that index is strictly less than the captured second bound.

Each iteration performs these operations in order:

1. Read the working object’s dispatch-table reference and obtain the entry at byte offset 0x28C.
2. Invoke that entry with the workspace address, the working object pointer, and the current unsigned 32-bit index.
3. Call F-0763bbe10778 with the workspace address.
4. If the predicate result is nonzero, assign the current index to the addressable 32-bit temporary.
5. For that nonzero result, read destination slot B and call F-84652ce813be with only the destination value as an explicit argument.
6. Increment the unsigned index by one.

The second destination call must not be specified as receiving the index or its address. Neither is present in the supplied call representation.

The local index assignment does not establish an index-bearing destination update. Any effective additional argument, hidden state, or interpretation by the callee remains unknown.

### 8. Invoke the final object operation

After both scans complete, the routine compares the retained object pointer with null.

If it is nonnull, the routine reads its dispatch-table reference and calls the entry at byte offset 0x1C. No explicit arguments are shown.

If it is null at this point, the final operation is skipped.

This late null check does not protect earlier object accesses. A null acquisition result is therefore not an established supported input.

The routine then returns without an explicit value.

### Bounds and arithmetic

For a captured bound of zero, the corresponding scan performs no record retrievals, predicate calls, or selected-item calls.

For a bound of \(N\), normal execution visits indices zero through \(N-1\), in ascending order, exactly once each.

The largest unsigned 32-bit bound is 4,294,967,295. At that bound, the last visited index is 4,294,967,294. Its increment produces 4,294,967,295, after which the strict comparison fails. The loop does not need an increment from the maximum unsigned value back to zero.

A negative value at the machine-result level, if interpreted through the captured unsigned 32-bit representation, may produce a very large bound. The routine contains no separate plausibility or range check.

## Side effects

### External call ordering

On a normally completed invocation, the observable call order is:

1. F-8157a180d901.
2. F-df2422ba76c2.
3. F-7a304fc4cb8d for destination A.
4. First count operation.
5. First-scan record, predicate, and conditional destination operations.
6. F-7a304fc4cb8d for destination B.
7. Second count operation.
8. Second-scan record, predicate, and conditional destination operations.
9. Conditional final object operation.

No interleaving between the two scans is shown.

### Global reads and dependency mutations

Destination slots are read at their respective call sites. Their values are not captured once for the entire routine.

Consequently, if an earlier dependency changes a destination slot, a later read can supply the changed value. This applies even between preparation of a destination and a later selected-item call for that destination.

Object dispatch-table references are also read at the individual dispatch sites. The routine retains the object pointer, not a fixed copy of its dispatch table.

No assumption is made that a dependency preserves globals, destination contents, object contents, or dispatch-table state.

### Temporary storage and lifetime

The same 20-byte workspace is reused across both scans. No explicit initialization, clearing, or destruction of that workspace is shown.

The routine therefore does not itself guarantee that every byte has been written before predicate evaluation. That guarantee, if required, must come from the record-producing operations or the predicate’s narrower reading requirements.

The index temporary is also reused. Its address is passed only in selected first-scan calls.

Both storage regions are local to this invocation. Retaining their addresses for later use would require a dependency contract not supplied here.

### Errors and cleanup

The routine has no explicit error branch, retry, rollback, or error reporting.

Predicate results are used exclusively as zero/nonzero selection decisions; they are not interpreted as error codes.

No exceptional-exit cleanup mechanism is established. If a dependency fails to return normally, the evidence does not establish that destination B is prepared, that either remaining scan executes, or that the final object operation runs.

No explicit release of the initial 32-bit acquisition result or destruction of individual workspace contents is shown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid dependencies and normal returns unless stated otherwise.

### Both bounds are zero

Expected observations:

- Destination A’s preparation call precedes the first count query.
- Destination B’s preparation call follows that query and precedes the second count query.
- Neither record operation nor the predicate is called.
- No selected-item call occurs.
- The final object operation occurs if the retained pointer is nonnull.

### First scan selects only its middle index

Given a first bound of three and predicate results zero, negative one, and zero:

- First-scan record operations receive indices 0, 1, and 2 in order.
- Each record operation is immediately followed by predicate evaluation.
- Exactly one first-scan call to F-84652ce813be occurs.
- Its second explicit argument points to a 32-bit temporary containing 1 at call entry.

The negative predicate result selects the index because it is nonzero.

### Second scan selects an index

Given a second bound of two and predicate results zero and one:

- Second-scan record operations receive indices 0 and 1.
- Exactly one second-scan call to F-84652ce813be occurs.
- That call has the current destination B value as its sole explicit argument.
- An expectation that the call explicitly receives index 1 or its address is unsupported.

### A dependency changes a destination slot

If an earlier dependency changes destination slot A before a selected first-scan destination call, that call uses the value read from slot A at that later call site, not necessarily the value supplied to destination preparation.

### Count state changes during a scan

If a record operation changes the object’s underlying count state, the current scan still follows its already captured bound. The routine does not re-query the count each iteration.

### Object acquisition yields null

The routine still reaches destination A’s preparation call before attempting its first object dispatch. The final null check does not make this path safe. Graceful handling of null acquisition is not an acceptance requirement supported by the evidence.
