# F-8ae6e00b5350

## Purpose

F-8ae6e00b5350 conditionally constructs a packed 32-bit value and invokes one dependency with a selector, the numeric argument 2, and a pointer to that value.

The first input controls whether the operation occurs and which selector is passed. For first-input values 0 through 7, exactly one dependency invocation is established. For all other unsigned 32-bit values, no dependency invocation occurs.

The packed value combines the upper 16 bits of the fourth input, selected bits of the third input, and all eight bits of the second input. Two bits of the constructed value are always cleared.

A likely intent is to prepare a selector-addressed transfer or update. That interpretation is not established: the dependency’s purpose and the meaning of its second argument are unknown.

## Behavior

### 1. Index gate

The index is compared with 8 as an unsigned 32-bit value.

- Values 0 through 7 enter the packing and dependency-call path.
- Values 8 through 4,294,967,295 skip that path.
- A high-bit-set input is not interpreted as a negative value that might pass the comparison.

The rejected-index path performs no established externally visible write and invokes no dependency.

### 2. Constructed value

For an accepted index, a local 32-bit object is initialized with the following final numeric layout:

| Constructed bits | Value |
|---|---|
| 31–16 | Bits 31–16 of the upper-word input, unchanged |
| 15–14 | Zero |
| 13–8 | Bits 5–0 of the packed-fields input |
| 7–6 | Bits 7–6 of the flags byte |
| 5 | Bit 5 of the flags byte OR bit 6 of the packed-fields input |
| 4–0 | Bits 4–0 of the flags byte |

Equivalently, the four numeric byte positions, from most significant to least significant, are:

1. Bits 31–24 of the upper-word input.
2. Bits 23–16 of the upper-word input.
3. The low six bits of the packed-fields input, with the byte’s upper two bits cleared.
4. The flags byte, with its bit 5 additionally set whenever bit 6 of the packed-fields input is set.

The low-byte operation is an inclusive OR. It can set bit 5, but it cannot clear a bit already present in the flags byte.

The two upper bits of the next byte are cleared regardless of the corresponding packed-fields input bits. Consequently:

- Packed-fields bits 0–5 affect constructed bits 8–13.
- Packed-fields bit 6 affects constructed bit 5.
- Packed-fields bit 7 has no effect.
- Packed-fields bits 8–31 have no effect.
- Upper-word bits 0–15 have no effect.
- Every bit of the flags byte is retained.

The static construction establishes the upper half before completing the combined value and clearing constructed bits 14 and 15. The dependency is invoked only after the local object has its final value. No intermediate value is supplied to the dependency.

### Memory layout and observation

The numeric bit layout is established; the physical byte order is not.

For example, if the constructed numeric value is 0xA1B23F20:

- On a little-endian target, its four bytes in increasing address order would be 0x20, 0x3F, 0xB2, 0xA1.
- On a big-endian target, they would be 0xA1, 0xB2, 0x3F, 0x20.
