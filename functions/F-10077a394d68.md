# F-10077a394d68

## Purpose

F-10077a394d68 describes a sequence of memory transfers, arithmetic-derived accesses, global assignments, and two abnormal control-flow boundaries. The supplied static representation does not establish an application-level purpose.

Established behavior includes copying values among caller-associated locations, using numeric values as addresses, writing to addresses associated with two dependencies, and modifying global and fixed-address storage. These operations do not establish initialization, allocation, interrupt-vector installation, or ownership transfer.

This contract distinguishes:

- **Established static evidence:** represented operations, explicit access widths, expression widths, ordering, and branch conditions.
- **Inferred intent:** possible interpretations that are not contractual behavior.
- **documented_only unknowns:** behavior that the supplied representation cannot resolve, including anomalous shifts, signed overflow, undeclared global-storage widths, and the consequences of abnormal boundaries.

No runtime tests have been performed.

### Width and arithmetic rules

Explicitly typed indirect accesses establish 8-, 16-, or 32-bit transfers. This does **not** establish the widths of assignments to globals whose declarations are absent.

For a global assignment, this contract states the assigned expression and any established expression width. The destination’s storage width remains **documented_only** unless independently established. In particular, a byte-valued constant does not prove a byte store, and a 16-bit cast does not prove a halfword-sized destination.

Arithmetic follows these distinctions:

- Unsigned 32-bit operations wrap modulo \(2^{32}\).
- Signed 32-bit subtraction, addition, multiplication, and left shifts are not assigned wrapping semantics where the representation does not establish them.
- Apparent shifts of a 32-bit value by 32 remain unresolved.
- Signed right-shift results are described conditionally under conventional arithmetic-right-shift semantics.
- “Low byte” and “low halfword” mean the least significant 8 and 16 bits respectively.

Byte order is unknown. Overlapping accesses therefore cannot be translated into an unconditional byte-level final state.

### Preconditions and outputs

No validation is represented. Executing any prefix requires that its arithmetic and accesses be meaningful and permitted by the actual target.

There is no represented normal return or error-result channel. Observable outputs are completed memory effects and, if reached, an abnormal boundary. Earlier memory faults or arithmetic-related failures are possible. No rollback is represented.

## Behavior

### 1. Initial transfers

Let W be the first loaded word and T the initially loaded unsigned byte. The represented order is:

1. Read W through the sum of two inherited machine values.
2. Read T through the sum of the common inherited base and the third inherited value.
3. Write W as 32 bits at D plus `0x08`.
4. Write D as 32 bits at A plus `0x40`.
5. Write W as 32 bits at C plus `0x74`.
6. Read a signed 32-bit value at D plus `0x28`; retain it for subsequent calculations.
7. Read 32 bits at C plus `0x5C`.
8. Write C’s low byte at W’s numeric address plus `0x03`.
9. Write T as one byte at C plus `0x10`.
10. Write the low byte of the value read at C plus `0x5C` at numeric address T plus `0x1C`.

The final destination ranges from `0x1C` through `0x11B`. There is no null, range, or object-boundary check.

Both reads in steps 6–7 occur after the three initial word writes. Aliasing may therefore make them observe modified storage.

### 2. A-derived accesses

The following quantities describe this phase:

- **U:** Convert the result of signed subtraction A minus `0x38` to unsigned 32 bits.
- **H:** Twice the unsigned 32-bit result of A minus `0xE0`, with unsigned wrapping.
- **M:** The unsigned 32-bit result of A minus `0xE0`, masked with `0x7FFFFFFF`.
- **Q:** M logically shifted right by one.

U is established only when the preceding signed subtraction is defined. For signed 32-bit A, subtraction is defined when A is at least `-2147483592`. Lower inputs overflow the represented signed subtraction; assigning its result to an unsigned destination does not repair or define that overflow.

H uses unsigned arithmetic because the subtraction includes an unsigned constant. M ranges from zero through `0x7FFFFFFF`; Q ranges from zero through `0x3FFFFFFF`.

A separate destination base is formed from the signed value read at D plus `0x28`: shift left by two, then right by `0x20`. Signed-left-shift validity and the shift by 32 are unresolved. Call this the **unresolved word base** without assigning it a numeric value.

The represented order is:

1. Write Q’s low byte at the retained D-associated value plus `0x0897E8B8`.
2. Assign `0xB8` to a global marker. Its destination width is unknown.
3. Write U’s low byte at A minus `0x32`.
4. Write U as 32 bits at the unresolved word base.
5. Write `0xFFFF` as 16 bits at H plus `0x04`.
6. Write `0xFFFF` as 16 bits at H plus `0x06`.
7. Write byte `0xB8` at the unresolved word base plus `0x04`.
8. Write `0xFFFF` as 16 bits at H plus `0x02`.
9. Assign H’s low 16 bits to another global. The expression is 16 bits; the destination width is unknown.
10. Read an unsigned 16-bit value at H.
11. Zero-extend that value to an address and write the 32-bit value U masked with `0x897E8B80` there.

All uses of U retain its signed-subtraction qualification. No defined value is promised for U when that subtraction overflows.

The writes at H plus two, four, and six do not directly initialize the halfword at H. Other overlapping writes may nevertheless affect the subsequent read.

### 3. First dependency address and early boundary

Let P be the 32-bit address representation of F-e47d7b2e9c88.

The representation derives:

- A **secondary base** by treating P as signed and shifting right by `0x20`. Its value is unresolved.
- A **sign halfword** by signed right shift of P by 31, followed by truncation to 16 bits. Under conventional arithmetic-right-shift semantics, this is zero for nonnegative P and `0xFFFF` for negative P.

First, write the sign halfword as 16 bits at secondary-base offset `0x04`.

Then test P as signed:

- If negative, reach the first displayed invalid-instruction boundary.
- Otherwise, continue.

The negative branch retains all preceding effects, including the immediately preceding halfword write.

On the continuing branch:

1. Write the sign halfword as 16 bits at secondary-base offset `0x12`.
2. Write P as 32 bits at address P.
3. Read a signed 16-bit value at secondary base plus Q.
4. Repeat the 16-bit write at secondary-base offset `0x12`.
5. Repeat the 32-bit self-address write at P.
6. Sign-extend the loaded halfword, shift it right by 16, and write the 32-bit result at secondary-base offset `0x08`.

Under conventional arithmetic shifts, the last result is zero for a nonnegative loaded halfword and `0xFFFFFFFF` for a negative one. It is not the raw halfword value.

The repeated writes are distinct operations. They must not be collapsed when their effects are observable.

### 4. Global assignments and stack-derived accesses

The continuing sequence first:

1. Assigns zero to a global associated by its label with exception handling.
2. Forms a selector equal to `(P masked with 4) + 0x58`.
3. Writes the secondary base as 32 bits at selector plus `0x04`.
4. Assigns the 16-bit conversion of M shifted right by 17 to a global.
5. Assigns Q’s low byte, zero-extended to 16 bits, to a status-associated global.
6. Writes Q as 32 bits at four times the selector plus `0x10`.
7. Assigns Q to another global.

The selector is `0x58` or `0x5C`. The explicit 32-bit destinations in steps 3 and 6 are consequently `0x5C` or `0x60`, and `0x170` or `0x180`, respectively.

The global destinations in this list have unknown storage widths. The two 16-bit conversions establish expression widths only.

Let S denote the stack-associated pointer and L the address of its stack slot. The next accesses are:

1. Write the selector’s low 16 bits at S.
2. Write the secondary base shifted left by eight as 32 bits at S.
3. Write that same expression as 32 bits at S plus `0x14`.
4. Write S’s numeric representation as 32 bits at S.
5. Read 32 bits at twice S’s numeric representation.
6. Write that loaded value’s low halfword at S.
7. Write the loaded 32-bit value at the address specified by that value.
8. Write the signed-right-shift-by-31 result of S’s numeric representation as 32 bits at 32 times L plus `0x18`.
9. Read the byte-valued global used as the low component of the status update, concatenate `0x0005` above that byte, and assign the resulting 24-bit expression to the status-associated global.
10. Write S as a 32-bit pointer representation at four times S’s numeric representation plus `0x18`.

L and S serve different address calculations and must not be conflated.

The byte read for the concatenation occurs after the preceding indirect writes. It is not necessarily equal to Q’s previously assigned low byte. The containing global’s destination width remains unknown.

Signed left shifts and signed pointer-derived multiplications in this phase retain their unresolved overflow or shift-validity conditions.

### 5. Late global and address-derived operations

Next, read a global value into a signed 32-bit working value, called V here, and obtain F-8afdaab91693’s address as data.

The represented sequence then:

1. Assigns four times S’s numeric representation to an address-bearing global.
2. Uses that global’s value as both address and value for a 32-bit self-address write.
3. Uses that global again to address a 32-bit write of Q at offset `0x04`.
4. Writes four times V as 32 bits at address four times V.
5. Writes four times F-8afdaab91693’s address as 32 bits at V plus the result of shifting V left by six and then right by 17.
6. Assigns V’s upper 16 bits, obtained through unsigned conversion and logical shift, to the reset-component global identified as Reset_2.
7. Assigns zero to another exception-associated global.
8. At eight times F-8afdaab91693’s address, writes zero as 32 bits at offsets zero and four.
9. At offset `0x10` of that base, writes one byte equal to the base’s low byte plus eight, truncated to eight bits.

Global storage widths remain unknown, including the address-bearing assignment, the assignment to Reset_2, and the zero assignment.

The address-bearing global is used after being assigned. With unrestricted aliasing, an indirect write may affect a later use of that global; the contract does not replace every later access with an immutable copy of its first assigned value.

Signed multiplications and shifts are not unconditionally interpreted as wrapping address arithmetic.

### 6. Final fixed-location assignments and late reset read

The remaining order is:

| Order | Destination | Assigned expression |
|---:|---|---|
| 1 | Fixed location `0x86` | `0x897EA700` |
| 2 | Fixed location `0xEA700000` | `0x66` |
| 3 | Fixed location `0x0897EB26` | `0xEAEC` |
| 4 | Fixed location `0x12FD4C34` | `0x1A` |

None of these assignments has a destination width established by an explicit typed indirect access. In particular, the assignment at `0x86` is not established as a word store merely because its constant has a 32-bit representation.

At order 6, **read Reset_2 at that point** as the 16-bit upper component of a concatenation. Place `0xEA70` in the lower 16 bits and assign the resulting 32-bit expression to the reset-associated global. The destination width remains unknown.

This late read occurs after the intervening global, indirect, and fixed-location writes, including the self-address assignment at order 5. It must not be replaced with V’s upper halfword saved from the earlier Reset_2 assignment. Overlapping globals or aliasing may have changed the component in between.

Execution then reaches the final displayed invalid-instruction boundary.

## Side effects

The represented effects include:

- Explicit byte, halfword, and word transfers through calculated addresses.
- Global assignments with unresolved destination widths.
- Numeric pointer truncation and reuse of loaded values as addresses.
- Writes to dependency-associated addresses without calls.
- Writes to small numeric addresses and fixed locations.
- Partial overwrites and repeated writes whose order can matter.

No allocation, release, ownership transfer, cleanup, synchronization, or transactional behavior is established. Storing a pointer does not establish ownership transfer.

No non-aliasing guarantee is supplied. Global labels may overlap, and indirect accesses may overlap globals or caller-associated storage. Later reads consume the then-current storage, not necessarily an earlier assigned value.

An access failure or abnormal boundary can leave a completed prefix visible.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Initial propagation.** If W is `0x12345678` and the relevant accesses succeed, that value is written as 32 bits at D plus `0x08` and C plus `0x74`. A separate byte write occurs at `0x1234567B`.

2. **Small-address destination.** If T is `0xFE`, the later small-address byte write targets `0x11A`. Its value comes from the low byte of the value read at C plus `0x5C`.

3. **Defined signed subtraction.** If A is `-1`, A minus `0x38` is the defined signed result `-57`. Conversion gives U equal to `0xFFFFFFC7`; the A-minus-`0x32` byte write therefore carries `0xC7`, provided preceding operations and that access succeed.

4. **Signed subtraction overflow.** If A is the minimum signed 32-bit value, the represented subtraction by `0x38` overflows. No wrapping U or resulting U-derived store value is specified.

5. **Global width restraint.** Assigning `0xB8` to the global marker does not require a one-byte transfer. Assigning a 16-bit expression to another global likewise does not establish a two-byte destination.

6. **Signed halfword reduction.** On the continuing branch, a loaded signed halfword with bits `0x8000` yields a stored word of `0xFFFFFFFF` under conventional arithmetic shifts; `0x7FFF` yields zero.

7. **Early abnormal boundary.** A negative signed representation of F-e47d7b2e9c88’s address reaches the early boundary after the secondary-base-plus-four halfword write. The later self-address writes are not on that branch.

8. **Late reset component.** Suppose the earlier Reset_2 assignment supplies `0x1234`, but an intervening overlapping write changes its subsequently read component to `0xABCD`. If execution reaches the final concatenation, its expression is `0xABCDEA70`, not `0x1234EA70`. This specifies the expression, not the unknown destination storage width.

9. **Terminal path.** If all required arithmetic and accesses permit continuation and the negative branch is not taken, the represented path reaches the final abnormal boundary. No ordinary successful return is established.
