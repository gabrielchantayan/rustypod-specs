# F-09a0c69fef86

## Purpose

F-09a0c69fef86 conditionally constructs an operation sequence relating a supplied target to a separately selected candidate. Admission, structural compatibility, and an auxiliary compatibility condition must pass before construction begins.

The ordinary 32-bit result distinguishes completion paths, not general success:

- **Zero before construction:** a checked admission or compatibility condition failed.
- **One after construction:** construction completed with a zero closing handle.
- **Zero after construction:** construction completed through the additional sequence associated with a nonzero closing handle.

Consequently, zero does not mean “no side effects,” and one does not establish that the constructed operations have executed or achieved their intended effect.

**Inferred intent:** the operation patterns and diagnostic association suggest a uniqueness-related transfer optimization. That interpretation imposes no additional requirements concerning execution, ownership transfer, atomicity, or error reporting.

## Behavior

### Admission and selection

Admission is short-circuited. After the null-request check, target admission requires a zero word at 0x20, followed by a zero byte at 0x39. Failure of the word check prevents the byte read. Mode validation occurs after these target accesses but before descriptor inspection.

Descriptor admission requires discriminator one, then a zero admission word. Request admission then requires zero words at 0x10, 0x1c, 0x14, 0x2c, and 0x20, in that order, followed by a zero byte at 0x05. Failure prevents later checks.

The nested selector is inspected only after these checks pass. Its discriminator must be one. Its character-slot pointer must lead to a character pointer whose first character is `k`. No later character or terminator is inspected. The intermediate pointers have no explicit null checks.

F-3747d6ba198f selects the candidate using context, zero, descriptor word 0x0c, and descriptor word 0x08. The relative evaluation order of those two lookup-word reads is not established. A null candidate or one identical to the target causes zero return before candidate-field eligibility checks.

A distinct candidate must satisfy, in order:

1. Admission byte 0x39 is zero.
2. Admission word 0x18 is zero.
3. Its count equals the target count.
4. Its classification equals the target classification.

The candidate admission word is deliberately distinct from the target admission word: 0x18 versus 0x20.

### Compatibility requirements

**Position-paired arrays.** Array compatibility starts at position zero and uses the target count as a signed 32-bit bound. Equal counts are required earlier, but nonpositive counts are not rejected; they produce no array visits while the bound remains nonpositive.

For each visited position:

- Equality bytes must match before comparison-word processing.
- The candidate comparison word is fetched before the target comparison word is tested.
- Two zero comparison words pass without a comparison dependency.
- Exactly one zero fails.
- Two nonzero words pass only when F-e6db2171781a returns zero.

The supplied call representation gives F-e6db2171781a no explicit arguments. The dependency’s effective inputs remain unresolved.

Directional compatibility follows comparison-word compatibility. A nonzero target directional byte requires a nonzero candidate directional byte. A zero target byte bypasses the candidate-byte read.

The directional check rereads array pointers rather than relying exclusively on the addresses used for the preceding checks. Subsequent loop-bound checks reread the target count. Candidate count equality is not revalidated on each iteration. Compatibility therefore does not describe an immutable snapshot when dependencies can mutate storage.

**Lists.** Every visited target entry must have at least one candidate entry for which F-8342452e4743 returns nonzero, with the target entry supplied first.

Each target visit obtains the candidate’s current list head before reading that target entry’s marking byte. A nonzero marking byte records a persistent condition for this invocation; later changes cannot clear it.

Search advances through candidate next pointers after unsuccessful comparisons. Exhaustion rejects compatibility. Each target entry starts a fresh search, so candidate entries are not consumed, a candidate entry may match several target entries, and extra candidate entries are permitted. The target next pointer is read after a match, allowing dependency mutations to affect subsequent traversal.

An empty target list requires no candidate-list match and records no marking condition.

**Auxiliary field.** After array and list compatibility, a zero target auxiliary word bypasses the auxiliary dependency. Otherwise, F-728a4665dcf4 receives the candidate auxiliary word and must return nonzero.
