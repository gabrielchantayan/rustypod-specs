# F-d7373ea964c3

## Purpose

F-d7373ea964c3 performs a selector-controlled operation on caller-provided storage. Three outcomes are established by the supplied static representation:

- **Initialization:** write a four-byte field containing 8, obtain an opaque eight-byte value from a dependency, and store that value at the beginning of the record.
- **Conversion:** process a four-byte record value through dependencies, then either store a two-byte result through an address held in the record or invoke an alternate output chain.
- **No selected operation:** return without explicitly accessing the record.

Every visible normal-return path returns the four-byte value zero. This return does not distinguish successful conversion, rejected conversion, initialization, or an unrecognized selector.

“Initialization,” “conversion,” and “output” describe the observed data flow. Their application-level meanings are not established.

## Behavior

### Branch selection and external-read sequence

The comparison selector is captured before branch selection. Subsequent dependency calls do not cause this captured value to be refreshed.

The initialization test uses the original selector plus the **first observation** of the selector bias. A zero result selects initialization immediately. On that path, the primary match value and secondary adjustment are not read by the visible selection logic.

When initialization is not selected, selection performs a new calculation using a **second observation** of the selector bias and an observation of the primary match value. The resulting difference is:

**original selector + second bias observation − first primary-match observation.**

This calculation is not established to reuse the biased value tested for initialization. Nor does the supplied representation establish the relative evaluation order of the bias read and primary-match read within this expression.

After the difference has been calculated, the primary match value is read **again, unconditionally on this non-initialization path**. This second observation is distinct from the observation used in the subtraction.

The remaining decision depends on the calculated difference:

- If the difference is zero, conversion is selected. The second primary-match read has nevertheless occurred; the secondary adjustment is not read.
- If the difference is nonzero, the secondary adjustment is read. Conversion is selected only if adding that observation to the difference produces zero.
- Otherwise, no operation is selected.

The second primary-match observation does not change either branch outcome: when the difference is zero, conversion already matches; when it is nonzero, the secondary-adjustment observation replaces its role. Its lack of influence on the result does not remove the source-visible read.

For **stable external values**, and arithmetic away from unresolved overflow boundaries, this simplifies to:

- Initialization when selector plus bias equals zero.
- Otherwise, conversion when selector plus bias equals the primary match value, or equals the primary match value minus the secondary adjustment.
- Otherwise, no selected operation.

These equations are conditional simplifications, not a substitute for the separate-read contract. Initialization has precedence only when its own test succeeds; the later calculation may observe a different bias.

All selector calculations are 32 bits wide. Unbounded mathematical arithmetic is not an adequate description at overflow boundaries. The supplied representation does not independently establish portable signed-overflow behavior.

### Initialization

Initialization directly writes the four-byte value 8 at record offset 20 **before** calling F-e8a86fe70632.

If that dependency returns normally, its opaque eight-byte return is written at record offset 0. The function then returns zero.

The first write has already occurred if the dependency fails to return normally. No eight-byte write after the call is established in that case.

The dependency’s result is not established to be a particular numeric, pointer, time, or composite representation. No conversion dependency is called on this path.

### Conversion preparation

Once conversion is selected, the conversion seed is read and placed in the first slot of a local array containing 64 four-byte slots, totaling 256 bytes. The function explicitly initializes only that first slot before passing the array to dependencies.

The function then reads the four-byte input at record offset 0 and calls F-695b165af768 with that value and the address of a local four-byte region. Its return value is not used.

After that call returns, F-a50f6b477c94 receives the same local-region address, the local-array address, and a zero third argument.

The supplied local layout also identifies three individually accessed bytes immediately following the four-byte region. This is evidence of where later byte reads occur, not proof that either dependency accepts a seven-byte output region or initializes all seven bytes.

### Validation and result construction

The working result is set to zero after F-a50f6b477c94 returns.

Only a return of **exactly 1** permits F-f523a2ef5e05 to be called. That second dependency receives the same two local addresses and a zero third argument.

F-f523a2ef5e05 permits result construction on **any nonzero return**. A zero return rejects it. Thus the two gates have different acceptance rules.

If either gate rejects, the working result remains zero and execution takes the ordinary two-byte-store exit. The captured comparison selector is not a prerequisite for that failure exit.

When both gates accept, the three bytes immediately following the initial four-byte region are copied, in address order, into the first three bytes of a separate four-byte local object. Each corresponding destination byte is assigned from its source byte, and the final byte is set to zero. The object’s address is passed to F-b902b5c89b26, whose four-byte integer return becomes the working result.

The terminating zero does not exclude embedded zeros in the preceding three bytes. Their interpretation belongs to F-b902b5c89b26; the function establishes neither numeric syntax nor character encoding. No explicit range validation is applied to its return.

After successful result construction, the original selector is compared with the comparison selector captured at entry:

- Equality selects the ordinary two-byte store.
- Inequality selects alternate output.

### Ordinary two-byte store

This exit is used after either validation failure, or after successful result construction when the selector equals the captured comparison selector.

The function reads the four-byte destination address from record offset 4 **after the preceding conversion dependencies have returned**. It then writes the low 16 bits of the working result through that address and returns zero.

Consequences include:

- Validation failure writes a two-byte zero regardless of the selector’s relationship to the captured comparison selector.
- Successful conversion to zero produces the same direct destination value as failure.
- Larger or negative results are narrowed to their low 16 bits; no saturation or explicit range error is visible.
- No bytes above those two destination bytes are directly written by this exit.

### Alternate output

Alternate output requires both validation gates to accept and the original selector to differ from the comparison selector captured at entry.

F-9d0ecc5f6adf is called first, with no visible arguments. After it returns, the output context is read for a call to F-5710a8628cba. That call receives the preceding return value, the observed output context, and the working result plus hexadecimal 605E.

The adjustment is a 32-bit calculation, not a two-byte adjustment. Its overflow-boundary behavior has the same unresolved arithmetic qualification as selection.

After F-5710a8628cba returns, the destination address is read from record offset 4. F-42c6c3f4a2d0 receives that dependency’s return, 255, and the observed destination address.

The function then returns zero without performing its ordinary two-byte store. The final dependency may write through the destination, but its write width, format, and failure behavior are unknown.

## Side effects

Direct effects are limited to the selected record writes, the ordinary destination write, and local-storage modifications described above. Initialization and conversion are mutually exclusive within one invocation.

External reads are themselves part of the established access contract:

- Entry always reads the comparison selector.
- The initialization test reads the bias.
- The non-initialization path rereads the bias and reads the primary match value twice.
- Only a nonzero difference causes the secondary-adjustment read.
- Conversion and alternate output introduce their own conditional external reads.

Dependency effects are not bounded by the direct writes. In particular:

- The saved comparison selector remains the entry observation even if a dependency modifies its external source.
- F-9d0ecc5f6adf must not be assumed to preserve the output context; that context is observed after the call.
- Conversion dependencies must not be assumed to preserve the destination-address field. The field is observed only when the selected exit needs it.
- The initialization dependency can observe the already-performed offset-20 write, subject to its access capabilities.

No explicit allocation, release, or ownership-transfer operation appears in the function. This does not establish that dependencies neither allocate nor release memory. Passing local or caller-provided addresses also does not establish retention permissions, lifetime requirements, or ownership transfer.

No disjointness check is present. A destination that aliases the record or other shared storage receives the ordinary two-byte write at that aliased location.

## Acceptance examples

These are conditional examples, not executed tests. Assume valid required storage, normally returning dependencies, and arithmetic away from unresolved overflow boundaries.

1. **Initialization wins.** If the first bias observation makes selector plus bias zero, the comparison selector has already been read. Offset 20 receives 8 before F-e8a86fe70632 runs; its return is then stored at offset 0. No second bias observation or primary-match observation occurs.

2. **Repeated bias observations differ.** Let the selector be 10, the first bias observation be 1, the second be −10, and the primary-match observation used in subtraction be zero. Initialization does not match, but the later difference is zero and conversion is selected. The primary match value is still read a second time, even if that observation is 123. The secondary adjustment is not read.

3. **Nonzero difference rejects.** Suppose initialization does not match, the later difference is 4, and the secondary-adjustment observation is 3. The second primary-match read occurs before the secondary-adjustment read. No conversion dependency is called, no record field is explicitly accessed, and the function returns zero.

4. **First validation rejects.** If conversion is selected and F-a50f6b477c94 returns 2, F-f523a2ef5e05 is not called. The eventual destination receives two zero bytes even when the selector differs from the captured comparison selector.

5. **Second validation rejects.** If the first validator returns 1 and the second returns zero, F-b902b5c89b26 and the alternate-output dependencies are not called. The ordinary exit writes a two-byte zero.

6. **Successful narrowing.** If both validators accept, the selector equals the captured comparison selector, and F-b902b5c89b26 returns hexadecimal 12345678, the direct destination receives the 16-bit value hexadecimal 5678. Its byte order depends on the target representation.

7. **Successful alternate output.** If both validators accept, the selector differs from the captured comparison selector, and the result is 5, F-5710a8628cba receives hexadecimal 6063 as its third argument. Its output-context argument is observed after F-9d0ecc5f6adf returns. The destination address is observed after F-5710a8628cba returns, then passed to F-42c6c3f4a2d0 with 255. No direct two-byte store follows.

The inferred intent is a staged conversion with two output forms. No specific parser, encoding, resource-management model, or application protocol is established.
