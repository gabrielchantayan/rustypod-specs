### Assembly-region contents

The assembly region is populated by several independent byte-producing operations. No complete byte layout is established.

For the descriptions below, byte results are reduced modulo 256. The equations describe stored-byte values only; they do not replace wider arithmetic used for control or indexing.

#### Four ordered writes

One construction operation derives a 32-bit quantity from a globally scaled aggregate, subtracts one, and performs four assembly writes.

The first three writes select, respectively, the quantity’s bits 24–31, 16–23, and 8–15. They do not include its low byte.

For the first two writes, a captured eight-bit global value is shared. If that value is \(g\) and the selected byte is \(b\), the stored byte is:

\[
\bigl(163g(b+1)+236\bigr)\bmod256.
\]

The third write uses the corresponding global in two operand positions rather than using that captured value. If the multiplicative and additive occurrences supply low-byte values \(g_m\) and \(g_a\), its stored byte is:

\[
\bigl(163(g_m b+g_a)+236\bigr)\bmod256.
\]

When both occurrences supply the same value \(g\), this reduces to the first formula. The representation does not establish an evaluation order between those two operand occurrences or guarantee stability under concurrent global changes.

The fourth write depends separately on the aggregate’s low byte \(a\):

\[
(163a+236)\bmod256.
\]

Its intermediate 16-bit narrowing does not alter this stored-byte equivalence.

The four writes occur in that order. If their position selectors coincide, later writes overwrite earlier ones. If argument setup has established the selectors and they have not been replaced, the destinations are assembly offsets zero through three.

## Acceptance examples

These are conditional static examples, not executed tests. Every memory example assumes valid calculated addresses and sufficient storage.

1. **Unchanged transferred byte.** If either single-byte transfer is reached with source byte **0xA7**, the corresponding destination write stores **0xA7** at the same calculated index.

2. **Input-byte transformation.** A reached input-derived construction stores **0xEC** for source byte **0x00**, and **0x89** for source byte **0x01**.

3. **High-byte extraction.** If a reached highest-byte operation uses further-scaled quantity **0x12345678**, the selected byte is **0x12** and the assembly write stores **0xF6**.

4. **Different low-byte coefficient.** If the earlier fourth-argument product has low byte **0x01**, its low-byte construction stores **0x8F**, not **0x89**.

5. **Stable global multiplier.** If the four-write operation uses multiplier low byte **1** throughout and one of its first three selected bytes is **0x00**, that write stores **0x8F**.

6. **Separate multiplier occurrences.** If the third write uses selected byte **0x00**, multiplicative occurrence **1**, and additive occurrence **2**, it stores **0x32**. This example is conditional on those observed operand values; it does not assert that such changes occur.

7. **Coincident positions.** If all four position selectors designate the same valid assembly byte, that byte ends with the fourth write’s value. Four writes do not imply four distinct populated bytes.

8. **Fixed bytes.** The fixed assembly operation stores **0x4F**. The fixed destination operation stores **0xEC**. Neither is replaced by zero under an assumed string interpretation.

9. **Saved-pointer independence.** If the second argument was saved before the multi-call interaction, the final F-0b6f5f32b71e call receives that saved pointer even though the candidate becomes the work-region address earlier in the interaction.

10. **Post-call global observation.** If an earlier call changes the global supplying the third F-74d7981315b3 call’s first argument, the later argument acquisition uses the post-call global state, not an unconditional pre-sequence snapshot.

11. **Unsigned return boundary.** Reaching the return operation with result bits **0xFFFFFFFF** returns **4294967295**. No error interpretation follows from that value.

12. **Null boundary.** A null first argument alone establishes neither a zero return nor avoidance of memory access.
