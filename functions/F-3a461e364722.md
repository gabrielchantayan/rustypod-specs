# F-3a461e364722

## Purpose

F-3a461e364722 conditionally processes an object and its record collection, changes two byte-sized controls, invokes dependent operations, and scans records selected by a flag bit.

The processing path is entered only when the low 32 bits of an initial collection query are zero. Otherwise, the function skips processing but still performs a second query and temporary-descriptor cleanup.

On the processing path, a nonzero intermediate result causes cleanup and an immediate zero return, without explicit restoration of the controls. A zero intermediate result leads to further operations, control restoration, a collection operation, and record traversal. Selected records trigger scratch-record updates and a removal sequence. A nonzero scratch first word after traversal causes submission of the scratch record.

**Inferred intent:** temporary-mode processing followed by selected-record consolidation. The semantic meanings of the controls, query results, state values, and record fields are not established.

All guarantees below concern explicit behavior and call ordering. Dependency names do not establish their effects, ownership rules, or preservation of memory.

## Behavior

### Entry and first query

The function performs these actions in order:

1. Reads and saves the eight-bit value at `+0xEF9`.
2. Reads and saves the eight-bit value at `+0xEFA`.
3. Initializes the temporary descriptor’s three 32-bit words to zero.
4. Calls F-beaa3d5aacef with the collection descriptor address.

The initial query result is represented as 64 bits. Its low 32 bits select the path. On the processing path, its high 32 bits are passed to F-0a08bd5d35c9.

The controls are therefore saved before the first query. If that query changes them, subsequent restoration still uses the entry snapshots.

### Nonzero initial low half

If the initial query’s low 32 bits are nonzero, the function bypasses the processing path.

It calls F-beaa3d5aacef again with the collection descriptor address, captures that result’s low 32 bits, calls F-b510f8158e70 with the temporary-descriptor address, and returns the captured value.

This path makes no explicit processing-state, control, marker, record, or collection-end writes. Dependency side effects remain possible. The two query results need not agree.

### Processing entry and intermediate failure

If the initial query’s low half is zero, the function:

1. Writes zero to `+0xEF9`.
2. Reads a fixed global 32-bit datum.
3. Writes one to `+0xEFA`.
4. Writes the 32-bit value one to `+0xE38`.
5. Calls F-0a08bd5d35c9.

That call receives, in order:

1. The object address.
2. The initial query result’s high 32 bits.
3. The 32-bit constant 2.
4. The 32-bit constant 0.
5. The captured global datum.

If its 32-bit result is nonzero, the function calls F-b510f8158e70 on the temporary descriptor and returns zero immediately.

On this branch there is no explicit control restoration, state-3 write, marker write, scan, or final query. The last direct writes to the controls and state are respectively 0, 1, and 1. Those are not guaranteed exit values because dependencies may modify the object.

### Successful intermediate processing

If F-0a08bd5d35c9 returns zero, the following calls occur in order:

1. F-c19e8ee32570 with the temporary-descriptor address and collection descriptor address.
2. F-41899b1592e0 with the object address.
3. F-087700124fe9 with the object address.

The function then writes one to `+0xEF9`, zero to `+0xEFA`, and the 32-bit value three to `+0xE38`, in that order.

It calls F-d5765e000192 with the object address. After that call returns, it restores `+0xEF9` from its entry snapshot, then restores `+0xEFA` from its entry snapshot.

Restoration preserves the original eight-bit patterns, including non-Boolean values. There is no corresponding restoration of the state word at `+0xE38`.

### Collection operation and scan setup

After restoring the controls, the function calls F-8601cc0f6544 with seven arguments:

1. The collection descriptor address.
2. The descriptor’s current first 32-bit word.
3. The temporary descriptor’s current first 32-bit word.
4. The temporary descriptor’s current second 32-bit word.
5. The previously captured global datum.
6. Zero.
7. Zero.

The global datum is reused rather than explicitly reloaded. The temporary descriptor’s third word is not explicitly passed.

After the call returns, the function writes one to `+0xE8C`. It then captures the collection’s begin pointer as the traversal cursor and calls an unidentified external dependency with the scratch-storage address and size 24.

The cursor capture precedes that external call. If the call changes the descriptor’s begin pointer, the cursor is not explicitly refreshed to match it.

The external dependency’s semantics are unknown. In particular, the supplied material does not establish that it zeroes the scratch storage or that it declines to retain the scratch address.

### Traversal condition and unselected records

Each loop condition compares the cursor with the end pointer currently stored at `+0xEB4`. The end pointer is not frozen at scan entry.

If they are equal, traversal ends.

Otherwise, the function reads the byte at cursor offset `+20` and tests mask `0x02`. If the bit is clear, it advances the cursor by 24 bytes. This branch makes no direct record-field or scratch-field write.

### Selected-record scratch handling

If the selection bit is set, the function examines the current 32-bit scratch first word.

If that word is zero, the function copies the selected record’s first 32-bit word into it. No other scratch-field assignment is explicit on this branch.

If the scratch first word is nonzero:

1. The selected record’s word at `+12` is compared with the scratch word at `+12`.
2. On inequality, the scratch word at `+12` is written with zero.
3. A 32-bit value is read at offset `+12` from an object reached through a global reference and written to scratch offset `+4`.
4. Scratch offset `+8` is written with zero.

The last two writes occur whether the comparison matches or differs. This global-backed read occurs on each execution of the nonzero-first-word branch; it is separate from the earlier captured global datum.

The copy-only branch does not initialize the scratch comparison word at `+12`. Its value comes from whatever scratch state exists at that point.

A zero selected-record first word leaves a currently zero scratch first word zero immediately after that copy. This is a local statement about that assignment, not a guarantee about subsequent iterations or final submission.

### Selected-record removal sequence

After scratch handling, the function compares the collection’s current begin and end pointers.

If they differ:

- It compares the current end pointer with the cursor plus 24 bytes.
- If those addresses differ, it calls F-e0f6aed6231a with the cursor plus 24 bytes.
- It then reads the current end pointer, subtracts 24 bytes, and stores the result at `+0xEB4`.

The decrement therefore uses the end pointer available after F-e0f6aed6231a returns, when that call occurs. It is not necessarily based on the end value used to decide whether to make the call.

The cursor does not advance on the selected-record branch. The next loop condition compares that unchanged cursor with the then-current end pointer.

If begin and end compare equal inside this branch, neither the call nor the decrement occurs. The cursor remains unchanged; progress is not established.

**Inferred intent:** F-e0f6aed6231a may support removal of a non-final record. Its actual effect on records, descriptors, globals, or previously exposed local storage is unknown. Stable compaction is not established.

In particular, the external dependency has already received the scratch address. No supplied contract excludes its retention or later use through F-e0f6aed6231a. Scratch preservation across that call must not be assumed.

### Submission, final query, and cleanup

After traversal ends, the function reads the current scratch first word.

- If nonzero, it calls F-a033e5498ce3 with the collection descriptor address and scratch address.
- If zero, it skips that call.

It then calls F-beaa3d5aacef with the collection descriptor address, captures the low 32 bits of the result, calls F-b510f8158e70 with the temporary-descriptor address, and returns the captured value.

Cleanup does not trigger a re-query. Changes made during cleanup do not change the already captured return value.

## Acceptance examples

These examples are conditional static specifications, not runtime observations.

### Initial-query bypass

Given an initial query with a nonzero low half and a final query with low half 7:

- No direct processing-path writes occur.
- The query is called twice.
- F-b510f8158e70 is called once.
- The return value is 7, independently of the first query’s low-half value.

### Intermediate failure

Given an initial query with low half zero and high half 9, followed by a nonzero F-0a08bd5d35c9 result:

- Its second argument is the 32-bit value 9.
- The control writes 0 and 1 and state write 1 precede that call.
- Temporary-descriptor handling occurs once.
- No final query occurs.
- The return value is zero.
- Neither saved control is explicitly restored.

### Exact restoration

Given entry controls `0xA5` and `0x7E`, and normal completion through successful intermediate processing, the explicit restoration writes put those exact byte values back before F-8601cc0f6544 is called.

This does not guarantee their values after that or any later dependency executes.

### Stable single selected record with zero first word

Assume that, after the external scratch call:

- The cursor points to the collection’s sole 24-byte record.
- Begin equals the cursor and end equals cursor plus 24.
- The record is selected and its first word is zero.
- The scratch first word is zero.
- The object, record, and scratch storage are distinct and remain stable except for the described direct writes, with no asynchronous modification.

Then:

- Scratch handling takes the copy-only branch and writes zero to its first word.
- F-e0f6aed6231a is not called.
- The end pointer is reduced by 24 bytes and becomes equal to the unchanged cursor.
- Traversal ends.
- The scratch first word is still zero when tested, so F-a033e5498ce3 is skipped.

These guarantees rely on the single-record configuration: no dependency call intervenes between the scratch copy and the submission decision.

### Multiple zero-valued selected records

An initially zero scratch first word and zero first words in every selected record are not sufficient to guarantee repeated copy-only handling or skipped submission.

If middle-record handling calls F-e0f6aed6231a, scratch preservation is unknown. If that call makes the scratch first word nonzero, later handling may take the other branch and final submission may occur.

Repeated copy-only handling and skipped submission require additional premises: intervening dependencies preserve the scratch first word, the zero-valued record condition remains true at each actual visit, traversal remains valid and terminates, and no other modification changes the scratch first word before its final test.

### Comparison mismatch

Given a selected record, a nonzero scratch first word, scratch comparison word 5, record comparison word 6, valid distinct storage, and a valid global-backed read:

- Scratch offset `+12` is written with zero.
- Scratch offset `+4` receives the global-backed word.
- Scratch offset `+8` is written with zero.

If the comparison words instead match, the latter two writes still occur, but there is no direct write to scratch offset `+12` on that branch. These statements describe scratch handling before any subsequent removal dependency runs.
