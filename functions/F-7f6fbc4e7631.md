# F-7f6fbc4e7631

## Purpose

The available static representation describes a routine that derives two scaled values from a caller-supplied address, invokes a sequence of dependencies, writes a six-word record through an indirectly obtained destination, and invokes further dependencies before reaching an undecoded terminal region.

The routine’s application-level purpose is **unknown**. The six-word write resembles record initialization, but allocation, registration, device configuration, and ownership transfer are not established. The dependency sequence is observable behavior in its own right; it must not be reduced to an assumed higher-level operation.

This contract distinguishes:

- **Established static evidence:** operations and ordering visible in the supplied representation.
- **Conditional interpretation:** behavior requiring assumptions about integer width, instruction semantics, memory validity, or dependency return.
- **documented_only unknowns:** details that the supplied material does not establish.

No runtime tests have been performed.

## Behavior

### 1. Capture state and derive values

The visible operation order begins with:

1. Read the fixed-location word and retain its value for the fifth record word.
2. Read a word at input address plus `0x10`; multiply that value by `0x10000`.
3. Read a word at input address plus `0x10` again; shift this second value left by 12 bits.

This contract calls the two derived results the **wide-scale value** and the **page-scale value**, respectively.

These are separate reads. The representation does not establish that the input location is immutable, ordinary RAM, or free from concurrent modification. Consequently, the two results must not unconditionally be described as transformations of one shared snapshot.

No dependency call is shown between those two reads.

4. **U-04** has no explicitly shown argument.

### 3. Select and initialize the destination record

After U-06 returns:

1. Read an unsigned 16-bit value from the address equal to the page-scale value plus `0x2e`.
2. Convert that value to the destination address.
3. Invoke **U-07**.
4. If U-07 returns, perform six word stores in the following order.

| Destination byte offset | Stored value |

The selector read occurs **before** U-07. No selector reread is shown after U-07. A selector modification by U-07 therefore does not itself change the already selected destination in the represented data flow.

The fixed-location word is likewise captured before the initial dependency sequence. The fifth store uses that captured value, not a fresh read after U-07.

No dependency call appears between the six stores. This does not make the initialization atomic. A fault, interrupt, concurrent observer, or device-side effect may expose only a prefix of the writes.

### Arithmetic interpretation

The representation contains multiplication, left shifts, and address additions on integer-sized values. It does not independently establish signed-overflow or address-wrap semantics.

Under an explicitly conditional **32-bit modular interpretation**:

- The wide-scale value retains the low 32 bits of the first field value multiplied by `0x10000`.
- The page-scale value retains the low 32 bits of the second field value shifted left by 12.
- U-02 receives the low 32 bits of the wide-scale value shifted left by 5.
- U-09 receives the low 32 bits of the page-scale value shifted left by 3.
- Address additions retain the low 32 bits.

This interpretation must not be treated as established portable signed arithmetic. In particular, the multiplication and shifts can exceed signed 32-bit range even for positive input values. Negative operands introduce further uncertainty in a source-language reading of left shift.

If both input reads return the same bit pattern and modular arithmetic applies, the U-02 and U-09 arguments reduce to shifts of that pattern by 21 and 15 bits, respectively. This is a conditional relationship, not permission to merge the two reads.
