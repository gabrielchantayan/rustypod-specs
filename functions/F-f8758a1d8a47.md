# F-f8758a1d8a47

## Purpose

F-f8758a1d8a47 updates selected fields of a caller-provided object, optionally transfers information into an embedded region, chooses one of two field-value pairs for recognized selectors, and invokes a three-call processing chain. Its result is the final 32-bit contents of the object field at offset `0x04`.

The established behavior is an ordered sequence of memory accesses and dependency calls. The semantic meanings of the object, selector, two value pairs, and payload are not established. In particular, the field-value pairs must not be treated as dimensions, and the returned word must not be treated as a success code, without additional evidence.

This contract describes behavior supported by static evidence. No runtime tests have been performed.

## Behavior

### Initial state change and payload capture

The first established memory write sets the 32-bit object field at offset `0x04` to zero.

The incoming payload is then copied into function-local 32-bit storage. The original payload and this mutable copy must be distinguished: later processing receives the address of the copy, and the final dependency receives whatever word remains there afterward.

The initial zero is not necessarily the return value. Dependencies execute before the return field is read again.

### Conditional source transfer

The function compares the source address with the address at object offset `0x40`.

- If the addresses are equal, F-151ab4bfe553 is not called. The function does not directly read the source word at offset `0x04`.
- If the addresses are unequal, it reads the source word at offset `0x04` and calls F-151ab4bfe553 with:
  1. the address at object offset `0x40`;
  2. the 32-bit word just read from the source.

The comparison is address equality, not content equality. Distinct regions with identical contents still take the transfer path.

The initial write to object offset `0x04` precedes the source read. Thus, if the source address equals the object address, the source read observes the zero just written, assuming ordinary stable memory and no external interference. That address relationship is different from the skipped-transfer case, which requires the source address to equal the address at object offset `0x40`.

No ownership or copy semantics can be assigned to F-151ab4bfe553 from this call alone. Its second argument is a word, but the evidence does not establish whether that word represents a scalar, pointer, handle, or other value.

### Selector recording and paired writes

After the optional transfer call returns, the function reads a primary external comparison word. It then writes the supplied selector to object offset `0x14`.

Consequently, F-151ab4bfe553, when called, runs before the selector store and before the primary comparison-word read. Its effects cannot be assumed absent.

The selector determines one of three paths:

| Condition | Direct write to offset `0x0c` | Subsequent direct write to offset `0x08` |
|---|---:|---:|
| Selector minus primary comparison word is zero | `0x000000dc` — 220 | `0x000000b0` — 176 |
| First condition is false, but selector minus primary comparison word plus secondary comparison word is zero | `0x000002d0` — 720 | `0x000001e0` — 480 |
| Neither condition holds | No write | No write |

The first condition has priority. When it succeeds, the secondary comparison word is not needed by the shown behavior.

On the second path, the secondary comparison word is read only after the selector has been stored at object offset `0x14`. The primary comparison uses the value read before that store. This distinction matters if unusual aliasing makes the selector store affect external comparison storage.

For either recognized case, the write to offset `0x0c` precedes the write to offset `0x08`. There is no evidence that the pair is updated atomically.

For an unrecognized selector, this function performs no direct write to either field. That does not guarantee preservation of their entry values: the optional transfer dependency has already run, and subsequent dependencies may also modify accessible state.

A 32-bit modular interpretation makes the second condition true when the selector equals the primary comparison word minus the secondary comparison word modulo \(2^{32}\). That is a useful inferred machine-level interpretation, not independently verified overflow behavior. The supplied material does not establish the instruction semantics or source-language overflow rules.

No widening, saturation, range normalization, or explicit overflow handling is shown.

1. F-44362605ab79 receives the address at object offset `0x40`.
2. F-4784b1a4efe2 receives:
   - the 32-bit result returned by F-44362605ab79;

3. F-10bf357441c5 receives:

The return values of F-4784b1a4efe2 and F-10bf357441c5 are not used by this function. No conditional branch based on their returned values is shown.

After F-10bf357441c5 returns, the function reads object offset `0x04` and returns that word. It does not return a cached copy of the entry-time zero.

## Acceptance examples

These examples are conditional acceptance criteria, not runtime observations. Unless stated otherwise, they assume valid memory, normal dependency returns, stable comparison words, and dependencies that do not modify the fields being checked.

### First selector case

If the selector and primary comparison word are both 100:

- object offset `0x14` receives 100;
- offset `0x0c` receives 220 before offset `0x08` receives 176;
- the second selector condition is not evaluated;
- the processing chain still executes.

A zero secondary comparison word does not select the second pair: the first case takes priority.

### Second selector case without overflow

If the primary comparison word is 100, the secondary comparison word is 20, and the selector is 80:

- the first condition is false;
- the second arithmetic result is zero;
- offset `0x0c` receives 720 before offset `0x08` receives 480;
- offset `0x14` contains 80.

These values avoid overflow ambiguity.

### Unrecognized selector

If the comparison words are 100 and 20 and the selector is 81, neither case matches. If offsets `0x08` and `0x0c` initially contain 900 and 901, those values remain unchanged by the function’s direct writes. The selector is still recorded, and the processing chain still executes.

### Source equals embedded-region address

If the source address equals the address at object offset `0x40`, F-151ab4bfe553 must be skipped, and no direct read of source offset `0x04` occurs. The later call to F-44362605ab79 still receives that embedded-region address.

### Source equals object address

If the source address equals the object address and differs from the embedded-region address, the transfer path is taken. Under ordinary stable-memory assumptions, the word supplied to F-151ab4bfe553 is zero because the initial clear precedes the source read.

### Payload replacement

If the incoming payload is 7 and F-4784b1a4efe2 replaces the temporary payload word with 11, F-10bf357441c5 receives 11 as its third argument.

### Final return-field update

If F-10bf357441c5 writes 37 to object offset `0x04` and returns normally, with no intervening modification before the final read, this function returns 37. If no dependency changes that field after the initial clear, the function returns zero.
