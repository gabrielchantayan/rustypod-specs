# F-1d2c2006114e

## Purpose

F-1d2c2006114e queries a signed 32-bit value through indirect dispatch. For accepted values, it normalizes the value, writes it into externally addressed state, and invokes eight dependency calls in a fixed order.

The acceptance rule is numeric:

- Negative values are rejected.
- Exactly one is rejected.
- Zero is accepted unchanged.
- Values greater than one are accepted and reduced by one.

Every visible path that completes normally returns the four-byte value one. This return value does not identify which branch was taken or report whether a dependency’s internal operation succeeded.

An indexing or selection conversion is a possible explanation for the normalization, but that intent is not established. The contract assigns no application meaning to the queried value, the state field, or the numeric dependency arguments.

## Behavior

### Initial query

The function first invokes F-938c950e5046. From the returned object, it reads the dispatch-table reference at the object’s beginning. It then reads and invokes the callable entry at byte offset 360 from that table.

These operations precede classification and occur on every normally progressing path, including paths that ultimately reject the result. Their effects cannot be omitted merely because the returned value will be rejected.

The indirect result is interpreted as signed 32-bit data.

### Classification and normalization

A result is accepted exactly when it is nonnegative and not equal to one.

Rejected values lead directly to the normal return of one. This function performs none of the accepted-path state access or eight downstream calls on that path.

For accepted values:

- Zero remains zero.
- A positive accepted value is reduced by one.

Since the smallest accepted positive value is two, the subtraction cannot produce a negative result. The largest accepted input, 2,147,483,647, becomes 2,147,483,646. No signed overflow is required.

The normalized output range is zero through 2,147,483,646. One is not accepted and converted to zero; it is excluded before normalization.

### External base read and state write

After acceptance and normalization, the function reads the externally stored state base. It writes the normalized four-byte integer at byte offset four from the base obtained by that read.

This ordering is part of the observable contract:

1. F-938c950e5046 and the indirect call execute.
2. The returned value is accepted and normalized.
3. The external state base is read.
4. The state field is written.
5. The eight accepted-path dependency calls execute.

The base read must not be hoisted before the initial lookup or indirect call. No evidence establishes that either call preserves that global value. Capturing the base earlier could direct the write to different storage.

Rejected paths do not perform this direct base read. Dependencies on those paths may independently access or change the same global state; their internal behavior is unknown.

## Acceptance examples

These examples are conditional requirements derived from static evidence. They are not executed tests. Unless an example states otherwise, assume valid memory, compatible calling conventions, and normally returning dependencies.

### Negative query

If the indirect result is negative one:

- The initial lookup and indirect call have occurred.
- This function does not read the external state base.
- It does not write the state field.
- None of the eight accepted-path dependency calls occurs.
- It returns one.

The minimum signed 32-bit value, −2,147,483,648, follows the same branch. These criteria do not prohibit the initial dependencies from having their own effects.

### Query equal to one

If the query returns one, it is rejected. There is no normalization to zero, no direct external-base read, no state-field write, and no accepted-path dependency sequence. Normal return is one.

### Query equal to zero

If the query returns zero, the function reads the external state base after the initial calls and writes zero at offset four from that base. The eight-call sequence follows, and F-0089b46f13cf receives zero as its second argument.

Zero must not be decremented to negative one.

### Smallest accepted positive query

If the query returns two, the normalized value is one. That value is written before the first accepted-path lookup and supplied as the second argument to F-0089b46f13cf.

### Maximum signed query

If the query returns 2,147,483,647, the write and F-0089b46f13cf argument both use 2,147,483,646. No wrapping or saturation is involved.

### Initial calls change the external base

Suppose the external base initially designates region A, but the initial lookup or indirect call changes it to region B before returning an accepted query.

If no later actor changes it before the direct base read, the write targets region B plus four, not region A plus four. Reading and retaining the base before the initial calls would violate the established ordering.

If those same calls instead produce a rejected query, this function performs no direct state-base read or state-field write.

### State mutation after the write
