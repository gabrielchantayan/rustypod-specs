# F-200380a3070f

## Purpose

F-200380a3070f fills selected fields of a caller-provided record using configuration data, an input address, and conditional decoding dependencies. It obtains an optional initial quantity, processes a subsequent field, and derives an extent and several 16-bit position or size fields.

**Established static behavior:** the routine stores the input address, performs configuration-directed reads and calls, writes selected record fields, and returns without an explicit result value. Its arithmetic includes 32-bit calculations, signed and unsigned comparisons, and narrowing to 16 bits.

**Inferred intent:** the quantities may describe positions, lengths, or segmented storage. These interpretations are not necessary to the contract. Neither the encoding format nor the application meaning of the derived fields is established.

A central distinction is between the initial quantity written at output offset +16 and the mutable temporary subsequently used to calculate the extent. If initial decoding exposes that temporary to F-887200f76f20, a later dependency may modify it through a retained address. The +16 write is therefore an earlier snapshot, not an unconditional definition of the later extent.

The routine provides no input-length parameter, explicit validation result, or rollback mechanism.

## Interface

The routine has four arguments:

| Argument | Interpretation |
|---|---|
| Configuration address | Address of an object containing flags, an initial input offset, two unsigned halfwords, and a nested-object address. |
| Input address | Address used as the origin for encoded-data reads and dependency arguments. Also stored in the output record. |
| Output-record address | Address of writable storage covering at least the routine’s direct accesses within 32 bytes. Dependencies may require additional storage. |
| Auxiliary value | A 32-bit pointer-represented value used to initialize the initial decoder’s destination temporary. This routine does not dereference it. |

The supplied representation uses 32-bit addresses and words, 16-bit halfwords, and 8-bit bytes. Byte and unsigned-halfword reads are zero-extended. Endianness and alignment requirements are not established.

There is no explicit return value.

## Behavior

### Initial processing and the +16 snapshot

The first direct operation stores the input address at output offset +0. Configuration reads occur afterward, so an overlapping output can affect those reads.

The routine reads the unsigned starting offset at configuration +9, initializes a separate scalar destination temporary with the output-record address, and examines the flag at configuration +7.

When initial decoding is disabled:

- The initial-quantity temporary becomes zero.
- No initial input byte is read.
- No dependency is called for this stage.
- The current input offset remains the configured starting offset.

When initial decoding is enabled, one unsigned input byte is read at the current offset.

For a byte below 128, that byte becomes the initial quantity and the offset advances by one.

For a byte of at least 128:

- The initial-quantity temporary is replaced with the auxiliary argument.
- F-887200f76f20 receives the current input address and the address of that temporary.
- The temporary’s post-call contents supply the initial quantity.
- The dependency’s ordinary return supplies the offset contribution.

The offset addition uses the represented 32-bit arithmetic. There is no check that the contribution is positive or consistent with available input.

The routine then writes the temporary’s current 32-bit contents to output +16.

This write does not sever the connection between the temporary and a dependency that retained its address. The routine continues to use the temporary later. It does not reload the initial quantity from output +16.

### Subsequent-field processing

The flag at configuration +3 is read after the +16 write.

#### Scalar mode

A zero flag selects scalar processing at the current input offset.

The first unsigned byte determines the decoding path:

- Below 128: the routine reads the byte again at the same address, uses the second read as the scalar value, and assigns a consumed contribution of one.
- At least 128: F-887200f76f20 receives the current input address and the address of the separate scalar destination temporary. Its post-call contents supply the scalar, and its ordinary return supplies the consumed contribution.

The scalar destination temporary was initialized with the output-record address before initial processing. It is not initialized to zero or to the auxiliary argument immediately before this call.

The below-128 path contains two distinct byte reads. Stable memory makes their values equal; changing or device-backed memory need not.

The routine writes the scalar to output +8, then writes zero to output +12. It then adds the scalar to the **current contents of the initial-quantity temporary**, producing the extent.

If the initial decoder previously received that temporary’s address, the subsequent scalar-decoder call may have modified it through a retained pointer. No supplied dependency contract excludes this behavior. Consequently, the extent need not equal the scalar plus the value previously written at +16.

#### Alternate mode

A nonzero flag selects F-174052de586c. It receives the current input address and output address +8. Its ordinary return is the consumed contribution.

The routine does not initialize output +8 or +12 before this call and does not directly add dependency-produced output fields to the initial-quantity temporary.

The extent is the temporary’s **current contents after the call**. Although this branch does not directly change that temporary before using it as the extent, F-174052de586c may modify it through an address retained from the initial decoder. Thus, equality between this extent and the +16 snapshot requires an explicit preservation assumption.

### Extent and position snapshots

After either mode, the routine writes the extent to output +20.

It computes the total input position by adding the subsequent consumed contribution to the current offset. That current offset already includes the configured starting offset and any initial-decoding contribution.

The low 16 bits of this total are written to output +24. The same narrowed value is retained internally and interpreted as signed when later used in the threshold-exceeded calculation. Output +24 is not read back for that calculation.

The unsigned threshold at configuration +10 is then read. The branch compares the current 32-bit extent against the zero-extended threshold using an unsigned interpretation.

Absent intervening mutation through aliasing or external activity, this is the extent just written at +20. Output +20 itself is not reread.

### Extent strictly above the threshold

When the unsigned extent exceeds the threshold, the routine reads:

1. The unsigned base at configuration +12.
2. The nested-object address at configuration +64.
3. The unsigned halfword at nested offset +30.

F-d7be9cfb4000 receives the represented 32-bit extent-minus-base value and the nested halfword minus four.

The second argument ranges from −4 through 65,531 before considering its 32-bit calling representation. No positive-value check is performed. The first argument can also represent a subtraction below zero because the base is not constrained by the threshold.

A secondary result from this dependency is added to the cached base to form a 32-bit candidate. The candidate is compared as signed against the cached, zero-extended threshold:

- If the candidate is greater, output +26 receives the base.
- Otherwise, output +26 receives the candidate’s low 16 bits.

The routine explicitly reads output +26 back as a signed 16-bit quantity. It adds that value to the retained signed 16-bit consumed position, narrows the result to 16 bits, and writes it at +28.

Four is then added to that narrowed intermediate, with the low 16 bits written at +30.

The threshold and base used after F-d7be9cfb4000 are cached; their configuration fields are not reread. The dependency may also mutate an escaped initial-quantity temporary, but this branch does not subsequently use that temporary to derive +26, +28, or +30. Its other side effects remain unknown.

### Extent at or below the threshold

Equality takes this branch.

The routine writes the low 16 bits of the current extent at +26. It then replaces the initial-quantity temporary with the represented 32-bit sum of:

- Its current extent value.
- The subsequent consumed contribution.
- The current input offset, including any initial contribution.

This sum is compared with four as a signed 32-bit value. A value below four is replaced with four. Output +28 receives zero, and output +30 receives the low 16 bits of the selected value.

The minimum check precedes narrowing. It does not guarantee that the stored halfword is at least four.

## Side effects

Direct record-write order is:

1. Input address at +0.
2. Initial snapshot at +16.
3. Scalar at +8 and zero at +12, in scalar mode only.
4. Extent at +20.
5. Consumed-position halfword at +24.
6. Selected halfword at +26.
7. Intermediate halfword at +28.
8. Final halfword at +30.

Conditional dependency calls occur between these writes as described above.

The routine performs no explicit allocation, release, ownership transfer, or global-variable access. That observation does not establish corresponding properties of its dependencies.

The two decoder destination temporaries have invocation-local storage. Passing their addresses permits synchronous writes during the respective calls. No supplied contract prohibits retaining those addresses or using the initial temporary’s address during a later call within the same invocation. No valid post-return lifetime, ownership transfer, or release obligation is established.

Earlier output writes are not protected from dependency mutations. In particular:

- +16 records an earlier temporary value; the temporary may subsequently diverge from it.
- A dependency may separately alter +16 or other output fields.
- +20 records the extent at its write point; later dependencies may alter output storage independently.

There is no explicit error result or rollback. An invalid access or dependency failure may interrupt execution after partial writes. The routine does not distinguish a negative consumed contribution from an ordinary arithmetic contribution.

### Alternate mode with temporary preservation

Starting offset is one. Initial decoding reads a direct byte value of seven, advancing the offset to two. F-174052de586c returns three and preserves the initial-quantity temporary. The threshold is ten.

The routine writes seven at +16 and +20, five at +24, seven at +26, zero at +28, and twelve at +30. Output +8 and any additional dependency-written fields depend on F-174052de586c.

### Scalar call mutates a retained initial destination

Starting offset is one. The initial byte selects F-887200f76f20, which writes seven into the initial temporary, retains its address, and returns two. Output +16 is therefore written as seven, and subsequent processing begins at offset three.

The scalar byte also selects F-887200f76f20. During this second call, the dependency:

- Writes five into the scalar destination.
- Changes the retained initial temporary to twenty.
- Returns one.

With threshold thirty and no other mutations, the routine writes five at +8, twenty-five at +20, four at +24, twenty-five at +26, zero at +28, and twenty-nine at +30. Output +16 remains seven.

Calculating the extent as seven plus five would not match this permitted behavior.

### Alternate call mutates a retained initial destination

Use the same initial call as above, giving a +16 snapshot of seven and current offset three. Alternate mode is selected.

F-174052de586c changes the retained initial temporary to twenty and returns three. With threshold thirty, the routine writes twenty at +20, six at +24, twenty at +26, zero at +28, and twenty-six at +30.

The extent is twenty, not seven, despite no direct addition in alternate mode.

### Threshold boundary and candidate selection

An extent equal to the threshold takes the at-or-below branch. The routine does not read the nested-object address or call F-d7be9cfb4000.

For an extent of twenty, threshold ten, base three, and retained consumed position six:

- Secondary result two gives candidate five: +26 is five, +28 is eleven, and +30 is fifteen.
- Secondary result nine gives candidate twelve: the base is selected, so +26 is three, +28 is nine, and +30 is thirteen.

### Narrowing after the minimum check

Initial decoding is disabled, starting offset is zero, and scalar decoding returns a consumed contribution of one while writing scalar 65,535. The threshold is 65,535.

The extent equals the threshold. The full-width size sum is 65,536, which passes the signed minimum check unchanged. Output +30 is therefore zero after narrowing, not four.
