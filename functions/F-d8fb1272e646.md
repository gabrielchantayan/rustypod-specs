# F-d8fb1272e646

## Purpose

F-d8fb1272e646 is represented as a non-returning sequence of indirect calls, memory reads, and memory writes repeated indefinitely. Its observable behavior includes a software breakpoint on each iteration.

The available evidence does not establish a domain-level purpose. In particular, it does not establish that the routine initializes an object, processes a queue, manages a device, or implements a protocol. Those interpretations would require evidence about its dependencies and execution environment.

This contract describes the supplied static representation. Some inputs, output channels, and addressing operations are incompletely recovered. They are documented explicitly rather than repaired into a conventional interface.

## Interface

### Explicit interface

- No explicit arguments.
- No explicit return value.
- No normal return path.
- An unconditional repetition of the body, provided every dependency returns and execution continues past the breakpoint.

A dependency that does not return, a memory fault, or a breakpoint handler that stops execution can prevent further progress. The routine contains no represented recovery path for these conditions.

### Implicit execution inputs

The body depends on the following entry state:

| Input | Required interpretation |
|---|---|
| Entry link value | Determines the first indirect-call target of the first iteration. |
| Incoming auxiliary register | Participates in a late byte-store address. No initialization is shown. |
| Frame-like base | Supplies several memory locations and is explicitly decreased during each iteration. Its status as an actual stack pointer is not established. |
| Global pointer slot A | Read early to obtain the base for two byte writes. |
| Global pointer slot B | Read later to obtain a base used by a halfword write. |
| Indirect-call environment | Must make the represented call targets executable with the required calling conventions. |
| Referenced memory | Must support the reads and writes described below for execution to continue. |

The two global slots are distinct observations. Their values must not be assumed stable across iterations, and dependencies must not be assumed to preserve them.

### Widths and notation

The contract uses:

- **Byte:** 8 bits.
- **Halfword:** 16 bits.
- **Word:** 32 bits.
- **Pair result:** a represented 64-bit result separated into low and high 32-bit words.
- **Low halfword:** truncation to the least significant 16 bits.

The address calculations are represented in a 32-bit setting. Shifts, multiplications, and additions are described at that width; they are not promises of unbounded mathematical arithmetic.

For compactness:

- **Frame base** means the frame-like base at the start of the current iteration.
- **K** means the word constant `0x21c48960`.
- **Derived base** means `(K shifted right by 18) multiplied by 4`, equal to `0x21c4`.

Names used here describe observations, not application objects or ownership classes.

## Behavior

### 1. Initial calls and first byte writes

Each iteration begins with an indirect call, **F-0001**, with two explicit zero arguments.

For the first iteration, its target is the entry link value plus `0xffe`. Near the end of the body, the represented link value is replaced with a fixed value. Consequently, subsequent iterations do not derive this call from the original entry link value.

The following ordering is represented:

1. Call **F-0002**.
2. Call **F-0003**.
3. Read global pointer slot A.
4. Call **F-0004**.
5. Call **F-0005**, obtaining a pair result.
6. Call **F-0006** with:
   - the low word of that pair;
   - the 32-bit sum of its high and low words.

An additional byte included in the represented sum is explicitly zero, so it does not change the value.

After F-0006, write one byte at the captured global-A base plus `0x11`. The byte comes from an auxiliary result channel associated with that call, not from an ordinary explicitly assigned return value.

Next:

1. Call **F-0007**.
2. Write zero as one byte at the same captured base plus `0x15`.
3. Call **F-0008**, obtaining a halfword.
4. Write that halfword at offset `0x0c` from an address supplied through an auxiliary result channel.

The global-A pointer is captured before F-0004. The two byte writes use that captured base; the representation does not reread the global slot between them.

### 2. Pair-derived writes and frame accesses

Call **F-0009**, obtaining another pair result.

Then perform these writes in order:

1. Write a zero halfword at the high word of the result plus `0x2c`.
2. Write a word at frame base plus `0x26c`. Its value is the low word logically shifted right by 26.

The second value is therefore in the range 0 through 63.

Next:

1. Call **F-0010**.
2. Read a word-sized pointer from frame base plus `0x320`.
3. Call **F-0011**.
4. Call **F-0012**.
5. Write a word at the captured pointer plus `0x54`.

The stored word is the low word returned by F-0009 shifted left by two, retaining the 32-bit result. It is not a newly obtained result from F-0010, F-0011, or F-0012.

Then call, in order:

- **F-0013**
- **F-0014**
- **F-0015**
- **F-0016**
- **F-0017**

Read an unsigned halfword from address K plus `0x34`. This halfword will subsequently be used as an address base; no pointer validation is represented.

Call **F-0018**.

Read a word from frame base plus `0x280`, and pass it as the explicit argument to **F-0019**. Retain F-0019’s word-sized result.

### 3. Breakpoint and intermediate indexed writes

Execute a software breakpoint with immediate `0x92`.

No following operation is guaranteed to occur unless the environment resumes execution after this breakpoint.

If execution continues:

- Shift F-0019’s retained result left by two.
- Form the derived base, `0x21c4`.
- Read a word-sized pointer at the earlier unsigned-halfword base plus `0x44`.

Call **F-0020**, followed by **F-0021**. F-0021 supplies a word result.

Read a word from the earlier unsigned-halfword base plus `0x04`, and call **F-0022** with:

1. F-0021’s word result;
2. the word just read.

After F-0022:

1. Read global pointer slot B.
2. Call **F-0023**.
3. Write the low halfword of the captured global-B value at the address formed by adding that value to the shifted F-0019 result.

The global-B value therefore serves both as a destination-address component and as the source of the truncated stored value.

Next:

1. Call **F-0024**.
2. Read a word-sized pointer at derived base plus `0x54`, numerically `0x2218`.
3. Call **F-0025**, obtaining an address.
4. Write a halfword at that address plus `0x04`.

The halfword written in step 4 is the low halfword of the derived base, namely `0x21c4`. It is not the pointer read in step 2.

Call **F-0026**, then **F-0027**.

### 4. Final pair result and frame-base transition

Using the pointer read at address `0x2218`, read an unsigned halfword at offset `0x34`. Call this the **selector**.

Call **F-0028**, obtaining a pair result. Its low word is the **payload**, and its high word is the **result base**.

Perform the following in order:

1. Write the payload as a word at frame base plus `0x258`.
2. Read an unsigned halfword from result base plus `0x14`; call this the **count**.
3. Form the payload shifted left by six.
4. Form result base multiplied by four.
5. Decrease the represented frame-like base by `0xf4`.
6. Form selector multiplied by four.
7. Write the payload as a word at address `(selector × 4) + 0x74`.

The explicit frame-base change is not undone before the loop repeats. Thus the next iteration’s frame-relative accesses use a base reduced by `0xf4`, subject to the underlying 32-bit address model.

The payload store at offset `0x258` occurs before the base change and uses the old base.

### 5. Final stores and iteration transition

Using the pointer captured earlier from the first unsigned-halfword base plus `0x44`:

1. Call **F-0029**.
2. Write the count as a word at pointer plus `0x54`.
3. Call **F-0030**.
4. Write the count as a word at pointer plus `0x64`.
5. Call **F-0031**.
6. Write the low halfword of that pointer at the address formed from the shifted payload plus an auxiliary address result associated with F-0031.

The two count stores use zero-extension of the unsigned halfword. Their upper 16 bits are zero.

Then:

1. Call **F-0032**.
2. Call **F-0033**.
3. Read one byte at selector plus four times selector, equivalently five times selector.
4. Call **F-0034**.
5. Write the captured byte at count plus the incoming auxiliary-register value plus `0x19`.
6. Call **F-0035**.
7. Write result base multiplied by four as a word at the retained pointer plus `0x44`.
8. Call **F-0036**.
9. Replace the represented link value with the fixed value used by the body.
10. Read a word at `(result base × 4) + 0x44`.
11. Pass that word to **F-0037**.
12. Begin the next iteration.

The byte read in step 3 is retained across F-0034. Changes to the source memory during that call do not, in the supplied representation, cause a second read.

## Side effects

### Direct memory effects

Each fully completed iteration contains:

- Three byte writes.
- Five halfword writes.
- Seven word writes.
- Reads of two global pointer slots.
- Several word, halfword, and byte reads through fixed, frame-relative, returned, and computed addresses.

These counts exclude all accesses performed by dependencies and by breakpoint handling.

Writes are not transactional. Earlier writes remain observable if a later call, breakpoint, or memory access prevents completion.

No represented validation checks:

- null pointers;
- alignment;
- address bounds;
- selector or count ranges beyond their unsigned-halfword widths;
- whether computed destinations overlap;
- whether low numeric addresses are valid.

Aliasing can therefore change the observed memory contents. For example, later reads can observe earlier writes when their addresses coincide. The sequence above establishes ordering but does not promise that the listed regions are disjoint.

### Execution-state effects

The routine:

- invokes 37 represented call sites per completed iteration;
- executes a breakpoint before the later indexed writes;
- decreases the frame-like base by `0xf4` per completed iteration;
- replaces the represented link value before the final call;
- repeats without a normal termination condition.

Dependency-side changes to global state, memory, registers, allocation state, or device state are unknown.

### Ownership

No allocation, release, ownership transfer, reference-count operation, or lifetime guarantee is established.

Pointer-looking values are used as addresses. That use does not establish that they name owned objects, valid objects, or objects with any particular layout beyond the accessed offsets.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Six-bit extraction.**  
   If F-0009’s low word is `0xfc000003`, the word written at frame base plus `0x26c` is `63`. The later store through the pointer captured from frame base plus `0x320` receives `0xf000000c`.

2. **Zero-extension of the count.**  
   If the halfword at result base plus `0x14` is `0xffff`, both count stores contain the word `0x0000ffff`, not `0xffffffff`.

3. **Selector-derived addressing.**  
   If the selector is `3`, the payload destination is address `0x80`, and the later byte source is address `15`. These addresses are used without a represented bounds check. Successful access depends on the environment.

4. **Truncation of an address-valued source.**  
   If global pointer slot B supplies `0x12345678`, the indexed halfword store writes `0x5678`, provided the computed destination is writable.

5. **Breakpoint interruption.**  
   If breakpoint `0x92` stops execution permanently, no post-breakpoint writes or final calls occur during that iteration. The earlier writes have already occurred.

6. **Repeated frame-relative behavior.**  
   If the starting frame-like base is B and execution completes an iteration, the next iteration starts with B minus `0xf4`. A second iteration’s write at relative offset `0x26c` consequently targets B plus `0x178`, under the represented address arithmetic.

7. **Captured byte across a call.**  
   If the byte at five times the selector is `0x7a` when read, and F-0034 later changes that source location, the subsequent byte write still uses `0x7a` in the represented data flow.
