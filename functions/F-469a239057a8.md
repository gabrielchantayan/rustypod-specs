# F-469a239057a8

## Purpose

F-469a239057a8 attempts to record an unsigned 32-bit value in a mutable structure. It selects among a bitmap, a table of 125 value slots, and a child-pointer representation.

The apparent intent is adaptive set insertion: suppress duplicates, store values directly while a counter is small, and convert a populated table into a child-based representation. That intent is not fully established. The arithmetic dependency has an incomplete calling contract, and the value argument for recursive reinsertion of saved entries is absent from the supplied representation.

For finite, normally returning executions following the visible control flow, the result is either **0 or 7**. Conversion combines recursive results using bitwise OR; because those recursive calls invoke this same function, that combination does not introduce another status.

This contract separates directly visible behavior from inferred purpose and unresolved dependency behavior. No runtime tests have been performed.

## Interface

### Inputs and widths

The function receives:

1. A pointer to mutable node storage.
2. An unsigned 32-bit value.

The supplied representation uses 8-bit bytes and 32-bit words. Stored child addresses occupy 32-bit words. The described layout therefore assumes the represented 32-bit address model; portability to wider pointers is not established.

### Node layout

|---|---:|---|
| 0 | 32 bits | Leading word: selects bitmap versus non-bitmap behavior and supplies conversion arithmetic |

| 8 | 32 bits | Zero selects table behavior after the leading-word check; nonzero selects child traversal |

The table payload contains 125 words, totaling 500 bytes. A zero word is treated as empty.

The child payload contains 32-bit addresses, with zero indicating an absent child. Its allocation size and number of valid child positions are unknown.

The bitmap payload begins at byte offset 12. Neither its allocation size nor the permitted value range is established by the leading-word threshold.

### Output

The output is an unsigned 32-bit status:

- **0** on bitmap completion, duplicate detection, and direct table insertion.
- **7** when a selected child slot is zero after the child-creation sequence and its trailing dependency call.
- During conversion, the bitwise OR of results from recursive calls to F-469a239057a8.

For a finite, normally returning execution, recursive results remain within `{0, 7}`, and their OR also remains within `{0, 7}`. The incomplete argument to saved-entry recursive calls makes their insertion behavior uncertain; it does not establish another return status.

A non-returning dependency, infinite probe sequence, invalid memory access, or nonterminating traversal has no established returned status.

### Preconditions and safety boundary

Safe operation requires readable and writable storage for every selected access, suitable alignment for word accesses, valid child addresses, and dependency results compatible with the active storage layout.

Additional requirements include:

- Valid initial table indices and child indices.
- A reachable empty or matching table slot if probing must terminate.
- Terminating child traversal and recursive conversion.
- Whatever synchronization the surrounding environment requires.

There is no visible null check, general bounds check, full-table escape, cycle detection, or validation of node consistency.

## Behavior

### Representation selection

At each traversal level, the function first reads the leading word.

- If it is below **4,001**, bitmap behavior applies immediately.
- Otherwise, the function reads the word at offset 8.
  - Zero selects table behavior.
  - Nonzero selects child traversal.

The leading-word test has precedence. A node whose leading word is 4,000 uses the bitmap even if its offset-8 word is nonzero.

Once a path has been selected, dependency calls do not cause an automatic restart of these checks. A dependency that changes representation fields can therefore affect later operations without causing the current frame to reconsider its earlier branch.

### Bitmap update

The function subtracts one from the input as an unsigned 32-bit operation.

From that result:

- The byte index is the result shifted right by three.
- The bit index is the low three bits.

It reads the byte at payload offset plus the byte index, ORs it with the selected single-bit mask, writes the byte back, and returns zero. Other bits in that byte are preserved by this update.

Consequences include:

- Input 1 selects bit zero of the first payload byte.
- Input 8 selects bit seven of the first payload byte.
- Input 9 selects bit zero of the second payload byte.
- Repeating the same input is idempotent with respect to the resulting bitmap byte.

The function does not compare the input with the leading word and does not explicitly update the counter.

Input zero is not rejected. Unsigned subtraction produces 4,294,967,295, yielding byte index 536,870,911 and bit index seven. This attempts a distant access relative to the payload; it is not a defined empty-value operation. Its validity depends on storage and address arithmetic outside the established contract.

### Child routing

In child mode, the function calls F-d7be9cfb4000 with the input minus one, using 32-bit unsigned subtraction.

The supplied representation consumes two 32-bit portions of the returned quantity:

- The lower portion is interpreted as a signed child index.
- The upper portion is incremented by one to form the value carried into the child.

The second quantity is visibly formed through a signed 32-bit interpretation before incrementing. Ordinary non-overflowing cases are established; exact signed-overflow semantics are not independently established by this static representation.

The selected child-address word is at byte offset 12 plus four times the signed index. There is no visible index validation. A negative index can select header storage or earlier memory; an excessive positive index can select storage beyond the node.

The arithmetic dependency executes before the child-slot read. Its preservation of the node is unknown. Consequently, the slot contents and other fields used afterward are those observed after that call, not necessarily their entry values.

### Child creation and continuation

If the selected child slot is nonzero at the initial test, the creation sequence is skipped. The function subsequently reads the slot to obtain the next node address.

If the selected slot is zero, the visible order is:

1. Call F-7107f219f55e with zero.
2. Read the current node’s word at offset 8.
3. Pass that word to F-094b96da48ec.
4. Store its returned 32-bit word in the selected child slot.
5. Call F-ffdded7ca165 with zero.
6. Read the selected slot and return seven if it is zero.
7. Otherwise, read the slot again to obtain the next node address.

The offset-8 argument is read after F-7107f219f55e. It is not necessarily the value observed during representation selection.

Likewise, the failure decision concerns the slot after F-ffdded7ca165, not merely the result returned by F-094b96da48ec. Unknown dependencies are not assumed to preserve the slot, other node fields, globals, or surrounding memory.

Traversal continues at the selected address with the transformed input. It returns to the leading-word check for that child.

The calls surrounding creation suggest synchronization or environment control, but that purpose is inferred. Locking, interrupt behavior, memory ordering, and reentrancy guarantees are unknown.

### Table lookup

After selecting table mode, the function calls F-d7be9cfb4000 with:

- The input multiplied by 37, reduced to 32 bits.
- The value 125.

A secondary result channel supplies a signed initial slot index. Its exact arithmetic meaning is unknown.

The function then probes from that index:

- It first reads the slot to test for zero.
- If nonzero, it reads the slot again to compare with the input.
- A matching comparison returns zero.
- Otherwise, it increments the index.
- An increment producing exactly 125 resets the index to zero.

This wrap rule does not normalize an invalid initial index. Safe table behavior requires an initial index in the range 0–124.

There is no probe-count limit. With a valid initial index, 125 nonzero slots, no matching value, and no intervening changes, probing repeats indefinitely.

A duplicate return causes no explicit counter or payload write by this frame. The preceding arithmetic dependency may nevertheless have changed memory.

### Counter update and direct insertion

After observing an empty slot, the function reads the counter at offset 4. It increments that captured value modulo 2³² and writes the result back.

The same incremented value determines the next action:

- Below 62: write the input into the selected slot and return zero.
- At least 62: begin conversion without first writing the pending input into that slot.

The counter is not recomputed from occupancy.

At the actual counter-read point:

- 60 becomes 61 and selects direct insertion.
- 61 becomes 62 and selects conversion.
- 4,294,967,295 becomes zero and selects direct insertion.

These are not unconditional consequences of entry counter values. The table arithmetic dependency runs before the counter read and has no established preservation contract.

For input zero, a zero slot ends probing rather than satisfying the duplicate comparison. If the incremented counter is below 62, the function writes zero back into that slot. The counter advances, but the slot remains indistinguishable from empty.

### Conversion

Conversion proceeds in this order:

1. Invoke an external operation with temporary storage as destination, the current payload as source, and a size of 500 bytes.
2. Invoke another external operation on the current payload with a size of 500 bytes, apparently to clear it.
3. Read the current leading word.
4. Call F-d7be9cfb4000 with that word plus 124, reduced to 32 bits, and with 125.
5. Store the primary 32-bit result at offset 8.
6. Recursively invoke F-469a239057a8 on the same node with the pending input.
7. Examine the 125 temporary words in ascending index order.
8. For each word observed as nonzero, recursively invoke F-469a239057a8 on the same node.
9. OR each recursive result into the accumulated status and return it.

The leading word used in conversion arithmetic is read after the two external memory operations. Its preservation by those operations is not established.

The saved-entry recursive calls do not expose their value argument. The visible scan therefore establishes which temporary positions trigger calls and their order, but not which values those calls attempt to insert.

All 125 positions are considered unless an operation fails to return or otherwise leaves normal execution. A returned seven does not short-circuit the scan. For finite normal completion, the aggregate is zero if every recursive result is zero and seven if any recursive result is seven.

This frame increments the counter before conversion and contains no explicit subsequent counter reset. External operations and recursive calls can change that field, so its value on return is not established.

No rollback is visible. The payload operations, discriminator replacement, and recursive mutations can occur before an eventual status of seven.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. They assume valid storage and normal execution unless stated otherwise.

1. **First bitmap bit.** With a leading word below 4,001, input 1, and a first payload byte of zero, the function writes that byte as 1 and returns zero.

2. **Bitmap byte boundary.** Input 8 sets the high bit of the first payload byte. Input 9 sets the low bit of the second. Unselected bits are preserved.

3. **Selection precedence.** A leading word of 4,000 selects bitmap behavior regardless of offset 8. A leading word of 4,001 makes offset 8 determine table versus child behavior.

4. **Duplicate table value.** If the arithmetic dependency returns a valid index and subsequent probing encounters the input before an empty slot, the function returns zero without an explicit counter or payload write on that path. This does not imply that the dependency made no changes.

5. **Insertion below threshold.** Suppose the arithmetic dependency preserves the relevant node fields and payload, returns a valid index, and probing reaches an empty slot for a nonzero absent input. If the counter is 60 when read, the function writes 61 to the counter, writes the input into that slot, and returns zero.

6. **Conversion boundary.** Under the same preservation and valid-probing assumptions, a counter of 61 when read becomes 62. Conversion begins instead of a direct write of the pending input. The counter’s eventual return value is not specified.

7. **Child-creation failure.** If the selected slot is initially zero and is still zero at the check after F-ffdded7ca165, the function returns seven, regardless of the earlier creation result.

8. **Conversion status aggregation.** If the pending insertion returns seven and all saved-entry calls return zero, conversion returns seven. If the pending insertion returns zero and any saved-entry call returns seven, conversion also returns seven. Returned errors do not stop later scan positions from being considered.

9. **Zero in table mode.** Suppose the arithmetic dependency preserves the relevant state and supplies a valid index. If the initial slot is zero and the counter is zero when read, input zero changes the counter to one, writes zero to the slot, and returns zero. No distinguishable occupied slot is created.

10. **Counter wraparound.** If an empty slot has been reached and the counter reads as 4,294,967,295, its increment wraps to zero. The direct-insertion branch is selected.

11. **Full unmatched table.** With a valid initial index, 125 nonzero slots, no matching input, and no subsequent mutation, probing does not terminate.
