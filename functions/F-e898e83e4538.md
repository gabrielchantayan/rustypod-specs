## Behavior

### 1. Initial destination and configuration publication

The function constructs the first destination address from the fourth argument and the low five bits of the first argument. It then writes, in order:

1. The 32-bit value \(q\) at that destination.
2. The ambient word four bytes later.

It next writes a fixed configuration quantity of hexadecimal `0x24` into a named state object, then publishes a pointer to a separate configuration payload object in another named state object.

It reads one byte at address \(q + \texttt{0x1f}\). That observation is subsequently converted to a 32-bit integer through a plain-character value. Whether bytes `0x80`–`0xff` become negative before widening is not established because plain-character signedness is not supplied.

The function then:

1. Stores address value \(p\) in a four-byte state cell beginning at address `0x0000001f`.
2. Stores \(q\) in the configuration payload object.
3. Begins writing through the pointer held in that low-address state cell.

The order matters: the initial destination writes precede the byte read, and the low-address pointer publication precedes the record writes.

### 2. First record construction

Using the pointer currently held in the state cell at `0x0000001f`, the body writes four consecutive 32-bit words:

| Offset | Value |
|---:|---|
| `0x00` | `0x12` |
| `0x04` | The widened character observation |
| `0x08` | `0x24` |
| `0x0c` | The ambient word |

It then captures a pointer 16 bytes beyond the base currently held in that state cell. Call this the **captured record pointer**.

The low-address pointer cell remains mutable. The supplied expressions refer to it repeatedly rather than establishing an immutable base for every later access. If a destination overlaps that cell, a later access can use a changed base. Consequently, the table above describes relative offsets, not a guarantee that all writes land in one stable allocation.

Next, two named control-state objects receive, in order, `0x19` and zero.

The function reads a four-byte pointer from address \(t+\texttt{0x6c}\). This observation becomes the **linked-record pointer**.

It then:

1. Stores \(u\) in a four-byte state cell beginning at `0x00000027`.
2. Publishes the captured record pointer in a named control-state object.
3. Stores the ambient word in another named control-state object.

### 3. Linked record and first byte observation

| Offset | Value |
|---:|---|
| `0x00` | \(t\) |
| `0x04` | The linked-record pointer itself |

| `0x0c` | Zero |

This is the **first byte observation**. A linked-record write can affect it if the relevant addresses overlap.

The body then performs these writes, in order:

2. At offset `0x14` from the current pointer held at `0x0000001f`: the captured record pointer.
3. At offset `0x18` from that current pointer: a pointer 12 bytes beyond that current base.
4. At offset `0x1c` from that current pointer: the first byte observation, zero-extended to 32 bits.

It advances the pointer stored at `0x0000001f` by eight bytes. It then stores:

- `0x1f` in the four-byte state cell beginning at `0x00000023`.
- A pointer to the configuration payload object in the four-byte state cell beginning at `0x0000002b`.

The cells beginning at `0x1f`, `0x23`, `0x27`, and `0x2b` are consecutive four-byte cells. Their alignment and accessibility are preconditions, not validated properties.

### 4. Second byte, halfword, and low-address record

The function next reads a byte using:

- The current pointer stored at `0x0000001f`.
- An additional displacement of \(q \times \texttt{0x400}\) **four-byte elements**.

The byte displacement is therefore \(q \times \texttt{0x1000}\), reduced to the effective address width. It is not a displacement of merely \(q \times \texttt{0x400}\) bytes.

If the pointer cell has retained its expected value throughout the preceding writes, this byte address is:

\[
(p + 8 + u) \bmod 2^{32}.
\]

Without that noninterference condition, the current cell value governs the address.

This **second byte observation** is retained for the return value and is also zero-extended into a destination address. That destination is therefore in the inclusive range `0x00000000`–`0x000000ff`.

Before writing through it, the function reads an unsigned 16-bit value at address \(t+4\). This is the halfword retained for the return value.

It also computes a word from the current contents of the state cell at `0x00000027`, minus `0x1f`. Through the address supplied by the second byte observation, it then writes:

| Offset | Value |
|---:|---|
| `0x00` | Zero |
| `0x04` | That destination address itself |
| `0x08` | The computed state-cell value minus `0x1f` |
| `0x0c` | An address identified as stack-relative |
| `0x10` | \(t\) |

The subtraction is computed before these five writes. Later aliasing writes do not retroactively change that stored value.

Because the destination is byte-derived, these writes can be unaligned and can overlap the low-address state cells. No alignment correction, range check, or exclusion of zero is visible.

### 5. Fixed-location read and conditional control updates

After the low-address record writes, the function reads a fixed-location object at address `0xc0000028` and converts its value to an unsigned 32-bit value. The underlying object’s declared width is absent.

The subsequent branch tests whether \(t\) equals zero.

If \(t\) is nonzero:

- No branch-specific control updates occur.
- The retained fixed-location observation is written as a 32-bit word to address `0xc0000030`.

If \(t\) is zero, the function performs these additional operations in order:

1. Writes `0xbffffffb` to the first control-state object.
2. Writes `0xc0000000` to the second.
3. Writes `0xfffffb00` to the control-state object that previously received the ambient word.
4. Writes zero to another control-state object.
5. Replaces the pending final write value with `0x8d`.
6. Reads a new unsigned halfword at address \(t+4\), which is address `0x00000004` in this branch, and publishes its zero-extended value as a pointer in the control-state object that previously held the captured record pointer.
7. Reads the fixed-location object at `0xc0000028` again and assigns its unsigned-32-bit conversion to an object at `0xc000003b`.
8. Writes the 32-bit value `0x8d` to address `0x00000030`.

The second halfword read does not replace the halfword already retained for return. Likewise, the branch’s second fixed-location read must not be assumed equal to the first.

The branch condition is not equivalent to “the first argument is zero.” With 32-bit products, it holds whenever bits 4–27 of the first argument are zero. Bits 28–31 and bits 0–3 may be nonzero.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Return packing.** If the second byte observation is `0xa5` and the retained halfword is `0xbeef`, normal completion returns `0x000000a50000beef`. Later changes to either sampled location do not change the retained result.

2. **Unsigned byte used as an address.** If the second byte observation is `0xe0`, the five-word low-address record begins at `0x000000e0`, not a sign-extended address.

3. **Character widening remains declaration-dependent.** If the earlier character read observes `0xff`, its first-record word is `0xffffffff` under signed eight-bit character semantics and `0x000000ff` under unsigned semantics. The supplied material does not select between them.

4. **Pointer arithmetic scales by four.** If \(q=1\) and the pointer state remains undisturbed, the second byte read occurs at `0x00011008`: base `0x00010008` plus `0x1000`.

5. **Nonzero final branch.** If \(t\ne0\), execution reaches the final write, and the fixed-location observation converts to `0x12345678`, the word at `0xc0000030` receives `0x12345678`. The branch-specific write to `0xc000003b` does not occur.

6. **Zero after truncation.** A first argument of `0x10000001` gives \(q=\texttt{0x01000000}\) and \(t=0\). Subject to successful earlier accesses, it takes the zero-\(t\) branch despite the first argument being nonzero.

7. **Repeated halfword observations can differ.** On the zero-\(t\) path, if the first read at address four observes `0x1122` and intervening writes make the later read observe `0x3344`, the return retains `0x1122`; the control-state pointer publication uses `0x00003344`.
