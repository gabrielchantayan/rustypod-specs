# F-8d9ba8db3918

## Purpose

F-8d9ba8db3918 conditionally requests a storage extent and then invokes an external operation using a destination derived from that storage.

The established sequence is:

- Obtain a source-derived measurement.
- Capture a descriptor address from the supplied object.
- Reject a null source or a particular observed flag state.
- Clear the object flag word’s low four bits.
- Read the descriptor’s previous extent and request that extent plus the measurement.
- Invoke the external operation only if the storage dependency returns exactly the requested extent.
- Return the saved measurement after the external operation returns normally.

The apparent intent is to append a measured source sequence to existing storage. That interpretation is **inferred**. The available evidence does not establish the measurement unit, the descriptor extent’s meaning, or the external operation’s actual transfer semantics.

Explicit rejection and storage-result mismatch return −1. The function performs no local rollback. A successful external-operation path returns the measurement without validating its sign, so −1 is not necessarily an unambiguous failure indicator.

## Interface

### Inputs and representation

The function accepts two arguments:

| Argument | Established use |
|---|---|
| Object address | Locates a flag word and a descriptor-pointer field. |
| Source value | Passed unchanged to the measurement dependency and, conditionally, the external dependency. Zero selects explicit rejection, but only after measurement and descriptor-pointer capture. |

The supplied representation uses 32-bit integer quantities, a 32-bit flag word, and pointer-bearing fields consistent with a 32-bit address model. The complete calling convention, alignment requirements, and arithmetic-overflow rules are not established.

Relevant object layout:

| Byte offset | Width | Meaning established by use |
|---|---:|---|
| 0x14 | 32 bits | Flag word. Mask 0x200 controls rejection at one read. A later read is masked with 0xfffffff0 and written back on the permitted path. |
| 0x20 | 32-bit pointer-bearing field | Descriptor address, captured after measurement and before the source-null decision. |

Relevant descriptor layout:

| Byte offset | Width | Meaning established by use |
|---|---:|---|
| 0x00 | 32 bits | Previous extent, captured after the flag write. |

These are partial layouts, not complete object definitions. The evidence establishes no disjointness or aliasing guarantees among the object, descriptor, source, and destination.

### Return value

The return is a 32-bit integer:

- **−1** after a normally returning null-source diagnostic.
- **−1** after a normally returning flag-rejection diagnostic.
- **−1** when the storage dependency returns a value unequal to the requested extent.
- **The saved measurement result** when storage-result equality is followed by a normally returning external operation.

No external-operation result is used to determine this return.

A measurement of zero or a negative measurement is not locally rejected. If the measurement is −1 and the equality path completes, the function also returns −1. Distinguishing that completion from explicit failure requires a dependency contract not supplied here.

### Conditional preconditions

Requirements depend on the path actually reached:

- The measurement dependency must accept the supplied source value if execution is to proceed beyond the first call.
- After measurement returns, the object must permit reading its descriptor-pointer field—even when the source is zero.
- A nonzero source requires a readable flag word.
- The permitted path requires a writable flag word and a readable first descriptor word.
- Storage-result equality additionally requires a readable second descriptor word and valid arguments for the external operation.
- Reached arithmetic and address calculations must be valid under the applicable execution model.

The function does not locally validate object or descriptor addresses, measurement range, available storage, source accessibility, overlap, or arithmetic boundaries. Dependency effects can invalidate these conditions; their continued validity is not guaranteed merely because they held at function entry.

## Behavior

### Measurement precedes object observations

The first dependency call is to F-1cb585febd84 with the original source value. This call occurs even when that value is zero.

Its result is retained for subsequent extent arithmetic, dependency arguments, and the possible successful return.

Only after that call returns does the function read the descriptor address from object offset 0x20. The captured address is used for all subsequent descriptor accesses and for the storage request.

Consequences of this ordering:

- The measurement dependency sees a null source before local null-source rejection.
- Descriptor selection reflects the pointer field observed **after** measurement, not necessarily its entry value.
- The flag and previous extent are also observed after measurement. Their entry values do not determine later behavior unless preservation is separately assumed.
- An invalid object access can prevent the diagnostic path from being reached.
- A later change to the object’s descriptor-pointer field does not, by itself, redirect accesses through the already captured address.

Capturing the descriptor address does not read either descriptor word.

### Null-source rejection

After descriptor-pointer capture, a zero source selects a call to F-4fc89ec41a6d with these arguments, in order:

1. 0x20, decimal 32.
2. 0x75, decimal 117.
3. 0x73, decimal 115.

Normal return from that dependency is followed by a return of −1.

This branch performs no direct flag read, flag write, descriptor-content read, storage request, or external-operation call. That restriction describes this function’s own operations, not effects of dependencies already invoked.

The diagnostic values are established. Their meaning, presentation, severity, and output destination are unknown.

### Flag-based rejection

For a nonzero source, the function reads the flag word at object offset 0x14 and tests mask 0x200.

If that **observed** word has bit 0x200 set, the function calls F-4fc89ec41a6d with:

1. 0x20, decimal 32.
2. 0x75, decimal 117.
3. 0x7e, decimal 126.

Normal diagnostic return is followed by −1.

No direct flag write, descriptor-content read, storage request, or external-operation call occurs on this branch. Measurement and descriptor-pointer capture have already occurred.

A rejection bit set at entry is insufficient to establish this outcome: the measurement dependency runs before the test and may change the relevant state.

### Flag mutation on the permitted path

If the source is nonzero and the rejection-test read has bit 0x200 clear, the function reads the flag word again. It masks this second observed value with 0xfffffff0 and writes the result to object offset 0x14.

This operation clears bits 0 through 3 and preserves bits 4 through 31 from the **masking read**.

The rejection-test read and masking read are separate observations. Their equality is not established under concurrent or asynchronous mutation. In particular, the function does not repeat the rejection decision if bit 0x200 becomes set between those reads; that bit would be preserved by the mask.

No atomic read-modify-write or synchronization guarantee is established.

### Extent capture and storage request

After the flag write, the function reads the first 32-bit word of the captured descriptor. This observed value becomes the saved previous extent.

The requested extent is the sum of:

- The saved previous extent.
- The saved measurement result.

The function then calls F-9a8ea7637eda with, in order:

1. The captured descriptor address.
2. The calculated requested extent.
3. The saved measurement result.

It compares the dependency’s return with the saved requested extent. Only exact equality selects the external-operation path.

A positive result, a nonzero result, or a result greater than the requested extent is not sufficient. The function does not reread the descriptor’s extent to determine success.

### Storage-result mismatch

Any unequal storage result causes an immediate return of −1.

By this point, the low-nibble flag write has occurred. The function does not restore that flag word, undo dependency effects, invoke a local diagnostic, or call the external operation.

This is not a locally transactional failure path. The descriptor, storage, object, or other state may already have changed.

### External-operation path

Following storage-result equality, the function reads the second word of the captured descriptor as a destination base.

The external dependency receives, in order:

1. That post-storage destination base plus the saved pre-storage previous extent.
2. The original source value.
3. The saved measurement result.

The base is therefore observed after the storage call; the offset remains the extent observed before that call. Changes to the descriptor’s first word during storage do not replace the saved offset.

There is no intervening reread of the source measurement or the object’s descriptor-pointer field. Changing that pointer field during storage does not redirect the base read to a different descriptor.

After the external operation returns normally, the function returns the saved measurement. It does not inspect the external operation’s result or verify destination contents.

The argument pattern suggests a memory transfer, but that is inferred intent. Byte-copy semantics, count units, overlap handling, terminator behavior, and negative-count behavior remain unresolved.

### Arithmetic boundaries

Two additions are observable:

- Previous extent plus measurement, producing the requested extent.
- Destination base plus previous extent, producing the external operation’s first argument.

The representation uses 32-bit integer-like quantities and shows no explicit sign, range, carry, or overflow checks.

The evidence does not establish saturation, widened arithmetic, mandatory wrapping, or rejection at overflow. Those boundary behaviors remain **documented_only** pending the applicable arithmetic and address-model contracts. Likewise, no evidence establishes that measurement and extent use compatible units, although their direct addition is established.

## Side effects

The only explicit local memory write is the masked flag-word write on the permitted path. It precedes extent capture and the storage call.

That write must not be interpreted as proof that no descriptor or source state changes locally: the available evidence does not exclude aliasing between the written field and other relevant memory. Its guaranteed description is the address written and the masked value stored.

Dependency effects are unrestricted by the supplied evidence:

- F-1cb585febd84 may change the object, its descriptor pointer, descriptor contents, globals, or other state before local observations occur.
- F-4fc89ec41a6d may produce diagnostics or other effects and may fail to return normally.
- F-9a8ea7637eda may modify the descriptor, backing storage, ownership, globals, or other state.
- The unmapped external dependency may modify memory or perform other operations.

No direct allocation, release, ownership transfer, or explicit source write is shown. This does not establish that dependencies avoid those effects or that aliases cannot expose the flag write through another view.

On the equality path, the function continues to access the captured descriptor after F-9a8ea7637eda returns. A valid continuation therefore requires that address to remain usable. The storage dependency’s implementation is unavailable, so preservation of descriptor lifetime cannot be assumed.

There is no local cleanup, rollback, post-transfer validation, or established global-state preservation guarantee.

## Acceptance examples

These are conditional static acceptance examples, not runtime observations. They assume valid reached accesses, valid arithmetic, and normal returns from the dependencies whose continuation is described. Values are specified at their actual observation points; no dependency preservation is implied.

### Ordinary permitted continuation

Suppose:

- The source is nonzero and F-1cb585febd84 returns 5.
- The descriptor-pointer read after measurement captures descriptor D.
- The rejection-test flag read observes bit 0x200 clear.
- The separate masking read observes 0x10f.
- The first word of D, read after the flag write, is 12.

Then:

- The local flag write stores 0x100.
- The requested extent is 17.
- F-9a8ea7637eda receives D, 17, and 5.
- If it returns 17, the function reads D’s destination base after that call.
- The external operation receives that base plus 12, the original source, and 5.
- Normal external return is followed by a return of 5.

This example makes no claim about entry-state values or that this function stores 17 into D.

### Storage-result mismatch

Under the same observation-point conditions as the preceding example, suppose F-9a8ea7637eda returns 16.

The function returns −1 without invoking the external operation. It has already stored 0x100 at the flag field. It does not restore the earlier value or undo dependency effects; the final flag value need not remain 0x100 if a dependency subsequently changes it.

### Null source

With source zero, the measurement dependency is still called first with zero. If it returns and the subsequent descriptor-pointer read succeeds, the diagnostic receives 32, 117, and 115. Normal diagnostic return produces −1.

No assumption that measurement leaves the object unchanged is necessary. The descriptor pointer captured is whichever value is observed after measurement.

### Rejection observed after measurement

Suppose the source is nonzero and the rejection-test flag read observes 0x200 set.

The diagnostic receives 32, 117, and 126. Normal diagnostic return produces −1, with no local flag clearing or storage request.

Conversely, if the entry flag had 0x200 set but measurement clears it before the rejection-test read, that entry value alone does not require rejection.

### Different values at the two flag reads

Suppose the rejection-test read observes 0x00000000, but the later masking read observes 0x0000020f.

The function follows the permitted path and writes 0x00000200. It does not reclassify the invocation as rejected merely because the second read contains the rejection bit.

This example specifies observations only; it does not assert that unsynchronized mutation is supported by the execution environment.

### Zero measurement

Suppose a permitted nonzero source produces measurement zero and the observed previous extent is 12.

The storage dependency is still called with the captured descriptor, 12, and zero. If it returns 12, the external operation is still invoked with a zero third argument. Normal completion returns zero. There is no local zero-measurement shortcut.

### Storage changes the destination base

Suppose the saved previous extent is 12, and storage returns the requested extent. If the subsequent second-word read from the captured descriptor observes base B, the external destination is B plus 12.

A changed descriptor extent does not replace the saved 12. A changed object descriptor-pointer field does not redirect the read away from the captured descriptor.
