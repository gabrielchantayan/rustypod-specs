# F-40f29d48590d

## Purpose

F-40f29d48590d performs an ordered update of a caller-supplied state object using two caller-supplied integer samples and two dependency calls.

The visible operation has three phases:

1. Invoke F-5f57ab3ca437 with the state-object address, then obtain both input samples.
2. Compute and publish intermediate state, including three zeroed fields, two reduced-resolution values, and one aligned value.
3. Invoke F-b443dcf6eb72 with the state-object address, then publish two higher-resolution values derived from the previously captured samples.

The normal return value is zero. It is not a status value propagated from either dependency.

**Inferred intent:** the arithmetic resembles conversion between fixed-point representations, with a lower-bound adjustment applied only to the first reduced-resolution value. The source does not establish units, application-level field names, or the meanings of either dependency. Those interpretations are not part of the required contract.

## Behavior

### Arithmetic model and its limits

The supplied representation uses signed integer operands and four-byte field accesses. The numerical descriptions and examples below use a **reconstructed 32-bit machine model**:

- A left shift by two retains the low 32 bits of the shifted value.
- A signed right shift by eight propagates the sign bit.
- Comparisons use signed 32-bit ordering.
- Stored integer results occupy four bytes.

For each captured sample, the function first shifts the sample left by two bits, then shifts that intermediate result right by eight bits.

This is not generally equivalent to dividing the original sample by 64. The initial left shift can discard high bits and change the sign of the intermediate value. Even without that loss, an arithmetic right shift rounds negative nonmultiples toward negative infinity rather than toward zero.

Under this model, each reduced-resolution value lies between `−8,388,608` and `8,388,607`, inclusive.

The exact target instruction semantics are not independently available. In particular, negative signed left shifts and overflowing signed left shifts must not be justified using portable source-language arithmetic rules. Target confirmation remains a documented uncertainty.

### Threshold edge cases

Equality does not trigger adjustment. A first reduced-resolution value equal to the threshold is stored unchanged.

For stable ordinary memory, the threshold subtraction cannot underflow signed 32-bit arithmetic: adjustment requires a value strictly below the threshold, which is impossible when the threshold is the minimum signed 32-bit value.

That argument assumes the threshold does not change between its comparison read and its branch-specific read. The representation does not provide synchronization or a stable snapshot guarantee. Concurrent mutation, device-backed memory, or other unusual read behavior would require a separate execution contract.

The threshold affects only offset `0x28`. It does not alter:

- The second reduced-resolution value.
- The aligned value at offset `0x40`.
- Either final shifted-sample write.

### Captured inputs and aliasing

## Side effects

The function directly performs eight four-byte stores:

- Six before F-b443dcf6eb72.
- Two after F-b443dcf6eb72.

Immediately before the second dependency is called, the six preceding stores have occurred in the represented order. This does not establish any particular dependency interpretation of those fields.

After that dependency returns normally, the function overwrites offsets `0x38` and `0x3C`. If the dependency wrote those same locations, these two writes supersede its values.

Conversely, the earlier writes are not guaranteed final-state invariants. F-b443dcf6eb72 may change offsets `0x1C`, `0x20`, `0x24`, `0x28`, `0x2C`, or `0x40`. The visible function does not restore them afterward.

No allocation, deallocation, ownership transfer, or explicit global access is visible in the function body. This does not establish that either dependency lacks those effects. The function visibly continues using the state address after the second call, but that is a caller/dependency lifetime requirement, not proof that the dependency preserves ownership.

There is no visible rollback. If execution fails after some stores have occurred, the body provides no restoration procedure.

## Acceptance examples

These are conditional behavioral examples, not runtime test results. They assume the reconstructed 32-bit shift model, valid storage, a stable threshold, and normal dependency returns.

### Positive samples without adjustment

Given captured samples `640` and `1280`, with threshold `5`:

- Reduced-resolution values are `10` and `20`.
- The first value is retained.
- Before the second dependency, offsets `0x28`, `0x2C`, and `0x40` have received `10`, `20`, and `5120`.

- After that dependency, offsets `0x38` and `0x3C` receive `2560` and `5120`.
- The function returns zero.

The pre-call stores are final values only if the second dependency leaves them unchanged.

### Threshold adjustment

Given captured samples `640` and `1280`, with threshold `20`:

- The first reduced-resolution value is `10`.
- Because `10 < 20`, offset `0x28` receives `19`, not `20`.
- The other derived values are unchanged from the preceding example.

### Threshold equality

Given a captured first sample of `640` and threshold `10`, offset `0x28` receives `10`. Equality does not select the threshold-minus-one result.

### Negative rounding

Given a captured second sample of `−65`:

- Its left-shifted intermediate value is `−260`.
- Arithmetic right shift by eight produces `−2`.
- Offset `0x2C` receives `−2`.
- Offset `0x40` receives `−512`.
- After the second dependency, offset `0x3C` receives `−260`.

A result of `−1` at offset `0x2C` would not match this arithmetic-right-shift model.

### High-bit loss

Given a captured first sample with bit pattern `0x40000000`, the modeled left shift by two produces zero. With threshold zero:

- Offset `0x28` receives zero.
- The final write to offset `0x38` is zero.

This distinguishes the represented operation from unrestricted mathematical division by 64.

### Dependency mutation

If the first dependency changes the first sample before returning, subsequent calculations use the changed value.

If the second dependency instead changes that sample storage, the final write to offset `0x38` still uses the already captured value. If it changes offset `0x28`, that change can remain after return because the function does not rewrite that field afterward.
