### Classification, temporary-word reuse, and flags

## Acceptance examples

These are conditional static-review criteria, not executed tests. Unless stated otherwise, they assume valid storage, compatible dependency results, and no intervening dependency mutations.

1. **Reuse:** A zero result from F-e9681753d786 skips new-record allocation and F-42fb116e4921.

2. **Initial allocation failure:** The allocation result has already reached destination `+0x84` when a nonzero status causes direct return. Cleanup is not invoked.

3. **Descriptor history:** After classification is first assigned `0x12`, descriptor `+0x00` receives the status-slot address. Before metadata invocation it receives the destination address. After F-1cb585febd84 returns, it receives the status-slot address again.

4. **Flag boundary and persistence:** Record weight `799` does not set bit `0x02`; `800` does. False source conditions do not clear preexisting style bits. Both retained bits select “Bold Italic” on successful completion.

5. **Scale and rounding boundaries:** Zero scales become `72`; `-1` remains `-1`. Scaling results `31` and `32` round to `0` and `64`, respectively. A rounded result with its high bit set is negative for the cap comparison and cannot trigger the cap against the nonnegative record-derived value.

6. **Conditional global reads:** No diagnostic pointer or level read occurs without the cap branch. On that branch, a level of `1` suppresses the diagnostic call; `2` enables it. The global supplying descriptor `+0x04` is read only for uppercase `M`. The metadata first-argument global is read at invocation.

7. **Count endpoints:** Endpoint bytes `10` and `8`, at `+0x6C` and `+0x6D`, produce zero. Values `10` and `7` produce `0xFFFFFFFF`.

8. **Empty name range:** Equal endpoints request one byte, pass zero as copy count, and place the terminator at offset zero. Completion still depends on dependency contracts.

9. **Registration failure:** A nonzero metadata return prevents subsequent count and name work and invokes cleanup. If cleanup leaves the status slot unchanged, that value is returned. If cleanup changes the slot, the subsequently read value is returned instead.
