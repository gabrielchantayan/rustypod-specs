# F-639f9141c4d5

## Purpose

F-639f9141c4d5 modifies a caller-supplied sequence of four-word blocks in place. It reverses the block order, preserving word order within each block, and then applies a table-derived transformation to every word of each interior block. The two endpoint blocks are excluded from the transformation phase.

The sequence length is determined by F-60d5b4852dfa rather than by an explicit length argument. For a supported nonnegative result \(r\), the sequence contains \(r+1\) blocks.

A single, fixed transformation describes all interior words only when the shared table-base value and the relevant table contents remain stable. That stability must include protection against the function’s own buffer writes: the buffer must not overlap either table entries or the storage holding the shared table-base value.

The structure suggests conversion of a round-oriented schedule into a reversed, transformed schedule. This is inferred intent, not an established algorithm identity or caller protocol.

## Interface

The function accepts one pointer to writable word storage. It has no explicit return value, status output, length argument, or capacity argument. Its direct result is mutation of the supplied storage.

Under the 32-bit interpretation supported by the supplied representation:

## Behavior

### Dependency and reference state

F-60d5b4852dfa is called exactly once, before the function’s direct buffer accesses and before its visible reads of shared table-base state. Its result determines both the reversal extent and the number of interior blocks processed.

“Initial buffer” below means the buffer immediately after that dependency returns. Equating this with the function-entry buffer requires an additional dependency-preservation guarantee that is not established.

If the dependency fails to return normally, neither subsequent phase is reached.

### Block reversal

The function first reverses blocks \(0\) through \(r\). It exchanges the outermost pair, then works inward. An unpaired middle block is untouched during this phase.

Within each exchanged pair, word positions are handled in ascending order, from 0 through 3. For each position, the visible buffer-access order is:

1. Read the lower-numbered block’s word.
2. Read the higher-numbered block’s corresponding word.
3. Write the latter value into the lower-numbered location.
4. Write the saved former value into the higher-numbered location.

There are \(\lfloor(r+1)/2\rfloor\) exchanged block pairs. The exchanges are not whole-block atomic operations, and no atomic word-pair guarantee is established.

For valid, uninterrupted accesses without interfering buffer changes, reversal places initial block \(r-j\) at block \(j\), preserving the four word positions.

Reversal writes can also change shared state if that state aliases the buffer. In particular, exchanging a word that holds the shared table-base value changes the base subsequently observed by the transformation phase. This requires neither an external writer nor overlap with table entries.

### Interior traversal

After reversal, the function visits blocks \(1\) through \(r-1\) in ascending order. Within each block, it processes word positions 0 through 3 in ascending order.

Each word is read, transformed, and overwritten before the next buffer word is read. Consequently:

- For \(r=0\), there is no reversal exchange and no transformation.
- For \(r=1\), the two blocks are exchanged, but neither is transformed.
- For \(r>1\), exactly \(4(r-1)\) interior words are overwritten by the transformation phase, assuming normal completion.
- Blocks \(0\) and \(r\) receive no transformation-phase writes.

Under the stable-base, stable-table, nonaliasing conditions specified above, one transformation \(T\) describes the final sequence:

- Final block \(0\) is initial block \(r\).
- Final block \(r\) is initial block \(0\).
- Final interior block \(j\) is the wordwise application of \(T\) to initial block \(r-j\).

Without those conditions, traversal and overwrite locations remain established, but a single \(T\) need not describe all words or blocks.

### Table layout and word transformation

For a fixed table base, the accessed layout consists of five consecutive 1,024-byte regions:

| Region | Byte offset from base | Entries | Entry width |
|---|---:|---:|---:|
| Substitution table \(S\) | 0 | 256 | 32 bits |
| Mixing table \(M_0\) | 1,024 | 256 | 32 bits |
| Mixing table \(M_1\) | 2,048 | 256 | 32 bits |
| Mixing table \(M_2\) | 3,072 | 256 | 32 bits |
| Mixing table \(M_3\) | 4,096 | 256 | 32 bits |

The full layout spans 5,120 bytes. This establishes address layout, not initialization, allocation ownership, or mathematical table contents.

For a 32-bit word \(w\), let \(b_0,b_1,b_2,b_3\) denote its numerical bytes, from most significant to least significant. These are bit slices of the loaded word, not an assertion about memory byte order.

Define the substitution-derived index as:

\[
s(b)=S[b]\mathbin{\&}255.
\]

Under a fixed base and stable tables, the transformation is:

\[
T(w)=
M_0[s(b_0)]
\mathbin{\oplus}
M_1[s(b_1)]
\mathbin{\oplus}
M_2[s(b_2)]
\mathbin{\oplus}
M_3[s(b_3)].
\]

Each substitution access reads a complete 32-bit word, but only its low eight bits select the mixing entry. Each mixing entry contributes all 32 bits to the XOR result.

The address calculations for the middle two bytes select the same four-byte-aligned entries as ordinary eight-bit indices. They do not widen those indices. No addition, carry propagation, or final substitution is part of the established word transformation.

### Shared-base observations and ordering

The representation does not establish a table snapshot covering the entire call.

The shared table-base value is read during every transformation-loop condition evaluation, before the extent comparison. This includes the final failed evaluation. Therefore, even for \(r=0\) or \(r=1\), shared base state is read although no table entry is accessed.

For each processed block:

- The condition-time base value is retained.
- The first buffer word is read.
- Four mixing-table addresses are formed from further shared-base reads, in table-offset order.
- The first word’s substitution lookups refer again to shared base state.
- The remaining three words use the retained condition-time base for substitution lookups and the already formed mixing-table addresses.

A changing base can therefore combine substitution and mixing accesses from different regions. The first word has different base-observation behavior from the following three words.

Within one transformed-word expression, each substitution lookup supplies the index for its associated mixing lookup. The relative evaluation order of the four XOR contributions is not established. No most-significant-byte-first table-read order is required.

A buffer overwrite that aliases base-value storage occurs after that word’s value has been computed. It can affect later shared-base observations, including the next block’s condition-time capture. It does not retroactively change base values or mixing addresses already retained for the current block.

## Side effects

The direct writes comprise the reversal exchanges followed by interior-word overwrites. The function provides no rollback or explicit error reporting.

No explicit assignment to shared table-base state or explicit table-entry write appears in the body. This is not a preservation guarantee:

- Buffer/table overlap can modify entries used by later lookups.
- Buffer/base-storage overlap can modify the shared base value and redirect later lookups.
- Both kinds of aliasing can occur during reversal or transformation.

In particular, an interior overwrite may change the base captured for a later block even when all table contents remain stable and disjoint from the buffer. Such behavior invalidates the single-\(T\) final-state model.

The dependency may introduce additional effects not characterized here.

If execution stops during buffer or table accesses, earlier writes may remain visible. Invalid addresses, unsupported arithmetic, or insufficient storage do not produce a specified error result. No locking, transactional behavior, or concurrent-access guarantee is established.

## Acceptance examples

These are conditional analytical examples, not observed executions. Each assumes normal dependency return and valid arithmetic and accesses.

### Zero extent

If the dependency returns \(0\):

- No buffer word is directly read or written.
- No table entry is read.
- Shared table-base state is read by the failed transformation-loop condition.
- No explicit result value is returned.

The dependency’s own effects remain unconstrained.

### Two endpoint blocks

If \(r=1\) and the initial blocks are \(A,B\), the final buffer is \(B,A\), with word order preserved within each block.

No table entry is read. If base-value storage aliases an exchanged word, reversal can nevertheless change that shared value before its condition-time read.

### One interior block

If \(r=2\) and the initial blocks are \(A,B,C\), then under a fixed shared base, fixed table contents, no external buffer interference, and buffer disjointness from both tables and base-value storage, the final buffer is:

\[
C,\ T(B),\ A.
\]

Here \(T(B)\) applies the same word transformation separately to all four words of \(B\).

### Two interior blocks

With \(r=3\), initial blocks \(A,B,C,D\), and the same stability and disjointness conditions, the final buffer is:

\[
D,\ T(C),\ T(B),\ A.
\]

The interior blocks are transformed after reversal, not in their original ordering.

### Base-value storage aliases an interior word

Suppose \(r=3\), table entries are stable and disjoint from the buffer, and the storage holding the shared base value aliases the first word of block 1. Suppose further that, after reversal, the base selects one valid table region, and transforming that first word writes a different valid base value into the aliased storage.

With no other interference:

- Block 1’s condition-time base and mixing addresses were obtained before that overwrite.
- Its remaining words use those retained values.
- The next condition evaluation reads the replacement base.
- Block 2 consequently obtains its base-dependent state from the replacement value.

There is no guarantee that one \(T\) describes both blocks. Stable, buffer-disjoint table contents do not prevent this case.

### Substitution truncation

For the numerical input word \(0x12345678\), the substitution indices are \(0x12\), \(0x34\), \(0x56\), and \(0x78\).

Under a fixed base, suppose the corresponding substitution entries are \(0x00000105\), \(0xABCDEF06\), \(0x00000007\), and \(0xFFFFFF08\). The mixing indices are then \(5,6,7,8\).

If the corresponding mixing words are \(0x80000000\), \(0x00400000\), \(0x00002000\), and \(0x00000001\), the output is \(0x80402001\). Higher substitution-entry bits have no effect on this result.
