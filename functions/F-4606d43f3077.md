# F-4606d43f3077

## Purpose

F-4606d43f3077 selects one of four behaviors using byte-sized fields in a supplied state object:

1. Construct a small response in storage returned by a dependency.
2. Process a special removal-like condition involving an embedded object and its owner.
3. Process an inactive embedded object, including conditional owner-state updates and a callback.
4. Clear an active-state byte and return the embedded object.

These are descriptive branch names, not established application semantics. The static evidence establishes field accesses, dependency calls, return values, and their ordering. It does not establish that the operation destroys an object, releases ownership, acquires a lock, or reports an application-level success.

The first dependency call occurs on every path, including paths that subsequently discard its returned pointer.

## Interface

### Inputs

The function accepts two machine-width arguments:

| Argument | Established use |
|---|---|
| First argument | An opaque 32-bit value passed unchanged to F-603a53835f04, followed by a second argument of zero. No other direct use is visible. |
| Second argument | A 32-bit address used as the base of a mutable state object. It is not checked for null or validity. |

The supplied representation uses 32-bit pointers and integers, 16-bit short values, and 8-bit byte fields. Pointer-bearing fields and dispatch entries are therefore described as 32-bit quantities.

The state object contains the following accessed locations. Names below describe roles in this contract, not declared source types.

| Byte offset | Width | Role |
|---|---:|---|
| +8 | 32 bits | First word of an embedded object, used as a dispatch-table pointer when invoking its callback. The embedded object’s address is the state base plus 8. |
| +12 | 32 bits | Owner address. This is also the embedded object’s field at offset +4. |
| +20 | 8 bits | Active-state byte, tested and sometimes cleared. |
| +80 | 8 bits | Highest-priority response flag. Any nonzero value selects the response path. |
| +81 | 8 bits | State byte cleared on every path except the response path. |
| +1116 | 8 bits | Special-condition flag. Any nonzero value selects the special branch after the response flag has been found clear. |
| +1117 | 8 bits | Special-condition state byte, set to one in the special branch. |

The owner has these accessed locations:

| Byte offset | Width | Role |
|---|---:|---|
| +4 | 32 bits | Address-bearing field used in the special branch’s final pointer lookup; its address is also passed to dependencies on certain paths. |
| +12 | 32 bits | Signed integer counter decremented in the special branch. |
| +32 | 32 bits | Pointer compared against the embedded object’s address. |
| +36 | 32 bits | Another pointer compared against, or captured for replacement of, the embedded object. |

The embedded object’s dispatch table has a callable entry at byte offset +28. That callback is invoked with the embedded object’s address as its visible argument.

### Output

The return is pointer-sized and path-dependent. It is not a uniform success/failure code:

- Response path: the pointer returned by F-603a53835f04, after four bytes are written through it.
- Active-state path: the embedded object’s address.
- Ordinary inactive path: the result of F-fd58bea73663, interpreted as a pointer.
- Special branch: null, or the result of an indirect dependency whose target is read from global storage.

The function does not explicitly return the owner’s +4 field or the first word reached through that field. Those values gate the indirect call; they are not its substitute result.

### Preconditions

Each selected path requires the memory it actually accesses to be valid for the corresponding read, write, or call. In particular:

- The response path requires at least four writable bytes at the initial dependency’s result.
- Paths accessing an owner require a valid owner pointer in the state object.
- Callback paths require a valid dispatch-table pointer and callable entry.
- The special branch’s final lookup requires a readable 32-bit word when the owner’s +4 field is nonnull.

No validation enforces these requirements.

## Behavior

### Common entry and priority

The function first calls F-603a53835f04 with the first input and zero. It then reads a 32-bit value from global storage.

Only after those operations does it inspect the state object’s response flag at +80. Consequently, dependency effects may change the state observed by this flag read. The global value is captured after that dependency call, rather than before it.

Branch priority is:

1. Nonzero response flag.
2. Otherwise, nonzero special-condition flag.
3. Otherwise, zero active-state byte.
4. Otherwise, nonzero active-state byte.

The +81 byte is cleared after rejecting the response branch and before reading the special-condition flag.

### Response path

For any nonzero response flag, the function writes a four-byte response into the initial dependency’s returned storage:

| Destination offset | Width | Value |
|---|---:|---|
| +0 | 8 bits | 2 |
| +1 | 8 bits | 5 |
| +2 | 16 bits | Low 16 bits of the captured global value |

The writes occur in that order. The function then returns that storage address.

The last field is one 16-bit write. Its byte order follows the target’s memory representation; this evidence alone does not establish a portable wire encoding.

This branch does not directly clear +81, inspect the special-condition flag, inspect the active-state byte, or access an owner.

### Special-condition branch

After +81 has been cleared, a nonzero flag at +1116 causes the following behavior:

- Write one to the state byte at +1117.
- Read and retain the owner address from state offset +12.
- Call F-4a19e3742733 with the address of the owner’s +4 field.

After that call, the function reads the retained owner’s +32 pointer and compares it with the embedded object’s address.

If equal, it calls F-8bf796272128 with the retained owner and zero. It then reads the embedded object’s dispatch-table pointer and invokes the entry at table offset +28, passing the embedded object’s address.

The callback lookup occurs after F-8bf796272128. No pre-call dispatch pointer is retained for that lookup.

Whether or not the comparison matched, the function next reads the retained owner’s signed 32-bit counter at +12, subtracts one, and writes the result back. This read occurs after the optional callback, so a callback’s counter change can affect the decremented value.

The final return selection uses fresh memory reads:

1. Read the retained owner’s +4 field.
2. If it is nonnull, read the first 32-bit word at the resulting address.
3. If either pointer value is null, return null.
4. If both are nonnull, invoke the globally selected indirect target and return its result as a pointer.

The supplied representation shows no explicit arguments for that final indirect call. Its complete calling convention and any implicit argument state are not established.

This branch does not directly read or clear the active-state byte. It also does not visibly call F-fd58bea73663.

### Ordinary inactive branch

This branch is selected when both earlier flags are zero and the active-state byte at +20 is zero.

The function reads and retains the owner address, then calls F-4a19e3742733. Unlike the special branch, this call has no explicit argument in the supplied representation. Its argument contract must not be silently inferred from the other call site.

After the call, the function reads the retained owner’s +36 pointer. If it equals the embedded object’s address, it calls F-1cd05d9f8b66 with the owner and zero.

It then reads the owner’s +32 pointer. This comparison occurs after the preceding conditional dependency call, if any, so that dependency may influence the comparison.

If the +32 pointer equals the embedded object’s address:

- Capture the current 32-bit value at owner offset +36.
- Call F-1cd05d9f8b66 with the owner and zero.
- Call F-8bf796272128 with the owner and the captured value.
- Invoke the embedded object’s dispatch-table entry at +28, passing the embedded object’s address.
- Call F-0827b08a6d41 with the owner.

The captured +36 value is used even if F-1cd05d9f8b66 changes that field.

If F-0827b08a6d41 returns zero, the function then reads the owner’s signed 32-bit counter at +12. If the counter is less than two, it calls F-938a7ce5ab19 with the owner. The comparison is signed: negative values, zero, and one satisfy it. The counter is not read for this test when the preceding dependency returns nonzero.

Finally, regardless of whether either owner-pointer comparison matched, the function calls F-fd58bea73663 with the address of the retained owner’s +4 field and returns its result as a pointer.

### Active-state branch

When both earlier flags are zero and the active-state byte is nonzero, the function clears that byte to zero and returns the embedded object’s address.

Besides the common entry dependency call, this path makes no explicit dependency calls. It directly writes +81 first and +20 later. It does not dereference the owner.

### Width and arithmetic requirements

Byte flag tests distinguish zero from any nonzero value; they do not require a canonical value of one.

The response’s 16-bit field discards the captured global value’s upper 16 bits. This is truncation, not a range check.

The special counter operation uses a signed 32-bit field. For values above the minimum signed 32-bit value, its mathematical result is the original value minus one. Overflow behavior at the minimum value is not established by this representation; a portable contract must not assume either trapping or wrapping without additional evidence.

Address offsets are byte offsets. Valid, appropriately accessible addresses are required; no bounds or arithmetic-overflow checks are visible.

## Side effects

Direct writes are limited to:

- Four bytes in the initial dependency’s returned storage on the response path.
- State byte +81 on every non-response path.
- State byte +1117 on the special branch.
- Owner counter +12 on the special branch.
- State byte +20 on the active-state branch.

Dependencies and callbacks may introduce additional writes, allocation, release, synchronization, or other externally observable effects. Their bodies are unavailable here.

No direct allocation or deallocation primitive is visible. In particular, the initial dependency’s pointer is not explicitly released when a non-response path is taken. That fact does not establish a leak: its ownership and lifecycle are unknown.

The retained owner address is not reloaded from the state after intervening calls. Subsequent owner accesses therefore continue through the captured address even if a dependency changes the state’s owner field.

No lifetime protection is visible around callbacks. Safe execution requires any memory subsequently accessed to remain valid despite intervening calls. Such preservation is a prerequisite, not a demonstrated property of those dependencies.

There is no explicit error-reporting channel, rollback, null-result recovery, or exception handling. A null initial result is only immediately dereferenced on the response path. Dependency failure conventions are otherwise unknown.

## Acceptance examples

These examples are conditional static expectations, not executed tests. They assume valid memory, returning dependencies, and no unmentioned dependency mutation.

1. **Response takes precedence.**  
   If the response flag is nonzero, even with both other flags nonzero, the response path is selected. For a captured global value of 0x1234ABCD, the three response fields become 2, 5, and 0xABCD. The returned address is the initial dependency’s result. State byte +81 is not directly cleared.

2. **Active state clears without owner access.**  
   If the response and special flags are zero and the active-state byte is 7, +81 becomes zero, then the active-state byte becomes zero. The returned address is state base plus 8. An invalid owner value does not itself cause an owner dereference on this path.

3. **Special branch returns null for an empty final link.**  
   If the special flag is nonzero, owner +32 does not match the embedded object, the counter is 4, and owner +4 is null, +1117 becomes one and the counter becomes 3. No embedded callback is invoked, and the result is null.

4. **Special callback can affect the counter.**  
   If owner +32 matches and the embedded callback changes the counter to 10, the later decrement writes 9, provided no further intervening effect changes that counter.

5. **Nonzero links enable the indirect result.**  
   If the special branch’s final owner +4 pointer and its first word are both nonnull, the global indirect target is invoked. If it returns address R, this function returns R, including when R is null.

6. **Ordinary processing observes dependency mutations.**  
   If owner +36 initially matches, F-1cd05d9f8b66 is called before the +32 comparison. If that call changes +32 from matching to nonmatching, the later callback sequence is skipped. F-fd58bea73663 is still called and supplies the return value.

7. **Replacement input is captured before clearing.**  
   On an ordinary +32 match, if +36 contains address P when captured, F-8bf796272128 receives P even if the preceding F-1cd05d9f8b66 call changes +36.

8. **Signed threshold boundary.**  
   After an ordinary matching callback, a zero result from F-0827b08a6d41 and counter 1 cause F-938a7ce5ab19 to be called. Counter 2 does not. A nonzero dependency result suppresses the counter test altogether.
