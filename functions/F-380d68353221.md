# F-380d68353221

## Purpose

F-380d68353221 computes unsigned division by 1,000 and returns both the quotient and remainder in one 64-bit result.

For the 32-bit unsigned value consumed by its arithmetic, the normal result is:

- Low 32 bits: the quotient, rounded down.
- High 32 bits: the remainder, in the range 0 through 999.

The function first invokes F-4085480a3d85 with a stack-relative address. That call is part of the established behavior, not an optional implementation detail. Its purpose, memory effects, and relationship to the arithmetic input are not established.

The division behavior is supported by static analysis of the supplied representation. No runtime tests have been performed.

### Output

On the normal arithmetic path, the function returns a 64-bit value containing two unsigned 32-bit fields:

| Bit positions | Meaning |
|---|---|
| 0–31 | Quotient: N divided by 1,000, rounded down |
| 32–63 | Remainder: N modulo 1,000 |

Equivalently, the returned value is the remainder multiplied by 2³², plus the quotient.

The following invariants hold for the normal result:

- N equals 1,000 times the quotient plus the remainder.
- The quotient is between 0 and 4,294,967 inclusive.

The high field is not a status code or sign extension. Consumers must not treat the entire 64-bit value as the quotient.

These are bit positions in a returned integer, not a specified byte layout in memory. The supplied representation does not establish memory byte order or the physical registers used to deliver the result.

### Unsigned division

The arithmetic computes quotient and remainder without an explicit division operation. It uses comparisons against scaled multiples of 1,000, conditionally subtracts those multiples, and accumulates quotient bits.

The externally relevant result is exact unsigned division. There is no rounding to nearest, saturation, loss of fractional remainder, or special treatment of zero.

Within a subtraction stage, the comparison uses the current residual value. A successful comparison reduces that residual before subsequent comparisons occur. The quotient therefore reflects a sequence of dependent decisions, not a set of independent comparisons against the original input.

A subtraction is selected only when its associated scaled quantity fits within the current unsigned residual. On the reachable division paths, this preserves a nonnegative residual.

### Width-sensitive control

The scaled paths process quotient decisions in groups and reduce the working scale by a factor of 64 between repeated groups.

Their continuation logic depends on carries from 32-bit additions. Some initial accumulator patterns are represented as negative signed values, but their role is to control fixed-width quotient construction and loop termination. They do not make the input division signed.

Two width rules matter:

1. Accumulator operations use 32-bit results with the indicated wraparound and carry behavior.
2. Carry-out information is tested separately from the wrapped result.

Replacing these operations with unrestricted integer arithmetic while ignoring the carry tests would not preserve the established control flow.

The finishing decisions account for the remaining quotient bits and select a remainder below 1,000. The returned fields then satisfy the quotient/remainder invariants stated above.
