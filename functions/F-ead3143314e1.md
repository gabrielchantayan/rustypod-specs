# F-ead3143314e1

## Purpose

F-ead3143314e1 resolves a two-word descriptor to a selected cache object. When the descriptor differs from the cache’s recorded keys, it records the new keys and, for most object types, invokes dependencies to construct a payload within that cache object. The output is the cache-object address, not the payload address.

Established behavior includes:

- Treating a descriptor as empty when clearing bit 0 of its first word produces zero.
- Selecting a default cache or a context-associated cache.
- Reading the default-cache pointer on every nonempty path, even when the context path subsequently replaces it.
- Comparing complete descriptor words against two cache-key words.
- Recording both keys before reading the object type or constructing a payload.
- Using different source layouts for type 5 and for types other than 5, 6, and 7.
- Skipping payload construction for types 6 and 7 without undoing the key updates.

“Cache,” “key,” and “payload” describe the visible access pattern. The domain meanings of the data and the intended validity of any resulting payload are not established.

## Interface

### Arguments and result

The function receives three arguments:

1. **Descriptor address:** storage containing two consecutive unsigned 32-bit words.
   - Offset 0 supplies both a tagged reference-like value and the first cache key.
   - Offset 4 supplies the second cache key.

2. **Output address:** writable storage receiving one 32-bit word.
   - The empty path writes zero.
   - Every normally completing nonempty path writes the selected cache address.

3. **Additional unsigned 32-bit value:** its incoming value does not affect the established behavior. When first keys match, the descriptor’s second word replaces this value before the second-key comparison. When first keys differ, the miss decision does not depend on it.

There is no explicit return value or recoverable error status.

### Widths and visible layouts

The supplied representation uses 32-bit addresses, 32-bit integer words, and signed 16-bit short fields.

The retained object address is the descriptor’s initial first word with bit 0 cleared. The other 31 bits remain unchanged. This operation establishes no alignment beyond clearing the lowest bit.

| Structure | Byte offset | Visible use |
|---|---:|---|
| Object | 4 | Signed 16-bit type |
| Cache | 0 | Unsigned 32-bit first key |
| Cache | 4 | Unsigned 32-bit second key |
| Cache | 8 | Payload-builder destination |
| Context | 24 | 32-bit cache pointer |

The default-cache pointer resides in global storage. Its location is distinct from the cache memory to which its value may point.

For the type-5 source layout:

| Byte offset | Visible use |
|---:|---|
| 0, 4, 8, 12 | Four signed 32-bit values copied into temporary storage |
| 16 | Signed 32-bit builder argument |
| 20 | A 32-bit integer narrowed to signed 16-bit width |
| 32 | Beginning of a region passed by address |

For the alternative source layout:

| Byte offset | Visible use |
|---:|---|
| 0, 2, 4, 6 | Four signed 16-bit values widened to signed 32-bit values |
| 8 | Signed 16-bit builder argument, widened to signed 32-bit |

| 20 | Beginning of a region passed by address |

The temporary sequence occupies four consecutive 32-bit slots. The lengths and interpretations of the trailing source regions are unknown.

### Preconditions

Normal defined completion requires valid storage for every access actually taken. This includes:

- The descriptor’s first word and the output word.
- The default-global pointer location on **every nonempty path**, including context paths.
- The context’s cache-pointer field when the context path is selected.
- The selected cache’s accessed key words.
- The object type on a miss.
- All accessed source fields and any additional memory required by dependencies.

A discarded default-cache pointer need not itself designate usable cache memory on the context path: this function reads the pointer value but does not dereference that value before replacing it.

No explicit checks establish pointer validity, sufficient destination capacity, synchronization, or absence of aliasing. Pointer-offset accesses require valid resulting addresses; the function provides no explicit address-overflow handling.

## Behavior

### Empty descriptor

The first descriptor access reads its first 32-bit word. The function clears bit 0 and retains the resulting object address.

If that address is zero, it writes zero to the output and returns. Initial first-word values 0 and 1 both satisfy this condition. This path does not read the second descriptor word, read the default-cache global, or invoke any dependency.

On a nonempty path, the retained object address is not recomputed after dependency calls. Later descriptor reads may therefore describe a different state from the object address retained at entry.

### Cache selection

For a nonempty descriptor, the observable sequence begins:

1. Call F-f4c5ae40135d without explicit arguments.
2. After that call returns, read the default-cache pointer from global storage.
3. Branch on the result returned by F-f4c5ae40135d.

The global read is unconditional within the nonempty path. It does not occur before F-f4c5ae40135d, and its value need not equal the global’s value before that call.

If the dependency returned zero, the previously read default pointer remains selected. No context dependency is called.

If it returned nonzero, the function calls F-3fdd14ecd250. Its result supplies the context address. The default pointer is replaced by a pointer read from context offset 24.

The representation then reads context offset 24 again to decide whether creation is necessary. Thus, it shows two reads of that field: one supplies the selected pointer, and the other controls the zero test. With stable storage, these agree. No dependency call occurs between them, but synchronization and concurrent stability are not established.

When the zero test requires creation, the sequence is:

1. Call F-8157a180d901 with integer value 192.
2. Call F-40704a881de6 without explicit arguments.
3. Use the latter result as the selected cache address.
4. Store that address at context offset 24.
5. Write zero to cache offset 0.
6. Write zero to cache offset 4.

The function does not check the returned address before storing through it. It does not explicitly initialize the payload at offset 8 or beyond.

This resembles allocation and initialization, but the dependency contracts do not establish allocation, a 192-byte extent, alignment, zero-filled storage, ownership, or lifetime.

### Key comparison

After selecting the cache, the function reads the cache’s first key and then the descriptor’s current first word.

The descriptor read occurs after all cache-selection calls. It is separate from the initial read used to retain the object address.

If the first keys differ, the function takes the miss path without reading the second cache key for comparison.

If the first keys match, it reads the cache’s second key and then the descriptor’s second word. Equal second keys produce a hit.

A hit skips:

- Cache-key writes.
- The object-type read.
- Both source-layout dependencies.
- The auxiliary conversion dependency.
- The payload builder.

Cache-selection activity, including the unconditional default-global read, has already occurred before a hit is identified.

The first-key comparison includes bit 0. Two descriptors differing only in that bit retain the same object address but have different first keys.

### Miss and key publication

On a miss, the function reads the descriptor’s second word for the update. When the first keys matched but the second keys differed, this is a new read after the comparison read.

It then performs these operations in order:

1. Write the first descriptor word captured during comparison to cache offset 0.
2. Write the just-read second descriptor word to cache offset 4.
3. Read the signed 16-bit type at retained object address plus 4.

The first key is not reread for the update. The object address is not recomputed from that key.

Consequently, if a dependency changed the descriptor during cache selection, the retained object address and recorded first key may correspond to different descriptor observations. The function does not reconcile them.

The two key writes precede all type-specific dependencies. There is no visible rollback if a later dependency fails or does not return.

### Type 5

For type 5, the function calls F-e2fb1a6905e1 with the retained object address.

From the returned source address, it reads the four 32-bit values at offsets 0, 4, 8, and 12, in that order, into the temporary sequence.

It then reads the 32-bit field at offset 20 and narrows it to signed 16-bit width. That signed value is widened to a signed 32-bit argument and passed to F-b4551e3e3ef6, followed by zero.

After the call returns, the function:

1. Rereads the 32-bit field at offset 20 and again narrows it to signed 16-bit width.
2. Reads the signed 32-bit field at offset 16.
3. Uses source address plus 32 bytes as the trailing-region address.

The two offset-20 observations are independent. Source preservation across F-b4551e3e3ef6 is not assumed.

### Types 6 and 7

For either type, the function skips source lookup, the auxiliary call, and payload construction.

The cache keys have already been updated. The function does not explicitly clear or replace the payload. It proceeds to publish the selected cache address.

A recorded key pair therefore does not establish that a payload was constructed for that pair.

### All other types

Every other signed 16-bit type, including negative values, selects F-9004b031ed2e with the retained object address. There is no visible invalid-type rejection.

The function reads signed 16-bit fields at offsets 0, 2, 4, and 6, in that order, widening each to signed 32-bit temporary storage.

It then reads the signed 16-bit field at offset 10 and calls F-b4551e3e3ef6 with its signed widened value and zero.

After that call returns, it:

1. Rereads the signed 16-bit field at offset 10.
2. Reads the signed 16-bit field at offset 8.
3. Uses source address plus 20 bytes as the trailing-region address.

Both post-call field values are widened with their signs preserved.

### Builder and final output

Both construction paths call F-8a2ae74ef867 with these eight ordered arguments:

1. Selected cache address plus 8 bytes.
2. Address of the temporary four-value sequence.
3. Trailing source-region address.
4. The post-auxiliary-call field from type-5 offset 16 or alternative-layout offset 8.
5. The signed 16-bit-derived value read after the auxiliary call.
6. The result returned by F-b4551e3e3ef6.
7. Zero.
8. Zero.

The temporary values were captured before the auxiliary call. Arguments 4 and 5 derive from reads performed afterward.

The builder’s return value, if any, is unused. On normal completion, the function writes the selected cache address to the output. This write occurs after the builder when construction occurs.

## Side effects

Direct writes target:

- The output word.
- Context offset 24 during cache creation.
- Cache offsets 0 and 4 during initialization and misses.
- Temporary storage used for the builder call.

The default-global pointer is read but not directly written by this function. Its read occurs after F-f4c5ae40135d on every nonempty path, even when its value is discarded.

The payload builder receives cache offset 8 as its destination, but its actual writes and their extent are unknown. Other dependencies may also modify globals, descriptors, contexts, caches, or source memory.

No direct release operation is visible. Ownership transfer and release obligations are not established for the cache, source layouts, auxiliary result, or output address value.

The temporary sequence has call-local lifetime. Safe retention of its address beyond the builder call is not established.

Aliasing is not prohibited. For example, if the output overlaps cache storage, the final output write can overwrite part of that cache. No transactional, reentrancy, or concurrency guarantee is visible.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, assume valid, disjoint, stable storage and normally returning dependencies.

1. **Empty values:** A descriptor first word of 0 or 1 produces output zero without reading the default global or calling a dependency. The second descriptor word need not be accessible.

2. **Default selection after global mutation:** Suppose F-f4c5ae40135d changes the default global from address A to address B and returns zero. The function reads the global afterward and selects B, not a pre-call snapshot of A.

3. **Discarded default read:** Suppose F-f4c5ae40135d returns nonzero and the context ultimately supplies cache C. The default-global read must still occur between that return and the call to F-3fdd14ecd250. The final selection is C, but an inaccessible default-global location still prevents a valid execution of this path.

4. **Cache hit:** Matching key pairs publish the selected cache address without reading the object type or invoking construction dependencies. Changing only the incoming third argument does not change this outcome.

5. **Tag-only difference:** First keys differing only in bit 0 cause a miss even though their masked object addresses agree.

6. **New cache and type 6:** With a stable zero context cache field, creation follows the two-call sequence, installs the returned pointer, and zeros both keys. A stable nonempty descriptor then causes key updates. Type 6 skips construction; payload initialization is not guaranteed.

7. **Signed short conversion:** An alternative-layout field representing −1 contributes −1 after widening, not 65535.

8. **Type-5 narrowing:** Under the represented low-16-bit signed conversion, an offset-20 value of 65535 contributes −1 to the auxiliary call or builder argument 5, depending on which read observes it.

9. **Source mutation:** If the auxiliary call changes the relevant source field from 3 to 4, its input can be 3 while builder argument 5 is 4. The four temporary values retain their earlier captured values.

10. **Skipped construction followed by a hit:** A type-7 miss records keys without constructing a payload. A later matching-key call skips construction again; payload correspondence is not checked.

## Uncertainties

The following remain **documented_only**:

- Domain meanings of descriptors, types, source fields, and payload contents.
- Default-cache initialization, capacity, ownership, and lifetime.
- Allocation or reservation semantics of the creation dependencies.
- Dependency failures, invalid results, exceptions, and nonlocal exits.
- Payload-builder write extent and address-retention behavior.
- Ownership and release obligations for dependency results.
- Global, context, descriptor, and source stability across calls.
- Synchronization and behavior when the two context-field reads disagree.
- Endianness, alignment requirements, and inaccessible-address behavior.
- Language-level portability of out-of-range narrowing; the stated signed narrowing describes the supplied representation.
- Valid domain restrictions beyond the visible branch conditions.

Zero output is established for the empty path, not as a general failure convention.

## Evidence

This contract derives solely from static inspection of the supplied representation. Established claims concern explicit reads, writes, widths, branches, dependency arguments, and their visible ordering.

In particular, cache selection visibly places the default-global pointer read after F-f4c5ae40135d returns and before branching to the context dependency. The read is unconditional for nonempty descriptors; use of its value is conditional.

Caching and allocation intent are inferences, not dependency guarantees. No runtime tests have been performed. The acceptance examples are conditional static expectations, not observed execution results.
