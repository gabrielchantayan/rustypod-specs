# F-751bc1015bb1

## Purpose

F-751bc1015bb1 searches an indirectly referenced collection for entries whose derived 32-bit classification equals a requested value. Its behavior depends on whether the caller supplies a cursor:

- **With a cursor:** return the first matching entry after the supplied position.
- **Without a cursor:** return an entry only if exactly one matching entry is encountered. A second match causes an immediate ambiguity result.

The function returns a 32-bit result obtained from a dependency for an accepted entry. It can also write an auxiliary 32-bit value and update a caller-owned cursor.

A zero return is not, by itself, a complete status indicator. The function returns zero for absence and ambiguity, but the result-producing dependency may also return zero for an accepted entry. The available evidence does not establish that dependency’s result range.

The collection’s application-level meaning, the classification’s meaning, and the returned value’s representation are unknown.

## Interface

### Inputs

The function accepts four arguments:

1. **Owner reference**
   - A pointer to a readable 32-bit word containing an object address.
   - The function reads a 32-bit collection reference at byte offset `0x24` from that object address.
   - Neither the owner reference nor the object address is checked for null before these reads.
   - A zero collection reference is handled as an absent collection.

2. **Requested classification**
   - A 32-bit value compared for equality with the result of F-2eb743f270d1.
   - Although the supplied representation treats this argument as signed, equality does not introduce signed ordering behavior. All 32 bits participate in the comparison.

3. **Optional auxiliary-output pointer**
   - Either null or a pointer to writable 32-bit storage.
   - For an accepted entry, receives the result of an unmapped metadata dependency.
   - For absence, receives `0xffffffff`.
   - For ambiguity in cursorless mode, receives `0xfffffffe`.

4. **Optional cursor pointer**
   - Either null or a pointer to readable and writable signed 32-bit storage.
   - Its presence selects cursor mode; its absence selects uniqueness mode.
   - In cursor mode, the initial value determines where scanning begins.
   - On a match, the function writes the matched index.
   - On absence, it writes `-1`.

The auxiliary output is a full 32-bit word. The two sentinel bit patterns may be interpreted as signed values `-1` and `-2`, respectively, but the available evidence does not establish a signed type for successful auxiliary values.

### Return value

The return value is one 32-bit word:

| Outcome | Return |
|---|---|
| Accepted entry | Result of F-d3c4429f541e for that entry |
| No accepted entry | Zero |
| Second matching entry in uniqueness mode | Zero |

There is no separate established error object, exception protocol, or diagnostic channel.

### Storage and validity requirements

The owner reference and referenced object must support the initial reads. A nonzero collection reference must be acceptable to the collection dependencies.

Each examined collection element must be a readable entry address containing at least one readable 32-bit word. The function dereferences that address without a null check before classifying the entry.

Any supplied output pointer must support the accesses described above. The function does not validate memory accessibility, collection integrity, or index consistency.

## Behavior

### Collection acquisition

The function first reads the object address through the owner reference, then reads the collection reference at offset `0x24`.

This collection reference is obtained once for the search. The visible body does not reload the owner’s collection field after dependency calls. Consequently, replacing that field during a dependency call does not visibly redirect later collection operations to the replacement.

A zero collection reference bypasses all collection, classification, metadata, and result-producing dependency calls. The function then performs the absence writes described below.

### Starting position

For a nonzero collection reference:

- Without a cursor, scanning begins at index zero.
- With a cursor, the function reads the cursor and forms its value plus one.
- If the computed signed value is negative, scanning begins at zero.
- Otherwise, scanning begins at that computed value.

For values whose increment is representable as signed 32-bit arithmetic, this establishes the following behavior:

- A cursor of `-1` starts at zero.
- A cursor below `-1` also starts at zero.
- A cursor of zero starts at one.
- A nonnegative cursor normally excludes that index and every earlier index from the search.

The behavior of incrementing the maximum signed 32-bit value is not fully established by the supplied representation. A wraparound interpretation would restart at zero after the negative-result check, but that interpretation requires confirmation from lower-level arithmetic evidence.

### Collection traversal

Before each potential element access, including the first and the check that terminates traversal, the function calls F-10b760faca36 with the captured collection reference.

It compares the current signed index with that dependency’s signed 32-bit result. If the index is not less than the reported bound, traversal ends.

The bound is therefore **not cached**. Changes to the collection’s reported size during the search may affect later iterations. No snapshot or stability guarantee is established.

For each index admitted by the bound check, the function:

- Calls F-6bbddce1b930 with the collection reference and index to obtain an entry address.
- Reads the first 32-bit word at that entry address.
- Passes that word to F-2eb743f270d1.
- Compares the resulting classification with the requested classification.

The classification dependency receives the entry’s first word, not the entry address itself.

An unmatched entry does not cause a direct output write. The index advances and the next bound check occurs.

### Cursor mode

When a cursor pointer is present, the first matching entry ends the search:

1. The matched index is written to the cursor.
2. If auxiliary output is requested, the metadata dependency is called with the entry address, and its result is written to the auxiliary output.
3. F-d3c4429f541e is called with the entry address.
4. Its 32-bit result is returned.

The function does not inspect later entries to determine whether the match is unique.

The cursor write precedes both successful-output dependencies. Thus a dependency may observe the updated cursor if it can access that storage. The visible body does not restore the cursor after those calls.

If traversal ends without a match, the function performs the absence writes.

### Uniqueness mode

When no cursor pointer is present, the function retains the address of the first matching entry but continues scanning.

If another matching entry is encountered:

- The function returns zero immediately.
- If auxiliary output is supplied, it first writes `0xfffffffe`.
- It does not call the metadata dependency or F-d3c4429f541e for either match.

This rule counts matching **encounters**, not distinct entry addresses. Two matching collection positions produce ambiguity even if both positions yield the same entry address.

If traversal ends after exactly one matching encounter:

1. If auxiliary output is supplied, the metadata dependency is called with the retained entry address, and its result is written to the auxiliary output.
2. F-d3c4429f541e is called with that entry address.
3. Its result is returned.

The retained address is not visibly re-fetched or reclassified before these calls. If intervening dependency calls change the entry, the successful-output dependencies receive the retained address in its then-current state.

If traversal ends without a matching encounter, the function performs the absence writes. An unmatched final entry is not accepted merely because it was the most recently examined entry.

### Absence handling

Absence includes a zero collection reference and exhaustion without a match.

The direct writes occur in this order:

1. If a cursor pointer is supplied, write signed `-1`.
2. If an auxiliary-output pointer is supplied, write `0xffffffff`.
3. Return zero.

There is no explicit failure branch for malformed entries, invalid addresses, or dependency failures. Such conditions are outside the established normal-return contract.

## Side effects

### Direct memory activity

The visible body directly:

- Reads the object address through the owner reference.
- Reads the collection reference from the object.
- Reads the initial cursor when a nonzero collection is searched in cursor mode.
- Reads the first 32-bit word of each examined entry.
- Writes cursor and auxiliary-output storage according to the selected outcome.

It shows no direct allocation, deallocation, collection update, or entry update.

That observation does not establish that the complete operation is read-only: dependency side effects are unknown.

### Output timing and aliasing

The function does not initialize output storage before searching. During unsuccessful intermediate iterations, the prior output contents remain unchanged by this body.

No non-aliasing requirement is visible. Where arguments designate overlapping valid storage, the actual access order governs the result:

- On cursor-mode success, the cursor write occurs before metadata computation and auxiliary assignment.
- On absence, the cursor write precedes the auxiliary write.
- If cursor and auxiliary output designate the same word, a successful auxiliary write overwrites the matched index.
- The result-producing dependency runs after any successful auxiliary write, so its observable effects may occur after that assignment.

If output storage aliases an entry or dependency-visible state, output writes may alter data subsequently consumed by a dependency. This contract does not assume alias independence.

### Ownership

No ownership transfer is established for the owner, collection, entries, or output storage.

The body retains an entry address only for use during the call. It makes no explicit release call. The ownership or lifetime effects of the dependencies are unknown; they must not be assumed to preserve or release memory.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Except where specified, they assume valid storage, stable collection contents and bounds, normally returning dependencies, and representable index arithmetic.

1. **Absent collection**
   - The collection field is zero.
   - Both output pointers are supplied.
   - Expected: cursor becomes `-1`, auxiliary output becomes `0xffffffff`, and the return is zero.
   - No dependency is called.

2. **Empty collection**
   - The collection reference is nonzero and its first reported bound is zero.
   - Expected: no element lookup or classification call; absence handling occurs.

3. **One match without a cursor**
   - Exactly one examined position has the requested classification.
   - Expected: scanning continues through the final bound check.
   - The retained matching entry is then passed to the optional metadata dependency and to F-d3c4429f541e.

4. **Two matches without a cursor**
   - Two examined positions classify as requested.
   - Expected: the second match immediately produces zero and, when requested, auxiliary value `0xfffffffe`.
   - Neither successful-output dependency is called.

5. **Repeated address**
   - Two collection positions return the same readable entry address, and both classification calls match.
   - No cursor is supplied.
   - Expected: ambiguity, not a unique result.

6. **Resume after an index**
   - The cursor initially contains `2`; matching entries exist at indices `2` and `4`.
   - Expected: scanning begins at `3`; index `4` is accepted and written to the cursor.
   - Index `2` is not inspected during this call.

7. **Negative cursor normalization**
   - The cursor initially contains `-5`.
   - Expected: scanning begins at zero because the representable increment remains negative.

8. **Final entry does not match**
   - In uniqueness mode, an early entry matches and every later entry does not.
   - Expected: the early matching entry is accepted after exhaustion, not the final examined entry.

9. **Accepted entry returns zero**
   - Exactly one entry is accepted, and F-d3c4429f541e returns zero.
   - Expected: the function returns zero despite acceptance; cursor or auxiliary effects remain those of the accepted-entry path.

10. **Auxiliary output omitted**
    - An entry is accepted with a null auxiliary-output pointer.
    - Expected: no metadata call; F-d3c4429f541e still supplies the return value.
