### Timing, aliasing, and state changes

The global reads occur at their respective stages, not collectively before the first call.

In particular:

- F-bf74dfda5df0 may affect the global values subsequently read.
- The write at byte offset 0 precedes the indirect-source access.
- The write at byte offset 176 precedes F-1e0cead58a3d.
- The write at byte offset 180 precedes F-8157a180d901.
- The final-argument source is used after F-8157a180d901 returns.

These ordering relationships matter if storage aliases or dependencies mutate shared state. For example, if the direct write overlaps storage subsequently used by the indirect-value source, the later read can observe the effect of that write. The evidence does not establish a non-aliasing guarantee.

Similarly, a field written before a dependency call is not guaranteed to retain that value through function return. A dependency could have access to the object through global state or another alias. The function does not restore earlier fields after such a mutation.

Under an additional assumption that dependencies and other actors do not modify the destination fields, the four fields at return contain the respective values described in the layout table. Without that assumption, the unconditional contract is the ordered sequence of writes, rather than preservation of every earlier value.
