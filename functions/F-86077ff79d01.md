# F-86077ff79d01

## Purpose

F-86077ff79d01 projects selected contents of a fixed-stride record sequence into two packed output streams. For each record processed, it transfers two 32-bit fields into one stream and writes a classification byte into another.

Under valid arithmetic, stable input, and nonoverlapping storage, a nonnegative count of \(N\) produces:

- \(8N\) field-output bytes, containing the fields at record offsets 16 and 20, in that order.
- \(N\) classification bytes, determined by bits 0 and 1 of each record’s initial 16-bit field.

Records are 40 bytes apart. Classification does not filter records: every processed record contributes both fields and one classification byte.

The function performs sequential, interleaved reads and writes. It does not provide a source snapshot, overlap-safe copying, validation, or transactional completion. The domain meanings of the fields and classifications are not established.

## Behavior

### Initialization and traversal boundary

The visible initialization reads the input-record pointer first and the field-output pointer second. It then reads the count and forms the input endpoint. The classification-output pointer is read after endpoint formation and before the initial loop comparison.

The endpoint is expressed as an offset of \(20N\) elements, each two bytes wide, from the input base. Its mathematical byte displacement is therefore \(40N\).

The arithmetic stages matter. The supplied representation multiplies the signed count by 20 before applying two-byte pointer scaling. It does not show a checked multiplication or an explicitly unsigned, wrapping calculation. Under a 32-bit signed-integer interpretation, representability of that intermediate product is required; valid pointer formation and ordering are separate requirements. A representable product does not prove that the storage exists or that the endpoint is valid.

Traversal is controlled by whether the current input position is less than the endpoint. It is not controlled by a separately decremented record count. After each processed record, the input position advances by 40 bytes. Under ordinary valid array-address conditions and a nonnegative count, exactly \(N\) records are processed.

Negative counts and invalid endpoint calculations do not have an established general result. The representation provides no explicit rejection path for them.

### Observable record access order

For each processed record, the first 32-bit source field, at offset 16, is read and written to the current field-output position. That write precedes the read of the second source field at offset 20. The second field is then written to the next 32-bit destination position.

Both field writes occur before the flag field is examined.

Classification first tests bit 0 of the 16-bit flag field at record offset 0. When that bit is clear, the visible logic accesses the flag field again to test bit 1. The selected byte is then written to the current classification-output position.

The next record uses a field-output position eight bytes later and a classification-output position one byte later. No destination capacity is checked before advancing or writing.

This is the access ordering expressed by the supplied static representation. Exact machine instructions, compiler transformations, and concurrent or device-memory semantics are not independently established.

### Classification

For stable flag storage, classification is:

| Flag condition | Output byte |
|---|---:|
| Bit 0 set | 0 |
| Bit 0 clear; bit 1 clear | 1 |
| Bit 0 clear; bit 1 set | 2 |

Bit 0 takes precedence. A flag with both low bits set produces 0.

Bits 2 through 15 do not affect this decision. Neither extracted 32-bit field directly participates in classification, although overlapping writes can change the flag storage before it is examined.

The bit-0-clear path contains two visible flag accesses rather than an explicit retained snapshot. If the storage changes between them, the two tests need not reflect the same value. This observation does not establish a supported concurrency contract or guarantee the number of physical memory reads.

There are no visible output headers, counts, separators, padding writes, or terminators. Unused destination capacity is not initialized.

The fields undergo no visible arithmetic, masking, or format conversion during transfer. Their stored byte representation follows the target’s native 32-bit accesses.

### Empty input

With a valid zero count and valid endpoint formation, the endpoint equals the input base. The record-processing body does not execute.

All four descriptor-field reads still occur. No record fields are read, and neither output stream is written.

An empty input therefore does not excuse inaccessible descriptor storage. Nor does the representation establish that arbitrary pointer values are valid merely because no record-body access follows.

### Overlapping storage

There is no explicit overlap handling. Results can depend on earlier writes rather than solely on the original input.

In particular:

- The first field write can overwrite the second source field before its read.
- Either field write can overwrite the flag before classification.
- A classification write can change a later record.
- Overlapping output streams can overwrite one another.
- Output writes can alter descriptor storage if the caller aliases it with a destination.

The initially loaded pointers and calculated endpoint are retained for traversal. Altering descriptor storage during processing does not itself cause those fields to be reloaded.

These are consequences of the represented sequential accesses, conditional on the overlapping accesses otherwise being valid. They are not a promise that every overlap arrangement has defined behavior under the original language, ABI, or execution environment.
