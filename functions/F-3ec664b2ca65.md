# F-3ec664b2ca65

## Purpose

F-3ec664b2ca65 performs an in-place update of two regions in a caller-supplied memory object:

- It replaces the first four-byte word with the value read from a shared four-byte data location.
- It clears the two least significant bits of the byte at offset 20, then retains only the two least significant bits of the complete four-byte word beginning at that same offset.

The byte and word updates overlap. Their combined result depends on how the lowest-addressed byte maps into the four-byte word. Under little-endian interpretation, the word at offset 20 finishes as zero. Under big-endian interpretation, it finishes with only its original two least significant bits retained.

These are consequences of the supplied static representation. No application-level meaning for either field is established.

The one-byte region is part of the four-byte region at offsets 20–23. It is not a separate field for purposes of access ordering.

The routine also reads one shared four-byte data location. Its address, meaning, initialization requirements, and mutability outside this routine are not established.

## Behavior

### Access order

At the level represented by the supplied statements, the routine performs these accesses in order:

1. Reads a four-byte value from the shared source location.
2. Writes that value into the four-byte region at offset 0.
3. Reads the byte at offset 20.
4. Writes that byte back with its two least significant bits cleared.
5. Reads the complete four-byte word at offset 20, including the preceding byte modification.
6. Writes that word back with all bits except its two least significant bits cleared.
7. Returns without a value.

The full-word read therefore uses the state after the byte write, not an independently saved copy of the word from entry.

This ordering describes the supplied static representation. It does not establish six separately observable machine transactions. Volatile behavior, atomicity, compiler transformations, and externally visible intermediate states are not specified.

### First-word replacement

The four-byte value read from shared storage replaces the entire word at offset 0. The previous destination value does not participate in this update.

There is no increment, merge, conversion, comparison, or conditional branch associated with this replacement. The source value is not shown being retained for use by either later masking operation.

If the destination aliases the shared source, the source read still precedes the first destination write in the represented operation order. The input value is therefore the value read at that point, not a guaranteed snapshot from some earlier time.

### Byte modification

For the byte at offset 20, the routine clears bits 0 and 1 and preserves bits 2 through 7. Bit positions here refer to the numeric value of that byte; bit 0 is its least significant bit.

Examples of this intermediate byte transformation:

| Byte read | Byte written |
|---|---|
| 0x00 | 0x00 |
| 0x03 | 0x00 |
| 0xA7 | 0xA4 |
| 0xFF | 0xFC |

This is an intermediate update. The following four-byte write can replace the same byte again.

### Full-word modification

The routine next reads the four-byte word beginning at offset 20 and retains only bits 0 and 1 of that word. All other bits are cleared.

The word operation is 32 bits wide. The retained-bit mask has the numeric value 3. The earlier byte operation is 8 bits wide and uses a retained-bit mask of 0xFC.

There is no arithmetic carry, signed comparison, shift, or saturation. The width-sensitive issue is the overlap between the byte and word, not arithmetic overflow.

### Endianness-dependent result

**Under little-endian interpretation:** the byte at offset 20 contains word bits 0 through 7. The byte update clears word bits 0 and 1. The final word update then clears every other bit. The resulting four-byte word is zero, regardless of its initial contents.

**Under big-endian interpretation:** the byte at offset 20 contains word bits 24 through 31. Clearing that byte’s bits 0 and 1 does not affect word bits 0 and 1. The final word therefore equals the original word with every bit except bits 0 and 1 cleared.

The supplied representation does not explicitly establish the target byte order. Accordingly, an unconditional zero-result contract requires additional evidence of little-endian interpretation.

For ordinary nonoverlapping memory without external interference or mapped-device effects, bytes outside the two written regions remain unchanged by this routine. This preservation claim does not imply that memory outside those regions must be initialized or read.

## Acceptance examples

These examples are conditional static expectations, not recorded runtime results. They assume valid ordinary memory, no concurrent modification, and no aliasing with the shared source unless stated otherwise.

### Little-endian destination

Given:

- The shared source holds 0x12345678.
- The word at offset 0 initially contains any value.
- The word at offset 20 initially contains 0xFFFFFFFF.

Expected on return:

- The word at offset 0 is 0x12345678.
- The word at offset 20 is zero.
- Untargeted bytes are unchanged.

The byte at offset 20 is first reduced from 0xFF to 0xFC. The final word mask then produces zero.

### Little-endian boundary values

For initial words at offset 20 of 0, 1, 2, or 3, the final word is zero in every case.

This distinguishes the combined behavior from a standalone word mask that would retain the values 1, 2, and 3. The preceding overlapping byte write clears those bits first.

### Big-endian destination

Given big-endian interpretation and an initial word at offset 20 of 0xFFFFFFFF:

- The intermediate word is 0xFCFFFFFF.
- The final word is 3.

For initial words 0x12345678, 0x12345679, 0x1234567A, and 0x1234567B, the final words are respectively 0, 1, 2, and 3.

### Changing shared source between calls

If one call reads a shared value of 0x11111111 and a later call reads 0x22222222, the first destination word receives those respective values.

No cached source value or once-only initialization behavior is present in the supplied representation.

### Destination aliases shared storage

If the first destination word is exactly the shared source location, the initial read followed by the first write writes back the value just read, absent interference.

If the shared source overlaps the word at offset 20 instead, that source value is read before the masking operations. Those later destination writes may then change the shared storage through the alias. The routine does not promise to preserve it.
