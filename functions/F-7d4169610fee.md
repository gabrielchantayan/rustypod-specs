## Behavior

### Ordered orchestration

On a path where all dependencies return normally, the function performs the following observable sequence.

1. It reads the byte at A4 plus 2.
2. It calls F-d7be9cfb4000 with that byte as its first argument and the constant decimal 12 as its second argument.
3. After that call returns, it reads the byte at A4 plus 1 and retains its value.
4. It initializes two separate four-byte temporary payloads to the values listed under **Purpose**.
5. It calls F-6ec180735aac with A1 and A4, in that order.
6. It selects the zero-result payload if that dependency’s primary integer result is exactly zero. Every nonzero result selects the other payload.
7. It calls F-efd44af20731 with eight arguments, detailed below.
8. If the final dependency returns normally, the function returns without an explicit result.

There is no direct loop, retry, early success return, or explicit error return in this behavior.

### Read timing and mutation visibility

The two record bytes are not captured together.

The byte at offset 2 is read before F-d7be9cfb4000 executes. The byte at offset 1 is read after that dependency returns. Consequently, if F-d7be9cfb4000 changes the byte at offset 1 through an alias or shared state, the later read observes the resulting value, subject to ordinary memory validity and execution assumptions.

The byte at offset 1 is not reread after F-6ec180735aac. Changes that dependency makes to the record therefore do not replace the already captured byte used in the final integer computation.

The four-byte field at A1 plus `0xBC` is loaded for the final call, after F-6ec180735aac has returned. Its value is not an entry-time snapshot. Mutations to that field by either preceding dependency can therefore affect the final argument.

These timing statements do not imply that any dependency actually performs such mutations. They specify which value the wrapper would use if it did.

### Payload selection

The primary result from F-6ec180735aac is tested only for equality with zero.

- Exactly zero selects `00 00 00 FF`.
- Any nonzero value selects `FF FF FF FF`.

There is no separate negative-result error branch. A negative primary result, if representable under the dependency’s actual return convention, takes the nonzero branch.

Both payloads are initialized before the selection dependency is called. The selected payload is passed by address, not as a packed four-byte scalar. Its byte sequence is therefore specified independently of integer endianness.
