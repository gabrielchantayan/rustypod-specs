# F-be6f8f51a231

## Purpose

F-be6f8f51a231 represents a fixed-order sequence of indirect calls, byte accesses, and 32-bit word accesses. It captures an initial byte selector, derives numeric addresses from that selector and dependency results, and performs further selector-directed writes using fresh byte reads.

No application-level purpose is established. The low numeric destinations do not establish device registers, an object layout, an allocation scheme, or a valid address range.

The supplied static representation warns of invalid instruction data and ends at a truncated control-flow boundary. This contract describes the represented operations, conditional on their accuracy and on execution reaching them. It does not establish a complete executable routine, a normal return, or the architectural consequence of the terminal boundary.

### Widths and interpretation

A byte is 8 bits; a word is 32 bits. A paired result is represented as 64 bits and is separated numerically into low and high 32-bit halves. This numerical separation does not establish a memory layout or byte order.

“Low byte” means the least significant 8 bits. Byte stores retain that byte even where the representation uses a signed-looking character conversion. Byte selectors are read as unsigned values from 0 through 255.

The right shifts described below operate on unsigned values. Left shifts and scaling appear in 32-bit expressions, including expressions represented with signed types. For arithmetic examples, this contract uses a **32-bit bit-pattern interpretation**: retain the low 32 bits after scaling or left shifting. That interpretation is not proof of defined signed-language arithmetic or of actual architectural address wrapping.

An access can complete only if its computed address is accessible with the required width and any applicable alignment requirements. No checks establish those conditions. Memory mapping, endianness, alignment rules, and fault behavior remain unknown.

## Behavior

### Initial selector and early calls

The first represented direct access reads one byte at **entry base + 1**. Its captured value is the **initial selector**.

The entry byte is then written to numeric address **initial selector + 17**. This destination ranges from 17 through 272. It is not relative to the entry base.

F-d001 through F-d005 are then invoked in order:

- F-d001 receives the explicit 32-bit input.
- F-d002 through F-d005 have no explicit arguments shown.

The first target is constructed from the entry link value plus 4094. Later targets are derived from embedded code-location values. Their actual identities and calling conventions are not established.

Subsequent expressions use the captured initial selector rather than rereading the entry byte at entry base + 1.

### Selector-derived writes and result chain

After F-d005, the represented operations write:

- The low byte of the entry word to **entry base + 13**.
- The initial selector to numeric address **13**.

The **doubled selector** is twice the initial selector. It ranges from 0 through 510, so this particular multiplication does not overflow 32 bits.

F-d006 receives, in order:

1. The doubled selector.
2. 152.
3. 608.

F-d007 follows with no explicit arguments shown. F-d008 receives an unsigned 32-bit register observation logically shifted right by 3. That observation is not established as a conventional return value of F-d007.

Byte value **192** is subsequently written to numeric address **13**. This is a separate access from the earlier selector write to address 13.

F-d014 receives the result of F-d013 shifted left by 2. F-d015 through F-d017 follow with no explicit arguments shown. F-d018 supplies another represented 32-bit result.

### First word writes and loaded-base continuation

The result of F-d018 is used in two scaled forms:

- Its value shifted left by 2 is written as a 32-bit word to **doubled selector + 36**.
- Its value shifted left by 5 becomes the **saved scaled result**.

After the first word write and before the next call, a 32-bit word is read from **doubled selector + 116**. Call the captured word the **loaded base**. It is subsequently used both as a numeric value and as an address base.

F-d019 receives:

1. The loaded base.
2. The loaded base shifted left by 1.
3. The saved scaled result.
4. The loaded base with bit 31 cleared, then logically shifted right by 2.

The fourth argument is not the original unsigned loaded base divided by four: the highest bit is discarded before the shift.

F-d020 through F-d023 follow without explicit arguments shown.

The saved scaled result is then written as a 32-bit word to **loaded base + 36**. A fresh 32-bit word is read from **loaded base + 116**, and that newly read word is passed to F-d024.

The two reads at offset 116 have different base expressions. Neither the values nor the effective addresses are required to match. Dependency calls occur between them and may affect memory.

### Late byte writes through fresh selectors

The byte at **loaded base + 1** is then read again. A byte derived from the late result is written through this new selector, again to numeric address **selector + 17**.

For this second stored byte, the represented expression clears bits 30 and 31 of the late result, shifts right by 20, and retains the low byte. The stored value therefore consists of original bits **20 through 27**. Original bits 28 and 29 are discarded by byte truncation.

The selector is not cached across F-d041 through F-d043. The two destination addresses may differ if those calls or another agent change the selector memory.

F-d044 receives the result of F-d043 shifted left by 2. F-d045 through F-d047 follow without explicit arguments shown. F-d048 supplies another represented 32-bit result.

## Acceptance examples

These examples are conditional arithmetic and ordering consequences, not runtime tests. They assume that the relevant operations are reached, memory accesses complete, and the stated dependency values are supplied. Overflowing examples additionally use the 32-bit bit-pattern interpretation.

1. **Maximum initial selector.** With an initial selector of 255, the first store targets address 272. The doubled selector is 510, and F-d006 receives 510, 152, and 608.

2. **Zero selector and repeated address 13.** With an initial selector of zero, the doubled-selector-plus-13 store targets address 13. It writes the low byte of the entry word before the separate store of 192. These accesses remain distinct even if their values happen to match.

3. **Byte versus word storage.** With an entry word of 0x123456AB, the two entry-word byte stores write 0xAB. The word store selected by F-d028’s high half writes all 32 bits, 0x123456AB. Its byte order is not specified.

4. **Highest-bit clearing.** With a loaded base of 0x80000004, F-d019’s fourth argument is 1. Under the 32-bit interpretation, its second argument is 8, rather than a widened mathematical product.

5. **First paired result.** If F-d028 supplies low half 3 and high half 5, the saved scaled low half is 12. The entry word is stored at address 40, and F-d029 receives 12, 12, 12, and 0.

6. **Second paired result.** If F-d030 supplies low half 7 and high half 24, F-d031 receives 7, 24, 7, and 3. These arguments come from the second paired result, not the first one.

7. **Fresh late selectors.** If the first late read at loaded base + 1 returns 2 and the second returns 9, the corresponding stores target addresses 19 and 26. A single cached selector would not satisfy the represented behavior.

8. **Late byte extraction.** With a late result of 0xABCDEF12, the first late byte store writes 0x48 and the second writes 0xBC. The latter selects original bits 20–27, not the highest byte.

9. **Two distinct clearing stores.** If the final selector reads return 4 and then 7, zero is written first to address 21 and later to address 24. These are the twelfth and thirteenth individual direct stores.
