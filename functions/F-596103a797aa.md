# F-596103a797aa

## Purpose

F-596103a797aa performs ordered recognition and dispatch. It supplies a selector and each reached configured candidate to a comparison dependency. The first comparison returning nonzero selects an action; zero permits searching to continue. If all comparisons return zero, the function returns false without preparation or action dispatch.

There are 18 candidate positions. The first 17 select ordinary handlers. The last selects preparation, conversion of the prepared temporary area, and an action receiving both the conversion result and a field read from the target.

The Boolean result reports recognition on normally returning paths, not successful completion of an application-level operation. Preparation and action return values are not tested.

**Established static evidence:** Candidate order, zero/nonzero selection, argument routing, temporary initialization, pointer-reference distinctions, and dependency-call ordering are visible in the supplied representation.

**Inferred intent:** The function resembles a property or command dispatcher. Selector meanings, candidate names, and action semantics are not established.

### Lookup and initialization ordering

The representation establishes the following ordering:

1. The primary global pointer value is captured.
2. Payload and companion initialize the temporary words.
3. Another primary-global reference supplies the base for reading the candidate at `0xE8`; that value is compared.
4. If the first comparison returns zero, the candidate at `0xE4` is read using the earlier captured primary value and compared.
5. After the second comparison returns, the secondary global pointer value is captured, whether that comparison returned zero or nonzero.
6. If the second comparison selected its candidate, preparation and its handler follow without any secondary-entry access.
7. Otherwise, the temporary words are reassigned the original payload and companion. Another secondary-global reference supplies the base for entry 3, which is then compared.
8. Subsequent secondary candidates, if reached, are read through the captured secondary value.

Candidate values are obtained as their positions are reached; there is no visible eager snapshot of all entries.

A first comparison that changes the primary global pointer does not redirect the second primary lookup: that lookup uses the earlier captured value. A mutation to the candidate stored at that captured base can affect the later read.

Either primary comparison may affect the secondary global value before its capture. However, entry 3 must still be described as using the later global reference, not the captured secondary value. No dependency call is shown between secondary capture and that later reference; only local state changes intervene. This neither proves two physical loads nor establishes a supported mechanism for those expressions to observe different values.

Once entry 3 has been compared, all remaining secondary lookups use the captured secondary value. A comparison can therefore change later candidate contents at that base, but replacing the secondary global pointer does not redirect those remaining lookups.
