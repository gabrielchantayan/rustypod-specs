# F-d4cc721b189f

## Purpose

F-d4cc721b189f scans an array-like region within a caller-supplied object. It conditionally invokes two dependencies, in a fixed order, if the scan accepts at least one record.

A record is eligible for comparison when its first status byte is exactly 1 and its second status byte is exactly 0. Its unsigned 32-bit ranking value must also be strictly less than the scan’s current threshold, initially 4,294,967,295.

With stable input memory, this is equivalent to asking whether any record has both required status values and a ranking value other than 4,294,967,295. The scan tracks the index of a lowest-ranking qualifying record, but does not pass that index, the ranking value, or a record address to either dependency. Consequently, the established externally relevant result of the selection is the decision whether to invoke the dependencies—not an established operation on the selected record.

The apparent intent is to identify a preferred eligible record before performing an object-related action. What that action does, and whether it independently locates a record, are unknown.

## Behavior

### Scan initialization and bounds

The scan begins at record index zero. Both the remembered index and the ranking threshold begin at the unsigned 32-bit maximum, 0xFFFFFFFF.

Before each iteration, the current unsigned 32-bit index is compared with a fresh read of the count at base + 0x468. An iteration occurs only if the index is strictly less than that count.

The count is not captured once at entry. Accordingly, a model in which the count changes between reads must account for those rereads. The supplied evidence does not establish that concurrent modification is supported or synchronized.

For a stable count:

- A count of zero causes no record fields to be read.
- Records are considered in ascending index order.
- A count of 4,294,967,295 permits indices zero through 4,294,967,294 in the abstract scan. The final index value equals the count and terminates the loop.
- The index value 0xFFFFFFFF is never processed as a record index, because no unsigned 32-bit count can be greater than it.

Very large counts do not imply valid backing storage. Address validity remains a caller-side precondition.

### Record-read order and acceptance

For each reached record, the source-level access order is:

1. Read the first status byte.
2. Read the second status byte only if the first status byte equals 1.
3. Read the ranking value for comparison only if the first status equals 1 and the second status equals 0.
4. If that ranking read is strictly below the current threshold, remember the record index and obtain the new threshold from another read of that record’s ranking field.

Thus, a record whose first status is not 1 does not cause a second-status or ranking-field read through this logic. A record whose first status is 1 but whose second status is not 0 does not cause a ranking-field read.

The status conditions are exact equality checks. A nonzero first status other than 1 is not accepted. A nonzero second status is not accepted. Whether a plain character is signed or unsigned does not change those equality outcomes.

Ranking comparisons are unsigned 32-bit comparisons. A ranking bit pattern of 0x80000000 represents 2,147,483,648 for this purpose, not a negative value.

The comparison is strict. Under stable memory, equal-ranking later records do not replace the earlier remembered record. A ranking of 0xFFFFFFFF cannot be the first accepted ranking, because it is not below the initial threshold.

The successful comparison and threshold update are expressed as separate ranking-field reads in the supplied representation. If those reads produce different values, the threshold receives the second value, not necessarily the one that passed the comparison. A stable-memory interpretation avoids that distinction; behavior under concurrent mutation or special memory semantics is not otherwise specified here.

### Completion and dependency calls

After the scan, the function checks whether a record index was remembered.

If none was remembered, the function returns without calling either dependency.

If an index was remembered:

- The fourth argument is copied into a local four-byte temporary.
- F-360ac6ff643e is invoked with the address of that temporary as its first argument and the object base as its second argument.
- If that invocation returns normally, F-9b718979506d is invoked with the same temporary’s address as its sole argument.
- If the second invocation returns normally, this function returns.

The temporary is initialized only once. It is not restored between calls. Therefore, any modification of its contents by F-360ac6ff643e is visible to F-9b718979506d.

The remembered record index is not forwarded. Neither is the final threshold. No supplied evidence supports a claim that either dependency acts on the record identified by the scan.

### Arithmetic and address formation

The index, count, ranking values, and threshold are 32-bit unsigned quantities in the supplied representation. Record displacement uses a 60-byte stride.

For sufficiently large indices, the stride multiplication or subsequent address formation can exceed a 32-bit address range. The supplied function contains no guard against that condition. This contract does not treat wrapped addresses as valid object storage or assign portable behavior to invalid accesses.

For an ordinary valid object, each accessed field must fit within its readable storage, with address calculations remaining meaningful on the target.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied representation, not reports of executed tests. Unless noted otherwise, assume stable readable memory, valid address calculations, and dependencies that return normally.

### Empty object

Given a count of zero:

- No record status or ranking field is read.
- Neither dependency is invoked.
- The function returns without a result value.

### First status rejects a record

Given a single record whose first status is 2:

- Its first status is read.
- Its second status and ranking are not read through this function’s scan logic.
- Neither dependency is invoked.

The same rejection applies to any first-status value other than 1.

### Second status rejects a record

Given a single record whose first status is 1 and second status is 1:

- Both status bytes are read in that order.
- Its ranking field is not read.
- Neither dependency is invoked.

### Maximum ranking does not trigger calls

Given one record with first status 1, second status 0, and ranking 0xFFFFFFFF:

- The ranking is compared with the initial threshold.
- Equality does not satisfy the strict comparison.
- No index is remembered and neither dependency is invoked.

If every eligible record has this ranking, the result is the same.

### One acceptable record triggers one call sequence

Given one record with first status 1, second status 0, and ranking 7:

- The record is accepted by the scan.
- After scanning finishes, the fourth argument initializes the temporary.
- F-360ac6ff643e receives its address and the object base.
- F-9b718979506d then receives that same address.

Changing only the second or third argument does not change this function’s established behavior.

### Multiple rankings do not produce multiple operations

Given three eligible records with rankings 9, 3, and 3:

- The first record establishes a threshold of 9.
- The second replaces it with 3.
- The third does not replace it because its ranking is equal.
- Exactly one dependency-call sequence follows the completed scan.

The internal preference for the second record does not establish that either dependency receives or acts on that record.

### Unsigned ranking interpretation

Given eligible records with rankings 0x80000000 followed by 1:

- The first ranking is below 0xFFFFFFFF and is initially accepted.
- The second ranking is smaller in unsigned comparison and replaces the threshold.
- One dependency-call sequence follows.

### Temporary mutation between calls

Given an accepted scan and a fourth argument containing a four-byte value:

- F-360ac6ff643e initially receives access to a copy of that value.
- If it replaces the temporary’s contents and returns normally, F-9b718979506d receives access to the replacement contents.
- This function does not restore the original value between calls.
