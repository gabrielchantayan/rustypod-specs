# F-6254c52d18c8

## Purpose

F-6254c52d18c8 conditionally updates a three-word destination descriptor using ranges described by a source descriptor. Its control flow depends on descriptor-address identity, source length, destination length, and destination capacity.

**Established behavior:** the function either returns without accessing descriptor fields, obtains replacement storage through dependencies, or reuses existing storage. The selected path determines which destination fields are written and when.

**Inferred intent:** the descriptor resembles a byte-addressed sequence, and the operation resembles assignment with capacity growth. The supplied source does not establish the payload type or the copying, construction, destruction, allocation, and release semantics of the dependencies.

Two details are part of the contract rather than conventionalized away:

- One reuse path writes the destination capacity end to the new logical end; another makes no direct capacity-end write.
- In the replacement path, destination start is written before source length is reread. Overlapping descriptor storage can therefore change the length used for the final logical-end write, even when dependencies leave descriptors unchanged.

No runtime tests have been performed.

## Interface

### Arguments and return value

| Argument | Established role |
|---|---|
| Destination descriptor address | Identifies three consecutive 32-bit words that this function may read and write. |
| Source descriptor address | Identifies a descriptor whose first two 32-bit words supply range boundaries. |
| Auxiliary word A | A 32-bit unsigned value assigned to temporary storage on existing-capacity paths. No subsequent consumption of that assigned value is explicit in the source. |
| Auxiliary word B | A 32-bit unsigned value assigned to temporary storage on existing-capacity paths. No subsequent consumption of that assigned value is explicit in the source. |

Every normal return produces the original destination descriptor address, not its backing-storage address.

### Descriptor layout

| Byte offset | Contract name | Use |
|---|---|---|
| 0 | Start | Address-like 32-bit word used as the storage origin. |
| 4 | Logical end | Address-like 32-bit word used to calculate logical length. |
| 8 | Capacity end | Address-like 32-bit word used to calculate capacity. |

The function directly reads only the first two source fields. It does not directly read a source capacity-end field.

For ordinary, non-overflowing ranges:

- Source length is source logical end minus source start.
- Destination length is destination logical end minus destination start.
- Destination capacity is destination capacity end minus destination start.

These differences are not scaled by an element size.

### Widths and arithmetic

Descriptor words and the unsigned comparison values are 32 bits. Growth calculation uses unsigned 32-bit additions and logical right shifts. Those unsigned additions are modulo \(2^{32}\), not unbounded mathematical arithmetic.

Some boundary subtraction, address addition, and traversal increments appear as signed integer operations in the supplied source. Their overflow behavior is not established here. Ordinary mathematical formulas below apply only when the relevant operations are representable and ranges remain coherent.

Unit increments and unscaled boundary differences support a byte-addressed interpretation, but do not prove a semantic element type.

### Validity and aliasing

The identity path does not require descriptor-field access. Other paths require descriptor storage to remain valid wherever the function reads or writes it. Dependencies may impose additional storage requirements that are not supplied.

There is no explicit check for null descriptors, reversed ranges, overflow, overlapping storage, allocation failure, or dependencies invalidating later accesses.

Distinct descriptor addresses do **not** establish disjoint descriptor storage or disjoint backing storage. Destination writes may modify source fields through overlap. A descriptor may also become invalid if it resides in storage affected by a dependency.

Consequently, a conventional assignment-style final-state guarantee requires more than dependencies leaving descriptors unchanged: relevant descriptor storage must remain valid, and direct destination writes must not alter source fields needed by later reads. The acceptance examples state these conditions explicitly.

## Behavior

### Identical descriptor addresses

When the source and destination descriptor addresses are equal, the function returns the destination address without reading descriptor fields, writing descriptor fields, or calling dependencies.

This is descriptor-address identity, not equality of contents or storage boundaries. The auxiliary words do not affect this path.

### Initial selection

For distinct descriptor addresses:

1. The function reads and retains source start.
2. It reads source logical end and calculates a 32-bit unsigned source-length value.
3. It obtains destination capacity from destination capacity end minus destination start.
4. An unsigned comparison selects replacement storage when destination capacity is less than source length. Otherwise, it selects existing-capacity handling.

The relative order of the destination-field reads within the capacity expression is not established.

These initial values are not a persistent snapshot. Later stages reread fields, including after dependency calls and direct descriptor writes.

### Insufficient capacity: capacity selection

The function rereads both source boundaries to obtain a length for capacity selection, then calculates destination logical length.

For destination length \(L\), the initial growth candidate is:

\[
G=L+(L\mathbin{\gg}1)+(L\mathbin{\gg}3).
\]

An unsigned comparison replaces that candidate with \(L+32\) if the latter is greater. A further unsigned comparison selects the reread source length when it is at least the candidate.

For non-overflowing ordinary values, the requested capacity is therefore:

\[
R=\max\left(S,\ L+\lfloor L/2\rfloor+\lfloor L/8\rfloor,\ L+32\right),
\]

where \(S\) is the source length reread on this path.

The formula must not be used as an unbounded or saturating rule. Unsigned growth additions can wrap, and no explicit overflow rejection is present.

### Insufficient capacity: calls and old-storage handling

The function calls F-871e64ddc6de with the selected capacity and zero. It retains the returned word as the proposed new storage start. No explicit failure check precedes subsequent use.

It then calls U-1 with:

1. Source start, reread after F-871e64ddc6de returns.
2. Source logical end, also reread after that return.
3. The retained proposed new start.
4. The destination descriptor address.

The order of individual argument-field reads within this call is not established. U-1’s returned value is unused.

After U-1 returns, the function captures destination start. From that captured value, it performs an empty traversal, incrementing by one until the traversal value equals destination logical end. No per-element operation or destruction call appears in the loop body.

The function next calls F-ff1bdc376dcd with:

1. The destination start captured after U-1.
2. Destination capacity end minus that captured start.
3. Zero.

The capacity-end value is read after U-1. Neither the captured start nor that capacity end is guaranteed to be an entry-time value.

### Insufficient capacity: descriptor writes

After F-ff1bdc376dcd returns, direct destination writes occur in this order:

1. Start becomes the retained result of F-871e64ddc6de.
2. Logical end becomes that retained result plus a newly read source length.
3. Capacity end becomes the retained result plus the selected capacity.

The source boundaries used in step 2 are read **after step 1**. They are not necessarily the boundaries used for the initial branch, the capacity request, or U-1.

This ordering matters independently of dependency side effects. If destination start overlaps source logical end, step 1 changes the source length subsequently used in step 2. “Dependencies leave descriptors unchanged” alone therefore cannot establish a final logical end of new start plus the original source length.

The capacity-end write uses the retained allocation result and selected capacity; it does not recompute capacity from the source.

### Existing capacity: destination shorter than source

The function calculates destination logical length and assigns the auxiliary inputs to two temporary words. It compares that unsigned destination length with the initially calculated unsigned source length.

When destination length is smaller:

1. F-7f306cecf838 is called with two explicit arguments: the initially retained source start, and that start plus the calculated destination length.
2. After the call returns, destination logical end is written as the then-current source length plus the then-current destination start.
3. U-1 is called with the then-current source start plus the previously calculated destination length, the then-current source logical end, the then-current destination start plus that same calculated length, and the destination descriptor address.
4. The function returns immediately.

The first dependency receives the initially retained source start, not a source-start reread at that call site.

The final U-1 arguments use field reads after the logical-end write. Descriptor overlap can make that write affect the source range passed to U-1. The offset used for the suffix remains the previously calculated destination length.

This function makes no direct start-field or capacity-end write on this path. That does not guarantee those fields remain unchanged: dependencies or aliasing may change them.

The logical-end write precedes U-1, so the descriptor can advertise its enlarged logical range before that dependency completes.

### Existing capacity: destination at least as long as source

When destination length is at least the initially calculated source length:

1. F-7f306cecf838 is called with no explicit arguments visible in the supplied source.
2. Its returned word initializes an empty traversal.
3. The traversal increments by one until it equals destination logical end.
4. A value is calculated from the then-current source length plus the then-current destination start.
5. Destination logical end is written with that value.
6. Destination capacity end is written with the same calculated value.
7. The function returns the destination descriptor address.

The two destination end writes use one retained value. If the first write changes source fields through overlap, the second write still uses that already calculated value.

The function makes no direct start-field write here. The capacity-end write collapses reported capacity to the newly calculated logical length. A contract that preserves the previous capacity on this path would contradict the source.

The no-explicit-argument call must not be silently treated as equivalent to the two-explicit-argument call. Its actual calling convention remains unresolved.

## Acceptance examples

These are conditional static expectations, not executed tests.

Unless an example explicitly introduces overlap, assume disjoint source and destination descriptor storage, continued validity of all descriptors and required storage, coherent non-overflowing arithmetic, normally returning dependencies, and no dependency changes to descriptor fields. Assume any traversals terminate. Payload-transfer results remain unspecified.

### Identical descriptors

Given equal source and destination descriptor addresses, expect that address as the result and no descriptor-field access or dependency call. Descriptor contents are irrelevant to this path.

### Replacement with minimum growth

Given destination length 8, capacity 16, and source length 20:

- The insufficient-capacity path is selected.
- Proportional growth is \(8+4+1=13\).
- Minimum-increase growth is \(8+32=40\).
- F-871e64ddc6de receives 40 and zero.

If it returns \(N\), final destination fields are start \(N\), logical end \(N+20\), and capacity end \(N+40\).

This final-state expectation requires the source length to remain 20 through the reread **after destination start is written**. Disjoint, still-valid descriptor storage and the stated dependency assumptions satisfy that requirement; unchanged descriptors across dependency calls alone do not.

### Overlapping descriptors alter the replacement length

Let the destination descriptor begin at address \(P\), and place the source descriptor one 32-bit word before it, at \(P-4\). Let \(B\) denote the initial destination backing-storage start.

Arrange the words so that:

- Source start is \(B-20\).
- Source logical end and destination start share the word containing \(B\).
- Destination logical end is \(B+8\).
- Destination capacity end is \(B+16\).

Initial source length is 20, destination length is 8, and destination capacity is 16. The requested capacity is therefore 40.

Assume dependencies leave these words unchanged, all relevant storage remains valid, and F-871e64ddc6de returns \(N\). Writing destination start to \(N\) also changes source logical end to \(N\). The subsequent source-length reread yields:

\[
N-(B-20).
\]

Subject to representable arithmetic, final destination logical end is consequently:

\[
N+\bigl(N-(B-20)\bigr),
\]

not necessarily \(N+20\). Capacity end is still \(N+40\). This example establishes no guarantee that the resulting logical end lies within the reported capacity.

### Source length dominates growth

Given destination length and capacity 64 and source length 200:

- Proportional growth is 104.
- Minimum-increase growth is 96.
- Requested capacity is 200.

The request depends on the capacity-selection reread still yielding source length 200.

### Reuse with a longer source

Given destination length 4, capacity 12, and source length 9:

- F-7f306cecf838 receives source start and source start plus 4.
- Destination logical end is written as destination start plus 9.
- U-1 receives the source suffix beginning at source start plus 4 and destination start plus 4 as its destination address.
- This function makes no capacity-end write.

These range expectations require the stated descriptor-stability and non-overlap conditions.

### Reuse with a shorter or empty source

Given destination length 9, capacity 12, and source length 4, the no-explicit-argument F-7f306cecf838 invocation occurs. After normal return and traversal termination, both destination end fields become destination start plus 4.

For a zero-length source and coherent ordinary destination ranges, the same reuse subpath is selected. Both end fields become destination start. Empty input does not bypass F-7f306cecf838.
