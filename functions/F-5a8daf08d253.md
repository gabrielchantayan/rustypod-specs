# F-5a8daf08d253

## Purpose

F-5a8daf08d253 conditionally publishes a sequence of fixed-stride input records into shared, indexed state associated with a selected channel. It can also request a completion-related state transition after processing the requested records.

The established behavior is narrower than a general-purpose enqueue operation:

- The requested channel must exactly match a byte stored in shared state.
- Each record uses the next candidate index derived from a shared cursor.
- A nonzero occupancy entry rejects that candidate immediately; the function does not search for another free entry.
- Successfully published records remain published if a later candidate is occupied.
- An optional post-processing path marks an indexed flag and, conditionally, updates shared state, writes a channel register, and calls a dependency.

The function returns a 32-bit success or failure bit pattern. Success does not establish that a consumer has processed the records or that any hardware operation has completed.

The interpretation of the shared arrays as a queue, and of the final state transition as an activation or completion request, is inferred intent. The reads, writes, conditions, and ordering below are established by the supplied static evidence.

### Return value

No separate result distinguishes channel mismatch from occupancy rejection. No count of successfully published records is returned.

### Shared state and storage

For description, the following role names identify storage without assigning an undocumented ownership model:

## Behavior

### 1. Entry and channel selection

The function obtains the state-block and occupancy/payload-array bases, then reads the byte at state-block offset 9.

It compares that byte, zero-extended, against the entire unsigned 32-bit A2 value. This is not a comparison against only A2’s low byte.

If unequal, the function returns `0xffffffff`. No explicit shared-state write, register write, or dependency call occurs on this path.

If equal, A2 must be within 0 through 255. The function selects a channel control address as follows:

| Selector bit 7 | Control-register address |
|---|---|
| Clear | `0x38400000 + 0x0b00 + 0x20 × (A2 & 0x7f)` |
| Set | `0x38400000 + 0x0900 + 0x20 × (A2 & 0x7f)` |

It reads one 32-bit word from that address and retains the value for subsequent record processing. This read occurs even when A4 is initially zero.

Later metadata calculations use only this saved word’s low 11 bits. The control register is not explicitly reread for each record.

The original channel byte is also retained and later determines the optional channel-register write. A later change to the shared channel byte does not change that selection within the visible body.

### 2. Count handling and candidate selection

At the top of each loop pass, the function tests whether the current count is zero and then decrements the local count. A zero pre-decrement value enters the post-processing/return path without attempting another record.

For a nonzero count, the function reads the signed cursor at state-block offset `0x1c` and forms a candidate by adding one.

If the candidate is signed-greater-than 43, it is replaced with zero. Otherwise it is used unchanged.

For the ordinary cursor domain −1 through 43:

- Cursor −1 selects candidate 0.
- Cursor 0 through 42 selects the following index.
- Cursor 43 wraps to candidate 0.

There is no explicit lower-bound correction. A cursor below −1 can therefore produce a negative candidate. Signed overflow in the increment is not resolved by the supplied representation; callers should not rely on behavior at the signed maximum.

The candidate’s 32-bit occupancy/payload entry is then read.

- Nonzero: return `0xffffffff` immediately.
- Zero: proceed to publish the input record.

An occupied candidate does not cause a search of other indices. It also does not trigger the optional post-processing path, even when A5 is nonzero.

### 3. Record-dependent computation

For an available candidate, the function reads the signed 16-bit field at A3 plus 6 and converts it to an unsigned 32-bit quantity, called **L** here.

Consequently:

- A stored value of zero gives L = 0.
- Positive signed values retain their numerical value.
- Negative signed values produce unsigned values from `0xffff8000` through `0xffffffff`.

A second quantity, **N**, is obtained as follows:

- If L is zero, N is 1 and no dependency is called for this computation.
- Otherwise, F-870c4fcf7295 is called with two 32-bit arguments: L − 1 and the saved control word masked with `0x7ff`. N is the returned value plus one.

The actual relationship computed by F-870c4fcf7295 is unknown. In particular, the supplied evidence does not establish division, rounding, a nonzero second argument, or a bounded return value.

The visible primary metadata expression combines:

- L;
- N shifted left by 19 bits;
- N shifted left by 29 bits;

using bitwise OR, not addition.

There is no explicit mask of L or N before this combination. Large values can overlap the apparent fields. A clean partition into independent bit fields must not be assumed.

The visible destination is 32 bits. Interpreting the shifts and increment as truncating target-word arithmetic is an inference about the machine-level behavior; signed overflow and shift semantics are not independently established by the supplied representation.

### 4. Publication order

After any F-870c4fcf7295 call returns, the function obtains the metadata-region base and performs the following explicit operations in order:

1. Write the combined 32-bit metadata value to the primary metadata entry for the candidate.
2. Read the 32-bit payload from the current input record and write it into the candidate’s occupancy/payload entry.
3. Write zero to the secondary metadata entry at metadata base plus `0x160 + 4 × candidate`.
4. Write the candidate to the cursor at state-block offset `0x1c`.
5. Advance the input pointer by 12 bytes.

The payload read is later than the metadata write and any dependency call. The function does not snapshot the whole input record in advance.

This matters if input storage aliases a destination, or if a dependency changes the input storage: the length-like field and payload can reflect different moments.

The occupancy check is likewise earlier than the dependency call. There is no explicit recheck before publication.

A zero payload is permitted by the visible body. Because the same destination is tested for nonzero occupancy on later attempts, publishing zero does not visibly establish occupancy through that entry alone. Whether zero is a valid payload requires an external contract.

### 5. Optional post-processing

When the loop reaches a zero-count exit:

- If A5 is zero, the function returns `0x00000000`.
- If A5 is nonzero, it first writes the 32-bit value 1 into the completion-mark entry indexed by the candidate value currently retained by the function.

After that mark write, it reads the byte at state-block offset 5.

If the byte is nonzero, there are no further explicit writes or dependency calls on this path, and the function returns zero.

If the byte is zero, the function:

1. Reads the signed 32-bit field at state-block offset `0x20`.
2. Replaces that field with `0xffffffff` only if its signed value is less than −1.
3. Writes byte value 1 at state-block offset 5.
4. Writes byte value 1 at state-block offset 6.
5. Writes a 32-bit zero to the channel address selected below.
6. Calls F-627c2cdb2924 with no explicit arguments.
7. Returns zero if the call returns.

The channel write address uses the original channel byte:

| Original channel bit 7 | Write address |
|---|---|
| Clear | `0x38400000 + 0x0b10 + 0x20 × (channel & 0x7f)` |
| Set | `0x38400000 + 0x0910 + 0x20 × (channel & 0x7f)` |

The completion mark is written even when offset 5 was already nonzero.

If at least one record was published, the retained candidate is the final published candidate. If the initial count is zero, the visible body does not initialize this candidate before using it in the A5-nonzero path. That combination has an unresolved implicit-state requirement and must not be specified as safely marking the current cursor.

## Acceptance examples

These examples are conditional on valid storage, returning dependencies, and no interfering changes except those stated.

1. **Full-width channel mismatch.**  
   The shared channel byte is `0x12`; A2 is `0x00000112`. The function returns `0xffffffff`, despite matching low bytes. No explicit channel-control read or shared write follows the mismatch.

2. **Matched empty request without post-processing.**  
   A2 matches the channel, A4 is zero, and A5 is zero. The channel-control word is read. No input record or occupancy entry is read. The function returns zero.

3. **Single zero-length record.**  
   The cursor is −1, entry 0 is zero, A4 is 1, and A5 is zero. A zero length-like field gives N = 1 without calling F-870c4fcf7295. The primary metadata value is `0x20080000`. The payload is copied, secondary entry 0 is cleared, cursor becomes 0, and the return value is zero.

4. **Immediate occupancy rejection.**  
   The cursor is 43 and occupancy entry 0 is nonzero. With a nonzero count, the function returns `0xffffffff` after testing entry 0. It does not inspect the record’s length-like field or run optional post-processing.

5. **Partial publication.**  
   Two records are requested. The first candidate is available and the next is occupied. The first record’s writes and cursor update remain. The result is `0xffffffff`; A5 does not cause a completion-mark write on this failure exit.

6. **Negative length-like field.**  
   A stored signed 16-bit value of −1 becomes L = `0xffffffff`. F-870c4fcf7295 receives `0xfffffffe` as its first argument. If it returns normally and publication proceeds, OR with L makes the primary metadata word `0xffffffff`.

7. **Already-active post-processing state.**  
   At normal count exhaustion, A5 is nonzero and state-block byte 5 is nonzero. The completion mark is still written. The field at `0x20`, bytes 5 and 6, and channel register receive no further explicit writes; F-627c2cdb2924 is not called.

8. **Initial zero count with completion requested.**  
   A4 is zero and A5 is nonzero. The evidence does not establish a valid completion-mark index. Acceptance is documented_only pending resolution of the implicit retained value; no specific array destination can be promised.
