# F-f72114b90855

## Purpose

F-f72114b90855 conditionally transforms a value supplied as two 32-bit words and returns a packed 64-bit result. Its decisions depend on an exponent-like field extracted from the upper input word, an externally supplied offset, and selected low-order bits.

For most paths, the returned bits are identical to the input bits. Some unchanged-result paths nevertheless invoke two dependencies in sequence. A narrower set of paths clears low-order bits and, for certain upper-word values, first increments the retained portion.

The field extraction and adjustment patterns suggest an operation on a split floating-point representation. That interpretation is **inferred intent**, not an established numerical contract. The supplied evidence does not provide the external constant values or dependency behavior needed to identify a particular rounding operation. In particular, the specification must preserve the unchanged-result paths that are present in the supplied representation rather than replace them with a presumed mathematical operation.

## Interface

### Inputs

The function receives two unsigned 32-bit words:

- **Lower word**, denoted \(L\).
- **Upper word**, denoted \(H\).

These names describe their positions in the returned 64-bit bit pattern. They do not establish a memory byte order or a floating-point calling convention.

All 32-bit input patterns are accepted by the visible control flow. There is no explicit pointer input, length input, validation failure, or error-result encoding.

### Output

On normal return, the function produces a 64-bit bit pattern:

\[
R = H_{\mathrm{out}}\times 2^{32}+L_{\mathrm{out}}.
\]

The upper and lower words are concatenated, not numerically converted from another type. The source does not establish how an external ABI classifies this result.

### Arithmetic conventions

- Unsigned 32-bit additions wrap modulo \(2^{32}\).
- Signed comparisons interpret a 32-bit word as a two’s-complement signed value.
- Right shifts used for field and mask extraction are logical.
- Bitwise complements are confined to 32 bits.
- Relevant shift counts are masked to their low eight bits in the supplied representation. On every reachable shifted path, the selector constraints already keep the actual counts within 0 through 31.

The contract assumes the supplied representation correctly expresses these integer operations. Machine-level calling-convention details are not available.

## Behavior

### 1. Derive and retain the selector

The function reads the exponent offset and extracts bits 20 through 30 of the original upper input word. Bit 31 is excluded.

The extracted field is:

\[
E=(H\mathbin{\&}\text{0x7fffffff})\mathbin{\gg}20,
\]

so \(E\) is between 0 and 2047.

The 32-bit selector is:

\[
S=(\text{exponent offset}+E)\bmod 2^{32}.
\]

Subsequent top-level branch decisions interpret \(S\) as signed. The selector is computed once; dependency calls do not cause it to be recomputed from external storage.

The output initially corresponds to the original input words.

### 2. Signed selector greater than 19

This region has three materially different cases.

#### Selector at least 52

When the signed selector is at least 52:

- Neither dependency is called.
- No input bits are changed.
- The original packed input is returned.

Only the initial exponent-offset read is established on this path.

#### Selector from 20 through 51, with no selected lower-word bits

For this range, the function constructs the lower-word mask:

\[
M=\text{0xffffffff}\mathbin{\gg}(S-20).
\]

This mask selects the lowest \(52-S\) bits of the lower word. For example:

- At 20, it selects all 32 lower-word bits.
- At 50, it selects the lowest two bits.
- At 51, it selects only bit 0.

If \(L\mathbin{\&}M=0\), the function returns the input unchanged and calls neither dependency.

No upper-word fraction test is performed in this region.

#### Selector from 20 through 51, with selected lower-word bits present

If \(L\mathbin{\&}M\neq0\), the function first invokes the two-dependency sequence described below. Output adjustment occurs only after both calls return normally.

At selector 51, the function returns the original input unchanged, despite having detected a selected lower-word bit and executed both dependency calls.

At selectors 20 through 50, the function clears the selected lower-word bits, with a preceding increment when the original upper word is positive under a signed 32-bit comparison.

The precise adjustment is:

- If the original upper word is signed-positive and the selector is 20, increment the upper word by one modulo \(2^{32}\). The lower word is then cleared to zero.
- If the original upper word is signed-positive and the selector is from 21 through 50, add \(2^{52-S}\) to the lower word modulo \(2^{32}\). If the wrapped sum is less than the original lower word under an unsigned comparison, increment the upper word by one modulo \(2^{32}\).
- If the original upper word is zero or signed-negative, perform neither increment.
- Finally, clear all bits selected by \(M\) from the resulting lower word.

“Signed-positive” means the upper word lies in the inclusive range 1 through 0x7fffffff. It is not a numerical comparison of the complete 64-bit input. In particular, an upper word of zero does not qualify even when the lower word is nonzero.

### 3. Signed selector less than zero

For every negative signed selector:

1. The function invokes the two-dependency sequence.
2. If both calls return normally, it returns the original input words unchanged.

There is no zero-input exemption on this path.

The supplied representation sets a local control value to true before the calls and subsequently takes an unconditional-in-effect path to the return. Consequently, later code that could construct a different upper word is unreachable under the visible semantics.

An inferred floating-point interpretation must not override this unchanged-result behavior.

### 4. Selector from 0 through 19

The function reads the upper-word mask seed and constructs:

\[
U=\text{upper-word mask seed}\mathbin{\gg}S.
\]

It then considers both original input words:

- If \(H\mathbin{\&}U=0\) and \(L=0\), it returns the original input unchanged without dependency calls.
- Otherwise, it invokes the two-dependency sequence and then returns the original input unchanged.

As in the negative-selector path, a local control value is set to true before the calls, making subsequent adjustment code unreachable under the visible semantics. There is no established path in this selector range that changes either returned word.

### 5. Two-dependency sequence

Whenever a branch requires dependency calls, their sequence is:

1. Read the first dependency operand pair and invoke the branch-selected first dependency with four 32-bit words: the original lower input, the original upper input, and the two externally supplied operand words.
2. Treat that dependency’s result as a 64-bit bit pattern.
3. Read the second dependency operand pair and invoke F-c6bfc9d0fb36 with the first result’s lower word, its upper word, and the second operand pair.
4. Disregard the second dependency’s return value and continue the selected branch.

The first dependency is:

- F-387e686c467e for selectors 20 through 51 with a nonzero selected lower-word field.
- F-1b22d7e17791 for negative selectors and for qualifying selectors 0 through 19.

The original inputs, rather than partially adjusted words, are passed to the first dependency. All established output adjustment happens after the second call.

Within each argument group, the representation does not establish an exact order between the two external operand reads. It does establish that the second operand pair is obtained for the second call after the first call has returned. The contract therefore does not assume the external operand pairs form a single entry-time snapshot.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, required dependency calls are assumed to return normally.

The selector conditions depend on the unknown exponent offset. Each case applies only when the selected inputs and external offset actually produce the stated selector.

1. **Large positive selector.**  
   Given a signed selector of 52 or greater, any input words are returned unchanged. Neither dependency is called.

2. **No selected lower-word bits at selector 30.**  
   At selector 30, the lower-word mask is 0x003fffff. With lower word 0x00400000, the selected field is zero. The complete input is returned unchanged, with no dependency calls.

3. **Positive-upper-word adjustment at selector 20.**  
   Given selector 20, a signed-positive upper word, and any nonzero lower word, the function calls F-387e686c467e followed by F-c6bfc9d0fb36. It then returns lower word zero and upper word incremented by one.

4. **Zero upper word does not trigger an increment.**  
   Given selector 20, upper word zero, and lower word one, the same two dependencies are called. The result has both words zero. The nonzero lower word does not make the upper-word signed comparison positive.

5. **Carry from the lower word at selector 21.**  
   Given selector 21, a signed-positive upper word, and lower word 0xffffffff, the lower-word increment is 0x80000000. The wrapped sum is 0x7fffffff, so the upper word is incremented. Clearing the selected lower 31 bits leaves output lower word zero.

6. **Bit clearing without increment for a signed-negative upper word.**  
   Given selector 50, a signed-negative upper word, and lower word 0x00000007, the two dependencies are called. The upper word is unchanged, and the output lower word is 0x00000004.

7. **Selector-51 boundary.**  
   Given selector 51 and an odd lower word, the two dependencies are called, but both output words remain identical to the inputs. Given an even lower word instead, neither dependency is called.

8. **Negative selector, including zero input.**  
   If the exponent offset produces a negative selector for an all-zero input, F-1b22d7e17791 and then F-c6bfc9d0fb36 are still called. The returned packed value remains zero.

9. **Small nonnegative selector with no selected bits.**  
   Given a selector from 0 through 19, lower word zero, and no upper-word bits selected by the shifted mask seed, the function returns unchanged without calls.

10. **Small nonnegative selector requiring calls.**  
    Given a selector from 0 through 19 and a nonzero lower word, the function calls F-1b22d7e17791 followed by F-c6bfc9d0fb36, regardless of the upper-word mask test’s outcome. The returned words remain unchanged.

11. **State changed by the first dependency.**  
    If the first dependency changes storage supplying the second operand pair, the second call uses the values read for that later invocation. No entry-time snapshot of those operands is established.
