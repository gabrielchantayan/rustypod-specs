# F-9918a047bc22

## Purpose

F-9918a047bc22 processes records from two sources associated with a mutable context. It visits the primary source first, then the secondary source unless primary processing returns a nonzero status or enters an exceptional path marked nonreturning.

For each selected record, a classification dependency determines whether record-specific processing is required. A primary record is either submitted for removal or retained with a position increment. A secondary record is submitted for removal after classification and any processing, including when processing returns a nonzero status.

The result is a 32-bit status. A nonzero primary status is returned only after primary removal-or-retention handling and maintenance. A nonzero secondary status is returned only after secondary removal.

“Source,” “record,” “position,” “classification,” and “removal” describe observed structural roles. Application meaning, ownership transfer, and actual erasure are not established.

## Interface

### Arguments and result

| Argument | Observed representation | Behavior |
|---|---|---|
| Context | 32-bit address-bearing value | Identifies mutable fields and associated objects. |
| Auxiliary value | 32-bit word | Has no visible use in the supplied body. |
| Decision pointer | Pointer to a 32-bit word | Initially eligible for forwarding to secondary classification. The function can replace its local copy with the address of local decision storage. |
| Initial decision | Unsigned 32-bit word | Initializes local decision storage. Every primary classification is followed by resetting that storage to zero before further handling. |

The result is a 32-bit integer. Status handling distinguishes zero from nonzero; no visible normalization changes a returned status bit pattern.

Replacing the local decision pointer does not replace the caller’s pointer variable. It changes the pointer subsequently forwarded by this function.

### Context and record layout

Offsets are byte offsets from the context address.

| Offset | Width or form | Observed role |
|---|---|---|
| `+0x04` | 32-bit address | Points to an associated object whose word at `+0x3c` is passed to primary processing. |
| `+0x0c` | 32-bit handle/address | Identifies the primary source. Zero prevents entry into a primary iteration. |
| `+0x10` | 32-bit word | Primary position; interpreted as unsigned for bounds comparisons and classification selection, but as signed for removal-address recomputation. |
| `+0x14` | 32-bit word | Primary pass counter, passed to primary processing and incremented after a wrap condition. |
| `+0x3c` | Embedded object address | Passed to secondary query and removal dependencies. Its first 32-bit word also supplies the selected secondary record address. |

The first 32-bit word addressed by the primary handle supplies the primary record-array base. Each selected record contains two consecutive 32-bit words, occupying eight bytes.

A secondary query exposes a 64-bit result. Its low 32 bits control continuation; its high 32 bits supply the selector passed to secondary classification. The record address itself comes from the context, not from that selector.

### Preconditions and validity

Every address actually dereferenced must support the indicated access. This includes the context, primary handle, primary array base, associated object, and secondary record address on paths using them.

The function provides no visible validation of those addresses, allocation bounds, or the caller’s decision pointer. A null decision pointer is not rejected locally, but whether a dependency accepts it is unknown.

Unsigned classification-address arithmetic has an established modulo result, described below. That arithmetic does not establish that the resulting address is valid.

## Behavior

### Initialization and phase ordering

The retained status begins at zero. Local decision storage begins with the initial-decision argument.

The primary phase runs before the secondary phase. A normal exit from the primary loop enters secondary processing; a nonzero primary status returns earlier after maintenance.

The supplied body never uses the initial-decision value before overwriting it. If primary processing never occurs, the local decision address is not forwarded. No direct influence of that initial value on visible behavior is established.

### Primary eligibility and bounds

Each primary iteration starts by reading the primary handle.

1. A zero handle ends the primary phase.
2. A nonzero handle permits a call to F-6e45b75056e5 with no explicit argument visible.
3. A zero result from that call ends the primary phase.
4. Otherwise, F-6e45b75056e5 is called with the primary handle read for that call.
5. After this query, the function captures the position as an unsigned 32-bit value.
6. If the query’s unsigned 32-bit result is less than or equal to that captured position, the primary phase ends.

The bounds exit does not itself reset the position, increment the pass counter, or run post-record maintenance.

The argument-less and explicit-handle calls are distinct observed call forms. Their equivalence, implicit arguments, and relationship to a particular source are not established.

### Primary classification selection: unsigned arithmetic

When the bound exceeds the captured position, the function reads the primary handle and obtains the array base from the first word it addresses.

The classification address is formed using the **captured unsigned 32-bit position**:

- Multiplication of the position by eight is unsigned 32-bit arithmetic, modulo \(2^{32}\).
- Addition of the 32-bit base is also unsigned 32-bit arithmetic, modulo \(2^{32}\).

Thus, classification selection has an established wrapped address bit pattern. It is not an unbounded mathematical array offset, and there is no visible checked-address operation.

The two consecutive 32-bit words at the selected address are supplied to F-389707b2b41e with the context and captured position. This call has four explicit arguments.

Both record words must be read before the call. The supplied representation does not establish a relative evaluation order between those argument reads.

The classification result is treated as a 32-bit word. After obtaining it, the function resets local decision storage to zero, then chooses a zero-classification or nonzero-classification path.

### Primary zero-classification path

A zero classification causes the function to:

- Set local decision storage to exactly one.
- Request primary removal through F-8f6b245a0a84.
- Leave the retained status unchanged.
- Perform no direct position increment on this path.

Removal uses freshly read context state rather than the captured classification position and base. Its address calculation has different arithmetic semantics, specified below.

### Primary nonzero-classification path

A nonzero classification causes the function to replace its local decision pointer with the address of local decision storage. This replacement persists for subsequent iterations and secondary processing.

It then calls F-28ddfa58f25b with:

- The context.
- The classification result.
- The current primary pass-counter word.
- The word at offset `+0x3c` in the associated object reached through context offset `+0x04`.
- The local decision-storage address.

The returned 32-bit status replaces the retained status. The function then reads the decision word.

Only the low eight bits determine removal:

- Nonzero low byte: request primary removal.
- Zero low byte: increment the context position instead.

The full decision word is retained on the removal path; it is not narrowed to eight bits. The low-byte test only chooses the branch.

A decision of `0x00000100` selects retention, while `0x00000101` selects removal. Either choice occurs before the retained status is checked.

### Primary removal selection: signed arithmetic

Both primary removal paths reread the primary handle, the base it addresses, and the context position after classification and any primary processing.

The removal address is formed differently from the classification address:

- The reread position is interpreted as a signed 32-bit integer.
- Its multiplication by eight is signed arithmetic in the supplied representation.
- Addition to the signed base value is also represented as signed arithmetic.

The source does **not** establish that overflow in these signed operations has the same modulo-\(2^{32}\) behavior as classification selection. Signed-overflow behavior remains unresolved.

Where all signed intermediate results are representable, the stated signed calculation determines the removal address. Where they are not, this contract does not assign a wrapped result.

F-8f6b245a0a84 receives the current primary handle and that recomputed address. Dependency-induced changes can make the removal address differ from the address classified earlier. Even without such changes, the arithmetic distinction must not be discarded.

### Primary maintenance and status return

After removal or the retention increment, the function calls F-6e45b75056e5 with the current primary handle.

If this query returns zero, it rereads the handle:

- If the handle is nonzero, it calls F-039b80c3dfb5 and then F-feee9156a257, both without explicit arguments.
- F-feee9156a257 is marked nonreturning. Under that annotation, normal execution does not reach the later clearing writes or return check.
- If the reread handle is zero, the function writes zero to the primary handle, then the position, then the pass counter.

The clearing writes are therefore conditional, not unconditional empty-source cleanup.

If the maintenance query returns nonzero, the function calls F-6e45b75056e5 again without an explicit argument. Its result is compared as unsigned with the current unsigned position. If the result is less than or equal to that position, the function:

1. Resets the position to zero.
2. Increments the pass counter.

The position increment used for retention and the pass-counter increment are represented as signed operations on 32-bit fields. No overflow handling is visible; modulo semantics for these increments are not established by this representation.

After maintenance, a nonzero retained status is returned. Otherwise, primary eligibility is checked again.

### Secondary processing

Each secondary iteration calls F-6e45b75056e5 with the address of the embedded object at context offset `+0x3c`.

If the low 32 bits of the 64-bit result are zero, the function returns the retained status immediately. It does not read a secondary record or request removal. A nonzero high half cannot override this termination condition.

Otherwise, the function obtains the record address from the first word of the embedded object and reads its two consecutive 32-bit words. F-389707b2b41e receives five explicit arguments:

- Context.
- High-half selector.
- First record word.
- Second record word.
- Current local decision pointer.

The selector preserves the high-half 32-bit pattern; its application interpretation is unknown. The decision pointer is the caller’s original pointer unless a primary nonzero-classification path replaced it. Once replaced, it points to local decision storage, whose contents may have changed in later primary iterations.

A zero classification leaves the retained status unchanged and skips secondary processing. A nonzero classification is passed with the context to F-32ecbbf59f8c, whose result replaces the retained status.

The function then calls F-8f6b245a0a84 with the embedded object address and the record address reread from context offset `+0x3c`. This removal request occurs for both classification outcomes and before returning a nonzero processing status.

The reread removal address need not equal the classified address if intervening dependencies changed the context.

After removal, a zero retained status repeats the secondary loop; a nonzero status is returned.

## Side effects

Direct context writes are limited to the primary handle, position, and pass-counter fields:

- Position increment on retention.
- Position reset followed by counter increment on wrap.
- Ordered handle, position, and counter clearing on the reachable clearing path.

The function also changes local decision storage and its local decision pointer. It does not visibly write record contents or directly write through the caller’s original decision pointer. Dependencies receiving that pointer may write through it.

No allocation or deallocation is directly visible. A removal request does not establish freeing, destruction, compaction, or ownership transfer.

Dependencies may change reachable state. Post-call field reads are behaviorally significant; this contract does not assume globals, context fields, handles, bases, or record addresses remain unchanged.

The local decision address is exposed to dependencies. Valid use is limited by the lifetime of that storage; permission to retain or use it after return is not established.

There is no visible iteration limit or progress guard. Termination depends on query results, statuses, dependency effects, and the exceptional path.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume dependencies preserve relevant context state and all accessed addresses are valid.

1. **No eligible records.** A zero primary handle followed by a secondary query with a zero low half produces a zero return without classification or removal.

2. **Position at the bound.** If primary eligibility succeeds but the explicit query equals the captured unsigned position, primary classification and maintenance are skipped. Secondary processing begins without a direct counter increment.

3. **Unsigned classification wrap.** With captured position `0x20000000`, an unsigned bound greater than that value, and base `0x00001000`, multiplication by eight wraps to zero. Classification reads the record at address `0x00001000`. This example requires that address to be valid; it does not authorize the analogous signed removal calculation.

4. **Signed removal remains unresolved.** Under the preceding position and base, if classification returns zero and the position remains unchanged, removal attempts signed multiplication of `536870912` by eight. That result exceeds the signed 32-bit range. The supplied representation does not establish which removal address or overflow outcome follows.

5. **Fresh removal selection without overflow.** Classification uses position two and base `0x1000`, selecting address `0x1010`. If classification changes the position to three and returns zero, removal uses the reread position and selects `0x1018`, assuming the base is unchanged and signed arithmetic remains representable.

6. **Zero primary classification.** An eligible record with zero classification causes decision storage to become one and requests removal. There is no direct position increment before maintenance.

7. **High decision bits do not select removal.** Primary processing writes `0x00000100` and returns zero. The function increments the position rather than requesting removal, provided the signed increment is representable.

8. **Removal precedes error return.** Primary processing writes `0x00000001` and returns a nonzero status. Removal and maintenance occur before that status is returned, if maintenance reaches the return check.

9. **Exceptional maintenance blocks normal return.** A zero maintenance result with a nonzero reread handle invokes the two exceptional-path dependencies. Under the nonreturning annotation, no normal status return follows.

10. **Secondary zero classification still removes.** A nonzero secondary-query low half and zero classification skip F-32ecbbf59f8c but still request removal before another query.

11. **Secondary processing error still removes.** A nonzero secondary classification followed by a nonzero processing status causes removal before that status is returned.

12. **Pointer replacement persists.** If any primary nonzero-classification path executes and control later enters secondary processing, secondary classification receives local decision storage rather than the caller’s original pointer.

13. **High-half-only result terminates.** A secondary query with a nonzero high half and zero low half returns without reading or classifying a record.
