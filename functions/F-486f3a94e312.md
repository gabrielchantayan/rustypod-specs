# F-486f3a94e312

## Purpose

F-486f3a94e312 specifies an operation whose visible behavior is an ordered sequence of indirect calls, byte accesses, and 32-bit memory accesses. It transforms input words and external results, writes values to calculated addresses, extracts bit fields, and supplies intermediate values to external operations.

No application-level purpose is established. Calculated addresses are not proven to identify ordinary objects. External results are not proven to be allocation handles, and external calls are not proven to allocate, initialize, commit, or release resources.

The supplied representation reports invalid instruction data and terminates at a truncated control-flow boundary. This contract therefore describes the represented execution prefix, conditional on the recovered operations and their ordering being accurate. It does not establish normal completion or behavior beyond that boundary.

It then writes the incoming 8-bit value to address B + 17. This destination is derived from the byte’s numeric value, not from the original read address. Its range is decimal 17 through 272.

Only after that write does the call sequence begin:

1. F-D001 receives the first explicit input shifted left by two.
2. F-D002 through F-D004 execute with no represented arguments.
3. F-D005 executes with no represented arguments and supplies a 32-bit result.
4. F-D006 receives B, zero-extended to 32 bits, followed by that result shifted left by two.

## Acceptance examples

These are conditional static deductions, not executed tests. Each assumes that the relevant accesses and calls continue successfully and that the stated 32-bit arithmetic model applies.

1. **Initial byte-derived destination.** If B is 255, the initial byte write targets address 272. F-D006 later receives 255 as its first argument, even if a callee changes the original byte location.

2. **Fourth-input scaling.** If the fourth input is 3, P is 3072, and F-D008 receives 3072 twice. If H is 7, the following word write stores 3072 at address 48.

3. **Discarded high bits.** If the fourth input’s bit pattern is 0x00400000, shifting it left by ten has low-32-bit value zero. P and its associated arguments and stored value are therefore zero under the descriptive arithmetic model.

4. **Low-half extraction.** If L is 0xFFFFFFFF, the first low-half write targets 0xF0000014 and stores 0xFC000000. The later masked field write stores 0x000FFFFF.

5. **Store/read aliasing.** If F-D029 returns zero, S is zero. The wide-slot write stores zero at address 20, and both argument reads for F-D030 address 20. If no independent modification occurs, F-D030 receives three zero arguments. That result is not generalizable to nonzero selectors.

6. **Separate argument reads.** If the word at S + 20 changes between F-D030’s two represented reads, its first and third arguments may derive from different word values. The contract does not select which read occurs first.

7. **Selector-derived fields.** If J is 3, T is 12. F-D070’s first argument is 0x00030000, and its third argument’s low-32-bit value is 0xC0000000, independently of V.

8. **Distinct late destinations.** If the first late byte read returns 5 and the second returns 9, the respective byte writes target addresses 22 and 26. Reusing the first captured selector for the second write would not match the represented behavior.

9. **Byte truncation.** If Q is 0x12345678, the first late byte write stores 0xE0, and the second stores 0x23.

10. **Partial execution.** If the initial byte write succeeds but F-D001 cannot execute, that write has already occurred. The evidence supplies neither rollback nor a particular error code.
