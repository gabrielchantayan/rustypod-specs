# F-8750d65192c6

## Purpose

F-8750d65192c6 dispatches a numeric operation against a record obtained through a dependency. Depending on the operation, it writes a command word, repeatedly requests a status, or performs a bounded reconciliation sequence involving a reported quantity and fields in the record.

The established contract covers local control flow, dependency calls, memory accesses, arithmetic, and return construction. Terms such as “command,” “polling,” and “reconciliation” describe observable usage; they do not establish hardware semantics, external completion, or progress guarantees.

A successful return does not necessarily mean an external operation completed. Some operations return success immediately after writing a command. Where status observations occur, an additional observation can supersede an earlier favorable result.

| Target | Pointer-shaped argument referring to unsigned 32-bit words | Forwarded to dependencies and compared numerically with sentinels 5 and 6. This function never directly dereferences it. |

The target’s pointer-shaped representation does not establish that every accepted target is a dereferenceable address. In particular, the sentinel cases require separate treatment.

### Return value

The result is a packed 64-bit value:

- Bits 63–32 contain the original selector’s 32-bit representation.
- Bits 31–0 contain the status’s 32-bit representation.

It is not a signed status merely extended to 64 bits.

| Status | Low 32 bits | Established local meaning |

## Behavior

### Initial resolution

Every invocation, including one with an unsupported operation, performs resolution before dispatch:

1. Interpret the selector’s low 16 bits as a signed 16-bit index.
2. Use that index with a stride of 396 bytes relative to a global table base.
3. Read a 32-bit table value.
4. Call F-a0f78003cb6f with that value and the original target.
5. Retain the returned record pointer.

The signed index ranges from −32768 through 32767. Its multiplication by 396 fits within signed 32-bit arithmetic. This arithmetic fact does not establish that the resulting table address is valid; negative indices are not rejected locally.

There is no local check of the table value or returned record pointer. The record is not resolved again later.

### Direct command operations

Operations 1, 2, 4, 32, and 64 write their operation value to the command word and return status 0.

Operation 8 normally writes command 8 and returns status 0. When the target’s numeric value is 6, it first calls F-f34b0b1c59dc with the original selector and numeric second argument 7:

- A result exactly equal to 2 causes another call.
- The first result other than 2 ends the loop.
- Command 8 is then written, followed by a successful return.

This loop has no local bound or delay. Any result other than 2 permits the write; no particular success value is required.

### Shared status-wait sequence

Operations 16 and 112, and an internal phase of operation 128, use the same status-wait pattern:

- Write command 4.
- Repeatedly call F-f34b0b1c59dc with the original selector and original target.
- End the polling phase when a call returns 7 or when its counter, initially 10, is zero.
- Make one additional unconditional call with the same arguments.
- Use this additional call as the decisive status observation.

Each polling call occurs before the counter condition is evaluated. Consequently, the polling phase makes between 1 and 11 calls, and the additional call raises the total to between 2 and 12.

An earlier result of 7 does not establish success. The additional call must itself return 7. Conversely, a result of 7 from that final call is sufficient even after all 11 polling calls returned other values.

No delay, elapsed-time limit, or yielding mechanism is established.

### Operations 16 and 112

After the shared sequence:

- A decisive result other than 7 sets status −236.
- A decisive result of 7 leaves status 0.
- Command 16 is written in either case.

Operation 16 then returns. Operation 112 additionally writes command 96 before returning.

The direct command-write order for operation 112 is therefore 4, 16, 96. A failed decisive observation does not suppress either later write.

### Rejected operations

Unsupported operations, including operation 128 with any target other than numeric value 5, return status −243.

Resolution still occurs. After resolution, these paths perform no direct record read or write. This restriction says nothing about effects performed by F-a0f78003cb6f.

### Operation 128 with target 5

This path begins with status 0, a reconciliation-completed flag clear, a local-failure flag clear, and an outer counter of 50.

#### Outer observations

Every outer observation first calls F-ed6f8b88b705 with the original selector.

- If the result is zero, the outer loop stops without reading the record’s flag word for that observation.
- Otherwise, the flag word is read.

Following a nonzero result and flag read, the loop stops if:

- The low three flag bits are all clear;
- The local-failure flag is set; or
- The outer counter is zero.

The dependency call and conditionally required flag read occur before the local-failure and counter checks can stop the loop. A failure recorded in a body therefore does not cause an immediate return.

At most 50 outer bodies execute. With no earlier stopping condition, there are 51 outer observations before the separate final observation.

#### Reconciliation before completion

If reconciliation has not been marked complete, an outer body performs the shared status-wait sequence.

A decisive result other than 7 sets status −236 and the local-failure flag. It performs no packed-field update.

A decisive result of 7 causes another call to F-ed6f8b88b705. This call’s result is retained locally as an unsigned 32-bit quantity for the following comparison and potential update.

The function reads the packed word and compares its high 16 bits with that quantity.

#### Quantity greater than the observed high half

If the quantity exceeds the observed high half, the function reads the observation word at offset 0 and tests its low two bits.

If both bits are clear:

- Write command 8.
- Mark reconciliation complete.

If either bit is set:

- Write command 8.
- Perform the repeated-observation sequence described below.
- If that sequence’s final comparison is unequal, leave reconciliation incomplete and proceed toward the next outer iteration.
- If its final comparison is equal, set status −236 and the local-failure flag.

Neither outcome in this greater-quantity branch updates the packed word or clears the observation word’s low two bits.

#### Quantity no greater than the observed high half

Entry into this branch establishes:

**The retained unsigned quantity is between 0 and 65535 inclusive.**

The first comparison admits the branch only when the quantity is no greater than a value obtained from a 16-bit high half. That high half cannot exceed 65535. Subsequent record changes cannot change the already retained quantity or invalidate this established range.

The accesses and update then occur in this order:

1. Read the packed word again and retain its low 16 bits as the provisional low half.
2. Read the packed word again and compare its newly observed high half with the retained quantity.
3. If the quantity is strictly smaller, read the packed word again and replace the provisional low half with that word masked by 0x0000FFCF.
4. Write the packed word formed from the provisional low half and the retained quantity shifted left by 16 bits.
5. Read the observation word, clear its low two bits, and write it back.
6. Write command 8.
7. Mark reconciliation complete.

The shift uses unsigned 32-bit arithmetic. Because the quantity is already established to be at most 65535, shifting it left by 16 does not discard any nonzero quantity bits. The provisional low half contains no bits above bit 15, so combining the halves does not overlap their bit positions.

For a stable packed word, equality preserves its low 16 bits; a decrease additionally clears bits 4 and 5. With changing contents, the separate reads remain significant: the initial branch comparison, provisional low-half extraction, second comparison, and conditional masked read need not observe the same word.

Such changes can affect the selected low half. They cannot admit a quantity greater than 65535 into this update branch.

#### Repeated-observation sequence

The greater-quantity case with low observation bits set compares two separate reads of the observation word.

A counter begins at 90. The sequence continues while a pair compares equal and the counter is nonzero, decrementing the counter after each continuing comparison.

The loop condition performs between 1 and 91 pairs of reads. Once it stops, another pair of reads is performed for a separate inequality test.

Only that final pair determines the outcome:

- Unequal: leave reconciliation incomplete and proceed toward the next outer iteration.
- Equal: record status −236 and local failure.

An unequal pair that ended the loop does not guarantee an unequal final pair. If the word remains stable throughout, the final pair is equal and failure is recorded.

There is no dependency call or established delay inside this sequence. The two reads within each comparison are distinct observations, but the supplied representation does not establish a source-language left-operand versus right-operand evaluation order.

#### Later bodies and termination

Every executed outer body decrements the outer counter, including a body that records failure or leaves reconciliation incomplete after an unequal final pair.

Once reconciliation is complete, later bodies skip the status-wait and reconciliation work. They still consume the outer counter and are preceded by outer observations.

Counter exhaustion alone does not set an error.

#### Final observation

After the outer loop stops, F-ed6f8b88b705 is always called once more.

If this final result is nonzero, the flag word is read:

- Low three bits clear: set status −235.
- Any low three bits set: set status −236.

This classification overrides any earlier status. No final command 16 is written on either nonzero-result path.

If the final result is zero:

- Preserve an existing nonzero status and return without another command write.
- Otherwise, write command 16 and return status 0.

A final zero result therefore does not erase an earlier failure. Conversely, outer-counter exhaustion can still be followed by a final zero result, command 16, and success.

## Side effects

- The command word at offset 16;

No direct write through the target, allocation, release, or ownership transfer is shown. Dependency effects remain unknown.

The resolved pointer is retained across calls. This does not establish that dependencies preserve the record, table base, or other global state, or that they acquire or release memory.

## Acceptance examples

These are conditional static acceptance criteria, not observed executions. They assume valid accesses, returning dependencies, and the stated observations.

1. **Direct operation:** Operation 32 performs resolution, writes command 32, and returns status 0 with the original selector in the upper 32 bits.

2. **Rejection after resolution:** Operation 3 still performs the table read and resolution call. It then returns −243 without direct record access.

3. **Wrong special target:** Operation 128 with target 6 returns −243 after resolution. It does not enter operation 8’s special polling loop.

4. **Special polling:** Operation 8 with target 6 and dependency results 2, 2, 9 makes three calls using numeric second argument 7, then writes command 8 and succeeds. An endless sequence of 2 prevents the write and return.

5. **Earlier favorable status is insufficient:** Operation 16 with first polling result 7 and decisive result 3 writes commands 4 and 16 and returns −236.

6. **Exhaustion followed by success:** Eleven polling results other than 7 followed by decisive result 7 produce success for operation 16 after twelve status calls.

7. **Failure preserves command order:** Operation 112 with a failed decisive observation writes commands 4, 16, and 96 in order and returns −236.

8. **Stable decrease:** If operation 128 reaches the update with packed word 0x000AFFFF stable across its reads and quantity 9, the packed word becomes 0x0009FFCF. The observation word’s low two bits are then cleared before command 8.

9. **Upper update boundary:** With quantity 65535 and a stable packed word 0xFFFF1234, the update writes 0xFFFF1234. The shifted quantity fits entirely within the upper 16 bits.

10. **Quantity outside the update range:** Quantity 65536 exceeds every possible observed 16-bit high half. It takes the greater-quantity branch, regardless of later packed-word changes. If the observation word’s low two bits are clear, command 8 is written and reconciliation completes without a packed-word update.

11. **Final classification overrides failure:** A final nonzero operation-128 result followed by flags with low three bits clear produces −235, even if reconciliation previously recorded −236.

12. **Immediate zero observations:** If operation 128’s first outer observation and separate final observation both return zero, reconciliation is skipped, command 16 is written, and status 0 is returned.

## Evidence

The established behavior derives solely from static examination of the supplied function representation and opaque dependency mapping: branch conditions, access widths and offsets, masks, call order, write order, counter bounds, and return construction.

The packed-update range follows directly from the unsigned entry comparison: a retained quantity no greater than an observed 16-bit high half is necessarily at most 65535. Later record reads can alter update decisions and low-half contents, but not that retained quantity.

Dependency implementations and runtime observations were not supplied. No runtime tests have been performed. The acceptance examples describe conditional consequences of the static evidence, not test results.
