# F-974e93391f25

## Purpose

F-974e93391f25 performs discriminator-dependent dispatch for a caller-supplied record, then invokes a sequence of indirect operations obtained from a globally selected object.

The established behavior has three stages:

1. Conditionally call one of two direct dependencies using the record’s second 32-bit word.
2. Obtain an object reference from global state and conditionally invoke an operation at byte offset 48.
3. Invoke the operation at byte offset 24 unconditionally, then inspect offset 48 again and conditionally invoke its current target with a different argument list.

The two offset-48 invocations are separate decisions. Their targets need not be identical, and either invocation can occur without the other if intervening activity changes the relevant slot.

The operation’s application-level purpose is unknown. In particular, the supplied evidence does not establish that the record is being destroyed, released, registered, or transferred. Such interpretations are documented_only.

## Behavior

### Discriminator-dependent dispatch

The function first reads the record’s first 32-bit word.

If that read equals 1:

- It reads the record’s second 32-bit word.
- It invokes F-fa5325efe259 with that value as the sole shown argument.
- It does not perform the discriminator comparison against 2.

If the first discriminator read does not equal 1, the supplied representation performs another read of the first word to test equality with 2.

If that second read equals 2:

- It reads the record’s second 32-bit word.
- It invokes F-90acc239ba9d with that value as the sole shown argument.

Otherwise, neither direct dependency is invoked.

These branches are mutually exclusive within this invocation. At most one direct dependency is called.

For stable record contents, discriminator 1 selects F-fa5325efe259, discriminator 2 selects F-90acc239ba9d, and every other value selects neither. If external activity can change the discriminator between its reads, dispatch follows the values actually observed. The evidence does not establish synchronization or promise a single discriminator snapshot.

No null check precedes the first record access. No validity check is performed on the second word before forwarding it. Its interpretation belongs to the selected dependency; it is not established here as a pointer, handle, allocation, or scalar identifier.

### Global object selection

After the selected direct dependency returns, or immediately after dispatch if neither dependency was selected, the function reads the global object reference and saves that value for later use.

It then reads the global object reference again to locate the initial callable entry at byte offset 48.

The distinction matters:

- The saved object reference determines the later offset-24 call and the final offset-48 lookup.
- The second global reference read determines the initial offset-48 lookup.
- A selected direct dependency runs before both global reference reads, so any global changes it makes can affect object selection.
- Later changes to the global reference do not replace the saved reference used for the final two lookups.

In ordinary execution without an intervening change, the two global reads identify the same object. Equality is not established as an unconditional invariant.

### Initial optional invocation

The function reads the callable entry at offset 48 through the second global reference value.

If the entry is null, it skips this invocation.

If the entry is non-null, it invokes that captured target with these five shown arguments, in order:

1. The original input record pointer.
2. Zero.
3. The captured target itself.
4. The fourth explicit input.
5. The incoming register-derived value whose meaning is unknown.

The third argument is the same target value selected for this invocation. The function does not visibly reload the slot to construct that argument.

No return value from this invocation is explicitly used. Its memory and global effects are not constrained by the supplied evidence. In particular, it may change the saved object’s callable entries; preservation must not be assumed.

### Required invocation

After the initial optional invocation has returned or been skipped, the function reads the callable entry at byte offset 24 of the saved object.

It invokes that target with the original input record pointer as the sole shown argument.

There is no null check on this entry. A non-null check also does not otherwise establish target validity; successful execution requires a callable target compatible with the invocation.

Because this lookup occurs after the initial optional invocation, a change that invocation makes to the saved object’s offset-24 entry affects the selected target.

The required invocation’s explicit result, if any exists at the machine level, is not used by the visible behavior.

### Final optional invocation

After the required invocation returns, the function rereads the entry at byte offset 48 of the saved object.

If that entry is null, the function returns without a final invocation.

If it is non-null, the function invokes its current target with these two shown arguments, in order:

1. Zero.
2. One.

The final invocation does not explicitly receive the record pointer, the fourth input, the earlier target value, or the register-derived value as additional arguments. The different argument lists must remain distinct in the contract; missing arguments must not be invented.

The final target is obtained from a fresh slot read. It may differ from the initial target because the initial lookup may have used a different object, because a dependency changed the saved object, or both.

The supplied representation models this final transfer as a call followed by return. Whether its machine-level form is an ordinary call or a tail transfer is documented_only; the established behavioral requirement is the conditional transfer to the selected target with the two shown arguments.

## Side effects

The function explicitly reads the input record, the global object reference, and callable entries. It contains no explicit write to the record, the global reference, or the object.

This does not make the operation side-effect-free. Every invoked dependency may have effects not described by this excerpt.

Observable call order, when all stages occur and return normally, is:

1. One selected direct dependency.
2. The initial offset-48 target.
3. The saved object’s offset-24 target.
4. The saved object’s freshly selected offset-48 target.

The first, second, and fourth calls are conditional. The third is unconditional once execution reaches it.

There is no explicit allocation, deallocation, reference-count adjustment, ownership annotation, error reporting, or rollback. Passing a record or payload value to a dependency does not establish transfer of ownership. Conversely, the absence of an explicit release in this function does not establish that dependencies retain the underlying storage.

For normal completion, the saved object must remain usable through its later slot reads, or dependency effects must otherwise leave those accesses valid. The function does not refresh the saved reference after a dependency changes the global selector.

If a dependency does not return normally, the subsequent stages are not established to occur. No local recovery path is visible.

- The final optional lookup still uses the saved object.
