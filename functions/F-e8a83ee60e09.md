# F-e8a83ee60e09

## Purpose

F-e8a83ee60e09 writes a compact, signed numeric field into caller-supplied storage. The field consists of:

- One caller-selected marker byte.
- A sign byte: `+` for a nonnegative input, `-` for a negative input.
- Two numeric-result bytes, or three when the adjusted numeric value is greater than 99.

The function returns an updated offset, not a pointer or a byte count.

**Established behavior:** the marker and sign are written directly. Numeric bytes are constructed from results supplied by F-870c4fcf7295, with an addition of 48 before byte storage.

**Inferred intent:** F-870c4fcf7295 supplies a quotient and remainder, allowing this function to emit a zero-padded decimal magnitude. This interpretation explains the divisors 100 and 10, but the dependency’s implementation and full calling convention are not supplied. Decimal-output examples below are conditional on that interpretation.

This is not an unrestricted integer-to-decimal conversion. It has only two numeric-output positions for values up to 99 and three positions for larger values. It contains no loop to accommodate additional digits.

## Behavior

### Field layout

| Relative position | Two-numeric-position path | Three-numeric-position path |

There is no explicit string terminator. The returned offset identifies the position immediately after this function’s explicit output region.

The numeric-path selection is based on the adjusted numeric value, not the signed input before adjustment. For ordinary representable negative values, that adjusted value is the positive magnitude.

### Observable operation order

The function first stores the marker at destination address plus starting offset. This occurs before sign adjustment and before any dependency call.

It then determines the sign:

- A negative input selects byte value 45, conventionally `-`, and is negated for subsequent numeric processing.
- A nonnegative input selects byte value 43, conventionally `+`, and is retained.

The selected sign is stored at the next byte position. Zero therefore receives `+`.

After these two stores, the function tests whether the adjusted numeric value is greater than 99.

#### Adjusted value at most 99

The function invokes F-870c4fcf7295 once, with the adjusted numeric value and the integer 10.

Two result channels from that invocation are consumed:

1. The primary result is reduced to a character-sized value, increased by 48, and stored at offset *s* + 2.
2. A secondary result is consumed in character-sized form, increased by 48, and stored at offset *s* + 3.

The function then returns *s* + 4.

The supplied representation does not establish how the secondary result is formally returned. Its use is visible, but its ABI-level guarantee is not.

#### Adjusted value greater than 99

The function first invokes F-870c4fcf7295 with the adjusted numeric value and the integer 100.

The primary result is reduced to a character-sized value, increased by 48, and stored at offset *s* + 2. A secondary result from this invocation becomes the numeric input for the next dependency call. This secondary value is represented as integer-sized, rather than merely character-sized.

The function then invokes F-870c4fcf7295 with that secondary value and the integer 10.

From this second invocation:

1. The character-sized primary result, increased by 48, is stored at offset *s* + 3.
2. The character-sized secondary result, increased by 48, is stored at offset *s* + 4.

The function returns *s* + 5.

The leading numeric byte is therefore stored between the two dependency calls. Any dependency side effects must be considered in that order.

### Decimal interpretation and limits

If F-870c4fcf7295 supplies integer quotient and remainder, the two-position path emits decimal tens and units, including a leading zero for magnitudes below 10.

Under the same assumption, the three-position path emits:

- The quotient on division by 100, converted to one output byte after adding 48.
- Two decimal positions derived from the remainder.

The first of these is not constrained to a decimal digit. For example, a magnitude of 1000 would produce a quotient of 10 for the leading position. Adding 48 produces byte value 58, conventionally `:`, rather than the two characters `10`.

No digit-range validation, clamping, truncation policy for oversized magnitudes, or error indication is visible.
