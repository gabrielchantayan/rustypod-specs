# F-29710791642d

## Purpose

F-29710791642d is represented as an unconditional, stateful execution loop. It interleaves indirect dependency calls with byte and 32-bit memory accesses, derives subsequent addresses and arguments from dependency results, and carries selected results into the next iteration.

The supplied representation establishes no application-level purpose. Interpreting the accesses as device registers, object fields, message descriptors, or a particular protocol would require additional evidence.

No normal return, successful completion condition, or explicit error result is shown. If execution continues through all dependency calls and memory accesses, it repeats indefinitely.

## Interface

### Explicit inputs

The apparent interface has four 32-bit inputs, designated here as:

- **Input A**
- **Input B**
- **Input C**
- **Input D**

These names describe interface positions, not recovered semantic roles.

A and B are passed to the first dependency call of an iteration. C contributes a shifted argument partway through the iteration and is later replaced by a dependency result. D initially determines a word-write address and a shifted dependency argument; it too is replaced before the next iteration.

### Additional entry state

The represented behavior also depends on state outside those four inputs:

- An inherited **address seed**, used in the initial byte read and in another address calculation during the first iteration.
- An inherited **byte value**, written once before the loop.
- An inherited **control address**, used to select the first indirect call target.
- An unnamed **global 32-bit value**, read late in every iteration.
- An additional **32-bit call-result register value**, passed as an argument at one intermediate point without an ordinary explicit assignment.

Consequently, the apparent four-input signature is not a complete executable contract. A caller would also need the applicable entry-state and calling-convention requirements.

### Outputs and memory requirements

There is no explicit return value. Observable effects consist of dependency calls, direct memory accesses, and loop-carried state changes.

All computed addresses must support the corresponding access if execution is to continue normally. This includes low numerical addresses: several destinations are formed by adding a small constant directly to a zero-extended byte.

No ownership transfer, allocation, release, reference-count operation, or buffer-lifetime guarantee is established. Passing a word to a dependency does not establish whether it is a pointer or whether that dependency retains or releases anything.

## Behavior

### Width and notation

The following descriptions use 8-bit bytes, 32-bit words, and two-component results consisting of a low 32-bit component and a high 32-bit component.

For compactness:

- **Sₙ(x)** denotes the low 32 bits of x shifted left by n positions.
- **Mₖ(x)** denotes the low 32 bits of x multiplied by k.
- **E(x)** denotes the logical right shift by 20 of x masked with `0x3fffffff`.
- A byte store retains only the low 8 bits of its value.
- A byte used in address formation is zero-extended.
- Address arithmetic below uses the apparent 32-bit address model.

This is a width-aware reading of the supplied representation, not a claim that signed source-language overflow or signed left shifts are defined. Exact executable arithmetic, alignment requirements, and fault behavior require target-level confirmation.

E(x) has a range of 0–1023. Storing it in a byte discards its upper two bits. By contrast, a word address formed as E(x) + `0x14` uses the entire extracted value.

### Dependency notation

The opaque identifiers **F-D01.1** through **F-D34.5**, as applicable below, identify dependency call sites for this contract. They do not assert resolved function identities.

A **five-call sequence F-Dnn** means calls to F-Dnn.1 through F-Dnn.5, in that order. Unless a stated exception applies:

- The listed arguments belong to the first call.
- The remaining four calls have no explicit arguments in the representation.
- A stated sequence result is the result of the fifth call.

A **two-call sequence** analogously identifies F-Dnn.1 and F-Dnn.2.

“No explicit arguments” does not establish that a call has no implicit register or global inputs. Every dependency call remains an observable boundary. In particular, calls between two memory reads may change the memory being read.

### Entry operation

Before entering the loop:

1. Read one byte at address **address seed + 1**.
2. Write the inherited byte value at address **the byte just read + `0x11`**.

This entry write occurs only once in the represented execution. It is not repeated at the loop back edge.

## Side effects

Direct effects include:

- Ordered 8-bit reads and writes.
- Ordered 32-bit reads and writes.
- A late read of an unnamed global word.
- Indirect calls whose internal effects are unknown.
- Replacement of A, B, C, D, the address seed, and control-address state.

There are no explicit bounds checks, null checks, alignment checks, dependency-error checks, retries, rollback operations, or memory barriers.

Earlier writes are not shown being undone if a subsequent access faults or a dependency does not return. No transactional or atomic multi-access guarantee is established.

Apparent repeated stores must not be collapsed: they are separated by calls and, frequently, fresh selector-byte reads. Likewise, the global read must not be moved across F-D31; its retained value is used after that sequence.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Entry byte selection.** If address seed + 1 contains `0x7f`, the entry operation writes the inherited byte at `0x90`. It does not dereference a pointer stored in a word at address seed + 1.

2. **Initial word scaling.** If Result A is 3 and D is 2, Word A is 12 and its first word-store address is `0x2014`, assuming the stated arithmetic and writable memory.

3. **Byte truncation.** If Word A is `0x3ff00000`, E(Word A) is `0x3ff`; the corresponding byte store writes `0xff`.

4. **Full extraction for a word read.** If Result O is `0x3ff00000`, the Loaded word read is at `0x413`. The extraction is not truncated to a byte before forming this address.

5. **Live selector changes.** If a dependency changes Byte-table base + 1 between two reads, subsequent byte stores follow the newly read selector. Reusing an earlier selector would violate the represented order.

6. **Cached selector exception.** If Cached byte is 9 and F-D30 later changes High-bit base + 1 to 12, the subsequent word store still targets `0x1d`, not `0x20`.

7. **High-bit-only value.** S₃₁(Result N) is zero for an even Result N and `0x80000000` for an odd Result N, under 32-bit truncation.

8. **Global snapshot.** A change to the global during F-D31 does not change the retained Global snapshot used afterward.

9. **Loop-carried inputs.** On completing an iteration, the next F-D01.1 receives equal A and B values. The entry byte write is not repeated.

10. **Failure to progress.** If any dependency does not return, later operations are not reached through the represented sequential path. No recovery path is established.
