# F-65c6e5a133ae

## Purpose

F-65c6e5a133ae conditionally updates two referenced objects when either of two sampled 32-bit values differs from its cached counterpart.

On the update path, it:

- Derives geometry from the first sample and two stored dimensions.
- Publishes both samples into cache fields.
- Requests a geometry update for one referenced object.
- Assigns complementary values in the range 0–255 to two referenced objects, with their assignment selected by a byte-valued flag.
- Performs two final association operations using additional stored references.

If both samples match their caches, none of those dependency calls or direct writes occurs. Every normally completed invocation returns the 32-bit value 1, including an invocation that skips the update.

Geometry, complementary values, and association are descriptive labels for the visible argument patterns. Their downstream meanings are not established by the supplied material.

## Interface

### Input and result

The function accepts one 32-bit value used as the address of a mutable state object. The supplied representation uses a 32-bit address and integer model; no portable 64-bit interface is established.

The result is a 32-bit value equal to 1 on every visible normal return. It does not distinguish “updated” from “unchanged,” and no dependency result is propagated as a status.

## Behavior

### Sampling and change detection

The function first reads the reference at `0x44`, then obtains the first sample from offset `0x04` of that referenced object. It next reads the reference at `0x48` and obtains the second sample in the same manner.

Both sample reads precede the cache comparison. Consequently, matching the first cache does not avoid reading the second sample, and an invalid second sample reference is not protected by an otherwise unchanged state.

The first sample is compared with the 32-bit cache at `0x4c`.

- If they differ, the function takes the update path without reading the cache at `0x50` for change detection.
- If they match, the function reads `0x50` and compares it with the second sample.
- Only when both comparisons match does the function skip the update.

Equality is exact 32-bit equality. It is not based on rounded geometry or on the eventual 8-bit-range complementary value. Different raw samples that produce identical derived values still trigger an update.

A skipped update makes no explicit writes and calls no dependencies.

### Derived geometry

The following names describe values, not source identifiers:

- **First sample** and **second sample** are the already-read samples.
- **Dimension A** is the 32-bit value read from `0x2c`.
- **Dimension B** is the 32-bit value read from `0x28`.
- **Rounded extent** is the first sample plus `0x7fff`, followed by a signed right shift of 16 bits.
- **Computed extent** is the 32-bit result of F-d7be9cfb4000.

On the update path, Dimension A is read before Dimension B. The rounded extent and the product of rounded extent with Dimension A are calculated for the arithmetic call:

| Argument position | Value |
|---|---|
| 1 | Rounded extent multiplied by Dimension A |
| 2 | Dimension B |

F-d7be9cfb4000 is called before either cache is written. Its arithmetic meaning is unknown. In particular, the visible call does not establish division, scaling, saturation, or protection against a zero second argument.

The samples, dimensions, and rounded extent used later are the values already obtained. They are not reloaded after this dependency returns.

### Cache publication

After F-d7be9cfb4000 returns, the function writes:

1. The second sample to `0x50`.
2. The first sample to `0x4c`.

This order is observable if the state is inspected through aliasing, instrumentation, or concurrent access. There is no visible atomic pair update.

Both stores precede the geometry and complementary-value calls. Thus, the caches record the sampled inputs before the remaining work has completed. No rollback is visible if a subsequent dependency does not complete normally.

### Geometry request

The function derives two offsets:

- **Offset A:** the logical right shift by one bit of the 32-bit unsigned interpretation of Dimension A minus computed extent.
- **Offset B:** the logical right shift by one bit of the 32-bit unsigned interpretation of Dimension B minus rounded extent.

These are unsigned shifts. A negative difference does not become a negative half-offset; its 32-bit representation becomes a large nonnegative argument.

The function then reads the reference at `0x24` and calls F-a05963f65233 with nine arguments:

| Position | Value |
|---|---|
| 1 | Current reference at `0x24` |
| 2 | 0 |
| 3 | 0 |
| 4 | Offset A |
| 5 | Offset B |
| 6 | Previously read Dimension B |
| 7 | Previously read Dimension A |
| 8 | Rounded extent |
| 9 | Computed extent |

The reference is read after F-d7be9cfb4000 returns and after cache publication. It is not an entry-time snapshot.

The argument pattern suggests centered placement or cropping, but no such interpretation is required by the established behavior.

### Complementary-value assignment

A base value is derived from the second sample:

\[
V = \bigl((\text{second sample} + \mathtt{0x7fff}) \mathbin{\&} \mathtt{0x00ffffff}\bigr) \gg 16
\]

The addition is unsigned 32-bit addition; the shift is logical. The mask means \(V\) is always between 0 and 255 inclusive. This is not a clamping operation.

After the geometry call returns, the function reads the byte at `0x3c`.

If the byte is zero:

1. It reads the reference at `0x20` and calls F-460b2abbbbbe with that reference and \(V\).
2. After that call returns, it reads the reference at `0x24`.
3. It calls F-460b2abbbbbe with the latter reference and \(255 - V\).

If the byte is nonzero:

1. It reads the reference at `0x20` and calls F-460b2abbbbbe with that reference and \(255 - V\).
2. After that call returns, it reads the reference at `0x24`.
3. It calls F-460b2abbbbbe with the latter reference and \(V\).

All nonzero flag values select the same branch. The selected branch is not reconsidered after the first assignment call, even if that call changes the flag.

The second target reference is read after the first assignment call. A dependency capable of mutating the state can therefore affect that target. Conversely, the base value remains derived from the original second sample; it is not resampled.

### Final association calls and return

After both complementary-value calls finish, the function performs these calls in order:

1. F-1d891874186d with the then-current fields at `0x20` and `0x1c`.
2. F-1d891874186d with the then-current fields at `0x24` and `0x18`.

These references are reloaded for their respective calls. They are not guaranteed to match references used earlier. Changes made by the first association call can affect the fields read for the second.

The exact read order between the two argument fields within either call is not established by the supplied representation.

After the final call, the function returns 1. Dependency return values other than the arithmetic result are unused.

### Integer-width constraints

The calculations use 32-bit operands. No wider intermediate, range check, or saturation is shown.

The unsigned addition used to derive \(V\), its 24-bit mask, and both unsigned offset shifts have explicit unsigned behavior. The complement \(255 - V\) cannot underflow because \(V\) is within 0–255.

The rounded-extent calculation uses a signed shift, not unsigned extraction. For non-overflowing addition, its signed behavior differs from truncation toward zero for some negative values.

The supplied material does not independently settle signed-overflow behavior for:

- First sample plus `0x7fff`.
- Rounded extent multiplied by Dimension A.
- Signed dimension-minus-extent subtractions before conversion to unsigned.

No contract of arbitrary-precision arithmetic should be inferred. Exact overflow outcomes require instruction-level evidence or a separate platform contract.

## Side effects

The only explicit writes made directly by this function are the two cache stores. They occur only on the update path, with `0x50` written before `0x4c`.

The dependency call sequence on that path is:

1. F-d7be9cfb4000, once.
2. Cache publication.
3. F-a05963f65233, once.
4. F-460b2abbbbbe, twice.
5. F-1d891874186d, twice.

Dependencies may have additional side effects. Their effects on globals, referenced objects, ownership, or the enclosing state are unknown and must not be assumed absent.

The function does not create a transaction spanning these operations. Samples and dimensions are snapshots taken before the first dependency; several object references and the flag are read later. Reentrant or externally visible mutation can therefore produce a mixture of earlier numeric values and later references.

No locking, memory-ordering mechanism, explicit error reporting, or recovery action is visible.

## Acceptance examples

These examples are conditional consequences of the visible behavior. They have not been executed.

### Unchanged input

Given readable sample objects, a first sample equal to `0x4c`, and a second sample equal to `0x50`:

- Both samples are read.
- Both cache comparisons occur.
- No dependency is called.
- No explicit state write occurs.
- The normal return is 1.

### First sample changed

Given a first sample different from `0x4c`, with the second sample readable:

- The function enters the update path regardless of the value stored at `0x50`.
- It does not read `0x50` for change detection.
- Both cached samples are nevertheless written after the arithmetic dependency returns.

### Centered geometry with a stipulated arithmetic result

Suppose:

- First sample is `0x00020000`.
- Dimension A is 100.
- Dimension B is 10.
- F-d7be9cfb4000 returns 20.

Then rounded extent is 2, and the arithmetic dependency receives 200 and 10. Offset A is 40; Offset B is 4.

The geometry call receives the current `0x24` reference followed by:

\(0,\ 0,\ 40,\ 4,\ 10,\ 100,\ 2,\ 20\).

The stipulated return value does not imply what F-d7be9cfb4000 normally computes.

### Complementary assignment and flag selection

For a second sample of `0x00800000`, \(V = 128\).

- With a zero flag, the `0x20` target receives 128 and the subsequently read `0x24` target receives 127.
- With any nonzero flag, those numeric assignments are 127 and 128 respectively.

The first assignment always targets the reference read from `0x20`.

### Masking rather than saturation

For a second sample of `0x01000000`, \(V = 0\), not 255. The mask discards bits above bit 23 after the unsigned addition.

Thus, numerically increasing the second sample does not guarantee a monotonically increasing base value across all 32-bit inputs.

### Unsigned half-offset

If Dimension A is 10 and computed extent is 20, their difference is −10 without signed overflow. Its unsigned 32-bit representation is `0xfffffff6`; logical right shift by one produces `0x7ffffffb`.

That large value is passed as Offset A. The function does not substitute zero or a signed −5.

### Mutation between calls

If the first complementary-value dependency changes field `0x24`, the second complementary-value call uses the changed reference. If the geometry dependency changes the flag, the branch uses that changed flag.

These outcomes follow from read timing; they do not assert that either dependency actually performs such mutations.
