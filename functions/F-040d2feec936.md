# F-040d2feec936

## Purpose

F-040d2feec936 performs one of two operations selected by a byte in a caller-supplied object:

- A zero selector invokes an alternate sequence of dependency calls and virtual dispatches.
- A nonzero selector enters transition checks, followed by either embedded-state normalization or a completion sequence with conditional linked-list insertion.

“Completion,” “normalization,” “registration,” and “deadline” describe the visible structure, not an established application protocol.

This contract separates directly represented behavior from inferred intent and unresolved dependency behavior. It is based on static evidence only; no runtime tests have been performed.

## Interface

### Input and return value

The function receives one object pointer and returns a 32-bit unsigned value.

The representation uses 32-bit words and four-byte pointers. All object offsets below are byte offsets. There is no visible check for a null object, sufficient object size, valid dispatch tables, or valid dependency-returned addresses.

Depending on the path, the result is:

- A 32-bit transition dependency result.
- A state byte captured before a later call and zero-extended to 32 bits.
- A 32-bit registration-field value.
- Zero.
- The result of an indirect dispatch.

The nonzero word inspected during finalization is **not** returned directly. It selects an indirect call whose result is returned.

### Accessibility and ownership

Every field reached on the selected path must remain accessible when used. The same applies to dispatch tables, the secondary object, dependency-returned storage, global-backed storage, and traversed nodes. Calls may change these structures; their preservation is not established.

Registration publishes an address inside the caller’s object. No allocation or copy of the embedded record is visible. Its storage must remain valid while the list can reach it. No direct allocation, deallocation, reference-count operation, or ownership transfer is established.

The finalization path has two pointer levels:

1. A global-backed value supplies a pointer to storage containing another pointer.
2. That stored pointer, when nonnull, identifies an object whose first 32-bit word is inspected.

There is **no null check before dereferencing the storage pointer**. That storage must be readable even when the pointer contained in it is null. A nonnull contained pointer must itself permit a four-byte read.

## Behavior

### Initial zero-selector path

The function first reads the byte at `0x4D2`. If it is zero, the observable call sequence is:

1. F-53fec46eb847 receives the object.
2. F-6ac70711bbb5 returns a word.
3. F-2926dbb9b751 receives that returned word and a global-backed operand read for this call.
4. U-02 is dispatched through the secondary object at `0x430`, using table offset `0x84`.
5. U-03 is dispatched three times through primary table offset `0x58`. Each call receives the object and two global-backed operands.
6. The third U-03 result is returned.

The representation supplies no recoverable explicit arguments for U-02.

Each U-03 invocation has its own pair of operand sources, read for that invocation. The first pair includes a four-byte portion of global-backed storage. These are not established immutable constants, and different sources do not guarantee different values. Earlier dependencies or dispatches may change the values read by later calls.

Dispatch structures are consulted where used. In particular, the three U-03 calls are not guaranteed to resolve to the same target. The representation does not establish the relative evaluation order of operand reads within a single invocation.

This path does not reach transition checks or registration.

### First transition check

For a nonzero initial selector, F-acc006b5b6e3 receives the object and `0x2B`.

- A result other than `0x2B` is returned immediately.
- A result equal to `0x2B` is followed by F-d3924012ab57 with the object, then F-d61aae6c1d89 with the object.
- F-1bb2cf286dfe is then called. Its zero/nonzero result selects the next branch.

No direct object-field write is represented before these calls. The dependencies’ writes remain unknown.

### State-normalization branch

If F-1bb2cf286dfe returns zero, F-338d16f9ce72 first receives the embedded address at `0x8C0`. The state byte at `0x8C9` is then read.

| Observed state | Direct action |
|---|---|
| `0x2A` | No state or flag write. |
| `0x2B` | Write state `0x2A`, then clear the byte at `0x8C8`. |
| `0x2C`, `0x2D`, `0x2E` | No state or flag write. |
| `0x2F`, low-byte flag zero | Write state `0x2A`. |
| `0x2F`, low-byte flag nonzero | Call F-f4c9f8a20a8f with the object and `1`, then write state `0x2A`. |
| Any other state byte | Invoke F-a817d8d58c10, represented as nonreturning. |

The `0x2F` cases do not directly clear the flag. Any flag change caused by F-f4c9f8a20a8f belongs to that dependency.

After a returning case, the function reads the state byte again and retains it. It then calls F-1333331b2da1 with `0x8C0` and returns the retained byte, zero-extended. A mutation by that final call cannot change the captured return value.

The paired calls suggest synchronization, but locking and release semantics are unknown. No matching final call is visible on the invalid-state path.

### Second transition check

If F-1bb2cf286dfe returns nonzero, F-acc006b5b6e3 receives the object and `0x2C`.

A result other than `0x2C` is returned immediately. Completion preparation occurs only after an exact `0x2C` result.

### Completion preparation

The following operations occur in order:

1. Call F-6ac70711bbb5 and write byte `1` at offset `0xD4` from its returned address.
2. Write byte `1` at object offset `0x4CC`.
3. Call F-f1d12ae3bbc0 with the object.
4. Call F-53fec46eb847 with the object.
5. Call F-6ac70711bbb5, then F-47a24ed201ac.
6. Call F-6ac70711bbb5 again, then F-39871ce20db7.
7. Call F-936a8728139d.
8. Read a global-backed 32-bit preparation value and assign it to `0x7F4`.
9. Test the 32-bit field at `0x7F0`. If nonzero, read that field for the return value and return it.

The repeated F-6ac70711bbb5 calls are separate operations. Their results need not match. No explicit argument forwarding to F-47a24ed201ac or F-39871ce20db7 is established by adjacency.

The assignment at `0x7F4` uses the preparation value available after the preceding calls. It is not established as a fixed constant.

A nonzero registration field avoids the subsequent registration sequence, but does not avoid the preceding calls, byte writes, or preparation-value assignment.

### Conditional registration and list traversal

If `0x7F0` is zero:

1. Read the global-backed pointer to synchronization storage and pass that pointer to F-338d16f9ce72.
2. Call F-add44d4e9aaa with the embedded-record address at `0x7D4`.
3. Read the 32-bit quantity at `0x7D8`.

A zero quantity skips arithmetic and insertion, but not finalization.

For a nonzero quantity, the sequence is:

1. Call U-01.
2. Capture the global-backed address of list-head storage.
3. Compute the deadline-like value from U-01’s result plus the previously captured quantity multiplied by decimal `1000`, and store it at `0x7DC`.
4. Read a global-backed 32-bit preparation value and assign it to `0x7EC`.
5. Load the traversal head through the previously captured list-head storage address.

The list-head storage address is therefore captured **before** the deadline write and preparation-value read. The head is loaded through that captured address afterward. The quantity used in arithmetic was read before U-01; it is not re-read afterward.

Traversal examines each captured nonnull node by calling F-0d70d6f9010c with the node’s address plus `0x08` and the object’s address plus `0x7DC`.

- A zero comparison result causes traversal to read that node’s next link after the call and advance.
- A nonzero result stops traversal at that node.
- A null node stops traversal without a comparison call.

Because next links are read after comparison calls, their contents may reflect mutations made by those calls. No snapshot of the whole list is established.

Insertion has this direct-write order:

1. With no traversed predecessor, write the embedded-record address through the **captured list-head storage address**. Otherwise, write it to the traversed predecessor’s next link.
2. Write `1` to `0x7F0`.
3. Write the captured stopped-at node address, possibly null, to the embedded next link at `0x7D4`.

If a comparison changes the global that originally supplied the list-head storage address, that does not retarget the saved insertion destination. Likewise, insertion uses the captured stopped-at node, not a freshly loaded global head.

Publication through the incoming link precedes initialization of the embedded record’s final next link. Safe concurrent observation depends on synchronization contracts not established here. The comparison’s ordering relation and tie behavior are unknown.

### Finalization and return

After either insertion or a zero-quantity skip:

1. Read a separate global-backed operand and pass it to F-5bcae2eff9a7.
2. Read the global-backed pointer to synchronization storage again.
3. Dereference that storage pointer to obtain another pointer, without first testing the storage pointer for null.
4. If the obtained pointer is null, return zero.
5. Otherwise, read its first 32-bit word.
6. If that word is zero, return zero.
7. Otherwise, invoke U-05 with no recoverable explicit arguments and return its result.

The post-finalization storage pointer may differ from the pointer passed earlier to F-338d16f9ce72. The contained pointer is obtained only after F-5bcae2eff9a7, so its effects may influence this branch.

The arithmetic uses represented 32-bit integer values and a 32-bit destination. There is no visible overflow check, saturation, or range rejection. ## Acceptance examples

These are conditional static expectations, not executed tests. Except where stated otherwise, dependencies return normally and reached storage remains valid.

- **Initial selector zero:** Execute the alternate sequence and return the third U-03 result. Do not enter transition checks.
- **Operands change between U-03 calls:** Later calls use their operand-source contents at their own invocation points. Neither equality nor inequality between operand pairs is required.
- **First check returns `0x31`:** Return `0x31` without calling the two post-check object operations.
- **Normalization state `0x2B`:** Write state `0x2A`, then clear the flag byte. Capture the state before F-1333331b2da1.
- **Final normalization call changes state:** Return the previously captured byte, not the later state.
- **State `0x2F`, nonzero low-byte flag:** Call F-f4c9f8a20a8f with `1`, then write state `0x2A`. No direct flag-clear requirement follows.
- **Invalid state:** Enter the represented nonreturning dependency; no normal return or matching final paired call is established.
- **Registration field remains `7`:** Perform completion preparation through the `0x7F4` assignment, then return `7` without entering registration.
- **Quantity zero after F-add44d4e9aaa:** Skip arithmetic and insertion, but perform finalization and its pointer inspection.
- **Empty captured list:** Write the embedded record through the captured head-storage address, write registration value `1`, then write a null next link.
- **First comparison nonzero:** Insert before the captured traversal node. With no predecessor, use the captured head-storage destination even if the comparison changed its supplying global.
- **Storage pointer valid, contained pointer null:** Dereference the storage pointer, then return zero without reading a target word or invoking U-05.
- **Storage pointer null:** No protected zero return is established; the storage-pointer dereference lacks a null check.
- **Contained pointer valid, first word nonzero:** Return U-05’s result, not the inspected word.
