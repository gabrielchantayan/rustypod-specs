# F-da62c29c744d

## Purpose

F-da62c29c744d conditionally extracts an unsigned integer from a byte-addressed record. A leading control byte determines whether extraction occurs, where the selected field begins, and whether the field occupies one, two, three, or four bytes.

The established behavior is little-endian extraction: the lowest-addressed selected byte supplies the least significant part of the result. The function reads the selected bytes in the opposite order, from highest address to lowest address.

A disabled extraction returns zero without accessing a selected field. An enabled extraction can also return zero, so the returned integer does not independently report whether extraction occurred.

“Control byte” and “selected field” describe their roles within this contract. The available evidence does not establish a protocol, the meaning of the intervening bytes, or the application-level meaning of the returned value.

## Behavior

Otherwise, the function selects a field position and width according to the tables above. It returns the unsigned value represented by that field.

The control byte is explicitly read once. All position and width decisions use that captured value. There is no explicit later control-byte read. ### Numerical interpretation

The selected field is interpreted in little-endian significance order:

- The first selected byte supplies result bits 0 through 7.
- The second, when present, supplies bits 8 through 15.
- The third, when present, supplies bits 16 through 23.
- The fourth, when present, supplies bits 24 through 31.

Each selected byte contributes an unsigned value. A byte with its highest bit set does not cause sign extension.
