# F-1ba216d0a747

## Purpose

F-1ba216d0a747 accepts two 32-bit words and either:

- returns the first input unchanged;
- returns a word containing comparison-related bits and selected incoming status bits; or
- transfers control through an address derived from the incoming return-address state, with arguments selected by a shared control word.

The constants and bit operations are consistent with handling exceptional binary32 encodings and constructing processor-status information. That interpretation is **inferred intent**, not an established floating-point interface. The established contract is expressed in terms of 32-bit words, unsigned comparisons, signed interpretations, and bit positions.

The indirect transfers have unresolved calling and return semantics. Their presentation as calls does not establish that they are ordinary functions, that they return normally, or that their apparent argument lists are complete.

## Interface

### Explicit inputs and result

The visible interface has two inputs:

| Input | Width | Interpretation |
|---|---:|---|
| First input | 32 bits | Raw unsigned word; also returned unchanged on early exits |
| Second input | 32 bits | Raw unsigned word used in classification and comparison |

The nominal result is one unsigned 32-bit word.

On direct-return paths, the result is determined entirely by the explicit inputs and, for packed comparison results, incoming status state. On an indirect-transfer path that returns as represented, the result is the 32-bit value produced by that transfer.

### Implicit inputs

The visible behavior also depends on:

- An incoming status byte. Its bits can contribute to packed results; it is not established to be a Boolean.
- An incoming return-address word. Its bottom two bits are cleared to obtain the indirect destination.
- A shared 32-bit control word, read at several separate decision points.
- Three shared 32-bit payload words:
  - a default single-argument payload;
  - a first paired payload;
  - a replacement second payload.

These descriptive labels do not imply initialization, ownership, synchronization, or storage duration guarantees.

### Arithmetic conventions

All word arithmetic is modulo \(2^{32}\). Left shifts discard bits above bit 31. Unsigned comparisons use values from 0 through `0xFFFFFFFF`. Signed interpretations use 32-bit two’s-complement values.

Bit 0 is the least significant bit.

Define the doubled form of an input as its left shift by one bit, truncated to 32 bits. This is not unbounded multiplication: for example, both `0x7F800000` and `0xFF800000` have doubled form `0xFF000000`.

No pointer input, buffer layout, allocation request, or explicit ownership transfer is established.

## Behavior

### 1. Classification and unchanged-result exits

The function first forms the bitwise union of the two inputs. This stage performs no visible shared-data reads.

The following rules describe the established early-exit behavior after reducing the signed arithmetic and overflow conditions to equivalent 32-bit ranges.

**When neither input has bit 31 set:**

- If both inputs are below `0x7F800000`, return the first input unchanged.
- Otherwise, continue to the doubled-value classification.

**When at least one input has bit 31 set:**

- If the bitwise union is below `0xFF800000`, return the first input unchanged.
- Otherwise, if both doubled inputs are below `0xFF000000`, return the first input unchanged.
- In every other case, continue to the doubled-value classification.

These are raw-word rules. In particular, a union of two inputs can cross a threshold even when neither individual input has the corresponding high-bit pattern.

An unchanged-result exit does not consult the control word, payload words, or indirect destination.

### 2. Doubled-value classification

For inputs not already returned, the next distinction is:

- If both doubled inputs are at most `0xFF000000`, produce a packed comparison result.
- If either doubled input exceeds `0xFF000000`, enter control-word dispatch.

The strict distinction between “below `0xFF000000`” in the earlier negative-sign classification and “at most `0xFF000000`” here is significant. Equality can reach the packed-result path.

The visible evaluation examines the second input’s doubled form first. It examines the first input’s doubled form only if the second is at most `0xFF000000`. These operations have no visible memory side effects.

### 3. Packed comparison result

All packed-result paths return directly and perform no visible shared-data reads.

The incoming status byte is combined with comparison bits using bitwise OR, not replacement. Consequently, an incoming status bit can force a packed result bit to one even when the corresponding comparison is false.

#### At least one input has bit 31 set

The result has these bits:

| Result bit | Established value |
|---:|---|
| 31 | One exactly when the second input is greater than the first, using unsigned comparison |
| 30 | Incoming status bit 3 OR equality of the inputs |
| 29 | Incoming status bit 2 OR “second input is at most first input,” unsigned |
| 28 | Zero |
| 27 | Incoming status bit 0 |
| 26–0 | Zero |

Other incoming status bits do not survive this path.

This comparison is an unsigned comparison of encodings. It must not be replaced with an assumed floating-point ordering.

#### Neither input has bit 31 set

The result has these bits:

| Result bit | Established value |
|---:|---|
| 31 | Incoming status bit 4 OR “second input is less than first input” |
| 30 | Incoming status bit 3 OR equality of the inputs |
| 29 | Incoming status bit 2 OR “first input is at most second input” |
| 28 | Incoming status bit 1 |
| 27 | Incoming status bit 0 |
| 26–0 | Zero |

Here both inputs are nonnegative under signed interpretation, so the signed difference used for bit 31 is negative exactly when the second input is smaller.

The supplied representation also contains an alternative for signed subtraction overflow. That alternative is unreachable under the established branch condition: subtracting two values in the range `0x00000000` through `0x7FFFFFFF` cannot overflow a signed 32-bit result.

### 4. Control-word dispatch

This stage is reached only when the doubled-value classification selects dispatch.

Every control-word access described below is a separate visible read. The contract does not assume that successive reads return the same value.

First, read the control word and inspect mask `0x000D0000`.

- If any masked bit is set, proceed directly to the common dispatch rules.
- If all masked bits are clear, read the control word again and select a mode from its low four bits.

#### Mode 10

The visible order is:

1. Read the default single-argument payload.
2. Read the control word and inspect bit `0x40`.
3. Select `0x80000000` instead of the payload if that bit is set.
4. Transfer indirectly with the selected word as the one visible argument.

The default payload is read even when the later control-word read causes it to be discarded.

If the transfer returns as represented, its result becomes the function result.

#### Mode 8

Read the control word and inspect bit `0x40`.

If that bit is set, transfer indirectly with two visible arguments, both zero. No payload word is read on this branch.

If the bit is clear:

1. Read the first paired payload.
2. Read the control word and inspect bit `0x10`.
3. If that bit is clear, transfer with the first paired payload and the original first input.
4. If that bit is set, read the replacement second payload and transfer with zero and that replacement payload.

Thus, the first paired payload is read even if the later `0x10` decision discards it.

If the transfer returns as represented, its result becomes the function result.

#### Mode 9

For subsequent common dispatch, substitute the value 8 for the second input’s working value.

This does not write to caller-owned storage. It changes only the value available to the later indirect-transfer argument selection.

Then proceed to common dispatch.

#### All other modes

Transfer indirectly with no explicit arguments visible in the supplied representation.

This does not establish that the target receives no meaningful register state or hidden arguments.

### 5. Common dispatch

Common dispatch is reached either because the first control-word mask test was nonzero or because mode 9 was selected.

First, read the control word and inspect bit `0x00100000`.

- If clear, transfer indirectly with one visible argument: zero.
- If set, read the control word again and inspect mask `0x00070000`.

If that mask is zero, transfer indirectly with three visible arguments:

1. `0x30000000`;
2. the original first input;
3. `0x30000000`, additionally ORed with bit 27 when incoming status bit 0 is set.

If that mask is nonzero, read the control word again and transfer indirectly with two visible arguments:

1. The original second input, except that the mode-9 path supplies 8.
2. A transformed control word: shift the newly read word left by 15 bits with 32-bit truncation, complement all 32 bits, then shift left by one bit with 32-bit truncation.

The final transformation always produces bit 0 equal to zero and bits 1 through 15 equal to one. Its high 16 bits are the complement of the final control-word read’s low 16 bits.

The threshold patterns resemble binary32 infinity/NaN classification, while the packed output resembles status-flag construction. Neither interpretation authorizes replacing the raw-word contract with a standard floating-point comparison API.
