# F-197711d9a5d9

## Purpose

F-197711d9a5d9 obtains a selector through an indirect call, reports that selector through a temporary-value workflow, and performs one of two action sequences when the selector is exactly zero or one. Other selector values bypass both action sequences.

The function returns a 64-bit value whose low 32 bits are always one on normal return. Its high 32 bits come from an address-exposed local word initially populated with the selector. That high word is not unconditionally the original selector: a dependency receives its address before dispatch occurs.

The established behavior is the call sequence, memory accesses, branch conditions, and result construction described below. Interpretations such as “mode selection,” “logging,” “resource reset,” or “notification” are inferred intent, not established dependency semantics.

## Interface

The supplied representation exposes four arguments:

| Argument | Represented width and role |
|---|---|
| A | A pointer-sized, apparently 32-bit address. Used as an object pointer only on the selector-zero path. |
| B | A 32-bit word, initially copied into an addressable local slot. That slot is subsequently overwritten with the selector. |
| C | An opaque 32-bit word copied into a separate addressable local slot. |
| D | An opaque 32-bit word copied into a separate addressable local slot. |

The function returns a 64-bit bit pattern. At normal completion:

- Bits 31 through 0 are `0x00000001`.
- Bits 63 through 32 are the final contents of the local slot initially holding B and later assigned the selector.

This describes result assembly, not a documented status convention. In particular, the low word being one does not establish that dependencies succeeded.

### Local layout and address exposure

The representation shows three consecutive four-byte local slots, in this order:

1. The slot initially holding B.
2. The slot initially holding C.
3. The slot initially holding D.

The addresses of the C and D slots are passed to F-9b9c1c7483f4. The address of the first slot, after replacement with the selector, is passed to F-ed08d1c0ca70. The D-slot address is subsequently passed to F-8a5aadac202f.

These are local copies, not addresses of caller-owned argument storage. Nevertheless, their addresses escape to dependencies during the call. The supplied evidence does not establish whether any dependency retains those addresses or accesses neighboring slots.

## Behavior

### Common prefix

Every normally executing invocation performs the following sequence before deciding which action path to take.

1. It initializes the three local argument slots from B, C, and D.
2. It calls F-938c950e5046 with no explicit arguments.
3. From the returned address, it reads a dispatch-table address, selects the callable entry at byte offset `0x168`, and invokes that entry with no explicit arguments shown.
4. It retains the resulting 32-bit selector separately from the addressable local slots.
5. It reads a four-byte field at offset `0x04` from a referenced global data location and calls F-9b9c1c7483f4 with:
   - the address of the D slot;
   - that global field value;
   - the address of the C slot.
6. It overwrites the B slot with the retained selector.
7. It calls F-ed08d1c0ca70 with:
   - a value obtained from a separate global reference;
   - the result of F-9b9c1c7483f4;
   - the address of the slot now holding the selector.
8. It calls F-8a5aadac202f with the address of the D slot.
9. It reads and retains a 32-bit global value, referred to below as the **primary word**.
10. It branches on the separately retained selector.

The primary-word read occurs even when the selector is neither zero nor one. It also occurs after F-8a5aadac202f, so modifications made by that dependency can affect the value captured.

The branch does not use the potentially modified addressable selector slot. A dependency can therefore change the eventual return high word without changing which action path this function selects.

No textual message format, encoding, allocation behavior, or reporting destination is established for this common prefix.

### Selector zero

When the retained selector equals zero, the function performs these operations in order:

1. Calls F-fdd8589eca2d with no explicit arguments.
2. Writes the 16-bit value one at byte offset `0x80` from the returned address.
3. Obtains five values through five separate pairs of calls:
   - F-bb50a072e902 with the 32-bit argument zero;
   - F-5b4ae75440ab with that call’s result and, respectively, the indices zero, one, two, three, and five.
4. Calls F-84055b679da8 once for each of the five resulting values, preserving that index order.
5. Calls F-bb50a072e902 once more with zero and does not otherwise use its returned value.
6. Calls F-5032ac6bc151 with no explicit arguments.
7. Reads A’s dispatch-table address, selects the callable entry at byte offset `0xb8`, and invokes it with A and the 32-bit value `0x10`.

All five indexed values are obtained before the first call to F-84055b679da8. The sequence is not acquisition followed immediately by processing for each index.

Index four is not requested. The six calls to F-bb50a072e902 are distinct observable calls. The function does not cache a single result for reuse.

The final method lookup occurs after F-5032ac6bc151. Consequently, the function uses the dispatch-table contents visible at that later point, not a table captured before the preceding calls.

The two-byte store does not establish a write to a complete four-byte field. No additional neighboring bytes are explicitly written by this function.

### Selector one

When the retained selector equals one, the function performs these operations in order:

1. Calls F-794d66f15c1d with no explicit arguments.
2. Calls F-b3f496fcfa74 with no explicit arguments and retains its 32-bit result as a condition.
3. Reads a second 32-bit global value, referred to below as the **default word**.
4. Chooses a **derived word**:
   - If the condition is zero, the derived word is the captured default word.
   - If the condition is nonzero, the derived word is the primary word ORed with the primary word interpreted as signed 32-bit and shifted arithmetically right by 24 bits.
5. Calls F-ef0964bd9b8a with no explicit arguments.
6. Calls F-1958950ee503 with four arguments:
   - the result of F-ef0964bd9b8a;
   - the captured primary word;
   - the derived word;
   - a 32-bit zero.
7. Calls F-76b1c50b12f7 with no explicit arguments.
8. Reads the returned object’s dispatch-table address, selects the callable entry at byte offset `0x04`, and invokes it with that object and the result of F-1958950ee503.

The default-word read occurs even when a nonzero condition causes its value to be discarded. It occurs after both initial calls on this path.

The primary word was captured before either of those calls. A later change to the corresponding global does not change the already captured primary word used in the transformation or passed to F-1958950ee503.

The original argument A is not used as the receiver on this path.

### Derived-word arithmetic

The nonzero-condition transformation is entirely 32-bit. The right shift is arithmetic, so it propagates the sign bit of the signed interpretation of the primary word. The shifted result is then ORed with the original 32-bit word.

Consequences include:

- Primary `0x12345678` produces derived `0x1234567a`.
- Primary `0x80000000` produces derived `0xffffff80`.
- Primary `0xff000000` produces derived `0xffffffff`.

This is not an unsigned right shift, a rotation, or a transformation limited to the lowest byte.

### Other selectors and completion

For every selector other than zero or one, neither action sequence executes. The function still performs the complete common prefix, including the primary-word read.

After any normally completing path, it assembles the 64-bit result from the final addressable selector-slot contents and low word one. Return values from the final indirect action calls are not incorporated into that result.

## Side effects

- Initialization of three local four-byte slots.
- Replacement of the first local slot with the selector.
- On selector zero only, a two-byte store of one at offset `0x80` in dependency-provided storage.

Additional writes can occur through dependencies and indirect calls. Their scope is not established here.

Observable ordering matters:

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Selector zero without local-slot mutation.** If the initial indirect call returns zero and dependencies leave the addressable selector slot unchanged, the function performs the two-byte store, requests indices zero, one, two, three, and five, processes all five values, performs the two trailing dependency calls, and invokes A’s `0xb8` dispatch entry with `0x10`. The returned bit pattern is `0x0000000000000001`.

2. **Acquisition order.** For selector zero, an observable trace must place every F-5b4ae75440ab call before the first F-84055b679da8 call. A trace that alternates indexed acquisition and processing is not equivalent.

3. **Selector one with a zero condition.** If the primary word is `0x12345678`, the default word is `0xaabbccdd`, and F-b3f496fcfa74 returns zero, F-1958950ee503 receives `0x12345678` as its second argument and `0xaabbccdd` as its third argument. With no selector-slot mutation, the final return is `0x0000000100000001`.

4. **Selector one with a nonzero condition.** If the primary word is `0x80000000` and the condition is nonzero, the third argument to F-1958950ee503 is `0xffffff80`. The default global is nevertheless read before that choice is made.

5. **Unrecognized selector.** If the initial indirect call returns the 32-bit pattern `0xffffffff`, both action sequences are skipped. With no selector-slot mutation, the return is `0xffffffff00000001`. The common reporting and cleanup-shaped calls still occur.

6. **Reporting changes the return high word.** If the initial selector is zero but F-ed08d1c0ca70 writes seven into the slot whose address it receives, the zero action sequence still executes. If that slot is not changed again, the return is `0x0000000700000001`.

7. **Global mutation after capture.** If the primary word is captured as `0x12345678` and F-794d66f15c1d subsequently changes its global storage, the selector-one sequence still uses captured `0x12345678`. Conversely, a change to the default-word storage before its later read can affect the zero-condition result.
