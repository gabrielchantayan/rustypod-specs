# F-42382d1a1b3b

## Purpose

F-42382d1a1b3b performs two unconditional dependency calls, evaluates a condition using a mutable four-word argument record and fields of a caller-supplied object, and conditionally updates an embedded region of that object through two further dependency calls and a one-byte flag write.

Its result is a 64-bit value assembled from the first two words of the mutable argument record. It is not necessarily a packing of the original first two arguments: a dependency receives access to that record before the condition and return value are evaluated.

The established behavior is structural. The meanings of the object, its fields, the selected values, and the dependency operations are not established. Any interpretation as initialization, notification, rendering, or state synchronization is inferred intent rather than part of this contract.

## Interface

### Inputs

The function accepts four 32-bit arguments:

| Argument | Established representation and use |
|---|---|
| Object address | A 32-bit value used as the base address for embedded regions and fields. Also copied into the first word of a temporary record. |
| Selector | A signed 32-bit value copied into the second word of the temporary record. Its **original** value determines which object field supplies a dependency argument and which Boolean value is written. |
| Opaque word | An uninterpreted 32-bit value copied into the third word of the temporary record. No subsequent direct use by this function is visible. |
| Endpoint | A signed 32-bit value copied into the fourth word of the temporary record. The record’s current fourth word participates in the branch condition. |

The original object address remains the base used for all explicit object accesses, even if a dependency changes the first word of the temporary record. Likewise, changing the record’s second word does not replace the original selector for field selection or the flag write.

### Temporary record

Before calling any dependency, the function creates a contiguous 16-byte temporary record:

| Byte offset | Width | Initial contents |
|---|---:|---|
| 0 | 4 bytes | Object address |
| 4 | 4 bytes | Selector |
| 8 | 4 bytes | Opaque word |
| 12 | 4 bytes | Endpoint |

A dependency receives the address of this record. Its contents must therefore be treated as potentially changed when that call returns.

The record is temporary storage belonging to this invocation. Passing its address does not establish an ownership transfer, a right to release it, or permission to retain and use it after the invocation ends.

### Object-relative layout

All offsets below are relative to the original object address.

| Offset | Access or role |
|---|---|
| `0x0A4` | Address passed to the first dependency; no direct field read is shown. |
| `0x22C` | Four-byte opaque value selected when the original selector is not 1. |
| `0x230` | Four-byte opaque value selected when the original selector is 1. |
| `0x240` | Signed 32-bit threshold read for the first part of the condition. |
| `0x244` | Signed 32-bit value read only if the first part of the condition is false. |
| `0x468` | Address of an embedded region passed to both conditional dependencies. |
| `0x494` | One-byte Boolean destination, written only on the conditional path. |

The flag at `0x494` is `0x2C` bytes beyond the embedded region’s starting address. No size or complete layout for that region is established.

### Output

On normal completion, the function returns a 64-bit bit-pattern:

- Bits 0–31 contain the current first word of the temporary record.
- Bits 32–63 contain the current second word of the temporary record.

The words are concatenated without sign extension. A negative signed interpretation of the second word does not alter its 32-bit contribution.

If those two words remain unchanged, the result packs the original object address into the low half and the original selector into the high half. The result is not established as a status code, Boolean, pointer, or ownership-bearing handle.

## Behavior

### 1. Record creation and unconditional calls

The function initializes all four words of the temporary record before making the first dependency call.

It then calls F-88dd67d704e5 with:

1. The original object address.
2. The address at object offset `0x0A4`.

After that call returns, it calls F-412e4635fdb0 with:

1. The original object address.
2. The address of the temporary record.

These calls occur in this order on every normally progressing invocation. Their return values do not visibly control subsequent behavior.

The condition is evaluated only after both calls return. Object fields may therefore reflect changes made by either dependency. The temporary record may reflect changes made through its supplied address.

### 2. Conditional decision

The first part of the condition compares:

- The current fourth record word minus the current second record word; and
- The signed 32-bit value read at object offset `0x240`.

This is a strict signed less-than comparison. Equality does not satisfy it.

If that comparison is true, the conditional path is taken without an explicit read of the field at `0x244` by this function.

If it is false, the function reads the signed 32-bit value at object offset `0x244`. The conditional path is taken if that value is greater than 1.

Thus:

- Either condition being true enters the conditional path.
- Both conditions being false bypass it.
- The second condition is short-circuited when the first is true.

The supplied representation establishes 32-bit signed operands for the subtraction and comparisons. It does not establish a portable overflow rule for subtraction outside the signed 32-bit range. Such cases are **documented_only** rather than assigned an assumed mathematical, wrapping, or saturating result.

The relative order of obtaining the subtraction operands and reading `0x240` is not separately established. The dependency-call ordering and the short-circuit behavior are established.

### 3. Conditional operations

If the condition is false, the function performs none of the following explicit actions:

- It does not read either selected-value field for the conditional call.
- It does not call F-6904f7699031.
- It does not write the flag at `0x494`.
- It does not call F-ec4cfa552cce.

This does not imply that the earlier dependencies left those fields unchanged.

If the condition is true, the function uses the address at object offset `0x468` as the embedded-region argument.

It selects one four-byte value using the **original selector**:

- Selector equal to 1: read the value at `0x230`.
- Any other selector: read the value at `0x22C`.

It passes the embedded-region address and the selected value to F-6904f7699031. The selected value is opaque; no conversion, range check, or interpretation is visible.

After F-6904f7699031 returns, the function writes one byte at object offset `0x494`:

- 1 if the original selector equals 1.
- 0 otherwise.

It then calls F-ec4cfa552cce with the embedded-region address.

The observable sequence is therefore:

1. Read the selected four-byte value and invoke F-6904f7699031.
2. After that call returns, write the Boolean byte.
3. Invoke F-ec4cfa552cce.

The write is not moved ahead of the first conditional dependency. The final dependency runs after the write, but its unknown effects mean that the byte’s value at function return is not guaranteed solely by this explicit store.

### 4. Result construction

After either bypassing or completing the conditional path, the function returns the packed current first and second record words.

There is no visible restoration of those words to their input values. No explicit local write changes them after initial record creation, but dependency-mediated changes cannot be excluded.

## Side effects

### Explicit effects

The function explicitly:

- Initializes the 16-byte temporary record.
- Calls two dependencies unconditionally.
- Reads the threshold at `0x240` after those calls.
- Conditionally reads `0x244`.
- On the taken path, reads exactly one selected-value field for the conditional call.
- On that path, calls F-6904f7699031, writes the Boolean byte, and calls F-ec4cfa552cce, in that order.

The only visible direct write into the object is the one-byte flag store. This does not bound writes performed by dependencies.

### Ownership and lifetime

No explicit allocation, release, reference-count update, or ownership transfer is visible in this function. It would be unsafe to infer that dependencies neither allocate nor release memory.

For normal completion, the object and every address subsequently used must remain valid for its required access. This includes validity after dependency calls, not just at entry. A dependency that invalidates the object can make later explicit accesses unsafe.

The temporary record’s address is exposed to F-412e4635fdb0. Whether that dependency retains the address or makes it reachable by later dependencies is unknown. No post-return lifetime is provided.

### Errors and abnormal completion

No dependency return value is visibly checked. The contract does not assign a success/failure meaning to those results.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume valid storage, normal dependency returns, representable subtraction, and no dependency changes beyond those explicitly described.

### First condition alone selects the path

After F-412e4635fdb0 returns:

- The record’s second word is 3.
- Its fourth word is 8.
- The threshold at `0x240` is 6.

The difference is 5, which is less than 6. The conditional path is taken. This function does not read `0x244` to decide that path.

If the original selector was 3, it supplies the value from `0x22C` to F-6904f7699031, writes 0 to `0x494`, and then calls F-ec4cfa552cce.

### Equality falls through to the second condition

The record’s second and fourth words are 3 and 8, and the threshold is 5.

The difference equals the threshold, so the first condition is false. The function reads `0x244`:

- A value of 2 takes the conditional path.
- A value of 1 bypasses it.
- A negative value also bypasses it.

### Original selector and mutable record serve different roles

The original selector is 1. F-412e4635fdb0 changes the record’s second word to 7 and its fourth word to 9. The threshold is 3.

The decision uses the modified difference, 2, and takes the conditional path. Field selection still uses the original selector:

- The selected value comes from `0x230`.
- The explicit flag write stores 1.
- If the record’s first two words remain unchanged thereafter, the returned high half is 7, not 1.

### Modified record address does not redirect object accesses

F-412e4635fdb0 changes the first record word to `0x12345678`.

Later explicit object accesses still use the original object address. If no later action changes the first record word again, the return value’s low half is `0x12345678`.

### Packed return preserves bit patterns

If the final first record word is `0x12345678` and the final second word is `0xFFFFFFFF`, the returned bit-pattern is `0xFFFFFFFF12345678`.

The high word is not numerically normalized because its signed interpretation is −1.

### False condition skips the explicit update sequence

If the first comparison is false and `0x244` contains 1, neither conditional dependency is invoked and this function does not perform the flag store. The two unconditional dependencies have already run; the example does not imply an absence of their side effects.
