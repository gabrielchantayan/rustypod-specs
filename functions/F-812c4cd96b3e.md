# F-812c4cd96b3e

## Purpose

F-812c4cd96b3e performs a fixed sequence of 32-bit word updates, invokes three external operations, and waits until either a status bit is clear or an external predicate returns a nonzero result.

The established behavior is a configuration-and-polling sequence. Its apparent intent is to initiate an operation and wait for completion subject to an externally evaluated stopping condition. The supplied evidence does not establish the device type, the meaning of the input, or whether the stopping condition represents elapsed time, an error, cancellation, or another event.

The function returns no value. A caller cannot distinguish its two return paths from the return value alone.

## Interface

### Input

The function accepts one unsigned 32-bit input, designated **P** in this contract.

Every 32-bit input pattern is processed without visible validation. The input is transformed into a word **V**:

- Shift P right by one bit using an unsigned, zero-filling shift.
- Set bit 31 of the result.

Consequently:

- V is always between `0x80000000` and `0xffffffff`, inclusive.
- P’s bit 0 is discarded.
- P’s bits 1 through 31 become V’s bits 0 through 30.
- Inputs differing only in bit 0 produce the same V.
- No addition, multiplication, or signed arithmetic is involved in this transformation.

### Result

The function has no explicit result value.

Normal return occurs when either:

1. A status-word read observes bit 3 clear; or
2. After observing bit 3 set, a call to F-03 returns a nonzero signed 32-bit result.

The function does not expose which condition caused the return.

### Shared data

The supplied representation identifies two externally supplied data values:

- A pointer to a region addressed as 32-bit words.
- A separate 32-bit datum obtained after F-02 returns.

For this contract, **B** denotes the region pointer captured at entry. The visible accesses use these locations:

| Location | Width | Role in the visible sequence |
|---|---:|---|

The offsets follow the supplied 32-bit word model. These role descriptions do not establish register names, hardware semantics, or permissions.

## Behavior

### Initial update and external operation

The function captures B before invoking any external operation.

It first performs a read-modify-write on the word at offset 0, clearing bit 21 with mask `0xffdfffff`. The written value preserves every other bit from the value read for that update.

It then calls F-01 with the numeric argument 1.

After F-01 returns, the function uses the captured pointer B to access offset 0 again. It performs a new read-modify-write, setting bit 21 with mask `0x00200000`.

This second update is based on a fresh read. It is not a restoration of the word read before F-01. Changes to other bits that are present in the second read are carried into the second write.

The supplied representation expresses the initial update through the shared pointer source, whereas subsequent region accesses use the captured B. With a stable pointer source, these refer to the same region. Behavior under concurrent changes to that pointer source is not established.

### Parameter-derived write and activation-bit update

After setting bit 21, the function replaces the entire word at B + 28 with V.

This is a full-word write. It does not preserve any previous bits at that location.

The function then reads the word at B + 4, sets bit 0, and writes the resulting word back. Other bits are preserved from that particular read.

The established program order is:

1. Clear bit 21 at offset 0.
2. Call F-01 with 1.
3. Set bit 21 at offset 0.
4. Write V at offset 28.
5. Set bit 0 at offset 4.

The function does not visibly restore the original values of these words before returning.

### Polling setup

Following the configuration writes, the function calls F-02 with no visible arguments and retains its 32-bit result.

Only after F-02 returns does the function read the separate 32-bit shared datum. That value is retained as well.

These two retained values become the arguments to every subsequent F-03 call:

- First argument: the result from F-02.
- Second argument: the datum read after F-02 returned.

The visible function calls F-02 once and reads the separate datum once. It does not refresh either retained value during polling.

The ordering matters if F-02 changes that datum: the function reads the datum after the call, rather than taking a pre-call snapshot.

### Polling and termination

Polling begins with a fresh 32-bit read at B + 12.

If bit 3 of that read is clear, the function returns immediately. F-03 is not called for that iteration.

If bit 3 is set, the function calls F-03 with the two retained arguments.

- A zero result causes another status-word read and another iteration.
- Any nonzero result causes the function to return immediately.

Negative and positive nonzero results have the same effect.

There is no final status-word read after a nonzero F-03 result. Thus, return does not establish that bit 3 is clear.

The visible function imposes no iteration count, sleep, retry delay, or independent deadline. If every status read observes bit 3 set and every F-03 call returns zero, polling continues indefinitely, assuming the operations themselves continue to return.

### Fresh read after F-01

A behavior that restores the original pre-F-01 word with bit 21 set would not match the established sequence.

### Status clear on first observation

Suppose all setup operations return normally and the first status read observes bit 3 clear.

The function returns after one status read. F-02 has already been called, and the separate datum has already been read. F-03 is never called.

### Retry followed by status clearance

Suppose the first status read observes bit 3 set, F-03 returns zero, and the next status read observes bit 3 clear.

The function makes exactly one F-03 call and returns after the second status read. Both F-03 arguments are the retained setup values.

### Nonzero predicate result

The function returns without another status read. Either result is sufficient; the function does not require a specific positive value.

### Shared datum changed during polling

Suppose the separate datum changes after it has been captured, while polling continues.

Later F-03 calls still receive the captured value. The visible function does not reread the datum.

### Persistent busy state

Suppose every status read observes bit 3 set and every F-03 call returns zero.

The function continues polling. No finite completion bound follows from the visible body alone.
