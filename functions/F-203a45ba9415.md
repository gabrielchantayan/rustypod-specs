# F-203a45ba9415

## Purpose

F-203a45ba9415 processes bounded parser input into indexed name and value tables, then conditionally performs transfers intended to place the entry named `.notdef` at index zero.

The table-building behavior is established by the supplied static representation. Recognition of `.notdef` and the meaning of the final transfers are partly inferred: an unresolved dependency receives the `.notdef` literal address and a table-entry pointer, and its zero return controls the relevant branches. Its implementation is not supplied, so string equality is not an established dependency guarantee.

The routine has no return value. Its observable results are parser-field changes, table operations, writes through table-provided pointers, diagnostics, and dependency effects.

No runtime tests have been performed.

## Interface

### Arguments and representation

The routine accepts:

1. A context reference, represented as a 32-bit address. Its field at byte offset `0x1E4` supplies a reference used to resolve initialization dispatch.
2. A mutable parser-state reference.
3. An auxiliary 32-bit argument. The numeric-header path retains its incoming value. The angle-delimited path replaces it internally with a saved input address before initialization.

### Preconditions

Safe execution requires valid storage for all accessed fields, callable callback targets, adequate table arrays, and readable input at every address actually inspected. Successful insertions must provide writable storage at the subsequent terminator address.

The routine does not independently enforce these requirements. In particular, it does not validate nonnegative counts, monotonic cursor movement, span lengths, allocation capacity, or arithmetic overflow. Captured-limit comparisons are not sufficient to establish memory safety if dependencies change cursors, input storage, or table references.

## Behavior

### Entry snapshots and opening selection

Before invoking a dependency, the routine captures the input-limit field, the initialization argument at `0x10`, and the context-derived dispatch reference. It also establishes the three embedded table addresses and initializes an internal marker flag and remembered index to zero.

It calls F-U02, then reads the current input address. An address at or beyond the captured limit selects the explicit bounds-error path.

Otherwise, the current byte is passed to F-cfad0582408b:

- A nonzero result selects header conversion.
- A zero result causes a fresh read of the parser cursor and its byte. That byte must be `<`; otherwise the invalid-opening error path is selected.

There is no new bounds comparison between the classification call and this fresh byte read. The classification dependency is not established to preserve the cursor or input.

### Numeric-header path

F-U04 is called, and its 32-bit return is written to `0x90`. The status field is then read. If nonzero, the routine returns without replacing that status.

If status is zero, the current cursor must be strictly below the captured limit before initialization proceeds. Otherwise the bounds-error path is taken.

The accepted number syntax, conversion rules, and permissible count range are dependency-defined. The name “numeric-header path” describes the observed use of the return, not an established lexical grammar.

### Angle-delimited preliminary scan

After accepting `<`, the routine calls F-U03 and returns immediately if status is nonzero. It then calls F-U02 and saves the resulting cursor as both the rewind address and the replacement auxiliary argument.

While the current cursor is below the captured limit:

- A byte `/` increments the provisional 32-bit count.
- A byte `>` writes that count to `0x90`, restores the saved cursor, and ends the preliminary scan.
- Any other byte leaves the count unchanged.

Unless `>` ended the scan, F-U03 is called. A nonzero status returns immediately; otherwise F-U02 runs before the next position is examined.

This counts slashes at dependency-selected inspection positions, not necessarily every slash byte. Reaching the captured limit without the closing byte leads to the bounds-error path. After a successful rewind, the saved address must still be strictly below that limit.

### Initialization and live dispatch

Initialization requests occur in this order:

1. Value table, with the current count and captured initialization argument.
2. Name table, with a newly read count and the same captured initialization argument.
3. Temporary table, requesting four entries and using that captured argument.

The context-derived reference is captured before the first callback, but the dispatch target is **not** frozen. For each invocation, the routine dereferences that captured reference to obtain an intermediate dispatch pointer, then dereferences the function slot to select F-U05. An earlier initializer can therefore alter the target used by a later initializer. Changing only the context field does not replace the already captured reference.

The first invocation also supplies a function-slot read as an additional argument, followed by a zero-valued internal marker and the auxiliary argument. The representation does not establish the authoritative callable signature or the evaluation order between target resolution and that extra function-slot read.

A nonzero initializer return stops the sequence and is written to status. Earlier effects are not rolled back. Callback-induced status changes are not independently checked between successful initializer returns.

### Entry scanning and stopping

The unsigned insertion index starts at zero. The scan body is entered before any comparison against the count; a zero count does not suppress this first scan.

Each scan attempt calls F-U02, saves the resulting cursor, and compares that saved address with the captured limit. Reaching or exceeding the limit ends scanning normally at this stage.

For an in-range address, stopping checks include:

- A leading `>` ends scanning.
- A leading `end`, with its fourth byte strictly below the captured limit, causes F-402c86044576 to receive that fourth byte. A nonzero result ends scanning.
- If that dependency returns zero, the routine rereads the byte at the **saved scan address** and ends scanning if it is now `>`.

The last check does not reload the parser cursor. Thus F-402c86044576 can return zero yet cause termination by changing the saved address’s byte to `>`. Moving the parser cursor to a different `>` is not sufficient for this particular check.

The strict fourth-byte bound is tested before reading the remaining prefix bytes. A trailing three-byte `end` alone cannot trigger the classifier-based stop. No independent preceding token-boundary check is made.

If scanning does not stop, F-U03 runs. A nonzero status causes immediate return. The byte at the saved, pre-advance address is then read again. Only `/` enters name capture; otherwise scanning repeats. Input mutation during advancement can therefore change entry recognition.

### Name capture and marker recording

For a recognized slash, the following byte must be strictly below the captured limit. Otherwise the bounds-error path is taken.

The name starts one byte after the saved slash and ends at the parser cursor following advancement. The routine computes their 32-bit difference and calls F-U06 with:

- The embedded name-table address.
- The current unsigned index.
- The original input-span address.
- The computed span length plus one.

A nonzero return is written to status and terminates the routine.

After success, the routine loads the indexed pointer through the live name pointer-array field and writes a zero byte at the saved span-length offset. It then reads the first byte of the **original input span**, not the stored table entry.

Only if that original byte is `.` does it load the stored name pointer again and call F-U01. The literal `.notdef` address is the first argument; the freshly loaded table-entry pointer is second. A zero return sets the internal marker and records the current index. A nonzero return leaves the previous marker and remembered index unchanged.

Consequently, insertion-induced changes can affect these operations differently: the terminator uses a table pointer, the dot guard uses original input, and F-U01 receives another live table-pointer read. Zero means “record this index” here; interpreting it as string equality is conditional on F-U01’s unresolved contract. The last index producing zero through this guarded call is retained.

### Value capture and iteration

After the name operation:

1. F-U02 runs.
2. The resulting cursor is saved as the value start.
3. F-U04 runs; its return value is ignored.
4. The resulting cursor is saved as the value end.

There is no immediate status check after these calls. If the value end is at or beyond the captured limit, the bounds-error path is taken. An end exactly equal to the limit is rejected.

F-U07 receives the value-table address, current index, saved start, and the 32-bit span difference plus one. A nonzero return is stored as status and stops execution.

On success, the routine forms the old index’s four-byte slot offset, increments the unsigned index, loads the stored value pointer through the live value pointer-array field, and writes a zero byte at the saved span-length offset. The increment therefore precedes the terminator write in the supplied representation.

Another scan occurs only if the incremented index is less than a fresh unsigned read of `0x90`. Dependency changes to that count affect continuation.

### Final count and conditional transfers

Normal scan termination writes the number of completed pairs to `0x90`.

If no marker was recorded, the routine selects the missing-special-entry diagnostic and follows the explicit error path. This does not establish that no actual `.notdef` bytes exist: marker recording depends on the original-input dot guard and F-U01’s returns.

If a marker was recorded, F-U01 is called with the `.notdef` literal address first and the current name-table entry-zero pointer second. A zero return ends the routine without transfers. This call has no original-input dot guard.

A nonzero return starts these ordered operations:

| Order | Destination | Source |
|---|---|---|
| 1 | Temporary slot 0 | Name at index zero |
| 2 | Temporary slot 1 | Value at index zero |
| 3 | Temporary slot 2 | Name at remembered index |
| 4 | Temporary slot 3 | Value at remembered index |
| 5 | Name at remembered index | Temporary slot 0 |
| 6 | Value at remembered index | Temporary slot 1 |
| 7 | Name at index zero | Temporary slot 2 |
| 8 | Value at index zero | Temporary slot 3 |

Each operation obtains source pointer and length arguments from the relevant live arrays and uses the destination’s current insertion callback. Earlier calls can therefore affect later arguments and targets.

The first nonzero return stops the sequence and is written to status. There is no rollback. Successful byte-preserving, non-destructive insertion would make this an exchange of two pairs; that outcome is conditional, not guaranteed by the call sites alone.

## Side effects

Established direct effects include cursor rewind, count and status writes, indexed table operations, and zero-byte writes through table-provided pointers.

Explicit bounds, invalid-opening, and missing-marker failures call F-4457a9a44a68 with the selected diagnostic address, then write status `3`. The diagnostic can have other effects, but the subsequent direct status assignment is `3` if it returns.

Initialization and insertion failures instead store their nonzero return without that diagnostic call. Designated parser-callback status checks return without a replacement assignment. Other callback sites have no equivalent immediate check.

The routine does not clear status on entry or success. A return without an explicit failure assignment does not prove zero status.

No explicit deallocation or destruction call appears. Copying, ownership transfer, aliasing, allocation, replacement, and release remain dependency-defined. There is no established atomicity for table construction or final transfers.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Empty effective input.** If the first inspection leaves the cursor equal to the captured limit, the bounds diagnostic runs and status becomes `3`; initialization is not reached.

2. **Header failure.** If F-U04 returns seven and leaves nonzero status on the header path, `0x90` receives seven before immediate return.

3. **Preliminary count.** If inspected positions expose three slashes followed by `>`, without callback errors or overflow, `0x90` becomes three and the cursor rewinds to the saved post-opening position.

4. **Live initialization target.** If the first initializer changes the intermediate dispatch pointer reachable through the captured reference, the next initialization resolves through the changed pointer. Merely changing the context’s original field does not replace the captured reference.

5. **Classifier-zero mutation.** At a saved `end` position, if F-402c86044576 returns zero and changes that saved position’s first byte to `>`, scanning terminates before token advancement. If it changes only the parser cursor to another address containing `>`, that alone does not satisfy the saved-address check.

6. **Original-span guard.** If name insertion changes the original name’s first byte from `.` to another byte, F-U01 is skipped for that name even if the stored entry contains `.notdef`. Conversely, an original leading dot permits the call using the then-current stored pointer.

7. **Opaque zero return.** If F-U01 returns zero for a guarded name call, that index is remembered regardless of the dependency’s actual comparison semantics. A later guarded zero replaces the remembered index.

8. **Already-first conditional outcome.** After a marker has been recorded, a zero result from the final F-U01 call causes return without temporary insertions. Under the additional assumption that F-U01 implements string equality, this corresponds to `.notdef` already occupying index zero.

9. **Conditional pair exchange.** Given names `A` and `.notdef`, appropriate F-U01 returns, and successful byte-preserving insertions that keep saved entries usable, the transfer sequence places `.notdef` and its value at zero and moves `A` and its value to the remembered index.

10. **Exact-limit value end.** If value consumption ends exactly at the captured limit, the bounds diagnostic runs and status becomes `3`; value insertion is not reached.

11. **Partial transfer failure.** If operation six fails, four temporary saves and operation five have already occurred. Its failure code is stored, with no restoration attempt.
