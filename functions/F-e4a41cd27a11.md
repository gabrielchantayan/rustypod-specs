# F-e4a41cd27a11

## Purpose

F-e4a41cd27a11 combines two words from a shared mutable table, replaces one of those words with the result, advances two shared indices backward, and returns the low 31 bits of the result.

The index transitions are asymmetric. A negative decremented first index causes the first index to reset to 54 and prevents correction of the second index during that call. Otherwise, a negative decremented second index resets to 54. Consequently, the function does not maintain both indices within 0–54 for every possible entry state.

A circular additive generator is a plausible intended application. That interpretation is inferred intent, not an established requirement. It supplies no initialization rules, table-size guarantee, statistical properties, or invariant restricting the relationship between the indices.

## Interface

### Arguments and result

The function takes no explicit arguments. Its inputs are shared state reached through two global references.

The result is an unsigned integer containing bits 0–30 of the calculated table word. Its numerical range is 0 through 2,147,483,647. Zero is an ordinary result, not an error indication.

The return value is derived from the calculated value retained during the call, rather than from a subsequent read of the updated table element.

### Shared state and layout

The function requires:

| Object | Required contents and access |
|---|---|
| Index reference | A reference to a mutable record containing two consecutive signed integer fields |
| Index record | A first index followed immediately by a second index |
| Table reference | A base address for integer-word accesses at four-byte index intervals |
| Selected table storage | Readable words at both selected positions and writable storage at the second-index-selected position |

The supplied representation uses signed integer reads for both indices and both table operands, and an unsigned integer write for the calculated table word.

Four-byte table spacing supports a 32-bit-word interpretation. Under a corresponding four-byte integer layout, the index record occupies eight bytes, with its fields at offsets zero and four. The representation does not independently establish the target ABI, alignment rules, pointer width, or every integer type width. Numerical examples below therefore state a 32-bit interpretation explicitly.

There is no visible table-length field. Resetting an index to 54 suggests a nominal range of 0–54, for which 55 elements would suffice. Neither that allocation nor those entry bounds are checked.

The ordinary behavior described below requires:

## Behavior

### Selection of the table entries

Both table selections use entry-state indices, before any index correction. The second index selects both an operand and the destination. The first index selects the other operand.

The second-index value is retained for the table destination and its later decrement. The first index is read separately for its decrement calculation and for its table selection. Under stable-state preconditions, those first-index reads agree.

There is no normalization before access. An entry index outside 0–54 is not first reduced, clamped, or wrapped into that interval. Whether such an access is valid depends on the actual addressable storage and arithmetic.

For example, an entry first index of 55 selects position 55 before becoming 54. It does not select position 54 merely because 54 is the reset value.

### Combination and replacement

The two selected table words contribute a signed sum. When that sum is representable in the signed operand type, its value is converted to the unsigned result type and stored at the position selected by the entry second index.

The destination receives the entire calculated unsigned word. Clearing the high bit is a return-value operation, not a restriction on the stored word.

Under the 32-bit interpretation:

- A nonnegative representable sum retains its numerical value.
- A negative representable sum converts modulo \(2^{32}\).
- The return value is the stored calculated word reduced to its low 31 bits.

Thus a sum of −1 produces a stored word of 4,294,967,295 and a return value of 2,147,483,647. A sum of −2,147,483,648 produces a stored word of 2,147,483,648 and a return value of zero.

When both indices select the same position, the same entry supplies both operands and receives the result. There is no distinct same-position rule. The arithmetic precondition still applies: doubling a signed value can overflow even though the subsequent destination is unsigned.

No unconditional result is established for a signed sum outside the representable range.

### Index-state transition

Each entry index is decremented by one. The first decremented value controls which correction is available:

| First decremented value | Second decremented value | Final first index | Final second index |
|---|---|---|---|
| Negative | Any representable value | 54 | Second decremented value, without correction |
| Nonnegative | Negative | First decremented value | 54 |
| Nonnegative | Nonnegative | First decremented value | Second decremented value |

The test is negativity, not equality to −1. The transition therefore also describes other negative decremented values, provided all preceding accesses and arithmetic satisfy the preconditions.

The first row takes precedence. If both entry indices are zero, the final state is first index 54 and second index −1. The second index is not corrected later in that call.

A later invocation would select a table operand using that −1 before applying any index correction. Whether such a subsequent access is valid is not established.

### Required ordering relationships

The supplied representation establishes these logical ordering constraints:

- The index-record reference used for index writes is captured before the operand calculation.
- The second index is obtained before the first-index decrement calculation.
- The first-index decrement calculation precedes the table-word calculation, but its record update follows the table update.
- Both table operands are read before the calculated word is written.
- The table update precedes the index-record updates.
- The decremented first index is written before the decremented second index.
- Any reset to 54 follows those decrement writes.

For a first-index reset, the first field therefore passes through its decremented value before receiving 54. For a second-index reset, the second field similarly passes through its decremented value.

The representation does not establish the relative evaluation order of the two table operand reads. It also does not justify treating repeated global-reference accesses as a single atomic snapshot.

These are logical access and mutation relationships. They do not establish that every intermediate write must remain a separately observable machine store under an unspecified compilation and memory model.

## Side effects

The intended mutation footprint is limited to the table word selected by the entry second index and the two index fields. With disjoint objects and stable references, other table words and the global references themselves remain unchanged.

The table update is committed logically before the index updates. No rollback mechanism is shown. The function is not established to be atomic, synchronized, reentrant, or transactional.

The separate reads matter when assessing aliasing or external mutation. In particular:

- The reference used for index writes has already been captured.
- Later index reads still obtain values through the global reference.
- The first index is read more than once.
- Table addressing refers to global table-reference state.

If references or overlapping storage change during the call, the ordinary description using one stable index record and one stable table is insufficient. Such executions are documented_only rather than assigned guessed snapshot semantics.

The evidence does not specify a diagnostic, exception, error return, or preserved-state guarantee for those cases. A failure after a mutation has begun has no established rollback behavior.
