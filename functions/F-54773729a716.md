# F-54773729a716

## Purpose

F-54773729a716 describes a recovered, incomplete execution prefix whose observable behavior consists of address-derived memory accesses, an indirect invocation, shared-state replacement, and overlapping record-like writes.

The available static evidence establishes neither a normal return nor a successful initialization operation. The representation stops at an invalid-instruction recovery boundary. It does not establish whether the executable actually traps there, continues through instructions not recovered, or can reach that boundary without an earlier fault.

The contract below distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied fragment.
- **Inferred intent:** some final writes resemble linked-record initialization. This interpretation provides no object-validity, allocation, or ownership guarantee.
- **documented_only:** behavior that cannot be resolved from the supplied evidence.

The contract concerns the represented prefix, not an independently verified machine-code execution.

## Behavior

### Entry observations and first writes

Before the indirect invocation, the routine captures the saved-word cell and then the displacement cell. The latter is interpreted as signed.

The next memory read is a 32-bit pointer read at the address obtained by doubling the index argument. There is no separate table-base addition. Thus this is not established as a conventional indexed lookup within a supplied array.

After that read, the routine stores the byte argument at the incoming ambient address plus 15 bytes. It then stores the low 16 bits of the loaded pointer at the address designated by that pointer.

The second store is self-address-derived: its value comes from the pointer representation, not from the contents of the pointed-to storage. No halfword read from that destination is represented.

These entry accesses precede the indirect invocation. Their destinations may overlap shared cells or later destinations. Consequently, initial captures and later shared-cell reads need not agree even before considering the indirect operation.

No bounds, null, alignment, or permissions check is visible.

### Anchor-derived addressing and invocation

Using the initially captured displacement, the routine forms an address relative to a fixed image anchor, converts that result to a signed 32-bit integer, and multiplies it by four. This intermediate is formed before the invocation.

The anchor’s declaration is absent. Its element size, and therefore the scale of the displacement in the anchor-relative addition, is **documented_only**. A byte-address interpretation must not be silently assumed.

The invocation target is the incoming link value with its two lowest bits cleared, followed by addition of `0x684`. The mask clears both low bits; it is not merely a single-bit adjustment.

The recovered invocation has no explicit argument list or established return contract. Its continuation consumes a 32-bit register value available afterward. That observation does not establish a conventional function return value.

The indirect operation may change shared cells, reachable memory, or other state. No preservation, allocation, release, or ownership behavior is known. All subsequent behavior is conditional on execution reaching the represented continuation.

### First post-invocation destinations

The pre-invocation arithmetic intermediate is multiplied by four again to obtain a word-store address. The post-invocation register value is written there as a 32-bit word.

A second destination is derived from that word-store address, not from the word just stored. The address advances by one 32-bit element, which is four bytes. Its resulting 32-bit value is interpreted as signed and shifted right by 12. A halfword is then stored 40 bytes beyond the shifted value, with the stored halfword taken from the shifted value itself.

In particular:

- The four-byte advance occurs before the shift.
- The 40-byte destination adjustment occurs after the shift.
- The low 16 bits written do not include that final 40-byte adjustment.

Signed right shift of negative values and overflow in the preceding signed calculations require an instruction-level interpretation not supplied here. Arithmetic shift and wrapping arithmetic are therefore conditional models, not unconditional guarantees.

### Shared-state replacement and address-cell observations

After those two post-invocation stores, the address cell is read and its 32-bit address value retained for a later scaled-address store. The first record base is derived by multiplying the post-invocation register value by four.

The replacement cell is then read and its value written to the displacement cell. The initial saved word is written to the forwarded-word cell. Both writes occur before the next address-cell observation.

The address cell is next read for its low 16 bits. This is a truncation of the cell’s address-bearing value; it is not a read through that address.

After capturing those bits, the routine writes the first record base into the replacement cell and the index-derived pointer into the saved-word cell. Only then does it read the address cell again as the destination of an immediate halfword store. That store uses the previously captured low 16 bits.

There are therefore three distinct address-cell observations:

| Observation | Purpose |
|---|---|
| First | Retains an address for a later multiplication by 16. |
| Second | Supplies the low 16-bit value used by two subsequent stores. |
| Third | Supplies the destination of the immediate address-directed store. |

They cannot be replaced by one assumed-stable observation. Intervening writes may affect overlapping storage, and the indirect invocation may already have changed the cell.

The replacement value copied to the displacement cell is read after the invocation. The saved word copied to the forwarded-word cell was captured before it.

### Record-region writes and terminal boundary

The low halfword obtained from the second address-cell observation is also stored two bytes into the first record region. This follows the immediate address-directed halfword store.

Next, the address retained by the first address-cell observation is multiplied by 16. The routine stores the low 16 bits of that scaled address at the scaled address itself. This destination does not come from a fresh address-cell read.

A second record base is then derived by multiplying the post-invocation register value by eight. The cleared cell receives zero before the full-width record writes begin.

The remaining writes have the following layout and relative order:

| Region | Offset in bytes | Width | Stored value |
|---|---:|---:|---|
| First record | 0 | 32 bits | Second record base |
| First record | 4 | 32 bits | Index-derived pointer |
| First record | 8 | 32 bits | Initially captured saved word |
| Second record | 0 | 16 bits | Low 16 bits of the initially captured saved word |
| Second record | 0 | 32 bits | Second record base |
| Second record | 12 | 32 bits | Second record base |

The final offset is 12 bytes because the represented address advances by six halfword elements.

The halfword store at first-record offset 2 precedes, and occupies bytes later covered by, the word store at first-record offset 0. Similarly, the halfword store at the second record base precedes a word store at that same base. These are distinct accesses even where ordinary memory ultimately retains only the later value.

The representation ends after the final self-address store, at an invalid-instruction recovery boundary. No subsequent behavior is established.

## Acceptance examples

These examples are conditional specifications, not executed tests. Unless otherwise stated, assume suitable mappings and permissions, sufficient alignment, ordinary memory, no interfering aliases, return from the indirect invocation, 32-bit wrapping arithmetic, and arithmetic signed right shift.

### Direct index addressing and self-address truncation

For index `0x100`, the pointer read is at `0x200`, without a table-base adjustment.

If that read yields `0x12345678`, the halfword written at `0x12345678` is `0x5678`. No contents from that destination are needed to determine the stored value.

With ambient address `0x2000` and byte argument `0xA5`, the byte store writes `0xA5` at `0x200F`. It precedes the halfword store at the loaded pointer.

### Invocation target

For incoming link value `0x1003`, clearing the two low bits produces `0x1000`, and the invocation target is `0x1684`.

This does not establish that executable code exists there or that the invocation resumes the continuation.

### Shift-derived store

If the anchor-derived word-store address is `0x00012000`, the post-invocation word store occurs there. Advancing by four produces `0x00012004`; shifting right by 12 produces `0x12`.

The following halfword store therefore targets `0x3A` and stores `0x0012`, not `0x003A`.

Under the conditional wrapping and arithmetic-shift model, a word-store address of `0xFFFFFFFC` advances to zero, yielding a halfword destination of `0x28` and value zero. This illustrates the model only; overflow semantics are unresolved in the static evidence.

### Record contents and overwritten accesses

For post-invocation register value `0x1000`, the first record base is `0x4000` and the second is `0x8000`.

The first record receives words at `0x4000`, `0x4004`, and `0x4008`, containing respectively `0x8000`, the index-derived pointer, and the initial saved word. The second receives self-address words at `0x8000` and `0x800C`, both containing `0x8000`.

A conforming access trace still includes the earlier halfword stores at `0x4002` and `0x8000`; their later overwrite does not make them optional.

### Captured state versus current state

If the saved-word cell initially contains `0x11223344` and the invocation changes that cell, the forwarded-word write and first-record offset-8 write still use `0x11223344`, absent an execution discrepancy outside the represented prefix.

Conversely, the value copied from the replacement cell is its post-invocation value, including effects of earlier aliasing stores.

### Three address-cell observations

Suppose the first address-cell observation is `0x900`, so its later scaled destination is `0x9000`. Suppose subsequent overlapping writes make the second observation `0x12345678` and the third `0x2000`.

The immediate address-directed store writes `0x5678` at `0x2000`. The first-record offset-2 store also uses `0x5678`. The later scaled-address store instead writes `0x9000` at `0x9000`.

These outcomes depend on the stated observations being possible under the actual storage layout; that layout is not supplied.
