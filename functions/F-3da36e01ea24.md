# F-3da36e01ea24

## Purpose

F-3da36e01ea24 selects a 32-bit value from two externally stored values according to whether its sole input equals the integer 3.

The supplied static representation establishes an asymmetric selection rule:

- The first stored value is read on every invocation.
- When the input equals 3, the second stored value is subsequently read and becomes the result.
- For every other input, the result is the value obtained from the first read.

The meanings of the two stored values are not established. Describing them as defaults, configuration entries, status codes, addresses, or handles would introduce unsupported semantics. This contract calls them **storage A** and **storage B** solely to distinguish their roles.

**Input**

One 32-bit integer argument is represented in the supplied evidence. Its only use is an equality comparison with 3.

The selection rule does not depend on ordering, magnitude, or arithmetic. Consequently, signed and unsigned interpretations of the same 32-bit argument produce the same branch decision: only the bit pattern representing 3 selects storage B.

The exact machine calling convention, argument-register assignment, and treatment of values supplied through an incompatible caller interface are not established.

The supplied representation does not establish whether callers interpret this result as an integer, an enumeration, a pointer representation, or another kind of token.

## Behavior

### Selection and read order

The first visible data-access operation obtains the 32-bit value from storage A. That value is the provisional result.

The function then distinguishes the argument value 3 from all other argument values.

If the argument equals 3, the function obtains the 32-bit value from storage B and uses that second value as the result. The earlier value from storage A does not contribute to the returned bits on this branch.

If the argument does not equal 3, no read of storage B is shown. The result remains the value previously obtained from storage A.

The function then returns the selected value.

This distinction concerns both the result and the represented access sequence. For an argument of 3, the supplied representation describes a read of storage A followed by a read of storage B, not merely a direct read of storage B. Whether those reads are independently observable on the actual target depends on memory attributes and executable details that are not supplied.

### Value preservation

The selected value is returned unchanged at the represented 32-bit width.

In particular:

- Zero is not treated specially.
- A value with its highest bit set is not rejected or normalized.
- A value whose bits could represent an address is not dereferenced.
- Equal contents in the two storage locations produce equal return values for both branches, without eliminating the represented difference in read behavior.

There is no arithmetic on the argument or stored values. Overflow, saturation, rounding, and arithmetic wraparound therefore do not arise within the visible function.

### State dependence

The return depends on the value obtained by the relevant read during that invocation, not on a value cached by this function across invocations.

The visible function maintains no persistent local state. It does not establish that either storage location remains unchanged between invocations.

No consistency relationship between storage A and storage B is enforced. In particular, the argument-3 branch does not construct a combined snapshot from both values; it discards the first value and returns the second.
