# F-0c8666b0fd7f

## Purpose

F-0c8666b0fd7f repeatedly invokes indirect dependencies and updates memory through incoming state, captured global pointers, selectors, and dependency results. The supplied body establishes an unconditional loop with **37 indirect call sites per complete pass**, one software breakpoint, and no normal return.

The observable contract is an ordered sequence of calls, reads, and writes. No application-level purpose, such as initialization or device servicing, is established. Those interpretations must not supply additional requirements.

A complete pass requires every dependency to return, every memory access to complete, and execution to continue past the breakpoint. Earlier writes are not rolled back if progress stops.

### Widths and arithmetic

The representation distinguishes 8-bit, 16-bit, and 32-bit memory accesses, and 64-bit dependency results split into low and high 32-bit words.

For describing the represented machine-value calculations:

- Unsigned 16-bit reads are zero-extended.
- Byte and halfword stores retain the low 8 or 16 bits, respectively.
- Low and high words of a 64-bit result are treated independently.
- A logical right shift of a 32-bit value by 26 yields a value from 0 through 63.
- Left shifts by 2 or 6, multiplication by 4, and address-related additions retain their represented 32-bit results.
- Decreasing the context base by `0xF4` changes the address-like state used on subsequent passes.

These rules describe bit-pattern behavior, not permission to reproduce potentially overflowing signed arithmetic in a particular implementation language. The architectural address model, byte order, alignment rules, and validity of the reconstructed context state are not independently established.

These are conditional static acceptance examples, not executed tests. Each assumes preceding events complete and relevant addresses are accessible.

3. **Argument addition.** If F-000000000005 supplies low word `0xFFFFFFFF` and high word 2, F-000000000006 receives `0xFFFFFFFF` and 1 under the represented 32-bit arithmetic.

4. **Breakpoint termination.** If execution permanently stops at breakpoint `0x92`, F-000000000019 has already returned, but no post-breakpoint access or invocation from that pass occurs.

5. **Selector boundaries.** A second selector of zero produces a word-store address of `0x74` and a byte-read address of zero. A second selector of `0xFFFF` produces addresses `0x40070` and `0x4FFFB`, respectively. No range rejection is represented.

6. **Captured payload.** A payload read of `0xFFFF` causes both destination-record payload stores to write `0x0000FFFF`. Changes to the payload source between those stores do not alter the retained value.

7. **Pointer narrowing.** If captured pointer B ends in `0xABCD`, the halfword stored at pointer B plus the scaled result is `0xABCD`.

8. **Final call boundary.** Once F-000000000036 returns, control is assigned `0x08712031`, then the final argument word is read, then F-000000000037 is invoked. No intervening indirect call is part of this body. If that read fails, the control assignment has occurred but the final call has not.
