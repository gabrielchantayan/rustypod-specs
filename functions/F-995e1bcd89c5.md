# F-995e1bcd89c5

## Purpose

F-995e1bcd89c5 conditionally performs receiver-state transitions, then dispatches an event through a virtual method. A fallback virtual method is eligible only when primary dispatch returns zero and the event’s then-current contents satisfy additional conditions.

The transition phase is gated by an initial event discriminator of `0x70001`. Depending on the receiver’s narrowed state value, it can issue the named operations `EnterDefault` and `EnterVolume`, write a state byte, and invoke F-979606fd565e with a value read from external storage.

Transition-call results do not determine the function’s return value. The returned 32-bit integer comes from primary dispatch, qualifying fallback dispatch, or an explicit zero result.

These are static behavioral findings. “Receiver,” “event,” and “transition” identify structural roles, not established application semantics.

## Interface

### Inputs and result

The function accepts four inputs:

1. **Receiver address:** an address identifying object storage containing a virtual-table pointer and the fields described below.
2. **Event address:** a 32-bit address value identifying the event record.
3. **First opaque value:** a 32-bit value.
4. **Second opaque value:** a 32-bit value.

The supplied representation uses 32-bit integers and address-bearing values. Each input is initially copied into its own addressable local slot. Some dependencies receive addresses of these slots.

Subsequent receiver accesses and event accesses use the original receiver and event arguments, not the potentially modified local copies. A dependency’s modification of a local copy alone therefore does not redirect later accesses through the original argument. Dependencies may nevertheless modify the objects those original addresses identify.

The function returns a 32-bit integer:

- A nonzero primary-dispatch result is returned unchanged.
- If primary dispatch returns zero and fallback is invoked, its nonzero result is returned unchanged.
- Otherwise, the result is zero.

There is no normalization to one. A negative 32-bit result is nonzero and is propagated unchanged.

### Relevant storage

All offsets are byte offsets.

| Storage | Offset | Established access |
|---|---:|---|
| Receiver | `+0x00` | Read the virtual-table address when resolving a selected virtual call |
| Receiver | `+0x50` | Read a 32-bit integer for fallback comparison |
| Receiver | `+0xB0` | Read a 32-bit integer, then narrow it to an eight-bit character value for comparison with one |
| Receiver | `+0x140` | Read a 32-bit integer, then narrow it to an eight-bit character value for transition selection |
| Receiver | `+0x140` | Separately, write exactly one byte with value five on the volume path |
| Event | `+0x04` | Read a 32-bit discriminator |
| Event | `+0x08` | Read a 32-bit nested-record address or comparison value, depending on the current discriminator |
| Nested record | `+0x04` | Read a 32-bit subtype |
| External storage | Unspecified | Read the value supplied as the second argument to F-979606fd565e |

The reads at receiver offsets `+0xB0` and `+0x140` are **integer-width memory reads followed by narrowing**. They are not byte-sized memory reads. Byte-only accessible storage at either location is insufficient to satisfy the shown access requirements.

The state write at `+0x140`, by contrast, is explicitly one byte wide. Its width must not be generalized to the preceding state read.

### Preconditions and addressing

Every executed dereference requires valid, suitably accessible storage for its full access width. Selected virtual-table entries must identify callable methods with the required calling convention.

An event whose discriminator is `0x16` at primary-selection time requires a valid nested-record address at event offset `+0x08` and an accessible 32-bit subtype at nested offset `+0x04`.

No null checks, bounds checks, type checks, lifetime checks, or address-overflow recovery are established. Fixed-offset address calculations must lead to valid storage on the executed path; this contract does not define behavior for invalid addresses.

## Behavior

### Initial copies and transition selection

The four input values are copied into separate local slots before the initial discriminator read.

The function then reads the 32-bit discriminator at event offset `+0x04`.

- If it differs from `0x70001`, no transition-state read or transition call occurs.
- If it equals `0x70001`, the function reads the 32-bit receiver field at `+0x140` and narrows the value to an eight-bit character for state selection.

Only narrowed values one through six select transition paths. Zero and every other narrowed value skip the transition phase.

| Narrowed state | Selected transition behavior |
|---:|---|
| `1` | Perform `EnterVolume`, write the state byte, then invoke F-979606fd565e |
| `2` | Invoke F-995e1bcd89c5.V1, then perform the conditional-default and volume sequence |
| `3` | Perform the conditional-default and volume sequence |
| `4` | Perform the conditional-default and volume sequence |
| `5` | Invoke F-979606fd565e without either named operation or an explicit state write |
| `6` | Perform the conditional-default and volume sequence |

The virtual dependency identifiers used here are defined under **Dependencies**.

The selected state path is not recomputed after calls. In particular, a state-two call that changes the receiver’s state does not cause a second state selection.

The higher bits of the loaded state integer do not independently select a path once narrowing has occurred. Character signedness does not distinguish the recognized values one through six; other narrowed values take the non-transition path.

### Conditional `EnterDefault`

This phase applies only to selected states two, three, four, and six.

For state two, F-995e1bcd89c5.V1 runs first with the original receiver as its sole explicit argument. Its return value is ignored.

The function next reads the **32-bit integer** at receiver offset `+0xB0`, narrows it to an eight-bit character, and compares that narrowed value with one. For state two, this read occurs after F-995e1bcd89c5.V1 returns, so that call can affect the decision.

If the narrowed value is not one, the default operation is skipped. If it is one, the following calls occur in order:

1. F-9b9c1c7483f4 receives the address of the local event-copy slot, the operation token `EnterDefault`, and the address of the local receiver-copy slot.
2. Its returned 32-bit value is passed, together with the original receiver, to F-995e1bcd89c5.V2.
3. F-8a5aadac202f receives the address of the same local event-copy slot.

The virtual-call result and any result from F-8a5aadac202f are ignored. No validation of the value returned by F-9b9c1c7483f4 is shown; zero or another unusual value is still forwarded.

Whether this default operation runs or is skipped, these four selected states continue to the volume operation.

### `EnterVolume`, state write, and external read

The volume phase applies to selected state one and to selected states two, three, four, and six after the conditional-default phase.

Its observable sequence is:

1. F-9b9c1c7483f4 receives the address of the local second-opaque-value slot, the token `EnterVolume`, and the address of the local first-opaque-value slot.
2. Its returned 32-bit value is passed, together with the original receiver, to F-995e1bcd89c5.V2.
3. F-8a5aadac202f receives the address of the same local second-opaque-value slot.
4. Exactly one byte at receiver offset `+0x140` is written with value five.
5. The external storage value used as F-979606fd565e’s second argument is read.
6. F-979606fd565e is invoked with the original receiver and that read value.

The external value is obtained when this call is reached. It is not established as an entry-time snapshot, cached value, constant, or invariant. Earlier dependencies may change the external storage before it is read. On this path, the external read also follows the explicit byte-five state write.

For selected state five, the function proceeds directly to the external-storage read and F-979606fd565e invocation. It performs neither named operation and makes no explicit state-byte write on that path.

The external value’s contents, semantic type, and access width are not established by the supplied representation. Those unknowns do not remove the established read or its ordering. F-979606fd565e’s result is ignored.

### Primary dispatch

Every normally completing transition path reaches primary dispatch. Skipping the transition reaches the same phase.

The function freshly reads the 32-bit discriminator at event offset `+0x04`. It does not reuse the initial discriminator.

- A discriminator other than `0x16` selects F-995e1bcd89c5.V4.
- A discriminator of `0x16` causes a 32-bit read at event offset `+0x08`, interpreted as a nested-record address. The function then reads the 32-bit subtype at nested offset `+0x04`.
  - Subtype `0x2A` selects F-995e1bcd89c5.V3.
  - Any other subtype selects F-995e1bcd89c5.V4.

The selected method receives the original receiver and original event address. Its virtual target is resolved from the receiver’s virtual table after the selection reads.

A nonzero result is returned immediately and unchanged. No fallback discriminator or comparison-field reads occur on that path.

### Fallback dispatch

Fallback evaluation begins only when primary dispatch returns zero.

The function freshly reads the event discriminator at `+0x04`. Primary dispatch may have changed it.

If it is not `0x0F`, the function returns zero without reading either fallback comparison field.

If it is `0x0F`, the function reads:

1. The 32-bit event field at `+0x08`.
2. The 32-bit receiver field at `+0x50`.

If the values differ, the function returns zero without invoking fallback. If they match, F-995e1bcd89c5.V5 receives the original receiver and event address.

A nonzero fallback result is returned unchanged. A zero fallback result produces zero. No further retry, alternate dispatch, or explicit restoration follows.

## Side effects

### Direct effects

The function initializes four local input copies. Its only established direct write to caller-reachable object storage is the one-byte assignment of five at receiver offset `+0x140` on the volume path.

That assignment does not itself overwrite adjacent bytes. It also does not prove that the state remains five at return: F-979606fd565e and event dispatch execute afterward and may alter it.

No direct event-field write is shown.

### Effects through dependencies and aliasing

Dependency bodies are unavailable. They may modify receiver storage, event storage, virtual tables, the external storage read for F-979606fd565e, or other reachable state.

Accordingly:

- The state-two default-condition read observes storage after F-995e1bcd89c5.V1.
- Virtual targets are not assumed stable across earlier calls.
- Primary selection observes the event after transition dependencies.
- Fallback observes the event and comparison fields after primary dispatch.
- The external argument observes external storage when its call is reached, not when the function was entered.

No dependency is assumed to preserve globals.

Distinctness of receiver, event, nested record, and externally accessible storage is not established. If valid aliasing makes an earlier write affect a later-read location, the later read observes the resulting storage. The contract does not impose a disjoint-storage model.

### Ownership, lifetime, and failures

F-9b9c1c7483f4 and F-8a5aadac202f receive addresses of invocation-local slots, not the caller’s argument slots. Those local addresses are not valid as this invocation’s storage after it returns.

The paired calls suggest temporary-value handling, but allocation, ownership transfer, retention, destruction, reference counting, and release behavior remain unknown. In particular, F-8a5aadac202f is not established to be a deallocator.

There is no explicit error-reporting protocol for inaccessible storage, invalid virtual targets, or dependency failure. No rollback or guaranteed cleanup is established if a call fails to return normally. A zero dispatch result is a control-flow condition, not independently an established error code.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations. Assume valid full-width storage, normally returning dependencies, and no relevant mutations except those stated. Every transition example explicitly requires initial discriminator `0x70001`.

1. **Transition gate absent.** With initial discriminator `0x0F` and narrowed state one, no transition-state read or transition operation occurs. Primary dispatch still runs.

2. **Unrecognized state.** With initial discriminator `0x70001` and narrowed state seven, no transition dependency runs. The discriminator is reread for primary selection.

3. **State one bypasses the default condition.** With initial discriminator `0x70001` and narrowed state one, `EnterVolume` runs even if the narrowed field at `+0xB0` would equal one. That field is not read for the default condition on this path.

4. **State two observes a changed condition.** With initial discriminator `0x70001` and narrowed state two, F-995e1bcd89c5.V1 runs first. If it changes the integer at `+0xB0` so its narrowed value becomes one, `EnterDefault` precedes `EnterVolume`.

5. **State three skips default entry.** With initial discriminator `0x70001`, narrowed state three, and a `+0xB0` integer narrowing to two, `EnterDefault` is skipped. `EnterVolume`, the byte-five write, the external read, and F-979606fd565e still occur.

6. **State five takes the direct path.** With initial discriminator `0x70001` and narrowed state five, neither named operation occurs and there is no explicit state write. External storage is read before F-979606fd565e is invoked.

7. **Narrowing is distinct from access width.** With initial discriminator `0x70001` and a 32-bit state value `0x00000101`, narrowing selects state one. The selection still requires the full 32-bit state-field read.

8. **External storage changes before use.** On a volume path, if an earlier dependency changes the relevant external storage from value A to value B and it remains B until the argument read, F-979606fd565e receives B. That read follows the byte-five write.

9. **Transition changes primary selection.** If a transition dependency changes the event discriminator to `0x16` and supplies a valid nested record with subtype `0x2A`, primary dispatch uses F-995e1bcd89c5.V3.

10. **Nonzero primary result suppresses fallback.** If primary dispatch returns `-3`, the function returns `-3` unchanged without fallback-field reads.

11. **Fallback observes post-dispatch storage.** If primary dispatch returns zero after making the discriminator `0x0F` and the two comparison fields equal, F-995e1bcd89c5.V5 runs. Its result determines the function result.

12. **Fallback mismatch.** With zero primary result, current discriminator `0x0F`, and unequal comparison fields, fallback is not invoked and the result is zero.
