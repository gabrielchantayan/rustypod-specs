# F-6363e4dd5e55

## Purpose

F-6363e4dd5e55 performs an ordered preparation sequence, obtains a decision from a dependency, and conditionally invokes an indirect callable stored at byte offset 20 from a working base address.

Its established behavior has three outcomes:

- A nonzero decision causes a 32-bit zero result.
- A zero decision with a non-null callable causes an indirect invocation using the original third input; the callable’s 32-bit result becomes this function’s result.
- A zero decision with a null callable transfers control to F-a817d8d58c10, which is represented as non-returning.

The preparation sequence can modify addressable local state. In particular, the working base used for the final callable lookup is not necessarily the original first input.

Any interpretation as a particular object operation, resource protocol, or callback framework is inferred intent, not an established contract.

### Decision preparation and decision call

After the three preparation calls return normally:

1. The function reads exactly one four-byte value from the original first input plus 20 bytes.
2. It stores that value in the mutable slot initially containing the second input.
3. It calls F-0c3ebe6e88e3 with:
   - The address of the mutable working base.
   - The address of the newly loaded four-byte value.

The original second input’s local copy is overwritten before this decision call. The second input had already been passed by value to F-9b9c1c7483f4.

F-0c3ebe6e88e3 can change both addressed local values. The function branches on whether its returned integer is exactly zero; it does not require a normalized Boolean result.

### Nonzero decision

If F-0c3ebe6e88e3 returns any nonzero value:

- The result is set to the 32-bit value zero.
- No callable-pointer access is performed by this function after the decision.
- No indirect callable is invoked.
- The function returns.

The original-base offset-20 read has already occurred. A nonzero decision does not bypass preparation or that earlier read.

### Zero decision

If F-0c3ebe6e88e3 returns zero:

1. The function uses the current working base to read the callable pointer at byte offset 20.
2. If that pointer is null, it calls F-a817d8d58c10.
3. Otherwise, it fetches the callable pointer at the current working base plus 20 for the indirect invocation.
4. It invokes that callable with the original third input as its sole displayed argument.
5. It returns the callable’s four-byte result.

The callable argument is not the mutable copy of the third input. A change to that copy through F-9b9c1c7483f4 does not replace the original third input used here.

The null check and invocation are represented as separate field accesses. The available evidence does not establish a single cached callable value or an atomic check-and-call operation. No additional validation appears between the check and invocation.

F-a817d8d58c10 is represented as non-returning. There is no established continuation contract if it unexpectedly returns.
