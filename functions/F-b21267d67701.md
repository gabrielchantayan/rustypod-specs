# F-b21267d67701

## Purpose

F-b21267d67701 describes a short, low-level execution fragment that initializes two global storage locations, obtains a pointer through an indirect call, clears a two-byte object through that pointer, invokes a second indirect dependency, and performs additional writes derived from an incoming signed value.

The recovered fragment ends at an invalid-instruction boundary. It does not establish successful completion, a normal return, or a coherent application-level purpose. In particular, the writes to addresses derived from a sign-shift result must not be reinterpreted as ordinary object initialization without further evidence.

This contract distinguishes:

- **Established static evidence:** operations explicitly represented in the supplied fragment.
- **Inferred interpretation:** the likely 32-bit machine model and arithmetic interpretation needed to describe those operations concretely.
- **documented_only unknowns:** ABI details, dependency behavior, memory validity, and execution beyond the invalid-instruction boundary.

No runtime tests have been performed.

## Behavior

### 1. Initial global writes

The fragment first writes the numeric value `0x28` to Global A. It then writes zero to Global B.

These writes precede the first dependency invocation. Their access widths, byte order, and possible interaction with overlapping symbols remain undocumented.

A write to Global B is established. An actual supervisor instruction, privilege transition, or system service invocation is not established merely by the associated symbol.

### 2. First dependency invocation

The fragment computes a byte-read address from the address seed:

- XOR the seed with `0x0897F3A8`.
- Multiply the result by `0x200`.

Under the inferred unsigned 32-bit model, multiplication retains the low 32 bits. Consequently, the computed address is a multiple of 512, and only the low 23 bits of the XOR result affect that address.

One byte is read at the computed address. That byte is interpreted as a plain character and converted to the integer passed as the first dependency argument. The second argument is zero.

Whether the character conversion sign-extends or zero-extends bytes whose high bit is set is not established. Accordingly:

- Bytes from `0x00` through `0x7F` have an unambiguous nonnegative numeric interpretation.
- Bytes from `0x80` through `0xFF` may become either negative integers or integers from 128 through 255, depending on the character signedness represented by the recovery.

The first call target is the call base plus `0xA84`, subject to the actual address-width and instruction-set rules. No explicit instruction-set-bit normalization is shown for this target.

The dependency is identified here as **F-indirect-01**. Its return value is used as a pointer to two-byte storage.

The byte read must occur before invocation with its resulting argument. The supplied representation does not establish the original instruction-level ordering of otherwise independent address calculations.

### 3. Returned-object clear and second dependency

If F-indirect-01 returns, the fragment writes zero through the returned pointer using a two-byte store.

It then invokes **F-indirect-02**, passing that same pointer as its sole visible argument.

The second target is formed from the constant `0x0897F3D5` by clearing its low two bits and adding `0x604`. The resulting numeric target is:

**`0x0897F9D8`**

The two-byte zero write precedes this invocation. There is no visible check of the returned pointer and no visible branch around the store.

The fragment does not use the second dependency’s return value. It also contains no later explicit access through the returned-object pointer.

No ownership interpretation follows from this sequence. In particular, the second dependency may inspect, retain, modify, transfer, or release the object; none of those behaviors is established here.

### 4. Signed-seed-derived write

After F-indirect-02 returns, the fragment shifts the signed seed right by four and uses the result as an address. It writes the 16-bit value `0xF484` there.

The recovered signed type suggests an arithmetic right shift. That interpretation is an inference, not an independently verified instruction property.

Under arithmetic right shift:

- A nonnegative seed produces its value divided by sixteen, rounded down.
- A negative seed produces a negative shifted result, subsequently interpreted as an address.

The store width is two bytes. Its byte representation depends on the target’s byte order.

No address masking, alignment adjustment, or validation is visible.

### 5. Final global and sign-derived writes

The remaining operations occur in this order:

1. Write zero to Global C.
2. Shift the signed seed right by thirty-one and use the result as the sign location.
3. Store the low byte of that result at the sign location.
4. Store the sign-location pointer at the output destination.
5. Store the low sixteen bits of the shifted result at the sign location plus `0x34`.

Under arithmetic right shift in the inferred 32-bit model:

| Signed seed | Shift result | Sign-location address | Byte stored there | Halfword value stored at address plus `0x34` |
|---|---:|---:|---:|---:|
| Nonnegative | `0` | `0x00000000` | `0x00` | `0x0000` |
| Negative | `−1` | `0xFFFFFFFF` | `0xFF` | `0xFFFF` |

The output destination receives the sign-location pointer, not the byte stored through that pointer.

For a nonnegative seed, the final halfword address is `0x00000034`.

For a negative seed, ordinary 32-bit machine-address wrapping would produce `0x00000033`. This is conditional on the recovered expression representing machine address arithmetic with that wrap behavior. It is not a portable object-pointer operation, and the fragment does not establish a valid object spanning these accesses.

- The `0xF484` halfword write targets address `0x00000010`.
- The sign-derived byte write targets address zero and writes zero.
- The output destination receives pointer value zero.

If the signed seed is −16, arithmetic right shift by four produces −1.

Under 32-bit machine address interpretation, the `0xF484` halfword store therefore targets `0xFFFFFFFF`. Execution may fail there before reaching the later sign-derived writes. No boundary-crossing or wrap behavior for that two-byte memory access is established.

If execution nevertheless reaches the later writes, the sign byte is `0xFF`, and the output destination receives `0xFFFFFFFF`. The final halfword value is `0xFFFF`; its address is `0x00000033` only under wrapping address addition.

### Failure after partial progress
