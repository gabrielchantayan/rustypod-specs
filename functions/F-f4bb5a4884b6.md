# F-f4bb5a4884b6

## Purpose

F-f4bb5a4884b6 dispatches on a 32-bit selector, invokes selector-dependent dependencies, copies four 32-bit words from a shared source region into an object, and stores the result of a final dependency call.

Selectors 0 through 8 take supported paths and return the 32-bit value 1 after completing their calls and writes. Every other selector invokes a different dependency with the object address and the constant 0x500, then returns the 32-bit value 0.

These return values distinguish dispatch paths. They do not establish that dependencies succeeded: the function neither checks their status nor interprets the final dependency’s result before returning 1.

## Interface

### Inputs

The function has two inputs:

| Input | Established representation | Role |
|---|---|---|
| Object address | 32-bit address-bearing value | Base address for object-relative accesses and dependency arguments |
| Selector | 32-bit value | Selects one of nine supported paths or the unsupported-selector path |

The object’s concrete type is unknown. The following offsets are byte offsets from its base:

| Offset | Access by this function | Meaning established here |
|---|---|---|
| 0x918 | Address passed to a dependency | First interior-address argument to the final call |
| 0x9F8 | Address passed to a dependency | Third argument to the final call |
| 0xA8C | Read as a 32-bit word | Argument to selector-dependent dependencies |
| 0xA9C | Written as a 32-bit word | First copied word |
| 0xAA0 | Written as a 32-bit word | Second copied word |
| 0xAA4 | Written as a 32-bit word | Third copied word |
| 0xAA8 | Written as a 32-bit word | Fourth copied word |
| 0xAAC | Written as a 32-bit word | Result of the final dependency call |

The four copied words occupy 16 contiguous bytes. The final result occupies the next four bytes. Successful supported execution therefore requires valid direct writes through offset 0xAAF, as well as a valid read at 0xA8C. This does not establish the object’s allocation size: dependencies may require additional storage.

A shared location supplies a source-region base address. Its contents are read once after the initial dependency returns. This captured base is used for all subsequent source accesses in that invocation.

### Output

The normal return is a 32-bit value:

- **1:** a supported selector path completed, including the final dependency call and result store.
- **0:** an unsupported selector path completed its designated dependency call.

There is no established exception, fault, or nonlocal-exit contract. If a dependency does not return normally, the corresponding normal return is not established.

### Preconditions and representation

For supported selectors, the source base must support the selected 32-bit reads through the offsets identified below. The object-relative addresses supplied to dependencies must satisfy those dependencies’ requirements, which are unknown here.

All copied values are opaque 32-bit words. No signed, floating-point, pointer, coordinate, or enum interpretation is established for them. Copying does not perform numeric conversion.

Address offsets are byte displacements. The evidence shows a 32-bit address model but does not establish portable behavior for overflowing address arithmetic, misalignment, or invalid addresses. Such cases are outside the established normal-execution contract.

## Behavior

### Entry and source-base capture

Every invocation begins by calling **F-04ee7ef2ef8d**, with no explicit arguments.

After that call returns, the function reads the shared source-base location and retains the resulting address. This occurs before selector dispatch, including for unsupported selectors.

Consequently:

- The initial dependency can affect which source base is captured.
- A later dependency’s change to the shared base location does not redirect this invocation’s subsequent source accesses.
- The source words themselves are not captured at entry. Later dependency calls can change the words subsequently read through the retained base.

No claim is made that any dependency preserves the object, the shared base location, or the source storage.

### Supported-selector dispatch

Each supported path first reads the current 32-bit word at object offset 0xA8C and passes it to an opening dependency. After that dependency returns, the function copies four words into object offsets 0xA9C, 0xAA0, 0xAA4, and 0xAA8.

It then reads object offset 0xA8C again and passes this newly read word to a closing dependency. The opening and closing arguments need not be equal.

### Copy ordering

The following sequences describe the ordering visible in the supplied static representation. They do not establish instruction-level timing or atomicity.

**Selector 0:**

1. Read the source word at 0x54.
2. Read the source word at 0x50 and write that word to object offset 0xA9C.
3. Write the previously read 0x54 word to object offset 0xAA0.
4. Read the source word at 0x5C.
5. Read the source word at 0x58 and write that word to object offset 0xAA4.
6. Write the previously read 0x5C word to object offset 0xAA8.

**Selectors 1 and 3:**

- Read both words of the selector-specific first pair, in ascending source-offset order.
- Write those retained words to object offsets 0xA9C and 0xAA0, in that order.
- Read source offsets 0x58 and 0x5C, in that order.
- Write those retained words to object offsets 0xAA4 and 0xAA8, in that order.

**Selector 2:**

- Read source offset 0x74.
- Read source offset 0x70 and write that word to object offset 0xA9C.
- Write the retained 0x74 word to object offset 0xAA0.
- Read source offsets 0x78 and 0x7C, in that order.
- Write those retained words to object offsets 0xAA4 and 0xAA8, in that order.

**Selectors 4 through 8:**

- Read both words of the selector-specific first pair, in ascending source-offset order.
- Write those retained words to object offsets 0xA9C and 0xAA0, in that order.
- Read source offset 0x5C.
- Read source offset 0x58 and write that word to object offset 0xAA4.
- Write the retained 0x5C word to object offset 0xAA8.

The function does not perform a general overlapping-memory copy. If source storage aliases destination storage, earlier writes can affect later source reads. Conversely, a source word already retained before a write is not reread for its corresponding destination store.

### Supported-path completion

After the closing dependency returns, the function calls **F-08149e8cb8ce** with these three arguments, in order:

1. Object address plus 0x918.
2. The constant 6.
3. Object address plus 0x9F8.

The first and third arguments are interior addresses, not values loaded from those addresses.

The dependency’s 32-bit return value is written to object offset 0xAAC. The function then returns 1, regardless of that stored value.

The closing dependency and the final dependency run after the four copy stores. Either may modify those destinations or other state. Thus, the table specifies this function’s copy operations; it is not an unconditional guarantee about the four words remaining unchanged at return.

### Unsupported selectors

For any selector other than 0 through 8, the function calls **F-375c8199e7c2** with:

1. The original object address.
2. The constant 0x500.

It then returns 0.

On this path, the function itself does not read object offset 0xA8C, perform the four copy stores, invoke a supported path’s closing dependency, call F-08149e8cb8ce, or store a result at 0xAAC.

This is not a promise that object state remains unchanged: F-04ee7ef2ef8d and F-375c8199e7c2 may have side effects. The shared source-base location is still read between those two calls.

## Side effects

Direct effects established for this function are:

- One initial dependency call on every path.
- One read of the shared source-base location after that call.
- For supported selectors, two separate reads of object offset 0xA8C.
- Four ordered 32-bit destination stores on supported paths.
- A selector-dependent closing call.
- A final three-argument dependency call and a 32-bit result store at 0xAAC.
- For unsupported selectors, a two-argument dependency call instead of the supported-path operations.

The function contains no explicit allocation, release, ownership transfer, synchronization, rollback, or cleanup operation. The contracts of its dependencies may include such effects; their absence cannot be inferred from this function.

Normal supported execution overwrites prior destination words without preserving them. If execution stops partway through, the evidence provides no transactional guarantee: preceding calls and writes may already have taken effect.

## Acceptance examples

These are conditional specification examples, not executed tests.

### Selector 0 with stable, disjoint storage

Assume valid, nonoverlapping object and source storage; all calls return normally; and dependencies do not alter the relevant words.

If source offsets 0x50, 0x54, 0x58, and 0x5C contain 0x11111111, 0x22222222, 0x33333333, and 0x44444444, respectively, the four destination words receive those values in that order.

The call sequence is F-04ee7ef2ef8d, F-0281cd12bdfb, F-1339740810fb, then F-08149e8cb8ce. The final dependency’s result is stored at 0xAAC, and the function returns 1.

### Selector 2 uses its own second pair

Under the same stability assumptions, selector 2 copies source offsets 0x70, 0x74, 0x78, and 0x7C. Values at 0x58 and 0x5C are not used by this function’s copy operations on that path.

### Selector boundaries

Selector 8 uses F-2aea16db53c2, copies its first pair from 0xA0 and 0xA4, and follows the supported completion path.

Selector 9 instead calls F-375c8199e7c2 after initialization and source-base capture, then returns 0. The 32-bit pattern 0xFFFFFFFF likewise takes the unsupported path; signed interpretation is unnecessary.

### Argument changes between dependency calls

Suppose the first read of object offset 0xA8C yields 0x12345678. The opening dependency receives that value.

If the field becomes 0x87654321 before the closing-call argument is read, the closing dependency receives 0x87654321. The function does not reuse the opening argument.

### Shared-base changes

Suppose the captured source base identifies region A. If an opening dependency changes the shared base location to identify region B, subsequent copy reads still address region A.

If that dependency instead changes words within region A before they are read, the copied values reflect those changed words.

### Zero final result

If F-08149e8cb8ce returns zero normally, zero is stored at object offset 0xAAC and F-f4bb5a4884b6 still returns 1. No failure interpretation is attached to zero here.
