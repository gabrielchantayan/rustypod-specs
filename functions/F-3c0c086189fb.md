# F-3c0c086189fb

## Purpose

F-3c0c086189fb performs a sequence of address-derived memory writes, conditional context-state reads and writes, and architecture-specific operations. One represented path returns normally; the others terminate at invalid-instruction boundaries, unless an earlier access or dependency prevents continuation.

An application-level purpose is not established. Context manipulation or machine-state record construction is **inferred intent**, not an interface guarantee.

This contract describes the supplied static representation. Its instruction-overlap warnings, removed unreachable region, and truncated control flow prevent treating that representation as independently verified executable behavior.

## Interface

### Entry and result

The apparent interface declares no parameters and no returned value. It nevertheless depends on substantial incoming state:

- Negative, zero, and overflow condition flags.
- A context-root address for initial pointer traversal.
- A working pointer used for indexed reads, optional writes, and the final record destination.
- A frame/context base used for restoration reads and context writes.
- An incoming value used by the optional write.
- A saved-register value used in the final record.
- Two represented 32-bit coprocessor-state operands.
- A pointer-sized stack input associated with offset `0x1e8`.
- A 32-bit stack input associated with offset `0x264`.
- Addresses of several stack locations.
- Memory and unresolved global state.

No ABI, address validity, alignment, privilege, or ownership guarantees are supplied. No error code or error object is established.

### Widths and notation

The representation uses 8-bit byte accesses, 16-bit halfword accesses, and 32-bit words and pointer representations. The unresolved global read and reset-labelled global assignment have **unknown access widths**.

This contract describes address arithmetic in a conditional 32-bit machine model: addition, multiplication, and left shifts retain their low 32 bits; logical right shifts insert zeroes; arithmetic right shifts propagate bit 31. Signed comparisons use bit 31. Signed-addition overflow means that the mathematical sum lies outside the signed 32-bit range.

These conventions make the represented dataflow explicit; they do not resolve uncertain instruction decoding or the semantics of signed expressions in the supplied representation.

## Behavior

### Entry and initial traversal

If the incoming zero flag is clear and the incoming negative and overflow flags agree, F-unknown-04 is requested with immediate `0xcfcecb`, before the initial object traversal. Whether it returns or changes relevant state is unknown.

If execution continues, the represented memory operations occur in this order:

1. Read a pointer at context-root offset `0x14`, then a pointer at offset `8` of that intermediate object, obtaining an owner address.
2. Read the owner’s first word as the primary-object address.
3. Read the owner’s word at offset `8`, then read the first word through that address, obtaining a byte-write destination.
4. Write the low eight bits of that destination address to destination offset `0x0b`.
5. Read the primary object’s word at offset `0x1c` as the descriptor address.
6. Read its word at offset `0x24` as an auxiliary word.

The byte write is address-derived, not a payload copy. Its position before the primary-object reads matters if memory aliases.

### Descriptor writes and field reads

The initial table value is the descriptor address interpreted as signed 32-bit and arithmetically shifted right by 24. Its signed range is therefore −128 through 127, not 0 through 255.

The descriptor address’s high byte is converted through an 8-bit character type, then converted to a 16-bit value and written at descriptor offset `0x2a`. Character signedness determines whether high-byte values with bit 7 set are sign-extended or zero-extended.

Five consecutive 32-bit words are then written at the initial table address, in ascending order:

| Byte offset | Value |
|---|---|
| `0` | Table value |
| `4` | Descriptor address |
| `8` | Stack address at offset `0x324` |
| `12` | Descriptor address arithmetically shifted right by 8 |
| `16` | Previously read auxiliary word |

After those writes, descriptor offsets `4`, `8`, and `12` are read, in that order, as the candidate, companion, and working word. Overlap with earlier writes can change these reads.

If the companion is zero:

- Add the table value to the candidate.
- Read the descriptor’s first word as an address, then read a 32-bit word through that address. Subtract the table value to obtain the working word.
- Replace the companion with the adjusted candidate logically shifted right by 16.

The indirect word read is conditional; reading only the descriptor’s first word is insufficient.

Next, write the descriptor address’s high byte at table offset `0x0d`. This overlaps the fourth word of the five-word table. Its significance within that word depends on endianness.

### Stack-derived setup

Let the stack anchor be the address at stack offset `0x324`. Arithmetic right shift of that address by 20 produces a derived base.

The working address becomes derived base minus `4`. A byte write at derived-base offset `9` stores the stack anchor’s low byte. The other value becomes the stack address at offset `0x248`.

If the candidate is zero, the following alternative applies, in order:

1. Replace the working address with the stack address at offset `0x244`.
2. Read the unresolved global value, convert it to a byte, and overwrite table offset `0x0d`. The underlying read width is unknown.
3. Multiply the table value by 16.
4. Set the other value to the arithmetic right shift by 8 of the 32-bit stack input minus 16 times the derived base.
5. Set the candidate to the scaled table value plus the working address.
6. Set the working word to the candidate logically shifted right by 20.
7. Replace the companion with the pointer-sized stack input.

The byte overwrite uses the table address before scaling.

### High-bit branch

This branch is selected when arithmetic right shift of the candidate by 28 is nonzero: precisely when the candidate lies outside `0x00000000` through `0x0fffffff`.

The branch performs these updates:

- Write the companion’s low 16 bits at working-address offset `0x24`.
- Replace the candidate with 16 times the current table value.
- Replace the companion with the stack address at offset `0x210`.
- Set the predicate word to the current table value shifted left by four.
- OR the working word with the other value.
- Replace the working address with the stack address at offset `0x254`.

If the 32-bit stack input is nonzero, execution transfers directly to the final stage. It bypasses common processing, the normal-return gate, restoration, context writes, and coprocessor operations.

On that direct transfer, both operands of the final predicate are established here: the candidate is 16 times the table value, and the predicate word is the table value shifted left by four. The final stage shifts that predicate word left by four **again**.

If the stack input is zero, processing instead continues:

1. Write a zero byte at the sum of the stack addresses at offsets `0x254` and `0x210`. This is address addition, not a conventional stack-slot access.
2. Multiply the table value by 256.
3. Replace the working address with that scaled value arithmetically shifted right by 8.
4. Replace the working word with bit 16 of the other value, all other bits cleared.
5. Replace the companion with address value `0x12`.
6. Replace the other value with the stack address at offset `0x14c`.

The candidate still holds the earlier multiplication by 16.

If that candidate is nonzero, the path selects between a word write and F-unknown-01. The write is selected only when:

- Adding the candidate to the stack address at offset `0x2d0` causes signed 32-bit overflow; and
- The 32-bit sum of the incoming working-pointer value, one if the masked working word is nonzero otherwise zero, and that pointer logically shifted right by 15 equals zero.

The second condition is evaluated only if the first holds. The selected write stores the other value at the current table address. Otherwise, F-unknown-01 receives that table address twice. If control continues, either alternative reaches F-unknown-05.

A zero candidate continues into common processing.

### Common processing and normal return

Common processing replaces the candidate with the table value plus the working address. Its logical upper 16 bits are retained separately as the **upper value**. The sign and zero status of the table value are also retained.

The predicate word is initialized to zero. If the table value is nonzero, it becomes the 32-bit word read through the working pointer at an element index equal to the table value multiplied by `−0x400000`. Each element is four bytes. Thus the effective address includes four-byte scaling in addition to the index calculation.

If the table value’s sign differs from the signed-overflow result of adding the table value and working address:

- Advance the working pointer by the candidate arithmetically shifted right by 6, as a byte displacement.
- Write the incoming optional-write value through the advanced pointer.

If bit 15 of the candidate is set, the routine now returns normally. The indexed read and optional write precede this return. Subsequent reset, restoration, context, coprocessor, and final-stage operations are bypassed.

### Restoration and context operations

If the return is not taken and the table value is zero, the predicate word remains zero and zero is assigned to the reset-labelled global. The global assignment’s width is not established.

For a nonzero table value, five ordered 32-bit restoration reads use the existing frame/context base:

| Read offset | Replacement |
|---|---|
| `−4` | Working pointer |
| `−8` | Saved-register value |
| `−0x18` | Candidate |
| `−0x1c` | Other value |
| `−0x10` | Frame/context base |

The final read replaces the base only after the preceding reads. These assignments affect the final predicate, record destination, and record contents. The predicate word remains the earlier indexed-read result.

If the table value is nonnegative, four 32-bit writes then use the current frame/context base, which may be restored:

| Offset | Written value |
|---|---|
| `0` | Architecture-specific register-space value |
| `−4` | Current frame/context base |
| `−8` | Current other value |
| `−12` | Predicate word |

Next, the working word becomes the upper value. If the table value’s sign equals the overflow result from the common address addition, the working word instead becomes upper value plus `0x2c0`, and F-unknown-02 receives:

- Selector `0xc`.
- The first incoming coprocessor-state operand.
- The **unadjusted upper value**, not the working word after adding `0x2c0`.

If the table value is nonzero, F-unknown-03 subsequently receives selectors `3`, `0`, and `4`, followed by the first and second incoming coprocessor-state operands.

Restoring the candidate does not recompute the upper value or the earlier addition’s overflow condition.

### Final record and termination

A zero current companion reaches F-unknown-05 without a final record write.

For a nonzero companion, form the 32-bit bitwise OR of:

- The current candidate; and
- The current predicate word shifted left by four.

Write the record only if that result is nonnegative as signed 32-bit.

On the direct high-bit transfer, these operands derive from the table value as described above. On the common path, the predicate word is zero or the indexed word; the candidate is the common address sum unless replaced by restoration at frame offset `−0x18`.

The record destination is the **current working pointer**. On the common nonzero-table path, this is the pointer restored from frame offset `−4`, replacing any pointer previously advanced by the optional write.

Eight consecutive 32-bit words are written in this order:

1. Stack address at offset `0x248`.
2. Constant `0x22`.
3. Current working address.
4. Current working word.
5. Current saved-register value.
6. Current working pointer itself.
7. Architecture-specific register-space value.
8. Constant `0x0860b3b4`.

Whether the record is written or omitted, continued execution reaches F-unknown-05, not a normal return.

## Acceptance examples

These are conditional static criteria, not executed tests. Access validity and continuation from earlier dependencies remain prerequisites.

1. **Entry condition.** Clear zero with equal negative and overflow flags selects F-unknown-04 before object traversal. Set zero does not select it.

2. **Signed table derivation.** Descriptor address `0x80000000` yields initial table value `0xffffff80`, not `0x00000080`. Its halfword conversion remains character-signedness-dependent.

3. **Conditional dereference.** A nonzero descriptor companion skips the dereference through the descriptor’s first word. A zero companion requires both pointer and pointee reads.

4. **Overlapping write.** In little-endian memory, the byte write at table offset `0x0d` replaces the second byte of the fourth table word. The byte address is unchanged under another byte order.

5. **Normal return.** A common-stage sum of `0x00008000` selects return after the indexed-read and optional-write decisions, before restoration and final-stage processing.

6. **Direct predicate provenance.** With table value `0x00000001` at the high-bit branch and a nonzero stack input, the candidate becomes `0x10`, the predicate word becomes `0x10`, and the final predicate evaluates `0x10` OR `0x100`. It permits record construction, assuming preceding accesses succeed.

7. **Restored predicate operand and destination.** On a common nonzero-table path, suppose the indexed word is zero and restoration supplies candidate `0x80000000`. The final predicate is negative and omits the record. If restoration instead supplies candidate zero, the predicate permits a record at the pointer restored from offset `−4`, with the saved-register field taken from offset `−8`.

8. **Coprocessor operand distinction.** With upper value `0x1234` and the load-like condition satisfied, the working word becomes `0x14f4`, but F-unknown-02 receives `0x1234` as its final operand.

9. **Null companion.** A zero companion at the final stage prevents all eight record writes and reaches the invalid-instruction boundary.
