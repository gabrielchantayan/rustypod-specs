# F-847a2a401182

## Purpose

F-847a2a401182 derives a 16-bit result from a compact record, a dependency’s zero/nonzero result, and indexed byte contributions obtained through a global table reference. It stores the result into the supplied record.

The calculation begins with an unsigned input byte minus one. It then adds contributions for successive indices, with the number of iterations governed by another unsigned input byte. At index 1, a zero dependency result substitutes the constant 28 for the ordinary table contribution.

This describes the established calculation, not its application-level meaning. A calendar-related interpretation is plausible from the second-entry substitution and the constant 28. Field names, units, valid calendar ranges, and calendar rules are not established.

## Behavior

### Initial capture and dependency call

The first observed data access reads the unsigned starting byte at offset 3. Subtracting one produces an initial accumulator value from −1 through 254. The subtraction is not an unsigned-byte decrement: an input of zero produces −1, not 255.

The function next reads the 16-bit word at offsets 0–1 and passes it to F-7264181a6e68. The returned signed 32-bit integer is retained. Only whether it equals zero affects contribution selection; its magnitude and sign otherwise have no visible significance.

The starting value has already been captured when the dependency runs. A dependency-induced change to offset 3 does not cause that byte to be read again.

By contrast, no control-byte read or table-reference evaluation occurs before the dependency call. Changes made by the dependency to those locations can affect subsequent execution.

The dependency is called once on every invocation that reaches the call, even if the control byte subsequently permits no iterations. There is no visible small-control shortcut around the call.

### Loop conditions and bounds

After the dependency returns, a signed 32-bit index begins at zero.

Every loop-condition evaluation reads the unsigned byte at offset 2, subtracts one using promoted integer arithmetic, and compares the index against that result. An iteration is admitted only when the index is strictly smaller.

For a control byte that remains stable:

| Control byte | Comparison limit | Admitted indices |
|---:|---:|---|
| 0 | −1 | None |
| 1 | 0 | None |
| 2 | 1 | 0 |
| 3 | 2 | 0 and 1 |
| 255 | 254 | 0 through 253 |

Thus a stable control value permits zero additions when it is 0 or 1, and otherwise permits one fewer addition than its value.

The control byte is read again after each completed iteration, including the read whose comparison terminates the loop. The visible body does not directly write this byte before termination, but the access is not represented as a single captured value.

Even if successive condition evaluations observe different byte values, no iteration with index 254 can be admitted: the greatest comparison limit is 254, and the comparison is strict. The index increases by one after every admitted iteration, so at most 254 iterations are admitted. This bound does not establish any concurrency or synchronization guarantee.

### Contribution selection and lookup ordering

Each admitted iteration adds exactly one contribution:

- At index 1 with a retained dependency result of zero, the contribution is 28.
- In every other case, the contribution is the unsigned byte selected through the global table reference at the current index.

The constant replaces the table contribution. It is not an additional adjustment, and it does not change the iteration count.

The access distinction is observable:

- An ordinary iteration first evaluates the table-reference global, then reads the indexed byte using the resulting base.
- The constant-28 branch performs neither the global-reference access nor the indexed-byte access.

Consequently, a zero dependency result removes both lookup accesses at index 1. It does not remove the ordinary accesses at index 0 or at any other admitted index.

All nonzero dependency results take the ordinary lookup path at index 1. Positive and negative nonzero results are equivalent for this decision.

If different ordinary iterations obtain different bases from the global reference, each uses its own evaluated base. The source does not establish one invariant table allocation for the entire invocation.

### Arithmetic and narrowing

Each addition uses integer promotion and assigns its result back to the signed 16-bit accumulator. The promoted addition itself does not require signed 32-bit overflow: its operands are a signed 16-bit accumulator value and a contribution no greater than 255.

Some assignments can nevertheless exceed the signed 16-bit range. The exact treatment of out-of-range signed narrowing is not independently established by the supplied representation. No saturation, overflow rejection, or arithmetic error status is visible.

Before considering intermediate narrowing, the mathematical total is bounded by:

- Minimum: −1.
- Maximum: 254 plus 254 contributions of 255, giving 65,024.

The constant-28 replacement cannot increase that maximum.
