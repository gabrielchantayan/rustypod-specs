# F-9f634613286e

## Purpose

F-9f634613286e transforms a 64-bit value supplied as two 32-bit words, using a third 32-bit word as an exponent adjustment.

**Established behavior:** For an input whose exponent field is between 1 and 2046 inclusive, the function adjusts that field when the resulting exponent remains in that range. Otherwise, it produces a signed zero or signed infinity. Inputs with exponent fields of zero or 2047 receive separate treatment.

**Inferred intent:** The bit layout matches IEEE 754 binary64, and the ordinary-input path resembles multiplication by an integral power of two. This interpretation does not make the function a general floating-point scaling operation: it does not construct subnormal results, flushes existing nonzero subnormals to positive zero, and delegates NaN-like inputs through an unresolved indirect transfer.

The contract below describes the supplied static representation. It does not assert runtime validation, full floating-point conformance, or behavior of the unresolved dependency.

## Interface

### Explicit inputs

| Input | Width | Interpretation |
|---|---:|---|
| Low word | 32 bits | Bits 31–0 of the value being transformed. Although represented as a signed integer in the supplied interface, its use here is bit-preserving or a comparison against zero. |
| High word | 32 bits | Bits 63–32 of the value being transformed. Contains the sign, exponent, and upper fraction bits. |
| Adjustment word | 32 bits | A bit pattern used in 32-bit arithmetic. The branch behavior for ordinary inputs corresponds to interpreting it as a signed two’s-complement integer. |

The logical 64-bit input has this layout:

| Component | Logical bit positions | Word location |
|---|---|---|
| Sign | 63 | High-word bit 31 |
| Exponent | 62–52 | High-word bits 30–20 |
| Fraction, upper portion | 51–32 | High-word bits 19–0 |
| Fraction, lower portion | 31–0 | Entire low word |

The exponent is an unsigned 11-bit quantity, with values from 0 through 2047. The fraction is zero only when both the low word and the lower 20 bits of the high word are zero.

These are logical word and bit positions. No byte-order requirement for memory storage follows from the supplied representation, because the function receives words rather than a byte buffer.

### Implicit input

The NaN-like branch uses an implicit 32-bit link-register value to form an indirect target. That value is not one of the three explicit arguments.

Its origin, validity, and relationship to the normal return address are not established. A valid continuation on that branch therefore requires execution-context information beyond the explicit interface.

### Output

The declared result is a 64-bit integer container. Direct-return paths construct its bits as a high word followed by a low word. The contract concerns those bits, not a signed numeric interpretation of the returned container.

The unresolved indirect branch returns the 64-bit result produced by its target, if that target returns normally.

There is no explicit status output, error code, output pointer, or separately returned floating-point exception indicator.

## Behavior

### Classification and evaluation order

The function first extracts the 11-bit exponent from the high word. It then distinguishes:

1. Exponent zero.
2. Exponent 2047.
3. Exponents 1 through 2046.

For an ordinary exponent, it evaluates the upper and lower limits for the adjustment before taking either the exponent-adjustment path or a terminal-result path.

The supplied representation expresses these limits using 32-bit arithmetic and signed-overflow conditions. The resulting acceptance condition can be stated without overflowing arithmetic:

> Interpret the adjustment word as a signed 32-bit integer. Add it mathematically to the extracted exponent. The direct exponent-adjustment path is taken exactly when that sum is between 1 and 2046 inclusive.

This mathematical formulation describes the branch result; it does not require an implementation to perform a wider addition.

### Ordinary exponent: adjusted exponent remains ordinary

When the original exponent is between 1 and 2046, and its adjusted value is also between 1 and 2046:

- The returned low word is unchanged.
- The returned high word is the original high word plus the adjustment word multiplied by \(2^{20}\), with multiplication and addition interpreted modulo \(2^{32}\).
- The sign bit and all 52 fraction bits are preserved.
- The exponent field becomes the original exponent plus the signed adjustment.

The accepted range prevents the exponent update from carrying into the sign bit or borrowing through the fraction field. A negative adjustment is represented through its 32-bit two’s-complement bit pattern; the modular high-word arithmetic still gives the stated exponent update.

An adjustment of zero preserves every input bit on this path.

### Ordinary exponent: adjusted exponent is zero or negative

When the original exponent is between 1 and 2046 and its mathematical sum with the signed adjustment is at most zero:

- The returned low word is zero.
- The returned exponent and fraction are zero.
- The original sign is preserved.

Under the binary64 interpretation, this is signed zero.

The function does not shift the significand to produce a subnormal result. The boundary case where the adjusted exponent is exactly zero follows this same zero-producing path. Any fraction information is discarded.

### Ordinary exponent: adjusted exponent is 2047 or greater

When the original exponent is between 1 and 2046 and its mathematical sum with the signed adjustment is at least 2047:

- The returned low word is zero.
- The returned exponent is 2047.
- The returned fraction is zero.
- The original sign is preserved.

Under the binary64 interpretation, this is signed infinity.

The boundary case where the adjusted exponent is exactly 2047 follows this path. Fraction bits are cleared rather than carried into an infinity-or-NaN encoding.

### Exponent zero: zero fraction

When the exponent and all fraction bits are zero:

- The returned low word is zero.
- Only the input sign bit is retained in the high word.
- The adjustment has no effect.

Thus positive zero remains positive zero and negative zero remains negative zero for every adjustment word.

### Exponent zero: nonzero fraction

When the exponent is zero and at least one fraction bit is set:

- The returned high word is zero.
- The returned low word is zero.
- The original sign is discarded.
- The adjustment has no effect.

Under the binary64 interpretation, every nonzero subnormal input becomes **positive zero**, including negative subnormals and inputs whose adjustment could otherwise normalize them.

This is established behavior, not an inferred rounding rule.

### Exponent 2047: zero fraction

When the exponent is 2047 and the fraction is zero:

- Both input words are returned unchanged.
- The adjustment has no effect.

Under the binary64 interpretation, positive and negative infinity remain unchanged.

### Exponent 2047: nonzero fraction

When the exponent is 2047 and any fraction bit is set, the function takes an indirect dependency path:

1. It obtains a target from the implicit link-register value.
2. It clears the target’s lowest two bits.
3. It invokes the resulting target.
4. If the target returns normally, it returns that target’s 64-bit result.

No explicit arguments are shown for this invocation. This does not prove that the target receives no machine-register context or other implicit inputs.

The supplied representation does not establish NaN payload preservation, sign preservation, quieting behavior, exception behavior, or a particular returned NaN. None of those may be substituted for the unresolved dependency’s actual behavior.

### Extreme adjustments

The adjustment is not restricted to a small range.

For an ordinary input exponent:

- Adjustment `0x80000000`, interpreted as −2147483648, produces signed zero.
- Adjustment `0x7FFFFFFF`, interpreted as 2147483647, produces signed infinity.
- Adjustment `0xFFFFFFFF`, interpreted as −1, decrements the exponent when the original exponent is at least 2; an original exponent of 1 produces signed zero.

The branch behavior must not be replaced with an unchecked wrapping comparison of an 11-bit or 32-bit adjusted exponent. Such a replacement could incorrectly accept extreme adjustments.
