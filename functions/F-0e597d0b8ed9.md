## Behavior

### 1. Capture the four input words

The function reads four global values in their displayed order and places them in successive 32-bit positions of the local working block.

For this contract, call the captured values **A**, **B**, **C**, and **D**, in increasing working-block address order. These labels describe values, not implementation identifiers.

Each captured value has a width of 32 bits. The working block therefore contains 128 bits, or 16 bytes.

The reads occur before any dependency call. This is not an atomic snapshot: the supplied material shows separate reads, not synchronization or a transaction. If another agent can modify the source storage concurrently, this function provides no visible mechanism to obtain a mutually consistent set of values.

The global source values are not directly rewritten by this function.

### 2. Shift the working words in reverse address order

The function processes the four working words from the highest-addressed word to the lowest-addressed word:

1. D
2. C
3. B
4. A

Each word is read, shifted right by one bit as an unsigned 32-bit value, and written back to its own location.

For any captured word \(x\), this operation produces \(\lfloor x / 2 \rfloor\):

- The original least-significant bit is discarded.
- The new most-significant bit is zero.
- No sign extension occurs.
- No bit is carried between neighboring words.

This is four independent 32-bit shifts, not a single shift of the entire 128-bit block.

Exactly four words are transformed. The neighboring storage used to establish the traversal’s starting boundary is not an additional input word and is not included in the transformation.

### 3. Narrow part of the fourth word

After the shifts, the function performs an additional narrowing operation on a three-byte subfield associated with the fourth word.

The three-byte field is converted to an unsigned 16-bit value and then assigned back to a three-byte field. Consequently:

- The field’s low 16 numeric bits are retained.
- Its remaining eight numeric bits become zero.
- The separate fourth byte is not explicitly overwritten by this narrowing assignment.

This operation follows all four word shifts and precedes the first dependency call.

The supplied representation identifies a 24-bit field and an adjacent one-byte field within the fourth word’s storage. A precise mapping between those fields and the whole word’s numeric bit positions requires the target byte order and field-layout interpretation.
