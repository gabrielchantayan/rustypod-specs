# F-d14ca8406e7a

## Purpose

F-d14ca8406e7a constructs a four-byte result from an input object and dispatches that result through one of two indirect operations on an embedded receiver.

The dispatch choice is established by a single byte read from the input object before either construction dependency runs:

- A zero byte selects the operation at dispatch-table byte offset 28.
- Any nonzero byte selects the operation at dispatch-table byte offset 32 and supplies an additional zero argument.

Both branches request 12 bytes from F-8157a180d901, pass its result and the input-object address to F-7fe4f8cb78f6, and pass the address of the resulting four-byte value to the selected operation.

This is the established local behavior. Descriptions such as “allocation,” “construction,” and “virtual dispatch” are plausible interpretations of the call pattern, not independently established dependency contracts. The meaning of the input flag and the two operations remains unknown.

## Interface

The interface has four argument positions and no defined return value.

| Argument | Represented width | Established use |
|---|---:|---|
| First | 32 bits | Address-like value identifying a containing object. The embedded receiver is located 108 bytes after this address. |
| Second | 32 bits | Address-like value identifying an input object. Its byte at offset 8 selects dispatch. The original address-like value is also passed to F-7fe4f8cb78f6. |
| Third | 32 bits | Not read or forwarded by this function. |
| Fourth | 32 bits | Initially placed into temporary four-byte storage, then replaced by the result of F-7fe4f8cb78f6 before that storage is passed to an operation. |

The first two arguments have integer representations in the supplied evidence but participate in address calculations and memory access. Their signed declaration does not establish a meaningful signed numeric domain for callers.

The established layout is byte-offset based:

| Location | Required interpretation |
|---|---|
| First argument + 108 | Address of the embedded receiver; also the location from which its dispatch-table reference is read. |
| Second argument + 8 | One-byte dispatch selector. Zero and nonzero are the only distinctions made. |
| Dispatch-table reference + 28 | Indirect operation selected when the selector is zero. |
| Dispatch-table reference + 32 | Indirect operation selected when the selector is nonzero. |

The receiver argument supplied to either indirect operation is the address at first argument + 108. It is **not** the dispatch-table reference stored at that address, and it is **not** the original first argument.

The supplied representation supports a 32-bit address and table-entry model. The temporary result and the values returned by the two direct dependencies are represented as four bytes. These widths describe the supplied evidence; they do not establish portability to a different pointer width or ABI.

Preconditions for normal completion include:

- The selector byte must be readable.
- The embedded receiver must remain at a usable address through dispatch.
- At dispatch time, the receiver must contain a valid dispatch-table reference, and the selected entry must identify a callable operation.
- Both direct dependencies must accept the supplied arguments and return normally.

The function does not check these preconditions.

## Behavior

### Dispatch selection

The function establishes the embedded receiver address using a byte displacement of 108 from the first argument.

It also initializes temporary four-byte storage from the fourth argument. That initial value is not used as an argument to either direct dependency.

The function reads exactly the selector byte at second argument + 8 for its local branch decision. Its test distinguishes zero from all nonzero byte representations. Whether a nonzero byte would be interpreted as positive or negative under a signed character type does not change the selection.

The selected branch remains fixed after this read. The function does not read the selector again after either dependency call. Consequently, a dependency changing the selector does not change which operation this invocation selects.

### Shared construction sequence

After selecting a branch, the function performs the same two direct calls in either case:

1. F-8157a180d901 receives the numeric argument 12.
2. Its four-byte result becomes the first argument to F-7fe4f8cb78f6. The original second argument becomes that dependency’s second argument.
3. The four-byte result of F-7fe4f8cb78f6 replaces the initial value in temporary storage.

There is no local check of the first dependency’s result before it is passed onward. In particular, a zero result is not locally rejected.

There is also no local check of the second dependency’s result before it is placed in temporary storage and offered to the selected operation. A zero value, a sentinel value, or any other four-byte representation follows the same local path if the dependencies return normally.

The initial fourth-argument value does not reach the selected operation through this storage: it has been replaced before the operation receives the storage address. No local result or branch decision depends on the third argument.

### Zero-selector operation

If the selector read was zero, the function obtains the dispatch-table reference from the embedded receiver after both direct dependencies have returned. It then selects the callable entry at table byte offset 28.

That operation receives two arguments, in order:

1. The embedded receiver address.
2. The address of the temporary four-byte storage containing the result of F-7fe4f8cb78f6.

After the operation returns normally, F-d14ca8406e7a returns without further local processing.

### Nonzero-selector operation

If the selector read was nonzero, the function likewise obtains the dispatch-table reference after both direct dependencies have returned. It selects the callable entry at table byte offset 32.

That operation receives three arguments, in order:

1. The embedded receiver address.
2. The numeric value zero.
3. The address of the temporary four-byte storage containing the result of F-7fe4f8cb78f6.

The extra zero occupies an argument position; it is not the temporary result and does not replace the receiver. Its semantic meaning is unknown.

After the operation returns normally, F-d14ca8406e7a returns without further local processing.

### Ordering and mutable state

The relevant local ordering is:

- Establish the embedded receiver address and initialize temporary storage.
- Read the selector and select a branch.
- Call F-8157a180d901.
- Call F-7fe4f8cb78f6 with that call’s result and the original input address.
- Replace the temporary value.
- Read the receiver’s dispatch-table reference and select the branch-specific entry.
- Invoke the selected operation.
- Return.

The dispatch-table reference is not cached before the direct dependency calls. If either dependency changes the receiver’s table reference or the selected table entry, the later dispatch uses the state available when that lookup occurs, provided the relevant accesses remain valid.

Conversely, the receiver address is established before those calls. The function does not recompute it from any state that a dependency might subsequently change.

These statements describe sequencing within this function. They do not establish synchronization, atomicity, or safe behavior under concurrent mutation.

## Side effects

The locally established memory reads are the selector byte, the embedded receiver’s dispatch-table reference, and the selected callable entry.

The function writes its own temporary four-byte storage, first with the fourth argument and later with the result of F-7fe4f8cb78f6. It exposes the address of that storage to the selected operation.

No direct write to the caller’s object or input object is established outside the dependency and indirect calls. Those calls may nevertheless modify caller-visible memory, globals, resources, or the receiver. Their side effects are not constrained by this evidence.

The selected operation can access the temporary storage through the address it receives. Whether it reads the value, replaces it, consumes a represented resource, or retains the address is unknown. Any value it writes there is not subsequently examined by F-d14ca8406e7a.

The temporary storage has invocation-local lifetime. Retaining its address does not establish a valid post-return storage lifetime. Likewise, the apparent request for 12 bytes does not establish who owns any resulting resource.

There is no explicit local release, deallocation, rollback, retry, or error report. Absence of such actions here does not prove that dependencies neither release resources nor implement error handling internally.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence, not reports of executed tests. Each assumes valid memory and normally returning callees unless otherwise stated.

1. **Zero selector.** With selector byte zero, the direct dependencies are called in the established order. The operation at offset 28 receives the embedded receiver address and the address of a slot containing the second dependency’s result. The offset-32 operation is not selected.

2. **Nonzero selector.** With selector byte 1 or 255, the operation at offset 32 receives the embedded receiver address, zero, and the temporary-slot address. Both selector representations select the same branch.

3. **Selector changed during construction.** If the initial selector is zero and a dependency later changes it to nonzero, offset 28 remains selected. The reverse change likewise does not undo an initially selected offset-32 branch.

4. **Dispatch table changed during construction.** If a dependency replaces the receiver’s table reference with another valid one, dispatch uses the later reference. Selection still uses the branch determined by the earlier selector read.

5. **Zero acquisition result.** If F-8157a180d901 returns zero normally, F-7fe4f8cb78f6 receives zero as its first argument. No local failure return intervenes. What that dependency does with zero remains unspecified.

6. **Zero construction result.** If F-7fe4f8cb78f6 returns zero normally, the selected operation is still invoked and receives the address of a four-byte zero value.

7. **Unused argument variation.** Changing only the third argument does not change any established local decision or forwarded argument. Changing only the fourth argument changes the temporary slot’s initial contents, but the slot contains the construction result by dispatch time.

8. **Operation overwrites temporary storage.** If the selected operation writes a new value into the supplied slot and returns normally, this function does not inspect that replacement or perform a subsequent explicit release.

9. **Invalid selector address.** An unreadable selector location does not lead to a defined local error result. The evidence establishes an unchecked read, not a recovery behavior.
