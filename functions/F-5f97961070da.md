# F-5f97961070da

## Purpose

F-5f97961070da updates a destination descriptor from a source descriptor and returns the destination descriptor’s address.

The established behavior is a branch-dependent sequence of dependency calls and descriptor writes. The sequence resembles assignment between contiguous containers of four-byte elements: reuse existing storage when sufficient, otherwise obtain replacement storage. That container interpretation is inferred intent, not a guarantee about element types, memory ownership, or dependency behavior.

A material distinction exists between the reuse paths:

- When the destination’s reported length is smaller than the source’s reported length, the function updates the destination’s logical end before invoking a suffix-processing dependency and performs no direct write to the third descriptor word.
- Otherwise, it sets both the second and third destination words to the same computed address.

These differences are part of the contract; the third word cannot be described as unconditionally preserved capacity.

The displayed representation uses 32-bit integer words to carry addresses and address-like values. The exact external calling convention and treatment of pointers outside that representation are not established.

Every temporary value that can subsequently affect a dependency call or descriptor write is replaced before use. ### Output

On every explicitly shown normal return, the function returns the original destination descriptor address, not its base address and not a newly allocated descriptor.

There is no explicit success flag, error code, or null-result check.

## Behavior

### 1. Identity handling

The first decision compares the source and destination descriptor addresses.

If they are equal:

- No dependency is called.
- No descriptor word is read or written by the displayed body.
- Neither auxiliary argument affects the operation.
- The destination address is returned.

Equality concerns descriptor identity. Distinct descriptors describing the same backing range do not receive this shortcut.

### 2. Initial branch selection

For distinct descriptors, the function:

1. Obtains an unsigned 32-bit quantity from F-e02ac27bd77d using the source descriptor.
2. Obtains an unsigned 32-bit quantity from F-2aa59d7a08b5 using the destination descriptor.
3. Compares the destination result with the source result using an unsigned less-than comparison.

The inferred meanings are source length and destination capacity, respectively. The established contract is the comparison of those returned quantities.

If the destination result is smaller, the replacement-storage path is taken. Otherwise, a second comparison selects one of the storage-reuse paths.

Dependency results are not generally cached across the entire operation. Subsequent calls may return different values, and the implementation uses those fresh results where specified below.

### 3. Replacement-storage path

This path is selected when the initial destination query result is less than the initial source query result.

#### Size selection

The function queries F-e02ac27bd77d again, first for the source and then for the destination.

Let:

- **S** be this fresh source result.
- **D** be this fresh destination result.

It forms two unsigned 32-bit growth candidates:

- **Additive candidate:** D + 32.
- **Proportional candidate:** D + floor(D / 2) + floor(D / 8).

The divisions arise from logical right shifts of the unsigned value. The proportional candidate is the sum of separately truncated terms, not necessarily floor(13D / 8).

It selects the larger candidate by unsigned comparison, then selects the larger of that result and S. Call the selected quantity **N**.

These computations use the displayed 32-bit unsigned representation. Addition may wrap modulo 2³²; there is no overflow check. Consequently, “larger” refers to the resulting unsigned values after those computations, not to unbounded mathematical growth.

#### Dependency sequence and publication

The remainder of this path occurs in this order:

1. Call F-871e64ddc6de with N shifted left by two bits and a second argument of zero. Save its returned value as the replacement base.
2. Call F-c816a9b43103 with the currently read source base, source end, replacement base, and destination descriptor address.
3. Call F-f19cd7a3a483 with the destination descriptor address and its then-current base and end.
4. Read and save the destination’s then-current base.
5. Call F-2aa59d7a08b5 on the destination again.
6. Call F-ff1bdc376dcd with the saved base, that fresh query result, and zero.
7. Write the saved replacement base into the destination’s base word.
8. Query F-e02ac27bd77d on the source again.
9. Write the destination end as its currently read base plus four times that fresh source result.
10. Write the destination limit as its currently read base plus four times N.
11. Return the destination descriptor address.

The allocation-like byte request is a 32-bit left shift; high bits can be discarded. There is no check that this byte request can represent storage for N elements.

The destination base used for the final address calculations is read after the intervening dependencies. The function does not enforce that it still equals the replacement base originally returned by F-871e64ddc6de.

The old-base value passed to F-ff1bdc376dcd is captured before the final F-2aa59d7a08b5 call. If that query mutates the descriptor, its mutation does not change the already saved first argument.

### 4. Storage reuse with a growing logical range

When the initial comparison permits reuse, the function calls F-e02ac27bd77d on the destination and then on the source. If the destination result is smaller than the source result, it takes this path.

The sequence is:

1. Query F-e02ac27bd77d on the destination again. Save this fresh quantity as **P**.
2. Call F-322ef06b78d8 with:
   - The current source base.
   - The current source base plus four times P.
   - The current destination base.
3. Query F-e02ac27bd77d on the source again.
4. Write the destination end as the currently read destination base plus four times that fresh source result.
5. Call F-c816a9b43103 with:
   - The then-current source base plus four times P.
   - The then-current source end.
   - The then-current destination base plus four times P.
   - The destination descriptor address.
6. Return immediately.

The return value of F-322ef06b78d8 is ignored on this path.

The destination end is published before the suffix dependency is invoked. Thus, that dependency can observe an end value representing the full requested logical range even though the function has not yet completed the suffix call.

There is no direct limit-word write on this path. This does not imply that the limit remains unchanged: a dependency receiving the descriptor may modify it.

The prefix and suffix boundary is based on the saved fresh quantity P, not necessarily the destination result used in the preceding branch comparison.

### 5. Storage reuse with a non-growing logical range

If the second comparison does not find the destination result smaller than the source result, the sequence is:

1. Call F-322ef06b78d8 with the current source base, source end, and destination base.
2. Pass its returned value to F-f19cd7a3a483 as the second argument, alongside the destination descriptor address and its then-current end.
3. Query F-e02ac27bd77d on the source again.
4. Compute an address from the currently read destination base plus four times that fresh source result.
5. Write that address to the destination end.
6. Write the same saved address to the destination limit.
7. Return the destination descriptor address.

Unlike the growing reuse path, this path uses the return value of F-322ef06b78d8.

The final two descriptor writes use one computed address. No dependency call separates those writes. Therefore, on normal completion of this path, end and limit are equal even if the destination previously had additional spare storage.

## Acceptance examples

The following examples are conditional observations, not runtime test results. Except where stated otherwise, they assume stable length and capacity queries, ordinary valid ranges, no arithmetic overflow, normally returning dependencies, and no descriptor mutation by dependencies.

### Identity

Given identical source and destination descriptor addresses, the result is that address. There are no dependency calls and no direct descriptor accesses. Changing either auxiliary argument does not change this trace.

### Replacement with additive growth

Given destination length 16, destination capacity 16, and source length 20:

- N is 48.

This result additionally assumes the later source query still returns 20.

### Replacement dominated by source length

Given destination length 16, destination capacity 16, and source length 100, N is 100. The byte request is 400. Under stable values, final end and limit both equal replacement base plus 400.

### Growing within existing storage

Given destination length 3, destination capacity 8, and source length 5:

- No replacement-storage dependency is called.
- F-322ef06b78d8 receives the source prefix ending 12 bytes after the source base.
- The destination end is set 20 bytes after its base before F-c816a9b43103 is called.
- The latter call receives the source suffix beginning 12 bytes after the source base and a destination address 12 bytes after its base.
- The function performs no direct limit write.

### Shrinking within existing storage

Given destination length 7, capacity 10, and source length 2:

- F-322ef06b78d8 receives the full source range.
- Its returned value is forwarded as the cleanup range’s starting value.
- Final end and limit both equal destination base plus 8.

The prior capacity of 10 is not preserved in the limit word by this path.

### Equal lengths and empty ranges

Equal reported lengths select the non-growing reuse path, not the growing path.

With a stable source length of zero, that path ends with both destination end and limit equal to the destination base. The range dependency and cleanup dependency are still called; an empty range does not cause an explicit early return.

### Changing query results

If the growing reuse branch is selected using destination length 3 but the subsequent destination query returns 4, the prefix and suffix split uses four elements. The implementation does not retain the earlier value 3 for that purpose.
