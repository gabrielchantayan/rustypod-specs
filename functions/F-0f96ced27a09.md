# F-0f96ced27a09

## Purpose

F-0f96ced27a09 prepares an operation, processes a mutable local copy of a four-word region, and invokes a completion dependency unless an early-return condition applies.

The established processing choices are:

- Delegation for operations other than 34, or when operation 34 observes source byte 3 equal to 255.
- Format-dependent direct processing for operation 34 with source byte 3 below 255.
- Completion without direct pixel work for particular direct-path endpoints.

The arithmetic and traversal suggest a region-filling operation with packed-color blending. That interpretation is **inferred intent**, not an established format or rendering contract.

This specification records static evidence. No runtime tests have been performed.

## Behavior

### Preparation, early returns, and completion

The function first copies the four region words and stores the original destination address in its local context. It then calls F-0c2e570de7fe with the source address and the destination word at offset 16 narrowed to signed 16 bits. The returned value and operation byte are placed in the operation record.

Only afterward does it read the original destination’s first word. If that word is zero, it returns without preparation, processing, or completion. The check does not protect the earlier region reads, destination word-4 access, or conversion call.

Otherwise, F-19b97bee6590 receives the operation record and preparation argument. A zero result causes another immediate return. A nonzero result leads, in order, to:

- F-23fa1bdb41b9 with the operation record.
- F-796b82d1c424 with the original destination and mutable context.
- Capture of the arithmetic-mask location into an unsigned 32-bit local.
- Capture of the format location into another unsigned 32-bit local.
- Processing selection.

Normal completion invokes F-21122d06e906 with the original destination and local context. This includes delegated paths, direct-processing paths, and no-pixel-work endpoints. Neither early return invokes completion.

No dependency preservation or cleanup guarantee follows from this ordering.

### Processing selection and format observations

When the full operation value is not 34, processing delegates to F-dd1a888bb5f5 with the operation record. This branch does not explicitly read source byte 3.

For operation 34, source byte 3 is read once for selection. A value of 255 also delegates. Values 0–254 lead to a comparison between:

- The unsigned 16-bit field at offset 16 of the context-referenced destination.
- A fresh direct reference to the external format location.

The earlier format capture does not control this comparison. It is retained for four-byte conversion calls.

There is no explicit narrowing of the fresh external operand to 16 or 32 bits. Comparison conversions depend on its unavailable declaration. The relative evaluation order of the destination-field access and external reference is not established.

### Matching-format four-byte path

If the format comparison succeeds and the selected source byte is zero, the function performs no direct pixel accesses and does not delegate. Completion still occurs.

For selected source-byte values 1–254, the initial address is the context-referenced destination’s storage base plus:

- Stride multiplied by starting row.
- Four multiplied by starting column.

The row count is ending row minus starting row. The column count is ending column minus starting column. Both loops continue only while their signed counts are positive.

Each processed pixel has the following observable sequence:

- Read a 32-bit destination value.
- Call F-1e2f295ee27c with that value, the **earlier captured unsigned 32-bit format value**, and a four-byte scratch address.
- Call F-86dd6fb1ad71 with a second scratch address, the first scratch address, the source address, and integer 255.
- Call F-35c2e4297234 with the first and second scratch addresses.
- Read four bytes from the first scratch area and write a packed 32-bit destination value.

If the scratch bytes are numbered 0–3 by increasing address, the numeric store places byte 3 in bits 31–24, byte 0 in bits 23–16, byte 1 in bits 15–8, and byte 2 in bits 7–0. This does not establish machine endianness or the relative evaluation order of the four byte reads.

Scratch initialization and dependency write coverage are unknown. Every scratch value consumed by a dependency or final packing must be valid at its consumption point.

The address advances four bytes after each pixel. At each row end, it is adjusted by the then-current context stride minus four times the captured column count. Row and column counts are captured before pixel calls; the stride is read again for row adjustment.

A nonpositive row count performs no pixel work. A nonpositive column count also performs no pixel work, but positive-count rows still execute their row adjustments.

Those shifts operate on the external operands before assignment. The missing declaration prevents establishing their promoted widths, whether right shift is logical, or whether left shift is defined for every observed value. Assignment to an unsigned 32-bit destination does not retroactively make these shifts unsigned 32-bit operations.

**Conditional interpretation:** if both operands have appropriate unsigned 32-bit shift semantics, the combined mask is the OR of the right observation shifted right 16 and the left observation shifted left 16, retaining 32 bits. It is a half-swap of one value only if both references observe the same value.

The references’ relative evaluation order is unspecified. They occur in the source expression even when the subsequent endpoint check skips pixel work or delegates. This is a source-level distinction, not proof of two physical loads or of permitted concurrent modification.

### Two-byte traversal and stores

The row loop continues while its signed row count is **nonzero**, decrementing it at the beginning of each iteration. This differs from the four-byte path’s positive-count condition.

Each row reads a current column count from the context. Traversal consists of:

- An unconditional-with-respect-to-width scalar prefix if the current address is not divisible by four, followed by a two-byte advance and one-column decrement.
- Paired updates while more than one column remains, advancing four bytes and subtracting two columns each time.
- A scalar tail if the remaining count is nonzero, followed by a two-byte advance.
- A row adjustment using the current stride plus twice the captured negative initial column count.

Thus, initial row and row-correction counts precede source packing, while row-local widths and strides are consumed later. Dependency preservation of reachable context is not assumed.

For a paired update, the destination contribution is the OR of:

1. Destination mask AND destination weight times the destination word masked with the combined mask, retaining the low 32 product bits and logically shifting right five afterward.
2. Initial mask AND destination weight times the destination word masked with hexadecimal F81F07FF and logically shifted right five before multiplication, retaining the low 32 product bits.

The source contribution is replicated by OR-ing it with itself shifted left 16. This replicated value is added to the destination contribution, and the low 32 sum bits are stored.

For a scalar update, the destination contribution uses:

1. The low 16 destination-mask bits AND destination weight times the low 16 input bits masked with hexadecimal F81F, shifted right five after multiplication.
2. The low 16 initial-mask bits AND destination weight times the low 16 input bits masked with hexadecimal 07FF, shifted right five before multiplication.

The low 16 source-contribution bits are added, and the low 16 sum bits are stored.

Each update expression contains two destination-input references. Their evaluation order is unspecified, and they are not guaranteed to represent one atomic snapshot. Scalar references use a source-level 32-bit access before narrowing to 16 bits. Two readable destination bytes alone are therefore not an established sufficient precondition for scalar edges; actual instruction-level load widths remain unknown.

Zero rows skip pixel updates only after source packing and mask preparation. Negative row counts are not normalized to empty regions. Zero or negative widths are likewise not reliable empty-operation indicators.

These are conditional static criteria, not executed tests. Memory and arithmetic validity are assumed unless the example identifies a hazard.

The later comparison uses an unsigned 16-bit access at bytes 16–17 of the context-selected destination. Providing only bytes 16–17 does not establish valid initial conversion.

2. **Zero destination word:** Conversion still occurs before the zero check. Preparation and completion do not occur afterward.

3. **Zero preparation result:** F-23fa1bdb41b9, context preparation, processing, and completion are skipped.

4. **Operation 290:** The record receives byte 34, but the full operation comparison fails. Delegation occurs without an explicit branch-selection read of source byte 3.

5. **Operation 34 and source byte 255:** Delegation is followed by completion.

6. **Different format observations:** Assuming an unsigned 32-bit external format type, an earlier capture of 100, fresh observation of 200, and destination field of 200 select the matching branch. Pixel conversion receives 100.

7. **Fresh format value 65536:** Under unsigned 32-bit comparison semantics, this cannot equal the unsigned 16-bit destination field. No unconditional external-width claim follows from this example.

8. **Matching format and source byte zero:** No direct pixels are accessed and no delegation occurs; completion does.

9. **Matching one-pixel region:** With valid positive extents and scratch values at consumption, the three pixel dependencies run in order before the packed store.

10. **Nonmatching source byte 7 or 248:** Both combined-mask operand references precede the endpoint decision. Byte 7 skips pixel work without delegation; byte 248 delegates.

11. **Distinct combined-mask observations:** Under unsigned 32-bit shift semantics, right operand hexadecimal 12345678 and left operand hexadecimal ABCDEF01 produce hexadecimal EF011234. Without suitable external-type semantics, this numeric result is not established.

12. **Different contribution-mask observations:** Destination calculations use the captured destination mask; the source expression uses its later external observation.

13. **Aligned pair:** With unchanged valid context, one positive row, two columns, and four-byte alignment, one paired update occurs without a scalar prefix or tail.

14. **Zero-width hazard:** One positive row with a misaligned start and zero columns performs a scalar prefix, makes the remaining count negative, and then performs a scalar tail. Zero width is not an empty-operation guarantee.
