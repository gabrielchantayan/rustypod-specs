# F-c1657415b585

## Purpose

F-c1657415b585 conditionally dispatches up to three pending operations through an interface receiver, then clears the corresponding pending indicators. Two operations carry values obtained from 16-bit state fields and reduced to their low eight bits. The third carries a byte-sized state value.

The established behavior is an ordered, callback-driven sequence over mutable state. It is not a snapshot-based batch: later pending indicators and payloads are examined after earlier callbacks return, so callback changes can affect the remainder of the invocation.

Interpreting these fields as a deferred-update mechanism is **inferred intent**. The meanings of the three operations, their payloads, and the receiver are unknown.

## Behavior

### Receiver acquisition and state selection

F-b7af80e829ec is called unconditionally, including when all pending indicators are zero. Its returned receiver is retained for all dispatches in the invocation.

The function reads the global state address after this call returns and retains that address for later checks and clearing writes. Consequently, the dependency may affect which state object is selected by changing the global before returning.

The first pending-indicator check and first payload read are expressed through the global state address, while the first clearing write and subsequent operations use the retained address. No intervening dependency call is shown between retaining the address and those initial reads. Without external interference, they refer to the same state object.

The exact number of physical loads of the global address is not established by the supplied representation. Concurrent or externally changing state is not given a synchronization contract.

### First operation

The byte at state offset +7 is examined.

If it is zero:

- The first operation is skipped.
- No first-payload read or first-indicator clearing write is shown for that branch.

If it is nonzero:

- The 16-bit first payload field at offset +10 is read.
- Its value is masked with 255.
- The receiver operation selected at dispatch-table offset 0x4C is called with the retained receiver and the masked value.
- After that operation returns normally, zero is written to offset +7 of the retained state object.

The effective payload is therefore in the range 0–255. The upper eight bits of the 16-bit source field do not affect it. The source field is not explicitly cleared or otherwise rewritten by this function.

The pending indicator is cleared **after**, not before, the callback. If the callback writes a nonzero value back to that same indicator and returns, this function’s subsequent clearing write overwrites it.

### Second operation

After the first operation has either been skipped or returned and had its indicator cleared, the byte at retained-state offset +8 is examined.

If it is zero, the second operation is skipped.

If it is nonzero:

- The 16-bit second payload field at offset +12 is read.
- Its value is masked with 255.
- The receiver operation selected at dispatch-table offset 0x3C is called with the retained receiver and the masked value.
- After normal return, zero is written to retained-state offset +8.

The second pending indicator and payload are not snapshotted before the first callback. A first callback that changes either field can therefore change whether the second operation runs and what value it receives.

The second payload field is not explicitly cleared or rewritten by this function.

### Third operation

After processing the second operation, the byte at retained-state offset +5 is examined.

If it is zero, the function returns without calling the third operation or clearing the third payload.

If it is nonzero:

- The byte-sized third payload at offset +6 is read.
- The receiver operation selected at dispatch-table offset 0x64 is called with the retained receiver and that payload.
- After normal return, zero is written to offset +5.
- Zero is then written to offset +6.
- The function returns.

The two final writes have a defined order in the supplied representation: pending indicator first, payload second.

The third payload is an eight-bit source value. Its exact signedness and argument-extension convention are not established. In particular, the supplied evidence does not establish how values with bit 7 set are interpreted by the target operation.

### Cross-operation ordering

For one non-reentrant invocation, the possible callback sequence is strictly:

1. First operation, if enabled when checked.
2. Second operation, if enabled when checked.
3. Third operation, if enabled when checked.

A later callback does not cause an earlier operation to be revisited. For example, if the second callback enables the first pending indicator, that newly enabled first operation is not processed again during this invocation.

The receiver address is retained, but its dispatch table is not shown as retained across callbacks. Each enabled dispatch obtains its operation through the receiver’s table at that point. A callback that changes the receiver’s table can therefore affect a later dispatch.
