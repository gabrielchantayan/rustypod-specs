# F-397f308d4bc4

## Purpose

F-397f308d4bc4 clears a caller-provided result slot, scans a zero-terminated byte sequence, and conditionally invokes dependencies using an address selected relative to the sequence’s terminator.

**Established behavior:** the function scans the entire sequence, clamps the requested count using a signed comparison, selects a candidate address, and conditionally performs a sizing-related call, an allocation-related call, a transfer-related call, and an explicit zero-byte write.

**Inferred intent:** construct a result containing at most the requested number of trailing source bytes. This is not an unconditional output guarantee. The amount passed to the transfer dependency comes from another dependency’s return value, not directly from the requested count.

**Unresolved behavior:** dependency semantics, ownership, and the final relationship between returned storage and the result slot. The visible body does not directly assign the allocation-related return value to the result slot. That slot’s final value can depend on any dependency’s effects and on aliasing with direct writes.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Entry and null-source handling

The first direct memory operation is a 32-bit zero write to the result slot. The function then reads the 32-bit source address from the source slot.

If that address is zero, the function returns immediately. It does not scan source bytes, invoke dependencies, or perform the later cleanup check.

The old result-slot value is not saved or passed to a release-related dependency before being overwritten. Whether this loses a resource depends on an ownership contract not supplied here.

### Source scan

For a nonzero source address, the function reads successive bytes in increasing address order until it reads a zero byte.

A signed 32-bit length counter starts at zero and increases once for each nonzero byte. The terminator is read but does not contribute to the counted payload length.

This scan precedes count rejection. Consequently, zero and negative requests do not avoid scanning a nonzero source address through its terminator.

No encoding validation or character-boundary processing is visible. The operation is byte-oriented; an ordinary suffix selection can begin inside a multibyte character.

The ordinary interpretation below requires that the payload length fit in a nonnegative signed 32-bit value and that the relevant address arithmetic remain valid. Overflow behavior is unresolved.

### Count selection

After the scan, the function compares the counted length with the requested count using signed comparison. If the length is smaller, it replaces the request with the length.

Call the resulting value the **effective count**. For an ordinary representable source length:

| Requested count | Effective count |
|---|---|
| Positive and smaller than the length | Requested count |
| Equal to or larger than the length | Source length |
| Zero | Zero |
| Negative | Original negative request |

The candidate address is then formed by subtracting the effective count from the terminating zero byte’s address in the supplied 32-bit representation.

For a positive effective count within the scanned payload, this selects the beginning of that many trailing bytes. When the effective count equals the payload length, the candidate is the original source address.

Candidate-address arithmetic occurs before the processing gate rejects zero or negative counts. Computing the candidate does not itself read bytes at that address. Arithmetic outside the representation’s supported range is not established as safe merely because a later gate would reject the count.

### Processing gate

The processing path requires all of the following:

1. The candidate address is nonzero.
2. The effective count is nonzero.
3. The effective count is nonnegative under signed 32-bit comparison.

Thus, where the preceding arithmetic is valid, processing requires a strictly positive effective count and a nonzero candidate address.

A zero or negative effective count fails the gate. A zero candidate address also fails it, independently of the count.

### Bypass cleanup
