# F-27487a7ca3f9

## Purpose

F-27487a7ca3f9 searches forward through integer elements, returning 1 when an eligible element equals the requested integer and 0 when the pointer is null or a stopping comparison ends the search.

Eligibility is determined before matching: at each position, the function first compares the current element with a value supplied by shared storage. Only if those operands compare unequal does it compare the element with the request.

**Inferred intent:** a membership query over a sequence terminated by a shared sentinel.

**Established limitation:** the shared object’s declaration is absent. Its type, width, signedness, and the conversions applied in the stopping comparison are not established. Consequently, describing the search as ordinary integer-sentinel membership requires a compatible integer-terminator model; it is not an unconditional property of the supplied evidence.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Null input

A null sequence pointer returns 0 without entering traversal.

Neither a sequence element nor the shared stopping operand is evaluated on this path. The requested value does not affect the result.

### Per-position decisions

For a non-null pointer, the stopping comparison is the first decision at every position.

If the current element and the shared operand compare equal under the applicable comparison semantics, traversal ends and the function returns 0.

If they compare unequal, the function evaluates the current element for equality with the requested value. A successful candidate comparison returns 1 immediately. Otherwise, traversal advances to the next integer element and repeats.

These dependencies establish:

- Stopping takes precedence over candidate matching at the same position.
- A position recognized by the stopping comparison is not subjected to the candidate equality comparison.
- A successful candidate comparison prevents advancement to the next position.
- A stopping comparison that ends traversal prevents advancement past that position.
- The visible traversal does not evaluate later elements after either stopping event.

The relative evaluation order of the two operands **within** a stopping comparison is not established.

### Stable-storage interpretation

With stable storage and fixed, valid comparison semantics, the searched region consists of the consecutive positions before the first position recognized by the stopping comparison. Within that region, the result is 1 exactly when a candidate equality comparison finds the requested integer.

This formulation does not require the shared operand to have the element type. It describes stopping by the comparison’s result rather than by an assumed common integer representation.

Under the additional assumption of a **compatible integer-terminator model**, the simpler sentinel description applies:

- The shared operand represents a fixed integer sentinel.
- The stopping comparison preserves ordinary integer equality between an element and that sentinel.
- The searchable region is the prefix before the first element equal to the sentinel.
- The sentinel element is excluded from membership.
- Requesting the sentinel returns 0, provided traversal reaches a stopping position normally.

Without that compatibility assumption, numerical claims about “the same sentinel value” are not established. Missing conversion semantics may affect which element values satisfy the stopping comparison.

### Repeated evaluations and changing storage

The visible body evaluates the current element in the stopping comparison and, conditionally, again in the candidate comparison. It does not explicitly retain a single element value for both decisions.

The shared operand is also referenced on each stopping-condition evaluation rather than through an explicit local snapshot.

These facts do not establish exact machine-load counts. Nor do they guarantee that changing storage yields one consistent value across comparisons.

If an element changes between its two evaluations, the candidate equality may observe a value different from the one used to pass the stopping condition. If the shared input changes between positions, later stopping comparisons need not use the earlier observed value.

The evidence supplies no synchronization, atomicity, visibility, or mutation protocol. It therefore does not define a deterministic result from an initial snapshot when relevant storage changes during execution. The stable-storage membership interpretation must not be extended into a concurrency guarantee.
