# F-e87d3815901b

## Purpose

F-e87d3815901b performs an entry-state-dependent halfword transfer, may perform one additional halfword update under highly restrictive conditions, and then enters an unconditional cycle of two indirect calls followed by a software interrupt.

No ordinary return, success result, or application-level error result is represented. The supplied representation does not establish an application purpose for the transfers, call targets, or interrupt.

The contract below distinguishes behavior established by the supplied representation from facts that require an instruction-level or runtime interpretation. In particular, pointer-shaped intermediate values participate in 32-bit arithmetic; they do not establish the existence of valid objects.

## Behavior

### Entry classification

The selector is multiplied by four as a 32-bit quantity. The initial transfer occurs exactly when that product is zero.

Under the represented 32-bit arithmetic, the transfer-enabled selector values are:

- `0x00000000`
- `0x40000000`
- `0x80000000`
- `0xC0000000`

For every other selector value, the represented path performs no explicit data-memory access before entering the repeating call-and-interrupt phase.

This condition must not be narrowed to “selector equals zero.” Three nonzero selectors also enable the transfer.

### Initial halfword transfer

On a transfer-enabled entry, the destination address is the source address plus the transfer displacement, with 32-bit wraparound.

The observable memory ordering is:

1. Read one unsigned 16-bit value from the source address.
2. Write that value as a 16-bit quantity to the destination address.

The represented working source address is also replaced by the destination address minus the adjustment. This replacement is used by subsequent comparisons; it does not cause another read at the replacement address.

There is no allocation, ownership transfer, release, or validation associated with this operation.

Aliasing is permitted by the arithmetic. If the source and destination addresses are equal, the operation remains a read followed by a write of the read value. If the destination overlaps memory used later, those later reads observe the intervening write, subject to the execution environment.

### Conditions for the additional halfword update

The representation contains a long series of zero-result gates. Their combined effect can be stated without treating each arithmetic expression as a separate public operation.

Under the 32-bit interpretation above, the additional update is reached only when all of the following hold:

1. The selector is one of the four transfer-enabled values.
2. The link address is zero.
3. The stack anchor is zero.
4. The comparison word equals the transfer displacement.
5. The adjustment equals the updated working source address: destination address minus adjustment, modulo \(2^{32}\).
6. The auxiliary word is zero.
7. Twice the transfer displacement is zero modulo \(2^{32}\).

The final condition restricts the transfer displacement to `0x00000000` or `0x80000000`.

The adjustment comparison can equivalently be expressed as twice the adjustment equaling the destination address modulo \(2^{32}\). This equivalence does not imply a unique adjustment: modular doubling can have two solutions or none.

These conditions are derived from the supplied static representation. They are not observed runtime conditions.

A consequence of these constraints is that a nonzero stack anchor prevents the additional update. A stack anchor of one can satisfy an earlier shifted-address comparison, but cannot satisfy the later zero-sum condition.

### Additional halfword update

If all additional-update conditions hold, the represented path:

- Assigns zero to the architecture-specific state location.
- Forms an updated link-derived address that is also zero.
- Reads a 16-bit value at address zero.
- Uses that value, zero-extended to 32 bits, as a destination address.
- Stores the read value plus 15 as a 16-bit quantity at that destination.

The store therefore wraps at 16 bits. For example, a read value of `0xFFF8` produces a stored value of `0x0007`.

The assignment represents two uses of the halfword at the link address: one to determine the destination and one to determine the value. It does not establish a relative evaluation order between those uses or a physical bus-read count. If memory can change independently, the two observations need not be assumed identical.

The initial transfer precedes this update. If that transfer writes address zero, the additional update can use the newly written halfword.

### Later conditional fragments are not reachable

The representation contains further conditional arithmetic and memory operations after the additional-update block. They do not describe additional reachable behavior under the stated 32-bit model.

The decisive relationship is:

- Reaching the additional-update block requires the initial four-times-selector value and the earlier stack/link-derived comparison value both to be zero.
- That block advances a halfword-pointer-shaped value from zero to byte address two.
- The next zero-result gate can pass, but the following gate compares the resulting byte address two against the earlier zero value through an exclusive-or operation.
- The result is two, not zero, preventing the remaining conditional chain from executing.

If the additional-update block is not reached, the entry gate for that later chain is already false.

Consequently, the later signed-halfword read, paired word stores, extra displacement updates, and variable-shift arithmetic do not form part of the reachable memory contract. This conclusion depends on the supplied representation being an accurate account of the executable control flow and widths.

### Repeating indirect calls and interrupt

After the conditional entry behavior, execution enters an unconditional repeating phase.

Each iteration, assuming every preceding operation returns normally, performs:

1. An indirect call to dependency F-unknown-01 with three represented arguments: zero, zero, and the 32-bit word `0xFFFFFFA5`.
2. An indirect call to dependency F-unknown-02 with no explicit arguments represented.
3. A software interrupt with immediate value `0x5B`.
4. Replacement of the first-call address basis with `0x083D4CC2`.

For the first iteration, the first call target is the incoming link address plus `0xEB6`, modulo \(2^{32}\). The conditional entry behavior does not change that final first-iteration target.

For subsequent iterations, the represented first call target is `0x083D5B78`.

The second call target is `0x0857A94B` on every represented iteration.

The third argument to F-unknown-01 is specified as a 32-bit bit pattern. It is equivalent to −91 under signed 32-bit interpretation, but the callee’s signedness contract is unknown.

The target addresses are numeric computed targets, not memory slots from which another function pointer is loaded.

If either call fails to return, the remaining operations in that iteration are not reached. Likewise, if the interrupt terminates execution, traps indefinitely, or transfers control elsewhere without returning, no later iteration is established.

## Acceptance examples

These are conditional static acceptance examples. No runtime tests have been performed.

### Selector bypasses the transfer

Given selector `1` and link address `0x1000`:

- There is no represented data-memory access before the repeating phase.
- The first call target is `0x1EB6`.
- F-unknown-01 receives the three specified arguments.
- If it returns, F-unknown-02 is invoked at `0x0857A94B`.
- If that call returns, interrupt `0x5B` is invoked.
- If the interrupt returns, the next first-call target is `0x083D5B78`.

This example requires valid executable targets to progress through the sequence.

### A nonzero selector enables the transfer

Given selector `0x40000000`, source address `0x1000`, transfer displacement `6`, and a readable halfword value `0xBEEF`:

- The initial destination is `0x1006`.
- The function reads `0xBEEF` at `0x1000`.
- It writes `0xBEEF` at `0x1006`.

A contract that skips this transfer because the selector is nonzero is incorrect.

### Transfer wraps in the address domain

Given a transfer-enabled selector, source address `0xFFFFFFFE`, and displacement `4`, the represented destination is `0x00000002`.

Whether those addresses can actually be accessed is environmental. The arithmetic does not itself reject the wraparound.

### Nonzero stack anchor blocks the additional update

Given a transfer-enabled selector and stack anchor `0x1000`, the initial transfer still occurs if its addresses are valid. The additional address-zero-derived update is not reached, regardless of the remaining comparison inputs.

### Additional update follows an earlier write to address zero

Assume:

- Selector, link address, stack anchor, transfer displacement, comparison word, adjustment, auxiliary word, and source address are all zero.
- Address zero supports the required accesses.
- Its initial halfword value is `0x0010`.

The initial transfer reads and rewrites `0x0010` at address zero. The additional update then writes `0x001F` at byte address `0x10`. The first indirect-call target is `0xEB6`.

This example does not establish that an actual execution environment permits address-zero access.

### The first dependency does not return

If F-unknown-01 does not return on an iteration, that iteration does not reach F-unknown-02 or interrupt `0x5B`. Unconditional repetition in the representation does not override dependency control flow.
