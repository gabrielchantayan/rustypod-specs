# F-0ee5f658b680

## Purpose

F-0ee5f658b680 is a mode-dependent dispatcher. It selects one of two dependencies using a byte in a caller-supplied object, obtains an additional argument from that object, and forwards either separate low-order values or packed 32-bit values.

The established dispatch behavior is:

- Mode byte zero: invoke F-c41a20765e01.
- Mode byte one: invoke F-d2f4138dec48.
- Any other mode byte: return without invoking either dependency.

A separate input determines whether a global-derived control value is retained or replaced with zero before dispatch. This input does not determine whether dispatch occurs.

The apparent intent is to adapt the same input set to two downstream argument formats. That interpretation is inferred from the argument construction; the meanings of the modes, packed fields, global value, and downstream operations are not established.

## Interface

### Inputs

The function accepts six positional inputs. The supplied representation uses 32-bit integer and word types. The following names describe their roles in this contract, not source-level identifiers.

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | Object address | An integer-valued address used to locate a mode byte at offset 0x65 and a 32-bit word at offset 0x70. Also forwarded unchanged as the first dependency argument. |
| 2 | Primary value | An unsigned 32-bit value. Only its low 16 bits reach either dependency. |
| 3 | Control selector | A signed 32-bit integer tested only for equality to zero. Zero selects a zero control value; every nonzero value selects the global-derived control value. |
| 4 | Primary extension | A signed 32-bit integer shifted left by 16 positions for the mode-one call. It is not used in the mode-zero call. |
| 5 | Control extension | A signed 32-bit integer shifted left by 16 positions and combined with the selected control value for the mode-one call. It is not used in the mode-zero call. |
| 6 | Forwarded word | An uninterpreted 32-bit word passed unchanged as the fifth argument to either dependency. |

The function also reads a global 32-bit value. Its numeric value, storage properties, and external meaning are not supplied.

The object layout known to this function is limited to:

| Object-relative offset | Width | Interpretation here |
|---|---|---|
| 0x65, or 101 bytes | One byte | Dispatch mode. Zero and one are the only recognized values. |
| 0x70, or 112 bytes | Four bytes | Uninterpreted object-associated word forwarded as the second dependency argument. |

Nothing establishes the object's total size, allocation origin, other fields, or the meaning of the forwarded object-associated word. In particular, the latter is not established to be a pointer, resource handle, or owned allocation.

### Output

The function has no specified return value. It does not expose a dependency's return value or a dispatch-status result.

A normal return therefore does not distinguish a supported dispatch from an unsupported mode. It also does not establish successful completion of any downstream operation.

### Preconditions

For defined ordinary execution:

- The object address must permit the required byte access at offset 0x65.
- On a path that dispatches, it must also permit the four-byte access at offset 0x70.
- The global value must be readable.
- Any additional requirements imposed by the invoked dependency must hold.

There is no explicit null check, object-length check, address-overflow check, alignment check, or validation of the object-associated word.

Alignment requirements, invalid-address behavior, and the formal treatment of signed left shifts are documented uncertainties. This contract does not invent validation or recovery behavior.

## Behavior

### Control-value selection

The represented operation first obtains the global 32-bit value.

If the control selector is zero, the selected control value becomes zero. Otherwise, it remains the global-derived value.

Only zero versus nonzero matters. A selector of one, a larger positive value, or a negative value has the same selection effect. The selector is not multiplied into the global value, and its magnitude is not forwarded.

The initial global read is represented even when the selector is zero or the eventual mode is unsupported. Whether that read has externally observable consequences depends on storage properties not provided here.

### Mode observation and dispatch

The function reads the object's mode byte at offset 0x65.

**First observation is zero.** The function reads the object-associated word at offset 0x70 and invokes F-c41a20765e01 with five arguments, in this positional order:

1. The original object address.
2. The object-associated 32-bit word.
3. The primary value restricted to its low 16 bits, represented in a 32-bit argument.
4. The selected control value, unchanged.
5. The forwarded word, unchanged.

The primary extension and control extension do not contribute to this call. In particular, the selected control value is not restricted to 16 bits on this path.

**First observation is nonzero.** The supplied representation contains a second mode-byte read. If this second observation is one, the function reads the object-associated word and invokes F-d2f4138dec48. Otherwise, it returns without a dependency call.

For a stable object, this means mode one dispatches and every mode other than zero or one does not.

For changing storage, the two observations must not be silently treated as one snapshot. A first observation of a nonzero value followed by a second observation of one selects F-d2f4138dec48. A first nonzero observation followed by zero selects neither dependency; the function does not return to the mode-zero path. These are consequences of the represented read structure, not a guarantee of supported concurrent access.

### Mode-one argument construction

F-d2f4138dec48 receives five arguments:

1. The original object address.
2. The object-associated 32-bit word.
3. A primary packed word.
4. A control packed word.
5. The forwarded word, unchanged.

Under the 32-bit machine-word interpretation of the supplied operations:

- The primary packed word's low half is the primary value's low 16 bits.
- Its high half is the primary extension's low 16 bits.
- The control packed word is the bitwise OR of the selected control value and the control extension shifted left by 16 bits.

The distinction between packing and OR-merging matters. The primary value is explicitly masked before combination, so its original upper half cannot affect the result. The selected control value is not masked. Any set bits already present in its upper half remain set after combination with the shifted control extension.

Consequently, the control extension does not necessarily replace the upper half of the selected control value. It can add set bits there but cannot clear existing ones.

If the control selector is zero, the selected control value is zero. On that path, the mode-one control packed word has a zero low half, with its high half supplied by the control extension under the same machine-word interpretation.

### Width and arithmetic boundaries

The explicit primary-value mask retains exactly 16 bits. The result is a 32-bit argument with its upper 16 bits clear before combination.

For a 32-bit bitvector left shift by 16:

- Bits originally above bit 15 are discarded.
- Bits originally in positions 0 through 15 move into positions 16 through 31.
- The low 16 bits of the shifted result are zero.

The extension inputs are displayed as signed integers. Literal signed-language semantics can differ from these bitvector rules, particularly for negative inputs or shifts whose mathematical result is outside the signed range. The supplied representation does not resolve that distinction for all inputs. Examples involving such values therefore require an explicit machine-word assumption.

No arithmetic overflow error, range rejection, saturation, or checked conversion is represented.

### Completion and failure paths

At most one dependency call is represented per invocation. No fallback from one dependency to the other is present.

After a dependency call returns normally, this function returns. If a dependency faults, raises an exception, terminates execution, or does not return, this function has no represented handler or recovery path.

Unsupported modes cause a silent return. They do not produce an explicit error, invoke a default dependency, or clear object state.

## Side effects

### Direct reads and writes

The represented direct accesses are:

1. Read the global control source.
2. Read the mode byte.
3. If the first mode observation is nonzero, read the mode byte again.
4. If the selected branch dispatches, read the object-associated word.
5. Invoke the selected dependency.

No direct object-field write, global write, allocation, release, logging operation, or I/O operation appears in this function.

The ordering above describes the supplied representation. It is not evidence of volatile access, atomicity, synchronization, or a guaranteed physical load sequence under optimization.

The input values are passed by value. Forwarding the object address does not itself copy the object.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless otherwise stated, assume valid memory, stable object contents, and dependencies that return normally.

### Mode zero discards the primary upper half

Given mode zero, primary value 0x89ABCDEF, and control selector zero:

- F-c41a20765e01 is invoked once.
- Its third argument is 0x0000CDEF.
- Its fourth argument is zero.
- The two extension inputs do not affect the call.
- F-d2f4138dec48 is not invoked.

The object address, object-associated word, and forwarded word retain their respective positions.

### A nonzero selector preserves the full selected control value

Given mode zero, a negative nonzero control selector, and global value 0x12345678:

- The fourth dependency argument is 0x12345678.
- It is not reduced to 0x00005678.
- The selector's negative sign does not select a separate branch.

### Mode one packs the primary fields

Given mode one, primary value 0x89ABCDEF, primary extension 0x1234, and control selector zero:

- F-d2f4138dec48 is invoked once.
- Its third argument is 0x1234CDEF.
- The original upper half 0x89AB does not contribute.

These values do not require a signed-overflow interpretation for the primary shift.

### Control packing preserves overlapping set bits

Given mode one, global value 0x00F000AA, nonzero control selector, and control extension 0x000F:

- The shifted extension contributes 0x000F0000.
- The fourth dependency argument is 0x00FF00AA.
- A result of 0x000F00AA would incorrectly replace, rather than OR-merge, the global-derived upper bits.

### Zero selector removes the global contribution

Given mode one, global value 0x76543210, control selector zero, and control extension 0x002A:

- The fourth dependency argument is 0x002A0000.
- Neither half of the global value contributes to that argument.
- This does not establish that the initial global read is absent.

### Unsupported stable mode performs no dispatch

Given a stable mode byte of two or 0xFF:

- Neither dependency is invoked.
- The object-associated word is not read by the represented path.
- No direct write occurs.
- The function returns without an explicit status.

A high-bit-set byte is not mode one regardless of whether a platform interprets plain character values as signed.

### Extension truncation is conditional on machine-word semantics

Given mode one and primary extension 0x00011234, a 32-bit bitvector shift produces the same high half as extension 0x00001234. Both produce primary packed word 0x1234CDEF when the primary low half is 0xCDEF.

This criterion is conditional because the larger signed input's left shift is not necessarily defined under literal signed-language rules.
