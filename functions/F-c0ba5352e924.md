# F-c0ba5352e924

## Purpose

F-c0ba5352e924 conditionally reads and returns one byte from a strided memory region. A two-word descriptor supplies a base address and a signed comparison bound. The second argument supplies the signed value used both for eligibility and for address calculation.

The function returns zero without accessing the strided region when the descriptor’s base word is zero or when the second argument is not strictly less than the bound under signed 32-bit comparison. Otherwise, it reads the byte at displacement six within a 24-byte stride.

This is not a conventional fully checked array lookup. In particular, there is no nonnegative-index requirement. Negative second-argument values can pass the comparison and select addresses before the base.

## Interface

### Inputs

The function accepts two pointer-shaped arguments. Their observable uses differ:

| Input | Required interpretation |
|---|---|
| First argument | Address of a descriptor containing a required 32-bit first word and a conditionally required 32-bit second word. |
| Second argument | A 32-bit address-shaped value whose bits are interpreted as a signed integer for comparison and address arithmetic. The function does not dereference this argument directly. |

The descriptor has the following established layout:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 4 bytes | Base-address word. Zero disables the eventual byte read. |
| 4 | 4 bytes | Signed bound, read only when the base-address word is nonzero. |

The first word is used as an address bit pattern, not as a signed magnitude. A nonzero value with its high bit set is not rejected.

The second word is interpreted as a signed 32-bit integer. The second argument’s 32-bit representation is interpreted the same way for the eligibility comparison. Neither its pointer-shaped type nor its numerical value establishes that it points to an object.

### Output

The result is one byte:

- Zero when the base word is zero.
- Zero when the base word is nonzero but the second argument is not strictly less than the signed bound.
- The byte read from the calculated address otherwise.

The returned byte preserves the selected byte’s eight-bit pattern. No signed interpretation, character encoding, or Boolean normalization is established.

A zero result does not distinguish an ineligible access from an eligible access that reads a zero byte.

### Width and address model

The supplied static representation establishes four-byte words and a four-byte subtraction-overflow test. The behavioral description therefore uses:

- 32-bit descriptor words;
- signed 32-bit comparison operands;
- eight-bit result data;
- 32-bit address arithmetic for the selected-byte calculation.

The contract does not extend these operations to native-width pointers on a wider host. A wider-host implementation would need to preserve the observed 32-bit behavior explicitly.

### Preconditions

For an execution that returns normally:

1. The first argument must permit reading the descriptor’s first four bytes.
2. If the first word is nonzero, the next four bytes must also be readable.
3. If the signed eligibility condition passes, the calculated byte address must be readable.

The function performs no explicit validation of these requirements. Null or inaccessible descriptor storage is not handled by a defined error return.

No storage reachable by dereferencing the second argument is required merely because it is pointer-shaped. Readability is required only at the eventual calculated address, if that read occurs.

## Behavior

### Descriptor-read ordering

The function first reads the descriptor’s first 32-bit word. The loaded value is retained for the subsequent decision and address calculation.

If that value is zero, the function returns zero. It does not read the second descriptor word and does not read a byte from the strided region.

If the first word is nonzero, the function next reads the descriptor’s second 32-bit word. That loaded word becomes the comparison bound.

Thus, the order of data reads established by the function is:

1. Descriptor word at offset zero.
2. Descriptor word at offset four, only if the first word was nonzero.
3. Selected byte, only if the signed eligibility condition succeeds.

No reload of either descriptor word is present in the supplied static representation.

### Eligibility comparison

With a nonzero base word, the selected-byte read occurs exactly when the signed 32-bit value of the second argument is strictly less than the signed 32-bit bound.

Equality is rejected. A value greater than the bound is also rejected.

The subtraction used to implement the comparison is accompanied by signed-overflow handling. Consequently, eligibility must not be reproduced by checking only the sign of a wrapped subtraction. For example, a positive bound and a negative second argument remain ordered as signed values even when their subtraction crosses the signed 32-bit range.

There is no separate lower-bound check. Consequences include:

- A negative second argument can be eligible under a positive, zero, or suitably larger negative bound.
- A zero bound does not categorically prevent access: negative second-argument values can still pass.
- A negative bound does not categorically prevent access: more-negative values can still pass.
- The minimum signed 32-bit bound admits no second-argument value, because no signed 32-bit value is strictly smaller.

These are consequences of the established comparison, not evidence that negative indexing is intended.

### Selected-byte address

For an eligible access, the byte address is:

**base-address word + 24 × signed second-argument value + 6**

The calculation uses the 32-bit address result. Equivalently, the resulting address bit pattern is the sum reduced modulo \(2^{32}\).

The multiplication is by 24, not by the four-byte width of the pointer-shaped input’s apparent element type. The final read is one byte, regardless of the input types.

The fixed displacement of six and stride of 24 are established. The source does not establish the meaning or layout of the other 23 bytes in a stride. It also does not establish that the descriptor actually describes a contiguous allocation large enough to cover every eligible address.

There is no check for:

- Multiplication or addition wrapping the 32-bit address space.
- The selected address preceding the base.
- The selected address lying inside an allocated object.
- The selected address overlapping the descriptor.
- Any relationship between the bound and the size of an allocation.

If a calculated address overlaps descriptor storage, the earlier word reads still precede the byte read. The final byte is read from memory; it is not extracted from a retained descriptor word.

### Return and failure behavior

After an eligible byte read, the function returns that byte. Otherwise, it returns zero.

No explicit error status, exception construction, retry, logging, or fallback access is established. If a required memory read cannot complete, the supplied source does not define a successful return value or recovery action. Fault behavior belongs to the execution environment and is documented_only here.

## Acceptance examples

These examples are conditional behavioral expectations derived from static evidence. They are not reports of executed tests. Unless stated otherwise, all accessed storage is assumed readable and unchanged during the call.

### Disabled descriptor

Given a descriptor whose first word is zero:

- The result is zero for every second-argument bit pattern.
- The second descriptor word is not read.
- No strided-region byte is read.

The result does not depend on whether storage for the second descriptor word is readable, because that read is skipped.

### Eligible positive value

Given a base word of `0x00001000`, a signed bound of 3, and a second-argument value of 2:

- The comparison succeeds.
- The selected address is `0x00001036`: base plus 48 plus six.
- If that address contains byte `0xA5`, the result is `0xA5`.

No other byte in the corresponding 24-byte stride is read by this function.

### Equality at the bound

Given a nonzero base word, a signed bound of 3, and a second-argument value of 3:

- Both descriptor words are read.
- The result is zero.
- No selected-byte read occurs.

Equality must remain ineligible even if the arithmetic difference is zero.

### Negative value with a zero bound

Given a base word of `0x00001000`, a signed bound of zero, and a second-argument value of −1:

- The comparison succeeds.
- The selected address is `0x00000FEE`, which is 18 bytes before the base.
- The result is the byte at that address.

An implementation that rejects every negative value would not preserve the established behavior.

### Signed versus unsigned ordering

Given a nonzero base word, a bound bit pattern of `0xFFFFFFFF`, and a second-argument value of zero:

- The bound is interpreted as −1.
- Zero is not less than −1.
- The result is zero without a selected-byte read.

Treating the bound as an unsigned maximum would produce a different result.

### Comparison despite subtraction overflow

Given a base word of `0x00001000`, a bound of 2,147,483,647, and a second-argument value of −1:

- The signed comparison succeeds.
- The selected address is `0x00000FEE`.
- The byte there is returned.

The mathematical difference between the bound and −1 exceeds the signed 32-bit maximum. The overflow-aware comparison nevertheless preserves the correct signed ordering.

### Address wrap

Given a base word of `0xFFFFFFF8`, a bound of 2, and a second-argument value of 1:

- The comparison succeeds.
- Adding 24 and then six produces the 32-bit selected address `0x00000016`.
- If that address is readable, its byte is returned.

The function does not reject the address wrap.

### Minimum signed bound

Given any nonzero base word and a bound bit pattern of `0x80000000`:

- No signed 32-bit second-argument value is eligible.
- The result is zero.
- No selected-byte read occurs.

The second descriptor word is still read.
