## Behavior

### Entry and path selection

The routine establishes three predicates from A:

- Whether unsigned A exceeds `0xFFFFFFCD`.
- Whether adding `0x32` causes signed 32-bit overflow.
- Whether the retained sum is negative.

It then reads an unsigned byte at twice C, with the address reduced to 32 bits. This read precedes the first dependency call.

The first indirect target is the incoming return-link value plus `0xEEA`. After that call returns a pair, the routine writes the low eight bits of C at the returned low word plus C. It then loads a global base word.

The **extended path** is selected when the sum’s negative predicate differs from its overflow predicate. Under the specified arithmetic, this is equivalent to signed A being less than −50. Otherwise execution takes the **direct path**.

On the direct path, the entry byte remains available to the common continuation and can affect its initial body-store value. On the extended path, another byte replaces it before subsequent explicit consumption.

### Extended path: initial operations

The subsequent sequence is:

1. Read a signed halfword at the derived base plus the replacement byte.
2. Read 16 uninterpreted bits at the saved global base plus that signed value.
3. Write the zero-extended replacement byte as 32 bits at global base plus `0x54`.
4. Call a dependency with the loaded 16-bit quantity.
5. Read and retain a word at the replacement byte’s numeric value plus `0x34`.
6. Perform a coprocessor operation with fixed selectors 9, 3, and 3, the sign-extended halfword, and the two incoming processor-control values.
7. Call a dependency returning 16 bits; store those bits at its secondary-result address plus `0x3C`.
8. Make two calls; read an unsigned halfword at the second call’s secondary-result address plus `0x24`.
9. Make another call, obtain a word from the following call, and pass that word with an existing stack word to another dependency.
10. Obtain a new 64-bit pair from a further call.

The routine then performs these stores in order:

| Destination | Width | Value |
|---|---:|---|

The next sequence is:

### Extended path: subtraction overflow

A dependency receives the scalar and its arithmetic right shift by 25. With the returned word as a base, the routine:

1. Stores the retained subtraction result at base plus `0x64`.
2. Reads a word at base plus `0x07000000`.

- Offset plus the loaded word.

#### Carry-selected interrupt path

2. Read an unsigned byte at base plus `0x07000008` plus offset.
3. Call a dependency.
4. Store the saved doubled scalar as 32 bits at base plus `0x07000054`.
5. Call a dependency.
6. Store the zero-extended byte from step 2 as 32 bits at base plus `0x07000044`.

10. Call another dependency with that scalar minus `0xA6`, retaining 32 bits.

The routine first stores the operand’s **low 16 bits** at replacement low word plus `0x2A`. It then compares:

- Twice its pair’s low word.
- Four times the square of its pair’s high word.

Both retain 32 bits.

It makes three calls. The first receives the pair’s low word plus an incoming ambient word. The second receives a global word evaluated for that call. After the third call, the routine reads a global selector.

If the selector is zero, the shared return produces:

- Low word: twice the arithmetic-right-shift-by-nine of the third call’s secondary result.
- High word: the return-time global word minus `0x54`.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume preceding accesses succeed and required calls return.

1. **Entry boundary.** A of `0xFFFFFFCE` represents −50, selects the direct path, and makes the initial unsigned condition true. A of `0xFFFFFFCD` represents −51, selects the extended path, and makes that initial condition false.

2. **Entry-read failure.** Failure of the read at twice C prevents reaching the first call and following byte write in the displayed sequence.

3. **Narrow initial write.** If C ends in `0xA7`, the post-first-call store writes byte `0xA7`; its address still uses the full word components.

4. **Entry-byte consumption.** On a direct path entering the body, an entry byte of `0xA7` and ambient subtraction operand of `0x100` produce initial body-store value `0x59`.

5. **Full-width predicate versus stored halfword.** On the direct path, let the predicate operand be `0x80000000`, the replacement high word be `0x2F`, and the retained unsigned condition be true. The halfword store writes zero. The full-width negative predicate is nevertheless true, while subtraction overflow is false, so execution selects the body.

6. **Overflow versus borrow.** Subtracting record address one from `0x80000000` causes signed overflow. Subtracting one from zero does not, despite unsigned underflow.

7. **Call placement in the carry path.** If the dependency after the byte read changes the source byte in memory, the later word store still uses the already captured byte. A dependency before the read may instead affect the value captured. The same reasoning requires retaining every specified call/access boundary.

8. **Loop-carried replacement.** A tail pair with low word three and high word four retains square-derived value 64. If its third call supplies secondary result `0x1000` and the selector is nonzero, it stores 64 at `0x3C`. The next body receives argument six and high state `0x1000`, then stores 64 at `0x103E` after its two calls.

9. **Return-test boundary.** Incremented body state `0x00008000` selects the early shared return because scaling by `0x10000` yields retained word `0x80000000`.

10. **Dispatch evaluations.** If the dispatch global evaluates to X for the first argument and Y for the separate byte-address expression, the arguments use X and the byte at Y plus nine. Equality of X and Y is not required.
