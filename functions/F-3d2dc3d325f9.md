# F-3d2dc3d325f9

## Purpose

F-3d2dc3d325f9 coordinates processing of a range in two stages: consecutive blocks of 84 address units, followed by paired whole-range operations whose size argument grows by a factor of four between pairs.

The established behavior is a sequence of calls to three dependencies. The supplied representation does not establish what those dependencies do to the referenced data. In particular, sorting, comparison, copying, allocation, and memory release are not established properties of this function.

An inferred interpretation is that the range contains 12-unit records, that initial blocks contain seven records, and that subsequent paired operations combine progressively larger runs using a workspace. That interpretation explains the constants and argument arrangement, but it is not a substitute for the observable call contract.

This specification distinguishes:

- **Established static behavior:** operations and call relationships visible in the supplied representation.
- **Inferred intent:** plausible meaning not established without dependency contracts.
- **documented_only unknowns:** behavior that cannot be resolved from the supplied material.

No runtime tests have been performed.

## Behavior

### Initial saved count

Before any block-processing call, the function calls F-870c4fcf7295 with:

1. Range limit minus range start.
2. The constant 12.

Its returned integer is saved as the **initial count**. That value determines whether the later paired-operation stage runs and contributes to the workspace endpoint calculation.

The helper’s exact arithmetic is unknown. In particular, this contract does not equate it unconditionally with division by 12. Signedness, rounding, exceptional inputs, and side effects require its own specification.

The function does not refresh the initial count after later helper calls or block operations.

### Initial block-processing stage

The initial block cursor is the range start.

Before each possible complete block, F-870c4fcf7295 is called with:

1. Range limit minus the current block cursor.
2. The constant 12.

This includes a call at the initial cursor, even though the same argument values were already supplied when computing the initial count. These are separate calls, and their results need not be equal without additional guarantees about F-870c4fcf7295.

The returned integer is compared with 6 using the signed integer comparison shown in the supplied representation.

If that result is greater than 6:

- F-98ebf0126b92 receives the current cursor, current cursor plus 84, and the operation context.
- After that call returns normally, the cursor advances by 84.
- The remaining-range helper call is performed again at the new cursor.

If the helper result is 6 or less:

- No complete-block call is made for that condition evaluation.
- The loop ends.
- F-98ebf0126b92 is called once with the current cursor, the original range limit, and the operation context.

Thus, whenever the loop terminates normally, there is exactly one final block-processing call after it. This call is not omitted for an empty-looking interval, a reversed interval, or a negative helper result.

The final interval’s numerical length is not necessarily below 84. That interpretation requires the helper to behave consistently with counting 12-unit records. The coordinator itself decides solely from the returned integer.

A further boundary consequence is that a helper result of exactly 7 takes the complete-block branch. If that advances the cursor precisely to the range limit and the next helper result ends the loop, the final block-processing call has equal endpoints.

### Paired-operation stage

After the final block-processing call returns, a size parameter begins at 7.

The function performs an iteration only while that size is strictly less than the saved initial count. Every iteration makes two calls, in this order:

| Call | First argument | Second argument | Third argument | Fourth argument | Fifth argument |
|---|---|---|---|---|---|
| First | Range start | Range limit | Workspace start | Current size | Operation context |
| Second | Workspace start | Workspace start plus initial count × 12 | Range start | Current size × 2 | Operation context |

Both calls target F-9514b3d301bb.

The first call must return before the second is reached. The second call’s arguments do not use a returned result from the first. Its source-looking endpoints are derived from the workspace start and the saved initial count, not from an endpoint reported by the dependency.

After both calls return, the size is shifted left by two bits before the next loop test. For positive values where these shifts remain representable, iteration sizes are:

7, 28, 112, 448, and so on.

The fourth arguments passed to the two calls in those iterations are respectively:

- 7 and 14;
- 28 and 56;
- 112 and 224;
- 448 and 896.

The comparison is strict. An initial count of 7 produces no paired-operation calls. An initial count of 28 produces the pair for size 7, but not the pair for size 28.

There is no intervening count-helper call during this stage.

Termination of the initial loop depends on helper results and arithmetic. Termination of the paired stage is straightforward only while the positive size progression remains representable. Neither loop has an independent iteration limit.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Empty interval with a quotient-like helper

Assume equal range endpoints and a helper that returns 0 for a zero difference.

Expected sequence:

- The saved initial count is 0.
- The first block-loop condition also returns 0.
- F-98ebf0126b92 is called once with equal endpoints.
- F-9514b3d301bb is not called.

Skipping the final empty-interval call would not match the visible behavior.

### Exactly seven 12-unit records

Assume the range length is 84, arithmetic is representable, and each helper call returns the exact record count.

Expected behavior:

- The saved initial count is 7.
- One complete-block call covers the entire range.
- A subsequent helper call at the range limit returns 0.
- The final block-processing call has equal endpoints.
- No paired-operation call occurs, because 7 is not less than 7.

### Eight 12-unit records

Assume the range length is 96 and the helper returns exact record counts.

Expected behavior:

- One initial block spans the first 84 units.
- The final block-processing call spans the remaining 12 units.
- One paired iteration occurs.
- Its first call uses the original endpoints, workspace start, and size 7.
- Its second call uses workspace start, workspace start plus 96, range start, and size 14.
- The next size is 28, so the paired stage ends.

This example establishes argument sequencing, not that the data becomes sorted.

### A strict iteration boundary

Assume a saved initial count of 28, normal termination of the initial stage, and representable arithmetic.

Only the size-7 pair occurs. Afterward the size becomes 28, which fails the strict less-than condition.

With a saved initial count of 29 under the same conditions, the size-7 and size-28 pairs occur. Their second-call size arguments are 14 and 56 respectively.

### Different results for repeated helper arguments

Assume the initial helper returns 20, but the next helper call, with the same difference and constant, returns 0.

The function still saves 20 for the paired stage. It makes no complete-block call, makes one final block-processing call over the original endpoints, and then performs the size-7 pair.

Replacing the two helper calls with a single shared result would change this behavior.

### Negative saved count

Assume the initial helper returns a negative integer and the block stage nevertheless terminates normally.

No paired iteration occurs because the positive initial size, 7, is not less than that negative count. Block-stage behavior remains controlled by its own helper results.
