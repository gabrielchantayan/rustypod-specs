# F-89299f871b1f

## Purpose

The established behavior is a memory-state transformation followed by indirect dispatch. The supplied evidence does not establish a higher-level purpose, object model, or ownership protocol. In particular, the small constants, byte fields, and scaled-address writes do not establish that this operation initializes an object, links a list, or processes a particular kind of message.

This contract describes the visible accesses and their order. It does not assume that distinct addresses refer to disjoint storage, that address-bearing values are valid pointers, or that the indirect dependency preserves any state.

### Aliasing and capture timing

Access order is part of the contract. Reads occur after all preceding writes and may therefore observe changes caused by those writes.

For example, the halfword write at twice the link value precedes the destination-value read. If those regions overlap, the destination value can incorporate bytes written by that halfword operation.

Conversely, retained values are not visibly reloaded:

- The context word is captured before the receiver-byte write and both context writes.
- The link value is captured before the scaled-address halfword write.
- The destination value is captured before the two secondary-storage writes.
- The dispatch word is captured before the receiver-reference read and the final three writes.
- The receiver reference is captured before the receiver byte at offset 0x09 is written.

Later memory changes do not, by themselves, change those retained values. In particular, the indirect invocation receives the captured destination value and dispatch word, not fresh reads from their original locations.
