# F-09958d49214d

## Purpose

F-09958d49214d conditionally constructs two destination records from a selected configuration entry and three supplied 32-bit words. It resolves two adjustments, validates two selectors, delegates conversion and storage, and, for one selector ordering, compares a converted interval against a threshold. Exceeding that threshold causes both destinations to be reconstructed.

Invalid selectors cause a one-byte invalidation of one destination rather than construction. Adjustment resolution precedes validation, so invalid selectors do not prevent earlier predicate calls or lookup accesses.

Calendar-like endpoints and cycle correction are inferred intent, suggested by seven-unit corrections, packed fields, and the threshold factor 364. Calendar units, valid dates, and conventional year advancement are not established.

This contract describes static evidence only. No runtime execution or tests have been performed.

| Entry index | Signed 32-bit representation | Selects an entry using a 16-byte stride. |
| Input word A | 32 bits | Initializes the first word of a local input image. |
| Input word B | Unsigned 32 bits | Supplies packed fields and predicate inputs. |
| Input word C | Unsigned 32 bits | Initializes the last word of the temporary record. |
| First destination | 32-bit address representation | Receives delegated output or a one-byte invalidation. |

There are no explicit buffer lengths, null checks, index bounds, or error-result arguments.

### Configuration and global addresses

A global context-address variable identifies a context whose byte offset 8 contains a configuration-table address. An entry begins at that table address plus 16 times the entry index.

| Entry offset | Width | Role |
|---|---:|---|
| 3 | 8 bits | First correction reference |
| 4 | 8 bits | Second correction reference |
| 8 | 16 bits | First selector |
| 10 | 16 bits | First adjustment mode |
| 12 | 16 bits | Second selector |
| 14 | 16 bits | Second adjustment mode |

A separate global supplies an adjustment-table address. Two further globals supply a default threshold factor and a threshold multiplier.

The initial address-read sequence is significant:

1. Capture the global adjustment-table address.
2. Capture the global context address.
3. Read the global context-address variable **again**, then read that context’s table pointer and the first adjustment mode.

The first-mode lookup therefore does **not** use the captured context address. Every subsequent configuration access is rooted in the captured context address, although table pointers or entry addresses are sometimes retained across several field reads.

If the two context-address reads observe different addresses, the first mode can come from one context while its selector, the second mode, validation, and construction use the other. No consistency check reconciles them.

The adjustment-table address remains the captured address throughout adjustment resolution. Later changes to its global address variable do not redirect those lookups.

### Local storage

A local 12-byte input image contains words A, B, and C consecutively. Its address is later passed to F-b8274406a146. Subsequent reads of this image use its then-current contents; the dependency is not assumed read-only.

A separate mutable 12-byte temporary record is initialized after both selector checks pass:

| Offset | Width | Initial content |
|---|---:|---|
| 0–2 | 24 bits | Numeric field value 0x020000 |
| 3 | 8 bits | Resolved first adjustment |
| 4 | 8 bits | Low byte of the first selector |
| 5 | 8 bits | Bits 8–15 of local input word B |
| 6–7 | 16 bits | Bits 16–31 of local input word B |
| 8–11 | 32 bits | Local input word C |

This describes the supplied overlapping-field representation, not a target-independent serialization. Byte order and the exact underlying machine realization remain unresolved.

### Preconditions and ownership

Reached configuration and lookup locations must be readable. The function does not check negative indices, excessive indices, address arithmetic overflow, or lookup bounds.

Invalidation requires one writable byte at destination offset 4. Successful construction requires the destination extent expected by F-dee541b2a059; that extent is unknown.

There is no explicit allocation, release, or ownership transfer. Dependencies receive local-storage and destination addresses, but their retention, mutation, allocation, and ownership contracts are unknown. Destination aliasing is not prohibited or specially handled.

## Behavior

### 1. Resolve the first adjustment, then the second

Both adjustments initially equal zero. Each mode selects the following behavior:

| Mode | Adjustment |
|---:|---|
| 0 | 0 |
| 1 | 7 |
| 2 | 14 |
| 3 | 21 |
| 4 | 28 |
| 5 | Predicate-dependent lookup |
| Other | 0 |

The first mode is read through the additional global context-address read described above. The second mode is read through the captured context address.

For first mode 5, the high 16 bits of original input word B are explicitly installed in the corresponding half of the local input image, then supplied to F-6985300e27da. For second mode 5, the dependency receives the high 16 bits then present in that local word.

Each mode-5 result controls these reads:

- If the predicate returns zero, read the corresponding selector through the captured context.
- If that selector equals 2, read adjustment-table byte 2 and subtract one.
- Otherwise, read the corresponding selector to obtain the adjustment-table index, then read that byte.

Thus a zero predicate result and a selector other than 2 cause two selector reads, each reached through a table-pointer read from the captured context. A nonzero predicate result skips the special-case selector read but still reads the selector for indexing.

The first mode’s context source does not carry over into these selector accesses. Even its mode-5 selector comes from the captured context, not necessarily the context that supplied the mode.

Adjustment storage is eight bits. Subtraction retains the low eight bits; subtracting one from lookup byte zero yields byte pattern 255. Plain-character signedness is not independently established.

Both adjustments are resolved before validation. A selector later rejected can already have been used as an unchecked lookup index.

### 2. Validate selectors

After adjustment resolution, the function reads a table pointer through the captured context and forms the selected entry address. It checks the first selector, then the second, using that entry address.

The displayed condition subtracts one from an unsigned 16-bit selector and compares the result with 12. Under ordinary integer promotions in the displayed 32-bit environment, selector zero promotes to a signed value and produces −1 after subtraction. The displayed condition consequently accepts **0 through 12**, inclusive.

Whether the underlying machine comparison instead rejects zero remains documented_only. An intended range of 1 through 12 is not sufficient evidence to impose that behavior.

On first-selector rejection:

- Write zero to first-destination byte 4.
- Do not construct either endpoint.
- Perform no direct invalidation of the second destination.

On second-selector rejection:

- Write zero to second-destination byte 4.
- Do not construct either endpoint.
- Perform no direct invalidation of the first destination.

Neither path clears an entire record.

### 3. Construct the first endpoint

After both checks pass, initialize the temporary record. The first selector is read again from the retained entry address to initialize its selector byte.

Call F-b8274406a146 with the temporary-record address and second argument 1. Discard its return value.

Next, reread the table pointer through the captured context and obtain entry byte 3. Compare this reference with the low byte currently at temporary offset 8. That byte may have changed during conversion.

If the bytes differ, subtract the following correction from the current adjustment byte:

- Observed byte minus reference, when observed is greater.
- Seven plus observed byte minus reference, when observed is smaller.

Retain eight bits. If the bytes are equal, perform no adjustment write.

This is a single conditional addition of seven, not general modulo-seven normalization. Arbitrary reference and observed bytes are not repeatedly reduced into a seven-value domain.

Call F-b8274406a146 again with the temporary record and argument 1. Forward its result and the first destination to F-dee541b2a059, without a local success check.

### 4. Reread selector ordering

After the first output operation, reread the table pointer through the captured context. Read the second selector, then the first selector, from that entry and compare them as unsigned 16-bit values.

- Second selector at least first selector: ordinary second-endpoint path.
- Second selector below first selector: interval-comparison path.

These values need not equal those validated earlier. Dependency effects or aliased writes can change configuration, and there is no repeated validation.

### 5. Ordinary second-endpoint path

Replace the temporary selector byte with the low byte of the reread second selector. Restore the previously resolved second adjustment. Retain other temporary contents, including dependency mutations.

Then:

1. Convert the temporary record with F-b8274406a146 and argument 1; discard the result.
2. Reread the table pointer through the captured context and obtain entry byte 4.
3. Apply the correction rule from step 3 to the current offset-8 byte and adjustment.
4. Convert the temporary record again.
5. Forward that result and the second destination to F-dee541b2a059.

No interval conversion or threshold calculation follows this path.

### 6. Construct the second endpoint for interval comparison

When the second selector is below the first, install its low byte into the overlapping four-byte field at temporary offsets 4–7, preserving the other three bytes initially.

The displayed field operations then increment the upper 16-bit portion, followed by an assignment of a saved low-16-bit value to the entire four-byte field. Under the literal displayed-width interpretation, that final assignment clears the upper half and defeats the preceding increment.

A conventional year or cycle advance is therefore not established. The ordering and overlapping widths must not be replaced with inferred calendar behavior.

Restore the second adjustment. Perform the same two conversions, correction against entry byte 4, and delegated second-destination output described for the ordinary path.

Both destinations have now received output calls.

### 7. Convert the interval and calculate the threshold

The following dependency calls occur in order:

1. F-b8274406a146 receives the second destination and argument 1.
2. F-b8274406a146 receives the local input image and argument 1.
3. F-6985300e27da receives the current high 16 bits of local input word B, widened and incremented by one.

The input-image conversion may mutate word B before the predicate argument is extracted. That argument is not necessarily derived from the original supplied word.

Extraction yields 0 through 65535. The addition occurs at a width greater than 16 bits, producing 1 through 65536, not a wrapped 16-bit result.

After the predicate returns:

1. Read the global default factor unconditionally.
2. If the predicate returned zero, replace the loaded factor with 364.
3. Read the global threshold multiplier for the calculation.

The default-factor read remains part of the sequence even when its value is discarded. Both threshold-global reads occur after the predicate call.

The threshold is the multiplier times the selected factor times 128, using the displayed 32-bit arithmetic. The converted second-destination result minus the converted input-image result is compared against that threshold as an unsigned 32-bit value.

There is no overflow check. A mathematically negative difference is not automatically treated as a short interval. Portable signed-overflow semantics are not established by this representation.

If the unsigned difference is at most the unsigned threshold, return without further output calls.

### 8. Reconstruct both outputs when the threshold is exceeded

Reduce the temporary upper 16-bit field by two, retaining 16 bits. Reread the first selector through the captured context, install its low byte, and restore the resolved first adjustment.

Repeat first-endpoint conversion, correction against a newly read entry byte 3, conversion, and first-destination output.

Next, restore the second adjustment and reread the second selector through the captured context. Install its low byte. The overlapping four-byte field is then truncated through its low 16 bits before its upper half is incremented.

Under the literal displayed-width interpretation, this truncation clears the upper half, so the subsequent increment produces upper-half value 1. Later dependency mutations are not constrained to preserve it.

Repeat second-endpoint conversion, correction against a newly read entry byte 4, conversion, and second-destination output. Do not perform another threshold comparison.

## Side effects

Established direct effects are:

- Global-address, context, configuration, lookup, and threshold reads.
- Local input-image and temporary-record initialization and mutation.
- One destination-byte write on a rejection path.
- Dependency calls that may mutate supplied storage or other accessible state.

Delegated output occurs once per destination on the ordinary path and on the interval path that does not reconstruct. Threshold excess causes a second output call for each destination.

The context-address global is read twice initially: once to capture an address, then again for the first-mode lookup. Subsequent configuration operations use the captured address. Replacing the global afterward does not itself redirect those operations, but changing the table pointer within the captured context can affect later table-pointer reads.

Some entry addresses are retained across multiple accesses; the function does not reread the table pointer for every individual field.

No rollback is present. Dependency failure or invalid memory access after an output operation can leave partially updated destinations. Return values are discarded, forwarded, or used arithmetically without local failure handling.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless specified otherwise, dependencies return normally and leave configuration unchanged.

1. **Distinct initial contexts.** Suppose the captured context contains first mode 1 and first selector 3, while the subsequent global context-address read identifies a context containing first mode 5. The function selects mode 5, not mode 1. Its mode-5 selector lookup nevertheless uses selector 3 from the captured context.

2. **Later context-global replacement.** After the first-mode lookup, replacing only the global context address does not redirect the second-mode read or validation. Those accesses remain rooted in the captured context.

3. **First rejection.** First selector 13 causes a zero write at first-destination offset 4 after adjustment resolution. No endpoint conversion occurs.

4. **Second rejection.** First selector 4 and second selector 13 cause a zero write at second-destination offset 4. The first endpoint is not constructed.

5. **Zero boundary.** Under ordinary displayed integer promotions, selector zero passes validation. Machine-level rejection of zero requires additional evidence.

6. **Mode-5 special case.** With selector 2 and lookup byte 2 equal to 10, a zero predicate result produces adjustment 9; a nonzero result produces 10.

7. **Seven-unit correction.** Adjustment 14, observed byte 1, and reference 5 produce correction 3 and adjustment 11.

8. **No general normalization.** Adjustment zero, observed byte 10, and reference 1 produce correction 9 and stored adjustment byte 247.

9. **Ordinary ordering.** If the reread second selector is at least the first, there are four temporary-record conversion calls and two output calls. Interval conversion and the threshold predicate are not reached.

10. **Threshold equality and excess.** Equality returns without reconstruction. A greater unsigned difference causes another output call for each destination, with no second threshold comparison.

11. **Maximum predicate input.** If local word B has high half 65535 after input-image conversion, the threshold predicate receives 65536.

12. **Mutated input image.** If that conversion changes the high half from 65535 to 7, the threshold predicate receives 8.

13. **Zero-result read order.** A zero threshold-predicate result still causes the default-factor global to be read before the multiplier global. The arithmetic uses factor 364.

## Uncertainties

The following remain documented_only:

- Calendar meanings, conversion units, valid correction-byte domains, and intended cycle behavior.
- Whether the underlying machine comparison accepts selector zero.
- Target-independent byte order and plain-character signedness.
- Exact machine semantics behind the overlapping packed-field assignments.
- Dependency mutation, retention, ownership, failure, and preservation contracts.
- Destination extents, aliasing guarantees, and consequences of overlapping storage.
- Reachable threshold-global ranges and overflow behavior beyond the displayed arithmetic.
- Runtime consequences of invalid addresses, unchecked indices, and dependency failures.
- Whether any execution environment permits the two initial context-address reads to observe different values.

These unknowns do not justify merging the two context-address reads, assuming immutable input storage, omitting the unconditional default-factor read, or substituting conventional calendar operations.
