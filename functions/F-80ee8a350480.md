# F-80ee8a350480

## Purpose

F-80ee8a350480 performs a sequence of indirect calls, calculated-address memory accesses, a coprocessor-directed operation, and potentially unbounded loop processing. The supplied representation contains two paths to a shared 64-bit return construction and another path that terminates at an explicit invalid instruction.

No application-level purpose is established. In particular, the evidence does not identify a protocol, allocator, collection, or device interface. Some calculated addresses are very small, wrapped, or unaligned; ordinary hosted-memory validity cannot be assumed.

This contract describes the behavior established by the supplied static representation, conditional on its control-flow and operand interpretation being accurate. The representation reports invalid instruction data and overlapping global storage, which limit confidence in executable behavior.

A normal return consists of two independently constructed 32-bit halves:

- **Low half:** a selected word shifted left by one, retaining only 32 bits.
- **High half:** an image-resident word minus 84, retaining only 32 bits.

The low-half shift does not carry into the high half.

No error-code convention is established. Possible non-returning outcomes include the represented invalid-instruction termination, memory faults, coprocessor exceptions, failure of an indirect callee to return, and infinite loop execution.

## Behavior

### Entry sequence

The routine first makes two indirect calls. The first target is calculated from the inherited link value. The second and subsequent early targets use fixed image-relative calculations.

After the second call, it multiplies the inherited base value by \(2^{20}\), retaining 32 bits. It records whether this **scaled value** is zero. Later calls do not cause that predicate to be recomputed.

The following sequence then occurs:

1. Make a third indirect call.
2. Read an image-resident word that will serve as a lookup base.
3. Make a fourth indirect call.
4. Store the fourth argument as a 32-bit word at the second argument arithmetically shifted right by 31, plus 100.
5. Make a fifth indirect call.
6. Store that call’s represented secondary result word at the inherited base value plus 36.
7. Make a sixth indirect call.
8. Store the fourth argument as a 32-bit word at the second argument arithmetically shifted right by 26, plus 20.
9. Make a seventh indirect call.
10. Store the inherited base value as a 32-bit word at the scaled value plus 4.
11. Make an eighth indirect call and retain its represented 64-bit result.

The first argument-derived store targets address 100 when the second argument is nonnegative and address 99 when it is negative.

For the second store, the shifted argument ranges from −32 through 31. Adding 20 gives a signed address expression ranging from −12 through 51; negative values become wrapped addresses under the 32-bit interpretation. Alignment and accessibility are not established.

### Nonzero-scaled-value termination

When the saved scaled value is nonzero:

1. Add the high word of the eighth call’s result to the previously read lookup base.
2. Read a character byte at that address.
3. Extend the represented signed character value to 16 bits.
4. Store that halfword at the low word of the eighth call’s result plus 60.
5. Reach the explicit invalid-instruction termination.

There is no represented normal return on this path.

The predicate is not a test of the original base value for zero. Multiplication by \(2^{20}\), truncated to 32 bits, produces zero whenever the original base value’s low 12 bits are zero.

### Zero-scaled-value continuation

When the scaled value is zero, another indirect call supplies an address-like word. The routine then:

1. Reads an unsigned byte at the second argument arithmetically shifted right by 26, plus 1.
2. Uses that byte’s numeric value directly as an address.
3. Reads a 32-bit word at the preceding call’s result plus 100; this becomes the **working base**.
4. Performs a coprocessor-directed operation with represented fixed selectors 3, 3, and 2, the working base, and the two inherited coprocessor operands.
5. Reads a word at the working base plus 20.
6. Makes an indirect call with the earlier address-like result and the loaded word.
7. Stores the low byte of the inherited base value at the byte-derived address plus the working base.
8. Writes four consecutive words beginning at the byte-derived address:
   - The latest call result.
   - The byte-derived address itself.
   - The scaled value, which is zero on this path.
   - The inherited base value.

The byte-derived address ranges from 0 through 255. It is not a word index and is not multiplied by four before use.

The byte store precedes all four word stores. Overlapping ranges are not checked; a later word store can overwrite that byte.

### Initial loop selection

Call the latest word-sized result the **initial working word**.

Before making the next call, the routine arithmetically shifts this word right by 9 and compares the shifted result, interpreted as unsigned, against `0xFFFFFFBE`. The predicate is true when that unsigned result is strictly greater than the constant.

It then makes an indirect call with three represented arguments:

- The initial working word.
- Its arithmetic right shift by 9, plus 65.
- The fourth argument minus 60, followed by an arithmetic right shift by 20.

The subtraction uses the 32-bit arithmetic model. The call occurs regardless of the predicate.

The predicate is true exactly when the signed shifted value is from −65 through −1. Equivalently, the signed initial working word lies from −33,280 through −1.

After the call:

- A false predicate enters the shared loop tail directly.
- A true predicate first stores the low 16 bits of the working base at the call’s low result word plus 42.

After that halfword store, the routine compares two Boolean conditions:

- Whether the working base is negative.
- Whether subtracting 47 from the call’s high result word has signed 32-bit overflow.

Equal conditions enter the shared tail. Unequal conditions enter the body first. This is not an ordinary signed comparison between the working base and either result word.

For direct body entry, the state is initialized as follows:

- **Difference:** inherited difference operand minus working base.
- **Unsigned working value:** low result word logically shifted right by 25.
- **Cursor:** high result word.

### Loop body and immediate return

Each body execution first makes an indirect call with the unsigned working value, cursor, and an address into the routine’s stack frame. A second indirect call follows and supplies a represented 64-bit result.

The routine then:

1. Calculates the cursor plus 10.
2. Stores the current difference as a word at the old cursor plus 62.
3. Multiplies the incremented cursor by \(2^{16}\), retaining 32 bits.
4. Tests whether that product is negative.

If the product is negative, the routine returns through the shared return construction. The low return half is the second call’s low result word shifted left by one.

The cursor-relative store occurs before this return decision. Its offset of 62 does not guarantee word alignment.

### Continuing body processing

If the product is nonnegative, the body continues:

1. Store the low 16 bits of the latest call’s low result word at its high result word plus 60.
2. Make two more indirect calls.
3. Store the halfword value 38 at the second of those calls’ result plus 2.
4. Multiply the incremented cursor by \(2^{28}\), retain 32 bits, and arithmetically shift that result right by 9.
5. Add this shifted intermediate to the incremented cursor.
6. Read an image-resident word for use as an XOR operand.
7. Make an indirect call with:
   - The preceding address-like call result shifted left by one.
   - The incremented cursor multiplied by \(2^{16}\), minus 81.
8. XOR the calculated sum with the previously read image word, producing a **derived address**.
9. Add 47 to the shifted intermediate.
10. Save the derived address in a represented stack slot.
11. Read one byte at the derived address plus 1.
12. Make an indirect call with a fixed image address, that byte, the shifted intermediate plus 47, and a secondary result word from the preceding call.
13. Store the shifted intermediate plus 47 as a word at the derived address plus 36.
14. Make another indirect call.
15. Construct the shared-tail input from:
   - Low word: the derived address.
   - High word: the latest secondary result word plus 48.

The XOR operand is read before the intervening call, not after it. The later byte read occurs before the word store at the derived address plus 36.

No string, table, or callback meaning is established for the fixed image address passed as an argument.

### Shared loop tail

The shared tail accepts a 64-bit value from either the initial selection call or the continuing body.

It derives:

- An unsigned working value from the low input word shifted left by one.
- A difference equal to four times the square of the high input word, retaining 32 bits.

It then makes three indirect calls in order:

1. A call with the low input word plus the inherited address offset.
2. A call with an image-resident word read for that argument.
3. A call with no reconstructed explicit arguments.

**Only after all three calls does the routine read and compare the image-resident flag with zero.** The flag’s storage width and access width are not established.

If the flag compares equal to zero:

- The subsequent high-word-derived store is skipped.
- The third call’s secondary result word is arithmetically shifted right by 9.
- That shifted value is selected for the shared return construction, which shifts it left by one for the low return half.

If the flag compares nonzero:

1. Store the calculated difference as a word at twice the high input word plus 52.
2. Set the next cursor to the third call’s secondary result word.
3. Execute the loop body again, retaining the working value and difference calculated by this tail.

There is no represented iteration bound, timeout, or progress guarantee. Indirect target calculations depend on the path and retained target-calculation state; identical callees across different tail entries must not be assumed.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Each assumes that preceding calls return and reached accesses and operations are permitted.

1. **Negative second argument.**  
   The first argument-derived word store targets address 99 and writes the fourth argument’s full 32-bit pattern. Address 100 would be incorrect for this case.

2. **Zero second argument.**  
   The two argument-derived word stores target addresses 100 and 20. On the zero-scaled continuation, the unsigned byte used directly as an address is read from address 1.

3. **Nonzero base with zero scaled value.**  
   An inherited base value of `0x00001000` produces a zero scaled value. The routine follows the zero-scaled continuation rather than selecting invalid-instruction termination solely because the original base is nonzero.

4. **Character extension on the terminating path.**  
   Under the represented signed-character interpretation, a lookup byte of `0x80` becomes halfword `0xFF80`. That halfword is stored before invalid-instruction termination.

5. **Initial selection boundary.**  
   An initial working word of −33,280 satisfies the predicate. A value of −33,281 does not. Zero does not. The selection call still occurs in every case.

6. **Immediate body return still writes.**  
   With cursor 32,758, incrementing by 10 produces 32,768. Multiplication by \(2^{16}\) yields `0x80000000`, selecting the immediate return. The difference is first stored at address 32,820, the old cursor plus 62.

7. **Flag checked after calls, without a width assumption.**  
   If the image-resident flag compares equal to zero when read after the three tail calls, the high-word-derived store is skipped and the return uses the third call’s secondary result word. Acceptance does not require this flag to occupy one byte.

8. **Nonzero flag repeats processing.**  
   If that comparison is nonzero, the routine stores four times the square of the high tail-input word, modulo \(2^{32}\), at twice that word plus 52. The third call’s secondary result becomes the next cursor.

9. **Independent return halves.**  
   On the immediate body-return path, a selected low word of `0x80000001` produces low return half `0x00000002`. The shifted-out bit does not alter the independently calculated high half.
