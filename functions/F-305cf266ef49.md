# F-305cf266ef49

## Purpose

F-305cf266ef49 scans an input region using a caller-supplied mutable parsing state. It recognizes slash-prefixed candidates, searches up to 19 descriptor positions, and dispatches the first matching descriptor. A separate marker-recognition path searches ahead and conditionally restores the cursor.

The established contract concerns address arithmetic, state accesses, dependency calls, descriptor selection, and status propagation. Interpreting the markers as directory-related syntax or the callbacks as token parsers is inferred intent, not an independently established guarantee.

The function returns the parsing state's current 32-bit status. Reaching the retained input boundary does not itself assign an error.

## Interface

### Arguments and widths

The interface has four 32-bit arguments:

| Argument | Role |
|---|---|
| Context address | Passed to descriptor-specific handlers; used to form context-relative destination addresses. |
| Parsing-state address | Identifies mutable cursor, boundary, status, and callback fields. |
| Input start address | Written as the initial state cursor. |
| Input extent | Added to the input start to form the retained boundary. |

Addresses and stored words follow the recovered 32-bit model. Address additions and cursor differences must not be interpreted as unbounded mathematical arithmetic. Safe behavior for wrapping addresses or negative extents is not established.

### Parsing-state layout

Offsets are in bytes from the state address.

| Offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Current cursor |
| 8 | 32 bits | Published boundary |
| 12 | 32 bits | Status |
| 28 | 32 bits | One-argument preparation callback address |
| 32 | 32 bits | One-argument advance callback address |
| 56 | 32 bits | Callback receiving state and temporary-output addresses |
| 64 | 32 bits | General five-argument descriptor callback address |
| 68 | 32 bits | Alternative five-argument descriptor callback address |

“Preparation” and “advance” describe invocation placement. Their actual parsing and cursor-progress guarantees are unknown. Each receives the state address; the other invocation shapes are specified below.

### Descriptor data

A readable global contains a 32-bit descriptor-table base address. The function examines indices 0 through 18, using a 28-byte stride.

This is not a snapshot of one immutable table. The global base is reread for every examined index. Changes made by comparison dependencies can therefore redirect subsequent iterations.

Within each retained entry, these fields are used:

| Offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Referenced name address |
| 4 | 8 bits | Destination selector |
| 5 | 8 bits | Dispatch selector |
| 8 | 32 bits | Descriptor-specific handler address |

Other descriptor bytes are not interpreted directly by this function, although a general callback receives the entire descriptor address.

### Return and preconditions

The return value is a fresh read of state offset 12 at exit. There is no separate result object or consumed-byte count.

Required conditions for useful execution include accessible state fields, readable input wherever direct reads occur, valid invoked callback addresses, and valid memory for descriptor and name accesses. Context-relative addresses must be usable by whichever dependencies consume them.

The function does not validate extent sign, address overflow, callback progress, cursor confinement, or memory overlap. State, input, and context are not required by the visible implementation to be disjoint. Termination depends partly on callback behavior.

## Behavior

### Initialization and retained values

The initial non-stack writes occur in this order:

1. Write the input start to the state cursor.
2. Clear the state status to zero.
3. Write input start plus extent to the published boundary.
4. Invoke the preparation callback.

The boundary is also retained independently of the published field. Later modifications to state offset 8 do not replace it.

The original context address is retained, and context plus 132 is computed after the initial preparation callback for later descriptor dispatch. This is address calculation, not a context-memory read.

Each outer iteration reloads the state cursor and compares it with the retained boundary. A cursor equal to or beyond that boundary ends scanning and returns the current status. The direct current-byte read occurs only after this comparison permits the iteration.

The recovered pointer comparisons establish strict boundary tests. Their complete machine-level interpretation for unusual address orderings is not established; the examples below assume ordinary increasing, nonwrapping addresses.

### First-marker path and repeated input reads

The function first reads the byte at the retained iteration cursor and tests for uppercase `F`.

If that byte is `F` but the boundary is not strictly beyond cursor plus 25, the function takes ordinary advancement directly. It does not attempt the first marker comparison or the slash-recognition path.

With more than 25 bytes remaining, it invokes F-fca51b715561 for a 13-byte comparison against a referenced marker. Zero selects the special marker path.

A nonzero result does **not** establish that ordinary advancement follows. Instead, the function rereads the byte at the same retained cursor address for the slash test. F-fca51b715561 may have modified that byte, the parsing state, or other memory. If the reread byte is now `/` and the slash boundary condition holds, slash recognition proceeds.

The slash test uses the retained cursor, not a cursor freshly loaded after this dependency. A dependency's change to state offset 0 does not change the address used by that test.

When the first outer byte was not `F`, the slash test likewise performs a subsequent byte read. No general input-preservation guarantee is established.

### Successful first-marker handling

After a zero result from the 13-byte comparison:

1. Invoke the advance callback.
2. Invoke the preparation callback.
3. Read the state cursor and retain it as the restoration position.
4. Search for the second marker using that cursor.

There is no status check between these first two calls or immediately after preparation.

A search position qualifies as the second marker only if:

- It is below the retained boundary.
- Its byte is lowercase `k`.
- The boundary is strictly beyond that position plus 5.
- F-fca51b715561 returns zero for a five-byte comparison against the second referenced marker.

Exactly five bytes remaining is insufficient.

When no match is found at a position below the boundary, the function invokes the advance callback and reads status. A nonzero status exits the entire function immediately, without restoring the saved cursor. Otherwise it invokes preparation, reloads the cursor, and continues searching.

A marker-comparison dependency may change the state cursor. The current comparison decision nevertheless uses the retained search position. After a failed comparison, the advance callback is still invoked; after a successful comparison, the matched-marker path is selected without revalidating a newly loaded cursor.

If a second marker is found:

1. Invoke the advance callback.
2. Invoke the callback at state offset 56 with the state address and a temporary-output address.
3. Inspect the low eight bits of a neighboring 32-bit temporary.
4. If those bits equal 3, replace the restoration position with the current state cursor.

The output address identifies an eight-byte scratch area in the recovered stack layout. The inspected 32-bit temporary is adjacent to that area and is also used elsewhere for descriptor destination storage. The visible function does not initialize it specifically before this callback. The dependency's output layout and responsibility for establishing the inspected value remain unresolved.

After either reaching the search boundary without a match or completing the matched-marker path, the function writes the restoration position to the state cursor. Thus, absent the value-3 decision, the search is undone at the cursor level. Other side effects are not undone.

Preparation then runs before the next outer boundary check. No direct status check occurs after the matched-marker advance, the offset-56 callback, or this restoration.

### Slash-prefixed candidate extraction

Slash recognition requires a reread byte equal to `/` and cursor plus 2 strictly below the retained boundary. Under nonwrapping arithmetic, at least three bytes must remain.

The function writes cursor plus 1 to state offset 0 and retains that address as the candidate start. It then invokes the advance callback and checks status. Nonzero status exits without trailing preparation.

Otherwise, the candidate length is the 32-bit difference between the post-callback state cursor and the retained candidate start. Lookup requires both:

- The unsigned 32-bit value obtained by subtracting one from the length is less than 21.
- The post-callback cursor is strictly below the retained boundary.

For ordinary forward movement, eligible lengths are 1 through 21 inclusive. Zero and ordinary backward differences fail. This arithmetic filter does not independently prove that the candidate occupies a valid readable slice.

An ineligible candidate causes no direct status assignment. Preparation runs before the next outer iteration.

### Descriptor lookup and observable read timing

For each index, in increasing order, the function:

1. Reads the descriptor-table global's current base value.
2. Computes and retains the entry address using that base plus index times 28.
3. Reads and retains the entry's name pointer.
4. Skips a null name pointer.
5. Reads the candidate's first byte and the retained name's first byte.
6. If they agree, invokes F-1cb585febd84 on the retained name pointer.
7. If that result equals the retained candidate length, invokes F-7f14f1ab6851 with candidate start, retained name pointer, and length.
8. Accepts zero from F-7f14f1ab6851 as a match.

The entry address and name pointer remain retained across these dependency calls. Changing the global base does not redirect the current entry. Changing the entry's name-pointer field does not replace the pointer already selected for the current comparison.

The pointed-to bytes are not snapshotted. Dependencies may mutate them. Candidate length and start are retained, and the function does not recheck state status, cursor, or boundary eligibility after these comparison calls.

If an iteration does not match, the next iteration rereads the global. Consequently, earlier comparison calls can redirect later indices to another table base. The candidate's first byte is also read again for each nonnull entry.

The first matching entry is dispatched; later indices are not visited. No match directly assigns an error. Status changes made by comparison dependencies are not immediately checked on the no-match path.

### Descriptor dispatch

Dispatch fields are read from the retained entry **after** matching dependencies return. They are not captured alongside the name pointer. A matching dependency can therefore change which dispatch behavior is selected without changing the retained entry address.

If descriptor byte 5 equals 10:

- Read the handler address at entry offset 8.
- Invoke it with the original context address and state address.
- Read status from the state.
- Write that same value back to the status field.

The handler's return value is ignored.

For other dispatch-selector values, initialize a 32-bit temporary to context plus 132. Read descriptor byte 4; if it is not 2, read that byte again and select context plus 456 only when the second read equals 4. With stable descriptor memory, only value 4 selects the latter destination.

The function then rereads descriptor byte 5 to select the general callback. Value 8 selects state offset 68. If that comparison fails, another read tests for 9, which also selects offset 68. Otherwise state offset 64 is selected.

The selected callback receives, in order:

1. State address.
2. Retained descriptor address.
3. Address of the destination temporary.
4. Zero.
5. Zero.

Its 32-bit return value is written to status, superseding any status value it left in the state. Changes to the destination temporary are not subsequently consumed on this dispatch path.

After either dispatch form, nonzero status ends scanning without trailing preparation. Zero permits preparation and another outer iteration.

### Ordinary advancement and termination

Ordinary advancement invokes the advance callback, reads status, and exits on nonzero. Otherwise it invokes preparation and repeats.

Status handling is path-dependent. Preparation-produced status is not checked immediately; nor are all marker-path callback results. A nonzero status therefore does not universally prevent subsequent calls or processing.

There is no iteration limit or enforced forward progress. Boundary termination returns whichever status exists at exit.

## Side effects

Explicit non-stack stores are addressed through the parsing-state pointer:

- Initial cursor, status, and published boundary writes.
- Cursor movement past a slash.
- Cursor restoration or selection after marker handling.
- Status assignment after descriptor dispatch.

There are no stores explicitly addressed through the input or context pointers. This does **not** imply those regions remain unchanged: state writes can modify overlapping input or context storage. Aliasing can also affect subsequent reads and execution.

The function uses temporary stack storage for callback arguments and decisions. No direct allocation or release operation is visible.

Dependency effects remain unconstrained by this function's body. Dependencies may modify input, context, state, descriptor data, the descriptor-table global, or other global state; allocation and release behavior are unknown.

Callback addresses are read from state when their calls are selected. Earlier dependencies are not assumed to preserve them.

Temporary addresses have invocation-local lifetimes. The visible calls establish neither ownership transfer nor permission to retain those addresses. Input and context ownership likewise cannot be inferred from the absence of direct allocation or release.

## Acceptance examples

These are conditional criteria, not executed tests. Address examples assume accessible, nonwrapping memory.

1. **Empty input:** With zero extent, initialization still invokes preparation. If preparation leaves cursor at the start and status zero, no input byte is read and the result is zero.

2. **Preparation status:** If initial preparation places the cursor at the boundary and sets nonzero status, that status is returned without advancement.

3. **Short uppercase candidate:** With `F` and exactly 25 bytes remaining, the 13-byte comparison is not called. Ordinary advancement occurs directly.

4. **Comparison mutates `F` to slash:** With more than 25 bytes remaining, suppose the first comparison returns nonzero after replacing the retained cursor's byte with `/`. The subsequent reread selects slash extraction if its boundary condition holds, even if the dependency also changed the state cursor.

5. **Second-marker boundary:** A search position containing `k` with exactly five bytes remaining is not compared as the second marker. Search advancement occurs.

6. **Slash boundary:** With only two bytes remaining, a slash does not cause the explicit one-byte cursor write. Ordinary advancement applies.

7. **Candidate limits:** A 21-byte forward candidate ending below the boundary is eligible; a 22-byte candidate is not. A candidate ending exactly at the boundary is ineligible regardless of otherwise valid length.

8. **Global redirection:** Suppose index 0 reaches a comparison dependency that changes the table-base global and then fails to match. Index 1 is computed from the new base plus 28, not from the old base.

9. **Retained current entry:** If a matching comparison changes the global base and the current entry's name-pointer field, dispatch still uses the retained entry. Any modified dispatch fields in that retained entry are read afterward.

10. **First match:** Once an entry matches, no later index is examined, even if another entry could match.

11. **General return overrides state:** If the general callback writes one status but returns a different 32-bit value, the return value becomes the stored status. A nonzero return prevents trailing preparation.

12. **Handler return ignored:** For selector 10, a nonzero handler return with state status left zero does not itself stop scanning.

13. **Search error:** A nonzero status observed after an advance inside the marker-search loop returns immediately without cursor restoration.

14. **Restoration and aliasing:** A completed unsuccessful search restores the saved cursor before preparation. If the state overlaps input or context, that cursor store may also modify bytes in the overlapping region; no disjointness guarantee prevents this.
