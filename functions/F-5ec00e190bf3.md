## Behavior

### Selection rules

The selector is read from word 0 before any direct record write.

Selection has the following priority:

1. If the selector equals the selector threshold, take the **threshold-equality path**.
2. Otherwise, if the selector is signed-less-than the threshold:
   - Selector 1 takes the **selector-1 path**.
   - Selector 49164, hexadecimal 0xC00C, takes the **selector-49164 path**.
   - Every other selector takes the **fallback path**.
3. Otherwise:
   - Selector 49168, hexadecimal 0xC010, takes the **selector-49168 path**.
   - Selector 49171, hexadecimal 0xC013, takes the **selector-49171 path**.
   - Every other selector takes the **fallback path**.

The equality test has precedence over every literal-selector case. Literal selectors are also constrained by which side of the threshold they occupy.

Consequently, this is not an unconditional mapping from the listed literal selectors to fixed configurations. For example, selector 49164 reaches its dedicated path only when it is less than the threshold. If it equals the threshold, it takes the threshold-equality path; if greater, it reaches fallback.

The represented comparisons are signed integer comparisons. Under the 32-bit model, a selector with its high bit set is negative, not a large positive selector.
