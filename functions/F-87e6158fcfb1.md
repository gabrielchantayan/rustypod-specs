# F-87e6158fcfb1

## Purpose

F-87e6158fcfb1 is a globally dispatched coordinator that manipulates opaque caller values, a handle-like value, a private byte buffer, status values, and shared flags. It returns an unsigned 32-bit value.

The supplied static representation establishes the effects of individual operations and their local ordering. It does not establish a complete entry-to-return sequence: the initial selection, subsequent destinations, and arithmetic branch predicates depend on unavailable global contents.

This contract distinguishes:

- **Established behavior:** explicit accesses, assignments, argument positions, widths, and ordering.
- **Inferred intent:** acquisition, notification, checking, and finalization suggested by the call structure.
- **documented_only:** unresolved reachability, dependency semantics, ownership, and arithmetic details requiring unavailable declarations or global values.

The function is not established to be a linear initialization-and-cleanup routine.

### Status representations and retention

For signed 16-bit results used by the normalization operations:

**Normalized status = low eight bits of 241 × the signed 16-bit result.**

Selected calls receive:

**Forwarded status = low eight bits of 17 × the stored status.**

Because `241 × 17` is congruent to `1` modulo 256, forwarding an unchanged normalized status recovers the original result’s low byte, not its full signed value.

The multiplication of a signed 16-bit result by 241 fits within signed 32-bit range. Masking produces a value from 0 through 255.

The normalization applies to results from F-c8e906e0b5f9, F-46b69b47db18, F-e36585d2c2a6, F-573b63bda7bf, and F-2c51ee1664c7. ## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Status round trip.** A normalized signed 16-bit result of `1` produces status `241`; forwarding that unchanged status produces `1`.

2. **Negative result.** A result of `−1` normalizes to `15` and forwards to `255`. No error interpretation follows.

3. **Upper-byte loss.** Results `1` and `257` both normalize to `241`. Normalization alone cannot distinguish them.

4. **Explicit status retention.** If current status is `241` and the status-retention operation is selected, the retained status argument becomes `241`. A subsequent forwarding call receives `1`; a subsequent F-03fb3a9079f5 call receives retained value `241` directly.
