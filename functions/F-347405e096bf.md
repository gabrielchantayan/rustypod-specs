# F-347405e096bf

## Purpose

F-347405e096bf conditionally transforms a mutable object containing a signed header and an address of 32-bit words. A second, 32-bit argument selects the direction and extent of the transformation through its signed interpretation.

The operations resemble rightward magnitude shifting for positive displacements and leftward magnitude shifting for negative displacements. This numeric interpretation is inferred, not an established representation guarantee: global multipliers control header and word interpretation, and their values are unavailable.

The residual-bit distinction is exact:

- A displacement magnitude divisible by 32 selects whole-word copying.
- A residual magnitude from **1 through 31** selects bit-combination processing.

Residual one is therefore not a whole-word-copy case.

The Boolean result is not a general success indicator. `true` denotes a visible rejection path. `false` includes zero-displacement no-op, completed processing, and an admitted positive input for which a dependency prevents subsequent direct transformation.

All behavior below is based on static evidence. No runtime tests have been performed.

## Interface

The function receives a mutable descriptor address and a 32-bit unsigned displacement bit pattern. The latter is also interpreted as a signed 32-bit value.

The visible descriptor layout is:

| Byte offset | Width | Meaning established by accesses |
|---|---:|---|
| 0 | 32 bits | Signed header used in count and sign calculations |

Array elements are 32 bits wide, with four-byte spacing. Index zero is the low-order end under the inferred numeric interpretation.

The address-bearing field is 32 bits. The evidence does not establish an equivalent descriptor layout using wider native pointers.

### Result

The function returns a Boolean. It may modify the header and referenced array, but does not directly return a new descriptor or array address.

There is no visible capacity parameter, error object, allocation result, or exception-handling protocol.

### Global roles

Distinct global roles are described without assuming their values or inverse relationships:

- Positive and negative header decoders.
- Positive and negative word decoders.
- Positive and negative word encoders.
- Positive and negative header encoders.

Entry-time decoder snapshots must be distinguished from later reads of the corresponding globals. Dependencies are not established to preserve any global.

### Preconditions and arithmetic limits

Every accessed descriptor field and array location must be accessible with the required read or write permission. No null or capacity validation is visible.

For the ordinary count interpretation, the admission-time signed header-decoder product and its absolute value must be representable as signed 32-bit integers. The admitted ordinary absolute count is at most 28.

Other signed products, including later header calculations and word-decoder products, also require representability before their results can be treated as established signed arithmetic. A later conversion to unsigned does not resolve overflow in an earlier signed multiplication.

The positive bit-combination path has an additional restriction: its next-word contribution is a **signed 32-bit left shift**, not an unsigned left shift. For a fully specified arithmetic result, the decoded next word must be nonnegative and remain within the signed 32-bit range after shifting. Otherwise, the supplied representation does not establish the result.

These are conditions for interpreting the operation, not checks performed by the function.

## Behavior

### Entry and dispatch

The function first reads the negative header decoder, then the positive header decoder, retaining entry-time snapshots.

If the displacement bit pattern is zero, it returns `false` after those reads. No descriptor access or dependency call occurs on that path.

Otherwise:

- Signed-positive displacement selects positive processing.
- Signed-negative displacement selects negative processing.

For an admitted displacement magnitude, let:

- \(q\) be its whole-word displacement, obtained by division by 32.
- \(r\) be its residual bit count, in the range 0–31.
- \(n\) be the absolute header count computed before the dependency call.

The count used to control the transformation is not recomputed after a dependency returns.

### Positive admission and dependency

The function rereads the positive header decoder, multiplies it by the current signed header, and forms the absolute count.

If the ordinary absolute count exceeds 28, it returns `true` without calling F-18cbf7a56e3c or making a direct descriptor or array write.

Otherwise it calls F-18cbf7a56e3c with the descriptor. After the call, it reads these globals in order:

1. Positive word decoder.
2. Positive word encoder.
3. Positive header encoder.

Those reads occur even if the dependency returned nonzero.

A nonzero dependency result causes a `false` return without subsequent direct descriptor or array writes. Dependency effects are not excluded.

A zero dependency result permits transformation using the previously computed count and the post-call descriptor.

### Positive complete removal

If \(q \ge n\), the function writes zero to the header and returns `false`.

No direct array write occurs. Backing words are not cleared.

This includes an ordinary zero-count positive input whose dependency returns zero: the dependency is called before the zero header is stored.

### Positive whole-word processing: residual zero

When \(q<n\) and \(r=0\), the function first updates the header:

- It reads the current header and multiplies it by the entry-time positive header decoder.
- If that decoded value is nonnegative, it subtracts \(q\).
- If it is negative, it adds \(q\).
- It multiplies the result by a fresh read of the positive header encoder and stores the header.

This is not necessarily a recomputation from \(n\): the dependency may have changed the header or decoder globals.

The function then copies \(n-q\) full words toward index zero, in increasing destination-index order. Destination index \(j\) receives the word at index \(j+q\).

The copies preserve word bit patterns; they do not apply the word decoder or encoder. Words outside the copied destination range are left uncleared.

The header write precedes all these array writes.

### Positive bit-combination processing: residual one through 31

When \(q<n\) and \(1\le r\le31\), let \(m=n-q\).

The function writes destination indices zero through \(m-2\) in increasing order. Each output combines:

- The decoded word at source index \(j+q\), converted to an unsigned 32-bit value and logically shifted right by \(r\).
- The decoded word at source index \(j+q+1\), left-shifted by \(32-r\), then combined by bitwise OR.

The combined value is multiplied by the captured positive word encoder and stored as a 32-bit word.

The two contributions have materially different arithmetic status:

- Both decoder multiplications are signed 32-bit expressions and have unresolved behavior if they overflow.
- The lower contribution is converted to unsigned before its right shift.
- The next-word contribution is **not converted to unsigned before its left shift**. Negative operands and results outside the signed range are not covered by an established wrapping rule.

A sufficient restriction for that next-word shift is:

\[
0\le \text{decoded next word}\le
\left\lfloor\frac{2^{31}-1}{2^{32-r}}\right\rfloor.
\]

For \(r=1\), this restriction permits only zero as the decoded next word. The function does not enforce it.

The final destination, at index \(m-1\), uses only the decoded last source word’s unsigned logical right shift. It is multiplied by the captured word encoder and written.

The function then multiplies that final encoded output by the captured word decoder. If the product is zero, the resulting count is reduced from \(m\) to \(m-1\). This is a single high-word check, not repeated normalization. The signed multiplication used for this check has its own representability requirement.

After the array writes, the function reads the current header and multiplies it by the entry-time positive header decoder:

- A positive result selects a positive resulting count.
- A zero or negative result selects a negative resulting count.

It encodes that signed count using the positive header encoder captured immediately after the dependency, stores the header, and returns `false`.

### Negative admission and dependency

For a signed-negative input, the magnitude is formed by unsigned 32-bit negation of the argument.

The function rereads the negative header decoder, multiplies it by the current header, and forms the absolute count. It rejects with `true` if:

- The ordinary absolute count exceeds 28; or
- The negated magnitude, interpreted as signed 32-bit, is nonpositive.

Consequently, argument bit pattern `0x80000000` is rejected: unsigned negation leaves that bit pattern unchanged, and its signed interpretation remains negative. The header count computation precedes this rejection.

For an admitted input, the function calls F-d72f047fba8b. It then reads the negative word encoder followed by the negative word decoder.

There is no zero/nonzero gate on the dependency result.

If the pre-call count is zero, the function returns `false` without subsequent direct array or header writes. The dependency call and post-call global reads still occur.

### Negative whole-word processing: residual zero

For nonzero \(n\) and \(r=0\), original indices \(n-1\) through zero are copied, in descending order, to indices increased by \(q\).

This direction preserves the intended overlapping-copy behavior when source and destination use the same stable array. The copies preserve full word bit patterns.

The function next writes literal zero to indices \(q-1\) down through zero.

For the header calculation, it first reads the current header and decodes it with the entry-time negative header decoder to select the direction:

- Negative decoded header: subtract \(q\).
- Otherwise: add \(q\).

It then reads the header again for the decoded value to which that adjustment is applied. Finally it multiplies by a fresh read of the negative header encoder and stores the header.

The dependency result does not determine this header.

### Negative bit-combination processing: residual one through 31

For nonzero \(n\) and \(1\le r\le31\), source words are consumed from index \(n-1\) down to zero.

Each source word is multiplied by the captured negative word decoder. The signed product is then held as an unsigned 32-bit value. Its upper contribution, obtained by logical right shift through \(32-r\), is combined with a carry from the previously consumed higher source word. The combination is multiplied by the captured word encoder and stored.

The next carry is formed by an unsigned left shift through \(r\). Unlike the positive path’s next-word contribution, this left shift is explicitly applied to an unsigned value. The preceding signed decoder multiplication remains subject to its separate overflow uncertainty.

The first destination is index \(n+q\), followed by descending destinations. Thus the function writes an extra high slot even when that slot will not count toward the final size.

After consuming all source words, it writes the remaining carry, then encoded-zero products, in descending order through index zero.

It rereads the word at index \(n+q\), multiplying it by the captured word decoder:

- Zero selects resulting count \(n+q\).
- Nonzero selects resulting count \(n+q+1\).

That count is multiplied by the return value of F-d72f047fba8b, then by a fresh read of the negative header encoder, and stored in the header.

No visible restriction requires the dependency result to be a sign value, nonzero, or small enough to avoid signed multiplication overflow. The function returns `false`.

## Side effects

Directly visible effects include global reads, dependency calls, header writes, and array writes.

Ordering differs by branch:

| Branch | Direct write order |
|---|---|
| Positive complete removal | Header only |
| Positive residual zero | Header, then ascending array copies |
| Positive residual 1–31 | Ascending array outputs, then header |
| Negative residual zero | Descending copies, descending low-word clearing, then header |

In the positive bit-combination loop, each iteration uses a common address value for its two source words and destination. Other accesses do not establish a whole-call address snapshot.

No direct allocation, release, or assignment to the array-address field appears. This does not establish ownership or lifetime guarantees for either dependency.

No synchronization, rollback, capacity growth, or fault recovery is visible. If an access faults after earlier writes, the representation provides no restoration mechanism.

## Acceptance examples

These are conditional static examples, not executed tests. Unless overridden, assume all decoder and encoder multipliers are one, dependencies preserve the descriptor, array, and globals, F-18cbf7a56e3c returns zero, F-d72f047fba8b returns one, and all accessed storage exists.

1. **Zero displacement.** The result is `false`. The two entry-time global reads occur; there is no descriptor access or dependency call.

2. **Positive complete removal.** Header 2 and displacement 64 produce header zero and return `false`. Neither backing word is directly cleared.

3. **Positive whole-word movement.** Header 2, words `[3, 4]`, and displacement 32 produce header 1 and low word 4. The former high word remains outside the new used range without clearing.

4. **Residual one performs bit processing.** Header 2, words `[3, 0]`, and displacement 1 produce words `[1, 0]` and header 1. The next-word signed left shift has operand zero, so this example does not depend on an unresolved signed shift.

5. **Positive two-bit combination.** Header 2, words `[0, 1]`, and displacement 2 produce words `[0x40000000, 0]` and header 1. The next-word shift is \(1\times2^{30}\), within the signed range.

6. **Unresolved positive signed shift.** Header 2, words `[0, 2]`, and displacement 2 reach a next-word contribution mathematically equal to \(2^{31}\). That exceeds the signed 32-bit positive range. No exact output is specified here; unsigned wrapping must not be assumed.

7. **Negative whole-word movement.** Header 2, words `[3, 4]`, and displacement −32 produce used words `[0, 3, 4]` and header 3.

8. **Negative residual one is distinct.** The same initial object with displacement −33 writes `[0, 6, 8, 0]` through index 3. The high zero is excluded from the resulting count, so the header is 3. This is not the −32 transformation.

9. **Negative carry growth.** Header 1, word `[0x80000000]`, and displacement −2 produce `[0, 2]` and header 2. The decoder multiplication is representable as a signed negative value before conversion to unsigned.

10. **Positive dependency declines.** A nonzero F-18cbf7a56e3c result yields `false`, after the three post-call global reads. Only absence of subsequent direct writes is established.

11. **Zero-count negative input.** Header zero and displacement −2 still invoke F-d72f047fba8b and read both negative word globals. No subsequent direct header or array write occurs.

12. **Rejection boundaries.** An ordinary decoded count of 29 returns `true` without a dependency call. Argument `0x80000000` also returns `true`, after its negative-path count computation.

- **documented_only — Positive signed left shift:** For residuals 1–31, the next-word contribution is shifted as signed 32-bit arithmetic. Negative operands or shifted values outside the signed range have no established result here. This uncertainty is distinct from multiplication and negation overflow.

- **documented_only — Aliasing and concurrency:** Descriptor/array overlap and concurrent mutation have no established supported semantics.
