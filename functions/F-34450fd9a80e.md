# F-34450fd9a80e

## Purpose

F-34450fd9a80e classifies a record using selected bits from one or two 32-bit fields and returns a 32-bit result in the range 0 through 4.

The established behavior is a bit-based classification with strict precedence. One condition can force result 0 before the remaining flags are considered. Otherwise, one flag selects between two classification branches.

The meanings of the flags and result values are unknown. Interpreting them as success, failure, readiness, permissions, or lifecycle states would go beyond the supplied evidence.

### Output

### Relevant masks

The primary field is interpreted as an unsigned 32-bit value. Only these masks affect classification:

| Primary mask | Role |
|---|---|
| `0x01` | Selects the classification branch |
| `0x02` | Controls the secondary read, the initial gate, and the choice between results 2 and 4 |
| `0x10` | Selects result 1 within the branch chosen by `0x01` |
| `0x20` and `0x40` | Jointly select result 3 within the branch where `0x01` is clear |

Only secondary mask `0x04` affects classification. All other secondary bits are ignored.

## Behavior

### Read order and initial gate

The function first reads the complete 32-bit primary field at offset `0x24`. All subsequent primary-flag decisions use that captured value; the supplied representation contains no additional primary-field read.

If primary mask `0x02` is clear, the initial gate permits classification without reading the secondary field.

If primary mask `0x02` is set, the function next reads the complete 32-bit secondary field at offset `0x28`:

- Secondary mask `0x04` clear: return 0.
- Secondary mask `0x04` set: permit the remaining classification.

This gate has precedence over every other classification rule. In particular, when primary mask `0x02` is set and secondary mask `0x04` is clear, neither primary mask `0x10` nor the combination `0x60` can produce a nonzero result.

The secondary read is not deferred until its relevance to a later branch is known. Whenever primary mask `0x02` is set, that read occurs before classification using primary mask `0x01`, even if the eventual result would otherwise be 0.

### Classification when primary mask `0x01` is set

After the initial gate permits classification:

- If primary mask `0x01` is set and primary mask `0x10` is set, return 1.
- If primary mask `0x01` is set and primary mask `0x10` is clear, return 0.

In this branch, primary masks `0x20` and `0x40` do not affect the result. Primary mask `0x02` affects the initial gate and secondary-read requirement, but does not otherwise distinguish results within this branch.

### Classification when primary mask `0x01` is clear

After the initial gate permits classification, and with primary mask `0x01` clear:

- If both primary masks `0x20` and `0x40` are set, return 3.
- If either of those masks is clear, return 2 when primary mask `0x02` is clear, or 4 when primary mask `0x02` is set.

The combined condition requires both bits. Setting only `0x20` or only `0x40` does not select result 3.

Primary mask `0x10` has no effect in this branch.

### Complete normal-return conditions

| Result | Required conditions |
|---|---|
| 0 | Primary `0x02` set and secondary `0x04` clear; **or**, with the gate permitting classification, primary `0x01` set and primary `0x10` clear |

| 2 | Primary `0x02` clear; primary `0x01` clear; at least one of primary `0x20` and `0x40` clear |

| 4 | Primary `0x02` set; secondary `0x04` set; primary `0x01` clear; at least one of primary `0x20` and `0x40` clear |

The gate permits classification precisely when primary `0x02` is clear or, after the required secondary read, secondary `0x04` is set.

### Width and arithmetic boundaries

Classification uses bit tests, not signed comparisons. A set high bit in either 32-bit field does not itself change the result.

The complement-based test in the supplied representation examines only mask `0x60`. Its behavioral meaning is “at least one of `0x20` and `0x40` is absent,” not “both are absent.”

There is no classification arithmetic that increments, subtracts, scales, or truncates a field. Address formation uses fixed byte displacements. Behavior for invalid, overflowing, or otherwise unrepresentable address calculations is not established.
