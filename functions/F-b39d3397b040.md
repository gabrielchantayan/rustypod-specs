# F-b39d3397b040

## Purpose

F-b39d3397b040 scans length-prefixed records in a caller-supplied byte region, starting at offset 8. Selected records update a caller-owned descriptor with presence flags, payload values, and payload locations.

The first eight region bytes are not directly inspected. The function does not validate an outer signature or identify an external format.

Updates are incremental, not transactional. Earlier descriptor writes survive later failures. Existing descriptor contents participate in processing; the function neither initializes the descriptor nor requires every recognized record class to occur.

Several comparison and return values come from unresolved global storage. Their numeric values and immutability are not established. Each executed read must therefore be distinguished from other reads of the same storage. Stable-global behavior is described conditionally, not assumed.

## Interface

### Inputs and result

| Input | Representation and use |
|---|---|
| Byte-region address | A 32-bit address-bearing value. Zero selects the invalid-argument path. Nonzero values are used for relative byte accesses. |
| Region extent | A signed 32-bit integer describing the region, including the eight skipped bytes. There is no separate rejection of negative extents. |
| Descriptor address | A pointer to writable unsigned 32-bit words. Null selects the invalid-argument path. |

The return value is a 32-bit integer:

- Ordinary successful exhaustion returns zero.
- Invalid arguments return the value read from the **argument-error global** on that path.
- Boundary failures return a fresh value read from the **scan-error global**.
- Record-processing failures use an earlier sample of the scan-error global, as detailed below.

Neither error global is established to be nonzero. Their values need not differ.

### Descriptor layout

Each field occupies one native-representation 32-bit word.

| Byte offset | Meaning assigned by this function |
|---|---|
| 0 | Accumulated flags |
| 4 | Four-byte value assembled least-significant byte first |
| 8 | First big-endian value from a fixed-size record |
| 12 | Second big-endian value from that record |
| 16 | Third big-endian value from that record |
| 20 | First range class: payload offset |
| 24 | First range class: payload length |
| 28 | Second range class: payload length |
| 32 | Second range class: payload offset |

The flag masks are:

| Mask | Associated record handler |
|---|---|
| `0x01` | Four-byte value |
| `0x02` | Presence only |
| `0x04` | Fixed-size three-value record |
| `0x08` | Second payload range |
| `0x10` | First payload range |

General use requires a descriptor spanning at least 36 bytes. Particular paths access fewer words.

### Memory and ownership preconditions

Every executed byte read, descriptor access, and unresolved-global read requires valid accessible storage. Descriptor word accesses require suitable writable storage and alignment. Invalid nonnull addresses have no established recovery behavior.

No allocation, release, or ownership transfer is visible. Stored payload locations are offsets, not copied payloads or owned pointers.

To isolate parsing from its own writes, descriptor storage must not overlap the scanned region. That alone does not ensure stable behavior: descriptor storage may also alias unresolved global storage. Such aliasing can change values observed by later global reads.

## Behavior

### Entry and boundary decisions

If either address input is null, the function reads the argument-error global and returns that sample. It does not access the byte region or descriptor on this path.

Otherwise, scanning starts at offset 8 with a zero carried result.

Before each attempted header read, the function adds 8 to the current offset using the recovered 32-bit arithmetic and compares the signed interpretation of that sum with the signed extent.

If the header-availability comparison fails:

1. If the current offset equals the extent, read the descriptor flags.
2. If those flags contain every bit in `0x0b`, return the carried result, which is zero on a continuing scan.
3. Otherwise, read the scan-error global at this boundary and return that newly sampled value.

The required completion bits are `0x01`, `0x02`, and `0x08`. Other bits do not affect this check. A non-exact boundary failure does not inspect descriptor flags.

Thus an extent of 8 can succeed with no records if the descriptor already contains the required bits. Conversely, one through seven trailing bytes cause boundary failure under ordinary non-wrapping arithmetic, even if all required flags are set.

Completion flags do not stop parsing while another complete header appears available.

### Header decoding and structural validation

Each record has an eight-byte header:

- Bytes 0–3: unsigned 32-bit big-endian total length.
- Bytes 4–7: unsigned 32-bit big-endian type.
- Payload: begins at record offset plus 8.
- Total length includes the header.

The function obtains the length word and then the type word before validating the decoded length. The exact order of byte loads within either word construction is not established.

After obtaining both words and computing the candidate end offset, every record iteration reads the scan-error global. This **initial record-error sample** occurs even for structurally valid records, recognized records, and unrecognized records.

Structural validity requires all of the following:

- The length, interpreted as signed 32-bit, is greater than 7.
- The computed end offset, interpreted as signed 32-bit, is nonnegative.
- The computed end is no greater than the signed extent.

For a structurally invalid record, the current offset is retained and the initial record-error sample becomes the processing result.

For a structurally valid record, the next offset becomes its computed end, and the initial record-error sample is discarded in favor of the preceding carried result, which is zero. Dispatch then begins.

### Conditional global reads and dispatch priority

Type selection uses unresolved globals, read only when their respective branches are reached:

1. Read the **range-type global** and compare it with the decoded type.
2. Only on a mismatch, read the **value-type global** and subtract that sample from the type with 32-bit arithmetic.
3. A zero difference selects the four-byte value handler.
4. Only for a nonzero difference, read the **adjustment global** and add that sample to the difference with 32-bit arithmetic.
5. An adjusted result of zero selects the second payload-range handler.
6. Otherwise, an adjusted result of four selects the presence-only handler.
7. Otherwise, read the **fixed-size-selector global** and compare it with the adjusted result.
8. A match selects the fixed-size handler; a mismatch leaves the record unrecognized.

Earlier matches prevent later global reads. For example, a direct range match does not read the value-type, adjustment, or fixed-size-selector globals.

The subtraction uses the value-type sample already read for that record. There is no additional value-type read when the adjustment is applied.

Numeric identities and possible collisions among these globals are unresolved. Priority can make a later handler unreachable. If global contents change, the same decoded type can select different handlers on different iterations.

### First payload-range handler

For a structurally valid direct range match, the observable descriptor operations are:

1. Write payload offset at descriptor offset 20.
2. Write total length minus 8 at offset 24.
3. Read flags, OR with `0x10`, and write flags.

No payload bytes are read. Total length 8 records an empty range.

### Four-byte value handler

For a structurally valid direct value match:

- At total length 12 or greater, read the first four payload bytes and assemble an unsigned 32-bit value with the first byte least significant.
- Write that value at descriptor offset 4.
- Then read flags, OR with `0x01`, and write flags.

Additional payload bytes are ignored.

Lengths 8 through 11 cause no descriptor update and do not independently select an error. Scanning advances to the record end.

### Second payload-range handler

For an adjusted selector of zero:

1. Write payload offset at descriptor offset 32.
2. Read flags, OR with `0x08`, and write flags.
3. Write total length minus 8 at descriptor offset 28.

The flag write precedes the length write, unlike the first range handler. No payload bytes are read; an empty payload is accepted.

### Presence-only handler

For an adjusted selector of four, read flags, OR with `0x02`, and write flags.

Any structurally valid length is accepted. No payload bytes or other descriptor fields are accessed by this handler.

### Fixed-size three-value handler

A fixed-size-selector match performs a **second scan-error-global read before checking the record length**. This **fixed-size error sample** replaces the otherwise zero processing result.

If total length is not exactly 20:

- No descriptor updates are made by this handler.
- The fixed-size error sample remains the processing result.
- The next offset remains the end of this structurally valid record.

If total length is exactly 20:

1. Read flags, OR with `0x04`, and write flags.
2. Read payload bytes 0–3 as an unsigned big-endian value and write descriptor offset 8.
3. Read payload bytes 4–7 as an unsigned big-endian value and write descriptor offset 12.
4. Read payload bytes 8–11 as an unsigned big-endian value and write descriptor offset 16.
5. Restore the preceding zero processing result, discarding the fixed-size error sample.

The second error read occurs even for a correctly sized record. A nonzero sample does not make such a correctly sized record fail.

### Continuation and returned samples

After record processing:

- A zero processing result resumes scanning at the selected next offset.
- A nonzero processing result returns that exact value.
- Returning a nonzero processing result does not reread the scan-error global, inspect completion flags, or read another header.

Consequently:

- A structurally invalid record uses its initial record-error sample. If nonzero, that sample is returned. If zero, scanning retries the same offset.
- A wrongly sized fixed-size record uses its second, fixed-size error sample. If nonzero, that sample is returned. If zero, scanning continues at the record end.
- Valid records other than wrongly sized fixed-size records continue regardless of the initial error sample.
- A later boundary failure takes a fresh error sample, independent of either earlier sample.

With stable input and a persistently zero initial error sample, a malformed record can be retried indefinitely. If global contents change, a later retry may instead terminate with a nonzero sample.

### Unknown and repeated records

Structurally valid unrecognized records produce no descriptor writes and advance to their declared end. They still perform the initial scan-error read and all dispatch-global reads needed to establish that they are unrecognized.

Repeated recognized records are allowed. Later writes replace earlier values in the same fields. Flag updates OR in their mask; they do not deliberately clear other bits.

No uniqueness, cross-record consistency, prescribed record ordering, or payload-content validation is visible.

## Side effects

### Read and write ordering

The established operation order includes:

- Both header words before the initial per-record scan-error read.
- That error read before structural validation.
- Structural validation before dispatch-global reads.
- Conditional dispatch-global reads in the order described above.
- A second scan-error read after a fixed-size-selector match and before its length test.
- Handler-specific descriptor accesses in the stated order.
- A fresh scan-error read only on an unsuccessful boundary-return path.

All explicit writes target descriptor words. No explicit byte-region write or dedicated global assignment is visible. Physical aliasing can nevertheless make a descriptor write modify input bytes or unresolved global storage.

The function provides no rollback. Failure after earlier records leaves their writes in place. Within the fixed-size handler, the flag is written before any of the three payload values.

### Mutation and aliasing

No snapshot of global storage is taken at entry. Different executed reads of the scan-error global may observe different values, including the two reads associated with one fixed-size record.

Descriptor writes can affect later type selection or error returns if they alias the relevant globals. They can affect later input reads if they alias the byte region. A previously sampled error value is not refreshed merely because its source storage changes.

Concurrent mutation, aliasing with global storage, and platform memory behavior are documented_only beyond these explicit read/write relationships. No synchronization or atomicity guarantee is established.

### Arithmetic limitations

The recovered values and address calculations are 32-bit. Lengths with bit 31 set fail the signed “greater than 7” test.

The header-availability comparison is not an overflow-safe bounds check. Near the maximum signed offset, adding 8 can yield a negative signed interpretation and permit a header read despite inadequate declared space.

Pointer arithmetic can also wrap without an explicit check. Callers must independently provide accessible storage for actual accesses. The exact language-level treatment of overflowing recovered signed expressions remains unresolved; the arithmetic account describes the apparent 32-bit behavior.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless an example says otherwise, assume accessible non-overlapping storage, stable globals, reachable handler conditions, ordinary non-wrapping arithmetic, and a nonzero scan-error value.

1. **Null address:** Either address input is zero. The argument-error global is read and its sample returned. No byte-region or descriptor access occurs.

2. **Empty successful sequence:** Extent is 8 and existing flags include `0x0b`. No header or error-global read occurs. The function reads flags, returns zero, and leaves the descriptor unchanged.

3. **Empty unsuccessful sequence:** Extent is 8 and a required flag is missing. After reading flags, the function reads the scan-error global and returns that sample without descriptor writes.

4. **Little-endian value:** A value-handler record has length 12 and payload bytes `01 02 03 04`. Descriptor offset 4 becomes `0x04030201`, followed by flag `0x01`. Overall success still requires successful exhaustion.

5. **Short value record:** A value-handler record has length 11. It performs the initial error read and relevant type reads, but makes no descriptor update. Scanning advances by 11 bytes.

6. **Empty second range:** A second-range record begins at offset 8 with length 8. Offset 32 receives 16; flags then gain `0x08`; offset 28 then receives zero.

7. **Correct fixed-size record:** Length is 20 and the first payload bytes are `01 02 03 04`. The handler reads the scan-error global a second time, writes flag `0x04`, then writes `0x01020304` at offset 8 and the next two big-endian values at offsets 12 and 16. It continues even if either error sample was nonzero.

8. **Different fixed-size error samples:** A structurally valid fixed-size record has length 16. Its initial error sample is nonzero, but its second sample is zero. The initial sample is discarded; the handler makes no descriptor writes and continues at the record end.

9. **Retained failure sample:** A structurally invalid record samples a nonzero scan-error value. That value is returned without rereading the global, even if the global changes afterward.

10. **Zero-error malformed retry:** A readable header declares length 7. Each initial error sample remains zero and input stays unchanged. The same header is processed repeatedly at the same offset.

11. **Trailing fragment:** Valid records leave three bytes before the extent. Earlier updates persist; the function returns a fresh boundary sample of the scan-error global, regardless of accumulated completion flags.

12. **Descriptor/global aliasing:** A descriptor write also changes storage backing a global used on a later iteration. The later read observes storage at that later point; entry-time global values are not a guaranteed reference. Exact results depend on the unresolved storage relationship.
