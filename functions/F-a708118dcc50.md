# F-a708118dcc50

## Purpose

F-a708118dcc50 conditionally updates shared state using a registered object, an acquired object, and supporting dependencies.

Three normal outcomes are established:

- Registered-object pointer is null when checked: return the 32-bit value **11**.
- Registered-object pointer is nonnull and its readiness query returns nonzero: return **0**, without the initialization sequence.
- Registered-object pointer is nonnull and its readiness query returns zero: execute the initialization sequence and return **0**.

Two conditions invoke F-a817d8d58c10, identified in the supplied representation as nonreturning:

- A refreshed signed gate value remains greater than 2.
- Acquisition of the acquired object returns null.

Updates are incremental. Earlier writes and dependency effects precede operations that may fail or not return. No rollback is established.

“Initialization,” “readiness,” and object-role descriptions summarize apparent purpose; they do not establish undocumented dependency semantics.

## Interface

### Inputs and result

There are no explicit parameters. The normal result is a 32-bit quantity, exactly 11 or 0.

Effective inputs include:

- Two separately evaluated reads of a global holding a shared-state address.
- Fields accessed through the first captured address.
- A context read through the address obtained by the second global evaluation.
- Dependency results, indirect-call results, and dependency side effects.
- Three external global values read during acquired-object processing.

The three external values are **not established constants**. Their meanings, declared types, and immutability are not supplied.

### Base and context capture

Entry performs two distinct evaluations:

1. Read the shared-state-base global and save its value for subsequent field accesses.
2. Evaluate that global again, then read a 32-bit context at offset `0x24` through this second value.

The second address is not established to equal the saved base. Equality requires a stability assumption absent from the supplied evidence.

All shared-state offsets below refer to the **saved first base**, except the entry-time context read just described. Later reads of offset `0x24` use the saved base, not a fresh evaluation of the base global.

## Behavior

### Entry, gate, and readiness

After the two base-global evaluations and context capture, the function invokes an unmapped entry-bracketing dependency with the captured context plus `0x2d0`.

It then reads the registered-object pointer at saved-base offset `0x28`.

If this pointer is null, gate processing and initialization are skipped. Normal exit returns 11.

Otherwise, the function reads offset `0x2c` as a signed 32-bit integer:

- Values at or below 2, including negative values, bypass refresh.
- Values above 2 invoke an unmapped gate provider.
- The provider result plus 4 becomes F-f82bb660a2ac’s first argument; its second argument is 4.
- The returned 32-bit value is written to offset `0x2c`.
- That returned value is compared with 2 as signed. If greater, F-a817d8d58c10 is invoked.

The post-refresh decision uses the returned value, not another read of offset `0x2c`.

If execution continues, the registered object is reloaded and its slot `0x24` is invoked. No explicit arguments are shown for this call. A nonzero result skips initialization; a zero result enters it.

### Early publication and local objects

Initialization performs the following ordered actions:

1. Write byte 0 at offset `0x00`.
2. Invoke an unmapped initialization provider.
3. Call F-23aadb16b673 with that provider result first and the current 32-bit field at offset `0x10` second. The field read occurs after the provider returns.
4. Pass an eight-byte, two-word local object to F-7a117b899bf6.
5. Initialize a separate two-word local pair to zero.
6. Invoke slot `0x0c` through the first word of the local object, passing the local object first and the pair’s address second.
7. Pass the pair’s address to F-bf18a6a8124b; store its 32-bit result at offset `0x14`.
8. Write byte 0 at offset `0x02`.
9. Write 32-bit zero at offset `0x18`.
10. Write byte 1 at offset `0x03`.
11. Reload the registered object for slot `0x20`, passing the object and 1.
12. Write byte 1 at offset `0x04`.

The slot `0x20` expression separately obtains the dispatch target and receiver from the registered-object field. The earlier nonnull check does not freeze either read.

The local object is not explicitly initialized before F-7a117b899bf6 receives it. The separate output pair is explicitly zeroed before the indirect call. Neither operation establishes ownership or the meaning of the resulting words.

## Side effects

Direct shared-state writes are limited to:

- Gate replacement at offset `0x2c`, when refresh occurs.
- The individual initialization-path writes described above.

No whole-record clearing is shown. Initialization skipping does not itself write initialization fields. A null secondary-object result does not itself write offset `0x3c`.

Dependencies may modify state even on paths with no direct initialization writes. Therefore, “no direct write” does not mean “unchanged after return.”

Writes are not transactional. In particular, acquisition failure occurs after the early byte and word publications. The final 64-bit result is published only after the conditional notification and secondary-object sequence.

The entry and exit calls resemble synchronization bracketing, but locking, memory-ordering, and exception-safety properties are not established.

The local pairs and 16-byte areas are invocation-local storage. Passing their addresses does not prove that callees avoid retaining them. F-54033250428c receives a pointer address and could alter the local pointer, but release, clearing, and ownership transfer are not established. The same limitation applies to F-ec22bd8215d3 and secondary-object slot `0x1c`.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, storage and dispatches are valid and dependencies return.

1. **Different entry bases.** If the first base-global evaluation yields address A and the second yields B, subsequent fields use A, while the entry context comes from B at `0x24`. Both bracketing calls use that captured context plus `0x2d0`.

2. **No registered object.** If A at `0x28` is null when checked, return 11 after normal exit bracketing. No gate refresh or direct initialization write occurs.

3. **Signed gate boundary.** Gates −1 and 2 bypass refresh. Gate 3 triggers refresh. A refresh result of −1 or 2 permits readiness checking; result 3 is stored before invoking F-a817d8d58c10.

4. **Readiness skips initialization.** A nonzero slot `0x24` result produces normal return 0 without calling F-be45cd43f92d.

5. **Acquisition fails late.** Zero readiness followed by null acquisition reaches F-a817d8d58c10 after the early writes, without the ordinary exit or final cleanup-like calls.

6. **First external read and argument order.** If F-bf351530c187 returns X and leaves the first external global as Y, F-a2bcece589e7 receives Y first and X second. A value held by that global before the conversion call is not substituted.

7. **Captured second value.** If the second external global is S at both initial evaluations, the first slot `0x5c` receives object, S, 50. If a later dependency changes the global to T, the second call still receives object, 50, S.

8. **Distinct result publication.** First slot `0x108` result A, slot `0x124` result B, and second slot `0x108` result C are directly written, in that order, to `0x30`, `0x38`, and `0x34`.

9. **Late third value.** If an earlier dependency changes the third external global to Z before final processing, slot `0x34` receives Z, not an entry-time snapshot.

10. **Secondary absence and context changes.** Null secondary construction omits the direct `0x3c` write and secondary slot `0x1c`. If notification is enabled, it reads current saved-base context and gate fields; normal exit still uses the original captured context.

## Uncertainties

The following remain **documented_only**:

- Domain meanings of fields, gates, objects, and external values.
- Stability of the base global between entry evaluations.
- Stability of the second external global between its capture and separate first-pass read.
- Declared types and interpretation of the first and third external globals.
- Hidden receivers or arguments for indirect calls without explicit arguments.
- Dependency preservation of globals, fields, pointers, and dispatch tables.
- Allocation, retention, ownership transfer, and release behavior.
- Local-object formats and whether area-populating calls fully initialize their outputs.
- Signedness of result words other than the signed gate comparisons.
- Byte order, atomicity, and visibility guarantees of the 64-bit store.
- Exceptions, nonlocal exits, and failures not explicitly branched upon.

Context-plus-`0x2d0` and provider-plus-4 occur in the recovered 32-bit address/value setting. No overflow check or widening operation is shown. A portable wrapping, trapping, or invalid-address policy is not established.
