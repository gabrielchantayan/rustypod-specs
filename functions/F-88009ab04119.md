# F-88009ab04119

## Purpose

F-88009ab04119 dispatches on a 32-bit selector. Depending on that selector, it performs zero to three context-processing calls, optionally invokes an auxiliary operation through a handle stored in the context, or prepares a temporary value through a separate dependency.

The result is a 64-bit encoding of the final selector value, not a dependency’s return value. Some branches replace the selector with zero or with the address of temporary storage before encoding it.

The meaning of the selector values, context-processing operation, auxiliary operation, and temporary value is not established. Names such as “handle” and “context” describe their structural roles, not verified application semantics.

## Interface

### Inputs

The supplied representation exposes four arguments:

| Position | Representation | Established use |
|---|---|---|
| 1 | 32-bit context-address value | Passed to F-ab545ff44214 and used as the base for two field accesses on selected branches. |
| 2 | 32-bit pointer-shaped selector | Compared against integer constants. Its incoming value is never dereferenced by this function. It may be replaced before return. |
| 3 | 32-bit opaque value | No direct use is visible. |
| 4 | 32-bit opaque value | Copied into a four-byte temporary at entry. Some branches overwrite that temporary or expose its address to dependencies. |

The pointer-shaped type of the second argument does not imply that callers must supply a readable pointer. This function dispatches on its numeric representation.

### Context layout used directly

Only these context fields are directly accessed:

| Byte offset | Width | Use |
|---|---:|---|
| `0xB0` | 32 bits | Tested against zero and, if nonzero, read again as the first argument to F-fc9444c74c1d. |
| `0xB4` | 32 bits | Read on the nonzero-handle path, then masked with `0xFF` for the second argument to F-fc9444c74c1d. |

There is no direct context-field write in the visible body.

The field at `0xB4` is read as a full 32-bit quantity. Only its low eight bits contribute to the dependency argument. This is not evidence of a one-byte memory access.

### Output

On normal completion, the function returns a 64-bit value with:

- Bits 31–0 equal to zero.
- Bits 63–32 equal to the final 32-bit selector representation.

This construction zero-extends the selector to 64 bits before shifting it left by 32. It does not sign-extend the selector.

Although the result is presented through a signed 64-bit return type, the bit layout above is the relevant contract. If the final selector’s top bit is set, the returned bit pattern has the signed 64-bit sign bit set.

### Preconditions

For branches that directly inspect the context, the context must support the required 32-bit reads at the offsets above. The body provides no null check, bounds check, alignment repair, or recovery mechanism for invalid accesses.

Additional requirements imposed by dependencies are unknown. In particular, passing the context to F-ab545ff44214 may require more than the directly visible field layout.

## Behavior

### Entry and common return construction

The function first copies the fourth argument into a four-byte temporary.

It then selects a branch using the incoming second argument. Dispatch is based on that incoming value; replacing the selector within a branch does not cause another dispatch.

Every normally completing branch finishes by encoding the current selector into the upper half of the 64-bit result. Dependency return values are not used in that encoding.

### Selectors `0x21`, `0x22`, and `0x23`

These selectors cause repeated calls to F-ab545ff44214, each receiving the original context argument:

| Incoming selector | Number of calls |
|---|---:|
| `0x21` | 1 |
| `0x22` | 2 |
| `0x23` | 3 |

Calls occur sequentially. A later call begins only after the preceding call returns normally.

The function itself does not replace the selector on these paths. Consequently, if execution reaches the return, the upper 32 bits of the result retain the incoming selector.

These calls must not be treated as redundant. Nothing establishes that the dependency is idempotent, preserves state, or produces identical effects on successive calls.

### Selectors `0x24` through `0x2C`

These nine selectors cause no dependency calls and no direct context reads.

The temporary still receives the fourth argument at entry, but its address is not passed to a dependency on these paths. The selector remains unchanged and is encoded into the result.

### Selector `0x2D`

This branch performs the following ordered operations:

1. Replace the temporary’s contents with the 32-bit value `0x00FFFFFF`.
2. Read the 32-bit field at context offset `0xB0` and test it against zero.
3. If that observation is nonzero:
   - Replace the selector with zero.
   - Invoke F-fc9444c74c1d with six arguments:
     1. A new read of the field at offset `0xB0`.
     2. A read of the field at offset `0xB4`, masked with `0xFF`.
     3. Zero.
     4. Zero.
     5. Zero.
     6. The address of the four-byte temporary.
4. Invoke F-ab545ff44214 with the context, regardless of whether the handle test was zero or nonzero.
5. Encode the final selector into the return value.

The handle used in the dependency call is read separately from the handle used in the preceding test. The source does not cache the tested value for reuse. If the field changes between those observations, the argument supplied to the dependency need not equal the value that satisfied the test.

The relative evaluation order of the handle and masked-field reads used as call arguments is not established. Both belong to preparation for the auxiliary call, after the successful test and before that call begins.

The fourth argument’s initial value does not determine the temporary value offered to the auxiliary dependency on this branch: it has already been replaced by `0x00FFFFFF`.

The normal return is:

- `0x0000002D00000000` if the handle test observes zero.
- `0x0000000000000000` if the handle test observes nonzero and all subsequent calls return normally.

The final context-processing call occurs after the auxiliary call on the nonzero path. It may therefore observe changes made by that auxiliary call.

### Selectors `0x2E` and `0x2F`

Both selectors use the same branch:

1. Invoke F-0c619ddcbcea with:
   - The address of the four-byte temporary.
   - A second argument supplied by a fixed data reference whose representation and meaning are not established.
2. After that dependency returns, read the 32-bit field at context offset `0xB0` and test it against zero.
3. If that observation is nonzero:
   - Replace the selector with the address of the temporary.
   - Invoke F-fc9444c74c1d with:
     1. A new read of the field at offset `0xB0`.
     2. A read of the field at offset `0xB4`, masked with `0xFF`.
     3. Zero.
     4. Zero.
     5. The address of the temporary.
     6. Zero.
4. Encode the final selector into the return value.

F-ab545ff44214 is not called on these branches.

F-0c619ddcbcea receives the temporary after its initialization from the fourth argument. Whether that dependency reads the initial contents, overwrites them, or performs some other operation is unknown.

The context test occurs after F-0c619ddcbcea returns. It must not be moved conceptually ahead of that call: the dependency is not established to preserve shared state.

As in the `0x2D` branch, the tested handle and the handle supplied to F-fc9444c74c1d come from distinct reads. The relative order of the argument-producing field reads is not established.

If the handle test observes zero, the selector remains `0x2E` or `0x2F`. If it observes nonzero, the upper half of the returned value contains the temporary’s address, not the temporary’s contents.

### All other selectors

Any selector outside `0x21` through `0x2F` takes no explicit action after entry initialization.

There are no dependency calls or direct context reads on this path. The incoming selector is preserved in the upper half of the return value. No invalid-selector error is reported.

All dependency return values are ignored. A dependency may report a failure through its return value, but this body does not inspect it.

## Side effects

### Direct effects

The function directly:

- Initializes one four-byte temporary.
- Replaces that temporary with `0x00FFFFFF` on selector `0x2D`.
- Changes its working selector on specific nonzero-handle paths.
- Reads the context fields described above.
- Calls dependencies in the specified sequence.

It performs no visible allocation, deallocation, or direct write to context storage.

### Indirect effects

Dependencies may modify context, global state, or other reachable storage. Their names and argument shapes do not establish narrower effects.

In particular:

- F-ab545ff44214 receives the context.
- F-fc9444c74c1d receives a handle, a masked field value, and sometimes a pointer to the temporary.
- F-0c619ddcbcea receives a pointer to the temporary and a data-derived argument.

These facts do not establish that any dependency preserves globals, releases a handle, acquires ownership, or limits writes to the temporary.

### Lifetime and ownership

The four-byte temporary belongs to the current invocation. Passing its address establishes no ownership transfer.

On the nonzero-handle path for `0x2E` or `0x2F`, the function encodes that temporary address in its return value. This is not a return of independently allocated storage. The temporary’s lifetime ends when the invocation ends; the result does not establish a valid post-return object to dereference.

Whether a dependency retains a supplied temporary pointer is unknown. Retention would not extend the lifetime established here.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Single context-processing call.** With selector `0x21`, if F-ab545ff44214 returns normally, exactly one such call occurs and the result is `0x0000002100000000`.

2. **Repeated context processing.** With selector `0x23`, normal completion requires three sequential calls to F-ab545ff44214. Their return values do not change the result `0x0000002300000000`.

3. **Inactive explicit branch.** With selector `0x28`, no dependency is called and no context field is directly read. The result is `0x0000002800000000`.

4. **Default branch.** With selector zero, no dependency is called and the result is zero. With selector `0x80000001`, the returned bit pattern is `0x8000000100000000`; the low half remains zero.

5. **`0x2D` with zero handle observation.** If the handle test reads zero, F-fc9444c74c1d is skipped, F-ab545ff44214 is called once, and normal completion returns `0x0000002D00000000`.

6. **`0x2D` with a stable nonzero handle.** If the handle remains nonzero and the field at `0xB4` reads `0x123456AB`, F-fc9444c74c1d receives `0xAB` as its second argument and the temporary address as its sixth. The temporary contains `0x00FFFFFF` when supplied. After that call returns, F-ab545ff44214 runs once. Normal completion returns zero.

7. **`0x2E` with zero after preparation.** F-0c619ddcbcea runs first. If the subsequent handle test reads zero, no auxiliary call follows and normal completion returns `0x0000002E00000000`.

8. **`0x2F` with nonzero after preparation.** If the post-preparation handle test reads nonzero, F-fc9444c74c1d receives the temporary address as argument five and zero as argument six. The return’s upper half equals that address’s 32-bit representation, not any value written into the temporary.

9. **Changed handle between reads.** If a handle test observes nonzero but the later argument read observes zero, the auxiliary call still occurs and receives the later zero value. There is no second eligibility test.
