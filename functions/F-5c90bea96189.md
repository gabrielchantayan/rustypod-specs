# F-5c90bea96189

## Purpose

F-5c90bea96189 partially initializes a caller-provided output record from a source record. It selects an output representation using a 16-bit source discriminator, computes two 32-bit coordinate differences, stores each difference twice, clears several output fields, and returns an eight-byte value read from the source.

The established behavior is narrower than complete record initialization: several output bytes retain their previous contents, and the discriminator determines whether one, two, or four bytes are written at output offset `0x30`.

Interpreting the coordinate differences as width and height, or the discriminator as a format identifier, is inferred intent. Those meanings are not necessary to the behavioral contract.

## Interface

| Second argument | A source-record address, represented as a 32-bit integer in the supplied interface. |
| Third argument | An address of writable output storage. |

Offsets below are byte offsets relative to the appropriate argument address.

The source fields used are:

| Source offset | Access width | Role |
|---|---:|---|
| `0x14` | 16 bits | Discriminator, compared with `0x0565` and potentially `0x1888`. |

## Behavior

### 1. Initial selector setup

The first output mutation writes the byte value `3` at offset `0x01`.

The source discriminator at offset `0x14` is then read and compared with `0x0565`.

If it matches:

1. Two zero bytes are written as a 16-bit value at output offset `0x30`.
2. Output offset `0x00` receives the byte value `2`.

If the first comparison does not match, the discriminator is read again and compared with `0x1888`.

If that second comparison matches:

1. Four zero bytes are written as a 32-bit value at output offset `0x30`.
2. Output offset `0x00` receives the byte value `3`.

If neither comparison matches:

1. Output offset `0x00` receives the byte value `0`.
2. Output offset `0x30` receives the byte value `0x80`.

Thus, the fallback branch writes the selector before the representation-specific byte; the two recognized branches write the representation-specific field before the selector.

After the selected branch completes, output offset `0x2D` receives zero.

The two discriminator comparisons must not be described as a single guaranteed read. A source mutation between reads could affect the second comparison, although the validity of concurrent mutation is not established by the supplied evidence.

### 2. Source capture and difference calculation

After the selector-related writes:

1. A signed 32-bit value is read from source offset `0x9C` and retained for the second subtraction.
2. A 64-bit value is read from source offset `0x98` and retained as the eventual return value.
3. A signed 32-bit value is read from source offset `0xA4`.
4. The first difference is calculated from separate signed 32-bit reads: the value at `0xA0` minus the value at `0x98`.

The supplied expression does not establish the relative evaluation order of the two reads used in the first subtraction. A contract should not impose an order between those two operand reads without additional target evidence.

The 32-bit read at `0x98` is distinct from the earlier 64-bit read at the same offset. Likewise, the retained value from `0x9C` comes from its own read rather than being extracted from the captured 64-bit return value.

Consequently, if the relevant source bytes change between reads, the returned value and the arithmetic inputs need not describe one coherent source snapshot. No synchronization or snapshot mechanism appears.

### 3. Difference stores

The first difference is written as a 32-bit integer:

1. At output offset `0x18`.
2. At output offset `0x10`.

The second difference is then calculated as the retained value from source offset `0xA4` minus the retained value from source offset `0x9C`.

It is written as a 32-bit integer:

1. At output offset `0x14`.
2. At output offset `0x0C`.

There is no clamping, absolute-value conversion, endpoint reordering, or rejection of negative differences.

For non-overflowing arithmetic, each pair of fields receives identical values. The order of those writes remains relevant when observing partial execution or overlapping storage.

### 4. Final clearing and return

The following 32-bit zero writes occur, in order:

1. Output offset `0x28`.
2. Output offset `0x24`.
3. Output offset `0x04`.
4. Output offset `0x08`.

The function then returns the previously captured 64-bit source value. It does not reload that value after the output writes.

### Partial initialization

The function is not a whole-record clear.

Within the first `0x34` output bytes, it never directly writes:

- `0x02`–`0x03`.
- `0x1C`–`0x23`.
- `0x2C`.
- `0x2E`–`0x2F`.

Additional untouched bytes depend on the discriminator:

- For `0x0565`, bytes `0x32`–`0x33` are not written.
- For the fallback branch, bytes `0x31`–`0x33` are not written.
- For `0x1888`, all four bytes at `0x30`–`0x33` are written.

With valid, independently stored output memory and no external mutation, these untouched bytes retain their entry values.

## Side effects

The established side effects are the output writes described above. The function contains no explicit writes through the source argument, no global accesses, and no calls to other functions.

If source and output storage overlap, output writes may modify bytes subsequently read through the source argument. In particular:

- The first output write precedes the discriminator read.
- Representation-related writes precede all coordinate and return-value reads.
- The return value is captured before the difference stores and final clears.

Therefore, the simple interpretation “read a source record, then initialize a separate output record” is valid only when the relevant memory does not overlap or when the particular overlap leaves the observations unchanged. No protective copy is made.

The supplied evidence does not establish whether arbitrary overlap is valid under the original language’s aliasing rules. An implementation-independent guarantee for overlapping objects is therefore **documented_only**.

No allocation, release, ownership transfer, pointer retention, logging, or external I/O is present in the body. The caller remains responsible for supplying and managing the referenced storage. No assumptions about unknown callees are necessary because this body contains no calls.

There is no normal error return. Invalid memory accesses, unsupported alignment, address overflow, or signed arithmetic overflow have no defined recovery path in the supplied evidence. Earlier writes may already have occurred before an access failure.

## Acceptance examples

These examples are conditional acceptance criteria, not recorded test results. Unless stated otherwise, assume valid aligned storage, non-overlapping source and output, stable source contents, sufficient output capacity, and representable signed differences.

### Recognized discriminator `0x0565`

Given:

- Discriminator `0x0565`.
- First coordinate pair: `10` and `25`.
- Second coordinate pair: `−4` and `8`.

Required results:

- Output byte `0x00` is `2`; byte `0x01` is `3`.
- The 16-bit field at `0x30` is zero.
- Output fields at `0x18` and `0x10` both contain `15`.
- Output fields at `0x14` and `0x0C` both contain `12`.
- Byte `0x2D` and the four specified final-clear fields are zero.
- Bytes `0x32`–`0x33`, if present, retain their previous contents.
- The return value is the eight-byte source value captured at `0x98`.

### Recognized discriminator `0x1888`

Given discriminator `0x1888`, output byte `0x00` must become `3`, and all four bytes at `0x30`–`0x33` must become zero.

Clearing only the first two bytes at `0x30` is not equivalent behavior for this branch.

### Unrecognized discriminator

Given a stable discriminator of `0`, or any other value unequal to both recognized constants:

- Output byte `0x00` becomes `0`.
- Output byte `0x30` becomes `0x80`.
- Output bytes `0x31`–`0x33` are not directly written.
- Difference calculation and final clearing still occur.

An unrecognized discriminator does not produce an early return or an error result.

### Negative differences

- Both first-difference fields contain signed 32-bit `−7`.
- Both second-difference fields contain signed 32-bit `−6`.

The function must not replace these values with zero or their magnitudes.

### Preserved bytes

For the fallback branch, bytes `0x31`–`0x33` also remain `0xA5`. This distinguishes the required partial initialization from a whole-record clear.
