# F-11bf454d01ce

## Purpose

F-11bf454d01ce copies four 32-bit storage elements from a source region to a destination region. Its distinguishing behavior is the order of transfer: element 0, then element 2, then element 1, then element 3.

For valid, nonoverlapping regions, the destination’s final four-element contents equal the source’s initial four-element contents. For overlapping regions, the transfer order matters: an earlier destination write can change the value obtained by a later source read.

This is an ordered sequence of individual transfers, not an established snapshot copy. It must not be specified as a general overlap-safe block move.

## Behavior

### Ordered transfers

At the source-level abstraction supplied for review, the function performs these transfers in order:

| Transfer | Source read | Subsequent destination write |
|---|---|---|
| First | Element 0, byte offset 0 | Element 0, byte offset 0 |
| Second | Element 2, byte offset 8 | Element 2, byte offset 8 |
| Third | Element 1, byte offset 4 | Element 1, byte offset 4 |
| Fourth | Element 3, byte offset 12 | Element 3, byte offset 12 |

Each write receives the value obtained by its corresponding read. That read precedes its write. Each complete transfer precedes the next transfer in the listed source-level sequence.

The evidence does not show all four source values being captured before any destination write. Consequently, the value transferred at a later step is the value available at that source location when the later read occurs, including changes caused by earlier writes when the regions overlap.

The offsets are fixed and fit within the 16-byte span. There is no element-value arithmetic, loop counter, variable transfer length, or caller-controlled size. No truncation, saturation, comparison, or explicit byte swapping appears.
