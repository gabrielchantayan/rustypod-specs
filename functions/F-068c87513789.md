- A dependency write to the slot can determine the returned value.

1. **Unchanged slot on zero status.** Given a third input of `0x12345678`, if the dependency returns zero without changing the first temporary word, the wrapper returns `0x12345678`. A fresh dependency-produced value is not required by the wrapper.

2. **Replacement slot on zero status.** Given the same third input, if the dependency writes `0x89ABCDEF` into the first temporary word and returns zero, the wrapper returns `0x89ABCDEF`. The high bit has no special wrapper-level meaning.

3. **Failure overrides a written result.** If the dependency writes `0x89ABCDEF` and returns status 1, the wrapper subsequently writes zero into the first temporary word and returns zero.

4. **All nonzero statuses take the same branch.** A status represented by `0xFFFFFFFF` also causes a zero return. The condition is nonzero, not positive.

5. **Successful zero is indistinguishable by return value.** If the dependency writes zero and returns zero, the wrapper returns zero. The same returned word arises when the dependency reports a nonzero status; the caller cannot distinguish those cases from this function’s result alone.

The second input occupies position 3, the third input occupies position 4, and positions 2 and 6 contain 2 and zero respectively.

7. **Invalid object access has no defined wrapper fallback.** If the field cannot be read, the supplied representation provides no path that converts that access failure into a normal zero result. The nonzero-status rule applies only after the dependency returns.
