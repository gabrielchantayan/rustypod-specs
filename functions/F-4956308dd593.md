# F-4956308dd593

## Purpose

F-4956308dd593 dispatches an event against a mutable object through three ordered stages:

- Initial handling selected by object flags and event type.
- Optional notification handling, using fields reread after initial callbacks.
- Fallback dispatch when earlier handling does not determine the result.

Every visible normal return is a 32-bit value of either 0 or 1. A return of 0 does not establish that no callbacks ran or that state remained unchanged.

**Established static evidence:** the supplied body determines the field accesses, conditional external-data reads, explicit byte writes, callback order, and return decisions described here.

**Inferred intent:** some fields appear to represent an index, a count, and deferred-action state. These labels aid description; they do not establish domain semantics.

**Unknown:** dependency implementations, external-data contents and preservation, exact callback prototypes, and payload layouts beyond the accessed fields.

## Behavior

### Initial selection and forwarding

The function reads the event type before reading object flags at `0x048`. Initial active mode is selected only when the flags masked by `0x1800` equal `0x0800`. Other masked values select alternate mode, including `0x1800`.

The initial handled result starts at zero.

In alternate mode, only type 15 receives initial processing. F-682adfd5a561 receives the event and selector `0x0D00`. If the extracted identity equals the first embedded member’s address, virtual slot `0x1BC` receives the object and 1. After that callback returns, the byte at `0x158` is cleared and the initial handled result becomes 1. Other identities leave it zero.

In active mode, ordinary forwarding is:

| Event type | Extraction selector | Virtual-table byte offset |
|---|---:|---:|
| 6, 7, 13 | `0x0A00` | `0x1B4` |
| 21 | `0x3500` | `0x1B8` |

Extraction precedes virtual-target selection. The method receives the object and extracted value; its result becomes the initial handled result. Nonzero results count as handled at the later initial-result decision.

Type 15 follows the member-specific rules below. Other event types have no initial action.

Successful initial handling does not immediately return. Notification eligibility is evaluated afterward.

### Active-mode type 15: first embedded member

F-682adfd5a561 receives the event and selector `0x0D00`. When the extracted identity equals object + `0x128`, bit 0 of the byte at `0x158` determines the argument to virtual slot `0x1BC`: 1 if set, otherwise 0.

After the callback returns, a 32-bit word beginning at `0x158` is read. Its low eight bits are decremented, and the eight-bit result is stored to the byte at `0x158`. This is not a decrement of a value saved before the callback. Callback mutations can change the resulting byte and branch.

A stored result of zero selects this ordered dependency chain:

- F-a66a9be680df produces a value.
- F-c5a232e4455b receives that value and the fixed immediate 12.
- F-4e95b66bff0e receives the preceding result, the fixed immediate 0, and the then-current word at `0x154`.
- F-8e50f265e4fa receives the object and the final chain result.

The `0x154` argument is therefore obtained after the preceding two calls, not captured before them.

A nonzero stored result instead calls F-ec4cfa552cce with the first embedded member’s address. Either outcome sets the initial handled result to 1.

At eight-bit result width, a low-byte value of zero decrements to `0xFF`, selecting the nonzero branch. The relationship between the low eight bits of the word read and the first addressed byte depends on target endianness; they must not be conflated without that prerequisite.

### Active-mode type 15: second embedded member

When the extracted identity instead equals object + `0x1AC`, F-fdd8589eca2d runs before F-bfa7e30ab583.

If F-bfa7e30ab583 returns zero, the target at virtual slot `0x1D8` is selected and receives the object plus the value read from the external second-member argument location. That external read occurs after the status query returns zero; it is absent on the nonzero branch.

Neither branch sets the initial handled result. Consequently, this processing can perform side effects and still finish with result 0. An identity matching neither embedded member causes no further initial action.

### Notification eligibility

After initial dispatch, the function rereads flags at `0x048`. If bit `0x20000000` is clear, notification-specific event reads are skipped.

If that bit is set, the event type is reread. Only type 19 proceeds to compare the event identity at `0x0C` with object field `0x044`.

Thus initial callbacks can affect notification eligibility. Neither the initial flags nor initial event type serves as a function-wide snapshot.

For an eligible notification, the event code and external notification-base value are read, and their 32-bit signed-integer difference is retained as the **delta**. This base read occurs before any delta branch. The retained delta is not recomputed after subsequent callbacks.

### Delta zero: count and index reconciliation

F-5710a8628cba receives the current word at `0x038`. Its 32-bit result is retained as the count-like value.

A final-refresh condition initially starts enabled. The function then reads flags at `0x124`:

- If bit `0x2` is set, virtual slot `0x188` is invoked.
- If that callback returns nonzero, final refresh is disabled and field `0x104` is **not read**.
- Otherwise, including when the optional callback is skipped, field `0x104` is read and compared with the retained count. Equality disables final refresh.

When the optional callback runs and returns zero, the `0x104` read occurs after it. Its mutations can therefore affect the comparison.

F-b3f4a7a52609 next receives the object and supplies a bound-like result. If the retained count is nonzero and is less than or equal to that bound under signed comparison, index processing occurs:

- If the signed word at `0x100` is less than the count, virtual slot `0x190` receives the object and count minus one. Slot `0x174` subsequently receives the same count-minus-one value.
- Otherwise, slot `0x190` receives the object, the current word at `0x100`, and an additional 1. After this call, `0x100` is reread; slot `0x174` receives that reread value.

The differing visible argument counts for slot `0x190` are retained as evidence, not reconciled into an invented prototype.

Slot `0x16C` then receives the object and retained count, regardless of whether index processing occurred. If final refresh remains enabled, slot `0x174` receives the then-current word at `0x100`.

F-92bea7c30bd6 runs next, followed by F-e6019f8ee60b. The function returns 1.

Zero count skips index processing but not these subsequent operations. Negative counts are not explicitly rejected; signed comparisons govern eligibility. Arithmetic overflow at count minus one is unresolved.

### Other notification deltas

An eligible notification matching none of these cases proceeds directly to fallback, bypassing the initial handled-result decision.

### Initial-result decision

When notification processing is ineligible, a nonzero initial handled result returns 1. Zero proceeds to fallback.

### Fallback dispatch

The visible fallback behavior is associated with F-147f81afa77f.

Fallback rereads event type and returns 0 unless it is 19. For type 19, it reads and saves the event identity.

If that identity equals object field `0x044`, fallback reads the event code and then object code `0x040`:

- Equality accepts the primary match without reading the external primary fallback code.
- Inequality causes the external primary fallback code to be read. Equality with that value accepts the primary match.

A primary match invokes virtual slot `0x0D4` with the object and returns 1.

Only without an accepted primary match is secondary matching considered. Object field `0x09C` is read first. If zero, fallback returns 0 without reading secondary identity `0x098` or the external secondary code.

When enabled, the saved event identity is compared with `0x098`. A mismatch skips both the secondary event-code read and external secondary-code read. A match causes the event code to be read, followed by the external secondary code.

If those codes match, F-5710a8628cba is called with no explicit arguments visible. One byte of its result is passed to virtual slot `0x0A0` with the object, and fallback returns 1. Otherwise it returns 0.

Primary acceptance takes precedence over secondary matching.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Mask boundary:** Flags masked to `0x1800` select alternate mode, not active mode. With unchanged type 6, no initial forwarding occurs and fallback returns 0.

2. **Ordinary forwarding:** In active mode, type 6 extracts with selector `0x0A00` and calls slot `0x1B4`. If subsequent eligibility remains false, a nonzero callback result returns 1; zero reaches fallback and returns 0 for unchanged type 6.

3. **Post-callback decrement:** For the active first member, if the word read after slot `0x1BC` has low eight bits equal to 1, the stored result is zero and the four-call chain runs. Low eight bits equal to zero instead produce `0xFF` and call F-ec4cfa552cce.

4. **Second-member external read:** A nonzero status result calls F-ec4cfa552cce without reading the external second-member argument. A zero result reads that value after the query and supplies it to slot `0x1D8`. With unchanged type 15, either path ultimately returns 0.

5. **Short-circuit recorded-count access:** On delta zero, bit `0x2` set and a nonzero slot-`0x188` result disable final refresh without accessing `0x104`. If that callback returns zero, the comparison uses `0x104` as read afterward.

6. **Zero count:** A retained count of zero skips slot `0x190` and its associated immediate slot-`0x174` call. Slot `0x16C`, any enabled final refresh, and both finishing dependencies still run; the result is 1.

7. **Index mutation:** In the non-less-than index branch, if slot `0x190` changes `0x100`, the following slot `0x174` receives the changed value.

8. **Conditional adjustment load:** Delta zero or `0x7F6` does not read the external adjustment. Other deltas do, and an addition result of zero calls F-92bea7c30bd6 without F-e6019f8ee60b.

9. **Primary object-code match:** Matching primary identity and object code invokes slot `0x0D4` without reading the external primary code or considering secondary matching.

10. **Secondary read gates:** Without primary acceptance, a zero secondary enable skips the secondary identity and external code. Enabled secondary matching with unequal identity also skips the secondary event-code and external-code reads.
