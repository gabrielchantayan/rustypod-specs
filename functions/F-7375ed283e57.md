# F-7375ed283e57

## Purpose

The visible fragment performs an ordered sequence of two 32-bit memory writes, four selector-byte reads, four byte writes, and thirty-six indirect calls. Entry-state values and selected call results determine addresses, stored values, and later call arguments.

No application-level purpose is established. The affected memory is not demonstrably an array, device register bank, serialized message, or owned object. Repeated byte extraction suggests a possible encoding operation, but that interpretation is not part of the established behavior.

The supplied representation ends at a bad-instruction boundary. It shows neither a normal return nor an explicit return value. Actual behavior at or beyond that boundary is documented_only.

### Stage 1: word writes and acquisition of the first data word

The first visible operation writes the input value as a 32-bit word at the numeric address:

\[
4 \times \text{input value} + 20
\]

This is followed by the following ordered calls and access:

1. **F-D001** receives the input value and four times the input value.
2. **F-D002** is invoked with no explicit arguments shown. Its 32-bit result is retained.
3. **F-D003** receives that result and the entry word logically shifted right by three.
4. **F-D004**, **F-D005**, and **F-D006** are invoked, in that order, with no explicit arguments shown.
5. **F-D007** is invoked with no explicit arguments shown. Its result is interpreted as a signed 32-bit word.
6. The entry word is written as a 32-bit word at four times the F-D007 result, plus 20.
7. **F-D008** receives four times the F-D007 result.
8. **F-D009**, **F-D010**, and **F-D011** are invoked, in that order, with no explicit arguments shown.
9. **F-D012** is invoked with no explicit arguments shown. Its unsigned 32-bit result becomes the **first data word**.

The first word write precedes every call. The second word write follows F-D007 and precedes F-D008. Neither destination is explicitly read before its word write.

The multiplications involving the signed input and signed F-D007 result retain the arithmetic uncertainty described under Interface.

### Stage 2: first byte write

An **entry-derived selector address** is calculated as:

\[
\text{entry word} \times 2^{19} + 1
\]

Under a 32-bit modular interpretation, only the low 13 bits of the entry word contribute to the product. The representation subsequently uses this calculated address for the first three selector reads.

The fragment then:

1. Reads an unsigned byte from the entry-derived selector address.
2. Writes **low8(first data word × 4)** to the numeric address equal to that selector plus 17.
3. Invokes **F-D013** with the first data word shifted left by two at unsigned word width.
4. Invokes **F-D014** with no explicit arguments shown and retains its 32-bit result.
5. Invokes **F-D015** with that result.
6. Invokes **F-D016**, **F-D017**, and **F-D018**, in order, with no explicit arguments shown.
7. Invokes **F-D019** with no explicit arguments shown and retains its signed 32-bit result.

The selector read precedes the corresponding store. The selector is an unsigned numeric value, not a pointer loaded from a pointer-sized field.

### Stage 3: second byte write and acquisition of the second data word

The fragment reads another unsigned byte from the same entry-derived selector address. It does not reuse the first selector.

It writes to the newly selected address, again selector plus 17. The stored byte is **bits 20–27 of the first data word**.

The visible value calculation first clears bits 30 and 31, then shifts right by 20, then narrows to a byte. The shifted intermediate can contain ten bits; the byte write retains only its low eight bits. Consequently, bits 28 and 29 do not affect the stored byte.

After this write:

1. **F-D020** receives the F-D019 result shifted left by two.
2. **F-D021**, **F-D022**, and **F-D023** are invoked, in order, with no explicit arguments shown.
3. **F-D024** is invoked with no explicit arguments shown. Its unsigned 32-bit result becomes the **second data word**.

The F-D020 argument involves a signed left shift. Its exact behavior for negative or overflowing operands remains documented_only.

Intervening calls or overlapping memory accesses may cause the second selector to differ from the first.

### Stage 4: third byte write and selector forwarding

The fragment reads an unsigned byte a third time from the entry-derived selector address and retains this selector.

It then writes **low8(second data word × 4)** to selector plus 17.

This store’s expression includes a byte-sized conversion before multiplication. Under the intended low-eight-bit narrowing interpretation, its stored bit pattern is the low eight bits of four times the second data word. It is not the unmodified low byte of that word.

After the store:

1. **F-D025** receives the retained third selector, zero-extended to an unsigned word.
2. **F-D026** is invoked with no explicit arguments shown and retains a 32-bit result.
3. **F-D027** receives that result.
4. **F-D028**, **F-D029**, and **F-D030** are invoked, in order, with no explicit arguments shown.
5. **F-D031** is invoked with no explicit arguments shown and retains a signed 32-bit result.

F-D025 receives the selector itself—not the destination address, stored byte, or second data word. The value is retained from the read preceding the store; no additional selector read is shown for this call.

### Stage 5: fourth byte write and terminal calls

The fourth selector address is calculated differently:

\[
\text{second data word} \times 8 + 1
\]

Under 32-bit modular arithmetic, only the low 29 bits of the second data word contribute to the product.

The fragment then:

1. Reads an unsigned byte from this fourth selector address.
2. Writes **bits 20–27 of the second data word** to the address equal to that selector plus 17.
3. Invokes **F-D032** with the F-D031 result shifted left by two.
4. Invokes **F-D033**, **F-D034**, **F-D035**, and **F-D036**, in that order, with no explicit arguments shown.
5. Reaches the represented bad-instruction boundary.

The F-D032 argument has the same unresolved signed-shift issues as F-D020.

The fourth selector address depends on the second data word, not the entry word. It may equal an earlier selector address, but equality is not required.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume compatible arithmetic and narrowing, valid mappings, returning callees, and no interfering changes except those stated.

1. **Initial word destination.** With input value 3, the first operation writes the 32-bit value 3 at numeric address 32. F-D001 subsequently receives 3 and 12.

2. **Logical shift.** With entry word \(0x80000000\), F-D003 receives \(0x10000000\) as its second argument. A sign-extending right shift would not match the unsigned operation.

3. **Multiplied-byte and extracted-byte values.** For first data word \(0x12345678\), the first byte write stores \(0xe0\), not \(0x78\). The second byte write stores \(0x23\). F-D013 receives \(0x48d159e0\).

4. **Selector re-reading.** If the first two selector reads return 5 and 9, their respective byte destinations are 22 and 26. Reusing the first selector would not match the visible second read.

5. **Retained selector argument.** If the third selector is 250, the third byte write targets address 267 and F-D025 receives 250. Even if that store aliases the selector source, F-D025 uses the retained value.

6. **Fourth-selector source.** If the second data word is 3, the fourth selector is read at address 25. If that read returns 7, the fourth byte write targets address 24 and stores zero.

7. **Repeated destination with distinct stored values.** If all four selector reads return 7, all four byte writes target address 24. Their order is exactly:
   - low8(first data word × 4);
   - bits 20–27 of the first data word;
   - low8(second data word × 4);
   - bits 20–27 of the second data word.

   For first data word \(0x12345678\) and second data word \(0xabcdef01\), the ordered bytes are \(0xe0\), \(0x23\), \(0x04\), and \(0xbc\). The first and third are multiplied-byte values, not the words’ unmodified low bytes.

8. **Unsigned selector boundary.** A selector byte \(0xff\) selects address 272, not an address derived from signed value −1.

9. **Interrupted execution.** If F-D019 does not return to its continuation, the second selector read and all subsequent events do not occur along that continuation. No recovery behavior is shown.
