# F-887200f76f20

## Purpose

F-887200f76f20 reads a variable-length byte sequence and writes a 32-bit result through a caller-supplied destination. It handles four short-form cases directly and delegates a remaining case to F-174052de586c.

The direct cases select lengths of two, three, four, or five bytes. Selection depends on the high bit of successive bytes starting at offset one, not offset zero. A direct return value identifies the selected length.

**Inferred intent:** the routine appears to decode an integer represented by ordered seven-bit groups, with an exceptional path for longer or otherwise special representations. This interpretation is not a complete established encoding specification. In particular:

- The first byte’s high bit does not determine the selected length.
- An unavailable 32-bit mask affects the three- and four-byte results.
- The delegated case has no available behavioral contract.
- No validation of canonical or shortest-form encoding is visible.

## Interface

The function has four inputs and a four-byte return value:

| Input | Established role |
|---|---|
| Input address | Address of bytes inspected by the direct paths and passed unchanged to F-174052de586c on delegation. |
| Result address | Address at which the function stores one 32-bit result. |
| Initial word | A 32-bit value copied into temporary storage only on the delegated path. |
| Auxiliary word | A four-byte value copied into separate temporary storage only on the delegated path. Its semantic type is unknown. |

The result destination is an output location. Its prior contents do not contribute to a direct result.

For describing the byte layout, let **B₀** denote the byte at the input address, **B₁** the byte at offset one, and so on. Each byte has a value from 0 through 255. “High bit” means bit 7, with mask 0x80.

Let **M** denote the unavailable 32-bit mask used in the three- and four-byte calculations. Its numeric value is not supplied. It must not be replaced with a presumed seven-bit-group mask when specifying unconditional behavior.

All shifts and combinations below operate on unsigned 32-bit values. Left shifts discard bits beyond bit 31. “OR” and “AND” mean bitwise operations.

### Caller obligations

For a direct execution with stable input:

- The input must allow the reads required by the selected path.
- The result address must allow a 32-bit store.
- Required alignment and address validity follow the execution platform; the supplied material does not define them.
- The input bytes and the mask must remain stable during evaluation if the deterministic formulas below are to apply.

There is no input-length argument and no visible bounds check. A caller cannot rely on the routine to reject truncated storage safely.

The fallback path may impose additional requirements through F-174052de586c. Those requirements are **documented_only** because the dependency’s implementation and contract are unavailable.

## Behavior

### Selection and read progression

The function first obtains the byte at offset one. It then tests that byte’s high bit.

1. If B₁ has its high bit clear, select the two-byte case.
2. Otherwise, obtain the byte at offset two and the first byte as part of an intermediate calculation. If B₂ has its high bit clear, select the three-byte case.
3. Otherwise, obtain B₃. If B₃ has its high bit clear, select the four-byte case.
4. Otherwise, inspect B₄. If B₄ has its high bit clear, select the five-byte case.
5. Otherwise, use the delegated case.

For stable input, the selection conditions are:

| Case | Required high-bit conditions | Return on direct completion |
|---|---|---:|
| Two-byte | B₁ clear | 2 |
| Three-byte | B₁ set; B₂ clear | 3 |
| Four-byte | B₁ and B₂ set; B₃ clear | 4 |
| Five-byte | B₁, B₂, and B₃ set; B₄ clear | 5 |
| Delegated | B₁ through B₄ all set | Dependency’s return value |

B₀’s high bit is not inspected for branch selection.

These are source-level dependencies, not a guarantee of one physical memory transaction per listed byte. The supplied representation includes repeated expressions reading B₁, B₂, and B₄. It does not establish how many machine loads occur or the ordering of operands within a single expression. Volatile, device-backed, or concurrently changing input therefore has no fully established access contract.

### Two-byte result

The written result consists of:

- B₁ in bits 0–6.
- The low seven bits of B₀ in bits 7–13.
- Zero in bits 14–31.

Equivalently, the result is B₁ OR the low seven bits of B₀ shifted left by seven.

Because this case requires B₁’s high bit to be clear, no extra masking of B₁ is needed. B₀’s high bit is discarded.

The function writes this result and returns 2. It does not consult bytes at offsets two or later on this path.

### Three-byte result

The result is the bitwise OR of:

- **M AND (B₂ OR (B₀ shifted left by 14))**.
- **The low seven bits of B₁ shifted left by seven**.

This formula is authoritative even when M is not known. The available evidence does not justify reducing it to an ordinary three-group base-128 value.

In particular, M determines which bits originating in B₀ and B₂ survive. The low seven bits of B₁ contribute independently of M. A selected bit in either contribution remains set in the final result.

The function writes the resulting 32-bit word and returns 3. Bytes at offsets three and later are not required by the visible direct path.

### Four-byte result

The result is the bitwise OR of:

- **M AND (B₃ OR (B₁ shifted left by 14))**.
- **(M AND (B₂ OR (B₀ shifted left by 14))) shifted left by seven**.

The second contribution is truncated to 32 bits after shifting. Both uses of M refer to the unresolved mask source. These expressions use one symbol under the stable-mask assumption; they do not establish a single machine read.

The mask controls more than a final cleanup step: it is applied separately before the two contributions are combined. Consequently, replacing this behavior with an assumed conventional 28-bit decoder is not justified without establishing M.

The function writes the result and returns 4.

### Five-byte result

The five-byte path does not use M. Its fixed masks and shifts simplify to the following nonoverlapping layout:

| Result bits | Origin |
|---|---|
| 0–6 | B₄ bits 0–6 |
| 7–13 | B₃ bits 0–6 |
| 14–20 | B₂ bits 0–6 |
| 21–27 | B₁ bits 0–6 |
| 28–31 | B₀ bits 0–3 |

B₄’s high bit is already known to be clear. The continuation bits of B₁, B₂, and B₃ are discarded.

Only the low four bits of B₀ survive. Bits 4–7 of B₀ do not affect this result. This is a 32-bit truncating representation, not a checked conversion of five unrestricted seven-bit groups. No overflow error or canonicality rejection is visible.

The function writes the result and returns 5.

### Delegated result

When B₁ through B₄ all have their high bits set:

1. The initial word is copied into a temporary 32-bit location.
2. The auxiliary word is copied into a separate four-byte temporary.
3. F-174052de586c is called with the original input address and the address of the first temporary.
4. If the dependency returns normally, the first temporary’s current 32-bit value is written to the caller’s result address.
5. The dependency’s four-byte return value is returned unchanged.

The dependency receives neither the caller’s result address nor the third and fourth arguments as separately visible call arguments.

The second temporary’s placement suggests possible participation in a wider local state layout, but the supplied material does not independently establish that layout or prove that the dependency accesses it. The auxiliary word’s effect is therefore unresolved.

If the dependency leaves the first temporary unchanged and otherwise completes normally, the outer function writes the original initial word. This is a conditional consequence, not a claim that the dependency preserves the temporary.

There is no visible interpretation of the dependency’s return value. In particular, the outer function does not visibly distinguish success from failure before copying the temporary to the result destination.

## Side effects

### Direct paths

The visible direct behavior consists of input reads, mask-dependent computation where applicable, and one 32-bit result store.

There is no visible direct-path:

- Input-buffer write.
- Allocation or release.
- Ownership transfer.
- Error-status output.
- Validation of representation minimality.
- Use of the initial or auxiliary word.

The result store occurs after the input values needed for that direct calculation have been obtained. No additional input read is visible after that store.

Input/result overlap is not explicitly checked. If the destination overlaps the input, the store can modify input storage. Whether such overlap is valid depends on the memory model, alignment, and underlying object representation; it is not established as a supported interface guarantee.

### Delegated path

The function initializes temporary storage, invokes the dependency, and then performs the result store if control returns normally.

The dependency’s other side effects are unknown. It must not be assumed to preserve global state, preserve input bytes, refrain from allocation, or respect any particular ownership discipline.

The outer function visibly performs no allocation or release itself. That observation does not establish the absence of such actions inside the dependency.

### Errors and abnormal execution

No explicit error handling is visible in the outer function.

Invalid addresses, insufficient readable input, an invalid result destination, or a dependency failure are not converted into a defined outer error result by the supplied behavior. If the dependency does not return normally, the final result store and normal return are not established to occur.
