# F-21fb6ce03494

## Purpose

F-21fb6ce03494 repeatedly performs indirect calls, reads and writes memory at computed addresses, and executes a software breakpoint. The supplied static representation contains no normal return, exit condition, explicit validation, or error result.

Its established behavior is a sequence of state transfers involving 8-bit, 16-bit, 32-bit, and paired 64-bit values. An application-level purpose—such as initialization, device servicing, or record processing—is not established.

An iteration reaches its end only if all preceding dependencies return, all memory accesses succeed, and execution resumes after the breakpoint. The contract below describes that conditional execution, not a guarantee of progress. No runtime tests have been performed.

- Byte: 8 bits.
- Halfword: 16 bits.
- Word: 32 bits.
- Paired result: 64 bits, divided numerically into low and high 32-bit portions.

Explicitly unsigned halfword reads are zero-extended. Halfword stores retain the low 16 bits of their source; byte stores retain one byte. Numerical extraction of a paired result does not establish its layout in memory. Endianness is unknown.

Offsets and constants below are hexadecimal unless stated otherwise. The two decimal offsets appearing in the supplied representation correspond to `0x320` and `0x258`; the target-record offset expressed there as decimal 100 is `0x64`.

## Behavior

### Ordering and retained values

Each iteration follows the phases below. F-D01 through F-D37 are opaque call-site identifiers defined under **Dependencies**. Separate identifiers do not necessarily mean different target addresses.

The sequence of calls and memory accesses is significant. Dependencies may change globals or pointed-to storage before later reads. A value captured by an earlier read is nevertheless the value used by subsequent operations that reference that capture in the supplied representation. This describes visible dataflow, not an independently established register-preservation convention.

No dependency is assumed to preserve globals, preserve referenced memory, allocate storage, or release storage.

### Opening calls and early byte fields

The iteration establishes a zero byte and invokes F-D01 with two explicit zero arguments. Its target is computed from the current link context plus `0xFFE`. A second zero byte is established before F-D02 and F-D03 execute, in that order.

Global slot A is then read as a word. Its value becomes the **early record base**, retained across subsequent calls. F-D04 executes, followed by F-D05, which supplies paired result A.

F-D06 receives two word arguments: A’s low word, followed by the sum of A’s high word, A’s low word, and the established zero byte. The latter byte contributes zero; the signed-sum overflow boundary remains unresolved. F-D05 and F-D06 have the same numerical call target despite their different visible argument and result uses.

The byte-valued secondary output associated with F-D06 is stored at early record base + `0x11`. F-D07 then executes, after which zero is stored at early record base + `0x15`.

Neither store rereads Global slot A. A dependency changing that global does not, by itself, replace the captured base.

### Halfword output and retained paired result B

F-D08 supplies a halfword result and an associated secondary address output. The halfword is stored at that address + `0x0C`.

F-D09 then supplies paired result B. Zero is stored as a halfword at B-high + `0x2C`. B-low, interpreted as an unsigned word and logically shifted right by 26 bits, is stored at context base + `0x26C`. This stored value is between 0 and 63.

The unsigned constant `0x21C48960` is established before F-D10 executes. A word is subsequently read from context base + `0x320`, becoming the **shifted-value destination base**. F-D11 and F-D12 execute before B-low, shifted left by two bits as an unsigned word, is stored at that base + `0x54`. This shift retains the low 32 bits.

The shifted value comes from the earlier F-D09 result. It is not replaced by a fresh result from an intervening call.

### Constant-address input and breakpoint

F-D13, F-D14, F-D15, F-D16, and F-D17 execute in that order. F-D13 shares F-D09’s numerical target address, but the earlier paired result B remains the captured value described above.

An unsigned halfword is then read at `0x21C48994`, the sum of `0x21C48960` and `0x34`. Its zero-extended value becomes the **small record base**.

After F-D18, a word read from context base + `0x280` is passed to F-D19. A software breakpoint with immediate value `0x92` follows that call.

No later operation is reached unless execution resumes after the breakpoint. Resumption and any handler effects are not established.

After resumption, the F-D19 result is shifted left by two bits to form the **table displacement**. This is a signed-shift expression whose extreme-value behavior remains unresolved.

The constant `0x21C48960`, logically shifted right by 18 bits and multiplied by four, produces `0x21C4`. A word read from small record base + `0x44` then supplies the **target record base**.

The small record base really originates from a 16-bit unsigned read. There is no intervening wider pointer load or validation before it is used as an address base.

### Forwarded arguments and table-related halfword stores

F-D20 executes, followed by F-D21. The word result from F-D21 is forwarded as the first argument to F-D22. The second argument is a word read from small record base + `0x04`, after F-D21 and before F-D22.

Global slot B is then read as a word and retained as the **table base**. F-D23 executes before a halfword store at table base + table displacement. The stored value is the low 16 bits of the table base, not the displacement.

F-D24 follows that store. A word read at `0x2218` supplies the **later record base**. This address is `0x21C4 + 0x54`; it is not relative to the original constant `0x21C48960`.

F-D25 then supplies an address-like result. The halfword `0x21C4` is stored at that result + `0x04`.

### New halfword inputs and context adjustment

F-D26 and F-D27 execute before an unsigned halfword is read at later record base + `0x34`. Its zero-extended value is the **small index**.

F-D28 supplies paired result C. C-low is stored as a word at context base + `0x258`. An unsigned halfword is then read at C-high + `0x14`, producing the zero-extended **small value**.

Two retained address-forming quantities are derived: C-low shifted left by six bits, and C-high multiplied by four. Both originate from signed 32-bit expressions; their overflow boundaries are unresolved.

The context base is decreased by `0xF4`. Small index is multiplied by four, and C-low is stored as a word at that product + `0x74`.

The context-relative store at `0x258` therefore uses the base before the decrease. The small-index store does not use the context base at all.

Because small index is zero-extended from 16 bits, its fourfold product is between 0 and `0x3FFFC`. The resulting store address is numerically between `0x74` and `0x40070`. No bounds or mapping check precedes the store.

### Target-record updates and byte transfer

F-D29 executes before small value is stored as a word at target record base + `0x54`. F-D30 intervenes before the same zero-extended value is stored as a word at target record base + `0x64`.

These are separate stores, not an atomic pair. An intervening dependency may observe or modify memory between them.

F-D31 then executes. The low 16 bits of target record base are stored at the address formed by adding the retained C-low-left-shifted-by-six quantity to F-D31’s secondary address output.

F-D32 and F-D33 execute before a byte is read at small index plus four times small index: numerically five times small index. This byte address is between 0 and `0x4FFFB`; it has no implicit table or record base.

F-D34 executes between that read and the corresponding byte store. The captured byte is stored at small value + auxiliary base + `0x19`. A change to the source memory during F-D34 does not, by itself, change the captured byte used by this store.

### Final update and repetition

After F-D35, the retained fourfold C-high quantity is stored as a word at target record base + `0x44`. F-D36 then executes.

The link context is assigned the fixed value `0x08712031`. A word is read at four times C-high + `0x44` and passed to F-D37. If that call returns, the next iteration begins unconditionally.

The final store and final read do not necessarily address the same location: their bases are target record base and four times C-high, respectively.

No visible operation restores the context base before repetition. In the represented state, each reached adjustment decreases it by another `0xF4`. The replacement link context makes the next F-D01 target numerically `0x0871302F`. Whether the register-like state accurately represents persistent machine execution remains documented_only.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes the relevant operation is reached, required accesses succeed, and intervening effects satisfy the stated conditions.

1. **Unsigned extraction and truncation.** If B-low is `0xFC000003`, the context store at `0x26C` receives `63`. The later shifted-value store receives `0xF000000C`.

2. **Captured early base.** If Global slot A supplies address A and F-D06 supplies secondary byte `0xA5`, the body stores `0xA5` at A + `0x11`, calls F-D07, and stores zero at A + `0x15`. Changing Global slot A alone does not replace A.

3. **Shared target, different interaction.** F-D05 and F-D06 must resolve to the same numerical target. Acceptance does not require equal results or effects: the second invocation has explicit arguments and consumes a secondary output differently.

4. **Table-value truncation.** If table base is `0x12345678` and table displacement is 12, the halfword at table base + 12 receives `0x5678`.

5. **Small-index addresses.** If small index is 3, the C-low word store uses numerical address `0x80`, and the later source-byte read uses numerical address 15. Neither address implicitly includes another base.

6. **Unsigned expansion.** If small value is `0xFFFF`, both target-record stores at `0x54` and `0x64` write `0x0000FFFF`, not a sign-extended word.

7. **Captured byte.** If the source-byte read obtains `0x7E`, a subsequent source-memory change by F-D34 does not itself alter the captured `0x7E` used for the destination store.

8. **Breakpoint interruption.** If execution does not resume after the breakpoint, later scaling, accesses, and repetition are not reached. Earlier effects are not undone.

9. **Distinct final addresses.** If target record base differs from four times C-high, the final store and final argument read use different addresses despite sharing offset `0x44`.
