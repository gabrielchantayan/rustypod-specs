# F-2d9f61cfe608

## Purpose

F-2d9f61cfe608 performs an ordered search over an indexed collection associated with a context object. For each visited index, it obtains an object, asks that object for a type discriminator, and conditionally obtains a 32-bit comparison value. It compares that value with the caller’s search key and returns the first matching object, while writing its index to an output location.

This description requires an important qualification: **not every path establishes a comparison value**. Some object types and selector values reach the comparison using a value retained from an earlier iteration or an unspecified incoming value. The function does not visibly reject these paths or skip their comparisons.

The likely intent is a selector-based object-property search. That intent does not establish reliable behavior for paths that leave the comparison value unassigned.

## Interface

The interface has four inputs and one pointer-valued return:

| Input | Interpretation |
|---|---|
| Context address | Address of an object containing a collection reference at byte offset `0x1E0`. |
| Search key | Unsigned 32-bit value compared for exact equality with the current comparison value. |
| Selector | Signed 32-bit value controlling which property or method supplies the comparison value. |
| Index-output address | Address of a writable signed 32-bit integer. |

The return is either:

- The object address obtained by the **first collection lookup at the matching index**; or
- A null pointer if the captured collection bound is exhausted without a match.

On the normal no-match path, the index output remains `-1`, provided no intervening dependency or aliasing effect changes that location. On a matching path, the function writes the matching zero-based index immediately before returning.

### Width and representation model

The supplied representation uses 32-bit signed integers, 32-bit unsigned integers, and address-like values stored in 32-bit fields. The layouts and arithmetic below describe that apparent 32-bit model. A separately verified ABI, pointer width, alignment rule, and byte order are not available.

The search-key comparison uses all 32 bits. Only the values obtained through two particular virtual methods are explicitly narrowed to 16 bits.

The selector is not range-checked at entry. Negative selectors and selectors greater than 10 can reach the comparison without assigning a new comparison value.

### Preconditions for defined, usable execution

The function performs no visible validation of its address inputs or traversed pointers. Successful execution therefore depends on:

- A writable index-output location.
- A readable context collection-reference field.
- Readable collection metadata and count storage.
- Valid object addresses returned by collection lookups.
- Readable dispatch tables and callable entries on paths that invoke methods.
- Readable property storage on paths that access fields directly.

The index output is written before the context is read. Consequently, aliases between that output location and subsequently read state can change the search itself.

## Behavior

### Initialization and collection bound

The function first writes the signed 32-bit value `-1` to the index-output address.

It then performs these reads in order:

1. Reads an address-sized collection reference from the context at byte offset `0x1E0`.
2. Reads a metadata reference from that collection at byte offset `0x04`.
3. Reads a signed 32-bit count from the metadata at byte offset `0x04`.

The collection reference and count are captured for this invocation. They are not visibly reloaded on later iterations.

Search begins at index zero. Before each iteration, the function compares the signed count with the signed current index. If the count is less than or equal to the index, it returns null.

Thus, a zero or negative count produces a null result without any collection lookup or object-method call. The initialization write and metadata reads still occur.

For a positive signed 32-bit count, the ordinary loop does not require signed index overflow: the final visited index is one less than the count, and the next boundary check terminates the search.

### First lookup and type query

For each visited index:

1. F-71f95996d3e8 is called with the captured collection reference and current index.
2. The returned object address is retained as the potential return value.
3. The function reads that object’s dispatch-table reference.
4. It invokes the entry at dispatch-table byte offset `0x10`, supplying the object address.
5. The method result determines the property-selection path.

Only discriminator values `0x14` and `0x16` have explicit property-selection behavior. Every other discriminator still proceeds to the equality comparison, without a new comparison-value assignment on that iteration.

There is no visible null check between the first lookup and the dispatch-table access.

### Discriminator `0x14`

For discriminator `0x14`:

- Selector 3 invokes the first object’s dispatch-table entry at byte offset `0x54`.
- Selector 8 invokes the same entry.
- Both invocations visibly receive the first object address.
- The full 32-bit result becomes the comparison value.

Every other selector leaves the comparison value unchanged and proceeds to comparison.

There is no second collection lookup on this discriminator path.

### Discriminator `0x16`

For discriminator `0x16`, the function calls F-71f95996d3e8 **again**, using the same captured collection reference and index.

The second returned object supplies the selected property or method. It is not necessarily identical to the first returned object: lookup stability is not established. The function does not query the second object’s discriminator before using it.

The selection behavior is:

| Selector | Comparison-value source from the second object |
|---|---|
| 0 | Full 32-bit result of dispatch-table entry at byte offset `0x5C`, invoked with the second object address. |
| 1 | Unsigned 32-bit field at property-block byte offset `0x10`. |
| 2 | Unsigned 32-bit field at property-block byte offset `0x2C`. |
| 3 | Unsigned 32-bit field at property-block byte offset `0x18`. |
| 4 | Unsigned 32-bit field at property-block byte offset `0x1C`. |
| 5 | Unsigned 32-bit field at property-block byte offset `0x20`. |
| 6 | No new assignment. |
| 7 | Unsigned 32-bit field at property-block byte offset `0x28`. |
| 8 | Full 32-bit result of dispatch-table entry at byte offset `0x54`, invoked with the second object address. |
| 9 | Low 16 bits of the result from dispatch-table entry at byte offset `0x34`. |
| 10 | Low 16 bits of the result from dispatch-table entry at byte offset `0x30`. |
| Any other value | No new assignment. |

For the direct field accesses, the property-block reference is read from the second object at byte offset `0x10`. The indicated unsigned 32-bit field is then read from that block.

For selectors 9 and 10, the supplied call representation shows no explicit arguments. It does not establish a receiver argument or any hidden calling-convention inputs. Their returned values are masked with `0xFFFF`, yielding comparison values from 0 through 65,535.

The second lookup occurs even for selector 6 or an out-of-range selector, although those paths do not assign a comparison value.

### Comparison and result

After the type-specific processing, the function compares the search key with the current 32-bit comparison value.

On equality:

1. It writes the current signed index to the index-output address.
2. It returns the object from the **first** lookup at that index.
3. It performs no further collection iteration.

On inequality, it increments the index by one and repeats the boundary check.

The function therefore selects the earliest matching index under its observed comparison state. For discriminator `0x16`, the returned object can differ from the object whose property was used for the match.

### Unassigned comparison paths

The comparison value is not visibly initialized at function entry. The following paths do not assign it:

- A discriminator other than `0x14` or `0x16`.
- Discriminator `0x14` with a selector other than 3 or 8.
- Discriminator `0x16` with selector 6.
- Discriminator `0x16` with a selector outside 0 through 10.

In the supplied representation, such a path retains the previous comparison value if an earlier iteration assigned one. If no earlier assignment occurred, the comparison depends on an unspecified incoming value.

No deterministic initial default, such as zero, may be substituted. These paths must not be described as automatic non-matches.

## Side effects

The function itself visibly writes only the index output:

- `-1` before reading the context.
- The matching index immediately before a successful return.

It does not visibly write collection fields, object fields, or property fields. It performs no explicit allocation, deallocation, reference-count adjustment, or ownership transfer.

Those observations do **not** establish that dependencies are side-effect-free. The collection lookup and virtual methods may mutate shared state, alter collection contents, affect object lifetimes, or write memory that aliases the index output. Their contracts are unavailable.

The captured collection reference and count remain in use after such calls. A dependency that changes the collection or invalidates an object can therefore affect later accesses without causing the function to reload its bound.

No explicit exception handling, error-code translation, or recovery path is present. Invalid addresses and failing indirect calls have no defined local recovery behavior in the supplied evidence.

The return value is an object address obtained from a dependency, not a copy. Its ownership, lifetime, and release obligations are undocumented. The absence of a release operation inside this function does not establish whether either lookup acquires ownership.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume valid memory, normal dependency returns, and no dependency or aliasing effects that interfere with the described state.

1. **Empty or negative bound.**  
   For a captured count of zero or a negative signed value, the function writes `-1`, reads the collection metadata, and returns null. It makes no collection lookup.

2. **First-index method match.**  
   Suppose index zero yields discriminator `0x14`, the selector is 3, and the method at `0x54` returns the search key. The function writes index zero and returns the first lookup’s object. It makes no second lookup.

3. **Second lookup supplies the match.**  
   Suppose the first lookup at index two yields object A with discriminator `0x16`, while the second lookup yields object B. With selector 2, the function reads B’s property-block field at `0x2C`. If that value equals the key, it writes 2 and returns A, not B.

4. **Low-16-bit comparison.**  
   With discriminator `0x16` and selector 9, a method result of `0xABCD1234` produces comparison value `0x00001234`. Key `0x00001234` matches; key `0xABCD1234` does not match through that value.

5. **Full-width method comparison.**  
   With discriminator `0x14` and selector 8, a method result of `0xABCD1234` is not narrowed. Key `0xABCD1234` matches; key `0x00001234` does not.

6. **Selector 6 is not a documented zero-valued property.**  
   If the first visited object has discriminator `0x16` and the selector is 6, the second lookup still occurs. The comparison uses an unspecified incoming value. Neither match nor non-match is statically guaranteed for any chosen key.

7. **Retained value after a non-match.**  
   Suppose an earlier iteration assigns comparison value 12 and fails against key 99. A later iteration that does not assign a new value compares 12 again and also fails. Without intervening changes to that retained state, such a path cannot introduce a new match after a known non-match.

8. **Output aliases the captured count’s storage.**  
   If the output location is the count field itself, the initial write changes that field to `-1` before the count is read. Assuming the pointer chain remains valid, the function then captures `-1` and returns null without lookup.

9. **Complete unsuccessful search.**  
   With a positive count, valid dependency behavior, and no equality at any visited index, the function returns null after processing every index below the captured count. Its own only output write is the initial `-1`.

## Uncertainties

### Established static evidence

The supplied representation establishes the initialization order, captured count, ordered iteration, repeated lookup for discriminator `0x16`, selector-dependent accesses, two low-16-bit masks, and return of the first lookup result.

It also establishes that several paths lack an explicit comparison-value assignment.

### Inferred intent

The operation appears intended to search objects by a selector-chosen property. The discriminator values likely distinguish object categories. No domain-specific property names or type meanings are established.

### documented_only

- Whether the missing assignments reflect deliberate machine-level behavior or limitations of the supplied representation.

- Whether repeated collection lookup returns the same object.

These unknowns are not replaced with validation rules, default values, or ownership assumptions.
