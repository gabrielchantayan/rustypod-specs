## Behavior

### Entry preparation

The second argument is called the **control word**. Its product with \(2^{28}\), reduced to 32 bits, is zero exactly when its low four bits are zero.

If those bits are nonzero:

- No initial transfer occurs.
- The restrictive preparation block cannot be entered.
- All subsequent preparation groups are skipped.
- The initial dispatch base is the incoming link-like pointer.

If the low four bits are zero, the routine performs one halfword transfer. Let the incoming source address be \(S\), the incoming displacement be \(D\), and the other incoming offset be \(O\). The destination is:

\[
S+D \pmod {2^{32}}.
\]

The established ordering is:

1. Read an unsigned 16-bit value at the incoming source address.
2. Replace the source-working address with \(S+D-O\), reduced to 32 bits.
3. Write the previously read 16-bit value at the destination.

The source-working update occurs between the read and write. It does not change which address supplied the value already read.

There is no length argument, overlap test, null check, or rollback. If the destination equals the source, the visible transfer still contains a read followed by a write.

This entry path also constructs an auxiliary numerical address from the incoming link-like address, control bit 2, and half the numerical address of the fifth argument’s storage. On this path, control bit 2 is necessarily clear. Writing the incoming link-like address as \(L\) and the argument-slot address as \(A\), the auxiliary address is therefore:

\[
L+(A\mathbin{\text{ shifted right by }}1)\pmod {2^{32}}.
\]

Both displayed scaled control addresses—using factors \(2^{28}\) and \(2^{29}\)—are zero on this path.

### Conditions for the restrictive preparation block

A cascade of zero-result gates follows. A failed gate disables the dependent gates; later Boolean results are explicitly cleared rather than inheriting an earlier successful condition.

Every right-shift expression actually reached in this cascade has a count of zero. The count is taken from the low byte of a result that must already be zero to enter the corresponding operation. Consequently, the relevant exclusive-or results act as equality tests, and their carry-like state is preserved.

Under the stated model, entry to the restrictive preparation block requires all of the following:

- The control word’s low nibble is zero.
- The incoming link-like address is zero.
- The auxiliary address is zero.
- The incoming equality operand equals the incoming displacement.
- The incoming other offset equals the updated source-working address.
- The incoming arithmetic operand is zero.
- The final addition involving the argument-slot address and twice the displacement produces zero.

The carry entering the arithmetic gates is zero. The contribution from the control word’s low nibble is also zero. Thus the arithmetic-operand gate really does require that operand to be zero; it is not an arbitrary carry-dependent equality.

The final address condition, under this model, is:

\[
A+2D\equiv0\pmod {2^{32}}.
\]

The actual slot placement is highly restrictive. The preceding conditions require \(A\) shifted right by one to be zero, so \(A\) is numerically zero or one. The final condition excludes one, because twice a 32-bit word is even. Thus entry to this block requires a numerical slot address of zero under the stated model.

This arithmetic deduction does not establish that such a calling environment exists or permits the required memory accesses.

### Restrictive preparation effects

If all entry conditions hold and execution continues normally, the block:

- Assigns the additional machine-state location a value derived from the argument-slot address multiplied by 64.
- Forms a new link-like address by adding that same 64-fold byte displacement to the prior link-like address.
- Uses halfword data read through the prior link-like address to select a destination address and a halfword value.
- Advances the scaled working halfword pointer by one element.

The data-addressed write uses the zero-extended source halfword as its numerical destination. The value written is the source halfword plus fifteen, truncated to 16 bits.

The displayed expression references the source halfword twice: once to obtain the destination and once to obtain the value. Both references precede the destination write, but a unique bus-level read count and an ordering between the references are not established. If the source changes between reads, the destination and stored value need not derive from the same observed halfword.

The machine-state assignment precedes this write. The visible source does not establish transactional behavior or rollback if a later access fails.

### Gate that blocks all later preparation

Reaching the assignment-containing block establishes that both the original scaled working address and the auxiliary address are zero. The block advances that scaled halfword pointer from numerical address zero to numerical address two.

The next cascade cannot progress:

- If the newly formed link-like address is nonzero, its initial zero test fails.
- If that address is zero, the first exclusive-or result is zero because the auxiliary address is zero.
- The next exclusive-or combines the advanced working address, two, with the auxiliary address, zero. Its result is two, not zero.

The latter operation again has a zero shift count. No wide-count shift interpretation is needed for this conclusion.

If the assignment-containing block is not entered, the following cascade is disabled immediately. Therefore, whether or not that block executes, every subsequent preparation group is unreachable under the stated model.

The additional machine-state location’s later displayed read belongs to these blocked groups. Any displayed path toward that read first passes through its assignment. There is no supported claim of a potentially uninitialized use.
