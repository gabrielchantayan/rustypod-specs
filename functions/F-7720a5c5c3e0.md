## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes storage remains valid for the accesses actually performed and preceding calls return unless stated otherwise. Relevant field preservation is required only where explicitly stated.

1. **Optional branches absent at their checks.** The early-child field is zero at its check, F-d277584d672d returns zero, the auxiliary-state field is zero when checked after notification, and the attachment field is zero at its final-stage check. The four global-sourced object writes occur in order, unconditional dependencies still run, and the original address is returned. Merely having these fields zero initially is insufficient.

2. **A later global value changes.** If an early-child callback changes slot B, the following B-sourced object write uses the value present at that later read. It is not required to reproduce B’s entry-time value. The same read-position principle applies to C, N, and D.

3. **Early-child replacement.** If the `0x30` callback replaces the child field and that replacement remains present at the subsequent reads, the `0x04` callback uses the replacement. Clearing the field skips that callback. The branch then explicitly clears the field.

4. **Associated-target equality.** A nonzero associated target whose `0x80` callback returns the original object triggers the retained target’s `0x7C` callback with zero, provided its storage and current table remain valid. A different result skips that callback.

5. **Two saved-association calls.** If the predicate is nonzero and the later context’s `0x28` equals the object, F-a82ec4b43e2f receives the saved association value twice. Changes to the association field between these calls do not change that saved argument.

6. **Output-slot obligations.** A nonzero F-ebd94610a438 result with a valid zero already available in the output slot causes no entry callback. A valid nonzero target causes its `0x04` dispatch. A nonzero result alone does not establish that either valid slot state exists.

7. **Final collection value controls dispatch.** The collection callback after F-944b595e25e9 uses the value present at the final reread. An earlier replacement matters only if later iteration calls, entry callbacks, and F-944b595e25e9 have not replaced or cleared it.

8. **Different clearing context.** If the context whose `0x24` matches the object differs from the next context, the zero write affects the latter, without testing its existing field value.

9. **Late-stage guard.** A zero initial attachment skips the late-stage condition read even if that condition is nonzero. With a nonzero initial attachment and a nonzero condition when eventually read, the non-returning dependency is reached if preceding calls return.
