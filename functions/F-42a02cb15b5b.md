# F-42a02cb15b5b

## Purpose

F-42a02cb15b5b traverses source-associated state, conditionally processes entries, and delivers constructed results through a caller-supplied indirect callback.

Three gates control delivery:

1. The traversal dependency returns nonzero.
2. The first byte of its flag storage is nonzero.
3. The predicate and subsequent extraction dependency each return nonzero.

Only entries passing these gates reach allocation, construction, and callback invocation.

Two distinct objects participate in processing. The **current object** is supplied to traversal, explicitly updated after transformation, and later supplied to the predicate. The **working object** is populated from a value obtained from the current object before transformation; that same working-object storage is subsequently supplied to transformation, extraction, and construction. This establishes object identity and call order, not preservation of pre-transformation contents. Transformation and intervening dependencies may mutate that storage directly or through aliases.

The apparent intent is enumeration, transformation, filtering, and result materialization. These are inferred operational roles, not established application semantics.

### Extraction setup and the two default reads

2. Second extraction field.
3. Third extraction field.
4. Construction field.
5. Additional extraction field.

The fourth and fifth initializations participate in explicit 32-bit stores. Their exact ordering is significant:

1. Initialize the construction field and retain the returned pointer.
2. Read the shared default into a saved 32-bit value.
3. Read the shared default again, separately, and write this second read’s value through the construction-field initializer’s returned pointer.

No explicit dependency call separates the two reads. Nevertheless, equality of their values requires the shared location to remain stable between them under the applicable memory and access semantics. The body supplies no synchronization establishing that stability.

The fifth initializer runs after the construction-field store. If it changes the shared default, that change does not replace the already saved value used by the subsequent store. It may have other effects, including effects on previously initialized objects if aliases exist.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Normal-return examples assume valid dependency inputs.

1. **Empty traversal.** If the first traversal call returns zero, no transformation, predicate, extraction, allocation, or callback occurs. Final cleanup remains working object, traversal state, current object.

2. **Disabled entry.** If traversal returns nonzero and the first flag byte is zero, processing skips directly to another traversal attempt. Nonzero bytes elsewhere in the flag region do not admit the entry.

3. **Mode distinction.** Mode 4 produces Boolean 1 for transformation and extraction. Mode 5 produces Boolean 0 there while traversal initialization and the predicate receive 5 unchanged.

4. **Predicate rejection.** Before a rejecting predicate runs, the explicit current-object update and both transformation-temporary finalizers have occurred. No extraction setup follows. The predicate’s exact observed object contents are not specified independently of those dependencies.

5. **Working-object mutation.** If transformation changes the working object and no later dependency reverses that change, extraction receives that same, changed storage. Requiring an untouched pre-transformation snapshot would contradict the established argument relationships.

6. **Configuration-base replacement.** If an earlier callback replaces the global configuration base before the next admitted entry’s read, that entry reads offset 12 from the newly retrieved base. Changing the field without replacing the base can also change the transformation argument.

7. **Stable shared default.** If the shared default remains unchanged across its two reads, both explicit stores use equal values. This equality depends on stability, not on a single shared snapshot.

8. **Different default reads.** If a permitted external mutation makes the first read yield 10 and the second yield 20, the construction-field store uses 20 and the additional-field store uses 10. If the fifth initializer subsequently changes the global to 30, the latter store still uses saved value 10.

9. **Extraction rejection.** A zero extraction return causes no allocation or callback. All six extraction-setup cleanup calls still occur in the specified order.

10. **Successful delivery.** If construction returns a chosen 32-bit value, the construction temporary is finalized before the callback receives a pointer to a slot containing that return value. Extraction-setup cleanup follows the callback.

11. **Zero allocation result.** If allocation returns zero normally, zero is still supplied to construction. Construction’s response is documented_only.

12. **Callback slot mutation.** If the callback overwrites the slot, the body makes no explicit later decision from the changed contents. This does not restrict alias-mediated effects.
