# F-78aeb390f956

## Purpose

F-78aeb390f956 consumes integer-valued input results, maintains a one-value cache, classifies candidate values, and selects among immediate returns, status writes, length-directed input consumption, indirect calls, and context-dependent numeric processing.

Interpreting the input handling as marker scanning with `0xFF` prefixes and a zero escape is **inferred intent**, not an established external format.

This contract describes the operations visible in the supplied static representation. Missing calling conventions, dependency semantics, and unresolved indirect behavior remain **documented_only**. No runtime tests have been performed.

## Interface

### Inputs and result

No explicit parameters are represented. The return value is unsigned and 32 bits wide.

Established return forms are:

- `0xFFFFFFFF` on several scanning and unsupported-class paths.
- Zero on restriction failure and completion of certain numeric paths.
- `0x15` on index-related failure.
- The complete 32-bit candidate, not merely its low byte.
- An unresolved indirect-call result, represented through the enclosing 32-bit return.

These are not necessarily distinct statuses: an unrestricted input result can itself equal any represented candidate value.

Implicit inputs include:

- An entry-object pointer obtained from a global location.
- A second global pointer, captured later to select the dispatch object.
- Results from F-fbfa6017b0f5.
- An incoming unsigned 32-bit bound.
- An incoming base address, an additional arithmetic operand, an enable value, and a context pointer.
- A global indexed-record base.
- Indirect-call state whose initialization is not established on every route.

The full ABI and provenance of these implicit inputs are unknown.

## Behavior

### Initial cache handling

The function selects the entry object and reads its discriminator at `+0x70`.

If the discriminator is `7`, it obtains the first value from `+0x6C`, without an input call. Otherwise, it:

1. Writes zero to entry-object `+0x6C`.
2. Writes `0xFFFFFFFF` to entry-object `+0x70`.
3. Calls F-fbfa6017b0f5.

The selected value is then recorded at entry-object `+0x74`.

If the complete value is not exactly `0x000000FF`, the function writes that value to `+0x6C`, writes discriminator `7`, and returns `0xFFFFFFFF`. A value such as `0x000001FF` therefore takes this early-return route.

### Prefix grouping and global-pointer capture

When the first value is exactly `0xFF`, another F-fbfa6017b0f5 call supplies the second result. This call is represented with an explicit `0xFF` argument; the dependency’s actual signature remains unresolved.

The function records that result at entry-object `+0x74`, then captures the second global pointer.

Every evaluation of the grouping-loop condition first writes the captured pointer back to that global location, then tests whether the controlling result equals `0xFF`. This includes the initial evaluation and the terminating evaluation.

Each iteration performs three input calls:

1. Record the first result at entry-object `+0x74`. If it differs from `0xFF`, write status `4` at entry-object `+0x34` and return `0xFFFFFFFF`.
2. Record the second result at `+0x74`. This value is not directly tested.
3. Record the third result at `+0x74`. It controls the next loop evaluation.

After recording the third result, the function refreshes the captured pointer from the second global. The next condition evaluation writes that refreshed pointer back.

Failure on an iteration’s first result skips the remaining calls, pointer refresh, and subsequent condition evaluation. Dependencies may change the global between the represented operations.

After normal termination, the function rereads entry-object `+0x74`. If it is zero, it caches `0xFF`, writes discriminator `7`, and returns `0xFFFFFFFF`.

### Dispatch selection and restriction

For a nonzero continuation, the dispatch object is selected using the previously captured pointer, not a fresh global read.

The function writes `0xFFFFFFFF` to dispatch-object `+0x70`, then zero to `+0x6C`.

It reads dispatch-object `+0x74`. While the controlling value is exactly `0xFF`, it assigns a fixed unresolved indirect target, calls F-fbfa6017b0f5, and records the result at dispatch-object `+0x74`.

The selected dispatch pointer remains captured even if dependencies change the global. After this loop, another 32-bit read of `+0x74` supplies the candidate.

Classification uses bits 7–4 for the class and bits 3–0 for the subtype. Higher candidate bits do not affect classification.

Before class-specific behavior, nonzero dispatch-object `+0x18` enables a restriction. The complete candidate must be in unsigned range `0xD0` through `0xD7`. The test uses 32-bit unsigned subtraction of `0xD0` and comparison with `7`. Failure writes status `0x0E` and returns zero.

### Classes `0xE` and `0xF`

Both classes make two input calls and construct a length from their low bytes: the first supplies the high byte, the second the low byte.

The resulting length ranges from zero through `65535`.

- Lengths zero, one, and two return the complete candidate without payload calls.
- Larger lengths cause exactly `length − 2` additional input calls, then return the complete candidate.
- The maximum payload-call count is `65533`.

These calls have no explicit caller-side recording at `+0x74`. Dependency side effects remain possible. No special interpretation of input errors or end-of-input is established.

### Unsupported classes

Classes outside `0xC`, `0xD`, `0xE`, and `0xF` call F-cc00fbc01b06, then write dispatch-object status `4`, then return `0xFFFFFFFF`.

The status write occurs after the dependency returns.

### Class `0xC`

Subtypes `1`, `2`, and `3` enter shared processing with:

- First working operand: zero.
- Second working operand: the complete candidate.
- Adjustment-control operand: the subtype.

The adjustment-control operand cannot contain `0x0800`, so the optional adjustment block is skipped on these entries regardless of the incoming enable value.

Subtype `0` invokes the unresolved indirect target without a represented argument and returns its result. Target initialization is established only on routes that executed the dispatch-stage repeated-`0xFF` loop.

Subtype `4` performs six consecutive 16-bit byte swaps at numeric addresses `4`, `6`, `8`, `10`, `12`, and `14`, in that order. Each word is read before its swapped value is written. It then invokes the unresolved indirect target with an explicit zero argument and returns its result.

These low-address accesses are not established to refer to a buffer. Their validity and fault behavior remain unknown.

All other subtypes write status `0x0D` and return the complete candidate.

### Class `0xD`: direct returns and subtype `8`

Subtypes `0` through `7` return the complete candidate.

Subtype `8` runs a dependency loop before continuing through subtype `9`. Its unsigned 32-bit counter starts at the complete candidate, whose low byte is necessarily `0xD8`.

Each iteration:

- Calls F-baed69327072 with the incoming base plus eight times the current counter, and the address of dispatch-object `+0x10`.
- Increments the counter by one.
- Continues only if the incremented counter is unsigned-less than the fixed incoming bound.

At least one call occurs, even when the initial counter already meets or exceeds the bound.

Assuming returning dependencies and valid execution of the represented operations, this counter loop terminates without wrapping. Its initial value is at most `0xFFFFFFD8`, hence below `0xFFFFFFFF`. If the bound exceeds the initial value, increments reach the bound and stop. Otherwise, the first increment ends the loop.

The call count is one when the bound is no greater than the initial counter; otherwise it is the bound minus the initial counter. This termination guarantee does not establish validity of the computed addresses or termination of the callees.

### Class `0xD`: subtypes `9` through `15`

Subtype `9`, including entry from subtype `8`, first captures the 16-bit flags at `+0x04`, then separately rereads that field for mask `0x0002`.

If `0x0002` is clear, processing follows subtype `10`.

Otherwise, the function reads the second working operand from `+0x0C`, then the first from `+0x08`. If either is nonzero, it enters shared processing, using the previously captured flags for the `0x0800` test. If both are zero, it returns zero without shared processing.

Subtype `10` reads `+0x08`, then `+0x0C`, and forms:

- First index: the unsigned 32-bit sum of `+0x08` and the additional incoming operand.
- Second index: the represented 32-bit result of `+0x0C` plus `14`.

A first index unsigned-greater than `13` causes failure. Only if that condition is false does the function compare the incoming bound with the second index; a bound less than or equal to the second index also causes failure.

Direct subtype `11` forms first index `3 + 13 = 16` and second index `13 + 14 = 27`. It fails because `16 > 13`.

Direct subtype `12` uses first index `4` and second index `27`. It fails when the incoming unsigned bound is at most `27`.

Direct subtype `13` begins with its failure condition true and fails without record reads.

Each failure returns `0x15` without a represented status write.

On the successful record path, addresses are formed from the global record base plus eight times each index. Address setup selects the second record before the first. The function computes:

- First component of the first record minus first component of the second record.
- Second component of the first record minus second component of the second record.

The first difference is formed before the second. Operand-load order within an individual subtraction is not established.

If either difference is nonzero, F-a8771a2dd698 receives the incoming bound minus `14` and incoming base plus `0x70`. The function then returns zero. Equal records return zero without that call.

Subtypes `14` and `15` write status `0x0D` and return the complete candidate.

Optional adjustment requires both a nonzero incoming enable value and a set `0x0800` bit in the path-selected adjustment-control operand.

When enabled, dependency order is:

3. F-1ea2f518fc81 with the sum of those results.

Next, the function reads incoming-context flags at `+0x10` and tests `0x00000001`.

If clear, it:

1. Reads the pointer at context `+0x04` and captures pointed-to `+0x34`.
2. Rereads the context pointer and obtains pointed-to `+0x30`.
3. Calls F-74efb2674226 with the first working operand and the obtained `+0x30` value.
4. Calls F-74efb2674226 with the second working operand and the previously captured `+0x34` value.

The fourth step retains the captured operand even if the preceding call changes the context pointer or storage.

If context bit `0x00000001` is set, both scaling calls and this flag read and transformation are skipped.

Finally, if either working operand is nonzero, F-a8771a2dd698 receives bound minus `14` and base plus `0x70`. The working operands are not represented as explicit arguments. Completion returns zero.

## Side effects

Established effects include cache invalidation and replacement, recorded input values, status writes, second-global-pointer writes, dependency calls, conditional low-address word swaps, and context and record reads.

No successful route is established to clear an existing status. A zero return does not imply a zero status.

Dependencies may mutate globals, input state, pointed-to storage, or other memory. Captured values remain captured; explicitly later reads observe storage at those later stages. Global preservation and memory ownership effects must not be assumed.

Unsigned 32-bit arithmetic has the represented modular width. Signed-typed sums, record-component subtraction, and address calculations do not establish portable overflow behavior outside valid representable contexts.

Repeated prefix-input results or nonreturning dependencies can prevent completion. The subtype-`8` counter loop itself does not acquire nontermination through wrapping: with its fixed unsigned bound and valid returning calls, it terminates as specified above.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless otherwise stated, assume valid storage and address arithmetic, returning dependencies, representable signed calculations, and no dependency mutations affecting the specified decisions.

1. **Initial non-prefix:** With discriminator other than `7` and first result `0x41`, cache invalidation precedes the input call. The result is recorded and cached with discriminator `7`; return is `0xFFFFFFFF`.

2. **Cached non-prefix:** With discriminator `7` and cached value `0x41`, the initial input call is omitted. The recorded and cached value remains `0x41`; return is `0xFFFFFFFF`.

3. **Zero continuation:** First value `0xFF` and second result zero cause the captured second global pointer to be written back on the initial terminating condition evaluation. The entry object caches `0xFF`; dispatch invalidation does not occur.

4. **Completed group:** After second result `0xFF`, group results `0xFF`, an untested value, and `0xD0` complete one iteration. A changed second global pointer is captured after the third recording, written back on termination, and used for dispatch.

5. **Group failure:** A first group result of `0x12` writes entry-object status `4` and returns `0xFFFFFFFF`, without the remaining group calls or pointer refresh.

6. **Length five:** Candidate `0xE2`, restriction disabled, and length low bytes `0x00`, `0x05` cause three payload calls and return `0xE2`. Lengths zero through two cause none.

7. **Restriction precedence:** Candidate `0xE2` with restriction enabled writes status `0x0E` and returns zero without length reads. Candidate `0x1D0` also fails restriction; with restriction disabled, it returns `0x1D0` through class `0xD`, subtype `0`.

8. **Shared class-`0xC` entry:** Candidate `0xC2` starts with working operands zero and `0xC2`. Optional adjustment is skipped. With context bit `1` set, scaling and masking are also skipped, and the nonzero second operand causes F-a8771a2dd698.

9. **Captured scaling operand:** If pointed-to `+0x34` initially contains `9`, the second scaling call receives `9` even if the first scaling call changes that field to `12`.

10. **Record direction:** Direct subtype `12`, bound `28`, record `4` equal to `(10, 20)`, and record `27` equal to `(3, 25)` produce differences `7` and `−5`. F-a8771a2dd698 is called, then the function returns zero.

11. **Index failures:** Direct subtype `11` returns `0x15` because its first index is `16`. Direct subtype `12` with bound `27`, and direct subtype `13` with any bound, also return `0x15` without record reads.

12. **Mandatory subtype-`8` iteration:** Candidate `0xD8` and bound `0xD8` cause one F-baed69327072 call. Incrementing to `0xD9` ends the loop; subtype-`9` processing follows.

13. **High-end counter termination:** Candidate `0xFFFFFFD8` and bound `0xFFFFFFFF`, with restriction disabled, cause exactly `39` loop calls. The counter reaches `0xFFFFFFFF`, fails the strict-less-than continuation test, and never wraps.
