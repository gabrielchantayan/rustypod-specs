# F-e6c2a72b1331

## Purpose

The established lookup interval is **zero inclusive to the bound exclusive**. Equality with the bound is rejected. Negative indices are rejected without reading the returned descriptor, but **the dependency is still called**.

The apparent intent is access to an indexed collection of pointer-like values. That interpretation is inferred: the available evidence establishes address-based loads and a raw integer return, not the application meaning of the collection, its entries, or zero.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Dependency invocation precedes index rejection

The dependency call happens before the index’s sign affects control flow.

Consequently, a negative index does not suppress the dependency’s execution or any effects it may have. The negative path only avoids this function’s subsequent descriptor and table reads.

No dependency-return status is checked.

### Negative index

If the index is negative, the function returns zero.

On this path, this function does not read:

- The descriptor’s bound field;
- The descriptor’s table-address field; or
- Any table entry.

This remains true regardless of the low or high portions of the dependency result, provided the dependency itself returns normally.

### Nonnegative index: bound read

For every nonnegative index, the function reads the signed 32-bit bound at descriptor address plus four bytes.

This read occurs even when the index is zero. Zero is not an unconditional rejection case.

The bound value is retained for the later decisions; the visible function does not reread the bound after loading the table address.

The decision is:

| Condition after the bound read | Result |
|---|---|
| Index equals bound | Reject and return zero. |
| Index exceeds bound, using signed comparison | Reject and return zero. |
| Index is less than bound | Continue to the table lookup. |

Because this stage is reached only for nonnegative indices, an accepted lookup requires a positive bound.

A zero or negative bound therefore rejects every nonnegative index. The bound field must nevertheless be readable to reach that decision.

### Accepted index: ordered pointer and entry reads

For an accepted index, the function first reads the table address from the descriptor’s first four bytes.

It then reads the selected four-byte table entry at the table address plus four times the index, and returns that entry’s bits.

The observable data-read order within this function is therefore:

1. Read the bound.
2. Read the table address.
3. Read the selected entry.

There is no table-address load on a bound-rejection path. There is no entry load before the table-address load. There is no additional check between loading the table address and accessing the selected entry.

In particular:

- A zero table address is not explicitly rejected.
- A zero selected entry is returned unchanged.
- An entry is not checked for alignment, validity, type, or ownership.
- The returned entry is not itself dereferenced.

The descriptor and table are not required by the visible operations to be disjoint. If they overlap, the same access order still applies. The function does not inspect their relationship.

### Integer widths and address arithmetic

The bound comparisons are signed comparisons. They must not be replaced with unsigned comparisons without proving equivalence for the actual data.

The table stride is four bytes. For index zero, the selected slot is at the table address itself.

Bounds acceptance does **not** prove that the selected address can be formed safely. The bound is a logical comparison value, not evidence of an allocation’s size or address range.

Two arithmetic issues remain distinct:

- Multiplying a sufficiently large accepted index by four can exceed signed 32-bit range.
- Adding even a representable displacement to a table address can exceed the address representation’s range.

For example, an index of 536,870,912 has a mathematical byte displacement of 2,147,483,648, beyond the maximum signed 32-bit integer. Such an index could still pass the bound check if the bound is larger.

The supplied representation does not establish portable behavior for overflowing signed arithmetic. Nor does it independently establish that address arithmetic wraps modulo \(2^{32}\). Wrapped-address behavior is therefore **documented_only**, not a guaranteed outcome.

For a fully determined accepted-lookup example, the arithmetic must be valid under the actual execution model and the selected word must be readable.
