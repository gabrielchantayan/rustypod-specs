# F-fc01ae5793b0

## Purpose

F-fc01ae5793b0 constructs output records describing a requested inclusive address interval. A one-byte selector determines which portion of an optional descriptor table is examined and how descriptor addresses are translated.

Two output modes are established:

- **Descriptor mode:** Each enabled descriptor whose interval overlaps the requested interval produces one clipped output record, in table order.
- **Fallback mode:** If no enabled descriptor is found, one record describes the request directly.

An enabled descriptor suppresses fallback even when it does not overlap the request. Consequently, successful completion can produce zero records.

The output storage is caller-supplied: a linked sequence of nodes refers to writable record payloads. The function does not visibly allocate or release storage.

The apparent intent is to translate logical ranges into selector-specific mapped ranges. That interpretation is inferred; the concrete contract is the field construction, traversal, and status behavior described below.

## Interface

The function has ten positional inputs and returns a 32-bit status value.

| Position | Contract role |
|---|---|
| 1 | Opaque 32-bit input; not used by the visible function body. |
| 2 | One-byte selector. Values 0, 1, and 2 have explicit configurations; other values take a distinct default configuration. |
| 3 | Unsigned 32-bit requested start address. |
| 4 | 32-bit requested length, presented as signed in the supplied representation. Its bit pattern participates in interval arithmetic and is copied into fallback output. |
| 5 | Optional descriptor-table address. Zero means no table. |
| 6 | Unsigned 32-bit descriptor-output capacity. |
| 7 | Initial output-node address, or zero. |
| 8 | Opaque 32-bit input; not used by the visible function body. |
| 9 | Address of a writable 32-bit emitted-record count. |
| 10 | Address of a writable 32-bit continuation-node address. |

The visible representation uses 32-bit address-bearing words. It does not establish a portable interface for wider pointers.

### Descriptor layout

Descriptors have a 16-byte stride. The following fields are accessed:

| Byte offset | Width | Meaning established by use |
|---|---:|---|
| 0 | 1 byte | Enabled indicator; any nonzero value is enabled. |
| 1 | 1 byte | Mapping attribute; value 1 can select a different scale. Also copied into output. |
| 4 | 32 bits | Mapping-base component. |
| 8 | 32 bits | Interval-start component. |
| 12 | 32 bits | Inclusive interval-end component before expansion. |

Bytes 2–3 are not explicitly read by this function. The dependency may inspect additional bytes.

### Output-node layout

Each output node contains at least two address-bearing 32-bit words:

| Byte offset | Meaning |
|---|---|
| 0 | Address of the writable record payload. |
| 4 | Address of the next output node. |

Nodes need not be contiguous. A zero next-node address becomes the continuation value after consuming that node.

### Output-record layout

Each record must provide at least 22 writable bytes:

| Byte offset | Width | Written value |
|---|---:|---|
| 0 | 1 byte | Selector. |
| 4 | 32 bits | Logical interval start. |
| 8 | 32 bits | Logical interval length. |
| 12 | 32 bits | Translated start value. |
| 16 | 32 bits | Scaled length. |
| 20 | 1 byte | Dependency result, or zero for fallback. |
| 21 | 1 byte | Descriptor attribute, or zero for fallback. |

Bytes 1–3 are not initialized. No record clearing is performed. Byte order and alignment requirements are not independently established by the supplied evidence.

### Preconditions

For ordinary successful execution, the count and continuation destinations must be writable. Any examined descriptor memory, consumed node, and referenced record payload must be valid for the accesses described here.

These requirements are not validated. In particular, fallback requires a valid initial node and record payload even if capacity is zero.

Distinct descriptor, node, record, count, and continuation storage is a safe caller-side precondition for obtaining the straightforward results described below. The function does not enforce non-aliasing.

## Behavior

### Initialization and selector configuration

Before examining descriptors or producing records, the function:

1. Writes zero to the emitted-record count.
2. Writes the initial output-node address to the continuation destination.

These writes occur even if a later descriptor emission returns the capacity error.

Selector configuration is:

| Selector | First descriptor index | Descriptors examined | Interval expansion shift | Mapping-base shift | Normal scale shift | Alternate scale shift | Fallback base |
|---|---:|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 2 | 7 | 6 | 2 | Not used | 0 |
| 1 | 2 | 8 | 7 | 8 | 2 | 1 | 65,536 |
| 2 | 10 | 8 | 7 | 8 | 2 | 1 | 98,304 |
| Other | 0 | 0 | 0 | 0 | 0 | Not used | 0 |

For selectors 1 and 2, descriptor attribute 1 selects the alternate scale shift. Every other attribute value selects the normal scale shift. Selector 0 always uses scale shift 2.

An unsupported selector does not return an invalid-selector error. It examines no descriptors and proceeds to fallback.

### Requested and descriptor intervals

The requested inclusive endpoint is formed as:

**requested end = requested start + requested length − 1**

The interval comparison uses unsigned 32-bit values. No check rejects zero length, negative signed length, or arithmetic wraparound.

For an enabled descriptor:

- Its interval start is its start component shifted left by 7.
- Its interval end is one less than its end component plus one, shifted left by 7.

Equivalently, for values that do not overflow, a descriptor with start component \(a\) and end component \(b\) covers:

\[
[128a,\;128(b+1)-1]
\]

The descriptor overlaps when both unsigned comparisons hold:

- Requested start is no greater than descriptor end.
- Descriptor start is no greater than requested end.

There is no separate validation that either interval is well-formed. These comparisons are the actual acceptance rule, including for wrapped or reversed endpoints.

### Descriptor scan

A zero table address skips scanning. Otherwise, descriptors are visited in increasing table-index order according to the selector configuration.

For each descriptor:

1. Read the enabled byte.
2. If it is zero, skip the descriptor.
3. Otherwise, remember that an enabled descriptor exists.
4. Read its interval components and mapping-base component.
5. Determine its scale shift. For selectors 1 and 2, this includes reading the attribute byte before the overlap decision.
6. Evaluate overlap.
7. If overlapping, attempt to emit one record.

Records are not sorted, merged, or deduplicated. Overlapping enabled descriptors can produce overlapping output records.

### Capacity check and clipping

Before writing an overlapping descriptor’s record:

- A zero current-node address causes immediate failure.
- Otherwise, the current emitted count is read. If it is greater than or equal to capacity, emission fails.

Both failures return **0xFFFFFF0C**, corresponding to −244 if interpreted as a signed 32-bit value.

The rejected record is not written, and its dependency is not called. Records emitted earlier remain modified.

For an accepted descriptor, the output interval is clipped to the request:

- Output start is the larger of descriptor start and requested start.
- Output end is the smaller of descriptor end and requested end.
- Output length is output end minus output start plus one.

These operations use the represented 32-bit values; there is no additional empty-result or overflow check.

### Descriptor record construction

For an overlapping descriptor, the visible write order is:

1. Record offset 4: clipped start.
2. Record offset 8: clipped length.
3. Record offset 12: translated start.
4. Record offset 16: scaled length.
5. Record offset 0: selector.
6. Call F-4a03c29443bb with the descriptor address and selector.
7. Record offset 20: the dependency’s one-byte result.
8. Record offset 21: the descriptor attribute byte, read after the call.
9. Advance to the current node’s next-node address.
10. Write that address to the continuation destination.
11. Read and increment the emitted count, then write it back.

The translated start is:

\[
\bigl((\text{mapping base} \ll \text{base shift})
+(\text{clipped start} \ll \text{scale shift})\bigr)
\mathbin{\&} 524287
\]

Thus only its low 19 bits are retained.

The scaled length is the clipped length shifted left by the selected scale shift. It is not subjected to the 19-bit mask.

The record address is fetched from node memory at multiple points rather than being preserved as an immutable destination for the whole operation. Likewise, the attribute used at offset 21 is read after the dependency returns. These details matter if storage aliases or the dependency changes reachable memory.

### Successful scan completion

If the scan observed any enabled descriptor, the function returns zero after completing the scan, regardless of whether any descriptor overlapped.

In particular, a table with enabled but non-overlapping descriptors produces:

- Success status zero.
- Emitted count zero.
- Continuation equal to the initial node address.
- No fallback record.

This outcome does not require a nonzero current node or positive capacity because no emission is attempted.

### Fallback

Fallback occurs when:

- The table address is zero.
- No examined descriptor is enabled.
- The selector causes zero descriptors to be examined.

Fallback writes exactly one record. It does **not** check capacity or the current-node address.

Its write order is:

1. Offset 4: requested start.
2. Offset 8: requested length bit pattern.
3. Offset 12: fallback base plus requested start shifted by the fallback scale shift.
4. Offset 16: requested length shifted by that scale shift.
5. Offset 0: selector.
6. Offset 20: zero.
7. Offset 21: zero.
8. Continuation destination: initial node’s next-node address.
9. Emitted count: current count plus one.

The fallback scale shift is 2 for selectors 0, 1, and 2, and 0 for other selectors.

Unlike descriptor-mode translation, fallback translation has **no 19-bit mask**. No dependency is called.

Under non-aliasing conditions, fallback returns zero with emitted count one. A missing node or invalid payload is an unchecked invalid memory access, not the descriptor-mode capacity error.

### Arithmetic boundaries

The visible operands, fields, and status values are 32-bit. No wider intermediate arithmetic is shown.

For a 32-bit bit-vector reading, additions, subtractions, and left shifts retain the low 32 bits. However, some operands are presented as signed values. The supplied representation alone does not establish portable language-level behavior for signed overflow or left shifts of negative values. Such cases are **documented_only** rather than assigned a portable arithmetic guarantee.

Zero length is not inherently empty under the visible overlap rule. For example, requested start zero and length zero form an endpoint of 0xFFFFFFFF under 32-bit wraparound, potentially allowing descriptor emissions. Consumers must not infer conventional half-open-range semantics.

## Side effects

The function visibly mutates:

- The emitted-count destination.
- The continuation destination.
- Selected fields of each emitted output record.
- Any state modified by F-4a03c29443bb.

It visibly reads descriptor memory and output-node links. It does not visibly modify descriptors or node links itself, although aliased output destinations or dependency behavior can do so indirectly.

There is no rollback. On a capacity failure, earlier records, dependency side effects, count updates, and continuation updates remain.

Count and continuation are not transactionally published. Entry initialization, record writes, dependency execution, continuation updates, and count updates are separately observable.

No allocation, deallocation, ownership transfer, or cleanup operation is visible. This does not establish that the dependency preserves memory, globals, or ownership.

Concurrent mutation and aliasing can affect subsequent reads. The function performs no visible synchronization or snapshotting.

## Acceptance examples

These examples assume valid, non-overlapping caller storage, stable descriptor and node memory, ordinary non-overflowing arithmetic, and a dependency that returns normally without mutating relevant state.

### Clipped selector-0 descriptor

Given:

- Selector 0.
- Request start 100, length 200, covering 100 through 299.
- Descriptor 0 enabled, with mapping base 3, start component 1, and end component 1.
- Descriptor 1 disabled.
- Capacity at least one and one usable node.
- Dependency result \(r\), descriptor attribute \(a\).

The descriptor covers 128 through 255. Exactly one record is emitted:

- Start 128.
- Length 128.
- Translated start \(3 \times 64 + 128 \times 4 = 704\).
- Scaled length 512.
- Selector 0.
- Result byte \(r\).
- Attribute byte \(a\).

Count becomes one, continuation becomes the consumed node’s successor, and status is zero.

### Alternate selector-1 scale

Given selector 1, an enabled descriptor at index 2 with attribute 1, mapping base 4, and interval components both 2, a request starting at 260 with length 10 lies entirely within that descriptor.

The output start is 260, length is 10, translated start is \(4 \times 256 + 260 \times 2 = 1544\), and scaled length is 20.

If the attribute is instead 0, translated start is 2064 and scaled length is 40.

### Enabled but non-overlapping table

Given a selected enabled descriptor covering 128 through 255 and a request covering 1000 through 1009, with every other examined descriptor disabled:

- Status is zero.
- Count is zero.
- Continuation remains the initial node address.
- No record is written.
- No dependency is called.

A zero initial node is acceptable for this particular path.

### Partial capacity failure

Given two enabled, overlapping descriptors, two valid nodes, and capacity one:

- The first record is emitted and its dependency is called.
- Continuation advances to the second node.
- Count becomes one.
- The second emission returns 0xFFFFFF0C before writing its record or calling its dependency.
- The first emission remains committed.

### Fallback ignores capacity

Given selector 2, no table, request start 5 and length 3, a valid node, and capacity zero:

- One fallback record is emitted.
- Translated start is \(98304 + 5 \times 4 = 98324\).
- Scaled length is 12.
- Result and attribute bytes are zero.
- Count becomes one and status is zero.

Replacing the valid node with a null address does not produce a defined capacity error on this path.

### Unsupported selector

Given selector 3, request start 10 and length 4, and a valid node:

- No descriptors are read, even if a nonzero table address was supplied.
- Fallback writes selector 3, start 10, length 4, translated start 10, and scaled length 4.
- Result and attribute bytes are zero.
