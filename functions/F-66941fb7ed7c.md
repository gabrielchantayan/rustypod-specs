# F-66941fb7ed7c

## Purpose

F-66941fb7ed7c selects a 32-bit notification value using a dependency-produced classification and, conditionally, flags stored in three records.

Two classification values select a reset path: the function clears one 32-bit field in each record and selects notification value 1. Every other classification selects an inspection path: the function examines bit 0 of another 32-bit field in each record and selects notification value 3 if any inspected bit is set, or 2 otherwise.

The selected value is passed to F-1b765582ee90. The function has no explicit return value.

This contract describes behavior established by the supplied static representation. The domain meaning of the classifications, record fields, and notification values is unknown.

### Record layout

## Behavior

### Dependency preparation

The function establishes two local 32-bit cells:

- A request cell initially containing the third argument, preserving its 32-bit value.
- A classification cell initially containing the value 4.

The initial candidate notification value is 2.

The function first calls F-b9d333145f3e with no explicit arguments. It captures a 32-bit result.

It then calls F-ca2888499290 with three arguments, in this order:

1. The result from F-b9d333145f3e.
2. The address of the request cell.
3. The address of the classification cell.

The addresses passed to F-ca2888499290 refer to local storage, not directly to the caller’s argument locations. The dependency can potentially modify those cells through the supplied addresses. The body does not subsequently inspect the request cell.

No direct access to record storage occurs before these two calls return. A dependency may nevertheless access or change that storage through other means; the supplied body does not establish otherwise.

### Classification decision

After F-ca2888499290 returns, the function reduces the classification cell’s value to an eight-bit character value for its branch decision.

Only values equal to 1 or 2 select the reset path. All other eight-bit values select the inspection path.

Consequently:

- Upper bits of the 32-bit classification cell do not affect the branch.
- A final classification of 0x00000101 selects the reset path.
- A final classification of 0x00000102 selects the reset path.
- A final classification of 0x00000100 selects the inspection path.
- If the classification cell remains at its initialized value of 4, the inspection path is selected.

Whether the character type is signed does not change the comparison outcomes: only the eight-bit values 1 and 2 match.

This decision concerns the low eight bits of the cell’s value. It does not establish which addressed byte holds those bits in memory; byte order is not specified here.

### Reset path

If the eight-bit classification is 1 or 2, the selected notification value becomes 1.

The function then performs three 32-bit zero stores in increasing record order:

1. Record 0, offset 24: absolute offset 24.
2. Record 1, offset 24: absolute offset 56.
3. Record 2, offset 24: absolute offset 88.

The direct body does not read the inspection fields on this path. Their bit values do not affect notification selection.

The stores occur before the final dependency call. They are not a transactional update: no rollback behavior is present if execution stops after only some stores have completed.

### Inspection path

For any other eight-bit classification, the function reads three unsigned 32-bit fields in increasing record order:

1. Record 0, offset 12: absolute offset 12.
2. Record 1, offset 12: absolute offset 44.
3. Record 2, offset 12: absolute offset 76.

It combines all three values with bitwise OR, starting from zero.

All three reads occur before notification selection completes. Finding bit 0 set in an early record does not short-circuit later reads.

After all reads:

- If bit 0 of the combined value is set, the selected notification value becomes 3.
- Otherwise, the selected notification value remains 2.

Equivalently, value 3 is selected if bit 0 is set in at least one inspected field. Bits 1 through 31 do not affect this choice.

The direct body performs no record writes on this path. That statement does not constrain writes performed by dependencies.

### Final call and completion

After the selected path completes, the function calls F-1b765582ee90 exactly once with the selected 32-bit notification value.

Assuming normal completion, dependency-call order is:

1. F-b9d333145f3e.
2. F-ca2888499290.
3. F-1b765582ee90.

The function does not inspect a result from the final call. It then returns without an explicit value.

If an earlier call does not return normally, or a required memory access fails, the supplied body provides no recovery path and does not establish that the final call occurs.

## Acceptance examples

These are conditional contract examples, not executed tests. Each assumes valid required storage and normally returning dependencies.

### Classification 1 selects reset

If F-ca2888499290 leaves the classification cell equal to 1:

- The function writes 32-bit zero at offsets 24, 56, and 88, in that order.
- It performs no direct reads at offsets 12, 44, and 76.
- It calls F-1b765582ee90 with 1 after the stores.

Any flag values in the inspection fields are irrelevant to this decision.

### Classification 2 has the same direct behavior

If the final classification value is 2, the same three zero stores occur and the final argument is 1. No distinct reset behavior for classifications 1 and 2 is established.

### Upper classification bits are ignored

If the final classification is 0xA5A50002, the reset path is selected because its low eight bits equal 2.

If it is 0x00000200, the inspection path is selected because its low eight bits equal zero.

### No classification update

If F-ca2888499290 does not change the classification cell, it remains 4. The function takes the inspection path; there is no special fallback based on whether an update occurred.

### Bit 0 clear in every inspected field

If the classification selects inspection and the three fields contain 0x00000000, 0x80000000, and 0xFFFFFFFE:

- All three fields are read in record order.
- No reset-field store is performed by this body.
- The final notification argument is 2.

The set upper bits do not affect the result.

### Bit 0 set only in the last record

If the inspected values are 0, 2, and 1, the final notification argument is 3.

### Bit 0 set in the first record

If the first inspected field contains 1, the second and third fields are still read before the final call. The final notification argument is 3.

An invalid third-field address is not made safe by the first field already establishing the eventual bit result.

### Dependency changes before inspection

### Request-cell mutation
