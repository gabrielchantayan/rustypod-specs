# F-7cb60db72009

## Purpose

F-7cb60db72009 searches a global, fixed-stride record region for the first record satisfying two conditions:

- A 16-bit field equals a supplied 32-bit identifier.
- An 8-bit field contains a selected bit.

On a match, it returns the record’s address through a 32-bit integer result. After an unsuccessful candidate, it advances the index and consults a global count to decide whether to stop with zero.

This is not an ordinary count-guarded search: the first record is examined before the count is checked. A zero count therefore does not prevent access to the first record or prevent that record from being returned.

**Established static evidence:** the supplied representation contains this search, no function calls, and no explicit memory writes.

**Inferred intent:** the global base and count describe a record table, the 16-bit field acts as a lookup key, and the byte acts as a capability or selection mask. These semantic names are descriptive, not established domain meanings.

## Interface

### Inputs

The function has three scalar inputs:

| Input | Width | Observed use |
|---|---:|---|
| First argument | 32 bits; interpretation unspecified | Unused in the visible behavior. |
| Bit selector | Unsigned 32 bits | Only its low eight bits determine the shift count. |
| Identifier | Unsigned 32 bits | Compared with a zero-extended 16-bit record field. |

The identifier is not truncated to 16 bits. Consequently, a value greater than 65,535 cannot match any normally read record identifier.

The selector is reduced modulo 256, not modulo 8. Selectors 0 and 256 select the same shift count; selectors 1 and 257 likewise do so.

### Global inputs

Two global values participate in the search:

- **Record base:** the starting address used to derive record addresses.
- **Record count:** the unsigned bound consulted after an unsuccessful candidate and an index increment.

The visible representation uses 32-bit address and index arithmetic. It does not establish the storage declaration, lifetime, synchronization, or ownership of either global.

### Record layout

Candidate records have a stride of 12 bytes:

| Offset from candidate address | Access width | Meaning in this function |
|---|---:|---|
| 4 | 16 bits | Identifier field |
| 6 | 8 bits | Bit-mask field |
| All other offsets | Not directly read | Unspecified |

The candidate at index \(i\) is addressed using the record base plus \(12i\).

The 16-bit field is interpreted in the execution environment’s native byte order. The supplied material does not independently establish that byte order.

A 12-byte stride does not establish that all 12 bytes are initialized, meaningful, or accessed. This function directly requires only the listed fields for each candidate it examines.

### Output

The result is a 32-bit integer:

- On success, it represents the address of the first matching candidate.
- On ordinary search exhaustion, it is zero.

The successful address is not a copy of the record, an index, or an independently allocated object. No ownership transfer is visible.

Because the declared result is an integer rather than a pointer, treatment of addresses with their high bit set depends on the target’s integer and address representation. Callers must not assume that every successful result is a positive signed integer.

Zero is not proven to be an unambiguous failure sentinel: if a matching record could legitimately be addressed at zero and its fields were readable, the successful result would also be zero.

## Behavior

### Candidate evaluation

The search begins at index zero without first consulting the count.

For each candidate:

1. The global base is read and combined with the current index and 12-byte stride to determine the candidate address.
2. The 16-bit identifier field at offset 4 is read.
3. If that field differs from the supplied identifier, the candidate fails without a visible read of its mask byte.
4. If the identifier matches, the byte at offset 6 participates in the bit-selection test.
5. A candidate succeeds only if that test produces a nonzero result.

The source-level condition uses short-circuit evaluation between the identifier comparison and the mask test. Thus, the mask-byte read is conditional on identifier equality.

Within the mask expression, the representation does not establish an evaluation order between the byte read and the shift calculation. No contract for memory-mapped I/O ordering or generated instruction ordering can be derived from it.

### Bit-selection semantics

The bit test combines:

- The record’s 8-bit mask, promoted to an integer value.
- The value obtained by shifting the integer constant one left by the selector’s low eight bits.
- A mask retaining only the low eight bits.

For shift counts from 0 through 7, the behavior is straightforward: the candidate matches precisely when the corresponding bit of the record byte is set.

For shift counts from 8 through 30, the shifted value has no low-eight-bit contribution. The candidate therefore cannot match, even when its mask byte is 255. For an identifier-matching candidate, the mask byte still participates in the evaluated expression; this is not an early rejection before that field access.

The representation uses an unsuffixed integer constant as the left operand of the shift. Under a 32-bit signed-integer interpretation:

- A shift count of 31 raises a signed-shift representability issue.
- Shift counts of 32 through 255 are outside the operand width.

The supplied material does not establish the underlying machine instruction behavior for those cases. This contract does not replace them with modulo-32 shifting, assume that they yield zero, or assign any other successful or unsuccessful result. Such selector values are **documented_only**.

### Failure progression and termination

After a candidate fails:

- The unsigned 32-bit index is incremented.
- The current global count is read.
- If the count is less than or equal to the incremented index, the function returns zero.
- Otherwise, the next candidate is examined.

For a stable positive count \(N\), ordinary execution examines indices zero through \(N-1\), stopping earlier at the first match.

For a stable count of zero, index zero is still examined. If it fails, the incremented index is one, the bound comparison succeeds, and the function returns zero. If it matches, the function returns that candidate without reading the count.

The count is therefore a bound on continuing after failure, not a prerequisite for accessing the current candidate.

### Success and address recomputation

On success, the function computes the returned address using a new read of the global base and the successful index.

It does not visibly return a saved copy of the address used to read the successful fields. Under a stable base, those addresses coincide. If the base changes between candidate evaluation and the success return, the returned address can refer to a different location from the record whose fields matched.

No synchronization or snapshot mechanism is visible. A consistent-table interpretation requires an external guarantee that the base, count, and relevant record contents remain suitably stable.

### Arithmetic boundaries

The index and the stride multiplication are represented as 32-bit unsigned arithmetic. Products and address sums can wrap at that width.

For a stable count, the largest count value does not by itself require the index to wrap: failure at index 4,294,967,294 increments the index to 4,294,967,295 and satisfies the exhaustion comparison. Address calculations can wrap much earlier.

No check detects:

- Overflow of the stride multiplication.
- Wraparound of the base-plus-offset calculation.
- An address outside the actual allocation.
- Misalignment of the 16-bit field.
- An unreadable record field.

A valid-use precondition is that each field access reached by the search is permitted in the execution environment and that address arithmetic identifies the intended storage. Integer-to-address conversion details are not fully established by the supplied representation.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume stable globals, readable and suitably aligned fields, ordinary nonwrapping address calculations, and a selector with defined shift behavior.

1. **First candidate matches.**  
   The count is three. Candidate zero has identifier 42 and mask value 4. The supplied identifier is 42 and selector is 2. The result is the base address. The count need not be read on this path.

2. **First qualifying record wins.**  
   Candidates zero and one both have identifier 42, but only candidate one has bit 2 set. Candidate two also satisfies both conditions. With count three and selector 2, the result is the base plus 12, not the address of candidate two.

3. **Identifier mismatch skips the mask field.**  
   Candidate zero’s identifier differs from the requested identifier. Its mask byte is not needed to reject that candidate. This does not remove the requirement that the identifier field itself be readable.

4. **Zero count does not suppress the first match.**  
   The count is zero, but candidate zero’s identifier and selected mask bit match. The result is the base address rather than an automatic failure.

5. **Zero count with first-candidate failure.**  
   The count is zero and candidate zero fails. After incrementing the index to one and reading the count, the function returns zero. It does not examine candidate one.

6. **Identifier exceeds the stored field’s range.**  
   The supplied identifier is 65,536. No 16-bit record identifier can equal it. With a stable positive count, all permitted candidates fail the identifier comparison, and the function returns zero without needing their mask fields.

7. **Selector wraps at eight input bits.**  
   Selectors 2 and 258 have identical effective shift counts. Under otherwise identical stable inputs, they produce the same search behavior.

8. **A valid shift outside the byte cannot match.**  
   The selector is 8. Even an identifier-matching record with mask value 255 fails the mask test. Search continuation still depends on the post-failure count check.

9. **Large shifts have no asserted outcome.**  
   The selector’s low byte is 31 or greater. A portable success or failure expectation is not established here. These cases require additional target-level evidence and remain documented_only.

10. **The return base is read again.**  
    A candidate matches using one base value, but the global base changes before success-address calculation. The static representation permits the result to use the later base with the successful index. This is not a guarantee that an unsynchronized concurrent execution has defined language-level behavior.
