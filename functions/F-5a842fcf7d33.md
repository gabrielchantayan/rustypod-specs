# F-5a842fcf7d33

## Purpose

F-5a842fcf7d33 traverses a source range in 16-byte records and, when the current destination address is nonzero, transfers each record to the corresponding destination position. Each record consists of four 32-bit words. It returns the destination cursor after the traversal.

The source range is controlled by equality between a moving source cursor and a supplied end cursor. It is not controlled by a byte count, ordering comparison, terminator value, or destination capacity.

**Established behavior:** the destination-null check applies separately to each iteration. A null initial destination is not a general request to suppress all copying: the destination cursor still advances after a skipped transfer.

**Inferred intent:** the routine resembles a fixed-size record transfer operation that returns the end of the destination range. No higher-level record meaning, container role, or ownership convention is established.

## Interface

The interface has three pointer-valued inputs and one pointer-valued result:

| Item | Role |
|---|---|
| Source start | Initial source cursor, identifying the first four-word record. |
| Source end | Exclusive stopping cursor, compared for equality with the current source cursor before each iteration. |
| Destination start | Initial destination cursor, tested for null before each record transfer. |
| Return value | Destination cursor after all completed iterations. |

Each addressed word is 32 bits, or four bytes. Each cursor step spans four such words, giving a 16-byte record stride.

The record layout is:

| Byte offset | Width | Meaning established here |
|---|---:|---|
| 0 | 32 bits | First word |
| 4 | 32 bits | Second word |
| 8 | 32 bits | Third word |
| 12 | 32 bits | Fourth word |

The words are transferred without numeric conversion, interpretation, byte swapping, validation, or field-specific processing. Their signedness and application-level meanings are not established. Pointer width is not established by the supplied evidence and must not be inferred from the 32-bit word width.

For an ordinary, finite, nonempty traversal, the end cursor must be reachable from the source start through repeated valid 16-byte advances. Source and destination storage must support every access actually performed. Alignment, address validity, and pointer-arithmetic requirements depend on the target execution environment.

These are caller-side preconditions, not checks performed by this routine. The function supplies no capacity argument and does not verify available storage.

## Behavior

### Range control and cursor progression

Before each iteration, the routine compares the current source cursor with the source end.

If they are equal, it returns the current destination cursor immediately. Consequently, an initially empty range causes no word reads, no word writes, and no cursor advances. The initial destination is returned unchanged, including when it is null.

If the source cursor differs from the end cursor, one iteration occurs. The routine first tests whether the current destination cursor is null:

- A nonnull destination causes one four-word transfer.
- A null destination suppresses all source-word reads and destination-word writes for that iteration.

After either case, the destination cursor advances by 16 bytes. The source cursor then advances by 16 bytes, and the next source/end comparison occurs.

If exactly \(N\) iterations complete through valid pointer arithmetic, the returned destination is the initial destination advanced by \(16N\) bytes. This describes cumulative cursor displacement; it does not establish a fixed-width integer multiplication or wraparound operation inside the routine.

The stopping rule is exact equality. A cursor that passes the end address does not stop merely because it has passed it. An end cursor that is not reachable by the required advances therefore does not define a valid finite traversal under this contract. No particular eventual fault, wraparound, or termination behavior is promised for that case.

### Record access order

For a nonnull destination, the established order within an iteration is:

1. Read the source word at offset 4.
2. Read the source word at offset 8.
3. Read the source word at offset 12.
4. Read the source word at offset 0 and write that value to destination offset 0.
5. Write the previously read offset-4 value to destination offset 4.
6. Write the previously read offset-8 value to destination offset 8.
7. Write the previously read offset-12 value to destination offset 12.

Thus, all four source values for the current record are obtained before the first destination write. The final three writes use retained values, rather than rereading their source locations after earlier writes.

This ordering describes the accesses established by the supplied representation. It is not a claim of atomic record transfer, a synchronization guarantee, or a hardware bus-transaction specification.

### Overlap

The routine does not test for overlap, select a traversal direction, or preserve the entire source range before writing.

Within one iteration, overlapping destination writes do not change the four values already obtained for that record. Across iterations, however, destination writes may overwrite source records that have not yet been read. A later iteration then uses the contents present at that later time.

Accordingly, the routine must not be specified as providing general overlap-safe movement. In particular, moving a multi-record range forward into itself can propagate earlier record contents into later output records.

Exact source/destination equality is a distinct case: for ordinary readable and writable memory, each iteration reads its record and writes the same four word values back to the same locations. Those writes still occur; this is not an access-free identity operation.

### Null destination behavior

A null current destination skips only the current record’s data accesses. It does not return early and does not prevent cursor advancement.

The supplied representation advances the destination even when it is null. The validity and result of that arithmetic depend on the execution model and are **documented_only** here. Under an address model where advancing zero by 16 produces address 16, the next iteration sees a nonnull destination and attempts a transfer there. The routine provides no special protection for that address.

A null source is not independently rejected. For an empty range, it need not be dereferenced. For a nonempty iteration with a nonnull destination, the routine attempts the described source reads without checking their validity.

## Side effects

For every iteration with a nonnull destination, the routine performs four 32-bit source reads and four 32-bit destination writes in the order specified above.

For an iteration with a null destination, it performs no record-data accesses. Cursor progression still occurs.

No allocation, deallocation, ownership transfer, reference-count adjustment, callback, or explicit global-state access is present in the supplied evidence. The caller retains responsibility for the storage. The routine does not establish that the destination contains newly owned objects or that overwritten contents receive cleanup.

Memory effects are not limited to a separate “output buffer” when the arguments alias. Writes may alter the source range, shared storage, or other state occupying the destination addresses.

There is no explicit error return, validation report, rollback, or recovery path. Invalid accesses or invalid pointer arithmetic are not converted into a defined failure result. If execution is interrupted during a record transfer, the evidence provides no transactional guarantee that its writes are all present or all absent.

## Acceptance examples

The examples below are conditional acceptance criteria derived from static evidence, not executed test results. Unless stated otherwise, storage is ordinary memory, accesses and cursor arithmetic are valid, and source and destination ranges are disjoint.

### Empty range

**Given:** source start equals source end.

**Required:** return the original destination without reading or writing record storage. A null destination remains null.

### Single-record transfer

**Given:** the source range contains exactly one record with words \((A, B, C, D)\), and the destination is nonnull.

**Required:** write \((A, B, C, D)\) to the destination record and return the destination advanced by 16 bytes. Accesses follow the specified read/write order.

### Two disjoint records

**Given:** the source contains records \(R_0\) and \(R_1\), and the end cursor is 32 bytes beyond the source start.

**Required:** transfer \(R_0\) first and \(R_1\) second. Return the destination advanced by 32 bytes.

### One-word overlapping displacement

**Given:** a single source record occupies four consecutive words containing \((A, B, C, D)\), a fifth word is writable, and the destination begins four bytes after the source.

**Required:** after completion, the five-word region contains \((A, A, B, C, D)\). Earlier destination writes must not replace the retained values used for subsequent writes within this record.

### Forward overlap across records

**Given:** two source records initially contain distinct values \(R_0\) and \(R_1\). The destination begins at the second source record, and a third record is writable.

**Required:** the first iteration replaces the second record with \(R_0\). The second iteration reads that modified record and writes \(R_0\) into the third record. It does not preserve the original \(R_1\).

### Exact in-place transfer

**Given:** source and destination start at the same address, with a valid finite range.

**Required:** retain the same ordinary-memory word contents while still performing the specified reads and writes. Return the cursor immediately following the destination range.

### Null destination under an explicit address model

**Given:** exactly one iteration, a null destination, and an execution model defining the destination advance as producing address 16.

**Required:** perform no source-word reads or destination-word writes, and return address 16.

**Boundary:** that result is conditional on the stated arithmetic model. It is not a portable guarantee about null-pointer arithmetic. With a second iteration, the routine would attempt a transfer through the resulting nonnull destination.
