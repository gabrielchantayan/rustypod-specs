# F-5bab859e156b

## Purpose

F-5bab859e156b coordinates an operation on an input object using two acquisition dependencies, indirect dispatch, argument conversion, and submission. A successful submission enables a further operation that either uses the original input object or exposes a local object-pointer slot for possible replacement.

Every normally returning path subsequently clears bit 0 of a context byte, calls a final dependency on local result storage, and returns a packed 64-bit value. The low word contains the selected status. The high word contains the local pointer slot’s contents **after the final dependency returns**, not necessarily the value observed at an earlier branch check.

This contract describes statically established control flow and data access. Application-level meanings such as commit, removal, release, or reference counting are not established.

## Interface

### Inputs

The function has four input positions:

| Position | Width and representation | Established use |
|---|---|---|
| Context | 32-bit address-bearing value | Locates a byte at offset 28 and, after successful submission, a 32-bit field at offset 12. |
| Input object | 32-bit pointer | Initializes a mutable local pointer slot and is passed unchanged as an argument to several dependencies. |
| Initial first word | 32-bit opaque value | Initially populates the first local result word. |
| Initial second word | 32-bit opaque value | Initially populates the second local result word. |

Both initial result words are overwritten after successful acquisition and before their storage is explicitly exposed to a callee. If acquisition fails, the function instead invokes a nonreturning dependency. Thus, the third and fourth inputs do not supply values to any explicitly shown downstream operation.

“Original input object” means the pointer value supplied at entry. It does not imply that the object’s contents or lifetime remain unchanged across calls.

### Exposed local storage

Two local regions matter:

- **Object-pointer slot:** one 32-bit pointer, initially equal to the input object. One success branch passes its address to an indirect operation.
- **Result region:** two consecutive 32-bit words, with the second four bytes after the first. Calls receiving the region receive the address of its first word.

On successful acquisition, the first result word is replaced with a fixed global 32-bit datum, and the second is replaced with zero.

These regions belong to the current invocation. Their addresses can be used during calls. The evidence establishes neither an ownership transfer nor a valid lifetime extending beyond the invocation. In particular, exposing the pointer slot allows a callee to retain an alias for use by another dependency **before this function returns**.

### Output

The return is a 64-bit packed value:

| Bit range | Contents |
|---|---|
| 31–0 | Final 32-bit status |
| 63–32 | Contents of the object-pointer slot when the return is formed, after F-289ec4311c64 returns |

This specifies bit composition, not memory byte order, a register assignment, or signed interpretation of the complete value.

The upper word is not necessarily the original pointer, a non-null pointer, or a live owned reference. A pointer-slot value used for an earlier null check or dispatch need not equal the value ultimately returned.

### Preconditions for ordinary completion

The selected execution path requires:

- A non-null input object.
- Non-null results from both acquisition dependencies.
- Valid readable dispatch-bearing objects and callable entries at the selected offsets.
- A readable and writable context byte at offset 28.
- On successful submission, a readable 32-bit context field at offset 12 and an argument acceptable to F-682a0c9a8e8e after the field’s value is increased by four.
- Valid storage and object lifetimes for all selected calls.
- Normal return from every selected dependency other than the designated nonreturning failure dependency.

The function does not visibly validate these memory and lifetime conditions.

## Behavior

### Acquisition and failure

The function first initializes its local pointer slot and two result words from the inputs.

Acquisition is short-circuited in this order:

1. A null input object selects failure without either acquisition call.
2. Otherwise, F-6693aefb6551 receives the original input object.
3. A null result selects failure without calling the second acquisition dependency.
4. Otherwise, F-882285eeb45e receives the associated object returned by F-6693aefb6551.
5. A null result from F-882285eeb45e selects failure.

Each acquisition failure invokes F-a817d8d58c10, identified in the supplied representation as nonreturning. There is no visible ordinary status return or common-completion sequence on these paths. Whether this dependency terminates execution or transfers control elsewhere is unresolved.

The associated object from the first acquisition remains the object selected for a later success-branch dispatch. The object from the second acquisition supplies the initial indirect operation.

### Result initialization and initial dispatch

After both acquisitions succeed, the function reads the fixed global 32-bit datum into the first result word, then sets the second result word to zero. The global read occurs after the acquisition calls; no entry-time snapshot is used.

The function obtains the dispatch-table pointer from the second acquired object, selects its entry at byte offset 0, and invokes it with:

- That acquired object.
- The address of the first result word.
- A literal zero.

The indirect operation returns a 32-bit value and has access to the exposed result region.

A zero return selects status 12. Conversion, submission, and success-only operations are then skipped.

Any nonzero return enables conversion and submission. Its magnitude and sign do not otherwise determine the visible behavior.

### Conversion and submission

The enabled path performs these calls in order:

1. F-8810f53aaa0b receives the current second result word.
2. F-44362605ab79 receives the address of the first result word.
3. F-e7f9d47b9573 receives:
   - The original input object.
   - The 32-bit result from F-44362605ab79.
   - The earlier result from F-8810f53aaa0b, decreased by one.

The third submission argument is derived from the saved conversion result, not from a fresh read of the second result word after F-44362605ab79. Changes to result storage during that intervening call do not replace the earlier conversion result.

The decrement is a 32-bit integer operation without a visible bounds check. A conversion result of zero yields −1, whose 32-bit representation is all ones. At the minimum signed 32-bit value, a portable signed-overflow rule is not established by the supplied representation.

The return from F-e7f9d47b9573 becomes the status. A nonzero status bypasses the success-only operations and proceeds to common completion.

### Success-only operations

Only a zero submission status enables this stage.

The function reads the 32-bit field at context offset 12, increases that field’s value by four, and passes the result to F-682a0c9a8e8e. This is arithmetic on the **loaded field value**, not an access to context offset 16.

No null, alignment, range, or overflow check is visible for the derived argument. Arithmetic behavior outside the representable signed range remains unresolved.

The 32-bit return from F-682a0c9a8e8e is compared with −1:

- **Equal to −1:** F-32f0109f8437 receives the original input object. The associated-object dispatch described below is skipped.
- **Any other value:** The function reads the associated object’s dispatch-table pointer and selects its entry at byte offset 12. That entry receives the associated object and the address of the local object-pointer slot.

After the offset-12 dispatch returns, the function reads the pointer slot:

- If the observed value is null, the offset-8 dispatch is skipped.
- If it is non-null, the function obtains that object’s dispatch-table entry at byte offset 8 and invokes it.

The offset-8 invocation has no explicit arguments in the supplied representation. Its calling convention, implicit receiver handling, and ownership effects are not established.

The null check controls only whether this offset-8 call occurs. It does not fix the eventual upper return word. The offset-12 dispatch has received the slot’s address and could make an alias available to another call during this invocation. Later calls, including F-289ec4311c64, have unknown effects through such aliases.

Neither success branch visibly assigns a different status; it remains zero.

### Common completion

Every path reaching ordinary completion performs the following sequence:

1. Read the context byte at offset 28.
2. Clear bit 0 and write the byte back to the same address.
3. Call F-289ec4311c64 with the address of the first result word.
4. Form the packed return from the status and the then-current pointer-slot contents.

The byte update preserves bits 1–7 as observed by this late read. Earlier dependency changes to that byte are therefore incorporated rather than overwritten from an entry-time snapshot.

The final dependency runs after this direct write. Its effects are unknown: the context bit is not guaranteed to remain clear, and a previously exposed pointer slot is not guaranteed to retain its earlier contents. The upper return word reflects the slot after this dependency returns.

## Side effects

### Direct effects

The function directly:

- Initializes local result storage and a local pointer slot.
- Reads a fixed global 32-bit datum after acquisition.
- Exposes result storage to three selected operations.
- Conditionally exposes the pointer slot to an indirect operation.
- Conditionally reads the context field at offset 12.
- Reads and writes the context byte at offset 28.
- Performs the dependency calls and dispatches in the stated order.

There is no visible direct heap allocation or deallocation. This does not establish that dependencies avoid allocation, deallocation, retention, or invalidation.

### Aliasing and ownership

The writable pointer slot is a local copy of the input pointer. The function does not directly update caller-owned storage holding that input pointer.

Once the slot’s address is exposed, its contents may change during later calls through a retained alias. A null value observed immediately after the offset-12 dispatch establishes only that the next indirect operation is skipped. It does not establish a null final return value without an additional no-intervening-modification assumption.

No ownership convention is established for the original input object, either acquired object, a replacement pointer, or data represented by the result words. F-32f0109f8437, the offset-8 indirect operation, and F-289ec4311c64 must not be specified as proven release or destruction operations.

### Error behavior

- Acquisition failures invoke the nonreturning dependency.
- A zero initial indirect result selects status 12.
- A nonzero submission result is returned as the low word without visible translation.
- The −1 result from F-682a0c9a8e8e selects an operation; it is not returned as the status.

No rollback, exception recovery, invalid-pointer recovery, or guaranteed completion following abnormal callee control transfer is visible.

## Acceptance examples

These examples are conditional consequences of the static representation, not executed tests. Unless stated otherwise, they assume valid memory and normal return from the selected calls.

1. **Null input.**  
   Neither acquisition dependency runs. F-a817d8d58c10 is invoked, with no visible ordinary return or common completion.

2. **Failed second acquisition.**  
   If F-6693aefb6551 returns non-null and F-882285eeb45e returns null, failure is selected. The fixed global datum has not yet been copied into result storage.

3. **Initial operation returns zero.**  
   The low return word is 12. Conversion, submission, and success-only operations are skipped. The context-byte update still precedes F-289ec4311c64.

4. **Submission returns 7.**  
   The low return word is 7. F-682a0c9a8e8e and both success alternatives are skipped. Common completion still occurs.

5. **Conversion ordering.**  
   If F-8810f53aaa0b returns 5, the third submission argument is 4. F-44362605ab79 runs before submission; changing the second result word during that call does not replace the saved 5.

6. **Successful sentinel branch.**  
   If submission returns zero and F-682a0c9a8e8e returns −1, F-32f0109f8437 receives the original input. The offset-12 dispatch is skipped, and the status remains zero.

7. **Null replacement without later modification.**  
   On the non-sentinel success branch, suppose the offset-12 dispatch writes null into the pointer slot. The subsequent null check skips the offset-8 dispatch. **If no intervening call modifies the slot**, including F-289ec4311c64, the upper return word is zero.

8. **Null replacement followed by alias-mediated modification.**  
   Suppose the offset-12 dispatch writes null and retains an alias usable during the invocation. The null check skips the offset-8 dispatch. If F-289ec4311c64 subsequently uses that alias to store another pointer, the upper return word contains that later pointer, not zero.

9. **Non-null replacement.**  
   If the post-dispatch slot observation is non-null, that object supplies the offset-8 dispatch. The upper return word equals that observed pointer only if no subsequent selected call changes the slot.

10. **Late byte preservation.**  
    If the context byte is 0xB7 at the common-completion read, the function writes 0xB6 before F-289ec4311c64. Its value after that dependency is not guaranteed.

## Evidence

Established static evidence comprises the null-check sequence, dependency order, selected dispatch offsets, 32-bit words and pointers, byte-sized context update, constants zero, 12, and −1, and packed return composition. It also establishes that F-289ec4311c64 executes before the pointer slot is used to form the return.
