# F-27a8b3e4f72c

## Behavior

### Transformation

The first represented operation invokes F-283eda65a14c with the original fourth input as its sole argument. Its 32-bit result is retained for the later indirect invocation.

No read through the first input and no destination-entry load is shown before that dependency invocation. Consequently, an invalid first input does not, by itself, establish that the wrapper fails before entering F-283eda65a14c.

If the dependency does not return normally, the represented lookup and dispatch are not reached. The wrapper shows no timeout, retry, alternative transformation, or local recovery path.

Nothing supplied about F-283eda65a14c establishes that it preserves global state, the storage addressed by the first input, or storage later used for destination selection.

### Destination lookup

After F-283eda65a14c returns, the wrapper reads the 32-bit integer at the address supplied as the first input.

The loaded value is then used as the lookup base with a fixed displacement of **0x104 bytes, or 260 bytes**. The wrapper loads the indirect destination from the resulting location.

The displacement is relative to the loaded base, not directly relative to the original first-input address. The established lookup therefore consists of two distinct memory reads:

1. Reading the 32-bit base through the first input.
2. Reading the destination entry at the displaced address.

The source representation expresses the displacement through integer addition before interpreting the result as destination-entry storage. It does not provide a complete address-arithmetic model. In particular, this contract does not promise modular wraparound, valid addressing across an integer boundary, or a defined outcome when the addition is not representable.

The second read obtains an executable destination through pointer-like storage. Its physical width, alignment requirements, and byte order are not independently established.

A dispatch-table interpretation is plausible, but not required by the evidence. If entries were four bytes wide and the base identified the beginning of a contiguous table, the displacement would correspond to zero-based entry 65. Those conditions are not established, so entry numbering must not replace the byte-displacement requirement.

On the represented normal path, there is one invocation of F-283eda65a14c followed by one indirect invocation. No local loop, fallback destination, or repeated dispatch is shown.

- The address held in the original first-input pointer must support the 32-bit read when that read occurs after F-283eda65a14c returns.
