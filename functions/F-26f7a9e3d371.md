# F-26f7a9e3d371

## Purpose

F-26f7a9e3d371 is represented as a state-mutating procedure that interleaves indirect calls with byte and 32-bit memory accesses. After a finite prefix, it enters an unconditional repeating call-and-write phase.

No application-level purpose is established. Address arithmetic and repetitive writes do not establish serialization, allocation, device access, initialization, or decoding.

This contract distinguishes:

- **Established static evidence:** operations, data dependencies, access widths, and ordering explicitly present in the supplied representation.
- **Inferred intent:** possible purpose not established by those operations.
- **documented_only:** behavior that cannot be resolved without additional instruction, ABI, dependency, or memory-model evidence.

All behavioral descriptions are conditional on the supplied representation accurately describing reachable execution and on preceding calls and accesses completing. Its diagnostics report invalid instruction data, removed unreachable regions, and overlapping global symbols.

## Behavior

### Call-sequence conventions

A **five-call chain** contains exactly five calls: one leading call with the stated explicit arguments, then four calls with no explicit arguments. Its result, when used below, is the ordinary result of the fifth call. Intermediate results are not implicitly forwarded unless stated.

“No explicit arguments” describes the representation, not a verified ABI signature.

A recurring **nine-call sequence** has the following structure:

| Call position | Explicit argument relationship |
|---|---|
| 1 | Initial arguments specified for the sequence. |
| 2 | No explicit arguments; produces a first intermediate result. |
| 3 | Consumes that first intermediate result. |
| 4 | No explicit arguments; produces a second intermediate result. |
| 5 | Consumes the second intermediate result, with any stated additional argument. |
| 6–9 | No explicit arguments. |

Calls 5–9 are the five-call chain within this sequence. Thus, call 3 is the first intermediate-result consumer and call 5 is the second. There is **not** an additional result-consuming call before the chain. The sequence result is the ordinary result of call 9.

This nine-call structure applies to the sequences associated below with A, B, D, E, I, and L.

### Unconditional repeating phase

The first chain’s leading arguments are the retained repeating argument and R logically shifted right by eight. Its completion is followed by a fresh selector read at the final selector base plus one and a zero-byte store at the selected destination.

The second chain begins with the first chain’s final result shifted left by two. Its final result determines both pieces of state for the next iteration:

- The next retained repeating argument is that result shifted left by two.
- The next R is that result shifted left by 26.

There is no represented exit condition. The selector base remains the one derived from U, but its selector byte is read anew each iteration.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initial byte extraction.** With first argument `0xABCDEF12`, the first byte-store value is `0x12` and the second is `0xAF`. Each store requires its own selector read.

2. **Selector mutation.** If the incoming selector is initially 3, the first destination is `0x14`. If a dependency changes it to 9 before the second selector read, the second destination is `0x1A`.

3. **Third-argument boundary.** Third arguments 127 and 128 select destinations `0x14` and `0x18`, respectively, for both captured-G stores.

4. **Captured global.** If G is captured as `0x11223344`, both explicit G stores use that value even if a dependency subsequently changes the global.

5. **Nine-call boundary.** For each B-, D-, E-, I-, or L-associated nine-call sequence, the next described direct write follows call 9. Call 3 consumes call 2’s result; call 5 consumes call 4’s result and is already the leading call of calls 5–9. An extra consumer before that chain would produce a different call sequence.

6. **Write-before-read alias.** If A is zero and accesses complete, the procedure writes zero at `0x14` before capturing W from `0x14`. With ordinary memory and no external modification, W is zero.

7. **Captured-word extraction.** If W is `0x89ABCDEF`, its shifts by sixteen, 24, and 31 yield `0x89AB`, `0x89`, and 1. The later direct byte destination derived from W is `0x1D`.

8. **Ordered aliasing.** If S plus one equals that direct byte destination, the U-derived byte write occurs before the following selector read. Under ordinary-memory semantics, that read observes the newly written byte absent another modifier.

9. **Repeating-phase entry.** If Z is `0xFFFFFFFF`, initial R is 31. The pre-loop call receives 62, and the first repeating chain receives zero as its second leading argument.
