# F-6ec4235d8ea3

## Purpose

F-6ec4235d8ea3 conditionally processes a byte sequence through a decoding dependency and records selected decoded values in a bitmap associated with a dispatch-provided state object.

For each decoding result, a decision dependency receives the state address and the value’s bitmap coordinates. A zero decision result causes this function to increment a count-like field and set the selected bitmap bit. A nonzero decision result suppresses those direct updates.

The function returns no value. Its observable behavior consists of dependency calls, sequence-byte checks, and conditional state accesses.

**Inferred intent:** the state may represent a collection of decoded values, with a count of accepted or newly recorded entries. Character encoding, membership testing, uniqueness enforcement, and the meaning of the count are not established.

## Interface

| Opaque argument | 32-bit quantity | No explicit use or forwarding appears in this function. |

The result is void: no success flag, count, state address, or error value is returned.

The handle normalization mask is `0xfffffffe`. Only the least significant bit is removed:

- Handles `0` and `1` both normalize to zero.
- Handles differing only in bit 0 select the same object address.
- Other low bits are not cleared.
- No address-validity or alignment check follows normalization.

## Behavior

### Handle gate and dispatch

The function first clears bit 0 of the tagged handle.

If the resulting address is zero, it returns immediately. It does not initialize or inspect the sequence cursor, read object storage, or call any dependency.

For a nonzero normalized address, the function:

1. Initializes local cursor storage with the supplied sequence address.
2. Reads the object’s dispatch-table address.
3. Invokes the indirect entry at dispatch-table byte offset 40.
4. Tests the returned 32-bit state representation for zero.

The exposed indirect invocation supplies no explicit arguments. A receiver convention, implicit arguments, or a complete callable signature cannot be established.

A zero dispatch result ends processing without an explicit sequence-byte read by this function. The dispatch dependency itself may have side effects, including sequence changes; those effects are not constrained by this body.

A nonzero result becomes the retained state address used for subsequent decision calls and direct state accesses.

**The first sequence-byte check occurs after dispatch returns.** A zero byte present before dispatch does not guarantee that decoding will be skipped: the unknown dispatch dependency may modify the sequence before that check.

If the byte at the cursor is zero when the first post-dispatch check actually occurs, the function performs no decoding, decision calls, or direct count and bitmap updates.

### Loop-entry check and decoding

At each loop check, the function reads the byte addressed by the cursor’s value at that time:

- Zero ends the loop.
- Nonzero causes one call to F-d3922c7fe0ec.

F-d3922c7fe0ec receives the address of local cursor storage. It can therefore change the cursor, rather than merely inspect bytes at its current address. Its return value is consumed as unsigned 32-bit data.

There is no separate cursor increment in this function. It neither verifies forward progress nor checks that a replacement cursor remains within the original sequence.

Passing the cursor’s address establishes that the decoder can modify it. It does **not** establish that the value present immediately after decoding remains unchanged until the next loop check. The decoder could expose the cursor-storage address to another dependency. Permitted aliasing or other unknown effects could also alter that storage during intervening operations.

Consequently, the next check uses the cursor value present **after the decision call and any conditional updates**, not an assumed preserved decoder output.

The loop termination condition is independent of the decoded value. A decoder return of zero is processed normally when the preceding loop-entry byte was nonzero.

### Coordinate calculation and decision

For each unsigned 32-bit decoded value, the function calculates:

- **Word index:** the value divided by 32, discarding the remainder.
- **Bit index:** the low five bits, ranging from 0 through 31.

It calls F-88658862e573 with these explicit arguments, in order:

1. Retained state address.
2. Word index.
3. Bit index.

Only the distinction between zero and nonzero return values matters to this function.

A nonzero result skips the caller’s direct count and bitmap updates. It does not establish that the dependency preserved state, sequence bytes, cursor storage, globals, or other memory.

There is no additional range, capacity, encoding, or uniqueness check between decoding and the decision call.

### Accepted update

When F-88658862e573 returns zero, the function performs the following direct state operations:

1. Reads the 32-bit count-like field at state offset 4.
2. Increments it by one and writes the result to that field.
3. Evaluates the bitmap update using the bitmap-base field at state offset 8.
4. Reads the selected 32-bit bitmap word, combines it with the selected one-bit mask using bitwise OR, and writes the result.

The count access occurs after the decision dependency returns. The count write precedes the bitmap expression, including its bitmap-base accesses.

The bitmap-base field is not cached before the decision call or before the count write. Changes made by the decision dependency therefore affect the subsequently evaluated update. If storage aliases, the count write may itself affect storage used by the bitmap expression.

The supplied expression references the bitmap-base field for both the word read and the destination. It does not establish one indivisible base snapshot or a complete ordering of all reads within that expression. Under stable, nonoverlapping storage, both references select the same word. Stronger behavior under concurrent changes or unusual aliasing is not established.

An already-set bit does not suppress the count increment or bitmap write when the decision result is zero. Deduplication, if any, must come from dependency behavior rather than an additional test here.

After either decision outcome, control returns to the next cursor-byte check.

## Side effects

The function directly modifies:

- Local cursor storage during initialization.
- The count-like field on a zero decision result.
- A selected bitmap word on a zero decision result.

F-d3922c7fe0ec additionally receives write access to the cursor through its address. The function contains no explicit sequence-buffer write, allocation, release, ownership transfer, logging, or error reporting.

## Acceptance examples

These are conditional static expectations, not runtime results. Unless stated otherwise, assume valid nonoverlapping storage, defined arithmetic, normal dependency returns, and no interfering changes.

1. **Masked-null handle.** Handle `0` or `1` causes immediate return without dispatch or sequence access. A readable sequence address is unnecessary on this path.

2. **Tag equivalence.** Handles `0x2000` and `0x2001` normalize to the same object address. With otherwise identical dependency behavior and storage, bit 0 does not distinguish processing.

3. **Zero dispatch result.** If dispatch returns zero, this function does not inspect the sequence byte or call either named dependency. Dispatch’s own effects remain possible.

4. **Zero at the first actual check.** If dispatch returns a nonzero state and the cursor points to a zero byte at the first check after dispatch, no decoder or decision call occurs, and the caller performs no count or bitmap update.

5. **Initially zero, then changed by dispatch.** Suppose the supplied sequence begins with zero before dispatch. If dispatch replaces that byte with a nonzero byte and returns a nonzero state, the first check observes nonzero and invokes the decoder. Initial emptiness alone does not suppress decoding.

6. **Coordinate boundary.** A decoded value of `31` produces decision coordinates `(0, 31)`. A value of `32` produces `(1, 0)`. These argument expectations do not require resolving high-bit mask semantics.

7. **Ordinary accepted update.** A decoded value of `37` produces coordinates `(1, 5)`. If the decision returns zero, the count is `7` when read, and the selected bitmap word is stably `0x00000004`, the caller writes count `8` before writing bitmap word `0x00000024`.

8. **Nonzero decision.** For value `37`, any nonzero decision result suppresses the caller’s direct updates. Dependency-originated changes remain possible.

9. **Repeated acceptance.** Two decoded values of `37`, each followed by a zero decision result, cause two count increments when both increments are defined. The second OR may leave the bitmap word numerically unchanged.

10. **Decoded zero.** A nonzero loop-entry byte followed by a decoder return of zero produces decision coordinates `(0, 0)`. The returned zero does not itself end the loop.

11. **Post-decoder cursor change.** Suppose the decoder exposes the cursor-storage address and leaves the cursor at a nonzero byte. If the decision dependency then changes that cursor to point to a zero byte, and no subsequent operation changes it again, the next check terminates processing. The decoder’s earlier cursor value does not control that check.

12. **Non-progressing execution.** If every check continues to find a nonzero byte and dependencies return normally, the function can continue indefinitely. No iteration limit is imposed.
