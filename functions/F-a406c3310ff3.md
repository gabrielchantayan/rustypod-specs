# F-a406c3310ff3

## Purpose

F-a406c3310ff3 selects the larger of two unsigned arithmetic candidates derived from one input:

- An additive candidate: the input plus 32.
- A proportional candidate: the input plus its right-shifted-by-one and right-shifted-by-three values.

The comparison occurs **after the candidate arithmetic has taken place**. Consequently, if the arithmetic uses fixed-width unsigned wraparound, this is a maximum of wrapped candidates—not a mathematical maximum computed with unlimited precision.

The apparent intent is to provide a growth amount that is at least an additive increment for small inputs and approximately 1.625 times the input for larger inputs. That intent is inferred, not an established allocation, capacity, or memory-safety guarantee. The supplied function does not allocate storage or identify what the input measures.

## Behavior

### Candidate definitions

Let \(x\) denote the input. Under the 32-bit unsigned interpretation, define the additive candidate as:

\[
A=(x+32)\bmod 2^{32}.
\]

Define the proportional candidate as:

\[
P=
\left(
x+
\left\lfloor\frac{x}{2}\right\rfloor+
\left\lfloor\frac{x}{8}\right\rfloor
\right)\bmod 2^{32}.
\]

The output is:

\[
\max_{\text{unsigned}}(A,P).
\]

The two divisions in this description represent the numerical effects of unsigned right shifts. They each discard their own fractional part. They must not be replaced indiscriminately with a single rounded multiplication by 1.625.

For example, at input 55, the proportional candidate is:

\[
55+27+6=88.
\]

Taking the floor of \(55\times1.625\) instead would produce 89 and would not match this contract.

### Selection rule

The proportional candidate is selected when it is greater than or equal to the additive candidate. Otherwise, the additive candidate is selected.

Equality therefore follows the proportional-selection branch in the supplied representation. Since both candidates are ordinary integer values and are equal in that case, the branch choice creates no distinct return value or ownership consequence.

There is no saturation, overflow error, retry, or special treatment of large inputs. In particular, an implementation must not replace the arithmetic with a saturating growth calculation if compatibility with the supplied behavior is required.

### Arithmetic width and intermediate results

For 32-bit unsigned arithmetic, additions are reduced modulo \(2^{32}\). An intermediate addition in the proportional calculation may wrap before the final addition. Modular addition makes the resulting candidate equal to the formula above.

Using a wider temporary is behaviorally equivalent only if the candidate is reduced to the required unsigned width **before comparison**. Comparing unbounded or widened candidates and narrowing only the selected result can choose the wrong candidate.

The additive candidate is also subject to wraparound. The number 32 is an increment, not a minimum result and not a promise that the output exceeds the input by 32.

### Small inputs and crossover

For inputs near zero, the additive candidate is larger.

Ignoring overflow in this small range, the proportional candidate exceeds the additive candidate precisely when:

\[
\left\lfloor\frac{x}{2}\right\rfloor+
\left\lfloor\frac{x}{8}\right\rfloor>32.
\]

The candidates are equal at inputs 52 and 53. At input 54, the proportional candidate is larger. There is no discontinuous application-specific rule at that crossover; it follows directly from the arithmetic and comparison.

### Large inputs

Unsigned wraparound can invalidate intuitive growth properties:

- The result need not exceed the input.
- The result need not exceed the input by 32.
- Increasing the input need not increase the output.
- The proportional candidate can become numerically smaller after wrapping.
- Near the unsigned maximum, the additive candidate can wrap to a small value.

The function offers no separate indication that any wraparound occurred.
