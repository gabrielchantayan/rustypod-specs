# F-6dd003795db7

## Purpose

F-6dd003795db7 wraps F-337a2fdf4aae, conditionally invokes a second dependency, publishes a 32-bit status, and returns a 64-bit value containing both a dependency result and an incoming value.

The established behavior is structural: delegation, a status-and-ordering gate, two arithmetic arguments to the conditional dependency, a final status write, and return-value packing. The available evidence does **not** establish that the conditional dependency clears, initializes, frees, validates, or otherwise modifies a memory range. Any such interpretation is inferred intent, not part of the established contract.

This specification describes the supplied static representation. No runtime tests have been performed.

## Interface

The function has six inputs and one 64-bit return value.

| Position | Descriptive name | Established representation | Role |

| 1 | Opaque input | 32-bit value | Forwarded to F-337a2fdf4aae without visible interpretation. |
| 2 | Scale | Signed 32-bit integer | Forwarded to F-337a2fdf4aae; used in both conditional arithmetic arguments. |
| 3 | Lower index | Signed 32-bit integer | Forwarded to F-337a2fdf4aae; compared with the upper index and used in arithmetic. |
| 4 | Upper index | Signed 32-bit integer | Forwarded to F-337a2fdf4aae; compared with the lower index and used in arithmetic. |

The descriptive names identify observable roles, not asserted application meanings. In particular, “scale” need not be an element size, and the two indices need not identify a valid allocation.

The return value has this bit layout:

- Bits 63–32: the incoming return tag, unchanged.
- Bits 31–0: the 32-bit result returned by F-337a2fdf4aae.

This is bit-field concatenation. A negative signed result from F-337a2fdf4aae contributes its 32-bit representation to the low half; it does not sign-extend over the return tag. The return tag and low result are not added.

The status destination is separate from the packed return value. The supplied representation does not establish which return-value interpretation callers use: unsigned integer, signed integer, or two logical fields.

## Behavior

### Initial delegation

The function first establishes a local 32-bit status value of zero.

It then calls F-337a2fdf4aae exactly once on the visible normal path. The first five inputs are forwarded in their original order. The sixth argument to that dependency is the address of the local status, **not** the caller’s status destination.

F-337a2fdf4aae therefore receives status storage that initially contains zero and may replace that value. Its 32-bit return value is retained independently of the status.

The caller’s status destination is not visibly written before this dependency call. This does not imply that arbitrary caller-visible memory remains unchanged: the dependency’s other effects are unknown.

### Conditional dependency invocation

After F-337a2fdf4aae returns, the wrapper evaluates a short-circuit condition:

1. Read the local status and compare it with zero.
2. Only if that comparison succeeds, compare the lower index with the upper index using signed ordering.

The second dependency, identified here as D-1, is invoked only when both conditions hold:

- The status observed for the gate is zero.
- The lower index is strictly less than the upper index.

Equality does not qualify. A nonzero status prevents the invocation regardless of index ordering. The sign or magnitude of the first dependency’s return value does not independently affect this gate.

When invoked, D-1 receives two arguments, in this order:

1. The retained dependency result plus the product of the scale and lower index.
2. The product of the scale and the difference between upper and lower indices.

The first expression has the shape of a base-plus-offset calculation, and the second has the shape of an extent calculation. Those shapes do not establish the arguments’ semantic types or D-1’s operation.

There is no visible third argument. D-1’s return value, if any, is not used by the wrapper.

The supplied representation establishes the argument expressions, but not their evaluation order relative to each other.

### Arithmetic boundaries

The arithmetic operands are represented as 32-bit integers. The upper-minus-lower subtraction, both multiplications, and the final addition have no visible widening, checked-arithmetic operation, overflow test, saturation, or bounds validation.

A signed lower-than comparison does not by itself make the subsequent subtraction representable. For example, a sufficiently negative lower index and sufficiently positive upper index satisfy the gate while their mathematical difference exceeds the maximum signed 32-bit value.

Likewise:

- A positive index difference does not guarantee a positive representable product.
- A negative scale is not rejected.
- A zero scale is not rejected.
- The calculated first argument is not visibly checked against any allocation.
- No visible condition requires the retained dependency result to represent a valid base address.

The exact outcomes of overflowing arithmetic are **documented_only**. The static representation is insufficient to establish a portable signed-overflow contract or guarantee modulo-\(2^{32}\) behavior. Conditional acceptance examples below use representable arithmetic.

### Final status publication and return

After the conditional path either completes or is skipped, the wrapper writes the current local status to the caller’s status destination.

The ordering is significant:

- The first dependency completes before the final status write.
- If D-1 is invoked, it completes before the final status write.
- The visible normal return follows the status write.

The final store uses the status value current at that point. It is not specified as a snapshot captured before D-1. Although D-1 does not directly receive the status pointer from this wrapper, F-337a2fdf4aae did receive it. The available evidence does not exclude indirect access or retention by dependencies.

The function then returns the packed 64-bit value described under Interface. No additional local error translation, cleanup, or return-code selection is visible.

If a dependency does not return normally, the later status write and packed return are not established as occurring.

## Acceptance examples

These examples are conditional static expectations, not runtime results. Unless stated otherwise, dependencies return normally, the status destination is valid, arithmetic is representable, and dependencies do not alter the local status beyond the stated writes.

1. **Enabled conditional path.**  
   Scale is 4, lower index is 2, upper index is 5, and F-337a2fdf4aae returns 1000 while leaving status zero. D-1 is called with first argument 1008 and second argument 12. The final status is zero.

2. **Nonzero status suppresses D-1.**  
   With the same indices, F-337a2fdf4aae writes status 7. D-1 is not called. The final status destination receives 7. The packed return still contains the dependency result and incoming return tag.

3. **Equal indices suppress D-1.**  
   With status zero and both indices equal to 5, D-1 is not called. The wrapper still publishes status and returns the packed value.

4. **Reversed indices suppress D-1.**  
   With status zero, lower index 6, and upper index 5, D-1 is not called. No visible error status is generated merely because of that ordering.

5. **Zero scale does not suppress the call.**  
   With status zero, scale 0, lower index 2, upper index 5, and dependency result 1000, D-1 is called with arguments 1000 and 0.

6. **Negative indices are not automatically rejected.**  
   With status zero, scale 4, lower index −2, upper index 1, and dependency result 1000, D-1 is called with arguments 992 and 12.

7. **Return packing preserves both halves.**  
   If the return tag is hexadecimal 12345678 and the dependency result has 32-bit representation FFFFFFFF, the return representation is hexadecimal 12345678FFFFFFFF. The low field does not replace or sign-extend across the high field.

8. **Final status can differ from the gate value.**  
   If the gate observes zero and D-1 subsequently changes the local status to 9 through an indirect access made possible by dependency behavior, the final destination receives 9. This example specifies the final-read ordering; it does not assert that such indirect access actually occurs.
