# F-56d06c91b163

## Purpose

F-56d06c91b163 selects one of three fixed-size dispatch records using a two-part match against its first argument, optionally obtains an auxiliary value through an object operation, and invokes the selected record’s callback.

The established behavior is selection and dispatch, not a particular application-level operation. The first argument is passed to comparison and length-like dependencies, which suggests a text or byte-sequence key. Its actual representation and validity requirements are not established.

The function has three explicit early-return conditions:

- The second argument is zero.
- None of the three records matches.
- A conditionally required auxiliary operation returns zero.

Otherwise, the selected callback determines the returned 32-bit value.

## Behavior

### Entry and zero-second-argument handling

The table base is obtained before the second argument is tested.

If the second argument is zero, the function returns `0xFFFFFFCF`. No record matching, auxiliary-object lookup, or callback invocation follows on this path.

Thus, “zero second argument” does not mean that the function performs no reads: the initial global table-base read precedes the rejection.

### Ordered selection

For a nonzero second argument, candidates are considered in increasing record order: first, second, then third.

For each candidate, the function invokes F-fca51b715561 with:

1. The candidate’s 32-bit field at offset 4.
2. The caller’s first argument.
3. The signed 16-bit narrowing of the candidate’s 32-bit word at offset 8.

A nonzero result rejects that candidate immediately. F-1cb585febd84 is not invoked for that candidate.

A zero result enables the second matching condition. The function calls F-1cb585febd84 with the caller’s first argument, adds one using 32-bit unsigned arithmetic, and compares that result with the candidate’s unsigned 16-bit field at offset 8.

The candidate matches only if the values are equal.

Important width consequences are:

- Addition is modulo \(2^{32}\), not an unbounded mathematical increment.
- The field used for equality is zero-extended from 16 bits.
- A dependency result of `0xFFFFFFFF` becomes zero after the increment and can therefore match a zero-valued halfword.
- A successful comparison by F-fca51b715561 alone is insufficient.
- The halfword used for the second condition is read after F-1cb585febd84 returns. It is not established to be a snapshot taken before either dependency call.

The first candidate satisfying both conditions wins. Later records are not examined.

If all three candidates fail, the function returns `0xFFFFFFCE`. It does not obtain an auxiliary object or invoke a record callback on this path.

### Captured base and mutable records

Candidate addresses are derived from the initially captured table base. The function does not visibly reload the global table-base location between candidates.

This distinguishes two kinds of mutation:

- Replacing the global table base during a dependency call does not visibly redirect the current search.
- Modifying storage reachable through the captured base can affect later reads, including reads from the current candidate.

There is no visible table lock, snapshot copy, version check, or revalidation. This description does not assume that any dependency preserves global state or table contents.

### Conditional auxiliary processing

After a candidate matches, the initial auxiliary value is zero.

The selected record’s 32-bit selector is tested using unsigned subtraction:

\[
(\text{selector} - \texttt{0x6001}) \bmod 2^{32} < \texttt{0xF3}.
\]

This is equivalent, for a 32-bit selector, to membership in the inclusive interval `0x6001` through `0x60F3`.

For a selector outside that interval:

- F-23e8d37d5f69 is not called.
- No object operation is invoked.
- The callback’s first argument remains zero.

For a selector inside that interval, the function calls F-23e8d37d5f69 with a single argument of zero.

The returned value is treated as an object address. The function reads an operation-table address from the object’s first 32-bit word, obtains a callable address at byte offset `0xDC` in that table, and invokes it with:

1. The object address.
2. The selected record’s selector.
3. The constant `0x6000`.

The selector passed to the operation is read after F-23e8d37d5f69 returns. Consequently, the value used to enter this branch and the value passed to the operation need not be identical if that dependency changes the selected record.

The operation’s result becomes the auxiliary value. If it is zero, the function returns `0xFFFFFFD1` without invoking the record callback. Any nonzero 32-bit result, including a value interpreted as negative in a signed representation, passes this local check.

There is no visible null check on the returned object or its operation-table pointer before dereference.

### Callback invocation

After selection and any required auxiliary processing, the function invokes the callback addressed by the selected record’s field at offset 12.

The callback receives, in order:

1. The auxiliary value: zero when auxiliary processing was skipped, otherwise the nonzero result of the object operation.
2. The caller’s second argument, unchanged.
3. The caller’s third argument, unchanged.
4. The selected record’s 32-bit field at offset 16.

The callback address and fourth argument are obtained after the preceding dependency calls. Changes to those fields made by earlier dependencies can therefore affect dispatch.

The callback’s return value is returned unchanged. No visible cleanup, result translation, or further table traversal follows.

The supplied representation does not establish a finer ordering among independent argument-field reads during preparation of an individual call.

## Acceptance examples

These are conditional contract examples derived from static evidence. They are not executed test results. Unless stated otherwise, assume valid memory, normal dependency returns, and no mutation of relevant record fields during calls.

1. **Zero second argument.**  
   Given a zero second argument, the result is `0xFFFFFFCF`. The table-base read still occurs, but no matching dependency or callback is invoked.

2. **Three immediate comparison failures.**  
   Given a nonzero second argument and nonzero results from F-fca51b715561 for all three records, that dependency is called three times in record order. F-1cb585febd84 is never called. The result is `0xFFFFFFCE`.

3. **Comparison succeeds but the second condition fails.**  
   If the first candidate’s comparison returns zero, its halfword is 5, and F-1cb585febd84 returns 3, the increment produces 4. The first candidate is rejected and selection continues.

4. **First match prevents later examination.**  
   If the first candidate’s comparison returns zero and its halfword equals the incremented length-like result, the second and third records are not matched, even if they would also qualify.

5. **Unsigned wraparound can satisfy selection.**  
   If a candidate’s comparison returns zero, its unsigned halfword is zero, and F-1cb585febd84 returns the bit pattern `0xFFFFFFFF`, the wrapping increment is zero. The candidate satisfies the second condition.

6. **Auxiliary-range boundaries.**  
   With a selected record, selectors `0x6001` and `0x60F3` trigger auxiliary processing. Selectors `0x6000` and `0x60F4` do not. For either outside value, the callback receives zero as its first argument.

7. **Auxiliary failure.**  
   If the selected record requires auxiliary processing and the object operation returns zero, the result is `0xFFFFFFD1`. The selected callback is not invoked.

8. **Nonzero auxiliary result.**  
   If that operation returns `0xFFFFFFFF`, the callback is invoked with that exact first-argument bit pattern. The wrapper does not reject it as a negative error value.

9. **Callback result propagation.**  
   If the callback returns `0xFFFFFFCE`, the wrapper returns that value unchanged. The result alone does not prove that selection failed.

10. **Mutation between range test and object operation.**  
    If the selector initially lies in range, but F-23e8d37d5f69 changes it before returning a valid object, auxiliary processing still proceeds. The object operation receives the subsequently read selector, not necessarily the value that passed the range test.
