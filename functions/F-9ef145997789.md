# F-9ef145997789

## Purpose

F-9ef145997789 dispatches on a 32-bit selector and an object address. Admitted paths optionally invoke selector-specific dependencies, perform an initial accounting update, and then conditionally validate metadata and perform further accounting and dependency calls.

**Established static behavior:** Null objects and rejected selectors return without entering the shared accounting path. On admitted paths, the initial accounting writes occur before the derived-address sentinel test and header validation. Invalid metadata therefore does not prevent those earlier effects.

The initial accounting operation uses **four distinct reads of a global context address**, not one captured context for all accesses. Its source and destination addresses can differ unless stability of those global reads is guaranteed externally.

**Inferred intent:** The operation resembles type-directed cleanup followed by allocation accounting and allocation management. Destruction, storage release, and synchronization are not established semantics of the dependencies.

### Initial accounting: ordered observations and stores

The shared path first reads G and retains A₀ for the eventual high-word destination. It then reads the displacement at P − 4, derives B, and reads Q at B − 8.

The remaining initial-accounting observations occur in this order:

1. G is reread as A₁, and the 32-bit low source value **L** is read at A₁ + 56.
2. G is reread as A₂, and the high source address A₂ + 60 is formed. The high value is not yet read.
3. G is reread as A₃, and the low result is written at A₃ + 56.
4. The 32-bit high source value **H** is read through the previously formed address A₂ + 60.
5. The high result is written at A₀ + 60.

The stored values are:

- At A₃ + 56: \(L-Q\), reduced modulo \(2^{32}\).
- At A₀ + 60: \(H-(S+U)\), reduced modulo \(2^{32}\).

Here:

- **S** is Q interpreted as signed 32-bit and arithmetically shifted right by 31: zero if Q’s high bit is clear, otherwise −1.
- **U** is one if unsigned L is less than unsigned Q, otherwise zero.

The borrow condition uses the captured low source value L, not a reread of either low-word location.

The high source address is retained across the low store, but its contents are read afterward. If A₃ + 56 overlaps A₂ + 60, that high read observes the low store, absent another intervening change. If the low store changes G itself, it does not redirect either the already formed high source address or the initially captured high destination.

Only when all four context observations agree, with no interfering changes to the relevant values, does this operation have the ordinary interpretation of updating one two-word accounting pair. Under those conditions, the numerical result is subtraction of the **sign-extended signed 32-bit interpretation of Q** from that pair, modulo \(2^{64}\). It is not generally unsigned-Q subtraction, and the two stores are not atomic.

After the high store, the function invokes F-2fd8826557a4 without explicit arguments.

### Header validation

\[

The ordered updates are:

## Side effects

Explicit stores use the initial accounting addresses or C-relative accounting addresses. None is explicitly addressed through P or through the retained header pointer.

This is not a non-mutation guarantee for object storage or metadata. Accounting destinations can overlap either. In particular, C + 8 can equal B − 16, causing the final quantity subtraction to write the header directly.

Accounting destinations can also coincide with each other. A first index of 58 makes its destination C + 780, so the first two quantity updates affect the same word sequentially.

The initial operation additionally permits distinct low-source, low-destination, high-source, and high-destination contexts. A low store can affect the later high read through overlap. Treating the initial operation as one captured-context update would omit this behavior.

Later changes to global context selection do not redirect retained addresses. They may still change or invalidate the storage reached through those addresses.

No transaction, synchronization guarantee, rollback, or recoverable-error protocol is established. Effects already performed remain relevant if a subsequent dependency does not return or a later access cannot complete. Platform fault behavior is unknown.

## Acceptance examples

These are conditional static examples, not executed tests. Unless specified otherwise, relevant storage is valid, dependencies return and preserve the illustrated values, and unrelated mutation or overlap is absent.

1. **Null or rejected input.** P equal to zero returns for every selector. With nonzero P and selector zero, the function returns without dereferencing P.

2. **Flag gate.** For selector `0xFFFFFFFB`, byte `0x02` at P + 4 causes return. Bytes `0x04` and `0xFF` admit the shared path.

3. **Selector-call ordering.** For selector `0xFFFFFFF9`, a word value of 17 at P is passed to F-449926a4de34. F-206e19806905 subsequently receives P and zero. Shared-path reads occur afterward.

4. **Stable-context borrow.** If A₀ through A₃ all select the same context, Q is 5, L is 3, and H is 9, the low result is `0xFFFFFFFE` and the high result is 8.

5. **Stable-context high-bit quantity.** Under the same context-stability condition, Q equal to `0xFFFFFFFF`, L equal to zero, and H equal to 9 produce low 1 and high 9. The shift contribution −1 cancels the borrow contribution 1.

6. **Different initial contexts.** If the four global observations select distinct, nonoverlapping contexts, Q is 5, A₁ + 56 contains 3, and A₂ + 60 contains 9, the function writes `0xFFFFFFFE` at A₃ + 56 and 8 at A₀ + 60. Neither source is itself a destination in this arrangement. This is not an update of one accounting pair.

7. **Low store changes high source.** Suppose A₃ + 56 equals A₂ + 60, while the other relevant locations are separate. With Q equal to 5 and L equal to 10, the low store writes 5 to that shared location. The later high read obtains 5, and the high destination receives 5 because both correction terms are zero.

8. **Sentinel after effects.** If B equals 8, the function first reads Q at address zero, completes initial accounting, invokes F-2fd8826557a4, and obtains C. Only then does it return without validation.

9. **Invalid header after accounting.** With B different from 8 and a stable zero header, F-a817d8d58c10 is entered after the initial stores and F-2fd8826557a4. No later continuation is established.

10. **Zero masked quantity.** Stable header `0x00000002` passes validation and yields M equal to zero. The quantity-update operations still occur, and both count updates decrement by one.

11. **Later quantity differs.** If M is 16 and F-09dcb55e8e0a changes the header’s masked quantity to 32, the first four quantity deductions use 16; the deduction at C + 8 uses 32.

12. **Repeated destination.** With first index 58, M equal to 16, and C + 780 initially 100, the first two quantity updates leave that word at 68.
