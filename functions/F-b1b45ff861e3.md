### Selector-based byte writes

The later phase derives a selector index from result H:

\[
\text{Selector index} =
\bigl((4 \times \text{result H}) \mathbin{\&} 0x7fffffff\bigr) \gg 7.

This expression depends on the target interpretation of the preceding multiplication when it overflows. Under a 32-bit bit-vector interpretation, the index is at most 16,777,215.

A selector-based destination is formed by:

- Reading one unsigned byte at selector index plus one.
- Zero-extending that byte.
- Adding seventeen.

Consequently, the resulting destination lies between address 17 and address 272 inclusive. This is an absolute byte-derived address in the supplied representation, not a demonstrated offset into an object.

The following operations occur in order:

### Transition to the infinite loop

The procedure obtains another dependency result, masks it with `0x3fffffff`, and shifts it right by twenty-five. This produces a value from 0 through 31.

A second selector scheme is then used. Its selector address is:

\[
1024 \times (4 \times \text{the result used for step 5 above}) + 1.
\]

One byte is read from that address, and zero is written at the byte’s zero-extended value plus seventeen.

A dependency receives twice the newly bounded value, therefore a displayed argument from 0 through 62. Another dependency produces the initial primary argument used by the loop.

### Infinite-loop behavior

Each iteration:

- Invokes a dependency with a carried primary value and a carried unsigned value logically shifted right by eight.
- Performs additional dependency calls.
- Re-reads the second selector and writes zero to its byte-derived destination.
- Passes four times another dependency result to a dependency.
- Performs further calls.
- Uses the final result to update both carried values.

The next primary value is that final result shifted left by two. The next unsigned carried value is that result shifted left by twenty-six.

The second selector address remains based on the pre-loop result; the visible body does not replace it with a loop result.

For the first iteration, the second displayed argument is necessarily zero because its source is between 0 and 31. Under 32-bit modular shift semantics, subsequent second arguments depend only on the lowest six bits of the preceding final result, positioned starting at bit eighteen.
