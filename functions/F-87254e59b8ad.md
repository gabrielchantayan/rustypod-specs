# F-87254e59b8ad

## Purpose

F-87254e59b8ad constructs a word-array result in storage selected through an optional context, writes a header into that storage’s descriptor, and calls F-c64ad9e9ad7c with the first operand and the destination descriptor.

**Established static behavior:** operand counts are derived before the context is tested. A zero context returns a captured external value without destination access or dependency calls. A nonzero context causes destination clearing, nested word arithmetic, a one-step candidate-length adjustment, two classification calls, a header write, and a final dependency call whose result is normalized to zero or one.

**Inferred intent:** multiplication of little-endian multiword integers, followed by assignment or transfer to the first operand. The multiplication interpretation requires appropriate coefficient values, valid and suitably nonoverlapping storage, stable relevant state, and representable count arithmetic. Storage conditions alone are insufficient. For example, a zero word-decoding coefficient causes every outer row to be skipped even when the stored operand words are nonzero.

The interpretation does not establish a canonical result header or extend through either dependency without its contract.

This document describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and visible layouts

The function accepts three arguments:

| Argument | Visible meaning |
|---|---|
| First operand | Address of an operand descriptor |
| Optional context | Zero or an address containing a destination-descriptor reference |
| Third operand | Address of an operand descriptor |

Each operand descriptor exposes two consecutive 32-bit fields:

- **Offset 0:** header, interpreted as a signed 32-bit value for count derivation.
- **Offset 4:** address of a word array.

For a nonzero context:

- **Context offset 48:** address of the destination descriptor.
- **Destination descriptor offset 0:** writable 32-bit header.
- **Destination descriptor offset 4:** address of writable destination words.

The context field contains a descriptor address, not the payload address directly.

Words are 32 bits wide, with successive words separated by four bytes. Decoded words participate as unsigned 32-bit values in the full-width multiplication. The visible representation stores payload addresses in 32-bit fields; a wider address model is not established.

### External coefficients and bypass value

Five externally stored 32-bit values affect execution:

| Contract name | Observable role |
|---|---|
| Length coefficient | Scales each operand header before signed-magnitude calculation |
| Bypass result | Supplies the return value when the context is zero |
| Header coefficient | Scales the adjusted candidate length and classification results |
| Word-decoding coefficient | Scales operand words and existing destination words before arithmetic |
| Word-encoding coefficient | Scales result words and terminal carries before writes |

These are role names, not established values. The coefficients are not known to be one, and the encoding and decoding coefficients are not known to be inverses. They are not all captured once on entry.

### Return value

The return is a 32-bit value:

- **Zero context:** the captured bypass result, without normalization.
- **Nonzero context reaching the final dependency:**
  - Zero when F-c64ad9e9ad7c returns unsigned zero or one.
  - One when it returns any other unsigned 32-bit value.

No success or failure meaning is established for these returned values.

### Preconditions and ownership

Every actual read and write requires valid storage at the address used at that moment. No capacity, pointer-validity, alignment, or allocation check is visible.

For ordinary nonnegative derived counts with a representable sum, destination capacity equal to their sum covers the function’s direct payload writes. Dependencies may impose additional requirements that are unknown.

The function contains no visible allocation or release. No ownership transfer, retention, copying, freeing, or allocation behavior may be assumed for either dependency.

## Behavior

### Count derivation precedes the context branch

The third operand header is read and multiplied by the length coefficient. If the signed 32-bit result is negative, the result is negated. The same operation then derives the first operand count.

The third count controls inner iterations; the first count controls outer iterations.

After both count calculations, the function captures the bypass result and tests the context. Therefore, even a zero context requires both operand headers to be readable. On that path, neither operand’s payload-address field is read.

The ordinary count interpretation requires representable signed products and magnitudes. Negating the most-negative signed 32-bit value cannot produce a positive signed 32-bit result. Overflowing count calculations remain unresolved rather than defining an accepted negative-count convention.

### Destination selection and clearing

For a nonzero context, the function reads the destination-descriptor address from context offset 48. That selected descriptor is used for the remainder of the direct operation and as the second argument to F-c64ad9e9ad7c.

The initial candidate length is the sum of the derived counts. Destination words are then cleared to literal zero in increasing index order while the signed loop index is less than that candidate length.

For ordinary nonnegative counts, the cleared range is index zero through candidate length minus one. A zero candidate length produces no clearing writes.

The destination payload address is obtained through its descriptor during clearing; a single immutable payload-address snapshot for the entire function is not established.

Clearing occurs before the first operand’s payload-address field is read. Consequently, overlap can change inputs or descriptor fields before subsequent reads.

### Outer rows and conditional skipping

After clearing, the function reads the first operand’s payload address, even if the first count is zero. A persistent unsigned 32-bit carry state starts at zero.

First-operand words are visited in increasing index order. Each word is scaled by the word-decoding coefficient and reduced to a 32-bit decoded value.

When that value is zero:

- The row performs no arithmetic destination writes.
- The third operand’s payload-address field is not read for that row.
- The persistent carry is left unchanged.

When it is nonzero:

- The third operand’s payload address is read anew.
- The carry is reset to zero.
- A destination cursor is formed from the destination payload-address field, starting at the current outer index.
- Inner iterations process consecutive third-operand and destination words.

The first operand cursor advances between rows; it is not reacquired from the descriptor each time. The third operand base and destination row base are reacquired for each nonzero row.

### Inner arithmetic and terminal carry

For each inner position:

1. The third operand word is scaled and reduced to a 32-bit decoded value.
2. The two decoded operand values are multiplied as unsigned values, yielding a 64-bit product.
3. The low product word is added to the decoded existing destination word, retaining a 32-bit sum.
4. The incoming carry is added to that sum, again retaining 32 bits.
5. The next carry combines the product’s high 32 bits and the carry-outs from those two additions.
6. The final low sum is scaled by the word-encoding coefficient and written as a 32-bit destination word.

The destination word is read before it is overwritten. Its decoded value appears in both the low-sum calculation and the first carry test. A single atomic snapshot of the destination word and coefficient is not established for externally changing storage.

For stable, nonoverlapping storage, outer index \(i\) and inner index \(j\) address destination word \(i+j\).

After every nonzero outer row, the encoded carry is written immediately after that row’s inner range, at index \(i+\text{third count}\). This write occurs even when the carry is zero.

If the third count is zero, a nonzero outer row still obtains the third payload address, resets carry, forms its destination cursor, and writes a zero terminal carry at the outer index. No third payload word is read.

### One-step candidate-length adjustment

After the outer loop, the candidate length is decremented once if the persistent carry is zero. Otherwise, it is unchanged.

This is not general leading-zero normalization:

- No destination word is inspected for this decision.
- The adjustment removes at most one word.
- Skipped rows preserve the carry from an earlier nonzero row.
- If all rows are skipped, or no outer iteration occurs, the carry remains zero.

Accordingly, the candidate length can exceed the actual nonzero payload extent. An all-zero payload does not necessarily produce a zero candidate length. With both counts zero, the candidate length changes from zero to negative one.

### Classification and header write

After direct payload writes, the function calls F-d72f047fba8b:

1. With the third operand descriptor.
2. With the first operand descriptor.

The destination header is then assigned the product of:

- The header coefficient.
- The adjusted candidate length.
- The first call’s returned classification.
- The second call’s returned classification.

The classification results are 32-bit values. Their interpretation as signs is inferred, not established.

The returned classifications are retained for header construction, but dependency preservation is unknown. The first call may change what the second observes. Either call may also change globals or storage used later. In particular, the header coefficient is used after these calls rather than being established as an entry-time snapshot.

### Final dependency and return normalization

After the direct header write, F-c64ad9e9ad7c receives:

1. The first operand descriptor.
2. The previously selected destination descriptor.

Its unsigned return value is normalized as specified under Interface.

No direct payload or header writes follow this call. The dependency may nevertheless modify storage or ownership state; its implementation is unavailable.

## Side effects

### Established phase order

The visible order is:

1. Derive the third operand count.
2. Derive the first operand count.
3. Capture the bypass result.
4. Test the context.
5. For a nonzero context, select the destination descriptor.
6. Clear destination words.
7. Read the first operand payload address.
8. Process rows and terminal carry writes.
9. Classify the third operand.
10. Classify the first operand.
11. Write the destination header.
12. Invoke F-c64ad9e9ad7c.
13. Normalize its result and return.

Independent reads within arithmetic expressions do not establish a stronger machine-level ordering.

### Aliasing and mutation

Nonoverlapping, stable storage is **not sufficient by itself** to establish multiplication. A straightforward unsigned word-product interpretation additionally requires appropriate length, decoding, and encoding coefficients and representable count arithmetic. Unit coefficients provide a concrete sufficient coefficient choice for the direct payload calculation under otherwise valid conditions.

Even under those assumptions, the header retains the one-step adjustment behavior, and the dependencies’ effects remain unknown.

No alias detection or defensive input copy is visible. With overlap:

- Clearing may erase payloads or alter descriptors before they are read.
- Earlier arithmetic writes may change later operand reads.
- Changes to the destination payload-address field may redirect later rows.
- A row already using its local destination cursor continues from that cursor rather than reacquiring the field for every inner word.

Dependency calls may introduce additional mutations. Concurrent access, volatile semantics, and memory-mapped storage behavior are not specified.

### Errors and partial state

There is no visible recoverable validation or arithmetic-error path. An invalid access or other execution fault may occur after clearing or partial accumulation. No rollback is shown.

No direct assignment to the first operand descriptor is shown before the dependencies. Whether it ultimately receives the constructed value depends on unknown dependency behavior.

## Acceptance examples

These are conditional static examples, not observed executions. Unless overridden, arithmetic examples assume stable relevant state, nonoverlapping valid descriptors and arrays, sufficient destination capacity, representable count and header arithmetic, all coefficients equal to one, and both classifications equal to positive one. Payload results describe the state after direct arithmetic, before possible dependency mutation.

### Zero context

Given readable operand headers and a zero context:

- Both counts are derived.
- The bypass result is captured and returned.
- Payload-address fields are not read.
- No destination access or dependency call occurs.

An unreadable operand header is not made safe by the zero context.

### Single-word product without high carry

For first payload \([3]\), third payload \([4]\), and counts one:

- Two destination words are cleared.
- Direct arithmetic produces \([12,0]\).
- Zero final carry reduces candidate length from two to one.
- With the stated header assumptions, the direct header is one.

### Single-word product with high carry

For first payload \([4294967295]\), third payload \([2]\), and counts one:

- Direct arithmetic produces \([4294967294,1]\).
- Final carry is one.
- Candidate length remains two.
- The direct header is two.

### Skipped trailing row retains carry

For first payload \([4294967295,0]\) with count two and third payload \([2]\) with count one:

- Three destination words are cleared.
- The first row produces the low words \([4294967294,1]\).
- The second row is skipped.
- Carry remains one.
- Candidate length and direct header remain three, although the highest destination word is zero.

Full leading-zero trimming would not preserve this behavior.

### Zero decoding coefficient defeats multiplication interpretation

Keep valid, stable, nonoverlapping storage and derived counts one, but set the word-decoding coefficient to zero. Let both stored operand words be nonzero.

- Two destination words are cleared.
- The decoded first word is zero, so its row is skipped.
- The third payload-address field is not read by that row.
- Carry remains zero; candidate length becomes one.
- The direct destination payload remains \([0,0]\), not the ordinary product.

If the header coefficient and classifications remain positive one, the direct header is one. This demonstrates why storage conditions alone cannot establish multiplication.

### All-zero first operand

For a first payload of two zero words and third count two:

- Four destination words are cleared.
- Both outer rows are skipped.
- Candidate length changes from four to three.
- Under the stated classification assumptions, the direct header is three.

If a classification instead returns zero, the header product can be zero.

### Both counts zero

- No destination payload is cleared.
- The first payload-address field is still read.
- No product row executes.
- Candidate length becomes negative one.
- Classification, header writing, and the final dependency still occur.
