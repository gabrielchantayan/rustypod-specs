## Behavior

### Complete classification

The observable result is determined entirely by the second argument:

| Unsigned input interval | Return value |
|---|---:|
| 0x00000000–0x0000FFDF | 3 |
| 0x0000FFE0–0xFFFFFFFF | 0 |

There are **65,504** input values in the return-3 interval. The upper boundary is inclusive; the immediately following value returns 0.

The classification uses the full 32-bit input. For example, **0x00010000 returns 0**, even though its least significant 16 bits are zero. High-bit-set inputs likewise remain large unsigned values and return 0.

### Grouping and internal boundaries

The comparison basis is the unsigned input shifted right by four bits. This discards the four least significant bits and produces a value between **0x00000000 and 0x0FFFFFFF**, inclusive.

Consequently, the result is constant within every aligned block of 16 consecutive inputs. Two inputs that differ only in their four least significant bits receive the same result.

The condition recognizes two adjacent regions:

- Shifted values below **0xF00**, corresponding to original inputs **0x00000000–0x0000EFFF**.
- Shifted values from **0xF00 through 0xFFD**, inclusive, corresponding to original inputs **0x0000F000–0x0000FFDF**.

Both regions return 3. Their boundary at **0x0000F000** is an internal evaluation boundary, not a change in the returned classification.

The final aligned block returning 3 is **0x0000FFD0–0x0000FFDF**. The first aligned block returning 0 is **0x0000FFE0–0x0000FFEF**. Thus the only transition in the numeric result as the unsigned input increases is between **0x0000FFDF** and **0x0000FFE0**.

The grouping is a mathematical consequence of the shift. It does not establish that the application uses 16-element records, pages, character groups, or any other specific domain objects.

### Evaluation order and arithmetic

The comparison against **0xF00** is evaluated first. When it succeeds, the second comparison is not evaluated.

The second comparison is reached only when the shifted input is at least **0xF00**. It compares the unsigned difference between that shifted input and **0xF00** against the strict upper limit **0xFE**, or decimal **254**.

On an evaluated path:

- The smallest possible difference is **0**, reached when the shifted input is **0xF00**.
- Differences **0 through 253** satisfy the second comparison.
- A difference of **254** does not satisfy it.
- The largest possible difference is **0x0FFFF0FF**, because **0x0FFFFFFF − 0x00000F00 = 0x0FFFF0FF**.

The subtraction therefore does not underflow: its evaluation is conditional on the minuend being at least the subtrahend. Its maximum result fits within 32 bits, so no overflow or wraparound is required to explain any evaluated result.

The right shift has a fixed count of four, within the 32-bit operand width. Because the operand is unsigned, the shift fills with zeros rather than propagating a sign bit.

These arithmetic details establish the boundary without relying on a narrowed input, signed comparison, saturation, or exceptional arithmetic behavior.
