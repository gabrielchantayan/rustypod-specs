# F-7c787b16647c

## Purpose

F-7c787b16647c conditionally performs an initialization-like sequence, then obtains and returns a 32-bit result from F-b5a76fecbe46.

The branch decision and the later flag write use **two separately fetched values of the same shared pointer global**:

- The first fetch supplies a saved pointer used for the later write of one.
- The second fetch supplies the pointer dereferenced for the zero test.

Both fetches occur after an entry dependency returns. The tested target and the saved write target are the same only if the two fetches produce the same pointer. This equality is not established unconditionally.

When the tested word is zero, the function exposes local input storage to a dependency, captures seven byte contributions, obtains another dependency result, writes a computed shared word, writes one through the saved pointer, and makes nineteen preliminary calls to F-b5a76fecbe46.

Every normally completing invocation then makes one result-producing call to F-b5a76fecbe46, calls an exit dependency with an earlier saved value, and returns the result-producing call’s value.

“One-time initialization” is inferred intent. The visible behavior does not establish synchronization, exclusive initialization, rollback, or that the tested word becomes nonzero.

## Behavior

### Entry processing and the two flag-pointer reads

The function first copies the third and fourth arguments into the two local words.

It then calls F-7bc76a790d92 without explicit arguments and saves its 32-bit result for the exit call.

After that dependency returns, the function performs these distinct observations in order:

1. It reads the flag-pointer global and saves the resulting pointer for a possible later write.
2. It reads the same global again.
3. It dereferences the pointer obtained by the second read and compares that 32-bit word with zero.

There is no visible dependency call between the two pointer reads. Nevertheless, the supplied body contains two reads, not a single pointer capture reused for the test. Their equality requires pointer stability between those observations.

F-7bc76a790d92 can affect both observations through changes made before it returns. A change to the pointer global between the two reads can instead cause the saved write target and the tested target to differ. The mechanism or synchronization governing such a change is not established.

The saved pointer is not subsequently refreshed for the direct flag write.

### Branch selection

If the word read through the second pointer is nonzero, the initialization sequence is skipped.

If that word is zero, initialization proceeds. There is no visible recheck of that word, of the saved write target, or of the flag-pointer global before the initialization writes and preliminary calls.

In particular, taking the branch does not establish that the word at the saved write target was zero.

### Exposing local input storage

On the zero-test branch, F-a8da4de9bd1d is called with:

- Zero as its first explicit argument.
- The address of the first local word as its second explicit argument.

Its return value is not consumed.

Writes it makes to the local words before returning can affect the subsequent byte contributions. The caller neither validates nor normalizes those words afterward.

The supplied body does not establish whether this dependency writes either word, writes both words, limits its accesses to them, or retains the address.

### Capturing seven byte contributions

After F-a8da4de9bd1d returns, the function derives seven unsigned contributions:

| Local word | Selected bit ranges |
|---|---|
| First | 0–7, 8–15, 16–23, and 24–31 |
| Second | 0–7, 8–15, and 16–23 |

Each contribution is between 0 and 255. Their total is between 0 and 1,785 inclusive.

The selection uses unsigned numerical shifts and masks. It does not require a particular memory byte order to describe the selected bit ranges. Memory byte order remains relevant to any undocumented memory accesses by dependencies.

Bits 24–31 of the second local word do not directly contribute through these seven terms. The inherited register operand must not be assumed to represent that omitted byte.

The contribution values are captured before the next external call and are not recomputed afterward. The supplied representation does not establish an atomic snapshot against asynchronous modification of the local storage.

### Obtaining the additional operand

The function next calls an external dependency without explicit arguments. No mapped function ID is supplied for it; this document identifies it as F-opaque-01.

Its result participates as a 32-bit integer operand in the destination computation. Its identity, full calling convention, and side effects remain unknown.

### Computing and writing the destination word

After F-opaque-01 returns, the function writes a 32-bit value at byte offset 8 of the destination region.

The computation combines:

- The result of F-opaque-01.
- The 32-bit word read at source-region byte offset 8.
- The seven previously captured unsigned byte contributions.
- The inherited register operand.

The source word is read after F-opaque-01 returns, not snapshotted at entry. Changes that dependency makes to the relevant globals or memory can therefore affect the computation or its destination.

The supplied representation does not establish a complete evaluation order among the shared pointer fetches and source-word read within this assignment. It does establish that the destination write completes before the subsequent write through the saved flag pointer.

There is an arithmetic qualification. The first addition combines two operands represented as signed 32-bit integers: the external result and the source word. If that addition remains within the signed 32-bit range, subsequent additions include unsigned 32-bit contributions, and the stored word is the total modulo \(2^{32}\).

If the initial signed addition exceeds the signed 32-bit range, the supplied material does not establish the original language’s overflow rules or provide instruction-level evidence resolving the result. Those cases remain documented_only. A wrapping-machine interpretation would retain the low 32 bits, but that interpretation is not an unconditional contract for the unresolved cases.

### Writing through the saved pointer

After the destination write, the function stores the 32-bit value one through the pointer saved by the **first** flag-pointer-global read.

It does not fetch the flag-pointer global again for this write, and it does not necessarily write the target inspected by the zero test.

Consequently:

- If both pointer reads returned the same address, this write marks the tested target as one.
- If they returned different addresses, this write marks the saved target; the tested target is not directly updated by this operation.
- Changes to the global after the first read do not redirect this direct write.
- Aliasing with the destination can cause this write to replace the computed destination value.

### Preliminary calls and final result

The function then calls F-b5a76fecbe46 nineteen times without explicit arguments, discarding each result.

The destination write and the write of one through the saved pointer precede all nineteen calls. Thus, before the first preliminary call begins, the caller’s direct store of one has occurred at the saved write target. This does **not** establish that the tested target is one. Nor does it establish preservation of either target throughout the calls.

No preliminary result is tested, and there is no visible early exit based on those results.

After the preliminary calls—or immediately after skipping initialization—the function:

1. Calls F-b5a76fecbe46 once and saves its 32-bit result.
2. Calls F-f88a82ca64d0 with the saved result of F-7bc76a790d92.
3. Returns the saved final result.

Assuming all calls return normally, F-b5a76fecbe46 is called twenty times on the zero-test branch and once on the nonzero-test branch.

## Side effects

Directly visible writes are:

- Initialization of the two local words.
- On the zero-test branch, one 32-bit destination write at offset 8.
- On that branch, a later 32-bit write of one through the saved flag pointer.

Dependency calls can have additional unspecified effects.

The destination and flag writes are separate operations. No atomic pairing, locking, or memory-ordering protocol is established. Cross-thread visibility guarantees cannot be derived from their order alone.

If the saved write target aliases the destination word, the later write replaces the computed destination value with one. This consequence does not require the tested target to alias either location.

No explicit allocation, deallocation, error reporting, retry, rollback, or exception cleanup is visible. If a dependency faults, exits nonlocally, or does not return, later operations are not guaranteed. The exit dependency is not shown to run through guaranteed cleanup.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests. They assume valid required accesses and normally returning dependencies unless stated otherwise.

### Nonzero tested target skips initialization

Suppose the second flag-pointer read identifies a word containing 9.

The function skips F-a8da4de9bd1d and F-opaque-01, performs neither direct initialization-branch shared write, calls F-b5a76fecbe46 once, calls F-f88a82ca64d0 afterward, and returns the saved result.

This remains the branch outcome even if the first pointer read identified a different word containing zero.

### Different saved and tested targets

Suppose the first pointer read returns address A, the second returns distinct address B, and the word at B is zero. Assume A, B, and the destination word are disjoint, and dependencies do not modify A or B.

Initialization occurs. After the destination write, the function writes one at A. The word at B remains zero.

The nineteen preliminary calls begin after the write at A. They cannot be described as necessarily observing a marked tested target: the tested target in this example remains zero.

### Stable pointer and zero flag

Suppose both pointer reads return the same valid address and its tested value is zero.

The destination write precedes the write of one at that address. Both precede nineteen preliminary F-b5a76fecbe46 calls. The twentieth call supplies the returned value.

### Arithmetic without signed-overflow ambiguity

Suppose the local words remain stable during extraction and contain hexadecimal 01020304 and AA050607 after F-a8da4de9bd1d returns. Suppose F-opaque-01 returns 10, the source word read is 20, and the inherited operand is 30.

The seven contributions sum to 28. The destination write is 88. The high byte AA does not directly contribute.

Later aliasing or dependency effects may change the destination; 88 describes the computed write, not an unconditional final memory value.

### Entry dependency changes the branch

Suppose the relevant flag was zero before invocation, but F-7bc76a790d92 changes the state so that the second pointer read identifies a nonzero word.

Initialization is skipped. The pre-invocation flag value does not determine the branch.

### Saved write target aliases the destination

Suppose initialization is taken and the pointer saved by the first read identifies the destination word at offset 8.

The function writes the arithmetic result there and then writes one there. Its last direct write to that word is one, regardless of whether the second pointer read identified that same location.

### Exit dependency changes shared state

Suppose the final F-b5a76fecbe46 call returns a value and F-f88a82ca64d0 subsequently changes shared globals but returns normally.

The function returns the previously saved result without recomputing it.

## Evidence

Established static evidence includes four 32-bit inputs, two local input copies, the entry call, two separate flag-pointer-global reads, a zero test through the second pointer, and a later write through the first saved pointer.

The initialization path additionally establishes the pointer-bearing dependency call, seven byte contributions, an external arithmetic operand, the destination write, the subsequent saved-pointer write, and nineteen preliminary result-dependency calls.
