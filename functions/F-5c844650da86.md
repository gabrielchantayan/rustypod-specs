## Behavior

### Gate and bound selection

The first explicit object access is the byte read at offset +0x10.

If this byte is zero, the function returns immediately. It does not explicitly read the bound or invoke any dependency.

If the byte is nonzero, the function reads the signed bound at offset +0x04. That value is captured for the examination. The function does not explicitly reload either field afterward.

Consequently, a dependency changing the object’s stored gate or bound does not, by that change alone, alter the caller’s already-selected gate decision or captured bound. Such changes may still affect later dependency behavior. Dependency effects on execution beyond ordinary call semantics are not established.

### Examination order

For a positive bound, examination covers successive integer indices beginning at zero. F-e1d0a9f8dcb0 receives:

1. The original base argument.
2. The current index.

Indices are presented in ascending order, with no gaps, until either a nonzero result is observed or all indices strictly below the captured bound have been examined.

A zero result permits examination to continue. Any nonzero integer result selects the terminal path. The caller does not distinguish positive results from negative results and does not expose the result as a return value.

A zero or negative bound produces no examination calls. In particular, a negative bound is not converted into a large unsigned iteration count.

For an all-zero result sequence and positive bound, there is exactly one examination call for each index from zero through one less than the bound. No call is made with an index equal to the bound.
