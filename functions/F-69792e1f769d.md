# F-69792e1f769d

## Purpose

F-69792e1f769d dispatches an operation according to a request discriminator and a context flag. Depending on that combination, it:

- Calls a dependency using a context-supplied value.
- Calls a dependency with a selected context and auxiliary value.
- Performs a three-dependency sequence around a conditional fallback operation.
- Returns without calling any dependency.

Every normally entered path first clears one byte at the fifth argument’s address.

The supplied representation exposes a 64-bit return assembled from two 32-bit components. The lower component usually contains a dependency result; the upper component varies by path. Whether these components form an intentional public result pair, or reflect calling-convention reconstruction, is not established.

### Return representation

For purposes of this contract, the exposed result is described as:

- **Lower component:** bits 0–31.
- **Upper component:** bits 32–63.

Address-valued components are represented by their 32-bit address bits. The function does not visibly write a 64-bit result to caller-provided memory.

### Preconditions

Ordinary defined execution requires:

- The fifth argument to address at least one writable byte.
- The context flag byte to be readable.
- The request discriminator to be readable.
- Every additional location selected by the actual branch to be readable.
- Arguments passed onward to satisfy the selected dependencies’ own contracts.

The internal null checks on the special discriminator-2 path do not make null request or fifth-argument addresses generally acceptable. Those addresses have already been dereferenced before the checks.

No non-aliasing requirement is established. If the fifth argument overlaps the request or context, the initial byte clear can change the subsequent dispatch decision or an address later read.

## Behavior

### 1. Entry write and dispatch reads

The first visible memory action is a one-byte write of zero at the fifth argument’s address. It is not a four-byte clear.

The function then reads the context flag byte at offset 29 and tests bit 0. Other bits do not affect this branch selection.

After selecting the flag branch, it reads the request’s 32-bit discriminator. Accordingly, dispatch observes memory after the initial byte clear.

### 2. Flag bit clear

When flag bit 0 is clear, the discriminator selects between two paths.

#### Discriminator other than 30

The function reads the 32-bit context value at offset 32 and calls F-47ce25a252ab with:

1. The request address.
2. That context value.

It returns:

- Lower component: the dependency’s exposed 32-bit result.
- Upper component: the fifth argument’s address bits.

There is no visible interpretation of the dependency result and no visible follow-up call.

#### Discriminator equal to 30

The function reads the context word at offset 16 and enters the common dispatch described below, using the original context address and that word as the auxiliary value.

### 3. Flag bit set, discriminator 2

The function reads the context word at offset 0 and adds 204 to form a derived address.

The visible model is 32-bit address arithmetic. The contract does not establish a wider intermediate or an overflow error. In particular, a base bit pattern of `0xFFFFFF34` produces a zero derived address under 32-bit wraparound.

#### Nonzero derived address

The visible validation requires a nonzero derived address, a nonnull fifth argument, and a nonnull request address. Its rejection value for the lower result is `0xFFFFFFCE`, the 32-bit representation of −50.

However, on an ordinary execution that successfully performed the entry write and discriminator read, the request and fifth-argument null checks do not provide a reachable null-input recovery mechanism. Invalid earlier accesses may already have faulted or otherwise left defined behavior.

When the validation conditions hold, calls occur in this order:

1. F-efaaaab570a3 receives the derived address.
2. F-c45cb3f8e7fd receives the derived address, zero, and two distinct addresses of temporary stack storage.
3. If and only if F-c45cb3f8e7fd returns a zero 32-bit result, F-daea5676dfac is called with the request address, the fifth argument, zero, and the fifth argument again.
4. F-2a517f9b9ef3 receives the same derived address.

The lower return component is:

- The nonzero result from F-c45cb3f8e7fd, when that result is nonzero.
- Otherwise, the result from F-daea5676dfac.

The contents of the two temporary storage locations are not visibly consumed by this function after F-c45cb3f8e7fd returns.

The upper return component is represented as the 32-bit value present in the secondary return register after F-2a517f9b9ef3. Its meaning and stability are unknown. It must not be specified as the fourth argument, fifth argument, derived address, or an error status without additional evidence.

#### Zero derived address

A zero derived address does **not** take the rejection return and does not execute the dependency sequence above.

Instead, execution enters the common dispatch with:

- The original context address.
- An auxiliary value of zero.

This distinction is part of the visible branch behavior, regardless of whether such a base value is valid in the intended application.

### 4. Flag bit set, discriminator 30

The function reads the original context word at offset 16 and enters the common dispatch with the original context address and that auxiliary value.

Thus, discriminator 30 reaches the same common operation regardless of the flag bit.

### 5. Flag bit set, discriminator 36

The function reads the candidate address from context offset 4 and initializes the auxiliary value to zero.

If the candidate address is zero:

- No replacement-context address is read.
- The working context remains the original context.
- The auxiliary value remains zero.

If the candidate address is nonzero:

1. The function reads the base value from original-context offset 0.
2. It reads a replacement context address from that base plus 64.
3. The replacement becomes the working context.
4. It compares the candidate address with the replacement context address.
5. If they differ, it reads the candidate’s word at offset 16 and uses that as the auxiliary value.
6. If they are equal, the auxiliary value remains zero and the candidate word at offset 16 is not read.

The function then enters the common dispatch.

The equality comparison is an address-bit comparison. No visible content comparison or null validation of the replacement context occurs.

### 6. Flag bit set, every other discriminator

For any discriminator other than 2, 30, or 36, the function calls no dependency and returns:

- Lower component: zero.
- Upper component: the original context address bits.

The initial one-byte clear still occurs.

### 7. Common dispatch

The common dispatch calls F-5670512d89b6 with:

1. The request address.
2. The working context address selected by the preceding branch.
3. The selected 32-bit auxiliary value.
4. Zero.

It returns:

- Lower component: the dependency’s exposed 32-bit result.
- Upper component: the fourth argument’s address bits.

The function does not visibly inspect or transform the dependency result.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. All examples assume valid selected memory accesses and normally returning dependencies unless stated otherwise.

1. **Flag-clear ordinary request.** With flag bit 0 clear and discriminator 7, the fifth argument’s first byte is cleared before dispatch reads. F-47ce25a252ab receives the request address and context word at offset 32. Its result becomes the lower component; the fifth argument becomes the upper component.

2. **Discriminator 30 with either flag value.** With discriminator 30, the common dependency receives the original context, its word at offset 16, and a final zero argument. The upper return component is the fourth argument.

3. **Unhandled flag-set discriminator.** With flag bit 0 set and discriminator 7, no dependency is called. The result has lower component zero and upper component equal to the original context address. The entry byte clear still happens.

4. **Discriminator 36, null candidate.** With flag bit 0 set and context offset 4 containing zero, the common dependency receives the original context and auxiliary zero. The replacement-context location is not read.

5. **Discriminator 36, matching addresses.** With a nonzero candidate equal to the replacement context, the common dependency receives that replacement context and auxiliary zero. Candidate offset 16 is not read.

6. **Discriminator 36, differing addresses.** With a nonzero candidate different from the replacement context, the common dependency receives the replacement context and the word read from candidate offset 16.

7. **Discriminator 2, nonzero primary result.** With a nonzero derived address, if F-c45cb3f8e7fd returns `0x12345678`, the fallback is skipped, F-2a517f9b9ef3 is still called, and the lower return component is `0x12345678`. No fixed upper component is asserted.

8. **Discriminator 2, zero primary result.** If F-c45cb3f8e7fd returns zero, the fallback receives the fifth argument in both its second and fourth positions. The fallback result becomes the lower component, followed by the final dependency call.

9. **Discriminator 2, zero derived address.** Under the visible 32-bit arithmetic model, a base value of `0xFFFFFF34` selects common dispatch with the original context and auxiliary zero. None of the four dependencies belonging to the nonzero-derived-address sequence is called.

10. **Entry-store aliasing.** If the fifth argument addresses the context flag byte, the initial zero store makes the subsequently read flag bit clear. Acceptance must follow the resulting flag-clear branch, not the flag value that existed before entry.
