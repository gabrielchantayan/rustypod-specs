# F-609bb7a48db0

## Purpose

F-609bb7a48db0 conditionally initializes a context-resident data block containing attribute descriptions, row descriptions, row-value storage, and short labels. When given an output-slot address, it also requests destination storage, invokes an external operation, reconstructs pointers in that destination, and publishes its address.

The apparent intent is a cached loader with an optional separately allocated copy. The supplied static representation does not establish copying, independent ownership, or correct population of distinct rows.

Important established limitations:

- Any nonzero cache pointer bypasses initialization, including one left by a failed earlier attempt.
- The wrapper-allocation result is published before its status is checked.
- No explicit cleanup or rollback occurs.
- Row loading retains one descriptor address rather than advancing through the row descriptors.
- Label construction and row-value writes reread pointers that can have changed.
- Size and address calculations lack explicit overflow checks.
- Successful output publication does not independently establish a zero return status.

## Interface

### Arguments and return value

The arguments are:

1. A context address in the represented 32-bit address space.
2. An optional address of a writable four-byte output slot.

The result is a 32-bit status value. Explicitly checked nonzero dependency statuses cause early termination. Structural validation failure returns `8`.

There is no single unconditional “completed execution returns zero” guarantee. The final return reads shared status storage whose address has been passed to allocation dependencies. Later dependencies are not established to preserve that storage.

A null output-slot address suppresses output allocation and reconstruction, but not initialization. With a preexisting nonzero cache, a null output-slot address, and valid context accesses, no dependency is called and the function returns the zero assigned at entry.

### Context layout

| Offset | Width | Use |
|---|---:|---|
| `0x64` | 32 bits | Allocation-provider argument, captured at entry |
| `0x68` | 32 bits | Stream argument, captured at entry |
| `0x1F8` | 32-bit callable address | Initialization callback |
| `0x2A0` | 32-bit pointer | Cache wrapper; zero selects initialization |

The entry reads occur in this order: stream argument, allocation-provider argument, then—after initializing shared status to zero—the cache pointer.

Each callback dispatch rereads the callable address. Some later cache operations also reread the context cache pointer rather than retaining an earlier wrapper address.

### Preconditions and ownership

The function performs no general null, bounds, alignment, overlap, or object-validity checks. Execution requires accessible context fields and sufficient readable or writable storage for each performed access.

A nonzero cache must be usable for the requested path. An output slot must permit a four-byte write.

No allocation freshness, non-aliasing, ownership transfer, release protocol, or dependency preservation guarantee is established. In particular, the final explicit output assignment is not the only possible write affecting an overlapping output slot.

## Behavior

### Initialization gate and preliminary operations

When the cache pointer is zero:

1. F-opaque-01 is called with the context, a globally supplied first selector, the captured stream argument, and an address for a 32-bit size result. Its return is assigned to shared status and checked.
2. On zero status, F-opaque-01 is called again with a second global selector and the same size-result storage. Its return is likewise assigned and checked.
3. F-b03b1199772e receives the stream argument and supplies a 32-bit position base.
4. F-de70a5256fd2 receives the stream argument and a global header-format descriptor. The low 32 bits of its displayed 64-bit result become shared status and are checked.

Either callback failure or a nonzero header status returns immediately. There is no retained independent copy of the first callback’s size result.

The complete convention by which the header operation supplies the subsequently consumed fields is not shown. The following validation contract is conditional on those fields being available as represented.

### Header validation and arithmetic

Contract names for the consumed fields are:

| Field | Width | Requirement or role |
|---|---:|---|
| Version | 32 bits | Must equal `0x00010000` |
| First marker | 16 bits | Must equal `2` |
| Second marker | 16 bits | Must equal `20` |
| N | 16 bits | Attribute count |
| R | 16 bits | Row count |
| O | 16 bits | Offset added to the position base |
| S | 16 bits | Required row size |

Validation requires:

- The version and both markers match.
- S equals the untruncated 32-bit value `4N + 4`.
- The callback-produced size is at least `R × S + O + 20N`, evaluated with the represented 32-bit unsigned arithmetic.

Failure returns `8` before wrapper allocation.

Because S is 16 bits, the row-size equality permits at most N = `16,382`. It does not compare S with a truncated 16-bit result. The available-size expression can nevertheless wrap modulo `2^32`; the comparison is not a checked mathematical-size comparison.

### Wrapper publication and backing allocation

F-3ce007b692cc is first called with the captured provider, a request for 40 bytes, and the shared-status address.

The returned address is written to context offset `0x2A0` **before** shared status is inspected. A nonzero status is returned without reverting that publication.

On reported success, the backing-size calculation is:

**B = 20 + 29N + 8R + 4NR**

B is calculated in 32-bit arithmetic and written at offset `0x0C` of the wrapper address returned by the first allocation.

The same dependency is then called for B bytes, again with the shared-status address. A nonzero status returns without clearing the cache. On reported success, the function rereads the context cache pointer and writes the backing address at wrapper offset `0x08`.

Thus, if a dependency changes the context cache field, the size write and backing-address write can target different wrappers.

### Backing layout and initial writes

The planned contiguous layout is:

| Region | Size |
|---|---:|
| Header | 20 bytes |
| Attribute descriptors | `24N` bytes |
| Row descriptors | `8R` bytes |
| Row-value arrays | `4NR` bytes |
| Label slots | `5N` bytes |

Pointers and ordinary stored words are 32 bits. Address calculations use the represented 32-bit arithmetic.

The five header words are written in order:

1. N.
2. `0xFFFFFFFF`.
3. R.
4. Attribute-region address.
5. Row-descriptor-region address.

In increasing row order, each row descriptor’s first word is initialized to its corresponding N-word value array. Its second word is not initialized by this pass.

In increasing attribute order, each attribute descriptor’s first word is initialized to its five-byte label slot.

There is no explicit general zero-fill. Other wrapper bytes, descriptor fields, and value-array contents have no established initial value.

### Attribute positioning and loading

F-e40a3ceddab2 receives the captured stream argument and the 32-bit sum of O and the retained position base. Its nonzero result is returned directly.

The attribute-descriptor address is then selected from the backing header. Attributes are processed in increasing order.

**Before every attribute-loop comparison, including the terminating comparison, shared status is explicitly reset to zero.** This also happens when N is zero.

For each entered iteration, F-de70a5256fd2 receives the stream, an attribute-format descriptor, and decoded-record storage. A nonzero return is returned directly before this function performs that attribute’s descriptor writes.

Successful processing writes:

| Descriptor offset | Contents |
|---|---|
| `0x00` | Previously initialized label pointer |
| `0x04` | First parsed ordinary 32-bit value |
| `0x08` | Second parsed ordinary 32-bit value |
| `0x0C` | Third parsed ordinary 32-bit value |
| `0x10` | Parsed 32-bit tag |
| `0x14` | Zero-extended parsed 16-bit value |

The direct descriptor-write order is `0x10`, `0x04`, `0x08`, `0x0C`, then `0x14`.

Label construction consists of five one-byte stores:

- The first byte is derived from the decoded tag storage’s most-significant byte.
- The next three bytes are derived from successive reads of descriptor offset `0x10`, selecting bits 23–16, bits 15–8, and bits 7–0 respectively.
- The fifth byte is zero.

The label pointer at descriptor offset `0x00` is read again for each store. There is no unconditional four-byte tag snapshot governing all five writes. The relative order of source-value and destination-pointer reads within an individual store expression is not established here.

With a stable label pointer and label storage disjoint from the descriptor and decoded-record storage, these writes produce the tag’s four bytes most-significant first, followed by zero. With aliasing, an earlier byte store can change a later tag read or destination pointer. Tags containing zero bytes can appear shorter than four characters to string consumers even under ordinary non-overlapping conditions.

### Row loading

After attribute processing, the function selects the row-descriptor address from the backing header once. It does not advance that selected address during row loading.

For each of R iterations:

1. F-d036abe1e536 receives the stream and `4 + 4N`. Its return is assigned to shared status; a nonzero status returns immediately.
2. F-7efb5338f0fa is called. Its low 16 bits, zero-extended to 32 bits, are written at offset `0x04` of the selected descriptor.
3. F-7efb5338f0fa is called again; its result is discarded.
4. F-77339711215b is called N times. After each call, the selected descriptor’s first word is read to obtain the destination array address. The returned 32-bit value is written at that address plus four times the element index.
5. F-9787e15c337d is called without checking its result.

A fixed descriptor address does **not** establish a fixed value-array address. The destination pointer is reread after every value-reader call, and those calls can have changed it. Dependencies can also alter previously written identifiers or values, including during the unchecked post-row call.

Under stable descriptor pointers and dependency preservation of payloads, all iterations directly populate the first selected row, with later iterations overwriting earlier identifiers and values. Under those assumptions, other rows receive only their initial array-pointer writes from this function. Without those assumptions, neither their final contents nor the selected row’s final contents are established.

### Optional output allocation and external operation

For a nonnull output-slot address, the function obtains a byte count from offset `0x0C` of the current cache wrapper and requests that many bytes from F-3ce007b692cc, passing the shared-status address.

A nonzero status skips reconstruction and final publication. There is no explicit cleanup.

On zero status, F-opaque-02 receives:

1. The allocation result.
2. The backing address from offset `0x08` of the then-current cache wrapper.
3. The byte count from offset `0x0C` of the then-current cache wrapper.

The source and length accesses occur after allocation; their relative evaluation order is not established. They can observe cache state different from the state used to size the allocation.

F-opaque-02 is not established to copy bytes. Its result, if any, is not checked. Reconstruction uses whatever destination contents it leaves.

### Output reconstruction and publication

The destination’s first and third words supply 32-bit attribute and row counts. They are not validated against the allocation size or original 16-bit counts.

The function rewrites the destination header’s attribute and row-region pointers and reconstructs row-array pointers according to the earlier layout. Counts and header pointers are read again at represented uses; immutable snapshots are not established under overlapping storage.

Before **each** output row-loop comparison, four global 32-bit words are read in this order:

1. The word displayed in association with `slnt`.
2. The word associated with `opsz`.
3. The word associated with `wdth`.
4. The word associated with `wght`.

These reads precede both entered and terminating comparisons, including the initial comparison for zero rows. With unchanged row count Q and ordinary non-overlapping storage, each word is read Q + 1 times.

The values from the terminating comparison are retained throughout the attribute-label pass. For each attribute, the function first installs its calculated five-byte slot pointer, then reads its tag and applies this priority:

| Equality with retained comparison word | Selected predefined label |
|---|---|
| `wght`-associated word | `Weight` |
| `wdth`-associated word | `Width` |
| `opsz`-associated word | `OpticalSize` |
| `slnt`-associated word | `Slant` |

The associations do not guarantee runtime comparison values. If values coincide, the first matching comparison wins.

Every attribute advances the label-slot position by five bytes, including redirected labels. Reconstruction writes no label bytes.

Finally, the allocator-returned destination address is written to the output slot. The function then returns shared status. Because unchecked dependencies have run since the allocation-status check, successful publication alone does not prove that this final value is zero.

## Side effects

Direct effects include cache publication, wrapper and backing writes, label-byte writes, global reads, output pointer reconstruction, and final output publication. Dependency calls can additionally affect stream state, context fields, globals, allocations, and other reachable memory.

Shared status is initialized at entry, assigned from preliminary checked operations, exposed by address to allocations, reset at every attribute-loop comparison, assigned during row preparation, and supplied again to optional output allocation. Unchecked later dependencies are not established to preserve it.

No explicit deallocation, rollback, cache clearing, or release of a previous output occurs. This does not constrain memory-management actions inside unknown dependencies.

An output slot can change before final publication through overlap. For example, an output slot at context offset `0x2A0` receives the wrapper-allocation result even when that allocation reports failure.

Predefined label pointers refer outside the planned destination region. Their lifetime, mutability, and release rules are unknown. No blanket per-label ownership rule is supported.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Cached, no output.** With valid entry accesses, a nonzero cache, and null output-slot address, expect zero without dependency calls.

2. **First callback failure.** With absent cache and first callback status `5`, expect return `5`, no second callback, and no allocation call by this function.

3. **Invalid header.** With successful preliminary calls but an incorrect version, expect `8` before wrapper allocation.

4. **One attribute, two rows.** N = 1 and R = 2 require S = 8 and produce B = 73. With valid storage, stable descriptor pointers, successful checked operations, and dependencies preserving identifiers and payloads, both row iterations directly populate the selected first row; its final identifier and value come from the second iteration. The second row receives only its layout pointer from this function. Without preservation, these final-content conclusions do not follow.

5. **Label encoding.** With a stable, disjoint five-byte label slot and parsed tag `0x41424344`, the direct byte stores produce `A`, `B`, `C`, `D`, zero. If the slot overlaps the tag field or label-pointer field, later bytes or destinations can differ because those fields are reread.

6. **Published failed wrapper.** If the output slot aliases context offset `0x2A0`, and the first allocator returns address A with status `6`, the overlapping slot contains A before return `6`.

7. **Attribute-loop reset.** Even with N = 0, reaching the attribute-loop condition resets shared status to zero. With R = 0 and no output request, no subsequent dependency call intervenes before the final return.

8. **Unchecked status mutation.** If output allocation reports zero but F-opaque-02 subsequently changes the escaped shared-status storage to `9`, otherwise valid reconstruction can still publish the output address and finish with return `9`.

9. **Conditional output labels.** Assuming adequate disjoint storage, actual copying by F-opaque-02, preserved payloads, and comparison words matching their displayed tags, `wght` selects `Weight`; an unmatched tag retains its destination-slot pointer.

10. **Zero-count reconstruction.** With valid zero-count destination contents, output reconstruction reads all four comparison words once despite entering no row iteration.
