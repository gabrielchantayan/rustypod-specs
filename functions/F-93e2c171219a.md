# F-93e2c171219a

## Purpose

F-93e2c171219a is a state-driven wrapper around F-2f66a9a6b537. It conditionally installs caller-supplied arguments, invokes that dependency with scaled integer arguments, and returns a scaled dependency result when a state-dependent selector equals one.

The function is not a simple unconditional forwarding operation. Depending on global configuration and changes made during dependency calls, it can:

- Return zero without invoking the dependency.
- Invoke the dependency with two zero-valued leading arguments rather than the caller’s corresponding arguments.
- Invoke the dependency with the caller’s leading arguments.
- Invoke the dependency repeatedly.
- Loop indefinitely without invoking the dependency.

The supplied static representation establishes these control-flow distinctions. It does not establish an application-level purpose for the scaling, states, or dependency.

## Interface

### Caller-supplied inputs

The function accepts four arguments, in this order:

| Position | Contract |
|---|---|
| First | An opaque 32-bit value. It becomes the dependency’s first argument only after a selector-two transition. |
| Second | An opaque 32-bit value. It becomes the dependency’s second argument only after a selector-two transition. |
| Third | An integer multiplied by an entry-time read of the first scale global. The resulting value becomes the active coordinate on a selector-two transition. |

The opaque values have no established pointer, handle, ownership, signedness, or encoding interpretation. In particular, forwarding a zero-valued opaque argument does not by itself establish that a null pointer is being passed.

### Return value

The return is integer-valued. It is initially zero and is replaced after every normally completed dependency invocation by:

**cached second scale × cached first scale × dependency return value**

The function returns this most recently stored result only when the selector equals one. A selector-two transition does not clear or replace the stored result.

These labels describe roles, not established application semantics.

## Behavior

### Entry-time capture

The established read and initialization sequence is:

1. Read the second scale and retain that value.
2. Read the first scale and retain that value for subsequent result scaling.
3. Read the first scale again and multiply this second read by the caller’s third argument. Retain the product as the reset coordinate.
4. Initialize the stored return result to zero.
5. Read the entry state and subtract one. Retain this predecessor value as the fixed state installed after every normally completed dependency call.
6. Initialize the active coordinate to zero.
7. Read the entry state again to obtain the initial active state.
8. Initialize both active opaque arguments to zero.

The repeated reads matter. The first scale used to construct the reset coordinate need not equal the first scale cached for result scaling if the location can change between reads. Likewise, the initial active state need not be one greater than the fixed post-call state if the two entry-state reads differ.

The representation does not establish synchronization or guarantee that concurrent modification is valid. These are separate reads in the supplied behavior, not a promised atomic configuration snapshot.

### Iteration selection

Each iteration uses the active opaque pair, active coordinate, and active state that existed at its beginning.

It reads the selector offset and forms:

**selector = active state + current selector offset**

There are three distinguished selector values: zero, one, and two. All other values, including negative values, follow the ordinary dependency-call path after a preliminary reset-state read.

The selector is not recomputed within the iteration. A global change occurring during a dependency call can influence later iterations, not the branch already selected.

### Selector equals one: return

The function immediately returns the stored result.

This path:

- Does not invoke F-2f66a9a6b537.
- Does not read the reset state.
- Does not replace the stored result.
- Returns zero if no dependency invocation has yet completed.

There is no separate success flag or error result.

### Selector equals two: install caller-derived state

The function installs:

- The reset coordinate computed at entry.
- A newly read reset-state value.
- The caller’s first and second opaque arguments.

It then starts another iteration.

This path does not invoke the dependency and leaves the stored result unchanged. Repeated selector-two iterations repeatedly read and install the reset state, while reusing the same entry-computed reset coordinate and original caller arguments.

### Selector equals zero: invoke directly

The function invokes F-2f66a9a6b537 with five arguments:

1. The iteration’s active first opaque argument.
2. The iteration’s active second opaque argument.
3. Cached second scale multiplied by the iteration’s active coordinate.
4. The iteration’s active state.
5. The caller’s fourth argument.

No reset-state read precedes this call on the selector-zero path.

After the dependency returns normally:

- Its return value is multiplied by the cached second scale and cached first scale.
- The resulting product replaces the stored result.
- The same product becomes the active coordinate.
- The fixed predecessor captured at entry becomes the active state.
- The iteration’s opaque argument pair remains active.

The next iteration then begins.

### Any other selector: preliminary reset, then invoke

For a selector other than zero, one, or two, the function first performs the same preliminary reset assignments used by the selector-two path, including reading the reset state.

It nevertheless invokes the dependency using the values captured at the beginning of the iteration, not the preliminary reset values.

Consequently:

- The dependency receives the pre-reset opaque pair.
- Its third argument uses the pre-reset coordinate.
- Its fourth argument is the pre-reset state.
- The reset-state read still occurs.
- The caller-derived reset values do not become the active state for the next iteration after a normal dependency return.

After the call, the result, coordinate, state, and opaque pair are updated exactly as on the selector-zero call path.

This distinction prevents treating every nonzero, non-one selector as an effective installation of the caller’s arguments.

### Repeated calls and termination

After every normally completed dependency call, the active state is restored to the same fixed predecessor captured at entry. It is not decremented from its previous value and is not derived from the dependency’s return.

The active coordinate, by contrast, becomes the newly scaled dependency result. A subsequent call without an intervening selector-two transition therefore receives:

**cached second scale × previous stored result**

as its third argument.

There is no iteration bound, timeout, or explicit cycle detection. Termination requires an iteration whose selector equals one. The supplied representation provides no general guarantee that such an iteration will occur.

## Side effects

### Directly established effects

The function directly:

- Reads the five global locations under the conditions described above.
- Performs integer additions, subtraction, and multiplications.
- Invokes F-2f66a9a6b537 zero or more times.
- Maintains its active state and stored result locally.
- Returns only through the selector-one path.

No direct write to those global locations, caller-addressed storage, or externally supplied buffers is established.

The order of global reads is behaviorally relevant where those reads are observable or where the execution environment permits the locations to change.

### Dependency effects

The dependency may have effects not exposed by the supplied representation. In particular, this contract does not assume that it preserves globals or that it refrains from modifying or releasing memory associated with any opaque argument.

After a dependency call:

- The selector offset is read again on the next iteration.
- The reset state is read again if a later selector requires it.
- The scales and entry-state values already captured by this function are not refreshed.

Thus dependency changes to the selector offset or reset state can affect later control flow. Changes to the scale globals or entry-state global do not replace this invocation’s cached scale values, reset coordinate, or fixed post-call state.

### Ownership and lifetime

No allocation, release, ownership transfer, retention rule, or lifetime extension is established for this function itself.

Any interpretation of an opaque argument as a resource reference, and any ownership consequences of passing it to F-2f66a9a6b537, require that dependency’s contract. This function supplies no visible ownership enforcement.

## Acceptance examples

These are conditional static acceptance examples, not results of executed tests. Arithmetic is assumed representable, and globals remain stable unless a change is explicitly stated.

### 1. Immediate zero return

Given:

- Both entry-state reads produce one.
- The selector offset is zero.

The first selector is one. The function returns zero without invoking the dependency or reading the reset state. Scale reads and entry-time arithmetic have already occurred before this return.

### 2. Caller arguments installed before one call

Given:

- First scale is three on both reads.
- Second scale is five.
- Both entry-state reads produce two.
- Selector offset is zero.
- Reset state is zero.
- Caller’s third argument is seven.
- The dependency returns four and leaves relevant globals unchanged.

The initial selector is two, so the caller’s opaque pair is installed and the active coordinate becomes twenty-one.

The next selector is zero. The dependency receives:

- The caller’s first opaque value.
- The caller’s second opaque value.
- One hundred five.
- Zero.
- The caller’s fourth opaque value.

Its return produces a stored result of sixty. The active state becomes one, so the next iteration returns sixty. Exactly one dependency call occurs.

### 3. Zero selector calls with zero-valued leading arguments

Given:

- Both entry-state reads produce zero.
- Selector offset initially equals zero.
- First scale is three.
- Second scale is five.
- The dependency returns four and changes the selector offset to two.

The first dependency call receives two zero-valued leading arguments, a third argument of zero, state zero, and the caller’s fourth argument.

The stored result becomes sixty. The active state becomes negative one. With the updated offset of two, the next selector is one and the function returns sixty.

The caller’s first and second arguments were never installed.

### 4. Non-special selector reads reset state but calls with old state

Given:

- Both entry-state reads produce three.
- Selector offset initially equals zero.
- First scale is three.
- Second scale is five.
- The dependency returns four and changes the selector offset to negative one.

The initial selector is three. The reset state is read before the dependency call, but the dependency still receives the initial zero-valued opaque pair, coordinate zero, and state three.

The stored result becomes sixty and the active state becomes two. The next selector is one, so the function returns sixty.

The reset-state value does not determine the dependency’s fourth argument in this example.

### 5. Reset-only nontermination

Given:

- Both entry-state reads produce two.
- Selector offset remains zero.
- Every reset-state read produces two.

Every iteration selects two. The function repeatedly installs the caller-derived values, never invokes the dependency, and never returns.
