# F-a4d60d5095f9

## Purpose

F-a4d60d5095f9 conditionally performs a multi-stage update on a caller-supplied object. Its observable behavior has two paths:

- When the object's byte at offset `0xF8` is nonzero, it stores the supplied 32-bit value at offset `0xF0` and returns without invoking dependencies.
- Otherwise, it records an additional byte, obtains an intermediate handle, invokes several preparation operations, constructs temporary state, optionally submits an operation, stores the supplied 32-bit value, and invokes a final operation on the temporary state.

These are structural descriptions, not established application semantics. In particular, the supplied value is not established to be an identifier, the intermediate handle is not established to be owned, and the final temporary-state operation is not established to release memory.

The contract below describes visible access and call ordering. Effects inside dependencies remain unknown unless explicitly constrained.

## Behavior

The following sequence is established by the supplied static body, subject to dependencies returning normally. Dependency calls can have unknown side effects; the sequence does not imply they preserve any object or global state.

### 1. Entry-path selection

The function reads the byte at object offset `0xF8`.

If that byte is nonzero:

1. It writes the supplied 32-bit value to object offset `0xF0`.
2. It returns.

On this path it does not directly write the recorded byte, read the halfword at `0xF6`, create temporary state through a dependency, or call any dependency.

The byte at `0xF8` is not reread later. A dependency changing that byte on the full path does not cause a new entry-path decision.

### 2. Initial full-path update and handle acquisition

If the entry byte is zero:

1. The function writes the recorded byte to object offset `0xF4`.
2. It calls F-1f46730b1ced with the address at object offset `0xC0` and the supplied 32-bit value.
3. It retains the returned 32-bit handle-like value for subsequent calls.

If the result is zero, the function calls F-a817d8d58c10.

The supplied representation marks this call as non-returning. Thus the represented failure path ends there, after the write at `0xF4` but before this function's final write at `0xF0`. Whether the dependency actually terminates the process, transfers control elsewhere, or behaves differently cannot be established from this body.

There is no explicit recovery branch after that call. If it unexpectedly returned, the visible continuation would use the zero result in subsequent operations. This is not a demonstrated supported execution mode.

### 3. Preparation using the acquired handle

Following nonzero acquisition, the function performs these calls in order:

1. F-d2f99870cc43 receives the acquired handle and returns an opaque 32-bit value.
2. F-89eab22346b0 receives the address at object offset `0x94` and that returned value.
3. F-81a479b6091f receives the object address.
4. F-fa8898fa75ae receives the acquired handle.

The same acquired handle is later supplied to the optional submission call. Consequently, the name or apparent position of F-fa8898fa75ae must not be taken as evidence that the handle has been released or invalidated.

These calls occur before temporary-state preparation and before the query that can suppress submission.

### 4. Temporary-state preparation

The function obtains external values through two separate calls to F-fdd8589eca2d:

1. From the first returned address, it reads the byte at offset `0x2C`.
2. It calls the accessor again.
3. From the second returned address, it reads the 32-bit value at offset `0x28`.

It then calls F-2c5a9f9c1eb3 with:

- The address of the 92-byte temporary region.
- The 32-bit value read through the second accessor result.
- The byte read through the first accessor result.

The two values need not describe the same external-state instance or moment. Replacing the two accessor calls with one cached result would impose a consistency property not present in the visible behavior.

### 5. Submission decision and argument selection

After temporary-state preparation, the function calls F-5c5958cfd5fe and compares its 32-bit result with exactly `8`.

If the result equals `8`, submission is skipped. In particular:

- There is no third call to F-fdd8589eca2d.
- There is no direct read of object offset `0xF6`.
- F-818c773e8c8a is not called.

All earlier full-path operations have already occurred.

If the result differs from `8`, the function calls F-fdd8589eca2d a third time. Its result becomes the first submission argument. This call occurs before any possible read at object offset `0xF6`.

The final submission argument is selected as follows:

| Selection flag | Submission argument | Selected 16-bit value |
|---|---|---|
| Nonzero | Any value | Zero |
| Zero | Zero | Zero |
| Zero | Nonzero | Current halfword at object offset `0xF6` |

Only the last case reads the object halfword. In that case the value is read after the third accessor call, not captured at function entry. Earlier dependency effects on that field can therefore affect the submitted value.

The function then calls F-818c773e8c8a with five arguments, in this order:

1. The result of the third F-fdd8589eca2d call.
2. The address of the temporary region.
3. The originally acquired handle.
4. The original 32-bit submission argument.
5. The selected 16-bit value.

A nonzero selection flag forces the final argument to zero; it does not suppress submission or replace the original submission argument.

The halfword access establishes a 16-bit quantity. Signed interpretation and any wider calling-convention extension are not established by the supplied body.

### 6. Final store and temporary-state operation

Both the skipped-submission path and the completed-submission path converge on:

1. A 32-bit write of the supplied value to object offset `0xF0`.
2. A call to F-920630e53283 with the temporary-region address.
3. Return with no explicit result.

The store occurs before the final dependency call. If that dependency observes or modifies the object indirectly, this ordering matters.

No rollback is shown if a dependency fails to return, faults, or transfers control elsewhere. Reaching the final store does not guarantee that its value remains unchanged after the final dependency runs.

## Side effects

The function's own direct writes are limited to:

- Object offset `0xF4`, one byte, on entry to the full path.
- Object offset `0xF0`, four bytes, either on the short path or near the end of the full path.

This is not a limit on total effects. Dependencies receive addresses that may permit additional reads and writes, and their global effects are unknown.

The function performs no explicit allocation or deallocation in the supplied body. That does not establish allocation-free execution: dependencies may allocate, release, retain, or transfer resources.

The temporary region has local call lifetime. Its address is exposed to dependencies, but no ownership-transfer or retention rule is established. Safe deferred use would require an independently established lifetime arrangement; none is visible here.

The function provides no explicit error result, retry, rollback, or synchronization. Concurrent or reentrant effects are not specified. In particular, the final halfword value and external-state values are sampled at their respective read points rather than as an atomic snapshot.

Address formation uses fixed offsets. No variable-size arithmetic, count multiplication, or numeric adjustment of the supplied value is shown. Valid address formation and storage access are preconditions, not checked outcomes.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Full-path examples assume valid storage, nonzero acquisition, and normal return from the dependencies reached unless stated otherwise.

### Nonzero entry byte

Given any nonzero byte at object offset `0xF8`, the function must directly write the supplied value at `0xF0` and return without dependency calls. The recorded-byte input must not cause a direct write at `0xF4`.

This holds for all nonzero byte patterns, not just `1`.

### Query result exactly eight

Given a zero entry byte and a query result of `8`, the function must complete the preceding preparation operations, skip submission, perform the final `0xF0` store, and invoke F-920630e53283.

It must call F-fdd8589eca2d twice, not three times, and must not directly read `0xF6`.

### Query result other than eight

A query result of `0`, `7`, `9`, or another 32-bit value unequal to `8` selects the submission path. The query is not treated as a Boolean.

### Forced zero halfword

Given a nonzero selection flag, submission receives a zero final argument regardless of the object halfword or submission argument. The original submission argument is still forwarded unchanged.

Given a zero selection flag and zero submission argument, the final argument is also zero. Neither case directly reads `0xF6`.

### Late halfword sampling

Given both a zero selection flag and nonzero submission argument, suppose the third external-state accessor changes the object halfword to `0xBEEF` before returning. The subsequent direct read supplies that 16-bit pattern to submission. An earlier value is not substituted.

### Separate external samples

Suppose the first accessor result exposes byte `0x12` at `0x2C`, while the second exposes `0x34567890` at `0x28`. Temporary-state preparation receives that byte and that 32-bit value, even if the results refer to different objects.

### Acquisition failure

Given a zero acquisition result, the recorded byte has already been directly written. F-a817d8d58c10 is then called. Under the represented non-returning behavior, no later dependency call or final `0xF0` store occurs.

### Final-call visibility

If the final dependency can observe the object indirectly, the function's `0xF0` store precedes that observation. The function does not perform another corrective store after the dependency returns.
