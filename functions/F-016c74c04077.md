# F-016c74c04077

## Purpose

F-016c74c04077 returns a binary comparison result for two memory objects. It compares selected fields, not complete objects, strings, or the contents of referenced storage.

For stable, valid inputs, equality is accepted in either of two cases:

- Both objects have a zero-valued first byte.
- Both objects have the same nonzero first byte, matching bytes at offset 1, and equal pointer values in fields beginning at offset 4.

A mismatch between the first bytes produces immediate rejection. A shared zero first byte produces acceptance without examining later fields.

**Inferred intent:** the function resembles a selective record-equality predicate with a special zero-leading representation. Neither the record type nor the meaning of its fields is established. This interpretation adds no requirements to the observed comparison.

## Interface

### Inputs

The function receives two addresses. Each identifies memory from which the function conditionally reads the following values:

| Offset from each input address | Value read | Condition selecting the access |
|---|---|---|
| 0 | One character-sized byte | Always |
| 1 | One character-sized byte | The first-byte comparison succeeds and the subsequent first-byte check is nonzero |
| 4 | One pointer-valued field | The nonzero path is selected and the first comparison of the offset-1 bytes succeeds |

Offsets are measured in character-sized addressable units from the corresponding original input address. The offset-4 field does not begin relative to the offset-1 byte.

The pointer field occupies one target pointer representation. Its width is not established by the supplied fragment. No complete object size is established.

The fragment does not independently establish the number of bits in a character-sized byte. On an octet-addressed target, offsets 1 and 4 mean one and four octets, respectively. No byte-order interpretation is needed for the individual character comparisons; representation rules still apply to the pointer-valued loads.

### Output

The supplied return type denotes a four-byte result. On an eight-bit-byte target, this is a 32-bit result.

Every normal return produces exactly one of:

- **0:** equality is rejected.
- **1:** equality is accepted.

There is no separate error value. Signed versus unsigned interpretation does not change the numerical meaning of these two results.

### Preconditions

Each selected memory access must be valid under the target execution model:

- Both input addresses must permit reading their first byte.
- The nonzero path requires readable offset-1 bytes in both objects.
- A path selecting the offset-4 loads requires readable pointer fields with suitable alignment and valid representations for those loads and the subsequent equality comparison.
- Address calculations for the selected offsets must be valid.

The function contains no explicit null, bounds, alignment, or representation checks.

A stable-memory precondition is required for the simplified equality rule in this document. Some byte locations are evaluated more than once, and the function supplies no synchronization or snapshot mechanism.

No non-aliasing requirement is established. The inputs may identify the same object or overlapping storage, provided every selected access is valid. No ownership precondition is established beyond whatever access permissions the surrounding environment requires.

## Behavior

### First-byte comparison

The function compares the first byte of one input with the first byte of the other.

If they differ, it returns 0. Neither offset-1 byte nor offset-4 field is selected for access on this path.

If they match, the function evaluates the first input’s first byte again and checks whether it is zero.

If this subsequent evaluation yields zero, the function returns 1. With stable memory, both first bytes are therefore zero, and all later storage is irrelevant to the result. The later fields need not be readable on this path.

The repeated evaluation matters to the source-level description: the second decision is not explicitly based on a saved result of the first read. It does not establish that a compiled implementation performs two distinct physical reads.

### Nonzero first-byte path

If the initial comparison succeeds and the subsequent check of the first input’s first byte is nonzero, the function proceeds to the bytes at offset 1.

It first compares those two bytes.

- If they compare equal, it loads the pointer-valued field at offset 4 from the first object, followed by the corresponding field from the second object.
- If they compare unequal, it skips both pointer-field loads.

The function then compares the offset-1 bytes again. These evaluations still refer to the original objects, even when the pointer fields have been loaded.

If this later byte comparison reports inequality, the function returns 0 without evaluating pointer equality.

If the later byte comparison reports equality, the function compares its currently selected pointer values:

- When the earlier offset-1 comparison succeeded, the selected values are the two loaded offset-4 fields.
- When the earlier offset-1 comparison failed, the selected values remain the two original input addresses.

Pointer inequality produces 0. Pointer equality permits the final return of 1.

For stable memory, an earlier offset-1 mismatch necessarily remains a mismatch at the later comparison. Consequently, comparison of the original input addresses after such a mismatch is not reached under the stable-memory contract. The source-level selection is nevertheless relevant when describing the repeated evaluations; it is not evidence of supported concurrent mutation.

### Stable-memory decision rule

Assuming all selected accesses are valid and the input memory remains stable:

| Condition | Result |
|---|---|
| First bytes differ | 0 |
| First bytes are both zero | 1 |
| First bytes match and are nonzero, but offset-1 bytes differ | 0 |
| First bytes match and are nonzero, offset-1 bytes match, but offset-4 pointer values differ | 0 |
| First bytes match and are nonzero, offset-1 bytes match, and offset-4 pointer values compare equal | 1 |

This table simplifies the repeated evaluations. It does not replace their source-level ordering or establish behavior for changing memory.

### Field interpretation and boundaries

The character-sized fields are compared for equality, not ordering. Their signedness does not introduce a distinction between equal stored character values. The function performs no case conversion, character decoding, normalization, or range validation.

Zero is special only at offset 0. At offset 1, zero is an ordinary value that can match or differ.

The pointer-field comparison concerns pointer values, not the contents of the referenced storage. The loaded pointers are not dereferenced. Equal referenced contents cannot compensate for unequal pointer values.

Offsets 2 and 3 are not explicitly read or compared. No comparison of padding, complete object representations, lengths, or terminators is present. There is no loop or traversal.

The offset calculations use fixed displacements. The fragment contains no variable-length arithmetic or size calculation. It provides no explicit protection against invalid address arithmetic.

### Ordering of reads and decisions

The source establishes these conditional phases:

1. Compare the two first bytes.
2. If they match, evaluate the first input’s first byte for the zero check.
3. If that evaluation is nonzero, compare the offset-1 bytes.
4. If that comparison succeeds, load the first object’s offset-4 pointer field, then the second object’s offset-4 pointer field.
5. Compare the offset-1 bytes again, using locations in the original objects.
6. If the later offset-1 comparison succeeds, compare the selected pointer values.

Within a two-operand byte comparison, the fragment does not establish which operand is evaluated first. The two pointer-field loads, when selected, occur in separate ordered assignments: first input, then second input.

These are source-level evaluation relationships. They are not guarantees about machine instruction ordering, bus transactions, speculative activity, or the number of physical loads. The accesses are not marked volatile. The fragment does not establish a memory-mapped-I/O contract.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They have not been executed. Unless stated otherwise, the inputs are stable and all selected accesses are valid.

1. **Different first bytes**

   If one first byte is zero and the other is nonzero, the result must be 0. Offset 1 and offset 4 need not be readable because neither is selected.

2. **Shared zero first byte**

   If both first bytes are zero, the result must be 1. Different trailing storage does not affect the result. No trailing terminator, offset-1 byte, or offset-4 pointer field is required on this path.

3. **Different offset-1 bytes**

   If the first bytes have the same nonzero value but the offset-1 bytes differ, the result must be 0. The offset-4 fields are not loaded.

4. **Matching nonzero representation**

   If the first bytes match and are nonzero, the offset-1 bytes match, and the offset-4 pointer values compare equal, the result must be 1. The referenced storage need not be inspected.

5. **Unequal pointer fields**

   If the byte conditions select the pointer-field comparison and the loaded values compare unequal, the result must be 0. Identical contents in any referenced objects do not change the result.

6. **Zero at offset 1**

   If the first bytes match and are nonzero and both offset-1 bytes are zero, the pointer fields must still be loaded and compared. Zero at offset 1 is not an early-success marker.

7. **Differences in unexamined storage**

   If the successful nonzero-path conditions hold, differences at offsets 2 and 3 must not independently cause rejection. No explicit comparison of those locations is present.

8. **Same object supplied twice**

   If both inputs identify the same stable, valid object, the result must be 1. A nonzero first byte still requires valid offset-1 and offset-4 accesses; address identity does not eliminate them.

9. **Null-valued pointer fields**

   If the nonzero path reaches two valid pointer fields containing null pointer values, their equality permits the result 1. This does not make null input addresses valid: input addresses are dereferenced before any field comparison.

10. **Readable fields, inaccessible referenced storage**

    If the byte conditions succeed and both pointer fields contain valid values that compare equal, inaccessible referenced storage does not itself require rejection or access. The function does not dereference the loaded values.

None of these examples establishes who owns the objects or their referenced resources.
