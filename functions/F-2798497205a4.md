# F-2798497205a4

## Purpose

F-2798497205a4 publishes a 32-bit value to caller-supplied storage, then selects either a bulk-processing/reset path or a repeated comparison-and-processing path. On normal completion it returns a 64-bit concatenation of two 32-bit words.

**Established behavior:** Two nonzero comparison results and a nonzero owner field select the bulk path. Otherwise, ordinary processing continues until a comparison returns exactly 1. The ordinary path exposes two persistent temporary words to a processing dependency. Later dependency calls may affect those words through retained addresses; the return uses their values after the terminating comparison.

**Inferred intent:** The owner and associated records resemble a container with a header. The ordinary path resembles traversal and removal over a range; the bulk path resembles clearing an entire container and restoring an empty header. These interpretations do not establish dependency semantics.

This contract specifies explicit accesses, branch conditions, call ordering, and consumption of mutable state. It does not assume that dependencies preserve globals, preserve records, release memory, or implement equality.

### Saved words and result

Two persistent 32-bit temporary words participate in ordinary processing:

- **Saved owner word:** Initialized to the owner argument.
- **Saved companion word:** Initialized to the output-address word; overwritten with the captured cursor contents on each ordinary iteration.

The ordinary processing dependency receives addresses of both words. They remain live across subsequent comparisons and iterations during this invocation.

The 64-bit result concatenates two 32-bit bit patterns:

- High half: bits 63–32.
- Low half: bits 31–0.

This is not an arithmetic sum, a sign-extended 32-bit result, or an established single pointer.

On the bulk path:

- The high half is the final header word read through owner +0x10.
- The low half is the saved companion word, initialized to the output address and not explicitly reassigned on that path.

On ordinary termination:

- The high half is the saved owner word.
- The low half is the saved companion word.
- Both values are consumed **after the comparison that returns exactly 1**.

After any ordinary processing call has exposed the saved-word addresses, later dependency calls may modify those words through retained addresses. Consequently, the returned pair need not equal the pair present immediately after the last processing call. The final high half also need not equal the last word explicitly written to the output.

No error-code interpretation is established for either half.

The straightforward examples below assume non-overlapping caller storage. Aliasing is not prohibited by the supplied evidence and may cause earlier writes to change later reads.

## Behavior

### Initial publication and preparation

Before any dependency call, the function:

1. Reads owner +0x10.
2. Writes that 32-bit word to the output address.
3. Reads owner +0x10 again.
4. Reads the resulting header’s +0x08 word into a separate comparison temporary.
5. Initializes the saved companion word from the output address and the saved owner word from the owner argument.
6. Initializes another temporary word from the cursor address.

The second header lookup occurs after the initial output write. If that write aliases the owner’s header field, the second lookup observes the resulting state. The entry header is not retained as an immutable basis for all later operations.

The comparison temporary and the second temporary are distinct from the saved owner and saved companion words.

### Bulk-path eligibility

F-d747682ef415 is first called with:

- The original cursor address.
- The address of the temporary containing the initial header +0x08 word.

If this result is zero, the remaining eligibility checks are skipped and execution reaches the ordinary comparison loop.

If it is nonzero:

1. Owner +0x10 is read again.
2. That header word replaces the second temporary’s contents.
3. F-d747682ef415 is called with the boundary word and the address of that second temporary.
4. If this result is nonzero, owner +0x14 is read.
5. The bulk path is selected only if that gate is nonzero.

Both eligibility results use a **nonzero** predicate. A result of 2 or a negative 32-bit value qualifies just as 1 does.

If the second result is zero, the owner +0x14 gate is not read by this eligibility sequence. If either comparison fails, or the gate is zero, execution reaches the ordinary loop.

The eligibility calls receive temporary-word addresses, not addresses of the corresponding owner or header fields. Mutations to those temporary contents are not subsequently consumed directly by this function. Their addresses have nevertheless been exposed, and no dependency-side retention or other side effect is ruled out.

### Bulk processing and reset

When eligibility succeeds, F-bde2dda221e5 is called with:

- The original owner address.
- The +0x04 word of a header freshly obtained through owner +0x10.

No return value from this dependency is consumed.

After it returns, the function completes these updates in order:

1. Assigns a header word obtained through owner +0x10 to a header’s +0x08 field.
2. Clears a header’s +0x04 field.
3. Assigns a header word obtained through owner +0x10 to a header’s +0x0c field.
4. Clears owner +0x14.
5. Reads owner +0x10 into a final publication value.
6. Writes that value to the output address.
7. Returns that value as the high half and the saved companion word as the low half.

The reset expressions perform fresh owner +0x10 lookups. They do not use a single header address saved before F-bde2dda221e5.

For each header-word assignment, the supplied representation does not establish the relative evaluation order of the destination-header lookup and the value-header lookup. It does establish the order of the completed assignments listed above.

Under stable, non-overlapping storage, the resulting header has:

- +0x04 equal to zero.
- +0x08 equal to its own address-like word.
- +0x0c equal to its own address-like word.

Owner +0x14 becomes zero, and the final header word is published to the output. If the bulk dependency changes owner +0x10, the reset can affect a different header from the one present at entry.

The ordinary loop is not entered after this path.

### Ordinary comparison and iteration

Each ordinary loop condition calls F-d747682ef415 with the original cursor address and the boundary word.

- Exactly 1 terminates ordinary processing.
- Every other result executes an iteration, including zero, 2, and negative 32-bit values.

An iteration performs these operations in order:

1. Reads and captures one 32-bit word from the cursor address.
2. Calls F-577be888b76b with the original cursor address.
3. Replaces the saved companion word with the captured pre-call cursor word.
4. Calls F-8d603c281c73 with the saved owner word’s address, the original owner argument, and the saved companion word’s address.
5. Reads the saved owner word and writes it to the original output address.
6. Proceeds to the next comparison.

The cursor word is captured before F-577be888b76b. Changes made by that dependency to cursor storage do not replace the captured value used in step 3.

The saved owner word persists across iterations; the function does not restore it to the original owner argument before processing. By contrast, the saved companion word is explicitly replaced on every iteration before F-8d603c281c73 is called.

The original owner argument passed to F-8d603c281c73 remains unchanged by mutations to the saved owner word.

### Retained addresses and ordinary termination

F-8d603c281c73 receives writable addresses of both saved words. Its writes are visible to the immediate output publication and to later execution. No supplied dependency contract prevents it from retaining those addresses during this invocation or making them available to another dependency.

Therefore, a subsequent F-d747682ef415 call may modify either saved word, including during the comparison that returns exactly 1.

On that terminating result:

- No further ordinary-body cursor capture occurs.
- Neither ordinary-body dependency is called again.
- The function performs no additional explicit output write.
- The return concatenates the saved owner and saved companion words as they exist after the terminating comparison.

The last explicit ordinary output write occurs immediately after a processing call. The return reads occur later, after the terminating comparison. These are distinct observations; equality between the last publication and the return’s high half requires additional preservation assumptions.

If the first ordinary comparison returns 1, no processing call has exposed these two saved-word addresses through this function. With no other relevant mutation, the return pairs the original owner word with the output-address word, while the output retains the initial header publication.

There is no iteration limit, progress check, or guaranteed termination.
