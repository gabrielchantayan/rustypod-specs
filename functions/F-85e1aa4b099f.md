# F-85e1aa4b099f

## Purpose

F-85e1aa4b099f conditionally checks a supplied record against a collection of expected values. It first honors an incoming status, then applies two prerequisite dependency checks, and finally evaluates record fields and dependency results in a fixed, short-circuiting order.

The established return outcomes are:

- The incoming status, unchanged, when that status is nonzero.
- **10** when an initial prerequisite fails.
- **11** when the prerequisites succeed but a subsequent record check fails.
- **0** when all required checks succeed.

The apparent intent is to validate a record containing text-like and scalar attributes. That interpretation is inferred from address usage and dependency call patterns. The supplied evidence does not establish the record’s domain, the meaning of its attributes, or whether the relevant dependencies actually implement text operations.

This contract describes the visible caller-side behavior. It does not assume that dependencies are pure, preserve memory, or implement familiar library semantics.

## Behavior

### Entry and status precedence

Before testing the incoming status, the function reads a four-byte value from a fixed global location and copies it into the first slot of a temporary descriptor.

Consequently, the incoming-status path is not established to be free of all memory reads. It does, however, bypass all visible dependency calls and record checks.

If the incoming status is nonzero, that exact status is returned. The initial reference, record reference, and expected values do not affect that return.

### Prerequisite checks

With a zero incoming status:

1. A zero initial reference produces return value 10.
2. For a nonzero initial reference, the remaining four descriptor slots are populated with copies of the initial reference, record reference, expected header, and comparison reference, in that order.
3. F-1cb585febd84 is called with the initial reference.
4. If that call returns zero, the function returns 10. F-3ec7d07fef90 is not called.
5. If the result is nonzero, F-3ec7d07fef90 is called with the initial reference and the address of the temporary descriptor.
6. If that dependency returns nonzero, the function returns 10.
7. Only a zero result from F-3ec7d07fef90 permits record checking.

The descriptor has five consecutive four-byte slots:

| Descriptor byte offset | Initial contents |
|---|---|
| 0 | Value read from the fixed global location |
| 4 | Initial reference |
| 8 | Record reference |
| 12 | Expected header |
| 16 | Comparison reference |

Only the first slot is initialized on the nonzero-incoming-status and zero-initial-reference paths. The full descriptor is initialized before either prerequisite dependency is called on the nonzero-initial-reference path.

F-3ec7d07fef90 receives the descriptor’s address. The evidence does not establish whether it reads, modifies, or retains that address. In particular, subsequent comparisons use the descriptor’s final slot after this call, not an independently refreshed copy of the fourth input.

### Header and paired comparison checks

After prerequisite success, all ordinary validation failures produce 11.

The function first tests the record reference for zero. A zero record reference fails without a direct record dereference.

For a nonzero record reference, the four-byte field at offset 4 is read and compared with the expected header. A mismatch ends validation.

If the header matches, the following dependency sequence occurs:

1. F-1cb585febd84 receives the address at record offset 8.
2. Its result is passed as the third, four-byte argument to F-7f14f1ab6851. The first argument is the address at record offset 8; the second is the current value of the descriptor’s final slot.
3. A nonzero result from F-7f14f1ab6851 ends validation.
4. On a zero result, F-1cb585febd84 receives the current value of the descriptor’s final slot.
5. Its result is passed as the third, four-byte argument to a second call of F-7f14f1ab6851. That call again receives the address at record offset 8 and the descriptor’s final slot as its first two arguments.
6. A nonzero result from the second comparison ends validation.

There is no visible rejection of a zero count-like result in either record-comparison stage. A zero is forwarded as the third argument.

The two comparisons are distinct required operations. Their third arguments come from separate calls with different inputs. The second comparison is not skipped merely because the first succeeded, and the evidence does not justify replacing both with one presumed full-text comparison.

The initial prerequisite use of F-1cb585febd84 is also different: there, its result is tested for nonzero rather than forwarded as a comparison argument.

### Scalar checks and mode mapping

Following two successful comparison results:

- The field at offset 520 is read and compared with expected scalar A.
- Only if that matches is the field at offset 524 read and compared with expected scalar B.
- Only if both match is the mode field at offset 528 checked.

The mode rule is asymmetric:

- If the expected mode is **2**, the stored mode must be **0**.
- For every other expected mode, the stored mode must equal that expected mode.

Thus, expected mode 0 and expected mode 2 both accept stored mode 0. Expected mode 2 does not accept stored mode 2.

A mode mismatch returns 11 before the remaining checks.

After a matching mode, the field at offset 532 is read and compared with expected scalar C. A mismatch ends validation.

### Final comparison and final scalar

When all preceding checks pass, the function calls the unresolved dependency identified here as **D-01**, supplying:

- The address at record offset 536.
- The auxiliary comparison argument.

D-01 is a document-local opaque dependency ID; no published opaque function ID was supplied for this dependency.

A nonzero result from D-01 ends validation with 11.

Only if D-01 returns zero does the function read the four-byte field at offset 588. Equality with the expected final scalar produces return value 0; inequality produces 11.

The final scalar is therefore read after D-01 executes. If that dependency changes the field through an alias or another reachable mechanism, the subsequent check observes the post-call value.

## Side effects

### Direct effects

The directly visible function:

- Reads one fixed global four-byte value on every entry.
- Writes its own temporary descriptor.
- Conditionally reads the listed record fields.
- Calls dependencies in the order described above.
- Returns a status.

No direct record write, global write, allocation, deallocation, I/O operation, or ownership transfer is visible.

This does not establish overall read-only behavior. Dependencies receive reference-like values, and one receives the address of the temporary descriptor.

### Ordering and mutation

The behavior is short-circuiting. Failed checks suppress later dependency calls and direct field reads.

The record is not snapshotted. Earlier dependency calls can precede later field reads, and the contract cannot assume those calls preserve the record, descriptor, global state, or other reachable objects.

The global value is copied before any dependency call. Later global changes do not visibly cause that value to be reread by this function.

The ordering described here is the control-flow and data-use ordering established by the supplied representation. It is not a claim about individual machine bus transactions.

### Preconditions and failure exposure

Normal completion requires every reached address computation, direct read, and dependency operation to be valid under the actual execution environment.

The function checks reference-like values only for zero at specific points. It does not visibly validate:

- Record size or alignment.
- Address-addition overflow.
- The extent or termination of data beginning at offsets 8 or 536.
- The validity of the descriptor’s final slot after dependency processing.
- Whether dependencies retain stack-backed descriptor storage.
- Whether dependencies release or invalidate referenced storage.

Invalid memory, dependency faults, or nonreturning dependencies have no established translation into return values 10 or 11.
