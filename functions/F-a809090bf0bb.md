# F-a809090bf0bb

## Purpose

F-a809090bf0bb extracts the three most significant bytes of a 32-bit unsigned input and submits them, in descending significance, to dependency F-9b794b5e3b70. It then reaches a software-interrupt operation identified in the supplied representation by the value 0x123456.

If execution continues normally beyond that operation, the represented return value is a 64-bit quantity whose low 32 bits equal 3 and whose high 32 bits contain a stack-associated address.

This is not an established four-byte serialization contract. The visible behavior submits only three bytes through F-9b794b5e3b70. There is no explicit submission of the least significant byte. The interrupt’s purpose, external effects, and relationship to the preceding submissions are unknown.

All behavior below is based on static evidence. No runtime tests have been performed.

## Behavior

### Byte selection

The first selected value is the input shifted right by 24 bits. Because the input is unsigned and 32 bits wide, this yields precisely the value of bits 31–24, without sign extension.

The second selected value is obtained by retaining the low 24 input bits and then shifting right by 16 bits. The resulting value is precisely bits 23–16. The masking excludes the most significant input byte before the shift.

The third selected value is obtained by retaining the low 16 input bits and then shifting right by 8 bits. The resulting value is precisely bits 15–8.

All three calculations remain within the 32-bit unsigned domain. None requires addition, signed arithmetic, a shift equal to or greater than the input width, or an overflow interpretation. Each result fits within eight bits.

The least significant input byte contributes to none of these three argument values. No claim is made that it is unobservable throughout the wider execution environment: the dependency implementations and interrupt behavior are unavailable.
