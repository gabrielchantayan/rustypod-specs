# F-6dedf9602b01

## Purpose

F-6dedf9602b01 conditionally updates a pair of caller-supplied word arrays, using values obtained from F-d7be9cfb4000 to compute a displacement and a final result.

The function returns one of two 32-bit status values:

- **0:** the initial eligibility condition passed, and the final dependency result had a zero upper 32-bit word. The lower word was stored in the first array.
- **0x17 (23):** either the initial eligibility condition failed or the final dependency result had a nonzero upper word.

A return of 23 does **not** generally mean that no state changed. When the initial condition passes, the second array is updated before the final success condition is known. Those updates are not rolled back on failure.

The arithmetic resembles a wrap-aware displacement followed by an alignment or residual calculation. That interpretation is **inferred intent**, not an established dependency contract. No division, remainder, buffer-management, or ownership semantics may be attributed to F-d7be9cfb4000 from the supplied evidence alone.

## Behavior

### 1. Initial eligibility check

The function first reads the first array’s word at offset 4.

If that word is zero, the function returns 23 immediately. It does not directly read the first array’s word at offset 12, access the second array, or invoke the dependency.

If the first word is nonzero, the function reads and captures the first array’s word at offset 12. Execution continues only if this captured word is also nonzero and has the same 32-bit value as the initially read word at offset 4.

If either requirement fails, the function returns 23 without any direct memory writes or dependency calls.

The captured offset-12 word remains the value used for the second dependency invocation and for the wrap-aware displacement calculation. Later dependency-induced changes to that memory field do not replace the captured value.

### 2. First two dependency invocations

After eligibility succeeds, the function invokes F-d7be9cfb4000 twice, in this order:

1. With the then-current word at offset 0 of the first array as the one explicitly shown argument.
2. With the then-current word at offset 8 of the first array and the captured eligibility word as the two explicitly shown arguments.

The second call’s first argument is read after the first call returns. If the first call changes that field through some external mechanism, the second call can observe the changed value.

The displacement calculation uses a 32-bit value exposed in the secondary result register after each call. Call these the **first secondary result** and **second secondary result**.

This observation does not establish a complete callable interface for the dependency. In particular, it does not prove that the first invocation has only one semantic input, that the two invocations implement different operations, or that these secondary results are remainders.

### 3. Displacement calculation

The two secondary results are compared as **unsigned 32-bit values**.

- If the first secondary result is less than the second, the displacement is the captured eligibility word minus the difference between the second and first secondary results.
- Otherwise, the displacement is the first secondary result minus the second.

These operations produce a 32-bit word, with wraparound modulo \(2^{32}\).

Consequences include:

- Equal secondary results produce zero displacement.
- The less-than branch does not itself guarantee a small or nonnegative mathematical displacement.
- If the difference exceeds the captured eligibility word, subtraction wraps.
- The sign bit of the resulting word does not prevent further processing. Subsequent counter and threshold arithmetic uses unsigned 32-bit operations.

The function does not validate that either secondary result lies below the captured eligibility value. Any such bound would have to come from a separately established dependency contract.

### 4. Unconditional counter update

After the two dependency calls and displacement calculation, the function reads the second array’s word at offset 12.

It adds the displacement to that word modulo \(2^{32}\), then stores the result back at offset 12.

This store occurs even when the displacement is zero. It also occurs before the final dependency invocation and before the function knows whether it will return 0 or 23.

The old counter value is retained for the subsequent threshold expression. The expression does not require another read of the newly stored counter.

### 5. Conditional adjustment

If the displacement is zero, the adjustment condition short-circuits. The function does not directly read the second array’s threshold or adjustment word for this condition.

Otherwise, it compares:

- the second array’s unsigned word at offset 0; and
- the old counter plus the displacement plus the second array’s word at offset 16, with the sum reduced modulo \(2^{32}\).

If the threshold is less than or equal to that wrapped sum, the function subtracts the **then-current** first-array word at offset 4 from the second array’s word at offset 16 and stores the wrapped 32-bit result back at offset 16.

Important distinctions:

- The comparison is unsigned and inclusive.
- The sum is not widened to prevent overflow.
- The subtracted first-array word is reread; it is not necessarily the initial eligibility value.
- The counter store precedes the threshold-related reads. Overlapping storage can therefore affect the condition.
- The representation shows a read of the adjustment word for the comparison and a read for the subsequent subtraction. It does not justify treating that field as a single immutable snapshot.

### 6. Final dependency invocation

The function next invokes F-d7be9cfb4000 with two explicitly shown arguments:

1. The then-current first-array word at offset 0, minus the sum of its then-current word at offset 8 and the displacement, using 32-bit word arithmetic.
2. The then-current first-array word at offset 4.

The captured initial eligibility value is not substituted for the second argument.

The supplied representation exposes a 64-bit result for this invocation. The function tests its upper 32-bit word:

- **Upper word zero:** store the lower 32-bit word at offset 16 of the first array, then return 0.
- **Upper word nonzero:** return 23 without that final store.

Testing the upper word after a signed conversion does not change this decision: only an all-zero upper word is accepted.

A zero lower word is valid on success. A nonzero lower word does not imply success if the upper word is nonzero.

These examples are conditional deductions from the visible operations, not runtime observations. Unless otherwise stated, they assume valid nonoverlapping storage and dependency behavior that does not change the arrays.

### Initial rejection

- Do not invoke F-d7be9cfb4000.
- Perform no direct writes.
- Do not directly access the second array.

### Equal secondary results

Suppose the eligibility words are both 10 and the first two secondary results are both 4.

The displacement is zero. The second-array counter is read and rewritten unchanged. The threshold and adjustment fields are not read for the conditional adjustment.

If the final result has upper word zero and lower word 6, the first array’s destination receives 6 and the function returns 0. If its upper word is nonzero, the function returns 23 without that destination store.

### Wrap-aware branch with adjustment

Suppose:

- Both eligibility words are 10.
- The secondary results are 2 and 7.
- The old counter is 20.
- The adjustment word is 4.
- The threshold is 29.

The displacement is 5. The counter becomes 25. The comparison sum is 29, so equality satisfies the condition. The adjustment word becomes \(4-10\) modulo \(2^{32}\), or 4,294,967,290.

If the final result is rejected, these counter and adjustment changes still occurred.

### Wrapped threshold sum

Suppose both eligibility words are 16, the secondary results are 8 and 0, the old counter is 4,294,967,292, the adjustment word is 3, and the threshold is 8.

The displacement is 8. The counter wraps to 4. The comparison sum wraps to 7. The threshold comparison fails because unsigned 8 is greater than 7, so the adjustment word remains unchanged.

The condition must not be evaluated using an unbounded or widened sum.

### Dependency changes a later-read field
