# F-25d96302c2cf

## Purpose

F-25d96302c2cf interprets a byte-oriented formatting description, obtains data through an array of argument slots, and writes directly to caller-selected memory. Supported operations include numeric fields, bounded strings, raw byte copies, literals, spaces, cursor positioning, count capture, and repeated groups.

Its return value is a signed 32-bit logical count. That count need not equal the number of bytes written, destination displacement, or resulting string length. Negative widths, cursor movement, and eight-bit numeric padding arithmetic can separate these quantities.

The established interface is unchecked. It has no destination-capacity input, implicit output terminator, NUL-based format termination, or explicit error result.

## Interface

### Inputs and representations

Three inputs are visible:

| Input | Interpretation |
|---|---|
| Format cursor | Address of readable directive, operand, delimiter, and literal bytes |
| Initial destination cursor | Address for output; also the initial line-positioning origin |
| Argument cursor | Address of consecutive 32-bit slots |

Bytes are 8 bits, short scalar reads are 16 bits, and integer scalar reads and count stores are 32 bits. Slots carry 32-bit addresses in the supplied representation. Alignment and byte order are not independently established.

Most slots contain addresses rather than immediate scalar values:

- Numeric values and dynamic widths are read through slot-supplied addresses.
- String and raw-copy slots directly identify source bytes.
- Destination switching uses the slot contents as the new destination address.
- Count capture uses the slot contents as a writable 32-bit address.
- Discarding a dynamic operand advances past a slot without reading its contents.

### Outputs and completion

The function returns the current logical count when completion of an outer group encounters the initialized outer sentinel.

Output is written incrementally. The destination cursor, argument cursor, and format cursor are advanced internally; updated cursors are not separately returned. No final NUL is appended automatically.

### Preconditions for bounded use

Execution requires readable format bytes through every reached scan, sufficient argument slots and valid referents, and writable memory for every reached output or count store. Cursor repositioning must also produce valid addresses for subsequent accesses.

Additional requirements include:

- A format that reaches the supported group-completion return path.
- No more than two simultaneously active groups.
- Numeric dependency results compatible with the 36-byte temporary buffer and subsequent reads.
- Arithmetic and pointer operations that remain within supported ranges.

These are caller obligations, not locally enforced checks. Safe memory access alone does not imply snapshot semantics when input and output overlap.

## Behavior

### Initialization and dispatch

Initial state consists of a zero logical count, pending repeat count one, ASCII-space numeric padding, and destination and line-origin addresses equal to the initial destination. The outer group sentinel occupies two initialized zero words.

The current format byte selects an operation. Unrecognized bytes advance the format cursor by one without consuming arguments or producing output. A zero byte follows this rule; it does not terminate interpretation.

A decimal digit invokes F-be4aec3be4dc with the address of the format cursor. Its signed 32-bit return becomes the pending repeat count. The dependency determines the resulting cursor position.

A standalone asterisk advances past itself, reads a signed 32-bit repeat count through the next argument slot, and consumes that slot.

The pending repeat count applies to a subsequent opening parenthesis, not to ordinary output directives.

### Groups and termination

An opening parenthesis saves the pending repeat count and the address immediately after the opening parenthesis. It then resets the pending repeat count to one and enters the body.

The body executes once even when the saved repeat count is zero or negative.

At a closing parenthesis, the active remaining count is decremented. If the result is at least one, execution resumes at the saved body address. Otherwise, the group is popped:

- If the preceding saved-address word is zero, the function returns the logical count.
- Otherwise, interpretation continues after the closing parenthesis.

Thus, the first completed outer group ends the call. Trailing format bytes are not processed.

Repetition does not restore argument consumption, output position, line origin, padding choice, logical count, or other continuing interpreter state. The visible storage accommodates the sentinel and two active groups. Further nesting and unmatched closing parentheses have no established safe behavior.

### Literals

An apostrophe introduces a literal terminated by another apostrophe.

`H` first advances to the following byte and uses that byte as the delimiter. Literal content begins immediately after it.

For either form, each candidate content byte is compared with the selected delimiter. A matching byte is consumed without being copied. Otherwise, the byte is written, the logical count is incremented, and the destination advances.

An immediate closing delimiter produces no output. There is no escape mechanism. NUL has no special treatment unless selected as the delimiter. A missing delimiter leads to continued reads and writes without a local boundary check.

### Numeric width and placement

Conversion occurs before width acquisition. A following asterisk supplies width through the next argument slot as a signed 32-bit integer. Otherwise, F-be4aec3be4dc is called after the directive, or after the unsigned subtype.

F-1cb585febd84 is then called with the temporary buffer. Its signed 32-bit result is the reported content length. If the requested width is zero, a second call with that buffer supplies the effective width. The first result remains the content length; the second need not equal it.

No dependency is established to leave the buffer unchanged. Bytes eventually copied are those present when the copy reads them, not necessarily the original conversion output.

The effective width is added to the logical count before field writes.

If effective width is less than reported length, positive width emits exactly that many ASCII asterisks. Nonpositive width emits no bytes on this branch.

Otherwise, the padding quantity is the low eight bits of effective width minus reported length, subject to the unresolved signed-arithmetic limits. Ordinary placement emits that many selected padding bytes and then copies the reported number of temporary-buffer bytes when that number is positive. No independent terminator is appended.

A special path applies when the temporary buffer begins with ASCII minus and zero padding is selected:

1. Emit the minus sign and advance the output position.
2. Replace the buffer’s first byte with ASCII zero.
3. Decrement the eight-bit padding quantity modulo 256.
4. Emit the resulting number of padding zeros.
5. Copy the full reported content length from the modified buffer.

Consequently, even a width exactly equal to a negative representation’s length can cause substantial output expansion.

### Padding selection

`Z` examines and consumes the following byte. A minus selects ASCII-zero padding; every other byte selects ASCII-space padding.

The setting byte is not dispatched as an operation. Padding selection persists across subsequent fields and group iterations.

### Raw copy: `O`

The first slot supplies a source address. Length is obtained either through a second slot when followed by an asterisk, or from F-be4aec3be4dc after `O`.

The signed length is added to the logical count before copying. A positive length copies exactly that many bytes in forward order. A nonpositive length copies nothing; a negative length still reduces the logical count.

NUL bytes are ordinary data. Each source-byte read occurs immediately before its corresponding destination write. Overlap is not handled as a protected move: earlier writes can change later source reads.

### Bounded string: `S`

The first slot supplies a source address. Width is obtained inline or through a second indirect 32-bit slot.

If the width representation is zero, F-1cb585febd84 is invoked without an explicit argument in the supplied representation. Its return supplies the effective bound. It is not established that this call measures the selected source.

For a positive effective bound, source bytes are copied until NUL is observed or the bound is reached. Remaining field positions are filled with ASCII spaces. Each copied or filled byte increments the logical count before its destination write.

The source-byte test precedes the bound comparison. Therefore:

- A source byte is read even for a zero or negative effective bound.
- Filling the field exactly can cause a read immediately after the last copied source byte.
- A copied source position is read for the condition and again for the output assignment.
- Once a NUL is observed, space filling does not require further source reads.

Unlike raw-copy and space widths, a negative effective string bound does not reduce the logical count.

## Side effects

Output and count stores are immediate, with no transaction or rollback. Earlier writes remain visible if later execution encounters invalid memory or fails to return.

Aliasing can affect future behavior. Output or count stores may overwrite unread format bytes, future argument slots, referenced scalars, or unread source bytes. The operation order above describes live accesses, not pre-read snapshots.

The logical count is not a capacity estimate:

- Positioning and destination switching do not change it.
- Negative raw-copy and space widths reduce it without writing.
- Numeric padding truncates to eight bits.
- Negative zero-padding can expand output unexpectedly.
- Repositioning can overwrite prior output.

The visible body performs no explicit heap allocation or release and returns no allocated object. Dependencies may have additional side effects. Their allocation, retention, ownership, global-state mutation, and memory-preservation behavior are undocumented.

Passing a temporary-buffer address to a dependency does not transfer established ownership or extend that buffer’s lifetime beyond the call to F-25d96302c2cf.

There is no visible null check, capacity check, nesting check, conversion-error handling, or separate error status.

## Acceptance examples

These are conditional static cases, not executed tests.

### Shared noninterference conditions

Every example requires valid accessed memory, sufficient capacity, supported arithmetic, and the stated dependency outcomes.

Output and count-store ranges must not overlap unread format bytes, future argument slots, scalar operands, or unread source bytes, unless the overlap is explicitly part of the example and leaves those future reads unchanged. Dependencies must likewise leave subsequently read data and already promised output unchanged, apart from their specified cursor updates, conversion output, and return values.

For numeric examples, after the stated conversion output is established, width parsing and every length call must leave those temporary-buffer bytes unchanged until placement. The formatter’s specified minus-to-zero replacement remains permitted. These are example conditions, not guarantees about the dependencies.

1. **Literal and explicit terminator.** With format `('ab'N)`, the writes are `a`, `b`, and NUL. The return is 3. No fourth terminating byte is added. No dependency call is required.

2. **Repeated numeric fields consume new arguments.** For `2(I1)`, require F-be4aec3be4dc to return 2 and leave the cursor at the opening parenthesis. On each width parse, require it to return 1 and leave the cursor at the closing parenthesis. Two successive value slots are read. If their conversions establish `7` and `8`, respectively, and each F-1cb585febd84 call returns 1 while preserving the established byte, output is `78` and the return is 2.

3. **Zero repeat still executes once.** For `0('x')`, require F-be4aec3be4dc both to return zero and to advance the cursor to the opening parenthesis. Output is one `x`; the return is 1. Returning zero without that cursor advancement does not establish this result.

4. **Repositioning differs from counting.** For `('abc'T1'Z')`, require the position parser to return 1 and leave the cursor at the following apostrophe. Output first writes `abc`, then overwrites its first byte with `Z`. Final modified bytes are `Zbc`; return is 4. This intentional output-over-output overlap must not affect the unread format.

5. **Destination switching preserves origin.** For `(PT1'v')`, require a valid destination-address slot and a position parse returning 1 with the cursor at the following apostrophe. `P` selects the supplied destination, but `T1` restores the original line-origin address. The literal writes `v` there; return is 1.

6. **Numeric overflow marker.** For a numeric field, require effective width 3 and the first F-1cb585febd84 call to return 4. Output is exactly three asterisks and the count increases by 3. Four conversion bytes alone do not establish the required length result.

7. **Eight-bit padding truncation.** Require conversion to establish `7`, explicit effective width 260, and F-1cb585febd84 to return 1 without changing that byte. Output is three spaces followed by `7`; the count increases by 260.

8. **Negative zero-padding underflow.** Require selected zero padding, conversion bytes `-12`, explicit effective width 3, and F-1cb585febd84 returning 3 while preserving those bytes. Output is a minus sign, 255 padding zeros, then `012`: 259 bytes. The count increases by 3.

9. **String fill without source interference.** For an `S` field whose source contains `a`, `b`, NUL, require effective width 5, obtained either dynamically or by a parser returning 5 at the next directive. Require destination writes not to alter those source bytes before their reads. Output is `ab` and three spaces; the count increases by 5. Overlap that changes later source reads is outside this case.

10. **Negative raw-copy length.** With dynamic `O` length −2, no source bytes are read or copied, and the count decreases by 2. The source-address slot and indirect length operand must still be readable.

11. **Outer completion stops interpretation.** For `('a')('b')`, only `a` is written and the return is 1. The second group is not reached. No dependency outcome is needed.

12. **Zero width involves two independent results.** Require a numeric conversion establishing `7`, requested width zero, first length result 1, and second length result 4. Both length calls must preserve `7`. With space padding, output is three spaces and `7`; the count increases by 4. Equal results from the two calls are not assumed.
