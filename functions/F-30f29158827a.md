# F-30f29158827a

## Purpose

F-30f29158827a conditionally replaces a one-byte discriminator in caller-supplied storage. Its behavior depends on the discriminator’s entry value and, for two entry values, a secondary byte.

Most active branches call one dependency and map its integer result to a replacement discriminator. One branch instead follows two stored addresses, checks a linked discriminator, copies a four-byte value into the original object, and then changes the original discriminator.

The operation has no explicit return value. Its observable results are direct memory accesses and writes, together with any effects of a selected dependency. An unsupported discriminator, secondary value, or dependency result does not produce a fallback discriminator.

“Classification” and “normalization” are possible interpretations, not established domain meanings. The contract below describes the statically visible behavior without assigning meanings to the numeric states.

## Interface

### Argument and result

The function receives one address-bearing argument identifying the base of mutable storage, called the **original object**.

The supplied representation uses a 32-bit integer argument for this address and four-byte loads for linked addresses. Dependency results are represented as 32-bit integers. These facts support a 32-bit address-bearing model for this contract, but do not establish a portable pointer interface, machine calling convention, or address-overflow semantics.

There is no explicit returned result, status code, or separate output parameter.

### Original-object layout

All offsets below are byte offsets from the original object’s base.

| Offset | Width directly accessed | Established role |
|---|---:|---|
| `+0x08` | 1 byte | Primary discriminator, read at entry and conditionally written. |
| `+0x09` | 1 byte | Secondary discriminator, read only for entry primary values 1 and 2. |
| `+0x10` | No direct access on dependency paths | Address supplied to F-f9f07d64c41b for primary values 4 and 5. |
| `+0x14` | No direct access on dependency paths | Address supplied to F-e28034694727 for primary values 1 and 3. |
| `+0x18` | 4 bytes on the linked-storage path | Stored first-link address and replacement destination; its address is instead passed to F-e28034694727 on the primary-2 classification path. |

Passing an interior address does not establish the extent, type, or mutability requirements of the dependency’s input. The locations at `+0x10`, `+0x14`, and `+0x18` are not established as independent subobjects.

### Linked-storage layout

For primary value 2 and secondary value 3, 6, or 7, the function uses the following additional locations:

| Base | Offset | Width | Role |
|---|---:|---:|---|
| Original object | `+0x18` | 4 bytes | Address of the first linked object. |
| First linked object | `+0x18` | 4 bytes | Address of the second linked object. |
| Second linked object | `+0x08` | 1 byte | Discriminator required to equal 6. |
| Second linked object | `+0x10` | 4 bytes | Replacement value copied into the original object. |

“Original,” “first linked,” and “second linked” identify traversal roles, not separate allocations. Their storage may overlap. Nothing in the supplied representation establishes disjointness.

### Preconditions

The primary discriminator must be readable at entry. Further validity requirements are branch-dependent:

- Primary values 1 and 2 require the secondary byte to be readable.
- A selected dependency call requires its argument and any storage it accesses to satisfy that dependency’s undocumented requirements.
- **If a dependency returns a recognized result, the original object’s byte at `+0x08` must still exist and be writable when the subsequent discriminator store occurs.** Dependency-input validity alone does not establish this post-call condition.
- The linked-storage path requires readable four-byte fields at the original object’s `+0x18` and the first linked object’s `+0x18`.
- A nonzero second-link address requires a readable byte at that object’s `+0x08`.
- If that byte equals 6, the second object’s four bytes at `+0x10` must be readable, and the original object’s four-byte replacement field and discriminator byte must remain writable through their respective stores.

There is no explicit null check for the original object or first-link address. Only the second-link address is checked for zero.

No bounds, alignment, lifetime, permission, or address-overflow validation is shown. The contract does not assign defined behavior to accesses that violate the required storage conditions.

## Behavior

### Dispatch and reads

The function first reads the primary byte at `+0x08`. That entry value selects one branch.

It reads the secondary byte only for primary values 1 and 2. No secondary-byte reread is shown. The primary-2 secondary value is treated as an unsigned byte; values from 128 through 255 do not enter a negative-value range.

| Entry primary | Secondary condition | Selected behavior |
|---:|---|---|
| 0 | Not read | Return. |
| 1 | Equals 11 (`0x0B`) | Call F-e28034694727 with the original address plus `0x14`. |
| 1 | Anything else | Return. |
| 2 | In the classification set below | Call F-e28034694727 with the original address plus `0x18`. |
| 2 | Equals 3, 6, or 7 | Attempt the linked-storage update. |
| 2 | Anything else | Return. |
| 3 | Not read | Call F-e28034694727 with the original address plus `0x14`. |
| 4 | Not read | Call F-f9f07d64c41b with the original address plus `0x10`. |
| 5 | Not read | Call F-f9f07d64c41b with the original address plus `0x10`. |
| Any other byte | Not read | Return. |

The primary-2 classification set is exactly:

**1, 2, 12, 13, 14, 15, 16, 17, 22.**

The linked-storage values 3, 6, and 7 are not members of that set. No dependency is called on the linked-storage path.

### Dependency-result transitions

A selected dependency is called once. If it returns normally, the function interprets its result according to the entry branch:

| Entry branch | Result 1 | Result 2 | Result 3 | Any other result |
|---|---:|---:|---:|---|
| Primary 1, secondary 11 | Write 12 | Write 14 | Write 13 | No direct discriminator write |
| Primary 2, classification secondary | Write 15 | Write 17 | Write 16 | No direct discriminator write |
| Primary 3 | Write 18 | Write 20 | Write 19 | No direct discriminator write |
| Primary 4 | Write 21 | Write 22 | No direct discriminator write | No direct discriminator write |
| Primary 5 | Write 23 | Write 24 | No direct discriminator write | No direct discriminator write |

Every listed transition is a one-byte write to the original object’s `+0x08`.

The function does not reread the primary discriminator after the call. A dependency’s change to that byte does not reselect the branch or change the mapping. Subject to the post-call storage precondition, a recognized result causes the mapped byte to be written at the original address plus `0x08`.

Unrecognized results, including zero and negative integers, cause return without a subsequent direct discriminator write. This does not undo dependency effects.

### Linked-storage update

This behavior applies only to entry primary 2 with secondary 3, 6, or 7.

The ordered direct accesses and conditions are:

1. The function loads the four-byte first-link address from the original object’s `+0x18`.
2. It loads the four-byte second-link address from the first linked object’s `+0x18`.
3. A zero second-link address causes return.
4. Otherwise, it reads the second linked object’s byte at `+0x08`.
5. A value other than 6 causes return.
6. For value 6, it reads the four-byte replacement from the second linked object’s `+0x10`.
7. It stores that replacement at the original object’s `+0x18`.
8. It stores 15 (`0x0F`) at the original object’s `+0x08`, then returns.

The first-link address is dereferenced without an explicit zero check. A zero second-link address is different: it is rejected before accessing the second object.

The replacement is copied as a four-byte value. It is not checked for zero, validity as an address, ownership, or consistency with any other field.

The replacement source is read before the destination store. The replacement-field store precedes the discriminator store. There is no shown rollback or transaction if execution fails or is interrupted between them.

### Aliasing and repeated invocation

The direct store destinations are expressed relative to the original object. Those destinations may also belong to linked storage.

For example, if the first linked object begins at the original object’s `+0x10`, the four-byte store at the original object’s `+0x18` also overwrites the first linked object’s bytes at offsets `+0x08` through `+0x0B`. It is therefore not valid to promise that linked objects remain unchanged.

Every discriminator explicitly written by this function is between 12 and 24 inclusive. None selects an active entry branch. If that byte remains unchanged and readable, a later invocation returns after its entry discriminator read. This is not a guarantee of broader idempotence in the presence of dependency effects or intervening mutation.

## Side effects

### Direct memory effects

The only direct write destinations shown are:

- The original object’s one-byte discriminator at `+0x08`.
- The original object’s four-byte field at `+0x18`, on a successful linked-storage update.

No direct store specifically targets the secondary byte. However, the absence of a store expressed relative to a linked object does not imply that its storage is preserved: linked storage can overlap either destination.

Paths that return before a dependency call or direct store perform only the applicable direct reads. On dependency paths, an unsupported result guarantees only that this function performs no subsequent direct discriminator store. The dependency may already have changed the original object, linked storage, globals, or other state.

### Ownership and lifetime

No explicit allocation, deallocation, retain, release, or destruction operation appears in this function.

The successful linked update overwrites the old four-byte value at `+0x18`. The function itself neither releases the displaced value nor explicitly acquires ownership of the replacement. Whether ownership obligations exist is unknown.

Dependency ownership and lifetime effects are also unknown. In particular, the contract does not assume that a dependency preserves the original allocation, preserves globals, retains its input, or releases any memory.

If a dependency invalidates the original discriminator’s storage and returns a recognized result, the subsequent store still appears in the visible behavior, but the required storage precondition is no longer satisfied. There is no shown revalidation or recovery path.

### Errors and concurrency

No explicit diagnostic, status return, retry, or exception handler is shown. An unrecognized dependency result is handled by ordinary return, not by a reported error.

There are no shown locks or atomic operations. The stated access order describes the supplied representation; it does not establish inter-thread visibility, atomic four-byte access, or fault-level atomicity.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Except where a precondition failure is the subject, assume valid storage, normal dependency return, and no external interference.

1. **Inactive discriminator.** Primary 0 or 255 causes return after the primary-byte read, without a secondary read, dependency call, or direct write.

2. **Primary-1 gate.** Primary 1 with secondary 10 returns without a call. With secondary 11, it calls F-e28034694727 at the original address plus `0x14`. Result 2 causes a write of 14, not 13.

3. **Classification membership.** Primary 2 with secondary 22 calls F-e28034694727 at the original address plus `0x18`. Result 3 produces discriminator 16.

4. **Unsigned nonmember.** Primary 2 with secondary 255 neither calls a dependency nor traverses linked storage. Secondary 18 likewise selects neither action.

5. **Zero second link.** Primary 2 with secondary 6 follows a valid first link. If its `+0x18` field contains zero, the function returns without reading a second discriminator or performing a direct write.

6. **Linked discriminator mismatch.** A nonzero second link whose byte at `+0x08` equals 5 causes return without reading the replacement at `+0x10`.

7. **Successful replacement, including zero.** For a second discriminator of 6, the four-byte replacement is stored at the original object’s `+0x18`, followed by discriminator 15. A zero replacement does not suppress either store.

8. **Overlapping first object.** Suppose the first linked object begins at the original object’s `+0x10`, and its `+0x18` field supplies a valid second link with discriminator 6. A successful replacement also overwrites the first linked object’s bytes `+0x08` through `+0x0B`. No particular resulting byte value is assumed without an established byte order and replacement value.

9. **Unsupported result with possible side effects.** Primary 4 with dependency result 3 causes no subsequent direct discriminator write. It does not establish that the discriminator or other memory retains its entry value.

10. **Dependency mutation with valid storage.** For entry primary 5, if F-f9f07d64c41b changes the primary byte, leaves that location valid and writable, and returns 2, the function subsequently writes 24 there.

11. **Dependency invalidates storage.** If the same call instead ends the original object’s lifetime and returns 2, the mapped store has no shown lifetime check. This case violates the post-call storage precondition; no safe outcome is specified.

12. **Later inactive invocation.** Following a completed discriminator write of 20, a later call with that byte unchanged and readable returns after reading it.

## Uncertainties

The following remain **documented_only**:

- Domain meanings of discriminator values and dependency results.
- Complete object layouts, allocation extents, alignment, and permitted aliasing relationships.
- Dependency implementations, accessed storage, global effects, and lifetime or ownership behavior.
- Whether the four-byte replacement is an owning pointer, borrowed pointer, or another value.
- Obligations associated with overwriting the displaced value.
- Target byte order and exact calling convention.
- Arithmetic behavior when address additions exceed the representable range; modular wrapping is not assumed.
- Outcomes of invalid accesses, nonreturning dependencies, asynchronous interruption, and concurrent mutation.

The visible transitions suggest conversion from active states to inactive states. That is inferred intent only.
