# F-3be477dba177

## Purpose

F-3be477dba177 conditionally notifies a dependency of a value replacement, then replaces matching values in a strided region associated with a supplied context.

The established behavior has two distinct paths:

- If the original and replacement values are equal, return without accessing the context or calling the dependency.
- Otherwise, call F-887ba2404a49 once, then scan the context’s entries in increasing index order. Replace each inspected value that equals the original value.

The notification precedes all scan-bound and entry reads. Consequently, the scan uses context state available after the dependency returns, not necessarily the state present when F-3be477dba177 was entered.

**Inferred intent:** the function appears to coordinate a replacement in an external subsystem with corresponding replacements in a local collection. The meanings of the context, values, and notification selector are not established.

## Behavior

### Equal-value short circuit

The first decision compares the original value with the replacement value.

If they are equal, the function returns immediately. In particular:

- It does not read the field at offset `0x0C`.
- It does not invoke F-887ba2404a49.
- It does not read the scan bound.
- It does not inspect or write entries.

This short circuit is based solely on the two value arguments, not on context contents.

### Notification before scanning

If the values differ, the function reads the four-byte field at context offset `0x0C` and invokes F-887ba2404a49 with these arguments, in this order:

1. The value read from offset `0x0C`.
2. The fixed numeric selector `0x72`, decimal 114.
3. The original value.
4. The replacement value.

The first argument is the loaded field value, not the address of that field. Its interpretation is unknown.

There is exactly one visible dependency invocation per unequal-values execution that reaches and completes this call. No scan-bound or entry-field read precedes it.

Any dependency result is ignored. There is no visible success test, failure branch, retry, or compensation. If the dependency returns normally, scanning proceeds without a visible check of its outcome.

### Ordered scan with a live bound

After the dependency returns normally, scanning begins at index zero.

Before inspecting each candidate entry, the function reads the signed 32-bit bound at offset `0x58`. It inspects the candidate only if the current index is strictly less than that freshly read bound.

For an inspected index, the compared field is located at:

`context address + 0x6C + 0x10 × index`

The function reads that field and compares it with the original value:

- A match causes a four-byte write of the replacement value to that same field.
- A nonmatch causes no direct write to that field.

The scan then advances to the next index. It does not stop after the first replacement and does not revisit earlier entries.

The bound is not captured once for the entire scan. Each subsequent condition evaluation reads it again. Therefore:

- A bound of zero or a negative bound at the first evaluation produces no entry accesses.
- If the bound remains a positive value \(N\), the scan inspects indices zero through \(N-1\), subject to valid addressing and ordinary completion.
- A changed bound can affect subsequent continuation.
- The comparison remains signed; a negative bound is not treated as a large unsigned count.

With a stable positive bound \(N\), ordinary completion performs \(N+1\) bound reads: one before each entry and one final read that terminates the scan. A nonpositive initial bound produces one bound read.

### Ordering of direct observable accesses

On the unequal-values path, the direct sequence is:

1. Read the dependency argument at offset `0x0C`.
2. Invoke F-887ba2404a49 and, if it returns normally, continue.
3. Read the bound.
4. If the current index is within that bound, read the corresponding entry field.
5. If that field matches, write the replacement to it.
6. Read the bound again for the next candidate.

Dependency effects occur before the scan’s first bound read. Thus, modifications made by the dependency to the bound or entries can affect the scan.

Within this function’s direct accesses, a matching entry is written before the next bound read or next entry read. Entries beyond the first failed bound comparison are not inspected.

### Widths and arithmetic boundaries

Entry spacing is 16 bytes, not four bytes. The compared field is four bytes wide despite the larger stride.

The index begins at zero and increases by one for every inspected entry. The bound is a signed 32-bit value. On the recovered arithmetic model, the index need not exceed the largest positive signed 32-bit value to terminate against any representable bound.

That does not establish safe addressing for very large positive bounds. Multiplication by 16 and addition to the context address can exceed the relevant integer or address range before the index itself reaches its limit. No range check is visible. Such cases are outside the established ordinary-completion behavior; neither safe wrapping nor a specific failure outcome is promised.

### No matches still produces notification
