### Exchange boundary

After the first dependency returns, the function exchanges the 32-bit contents of +0x7C and +0x80.

The exchange preserves a specific access order. The value at +0x80 is read and retained. The value at +0x7C is then read and written to +0x80. Finally, the retained value is written to +0x7C.

Consequently, the value retained for the exchange is a fresh read after the first dependency call. It is not necessarily the same value previously passed as that call’s second argument.

The exchange has no equality check. Equal field values still undergo the established reads and writes. No atomic exchange, synchronization operation, or exclusion of concurrent observers is established. In particular, the supplied behavior includes an intermediate state after +0x80 has been written but before +0x7C has been written.

In the absence of external interference during these accesses, the two fields contain each other’s pre-exchange values when this phase finishes.

### Second dependency boundary
