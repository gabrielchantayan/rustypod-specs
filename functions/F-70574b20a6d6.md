# F-70574b20a6d6

## Purpose

F-70574b20a6d6 conditionally selects an indexed byte string, skips a classified prefix, removes at most one sign byte, obtains a 64-bit conversion result, and applies signed-range handling.

Ineligible descriptors and failed index checks return a caller-supplied 64-bit fallback. These paths perform no explicit error-indicator write, although any dependency already called may have its own side effects.

The established contract covers memory accesses, selection, traversal, sign handling, result arithmetic, and explicit saturation. It does not establish the conversion dependency’s numeric grammar, base rules, or error conventions.

## Interface

### Inputs and result

| Input | Width and interpretation |
|---|---|
| Descriptor address | A recovered 32-bit address of storage containing an object-reference word at byte offset 0 and additional control storage beginning at byte offset 4. |
| Requested index | Unsigned 32-bit value. |
| Fallback low word | Uninterpreted 32-bit value supplying result bits 31–0. |
| Fallback high word | Uninterpreted 32-bit value supplying result bits 63–32. |

The result is a 64-bit bit pattern exposed as a signed 64-bit value.

Fallback assembly concatenates the high and low words; it does not sign-extend the low word. A high word of zero and low word of 4,294,967,295 therefore produce positive 4,294,967,295.

### Access-dependent storage requirements

The descriptor address must permit a 32-bit read at offset 0. A null descriptor address is not an ordinary fallback case.

The two control accesses at offset 4 have different widths:

- Initial eligibility conditionally reads **one byte** at offset 4.
- After the first bound query succeeds, remapping reads a **32-bit word** at offset 4 and narrows that word to a character-sized value before comparing it with 2.

Consequently, successful progression to the remapping decision requires the entire four-byte region at offsets 4–7 to be readable, not merely the byte at offset 4. Access alignment and other platform requirements are not independently established.

Successful string selection also requires these fields:

| Location | Accessed contents |
|---|---|
| Selected object, byte offset 20 | 32-bit entry-table reference. |
| Entry table plus 40 times the effective index, then byte offset 16 | 32-bit string reference. |

No complete descriptor, object, or entry layout is established.

The selected string must remain readable for the traversal performed here and for the conversion dependency’s accesses. No string length is supplied.

## Behavior

### Eligibility: initialized value and two object reads

Eligibility uses an intermediate unsigned 32-bit value initially equal to the requested index. The recovered access sequence is:

1. Read the descriptor’s object-reference word at offset 0.
2. If that first read is nonzero, read the single byte at descriptor offset 4 and replace the intermediate value with that byte, zero-extended to 32 bits.
3. Read the descriptor’s object-reference word at offset 0 again.
4. Proceed toward the first bound query only when the second object read is nonzero and the intermediate value is nonzero.

The second object read occurs even when the first object read was zero. In that case, the intermediate value still contains the original requested index; no eligibility-byte read has occurred.

Thus, the recovered condition is not unconditionally equivalent to requiring a previously read nonzero control byte. If the two object reads were to differ, the condition would depend on which value remained in the intermediate state.

Under **stable descriptor contents**, the sequence simplifies:

- A zero object word selects the fallback without reading the byte at offset 4.
- A nonzero object word and zero eligibility byte select the fallback.
- A nonzero object word and nonzero eligibility byte reach the first bound query, including when the requested index is zero.

This simplification does not replace the established read sequence. Nor does the sequence establish supported concurrent mutation, atomicity, synchronization, or defined behavior for a data race.

### First bound check

Once eligibility passes, F-e84094e554a6 is called. No explicit argument is shown for this invocation; its effective calling contract remains unresolved.

Its result is interpreted as an unsigned 32-bit bound. The **original requested index** must be less than or equal to that result. The intermediate eligibility value is not the index being checked.

Equality passes. If the requested index exceeds this first bound, the fallback is returned without the remapping word read, second bound query, string selection, or conversion call.

### Word-sized remapping control and second bound check

After the first bound check passes, the function reads the 32-bit descriptor word at offset 4. It narrows that word to the recovered character width and compares the narrowed value with 2.

In the recovered 8-bit character model, the comparison selects the word’s low eight bits. Whether plain characters are signed does not change equality with 2.

This is distinct from another direct read of the byte at offset 4:

- With little-endian word storage, the low eight bits correspond to the byte at offset 4.
- With big-endian word storage, they correspond to the byte at offset 7.

Identifying the narrowed value with the earlier eligibility byte therefore requires an appropriate byte-order assumption and unchanged relevant storage. The supplied body alone does not establish that assumption.

If the narrowed value equals 2, the effective index is twice the requested index plus one, modulo 2³². Otherwise, the effective index remains the requested index.

No independent overflow rejection is performed. The original index has already passed the first bound check before this transformation.

The function then reads the descriptor’s current object-reference word and explicitly supplies it to a second call to F-e84094e554a6. The effective index must be less than or equal to this second unsigned 32-bit result. Failure returns the fallback.

The two calls are distinct. Their bounds need not be assumed equal, and the first call must not be assumed to receive the same object argument as the second.

### String selection

After the second bound check passes, the function rereads the descriptor’s object-reference word. From that object it obtains the 32-bit table reference at offset 20. It then obtains the string reference at table offset:

40 times the effective index, plus 16.

The effective index is not checked again.

These are recovered 32-bit address calculations. No separate guard rejects index-stride overflow, address wraparound, null references, or inadequate backing storage. Such arithmetic does not establish that the resulting address is valid.

The object used for selection is read after the second bound-query call. It is not an immutable object snapshot retained from an earlier check. Dependencies are not assumed to preserve the descriptor or referenced storage; all subsequently accessed memory must remain valid at its actual access time.

### Classified-prefix traversal

The function starts at the selected string and examines bytes in increasing address order.

For each position, it reads one byte as an unsigned value from 0 through 255 and establishes the following byte address as the candidate continuation address.

- A zero byte ends traversal without a classification call.
- For a nonzero byte, F-2a4c402ba617 is called.
- The returned address is dereferenced to obtain a classification-table reference.
- The table byte indexed by the already-read unsigned string byte is fetched.
- If bit 0 is set, traversal continues at the following string byte.
- Otherwise, traversal stops on the already-read byte.

The dependency is called for every examined nonzero byte, including the first one whose classification bit is clear. Its returned table reference is obtained anew on each call.

No specific category, such as ASCII whitespace, is established. No stable classification table or unchanged string storage across dependency calls is guaranteed. Sign handling uses the byte value already read; the body does not reread that byte after classification.

### Sign handling and conversion

The byte ending traversal determines the conversion start and local sign:

| Ending byte | Conversion start | Local sign |
|---|---|---|
| 43, “+” | Immediately after that byte | Nonnegative |
| 45, “-” | Immediately after that byte | Negative |
| Any other byte, including zero | At that byte | Nonnegative |

Only one sign byte is removed. There is no second local classification pass after a sign, and no local rejection of another sign immediately afterward.

F-c4e0ec1bb29e is then called with the conversion-start address and two zero-valued arguments. Its return is used as a 64-bit pattern.

The supplied body does not establish that the zeros mean “no end pointer” and “automatic base.” No returned end position is inspected.

### Result without a removed minus sign

When no minus sign was removed, the returned 64-bit pattern is interpreted as signed:

- A nonnegative signed result is returned unchanged.
- A pattern with bit 63 set triggers F-4af36158f863. The function stores the 32-bit value 2 through the returned address and returns 9,223,372,036,854,775,807.

This handling does not distinguish a large unsigned magnitude, a negative conversion result, or a dependency-specific error sentinel with bit 63 set.

### Result with a removed minus sign

When a minus sign was removed, the conversion result is treated as an unsigned 64-bit magnitude for the local range decision:

- Magnitudes from zero through 9,223,372,036,854,775,808 are accepted.
- The result is their 64-bit two’s-complement negation.
- Zero remains zero.
- Exactly 9,223,372,036,854,775,808 produces −9,223,372,036,854,775,808 without this function’s explicit error write.
- Larger unsigned magnitudes trigger F-4af36158f863, a 32-bit store of 2 through its returned address, and negative saturation to −9,223,372,036,854,775,808.

The boundary follows from the paired 32-bit arithmetic and overflow conditions. It is not merely a test of the sign of the negated result.

Conversion precedes either saturation decision. The body does not explicitly read or clear an error indicator before conversion.

## Acceptance examples

These are conditional static consequences, not executed tests. Relevant storage and dependency-returned addresses are assumed valid.

1. **Fallback assembly.** With a stable zero object word, fallback high word 1, and low word 2, the result is 4,294,967,298. Both initial object reads occur; no eligibility byte or dependency is accessed.

2. **Stable zero eligibility byte.** A stable nonzero object word and byte zero at offset 4 return the fallback before any bound query.

3. **Zero requested index can pass eligibility.** With stable nonzero object storage and eligibility byte 1, requested index zero reaches the first bound query. Initialization from index zero does not prevent this because the byte replaces that intermediate value.

4. **Differing-read condition.** As an access-trace condition only, a first object read of zero, second object read nonzero, and requested index 5 satisfy the recovered eligibility condition without an eligibility-byte read. Requested index zero would not. This does not assert supported concurrent modification or defined data-race behavior.

5. **Inclusive bounds.** Requested index 7 and first bound 7 pass the first check. First bound 6 returns the fallback without the four-byte remapping read.

6. **Word narrowing and storage width.** If the remapping word is 0xAABBCC02, its narrowed value is 2 and index 3 becomes 7. The whole four-byte word must be readable even though only its low eight bits affect that comparison.

7. **Byte-order distinction.** Under stable big-endian storage, a word of 0x01000002 at offset 4 supplies eligibility byte 1 but remapping value 2. Under stable little-endian storage, the eligibility byte is 2. Both cases can pass eligibility, but the equality of the two control values is not byte-order-independent.

8. **Second bound and wraparound.** Remapped index 7 passes second bound 7 and fails bound 6. If requested index 2,147,483,648 passes the first check and remapping is selected, its effective index is 1 modulo 2³².

9. **Classified prefix and plus.** Two leading nonzero bytes with classification bit 0 set, followed by an unclassified “+”, cause three classification calls. Conversion starts immediately after the plus.

10. **Empty string and repeated signs.** An initial zero byte causes no classification call and is passed as the conversion start. For two leading “-” bytes where the first is unclassified, only the first is removed; conversion receives the second.

11. **Positive range.** Without a removed minus, conversion pattern 9,223,372,036,854,775,807 is returned unchanged. Pattern 9,223,372,036,854,775,808 causes the explicit error write and positive saturation.

12. **Negative range.** With a removed minus, magnitudes 0, 1, and 9,223,372,036,854,775,808 produce 0, −1, and the minimum signed 64-bit value without this function’s explicit error write. Magnitude 9,223,372,036,854,775,809 causes that write and negative saturation.
