### Arithmetic interpretation

The displayed value types are consistent with 32-bit integer calculations. All explicit write widths are eight bits, and all untyped forwarded results are four bytes.

Unsigned operations have a clearer static interpretation:

- Testing selector bit 30 examines mask 0x40000000.
- Shifting the unsigned selector left by two retains only the low 32 result bits under 32-bit unsigned semantics.
- Right-shifting the unsigned byte source by 22 is logical.
- Narrowing a value to the stored byte selects its low eight bits at the memory interface.

Several address and argument calculations instead use signed integer expressions. Negative operands, overflowing multiplication, and left shifts that exceed the signed range do not support an unconditional portable arithmetic contract.

A 32-bit machine model may implement such operations by retaining low-order bits, but that interpretation is **documented_only**, not established executable behavior. Pointer conversion, address width, and target-specific treatment of shifted values likewise remain unresolved.

For nonnegative inputs whose displayed intermediate results remain representable, the ordinary multiplication and power-of-two scaling relationships are unambiguous.
