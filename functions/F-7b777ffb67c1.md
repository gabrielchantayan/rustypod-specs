# F-7b777ffb67c1

## Purpose

F-7b777ffb67c1 performs three ordered, short-circuited admission checks. A failed check selects a fallback return path. Successful admission enters an iterative path that prepares invocation-local storage, performs a lookup, and conditionally invokes an operation through the lookup result.

The iterative path uses two opaque static objects:

- **Static object A:** its address is supplied to the first admission check and to a comparison during each iteration.
- **Static object B:** its address is supplied to an optional operation and, separately, to the comparison controlling reset eligibility.

Neither object’s contents are established. In particular, the supplied representation does not establish that object B contains a string, any particular bytes, or a terminator.

“Admission,” “preparation,” “lookup,” “comparison,” “cursor,” and “cleanup” describe observed roles and placement. They do not establish the dependencies’ semantic purposes, ownership rules, or failure contracts.

## Behavior

### Initialization and admission

Before admission calls, the function forms the initial lookup argument from the original context value plus `0x58` and initializes the local working storage. Forming this argument does not itself dereference the resulting address.

Admission consists of three checks in this order:

1. Read the 32-bit word at the original input address plus `4`. Pass that value and the address of static object A to F-4a6c0bf0740c.
2. If the first result’s low 32 bits are nonzero, evaluate the first global pointer-valued expression and dereference its result. Pass the original input address and the argument value obtained from that dereference to F-3805a25164a0.
3. If the second result’s low 32 bits are nonzero, independently evaluate the second global pointer-valued expression and dereference its result. Pass the original input address and the resulting argument value to F-3805a25164a0.

For steps 2 and 3, the dereferenced contents, rather than the pointer expression itself, supply the second argument. The load width and any intervening conversion are unknown.

The three admission results are represented as 64-bit quantities. Only the low 32 bits determine success. The high 32 bits of the most recently executed check are retained for possible fallback.

A zero low word ends admission immediately. Subsequent admission calls, pointer-expression evaluations, and corresponding dereferences do not occur.

The two pointer-valued expressions are distinct expressions, but their evaluated addresses need not differ. Neither their relationship nor their pointee contents are established.

Each expression is evaluated and dereferenced when its own check is reached, after the preceding admission call. Earlier dependencies may change state affecting later pointer evaluation or dereferencing. The observations cannot be treated as an entry-time snapshot.

### Fallback

A failed admission check selects the following sequence:

1. Call F-eb329b335e1b with the original context value, the failed check’s high 32-bit result word, and `0x4A00`.
2. Pass that dependency’s 32-bit result and `0x4A00` to F-682adfd5a561.
3. Return the latter result.

The high word comes from the check that failed, whether first, second, or third. Its meaning is unknown; it is not established to be an error code or an address.

Fallback does not call the iteration-preparation dependency, perform lookup, or invoke F-289ec4311c64.

### Iteration preparation and lookup

Three successful admission checks enter the loop.

Each iteration begins with F-e80871fb2c8c receiving:

- the working-record address;
- the original input address;
- the cursor address;
- the control address.

Next, F-3805a25164a0 receives the working-record address and the address of static object A. Its 32-bit result controls an optional operation:

- Zero: call F-438680ffebfe with the working-record address and the address of static object B.
- Nonzero: omit that call.

The return from F-438680ffebfe is unused. Its effects on working storage and external state are unknown.

F-fc56e84fc491 then receives the current lookup argument and the working-record address. Initially, the lookup argument is the original context value plus `0x58`. Later iterations retain the current value unless a specified `0x4B00` operation replaces it.

### Zero lookup result

If F-fc56e84fc491 returns zero:

1. Call F-682adfd5a561 with the current lookup argument and `0x4A00`.
2. Retain its result.
3. Call F-289ec4311c64 with the working-record address.
4. Return the retained result.

The returned value is the `0x4A00` operation’s result, not necessarily zero.

There is no continuation decision on this path. Changes to control during cleanup cannot cause another iteration.

### Nonzero lookup result and preliminary control handling

A nonzero lookup result becomes the iteration’s retained **found value**.

The function observes the low byte of control:

- A nonzero byte selects the indirect-operation branch directly.
- A zero byte causes F-682adfd5a561 to receive the found value and `0x4B00`. Its result replaces the current lookup argument.

After this preliminary replacement:

- If the replacement is zero, call F-289ec4311c64 and return the found value immediately.
- If the replacement is nonzero, observe the control byte again. A nonzero byte selects the indirect-operation branch; a zero byte skips that branch and proceeds to ordinary cleanup.

The second control observation occurs after the `0x4B00` call. It cannot be replaced with the earlier observation because the dependency is not assumed to preserve control.

The early-return path returns the found value, not the zero replacement. It performs no subsequent dispatch read or continuation decision.

### Indirect operation and reset eligibility

Only a selected indirect-operation branch performs these accesses:

1. Read the found value’s first 32-bit word as a dispatch-table address.
2. Read the callable entry at table byte offset `0x18`.
3. Invoke that entry with the found value as its sole explicit argument.

The indirect call’s 32-bit result is compared with exact value `1`.

- Any result other than `1` skips the reset-eligibility comparison and reset.
- Result `1` causes F-3805a25164a0 to receive the working-record address and the address of static object B.

This is the same static object whose address is supplied to the optional operation earlier in the iteration. Its contents and interpretation remain unknown.

A zero comparison result skips reset. A nonzero result selects this ordered sequence:

1. Clear the entire 32-bit control word.
2. Freshly read the 32-bit word at the original input address plus `4`.
3. Pass that value to F-d8cbf9aa79a9.
4. Store its 32-bit result in cursor storage.
5. Increment the stored cursor by one.
6. Call F-682adfd5a561 with the found value and `0x4B00`, replacing the current lookup argument.

Clearing control precedes the input-field read and F-d8cbf9aa79a9 call. Dependencies are not assumed to preserve that cleared value.

Unlike the preliminary replacement, this reset-path replacement is not tested for immediate return. A zero replacement may become the next iteration’s lookup argument.

### Ordinary cleanup and continuation

After normal processing of a nonzero found value, the function calls F-289ec4311c64 with the working-record address. This includes paths that skip the indirect branch and paths that complete reset.

Only after cleanup does the function observe the control byte:

- Nonzero: return the retained found value.
- Zero: begin another iteration.

Cleanup effects on control therefore participate in continuation.

No explicit iteration limit, progress check, or termination guarantee is present.

## Side effects

Directly represented writes affect invocation-local storage:

- Initialization of the four working words.
- Clearing the full control word during reset.
- Storing and incrementing the cursor during reset.

The function’s direct reads and calls have these ordering constraints:

- Admission checks short-circuit in order.
- Each later admission pointer expression and dereference occurs only after the preceding admission call succeeds.
- Preparation precedes the comparison against static object A, the optional operation using static object B, and lookup.
- A zero lookup result selects `0x4A00` processing before cleanup.
- Dispatch reads occur only after control handling selects the indirect branch.
- Reset clears control before rereading the original input field.
- Ordinary cleanup precedes the continuation decision.

For normally completing executions of the lookup path, F-289ec4311c64 is called once before each return or loop continuation. It is not called on fallback. “Cleanup” identifies placement, not proven destruction or deallocation.

Dependencies may mutate globals, local storage reachable through supplied addresses, input storage, found objects, or dispatch data. Allocation, release, retention, diagnostics, and other effects are unresolved.

No dependency is assumed to preserve object lifetime. Returning a retained found value after intervening calls does not prove the object survived those calls.

The working-record, cursor, and control addresses identify invocation-local storage. Dependency retention of those addresses is unknown; safe use after return is not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

### Failed admission suppresses later observations

If the first admission result has low word zero and high word `H`, neither later admission pointer expression is evaluated or dereferenced. Fallback passes `H` to F-eb329b335e1b.

If the second check fails, the third expression and dereference are omitted, and fallback uses the second check’s high word.

### Admission uses dereferenced contents

Suppose the first check succeeds and the second check’s pointer expression evaluates to address `P`.

The second argument to F-3805a25164a0 comes from dereferencing `P`, with whatever conversion the missing type information requires. It is not supplied merely as the pointer expression’s value.

This case does not establish a four-byte read at `P`, signedness, extension, truncation, or identity conversion. The same limitation applies independently to the third check.

### Earlier calls can affect later admission inputs

If the first dependency changes state governing the second pointer expression, the second check uses that expression as evaluated after the call.

If the second dependency changes the third expression’s result or its designated contents, the third check observes the state when reached. The memory width of that observation remains unresolved.

### Static object identity does not establish contents

If the comparison against static object A returns zero, F-438680ffebfe receives static object B’s address.

If reset eligibility is later evaluated, F-3805a25164a0 receives that same object’s address. Acceptance does not depend on any assumed text, encoding, length, or termination.

### Zero lookup returns the operation result

After successful admission, a zero first lookup result causes F-682adfd5a561 to receive context plus `0x58` and `0x4A00`. Cleanup follows, and that operation’s result is returned even if cleanup changes control.

### A found value can return without dispatch access

With a nonzero found value, zero control byte, and zero preliminary `0x4B00` result, cleanup occurs and the found value is returned. This function does not read the found value’s dispatch data on that path.

A nonzero preliminary replacement followed by a still-zero control byte also skips dispatch, but reaches ordinary cleanup and its continuation decision.

### Exact indirect result controls reset eligibility

An indirect result of `2` skips the comparison against static object B.

An indirect result of `1`, followed by a nonzero comparison, clears control, refreshes the input field, stores and increments the cursor, and replaces the lookup argument. If cleanup leaves control’s low byte zero, the next lookup uses that replacement, including zero.

### Only the low control byte selects branches

Control value `0x00000100` has a zero low byte and follows zero-byte branches despite its nonzero full-word value.
