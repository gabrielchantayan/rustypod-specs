# F-ad34778f6370

## Purpose

F-ad34778f6370 computes a nonnegative classification or ordinal from an unsigned control word, a signed selector, and byte-addressed state.

The control word’s bit 7 enables all state inspection. When enabled, a state byte selects between two behaviors:

- A direct classification based on the selector and, conditionally, another state byte.
- A scan that returns the one-based ordinal of a qualifying entry whose index matches the control word’s low seven bits.

A result of zero means that no positive result was selected by the executed path. The supplied evidence does not establish whether callers interpret zero as failure, absence, or a valid category.

This is a static behavioral contract. No runtime tests have been performed.

## Behavior

### Disabled processing

The enable bit is tested before any state access.

If control bit 7 is clear, the function returns 0 immediately. It does not read the branch byte, the scan bound, any entry, or the direct-classification byte. The selector has no effect.

### Branch selection

If control bit 7 is set, the byte at offset `0x2b` is read and compared with zero.

- Zero selects direct classification.
- Any nonzero byte selects scanning.

Only zero versus nonzero matters for this decision. Whether the recovered character type is signed does not change that distinction.

The branch decision is made once. The function does not re-read this byte to reconsider its branch, although a later scan entry may access the same address.

### Direct classification

When the branch byte is zero:

1. Selector 1 produces result 1 immediately.
2. For every other selector, the unsigned byte at offset `0x35` is read.
3. Result 2 is produced only when that byte is greater than 1 and the selector equals 3.
4. All remaining cases return 0.

The read ordering is significant. Selector 1 bypasses the offset-`0x35` read entirely. Any other selector causes that read, even when the selector is neither 1 nor 3 and therefore cannot produce a positive result.

The direct-classification byte is unsigned. Its qualifying range is 2–255; values 0 and 1 do not qualify.

The control word’s low seven bits have no effect in this branch.

### Scanning

When the branch byte is nonzero, the function begins with:

- Candidate index 1.
- Qualifying-entry count 0.

Before visiting an index, it reads the unsigned byte at offset `0x1a`. The candidate index is visited only if it is strictly less than that byte’s value.

For each visited index, the function reads the unsigned byte at offset `4 + index`.

- An entry of 2–255 is skipped without increasing the count.
- An entry of 0 or 1 increases the qualifying-entry count by one.
- After that increase, the function compares the current index with the control word’s low seven bits.
- If the indices match, the function returns the updated count immediately.

Thus, the returned ordinal includes the matching entry itself. It counts qualifying entries from index 1 through the requested index, not all visited entries.

A requested index containing a nonqualifying entry does not return an ordinal. Scanning continues, but later indices cannot satisfy that same requested-index comparison.

If no return occurs, the index advances by one and the bound is read again. Exhaustion returns 0.

### Bounds and arithmetic

Because the bound is an unsigned byte, its maximum value is 255. The strict comparison makes index 254 the largest index that can be visited. The largest scan-entry offset is therefore 258, or `0x102`.

Under the 32-bit interpretation:

- The loop index remains between 1 and 255 during loop-condition evaluations.
- At most 254 entries qualify during a complete scan.
- Neither the index nor the qualifying-entry count approaches integer overflow.
- The recovered signed comparison of the index and the zero-extended bound has the same result as their ordinary nonnegative comparison over this range.

A bound of 0 or 1 yields no entry reads and returns 0.

A requested index of 0 cannot match because scanning begins at 1. Requested indices 1–127 can match only if visited and qualifying. Indices 128–254 may still be read and counted before exhaustion, but cannot be selected by the seven-bit request field.

The selector is unused throughout the scanning branch.
