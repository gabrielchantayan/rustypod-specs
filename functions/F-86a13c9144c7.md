# F-86a13c9144c7

## Purpose

F-86a13c9144c7 prepares mode-dependent construction descriptors, conditionally initializes two shared measurements, and issues an ordered sequence of allocation and construction calls.

The established behavior includes:

- Using the first shared measurement as the sole initialization sentinel.
- Obtaining two measurements from resource-derived, tagged addresses when initialization is required.
- Preparing six main descriptor regions through calls to an unidentified transfer dependency and subsequent direct field writes.
- Selecting companion fields from a two-entry table.
- Computing a signed placement value from a context width and the measurements.
- Issuing five constructions for mode 0 or four for any nonzero mode, plus one optional construction controlled by a later context-flag read.

The measurements and placement calculation suggest layout-related intent. Rendering, parent attachment, registration, and public object types are not established.

All behavior below is derived from static evidence. No runtime tests have been performed.

## Behavior

### 1. Conditionally initialize the measurements

The routine captures the shared-state address on entry. Its measurement writes and later placement reads use that captured address. The entry sentinel expression also reads the global state-address value; no dependency call intervenes between the initial capture and this check.

Initialization occurs exactly when the signed 32-bit field at offset 52 is zero. Offset 56 is not independently tested.

When initialization is required:

1. F-9d0ecc5f6adf is called without arguments. Its result is retained as the resource-context value for both resource paths.
2. F-ed4b1fd8953e receives the caller’s context and the first global-supplied resource identifier.
3. After that lookup returns, the current global resource-domain value is captured.
4. The descriptor address is read from offset 8 of the lookup result.
5. F-5710a8628cba receives the retained resource context, a **separate read of the global resource-domain value**, and the descriptor’s word at offset 0.
6. F-59c1430f85c2 receives temporary output storage, the preceding resolution result, the low 16 bits of the descriptor’s word at offset 4, and its byte at offset 12.
7. The first 32-bit output word is read, and bit 0 is cleared. The resulting address is used to read signed 16-bit fields at offsets 82 and 84.
8. Those two fields are sign-extended, added, and stored as a signed 32-bit value at shared-state offset 52.
9. F-ed4b1fd8953e is called for the second resource identifier.
10. The second lookup result supplies another descriptor address through offset 8.
11. F-5710a8628cba receives the same retained resource context, the resource-domain value **captured after the first lookup**, and the second descriptor’s word at offset 0.
12. F-59c1430f85c2 and the tagged-address measurement extraction are repeated. The resulting sum is stored at shared-state offset 56.

The first resolution therefore uses a fresh global-domain read; the second uses the earlier captured value. Equality between those arguments requires a stability assumption. In particular, the second resolution does not reacquire the domain after intervening dependency calls.

The descriptor fields used by F-59c1430f85c2 are read after F-5710a8628cba returns. They must not be described as an immutable snapshot taken before that call.

Each measured sum lies between −65,536 and 65,534 and fits in signed 32-bit storage. The first measurement write precedes the second lookup, so initialization is not transactional.

A computed first measurement of zero remains a zero sentinel unless subsequently changed. A later invocation can therefore repeat initialization.

### 2. Prepare the six main descriptor regions

The six regions are labeled **Base**, **Zero companion**, **Nonzero companion**, **Placement**, **Common**, and **Flag-gated**. These labels identify storage roles, not public object types.

For each region, the function calls an unidentified dependency with a destination address, a global-supplied template address, and length 104 bytes.

**Established:** these calls, their arguments, their order, and the direct field writes described below.

**Conditional:** if the unidentified dependency performs an ordinary bounded byte copy, each region receives its corresponding 104-byte template. Its implementation is unavailable; copying, preservation of unrelated storage, and preservation of globals are not independently established.

Preparation proceeds as follows:

1. Issue the 104-byte Base transfer call.
2. Issue the 104-byte Zero companion transfer call.
3. Capture the global companion-table base.
4. Read the context flag byte and select entry index 0 or 1 for the Zero companion.
5. Separately reload the global table base, read the selected 32-bit entry through that reloaded base, and write it at Zero companion offset 72.
6. Issue the 104-byte Nonzero companion transfer call.
7. Read the context flag byte again and independently select its entry index.
8. Read the selected 32-bit entry through the table base captured in step 3, and write it at Nonzero companion offset 72.
9. Read the first shared measurement, the second shared measurement, and the signed context width, in that order.
10. Read the non-mode-1 global opaque value unconditionally. If mode equals 1, read the mode-1 global value afterward and replace the selected value.
11. Issue the 104-byte Placement transfer call, then write its placement field and selected opaque field.
12. Issue the 104-byte Common transfer call, then write its selected opaque field.
13. Issue the 104-byte Flag-gated transfer call.

All six transfer calls occur before the first allocation, regardless of which descriptors the later construction branch uses.

#### Companion selection and table-base lifetime

Each index is 1 only when that particular flag read has bit 0 set **and** mode equals exactly 1. Otherwise it is 0. Other flag bits have no visible effect.

The Zero companion assignment uses the separately reloaded table base. The Nonzero companion assignment uses the earlier captured base across the intervening Nonzero companion transfer call.

Capturing a base does not capture the table’s entries. The second entry read observes memory through the retained base at the time of that read. If an intervening dependency changes the global base, the second assignment does not necessarily use the new base. If it changes the retained table’s contents, the second read can observe those changes.

#### Placement arithmetic

Let the three retained signed 32-bit reads be:

- \(A\): shared-state offset 52.
- \(B\): shared-state offset 56.
- \(W\): context offset 8.

The direct write at Placement offset 60 is:

\[
A+\operatorname{trunc}_0\!\left(\frac{W-(A+B)-2}{2}\right)
\]

Division truncates toward zero. Thus a numerator of −1 produces a quotient of 0.

The represented calculation forms \(A+B\), subtracts that sum from \(W\), subtracts 2, divides by 2, and adds \(A\). The signed 32-bit additions and subtractions require representable intermediate results for this formula to be an established acceptance condition. Overflow behavior is documented_only.

The retained numeric inputs are used after the Placement transfer call. That call does not cause the routine to reread the measurements or width.

#### Mode-dependent opaque value

The non-mode-1 global value is read even when mode equals 1. In that case, the subsequent mode-1 read supplies the selected value.

Both reads precede the Placement transfer call. The selected 32-bit value is retained and directly written to:

- Placement offset 64.
- Common offset 64.

The Common assignment does not reacquire either global after intervening calls. These are guarantees about the issued direct writes, not guarantees that later dependencies preserve the written fields.

#### Mode is nonzero

2. Prepare an extended descriptor region using the operations below.
3. Read the global-supplied allocation request and pass it to F-8157a180d901.

The extended-region operations are ordered as follows:

| Order | Relative offset | Operation |
|---|---:|---|

How much descriptor storage F-4a73b9be0f3a reads is unknown.

### 5. Issue the Common construction

After either mode branch, request 544 bytes and invoke F-7f6becd152e6 with Common.

### 6. Conditionally issue the Flag-gated construction

If bit 0 is set:

1. Read the global-supplied optional-field source base.
2. Read its 32-bit field at offset 32.
3. Write that value at Flag-gated offset 100.
4. Request 560 bytes.
5. Invoke F-60fe53f7ab39 with Flag-gated.

If bit 0 is clear, these operations are skipped.

This decision uses the final flag read, not either companion-selection read.

## Acceptance examples

These are conditional static expectations, not observed executions. They require normal dependency returns and valid reached accesses. Examples involving descriptor contents additionally require ordinary bounded-copy semantics and preservation of relevant storage until observation.

### Cached measurements

If offset 52 contains 12 at the entry sentinel check, initialization is skipped even if offset 56 is zero or otherwise unsuitable. If later reads obtain 12, 8, and width 101, Placement offset 60 is directly written with 51.

### Initialization and signed extraction

If the sentinel is zero, both resource paths are reached in order, assuming normal returns. The first sum is stored before the second lookup.

If a measurement object contains signed 16-bit values −3 and 7, its stored sum is 4. If the output address word has bit 0 set, that bit is cleared before accessing those fields.

### Resource-domain reads

If the post-first-lookup capture obtains domain value D, but the separate first-resolution read obtains E, the first F-5710a8628cba call receives E and the second receives D. Intervening changes to the global domain do not replace the retained D.

### Table-base capture

Suppose the table base captured after the Zero companion transfer is T, and the separately reloaded base is U. The first assignment reads through U.

If the subsequent Nonzero companion transfer changes the global base to V, the second assignment still reads through T. Its selected entry depends on its own flag read, and its contents are those observed through T at that later time.

### Mode-value read order

For mode 1, the non-mode-1 value is read first, then the mode-1 value. If the latter is M, both direct field assignments use M even if intervening transfer calls change the global values.

### Negative odd placement numerator

If the retained measurements are both zero and width is 1, the numerator is −1, the quotient is 0, and Placement offset 60 receives 0.

Because a zero sentinel triggers initialization, this example requires the later measurement reads actually to obtain zero.

### Construction branches

With a stable clear flag and mode 0, descriptor arguments occur in this order: Base, Zero companion, Placement, separate 92-byte region, Common.

With a stable set flag and mode 1, the order is Base, Nonzero companion, extended region, Common, Flag-gated. Both companion indices are 1.

With a stable set flag and mode 2, the same nonzero construction branch is used, but both companion indices are 0 and the non-mode-1 opaque value is selected.

### Extended-region contents

If the transfer dependency copies exactly the requested range without changing unrelated storage, and subsequent dependencies preserve the region, F-4a73b9be0f3a receives the extended layout specified above. Without those assumptions, only the direct writes and transfer-call sequence are established.
