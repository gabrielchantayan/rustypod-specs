# F-8c14e6e0460d

## Purpose

The visible fragment interleaves four byte stores with 24 indirect calls. The stored values are derived from an explicit input word and an intermediate call result. Each store destination is selected by a byte read from another address.

No application-level purpose is established. The evidence does not identify initialization, encoding, device control, or memory management.

This contract describes the supplied static representation, not independently validated executable behavior. The representation reports invalid instruction data and ends at a bad-data boundary. The function boundary, recovered calling convention, and hidden entry-state requirements remain uncertain.

## Interface

### Explicit input

The recovered interface accepts one unsigned 32-bit **input word**.

The fragment uses it as follows:

- Its low eight bits supply the first stored byte.
- Its full 32-bit value is passed to F-000000000001.
- Bits 22 through 29 supply the second stored byte.

Bits 30 and 31 do not contribute to the second stored byte: although the logical right shift retains them temporarily, the subsequent byte narrowing discards them.

### Hidden entry state

Two recovered signed integer values are consumed without appearing in the explicit argument list:

- An incoming general-register value, multiplied by 524,288 to form the **initial address basis**.
- An incoming link-state value, increased by 4,080 to form the first indirect-call target.

Their provenance and permissible entry values are unknown. Neither may be assumed to be zero.

Both calculations require signed-arithmetic qualifications. In particular, the link-state addition is not established as a wrapping address calculation. If adding 4,080 exceeds the signed type’s representable range, the resulting behavior is unknown.

### Outputs and completion

The recovered return type is void, but no normal return is visible.

Observable outputs consist of:

- Up to four direct byte stores.
- The sequence of indirect invocations and their visible arguments.
- Additional effects of those invocations, which are unspecified.

The terminal bad-data marker does not establish a successful return, an executable halt instruction, or a particular platform exception.

### Widths and address interpretation

The represented dataflow includes:

- Eight-bit selector reads and byte stores.
- An unsigned 32-bit input word.
- An unsigned 32-bit intermediate result.
- Two opaque four-byte results forwarded between calls.
- Signed integer entry values and call results.

Under the recovered 32-bit integer model, unsigned arithmetic is modulo \(2^{32}\). This applies to the intermediate word’s address calculation, not to signed calculations merely because their results are subsequently converted to addresses.

The signed calculations requiring qualification are:

1. Multiplication of the incoming general-register value by 524,288.
2. Addition of 4,080 to the incoming link-state value.
3. Two left shifts of signed call results by two bits.

The representation does not justify unconditional wrapping for any of these operations. Pointer width, integer-to-address conversion rules, executable-address requirements, and the accessibility of computed addresses are not independently established.

## Behavior

F-000000000001 through F-000000000024 are opaque identifiers for call sites in invocation order. They do not imply 24 distinct runtime functions.

Every step below is conditional on preceding accesses completing and preceding calls returning. Dependencies may modify memory or other shared state between the fragment’s own accesses.

### 1. Initial selector read and first store

The fragment forms the initial address basis by signed multiplication of the incoming general-register value by 524,288.

It reads one unsigned byte at that basis plus one. It then adds 17 to the selector byte’s numerical value and stores the input word’s low eight bits at the resulting address.

The selector is zero-extended. The store destination is therefore a numerical address from 17 through 272, inclusive—not an offset from the initial address basis.

There is no visible address validation. If the initial signed multiplication is outside its representable range, the representation supplies no reliable resulting address. When that multiplication is representable under the recovered signed 32-bit model, adding one to its result is also representable.

### 3. Second selector read and second store

After F-000000000007 returns, the fragment rereads the unsigned byte at the initial address basis plus one.

It adds 17 to this newly read selector and stores:

\[
\left\lfloor \frac{\text{input word}}{2^{22}} \right\rfloor \bmod 256
\]

The second store therefore uses input bits 22 through 29.

The selector is read again rather than reused. The first two stores can target different addresses if a dependency, an earlier aliased store, or another source of memory change alters the selector.

### 5. Third selector read, third store, and retained selector

The fragment reads the unsigned byte at the initial address basis plus one for a third time.

Using this selector, it stores the following byte at the selector value plus 17:

Only bits 0 through 5 of the intermediate word affect this stored byte. The stored byte’s low two bits are zero.

The fragment retains the selector value read before the store and passes that value, zero-extended to an unsigned integer, to F-000000000013. It does not pass the product byte and does not reread the selector for this argument.

If the third store aliases the selector location, the argument still reflects the pre-store selector value.

### 7. Fourth selector read and fourth store

The fourth selector-read address is derived from the intermediate word rather than from the initial address basis:

\[
\text{selector address} =
(8 \times \text{intermediate word} + 1) \bmod 2^{32}
\]

Both the multiplication and addition belong to the recovered unsigned 32-bit arithmetic. The resulting integer is interpreted as an address; the validity of that conversion and address remains unestablished.

The fragment reads one unsigned byte there, adds 17 to the selector value, and stores:

\[
\left\lfloor \frac{\text{intermediate word}}{2^{20}} \right\rfloor \bmod 256
\]

Thus the fourth stored byte consists of intermediate-word bits 20 through 27.

The represented calculation masks the intermediate word with \(2^{30}-1\) before shifting right by 20. Clearing bits 30 and 31 does not change the final byte: neither bit would survive byte narrowing. Bits 28 and 29 likewise do not survive that narrowing.

## Side effects

### Direct memory effects and ordering

If all visible operations are reached, the fragment performs four byte reads and four byte stores, excluding dependency effects.

Their order is:

1. Initial-basis selector read and first store.
2. Calls 1–7.
3. Initial-basis selector reread and second store.
4. Calls 8–12.
5. Initial-basis selector reread and third store.
6. Calls 13–19.
7. Intermediate-word-derived selector read and fourth store.
8. Calls 20–24.

All four direct store destinations lie in the numerical range 17 through 272. Destinations may coincide; a later store then replaces the byte written earlier, subject to any intervening dependency effects.

Selector addresses and store destinations are not proven disjoint. Aliasing can affect later selector reads. No buffering, atomicity, rollback, or preservation of previous destination contents is visible.

### Errors and interruption

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes that preceding operations complete and that the relevant addresses and call targets are usable.

### Input extraction

For input `0xFFFFFFFF`:

- The first stored byte is `0xFF`.
- The second stored byte is `0xFF`, not `0x3F`.

The logical right shift by 22 yields `0x3FF`; byte narrowing retains `0xFF`.

For input `0x00400080`:

- The first stored byte is `0x80`.
- The second stored byte is `0x01`.

Each destination depends on its own selector read.

### Independent selector reads

If the first three selector reads return 3, 9, and 255, their store destinations are numerical addresses 20, 26, and 272.

F-000000000013 receives 255 regardless of whether the third store subsequently changes the selector location. Reusing the first selector or passing the third stored byte would not match the represented behavior.

### Intermediate-word arithmetic

If F-000000000012 returns `0xF1234567`:

- The third stored byte is `0x9C`.
- The fourth stored byte is `0x12`.
- Multiplication by eight modulo \(2^{32}\) yields `0x891A2B38`.
- The fourth selector-read address is numerically `0x891A2B39`, conditional on the recovered integer-to-address interpretation.

The fourth store destination still depends on the byte read at that address.

### First-target signed-addition boundary

Under the recovered signed 32-bit model, an incoming link-state value of 2,147,479,567 produces the representable target integer 2,147,483,647 after adding 4,080. This establishes arithmetic only, not an executable target.

An incoming value of 2,147,479,568 would require the mathematical result 2,147,483,648, outside that signed range. No wrapped target or subsequent invocation is specified for this case.

Because the first store precedes the first call, the representation places that store before the target use. This ordering does not resolve machine behavior for an overflowing signed target calculation.

### Signed-result arguments

If F-000000000007 returns 5, F-000000000008 receives 20.

If F-000000000019 returns 7, F-000000000020 receives 28.

No unconditional expected argument is established for negative operands or unrepresentable signed left shifts.

### Interrupted execution

If F-000000000012 does not return, the third and fourth direct stores are not reached. No rollback of the first two stores is visible, and their continued contents depend on intervening dependency effects.
