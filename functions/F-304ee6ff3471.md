### Width and arithmetic interpretation

Memory operations distinguish 8-bit bytes, 16-bit quantities, and 32-bit words. Represented wide results contain 64 bits.

For conditional arithmetic examples, word operations retain the low 32 bits:

- Left shifts discard displaced upper bits.
- Right shifts cannot recover previously discarded bits.
- Successive left shifts totaling at least 32 yield zero under this interpretation.
- Byte and 16-bit stores retain the low 8 and low 16 bits respectively.
- Explicit unsigned byte widening produces values from 0 through 255.
- Scaled addresses and additions may wrap under a 32-bit address interpretation.

These are conditional bit-vector rules, not an assertion that signed overflow or invalid shifts are defined in a higher-level language.

A late right shift operates on a signed word, using the low byte of another value as its count. That byte can represent counts above 31. Signed right-shift behavior and excessive-count handling are **documented_only**; masking the count to five bits is not established.

Under the conditional 32-bit interpretation, the index field equals four times its originating word’s low seven bits. The index base therefore ranges from 0 through 1,016 in multiples of eight. It is not necessarily an object address.

The opening region first stores the shifted link as a word at the final wide result’s upper-word-derived address plus 0x14. A byte from that upper word is then stored at shifted-link offset 9. A word store through the wide result’s low word, scaled by 256 and offset by 0x54, publishes the shifted base. The offset-9 byte is then overwritten with the shifted link’s low byte.

Next, shifted-base offset 0x14 is cleared as a word, and its offset-5 byte is read. Index-base offset 0x14 is cleared before the saved byte is widened and stored as a word at shifted-base offset 0x34. Only then is the opening word read. ### Early fixed-address effects and linked mutation

Immediately after the opening region, the function captures the global value at fixed address **0x05**, then writes the low byte of the index base to fixed address **0x01**. The read precedes that write. The supplied material does not independently establish the global declaration’s read width or signedness; those details remain **documented_only**. Its value is converted to a 32-bit unsigned quantity and used as an address base.

Computed mutations then intervene before the linked capture is obtained. They include a byte write at that global-derived base plus 0x15, a byte write at shifted-base offset 0x11, a word write at opening-word offset 0x54, and a clearing byte write at shifted-base offset 0x11. The first offset-0x11 byte write therefore remains an event even though a later store clears the same location.

The word at global-derived offset 0x54 is captured before that location is overwritten with the opening word. Consequently, the linked capture depends on memory as modified by the intervening computed writes, not simply on entry memory.

Further accesses use words read at offset 0x74 as address bases, perform self-referential word stores, and repeat byte and word stores. One represented assignment reads index-base offset 0x74 for both destination construction and stored value; the exact operand-read ordering within that expression is **documented_only**.

Two fixed writes occur amid these computed mutations:

- A **32-bit write at 0x54** stores twice the linked capture. It follows an index-base offset-0x14 word write derived from the shifted-base origin. Two stores of the linked capture at that computed offset follow the fixed write.
- Later, after two byte writes of the low byte of four times the linked capture at index-base offset 0x15, an **8-bit write at 0x15** stores the index base’s low byte.

These fixed destinations must remain distinct access events even if they alias computed destinations.

The ensuing region uses byte and word accesses at offsets including 0x01, 0x04, 0x05, 0x09, 0x0D, 0x14, 0x15, 0x24, 0x34, 0x44, 0x54, 0x64, and 0x74. Some unsigned byte reads become address bases for word reads. Repeated reads of a location are not interchangeable when writes intervene.

### Late capture and global reloads

After publication, the function captures the **32-bit word at fixed address 0xA9**. It next captures a word at payload offset 0x74, then writes a byte at fixed address **0x3A**. That byte is derived from eight times the adjusted base plus 0x30, truncated to eight bits.

The 0xA9 capture therefore precedes the 0x3A write. The captured word remains a saved value even if the write aliases its storage.

Let the **late link** denote twice the late linked word. After the 0x3A write, the function captures words at late-link offset 0x14 and work-base offset 4. It then performs computed byte writes, including numeric 0x6C at work-base offset 8, and a self-referential word write at late-link offset 0x54.

Only afterward does it write the saved 0xA9 word’s low byte to fixed address **0x67**. A word read at late-link offset 0x44 follows. The function then reads the byte at **0x67** and writes that read value to fixed address **0x21**.

This is a read of current memory, not merely reuse of the originally saved byte. No represented write separates the 0x67 store from that first reload, but device or concurrent-observer semantics are unknown.

Computed mutations subsequently intervene before each of two more 0x67 reloads:

- Before the first later reload, the function writes at work-base offset 0x10 and publication-base offset 0x54, performs the signed variable-count shift for a byte store at late-link offset 1, overwrites publication-base offset 0x54 again, and makes further word reads and stores. The freshly read 0x67 byte is stored at work-base offset 9.
- Before the second later reload, it writes a byte at late-link offset 9, writes the captured 0xA9 word at work-base offset 0x44, and reads a word at work-base offset 0x54. It then reads **0x67 again** and stores that newly read byte at work-base offset 9.

The two later reloads cannot be replaced by the captured word’s low byte or assumed equal to each other. Any intervening computed write may overlap 0x67.

### Final mutation and terminal invocation

Later writes restore the previously captured late-link offset-0x14 word at late-link offset 0x54, publish low bytes from saved or newly read words, and overwrite work-base offset 0x44.

A word read at late-link offset 4 supplies a base for a **16-bit store of 0x65 through its doubled address**. A subsequent word read at that base plus 0x64 supplies a terminal-chain value. ### Narrowing and small addresses

Under 32-bit bit-vector arithmetic, the low byte of a word shifted left by 25 is zero. The opening shifted-link offset-9 overwrite therefore stores zero.

If the index origin’s low seven bits are 127, the index base is 1,016, and its offset-0x14 access targets address 1,036. Acceptance must not substitute an assumed heap-object destination.

An explicitly unsigned byte value 0xFE widened to a word becomes 254, not −2.

### Early fixed-state ordering

If the write at 0x01 overlaps storage contributing to the 0x05 global read under the actual mapping, it cannot change the value already captured by that earlier read. Later computed writes may nevertheless affect the subsequent linked capture.

If the linked capture is 3, the fixed word write at 0x54 carries 6 under the conditional word interpretation. That event remains required even if a subsequent computed store overwrites it.

### Publication capture

If the publication global yields a base before the 0x60 write, publication uses that captured base even when writing 0x60 changes its backing storage. Reloading the publication global after the fixed write is not equivalent.

### Distinct 0x67 observations

Suppose the saved 0xA9 word has low byte 0xAB. In ordinary memory without intervening external changes, the first 0x67 reload supplies 0xAB to 0x21.

If an intervening computed write changes 0x67 to 0xCD before the first later reload, that reload supplies 0xCD to work-base offset 9. If another intervening write changes it to 0xEF before the second later reload, the second store supplies 0xEF. Replacing all three observations with 0xAB violates the specified state dependencies.
