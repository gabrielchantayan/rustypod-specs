# F-2c52745b6e86

## Purpose

The supplied static representation describes an ordered sequence of indirect calls, interspersed with eight 32-bit stores and four byte stores. Returned words determine several store addresses and later call arguments. Additional address and data calculations depend on incoming machine state that is not represented by the single explicit argument.

No application-level purpose is established. In particular, the small address offsets do not establish object fields, array elements, device registers, or a serialization format.

This contract distinguishes:

- **Established static evidence:** operations and ordering present in the supplied representation.
- **Inferred intent:** possible interpretations that are not required behavior.
- **Unknowns:** matters designated **documented_only**, with no invented implementation requirement.

The representation carries warnings about invalid instruction data, overlapping global symbols, and truncated control flow. Consequently, this is a conditional contract for the represented execution sequence, not proof that the original executable can execute that sequence successfully.

### Output and termination

There is no visible normal return. The representation ends at a bad-instruction/truncated-control-flow marker after the final indirect call. It does not establish whether the executable traps, continues through undiscovered instructions, or reaches this point at all.

### Preconditions

Completion of the represented sequence requires:

- Every reached indirect-call target to be executable under the actual calling convention.
- Every reached dependency to return if subsequent operations are to occur.
- Each explicit memory access to be valid for its width and address.
- Required hidden machine state to be supplied consistently with the actual entry convention.

There are no visible bounds checks, alignment checks, null checks, allocation checks, or dependency-status checks.

Signed-index arithmetic needs particular care. The representation uses signed-looking 32-bit results in multiplications and left shifts. Negative values, signed overflow, and address conversion cannot be assigned portable semantics from this material alone. The acceptance examples use small nonnegative indices unless another arithmetic assumption is stated.

### Arithmetic and layout constraints

All eight direct word stores write four bytes. Their values are either an uninterpreted 32-bit payload, a derived unsigned quantity, or a scaled index. Endianness is not established.

The selector-fragment store is unusual: its destination advances by one byte per increment of the fragment, despite writing four bytes. It is not a four-byte-strided table. Its possible start addresses are `0x24` through `0x423`; its last possible written byte is at `0x426`.

Every byte-store destination lies between `0x11` and `0x110`, inclusive, because the loaded selector is an unsigned byte. These are literal derived addresses in the representation, not offsets from an established object pointer.

The first three byte loads use the same retained lookup-base expression but are separate reads. The fourth uses a different expression based on the second byte-source word. None may be replaced by an assumed cached byte.

The byte data calculations discard information:

- Multiplication by four followed by an 8-bit store retains original bits 0–5, shifted into destination bits 2–7.
- The upper-byte projection retains original bits 20–27.
- The full shifted word passed to F-a46 is not limited to the byte stored immediately before it.

The lookup-base multiplication is unsigned 32-bit arithmetic in the representation and can wrap. It is not equivalent to unbounded multiplication. For example, a primary scale of 8192 yields a lookup base of zero under those semantics.

## Side effects

The directly visible memory effects, in program order, are eight 32-bit writes followed by four byte writes, with calls interleaved as specified above. The four explicit memory reads occur immediately before their corresponding byte writes.

This ordering is significant:

- The payload store using the first index precedes the selector-fragment store.
- Each later word store occurs before the following dependency call.
- Each byte selector is read before its destination is written.
- F-a58 receives the byte read before the third byte store, even if that store changes the byte’s backing memory.
- The final byte selector is obtained from the second byte-source word’s address expression, not from the retained lookup base.

Aliasing is unrestricted by the evidence. Word stores may overlap each other, byte destinations may coincide, and a write may affect a subsequent selector read. Intervening dependencies may also modify those locations. Therefore, neither repeated destination equality nor stable selector contents may be assumed.

There is no directly visible allocation, deallocation, reference counting, resource acquisition, or resource release. This absence does not constrain dependencies. No ownership transfer is established for the explicit input, payload word, returned words, or addressed memory.

There is no visible rollback. If an access or dependency fails after earlier writes have completed, the representation contains no compensating operation.

Atomicity, memory barriers, concurrency guarantees, and memory-mapped I/O semantics are **documented_only**.

## Acceptance examples

These are conditional contract examples, not executed tests. Each assumes valid targets, returning dependencies, accessible memory, and defined arithmetic for the values used.

### Selector store is byte-strided

If the selector word is `0x00C00000`, its selector fragment is 3. The second direct word store writes the 32-bit value 3 beginning at address `0x27`.

A store at `0x30` would incorrectly treat the fragment as a four-byte element index.

### Reuse of the retained scaled index

If F-a23 returns 3 and F-a28 returns 5:

- The earlier store writes 12 at address `0x44`.
- F-a24 receives 12.
- The later store writes the same value 12 at address `0x28`.
- F-a29 receives 20.

The later store’s value must not be replaced by four times F-a28’s result.

### Repeated selector reads can select different destinations

Suppose the first byte-source word is `0x12345678`. Suppose the first selector read returns `0x20`, and the second returns `0x21`.

The first byte store writes `0xE0` at address `0x31`. The second writes `0x23` at address `0x32`. F-a46 receives `0x48D159E0`.

These destinations differ legitimately. Reusing the first selector byte for the second store would violate the represented read sequence.

### Third byte call receives the selector, not the stored data

Suppose the second byte-source word is 5 and the third selector read returns 7.

The third byte store writes decimal 20 at address `0x18`. F-a58 then receives decimal 7, zero-extended to 32 bits—not 20 and not the destination address.

### Final lookup uses a different base

With the second byte-source word equal to 5, the final byte selector is read at address `0x29`. If that read returns 9, the final byte write targets `0x1A` and writes zero, because bits 20–27 of 5 are zero.

This remains the required represented lookup even if the retained lookup base has a different value.

### No established recovery after a fault

If the selector-fragment store faults, the preceding payload store and completed dependency calls are earlier effects. No later call, cleanup, rollback, or successful return is established by this representation.
