## Behavior

1. The low six bits of the unsigned scaled selector index, shifted left by 14.
2. The scaled fourth wide-stride index.
3. The unscaled selector index shifted left by 30.

F-U42, F-U43, and F-U44 follow with unspecified arguments. F-U45 supplies the fourth transfer index.

### 6. First byte placement and opaque forwarding

The routine reads one unsigned byte from the selector address. It zero-extends the byte and adds `0x11` to determine the first byte destination.

At that destination, it stores the low eight bits of the packed word shifted left by two. Packed-word bits 0 through 5 become stored-byte bits 2 through 7; stored-byte bits 0 and 1 are zero.

F-U51 receives:

1. The packed word shifted left by two, converted to a signed 32-bit temporary.
2. The same converted value again.
3. The packed word shifted left by four.

These shifts originate from an unsigned 32-bit value. Shifted-out high bits are discarded. Interpretation of a high-bit-set result after conversion to the signed temporary is not independently established.

F-U51 uses target displacement `0xFEC`.

F-U52 supplies an opaque 32-bit value. F-U53 receives that value unchanged. F-U54, F-U55, and F-U56 follow with unspecified arguments. F-U57 supplies the late index.

### 7. Second byte placement and terminal boundary

The routine reads the selector address again as an unsigned byte and retains this second result.

It writes one byte at `0x11 + second selector byte`. The stored value is the low eight bits after masking the packed word with `0x3FFFFFFF` and logically shifting right by 20. The resulting byte contains packed-word bits 20 through 27.

F-U58 receives the late index shifted left by two. F-U59, F-U60, and F-U61 follow with unspecified arguments. F-U62 supplies the final index.

F-U63 receives:

1. The final index shifted left by two.
2. The zero-extended second selector byte.

F-U64 follows with unspecified arguments. The supplied representation then reaches a reported invalid-instruction boundary.

F-U63 uses the byte captured before F-U58, not a fresh read immediately before F-U63.

Under non-overflowing integer arithmetic or 32-bit modular address arithmetic, neither byte destination can have the same calculated address as the selector source. Selector addresses are congruent to 1 modulo `0x10000000`; byte destinations range from `0x11` through `0x110`.

This is address inequality only. It does not establish distinct backing storage, exclude mapped aliases, or exclude device-mediated effects. In particular, the first byte store may affect the subsequent selector read through unknown mapping or access semantics, despite unequal calculated addresses.

### Different strides and retained data

If F-U30 returns 2, the wide-stride store writes 8 at `0x34`. The following word read uses `0x1C`.

If that read returns `0xFEDCBA98`, the later shifted-word store writes `0x000FEDCB`, even if intervening calls change the source memory.

Assuming ordinary readable/writable memory with no external interference or access side effects, the read obtains the stored zero. Without those additional assumptions, the returned read value remains unspecified by this evidence.

### Masking the scaled selector

With selector index 5 and fourth wide-stride index 3, F-U41’s first two arguments are `0x50000` and 12.

Under 32-bit bit-vector left-shift semantics, its third argument is `0x40000000`. That value is conditional: the signed left shift is not established as portable arithmetic for this input.

Masking the unscaled selector index instead would produce the wrong first argument.

### Independent selector observations

Suppose the packed word is `0x12345678` and the first selector read returns `0x20`. The first byte store writes `0xE0` at `0x31`.

If the second selector read returns `0x40`, the second byte store writes `0x23` at `0x51`. F-U63 later receives `0x40` as its second explicit argument.

The reason for the changed read value is not determined. Possible environmental explanations include callee effects, external activity, mapped-storage aliasing, or device behavior. The representation does not select one explanation.

### Unequal addresses without a storage-independence guarantee

Under 32-bit modular address arithmetic, selector index zero calculates selector address `0x00000001`. If the first selector read returns `0x20`, the first byte destination is `0x31`.

Those addresses are unequal. Nevertheless, a mapping in which a write at `0x31` affects a subsequent read at `0x00000001` is not excluded by the supplied evidence. A contract requiring the second selector value to remain unchanged solely because the addresses differ would be unsupported.

More generally, the residue argument excludes calculated-address equality for all selector indices under the stated arithmetic models. It does not exclude shared backing storage or cross-address side effects.
