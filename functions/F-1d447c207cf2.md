### Widths and notation

A **byte** is 8 bits; a **word** is 32 bits. Doubled-width results contain 64 bits, divided into low and high 32-bit halves. Passing those halves as arguments does not establish memory byte order.

Arithmetic descriptions use a 32-bit bit-vector interpretation: multiplication and left shifts retain the low 32 bits. This makes truncation explicit without asserting that every displayed signed operation has defined high-level-language semantics. Address calculations using this interpretation remain conditional on the actual execution model.

The following terms describe access patterns, not additional functions:

- A **selector read at base B** reads an unsigned byte at B + 1.
- A **selected-byte write** writes at address 17 plus the selector’s numeric value.
- **Middle extraction** clears a word’s top two bits, shifts right by 20, and retains the low byte. The resulting byte contains original bits 20–27.

Selected-byte addresses therefore range from 17 through 272. The selector-derived word store described below targets addresses 20 through 275. These are numeric addresses, not offsets added back to the selector’s base.

## Side effects

The direct side effects are the ordered accesses and state replacements above. Every dependency may have additional unknown effects.

Selector reads are separate observable operations. A dependency may change selector storage between reads. In contrast, the selector retained across phases 1–2 is not reloaded before the argument-derived word store.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Initial truncation.** With seed 65 and first selector 7, the first byte write stores 4 at address 24.

2. **Selector reread.** If an intervening dependency changes the entry-base selector from 7 to 9 before phase 1’s second selector read, that later selected-byte write targets address 26.

3. **Retained selector.** If the second selector is 9, later changes to its source byte during phase 2 do not change the argument-derived word destination: it remains address 29.

4. **Extraction width.** A word with bits 20–27 equal to 165 yields middle-extraction byte 165 regardless of its top two bits. This does not imply that the final word-read address calculation uses only eight bits.

5. **32-bit wraparound.** Under the bit-vector interpretation, a third argument of 1073741824 produces zero when multiplied by four for the initial argument store.

6. **Repeated direct clearing.** Even if all four byte writes encounter zero, their order remains base + 17, base + 1, intervening calls, base + 17, base + 1.

7. **Late read aliasing.** If phase 11’s store and following read use the same valid word address, ordinary memory semantics yield the parity-derived word just stored.

8. **Control-state placement.** If a dependency can observe this state through an unknown hidden interface, `F-D26-04` occurs after its replacement. `F-D26-03` occurs before it. A replacement deferred until after `F-D26-04` would violate the visible ordering.

9. **Continued execution.** If every dependency returns and every access succeeds, the function begins another iteration rather than returning a status.
