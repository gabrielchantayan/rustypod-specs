# F-4a2518f19567

## Purpose

F-4a2518f19567 makes two ordered dependency calls, reads one byte through its first argument, and selects between two paths:

- An observed byte equal to decimal **200** produces the 32-bit return value **200**, without the third dependency call or the function’s own word update.
- Any other observed byte leads to a third dependency call and a masked 32-bit memory update, followed by the 32-bit return value **0** if execution completes normally.

The update’s address selector depends on the observed byte’s upper three bits. Its bit selector depends on the fourth argument’s low eight bits.

These are established operations, not established application semantics. Interpreting the first two calls as initialization or preparation, or the update as removing membership from a collection, is **inferred intent only**.

The update expression uses a shared-base global separately for its read address and its write address. It does not establish a cached base or an order between those address evaluations. Consequently, clearing a bit **in the same word** is guaranteed only under suitable base-stability and arithmetic conditions.

The subsequent signed conversion is target-dependent. If that conversion maps 0xFFFFFFFF to −1, the selector is −1 and its multiplication by four produces a displacement of **−4 bytes**. The supplied evidence does not independently establish that conversion rule.

- Extending that range to **−4 through +24 bytes** requires the stated signed-conversion behavior.

### Shift count and mask

The fourth argument is reduced to its low eight bits. The resulting shift-count operand ranges from **0 through 255**.

The mask expression shifts the integer value one left by that count, complements the result, and combines it with the unsigned 32-bit word using bitwise AND.

For counts **0 through 30**, the ordinary 32-bit bit-clear interpretation is established:

- The selected numeric bit is cleared.
- All other bits in the value actually read are retained in the value to be written.
- A selected bit already equal to zero yields an unchanged numeric value.

For count **31**, clearing the highest bit is a plausible target-level interpretation, but the signed left-shift expression does not establish that result independently of the target’s rules.

For counts **32 through 255**, the supplied expression establishes no portable result. It contains no explicit modulo-32 reduction or range check. Wrapping the count, producing a zero mask, trapping, and completing with a particular word value are not established guarantees.

The low-eight-bit reduction remains established regardless of those uncertainties. For example, fourth-argument values 1 and 257 both supply shift count 1.

### Separate read and write address evaluations

After the third dependency returns, the update expression contains two uses of the shared-base global:

- One determines the address from which the unsigned 32-bit word is read.
- Another determines the address to which the masked value is written.

Each address incorporates the calculated selector multiplied by four.

The expression does **not** establish which shared-base evaluation occurs first. The write address may be determined before or after the read-side address evaluation or word read. The value read must contribute to the value eventually stored, but this data dependency does not establish an order between the two base evaluations.

The two source-level uses also do not, by themselves, prove an exact number of machine-level global loads.

If both base evaluations yield the same address value and address arithmetic behaves consistently, the read and write target the same word. Otherwise, the function may read one word, mask that value, and write the result to a different word. In that case, the write is not necessarily a bit clear relative to the destination’s previous contents.

After the write completes, the function returns **0**.

### Memory effects and concurrency

The body performs a 32-bit read and a 32-bit write on the update path, even when the masked numeric value equals the value read.

No atomic read-modify-write primitive, lock, retry, or validation is visible. Dependencies might provide synchronization, but their behavior is unknown. The visible body alone provides no concurrency guarantee.

Any promised in-place bit-clear behavior therefore requires appropriate base and memory stability, or an equivalent externally established synchronization condition.

The layout exposed by the address calculation consists of word positions separated by four bytes. Numeric bit positions do not establish the physical byte order.
