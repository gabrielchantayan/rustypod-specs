# F-c51683ef4529

## Purpose

F-c51683ef4529 expands an alternating run-length byte stream into packed output bits. A state record supplies the requested total bit count, row width, destination row base, and row stride.

The established transformation has these properties:

- Every consumed input byte toggles the current output-bit value.
- A nonzero input byte specifies the length of the newly selected run.
- A zero input byte changes polarity without producing bits; input scanning continues.
- Output bits are packed most-significant-bit first.
- Each completed row ends its current output byte, with unused low-order positions zeroed.
- Input exhaustion does not terminate output generation. The current polarity continues until the requested total bit count is satisfied.
- Each completed row updates the destination row-base field, including a row completed by the final requested bit.

The apparent intent is expansion of a run-length bitmap into strided rows. That interpretation is inferred. No external image format or caller protocol is established.

## Interface

The function takes three arguments and returns no value:

1. **State address:** an address identifying a mutable, integer-word-based record.
2. **Input cursor:** the address of the first candidate encoded byte.
3. **Input limit:** an exclusive upper-bound address for encoded-byte consumption.

The input cursor is passed by value. Its final position is neither returned nor explicitly stored in the state.

## Behavior

### Initialization and early return

The initial state reads occur in this order:

1. Requested total bit count from word 4.
2. Configured row width from word 2.
3. Destination row-base address from word 0.

The total count and current row width are then maintained locally. The initial output address is the initial row base.

The initial generation state is:

- Current output-bit value: one.
- A new run is required.
- Run counter: zero.
- Accumulator: zero.
- Next bit position: bit 7, the most-significant position of an output byte.

Before generating each bit, the function tests whether the remaining total count is less than one.

For an initially zero or negative total count, it returns after the initialization reads. It consumes no input, writes no output, and does not update the stored row base. The state record must therefore still support those initialization reads even for an empty request.

The requested count in state word 4 is never explicitly decremented or replaced.

### Acquiring runs

When a new run is required, the function scans input toward the exclusive limit.

Before every candidate-byte dereference, it checks whether the candidate address is at or beyond the limit. If a byte is available:

- That byte is read and the input cursor advances by one.
- Its unsigned value replaces the run counter.
- The current output-bit value toggles.
- A zero value causes another scan attempt.
- A nonzero value ends scanning and supplies the length of the selected run.

Consequently, without leading zero bytes, the first nonzero run produces zero-valued output bits: the initial polarity is one, and consuming that run-length byte toggles it to zero.

Every leading, intermediate, or trailing zero byte still toggles polarity. Zero bytes do not directly consume any requested output bits.

A run can cross both output-byte and row boundaries. Neither boundary resets polarity, discards a remaining run, nor independently consumes input.

### Input exhaustion

If the input cursor is at or beyond the limit when scanning is attempted:

- No candidate byte is read.
- The cursor does not advance during that attempt.
- The polarity does not change.
- No replacement run count is obtained.
- Output generation proceeds.

Thus, an initially empty input range produces one-valued bits throughout a positive request.

After a nonzero run finishes, exhaustion preserves the last selected polarity. If zero bytes are consumed before the limit is reached, their toggles remain effective.

After every generated bit, the unsigned run counter is decremented. A new scan is requested when the decremented value, interpreted as signed, is less than one. This is not simply an unsigned zero test.

In particular, decrementing a zero unsigned counter produces the maximum unsigned value. Under the apparent 32-bit signed interpretation, that result is negative, so another scan is requested on the next output iteration. Input exhaustion does not cause a short result, error return, or diagnostic.

### Packing each generated bit

For each requested bit:

- A one-valued polarity includes the current bit-position mask in the accumulator.
- A zero-valued polarity leaves the accumulator unchanged.
- The remaining row width decreases by one.
- The bit-position mask shifts toward the least-significant position.

The packing order within a byte is bit 7 through bit 0.

Output memory is not read for merging. Every emission replaces an entire byte. Because each accumulator starts at zero, unused low-order positions in a partial byte are zero.

Storage handling has this precedence:

1. Complete the row if the decremented remaining row width is less than one.
2. Otherwise, emit a full byte if all eight positions have been used.
3. Otherwise, retain the partial accumulator.

When a row boundary coincides with an eight-bit boundary, only the row-completion path emits the byte. There is no duplicate write.

After storage handling, the function decrements the run counter and total remaining count, updates whether another input scan is needed, and proceeds to the next total-count check.

### Completed rows

On row completion, the function first writes the accumulator to the current local output address. This occurs whether the byte contains one bit, eight bits, or an intermediate number of bits.

The subsequent row-transition accesses occur in this order:

1. Read the stored row base from state word 0.
2. Reload the configured row width from state word 2.
3. Reset the accumulator and restore the bit-7 mask.
4. Read the stride from state word 1.
5. Add that stride to the previously read row base and write the result into state word 0.
6. Read the stride again and select the next local output address by adding it to the same previously read row base.

The second address calculation is not expressed as a readback of the updated state word 0.

With stable, non-overlapping state, the stored row base and next local output address both become the previous stored row base plus the stride. The next row does not start relative to the last byte emitted within the completed row.

These operations occur even if the row ended on the final requested bit. In that case, the function still reloads the width, reads the stride, and advances the stored row base before returning.

Zero stride is not rejected. It causes successive rows to start at the same address under stable state. Negative stride is also not rejected, provided the arithmetic and resulting accesses are valid.

### Full bytes within an unfinished row

When eight bits have accumulated but the row has not completed:

- The accumulator is written at the current local output address.
- The local address advances by one byte.
- The accumulator resets to zero.
- The next bit position resets to bit 7.

This local advancement does not update state word 0.

### Return with a partial byte

At the next total-count check after the final bit, a byte is emitted only if the bit-position mask indicates an unfinished byte.

This condition does not depend on whether the accumulator is nonzero. A partial byte containing only zero-valued output bits is still written.

If the preceding bit completed a byte or row, the mask has already reset and no additional byte is written.

Ending partway through a row does not advance the stored row base, even if full bytes were emitted earlier within that row.

## Side effects

### Output writes

For a stable positive row width of \(w\) bits, each complete row causes \(\lceil w/8 \rceil\) byte writes. A final incomplete row emits its full bytes plus one partial byte when needed.

Row stride is independent of the number of bytes emitted per row. Rows can overlap, leave gaps, or proceed toward lower addresses. The function does not validate any of those arrangements.

### State changes and aliasing

The only explicit state-record assignment is to word 0 after a completed row.

There are no explicit assignments to the stride, configured width, unused word, or requested total count. Output overlapping the record can nevertheless modify any overlapping bytes.

The row-ending output write occurs before the row base, configured width, and stride are read for that transition. An overlapping output byte can therefore affect the immediately following transition, not merely a later row.

The active row’s output address and remaining width are local. Changes to the stored row base or configured width do not independently redirect or resize that active row before its transition logic is reached.

The total count is captured once. Later changes to state word 4 do not change the locally tracked remaining total.

Input is consumed on demand. Output overlapping unread input can change subsequent run lengths and polarity toggles.

- State word 0 remains \(D\).

- The first two bits are zero.
- The trailing zero toggles polarity to one before exhaustion.
