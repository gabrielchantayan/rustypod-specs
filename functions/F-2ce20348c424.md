# F-2ce20348c424

## Purpose

F-2ce20348c424 coordinates object-related dependency calls, context updates, and optional successor processing. Its inputs identify a context, an eight-byte-stride table, a caller-owned slot containing an object address, a mode, and an unsigned index.

The retained object’s fields determine whether two ordered phases run. The mode and a context-selected index further determine whether successor processing is recursive, specialized, or suppressed.

Established behavior consists of explicit memory accesses, arithmetic, dependency arguments, branch conditions, direct writes, and status propagation. Object removal, link maintenance, decoding, and resource cleanup are possible interpretations, not established dependency semantics.

The operation is not visibly transactional. Writes and dependency effects can precede a checked failure; no explicit rollback is present.

### Arithmetic

The initial table-entry address is the table base plus eight times the unsigned input index, calculated modulo \(2^{32}\).

The successor index is the unsigned 32-bit sum of the input index and one, followed by masking with `0xfffeffff`. This clears bit 16 only; it is not a general 16-bit increment. Successor table addressing, including the additional offset four, also uses unsigned 32-bit arithmetic.

The specialized displacement-field address is the object address plus the unsigned 16-bit context field at offset 28, minus two, modulo \(2^{32}\).

These wraparound rules do not establish address validity. The final signed displacement addition and other signed address-bearing additions do not have an equally established unsigned-wrap guarantee.

An offset-10 value of zero selects both object-related phases and provisionally enables recursive successor processing.

The first phase calls F-4055be9c3f18 with the retained object’s offset-4 address.

If that call returns zero, the object byte at offset 8 is read. An all-ones byte causes another F-4055be9c3f18 call, with the object’s offset-0 address. That additional call’s four-byte result is written to context offset 20. Otherwise, neither the additional call nor the context write occurs.

If the first call returns nonzero:

1. F-5f9a16493218 receives the context, that returned value, and the temporary-slot address.
2. A nonzero status immediately enters the common error path.
3. On zero status, F-4055be9c3f18 receives the retained object’s offset-0 address.
4. F-946cac4b59bc receives that returned value and the current four-byte value in the temporary slot. Its result is ignored.
5. F-f7c5b7585b2d receives the context, temporary-slot address, zero, and `0x100`. Its nonzero status enters the error path.

If the result is zero, the object byte at offset 8 is read again. An all-ones byte causes F-4055be9c3f18 to receive the offset-4 address, followed by a four-byte write of its result to context offset 24.

If the result is nonzero:

### Context-selected override

After the preceding processing succeeds, the unsigned 16-bit context field at offset 2 is compared with the full unsigned 32-bit input index. The index is not truncated; an index greater than 65,535 cannot match.

A mismatch preserves the provisional successor choice.

A match suppresses both successor paths and rereads the original caller’s slot:

- A null refreshed address causes a four-byte clear at context offset 12, followed by a two-byte clear at offset 2.
- A nonnull refreshed address causes a signed 16-bit read at its offset 10.
- If that value equals one, F-8e07a3b1e408 receives the context and original slot address. Its nonzero status enters the error path.
- Any other nonnull field value causes no such call.

Earlier dependency effects can therefore influence the selected-index comparison and refreshed-slot processing.

### Successor acquisition

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes valid reached memory and the dependency behavior stated in the example.

1. **Consumed nonzero value is not failure.** If the first F-4055be9c3f18 call returns seven, seven is supplied to F-5f9a16493218. Seven is not directly returned as an error. A nonzero status from F-5f9a16493218 instead triggers failure.

2. **Unchecked context value.** If a phase’s initial F-4055be9c3f18 result is zero and the inspected byte is all ones, the additional call’s result is written to the corresponding context field even if that result is nonzero.

3. **Initial slot replacement.** If the initial F-76b5978a0554 call replaces the caller’s slot, the immediate offset-10 read still uses the previously retained object. A later matching-index override uses the refreshed slot.

4. **Matching index and null slot.** After preceding success, a matching index and null refreshed slot cause the offset-12 four-byte clear before the offset-2 two-byte clear. Neither successor path runs. Final caller-slot processing still occurs.

5. **Matching index and field one.** A nonnull refreshed object with offset-10 value one causes F-8e07a3b1e408 to run. Its nonzero status causes both error calls and is returned unchanged.

6. **No successor selected.** With a nonzero initial object field, nonzero mode, and mismatching selected index, no successor entry is accessed. Final F-f7c5b7585b2d determines success or checked failure.

7. **Early failure.** A nonzero first-phase F-5f9a16493218 status skips later normal processing. Both error calls occur, including the call receiving the five-word region before visible initialization.

8. **Successor boundaries.** Index 65,535 produces successor zero. Index 131,071 produces successor 131,072. Index `0xffffffff` produces successor zero through unsigned wraparound.

9. **Wrapped table address.** Table base `0xfffffffc` and successor index one produce entry address `0x00000004` and offset-4 field address `0x00000008`. Address validity remains a separate precondition.

10. **Signed displacement.** With stable object base `0x1000` and context offset-28 value `0x20`, the displacement field is at `0x101e`. A displacement of −4 produces final address `0x0ffc`. Base `0xfffffff0` instead places the displacement field at `0x0000000e` through unsigned wraparound.
