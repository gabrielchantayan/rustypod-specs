# F-36a285714182

## Purpose

F-36a285714182 performs a bounded, first-match search over four one-byte candidates. It returns the index of the first candidate equal to an unsigned 32-bit search value, or −1 if all four candidates differ.

Candidate selection uses an implicit global base expression and a displacement of 24 bytes per index. The base expression is evaluated separately for each reached candidate. The function therefore does not establish that all four candidates belong to one unchanged table.

When the base remains constant, the candidate bytes are at offsets 0, 24, 48, and 72 from that base. Only those bytes participate directly in equality comparisons. The meaning of surrounding storage is not established.

This contract describes source-level behavior. It does not prescribe a generated instruction sequence or claim runtime verification.

## Behavior

### Ordered evaluation and access

The search starts with candidate 0 and advances in increasing index order, stopping at the first match.

For each reached candidate, the source-level ordering is:

1. Evaluate the implicit global base expression for that candidate.
2. Use that value with the candidate’s displacement to determine the candidate address.
3. Read one unsigned byte at that address.
4. Compare the byte’s numeric value with the full unsigned 32-bit search value.
5. Return the current index if equal; otherwise advance toward the next candidate.

After a mismatch at candidate 3, the function returns −1. There is no fifth candidate and no sentinel-based continuation.

The base expression is inside the repeated lookup operation. It is not established as a value captured once at entry. An earlier evaluation does not replace a later reached evaluation in this source-level contract.

This distinction does not establish a particular machine-level load count. The evidence does not specify whether the global storage is volatile, what optimizations apply, or which instructions are generated.

### Access extent and early termination

The number of reached candidate-byte reads is determined by the first match:

| Outcome | Reached candidate-byte reads |
|---|---|
| Match at index 0 | Candidate 0 only |
| First match at index 1 | Candidates 0, 1 |
| First match at index 2 | Candidates 0, 1, 2 |
| First match at index 3 | Candidates 0, 1, 2, 3 |
| No match | Candidates 0, 1, 2, 3 |

Each reached candidate also has its corresponding source-level base-expression evaluation before the candidate-byte read. After a match, no later iteration is reached, so no later base evaluation or candidate read is required by the body.

These statements concern expressed program behavior, not speculative hardware access or cache effects.

### Changing implicit state

The lookup does not explicitly save a base snapshot. If the surrounding execution model permits the implicit base to change between reached evaluations, later candidates use the values obtained by their own evaluations.

Consequently, the general contract is an ordered search over encountered bytes, not necessarily over four positions relative to one common base.

This observation does not establish that unsynchronized concurrent modification is valid. Whether changes can occur legally, and whether an evaluation observes them, depends on execution-environment rules absent from the evidence. No concurrency guarantee is added here.

The function also does not copy all candidate bytes before comparing them. A later candidate’s value is the value obtained when that candidate is reached, subject to the same unresolved execution rules.

### Equality and arithmetic widths

Each candidate is an unsigned byte with a numeric value from 0 through 255. That value is compared with the unsigned 32-bit search value without truncating the search value.

Therefore:

- A byte value of 255 can match a search value of 255.
- It cannot match 4,294,967,295.
- A byte value of 0 cannot match 256.
- Any search value greater than 255 necessarily differs from every successfully read candidate.

The body does not reject search values greater than 255 before accessing candidates. Such a search still reaches all four iterations, including their base evaluations and candidate reads, unless execution fails before normal completion.

The index begins at 0, advances by one after each mismatch, and terminates after the fourth mismatch. Its bounded progression does not require signed 32-bit overflow. The largest candidate displacement is 3 × 24 = 72 bytes; that displacement calculation likewise requires no overflow.

The evidence does not establish address width, address wrapping, or the exact representation used in base-plus-displacement address formation. Valid address formation remains a precondition.

Because each candidate comparison consumes a single byte, multibyte byte order does not affect the candidate’s numeric value. This does not establish anything about the representation of the implicit base.

### Duplicate values

The earliest matching encountered candidate wins. Once it matches, later candidates are not reached.

With an unchanged base and unchanged candidate bytes, this is lowest-index precedence among the four fixed locations. Without those stability conditions, precedence still follows iteration order, but there is no established single snapshot against which all four values can be compared.

### Preconditions and failure behavior

Normal completion requires each reached base-expression evaluation and candidate-byte access to be valid under the execution environment.

A full traversal requires four valid candidate reads, each addressed using its own base evaluation. An early match does not require later candidate accesses.

There is no visible null check, allocation check, bounds check, or memory-access recovery. If a reached evaluation or access is invalid, the supplied evidence does not establish a normal return value, exception type, or recoverable error protocol.

In particular, −1 is a completed no-match result. It is not an established result for invalid storage.
