# F-336d0b6379eb

## Purpose

F-336d0b6379eb coordinates a bounded conversion through F-fce65b18a380, optionally requiring an opening delimiter and checking a closing delimiter. It stores the conversion dependency’s 32-bit result in caller-provided storage and, on successful completion of its own checks, publishes the resulting position to a state record.

The established behavior is narrower than a general promise to parse a delimited value:

- Conversion semantics belong to F-fce65b18a380 and are not available here.
- An empty or reversed range returns success without invoking the conversion dependency.
- In delimiter mode, a missing opening delimiter is an error.
- A closing-delimiter error is reported only when the conversion position is strictly below the currently observed limit and the byte at that position is not the closing delimiter.
- A conversion position at or beyond that limit is accepted by this wrapper and advanced by one position, subject to pointer-validity constraints.

The apparent intent is to convert a byte-oriented representation, optionally enclosed by `<` and `>`. That intent does not establish validation rules, output allocation, or conversion-error behavior beyond the observations below.

## Interface

### Inputs

The function takes five arguments:

| Argument | Established role |
|---|---|
| State record | Address of a writable record containing at least three consecutive 32-bit words. The first word supplies a position; the third word supplies a limit. |
| Conversion argument A | Opaque 32-bit value forwarded unchanged to F-fce65b18a380. |
| Conversion argument B | Opaque 32-bit value forwarded unchanged to F-fce65b18a380. |
| Result destination | Address at which the conversion dependency’s 32-bit return value is stored if conversion is reached. |
| Delimiter mode | A 32-bit integer tested for zero versus nonzero. Any nonzero value selects delimiter mode. |

The visible representation uses 32-bit words as pointer-bearing fields. The relevant state layout is:

| Byte offset | Width | Meaning used by this function |
|---|---:|---|
| 0 | 32 bits | Current-position address; read after preparation and explicitly overwritten on successful conversion completion. |
| 4 | 32 bits | No direct access by this function. |
| 8 | 32 bits | Limit address; read repeatedly at distinct stages. |

This establishes neither a portable layout on wider-pointer systems nor the full size or meaning of the state record. Dependencies may require additional fields.

Although the result destination is represented through a character-pointer type in the supplied material, its visible use is a **32-bit store**, not a single-byte store. Callers must provide storage suitable for that access whenever conversion can be reached.

### Output

The function returns a 32-bit value:

- **0:** no wrapper-detected delimiter error, including the early exit for an empty or reversed range.
- **3:** an opening- or closing-delimiter error, after invoking F-4457a9a44a68.

These outcomes assume the invoked dependencies return normally. The conversion dependency’s return value is stored separately at the result destination; it is not returned as the wrapper’s status and is not checked by this function.

### Preconditions and validity

For defined execution, the following accesses and operations must be valid on every reached path:

- Reading the state’s limit before preparation.
- Any state accesses and other operations required by F-1fe3b1afff2c.
- Reading the state’s first and third words after preparation.
- Reading an opening byte when delimiter mode is enabled and the initial range check passes.
- Storing four bytes at the result destination when conversion is reached.
- Reading a possible closing byte when the closing check’s range comparison permits it.
- Advancing the conversion position by one in delimiter mode.
- Writing the final position to the state’s first word on successful conversion completion.

The contract does not add null checks, alignment repair, address-overflow handling, or object-boundary validation. Valid address comparisons and pointer arithmetic are caller/dependency obligations in the represented execution model.

No non-aliasing guarantee is established. If the result destination overlaps the state or input, the ordering below determines which later observations can be affected.

## Behavior

### 1. Preparation occurs before any range exit

The function reads the state’s third word and invokes F-1fe3b1afff2c with:

1. The state-record address.
2. The third-word value observed for that call.

This call happens unconditionally. An input that later causes an immediate return does not bypass preparation.

After the call returns, the function reads the state’s first word as its working position. It then reads the state’s third word for the initial range comparison.

The post-preparation fields control subsequent behavior. The function does not use a pre-call copy of the current position, and it does not assume that preparation preserved the limit.

### 2. Empty and reversed ranges return zero

If the observed limit is less than or equal to the working position, the function returns 0 immediately.

On this path, the wrapper does not:

- Inspect an opening delimiter.
- Invoke F-fce65b18a380.
- Store a conversion result.
- Explicitly publish a new position.
- Report a delimiter error.

Preparation may nevertheless have produced side effects. Consequently, “no result store by this wrapper” is more precise than “the destination remains unchanged.”

This early return applies in both delimiter modes.

### 3. Delimiter mode requires an opening byte

If the initial position is below the limit:

- With delimiter mode zero, conversion starts at that position.
- With delimiter mode nonzero, the function reads the byte at that position.

In delimiter mode, the byte must be `<`. If it is not:

1. The function invokes F-4457a9a44a68 with an opening-delimiter diagnostic.
2. If that dependency returns normally, the function returns 3.

No conversion call or direct result-destination store occurs on this error path. The wrapper does not explicitly update the state’s first word.

If the byte is `<`, the working position advances by one byte before conversion. There is no second range check between consuming the opening delimiter and invoking the conversion dependency. An opening delimiter in the last available byte therefore causes conversion to begin exactly at the previously observed limit, assuming no intervening relevant mutation.

### 4. Conversion receives a mutable working position

The function invokes F-fce65b18a380 with:

1. The address of its local working-position storage.
2. A newly read value of the state’s third word.
3. Conversion argument A.
4. Conversion argument B.

The dependency can update the working position through the first argument. Its returned value is treated as an opaque 32-bit result.

The wrapper does not establish that the dependency:

- Advances the position.
- Leaves the position within the supplied range.
- Stops at a delimiter.
- Reports failure through any particular result value.
- Preserves state fields or global state.

Immediately after the dependency returns, the wrapper stores its 32-bit result at the result destination.

That store occurs **before** closing-delimiter validation and before the final explicit position publication.

### 5. Delimiter mode checks the conversion position

With delimiter mode zero, the function performs no closing-delimiter check and no additional one-byte advancement.

With delimiter mode nonzero, it reads the state’s limit again and evaluates the conversion position:

- If the position is strictly below the observed limit, the byte at the position is read.
  - If that byte is `>`, processing continues.
  - Otherwise, the function invokes F-4457a9a44a68 with a closing-delimiter diagnostic and, if the dependency returns normally, returns 3.
- If the position is equal to or greater than the observed limit, no closing byte is read and no closing-delimiter error is reported by this check.

When no closing-delimiter error is reported, the working position advances by one byte. This advancement occurs even when the preceding comparison found the position at or beyond the limit.

The latter case is an established branch behavior, not a guarantee that the resulting address operation is valid. For example, advancing a position already at a one-past-the-object address may violate the execution model’s pointer-arithmetic rules.

### 6. Successful completion publishes the position

After conversion and any successful delimiter processing, the wrapper stores the final working position into the state’s first word and returns 0.

On a closing-delimiter error, the conversion result has already been stored, but this final position store is skipped.

Neither error path performs rollback. Any effects of preparation, conversion, diagnostic reporting, or aliasing remain outside a rollback guarantee.

## Side effects

The observable sequence, for a normally returning conversion path, is:

1. Read the state limit for preparation.
2. Invoke F-1fe3b1afff2c.
3. Read the post-preparation current position and limit.
4. Optionally inspect and consume an opening delimiter.
5. Read the state limit for conversion.
6. Invoke F-fce65b18a380 with mutable local position storage.
7. Store the dependency’s 32-bit result at the result destination.
8. In delimiter mode, read the state limit again and conditionally read a closing byte.
9. Either invoke the diagnostic dependency and return 3, or advance as required and publish the final position.
10. Return 0 on successful completion.

Important consequences include:

- **Output can be committed on error.** A closing-delimiter error occurs after the result store.
- **The limit is not a single immutable snapshot.** Preparation, conversion, or an overlapping result store can affect later limit reads.
- **An overlapping result store can affect validation.** If it changes the limit field or the prospective closing byte, the closing check observes the altered data.
- **The final position store can overwrite an overlapping result.** If the result destination overlaps the first state word, successful completion publishes the position after storing the result.
- **Failure does not guarantee an unchanged state.** Skipping the explicit final position store does not undo dependency effects or overlapping writes.

The function has no visible direct allocation or deallocation. The meaning of the stored 32-bit result, including whether it represents a pointer, count, status, or owned resource, is unknown. No ownership transfer or release obligation can be inferred.

The mutable position argument passed to conversion refers to storage local to this invocation. Its synchronous use is visible; no supported right to retain or later dereference that address is established.

## Acceptance examples

These are conditional behavioral examples derived from static evidence, not executed tests. Unless otherwise stated, dependencies return normally, addresses are valid, and there is no aliasing or unlisted mutation.

1. **Preparation produces an empty range.**  
   After preparation, position equals limit. The wrapper returns 0 in either mode, without conversion, delimiter inspection, or a direct result store.

2. **Preparation produces a reversed range.**  
   After preparation, position is greater than limit under the represented address comparison. The wrapper returns 0 rather than 3. It does not diagnose the ordering.

3. **Undelimited conversion.**  
   Mode is zero and the initial position is below the limit. Conversion receives that position. If it returns a result and updates the position, the wrapper stores the result, publishes that updated position without adding one, and returns 0.

4. **Missing opening delimiter.**  
   Mode is nonzero, position is below limit, and the first byte is not `<`. The opening diagnostic is invoked. The wrapper then returns 3, with no conversion call and no direct result store.

5. **Delimited success.**  
   The opening byte is `<`. Conversion receives the following position and returns a position below the later limit whose byte is `>`. The result is stored first; the final published position is one byte after `>`; status is 0.

6. **Wrong closing byte.**  
   Conversion returns a position below the later limit whose byte is not `>`. The result is still stored. The closing diagnostic is invoked and status is 3. The wrapper skips its final position publication.

7. **Conversion reaches the limit.**  
   In delimiter mode, conversion returns a position equal to the limit observed by the closing check. The wrapper does not read a closing byte or report a missing closing delimiter. It attempts the one-byte advancement and publication. Acceptance of the complete execution additionally requires that advancement to be valid.

8. **Conversion result resembles an error value.**  
   Whatever 32-bit value conversion returns, the wrapper stores it and continues its own checks. No particular returned bit pattern independently changes the wrapper’s status.

9. **Result destination overlaps the limit.**  
   If the result store replaces the third state word, delimiter validation uses that replacement as its limit. The contract does not substitute the limit previously passed to conversion.
