# F-15f21d04d62d

## Purpose

F-15f21d04d62d is a state-dependent dispatcher. It repeatedly selects dependency calls using a one-byte state field associated with a caller-supplied context. Each completed dispatch produces a new 32-bit unsigned control value.

Two conditions end normal processing:

- A control value greater than 3 causes an immediate return without another state-field access by this function.
- An unrecognized state byte, encountered while the control value is in the range 0–3, causes this function to write zero to the state field and return.

The recognized state bytes are 0, 1, 2, and 3. State 0 selects one dependency; each other recognized state selects an ordered pair of dependencies.

This behavior is established by the supplied static representation. The application-level meaning of the states and control values is unknown. In particular, the evidence does not establish that zero means initialization, that a control value above 3 means failure, or that clearing an unrecognized state constitutes error recovery.

## Behavior

### Control-value gate

The control value is interpreted as unsigned and compared with 3 before every state selection.

- Values 0, 1, 2, and 3 permit a state-byte read.
- Values 4 through 4,294,967,295 cause immediate return.

The initial input is subject to this gate. Every completed dispatch replaces the current control value with its result, and that replacement is subject to the same gate before another state-byte read.

The unsigned interpretation matters. For example, the 32-bit pattern `0xFFFFFFFF` is out of range; it is not treated as a negative value that might satisfy a signed comparison against 3.

The dispatcher performs no visible arithmetic on the control value: no increment, decrement, masking, clamping, or normalization occurs.

### State observation

After a successful control-value gate, the function reads exactly one byte at context displacement +8. The observed byte selects the dispatch for that iteration.

The selector is not reread between the two calls of a paired dispatch. A dependency may change the stored state byte, but such a change does not alter the already selected pair. The new stored byte becomes relevant only if the completed dispatch produces an in-range control value and execution reaches the next state read.

In particular, an intermediate result above 3 does **not** trigger the control-value exit. Only the completed dispatch result becomes the next control value. The second dependency in a selected pair is still called if the first dependency returns normally, regardless of the intermediate value.

The auxiliary value is forwarded unchanged at the dispatch level. It is not read as an address or otherwise interpreted by the visible body. It is neither passed to the second dependency in state 2 nor supplied to dependencies selected by the other states.

### Continuation

After a recognized-state dispatch completes:

1. Its result becomes the current unsigned 32-bit control value.
2. The function applies the control-value gate.
3. If the value remains in range, the function reads the state byte again and selects another dispatch.

There is no visible bound on the number of iterations. The function can continue indefinitely if dependency calls keep returning normally, completed dispatch results remain in range, and each subsequently observed state remains recognized.

There is no built-in progression from state 0 through state 3. The next state is whatever byte is observed at the next permitted state read.

### Unrecognized state

If the control value is in range and the observed state byte is not 0, 1, 2, or 3, the function:

- Calls none of the listed dependencies for that iteration.
- Writes a one-byte zero at context displacement +8.
- Returns immediately.

It does not continue into the state-0 dispatch after clearing the byte. Any later state-0 processing would require a later invocation or some other execution path outside this function.

The state load is represented as a character load. Whether character values are signed is immaterial to the recognized set: only byte patterns 0, 1, 2, and 3 match. Every other byte pattern takes the clearing exit.

## Side effects

### Direct memory effects

The visible body directly:

- Reads the state byte once per iteration that passes the control-value gate.
- Writes zero to that byte only on the unrecognized-state exit.

It does not directly update the state byte after a recognized dispatch, persist the control value, or modify the auxiliary value.

These statements describe direct effects only. They do not imply that state remains unchanged across a dependency call.

### Call ordering

For a recognized state, the visible ordering is:

- Successful control-value check.
- State-byte read.
- Selected dependency call or calls, in the specified order.
- Adoption of the completed dispatch result as the next control value.
- Next control-value check, if execution continues.

No dispatcher-level state read or control-value range check occurs between the two calls of a paired dispatch.

If the first dependency in a pair does not return normally, the visible body does not reach the second call. No cleanup or compensating action is shown for that situation.

## Acceptance examples

These are conditional behavioral criteria derived from static evidence, not records of executed tests.

### Initial control value above the boundary

Given an initial control value of 4, the function returns without reading or writing the state byte and without calling a listed dependency. The same applies to `0xFFFFFFFF`.

A value of 3 is different: it permits a state-byte read.

### State 0 followed by an out-of-range result

Given an initial control value of 2 and a readable state byte of 0:

- F-049f25d41fb1 receives the original context reference and the value 2.
- If it returns 4, the dispatcher returns without another state-byte read.
- The dispatcher itself does not clear the state byte.

Any state change made by that dependency is not undone by the visible body.

### A paired dispatch does not validate its intermediate

Given an in-range control value and state byte 1:

- F-46d4377e5241 runs first.
- If it returns the intermediate bit pattern `0xFFFFFFFF` normally, F-b295ade20722 still runs with that intermediate.
- If F-b295ade20722 returns 4, the dispatcher returns at the next control-value gate.

The intermediate is not mistaken for the next control value.

### A state change during a pair applies later

Given state byte 2, suppose F-8f42edb60a53 changes the stored state byte to 3 and returns normally.

F-0c7124188ad1 still runs next. If its result is in range, and the state byte remains 3 through the next state read, the next selected pair is F-5d792a3fad2d followed by F-51f2ec0e2f90.

### Unrecognized state is cleared without dispatch

Given an initial control value of 0 and a state byte of 255, the function writes zero to the state byte and returns. It calls no dependency and does not subsequently perform the state-0 dispatch during that invocation.

### Range exit takes precedence over clearing

Given an initial control value of 4 and a stored state byte of 255, the dispatcher does not inspect or clear the byte. The control-value gate ends processing first.

### Continued processing is possible

If every completed dispatch returns an in-range control value and every state read observes a recognized byte, no exit is required by the visible body. This includes repeated selection of the same state.
