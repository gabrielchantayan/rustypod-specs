# F-3e95f52e82a5

## Purpose

F-3e95f52e82a5 selects between a bulk reset and an incremental processing loop. It writes a caller-supplied 32-bit output word and returns a 64-bit value formed from two 32-bit components.

The structure is consistent with processing or removing a range from a container: preliminary comparisons can select bulk processing, while the alternative captures a position’s current word, advances that position, and processes the captured value. This is **inferred intent**, not an established container, iterator, or ownership contract.

The established behavior consists of the direct memory accesses, dependency calls, branch conditions, and result construction below. Preliminary comparison results are accepted when nonzero. The loop terminates only when its comparison returns exactly one.

An important distinction concerns the incremental return: both components come from mutable temporaries read when constructing the return. Once their addresses have been passed to a dependency, later calls may modify them through retained references. The final return therefore need not match either the last processing call’s immediate results or the last published output word.

### Mutable result storage

Two distinct 32-bit temporaries are relevant to incremental processing:

- **Context-result temporary:** initialized to the original context-address value.
- **Item-result temporary:** initialized to the original output-address value, then overwritten with the captured item after each advancement call.

F-4e79646b68df receives both temporary addresses. Their values can subsequently change through those escaped addresses, including during other dependency calls.

The function does not reinitialize the context-result temporary between iterations. That is not a guarantee that a value written by one processing call survives until the next: later comparison or advancement calls may change it through retained references.

### Outputs

The output word is first written with the context’s header reference, before any dependency call.

The 64-bit return is a concatenation, with the first listed component occupying the high 32 bits and the second occupying the low 32 bits:

| Completion path | High component | Low component |
|---|---|---|
| Bulk reset | Header reference sampled after the reset writes | Original output-address value |
| Incremental path, no iterations | Original context-address value | Original output-address value |
| Incremental path, at least one iteration | Context-result temporary as read for return construction | Item-result temporary as read for return construction |

On the incremental path, the terminating comparison occurs before return construction. Its permitted effects through previously retained temporary addresses are therefore included in the returned components.

## Behavior

### Entry publication

The function first reads the header reference at context offset +16 and writes that 32-bit value through the output address.

It then reads context offset +16 again and copies the word at the resulting header’s offset +8 into a separate 32-bit comparison temporary.

These are separate accesses. In particular, the initial output store precedes the second header lookup. Aliasing can therefore affect subsequent addressing.

The output-address and context-address values are also retained in the two result temporaries before dependency calls begin.

### Preliminary comparisons

The first call to F-27df7c446fb9 receives:

- the position address;
- the address of the copied header +8 word.

The second operand refers to a temporary, not the header field itself. A write through that operand does not, by that route alone, modify header offset +8.

If this call returns zero, the remaining preliminary checks are skipped and execution proceeds to the loop.

If it returns any nonzero value, the function rereads the header reference at context offset +16, places it in another temporary, and calls F-27df7c446fb9 with:

- the boundary operand;
- the address of that header-reference temporary.

This second temporary is distinct from both result temporaries.

A zero result from the second comparison selects the loop without reading context offset +20 for the bulk decision. A nonzero result causes the state word at context offset +20 to be read.

Bulk processing is selected only when all three conditions hold:

1. The first preliminary comparison returned nonzero.
2. The second preliminary comparison returned nonzero.
3. The subsequently read state word was nonzero.

Neither preliminary check requires a result exactly equal to one.

### Bulk processing and reset

The bulk path reads the header reference from context offset +16, reads the word at that header’s offset +4, and calls F-ce267b08801d with the original context address and that word.

The dependency’s result is not inspected. Its effects on memory, ownership, and the context’s header reference are unknown.

After the dependency returns, the function performs the following direct writes in order:

1. Store a header self-reference at header offset +8.
2. Store zero at header offset +4.
3. Store a header self-reference at header offset +12.
4. Store zero at context offset +20.

The header-dependent reset operations obtain their references from context offset +16 after the call; they do not all rely on a header value saved before it. The separate reset statements also reread the context’s header reference rather than establishing one immutable reset target.

Under stable, nonoverlapping storage, a replacement header installed by F-ce267b08801d is consequently the reset target. With overlapping storage or changes to the reference between accesses, a single-header postcondition is not established.

After the reset writes, the function reads context offset +16 into a 32-bit value, writes that value through the output address, and uses the same sampled value as the high return component. The low component is the original output-address value.

No loop comparison, advancement, or incremental-processing call follows this reset.

### Incremental comparison and capture

If the bulk path is not selected, the function calls F-27df7c446fb9 with the original position address and the boundary operand.

A result exactly equal to one terminates the loop. Every other 32-bit result, including zero, two, and negative values, enters an iteration.

For each entered iteration, the function:

1. Reads the first 32-bit word at the position address and captures its value.
2. Calls F-50ef9e9e7cc8 with the position address.
3. Overwrites the item-result temporary with the captured word.
4. Calls F-4e79646b68df with the context-result temporary’s address, the original context address, and the item-result temporary’s address.
5. Reads the context-result temporary and writes that value through the original output address.
6. Calls the loop comparison again.

The captured item is the word read before advancement. Changes made by the advancement call to the position’s contents do not cause that iteration’s item to be recaptured.

The overwrite in step 3 is also significant after addresses have escaped: if the advancement call changes the item-result temporary through a retained reference, that change is replaced by the captured word before processing. No corresponding direct overwrite of the context-result temporary occurs at that point.

### Escaped temporary effects

F-4e79646b68df receives addresses of both result temporaries. No supplied dependency contract prohibits retaining those addresses or making them available to another dependency.

Consequently:

- A later loop comparison may change either result temporary.
- A later advancement call may change either result temporary.
- The context-result value presented to the next processing call is its then-current value, not necessarily the value left by the preceding processing call.
- The item-result value is explicitly replaced after each advancement, before the processing call.
- A terminating comparison may change both temporaries and then return one.

When a comparison returns one, the function does not republish the context-result temporary. It constructs the return from the temporary values read after that comparison. Thus the last direct output publication can differ from the high return component.

The function establishes neither a snapshot at the last processing call nor preservation of that call’s results across subsequent dependency calls.

### Zero-iteration completion and progress

If the first loop comparison returns one, no item is captured and neither F-50ef9e9e7cc8 nor F-4e79646b68df is called. The two result temporaries have not been passed by address to the processing dependency. The return components are their initial context-address and output-address values.

The entry output publication has nevertheless occurred. Comparison dependencies may affect caller-visible storage, so that publication alone does not establish the output word’s final contents.

There is no iteration bound, fallback exit, or independently established progress condition. If no loop comparison returns exactly one, normal completion is not established.

The function also writes its temporary storage, including the item replacement after advancement. Dependencies can affect this storage once its address has escaped.

All dependencies may have additional effects. Their names and use as comparisons or processing operations do not establish purity, preservation of globals, or preservation of reachable objects.

## Acceptance examples

These are conditional static scenarios, not executed tests. Unless a scenario specifies otherwise, storage is valid and nonoverlapping, and dependencies make no changes beyond those described.

### Stable bulk reset

Given header reference H, a nonzero state word, and nonzero results from both preliminary comparisons:

- The entry output receives H.
- F-ce267b08801d receives the context and H’s +4 word.
- If the dependency leaves the header reference unchanged, H receives the ordered reset writes.
- Context offset +20 becomes zero.
- The output receives H again.
- The return has H in its high half and the original output address in its low half.

No incremental calls occur.

### Replacement header

If the bulk dependency changes context offset +16 from H to valid J and the reference remains stable afterward, the reset targets J. The final publication and high return component are J.

Requiring the reset to target the pre-call H would contradict the post-call header lookups.

### Immediate loop termination

If the first preliminary comparison returns zero and the first loop comparison returns one, no advancement or processing occurs. The return contains the original context and output addresses. The entry publication has already occurred.

### Noncanonical comparison values

A preliminary comparison result of two satisfies its nonzero gate.

A loop comparison result of two does not terminate traversal; it enters an iteration. A negative loop result likewise enters an iteration.

### One item without subsequent temporary mutations

Suppose loop comparisons return zero and then one. The captured position word is X, and advancement changes the position word to Y.

Processing receives X through the item-result temporary, not Y. If processing leaves R in the context-result temporary and S in the item-result temporary, the output receives R.

**Provided the terminating comparison does not subsequently modify either escaped temporary**, the return has R in its high half and S in its low half.

### Terminating comparison changes the return

Suppose processing leaves R and S in the result temporaries, and the function publishes R. Through retained temporary addresses, the next comparison changes those values to T and U, then returns one.

The function returns T in the high half and U in the low half. It performs no additional direct output publication after that comparison. If the comparison does not separately modify the output word, the output remains R.

### Mutations between iterations

Suppose processing leaves R in the context-result temporary. The next comparison changes it to T and returns zero. Advancement then changes it to V.

The next processing call receives the same temporary address, now containing V—not necessarily R or T.

If that advancement also changes the item-result temporary, the function overwrites that change with the newly captured pre-advance item before processing.

### Zero state word

If both preliminary comparisons return nonzero but the subsequently read state word is zero, bulk processing is skipped. The loop still runs; a zero state word is not an immediate-return condition.
