# F-b127cc91530e

## Purpose

F-b127cc91530e selects between an ordered three-component transfer and a table-assisted computation that repeatedly transforms a destination and conditionally combines it with a temporary table entry.

The established contract concerns call order, data layout, status handling, arithmetic, and resource handling. A windowed mathematical computation is plausible inferred intent, not an established interpretation of the component values or operations.

This specification is based on the supplied static representation only. No runtime execution or tests have been performed. Dependency internals, unresolved arithmetic semantics, and mutable global values remain explicitly unresolved.

### Numeric validation and rejection reads

After allocation and both initialization writes, the function rejects the lower parameter if it is zero or its signed value exceeds four.

It rejects the upper parameter if:

- Its unsigned value is zero.
- Its signed 32-bit interpretation exceeds four.
- Its signed 32-bit interpretation is less than the lower parameter.

Each rejection reads the argument-rejection global at that exit and returns the word read. The allocation dependency has already run and may have changed that global. This function does not release the allocated object on these exits.

\[
1 \le \text{lower parameter} \le \text{upper parameter} \le 4.
\]

That is not the complete admitted set. Negative lower parameters can pass. High-bit-set upper parameters can also pass when their signed interpretations satisfy the comparisons. Validation therefore does not establish safe precomputation bounds or arithmetic for all admitted bit patterns.

### Local table layout and initialization

The table-assisted path initializes **16 table entries** using:

- A 48-word array containing three descriptor pointers per entry.
- Three arrays of 16 descriptors, one array per component.
- A 1,344-byte backing region.
- Two 32-bit words per descriptor: an initial zero word and a backing-storage pointer.

For entry \(t\) and component \(c\), the backing slice starts at:

\[
84t + 28c,\qquad 0 \le t < 16,\quad 0 \le c < 3.
\]

Each slice is 28 bytes; each table entry has three adjacent slices totaling 84 bytes. Descriptors are separate from the backing region.

Within each entry’s initialization, the function writes the three descriptors’ first words to zero, then their backing pointers in component order, then the three table pointers in component order. It does not explicitly clear the backing slices.

The initialization index starts at zero. Its update is a 32-bit increment followed by masking with **0xfffeffff**, which clears bit 16. Because this loop stops at 16, it visits entries 0 through 15 normally.

After table initialization, F-f7b210fb9ec5 receives the context. Its 32-bit result is retained for the initial remaining-work calculation.

## Side effects

Within an iteration, destination transformations precede temporary-object processing. Remaining-work subtraction precedes F-347405e096bf. The multiplication-factor read follows that call’s success. Any selected combination follows the selector-producing helper call.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Allocation failure takes precedence.** With invalid numeric arguments and a null allocation result, return 4 without reading either rejection global or accessing vectors.

2. **Argument rejection observes post-allocation state.** With lower parameter zero and successful allocation, perform both header writes, then return the argument-rejection global’s value at that exit. If allocation changed that global, its earlier value is not authoritative. Do not call the release dependency.

3. **Context rejection observes post-query state.** With admitted numeric arguments, if F-d72f047fba8b returns two, return the context-rejection global’s value after that call. Do not query mode or explicitly release the allocation.

4. **Negative lower input can pass.** Upper parameter two and lower parameter −1 pass numeric validation. This alone does not establish safe later arithmetic.

5. **Direct transfer stops at the first failure.** With both context queries returning one, component 0 succeeding and component 1 failing, omit component 2, invoke release, and return 1. Earlier changes remain.

6. **No positive initial work still requires precomputation.** With ordinary admitted inputs, retained context-query result one, and all initialization calls succeeding, complete precomputation, then finish successfully without an iteration’s generator call.

7. **Ordinary maximum precomputation stays within the table.** Upper parameter four builds entries 3 through 15 after preparing entry 2, assuming every checked call succeeds.

8. **A valid shift does not imply table safety.** Upper parameter 0x80000005 and lower parameter −2147483643 pass validation and produce bound 32. Successful earlier operations reach an attempted use of entry 16. No successful or error return is promised beyond that invalid local-table access.

9. **The factor can change between iterations.** If dependencies change the multiplication-factor global before successive selector expressions, each expression uses its newly read value, not a function-entry or previous-iteration snapshot.

10. **Zero selector skips combination.** A zero secondary result from the selector-producing helper suppresses that iteration’s combination. Any nonzero checked operational status instead causes release and return 1.
