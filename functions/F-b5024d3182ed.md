# F-b5024d3182ed

## Purpose

F-b5024d3182ed performs an ordered sequence of byte, halfword, and word memory accesses using three ambient address-bearing values. It updates two fixed-address bytes, modifies several potentially overlapping records, writes through two doubled numeric addresses, and finally transfers control to an unresolved indirect dependency.

The established behavior is memory manipulation and indirect dispatch. The available evidence does not establish a higher-level purpose such as allocation, list maintenance, device configuration, or message processing.

This contract distinguishes source-visible access order from assumptions about the execution architecture. It does not assert that the apparent interface is complete or that the recovered control transfer is an ordinary returning call.

## Interface

The supplied representation exposes four arguments:

|---|---:|---|
| First argument | 32 bits | No explicit use is visible. |
| Second argument | 32 bits | Its low eight bits initialize a fixed-address byte; its full width is later written into a record. |
| Third argument | 32 bits | Written into a record and supplied to the final indirect transfer. |
| Fourth argument | 8 bits | Written to two byte fields. |

An unused first argument does not establish that the original machine-level interface ignores every register or stack location associated with it. It establishes only that no use appears in the supplied representation.

### Ambient inputs

Four additional entry-state values participate without being defined in the body:

- **Address A:** a 32-bit unsigned value used as a record address, a stored word, a source of a low byte, and a source of a shift count.
- **Address B:** an address-bearing value used for three word-field destinations.
- **Address C:** an address-bearing value used for record accesses and stored as a word.
- **Ambient payload:** a 32-bit value written to a field relative to Address B.

The indirect control-transfer target is also unresolved entry or execution context. It is not obtained by an explicit visible load in this body.

These values are necessary behavioral inputs even though they are absent from the apparent four-argument interface.

### Memory widths and notation

A byte is 8 bits, a halfword is 16 bits, and a word is 32 bits. Offsets below are byte offsets. Hexadecimal offsets identify locations relative to the named base unless explicitly identified as fixed addresses.

The two fixed-address byte locations are:

- **Global byte G:** address `0x67`.
- **Global byte H:** address `0x21`.

Words loaded during execution receive descriptive names in this contract. These names describe captured values, not persistent structure members or ownership relationships.

### Output and return

## Behavior

### Access-order rule

The following phases describe the source-visible order. Loads occur when specified, after preceding writes; they must not be interpreted as a snapshot of entry memory.

Aliasing is significant. Addresses A, B, and C may overlap each other, the fixed-address bytes, or addresses derived from later loads. Consequently, an earlier store can change the value of a subsequent load.

No disjointness check, bounds check, alignment check, or validation branch is visible.

### 1. Initial record and fixed-byte updates

First, the function writes Address C as a word at Address C plus `0x54`.

It then writes the low eight bits of the second argument to G. Next, it reads a word at Address C plus `0x44`; call the captured value the **initial link**.

After that word read, the function reads G and writes that byte to H. The H update therefore occurs after the initial-link read, not immediately after the initial G write.

The function writes the low eight bits of the initial link at Address A plus `0x10`, then writes the complete initial link as a word at Address B plus `0x54`.

It next writes one byte at Address C plus `0x01`. This byte is obtained by right-shifting the initial link using the low eight bits of Address A as the shift count, then retaining the low eight bits of the result.

The initial link is represented as a signed 32-bit value at this operation. Negative operands and shift counts of 32 or greater require architecture or language-semantics information not supplied here. For a nonnegative initial link and a count from 0 through 31, the resulting byte is unambiguous.

Finally in this phase, the word at Address B plus `0x54` is overwritten with Address A. The earlier initial-link store is still part of the access sequence; it is not safe to remove it merely because this later store uses the same destination.

### 2. Replacement word and record links

The function reads a word at Address A plus `0x40`; call this the **replacement word**.

It then performs these updates in order:

- Writes the ambient payload as a word at Address B plus `0x74`.
- Writes the replacement word as a word at Address A plus `0x10`.
- Writes Address C as a word at Address B plus `0x44`.

The replacement-word store covers the byte location written earlier at Address A plus `0x10`, along with the next three bytes. Byte ordering within that word depends on the target architecture.

Next, the function reads G again and writes the resulting byte at Address A plus `0x09`. It writes the low eight bits of Address A at Address C plus `0x09`, then writes the complete second argument as a word at Address A plus `0x44`.

### 3. Selecting another record

The function reads a word at Address A plus `0x54`; call the captured value the **selected record address**.

It reads G again and writes that byte at Address A plus `0x09`. This is a distinct read and write from the earlier G-to-record update. The two writes need not have identical values if intervening writes alias G.

The fourth argument is then written as a byte at the selected record address plus `0x0D`.

Next, the third argument is written as a word at Address C plus `0x54`, replacing the initial self-address store at that location.

The function then reads a word at Address A plus `0x14`; call it the **byte-source word**. This read occurs after all preceding updates, including the third-argument store.

### 4. Byte fields and selected-record publication

The fourth argument is written as a byte at Address C plus `0x11`.

The low eight bits of the selected record address are then written at Address A plus `0x09`, replacing the byte most recently copied there from G.

The complete selected record address is written as a word at Address A plus `0x44`, replacing the earlier second-argument store.

The function next reads a word at Address C plus `0x04`; call it the **index carrier**. This captured value is used both as an address base and as a numeric quantity for a doubled-address store.

### 5. First doubled-address store and selected-record completion

A halfword with numeric value `0x0065` is written at the address obtained by doubling the index carrier. This destination is not described as an array element relative to any separate base: the visible address expression is the doubled value itself.

Only after that halfword write does the function read a word at the index carrier plus `0x64`; call the captured value the **forward value**. The halfword store can affect this read if their storage overlaps.

Next, the low eight bits of the previously captured byte-source word are written at the selected record address plus `0x11`.

The word value `0x00000064` is then written at the selected record address plus `0x54`.

### 6. Dispatch data and final memory updates

The function reads a word at the index carrier plus `0x74`; call it the **dispatch payload**.

It then reads a word at Address C plus `0x64`; call the result the **destination record address**.

The low eight bits of the index carrier are written at Address C plus `0x09`.

Next, the forward value is written as a word at the destination record address plus `0x54`.

Finally, the destination record address is written as a word at the address obtained by doubling the forward value. This second doubled-address store has width 32 bits, unlike the earlier 16-bit doubled-address store.

The dispatch payload and destination record address are captured before these final writes. Later memory changes do not cause either captured value to be reread.

### 7. Indirect transfer

After all listed memory accesses, the function transfers control to the unresolved indirect dependency with four supplied values, in this order:

1. Numeric constant `0x72`.
2. The captured forward value.
3. The third explicit argument.
4. The captured dispatch payload.

The three nonconstant values are word-sized. The representation does not independently establish the full calling convention, the constant argument’s ABI extension rules, or any additional implicit inputs.

No explicit use of the dependency’s return value is visible.

## Side effects

### Memory mutation

The function directly writes:

- Both fixed-address bytes G and H.
- Byte and word fields relative to Addresses A, B, and C.
- Byte and word fields relative to the selected record address.
- A word relative to the destination record address.
- A halfword at twice the index carrier.
- A word at twice the forward value.

This is an access description, not a set of necessarily distinct destinations. Aliasing can merge or partially overlap any of these writes.

An overwritten store remains relevant for memory-mapped devices, externally observable memory, faults, and alias-dependent subsequent loads. The evidence does not establish that these locations are ordinary, nonvolatile RAM.

The indirect dependency’s ownership behavior is unknown. It must not be assumed to preserve globals, retain no pointers, release no memory, or leave the written records unchanged.

If an access faults or a platform rejects an address or alignment, preceding writes may already have occurred. The supplied evidence does not specify fault delivery or recovery.

Successful completion therefore requires an execution environment in which the actual sequence of accesses and the final control transfer are valid.

These examples are conditional static expectations, not executed tests.

### Ordinary disjoint records

Assume all accessed storage is valid, suitably aligned where required, ordinary memory, and disjoint except for explicitly repeated destinations. Also assume:

- The second argument is `0x123456AB`.
- The third argument is `0xCAFEBABE`.
- The fourth argument is `0x7E`.
- Address A is `0x1000`.
- The initial link is `0x12345678`.
- The replacement word is `0x11223344`.
- The selected record address is `0x4000`.
- The byte-source word is `0xA1B2C3D4`.
- The index carrier is `0x5000`.
- The forward value is `0x6000`.
- The dispatch payload is `0xDEADBEEF`.
- The destination record address is `0x7000`.

Under those conditions:

- G and H receive `0xAB`.
- The shift count is zero, so Address C plus `0x01` receives `0x78`.
- Address A plus `0x10` ends with the word `0x11223344`.
- Address A plus `0x09` ends with `0x00`, the low byte of `0x4000`.
- Address A plus `0x44` ends with `0x00004000`.
- Address B plus `0x54` ends with `0x00001000`.
- Address C plus `0x54` ends with `0xCAFEBABE`.
- Address C plus `0x11` receives `0x7E`.
- Address C plus `0x09` ends with `0x00`, the low byte of `0x5000`.

- Address `0x4054` receives the word `0x00000064`.
- Address `0xA000` receives the halfword `0x0065`.
- Address `0x7054` receives the word `0x00006000`.
- Address `0xC000` receives the word `0x00007000`.

The final transfer supplies `0x72`, `0x6000`, `0xCAFEBABE`, and `0xDEADBEEF`. These expectations describe state immediately before that transfer; they do not constrain changes made by F-UNKNOWN-01.

### Aliasing changes a later read

If Address A equals Address B, the early store of Address A at Address B plus `0x54` also changes Address A plus `0x54`.

If no intervening overlapping write changes that word, the selected record address subsequently read from Address A plus `0x54` is Address A itself, regardless of that field’s entry value. An implementation that preloads the selected record address at entry would not preserve this behavior.

### Defined small shift

If the initial link is `0x12345678` and the low eight bits of Address A equal 8, Address C plus `0x01` receives `0x56`, assuming the earlier writes do not alter the initial-link read.

For a count of 32 or greater, no specific result is accepted without additional target-semantics evidence.

### Captured dispatch payload

If either final word store overlaps the memory location from which the dispatch payload was read, the final transfer still receives the previously captured dispatch payload. It does not receive a fresh load from the modified location.
