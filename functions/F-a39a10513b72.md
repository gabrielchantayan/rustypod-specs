# F-a39a10513b72

## Purpose

F-a39a10513b72 produces two retained temporary values from table entries and an input-relative address. It obtains a four-byte result from each retained value, combines those results with an input byte in a final temporary, and passes that temporary to an operation involving another input-relative address.

After the operation returns normally, the function invokes three cleanup calls and returns one of two four-byte bit patterns:

| Operation result | Function return |
|---|---|
| Zero | `0xffffffff` |
| Any nonzero value | `0x00000000` |

The representation establishes call order, argument relationships, direct reads, and return normalization. It does not establish the application meaning of the objects or dependencies. “Seed,” “retained value,” “initializer,” and “cleanup” describe call roles, not verified ownership or resource-management semantics.

This contract is based on static evidence only. No runtime tests have been performed.

### Global input

A global location supplies a table pointer. The function evaluates that global location **twice**, in this order:

1. It reads the global pointer and saves that pointer value for later use.
2. It evaluates the global pointer again and reads the first four-byte entry through this second pointer value.

No dependency call intervenes between these two pointer evaluations. They nevertheless remain distinct observations in the supplied representation. The representation does not justify treating them as one read or unconditionally identifying their resulting pointers.

Later, after the first construction and cleanup sequence, the function reads a four-byte entry at byte offset 4 through the pointer saved by the **first** evaluation.

Consequently:

- The first entry comes from the pointer obtained by the second global-pointer evaluation.
- The second entry comes from offset 4 of the table reached through the saved first pointer.
- If the two pointer evaluations agree, the entries are the first and second four-byte entries of the same table.
- Equality of those pointer values is not an unconditional property established here.

The required validity and lifetime of each referenced table remain preconditions. A saved pointer does not preserve the table’s contents or keep its storage alive.

### Return value

The return value is four bytes wide. Its only established normal-return bit patterns are `0xffffffff` and `0x00000000`.

Under a signed 32-bit interpretation, these mean −1 and 0. The representation does not establish a stronger return type or application-level success convention.

## Behavior

It then evaluates that global pointer location again and reads the four-byte entry at offset 0 through the newly obtained pointer. This entry is passed to F-398e0e9a318a along with the address of the first seed region.

F-398e0e9a318a’s four-byte return value becomes the third argument to F-869fb77ab4a4. That call receives:

1. The first intermediate region.
2. The input-relative address at offset 92.
3. The preceding seed-call result.

Next, F-1fab02e9be4d receives the first retained region and the first intermediate region, in that order.

The function then calls F-289ec4311c64 twice:

1. On the first intermediate region.
2. On the first seed region.

The first retained region is therefore passed to its producer before either of these cleanup calls. Whether its later use remains valid depends on the dependencies’ ownership and aliasing rules; the call sequence does not prove an independent copy was made.

### 2. Read the saved table’s second entry and produce the second retained value

After the first sequence finishes, the function reads four bytes at offset 4 through the pointer saved by the initial global-pointer evaluation.

The function does not reread the global pointer for this entry. Changes to the saved table’s contents can affect this read. Replacing the global pointer alone does not redirect it.

The second sequence is:

1. F-398e0e9a318a receives the second seed region and the newly read entry.
2. F-869fb77ab4a4 receives the second intermediate region, the input-relative address at offset 92, and the preceding seed-call result.
3. F-1fab02e9be4d receives the second retained region and the second intermediate region.
4. F-289ec4311c64 receives the second intermediate region.
5. F-289ec4311c64 receives the second seed region.

Both construction sequences receive the same input-relative address at offset 92. This function does not snapshot the storage at that address. The second sequence may therefore encounter changes made during the first sequence.

The saved table’s second entry is likewise a later observation, not an entry-time snapshot.

### 3. Obtain results from the retained regions

1. On the second retained region.
2. On the first retained region.

## Side effects

### Direct nonlocal reads

The direct nonlocal observations appear in this order:

1. Read the global pointer into saved state.
2. Read the global pointer again.
3. Read the first four-byte entry through the second pointer value.
4. After the first construction and cleanup sequence, read four bytes at offset 4 through the saved first pointer.
5. After both retained-value extraction calls, read the byte at input offset 100.

The two global-pointer evaluations occur without an intervening dependency call. The later entry and byte reads do have dependency calls before them.

### Writes and dependency-visible state

No explicit direct store to input or global storage appears. The function uses local storage and passes its addresses to dependencies.

This is not a read-only guarantee. Dependencies may modify storage reachable through their arguments or through globals. In particular, they may affect:

- The saved table’s later-read entry.
- Storage associated with input offset 92.
- The byte eventually read at input offset 100.
- Other state used by later dependencies.

No dependency is assumed to preserve globals or input-associated storage.

### Ownership and lifetime

There is no explicit heap allocation or deallocation in this function. Whether dependencies allocate, share, retain, transfer, or release resources is unknown.

The local storage regions cease to exist when this invocation ends. Passing an address does not establish permission for a dependency to retain it beyond that lifetime.

The cleanup ordering is established; actual resource release is not:

- Each intermediate is cleaned up before its associated seed.
- Both are cleaned up before construction of the next retained value begins.
- The final temporary is cleaned up before either retained region.
- The second retained region is cleaned up before the first.

The extracted results may be borrowed, owned, or another kind of value. Their four-byte width alone does not establish pointer semantics.

### Errors and concurrency

The only explicit result classification is the zero/nonzero check on F-086cb6e3869b. A zero intermediate result is not treated as an error by this function.

Invalid addresses, invalid dependency state, arithmetic outside the target’s valid rules, and abnormal dependency exits have no established error return or recovery path.

No synchronization is visible. The separate global-pointer evaluations must be distinguished in this static contract, but this does not establish that concurrent mutation is safe, race-free, or defined by the target environment.

## Acceptance examples

These are conditional static cases, not executed tests. Except where stated otherwise, storage remains valid and every dependency returns normally.

1. **Zero operation result.**  
   If F-086cb6e3869b returns zero, final-temporary cleanup occurs, followed by second-retained and first-retained cleanup. The function returns `0xffffffff`.

2. **Nonzero operation result.**  
   If the operation returns any nonzero integer, including a negative value, the same cleanup sequence occurs and the function returns `0x00000000`.

3. **Stable global pointer.**  
   If the two initial global-pointer evaluations return the same pointer, the first seed call receives the table’s offset-0 entry. The second seed call later receives that table’s offset-4 entry as it exists when read.

4. **Different initial pointer observations.**  
   If an execution environment permits the two pointer evaluations to produce different valid pointers, the first seed call receives the offset-0 entry through the second pointer. The second seed call receives the offset-4 entry through the first, saved pointer. This case specifies provenance, not a guarantee of defined concurrent mutation.

5. **Global pointer replaced by a dependency.**  
   If a dependency replaces the global pointer after the first seed call begins, while the saved table remains valid, that replacement does not redirect the later offset-4 read. The function uses its saved pointer.

6. **Saved table entry changed.**  
   If an earlier dependency changes the saved table’s offset-4 entry before its read, the second seed call receives the changed entry. No entry-time copy is substituted.

7. **Input byte changed during extraction.**  
   If either F-44362605ab79 call changes the byte at input offset 100, the initializer receives the conversion of the byte present at the subsequent load.

8. **Extraction order differs from argument order.**  
   If extraction from the second retained region returns `0x11223344` and extraction from the first returns `0x55667788`, the initializer’s second argument is `0x55667788` and its fourth argument is `0x11223344`.

9. **High-bit input byte.**  
   For a byte value of `0xff`, the initializer receives −1 under signed plain-character interpretation or 255 under unsigned interpretation. The supplied evidence does not select between these cases.

10. **Zero intermediate result.**  
    A zero result from either extraction call is forwarded unchanged. It does not trigger an early return or bypass the final operation.

11. **Invalidated saved table.**  
    If an earlier dependency invalidates the saved table before the offset-4 read, no defined error result or completed cleanup sequence is established. This is not equivalent to the operation returning zero.
