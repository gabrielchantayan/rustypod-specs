# F-73a1423ea490

## Purpose

F-73a1423ea490 repeatedly invokes a status-producing dependency and selects one of three outcomes:

- Return the 32-bit value `1` when the dependency reports status `2`.
- Return the 32-bit value `0` when it reports status `1` and the third input is zero.
- Invoke a result-producing dependency and return its 32-bit result when it reports status `3`.

Status `1` with a nonzero third input causes an auxiliary call followed by another status query. Every other status value also causes another status query, without that auxiliary call.

A preliminary dependency is called before polling begins. A final dependency is called on every explicitly represented terminating path, after the return value has been selected and before it is returned.

This is a control-flow contract. The supplied evidence does not establish what the statuses mean, what resource the first input identifies, or whether the preliminary and final calls implement locking, initialization, cleanup, or another protocol.

## Interface

### Inputs

The function receives three inputs, in this order:

| Input | Represented width | Established use |
|---|---:|---|
| Context value | 32 bits | Passed unchanged to the status-producing, result-producing, and final dependencies. Also used to form an address-like value eight bytes beyond it for the auxiliary dependency. |
| Companion value | 32 bits | Passed unchanged to the status-producing and result-producing dependencies. No other interpretation is visible. |
| Continuation control | 32 bits | Compared with zero only when the status-producing dependency returns `1`. |

The context and continuation-control inputs are represented as signed integer values in the supplied source representation. The companion input has an unspecified 32-bit type. These representations establish the operations visible here, not the higher-level meanings of the inputs.

The continuation control is a zero-versus-nonzero selector, not a value restricted to `0` and `1`. A negative value takes the same branch as any other nonzero value.

### Output

The function returns one 32-bit value:

- Exactly `1` following status `2`.
- Exactly `0` following status `1` with zero continuation control.
- The 32-bit result supplied by F-fd8c4998fac3 following status `3`.

There is no visible normalization of the delegated result into a Boolean or restricted status range. In particular, the function may return a value other than `0` or `1` through that path.

### Preconditions and validity

No input validation is visible. The function does not establish that the context is nonzero, aligned, points to allocated storage, or refers to a particular object type.

A safe invocation therefore depends on the requirements of the dependencies that are actually reached. Those requirements are not supplied. The context-derived value used by the auxiliary dependency must also be valid for that dependency whenever status `1` occurs with nonzero continuation control.

The eight-byte displacement is established. Boundary behavior when adding that displacement to an extreme context value is not established by the supplied representation. This contract does not assume portable signed overflow, a particular fault, or a particular wrapped address.

## Behavior

### Entry and first query

The first visible operation is a call to F-338d16f9ce72 with no explicit arguments. Its return value, if any, is not used by this function.

After that call returns normally, the function prepares a default return value of `1` and calls F-fd11e09803f1 with the context and companion inputs, in that order.

The preliminary call occurs once per invocation, not once per polling iteration. Even an invocation that terminates on its first status query performs this call first.

### Status-dependent behavior

Each completed call to F-fd11e09803f1 determines the next action independently.

**Status `2`: terminate with the default result.**

The function selects the already prepared result `1`. It does not invoke the auxiliary dependency or the result-producing dependency for this status. It proceeds to the final dependency call.

This behavior does not depend on continuation control.

**Status `1` with zero continuation control: terminate with zero.**

The function changes the selected result to `0` and proceeds to the final dependency call. It does not invoke the auxiliary dependency or the result-producing dependency for this status.

The zero check occurs after the status query has returned. Zero continuation control therefore does not suppress the preliminary call or the first query.

**Status `1` with nonzero continuation control: perform an auxiliary action and query again.**

The function calls F-162a41bac6a7 with one argument: the context value displaced by eight bytes.

If that call returns normally, the function invokes F-fd11e09803f1 again with the original context and companion argument values. No return value from the auxiliary call is inspected or forwarded.

A repeated sequence of status `1` results therefore produces one auxiliary call after each such result, provided continuation control is nonzero. The final dependency is not called between these iterations.

**Status `3`: obtain the return value from a dependency.**

The function invokes F-fd8c4998fac3 with the context and companion inputs, in that order. Its 32-bit result becomes the selected return value.

The function then proceeds to the final dependency call without another status query. This branch does not consult continuation control.

**Any other status: query again.**

Every status other than `1`, `2`, and `3` causes another invocation of F-fd11e09803f1 with the same argument values.

There is no visible error return, retry limit, delay, auxiliary call, or final call associated with such a status. Zero and negative statuses belong to this category unless their represented value equals one of the three distinguished values.

### Final call and return

Every terminating branch explicitly represented in this function calls F-1333331b2da1 with the original context value.

This call occurs:

- After the last status query on the status-`2` and zero-control status-`1` paths.
- After F-fd8c4998fac3 has returned on the status-`3` path.
- Before F-73a1423ea490 returns its selected result.

No return value from F-1333331b2da1 is used. The visible control flow contains no conditional rejection, conversion, or replacement of the selected result after that call.

This guarantee applies to normal returns from reached dependencies. The evidence supplies no exception-handling, nonlocal-exit, or fault-recovery mechanism that would ensure the final call occurs if an earlier dependency fails to return normally.

### Repetition and termination

There is no visible bound on the number of status queries.

An endless sequence of unrecognized statuses does not reach the final call. Neither does an endless sequence of status `1` with nonzero continuation control, assuming each dependency call returns normally.

Zero continuation control is not a general “query once” mode. It terminates polling only when a query returns status `1`. Unrecognized statuses still cause repeated queries.

## Side effects

The supplied function body contains no explicit dereference of the context, no direct write through an input, and no explicit global-memory access. Its observable external actions are dependency calls and the final return.

The normal call order is constrained as follows:

1. F-338d16f9ce72.
2. One or more calls to F-fd11e09803f1.
3. Immediately after each status `1` with nonzero continuation control, F-162a41bac6a7 before the next query.
4. On status `3` only, F-fd8c4998fac3 after the terminating query.
5. F-1333331b2da1 after a terminating result has been selected.
6. Return of that selected 32-bit result.

The context and companion argument values are reused unchanged across queries. That does not imply that the state they identify remains unchanged. Any dependency may have side effects that influence later dependencies or status results.

The function does not visibly allocate, copy, retain, or free a memory region. It also does not visibly transfer ownership. These absences do not establish what the dependencies do. In particular:

- The preliminary call is not established to acquire a lock or resource.
- The auxiliary call is not established to wait, sleep, acknowledge, or release anything.
- The final call is not established to release ownership or restore prior global state.
- The result-producing call is not established to preserve the context or companion-associated state.

No ordering of individual memory reads and writes inside those dependencies can be specified from this evidence.

## Acceptance examples

These examples are conditional behavioral expectations derived from static control flow. They are not reports of executed tests. Each assumes that reached dependencies return normally and that all argument requirements are satisfied.

### Immediate status `2`

Given any continuation-control value, if the first status query returns `2`:

- The preliminary call occurs first.
- Exactly one status query occurs.
- Neither the auxiliary nor result-producing dependency is called.
- The final dependency is called with the original context.
- The function returns `1`.

### Immediate status `1` with zero control

If continuation control is zero and the first status query returns `1`:

- The preliminary call and first query still occur.
- No auxiliary call occurs.
- The final dependency is called.
- The function returns `0`.

### Status `1` followed by status `2`, with nonzero control

If continuation control is nonzero and successive queries return `1`, then `2`:

- The first query is followed by one auxiliary call using the context displaced by eight bytes.
- A second query receives the original context and companion values.
- The final dependency follows the second query.
- The function returns `1`.

A negative continuation-control value has the same branch behavior.

### Status `3` returning an unrestricted value

If the first status query returns `3` and F-fd8c4998fac3 returns the 32-bit value `0x80000000`:

- The result-producing call receives the original context and companion values.
- The final dependency runs after that call returns.
- The function returns `0x80000000`, without Boolean conversion.

This applies whether continuation control is zero or nonzero.

### Unrecognized statuses before termination

If successive queries return `0`, `-1`, then `2`:

- Three status queries occur.
- No auxiliary or result-producing call occurs.
- The first two statuses do not become return values.
- The final dependency runs after the third query.
- The function returns `1`.

### Repeated continuation

If continuation control is nonzero and queries return `1`, `1`, then `3`, with delegated result `7`:

- Each of the first two queries is followed by its own auxiliary call.
- The third query is followed by the result-producing call.
- The final dependency runs once.
- The function returns `7`.

### No terminating status

If every query returns an unrecognized status, polling continues without a represented return or final call. If every query instead returns `1` with nonzero continuation control, polling alternates with auxiliary calls, again without a represented return or final call.
