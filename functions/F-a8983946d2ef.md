# F-a8983946d2ef

## Purpose

F-a8983946d2ef performs two byte-sized writes to addresses selected through an implicit context, interleaved with fourteen indirect calls. It forwards the explicit input, shifted values, selected call results, and a saved selector byte to particular dependencies.

The supplied representation ends at an invalid-instruction boundary. It does not establish a normal return, a recoverable error result, or the behavior of any continuation beyond that boundary.

This contract describes the statically visible prefix. It does not assign a higher-level purpose such as initialization, decoding, or device control: those interpretations are not established by the available evidence.

## Interface

### Explicit input

The recovered interface has one unsigned, 32-bit input and no declared return value.

Three transformations of that input are visible:

- Its low eight bits become the first stored byte.
- A left shift by two supplies the third argument to the first dependency.
- A logical right shift by 22, followed by byte truncation, supplies the second stored byte. This extracts input bits 22 through 29, not the entire upper byte.

The first dependency also receives two unmodified copies of the input.

The 32-bit model follows the recovered types. The original ABI and type declarations are unavailable.

### Implicit inputs

The visible body relies on two values not supplied as explicit parameters:

- **Context-base value:** used to read one byte at an offset of one.
- **Link-derived value:** used to construct the first indirect-call target by adding 4,076 bytes.

Both must already be meaningful on entry for the visible operations to proceed as intended. Their initialization, validity rules, and relationship to any larger object are unknown.

Several other call targets are formed from fixed or symbolic anchors with an added displacement of 4,094 bytes. These are executable-address constructions, not data-buffer accesses. Their validity and any architecture-specific instruction-state interpretation remain external preconditions.

### Outputs

There is no established normal return value.

Observable outputs can include:

- Two byte writes, if execution reaches both.
- Effects of each dependency actually entered.
- Failure, nonreturn, or other behavior within those dependencies.
- Arrival at the invalid-instruction boundary after the final visible call returns.

No allocation, ownership transfer, release operation, output buffer, or returned object is explicit in this function.

## Behavior

### Widths and address selection

Each selector read is exactly one byte from the address one byte beyond the context-base value. The selector is treated as an unsigned value in the range 0 through 255.

For either explicit store, the destination address is:

- The selector value, numerically promoted for address calculation;
- Plus 17;
- Used directly as the destination address.

This is not an offset added back to the context base. Consequently, the directly selected destination lies between address 17 and address 272 inclusive.

Each store writes exactly one byte. Truncating the input to that byte retains its low eight bits regardless of whether a recovered character type is signed.

The address arithmetic for these destinations cannot overflow a 32-bit address quantity because its largest result is 272. Whether those low addresses are accessible, mapped to memory or devices, or otherwise meaningful is unknown.

### Selector lifetime and aliasing

The second selector determines both the second write address and the later selector argument to F-000000000013.

There is no third explicit selector read. Thus, subsequent changes to the selector’s memory location do not, in the represented flow, change that saved argument.

The two selector reads need not agree:

- The first write may itself affect the selector location if the addresses alias.
- Any intervening dependency may change the selector or other relevant state.
- Other agents may change the memory if the execution environment permits concurrent or device-driven changes.

The representation contains no equality check, retry, synchronization, or restoration of the initial selector.

### Shift semantics

For the unsigned input, a 32-bit interpretation of the left shift by two discards the upper two bits and inserts two zero low bits. The right shift by 22 is logical because the input is unsigned.

The two shifted dependency results are recovered as signed 32-bit integers. Their exact machine-level behavior cannot be established merely by applying source-language signed-shift rules. In particular, negative results and results whose shift exceeds the signed range require instruction-level evidence that is absent here.

Where a dependency result is nonnegative and its value multiplied by four fits within a signed 32-bit integer, the represented shift unambiguously supplies that product. Other cases remain documented_only rather than receiving an invented overflow policy.

## Side effects

### Direct memory effects

The function explicitly performs:

- Two one-byte reads from the context-base address plus one.
- Two one-byte writes to selector-derived low addresses.

The first write precedes every dependency call. The second write follows F-000000000007 and precedes F-000000000008.

No explicit write is made to the context structure merely because it supplies the selector. Such a write is possible through address aliasing, but is not a separate operation.

If both selectors agree, both explicit writes address the same byte. The second write then supersedes the first as this function’s latest explicit write to that byte. Dependencies can still modify that location before or after either write, so this does not establish its final contents.

## Acceptance examples

These are conditional static acceptance examples, not runtime observations. They assume valid target resolution and successful memory access. Examples reaching later steps additionally assume that earlier dependencies return.

### Zero input with a stable selector

Given input zero and a selector of 5 at both reads:

- The first explicit write stores zero at address 22.
- F-000000000001 receives three zero arguments.
- The second explicit write also stores zero at address 22.
- F-000000000013 receives 5 as its second visible argument.

No conclusion follows about dependency effects or final memory contents.

### Distinguishing the two byte extractions

Given input `0x12345678`:

- The first stored byte is `0x78`.
- F-000000000001 receives `0x12345678`, `0x12345678`, and `0x48D159E0`.
- The second stored byte is `0x48`.

The second byte is therefore not the input’s most significant byte, which is `0x12`.

### Input-shift truncation

Given input `0xC0000001`, under the recovered unsigned 32-bit model:

- The first stored byte is `0x01`.
- The third argument to F-000000000001 is `0x00000004`.
- The second stored byte is zero.

The input’s top two bits do not survive the left shift or contribute to the second stored byte.

### Changed selector between reads

Given an initial selector of 2 and a second selector of 200:

- The first explicit write targets address 19.
- The second explicit write targets address 217.
- The second argument to F-000000000013 is 200.

If the selector location changes again after the second read, that later memory change does not cause an explicit reread before F-000000000013.

### Boundary selectors

A selector of zero selects address 17. A selector of 255 selects address 272.

Neither value triggers an explicit bounds rejection. Address accessibility is an external precondition.

### Unambiguous shifted dependency results

If F-000000000007 returns 3 and F-000000000012 returns 7:

- F-000000000008 receives 12.
- F-000000000013 receives 28 as its first visible argument.

These values avoid the unresolved signed-shift edge cases.

### Interrupted execution

If F-000000000007 does not return, the second selector read, second explicit write, and remaining calls are not reached through the represented sequence. The first write has already occurred, assuming its access succeeded.
