# F-fa3b853f090d

## Purpose

F-fa3b853f090d traverses a linked sequence, checks entries matching a requested 32-bit value, and excludes one entry address from those checks.

A qualifying entry selects one of two behaviors:

- A zero state byte requires a compatible owner. Failure returns **6** immediately.
- A nonzero state byte requires comparison with a related object’s value. A mismatch causes a call to **F-7f3971a6513c**, after which traversal continues if the call returns.

Reaching a null current-entry address returns **0**.

These return conditions do not establish application-level meanings such as success, validity, or repair. In particular, result 0 does not imply that any matching entry existed or that execution had no side effects.

## Interface

### Arguments

| Argument | Observed representation | Role |
|---|---|---|
| Context address | 32-bit address | Provides a reference identity and the address of a sequence container |
| Requested value | Unsigned 32-bit value | Compared for exact equality with selected entry values |
| Excluded entry address | 32-bit address | An entry at this address is traversed without performing its selection or validation checks |

The excluded address is compared with the current entry address; it is not independently dereferenced. It need not identify an entry in the sequence.

### Accessed layouts

Offsets are in bytes. These tables describe accessed storage, not complete object definitions.

| Base | Offset | Width | Observed role |
|---|---:|---:|---|
| Context | 0 | 32 bits | Reference identity saved for ownership comparisons |
| Context | 4 | 32 bits | Sequence-container address |
| Sequence container | 8 | 32 bits | Initial entry address |
| Entry | 0 | 32 bits | Holder address |
| Entry | 8 | 32 bits | Next entry address |
| Entry | 20 | 32 bits | Value compared with the requested value |
| Entry | 24 | 32 bits | Related-object address |
| Entry | 64 | 8 bits | State: zero versus nonzero |
| Entry | 67 | 8 bits | Type: only value 1 qualifies |
| Holder | 0 | 32 bits | Owner address |
| Owner | 12 | 32 bits | Flags containing permission bit 0x4000 |
| Related object | 76 | 32 bits | Value compared with the selected entry value |

The holder and owner are distinct levels of indirection. The word at entry offset 0 identifies the holder; the holder’s first word supplies the owner address.

The saved reference identity is used for equality comparison. This routine does not dereference that identity merely because it was loaded from the context.

### Result

The explicit result is 32 bits:

- **0** when the current-entry address is null.
- **6** when a qualifying zero-state entry fails the ownership condition.

No other explicit result is established. Invalid memory access, nontermination, or abnormal behavior of the dependency is not translated into an established return code.

### Conditional memory requirements

Readable storage is required only for accesses actually reached:

- Initialization requires the context words at offsets 0 and 4, followed by the sequence-container word at offset 8.
- A non-null, non-excluded entry requires its type byte at offset 67.
- Type 1 additionally requires its value word at offset 20.
- A matching value additionally requires its state byte at offset 64.
- A matching zero-state entry requires its holder-address word and the first word at that holder.
- A non-null owner differing from the saved reference identity additionally requires the flags word at owner offset 12.
- A matching nonzero-state entry requires its related-object-address word and the value word at related-object offset 76.
- **The next-address field at entry offset 8 is required only when execution reaches advancement.** This includes advancement after a returning dependency call.

A qualifying zero-state entry that causes immediate result 6 does **not** need a readable next-address field for this routine’s execution. That field is not accessed on the rejecting path.

An excluded entry still requires a readable next-address field when advancement is reached, despite requiring none of its selection or validation fields.

No explicit null checks protect the context, sequence container, holder, or related object. The owner address, by contrast, is explicitly checked for null before an owner-flags access.

## Behavior

### Initialization

The routine reads the reference identity from context offset 0 and saves it for the traversal. It then reads the sequence-container address from context offset 4 and obtains the initial entry address from container offset 8.

This initialization occurs even if the initial entry address is null. A null head therefore avoids entry accesses, not the context and container accesses.

The saved reference identity is not refreshed during traversal. The sequence head is likewise not reloaded.

### Selection and skipped entries

A null current-entry address ends execution with result 0.

For a non-null current entry, the address comparison against the excluded address precedes entry-field checks. An equal address skips those checks and proceeds to advancement.

For a non-excluded entry, selection proceeds in this order:

1. Read the type byte at offset 67.
2. Only if the type equals 1, read the 32-bit entry value at offset 20.
3. Only if that value equals the requested value, read the state byte at offset 64.

An entry failing either selection condition proceeds directly to advancement. Its holder, owner, state-dependent data, and related-object value are not inspected.

Type and state have different conditions. The type must be exactly 1. The state distinguishes only zero from nonzero; no particular nonzero byte value has a separate behavior.

### Zero-state ownership condition

For a selected entry with state zero, the routine reads the holder address from entry offset 0 and then the owner address from holder offset 0.

The owner determines the outcome:

| Owner condition | Behavior |
|---|---|
| Null | Return 6 immediately |
| Non-null and equal to the saved reference identity | Proceed to advancement without reading owner flags |
| Non-null, different identity, bit 0x4000 set in owner flags | Proceed to advancement |
| Non-null, different identity, bit 0x4000 clear in owner flags | Return 6 immediately |

The null check takes precedence over identity equality. A null owner is rejected even when the saved reference identity is also zero.

Only bit 0x4000 influences the flag-based decision. Other flag bits do not affect this routine’s result for that owner.

A rejecting entry causes no next-address read and no inspection of later entries. The zero-state path neither reads the related-object field nor calls F-7f3971a6513c.

### Nonzero-state related-value condition

For a selected entry with nonzero state, the routine reads the related-object address from entry offset 24 and the 32-bit related value from related-object offset 76.

It compares that value with the entry value already obtained during selection. The entry value is not reread. Because selection required equality with the requested value, the saved comparison value also equals the requested value.

- Equal related and selected values cause no dependency call.
- Unequal values cause a call to **F-7f3971a6513c** with the current entry address as the sole observed argument.

No dependency result is inspected or propagated. If the call returns normally, execution proceeds to advancement without rechecking the entry’s type, value, state, or related value.

This path does not read the holder or perform the ownership condition.

### Advancement and mutation

Whenever execution reaches advancement, it reads the current entry’s next-address field at offset 8. That address becomes the current entry for the next iteration.

For a visit that calls F-7f3971a6513c, the next-address read occurs **after** the call returns. The routine does not save the successor before calling. A dependency change to the current next field can therefore change subsequent traversal.

No restart, head reload, duplicate suppression, visit limit, or cycle detection is visible. Entries can be revisited. A revisited qualifying mismatch can cause another dependency call.

The current entry must remain readable at its next-address field if a returning call is followed by normal advancement. No guarantee that the dependency preserves this readability is established.

### Widths and arithmetic

The requested, entry, and related values are 32-bit quantities compared for equality. There is no signed ordering comparison, range restriction, or arithmetic transformation of these values.

The state and type occupy individual bytes. State testing depends only on whether the byte is zero. The permission test applies mask 0x4000 to a 32-bit flags word.

The observed address representation is 32 bits, with fixed byte offsets for field access. There are no counters, length calculations, or value increments. The evidence does not establish safe or portable behavior for address overflow, inaccessible storage, or misaligned accesses.

## Side effects

No direct memory stores are visible in F-fa3b853f090d. Its established observable actions are conditional memory reads, dependency calls, and the explicit return of 0 or 6.

The routine directly performs no visible allocation, release, reference-count update, or ownership transfer. Passing an entry address to F-7f3971a6513c does not establish whether that dependency borrows, retains, releases, or otherwise changes the entry.

Dependency-mediated effects can occur before a later rejection. If an earlier visit invokes the dependency and a later zero-state entry fails its ownership condition, the routine returns 6 without any visible rollback.

No direct global access is visible. This does not establish freedom from global effects: the dependency may access or change global state, reachable memory, or entry lifetimes.

The explicit early return is significant for memory access as well as result selection. On an ownership rejection, the routine does not attempt the current next-address read, even if that field would be inaccessible.

## Acceptance examples

These are conditional static expectations, not executed tests. Except where specified otherwise, accessed storage is readable, dependency calls return normally, and the remaining sequence reaches null.

1. **Empty sequence.** A null initial entry produces result 0 after context and container initialization reads. No entry fields are read.

2. **Excluded entry.** An entry whose address equals the excluded address is traversed using its next field. Its type, value, state, holder, and related-object fields are not inspected, regardless of their contents.

3. **Selection short-circuiting.** A non-excluded type-2 entry is skipped without reading its value or state. A type-1 entry with a nonmatching value is skipped without reading its state.

4. **Null owner and unreadable successor.** A selected zero-state entry has a readable holder containing a null owner, but its next-address field is unreadable. The routine returns 6 without accessing that field. This remains true when the saved reference identity is zero.

5. **Flag rejection and unreadable successor.** A selected zero-state entry has a non-null owner different from the saved reference identity, and its readable flags word lacks bit 0x4000. Result 6 occurs without requiring a readable next-address field.

6. **Identical non-null owner.** A selected zero-state entry has an owner equal to the saved nonzero identity. No owner-flags read occurs. Advancement is then reached and requires the entry’s next field to be readable.

7. **Permission bit.** For a different non-null owner, flags 0x4000 and 0x4001 permit advancement. Flags 0x0001 cause result 6. The entry’s related object is not inspected in any of these zero-state cases.

8. **Nonzero state with equal values.** A selected entry has state 255 and a related value equal to its selected value. No dependency call occurs. State 255 selects the same path as state 1.

9. **Dependency changes the successor.** A selected nonzero-state mismatch causes one dependency call for that visit. If the dependency changes the current next field to null and returns with that field readable, advancement observes null and the routine returns 0.

10. **Post-call lifetime requirement.** If that dependency instead invalidates the current entry, the routine still attempts the next-address read after return. No defined recovery result is established.

11. **Effects before rejection.** An earlier mismatch causes a dependency call. A later zero-state entry has a null owner. The result is 6 after the earlier call, without visible rollback.

12. **Full-width equality.** Requested value 0xFFFFFFFF selects an entry with value 0xFFFFFFFF. An equal related value suppresses the call; a different related value triggers it on the nonzero-state path.

13. **Persistent cycle.** A non-rejecting entry points to itself, and no dependency changes the conditions. Traversal does not reach an explicit return. A persistent nonzero-state mismatch can cause repeated calls.
