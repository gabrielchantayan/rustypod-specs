# F-69968ce901c0

## Purpose

F-69968ce901c0 dispatches an incoming event by comparing it against seven event references in a fixed order. The first comparison returning zero selects the event. A branch-specific sentinel then determines whether to invoke its handler.

Recognition and execution are separate:

- A recognized event returns the 32-bit value **1**, even when its handler is suppressed.
- An event for which all seven comparisons return nonzero returns the 32-bit value **0**.
- A handler’s return value does not determine the dispatcher’s result.

The reference labels suggest audiobook chapter resume selection, selection, highlighting, play/pause, addition to an on-the-go collection, remote video play/pause, and contextual-menu display. These meanings are inferred intent, not established reference contents or comparison semantics.

1. Reads the receiver’s first word as a dispatch-table address.

- **348 bytes** for the first event.
- **296 bytes** for the sixth event.

The supplied representation is consistent with four-byte words and pointers. Under that model, the offsets correspond to zero-based slots 87 and 74. The byte offsets are the operative layout requirements; a complete ABI is not supplied.

There is no visible receiver null check, table-size check, target validation, or runtime type check. The receiver and table must support the reads actually reached. Suppressed indirect handlers do not require those reads from this dispatcher.

### Ordered recognition

Each reached comparison calls D-01 with the original event value followed by the applicable reference.

A zero result selects that reference. Any nonzero result continues to the next reference. The sign and magnitude of a nonzero result have no further effect.

The first zero result ends the search. Suppressing that event’s handler does not resume comparison or permit a later handler to run. At most one event handler is invoked.

References need not be distinct under D-01’s unknown comparison semantics. If multiple references could match, comparison order determines precedence.

### First event

The dispatcher first compares the event value with R-01.

If D-01 returns zero:

- Read S-01.
- Compare the event argument with that value.
- If equal, invoke no handler.
- If unequal, read the receiver’s current table address, obtain D-02 at byte offset 348, and invoke it with the receiver and event argument.
- Return 1 after normal completion.

This path performs no comparison against R-02 through R-07 and no dispatcher read of S-02.

If the first comparison returns nonzero, the dispatcher proceeds to R-02 without reading S-01.

### S-02 snapshot and second-event reread

After the R-02 comparison returns, the dispatcher unconditionally reads S-02 and retains that value as a snapshot. This read occurs whether the R-02 comparison returned zero or nonzero.

The subsequent behavior distinguishes two cases:

- **R-02 matched:** The dispatcher reads S-02 **again** for the suppression comparison. The earlier snapshot does not decide whether the second event’s handler runs.
- **R-02 did not match:** The dispatcher continues to later comparisons. R-03 through R-07 use the already captured snapshot for suppression; they do not reread S-02 for that decision.

Thus, an R-02 match reaches two S-02 read sites in order: the unconditional snapshot read and the suppression read. A path reaching R-03 or later reaches only the snapshot read.

The values obtained by the two R-02-path reads are not required to agree. No synchronization, atomicity, or protection against intervening mutation is established. These are source-level read distinctions; executable instruction selection and concurrent-memory semantics are not supplied.

### Second event

If the R-02 comparison returned zero:

- Complete the unconditional S-02 snapshot read.
- Read S-02 again for comparison with the event argument.
- Invoke F-5ff4771492d5 with the original receiver and event argument only if the event argument differs from this **second** value.
- Return 1 after normal completion.

The snapshot’s value is irrelevant to suppression on this branch. No later event is compared, including when the second read suppresses the handler.

### Third through seventh events

If R-02 did not match, the dispatcher compares R-03 through R-07 in order.

For the first zero comparison result:

- Compare the event argument with the snapshot captured immediately after the R-02 comparison.
- If equal, invoke no handler.
- If unequal, invoke the corresponding handler with the original receiver and event argument.
- Return 1 after normal completion.

For R-06, the receiver-table reads needed to resolve D-03 occur only after recognition and after establishing inequality with the snapshot.

Changes to S-02 during comparisons with R-03 through R-07 do not replace the captured suppression value. Those dependencies may still have other effects; none are assumed absent.

If the R-07 comparison also returns nonzero, return 0 without invoking an event handler.
