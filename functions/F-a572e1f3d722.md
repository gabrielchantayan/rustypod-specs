# F-a572e1f3d722

## Purpose

F-a572e1f3d722 coordinates opaque dependency calls with direct memory accesses. Established effects include propagation of 32-bit values, extraction of high-order fields, lookup-selected byte writes, byte and word clears, a halfword clear, and two updates of one shared word. The final visible action is a call to numerical address zero.

No application-level purpose is established. Initialization, serialization, allocation, resource release, and privileged dispatch are not established by the supplied evidence.

This contract describes the visible continuation conditional on preceding dependencies returning and memory operations completing. It does not guarantee normal completion.

## Interface

### Entry and completion

The supplied representation declares no explicit parameters and no result. Execution nevertheless depends on ambient inputs:

- A control-flow value used to calculate the initial indirect target.
- A base address for an early word read at displacement `0x14`.
- An unsigned 32-bit extraction input.
- A 32-bit payload for the first direct store.
- Secondary dependency-result channels supplying indices, values, and a pointer.
- Shared and indirectly addressed memory.

The complete entry convention, argument channels, and register-preservation rules are documented_only unknowns. A parameterless declaration does not establish that arbitrary entry state is acceptable.

There is no visible status result. Reaching the return requires the terminal call to address zero to return to its continuation.

### Widths and address vocabulary

The representation uses 8-bit bytes, a 16-bit terminal clear, and 32-bit words and address quantities. Several dependencies expose 64-bit results whose low and high 32-bit parts are consumed separately.

| Term | Meaning |
|---|---|
| Ordinary indexed destination | Four times an index, plus `0x14` |
| Selected byte destination | An unsigned lookup byte plus `0x11` |
| Shared word A | The shared 32-bit location written twice |
| Shared word B | The shared 32-bit location sampled as a base |

Byte stores retain the low eight bits of their supplied values. Unsigned right shifts insert zeros. Consequently, shifting a 32-bit unsigned value right by 22 yields 0–1023; shifting right by 23 yields 0–511.

Unsigned arithmetic has the represented 32-bit width. Some scaling and left shifts involve signed-looking 32-bit quantities. Exact overflow and address-formation behavior for those expressions is documented_only. Examples requiring discarded high bits are conditional on 32-bit bit-vector behavior.

## Behavior

### Ordering and captured values

The direct effects below occur in the stated order, with dependencies between them. Dependencies are observable boundaries and may change memory.

A captured scalar is distinct from a later memory observation. A retained selector, base, or word is reused without an implied refresh. Conversely, explicitly repeated reads remain separate observations even when their addresses match.

### Initial word propagation

Five opaque calls precede the first direct store. The fifth returns an index; its ordinary indexed destination receives the ambient payload.

Only after this store is a word read from the ambient base plus `0x14`. Aliasing can therefore make the store affect that read.

Five more calls precede the next direct store. The first receives four times the preceding index. The ambient unsigned extraction input is shifted right 22, producing a ten-bit value. A secondary-result-selected ordinary destination receives that value as a full 32-bit word.

The early loaded word is shifted right 23 to produce a nine-bit field. The following four-argument dependency receives, in order:

1. The secondary index.
2. That same secondary index.
3. The nine-bit field.
4. The ten-bit extraction.

A result-producing call and a call forwarding its result follow. The nine-bit field is also shifted right another 23 bits. This second shift necessarily produces zero, independently of the original word.

After four further calls, another ordinary destination receives the ten-bit extraction. A call receiving four times that destination’s index and four further calls precede a word clear at a secondary-result-selected ordinary destination.

A dependency receives that secondary value, followed by a result-forwarding pair and four calls. The next ordinary destination receives the twice-shifted early field, hence zero.

Immediately afterward, a word is read at an address obtained by masking a secondary 32-bit value with `0x1fffffff`, shifting right 19, and adding `0x14`. There is **no multiplication by four** in this address calculation. Its range is `0x14`–`0x413`; alignment is not established.

### First byte-selection period

Five calls separate that word read from the first selected-byte write. The first receives four times the preceding destination index. The loaded word is shifted right 22, producing a new ten-bit extraction.

A separate unsigned 32-bit scalar is assigned zero before the selected-byte write.

The first lookup reads a byte at the twice-shifted early field plus one. Because that field is zero, this lookup reads numerical address `1`. The selected destination receives the low eight bits of the new ten-bit extraction.

The dependency sequence between this write and the next lookup is established:

1. Immediately after the write, a four-argument dependency receives the same secondary 32-bit value in its first three positions and zero in its fourth position. This secondary value is distinct from the extraction unless actual values happen to coincide.
2. A call with no explicit arguments follows.
3. A call with one visible argument follows. Its argument is the separately assigned unsigned zero shifted right 23, and is therefore exactly zero.
4. Four further calls occur, the last supplying an index used after the next clear.
5. The next lookup and selected-byte clear occur.

Neither the repeated secondary argument nor either zero argument may be treated as irrelevant: dependency behavior is unknown.

The second lookup reads at four times the ten-bit extraction plus one, giving a lookup-address range of `1`–`4093`. Its selected destination is cleared as a byte.

A dependency then receives the last returned index shifted left two. Four calls produce another index, followed by a dependency receiving that index shifted left two in both argument positions. A result-producing call, its forwarding call, and an additional call follow. The selector at address `1` is then freshly read, and its selected destination is cleared.

The lookup observations are separate. An earlier selected write or intervening dependency may change a later lookup byte.

### Retained selector and first shared update

A secondary 32-bit value is captured for later shifted arguments and passed three times to a dependency. A returned word is then passed to another dependency together with a preceding retained result shifted right 23.

After four calls, the selector at address `1` is read again. This observation is retained as an unsigned base, and its selected destination at base plus `0x11` is cleared.

A dependency receiving the current index shifted left two, four calls, and a dependency receiving the next index shifted left two twice precede another returned word. That word is written to shared word A **before** it is forwarded to a dependency. One further call occurs.

A word is then read at retained selector base plus `0x74`, and its low byte is written at retained selector base plus one. The base is not refreshed from address `1`.

Because the retained selector is an unsigned byte, these source and destination address ranges are `0x74`–`0x173` and `1`–`0x100`. Accessibility and alignment remain preconditions.

### Field copying and retained-word propagation

The retained secondary value is passed to a dependency after a left shift of 11. A subsequent 64-bit result supplies the next dependency’s first two arguments, low part first and high part second. Its third argument is the earlier word written to shared word A, shifted right 23.

That third argument uses the captured word, not a fresh read of shared word A. A dependency’s intervening modification of shared word A does not itself change this argument.

After four calls, a returned index is multiplied by four. A word at this scaled base plus `0x74` is read, and its low byte is stored at base plus one. A dependency receives the scaled base.

Four more calls produce a different index. Before that index is passed onward, the preceding word-read/byte-write operation is repeated using the **previous scaled base**. The source word is freshly read.

The next four-argument dependency receives:

1. The retained secondary value shifted left 12.
2. The new index shifted left two.
3. The same two-bit-shifted value.
4. The new index shifted left 18.

Two result-forwarding pairs and four calls lead to another scaled index. A word at this base plus `0x74` is read, its low byte is written at base plus one, and the full word is retained as the retained field word.

A dependency receives this scaled base. After four calls, the retained field word is stored at sixteen times a newly returned index plus `0x14`. This uses sixteen-byte scaling, not ordinary four-byte scaling.

A subsequent dependency receives the earlier two-bit-left-shifted index value after an unsigned right shift of two and a left shift of 16. This is not generally equivalent to shifting the original index left 16: high bits may already have been discarded.

Two result-forwarding pairs and four calls precede a copy of the retained field word to an ordinary indexed destination.

A dependency receiving that destination’s four-times-index value and four calls supply a fresh index. This index is shifted left two and stored at the earlier two-bit-left-shifted index value, masked with `0xfffffffc`, plus `0x14`. The newly shifted value is then passed twice to a dependency.

Another two result-forwarding pairs and four calls precede an ordinary-destination word clear.

### Split results and late byte updates

A dependency receives four times the cleared destination’s index. Four calls follow, the last exposing a 64-bit result.

Its low 32-bit part is shifted left two and stored at the ordinary destination selected by its high 32-bit part. Shared word B is read immediately afterward and retained as a base address.

The next dependency receives four arguments: the shifted low part, the high part, the shifted low part, and the shifted low part.

After four calls, another ordinary destination receives the same shifted low part. A word is then read at the captured shared-word-B base plus `0x14`; this is the late word. Changes to shared word B after its capture do not select a new base for this read.

A dependency receiving four times the current index and four calls lead to another 64-bit result. Its low part becomes the final address value; its high part is used in subsequent dependency arguments.

The next lookup reads at the retained field word shifted right 23, plus one. This lookup-address range is `1`–`512`. Its selected destination receives the low eight bits of the late word.

The following dependency receives the high result part three times, followed by the final address value shifted left two. A result-forwarding pair and four calls precede the next lookup.

This lookup reads at the final address value masked with `0x3fffffff`, shifted right 21, plus one. Its range is also `1`–`512`. Its selected destination receives the low eight bits of the late word shifted right 22: original bits 22–29. Bits 30–31 do not survive the byte store.

A dependency receives a returned index shifted left two. Four calls and a dependency receiving the next index shifted left two twice precede the terminal sequence.

### Terminal ordering

One additional call and a result-forwarding pair precede a final dependency result comprising an eight-bit value and a secondary pointer.

The terminal direct effects occur in this order:

1. Clear the byte addressed by the secondary pointer.
2. Obtain the upper source and construct a 32-bit value with the final eight-bit result in bits 0–7 and the upper source in bits 8–31. Write that value to shared word A.
3. Store a 16-bit zero at the final address value masked with `0x3fffffff` and shifted right seven.
4. Call numerical address zero with three visible zero arguments.

The upper-source observation follows the pointer-based clear. If that clear overlaps the upper source, it can affect the subsequently assembled value.

The halfword destination ranges from zero through `0x007fffff` and need not be even. Normal return is conditional on the zero-address call returning.

## Acceptance examples

These are conditional consequences of the representation, not execution results. Each assumes preceding calls return and required accesses succeed.

1. **Double-shift zero.** An early loaded word of `0xffffffff` becomes `0x1ff` after an unsigned right shift of 23. Shifting that result right 23 produces zero. Its later word store writes zero, and the first byte lookup reads address `1`.

2. **Word extraction versus byte truncation.** An ambient extraction input of `0xffc00000` produces `0x3ff`, stored as a full word. A separate ten-bit extraction of `0x3ff` contributes only `0xff` to its selected-byte write.

3. **Unscaled masked read.** A masked secondary value of `0x00080000` produces a word-read address of `0x15`, not `0x18`. Successful continuation requires support for that potentially unaligned access.

4. **Required dependency inputs between byte operations.** If the relevant secondary value is `0x12345678`, the dependency immediately after the first selected-byte write receives that value in its first three positions and zero in its fourth. A no-explicit-argument call follows, then a one-argument call receiving zero, then four calls, and only then the second lookup/clear. A dependency modification of the second lookup’s byte during this interval is observed by that lookup.

5. **Selected destination bounds.** A lookup byte of `0x20` selects address `0x31`; `0xff` selects `0x110`. The destination addition is not truncated to eight bits.

6. **Fresh repeated copy.** A first source word of `0x12345678` supplies byte `0x78`. If an intervening dependency changes that same source to `0xabcdef01`, the repeated copy supplies `0x01`.

7. **Sixteen-byte scaling.** With index three and no overflow, the retained field word is stored at `0x44`, not the ordinary indexed destination `0x20`.

8. **Discarded index bits.** Under 32-bit bit-vector left-shift behavior, `0xc0000001` shifted left two becomes `0x00000004`. The subsequent unsigned-right-two, left-sixteen transformation yields `0x00010000`.

9. **Late extraction.** A late word of `0xffc00000` contributes zero to the low-byte write and `0xff` to the right-22 byte write.

10. **Terminal ordering and failure.** If the pointer clear overlaps the upper source, assembly uses the source after that clear. If the later zero-address call fails, the preceding byte clear, shared-word update, and completed halfword clear are not visibly rolled back.
