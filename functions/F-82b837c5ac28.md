# F-82b837c5ac28

## Purpose

F-82b837c5ac28 updates a 32-bit field in a mutable object, conditionally invokes object-associated operations, and may calculate and store a bounded signed quantity.

The supplied static evidence establishes three phases:

1. Store the requested value and conditionally dispatch an operation based on a signed threshold comparison.
2. Inspect an object flag and associated-object pointer, optionally dispatch an associated-object operation, and then dispatch another operation on the primary object.
3. Inspect a separate flag and pointer gate; either return immediately or calculate a value through two dependencies and store a signed upper-bounded result.

The meanings of the fields are unknown. Interpretations such as position, range, extent, notification, or synchronization are inferred intent, not established behavior.

This contract describes only the supplied static evidence. No runtime tests have been performed.

## Behavior

### 1. Initial store and threshold dispatch

The function first writes the requested value to offset `0x104`.

It then reads the signed threshold at offset `0x0FC` and compares the original requested-value input against it. Equality satisfies the condition.

If the requested value is less than or equal to the threshold, the function invokes the primary object’s indirect dependency through dispatch-table byte offset `0x164`, passing the primary object as the explicit argument.

The initial store precedes this call. Consequently, the called operation can observe that store, subject to any additional behavior outside this evidence.

The comparison uses the original input, not a later reread of offset `0x104`. The dispatch may change object fields or other state; the function does not restore them afterward.

### 2. First flag and associated-object dispatches

After the threshold operation returns, or immediately if it was skipped, the function reads the flag word at offset `0x048` and tests bit `0x10`.

If the bit is clear:

- This phase does not read the associated-object pointer.
- Neither of this phase’s indirect dependencies is called.

If the bit is set, the function reads the associated-object pointer at offset `0x0EC`.

If that captured pointer is zero, neither indirect dependency in this phase is called.

If the captured pointer is nonzero:

1. When the control input is nonzero, invoke the indirect dependency selected through that associated object’s dispatch-table byte offset `0x16C`.
2. Invoke the primary object’s indirect dependency selected through dispatch-table byte offset `0x084`, explicitly passing the primary object.

The primary-object operation occurs whether the control input is zero or nonzero, provided the earlier flag and pointer checks admitted this phase.

The associated-object call has no explicit argument expression in the supplied evidence. An implicit receiver or other calling-convention detail is not established.

The decision to invoke the primary-object operation is based on the flag and pointer already captured. There is no intervening recheck after the optional associated-object operation. That operation may change the primary object’s flags or associated-object pointer without canceling the already-selected primary-object call.

The primary object’s dispatch table is obtained for its call after the optional associated-object operation. The evidence does not establish that an earlier dispatch-table value is retained across that operation.

### 3. Second flag gate and early returns

The function next reads the entire 32-bit word at offset `0x124`.

If bit `0x01` is clear, the function returns that captured word immediately. Other set bits are retained in the returned value. No calculation dependencies are called, and this function does not directly write offset `0x120`.

If bit `0x01` is set, the function reads the associated-object pointer at offset `0x0EC`.

- A zero pointer produces an immediate zero return.
- A nonzero pointer admits the calculation phase.

This gate is independent of the first flag word, the earlier associated-object snapshot, and the control input. Changes made by earlier indirect calls are visible to these later reads.

### 4. Captured arithmetic inputs

On the calculation path, the function captures these fields in order:

1. The 32-bit operand at offset `0x0D0`, treated as unsigned in the visible subtraction and eventual return.
2. The signed operand at offset `0x0D8`.
3. The signed requested-value field at offset `0x104`.
4. The signed baseline at offset `0x100`.

The value read at offset `0x104` need not equal the original requested-value input. Earlier indirect calls may have changed it.

The function then rereads the associated-object pointer at offset `0x0EC` and forms an address `0x80` bytes beyond it. That address is passed to F-b01436b9ce2b.

The pointer used for this address is a fresh read, not the pointer retained from the immediately preceding nonzero gate. No additional nonzero check is shown for the fresh read.

F-b01436b9ce2b returns a 32-bit value. Its interpretation is unknown.

### 5. Calculation, result writes, and return

The function calls F-870c4fcf7295 with:

- The difference between the captured operand from `0x0D8` and the captured operand from `0x0D0`.
- The 32-bit value returned by F-b01436b9ce2b.

For the first difference, the unsigned operand makes the visible subtraction a 32-bit unsigned calculation: the result is reduced modulo \(2^{32}\). The interpretation or conversion of that bit pattern at the dependency boundary is not established without the dependency’s interface.

The result from F-870c4fcf7295 is captured as a signed 32-bit quantity.

The function then:

1. Writes that result to offset `0x120`.
2. Computes the difference between the captured requested-value field and captured baseline.
3. If that signed difference is strictly less than the dependency result, overwrites offset `0x120` with the difference.
4. Returns the operand previously captured from offset `0x0D0` as an unsigned 32-bit value.

When the signed difference is representable, the final direct write leaves the smaller of that difference and the dependency result in the result field. This is an upper-bound operation only: there is no explicit lower bound or clamp to zero.

The two-write behavior matters independently of the eventual numeric result: the dependency result is written first, and a smaller limiting difference is written afterward. No atomicity or concurrent-observer guarantee is established.
