# F-e2303c7cb41c

## Purpose

F-e2303c7cb41c conditionally passes caller-supplied 32-bit values and calculated sizes to a dependency, then records four supplied values in an object and sets a one-byte marker.

Two object bytes select the dependency-call pattern. One pattern makes three calls using three separate supplied values; two other patterns make one call using the first supplied value. All remaining combinations skip that dependency but still perform the final object updates.

The dependency’s actual operation is unknown. The visible behavior does not establish whether it reads, writes, validates, registers, transfers, or releases the supplied values. Likewise, the final marker’s application-level meaning is not established.

## Behavior

### Initial conditional dependency

The function first reads the byte at object offset `0x41`.

- If it is zero, the function calls F-04dc4af298fc with the object address.
- If it is nonzero, that call is omitted.

There is no visible second check of this byte after the call. F-e2303c7cb41c does not itself write the byte.

The dependency may affect later behavior through object mutations: both selector reads occur after this optional call. Its return value, if any, is not visibly used. Normal continuation presumes that it returns.

### Selector sampling

After the optional initial call, the function reads the secondary selector at offset `0x0A`, then reads the primary selector at offset `0x08`.

The secondary selector is retained for the subsequent branch decisions. The visible function does not reread either selector after entering the size-dependent call sequence. Consequently, mutations made by later calls do not cause it to select a different call family.

The following patterns are mutually exclusive.

### Primary selector 5

If the primary selector is 5, both of these conditions are required for size-dependent calls:

1. The sampled secondary selector is zero.
2. Bit 31 of the first supplied value is clear.

If either condition fails, no call to F-a460a9009a02 occurs. The function proceeds to the final object updates.

If both conditions hold, three calls to F-a460a9009a02 occur in this order:

| Call | First argument | Second argument |
|---|---|---|
| First | First supplied value | Product of the two signed 32-bit size factors |
| Second | Second supplied value | Newly calculated product of the size factors, shifted right by two bits |
| Third | Third supplied value | Another newly calculated product of the size factors, shifted right by two bits |

The products are not visibly computed once and reused. The first call completes before the size factors for the second call are read. The second call completes before the factors for the third call are read.

Therefore, equal sizes for the second and third calls are guaranteed only under additional conditions, such as unchanged factors and well-defined arithmetic. A dependency that changes the factor fields can change subsequent call sizes.

Neither the second nor third supplied value receives the first value’s bit-31 check. The first value’s bit-31 condition gates the entire three-call sequence; it does not merely omit the first call.

### Primary selector other than 5

For every primary selector value other than 5, the secondary selector determines behavior:

| Secondary selector | Calls to F-a460a9009a02 |
|---|---|
| 2 | One call with the first supplied value and a size equal to the product of the two factors, then multiplied by 2 |
| 3 | One call with the first supplied value and a size equal to the product of the two factors, then multiplied by 4 |
| Any other value | No call |

The first supplied value’s bit 31 is not checked on these paths. A value with that bit set can therefore reach F-a460a9009a02 when the primary selector is not 5 and the secondary selector is 2 or 3.

The second, third, and fourth supplied values do not participate in these single-call paths.

### Arithmetic boundaries

The size factors are read as signed 32-bit integers. The visible expressions contain no widening conversion before multiplication.

Accordingly:

- The evidence does not establish a 64-bit intermediate.
- Multiplication by 2 or 4 is part of the size calculation, not an address-scaling operation established independently of that calculation.
- Right shift by two is not universally interchangeable with signed division by four.
- No negative-size, zero-size, overflow, or divisibility check is visible.

For nonnegative products representable in signed 32 bits, shifting right by two gives the integer quotient rounded down. There is no requirement that the product be divisible by four.

The supplied representation does not establish a portable overflow rule for signed multiplication or a definitive machine-level rule for shifting negative results. Those cases remain documented_only uncertainties rather than grounds to promise wrapping, saturation, rejection, or a particular negative result.

The relative order of the two factor loads within an individual product is not established here. What is established is the placement of each product calculation relative to the dependency calls.

### Final object updates

After the selected call sequence completes—or immediately after a branch that skips it—the function performs these direct writes in order:

1. Store the first supplied 32-bit value at offset `0x1C8`.
2. Store the second supplied 32-bit value at offset `0x1CC`.
3. Store the third supplied 32-bit value at offset `0x1D0`.
4. Store the fourth supplied 32-bit value at offset `0x1D4`.
5. Store the byte value 1 at offset `0x1BC`.

Every normally completing branch reaches these writes. Skipping the size-dependent calls does not skip recording the values or setting the marker.

These stores occur after all dependency calls made by this invocation. If a dependency previously changed one of these locations and returned normally, the corresponding final store overwrites that change.

The visible store order does not establish atomic publication, memory barriers, synchronization, or what a concurrent observer can safely infer from the marker.

## Side effects

The function’s direct writes are limited to four 32-bit stores and one byte store at the offsets listed above. Other effects may occur inside either dependency.

The visible function performs no direct allocation, deallocation, supplied-value dereference, or explicit transfer of ownership. However, the absence of those direct operations is not an ownership guarantee: F-a460a9009a02 receives the supplied values, and its effects are unknown.

No rollback is visible. If execution faults or a dependency does not return normally, the final records and marker are not guaranteed to be written. Effects already performed by an earlier dependency call are not visibly undone.

There is no checked status from either dependency. The function provides no explicit success or failure result. In particular, the final marker cannot be treated as proof that an unknown dependency achieved its intended operation.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, assume valid object accesses, normal dependency returns, representable nonnegative arithmetic, and no dependency mutations.

1. **Three-call path.**  
   With primary selector 5, secondary selector 0, factors 100 and 80, and bit 31 clear in the first supplied value, the calls use the first, second, and third supplied values in that order. Their sizes are 8000, 2000, and 2000. The four values are then recorded, followed by marker 1.

2. **High bit suppresses all three calls.**  
   With primary selector 5 and secondary selector 0, a first supplied value of `0x80000000` causes all F-a460a9009a02 calls to be skipped. The function still records all four supplied values and sets the marker.

3. **Secondary-selector mismatch suppresses the three-call family.**  
   With primary selector 5 and secondary selector 2, there are no size-dependent calls. This does not fall through to the doubled-size behavior, which requires a primary selector other than 5.

4. **Doubled-size path permits the high bit.**  
   With primary selector 4, secondary selector 2, factors 10 and 6, and first supplied value `0x80000000`, one call occurs with that value and size 120. The high bit does not suppress this branch.

5. **Quadrupled-size path.**  
   With primary selector 0, secondary selector 3, and factors 10 and 6, one call occurs with the first supplied value and size 240. All four supplied values are subsequently stored.

6. **Unrecognized secondary selector.**  
   With primary selector 4 and secondary selector 0, no F-a460a9009a02 call occurs. Final storage remains mandatory on normal completion.

7. **Non-divisible product.**  
   On the three-call path with unchanged factors 3 and 3, the sizes are 9, 2, and 2. No divisibility error is introduced by this function.

8. **Factor mutations between calls.**  
   On the three-call path, suppose the factors begin as 8 and 8. If the first dependency call changes them to 12 and 8, and the second changes them to 16 and 8, the sizes are respectively 64, 24, and 32. This illustrates the separate factor reads; it does not claim that the dependency actually performs such mutations.

9. **Initial dependency changes selection.**  
   If offset `0x41` initially contains zero, F-04dc4af298fc is called. If it returns after changing the selector bytes, the subsequent selection uses those changed bytes, not selector values from before the call.
