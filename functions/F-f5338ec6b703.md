# F-f5338ec6b703

## Purpose

F-f5338ec6b703 conditionally assigns a 32-bit value to each eligible element in a contiguous sequence. It searches two record collections in a supplied context, compares each record’s bounds against the element’s coordinate, and applies every matching record in traversal order.

A match writes a record-supplied value into the element and sets flag bits `0x30`. Matching does not stop either search. Consequently, later matches can overwrite earlier assignments; any match in the second collection takes precedence over all matches in the first collection.

The apparent intent is coordinate-based association with nearby records. The meanings of the coordinates, record values, marker bytes, and flags are not established. The contract below describes their observable treatment without assigning domain-specific names.

1. **Context**: storage containing collection counts, fixed-stride records, and matching controls.
2. **Sequence descriptor**: storage containing an element count and an address for the first element.

## Behavior

### Initial capture and sequence traversal

The function first reads the descriptor’s count and element address. These values drive the entire traversal; the descriptor is not reread between elements.

If the captured count is zero, the function returns without accessing an element or the context.

For a positive count, elements are visited in increasing address order, separated by `0x30` bytes. After each element, the remaining count is reduced by one and the working element address advances by `0x30`. The zero check occurs at the beginning of the next iteration.

### Eligibility

For each element:

1. Read the primary marker at `0x14`.
2. If that marker is neither `0x02` nor the character value `−2`, read the secondary marker at `0x15`.
3. Continue only if at least one examined marker has one of those two values.
4. For such a marker-qualified element, read its flags and continue only if bit `0x10` is clear.

The target-style byte representation of character value `−2` is `0xFE`; the signed-character interpretation is discussed under uncertainties.

The secondary marker is not read when the primary marker already qualifies. The flags eligibility test is not reached when neither marker qualifies.

An element rejected by these checks receives no explicit writes and causes neither collection to be searched.

For an eligible element, the coordinate at `0x24` is read once. Both collection searches use that captured coordinate, even if later writes alias its storage.

### First collection: forward search

The first collection count is read from context offset `0x000`. Records are visited from record zero upward.

For each visited record, define:

- \(x\): the captured element coordinate.
- \(a\): the record’s first bound.
- \(b\): the record’s second bound.
- \(t\): the tolerance read for this iteration.
- \(d = x-b\).
- \(L\): the additional distance limit, if its conditional read is reached.

The search terminates immediately when both conditions hold:

- \(d \le -t\);
- \(-d \ne t\).

When all arithmetic is representable, this is equivalent to \(d < -t\), or \(x < b-t\). Equality at the tolerance boundary does **not** terminate the search.

If the search does not terminate, the record matches when:

- \(x \le a+t\); and
- either the byte-sized mode interpretation is nonzero, or \(d \le L\).

The mode field is read only if the first-bound condition succeeds. The additional distance limit is read only if that condition succeeds and the mode interpretation is zero.

For every matching record, the function:

1. Reads the record’s assignment value.
2. Writes it to element offset `0x2C`.
3. Reads the element’s current flags.
4. Writes those flags ORed with `0x30` to offset `0x10`.

It then continues to the next record. Setting bit `0x10` during this search does not trigger another eligibility check and does not stop processing the current element.

### Second collection: reverse search

After the first search finishes or terminates early, the second collection count is read from context offset `0x204`.

For a positive count, traversal starts at the highest-indexed record and proceeds toward record zero. A zero count produces no record-body accesses.

For each visited record, use the same captured coordinate \(x\), with this collection’s bounds \(a\) and \(b\), and define:

- \(t\): the tolerance read for this iteration.
- \(d = a-x\).

The search terminates immediately when:

- \(d \le -t\); and
- \(-d \ne t\).

With representable arithmetic, this is equivalent to \(d < -t\), or \(a < x-t\). Equality does not terminate the search.

If it continues, the record matches when:

- \(b-t \le x\); and
- either the byte-sized mode interpretation is nonzero, or \(d < L\).

The second collection uses a **strict** distance-limit comparison. The first collection uses an inclusive comparison.

Conditional mode and distance-limit reads follow the same short-circuit structure as in the first search.

Every match writes the second collection’s assignment value and then updates flags exactly as described above. Reverse traversal continues after a match.

### Final assignment and precedence

For an eligible element:

- No matches: destination and flags remain explicitly unwritten.
- First-collection matches only: the highest-indexed matching record among those actually visited supplies the final value.
- Any second-collection matches: they supersede first-collection assignments.
- Multiple second-collection matches: the lowest-indexed matching record among those actually visited supplies the final value.

These rules apply to records reached before an early termination. A later record that would otherwise match is irrelevant if traversal stops before reaching it.

Each match sets both `0x10` and `0x20`. Other flag bits are preserved from the flags value read immediately before that match’s flag write.

## Side effects

The only explicit memory writes are to a matched element’s:

- 32-bit destination at `0x2C`;
- 32-bit flags at `0x10`.

The destination write precedes the flags read and flags write. This ordering matters if storage aliases.

The function does not explicitly modify the descriptor or context. Nevertheless, overlapping storage can make an element write modify either one.

Important read-timing consequences include:

- The descriptor count and element address are captured once.
- The element coordinate is captured once per eligible element.
- The first collection count is captured before its search.
- The second collection count is captured only after the first search.
- Tolerance is reread for every visited record.
- Mode and distance limit are conditionally reread for matching decisions.
- Record bounds and assignment values are read during traversal, not copied in advance.
- Flags are reread after each assignment write.

Thus, it is not justified to describe the entire context as a single immutable snapshot if aliasing or external mutation is possible.

There are no visible allocation, deallocation, ownership-transfer, I/O, locking, or callback operations. The function uses caller-provided storage without an explicit ownership change.

## Acceptance examples

These are conditional examples derived from static behavior, not runtime test results. Unless specified otherwise, storage is valid, arithmetic is representable, counts are nonnegative, and inputs do not alias.

### Empty sequence

Given a readable descriptor with count zero, the function reads the count and stored element address, then returns. It does not dereference that element address or read the context.

### Marker short-circuit

Given a primary marker of `0x02`, the secondary marker need not be read. If flag bit `0x10` is already set, neither collection is searched and the element remains unchanged.

Given a nonqualifying primary marker and qualifying secondary marker, the element proceeds to the flags eligibility check.

### First-search inclusive distance limit

Let the coordinate be 100, tolerance 10, and mode zero. Consider a first-collection record with first bound 95, second bound 97, and distance limit 3.

The difference is 3. Early termination does not occur; \(100 \le 105\), and \(3 \le 3\). The record matches.

If its assignment value is 77 and the original flags are `0x04`, that match writes 77 to the destination and produces flags `0x34`.

### Second-search strict distance limit

Let the coordinate be 100, tolerance 10, and mode zero. Consider a second-collection record with first bound 103 and second bound 105.

The difference is 3, and the bound condition succeeds because \(105-10 \le 100\).

- Distance limit 3: no match, because \(3 < 3\) is false.
- Distance limit 4: match, because \(3 < 4\) is true.

### Equality at the early-termination boundary

For a first-collection record, let the coordinate be 100, second bound 110, and tolerance 10. The difference is −10.

The search does not terminate: the negated difference equals the tolerance. If the remaining conditions succeed, this record can match.

Changing the second bound to 111 gives a difference of −11 and terminates that search before its assignment decision.

### Overwrite order

Suppose first-collection records zero and one both match, assigning 11 and 22. Suppose second-collection records zero and one also match, assigning 33 and 44.

The assignment order is 11, 22, 44, 33. The final destination is 33, and both flag bits `0x30` are set.

### Byte-sized mode

Under byte-truncating character conversion, mode `0x00000100` takes the zero-mode path; mode `0x00000101` bypasses the distance-limit comparison. The other bound and early-termination conditions still apply.
