## Behavior

### 1. Initial calls, indexed store, and retained load

The function first calls the target formed from the incoming link-register value plus hexadecimal `FFE`. No explicit arguments or consumed return value are shown.

It then invokes a second target and uses that call’s result as I.

The next explicit memory operation stores the incoming r7 payload as four bytes at:

**4 × I + hexadecimal 14**

This is an address calculation, not a store into an established object or array. No object base, bounds, or ownership relationship is provided.

After that store, the function reads four bytes from:

**incoming r5 + hexadecimal 14**

The loaded value becomes W. The ordering is significant: if the store and load overlap, the load observes memory after the store, subject to the platform’s access semantics.

The third call receives **4 × I** as its one explicit argument. Four further calls follow; the last of these supplies the 64-bit result divided into H and L.

The supplied representation retains W for subsequent computation. It does not show another load of W’s original source address.

### 2. First selector-based byte store

After the seventh call returns, the function:

1. Reads one byte at **incoming r6 + 1**.
2. Interprets that byte as an unsigned selector.
3. Adds hexadecimal `11` to the selector to form a destination address.
4. Stores the low eight bits of W at that address.

The destination range is therefore hexadecimal `11` through hexadecimal `110`, inclusive. The selected byte is used directly in address formation; it is not shown as an index into a separately based table.

The selector is read at this point, after the intervening dependency calls. It is not captured at function entry. Changes made by earlier calls can therefore affect this read.

### 3. Wide-result arguments and intermediate calls

The eighth call receives four explicit arguments, in order:

1. H.
2. H.
3. H.
4. L shifted left by two bits as a 32-bit unsigned quantity.

Bits shifted beyond the 32-bit width do not remain in the fourth argument. The repeated H arguments are identical bit patterns; no interpretation of H as a pointer, count, or status is established.

The ninth call supplies a four-byte result that becomes the single explicit argument to the tenth call.

Four more calls follow. The fourteenth call supplies J.

### 4. Second selector-based byte store

Before J is passed onward, the function derives another selector address from L:

**((L AND hexadecimal 3FFFFFFF) shifted right by 21) + 1**

The mask discards L’s two most significant bits. The shift retains the nine bits originally occupying positions 21 through 29. Consequently, this selector-load address lies between hexadecimal `1` and hexadecimal `200`, inclusive.

The function reads one unsigned byte at that address, adds hexadecimal `11` to its value, and stores one byte at the resulting destination.

The stored byte is:

**the low eight bits of W shifted right by 22**

Equivalently, it contains W’s original bits 22 through 29. W’s original top two bits are not part of this byte.

This is a new selector read. It is not interchangeable with the selector read used for the first byte store. Its timing permits it to observe earlier explicit writes or dependency effects.

The fifteenth call then receives J shifted left by two bits.

### 5. Remaining ordinary call sequence

Three calls with no explicit arguments follow. The nineteenth call supplies K.

The twentieth call receives two explicit arguments, both equal to K shifted left by two bits.

The twenty-first call has no explicit arguments. The twenty-second supplies a four-byte result, which is passed as the single explicit argument to the twenty-third.

The twenty-fourth call supplies a result that is assigned to the externally visible supervisor-call slot.

These are ordered, distinct call events. The evidence does not establish that their target functions are distinct, that any is pure, or that any preserves global state.

### 6. Final stores and address-zero call

After assigning the supervisor-call slot, the function performs these operations in order:

1. Stores a zero byte through Q.
2. Stores a zero halfword at **(L AND hexadecimal 3FFFFFFF) shifted right by 7**.
3. Attempts an indirect call through address zero, supplying three explicit zero arguments.
4. Returns if that call returns.

The halfword-store address ranges from zero through hexadecimal `7FFFFF`. The address is not scaled by the halfword width and is not explicitly aligned. Odd addresses are possible.

No check tests Q, the halfword destination, or the final call target before use.

## Acceptance examples

### Initial store affects the retained load

Suppose I is 8 and incoming r5 is hexadecimal `20`. The initial store and the load producing W both address hexadecimal `34`.

The load must occur after the four-byte store. Under ordinary readable/writable memory semantics, W therefore receives the just-stored four-byte payload.

### First selector destination

Suppose W is hexadecimal `89ABCDEF`, and the byte read at incoming r6 plus one is hexadecimal `20`.

The first selector-based store writes hexadecimal `EF` to address hexadecimal `31`. It does not write W in full and does not multiply the selector by an element size.

### Second selector and later halfword destination

Suppose L is hexadecimal `00400080`, W is hexadecimal `2AC00000`, and the byte read at address `3` is hexadecimal `40`.

Then:

- The second selector-load address is `3`.
- The second byte-store destination is hexadecimal `51`.
- The stored byte is hexadecimal `AB`.
- The later zero-halfword destination is hexadecimal `8001`.

The final destination is odd. Successful execution of that store remains conditional on the platform permitting it.

### Unsigned argument truncation

Suppose L is hexadecimal `C0000001`.

The eighth call’s fourth argument is hexadecimal `00000004`, because the left shift is 32-bit unsigned arithmetic. The two high bits do not survive.

The later masked address calculations use only the low 30 bits, yielding a second selector-load address of `1` and a final halfword-store address of zero.

### Repeated byte destination

If both selector reads produce hexadecimal `20`, both selector-based stores target hexadecimal `31`.

The second store occurs later and writes W bits 22–29. Subject to intervening effects, that byte replaces the first store’s W bits 0–7.

If the final address-zero call fails, no normal return is established. The contract does not reinterpret that call as a successful no-op.
