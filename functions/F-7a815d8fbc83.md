# F-7a815d8fbc83

## Purpose

F-7a815d8fbc83 has two substantially different behaviors, selected through a dynamically dispatched query on an acquired object:

- If the query returns nonzero, it invokes three buffer-writing dependencies, advances a one-byte buffer cursor by a nominal total of eight bytes, and returns the 32-bit value zero.
- Otherwise, it inspects another dynamically obtained object and conditionally updates persistent state in the first argument. This path ends by invoking F-feee9156a257, which the supplied static evidence marks as non-returning.

The stateful path appears intended to defer acceptance of a changed value until a comparison against a derived two-word threshold succeeds. That interpretation is inferred intent, not an established meaning for the stored fields or comparison result.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

### Arguments

The function accepts two arguments:

| Argument | Representation | Observed use |
|---|---|---|
| State address | 32-bit address-like value | Base address for fields at offsets `0x2dc` through `0x2eb` on the stateful path. |
| Buffer address | Pointer to bytes | First byte is read and rewritten as an unsigned 8-bit cursor on the returning path. Dependency destinations are computed relative to this address. |

There is no explicit buffer-capacity argument and no explicit state-object size argument.

The state address is not directly dereferenced on the returning buffer path. The buffer address is not directly dereferenced on the stateful path. This branch-local behavior does not establish what dependencies may access indirectly.

### State layout

The following fields are directly accessed:

| Offset | Width | Behavior |
|---|---:|---|
| `0x2dc` | 32 bits | Stored comparison value; may receive `0xffffffff` or a newly obtained 32-bit value. |
| `0x2e0` | 8 bits | Pending-state flag. Zero and nonzero are distinguished; writes use zero or one. |
| `0x2e4` | 32 bits | First word of a stored two-word value. |
| `0x2e8` | 32 bits | Second word of that stored value. |

Bytes between the flag and the next word are not directly written by the function.

### Return and termination

The only explicit normal return is the 32-bit value zero, after the three buffer-helper calls.

Two dependency calls are marked non-returning in the supplied evidence:

- F-a817d8d58c10, reached if initial object acquisition returns null.
- F-feee9156a257, reached at the end of the stateful path.

The evidence does not identify whether these dependencies terminate execution, throw, transfer control, or use another nonlocal mechanism. If either unexpectedly returns, subsequent behavior is not established as a supported interface.

### Preconditions

For defined execution of the selected path:

- Every directly accessed address must be valid for its access width.
- Dynamically returned objects must support the table entries used below.
- The stateful path requires a usable secondary object; no null check precedes its first dispatch.
- Buffer storage must cover the actual accesses performed by the writing dependencies, including destinations produced after 8-bit cursor wraparound.
- Arithmetic and the adjustment loop must have meaningful target-platform behavior. The supplied representation does not establish a portable signed-overflow policy.

No validation enforces these preconditions.

## Behavior

### 1. Acquire the primary object

The function first calls F-b7af80e829ec without explicit arguments.

If the result is null, it invokes F-a817d8d58c10. No direct access to either caller-supplied argument precedes this invocation.

For a non-null result, the function dynamically invokes the primary object’s table entry at byte offset `0x120`, passing the primary object.

### 2. Nonzero query: buffer-writing path

A nonzero result selects this path.

The first buffer byte acts as a cursor. Each direct cursor update is stored in eight bits, so additions wrap modulo 256.

The observable sequence is:

1. Read the cursor and compute a destination one byte beyond that cursor position.
2. Invoke F-b9d9c0b9bfab with that destination and the 32-bit bit pattern `0xffffffff`.
3. Read the cursor again, add four, and store the low eight bits back to the cursor.
4. Invoke F-3a7a47316439 with a destination one byte beyond the newly computed, eight-bit cursor and the value zero.
5. Read the cursor again, add two, and store the low eight bits.
6. Invoke F-3a7a47316439 with a destination one byte beyond this newly computed, eight-bit cursor and the value `0xffff`.
7. Read the cursor again, add two, and store the low eight bits.
8. Return the 32-bit value zero.

The rereads matter. A writing dependency is not assumed to preserve the cursor, other buffer bytes, global state, or caller state. In particular:

- The first cursor increment uses the byte observed after F-b9d9c0b9bfab returns.
- The next increment uses the byte observed after the first F-3a7a47316439 call returns.
- The final increment uses the byte observed after the second F-3a7a47316439 call returns.

Each of the two later helper destinations uses the narrowed cursor value calculated immediately before its call. It is not independently recomputed from another cursor read.

If the helpers preserve the cursor byte, the final cursor is the original cursor plus eight, modulo 256. That outcome is conditional, not an unconditional guarantee.

The constants and cursor advances suggest a four-byte item followed by two two-byte items. The actual write widths, byte order, encoding, and possible additional writes belong to the dependencies and are not established here.

There is no explicit capacity check or rejection of wraparound. A wrapped destination can point back toward the beginning of the buffer.

### 3. Zero query: obtain the secondary object

A zero result from the initial query selects the stateful path.

The function:

1. Invokes the primary object’s table entry at `0xe0`, passing the primary object.
2. Passes its 32-bit result, together with the primary object, to table entry `0xf4`.
3. Treats the result as the secondary object.
4. Invokes the secondary object’s table entry at `0x08`.

The supplied representation shows no explicit argument to the last invocation. A hidden receiver or calling-convention detail is not established.

If that last result is zero, the function writes `0xffffffff` to state offset `0x2dc`. It does not directly clear the pending flag or either stored word in this branch.

If the result is nonzero, processing continues as follows.

### 4. Determine whether a changed value needs processing

The function invokes the secondary object’s table entry at `0x138`, again with no explicit argument shown.

If its result is zero, no further direct state-field access occurs before the final F-feee9156a257 call.

If its result is nonzero:

1. Invoke primary-object table entry `0xf8`, passing the primary object.
2. Invoke secondary-object table entry `0x144`, passing the secondary object and the preceding result.
3. Compare the returned 32-bit value with the word at state offset `0x2dc`.

If the two values match, no direct state update follows.

If they differ, read the byte at offset `0x2e0` and choose one of the following pending-state cases.

### 5. Changed value with a zero pending flag

The function creates a temporary object through F-abdfc193d880. It then invokes that temporary object’s table entry at `0x0c`, passing:

- The address of the temporary object.
- The address of the state’s two-word region beginning at `0x2e4`.

After that invocation returns, the function directly writes one to the pending flag at `0x2e0`.

It then calls F-ec22bd8215d3 with the temporary object’s address.

This branch does not directly write the newly obtained comparison value to `0x2dc`. It establishes pending state first. The exact writes performed through the two-word destination are dependency-defined; the destination alone does not prove that both words are initialized.

### 6. Changed value with a nonzero pending flag

This branch creates another temporary object through F-abdfc193d880.

It next reads a 32-bit global parameter, called **A** here, and retains that value. It then invokes the temporary object’s table entry at `0x0c`, passing the temporary object’s address and an eight-byte temporary destination.

Only after that invocation does it read the two stored state words.

A candidate two-word value is derived as follows:

- The second candidate word starts as the stored second word plus A.
- The first candidate word starts from the stored first word but is incremented before every loop-condition evaluation, including the first evaluation.
- The condition compares the second candidate word against A minus one-half of another 32-bit global parameter, called **B** here.
- While that threshold is less than or equal to the second candidate word, the second candidate word is advanced by B and the condition is evaluated again.

The half operation is represented as a signed right shift by one. The comparison is represented as signed. The supplied evidence does not establish numeric values for A or B.

B is referenced again for condition evaluation and loop advancement; it is not represented as one captured value. A is captured before the temporary object’s `0x0c` invocation. Consequently, changes to A during that invocation do not change the captured A, while later reads of B may observe a different value.

If B remains constant, arithmetic does not overflow, and the loop performs exactly *n* advances of the second candidate word, the candidate is:

- First word: stored first word plus *n* plus one.
- Second word: stored second word plus A plus *n* times B.

Thus, even when the initial condition is false, the first candidate word has already been incremented once.

The function passes the eight-byte temporary destination first, and the derived two-word candidate second, to F-07039e49888b.

If its result is zero, this branch makes no direct update to the persistent fields.

If its result is nonzero, direct writes occur in this order:

1. Write zero to the pending flag at `0x2e0`.
2. Write zero to the first stored word at `0x2e4`.
3. Write the previously obtained changed value to `0x2dc`.
4. Write zero to the second stored word at `0x2e8`.

These are separate writes, not an atomic state transition.

The temporary object is then passed to F-ec22bd8215d3 regardless of whether the comparison result was zero or nonzero.

### 7. Final stateful-path transfer

Every normally completed stateful branch invokes F-feee9156a257 with the secondary object.

No explicit normal return follows this call. In the pending branches, temporary-object processing through F-ec22bd8215d3 precedes this final invocation.

## Side effects

Direct side effects are limited to:

- Three possible writes to the buffer’s cursor byte.
- A possible `0xffffffff` write to state offset `0x2dc`.
- Setting the pending flag to one after the first pending-state capture.
- Clearing the pending flag and stored words, and committing a changed value, after a nonzero comparison result.

Additional effects may occur through any dependency or dynamic dispatch.

Ownership is not established:

- Acquiring an object does not prove ownership transfer.
- Passing the secondary object to F-feee9156a257 does not prove release.
- Passing a temporary object to F-ec22bd8215d3 suggests lifecycle handling but does not prove destruction or memory release.
- Dependencies receiving addresses may retain or modify them unless their separate contracts prohibit that behavior.

No direct allocation, explicit locking, rollback, or error-status propagation is visible. Intermediate state is observable if dependencies, callbacks, or concurrent execution can access it; synchronization requirements are undocumented.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

### Buffer path without cursor mutation by helpers

Given an initial cursor of 10, a nonzero initial query, and helpers that preserve the cursor:

- F-b9d9c0b9bfab receives buffer offset 11.
- The first F-3a7a47316439 call receives offset 15 and zero.
- The second receives offset 17 and `0xffff`.
- The final cursor is 18.
- The function returns zero.

The bytes written at those destinations cannot be specified without the helper contracts.

### Buffer cursor wraparound

Given an initial cursor of 254 and helpers that preserve it:

- The first helper destination is offset 255.
- Adding four narrows the cursor to 2; the next destination is offset 3.
- Adding two produces cursor 4; the third destination is offset 5.
- The final cursor is 6.

No overflow error is directly reported.

### First observation of a changed value

Given successful stateful queries, a value unequal to the stored comparison word, and a zero pending flag:

- The capture dispatch receives the stored two-word region as its destination.
- The pending flag is set to one after capture returns.
- The changed value is not directly committed during this branch.
- Temporary processing precedes the final non-returning dependency call.

### Pending comparison rejects commitment

Given a changed value, a nonzero pending flag, terminating candidate arithmetic, and a zero result from F-07039e49888b, no direct clearing or commitment occurs. Dependency-induced mutations remain possible.

### Pending comparison permits commitment

Under the same conditions but with a nonzero comparison result, the direct write order is flag clear, first-word clear, changed-value commit, second-word clear.

### Initial secondary query returns zero

The stored comparison word becomes `0xffffffff`. The function does not directly reset an already nonzero pending flag or clear either stored word.
