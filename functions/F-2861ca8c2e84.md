# F-2861ca8c2e84

## Purpose

The established behavior is a sequence of low-level state transfers. It includes a 16-bit store at an address derived by doubling one incoming value, two 32-bit reads at byte offset 100 from different bases, and two subsequent stores using the values obtained by those reads.

The higher-level purpose is unknown. The offsets and cross-references could belong to structured state, but the available evidence does not establish a data structure, resource type, ownership model, or application-level operation. Such interpretations are not part of this contract.

## Behavior

### Ordered memory effects

The following order is established by the supplied static representation. Offsets are byte offsets.

1. **Store the first explicit input through a doubled address.**  
   The function stores 16 bits at the address obtained by multiplying A by two. This is not a store at A plus two, nor an access to a field two bytes into A.

2. **Read a first 32-bit value.**  
   The function reads four bytes at A plus 100. Call the captured value X. This read occurs after the preceding 16-bit store, so overlapping storage can affect X.

3. **Store the incoming byte.**  
   The function stores S at B plus 17.

4. **Store the constant 100.**  
   The function stores the 32-bit numeric value 100 at B plus 84. This is decimal 100, not hexadecimal 100. It is distinct from the address offset 84 used for this store.

5. **Read a forwarded 32-bit value.**  
   The function reads four bytes at A plus 116. Call the captured value Q. This read occurs after both stores through B.

6. **Read a second address-bearing value.**  
   The function reads four bytes at C plus 100. Call the captured value Y.

7. **Store the low byte of A.**  
   The function stores the low eight bits of A at C plus 9. This is a truncation of A itself, not a byte read from memory at A.

8. **Store X through an address derived from Y.**  
   The function stores the captured 32-bit value X at Y plus 84.

9. **Store Y through a doubled address derived from X.**  
   The function stores the captured 32-bit value Y at the address obtained by multiplying X by two.

10. **Invoke the indirect dependency.**  
    The function invokes T with the four arguments described below.

11. **Return if control returns normally.**  
    No additional explicit memory access or result construction appears after the invocation.

The function therefore contains six explicit stores and three explicit reads before the indirect invocation. This count excludes any activity performed by the dependency and any instruction-fetch or calling-convention activity not represented in the supplied material.

### Captured values and aliasing

X, Q, and Y are values captured at their respective reads. Subsequent writes do not cause them to be read again.

This distinction is observable when addresses overlap:

- The initial 16-bit store can affect the later read of X.
- The stores at B plus 17 and B plus 84 can affect the later reads of Q or Y.
- The store at C plus 9 occurs after Y has been captured. Even if it overlaps the storage from which Y was read, the remaining operations use the captured Y.
- The store at Y plus 84 can overlap the destination at twice X. If so, the later store of Y determines the final bytes in the overlapping region.
- Q is read before the last three stores. The dependency receives the captured Q even if those stores change its original memory location.

No snapshot, atomic transaction, or isolation from concurrent changes is established. This sequence specifies the visible ordering in the supplied representation; it does not establish a platform memory-ordering guarantee for concurrent observers.
