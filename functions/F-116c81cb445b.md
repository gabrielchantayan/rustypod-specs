# F-116c81cb445b

## Purpose

F-116c81cb445b invokes F-731e7d75327a once, optionally publishes that dependency’s 32-bit result through two output destinations, and returns a 64-bit value whose upper half contains a previously captured shared value and whose lower half is zero.

The optional one-byte output distinguishes a dependency result of zero from every nonzero result:

- Result zero produces byte value 1.
- Any nonzero result produces byte value 0.

The optional four-byte output receives the dependency result without transformation.

The returned value does not encode the dependency result. It encodes the shared value captured before the dependency invocation. Any business meaning for that shared value, the dependency result, or the one-byte indicator is unknown.

This contract describes behavior established by the supplied static representation. It does not establish runtime correctness or the behavior of the dependency.

## Behavior

The function first obtains the shared value and retains its unsigned 32-bit value for constructing the eventual return.

This capture precedes the dependency invocation. A change to the shared datum during that invocation does not cause the function to refresh its captured return component.

The first argument has no visible role in this capture or in any subsequent operation.

### 2. Invoke the dependency

F-731e7d75327a is invoked exactly once on the displayed normal path, with seven arguments in this order:

1. The function’s second argument.
2. The function’s third argument.
3. The function’s fourth argument.
4. The function’s fifth argument.
5. The shared datum obtained for this call.

The two trailing constants are established values, but their meanings and the dependency’s formal parameter widths are not available.

The dependency’s returned value is retained as an unsigned 32-bit result. All later indicator decisions and the optional four-byte output use that retained result. The function does not invoke the dependency again to obtain either output.

The dependency call occurs even when both output destinations are null.

### 3. Write the optional indicator

After the dependency returns normally, the function examines the indicator destination.

If it is null, no indicator write occurs.

If it is non-null, exactly one byte is written:

| Unsigned 32-bit dependency result | Written byte |
|---|---|
| 0 | 1 |
| 1 | 0 |
| 2 through 4,294,967,295 | 0 |

The static representation contains a byte-sized intermediate calculation and an unsigned comparison against 1. Their combined observable result is the table above. In particular, the indicator is not a test of only the result’s low byte. A result such as 256 still produces 0, not 1.

The previous contents of the destination are not read by this function before the write.

### 4. Write the optional full result

After the indicator step, the function examines the result destination.

If it is null, no full-result write occurs.

If it is non-null, the function writes the retained unsigned 32-bit dependency result to that destination. The value is neither clamped nor converted to the indicator.

The previous contents of this destination are not read by this function before the write.

### 5. Return the captured shared value

After the optional writes, the function returns the 64-bit value assembled from the initially captured shared value.

On normal completion:

- The dependency result does not contribute to the return bits.
- The output destinations’ prior contents do not contribute to the return bits.
- Selecting or omitting either output does not suppress the dependency call.
- No later access to the shared datum is displayed for return construction.

### Ordering, overlap, and interruption

The established source-level order is:

1. Initial shared-value capture.
2. Shared-value access for the dependency argument.
3. Dependency invocation and normal return.
4. Optional one-byte write.
5. Optional four-byte write.
6. Function return.

This is not a claim of atomicity, synchronization, or visibility ordering for unsynchronized concurrent observers.

The output regions are not required to be disjoint by any visible check. If they overlap, the four-byte write occurs after the one-byte write and overwrites any common bytes. The final value observable through the indicator address may therefore differ from the initially written indicator. Which byte of the full result occupies a particular address depends on the target’s object representation and byte order.

If the dependency does not return normally, the displayed function does not reach either output write or its normal return. Likewise, if the indicator write fails, the later result write is not established to occur. No rollback or recovery path is shown.
