# F-9e3e749b154b

## Purpose

F-9e3e749b154b coordinates a context lookup, a three-argument dependency call, a two-argument dependency call, and conditional copying of a 16-bit field into a context field.

Its 32-bit return value comes from F-a3c410f12096. After obtaining that value, the function may invoke another dependency and may write a context field before returning. Those later actions do not supply a replacement return value.

The established behavior is orchestration and conditional field propagation. The meanings of the subject, mode, context, and fields are not established. Describing the operation as initialization, registration, synchronization, or resource management would be inferred intent, not a supported semantic contract.

## Behavior

After that call returns, it calls F-3e5212464798 with three arguments, in this order:

3. A 32-bit zero value.

Next, it calls F-a3c410f12096 with the original subject address and the original mode value. Its 32-bit result is retained for the eventual return.

### Optional call for nonzero mode

This call occurs after F-a3c410f12096 returns and before the subject field is examined. Its result, if any, is not used.

### Conditional field propagation

After the optional call, the function reads the 16-bit subject field at offset `0xF2` and tests it against zero.

This read precedes the mode test within the propagation condition. Consequently:

- A zero subject field prevents further context lookups for propagation.
- A nonzero subject field with zero mode also prevents those lookups.
- Zero mode does not bypass the initial subject-field read.

If the subject field is nonzero and the mode is nonzero, the function calls F-fdd8589eca2d again. It reads the 16-bit field at offset `0x80` from the context address returned by this call.

If that context field is nonzero, propagation stops. There is no explicit write by F-9e3e749b154b on this path.

If that context field is zero, the function calls F-fdd8589eca2d one more time. It then reads the subject field again and writes that 16-bit value to offset `0x80` in the context returned by this final lookup.

Two distinctions are essential:

- **The checked context and written context need not be the same.** They come from separate dependency calls.
- **The copied subject value need not be the value that passed the initial nonzero test.** The source is read again after the final lookup.

There is no second nonzero test of the source and no zero test of the final destination. Thus a completed copy can write zero, and it can overwrite a nonzero field in the final context.

### Completion

After the conditional work, the function returns the retained result from F-a3c410f12096.

There is no retry, loop, explicit rollback, or explicit cleanup. Normal completion depends on every reached call and memory access completing normally.

## Side effects

The function has one explicit memory-write operation: the conditional 16-bit store to a context field at offset `0x80`.

Its explicit field-access order is:

1. Read the subject field after the initial dependency sequence and optional nonzero-mode call.
2. If eligible, obtain a context and read its field.
3. If that field is zero, obtain another context.
4. Read the subject field again.
5. Write the copied value into the final context field.
