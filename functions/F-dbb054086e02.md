# F-dbb054086e02

## Purpose

F-dbb054086e02 derives a 32-bit quantity from its five inputs, passes that quantity and an unsigned maximum to F-d7be9cfb4000, and returns a wrapped product with a nonzero fallback rule.

Two derivation paths are established:

- A direct arithmetic path for a small third input when the fourth input is zero.
- A table-selection path for every other case. This path selects one of fifteen rows and one of two 16-bit entries within that row.

The broader meaning of the quantities, the table, and the dependency’s result is not established. Interpreting this function as a particular sizing, timing, allocation, or rate-selection operation would exceed the available evidence.

## Interface

### Inputs

The function has five inputs, in order:

| Position | Observed representation | Established role |
|---|---|---|
| First | Unsigned 32-bit integer | Compared with the second input; their unsigned maximum becomes the second dependency argument and the final multiplication factor. |
| Second | Unsigned 32-bit integer | Supplies the other operand of that maximum and independently contributes to the direct-path quantity. |
| Third | Unsigned 32-bit integer | Supplies the direct-path quantity or the lower word of the table-index calculation. |
| Fourth | Unsigned 32-bit integer | Selects against the direct path when nonzero and supplies the upper word of the table-index calculation. |
| Fifth | Signed 32-bit integer | Selects the second table entry when zero and the first table entry when nonzero. Unused on the direct path. |

All unsigned comparisons use the full 32-bit values. In particular, a first or second input with its top bit set is not treated as negative.

The fifth input is a zero/nonzero selector, not a bounded enumeration. Negative values select the same entry as positive nonzero values.

### Output

The output is one unsigned 32-bit integer.

Let the **effective factor** mean the unsigned maximum of the first and second inputs. After the dependency returns, the function multiplies that factor by the dependency’s 32-bit return representation, retaining only the low 32 bits.

- If the retained product is nonzero, it is returned.
- If the retained product is zero, the effective factor is returned instead.

The dependency result is represented as a signed 32-bit integer in the supplied material, but the multiplication uses its 32-bit bit pattern under unsigned arithmetic. A negative result is therefore not rejected or clamped.

### Memory and validity requirements

None of the five inputs is used directly as a pointer.

The table-selection path requires a readable table base and a readable selected 16-bit entry at the computed address. The function contains no visible validation of that storage.

Successful completion also requires F-d7be9cfb4000 to return normally. Its own preconditions and failure behavior are not supplied.

## Behavior

### Arithmetic conventions

The contract uses these widths:

- Ordinary unsigned values and arithmetic results: 32 bits.
- Table entries: unsigned 16 bits.
- The loop counter and the observed dependency result: signed 32 bits.
- A mathematical 64-bit combination of the third and fourth inputs: used below to describe the index calculation, not to claim a particular machine instruction or calling convention.

Unsigned 32-bit shifts and multiplication discard bits outside the 32-bit result. No saturation is present.

### Effective factor

The function first selects the unsigned maximum of the first and second inputs.

This selection affects the second dependency argument and final multiplication. It does **not** replace the second input in the direct-path scaling calculation. That distinction is observable when the first input exceeds the second.

### Direct arithmetic path

This path is selected exactly when:

- The fourth input is zero; and
- The third input is strictly less than 2,097,152, or \(2^{21}\).

The derived quantity is the unsigned maximum of:

1. Four times the third input.
2. The low 32 bits of eight times the second input.

The first candidate cannot overflow: the branch condition limits it to at most 8,388,604.

The second candidate can overflow. Its wrapping occurs before the comparison. Consequently, this path does not necessarily enforce a mathematical lower bound of eight times the second input.

The comparison is unsigned and selects the larger retained 32-bit value. Equality leaves the same resulting value regardless of which candidate is considered selected.

This path does not read the table. The fifth input has no effect on its local calculation.

### Table-selection path

This path is selected when either:

- The fourth input is nonzero; or
- The third input is at least \(2^{21}\).

For describing the index, define the nonnegative mathematical quantity

\[
X = 2^{32}\times\text{fourth input}+\text{third input}.
\]

The observed shifts form the two-word representation of \(\lfloor X/2^{22}\rfloor\). The function then counts right shifts until that representation becomes zero, stopping after at most fourteen shifts.

Equivalently, the row index is:

\[
\min\!\left(14,\operatorname{bitlength}\!\left(\left\lfloor X/2^{22}\right\rfloor\right)\right),
\]

where the bit length of zero is defined as zero.

The signed comparison machinery in the supplied material does not introduce an additional index range: the counter starts at zero and stops no later than fourteen.

The resulting row boundaries are:

| Row | Values of \(X\) on this path |
|---|---|
| 0 | \(2^{21}\) through \(2^{22}-1\) |
| 1 through 13 | For row \(r\), \(2^{r+21}\) through \(2^{r+22}-1\) |
| 14 | \(2^{35}\) through \(2^{64}-1\) |

Thus row 14 is a capped bucket for every sufficiently large combined input. The function does not continue counting to distinguish larger magnitudes.

### Table layout and entry selection

The table has an observed row stride of four bytes. Each reachable row contains two selectable unsigned 16-bit entries:

| Fifth input | Selected byte offset within the row |
|---|---|
| Zero | 2 |
| Any nonzero value | 0 |

The function performs one selected 16-bit entry read. There is no visible requirement to read both entries.

Supporting every input on this path requires fifteen accessible rows: offsets 0 through 59 from the table base. An individual invocation needs only its selected entry to be readable.

The loaded entry is zero-extended to 32 bits and shifted left by twenty bits, retaining only the low 32 bits. Therefore:

\[
\text{derived quantity}
=
(\text{entry}\bmod 4096)\times 2^{20}.
\]

The entry’s upper four bits do not affect the derived quantity. A nonzero table entry can produce zero; for example, an entry of 4096 does so. The largest possible derived quantity is hexadecimal FFF00000.

The table’s byte order is not independently established. The contract specifies the observed unsigned 16-bit load at the selected byte offset, rather than imposing an external serialized byte order.

### Dependency call and final result

After deriving the quantity by exactly one path, the function calls F-d7be9cfb4000 exactly once on a normally progressing invocation.

The arguments, in order, are:

1. The derived 32-bit quantity.
2. The effective factor.

No original third, fourth, or fifth input is separately forwarded.

If the dependency returns normally, its result is multiplied by the effective factor modulo \(2^{32}\). The zero-product fallback is then applied.

This fallback tests the product, not the dependency result. It therefore applies both when the dependency returns zero and when a nonzero result produces a wrapped zero product.

Consequences include:

- An effective factor of zero always produces a final result of zero, provided the dependency returns.
- A nonzero effective factor always produces a nonzero final result on normal completion.
- A nonzero dependency result does not guarantee that the wrapped product is returned.
- The dependency is still called when the effective factor is zero.

## Side effects

The supplied body establishes the following ordering:

1. Compute the effective factor and choose a derivation path.
2. On the table path, obtain the table base and read the selected entry.
3. Call F-d7be9cfb4000 with the derived quantity and effective factor.
4. On normal return, compute and return the final result.

The wrapper contains no visible memory stores, allocation requests, release operations, or writes through caller-provided pointers. Its input changes are confined to local computation.

That observation does not make the whole call side-effect-free. F-d7be9cfb4000 may read or modify memory, alter global state, acquire resources, release resources, or fail to return; none of those properties is resolved here.

The table read precedes the dependency call. No table read or table-base reload is visible after the dependency returns. A dependency-induced table change therefore does not cause this invocation to recompute its already-derived quantity.

Ownership of the table and any resources used by the dependency is unknown. No ownership transfer is established by this interface.

There is no visible error-status channel or explicit invalid-input return. The zero-product fallback is ordinary result construction, not an established error indication.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied static evidence. They are not runtime test results.

1. **The original second input controls the direct-path floor.**  
   With inputs 100, 3, 1, 0, and any fifth input, the effective factor is 100. The direct candidates are 4 and 24. The dependency must receive 24 and 100, in that order—not 800 and 100. If it returns 2, the final result must be 200.

2. **The direct-path upper boundary is exclusive.**  
   With first and second inputs both zero, third input \(2^{21}-1\), and fourth input zero, the direct path derives 8,388,604. Increasing the third input to \(2^{21}\) selects table row 0 instead.

3. **The direct-path floor wraps before comparison.**  
   With the second input equal to hexadecimal 20000000, third input 1, and fourth input zero, eight times the second input wraps to zero. The derived quantity must therefore be 4, not a saturated value.

4. **A row transition occurs at \(2^{22}\).**  
   With the fourth input zero, a third input of \(2^{22}-1\) selects row 0. A third input of \(2^{22}\) selects row 1.

5. **The fourth input contributes as the upper word.**  
   With third input zero and fourth input 1, \(X=2^{32}\), so row 11 is selected. With fourth input 8, \(X=2^{35}\), so row 14 is selected. Larger combined values remain capped at row 14.

6. **Zero and nonzero selectors choose different halfwords.**  
   Suppose a selected row contains 16-bit values 3 at offset 0 and 7 at offset 2. A fifth input of zero derives hexadecimal 00700000. A fifth input of either 1 or −1 derives hexadecimal 00300000.

7. **The table entry’s upper four bits are discarded.**  
   If the selected entry is hexadecimal F123, the derived quantity is hexadecimal 12300000. If it is hexadecimal 1000, the derived quantity is zero. Both cases still proceed to the dependency call.

8. **A nonzero dependency result can trigger fallback.**  
   If the effective factor is 65,536 and the dependency returns 65,536, the product wraps to zero. The function must return 65,536.

9. **Negative dependency results retain their bit-pattern effect.**  
   If the effective factor is 2 and the dependency returns −1, the final result is hexadecimal FFFFFFFE. No sign-based rejection is established.

10. **Zero does not bypass the dependency.**  
    If the first and second inputs are both zero, the dependency must still be called after quantity derivation. If it returns normally, the function returns zero.
