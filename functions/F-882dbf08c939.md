## Behavior

### 1. Capture dimension gates

The function first calls:

1. F-3d16c4397c76 with no explicit argument.
2. F-5e490153287b with the object address.

Both calls occur, in that order, even if the first returns zero. Their returned integers are retained as the horizontal and vertical gates for this invocation.

The address of the object’s bounds region, `object + 0x80`, is also retained.

If both gates are zero, the function skips all dimension-processing work and proceeds to the final bounds/state phase.

Otherwise, it:

1. Calls F-7a1c296974df with the object.
2. Calls F-163aa6442bb1 with the object and retains the returned integer as the padding-like quantity.
3. Captures the global byte-data address described above.

The two gates are not recalculated after these calls. The function does not establish that any dependency preserves object fields, globals, or memory ownership.

### 2. Process the horizontal dimension when its captured gate is nonzero

The function first calls F-b01436b9ce2b with `object + 0x80`, retaining its integer result as the horizontal extent.

It then reads the text address at `+0xF8`. If the address is nonnull, it reads the first byte. Define **text present** as a nonnull address whose first byte is nonzero.

The function selects between two principal cases:

- Text is present, or bit `0x20` at `+0xF0` is set.
- Neither condition holds.

#### Text present or bit `0x20` set

The next decision uses bit `0x08000000` at `+0x48`.

**When that bit is clear:**

- A nonzero horizontal extent produces no horizontal setter call on this path.
- A zero horizontal extent causes the function to read the cached quantity at `+0xEC`.
  - If the cached quantity is nonzero, the function calls F-065fd89ae7c4 with the object and that cached quantity exactly. No padding is added.
  - If the cached quantity is zero, the function:
    1. Calls F-7fa874cbac7a with the object and `object + 0xA4`.
    2. Calls F-7ec5c59748e6 with `object + 0xA4`.
    3. Reads the adjustment byte at `+0xEA` and adds its integer conversion to the measurement.
    4. Adds twice the retained padding-like quantity.
    5. Calls F-065fd89ae7c4 with the resulting value.

**When bit `0x08000000` is set:**

- If the byte at the captured global address is zero, no horizontal setter is called.
- If that byte is nonzero, the function:
  1. Calls F-7fa874cbac7a with the object and `object + 0xA4`.
  2. Calls F-19fde5f06ccc with `object + 0x80`.
  3. Calls F-7915d17c3515 with the embedded-region address, the then-read text address, the result of F-19fde5f06ccc, and the integer-converted adjustment byte.
  4. Adds twice the retained padding-like quantity to that result.
  5. Calls F-065fd89ae7c4 with the object and the computed value.

This branch can execute when the text address is null or points to an empty string, because bit `0x20` alone can select it. The function does not reject such an address before passing it to F-7915d17c3515.

The text address supplied to measurement is read after the preparation call; it need not equal the address used in the earlier text-presence decision.

#### No text and bit `0x20` clear

A signed-positive horizontal extent causes two actions, in order:

1. Store the extent into `+0xEC`.
2. Call F-065fd89ae7c4 with the object and twice the retained padding-like quantity.

A zero or negative extent produces neither action.

Thus the cached quantity can be replaced by the current extent while the setter receives a different value. The function does not directly cache every computed horizontal measurement.

### 3. Process the vertical dimension when its captured gate is nonzero

This phase follows horizontal processing. It rereads the text address and, when nonnull, its first byte. Horizontal dependencies may therefore affect the vertical branch.

If text is present:

- A zero byte at the captured global address skips the vertical setter and proceeds directly to the final phase.
- Otherwise:
  1. Call F-7fa874cbac7a with the object and `object + 0xA4`.
  2. Call F-a0576cc39408 with `object + 0xA4` and the then-read text address.
  3. Add twice the retained padding-like quantity to the returned measurement.
  4. Call F-d25031d00f00 with the object and the result.

If text is absent, call F-d25031d00f00 with twice the retained padding-like quantity.

Unlike horizontal processing, this phase does not consult bit `0x20`, the horizontal extent, the cached quantity, or the adjustment byte.

### 4. Optionally evaluate bounds and change state

After dimension processing—or immediately when both initial gates were zero—the function reads `+0xF0`. If bit `0x80` is clear, it returns.

If the bit is set, it reads:

1. The parent address from the object’s `+0x34`.
2. Four parent components at `+0x80`, `+0x84`, `+0x88`, and `+0x8C`, in that order.
3. Four object components at the corresponding offsets, in that order.

These eight values are snapshots used for the following comparisons.

For description, interpret the components as left, top, right, and bottom respectively. The decisions use signed 32-bit comparisons:

- Vertical overflow: object top is less than parent top, or parent bottom is less than object bottom.
- Horizontal overflow: object left is less than parent left, or parent right is less than object right.

The function calls F-5e490153287b with the then-read parent address. The state is classified as **outside** if that result is zero and vertical overflow exists.

Only if this first condition does not establish outside does it call F-3d16c4397c76 with the then-read parent address. A zero result combined with horizontal overflow also establishes outside.

Consequently:

- The second parent gate call is short-circuited when the first gate and vertical comparison already establish outside.
- Equality at an edge is not overflow.
- The parent address passed to a later dependency can differ from the parent whose components were captured, if intervening calls change `+0x34`.
- Later mutations of bounds do not update the captured comparison values.

The no-argument initial use of F-3d16c4397c76 and its parent-argument use here are both present in the supplied representation. Their shared low-level calling contract is not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, dependencies return normally and do not mutate relevant fields.

1. **Both initial gates zero.** Neither initialization, padding acquisition, nor dimension setter is called. A set final `0x80` flag still causes bounds/state processing.

2. **Restore cached horizontal value.** With horizontal processing enabled, text present, `0x08000000` clear, extent zero, and cache value 37, F-065fd89ae7c4 receives 37. Padding is not added.

3. **Measure uncached horizontal value.** Under the same conditions but cache zero, measurement 20, adjustment 3, and padding 4, F-065fd89ae7c4 receives 31.

4. **Cache an extent and reduce the dimension.** With text absent, `0x20` clear, extent 42, and padding 4, the function stores 42 at `+0xEC` before calling F-065fd89ae7c4 with 8. A zero or negative extent instead skips both actions.

5. **Global byte suppresses text measurement.** With the constrained horizontal mode selected and the global byte zero, no horizontal setter occurs through that branch. With vertical processing enabled and text present, the same zero byte suppresses the vertical setter. It does not suppress the final bounds/state phase.

6. **Absent text still sets vertical size.** With the vertical gate nonzero, text absent, and padding 4, F-d25031d00f00 receives 8 regardless of the global byte.

7. **Touching boundaries.** Equal corresponding bounds do not establish overflow. If neither axis establishes outside, the state virtual entry receives one and bit `0x1` is subsequently set.

8. **Vertical short-circuit.** A zero parent vertical gate and an object top smaller than the captured parent top establish outside. The parent horizontal gate is not called; the state virtual entry receives zero.

9. **Preserve callback flag changes.** If the state virtual entry changes unrelated flag bits, the subsequent direct write preserves those changes while forcing bit `0x1` to the target state.

10. **Conditional ancestor notification.** Outside with special mode clear and the state bit already clear performs the state dispatch and flag write but skips ancestor traversal. Not-outside with special mode active and the state bit already set also skips traversal.
