# F-113b47c20b18

## Purpose

F-113b47c20b18 repeatedly searches an input for an opening delimiter, obtains a candidate from a construction-like dependency, optionally searches for a closing delimiter and processes intervening content, then delivers the candidate through a receiver’s indirect operation.

The established behavior consists of calls, field accesses, local-state changes, and conditional control flow. Interpreting the operation as tag parsing is inferred intent, supported by the incomplete-tag diagnostic. Delimiter representation, matching semantics, candidate ownership, and content-management semantics are not established.

The function has no explicit return value. Observable outcomes include receiver calls, candidate-field changes, dependency side effects, diagnostic handling, and entry into a dependency annotated as nonreturning.

### Local storage and alias relationships

Two adjacent 32-bit local words are initialized once, before the first search:

- The first word receives the input argument.
- The following word receives the auxiliary argument.

The address of the first word is later passed to content-related dependencies. The following word is the **same handle slot** later overwritten with a candidate address and passed by address to the receiver.

Neither initialization repeats at the loop boundary. Consequently:

- Changes to the first word can remain present during later iterations.
- Receiver changes to the handle slot can remain present until a subsequent write replaces them.
- A later content operation receives the first word’s address while the adjacent handle slot may still contain a previous receiver-written value.
- Whether any content dependency actually reads or writes that adjacent slot is unknown; adjacency alone does not establish its accepted storage extent.
- Immediately before each normal delivery, the function overwrites the handle slot with the current candidate address.

The candidate address used for field accesses is retained separately. Merely replacing the handle slot’s contents does not replace that retained address.

## Behavior

### Opening search and candidate acquisition

The search cursor starts at unsigned 32-bit zero.

Each iteration calls F-a21141daa905 with the original input argument, a read of descriptor offset 4, and the current cursor. A result with the 32-bit −1 bit pattern terminates the function normally, without candidate construction or delivery for that search.

Every other result is retained as the opening-match position. No local check requires it to be nonnegative, within the input, or at or beyond the cursor.

After a successful opening search, the call sequence is:

1. F-8157a180d901 receives the integer 20.
2. F-1cb585febd84 receives a fresh read of descriptor offset 4.
3. F-f762c9d297ce receives the returned word from the first call, the descriptor’s one-byte discriminator, the opening-match position, and the opening-match position plus the second call’s result.

The return from F-f762c9d297ce becomes the retained candidate address.

The descriptor is not snapshotted. For example, a dependency may change descriptor offset 4 between the opening search and the length-like query. The discriminator read for construction also occurs after the preceding calls.

The values returned by F-1cb585febd84 are used as delimiter lengths. Their units and semantic guarantees are not independently established.

### No required closing delimiter

After candidate construction, descriptor offset 8 is read.

If zero, closing search, candidate-end update, extraction, and content-related cleanup are skipped. Execution proceeds to normal delivery.

The constructor determines the candidate fields later used for continuation on this path. The supplied caller does not establish how its constructor arguments map to candidate offsets 4 and 8.

### Required closing delimiter

If descriptor offset 8 is nonzero, the function reads candidate offset 8 and retains that value as the closing-search origin. It then calls F-a21141daa905 with the original input, a read of the closing-delimiter reference, and that origin.

#### Missing closing match

A closing-search result of −1 selects this sequence:

1. F-d69c68d6696d receives the receiver, retained candidate address, and a fixed incomplete-tag diagnostic.
2. If the retained candidate address is nonzero and the diagnostic call returns, F-f8e663c32a06 receives that candidate.
3. If that call returns, F-feee9156a257 is invoked. The supplied representation annotates it as nonreturning.

No normal delivery occurs before these operations.

If the candidate address is zero and execution reaches this branch, the two latter calls are skipped. The cursor becomes the opening-match position plus one, and opening search resumes without the normal continuation-bound query.

That zero-address branch is visible control flow, not an established safe case: candidate offset 8 has already been dereferenced.

Neither adjacent local word is explicitly reinitialized on this retry, and the handle slot is not overwritten with the failed candidate before retrying. Dependency changes to accessible state may therefore carry forward.

The nonreturning annotation is static evidence about the represented control flow, not runtime confirmation of termination behavior. If an earlier dependency does not return, subsequent operations do not occur.

### Normal delivery and continuation

Immediately before normal delivery, the retained candidate address is written into the handle slot—the same word initialized once from the auxiliary argument.

F-indirect-01 is then resolved through the receiver’s dispatch table at byte offset 28 and called with the receiver and the handle slot’s address.

The receiver can change the slot through that address. After return:

- Its changed slot contents remain until overwritten or otherwise changed.
- The function still uses its separately retained candidate address.
- The function does not directly read the slot to determine continuation.

Continuation uses fresh reads from candidate offsets 8 and 4:

**next cursor = field at offset 8 − field at offset 4 + retained opening-match position**

The receiver can therefore affect continuation through candidate-field changes. Changing only the handle slot does not directly change this calculation. Releasing or invalidating the retained candidate during delivery would make the later reads unsafe unless an external lifetime contract preserves access.

After computing the cursor, the function reads input offset 4 and passes that 32-bit word to F-8810f53aaa0b. Its result is compared with the cursor as unsigned 32-bit values:

- Result less than or equal to cursor: return normally.
- Result greater than cursor: begin another opening search at that cursor.

No progress requirement is enforced. Repeated or backward cursors can repeat work or prevent termination if dependencies permit it.

## Acceptance examples

These are conditional static expectations, not executed tests. Arithmetic examples assume representable intermediate values and returning dependencies unless stated otherwise.

1. **No opening match.** If the first search returns −1, the function returns without calling F-8157a180d901, constructing a candidate, or delivering one. The two local-word initializations have already occurred.

2. **Opaque preparation result.** After an opening match, F-8157a180d901 receives 20. If it returns a particular word, that word is forwarded to F-f762c9d297ce. Acceptance does not require interpreting it as an allocated address or interpreting 20 as bytes.

3. **Opening-only termination at equality.** If the closing field is zero, the opening position is 5, and candidate offsets 4 and 8 contain 5 and 8 after delivery, the next cursor is 8. A continuation bound of 8 terminates.

4. **Ordinary closing arithmetic.** With retained origin 12, closing match 17, closing length 3, and the fresh candidate-end read still 12, the written end is 20. Extraction receives origin 12 and extent 5.

5. **Candidate mutation before end update.** With the same origin, match, and length, but a fresh candidate-end read of 40, the written end is 48 rather than 20.

6. **Missing close with nonzero candidate.** If the closing search fails and the diagnostic returns, F-f8e663c32a06 receives the candidate. If it returns, F-feee9156a257 is called. Normal delivery is not reached before that annotated nonreturning call.

7. **Handle-slot replacement.** If the receiver replaces the delivered slot value, the continuation calculation still uses the separately retained candidate address. Candidate-field changes made by the receiver can affect that calculation.

8. **Cross-iteration storage.** Suppose a receiver writes a replacement word into the handle slot, and a later iteration reaches extraction. The first local word is not reset to the input argument, and its adjacent slot is not reset to the auxiliary argument. In the absence of intervening changes, those prior contents remain present. Whether extraction reads the adjacent slot is unknown. Before that iteration’s delivery, the slot is overwritten with its current candidate.

9. **No guaranteed progress.** If continuation produces the same cursor and the bound is greater, search resumes at that cursor without a forced increment.
