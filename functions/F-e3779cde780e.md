# F-e3779cde780e

## Purpose

F-e3779cde780e describes an ordered sequence of memory reads and writes followed by an unresolved indirect control transfer with four arguments.

The established behavior is low-level memory mutation and argument preparation. The supplied representation does not establish an application-level purpose, object model, or complete public calling convention. Three incoming values have no visible initialization; their availability is a prerequisite for interpreting the body.

Access order matters. The routine repeats writes, replaces intermediate values, and accesses overlapping byte and word regions. A contract containing only final memory values would omit established behavior.

This specification describes static evidence. It does not claim that the representation establishes every instruction-level effect or that execution has been observed.

## Interface

The visible interface supplies one explicit **input word**, represented as a 32-bit signed integer. The body stores its bit pattern and uses it as an address base for a word read at offset `0x74`.

### Outputs

### Widths, offsets, and arithmetic

Byte, halfword, and word accesses are respectively 8, 16, and 32 bits in the supplied representation. All offsets in this contract are byte offsets.

A low-byte extraction means retention of the least significant eight bits. The fixed halfword store has value `0x0065`; the fixed word store has value decimal `100`, or `0x00000064`. Neither description specifies the order of constituent bytes in memory.

Primary-base doubling and primary-base address additions use the recovered unsigned 32-bit representation. Their numeric results are reduced modulo \(2^{32}\). Converting those results into usable addresses still depends on target address semantics.

Other address expressions include signed 32-bit bases and signed words obtained from memory. Their offset additions, as well as the two later signed doublings, can exceed the signed range. The evidence does not establish a portable overflow rule. Modular wrapping must not be assumed for every address expression merely because the access width is 32 bits.

Endianness, alignment requirements, and the target’s address-space mapping remain unresolved.

### Preconditions

For complete execution, every reached address must support its specified access, and the indirect target must support the actual transfer and argument convention.

This requirement includes addresses derived from words read during execution. Validity of the initial bases alone is insufficient.

No bounds, null, alignment, or arithmetic-validity checks are visible. Zero, overlapping, or otherwise unusual bases are not explicitly rejected; that does not establish that they are safe.

## Behavior

The following phases describe the represented access order. A **retained word** is the value captured at its stated read, not a later read of the same location.

### Repeated opening writes

The body begins with three consecutive repetitions of the same four-write sequence:

1. The input word is stored as a word at twice the primary base plus `0x54`.
2. The primary base’s low byte is stored at secondary-base offset `0x19`.
3. The secondary base’s low byte is stored at primary-base offset `0x11`.
4. Twice the primary base is stored as a word at secondary-base offset `0x34`.

This establishes twelve explicit writes, without an intervening memory read or dependency invocation in the supplied body.

The repetition is not established as a retry, initialization protocol, or synchronization mechanism. It must nevertheless remain distinct in an access-sequence contract. Aliasing can affect the resulting bytes, and an observer capable of distinguishing writes could distinguish three repetitions from one.

### Early snapshots and byte updates

After the opening writes, the body captures a word beginning at absolute address `0xA9`, then a word at input-word offset `0x74`.

It next writes a byte at absolute address `0x3A`. That byte is twice the primary base’s low byte plus `0x30`, reduced to eight bits. No validation restricts this calculation to decimal-digit encodings.

Only after that byte write does the body capture a word at tertiary-base offset `0x14`, followed by a word at primary-base offset `0x04`.

The subsequent writes occur in this order:

- Tertiary-base offset `0x0D` receives the primary base’s low byte.
- Primary-base offset `0x08` receives byte `0x6C`.
- Primary-base offsets `0x0D` and then `0x09` receive the secondary base’s low byte.
- Tertiary-base offset `0x54` receives the tertiary base as a word.
- Absolute address `0x67` receives the low byte of the retained word from `0xA9`.

These snapshots precede the listed updates. If locations overlap, replacing the snapshots with reads after the updates would change behavior.

### Intermediate word and shifted byte

The next word read is at tertiary-base offset `0x44`. Call its captured value the **intermediate word**.

After this read, the current byte at absolute address `0x67` is read and copied to absolute address `0x21`. The intermediate word’s low byte is then written at primary-base offset `0x10`, followed by its full word at secondary-base offset `0x54`.

Next, tertiary-base offset `0x01` receives the low byte of the intermediate word right-shifted by the primary base’s low eight bits.

The shifted operand has a recovered signed 32-bit representation. For a nonnegative operand and a count from zero through 31, the ordinary signed right-shift result is established by that representation. Negative-operand right-shift semantics and counts of 32 or more require target-specific information. The source does not justify silently masking the count to five bits.

Secondary-base offset `0x54` is then overwritten with the primary base as a word. Consequently, the intermediate word is a real earlier store, not merely a value superseded before any specified write.

### Word replacement and repeated absolute-byte observations

The body next reads a word at primary-base offset `0x40`. It then performs these writes in order:

- Secondary-base offset `0x74` receives the retained word from primary-base offset `0x04`.
- Primary-base offset `0x10` receives the word just read from offset `0x40`.
- Secondary-base offset `0x44` receives the tertiary base as a word.

Only then is absolute address `0x67` read again. Its current byte is stored at primary-base offset `0x09`. Tertiary-base offset `0x09` subsequently receives the primary base’s low byte, and primary-base offset `0x44` receives the retained word originally read at absolute address `0xA9`.

The word store at primary-base offset `0x10` covers offsets `0x10` through `0x13`. It overlaps both the earlier intermediate-word byte at offset `0x10` and the opening byte stores at offset `0x11`.

The absolute-byte read is a fresh observation. Intervening writes can alias address `0x67`, so its result cannot generally be replaced with the low byte originally written there.

### Selected-address capture

The body reads a word at primary-base offset `0x54`. Its captured value is the **selected address**, represented as a signed 32-bit integer.

This read is not generally a readback of the opening input-word store: that store uses twice the primary base plus `0x54`, whereas this read uses the primary base plus `0x54`.

After capturing the selected address, the body reads absolute address `0x67` for the third time and writes that byte at primary-base offset `0x09`.

It then:

- Writes the low byte of the retained input-word-offset-`0x74` word at selected-address offset `0x0D`.
- Replaces the word at tertiary-base offset `0x54` with the retained word from tertiary-base offset `0x14`.
- Reads and retains a word at primary-base offset `0x14`.
- Writes the same retained input-derived low byte at tertiary-base offset `0x11`.
- Writes the selected address’s low byte at primary-base offset `0x09`.
- Writes the selected address as a word at primary-base offset `0x44`.

The retained input-derived byte is not reloaded between its two stores.

### Linked-address reads and terminal writes

The body reads a word at tertiary-base offset `0x04`. Its captured value is the **linked address**, represented as a signed 32-bit integer.

It immediately stores halfword `0x0065` at twice the linked address. It then reads a word at linked-address offset `0x64`; call that captured signed 32-bit value the **linked word**.

The next two stores target the selected address:

- Its offset `0x11` receives the low byte of the retained word from primary-base offset `0x14`.
- Its offset `0x54` receives word value `100`.

The body then captures a word at linked-address offset `0x74`, followed by a word at tertiary-base offset `0x64`. The latter is the **destination address**, represented as a signed 32-bit integer.

Three terminal stores follow, in order:

- Tertiary-base offset `0x09` receives the linked address’s low byte.
- Destination-address offset `0x54` receives the linked word as a word.
- Twice the linked word receives the destination address as a word.

Both doubled destinations in this phase use signed operands in the supplied representation. Overflow behavior is unresolved.

Ordering can affect captured values. For example, the halfword store precedes the linked-word read, and the selected-address constant store precedes both final word reads. Aliasing must therefore be evaluated against the memory state at each access, not against entry memory alone.

### Indirect transfer

After the final store, the unresolved indirect target is presented with these arguments, in order:

1. Constant `0x72`, decimal `114`.
2. The linked word.
3. The retained word from tertiary-base offset `0x14`.
4. The retained word from linked-address offset `0x74`.

The arguments are captured values. Their source locations are not re-read at transfer time.

A return follows in the supplied representation, but normal return from the target is not established. There is no later explicit memory access in the visible body.

## Acceptance examples

These are conditional static examples, not executed tests. Except where aliasing is the subject, assume valid accesses and no aliasing that changes the described values.

### Opening-write multiplicity

An access trace conforming to the supplied body contains three consecutive repetitions of the four opening writes. Reducing them to one repetition does not preserve the specified explicit-write sequence, even if ordinary memory ends with identical bytes.

### Low-byte arithmetic

If the primary base’s low byte is `0x05`, the byte stored at absolute address `0x3A` is `0x3A`.

If that low byte is `0xFF`, the stored byte is `0x2E`. This follows from eight-bit reduction, not from digit validation. Neither example asserts that every address derived from that primary base is valid.

### Intermediate replacement

If the intermediate word is `0x12345678`, secondary-base offset `0x54` first receives that word and subsequently receives the primary base. A final-state-only description omits the first word store.

### Defined shift case

If the intermediate word is nonnegative `0x12345678` and the primary base’s low byte is `0x04`, the shifted-byte store at tertiary-base offset `0x01` has value `0x67`.

This example does not establish behavior for a negative operand or an oversized count.

### Retained argument

If tertiary-base offset `0x14` yields `0x11223344` at its specified read, the third indirect argument is `0x11223344`, even if later accesses change that source location.

### Fresh absolute-byte read

If an intervening write changes absolute address `0x67`, the next specified read there observes the memory value at that later point. Reusing the original byte from absolute address `0xA9` is not generally equivalent.

### Unresolved boundaries and failures

For a shift count of 32 or more, or signed address arithmetic outside its representable range, this contract does not invent masking or wrapping semantics.

If the indirect target changes earlier destinations and then fails, the visible body supplies no guarantee that those destinations retain either their pre-call or pre-entry values.
