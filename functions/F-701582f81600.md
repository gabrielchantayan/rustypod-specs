# F-701582f81600

## Purpose

F-701582f81600 performs an ordered mutation of a caller-provided memory graph and then invokes an unresolved indirect target. Its effects include constant markers, self-references, replaced links, bytes extracted from address-like values, and writes to addresses computed by addition, subtraction, or doubling.

No application-level purpose is established. The values 100, 0x73, 0x74, 0x66, 0x44, and 0x45 are observable constants, not evidence of an encoding or object type.

This contract describes static evidence. It does not establish that the implicit inputs, memory graph, computed destinations, or final invocation are valid in an executable environment.

### Implicit inputs

Three incoming address-like values are used without their acquisition being represented by the explicit interface:

- **Entry object:** destination of the earliest writes.
- **Secondary base:** supplies the working-object link at offset 0x14.
- **Context object:** receives initial writes and supplies two initial links.

The function also reads three external 32-bit data slots, designated **D1**, **D2**, and **D3**, and invokes an unresolved target designated **F-INDIRECT-01**. These are contract labels, not recovered identities.

The four explicit arguments alone do not supply all required execution state.

### Memory layout and arithmetic

All offsets are byte offsets. Accesses are 8-bit bytes, 16-bit halfwords, or 32-bit words. Links and address-like integer values are represented as 32-bit quantities in the supplied evidence.

A byte extracted from a word or address-like value retains its low eight bits. Halfword reductions retain the low sixteen bits at the represented bit-width level. Byte order and alignment requirements are not supplied; overlapping writes must not be interpreted using an assumed byte order.

Address arithmetic is not uniformly unsigned:

- The selector is explicitly converted to an unsigned 32-bit value. Its additions of 0x44 and 0x45 therefore have unsigned 32-bit arithmetic.
- The evidence does not establish universally defined modular behavior for signed address arithmetic, signed doubling, or integer-to-address conversion.

## Behavior

### Ordering rules

The phases below retain the represented access order. A **captured** value is the result of its particular read; a **fresh** read obtains memory again. Earlier writes can affect subsequent reads through aliasing.

Repeated writes and read/write-back operations are retained in this contract. This does not establish that the underlying storage is volatile or that every represented access survives compilation as a separately observable physical transaction.

Within compound accesses, required dependent reads precede their use. No additional machine-level ordering between independent operand evaluations is claimed.

### 1. Initialize the entry and initial graph

The function performs these accesses in order:

1. Write the first input as a word at entry offset 0x10.
2. Write the third input as a word at context offset 0x54.
3. Write the first input’s low byte at entry offset 0.
4. Write the secondary base’s low byte at entry offset 9.
5. Capture the word at secondary-base offset 0x14 as the **working object**.
6. Write the entry address’s low byte at context offset 0x11.
7. Write the working-object address at entry offset 0x44.
8. Write the first input’s low byte at entry offset 0 again.
9. Capture context offset 0x74 as the **initial context tail**, then context offset 0x14 as the **initial branch**.
10. Write the entry object’s own address at entry offset 0x54.

The initial branch’s offset-4 link supplies the **initial child**. The second input is written at initial-child offset 0x11, followed by byte 100 at offset 0x10. Word 100 is written at working-object offset 0x54, then initial-child offset 0x60.

The old working-object offset-0x74 link is captured. That field is replaced with the initial-branch address, and word 100 is written at offset 0x30 of the captured old target.

The initial branch’s offset-0x14 link supplies the **branch child**. Its offset 9 receives the second input. Working-object offset 0x54 becomes a self-reference.

Finally, a word is written at initial-context-tail minus 0x20. Its value is initial-context-tail minus 0x74.

### 2. Populate branch-related fields

Capture the branch child’s offset-0x14 link as an **early descendant**. Write the fourth input at initial-branch offset 0x11. Freshly read initial-branch offset 0x14, retaining this as the **earlier branch word**, and write its low byte at early-descendant offset 0x15.

Read initial-branch offset 0x14 again as the **current branch child**. Read working-object offset 0x64 as the **first working word**, then write that captured word back to the same field.

Next, in order:

- Write byte 0x73 at current-branch-child offset 0x0c.
- Write the first working word’s low byte at working-object offset 0x15.
- Write the earlier branch word at initial-branch offset 0x34.
- Capture current-branch-child offset 0x74 as the **saved child-tail word**.
- Make current-branch-child offset 0x54 a self-reference.
- Capture the working-object address’s low byte as the **working-address byte**, and write it at initial-branch offset 0x0d.
- Write the earlier branch word at initial-branch offset 0x54.
- Write the current-branch-child address at initial-branch offset 0x14.

### 3. Apply the 0x74 sequence

Freshly read working-object offset 0x64 as the **second working word**.

Write byte 0x74 at current-branch-child offset 0x10, word 0x74 at working-object offset 0x54, then word 0x74 at current-branch-child offset 0x10. The last write spans four bytes, unlike the first.

Capture current-branch-child offset 0x74 as the **retained child tail**. Make initial-branch offset 0x54 a self-reference, then write word 0x74 at current-branch-child offset 0x30.

Continue in order:

- Write the first working word’s low byte at working-object offset 1.
- Treat the first working word as an address and write the second working word’s low byte at its offset 9.
- Write the second working word at working-object offset 0x74.
- Write byte 0x74 at working-object offset 0x11.
- Capture current-branch-child offset 0x60.
- Overwrite working-object offset 0x11 with the first working word’s low byte.
- Write the second working word at working-object offset 0x34.

### 4. Apply the 0x66 sequence

Freshly read working-object offset 0x14 as the **marker target**.

Write the saved child-tail word’s low byte at initial-branch offset 0x11. Write the initial-branch address at working-object offset 0x44, then the second working word’s low byte at working-object offset 0x11.

Capture a fresh working-object offset-0x74 word as the **saved working-tail word**. Write the initial-branch address’s low byte at working-object offset 0x0d.

- Word 0x66 at marker-target offset 0x10.
- Initial-branch address at working-object offset 0x44 again.
- Byte 0x66 at marker-target offset 0x10.
- Word 0x66 at working-object offset 0x54.

Write the saved working-tail word’s low byte at working-object offset 0x0d. Capture replacement-tail offset 0x44. Make working-object offset 0x54 a self-reference, followed by retained-child-tail offset 0x54 becoming a self-reference.

Read replacement-tail offset 0x14 as a descendant address. Write the captured replacement-tail offset-0x44 word’s low byte at initial-branch offset 0x11. Freshly read initial-branch offset 0x14 and write its low byte at that descendant’s offset 0x15.

### 5. Redirect through descendant links

Freshly read initial-branch offset 0x14 as the **descendant**. Read working-object offset 0x64 as the **first redirect word**, write word 0x73 at descendant offset 0x20, then read working-object offset 0x64 again as the **second redirect word**.

Capture the second redirect word’s low byte as the **repeated marker byte**, and write it at descendant offset 9.

1. Write the working-address byte at offset 0x0d.
2. Read offset 0x54 and write the captured word back there.
3. Write byte 0x74 at offset 9.

Write the first redirect word at working-object offset 0x44, then the working-object address at descendant-tail offset 0x34.

Read descendant-tail offset 4 as the **forward node**. Write the second redirect word at forward-node offset 0x24, then the first redirect word’s low byte at working-object offset 0x19.

Capture forward-node offset 0x74 as the **forward tail**, followed by forward-node offset 4 as the **forward word**.

Freshly read working-object offset 0x74 as the **current working tail**. Follow its offset-0x14 link and write the forward-tail address at that object’s offset 0x54.

Read current-working-tail offset 4 as the **side node**. Write the repeated marker byte twice consecutively at working-object offset 0x0d. Write the forward word at working-object offset 0x64, then word 0x74 at side-node offset 0x30.

### 6. Prepare the terminal graph

Freshly follow current-working-tail offset 4 and then the reached object’s offset 0x74 to obtain the **traversal node**.

Read working-object offset 0x64, capture its low byte as the **new marker byte**, and write that byte at working-object offset 0x1d.

Freshly follow working-object offset 0x44 and then offset 0x14 to obtain the **replacement child**. Write the forward-tail address at traversal-node offset 0x34, then the replacement-child address at working-object offset 0x14.

Capture working-object offset 0x54 as the **saved working-self word**. Write the working-address byte at replacement-child offset 9.

Follow traversal-node offset 4 and then offset 0x74 to obtain the **terminal child**. Write the forward-tail address’s low byte at terminal-child offset 0x15.

Next:

- Make working-object offset 0x54 a self-reference.
- Write the traversal-node address’s low byte at working-object offset 0x11.
- Write the saved working-self word’s low byte at terminal-child offset 0x11.
- Capture terminal-child offset 0x64 as the **terminal word**.
- Write the new marker byte at working-object offset 9.

Freshly read traversal-node offset 4 as the **terminal node**. Write the working-address byte at terminal-node offset 9, then capture terminal-node offset 0x50.

Write the terminal word’s low byte at terminal-node offset 0x11, followed by the working-address byte at terminal-node offset 9 again.

Write the terminal word at working-object offset 0x14, the terminal-node address’s low byte at working-object offset 0x0d, and the captured terminal-node offset-0x50 word’s low byte at terminal-node offset 0.

### 7. Finish graph writes

Capture traversal-node offset 0x74 as the **terminal tail**.

**The traversal node’s offset-0x14 link supplies the terminal branch.** This read is from the traversal node itself, not from the terminal tail. The terminal tail and terminal branch are independently captured values.

Make terminal-node offset 0x54 a self-reference. Then follow terminal-branch offset 4 to obtain the **final child**.

Perform these writes in order:

1. Byte 100 at final-child offset 0x10.
2. Word 100 at working-object offset 0x54.
3. Word 100 at final-child offset 0x40.
4. The terminal word’s low byte at working-object offset 0x0d.
5. The final-child address’s low byte at terminal-branch offset 9.
6. The terminal word at working-object offset 0x24.
7. The working-address byte at terminal-branch offset 0x11.

The terminal tail remains a captured input to the later selector read; it does not supply this phase’s terminal-branch traversal.

### 8. Perform computed writes and invoke the target

Read D1, then freshly read working-object offset 0x74 as the **final link**.

In order:

1. Write the final link’s low sixteen bits at final-link plus working-object.
2. Write D1’s low sixteen bits at twice the final-child address.
3. Read one character-sized value at terminal-tail plus working-object and convert it to an unsigned 32-bit **selector**.
4. Write the final link’s low sixteen bits at D1 plus final-link.
5. Repeat the halfword write at final-link plus working-object.
6. Write word 0x45 at selector plus 0x45.

The selector read uses the captured terminal tail, not a fresh traversal-node tail read. Character signedness is unresolved: a high-bit-set byte can become either a small unsigned value or a sign-extended value subsequently converted to unsigned 32 bits.

Read D2, then D3, then freshly read working-object offset 0x44 as the **final argument word**.

Perform the remaining writes in order:

- Byte 0x44 at selector plus 0x44.
- D3 as a word at twice D2.
- D2’s low sixteen bits at forward-tail plus D2.

Invoke F-INDIRECT-01 with three visible 32-bit values:

1. Selector bitwise-OR 0x44.
2. D2.
3. The final argument word.

The first argument uses bitwise OR, not addition. The final argument word is captured before the last three writes, even if those writes alias its source field.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes execution reaches the relevant accesses with valid arithmetic and accessible memory.

1. **Input reduction:** For first input 0x123456AB, the initial word write at entry offset 0x10 carries 0x123456AB. Both initial byte writes at entry offset 0 carry 0xAB. Later aliasing can alter those destinations.

2. **Width-sensitive marker:** The 0x74 sequence writes one byte and later four bytes at current-branch-child offset 0x10. A byte-only model of both writes is incorrect.

3. **Reload sensitivity:** If an intervening aliased write changes working-object offset 0x64, successive reads may differ. Stored values and low-byte derivatives must follow their particular captures.

4. **Independent terminal links:** Suppose traversal-node offset 0x74 supplies address A and traversal-node offset 0x14 supplies distinct address B. The final child comes from B’s offset 4, regardless of A’s offset-0x14 contents. The later selector character comes from A plus working-object.

5. **Terminal-load timing:** The terminal-branch address is captured before terminal-node offset 0x54 becomes a self-reference. The final-child link is read afterward. Aliasing can therefore change the final-child link without retroactively changing the captured terminal-branch address.

6. **Repeated computed store:** Final-link plus working-object receives the captured final link’s low sixteen bits twice. The selector read occurs between these writes, so overlap can affect the selector.

7. **Selector arithmetic:** A selector character of 0x21 gives selector 0x21 regardless of signedness. The first invocation argument is 0x65; the selector-relative byte and word destinations are 0x65 and 0x66 respectively.

8. **High-bit character:** A character byte of 0x80 can produce selector 0x00000080 or 0xFFFFFF80, depending on character signedness. The corresponding first arguments are 0x000000C4 and 0xFFFFFFC4. Neither alternative is selected by this evidence.

9. **Captured final argument:** If a last-stage destination overlaps working-object offset 0x44, the third invocation argument still uses the word captured before those stores.

10. **Returning target:** If all accesses succeed and F-INDIRECT-01 returns normally, no further explicit memory writes occur in the visible body.
