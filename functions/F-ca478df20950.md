# F-ca478df20950

## Purpose

F-ca478df20950 updates a status word, evaluates eligibility, and either adjusts a count toward a calculated target or drains a count until it is zero. An adjustment sequence is followed by shared completion processing.

The function is stateful. Its result can be a freshly read count, an immediate zero, a completion code, or a value exposed to modification by a notification dependency. It is not uniformly a count or a fixed set of result codes.

“Count,” “target,” “limit,” and “completion” describe observed roles. Their application-level meanings are not established.

## Interface

**Explicit inputs:** None.

**Output:** An unsigned 32-bit value, selected as follows:

| Returning path | Result |
|---|---|
| Normal target equals the count used for the early comparison | A separate read through the current-count global reference |
| Initial drain check observes zero | Zero |
| Completion comparison mismatches | Nine |
| Completion comparison matches and the first signed countdown read is at least two | Ten |
| Completion comparison matches, countdown is below two, and completion activity is zero | Zero |
| Completion comparison matches, countdown is below two, and completion activity is nonzero | The post-notification value of the temporary record’s second 32-bit word |

The last result is initialized to zero but is not guaranteed to remain zero.

**Implicit state and layout:**

| Role | Established representation |
|---|---|
| Status block reference | Refers to a block whose source word is at offset 0 and destination word at offset 16 |
| Control-block reference | Refers to 32-bit fields: flags at offset 0, eligibility field at offset 12, limit at offset 16, requested value at offset 20 |
| Additional eligibility reference | Refers to a value tested for zero; its access width is unresolved |
| Current-count reference | Refers to an unsigned 32-bit count |
| Drain-count reference | Refers to a 32-bit count tested for equality with zero |
| Completion-block reference | Supplies addresses for fields at offsets 704, 708, and 712 |
| Completion-reference reference | Refers to the 32-bit value compared with the completion field at offset 704 |
| Notification record | Three consecutive 32-bit words, occupying 12 bytes |

The completion field at offset 708 is accessed as a signed 16-bit value for comparisons and subtraction, and written with a 16-bit store. Completion fields at offsets 704 and 712 use 32-bit accesses.

A global reference and a previously captured address are distinct inputs to this contract. Repeated evaluations of a global reference are not guaranteed to produce the same address. Likewise, repeated accesses to one address are not guaranteed to return the same contents.

**Reached-access preconditions:**

- Every reached reference access must be valid, including references read before a branch that subsequently rejects the normal path.
- Every reached dereference must address readable storage of the stated width; direct writes require writable storage.
- The current-count reference is read immediately after F-unmapped-03 returns, even if that return selects the drain path. This capture alone does not dereference the captured count address.
- Captured addresses used after dependency calls must remain valid until their last access.
- Dependencies must be callable in the execution context.
- Termination requires the adjustment dependencies and surrounding environment eventually to make each reached loop condition false.

No validation, timeout, iteration bound, explicit fault handling, or recovery is shown.

## Behavior

### 1. Status update

Before eligibility checks, the function reads a 32-bit status-source word, extracts bit 7, inverts that bit, and stores a full 32-bit zero or one to the status destination at offset 16:

- Source bit 7 clear: store one.
- Source bit 7 set: store zero.

Other source bits do not affect the calculated value. This replaces the destination word rather than preserving its other bits.

The expression obtains the source and destination through the status-block global reference. It does not establish an independently captured common base that must serve both accesses. If that reference is stable, the source and destination belong to the same block. Exact evaluation order among the reference accesses within this expression is not established.

### 2. Eligibility and address capture

The function first captures a control-block address for possible later target calculation.

It then evaluates eligibility using fresh accesses through the control-block global reference, rather than the captured address:

- Mask the flags word with hexadecimal `46`, selecting bits 1, 2, and 6.
- Combine that masked value with the complete 32-bit eligibility field at offset 12.
- Continue only if the combined value is zero.

The flags and offset-12 accesses independently use the global reference. A stable reference makes them accesses to the same block; address identity is not otherwise guaranteed. Their exact operand-evaluation order is unresolved.

If the combined value is nonzero, select the drain path. Do not read the additional eligibility value or call the eligibility dependencies.

If the combined value is zero, read the additional eligibility value. A nonzero value selects the drain path without calling an eligibility dependency.

If that value is also zero:

1. Call F-unmapped-01.
2. If its result is nonzero, select the drain path.
3. Otherwise, call F-unmapped-02; its return value is not inspected.
4. Call F-unmapped-03.
5. Immediately capture an address from the current-count global reference.
6. Test F-unmapped-03’s result.
7. A nonzero result selects the drain path; zero permits target calculation.

Thus, the current-count address capture occurs even when F-unmapped-03 rejects normal processing. It does not occur on earlier eligibility failures.

The retained control-block address predates these calls. Target calculation reads its contents afterward; neither the address nor the contents used by eligibility must match those used for target calculation.

### 3. Target calculation

Read the flags and requested value from the captured control-block address. Target values and their ordering comparisons are unsigned 32-bit quantities.

The requested value initially supplies the target.

**Flag bit 0 set:** Read the limit for an unsigned comparison against the requested value.

- If this first limit read is greater than the requested value, select the requested value without another limit read.
- If this first limit read is less than or equal to the requested value, read the limit again and select that second value.

The second read occurs on equality as well as on a strictly smaller first limit. It need not equal the comparison value.

Next, calculate a floor of one if flag bit 7 is clear, or zero if bit 7 is set. Raise the selected value to that floor when necessary.

Only under a stable-limit assumption is this stage equivalent to taking the smaller of the requested value and limit, then raising it to the floor. Without stability, the selected second limit can exceed the requested value.

**Flag bit 0 clear:** Retain the requested value. Do not read the limit for this calculation, and do not apply the bit-7-derived floor.

Apply the remaining overrides afterward:

- If bit 3 is set, replace the target with one; if bit 4 is also set, replace it with zero. Bit 5 has no effect in this case.
- If bit 3 is clear and bit 5 is set, replace a nonzero target with zero.
- If bit 3 is clear, bit 4 has no effect.

These rules use selection and comparison, not target addition or multiplication. They introduce no target arithmetic overflow.

### 4. Normal early return

Compare the calculated target with a count obtained through a fresh read of the current-count global reference. This comparison does not use the previously captured adjustment address.

If equal, return a second count read through another evaluation of that global reference.

The comparison and return can therefore use different addresses or different contents. The result equals the target only if the relevant references and contents remain stable between accesses.

This path calls no adjustment notification, token, adjustment, restoration, or completion dependencies.

### 5. Normal adjustment

If the early comparison does not match:

1. Call F-3b7c5b30bd55 with the 32-bit value 22.
2. Call F-f120802e6343 and retain its 32-bit result as an opaque token.
3. While the target is less than the count at the captured current-count address, call F-c6c2e1b896e3.
4. Once that loop exits, while the count at that same captured address is less than the target, call F-a870a0416476.
5. Call F-82729ee22091 with the retained token.
6. Enter completion processing.

Each loop condition rereads the count. Neither the target nor the captured address is recalculated after dependency calls.

The two loops are sequential, not enclosed in a convergence loop. Overshoot by the second adjustment dependency does not restart the first loop.

The dependencies’ apparent reducing and increasing roles are inferred from their call conditions. Exact step size, progress, and preservation of other state are not established.

### 6. Drain processing

Every eligibility failure reaches this path.

First capture an address from the drain-count global reference. Then perform the initial zero check through a separate evaluation of that global reference, not through the captured address.

If this check observes zero, return zero immediately.

Otherwise:

1. Call F-3b7c5b30bd55 with 22.
2. Call F-f120802e6343 and retain its 32-bit token.
3. While the 32-bit count at the captured drain address is nonzero, call F-c6c2e1b896e3.
4. Call F-82729ee22091 with the token.
5. Enter completion processing.

The initial check and loop conditions can address different storage if the global reference changes. The loop tests nonzero, not signed positivity; a bit pattern interpreted as negative still continues the loop.

No identity between the normal and drain count addresses is established.

### 7. Completion processing

This shared continuation corresponds to F-5a0e2e961d01. The supplied body shows a transfer into this behavior, not a separate ordinary call to that dependency.

Before F-unmapped-04:

1. Read the completion-block global reference and retain a base for accesses at offsets 708 and 712.
2. Read that global reference again and form a separate retained address for the 32-bit field at offset 704.
3. Call F-unmapped-04.

These two retained addresses need not belong to the same block. Both survive the call for subsequent accesses.

After F-unmapped-04, compare the 32-bit value at the retained offset-704 address with the value obtained through the completion-reference reference.

**Comparison unequal:**

- Call F-unmapped-05.
- Set the result to nine.
- Return it.

This branch performs no direct completion-field write.

**Comparison equal:** Read the signed 16-bit field at offset 708 of the first captured completion base.

If this first read is at least two:

- Read the signed 16-bit field again.
- Subtract one from that second value.
- Write the resulting low 16 bits back to the field.
- Call F-unmapped-05.
- Set the result to ten and return it.

The comparison does not constrain the second read without a stability assumption. With stable contents, the second value is between two and 32767, so the stored result is between one and 32766. Without stability, any signed 16-bit second value is possible. Subtraction remains within signed 32-bit range; narrowing the result to the 16-bit store can wrap its 16-bit representation.

If the first signed read is below two, read the 32-bit field at offset 712 of the first captured base.

**Offset-712 value zero:**

- Write zero to the 16-bit field at offset 708.
- Write zero to the separately retained 32-bit offset-704 address.
- Call F-unmapped-05.
- Set the result to zero and return it.

The two direct writes occur in that order.

**Offset-712 value nonzero:**

- Call F-unmapped-05.
- Initialize a temporary three-word record, in order, to 15, zero, and 22.
- Pass its starting address to F-c81f7910921f.
- Return the post-call value of its second 32-bit word.

The second word is both part of the exposed record and the returned result storage. F-c81f7910921f can modify it through the supplied address. Returning zero is conditional on that word remaining zero.

## Side effects

Direct effects consist of:

- The unconditional full-width status write.
- A possible 16-bit completion decrement.
- Possible zeroing of the 16-bit offset-708 field followed by the separately addressed 32-bit offset-704 field.
- Initialization of the temporary notification record.

Dependencies can additionally modify global references, pointed-to storage, the notification record, or external state. No preservation guarantee is supplied.

The token is retained and passed to F-82729ee22091 after the adjustment loops. This suggests paired state management, but locking, interrupt masking, restoration, and exclusion are inferred possibilities, not established effects.

The notification record is locally provided storage. No explicit ownership transfer is shown. Its address is valid for the synchronous call under the ordinary local-storage lifetime assumption; retention beyond the function’s return requires an external lifetime contract. The caller’s post-call use of the second word makes in-call mutation observably significant.

No explicit allocation or deallocation appears. Dependencies’ allocation, release, and ownership behavior remains unknown.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example specifies mutation, assume valid storage and stable relevant references and contents.

1. **Status before immediate return.** With status bit 7 clear, a nonzero eligibility field, and an initial drain observation of zero, store one to the status destination and return zero. No eligibility or adjustment dependency is called.

2. **Rejected eligibility still captures a reference.** If F-unmapped-03 returns nonzero, read the current-count global reference before selecting drain processing. Do not calculate the normal target or dereference that captured count address on this path.

3. **Stable floor behavior.** With eligibility passing, bit 0 set, bits 3, 5, and 7 clear, requested value five, and a stable zero limit, calculate target one. Setting bit 7 changes the target to zero.

4. **Changing limit.** With bit 0 set and requested value five, suppose the comparison reads limit three and the selected-value read obtains nine. With no later override, target nine results, not three or five.

5. **Flag precedence.** With bits 3 and 5 set and bit 4 clear, target one results. Setting bit 4 changes it to zero. Any reached bit-0 limit accesses still occur before this override.

6. **Fresh early-return value.** If the early comparison observes target seven at one current-count address, but the return access resolves to a count of eleven, return eleven without adjustment.

7. **Different drain addresses.** If the captured drain address contains zero but the fresh initial check observes a nonzero count elsewhere, notification and token calls still occur. The subsequent drain loop immediately exits if the captured count remains zero.

8. **Sequential-loop overshoot.** For target three and captured count five, a reducing call changes the count to two. An increasing call then changes it to four. Adjustment ends without revisiting the reducing loop.

9. **Repeated countdown read.** With matching completion values, a first countdown read of two enters the decrement branch. If the second read is seven, store six and return ten. If the second read is negative 32768, the 16-bit store yields hexadecimal `7FFF`; return ten.

10. **Mutable notification result.** With matching completion values, a countdown below two, and nonzero activity, F-unmapped-05 precedes notification. F-c81f7910921f receives words 15, zero, and 22. If it writes 37 to the second word, return 37; if that word remains zero, return zero.
