## Behavior

### Selection rule

The function first reads the record’s byte at `0x60` and converts it to an integer. It then reads the object’s 32-bit word at `0x48` and tests mask `0x08000000`, corresponding to bit 27 when the least significant bit is numbered zero.

The selected pair is:

| Tested flag | Dependency argument 5 | Dependency argument 6 |
|---|---|---|
| Clear | Integer zero | Integer conversion of the initial byte read at `0x60` |
| Set | Integer conversion of a subsequent byte read at `0x60` | Integer conversion of the byte read at `0x61` |

No other flag bits affect the selection.

In the flag-set branch, the initial value read from `0x60` is replaced. The function reads `0x61` first and then reads `0x60` again. Thus, it does not simply reuse the initial byte read.

For stable ordinary memory, the flag-set branch selects the bytes at `0x60` and `0x61` in that order for arguments 5 and 6. That description does not eliminate the earlier read or change the actual read ordering.

These are conditional acceptance cases derived from static evidence, not executed tests. Unless otherwise stated, memory is stable, addresses are valid, accesses succeed, and the dependency returns normally.

Suppose the flag word is `0x08000000`, the byte at `0x60` is 7, and the byte at `0x61` is 12.

The dependency must receive 7 and 12 at positions 5 and 6. Before the call, the established byte-read sequence is `0x60`, then `0x61`, then `0x60`, with the flag-word read between the first two byte reads.

A flag word of `0x00000001` selects the clear-flag behavior. A flag word of `0x08000001` selects the set-flag behavior.

The branch depends only on whether mask `0x08000000` has a nonzero intersection with the word.

The initial 7 does not become a dependency argument in this case. This example does not assert that unsynchronized concurrent modification is defined.

An unconditional requirement for either result would exceed the available evidence.
