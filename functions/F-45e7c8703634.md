# F-45e7c8703634

## Purpose

F-45e7c8703634 performs a repeating sequence of indirect calls and fixed-width memory transfers. The supplied static representation contains an unconditional back edge, no ordinary return, and no explicit termination condition.

The established behavior is an ordered interaction with externally supplied state. Each completed iteration invokes 37 dependency sites, performs 15 explicit memory writes, encounters a software breakpoint, and changes state carried into the next represented iteration.

A record-maintenance interpretation is plausible but **inferred intent only**. The evidence does not establish an application-level purpose, object model, scheduling role, or resource-management protocol.

This contract describes the supplied representation. Progress beyond any call, memory access, or breakpoint is conditional on that operation allowing execution to continue.

## Interface

### Declared and implicit interface

There are no declared parameters or return value. There is no visible error result.

The behavior nevertheless requires these implicit inputs:

- A link-like incoming value used to form the first indirect call target.
- A register-backed memory base used for several accesses and subsequently reduced by 244 bytes.
- Another incoming register value used in a late byte-store address.
- Two global slots supplying address-bearing values at different points in an iteration.
- Memory reachable through fixed addresses, loaded values, and dependency results.
- Additional register outputs associated with three dependency calls.
- The execution behavior of all indirect dependencies.

The additional register outputs are not established ordinary return values. Their availability depends on an unresolved machine-level calling convention.

### Widths and arithmetic

The visible accesses have widths of 8, 16, or 32 bits. Three dependency results are represented as 64-bit values, each separated into low and high 32-bit words.

Unsigned halfword loads produce values from 0 through 65,535. When subsequently stored as words, these values are zero-extended. Halfword and byte stores retain only the low 16 or eight bits, respectively.

Address calculations and the transformations described below use a **32-bit bit-pattern model**. Within that model, high bits lost through addition, multiplication, or left shift are discarded. The right shift used to extract six bits is logical.

Some supplied expressions have signed types. The evidence does not independently establish executable-language overflow semantics. Consequently, modular examples describe the represented transformations, not a guarantee that arbitrary signed source-language operations are defined.

Endianness, alignment requirements, address validity, permissions, and access atomicity are not established.

## Behavior

### Ordering and dependency notation

F-01 through F-37 are opaque dependency identifiers assigned to call sites in execution order. They do not establish distinct target identities: two sites could reach the same function.

The phases below occur in order. Within each phase, the stated calls, reads, and writes retain their described ordering. A later memory read occurs after preceding dependency calls return and can observe their effects.

Captured values are not visibly reloaded merely because a later call occurs. This is a property of the supplied representation, not an assumption that unknown callees preserve globals, registers, or memory.

### Opening calls and primary updates

Each iteration begins with fresh zero-valued byte state. F-01 is called with two explicit zero arguments. Its target is formed by adding 4094 to the represented link-like value.

F-02 and F-03 follow. Only after those calls does the function read the primary base from the first global slot. F-04 then runs, followed by F-05, whose represented 64-bit result becomes the first pair.

F-06 receives two explicit 32-bit arguments: the first pair’s low word, and the sum of its high and low words. The byte addend also present in the represented sum is zero at this point. The second argument therefore has the bit pattern of that two-word sum reduced to 32 bits.

After F-06 returns, an additional byte-valued register output is stored at primary base plus 17. F-07 follows, after which a zero byte is stored at primary base plus 21.

F-08 supplies a 16-bit ordinary result and an additional address-bearing register output. The result is stored as a halfword at that additional output plus 12.

The two primary-base stores use the value captured before F-04. There is no intervening reread of the first global slot.

### Second-pair transfers

F-09 supplies the second pair. A zero halfword is written at its high word plus 44. Next, a word containing the top six bits of its low word is written at iteration base plus 620. This stored value is between zero and 63.

F-10 runs before a word is read from iteration base plus 800. That loaded word is retained as a destination base. F-11 and F-12 then run, followed by a word store at the retained destination plus 84. The stored value is the second pair’s low word shifted left by two, retaining 32 bits.

F-13, F-14, F-15, F-16, and F-17 follow in that order.

Both transformations use the same captured low word. Changes to the original source of that dependency result do not cause a visible refresh.

### Fixed-memory input and breakpoint

A halfword is read from address 0x21C48994 and zero-extended to form the narrow base. F-18 runs next. A word is then read at iteration base plus 640 and supplied as the explicit argument to F-19.

After F-19 returns its 32-bit result, the function encounters a software breakpoint with immediate value 0x92. No continuation behavior is established for that breakpoint.

If execution continues, the captured F-19 result is shifted left by two for later use as a byte offset. The represented constant calculation also produces 0x21C4: shifting 0x21C48960 right by 18 gives 0x871, and multiplication by four gives 0x21C4.

A word read at narrow base plus 68 supplies the record base. The narrow base is the numeric value of a halfword, not a full-width pointer loaded from the fixed address.

### Intermediate calls and table updates

F-20 runs, followed by F-21. Its 32-bit result is retained. A word is then read at narrow base plus four. F-22 receives the retained F-21 result as its first explicit argument and this newly read word as its second.

The table base is read from the second global slot after F-22. F-23 then runs. A halfword store uses the table base plus the shifted F-19 result as its destination; its value is the low 16 bits of the table base itself.

After F-24, a word is read from address 0x2218 and retained as another address-bearing value. This fixed address is 0x21C4 plus 84.

F-25 then returns a 32-bit address-bearing value. A halfword containing 0x21C4 is written at that returned value plus four.

F-26 and F-27 follow. Finally, a halfword is read at the address retained from 0x2218, plus 52. Its zero-extended value becomes the selection.

There is no visible range check for the table offset, no validation of the returned F-25 destination, and no rejection of a zero narrow base.

### Final-pair transfers and base transition

F-28 supplies the final pair. Its low word is first stored as a word at iteration base plus 600. A halfword read at the final pair’s high word plus 20 then supplies the field value.

The later transfers use three derived quantities: the final pair’s low word shifted left by six, its high word multiplied by four, and the selection multiplied by four.

The register-backed base is explicitly reduced by 244 bytes before the next store. That next store writes the final pair’s low word as a word at selection multiplied by four, plus 116. This address does not include the iteration base.

F-29 then runs. The field value is written as a zero-extended word at record base plus 84. F-30 runs before the same captured field value is written as a word at record base plus 100.

F-31 follows. Its additional address-bearing register output is added to the final pair’s low word shifted left by six. A halfword containing the low 16 bits of the record base is written at that address.

The base reduction occurs after all explicit accesses described using iteration base plus 620, 800, 640, and 600. The two record-field stores use one previously captured field value, regardless of later changes to the halfword from which it came.

### Final byte transfer and continuation

F-32 and F-33 run before a byte is read from the numeric address selection multiplied by five. There is no visible pointer-table dereference in that address calculation.

F-34 runs between this byte read and its destination write. The captured byte is then stored at the sum of the field value, the represented incoming register value, and 25.

F-35 follows. The final pair’s high word multiplied by four is stored as a word at record base plus 68. After F-36, the link-like state is assigned the fixed value 0x08712031.

A word is then read at the final pair’s high word multiplied by four, plus 68. F-37 receives this word as its explicit argument. If it returns, control follows the unconditional back edge.

In the represented state flow, the next iteration inherits the reduced register-backed base and the newly assigned link-like value. Its F-01 target calculation consequently produces 0x0871302F. Whether the underlying executable’s register conventions support this literal interpretation remains unresolved.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes execution reaches the relevant operations and that the stated addresses are accessible.

### Pair transformations

If the first pair has low word 0xFFFFFFFF and high word 2, F-06 receives argument bit patterns 0xFFFFFFFF and 1 under the represented 32-bit arithmetic model.

If the second pair’s low word is 0xFC000003, the word at iteration base plus 620 receives 63. The later destination-plus-84 store receives 0xF000000C. Intervening calls do not visibly replace that captured low word.

### Narrow-base boundary

If the fixed halfword input is zero, the record-base read uses address 68 and the later F-22 input read uses address four. Zero is not visibly rejected as a null sentinel.

If the input is 0xFFFF, those addresses are 0x10043 and 0x10003, respectively. The halfword input is zero-extended before address addition; these additions are not truncated to 16 bits.

### Table offset and stored-value truncation

If F-19 returns 3 and the table base is 0x1234ABCD, the table halfword destination is 0x1234ABD9 and the stored value is 0xABCD.

If F-19 instead returns 0x40000000, its represented two-bit left shift produces zero, so the table destination is the table base itself.

The separate F-25-relative halfword receives 0x21C4.

### Captured field and byte

If the field halfword is 0xFFFF when read, the two record-field word stores both receive 0x0000FFFF. A dependency changing the original halfword between those stores does not visibly change the captured value.

Likewise, F-34 occurs after the final source byte is captured. If F-34 changes that source location, the destination still receives the earlier captured byte in the represented sequence.

### Selection-derived addresses

For selection 3, the final pair’s low word is written at address 128 and the final byte source is address 15.

At the maximum selection, 65,535, those addresses are 262,256 and 327,675. Both calculations fit within 32 bits; neither performs an additional pointer lookup.

### Interruption and repetition

If the breakpoint stops execution without resumption, no later operation in that iteration occurs. Earlier completed effects remain; no cleanup is visible.

If all calls return, all accesses complete, and the breakpoint permits continuation, F-37 is followed by another iteration rather than a normal return. In the represented state flow, that iteration uses a base reduced by 244 bytes and the updated link-like state.
