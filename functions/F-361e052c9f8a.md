# F-361e052c9f8a

## Purpose

F-361e052c9f8a accepts four 32-bit words and ordinarily returns one 32-bit word. It exposes a local adjustment word to a dependency, adds a fixed offset, and selects among dependency-assisted conversion, direct bit-pattern conversion, stored boundary results, and unresolved continuation dispatch.

**Established static behavior:** the routine uses signed adjustment comparisons, classifies fields from the first two inputs, rounds and packs selected patterns, and calls dependencies in branch-specific order.

**Inferred intent:** the first two words appear to represent a wider floating-point value, with conversion to a narrower representation. Sign handling, rounding, and the result pattern `0x7f800000` support this interpretation. This contract defines word-level behavior without assuming complete compliance with any floating-point standard.

The adjustment is not necessarily stable after its address escapes. Some branch decisions are cached before dependency calls; others read the local adjustment afterward. Those distinctions are part of the contract.

Unresolved continuation behavior and dependency internals remain **documented_only**. No runtime tests have been performed.

## Interface

All explicit inputs and the ordinary result are 32-bit words.

| Input | Established use |
|---|---|
| First word | Classification, rounding, result packing, and dependency arguments. |
| Second word | Sign extraction, classification, magnitude fields, and dependency arguments. |

The first and second words retain their original values until the direct rounding path potentially increments the first word. That modified value is used for final packing on that path.

The returned word may be:

- a directly constructed pattern;
- positive zero or a sign-only pattern;
- the result of F-f040c60c1676;
- a stored boundary result; or
- the result attributed to an unresolved indirect continuation.

There is no separate visible status result.

### Widths and arithmetic

Unless explicitly described as signed:

- Values are unsigned 32-bit words.
- Addition and left shifts retain the low 32 bits.
- Right shifts insert zero bits.
- Complement operates on exactly 32 bits.

Signed comparisons interpret a word as a 32-bit two’s-complement integer. In particular, adding `0x7e` to the adjustment wraps modulo \(2^{32}\).

The direct packing path uses a signed 32-bit intermediate. Its initial value is the 32-bit sum of the sign-cleared second input and `0xc8000000`, interpreted as signed.

## Behavior

### 1. Initialize the adjustment and capture initial decisions

The routine:

1. Initializes the local adjustment from the fourth input.
2. Calls F-6006570f9428 with the first word, second word, and address of the local adjustment.
3. Adds `0x7e` to the local’s then-current contents, modulo \(2^{32}\).
4. Captures whether the resulting local word equals zero.
5. Tests whether the local word is positive under signed interpretation.

The zero decision is captured before any call to F-a2d1320ee317. The positive test also precedes that call.

Under stable local contents during these initial reads:

| Initial post-addition value | Immediate handling |
|---|---|
| Signed positive | Enter the range-processing branch without F-a2d1320ee317 or the accompanying state-mask read. |
| Zero | Call F-a2d1320ee317, read the state mask, then enter the range-processing branch. |
| Signed negative | Call F-a2d1320ee317, read the state mask, then enter dependency-assisted conversion. |

F-a2d1320ee317 receives the original first and second inputs and the stored operand pair. Its return value is unused. After it returns, the state mask is read and saved before the captured zero decision determines which branch follows.

**Aliasing distinction:** F-a2d1320ee317 may change the local adjustment through an alias retained by F-6006570f9428. That change does not replace the cached zero decision:

- An initially negative value still selects dependency-assisted conversion, even if the local becomes zero or positive during F-a2d1320ee317.
- An initially zero value still selects range processing, but that processing reads the potentially changed local adjustment.

The supplied representation does not establish atomicity between separate reads if another agent can modify the escaped local asynchronously.

### 2. Dependency-assisted conversion

This path follows an initially nonpositive positive-test outcome together with a false cached zero decision. With stable initial reads, that means an initially negative adjustment.

After F-a2d1320ee317 and the saved state-mask read, the routine:

1. Reads the state mask again and calls F-96fcc6b36b88 with that fresh value and zero.
2. Calls F-f040c60c1676 with the original first and second inputs.
3. Calls F-96fcc6b36b88 with:
   - the previously saved state mask;
   - the bitwise intersection of that saved mask and the first F-96fcc6b36b88 result.
4. If the conversion result has no bits set outside bit 31, calls F-77dd9f40f9b6 with `2`.
5. Returns the conversion result.

Both `0x00000000` and `0x80000000` trigger the notification in step 4.

The first saved mask and the fresh mask passed to the first state-related call are distinct reads. Their equality is not guaranteed. No dependency is assumed to preserve shared storage.

Changes to the escaped adjustment during this sequence do not cause the routine to reconsider its selected branch. There is no subsequent adjustment read on this path.

### 3. Range processing and boundary selection

On entry to range processing, the routine reads the local adjustment to capture two boundary flags:

- whether it is greater than `0xfe` using an **unsigned** comparison;
- whether it equals `0xff`.

It then reads the local for a **signed** comparison against `0xff`.

If the signed comparison is less than `0xff`, processing continues to direct classification. Otherwise, the upper-boundary path runs.

These are post-F-a2d1320ee317 reads when the initial adjustment was zero. Consequently, range processing is not restricted to values from zero through `0xfe`:

- A local changed to `0x100` reaches the upper-boundary path.
- A local changed to a high-bit-set word is signed negative and reaches direct classification.
- Neither case changes the earlier cached decision to enter range processing.

On the upper-boundary path, the routine:

1. Calls F-77dd9f40f9b6 with `2`.
2. Calls F-c6bfc9d0fb36 with the original inputs and the stored operand pair.
3. Reads boundary result A.
4. Reads and selects boundary result B only if the captured unsigned-greater flag is true and the captured equality flag is false.
5. Returns the selected result.

The flags are captured **before both dependency calls**. Later mutations of the escaped adjustment do not alter boundary-result selection.

With stable adjustment contents across the flag captures and signed comparison:

- `0xff` selects A.
- `0x100` through `0x7fffffff` select B.
- Signed values below `0xff`, including negative values introduced after an initially zero adjustment, bypass this boundary path.

Without stability across those separate reads, the exact rule remains the captured-flag rule above; a single coherent adjustment snapshot is not established.

Boundary-result storage is read after both calls. On the B-selection path, A is read first and then replaced by a read of B.

### 4. Direct classification

This stage is reached whenever the range-processing signed comparison is less than `0xff`. It does not otherwise use the adjustment.

The routine extracts the sign as bit 31 of the second input. It forms a classification word by XORing:

- the second input with bit 31 cleared; and
- the second input shifted left by one bit.

If either mask `0x7f000000` or `0x00e00000` selects a nonzero bit from that classification word, the direct rounding path runs. Otherwise, the exceptional-pattern path runs.

### 5. Direct rounding and packing

The signed packing intermediate is formed from the sign-cleared second input plus `0xc8000000`, retaining 32 bits.

If this signed value is less than `0x00100000`, the result is `0x00000000`. The extracted sign is discarded on this return.

Otherwise, the first input supplies:

- bit 28: guard bit;
- bits 0–27: lower discarded bits;
- bit 29: least-significant retained bit.

The first word is incremented by `0x20000000` exactly when the guard bit is set and either:

- at least one lower discarded bit is set; or
- retained bit 29 is set.

If an increment occurs and the original first word exceeds `0xdfffffff`, the signed packing intermediate is also incremented by one. The first-word addition wraps at 32 bits.

This decision has ties-to-even behavior at this retained-bit boundary. It does not establish rounding semantics on dependency-controlled paths.

After rounding:

- If the signed intermediate exceeds `0x0fefffff`, return the extracted sign OR `0x7f800000`.
- Otherwise, return the OR of:
  - the extracted sign;
  - the intermediate shifted left by three;
  - the updated first word shifted right by 29.

The carry into the intermediate is applied before the upper-range check. The intermediate’s possible positive values on this path, including that increment, do not overflow signed 32-bit range.

### 6. Exceptional-pattern handling

This path requires both classification masks to select zero.

**Second-input bit 20 clear:**

- If the first input is nonzero or the sign-cleared second input is nonzero, return positive zero.
- Otherwise, return the extracted sign.

Thus signed zero is preserved for an all-zero magnitude, while other qualifying nonzero patterns return positive zero.

**Second-input bit 20 set, first input zero, and low 20 second-input bits zero:**

Return the second input AND `0xff8fffff`.

**All remaining patterns:**

Enter unresolved continuation dispatch.

## Acceptance examples

These are conditional static expectations, not executed tests. Dependencies are assumed to return normally. Stability assumptions apply only where stated.

1. **Exact upper boundary, even if a later dependency changes the local.**  
   F-6006570f9428 leaves `0x81`; the addition produces `0xff`. If that value remains stable through boundary-flag capture and the signed comparison, F-77dd9f40f9b6 receives `2`, then F-c6bfc9d0fb36 runs, then A is read and returned. A later adjustment change during either call does not select B.

2. **Above the upper boundary.**  
   F-6006570f9428 leaves `0x82`, producing `0x100`. With stable boundary-decision reads, both boundary dependencies run, A is read, and then B is read and returned.

3. **Initially zero with no alias mutation.**  
   Leaving `0xffffff82` produces zero. F-a2d1320ee317 runs and the state mask is read. If the local remains zero through the subsequent range decisions, direct classification follows. Dependency-assisted conversion does not run.

4. **Initially zero changed to an upper-boundary value.**  
   With the same initial zero, suppose F-a2d1320ee317 changes the escaped local to `0x100`. If it stays stable through the subsequent decision reads, the upper-boundary path runs and selects B.

5. **Initially zero changed to a negative value.**  
   Suppose F-a2d1320ee317 instead changes the local to `0xffffffff`, stable through the range reads. The cached zero decision still selects range processing. The later signed comparison admits direct classification, not dependency-assisted conversion. With first input zero and second input `0x80000000`, the result is `0x80000000`.

6. **Initially negative changed to positive.**  
   Leaving `0xffffff81` produces `0xffffffff`. Even if F-a2d1320ee317 changes the local to `0x100`, the false cached zero decision selects dependency-assisted conversion. If F-f040c60c1676 returns `0x80000000`, the second F-96fcc6b36b88 call precedes notification with `2`, and `0x80000000` is returned.

7. **Rounding ties.**  
   Conditional on reaching direct classification, second input `0x3ff00000` and first input `0x10000000` produce `0x3f800000`: no increment occurs at the even tie. Changing only the first input to `0x30000000` causes an increment and produces `0x3f800002`.

8. **Continuation result remains unconstrained.**  
   Conditional on reaching continuation dispatch, a stable control word with low nibble `10` and bit `0x40` set selects the explicit argument `0x80000000`. No particular return word follows without the continuation’s contract.
