# F-07888406f55a

The supplied representation does not establish an application-level purpose. It does not justify identifying the function as an allocator, decoder, device handler, or ordinary returning service.

Under the 32-bit arithmetic interpretation defined below, the observable behavior has three principal cases:

- If both bits are clear, execution first reads and writes one 16-bit value.

Later conditional memory blocks are unreachable under this interpretation. No runtime tests have been performed.

## Behavior

### Initial selector-dependent copy

When either low selector bit is set, the initial copy is skipped.

When both bits are clear, the function:

1. Forms a destination address from the incoming source address plus the offset.
2. Reads a 16-bit value from the incoming source address.
3. Replaces its internal source-address state with the destination minus the adjustment.
4. Writes the loaded halfword to the destination.

All address calculations use the stated 32-bit model. The internal source-address replacement occurs after the read and before the store; the store still uses the previously formed destination.

If source and destination coincide, the representation still specifies a read followed by a write of the loaded value. It does not replace this case with a no-op.

No further pre-terminal memory operation is reached unless the subsequent equality requirements all succeed.

### Requirements for exceptional progression

Progression to the exceptional operation requires all of the following:

- The selector’s low two bits are clear.
- The incoming link address is zero.
- The stack-origin address shifted right by one is zero.
- The comparison word equals the offset.
- The replacement source address equals the adjustment.
- The auxiliary word is zero.
- The stack-origin address plus twice the offset is zero modulo \(2^{32}\).

The replacement-source requirement is equivalently:

\[
\text{incoming source address}+\text{offset}
\equiv 2\,\text{adjustment}\pmod{2^{32}}.
\]

The carry contribution to the final address calculation is zero on this path. The preceding equalities force the shift counts used along this progression to zero; this reduction does not require selecting semantics for an out-of-range shift.

Together, these requirements imply:

- The stack-origin address is zero.
- The offset is either `0x00000000` or `0x80000000`.
- The incoming link address remains zero at entry to the exceptional operation.

The stack-origin conclusion follows because its right shift initially restricts it to zero or one, while adding an even quantity can produce zero modulo \(2^{32}\) only from the even candidate.

These are conditions on represented machine state, not evidence that such state is valid in an actual calling environment.

### Exceptional state assignment and halfword operation

If every requirement holds and preceding accesses complete, the exceptional branch performs the architecture-specific state assignment **before either address-zero halfword evaluation and before the resulting halfword store**.

The assigned value is the stack-origin address multiplied by 64, reduced to the represented width. The enabling conditions force this value to zero.

The representation next forms an adjusted link-derived address. Under the enabling conditions, that address is also zero. It then performs an operation containing two halfword source evaluations at the incoming link address, which is necessarily zero:

- One evaluation supplies an unsigned 16-bit destination address.
- The other supplies a value to which 15 is added before a 16-bit store.

The ordering between those two source evaluations is not established. Their common placement **after the architecture-specific assignment** is established.

For stable memory, if both evaluations produce \(h\), the resulting store is:

- Destination address: zero-extension of \(h\), in the range `0x00000000` through `0x0000FFFF`.
- Stored halfword: \((h+15)\bmod 2^{16}\).

For changing memory, the values need not agree. The destination comes from the address-supplying evaluation; the stored value comes from the value-supplying evaluation. No relative evaluation order should be imposed.

If the architecture-specific assignment completes and a subsequent halfword evaluation or store faults, that assignment has already occurred in the represented sequence.
