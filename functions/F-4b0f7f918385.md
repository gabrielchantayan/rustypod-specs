# F-4b0f7f918385

## Purpose

F-4b0f7f918385 performs a sequence of input-dependent memory accesses, global-state assignments, and two indirect calls. The supplied static representation does not establish an application-level purpose, a success result, or a normal return.

Its entry-path behavior is substantially constrained by the initial input width. The first read produces an unsigned 16-bit value. The subsequent branch tests signed 32-bit overflow when adding small positive constants to that value. Overflow is impossible over the represented input range, so execution reaching this test selects the branch ending at an invalid-instruction marker.

The contract below describes that selected path. The extensive alternative continuation is statically excluded from ordinary entry under the represented widths. Neither its presence nor the invalid-instruction warning establishes that the representation faithfully describes an executable routine.

## Interface

| Input | Represented interface | Role |

| B | Pointer to a 32-bit integer location | Receives an initial four-byte store. The address four bytes beyond B is subsequently stored elsewhere. |
| C | 32-bit integer | Supplies the operand for a variable left shift whose result is interpreted as an address. |

The representation uses 32-bit integer and address values for the calculations described below. Explicit byte, halfword, and word accesses have widths of one, two, and four bytes respectively. These explicit widths do **not** establish widths for separately named globals whose declarations are absent.

The represented interface has no return value. No ordinary return is established on the selected path.

A must permit the initial two-byte read. Continuing execution requires each subsequent read, write, and call to be valid when reached.

There are no represented null checks, bounds checks, alignment checks, or memory-access validation operations. In particular:

- B must support a four-byte write.
- The shifted address derived from C must support a four-byte read.

## Behavior

### Values and arithmetic

The following notation describes captured values and computed addresses:

- **H**: the unsigned 16-bit value read from A.
- **P**: the represented 32-bit result of shifting C left by the low eight bits of H, interpreted as an address.
- **B₁**: B’s address plus four bytes.
- **V**: the four-byte value read through P after the first two stores.
- **J**: H + 0x65.
- **S**: the represented 32-bit sum of P, H, and 0x61, subsequently used in a signed right-shift expression.

The initial shift count ranges from 0 through 255. The supplied representation does not establish executable behavior for all such counts, particularly counts of 32 or greater. It also does not independently settle the target’s rules for signed left shifts, overflow, or conversion between address bit patterns and signed integers.

Explicit byte and halfword stores retain the corresponding low eight or sixteen bits. Address calculations must not be interpreted as unlimited-precision addresses when they exceed the represented address width.

### Initial access sequence

Subject to completion of each preceding operation, the order is:

1. Read H from A as an unsigned 16-bit value.
2. Compute P from C using the low eight bits of H as the shift count.
3. Store R as a four-byte value through B.
4. Store the low eight bits of H + 0x59 at address H + 0x69.
5. Read four bytes through P and capture the resulting value as V.
6. Store B₁ as a four-byte address value at H + 0x59.
7. Store P as a four-byte address value at H + 0x5d.
8. Store the low sixteen bits of B₁ at R + 2.
9. Form the values used by the branch and subsequent stores.

These accesses may alias. The store through B and the byte store at H + 0x69 precede the read producing V. Either can therefore affect V if its destination overlaps the four-byte read range.

Later writes to memory do not, merely by changing the original read location, replace the already captured V.

### Branch selection

The condition asks whether adding four to H + 0x61 causes signed 32-bit overflow.

For all possible H:

- H + 0x61 lies between 97 and 65,632.
- Adding four produces a value between 101 and 65,636.
- Neither operand nor result approaches the signed 32-bit boundary.

Consequently, execution reaching this condition selects the no-overflow branch for every represented input value. P, R, Q, and memory contents do not alter this arithmetic conclusion.

This is a reachability result, not a guarantee that execution reaches the condition. An earlier access or shift can prevent further progress.

### Selected-branch sequence before the calls

The selected branch continues as follows:

1. Store P as a four-byte value at H + 0x65.
2. Store V as a four-byte value at H + 0x69, replacing the earlier byte at that address.
3. Store the low sixteen bits of H + 0x6d at address H + 0x6d.
4. Perform a second two-byte store at the indexed address:

   **H + 0x6d + 2 × ((H + 0x65) × 0x200 + 0x12).**

   Its value is the low sixteen bits of the represented signed right shift of S by 31. The factor of two is required by the halfword indexing. This indexed address calculation fits within 32 bits for every permitted H.

5. Evaluate G for the Q update. Use the low sixteen bits of this evaluation to replace Q’s low half, retaining Q’s upper sixteen bits at that update.
6. Evaluate G again for the next operation. Store the low sixteen bits of this second evaluation through the address obtained by shifting P left by 20.
7. Assign 0x28 to the global associated with fixed address 0x00000028.
8. Assign zero to the supervisor-call state.
9. Assign the result of converting R to a 16-bit short to the global associated with fixed address 0x000897f5.
10. Form a byte-read address by XORing V with 0x0897f3a8 and multiplying the result by 0x200.
11. Read one byte at that address.

Steps 5 and 6 are distinct, ordered semantic evaluations of G. The contract does not replace them with one captured value. The Q update lies between them and may affect storage observed by the second evaluation if aliasing permits it.

The representation does not establish G’s declared access width, volatility, or the number of physical loads used to implement these evaluations. It also does not establish the relative evaluation order of the operands used to construct the replacement Q value.

For steps 7–9, the assigned values and ordering are established; the global destination widths are not. In particular, converting R to a 16-bit short on the right-hand side does not prove a two-byte destination store.

### Calls and remaining effects

After the byte read:

1. Invoke **F-indirect-01** with the byte converted through the represented character-to-integer conversion, followed by a second argument of zero.
2. Interpret its returned value as a pointer.
3. Store a two-byte zero through that pointer.
4. Invoke **F-indirect-02** with that pointer.
5. Assign 0xf484 to the global associated with fixed address 0x0000897f.
6. Assign zero to the global associated with fixed address 0x44bf9d40.
7. Read the current reset-state global and assign back its value masked with 0xff00.
8. Store a four-byte zero through Q as available at this point.
9. Assign zero to the global associated with fixed address 0x00000034.
10. Reach the endpoint marked as invalid instruction data.

The destination widths of the globals at 0x0000897f, 0x44bf9d40, and 0x00000034 are unresolved. The reset-state read and write widths are also unresolved.

The reset expression retains bits 8–15 and clears every other bit represented by the mask operation. It is not established to be an operation on a 16-bit object, nor necessarily an operation retaining that object’s “upper byte.”

Both indirect calls occur before the reset read and final Q-directed store. No dependency contract establishes preservation of Q, reset state, G, or other global storage.

## Acceptance examples

These are conditional static expectations, not executed tests.

### Zero input

If H is zero and all relevant operations complete:

- The initial shift count is zero.
- The initial byte store targets 0x69 and supplies 0x59.
- B₁ is stored at 0x59.
- P is stored at 0x5d and later at 0x65.
- V is later stored at 0x69.
- The branch selects the no-overflow path.

This requires the low-address destinations to be accessible; their existence is not established.

### Maximum unsigned halfword

If H is 65,535 and execution reaches the condition, the tested sum is 65,636 and does not overflow signed 32-bit arithmetic.

The initial shift count is 255. This example does not establish that the preceding shift has defined executable behavior; branch selection is conditional on reaching the test.

### Read after an overlapping write

If P equals B, the read producing V occurs after R has been stored through B.

If the intervening byte store does not overlap that four-byte range, and there are no additional external changes, V reflects R’s stored bit pattern. Otherwise V reflects the combined memory state at the read, subject to byte order.

### Distinct evaluations of G

Suppose Q’s upper half at the replacement operation is 0x1234 and the first G evaluation supplies low half 0xabcd. The Q update constructs 0x1234abcd.

If the second G evaluation supplies low half 0x5678, the following shifted-address halfword store supplies 0x5678—not 0xabcd. Such differing evaluations are not excluded by the representation.

The later four-byte zero targets 0x1234abcd only if Q remains that value through intervening accesses and calls.

### Reset masking without an assumed width

If the reset read supplies 0xabcd, the mask expression produces 0xab00.

If the global instead has a wider representation capable of supplying 0x1234abcd, the mask expression still produces 0x0000ab00. Bits above bit 15 are cleared, not preserved. Neither example establishes the physical access width.

### Nonreturning dependency

If F-indirect-01 does not return, the returned-pointer zero store, F-indirect-02 call, and all subsequent direct effects are not reached.

If F-indirect-02 does not return, the returned-pointer halfword zero has already been stored, but the subsequent fixed-global assignments and reset update are not reached.
