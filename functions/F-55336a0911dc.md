# F-55336a0911dc

## Purpose

F-55336a0911dc returns one of two opaque 32-bit values from addressed storage. Bit 0 of a separate 8-bit selector determines which value is returned.

The established operation is selection, not interpretation or transformation of the selected value. The function does not establish whether either candidate represents an integer, address, handle, flags, or another encoding. Likewise, it does not establish a domain-specific meaning for the selector.

## Interface

The function accepts one argument used as the base address for fixed-offset memory reads.

The supplied representation expresses that argument as an integer used in address calculations. This establishes its address-bearing role, but does not independently establish the original parameter type, calling convention, pointer width, or integer-overflow semantics.

The addressed fields are:

| Byte offset from base | Access width | Role |
|---|---:|---|
| `0x5F8` | 8 bits | Selector; only bit 0 determines the branch |
| `0x5E4` | 32 bits | Candidate selected when bit 0 is clear |
| `0x2EC` | 32 bits | Candidate selected when bit 0 is set |

Offsets are measured in bytes. They are not indices into an array of 32-bit elements.

The candidate at `0x5E4` occupies byte offsets `0x5E4` through `0x5E7`; the candidate at `0x2EC` occupies offsets `0x2EC` through `0x2EF`. The selector occupies the single byte at `0x5F8`.

### Output

The entire selected 32-bit pattern is returned. No result masking, arithmetic adjustment, sign-based decision, or fallback interpretation is shown.

Zero and `0xFFFFFFFF` are ordinary possible data values. Neither is designated as a success indicator, failure indicator, sentinel, or request to inspect the other candidate.

## Behavior

### Selection

The function obtains the selector byte and tests its least significant bit.

| Selector bit 0 | Selected candidate offset |
|---|---|
| Clear | `0x5E4` |
| Set | `0x2EC` |

The other seven selector bits do not affect this decision. In particular, this is not a test of whether the entire byte is zero.

Examples of equivalent selector values are:

- `0x00`, `0x02`, `0x80`, and `0xFE` select `0x5E4`.
- `0x01`, `0x03`, `0x81`, and `0xFF` select `0x2EC`.

There is no requirement for the selector to contain only zero or one.

### Logical read order

The supplied representation establishes two logical memory reads on a completing path:

1. The 8-bit selector read at offset `0x5F8`.
2. The 32-bit read at the candidate offset chosen from that selector value.

The selected candidate's value is then returned. There is no explicit selector reread, retry, loop, or validation after the candidate read.

The unselected candidate is not evaluated by the represented branch. Consequently, the logical result depends on the selector and the selected candidate, not on both candidate values.

This is a source-level access contract. It does not establish exact machine instructions, speculative accesses, cache effects, bus transactions, or device-memory behavior. In particular, it is not a physical no-access guarantee for the unselected address.

### Widths and arithmetic

Only fixed positive byte offsets participate in the address calculations. There is no caller-supplied length, index, stride, or count. Nevertheless, the supplied representation does not establish a portable rule for overflow or address wrapping.
