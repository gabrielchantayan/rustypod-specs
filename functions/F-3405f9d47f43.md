# F-3405f9d47f43

## Purpose

The operation has two distinct observation roles: an earlier observation determines a candidate result, and a later observation determines whether that candidate is retained or replaced by zero. The return value therefore need not describe a single snapshot of the external state.

For stable zero and one, under value-preserving arithmetic and conversion, the result is respectively one and zero. **Inferred intent:** this is consistent with inversion of a binary state. Neither a binary-only input domain nor a binary-only output range is established.

## Behavior

### Result contract

The earlier observation determines a candidate representing the amount by which that observed value falls short of unity. That candidate is converted into the signed-integer result category before the later selection decision.

Where arithmetic and conversion preserve mathematical values, the earlier observation and the candidate sum to one. This relationship is conditional: it is not a promise of arbitrary-precision arithmetic, saturation, modular signed results, or successful conversion for every possible input.

The later observation has only a selection role:

- A value strictly greater than one selects zero.
- A comparison that does not establish that strict relationship retains the previously formed candidate.

Equality with one does not select replacement. Neither does an ordinary numeric value below one. Retaining the candidate does not recalculate it using the later value.

The later comparison uses the referenced value under its applicable comparison rules. It is not established as a comparison against a version first converted into the signed return category.

### Ordering and observation consistency

Candidate formation, including conversion into the signed-integer result category, precedes the later threshold decision. Both observation roles obtain their numeric input through the external pointer.

This ordering is significant even when the eventual result is zero. The earlier access, arithmetic, and conversion are not conditionally skipped merely because a later value exceeds one. If an earlier operation prevents normal continuation, the later selection supplies no recovery guarantee.

No separately retained target address is established. The evidence therefore does not guarantee that both observation roles reach the same object. Equally, it does not establish that changing the pointer or target during an invocation is permitted.

The contract distinguishes evaluation roles, not an exact count of machine loads or externally visible bus transactions. It supplies no atomicity, memory barrier, locking, or coherent-snapshot guarantee. Ordinary shared-state changes require whatever synchronization the actual declarations and execution environment demand.

### Stable and changing state

For stable values, valid accesses, and value-preserving arithmetic and conversion:

- Zero produces one.
- One produces zero without threshold replacement.
- Negative one produces two, if that input is supported.
- A value greater than one produces zero, provided candidate formation completes normally.

Supported negative inputs can therefore produce results greater than one. The function is not established as Boolean normalization.

If differing observations are legally possible, the earlier observation remains authoritative for the retained candidate. An earlier zero followed by a later one produces one, not a freshly calculated zero. Conversely, a later value greater than one discards the earlier candidate, regardless of its value. There is no represented retry, reconciliation, or additional candidate calculation.
