# F-698e07167b62

## Purpose

F-698e07167b62 performs a fixed sequence of memory mutations using two explicit 32-bit inputs and three implicit machine-state inputs. It then transfers control to an unresolved indirect dependency with four arguments.

The supplied static representation establishes byte, halfword, and word accesses, including repeated writes, overlapping fields, fixed-address storage, and addresses derived from previously loaded words. It does not establish a higher-level purpose such as initialization, serialization, device control, or object management.

This contract describes the visible access sequence, not an inferred application operation. Successful completion is conditional on valid memory accesses, defined target arithmetic, and the behavior of the unresolved final transfer.

## Behavior

### Access model and ordering

The order below is the order represented by the supplied static evidence. It is not a claim about bus transactions, atomicity, compiler barriers, or inter-thread visibility.

Aliasing is not excluded. A write may modify a later read location, including a location reached through a different base. Consequently, a value described as “loaded” means the value at that point in the sequence, not necessarily its entry value.

### Repeated write prefix

The prefix repeatedly touches four destinations:

| Destination | Width | Written value |
|---|---:|---|
| B + `0x19` | 8 bits | a |
| A + `0x11` | 8 bits | b |
| B + `0x34` | 32 bits | Q on its first occurrence; D thereafter |
| D + `0x54` | 32 bits | P |

Within each complete repetition, the byte write relative to B precedes the byte write relative to A, followed by the word write relative to B and then the word write at the doubled-A-derived address.

The first repetition exposes Q at B + `0x34`. Later repetitions replace it with D. The prefix ends with another occurrence of the first three writes, without the fourth write before the next phase.

These repetitions are part of the visible access history. They must not be treated as a single final assignment when writes can have externally visible effects. Under ordinary, non-overlapping RAM semantics, most of their intermediate effects are overwritten.

The exact number of repeated occurrences has not been independently enumerated and is **documented_only**. This contract therefore does not establish an exact total transaction count for the prefix.

### Initial snapshots and fixed-address updates

After the prefix, the function obtains three snapshots in a specific order:

1. A 32-bit value from fixed address `0xA9`, called **G**.
2. A 32-bit value from P + `0x74`, called **X**.
3. After an intervening byte write described below, a 32-bit value from C + `0x14`, called **Y**.

The intervening write stores the low byte of twice a plus `0x30` at fixed address `0x3A`. Its byte result is equivalently:

**(2 × a + 48) modulo 256.**

The function next captures a 32-bit value from A + `0x04`, called **Z**.

These snapshots are retained for later writes or final arguments. Subsequent modifications to their source locations do not, by themselves, change the captured values.

### Initial field mutation

Using those snapshots and the entry-state byte values, the function:

- Writes a at C + `0x0D`.
- Writes `0x6C` at A + `0x08`.
- Writes b at A + `0x0D`, then at A + `0x09`.
- Stores C as a word at C + `0x54`.
- Writes the low byte of G to fixed address `0x67`.

Only after those effects does it load a 32-bit value from C + `0x44`, called **H**.

It then copies the byte currently read from fixed address `0x67` into fixed address `0x21`. This is a read of the fixed-address byte, not merely a contractual reuse of the low byte of G: aliasing or externally mutable memory can make the distinction observable.

The low byte of H is written at A + `0x10`, and H is stored as a word at B + `0x54`.

Next, a byte derived from a signed right shift of H is written at C + `0x01`. The represented shift count is the low eight bits of A. This contract does not assign a portable result to counts of 32 or greater, nor does it establish how the target handles right shifts of negative signed values.

The H word at B + `0x54` is then replaced with A.

### Word replacement and pointer discovery

After replacing that word, the function captures a 32-bit value from A + `0x40`, called **W**.

It subsequently:

- Stores Z at B + `0x74`.
- Stores W as a word beginning at A + `0x10`, replacing the earlier byte there and the following three bytes.
- Stores C at B + `0x44`.
- Reads fixed address `0x67` and writes the resulting byte at A + `0x09`.
- Writes a at C + `0x09`.
- Stores G at A + `0x44`.

Only then does it load the word at A + `0x54`, called **J**, which is subsequently used as an address base.

The byte at fixed address `0x67` is read again and written again at A + `0x09`. The two fixed-address reads are distinct observations; equality is conditional on intervening effects not changing that location.

### Linked-state mutation

The low byte of X is written at J + `0x0D`. The function then stores Y at C + `0x54`, replacing the earlier self-address word there.

Next it captures a word from A + `0x14`, called **K**. After this read, it:

- Writes the low byte of X at C + `0x11`.
- Writes the low byte of J at A + `0x09`.
- Stores J at A + `0x44`, replacing the earlier G word.

Thus A + `0x09` has several intermediate byte values. Its final visible direct write uses J, not X, b, or G. Aliasing can still cause a later access elsewhere to affect the same byte.

### Final memory operations and transfer

The final phase discovers additional addresses through C:

- A word loaded from C + `0x04`, called **L**, supplies both an address base and a doubled address.
- A 16-bit value `0x0065` is stored at twice L.
- A word loaded from L + `0x64`, called **M**, becomes another address-bearing value and a final argument.

The halfword store occurs before the load of M. If its destination overlaps L + `0x64`, it can affect M.

After M is captured, the function writes the low byte of K at J + `0x11` and stores the word `100` at J + `0x54`.

It then loads a word from L + `0x74`, called **N**, followed by a word from C + `0x64`, called **R**. These reads occur after the writes relative to J, so aliases with those writes affect the loaded values.

The last three visible writes are:

- The low byte of L at C + `0x09`.
- M as a word at R + `0x54`.
- R as a word at twice M.

The unresolved indirect dependency receives, in order:

| Argument position | Value |
|---|---|
| First | `0x72` |
| Second | M |
| Third | Y |
| Fourth | N |

The third argument is the earlier snapshot from C + `0x14`; it is not a fresh read at transfer time.

### Arithmetic boundaries

Unsigned doubling of A produces a 32-bit result, including wraparound. In particular, D + `0x54` is an address derived from the doubled numeric value of A, not an offset within an established object.

The doubled-L and doubled-M expressions are represented with signed 32-bit operands. Their behavior on signed overflow cannot be established solely from the supplied representation. A portable contract must either restrict these operands to non-overflowing cases or obtain target-specific arithmetic evidence.

Byte order is not supplied. Word and halfword values are specified by width and numeric bit pattern; their constituent byte order remains **documented_only**.

## Acceptance examples

These examples are conditional predictions from static evidence, not executed tests.

### Distinct ordinary-memory regions

Assume all relevant locations are valid, non-overlapping ordinary RAM; arithmetic is defined; and no external writer intervenes.

Before the final dependency executes:

- B + `0x34` contains D, even when Q differs from D.
- B + `0x54` contains A rather than H.
- C + `0x54` contains Y rather than C.
- A + `0x44` contains J rather than G.
- J + `0x54` contains the 32-bit value `100`.
- C + `0x09` contains the low byte of L.
- The dependency receives `0x72`, M, Y, and N in that order.

These conclusions cease to be unconditional when later destinations alias the listed locations.

### Byte truncation

If a is `0xF0`, the fixed-address write at `0x3A` stores `0x10`, because `2 × 240 + 48` reduces to 16 modulo 256.

If G is `0x123456AB`, the initial byte written at fixed address `0x67` is `0xAB`. The whole G word, not just that byte, is later written at A + `0x44`.

### Overlapping byte and word fields

Assume no unrelated aliasing. The early byte write at A + `0x10` does not determine that byte’s final value: the later word store of W begins at the same address.

Likewise, A + `0x11` initially receives b but lies within that later word store. A replacement that preserves the initial byte there would not match the visible mutation sequence.

### Snapshot versus later source changes

Suppose the word at C + `0x14` changes after Y is captured, without altering the captured execution value. The final dependency still receives Y as its third argument. It does not receive the later memory contents merely because they occupy the original source address.

### Aliasing affects discovery

If the halfword destination at twice L overlaps the word at L + `0x64`, M must be determined from memory after that halfword write. Using the entry contents of L + `0x64` would be incorrect.

### Unsupported shift count

If the low byte of A is 40, the representation requests a signed 32-bit shift with count 40. No portable expected byte at C + `0x01` is established. Acceptance requires additional target semantics rather than an assumed count mask.
