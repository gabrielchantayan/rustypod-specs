# F-59482561b347

## Purpose

F-59482561b347 copies bytes from a zero-terminated source region to a destination region, conditionally transforms each nonzero byte, and writes a final zero byte.

The apparent intent is an uppercase-copy operation. That intent is not sufficient to establish the transformation’s exact domain: the supplied comparison has an integer-promotion issue that can distinguish an ASCII lowercase conversion from a broader byte transformation.

This contract therefore separates:

- **Established static behavior:** forward source reads, conditional subtraction, forward destination writes, and zero termination.
- **Conditional arithmetic behavior:** the exact transformed values under explicitly stated byte and comparison semantics.
- **Unknowns:** missing type definitions, executable arithmetic details, allocation sizes, and runtime behavior.

No runtime tests have been performed.

## Behavior

### Read and write order

The function processes the source from its starting address toward increasing addresses.

For each iteration:

1. It reads the current source byte.
2. It tests that fetched byte for zero.
3. If the byte is zero, it exits the copying loop without writing that byte through the ordinary transformation path.
4. Otherwise, it conditionally transforms the fetched byte and writes the result to the current destination position.
5. The next iteration reads the next source position and, if it continues, writes the next destination position.

In the supplied representation, the local source pointer advances before the destination store, while the local destination pointer advances after that store. These are local cursor updates, not writes to caller-owned pointer variables.

After observing a zero source byte, the function writes exactly one zero to the current destination position and returns.

The terminator source read therefore precedes the final destination write. An empty source still requires a valid source read and a valid destination write.

### Conditional transformation

The transformation tests whether the fetched byte minus hexadecimal `61` is less than hexadecimal `1A`. If the condition holds, the value written is obtained by subtracting hexadecimal `20` and assigning the result back to the byte-sized value.

The constants correspond to:

- `61`: decimal 97.
- `1A`: decimal 26.
- `20`: decimal 32.

The supplied expression does **not**, by itself, safely establish that only values `61` through `7A` are transformed. The subtraction’s width and the comparison’s signedness matter.

#### Ordinary C interpretation with an unsigned 8-bit byte

If the byte type is an unsigned 8-bit integer and ordinary integer promotions apply, the fetched byte promotes to signed `int`. The subtraction then ranges from −97 through 158.

Under those assumptions:

- Every nonzero input from `01` through `7A` satisfies the condition.
- Inputs from `7B` through `FF` do not satisfy it.
- Selected inputs are reduced by 32 and converted back to an unsigned 8-bit value, modulo 256.
- Input zero is handled by termination before the arithmetic condition is evaluated.

Consequently:

- `61` through `7A` become `41` through `5A`.
- `20` becomes `00`.
- `01` through `1F` wrap to `E1` through `FF`.
- `21` through `60` also change.

This interpretation is broader than ASCII lowercase-to-uppercase conversion.

#### Unsigned range-test interpretation

If executable evidence instead establishes an unsigned comparison of the subtraction result at a suitable width, the condition can select only `61` through `7A`. Under that interpretation, other nonzero bytes remain unchanged.

That interpretation is **not established by the supplied source expression alone**. A consumer must not silently replace the literal promoted-arithmetic behavior with the apparent uppercase-copy intent.

### Termination and embedded output zeros

Only the fetched **source** byte controls termination.

A transformed result of zero does not stop the loop. Under the ordinary unsigned-byte C interpretation, a source byte of `20` produces an embedded destination zero, after which copying continues until a source zero is read.

Thus the number of bytes written need not equal the length later reported by a zero-terminated-string consumer.

For a stable, non-overlapping source containing \(n\) nonzero bytes before its terminator:

- There are \(n+1\) source-byte reads.
- There are \(n\) transformed-or-unchanged data writes.
- There is one final zero write.
- No byte after the source terminator is read by this body.

These counts do not apply to an initially measured source if overlapping writes change what later reads encounter.

### Overlap

The function does not snapshot the source or perform overlap detection.

With identical source and destination addresses, each source byte is read before that same position is overwritten. The final zero is also read before being written back.

With other overlapping placements, output stores can modify source bytes that have not yet been read. Subsequent iterations use those modified bytes. An overwritten terminator can extend execution; a newly written zero at a future source position can shorten it.

There is no general guarantee equivalent to an overlap-safe bulk copy. The behavior must be derived from the actual sequential reads and writes.
