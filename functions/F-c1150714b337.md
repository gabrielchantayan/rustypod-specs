# F-c1150714b337

## Purpose

F-c1150714b337 conditionally copies one 32-bit value from a selected record to caller-provided destination storage. It returns a 32-bit status identifying success, a disabled gate, or rejection by position checks.

Two byte-valued gates control processing. A signed 32-bit field in one record set supplies a position source. Subtracting one produces the position used to address a four-byte slot in another record set. Two signed 32-bit limits in that second record determine whether the position is admitted.

The destination is cleared only after both gates have been observed as nonzero. On an admitted lookup, a subsequent write replaces that zero with the selected payload.

**Established static behavior:** record selection, access ordering, field widths, admission conditions, destination writes, and normal return statuses are described below.

**Inferred intent:** the position source appears to be one-based, and the limits appear to describe available entries. Neither interpretation establishes an application-level container contract or additional bounds.

## Interface

### Inputs

- **Destination address:** identifies storage for a four-byte output.
- **Selector:** a signed 32-bit integer. Exactly 1 selects the second record in each record set. Every other value selects the first record.

There is no explicit read through the destination parameter. This does **not** mean that destination storage is never read: it can overlap an input accessed through another address.

In particular, destination storage may overlap the selected position-source field, which is read before destination initialization. Its entry contents can therefore influence the derived position and eventual status even on a path that subsequently writes the destination. Entry contents can also participate in other aliased input reads. Treating the destination as output-only requires a nonoverlap assumption not established by the function.

### Return value

The return value is 32 bits wide.

| Status | Meaning on normal return |
|---|---|
| 0 | The position was admitted, and a 32-bit payload was written to the destination. |
| 1 | A gate was observed as zero. No write through the destination parameter occurred. |
| 6 | Both gates were observed as nonzero, but the position was rejected. The destination was cleared. |

These meanings concern the function’s explicit accesses. For example, status 1 does not promise that unrelated concurrent activity left destination storage unchanged.

Invalid addresses, inaccessible storage, and platform faults are not visibly translated into these statuses.

### Externally supplied state

The function accesses two byte-valued gates and two record-set base addresses. The address-bearing quantities in the supplied representation are 32 bits wide.

For each record set:

- The first record begins at its base address.
- The second record begins 72 bytes after its base address.
- Only selector 1 chooses the second record.

Relevant fields are relative to the selected record’s start:

| Record set | Byte offset | Width and interpretation |
|---|---:|---|
| Position records | 64 | Signed 32-bit position source |
| Data records | 68 | Signed 32-bit first admission limit |
| Data records | 64 | Signed 32-bit second admission limit |
| Data records | Four times the derived position | Four-byte payload |

The first and second limits are named by their checking order, not by increasing address.

The two record sets have different access roles, but their backing storage is not established to be disjoint. Neither is destination storage established to be disjoint from either set, gate storage, or stored base addresses.

### Preconditions

Every access actually reached must address suitable storage:

- The first gate must be readable.
- If the first gate is nonzero, the selected position-source field and second gate must be readable.
- If both gates are nonzero, the destination must support a four-byte write.
- The selected data-record base is obtained after that write, including on paths with a negative derived position.
- Admission limits and payload storage must be readable when their conditional accesses are reached.

The function supplies no explicit null checks, allocation-extent checks, alignment checks, or synchronization. Logical admission does not prove that a computed address belongs to an allocation.

No destination dereference through the destination parameter occurs on a gate-disabled path. That fact does not rule out an input access to overlapping storage.

## Behavior

### Gate handling and position capture

The first observable gate access reads one byte.

If that byte is zero, the function returns 1. It does not obtain either record-set base, read the position source, inspect the second gate, or write through the destination parameter.

Otherwise, it obtains the position-record base and chooses the record according to the selector. It reads the signed 32-bit field at offset 64 and subtracts one to derive the lookup position.

For position-source values from −2,147,483,647 through 2,147,483,647, the mathematical result fits in signed 32 bits. The minimum signed 32-bit source value is an exceptional arithmetic case documented under **Uncertainties**.

The derived position is retained; the position-source field is not visibly reread. This matters when the destination overlaps that field: clearing or replacing the field later does not cause the position to be recomputed.

The function next reads the second gate as a byte. If it is zero, the function returns 1 without writing through the destination parameter. The position-source read has nevertheless already occurred.

### Destination initialization and data-record selection

When the second gate is nonzero, the function writes a full 32-bit zero to the destination.

Only afterward does it obtain the data-record base and select the first or second data record. The selector rule remains exactly the same: 1 chooses the record displaced by 72 bytes; all other values choose the base record.

Consequently, data-record selection and later reads must be understood using storage as it exists after the destination clear, not necessarily as it existed at entry. For example, destination overlap with stored data-record address information can change the address subsequently used.

Conversely, inputs already captured are not reread merely because the clear changes their backing storage. A position-source field overwritten by the clear has already supplied the retained position.

### Admission checks

For a well-defined derived position, the admission rules are signed 32-bit comparisons:

1. A negative position is rejected.
2. A nonnegative position must be strictly less than the first limit at offset 68.
3. Only after passing that comparison, the position must be strictly less than the second limit at offset 64.

Equality with either limit is rejection, not admission.

For a negative position, neither admission limit nor a payload is read. The function has already cleared the destination and obtained the data-record base; it returns 6.

For a nonnegative position, the function reads the first limit. If the position is equal to or greater than that limit, it returns 6 without reading the second limit.

If the first limit admits the position, the function reads the second limit. Equality with or exceeding that limit produces status 6.

The represented subtraction-sign and signed-overflow conditions jointly establish the signed comparisons. A contract based only on the sign of a truncated subtraction would be incorrect at signed integer boundaries.

Under stable-memory conditions, admission therefore requires:

- A nonnegative derived position.
- A first limit strictly greater than that position.
- A second limit strictly greater than that position.

A zero or negative first limit rejects every nonnegative position without accessing the second limit. A zero or negative second limit rejects every position that reaches it.

### Payload transfer

Once admitted, the function reads four bytes from the selected data-record address plus four times the derived position. It then writes that complete 32-bit value to the destination and returns 0.

The payload is copied without visible content validation or conversion. Its bits are not subjected to a signedness-based acceptance rule. A zero payload is a successful result.

There is no independent rule confining payload slots to a region before the metadata. For example, position 16 addresses offset 64, the second-limit field itself.

### Observable access order

The supplied representation establishes this logical sequence, omitting accesses whose conditions are not met:

1. Read the first gate byte.
2. Obtain the position-record base.
3. Read the selected position-source field.
4. Read the second gate byte.
5. Write four zero bytes to the destination.
6. Obtain the data-record base and select the data record.
7. For a nonnegative position, read the offset-68 limit.
8. If the first limit admits the position, read the offset-64 limit.
9. If the second limit admits the position, read the payload.
10. Write the payload to the destination.

Neither gate is visibly reread. Neither admission limit is visibly reread after payload retrieval.

This sequence describes the supplied representation’s logical accesses. It does not establish processor-level bus transactions, atomicity, or a concurrent memory-ordering guarantee.

## Side effects

The explicit destination writes are:

| Path | Writes through the destination parameter |
|---|---|
| First gate zero | None |
| First gate nonzero, second gate zero | None |
| Both gates nonzero, position rejected | One four-byte zero write |
| Both gates nonzero, position admitted | One four-byte zero write, then one four-byte payload write |

No allocation, release, retention, or ownership transfer is visible. Destination storage and all accessed backing memory remain externally managed.

There are no separate explicit assignments to gate storage, stored base addresses, or record metadata. Nevertheless, either destination write can modify such storage through aliasing.

Aliasing has effects both before and after initialization:

- **Before initialization:** destination entry contents can be read as the position source or another input. Such contents can affect a path that later clears and overwrites the destination.
- **After initialization:** later base-address, limit, or payload accesses can observe changes caused by the clear.
- **After payload retrieval:** the final destination write can alter overlapping input storage, but the function does not visibly repeat its earlier decisions.

For example, with the destination exactly overlapping the selected position-source field, an entry value of 1 yields position 0 before the field is cleared. A later successful payload write may replace the field with an unrelated bit pattern without changing the already selected payload address.

If the destination instead overlaps the payload being read, the payload read observes the effects of the preceding clear. Partial overlaps also follow the access order, although their numerical consequences depend on byte order and the overlap geometry.

There is no visible rollback or recovery mechanism. A fault after initialization is not accompanied by an established restoration of the destination’s entry value.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless a case states otherwise, assume stable nonoverlapping input and destination storage, readable inputs, writable output, representable arithmetic, and valid address formation.

| Conditions | Required normal behavior |
|---|---|
| First gate is zero; destination contains a nonzero value | Return 1 without writing the destination or accessing either record set or the second gate. |
| First gate is nonzero; second gate is zero | Read the selected position-source field before returning 1; perform no destination write. |
| Both gates nonzero; position source 0 | Derive position −1, clear the destination, and return 6 without reading either limit. |
| Both gates nonzero; position source 1; both limits 1 | Derive position 0, clear the destination, copy payload slot 0, and return 0. |
| Both gates nonzero; position source 3; first limit 2 | Derive position 2, clear the destination, and return 6 without reading the second limit. |
| Both gates nonzero; position source 3; first limit 4; second limit 2 | Read both limits, reject equality with the second limit, and return 6 with the destination cleared. |
| Both gates nonzero; position source 3; first limit 4; second limit 3 | Copy payload slot 2 after initialization and return 0. |
| An admitted payload is zero | Return 0 with destination zero; zero payload content does not imply rejection. |

Additional selection, boundary, and aliasing cases:

- **Selector handling:** selectors −1, 0, and 2 choose the first record in both sets. Selector 1 chooses the record displaced by 72 bytes in both sets.
- **Signed comparison boundary:** position source 1 produces position 0. A first limit of −2,147,483,648 rejects that position without reading the second limit. Overflow in a comparison-related subtraction does not make this an unsigned admission.
- **Metadata as payload:** position source 17 with both limits 17 admits position 16. The payload address is offset 64, so the copied value is 17 under the stated nonoverlap and stability assumptions.
- **Destination overlaps payload:** if the destination is exactly payload slot 0, position 0 is admitted, and the destination does not overlap limits or address storage, initialization makes the subsequently read payload zero. The function returns 0 and leaves that slot zero.
- **Destination overlaps position source, initial value 1:** suppose the destination exactly overlaps the selected position-source field; data records and other inputs are separate; both gates are nonzero; both limits equal 1. The function reads the entry value 1, retains position 0, clears the overlapping field, copies data slot 0 into it, and returns 0.
- **Same overlap, initial value 0:** under the preceding arrangement, changing only the destination’s entry value to 0 produces position −1. The function clears the field and returns 6 without reading either limit. Thus destination entry contents can determine success versus rejection despite a later destination write.

## Uncertainties

### documented_only: position subtraction overflow

Subtracting one from −2,147,483,648 is not mathematically representable as a signed 32-bit value.

A wrapping 32-bit interpretation would produce 2,147,483,647. Under that interpretation, the first signed 32-bit limit cannot be strictly greater than the resulting position, so the lookup would be rejected.

The supplied representation does not independently establish the applicable overflow semantics for this position calculation. The wrapping result and its consequent rejection are conditional, not unconditional requirements.

### documented_only: address arithmetic and extents

Record selection can add 72 bytes. Payload addressing multiplies the derived position by four and adds that offset to the selected data-record address.

The representation uses 32-bit address-bearing quantities but does not establish address-wrap semantics, mapped memory, or allocation extents. Successful logical admission does not supply those missing guarantees.

### documented_only: storage representation and faults

Access widths are established, but byte order, alignment requirements, and fault handling are not independently specified.

Exact-field aliasing examples above avoid requiring a byte-order assumption. Numerical results from partial overlap may require one.

### documented_only: concurrency and special storage

No locking, atomic operation, or memory barrier is visible. The logical access sequence does not establish behavior under concurrent mutation or special memory semantics such as device-backed storage.

### Inferred intent, not an additional requirement

The subtraction suggests a one-based position source. The limits suggest availability or capacity checks. These interpretations do not impose a required relationship between the limits, prohibit metadata payloads, or establish ownership.
