# F-3ac037b907a4

## Purpose

F-3ac037b907a4 performs structural checks on a descriptor-backed request, extracts supported payload forms into temporary storage, and invokes response and completion dependencies.

Its established normal-return statuses are:

- **0:** A supported request form passed the visible checks and completed its parsing branch.
- **4:** The request failed a visible structural check or selected an unsupported type or subtype.
- **7:** A prerequisite dependency returned zero.

After prerequisite success, a zero captured request-buffer address or context value instead invokes a dependency designated nonreturning.

Every normal-return path supplies a 16-bit temporary value to a response-related dependency, explicitly writes the selected status at response offset 2, and invokes an emission dependency with length 3. Response-prefix contents and successful delivery are not established.

The routine also prepares fields within a 44-byte temporary region. Structural acceptance does not establish that a setting is applied, that an external operation copies payload bytes, or that persistent state changes.

## Behavior

### Initial operations and preliminary decoding

The routine initially selects status 4. Its observable operation order is:

1. Invoke F-5f5f14cedda3 with the descriptor and retain its 32-bit result.
2. Capture the request-buffer address from descriptor offset 8.
3. Capture the context value from descriptor offset 0.
4. Capture the unsigned 16-bit total length from descriptor offset 12.
5. Invoke F-000000000001 with the address of the temporary record and size 44.
6. If the captured buffer address is nonzero and the captured length is at least two, invoke F-64e2dfdd4a5d at the buffer start and explicitly store its 16-bit result at record offset 6.

F-000000000001 has an unavailable implementation. Its arguments suggest initialization, but neither clearing nor any particular resulting byte value is established.

**The preliminary write at record offset 6 does not require full-header processing or prerequisite success.** It occurs before the prerequisite call. It therefore also occurs on qualifying paths that subsequently return status 7, reject a total length below five, or invoke the nonreturning dependency because the captured context is zero.

Descriptor capture follows the initial F-5f5f14cedda3 invocation, so mutations by that dependency can affect captured values. Later direct parsing uses the captured buffer address and length rather than reloading those fields. This does not imply that dependencies preserve the referenced memory.

### Prerequisite and nonreturning path

F-e3db96f62982 receives the result retained from the first F-5f5f14cedda3 invocation.

- A zero result selects status 7 and proceeds to the final response sequence.
- A nonzero result permits the captured-field checks.
- After a nonzero result, a zero captured buffer address or context value invokes F-a817d8d58c10.

F-a817d8d58c10 is designated nonreturning. No normal response sequence, completion invocation, or return is established after that call.

Prerequisite failure bypasses the explicit zero-field checks, but not the earlier descriptor captures, initialization-related invocation, or qualifying preliminary decode and offset-6 write.

### Full-header processing

Following prerequisite success and nonzero captured-field checks, total length below five retains status 4 and proceeds to the final response sequence.

For total length at least five, the routine performs these operations in order:

1. Invoke F-5f5f14cedda3 again with the descriptor and store its 32-bit result at record offset 0.
2. Store the 16-bit value 44 at record offset 4.
3. Invoke F-64e2dfdd4a5d again at the captured buffer start and store its result at record offset 6.
4. Read request byte 2 and store it at record offset 8.
5. Read request byte 3 and store it at record offset 9.
6. Derive payload length by subtracting four from total length.
7. Reject with status 4 if the discriminator is nonzero.

The type byte is therefore read and stored even when the discriminator rejects the request.

The second decoder result overwrites the preliminary result at record offset 6. Equality between those results is not guaranteed. The second descriptor-derived result likewise need not equal the first.

Total length is unsigned 16-bit. The subtraction is converted through an unsigned 16-bit result and then an unsigned 32-bit value. Because this path requires total length at least five, payload length is 1–65531 without underflow.

## Acceptance examples

These are conditional static examples, not executed tests.

Unless stated otherwise, parsing examples require valid accessed storage, nonzero captured buffer and context, prerequisite success, normally returning dependencies, defined temporary values where read, a zero discriminator, and the stated bytes being present when accessed. These conditions do not establish decoder byte order, actual copying, or delivery.

- **Preliminary write followed by status 7:** With a nonzero captured buffer and total length 2, the preliminary decoder result is explicitly written at record offset 6 before the prerequisite returns zero. Status 7 follows. The remaining full-header writes do not occur.
- **Preliminary write followed by short-request rejection:** With total length 4 and prerequisite success, the preliminary decoder result is written at offset 6. Status 4 follows without full-header processing, provided captured context is nonzero.
- **Two offset-6 writes:** With total length at least five, prerequisite success, and nonzero captured fields, preliminary decoding writes offset 6 before prerequisite evaluation. Full-header decoding later overwrites it, even if the discriminator then rejects the request.
- **Type 0, total length 6:** Payload bytes 18 and 52 produce scalar low 16 bits equal to 4660. The upper 16 bits are retained; status becomes 0.
- **Type 3, total length 6:** The same bytes produce scalar low 16 bits equal to 13330; status becomes 0.
- **Type 4, total length 7:** Payload length three rejects with status 4 without a type-specific decoder invocation at offset 4. Both earlier buffer-start decodes have already occurred.
- **Type 6, subtype 4:** Total lengths 6 and 37 request external transfers of 1 and 32 bytes from request offset 5 to record offset 12. Normal return selects status 0 without proving copying. Total lengths 5 and 38 reject after reading and storing the subtype.
- **Type 15:** Total lengths 5 and 36 request external transfers of 1 and 32 bytes from request offset 4. Total length 37 rejects.
- **Type 19:** Total length 5 with byte 4 zero selects status 0. A nonzero byte rejects. A longer payload also rejects, but byte 4 is still read.
- **Type 8, total length 11:** Structural checks pass. The direct read at request offset 7 precedes the 32-bit decoder invocation there; the scalar is subsequently masked to 24 bits.
- **Zero context after prerequisite success:** With a nonzero buffer and length at least two, preliminary decoding and its offset-6 write occur before the nonreturning invocation. No normal response is established.

On normally completing status-0 paths, emission precedes completion, which precedes the success-only invocation. Status-4 and status-7 paths omit the success-only invocation.
