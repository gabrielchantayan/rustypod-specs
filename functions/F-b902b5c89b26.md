# F-b902b5c89b26

## Purpose

F-b902b5c89b26 scans caller-supplied byte storage, accumulates a decimal-weighted value, applies a multiplier selected by the initial byte, and returns a signed integer.

The apparent intent is numeric conversion with optional negative polarity. The established behavior differs materially from conventional decimal-string parsing:

- Acceptance has an upper bound but no explicit lower bound.
- An initial minus sign selects negative polarity but is not skipped.
- Under the unsigned 8-bit byte interpretation, a zero byte is accepted rather than terminating the scan.
- Accumulation includes signed multiplication, unsigned arithmetic, and conversion back to a signed type.
- There is no supplied length, validity indicator, overflow check, or explicit error result.

Negative mathematical byte offsets do not, by themselves, establish negative stored accumulator values. An update can produce an unsigned value outside the signed range. That assignment’s outcome affects both the current value and every subsequent update.

## Interface

### Input and storage

The function accepts one pointer to byte-addressed storage. It starts reading at that address and advances its local scan position by one byte after each accepted position.

There is no length or end-address argument. For an execution with defined arithmetic, the caller must provide legally readable storage through the first rejected byte. That rejected byte is read but not accumulated.

A conventional null-terminated string does not establish safe termination under the baseline interpretation: its zero terminator is accepted, allowing the scan to continue into later storage.

The function does not update a caller-owned pointer object. It returns neither the stopping address nor a consumed-byte count.

### Output

The return value is a signed integer obtained by multiplying the final signed accumulator by the selected polarity.

No separate output reports:

## Behavior

### Initialization and initial-byte polarity

The signed accumulator starts at zero. The final multiplier starts at positive one.

The initial byte is inspected before scanning. If it equals `0x2D`, the ASCII minus-sign value, the multiplier becomes negative one.

This inspection does not advance the scan position. The initial byte is therefore tested again for acceptance and, if accepted, read for accumulation.

Only the initial inspection selects polarity. An interior minus sign does not change it. There is no corresponding special handling for a plus sign, and no whitespace skipping.

### Acceptance and stopping

The acceptance comparison subtracts `0x30` from the current byte’s promoted value and tests whether the result is less than ten.

Under the baseline interpretation, the subtraction ranges from −48 through 207. Consequently:

- Accepted bytes are exactly `0x00` through `0x39`, inclusive.
- Rejected bytes are exactly `0x3A` through `0xFF`, inclusive.

Digits are accepted, but so are all lower-valued bytes, including zero, common ASCII whitespace, plus, minus, and slash.

A rejected byte terminates scanning without accumulation or advancement at that position. If the initial byte is rejected, the accumulator remains zero and the function returns zero; the source-level behavior requires no access to the following position.

There is no separate termination rule for a zero byte. A readable region containing only accepted bytes supplies no stopping condition.

### Accumulator arithmetic

Each accepted position updates the accumulator before advancing the local pointer.

The arithmetic has three distinct parts:

1. The previous signed accumulator is multiplied by ten using signed arithmetic.
2. That product is combined with the current byte converted to the unsigned integer type, then with the negative constant corresponding to 48. These additions use unsigned arithmetic.
3. The resulting unsigned value is assigned to the signed accumulator.

If the signed multiplication is representable, the unsigned result is:

\[
R=(10A+b-48)\bmod U,
\]

where \(A\) is the actual signed accumulator entering this update and \(b\) is the byte observed for accumulation.

This formula establishes the unsigned computation for a given incoming signed value. It does not independently determine that incoming value after an earlier unresolved unsigned-to-signed assignment.

For example, a first accepted slash byte produces unsigned \(U-1\). That residue is established before any unresolved assignment. Whether the accumulator then becomes −1 requires a conversion rule; assumption C supplies that result.

Similarly, a first accepted plus byte produces unsigned \(U-5\). If assumption C applies, the accumulator becomes −5. A following digit-one byte then produces unsigned \(U-49\), provided the signed multiplication is representable. Without a rule establishing the first assignment’s result, the second residue is not independently established as \(U-49\). A different first result could also make the next signed multiplication overflow.

Not every byte below `0x30` causes an out-of-range assignment. After a known accumulator value of one, an interior minus gives an unsigned result of seven, which is representable under the stated width conditions.

### Conditional mathematical interpretation

Under assumption C, an update stores the mathematical value \(10A+b-48\) when that value is within the signed range and the preceding multiplication by ten is representable.

Within those conditions:

- Digits contribute mathematical offsets zero through nine.
- Accepted bytes below `0x30` contribute negative mathematical offsets.
- Every accepted position participates in decimal weighting.
- Punctuation, zero bytes, signs, and whitespace are not skipped.

This interpretation is conditional. The actual update still passes through unsigned arithmetic and assignment back to the signed type.

If the mathematical update falls outside the signed range, assumption C instead determines the signed interpretation of its unsigned residue. That does not cure an earlier signed multiplication overflow.

### Final polarity multiplication

After a rejected byte ends scanning, the signed accumulator is multiplied by the selected polarity.

A leading minus therefore has two effects: it participates in accumulation and selects a negative final multiplier.

For the bytes `0x2D 0x31 0x32 0x3A`, assumption C and adequate signed range give successive accumulator values −3, −29, and −288, followed by a return value of 288.

The first unsigned residue, \(U-3\), is independently determined under the baseline interpretation. The later numerical residues and accumulator values depend on the earlier conversions. They are not unconditional consequences of byte acceptance alone.

### Arithmetic limits

- An out-of-range unsigned-to-signed assignment requires conversion semantics not established by the supplied representation.
- Final multiplication by negative one may exceed the signed range if the accumulator is the most-negative signed value.

Assumption C addresses assignment conversion only. It does not define signed-overflow behavior.

No saturation, overflow rejection, error return, or universally wrapping result is established.
