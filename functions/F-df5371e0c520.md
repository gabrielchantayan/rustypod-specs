# F-df5371e0c520

## Purpose

F-df5371e0c520 performs a one-byte state write, selects one of two paths using a byte in separately referenced storage, and invokes exactly one dependency on a normally completing execution.

The selected path either:

- Supplies writable local storage containing copies of the third and fourth input words to F-4607f7b67300; or
- Supplies the address of a local pointer slot, together with a zero-valued argument, to F-5836e250b35a.

The established behavior is this state write and conditional dispatch. The meaning of the state byte, the selector byte, the supplied pointer, and either dependency’s work is not established. Descriptions such as “initialization,” “notification,” or “registration” would be inferred intent, not part of this contract.

## Interface

### Inputs

The function has four explicit inputs, each represented as a 32-bit word.

| Input | Established use |
|---|---|
| First word | Not read or forwarded by the visible body. |
| Second word | Not read or forwarded by the visible body. |
| Third word | Copied into a local 32-bit slot only when the selector byte is zero. |
| Fourth word | Copied into the first element of a local two-element, 32-bit-per-element array only when the selector byte is zero. |

The visible body does not interpret these input words as signed integers, addresses, flags, or handles. In the zero-selector path, the third and fourth words are copied without visible arithmetic, truncation, or conversion. All 32 bits of each are retained in its respective local slot.

### Implicit state

For this contract, the following descriptive names identify externally supplied storage relationships, not source symbols:

- **Marker pointer:** a pointer obtained from global storage and used to address a one-byte write.
- **Selector base:** a value obtained from separate global storage. The byte at an offset of two bytes from this base controls dispatch.
- **Alternate pointer:** a pointer obtained from another global location and copied into a local pointer slot in the nonzero-selector path.

These names do not establish that the underlying locations are distinct, immutable, or free from aliasing.

### Output and completion

The interface has no explicit return value. On a path where the selected dependency returns normally, this function returns normally without a further visible operation.

No status value from either dependency is captured, interpreted, or returned. The function does not establish a success or failure result through an explicit output parameter. Its observable outputs are its memory write, its dependency invocation, and any effects caused by that dependency.

### Preconditions

Defined normal execution requires:

- The global storage used to obtain the marker pointer is readable.
- The resulting marker target is writable for one byte.
- The selector base can be obtained, and the byte at offset two from that base is readable.
- On the nonzero-selector path, the global storage containing the alternate pointer is readable.
- The selected dependency can be invoked under its actual calling convention.

Any additional requirements imposed by the dependencies remain unknown. In particular, this body does not establish whether the alternate pointer must address valid data or whether the copied third and fourth inputs have valid dependency-specific meanings.

There is no visible validation of these preconditions.

## Behavior

### Common prefix

The visible body first copies the marker pointer into a local pointer slot. It then writes the value one to a single byte addressed through the globally supplied marker pointer.

Only after this byte write does it inspect the selector. It reads the byte located two bytes beyond the selector base and compares it with zero.

This order is material. The marker write is not conditional on the selector, and it precedes the selector read. If the marker target aliases the selector byte, the write can determine the branch selected by the subsequent read. A contract that samples the selector before writing the marker would not preserve the visible behavior.

The initial local pointer copy and the pointer used for the byte write are expressed as separate accesses to the global pointer value. No guarantee of a single snapshot, atomicity, or synchronization is established. Under stable ordinary memory they identify the same target; behavior involving concurrent mutation or unusual memory semantics is not specified here.

### Zero-selector path

If the byte read from the selector location is zero:

1. A local 32-bit slot receives the third input word.
2. The first element of a local two-element array receives the fourth input word.
3. F-4607f7b67300 is invoked with:
   - First argument: the address of that local array’s first element.
   - Second argument: the address of the separate local slot containing the third input word.
4. If the dependency returns normally, the function returns.

The dependency therefore receives addresses of writable local storage, not the third and fourth input words directly and not addresses of the caller’s original argument storage.

Immediately before the call, the established contents are:

| Referenced local storage | Extent visible in the body | Initialized content |
|---|---:|---|
| Array | Two 32-bit elements; eight bytes total | First element contains the fourth input word. |
| Separate word slot | One 32-bit word; four bytes | Contains the third input word. |

The array’s second element is not initialized by the visible body. Its value must not be treated as zero, a terminator, a duplicate input, or any other defined content.

The two arguments designate distinct local objects. Their relative addresses and any adjacency between them are not part of the behavioral interface. Only the array’s own two-element layout is established.

After the dependency returns, the function does not inspect either local object. Writes by the dependency to those objects are not explicitly copied back to caller storage by this body.

### Nonzero-selector path

If the byte read from the selector location is nonzero:

1. The local pointer slot is overwritten with the alternate pointer.
2. A local 32-bit word slot is set to zero.
3. The first element of the local two-element, 32-bit-per-element array is set to zero.
4. F-5836e250b35a is invoked with:
   - First argument: the address of the local pointer slot.
   - Second argument: the literal value zero.
5. If the dependency returns normally, the function returns.

The first dependency argument is a pointer to a pointer-holding local slot. It is not a direct passing of the alternate pointer’s target. At entry to the dependency, reading that slot yields the alternate pointer, absent intervening effects outside the visible body.

The two zero-initialized word locations are local state changes. Neither is passed as a separate explicit argument to F-5836e250b35a. Their existence does not establish that the dependency may reach them through the pointer-slot argument or that they form a larger argument record.

All nonzero selector-byte values select this same path. No further classification, masking, or range check occurs.

### Widths and arithmetic

The selector decision depends on a single byte. Whether that byte is interpreted as signed or unsigned does not change equality with zero.

The marker store affects one byte and writes the value one. It does not establish that adjacent bytes are cleared or otherwise modified.

The only explicit address arithmetic is the two-byte offset used to locate the selector. There is no visible arithmetic on the four input words. Pointer width, address-overflow behavior, byte order, and alignment requirements are not independently established by this body.

## Side effects

The direct shared-memory side effect is the one-byte marker write before dispatch.

Other visible writes initialize local storage. Those writes become observable to a dependency only to the extent that the dependency is given a valid means to access the relevant storage.

The function performs no visible allocation, deallocation, resource acquisition, or ownership transfer. This does not establish that either dependency lacks such effects.

The dependency arguments expose local storage whose lifetime is limited to this invocation. No supported right to retain and later dereference those local addresses is established. Whether a dependency nevertheless retains an address, stores it elsewhere, or uses it asynchronously is unknown.

Neither dependency may be assumed to preserve global state, preserve the marker byte, leave the alternate pointer unchanged, or refrain from modifying pointed-to memory. Consequently, the marker write establishes that the byte becomes one at that point in execution; it does not guarantee that the byte remains one when the function returns.

There is no visible cleanup action after either dependency call. If a dependency does not return normally, this body supplies no visible recovery, retry, alternate dispatch, or compensating write.

## Acceptance examples

These examples are conditional on valid memory access and a selected dependency that returns normally. They describe observable behavior, not runtime results.

### Zero selector with distinct storage

Given stable, nonaliasing marker and selector storage, a selector byte of zero, and third and fourth inputs of `0x12345678` and `0x89ABCDEF`:

- The marker target receives a one-byte write of one before dispatch.
- F-4607f7b67300 receives an array address whose first 32-bit element contains `0x89ABCDEF`.
- Its second argument addresses a 32-bit slot containing `0x12345678`.
- No value is promised for the array’s second element.
- F-5836e250b35a is not invoked.

### Nonzero selector

Given stable selector storage containing `0x80`:

- The marker write occurs first.
- F-5836e250b35a receives the address of a local slot containing the alternate pointer and a zero-valued second argument.
- F-4607f7b67300 is not invoked.
- The third and fourth inputs do not determine the initialized call data on this path.

A selector byte of `0x01` or `0xFF` produces the same path selection.

### Marker aliases selector

Given a marker target that is exactly the selector-byte location, with otherwise stable accessible storage:

- Even if that byte initially contains zero, the common-prefix write changes it to one.
- The subsequent selector read observes the nonzero value.
- The nonzero-selector path is taken.

### Unused inputs differ

For executions with identical relevant memory and identical third and fourth inputs, changing only the first two input words does not change the visible body’s reads, writes, or call arguments. This does not constrain behavior caused by external state changes or dependency internals.

### Dependency changes shared state

If the selected dependency changes the marker byte after the function writes one, normal return does not restore the byte. Acceptance must not require the final marker value to be one without an additional dependency guarantee.
