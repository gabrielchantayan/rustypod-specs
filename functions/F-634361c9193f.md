# F-634361c9193f

## Purpose

F-634361c9193f conditionally dispatches an indirect operation to the first non-null entry in a two-entry pointer table.

The operation is gated by two conditions, evaluated in order:

1. F-92e8c88e6cb8 returns zero when given an address derived from the input.
2. An unsigned byte at a different input-relative address equals exactly one.

If either condition fails, this function returns without inspecting the pointer table. If both pass, it examines at most two table entries. A non-null first entry takes precedence over the second. If neither entry is non-null, the function returns without an indirect call.

This is the established structural behavior. The application-level meaning of the gate, entries, and dispatched operation is unknown. In particular, the literal argument one does not establish that the operation enables, selects, releases, or destroys anything.

## Behavior

### Exact-byte gate

After a zero dependency result, the function reads one unsigned byte at input base plus 0x44.

The accepted value is exactly one. Zero and every value from two through 255 reject the gate. The evidence does not support interpreting this as a generic nonzero Boolean, a bit mask, or a test of the least significant bit.

This read occurs after the dependency returns. Consequently, if the dependency changes the byte or changes the validity of the underlying memory, the subsequent read operates on that resulting state. No pre-call snapshot of the byte is visible.

When the byte is not one, this function returns without inspecting the pointer table.

### Ordered, bounded table selection

After both gates pass, the function obtains entries through a global table-base reference.

The selection rule is:

- Read the first four-byte entry.
- If it is nonzero, select it and do not read the second entry.
- If it is zero, read the second four-byte entry.
- Select the second entry if it is nonzero.
- If both entries are zero, return without an indirect call.

No third entry is inspected. A nonzero value is sufficient for selection; the function does not first determine whether that value names a valid object.

The global table-base reference occurs in the entry-loading expression rather than being explicitly saved before the scan. The static representation therefore does not establish a stable table-base snapshot across both loads. In a setting where another actor can change that reference, both reads must not automatically be described as using one immutable table instance. Whether such concurrent changes are supported is unknown.

The table index takes only the values needed for these two entries. Its four-byte stride calculation does not approach an integer-width boundary.

### Indirect operation

The target operation is reached through a pointer at the beginning of that receiver, followed by a function-pointer slot at dispatch-table-relative offset 0x14. The indirect operation is invoked with:
