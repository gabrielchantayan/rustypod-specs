# F-82391f550ffc

## Purpose

**Established static behavior:** F-82391f550ffc performs three entry-time 32-bit stores, then enters an unconditional loop containing indirect calls, memory reads, narrow and full-width stores, and a software-breakpoint operation.

The loop repeatedly obtains values from dependencies, uses some values as addresses, and distributes truncated or shifted values to several unrelated memory locations. It does not expose a normal return path.

**Inferred intent:** The repeated writes could maintain shared records or device-facing state. The supplied material does not establish that interpretation. This contract therefore describes memory operations rather than assigning application meanings to fields.

**Scope:** All behavior below is conditional on execution reaching the relevant operation. A dependency may fail to return, alter shared memory, or transfer control elsewhere. The breakpoint may prevent the remainder of an iteration from executing.

### Width and address conventions

This contract uses:

- **Byte:** 8 bits.
- **Halfword:** 16 bits.
- **Word:** 32 bits.
- **Pair:** a represented 64-bit result divided into low and high 32-bit words.

Offsets are byte offsets. A halfword store retains the low 16 bits; a byte store retains the low 8 bits. A halfword load used numerically is zero-extended.

Arithmetic is described as the represented 32-bit machine arithmetic, retaining the low 32 bits where necessary. This is not a claim that equivalent signed expressions are portable in a high-level language. Address validity, alignment requirements, and fault behavior remain platform-dependent.

No byte order is established by the supplied material.

## Behavior

### 1. Entry-time stores

The entry sequence obtains a shared base address and calculates the second input multiplied by 512.

Its apparent store sequence is:

1. Store a base-address value as a word at a base-address-plus-input-times-256 location.
2. Store the input-times-512 value as a word at the previously obtained base plus that offset.
3. Store the previously obtained base itself as a word at exactly the same destination as step 2.

The last two stores are distinct operations. They must not be collapsed merely because the latter overwrites the former. An observer, memory-mapped device, or fault can distinguish them.

For a stable shared base, the first destination is the base plus 256 times the second input. The other destination is the base plus 512 times the second input.

**Aliasing qualification:** The supplied representation refers to the shared base more than once in the first store expression. If that store aliases the storage holding the shared base, the precise evaluations and captured values require lower-level evidence. The later two destinations use the previously captured base.

These stores execute once per invocation, not once per loop iteration.

### 2. Beginning of each iteration

At the start of an iteration:

1. F-opaque-01 is called with two explicit zero arguments.
2. F-opaque-02 is called.
3. F-opaque-03 is called.
4. A shared address is read and retained as the iteration’s early destination base.
5. F-opaque-04 is called.
6. F-opaque-05 returns a pair.

F-opaque-06 is then called with:

- The low word of that pair.
- The 32-bit sum of the pair’s high and low words.

The represented expression includes an additional byte contribution initialized to zero. No explicit intervening assignment changes that contribution.

After F-opaque-06 returns, one byte from an auxiliary output register is stored at early destination base plus `0x11`.

Next:

1. F-opaque-07 is called.
2. A zero byte is stored at early destination base plus `0x15`.
3. F-opaque-08 is called.
4. Its halfword result is stored at offset `0x0c` from an auxiliary address output associated with that call.

The early destination base is sampled before F-opaque-04. A later change to the shared address does not itself retarget these already represented stores. Dependencies may nevertheless alter the destination memory or its validity.

### 3. First pair distribution and intervening calls

F-opaque-09 returns another pair. Let its low and high words be the **first distribution value** and **first distribution address**, respectively.

The function then:

1. Stores a zero halfword at first distribution address plus `0x2c`.
2. Stores the first distribution value shifted right by 26 as a word at frame offset `0x26c`.
3. Calls F-opaque-10.
4. Reads a word-sized address from frame offset `0x320`.
5. Calls F-opaque-11.
6. Calls F-opaque-12.
7. Stores the first distribution value shifted left by two as a word at offset `0x54` from the address read in step 4.

The right shift extracts the upper six bits of the low word. The left shift discards the original upper two bits.

The frame-derived address is read between F-opaque-10 and F-opaque-11. The store uses that captured address after F-opaque-12; it is not an explicitly fresh frame lookup.

F-opaque-13, F-opaque-14, F-opaque-15, F-opaque-16, and F-opaque-17 are then called in that order.

### 4. Fixed-address read, breakpoint, and record selection

A halfword is read from address `0x21c48994`. Call its zero-extended value the **first record address**. Despite its 16-bit width, this value is subsequently used as an address.

The function then:

1. Calls F-opaque-18.
2. Reads a word from frame offset `0x280` and passes it to F-opaque-19.
3. Receives a word-sized result from F-opaque-19.
4. Executes a software-breakpoint operation with immediate value `0x92`.

No successful continuation past the breakpoint is established. The following behavior is conditional on execution resuming there.

The F-opaque-19 result is shifted left by two, producing a byte offset. A separate selector is formed by logically shifting `0x21c48960` right by 18 and multiplying by four. Its resulting value is `0x21c4`.

A word is read from first record address plus `0x44`. It becomes the **retained destination address** used later in the iteration.

Next:

1. F-opaque-20 is called.
2. F-opaque-21 returns a word.
3. F-opaque-22 is called with that returned word and a word read from first record address plus `0x04`.

The second argument’s memory read occurs after F-opaque-21 has returned.

### 5. Shared-table and selector writes

After F-opaque-22:

1. A second shared address value is read.
2. F-opaque-23 is called.
3. The low halfword of the sampled shared address is stored at that address plus the shifted F-opaque-19 result.

The address value therefore serves both as the destination base and as the source of the stored low 16 bits. There is no explicit addition of an entry width beyond the earlier multiplication by four.

Then:

1. F-opaque-24 is called.
2. A word is read from address `0x2218`, which is selector `0x21c4` plus `0x54`.
3. F-opaque-25 returns an address.
4. Halfword `0x21c4` is stored at that returned address plus `0x04`.
5. F-opaque-26 is called.
6. F-opaque-27 is called.
7. A halfword is read at offset `0x34` from the address obtained in step 2.

Call the final halfword the **second selector**. It is zero-extended before further arithmetic.

### 6. Second pair distribution and frame movement

F-opaque-28 returns a pair. Call its words the **second distribution value** and **second distribution address**.

The function performs these operations in order:

1. Stores the second distribution value as a word at current frame offset `0x258`.
2. Reads a halfword from second distribution address plus `0x14`, zero-extending it to a word. Call this the **copied field**.
3. Forms an offset by shifting the second distribution value left by six.
4. Multiplies the second distribution address by four, retaining a word-sized result. Call this the **scaled address**.
5. Moves the represented frame-like base downward by `0xf4` bytes.
6. Multiplies the second selector by four.
7. Stores the second distribution value as a word at address four-times-second-selector plus `0x74`.

The final destination is a numeric address derived directly from the selector. No additional table base is explicit.

The earlier frame store uses the frame base before the downward adjustment. The representation does not show a matching upward adjustment before the next iteration.

### 7. Final record writes and loop continuation

The iteration continues:

1. F-opaque-29 is called.
2. The copied field is stored as a word at retained destination address plus `0x54`.
3. F-opaque-30 is called.
4. The same copied field is stored as a word at retained destination address plus `0x64`.
5. F-opaque-31 is called.
6. The low halfword of the retained destination address is stored at the sum of:
   - The second distribution value shifted left by six.
   - An auxiliary address output associated with F-opaque-31.
7. F-opaque-32 is called.
8. F-opaque-33 is called.
9. A byte is read from address five-times-second-selector.
10. F-opaque-34 is called.
11. That captured byte is stored at copied field plus the incoming register-derived address contribution plus `0x19`.
12. F-opaque-35 is called.
13. The scaled address is stored as a word at retained destination address plus `0x44`.
14. F-opaque-36 is called.
15. A word is read from scaled address plus `0x44` and passed to F-opaque-37.

The byte source address is the second selector plus four times that selector. The representation supplies no separate base for this read.

After F-opaque-37, execution returns to the beginning of the loop. The represented link-register-like value has been assigned an internal continuation value before that call, so F-opaque-01’s next target is not necessarily selected from the original incoming value.

There is no visible loop-exit condition.

## Side effects

### Direct memory effects

The function directly performs byte, halfword, and word stores. Their destinations include:

- Input-indexed entry locations.
- Shared-address-derived records.
- Auxiliary dependency-output addresses.
- Frame-relative locations.
- Numeric addresses calculated from zero-extended halfwords.
- Addresses formed from shifted dependency results.

The contract preserves store widths and order. A word store of a zero-extended halfword writes four bytes, not two.

No bounds, null, alignment, or accessibility check precedes these accesses. Invalid addresses may fault before later calls or writes occur.

### Dependency effects

Every dependency may have additional effects not described by the caller body. In particular, this contract does not assume a dependency:

- Preserves shared globals.
- Preserves pointed-to memory.
- Allocates or releases memory.
- Returns normally.
- Reports errors through its nominal return value.
- Preserves registers outside a verified calling convention.

Captured values are distinguished from later shared-memory reads; this does not guarantee that captured addresses remain valid.

### Ownership and lifetime

No allocation, release, reference-count change, or ownership transfer is explicitly established. Passing or storing an address is not evidence of ownership transfer.

Memory must remain accessible until each actual access. Where dependencies run between capture and use, lifetime preservation is an external prerequisite.

### Errors and interruption

There is no explicit error result, rollback, or cleanup path. Earlier writes remain observable if a later access faults, a dependency does not return, or the breakpoint interrupts execution.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Zero second input.** With a stable valid entry base and no aliasing of the shared base’s storage, all three entry stores address the base itself. The middle store writes zero; the final store writes the base.

2. **Nonzero second input.** For second input 1 and a stable base, the first destination is base plus `0x100`; the next two destinations are base plus `0x200`. Both writes at the latter destination remain required.

3. **Upper-bit extraction.** If the first distribution value is `0xfc000003`, the frame-offset-`0x26c` word becomes `0x3f`, and the later offset-`0x54` word becomes `0xf000000c`.

4. **Narrow address-derived store.** If the sampled second shared address ends in `0xabcd`, its table store writes halfword `0xabcd`, regardless of the upper address bits.

5. **Word-width field copies.** If the copied field is `0xffff`, the writes at retained destination offsets `0x54` and `0x64` each write word `0x0000ffff`.

6. **Selector-derived addresses.** If the second selector is 3, the direct word destination is `0x80`, and the later byte source is address `0x0f`. No unstated table base may be inserted.

7. **Breakpoint stops execution.** If breakpoint handling does not resume the function, none of the subsequent record-selection or final-distribution operations is required to occur.

8. **Dependency changes a shared address.** A change after that address has been sampled does not change the captured value used by the represented later store. It may still change memory contents or invalidate the destination.
