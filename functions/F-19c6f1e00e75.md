# F-19c6f1e00e75

## Purpose

The conditional dispatch examines a field four bytes before the dependency’s result. At the source-representation level, that field is evaluated once for a null check and evaluated again within the non-null branch. The branch does not explicitly retain and reuse the pointer value obtained by the check.

These are established operations, not an established object-lifecycle protocol. A containing object, interior component, or finalization-style callback is a possible interpretation, but none is required by the evidence.

This contract describes normal completion when the required accesses and calls are valid and the called functions return normally. Invalid accesses, non-returning calls, and arithmetic outside the execution environment’s supported range have no established recovery behavior here.

### Null check and second field evaluation

After the dependency returns, the function evaluates the pointer-valued field at R − 4 bytes and compares that value with null.

If the checked value is null, the branch is skipped. There is no branch-side evaluation of the field, no dispatch-base read, and no indirect call.

If the checked value is non-null, the branch evaluates the pointer-valued field at R − 4 again. The pointer value from this branch evaluation supplies the address used for the dispatch-base read.

This is a distinction in the source-level access structure:

- The null check evaluates the field.
- The taken branch evaluates the field again.
- The branch’s subsequent dereference is expressed through that second evaluation, rather than through an explicitly saved result from the check.

The evidence does **not** establish two physical machine loads. It also does not establish volatile access, concurrent modification, or circumstances in which the two evaluations can yield different values. There is no intervening call between the check and the branch evaluation.

Consequently, a description that assumes one retained pointer for both uses omits a represented evaluation. Conversely, a description that requires two distinct machine loads or promises differing values would exceed the evidence.

It then uses that base plus four bytes as the address of a callable-target entry, reads the target, and invokes it.

The only represented null check applies to the field evaluation used by the condition. No additional check is shown for:
