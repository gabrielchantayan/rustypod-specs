## Behavior

### Ordered dispatch

The wrapper’s explicit behavior has the following observable ordering:

1. Read the integer stored at the input address.
2. Add 292 to that value.
3. Interpret the computed value as the address of a slot containing a callable address.
4. Read the callable address from that slot.
5. Invoke the loaded target once.
6. Return if that invocation returns normally.

The slot read depends on the initial integer read and the arithmetic result. The invocation depends on the slot read. There is no alternate branch, retry, fallback target, or second dispatch in the supplied body.

The initial loaded value is not itself invoked. It is used to locate a slot at the fixed displacement. Likewise, the slot’s address is not directly invoked; its contents supply the callable target.

Only one initial integer load and one callable-address load are explicitly represented. There is no explicit read of the input storage after the target returns, and no explicit redispatch based on state modified by the target.
