# F-831d80e66c03

## Purpose

F-831d80e66c03 conditionally reports two single-bit values from an object. Depending on object screening and a separate control bit, it either returns zero directly or evaluates up to two dependencies before reaching an unresolved indirect transfer.

Three outcomes are established by the supplied static representation:

- An absent object, or an object whose stored function pointer matches a comparison value read from global storage, causes optional zero-byte output writes and a zero return.
- An eligible object supplies two optional byte outputs. If its control bit is set when examined, the function then returns zero.
- An eligible object whose control bit is clear causes short-circuited dependency evaluation. An unresolved indirect target receives zero or one, and the 32-bit result attributed to that target becomes the function’s result.

“Eligible,” “status,” and “control” describe operational roles only. The object’s application-level meaning, the significance of the comparison values, and the semantics of the dependency results are unknown.

## Interface

The function accepts three arguments:

| Argument | Representation and use |
|---|---|
| Object reference | A 32-bit integer in the supplied representation, used as an object base address. Zero denotes absence. |
| First output address | Optional writable address receiving one byte. Zero suppresses this output. |
| Second output address | Optional writable address receiving one byte. Zero suppresses this output. |

On the eligible-object path, omitting an output also suppresses the status-byte read associated with that output. Output omission does not suppress object screening, the later control-byte read, or otherwise reachable calls.

The integer representation of the object reference does not establish a portable integer-to-pointer interface. Address interpretation must be valid for the original execution environment.

### Object and global storage

The supplied representation treats the object field and global values as function pointers. Their storage width and alignment requirements are not independently established. The status and control fields are separate eight-bit bytes.

### Result and arithmetic

The result is 32 bits. Direct-return paths produce zero. The indirect-transfer path returns the 32-bit result attributed to the target, without visible Boolean normalization.

The identified dependencies return values represented as 32-bit integers. This function uses only whether each result equals zero.

The object offsets are byte offsets. No bounds check or address-overflow handling is visible. Normal completion requires the reached address calculations and accesses to be valid in the original environment; the representation does not establish a portable wrapping rule for invalid address arithmetic.

For output extraction, the first value is status bit 0. The second value is status bit 1 shifted into bit 0. Both resulting byte values are exactly zero or one; neither operation can produce a larger output value.

## Behavior

### Screening and global-read order

For a zero object reference, the function performs no object-field read and reads neither global comparison slot. It proceeds directly to the zero-output path.

For a nonzero object reference, screening has this established order:

1. Load the function pointer from object offset `0x198`.
2. Read the first comparison value from global storage.
3. Compare the loaded object pointer with that first value.
4. Only if they differ, read the second comparison value from global storage and compare the same loaded object pointer with it.

Equality with either value selects the zero-output path. The second global read is absent when the first comparison matches.

An object is eligible only when its reference is nonzero and its loaded function pointer differs from both global values as read during this screening.

All screening reads precede output writes and dependency calls. The function does not reload the object’s pointer field, reread either comparison slot, or repeat screening after those later effects.

The comparisons use values obtained at separate read points. No synchronization or simultaneous snapshot of the object field and global slots is established.

### Zero-output path

An absent object or a screening match produces these effects in order:

1. Write one zero byte to the first output, if supplied.
2. Write one zero byte to the second output, if supplied.
3. Return the 32-bit value zero.

Neither object byte at `0x18c` or `0x18d` is read on this path. No identified dependency or unresolved indirect target is invoked.

Screening may already have required object and global reads before a match selects this path. In particular, matching the second global value requires both global reads; matching the first requires only the first.

### Eligible-object outputs

For an eligible object, the optional output operations occur in argument order:

- If the first output is supplied, read the byte at object offset `0x18c`, extract bit 0, and write the resulting zero or one to that output.
- If the second output is supplied, read the byte at object offset `0x18c` again, extract bit 1, and write the resulting zero or one to that output.

These are separate conditional reads, not a shared initial snapshot. Bits 2 through 7 do not contribute to either output.

If both outputs are omitted, neither status-byte read occurs. If the first write changes the source of the second read, the second output reflects the changed byte.

If both outputs designate the same external byte and do not affect the object, both writes still occur. The second write determines that byte’s final value before subsequent calls.

### Control decision

After completing both optional output operations, the function reads the byte at object offset `0x18d` and tests mask `0x40`.

If that bit is set, the function returns zero without invoking either identified dependency or the unresolved indirect target. Other bits in the control byte do not affect this decision.

If the bit is clear, dependency evaluation begins.

Because this read follows the output writes, an output that overlaps the control byte can change the branch. The entry value is not preserved for this decision.

### Dependency evaluation

F-773adfd603a0 is called first with the original object reference.

- A nonzero result suppresses F-e4be99d1b0d1 and selects indirect argument zero.
- A zero result causes F-e4be99d1b0d1 to be called with the original object reference.

When the second dependency is called:

- A nonzero result selects indirect argument zero.
- A zero result selects indirect argument one.

Thus, one is selected only when both dependencies are called and both return zero. All other normally returning dependency-result combinations select zero.

The function does not repeat screening, reread the status or control bytes, or rewrite the outputs between these calls. Nevertheless, dependencies may change the object, globals, output storage, or state relevant to the indirect transfer. No preservation contract is supplied.

### Indirect transfer and return

After dependency evaluation completes normally, the supplied representation shows an unresolved indirect transfer with one argument: the selected zero or one.

The representation treats this transfer as a call and attributes a 32-bit return value to it. F-831d80e66c03 returns that value without visible transformation.

The selected argument is not itself the enclosing function’s return value. Passing one does not establish a return of one; passing zero does not establish a return of zero.

The target’s identity, resolution mechanism, full calling convention, and precise call-versus-tail-transfer mechanics remain documented_only.

## Side effects

### Direct effects and ordering

The visible function can perform:

- One object function-pointer load.
- One or two global comparison-value reads, according to screening.
- Up to two status-byte reads and corresponding one-byte output writes.
- One control-byte read.
- One mandatory and one conditional dependency call on the control-clear path.
- An unresolved indirect transfer after those dependency results.

On the nonzero-object path, screening reads precede every output write. On eligible paths, output writes precede the control read, which precedes all calls.

No direct allocation, deallocation, explicit global assignment, or ownership transfer is shown. Writes through caller-supplied addresses can nevertheless modify global storage if the addresses designate it. Calls may have additional effects that are not established here.

There is no visible rollback or restoration of earlier writes.

### Aliasing

The function establishes no non-aliasing guarantee.

Important consequences include:

- First-output and second-output writes occur in that order.
- A first output overlapping the status byte can change the second status read.
- An output overlapping the control byte can change whether calls occur.
- An output overlapping the stored object pointer changes its storage after screening, but does not cause a new pointer load or comparison.
- An output overlapping a global comparison slot writes there after the screening reads. That write does not retroactively alter screening, although later dependencies or other observers may see it.

The last case does not establish how a one-byte change affects a function-pointer value; pointer layout and representation are unresolved.

### Ownership and lifetime

The visible body does not retain either output address for later use and performs no explicit release of the object or output storage.

The original object reference is passed to the identified dependencies. Their ownership, retention, release, and lifetime effects are unknown. In particular, this contract does not assume that the first dependency preserves the object for the second.

After dependency evaluation begins, the visible body performs no further direct object-field reads. A second dependency can still receive the original reference even if the first dependency has changed its lifetime or contents.

### Errors and abnormal completion

No explicit error status, validation failure branch, exception handler, or recovery mechanism is visible.

Zero is not a unique success or failure indication: multiple ordinary paths return zero, and the unresolved target may also return zero.

Invalid memory, invalid pointer representations, unavailable call targets, and dependencies that fail to return normally have no established recovery behavior. Earlier output writes are not visibly undone.

## Acceptance examples

These are conditional static expectations, not runtime observations. Unless stated otherwise, storage is valid, outputs are separate from the object and globals, no concurrent mutation occurs, and reached calls return normally.

1. **Absent object.** With a zero object reference and both outputs supplied, the function writes zero to the first output, then zero to the second, and returns zero. There are no object reads, global comparison reads, or calls.

2. **Absent object with omitted outputs.** With all three arguments zero, there are no object reads, global comparison reads, or output writes. The result is zero.

3. **First global match.** For a nonzero object, the pointer field is loaded before the first global comparison value is read. If they match, the second global slot is not read. Supplied outputs receive zero, and the function returns zero without reading status or control.

4. **Second global match.** If the loaded pointer differs from the first global value, the second global value is read next. If that value matches, supplied outputs receive zero. Neither object byte is read and no dependency is invoked.

5. **Eligible object with omitted outputs.** If the loaded pointer differs from both global values, both global reads occur. With both outputs omitted, no status-byte read occurs; execution proceeds to the control-byte read.

6. **Bit extraction with control set.** For an eligible object with status byte `0xFE` and control bit `0x40` set, the first output receives zero and the second receives one. The function returns zero without calls.

7. **Both dependency results zero.** For an eligible object with control bit clear, zero results from both dependencies select argument one for F-UNKNOWN-01. If that target returns the 32-bit pattern `0x12345678`, the enclosing function returns that same pattern.

8. **First dependency nonzero.** Any nonzero result from F-773adfd603a0 suppresses F-e4be99d1b0d1 and selects argument zero for F-UNKNOWN-01. The enclosing return still depends on the unresolved target’s result.

9. **Second dependency nonzero.** A zero first result followed by a nonzero second result causes both dependencies to run in order and selects indirect argument zero.

10. **Outputs alias each other.** With unchanged status byte `0x01` and both outputs pointing to the same external byte, the function writes one and then zero. That byte is zero immediately afterward.

11. **First output aliases status.** With initial status byte `0x02`, a first output pointing to that byte receives zero and overwrites it. A separate second output then receives zero from the subsequent read, not one from the entry value.

12. **Output aliases control.** For an eligible object, an output pointing to the control byte writes zero or one before the control read. Either value clears mask `0x40`, so dependency evaluation is reached even if that bit was initially set.

13. **Output changes comparison storage after screening.** If an eligible invocation writes an output into writable comparison-slot storage, screening has already used the required global values. The function does not reread those slots or reconsider eligibility. Effects on later observers remain dependent on their behavior.
