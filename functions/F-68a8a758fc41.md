# F-68a8a758fc41

## Purpose

The supplied static representation describes an ordered sequence of address-dependent memory reads and writes, with a conditional invalid-instruction termination marker and a final unconditional marker. It does not establish an application-level purpose.

Visible effects include pointer propagation, low-address writes, overlapping stores of different widths, repeated stores, and writes to addresses derived from dependency-symbol values. No dependency invocation is visible.

This is a **documented_only** contract. The supplied representation warns of invalid instruction data and overlapping global symbols. Two displayed shifts also have unresolved semantics. Consequently, the contract distinguishes the displayed access sequence from any claim that a real execution can traverse it successfully.

An interpretation as initialization, exception-vector configuration, or device setup would be inferred intent, not established behavior.

### Initial propagation

A halfword store to the sum of the two implicit register values writes the low 16 bits of the first register-associated value. Next, a word is read from the table base plus the selector bitwise-ORed with `0x88`; a byte is then read from the second register-associated value plus that same OR-derived offset. The offset uses OR, not addition of `0x88`.

The captured table word is written at fourth argument plus 8. The fourth argument is then written as a word at selector plus `0x40`, followed by a word store of the captured table value at working base plus `0x74`.

Only after those stores does the procedure read a word from fourth argument plus `0x28`, followed by an opaque word from working base plus `0x5c`. Earlier writes can therefore affect either read through aliasing.

Three byte stores follow, in order:

- The low byte of the working base goes to captured table word plus 3.
- The previously read byte goes to working base plus `0x10`.
- The low byte of the opaque word goes to an address equal to the zero-extended captured byte plus `0x1c`.

The last destination is between `0x1c` and `0x11b`; it is not relative to the working base.

### First dependency symbol and conditional termination

A separate signed right shift by 31 produces a sign-derived halfword: `0x0000` for a nonnegative 32-bit symbol value and `0xffff` for a negative one, under arithmetic signed-shift semantics.

If the symbol value is negative, the displayed path reaches an invalid-instruction termination marker. No later operations are shown for that branch.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Initial field update.** If the initial accesses succeed, the captured table word is written at fourth argument plus 8 before the word read at fourth argument plus `0x28`. Aliasing with preceding stores can affect that later read.

2. **Negative first symbol.** If F-e47d7b2e9c88 has its sign bit set and execution reaches that phase, a halfword `0xffff` is stored at companion plus 4 before the conditional termination marker. The later companion-plus-`0x12` stores are not shown on this branch.

3. **Repeated nonnegative-path accesses.** If the first symbol is nonnegative, the two self-addressed word stores are distinct, with a signed halfword read between them. A captured halfword `0xffff` produces a later word `0xffffffff` under arithmetic signed-shift semantics; `0x7fff` produces zero.

4. **Array boundary.** Direct halfword initialization covers byte offsets 4, 6, and 2, not offset 0. Absent aliasing changes, the word-store destination derived from offset 0 depends on its pre-existing contents.

5. **Low-address selection.** Clearing bit 2 of the first symbol selects word destinations `0x5c` and `0x170`; setting it selects `0x60` and `0x180`.

6. **Independent scaled destinations.** Suppose the stack pointer has numeric value `0x1000`, the later captured global word is `0x2000`, arithmetic supports these addresses, and no relevant mutation intervenes. The scaled-pointer sequence writes `0x4000` at `0x4000`, then the reduced value at `0x4004`. The independent scaled-global store writes `0x8000` at `0x8000`, not at `0x4000`.

7. **Fresh global read.** If `0x0897ea80` changes after the self-addressed store but before the following destination read, the reduced-value store uses the newly read word plus 4. It is not constrained to the originally assigned scaled-pointer address. Separate destination and value reads for the preceding store also need not agree under external mutation.

8. **Completion.** If every preceding operation is reached and succeeds, the final assignment of `0x5c` precedes an invalid-instruction marker, not an ordinary return.
