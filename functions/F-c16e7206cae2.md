# F-c16e7206cae2

## Purpose

F-c16e7206cae2 accepts two 32-bit words and produces a 64-bit result. Its visible behavior consists of three paths:

- A direct zero result for one range of signed upper-word values.
- A shift-based result for a bounded range of nonnegative upper-word values.
- Saturation or configuration-dependent indirect dispatch for the remaining inputs.

**Inferred intent:** the input words appear to encode an IEEE 754 binary64 value, with the first argument containing the low 32 bits and the second argument containing the high 32 bits. Under conventional register-shift semantics, the ordinary numeric paths behave like conversion to an unsigned 64-bit integer: truncate nonnegative finite values toward zero, map negative numeric values to zero, and saturate positive overflow to the largest unsigned 64-bit value. NaN encodings reach configuration-dependent handling.

That interpretation is not an established interface declaration. The word-level contract below is primary. In particular, the supplied representation does not establish oversized-shift semantics, the meaning of the configuration data, or the identity and ABI of the indirect dependency.

## Interface

### Inputs

The visible interface has two explicit arguments:

| Argument | Width | Interpretation in this contract |
|---|---:|---|
| Lower word | 32 bits | Unsigned bit pattern, denoted \(L\) |
| Upper word | 32 bits | Signed two’s-complement value, denoted \(H\); its unsigned bit pattern is denoted \(U\) |

There are no explicit pointer arguments, lengths, output buffers, or ownership-bearing objects.

The exceptional path also uses an incoming execution-context value that is not an explicit argument. The visible indirect target is obtained by clearing its two least significant bits. Whether this represents a genuine callable dependency or an incorrectly reconstructed control transfer is unresolved.

### Output

The ordinary paths return a 64-bit bit pattern. Where described as a pair \((R_{\mathrm{high}}, R_{\mathrm{low}})\), its numeric value is:

\[
R_{\mathrm{high}}\,2^{32}+R_{\mathrm{low}}.
\]

This describes word significance, not memory byte order or a fully established machine calling convention.

Indirect-dispatch paths return the 64-bit result attributed to the indirect dependency. No normalization, saturation, or other postprocessing of that result is visible.

### Arithmetic conventions

Unless otherwise specified:

- Word-level bit operations use 32-bit bit patterns.
- Unsigned addition, multiplication, and left-shift results are reduced modulo \(2^{32}\).
- The signed right shifts used to extract fields are treated as sign-extending, consistent with the supplied representation.
- A 32-bit complement flips all 32 bits.
- Logical right shifts fill with zeros.

Oversized shifts require a separate qualification. The visible representation uses shift counts of 32 or greater on ordinary conversion paths. Their target-level meaning is not established by the supplied material. Conditional results under a zero-on-oversized-shift rule are identified below rather than assumed silently.

## Behavior

### 1. Classification and initial significand construction

The upper word is classified using:

\[
E = H \mathbin{\mathrm{arithmetic\ right\ shift}} 20.
\]

Thus \(E\) ranges from \(-2048\) through \(2047\).

A 32-bit high significand fragment is formed from:

\[
A = ((U \ll 11)\bmod 2^{32}) \mathbin{\mathrm{OR}} (L \gg 21).
\]

When \(E\ne0\), bit 31 of \(A\) is additionally set. When \(E=0\), that bit is not explicitly inserted.

The complementary low fragment is:

\[
B=(L\ll11)\bmod2^{32}.
\]

These fragments account for the input bits used by the shift-based return path. They do not imply any reads from input-addressed memory.

### 2. Immediate zero range

When \(E<0\), the function compares the signed quantity \(H+0x40000000\) against \(-0x00100000\).

The immediate-zero condition is equivalently:

\[
H < -0x40100000.
\]

For these inputs, the result is exactly zero. The lower word does not affect this decision.

The addition is representable throughout this branch: \(H\) is negative, so adding \(0x40000000\) cannot overflow a signed 32-bit value.

Negative upper-word values outside this immediate-zero range continue to the saturation-or-dispatch classification. They do not enter the shift-based conversion path.

### 3. Shift-based return range

For \(E\ge0\), the shift-based return is selected when:

\[
E-78<1009,
\]

equivalently:

\[
0\le E\le1086.
\]

The initial shift distance is \(1086-E\). Distances greater than 79 are replaced with 80. Consequently, the effective distance is:

\[
s=
\begin{cases}
80,&0\le E\le1006,\\
1086-E,&1007\le E\le1086.
\end{cases}
\]

The resulting distance is always between 0 and 80.

The visible return combines right shifts of \(A\) and \(B\), plus a cross-word contribution:

- The result’s high word is \(A\) logically shifted right by \(s\).
- The low word includes \(B\) logically shifted right by \(s\).
- For \(0\le s\le31\), the low word also includes \(A\) shifted left by \(32-s\).
- For \(32\le s\le80\), the low word instead includes \(A\) logically shifted right by \(s-32\).
- Contributions to the low word are combined with bitwise OR.

The visible shift expressions mask their shift counts to eight bits. This does **not** establish modulo-32 shift behavior.

For \(1\le s\le31\), all participating shifts are below 32, and the result is the ordinary logical right shift by \(s\) of the 64-bit pair \((A,B)\).

For other distances, at least one expression has an oversized count. Under a rule in which logical shifts by 32 or more yield zero, the complete path is equivalent to:

\[
R=((A\,2^{32})+B)\gg s.
\]

Under that rule:

- \(s=0\) returns \((A,B)\).
- \(s=32\) returns \((0,A)\).
- \(32<s<64\) returns the appropriately shifted portion of \(A\) in the low word.
- \(s\ge64\) returns zero.

Those boundary results are conditional on the shift rule, not independently established platform guarantees.

No configuration-data read or indirect call is visible on this path.

### 4. Saturation-or-dispatch classification

Inputs that have not returned earlier are classified using the unsigned 32-bit quantity:

\[
T=(2U+[L\ne0])\bmod2^{32},
\]

where \([L\ne0]\) is one when the lower word is nonzero and zero otherwise.

When:

\[
T<0xFFE00001,
\]

the function returns a repeated 32-bit sign-derived word:

- If \(H\ge0\), both result words are `0xFFFFFFFF`.
- If \(H<0\), both result words are zero.

The supplied representation includes two branches inside this range, but both produce the same result. They establish no distinct output behavior.

When:

\[
T\ge0xFFE00001,
\]

the function enters configuration-dependent indirect dispatch.

**Inferred binary64 interpretation:** this final range selects NaN encodings, while infinities take the preceding saturation path. No floating-point comparison or floating-point arithmetic is visible.

- \(K_0\): one external 32-bit data word.

These labels express distinct visible data references, not inferred meanings or resolved storage relationships.

The first configuration-dependent operation obtains:

\[
m=C\mathbin{\mathrm{AND}}0xF.

## Acceptance examples

These examples are static contract consequences, not executed tests.

### Unconditional word-level examples

1. **Immediate negative-range result**

   For upper-word bits `0x80000000`, the signed upper value satisfies the immediate-zero condition. The result is zero for every lower word.

2. **Negative boundary outside the immediate return**

   For upper-word bits `0xBFF00000` and lower word zero, the immediate-zero comparison is false. The later classification returns zero because the upper word is negative and \(T<0xFFE00001\).

3. **Positive saturation**

   For upper word `0x43F00000` and lower word zero, the shift-based range is not selected. The result is `0xFFFFFFFFFFFFFFFF`.

4. **Infinity-shaped inputs**

   With lower word zero:
   - Upper word `0x7FF00000` returns `0xFFFFFFFFFFFFFFFF`.
   - Upper word `0xFFF00000` returns zero.

   Neither case reaches configuration-dependent dispatch.

5. **Dispatch boundary**

   Upper word `0x7FF00000` with lower word one produces \(T=0xFFE00001\), selecting configuration-dependent dispatch. Its final result is not specified independently of F-unknown.

6. **Mode-8 discarded reads**

   For a dispatch-selecting input, suppose the mode read yields 8, the next configuration read has bit `0x40` clear, and the later configuration read has bit `0x10` set. The visible sequence reads \(K_1\), then \(K_0\), then \(K_2\), and dispatches with argument words \(0,K_2\).
