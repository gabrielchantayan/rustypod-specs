# F-36c2c2b132fa

## Purpose

F-36c2c2b132fa updates two fields of a caller-supplied memory record using an existing value, a one-byte selector, and, on one branch, an additional arithmetic operand.

The established behavior is a two-branch transformation:

- When the selector byte is zero, the first destination receives the existing value, and the second destination receives that value plus the additional operand minus one.
- When the selector byte is nonzero, the first destination receives the existing value plus one, and the second destination receives the unchanged existing value.

The field arrangement and arithmetic are consistent with calculating a pair of positions or bounds. That interpretation is **inferred intent**, not an established semantic meaning. Nothing supplied identifies the record type, the units of its fields, or whether the results represent positions, lengths, limits, or another quantity.

The observable result is the mutation of the record. There is no returned result value.

## Behavior

### Common initial observation

The existing value at +0x1C is read before the selector byte at +0x05.

Both destination calculations use that initially read value. There is no second read of +0x1C, and the function does not write that field.

The selector is tested only for equality with zero. It is not interpreted as a count or restricted to the values zero and one. Every nonzero byte selects the same branch.

### Zero-selector behavior

When the selector byte is zero:

1. The first destination, at +0x18, receives the initially read existing value.
2. The additional operand at +0x10 is read.
3. The second destination, at +0x20, receives the existing value plus the additional operand minus one.

The first destination write precedes the read of the additional operand in the supplied operation ordering. Consequently, the additional operand is not shown as an entry-time snapshot.

For arithmetic whose intermediate and final values are representable, the resulting destination values are:

- First destination: existing value.
- Second destination: existing value + additional operand − 1.

The addition of the existing value and the additional operand occurs before subtraction of one. Intermediate overflow therefore matters even if the combined mathematical expression would fit in the result width.

### Nonzero-selector behavior

When the selector byte is nonzero:

1. The first destination, at +0x18, receives the initially read existing value plus one.
2. The second destination, at +0x20, receives the initially read existing value.

The additional operand at +0x10 is not read on this branch. Its contents do not affect this branch’s computed results.

For representable arithmetic, the resulting destination values are:

- First destination: existing value + 1.
- Second destination: existing value.

### Write order and preservation

The first destination is written before the second destination on either branch. The pair of writes is not established as an atomic update.

The supplied body contains no explicit writes to the selector, the additional operand, or the existing-value field. It contains no explicit writes to any other part of the record.

The ordering described here is established by the supplied source-level representation. It is not an independently verified guarantee about machine-instruction scheduling, memory barriers, or visibility to concurrent observers.

### Boundary behavior

No visible rule rejects negative existing values or negative additional operands. Within the representable arithmetic domain, they participate in the same calculations as positive values.

On the zero-selector branch:

- An additional operand of one makes both destinations equal.
- An additional operand of zero makes the second destination one less than the first, provided the arithmetic is representable.
- A negative additional operand can place the second destination below the first.
- There is no visible clamp, normalization, or ordering check.

On the nonzero-selector branch, the first destination is one greater than the second when the increment is representable.
