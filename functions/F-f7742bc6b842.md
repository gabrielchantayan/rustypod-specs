## Behavior

### Early return

### Reading and fixing the traversal range

When both arguments are nonzero, the function first reads the unsigned 32-bit starting value at descriptor offset 4. It then reads the signed 16-bit field at descriptor offset 2 and uses both values to calculate an unsigned 32-bit endpoint.

The signed field is sign-extended before multiplication by eight. Its range is −32,768 through 32,767, so the product ranges from −262,144 through 262,136. That multiplication fits in a signed 32-bit integer.

The endpoint is the starting value plus that product, reduced modulo \(2^{32}\). Consequently:

- A negative field contributes a negative displacement before unsigned modular interpretation.
- Addition near either end of the 32-bit range can wrap.
- The endpoint is not a saturating bound.
- The signed field is not directly tested for positivity.

The starting value and endpoint are fixed before the first dependency call. The supplied body contains no later descriptor-field reads. A dependency changing the descriptor therefore does not, by itself, change the already selected traversal range.

### Invocation sequence

### Exact call-count rule

Let:

- \(S\) be the unsigned 32-bit starting value;
- \(C\) be the signed 16-bit field;
- \(E = (S + 8C) \bmod 2^{32}\).

Subject to successful field reads and normal return from every dependency invocation:

- If \(S \geq E\), there are no dependency calls.
- If \(S < E\), the number of calls is \((E-S)/8\).

The division is exact: the endpoint and starting value have the same remainder modulo eight, because both the displacement and \(2^{32}\) are multiples of eight.

For a nonempty traversal, the first argument values are \(S\), then \(S+8\), and so on, ending at \(E-8\). The endpoint itself is not passed.

Although the increment uses unsigned arithmetic, a nonempty traversal reaches its endpoint without wrapping the current value. The endpoint is numerically above the starting value, and their difference is a multiple of eight.

### Consequences of the signed field

For a positive field:

- If the endpoint addition does not wrap, the call count equals that field.
- If the endpoint addition wraps, the endpoint is below the starting value and the function makes no calls.

For a zero field, the endpoint equals the starting value, so there are no calls.

For a negative field:

- If the modular endpoint lies below the starting value, there are no calls.
- If it lies above the starting value, the traversal can be very large.

In the latter case, the call count is \(2^{29}+C\), rather than the magnitude of the negative field. A field of −1 can therefore produce 536,870,911 calls. The function contains no explicit cap, cancellation check, or negative-field rejection.
