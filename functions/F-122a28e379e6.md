# F-122a28e379e6

## Purpose

F-122a28e379e6 conditionally retrieves a signed 16-bit value from an object-associated data structure and returns it as a signed integer. Retrieval is permitted only after two nonzero results: one from an object-selected indirect callback, and one from F-a664bdd89f4f. F-7e4f952e879e runs between those checks.

When retrieval is permitted, a nonzero value from an optional record takes precedence. If that record is absent, or its selected value is zero, the function retrieves a fallback value from a different record.

The function returns −1 when either gating result is zero. However, −1 is also a possible value read from either record. The returned integer alone therefore cannot reliably distinguish a failed gate from successful retrieval of the value −1.

These are structural observations from the supplied source representation. The domain meaning of the object, the gates, and the selected values is not established.

## Interface

### Input

The function takes one object-address argument.

The supplied representation uses a 32-bit layout: integer-sized fields and stored addresses occupy four bytes, and the selected record values occupy two bytes. The contract below describes that represented layout; independent confirmation of the target ABI is unavailable.

The object has these relevant fields:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 4 bytes | Address of a dispatch table |
| 8 | 4 bytes | Address of an associated structure |

The dispatch table contains a callable address at byte offset 8. That callable receives the original object address as its sole explicit argument.

The associated structure has these relevant fields:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 4 bytes | Address of the fallback record |
| 16 | 4 bytes | Address of an optional preferred record; zero means absent |

The records expose these selected fields:

| Record | Byte offset | Width | Interpretation |
|---|---:|---:|---|
| Preferred record | 42, or 0x2A | 2 bytes | Signed preferred value |
| Fallback record | 2314, or 0x90A | 2 bytes | Signed fallback value |

Offsets are byte offsets from the respective structure or record address, not indices measured in four-byte words.

### Output

The function returns a signed 32-bit integer in the represented interface:

- −1 if the indirect callback returns zero.
- −1 if F-a664bdd89f4f returns zero.
- Otherwise, the selected signed 16-bit record value, widened while preserving its sign.

Thus a retrieved value lies in the range −32768 through 32767. A preferred value of zero is not returned directly: it causes fallback retrieval. A fallback value of zero is returned as zero.

### Preconditions

The function does not validate the input object address before its first dereference. Callers must provide an object and dispatch chain valid for the initial indirect call.

Additional memory must be valid only on paths that reach its reads:

- After both gates pass, the object’s associated-structure field and that structure’s preferred-record field must be readable.
- A nonzero preferred-record address must permit a two-byte read at offset 42.
- If fallback is selected, the then-read associated structure must provide a readable fallback-record address, and that record must permit a two-byte read at offset 2314.

The target’s alignment and address-representation requirements must also be satisfied. No recovery behavior is established for invalid addresses, misalignment, address arithmetic overflow, or an invalid callable address.

## Behavior

### Initial indirect gate

The function first reads the dispatch-table address from byte offset 0 of the input object. It then obtains the callable address at byte offset 8 of that table and invokes it with the original object address.

This call precedes both named dependencies and all explicit associated-record reads.

A zero return ends normal processing immediately with −1. On that path, neither named dependency is invoked, and no preferred or fallback record is explicitly read by F-122a28e379e.

Any nonzero result passes this gate. Positive values are not required; negative results also pass. The callback result is used only to decide whether to continue.

The callback’s identity is selected at runtime. Its effects, calling requirements beyond the visible argument, and behavior on failure are not available.

### Intermediate dependency and second gate

If the indirect callback returns nonzero, the function invokes F-7e4f952e879e with no explicit arguments. Its return value, if any, does not participate in the visible decision.

After that invocation returns, the function invokes F-a664bdd89f4f with no explicit arguments.

A zero result from F-a664bdd89f4f causes an immediate return of −1. A nonzero result allows record selection. As with the first gate, any nonzero integer—including a negative value—passes.

No associated-structure address is explicitly cached by this function before these calls. Consequently, the subsequent associated-structure read observes the object field after both named dependencies have returned. This does not establish that the dependencies preserve or modify that field.

### Preferred-record selection

After both gates pass, the function reads the associated-structure address from byte offset 8 of the input object. It then reads the preferred-record address from byte offset 16 of that structure.

If this address is zero, the preferred record is absent. No read at preferred-record offset 42 occurs, and the function proceeds to fallback selection.

If the preferred-record address is nonzero, the function reads a signed two-byte value at byte offset 42 of that record.

- A nonzero value is widened to the return width and returned.
- A zero value causes fallback selection.

A negative preferred value is a valid nonzero selection. In particular, −1 is returned directly rather than treated as another reason to fall back.

When a preferred value is returned, the fallback-record address and fallback value are not explicitly read by this function.

### Fallback selection

Fallback occurs in either of two circumstances:

1. The preferred-record address is zero.
2. The preferred-record address is nonzero, but its selected signed value is zero.

For fallback, the function reads the associated-structure address again from byte offset 8 of the input object. It then reads the fallback-record address at byte offset 0 of that structure, followed by the signed two-byte value at byte offset 2314 of that record.

This is a new associated-structure read, not a contractual reuse of the address obtained for preferred selection. No dependency call appears between the preferred-selection reads and this fallback read. Nevertheless, the supplied material does not establish immutability, synchronization, or protection against externally changing memory.

The fallback-record address is not checked for zero. The fallback value is returned after signed widening, without further filtering. Zero and −1 are both valid fallback results.

### Observable ordering

For a normal invocation that reaches fallback through a present preferred record, the explicit operations have this order:

1. Read the object’s dispatch-table address.
2. Read the indirect callable address.
3. Invoke the indirect callback and inspect its result.
4. Invoke F-7e4f952e879e.
5. Invoke F-a664bdd89f4f and inspect its result.
6. Read the object’s associated-structure address.
7. Read the preferred-record address.
8. Read the preferred signed value.
9. If that value is zero, reread the object’s associated-structure address.
10. Read the fallback-record address.
11. Read the fallback signed value and return it.

An absent preferred record omits step 8. A nonzero preferred value omits steps 9–11. A failed gate omits all subsequent steps.

This ordering describes the supplied sequential source representation. It is not evidence of machine-level atomicity, volatile accesses, or a cross-thread memory-ordering guarantee.
