# F-f4f759946309

## Purpose

F-f4f759946309 dispatches a request according to the signed low 16 bits of its operation selector. It invokes operation-specific dependencies, conditionally changes request or shared state, and either exits directly or enters shared post-dispatch processing.

Established behavior consists of explicit reads, writes, comparisons, arithmetic, and dependency invocations in the supplied static representation. Protocol meanings, dependency implementations, ownership transfers, and synchronization guarantees are not established. Prepared temporary values are not necessarily response contents: several subsequent calls receive no explicit pointer to them.

## Interface

### Arguments and result

The function accepts two 32-bit arguments:

- **Context:** passed to specialized handlers and used as an address by operation `0x26`. Its saved 32-bit value also becomes the shared tail’s signed working value.
- **Request:** an address of mutable, byte-addressable storage.

The result occupies 32 bits. Explicit results include zero, 10, and `0x3E`. Operations `0x18` and the shared `0x17` path forward dependency results. Paths containing a dependency annotated as nonreturning do not establish a normal return.

### Request and associated-object layout

Offsets are in bytes.

| Location | Width | Use |
|---|---:|---|
| Request `0x00` | 32 bits | Associated-object address |
| Request `0x08` | 32 bits | Payload address |
| Request `0x0C` | Low 16 bits | Signed comparisons with zero or one |
| Request `0x10` | Initially 32 bits | Selector; dispatch uses its signed low half |
| Request `0x1A` | 8 bits | Shared-tail state |
| Associated object `0x08` | 32 bits | Identifier captured at entry |
| Context `0x2D0` | 32 bits | Read and conditionally written by operation `0x26` |

Other referenced storage includes:

- A globally selected control region: mask at `0x28`, signed 32-bit field at `0x34`, and 32-bit field at `0x5C`.
- An identifier-indexed table with four-byte entries: enable byte at zero, limit byte at one, counter byte at two.
- An identifier-indexed table with `0x24`-byte entries and a 32-bit field at `0x14`.
- A shared tail-object pointer and three separate 32-bit globals used by tail processing.

### Preconditions

The request selector and associated-object address are dereferenced before dispatch; the associated object’s identifier is then read. Later null checks do not make a null request valid.

Branch-specific requirements include readable payloads, writable state fields, valid table indices, valid dependency-returned objects and storage, and callable indirect targets. No general address, bounds, capacity, or arithmetic validation is shown. Invalid inputs have no established recovery behavior.

## Behavior

### Entry and control-region snapshots

Entry processing reads, in order, the request’s selector word, associated-object address, and associated-object identifier. It saves the context and initializes a local holder with the request pointer.

It then calls U-01 and calls F-62d1a359629f with the U-01 result plus four and the captured identifier. The resulting flags affect operations `3`, `5`, and `6`.

**After that flags query and before dispatch, the global control-region base pointer is captured.** This snapshot is distinct from later global base-pointer reads. Dependencies are not assumed to preserve either the global pointer or storage reachable through an earlier snapshot.

The entry query occurs even for operations that subsequently return immediately.

Unless specified otherwise, an operation continues into shared post-dispatch processing.

### Flag-dependent operations

**Operation `3`:** If entry flags contain `0x10`, calls F-c4c0ca1daaf5 with an address of 32-bit temporary storage not explicitly initialized on this path. A zero result causes F-dece790ddc92 with request, captured associated object, zero, zero.

**Operation `5`:**

- Reloads the global control-region base pointer, reads its `0x5C` field, and passes that value to U-02.
- Requires entry flag `0x10` and either identifier 2, identifier 4, or a signed field at offset `0x34` that differs from `-1` and is less than 16. This field is read through the **pre-dispatch captured base**, only when the identifier alternatives fail. Negative values other than `-1` qualify.
- Initializes a 32-bit temporary to zero and calls F-c4c0ca1daaf5.
- A zero result and zero low output byte permit F-a708118dcc50. A zero result from that call permits F-5d13d49443f6 with associated object, zero, zero, 2.
- A nonzero result from F-5d13d49443f6 is passed to F-256e8a77aa59 with second argument zero.
- Finally reads offset `0x5C` through the **captured base**, without reloading the global base pointer, and passes that field value to U-03.

Thus U-02 and U-03 can receive values from different control-region objects. Their pairing does not establish locking.

**Operation `6`:** Requires entry flag `0x10`. Initializes a temporary to zero and calls F-c4c0ca1daaf5. A zero result with nonzero low output byte permits F-ec91e5fbd054. If that returns zero, the same F-5d13d49443f6 and conditional F-256e8a77aa59 sequence follows. Neither U-02 nor U-03 is called.

### Object-derived operations

**Operation `0x0D`:**

2. Obtains another object through F-cdd33263ee89 and invokes slot `0x28` with an output-holder address and object.

### Operation `0x0F`: indexed output preparation

Requires the signed low half at request `0x0C` to equal one. Initializes two 32-bit output temporaries to `0xFF`, then reads one unsigned payload byte.

Continues only if that byte is at most 12 and its bit is set in the control-region mask at `0x28`. This mask access uses a global base-pointer read, not the pre-dispatch snapshot.

Calls U-01, then F-9266831caef7 with its result plus four and the payload byte. A null result invokes nonreturning F-a817d8d58c10.

Invokes virtual slot `0x18` with object and the first output address. If the relevant low bytes of both output temporaries equal `0xFF`, no F-dece790ddc92 call occurs. Otherwise it prepares three consecutive bytes: input byte, first output low byte, second output low byte. A fourth byte is retained from storage whose initialization is not established. F-dece790ddc92 follows.

The representation does not establish a portable secondary-register output contract or how the second output storage is populated.

### Operation `0x15`: counter gate

Reads the selected four-byte entry’s enable byte. If it equals one, the table base is read again to establish the entry address, and its counter byte is incremented and stored with eight-bit wrapping.

If the new counter is greater than one and no greater than the unsigned limit byte, a valid nonnull request enters finalization. Displayed counter comparisons and resets after the nonreturning call are not established normally reachable behavior.

Otherwise, calls F-71222f35d2d3 with context and request.

### Shared post-dispatch processing

Freshly reads the selector’s unsigned low half and compares it with the original selector’s signed low half promoted to 32 bits. Equality assigns `0xFF` to a 32-bit temporary and calls F-09b5d9827724 with request, captured associated object, zero, zero. Original low halves `0x8000`–`0xFFFF` cannot satisfy this comparison.

Reads the selector again. If its signed low half equals `0x17`, returns F-3105e44fc8f9 with context, request, and the selected `0x24`-byte table entry’s field at `0x14`, using the entry-captured identifier.

Otherwise captures the shared tail-object pointer. Zero returns 10. A nonzero pointer leads to a null-request check invoking F-a817d8d58c10 on null, then a zero write to request byte `0x1A`.

### Shared tail

The holder initially contains the request pointer, but is not reset each iteration. Dependencies receiving frame addresses must not be assumed to preserve it.

Each iteration:

- Reads request byte `0x1A` and stores its value XOR one in a 32-bit unsigned prepared value.
- Calls F-6bcf51bcbf9f with captured tail object, zero, four, and another frame-storage address. Zero returns zero immediately.
- Calls F-21db160d8c99 with the holder’s address and zero.
- After that call returns, captures the initial-adjustment global.
- Then reads the separate shared-value global and writes its 32-bit value through the returned storage pointer.
- Reads the callback target at byte offset `0x0C` of the object **currently referenced by the holder**, then calls it with holder address and prepared-value address.
- Adds the previously captured initial adjustment to the signed 32-bit working value.
- Repeatedly reads the step global for the condition and compares its negation as **less than or equal to the working value**. Each successful condition increments the unsigned prepared value modulo \(2^{32}\), then separately rereads the step global and adds that value to the working value.
- Calls U-05 with captured tail-object address plus `0x14C` and prepared-value address, then F-ec22bd8215d3 with holder address.

Processing repeats after each nonzero F-6bcf51bcbf9f result. Condition reads and update reads of the step global are distinct. Signed overflow, negation of the minimum signed value, frame aliasing, and termination are unresolved.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Selector truncation:** `0x12340013` selects `0x13`. Entry querying and base capture precede F-d7f4331ded9b; the function returns zero without shared processing.

2. **Distinct control bases:** If U-02 changes the global control-region pointer, operation `5` still uses the pre-dispatch base for its conditional `0x34` read and final `0x5C` read.

3. **Distinct preceding-field reads:** For `0x0D`, an initial preceding value of 10 requests 15 from F-fab3799b3190. If the later current preceding value is 20, U-04 receives 21 as its third argument. This establishes no copying.

4. **Allocation failure:** A zero F-fab3799b3190 result skips F-b9d9c0b9bfab, U-04, F-dece790ddc92, and F-58ba61416cc9 on that branch. F-9088f1254fb8 still occurs.

5. **Capability condition:** In `0x24`, a nonzero slot `0x2C`, nonzero F-76ed42657cca result, and query result `0xD000` enable bit `0x20`; another query result leaves it clear.

6. **Counter wrap:** An enabled counter of 255 becomes zero, fails the greater-than-one gate, and proceeds to F-71222f35d2d3.

7. **Holder replacement:** If F-21db160d8c99 replaces the holder, callback selection uses the replacement object’s `0x0C` field, not the original request’s.

8. **Tail read ordering:** If the callback changes the initial-adjustment global, the addition still uses its pre-callback captured value. Step-global condition and update reads remain separate.

9. **First tail refusal:** A zero first F-6bcf51bcbf9f result returns zero after resetting request byte `0x1A`, without storage acquisition or callback invocation.
