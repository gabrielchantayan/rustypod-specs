# F-b7296c96c0ec

## Purpose

F-b7296c96c0ec performs an ordered, two-slot operation using a caller-supplied object and a separate context value. An object-level flag enables a preliminary operation for both slots. Independently of that flag, each slot with a nonzero resource field receives a sequence of resource-description, local-copy transformation, context preparation, and final submission calls.

The established behavior is the ordering and data flow of these operations. Interpreting the function as rendering two resources using transformed rectangles is plausible, but the supplied evidence does not establish the meanings of the resource fields, temporary data, or context.

This contract describes a normal execution in which all invoked dependencies return normally. Dependency-specific failures, nonlocal exits, and invalid-memory behavior are not defined by the supplied evidence.

## Behavior

### Preliminary phase

The function first reads the byte at object offset 184.

If that byte is zero, the preliminary phase makes no dependency calls. Execution still proceeds to the per-slot resource phase.

If the byte is nonzero, the function calls F-cf7ecaff2699 twice, in slot order:

1. For slot 0, it supplies the context value, the object-relative address at offset 200, and the low eight bits of the 32-bit field at offset 192.
2. For slot 1, it supplies the context value, the object-relative address at offset 412, and the low eight bits of that same 32-bit field.

The 32-bit field at offset 192 is read separately for each call. The low-byte value is obtained by masking the full 32-bit value with 255, producing a value in the range 0 through 255. This is not evidence of a one-byte memory read at offset 192.

The flag is tested only once. A dependency that changes the flag during the first preliminary call does not cause this function to reconsider whether to make the second preliminary call. However, a change to the 32-bit field at offset 192 can affect the second call because that field is read again.

Both preliminary calls, when enabled, occur before either slot’s resource phase.

### Per-slot resource phase

The function processes slot 0 and then slot 1. It computes each slot’s base using the 212-byte stride.

For each slot, it first reads the 32-bit resource field located 216 bytes after that slot’s base.

- If the field is zero, the function skips all remaining operations for that slot.
- If the field is nonzero, the function performs the following sequence.

#### 1. Obtain resource-associated data

The function calls F-59fa3fd3efc5 with:

- A fresh read of the slot’s 32-bit resource field.
- The address of the 16-byte description area.

The resource value used for this call is not stored from the earlier nonzero test. The supplied representation contains a separate read for the call argument.

There is no local branch on the dependency’s return value and no explicit verification that it wrote all 16 bytes.

#### 2. Copy the description into separate working storage

After F-59fa3fd3efc5 returns, the function copies the four 32-bit words from the description area into the working area.

The copied word offsets are 0, 4, 8, and 12, in that order. The two areas are distinct: the working area is not an alias of the description area.

At the completion of these copies, the working area contains the description area’s four observed word values. Subsequent equality between the areas is not guaranteed.

#### 3. Apply the slot-associated operation

The function calls F-cca11044abb5 with:

- The address of the working area.
- The embedded-data address for the current slot: object offset 200 for slot 0, or offset 412 for slot 1.

The function does not directly read the embedded data. Its contents and extent are interpreted by the dependency.

The apparent intent is to modify the copied description using slot-associated data. The exact operation, coordinate system, arithmetic, and mutation behavior are unknown.

#### 4. Prepare the context

The function calls F-33ca0546dba1 with:

- The context value.
- The constant value 1.

This call occurs after F-cca11044abb5 and before final submission. No return value is checked.

The function makes no explicit attempt to preserve or restore context state around this call.

#### 5. Submit the resource and both temporary areas

The function calls F-b774eb6cb163 with six arguments, in this logical order:

1. The context value.
2. A new read of the current slot’s 32-bit resource field.
3. The address of the description area.
4. The address of the working area.
5. The constant value 255.
6. The constant value 0.

The final resource argument is read after F-33ca0546dba1 returns. It is not necessarily the resource value tested at the start of the slot, nor the resource value passed to F-59fa3fd3efc5.

The function does not repeat the nonzero test before final submission. If an intervening dependency changes the resource field to zero, the final dependency can receive zero.

### Overall ordering and bounds

The function has two fixed two-iteration loops. Their indices take only the values 0 and 1, so their own increments and stride products do not approach 32-bit integer limits.

The largest slot-stride product is 212. Address calculations additionally depend on the supplied object address. The function contains no explicit overflow detection or bounds enforcement. Valid, representable addresses for the reached accesses and calls are preconditions; behavior at an address-space boundary is not established here.

With stable object contents and normally returning dependencies:

- The preliminary phase makes either zero or two calls.
- Each inactive resource slot makes no resource-phase calls.
- Each active resource slot makes four resource-phase calls.
- The maximum dependency-call count is ten.
