# F-7214963bd1d4

## Purpose

F-7214963bd1d4 counts consecutive zero bits beginning at a specified bit position in a byte-addressed region. Bits are examined most-significant-bit first. The function returns when it encounters the first one bit, excluding that terminating bit from the count.

At selected byte boundaries, the function calls F-5480c9185606. A nonzero result causes exactly one byte to be skipped without examining its bits. A separate one-byte output records that such a result occurred through explicit writes by this function.

This is not a bounded bit reader. The visible interface supplies no end pointer or explicit scan limit, and the function has no visible end-of-input return. Termination requires an examined one bit, unless execution is interrupted by a dependency, invalid memory access, or another external condition.

## Interface

### Inputs and result

The function accepts two arguments:

1. **Descriptor address.** Points to three consecutive words used as:
   - A base address for byte access.
   - A starting bit-position value.
   - A value passed to F-5480c9185606.

2. **Status-output address.** Points to one writable byte.

The result is an integer count of examined zero bits before the first examined one bit.

The recovered representation uses a 32-bit integer model. Under that model, the descriptor occupies 12 bytes:

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | Encoded base address |
| 4 | 32 bits | Starting bit position |
| 8 | 32 bits | Dependency argument |

This layout describes the supplied representation, not a portable interface for arbitrary pointer widths. In particular, the base address is held in an integer-valued field rather than a separately established native-pointer field.

### Bit-position interpretation

For an ordinary nonnegative starting position:

- The byte displacement is the starting position divided by eight, discarding the remainder.
- The low three bits select the starting position within that byte.
- Position zero within a byte means its most-significant bit.
- Position seven means its least-significant bit.

The actual displacement calculation interprets the position as signed before shifting right by three. Negative values therefore require the signed-shift and address rules discussed under **Uncertainties**; they must not automatically be interpreted as large positive offsets.

### Preconditions

For normal, defined completion:

- The descriptor must support the reads described below.
- The status-output address must support a one-byte write before any descriptor field is read.
- Every byte actually examined must be readable.
- Addresses passed to F-5480c9185606 must satisfy that dependency’s unknown requirements.
- Address calculations and the accumulating result must remain within the applicable execution model.
- An examined one bit must eventually occur if a normal return is expected.

No explicit null check, bounds check, descriptor validation, or output-alias check is present.

The source does not establish that the two arguments designate disjoint storage. Aliasing can affect behavior because the initial status write occurs before descriptor reads.

## Behavior

### Initial state and access order

The first externally visible action is a one-byte zero write to the status output.

Only afterward does the function obtain the starting bit position and base address from the descriptor. It calculates the initial byte address and the number of bits remaining in that byte. The zero count starts at zero.

For a conventional valid position, the number of remaining bits is between one and eight:

- Eight at a byte boundary.
- Seven when starting at the second-most-significant bit.
- One when starting at the least-significant bit.

Consequently, placing the status output inside the descriptor or byte region can change the scan before it begins. The contract does not replace this ordering with an abstract, simultaneous capture of the inputs.

### Starting at a byte boundary

When all eight bits of the initial byte are eligible for examination, the function:

1. Reads the descriptor’s third word for the dependency argument.
2. Calls F-5480c9185606 with the initial byte address and that value.
3. If the result is nonzero, advances the byte address by one and writes one to the status output.
4. Reads the byte at the resulting address.
5. Examines its bits from most significant to least significant.

A nonzero dependency result skips exactly the candidate byte supplied to the dependency. The replacement byte is not itself submitted to the dependency before this examination.

If the dependency result is zero, the candidate byte is examined without the one-byte advance or the status-one write.

### Starting inside a byte

When the starting position is not byte-aligned, the initial byte is read without a preceding dependency call.

Bits preceding the selected starting bit are discarded. The remaining bits are examined most-significant-first within that selected suffix.

For example, starting at position three within a byte examines the bit with mask `0x10` first, then the four lower bits. The three higher bits have no effect on the count or termination.

If this suffix contains a one bit, the function returns immediately. F-5480c9185606 is never called on that path.

### Counting and termination

Each examined zero bit increases the result count by one. The first examined one bit returns the current count immediately.

The terminating one bit:

- Is not included in the result.
- Does not trigger an additional dependency call.
- Does not cause an explicit update to the descriptor.
- Does not cause a final status write.

A skipped byte contributes no bits to the count, regardless of its contents.

After the initially selected byte or suffix is exhausted without finding a one, each subsequently examined byte contributes eight zeros if it is entirely zero.

### Moving to subsequent bytes

Whenever an examined byte is exhausted:

1. The candidate address advances by one byte.
2. The descriptor’s third word is read again.
3. F-5480c9185606 is called with that candidate address and the freshly read value.
4. A nonzero result causes a one-byte status write of one and a further one-byte address advance.
5. The byte at the resulting address is read and examined from its most-significant bit.

There is no dependency call on the replacement byte before it is examined. A nonzero result does not cause repeated skipping until the dependency accepts a byte.

For example, if an exhausted byte is followed by a candidate for which the dependency returns nonzero, that candidate is skipped and the following byte is examined directly. Only after that examined byte is exhausted does another dependency call occur.

The third descriptor word is reread for every call. The base address and starting position are used to establish the scan location initially; the visible function does not reread them to restart or redirect the scan after dependency calls.

### Status semantics

The function explicitly performs only these status writes:

- Zero on entry.
- One after every nonzero dependency result.

It never explicitly resets the status to zero after scanning begins.

With disjoint storage and a dependency that does not alter the status byte, the returned status is therefore:

- Zero if every dependency result was zero, including a path with no dependency calls.
- One if at least one dependency result was nonzero.

Those final-value statements are conditional. A dependency may alter aliased storage or the status byte itself; no preservation guarantee is visible.

## Side effects

### Direct memory effects

The function directly writes only the status byte. It has no explicit descriptor-field update and no explicit write to scanned bytes.

This does not imply that descriptor or byte-region contents remain unchanged:

- The status byte may alias either region.
- F-5480c9185606 may modify memory.
- External mutation is not addressed by the supplied evidence.

In particular, the function does not commit an updated bit position to the descriptor. Its return value is a count, not a persisted cursor advance.

### Observable reads

The significant read and write ordering is:

- Initial status-zero write before descriptor reads.
- Initial position and base-address reads before the first dependency call.
- Dependency-argument read before each call.
- Dependency call before the corresponding byte read.
- For a nonzero result, status-one write before reading the byte selected after the skip.
- No byte read for a skipped candidate by this function itself.

The dependency may independently read the address it receives. “Skipped” means not examined by this function’s bit-counting logic, not necessarily unread by the entire call chain.

Each examined byte is loaded before its bits are tested. There are no dependency calls between individual bit tests within that loaded byte.

### Ownership and resources

The visible function performs no allocation, deallocation, ownership transfer, or explicit resource acquisition.

The input region and descriptor are caller-supplied storage. The dependency’s ownership and lifetime effects are unknown; this function’s lack of allocation or release does not establish that the dependency behaves similarly.

### Errors and nontermination

There is no explicit error result or separate error status.

A return of zero is a successful scan result when the first examined bit is one. A status value of one indicates a nonzero dependency result under the conditions above; it is not established as an error indicator.

A region containing only examined zero bits can lead to indefinite scanning, an invalid access, or arithmetic limits. No visible branch converts any of those conditions into a defined failure return.

## Acceptance examples

These examples are conditional behavioral criteria derived from static evidence, not observed test results. Unless stated otherwise, assume valid accessible storage, disjoint status storage, a dependency that returns normally without modifying relevant memory, and representable arithmetic.

1. **Immediate one at an aligned start.**  
   Start at bit position zero. The initial byte is `0x80`, and the dependency returns zero. The result is zero, the status is zero, and exactly one dependency call occurs.

2. **Three zeros before a one.**  
   Start at bit position zero with initial byte `0x10`. The dependency returns zero. The result is three. Lower bits are not examined after the terminating one.

3. **Unaligned start ignores earlier bits.**  
   Start at bit position three with byte `0xE8`. The selected suffix begins with zero and then one. The result is one, the status is zero, and no dependency call occurs.

4. **Crossing from a partial byte.**  
   Start at bit position six in `0xFC`. The two selected bits are zero. The next candidate byte is `0x40`, and its dependency result is zero. The result is three: two zeros from the initial suffix and one from the next byte.

5. **Initial skip excludes an entire byte.**  
   At an aligned start, the dependency returns nonzero for an initial `0x00` byte. The following byte is `0x20`. The result is two and the status is one. The skipped byte contributes no zeros, and the following byte receives no separate dependency call before examination.

6. **Skip after an exhausted byte.**  
   An aligned initial `0x00` byte is accepted with a zero dependency result. The next candidate receives a nonzero result. Its following byte is `0x80`. The result is eight and the status is one.

7. **Dependency argument can change.**  
   If the dependency changes the descriptor’s third word during an earlier call and scanning continues, the next call receives the changed value. The initial argument value is not cached for the entire scan.

8. **Status alias affects input.**  
   If the status output aliases the first scanned byte, the entry write changes that byte to zero before scanning. Any expected result must account for this mutation and for later status writes to the same location.
