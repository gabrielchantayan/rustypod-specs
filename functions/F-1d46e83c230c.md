# F-1d46e83c230c

## Purpose

The established behavior is a memory-access sequence, not a demonstrated hardware operation. The combination of fixed offsets and repeated writes is consistent with device or peripheral control, but that interpretation is **inferred intent**. The source does not establish register names, device semantics, timing requirements, or the meaning of the written values.

## Behavior

### Setup sequence

The represented access order is:

1. Read the first base slot and retain the resulting address for subsequent first-group operations.
2. Read the first base slot again. Using this second result, write 0xFFFFFFFF at offset +0xAC.
3. Using the retained first base, write 0xFFFFFFFF at offset +0xB8.
4. Read the second base slot and retain the resulting address for subsequent second-group operations.
5. Read the second base slot again. Using this second result, write 0xFFFFFFFF at offset +0x14.
6. Using the retained second base, write 0x00000000 at offset +0x10.

Thus, a stable-slot execution uses one base for both initialization destinations in each group. Stability is not checked or enforced.

If the first base slot changes between its two reads, the +0xAC destination can be based on a different address from the +0xB8 and repeated first-group destinations. The same distinction applies to the second slot: its +0x14 destination can differ in base from the +0x10 and repeated second-group destinations.

All four initialization writes precede the repeated sequence. In particular, the second group is not captured before the first group’s two initialization writes. If those writes have external effects on the second base slot, the later reads can observe those effects.

### Repeated sequence

After setup, the function executes exactly 64 iterations, provided execution proceeds normally.

Each iteration performs these two writes in this order:

- Write the 32-bit value 0x00000001 to the retained first base minus 0xBFF100.
- Write the 32-bit value 0x00000001 to the retained second base plus 0xF00.

The next iteration begins only after that pair in the represented control flow. There is no destination-address increment: all 64 first-group writes use the same derived address, and all 64 second-group writes use the same derived address.

The loop executes at least once and terminates after its 64th iteration. Its counter begins at zero, advances once per pair, and reaches 64. This bounded progression does not require counter overflow.

No destination value is read back. There is no explicit delay, acknowledgment check, readiness test, retry decision, or early-exit condition. A destination that already contains one does not cause the function to omit a represented write.

## Acceptance examples

These are conditional contract examples, not runtime test results.

### Stable bases and distinct ordinary-memory destinations

Assume each base slot returns a stable address, all derived destinations are valid and mutually non-overlapping, and no external actor changes the relevant memory.

Expected behavior:

- The first group receives 0xFFFFFFFF at +0xAC, followed by 0xFFFFFFFF at +0xB8.
- The second group receives 0xFFFFFFFF at +0x14, followed by zero at +0x10.
- The function then performs 64 alternating pairs of one-valued stores at the two repeated destinations.
- Normal return follows the final second-group repeated write.

The final contents of the four initialization destinations retain their initialization patterns. Both repeated destinations contain one.

### First base changes between its two reads

Assume the first read returns one valid base and the second read returns another.

The +0xAC initialization uses the second result. The +0xB8 initialization and all first-group repeated writes use the first result. An implementation that refreshes the first base on every iteration would not match the represented behavior.

### Second base changes after capture

Assume the second base slot changes after its two setup reads, while execution remains valid.

The repeated second-group destination remains derived from the retained first read of that slot. The function does not consult the slot again during the loop.

### Repeated destinations coincide

Assume the two repeated address calculations resolve to exactly the same valid four-byte destination.

Each iteration still represents two ordered stores of one to that destination. The repeated sequence contains 128 stores, not 64. Whether those stores produce distinct externally visible events is a property of the execution environment.

### A later access cannot complete

Assume earlier initialization writes succeed but the +0x10 write faults.

The contract provides no recovery, rollback, or status return. Earlier effects may remain, and completion of the repeated sequence is not guaranteed.
