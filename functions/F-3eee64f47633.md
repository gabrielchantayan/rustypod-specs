# F-3eee64f47633

## Purpose

F-3eee64f47633 conditionally updates a caller-supplied record using results from F-567b1e4ae69d. It always obtains and stores three normalized Boolean values. Between the second and third Boolean updates, it may obtain and store a full 32-bit value.

After these initial updates, a record byte selects either an immediate return of status 3 or a later update phase ending in status 0. The later phase uses additional record bytes to select optional dependency calls and writes.

**Established behavior:** selection depends on record values observed at specific points during execution, not on a single snapshot taken at entry. Dependency calls occur between some of these observations and may affect subsequent decisions if they can mutate the record.

**Inferred intent:** the selectors passed to the dependency resemble requested bit widths, and the record resembles a collection of decoded optional fields. Neither interpretation is established. This contract therefore treats selectors as opaque request values and does not impose result bounds suggested by them.

## Interface

### Arguments

| Argument | Width or representation | Established use |
|---|---|---|
| First context | 32-bit opaque value | Passed unchanged as the first argument to every dependency invocation. |
| Second context | 32-bit opaque value | Passed unchanged as the second argument to every dependency invocation. |
| Record address | Address; pointer width not established here | Base address for the record reads and writes described below. |

The function does not establish whether either context represents a handle, address, cursor, or ordinary integer.

Every invocation of F-567b1e4ae69d receives the same two context values. Its third argument is one of the selectors **1, 3, 5, 11, or 14**. Returned values are consumed as 32-bit results, with some subsequently normalized or narrowed.

### Return value

The normal return is a 32-bit status:

- **3:** the byte at record offset 0x01 is zero when examined after the initial updates.
- **0:** that byte is nonzero at that decision point and all subsequently reached operations complete normally.

There is no other explicit normal return. Neither status is selected through a dependency-error check.

The four-byte stores preserve all 32 result bits. Their byte order follows the execution environment and is not independently established here. Alignment requirements and unaligned-access behavior are also unresolved.

### Preconditions and ownership

The record must remain valid for every reached read and write, including accesses following dependency calls. The function performs no explicit null, extent, alignment, or lifetime validation.

No allocation, release, or ownership transfer is explicit in F-3eee64f47633. This does not establish that F-567b1e4ae69d preserves storage, globals, ownership, or accessible state. Normal completion requires that any dependency effects leave subsequent required accesses valid.

## Behavior

The following order is established at the level of the supplied static representation. It is not an instruction-level ordering, atomicity, or synchronization guarantee.

### Initial updates

The function performs these operations before reading the gate at offset 0x01:

1. Invoke F-567b1e4ae69d with selector 1. Store its zero/nonzero normalization at offset 0x25.
2. Invoke the dependency with selector 1 again. Store its zero/nonzero normalization at offset 0x26.
3. If the second invocation returned a nonzero 32-bit value, invoke the dependency with selector 14 and store its entire 32-bit result at offset 0x28.
4. Invoke the dependency with selector 1. Store its zero/nonzero normalization at offset 0x2C.

Normalization produces exactly byte 0 for a zero result and byte 1 for any nonzero result. It is not low-byte truncation. For example, 0x00000100 produces Boolean byte 1.

The selector-14 decision uses the second invocation’s result, not a reread of offset 0x26. A dependency mutation of that field does not change this already determined condition.

When the second result is zero, this function does not write offsets 0x28–0x2B. It does not clear that field.

### Primary gate and return selection

After storing the initial Boolean at offset 0x2C, the function reads offset 0x01:

- Zero causes an immediate return of 3.
- Any nonzero byte enters the later update phase.

The observed value need not equal the entry value: earlier dependency calls may have changed it.

A return of 3 therefore follows at least three dependency invocations and three explicit byte writes. It may also follow a selector-14 invocation and its four-byte write.

After taking the nonzero branch, the function does not reread offset 0x01 to select its eventual status. Later changes to that byte do not themselves cause status 3.

### Optional update for tag 6 or 20

In the later phase, the function tests the tag at offset 0x00 for values 6 and 20. The supplied expression tests for 6 first and tests for 20 only if needed. No dependency invocation intervenes between those comparisons.

If the tag selects either value, the function:

- Invokes F-567b1e4ae69d with selector 3.
- Stores the low eight bits of the result at offset 0x2D.

This happens before the later read of offset 0x2C. It does not require that field to be nonzero.

The result is not explicitly restricted to three bits. For example, a result of 0x000001AB produces stored byte 0xAB.

### Secondary gate

The function next reads the record byte at offset 0x2C:

- Zero skips all remaining optional updates and leads to return 0.
- Any nonzero byte enters the final update block.

This is a record read, not reuse of the initial third dependency result. In particular, a selector-3 invocation may have changed the field before this decision.

Once the final block is entered, offset 0x2C is not checked again. Later dependency mutations of that field do not terminate the block.

### Optional tag-22 updates

Within the final block, the function examines the tag at offset 0x00.

If the observed tag is 22, it performs both operations in this order:

1. Invoke the dependency with selector 5 and store the low eight result bits at offset 0x2E.
2. Invoke the dependency with selector 11 and store the entire 32-bit result at offset 0x30.

Once this branch is selected, there is no tag or gate recheck between the two operations. A tag change during the selector-5 invocation does not suppress the selector-11 invocation.

Neither store applies a mask corresponding to the selector. The first narrows to eight bits; the second preserves all 32 bits.

### Optional three-Boolean group

After the tag-22 branch, whether taken or skipped, the function reads the tag again.

If that observation is **17, 19, 20, or 23**, it invokes the dependency three times with selector 1. Each result is normalized and stored before the next invocation:

- First at offset 0x34.
- Second at offset 0x35.
- Third at offset 0x36.

The tag is not rechecked between these calls. Once the group is selected, all three operations occur if the dependency calls and stores complete normally.

This tag observation is distinct from the earlier observations. A tag that previously selected the selector-3 or tag-22 branch may subsequently select this group.

### Final Boolean

Every execution entering the final block performs one final selector-1 invocation and writes its normalized result at offset 0x37.

This update requires no recognized tag. Afterward, the function returns 0.

### Dependency-call bounds

Every normally completed invocation makes **at least three and at most eleven** dependency calls.

The maximum consists of:

- Three mandatory selector-1 calls.
- One optional selector-14 call.
- One selector-3 call.
- Two tag-22 calls, with selectors 5 and 11.
- Three calls for the Boolean group.
- One final selector-1 call.

These optional branches are not mutually exclusive when dependency mutation is permitted. A reachable conditional sequence is:

**1, 1, 14, 1, 3, 5, 11, 1, 1, 1, 1**

For this sequence, the selector-3 invocation changes an initially qualifying tag to 22, and the selector-11 invocation changes the tag to a value selecting the three-Boolean group. The primary and secondary gates must permit their respective phases.

Without the selector-3 branch, a tag-22 branch followed by a changed tag selecting the Boolean group can still make ten calls when selector 14 is enabled.

## Side effects

### Explicit writes

The function explicitly writes only the output fields identified in the layout. It does not explicitly initialize or modify either the tag or the primary gate.

On normal completion:

- Offsets 0x25, 0x26, and 0x2C have each received an explicit normalized-byte write.
- Offset 0x28 receives a four-byte write only if the second initial result is nonzero.
- Offset 0x2D receives a byte write only if the later phase’s first tag test selects 6 or 20.
- Offsets 0x2E and 0x30 receive their respective writes only if the final block’s tag test selects 22.
- Offsets 0x34–0x36 receive writes only if the later tag observation selects the three-Boolean group.
- Offset 0x37 receives a write whenever the final block is entered.

Skipped fields are not cleared. They may retain earlier contents, subject to dependency effects.

These are guarantees about explicit writes, not necessarily final field values. A later dependency call may overwrite an earlier result if it has access to the record.

### Ordering and partial completion

Each dependency invocation precedes the store of its own result. Earlier completed stores are therefore already in place when later dependency calls begin.

No rollback is visible. If an access fails or a dependency does not return normally, previously completed stores and dependency effects are not explicitly undone.

The function has no explicit logging, I/O, synchronization, allocation, release, or direct global-state access in the supplied representation. Such effects remain possible inside the dependency.

## Acceptance examples

These are static, conditional examples—not runtime observations. Unless stated otherwise, assume valid storage, normal dependency returns, and no dependency mutation of the record.

### Early return still performs initial updates

Assume offset 0x01 is zero. The three initial selector-1 results are 0, 2, and 0; selector 14 returns 0x12345678.

The selector sequence is **1, 1, 14, 1**.

The function explicitly stores 0 at 0x25, 1 at 0x26, the full value 0x12345678 at 0x28, and 0 at 0x2C. It then returns 3 without tag-dependent updates.

### A zero second result leaves the full-width field unwritten

Assume offset 0x01 is nonzero, the tag is 9, and all three initial results are zero.

The selector sequence is **1, 1, 1**. The function returns 0. It does not explicitly write offset 0x28 or any later optional output field.

### Tag 6 does not require the secondary gate

Assume offset 0x01 is nonzero, the tag is 6, and all three initial results are zero. Selector 3 returns 0x000001AB.

The selector sequence is **1, 1, 1, 3**. Offset 0x2D receives 0xAB. Offset 0x2C remains zero, so the final block is skipped and offset 0x37 is not explicitly written. The return is 0.

### Stable tag 20 selects both applicable groups

Assume offset 0x01 is nonzero, the tag remains 20, the second initial result is zero, and the third is nonzero.

The selector sequence is **1, 1, 1, 3, 1, 1, 1, 1**.

The function writes offset 0x2D, then the three Boolean fields at 0x34–0x36, then the final Boolean at 0x37. It returns 0.

### Stable tag 22 preserves width distinctions

Assume offset 0x01 is nonzero, the tag remains 22, the second initial result is zero, and the third is nonzero. Selector 5 returns 0x123456FE; selector 11 returns 0xABCDEF01.

The selector sequence is **1, 1, 1, 5, 11, 1**.

Offset 0x2E receives 0xFE. The four-byte field at 0x30 receives the full value 0xABCDEF01. The three-Boolean group is skipped, but offset 0x37 is updated. The return is 0.

### Dependency mutation changes a later gate

Assume the tag selects 6 and the initial write to offset 0x2C stores 1. If the selector-3 invocation changes that field to zero, the subsequent gate read skips the final block.

The selector-3 result is still stored at offset 0x2D. Offset 0x37 is not explicitly written.

### Eleven calls are conditionally reachable

Assume:

- The second initial result is nonzero, enabling selector 14.
- The third initial result is nonzero.
- Offset 0x01 is nonzero when examined.
- The first later tag test observes 6 or 20.
- Selector 3 changes the tag to 22 and leaves offset 0x2C nonzero.
- The tag remains 22 until the tag-22 branch is selected.
- Selector 11 changes the tag to 17 before the three-Boolean-group test.
- All calls and stores complete normally.

The selector sequence is **1, 1, 14, 1, 3, 5, 11, 1, 1, 1, 1**: eleven calls.

All optional output groups receive their explicit writes, followed by return 0. A single entry-time tag snapshot would not preserve this behavior.
