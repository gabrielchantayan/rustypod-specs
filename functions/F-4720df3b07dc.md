# F-4720df3b07dc

## Purpose

F-4720df3b07dc performs two 16-bit memory reads, selects a path according to whether its second explicit argument is zero, performs conditional global assignments and 32-bit memory writes, and returns its fifth explicit argument unchanged.

The behavior also consumes two incoming machine-state values not described by the explicit argument list: a 32-bit base and a 32-bit auxiliary value. The base participates in address calculations and zero-path state changes. The auxiliary value is assigned to global storage only on the zero path.

A zero second argument does not bypass the initial memory access. The function first reads 16 bits at that argument plus four, so the zero path requires a successful read at byte address `0x04`.

The established purpose is a low-level memory-effect operation. No particular initialization, exception-handling, or device-control purpose is established.

## Behavior

### Common reads and branch selection

The supplied representation establishes this order:

1. Read an unsigned 16-bit value at the second argument plus `0x04`.
2. Read an unsigned 16-bit value at the incoming base plus `0x28` and convert it to unsigned 32-bit form.
3. Select the path according to whether the second argument equals zero.

Both reads precede every explicit write.

The first read’s captured value is used only on the zero path. Its lack of contribution to the nonzero-path store does not remove the represented access.

The second read’s captured value supplies either the nonzero-path store or the first zero-path pointer-addressed store. Its conversion to unsigned 32 bits preserves the original 16 value bits and makes the upper 16 value bits zero.

Later writes do not, by themselves, reload or recompute either captured value, even if their destinations overlap the original read locations.

This is the order represented by the supplied static material. It does not independently establish volatile access, atomicity, compiler scheduling constraints, or hardware visibility guarantees.

### Nonzero second argument

When the second argument is nonzero:

- None of the five conditional global assignments occurs.
- The captured, zero-extended base-relative value is written as a 32-bit quantity at the incoming base plus `0x30`.
- The fifth argument is returned unchanged.

For example, a captured 16-bit value of `0xBEEF` produces the 32-bit stored value `0x0000BEEF`, not a sign-extended value. The byte arrangement depends on target endianness, which is unspecified.

The destination derives from the incoming base, not from the second argument.
