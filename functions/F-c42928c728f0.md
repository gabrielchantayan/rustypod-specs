# F-c42928c728f0

## Purpose

F-c42928c728f0 updates an indexed record’s state byte and, after two successful gates, sends notifications, conditionally mirrors the state into another table, and conditionally updates one of two 32-bit flag fields.

The initial byte write precedes both gates. Failure of either gate leaves that write in place. Later effects are not transactional and have no visible rollback.

Two independent reads of the primary-table-base global serve different purposes:

- The **first base read** is retained for fetching the notification’s offset-0 argument.
- The **second base read** determines the record address used for the initial state update and subsequent offset-4, offset-12, and offset-16 accesses.

No dependency call separates those reads. Nevertheless, the supplied representation does not establish that they return the same value. References below to the **notification record** and **state record** preserve that distinction. They denote the same address only if the two base reads and their address calculations agree.

An option-toggle-and-synchronize interpretation is inferred intent. The established contract is the access, call, and write behavior below.

## Interface

### Inputs and result

The function receives:

- An object address, interpreted according to the supplied 32-bit layout.
- A 32-bit integer record index.

There is no explicit return value. Normal completion does not distinguish gate failure, unsupported classification, unchanged destination flags, or a completed flag update.

## Behavior

### 1. Capture two bases and update the state record

The initial ordering is:

1. Read the primary-table-base global and retain that value for the later notification-record access.
2. Read the same global again and derive the state-record address using the supplied index and 20-byte stride.
3. Read the state record’s unsigned byte at offset 16 for subtraction.
4. Read that byte again for comparison with 1.
5. Write the low byte of the computed replacement to state-record offset 16.

There is no intervening dependency call between these operations. That absence does not establish equality of the two global reads or of the two state-byte reads.

For stable state-byte storage:

| Original byte | Computed replacement | Written byte |
|---:|---:|---:|
| 0 | 1 | 1 |
| 1 | 0 | 0 |
| 2–255 | 0 | 0 |

The replacement is computed in a 32-bit integer temporary, not captured solely as a byte. The first state read supplies an unsigned value for subtraction from 1. If the second state read exceeds 1, the replacement is overwritten with zero.

If those reads disagree, the stable-input table need not apply. For example, if the first read is 255 and the second is 0, the unsigned 32-bit subtraction produces the bit pattern `FFFFFF02`; the byte store receives `02`. The recovered representation then retains that result in a 32-bit integer temporary. Its precise portable signed-conversion interpretation is not established, but it must not be reduced to a guaranteed Boolean value.

The retained replacement is used for notification and, with byte truncation, for the optional mirror write. Later flag processing instead reads the state byte afresh.

Neither captured primary base is refreshed later. Changes to the base global after capture do not redirect these primary-record accesses; changes to the captured storage can still affect their observed contents.

### 2. Apply two gates

F-938c950e5046 is called to obtain a receiver. The function dereferences that receiver to invoke D-01, the indirect-call-table entry at offset 248, with the receiver and a global argument.

There is no visible null check on the receiver before dereference.

If D-01 returns zero, processing stops. The initial state-record byte write remains.

If D-01 returns nonzero, its result and the literal 5888 are passed to F-682adfd5a561. A zero result from that dependency also stops processing without undoing the byte write.

A nonzero result from F-682adfd5a561 permits continuation. That result is not otherwise used by this function.

### 3. Notify using the first captured base, then invoke the object callback

After both gates succeed, the function reads the 32-bit value at offset 0 of the notification record. Its address is formed from the **first** captured primary base and the supplied index.

D-02 receives:

- That 32-bit offset-0 value.
- The retained 32-bit replacement from the initial state calculation.

The notification argument is therefore read after the gates, from storage selected by the first base read. It is not necessarily read from the record whose state was changed through the second base read. Even when both bases initially agree, preceding dependencies may have changed the contents at offset 0 before this read.

After D-02 returns, D-03 is invoked through the input object’s indirect-call-table entry at offset 88. Its arguments are the input object followed by two global values in the supplied order. The source does not establish the relative evaluation order of the callback-target read and those argument reads.

Neither call’s return value controls subsequent processing.

### 4. Optionally mirror the retained replacement

After the callback, the function compares the 32-bit field at state-record offset 4 with a global comparison value.

If unequal, it performs neither the secondary-table write nor the associated dependency call.

If equal:

1. The secondary-table base and the input object’s offset-32 index determine a secondary record.
2. The low byte of the retained replacement is written at secondary-record offset 16.
3. A global pointer is read, its referenced 32-bit value is read, and that value is passed to F-b002ce492389.

The representation does not establish an evaluation order between the secondary-table-base read and the object-index read within the address expression.

The comparison occurs after the preceding dependencies. The secondary index is also read only when this branch executes. Neither should be treated as an entry-time snapshot.

The mirror uses the retained replacement, not a fresh primary-state read. A callback can therefore make the mirrored byte differ from the state byte later used for flags.

### 5. Capture flag-processing inputs

After the optional mirror operation and its dependency call, the function captures, in order:

1. The character at state-record offset 16.
2. The 32-bit descriptor at state-record offset 12.
3. The intermediate-context address at input-object offset 888.

It then calls:

1. F-270c5b6d8d34 with the captured descriptor, obtaining a 32-bit mask.
2. F-266e368c1191 with the same descriptor, obtaining the classification.

Both calls occur regardless of whether the classification is supported.

The captured state, descriptor, and intermediate-context address are not refreshed after these calls. The address stored at intermediate-context offset 168 is read later as needed.

Only zero versus nonzero matters for the captured character; its signedness does not change that decision.

### 6. Construct the candidate flags

The candidate begins at zero.

- Classification 0 selects F-2bd8af926943 to supply the starting flags.
- Classification 1 selects F-3d1cdf97ba16.
- Any other classification selects neither dependency.

For either supported classification, the chosen dependency receives the address then read from intermediate-context offset 168.

The captured state controls the mask operation:

- Zero clears the mask-selected bits from the starting flags.
- Nonzero sets the mask-selected bits.

The mask and candidate are unsigned 32-bit quantities. Clearing uses a 32-bit complement. Bits outside the mask retain their starting values.

For an unsupported classification, the candidate is still calculated from an initial value of zero, but no final flag-field commit follows.

### 7. Compare, commit if different, and mark changed

For classification 0 or 1, the function freshly reads the address at intermediate-context offset 168. From that containing object it reads the final-object address at offset 3840.

It compares the candidate with the current 32-bit destination:

| Classification | Destination offset |
|---:|---:|
| 0 | 2864 |
| 1 | 2956 |

If equal, the function returns without writing either that destination or the change marker.

If different, it writes the candidate to the selected destination. It then reloads the final-object address from offset 3840 of the same containing object and writes byte value 1 at offset 2960 of the reloaded final object.

Thus:

- The commit comparison uses destination memory, not merely the earlier flag dependency’s return value.
- The offset-168 address used for the flag dependency need not equal the one later used for commitment.
- The final-object address used for the marker is reloaded after the flag store. Aliasing or external mutation can make it differ from the address used for that store.

Unsupported classifications return without reading these final commit destinations or writing their marker.

## Side effects

Direct writes, in execution order, are:

1. An unconditional byte store to the state record.
2. A conditional byte store to a secondary record.
3. A conditional 32-bit store to one selected flag field.
4. A byte store of 1 to a change marker, only after a differing flag value is stored.

The function never explicitly clears the marker. If destination flags already equal the candidate, the marker remains untouched, whatever its previous value.

Dependency effects are unknown. Calls must not be assumed to preserve globals, captured storage, input-object fields, nested pointers, or object lifetimes. Aliasing can also make an apparently separate write affect later reads.

No direct allocation, deallocation, reference-count operation, or explicit ownership transfer is visible. Passing an address does not establish whether a dependency borrows, retains, releases, or invalidates it.

The two zero-result gates are explicit early-exit conditions, not a general error-reporting interface. Invalid accesses and invalid call targets have no visible recovery path. Earlier effects are not rolled back.

## Acceptance examples

These are conditional predictions, not executed tests. Unless specified otherwise, assume valid addresses, successful gates, stable relevant storage, and no dependency mutations beyond stated results.

1. **Different primary-base reads select different records.**  
   The first base read selects a notification record whose offset-0 value is 42. The second selects a different state record whose byte is 0. The state record’s byte becomes 1. D-02 receives 42 and replacement 1. Subsequent primary offset-4, offset-12, and offset-16 reads use the state record, not the notification record.

2. **First gate fails after enabling.**  
   A stable state byte of 0 becomes 1. D-01 returns zero. F-682adfd5a561 and all later calls and writes are skipped. The initial byte remains 1.

3. **Second gate fails after disabling.**  
   A stable state byte of 1 becomes 0. D-01 succeeds, but F-682adfd5a561 returns zero. No notification, mirror, or flag processing follows.

4. **Stable nonbinary state becomes zero.**  
   A state byte of 255 becomes 0. If later calls leave it unchanged, flag processing clears mask-selected bits.

5. **The two state reads disagree.**  
   The subtraction read observes 255; the comparison read observes 0. The comparison does not replace the subtraction result with zero. Under the supplied 32-bit arithmetic representation, the byte written is `02`, and the retained notification argument has the full `FFFFFF02` bit pattern, not merely byte value 2. This example does not establish synchronization or portable signed-conversion semantics.

6. **Classification 0 sets bits.**  
   Captured state is nonzero, mask is `00000005`, and F-2bd8af926943 returns `00000008`. The candidate is `0000000D`. If destination offset 2864 contains `00000008`, it receives `0000000D`, followed by marker value 1.

7. **Classification 1 clears bits.**  
   Captured state is zero, mask is `00000005`, and F-3d1cdf97ba16 returns `0000000F`. The candidate is `0000000A`. Offset 2956 is written only if its current value differs.

8. **Candidate matches destination.**  
   The selected destination already equals the candidate. Neither it nor the marker is written. Earlier state changes, notifications, and any mirror operation remain effective.

9. **Unsupported classification.**  
   Classification is 2. The mask and classification calls occur, but neither starting-flags dependency runs. No final flag-field or marker write occurs.

10. **Callback changes the state record.**  
    The retained replacement is 1, but D-03 changes the state-record byte to 0. If the special comparison matches, the secondary byte receives 1. Later flag processing captures 0 and clears mask-selected bits.

11. **Zero mask still permits a commit.**  
    A zero mask preserves the starting-flags dependency’s returned value. If destination memory differs from that value, the function still stores the candidate and marks a change.
