# F-b774eb6cb163

## Purpose

The dependency also receives two adjusted object-associated addresses, several addresses into the first object, a byte read from that object, and two opaque values supplied by the caller.

The established behavior is coordinate preparation followed by one unconditional dependency call. The meaning of the delegated operation is unknown. In particular, the evidence does not establish copying, drawing, clipping, compositing, or any particular interpretation of the coordinate records.

The ordering of the public inputs differs from the ordering of the prepared records passed onward: the record associated with the second object is passed to the dependency before the record associated with the first object.

## Behavior

### Coordinate preparation

The function constructs two temporary records, each consisting of four consecutive 32-bit integer components.

It completes the temporary record associated with the second object first. Its components are prepared in this order:

1. First coordinate record component 0, increased by the second object’s value at +0x30.
2. First coordinate record component 1, increased by the second object’s value at +0x2c.
3. First coordinate record component 2, increased by the second object’s value at +0x30.
4. First coordinate record component 3, increased by the second object’s value at +0x2c.

It then constructs the temporary record associated with the first object:

1. Second coordinate record component 0, increased by the first object’s value at +0x30.
2. Second coordinate record component 1, increased by the first object’s value at +0x2c.
3. Second coordinate record component 2, increased by the first object’s value at +0x30.
4. Second coordinate record component 3, increased by the first object’s value at +0x2c.

Thus, each object’s +0x30 value is applied to components 0 and 2, and its +0x2c value is applied to components 1 and 3.

The displayed preparation reads an object translation field separately for each component that uses it. It does not explicitly capture either translation field once and reuse that captured value. If the memory is stable, the paired components receive equal translations. Behavior involving concurrent mutation, volatile storage, or externally changing memory cannot be fully specified from this representation.

Within each individual addition, the relative evaluation order of the coordinate read and the object-field read is not established. The eight component preparations themselves appear in the order described above.

There is no coordinate validation, endpoint reordering, normalization, saturation, clipping, scaling, or conversion in the visible preparation.

The dependency is still called once. Zero translation does not bypass the operation or forward the original coordinate-record pointers in place of the temporary-record pointers.

### Reversed endpoints remain reversed

This example assumes no external mutation during preparation.
