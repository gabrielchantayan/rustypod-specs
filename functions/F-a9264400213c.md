# F-a9264400213c

## Purpose

F-a9264400213c obtains a destination address, publishes a value through two ordered two-byte stores, and invokes a dependency on the temporary used for that publication. A subsequent predicate determines whether the function performs a second stage.

On the nonzero branch, the function invokes an indirect operation selected through the third argument, obtains another writable address, assigns a global four-byte value through that address, and performs a replacement publication to the original destination.

Each publication uses **two separate source reads**, not a single four-byte snapshot:

- The first reads the four-byte temporary and converts its value to two bytes.
- The second reads the two-byte slice at byte offset 2 within that temporary.

The second read is not established to represent the numeric high-order half without an endianness assumption.

The two-stage update is established static behavior. Its domain meaning, and whether any dependency allocates, releases, validates, or transforms an object, remain unresolved.

## Behavior

The following sequence applies when dependencies return normally and all required memory accesses are valid. A fault, exception, or nonlocal transfer may interrupt it; the body contains no recovery mechanism.

### 1. Acquire the destination

F-603a53835f04 receives, in order:

1. The first argument.
2. Zero.
3. Zero.
4. Zero.

Its returned address is retained as the destination for both possible publications.

The function performs no visible null, bounds, alignment, or writability check. Normal completion requires that the destination support two-byte stores at byte offsets 0 and 2 when those stores occur. The body does not explicitly release the destination.

### 2. Prepare and perform the first publication

F-5d7410a76c21 receives:

1. The address of the value temporary initialized from the fourth argument.
2. The original second argument by value.
3. One.

The caller does not consume a return value from this dependency. Whatever contents remain in the value temporary supply the subsequent publication reads.

The publication has four ordered actions:

1. Read the four-byte value temporary and convert its value to a two-byte quantity, retaining its low-order 16 bits.
2. Store that two-byte quantity at destination byte offset 0.
3. Separately read the two-byte slice at byte offset 2 within the value temporary.
4. Store that two-byte slice’s value at destination byte offset 2.

The numeric truncation in the first action and the storage slice in the third action are distinct operations. Identifying the offset-2 slice with the original value’s high-order 16 bits requires little-endian storage. Under big-endian storage, that slice instead corresponds to the original value’s low-order 16 bits, provided the temporary remains unchanged.

The second source read occurs after the first destination store. The body does not establish a shared snapshot for the two stores. If an allowed aliasing relationship causes the first store to change the source slice, the second read observes the source at that later point. Whether such aliasing is valid under the complete calling contract remains unknown.

There is no dependency call between the two stores. Nevertheless, the representation does not establish an atomic four-byte update, hardware visibility ordering, or synchronization with other observers.

After both stores, F-9b718979506d receives the address of the same value temporary. Its role is unknown. It must not be assumed to preserve, clear, release, or invalidate that temporary or any other accessible state.

### 3. Evaluate the continuation predicate

F-ec61551795ee receives the destination address.

- Any nonzero result selects the second stage.

The distinction is zero versus nonzero, not positive versus negative.

This call occurs after the first publication and after F-9b718979506d returns. The predicate therefore operates after any side effects those preceding operations have produced. The visible body does not independently compare or validate destination contents.

The body contains no checks for an invalid third argument, invalid table address, invalid entry, or unusable callable target. It also contains no explicit validation of the table-address-plus-8 calculation. Valid dispatch storage and a valid callable entry are preconditions for normal continuation.

### 6. Prepare and perform the replacement publication

F-4062894eb208 receives:

2. The original second argument by value.
3. The third argument.
4. The address of the temporary initially containing the copy of the second argument.

The value temporary has not been explicitly reinitialized since F-9b718979506d received its address. The second-argument copy may have been modified by F-67a6bf796de6 or other accessible-state effects. Neither temporary is guaranteed to retain its initial contents.

The separate by-value second argument is still supplied from the original argument, not by reading the exposed copy.

After F-4062894eb208 returns, the function performs the replacement publication to the original destination:

1. Read the four-byte value temporary and convert its value to two bytes, retaining the low-order 16 bits.
2. Store that quantity at destination byte offset 0.
3. Separately read the temporary’s two-byte slice at byte offset 2.
4. Store that slice’s value at destination byte offset 2.

The same endianness and separate-read qualifications apply as in the first publication. The function does not establish one four-byte snapshot or one indivisible four-byte store.

F-9b718979506d then receives the value temporary’s address again. The function returns without another predicate evaluation or loop.

## Side effects

### Explicit writes

The visible body performs:

- Initialization of three invocation-local temporary objects.
- An unconditional pair of two-byte destination stores.
- On the nonzero branch, a four-byte store through the address returned by F-67a6bf796de6.
- On that branch, a second pair of two-byte stores to the original destination.

Dependency side effects are additional and unresolved. Consequently, the last explicit destination stores do not, by themselves, guarantee the destination’s contents at return: the final F-9b718979506d invocation may affect accessible state.

### Ownership and failures

## Acceptance examples

These are conditional obligations derived from static evidence, not executed tests. Unless an example says otherwise, assume valid accesses, normal returns, stable source storage during each publication, and no additional dependency side effects.

### Zero result with little-endian storage

Assume little-endian storage and that F-5d7410a76c21 leaves the value temporary equal to hexadecimal A1B2C3D4.

The first publication must:

- Read the four-byte temporary, truncate its value to hexadecimal C3D4, and store that two-byte quantity at destination offset 0.
- Then separately read the two-byte source slice at offset 2, whose value under these assumptions is hexadecimal A1B2, and store it at destination offset 2.

If F-9b718979506d leaves the destination unchanged and the predicate returns zero, no indirect dispatch, F-67a6bf796de6 call, or F-4062894eb208 call follows.

### The same value with big-endian storage

Assume instead big-endian storage and the same unchanged numeric value, hexadecimal A1B2C3D4.

The first conversion still yields hexadecimal C3D4. The separately read source slice at byte offset 2 also has value hexadecimal C3D4 under this storage assumption. Thus both destination halfword stores carry C3D4.

This conditional example demonstrates why the second store cannot unconditionally be specified as a numeric high-half store or why the pair cannot universally be described as copying the original four-byte representation.

### Nonzero continuation and replacement

Suppose the predicate returns nonzero, the indirect operation returns a four-byte token, and F-67a6bf796de6 returns valid independent storage.

The token must be forwarded to F-67a6bf796de6. The global read and assignment must occur after that call and before F-4062894eb208.

If F-4062894eb208 leaves hexadecimal 11223344 in the value temporary, then under little-endian storage the replacement publication stores hexadecimal 3344 at destination offset 0, followed by the separately read hexadecimal 1122 at offset 2. The second F-9b718979506d invocation follows both stores.

Any nonzero predicate value selects this sequence, including one interpreted as negative.

### Changed copied argument

If F-67a6bf796de6 changes the exposed copy of the second argument, F-4062894eb208 receives that changed object by address. Its separate by-value second argument remains the original argument. Those two inputs need not agree.

### Changed global

If the indirect operation or F-67a6bf796de6 changes the global before returning, the subsequent assignment uses the global read after F-67a6bf796de6 returns, not an entry-time snapshot.

### Unchanged initial temporary

If F-5d7410a76c21 leaves the value temporary unchanged, the first conversion and later slice read use storage initialized from the fourth argument. Their respective numeric results still depend on conversion rules and storage byte order as described above.
