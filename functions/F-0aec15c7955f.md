# F-0aec15c7955f

## Purpose

F-0aec15c7955f processes a tagged input stream associated with a caller-supplied object. It maintains three numeric attributes and a string-like temporary, and dispatches constructed records through an indirect callback on that object.

The visible control flow distinguishes:

- **Ordinary completion:** a nonzero reader/setup status or a recognized closing marker leads to a common cleanup sequence.
- **Fatal invariant failure:** repetition of an already-nonzero numeric attribute, or a failed predicate before string-data processing, invokes F-a817d8d58c10, which is identified as non-returning.
- **Record dispatch:** a particular tagged marker causes allocation, record-related writes, and callback invocation. Dispatch does not itself end processing.

“Parser,” “attribute,” “string,” and “record” describe inferred intent. The contract below separately identifies the established accesses, ordering, status handling, and unresolved dependency behavior.

## Interface

### Input object

The function accepts one object pointer. The supplied representation uses 32-bit words and 32-bit pointer-sized values.

| Object byte offset | Established access |
|---|---|
| 0 | Read as the address of a dispatch table. |
| 52 | Address supplied to reader-related dependencies. |
| 64 | One byte cleared during ordinary cleanup. |

For dispatch, the function loads the callback address from byte offset 28 of the dispatch table. It invokes that callback with:

1. The original object pointer.
2. The address of a temporary 32-bit record-pointer slot.

The object layout beyond these accesses is unknown. The body does not check the object pointer, dispatch-table address, callback address, or reader-context storage for validity.

### Local state and widths

The function maintains:

- A stop state.
- A 32-bit retained status, tested for zero versus nonzero.
- A numeric attribute associated with identifier `0x2B`, stored in a 32-bit quantity but restricted to values `0` through `255`.
- Two unrestricted 32-bit numeric attributes associated with identifiers `0x2C` and `0x2D`.
- An eight-byte string-like temporary.
- An eight-byte initialization temporary.
- A 256-byte input buffer.
- A signed 32-bit buffer-length output.
- A 32-bit tag and a 32-bit numeric-reader output.
- A temporary 32-bit record-pointer slot.

The tag’s low 24 bits select an identifier. Its high 8 bits select a class where explicitly tested. Serialized byte order and numeric decoding are delegated to dependencies.

### Output and preconditions

There is no explicit return value. Observable results consist of dependency calls, callback invocations, record-storage writes, object mutation, and ordinary return or fatal termination.

Required conditions for well-defined accesses include valid object storage, valid indirect-call targets, writable destinations returned by construction dependencies, and an in-range buffer length when the terminator is written. Allocation and construction results are used without local failure checks.

Dependencies must return normally for the subsequent steps described here to occur. No preservation of global values, object fields, or memory ownership is assumed merely because a dependency returns.

## Behavior

### Initialization

The established initialization order is:

1. Invoke F-73af2c5bbd36 without arguments.
2. Invoke F-58eb88c5871a with the object.
3. Clear the stop state and initialize the `0x2B` and `0x2C` attributes to zero.
4. Invoke F-398e0e9a318a on the eight-byte string-like temporary, supplying a fixed static datum.
5. Through a global base pointer, read the 32-bit value at byte offset 4. Supply that value and the initialization temporary to F-9d500e3cf762.
6. Supply F-9d500e3cf762’s result to F-aa9d0af98dd1, together with the object’s reader-context address and a zero argument. Retain its status.
7. Invoke an unmapped dependency with the initialization temporary.
8. Initialize the `0x2D` attribute to zero.
9. Enter the processing loop.

Thus, the `0x2D` attribute is initialized **after both F-aa9d0af98dd1 and the unmapped dependency return**, not alongside the other two attributes.

The unmapped dependency is called even if F-aa9d0af98dd1 returns nonzero. Provided it returns, the `0x2D` initialization still occurs before that retained failure status is handled at loop entry. Its effects, including any resource release, are unknown.

The global-derived initialization value is obtained after the earlier initialization calls. There is no basis for treating it as a snapshot taken on function entry.

### Loop entry and tag selection

Each loop entry checks, in order:

1. Whether the retained status is nonzero.
2. Whether the stop state is set.
3. Otherwise, whether F-4b3a084696b2 returns a nonzero status while producing the next 32-bit tag.

Any satisfied condition enters ordinary cleanup. The first two conditions suppress the next tag-reader call.

After a successful tag read, the identifier is the low 24 bits. Only identifiers `0x29` and `0x2A` test whether the class equals `0xC0`. The class does not qualify the numeric or string-data identifiers.

### Identifier `0x29`: closing marker

With class `0xC0`, the function sets the stop state. At the next loop entry, cleanup occurs without another tag read.

With any other class, the tag has no further explicit effect.

Neither case dispatches accumulated state, resets numeric attributes, or updates the string-like temporary.

### Identifier `0x2A`: reset or dispatch

#### Class other than `0xC0`

The function resets state in this order:

1. Set the `0x2B` attribute to zero.
2. Set the `0x2D` attribute to zero.
3. Set the `0x2C` attribute to zero.
4. Invoke F-438680ffebfe on the string-like temporary using the fixed static datum.

No record is allocated or dispatched on this branch.

#### Class `0xC0`

The function performs the following ordered operations:

1. Request 20 bytes from F-8157a180d901.
2. Write the low byte of the `0x2B` attribute at allocation offset 0.
3. Write the 32-bit `0x2C` attribute at allocation offset 4.
4. Invoke F-b9acea4b06ad with allocation address plus 8 and the string-like temporary.
5. Store that dependency’s returned address minus 8 into the temporary record-pointer slot.
6. Write the 32-bit `0x2D` attribute at returned-address offset 8.
7. Read the object’s dispatch-table pointer and callback entry, then invoke the callback with the object and the address of the pointer slot.

The pointer-slot store precedes the final attribute store. This ordering matters because F-b9acea4b06ad’s returned-address contract is unknown. If the final attribute destination aliases the pointer slot, the later attribute write changes what the callback sees in that slot.

The address arithmetic is expressed using the representation’s 32-bit address-sized quantities. There is no explicit bounds or overflow check establishing that either derived address belongs to the allocation. Validity of those accesses is a dependency/precondition issue, not a locally enforced guarantee.

If F-b9acea4b06ad returns the destination address it received, then:

- The derived pointer is the allocation base.
- The final attribute write is at allocation offset 16.
- The visible record writes occupy offset 0, offsets 4–7, and offsets 16–19, with construction delegated at offset 8.

The body explicitly writes no value to allocation bytes 1–3. Other bytes may be initialized by dependencies, but their exact write extent is unknown.

There is no explicit allocation-failure check, construction-failure check, or record release. Dispatch does not explicitly reset the accumulated attributes or string-like temporary. The function does not inspect the pointer slot after the callback.

### Identifier `0x2B`: low-byte numeric attribute

If the retained `0x2B` attribute is nonzero, invoke F-a817d8d58c10 before another numeric read.

Otherwise, invoke F-7d397109ac66 with the reader context and a 32-bit output location. On zero status, retain only the output’s low 8 bits. On nonzero status, leave the retained attribute unchanged and enter ordinary cleanup at the next loop entry.

This guard tracks the retained value, not whether the tag has appeared:

- Reading `0` successfully permits another occurrence.
- Reading `0x100` successfully also permits another occurrence.
- Reading any value with a nonzero low byte makes the next occurrence fatal unless a reset intervenes.

### Identifier `0x2C`: full-width attribute and string operation

If the retained `0x2C` attribute is nonzero, invoke F-a817d8d58c10 before reading a replacement.

Otherwise, invoke F-7d397109ac66. On zero status:

1. Retain the complete 32-bit output as the `0x2C` attribute.
2. Invoke F-438680ffebfe on the string-like temporary using the fixed static datum.

A successful zero value still causes the string operation and leaves repetition permitted.

On nonzero status, neither the retained attribute nor the string-like temporary is explicitly updated by this branch. Cleanup follows at the next loop entry. The supplied representation also shows a load from the numeric-output storage before testing this status; the failed-read output-initialization guarantee is unknown.

### Identifier `0x2D`: other full-width attribute

If the retained `0x2D` attribute is nonzero, invoke F-a817d8d58c10.

Otherwise, invoke F-7d397109ac66 and retain its complete 32-bit output only on zero status. Successful zero values permit repetition. A nonzero status leads to cleanup at the next loop entry.

This branch performs no explicit string operation.

### Identifier `0x44`: buffered string-data operation

First invoke F-6d70e45e29c9 with the string-like temporary. A zero result invokes F-a817d8d58c10 before any buffer-read operation.

A nonzero result permits this sequence:

1. Initialize the signed 32-bit length output to zero.
2. Invoke F-b68442c76a52 with the reader context, capacity 256, the buffer address, and the length-output address.
3. Write one zero byte at the buffer index specified by the resulting length.
4. Invoke F-438680ffebfe with the string-like temporary and the buffer address.
5. Set the `0x2C` attribute to zero.

Steps 3–5 occur regardless of whether F-b68442c76a52 returns zero or nonzero status. A nonzero status causes cleanup only at the next loop entry.

The explicit terminator write is within the declared buffer only for lengths `0` through `255`, inclusive. Length 256 points immediately beyond it; a negative length points before it. The capacity argument of 256 does not establish that the dependency reserves space for this terminator. No local range check is present.

The subsequent string operation receives a buffer pointer without a length. Whether embedded zero bytes truncate interpretation, or how other byte values are interpreted, depends on F-438680ffebfe.

### Other identifiers

The function does not establish whether this dependency skips a payload, validates input, or performs another operation.

### Ordinary cleanup

Every visible ordinary exit performs:

1. Invoke F-f0952e578836 with the reader context.
2. Read a separate global datum and overwrite the first 32-bit word of the string-like temporary with it.
3. Clear one byte at object offset 64.
4. Invoke F-22abefe7f288 with the string-like temporary.
5. Return.

The global datum is read after F-f0952e578836 returns. The object write is one byte, not a full-word clear. The final dependency may have further effects; the body does not establish that the byte remains zero after that call.

No ordinary cleanup is visible following a non-returning fatal call. End of input, read failure, and closing markers do not implicitly dispatch a partial record.

## Side effects

Directly established effects include reader/dependency calls, temporary-state updates, one allocation request per dispatch, record-related writes, indirect callback invocation, and the single-byte object-state clear during ordinary cleanup.

The callback receives the address of invocation-local pointer storage. No lifetime guarantee permits retaining that slot address after the invocation ends. The record address stored in the slot has a separate, unknown lifetime.

The absence of an explicit record release does not establish a leak. The allocation, construction dependency, or callback may transfer, retain, share, or release resources. None of those ownership policies is established here.

Dependencies may change globals or object fields. In particular, dispatch resolves the callback after the construction dependency returns, and cleanup obtains its global replacement value after the reader-cleanup dependency returns. These reads must not be specified as values cached before those calls.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid accesses and normal dependency returns except for the identified fatal operation.

1. **Initialization ordering.** F-398e0e9a318a occurs after initialization of the stop state and the `0x2B` and `0x2C` attributes. The `0x2D` initialization occurs only after the setup-status call and initialization-temporary dependency return.

2. **Setup failure.** If F-aa9d0af98dd1 returns nonzero, the initialization-temporary dependency is still called. The `0x2D` attribute is then initialized, and cleanup occurs without a tag read.

3. **Closing marker.** Tag `0xC0000029` stops processing without another tag read or a dispatch. Identifier `0x29` with another class does not stop processing.

4. **Truncated duplicate guard.** A successful `0x2B` value of `0x12345678` retains `0x78`; another `0x2B` before reset is fatal. A successful value of `0x100` retains zero and permits repetition.

5. **Repeated zero attribute.** Two successful `0x2C` reads of zero are permitted. Each invokes F-438680ffebfe with the static datum.

6. **Failed buffer read still updates state.** Given a passing predicate and an in-range reported length, a nonzero buffer-read status still permits the terminator write, string operation, and `0x2C` reset before cleanup.

7. **String operation reopens `0x2C`.** After a nonzero `0x2C` value, a successful `0x44` branch resets that attribute. A later `0x2C` is not rejected by its previous nonzero value.

8. **Repeated dispatch.** Two successive `0xC000002A` tags request two allocations and invoke two callbacks, with no explicit intervening attribute reset.

9. **Dispatch store order.** After construction returns, the derived pointer is stored in the temporary slot before the `0x2D` store. If that later store aliases the slot, the callback observes the slot after the aliasing write, not a guaranteed intact derived pointer.

10. **Conditional layout.** If construction returns its supplied destination and the allocation does not overlap the pointer slot, the slot contains the allocation base and the `0x2D` write lands at allocation offset 16.

11. **Cleanup ordering.** The one-byte clear at object offset 64 occurs after the cleanup-time global read and temporary-word replacement, but before F-22abefe7f288. The final dependency’s effects are not constrained.
