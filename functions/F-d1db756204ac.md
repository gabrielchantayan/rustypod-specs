# F-d1db756204ac

## Purpose

F-d1db756204ac transforms the low five bits of an unsigned input into a value from 0 through 31, writes that value to a caller-supplied integer destination, and returns zero.

The transformation preserves the lowest three bits and reverses the order of the four eight-value groups selected by the next two bits. Within each 32-value input block:

- Inputs 0–7 map to outputs 24–31.
- Inputs 8–15 map to outputs 16–23.
- Inputs 16–23 map to outputs 8–15.
- Inputs 24–31 map to outputs 0–7.

All input bits above bit 4 are ignored. This is a bounded bit-field permutation, not a reversal of all five individual bits.

The mechanics are established by the supplied static evidence. Any application-level purpose, such as translating a position or indexing a particular data layout, is unknown.

## Behavior

### Transformation

Let:

- \(r\) be the input’s lowest three bits, interpreted as an integer from 0 through 7.
- \(g\) be input bits 3 and 4, interpreted as an integer from 0 through 3.

The destination receives:

\[
r + 8(3-g)
\]

Thus the three-bit position within a group remains unchanged, while the group number changes from \(g\) to \(3-g\).

An equivalent characterization is that bits 3 and 4 of the low-five-bit input are complemented, bits 0 through 2 are retained, and all higher result bits are zero. This equivalence describes the observable mapping; it does not require any particular implementation technique.

### Integer widths and bounds

The masks constrain every arithmetic operand before it contributes to the result:

- The retained low-bit component is between 0 and 7.
- The extracted group number is between 0 and 3.
- Subtracting that group number from 3 yields a value between 0 and 3.
- Multiplication by 8 yields one of 0, 8, 16, or 24.
- Adding the retained component yields a value between 0 and 31.

Consequently, the represented 32-bit arithmetic does not overflow or underflow. The right shift operates on a masked unsigned value, so its meaning does not depend on implementation-specific treatment of right shifts of negative signed integers.

The unsigned input has no negative-value case at this interface. If a caller converts a signed value before calling, the applicable calling-language conversion rules are outside this function’s established behavior.

### Observable operation order

For a valid destination and normal completion:

1. The function computes the bounded transformation from the by-value input.
2. It stores the resulting integer in the destination.
3. It returns zero.

There is no source-level read of the destination’s previous value. That value does not influence the result. There is one source-level integer assignment to the destination; the evidence does not establish the number of physical memory transactions or the atomicity of that assignment.

No additional output is produced. The function does not branch on the input or on the destination’s existing contents.

### Structural properties

The mapping has the following consequences:

- **Period 32:** Inputs that differ only above bit 4 produce the same destination value.
- **Low-three-bit preservation:** The result modulo 8 equals the input modulo 8.
- **Complete range:** As the low five input bits cover 0 through 31, the outputs cover 0 through 31 exactly once.
- **Self-inverse on the low-five-bit domain:** Applying the transformation twice restores the original low five bits.
- **No restoration of discarded high bits:** For an input above 31, applying the transformation twice yields only that input’s low-five-bit value.
- **No fixed points:** No low-five-bit input maps to itself, because its two-bit group number is complemented.

These are consequences of the established mapping, not additional caller obligations.
