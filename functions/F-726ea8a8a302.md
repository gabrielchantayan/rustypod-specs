# F-726ea8a8a302

## Purpose

F-726ea8a8a302 conditionally updates links associated with a caller-supplied record and processes a work chain rooted in that record.

A 32-bit value at record byte offset 16 controls entry:

- If its initial value is zero, the function skips linking and work processing and returns the record address paired with the second input.
- If its initial value is nonzero, the function calls F-7fa3e55b7211, performs two linking writes, and repeatedly processes the current record head through two calls to F-ff1bdc376dcd per encountered item.

“Selected object,” “link,” and “work item” describe access relationships only. Application-level types, ownership transfer, allocation, and destruction are not established.

The order of linking and head inspection is significant. The first head inspection occurs **after both linking writes**. With unrestricted aliasing, those writes can change the head or the temporary value later used in the return.

## Interface

### Inputs

| Input | Representation | Established role |
|---|---|---|
| Record address | Address represented in the supplied 32-bit address model | Base of the accessed record; low half of the return value |
| Fallback value | 32-bit integer | High half of the return value on the initially zero path |
| Unused value | 32-bit value | Not consumed or forwarded |
| Auxiliary value | 32-bit value | Copied to temporary storage and passed by address to F-7fa3e55b7211 on the active path |

The supplied representation uses four-byte words and addresses carried in 32-bit values. This contract does not establish portability to a different pointer width.

The fallback value is preserved as a 32-bit bit pattern. Its signed interpretation does not change the return-half construction.

### Accessed layouts

Record accesses are limited to the following locations:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Current work-item address |
| 4 | 32 bits | Link value, subsequently replaced with a selected-object address |
| 16 | 32 bits | Initial entry condition and source of selected-object addresses |

Selected-object accesses are:

| Byte offset | Width | Role |
|---|---:|---|
| 8 | 32 bits | Value read before F-7fa3e55b7211 |
| 12 | 32 bits | Destination of the first linking write after that call |

The pre-call read and post-call write need not address the same object.

Each encountered work item has these accessed locations:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Successor copied to record offset 0 |
| 4 | 32 bits | Second argument of its first F-ff1bdc376dcd call |
| 8 | 32 bits | First argument of its first F-ff1bdc376dcd call |

No interpretation is established for unaccessed fields. These tables do not require the record, selected objects, and work items to occupy disjoint storage.

### Output

The return is a 64-bit composite:

- Bits 31–0 contain the original record address in the represented address model.
- Bits 63–32 contain either the fallback value or a value sampled from a dependency-visible temporary slot.

These are numeric bit positions, not a statement about memory byte order or return-register placement.

There is no separate success flag, processed-item count, or explicit error result.

## Behavior

### Initial condition

The first explicit memory read obtains the 32-bit value at record offset 16 and stores it in a temporary selector slot.

If that value is zero:

- Neither dependency is called.
- Record offsets 0 and 4 are not inspected.
- No selected-object or work-item storage is accessed.
- No explicit write is made to caller-supplied memory.
- The high return half is the fallback input.

A nonzero work head does not independently cause processing. Entry depends only on the initial offset-16 value.

The temporary selector slot is assigned the chosen high-half value before return. On this inactive path its address has not been passed to a dependency.

### Active-path preparation

When the initial selector is nonzero, the function reads record offset 16 again and uses this second value as the address for a 32-bit read at selected-object offset 8. That field value is stored in a second temporary slot. The auxiliary input is stored in a third temporary slot.

The initial condition and the offset-8 read therefore depend on separate reads of record offset 16. They agree under stable memory, but no synchronization or consistency mechanism is visible.

F-7fa3e55b7211 then receives four arguments, in this order:

1. Address of the auxiliary slot.
2. Record address.
3. Address of the field-value slot.
4. Address of the selector slot.

Its return value is ignored. The function subsequently uses both the record and the selector slot without assuming they retained their pre-call values.

### Linking after the first dependency

After F-7fa3e55b7211 returns, the function:

1. Reads record offset 16 and retains that selected-object address for the linking operations.
2. Reads the current value at record offset 4.
3. Writes that value to byte offset 12 of the retained selected-object address.
4. Writes the retained selected-object address to record offset 4.

The address used in both linking operations comes from the post-call record read. It does not come from the selector slot.

The first write can alter memory subsequently observed by the function, including record fields or the selector slot if they alias its destination. The second write still uses the already retained selected-object address; it does not reread record offset 16 after the first write.

There is no post-call null check. If record offset 16 is zero at step 1, the function still attempts the write at byte offset 12 relative to that address.

Neither a zero head nor a particular selector-slot value immediately after the dependency call determines the loop’s behavior by itself. Both linking writes occur before the loop examines those values.

### Work-chain processing

Each loop inspection performs the following observations in order:

1. Reads the current work-item address from record offset 0.
2. Samples the selector slot into the value used for the eventual high return half.
3. Determines whether the retained work-item address is zero.

If the address is zero, processing ends.

Otherwise, the function reads that item’s successor at offset 0 and writes it to record offset 0. Only after this head update does it obtain the item’s offset-8 and offset-4 values for the first dependency call.

The two calls for the retained item are:

| Call | First argument | Second argument | Third argument |
|---|---|---|---|
| First | Item’s offset-8 value | Item’s offset-4 value | Zero |
| Second | Retained item address | One | Zero |

The relative evaluation order of the two payload-field reads is not established. Both supply the first call, and both occur after the head update.

This timing matters under aliasing. If advancing the head overwrites either payload field, the first call receives the values present after that write, not necessarily the values that existed when the item was selected.

The second call follows the first if the first returns normally. It uses the retained item address even if the first call changes the record head. No item-field reread is required between the calls. Both return values are ignored.

After the pair of calls, the function starts another inspection by rereading record offset 0. It does not preserve a private traversal cursor to the previously read successor. Dependency-induced changes to the head can therefore redirect processing.

### Active-path return

On ordinary loop termination:

- The low return half is the original record address.
- The high return half is the selector-slot value sampled during the terminating inspection.

The selector slot is sampled even when the first inspected head is zero.

The high half need not equal the initial selector, the current record offset-16 value, the address written to record offset 4, or the fallback input. Linking writes and dependency effects may change the selector slot before the terminating sample.

Immediately before return, the temporary selector slot is assigned the selected high-half value. This does not add another read of record offset 16 or another loop inspection.

There is no explicit iteration bound or chain-length arithmetic.

## Side effects

### Explicit memory changes

On the active path, the function explicitly performs:

- One write of the current record link value to the post-call selected object at offset 12.
- One write of the retained selected-object address to record offset 4.
- One head write per encountered work item, copying its successor to record offset 0.

It also initializes temporary slots and assigns the final high-half value to the selector slot before return.

Aliasing can make these writes affect locations with other described roles. The contract specifies their order, not that each affects only one logical field. In particular:

- Linking can create, replace, or clear the head before its first inspection.
- Linking can change the selector slot before its first loop sample.
- Advancing the head can change payload fields read afterward.
- Writes through selected-object storage can affect record fields without an explicit write to those fields by name.

### Dependency effects and ownership

Neither dependency’s implementation is supplied. No preservation guarantee is established for globals, reachable memory, the record, or temporary storage whose address has escaped.

The two calls per work item are not sufficient evidence that a payload or item is released. The function contains no independently identified allocation or deallocation operation outside these unknown dependency calls.

Passing temporary addresses does not establish permission to retain or use them after F-726ea8a8a302 returns. Ownership and retention rules remain unresolved.

### Preconditions for ordinary completion

The accessed locations must be valid for the operations actually taken:

- Record offset 16 must initially be readable.
- The active path must support the subsequent record accesses and writes.
- The selected-object offset-8 location addressed before F-7fa3e55b7211 must be readable.
- The post-call selected-object offset-12 location must be writable.
- Every encountered item must support its successor and payload reads when those reads occur.
- Dependencies must return normally for subsequent steps to occur.

These are access-time requirements. A valid pre-call object does not establish validity of a different address supplied through post-call state.

### Errors and nontermination

There is no visible validation branch, rollback, recovery path, cycle detector, or conversion of memory failures into an error result.

Invalid accesses can prevent completion through platform-specific behavior. No particular exception, signal, or diagnostic is established.

Cycles or dependencies that repeatedly install a nonzero head can prevent termination. No claim is made that the chain existing at entry will necessarily be exhausted.

Offsets are fixed byte displacements in the represented 32-bit model. The evidence does not establish portable behavior for address overflow or invalid address arithmetic; unconditional wraparound behavior is not part of this contract.

## Dependencies

### F-7fa3e55b7211

Invoked once on the initially nonzero path, provided execution reaches the call; not invoked on the initially zero path.

It receives three temporary addresses and the record address in the order specified above. Its relevant possible effects include changes to:

- Record selection, link, and head fields.
- The selector slot later sampled for the return.
- Memory that aliases subsequent access locations.

The auxiliary and field-value slots are not explicitly read afterward by this function. Their significance within the dependency is unknown.

### F-ff1bdc376dcd

Invoked twice for each entered item-processing body, provided both calls are reached and return normally.

The head is advanced before the first call. The second call uses the same retained item address regardless of head changes made by the first.

Argument meanings, accepted payload ranges, global effects, ownership behavior, and possible nonlocal exits are documented_only unknowns.

## Acceptance examples

These are conditional static expectations, not reported executions. Each presumes valid accesses and normal dependency returns where needed.

1. **Initially zero selector with pending work.**  
   Record offset 16 is zero, while offset 0 contains a nonzero address. Neither dependency is called. The function does not inspect the pending item or explicitly change the head or link. The return combines the fallback high half with the record-address low half.

2. **Empty chain after linking.**  
   F-7fa3e55b7211 returns with record offset 16 naming object B and offset 4 containing L. The function writes L to B’s offset 12, then writes B’s address to record offset 4. Suppose that **after both writes**, the head is zero and the selector slot contains S, with no intervening external change. No F-ff1bdc376dcd call occurs, and the high return half is S. A zero head merely at dependency return would not establish this outcome.

3. **Linking creates work through aliasing.**  
   The dependency returns with a zero head, selected object B, and link value L. Suppose B’s offset 12 aliases record offset 0, L is a valid nonzero item address, and the second linking write does not overlap the head. The first linking write installs L as the head. The following loop inspection sees work despite the head having been zero immediately after the dependency returned.

4. **One item after linking.**  
   Suppose that **after both linking writes**, the head names item Q, Q’s successor is zero, and the subsequent head update does not alter Q’s payload fields. If neither per-item call reinstalls work and no other mutation changes the head, the function writes zero to the head, calls F-ff1bdc376dcd with Q’s offset-8 and offset-4 values and zero, then with Q’s address, one, and zero. The next inspection terminates.

5. **Linking changes the returned selector.**  
   Suppose the first linking destination aliases the selector slot. The written link value is L, and after both linking writes the head is zero and the selector slot contains L. With no intervening mutation, the high return half is L, regardless of the selector-slot value immediately after F-7fa3e55b7211 returned.

6. **Dependency changes the selected object.**  
   Under stable pre-call selection, the offset-8 read uses object A. F-7fa3e55b7211 then changes record offset 16 to object B. The linking destination is B’s offset 12. A and B need not be identical.

7. **Per-item call redirects traversal.**  
   An item’s successor is R, and the function writes R to the head. One of that item’s dependency calls then changes the head to T. If nothing changes it afterward, the next inspection uses T, not a privately retained R.

8. **Post-call null selection.**  
   F-7fa3e55b7211 leaves record offset 16 equal to zero. The function still attempts the offset-12 linking write. This is not a graceful empty-selection exit, and successful completion is not guaranteed.

## Uncertainties

**Established static evidence:** four-byte field widths, accessed offsets, separate selection reads, dependency argument relationships, linking before head inspection, head advancement before payload reads and calls, repeated head reads, selector sampling, and numeric return-half construction.

**Inferred intent:** the operations resemble linking an object and draining pending work. Those interpretations do not establish application semantics or resource release.

**documented_only unknowns:**

- Concrete types and application invariants.
- Byte order, complete ABI, alignment rules, and address-boundary behavior.
- Dependency implementations, callbacks, exceptions, and nonlocal exits.
- Ownership, allocation, release, and retention obligations.
- Valid alias configurations and concurrency discipline.
- Whether later calls access previously exposed temporary storage.
- Payload validity rules and whether cyclic or redirected chains are valid application states.
