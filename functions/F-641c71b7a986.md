# F-641c71b7a986

## Purpose

F-641c71b7a986 performs a sequence of dependency calls and updates a 32-bit linked-record structure associated with a supplied context. It may insert that record into a shared singly linked list, then conditionally invoke an indirect dependency based on a separate shared structure.

The established behavior is structural, not semantic: the supplied representation shows record preparation, an early-return condition, optional key calculation and list insertion, and a final conditional dispatch. It does not establish that the list is a timer queue, that the calculated key is a deadline, or that surrounding calls acquire and release a lock. Those are possible interpretations, not contractual guarantees.

This contract describes the supplied static evidence. No runtime tests have been performed.

## Behavior

### 1. Initial dependency sequence and record selection

The following operations occur in this order, assuming each dependency returns normally:

1. Invoke F-9d5d90660a7a with no explicit arguments shown.
2. Read the context field at byte offset 184 and invoke F-5da16db99672 with the context address and that value.
3. Read the context field at byte offset 176 and invoke F-6904f7699031 with that value and the integer 500.
4. Read the context field at byte offset 176 again. Retain this second value as the selected-record address.
5. Invoke F-936a8728139d with no explicit arguments shown.
6. Read a shared 32-bit value and write it to the selected record at byte offset 32.
7. Read the selected record at byte offset 28.

Because dependencies execute between these reads, neither context field nor shared storage is assumed to retain an earlier value. In particular, the selected record is captured before F-936a8728139d, while the value written at record offset 32 is obtained afterward.

### 2. Early return

If the value read at selected-record offset 28 is nonzero, the function returns immediately.

This return occurs after the write at offset 32. It is therefore not a side-effect-free rejection of an already-marked record.

On this path, the function does not invoke F-338d16f9ce72, F-add44d4e9aaa, the unmapped scalar-producing dependency, F-0d70d6f9010c, F-5bcae2eff9a7, or the final indirect dependency.

No visible operation clears the indicator at offset 28.

### 3. Preparation for possible insertion

If the early-return indicator is zero:

1. Read a shared value and pass it to F-338d16f9ce72.
2. Invoke F-add44d4e9aaa with the selected-record address.
3. Read the 32-bit quantity at selected-record offset 4.

The quantity is read after F-add44d4e9aaa returns. Consequently, a value present on entry does not determine whether insertion occurs if a dependency changes it before this read.

If the quantity is zero, the function skips key calculation and list insertion, then proceeds to the post-insertion phase.

If it is nonzero, the function proceeds with insertion preparation.

### 4. Key calculation and shared-head capture

For a nonzero quantity:

1. Invoke an unmapped dependency, designated here **F-unmapped-01**, and capture its recovered integer result.
2. Read shared storage containing the address of the list-head slot and retain that slot address.
3. Calculate a key from the captured result plus the previously read quantity multiplied by 1000.
4. Store that key at selected-record offset 8.
5. Read another shared 32-bit value and store it at selected-record offset 24.
6. Read the current head pointer from the captured head slot.

The quantity is not reread after F-unmapped-01. The head-slot address is captured before the two record writes, but the head pointer stored in that slot is read afterward.

### 5. List traversal and insertion

Traversal starts at the captured head pointer with no predecessor.

For each non-null current node, the function invokes F-0d70d6f9010c with:

- The address eight bytes into the current node.
- The address eight bytes into the selected record.
- The third explicit argument.
- The fourth explicit argument.
- The unresolved additional 32-bit value.

A zero comparison result means continue traversal. A nonzero result means stop at the current node.

After a zero result, the function reads the current node’s first 32-bit word as the next pointer and records the current node as the predecessor. Thus, the next-link read occurs after the comparison call. If that dependency changes the current node’s link, the subsequently read value determines traversal.

Traversal stops when either:

- A comparison returns nonzero; or
- The current pointer becomes null.

The visible insertion order is then:

1. Update the captured head slot to the selected record if there is no predecessor; otherwise, update the predecessor’s first word to the selected record.
2. Write 1 to selected-record offset 28.
3. Write the stopping current-node pointer to selected-record offset 0.

This establishes insertion before the first node producing a nonzero result, or at the tail if every comparison produces zero.

The visible writes are not an atomic list update. The incoming link changes before the selected record’s outgoing link is assigned. Any guarantee that another observer cannot see this intermediate state would have to come from synchronization outside these direct writes.

No direct duplicate search, self-insertion guard, cycle detection, or traversal limit is visible.

### 6. Post-insertion phase and conditional dispatch

This phase is reached whenever the early-return indicator was zero and preceding operations complete normally, whether insertion occurred or was skipped.

The function:

1. Reads a shared value and passes it to F-5bcae2eff9a7.
2. Reads a pointer from the shared location also used to supply the earlier argument to F-338d16f9ce72.
3. Dereferences that pointer to obtain another pointer.
4. If the resulting pointer is non-null, reads its first 32-bit word.
5. Invokes an indirect dependency only when both that resulting pointer and its first word are nonzero.

The indirect dependency is designated **F-unmapped-02**. Its target is obtained from separate shared function-pointer storage; it is not the nonzero first word used by the condition.

The first shared pointer must be valid even when the pointer obtained through it is null. Only the latter pointer is visibly checked before its first word is read.

No explicit arguments are shown for F-unmapped-02. After that invocation returns, this function returns.

## Side effects

### Direct writes

Subject to the reached branches, the function directly writes:

- Selected-record offset 32 on every normally progressing path, including the early-return path.
- Selected-record offsets 8 and 24 when the quantity at offset 4 is nonzero.
- Either the captured list-head slot or a predecessor’s next-link field during insertion.

When insertion is skipped because the quantity is zero, this function performs no explicit insertion-phase write to offsets 0, 8, 24, or 28. Dependencies may still change them.
