# F-e178ac98b71c

## Purpose

F-e178ac98b71c routes an event-like object through optional specialized processing, a selected indirect callback, and a conditional final callback. Processing stops at the first processing callback that returns a nonzero result. An event whose initially observed type is `0x15` instead returns `1` immediately.

The established behavior is dispatch and result propagation. Descriptions such as “event,” “context,” “type,” and “handled” are explanatory labels, not independently established application semantics. In particular, a nonzero result is a stopping condition; the supplied evidence does not establish that every nonzero value denotes success rather than an error or another status.

## Interface

### Inputs

The function takes two arguments:

- **Context reference:** a reference to an object whose first word supplies the base address used to retrieve indirect callback targets. Another context word, at byte offset `0x50`, participates in the final equality check.
- **Event reference:** an address identifying an object with a type word at byte offset `0x04`. Depending on that type and the execution path, the word at byte offset `0x08` is used either as another object’s address or as a value to compare against the context.

Both arguments are forwarded, in the same order and without an explicit adjustment, to every processing dependency or indirect callback invoked by this function. F-468ee00d626a receives only the event reference.

### Widths and accessed layout

### Output

The result is a 32-bit integer:

- Exactly `1` for an initially observed event type of `0x15`.
- Otherwise, the first nonzero result from an invoked specialized processor, selected primary callback, or conditional final callback.
- Exactly `0` if no such invocation produces a nonzero result.

Results are not normalized to a Boolean. Negative and positive nonzero results are both propagated unchanged.

### Preconditions

Every memory read reached by the chosen execution path must refer to valid, suitably accessible storage. Every selected indirect callback target must be callable with the supplied arguments and compatible return convention.

There are no explicit null, bounds, alignment, callback-presence, or object-lifetime checks. These requirements are path-dependent: an initial type of `0x15` does not require reading the context, whereas subsequent dispatch paths generally do.

## Behavior

### 1. Initial short circuit

The first observable field read is the event type at offset `0x04`.

If that value is `0x15`, the function returns `1`. It does not invoke a dependency, read the context, inspect the event payload, or retrieve a callback target on this path.

If that value differs from `0x15`, processing continues. Later observations of type `0x15` do not trigger this initial short circuit again.

### 2. Specialized processing selection

The function reads the event type again.

If this observation is `0x0D`, it invokes F-468ee00d626a with the event reference. If that invocation returns exactly `0x6F`, it invokes F-39a169b4a9ec with the context and event references. This choice is based on the type value observed before the classifier call; there is no intervening type reread before F-39a169b4a9ec.

If this first specialized route is not selected, a separate selection process follows:

1. The event type is read again.
2. If that observation is `0x0D`, F-468ee00d626a is invoked again. A result of exactly `0x6E` selects F-62a6b26d6853.
3. If the preceding condition does not select F-62a6b26d6853, the event type is read again. If this observation is `0x08`, F-468ee00d626a is invoked. A result of exactly `0x6E` selects F-62a6b26d6853.
4. If neither condition selects it, specialized processing is skipped.

Only one specialized processor is invoked: either F-39a169b4a9ec or F-62a6b26d6853.

A nonzero specialized-processor result is returned immediately. A zero result continues to primary callback dispatch. Skipping specialized processing also continues to primary callback dispatch.

The repeated classifier calls and type reads are behaviorally significant. There is no cached classification shared across the first and second selection attempts. For example, with an unchanged type of `0x0D`, a classifier result other than `0x6F` on the first invocation can be followed by a second invocation whose result selects, or does not select, F-62a6b26d6853.

A classifier result is never itself returned as the function’s result. It controls selection only.

### 3. Primary callback selection and invocation

After specialized processing is skipped or returns zero, the function reads the event type afresh.

- If the observed type is not `0x16`, it selects the callback at callback-table offset `0x110`.
- If the observed type is `0x16`, it reads the event word at offset `0x08` as a nested-object address, then reads the nested object’s word at offset `0x04`.
  - A nested word equal to `0x2A` selects callback-table offset `0x10C`.
  - Every other nested word selects callback-table offset `0x110`.

For a type of `0x16`, the nested-object reads occur before the callback-table base is read from the context. There is no null guard on the nested-object address.

After determining which slot applies, the function reads the callback-table base from context offset `0x00`, reads the selected callback target, and invokes it with the context and event references.

A nonzero callback result is returned immediately. A zero result permits the final conditional stage.

A specialized processor may have changed the event, context, callback-table base, or callback entries before this stage. The primary dispatch uses the values read after that processor returns; it does not retain an earlier type or table base.

### 4. Conditional final callback

After a primary callback returns zero, the event type is read again.

If this observation is not `0x0F`, the function returns zero without reading the event payload or context comparison field for this stage.

If this observation is `0x0F`:

1. The event word at offset `0x08` is read.
2. The context word at offset `0x50` is read.
3. Those two 32-bit words are compared for equality.

A mismatch returns zero without invoking another callback.

On equality, the function reads the callback-table base from context offset `0x00` again, retrieves the callback at offset `0x0E0`, and invokes it with the context and event references. A nonzero result is returned unchanged; a zero result yields zero.

The final stage therefore observes state after the primary callback. The primary callback may enable or disable this stage by changing the event type or either comparison field. It may also change the callback-table base used to obtain the final callback.

### Ordering and arithmetic constraints

The field accesses and dependency invocations occur in the order described above. Conditions short-circuit: reads and calls belonging only to a later alternative do not occur once an earlier alternative has selected a route.

The visible logic uses fixed-offset address formation, equality comparisons, and zero/nonzero result tests. It performs no visible payload addition, subtraction, narrowing, range validation, or signed ordering comparison. Equality of the two final comparison words does not establish whether they represent identifiers, addresses, counters, or another kind of value.
