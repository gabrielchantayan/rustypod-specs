# F-13b43f762d0e

## Purpose

F-13b43f762d0e performs an ordered update on a caller-supplied object. It:

- Consults an embedded region through F-d1b4663968a8.
- Conditionally passes an object field to F-88efe4fe0e59 and performs an indirect dispatch.
- Conditionally clears one byte of object state after an unsigned threshold comparison.
- Performs three further indirect dispatches, the last of which is represented by an incompletely recovered indirect transfer.

These operations and their ordering are established by the supplied static representation. Their application-level meaning is not established. In particular, the evidence does not prove that the embedded region is a queue, that F-88efe4fe0e59 releases a resource, or that the threshold comparison measures elapsed milliseconds.

This contract describes normal continuation through the visible operations. It does not assume that dependencies return normally, preserve object state or global storage, or leave ownership unchanged.

## Behavior

### 1. Consult the embedded region

The function first calls F-d1b4663968a8 with the address 56 bytes into the input object.

Its result is tested only for zero versus nonzero. Both positive and negative nonzero results select the conditional branch.

After that dependency returns, the function reads the shared argument cell and retains the resulting 32-bit value. This read occurs regardless of the dependency’s result.

Consequently, changes to the shared argument cell made by F-d1b4663968a8 can affect the retained value. Later changes to that cell do not cause this function to refresh the retained value.

### 2. Perform the conditional dependency call and dispatch

If F-d1b4663968a8 returned nonzero, the function:

1. Reads the 32-bit object field at byte offset 1,824.
2. Passes that value to F-88efe4fe0e59.
3. After that dependency returns, resolves an indirect target through object offset 0 and table offset 88.
4. Invokes that target with the object pointer, the retained shared value, and the value from the conditional argument cell.

If the initial result was zero, both F-88efe4fe0e59 and this conditional dispatch are skipped.

The indirect target is resolved after F-88efe4fe0e59 returns. Changes that dependency makes to the object’s dispatch-table reference can therefore affect the dispatch target. The conditional global argument is also consumed for this dispatch rather than being part of the earlier shared-value snapshot.

The supplied expression does not establish the relative evaluation order of the dispatch-target lookup and the conditional global argument read. Both belong to preparation of this dispatch, after the preceding dependency has returned.

### 3. Test and possibly clear the flag byte

After the optional branch completes, the function reads the word at object offset 1,324 and converts it to a character-sized value.

If that converted value is zero:

- F-721765717a6b is not called.
- The threshold field at offset 1,316 is not read by this comparison.
- No direct flag-clearing write occurs.

If the converted value is nonzero, the function calls F-721765717a6b with the object pointer. Its result is interpreted as an unsigned 32-bit value.

Only after that call returns does the function read the word at offset 1,316 and compute the threshold:

**Threshold = (32-bit field value + 1,000) modulo 2³².**

It compares the threshold to the dependency result using unsigned 32-bit ordering. If the threshold is less than or equal to the result, the function writes zero to the single byte at object offset 1,324.

Important consequences:

- Equality clears the byte.
- Overflow wraps modulo 2³²; the addition is not saturating.
- The comparison is not a signed comparison.
- It is not an elapsed-time subtraction and does not establish wrap-safe timer semantics.
- The threshold field is read after F-721765717a6b, so mutations made by that dependency affect the comparison.
- The initial flag condition is not re-evaluated after that dependency returns.

The direct store writes exactly one byte. It does not clear the entire 32-bit word at offset 1,324.

On an ordinary little-endian, 8-bit-byte target, that store clears the same low-order byte tested by the character conversion. Without an established byte order and conversion model, that equivalence must not be generalized to every architecture.

### 4. Perform the unconditional dispatch sequence

After the flag-processing stage, the visible control flow performs three indirect invocations in this order:

| Dispatch | First argument | Middle argument | Final argument |
|---|---|---|---|
| First unconditional | Object pointer | Retained shared value | First unconditional argument cell |
| Second unconditional | Object pointer | Retained shared value | Second unconditional argument cell |
| Final | Object pointer | Final leading argument cell | Final trailing argument cell |

Each invocation uses the dispatch-table location at table byte offset 88. The target lookup is repeated for each invocation; the visible body does not retain one target for the whole function.

Accordingly, earlier dependencies or dispatches can change the target reached by a later dispatch. The retained shared value remains unchanged for the invocations that use it, even if the global cell from which it originated has changed.

The final invocation differs from the preceding two: it does not use the retained shared value as its middle argument.

The representation warns that the final indirect transfer was not fully recovered and models it as a call. Its position and supplied arguments are visible, but its precise call-versus-tail-transfer mechanics and return behavior are documented_only.
