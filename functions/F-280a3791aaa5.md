# F-280a3791aaa5

## Purpose

F-280a3791aaa5 describes an ordered mutation of an externally supplied, pointer-linked memory graph, followed by an unresolved indirect control transfer.

The supplied static body establishes stores of argument values, address-derived bytes, self-references, and constants. It also establishes link reloads after mutations, overlapping accesses, arithmetic-derived destinations, and three arguments to the indirect target.

No application-level purpose is established. Initialization, object construction, and parsing would be interpretations, not supported contract terms.

The ordering below preserves the supplied body's memory-access sequence, including interleavings that matter under aliasing. It does not establish that every explicit store is separately observable in an executed program.

No runtime tests have been performed.

## Interface

### Explicit inputs and output

| Input | Width | Established use |
|---|---:|---|
| Payload | 32 bits | Written to two early destinations. |
| Initial byte | 8 bits | Written through the initial Active link. |
| Frame address | 32-bit integer/address representation | Supplies an address calculation and a stored address-derived value. |
| Active byte | 8 bits | Written to Active at offset `0x11`. |

The visible interface has no return value. A return without a result follows the indirect transfer in the supplied representation. Whether the target returns is unknown.

### Ambient inputs

Three address-bearing entry-state values are required:

- **Anchor:** base of the first Payload destination.
- **Context:** principal mutable record.
- **Active:** another mutable record, repeatedly installed in Context links.

Their origins, calling convention, validity, and preservation requirements are not established.

Three external 32-bit words are read late:

- **First external word:** used as an address component and halfword source.
- **Second external word:** used in address arithmetic, a halfword store, and an indirect-call argument.
- **External payload word:** written through a destination derived from Second external word.

The indirect target is unresolved.

### Memory model and preconditions

All offsets are byte offsets. “Word,” “halfword,” and “byte” mean 32-, 16-, and 8-bit accesses respectively. Address-bearing links have a visible 32-bit representation.

A low-byte or low-halfword value retains the least significant 8 or 16 bits. The effect of a byte store on an overlapping numeric word depends on byte order.

Successful traversal requires every reached address to support its access width. This includes addresses produced by saved links, newly reloaded links, subtraction, addition, doubling, and character conversion. No null, bounds, alignment, or graph-consistency checks are visible.

The supplied representation does not establish target byte order, alignment behavior, or a universal wrapping rule for address arithmetic. In particular, signed address additions and doubling must not silently be specified as modulo-\(2^{32}\) operations. Their overflow behavior remains documented_only.

No allocation, release, ownership transfer, or ownership of reachable storage is established.

## Behavior

### Ordering and saved values

The following regions are ordered. Within each region, prose order preserves memory-access order; grouped descriptions do not authorize moving accesses past intervening reads or writes.

Names such as **Marked record** identify saved address values, not stable object identities. A fresh link read may produce a different address because of earlier writes or aliasing. Saved values remain snapshots unless explicitly reloaded.

### 1. Initial publication

Payload is first written to Anchor at `0x60`.

Context's `0x74` word is then read and saved. Context at `0x74` receives Active, after which Payload is written to the previously linked record at `0x30`. The second Payload destination therefore comes from the old link.

Active's `0x14` link is read, and Initial byte is written to that record at `0x09`. Context receives its own address at `0x54`. A word representing Frame address minus `0x74` is written at Frame address minus `0x20`.

The initially reached record's `0x14` link is then followed. Active byte is written to Active at `0x11`; a new word read from Active at `0x14` supplies a saved link whose low byte is written to the second-level record at `0x15`.

That saved link is not assumed equal to the initial Active-link read.

### 2. Early markings and overlapping fields

A fresh Active `0x14` read selects **Marked record**. Context's `0x64` word is read as **Early first word**, then written back to the same field. Marked record receives byte `0x73` at `0x0C`; Context receives Early first word's low byte at `0x15`.

The next accesses have this specific interleaving:

- Active at `0x34` receives the saved Active-link word from the preceding region.
- Marked record's `0x74` word is read as **First marked link**.
- Marked record at `0x54` receives its own address.
- Active at `0x0D` receives Context's low address byte.
- Active at `0x54` receives the saved Active-link word.
- Active at `0x14` receives Marked record's address.

Context's `0x64` word is read again as **Early second word**. Marked record receives byte `0x74` at `0x10`; Context receives word `0x74` at `0x54`; Marked record then receives word `0x74` at `0x10`.

Marked record's `0x74` link is read again as **Second marked link**. Active receives its own address at `0x54`, and Marked record receives word `0x74` at `0x30`.

Context at `0x01` receives Early first word's low byte. The address represented by Early first word receives Early second word's low byte at `0x09`.

The remaining accesses in this region are ordered as follows:

- Context at `0x74` receives Early second word.
- Context at `0x11` receives byte `0x74`.
- Marked record's `0x60` word is read and saved.
- Context at `0x11` receives Early first word's low byte.
- Context at `0x34` receives Early second word.
- Marked record at `0x10` receives the saved `0x60` word's low byte.

The `0x60` read therefore occurs between the two Context `0x11` stores, before the Context `0x34` store. Aliasing can make that placement significant.

### 3. Context-link replacement

Context's `0x14` link is read as **Branch record**. Active at `0x11` receives First marked link's low byte. Context at `0x44` receives Active, and Context at `0x11` receives Early second word's low byte.

Context's `0x74` word is saved as **Earlier Context link**. Context at `0x0D` receives Active's low address byte.

Branch record receives word `0x66` at `0x10`. Context at `0x44` receives Active again, then Branch record receives byte `0x66` at `0x10`. Context at `0x54` and Branch record at `0x60` subsequently receive word `0x66`, in that order.

Context's `0x74` link is freshly read as **Replaced record**, then replaced with Active. Replaced record receives word `0x66` at `0x40`. Context at `0x0D` receives Earlier Context link's low byte.

Replaced record's `0x44` word is saved. Context's self-reference is restored at `0x54`, and the record identified by Second marked link receives its own address at `0x54`.

Replaced record's `0x14` link is followed. Active at `0x11` receives the saved `0x44` word's low byte. A fresh Active `0x14` read supplies the low byte written to the followed record at `0x15`.

### 4. Traversal and redistribution

A fresh Active `0x14` read selects **Transfer record**. Context's `0x64` word is saved as **Transfer first word**. Transfer record receives word `0x73` at `0x20`. Context's `0x64` word is read again as **Transfer second word**, whose low byte is written to Transfer record at `0x09`.

Transfer record's `0x74` link selects **Carrier record**. Carrier record receives Context's low address byte at `0x0D`, then has its own `0x54` word read and written back.

Carrier record next receives byte `0x74` at `0x09`. Context at `0x44` receives Transfer first word before Carrier record at `0x34` receives Context's address.

Carrier record's `0x04` link selects **Relay record**. Relay record at `0x24` receives Transfer second word. Context at `0x19` receives Transfer first word's low byte.

Relay record's `0x74` word is saved as **Transfer link**, followed by its `0x04` word as **Replacement word**.

Context's `0x74` link is read and saved as **Traversal base**. Traversal base's `0x14` link is followed, and that destination receives Transfer link at `0x54`. Traversal base's own `0x04` link is then followed to select **Earlier child**. This second traversal does not start from the destination of the preceding `0x54` store.

Context receives two consecutive byte stores at `0x0D`, both using Transfer second word's low byte. Context at `0x64` receives Replacement word. Earlier child receives word `0x74` at `0x30`.

### 5. Final ordinary graph updates

Traversal base's `0x04` link is read again, and the resulting record's `0x74` link selects **Working record**. This fresh traversal need not pass through Earlier child.

Context's `0x64` word is freshly read; its low byte is retained and written to Context at `0x1D`.

Context's `0x44` link and that record's `0x14` link select **Published record**. Working record at `0x34` receives Transfer link. Context at `0x14` receives Published record. Context's `0x54` word is saved, then Published record at `0x09` receives Context's low address byte.

Working record's `0x04` link, followed by the resulting record's `0x74` link, selects **Descendant record**. Descendant record at `0x15` receives Transfer link's low byte. Context receives its own address at `0x54`, then Working record's low address byte at `0x11`. Descendant record at `0x11` receives the saved Context `0x54` word's low byte.

Descendant record's `0x64` word is saved as **Descendant word**. Context at `0x09` receives the low byte retained from the fresh Context `0x64` read.

Working record's `0x04` link is read again as **Leaf record**. Leaf record receives Context's low address byte at `0x09`; its `0x50` word is read and saved; it receives Descendant word's low byte at `0x11`; and it receives Context's low address byte at `0x09` again.

Context at `0x14` receives Descendant word. Context at `0x0D` receives Leaf record's low address byte. Leaf record's byte at offset zero receives the saved `0x50` word's low byte.

Working record's `0x74` link is saved as **Late link**. Its `0x14` link is then read as **Recipient record**. Leaf record receives its own address at `0x54`.

Recipient record's `0x04` link selects **Final record**. Final record receives byte `100` at `0x10`; Context receives word `100` at `0x54`; Final record receives word `100` at `0x40`.

The final four stores preserve this interleaving:

- Context at `0x0D` receives Descendant word's low byte.
- Recipient record at `0x09` receives Final record's low address byte.
- Context at `0x24` receives the full Descendant word.
- Recipient record at `0x11` receives Context's low address byte.

The two Context stores are not adjacent in the supplied sequence.

### 6. Arithmetic-derived accesses and transfer

First external word is read. Context's `0x74` word is then saved as **Arithmetic link**.

The low halfword of Arithmetic link is written at Context plus Arithmetic link. The low halfword of First external word is written at twice Final record's address.

A character is read at Context plus Late link and converted to an unsigned 32-bit value, called **Character value**. Character signedness is unresolved: the conversion may preserve an unsigned byte value or convert a sign-extended negative character to a large unsigned value.

Arithmetic link's low halfword is written at First external word plus Arithmetic link. The halfword store at Context plus Arithmetic link is then repeated.

Word `0x45` is written at Character value plus `0x45`.

Second external word, External payload word, and Context's `0x44` word are read in that order. The Context value is retained for the indirect transfer.

Byte `0x44` is written at Character value plus `0x44`. External payload word is written as a word at twice Second external word. Second external word's low halfword is written at Transfer link plus Second external word.

The indirect transfer receives three visible arguments:

1. Character value bitwise-OR `0x44`.
2. Second external word.
3. The saved Context `0x44` word.

No validation or explicit error handling intervenes.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Old-link Payload destination.** With valid storage and no interfering aliasing, the second Payload store targets the old Context `0x74` destination at `0x30`, despite Context `0x74` already containing Active.

2. **Frame calculation.** If Frame address is `0x1000` and the arithmetic is valid, word `0x0F8C` is written at address `0x0FE0`.

3. **Early interleaving under aliasing.** If Marked record's `0x74` word occupies the same storage as Active's `0x34` word, the First marked link read follows the saved Active-link store to that storage. Subject to valid ordinary-memory semantics and no external interference, it reads that newly stored word.

4. **Read between byte stores.** If Marked record's `0x60` word starts at Context `0x11`, the saved read occurs after the byte `0x74` store there and before the Early first word byte store. On a little-endian target, its low byte is therefore `0x74`, absent external interference.

5. **Traversal base distinction.** If Traversal base's `0x14` and `0x04` links point to different records, Transfer link is stored at the former destination's `0x54`, while the later `0x30` marking targets the latter destination. No `0x04` traversal from the former destination is specified.

6. **Character value without signedness ambiguity.** A late character byte `0x20` yields Character value `0x20` under either interpretation. If execution reaches the accesses, word `0x45` targets address `0x65`, byte `0x44` targets address `0x64`, and the first indirect argument is `0x64`.

7. **Repeated stores.** The two consecutive Context `0x0D` stores remain distinct entries in the static sequence. Independent external observation requires additional target and execution conditions; it is not an unconditional acceptance requirement.

8. **Fault prefix.** If the first arithmetic-derived halfword store prevents continuation, subsequent external-word reads and the indirect transfer are not reached. Earlier graph mutations may already have occurred.
