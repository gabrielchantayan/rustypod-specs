# F-fb33fe278f47

## Purpose

F-fb33fe278f47 assembles an opaque 32-bit aggregate from a descriptor and a terminal handle. It accepts initial descriptor classifications `0x16`, `0x17`, and `0x18`.

Established behavior includes:

- Clearing a descriptor status word after classification.
- Building an optional sequence for classifications `0x16` and `0x18`.
- For classifications `0x17` and `0x18`, acquiring another component, preparing associated-object data, writing a result area, and processing a collection in two passes.
- Selecting a terminal internally when the caller supplies zero.
- Calling a combination dependency and returning the retained aggregate handle.
- Returning zero on explicit rejection and failure paths.

“Aggregate,” “component,” “preparation,” and “conversion” describe local usage, not established application semantics. A zero return does not distinguish explicit failure from normal completion with an empty aggregate.

## Interface

### Arguments and result

| Item | Width | Contract |
|---|---:|---|
| Descriptor address | 32 bits | Used to access the descriptor and its referenced storage |
| Caller terminal | 32 bits | Opaque handle; zero requests internal terminal selection |
| Result | 32 bits | Retained aggregate handle, or zero |

Nonzero caller terminals receive no local validity check. Pointer-bearing fields and handles are 32-bit quantities. Counts, indices, measurements, dimensions, and several dependency results use signed 32-bit comparisons.

### Descriptor and referenced layouts

Offsets are byte offsets. Every listed field is four bytes wide.

| Descriptor offset | Meaning |
|---|---|
| `+0x08` | Status word explicitly cleared |
| `+0x10` | Value passed to F-2eb743f270d1 |
| `+0x14` | Address of a classification-dependent payload |

Payload interpretation:

| Initial classification | Payload fields |
|---|---|
| `0x16` | `+0x04`: optional initial collection |
| `0x17` | `+0x04`: second collection; `+0x08`: associated-structure address |
| `0x18` | `+0x04`: optional initial collection; `+0x14`: associated-structure address; `+0x18`: second collection |

For `0x17` and `0x18`, the associated structure supplies:

| Offset | Meaning |
|---|---|
| `+0x04` | Address of a writable two-word result area |
| `+0x0c` | Required nonzero associated-object address |

The associated object supplies a retained 32-bit value at `+0x08` and a retained signed 32-bit dimension at `+0x0c`.

Initial-collection entries must permit reading their first four-byte word. Second-collection entries supply:

| Offset | Meaning |
|---|---|
| `+0x0c` | Value passed to F-bbc440b3aefa after a positive conversion result |
| `+0x10` | Value required to be nonzero during the first pass and explicitly passed to F-82d6fbbbf739 during the second pass |

Internal terminal lookup can read payload offset `+0x14` for any initial classification. Its returned record, when eligible, supplies a signed first word at `+0x00` and another four-byte value at `+0x08`.

### Preconditions

All addresses actually dereferenced must permit the observed accesses. The function does not validate the descriptor, payload, associated structure, result-area address, associated-object address beyond its nonzero check, or retrieved entry addresses.

A zero initial collection is explicitly skipped. The second collection has no equivalent local null check: its value is passed to collection dependencies even when zero.

Validity requirements imposed by dependencies, including storage capacity and handle validity, remain external preconditions.

## Behavior

### 1. Initial classification and descriptor reads

The function reads descriptor `+0x10`, calls F-2eb743f270d1, and then writes zero to descriptor `+0x08`. The status write therefore occurs after the classification call, including when its result will be rejected.

Subsequent behavior depends on that result:

- **`0x16`:** Read the payload address and its initial-collection field.
- **`0x17`:** Read the second collection, then the associated-structure address, its result-area address, and its associated-object address.
- **`0x18`:** Read the initial collection, second collection, associated structure’s result-area address, and associated-object address, in that order. These associated values are obtained before initial-collection processing.
- **Any other result:** Call F-4fc89ec41a6d with `0x21` and `0x69`, then return zero without component cleanup.

For `0x17` and `0x18`, a zero associated-object address takes the same immediate diagnostic-and-return path. The associated structure and its result-area field have already been read; their validity is not established by the associated-object check.

The descriptor and payload fields are read after the initial classification call, so mutations performed by that dependency can affect those reads.

### 2. Optional initial sequence

Classifications `0x16` and `0x18` process a nonzero initial collection. The retained sequence initially equals zero.

Traversal begins at signed index zero. Before every iteration, including the terminating check, F-10b760faca36 receives the collection and supplies a fresh signed count. An iteration occurs only when the index is less than that count. F-6bbddce1b930 then receives the collection and index.

For each retrieved entry, the observable sequence is:

1. Call F-4a90bce69a78 with no explicit arguments.
2. Obtain a component from F-06794276d5a4.
3. If the component is zero, take generic failure.
4. Read the entry’s first word and pass it to F-2eb743f270d1; its result is not tested.
5. Call F-85ea43423066, then F-61178237911c, both without explicit arguments.
6. If F-61178237911c returns zero, take generic failure.
7. Call F-a5253d33ff6f with the component, `0x6f`, and zero.
8. If a sequence already exists, call F-5f0426916b66 with the sequence and component.

The first successful component becomes the sequence. Later combination results are ignored; the retained sequence remains the first handle rather than being replaced by a combination return value.

A null collection or a nonpositive count at the first check produces no entries. Counts and entries are not snapshotted.

Classification `0x16` proceeds directly to terminal selection with the retained sequence as aggregate. Classification `0x18` continues using the associated addresses and second collection obtained earlier.

### 3. Associated component and result-area preparation

For `0x17` and `0x18`, call F-2ee4104c695c and then F-06794276d5a4. A zero component takes generic failure.

With a nonzero component:

1. Call F-a5253d33ff6f with the component, `0x81`, zero, and the address of a four-byte local output slot.
2. Read and retain associated-object `+0x08`, followed by its signed `+0x0c` dimension.
3. Call F-84c67c58205c with a 32-byte local workspace and the retained `+0x08` value.

The output slot has no explicit initialization before step 1. Its later value depends on dependency behavior.

A signed F-84c67c58205c result below one enters component cleanup without an additional local diagnostic. Otherwise:

1. Call F-8ef9626e8f39 with the associated-object address.
2. Call F-83fcd2d25cd8 with no explicit arguments and write its four-byte result to the first result-area word.
3. If the retained dimension is positive, call F-4d8f43145dac with a separate 16-byte local workspace and that dimension.
4. Call F-b942ec7a0234 with the output-slot value, associated-object address, zero, the 32-byte workspace address, the 16-byte workspace address, and one.

The 16-byte workspace is passed even when its conditional preparation was skipped. The supplied body contains no other initialization of it.

When the retained dimension is positive, subsequently inspect the result area’s second word:

- If zero, call F-c810c23e5619 **without explicit arguments** and write its result to that second word.
- Then read the second word for F-ac3f8766b115, passing the output-slot value and that word.
- A signed negative result enters component cleanup. Zero and positive results continue.

A nonpositive dimension skips this entire second-word stage. Neither result-area write is rolled back on later failure.

### 4. First pass over the second collection

Start with signed maximum zero and index zero. Each loop check calls F-10b760faca36 again. Each entered iteration retrieves its entry through F-6bbddce1b930.

For each entry:

1. Read `+0x10`; zero takes generic failure.
2. Call F-82d6fbbbf739 **without explicit arguments** and retain its returned temporary handle.
3. Call F-f160bf832b18 without explicit arguments to obtain a signed measurement.
4. Pass the temporary handle to F-55d57b266fd4.
5. Replace the maximum only if the measurement is greater.

The checked entry value is not explicitly passed to F-82d6fbbbf739 at this call site. Negative measurements leave the initially zero maximum unchanged. No local check rejects a zero temporary handle.

After traversal, call F-43da6b23bd44 with the maximum, zero, and zero. Its zero result takes generic failure. This call occurs even for an empty collection, with maximum zero.

### 5. Second pass over the second collection

With nonzero temporary storage from F-43da6b23bd44, start another traversal at index zero. Counts and entries are reacquired; neither membership nor entry contents are frozen by the first pass.

For each entry:

1. Read `+0x10` and explicitly pass that value to F-82d6fbbbf739.
2. Call F-c52870ba9865 with temporary storage, the 32-byte workspace, retained associated-object `+0x08` value, and returned temporary handle.
3. Pass the temporary handle to F-55d57b266fd4 before testing the conversion result.
4. If the signed conversion result is below one, call F-4fc89ec41a6d with `0x21`, `0x69`, `6`, zero, and zero; pass temporary storage to F-5990a26eaaa3; then enter component cleanup.
5. Otherwise, read entry `+0x0c` and call **F-bbc440b3aefa** with that value, temporary storage, and the positive conversion result. Its return is not used.

There is no second-pass zero check for entry `+0x10`. The successful processing dependency is F-bbc440b3aefa, not F-c810c23e5619.

After normal traversal, call F-5990a26eaaa3 with temporary storage, then F-80308ee0e93f with the 32-byte workspace and retained associated-object value.

If an initial sequence exists, call F-5f0426916b66 with that sequence and the associated component, ignore its result, and retain the sequence as aggregate. Otherwise retain the associated component.

### 6. Terminal selection and return

A nonzero caller terminal bypasses all internal terminal selection.

For a zero caller terminal, reread descriptor `+0x10` and call F-2eb743f270d1 again. The initial classification is not reused.

If this new classification is `0x16`, call F-5ae03d3507dc with the descriptor, `2`, zero, and zero. A nonzero result selects the special branch: call F-c33e4ea372ac, then obtain the terminal from F-06794276d5a4.

Otherwise, use fallback lookup:

1. Reread the descriptor’s payload address and read payload `+0x14`.
2. Pass that value to F-467cb0c60ff3, whose result is 64 bits.
3. Treat only the low 32 bits as a record address.
4. If that address is nonzero, read its first signed word.
5. Only a positive first word permits reading record `+0x08` and passing it to F-6b64f8976567.
6. A nonzero F-6b64f8976567 result becomes the terminal.

A zero low-half address, nonpositive first word, or zero derived terminal selects default construction: call F-4cfdc219c316, obtain a terminal from F-06794276d5a4, and call F-a5253d33ff6f with that terminal, `0x82`, zero, and zero.

The high half of the 64-bit lookup result has no effect on branch selection: a zero low half already selects default construction; a nonzero low half makes the record’s first word decisive.

Neither constructed terminal is checked for zero. Finally, call F-5f0426916b66 with the retained aggregate and terminal, ignore its return, and return the retained aggregate.

## Side effects

### Direct writes and retained state

Explicit writes outside local storage are:

- Descriptor `+0x08` cleared after initial classification.
- Result-area first word replaced after successful workspace preparation.
- Result-area second word conditionally replaced when the retained dimension is positive and that word is zero.

These writes persist across later local failure handling. Referenced storage may alias; no disjointness checks are present.

Dependencies may modify referenced objects, collections, globals, output slots, or workspaces. No preservation guarantee is established. Fresh field reads and collection queries can therefore observe intervening changes, while explicitly retained values are not automatically refreshed.

### Failure handling and ownership

Generic failure calls F-4fc89ec41a6d with `0x21` and `0x69`, then enters component cleanup. Preparation failure and a negative F-ac3f8766b115 result enter cleanup without that diagnostic. Conversion failure uses the five-argument diagnostic described above.

Component cleanup calls F-738868077376 first for a nonzero initial sequence, then for a nonzero current component. No equality check prevents two calls with the same value if the tracked handles alias. This is conditional call behavior, not proof of double release.

Temporary handles are passed to F-55d57b266fd4 in both collection passes. Temporary storage is passed to F-5990a26eaaa3 after successful processing and after a nonpositive conversion result.

F-80308ee0e93f is called only after normal second-pass completion. No equivalent call is shown on intervening failures.

Consumption, release, retention, and ownership transfer are documented_only for all dependencies and returned handles.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Unsupported classification:** If initial classification returns `0x19` normally, status is cleared before the two-argument diagnostic, followed by zero return.

2. **Missing associated object:** For `0x17` or `0x18`, a zero associated-object field causes immediate diagnostic and rejection, after preceding pointer reads but before collection processing.

3. **Empty plain aggregate:** For `0x16`, a null initial collection and nonzero caller terminal cause final combination with aggregate zero and that terminal. The function returns zero without explicit failure.

4. **Terminal bypass:** With a nonzero caller terminal, no terminal-selection reclassification or lookup occurs.

5. **Nonpositive dimension:** Successful preparation with dimension zero or negative skips F-4d8f43145dac, F-c810c23e5619, and F-ac3f8766b115. F-b942ec7a0234 still receives the 16-byte workspace.

6. **Second-word production:** With positive retained dimension and a zero second word at its check, F-c810c23e5619 is called without explicit arguments and its result is stored. A nonzero second word skips that call.

7. **Conversion boundary:** Conversion zero triggers the five-argument diagnostic, temporary-storage handling, and component cleanup. Conversion one instead causes F-bbc440b3aefa to receive entry `+0x0c`, temporary storage, and one. This successful entry operation does not call F-c810c23e5619.

8. **First-pass rejection:** A first-pass zero entry `+0x10` triggers generic failure. Earlier result-area writes are not undone.

9. **Changing entry:** If a previously nonzero `+0x10` becomes zero before its second-pass read, zero is still passed to F-82d6fbbbf739; there is no repeated local rejection check.

10. **Empty measurement pass:** If the first second-collection count is nonpositive, F-43da6b23bd44 still receives zero, zero, and zero.

11. **Lookup boundary:** A nonzero low-half record address with first word one permits terminal derivation. First word zero or negative selects default construction. A zero low-half address selects default regardless of the high half.

12. **Ignored combination return:** If a combination dependency returns a different handle, that return does not replace the retained aggregate.

## Uncertainties

The following remain documented_only:

- Domain meanings of classifications, operations, handles, diagnostics, and stored results.
- Full dependency signatures, especially no-explicit-argument calls and differing argument counts.
- Whether the output-slot operation initializes its slot.
- Valid downstream interpretation of the 16-byte workspace when preparation is skipped.
- Dependency mutation, aliasing, ownership, and cleanup semantics.
- Temporary-storage capacity and lifetime guarantees.
- Behavior of invalid addresses, dependency exceptions, and nonlocal exits.

Under the displayed signed 32-bit comparisons, loop-index increment itself cannot overflow: an entered iteration requires an index below a signed count, so its greatest possible index is `2,147,483,646`. The next check at `2,147,483,647` cannot admit another iteration. This does not establish safe resource use for extreme counts or valid collection contents.
