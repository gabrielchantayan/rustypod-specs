## Behavior

### First conditional stage

The function first reads the 32-bit field at offset 100 and compares it with the all-ones sentinel, `0xFFFFFFFF`. At this width, that pattern is also the representation used for the comparison value −1.

Every other 32-bit pattern selects the dependency, including zero, positive values, and negative values other than −1. When selected:

- F-ea604bc7e0ca is invoked.
- If it returns normally, the function writes `0xFFFFFFFF` to the 32-bit field at offset 100.

The sentinel write follows the call. This function has therefore not performed that write when the dependency is entered.

There is no second comparison before the write. If the dependency changes offset 100 and returns normally while the storage remains valid, the subsequent direct write replaces the dependency’s resulting value.

If the dependency does not return normally, the following sentinel write and all later operations are not established as executed.

### Second conditional stage

After the first stage completes, the function reads the 32-bit field at offset 112.

This read occurs after any selected first dependency and its following sentinel write. Consequently, the second decision is based on the value present at this later read, not necessarily the value present when the function was entered.

A zero value skips F-702e45e090f5. Any nonzero 32-bit pattern selects it. This is not a signed-positive test: `0x80000000` and `0xFFFFFFFF` both select the call.

If F-702e45e090f5 is invoked, both final writes wait for its normal return. Its effects on storage, globals, ownership, and control flow are otherwise unknown.
