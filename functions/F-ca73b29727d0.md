# F-ca73b29727d0

## Purpose

F-ca73b29727d0 represents an ordered sequence of opaque dependency calls and coprocessor-related operations, followed by a calculated-address 16-bit store. The available static evidence does not establish an application-level purpose.

If execution follows the represented sequence through its final store, it writes **0x00CD** to an address determined by the upper 12 bits of a late 64-bit dependency result. The representation ends at a bad-instruction boundary; no normal return is shown.

This contract is **documented_only**. It describes represented behavior and explicitly identified arithmetic deductions, not a verified execution trace. The supplied representation contains warnings about bad instruction data and truncated control flow.

## Acceptance examples

These are conditional static expectations under the stated width model, not runtime test results.

1. **Third-input selection.**  
   For a third input of **0x12345678**, coprocessor operation 2 and F-000000000011’s first argument carry **0x78000000**. F-000000000016’s second argument is **0x03456780**.

2. **First-input truncation.**  
   First-input values **1** and **33** both produce **0x08000000** for F-000000000011’s second argument. This establishes equality of that argument, not equivalence of complete executions.

3. **Derived zeros.**  
   For every 32-bit R, U has its low four bits clear. Consequently, F-000000000023 receives zero and F-000000000031 receives zero in its second position.

4. **Repeated target without assumed repeat behavior.**  
   If execution reaches both F-000000000008 and F-000000000018, their represented target addresses are equal. A conforming account must preserve that equality; it need not claim equal effects or unchanged target contents.

5. **Shared target with different inputs.**  
   F-000000000024 and F-000000000029 have equal represented target addresses. If the result of F-000000000023 differs from Z’s low 32 bits, the two sites pass different visible argument values despite that target equality.

6. **Ambient-source relationships.**  
   The seven ordered ambient pairs are **(A,E), (B,E), (C,E), (D,E), (C,E), (E,E), (C,E)**. Replacing repeated references with unrelated sources would lose established dataflow. Equal sampled values across time are not required.

7. **Zero destination.**  
   If Z’s top 12 bits are zero and execution reaches the store, its destination is address **0**. The body shows no rejection of that destination.

8. **Noncontiguous destinations.**  
   Top-12-bit values **3** and **4** produce destinations **3** and **5**, respectively. Odd destinations are possible, and address **4** is skipped.

9. **Maximum destination.**  
   If Z’s top 12 bits equal **4095**, the destination is **5118**, or **0x13FE**. Subject to access validity and completion of preceding operations, the store writes **0x00CD** there.

10. **Address equality is not execution equality.**  
    Two Z values with the same top 12 bits produce the same destination. Different low 32 bits may still change the argument supplied to F-000000000029.

11. **Interrupted sequence.**  
    If F-000000000032 does not return, the final store is not established as occurring. An interruption earlier in the sequence likewise prevents claiming the remaining effects.
