## Behavior

The function performs a single explicit memory update: it writes **0xFF** to the byte selected by **B + 4**. It then returns without producing a value.

The previous contents of the target byte are irrelevant to the value written. There is no explicit read of that byte before the write, and no conditional branch based on its contents. A previous value of 0x00, 0x7F, or 0xFF leads to the same store.

The established explicit data-memory access sequence consists of that one byte store. The evidence contains no reads of surrounding bytes and no writes to them. In particular:

- Bytes at offsets 0 through 3 are not explicitly modified.
- Offset 4 receives 0xFF.
- Offset 5 and later bytes are not explicitly modified.
- No containing word, record, or buffer is cleared or initialized as a whole.

These statements describe the function’s explicit data operation, not ordinary instruction-fetch, call-stack, or other execution machinery.

The store has a one-byte extent. It does not depend on multi-byte endianness, and the supplied evidence establishes no requirement that **B** be aligned for a wider integer access. Address validity and access permissions remain requirements of the execution environment.

There is no value-dependent early return, retry, loop, or alternative success path. If the store completes normally, the function returns. If it does not complete normally, the supplied evidence defines no fallback result.
