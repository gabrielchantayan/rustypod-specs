## Behavior

### Initialization and captured state

The represented initialization performs the relevant global reads in this order:

1. Capture the second multiplier.
2. Capture the first multiplier.
3. Read the base selector and subtract one, capturing a **minus-one selector**.
4. Read the base selector again and subtract two, capturing a **minus-two selector**.
5. Read the base selector again and add one, capturing a **plus-one selector**.
6. Read the base selector again to initialize the **current selector**.

The working value, committed result, and pending dependency argument are initialized to zero before dispatch begins.

The four base-selector reads are distinct in the supplied representation. Their results must not be collapsed into one snapshot without an additional stability assumption. If the base selector changes between those reads, the captured selectors need not be adjacent values derived from a common base.

Similarly, the two multipliers are captured separately. They are not refreshed when the dependency is subsequently called.

This ordering describes the supplied representation. It does not independently prove the number or order of physical memory transactions in an executable, particularly because volatility, compiler behavior, and synchronization are not supplied.

### Dispatch decision

At the start of every iteration, the function adds the current selector to a fresh read of the dispatch adjustment.

The resulting value selects one of five actions:

| Dispatch value | Action |
|---|---|
| 0 | Select the captured minus-two selector. |
| 1 | Call the dependency and apply the first multiplier. |
| 3 | Select the caller’s input as the pending argument and redirect execution. |
| 4 | Return the committed result. |
| 2, or any other value | Apply the second multiplier and commit the working value. |

The default action therefore includes negative dispatch values and values greater than four. An unrecognized dispatch value is not an error condition.

After every non-returning action, execution makes another dispatch decision. The dispatch adjustment is read again rather than retained from the previous decision.

### Dispatch value 0: selector change

The current selector becomes the captured minus-two selector.

This action does not call the dependency, change the pending argument, modify either numeric result, or read the redirect selector.

### Dispatch value 1: dependency call and first scaling

The function performs these operations in order:

1. Call F-86cc0abfa18b with the pending dependency argument.
2. Replace the working value with the returned integer.
3. Multiply that working value by the captured first multiplier.
4. Replace the current selector with the captured minus-one selector.

The committed result is unchanged.

Every execution of this action makes a fresh dependency call. The new dependency result replaces the previous working value before multiplication; it is not multiplied into the old working value.

The argument is initially the all-zero four-byte word. It becomes the caller’s input word only after dispatch value 3 has executed. Once selected, that input remains the pending argument because no action resets it to zero.

Any dependency changes to the dispatch adjustment can affect the next decision. Changes to the global multiplier or base-selector storage do not refresh values already captured by this invocation.

If the dependency does not return, none of the post-call operations in this action occur.

### Dispatch value 3: input selection and redirection

The function performs these state changes in order:

1. Read the redirect selector into the current selector.
2. Replace the pending dependency argument with the caller’s input word.

It does not call the dependency immediately. A later dispatch value of 1 is required to forward the selected input.

The working value and committed result are unchanged. Repeating this action rereads the redirect selector and selects the same input word again.

### Dispatch value 2 or default: second scaling and commitment

The function performs these operations in order:

1. Multiply the current working value by the captured second multiplier, replacing the working value.
2. Replace the current selector with the captured plus-one selector.
3. Copy the working value into the committed result.

This action does not call the dependency and does not change the pending argument.

Repeated executions repeatedly apply the second multiplier to the existing working value. They do not start again from an earlier dependency result.

If this action occurs before any dependency call, it operates on the initialized working value of zero. For ordinary representable integer multiplication, the committed result remains zero.

### Dispatch value 4: return

The function immediately returns the committed result.

It does not apply a multiplier, make a dependency call, or copy the working value into the committed result at this point.

This distinction is observable: a dependency call can produce a new working value that is never committed. A subsequent return then yields the older committed result, including the initial zero.
