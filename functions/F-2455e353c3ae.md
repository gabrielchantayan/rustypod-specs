# F-2455e353c3ae

## Purpose

F-2455e353c3ae updates part of a caller-supplied destination through one of two paths:

- A **sentinel path** obtains data from a globally referenced object.
- A **dispatch path** invokes an indirect operation associated with the first input, transfers data from a mutable local argument area, and invokes a final dependency on that area.

Both paths return a 64-bit value formed from two local 32-bit components. The return is not established to be a status code or a pointer.

The branch condition, call order, explicit four-byte destination write, and return construction are established by the supplied static representation. Descriptions such as “default value,” “copy,” and “cleanup” are possible interpretations, not established dependency semantics.

The actual ABI and machine instructions are not supplied, so pointer width and address-arithmetic behavior remain target assumptions rather than independently verified facts.

No input validation is visible.

### Object-relative accesses

The following offsets are byte offsets under the indicated four-byte word model:

- Object offset **0** contains a value used as the base of an indirect-call table.
- Object offset **64** contains a value used as the base of another referenced region.
- Offset **24** within that referenced region contains the 32-bit sentinel field.

The sentinel is the 32-bit signed integer value **−1**, corresponding to all bits set.

These offsets establish only the fields accessed here. They do not establish complete object sizes, class identity, field names, or ownership.

### Destination-relative accesses

The function supplies **destination + 4** as the first argument to F-46f0b3cb316e on either path.

It also explicitly stores one four-byte word at **destination + 12** after that dependency returns.

No explicit write to destination offsets 0–3 appears. However, the write extent of F-46f0b3cb316e is unknown; destination bytes outside the explicit four-byte store must not be assumed unchanged.

### Return value

The return representation is 64 bits:

- Bits 0–31 come from the local object-reference component.
- Bits 32–63 come from the local destination-word component.

This is bit concatenation, not signed addition or sign extension. If the upper component has its top bit set, that bit remains part of the upper half of the result.

On the sentinel path, the visible body does not modify these two components after initialization. On the dispatch path, they are returned after the final dependency call and may reflect mutations through the local-area pointer.

## Behavior

### Entry preparation and branch selection

Before selecting a path, the function:

1. Reads a global reference and retains that value locally.
2. Initializes four local components from the four inputs, preserving their order.
3. Reads the reference at object offset 64.
4. Reads the four-byte field at offset 24 from that referenced region.
5. Compares the field with −1.

The third and fourth inputs do not participate in the branch decision.

The initial global-reference read occurs even when the dispatch path is selected and that retained reference is not subsequently used by the visible body.

The body contains no synchronization, retry, or recovery mechanism. The validity and stability needed for these accesses are caller or environment preconditions.

### Sentinel path

If the sentinel field equals −1, the observable sequence is:

1. Obtain the global reference used to form the dependency’s source address.
2. Invoke F-46f0b3cb316e with:
   - first argument: destination address plus 4;
   - second argument: that global reference plus 4.
3. After the dependency returns, read a four-byte word at offset 12 from the global reference retained at entry.
4. Store that word at destination offset 12.
5. Return the concatenation of the local destination-word and object-reference components.

Two distinctions matter:

- **The global reference used for the dependency argument is a separate expression from the reference retained at entry.** If the global reference changes between the two reads, the dependency’s source address and the later explicit source read can refer to different regions.
- **The word at offset 12 is read after F-46f0b3cb316e returns.** Retaining the reference does not snapshot the referenced contents. If the dependency changes that word, the explicit store observes the post-call value, subject to the execution environment’s memory rules.

Neither the indirect object operation nor F-ee5919ca4be6 is called on this path.

The body does not explicitly modify the local return components on this path. Thus, in an execution where no external action modifies their storage, the result contains the original destination word in the upper half and the original object-reference representation in the lower half.

### Dispatch path

If the sentinel field is anything other than −1, including zero or another negative value, the sequence is:

1. Read the indirect-call table reference from object offset 0.
2. Resolve the callable target at table offset 316.
3. Invoke that target with:
   - first argument: the address of the local object-reference component;
   - second argument: the original object reference.
4. Invoke F-46f0b3cb316e with:
   - first argument: the original destination address plus 4;
   - second argument: the address of the local destination-word component.
5. After F-46f0b3cb316e returns, read the fourth local component.
6. Store that component as four bytes at the original destination address plus 12.
7. Invoke F-ee5919ca4be6 with the address of the local object-reference component.
8. After that call returns, concatenate the current local destination-word and object-reference components into the 64-bit result.

The indirect operation receives a pointer to local storage, not merely the object-reference value. The later dependencies also receive pointers into that local storage. Consequently, the final values must not be described as necessarily equal to the original inputs.

The original destination address remains the base used by the visible destination expressions. A changed local destination-word component can affect the source supplied to F-46f0b3cb316e and the returned upper half without redirecting those explicit destination expressions.

The explicit destination store occurs **after** F-46f0b3cb316e and **before** F-ee5919ca4be6. Therefore:

- A change to the fourth local component made before the store can affect the stored word.
- A change made to that component only by F-ee5919ca4be6 is too late to change that already completed store through this function’s own instructions.
- Changes made by F-ee5919ca4be6 to either return component can affect the returned 64-bit value.

Independent writes by dependencies remain outside these statements about the function’s own explicit store.

These examples are conditional static acceptance criteria. No runtime tests have been performed.

### Sentinel selects the global-backed path

- F-46f0b3cb316e must receive destination + 4 and the separately read global reference + 4.
- The explicit destination-offset-12 store must use a word read after that call, through the entry-retained global reference.
- The indirect operation and F-ee5919ca4be6 must not be invoked.

- The indirect operation must run first.
- F-46f0b3cb316e must run next.
- The explicit destination-offset-12 store must follow.
- F-ee5919ca4be6 must run before return construction.

There is no visible special treatment of other negative values.

### Changed global reference does not replace the retained reference

Provided execution remains valid:

- F-46f0b3cb316e receives B + 4.
- The later explicit source read uses A + 12.

The source reference for that explicit read is not refreshed after the dependency call.

### Dependency mutation affects the later explicit store
