# F-30f3d8fd1907

## Purpose

F-30f3d8fd1907 conditionally performs a set of reset writes or repeatedly invokes dependencies around a caller-supplied cursor operand. It publishes 32-bit values through a caller-provided output slot and returns a 64-bit composition of two 32-bit values.

Established behavior has two paths:

- A shortcut selected by two nonzero dependency results and a nonzero context field. It calls a dependency, rewrites fields reached through the context, clears another context field, and publishes a freshly read header address.
- A general path that repeatedly calls a comparison dependency. For each result other than exactly `1`, it captures a cursor word, calls another dependency with the cursor operand, calls a processing dependency with two writable temporary addresses, and publishes one temporary’s value.

The source establishes the call involving the cursor operand, not cursor advancement. Traversal, removal, destruction, and storage release are not established dependency semantics.

The field layout and reset pattern suggest a container header or sentinel. That interpretation is **inferred intent**, not part of the established behavioral contract.

### Return value

The return combines two 32-bit bit patterns:

- The first value occupies bits `63:32`.

On the general path, the halves are the two result temporaries as they stand **after the terminating comparison returns**. They need not equal the last processing-call outputs or the last value published through the output slot.

## Behavior

### Entry accesses and initialization

Before any dependency call, the function performs these ordered accesses:

1. Read context offset `0x10`.
2. Write that value to the output slot.
3. Read context offset `0x10` again.
4. Read offset `0x08` of the object reached by that second read.
5. Save the resulting 32-bit word in a selection temporary.

The initial output write precedes the second context read. If the output slot aliases context offset `0x10`, the later header access follows the value present after that write. More generally, the evidence does not permit replacing the two context reads with a single entry snapshot.

Before the first dependency call, two result temporaries are initialized:

- The result-address temporary contains the output-slot address.
- The result-context temporary contains the context address.

The function then calls F-be1b50af3623 with the cursor operand and the address of the saved selection word. The second argument points to temporary storage, not directly to header offset `0x08`.

### Shortcut selection

The first comparison result is tested for zero versus nonzero.

If it is zero, the function proceeds directly to the general-loop comparison.

If it is nonzero:

1. The function reads the current context field at `0x10` into a second selection temporary.
2. It calls F-be1b50af3623 with the boundary operand first and the address of that temporary second.
3. If the second result is nonzero, it reads context offset `0x14`.
4. It takes the shortcut only if that field is also nonzero.

If the second result is zero, context offset `0x14` is not read by this selection logic. If the field is read and equals zero, execution proceeds to the general loop.

Both selection-result tests accept any nonzero result. The context-field test also accepts every nonzero 32-bit pattern; it is not a positive-count test.

Changes made through either selection temporary are not directly copied back into the header or context by this function. Dependency side effects and retained references remain separately unknown.

### Shortcut execution

The shortcut begins by reading the current context field at `0x10`, reading offset `0x04` of the resulting header, and calling F-05865b12fc26 with:

- The context address.
- That 32-bit header-field value.

After the dependency returns, the function performs these writes in order:

1. Assign a header address to header offset `0x08`.
2. Assign zero to header offset `0x04`.
3. Assign a header address to header offset `0x0c`.
4. Assign zero to context offset `0x14`.

Each header-field destination is obtained through a fresh context-offset-`0x10` read. Each address-valued assignment also reads context offset `0x10` for the value to store. The relative order of the destination-address and stored-value reads within either such assignment is not resolved by the supplied representation.

These writes do not use an entry-time header snapshot. In particular, F-05865b12fc26 may change the context’s header field, and subsequent accesses use the post-call field. Aliasing may also make an earlier write affect a later destination or stored value.

With stable, nonoverlapping storage, the resulting state is:

- Header offset `0x08` contains the header address.
- Header offset `0x04` contains zero.
- Header offset `0x0c` contains the header address.
- Context offset `0x14` contains zero.

The function then reads context offset `0x10` once more, captures that word, and writes it to the output slot. It returns the captured word in the upper 32 bits and the output-slot address in the lower 32 bits.

The general-loop dependencies are not called on this path.

### General-loop comparison

Every path that does not take the shortcut reaches a call to F-be1b50af3623 with the cursor operand and boundary operand directly.

The loop terminates only when this call returns **exactly `1`**.

Every other result enters the body, including zero, `2`, and negative signed results. This exact-one termination condition differs from the nonzero conditions used during shortcut selection.

No iteration limit is present. Termination depends on dependency behavior.

### General-loop body

Each entered body performs these ordered actions:

1. Read the 32-bit word at the cursor operand and retain that captured word.
2. Call F-8abb04e87ea7 with the cursor operand.
3. Assign the previously captured word to the result-address temporary.
4. Call F-486dc725426a with the address of the result-context temporary, the context address, and the address of the result-address temporary, in that order.
5. Read the result-context temporary and write its value to the output slot.
6. Repeat the loop comparison.

The call to F-8abb04e87ea7 is established; advancement or any other specific mutation is not. If that call changes the cursor word, the third argument supplied to F-486dc725426a nevertheless initially refers to a temporary containing the word captured before the call.

The direct return values of F-8abb04e87ea7 and F-486dc725426a are not inspected.

The result-context temporary is initialized once, before selection. The function does not reset it to the context address at each iteration. Its current value, including any dependency-mediated changes, is available to the next processing call.

The result-address temporary is explicitly overwritten during every entered body, after F-8abb04e87ea7 returns and before F-486dc725426a is called. Any earlier value in that temporary is replaced at that point.

### Retained temporary addresses and general-path return

F-486dc725426a receives addresses of both result temporaries. Whether it retains those addresses is unknown. While the enclosing function remains active, subsequent dependencies could access either temporary through previously retained addresses.

Consequently, a later F-be1b50af3623 call may change either result temporary, including while returning exactly `1`. The last processing-call outputs are not guaranteed to survive that comparison.

After a comparison returns exactly `1`, the function composes its return from the then-current temporaries:

- Upper half: current result-context word.
- Lower half: current result-address word.

There is no additional output-slot write after the terminating comparison. The return’s upper half may therefore differ from the last word this function published. The comparison may also independently modify the output slot or other reachable state; no preservation guarantee is established.

If no body executes, the function itself has not reassigned either result temporary after initialization. Absent dependency-mediated changes to those temporaries, the return contains the context address above the output-slot address. The entry write is then the function’s only direct output-slot write.

## Side effects

### Direct writes

The function directly writes:

- The output slot on entry.
- The output slot after each completed processing call in the general loop.
- On the shortcut, header offsets `0x08`, `0x04`, and `0x0c`, followed by context offset `0x14`, followed by the output slot.

Dependency writes are additional possible effects, not bounded by this direct-write list.

### Ownership and lifetime

No direct allocation, deallocation, ownership transfer, or destruction operation is established. Such effects, if any, belong to undocumented dependency behavior.

Dependencies receive addresses of temporary storage. The source does not establish whether those addresses are retained. Retention cannot be excluded when describing later calls within the same invocation, but it does not authorize access after the enclosing invocation ends.

The function does not itself persist those temporary addresses in a context or header field.

### Preconditions and errors

Every reached direct read and write requires suitably accessible storage. In particular:

- The output slot must support the unconditional entry write.
- Context offset `0x10` must support the reached reads.
- The header reached after the entry output write must support the offset-`0x08` read.
- Each entered loop body requires a readable 32-bit cursor word.
- The shortcut requires its additional header and context accesses to remain valid.

The function contains no explicit null, alignment, bounds, overflow, or allocation-failure checks. A zero context field at `0x14` does not bypass the earlier header access.

Address formation uses the displayed byte offsets in the represented address model. Wraparound validity and behavior at invalid addresses are not established. No count arithmetic or cursor increment is directly performed.

There is no explicit error-reporting or recovery branch. Dependency failures, exceptions, nonreturning calls, invalid accesses, and concurrency effects are **documented_only**.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Immediate general-path termination

Assume valid, nonoverlapping storage and dependencies that preserve relevant state. If the first selection call returns zero and the first loop comparison returns `1`:

- The output slot contains the entry header address.
- No loop body executes.
- Neither the shortcut dependency nor either body dependency is called.
- The return contains the context address in its upper half and the output-slot address in its lower half.

### Stable-header shortcut

Assume both selection calls return nonzero, the subsequently read context field at `0x14` is nonzero, and the header remains stable with no relevant overlap.

After the shortcut dependency returns, the function makes header offsets `0x08` and `0x0c` equal the header address, clears header offset `0x04`, clears context offset `0x14`, and publishes the header address. The return contains that address above the output-slot address.

This example requires no particular release or destruction effect.

### Zero indicator

If both selection calls return nonzero but the subsequently read context offset `0x14` is zero, the next dependency call is the general-loop comparison. Zero does not cause an immediate return.

### Exact-one termination

A loop comparison result of `2` enters the body. A later result of `1` terminates the loop. Treating every nonzero result as termination violates the established condition.

### Captured cursor word

Suppose the cursor word is A when the body reads it, and F-8abb04e87ea7 changes that word to B. The result-address temporary supplied to F-486dc725426a initially contains A, not B.

If the processing call leaves the result-context temporary as X and the result-address temporary as Y, the next direct output write publishes X.

### Terminating comparison changes retained temporaries

Suppose F-486dc725426a retains both temporary addresses and leaves their values as X and Y. The function publishes X.

If the next comparison uses those retained addresses to change the temporaries to U and V and returns exactly `1`, the return contains U above V. If that comparison leaves the output slot untouched and no relevant aliasing exists, the output slot still contains X. Requiring the return to contain X and Y would be incorrect.

### Header replacement

Suppose F-05865b12fc26 changes context offset `0x10` from H1 to H2. If H2 remains valid and stable, the subsequent header reset writes target H2, and the final output is H2. Reusing H1 would not match the represented accesses.
