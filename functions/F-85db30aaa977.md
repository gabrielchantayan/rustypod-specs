## Behavior

### Initial state and dispatch

At entry, the function initializes all retained arithmetic values, both retained opaque arguments, and the retained return value to zero. It reads D01 to establish its initial dispatch state.

Each dispatch combines the current dispatch state with a fresh read of D02. The resulting selector chooses an action:

| Selector | Action |
|---|---|
| 0 | Invoke the dependency and process its result |
| 1 | Prepare arguments |
| 2 | Scale an intermediate |
| 3 | Capture a final result |
| 4 | Return |
| Any other value | Prepare arguments |

Selector 1 and all unrecognized selectors have the same behavior. An unrecognized selector is not rejected and does not directly produce an error.

Except for return, each action obtains a new dispatch-state value from its designated external location and then dispatches again. That value is not itself necessarily the next selector: the next dispatch adds the then-current D02.

The function has no visible iteration limit, timeout, cycle detection, or fallback exit.

### Retained values and overwrite rules

The observable behavior depends on retained state, rather than on an assumed fixed sequence of actions.

There are separate retained values for:

- the two opaque dependency arguments;
- the prepared base for the dependency’s third argument;
- a value shared between intermediate calculations and dependency-argument preparation;
- another value shared between second-input preparation and the dependency’s fourth argument;
- the processed dependency result;
- the final return value.

An action changes only its specified retained values. Skipping an action therefore leaves the affected values at zero or at values produced by an earlier visit. Repeating an action can reuse, overwrite, or further transform prior state.

### Argument preparation

The fourth input is multiplied by a read of D12. The second input is then multiplied by a separate read of D12. Thus, although the same external location supplies both coefficients, there are two reads; equality of their observed values must not be assumed if that storage can change.

The already-scaled fourth input is multiplied by D13. That result becomes the retained base used to prepare the dependency’s third argument.

The scaled fourth input also replaces the shared intermediate value. The scaled second input replaces the retained value later used to prepare the dependency’s fourth argument.

The function then reads D14 as its next dispatch state and retains the original third and first inputs as the dependency’s second and first arguments, respectively.

Argument preparation does not clear the processed dependency result or the retained return value. Revisiting preparation therefore does not reset the entire invocation.

### Intermediate scaling

The currently retained value associated with the second input or fourth dependency argument is multiplied by D05. The product replaces the shared intermediate value.

D06 supplies the next dispatch state.

This action does not necessarily operate on the original scaled second input. A prior dependency invocation may already have replaced its input with a subtractively adjusted value. If reached before argument preparation, its retained input is initially zero.

### Dependency invocation and result processing

Before calling F-027e3622c32f, the function performs these preparations in order:

1. It subtracts D07 from the current shared intermediate and retains the difference as the dependency’s fourth argument.
2. It adds D08 to the retained third-argument base and replaces the shared intermediate with that sum.

The dependency then receives, positionally:

- the retained first opaque argument;
- the retained second opaque argument;
- the newly formed sum;
- the newly formed difference.

The dependency is therefore not guaranteed to receive the original opaque inputs. If argument preparation has not occurred, the two retained opaque arguments are zero.

After the dependency returns, its integer result is multiplied by D09, and D10 is subtracted from that product. The resulting value replaces the processed dependency result. D11 then supplies the next dispatch state.

D09, D10, and D11 are used after the dependency returns. Their values must not be assumed equal to any values that existed before the call. The dependency may alter external storage; its behavior is not supplied.

Repeated invocation is stateful. In particular, the shared intermediate was overwritten with the previous call’s third argument, so a later invocation need not repeat the previous fourth-argument calculation.

### Final-result capture

The current processed dependency result is multiplied by D03. The product replaces both the shared intermediate and the retained return value.

D04 supplies the next dispatch state.

Capturing a result does not itself return. Further preparation, scaling, calls, captures, or dispatch cycles may occur afterward.

If no dependency result has yet been processed, its retained value is zero. Under ordinary arithmetic in which multiplication by zero is defined, capturing at that point records zero.

### Return

Selector 4 returns the retained return value immediately.

Only final-result capture updates that value. Consequently:

- an immediate return yields zero;
- a dependency call followed directly by return still yields zero if no capture has occurred;
- later dependency calls do not alter an already captured return value unless another capture occurs.

There is no visible error branch or special handling for particular dependency results.
