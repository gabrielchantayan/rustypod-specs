# F-2e2f372aa980

## Purpose

F-2e2f372aa980 conditionally submits a negative or positive direction to F-e6a507a7fb23. The direction is determined either by a signed 32-bit value read from a supplied state object or, for six recognized selector values, by the signed 32-bit result of F-aa672b15efb7.

The function has three observable outcomes on a normally returning dependency path:

- A zero decision value causes no direction submission.
- A negative decision value causes submission of the 32-bit value `0xffffffff`.
- A positive decision value causes submission of the 32-bit value `0x00000001`.

If the submission dependency returns a nonzero value, the function calls an additional dependency with argument `1`. The supplied evidence does not identify that dependency’s behavior or establish whether it returns.

Whenever this function reaches its own return, it returns the 32-bit value `1`. That return does not distinguish a zero decision, a successful submission, or a normally returning invocation of the additional dependency.

The apparent intent is selector-dependent comparison followed by direction handling. That interpretation is inferred; the established contract is the call, read, branch, and return behavior below.

## Behavior

Consequently, recognized-selector paths still require this initial read to succeed, even though its value is subsequently replaced by another dependency’s result.

The selector used for branching is the value already obtained from F-7ea64a6e1422. There is no second selector acquisition.

For each recognized selector, the function instead performs the following ordered operations:

2. Calls F-8bb3020950cd again with the same state address. Its return value is not used.
3. Reads the 32-bit field at state offset `0x0c` again.
4. Reads one 32-bit context field:

The first and second state-field reads are separate accesses. The second is not constrained to equal the first. Both intervening dependencies may affect reachable state; their names and call positions do not establish preservation guarantees.

Likewise, the selected context field is read after both recognized-path dependencies. It is not a snapshot taken at function entry.

### Direction submission

The function tests the decision value against zero using signed 32-bit interpretation.

- If the decision is zero, it skips F-e6a507a7fb23 and the additional dependency.
- If the decision is negative, it calls F-e6a507a7fb23 with the context address and `0xffffffff`.
- If the decision is positive, it calls F-e6a507a7fb23 with the context address and `0x00000001`.

This is sign normalization, not magnitude preservation. For example, negative one and the minimum signed 32-bit value both produce `0xffffffff`; positive one and the maximum signed 32-bit value both produce `0x00000001`.

No negation or absolute-value calculation is required by the visible behavior. The minimum signed 32-bit value therefore does not introduce an arithmetic-overflow case in this normalization.

The function then checks F-e6a507a7fb23’s return value:

- Zero: no additional call.
- Any nonzero 32-bit value: call the unmapped dependency with the single explicit argument `1`.

This last check is a zero/nonzero test, not a positive/negative distinction. A negative return value triggers the additional call just as a positive one does.

If all reached calls return normally, the function returns `1`.
