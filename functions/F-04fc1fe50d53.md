# F-04fc1fe50d53

## Purpose

F-04fc1fe50d53 traverses an input byte span, obtains values using a selected decoding mode, and submits values to an output dependency. It accumulates that dependency’s nonnegative results.

Two output paths are available:

- **Direct output:** submit the decoded value to F-9b38954a8ce5.
- **Alternate output:** call F-599631f2aae1 with temporary storage, then submit the bytes indicated by its returned count to F-9b38954a8ce5.

The alternate dependency receives no explicit decoded-value argument. The supplied evidence therefore does not establish that its generated bytes represent the decoded input.

Successful traversal ends only when the current input address equals a fixed end address. A negative decoder or output result causes an immediate return of −1. Earlier dependency effects are not reversed.

These findings are based on static evidence only. No runtime tests have been performed.

## Interface

The function accepts seven arguments:

| Position | Input | Established role |
|---:|---|---|
| 1 | Input address | Initial byte address and starting traversal position. |
| 2 | Signed 32-bit length | Used to compute the fixed end address; also passed unchanged to every delegated decoding call. |
| 3 | Unsigned 32-bit options | Bits 0–2 select decoding; bit 3 selects alternate output. |
| 4 | Unsigned 32-bit output flags | Combined with the automatically selected boundary marker for every output call. |
| 5 | Opaque four-byte argument A | Forwarded unchanged to the output dependency. |
| 6 | Opaque four-byte argument B | Forwarded unchanged to the output dependency. |
| 7 | Opaque four-byte argument C | Forwarded unchanged to the output dependency. |

Decoded-value storage is unsigned 32-bit. Input bytes and temporary output elements are eight bits. Dependency results and the accumulated return value are signed 32-bit integers.

The meanings of the three opaque arguments are unknown. Their four-byte representations do not establish whether they are addresses, handles, integers, or other payloads.

### Options

| Low three option bits | Decoding behavior |
|---:|---|
| 0 | Call F-8f9b7243afe4. |
| 1 | Read one unsigned byte. |
| 2 | Read two bytes in most-significant-byte-first order. |
| 4 | Read four bytes in most-significant-byte-first order. |
| 3, 5, 6, 7 | No decoded-value assignment or input advancement is established. |

Option bit 3 selects alternate output when set and direct output when clear. Higher option bits have no visible effect within this function.

### Return value

- **0:** completion without a positive accumulated contribution, including an empty span.
- **Nonnegative signed 32-bit value:** the sum of nonnegative F-9b38954a8ce5 results, provided every addition remains representable.
- **−1:** immediate failure after a negative F-8f9b7243afe4 or F-9b38954a8ce5 result.

A negative F-599631f2aae1 result does not trigger −1. It suppresses byte-output calls for that iteration.

No separate status is provided for truncation, unsupported decoding selectors, lack of progress, excessive temporary-output counts, or arithmetic overflow.

### Preconditions for defined, bounded use

The function does not enforce the following conditions:

- End-address computation and subsequent address arithmetic must be valid.
- Every selected input read must address readable storage.
- Fixed-width traversal must reach the exact end, rather than merely pass it.
- Delegated decoding must provide a usable decoded value and advancement consistent with valid storage and eventual exact-end completion.
- Every temporary byte read must have been initialized and remain readable.
- Positive alternate-output counts must not require reads outside the eight-byte temporary object.
- Accumulated output results must remain within the signed 32-bit range.

Storage validity does not imply storage stability. A dependency may alter unread input through an alias. Likewise, an output dependency may alter unread temporary bytes if a preceding dependency made their address accessible. Predicting values across calls requires an additional stability assumption or a statement of the bytes present at each read.

## Behavior

### Traversal and completion

The function initializes its output total to zero, retains the original input address and length, and computes one fixed end address by adding the signed length to the original address.

At the start of every iteration, it compares the current address with that end address. Equality returns the accumulated total before decoding or output.

Consequently, a valid zero-length span returns 0 without dependency calls. There is no ordered bounds comparison: an address beyond the end does not count as completion. Negative lengths have no special handling.

For each nonempty iteration, processing occurs in this order:

1. Select a provisional marker according to whether the current address equals the original address.
2. Decode, or take an unsupported-selector path.
3. Replace the marker if the resulting address equals the end.
4. Perform direct output or alternate generation followed by byte output.
5. Return to the equality check.

An error stops this sequence immediately at the failing call.

### Delegated decoding

For selector 0, F-8f9b7243afe4 receives:

- The current input address.
- The original signed 32-bit input length.
- An address for writing the unsigned 32-bit decoded value.

The length is not reduced as input advances. Later calls receive the same length but a different current address.

A negative return immediately produces −1, without output for that iteration. A nonnegative return is added to the current input address as a byte displacement.

Zero advancement is accepted. The function can therefore repeatedly decode and output at the same address. If that address is the original address, each iteration again qualifies for the provisional first-position marker.

The caller does not verify that the dependency initialized decoded-value storage, stayed within the remaining span, or made progress. If the dependency leaves that storage unwritten, the function does not supply a replacement value.

### Fixed-width decoding

**Selector 1:** Read the current byte as an unsigned value from 0 through 255, then advance one byte.

**Selector 2:** Read the current byte for bits 15–8 and the next byte for bits 7–0. The resulting unsigned value ranges from 0 through 65,535. Advance two bytes.

The first byte read precedes the second byte read. No remaining-length check precedes either read.

**Selector 4:** Assemble four bytes into an unsigned 32-bit value, with successive byte positions contributing bits 31–24, 23–16, 15–8, and 7–0. Advance four bytes.

The full unsigned range is available. A set high bit does not itself cause sign extension, rejection, or a negative decoded value.

The expression establishing the first three byte contributions precedes the final-byte read. The evidence does not establish an ordering among those first three reads. No sufficient-input check is present.

Input is read as traversal proceeds, not copied into a stable snapshot before calls begin. An earlier dependency call can therefore affect a later decoded value by modifying unread input through an accessible alias.

### Unsupported decoding selectors

Selectors 3, 5, 6, and 7 perform no visible decoded-value assignment and no input advancement.

On a nonempty span in direct mode, the first output would use decoded-value storage without an established initialized value. In alternate mode, the function still performs alternate generation and any resulting output, but makes no traversal progress.

These selectors are not established as safe no-op modes. In particular, alternate mode does not turn them into guaranteed termination: calls can repeat until an output failure or other behavior intervenes.

### Boundary markers

Before decoding, the provisional marker is:

- `0x20` when the current address equals the original address;
- zero otherwise.

After decoding, equality with the fixed end replaces that marker with `0x40`.

Replacement is significant. An item that is both first and last receives automatic marker `0x40`, not `0x60`.

Each output call receives the caller’s flags bitwise-ORed with the selected marker. Caller-provided bits are not cleared. A caller can therefore supply either boundary bit independently of the traversal position.

The marker describes address comparisons for an iteration, not the ordinal position of an actual output call. An alternate iteration may consume input but emit nothing. Conversely, every output byte from one alternate iteration receives the same marker.

### Direct output

With option bit 3 clear, F-9b38954a8ce5 is called once per iteration with:

1. The unsigned 32-bit decoded value.
2. Caller flags combined with the selected marker.
3. Opaque argument A.
4. Opaque argument B.
5. Opaque argument C.

A negative result returns −1 immediately. Otherwise, the result is added to the accumulated total.

No additional decoded-value validation is visible. In particular, four-byte values are not limited to a character set, scalar-value domain, or signed positive range.

### Alternate output

With option bit 3 set, F-599631f2aae1 receives the address of eight bytes of local temporary storage and the integer 6.

The storage is not visibly initialized before the call. No decoded value is explicitly passed. The meaning of 6 is unknown; it is not an enforced returned-count limit in this function.

The signed return value controls a sequential byte-output loop:

- A zero or negative count produces no output calls.
- A positive count causes temporary bytes to be read beginning at index zero.
- Each byte is submitted individually to F-9b38954a8ce5 as an unsigned byte value.
- Each call receives the same combined flags and opaque arguments for that iteration.
- A negative output result immediately returns −1.
- Every nonnegative output result is added to the total.

Each temporary-byte read occurs before its corresponding output call and after any preceding output calls. The bytes are not all captured before output begins. Thus, if the first output call can access the temporary object through shared state or a retained address, it may change the byte that the second call will receive.

The returned count is not clamped to 6 or to eight. A count above eight causes attempted reads beyond the established temporary object. Counts from 7 through 8 are within its physical extent only if those bytes were initialized; the literal argument 6 supplies no such guarantee.

Input advancement and boundary-marker selection precede alternate generation. A nonpositive count does not undo that advancement.

### Accumulation and failures

Only F-9b38954a8ce5 results contribute to the total. Decoder displacements and alternate-output counts do not.

No overflow check, saturation, or wider accumulator is visible. Signed wraparound must not be assumed. The nonnegative-success contract applies only while additions remain representable.

A failure after earlier successful output returns −1 rather than the partial total. A failure within alternate output leaves subsequent temporary bytes unsubmitted. Neither path reverses completed calls or effects.

## Side effects

Directly visible effects include input reads, writes to local working storage, and sequential dependency calls. No direct input write, allocation, release, or ownership transfer is visible.

This absence does not constrain dependency behavior. In particular:

- Opaque arguments may provide aliases to unread input.
- A dependency may expose the temporary-buffer address through shared state.
- A later dependency may modify storage that this function has not yet read.
- Dependencies may affect global state, perform I/O, retain addresses, or alter caller-accessible memory.

The supplied evidence neither proves nor excludes those behaviors.

Decoded-value storage and alternate temporary storage have local lifetime. Passing their addresses does not establish a durable lifetime or permission to use them after this function returns. No dependency ownership or release contract is available.

Decoding precedes output for each iteration. Alternate generation precedes its byte-output calls. Future input and temporary-byte reads are interleaved with those calls as described above.

There is no visible synchronization, snapshotting, transaction boundary, or rollback mechanism.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, addresses and arithmetic are valid, reads are initialized, and accumulation remains representable. Caller flags are zero unless specified. Dependency storage validity alone does **not** imply preservation across calls.

1. **Empty span.** With length zero and valid end-address computation, the result is 0 and no dependency is called.

2. **Single one-byte item.** For selector 1 and direct output, if the byte read is `0xA5`, output receives value 165 with flags `0x40`. A result of 3 yields final result 3. Automatic flags are not `0x60`.

3. **Two one-byte items with stable unread input.** Suppose the two bytes initially contain `0x11, 0x22`, and the first output call does not change the second byte before its read. Direct output receives 17 and 34, with flags `0x20` and `0x40`. Results 2 and 5 yield 7. Without that preservation condition, the second value follows the byte actually read, not necessarily 34.

4. **Three two-byte items with stable unread input.** Suppose six bytes initially contain `0x01, 0x02, 0x03, 0x04, 0x05, 0x06`, and preceding output calls leave all not-yet-read bytes unchanged. Selector 2 produces `0x0102`, `0x0304`, and `0x0506`, with automatic markers `0x20`, zero, and `0x40`. An alias-based change to an unread byte can change a later value.

5. **Full-width unsigned value.** For selector 4, bytes read as `0x80, 0x00, 0x00, 0x01` produce unsigned value 2,147,483,649. Direct output is not preceded by a signed-range rejection.

6. **Caller boundary bits.** For a two-item one-byte span and caller flags `0x40`, the first direct output receives flags `0x60`; the second receives `0x40`. The first call’s last-position bit comes from the caller.

7. **Original delegated length.** With initial length 5, suppose delegated decoding successfully advances by 2 and then 3 and supplies usable values. Both calls receive length 5. Successful output permits exact-end completion.

8. **Decoder failure after output.** If an earlier item has been output and the next decoder returns a negative result, the function returns −1. Earlier output is not rolled back.

9. **Alternate bytes preserved until their reads.** For one fully consumed input item, suppose F-599631f2aae1 initializes temporary bytes zero and one to `0x41` and `0xFE` and returns 2. Additionally, suppose those bytes retain those values until their respective reads, including across the first output call. Output receives 65 and 254, each with flags `0x40`. Results 1 and 4 yield 5. If the first output call instead changes byte one through an accessible address, the second output receives that changed byte.

10. **Negative alternate count.** If one item reaches the end and alternate generation returns −2, there are no output calls. The final result is 0, not −1.

11. **Alternate output failure.** If alternate generation returns 3 with readable initialized bytes and output returns a negative result on the second submission, the third byte is not submitted. The function returns −1 regardless of the first result.

12. **Truncated fixed-width input.** Selector 2 with only one readable byte does not provide a safe truncation error. A second-byte read is attempted without a bounds check.

13. **Overshoot is not completion.** If a delegated decode moves beyond the fixed end, a successful output does not make the traversal complete. The next iteration still uses exact equality, subject to all address-validity constraints.
