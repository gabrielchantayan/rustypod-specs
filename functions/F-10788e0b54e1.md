# F-10788e0b54e1

## Purpose

F-10788e0b54e1 repeatedly invokes unresolved indirect dependencies and performs interleaved byte and 32-bit memory accesses. Dependency results determine stored values, subsequent call arguments, computed addresses, and state carried into the next iteration.

The visible control flow has an unconditional back edge and no normal return path. This does not guarantee continued execution: a dependency may fail to return, or a memory access or external event may interrupt execution.

No application-level purpose is established. Repeated scaling factors and address offsets suggest structured state manipulation, but identifying an allocator, object layout, protocol, or hardware operation would exceed the evidence.

## Behavior

### Widths and descriptive notation

A byte is 8 bits; a word is 32 bits. Four dependency results are represented as 64-bit quantities, with explicitly consumed low and high 32-bit halves.

The following notation describes the apparent fixed-width behavior:

- **W(x)** retains the low 32 bits.
- **B(x)** retains the low 8 bits.
- **L(x, n)** shifts a 32-bit value left by \(n\), retaining the low 32 bits.
- Right shifts described as logical insert zero bits.
- All computed word-sized addresses use the same 32-bit arithmetic model.

This model captures the represented truncations and scaling. It does not establish portable signed-overflow semantics or independently verify executable instructions.

A **selector-mediated write** reads an unsigned byte at address W(base + 1), then writes one byte at the selected value plus 17. Its destination is therefore between addresses 17 and 272, inclusive—not base plus 17.

Dependency IDs below identify call sites, not necessarily distinct implementations. A **four-call group** invokes its four listed sites in ascending order, without explicit arguments. Unless otherwise stated, the fourth result is consumed and the first three results are not explicitly consumed. Discarding a result does not eliminate possible call effects.

Descriptive intermediate values below are explanatory names, not interface fields.

A complete iteration performs **27 explicit stores: 13 word stores and 14 byte stores**. These counts describe executed store operations, not distinct destinations or changed bytes. Aliasing and repeated writes do not reduce them.

The 14 byte stores comprise:

- **Four direct clearing writes:** two ordered writes to selector base plus 17 and plus 1, repeated once.
- **Ten selector-mediated writes:** the initial write; the two byte-source writes, including the write through saved selector; the global-derived write; the following zero write; the middle-word-derived write; three further zero writes; and the final-word-derived write.

The later word write through saved selector is a separate 32-bit store, not an additional selector-mediated byte store.

Explicit reads comprise ten selector-byte reads, one masked-address word read, and one global word read. The saved-selector word store does not reread its selector.

Dependency effects are excluded from all counts. Their store and read counts are unknown.

## Acceptance examples

These are conditional static expectations, not executed tests. Arithmetic examples use the stated 32-bit model.

1. **Initial selector destination.** If the initial selector read returns 7 and the incoming byte is 165, the first explicit store writes 165 at address 24. The incoming base does not directly determine that destination.

2. **Different value and address scales.** If F-D020 returns 3, the following word store writes 12 at address 68. F-D021 receives three arguments, each equal to 12.

3. **Masked-address upper boundary.** If masked-address source is 0xffffffff, the word read uses address 1043. Reaching subsequent operations requires that this unaligned 32-bit access be supported and valid.

4. **Byte truncation.** If byte source is 65, L(byte source, 2) is 260, but its first selector-mediated byte store writes 4.

5. **Saved selector across calls.** If saved selector is 9, the later retained-word store uses address 29, even if F-D073–F-D076 change the selector byte in memory. The word value is L(retained word, 2).

6. **Fresh selector observation.** If a dependency changes a selector byte between two fresh selector-mediated writes, the later write uses the new byte. Reusing a previously captured selector would not match the represented behavior.

7. **Global sampling order.** If global sample is captured before F-D077 and a later dependency changes that global, the global-derived byte still uses the captured value. Its destination nevertheless uses the selector read after F-D081.

8. **Iteration access counts.** If every dependency returns and every access completes through the back edge, the body performs 13 word stores and 14 byte stores, including four direct byte clears and ten selector-mediated byte writes. Dependency stores are additional and uncounted.

9. **No automatic failure interpretation.** A zero dependency result causes no visible error branch. It remains subject to the specified shifts, scaling, and address calculations.

10. **Next-iteration arguments.** If F-D144 returns 1, the next fourth argument is 4 and the next second argument is 0x40000000. The next first argument independently comes from F-D146.
