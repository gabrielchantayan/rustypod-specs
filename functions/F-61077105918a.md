# F-61077105918a

## Purpose

F-61077105918a is a machine-state-dependent routine with a conditionally executed halfword transfer followed by a nonterminating dispatch-and-interrupt cycle.

The supplied representation does not establish a conventional application-level purpose. In particular, it does not justify describing this routine as a parser, allocator, serializer, or ordinary returning procedure.

Under the 32-bit address arithmetic reflected in the representation, most of the apparent conditional processing cannot be reached. The reachable behavior consists of:

- Deriving a branch condition from the low four bits of an incoming machine word.
- Conditionally reading and copying one 16-bit value.
- In a highly constrained, zero-stack-address case, performing an additional indirect halfword update.
- Repeatedly invoking two indirect destinations and requesting software interrupt number 91.

These are static conclusions about the supplied representation, not runtime observations.

## Behavior

### 1. Initial branch selection

The routine multiplies the selector word by \(2^{28}\), retaining the 32-bit result.

This result is zero exactly when the selector’s low four bits are zero. Higher selector bits do not affect that condition.

If the result is nonzero:

- The initial memory transfer is skipped.
- The subsequent exceptional-memory path is skipped.
- Execution proceeds to the terminal cycle.
- The first indirect invocation uses the incoming link address as its base.

In particular, a set selector bit 2 cannot independently enable later behavior. Whenever the initial result is zero, bit 2 is necessarily clear.

### 2. Conditional halfword transfer

If the selector’s low four bits are zero, the routine performs the following observable transfer:

1. Read an unsigned 16-bit value at the incoming source address.
2. Write that value as 16 bits at the source address plus the offset word, with 32-bit address wrapping.

The read precedes the write. There is no intervening dependency invocation.

The routine also derives an intermediate address equal to:

\[
\text{source address}+\text{offset word}-\text{adjustment word}
\pmod {2^{32}}.
\]

That intermediate is used in subsequent comparisons. It is not itself dereferenced on the reduced reachable path.

A zero offset makes the transfer a read followed by a write to the same address. The write is still represented; the routine does not skip self-copies.

For overlapping but unequal addresses, the operation remains one halfword read followed by one halfword write. It is not a general overlapping-buffer copy.

### 3. Conditions for the additional halfword update

After the transfer, the routine evaluates a sequence of conditional arithmetic operations.

Although the representation contains several variable-shift expressions, every right shift reached in this sequence has shift count zero: entry into each such operation requires the preceding intermediate result to be zero. Consequently, no arbitrary large right-shift behavior is needed to characterize the reachable path.

For the additional memory update to be reached, all of these conditions must hold:

- The selector’s low four bits are zero.
- The incoming link address is zero.
- The entry stack address is zero.
- The comparison word equals the offset word.
- The adjusted address from the initial transfer equals the adjustment word.
- The auxiliary word is zero.
- Twice the offset word is zero modulo \(2^{32}\).

The last condition restricts the offset word to either zero or `0x80000000`.

Equivalently, the adjusted-address equality requires:

\[
\text{source address}+\text{offset word}
=
2\times\text{adjustment word}
\pmod {2^{32}}.
\]

These are path conditions, not input checks with reported errors. If any fails, the routine simply does not reach the additional update.

The zero-stack-address requirement follows from two earlier zero requirements:

- With a zero incoming link address, an earlier intermediate requires the entry stack address shifted right by one to be zero. Thus the stack address can only be zero or one.
- A later intermediate requires the stack address plus twice the offset word to be zero modulo \(2^{32}\). With zero carry entering that addition, an odd stack address cannot satisfy it.

Therefore, an environment that excludes an entry stack address of zero also excludes this additional update.

### 4. Exceptional indirect halfword update

If all the preceding conditions hold, the routine reaches an update whose addressing and value both come from unsigned halfword reads at address zero.

For stable ordinary memory, let the halfword at address zero, after the initial transfer, have value \(v\). The update then:

- Uses the zero-extended value \(v\) as its destination address.
- Writes the low 16 bits of \(v+15\) at that destination.

The address is not multiplied by two. A loaded value of 32 identifies byte address 32, not byte address 64.

The representation uses separate occurrences of the halfword read to obtain the destination and the value. It does not establish their relative evaluation order. If address zero is volatile, changes asynchronously, or has read side effects, a contract must not assume both reads return the same value.

The initial transfer finishes before these exceptional reads and the resulting store. Thus an initial transfer targeting address zero can change the value subsequently used by this update.

This path also assigns zero to an additional machine-state quantity represented as an address base and produces a temporary halfword-pointer value with numeric address two. The architectural meaning and external visibility of the additional base assignment are not established.

### 5. Why the later conditional regions do not execute

The exceptional path cannot continue through the next complete zero-result chain.

Reaching that path already requires the earlier derived address involving the incoming link and stack address to be zero. The exceptional path then changes another temporary address to two.

The next zero-result chain consequently reaches an exclusive-or result of two, not zero. Its next stage is disabled.

If the exceptional path was not entered, the entry condition for that chain is false instead. Thus neither route can reach the later conditional arithmetic, record stores, signed-halfword-derived stores, or associated pointer adjustments.

This is a reachability conclusion under the stated 32-bit model. Those textual operations are not additional accepted side effects of the routine under that model.

### 6. Terminal dispatch-and-interrupt cycle

Every path that completes its preceding memory operations reaches a repeating cycle.

For the first cycle:

1. Invoke an indirect destination at the incoming link address plus `0xEB6`, modulo \(2^{32}\).
2. If that invocation returns, invoke the destination at `0x0857A94B`.
3. If the second invocation returns, request software interrupt number `0x5B`.
4. If the interrupt operation returns, set the first invocation’s base to `0x083D4CC2` and repeat.

The first invocation is shown with three explicit 32-bit argument values:

- Zero.
- Zero.
- `0xFFFFFFA5`.

The third value is the unsigned bit pattern corresponding to signed −91. Its consumer-side interpretation is unknown.

The second invocation has no explicit argument expressions in the representation. That does not establish a trustworthy no-argument ABI or guarantee that it receives no machine-state inputs.

From the second cycle onward, the first destination is `0x083D5B78`, provided execution follows the represented return path. The second destination remains `0x0857A94B`.

On the exceptional path, the incoming link address is necessarily zero, so the first destination is `0x00000EB6`.

No return values from either invocation are explicitly consumed. Either invocation or the interrupt may fail, terminate execution, transfer control elsewhere, or never return; the supplied material does not constrain those behaviors.

## Acceptance examples

These are conditional static acceptance examples. None has been executed.

1. **Selector excludes the copy.**  
   Given selector `1`, valid execution destinations, and returning dependency behavior, no data-memory access occurs before the first indirect invocation. Its destination is the incoming link address plus `0xEB6`.

2. **Higher selector bits do not prevent the copy.**  
   Given selector `0x10`, source address `0x1000`, offset `4`, a source halfword `0xBEEF`, and a nonzero incoming link address, the routine reads `0x1000`, writes `0xBEEF` at `0x1004`, and reaches the terminal cycle without the exceptional update.

3. **Zero-offset transfer remains observable.**  
   Given selector zero and offset zero, the initial operation reads the source halfword and writes it back at the same address. An implementation that omits that write would not preserve behavior for write-sensitive memory.

4. **Nonzero valid stack excludes the exceptional update.**  
   Given any nonzero entry stack address, the additional indirect halfword update is unreachable under the stated arithmetic model. This does not exclude the initial transfer.

5. **Exceptional zero-address behavior.**  
   Suppose the selector, source address, offset word, adjustment word, comparison word, auxiliary word, incoming link address, and entry stack address are all zero. Suppose address zero contains stable halfword `0x0020`, and all necessary accesses are supported. The initial transfer writes `0x0020` back to address zero. The exceptional update writes `0x002F` at byte address `0x20`. The first indirect destination is then `0x00000EB6`.

6. **Halfword overflow in the exceptional update.**  
   Under otherwise valid exceptional conditions, stable loaded value `0xFFFF` selects byte address `0xFFFF` and produces stored halfword `0x000E`. Whether that destination supports a halfword write is environment-dependent.

7. **Continued dispatch.**  
   If both invocations and the interrupt return, the next cycle invokes `0x083D5B78`, then `0x0857A94B`, then requests interrupt `0x5B`. No successful-completion return is expected.
