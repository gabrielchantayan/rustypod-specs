# F-1da4010d015d

## Purpose

The established behavior is a partially recovered execution fragment containing two ordered source-level evaluations of one fixed-location 32-bit global word, seven call sites, and five explicit memory writes. The first global evaluation supplies a retained value for the final call. The second supplies the first call’s third argument. These values need not be equal.

The fragment ends at an invalid-instruction boundary. No ordinary return or successful-completion result is established.

No application-level purpose is recoverable. Describing the writes as initialization, device configuration, object mutation, or cleanup would require unavailable information about the destinations and dependencies.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, value relationships, and ordering.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **Unknowns:** behavior requiring unavailable instruction, memory-map, dependency, or calling-convention information.

The two global evaluations are source-level observations. They do not establish two distinct machine-load transactions. Executable validity and correspondence between the supplied representation and actual instructions remain unresolved.

2. Evaluate the same global word again as F-U01’s third represented argument.

## Acceptance examples

These are conditional static expectations, not runtime test results. Each assumes accurate recovery, reachable operations, valid accesses, and dependency behavior sufficient for the described sequence to proceed.

### Stable global across both evaluations

Suppose the global word evaluates to 96 on both evaluations, and the retained value survives intervening execution.

- F-U01 receives 96 as its third represented argument.
- F-U07 receives 3.
- Equality of the original global values follows from the stated stability assumption, not from shared use of a single evaluation.

This example does not require or establish two distinct machine-load transactions.

### Different values across the evaluations

Suppose the first global evaluation yields 96 and the second yields 160.

- F-U01 receives 160 as its third represented argument.
- F-U07 receives 3, derived from the earlier retained value of 96.
- F-U07 does not receive 5 merely because F-U01 received 160.

How the location could change between evaluations is not established. The example specifies conditional dataflow, not an observed concurrent update.

### Global modification after the first call begins

Suppose the first evaluation yields 96, the second yields 160, and F-U01 subsequently changes the global location to 224.

- F-U01 has already received 160 as its third represented argument.
- F-U07’s represented argument remains 3, assuming the retained value survives.
- The later value 224 is not visibly evaluated for either call.
