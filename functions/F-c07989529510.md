# F-c07989529510

## Purpose

F-c07989529510 transfers sample blocks from record-supplied source storage into one of three destination planes. It supports a direct-transfer path when both configured scale factors equal 256 and a coordinate-mapped path otherwise.

The destination-plane selector, global sampling mode, scale factors, and record coordinates determine the destination region and source-sample layout. The function does not allocate destination storage, validate buffer bounds, or report errors.

**Established behavior:** the operation consists of ordered memory reads and destination writes, with two calls to F-870c4fcf7295 for each supported coordinate-mapped record.

**Inferred intent:** the three planes and sampling modes resemble a full-resolution plane plus two reduced-resolution planes. No color model, pixel format name, or external image standard is established by the supplied evidence.

## Interface

The function has three inputs and no returned value:

1. **Destination descriptor:** an address of a structure containing destination-plane addresses and dimensions.
2. **Record array:** an address of consecutive 20-byte records.
3. **Record count:** a signed 32-bit integer.

The supplied representation uses 32-bit addresses, 32-bit signed integers, 32-bit unsigned integers, 32-bit word accesses, and 8-bit byte accesses.

| Byte offset | Field | Interpretation |
|---|---|---|
| 32 | Plane 0 address | Destination base for selector 0 |
| 36 | Plane 1 address | Destination base for selector 1 |
| 40 | Plane 2 address | Destination base for selector 2 |

### Record layout

| Byte offset | Field | Interpretation |
|---|---|---|
| 0 | Selector | Signed 32-bit plane selector |
| 4 | Horizontal origin | Signed 32-bit coordinate |
| 8 | Vertical origin | Signed 32-bit coordinate |

Records are processed in increasing index order. Neither the records nor their source buffers are copied before processing.

### Shared configuration

A shared configuration object supplies:

### Preconditions

For a defined, bounded transfer, the caller must provide:

- Valid descriptor, record, configuration, source, and destination storage for every access actually reached.
- A supported selector: 0, 1, or 2.
- For selectors 1 and 2, a supported sampling mode: 0, 1, or 2.
- Suitable alignment for every reached 32-bit source read and destination write.
- Coordinates, dimensions, and arithmetic ranges that keep all accessed addresses valid.
- A known contract for F-870c4fcf7295 sufficient to establish safe mapped starting coordinates.

The function does not enforce these conditions. Unsupported selectors are particularly unsafe; they are not consistently ignored.

## Behavior

### Record entry and path selection

A count less than 1 returns immediately without explicit access to descriptor fields, records, configuration, or sample storage.

For each processed record, the function first reads the selector and descriptor width to derive the destination row pitch:

- Selector 0: width rounded upward to a multiple of 8.
- Any other selector: the unsigned width is shifted right by one, then rounded upward to a multiple of 4.

These operations use unsigned 32-bit arithmetic. Addition can wrap before the low alignment bits are cleared; this is not an unbounded mathematical rounding operation.

The source address is then loaded from the record. The horizontal scale is read next. If it equals 256, the vertical scale is read to decide whether the direct path applies. If the horizontal scale differs from 256, that particular vertical-scale path-selection read is skipped.

Consequently, the function does not capture one atomic configuration snapshot.

### Direct transfers

When both scale factors equal 256, no call to F-870c4fcf7295 occurs. Descriptor height is not used, and no right-edge or bottom-edge clipping is performed.

Selector 0 always uses the full 8-by-8 transfer, regardless of sampling mode. Selectors 1 and 2 use the sampling mode to choose the transfer shape.

| Selector and mode | Destination origin relative to selected plane | Output shape | Source-row spacing |
|---|---|---|---|
| Selector 0 | horizontal origin + pitch × vertical origin | 8 columns × 8 rows | 32 bytes |
| Selector 1 or 2, mode 0 | horizontal origin + pitch × vertical origin | 8 columns × 8 rows | 32 bytes |
| Selector 1 or 2, mode 1 | horizontal origin + signed-half of the pitch–vertical-origin product | 8 columns × 4 rows | 64 bytes |
| Selector 1 or 2, mode 2 | signed-half of horizontal origin + signed-half of the pitch–vertical-origin product | 4 columns × 4 rows | 64 bytes |

Here, “signed-half” means signed division by two with truncation toward zero. In the vertical term, the pitch–coordinate product is formed first, then interpreted as signed 32-bit before division. Dividing the coordinate before multiplication is not generally equivalent.

#### Eight-column rows

For each row, the function:

1. Reads the first 32-bit source word.
2. Reverses that word’s four byte positions and writes one 32-bit destination word.
3. Reads the next 32-bit source word.
4. Reverses its byte positions and writes the next destination word.
5. Advances to the next source and destination rows.

On a little-endian target, the eight output bytes are source byte offsets:

**3, 2, 1, 0, 7, 6, 5, 4**

relative to that source row.

The two source words are not read together before writing. Aliasing can therefore change the second word before it is read.

#### Four-column rows

For mode 2, each row writes four destination bytes, in this order:

1. Byte at source-row offset 2.
2. Low eight bits of the 32-bit word at source-row offset 0.
3. Byte at source-row offset 6.
4. Low eight bits of the 32-bit word at source-row offset 4.

On a little-endian target, these correspond to source byte offsets **2, 0, 6, 4**. The second and fourth operations nevertheless perform word reads, not byte reads.

For selectors 1 and 2, unsupported sampling modes cause no explicit sample transfer on the direct path.

### Coordinate-mapped transfers

When either scale factor differs from 256, the function selects the destination plane and caches its bounds:

- Selector 0: plane 0, full width, full height.
- Selector 1: plane 1, unsigned width shifted right by one, unsigned height shifted right by one.
- Selector 2: plane 2, the same reduced bounds.

The bounds are subsequently compared as signed 32-bit values.

Two rounding biases are chosen:

- Vertical bias: 0 if a fresh vertical-scale read is less than 256; otherwise 128.
- Horizontal bias: 0 if the previously loaded horizontal scale is less than 256; otherwise 128.

The biases remain fixed for the record, even if configuration changes afterward.

Selector 0 uses the full source-block interpretation. For selectors 1 and 2, the function reads sampling mode and uses:

| Mode | Origin supplied for vertical mapping | Origin supplied for horizontal mapping | Source extent | Source-row spacing |
|---|---|---|---|---|
| 0 | Vertical origin | Horizontal origin | 8 × 8 | 32 bytes |
| 1 | Vertical origin divided by 2 | Horizontal origin | 8 × 4 | 64 bytes |
| 2 | Vertical origin divided by 2 | Horizontal origin divided by 2 | 4 × 4 | 64 bytes |

Origin division is signed division with truncation toward zero.

#### Starting coordinates and dependency calls

The vertical mapping call occurs first, followed by the horizontal mapping call.

For each axis, its applicable origin is shifted left by 16 bits before being supplied to F-870c4fcf7295. The horizontal invocation also visibly supplies the previously loaded horizontal scale. The supplied representation does not establish the dependency’s complete calling convention.

Each returned signed 32-bit value is combined with the applicable bias, then divided by 256 with truncation toward zero to produce the starting destination coordinate.

This is not arithmetic right shift alone: the visible calculation adds 255 to negative intermediate values before shifting. The division interpretation applies where the intermediate additions do not overflow.

#### Traversal and source selection

Traversal is row-major: increasing destination row, and within each row increasing destination column. Each row restarts at the same computed horizontal starting coordinate.

For each destination row, the function:

- Multiplies the row coordinate by a newly read vertical scale.
- Adds the cached vertical bias.
- Divides by 256 with truncation toward zero.
- Subtracts the record’s applicable vertical origin.

A negative source-row result is clamped to zero. A result beyond the last source row terminates the entire row loop.

For each destination column, it similarly uses a newly read horizontal scale and the cached horizontal bias, then subtracts the applicable horizontal origin. A negative source-column result selects the first source column. A result beyond the last source column terminates that row’s column loop.

The upper bounds on destination rows and columns are exclusive. There is **no lower-bound clamp on destination coordinates**. A negative mapped starting coordinate can therefore cause writes before the selected plane base.

The scale fields and record origins are reread during traversal. Treating them as immutable snapshots would change behavior if they alias writable storage or are modified by the dependency or another actor.

#### Source layouts

For an eight-column source row, logical source columns 0 through 7 select byte offsets:

**3, 2, 1, 0, 7, 6, 5, 4**

The row spacing is 32 bytes in mode 0 and 64 bytes in mode 1. Each selected sample is read as a byte.

For mode 2, logical source columns 0 through 3 select:

- Column 0: byte at row offset 2.
- Column 1: low eight bits of the word at row offset 0.
- Column 2: byte at row offset 6.
- Column 3: low eight bits of the word at row offset 4.

Negative mapped source columns also select column 0’s sample. Destination writes on every mapped path are individual bytes.

Unsupported sampling modes for selectors 1 and 2 perform no explicit mapped transfer and make no mapping calls.

### Unsupported selectors

Selectors other than 0, 1, and 2 do not have a safe no-operation contract.

On the direct path, a supported sampling mode can enter a copy loop without establishing a destination address for the current record. That address may be null initially or may be a cursor retained from a previous record.

On the mapped path, unsupported selectors bypass destination-plane and dimension initialization, yet can continue into mode-dependent mapping and transfer logic using retained or indeterminate state.

Such inputs are outside the defined-use preconditions. An implementation must not characterize them as validated, rejected, or harmlessly skipped.

## Side effects

The function explicitly writes destination sample storage only. It performs no explicit allocation, deallocation, ownership transfer, descriptor update, record update, or configuration update.

Source and destination storage remain caller-provided. Nothing establishes ownership transfer to F-870c4fcf7295 or establishes that the dependency releases no memory.

Overlapping records are applied in record order. Later explicit writes can overwrite earlier ones.

Source and destination overlap is not handled as a buffered move. Reads occur immediately before their associated writes, so earlier writes can alter later source values. Aliasing with descriptors, records, or configuration can also affect subsequent reads.

There is no error return, bounds failure report, rollback, or transactional guarantee. If an invalid access occurs after some writes, no mechanism to undo those writes is visible.

## Dependencies

### F-870c4fcf7295

This dependency is called twice for each supported mapped transfer: vertical mapping first, horizontal mapping second.

Established facts:

- Origins undergo any mode-specific division before the 16-bit left shift.
- Return values participate in signed fixed-point-to-integer conversion.
- The horizontal invocation visibly includes the earlier horizontal-scale value.
- Cached destination addresses, dimensions, pitch, source address, and biases are not recomputed after the calls.
- Later loop reads can observe changed configuration or record coordinates.

Unknowns include the complete argument list, transformation formula, implicit inputs, error behavior, memory ownership effects, and global-state effects. The contract therefore does not assume that this dependency preserves shared configuration or caller memory.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Unless stated otherwise, assume valid aligned storage, supported selectors and modes, non-overflowing arithmetic, and stable memory.

1. **Nonpositive count.** With count 0 or a negative count, the function returns without dereferencing the supplied descriptor or record addresses.

2. **Full direct block.** With both scales equal to 256, selector 0, and width 13, the pitch is 16 bytes. Eight rows of eight bytes are written at the record’s unscaled destination origin. Source rows begin 32 bytes apart. Descriptor height does not restrict this copy.

3. **Mode-independent first plane.** Changing sampling mode while retaining selector 0 and unity scales does not change the direct block’s 8-by-8 shape.

4. **Reduced-height direct block.** With selector 1, mode 1, unity scales, width 32, horizontal origin 3, and vertical origin 5, pitch is 16 and the destination offset is 43 bytes. Four rows of eight bytes are written; source rows are 64 bytes apart.

5. **Reduced-width direct samples.** With selector 2 and mode 2 on a little-endian target, each direct output row contains source offsets 2, 0, 6, and 4. The next source row begins 64 bytes later.

6. **Negative half-coordinate.** In mode 2, a horizontal origin of −3 contributes −1 to the direct destination offset, not −2. This does not make the resulting destination address safe.

7. **Mapped source-edge repetition.** If a mapped destination coordinate produces a negative source-column index, the first source column is selected. If a later coordinate produces an index equal to the source width, that row stops without writing that coordinate.

8. **Mapped destination upper boundary.** If the computed starting column is already at or above the cached signed width, the row receives no writes. A negative starting column is not similarly suppressed.

9. **Record overwrite order.** If two valid records target the same byte, the later record’s write takes precedence, provided neither transfer modifies inputs used by the other.
