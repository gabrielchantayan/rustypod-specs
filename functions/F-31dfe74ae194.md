# F-31dfe74ae194

## Purpose

F-31dfe74ae194 transforms memory using incoming addresses, signed address-forming values, and values recovered from memory. It then exposes partially prepared frame storage to an incoming callable. Further frame updates and dependency calls are conditional on that callable returning.

No application-level purpose is established. In particular, the evidence does not establish a collection operation, allocator, object lifecycle, or ownership protocol. Values used as addresses are also published as data; multiplication results are used as addresses without visible validation.

This contract describes the represented behavior and its ordering constraints. It does not establish that a valid, successfully terminating entry state exists.

### Width and arithmetic contract

Address-forming halfword observations are signed. A halfword with its top bit set therefore supplies a negative value, not an unsigned value between 32,768 and 65,535. That signed value can become an independent address base or a multiplication factor.

Byte and halfword publications retain the low eight or sixteen bits. A word observed solely to supply a byte publication is nevertheless a **32-bit read**, with the corresponding access requirements and possible effects.

The represented integer operations include 32-bit addition, multiplication, doubling, and left shifts. Wider intermediates and universal modulo-\(2^{32}\) arithmetic are not established. ## Behavior

### Ordering and memory identity

The behavioral roles below do not imply separate allocations. Input-addressed memory, context, working regions, literal storage, computed destinations, and frame storage may overlap.

Consequently, ordering is significant even when two executions would leave identical final bytes. Earlier publications can change subsequent observations. A value already captured from memory is distinguished from a later observation of the same location.

The retained word at frame offset `0x108` needs particular care: it is explicitly frame-backed. Subsequent references are not guaranteed to preserve its original contents when computed writes overlap that field.

Each working-base acquisition and its associated link publication use separate represented evaluations of the relevant literal-backed value. Their equality requires stable storage or another preservation guarantee. This does not establish a particular number of physical machine loads.

### Entry relationship and initial publication

The entry link is the word observed at context offset `0x44`. The entry offset is the signed halfword subsequently observed at context plus the incoming displacement. Both are obtained before either input-related publication.

The entry displacement’s low byte is first published at second-input offset `0x15`. The complete second input is then published at displacement offset `0x44`.

The captured entry link selects a successor through its offset `0x74`. At successor plus the captured entry offset, a halfword publication records the entry link’s low sixteen bits. The initial payload is the word observed afterward at successor offset `0x44`; overlap with that halfword publication therefore affects the payload.

Initial publication establishes the context’s self-reference at offset `0x54`, then acquires the first working base. A separate evaluation of the first literal-backed value is published at entry-link offset `0x44`. The acquired working base receives the initial payload at offset `0x14`. Finally, context offset `0x11` receives the low byte of the context address shifted left once.

Later observations of context storage are fresh observations. They do not replace the entry link already captured.

### Two transfers and their selection boundaries

Two transfers move link, payload, and destination information through successive working regions. The first uses the initial payload and first working base. The second uses the first transfer’s carried word and second working base.

Each transfer begins with three ordered observations:

1. A word from first-input offset `0x64`.
2. The active link.
3. A signed halfword supplying an independent address operand.

For the first transfer, the active link comes from context offset `0x44`, and the signed halfword comes from context plus the first working base. For the second, both observations are relative to the first selected destination: its offset `0x44` supplies the active link, and its address plus the second working base supplies the signed halfword.

A destination is selected by observing a word at signed-operand offset `0x14`. This lookup does **not** implicitly add the context, working base, or previous destination.

The first selection immediately follows its three observations. The second selection has an intervening publication boundary: the first carried word’s offset `0x54` receives the first selected destination; that destination’s offset `0x11` receives the second input sample’s low byte; and second-active-link offset `0x44` receives the captured second working base. Only afterward is the replacement destination observed. An overlapping publication can therefore change that selection.

Once selected, each transfer has the same ordered effects:

- The active link publishes itself at offset `0x54`. The external value is then published as a word at working base plus payload operand, followed by the active link at working-base offset `0x14`.
- A word observation at external-value offset `0x44` supplies the byte published at working-base offset `0x0d`.
- Destination offset `0x0d` receives the active link’s low byte. A halfword publication at working base plus the signed operand then records the active link’s low sixteen bits.
- The carried word is observed at working-base offset `0x44`. The destination subsequently publishes itself at offset `0x54`.

Thus, carry capture occurs after the link, external-sample, and halfword publications. The carry need not equal any earlier payload or link.

Each transfer concludes by acquiring the next working base, publishing a separate evaluation of that next literal-backed value at active-link offset `0x44`, and publishing the carried word at next-working-base offset `0x14`. The selected destination then receives the transfer’s captured input sample at offset `0x11`, truncated to a byte.

There are exactly two represented word observations at first-input offset `0x64`. The first selected destination receives the first sample after the first transfer and the second sample during preparation for the second selection. The replacement destination receives the second sample after the second transfer. These are distinct publications even if both destination addresses coincide.

### Product-directed traversal

After the transition to the third working base, replacement-destination offset `0x44` supplies a multiplier word. A subsequent signed-halfword observation at replacement destination plus third working base supplies the factor.

Before traversal, a publication pair occurs twice: the factor is published as a word at factor offset `0x54`, followed by the replacement destination’s low byte at third-working-base offset `0x11`. Neither repetition is omitted by this contract.

The factor multiplied by the captured multiplier word forms the traversal’s starting address. Three dependent word observations follow offsets `0x44`, `0x74`, and `0x14`, respectively. Each observation after the first uses the preceding result as its address base. The final result is the endpoint.

Endpoint offset `0x14` supplies a saved address before that field is overwritten with the replacement destination shifted left once. The next lookup follows the saved address, not a fresh observation of the overwritten endpoint field.

A word at saved-address offset `0x14`, multiplied by the factor, supplies the initial product. Before observing initial-product offset `0x74`, the factor again publishes itself at offset `0x54`, followed by the saved address’s low byte at third-working-base offset `0x11`.

The resulting word is assigned to frame offset `0x108`, called the retained field. The expanded product is the initial product multiplied by the factor. Another factor self-publication precedes publication of the retained field’s low byte at third-working-base offset `0x11`.

These products are address-forming integer expressions. No evidence establishes them as sizes, array indices, or valid pointers.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes accessible memory and defined arithmetic through the relevant boundary.

1. **Signed address formation.** A halfword containing `0xfffe` supplies −2. A destination lookup uses −2 plus `0x14`, not 65,534 plus `0x14`, and does not silently add the context.

2. **Entry overlap.** If the successor-directed halfword publication overlaps successor offset `0x44`, the initial payload reflects the subsequent word observation under the applicable byte order. Using a pre-publication snapshot would violate the ordering.

3. **Two samples, three publications.** For input samples `0x123456ab` and `0x876543cd`, the first selected destination receives `0xab` and later `0xcd` at offset `0x11`. The replacement destination receives `0xcd` without a third sample.

4. **Selection after preparation.** If a second-transfer preparatory publication changes the word that supplies the replacement destination, the changed word determines selection.

5. **Literal evaluation distinction.** If a working-base acquisition and its associated literal evaluation differ, working-region accesses use the acquisition, while the link publication uses the separate evaluation.

6. **Saved traversal address.** Overwriting endpoint offset `0x14` does not redirect the next lookup. That lookup uses the address captured before the overwrite.

7. **Repeated effects.** Where the memory environment distinguishes repeated publications, both pre-traversal publication pairs must occur in order. Matching final bytes alone is insufficient.

8. **Late reread.** If intervening publications change expanded-product offset `0x44`, third-working-base offset `0x09` receives the earlier observation’s low byte, while expanded-product offset `0x11` receives the later observation’s low byte.

9. **Frame exposure timing.** F-unresolved-01 has no established guarantee that frame offset `0x100` is zero. Its explicit zero assignment occurs only after that callable returns.

10. **Conditional downstream work.** If F-unresolved-01 does not return, subsequent frame assignments and dependency calls are not reached. If it changes the later literal-backed argument and returns, F-cdec09f5d432 receives the subsequently evaluated value.
