# F-3959199a1859

## Purpose

When both fields are nonzero, it invokes F-ff12ffcda729 and returns that dependency’s 32-bit result. Otherwise, it invokes F-4fc89ec41a6d with a fixed five-argument tuple and, if that invocation returns normally, returns zero.

The established behavior is a gate and dispatch operation. The evidence does not establish the application-level meaning of the record, either gating field, or the delegated operation. In particular, a nonzero field is not evidence that an address is valid, a resource is available, or an object satisfies any stronger invariant.

## Behavior

### Ordered field inspection

The first observable record access is a 32-bit read at offset +4.

If this value is zero, the function takes the rejection path. It does not read the fields at offsets +8 or +12 before calling the rejection dependency.

If the first value is nonzero, the function next reads the 32-bit field at offset +8. A zero value there selects the rejection path. A nonzero value selects delegation.

Both gates are exact zero-versus-nonzero tests. No positive-only condition, range check, bit-mask requirement, or comparison between the fields is established. A 32-bit value with its high bit set still qualifies as nonzero. There is no visible arithmetic on either gating value.

The offset +8 field affects path selection only. It is not among the arguments explicitly supplied to the delegation dependency.

### Delegation path

After observing nonzero values at both offsets +4 and +8, the function reads the 32-bit field at offset +12. It then invokes F-ff12ffcda729 with these five arguments, in order:

1. The original first argument.
2. The original first argument again.
3. The value previously read at record offset +4.
4. The value read at record offset +12.
5. The original third argument.

The first two dependency arguments therefore have identical 32-bit values. This does not establish whether those values represent addresses, handles, flags, or another kind of data.

The offset +12 value is forwarded without a visible nonzero check or transformation. Zero is accepted by this wrapper on that field, although the dependency’s interpretation of zero is unknown.

If F-ff12ffcda729 returns normally, the function returns its result unchanged. A zero result is permitted on this path; the wrapper does not convert it into a rejection call or otherwise distinguish it from the zero returned on rejection.

No further record read, record write, or dependency invocation is visible after the delegation call.

### Rejection path

Rejection occurs if either:

- The offset +4 field is zero; or
- The offset +4 field is nonzero and the offset +8 field is zero.

The function invokes F-4fc89ec41a6d with the following ordered arguments:

2. 100
3. 107
4. 0
5. 0

If that invocation returns normally, the function returns the 32-bit value zero. Its return value does not depend on any value returned by F-4fc89ec41a6d.

The same tuple is used for both rejection conditions. The visible interface does not report which field caused rejection.
