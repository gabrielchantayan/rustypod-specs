## Behavior

### Dependency invocation phase

The first target is obtained by adding `0xFFE` to incoming link state. Its displayed arguments, in order, are:

1. The first explicit argument.
2. The second explicit argument shifted left by 14.
3. The third explicit argument.
4. The incoming unsigned machine-state word logically shifted right by 15.

An extended straight-line chain follows. Most subsequent targets are formed from embedded continuation-like values plus the same displacement. There is no displayed conditional branch or loop controlling this chain.

Call sites display between zero and four argument words. An invocation with no displayed arguments does not establish that its target consumes no implicit machine state. Several results are displayed as 64-bit quantities; others supply 32-bit words or secondary result state.

No dependency status checking, retry policy, or recovery branch is represented. Later operations are reached only if earlier dependencies permit execution to continue.

The chain includes shifts, masks, zero arguments, and forwarding of separately extracted lower and upper result words. Detailed call-by-call argument coverage beyond the rules stated here is **documented_only**; this document does not establish an exhaustive invocation trace.

### Arithmetic and widths

Words are displayed as 32 bits, double words as 64 bits, halfwords as 16 bits, and bytes as 8 bits. Separating a 64-bit result into lower and upper words does not establish memory byte order.

Unsigned extraction rules include:

| Selected bits | Result range |
|---|---:|
| Bits 8–23 of a word | 0–65,535 |
| Bits 11–17 of an upper result word | 0–127 |
| Bits 4–16 of a word | 0–8,191 |
| Bits 12–23 of a word | 0–4,095 |

Byte values used for addressing are zero-extended. Byte stores retain only the low eight bits of their source.

Signed left shifts occur before some later unsigned assignments or masks. A later unsigned operation does **not** retroactively make the preceding signed operation unsigned. Signed multiplication, addition, and address calculations likewise lack a general checked, saturating, or modular guarantee.

Where a **32-bit machine-word interpretation** is explicitly assumed, left shifts discard bits beyond bit 31. Successive shifts totaling at least 32 positions can therefore eliminate all original bits. This is conditional machine-word behavior, not a universal interpretation of the displayed signed expressions.

### Beginning of direct memory effects

The following descriptive labels identify values, not object types:

- **High-shift base:** a signed dependency result multiplied by `0x02000000`.
- **Packed base:** the low word of an earlier dependency result, interpreted as signed for a left shift by 25, then held as an unsigned word.
- **Compact index:** another signed dependency result shifted left by 8, then masked with unsigned `0x7FFF`, then logically shifted right by 6.
- **Compact base:** twice the compact index.
- **Terminal pair:** the lower and upper words of the last displayed 64-bit result before direct stores.

The compact calculation has an important interpretation boundary. Its left shift occurs on a signed value **before** the unsigned mask. Under an explicit 32-bit machine-word left-shift interpretation, the index is a multiple of four from 0 through 508, and the compact base is a multiple of eight from 0 through 1,016. These bounds are not unconditional for arbitrary signed inputs under ordinary signed-expression semantics.

The opening memory effects have this order:

- A word containing the packed base is stored at terminal-upper-word offset `0x14`; its destination is computed from that upper word. A byte containing the upper word’s low byte is then stored at packed-base offset `9`.
- The high-shift base is stored as a word at terminal-lower-word times 256 plus `0x54`. The byte at packed-base offset `9` is then overwritten with the packed base’s low byte.
- A zero word is stored at high-shift-base offset `0x14`, followed by a byte read at high-shift-base offset `5`.
- A zero word is stored at compact-base offset `0x14`. The previously read byte is zero-extended into a word store at high-shift-base offset `0x34`.
- The word at high-shift-base offset `0x14` is loaded. Another zero word is stored at compact-base offset `0x14`, followed by two byte stores of the loaded word’s low byte at compact-base offset `0x15`.

These accesses cannot be reduced to final assignments. Reads occur between stores, and computed destinations may overlap.

### Fixed-address input at `0x05`

After the preceding stores, the routine reads the byte at numerical address `0x05`. Its unsigned value becomes a computed base in the range 0–255.

This read precedes:

- A byte store of the compact base’s low byte to `0x01`.
- A byte store of the compact index’s low byte at the newly loaded base plus `0x15`.
- Further stores involving the high-shift base and a previously loaded word.
- A word read at the newly loaded base plus `0x54`, followed by a word overwrite of that same destination.

The value loaded by that word read is retained and drives later scaling and addressing.

The byte at `0x05` must be sampled at this point, not at entry. Earlier unknown calls and all preceding direct stores have already occurred. A preceding computed store that overlaps `0x05` can affect the selected base.

### Anchor input and repeated publication

For the later region, use these additional descriptive labels:

- **Adjusted value:** four times the retained word loaded through the `0x05`-derived base, minus `0x96`.
- **Publication base:** four times the adjusted value.
- **Anchor:** the word read at fixed address `0x087FBBBC`.
- **Payload base:** four times an indirectly loaded word.
- **Doubled base:** twice that same indirectly loaded word.

Arithmetic involving these labels retains the signed-overflow qualifications above.

The anchor read occurs **after** the four-write `0x20`/`0x2F` sequence and **before** the fixed word store of `0x20` to `0x60`. It is not an entry-state input. Prior calls and stores can affect it through aliasing.

Publication groups then perform, in order:

1. A word store to a scaled destination plus `0x54`.
2. A byte store of the publication base’s low byte at anchor offset `0x19`.
3. A byte store of the anchor’s low byte at publication-base offset `0x11`.
4. A scaled word store at anchor offset `0x34`.

The first group uses a scale derived from the earlier retained word. Subsequent groups use a scale derived from the adjusted value. The payload stored by the first operation is the payload base.

The anchor is retained throughout these groups; it is not reloaded before every group. The exact group count is **documented_only** in this contract. Repetition is established, but collapsing the groups is not authorized.

### Terminal fixed-storage sequence and reloads

After the repeated region, the word at `0xA9` is read and retained as the **saved global word**. A word at payload-base offset `0x74` is also saved. Both reads precede the byte write to `0x3A`.

The `0x3A` byte is derived from the adjusted value using multiplication by eight and addition of `0x30`, with final byte-width truncation subject to the displayed arithmetic’s interpretation. It is not established as formatted text.

Before modifying the relevant terminal fields, the routine saves words from doubled-base offset `0x14` and publication-base offset `4`. It then performs several byte publications, including `0x6C` at publication-base offset `8`, and stores the doubled base at its own offset `0x54`.

Only after those effects is the saved global word’s low byte written to `0x67`.

The subsequent accesses to `0x67` are distinct reads:

| Access interval | Required fixed-storage behavior |
|---|---|
| Initial retention | The full word from `0xA9` was saved before the write to `0x3A`. |
| Byte publication | The retained word’s low byte is written to `0x67`. |
| Fixed-address copy | After an intervening word read at doubled-base offset `0x44`, the current byte at `0x67` is read and copied to `0x21`. |
| First computed copy | After further computed stores and a word read, `0x67` is read again; that byte is stored at publication-base offset `9`. |
| Second computed copy | After additional stores and a word read at publication-base offset `0x54`, `0x67` is read again and copied to publication-base offset `9`. |

Between the fixed-address copy and the first computed copy, the routine writes at publication-base offset `0x10`, anchor offset `0x54`, and doubled-base offset `1`; overwrites anchor offset `0x54`; reads publication-base offset `0x40`; and writes at anchor offsets `0x74` and `0x44` and publication-base offset `0x10`.

Between the two computed copies, it writes a byte at doubled-base offset `9`, stores the **full saved global word** at publication-base offset `0x44`, and loads a word from publication-base offset `0x54`.

Consequently, the three reads of `0x67` can return different bytes through aliasing. Neither computed copy nor the copy to `0x21` may be replaced with unconditional reuse of the byte originally retained from `0xA9`.

The saved global word remains separately available for its full-width store even if `0x67` changes.

## Acceptance examples

These are conditional static-review examples, not executed tests.

1. **Initial arguments.** With second argument 1 and incoming unsigned machine-state word `0x00018000`, the first dependency receives `0x00004000` second and 3 fourth. Its first and third displayed arguments remain unchanged.

2. **Unsigned extraction.** For word `0xAB123456`, bits 8–23 yield `0x1234`; bits 12–23 yield `0x123`.

3. **Compact-index interpretation.** Under an explicit 32-bit machine-word left-shift interpretation, an all-bits-set result yields compact index 508 and compact base 1,016. This is **not** an unconditional signed-expression example: the signed negative input is shifted before the unsigned mask. A nonnegative result of 127 also yields 508 and 1,016 without requiring an overflowing signed left shift.

4. **Late fixed input.** If an earlier computed store changes `0x05` to 7 before its designated read, the subsequent computed base is 7, not the entry value of that byte.

5. **Anchor timing.** If a preceding store changes the word at `0x087FBBBC`, the anchor read observes that changed word. The read still precedes the word store to `0x60`.

6. **Terminal reload distinction.** Suppose the low byte saved from `0xA9` is `0x7B`. The routine publishes `0x7B` to `0x67`. If an intervening aliased store changes `0x67` before a later designated reload, that reload supplies the changed byte. Reusing `0x7B` would be incorrect.

7. **Retained full word.** A later change to `0x67` does not alter the already retained full word from `0xA9`; its subsequent word store uses the saved word.

8. **Failure and completion.** If the first dependency never returns, subsequent calls and direct stores are not reached. If the terminal transfer is reached, its first displayed argument is `0x72`; return to the original caller remains unresolved.
