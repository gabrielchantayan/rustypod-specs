# F-6c4b8933dc09

## Purpose

F-6c4b8933dc09 is a global-dependent dispatcher with a 32-bit result. Depending on the selected alternatives, it stages arguments, calls dependencies, performs address-relative memory accesses, writes through a caller-provided output pointer, and incorporates an internal address into arithmetic.

The established behavior is conditional. Unknown global values prevent reconstruction of a guaranteed sequence from entry to return. The evidence does not establish a conventional allocation–initialization–publication lifecycle, a success path, an error path, or termination.

One dependency receives the integer 36 and returns a value used as an address. Another receives seven arguments, including that working address and its offset-32 location. Separate alternatives read the offset-32 location, invoke an external dependency with the offset-4 address and integer 24, store a 32-bit field at offset 28, and publish the working address.

Allocation, construction, copying, and cleanup are possible interpretations, not established contracts. Neither 36 nor 24 establishes byte-count units or a valid memory extent.

### Argument staging and non-nullness

The staging alternative transfers the preserved third, second, and fourth arguments into the working source, opaque-argument, and output-pointer slots. It also introduces the first and fifth arguments into separate arithmetic values.

This is not comprehensive validation. The output-pointer test does not directly guard the publication store. A nonzero source value does not establish readability. Before staging, these tests can observe the initialized working values rather than the caller’s arguments.

### Dependency-return capture

2. Read a global multiplier and multiply it by the **then-current working arithmetic value**.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Immediate return.** If initial dispatch selects the return alternative, with no intervening operation, the returned result is zero.

2. **Capture before staging.** If the address-returning call executes while its multiplication operand still has its entry value of zero, the post-call unsigned product is zero. A nonzero fifth argument does not change this obligation.

3. **Capture after staging.** If staging assigns the fifth argument to that operand and nothing subsequently replaces or modifies it before multiplication, the post-call multiplier is applied to that argument value.

4. **Replaced operand.** If a preceding alternative has replaced the operand with 7 and the post-call multiplier is 3, the product is 21 under the represented unsigned 32-bit arithmetic. The fifth argument is irrelevant to that particular multiplication.

5. **Literal without extent.** If F-d33f6d597e5d executes, it receives 36. Acceptance must not additionally require allocation of 36 bytes or infer valid bounds from that literal.

6. **Zero return.** A zero dependency return selects the zero-specific transition expression. It does not require immediate failure return or a particular error code.

7. **Stable dispatch base.** If the transition-time and following dispatch-time bases agree, zero and nonzero dependency returns select alternatives 0 and 4 respectively, subject to the represented arithmetic. Without that agreement, those alternative numbers are not guaranteed.

8. **Post-call global change.** If F-d33f6d597e5d changes the multiplier and returns normally, multiplication uses a post-call observation, not the earlier dispatch snapshot.

9. **Publication order and overlap.** Given valid locations and normal external return, the external call precedes the field store, which precedes publication. If publication targets base + 28, its store can replace the field value.

10. **Separate trailing observations.** If both offset-32 alternatives execute and intervening activity changes the location, each dependency receives its own observed value.

11. **Internal address introduction.** The internal scalar receives 36 before its address enters arithmetic. This establishes no extent for the working address.

12. **Conditional preservation.** Returning without publication preserves the output only if no other executed write or dependency modifies overlapping storage. Likewise, absence of explicit result assignment requires a zero result only if the initialized result slot remains unmodified.

13. **Snapshot reuse.** If the byte store changes a snapshotted global, subsequent snapshot-based arithmetic uses the earlier value; a later dispatch observation may see the change.
