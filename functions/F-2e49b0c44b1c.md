# F-2e49b0c44b1c

## Purpose

F-2e49b0c44b1c repeatedly invokes unresolved dependencies, propagates 32-bit values through calculated memory addresses, performs byte-directed writes, and derives the next iteration’s input from a dependency result.

No application-level purpose is established. The address calculations do not establish allocation, collection management, parsing, device control, or a particular encoding.

This contract distinguishes three evidence levels:

- **Established static evidence:** represented calls, access widths, data dependencies, and operation ordering.
- **Conditional arithmetic consequences:** results that follow if integer and address calculations use wrapping 32-bit arithmetic.
- **documented_only:** behavior not established by the supplied representation, including dependency effects and execution prerequisites.

No runtime tests have been performed.

## Interface

### Explicit input and completion

The apparent interface accepts one 32-bit integer. Its first visible use calculates the address obtained by multiplying it by four and adding 20.

Neither a count interpretation nor an ordinary object-pointer contract is established. Participation in a scaled address expression establishes that calculation, not the input’s application-level meaning.

No return value or normal termination path is represented. If all calls return and all memory operations complete, the routine repeats indefinitely.

### Additional state

The apparent argument is not a complete description of entry requirements:

- An incoming retained 32-bit value supplies the first word written.
- Incoming link-related state supplies the basis of the first indirect call target.
- An additional result-register value is used as an argument late in the iteration; its producing contract is unavailable.
- A global 32-bit word is sampled during each iteration.

These values cannot be replaced with assumed zeroes.

The routine explicitly derives a retained word for the next iteration and obtains the next explicit input from the final dependency call. It assigns a fixed internal link basis **before that final invocation**, not afterward. Whether the final dependency preserves or changes relevant hidden state is unknown.

### Widths and address notation

The following descriptive terms are used throughout:

| Term | Meaning |
|---|---|
| Word | A 32-bit value or memory access |
| Byte | An 8-bit value or memory access |
| Pair | A represented 64-bit result, split into low and high 32-bit halves |
| Scaled value | Four times a value, or its equivalent two-bit left shift under wrapping arithmetic |
| Word slot | Address `4 × value + 20` |
| Wide slot | Address `16 × value + 20`; the access itself is still only 32 bits |
| Selector write through a base | Read an unsigned byte at `base + 1`, then write a byte at the resulting selector plus 17 |

A selector write is not a write relative to its original base. Its destination is between addresses 17 and 272 inclusive.

Every byte store retains only the low eight bits of the specified value. Pair extraction is logical high/low-half extraction; it does not establish a memory byte order.

Wrapping arithmetic, where discussed, means reduction modulo \(2^{32}\) after 32-bit operations. It is a conditional interpretation, not a claim that the represented signed expressions define portable arithmetic. No endianness, alignment policy, address-space validity, or ordinary-memory versus device-memory distinction is established.

## Behavior

The phases below describe one iteration in execution order. Names such as “first index” are descriptive labels for retained results, not claims about data structure roles.

A **five-call chain** consists of one F-U invocation with the stated explicit arguments, followed by four F-U invocations with no explicit arguments shown. Unless otherwise stated, its fifth result supplies the named word or pair. Each occurrence may address a different dependency. Omitted arguments do not establish the absence of hidden inputs.

### 1. Initial word propagation

The first memory operation writes the incoming retained word to the word slot of the iteration input.

A five-call chain beginning with the scaled iteration input produces the **first index**. Its scaled value is written to its wide slot.

A chain beginning with three copies of that scaled value produces the **second index**. The scaled first index is then written to the second index’s word slot.

A chain beginning with the scaled second index produces the **third index**. Its scaled value is written to its wide slot.

A chain beginning with three copies of the scaled third index produces the **fourth index**. The scaled third index is written to the fourth index’s word slot.

A chain beginning with the scaled fourth index produces the **first extraction value**.

The **primary byte base** is the third index multiplied by \(2^{30}\). Under wrapping arithmetic, only the third index’s lowest two bits affect this base.

### 2. Direct clears and sampled word

The routine writes a zero byte at the primary byte base plus 17, then a zero byte at the primary byte base plus 1.

Two individual F-U calls follow: the first receives the scaled first extraction value; the second has no explicit arguments and supplies a word. A five-call chain beginning with that word produces the **fifth index**.

The same direct clears occur again, in the same order: offset 17 before offset 1. These are distinct stores separated from the earlier clears by dependency calls.

A chain beginning with the scaled fifth index produces the **sixth index**. The fourth index shifted left by 31 bits is written to the sixth index’s wide slot.

The next explicit read obtains a word from the address formed by:

- Masking the first extraction value with `0x3fffffff`;
- Shifting the masked value logically right by 20 bits;
- Adding 20.

This **sampled word** comes from an address between 20 and 1043 inclusive. The address need not be word-aligned.

### 3. Retained result and retained selector

An F-U call receives the scaled sixth index. A subsequent no-explicit-argument call supplies the **retained result**.

A five-call chain beginning with the sampled word shifted logically right by 22 bits and then left by 28 bits produces the **seventh index**. A zero word is written to its word slot.

A chain beginning with the scaled seventh index produces the **second extraction value**. A fresh selector write through the primary byte base stores its scaled value’s low byte.

Two individual calls follow: one receives the scaled second extraction value, and one with no explicit arguments supplies a word. A chain beginning with that word and the second extraction value shifted left by 30 bits produces the **eighth index**.

The routine now reads and retains the unsigned selector byte at the primary byte base plus 1. At that selector plus 17, it stores the low byte of the second extraction value masked with `0x3fffffff` and shifted logically right by 20 bits.

A chain beginning with the scaled eighth index follows; its terminal result is not used by the visible dataflow. After this chain, the scaled retained result is written as a word at the **previously retained selector plus 20**. There is no fresh selector read for this word store.

The global 32-bit word is then read and retained as a snapshot.

### 4. First pair and additional word propagation

A chain beginning with the scaled sixth index produces the **first pair**. Define the **first scaled low half** as four times its low half.

A fresh selector write through the primary byte base stores the low byte of the global snapshot shifted logically right by 22 bits. Dependencies have executed since the global read, but this write uses the retained snapshot, not a new global read.

An F-U call receives the first pair’s high half. A no-explicit-argument call supplies a word. A chain beginning with that word and the first scaled low half shifted left by 28 bits produces the **ninth index**.

A fresh selector write through the primary byte base stores zero.

A chain beginning with the scaled ninth index produces the **tenth index**. Another chain, beginning with two copies of the scaled tenth index, produces the **eleventh index**.

The scaled eleventh index is written as a word at the first scaled low half multiplied by 4096, plus 20.

A chain beginning with the first scaled low half shifted left by 14 bits produces the **twelfth index**. The scaled eleventh index is written to that index’s word slot.

A chain beginning with the scaled twelfth index produces the **second pair**.

### 5. Changed selector bases and pair forwarding

Define the **second scaled low half** as four times the second pair’s low half.

A selector write through the first scaled low half multiplied by 16384 stores the low byte of the scaled eleventh index masked with `0x3fffffff` and shifted logically right by 20 bits.

The next seven individual invocations have this argument/result relationship:

1. F-U receives the second pair’s high half.
2. F-U has no explicit arguments and supplies a word.
3. F-U receives that word.
4. F-U has no explicit arguments and supplies a **forwarded pair**.
5. F-U receives the forwarded pair’s low half followed by its high half.
6. F-U has no explicit arguments.
7. F-U has no explicit arguments and supplies the **thirteenth index**.

A selector write through the second scaled low half multiplied by \(2^{28}\) stores zero. Under wrapping arithmetic, this selector base has only four possible values, because the scaled low half already has its lowest two bits clear.

A chain beginning with the scaled thirteenth index produces the **fourteenth index**.

A selector write through the second scaled low half multiplied by four stores zero.

### 6. Late payload propagation

An F-U invocation receives the second scaled low half shifted left by 10 bits. A no-explicit-argument invocation supplies a word.

A chain beginning with that word and the retained result shifted left by 28 bits produces the **fifteenth index**.

Another selector write through the second scaled low half multiplied by four stores zero. A chain beginning with the scaled fifteenth index follows; its terminal result is not retained.

Define the **late payload** as the fourteenth index shifted left by 14 bits. This payload is written as a word at the scaled fourteenth index multiplied by 4096, plus 20.

An F-U call receives the scaled fourteenth index shifted left by 14 bits. Another F-U call has no explicit arguments.

A five-call chain then begins with two explicit arguments:

- The late payload shifted left by 28 bits;
- The additional result-register value from the preceding call context.

Its terminal word is the **sixteenth index**. The additional result-register value is not established as equal to any ordinary return value described elsewhere.

Under wrapping arithmetic, the first argument is always zero: the late payload already has its lowest 14 bits clear. This arithmetic consequence does not eliminate the invocation or its second argument.

The late payload is written to the sixteenth index’s word slot. A chain beginning with the scaled sixteenth index produces the **seventeenth index**.

A selector write through the second scaled low half multiplied by four stores the low byte of the late payload masked with `0x3fffffff` and shifted logically right by 20 bits.

### 7. Iteration transition and link-basis assignment

Seven individual invocations follow:

1. F-U receives the fourteenth index shifted left by 26 bits.
2. F-U has no explicit arguments and supplies a word.
3. F-U receives that word and the scaled seventeenth index shifted left by 28 bits.
4. F-U has no explicit arguments and supplies a pair.
5. F-U receives that pair’s low half followed by its high half.
6. F-U has no explicit arguments.
7. F-U has no explicit arguments and supplies the **eighteenth index**.

A selector write through the second scaled low half multiplied by four stores zero.

A chain beginning with the scaled eighteenth index produces the **nineteenth index**. Its scaled value becomes the **next retained word**, which is written at the scaled seventeenth index multiplied by 4096, plus 20.

The final five-call sequence has an intervening state assignment:

- Its first invocation receives four arguments, in order: the scaled seventeenth index multiplied by 1024; that same value again; the seventeenth index shifted left by 14 bits; and the next retained word.
- Its second, third, and fourth invocations have no explicit arguments.
- **After the fourth invocation returns, the represented fixed internal link basis is assigned.**
- Its fifth invocation, with no explicit arguments shown, supplies the next iteration’s explicit input.

Execution then repeats without a represented condition or exit branch.

The assignment precedes the fifth invocation, not merely the next iteration. This establishes event order, but does not establish a calling-convention meaning or guarantee that the fifth dependency preserves hidden state.

## Side effects

### Memory and ordering

Every listed byte or word access is part of the represented behavior. Access ordering matters because no non-aliasing guarantees are supplied.

In particular:

- Word slots, wide slots, selector bytes, selector destinations, the global word, and dependency-accessed memory may overlap.
- A word write may change a later selector.
- A selector-directed byte write may affect a later word read.
- A dependency may alter storage between repeated clears or selector writes.
- A direct clear at a selector location does not establish the value returned by a later read after intervening dependencies.

Fresh selector writes require fresh byte reads. The retained selector in phase 3 is different: its subsequent word destination is based on the earlier byte value despite intervening calls.
