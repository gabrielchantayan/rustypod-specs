# F-c158f6e5f468

## Purpose

F-c158f6e5f468 performs a tag-dependent, partial update of caller-supplied output storage.

The supplied static representation establishes three paths:

- Tag `0x0100`: writes discriminator `1`, transfers selected scalar values, invokes several dependencies, and invokes a target obtained from a global function-pointer slot.
- Tag `0x0200`: writes discriminator `2`, transfers selected scalar values, invokes dependencies, constructs two signed extensions, and populates two eight-entry arrays.
- Any other stable tag: writes discriminator `0`, without invoking a dependency.

The apparent purpose is conversion between record layouts. That is **inferred intent**, not an established semantic interpretation of the fields.

This is not whole-record initialization. The body leaves gaps between its explicit output writes. Dependencies may also modify previously written fields, input storage, context storage, the global target slot, or other state. Consequently, the explicit stores described below are not unconditional guarantees about the record at return.

## Behavior

### Dispatch and observation timing

The first decision reads the 16-bit input tag and compares it with `0x0100`. If that comparison fails, the representation shows another tag read for comparison with `0x0200`.

For stable ordinary memory, this selects the three paths described above. For changing memory, the second decision uses its own observation; the representation does not establish an atomic tag snapshot or a supported concurrent-access protocol.

If neither comparison succeeds, the body writes the 16-bit value `0` at output offset `0` and returns. It performs no other explicit write or dependency invocation on that path.

All recognized-path operations below are incremental. Later reads are not entry-time snapshots. Earlier output writes or dependency effects may change what later reads observe when storage overlaps or shared state is mutable.

### Shared state and aliasing

The body explicitly reads the global function-pointer slot on `0x0100`. It contains no explicit assignment to that slot, input storage, or context storage. None of those facts establishes preservation by dependencies.

There is no checked non-overlap requirement. Output writes precede later input and context reads, so overlapping storage can affect subsequent values. Earlier dependencies may likewise affect later reads or overwrite earlier output fields.

### Failure and partial completion

The discriminator is written before dependency processing on each recognized path. A later failure or nonlocal exit can leave a partially updated record.

The representation provides no explicit status result, dependency-status check, rollback, fault handler, or exception handler. A discriminator store of `1` or `2` is not proof of completed processing, nor a guarantee that the discriminator still has that value at return.

An invalid global target, invalid storage, or dependency failure has no established recovery behavior.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, they specify **values written at particular steps**, not guaranteed return-state values.

### Unrecognized tag

If both tag observations fail their respective comparisons, the body stores 16-bit zero at output offset `0` and invokes no dependency.

With ordinary valid storage and no external mutation, that zero remains at return and other output bytes remain unchanged.

### Unsigned widening on `0x0100`

If the read at input offset `4` observes `0xFFFF`, the corresponding store at output offset `4` writes `0x0000FFFF`, not `0xFFFFFFFF`.

The earlier discriminator step writes `1`. To conclude that the returned discriminator is `1`, all subsequent dependencies—including the final indirect target—and any external activity must preserve those discriminator bytes. Preserving input offset `4` alone is insufficient.

### Late global target selection

Suppose the global slot initially selects one target, but an earlier dependency changes it to another before the late slot read. If no intervening effect changes it again, the final invocation uses the later target.

Caching the entry-time target would not reproduce this access pattern. This criterion concerns target selection, not the unknown effects of either target.

### Single-byte widening on `0x0200`

If the read of input byte `2` observes `0xFE`, the corresponding 16-bit store at output offset `2` writes `0x00FE`.

An entry-time value supports this prediction only if preceding effects, including the discriminator store through potentially overlapping output storage, leave that input byte unchanged. Later dependencies must preserve output bytes `2–3` for the value to remain at return.

### Signed extensions

If the F-4055be9c3f18 invocation using input offset `26` returns `0x80000000`, the body stores `0x80000000` at output offset `88`, followed by `0xFFFFFFFF` at offset `92`.

A result of `0x7FFFFFFF` instead produces a zero sign word. A signed value of `-1` observed by the direct read at input offset `36` produces all-one words at output offsets `168` and `172`.

Later dependencies may overwrite these fields; unchanged return-state values require their preservation.

### Array reads and clearing

If the successive reads for first-array entry `2` observe `0xFFFF` and `0x8000`, the corresponding stores at output offsets `120` and `124` write `0x0000FFFF` and `0x00008000`.

Predictions from entry-time input require that earlier dependencies and output writes do not alter the relevant input bytes. Nonoverlapping input and output storage, together with dependency preservation of those input bytes, is sufficient.

Every field in entries `3–7` of both arrays receives a 32-bit zero. With valid ordinary output storage and no external mutation, these zero stores remain at return: there are no later dependency calls or overlapping explicit output stores to those fields.

### Fresh context observations and untouched bytes

If the two context reads observe distinct values, the respective F-d7be9cfb4000 invocations receive those distinct values. Reusing the first observation for both calls does not satisfy the represented behavior.

On `0x0200`, output bytes `4–7` retain their entry contents only if dependencies and external activity leave them unchanged. The body itself performs no store to those bytes.
