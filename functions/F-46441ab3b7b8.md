# F-46441ab3b7b8

## Purpose

F-46441ab3b7b8 computes two 32-bit coordinates from an object, indirectly resolved metrics, and an origin-selection argument. An object flag gates calls that consume those coordinates and an interior object address. When that gate is enabled, an independent input flag selects an additional operation at a vertical coordinate increased by two, surrounded by a dependency-provided state-token sequence.

Metric resolution and coordinate computation occur even when the object flag disables all subsequent output calls. The result is a 64-bit concatenation of two mutable local argument words, not either computed coordinate or an explicit success indicator.

**Inferred intent:** the metric arithmetic resembles vertical centering; the optional operation resembles an underline. These interpretations do not establish the dependencies’ domain semantics.

## Interface

### Arguments

The supplied representation uses 32-bit addresses and argument words.

| Argument | Width | Established role |
|---|---:|---|
| Object address | 32 bits | Identifies the original object used for structural reads and an interior-address argument. |
| Context word | 32 bits | Forwarded unchanged from the original argument to dependencies. |
| Metric/option word | 32 bits | Copied into writable local storage for the first metric resolution. Bit 2 of the original argument controls the optional operation. |
| Origin-selection word | 32 bits | Zero enables an additional vertical-origin contribution; every nonzero value omits it. |

The function initializes mutable local copies of all four arguments. The supplied layout places these in consecutive four-byte slots in argument order.

Original arguments and local copies have distinct roles. Structural object accesses use the original object address. Dependency calls use the original context argument. The optional-operation test uses bit 2 of the original metric/option argument, and origin selection uses the original fourth argument. Mutations to the corresponding local copies do not replace those original values.

- Low 32 bits: final contents of the local word initialized from the object address.

The first of these words is directly exposed to F-78beca4e4455 through a writable address. The adjacent context-copy word is not established to remain unchanged by that dependency.

## Behavior

All coordinate arithmetic below is expressed as 32-bit bit-vector arithmetic: additions, subtraction, and multiplication retain the low 32 bits. The aggregate metric has an additional signed 16-bit narrowing step.

### 1. Initialize local argument storage and resolve the first metric

After initializing the four local argument copies, the function calls F-78beca4e4455 with the address of the local metric/option word.

It then reads that word and clears bit 0.

- If the normalized address is zero, the first metric contribution, \(A\), is zero.
- Otherwise, it reads the signed 16-bit field at normalized address plus 82 and sign-extends it to obtain \(A\).

Thus, resolution words zero and one both avoid metric dereferencing. A tagged nonzero address and the corresponding address with bit 0 clear select the same storage.

### 2. Save a descriptor value and resolve the second metric

Using the original object address, the function reads its secondary-record pointer, follows that record’s descriptor pointer, and reads the descriptor’s 32-bit field at offset 200. Call this saved value \(D\).

This read occurs after the first resolution call and before the second resolution call. Subsequent changes to the descriptor field do not replace the saved value.

The function then calls F-78beca4e4455 with:

- The address of the local word initialized from the object address.
- The original context argument.

It reads the resulting first local word and clears bit 0.

- If the normalized address is zero, the aggregate metric, \(T\), is zero.
- Otherwise, it reads the signed 16-bit fields at offsets 82, 84, and 86.

For nonzero normalized storage, \(T\) is the signed 16-bit interpretation of the sum of those three components modulo \(2^{16}\). It is not an unrestricted 32-bit sum. The signed interpretation of that narrowed result is used in the vertical calculation.

The supplied representation shows different argument counts at the two calls to F-78beca4e4455. A complete callable interface cannot be established from these call sites alone.

### 3. Select the vertical-origin contribution and compute a partial vertical coordinate

The original origin-selection argument determines whether an additional descriptor read occurs.

- If it is zero, the function follows the original object’s current secondary-record and descriptor pointers and reads descriptor offset 204. That value becomes the extra vertical-origin contribution.
- If it is nonzero, that conditional pointer traversal and descriptor-field read are omitted, and the extra contribution is zero.

This conditional read occurs after the second metric resolution and before the partial vertical arithmetic.

Let \(O\) denote the selected extra contribution. The partial vertical coordinate is:

\[
Y_{\mathrm{partial}}
=
A+\left(\operatorname{u32}(D-T)\mathbin{\gg}1\right)+O
\pmod{2^{32}}.
\]

The shift is a logical right shift of the unsigned 32-bit subtraction result. It is not signed division by two. A subtraction whose signed interpretation is negative can therefore yield a large positive shifted value.

The final secondary-record vertical adjustment has **not yet been read** at this point.

### 4. Capture one secondary-record pointer, compute horizontal position, then finish vertical position

After the conditional origin contribution and partial vertical calculation, the function reads the secondary-record pointer from the original object once for this stage. That captured pointer is shared by the following horizontal calculation and the subsequent vertical-adjustment read.

First, it evaluates the horizontal-coordinate expression using:

- The unsigned byte at original-object offset 19.
- Descriptor offset 196, reached through the captured secondary record.
- Descriptor offset 204, also reached through the captured secondary record.
- Offset 36 of the captured secondary record.

The resulting coordinate is:

\[
X=
(\text{unsigned object byte at 19}\times\text{descriptor field at 196})
+\text{descriptor field at 204}
+\text{captured secondary-record field at 36}
\pmod{2^{32}}.
\]

The multiplier ranges from 0 through 255; it is not sign-extended.

**Only after evaluating this horizontal expression**, the function reads offset 40 from that **same captured secondary record** and computes:

\[
Y=Y_{\mathrm{partial}}+\text{captured secondary-record field at 40}
\pmod{2^{32}}.
\]

There is no fresh object-to-secondary-record lookup between the horizontal calculation and this vertical-adjustment read.

The ordering among independent operand reads inside the horizontal expression is not established. That uncertainty does not extend across the separate statements: the horizontal expression precedes the offset-40 read. Sharing the secondary-record pointer also does not establish that all descriptor-field operands come from one separately captured descriptor-pointer snapshot.

### 5. Apply the object output gate

After both coordinates are complete, the function reads the unsigned 16-bit field at original-object offset 20 and tests bit 0.

If that bit is clear, no calls occur to:

- F-e5e685741bac
- F-9a8e33ae595c
- F-da61fe335489
- F-33ca0546dba1
- F-02e7aa681484

The two metric-resolution calls and all preceding coordinate-related reads still occur. Disabled output is not an early return that avoids object or metric access.

If the bit is set, the function calls, in order:

1. F-e5e685741bac with the original context word, \(X\), and \(Y\).
2. F-9a8e33ae595c with the original context word, the interior address at original-object offset 16, and the 32-bit constant one.

Neither return value is visibly inspected.

### 6. Perform the optional operation

This stage requires both an enabled object output gate and bit 2 set in the original metric/option argument. The resolved contents of the local metric/option word do not control this test.

The ordered interactions are:

1. Call F-da61fe335489 with the original context word and retain its 32-bit result.
2. Call F-33ca0546dba1 with the original context word and zero.
3. Call F-e5e685741bac with the original context word, \(X\), and \(Y+2\).
4. Follow the original object’s current secondary-record and descriptor pointers and read descriptor offset 196.
5. Call F-02e7aa681484 with the original context word, the freshly read descriptor value plus \(X-1\), and \(Y+2\).
6. Call F-33ca0546dba1 with the original context word and the retained result from step 1.

Coordinate arithmetic wraps to 32 bits. The descriptor field used for the endpoint is freshly read after the earlier output calls; it need not match the field used to calculate \(X\).

The final call passes back a saved token. It does not establish restoration of the entire context, unrelated globals, or every dependency-visible state change.

### 7. Construct the result

The function combines the final first and second local argument words into the low and high halves of its 64-bit result. Coordinates are not returned through this construction.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. Unless an example specifies otherwise, assume valid storage, no relevant dependency mutations, and normal return from every dependency.

1. **Output disabled does not suppress computation.**  
   With bit 0 clear at object offset 20, both metric-resolution calls and coordinate-related reads occur. No output or token-sequence calls occur, even if original option bit 2 is set.

2. **Tagged null metrics.**  
   If both resolutions leave their target words equal to one, both normalized addresses are zero. No metric fields are read, and \(A=T=0\).

3. **Ordinary coordinates with an extra origin.**  
   Let \(A=3\), \(D=30\), and the second metric components be 4, 6, and 2. Let descriptor offset 204 be 10, the horizontal multiplier be 2, descriptor offset 196 be 8, secondary-record offset 36 be 7, and offset 40 be 5. With origin selection zero:
   - \(T=12\).
   - \(Y_{\mathrm{partial}}=3+9+10=22\).
   - The horizontal expression produces \(X=2\times8+10+7=33\).
   - The subsequent offset-40 read produces \(Y=22+5=27\).

   With output enabled, the first F-e5e685741bac call receives \((33,27)\).

4. **Nonzero origin selection.**  
   With the same values but a nonzero origin-selection argument, the conditional vertical-origin read is omitted. The horizontal expression still reads descriptor offset 204. The coordinates are \((33,17)\).

5. **Shared record and statement ordering.**  
   If the secondary-record pointer captured for the horizontal stage identifies record R, the horizontal adjustment comes from R at offset 36. After the horizontal expression completes, the vertical adjustment comes from R at offset 40, without re-reading the object’s secondary-record pointer. A trace placing that offset-40 read before the horizontal expression would not match this contract.

6. **Logical shift of a negative difference.**  
   With \(D=10\), \(T=12\), \(A=0\), nonzero origin selection, and zero final vertical adjustment, \(Y\) has bit pattern `0x7fffffff`, not the bit pattern for negative one.

7. **Signed aggregate narrowing.**  
   Components 30000, 10000, and zero produce \(T=-25536\), not 40000. The vertical subtraction uses that signed value.

8. **Optional endpoint and token sequence.**  
   For \(X=33\), \(Y=27\), and a fresh endpoint extent of 8, the optional positioning coordinates are \((33,29)\), and the endpoint coordinates are \((40,29)\). Token acquisition precedes passing zero; passing back the saved token follows the endpoint call.

9. **Local mutations determine the result.**  
   If the final first and second local words are `0x11223344` and `0xaabbccdd`, the exposed result is `0xaabbccdd11223344`, regardless of their initial argument values.
