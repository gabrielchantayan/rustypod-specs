# F-261627257752

## Purpose

F-261627257752 searches an ordered sequence of fixed-stride records and returns the index of the first record whose unsigned threshold is at least the supplied query, provided that record also has a nonzero eligibility word.

The function does **not** search for the first record satisfying both conditions independently. Once a threshold qualifies, that record determines the result: a zero eligibility word produces failure immediately, even if a later record would be eligible.

The established return value for all unsuccessful paths is −1. The function does not distinguish a disabled object, a negative dependency result, an empty sequence, no qualifying threshold, or an ineligible first qualifying record.

An interpretation as a boundary lookup is plausible, but the supplied evidence does not establish the application meaning of the query, thresholds, or eligibility word.

## Interface

The function accepts two inputs:

1. **Object address.** An address-like value identifying storage containing a gate word and a record-table reference.
2. **Query.** An unsigned 32-bit value used in threshold comparisons.

The source represents the object address and stored table reference through integer-typed values rather than providing a complete pointer or object declaration. Their intended use as addresses is evident from the accesses. A complete platform ABI, address-space model, alignment contract, and byte order are not supplied.

These widths describe the supplied representation; they do not establish portability to a different ABI.

### Record layout

| Byte offset within record | Representation | Use |
|---|---|---|
| +0 | Signed 32-bit word | Eligibility word; zero rejects the selected record |
| +4 through +11 | Unspecified | Not directly read by this function |
| +12 | Unsigned 32-bit word | Threshold compared against the query |

The eligibility word is tested only for equality to zero. Negative values are therefore eligible just as positive values are.

### Output

The result is a signed 32-bit value:

- A nonnegative, zero-based record index on success.
- −1 on every ordinary unsuccessful path.

The function returns neither a record address nor the eligibility word.

## Behavior

### Initial gate

The first direct access is the signed word at object offset +4.

If that word is zero, the function returns −1. On this path:

- F-d25a91b7600a is not called.
- The table reference is not directly read.
- No record is inspected.

Every nonzero gate value passes this check, including negative values. The gate is not treated as a positive record count.

### Dependency call and search bound

When the gate is nonzero, the function calls F-d25a91b7600a once, passing the object address.

Its result is interpreted as a signed 32-bit value:

- A negative result produces −1 without direct record inspection.
- Zero produces −1 without direct record inspection.
- A positive result supplies the exclusive upper bound for record indices.

The dependency result is retained as the search bound. The function does not repeatedly call the dependency or directly refresh this bound from object storage.

The initial gate is not checked again after the dependency returns. If the dependency changes the gate, that change does not itself cancel the search.

### Ordered threshold search

For a positive bound, records are considered in ascending index order, beginning with index zero and stopping before the bound.

At each reached index, the function obtains the table reference from object offset +8 and reads the unsigned threshold at the corresponding record’s offset +12.

The comparison is:

- A threshold smaller than the query does not qualify.
- A threshold equal to or larger than the query qualifies.

Both operands of this comparison are unsigned 32-bit values. Values with the high bit set are not interpreted as negative thresholds.

If a record does not qualify, its eligibility word is not directly inspected. Processing advances to the next index.

### First qualifying record

At the first qualifying threshold, the function obtains the table reference again from object offset +8 and reads the eligibility word at offset +0 of that indexed record.

It then terminates:

- If the eligibility word is zero, the result is −1.
- If the eligibility word is nonzero, the result is the current index.

No later record is inspected after a qualifying threshold is found, regardless of whether the selected eligibility word is zero.

The threshold and eligibility accesses are separate source-level accesses, each deriving its address from the object’s table-reference field. The function does not explicitly capture one table reference for the entire search or for both accesses.

### Exhaustion

If all considered thresholds are smaller than the query, the function returns −1.

The function does not require or verify sorted thresholds. For an unsorted sequence, its established behavior remains an ascending-index search for the first threshold meeting the comparison. It does not select the numerically smallest qualifying threshold.

### Arithmetic boundaries

The record address uses an index multiplied by 16, followed by the relevant field offset and table-base arithmetic.

The search counter itself does not need to advance beyond the positive signed bound: even for the largest positive bound, the final increment reaches that bound and the search ends. Record-address arithmetic is a separate concern and may exceed its representable range much earlier.

No wraparound addressing, large-count rejection, or bounds validation is established. Callers must not infer that every positive signed bound is safe merely because it fits the dependency’s return type.
