# F-30f81250a63b

## Purpose

F-30f81250a63b exposes a machine-state-dependent control-flow fragment rather than an established application-level operation. Its initial path depends on an incoming overflow condition:

- With overflow clear, it reads one byte and invokes an indirectly selected target.
- With overflow set, it requests two software interrupts, performs arithmetic, reads a base value from global storage, reads a byte relative to that base, and writes a 32-bit value.

No ordinary return is visible. The represented continuations lead to invalid-instruction boundaries or an empty, non-progressing loop.

This contract describes the supplied static representation. It does not assign an unsupported purpose such as decoding, dispatch, validation, or recovery. Invalid instruction data and truncated control flow limit what can be established about executable behavior beyond the visible operations.

## Behavior

### Entry selection

The incoming overflow condition is tested before the two visible paths diverge. No visible calculation derives that condition from the explicit arguments.

Consequently, identical explicit argument words can select different behavior when implicit entry state differs.

### Overflow-clear path

Let \(q\) be the unsigned fourth argument logically shifted right by two:

\[
q=\left\lfloor\frac{\text{fourth argument}}{4}\right\rfloor,
\qquad
0\le q\le \texttt{0x3fffffff}.
\]

The fragment reads one byte from numeric address \(q+1\). The address is not represented as an offset from a caller-provided buffer.

The possible addresses are `0x00000001` through `0x40000000`, inclusive. Forming \(q+1\) does not overflow a 32-bit unsigned word.

After the byte has been obtained, the fragment invokes the target selected by adding `0x82` to the incoming saved control address. The argument order is:

1. The byte read from \(q+1\).
2. The second explicit argument.
3. \(q\).
4. \(q\), repeated.

The byte read precedes entry into the target. Its failure can prevent the call. The evidence does not establish a callable prototype, the byte’s widening convention at the call boundary, or the instruction-set interpretation and address-boundary behavior of the computed target.

No target return value is visibly consumed. If the target returns to the displayed continuation, execution reaches an invalid-instruction boundary rather than an ordinary return. If it does not return, no subsequent local behavior is established.

### Overflow-set path: interrupt continuations

The first visible request is software interrupt `0xb6`. The second is software interrupt `0xd2`.

The second request is reachable only if the first resumes at the displayed continuation. Arithmetic and memory accesses following the second request are reachable only if that service also resumes at its displayed continuation.

Neither service has a supplied preservation contract. Registers, global storage, mappings, and ownership state must not be assumed unchanged. References below to values consumed after the interrupts identify continuation-time values, not guaranteed entry-state values.

### Arithmetic after the interrupts

Using the unsigned fourth-argument value consumed by the displayed arithmetic, define \(q\) as its logical right shift by two. The fragment forms \(q+7\), whose range is:

\[
7\le q+7\le \texttt{0x40000006}.
\]

This addition cannot overflow a 32-bit unsigned word.

A separate predicate tests signed 32-bit addition overflow for:

- The auxiliary 32-bit word logically shifted right by eleven bits.
- The positive constant `0xc6`, equal to 198.

The shifted operand is at most `0x001fffff`. Its sum with 198 is at most `0x002000c5`, below the maximum signed 32-bit positive value. Under the represented widths and logical-shift semantics, the overflow predicate is therefore always false, regardless of the auxiliary word’s value at this continuation.

The representation includes a branch that, if this predicate were true, would replace the arithmetic value with zero, select a stack-relative store base, and replace the remembered byte with zero. That branch is unreachable under the established operand bounds. It is not an input-selectable mode.

### Global-base read and dependent byte read

After the two interrupt continuations and the displayed arithmetic, the fragment obtains a base value by reading global storage. It then reads one byte at displacement `0x18` from that obtained base.

These are distinct accesses:

1. Read the global-held base value.
2. Read the byte addressed using that value plus `0x18`.

Both occur after the interrupt continuations and before the 32-bit store. The global read is not an entry-time snapshot. If an interrupt changes the global-held base, the later access uses the value obtained from global storage at that later read.

Failure to obtain the global-held base can prevent both the dependent byte read and the store. Failure of the dependent byte read can likewise prevent the store.

The evidence does not establish the storage width of the global-held base, its validity, or any relationship between that base and the explicit arguments. The dependent access itself is one byte wide.

### Store

On the arithmetically reachable path, the fragment stores the 32-bit unsigned value

\[
w=\left\lfloor\frac{q+7}{2^{23}}\right\rfloor.
\]

Its range is zero through 128, inclusive.

The destination is formed using displacement `0x180` from the machine-state base consumed at the store continuation. It is not contractually the incoming base: both software interrupts precede its use, and their preservation behavior is unknown.

The represented destination calculation includes a 32-bit integer treatment of the base. The supplied evidence does not establish a portable address-overflow rule, destination validity, alignment, or byte order. No bounds or permission check is visible before the store.

The global-base read and dependent byte read precede this write even when the byte’s value will not affect the subsequent outcome.

### Behavior after the store

If \(w=0\), execution enters an empty loop controlled by the previously calculated overflow predicate. Since that predicate is false under the represented arithmetic, the loop does not make visible progress or exit.

If \(w\ne0\), the remembered byte is tested for zero. Both outcomes reach an invalid-instruction boundary. The test therefore establishes no successful exit. Byte signedness does not affect this zero-versus-nonzero distinction.

The exact store boundary is:

| Fourth-argument value consumed by the arithmetic | Stored value | Subsequent represented behavior |
|---|---:|---|
| `0x00000000`–`0x01ffffe3` | 0 | Empty loop without visible progress |
| `0x01ffffe4`–`0xffffffff` | 1–128 | Invalid-instruction boundary after the byte test |

## Side effects

### Observable ordering

On the overflow-clear path, the local ordering is:

1. Read one byte from \(q+1\).
2. Invoke the indirect target.
3. If the target returns to the displayed continuation, reach an invalid-instruction boundary.

On the overflow-set path, assuming both services resume, the local ordering is:

1. Request interrupt `0xb6` and resume.
2. Request interrupt `0xd2` and resume.
3. Perform the displayed arithmetic.
4. Read the base value from global storage.
5. Read one byte at displacement `0x18` from that obtained base.
6. Write the 32-bit result at displacement `0x180` from the store-continuation base.
7. Enter the empty loop or proceed through the byte test to an invalid-instruction boundary.

This is ordering in the supplied representation, not a guarantee about memory barriers, inter-thread visibility, or device ordering. The external target and interrupt services may perform additional accesses and state changes.

### Changed continuation-time bases

If the interrupt services resume but change the global-held base, the dependent byte read uses the value subsequently obtained from global storage, not its entry-state value.

If they change the machine-state store base, the destination uses the base consumed at the store continuation. A specification requiring the entry-state destination would need an additional preservation premise.

### Failed global-base read

If both interrupts resume but obtaining the global-held base fails, the fragment does not establish that either the dependent byte read or the store occurs.

### Non-resuming first interrupt
