# F-4eb49855b877

## Purpose

F-4eb49855b877 exposes a short, partially recovered sequence of state-changing operations: it assigns zero to one global destination, assigns the third explicit input to another global destination, and attempts a 16-bit write to an address derived from an incoming 32-bit register value.

The supplied evidence does not establish a higher-level purpose. In particular, it does not justify interpreting these operations as device initialization, exception handling, a reset procedure, or a valid callable service. Such interpretations would require surrounding instructions, global declarations, and an execution-environment description.

The recovered sequence ends at an instruction that the analysis could not represent as valid control flow. Consequently, this contract describes the visible prefix and its limits. It does not promise normal completion or specify behavior beyond that boundary.

No runtime tests have been performed.

## Behavior

This is the order represented by the supplied evidence. It is not independently verified machine-level ordering, a guarantee of cross-processor visibility, or a memory-barrier contract.

### Derived address and stored value

R is treated as unsigned and shifted right by 22 bits. The resulting value is multiplied by 256 to form the derived address.

The arithmetic has these established bounds:

| Quantity | Range or property |
|---|---|
| R | 0 through 4,294,967,295 |
| R shifted right by 22 | 0 through 1,023 |
| Derived address | 0 through 261,888, inclusive |
| Derived address in hexadecimal | 0x00000000 through 0x0003FF00 |
| Address spacing | 256 bytes |
| Stored bit pattern | Low 16 bits of R |

The address multiplication cannot overflow a 32-bit unsigned value: its maximum result is 0x0003FF00. Every selected address is divisible by 256 and therefore satisfies ordinary two-byte alignment.

The write is represented as a short-width store. Under the recovered type interpretation, it writes 16 bits. A signed interpretation of that short value does not change the low-16-bit pattern being stored. Byte order is not provided, so this contract does not specify which byte occupies the lower address.

Address selection depends only on R’s upper ten bits. The stored bit pattern depends only on its lower sixteen bits. Bits 16 through 21 affect neither. Thus, distinct values of R can select the same address and write the same value.

R values below 0x00400000 select address zero. The recovered prefix contains no check that excludes this address.
