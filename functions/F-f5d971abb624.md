# F-f5d971abb624

## Purpose

F-f5d971abb624 updates a caller-supplied descriptor, selects two values from shared data, invokes an external operation, and writes two output regions.

The established behavior is:

- Clear one descriptor field before checking whether resolution is enabled.
- Optionally replace that field with a direct value or an indexed-resolution result.
- Select two shared-data elements using a descriptor selector, shared comparison expressions, and an option argument.
- Store the resulting four-byte values in the descriptor.
- Pass local storage and the descriptor to an external dependency.
- Publish two local values, the enable argument’s low byte, and two freshly read descriptor fields.

One indexed-resolution outcome returns before selection or output publication. Bound rejection and rejection by an indexed entry’s low bit do not cause that return.

“Descriptor,” “resolution,” and “selection” are explanatory labels, not recovered domain meanings. The declarations of both shared selection objects are absent. Their types, access widths, and some comparison and addressing semantics therefore remain unresolved.

## Behavior

### Initial clear and resolution gating

The first direct memory effect is a four-byte zero write to descriptor +24.

If enable is zero, resolution is skipped and selection follows.

Otherwise, the unsigned 32-bit index at descriptor +12 is read:

- **Index zero:** read the signed four-byte value at descriptor +8 and store it at descriptor +24. No context lookup is needed.
- **Index nonzero:** compare it with the unsigned bound at context +2768. An index greater than or equal to the bound skips resolution assignment and continues to selection.

Bound rejection short-circuits the remaining eligibility check. It does not require reading the stored lookup base or the indexed entry.

For a nonzero index below the bound, the function reads the stored base at context +2760 and a calculated four-byte lookup entry. The entry is eligible exactly when its least significant bit is clear.

An entry with its low bit set skips resolution assignment and continues to selection. Other entry bits do not affect eligibility.

### Lookup arithmetic

The index is unsigned 32-bit. Multiplication by four is unsigned 32-bit arithmetic. Addition of that result to the stored signed 32-bit base is also unsigned 32-bit arithmetic under the supplied operand representations.

Thus the lookup address integer is:

- Formed using a scaled index reduced modulo \(2^{32}\).
- Reduced modulo \(2^{32}\) again by the base addition.

This establishes integer arithmetic, not accessibility or the environment’s interpretation of the resulting integer as an address.

Other address-forming expressions do not acquire this wraparound guarantee merely because this lookup calculation has it. Signed address arithmetic outside its representable range remains unresolved.

### Eligible indexed resolution

An eligible entry causes a call to F-a01d4dfb5f88 with the address context +2760. The index is not separately passed.

The returned address is read for a signed four-byte value:

- If the first value read is zero, the function returns immediately.
- Otherwise, the returned address is read again, and descriptor +8 is read after the dependency call. Their signed 32-bit sum is stored at descriptor +24.

The second returned-address read is distinct from the zero-test read. It may produce a different value, including zero. The addend is also a post-call read rather than a preserved pre-call value.

The relative evaluation order of the two reads supplying the addition is not established. No widening, saturation, overflow check, or overflow-specific branch is shown. Behavior for a mathematical sum outside the signed 32-bit range is **documented_only**, not guaranteed modular arithmetic.

On early return, selection, the later external operation, and all direct output writes are skipped. The initial clear has occurred, but descriptor +24 need not remain zero because F-a01d4dfb5f88 has no supplied preservation contract.

### Selection predicates and precedence

On paths continuing past resolution, the signed selector at descriptor +4 is sampled once.

Selection uses these predicates:

1. Evaluate the shared comparison operand and compare it for equality with the sampled selector, using the actual operand types and conversions.
2. If equal, select indices 8 and 9. No second comparison-operand evaluation is required.
3. Otherwise, evaluate the shared comparison operand again and test whether that operand compares less than the selector, again using the actual types and conversions.

The index pairs are then:

| Predicate outcome | Additional selector condition | Indices |
|---|---|---|
| First equality true | None | 8, 9 |
| Equality false; second comparison true | Selector is 0x1406 | 12, 13 |
| Equality false; second comparison true | Selector is 0x140C | 10, 11 |
| Equality false; second comparison true | Any other selector | 0, 1 |
| Equality false; second comparison false | Selector is 0x1400 | 2, 3 |
| Equality false; second comparison false | Selector is 0x1401; option zero | 6, 7 |
| Equality false; second comparison false | Selector is 0x1401; option nonzero | 4, 5 |
| Equality false; second comparison false | Any other selector | 0, 1 |

This table does not require an assumption about the missing comparison declaration.

In particular, the second predicate must not unconditionally be described as signed ordering. A false second predicate also must not unconditionally be described as “selector less than comparison.” Besides possible changes between evaluations, the missing type may affect conversions and which comparison outcomes are possible.

If the comparison operand is specifically a stable signed 32-bit integer, ordinary signed equality and ordering apply: equality selects 8 and 9; a greater selector uses the second-predicate-true rows; a lesser selector uses the second-predicate-false rows. That interpretation is conditional, not established.

## Acceptance examples

These are conditional static deductions, not executed tests. Assume usable storage, defined applicable arithmetic and conversions, normal dependency returns, and usable post-call local values unless stated otherwise.

1. **Disabled resolution.** Enable zero clears descriptor +24 and skips resolution. If nothing subsequently changes that field before its publication read, second-output +0 receives zero. If F-unknown-01 changes it to 77 and it then remains unchanged, publication yields 77 instead.

2. **Direct resolution.** With nonzero enable, index zero, and descriptor +8 containing 96, resolution stores 96 without a context-table lookup. Publication yields 96 only if that field remains unchanged until its final read.

3. **Bound rejection.** A nonzero index equal to the unsigned bound prevents the lookup-base and entry reads. Selection and publication continue.

4. **Entry rejection.** An in-range nonzero index with an odd entry does not invoke F-a01d4dfb5f88. Selection and publication continue.

5. **Unsigned scaling.** Index 0x40000001 below bound 0x40000002 scales to 4 modulo \(2^{32}\). Base 0x1000 produces lookup address integer 0x1004.

6. **Unsigned base addition.** Index 1 and base bits 0xFFFFFFFC produce address integer zero. This does not make dereferencing zero valid.

7. **Early return.** A zero first value at the address returned by F-a01d4dfb5f88 skips selection, F-unknown-01, and direct output writes. Dependency mutations may still have occurred.

8. **Repeated resolution read.** A first returned-address value of 4096, second value of zero, and post-call addend of 24 produce a resolution store of 24.

9. **Enable truncation.** Enable 256 enables resolution but publishes byte zero. Enable −1 enables resolution and publishes byte 255.

10. **Equality precedence.** Whenever the first equality comparison evaluates true, indices 8 and 9 are selected regardless of option or selector-specific cases.

11. **Conditional signed selection.** If the comparison operand is signed 32-bit, selector 0x1401 with comparison values 0x1400 first and 0x1401 second enters the second-predicate-false branch. Option zero selects 6 and 7.

12. **Type-dependent ordering.** Suppose the shared operand is stable, four bytes wide, and has bits 0xFFFFFFFF. With selector 0x1401, a signed 32-bit interpretation makes the second predicate true and selects 0 and 1. An unsigned 32-bit interpretation converts the selector for comparison, makes the predicate false, and selects 6 and 7 when option is zero. The missing declaration prevents choosing between these interpretations.

13. **Conditional changing pointer.** If the selection-data object is a stored pointer to four-byte elements, indices 6 and 7 are selected, and execution validly observes different pointer values at the two element evaluations, the values can come from different referenced tables. This example does not apply merely because array indexing appears in the body.

14. **Publication aliasing.** If second-output +0 overlaps descriptor +28, the first second-output write can change the value subsequently read for second-output +4. A pre-publication snapshot of both fields is not established.
