# F-09dd86e5c9b9

## Purpose

F-09dd86e5c9b9 gates up to two operations on a comparison between two record fields. When the fields match, it optionally invokes F-f7742bc6b842 and then optionally invokes F-074238b57126, both using an address inside the second record. When the fields differ, it invokes neither dependency and returns status 6.

A matching comparison produces status 0 if execution returns normally, including when neither optional operation is requested. Status 0 therefore establishes that the comparison matched and control reached the normal return; it does not independently establish that either dependency achieved its intended effect.

The application-level meaning of the records, compared fields, embedded region, and optional operations is not established. Descriptions such as “reset,” “assignment,” “identifier,” or “ownership transfer” would require evidence beyond this function.

## Behavior

### Comparison gate

The function obtains a 32-bit value from the first record at offset 24 and another from the second record at offset 72, then tests them for equality.

Equality, rather than ordering or arithmetic, determines the branch. The comparison does not add, subtract, truncate, or scale the field values. For equal-width 32-bit operands, signed versus unsigned interpretation does not change whether their bit patterns compare equal.

The evidence does not establish which of the two comparison locations is read first. It establishes that both values are used to resolve the gate before either optional dependency call.

If the values differ:

- Neither dependency is invoked.
- The optional value address is not dereferenced.
- The operation selector does not cause an operation.
- The function returns 6.

This path still requires the comparison reads. Disabling both optional operations does not bypass the gate.

### Matching path

If the values match, two independent conditions determine whether calls occur.

First, the function tests the operation selector. Any nonzero value enables a call to F-f7742bc6b842 with the address at byte offset 108 in the second record. Zero disables this call. There is no established distinction among positive, negative, or other nonzero selector values.

Second, the function checks whether the optional value address is null. If it is non-null, the function reads one 32-bit value from that address and calls F-074238b57126 with:

1. The address at byte offset 108 in the second record.
2. The 32-bit value just read from the optional value address.

The second argument is the value read, not the optional value address itself. The wrapper does not directly write a result through that address.

When both calls are enabled, F-f7742bc6b842 is invoked first. The optional 32-bit value is read only after that call returns. Consequently, the second call can receive a value affected by the first dependency, including through aliasing or changes to memory lifetime.

The comparison is not repeated between the calls. Changes to either comparison field during F-f7742bc6b842 do not, by themselves, cause the wrapper to abandon the already-selected matching path.

If all enabled calls return normally, the function returns 0. No dependency return value is inspected to choose this status.

### Observable ordering

The established ordering constraints are:

- The comparison reads precede any enabled dependency call.
- A mismatch prevents both dependency calls and the optional-value read.
- When enabled, F-f7742bc6b842 completes before the optional-value read and the invocation of F-074238b57126.
- The optional-value read precedes F-074238b57126.
- The wrapper’s normal return follows all enabled calls.

These constraints do not specify ordering between the two initial comparison reads or memory operations internal to either dependency.

There is no wrapper-level loop or retry. Each dependency is invoked at most once by this function during one normal invocation.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed test results. Unless otherwise stated, required accesses are valid and enabled dependencies return normally.

### Mismatch overrides both options

Given unequal comparison fields, a nonzero operation selector, and a non-null optional value address:

- Return 6.
- Invoke neither dependency.
- Do not read through the optional value address.

The same result applies with either option disabled.

### Match with neither option enabled

Given equal comparison fields, a zero operation selector, and a null optional value address:

- Perform the comparison.
- Invoke neither dependency.
- Return 0.

This demonstrates that status 0 does not imply a dependency call occurred.

### Match with only the first operation enabled

Given equal comparison fields, a nonzero operation selector, and a null optional value address:

- Invoke F-f7742bc6b842 once with the second record’s offset-108 address.
- Do not invoke F-074238b57126.
- Return 0 after the enabled call returns normally.

A negative selector has the same enabling effect as any other nonzero selector.

### Match with only the second operation enabled

Given equal comparison fields, a zero operation selector, and a non-null address containing a 32-bit value:

- Do not invoke F-f7742bc6b842.
- Read that value.
- Invoke F-074238b57126 once with the embedded address and the read value.
- Return 0 after the call returns normally.

Zero is a permitted read value; only the address’s nullness controls whether this call is enabled.

### Both operations enabled

Given equal comparison fields and both options enabled:

- Invoke F-f7742bc6b842 first.
- After it returns, read the optional value.
- Invoke F-074238b57126 with that value.
- Return 0 after the second call returns normally.

The optional value must not be treated as an entry-time snapshot.

### Earlier dependency changes the optional value

Suppose both operations are enabled and F-f7742bc6b842 changes the memory addressed by the optional value address while leaving it valid and readable.

F-074238b57126 receives the value present at the later read, not necessarily the value present when the wrapper began.

### Earlier dependency changes a comparison field

Suppose the initial comparison matches and F-f7742bc6b842 subsequently makes the two comparison fields unequal.

If the optional value address is non-null and remains readable, the second operation still proceeds. There is no second comparison gate.

### Invalid optional value address

On a mismatch, a non-null but unreadable optional value address is not dereferenced by this wrapper.

On a match, if the second operation is enabled and execution reaches its read, no normal result is specified for an unreadable address. The evidence does not support converting that failure into status 6.
