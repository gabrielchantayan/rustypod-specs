# F-f864d4b0c549

## Purpose

F-f864d4b0c549 performs a fixed, partial conversion from a 32-bit selector to an 8-bit value. It reports whether the selector has a defined mapping and writes the mapped byte only when that mapping exists.

The conversion is not an identity mapping, and it is not one-to-one: selectors 1 and 4 both produce byte value 4. Selector 6 produces byte value 0 while still reporting success. Consequently, neither the output byte’s value nor its equality to the selector determines success; the return value does.

The supplied static evidence establishes the complete mapping and the function’s direct memory effects. It does not establish what the selectors or resulting bytes mean in the surrounding application. Any interpretation as an enumeration conversion, protocol translation, or category remapping is inferred intent rather than part of this contract.

## Interface

The function accepts two arguments:

| Argument | Representation | Role |
|---|---|---|
| Selector | 32-bit value | Chooses a mapping entry. |
| Output destination | Pointer to a one-byte storage location | Receives the mapped value on success. |

The return value is 32 bits wide:

| Return value | Meaning |
|---|---|
| 1 | A mapping exists, and the function writes the corresponding byte before returning normally. |
| 0 | No mapping exists, and the function does not access the output location. |

No other normal return values are shown.

The selector’s signedness is not established by the supplied type information. Its behavior is nevertheless fully determined by its 32-bit value: only the listed small nonnegative values are accepted. A bit pattern interpreted elsewhere as a negative signed 32-bit integer is not a supported selector.

The output is exactly one byte, not a 32-bit integer or a larger record. There is no associated length, terminator, alignment padding, or additional field in this interface. Byte order does not affect the mapped value because only one byte is stored.

For a supported selector, the caller must supply a destination that permits a one-byte write. The function does not check the pointer before using it. For an unsupported selector, the function does not dereference the destination, so writable storage is not required by the demonstrated function body on that path. Any additional calling-environment restrictions on pointer arguments are outside the supplied evidence.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not reports of executed tests.

1. **Ordinary conversion:** Given selector 2 and a writable destination initially containing 170, a normal call must return 1 and leave the destination containing 1.

2. **Shared result:** Given selector 1 or selector 4 and a valid destination, each call must return 1 and write 4. An implementation that requires every accepted selector to produce a unique byte would violate the mapping.

3. **Zero-valued successful output:** Given selector 6 and a destination initially containing 255, the call must return 1 and write 0. Reporting rejection merely because the mapped byte is zero would be incorrect.

4. **Explicit rejection at zero:** Given selector 0 and ordinary writable storage initially containing 170, the call must return 0 and leave that storage containing 170.

5. **Explicit interior rejection:** Given selector 15 and a destination initially containing 85, the call must return 0 without changing that byte. Treating the entire range from 1 through 22 as accepted would be incorrect.

6. **Highest accepted selector:** Given selector 22 and a valid destination, the call must return 1 and write 17. Given selector 23, it must instead return 0 and perform no destination access.

7. **No low-byte reduction:** Given selector 258, whose low eight bits equal 2, the call must return 0 and leave the destination untouched. The successful mapping for selector 2 does not apply.

8. **Full-width rejection:** Given the 32-bit value 4,294,967,295, the call must return 0 without accessing the destination. This remains true whether a caller describes that bit pattern as unsigned maximum or signed negative one.

9. **Write footprint:** Given selector 16 and a destination located within a larger writable byte sequence, the addressed byte must become 24. This function must not modify neighboring bytes.

10. **No output dereference on rejection:** If the calling environment permits passing a null pointer value, a call with selector 15 follows a path that returns 0 without dereferencing it. This example does not extend to supported selectors.

11. **Existing matching contents:** Given selector 7 and a destination already containing 7, the call must still return 1 and execute the specified byte write. An unchanged final value does not imply that the store was skipped.
