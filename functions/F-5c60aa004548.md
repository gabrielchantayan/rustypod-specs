# F-5c60aa004548

## Purpose

F-5c60aa004548 scans a mutable byte sequence using a caller-supplied byte-classification table. It can skip an initial class of bytes, traverse delimiter-controlled regions and escaped bytes, stop without changing the sequence, or replace a selected byte with zero.

The established behavior is table-driven. No particular byte value—including zero, a quote character, a backslash, or a whitespace character—has an intrinsic meaning independent of its table entry.

**Inferred intent:** the routine resembles an in-place lexical scan that finds a truncation point while passing over quoted or escaped content. That interpretation is not required by this contract; the observable rules below are expressed in terms of classification masks.

## Interface

### Inputs

The routine takes two arguments:

1. **Context reference.** A machine-address-valued argument identifying a readable context object. A 32-bit value at byte offset 4 supplies the classification-table address.
2. **Sequence reference.** A pointer to mutable bytes. This is the initial scan position.

The supplied representation uses a 32-bit integer-shaped first argument and a 32-bit load for the table address. It does not establish a portable, pointer-width-independent interface.

### Classification-table layout

Each byte value selects an unsigned 16-bit classification entry:

- Index range: 0 through 255.
- Entry spacing: 2 bytes.
- Entry byte offset: twice the unsigned byte value.
- A complete table occupies 512 bytes.

Only the entries actually reached need to be readable for a particular execution. A complete table is the straightforward caller-side provision.

The table is accessed using native 16-bit loads. The source does not independently establish byte order, alignment requirements, or portability to unaligned-access targets.

The behavior uses these masks:

| Mask | Role |
|---|---|
| `0x0800` | Immediate truncation during the initial scan only |
| `0x0010` | Initial-scan skipping |
| `0x0080` | Truncation during the main scan |
| `0x0400` | Region with doubled-delimiter handling |
| `0x0040` | Region with escape handling |
| `0x0020` | Escape handling |
| `0x0008` | Boundary handling |

Entries may contain several masks. Their precedence is part of the behavior; the masks are not mutually exclusive categories.

### Output and ownership

The routine has no explicit return value.

Its directly established sequence effects are:

- No sequence modification; or
- Exactly one byte overwritten with zero.

It does not return the final scan position, a token length, or a success indicator. It does not allocate, free, or transfer ownership of memory.

### Preconditions

For defined, successful execution, the caller must provide:

- A context permitting the 32-bit read at offset 4.

There is no length argument and no bounds check. A zero byte is not an implicit stopping condition: its classification controls what happens.

## Behavior

### 1. Establish the classification table

The routine reads the table address from the context once, before scanning.

Subsequent classifications use that captured address. The routine does not explicitly reload the context field.

### 2. Perform the initial scan

At the current position, the routine reads the byte and its 16-bit classification.

The precedence is:

1. If `0x0800` is set, overwrite the current byte with zero and return.
2. Otherwise, if `0x0010` is set, advance one byte and repeat the initial scan.
3. Otherwise, enter the main scan at the same position.

Consequences:

- A byte carrying both `0x0800` and `0x0010` is overwritten, not skipped.
- Other masks do not affect initial skipping while `0x0010` remains set and `0x0800` is clear.
- The initial classification is not simply reused for main-scan dispatch; the byte and its classification are read again.

### 3. Dispatch the main scan

At each main-scan position, the routine reads the current byte and its classification. It applies this priority order:

1. `0x0080`: overwrite the current byte with zero and return.
2. `0x0400`: traverse a doubled-delimiter region.
3. `0x0040`: traverse an escape-aware region.
4. `0x0020`: process an escape outside either region.
5. `0x0008`: return without writing.
6. None of the above: advance one byte and repeat main-scan dispatch.

The initial-scan masks `0x0800` and `0x0010` have no independent effect in this phase.

An entry containing `0x0080` and any lower-priority mask therefore causes a write. An entry containing `0x0008` together with a region or escape mask does not necessarily cause an immediate return.

### 4. Traverse a doubled-delimiter region

The opening byte’s value becomes the delimiter value. The opening byte is not modified.

Traversal begins with the next byte:

- Read and classify the candidate byte.
- If its classification contains `0x0008`, stop region traversal at that candidate.
- Otherwise, compare its byte value with the opening delimiter.
  - If it differs, continue to the following byte.
  - If it matches, read the immediately following byte without classifying that following byte at this point.
    - If the following byte also equals the delimiter, treat the pair as an interior doubled delimiter and continue after both bytes.
    - If it does not match, stop region traversal at the first matching delimiter.

After traversal stops, the routine reads the stopping byte’s value again:

- If it equals the opening delimiter, advance past it.
- Otherwise, leave the scan position on it.

Then resume main-scan dispatch.

Important consequences:

- A matching delimiter encountered as a `0x0008` boundary is consumed.
- A nonmatching `0x0008` boundary remains available for main-scan processing.
- The second byte of an accepted doubled pair is not classified by the region traversal.
- A matching delimiter that is not also a boundary requires one-byte lookahead to decide whether it is doubled. That lookahead byte can subsequently be processed again by the main scan.
- Within the region, masks other than `0x0008` do not themselves trigger normal main-scan behavior.

### 5. Traverse an escape-aware region

The opening byte’s value becomes the delimiter value. Traversal starts at the following byte.

For each candidate:

1. Read the candidate byte and classification.
2. If its classification contains `0x0008`, or its value equals the delimiter, stop region traversal.
   - The candidate byte is read again to decide whether it equals the delimiter.
   - If it matches, advance past it.
   - Otherwise, retain it as the current position.
3. If neither stopping condition applies and the candidate has `0x0020`, move to the immediately following byte and classify that byte:
   - If this escaped byte has `0x0008`, stop region traversal with the scan position on the escaped byte.
   - Otherwise, continue traversal after the escaped byte.
4. If the candidate is neither a stopping byte nor an escape byte, continue with the following byte.

Resume main-scan dispatch at the resulting position.

Consequences:

- Delimiter matching and `0x0008` take precedence over escape handling for a candidate.
- An escaped byte is not checked for delimiter equality by the region’s stopping comparison.
- An escaped matching delimiter without `0x0008` is passed over as content.
- An escaped byte with `0x0008` is left for main-scan dispatch. It is not automatically consumed.
- `0x0080` on an interior candidate or escaped byte does not itself cause truncation while region traversal continues.
- After leaving the region, the resulting position is classified anew by the main scan.

### 6. Process an escape outside a region

When main-scan dispatch selects `0x0020`, the routine classifies the following byte:

- If that following byte has `0x0008`, advance by one byte.
- Otherwise, advance by two bytes.

Then resume main-scan dispatch.

Thus a following boundary byte is left as the next main-scan position. A following nonboundary byte is skipped, even if it has a mask that would otherwise trigger truncation or open a region.

The current escape byte’s own `0x0008` mask does not override its higher-priority `0x0020` behavior.

### 7. Termination and progress

Normal completion occurs only through:

- Initial-scan `0x0800`: write zero and return.
- Main-scan `0x0080`: write zero and return.
- Main-scan `0x0008`, with all higher-priority dispatch masks absent: return without writing.

No backward movement is established. Each continuing traversal advances the position, but progress alone does not guarantee termination within valid memory.

## Side effects

2. Read sequence bytes and corresponding 16-bit table entries as scanning proceeds.

No other explicit memory writes are present.

Several reads are repeated rather than cached:

## Acceptance examples

### Initial skipping followed by truncation

Given bytes `S S T`, with `S` classified as `0x0010`:

- Both `S` bytes remain unchanged.
- `T` is replaced with zero.
- No later sequence byte is required to determine completion.

If the first `S` instead has both `0x0010` and `0x0800`, that first byte is replaced with zero immediately.

### Boundary completion without writing

Given an ordinary byte followed by `E`:

- The ordinary byte is passed.
- The routine returns at `E`.
- Neither byte is changed.

If `E` also has `0x0080`, it is overwritten instead, because truncation has higher main-scan priority.

### Initial-only masks

Suppose `A` is ordinary, `B` has only `0x0800`, and the sequence is `A B E`.

- Initial scanning ends at `A`.
- Main scanning passes both `A` and `B`.
- The routine returns at `E` without writing.

The `0x0800` mask does not regain its initial-scan meaning later.

### Escape outside a region

Let `X` have only `0x0020`.

For `X T E`:

- `T` is classified as lookahead and skipped because it lacks `0x0008`.
- The routine returns at `E`.
- `T` is not overwritten.

For `X E`:

- The escape advances only to `E`.
- Main scanning returns there without writing.

### Doubled delimiters

Let `Q` have only `0x0400`. For `Q a Q Q b Q T`:

- The middle `Q Q` pair is traversed as doubled content.
- The final `Q` is recognized as a closing delimiter because the following `T` differs.
- Main scanning resumes at `T`.
- `T` is replaced with zero; all preceding bytes remain unchanged.

For `Q a E`, the region stops on the nonmatching boundary `E`, and main scanning returns without modifying it.

### Escaped delimiter within a region

Let `Q` have only `0x0040` and `X` only `0x0020`. For `Q X Q Q T`:

- The first interior `Q` is skipped as the byte following `X`.
- The next `Q` closes the region.
- `T` is replaced with zero.

For `Q X E`:

- Escape-aware traversal stops on the escaped boundary `E`.
- Main scanning returns there without writing.

### Zero is table-defined

If byte value zero has only `0x0080`, reaching it through main dispatch performs a zero write and returns.

If zero has classification zero, reaching it does not itself stop scanning. Further storage must remain readable until another stopping condition is reached.
