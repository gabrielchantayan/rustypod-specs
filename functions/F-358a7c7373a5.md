# F-358a7c7373a5

## Purpose

F-358a7c7373a5 conditionally executes an ordered sequence of operations involving a parent object and two subordinate references obtained from that parent.

Execution is enabled only when the selector argument, the initially checked first subordinate reference, and the initially checked second subordinate reference are all nonzero. Otherwise, the function returns without calling a dependency.

On the enabled path, the function invokes subordinate dispatch entries, obtains two parent-provided quantities at different points, performs configuration-like calls, submits a six-argument operation, and finally calls a dependency with the parent.

**Established static behavior:** the entry conditions, field accesses, dispatch offsets, explicit arguments, dependency order, arithmetic expressions, and absence of an explicit result or status check.

**Inferred intent:** preparation or configuration of related objects for an operation whose extent depends on a count and a parent-provided quantity. The source does not establish the objects’ semantic roles, the units of the quantities, or the meanings of the constants.

### Preconditions for normal completion

A zero selector requires no readable parent storage: the function does not dereference the parent on that path.

For a nonzero selector, the parent must be readable at `0x04`. Only if that field is nonzero does the gate require a read at `0x08`.

If the gate succeeds, every later memory access and dependency invocation must be valid when it occurs. The initial checks do not ensure later validity. Dependencies may replace references, change dispatch tables, invalidate objects, or alter other state before subsequent accesses. No later null check is shown.

There is no established requirement that the two subordinate references be distinct. Safe behavior under aliasing is not established.

## Behavior

### Entry gate and early returns

The gate is evaluated in this order:

1. Determine whether the selector is zero.
2. If the selector is nonzero, read the first subordinate reference at parent offset `0x04`.
3. If the selector and first subordinate reference are nonzero, read the second subordinate reference at parent offset `0x08`.
4. Enter the operational sequence only if all three tested values are nonzero.

Consequently:

- With a zero selector, neither subordinate field is read.
- With a nonzero selector and zero first subordinate, the second subordinate field is not read.
- With a nonzero selector, nonzero first subordinate, and zero second subordinate, both fields are read, but no dependency is called.

These paths perform no explicit writes through the supplied references.

The checks establish only nonzero values. They do not establish mapping, alignment, type compatibility, object lifetime, or callable dispatch entries.

### Initial subordinate calls

After the gate succeeds, the first operation invokes dispatch entry `0x00` using the **first subordinate reference retained from the gate**. No explicit arguments are shown.

After that call returns, the function rereads the parent’s second subordinate field and invokes dispatch entry `0x00` through the resulting reference. This is not necessarily the second subordinate reference that passed the gate.

Neither return value is used.

This distinction matters if the first call changes the parent: the initial first-subordinate call uses the retained reference, whereas the subsequent second-subordinate call uses the newly read reference. There is no intervening null check.

### First parent query and second-subordinate operations

The function invokes parent dispatch entry `0x20`, explicitly passing the parent reference. The resulting signed 32-bit quantity is retained for both later count multiplications.

It then performs the following indirect calls, in order:

1. Second-subordinate dispatch entry `0x04`, receiving the current second subordinate reference and the original selector.
2. Second-subordinate dispatch entry `0x0C`, receiving the current second subordinate reference and the product of the original count and the retained first parent-query result.

The second subordinate is accessed again for each call. Its identity need not remain the same across these operations.

Both multiplication operands are represented as signed 32-bit integers. The source shows no wider intermediate, overflow test, saturation, or overflow-dependent branch. When the mathematical product is representable in signed 32 bits, that product is the established argument. For products outside that range, target-level overflow behavior remains **documented_only**; neither portable wrapping nor trapping is established.

## Acceptance examples

These are conditional criteria derived from static evidence, not runtime observations. Enabled-path examples assume valid accesses and normally returning dependencies unless stated otherwise.

### Zero selector

With selector zero, no parent dereference or dependency call occurs, even if the parent reference would be invalid to dereference. The function returns without a status.

### Missing subordinate references

With a nonzero selector and a readable zero first-subordinate field, only that subordinate field is read by the gate. The second field is not read, and no dependency is called.

With a nonzero selector, nonzero first subordinate, and zero second subordinate, the gate reads both fields in that order. No dependency is called.

### Ordinary products and distinct parent results

Assume the first parent query returns `12`, the count is `3`, and references remain valid.

- Second-subordinate dispatch entry `0x0C` receives `36`.
- F-cd9a0e0317f8 receives `36`.
- F-e9d4d014951e receives count `3`, not `36`.
- The payload retains all four input bytes.

If the second parent query returns `20`, F-5cc44b93421a receives `20`; neither earlier product changes.

### Zero and negative inputs

With count zero and an enabled gate, both products are zero, but the entire sequence still runs.

With selector `-1`, count `-3`, and first parent-query result `7`, the selector enables execution and is forwarded unchanged. Both products are `-21`. No positivity restriction is introduced.

A product outside the signed 32-bit range has no specified numerical acceptance result under this contract.

### Mutated subordinate references

If the first initial indirect call replaces the parent’s second subordinate reference, the next indirect call uses the replacement, not the second reference checked by the gate.

If the first conversion replaces the first subordinate reference, F-ab462c383b3b receives the replacement.

If a dependency sets a subordinate field to zero after the gate, the function does not convert this into an early return. Later argument forwarding or dispatch access proceeds without another null check; its outcome depends on the affected access or dependency.

### Changed global and conversion inputs

If an earlier dependency changes the global storage used by F-bff5594baeba, that dependency receives the value read at its later call position. This criterion does not prescribe the read’s width.

If the parent field at `0x10` changes between conversions, the second conversion receives the later field value. F-e9d4d014951e receives the second conversion result.

### Normal call accounting

With the gate enabled and every dependency returning normally, the observed sequence contains eighteen calls: six indirect and twelve identified. F-b53a2bf21f22 follows F-e9d4d014951e; it is not conditional on a returned success indication.
