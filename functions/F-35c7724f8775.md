# F-35c7724f8775

## Purpose

F-35c7724f8775 constructs a replacement byte buffer, changes its extent according to the difference between a requested value and an encoded field, and adjusts selected encoded fields. It then overwrites one buffer and passes that buffer’s address to a dependency.

On the successful adjustment path, the caller publishes the replacement address and metadata before overwriting the original buffer. On detected traversal failure, it writes the saved original descriptor words back before overwriting the replacement.

These are ordered operations, not a guarantee of transactional replacement. Buffer writes can affect descriptor storage through aliasing, and the final dependency has unknown side effects.

The apparent intent is to resize a region within a structured buffer and update related positions or sizes. That interpretation is inferred. The copying, arithmetic, field traversal, descriptor writes, and overwrite operations are established by the supplied static evidence.

## Interface

The function accepts four arguments:

| Argument | Width and established use |
|---|---|
| Target offset | Unsigned 32-bit byte offset. Identifies the initially decoded field and the adjustment position required for success. |
| Requested value | Unsigned 32-bit value. Compared with the initially decoded field and used to calculate the change amount. |
| Prefix length | Unsigned 32-bit byte count. Controls the initial copy and the insertion or removal boundary. |
| Descriptor address | Nullable pointer to two consecutive 32-bit words. |

The descriptor contains:

| Byte offset | Contents |
|---|---|
| 0–3 | Buffer address, represented as a 32-bit word. |
| 4–7 | Metadata used in extent calculations. |

The return value is a 32-bit word, not an established Boolean or uniform success/error enumeration:

- A saved external initial-result word when the descriptor or its initial buffer address is null.
- Zero when the initial field already equals the requested value.
- A subsequently read external allocation-failure-result word when the replacement dependency returns zero.
- Zero after successful adjustment and the final dependency call.
- A nonzero traversal-error word after detected traversal failure and the final dependency call.

The allocation-failure-result word can itself be zero; its meaning is unknown.

Five external 32-bit words participate:

1. Initial result.
2. Extent multiplier.
3. Allocation-failure result.
4. Replacement-metadata multiplier.
5. Traversal-error result.

Their concrete values and semantic meanings are **documented_only**. The two multipliers are not established to be inverses.

### Preconditions for ordinary completion

The function performs no general validation of storage or structure. Ordinary completion requires accessible descriptor words, accessible field and copy ranges, usable replacement storage, and traversal data that reaches the target or produces a terminating failure.

Appropriate nonaliasing is additionally required for the ordinary interpretation of “publish replacement, dispose original” or “restore original, dispose replacement.” In particular, overwriting a buffer must not overwrite the descriptor if its written state is expected to persist.

No exception, fault-recovery, synchronization, alignment-tolerance, or allocation-format contract is established.

## Behavior

### Arithmetic and encoded fields

Addresses, offsets, externally supplied words, and returned values use the displayed 32-bit representation. Unsigned comparisons range from zero through 4,294,967,295.

A stored field occupies four bytes. Each stored byte is multiplied by 23, reduced to eight bits, and the resulting bytes are assembled most-significant first into a 32-bit value.

Encoding applies multiplication by 167 modulo 256 to each corresponding value byte. This is the inverse byte transformation because 23 × 167 is congruent to one modulo 256.

Examples:

- Stored bytes `00 00 00 01` decode to 23.
- Value 1 encodes as `00 00 00 A7`.
- Encoded-field adjustment retains the 32-bit representation of the decoded value plus the change amount.

Several extent intermediates are displayed as signed 32-bit quantities. The function contains no explicit negative-size or signed-overflow rejection. Nonnegative, nonoverflowing extents have an unambiguous interpretation. Outside that domain, the evidence must not be treated as a checked signed-arithmetic contract; exact language-level overflow semantics are **documented_only**.

Unsigned count subtraction and address arithmetic can produce wrapped values. There are no general overflow checks.

### Entry and unchanged-value path

The initial-result word is read before examining the descriptor.

If the descriptor address is null, that saved word is returned without descriptor access.

Otherwise, the initial buffer address is read. If it is zero, the saved initial result is returned without reading the target field or metadata.

For a nonzero initial buffer address, the four-byte field at the target offset is decoded. No preceding bounds check is shown.

If the decoded value equals the requested value, the function returns zero. On this path, the caller does not read descriptor metadata, call either dependency, write the descriptor, or modify buffer bytes.

### Replacement request and unconditional result-word read

When the values differ, the caller saves the descriptor metadata and calculates:

- Original copy extent: saved metadata multiplied by the current extent multiplier.
- Change amount: requested value minus the initially decoded value.
- Replacement extent: original copy extent plus the change amount.

F-d33f6d597e5d is called once with the replacement extent’s 32-bit representation.

**After that dependency returns, the allocation-failure-result word is read unconditionally.** This read occurs for both rejected and accepted results. On the accepted path, it precedes the second extent-multiplier read and the replacement-metadata-multiplier read.

Only a zero dependency result is rejected. **A result of one is accepted**, as is every other nonzero 32-bit result.

For a zero result, the function returns the allocation-failure-result word just read. It performs no subsequent caller-side copying, descriptor publication, overwrite, or disposal call. Effects already performed by F-d33f6d597e5d remain possible.

For an accepted result, the returned word is used as the replacement address without an accessibility, alignment, size, or distinctness check. The caller then:

1. Rereads the extent multiplier and multiplies it by the saved metadata to obtain the original-buffer overwrite length.
2. Reads the replacement-metadata multiplier and multiplies it by the previously calculated replacement extent.

The original copy extent is not recomputed. Consequently, the original copy extent and original overwrite length can differ if the dependency changes the extent multiplier.

The dependency can also change original-buffer bytes, descriptor storage, or other external state. Copying uses the saved original address but reads the bytes present after the dependency call.

### Copy construction

The prefix copy transfers the prefix-length bytes from original offset zero to replacement offset zero.

Each copy chooses its direction by comparing its destination start address with its source start address:

- Lower destination address: ascending offsets.
- Equal or higher destination address: descending offsets.

Each byte is read before its corresponding destination write. The complete prefix copy precedes the suffix copy.

For an increase, where the requested value exceeds the initial decoded value:

- The suffix source begins at the prefix length.
- The suffix destination begins at the prefix length plus the increase.
- The suffix length is the original copy extent minus the prefix length.

The interval between the copied prefix and shifted suffix is not initialized by these copies. Later field writes may affect it.

For a decrease:

- The suffix source begins at the prefix length plus the amount removed.
- The suffix destination begins at the prefix length.
- The suffix length is the replacement extent minus the prefix length.

No check ensures that the prefix fits either extent, the removal boundary lies within the original buffer, or the calculated addresses do not wrap.

Direction selection provides an overlap-aware order for each individual copy. It does not prove that the combined operations are safe for arbitrary overlap involving the buffers, descriptor, or external words.

### Publication and adjustment

After copying, the caller writes:

1. The replacement address into descriptor bytes 0–3.
2. The calculated replacement metadata into descriptor bytes 4–7.

These writes precede adjustment validation and either overwrite path. Their persistence is conditional on later writes and dependency effects not modifying the descriptor.

Adjustment starts at byte offset 12.

At each selected adjustment offset, the caller:

- Loads the buffer address currently stored in the descriptor and decodes the field there.
- Adds the original change amount.
- Reloads the descriptor’s buffer address.
- Writes the encoded result in four consecutive byte writes, most-significant byte first.
- Tests whether the adjusted offset equals the target offset.

The address used for decoding is captured for that field read. The address used for encoding is reloaded and then used for all four writes; it is not reloaded between those writes.

Neither the initial decoded target value nor the change amount is recomputed.

If the adjusted offset equals the target, the caller takes the success path. Otherwise, traversal begins at the adjusted offset plus 20. That addition has no explicit wraparound check.

### Traversal

At each scan position, traversal loads the buffer address from the descriptor, decodes a field, and adds its value to the current scan position.

**The traversal-error-result word is read after every such decoded advance**, including advances that do not wrap. Its value is retained as the pending status only when the addition wraps below the current scan position.

For a nonwrapping sum:

- If the sum is at or below the target, traversal continues at that sum.
- If the sum exceeds the target, traversal ends and the current scan position—not the greater sum—is selected for adjustment.

The traversal-error word read during a nonwrapping advance does not cause failure.

For a wrapping sum:

- A nonzero traversal-error result causes rollback without another field decode.
- A zero traversal-error result causes another attempt at the same scan position.

Thus, unchanged data and a persistently zero error word can produce indefinite repetition after wraparound. A zero decoded advance also repeats indefinitely when its position is at or below the target.

There is no extent bound check, general cycle detection, or explicit requirement that the target be at least 12. An adjustment offset greater than the target is not immediately rejected.

### Success and rollback

On success, the caller performs no descriptor-restoration writes. It overwrites the saved original buffer using the original-buffer overwrite length, calls F-5e3309c9d083 with the saved original address, and returns zero.

“Success” does not guarantee that the descriptor still contains the published words immediately before or after that dependency:

- Field adjustment can modify descriptor storage through aliasing.
- The original-buffer overwrite can modify descriptor storage through aliasing.
- F-5e3309c9d083 can modify the descriptor or referenced memory through unknown side effects.

On terminating traversal failure, the caller writes the saved original address back to the descriptor, then writes the saved original metadata. It overwrites the replacement for the calculated replacement extent, calls F-5e3309c9d083 with the replacement address, and returns the saved nonzero traversal status.

The same persistence limitations apply to rollback: the replacement overwrite may alias the descriptor, and the dependency may subsequently change it. Restoring descriptor words also does not restore original-buffer bytes changed by overlapping copies or field writes.

## Side effects

### Observable access order

The principal caller-side order is:

1. Read the initial-result word.
2. Read the initial descriptor address word, if applicable.
3. Read the initial encoded target field, if applicable.
4. When change is needed, read metadata and the first extent multiplier.
5. Call F-d33f6d597e5d.
6. Unconditionally read the allocation-failure-result word.
7. On acceptance, reread the extent multiplier, then read the replacement-metadata multiplier.
8. Copy the prefix, then the suffix.
9. Write replacement address, then replacement metadata.
10. Adjust fields and perform any traversal reads, including traversal-error-word reads.
11. On rollback, write original address, then original metadata.
12. Overwrite the selected buffer.
13. Call F-5e3309c9d083.

The static evidence establishes four ordered byte writes for encoding, but not a strict order among the four reads within a field decode.

Descriptor publication and field encoding are not atomic. No synchronization is shown. Aliasing can make writes affect later reads, including reads of external words.

### Disposal overwrite

The overwrite visits the selected range from its final byte toward its first byte.

An eight-bit state begins at hexadecimal B4. For each byte, the written value is the low eight bits of:

- The state XOR hexadecimal BA,
- multiplied by the state plus hexadecimal 11, with byte reduction.

The state advances by one modulo 256 after each write. The first two values written are `C6` and `9A`, in descending address order.

A zero overwrite length performs no overwrite writes but still reaches the disposal dependency. Unvalidated negative or overflowed extent representations must not be interpreted as safely rejected sizes.

The overwrite is deterministic, not zero filling. Its intended security property is **documented_only**.

### Ownership

The caller does not establish that replacement storage is distinct from original storage.

Passing an address to F-5e3309c9d083 establishes a call after the overwrite, not actual release or ownership transfer. Allocator compatibility and subsequent pointer validity are unknown.

## Acceptance examples

These are conditional static expectations, not executed tests. Except where stated otherwise, assume accessible ranges, ordinary nonoverflowing extents, distinct buffers, descriptor and external-word storage disjoint from buffer writes, stable external words, and dependencies that do not modify unrelated state.

1. **Null descriptor.** With initial result 9, a null descriptor returns 9. No descriptor memory is read and neither dependency is called.

2. **No change.** If the target field decodes to 23 and the requested value is 23, the return is zero. Descriptor metadata is not read, and neither dependency is called.

3. **Rejected replacement.** If F-d33f6d597e5d returns zero and the subsequently read allocation-failure-result word is 7, the return is 7. No caller-side publication or disposal follows.

4. **Replacement address one.** A dependency result of one enters the accepted path, not the rejection path. The caller reads the allocation-failure-result word, rereads the extent multiplier, reads the replacement-metadata multiplier, and proceeds using address one. Completion additionally requires every resulting memory access to be valid.

5. **Accepted-path external reads.** If the allocation-failure-result word is 7 but the replacement address is accepted, that word is still read. It is not the successful return value. With successful adjustment, the return is zero.

6. **Increase at offset 12.** With original copy extent 64, target offset 12, initial decoded value 8, requested value 12, and prefix length 32:
   - The replacement request is 68.
   - Original bytes 0–31 go to replacement bytes 0–31.
   - Original bytes 32–63 go to replacement bytes 36–67.
   - Replacement bytes 32–35 are not initialized by copying.
   - The field at offset 12 is increased by four.
   - The original buffer is overwritten and passed to F-5e3309c9d083.
   - The return is zero.

7. **Decrease.** With original extent 64, target offset 12, initial value 12, requested value 8, and prefix length 32, the replacement extent is 60. Original bytes 36–63 go to replacement bytes 32–59. The field at offset 12 is decreased by four.

8. **Traversal and discarded error reads.** With target 72, traversal after adjustment at 12 starts at 32. If the advance at 32 reaches 52 and the advance at 52 exceeds 72 without wrapping, offset 52 is adjusted next. The error word is read for both advances; even a nonzero value does not cause rollback on these nonwrapping advances.

9. **Wrapping traversal.** If an advance wraps below its scan position and the error word is 5, the caller writes the original descriptor words back, overwrites the replacement, calls F-5e3309c9d083 with it, and returns 5. With a persistently zero error word and unchanged field data, traversal repeats at that position instead.

10. **Descriptor persistence limit.** If the disposal overwrite overlaps descriptor storage, it may overwrite previously published or restored words before F-5e3309c9d083 is called. Independently, that dependency may change those words before returning.
