- A **word** is four bytes.
- A **halfword** is two bytes.
- A **byte** is one byte.
- A value “captured” by a read remains that value for its subsequent uses; another read of the same location is a distinct observation.
- **Low byte** and **low halfword** describe the stored low 8 or 16 bits.

Byte arithmetic contributes these stored bit patterns:

- First marker: low byte of B plus `0x6C`, reduced to eight bits.
- Second marker: low byte of B minus `0x22`, reduced to eight bits.

The evidence does not establish endianness. Word-to-byte conversion selects the low-order bits of the value, which is not necessarily the first byte at that value’s original memory address.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume accesses are valid, arithmetic is representable, and unrelated destinations do not overlap.

1. **Byte-marker arithmetic.** If B has low byte `0xF0`, the first marker stored at original A plus `0x15` is `0x5C`; the later second marker is `0xCE`. Under non-aliasing conditions, `0xCE` remains there.

2. **D truncation versus full-width storage.** If D is `0x1234ABCD`, both doubled-address halfword writes store `0xABCD`, the final doubled-link byte write stores `0xCD`, and adjusted A plus `0x14` receives the full `0x1234ABCD`. Byte ordering within multi-byte stores remains platform-dependent.

3. **Adjusted address use.** If original A is `0x2000` and the displacement read is `0x0100`, adjusted A is `0x1F00`. The function writes `0x1F00` at address `0x1F30`, writes D at `0x1F14`, and replaces the earlier original-A word at B plus `0xF2` with `0x1F00`.

4. **Different root-field observations.** If the first root-field read returns X and the second returns Y, C plus `0x24` receives X while C plus `0x54` receives Y. The contract does not equate X and Y.

5. **Different C-field observations.** If the pre-write C field differs from the displacement, both values are used. The former is written to link base plus `0x54` before the latter replaces it there; only the latter determines adjusted A and subsequent displacement-based reads.

6. **Non-aliasing final link fields.** If all later writes are disjoint from link base plus `0x14` and `0x54`, those fields finish as zero and the displacement, respectively. Without that disjointness condition, these final-value claims do not follow.

7. **Changed child link.** If the two reads of displacement plus `0x64` yield different addresses, the earlier child receives the earlier `0x44`, `0x54`, and `0x34` updates, while the later child receives the final `0x44` and `0x54` updates.
