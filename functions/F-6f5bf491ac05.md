# F-6f5bf491ac05

## Purpose

F-6f5bf491ac05 conditionally obtains a candidate object, processes candidate-associated state using two eight-byte local storage regions, writes two candidate bytes, and conditionally passes the candidate to a final dependency.

The two eight-byte regions establish local storage capacity, not the size of a logical value. The representation, initialized extent, and ownership of anything placed in those regions are unknown.

The visible behavior is:

- Begin construction only when a byte in the fifth input’s addressed storage equals `0x0A` and the third input is nonzero.
- Continue only when candidate initialization returns a nonzero address.
- Perform dependency calls using the two local regions and candidate offset `+4`.
- Store a control byte at candidate offset `+12` and the fourth input’s low eight bits at offset `+14`.
- Obtain a 32-bit mask and submit the candidate if the fourth input requests no bits outside that mask, or if the second input is nonzero.
- Return `1` after the final dependency returns; otherwise return `0` on the visible early-exit and rejection paths.

“Construction,” “candidate,” “control byte,” “mask,” and “submission” describe observable roles. Their application-level meanings are not established.

## Acceptance examples

These are conditional requirements derived from static control flow, not executed tests. Unless specified otherwise, assume valid accesses, normally returning dependencies, an initial discriminator of `0x0A`, a nonzero third input, and a nonzero candidate result.

1. **Discriminator mismatch.** With discriminator `0x09`, return `0` without any listed dependency call, regardless of the remaining inputs.

4. **Zero candidate result.** If F-d0d9c9d6a6d3 returns zero, return `0` without either local-processing sequence or either candidate-byte store.

5. **No requested bits.** With fourth input zero, acceptance succeeds for every mask. Candidate offset `+14` receives zero. Submission follows the second cleanup-like call.

6. **Subset accepted.** With fourth input `0x00000005`, mask `0x0000000D`, and second input zero, submit the candidate and return `1` after submission returns.

7. **Missing bit rejected.** With fourth input `0x00000005`, mask `0x00000001`, and second input zero, omit submission and return `0`. Both candidate-byte stores and both cleanup-like calls have already occurred.

8. **High bit remains significant.** With fourth input `0x00000100`, mask zero, and second input zero, store zero at candidate offset `+14` but reject because bit 8 is absent from the mask.

9. **Nonzero override.** With fourth input `0x80000000`, mask zero, and second input `-1`, accept. Candidate offset `+12` receives zero. Mask production and both cleanup-like calls still occur.
