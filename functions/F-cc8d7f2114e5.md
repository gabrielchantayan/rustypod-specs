## Behavior

### Dispatch selection

The wrapper first reads the integer at the input location. That value determines the dispatch base for this invocation.

It then forms the address displaced by 292 bytes from that base and reads the callable entry stored there. The input address itself is not the dispatch base: the initial load is a required level of indirection.

Consequently, if the input location is address A and its initial value represents address B, the selected entry is read from B plus 292, not from A plus 292.

No additional table index, length field, tag, or alternative selector is visible.

### Invocation and completion

After loading the callable entry, the wrapper invokes it once, with no explicit arguments in the supplied representation.

If the target returns normally, the wrapper completes normally. It performs no visible result conversion, result inspection, or subsequent dispatch. A value produced by the target is not exposed as an explicit wrapper result.

There is no visible retry, fallback, alternate target, or conditional branch. This single-invocation description assumes execution reaches the call and that the target itself does not re-enter the wrapper. Calls initiated by the target are outside the wrapper’s own dispatch sequence.

### Observable ordering

The established ordering is:

1. Read the integer at the input location.
2. Read the callable entry at the displaced address derived from that integer.
3. Invoke the selected target.
4. Return if the target returns normally.

The second read depends on the first, and the invocation depends on the second. No wrapper-authored data write appears between these operations.

The evidence does not establish atomicity, synchronization, memory barriers, or a coherent snapshot across the two reads. Concurrent changes to the input storage or dispatch slot therefore have no specified consistency guarantee here.
