# F-78d1342ad960

## Purpose

F-78d1342ad960 conditionally processes a record associated with a shared context. Depending on context flags, record state, and signed index comparisons, it invokes preparation dependencies, updates primary and secondary storage, allocates record-local buffers, links a record into a context-owned list, and advances a high-water field.

The established behavior is an ordered sequence of conditional calls and mutations, not an atomic operation. Several failures occur after visible writes, and no rollback is shown.

“Primary,” “secondary,” “index,” and “high-water” are descriptive labels for the observed roles of fields. Their application-level meanings are inferred, not established.

## Interface

### Input and result

The function accepts one pointer to a mutable record and returns a 32-bit integer.

The record contains a context pointer at byte offset `0x00`. Most context accesses use the pointer captured at entry. A later list-maintenance path explicitly reloads the context pointer from the record.

The return value is:

- The context’s initial 32-bit value at `0x20`, if nonzero.
- `3` when that value is zero and context byte `0x10` is nonzero.
- A nonzero result propagated from certain dependencies.
- `7` when primary buffer allocation returns zero.
- Otherwise, normally `0`.

Zero does not establish that every requested allocation succeeded: secondary buffer allocation can return zero without producing a nonzero function result.

## Behavior

### Entry gates and preparation

The function first captures the record’s context pointer and source field, then reads context status `0x20`.

A nonzero status returns immediately. In particular, the rejection flag at `0x10` is not consulted on this path.

With zero status, a nonzero rejection flag returns `3`. Otherwise, F-4c6b253a4fd3 is called with the record. A nonzero result is returned without executing the later processing stages.

After successful preparation, F-6398fbab1062 is called with the record. Its result is not used.

The function then decides whether to enter the main processing body:

- An unset record marker at `0x1C` enters without calling F-e46b10086b1c at this decision.
- An already-set marker causes F-e46b10086b1c to be called.
- With an already-set marker, entry requires both a zero dependency result and nonzero context byte `0x09`.

The context byte is tested after the dependency returns. It must not be treated as a value captured before that call.

When this decision rejects the main body, the function still sets context bytes `0x12` and `0x19` to `1`, then proceeds to high-water handling.

### Main-body preparation

The main body first calls F-14d1c687a87a with the record and a zero argument. Any nonzero result returns immediately.

Next, if context byte `0x04` is zero, byte `0x06` is nonzero, and byte `0x18` is not `2`, the function calls F-2642a413cd82 with the captured context pointer. A nonzero result returns immediately.

Only after those gates succeed does this path set context bytes `0x12` and `0x19` to `1`.

### Primary processing

Primary processing is considered only when the record’s `0x1C` marker is zero at this later read. It additionally requires nonzero context byte `0x04` or nonzero context byte `0x14`.

If that condition is false, neither the record’s processed marker nor the pending marker is changed by this primary block.

#### Index above the primary threshold

If the signed context value at `0x28` is less than the current signed record index, the pending marker becomes `1` exactly when both context bytes `0x05` and `0x0B` are zero. Otherwise it becomes `0`.

No primary allocation or I/O-like sequence is performed on this branch.

#### Primary I/O-like path

If the index is not above the threshold and context byte `0x14` is zero:

1. F-01aa528e5c81 receives the captured context pointer and entry-captured source value. Its 64-bit result is retained as separate high and low 32-bit words.
2. F-1c5fd5dfb1fb is called with five visible arguments: primary handle, translated high word, current position low word, current position high word, and current record index. A nonzero result returns immediately.
3. A temporary high word is calculated from the then-current position high word plus the carry that adding four to its low word would generate.
4. F-87fe98a22e06 receives the primary handle, entry-captured source, and current size.
5. Before checking that result, the tracked position is advanced using fields read after the call. Let **d** be the 32-bit wrapped result of current size plus four. The low word is increased by **d**. The high word is increased by the sign extension of **d** and by the unsigned carry from the low-word addition. The low word is stored before the high word.
6. A nonzero F-87fe98a22e06 result now returns, leaving that position change in place.
7. F-1c5fd5dfb1fb is called again, this time with six visible arguments: the primary handle, computed position high word, computed position low word, that same high word again, retained translated low word, and the temporary high word from step 3.
8. After this call, the current tracked position is increased by four, low word first and high word second, before checking the call’s result.
9. A nonzero result returns with that increment retained.
10. The primary counter at `0x30` is incremented. F-469a239057a8 receives handle `0x54` and the current record index.
11. The pending marker is set to `1` only when context byte `0x0B`, interpreted as an unsigned byte, is zero. Values `1` through `255` produce zero.
12. If context byte `0x09` is nonzero at the subsequent read, F-469a239057a8 also receives handle `0x58` and the current record index.

The two F-1c5fd5dfb1fb call shapes are materially different in the supplied evidence. Their arguments must not be normalized into an assumed conventional API.

#### Primary allocated-buffer path

If the index is not above the threshold and context byte `0x14` is nonzero:

- The dynamic displacement is read before calling F-391e3d30e634 with the size.
- The returned pointer is stored at record offset `D + 0x38`.
- A zero pointer returns `7`, after the zero has been stored.
- Otherwise, an unmapped external dependency receives the new pointer, the record’s source field reloaded at this point, and the current context size.

This block does not assign the pending marker.

#### Primary completion

After any non-failing primary branch, a nonzero pending marker sets context byte `0x11` to `1`. The function does not clear that context byte when the marker is zero.

It then sets the record’s `0x1C` marker to `1`.

### Secondary processing

After the primary stage, secondary processing requires all of the following, in order:

1. Nonzero context byte `0x09`.
2. A zero result from F-e46b10086b1c on the record.
3. Current signed record index less than or equal to signed context threshold `0x2C`.

If any condition fails, secondary processing is skipped.

With context byte `0x14` zero, the function calculates a 32-bit stride equal to size plus four, then a 32-bit product of that stride and counter `0x38`. It calls F-1c5fd5dfb1fb with five visible arguments: secondary handle, stride, product, arithmetic sign extension of the product, and record index.

A nonzero result returns immediately. Otherwise, F-87fe98a22e06 receives the secondary handle, entry-captured source, and current size. A nonzero result returns without incrementing the secondary counter. On success, that counter is incremented and F-469a239057a8 receives handle `0x58` and the current record index.

With context byte `0x14` nonzero:

- F-391e3d30e634 is called with the size.
- Its pointer result is stored at record offset `D + 0x3C`, using a displacement captured before the call.
- A nonzero pointer triggers the unmapped external dependency with only two visible arguments: destination and the record’s then-current source.
- A zero pointer does not cause an error return.
- The context pointer is then reloaded from the record, and the displacement is read from that context.
- If the record’s membership byte at `D + 0x48` is zero, the record is prepended to the list.

Prepending first writes the record pointer into the previous head’s `D + 0x44` field when a previous head exists. It then stores the context’s current head in the record’s `D + 0x40` field, updates context head `0x8C` to the record, and finally sets membership to `1`. A nonzero membership byte suppresses all these list writes.

### High-water handling

Paths that complete preparation without an early error reach this stage, including paths that skipped the main body.

The record index is read. If it exceeds the signed context high-water value, the high-water field is first set to that index.

If context byte `0x14` is then zero, F-870c4fcf7295 is called with `0x40000000` and the current size. When its result equals the captured index, the high-water field is overwritten with index plus one.

This stage does not run after earlier error returns.

## Side effects

The function can mutate context flags, counters, tracked-position words, and the high-water value; record markers and buffer-pointer slots; and list links in both the record and an existing head.

No release of an existing buffer is visible before either pointer slot is overwritten. No explicit release occurs on subsequent failure. Allocation ownership, replacement policy, and eventual cleanup are unknown.

Dependency effects are additional to these direct writes. The function’s behavior must not assume that dependencies preserve context fields, record fields, globals, or memory ownership. Captured values remain captured; later loads may observe dependency changes.

There is no visible synchronization or transactional protection. Concurrent mutation and reentrant execution are not specified.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless specified otherwise, dependencies return normally and do not modify the relevant fields.

- **Status precedence:** With initial context status `12` and rejection byte nonzero, return `12`; no dependency is called.
- **Rejection:** With zero initial status and nonzero rejection byte, return `3`; preparation is not called.
- **Preparation error:** If F-4c6b253a4fd3 returns `9`, return `9` without calling F-6398fbab1062 or performing high-water handling.
- **Skipped main body:** With an initially set record marker and F-e46b10086b1c returning nonzero, set context bytes `0x12` and `0x19`, skip the main-body gates and storage operations, and still consider high-water advancement.
- **Primary threshold branch:** With primary processing eligible and index above threshold, pending becomes `1` only when bytes `0x05` and `0x0B` are both zero. The processed marker becomes `1`.
- **Primary allocation failure:** On a selected primary allocated-buffer path, a zero allocation result is stored in the primary slot and causes return `7`. No primary transfer or high-water update follows.
- **Position change despite error:** On the primary I/O-like path, let the position be zero and size be eight. If the first F-1c5fd5dfb1fb call succeeds and F-87fe98a22e06 returns `6`, return `6` with position advanced to twelve.
- **Carry on the later increment:** If the second primary F-1c5fd5dfb1fb call leaves the position low word at `0xFFFFFFFC` and high word at `2`, the following increment stores low word zero and high word `3`, even if that call returned an error.
- **Secondary allocation failure:** If secondary allocation returns zero, store zero in its pointer slot, skip the external transfer, and still perform eligible list insertion. This failure alone does not change the result from zero.
- **High-water boundary:** With high-water `10`, index `11`, and storage-mode byte zero, first store `11`. If F-870c4fcf7295 returns `11`, then store `12`; otherwise retain `11`.
