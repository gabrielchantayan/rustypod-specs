# F-e9a8d36566ae

## Purpose

F-e9a8d36566ae selects a node by its zero-based position in a singly linked chain and returns two addresses within that node through caller-provided output storage.

On success, the first output receives the address 20 bytes beyond the selected node’s base, and the second receives the address 16 bytes beyond that base. The function returns addresses, not the contents at those addresses.

If traversal encounters a null node before selecting the requested position, the function returns the 32-bit status pattern `0xFFFFFF85` and does not write either output.

This is a static behavioral contract. Field meanings, allocation boundaries, ownership conventions, and the larger application purpose are not established.

## Interface

The interface has four inputs and one 32-bit return value:

| Input | Role |
|---|---|
| Context address | Identifies storage containing the initial chain pointer at byte offset 12. |
| Requested position | A signed integer used in an equality comparison with a traversal counter that starts at zero. |
| First output address | Identifies a four-byte destination for the selected node’s address plus 20 bytes. |
| Second output address | Identifies a four-byte destination for the selected node’s address plus 16 bytes. |

The recovered interface uses four-byte output words and an integer traversal counter. Its address-bearing values are represented in this 32-bit interface. Porting the behavior to a wider-address environment requires an explicit representation decision; simply widening output stores would change the observed interface.

The return values are:

| Result | Return value |
|---|---|
| A non-null node is selected | `0x00000000` |
| A null node is encountered before selection | `0xFFFFFF85` |

Interpreted as a signed 32-bit integer, `0xFFFFFF85` is −123. No symbolic error name or external error convention is established.

### Storage layout used by this function

The function uses only these locations:

| Object | Byte offset | Use |
|---|---:|---|
| Context | 12 | Read the initial node address. |
| Each traversed node | 0 | Read the next-node address when advancing. |
| Selected node | 16 | Form this address for the second output; do not read its contents. |
| Selected node | 20 | Form this address for the first output; do not read its contents. |

The offsets do not establish the full size or type of either object. In particular, returning an interior address does not establish the extent, validity, or meaning of storage available through that address.

### Preconditions

For ordinary successful execution:

- The context address must permit reading its pointer field at byte offset 12.
- Every link field actually traversed must be readable and contain an address usable for the next iteration, or null.
- Both output destinations must permit four-byte stores.
- The address calculations and traversal-counter arithmetic must remain valid under the execution environment’s rules.

There are no explicit checks for these conditions. The output destinations need not be accessed on the null-chain failure path.

## Behavior

### Initial read

The function first reads the initial node address from the context at byte offset 12. It initializes its traversal position to zero.

This context-field read occurs even when the requested position is negative. There is no early rejection of a negative position.

### Selection and traversal

At each position, the function checks whether the current node is null **before** comparing the traversal position with the requested position.

Consequently:

- A null initial node fails even for requested position zero.
- A null pointer reached at exactly the requested position is not a selectable element.
- Success always requires a non-null current node.

If the current node is non-null and the traversal position equals the requested position, traversal stops successfully.

Otherwise, the function reads the next-node address from byte offset zero of the current node, then increments the traversal counter by one. It repeats the null check and position comparison using that next node and the incremented counter.

For a nonnegative requested position \(k\), provided traversal reaches a non-null node at that position without arithmetic or memory-access problems:

- The context’s initial-node field is read once.
- Exactly \(k\) next-link reads occur.
- No next-link read is performed on the selected node.
- Selection does not require the selected node to have a non-null successor.

The traversal has no cycle detection and no explicit length limit.

### Successful output writes

After selection, two four-byte stores occur in this order:

1. The first output destination receives the selected node’s address plus 20 bytes.
2. The second output destination receives the selected node’s address plus 16 bytes.

The function then returns zero.

Neither target location inside the selected node is dereferenced. In particular, this function does not fetch, copy, validate, or modify the values at offsets 16 or 20 merely by returning their addresses.

Both output addresses are derived from the already-selected node. The function does not reread the context’s head field or traverse another link between the output stores.

### Failure

If the current node is null at an iteration’s null check, the function returns `0xFFFFFF85` immediately.

On this ordinary failure path:

- Neither output destination is written.
- Existing contents of both output destinations remain unchanged by this function.
- Any context or link reads required to reach that null pointer have already occurred.

Invalid memory accesses and arithmetic outside the supported model are not converted into this status by any visible handling.

### Negative positions and counter limits

The requested position is tested for equality; it is not range-checked.

For a negative requested position, a finite chain that reaches null while the counter remains representable produces the ordinary null-chain failure. A nonnegative counter cannot select a negative position before an arithmetic boundary is crossed.

Behavior after signed counter overflow is not established. The contract therefore does not promise wraparound, eventual selection of a negative position, or any particular outcome for traversals requiring such overflow.

## Side effects

The only explicit memory writes are the two successful output stores. There are no visible allocations, deallocations, external calls, global accesses, or direct writes to chain links.

Caller-supplied aliasing can nevertheless make those output stores modify the context or a node. For example, an output destination could identify a link field. The function does not prohibit or detect that arrangement.

Important aliasing consequences include:

- If both output destinations identify exactly the same four-byte storage, the second store replaces the first. After normal completion, that storage contains the selected node’s address plus 16 bytes.
- If an output destination overlaps the context’s head field, selection still uses the head value read before either output store.
- If an output destination overlaps a node’s link field, the store can change the chain after traversal has selected its node.

Partially overlapping destinations depend on byte order and permitted access alignment. The established behavior is the order of the two four-byte stores; a portable final byte pattern for arbitrary overlap is not established.

No rollback is visible. If the first store succeeds but the second store faults, the first store may already have changed memory. Such a fault is not an ordinary returned failure.

The function returns addresses into existing storage rather than making independent copies. It performs no visible ownership transfer or lifetime extension. The lifetime of the selected node and the caller’s permission to use the returned addresses remain external obligations.

## Dependencies

No called-function dependencies are visible. F-e9a8d36566ae performs traversal and output stores directly.

Its behavior depends on caller-provided memory and the execution environment’s address, alignment, arithmetic, and fault semantics. No external component’s ownership behavior or preservation of global state is assumed.

## Acceptance examples

These examples are conditional static expectations, not reports of executed tests. Unless stated otherwise, memory accesses are valid, address calculations are representable, output destinations are separate, and no concurrent mutation occurs.

### Selecting the initial node

Given a context whose initial-node field contains a non-null address \(A\), requesting position zero:

- Returns zero.
- Stores \(A + 20\) in the first output.
- Stores \(A + 16\) in the second output.
- Does not read the next-link field at \(A\).

The contents at \(A + 16\) and \(A + 20\) do not affect selection or the returned values.

### Selecting a later node

Given a chain with initial node \(A\), whose next link is \(B\), whose next link is \(C\), requesting position two:

- Reads the next link from \(A\), then from \(B\).
- Selects non-null \(C\).
- Stores \(C + 20\), then \(C + 16\).
- Returns zero without reading \(C\)’s next link.

### Empty chain

Given a null initial-node field, requesting position zero returns `0xFFFFFF85`. Both output destinations retain their previous contents.

### Request immediately beyond the chain

Given a single non-null node whose next link is null, requesting position one reads that link and returns `0xFFFFFF85`. It does not return addresses derived from null and does not write either output.

### Negative request on a short finite chain

Given a short finite chain and requested position −1, traversal proceeds until null and returns `0xFFFFFF85`, provided the counter does not overflow. There is no immediate invalid-position return.

### Shared output destination

Given a successful selection at address \(A\), if both outputs identify the same valid four-byte destination, normal completion leaves \(A + 16\) there because the second store occurs last.

### Cyclic chain

Given a cycle and a reachable nonnegative requested position, selection is based on traversal count, not node uniqueness. A node may be revisited and later selected. No repeated-node error is produced.
