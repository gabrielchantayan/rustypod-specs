# F-114a141c8f07

## Purpose

No application-level purpose is established. The available evidence does not identify an initializer, allocator, serializer, device interface, or conventional buffer operation. Calculated destinations include absolute addresses in a low address range; the repeated address displacements do not establish an object layout.

**Evidence boundary:** the supplied static representation reports invalid instruction data and removal of regions considered unreachable. This contract describes the represented path conditionally, not a proven reconstruction of complete executable behavior.

### First byte-derived destination

A recurring byte destination is formed by loading one byte from address \(byte\text{-}table\ index + 1\), zero-extending it, and adding 17. The resulting destination is between 17 and 272 inclusive.

This is a byte-derived absolute address, not a pointer-sized table entry. **Each occurrence performs a fresh source-byte load.** Earlier loaded bytes and destinations cannot be reused as established equivalents.

The ordered operations are:

1. Load the source byte and write the low byte of the first byte-source word shifted left by two to the resulting destination.

2. Execute seven-call family **F-D11**:
   - The first call receives the first byte-source word shifted left by two in all three displayed argument positions.
   - The second produces a four-byte result.
   - The third receives that result.
   - Four further calls have no displayed explicit arguments.
   - The seventh result becomes the **ninth selector**.

3. Reload the source byte. At the resulting destination, write the low byte of the first byte-source word masked with `0x3fffffff` and logically shifted right by 20.

4. Invoke **F-D12**, first passing the ninth selector shifted left by two. Its fifth result becomes the **second byte-source word**.

5. Form the **retained shifted word** as the second byte-source word shifted left by two. Write its low byte directly to address \(28 + (incoming\ word \mathbin{\text{logical-right-shift}} 23)\).

6. Reload the first recurring source byte and write zero at the derived destination. No represented dependency call separates this operation from the preceding direct byte write.

7. Execute seven-call family **F-D13**:
   - The first receives the incoming word logically shifted right by 23.
   - The second has no displayed explicit arguments.
   - The third receives the second byte-source word masked with `0x3fffffff` and logically shifted right by six.
   - Four further calls have no displayed explicit arguments.
   - The seventh result becomes the **tenth selector**.

8. Reload the first recurring source byte and write zero at the derived destination.

9. Invoke **F-D14**, first passing the tenth selector shifted left by two. Mask its fifth result with `0x3fffffff`, then logically shift right by 25. The resulting **initial loop field** is between zero and 31 inclusive.

If a byte write aliases a subsequent byte-load source, the subsequent load observes memory after that write, subject to the execution environment. This matters even when no dependency call intervenes.

### Nonterminating loop and target transition

Each iteration performs these operations in order:

1. Execute five-call family **F-D16**. Its first call receives the current loop-carried word and the current loop field logically shifted right by eight. Retain the fifth result.

2. Reload a byte from the second recurring source address. Write zero at the destination obtained by adding 17 to that byte.

3. Execute five-call family **F-D17**, first passing the retained F-D16 result shifted left by two.

4. Replace the loop-carried word with F-D17’s fifth result shifted left by two.

5. Replace the loop field with that same result shifted left by 26.

There is no represented exit condition.

**F-D16.1 does not have one fixed target across initial entry and later iterations:**

| Invocation | Represented target expression | Target value |
|---|---|---|
| First iteration | `0x08832789 + 0x00000ffe` | `0x08833787` |
| Second and subsequent iterations | `0x088327c7 + 0x00000ffe` | `0x088337c5` |

The initial base is the one assigned immediately before F-D15.2. The later base is assigned immediately before F-D17.5 and carried through the back edge to F-D16.1. The subsequent loop-body assignments restore that later base before each further back edge.

These are different represented target expressions and values. Neither the shared call-site ID nor the repeated argument pattern establishes identical implementations, equivalent effects, or equal results. A model that dispatches every F-D16.1 invocation to the initial target loses represented behavior.

On the first iteration, F-D16.1’s second explicit argument is zero because the initial loop field is at most 31. Thereafter, the loop-field replacement places the low six bits of the latest F-D17 result in bits 26–31. Its following logical right shift by eight produces an argument whose low 18 bits are clear.

## Acceptance examples

These are conditional arithmetic and ordering examples, not executed tests. Unless stated otherwise, they assume accesses succeed and dependencies return.

### Initial write

For explicit input 3, the first represented observable operation writes four bytes representing 3 at address 32, before the first dependency call.

For input zero, that write targets address 20. No zero-input rejection is represented.

### Repeated word destination

If the seventh selector is 2, phase 9 writes 8 at address 52. After F-D09 returns, phase 10 writes 32 at address 52.

The value remains 32 only if that write succeeds and no later operation changes the location.

### Fresh byte load

If one first-recurring source-byte load yields 5, its store targets address 22. If an intervening dependency changes that source byte to 9, the next corresponding store targets address 26. Caching address 22 would not preserve this behavior.

### Byte truncation

For first byte-source word `0x00000123`, shifting left by two produces low byte `0x8c`; the first indirect byte store writes `0x8c`.

For first byte-source word `0x3ff00000`, masking and shifting right by 20 produces `0x3ff`; the subsequent byte store writes only `0xff`.

### Direct byte address

For incoming word `0xffffffff`, its logical right shift by 23 is 511. The direct byte store therefore targets address 539.

### Initial and subsequent loop dispatch

Suppose execution completes loop setup and one full iteration. The first F-D16.1 invocation uses represented target `0x08833787`. The next uses `0x088337c5`. If further iterations complete, they continue using the latter represented target.

Even if the supplied arguments happen to be equal on two iterations, the first and later invocations cannot be treated as calls to one fixed dependency destination.

### Loop fields

An initial loop field of 31 gives F-D15.1 an argument of 62 and the first F-D16.1 a second argument of zero.

If F-D17.5 returns `0x0000003f`, the next loop-carried word is `0x000000fc`, and the next loop field is `0xfc000000`. The next F-D16.1 receives second argument `0x00fc0000` and uses the subsequent-iteration target.

### Interrupted execution
