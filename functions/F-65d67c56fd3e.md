## Behavior

### Primary-key decision

If that first comparison does not establish a smaller first primary key, a second primary-key comparison determines whether the first primary key is less than or equal to the second.

For stable contents:

- Equal primary keys lead to secondary-key comparison.
- A larger first primary key leads to `0x00000001`, without accessing either secondary key.

The representation contains two primary comparison expressions. It does not establish that the implementation takes and retains a single snapshot of each primary field.

### Secondary-key decision

The first secondary decision asks whether the second record’s unsigned secondary key is smaller than the first record’s unsigned secondary key. If so, the function immediately returns `0xFFFFFFFF`.

Otherwise, a further comparison asks whether the second secondary key is less than or equal to the first secondary key.

- A larger first secondary key produces `0xFFFFFFFF`.
- Equal secondary keys produce `0x00000000`.
- A smaller first secondary key produces `0x00000001`.

This direction is the reverse of the primary-key direction. Both fields use unsigned comparisons; descending secondary order does not imply signed interpretation.
