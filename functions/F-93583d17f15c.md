# F-93583d17f15c

## Purpose

F-93583d17f15c performs a forward copy of a count-prefixed sequence of unsigned 16-bit elements. The first source element supplies the number of subsequent elements to copy. The prefix itself is also copied.

For a stable source whose initial prefix is \(N\), the destination receives \(N+1\) elements: the prefix followed by \(N\) payload elements. A zero prefix therefore requests one element transfer, not an empty transfer.

Either pointer being null causes an immediate return without accessing the referenced storage.

This is a description of the supplied static representation. Interpreting the data as a count-prefixed record is inferred intent; the established behavior is an element-by-element copy controlled by the initial source value.

## Interface

**Inputs**

- A source pointer to unsigned 16-bit elements.
- A destination pointer to unsigned 16-bit elements.

The pointers identify caller-provided storage. There is no separate length, capacity, allocation, or error-output argument.

**Output**

The function returns no value. Its normal output is the sequence of destination writes.

**Represented widths and arithmetic**

The supplied representation uses:

- Unsigned 16-bit source and destination elements, with values from 0 through 65,535.
- An unsigned 32-bit working count.
- A signed 32-bit interpretation of that count for the termination decision.

These widths describe the represented operation. Independent confirmation of the original target’s type definitions and machine instructions is unavailable.

The initial count is obtained by widening the first source element without sign extension. Consequently, values with the element’s high bit set remain positive counts; a prefix of 65,535 does not mean −1.

**Storage preconditions for successful completion**

When both pointers are nonnull:

- The first source element must be readable.
- The destination must support the initial element write.
- For an initial count \(N\), the source and destination ranges must each support access to \(N+1\) consecutive elements.
- Pointer advancement through those ranges, including formation of the position immediately after the final transferred element, must be valid under the execution environment’s pointer rules.
- Any alignment requirements for 16-bit element accesses must be satisfied.

The required extent is \(2(N+1)\) bytes under the represented 16-bit layout. Its maximum is 131,072 bytes per range. This calculation is descriptive; the function does not calculate or validate a byte capacity.

## Behavior

### Null handling

The function first checks whether either pointer is null. If so, it returns before reading a count or writing an element.

This includes both pointers being null. A nonnull pointer supplied alongside a null pointer is not dereferenced by this function.

Null handling is not general pointer validation. A nonnull but inaccessible or insufficiently sized address does not take the early-return path.

### Count capture and prefix transfer

With two nonnull pointers, the function first reads the initial source element and retains its value as the working count.

It then transfers the initial source element to the initial destination position. The supplied representation contains a source read for count capture and a separate source read for this transfer. It does not express a transfer from the retained count.

For ordinary stable storage, the two reads produce the same value. If the source can change between them, the captured count and the value written as the destination prefix need not match. Exact machine-level read multiplicity is not established by this static representation.

The captured count is not subsequently reloaded from the source or destination prefix. Later overwrites of either prefix do not revise the selected transfer count.

### Payload transfer

After the prefix write, processing advances toward increasing element addresses. Each payload transfer reads the current source element and writes that value to the corresponding destination position.

Transfers are sequential, not described as a snapshot of the source range. Each later read therefore observes storage after earlier destination writes, subject to the execution environment’s ordinary memory semantics.

The count is decremented before each continuation decision. Source and destination positions are also advanced before that decision. If the decremented count has a negative signed 32-bit interpretation, processing stops without transferring at those newly advanced positions.

For an initial count \(N\):

- Exactly \(N\) payload transfers follow the prefix transfer, assuming all accesses complete.
- The last transferred element has offset \(N\) from each original pointer.
- The internal positions finish at offset \(N+1\).
- No element is read or written at that final offset.

The final pointer positions are local state; they are not returned or written back to the caller.

### Termination arithmetic

For a positive working count, decrementing produces another nonnegative value until zero is reached. A decrement from zero wraps the unsigned 32-bit count to 4,294,967,295. Its signed 32-bit interpretation is −1, so processing stops.

Thus:

- An initial count of zero stops after the prefix transfer.
- An initial count of one permits one payload transfer.
- An initial count of 65,535 permits 65,535 payload transfers.

The initially widened 16-bit count cannot begin in the negative signed 32-bit range. The terminating wrap does not select a huge additional copy.

### Overlapping ranges

The function does not inspect overlap and does not choose a direction based on the relative addresses.

If source and destination are identical, each transfer reads and writes the same element. With stable ordinary storage, values remain unchanged, but the represented accesses still occur.

If the destination begins inside the source range at a higher address, earlier writes can overwrite source elements before later reads reach them. The resulting destination need not equal the source’s original contents.

If the destination begins at a lower address in a valid overlapping region, forward traversal can preserve the original sequence because writes occur behind subsequent source reads. This observation does not establish a general overlap-safe copying interface.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

1. **Either pointer is null.**  
   Given a null source or a null destination, the function returns without reading or writing the pointed-to storage. In particular, the other pointer need not be dereferenceable for this path.

2. **Zero payload count.**  
   Given disjoint valid ranges and a source beginning with `[0, 91]`, the first destination element becomes `0`. The second destination element remains unchanged. The source element containing `91` is not transferred.

3. **Ordinary count-prefixed copy.**  
   Given a stable source `[3, 100, 200, 300, 400]` and a sufficiently large disjoint destination, the first four destination elements become `[3, 100, 200, 300]`. The fifth destination element remains unchanged.

4. **High-bit count remains unsigned.**  
   Given an initial source element of 32,768 and sufficiently large valid ranges, the function transfers 32,769 elements in total. It does not interpret the prefix as a negative 16-bit count.

5. **Maximum represented count.**  
   Given a prefix of 65,535 and valid ranges of 65,536 elements, all 65,536 elements are transferred. No element at offset 65,536 is accessed.

6. **Identical pointers.**  
   Given a valid stable sequence `[2, 10, 20]` and identical source and destination pointers, the sequence remains `[2, 10, 20]` after completion. This outcome does not mean that the function skipped its reads or writes.

7. **Destination one element ahead.**  
   Given one ordinary array initially containing `[2, 10, 20, 30]`, with the source at its first element and destination at its second, the resulting array is `[2, 2, 2, 2]`. Each write replaces the next source value before that value is read. Only three elements are transferred because the original count was captured first.

8. **Destination one element behind.**  
   Given one ordinary array initially containing `[99, 2, 10, 20]`, with the source at its second element and destination at its first, the resulting array is `[2, 10, 20, 20]`.

9. **Insufficient capacity.**  
   A nonnull destination too small for the selected extent is outside the successful-completion preconditions. Acceptance must not require a clean rejection, unchanged destination, or reported error.
