# F-9d6f952b7302

## Purpose

For an accepted index, it exposes the address of a local two-byte field to F-f376023180bc. If that call returns normally, it reads the field and invokes F-b287fa5e8a41 with the resulting value and the address of adjacent local storage. For a rejected index, it invokes F-438680ffebfe with a fixed embedded reference.

These are argument-passing and sequencing guarantees. The function does not establish that any dependency produces output, initializes storage, retrieves data, or reports an error. Those interpretations remain inferred intent, not contractual behavior.

## Behavior

### Signed-index gate

The function first interprets the index’s 32-bit pattern as a signed 32-bit integer and checks whether it is greater than `-1`.

- `0x00000000` through `0x7FFFFFFF` pass.
- `0x80000000` through `0xFFFFFFFF` fail.

Failure immediately selects the rejection path. The context field and bound are not directly read on that path.

This condition is independent of the upper bound. Even an unsigned bound of `0xFFFFFFFF` cannot admit an index whose high bit is set.

### Unsigned upper-bound check

If the signed gate passes, the function obtains the nested-object address from context offset `0x40`, then reads the unsigned 32-bit bound at nested-object offset `0xE78`.

The index is accepted only if it is strictly less than the bound under an unsigned 32-bit comparison. Equality rejects.

Consequences include:

- A zero bound admits no index.
- A bound of one admits only index zero.
- A bound of `0x80000000` admits every index that passes the signed gate.
- Any larger unsigned bound also admits every index that passes that gate.

There is no index increment, decrement, multiplication, or scaling in this selection rule. The bound is not reduced before comparison.

### Accepted-index sequence

If both checks pass, the established sequence is:

1. Obtain the nested-object argument through the context’s `0x40` field.
2. Invoke F-f376023180bc with that value, the original 32-bit index, and the address of the local two-byte field.
3. If the dependency returns normally, read the two-byte field.
4. Invoke F-b287fa5e8a41 with the original forwarded argument, the address of the adjacent 510-byte array, and the value obtained from the field.
5. Return if the second dependency returns normally.

The context-field expression appears both in the bound access and in preparation for F-f376023180bc. The source does not explicitly save a shared snapshot for both uses. The contract therefore does not require those uses to observe one immutable nested-object value. Exact machine-load behavior and concurrent-mutation semantics remain unresolved.

The function does not inspect a result from F-f376023180bc or branch on a success indication. It performs no visible validation between that call and F-b287fa5e8a41.

In particular, it does not establish or check that:

- The two-byte field was initialized.
- Any part of the adjacent array was initialized.
- The two-byte value is no greater than 510.
- The array contains a terminator.
- The array contents satisfy an encoding or format.
- The nested object or other state remained unchanged during the first call.

There is no second range check after F-f376023180bc returns.

### Rejected-index sequence

If either range condition fails, the function invokes F-438680ffebfe with:

1. The original forwarded argument.
2. A fixed embedded reference.

It then returns if that dependency returns normally.

Neither accepted-path dependency is invoked on this branch. The embedded reference’s contents, extent, type, mutability, and semantic meaning are not supplied. Rejection must not be specified as producing a particular message or returning an error code.
