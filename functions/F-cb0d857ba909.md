# F-cb0d857ba909

## Purpose

The established behavior is address selection, not retrieval or interpretation of the contents at that address. The supplied representation does not establish whether the selected data represents numbers, characters, descriptors, or another format.

This contract uses **B** as an abstract name for the address selected by `0x00006F81`. B is a descriptive reference point, not an additional parameter, a global variable name, or a requirement that the implementation expose a base-address symbol. Other selected addresses are specified as byte offsets from B so that their relationships can be stated without exposing private location identifiers.

## Behavior

### Selection rule

For a recognized input, the selected address advances by four bytes for each increment of one in the input.

The complete mapping can be expressed as:

**Selected address = B + 4 × (input − `0x00006F81`) bytes**, when the input is within the inclusive recognized interval.

For every other input:

**Selected address = B + 156 bytes.**

This describes the result relation. It does not require an implementation to perform subtraction, multiplication, range checking, or pointer arithmetic at runtime.

The recognized-input offsets range from 0 through 152 bytes, inclusive, in four-byte steps. The fallback location is four bytes beyond the location selected by the largest recognized input.

| Input or input class | Returned address |
|---|---|
| `0x00006F81` | B |
| `0x00006F82` | B + 4 bytes |

There are consequently 40 distinct represented return addresses: 39 recognized selections and one fallback selection.

### Full-width matching

Recognition applies to the complete 32-bit input value. There is no represented masking, normalization, modulo reduction, or reinterpretation of a low-order subfield.

For example, `0x00006F81` is recognized, but `0x00016F81` is not. Their low-order 16 bits agree, but the latter does not equal any recognized 32-bit value.

The same rule applies to inputs with the high bit set. They select the fallback, regardless of whether an external interface describes those bit patterns as negative integers or large unsigned integers.

### Arithmetic boundaries

The mathematical difference between a recognized input and the minimum recognized input is between 0 and 38. Multiplication by four therefore produces an offset between 0 and 152. Those quantities fit within 32-bit arithmetic without overflow.

The fallback offset is 156 bytes. It is a fixed result, not an extrapolation rule for unrecognized inputs.

In particular, the input immediately below the recognized interval does not select an address four bytes before B. Inputs above the interval do not continue to select successively higher addresses. All such inputs select the same fallback location.

### Address identity and layout

Different recognized inputs select distinct addresses. No recognized input selects the fallback address. Two unrecognized inputs select the same address even when their numeric values differ substantially.

The four-byte spacing establishes address relationships only. It does not establish that:

- Each target is an object of exactly four bytes.
