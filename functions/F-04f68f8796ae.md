# F-04f68f8796ae

## Purpose

F-04f68f8796ae describes a context-dependent routine that performs ordered indirect calls, memory reads and writes, and arithmetic before selecting between two continuations using a represented overflow condition.

The overflow-selected continuation includes additional memory accesses, software interrupt `0x73`, a condition-controlled loop, and breakpoint `0xc9`. Its recovered control flow ends at invalid or unrecovered instruction data. The other continuation ends in an unrecovered indirect transfer.

No application-level purpose, ordinary success condition, or reliable normal-return contract is established. Terms such as “record,” “lookup,” and “base” describe access relationships, not verified object types or allocation boundaries.

This contract distinguishes represented behavior from unresolved machine-level semantics. No runtime tests have been performed.

### Outputs and completion

No ordinary return value is established. Observable effects include:

- Ordered dependency invocations.
- Reads and writes with 8-, 16-, and 32-bit widths.
- Interrupt `0x73` and breakpoint `0xc9`.
- Potentially unbounded repetition.
- An unresolved final indirect transfer.

The non-overflow continuation is represented as a final call followed by return. Because the underlying transfer was not recovered, neither ordinary returning-call behavior nor an actual return to the caller is guaranteed.

### Representation and preconditions

All offsets below are bytes. A word is 32 bits; a halfword is 16 bits. Pointer stores are represented as 32 bits, without independently establishing the full machine address model.

For execution to continue through a particular access or invocation, the address actually used must be usable in the execution environment. No explicit null, bounds, alignment, permission, or allocation checks are shown. This operational requirement does not establish who supplies any address, particularly F-D088’s unresolved target.

The following descriptive state is used:

- **Working base:** zero-extended first halfword load.
- **Secondary index:** zero-extended second halfword load.
- **Linked address:** subsequent 32-bit address-like load.
- **Derived base:** initially a halfword loaded through the linked address, later replaced by another halfword.
- **Lookup base:** a captured global 32-bit value on the overflow continuation.

Represented unsigned 32-bit additions wrap modulo \(2^{32}\). This applies where a working base, secondary index, or derived base makes the addition unsigned. Signed-only additions and signed subtraction do not establish portable overflow behavior. Address usability remains separate from arithmetic representation.

## Behavior

### Initial calls and writes

Execution begins by invoking F-D001 at the incoming link plus `0xf20`.

The following actions occur in order:

1. Store the self-reference base as 32 bits at that base plus `0x14`.
2. Invoke F-D002.
3. Read an unsigned halfword at the primary value plus F-D002’s secondary output. Preserve that halfword and zero-extend it into the working base.
4. Invoke F-D003; store the record address at working base plus `0x34`.
5. Invoke F-D004; store its 32-bit result at record offset `0x64`.
6. Invoke F-D005; store the preserved word at working base plus `0x64`.
7. Invoke F-D006; store the working base at working base plus `0x34`.
8. Invoke F-D007.
9. Store F-D007’s secondary 32-bit output, the primary value, and the preserved word at record offsets `0`, `4`, and `8`, respectively.

The two writes to working base plus `0x34` are distinct observable events. The earlier record address cannot be discarded merely because a later write replaces it.

### Additional address acquisition

Invoke F-D008, F-D009, and F-D010 in order.

Read an unsigned halfword at the primary value plus F-D010’s secondary output; zero-extend it into the secondary index. Invoke F-D011, then read the linked address as 32 bits at the primary value plus F-D011’s secondary output.

Continue with these call/store pairs:

| Invocation | Following 32-bit store |
|---|---|
| F-D012 | Primary value at working base plus `0x24` |
| F-D013 | Secondary index at working base plus `0x34` |
| F-D014 | Working base at working base plus `0x34` |
| F-D015 | Linked address at working base plus `0x14` |
| F-D016 | Secondary index at working base plus `0x44` |

Invoke F-D017. Read an unsigned halfword at linked address plus `0x0c`; zero-extend it into the derived base.

Values originating as halfwords are nevertheless written as full 32-bit values in the table above.

### Byte production and signed argument reads

Invoke F-D018 with the two 32-bit words at pair-source offsets `0` and `4`. The relative evaluation order of those two argument reads is not established.

Then:

1. Invoke F-D019 and store its 8-bit result at primary value plus secondary index.
2. Invoke F-D020.
3. Invoke F-D021 with F-D020’s 32-bit result and a fresh character-sized read from primary value plus secondary index, represented as a signed-byte argument extended to 32 bits.
4. Store the current derived base as 32 bits at working base plus `4`.
5. Invoke F-D022.
6. Invoke F-D023 with F-D022’s 32-bit result and a fresh signed-halfword read from working base plus secondary index, sign-extended to 32 bits.
7. Invoke F-D024 with a separate signed-halfword read from the same address, also sign-extended.
8. Replace the derived base with a zero-extended unsigned halfword read at its previous value plus `4`.

Intervening calls may change memory. Neither the byte read nor either signed-halfword read may be replaced by an earlier value without additional evidence.

The represented overflow condition now selects the continuation. No validation predicate or dependency-result comparison is shown.

### Overflow-selected continuation

When the overflow condition is nonzero:

| Order | Action |
|---|---|

| 2 | Invoke F-D025; store its secondary output’s low 16 bits at that output plus `0x0c`. |
| 3 | Invoke F-D026; store the original working-base halfword at its secondary output plus `0x1c`. |
| 4 | Invoke F-D027; store the low 16 bits of the address twelve bytes beyond the pair source at its secondary output plus `0x24`. |
| 5 | Invoke F-D028; store the primary value as 32 bits at derived base plus its secondary output. |
| 6 | Invoke F-D029, then F-D030. |
| 7 | Invoke F-D031 with F-D030’s 32-bit result and a fresh sign-extended halfword from working base plus secondary index. |
| 8 | Invoke F-D032, obtaining a represented 64-bit result. |

Split F-D032’s result into low and high 32-bit halves. Store the derived base’s low 16 bits at the address represented by the high half plus `4`.

Issue software interrupt `0x73`. If execution resumes on this continuation:

1. Invoke F-D033 with the low half and an 8-bit value read at low-half address plus `6`. Its result supplies an address.
2. Invoke F-D034 with an 8-bit value read at that address plus `2`.
3. Invoke F-D035.
4. Invoke F-D036 with an 8-bit value read at F-D035’s secondary output plus `0x16`.
5. Capture the global 32-bit lookup base.
6. Invoke F-D037; store the low 8 bits of the address twelve bytes beyond the pair source at derived base plus its secondary output.
7. Invoke F-D038; read an unsigned byte at lookup base plus its secondary output.
8. Invoke F-D039, F-D040, and F-D041.
9. Read an unsigned halfword at lookup base plus the previously read byte.
10. Invoke F-D042.
11. Read an unsigned byte at lookup base plus that halfword. Zero-extend it into a new destination base.

The raw 8-bit arguments to F-D033, F-D034, and F-D036 do not establish a signed-extension convention. The captured lookup base is not automatically reloaded after subsequent calls.

### Loop state and exit

The loop retains two separate scalars:

- An address-valued scalar initially containing the captured lookup base.
- A dispatch base set to `0x0870e6f9` before F-D043.

Every loop-condition evaluation first captures the address-valued scalar’s low 8 bits. The loop continues while the represented zero condition is clear.

Each iteration:

1. Replaces the address-valued scalar with `0x0870e660`.
2. Establishes a separate target base of `0x0870e3d5`.
3. Invokes F-D044 at the current dispatch base plus `0xf44`.
4. Replaces the dispatch base with `0x0870e3d7`.
5. Invokes F-D045 at the separate target base plus `0xbfe`.

Thus F-D044 targets `0x0870f63d` on its first iteration and `0x0870f31b` on subsequent iterations. F-D045 targets `0x0870efd3` on every iteration. The dispatch-base replacement occurs after F-D044, not before it.

No explicit update of the zero condition is represented. If it remains clear, repetition is unbounded. Any actual exit after entering the loop depends on unresolved condition behavior.

On exit, the address-valued scalar is replaced with `0x0870e3db`, and F-D046 uses the retained dispatch base plus `0x7fe`:

- Loop bypassed: `0x0870eef7`.
- At least one iteration followed by exit: `0x0870ebd5`.

Replacing the address-valued scalar does not change the already captured byte.

After F-D046:

1. Invoke F-D047, F-D048, and F-D049.
2. Store the captured byte at destination base plus `0x0d`.
3. Invoke F-D050; store the same byte at destination base plus `9`.
4. Invoke F-D051; store the lookup halfword’s low 8 bits at destination base plus `0x11`.
5. Invoke F-D052.
6. Issue breakpoint `0xc9`.

With loop bypass, the captured byte is the lookup base’s low byte. Following one or more iterations and a later exit, it is `0x60`.

Recovered control flow ends at bad instruction data after the breakpoint. Neither return nor fallthrough into the non-overflow continuation is established.

### Non-overflow continuation

When the overflow condition is zero:

1. Invoke F-D053 with `0x2c`, then F-D054.
2. Capture a global 32-bit word.
3. Invoke F-D055; store that captured word at derived base plus secondary index.
4. Invoke F-D056; store the derived base as 32 bits at derived base plus its secondary output.
5. Invoke F-D057 and F-D058.
6. Invoke F-D059 with `0x52`, obtaining a represented 64-bit result.
7. Invoke F-D060 with that result’s low 32 bits, high 32 bits, and `0x29` minus the low half interpreted as signed 32 bits.
8. Invoke F-D061, obtaining another represented 64-bit result.
9. Invoke F-D062 with its low half, high half, and the secondary index.
10. Invoke F-D063.
11. Capture another global 32-bit address-like value.
12. Invoke F-D064; store the captured value at its own address plus secondary index.
13. Invoke F-D065.
14. Invoke F-D066 with F-D065’s 32-bit result and `0x26`.

F-D060’s subtraction is neither widened nor saturated in the representation. Signed-overflow behavior remains unresolved.

### Final non-overflow calls

Shift the signed primary value right by 16. Invoke F-D067, F-D068, and F-D069.

Then:

1. Invoke F-D070 with the already shifted primary value shifted right by another 20.
2. Invoke F-D071.
3. Invoke F-D072 with F-D071’s result and a global 32-bit value read for this call.
4. Invoke F-D073 and F-D074.
5. Invoke F-D075 with F-D074’s result and zero.
6. Invoke F-D076, F-D077, and F-D078.
7. Invoke F-D079 with F-D078’s result and `0x22`.
8. Invoke F-D080 with another global 32-bit value.
9. Invoke F-D081 and F-D082.
10. Invoke F-D083 with `0x25`.
11. Invoke F-D084 with zero, then F-D085 with zero.
12. Invoke F-D086 and F-D087.
13. Reach F-D088, the unrecovered indirect transfer.

The zero arguments at F-D075 and F-D084 derive from successive shifts of a scalar set to `0x52`; F-D085 receives an explicit zero.

The primary shifts are separate 32-bit operations, not one shift by 36. Under arithmetic-right-shift semantics, F-D070 receives zero for an originally nonnegative primary value and negative one for an originally negative value.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Unsigned base:** An initial halfword of `0xffff` produces working base `65535`, not negative one.

2. **Fresh byte argument:** Under the represented signed-byte interpretation, a fresh F-D021 argument load of `0x80` supplies `-128`, independently of F-D019’s earlier result.

3. **Independent halfwords:** If F-D023’s argument read yields `0xffff`, it receives `-1`. If that call changes the same memory to `0x0002`, F-D024 receives `2`.

4. **Intermediate writes:** Removing earlier writes at working base plus `0x34` is not behavior-preserving when an intervening dependency observes them.

5. **Initial target:** Incoming link `0x1000` gives F-D001 target `0x1f20`, conditional on representable addition and a usable target.

6. **Loop bypass:** If the zero condition is set initially, F-D044 and F-D045 are skipped. F-D046 targets `0x0870eef7`; the captured byte is the lookup base’s low byte.

7. **Two iterations:** F-D044 first targets `0x0870f63d`, then `0x0870f31b`. Both F-D045 invocations target `0x0870efd3`.

8. **Later loop exit:** Conditional on an exit after entering the loop, F-D046 targets `0x0870ebd5`, and the captured byte is `0x60`.

9. **Persistent clear condition:** If the zero condition remains clear, no iteration limit is represented. F-D046 and subsequent stores are not reached.

10. **Captured global:** If F-D055 changes the global captured before it, the following store still uses the previously captured word.

11. **Sequential shifts:** Under arithmetic-right-shift semantics, original primary bits `0x80000000` produce F-D070 argument `-1`.

12. **Interrupt diversion:** If interrupt `0x73` does not resume this continuation, F-D033 and later actions do not occur on that execution.

13. **Final-transfer boundary:** Reaching F-D088 establishes an unresolved indirect transfer, not consumption of a caller-supplied target. An acceptance condition requiring such a caller input would add an unsupported obligation.
