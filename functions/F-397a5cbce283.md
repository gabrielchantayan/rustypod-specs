# F-397a5cbce283

## Purpose

The available evidence does not establish an application-level purpose. In particular, it does not establish that the routine implements copying, decoding, dispatch registration, or exception handling as a coherent public operation.

A substantial portion of the supplied representation is guarded by conditions that cannot be satisfied under its ordinary 32-bit arithmetic interpretation. This contract distinguishes those syntactically present operations from behavior reachable under that interpretation. It does not turn unreachable operations into required runtime behavior.

No runtime tests have been performed.

## Behavior

### Interpretation boundary

The following reachable-behavior description uses unsigned, 32-bit, wrapping address arithmetic. A 16-bit pointer increment advances by two bytes. Converting a 16-bit unsigned memory value to an address zero-extends it.

This interpretation is supported by the represented widths and address operations, but it is not a substitute for a verified machine-level execution model. Some unusual stack and processor-state expressions remain documented_only.

### Initial path selection and transfer

The routine first derives a working address by multiplying the input word by 4096 modulo \(2^{32}\).

If that address is nonzero:

- The initial memory transfer is skipped.
- The subsequent conditional arithmetic chains are not entered.
- The initial repeating-call base remains the entry link address.

If the derived address is zero, the routine performs an initial transfer:

1. It derives a destination address by adding the second comparison word to the entry source address.
2. It reads one unsigned 16-bit value from the entry source address.
3. It derives a replacement working source address by subtracting the subtraction word from the destination address.
4. It writes the previously read 16-bit value to the destination address.

The read precedes the write. There is no overlap restriction. If source and destination are equal, the represented operation still includes a read followed by a write; it is not specified to omit the write.

The source-address replacement is a change to working state. The supplied representation does not prove that this change is observable as a preserved register value after execution.

On this path, the routine also derives an auxiliary word from the link address, the extracted bit 18, and half the stack-associated address, rounded down.

Because this path requires the low 20 input bits to be zero, bit 18 is necessarily zero. The auxiliary word therefore reduces to the link address plus the stack-associated address shifted right by one, with 32-bit wrapping.

### Conditional progression after the transfer

Further progression requires the entry link address to be zero.

The following gates then restrict progression:

- The auxiliary word must be zero.
- The first and second comparison words must be equal.
- The subtraction word must equal the replacement working source address.
- The addend word must be zero.
- The stack-associated address plus twice the second comparison word must be zero modulo \(2^{32}\).

The intervening exclusive-or and shift expressions do not introduce arbitrary shift counts on these reachable paths. Each such expression is entered only after the preceding result is zero; its shift count is therefore zero.

Several represented gates repeat an equality already forced by earlier conditions. They do not add memory accesses or new externally supplied data.

Under the stated arithmetic interpretation, the full set of gates implies:

- The link address is zero.
- The stack-associated address is zero.
- The second comparison word is either zero or `0x80000000`.
- The first comparison word equals the second comparison word.
- The subtraction word equals the replacement working source address.
- The addend word is zero.

These are reachability constraints, not a recommendation that callers provide such state. In particular, a zero stack-associated address may be incompatible with a real execution environment.

### Exceptional conditional memory operation

If all the preceding gates succeed, the representation includes an unusual processor-state update and an additional memory operation.

The processor-state update assigns a value derived by multiplying the stack-associated address by 64 to a stack-related machine-state location. The exact architectural meaning of that location is not established.

The additional memory operation:

- Uses the link address as a location containing an unsigned 16-bit value.
- Uses a 16-bit value read there as a zero-extended destination address.
- Writes a 16-bit value formed by adding 15 to a value read from the link address, truncating the result to 16 bits.

The representation contains two reads of the link-address location for this operation: one contributing the destination and one contributing the stored value. It does not establish their relative order or guarantee that they observe identical values.

On the reachable path described above, the link address is zero. Thus this operation requires reading a 16-bit value at address zero. It is not a null-checked operation.

This path also advances one working address by two bytes and replaces the working link-derived address with another computed address. Under the reachability constraints above, that replacement address is zero.

Under the same 32-bit interpretation, it cannot reach the later subtraction and record-writing region:

2. Invoke dependency F-000000000002 at address `0x0857A94B`.
3. Issue software interrupt `0x5B`.
4. If execution resumes, replace the call base with `0x083D4CC2`.

The first dependency receives three represented 32-bit arguments:

The third argument is the unsigned 32-bit pattern `0xFFFFFFA5`; interpreting it as signed would produce −91, but signed interpretation is not established by the call expression.

No explicit arguments are shown for the second dependency. This does not establish that its behavior is independent of registers, memory, or other machine state.

For subsequent iterations, the first dependency’s represented target is `0x083D5B78`.
