# F-d029e3dd0581

## Purpose

F-d029e3dd0581 retrieves a single byte through a two-stage memory lookup. The input identifies a base address. A 32-bit value stored at byte offset `0xF00` from that base supplies a second address. The result is the byte stored at offset `0xB4C` from the second address.

The established behavior is a byte retrieval, not a Boolean conversion, validation operation, or state transition. The supplied evidence does not establish what either memory region represents or what the returned byte means.

**Inferred intent:** the first region may contain a reference to another object, with the returned byte representing one field of that object. This interpretation is not required by the observable lookup and is not an established object model.

## Behavior

1. Form the location `0xF00` bytes beyond the input address.
2. Read the 32-bit integer value at that location.
3. Use that value as the base for a location `0xB4C` bytes farther on.
4. Read one byte at the second location and return that byte.

The second read depends on the value obtained by the first read. There is no independent second base address and no additional dereference between the intermediate address value and the final byte read.

For a fixed input, changing the stored intermediate address can redirect the final read. For a fixed input and intermediate address, changing the final byte can change the return value.

## Acceptance examples

The following examples are conditional behavioral criteria, not runtime observations. Each successful example assumes valid address arithmetic, an appropriate target representation, readable locations, and no interfering mutation.

### Ordinary retrieval

Given an input address of `0x10000000`, suppose the four-byte integer read at `0x10000F00` yields the address value `0x20000000`.

If the byte at `0x20000B4C` is `0x37`, the function returns the one-byte value `0x37`.

This distinguishes the two-stage lookup from reading directly at an offset from the original input.

### Preservation of the full byte pattern

With the same intermediate address:

- A final byte of `0x00` produces `0x00`.
- A final byte of `0x80` produces `0x80`.
- A final byte of `0xFF` produces `0xFF`.

Returning `0x01` for every nonzero byte would not satisfy the contract.

### Redirection through the intermediate value

Suppose the input remains `0x10000000`, but the four-byte value at `0x10000F00` changes to `0x30000000` before a later invocation.

That invocation obtains its result from `0x30000B4C`, assuming stable, valid memory during the lookup. It must not retain the earlier intermediate address as function-local persistent state.

### No direct-result shortcut

Suppose the intermediate read yields `0x20000000`, whose low byte is `0x00`, while the byte at `0x20000B4C` is `0xA6`.

The result is `0xA6`, not `0x00`. The intermediate value is an address carrier, not the returned data.

### Unreadable final location

Suppose the first read succeeds but the final calculated location is unreadable.

There is no established normal return value. Returning zero, retrying, or substituting another location would add behavior not supported by the evidence. The precise failure manifestation is **documented_only**.
