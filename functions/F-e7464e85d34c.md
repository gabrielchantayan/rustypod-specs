# F-e7464e85d34c

## Purpose

F-e7464e85d34c coordinates two temporary descriptors, an optional operation using a selected descriptor and a captured external value, request-dependent output processing, and two writes to a field in a caller-supplied object.

Its established responsibilities are:

- Prepare and populate both descriptors.
- Prefer the first descriptor when its eligibility result is nonzero; check the second only when the first result is zero.
- Initialize a workspace for the selected descriptor and conditionally invoke an operation based on workspace status.
- Invoke a separate operation using the captured external value, whether or not a descriptor was selected.
- Obtain a request-dependent output word and flag, dispatch an indirect method with the output word, and normalize the flag’s first byte into a four-byte object field.
- Finalize temporary descriptors and perform a closing call.

The apparent intent is to choose an available source and apply a request-related result. That interpretation is inferred, not a verified semantic contract for the dependencies. In particular, neither the contents of the shared storage nor the meanings of the output word and object field are established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes normal dependency returns and valid, sufficiently initialized storage for every subsequent access.

### First descriptor takes precedence

Given a nonzero first eligibility result and zero workspace status:

- The second descriptor is prepared and populated but not eligibility-checked.
- Workspace initialization receives the first descriptor.
- F-8737e491f1cd is invoked with `0x20` and the captured value.
- Its 32-bit result becomes the function’s return value.
- Both descriptors are finalized, second before first.

A negative nonzero eligibility result has the same selection effect as a positive nonzero result.

### Second descriptor is the fallback

Given zero from the first eligibility check and nonzero from the second:

- Both checks occur in first-then-second order.
- Workspace initialization receives the second descriptor.
- Workspace status alone determines whether F-8737e491f1cd is invoked.
- No later attempt is made with the first descriptor.

### Neither descriptor is eligible

Given zero from both checks:

- Workspace initialization, status inspection, optional operation, and workspace finalization are absent.
- F-f072fb9711f1 still receives the captured value and `0x20`.
- Output processing, indirect invocation, flag-dependent field update, descriptor finalization, and closing still occur.
- No specific return value is established.

### Selected workspace has nonzero status

Given a selected descriptor and nonzero workspace status:

- F-8737e491f1cd is skipped.
- F-a19c2808de87 still runs.
- F-f072fb9711f1 follows workspace finalization.
- No fallback selection or explicit error return is introduced.
- The return value remains unspecified.

### Flag branch selects a full-width normalized write

If the first flag byte is zero when read after indirect invocation, the final explicit four-byte field write is zero, even if the other three flag bytes are nonzero.

If that first byte is `0x80`, the final explicit four-byte field write is one, not `0x80`.

These cases require the branch to use the post-invocation byte, not a value sampled before the indirect method.

### Capture timing is preserved

If F-438680ffebfe changes Global B before returning, capture uses the value subsequently read from Global B.

If another dependency changes Global B after capture, the caller still passes the captured value to both applicable later call sites. This does not imply that storage referenced by that value remains unchanged.

### Field writes retain their ordering

On ordinary completion, the initial zero write precedes the first eligibility check. The flag-dependent write follows indirect invocation and precedes both descriptor finalizers.

A finalizer may subsequently modify the field; the contract does not equate the last explicit caller write with a guaranteed return-time field value.
