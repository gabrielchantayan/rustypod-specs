# F-26faa6c63a28

## Purpose

F-26faa6c63a28 resolves an input within a context, looks up an associated record, and handles a selector through either a direct field copy or an indirect callback.

The established ordinary outcomes are:

- Return the 32-bit value zero when resolution reports the unresolved sentinel or lookup returns zero.
- Copy a 32-bit record field to the output location and return one when the selector matches a distinguished global value.
- Return a selected callback’s 32-bit result unchanged.

Three checked dispatch failures invoke F-a817d8d58c10, which the supplied static annotation classifies as non-returning.

Resolution uses two addressable slots whose addresses are passed to a dependency. Later uses of these slots are separate observations, not guaranteed snapshots of the values present immediately after resolution. The function does not establish that dependencies preserve those slots or global storage.

The application-level meanings of the selectors, record fields, resolution values, and dispatch entries are unknown.

These names identify storage roles, not domain meanings or immutable values.

## Behavior

### Resolution and lookup

The function first initializes the primary slot to signed 32-bit −1, then initializes the secondary slot to −1. It invokes F-bc41062d83c2 with:

- The context.
- The resolution input.
- The primary-slot address.
- The secondary-slot address.

No return value from this dependency is used.

After resolution returns, the function reads the primary slot and compares its full 32-bit value with −1. Equality causes an immediate return of zero. This path performs no subsequent context-field read, lookup call, associated-record access, or direct output write.

Otherwise, the function invokes F-0ff4e60503e7 with the context field at offset 0x18 and a converted primary-slot value. The primary slot is read again for this argument. Its low 16 bits are interpreted as a signed 16-bit value and sign-extended to the 32-bit argument width.

Consequences of this conversion include:

- 65,535 becomes −1.
- 32,768 becomes −32,768.
- 65,536 becomes zero.
- Higher bits do not survive the conversion.

The full-width sentinel test and the narrowed lookup argument therefore have different meanings. A primary value can pass the sentinel test while supplying −1 to lookup.

The context-field read and primary-slot read are both used to prepare the lookup call; their relative evaluation order is not established. No dependency call intervenes between the sentinel test and preparation of this call, but the evidence does not establish a general concurrency or mutation guarantee equating separate slot reads.

If lookup returns zero, the function returns zero without reading an associated-record address or any record field. Otherwise, it reads a 32-bit associated-record address from lookup-result offset 0x08. That address is not checked for zero.

The obtained record address is retained for subsequent accesses and for the callback argument. The lookup-result field is not visibly reread.

### Direct-result selection

After obtaining the record address, the function reads the distinguished selector from global storage and compares it with the original selector.

On equality, it reads the record’s 32-bit field at offset 0x30, writes that value to the output location, and returns one.

This path does not read the dispatch gate or dispatch value, call the conditional selection helpers, or access the dispatch table. A zero dispatch gate therefore does not block a direct result.

The distinguished global selector is read after resolution and lookup. The contract does not substitute an earlier global value or assume those dependencies preserve that storage.

### Dispatch gate and initial index

When the selector does not match, the function reads the byte at record offset 0x64.

- Zero invokes F-a817d8d58c10.
- Any nonzero byte permits dispatch selection.

The supplied non-returning annotation establishes no ordinary return from the zero-gate path. It does not establish whether the dependency terminates execution, throws, transfers control elsewhere, or uses another mechanism.

After a nonzero gate, the function reads the signed 32-bit dispatch value at record offset 0x60.

If that value is not one, it is used directly as the selected table index. There is no visible nonnegative check, range check, or normalization.

If the value is one, the function reads the secondary slot and tests that observation as signed 32-bit:

- A negative observation skips the conditional helpers and selects index two.
- A nonnegative observation enters the helper sequence.

The branch depends on that particular observation. A subsequent change to the slot does not repeat or reverse the test.

### Conditional helper sequence

For dispatch value one with a nonnegative secondary-slot observation, the following dependency order is established:

1. Read context offset 0x20 and invoke F-283eda65a14c with that 32-bit value.
2. Invoke F-682adfd5a561 with the preceding result and the integer six.
3. If its result is zero, invoke F-a817d8d58c10.
4. Otherwise, invoke F-9dfe5f6048f1.

F-9dfe5f6048f1 receives four arguments:

1. The nonzero result from F-682adfd5a561.
2. The helper-key value read from global storage.
3. The 32-bit context field at offset 0x24.
4. A full-width value read again from the secondary slot.

The helper-key, context-field, and secondary-slot reads for this call occur after the preceding helper calls return. Their relative evaluation order is unspecified.

The secondary argument is not a saved copy of the nonnegative value tested earlier. Entering the sequence therefore does not establish that this later argument is nonnegative.

The result of F-9dfe5f6048f1 determines the selected index:

- Zero selects index two.
- Any nonzero result is itself the index.

A nonzero result does not merely authorize use of index one. No visible sign or range validation is applied.

A zero result from F-682adfd5a561 is different: it invokes the non-returning dependency rather than selecting fallback index two.

### Table access and callback invocation

After the applicable helper sequence completes, the function reads the dispatch-table base from global storage to evaluate the selected table-slot address. The represented slot address uses that base plus four times the selected index.

The base is not a fixed address or a value captured before the helpers. Changes made by dependencies can affect the later base observation.

There is no visible bounds check or overflow check. The four-byte stride is established, but portable behavior for overflowing arithmetic, negative-index addressing, or invalid storage is not. Valid accessible storage and usable address arithmetic are preconditions for defined delegated execution.

The selected slot supplies a 32-bit dispatch-entry address. If it is zero, F-a817d8d58c10 is invoked. A nonzero entry passes the only visible null check in this part of the path.

After entry selection and that check, the indirect call requires:

- Reading the callable-metadata address from entry offset 0x00.
- Reading the callback address from metadata offset 0x04.
- Evaluating the seven callback arguments.
- Invoking the resulting callback.

The metadata-address read necessarily supplies the address used for the callback-address read. However, the supplied representation does **not** establish an evaluation order between the function designator, including those two reads, and the callback arguments, including the resolution-slot reads.

Accordingly, callback arguments are evaluated after the selected entry has been loaded and checked, and before callback invocation. Their evaluation is not established to occur after callable-metadata or callback-address evaluation. The relative evaluation order of the separate arguments is also unspecified.

Neither the callable-metadata address nor the callback address receives a visible null check.

The callback’s primary and secondary arguments are full-width observations made for this invocation. They need not equal values observed during earlier resolution checks, lookup preparation, or helper preparation. Lookup and selection are not repeated merely because a later slot observation differs.

The callback’s 32-bit result is returned unchanged. The function performs no subsequent direct output write.

### Established ordering limits

The function establishes these relevant boundaries:

- Slot initialization precedes resolution.
- Resolution returns before the primary sentinel check.
- Successful lookup precedes record-address acquisition and the distinguished-selector comparison.
- The gate read precedes the dispatch-value read.
- The secondary sign test precedes the conditional helpers.
- The later secondary read for F-9dfe5f6048f1 follows the preceding helpers.
- The table-base read follows all applicable selection helpers.

The last boundary does not impose an order between callable evaluation and argument evaluation.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid accessed storage and dependencies. Any mutation relevant to an example is stated explicitly.

1. **Unresolved primary.** A sentinel-check observation of −1 returns zero without lookup, record access, or direct output assignment.

2. **Full-width check versus narrowing.** If the sentinel and lookup-preparation observations are both 65,535, lookup receives −1. If delegation occurs and the later callback argument observation remains 65,535, the callback receives 65,535, not the narrowed value.

3. **Lookup miss.** A non-sentinel primary observation followed by a zero lookup result returns zero without reading lookup-result offset 0x08.

4. **Direct result bypasses dispatch.** With successful lookup and a matching distinguished selector, a record field of 0x89ABCDEF is copied unchanged to the output and the function returns one. A zero gate does not affect this path.

5. **Zero gate.** With a nonmatching selector and zero gate, F-a817d8d58c10 is invoked. No ordinary return is established.

6. **Negative secondary observation.** Dispatch value one and a sign-test observation of −2 select index two without the conditional helper sequence. The later callback observation is not thereby fixed at −2.

7. **Secondary changes during helpers.** If the sign-test observation is zero and a preceding helper changes the slot to −3, F-9dfe5f6048f1 receives −3 when its later argument read observes that value. There is no second sign check.

8. **Intermediate failure versus fallback.** A zero result from F-682adfd5a561 invokes F-a817d8d58c10 without table selection. A zero result from F-9dfe5f6048f1 instead selects index two; a result of five selects index five.

9. **Late global base.** If an applicable helper changes the global table base and the later read observes that change, selection uses the new base rather than an earlier snapshot.

10. **Later primary observation.** Lookup may use a primary observation of seven while the callback receives nine after a later dependency changes the slot. No repeated lookup is required.

11. **Indirect-call evaluation boundary.** Once a nonzero entry is selected, neither “read both resolution arguments before evaluating callable metadata” nor the reverse is a required ordering. An acceptance criterion requiring either ordering is unsupported. Both arguments and the callable address must be evaluated before invocation.

12. **Return and null checks.** A callback result of 0x80000007 is returned unchanged. A zero selected entry invokes F-a817d8d58c10. That entry check does not validate the metadata or callback address.
