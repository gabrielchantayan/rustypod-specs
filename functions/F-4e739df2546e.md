# F-4e739df2546e

## Purpose

F-4e739df2546e obtains one unsigned value from a dependency and classifies it into a zero-result interval or its complement.

Under the apparent 32-bit unsigned interpretation of the supplied source, it returns:

- **0** for values from **0x000B0000 through 0x000B0010, inclusive**.
- **1** for every other 32-bit value.

The zero-result interval contains exactly 17 values. The numeric results are established behavior; their application-level meanings are not. In particular, the evidence does not establish whether zero means success, compatibility, availability, or some other condition.

This is a source-based behavioral contract. No runtime tests have been performed.

## Behavior

### Acquisition and ordering

The first visible operational action is one invocation of F-dep-01. The supplied function body contains no visible explicit global-memory read, global-memory write, or caller-memory access before that invocation.

If the dependency returns normally, its result is captured in the unsigned working value. Both classification conditions use that same captured value. The function does not call the dependency again to obtain a second sample.

The visible sequence is:

1. Invoke F-dep-01 once.
2. Capture its returned value in the unsigned working type.
3. Examine the value after an unsigned right shift by 16 bits.
4. Only if that result equals decimal 11, examine the low 16 bits.
5. Return the classification result.

This describes source-level evaluation order, not a guarantee about the exact instructions emitted by a compiler.

### Classification

The function returns zero only when both conditions hold:

- The captured unsigned value, shifted right by 16 bits, equals **0x000B**.
- The captured value masked to its low 16 bits is strictly less than **0x0011**.

For a 32-bit unsigned value, the first condition requires the upper 16 bits to equal 11. The second permits low-half values **0 through 16**, inclusive.

All other values produce one. In particular:

- A different upper half produces one regardless of the low half.
- With upper half 11, a low half of 17 produces one.
- With upper half 11, every larger low-half value also produces one.

The low-half comparison is strict. The last zero-producing value is therefore 0x000B0010, not 0x000B0011.

### Arithmetic and widths

The visible operations are unsigned shifting, masking, equality comparison, and unsigned magnitude comparison. There is no addition, subtraction, multiplication, division, range accumulation, or pointer arithmetic.

- Masking with 0xFFFF selects exactly the low 16 bits.
- Every comparison constant is representable.
- No arithmetic overflow or wraparound is required to explain the result.

The function does not visibly reinterpret the dependency result as a signed integer. Values with bit 31 set therefore fail the upper-half equality and return one.

The comparison applies to the captured unsigned value, not necessarily to an independently known original representation returned by the dependency. Any conversion at that boundary depends on declarations and ABI details absent from the evidence.
