# F-363688946aac

## Purpose

F-363688946aac performs a fixed sequence of three dependency calls followed by initialization writes through two dependency-produced addresses.

The established behavior is:

- Request a value from F-8157a180d901 using the constant 252.
- Pass that result and the first caller-supplied argument to F-b7672b61693c.
- Write a value read from a global 32-bit storage location into the first four bytes of the address returned by F-b7672b61693c.
- Call F-9563b8df22d3 with an address 192 bytes beyond that returned address, the second caller-supplied argument, and the constant 1.
- Write the third and fourth caller-supplied arguments, plus a zero byte, at fixed offsets from the result of F-9563b8df22d3.

The function has no explicit return value and contains no conditional branches or explicit failure handling.

An allocation-and-construction interpretation is plausible: the constant 252 may be an allocation size, the first returned address may identify an enclosing object, and the second returned address may identify a related object. Those roles are inferred intent, not established dependency contracts.

1. The result of F-8157a180d901.
2. The first caller-supplied argument.

Its result supplies the primary base.

The function then reads a global 32-bit value and stores that value at offset 0 from the primary base. This operation affects bytes 0 through 3 of the primary region, subject to the target’s byte order.

The global read occurs after F-b7672b61693c returns and before F-9563b8df22d3 is called. It is therefore the value available at that point in the sequence, not necessarily the value that existed at function entry. The function does not cache the global before either earlier dependency call.

### Establishment of the secondary base

1. The address 192 bytes beyond the primary base.
2. The second caller-supplied argument.

The call result supplies the secondary base. The function does not explicitly verify that this result equals its first argument, lies inside the primary region, or refers to a newly created object.

The first argument to F-9563b8df22d3 and its result must therefore remain distinct concepts. Any relationship between them requires evidence from that dependency.

### Zero or high-bit-set payloads

### Overlapping destinations

This is a conditional consequence of the visible access order, not evidence that this overlap occurs in normal use.
