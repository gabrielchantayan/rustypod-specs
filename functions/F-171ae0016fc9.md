# F-171ae0016fc9

## Purpose

F-171ae0016fc9 executes an ordered sequence of unresolved indirect invocations, transforms dependency-produced machine words, mutates fixed and derived memory locations using several access widths, and finishes with an unresolved four-word indirect handoff.

No domain-level purpose is established. Character-like constants and link-like writes do not establish text generation, a record schema, allocation, initialization, or ownership transfer.

This contract distinguishes:

- **Established static evidence:** widths, dataflow relationships, and access ordering represented in the supplied material.
- **[INFERENCE]:** consequences requiring an explicitly stated execution model.
- **documented_only:** behavior unresolved by the available evidence.

The contract describes observable access requirements, not merely final memory contents. Repeated stores and intervening reads can matter when addresses alias, storage is device-backed, or external agents modify memory. No runtime tests have been performed.

## Interface

### Inputs and outputs

The presented interface has no explicit parameters and no declared return value. No result buffer, success flag, or error code is established.

Effective inputs nevertheless include:

- Incoming return-link-related machine state used to derive the first indirect target.
- Primary and secondary words produced by dependencies.
- Additional post-call register values whose ABI roles are unresolved.
- Fixed storage and memory reached through dependency-produced or subsequently loaded values.

A conventional return follows the final represented invocation. Normal completion requires every earlier invocation and that final operation to return normally; actual control-transfer semantics remain unresolved.

**[INFERENCE]** Under a 32-bit machine-bitvector model, arithmetic results used as words retain their low 32 bits. Byte and halfword stores then retain the low 8 or 16 bits. All conclusions below involving wraparound or discarded intermediate bits are conditional on that model.

Byte order, alignment rules, address mapping, and access atomicity are **documented_only**. In particular, a byte store within a word-sized region cannot be assigned a numeric effect on that word without a byte-order assumption.

## Behavior

### Dependency execution and transformed arguments

The initial phase is a long straight-line sequence of indirect invocations. No explicit loop or conditional branch controls that sequence in the supplied representation.

The first target depends on incoming machine state. Later targets are derived from embedded code-related values using a common displacement of 0xFFE. Their identities and contracts are unresolved.

Invocation order is observable whenever dependencies return normally. An invocation whose displayed result is unused may still modify memory, devices, registers, or state consumed later. It must not be treated as effect-free.

Arguments include shifted result words, unchanged high result words, explicit zeros, duplicated words in multiple positions, retained earlier results, and unresolved post-call register values. A displayed one-argument invocation does not establish zero values in every other machine argument location.

The transformations include masks retaining low-order fields of several widths, followed by left shifts or logical right shifts. Examples include:

- Retaining 24 low bits before shifting left by 6.
- Retaining 22 low bits before shifting left by 7 or 8.
- Extracting a high result word and logically shifting it right by 2, 3, 4, or 12.
- Selecting fields from a masked low 24-bit value.
- Shifting an already shifted word again.

These operations establish bit selection, not range validation, saturation, rounding, or sign extension.

**[INFERENCE]** With 32-bit intermediates, shifting a word left by 28 and then shifting that result left by 28 yields zero. Preserving a 56-bit intermediate would change the represented argument dataflow. Likewise, a word shifted left by 25 has a zero low byte.

Locally retained zeros remain zero through their represented shifts. This says nothing about dependency effects on global storage.

### Address relationships used below

The following labels describe dataflow, not types or ownership:

| Label | Relationship |
|---|---|
| Primary base | A dependency result multiplied by \(2^{25}\) |
| Retained base | A paired result’s low word shifted left by 25 |
| Shifted payload | A later result shifted left by 8 |
| Small index | Another result shifted left by 8, masked to 15 low bits, then logically shifted right by 6 |

**[INFERENCE]** Under 32-bit bitvector arithmetic, the small index is four times the low seven bits of its source: 0 through 508 in multiples of four. The small base is 0 through 1016 in multiples of eight.

### Initial memory mutations

The first direct store writes the retained base as a 32-bit word at offset 20 from the final pair’s high word. The retained-base byte at offset 9 then receives the low byte of that high word. Before that byte is overwritten with the low byte of the retained base, a word destination formed from 256 times the final pair’s low word plus 84 receives the primary base.

The primary-base word at offset 20 is cleared before the byte at primary base plus 5 is sampled. The small-base word at offset 20 is cleared before that sampled byte is stored, zero-extended to 32 bits, at primary base plus 52.

A subsequent read of primary base plus 20 precedes another clear of small base plus 20. Two byte stores at small base plus 21 then receive the low byte of that read word. The read remains an access requirement: replacing it with zero requires additional assumptions about aliasing, ordinary RAM, and external modification.

Fixed storage at address 5 is sampled next, followed by a byte store of the small base at address 1. The sample supplies a base for later accesses. Its original access width is not independently established by the visible unsigned conversion.

The shifted payload is briefly written as a byte at primary base plus 17 and as a word through the earlier offset-20 sample plus 84. The byte at primary base plus 17 is then explicitly cleared.

The word at offset 84 from the address-5-derived base is retained before that location is replaced with the earlier offset-20 sample. This retained word supplies the fourfold and eightfold bases.

### Linked mutations and fixed low-address writes

The next region mixes loads, repeated stores, and scaled addressing. It includes:

- Reads at offset 116 whose values become destinations for offset-84 stores.
- Repeated self-referential word stores at offset 36 from the retained loaded word.
- Repeated byte stores at offset 9.
- Stores through the small base and through fourfold or doubled loaded addresses.

Two fixed-address changes are explicit parts of this region, before the constant-write and publication region:

- **Address 0x54 receives a 32-bit store of the retained loaded word shifted left by one.** This occurs after small base plus 20 receives a dependency-derived value shifted left by 26, and before small base plus 20 receives the retained loaded word twice.
- **Address 0x15 receives an 8-bit store of the low byte of the small base.** Before this fixed-byte store, two stores at small base plus 21 receive the low byte of the fourfold base. The fixed-byte store precedes the subsequent fourfold-base linking and constant writes.

Neither fixed write is an offset within an established object. They must remain distinct from derived stores that may happen to overlap them.

Later operations repeatedly sample bytes at offset 5 and use those byte values as bases for offset-116 word reads. Other word reads follow links at offsets 4 and 100. Writes affect offsets 9, 13, 20, 21, 52, 68, and 84 of several derived bases.

The footprint distinguishes reads from writes:

| Access class | Derived offsets represented |
|---|---|
| 8-bit reads | 4, 5, plus separately identified fixed-byte reads |
| 32-bit reads | 4, 20, 64, 68, 84, 100, 116 |
| 8-bit writes | 1, 8, 9, 13, 16, 17, 21, 25 |
| 32-bit writes | 16, 20, 32, 36, 52, 68, 84, 116 |
| 16-bit writes | Scaled destinations described below |

**Offsets 36 and 52 are word-store destinations, not word-load offsets, in this direct-memory phase.** The combined footprint is not a structure declaration. For example, a byte at offset 21 overlaps a word beginning at offset 20.

### Constants and publication ordering

A loaded word supplies three constant destinations: its four-times-scaled address receives an 8-bit 0x3A, its eight-times-scaled address receives a 16-bit 0x003A, and its four-times-scaled address plus 32 receives a 32-bit 0x0000003A.

The fourfold base is adjusted by subtracting 150. Call the result the **adjusted value**, its four-times form the **adjusted fourfold base**, and its eight-times form the **adjusted eightfold base**.

At adjusted fourfold base plus 32, successive word stores publish 0x20, 0x2F, a zero-extended byte sampled from adjusted fourfold base plus 4, and 0x20 again. Intermediate values and the intervening byte read are observable requirements.

**The global word supplying the publication base is read after those offset-32 operations and before the fixed 32-bit store of 0x20 at address 0x60.** The publication base is the retained result of that read. It is not a fresh read after the fixed store. This distinction matters if storage mappings overlap.

The repeated publication region uses four ordered stores per group:

- A word at a scaled base plus 84 receives the earlier loaded word’s four-times form.
- A byte at publication base plus 25 receives the low byte of the adjusted fourfold base.
- A byte at adjusted fourfold base plus 17 receives the low byte of the publication base.
- A word at publication base plus 52 receives an eight-times-scaled address.

The initial group uses the original eightfold base for the first destination and final stored word. Subsequent groups use the adjusted eightfold base instead. The publication base and byte payloads are retained values; the region does not repeatedly reload the publication-base global.

Many groups are explicitly represented. Exact multiplicity remains **documented_only** in this contract; it must not be guessed or reduced to one final-state update.

### Final interleaved reads and writes

For this phase, the **linked base** is the retained doubled address obtained before the constant region, and the **publication payload base** is the four-times form of the loaded word used for the 0x3A destinations.

The final phase does not begin with all reads followed by all writes:

- A 32-bit read at fixed address 0xA9 and a word read at publication payload base plus 116 precede the byte write at fixed address 0x3A.
- That fixed-byte write receives the low-byte result corresponding to eight times the adjusted value plus 0x30.
- Only afterward are the word at linked base plus 20 and the word at adjusted fourfold base plus 4 sampled and retained.

Before fixed address 0x67 is written, derived byte stores modify linked base plus 13 and adjusted fourfold base plus 8, 13, and 9. The offset-8 byte receives 0x6C; the other payloads are low bytes of retained address-like values. A word at linked base plus 84 is also set to the linked base.

Fixed address 0x67 then receives the low byte of the earlier 0xA9 word. A word is read at linked base plus 68 **before address 0x67 is read for the byte store at address 0x21**.

That loaded offset-68 word supplies a byte at adjusted fourfold base plus 16, an intermediate word at publication base plus 84, and a signed-right-shift-derived byte at linked base plus 1. The shift count is the low byte of the adjusted fourfold base. Negative operands and counts outside 0 through 31 require target-specific semantics and remain **documented_only**.

The publication-base word at offset 84 is then replaced with the adjusted fourfold base. A read at adjusted fourfold base plus 64 precedes stores of the retained offset-4 word at publication base plus 116, the newly sampled offset-64 word at adjusted fourfold base plus 16, and the linked base at publication base plus 68.

**Address 0x67 is read again** for a byte store at adjusted fourfold base plus 9. Intervening mutations then include:

- A byte store at linked base plus 9.
- A word store of the retained 0xA9 sample at adjusted fourfold base plus 68.
- A word read at adjusted fourfold base plus 84, producing a child base.

**Address 0x67 is read a third time** for another byte store at adjusted fourfold base plus 9. These reads must not reuse the originally assigned byte: intervening derived stores may alias 0x67.

Further mutations use the child base, the retained offset-20 word, and the low byte of the earlier publication-payload offset-116 sample. They include replacement of linked base plus 84, a fresh read at adjusted fourfold base plus 20, and byte and word stores through the child base.

A word read at linked base plus 4 supplies another base. Twice that value receives the 16-bit constant 0x0065. Its offset-100 word is retained for the handoff. After intervening child-base writes, including a word store of decimal 100 at child base plus 84, its offset-116 word is sampled.

A later read at linked base plus 100 supplies another destination base. Final linking writes store the retained offset-100 word at that destination plus 84 and store that destination through twice the retained offset-100 word.

The final indirect invocation receives four represented words, in order:

1. 0x72.
2. The retained offset-100 word from the base obtained through linked base plus 4.
3. The word sampled at linked base plus 20 after the fixed 0x3A write.
4. The later offset-116 sample from the same base used for the offset-100 sample.

## Acceptance examples

These examples are conditional static consequences, not executed tests.

### Small-index boundary

Under 32-bit bitvector arithmetic, a source whose low seven bits are 127 produces small index 508 and small base 1016. Higher source bits do not affect those results.

### Fixed mutations before publication

If the retained loaded word is 0x12345678, a valid disjoint address 0x54 receives the word 0x2468ACF0 under the bitvector model. If the small index is 508, address 0x15 receives byte 0xF8. Both accesses precede the constant/publication region.

### Publication-base capture

If an allowed storage mapping makes the publication-base global overlap the word at 0x60, publication uses the value sampled before the fixed 0x20 store. Substituting a post-store reload is not equivalent.

### Intermediate values and widths

A device-backed adjusted offset-32 destination observes 0x20, 0x2F, the sampled byte extended to a word, and 0x20 in that order. The separate byte, halfword, and word stores of 0x3A retain their distinct widths.

### Interleaved fixed-byte sampling

If a derived store between the first and second later reads of 0x67 aliases that byte, the second read observes storage at its own position in the access sequence. Reusing the low byte originally copied from 0xA9 is not accepted.

### Failure and handoff

If an early dependency never returns, later direct mutations need not occur. If execution reaches the final invocation, its argument words follow the specified retained-load dataflow; no independent success result is established.
