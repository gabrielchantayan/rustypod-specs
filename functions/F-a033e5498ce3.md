# F-a033e5498ce3

## Purpose

F-a033e5498ce3 updates a three-word descriptor and processes a supplied 32-bit value using a fixed 24-byte stride.

**Established static behavior:** The function saves the descriptor’s current end and compares it with the limit. Depending on that comparison and dependency results, it follows one of three paths:

- Obtains a replacement base from a dependency, invokes processing dependencies, passes a saved previous start to another dependency, replaces all three descriptor words, and returns the computed replacement limit.
- Advances the current end, optionally invokes additional processing dependencies, and returns the result of a late-dispatched indirect call.
- Advances the current end and returns zero when the unequal-end path has a saved entry end of zero.

The indirect target is read from a global function-pointer dispatch slot at the terminal call site. It is not visibly cached at function entry.

**Inferred intent:** The descriptor resembles a contiguous container. The replacement-base and previous-start operations resemble allocation and release; other operations resemble element insertion and range movement. These interpretations do not establish allocation, deallocation, copying, destruction, or ownership semantics.

The return value is path-dependent, not a uniform success indicator, element address, or size.

### Return value

No common error or success convention is established.

### Arithmetic and representation

The stride is **24 bytes**.

The decision results and replacement-capacity calculations use unsigned 32-bit quantities. Capacity additions and multiplication by 24 therefore wrap modulo \(2^{32}\).

Other address-like values and intermediate arithmetic appear in signed 32-bit forms. The final result of F-beaa3d5aacef is held in such an intermediate before contributing to the new current end. The representation does not establish portable overflow behavior for those signed calculations or valid language-level pointer arithmetic.

### Preconditions and unsupported inputs

There is no visible validation of descriptor validity, field ordering, alignment, stride divisibility, arithmetic overflow, available storage, the supplied value, or the replacement-base result.

The replacement path includes a traversal that terminates only when its advancing position equals the descriptor’s current end. Reachability by repeated 24-byte advances is therefore a condition for ordinary termination. Invalid arithmetic or unreachable endpoints have no explicit recovery path.

## Behavior

### Entry reads and branch selection

The function first reads and saves current end, then compares that saved value with limit.

The saved entry end remains distinct from later descriptor reads. A dependency may change current end without changing the saved value.

If entry end differs from limit, execution follows the unequal-end path.

If they are equal:

1. F-f4be0af7d6d1 is called with no explicit argument shown.
2. F-beaa3d5aacef is called with the descriptor address.
3. Their results are compared as unsigned 32-bit values.

Replacement storage is selected when the first result is less than or equal to the second. Otherwise, execution follows the equal-end, non-replacement path.

The meanings of these results are unknown. The comparison must not be reversed to match an inferred container algorithm.

### Unequal-end path

The observable sequence is:

1. Write current end as saved entry end plus 24.
2. Test the saved entry end against zero.
3. If it is zero, return zero.
4. Otherwise, reach the terminal indirect dispatch.

The terminal call receives the saved entry end, the supplied value, and 24.

The current-end write occurs before both the zero return and the indirect dispatch. No comparison checks whether the advanced end remains within limit. No rollback is visible if the indirect dependency fails or does not return normally.

Neither equal-end decision dependency is invoked on this path.

### Equal-end, non-replacement path

This path is selected when the entry end equals limit and the first decision result is unsigned-greater than the second.

After both decision dependencies return, the function rereads current end. This later end need not equal the saved entry end.

The sequence is:

1. Write current end as the later end plus 24.
2. Invoke F-bfb0cc228653 with:
   - the descriptor address;
   - the later end;
   - the later end minus 24.
3. Invoke F-376c18b590ac with:
   - the saved entry end;
   - the later end minus 24;
   - the later end.
4. Reach the terminal indirect dispatch with:
   - the saved entry end;
   - the supplied value;
   - 24.

The later-end-derived arguments remain based on the value saved before F-bfb0cc228653, even if that dependency changes the descriptor.

The third argument to F-bfb0cc228653 is an address-like value preceding the later end by 24 bytes, not the supplied value.

There is no zero check on this path before terminal dispatch.

### Terminal indirect dispatch

At the terminal call site, the function reads a function pointer from a global dispatch slot and invokes the target obtained by that read.

On the equal-end, non-replacement path, this slot read occurs **after F-bfb0cc228653 and F-376c18b590ac return**. Those dependencies, as well as the earlier decision dependencies, may change the slot. The dispatched target is therefore determined by the slot’s value at the terminal site, not by an entry-time snapshot.

On the unequal-end path with nonzero saved entry end, the slot read occurs after the current-end write and zero test.

The target receives three visible arguments: saved entry end, supplied value, and 24. Its result becomes this function’s return value.

The replacement path and the unequal-end zero-return path do not reach this slot read. There is no visible validity or null check for the target.

### Replacement-storage path: capacity selection

F-beaa3d5aacef is called again with the descriptor address. This fresh result supplies the unsigned 32-bit growth count; the earlier comparison result is not reused.

Two candidates are formed:

- Growth count plus 32.
- Growth count plus its unsigned right shift by one, plus its unsigned right shift by three.

Each addition uses 32-bit unsigned arithmetic. The larger wrapped candidate under unsigned comparison is selected. Equality selects the second candidate, without changing the numerical result.

The shifted terms discard low bits independently. This is not equivalent in all cases to multiplying the count by 1.625 and applying a single rounding operation.

F-871e64ddc6de receives:

- The selected count multiplied by 24, with unsigned 32-bit wraparound.
- Zero.

Its result is saved and used as the replacement base. No failure or null check is visible. Describing this as an allocation request is inferred intent, not an established dependency guarantee.

## Acceptance examples

These are conditional static criteria, not executed tests. Arithmetic examples assume the stated small address calculations are representable.

1. **Unequal end with nonzero saved end.**  
   With current end 4096 and limit 8192, current end becomes 4120 before the dispatch-slot read. The target read there receives 4096, the supplied value, and 24. Its result is returned.

2. **Unequal end with zero saved end.**  
   With current end zero and nonzero limit, current end becomes 24 and the function returns zero. Neither the decision dependencies nor terminal dispatch-slot read is reached.

3. **Equal-end non-replacement with stable descriptor.**  
   With entry end and limit both 4096, unchanged descriptor fields, and first decision result greater than second, current end becomes 4120. F-bfb0cc228653 receives the descriptor, 4096, and 4072. F-376c18b590ac receives 4096, 4072, and 4096. Terminal dispatch then uses saved entry end 4096.

4. **Late dispatch observes a changed slot.**  
   On that same path, suppose the slot initially designates target A and F-376c18b590ac changes it to target B. If execution returns normally to the terminal site and no subsequent change intervenes, target B is invoked. An entry-cached invocation of A would not match the visible behavior.

5. **Small growth count.**  
   If replacement is selected and the fresh growth count is 16, the candidates are 48 and 26. F-871e64ddc6de receives 1152 and zero. This does not establish that storage is successfully allocated.

6. **Larger growth count and independent final result.**  
   A growth count of 64 produces candidates 96 and 104, hence a first argument of 2496 to F-871e64ddc6de. If the final F-beaa3d5aacef result is 64 and later calls return normally, current end becomes replacement base plus 1560 and limit becomes replacement base plus 2496.

7. **Mutation between difference calculations.**  
   If the first F-e436c440ac93 changes start, the following difference uses that changed value. If F-bfb0cc228653 changes start again, the second difference uses the newer value. Reusing the first helper result is not justified.

8. **Unsigned capacity wraparound.**  
   A growth count of 4,294,967,295 produces wrapped candidates 31 and 2,684,354,557. The latter is selected. Multiplication by 24 yields the 32-bit argument 4,294,967,224.

9. **No terminal dispatch on replacement.**  
   If the replacement path reaches its final writes, it returns the computed replacement limit without reading the terminal dispatch slot.
