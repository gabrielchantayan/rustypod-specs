# F-2115d9671c48

## Purpose

F-2115d9671c48 performs two ordered updates to caller-supplied storage, invokes two dependencies, and returns the original storage address if execution completes normally.

Each update writes a 32-bit value obtained from a global data location. The two global locations are distinct; their contents are not established constants. The first global is read before the first dependency call. The second global is read after that call returns, so changes made by the first dependency can affect the second update.

After the second update, the function captures an object field, executes an empty equality-controlled loop with four-unit increments, and invokes the second dependency with the captured value and a shifted difference derived from another field.

**Inferred intent:** the updates may represent dispatch-state or object-state transitions, and the later fields may describe a storage range. These interpretations do not establish construction, destruction, allocation, release, or ownership transfer.

## Behavior

### Ordered global reads, object writes, and first call

The initial sequence is:

1. Read the value supplied by the first global location.
2. Write that value as a 32-bit word at object offset 0.
3. Read the byte at object offset 36.
4. Compare that byte with zero.
5. Call F-63e33b64c660 with the original object address and the resulting Boolean.

The first global read therefore precedes both the first object write and the flag read. The flag is not captured before the write.

Every nonzero byte produces true; zero produces false. The full byte value is not forwarded as the second argument. The first dependency is called for either Boolean value: the Boolean is an argument, not a condition controlling whether the call occurs.

Aliasing can make the ordering observable. For example, if an offset-0 write overlaps a global location, it can change the value available to a later global read. The evidence does not permit replacing either global read with an assumed constant.

### First dependency boundary and second update

If F-63e33b64c660 returns normally, the function:

1. Reads the value supplied by the second global location.
2. Writes that value as a 32-bit word at offset 0 of the original object address.
3. Captures the 32-bit field at offset 12.

The second global is not read in advance of the first dependency. If that dependency changes the second global, the subsequent write uses the value available when the post-call read occurs.

The first dependency may also change the object’s fields, other global state, or storage lifetime. No preservation guarantee is visible. Later accesses therefore depend on the state left by that call, together with any effects of the second offset-0 write.

The second write replaces whatever value is then at offset 0. It is not conditional on the flag or on a dependency result.

Possible object/global aliasing must remain part of this account. The first write may affect a later global read, and the second write may modify global storage if its destination overlaps such storage. Neither read is established to be volatile or atomic.

### Captured start and empty stepping loop

After the second write, the field at offset 12 is captured as a 32-bit starting value. A separate cursor begins at that value.

The loop compares the cursor with the field at offset 16. While they are unequal, it advances the cursor by four. The loop body contains no operation.

Directly established properties are:

- Equality is the exit condition; there is no ordered bounds comparison.
- If the initial values compare equal, no increment occurs.
- The cursor is not dereferenced.
- The loop does not inspect, copy, or destroy an element.
- The loop contains no dependency call or explicit object write.
- The captured start is retained independently of the advancing cursor.

The condition references offset 16 on each logical condition evaluation. This does not independently establish repeated physical loads, volatile behavior, synchronization, or reliable observation of concurrent updates.

The cursor is represented as a 32-bit integer. The evidence does not justify widening it to avoid overflow or replacing the equality loop with a bounded traversal. Overflow-sensitive cases remain unresolved unless a specific arithmetic interpretation is supplied.

### Derived value and second call

After the loop terminates, the function reads the field at offset 20 and derives the second argument to F-ff1bdc376dcd:

- Subtract the captured start from the offset-20 value.
- Shift the resulting difference right by two bit positions.

The subtraction precedes the shift. There is no visible divisibility check, upward rounding, clamping, or validation against the loop target.

The second dependency receives six values in this order:

| Argument | Supplied value |
|---|---|
| First | Captured 32-bit value from offset 12 |
| Second | Offset-20 value minus the captured start, then shifted right by two |
| Third | Zero |
| Fourth | Original fourth explicit input |
| Fifth | First incoming execution-context value |
| Sixth | Second incoming execution-context value |

The first argument is the captured start, not the loop’s final cursor. The second argument uses offset 20, not the offset-16 loop target.

For a nonnegative difference whose evaluation is representable, shifting right by two discards the remainder on division by four. Differences of eight and eleven therefore both produce two. Negative, wrapping, and high-bit-set cases require arithmetic details not established here.

### Completion

If F-ff1bdc376dcd returns normally, the function returns the original object address.

Neither dependency result is explicitly inspected. There is no visible restoration or further write to offset 0 after the second dependency call.
