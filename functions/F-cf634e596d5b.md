## Behavior

The opening phase is a large, ordered sequence of indirect invocations and transformations, without a represented conditional branch or loop. Later effects are reached only if preceding invocations return normally.

The first target derives from incoming control-flow state plus 0xFFE. Subsequent targets predominantly derive from embedded control-flow anchors with the same displacement. Similar argument shapes do not establish identical targets.

## Acceptance examples

These are conditional static examples, not executed tests.

2. **Bounded index:** Under the 32-bit truncating interpretation, the index cannot exceed 508 and is divisible by four. This establishes no address validity.

3. **Explicit byte versus undeclared global:** An explicit unsigned-byte read of 0xFE produces 254. If storage at 0x05 were signed eight-bit storage containing −2, conversion to unsigned 32-bit form would instead produce 0xFFFFFFFE. Its declaration is not supplied.

4. **Early ordering:** Evaluation of storage at 0x05 precedes assignment at 0x01, which precedes the explicit byte store at global-selected base plus 0x15. The named assignment cannot be omitted because its width is unknown.

5. **Separated capture:** If the actual assignment extent at 0x3A overlaps either following word capture, the capture reflects that intervening mutation under the actual layout.

6. **Restoration before fresh capture:** If final link base plus 0x54 overlaps the word at derived base plus 0x14, the fresh field capture follows the restoration. Moving the read earlier is unacceptable.

7. **Delayed final-link byte:** The byte store at final link base plus 0x11 follows the fresh field capture. If those locations overlap, moving the byte store before the capture can change the captured value and violates the contract.
