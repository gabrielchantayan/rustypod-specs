# F-306b6a90102c

## Purpose

F-306b6a90102c processes three input records against a mutable context. It prepares two scan-conversion edges, applies a quantized orientation gate, constructs interpolation state, and visits aligned eight-by-eight regions. Each region is offered to one context-provided predicate. A nonzero predicate result permits attribute reconstruction, conditional updates to two resource-selection slots, and a consumer callback.

Triangle rasterization, perspective correction, and resource-level selection are **inferred intent**. The established behavior is the access pattern, fixed-width arithmetic, dependency invocation, and mutation described below. Coverage decisions and final output depend on unavailable functions.

The function has no explicit return value or local error-reporting channel.

## Behavior

### 1. Initial coordinate snapshot and edge preparation

The function initially reads the three horizontal coordinates in argument order, then the three vertical coordinates in argument order. Each receives an addition of `0x8000`.

Coordinate pairs are sorted by signed vertical comparison. Exchanges use strict comparisons; equality alone does not cause an exchange. This sorting does not reorder the original record arguments used by subsequent interpolation reads.

Arithmetic right shifts by 16 produce top, middle, and bottom scanlines. Equal top and bottom scanlines cause immediate return, before any dependency call or direct context write.

Otherwise, edge preparation uses F-dc13818ac82a and F-e713aa9f4f3b:

- When middle and bottom scanlines differ, the lower segment is prepared first.
- When top and middle coincide, that lower segment supplies the initial short edge.
- Otherwise, the upper short segment is prepared.
- The full-height segment is then prepared.

The active edges are ordered by signed horizontal start, breaking equal starts by signed increment.

Fractional-start adjustment uses an unsigned 32-bit expression: the low 16 vertical bits are multiplied by negative `0x10000`, then logically shifted right by 16. Its result is zero for a zero fraction and `65536 − fraction` otherwise. It is not a signed negative fractional displacement.

Edge setup can invoke dependencies even when the later orientation gate rejects the input.

### 2. Fresh coordinate reads and orientation gate

After edge-helper calls, the function **reads the input coordinates again**: all three horizontal coordinates, then all three vertical coordinates, in original argument order. These are not derived from the initial snapshots. Dependency mutations of record storage can therefore make the gate and interpolation geometry differ from the prepared edges.

For each freshly read coordinate, quantization adds `0x1000`, arithmetic-shifts right by 12, and clears bit zero. For quantized positions \((x_1,y_1)\), \((x_2,y_2)\), and \((x_3,y_3)\), processing requires the represented 32-bit result

\[
D=(y_1-y_2)(x_3-x_1)-(y_3-y_1)(x_1-x_2)
\]

to compare signed-greater-than 15.

There is no absolute value. Reversing winding is not generally equivalent.

A failed gate prevents setup, predicates, and consumer calls, but does not undo earlier helper effects. This is fixed-width arithmetic, not an unbounded determinant; target overflow semantics remain unresolved.

### 4. Vertical bands and coverage

Bands proceed in ascending vertical order, eight scanlines apart, while the current coordinate compares signed-less-than the aligned bottom.

The coverage buffer contains eight row pairs, each holding two 16-bit edge coordinates. Active rows occupy the top-inclusive, bottom-exclusive scanline interval.

For each active row:

- The first edge is shifted right by 16 and narrowed to 16 bits for storage.
- The second edge is similarly stored.
- Extrema are maintained using the full signed 32-bit shifted coordinates.
- Both edge accumulators advance.
- A scheduled middle transition replaces the appropriate edge for the next row.

Maxima start at zero; minima start at signed `0x7fffffff`. In particular, a maximum need not equal the largest sampled coordinate when every sample is negative.

Trailing inactive rows receive explicit zero pairs. Leading inactive rows in the first band depend on D-1; the function does not explicitly initialize those entries. D-1’s operation is unknown.

### 8. Advancement

After every candidate, accepted or rejected, the function advances the biased current value, denominator current value, and active component accumulators. It then advances the live second cursor followed by the live first cursor.

Their increments are respectively `0x40` and eight, shifted by configurations freshly read for those advances. Cursor mutations made by callbacks therefore participate in subsequent advancement.

After each band, the function advances:

1. Component row origins.
2. First captured cursor row base.
3. Second captured cursor row base.
4. Denominator row origin.
5. Biased row origin.

Both cursor row bases use the previously captured eightfold stride, but their shift configurations are freshly read at these separate updates. Later stride mutations do not alter the captured stride; later configuration mutations can alter row-base advancement.

Original context cursors are not restored.

## Acceptance examples

These are conditional static scenarios, not executed tests.

1. **Flat scanline extent.** Equal initial top and bottom scanlines return before all dependency calls and direct context writes.

2. **Orientation boundary.** With defined intermediate arithmetic, \(D=15\) rejects and \(D=16\) passes the gate. Passing alone does not guarantee a candidate or consumer call.

3. **Mutation between snapshots.** If an edge helper changes an input coordinate, prepared edges retain their initial coordinate basis, while the gate uses the freshly read coordinate.

4. **Captured stride, live shifts.** If setup establishes stride 12 and a later helper changes it to 20, row-base advancement still uses the captured eightfold value 96. A later shift-configuration change can affect placement and advancement.

5. **Vertical output increments.** If reconstructed current and vertical corners are 100 and 132, word 1 is 4. If horizontal and diagonal corners are 180 and 196, words 2 and 3 are 180 and 2.

6. **Resource variation.** For \((a,b,c,d)=(100,4,180,2)\), helper inputs are 9 and 3. The estimate is the signed maximum of the helper results, not necessarily 9.

7. **Changing resource pointer.** If second-component helpers replace the table pointer, the second dimension comes from the replacement table. If F-38db3e9c0785 replaces it again, the selected address uses that later table.

8. **Rejected region.** Predicate zero suppresses reconstruction, slot processing, and D-4 for that candidate. Interpolation and cursors still advance; subsequent acceptance requires four corner calls.

9. **Adjacent acceptance.** Two uninterrupted accepted candidates in one band require four then two denominator-corner calls.

10. **Inactive slot or components.** A zero flag or negative pair index skips that slot. A stable zero component count skips component loops but does not itself suppress predicates or D-4; eligible slots would still require valid initialized pair storage.

11. **Negative level.** A negative candidate below the signed upper limit is stored without a zero clamp.
