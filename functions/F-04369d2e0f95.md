# F-04369d2e0f95

## Purpose

F-04369d2e0f95 produces a 32-bit result using one of two paths selected by a dependency:

- A direct path reads a 32-bit value from the supplied object.
- A composed path obtains two 32-bit values through calls and combines them with bitwise inclusive OR.

Both paths are preceded by a call that receives a mutable, invocation-local slot and the object address. Both normally end with a call that receives the slot’s current contents.

**Established behavior:** selection, field access, call sequencing, bitwise combination, and finalization are visible in the supplied static evidence.

**Inferred intent:** the result may represent a set of flags, and the opening and closing calls may form a scoped state-management pair. Neither interpretation is required by this contract. The values are specified as bit patterns, and the calls are specified by their observable arguments and order.

## Behavior

### Entry and mutable local slot

The function first creates an invocation-local 32-bit slot containing the fourth input’s bit pattern. It then calls F-3794f888f18b with:

1. The address of that slot.
2. The first input, used as the object address.

The slot is passed by address, so F-3794f888f18b can change its contents. The value later supplied to F-fd58bea73663 is the slot’s contents after intervening execution, not necessarily the original fourth input.

The object is also exposed to F-3794f888f18b. Nothing supplied establishes that this dependency preserves object fields, global state, or memory reachable through other references. Consequently, later reads are not snapshots of entry-time object contents.

### Path selection

After F-3794f888f18b returns normally, the function calls F-56e2874b0016 with the object address.

Its returned 32-bit value is tested for equality with zero:

- Exactly zero selects the direct path.
- Every nonzero bit pattern selects the composed path.

No particular nonzero value is privileged. In particular, a value with only its highest bit set still selects the composed path.

### Direct path

When the selector returns zero, the function reads the 32-bit word at object byte offset 28 and selects that value as its result.

The read occurs after both preceding dependency calls have returned. Changes those calls make to this field can therefore affect the result.

On this path, the function does not directly:

- Call F-8527046ed165.
- Call F-a6226d4de001.
- Perform the indirect operation-table dispatch.
- Read the object word at offset 24.

The result is retained for return while the closing call is performed.

### Composed path

When the selector returns nonzero, the following operations occur in order.

First, F-8527046ed165 is called with the address at object byte offset 64. The argument is the region’s address, not a pointer value loaded from that offset. Its 32-bit result is retained as the first contribution.

Second, F-a6226d4de001 is called with the object address and the literal integer value 1. Its result supplies the receiver for the indirect call.

Third, the function obtains an operation-table address from the receiver’s first word and selects the callable entry at table byte offset 44. It also reads the 32-bit word at object byte offset 24. The selected operation is invoked with:

1. The receiver returned by F-a6226d4de001.
2. The word read from object offset 24.

These dispatch and argument reads occur after F-a6226d4de001 returns. The evidence does not require a particular relative ordering among the individual loads needed to prepare this one indirect call.

The indirect operation’s 32-bit result is combined with the retained result from F-8527046ed165 using bitwise inclusive OR. Each output bit is set if either corresponding input bit is set.

This is not addition, logical OR, or a comparison. There is no carry propagation, saturation, or reduction to a Boolean result. Duplicate set bits remain single set bits.

The word at object offset 28 is not directly read on this path. There is no visible fallback to that word if a composed-path dependency returns zero.

### Closing call and return

After either path has selected its result, the function calls F-fd58bea73663 with the current contents of the local slot.

The selected result is then returned unchanged as a 32-bit value, provided the closing call returns normally.

This ordering has two consequences:

- A closing-call change to the object field at offset 28 does not cause the direct-path result to be read again.
- The closing call is part of normal execution on both paths, including when the selected result is zero.

The evidence shows a shared normal-completion call, not a guaranteed unwinding mechanism. It does not establish that F-fd58bea73663 runs after a fault, exception, nonlocal transfer, or nonreturning dependency.
