# F-1e973c6163ab

## Purpose

F-1e973c6163ab performs staged initialization of caller-supplied object state. It invokes an attached provider, conditionally invokes that provider again and decodes temporary data, calls a secondary initializer, populates selected zero-valued fields, and writes finalization state.

The provider calls receive temporary addresses and numeric arguments. The supplied body does **not** establish that those arguments specify byte counts, that the calls transfer data, or that they write exactly four or six bytes.

The routine returns a 64-bit composite. Its low word is zero on normal completion or three on an explicit failure path. Its high word is the final first word of a temporary payload area initialized from the second argument.

The application meanings of the fields, provider operations, and arithmetic dependency remain unknown. Initialization, caching, adjustment, and limit terminology below describes observable roles rather than established domain semantics.

## Behavior

### 1. Reset state and invoke the provider

The first explicit object write stores zero at `+0x00c`. The routine then initializes the two payload words and the probe temporary.

It resolves the current provider and dispatch entry `+0x10`, then invokes that entry with four explicit arguments:

1. The provider pointer.
2. The probe temporary’s address.
3. The number four.
4. The number one.

The return must equal four. Every other return takes the failure exit immediately, producing low return word three. The optional provider invocation, decoder, and secondary initializer are not reached.

The exact comparison is established. Interpreting the return as a transferred-byte count is not. No retry or separate handling for negative, partial, or other unexpected results appears.

### 2. Read the global and conditionally invoke the provider again

After the first invocation returns four, the routine evaluates the probe temporary plus an unavailable 32-bit global value and compares the resulting unsigned word with `0x000000ff`.

The global is read **after** the initial provider invocation. It is not established to be immutable; that invocation may change it. Substituting a value captured before the call, or treating it as a fixed constant across invocations, is unsupported.

Under a 32-bit modular interpretation, the branch is taken when the sum is strictly less than 255. For a **fixed value of the global**, exactly 255 possible probe words satisfy this predicate. Equality with 255 does not.

If the predicate is false, the optional provider invocation and decoder are skipped. There is no additional explicit adjustment write before the saving step.

If true, the routine freshly resolves the current provider and its table entry `+0x10`, then passes:

1. That provider pointer.
2. The beginning of the payload temporary.
3. The number six.
4. The number two.

The return must equal six. Any other value immediately returns failure. In particular, any payload changes made before an unexpected return remain reflected in the high return word.

The address points to the first of the two initialized payload words. Passing six does not establish a six-byte write or limit the dependency’s writable extent. A conventional six-byte transfer would cover the first word and two address-order bytes of the following word, but that interpretation is not an established requirement.

After an exact-six return, F-1e9b48c57a00 receives an address two bytes beyond the payload’s beginning. Its 32-bit result, increased by ten, is stored at `+0x00c`. The body supplies no range or overflow check. The dependency’s read extent and decoding rule are unknown.

### 3. Save the adjustment and invoke secondary initialization

The current word at `+0x00c` is copied to `+0x020`. F-be470d4919c3 is then invoked with the object address and zero.

A nonzero result takes the failure exit. There is no subsequent explicit restoration, cache population, or finalization on that path.

A zero result is followed by a read of `+0x020` and a write of that value to `+0x00c`. This uses the saved field’s **post-call contents**. The dependency is not established to preserve either field, so the write need not restore the value saved before the call.

### 4. Populate the provider-derived cache if zero

There is no special handling for a zero subtraction result or a result with its high bit set.
