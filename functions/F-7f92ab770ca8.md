# F-7f92ab770ca8

## Purpose

F-7f92ab770ca8 first delegates an operation on a writable 16-bit-word sequence, then scans the resulting sequence for a percent sign or caret immediately followed by an ASCII digit from `1` through `9`. It selects the occurrence having the smallest digit; equal digits do not displace an earlier selection.

When a selection exists, the function invokes dependencies consistent with removing a two-word marker and inserting a supplied replacement. It conditionally routes the replacement through a 256-word temporary buffer when the observed sequence lengths sum to more than 255.

**Established behavior:** the scan, selection rule, dependency invocation order, argument values, and conditional use of temporary storage are visible in the supplied static evidence.

**Inferred intent:** the surrounding dependencies appear to implement preparation, deletion, bounded copying, and insertion for length-prefixed strings. Their actual effects are not established here. In particular, this function alone does not establish the final destination contents, a final length limit, or termination conventions.

### Sequence layout

For the destination, word offset 0 is treated as an unsigned 16-bit length. A length of \(L\) causes the scan to consider word offsets 1 through \(L\), subject to the current length being reread during loop control.

The function does not require or inspect a terminator. A zero-valued word inside the declared payload is ordinary data and does not stop scanning.

The replacement’s word at offset 0 is likewise interpreted as an unsigned 16-bit length when evaluating the replacement-size condition. Its remaining layout is not directly inspected by this function. Any stronger interpretation depends on the dependency contracts.

Each word occupies two bytes. The length fields can represent values from 0 through 65,535; the function does not initially reject destination or replacement lengths above 255.

## Behavior

### 1. Initial dependency call

The first observable delegated operation is:

- F-93583d17f15c receives the preparation value, followed by the destination pointer.

The scan begins only after this call returns. Consequently, marker selection applies to the destination state **after** this call, not necessarily its state on entry.

The function does not inspect a status result or branch on success or failure.

### 2. Scan and marker selection

The scan starts at destination word offset 1. At each loop condition, it reads the destination’s current length field and checks whether the current scan position is at or before the declared last payload word.

Each admitted iteration reads one payload word and advances the scan position by one word.

Only these two payload values trigger a lookahead:

- `0x0025`: percent sign.
- `0x005E`: caret.

For either trigger, the function reads the immediately following 16-bit word. That word is examined even when it lies beyond the declared payload.

The following word qualifies as a marker digit only if it is one of:

- `0x0031` through `0x0039`, corresponding to ASCII `1` through `9`.

The selection threshold begins at `0x003A`, one greater than ASCII `9`. A qualifying digit replaces the current selection only when its numeric word value is strictly less than the threshold. The threshold then becomes the selected digit.

The resulting selection rule is:

1. Prefer the smallest digit value, regardless of where it occurs.
2. Among occurrences with that digit value, retain the first encountered occurrence.
3. Treat percent and caret markers identically.
4. Continue scanning after finding a selection, including after finding digit `1`.

The stored selection is the address of the **digit word**, not the marker-symbol word. The function does not save a copy of either word.

A lookahead does not consume an additional scan position. The following word is still read again as the normal payload word of the next iteration if that iteration is within the declared length.

### 3. No-selection path

If no qualifying marker is selected, the function returns after the scan.

On this path:

- F-93583d17f15c has already been called.
- None of the other three dependencies is called.
- The replacement is not directly read by this function.
- There is no explicit failure or “not found” return value.

### 4. Selected-offset calculation

When a selection exists, the function derives an integer position from the selected digit’s address:

- Take the byte-address difference between that digit and the destination base.
- Divide the aligned difference by two using a signed right shift.
- Subtract one.

Under an ordinary valid, non-wrapping layout, a selected digit at destination word offset \(k\) produces position \(k-1\). This is also the destination word offset of its preceding percent or caret.

For example, a marker symbol at payload offset 1 and its digit at offset 2 produce position 1. The function does not convert this to a zero-based payload position.

The address calculation uses 32-bit signed integer operations in the supplied representation. Its ordinary interpretation requires the relevant address difference and arithmetic to remain representable. No alternative behavior for address wrapping or signed overflow is established.

### 5. Two-word editing dependency

The function next invokes F-87bf9031895e with:

1. The destination pointer.
2. The calculated position.
3. The integer value 2.

This call occurs before the replacement-length decision.

A two-word deletion beginning at the marker is a plausible interpretation, but is not independently established. The function does not verify what the dependency changed and does not inspect a status result.

The calculated position remains fixed for the later insertion call. It is not recomputed after this dependency returns.

### 6. Replacement-size decision

After F-87bf9031895e returns, the function reads the current replacement and destination length fields, promotes them to unsigned 32-bit values, and adds them.

Both fields are at most 65,535, so this sum is at most 131,070. The addition therefore does not overflow 32 bits.

The test is strictly:

- Use the temporary-buffer path if the sum is greater than 255.
- Otherwise use the original replacement pointer.

A sum of exactly 255 does not trigger the temporary-buffer path.

The evidence does not establish an order between the two header reads within this addition. It does establish that they occur after the editing dependency returns. In particular, the test does not necessarily use entry-time lengths or the destination length observed during scanning.

### 7. Conditional temporary-buffer path

When the sum exceeds 255, the function invokes F-c5c45b89a02d with:

1. The replacement pointer.
2. A function-local buffer of 256 unsigned 16-bit words.
3. The unsigned 32-bit quantity \(255-D\), where \(D\) is read again from the current destination length field for this call.

The buffer occupies 512 bytes. No initialization of it is visible before this dependency call.

For a destination length at or below 255, the third argument ranges from 255 down to 0. For a destination length above 255, subtraction wraps modulo \(2^{32}\). For example, a length of 256 produces `0xFFFFFFFF`, not zero or a negative signed capacity.

After the dependency returns, the function uses the temporary buffer as the replacement source. It does not inspect a copied length, success indicator, or bounds result.

The function therefore does **not** independently guarantee that the temporary buffer contains a valid sequence or that it holds at most 255 payload words. Those properties require an appropriate dependency contract and input state.

### 8. Final dependency call

The final call is F-044219df39fe with:

1. The original replacement pointer, or the temporary buffer on the conditional path.
2. The previously calculated position.
3. The destination pointer.

The function then returns without inspecting a result.

Insertion of the replacement at the selected marker position is inferred intent. Exact indexing, copying, capacity enforcement, and final length behavior remain dependency-defined.

## Acceptance examples

These examples describe static consequences, not executed tests. Unless stated otherwise, the destination notation describes payload words immediately after F-93583d17f15c returns. Dependencies are assumed to return normally and leave storage valid.

1. **Empty destination.**  
   With destination length 0, no payload word is read. Only the initial dependency is called. The replacement header is not directly inspected.

2. **Smallest digit wins.**  
   For payload `%7x^2y%5`, the selected digit is `2`. Its caret is at word offset 4, so the editing and final dependencies receive position 4. The later `5` does not replace the selection.

3. **Equal digits retain the first occurrence.**  
   For payload `^3x%3`, the first marker remains selected. Both editing and final calls receive position 1.

4. **Unsupported digit values do not qualify.**  
   Payload `%0^:` contains trigger symbols and causes lookahead reads, but neither following word qualifies. No editing, copying, or final dependency is called.

5. **A selected digit does not stop scanning.**  
   For payload `%1xyz^9`, the first marker remains selected, but scanning continues through the entire declared payload and performs the lookahead after the caret.

6. **Exact size boundary.**  
   After the editing call, destination length 200 and replacement length 55 produce a sum of 255. F-c5c45b89a02d is skipped; the final dependency receives the original replacement pointer.

7. **Temporary-buffer boundary.**  
   After the editing call, destination length 200 and replacement length 56 produce a sum of 256. If the destination header remains 200 for the later read, F-c5c45b89a02d receives bound 55. The final dependency receives the temporary-buffer pointer.

8. **Zero copy bound.**  
   Destination length 255 and replacement length 1 trigger the temporary-buffer path with bound 0, assuming the destination header remains unchanged. The meaning of a zero bound is dependency-defined.

9. **Unsigned bound underflow.**  
   Destination length 256 and replacement length 0 trigger the temporary-buffer path. If the destination header remains 256, the bound is 4,294,967,295. The function does not clamp it.

10. **Marker at the logical end.**  
    With declared payload consisting only of `%`, the function reads word offset 2. If that word is accessible and contains ASCII `4`, it selects a marker and calculates position 1 despite the digit being outside the declared payload. If the word is inaccessible, this function provides no guard or defined error response.
