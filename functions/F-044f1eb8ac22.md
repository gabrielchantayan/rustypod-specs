# F-044f1eb8ac22

## Behavior

### Dispatch precedes field consumption

The function first reads the dispatch base from the beginning of the supplied object. It then reads the indirect target address at dispatch-base offset 8 and invokes that target, passing the original object pointer.

The direct field read at object offset 20 occurs only after this invocation returns normally. There is no visible read of that field before dispatch and no pre-call clearing of it.

This ordering is externally significant. If the indirect target changes the designated field, the returned value reflects its post-call contents rather than its entry contents.

The dispatch target is resolved from the pre-call dispatch data. If the invoked operation subsequently changes the object’s dispatch base or a dispatch entry, this function does not visibly reload either one to select another target.

### Post-call retrieval and clearing

After the indirect call completes, the function reads the 32-bit integer field at byte offset 20 of the original object address. It retains that value as its return result, writes a 32-bit zero to the same field, and returns the retained value.

Consequently, on a normal, uninterrupted execution without intervening external modification:

- The result equals the field’s value immediately after the indirect call.
- The field contains zero when the function returns.
- The field is written even when the retrieved value is already zero.

The indirect target’s return value does not determine the result. The post-call object field does.

The result is represented as an integer in the supplied evidence. There is no visible arithmetic, range check, saturation, or conversion applied to the field value. Under the apparent 32-bit model, its 32-bit value is retained through the read and return. The evidence does not establish whether application-level consumers interpret that value as a count, status, flags, signed quantity, or encoded value.
