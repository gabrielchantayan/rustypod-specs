# F-11d544a72c03

## Purpose

F-11d544a72c03 updates a three-word state record and initializes a two-word entry area. It records an incoming 32-bit value as the latest entry, either installs that value in the state’s first word or writes it to an address derived from the previous latest value, and conditionally installs it in the state’s third word.

The structure suggests insertion into a linked sequence with a separately tracked selected entry. That interpretation is **inferred intent**, not an established data-type contract. In particular, the relationship between the entry area and the incoming value is not supplied.

The established contract is the ordered set of memory accesses and conditional updates below. The function has no explicit return value, allocation, release, or error-reporting operation.

## Interface

The function accepts three arguments:

| Argument role | Representation and required use |
|---|---|
| **State address** | Address of storage containing three consecutive 32-bit words, at byte offsets 0, 4, and 8. |
| **Entry-area address** | Address of storage containing at least two consecutive writable 32-bit words, at byte offsets 0 and 4. |
| **Incoming value** | A 32-bit integer value. It is stored as data and can also participate in address calculation or serve as the base address of a byte read. |

For this contract, the state words are named:

- **First word:** state offset 0.
- **Latest word:** state offset 4.
- **Selection word:** state offset 8.

The entry-area words are named:

- **Forward word:** entry-area offset 0.
- **Backward word:** entry-area offset 4.

These names describe apparent roles without asserting a complete container format.

### Width and address model

The supplied representation uses four-byte words and an eight-bit byte read. Its address arithmetic casts an address to an integer and combines it with integer arguments. A **32-bit address model is inferred** from that representation.

Under that model, the nonzero-latest branch writes a 32-bit value at:

**entry-area address + current latest value − incoming value**

The byte used by the selection rule is at:

**incoming value + 30 bytes**

The first expression is byte-address arithmetic. The displacement is not multiplied by four.

Calculations that remain representable and produce valid addresses have the behavior specified here. Exact handling of signed arithmetic overflow, address wraparound, and integer-to-address conversion is **documented_only**: the supplied representation does not independently establish those target-level rules. A consumer must not rely on a particular overflow result without additional platform evidence.

For normal completion, each address actually accessed must be valid for its access width and permissions:

## Behavior

### Entry-area initialization

The first observable write stores a 32-bit zero in the entry area’s forward word.

The function then reads the state’s latest word and writes that value into the entry area’s backward word.

Consequently, the saved backward value is the latest word’s value **after** the initial zero store. If the entry area overlaps the state, this can differ from the latest word’s value at function entry.

The function does not initialize any other entry-area storage.

### First-word or computed-link update

After initializing the two entry-area words, the function reads the state’s latest word again and tests whether it is zero.

If that read yields zero, the function writes the incoming value into the state’s first word. It does not perform the computed-link store in this branch.

If that read yields a nonzero value, the function reads the latest word for the address calculation and writes the incoming value to the computed link destination:

**entry-area address + latest value − incoming value**

The stored value is the incoming value itself, occupying one 32-bit word.

The write is not necessarily to the state, the entry area, or an independently identified object. Its destination depends on the relationship among the three arguments and the latest word. The supplied representation gives no separate bounds or ownership constraint for that destination.

In the zero branch, the state’s first word is assigned without checking its existing contents. In the nonzero branch, there is no direct assignment to the first word, although the computed destination can alias it.

### Latest-word replacement

After either branch completes, the function writes the incoming value into the state’s latest word.

This store occurs after the first-word or computed-link store. If the earlier store targets the latest word, this later store still follows it.

With disjoint storage and no external interference, the latest word therefore equals the incoming value on normal return.

### Conditional selection update

The function next reads the state’s selection word.

If the selection word is nonzero:

- The byte at incoming value plus 30 is not read.
- No direct store to the selection word occurs in this final phase.

If the selection word is zero:

- The function reads exactly one byte at incoming value plus 30.
- A zero byte causes a 32-bit store of the incoming value into the selection word.
- A nonzero byte causes no selection-word store.

The byte is tested only for zero versus nonzero. No specific nonzero value has a distinct effect.

The selection-word read occurs after the latest-word replacement. Thus, overlapping storage or an earlier computed-link store can affect whether the byte is read.

### Observable order and aliasing

The ordered operations are:

1. Store zero in the entry-area forward word.
2. Read the latest word and store it in the entry-area backward word.
3. Read the latest word to select the first-word or computed-link branch.
4. Perform the selected branch’s store; the computed-link branch also reads the latest word to form its address.
5. Store the incoming value in the latest word.
6. Read the selection word.
7. If that read is zero, read the byte at incoming value plus 30.
8. If that byte is also zero, store the incoming value in the selection word.

These accesses must not be replaced conceptually with a single snapshot of the initial state. Earlier writes can change the values used by later reads.

The function does not explicitly prohibit overlapping arguments. However, a convenient “append” interpretation requires additional noninterference assumptions. With overlap, the ordered memory effects above govern the result rather than the simple field-level summary.

No atomicity, synchronization, or concurrency guarantee is established.

## Side effects

On a normally completing call, the function always attempts:

- Two 32-bit stores to the entry area.
- One 32-bit store to either the state’s first word or the computed link destination.
- One 32-bit store to the state’s latest word.

It additionally performs a 32-bit store to the selection word only when both the observed selection word and the subsequently read byte are zero.

These are counts of store operations, not necessarily distinct destinations. Aliasing can cause several stores to affect the same location.

The byte at incoming value plus 30 is read-only within this function. There is no explicit write to that byte, although another write could overlap it if addresses coincide.

The function does not explicitly allocate, free, retain, or release memory. It stores address-like values into caller-supplied storage, but that does not establish an ownership-transfer rule. Memory lifetime and ownership remain caller responsibilities unless defined by an external contract.

There is no explicit success indicator or recoverable error path. Invalid memory access may prevent completion after earlier writes have already occurred. Fault behavior, rollback, and delivery of platform exceptions or signals are **documented_only**. No rollback mechanism appears in the supplied representation.

## Acceptance examples

These examples are conditional deductions from the supplied representation, not runtime observations. Unless stated otherwise, storage is disjoint, address calculations are representable, accesses are valid, and no other actor modifies memory during the call.

### Initially empty latest word, zero classification byte

Given:

- Latest word is zero.
- Selection word is zero.
- Incoming value is a valid nonzero address-like value.
- The byte at incoming value plus 30 is zero.

Expected result:

- Entry-area forward word becomes zero.
- Entry-area backward word becomes zero.
- State first word becomes the incoming value.
- State latest word becomes the incoming value.
- State selection word becomes the incoming value.

No computed-link store occurs.

### Existing latest value, nonzero selection

Given:

- Latest word is `0x2000`.
- Incoming value is `0x3000`.
- Entry-area address is `0x3010`.
- Selection word is nonzero.

Expected result:

- Entry-area backward word receives `0x2000`.
- The computed-link destination is `0x2010`.
- A 32-bit `0x3000` is stored at `0x2010`.
- Latest word becomes `0x3000`.
- The final phase does not read the byte at `0x301E`.
- The selection word receives no direct final-phase store.

Assuming the computed destination is also disjoint from the state, the first and selection words remain unchanged.

### Zero selection, nonzero classification byte

Given a zero selection word and a byte value of `0x80` at incoming value plus 30, the function reads that byte but does not store the incoming value into the selection word.

The same selection decision applies to every nonzero byte, including `0x01` and `0xFF`.

### Selection word changed by the computed-link store

If the computed-link destination coincides with the selection word and the incoming value is nonzero, that store makes the selection word nonzero before the final selection check.

The final phase then skips the byte read. The selection decision is based on the later observed value, not the selection word’s entry value.

### Entry-area forward word overlaps the latest word

If the forward word occupies the same address as the latest word, the initial zero store clears the latest word before it is copied or tested.

Absent other interfering overlap:

- The backward word receives zero.
- The first-word branch is selected, regardless of the latest word’s value before the call.

This demonstrates why initial-state-only descriptions are insufficient for overlapping storage.

### Zero incoming value

Zero is not rejected as an incoming value.

It is stored into the latest word and into the selected first-word or computed-link destination. If the selection word is zero at the final check, the function attempts to read the byte at address 30 under the inferred address model.

Whether that address is readable is an external precondition. Zero input does not establish a safe empty-insertion operation.
