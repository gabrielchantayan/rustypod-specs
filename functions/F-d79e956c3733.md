# F-d79e956c3733

## Purpose

F-d79e956c3733 resolves a record through a signed, relative displacement and returns a four-byte value from a position selected by that record’s leading unsigned value.

A flag in a separate context selects one of two addressing rules:

- **Narrow-selector mode:** use the low eight bits of the record’s leading 16-bit value, then add one.
- **Wide-selector mode:** use the entire leading unsigned 16-bit value, then add two.

The returned value is loaded from memory. It is not the computed address, a widened selector, or a status code.

The established behavior is an address-resolution and load operation. Interpretations such as “lookup table,” “record length,” or “payload header” are inferred intent, not established data-format semantics.

## Behavior

### 1. Locate the displacement entry

The function reads the unsigned 16-bit field at context byte offset 28. Its numeric range is 0 through 65,535.

The displacement-entry address is the data base plus that unsigned field, minus twice the index, minus two bytes:

**Entry address = data base + origin offset − 2 × index − 2.**

The origin offset is not sign-extended. An origin field whose high bit is set therefore contributes a positive value, not a negative displacement.

For arithmetic that remains within the applicable address range:

- Index zero selects the entry two bytes before the origin.
- Index one selects the entry four bytes before the origin.
- Increasing the index by one moves the entry address backward by two bytes.
- Index negative one selects the entry exactly at the origin.

There is no explicit rejection of zero or negative indexes and no bounds check against a table size.

### 2. Resolve the record

The function reads a signed 16-bit displacement at the entry address. Its numeric range is −32,768 through 32,767.

The record address is:

**Record address = data base + signed displacement.**

Consequently:

- A zero displacement selects the data base itself.
- A positive displacement selects a higher address.
- A negative displacement selects a lower address.

The origin field and index affect where the displacement is read. They are not added again when resolving the record address.

### 3. Select the addressing mode

After resolving the record address, the function reads the 32-bit flags field at context byte offset 48.

Only mask 2 matters:

- If that bit is clear, narrow-selector mode applies.
- If that bit is set, wide-selector mode applies.

Other flag bits do not affect the branch or subsequent arithmetic shown in the supplied evidence.

### 4. Read the record selector and determine the return address

In both modes, the supplied expression reads the record’s leading value as unsigned 16-bit. Narrow mode then reduces that numeric value to its low eight bits.

Let the leading unsigned 16-bit value be the **selector**.

| Mode | Byte offset from record start |
|---|---:|
| Narrow | Low eight bits of selector, plus 1 |
| Wide | Full selector, plus 2 |

In narrow mode, the final offset ranges from **1 through 256** inclusive. In wide mode, it ranges from **2 through 65,537** inclusive.

The additions do not wrap within eight or sixteen bits. In particular:

- Narrow selector low bits of 255 produce offset 256, not zero.
- Wide selector 65,535 produces offset 65,537, not one.

There is no multiplication by four, alignment adjustment, or additional indirection between computing this offset and reading the result.

### 5. Return the four-byte load

The function reads four bytes beginning at the record address plus the selected offset and returns that value directly.

The selected address need not be naturally aligned by construction. The read may overlap the record’s leading selector bytes: narrow mode can select offset 1. The evidence imposes no non-overlap requirement.
