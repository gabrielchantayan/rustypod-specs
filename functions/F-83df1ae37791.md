# F-83df1ae37791

## Purpose

F-83df1ae37791 obtains a collection through dependencies, selects the earliest record whose one-byte discriminator equals 1 or 2, and publishes that record’s two four-byte payload words through optional output pointers.

If the collection-producing dependency returns a nonzero result, or no eligible record is found, each requested output receives the four-byte sentinel pattern 0xFFFFFFFF.

Every normally completing path returns the four-byte value zero. The return value does not distinguish selection, absence of a matching record, or a nonzero dependency result.

These behaviors are established by the supplied source. The application meanings of the request, discriminators, payloads, and sentinel are not established.

Null output pointers suppress only their corresponding final stores. They do not suppress dependency calls, global-state reads, collection inspection, or selected payload reads. Both output pointers may be null.

The payloads and outputs are four-byte quantities. Their signedness and application interpretation are unspecified. The sentinel is an established bit pattern, not an established application error code.

### Return value

Normal completion returns zero as a four-byte quantity.

The function contains no alternative normal return for dependency failure, an empty collection, or an unsuccessful scan. Invalid memory accesses and abnormal dependency exits are not visibly converted into a normal return.

### Preconditions

Ordinary defined operation requires:

- Every non-null output pointer supports its four-byte store.
- F-fbcf824e7197 returns a usable dispatch base, with a readable callable entry at byte offset 8.
- That entry identifies a callable target accepting the supplied scratch-storage address under the applicable calling convention.

## Behavior

### Initial values and indirect callback

Two prospective output values begin with the pattern 0xFFFFFFFF.

The function calls F-fbcf824e7197 without arguments. From its result, it locates a callable entry at byte offset 8 and invokes that entry with the address of a separate four-byte automatic-storage region.

No explicit null check or failure check intervenes between obtaining the dispatch base and invoking the callback. The callback’s return value is not used.

The four-byte region passed to this callback is not explicitly initialized beforehand or read afterward by this function. It is distinct from the storage later passed to the collection-producing dependency. Its lack of a later direct read does not establish that the callback has no effect.

### Global pointer dereference and collection request

After the indirect callback returns, the function obtains the first argument for F-f5b72f3fca12 through two source-visible memory reads:

1. It reads the pointer stored in the referenced global location.
2. It reads the value through that pointer.

The value obtained by the second read becomes the first argument. The argument is not the pointer itself, and the operation is not merely a read of a global scalar.

Neither the pointer nor its pointee value is captured before the callback. The callback may change the pointer, the value reached through it, or both. Any such changes can therefore affect the subsequent argument or the validity of its acquisition. The source does not establish that the callback preserves either location.

The function then calls F-f5b72f3fca12 with:

| Position | Argument |
|---|---|
| First | The value obtained through the post-callback global pointer dereference. |
| Second | The address of collection scratch storage. |
| Third | The caller’s unchanged four-byte request value. |

Both global-related reads occur after the callback and before this dependency call. The source does not establish an atomic snapshot, synchronization, or protection against concurrent changes.

Exactly zero from F-f5b72f3fca12 enables collection inspection. Any nonzero result bypasses the count and record inspection performed by this function, leaving both prospective outputs at 0xFFFFFFFF.

### Record selection

After a zero dependency result, scanning starts at unsigned index zero and proceeds in ascending order.

At each loop condition, the index is compared with the unsigned 32-bit count. If it is not less than the count, scanning ends without a selection. Otherwise, the indexed record’s discriminator is compared first with 2 and, if that comparison fails, with 1.

Either value qualifies. Any other one-byte value causes the index to advance.

The first qualifying record is selected. There is no priority for a later discriminator-2 record over an earlier discriminator-1 record. Record position controls selection.

The discriminator comparison order is established at the expression level. It does not establish that two distinct physical memory loads occur when both comparisons are evaluated.

Once a record qualifies, its first four-byte payload is read, followed by its second four-byte payload. Both reads occur before either direct output store, even if one or both output pointers are null. Later records are not inspected.

If the count is zero, no discriminator or payload is read. If every inspected discriminator fails, both prospective outputs retain the sentinel.

### Widths, arithmetic, and bounds

The count and scan index are unsigned 32-bit quantities. A count with its high bit set is a large positive bound, not a negative count.

The discriminator addressing uses an unsigned 32-bit index product by 12. Payload indexing uses an unsigned 32-bit product by 3, with an additional word-index increment for the second payload. These operations must not be interpreted as unlimited-precision arithmetic.

For indices zero through seven, the apparent record layout accounts for the accessed fields without index-product overflow.

The function does not enforce an eight-record bound. An excessive count may still lead to ordinary selection if an early accessible record qualifies, but otherwise scanning can reach beyond the apparent local record region. At sufficiently large indices, unsigned arithmetic wrapping also becomes relevant. Neither wrapping nor excessive counts establish a safe extended collection.

The contract does not promise safe exhaustion, sentinel publication, or a recoverable error after an invalid record access.

### Output publication

After dependency processing and any record scan, the function performs these operations in order:

1. If the first output pointer is non-null, store the first prospective value there.
2. If the second output pointer is non-null, store the second prospective value there.
3. Return zero.

For exactly aliased valid output pointers, the second store replaces the first. The final four-byte value is the second selected payload, or 0xFFFFFFFF when no selection occurred.

For partially overlapping output regions, the first store still precedes the second. The resulting byte arrangement depends on byte order and on whether the accesses satisfy the platform’s alignment and memory-access rules.

Payloads equal to 0xFFFFFFFF are copied without filtering. Output values alone therefore cannot always distinguish a successful selection from a sentinel-producing path.

These are conditional behavioral examples, not executed tests. Unless an example says otherwise, assume normally returning dependencies, valid global-pointer reads, initialized accessible collection contents, and writable requested outputs.

   The global pointer remains unchanged, but the callback changes its pointee value from 31 to 47. If no intervening change occurs, the collection dependency receives 47. The function does not reuse a pre-callback pointee value.

3. **Callback invalidates the pointer.**

4. **Collection dependency returns nonzero.**  
   Both requested outputs receive 0xFFFFFFFF, and normal completion returns zero. The selection logic reads no collection count or record. The callback and global-pointer dereference have already occurred.

5. **Empty collection.**  
   The dependency returns zero and supplies count zero. Both requested outputs receive 0xFFFFFFFF. No record is inspected.

6. **Earlier discriminator 1 beats later discriminator 2.**  
   The first record has discriminator 1 and payloads 17 and 29. A later record has discriminator 2. The published values are 17 and 29.

7. **Skipped records do not supply payloads.**

9. **One or no outputs requested.**

10. **Exactly aliased outputs.**  
    Both output pointers identify the same valid four-byte location. A selected record contains 83 and 97. The location is written first with 83, then with 97; its final value is 97.

11. **Sentinel-valued selected payloads.**  
    An eligible record contains 0xFFFFFFFF in both payload fields. Those patterns are published, with no separate success indicator.

12. **Count exceeds apparent capacity.**
