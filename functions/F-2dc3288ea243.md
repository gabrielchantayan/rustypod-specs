### Selection and return semantics

Selection uses the complete input value. It does not use only the lowest byte, a character interpretation, or a masked subset of bits. Consequently, a value whose low byte equals a listed input does not receive that substitution unless its remaining bits are also zero.

Exactly one mapping decision applies to each invocation. A replacement is returned as the result; it is not fed back into the mapping during that invocation.

The explicitly listed input 8 returns 8. Its result is therefore indistinguishable from identity behavior at the interface, although it is a separately represented case.

All replacement values fit within eight bits, but the result interface remains 32 bits. The established replacement patterns have zero in every bit above their stated numeric value. There is no basis for leaving upper result bits unspecified.

### Arithmetic and boundaries

If a caller treats the argument as signed, negative values retain their original 32-bit patterns. This follows from the absence of any matching negative case; it does not establish a signed interface declaration.

## Acceptance examples

The following are conditional acceptance criteria derived from the supplied representation. They are not reports of executed tests.

### Exact substitutions

For each row in the mapping table, supplying the input must return the listed 32-bit result. In particular:

- Input 0 must return 126, not 0.
- Input 1 must return 60.
- Input 5 must return 48.
- Input 6 must return 10.
- Input 7 must return 9.
- Input 8 must return 8.

A result truncated to a byte at an external boundary would not by itself demonstrate compliance with the 32-bit return contract.

### Identity boundary

If the input is 9, the result must be 9. If the input is 10, the result must be 10. Neither value begins a further conversion process.

If the input is 126, the result must be 126. The mapping does not reverse the substitution for input 0.

### Full-width comparison

If the input is 0x00000100, the result must remain 0x00000100. Its lowest byte is zero, but the complete value does not match input 0.

If the input is 0x00000106, the result must remain 0x00000106. It must not become 10 merely because its lowest byte equals 6.

### High-bit preservation

If the input is 0x80000000, the result must be 0x80000000.

If the input is 0xFFFFFFFF, the result must be 0xFFFFFFFF, regardless of whether the caller displays that pattern as an unsigned maximum or as a negative signed value.

### Independent invocations

If one invocation receives 0 and a later invocation receives 1, their results must be 126 and 60 respectively. The earlier invocation must not change the later mapping.

If the result of an invocation receiving 6 is explicitly passed to a second invocation, both results must be 10. The second result follows from identity handling of input 10.
