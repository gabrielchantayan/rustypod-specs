# F-ca5205b3904f

## Purpose

F-ca5205b3904f initializes a record obtained from an input object, performs three object-dispatched operations, and then chooses between two completion paths using a selected value and an unsigned comparison against a derived threshold.

The established behavior is structural: record writes, dependency calls, an object-field update, and return-value propagation. A likely intent is to compare a current measurement with a selected item’s measurement plus 60, but the measurement’s units, encoding, and domain are not established. In particular, the constant 60 does not by itself establish a time interval.

This contract describes the supplied static evidence. No runtime tests have been performed.

## Behavior

### 1. Acquire a writable record

The function resolves the object’s dispatch-table entry at offset `0xC0` and calls it with the object address.

If that call returns zero, the function immediately returns zero. On this path, the function itself does not read the source byte, write the record fields, invoke the three operations at table offset `0x58`, or update object offset `0xC4`.

The acquisition operation may have its own side effects; its zero result does not establish that the overall call was side-effect-free.

### 2. Initialize the acquired record

For a nonzero acquisition result:

1. F-b8274406a146 is called with the source address and the explicit second argument `1`.
2. Its 32-bit result is written to record offset `0x0C`.
3. The same saved result is written to record offset `0x08`.
4. A 32-bit global value, designated **global A** here, is captured.
5. The unsigned byte at source offset `0x03` is read.
6. That byte is zero-extended to 32 bits and written to record offset `0x10`.
7. A second 32-bit global value, **global B**, is captured for later calls.

The order matters. The two record writes occur before the source-byte read. If the record aliases the source, those writes may affect the subsequently read byte. Likewise, F-b8274406a146 may change accessible memory before that read. The contract therefore concerns the byte present at the actual read, not necessarily the byte present on entry.

The function performs no success check on the conversion result before storing it.

### 3. Perform three object-dispatched operations

The function invokes the operation at dispatch-table offset `0x58` three times, in this order:

| Invocation | Arguments after the object |
|---|---|
| First | A fresh read of global B; the saved global A |
| Second | The saved global B; a read of global C |
| Third | The saved global B; a read of global D |

Globals C and D are distinct global locations.

The first invocation reads global B again rather than merely using the previously captured copy. Under ordinary execution without intervening mutation, the values coincide, but the accesses are distinct.

Global C is read after the first invocation returns. Global D is read after the second invocation returns. Consequently, changes made by earlier callbacks may affect later arguments. The second and third invocations nevertheless use the saved global B, even if the global location itself has changed.

The object’s dispatch information is resolved for each invocation. The evidence does not establish that every invocation reaches the same implementation if earlier callbacks mutate the object or its table.

All three return values are ignored.

### 4. Obtain a selection

After the three operations, the function calls F-fd8692810e8b with no explicit arguments.

Its result is interpreted as zero versus nonzero. A nonzero result is retained as an opaque 32-bit selected value; the function does not independently dereference it.

#### Zero selection

When the result is zero:

1. The function writes zero to object offset `0xC4`.
2. It calls F-f2b8332efb8a with the integer argument `3`.
3. If that call returns normally, the function returns zero.

F-f2b8332efb8a’s result is ignored. It runs after the object-field write and may itself modify the object or other state. Therefore, “zero is written before the call” is established; “the field is still zero at function return” is not guaranteed without an additional dependency contract.

#### Nonzero selection

When the result is nonzero, processing continues as follows:

1. F-ebc906d2c2d5 receives the selected value.
2. Its result is passed to F-dee541b2a059 together with an address in local byte storage.
3. F-6132bda8e448 receives the address of a separate local buffer represented as 12 bytes.
4. F-b8274406a146 receives the first local-storage address and the explicit second argument `0`.
5. A threshold is formed by adding `0x3C`, or decimal 60, to that result using 32-bit unsigned arithmetic.
6. F-dee541b2a059 receives that threshold and the first local-storage address again.
7. Three bytes are read from consecutive locations beginning at that address and packed into a 32-bit word.
8. The selected value is written to object offset `0xC4`.
9. F-b8274406a146 receives the separate buffer address. Only one explicit argument is visible at this call site.

F-6132bda8e448 runs before the first local-storage conversion, not immediately before the final comparison. The evidence does not establish when it samples any external state or what the separate buffer represents.

### 5. Threshold arithmetic and byte packing

The threshold is the conversion result plus 60, reduced modulo \(2^{32}\). There is no overflow rejection or saturation.

The later comparison uses this same numerical threshold, derived from the saved conversion result. It does not reparse the byte representation produced by the second F-dee541b2a059 call.

For the three consecutive bytes read after that call:

- The first byte contributes bits 16–23.
- The second contributes bits 8–15.
- The third contributes bits 0–7.
- Bits 24–31 of the packed word are zero.

This describes a numerical packing operation, not a claim about the target’s in-memory byte order for 32-bit words. No range restriction other than each input being an 8-bit byte is evident.

### 6. Choose and return the completion result

Let the unsigned result of the final F-b8274406a146 call be the comparison value.

- **Comparison value below threshold:** call F-910df819391b with the integer argument `1` and an address in local storage. Return its result unchanged.
- **Comparison value equal to or above threshold:** resolve the object’s dispatch-table entry at offset `0xE8`, call it with the object and integer argument `2`, and return its result unchanged.

Equality takes the second path.

The selected value is written to object offset `0xC4` before the final conversion and before either completion operation. Those later dependencies may observe or modify that field.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Each assumes valid accessible storage, normally returning dependencies, and no unspecified mutation that invalidates the stated observations.

1. **Acquisition returns zero.**  
   The function returns zero without calling F-b8274406a146 or F-fd8692810e8b and without directly writing object offset `0xC4`.

2. **Source-byte zero extension.**  
   If the source byte is `0xFE` when actually read, record offset `0x10` receives `0x000000FE`, not a sign-extended negative value.

3. **Duplicated conversion result.**  
   If the initial conversion returns `0x12345678`, the function writes that value first at record offset `0x0C`, then at `0x08`. No interpretation or validation of the value intervenes.

4. **Callback changes a later global.**  
   If the first operation at table offset `0x58` changes global C, the second operation receives the changed C value. If it changes global B, the second operation still receives the previously saved B value.

5. **No selection.**  
   If F-fd8692810e8b returns zero, the object field is written with zero before F-f2b8332efb8a receives `3`. Neither comparison completion path is reached.

6. **Ordinary threshold boundary.**  
   If the conversion used to form the threshold returns 100, the threshold is 160. A final comparison value of 159 selects F-910df819391b; values of 160 or 161 select the object operation at table offset `0xE8`.

7. **Unsigned overflow.**  
   If the threshold-producing conversion returns `0xFFFFFFF0`, adding 60 produces `0x0000002C`. A final value of `0x0000002B` selects the below-threshold path; `0x0000002C` selects the other path.

8. **Packed-byte contribution.**  
   If the three bytes read after the second F-dee541b2a059 call are `0x12`, `0x34`, and `0x56`, the packed word is `0x00123456`. This does not establish the contents of the four preceding bytes passed as part of the local-storage region.

9. **Opaque result propagation.**  
   If the chosen completion operation returns `0x80000001`, F-ca5205b3904f returns that same 32-bit pattern without Boolean normalization.
