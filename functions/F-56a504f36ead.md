# F-56a504f36ead

## Purpose

F-56a504f36ead performs globally controlled dispatch over operations involving an opaque resource word, dependency-produced numeric values, mutable arithmetic state, and a possibly allocated 52-byte record. A record-population operation publishes the current allocation address through a working output pointer.

The supplied static body establishes individual operations, argument widths, arithmetic dependencies, and local ordering. It does not supply the global values needed to establish a complete execution sequence. Acquisition, queries, allocation, population, publication, and resource handling therefore cannot be specified as an unconditional pipeline.

“Acquisition,” “configuration,” “query,” and “validation” describe **inferred intent**, not independently established dependency semantics. In particular, no dependency is established as releasing a resource or transferring ownership.

## Interface

The function accepts five arguments and returns an unsigned 32-bit word.

| Argument | Representation | Established treatment |
|---|---|---|
| First | Unsigned 32-bit word | Captured at entry. Argument setup multiplies it by a global coefficient and installs the low 32 bits in the working first-input slot. |
| Second | Opaque four-byte word | Captured at entry and later installed in the working second-input slot by argument setup. |

Entry capture and argument setup are separate events. Before setup, the working first, second, and fifth inputs and the working publication pointer are zero. The shared accumulator also starts at zero, but other operations can overwrite it before setup executes.

Setup may be delayed, repeated, or absent on a particular path. Dependency inputs and the publication destination must consequently be described using the **current working state**, not automatically identified with caller arguments.

The return operation returns the current 32-bit result word. This word starts at zero and is subsequently replaceable by arithmetic results, retained status values, or global words. The evidence does not identify any particular value as success, invalid input, allocation failure, or another error.

## Behavior

The resource word, internal dependency-output slots, working inputs, publication pointer, allocation pointer, token, result word, and several arithmetic/status values are initialized to zero. The first four caller arguments are captured separately. An initial dispatch state comes from another global word.

Each dispatcher iteration includes:

1. A read of an additional global word before operation selection.
2. A separate read of the dispatch-offset global.
3. Selection using the current state plus that offset.

The first read is not the offset read. Certain operations retain it for state calculation; others overwrite the temporary carrying it. Neither global is established as stable across iterations.

Argument setup installs the captured second argument, the globally scaled first argument, the fifth argument, the captured publication pointer, and the captured fourth argument into their working locations. It also places the unscaled captured first argument into a separate mutable arithmetic intermediate.

### Arithmetic, unused computation, and live predicates

Ordinary word operations retain 32-bit results. Products, sums, subtraction, negation, and bitwise combinations use fixed-width word behavior; overflow discards bits beyond the retained width. Explicit signed interpretations supply arithmetic sign extension or a signed-negative test. The byte-field calculation retains eight bits.

Several predicates extract bit 31 from combinations of transformed words, complements, and offsets such as one or 65,536. Unknown global coefficients prevent generally classifying these as zero tests, sign tests, or checks of a particular application interval.

The larger arithmetic operation requires a distinction between an **unused computation** and the **live predicate**.

A query-output word is first multiplied by a global coefficient, retaining a 32-bit word. That word and the entry coefficient are then treated as unsigned 32-bit operands of a widened product. Its low 32 bits are used by the live calculation.

The upper 32 bits contribute only to an intermediate assignment whose result is never subsequently read. That unused assignment also combines a signed-extension term and an unsigned comparison against a global word. **The upper product half does not feed the final predicate**, either directly or through that assigned intermediate.

The unused assignment nevertheless contains a separate global read. The later live subtraction reads the same global location again. These are distinct source-level reads:

- The earlier read participates in the unsigned comparison within the unused assignment.
- The later read supplies the subtraction involving the product’s low half in the live calculation.

The read inventory must retain both occurrences. The unused result does not justify describing the live subtraction as consuming the earlier global snapshot.

The live calculation combines the product’s low half with further global values, then performs additional multiword arithmetic. It includes signed extension, explicit carry and unsigned-borrow terms, two-word negation and addition, bitwise combinations, and a final signed-negative test. It also consumes the adjacent internal pair initialized by configuration.

Thus, the live predicate still contains multiword arithmetic, but it is **not** a predicate consuming both halves of the widened product. Replacing it with an assumed application-level comparison, unrestricted integer arithmetic, or floating-point arithmetic is unsupported. Its intended numeric constraint remains **documented_only**.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Acquisition before setup.** If acquisition occurs before setup and no intervening operation changes the relevant state, the working second and fifth inputs are zero. Acquisition transforms a zero accumulator rather than the caller’s fourth argument.

2. **Accumulator replacement.** If setup loads the fourth argument, a query-derived operation replaces the accumulator, and acquisition follows, acquisition transforms the replacement. Reloading the original fourth argument would change the established behavior.

3. **Repeated acquisition.** Two acquisitions without an intervening accumulator writer apply successive affine transformations. Coefficients are read for their respective executions; unchanged values are not guaranteed.

4. **Unused upper product half.** Given identical live inputs, identical live-read results, and identical subsequent execution conditions, a difference confined to the widened product’s upper half cannot change the larger predicate through the unused assignment. The low half remains a live input.

5. **Separate predicate global reads.** If the earlier comparison read and later subtraction read return different values, the live subtraction uses the later value. The earlier value contributes to an unread intermediate, not to a reused snapshot for that subtraction.

6. **Construction snapshots.** Let the entry coefficient be \(E\), the cached construction coefficient be \(C\), and the separate offset-28 read be \(R\). Offset 28 uses its output word multiplied by \(E R\); offset 48 uses its output word multiplied by \(E C\), modulo \(2^{32}\). Requiring \(C=R\) adds an unsupported assumption.

7. **Publication order.** With valid storage and normally returning dependencies, the offset-0 store precedes the unmapped call. Publication follows every listed explicit field store.

8. **Unwritten bytes.** If bytes 34–35 initially contain nonzero values and no dependency modifies them, population leaves those bytes unchanged.

9. **Byte narrowing.** A working first input with low byte 1 yields 219 at offset 32. A low byte of zero yields zero. The working input need not equal the caller’s unscaled first argument.

10. **Null allocation.** A null allocation result selects the null-result state alternative. A specific error code or cleanup sequence cannot be inferred.

11. **Repeated output use.** A dependency that leaves an internal output unchanged preserves its current value, which may be a previous call’s result rather than entry-time zero.
