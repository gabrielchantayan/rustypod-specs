# F-2200228f531d

## Purpose

F-2200228f531d searches a linked sequence of records and returns the first record whose associated unsigned 32-bit value satisfies a query-dependent predicate.

The query selects one of two matching rules:

- **Exact-value matching:** if any bit in the query’s least significant byte is set, the associated value must equal the complete 32-bit query.
- **Any-bit matching:** if the query’s least significant byte is zero, the associated value must share at least one set bit with the complete 32-bit query.

A record whose associated-value address evaluates to null at the initial field check cannot match. The search continues through that record’s next link.

The search behavior and predicate selection are established by the supplied static representation. The application-level meaning of the records and query bits is unknown. Interpreting them as flags, categories, or identifiers would be inferred intent, not an established requirement.

## Behavior

### Entry and traversal

A null starting-record address returns null without accessing record memory.

For each nonnull current record:

1. The associated-value address field is evaluated for a null check.
2. If that evaluation yields null, the record cannot match. No associated value is read, and traversal proceeds through the next-link field.
3. If that evaluation yields nonnull, the associated-value address field is evaluated again. The address obtained by this second evaluation is used to read an unsigned 32-bit value.
4. The read value is compared with the query using the selected predicate.
5. A match returns the current record immediately. Otherwise, the next-link field is read and traversal continues from that address.

A null next-record address ends the search with a null result.

These are source-level evaluations and access dependencies. They do not require two distinct machine loads of the associated-value field: the accesses are not identified as volatile or atomic, and optimization may affect their realization.

### Exact-value mode

A nonzero least significant query byte selects equality.

All 32 bits of the associated value must equal all 32 bits of the query. Sharing query bits, or merely having the same low byte, is insufficient.

For example, query `0x00000101` does not match value `0x00000301`, despite their shared bits and identical low byte. It does match `0x00000101`.

### Any-bit mode

A zero least significant query byte selects a bitwise-intersection test.

A record matches when the associated value and the complete query share at least one set bit. The associated value need not contain every set bit of the query.

Because this mode requires the query’s low byte to be zero, bits confined to the associated value’s low byte cannot produce a match.

For example, query `0x00000300` matches either `0x00000100` or `0x00000200`. It does not match `0x000000FF`.

### Widths and arithmetic

The selector examines only query bits 0 through 7. It does not truncate the query used in either matching predicate.

Both the associated value and query participate as unsigned 32-bit values. Bit 31 can contribute to a match in any-bit mode and must agree in exact-value mode. Signed ordering is not used.

There is no numeric addition, subtraction, multiplication, or range comparison involving the query or associated value. Matching therefore introduces no arithmetic-overflow case.

Traversal obtains the next address from the link field. It does not advance to an adjacent record by adding a record size. The field position at byte offset 36 follows from the represented 4-byte slot width.

### Zero query

A zero query selects any-bit mode, but its intersection with every associated value is zero. No record can match.

This is not an early-return case. For each reached record, the function still:

- Evaluates the associated-value field for the null check.
- If that evaluation is nonnull, evaluates the field again and reads the associated value through the resulting address.
- Reads the next-link field because no match is possible.

Thus, zero does not avoid associated-value dereferences or make malformed storage safe. A stable cycle cannot terminate through a match when the query is zero.

### First match and termination

The earliest matching record in link-following order wins. Its next-link field and all later records are not examined.

There is no visited-record set, cycle detection, iteration limit, or separate cycle result. A stable cycle with no matching record repeats indefinitely, assuming its required accesses remain valid and execution continues.
