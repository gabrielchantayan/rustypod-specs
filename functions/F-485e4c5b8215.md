# F-485e4c5b8215

For each permitted index, it requests an entry address and, if that address is non-null, compares the integer at the beginning of the entry with the supplied target. It returns the index of the first match actually observed, or returns 0 when a freshly read bound excludes the current index.

The apparent intent is to locate a target integer within an address-based collection. That collection interpretation is inferred; the established behavior consists of object-relative memory reads, ordered dependency calls, conditional entry reads, and integer comparisons.

## Behavior

### Search progression and observable ordering

The initial index is 1. The function reads the bound before requesting any entry.

Each prospective lookup is authorized by comparing the current unsigned index with the newly read unsigned bound. A bound strictly smaller than the index terminates the function with 0, without a dependency call at that index. Equality permits the lookup.

For an authorized lookup, F-89ebe7aabbb8 is called with the computed address at object offset 12 and the current index. Any effects of that call occur before this function examines its returned address.

A null result is treated as a non-match, with no entry read. A non-null result causes a read of the integer at the returned address and an equality comparison with the target. Equality terminates the function immediately with the current index.

After either a null result or an unequal integer, the unsigned index advances by one. The next lookup requires another bound read. There is no bound recheck between a dependency return and acceptance of its matching entry.

This ordering matters if the dependency mutates the bound or entry storage. The function searches observations made during the call, not a demonstrated snapshot of the object.

### Bound behavior

The bound is not saved once for the whole invocation. Its value is read at every reached iteration, including an iteration that terminates with exhaustion.

With a stable bound of 3, lookups at indices 1, 2, and 3 are permitted. If none matches, the next bound read excludes index 4, and the function returns 0 without requesting that index.

An initial bound of 0 excludes the initial index 1. The function returns 0 without calling F-89ebe7aabbb8.

A dependency call can change the bound without invalidating the lookup already authorized by the preceding read. If that call returns a matching entry, the function returns its index even if the bound has meanwhile fallen below it. If the result does not match, the changed bound can affect the next iteration.

No preservation of the object or its bound across dependency calls is established. Continued validity of the bound storage is required whenever another iteration is reached.

### Entry interpretation and first-match behavior

Only the integer at the beginning of a non-null returned entry is inspected directly. The function does not establish or inspect an entry length, tag, string, secondary field, or validity marker.

A null address is skipped rather than treated as an immediate search failure. A non-null address is not otherwise validated before its initial integer is read.

The first-match rule concerns lookup order and observed values. In an ordinary non-wrapping traversal, the first observed match has the smallest index among the entries actually examined up to that point. This does not establish a minimum over a fixed collection if dependency calls alter entries or return time-dependent results.

Once a match is observed, this function performs no subsequent bound read or lookup.

### Unsigned wraparound and termination

When the current index equals the unsigned maximum, the bound check permits a lookup only if the bound is also that maximum. A non-match at that index advances the index to 0.

At index 0, no unsigned bound can be smaller than the current index. Provided execution and storage remain valid, the next dependency call therefore receives index 0 regardless of the bound value read for that iteration.

A match at index 0 returns 0. A non-match advances the index to 1, permitting another traversal.

A stable bound below the unsigned maximum yields finite exhaustion if every permitted dependency call returns normally, all required accesses remain valid, and no entry matches. A stable maximum bound with perpetual non-matches can instead produce repeated cycles. Dependency non-return, invalid storage, or changes to the bound prevent any unconditional termination guarantee.
