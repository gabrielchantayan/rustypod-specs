# F-60d5b4852dfa

## Purpose

F-60d5b4852dfa converts a byte-oriented input into a word-oriented expanded schedule. It recognizes selectors 128, 192, and 256, producing respectively 44, 52, and 60 unsigned 32-bit words and returning respectively 10, 12, and 14.

The structure is consistent with an AES-style key expansion. That interpretation is **inferred intent**, not an independently established algorithm identity: the supplied evidence does not include the contents of the substitution or constant tables. The contract below therefore defines the transformation in terms of those actual table values rather than assuming standardized cryptographic constants.

An unrecognized selector returns zero **after writing the first eight words**. It is not a side-effect-free validation failure.

## Interface

The function receives three arguments:

| Argument | Contract |
|---|---|
| Destination | Address of writable unsigned 32-bit words. The function also reads previously stored words from this region during expansion. |
| Input | Address of readable 8-bit bytes. Required extent depends on the selector. |
| Selector | A signed 32-bit integer compared exactly against 128, 192, and 256. It is not interpreted as a byte count or normalized to a supported value. |

The result is a 32-bit value:

| Selector | Input bytes consumed | Destination words written | Destination bytes written | Result |
|---:|---:|---:|---:|---:|
| 128 | 16 | 44 | 176 | 10 |
| 192 | 24 | 52 | 208 | 12 |
| 256 | 32 | 60 | 240 | 14 |
| Any other value | 32 | 8 | 32 | 0 |

These extents describe a completed execution with valid memory. There are no length arguments, pointer checks, alignment checks, or capacity checks.

For ordinary defined use:

- The input must be readable for the applicable extent.
- The destination must support the applicable 32-bit reads and writes.
- The destination and table addresses must satisfy the target’s requirements for word accesses.
- The external table configuration must identify valid readable storage.
- Input, destination, and table storage should be disjoint and stable if the caller expects the mathematical schedule specified below.

The function does not allocate, free, retain, or transfer ownership of either argument. It does not erase the input or clear the destination after use. Ownership and initialization of the external tables are not established by the supplied evidence.

## Behavior

### Word representation and arithmetic

Each input group of four bytes is interpreted in big-endian significance order. For bytes \(a,b,c,d\), the resulting unsigned 32-bit value is

\[
(a \ll 24)\ \oplus\ (b \ll 16)\ \oplus\ (c \ll 8)\ \oplus\ d.
\]

Each byte contributes to a distinct bit range, so these exclusive-OR operations have the same result as assembling the four byte fields.

This specifies the **numeric value of a destination word**, not a portable byte serialization of that word. Destination storage uses the target’s native 32-bit word representation. The input’s big-endian interpretation does not establish that destination memory contains big-endian bytes.

All schedule values, table values, masks, shifts, and exclusive-OR results are 32-bit quantities. Byte extraction uses unsigned values, including the most-significant-byte extraction. There is no sign extension of input bytes or schedule words.

### External table model

Before reading input bytes or writing destination words, the function reads a global address value. Call the captured address \(B\).

Two table views are derived from this captured address:

- \(C_j\): the 32-bit word at address \(B + 4j\).
- \(T_x\): the 32-bit word at address \(B - 6144 + 4x\), for byte index \(x\) from 0 through 255.

The table-base displacement is 6144 **bytes**, not words. Both table views use four-byte entry spacing. No wider table extent is established or required by this function’s indexed accesses.

The function does not reload the global address during expansion. It does, however, perform table-entry reads as the schedule is generated. Capturing the address is not a snapshot of the table contents.

For a word with bytes \(b_0,b_1,b_2,b_3\), listed from most to least significant, define two transformations.

The rotated transformation is

\[
R(x)=
(T_{b_1}\mathbin{\&}\texttt{0xFF000000})
\oplus
(T_{b_2}\mathbin{\&}\texttt{0x00FF0000})
\oplus
(T_{b_3}\mathbin{\&}\texttt{0x0000FF00})
\oplus
(T_{b_0}\mathbin{\&}\texttt{0x000000FF}).
\]

The unrotated transformation is

\[
U(x)=
(T_{b_0}\mathbin{\&}\texttt{0xFF000000})
\oplus
(T_{b_1}\mathbin{\&}\texttt{0x00FF0000})
\oplus
(T_{b_2}\mathbin{\&}\texttt{0x0000FF00})
\oplus
(T_{b_3}\mathbin{\&}\texttt{0x000000FF}).
\]

Each transformation uses four indexed 32-bit table reads and selects one byte lane from each value. The contract does not assume that the four lanes of an entry are equal, that entries contain replicated substitution bytes, or that repeated accesses to an entry can be collapsed into a single observable read.

Constant-table values are exclusive-ORed as complete 32-bit words. Their contribution is not masked to a particular byte lane.

### Initial writes and selector handling

The first four destination words are assembled from input bytes 0 through 15 and stored in increasing word-index order. This happens for **every** selector.

The subsequent behavior is:

1. If the selector is 128, expansion starts from those four words. No input bytes at offsets 16 or greater are read.
2. Otherwise, words 4 and 5 are assembled from input bytes 16 through 23 and stored in that order.
3. If the selector is 192, expansion starts from those six words.
4. Otherwise, words 6 and 7 are assembled from input bytes 24 through 31 and stored in that order.
5. If the selector is 256, expansion starts from those eight words.
6. Otherwise, the function returns zero without generating additional words.

Thus even a negative selector, zero, or a value close to a recognized selector follows the same unsupported-selector path. There is no early rejection before input consumption.

Each initial destination store follows the reads used to assemble that word and precedes assembly of the next word. The supplied expression structure does not establish the relative read order of the four bytes within a word.

### Schedule definition for stable, non-overlapping storage

Let \(W_i\) denote destination word \(i\). Initial words are assembled as described above.

For selector 128, words 4 through 43 are generated. For each generated index \(i\):

- When \(i\) is divisible by 4,

\[
W_i=W_{i-4}\oplus R(W_{i-1})\oplus C_{i/4-1}.
\]

- Otherwise,

\[
W_i=W_{i-4}\oplus W_{i-1}.
\]

Exactly ten constant entries are used: \(C_0\) through \(C_9\). The function returns 10.

For selector 192, words 6 through 51 are generated. For each generated index \(i\):

- When \(i\) is divisible by 6,

\[
W_i=W_{i-6}\oplus R(W_{i-1})\oplus C_{i/6-1}.
\]

- Otherwise,

\[
W_i=W_{i-6}\oplus W_{i-1}.
\]

Exactly eight constant entries are used: \(C_0\) through \(C_7\). The function returns 12.

For selector 256, words 8 through 59 are generated. For each generated index \(i\):

- When \(i\) is divisible by 8,

\[
W_i=W_{i-8}\oplus R(W_{i-1})\oplus C_{i/8-1}.
\]

- When the remainder of \(i\) divided by 8 is 4,

\[
W_i=W_{i-8}\oplus U(W_{i-1}).
\]

- Otherwise,

\[
W_i=W_{i-8}\oplus W_{i-1}.
\]

Exactly seven constant entries are used: \(C_0\) through \(C_6\). The function returns 14.

These equations describe the normal stable-memory result. They must not be treated as permission to snapshot input or tables when reproducing behavior involving overlapping or externally changing storage.

### Expansion order and final partial groups

Generated destination words are stored in strictly increasing index order.

For selector 128, expansion consists of ten groups of four stores. Each group begins by reading its preceding group’s last word for the rotated transformation. The remaining generated words form an exclusive-OR chain, with each new value feeding the next.

For selector 192, expansion consists of seven complete groups of six stores followed by a final group of four stores. The final group writes words 48 through 51 and stops. Words 52 and 53 are not generated.

For selector 256, expansion consists of six complete groups of eight stores followed by a final group of four stores. The unrotated transformation occurs only in the six complete groups. The final group writes words 56 through 59 and stops before any unrotated transformation or stores to words 60 through 63.

Within each group, the preceding group’s last word is captured before the first generated store. That captured value is reused for the last word of a complete group. Intermediate generated values are retained for the exclusive-OR chain rather than requiring a fresh read of the just-written destination word.

The relative ordering of individual table reads and other operands inside a single exclusive-OR expression is not established by the supplied evidence. No volatile-access or synchronization semantics are established.

## Side effects

The explicit writes are confined to the destination words listed in the interface table. Within that extent, every word is written once; no tail clearing or metadata write is shown.

The function:

- Reads the global table address once.
- Reads input bytes while performing the initial word stores.
- Reads earlier destination words during expansion.
- Reads substitution-table and constant-table words during supported expansions.
- Makes no explicit writes to the input, tables, or global address.
- Makes no calls, allocation requests, deallocation requests, logging operations, or callbacks.

Aliasing can make these categories overlap physically. For example, a destination store can overwrite input bytes that a later initial-word assembly will read. Likewise, destination overlap with a table can change the values used by later table reads. No overlap check or temporary copy protects against either case.

The function supplies no transactional behavior. An invalid memory access can occur after earlier destination words have already been written. The evidence establishes no recovery path, rollback, exception translation, or diagnostic result for such failures.

Unsupported selectors are the only explicit zero-result case. Zero does not indicate that destination memory was left unchanged.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reported runtime results.

### Input assembly and destination representation

Given valid disjoint storage and input bytes beginning with `01 23 45 67`, destination word 0 must have numeric value `0x01234567`, regardless of the recognized selector.

The bytes representing that word in destination memory depend on the target’s native word layout; requiring the destination bytes themselves to remain `01 23 45 67` would add an unsupported serialization requirement.

### Unsupported selector still consumes 32 bytes

Given selector 129, valid input bytes with values 0 through 31, and sufficient destination storage:

- The result must be zero.
- Destination word 0 must be `0x00010203`.
- Destination word 7 must be `0x1C1D1E1F`.
- Only destination words 0 through 7 are explicitly written.
- No substitution-table or constant-entry reads are required by this path, although the global table address is still read.

Supplying only 16 input bytes is not a valid unsupported-selector invocation.

### Recognized extents

With valid stable tables and disjoint buffers:

- Selector 128 must write exactly words 0 through 43 and return 10.
- Selector 192 must write exactly words 0 through 51 and return 12.
- Selector 256 must write exactly words 0 through 59 and return 14.

A sentinel immediately after each applicable destination extent must remain unchanged by this function’s explicit stores.

### Rotated lane selection

If the word entering a rotated transformation is `0x11223344`, the transformation must select:

- The most-significant byte lane from entry `0x22`.
- The next byte lane from entry `0x33`.
- The next byte lane from entry `0x44`.
- The least-significant byte lane from entry `0x11`.

The result is then combined with the appropriate earlier schedule word and complete constant word.

### Additional transformation for selector 256

For selector 256, word 12 must satisfy

\[
W_{12}=W_4\oplus U(W_{11}).
\]

It must not use the rotated transformation at this position, and no constant word is added at this position.

The corresponding extra transformation must not occur after word 59, because the function has already reached its final partial group.
