# F-967aafa9a357

## Purpose

F-967aafa9a357 initializes caller-provided storage as sixteen contiguous tables, each containing 256 four-byte words. Eight tables contain zero; eight contain the entry index positioned in one of four byte-sized fields of a 32-bit word.

The destination comprises two `0x2000`-byte groups with **different table arrangements**. For an entry index **i**, their values in ascending table-address order are:

- First group: **i shifted left 24 bits, zero, i shifted left 16 bits, zero, i shifted left 8 bits, zero, i, zero**.
- Second group: **zero, i shifted left 24 bits, zero, i shifted left 16 bits, zero, i shifted left 8 bits, zero, i**.

The groups contain corresponding value families, but are not identical memory images. Their zero and index-derived tables occupy opposite positions within each adjacent pair.

This is an initialization operation. Existing destination contents do not contribute to the result.

The arrangement is consistent with precomputed byte-contribution tables. That is inferred intent, not an established application-level purpose. No consumer is identified by the supplied evidence.

## Interface

**Input:** one address-bearing argument, represented as a signed 32-bit integer in the supplied source. Let **B** denote the destination address it identifies.

**Output:** no returned value. On normal completion, the result is the initialized destination region. During execution, the routine performs the destination assignments specified below.

**Storage extent:** `0x4000` bytes, or 16,384 bytes, beginning at B. The highest-addressed word begins at **B + `0x3FFC`** and occupies four bytes, ending at **B + `0x3FFF`**.

**Table layout:** sixteen tables of `0x400` bytes each. Each table contains 256 consecutive 32-bit entries with a four-byte stride.

Successful use requires:

- Every specified four-byte destination access is writable.
- The storage remains valid throughout execution.
- Address calculations identify the intended contiguous region.
- The destination satisfies the execution environment’s alignment requirements.
- The caller permits replacement of all prior contents in that region.

These requirements are not checked. The routine has no length, stride, mode, allocation, or status argument. It does not reject a represented address merely because its signed value is negative.

The signed integer representation of the address is not sufficient evidence of a portable pointer interface or of defined behavior for every 32-bit bit pattern. Pointer interpretation, address overflow, and mixed signed/unsigned address arithmetic remain target-dependent concerns.

## Behavior

### Final destination layout

Let **i** range from 0 through 255 inclusive. The entry for index i in a table with byte offset **T** begins at:

**B + T + 4 × i**

After normal completion, its numeric 32-bit value is:

| Table offset from B | Value at entry i |
|---|---|
| `0x0000` | i shifted left by 24 bits |
| `0x0400` | Zero |
| `0x0800` | i shifted left by 16 bits |
| `0x0C00` | Zero |
| `0x1000` | i shifted left by 8 bits |
| `0x1400` | Zero |
| `0x1800` | i |
| `0x1C00` | Zero |
| `0x2000` | Zero |
| `0x2400` | i shifted left by 24 bits |
| `0x2800` | Zero |
| `0x2C00` | i shifted left by 16 bits |
| `0x3000` | Zero |
| `0x3400` | i shifted left by 8 bits |
| `0x3800` | Zero |
| `0x3C00` | i |

Under valid contiguous address arithmetic, these tables cover the entire destination region without gaps or overlapping words.

The second group is **not a copy of the first group**. In the first group, each index-derived table precedes a zero table. In the second group, each zero table precedes its corresponding index-derived table. For example, the first group begins with the 24-bit-shifted table at `0x0000`; the second begins with a zero table at `0x2000`, followed by the 24-bit-shifted table at `0x2400`.

Both groups are populated directly. Neither group is read to construct the other.

### Traversal and assignment order

Indices are processed in ascending order, starting at zero and ending at 255. All sixteen destination assignments for an index occur before the first assignment for the next index.

For each index, the supplied source specifies this assignment order:

| Assignment position | Table offset |

| 1 | `0x0000` |

| 11 | `0x2800` |
| 12 | `0x2C00` |
| 13 | `0x3000` |
| 14 | `0x3400` |
| 15 | `0x3800` |
| 16 | `0x3C00` |

Each offset is augmented by **4 × i**. The order is not entirely ascending by address: the zero assignment at offset `0x1400` precedes the shifted-value assignment at offset `0x1000`.

The internal counter advances after assignment 14 and before assignment 15. The last two assignments nevertheless use the address and low-eight-bit value already established for the current entry. They therefore initialize index i, not index i + 1. The next iteration begins only after assignment 16 and the continuation check.

The first destination assignment stores zero at B. The final destination assignment stores the numeric value 255 at **B + `0x3FFC`**.

There are exactly 256 iterations and sixteen four-byte assignments per iteration: **4,096 destination assignments**. Each destination word is assigned once.

This is the order established by the supplied source. It does not establish individual machine-store instructions, atomicity, bus ordering, compiler barriers, or inter-thread visibility.

### Integer widths and bounds

The entry counter and value calculations use unsigned 32-bit quantities in the supplied representation.

For the unshifted, 8-bit-shifted, and 16-bit-shifted values, the counter is explicitly reduced to its low eight bits. Every processed index is already between 0 and 255, so this reduction does not alter any stored value.

The 24-bit-shifted values use the current counter directly. The largest values in the four index-derived table families are:

| Value family | Maximum numeric word |
|---|---|
| Shifted left 24 bits | `0xFF000000` |
| Shifted left 16 bits | `0x00FF0000` |
| Shifted left 8 bits | `0x0000FF00` |
| Unshifted | `0x000000FF` |

All results fit within 32 unsigned bits. The high bit in `0xFF000000` does not make the table’s specified numeric value negative.

The counter advances from 255 to 256 before termination. The continuation comparison uses a signed interpretation, but its compared values are only 1 through 256. No signed-range boundary is crossed, and this interpretation does not change the iteration count.

The maximum displacement within a table is **4 × 255 = `0x3FC`**. Adding the final table’s offset gives **`0x3C00` + `0x3FC` = `0x3FFC`**, the final word’s starting displacement.

These bounded offsets do not resolve address overflow involving B. A valid destination still requires the complete address calculation to identify accessible storage.
