# F-2a151965c5e4

## Purpose

F-2a151965c5e4 describes an indefinitely repeating computation that publishes address-derived values, samples a word through a changing pointer, invokes dependencies, and selects between repeating an inner cycle and re-entering an outer publication phase.

No ordinary return, completion status, allocation protocol, or application-level purpose is established. The observable contract is the ordering of calls, memory accesses, retained values, and state transitions.

Some computations have established unsigned 32-bit semantics. Others involve signed arithmetic, signed conversions, or an out-of-range shift whose concrete execution semantics are unresolved. Behavior following those operations is conditional; this contract does not replace them with assumed wrapping arithmetic.

The evidence is static. No runtime tests have been performed.

## Interface

### Explicit inputs

| Position | Represented input | Established role |
|---|---|---|
| 1 | Opaque 32-bit value | No direct consumption is visible in the function body. |
| 2 | Pointer to 32-bit words | Initial publication destination. Its address is also published and used in address arithmetic. |
| 3 | Opaque 32-bit value | No direct consumption is visible in the function body. |
| 4 | Unsigned 32-bit value | Initial carried value whose low byte is published at outer entry. Later transitions replace it. |

The absence of direct use of positions 1 and 3 does not establish their irrelevance to the actual calling convention or to dependencies.

### Additional incoming state

The represented body consumes four values without establishing their initial values:

- An unsigned 32-bit **accumulator**.
- A **source pointer** to a 32-bit word.
- A signed 32-bit **address seed**.
- A **continuation selector** used to determine indirect-call targets.

These are descriptive contract terms, not an inferred object layout. Their ABI origin and initial validity remain unknown.

The publication pointer, source pointer, accumulator, seed, selector, and carried fourth value persist until explicitly replaced. A dependency’s memory effects must not be mistaken for additional assignments to these retained values.

### Outputs and completion

There is no visible ordinary return path. Successful execution continues through outer publications and inner iterations indefinitely.

Progress can instead stop at an invalid memory access, a dependency that does not return, or the software breakpoint. No error code, recovery mechanism, or rollback is shown.

### Widths and memory requirements

The representation uses 8-, 16-, 32-, and 64-bit memory accesses, with pointer values represented in a 32-bit address domain. Integer and pointer ABI details have not been independently verified.

Every reached access requires a suitable address, alignment, and access permission. No validation precedes the accesses. In particular, address zero is not excluded.

No disjointness requirement is enforced. Publication destinations, source words, dependency-selected locations, and the global byte may overlap. Endianness and memory-mapped side effects are unresolved.

Established unsigned 32-bit operations wrap modulo \(2^{32}\). That rule does not extend to an earlier signed operation merely because its result is subsequently assigned to unsigned state.

## Behavior

### Outer entry and retained byte

Each outer entry derives a 32-bit **entry value** by shifting the unsigned accumulator left by two. Bits beyond the 32-bit result are discarded.

The low eight bits of the carried fourth value are then written to a global byte, and that byte is read into retained state. This read precedes both outer dependency calls.

The first outer call, **F-D01**, receives the source-pointer address represented as unsigned 32-bit and shifted right by two. Its target depends on the current continuation selector. Initially that selector is incoming state; on later outer entries it reflects prior transitions.

After this call returns, the selector is replaced with the outer continuation state. **F-D02** is then called and supplies a 64-bit result. The low and high 32-bit portions of that result serve as two address values, while the full 64 bits remain available for publication.

A dependency changing the global byte after its capture does not introduce another read. The later byte publication uses the captured value.

### Outer publications and replacement state

The first group of memory effects has the following ordering:

- The captured byte is published to the address obtained by converting the low result address to signed 32-bit and multiplying it by two.
- A byte derived from the high 32-bit result portion is published eight bytes after the low result address.
- The current publication pointer is stored as a 32-bit pointer at the address obtained by multiplying the signed address seed by two.
- The complete 64-bit dependency result is stored at the low result address.

The first and third address calculations contain signed multiplication. Their overflow is not established to wrap. The eight-byte displacement is a consequence of advancing by one 64-bit memory element, not by one byte.

These writes may overlap. The later 64-bit store can overwrite either earlier byte publication or the pointer publication. No restoration follows.

Next, the seed is replaced by four times the publication-pointer address after conversion to signed 32-bit. The accumulator is replaced by the source-pointer address converted to signed 32-bit and shifted left by eight. Both operations retain their signed-operation limitations.

Three ordered 32-bit stores then populate the publication destination:

| Byte offset | Published value |
|---|---|
| 0 | Entry value computed before the outer calls |
| 4 | Newly replaced accumulator |
| 8 | Current source-pointer address |

These are separate word stores, not an established atomic record update. They can overwrite overlapping earlier publications.

### Outer branch condition

The branch discriminator comes from the source-pointer address through a signed 32-bit conversion, a signed left shift by 31, a signed right shift by 32, conversion to unsigned 32-bit, and an unsigned right shift by 20.

A shift count of 32 is outside the ordinary defined range for a 32-bit operand. The preceding signed left shift can also lack defined semantics. Consequently, this representation does not establish a unique discriminator or prove either branch unreachable.

The following branch contracts apply only when the relevant execution semantics establish that branch.

### Zero-discriminator transition

The zero branch clears the global byte. It then adds the entry value to the current seed and stores the resulting 32-bit seed representation at the high result address from **F-D02**.

At this point, the seed already reflects the earlier multiplication of the publication-pointer address by four. The addition combines signed seed state with an unsigned 32-bit entry value. Under the represented integer widths, the addition is unsigned; assignment back to signed state remains subject to the applicable out-of-range conversion rules.

This transition enters the inner cycle with argument zero and replaces the carried fourth value with the entry value. It does not read a source word before that replacement.

The accumulator remains the value derived from the source pointer during outer publication. This branch does not execute the breakpoint or the alternate accumulator replacement.

### Nonzero-discriminator transition

The nonzero branch derives an unsigned 32-bit product by multiplying the entry value by 256. It stores the discriminator as a 32-bit word at that product plus 32 bytes. Both the unsigned multiplication and unsigned address addition wrap modulo \(2^{32}\).

The continuation selector changes to an alternate state. The initial inner-call argument is obtained by converting the product to signed 32-bit and shifting it right by 29.

Software breakpoint number 4 occurs before the remaining transition actions. Its handling, including whether execution resumes, is unknown.

If execution continues, the accumulator is replaced by the high result address from **F-D02**, converted to signed 32-bit and shifted right by 18. The resulting value is assigned to the unsigned accumulator. The carried fourth value becomes the entry value, and the inner cycle begins.

Signed conversion and signed right-shift behavior require the applicable execution semantics.

### Inner-cycle memory effects and sampling

Each inner iteration begins with **F-D03**, using the current inner-call argument. Its target depends on continuation state: outer continuation on a zero-branch entry, alternate continuation on a nonzero-branch entry, and inner continuation after an inner restart.

The returned 64-bit value has two distinct memory roles. Its low 32 bits supply an address for a 16-bit store derived from the returned value. Its high 32 bits supply the base for a later pointer load.

Before that pointer load, the inner cycle performs an unsigned accumulator multiplication by 64 and stores the resulting 32-bit product at the address equal to that product. This self-addressed store does **not** replace the accumulator. All subsequent accumulator-relative addresses still use the unchanged accumulator.

The current source pointer is then used to read a 32-bit **sampled word**. This sampling occurs after both the returned-value halfword store and the self-addressed product store. Either earlier store can therefore affect the sample through aliasing.

After sampling, a 16-bit value is stored at the accumulator address plus four bytes. Its value is derived by converting the old source-pointer address to signed 16-bit, adding four after integer promotion, and converting the sum for the halfword store. Under ordinary low-bit-preserving conversions, the stored bits are the low 16 bits of the old source-pointer address plus four. The conversion rules themselves are not independently established.

Only then is the source pointer replaced by a 32-bit pointer loaded from an address formed by converting the high half of **F-D03**’s result to signed 32-bit and adding 80 bytes. This addition is signed; overflow is not established to wrap.

Thus the sampled word and the first source-derived halfword concern the old source pointer. Later uses concern the replacement pointer.

### Inner calls and retained sample

After the replacement-pointer load, the visible call order is **F-D04**, **F-D05**, **F-D06**, then **F-D07**.

**F-D06** receives the sampled 32-bit word. Before **F-D07**, the selector changes to the inner continuation state. **F-D07** receives the sampled word shifted right by three as an unsigned value.

No intervening reload of the sampled word is shown. Dependency changes to the sampled memory do not themselves replace the retained argument value. This does not establish any general preservation rule for globals or dependency-owned memory.

The high 32 bits returned by **F-D07** replace the publication pointer before the subsequent result-address store and branch decision.

### Result address and continuation

The result address is derived from **F-D07**’s return value by conversion to signed 32-bit, multiplication by 32 as a signed operation, and assignment to unsigned 32-bit state.

The signed multiplication is defined mathematically within signed 32-bit range when its operand is between \(-67{,}108{,}864\) and \(67{,}108{,}863\), inclusive. Outside that range, overflow behavior is unresolved. The unsigned destination does not establish wrapping multiplication.

Where a result address is established, that 32-bit value is stored at the address equal to itself. Only afterward is it compared, as unsigned, against 19.

A result address at most 19 restarts the inner cycle with argument zero and replaces the carried fourth value with the sampled word. The source pointer and publication pointer retain their replacements, and the selector remains in the inner continuation state.

For a defined signed product followed by unsigned conversion, the result address is a multiple of 32. Consequently, the only such address at most 19 is zero. The address-zero store still precedes the restart decision.

A result address greater than 19 instead causes a 32-bit store of the accumulator at the result address plus 88 bytes, followed by a 16-bit publication derived from the replacement source-pointer address at the accumulator address plus 14 bytes. These unsigned address additions wrap modulo \(2^{32}\).

The outer phase then resumes. This exit does not replace the carried fourth value: it retains the entry value or the sample installed by the most recent restart.

## Side effects

The routine writes a global byte, caller-supplied publication memory, incoming-state-selected memory, dependency-selected memory, and arithmetic-derived addresses.

Writes are ordered but not transactional. A later fault, breakpoint, or non-returning dependency can leave earlier writes visible. No rollback or compensating publication is established.

Aliasing can affect both final memory and later reads. In particular:

- Outer publications can overwrite one another.
- The three publication words can overlap prior destinations.
- Inner stores preceding sampling can change the sampled word.
- The source-pointer-derived halfword store can affect the subsequent replacement-pointer load if their addresses overlap.

Retained values are not automatically reloaded because their originating memory changes.

No allocation, release, reference counting, locking, or ownership transfer is directly established. Passing or publishing a pointer does not establish ownership. Dependencies may have additional effects, including effects on global memory; none is assumed to preserve globals or own or release memory.

## Acceptance examples

These are conditional static consequences, not runtime observations.

1. **Captured byte survives later global modification.** A carried fourth value of `0x123456AB` causes outer entry to write and capture `0xAB`. If a dependency subsequently changes the global byte, the first outer publication still uses the captured value, provided execution reaches it.

2. **Overlapping publications preserve order, not earlier contents.** If the first byte destination lies within the later 64-bit destination, both writes are required in their represented order. The final byte need not retain the earlier captured value.

3. **Zero branch enters rather than returns.** Conditional on a zero discriminator and successful preceding operations, the global byte is cleared, the updated seed is stored at the high result address, and the inner cycle begins with argument zero and the entry value carried forward. No breakpoint occurs on this transition.

4. **Sampling precedes later dependency effects.** If the source read yields `0x40`, **F-D06** receives `0x40` and **F-D07** receives `0x08`. A later dependency changing the source word does not establish a reload.

5. **The accumulator product is not replacement state.** With accumulator `0x100` during an inner iteration, the self-addressed product store writes `0x4000` at address `0x4000`. The subsequent source-derived halfword destination is `0x104`, not `0x4004`, assuming the relevant accesses complete.

6. **Defined zero result attempts a zero-address write.** If the signed result-address operand is zero, the routine attempts a 32-bit zero store at address zero before restarting. A fault prevents the restart.

7. **Defined positive result re-enters the outer phase.** If that operand is 1, the routine stores 32 at address 32, then stores the accumulator at address 120, performs the replacement-source halfword publication, and re-enters the outer phase, conditional on successful accesses.

8. **Defined negative result uses unsigned comparison.** An operand of \(-1\) yields a defined signed product of \(-32\), then unsigned address `0xFFFFFFE0`. It compares greater than 19. Adding 88 wraps to address `0x00000038`.

9. **Overflow does not establish restart.** An operand of `0x08000000` overflows signed 32-bit multiplication by 32. Static evidence establishes neither a zero result address nor a restart. Only independently established wrapping execution semantics would yield zero and an attempted address-zero store.
