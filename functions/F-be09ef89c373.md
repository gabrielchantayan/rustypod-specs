# F-be09ef89c373

## Purpose

The available static evidence describes a stateful, machine-level operation that performs indirect calls, reads and writes memory through computed addresses, and follows arithmetic-dependent control flow. No application-level purpose is established.

The observable contract is therefore conditional: it specifies the operations visible in the supplied representation without assigning meanings such as “object,” “buffer,” or “allocator” to untyped addresses and dependencies.

Two broad paths are visible:

- A signed-subtraction-overflow path that performs additional memory accesses and then either reaches an invalid-instruction boundary or proceeds through a software interrupt to an unresolved indirect transfer.
- A non-overflow path that enters a repeated state-update sequence, with two visible routes to a shared return construction.

The supplied representation explicitly reports invalid instruction data and incomplete control-flow recovery. Consequently, this is a partial static contract, not a claim that every represented operation corresponds to an executable instruction sequence.

## Behavior

### Initial calls and state accesses

The visible sequence begins with an indirect call whose target depends on the incoming link-register value. After that call, the operation reads a 32-bit address from a location formed using a post-call register value and the incoming displacement. This address is referred to below as the **primary address**.

The next visible operations occur in this order:

1. An indirect call.
2. A byte write at primary address + 11, taking the low byte of the incoming displacement.
3. An indirect call.
4. An unsigned byte read at primary address + 15. The captured value is the **selector byte**.
5. An indirect call.
6. A byte write at primary address + 19, taking a post-call register byte.
7. An indirect call producing a base address.
8. A 32-bit read at that base address plus the selector byte. The captured value is the **selected word**.
9. Two further indirect calls, the second producing an **arithmetic word**.

The selector is a byte displacement. The evidence does not scale it by four or establish a word-array layout.

Calls intervene between several reads and writes. No preservation of pointed-to memory or global state by those calls is assumed. The selected byte and selected word are captured values; subsequent memory changes do not retroactively change them.

### Signed-subtraction-overflow path

The first branch tests whether subtracting the primary address from the selected word would overflow signed 32-bit subtraction. It does not merely test whether one address is less than the other.

When overflow is indicated:

1. Capture the arithmetic word shifted left by one, retaining 32 bits.
2. Form the selector byte plus 18. This value lies between 18 and 273 inclusive.
3. Call a dependency with the arithmetic word and its signed right shift by 25.
4. Treat the returned 32-bit value as a **region base**.
5. Write the wrapped selected-word-minus-primary-address difference at region base + 100.
6. Read a 32-bit **region word** at region base + 117,440,512.

A second branch tests two unsigned additions. Its condition is true if either:

- selector-plus-18 + region word carries out of bit 31; or
- the wrapped result of that addition, plus an extra value of zero or one, carries out of bit 31.

The extra value is one exactly when the unsigned region base is greater than 4,177,526,783. This comparison is strict.

If neither addition carries:

- Write one byte at a fixed-location base + 17.
- The byte is the low eight bits of selector-plus-18 + region word + the extra value.
- Reach the reported invalid-instruction boundary.

No ordinary return value is established for this branch.

If either addition carries, the visible sequence is:

1. An indirect call.
2. An unsigned byte read at region base + 117,440,520 + selector-plus-18.
3. An indirect call.
4. A 32-bit write of the earlier doubled arithmetic word at region base + 117,440,596.
5. An indirect call.
6. A 32-bit write of the zero-extended byte just read at region base + 117,440,580.
7. An indirect call.
8. A byte write at that zero-extended byte value plus selector-plus-18. The stored byte is the low byte of region base + 117,440,520.
9. An indirect call producing a word, followed by another call receiving that word minus 166.
10. A further indirect call.
11. Software interrupt number 74.
12. An unresolved indirect transfer, represented as receiving a fixed-location value, a byte read at that value + 9, a second fixed-location value, and an address of stack storage.

If the final transfer returns as represented, its 64-bit result is returned unchanged. Whether execution actually resumes after the software interrupt is unknown.

### Non-overflow entry

When signed subtraction does not overflow, a condition is captured from the arithmetic word:

- Arithmetic-right-shift it by nine.
- Interpret the shifted bits as unsigned.
- Compare that value strictly greater than 4,294,967,230.

A dependency is then called with:

- The arithmetic word.
- Its signed right shift by nine, plus 65.
- The selected word minus 60, followed by signed right shift by 20.

Its 64-bit result supplies a **low result word** and a **high result word**.

If the captured condition is false, execution enters the shared update sequence described below without the intervening halfword write.

If the condition is true:

1. Write the low 16 bits of the primary address at low result word + 42.
2. Compare the sign of the primary address with the signed-overflow flag for high result word minus 47.
3. If those Boolean values are equal, enter the shared update sequence.
4. Otherwise, prepare the loop body:
   - Set the pending value to incoming preserved-register value minus primary address.
   - Set the loop argument to the low result word shifted right logically by 25.

The overflow flag in step 2 is not the sign of the subtraction result.

### Loop body

The loop body performs:

1. An indirect call receiving the loop argument, the current high state word, and an address of stack storage.
2. An indirect call producing a 64-bit result.
3. A 32-bit write of the pending value at current high state word + 62.
4. Formation of an incremented state word by adding ten to the current high state word.

If the wrapped product of that incremented word and 65,536 is negative as a signed 32-bit value, execution returns through the shared return construction. Its lower result word is twice the low word from the immediately preceding 64-bit call. The write at current high state word + 62 occurs before this test.

Otherwise:

1. Write the low 16 bits of that call result at its upper word + 60.
2. Make an indirect call.
3. Make another indirect call producing an address.
4. Write the 16-bit value 38 at that address + 2.
5. Multiply the incremented state word by 268,435,456 with 32-bit wrapping, then arithmetic-right-shift by nine. Call this the **transformed value**.
6. Add the transformed value to the incremented state word, with wrapping.
7. Read a fixed-location 32-bit value.
8. Call a dependency with twice the address from step 3, and the wrapped product of the incremented state word and 65,536 minus 81.
9. XOR the sum from step 6 with the captured fixed-location value, producing a **derived address**.
10. Add 47 to the transformed value, producing an **adjusted value**.
11. Store the derived address in a represented stack slot.
12. Read a byte at derived address + 1 and call a dependency with a fixed address-like value, that byte, the adjusted value, and another post-call register value.
13. Write the adjusted value as a 32-bit word at derived address + 36.
14. Make an indirect call.
15. Form a new 64-bit state whose low word is the derived address and whose high word is the newly exposed post-call register value plus 48.
16. Enter the shared update sequence.

The fixed-location XOR operand is captured before the intervening call. It must not be silently re-read afterward.

### Shared update sequence and returns

The shared sequence accepts the current 64-bit state and:

1. Extracts its upper word as the current high state word.
2. Sets the loop argument to twice its low word, with wrapping.
3. Computes the pending value as four times the square of the high state word, retaining 32 bits.
4. Calls a dependency with the low state word plus the second incoming preserved-register value.
5. Reads a fixed-location 32-bit argument and calls another dependency with it.
6. Makes a further indirect call.
7. Tests a fixed-location control value.

If the control value is zero, the low word used by the shared return construction is a post-call register value arithmetic-right-shifted by nine. That word is then shifted left by one for the final lower 32 bits.

If the control value is nonzero:

- Write the pending value at twice the high state word + 52.
- Replace the high state word with a post-call register value.
- Repeat the loop body.

There is no visible iteration bound. Termination depends on dependency results, arithmetic state, and the control value.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Selector is a byte offset.**  
   Given a selector byte of 3 and a dependency-produced base address, the selected-word read is at base + 3, not base + 12.

2. **Signed overflow controls the first branch.**  
   Given a selected word of 2,147,483,647 and a primary address whose signed interpretation is −1, subtraction overflows signed 32-bit range. The overflow path is selected, and its stored difference is the wrapped word 2,147,483,648.

3. **The region-base threshold is strict.**  
   A region base of 4,177,526,783 contributes an extra value of zero to the carry logic. A region base of 4,177,526,784 contributes one. These examples do not establish that either address is valid.

4. **The second addition can determine the branch.**  
   If selector-plus-18 + region word is exactly 4,294,967,295 and the extra value is one, the first addition does not carry, but the second does. Execution takes the carry branch.

5. **The initial non-overflow condition is captured before the call.**  
   With an arithmetic word of −1, its signed right shift by nine is −1, whose unsigned interpretation exceeds 4,294,967,230. The halfword write at low result word + 42 precedes the later equality test.

6. **A loop return does not suppress the preceding write.**  
   If the incremented state word is 32,768, its wrapped product with 65,536 is negative. The pending-value write at the old high state word + 62 still occurs before returning.

7. **Zero control selects the alternate return input.**  
   If the fixed-location control value is zero, the operation returns using the shifted post-call register value. It does not perform the nonzero-path write at twice the high state word + 52.

8. **Dependency mutation remains observable.**  
   If a dependency changes a fixed-location value before a later explicit read, that read observes the value then present. A previously captured operand is not replaced with a fresh read.
