# F-a98bd2c7c864

## Purpose

F-a98bd2c7c864 coordinates three ordered operations over a caller-supplied four-word region and three resources selected from an object.

The established behavior is:

1. Query the first resource and submit a region anchored at the input region’s first two components.
2. Advance one component of a private working region.
3. Query the second resource and submit a region anchored against the input region’s fourth component.
4. Retreat that fourth component in the private working region.
5. Query the third resource and submit the resulting working region.

**Inferred intent:** the four-word records appear to represent rectangles, and the three operations appear to place upper and lower elements before processing the intervening area. Neither coordinate semantics nor rendering behavior is established independently of the dependencies.

This contract specifies the wrapper’s reads, arithmetic, argument construction, and call order. It does not assign undocumented behavior to the called functions.

## Interface

The function has three inputs and no explicit return value.

| Input | Established representation | Use |
|---|---|---|
| Object reference | Address represented by a 32-bit integer in the supplied representation | Supplies three 32-bit resource values at byte offsets `0xA8`, `0xAC`, and `0xB0`. |
| Operation context | Opaque 32-bit value | Forwarded unchanged to each of the two calls to F-945301cd184f and the final call to F-168345203dbe. |
| Region reference | Pointer to four consecutive 32-bit integer words | Read into private working storage before any dependency call. |

For descriptive purposes, denote the four initial region words by **A**, **B**, **C**, and **D**, in increasing address order. These are specification labels, not source identifiers.

Each four-word record occupies 16 bytes, with components at byte offsets 0, 4, 8, and 12. No additional fields or padding are exposed in the supplied representation.

The wrapper creates:

- A private working region initialized to `(A, B, C, D)`.
- A four-word query-result record.
- A separate four-word source record for the first and second submission calls.
- A separate four-word destination record for those calls.

## Behavior

### 1. Capture the input region

Before invoking a dependency, the wrapper reads all four input words into its private working region.

Consequences:

- Later ordinary modifications to the caller’s region do not change the already captured values.
- The caller’s region address is not forwarded directly to a dependency.
- The third word, **C**, is captured even though it does not participate in either initial destination calculation. It remains available for the final operation.

The supplied representation places these reads in component order. It does not establish a machine-level memory-ordering guarantee for concurrent access.

### 2. Query the first resource

The wrapper reads the 32-bit resource value at object offset `0xA8` and calls F-c24767c70ad0 with:

1. The address of its query-result record.
2. The resource value just read.

After this call returns, the wrapper copies the query-result record into its separate source record.

Denote this copied record by `(q₀, q₁, q₂, q₃)`. Its inferred horizontal and vertical extents are:

- Horizontal extent: `q₂ − q₀`.
- Vertical extent: `q₃ − q₁`.

The wrapper constructs the first destination record as:

| Component | Value |
|---|---|
| 0 | `A` |
| 1 | `B` |
| 2 | `A + (q₂ − q₀)` |
| 3 | `B + (q₃ − q₁)` |

The queried record is forwarded as a whole; it is not normalized to a zero origin.

### 3. Submit the first operation

The wrapper reads the resource value at object offset `0xA8` **again**, then calls F-945301cd184f with five arguments:

1. The newly read resource value.
2. The original opaque operation context.
3. The address of the copied source record.
4. The address of the constructed destination record.
5. The constant `0xFF`, numerically 255.

The second read is significant. If the query dependency changed the object’s resource slot, this call receives the changed value, not necessarily the value used for the query.

After this call returns, the wrapper advances the private working region’s second component by the difference between components 3 and 1 of the **source record as it exists after the call**:

- Working component 1 becomes its previous value plus that difference.

The update does not read the destination record or re-read the query-result record.

Therefore, if F-945301cd184f changes the supplied source record, those changes can affect the working region used later. Treating this update as necessarily using the original queried height would require an additional dependency guarantee.

### 4. Query the second resource

The wrapper reads the 32-bit resource value at object offset `0xB0` and calls F-c24767c70ad0 with the query-result record’s address and that resource value.

It then copies the returned query-result record into the separate source record, replacing the source record used for the first operation.

Denote this new copied record by `(r₀, r₁, r₂, r₃)`. The second destination record is constructed as:

| Component | Value |
|---|---|
| 0 | `A` |
| 1 | `D − (r₃ − r₁)` |
| 2 | `A + (r₂ − r₀)` |
| 3 | `D` |

The second destination is anchored using the original first and fourth region components. The advanced working second component does not participate in this destination construction.

### 5. Submit the second operation

The wrapper reads the resource value at object offset `0xB0` again and calls F-945301cd184f with:

1. The newly read resource value.
2. The original operation context.
3. The address of the current source record.
4. The address of the second destination record.
5. The constant `0xFF`.

As in the first operation, the resource queried and the resource submitted can differ if a dependency changes the relevant object slot.

After this call returns, the wrapper reduces the private working region’s fourth component by the difference between components 3 and 1 of the **source record as it exists after this second submission**.

Again, destination-record changes are not consulted for this update.

### 6. Query the third resource and submit the working region

The wrapper reads the resource value at object offset `0xAC` and calls F-c24767c70ad0 with the query-result record’s address and that value.

Unlike the first two stages, the wrapper does not copy this query result into the separate source record.

It then reads the resource value at object offset `0xAC` again and calls F-168345203dbe with six arguments:

1. The newly read resource value.
2. The original operation context.
3. The address of the query-result record itself.
4. The address of the private working region.
5. The constant `1`.
6. The constant `0`.

Immediately before this final call, the working region is:

- Component 0: `A`.
- Component 1: `B` plus the first post-submission source extent.
- Component 2: `C`.
- Component 3: `D` minus the second post-submission source extent.

The final call is the first dependency call that receives the working region’s address. The wrapper performs no further processing after that call returns.

## Side effects

The wrapper directly writes only its private records. It contains no explicit write to the caller’s region or to the object’s resource slots.

That does not establish that the overall invocation leaves those objects unchanged. Dependencies may have independently accessible aliases or other stateful behavior.

Observable interaction consists of six dependency calls in this order:

1. F-c24767c70ad0 for offset `0xA8`.
2. F-945301cd184f for offset `0xA8`.
3. F-c24767c70ad0 for offset `0xB0`.
4. F-945301cd184f for offset `0xB0`.
5. F-c24767c70ad0 for offset `0xAC`.

The wrapper contains no explicit allocation, release, resource acquisition, or resource cleanup. Passing a resource value does not establish ownership transfer.

Addresses of private records are supplied to dependencies. Their valid lifetime is bounded by this invocation; retaining or using those addresses afterward is not supported by the wrapper. Whether a dependency retains them is unknown.

There is no explicit status result, error translation, rollback, or retry. The wrapper does not inspect dependency return values. A dependency that does not return normally prevents completion of the subsequent sequence.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume each query supplies all four words, submission calls do not modify source records, resource slots remain stable, and arithmetic is representable.

### Ordinary three-part arrangement

Input region: `(10, 20, 110, 220)`.

First query result: `(2, 3, 22, 13)`.

- First source extent: width 20, height 10.
- First destination: `(10, 20, 30, 30)`.
- Working second component after submission: 30.

Second query result: `(0, 5, 30, 25)`.

- Second source extent: width 30, height 20.
- Second destination: `(10, 200, 40, 220)`.
- Working fourth component after submission: 200.

The final call receives the third query result directly and the working region `(10, 30, 110, 200)`. The initial third component, 110, was not replaced by either queried width.

### Source mutation affects the remaining region

Use the same input and first query result, but suppose the first F-945301cd184f call changes its source record to `(2, 3, 22, 18)`.

- The first destination was already constructed as `(10, 20, 30, 30)`.
- The subsequent working-region update uses height 15.
- The working second component becomes 35, not 30.

Changing only the submitted destination record would not produce this effect.

### Resource replacement between query and submission

Suppose object offset `0xA8` contains resource value X when the first query begins, and F-c24767c70ad0 changes that slot to Y.

- The query receives X.
- The following F-945301cd184f call receives Y.
- Its source record still comes from the query performed with X.

No resource-consistency check intervenes.

### Combined extents exceed the available interval

Input region: `(0, 0, 100, 10)`. First and second queried heights are both 8.

The final working region is `(0, 8, 100, 2)`. The wrapper still calls F-168345203dbe; it does not reject the inverted vertical interval.

### Zero or negative extent

A first query whose fourth component equals its second component produces zero destination height and no working second-component advance, absent source mutation.

If the queried vertical extent is negative, the first working second component decreases. For a negative second-stage extent, the working fourth component increases. No local validation prevents either outcome.
