# F-517e6995be3b

## Purpose

F-517e6995be3b conditionally forwards a decoded integer to an external dependency. For byte counts from zero through four, it compares a decoded 32-bit value against a 32-bit field in a caller-supplied state object. A difference causes a four-byte forwarding call and a return value of 1. Equality causes a separate notification call and a return value of 0.

Counts of five or more bypass decoding and comparison. They cause the same notification call and return value of 0.

The apparent intent is to decode a short, signed, big-endian integer and report a changed value. That interpretation is inferred from the arithmetic and comparison. The supplied evidence does not establish the application meaning of the value, the state field, or either dependency.

## Interface

### Inputs

The function takes six arguments, in this order:

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | Forwarding context | An opaque 32-bit value, passed unchanged as the first argument of the forwarding dependency when a difference is detected. |
| 2 | Encoded bytes | A byte-addressed pointer. Read only when the byte count is between one and four inclusive. |
| 3 | Byte count | An unsigned 32-bit integer. Values zero through four enter the decoding-and-comparison path; all other values bypass it. |
| 4 | Auxiliary word | An unsigned 32-bit value. It does not affect any established return value, dependency arguments, or caller-visible write. |
| 5 | Unused word | An opaque 32-bit argument with no use in the supplied body. |
| 6 | State address | An address represented by the supplied signed integer type. On the decoding-and-comparison path, a 32-bit unsigned field is read at byte offset 0x14 from this address. |

The contract uses 32-bit words and 8-bit bytes, consistent with the supplied representation and its explicit four-byte forwarding operation. An independently verified target ABI, pointer width, and alignment policy are not supplied.

### Output

The return value is a 32-bit word with two established values:

- **1:** decoding and comparison took place, the decoded value differed from the state field, and the forwarding dependency returned normally.
- **0:** either the byte count was at least five, or the decoded value equaled the state field, and the notification dependency returned normally.

These values describe the branch taken. They are not established success or failure codes for the dependencies: neither dependency’s return value is inspected.

### Memory requirements

For a byte count between one and four inclusive:

- The encoded-byte pointer must support the byte reads described below.
- The state address plus offset 0x14 must support a 32-bit read.
- The input bytes must remain suitable for reading throughout the decoding sequence. The first byte is read once to select sign handling and again during accumulation.

For a byte count of zero:

- This function does not dereference the encoded-byte pointer.
- The state field must still be readable.

For a byte count of at least five:

- This function does not dereference either the encoded-byte pointer or the state address.

These are direct-access requirements of this function. They do not constrain what an unknown dependency might access indirectly.

No null checks, buffer-length checks beyond the count branch, state-object validation, or explicit alignment checks are present.

## Behavior

### 1. Select the count-dependent path

The byte count is compared as an unsigned value against five.

If it is at least five, the function:

1. Does not read encoded bytes.
2. Does not read the state field.
3. Calls F-4fc89ec41a6d with the five argument values described under **Dependencies**.
4. Returns 0 if that call returns normally.

Although the auxiliary word is carried through local working storage on this path, it is not passed to the notification dependency and does not affect the established result.

If the byte count is zero through four, the function decodes a value and reads the state field.

### 2. Decode zero bytes

A zero byte count produces the 32-bit value zero.

There is no encoded-byte read. The auxiliary word participates in a local bit test in the supplied representation, but because the byte count is zero, that test cannot enable byte inversion or final negation. Consequently, the auxiliary word cannot change the decoded value.

The function proceeds to compare zero against the state field.

### 3. Decode one through four bytes

The function first reads the first encoded byte and tests its high bit, mask 0x80. That initial read determines sign handling for the entire decode.

It then reads exactly the specified number of bytes in ascending address order, starting with the first byte again. Thus, for a count of \(n\) in the range one through four, the direct source-read sequence is:

- One initial read at byte offset zero.
- Then reads at offsets zero through \(n-1\), in increasing order.

The initial byte is therefore read twice. The contract must not replace these with a single read when repeated reads are observable.

If the high bit from the initial read is clear, the bytes are accumulated in big-endian order. Earlier bytes occupy more significant positions than later bytes. The result is a 32-bit unsigned bit pattern; shorter inputs with a clear high bit have zero-filled upper bits.

If the initial high bit is set:

- Each subsequently read byte is inverted within its eight-bit value.
- Those inverted bytes are accumulated in big-endian order.
- The accumulated 32-bit value is incremented and then negated using unsigned 32-bit arithmetic.

All accumulation, increment, and negation results are interpreted modulo \(2^{32}\). There is no signed-overflow error path.

For stable input bytes, this is equivalent to interpreting the input as a big-endian two’s-complement integer of the supplied byte width, then representing that value in 32 bits. For inputs shorter than four bytes, negative values are sign-extended by the arithmetic rather than by an explicit sign-extension operation.

That equivalence depends on input stability. If the first byte changes between the initial sign read and its accumulation read, sign selection follows the first read while the accumulated byte value follows the second. The function does not take or validate a coherent snapshot.

### 4. Compare against the state field

After decoding, the function reads a 32-bit unsigned value from the state address at byte offset 0x14.

The comparison is exact equality of the full 32-bit bit patterns. There is no masking, tolerance, range normalization, or separate signed comparison.

This read occurs after all direct encoded-byte reads. The supplied body contains one direct state-field read on this path.

### 5. Forward a differing value

If the decoded value differs from the state field, the function calls the external forwarding dependency identified here as F-22000020.

The arguments, in order, are:

1. The original forwarding context.
2. The address of a local 32-bit word containing the decoded value.
3. The length value 4.
4. The number of completed accumulation iterations.
5. The original byte count.

On this branch, the fourth and fifth arguments have the same numeric value, between zero and four inclusive. For a zero-byte input that differs from the state field, both are zero even though the forwarded local object is four bytes long.

The dependency receives a pointer to the local decoded word, not the encoded-byte pointer and not the state-field address. The four-byte object’s in-memory byte order is the target’s native representation; the supplied evidence does not establish that native byte order.

After the dependency returns normally, the function returns 1. It does not inspect the dependency’s return value, re-read the local word, re-read the state field, or invoke F-4fc89ec41a6d.

### 6. Notify otherwise

If the decoded value equals the state field, the function calls F-4fc89ec41a6d and returns 0 after normal completion of that call.

This is the same notification call used for counts of at least five. The notification arguments do not distinguish equality from an out-of-range byte count.

## Side effects

### Direct reads and writes

The established direct caller-memory accesses are:

- Encoded-byte reads for counts one through four, in the order specified above.
- One 32-bit state-field read for counts zero through four.

The function does not directly write to the encoded bytes or the state object. In particular, detecting a difference does **not** directly replace the stored state field.

Local working storage is initialized and updated during decoding. On the differing-value branch, the address of one local 32-bit object is exposed to F-22000020.

### Ownership and lifetime

The supplied body performs no explicit allocation, deallocation, ownership transfer, or release of caller-provided memory.

The forwarded pointer refers to local storage whose lifetime is limited to the current invocation. The body does not arrange for that storage to remain available after return. A consumer requiring a lasting value would need an independent lifetime arrangement; whether F-22000020 makes a copy is unknown.

The forwarding dependency is not established to be read-only. It may modify the pointed-to local word. Such a modification does not alter this function’s branch result after normal dependency return.

Neither dependency is established to preserve global state, preserve caller-owned objects, avoid allocation, avoid releasing resources, or refrain from reentrant activity.

### Errors and abnormal completion

The body provides no explicit recovery for inaccessible memory, invalid addresses, alignment faults, or abnormal dependency termination.

An invalid encoded-byte pointer does not itself cause a direct read on the zero-byte or at-least-five-byte paths. An invalid state address does not itself cause a direct read on the at-least-five-byte path.

If a required read or dependency call does not complete normally, the supplied evidence does not establish a returned value. A return of 0 must not be interpreted as a general memory-error or dependency-error report.

## Uncertainties

The following items are **documented_only**:

- The application meaning of the encoded integer and the state field.
- The exact target ABI, native byte order, alignment requirements, and address-arithmetic rules.
- The authoritative identity and complete signature of F-22000020.
- The behavior, side effects, ownership rules, and termination guarantees of both dependencies.
- Whether the exposed local-word pointer is copied, retained, or modified by F-22000020.
- Whether concurrent mutation, volatile memory, or memory-mapped input is permitted by the surrounding system.
- The fault behavior for invalid pointers or unavailable memory.
- Whether callers impose a narrower valid byte-count range than the function itself accepts.

Signed big-endian decoding is an inferred intent supported by the stable-input arithmetic. “Changed value” forwarding is likewise an interpretation of the comparison and call. Neither interpretation establishes a higher-level protocol.
