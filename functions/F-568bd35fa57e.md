# F-568bd35fa57e

## Purpose

F-568bd35fa57e obtains a selector through an indirect callback, accepts only selector bytes zero and one, and requests a corresponding operation from F-364a7aebb37d. It returns a 32-bit status: zero when the requested operation reports success, or three when the selector is unsupported or the operation reports a nonzero result.

The selector is the low eight bits of a callback-accessible 32-bit temporary. The fourth argument initializes that entire temporary before the callback executes. Consequently, the fourth argument supplies the selector if the callback leaves the temporary unchanged.

This is an independent contract based on static evidence. It establishes the wrapper’s explicit decisions and effects, not the internal behavior of either dependency. No runtime tests have been performed.

## Behavior

### Selector storage and callback invocation

The function first initializes a private 32-bit temporary from the fourth argument. This initialization precedes the callback and does not depend on the first or third arguments.

To invoke the callback, it reads the dispatch-table address through the second argument and obtains the callable entry at table offset eight. It calls that entry with two arguments:

- The dispatch-bearing object address supplied as the second argument.
- The address of the initialized 32-bit temporary.

No explicit null check or validity check precedes this dispatch. A valid object, readable dispatch information, and a callable target are therefore preconditions for defined normal execution.

The callback can inspect or modify the temporary through the supplied address. The wrapper does not require the callback to write it: unchanged storage remains initialized from the fourth argument. Any callback return value is not used in the wrapper’s subsequent decision.

The wrapper evaluates the temporary only after the callback returns normally. A callback that does not return prevents all later wrapper behavior described below.

### Selector interpretation

Only the low eight bits of the temporary determine the selector. The other 24 bits do not participate in validation or in the mode passed onward.

The accepted selector values are exactly:

- Zero: select mode zero.
- One: select mode one.

Every other low-byte value, from two through 255 inclusive, causes the function to return status three without invoking F-364a7aebb37d.

This is a numeric low-byte rule, not a truth-value conversion. In particular, the function does not treat every nonzero byte as mode one. A word whose low byte is two is rejected even if other interpretations might consider it “enabled.”

The decision uses the post-callback temporary. An initially unsupported selector may become accepted if the callback changes it. An initially accepted selector may become unsupported.

### Requested operation

For either accepted selector, the function invokes F-364a7aebb37d with these three arguments, in order:

1. The original first argument.
2. A 32-bit mode value equal to zero or one, as selected above.
3. The first argument plus 4216.

The derived third argument uses the same original first-argument value as the first dependency argument. The visible wrapper performs no bounds check, object-layout check, or overflow check for this calculation.

The recovered expression presents the addition in a signed 32-bit integer context. Static evidence does not establish a portable rule for overflowing that expression. A specification consumer should not silently substitute unbounded arithmetic or guarantee wraparound. For ordinary address-like uses, require that the derived value be valid under the actual execution model and satisfy the callee’s requirements.

F-364a7aebb37d is called once on the supported-selector path. It is not called on the unsupported-selector path.

### Result mapping

After F-364a7aebb37d returns, the wrapper compares its result with zero.

- A zero result produces wrapper status zero.
- Any nonzero result produces wrapper status three.

The wrapper does not preserve distinct nonzero dependency results. A dependency result of three has no special treatment relative to another nonzero result.

There is no visible compensating operation or rollback after failure. Returning three does not establish that either dependency left state unchanged.
