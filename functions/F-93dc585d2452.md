# F-93dc585d2452

## Purpose

If either comparison differs, it replaces both stored values with the low 16 bits of the corresponding inputs and invokes F-b9206d15ac57. If both comparisons match, it leaves those fields unwritten by this function and invokes F-7fef71cf7cf3.

An initial call to F-8a2b303ae860 precedes all demonstrated record accesses. Its effects are unknown, so the comparison concerns the record contents after that dependency returns, not necessarily the contents at function entry.

The distinction between full-width comparison and truncated storage is essential: a request containing any nonzero upper 16 bits cannot match its corresponding stored field, even when its low 16 bits already equal that field.

### Comparison

After the initial dependency returns, the function reads the unsigned 16-bit field at offset +6 and extends it to an unsigned 32-bit value.

It compares that extended value with the complete 32-bit first request.

If they differ:

- The function selects the replacement path.
- It does not directly read the 16-bit field at +8 before replacing it.

If they match:

- The function reads the unsigned 16-bit field at +8.
- It extends that value to 32 bits.
- It compares that extended value with the complete 32-bit second request.
- Equality selects the unchanged path; inequality selects the replacement path.

Thus, equality requires both requests to lie between 0 and 65,535 inclusive and to match their respective stored values. The requests are not truncated before comparison.

### Replacement path

On this path, the function performs these direct record accesses in order:

1. Writes the low 16 bits of the first request to offset +6.
2. Writes the low 16 bits of the second request to offset +8.
3. Reads the 8-bit payload at offset +4.

Both writes occur regardless of which comparison differed. A field whose numeric value already matches the corresponding truncated request is still written.

The function then calls F-b9206d15ac57 with six logical arguments, in this order:

### Arithmetic and boundary behavior

Storage uses only the low 16 bits of each request, equivalent to reduction modulo 65,536 for unsigned 32-bit inputs. There is no saturation, range rejection, or sign-based interpretation.

The full-width comparisons produce an important non-idempotent dispatch case: a request above 65,535 always selects replacement, even after a previous invocation stored its low 16 bits. Repeating that request can therefore repeat both writes and the replacement call without changing the resulting 16-bit numeric values.
