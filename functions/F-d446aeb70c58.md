# F-d446aeb70c58

## Purpose

F-d446aeb70c58 conditionally updates three locations in caller-supplied object storage. A primary byte flag gates all further work. When that flag is nonzero, the function reads a four-byte object field and a global datum, then supplies their values to an authorization dependency. A nonzero authorization result enables an ordered sequence: issue a notification, obtain and store a replacement four-byte value, clear the primary flag, and inspect a secondary byte flag. A nonzero secondary flag causes a second notification followed by clearing that flag.

“Primary flag,” “secondary flag,” “authorization,” and “replacement field” describe roles in this function. They do not establish application semantics. In particular, the evidence does not identify the operation as resource release, acknowledgment, timeout processing, or a lifecycle transition.

This contract distinguishes the function’s direct operations from effects of its dependencies. All established behavior comes from the supplied static body. No runtime tests have been performed.

## Behavior

### Initial gate

The function first reads one byte at object offset `0x45e`.

If that byte is zero, it returns immediately. This path has:

- No read of the four-byte object field.
- No read of G-01.
- No read of the secondary flag.
- No dependency call.
- No direct write.

A nonzero secondary flag cannot independently activate processing when the primary flag is zero.

### Authorization inputs and decision

For a nonzero primary flag, the function obtains:

- The current four-byte value at object offset `0x460`.
- The value read from global datum G-01.

It passes these as the first and second arguments, respectively, to F-dep-01. Both values are obtained for this call after the primary gate succeeds. Their relative acquisition order is not established.

F-dep-01’s result is tested against zero:

- A zero result causes an immediate ordinary return.
- Any nonzero result enables the primary transition.

No positive-only success rule, canonical Boolean requirement, or negative-result error convention is evidenced. The function does not expose the result to its caller.

When F-dep-01 returns zero, this function has made no direct write and calls no further dependency. This does not guarantee unchanged object or global state: F-dep-01’s effects are unknown.

### Primary transition

After a nonzero authorization result, the following actions occur in order, provided each preceding call returns normally:

1. Call F-5da1ad7278c2 with numeric argument `10`.
2. Call F-dep-02 with no explicit arguments.
3. Store F-dep-02’s four-byte result at object offset `0x460`.
4. Store a zero byte at object offset `0x45e`.
5. Read one byte at object offset `0x45f`.

The notification with argument `10` therefore occurs before replacement-value acquisition, and replacement-value acquisition occurs before either direct store. The four-byte replacement store precedes the primary-flag clear.

Neither the primary flag nor the authorization decision is rechecked during this sequence. A dependency may change the primary flag or the four-byte field, but such changes do not cancel the later direct stores if execution returns normally to them.

The secondary flag is not read or cached at entry. Its controlling observation occurs only after the replacement store and primary clear. Changes made by earlier dependencies can therefore determine whether the secondary transition occurs.

### Secondary transition

If the secondary read observes zero, the function returns. It issues no notification with argument `11` and makes no direct store to the secondary flag on that path.

If the secondary read observes any nonzero byte, the function:

1. Calls F-5da1ad7278c2 with numeric argument `11`.
2. After that call returns normally, stores a zero byte at object offset `0x45f`.
3. Returns.

There is no new secondary-flag test after the notification. Even if the notification changes that flag, the subsequent direct store still clears it when reached.

The second notification occurs after the primary-transition writes. Its unknown effects may modify the replacement field or primary flag again. Consequently, completion of the earlier stores alone does not establish those locations’ final values after the second notification.

### Widths and arithmetic

The two flag reads and their direct clears are one-byte operations. The object-field read, replacement result, and replacement store are four-byte operations. These direct stores do not extend into adjacent fields.

The visible arithmetic consists of adding fixed offsets to the input base. No arithmetic, range adjustment, increment, or subtraction is performed on the four-byte field.

The authorization result is represented as an integer in the supplied body, but its exact ABI width is not independently established. Only its zero/nonzero classification affects this function. The widths used to pass notification arguments are likewise not established; their numeric values are `10` and `11`.

## Side effects

### Direct effects

The function directly reads:

- The primary flag on every invocation reaching the body.
- The four-byte field and G-01 only after a nonzero primary observation.
- The secondary flag only after successful authorization and completion of the primary-transition stores.

Its direct writes are limited to replacing the four-byte field, clearing the primary flag, and conditionally clearing the secondary flag. No direct global write appears in the body.

The first two writes require a nonzero primary observation and nonzero authorization result, followed by normally returning calls. The secondary clear additionally requires a later nonzero secondary observation and normal return from the notification with argument `11`.

## Acceptance examples

These examples are conditional acceptance criteria, not executed tests. Unless stated otherwise, they assume valid storage, normally returning dependencies, and no interference or dependency-induced changes beyond those described.

### Primary gate disabled

Given a zero primary flag and a nonzero secondary flag, execution returns after reading the primary byte.

Acceptance requires no dependency call, no G-01 read, no four-byte-field read, no secondary read, and no direct write.

### Authorization rejects the transition

Given a nonzero primary flag and an F-dep-01 result of zero:

- The four-byte field and G-01 are read to prepare F-dep-01’s arguments.
- No relative order between those two reads is required.
- F-dep-01 is the only dependency invoked.
- No direct object write occurs.

Changes made internally by F-dep-01 do not violate the no-direct-write requirement.

### Global value changes between invocations

Suppose two invocations both observe a nonzero primary flag, and G-01 has different values at their respective argument-preparation reads.

Each authorization call must receive the value read for that invocation. Acceptance must not substitute a fixed constant or reuse a previously cached value.

This criterion does not define the outcome of an unsynchronized concurrent modification during a read.

### Primary transition only

Given nonzero authorization, an F-dep-02 result R, and a secondary flag that reads as zero after the primary stores, the required sequence is:

- F-dep-01.
- F-5da1ad7278c2 with `10`.
- F-dep-02.
- Four-byte store of R.
- Primary-byte clear.
- Secondary-byte read.

There is no notification with `11` and no direct secondary clear.

### Both transitions

Under the same conditions, except that the secondary read observes nonzero, acceptance additionally requires F-5da1ad7278c2 with `11`, followed by a zero-byte store to the secondary flag.

The second notification must occur after the primary clear and before the secondary clear.

### Noncanonical nonzero values

A primary byte of `0x80` enables authorization just as `0x01` does. A secondary byte of `0xff` enables its notification. An authorization result other than zero enables the primary transition even when it is not one.

### A dependency changes the secondary flag

If the secondary flag starts at zero but an earlier dependency makes it nonzero before the secondary read, the second notification is required.

If the flag starts nonzero but becomes zero before that read, the second notification is omitted. Entry state does not control this branch.

### The final notification changes object state

If the notification with `11` writes a nonzero secondary byte and returns normally, the function subsequently clears that byte without rechecking it.

If that notification also changes the primary flag or replacement field, this function does not subsequently restore those two locations. Acceptance must distinguish the earlier direct stores from final object state.
