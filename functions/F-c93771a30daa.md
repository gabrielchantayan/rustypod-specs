# F-c93771a30daa

## Purpose

F-c93771a30daa conditionally initializes incoming state, publishes values to address-dependent storage, and enters repeated acquisition and publication through opaque dependencies.

The established behavior is a contract of access widths, access ordering, arithmetic, and control transitions. It does not establish a device, protocol, application purpose, or successful completion condition.

Under the represented control calculations, neither initialization outcome selects the available return transaction. Continuing execution can repeat acquisition without further output. Extended processing reaches an invalid full-width shift, beyond which branch behavior is not established.

All conclusions below are static. No runtime execution, tests, or instruction-level validation have been performed.

## Interface

### Inputs

The formal interface contains five 32-bit argument positions. Only the third and fifth have direct uses:

- The third is signed and supplies an initial displacement through multiplication by 256.
- The fifth is signed and participates in a later address-and-value calculation.
- No direct consumption of the first, second, or fourth argument is shown. This does not establish their irrelevance to an unknown calling convention.

Additional incoming state supplies a 32-bit unsigned control word, a working-address representation, a 16-bit setup datum, a 32-bit unsigned seed, and two values used to select indirect dependencies. One dependency-target input is unsigned; the other is signed.

Two signed 32-bit global values provide a base and a scale. Initialization also consumes a signed 32-bit quantity available after F-01, whose origin is not established.

### Outputs and representation

No returned data value is established. The structurally represented return transaction performs a valueless return if F-02 completes normally; ordinary entry does not select that transaction.

Addresses and words are represented in 32 bits; halfwords occupy 16 bits; bytes occupy 8 bits. F-03, F-07, and F-09 return 64-bit quantities whose low and high 32-bit portions have different roles.

All stated offsets are byte offsets, including those arising from advancement of typed pointers. Unsigned 32-bit arithmetic wraps modulo \(2^{32}\). Signed arithmetic is not assigned wrapping semantics.

### Preconditions and ownership

Every reached memory operation requires a valid address, sufficient extent, appropriate alignment and permissions, and a live storage object under the applicable execution model. Address zero and apparently unaligned addresses are not exempt.

No explicit bounds checks, allocation, release, ownership transfer, rollback, or error result are represented. The caller cannot infer that a dependency preserves memory, globals, hidden state, or ownership merely because an argument or result is absent.

## Behavior

### Initialization and retained observations

The base is read before initialization selection. This observation is retained independently of any subsequent base read.

The third argument is multiplied by 256 using signed 32-bit arithmetic; its result becomes an unsigned displacement. This calculation occurs even when initialization will replace the displacement. Later replacement therefore does not eliminate an earlier signed-overflow problem.

Before initialization, the publication basis is the control word shifted left five using unsigned arithmetic, then converted to signed. The anchor address is `0xA1`.

Initialization is selected whenever any of control bits 0–23 is set. Otherwise, the incoming working address and seed remain current, along with the initial displacement, basis, and anchor.

Selected initialization has these ordered external effects:

- Interrupt-designated storage receives logical value `0x18`, followed by a write of the setup datum to storage at `0x225FB880`.
- A fresh base observation, added to the displacement using unsigned arithmetic, selects a byte destination receiving `0xCE`.
- Storage at `0x0CE00026` is read and converted to the seed. Storage at `0x0CE00000` then receives zero.
- F-01 receives three arguments: control bits 0–23 shifted right ten, `0xC0`, and address `0x0CE00000`.

The physical widths and extension behavior of these symbolic-storage operations are incompletely declared.

After normal F-01 completion, the working address is derived by signed left shift of the retained entry base by one. The displacement becomes `0x0897ECA0`. The scale is then read and multiplied by 32 using signed arithmetic.

Two halfword writes of `0xECA0` follow. Their destinations are, respectively, four times the unexplained post-F-01 quantity, and the scale product plus six. Both address calculations are signed. The scale read precedes both writes.

Completed initialization establishes control 16, basis zero, and anchor zero. A later change to the base does not replace the retained entry observation. Changes affecting the later scale read can affect its result.

### Common publication and routing

Both initialization outcomes perform four distinct publications in order:

| Destination | Publication |
|---|---|
| Basis plus `0x30` | Halfword converted from the basis |
| Control multiplied by `0x02000000`, plus `0x40` | Word containing that multiplication result |
| Anchor | Zero byte |
| Anchor | Seed word |

The basis-relative addition is signed. The control multiplication and its offset addition are unsigned. Conversion of the basis to signed halfword is subject to the conversion uncertainties below.

The anchor byte and word writes remain separate obligations, even when they overlap completely.

The return transaction requires control bit 6 and at least one of control bits 0–5. Initialization establishes control 16, which fails this condition. Skipping initialization requires all low 24 control bits to be clear, which also fails it. Thus ordinary entry selects continuing processing, provided preceding operations have valid execution semantics.

### Structurally present return transaction

This transaction is described for completeness, not as an ordinary-entry outcome.

Its primary destination is control multiplied by `0x04000000` using unsigned arithmetic. Advancing that byte pointer by the seed produces a secondary destination.

Publication begins with a zero byte at the primary destination, then a halfword converted from the anchor at working address plus two. Next, the secondary address is written as a word at secondary offset `0x40`, followed by a halfword converted from that address at the secondary destination itself.

The working-address addition is signed; secondary-address construction requires valid pointer arithmetic.

A separate address is formed by unsigned control multiplication by `0x40000000` and addition of `0x11`. After signed conversion, that address receives a word containing its own address representation.

Another destination depends on the bitwise intersection of displacement and secondary address: the intersection is shifted left one unsigned, converted to signed, and shifted right ten. Two distinct, identical halfword writes publish the converted destination address there. The unsigned intersection plus two then receives halfword `0x0050`.

The remaining order is:

1. Logical value `0xF430` is written to storage at `0xFD`.
2. Reset-designated storage receives `0x0897F430`.
3. Undefined-instruction-designated storage receives zero.
4. Supervisor-call-designated storage is read and converted through an unsigned word into an address.
5. That address receives word `0x0897F430`.
6. F-02 is invoked; normal completion is followed by a valueless return.

F-02’s first argument is derived by advancing the supervisor-supplied word pointer by 16 bytes, converting the result to signed, and multiplying by `0x01000000`. Its other arguments are zero, `0x5000`, and `0x56`. Pointer validity and signed-multiplication validity remain prerequisites.

### Continuing publication

Continuing processing first writes word `0x40` at anchor offset `0x28`, followed by the anchor address at offset `0x2C`.

The initial accumulated total is seed intersected bitwise with displacement. The descriptor is eight times displacement minus two. The processing address is displacement multiplied by `0x01000000`; the output address initially equals it. Initial stride is displacement multiplied by `0x02000000`, and initial payload is zero. These calculations are unsigned.

Separately, the signed interpretation of the working address is added to the fifth argument, then increased by eight. A word containing that result is written at twice the result. Both additions and the doubling are signed operations.

The displacement is written as a word at anchor offset four. A character-converted descriptor is then written as a byte at processing-address offset `0x14`. The character type’s signedness is not established.

Each output transaction performs a zero-byte write, a converted-descriptor halfword write, and a payload-word write at the processing address, in that order. It then increases the accumulated total by the current stride using unsigned arithmetic and writes the updated total at the output address.

The first output transaction precedes acquisition. Its four writes share one address. Later transactions can use different processing and output addresses.

### Acquisition and short continuation

Immediately before every F-03 invocation, the current stride’s low byte is captured. Replacing stride during that acquisition does not replace the captured byte.

F-03 has four distinct target forms, selected by acquisition history: initial entry, short continuation, output re-entry, and breakpoint continuation. The first three receive selector zero.

After normal F-03 completion, memory effects occur in this order:

- Its low result word selects a halfword destination, which receives the converted result value.
- Descriptor multiplied by 64 unsigned selects a word destination, which receives its own address.
- A word read through the old working address replaces stride.
- Descriptor plus four receives a halfword derived by converting the old working address to signed halfword before adding four.
- A word read at the signed interpretation of F-03’s high result word plus `0x50` replaces the working address.

The last address addition is signed. The halfword-derived addition is performed after integer promotion, not by adding four to the full working address before conversion.

These operations are alias-sensitive. Either of the first two writes can affect the stride read. The intervening halfword write can affect the replacement-working-address read.

F-04, F-05, F-06, and F-07 follow in that order. F-06 receives the acquired stride; F-07 receives that stride logically shifted right three.

F-07’s high word supplies a field-area address. Its low word is converted to signed and multiplied by 32; the unsigned representation of the result is the candidate address. Before any candidate-dependent routing, the candidate receives a word containing its own address.

A candidate below `0x14` selects another acquisition, without an output transaction. Descriptor and accumulated total are retained; acquired stride and replacement working address remain current. The next invocation uses F-03’s short-continuation target and selector zero.

Where the signed multiplication is valid, zero is the only candidate below `0x14`.

### Extended publication

A candidate of at least `0x14` selects extended processing. First, the descriptor is written as a word at candidate offset `0x58`. Next, a converted replacement working address is written as a halfword at descriptor offset `0x0E`.

Revised stride is descriptor shifted left two unsigned. Reset-designated storage then receives a logical value combining the captured byte in its low eight bits with a three-byte reset-associated value in its upper 24 bits. The associated read follows the two preceding publications. Its exact physical overlap and access decomposition are not declared.

F-08 receives the replacement working address logically shifted right two. F-09 follows and supplies a 64-bit result. Its low word identifies result storage; its high word becomes the output address.

Four publications follow in order:

| Order | Publication |
|---|---|
| First | Captured byte at twice the signed interpretation of result storage |
| Second | Character-converted output address at result-storage offset eight |
| Third | Field-area address as a word at twice the old accumulated total, calculated unsigned |
| Fourth | Full 64-bit F-09 result at result storage |

Result-storage doubling is signed. The offset-eight access comes from advancement by one 64-bit object. The wide write remains distinct from preceding narrow writes; byte order, atomicity, and physical decomposition are not established.

The next accumulated total comes from signed left shift of the field-area address by two. The next descriptor comes from signed left shift of the replacement working address by eight. Each result is then represented unsigned, subject to signed-shift validity.

The field area receives three ordered words: revised stride at offset zero, next descriptor at offset four, and replacement working address at offset eight. Next payload is revised stride multiplied by 256 unsigned.

### Unresolved continuation decision

The continuation expression first shifts the signed replacement working address left by 31, then shifts that signed result right by 32. Unsigned conversion and a logical right shift by 20 follow.

The right-shift count equals the 32-bit operand width. Ordinary source-language shift rules do not define this operation. The preceding signed left shift has its own validity restrictions. Consequently, neither a decision value nor either subsequent route is established.

The following are conditional structural outcomes only, requiring an external execution interpretation:

- A zero decision sets the processing address to zero and performs another output transaction, using the F-09-derived output address and revised stride. Acquisition then uses the output-re-entry target with selector zero.
- A nonzero decision sets the processing address to zero but performs no output transaction. The decision is written as a word at next payload plus `0x20` unsigned, followed by F-10 with breakpoint immediate 4.

The breakpoint-continuation target and selector are selected before F-10. Its selector is the signed interpretation of next payload shifted right 29.

Normal breakpoint resumption is not guaranteed. If it occurs, the descriptor becomes the signed output address shifted right 18, then represented unsigned. Acquisition resumes through the breakpoint-continuation target without an intervening output transaction.

## Acceptance examples

These are conditional static obligations, not executed tests. Each requires valid preceding operations and normal completion of intervening dependencies.

1. **Initialization selection:** Control 1 selects initialization even though F-01’s first argument is zero. Selection is not equivalent to testing that argument.

2. **Separate base observations:** If setup-related effects change the base before its second read, the `0xCE` publication uses the second observation. The later working-address calculation still uses the retained entry observation.

3. **Unrepaired overflow:** Third argument `0x00800000` cannot be multiplied by 256 within signed 32-bit range. Selecting initialization does not validate that earlier operation.

4. **Return exclusion:** Initialized control 16 fails the return predicate. Every control value that skips initialization also fails it.

5. **Overlapping anchor writes:** Completed initialization requires a zero-byte write at address zero followed by the seed-word write there. Equivalent final contents do not eliminate either access.

6. **Acquisition aliasing:** Descriptor `0x100` requires word `0x4000` at address `0x4000`. If the old working address is also `0x4000`, the subsequent stride read observes that publication absent intervening external effects.

7. **Conversion before addition:** If converting working address `0x0000FFFE` to signed halfword yields −2, the subsequent addition produces 2. This example does not select a universal out-of-range conversion rule.

8. **Candidate boundary:** F-07 low word zero requires a zero-word write at address zero before short continuation. Low word one requires word `0x20` at address `0x20` before extended processing.

9. **Captured-byte lifetime:** A round beginning with stride ending in `0x12` retains captured byte `0x12` even when acquisition replaces stride with a value ending in `0xAB`. A following short-continuation round captures `0xAB`.

10. **Signed address doubling:** Result-storage address `0x40000000` does not establish a valid byte publication at `0x80000000`; its signed doubling exceeds range.

11. **Conditional breakpoint:** Given an externally supplied nonzero decision and next payload `0x100`, the pre-breakpoint word destination is `0x120`. This does not resolve the invalid shift or guarantee resumption.
