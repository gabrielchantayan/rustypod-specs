# F-43d17b9e9ea1

## Purpose

F-43d17b9e9ea1 constructs a word-array result in workspace obtained from a context, conditionally invokes an adjustment dependency, and invokes an output dependency if preceding status checks permit it.

The arithmetic resembles multiword multiplication with integrated reduction and a one-word downward shift per outer iteration. This is **inferred intent**, not an established mathematical guarantee. The supplied evidence does not establish the representation, global constants, coefficient requirements, or dependency semantics needed to promise modular multiplication.

Established behavior includes:

- Operand-role selection using signed scaled headers, before absolute-value conversion.
- Workspace clearing followed by a fixed number of outer iterations.
- Unsigned word products, carry propagation, and scaled word stores.
- Repeated evaluation of globals and descriptor storage-pointer fields.
- One comparison-dependent adjustment call, followed conditionally by an output call.
- Overall success only when every invoked status-producing dependency returns **zero**.

The last point is significant: a status of one is rejected, not accepted.

No runtime tests have been performed.

## Behavior

### Width calculation and global-load schedule

The function first reads the header-scale location and retains that value for later operand-length calculations.

It then evaluates the header-scale location separately when scaling the reduction header. The signed absolute value of that scaled header determines the arithmetic width, **N**.

Thus, even the retained scale and the scale used to determine N are separate observations. Their equality is not established.

The reduction-header access and width calculation precede the context-zero check. If the context is zero, execution returns the null-context result without selecting operands, accessing workspace, or calling dependencies.

For nonzero context, the header-scale location is evaluated separately for each selection-time operand-header calculation. Neither selection-time scale is required by the visible function to equal the retained initial scale, the width scale, or the other selection-time scale.

After workspace clearing, both operand lengths use the **same retained initial scale**, not fresh evaluations of the header-scale location.

Other external evaluations occur as follows:

- The word decoder is evaluated separately at each executed decoding expression.
- Decoding the captured inner first word occurs anew in each outer iteration.
- Each encoded word store evaluates the word encoder at that store.
- Each encoded header store evaluates the header encoder at that store.
- Raw zero stores do not use either encoder.
- The null-context result is evaluated only on the zero-context return path.

These are expression-level observations. The supplied representation does not establish an exact ordering between reads within a single expression.

### Operand selection and retained addresses

For nonzero context, the selection-time scaled headers are compared as signed 32-bit values before absolute-value conversion.

For ordinary representable control arithmetic:

- The operand with the smaller signed scaled header becomes the **outer operand**.
- The other becomes the **inner operand**.
- Equal scaled headers retain the first argument as outer and the fourth argument as inner.

This is signed ordering, not magnitude ordering. A negative scaled header can select an operand whose later absolute length is larger.

The context’s workspace-descriptor pointer is read once and retained. The selected operand descriptor addresses are also retained. Retaining these addresses does **not** retain their storage bases.

### Workspace clearing and length capture

The function writes raw zero at workspace indices 0 through N + 2, inclusive, when N is ordinary and nonnegative. This is N + 3 writes.

For each clearing access, the workspace descriptor’s storage-pointer field is evaluated again. Consequently, “workspace index” means an offset from the base obtained for that particular access. If a write changes the descriptor’s storage-pointer field through aliasing, later clearing accesses can use a different base.

The clearing loop does not intentionally initialize the workspace header.

After clearing, the selected operand headers are read again. Each is scaled with the retained initial scale and converted to a signed absolute length. These lengths are retained for the arithmetic loops. They are not necessarily the magnitudes of the selection-time values: the headers can have changed, and the scale used for selection can differ.

The inner operand’s storage-pointer field is then evaluated and its first stored word is captured. This read occurs even if N or the inner length is zero.

Only this first **stored word value** is captured. The inner storage base is not thereby captured for subsequent indexed reads.

### Word arithmetic

Arithmetic words are 32-bit bit patterns. Word-level products and sums retain their low 32 bits unless explicitly widened. Carries describe unsigned overflow beyond bit 31.

Products used for the main multiply-and-accumulate operations are unsigned 64-bit products. Their low and high halves feed the accumulated word and carry states.

A decoded word is the low 32 bits of a stored word multiplied by the word decoder observed at that expression. An encoded word is the low 32 bits of an arithmetic word multiplied by the word encoder observed at that store.

These transformations are not established to be identity operations or inverses.

Header scaling, absolute-value conversion, loop bounds, and index calculations involve signed control values. Signed-overflow boundaries are not covered by a portable contract. In particular, the most-negative signed 32-bit value has no representable positive signed absolute value.

### Outer iterations

For ordinary nonnegative N, exactly N outer iterations execute.

At each outer position:

1. The outer word is decoded from its indexed storage access when the position is below the retained outer length; otherwise the arithmetic word is zero and that operand word is not read.
2. The previously captured inner first stored word is decoded using a fresh decoder evaluation.
3. Workspace word zero is decoded using another decoder evaluation.
4. The context coefficient at byte offset 68 is read.
5. Multiplication and reduction carry states begin at zero.

The iteration’s reduction factor is the low 32 bits of the coefficient multiplied by the sum of:

- The decoded workspace word zero.
- The low 32-bit product of the outer word and the decoded captured inner first word.

The coefficient and these decoded values are retained within the iteration. Re-evaluating the factor during inner accumulation does not reload the coefficient or the captured first word.

### Inner accumulation and shifted stores

Each outer iteration processes inner positions zero through N − 1.

At each position:

- The indexed inner operand word is decoded if the position is below the retained inner length; otherwise its arithmetic value is zero.
- The indexed workspace word is read and decoded.
- The outer/inner unsigned product is combined with that workspace word and the incoming multiplication carry.
- The low 32-bit sum is retained. The next multiplication carry combines the product’s high half and the unsigned carries from the two additions.
- The indexed reduction word is read and decoded, without a separate reduction-length guard.
- An unsigned 64-bit accumulation combines the reduction-factor/reduction-word product, the preceding low sum, and the incoming reduction carry.
- Its high half becomes the next reduction carry.

At position zero, the final low half is discarded. At every positive position, that low half is encoded and stored one workspace position lower.

The workspace read therefore precedes the associated shifted write. Operand and reduction reads occur among workspace writes rather than from a complete input snapshot.

Every executed array access evaluates the relevant descriptor’s storage-pointer field again:

- Outer accesses use the outer descriptor’s current field.
- Inner indexed accesses use the inner descriptor’s current field.
- Reduction accesses use the reduction descriptor’s current field.
- Workspace reads and writes separately use the workspace descriptor’s current field.

Even a read and its associated shifted write need not use the same workspace base if intervening writes affect the descriptor. Index-based descriptions do not promise one contiguous physical array under such aliasing.

### Carry propagation and header update

After the N inner positions, propagation starts at workspace position N.

At each propagation position, the function decodes the current workspace word, adds the multiplication carry, and then adds the reduction carry. Each addition produces a low word and an unsigned carry. The new multiplication carry is the carry from the first addition; the new reduction carry is the carry from the second.

Propagation stops when the **second addition’s low word is zero and its carry is zero**. The stopping condition does not independently require the first addition’s newly produced carry to be zero.

If propagation continues, the second sum is encoded and written one position lower when the current position is positive. The propagation position then advances.

On termination at positive position k:

- The workspace header is written using the low 32 bits of (k − 1) multiplied by the header encoder evaluated for that store.
- Workspace position k − 1 is then overwritten with raw zero.

The header write precedes the terminal zero access. The terminal access reloads the storage-pointer field after that header write, so overlap can affect its destination.

If termination occurs at a nonpositive position, the header is set to raw zero instead.

Propagation has no explicit capacity check or fixed limit tied to the initial N + 3 cleared words. The visible body does not establish that those words suffice for every possible state and external-value sequence.

This accumulation and propagation sequence repeats for each outer position. There is no separate final general normalization pass.

## Acceptance examples

These are conditional criteria from static evidence, not executed tests.

### Zero context

With a readable reduction header and valid width calculation, a zero context returns the null-context result observed on that path. Operand descriptors are not read. An unreadable reduction header is not made safe by the zero context.

### Distinct scale observations

If the initially retained scale is two but the separately observed width scale is three, a reduction header of four yields N = 12, assuming representable arithmetic. Later operand-length calculations use two. Selection uses its own two separate scale observations.

### Signed selection

If selection-time scaled headers are −3 and +2, the first operand is selected as outer. A later outer length of three follows only if the reread header and retained scale produce −3.

Equal selection-time scaled headers leave the first operand outer.

### Zero width

With N = 0, valid nonoverlapping storage, and representable bounds:

- Three workspace words are cleared.
- The inner first stored word is still captured.
- No outer iteration runs.
- The function body does not explicitly update the workspace header.
- Comparison and subsequent status handling still execute.

Dependency effects on the header and storage remain unknown.

### Pointer-field reloads

If one workspace write validly changes the workspace descriptor’s storage-pointer field, the next workspace access uses the newly observed field. It is not required to use the base from the preceding access.

### Short operand

When an indexed position is outside a retained operand length, that operand contributes arithmetic zero without an indexed word read. This does not suppress the unconditional first-inner-word capture or the N reduction-word reads per outer iteration.

### Negative comparison

If F-61e238108dfa returns a negative signed value, adjustment is skipped. If F-a743bb08af07 returns zero, the overall result is zero. If it returns one, the overall result is one.

### Nonnegative comparison

If comparison returns zero or a positive signed value:

- Adjustment result zero permits the output call.
- Adjustment result one, two, or any other nonzero value returns one immediately and skips output.

### Failure and storage state

A nonzero output result produces overall return one. The function performs no subsequent rollback. The final contents, ownership, and validity of workspace depend on what the invoked dependencies did; preservation of earlier writes is not an acceptance condition.
