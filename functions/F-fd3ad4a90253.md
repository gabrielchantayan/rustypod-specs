## Behavior

### Dispatch selection

The visible operation is a memory-dependent lookup followed by an indirect invocation.

The first lookup obtains a four-byte value from the location supplied by the caller. The next lookup uses that value as an address and obtains the dispatch-base value. The target slot is selected by a fixed displacement of 12 bytes from that base.

The displacement is byte-based. It is not established as an element index. In an execution model with four-byte table entries, this displacement would select the fourth entry relative to the base; that table interpretation remains conditional.

The callable address is read from the selected slot. The function does not visibly call the dispatch-base address itself, the slot address itself, or a target derived directly from the first value without the intervening lookup.

There is no represented branch that selects a different displacement, retries a failed lookup, or supplies a fallback target.

### Observable read order

The address dependencies establish this logical order:

1. Read the initial value from the input location.
2. Read the dispatch-base value from the location designated by the initial value.
3. Read the callable target from the slot at the dispatch base plus 12 bytes.
4. Invoke the selected target.

Each later lookup depends on the preceding lookup’s result. The supplied representation shows no additional dispatch-data read and no write between these operations.

This is a description of the represented memory operations, not a guarantee about bus transactions, speculative accesses, atomicity, or synchronization. The material provides no concurrency contract.
