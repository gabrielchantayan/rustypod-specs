# F-0c99340f8c65

## Behavior

It then invokes F-9a24beb5b760 with two arguments, in this order:

1. The integer constant one.
2. The captured value.

The second argument is the value obtained by the initial read. It is not an additional read through the input pointer and is not the four-byte field used by the later indirect invocation.

The wrapper cannot make its branch decision until this invocation returns a result. If the dependency does not return normally, the supplied material establishes no subsequent wrapper action.

### Return decision

The reconstructed condition tests whether subtracting one from the dependency’s signed result produces a nonnegative value.

For results where this subtraction is representable in a signed 32-bit integer:

| Dependency result | Wrapper action |
|---|---|
| 1 through 2,147,483,647 | Return without the indirect invocation |
| −2,147,483,647 through 0 | Continue to the indirect invocation |

Consequently, zero does not take the immediate-return path. One does.

The result −2,147,483,648 is exceptional: subtracting one is outside the signed 32-bit range. Its behavior cannot be established merely by treating the reconstructed expression as an ordinary signed comparison.

Under a 32-bit wrapping-subtraction interpretation, that result would become 2,147,483,647 and take the immediate-return path. That is a conditional arithmetic interpretation, not verified runtime behavior. The instruction-level behavior for this boundary is documented_only.

### Indirect invocation

If the wrapper does not take the immediate-return path, it obtains one four-byte value from byte offset four relative to the **originally captured value interpreted as an address**.

The field read occurs after F-9a24beb5b760 returns. Therefore:

- A change that the dependency makes to the offset-four field can affect the argument passed onward.
- A change that the dependency makes to the caller’s input storage does not replace the captured base value.
- A dependency action that invalidates the captured address can make the later read invalid. The wrapper provides no visible protection against this.

The four bytes become the sole explicit argument to the indirect invocation. Their interpretation is unknown: they might encode an integer, pointer, handle, or other value. No additional wrapper-side dereference of that argument is shown.

The indirect target comes from a fixed storage location identified by the supplied reconstruction. Its identity and behavioral contract are not provided. The recovered control transfer is represented as an invocation, but the source evidence does not establish whether the underlying mechanism is an ordinary call, a tail transfer, or another indirect dispatch arrangement.

If the indirect invocation returns normally under the reconstructed call model, the wrapper then returns without using an explicit result from that invocation.
