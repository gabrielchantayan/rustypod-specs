# F-caf78c6998c3

## Purpose

F-caf78c6998c3 performs an indefinitely repeated sequence of indirect calls, computed-address memory accesses, and bit-field transformations. Each completed iteration derives replacement values for three 32-bit inputs and clears the one-byte input before beginning the next iteration.

The supplied static representation establishes no application-level purpose. It does not establish that the computed addresses refer to ordinary objects, that the indirect calls implement a particular protocol, or that the routine initializes a recognizable data structure. Those interpretations are **documented_only**.

The strongest supportable contract is an ordered interaction contract: which values are passed to unresolved dependencies, which memory locations are accessed, what widths are used, and how values retained across calls influence later operations.

No explicit error result, status output, exception handler, timeout, cancellation check, or rollback path is visible. A dependency that does not return, or a failing indirect call or memory access, prevents the subsequent visible actions from being reached.

### Arithmetic notation

The behavioral description below uses:

- **W(x):** the low 32 bits of a value.
- **B(x):** the low 8 bits.
- **L(x)** and **H(x):** the low and high 32-bit halves of a represented 64-bit result.
- **S(x):** `(x masked to its low 30 bits) shifted right by 20`.
- **Selector write at base x:** first read an unsigned byte at address W(x + 1), then write one byte at the address equal to that byte value plus 17.

All address arithmetic, multiplication, and left-shift results in the trace below are expressed as 32-bit machine bit-vector operations. In particular, discarded high bits do not become additional address bits.

This is a machine-level interpretation of the supplied representation, not a claim that signed overflow or negative left shifts have portable language-level semantics. Exact instruction semantics remain an uncertainty.

## Side effects

The routine directly performs byte writes, 32-bit word writes, byte reads, one computed-address word read, and one separately identified global word read per completed visible iteration.

A selector byte is unsigned. Consequently, a selector-directed byte destination lies between addresses 17 and 272 inclusive. The word destination based on the saved selector starts between addresses 20 and 275 inclusive. These small numeric addresses are literal consequences of the represented arithmetic, not evidence of valid application memory.

There is no established object layout beyond the access formulas. Offsets 1, 17, and 20 do not prove the presence of object fields. Computed addresses may alias one another, the global location, dependency-managed memory, or other externally significant storage.

No allocation, ownership transfer, release, or deallocation is directly established. Dependencies may have such effects; their contracts are unknown.

There is no visible synchronization or atomicity guarantee. The ordering described is the order of operations in the supplied representation, not a cross-thread memory-order guarantee.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial word storage.** If sequence A returns 3, the first visible word write starts at address 32 and stores the original first input’s 32-bit pattern.

2. **High-bit loss.** If B is 5, **base** is 2³⁰, not five times 2³⁰ in a wider address space. If B is 4, **base** is zero.

3. **Single-bit publication.** If C is even, the word written after sequence F is zero. If C is odd, its stored bit pattern is 0x80000000.

4. **Computed read boundary.** If D has its low 30 bits clear, the computed word read starts at address 20. If those bits are all set, it starts at address 1043.

5. **Selector re-read.** If a selector byte is 9 for one selector write, that write targets address 26. If an intervening dependency changes it to 12, a later fresh selector write targets address 29.

6. **Saved selector retention.** If the saved selector is 9 and sequence J changes its original byte location to 12, the subsequent word write still starts at address 29: saved selector plus 20.

7. **Byte truncation.** If J is 0x12345678, the selector write immediately after sequence H stores 0xE0, the low byte of J shifted left by two.

8. **Iteration transition.** If AE is 7, the boundary word write stores 28 at address 132. The next iteration’s first call receives 28, 28, and 28. Its later byte-initialization writes use zero.

9. **Interrupted progress.** If a dependency does not return, no later direct access in this contract is reached through the visible continuation. Earlier writes are not rolled back.
