### Source-word read and initial reversal

The source word is numerically byte-reversed. If its bytes, ordered from most significant to least significant, are \(a,b,c,d\), the transformed word has bytes \(d,c,b,a\).

This reversal is defined on the numeric word. Mapping physical memory bytes to the initial numeric word additionally requires the target’s memory byte order, which is not supplied.

### Masking and extraction

The byte-reversed word is ANDed with both unsigned 32-bit extraction masks.

Let:

- \(p\) be the low five bits of the position-like value, so \(0 \le p \le 31\).
- \(w_e\) be the signed 32-bit width read at offset 8 through the retained descriptor address.
- \(s\) be the encoded right-shift count.

The count is:

\[
s = (32 - p - w_e)\mathbin{\&}255
\]

The subtraction is evaluated using unsigned 32-bit arithmetic because the position-like operand is unsigned. The width therefore participates through its unsigned 32-bit representation. The final mask retains the low eight bits.

Consequently, \(s\) ranges from 0 through 255, not merely 0 through 31.

The masked word is logically shifted right by \(s\), subject to the actual target’s shift semantics:

- Counts 0 through 31 have the ordinary unsigned 32-bit logical-shift interpretation.
- Counts 32 through 255 have no established portable result here.
- Replacing the eight-bit count mask with a five-bit mask is not justified by this evidence.

The source-word read precedes the extraction expression. Within that expression, the relative evaluation order of the masks, position-like value, and extraction-width access is not established.

### Separate transformation-width read

After extraction, the function reads a signed 32-bit width at offset 8 through the original descriptor argument. This value selects replication and the width-dependent reversal.

This is a separate read from the extraction-width access. The two reads can address different descriptors if setup changed the retained address. Even when they address the same location, equality requires stable contents.

No consistency check compares these widths.

### Selected-width replication

Replication modifies an unsigned 32-bit working word through successive OR operations. Each stage retains the existing word and adds a shifted contribution.

The available stages are:

| Stage | Contribution ORed into the current word |
|---|---|
| One-bit stage | The current low bit shifted left by 1 |
| Two-bit stage | The current low two bits shifted left by 2 |
| Nibble stage | The current low four bits shifted left by 4 |
| Byte stage | The current low eight bits shifted left by 8 |
| Halfword stage | The entire current word shifted left by 16, retaining only the 32-bit result |

The transformation width selects the following ordered stages:

| Signed transformation width | Stages performed |
|---|---|
| 1 | One-bit, two-bit, nibble, byte, halfword |
| 2 | Two-bit, nibble, byte, halfword |
| 4 | Nibble, byte, halfword |
| 8 | Byte, halfword |
| 16 | Halfword |
| Any other value | None |

Each stage uses the word resulting from the preceding stage.

For the halfword stage, shifting the entire word left by 16 has the same 32-bit contribution as shifting its low halfword left by 16. Higher original bits are nevertheless preserved by the OR with the unshifted word.

No stage first truncates the working word to the nominal transformation width. Thus, uniform repetition across 32 bits is guaranteed only when extraction has cleared all bits above that width. Surviving higher bits may produce a nonuniform result.

All replication shift counts are fixed and below 32. Bits shifted beyond bit 31 do not remain in the 32-bit result.

### Width-dependent byte reversal

After replication, the transformation width is compared with 15 as a signed 32-bit value.

If it is greater than 15, the current word is byte-reversed once.

This applies to width 16 and to all other signed widths above 15, including widths that receive no replication. Zero and negative widths do not satisfy this comparison.

### Flag-dependent byte reversal

Next, the function reads unsigned 16-bit flags from the original descriptor at offset 16.

If bit `0x2000` is set, the current word is byte-reversed once more. Other flag bits do not directly affect the transformation visible in this function.

The two post-replication reversal conditions are independent:

| Transformation width greater than 15 | Flag bit `0x2000` | Net post-replication reversal |
|---|---|---|
| No | Clear | None |
| No | Set | One |
| Yes | Clear | One |
| Yes | Set | None; two reversals cancel |

The initial source-word reversal occurs regardless of these conditions on every completing path.

### Final invocation

After the flag-dependent reversal decision, the function reads the original descriptor’s unsigned 16-bit flags again for the final dependency argument.

F-1e2f295ee27c receives the transformed word, this second flags value, and the opaque payload. The first flags read is not reused for forwarding.

The two reads therefore have distinct roles. If different values are observed, the transformed word can reflect one flags value while the dependency receives another. Whether such mutation is permitted by the execution environment is unresolved.

After the final dependency returns, this function returns without inspecting its result.

## Acceptance examples

These are conditional arithmetic expectations from static evidence, not executed tests. Unless specified otherwise, they assume valid accesses, normally completing dependencies, defined shift behavior, and stable descriptor contents.

### One-bit replication

If extraction produces exactly `0x00000001` and the transformation width is 1, replication produces `0xFFFFFFFF`.

If extraction produces exactly zero, the result remains zero.

Neither result changes under byte reversal.

### Four-bit replication

If extraction produces exactly `0x0000000A` and the transformation width is 4, replication produces `0xAAAAAAAA`.

This expectation depends on the absence of higher set bits after extraction.

### Eight-bit extraction

Assume:

- The initially byte-reversed source word is `0x12345678`.
- Both masks are `0xFFFFFFFF`.
- The low-five-bit position is zero.
- Both width reads yield 8.
- Flag bit `0x2000` is clear.

The shift count is 24. Extraction produces `0x00000012`; replication produces `0x12121212`. That word is forwarded.

### Sixteen-bit replication and reversal

With the same reversed source word and masks, position zero, and both widths equal to 16:

- Extraction produces `0x00001234`.
- Replication produces `0x12341234`.
- The width-dependent reversal produces `0x34123412`.

With flag bit `0x2000` clear, the final word is `0x34123412`. With that bit set, the additional reversal restores `0x12341234`.

### Unsupported replication widths are not rejected

If extraction produces `0x00000005`, transformation width is 3, and flag bit `0x2000` is clear, the final word remains `0x00000005`.

If extraction produces `0x00123456`, transformation width is 24, and the flag bit is clear, the final word is `0x56341200`: there is no replication, but the signed width comparison triggers reversal.

A negative transformation width likewise receives no replication and no width-dependent reversal. Extraction remains conditional on its separately computed shift being defined.

### Higher bits survive replication

If extraction produces `0x00000102`, transformation width is 8, and flag bit `0x2000` is clear:

- The byte stage contributes `0x00000200`.
- ORing that contribution into the existing word produces `0x00000302`.
- Shifting this updated word left by 16 produces `0x03020000`.
- The halfword-stage OR produces **`0x03020302`**.

The final dependency receives `0x03020302`, not `0x03030302`.

Truncating extraction to eight bits first would instead produce `0x02020202`; that would change the established behavior.

### Separate flags values

If the reversal-decision read observes bit `0x2000` set and the forwarding read observes it clear, the word receives the flag-dependent reversal while the dependency receives flags with that bit clear.

This expectation is conditional on an environment in which those distinct observations are possible and defined; it does not establish concurrency support.

### Encoded shift outside the ordinary range

If the extraction width is 33 and the low-five-bit position is zero, unsigned subtraction followed by the eight-bit mask produces a shift count of 255.

No portable extraction result is specified. Treating that count as 31 requires additional target evidence.
