# F-025f9694a114

## Purpose

F-025f9694a114 resolves an integer result from an object’s override byte, stored status, and mode byte. A stored status of −1 activates a dependency-driven table-selection path. If the first selected value matches an object-associated exclusion value, the function performs exactly one replacement selection.

The established priority is:

1. A nonzero override byte returns 14.
2. Otherwise, a negative mode byte enables four exact status remappings.
3. Any remaining status other than −1 is returned unchanged.
4. A status of −1 triggers table selection and, conditionally, one replacement selection.

“Status,” “mode,” “selection,” and “exclusion” describe observed roles, not established application semantics. Neither randomness nor guaranteed exclusion is established.

The fallback path contains **two distinct evaluations of the global table-base datum before the first entry is loaded**: one captures an address for a possible replacement load; the other supplies the address for the first load. These evaluations must not be collapsed into a single captured value in the behavioral description.

## Interface

### Input and object layout

The function accepts one argument used as an object base address. The supplied representation expresses that argument as an integer, but accesses storage relative to it.

| Object-relative location | Access | Role |
|---|---|---|
| +0x141 | Byte read | Override condition |
| +0xB4 | Integer-word read | Stored status |
| +0xB8 | Integer-word read, fallback only | Exclusion value |
| Displacement obtained from a global datum | Byte read | Mode condition |

The numeric mode displacement is not supplied. Its addressed byte must not be assumed distinct from the other listed fields.

Two global data roles are visible:

- A displacement used to address the mode byte.
- An address used as the base for selection-table accesses.

Their initialization, ownership, lifetime, and possible aliasing relationships are unknown.

### Output

The function returns an integer through its ordinary return channel. Reachable result classes are:

- 14 for a nonzero override;
- 15, 1, 19, or 18 for the corresponding mode-dependent remappings;
- an unchanged stored status other than −1;
- a value loaded from the selection table.

There is no separate visible success indicator, error result, or diagnostic channel. No returned number is established as an error code.

### Widths and representation

The representation uses integer-word object reads and table loads with an explicit four-byte entry stride. It is consistent with a 32-bit integer model and four-byte integer entries. The original ABI, address width, integer representation, and alignment requirements are not independently established.

The byte predicates differ:

- The override byte is tested for nonzero; its signedness does not affect that predicate.
- The mode byte is tested for negativity; interpretation therefore depends on byte signedness.

Under an eight-bit signed-byte interpretation, mode patterns 0x80–0xFF are negative. That bit-pattern rule is conditional, not an independently established target property.

The table-address calculation scales an index by four and adds it to a base address. The replacement-call argument increments a captured integer by one. Neither operation is accompanied by a visible overflow check. Wrapping, trapping, or other overflow behavior must not be invented.

### Preconditions

For an ordinary defined execution, every reached access and operation must be valid:

- The global mode displacement must yield a readable byte address.
- Each table-base evaluation used for an entry load must yield a suitable address.
- Each selected index must produce a valid integer-entry address.
- The retained base must remain usable if a replacement load is reached.

No visible null check, bounds check, alignment check, arithmetic check, or recovery path enforces these requirements.

## Behavior

### Override precedence

The first object access reads the byte at +0x141.

If it is nonzero, the function immediately returns 14. It does not reach the stored-status read, mode-displacement evaluation, mode-byte read, table-base evaluations, exclusion read, or dependency calls.

This priority holds regardless of what those unreached locations contain.

### Status capture and mode inspection

When the override byte is zero, the function reads and captures the integer at +0xB4.

It then obtains the global mode displacement, reads the addressed object-relative byte, and tests that byte for negativity. This happens before deciding whether the captured status is the −1 fallback sentinel.

The captured status is not subsequently reread from the object. A valid mode access is required even when the function will return the status unchanged.

### Mode-dependent remappings

A negative mode byte enables these exact mappings:

| Captured status | Returned value |
|---|---|
| 1 | 15 |
| 15 | 1 |
| 18 | 19 |
| 19 | 18 |

A matching case returns immediately, without fallback dependency calls or table accesses.

No other status is remapped. In particular, a negative mode does not suppress fallback for −1.

If the mode byte is not negative, these mappings do not apply.

### Non-sentinel pass-through

After the remapping decisions, any captured status other than −1 is returned unchanged.

This includes zero and negative values other than −1. No visible validation restricts the result to an enumerated set or normalizes an out-of-range status.

### Initial fallback selection

For a captured status of −1, the function performs the following observable sequence in the supplied representation:

1. Calls F-eec8106f4698 without explicit arguments and captures its ordinary integer result.
2. Calls F-d7be9cfb4000 with that captured result and the constant 5.
3. Uses a secondary output associated with this call as the first table index.
4. Evaluates the global table-base datum and retains that value for possible later use.
5. Evaluates the global table-base datum again to address the first table-entry load.
6. Loads the integer at the base from the second evaluation plus four times the first index.
7. Reads the object integer at +0xB8.
8. Compares that exclusion value with the captured first table value.

The first dependency’s ordinary result is an argument to the second dependency; it is not directly used as the table index. The ordinary return of F-d7be9cfb4000 is not visibly consumed.

The constant 5 is established only as an argument. It does not prove that the index lies in 0–4, that the table has five entries, or that the dependency computes a remainder.

The two table-base evaluations are distinct in the supplied representation. No visible dependency call occurs between them. The evidence establishes neither that their values differ nor a volatile, atomic, or physical-load interpretation.

Both dependency calls precede both table-base evaluations and the exclusion read. Their unknown effects may therefore affect the storage subsequently consulted.

### Initial mismatch

If the first loaded table value differs from the exclusion value, the function returns that captured table value.

There is no second call to F-d7be9cfb4000, no replacement entry load, and no reread of the first entry.

The base retained before the first entry load does not determine the returned value on this path.

### Initial match and replacement

If the first table value equals the exclusion value, the function:

- Calls F-d7be9cfb4000 again with the captured result from F-eec8106f4698 incremented by one, and with 5 as the second argument.
- Uses the new secondary output as the replacement index.
- Loads an integer at the **retained base from the first table-base evaluation**, plus four times the replacement index.
- Returns that newly loaded integer immediately.

F-eec8106f4698 is not called again.

The replacement is not checked against the exclusion value. It may equal the exclusion, equal the first selected value, or address the same entry. There is no retry loop.

The replacement load does not reevaluate the global table-base datum. Consequently, a change to that global during the second F-d7be9cfb4000 call does not redirect the replacement load. Changes to the retained table’s contents can affect the load; invalidation of that storage violates the required memory-validity conditions.

## Side effects

### Direct operations

### Read and call ordering

The significant order is:

- Override read before all lower-priority work.
- Stored-status capture before mode inspection.
- Mode inspection before sentinel-based fallback.
- F-eec8106f4698 before the first F-d7be9cfb4000 call.
- First F-d7be9cfb4000 call before the retained-base capture.
- Retained-base capture before the separate table-base evaluation used for the first entry load.
- First entry load before the exclusion read.
- Equality decision before the optional second F-d7be9cfb4000 call.
- Optional second call before the replacement load through the retained base.

The override, status, and mode are not revisited after dependency execution. The exclusion is read once and is not reread after the optional second call.

This is ordering evidence from the supplied representation, not a guarantee of synchronization, volatile semantics, atomicity, or defined behavior during unsynchronized concurrent mutation.

## Acceptance examples

These are conditional static acceptance criteria, not observed test results. Unless stated otherwise, assume valid memory, defined arithmetic, normally returning dependencies, and a signed mode-byte interpretation.

### Override suppresses lower-priority accesses

With a nonzero override byte, the result is 14. No status, mode, exclusion, or table access is reached, and neither dependency is called.

### Negative mode enables only the specified remappings

With a zero override and negative mode, statuses 1, 15, 18, and 19 return 15, 1, 19, and 18 respectively. No fallback dependency is called.

With nonnegative mode, status 18 returns 18.

With either mode condition, status −2 returns −2. Mode inspection still occurs.

### First selection mismatch

Suppose the captured status is −1, the initial index is 2, the table addressed by the second table-base evaluation contains 7 at entry 2, and the subsequently read exclusion is 9.

The result is 7. F-eec8106f4698 and F-d7be9cfb4000 are each called once. The retained base does not replace the second global evaluation for this load.

### Equality permits exactly one replacement

Suppose F-eec8106f4698 returns 40. The initial F-d7be9cfb4000 call receives 40 and 5.

If the first entry equals the exclusion, the second call receives 41 and 5. The replacement entry is loaded through the retained base and returned without another exclusion comparison.

If the replacement also equals the exclusion, that value is still returned.

### Distinct base-evaluation roles

If an execution model permits the first global table-base evaluation to yield address A and the second to yield address B, the initial entry is read through B. If that value matches the exclusion, the replacement is read through A.

This criterion distinguishes the two roles; it does not assert that such differing observations are possible under the unknown concurrency and access semantics.

### Global mutation during replacement

Suppose the retained base is A and the second F-d7be9cfb4000 call changes the global table-base datum to B.

The replacement load still addresses A. A must remain readable. If the dependency changes the selected entry within A, the replacement load observes the contents supplied by that subsequent access, subject to the target’s access semantics.
