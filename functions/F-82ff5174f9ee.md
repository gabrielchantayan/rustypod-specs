# F-82ff5174f9ee

## Purpose

F-82ff5174f9ee coordinates a bounded, mode-dependent operation over an object-associated resource. It checks a requested range, invokes two preparation dependencies, optionally invokes a cursor-adjustment dependency, and conditionally dispatches through one of three indirect callback targets. After successful preparation, it invokes a finalization dependency whether or not a callback runs.

The established behavior is orchestration: argument selection, 32-bit arithmetic, dependency order, cursor handling, callback selection, and result construction. The meanings of the resource, modes, callbacks, and finalization operation are not established.

Its result contains two distinct 32-bit components:

- A lower component containing a status from a checked operation, or the locally generated value 6.
- An upper component containing either the original mode argument or the sixth argument, depending on whether callback dispatch occurs.

The upper component is therefore not uniformly a success indicator, an error category, or a preserved caller value.

## Behavior

### Arithmetic rules

All offset, length, cursor, and endpoint arithmetic described here is 32-bit arithmetic. Unsigned addition wraps modulo \(2^{32}\). Range comparisons and the mode-8 cursor comparison are unsigned.

In particular, the initial range check does not use an overflow-detecting addition. A wrapped offset-plus-length value may pass the check even when the corresponding mathematical sum exceeds the 32-bit range.

### Initial reads and range rejection

The function first reads and retains the resource token from object offset +4. It then reads the unsigned limit at offset +24 and compares that limit against the 32-bit sum of requested offset and requested length.

If the limit is less than that sum:

- No dependency is invoked.
- The lower result component is 6.
- The upper result component remains the original mode.
- The base field at offset +20 is not read.

Equality passes the range check. Zero-length requests receive no special treatment.

This check uses the requested offset and length, not the base-adjusted position used by preparation.

### Preparation

If the range check passes, preparation occurs in this order:

1. Read the base field at object offset +20.
2. Invoke F-e40a3ceddab2 with the captured resource token and the 32-bit sum of the base field and requested offset.
3. If that call returns zero, invoke F-977b73bb902a with the same captured resource token, the original requested length, and the address of a mutable 32-bit local cell.

Before F-977b73bb902a is invoked, that mutable cell contains the requested offset. It is not an uninitialized output-only cell: the dependency can observe its initial value.

If F-e40a3ceddab2 returns nonzero, the function returns that status in the lower component and the original mode in the upper component. F-977b73bb902a and finalization are not invoked.

If F-977b73bb902a returns nonzero, the function likewise returns that status and the original mode. Finalization is not invoked on this path, even if the dependency has already modified the mutable cell or other state.

On successful return from F-977b73bb902a:

- Its mutable cell supplies the starting cursor for subsequent processing.
- An endpoint is calculated as that cell’s value plus the original requested length, with 32-bit wraparound.
- A separate mutable cursor cell is initialized to that same starting value.

The original requested offset is not substituted back into these calculations. The endpoint remains fixed for the remaining visible processing, even if the separate cursor is later changed.

### Optional cursor adjustment

The mode determines whether F-2790da281ffe is called:

| Mode | Cursor adjustment |
|---:|---|
| 1, 2, 8 | Invoke with flag 0. |
| 6, 7, 9 | Invoke with flag 1. |
| 0, 3, 4, 5, and all other values | Do not invoke. |

The adjustment arguments are:

1. The original object address.
2. The address of the separate mutable cursor cell.
3. The fixed endpoint.
4. The selected flag, exactly 0 or 1.

The dependency may read or change the cursor cell. The visible body does not constrain that change to remain within the prepared interval.

A nonzero adjustment status suppresses callback dispatch but does not suppress finalization. The upper result component remains the original mode.

When adjustment is not invoked, the checked status remains zero from successful preparation.

### Callback dispatch

After successful preparation and, where applicable, successful cursor adjustment, callback selection is:

| Mode | Callback target | Starting cursor |
|---:|---|---|
| 0 | None | Not applicable. |
| 1 | Primary target | Current cursor. |
| 2 | Alternate target | Current cursor. |
| 3 | None | Not applicable. |
| 4 | None | Not applicable. |
| 5 | Alternate target | Prepared starting cursor; no adjustment occurred. |
| 6 | Primary target | Current cursor. |
| 7 | Alternate target | Current cursor. |
| 8 | Third target, subject to a cursor check | Current cursor plus one, using 32-bit wraparound. |
| 9 | Third target | Current cursor. |
| Any other value | None | Not applicable. |

The primary target pointer is fetched before this callback-selection decision, even for modes that ultimately invoke no callback. The alternate or third target pointer is fetched when selected by the mode. For mode 8, the third target pointer is fetched before the additional cursor check.

For mode 8, the incremented cursor must be unsigned-less-than-or-equal to the endpoint. If it is greater than the endpoint:

- No callback is invoked.
- The checked status remains zero.
- The upper result component remains the mode, 8.
- Finalization still occurs.

There is no corresponding explicit cursor-versus-endpoint check for modes 1, 2, 5, 6, 7, or 9. There is also no explicit overflow rejection for the mode-8 increment.

Immediately before invoking a callback, the upper result component is changed to the sixth argument. Each callback receives:

1. The original object address.
2. The selected starting cursor by value.
3. The fixed endpoint by value.
4. The fifth argument unchanged.

The callback’s status becomes the lower result component, including when it is nonzero. The upper result component remains the sixth argument on normal return.

### Finalization and return

F-840cb7b3952f is invoked exactly once on every normally progressing path that has passed both preparation calls successfully.

It receives:

- The resource token captured at function entry.
- The address of the original mutable cell supplied to F-977b73bb902a.

This is not the separate cursor cell supplied to F-2790da281ffe. Changes to the adjustment cursor do not, by themselves, change the cell passed to finalization.

Finalization occurs after:

- A successful callback.
- A failed callback.
- A failed cursor adjustment.
- A mode that selects no callback.
- A mode-8 cursor check that suppresses the callback.

Its return value, if any, is ignored. The result status is not replaced by a finalization status.

These ordering guarantees assume invoked dependencies return normally. No recovery behavior is established for faults, nonlocal exits, or nontermination.

## Side effects

### Directly established effects

The visible body:

- Reads the three object fields described above, subject to path conditions.
- Reads callback target pointers on the successful dispatch-selection path.
- Writes local 32-bit cells and passes their addresses to dependencies.
- Invokes dependencies and callbacks in the specified order.
- Does not directly write an object field.
- Does not visibly allocate, free, copy, or return a memory buffer.

The resource token is captured once. Later preparation and finalization calls use that captured value rather than rereading object offset +4. A dependency’s change to that object field therefore does not change the token used by subsequent visible calls.

Callback target pointers are fetched after preparation and optional adjustment. No assumption is made that those earlier calls preserve global target slots.

### Ownership and lifetime

No ownership transfer is established for the object, resource token, callback argument, or memory potentially represented by the prepared cursor.

The addresses supplied to F-977b73bb902a, F-2790da281ffe, and F-840cb7b3952f refer to local cells. They are available during the corresponding calls. Their retention or use after this function returns is not established as valid.

The final dependency’s placement suggests a cleanup role, but the evidence does not prove that it releases a resource, reverses preparation, or restores state. Conversely, failure paths that omit it do not prove the absence of resources requiring cleanup.

## Acceptance examples

These are conditional examples derived from the supplied static evidence. They are not runtime observations.

   With limit 100, requested offset 90, and requested length 11, the sum is 101. The function reads the resource token and limit, invokes no dependencies, and returns lower component 6 with upper component equal to the mode.

4. **First preparation failure.**  
   If F-e40a3ceddab2 returns status 12, no second preparation, adjustment, callback, or finalization occurs. The lower component is 12 and the upper component is the original mode.

5. **Second preparation failure after a cell change.**  
   If F-977b73bb902a changes its mutable cell and then returns status 7, the function returns status 7 without invoking finalization. It does not visibly roll back that cell or other dependency effects.

6. **Successful preparation with no callback.**  
   For mode 3, if both preparation calls succeed, no cursor adjustment or callback occurs. Finalization runs, and the returned components are lower 0 and upper 3. An unrecognized mode follows the same no-callback pattern while preserving its own value in the upper component.

7. **Adjustment error preserves the mode tag.**  
   For mode 7, if F-2790da281ffe returns status 9, the alternate callback is not invoked. Finalization runs. The returned components are lower 9 and upper 7, regardless of the sixth argument.

8. **Callback error preserves the dispatch tag.**

9. **Mode-8 suppression is not an error status.**

11. **Preparation and adjustment cells remain distinct.**
