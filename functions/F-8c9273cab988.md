# F-8c9273cab988

## Purpose

F-8c9273cab988 conditionally updates a shared record and invokes dependencies according to an incoming record’s discriminator and an extracted 8-bit selector. Every path that completes its preceding operations normally then checks a shared root and may invoke an indirect dependency.

The established behavior has two principal branches:

- A matching discriminator permits selector-dependent processing only when a predicate dependency returns zero.
- A nonmatching discriminator causes a dependency invocation and a byte clear only when the incoming selector equals a freshly observed shared-state byte.

“Selected state,” “configuration,” and “stop-like operation” are descriptive interpretations, not established subsystem semantics. The function’s direct behavior is defined by its reads, writes, conditions, and dependency invocations.

## Interface

### Input and result

The function accepts one pointer to an incoming record. No explicit result value is established.

The supplied representation shows two 32-bit input fields:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Discriminator compared with a shared discriminator |
| 20 | 32 bits | Packed value containing the selector in bits 16–23 |

The selector is an unsigned value from 0 through 255, obtained by isolating bits 16–23 of the loaded 32-bit packed value. Other bits do not affect it. Extraction cannot produce a value outside that range.

The packed value is read before the initial dependency call. The discriminator is read after that call. Consequently, these fields are not observed as one consistent snapshot.

Byte order is not established. Selector extraction is specified in terms of the loaded 32-bit value rather than a particular input byte position.

## Behavior

### 1. Capture the selector and invoke the initial dependency

The function first reads the packed 32-bit value at incoming-record offset 20 and extracts its selector.

It then invokes F-338d16f9ce72 with the current root-reference address as its single visible argument. No return value from this invocation is used.

After that dependency returns, the function reads and retains the shared state-record pointer. Later state-record accesses use this retained pointer, except for the explicitly fresh pointer observation in the nonmatching branch.

The selector remains derived from the original packed-value read. Neither an input mutation by the initial dependency nor a later aliased write causes it to be extracted again.

### 2. Compare discriminators

After the initial dependency and state-pointer capture, the function compares the incoming 32-bit discriminator with the shared matching discriminator.

Equality selects the matching branch. Inequality selects the nonmatching branch. The representation does not establish an observable ordering between the two operand reads within this comparison.

Later changes to either discriminator do not cause the branch decision to be reconsidered.

### 3. Matching-discriminator branch

The function invokes F-e1dc3a9218c2 with the selector.

The represented predicate result is a 32-bit integer tested only for equality to zero. Its sign and any distinctions among nonzero values do not affect this function’s branch behavior.

If the result is nonzero:

- No selected-state store is performed by this branch.
- F-da2d75c0df8d, F-689e9e98c8f7, and D-01 are not invoked by this branch.
- Execution proceeds to the terminal root check.

If the result is zero, the following operations occur in order:

1. Read the selected-state byte at offset 2 through the retained state-record pointer.
2. If that byte is nonzero, invoke F-da2d75c0df8d with the current operation argument.
3. Read and retain the current selector-table pointer.
4. Store the selector as one byte at offset 2 through the retained state-record pointer.
5. Read the 32-bit default configuration value at offset 12 through that same retained state-record pointer.
6. Read the table byte at the retained table base plus the selector.
7. If the table byte is nonzero, read the 32-bit alternate configuration value at state offset 28 and select it instead of the default.
8. Invoke F-689e9e98c8f7 with the current operation argument and the selected 32-bit configuration value.
9. After that call returns, invoke D-01 with the current operation argument.
10. Proceed to the terminal root check.

Important consequences:

- The previous selected-state byte is tested for nonzero, not for inequality with the incoming selector. Repeating an already-selected nonzero selector still invokes F-da2d75c0df8d.
- Selector zero is accepted. It is stored as zero, and configuration processing still occurs.
- Storing the selector loses no selector bits: its established range fits exactly in eight bits.
- The default configuration is read even when a later nonzero table byte selects the alternate.
- The alternate configuration is read only when the table byte is nonzero.
- The retained state-record pointer is not refreshed after the predicate or stop-like dependency.
- The table pointer is captured after the optional stop-like call but before the selector store.

The selector store can affect later reads through aliases. For example, if the addressed table entry is the same byte as the selected-state store target, the subsequent table lookup observes the stored selector byte, assuming no intervening external mutation. Capturing the table pointer before the store preserves the address used for the lookup, not the previous contents at that address.

The operation argument is obtained separately at each call site. Dependencies or aliasing can change its shared source; successive calls are not guaranteed to receive identical values.

### 4. Nonmatching-discriminator branch

The function freshly reads the shared state-record pointer and reads the byte at its offset 2 as an unsigned 8-bit value.

If this byte differs from the selector, the branch performs no direct store and does not invoke F-da2d75c0df8d.

If the byte equals the selector:

1. Invoke F-da2d75c0df8d with the current operation argument.
2. Store zero as one byte at offset 2 through the earlier retained state-record pointer.

The comparison uses the freshly observed pointer; the store uses the retained pointer. A change to the shared pointer during F-da2d75c0df8d does not redirect that store. Validity of the retained destination must still hold when the store is reached.

There is no nonzero guard. Selector zero matching a freshly read zero byte still causes the dependency invocation and zero store.

### 5. Terminal root check

Every normally continuing branch reaches this check, including predicate rejection and a nonmatching selector/state comparison.

The function freshly obtains the current root-reference address and reads the root pointer from that location.

- If the root pointer is null, no root-word read or indirect invocation occurs.
- If the root pointer is nonnull, its first 32-bit word is read.
- If that word is zero, no indirect invocation occurs.
- If that word is nonzero, D-02 is invoked with no explicit arguments shown.

The root’s first word is a guard, not the call target. The indirect target comes from a separate shared source.

The root-reference address, root pointer, root word, and indirect target are not assumed to retain values observed before earlier dependencies or stores. Aliasing can make the function’s own byte store relevant to this final check.

The representation shows completion after the indirect invocation. The exact machine-level distinction between an ordinary call and a terminal transfer remains **documented_only**.

## Side effects

### Explicit stores and aliasing

|---|---|
| Matching discriminator and zero predicate result | Extracted selector |
| Nonmatching discriminator and equal freshly observed state byte | Zero |

This identifies the store address and width; it does not establish which logical objects remain unchanged.

If other objects overlap this byte, the store is visible through those objects too. Examples include:

- Incoming-record storage overlapping the retained state record.
- A selector-table entry overlapping the store target.
- Root storage or a shared binding overlapping the store target.

In particular, if the incoming record and retained state record share a base address, the store at offset 2 changes one byte within the incoming record’s 32-bit discriminator. Byte order determines which discriminator bits change. The earlier discriminator comparison is not repeated.

There are no additional explicit store targets shown for the input, table, configuration fields, or root storage. That is not a disjointness or preservation guarantee.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless a scenario says otherwise, dependencies return normally, required storage remains valid, and no dependency or concurrent actor changes relevant values.

### Predicate rejection

Given matching discriminators and a nonzero predicate result:

- The initial dependency occurs before the predicate.
- The predicate receives the originally extracted selector.
- This branch performs no explicit selected-state store or configuration calls.
- The terminal root check still occurs.

### Default configuration

Given matching discriminators, selector 37, a zero predicate result, an initial state byte of zero, and a table entry that remains zero:

- No stop-like invocation occurs.
- The selector byte is stored as 37.
- The default configuration is read and supplied to F-689e9e98c8f7.
- The alternate configuration is not read.
- D-01 follows the configuration call.

The table-entry condition applies at lookup time, after the selector store.

### Repeated nonzero selection

Given matching discriminators, selector 37, an initial state byte of 37, and a zero predicate result:

- F-da2d75c0df8d is invoked despite equality of the old and incoming selectors.
- The selector is subsequently stored as 37.
- Configuration processing continues.

### Alternate selection through an alias

Given matching discriminators, selector 37, a zero predicate result, and a table entry whose address equals the retained selected-state byte address:

- The selector store writes 37 to that shared byte.
- The default configuration is read.
- The table lookup reads 37 and therefore selects the alternate configuration.
- The alternate configuration is read and supplied to F-689e9e98c8f7.

This example assumes the overlapping byte and all other required accesses remain valid.

### Input and state record sharing storage

Given that the incoming record and retained state record have the same base address, and a reached store changes the byte at offset 2:

- The store also changes one byte of the incoming discriminator.
- The discriminator comparison already performed is not repeated.
- Behavior continues along the previously selected branch.
- Which discriminator bits change depends on byte order.

### Nonmatching zero selector

Given nonmatching discriminators, selector zero, and a freshly observed state byte of zero:

- F-da2d75c0df8d is invoked.
- Zero is stored through the retained pointer.
- The predicate and configuration dependencies are not invoked.

### Input mutation during the initial dependency

If the original packed value encodes selector 9 and the initial dependency changes it to encode 11, later selector-dependent behavior still uses 9.

If that dependency changes the incoming discriminator, the later comparison uses the subsequently read discriminator.

### Terminal dispatch

For a valid root-reference location:

- Null root: no root-word read and no D-02 invocation.
- Nonnull root with first word zero: root-word read, no D-02 invocation.
- Nonnull root with first word nonzero: one D-02 invocation.

These cases apply after every normally continuing earlier branch.
