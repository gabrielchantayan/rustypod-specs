## Behavior

### Indirect-call phase

The first call target is constructed from the incoming return-link value plus 4094. Subsequent preparatory targets are largely constructed from embedded execution-location references plus the same displacement.

The visible path contains a long straight-line call sequence, without an explicit loop or data-dependent branch. This says nothing about control flow inside dependencies.

Argument construction includes:

- Calls without represented explicit arguments.
- Explicit zero arguments.
- Primary 32-bit results shifted left by eight.
- Low and high portions of combined 64-bit results.
- High portions forwarded unchanged, shifted left, or shifted right unsigned.
- One transformed result supplied in multiple argument positions.
- Results retained across intervening calls.

A call without represented arguments does not imply cleared machine argument locations. An unused primary result does not imply an effect-free call.

Transformations include left shifts through bit 31; masks retaining fields of various widths, including 11–24 bits; and unsigned extraction from combined results above bits 32, 34, 36, and 44. These operations are not interchangeable. For example, shifting a combined result right by 36 selects a different quantity from its unshifted high word.

Several retained quantities are explicitly set to zero and subsequently shifted or masked. Their represented transformations remain zero until replacement. This does not imply preservation of globals or hidden state by intervening dependencies.

### First mutation boundary and the read at 0x05

A word store at final-preparatory-high-word offset 0x14 publishes the shifted base. A byte at shifted-base offset 9 then receives the low byte of that high word. Between this byte store and a second store to the same byte, a word at final-preparatory-low-word multiplied by 256, plus 0x54, receives the scaled base. The second byte store uses the low byte of the shifted base.

The scaled-base word at offset 0x14 is cleared before an unsigned byte is read at offset 5. A word at twice-small-index offset 0x14 is cleared before the promoted byte is stored as a word at scaled-base offset 0x34.

The scaled-base word at offset 0x14 is then loaded. It is not guaranteed to remain zero: intervening calculated accesses may overlap it. The twice-small-index word clear is repeated, followed by two byte stores at twice-small-index offset 0x15, both using the low byte of that loaded word.

**Only after both offset-0x15 byte stores does the function read fixed storage at 0x05.** That captured value precedes the byte write at fixed address 0x01, which receives the low byte of twice the small index.

The captured early fixed-storage value subsequently supplies:

- The base for a byte write at offset 0x15, receiving the low byte of the small index.
- The base for a word read at offset 0x54.
- The same base for the following replacement word store at offset 0x54.

Between capture and the offset-0x54 read, other writes occur: a scaled-base byte at offset 0x11 receives the low byte of the forwarded word, a word through the earlier scaled-base-offset-0x14 load receives the forwarded word at offset 0x54, and the scaled-base byte at offset 0x11 is cleared.

Consequently, the offset-0x54 word read uses the retained address value but current memory contents. Neither re-reading 0x05 later nor reading the offset-0x54 word at capture time is equivalent.

### Linked and scaled mutations

The old offset-0x54 word becomes the retained link; its storage is replaced with the earlier scaled-base-offset-0x14 load.

Subsequent groups read words at offsets 4, 0x64, and 0x74, use loaded values as addresses, and write byte fields and word links. Some word stores place an address-derived value back through an address derived from that value. Some identical stores are repeated without a fresh source read.

The retained link is scaled by two, four, and eight. Fixed word storage at 0x54 receives twice the retained link; fixed byte storage at 0x15 receives the low byte of twice the small index.

Unsigned bytes read at offset 5 participate directly in address selection. In particular, a word load at a promoted-byte value plus 0x74 is not equivalent to loading a full-width pointer at offset 5.

Later accesses to apparently unchanged bases can observe earlier writes through aliases. The represented access inventory does not establish disjoint objects.

### Constant stores and publication capture

The late link supplies three destinations receiving numeric value 0x3A:

- A byte at four times the late link.
- A halfword at eight times the late link.
- A word at quadrupled-late-link offset 0x20.

These are different-width stores at differently constructed addresses.

At constant-base offset 0x20, the ordered word values are 0x20, 0x2F, an unsigned byte freshly loaded from constant-base offset 4, and 0x20 again. The byte read occurs after the first two stores.

**After the last of these derived offset-0x20 stores, the function reads the separate publication global. That read precedes the fixed-address word store of 0x20 at 0x60.** The captured global value becomes the publication base.

Earlier calculated stores may alias this global. The publication base therefore reflects storage at that boundary, not necessarily its entry value. Conversely, later changes to the global do not replace the retained publication base.

### Repeated publication-shaped writes

The first publication group has this observable ordering:

- A word at eight-times-retained-link offset 0x54 receives the quadrupled late link.
- A byte at publication-base offset 0x19 receives the low byte of the constant base.
- A byte at constant-base offset 0x11 receives the low byte of the publication base.

Subsequent repeated groups use eight times the adjusted quantity instead of eight times the retained link for the first destination base and final stored word. The byte destinations and retained byte values remain as described.

The repeated groups are explicitly represented, not expressed as a loop. The publication global is not reloaded for each group. Matching calculated values do not establish that repeated accesses can be discarded.

**Inferred intent:** the groups resemble repeated state publication or device transactions. Neither interpretation is established. Exact repetition multiplicity is **documented_only** in this contract; it has not been independently enumerated.

### Closing fixed-storage reads and fresh reads of 0x67

The closing sequence first captures the word at fixed address 0xA9. It next reads a word at quadrupled-late-link offset 0x74, and only then writes the byte at fixed address 0x3A. That byte is the low-byte result of eight times the adjusted quantity plus 0x30, not necessarily numeric value 0x3A.

Words are then captured at doubled-late-link offset 0x14 and constant-base offset 4. Before fixed storage at 0x67 is assigned, the sequence writes:

- The retained low byte of the constant base to doubled-late-link offset 0x0D.
- Numeric byte 0x6C to constant-base offset 8.
- The retained low byte of the publication base to constant-base offsets 0x0D and 9.
- The doubled late link as a word at its own offset 0x54.

Fixed byte storage at 0x67 then receives the low byte of the previously captured 0xA9 word. After this assignment, a word is loaded at doubled-late-link offset 0x44. **The subsequent assignment to fixed byte 0x21 freshly reads 0x67 after that derived word load.**

Further writes use the offset-0x44 load at constant-base byte offset 0x10 and publication-base word offset 0x54. A signed variable-count right shift also supplies doubled-late-link byte offset 1. Publication-base offset 0x54 is then overwritten with the constant base.

A fresh word from constant-base offset 0x40 replaces constant-base offset 0x10, after the earlier byte write to that same offset. The earlier constant-base-offset-4 capture is stored at publication-base offset 0x74, and publication-base offset 0x44 receives the doubled late link.

**The next store to constant-base byte offset 9 freshly reads fixed byte 0x67.** It is followed by a byte store at doubled-late-link offset 9 and a word store at constant-base offset 0x44 using the full retained 0xA9 word. A word is then loaded at constant-base offset 0x54. **The following store to constant-base byte offset 9 reads 0x67 again.**

Thus the assignment to 0x21 and these two offset-9 stores have three distinct fixed-storage reads. None is contractually replaced by reuse of the original low byte captured from 0xA9. Intervening calculated writes may alias 0x67.

### Final mutation and dispatch

The closing stores also restore the retained doubled-late-link-offset-0x14 word into that base’s offset 0x54, while other fields are replaced with newly loaded words or their low bytes.

A word loaded from doubled-late-link offset 4 selects a further base. A halfword store of 0x65 occurs at twice that loaded value. Words from the selected base at offsets 0x64 and 0x74 are retained for dispatch. Another word is loaded at doubled-late-link offset 0x64.

Near completion, a derived offset-0x54 word receives numeric value 100. The final represented word stores precede the indirect dispatch.

The four dispatch arguments, in order, are:

1. Numeric value 0x72.
2. The retained word from selected-base offset 0x64.
3. The earlier word captured at doubled-late-link offset 0x14.
4. The retained word from selected-base offset 0x74.

These are retained values, not implied reloads immediately before dispatch.

## Acceptance examples

These are conditional static consequences, not executed tests.

### Early fixed-storage sampling

If earlier stores change storage at 0x05 before its designated read, the captured value reflects that changed storage. If the later byte write at 0x01 changes overlapping storage, it does not retroactively change the captured address used at offsets 0x15 and 0x54.

### Publication boundary sampling

If the last constant-base-offset-0x20 store changes the publication global through aliasing, the following global read captures that change. If the subsequent fixed word write at 0x60 changes the global, the retained publication base nevertheless remains the previously captured value.

### Fresh 0x67 reads

Suppose the low byte captured from 0xA9 is 0x12. If an intervening calculated write changes 0x67 to 0x34 before the first closing offset-9 copy, that copy uses 0x34. If another intervening write changes it to 0x56 before the second copy, the second uses 0x56. The earlier assignment to 0x21 uses its own earlier read.

### Byte promotion and index boundary

An unsigned offset-5 byte of 0xFE produces numeric word value 254, not a negative sign-extended value.

Under truncating 32-bit shifts, a small-index source with its lowest seven bits set produces index 508 and doubled index 1016. Address validity remains a separate prerequisite.

### Intermediate writes and aliasing

An observable constant-base-offset-0x20 destination receives 0x20, 0x2F, the promoted freshly read byte, and 0x20. Producing only the final value is insufficient.

Likewise, an intervening aliasing write can change the scaled-base-offset-0x14 word after its clear. Its later load need not yield zero.

### Interruption and dispatch

A preparatory dependency that does not return prevents subsequent direct stores and final dispatch. No synthetic completion or rollback is required.

If dispatch is reached, its first represented argument is 0x72; the other arguments use the specified retained words.
