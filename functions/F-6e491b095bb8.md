# F-6e491b095bb8

## Purpose

F-6e491b095bb8 performs prioritized dispatch using a receiver and a record. It may first call a handler selected by the record’s initial discriminator and associated comparison data. A nonzero result from that handler is returned unchanged. A zero result allows further dispatch using newly read record state.

The later dispatch recognizes discriminator values `0x14` and `0x13`. Either recognized case calls an indirect dependency and then returns `1`, ignoring that dependency’s result. If neither case matches, the function returns `0`.

The structure suggests event or message routing. That interpretation is inferred intent; the contract does not depend on it.

## Interface

### Arguments

The function receives three arguments:

1. **Receiver address:** an address used to access a dispatch-table address and two comparison fields.
2. **Record address:** an address used to access a discriminator and path-dependent payload fields.
3. **Incoming scalar:** an integer whose incoming value has no established effect on dispatch or the result. Every path that would use its working value in a comparison first replaces that value.

The receiver and record addresses supplied to first-stage dependencies are the original incoming addresses. Second-stage dependencies receive the receiver address and payload words read from the record.

### Result

The represented result is a 32-bit integer:

- A nonzero first-stage dependency result is returned unchanged, including a negative result.
- A normally completed second-stage call produces result `1`, regardless of the dependency’s result.
- Failure to select a second-stage dependency produces result `0`.

There is no distinct validation-error result. A result of `0` does not establish that all storage was valid or that a dependency was called.

The supplied representation uses four-byte integer and payload accesses. Receiver indexing establishes four-byte elements; dispatch-table accesses use the byte offsets listed below.

Address-bearing words are used as addresses in this representation. A portable pointer width, calling convention, byte order, and alignment policy are not independently established.

### Access preconditions, not continuous lifetime requirements

Each actual dereference requires readable storage of the appropriate width at that point. Each selected indirect target must be callable with the supplied arguments. These requirements are path-specific:

- The initial discriminator read always requires record storage at offset `0x04`.
- Initial `0x16` requires the record word at `0x08`, the reached nested word at `0x04`, and the global comparison word. Receiver and table storage are dereferenced only if the comparison selects the indirect handler.
- Initial `0x0F` requires the first record and receiver comparison fields. The lower-priority comparison fields are read only if the first comparison fails.
- A nonzero first-stage result causes an immediate return. The wrapper performs no later receiver, record, nested-object, or table access.
- A zero first-stage result requires subsequent discriminator access at the original record address. Receiver storage is subsequently dereferenced only if a second-stage handler is selected.
- A selected second-stage call requires its table lookup and payload reads before invocation. After that call returns normally, the wrapper only returns `1`; it does not access either object again.

The source does **not** impose continuous receiver or record validity throughout dependency execution. It also does not establish a continuous lifetime requirement for the nested object after its comparison word has been read.

Dependencies may have their own argument-validity, lifetime, and ownership requirements. Those are unknown. The absence of later wrapper accesses does not waive a dependency’s requirements or establish that releasing an object is safe for other callers.

## Behavior

### Initial classification

The function first reads the discriminator at record offset `0x04`. This observation governs first-stage selection.

Later discriminator reads are separate observations. The function does not require them to equal the initial value.

### First-stage selection: initial discriminator `0x16`

For initial discriminator `0x16`, the wrapper performs these ordered reads:

1. The nested-object address from record offset `0x08`.
2. The comparison word at offset `0x04` from that nested address.
3. The global comparison word.

It compares the nested and global words for equality.

If they match, it reads the dispatch-table address through the receiver, obtains the target at table offset `0x94`, and invokes that target with the receiver address and original record address.

- A nonzero dependency result is returned immediately.
- A zero result permits second-stage dispatch.

If the words do not match, no first-stage dependency is called, and second-stage dispatch follows. No receiver comparison field is read on this path.

The incoming third scalar does not supply either comparison value.

### First-stage selection: initial discriminator `0x0F`

The higher-priority comparison reads:

1. The record word at offset `0x08`.
2. The receiver word at offset `0x8E4`.

If those words match, the wrapper resolves table offset `0x98` through the receiver and calls that target with the receiver and original record addresses.

This match is decisive for first-stage selection. A zero result from this target does **not** cause the lower-priority comparison or F-d8689d6a5352 to be attempted.

If the higher-priority comparison fails, the wrapper performs a separate pair of reads:

1. The record word at offset `0x08` again.
2. The receiver word at offset `0x8DC`.

If those words match, it calls F-d8689d6a5352 with the receiver and original record addresses.

For either selected dependency, a nonzero result is returned unchanged and a zero result permits second-stage dispatch. If both comparisons fail, second-stage dispatch follows without a first-stage call.

The second record comparison uses a distinct read, not a saved copy of the first payload observation. This establishes the represented access sequence, not a synchronization or concurrent-mutation guarantee.

### Other initial discriminators

An initial discriminator other than `0x16` or `0x0F` causes no first-stage call. Execution proceeds to second-stage dispatch.

In particular, a stable initial `0x13` or `0x14` does not require either receiver comparison field or nested-object storage.

### Second-stage dispatch

Second-stage dispatch occurs after no first-stage handler was selected, or after a selected first-stage handler returned zero.

The wrapper reads the discriminator at record offset `0x04` again.

If this observation equals `0x14`, it resolves the receiver’s dispatch-table target at offset `0x78` and invokes it with these logical arguments:

1. Receiver address.
2. Four-byte word from record offset `0x08`.
3. Four-byte word from record offset `0x0C`.
4. Four-byte word from record offset `0x10`.

After normal completion, the wrapper returns `1`. The dependency’s result is ignored, and there are no further receiver or record accesses.

If that discriminator observation is not `0x14`, the wrapper reads the discriminator at offset `0x04` once more.

If this later observation equals `0x13`, it resolves table offset `0x5C` and invokes that target with:

1. Receiver address.
2. Four-byte word from record offset `0x08`.
3. Four-byte word from record offset `0x0C`.

After normal completion, the wrapper returns `1`, without using the dependency’s result or accessing the objects again. Record offset `0x10` is not read on this path.

If the later observation is not `0x13`, the wrapper returns `0`.

These are two distinct second-stage discriminator reads. A contract that substitutes one cached observation would omit represented behavior.

### State changes across calls

A first-stage dependency may change the record, receiver, dispatch table, or global state. No preservation guarantee is established.

After a zero first-stage result:

- Discriminator selection uses subsequent reads from the original record address.
- Any forwarded payload words are read after the call.
- A selected second-stage target is resolved through the receiver after the call.
- If neither second-stage discriminator matches, the wrapper does not dereference the receiver again.

Thus a first-stage dependency can change the discriminator from `0x0F` to `0x14`, return zero, and enable the `0x14` second-stage call, provided the accesses actually performed afterward are valid.

Conversely, a nonzero first-stage result ends execution without inspecting any post-call object state.

4. **Lower-priority match propagates its result.**

5. **Zero permits dispatch through changed state.**
