# F-072894580067

## Purpose

F-072894580067 conditionally transfers control to an indirectly selected callable. The decision depends on a chain of three values: an address stored in the input object, an address stored at that location, and a 32-bit value stored at the second location.

The established behavior is a conditional dispatch:

- An initially null first-level address causes an immediate return.
- A null second-level address causes a return without dispatch.
- A zero 32-bit value at a nonnull second-level address causes a return without dispatch.
- A nonnull second-level address containing a nonzero 32-bit value reaches the indirect control transfer.

The available static representation does not establish the application-level meaning of these values. In particular, it does not establish that the final value is a count, status, reference count, or ownership indicator.

No runtime tests have been performed.

## Behavior

### Initial gate

The function first reads the address-bearing field at byte offset 8 from the input address.

If that value is zero, the function returns immediately. On this path, the supplied representation performs no traversal to the intermediate location, no decision-value read, and no indirect dispatch.

This is a check of the field’s contents, not a check of the input address.

### Traversal after the gate

If the initial field value is nonzero, the supplied representation reads that same field again. It then reads a four-byte address value from the location designated by this second field value.

The second read matters to the behavioral contract. The initial null check is not shown as producing a retained address that is reused for traversal. Consequently:

- With stable memory, both field reads obtain the same address.
- If the field changes between reads, traversal uses the second value.
- A nonzero first read does not establish that the second value is nonzero or readable.
- No second null check protects the intermediate-location read.

These observations describe the supplied access sequence. They do not establish that concurrent modification is supported, synchronized, or defined by the original implementation language.

### Decision-value access

If the address retrieved from the intermediate location is zero, the function does not read through it and does not dispatch.

If that address is nonzero, the function reads one 32-bit integer from the referenced location. The dispatch condition uses the value obtained by this read; the supplied representation does not show another read of that location for the final decision.

Only equality with zero matters. Every nonzero 32-bit value satisfies the value portion of the dispatch condition. This includes values whose most significant bit is set and values that would be negative under a signed 32-bit interpretation.

No addition, subtraction, masking, shifting, range check, or normalization is applied to the decision value.

### Indirect transfer

Dispatch is reached only when both of the following hold:

- The address retrieved from the intermediate location is nonzero.
- The 32-bit value read from that address is nonzero.

The destination is supplied by a separate indirect target reference. No explicit argument is shown at the call site, and no result from the target is used.

The static representation explicitly reports uncertainty in recovering this transfer and treats an indirect jump as a call. Therefore, the contract distinguishes two levels of evidence:

- **Established:** the qualifying path reaches an indirect control transfer.
- **Represented but not fully established:** that transfer behaves as an ordinary returning call with no arguments.

If the transfer returns as represented, F-072894580067 returns without further shown work. If it does not return, the subsequent return is not reached.

There is no shown validation of the target before transfer.

## Acceptance examples

These examples are conditional acceptance criteria derived from static evidence. They are not reports of executed tests. Except where an example explicitly concerns a changed field, assume stable, readable memory and compatible target execution.

### Initially null first-level field

Given an input whose offset-8 field contains zero:

- The function returns without dispatch.
- No intermediate-location or decision-value read is required by this path.
- No direct write occurs.

This example still requires the offset-8 field itself to be readable.

### Null address at the intermediate location

Given a nonzero first-level field whose referenced location contains a zero address:

- The function reads the intermediate address value.
- It does not dereference that zero address.
- It returns without dispatch and without direct writes.

### Zero decision value

Given a nonzero first-level field, a nonzero address at the intermediate location, and a zero 32-bit value at the referenced location:

- The function reads that decision value.
- It does not reach the indirect target.
- It returns without direct writes.

### Nonzero decision value

Given the same valid chain with a decision value of 1:

- The indirect transfer is reached once during this invocation.
- No result from the target is used.
- If the transfer returns as represented, the function then returns.

The same dispatch decision applies to any other nonzero 32-bit pattern, including the all-ones pattern.

### Field changes between its two reads

Suppose the first field read obtains a nonzero address, but the second field read obtains a different address.

Under the supplied access model, the intermediate-location read uses the second address. Acceptance must not require reuse of the initially checked value.

If the second value is zero or inaccessible, the initial nonzero check does not provide a safe-return guarantee. The exact resulting failure behavior is platform-dependent and unresolved.

### Invalid indirect destination

Given a valid traversal and a nonzero decision value, an unusable indirect destination does not select a shown fallback path. The function attempts the qualifying control transfer; no explicit error result or recovery is established.
