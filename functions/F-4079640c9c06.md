# F-4079640c9c06

## Purpose

F-4079640c9c06 performs a signed-index lookup through a context obtained from F-ecd921e533b1. It returns either a 32-bit value loaded from a table or zero when the index fails the visible range check.

The accepted index range is zero inclusive to a stored signed bound exclusive. An index equal to the bound is rejected. A negative index is rejected without reading the context’s bound or table fields, although the context-producing dependency is still called.

The returned value is represented as an integer. Its use as a pointer, handle, or other token by callers is not established. The visible operation does not dereference the selected value after loading it.

## Interface

### Input

One signed 32-bit integer, interpreted as an index.

There is no explicit context, table address, output buffer, or error-output argument. The context comes from F-ecd921e533b1.

### Output

One 32-bit integer containing either:

- Zero, for a rejected index.
- The bit pattern of the selected 32-bit table entry, for an accepted index.

A selected entry may itself be zero. Consequently, the return value alone does not distinguish a rejected index from an accepted index whose entry contains zero.

The visible implementation routes the loaded entry through a pointer-shaped intermediate before returning it as an integer. This does not establish that the entry designates a valid object. Nonzero results are not validated.

The supplied representation uses a 32-bit integer/address model. F-ecd921e533b1 produces a 64-bit result, of which only the low 32 bits affect this function’s result or memory accesses.

## Behavior

### Context acquisition

F-ecd921e533b1 is called once, before the input’s sign determines whether context memory will be read.

This call occurs for every input, including negative inputs that ultimately produce zero. The function therefore does not provide a dependency-free rejection path.

The low 32 bits of the returned value supply the context base. There is no visible check for a zero or otherwise invalid context base.

### Negative inputs

Every negative input produces zero, provided the dependency call returns normally.

For this path, the visible function does not read:

- The stored bound.
- The table-address field.
- A table entry.

The dependency may itself perform reads, writes, or other actions. Those actions cannot be inferred from this function.

### Nonnegative inputs and the bound

For every nonnegative input, the function first reads the signed 32-bit bound from context offset 196.

The input is accepted only when it is strictly less than that bound. Thus:

- A positive bound permits indices from zero through one less than the bound.
- A zero bound permits no indices.
- A negative bound permits no indices, because all inputs reaching this check are nonnegative.
- Equality with the bound is rejected.

A rejected nonnegative input returns zero without reading the table-address field or a table entry.

The bound is read once. The visible function does not refresh it after loading the table address or before reading the selected entry.

### Accepted lookup

For an accepted input, the function reads the 32-bit table base from context offset 192. It then reads one 32-bit entry at the table base plus four times the input index.

That entry supplies the returned bit pattern.

There is no visible:

- Null check on the table base.
- Check that the selected entry is nonzero.
- Dereference of the selected entry’s value.
- Search, iteration, fallback, or retry.
- Additional validation of the table’s allocated extent.

A null table base is not a special empty-table marker in the visible behavior. If the bound accepts the input, lookup proceeds using that base.

### Access order

The visible operation order is:

1. Call F-ecd921e533b1.
2. For a nonnegative input, read the bound.
3. For an accepted input, read the table base.
4. Read the selected table entry.
5. Return that entry’s bit pattern.

A rejected input omits the table-base and entry reads. A negative input also omits the bound read.

This is the order established by the supplied representation. It does not establish hardware memory-ordering guarantees, synchronization, or atomicity with respect to concurrent writers.

### Integer and address boundaries

Index comparisons use signed values. A bound whose high bit is set is therefore negative, not a large positive capacity.

Table entries occupy four bytes. An accepted index is not automatically a safely addressable index: multiplying a large positive index by four may exceed the range of a signed 32-bit intermediate, and adding either a context offset or an entry displacement may cross the address range.

The representation does not provide enough information to define those overflow cases as portable arithmetic. In particular, this contract does not promise wraparound, trapping, or successful access for such cases. Ordinary lookup examples below assume that address arithmetic is representable and the required reads are valid.
