# F-7e3c181d3a8f

## Purpose

F-7e3c181d3a8f searches an object's associated sequence of 32-bit integer values for a requested value. On the first match, it copies the matching sequence element into a field of the object and returns status 0. Otherwise, it returns a status distinguishing a null object, a null sequence pointer, or exhaustion of the search range.

The established behavior is a bounded, forward, exact-equality search followed by one destination write. Interpreting the destination as a “current selection” is inferred intent, not an established requirement. No evidence identifies the application-level meanings of the sequence values or status codes.

## Interface

The function accepts two arguments:

| Argument | Behavioral role |
|---|---|
| Object address | Identifies the object containing the sequence description and destination field. Zero receives explicit handling. |
| Requested value | A 32-bit integer compared for exact equality against sequence elements. |

The supplied representation uses an integer-typed object address and 32-bit integer data accesses. It is consistent with a 32-bit address model. The exact calling convention, pointer representation, and machine-level interpretation of address comparisons are not independently established.

### Object layout

Only the following portions of the object are referenced:

| Byte offset from object address | Accessed content | Use |
|---|---|---|
| 0x24 | 32-bit integer | Number of sequence elements used to calculate the search endpoint |
| 0x28 | Sequence pointer | Address of the first sequence element |
| 0x5c | 32-bit integer | Destination for the matching element |

Sequence elements are 32-bit integers with a four-byte stride. The endpoint is calculated by advancing the sequence pointer by the element count, not by treating the count as a byte count.

No evidence establishes the object's complete size, surrounding fields, allocation method, or invariants beyond these accesses.

### Output

The return value is a 32-bit status:

| Status | Condition |
|---|---|
| 0 | A matching element was found and the destination write was performed |
| 6 | The search reached or was already at its endpoint without finding a match |
| 0x23, decimal 35 | The object address was zero |
| 0x26, decimal 38 | The object was nonzero, but its sequence pointer was zero |

The supplied evidence contains no additional ordinary return path. Invalid memory access and invalid address arithmetic are not translated into these statuses.

### Access preconditions

For execution beyond the null-object case, the sequence-pointer field must be readable. If that pointer is nonzero, the count field must also be readable.

For an ordinary positive-length search, the sequence must provide readable storage for the declared number of four-byte elements, and endpoint calculation must be valid for that storage. If a match occurs, the destination field must be writable.

The function does not validate these preconditions. In particular, a nonzero address is not evidence that it identifies accessible storage.

## Behavior

### Initial checks and their precedence

The object address is checked first. If it is zero, the function returns 0x23 without reading any object or sequence storage.

For a nonzero object address, the function reads the sequence pointer at offset 0x28. If this pointer is zero, it returns 0x26. In this case it does not read the count field, inspect any sequence element, or write the destination.

Only after obtaining a nonzero sequence pointer does the function read the count at offset 0x24 and calculate the endpoint.

This ordering is observable in the supplied access structure. A null sequence pointer takes precedence over any count value. A zero count does not turn a null sequence pointer into an empty-search result.

### Range formation

The sequence pointer establishes the initial search position. The count establishes an endpoint at that many four-byte elements beyond the initial position.

For an ordinary valid count of \(n\) elements, the byte displacement is \(4n\). That expression describes the layout relationship; it is not a guarantee of arbitrary-precision arithmetic, checked multiplication, or wrapping behavior.

The established range-control rule is that the search stops whenever the current position is greater than or equal to the endpoint. Consequently:

- A valid zero-length range is exhausted immediately.
- The endpoint is excluded from the search.
- The function checks the range boundary before reading the element at the current position.
- The function does not use a sentinel value to terminate the sequence.

Negative counts and endpoint calculations outside valid address ranges require qualification; they are addressed under Uncertainties.

### Search and successful update

For each position that passes the boundary check, the function reads the current 32-bit sequence element and compares it with the requested value.

If they differ, it advances by one four-byte element and repeats the boundary check. There is no subtraction-based comparison, ordering-based value test, or special treatment of zero or negative sequence values.

If they match, the search stops at that position. The function then reads that same element again and writes the result of this second read into the object's destination field at offset 0x5c. It returns 0 after that write.

This second read is significant. Under stable memory, the destination receives the requested value because the selected element just compared equal to it. The supplied access structure does not instead assign the requested argument directly, nor does it explicitly retain the comparison read for the destination update.

If storage can change between the comparison read and the subsequent read, the evidence does not establish that the written value must still equal the requested value. No synchronization or atomic transaction is present in the supplied representation.

### Exhaustion

If the boundary check determines that no searchable position remains, the function returns 6.

It does not clear, reset, or otherwise write the destination on this path. For an ordinary valid range whose elements do not match, the destination retains its previous contents, absent changes by another actor.

## Side effects

The function's explicit data accesses occur in this order:

1. Read the sequence-pointer field, unless the object address is zero.
2. Read the count field, unless the sequence pointer is zero.
3. Read candidate sequence elements in ascending position order, subject to a boundary check before each candidate.
4. On a match only, read the matching element again.
5. Write one 32-bit value to the destination field.

This list describes the supplied function's access structure, not a guarantee about processor bus transactions, compiler transformations, or a concurrent memory model.

The sequence pointer and count are each obtained once for the search. They are not explicitly refreshed after each element. The destination is not explicitly read before it is written.

There is no explicit allocation, deallocation, ownership transfer, I/O, callback, or global-state access. Caller-provided storage remains caller-provided storage; the function does not release it.

The only explicit write targets the destination field. If the caller arranges overlapping storage, that write can also affect whatever aliases the same bytes. For example, if the destination overlaps a sequence element, a successful call writes that element's storage. The function performs no subsequent search after its successful write.

There is no rollback mechanism for invalid accesses. A failure while reading an element or writing the destination is not represented by an ordinary error status in the supplied evidence.
