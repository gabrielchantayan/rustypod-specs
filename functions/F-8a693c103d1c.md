# F-8a693c103d1c

## Purpose

F-8a693c103d1c consumes two encodings, each supplied as two 32-bit words, and returns one 64-bit bit pattern.

**Inferred intent:** sign-dependent magnitude addition and subtraction, exponent alignment, normalization, and rounding adjustments suggest software binary64 subtraction: the first operand minus the second.

**Established limitation:** the supplied static representation does not establish universal IEEE 754 behavior. Global values participate in classification, significand construction, dispatch, and result selection. Their contents are unavailable. Some exceptional cases transfer control to an unresolved target, and some shifts require processor semantics not established here.

The contract therefore distinguishes visible word-level behavior from inferred numerical meaning. In particular, it does not substitute conventional floating-point classification or significand extraction for the visible global-dependent operations.

| Position | Interpretation |

| 1 | First operand’s low word |
| 2 | First operand’s high word |
| 3 | Second operand’s low word |
| 4 | Second operand’s high word |

An operand’s encoding is its high word multiplied by \(2^{32}\), plus its low word. Return values use the same high/low assembly.

The operands are values, not pointers. No explicit buffer, length, allocator, or output-storage argument is present.

The apparent numerical layout is:

- Bits 62–52: an 11-bit exponent.

This interpretation follows from the masks and shifts. It does not establish memory byte order or the external calling convention.

### Widths and interpretation

Word-level arithmetic is interpreted as wrapping modulo \(2^{32}\). Complements are 32-bit complements. Carry refers to carry beyond bit 31; low-word carry or borrow participates in high-word arithmetic where shown.

Comparisons are unsigned unless a signed interpretation is specified. Signed tests use the 32-bit sign bit. Signed right shifts of the mask provide sign-extended values in the supplied representation.

Result assembly preserves bit patterns without numerical floating-point conversion. Reversing an encoding’s sign toggles bit 63.

## Behavior

### Initial classification

Classification examines the first operand before the second.

For the first operand, its high word is increased by `0x00100000`, doubled with 32-bit wraparound, and intersected with a read of the classification mask. A zero intersection immediately selects exceptional processing.

Only if that intersection is nonzero is the corresponding test performed for the second operand, using another source-level reference to the mask. A zero second intersection also selects exceptional processing. Main arithmetic requires both intersections to be nonzero.

This predicate is the established classifier. Its equivalence to any conventional floating-point category depends on the mask.

### Exceptional direct selection

Exceptional processing reads the classification mask again and sets bit `0x00200000` in that value to obtain a derived mask.

A direct-selection subcase applies if, for each operand, the derived mask contains at least one bit absent from that operand’s doubled high word. Within that subcase:

1. A nonzero intersection between the derived mask and the first operand’s doubled high word returns the first operand unchanged.
2. Otherwise, such an intersection for the second operand returns the second operand with bit 63 toggled.
3. Otherwise, zero-sign selection applies.

The first operand has precedence when both intersections are nonzero. These returns are not independently established as particular floating-point categories.

Zero-sign selection retains the first operand only when it is exactly negative zero: high word `0x80000000`, low word zero. Every other first encoding is replaced by all-zero bits. If the second operand is exactly negative zero, the returned high word is forced to zero as well.

Consequently, this subcase returns negative zero only when the first operand is exactly negative zero and the second is not exactly negative zero.

### Exceptional compressed comparison

When direct selection does not apply, each operand receives a compressed classification value: twice its high word, plus one if its low word is nonzero, all at 32-bit width.

The first compressed value is compared with the derived mask. The second comparison is needed only if the first does not exceed that mask. If either value strictly exceeds the mask, processing proceeds to indirect dispatch.

Otherwise:

- Equal compressed values and different original signs return the first high word with a zero low word.
- Equal compressed values and matching signs return a global exceptional-result high word with low word one.
- Unequal compressed values return the first high word with low word zero when the first compressed value is `0xffe00000`.
- All other unequal cases return the second high word with its sign toggled and low word zero.

Compressed equality is not full encoding equality. The low words contribute only their zero/nonzero predicates.

### Exceptional indirect dispatch

The low four bits of a control-word read select a dispatch route. Later control-bit tests and argument construction reference the control global separately; they are not established uses of the selector’s original value.

The indirect target is the incoming return-link value with its bottom two bits cleared. The representation treats the transfer as a call whose apparent 64-bit result is returned directly. Whether the executable uses an ordinary call or another continuation convention is unresolved.

The visible argument forms are:

| Selector | Subsequent condition | Explicit supplied arguments |
|---|---|---|
| 9 | Bit `0x00100000` clear | Zero; shared dispatch constant |
| 9 | That bit set, and any bit in `0x00070000` set | Eight; transformed control word described below |
| 9 | That bit set, and all bits in `0x00070000` clear | `0x30000000`; shared dispatch constant; `0x30000000` with incoming processor-state bit 0 inserted at bit 27 |
| 10 | Any | One word: `0x80000000` when a subsequent control read has bit `0x40` set, otherwise zero |
| 8 | Bit `0x40` set | Zero; zero |

| 8 | Bit `0x40` clear, bit `0x10` set | Zero; alternate dispatch constant |

For the second selector-9 route, the control value used for argument construction is first shifted left by 15, then complemented at 32-bit width, then shifted left once more. The resulting word has:

- Bit 0 clear.
- Bits 1–15 set.
- Bits 16–31 equal to the complements of control bits 0–15.

Equivalently, its bit pattern is the complemented control word shifted left by 16, with `0x0000fffe` set. Omitting those low set bits changes the argument.

For selector 8 with bit `0x40` clear, the ordinary low-word constant is obtained first, followed by the shared dispatch constant. The subsequent bit-`0x10` test can replace that pair with zero and the alternate constant. Selecting the alternate pair does not establish that the ordinary constants were unread.

### Main arithmetic with equal signs

Matching original sign bits select magnitude subtraction.

The function orders working encodings using unsigned high/low comparisons. If the second encoding exceeds the first, it rearranges the working words and adjusts a sign bit before continuing. These changes affect local values, not caller storage.

The larger working high word supplies an exponent/sign-related field through a right shift by 20. Removing that field leaves its low 20 bits.

The smaller operand is **not** processed by an unconditional low-20-bit fraction extraction. The classification mask participates again:

- One mask reference, interpreted as signed and shifted right by two, supplies a subtraction base.
- Another reference, also interpreted as signed and shifted right by two, is complemented to mask the smaller working high word.
- The masked high word, increased by one when the smaller low word is nonzero, is subtracted from the base.
- The smaller low word contributes its 32-bit negation.

If both references observe the same mask value, the same signed-shifted mask therefore serves as both subtraction base and the source of the complement mask. Equal observations are not guaranteed under mutation; the supplied expression does not establish a relative evaluation order for those two references.

The exponent-field difference determines alignment:

- Differences through 32 use a direct two-word alignment route.
- Larger differences use a reduced discarded-bit representation.
- Original differences of 62 or more return the selected larger working encoding without subsequent normalization.

Carry from low-word accumulation feeds the signed high intermediate. The sign of that intermediate selects direct reconstruction or further shifting and normalization.

The normalization routes can:

- Use leading-zero counts across both working words.
- Reconstruct an exponent after accounting for the normalization distance.
- Return literal positive zero when the reconstructed exponent is negative.
- Return literal positive zero in another small-result range.
- In a terminal case, return a surviving low word with a zero high word.

Thus a universal gradual-underflow guarantee is not established.

Rounding uses retained and discarded information. An increment can carry into the high word. Some exact-boundary cases clear the result’s low bit, consistent with ties-to-even behavior, but insufficient to establish one rounding rule for every route.

### Main arithmetic with different signs

Different original sign bits cause the second sign bit to be toggled, followed by working-encoding ordering and magnitude addition.

The larger high word again contributes its exponent/sign-related field and low 20 bits. Construction of the smaller high contribution uses an additional classification-mask read:

- Interpret that mask as signed.
- Shift it right by one with sign extension.
- Complement that 32-bit value and use it to mask the smaller high word.
- Set bit `0x00100000` in the masked result.

This dependence must be retained even when the mask’s deployed value is unknown.

Exponent differences through 32 use a direct two-word alignment route. Larger differences use a separate high-word alignment and reduced rounding contribution. Low-word carry participates in the high accumulation. A significand carry can cause a one-bit right normalization and exponent adjustment.

Rounding can increment the low word, propagate into the high word, or clear the lowest result bit for a boundary case. It is not equivalent to incrementing whenever any discarded bit is nonzero.

Certain normalization and final-rounding routes range-check twice the reconstructed high word, using wrapped unsigned arithmetic, against `0xffe00000`. Other direct-return routes do not perform that check.

When a checked result fails the range condition:

- The returned low word is zero.
- The high word is selected from a global overflow-result constant.
- A signed test involving the reconstructed high word and an address-like quantity can select another read of that constant with its sign bit set.

The constant’s contents and the address-like expression’s numerical interpretation are unavailable. A correctly signed infinity result is therefore not an unconditional guarantee.

## Side effects

### Direct effects and ownership

The function reads global classification, control, and result-selection data. No direct global store is visible.

No explicit allocation, release, buffer write, file operation, or synchronization operation appears. The operands are passed by value, and local rearrangement does not modify caller-owned input objects.

There is no separate visible error status. Direct returns are 64-bit bit patterns, including exceptional-result encodings.

The unresolved indirect dependency may have additional effects. Neither preservation of globals nor acquisition or release of memory may be assumed.

### Source-level access ordering

The meaningful ordering is:

1. First-operand classification precedes second-operand classification and can suppress it entirely.
2. Exceptional entry performs a fresh mask reference to construct the derived mask.
3. Main arithmetic instead reaches its own additional mask references: two uses in equal-sign subtraction, one in different-sign addition.
4. Exceptional dispatch extracts the selector before route-specific control tests.
5. Selector-9 tests occur before its route-specific argument construction, which can read the control word again.
6. Selector-8’s ordinary constant pair is obtained before its bit-`0x10` selection test.
7. Any indirect transfer follows the selected argument preparation.

The equal-sign expression’s two mask references do not establish an internal evaluation order. Nor does argument-list presentation establish a general order among otherwise independent argument evaluations.

These are source-level ordering facts, not machine-load counts. Volatility, atomicity, compiler reuse, and coherent behavior under concurrent mutation are not established. No global read is shown after the indirect dependency returns.

## Acceptance examples

All examples are conditional static acceptance criteria, not reported executions.

### Zero-sign selection

Assume every relevant mask read yields `0xffe00000`.

| First operand | Second operand | Required result |
|---|---|---|
| Positive zero | Positive zero | Positive zero |
| Negative zero | Positive zero | Negative zero |
| Positive zero | Negative zero | Positive zero |
| Negative zero | Negative zero | Positive zero |

These cases do not require indirect dispatch.

### Infinity-shaped exceptional encodings

Under the same mask assumption, two operands with high word `0x7ff00000` and low word zero return the global exceptional-result high word with low word one.

With first high word `0x7ff00000`, second high word `0xfff00000`, and both low words zero, the result is `0x7ff0000000000000`. Reversing those signs yields `0xfff0000000000000`.

### Selector-9 transformed argument

Assume dispatch is reached and the selector, subsequent tests, and construction read all observe control value `0x00110009`.

The selector is 9, bit `0x00100000` is set, and `0x00070000` has a set bit. The explicit arguments are eight and `0xfff6fffe`.

An argument of `0xfff60000` would fail this criterion: bits 1–15 must remain set.

### Arithmetic mask participation

Assume the equal-sign arithmetic expression’s two mask references both yield `0xffe00000`. Its signed right-shift-by-two value is `0xfff80000`, and the complementary smaller-high-word mask is `0x0007ffff`.

If the smaller working high word is `0x00180000` and its low word is zero, the masked contribution is zero and the subtraction base remains `0xfff80000`. Replacing this operation with conventional low-20-bit extraction would incorrectly retain `0x00080000`.

For different-sign arithmetic with mask `0xffe00000`, the signed right-shift-by-one value is `0xfff00000`. Its complement is `0x000fffff`; bit 20 is set after masking.

These criteria concern intermediate behavior, not an asserted final numerical result.

### Dispatch and access boundaries

If the first initial classification intersection is zero, second-operand initial classification is skipped. Exceptional-mask construction still references the mask again.

If selector 8 reaches the bit-`0x10` alternate selection, the ordinary constant pair has already been obtained at source level. A specification promising that those reads never occur would be incorrect.

### Rounding and small-result boundaries

On a route that propagates an incrementing-rounding carry, a retained low word of `0xffffffff` becomes zero and increments the high word.

If equal-sign normalization reaches its explicit negative reconstructed-exponent return, the result is all-zero bits. Returning a nonzero subnormal solely to match conventional binary64 subtraction would violate that branch.
