# F-2f29757a145a

## Purpose

F-2f29757a145a performs an ordered sequence of raw memory reads and writes, followed by an indirect control transfer with four arguments. Its visible effects include:

- Updating fields reached through explicit and implicit inputs.
- Using scaled integer values as memory addresses.
- Truncating addresses and other 32-bit values into byte-sized fields.
- Repeatedly publishing the same values to several locations.
- Reading and writing fixed low-address storage.
- Invoking an unresolved target after the memory updates.

No application-level purpose is established. In particular, the evidence does not establish that this is a formatter, collection operation, object initializer, or ownership-management routine. Apparent character constants and pointer-like relationships are insufficient to assign those meanings.

This contract describes the supplied static representation. It does not establish that the representation is a complete or accurate account of executable behavior.

## Interface

### Explicit inputs

The displayed interface has four 32-bit inputs and no declared return value.

| Input | Established use |
|---|---|
| First input | Not referenced in the visible body. |
| Second input | An address-like value used for a 32-bit write at offset `0x34` and a 32-bit read at offset `0x74`. |

- A **scale seed**, doubled and quadrupled for address calculations and stored values.
- A **link seed**, stored directly and also doubled for a later address calculation.

Their calling-convention locations and initialization requirements are **documented_only**. They are genuine dependencies of the supplied representation, not values established by the four explicit inputs.

### Contract notation

The following labels describe roles and derived values; they are not source identifiers:

- **Primary base**: the original third input.
- **Secondary base**: the second input.
- **Doubled seed** and **quadrupled seed**: twice and four times the scale seed.
- **Secondary-derived base**: twice the 32-bit value read from secondary base plus `0x74`.
- **Initial selected base**: the 32-bit value read at an address formed by adding `0x74` to the unsigned byte read from doubled seed plus `5`.
- **Primary-linked base**: the 32-bit value read from primary base plus `4`.
- **Later selected value**: the 32-bit value obtained through a subsequent byte-indexed lookup using primary-linked base plus `5`.
- **Twice-selected base** and **four-times-selected base**: twice and four times the later selected value.
- **Adjusted input**: primary base minus `0x96`.
- **Scaled base**: four times the adjusted input.
- **Eightfold base**: eight times the adjusted input.
- **Shared base**: a 32-bit address-like value loaded from a fixed global slot during execution.

“Low byte” means truncation to the least significant eight bits. Byte reads used as lookup addresses are unsigned and range from 0 through 255.

## Behavior

### Widths, arithmetic, and aliasing

The representation distinguishes 8-bit, 16-bit, and 32-bit accesses. A byte store does not imply a word store; the halfword stores described below are likewise distinct.

Most address arithmetic is represented using signed 32-bit quantities. The scaled base is held as an unsigned 32-bit quantity after its arithmetic expression is evaluated. This does not, by itself, prove that preceding signed multiplication or subtraction has defined wraparound semantics.

For conditional acceptance, arithmetic that stays within the relevant representable ranges avoids this ambiguity. Overflow, negative left-shift operands, and excessively large shift counts remain **documented_only** unless machine-level semantics are supplied.

Address ranges may overlap. Values read later must reflect earlier writes where aliasing requires it. A read described below is not generally an entry-state snapshot. Conversely, once a value has been loaded and retained, later writes to its original storage do not establish a reload.

### Initial field updates and selection

The initial phase establishes several link-like fields while retaining intermediate values:

- The fourth input is written to primary base plus `0x54`, then the link seed is written to secondary base plus `0x34`.
- The secondary-derived base is obtained from secondary base plus `0x74`. That read occurs after both preceding stores.
- Doubled seed plus `0x54` receives the doubled seed itself.
- Primary base plus `0x15` receives the low byte of the quadrupled seed.
- Auxiliary base plus `0x44` receives the secondary-derived base.

The initial selected base is then obtained through the unsigned byte at doubled seed plus `5`. The byte is used directly as an address contribution: the 32-bit lookup occurs at that byte’s value plus `0x74`. It is not established as an index into a separately supplied table.

The initial selected base plus `0x44` receives the secondary-derived base. Primary base plus `0x15` is then overwritten with the low byte of the doubled seed.

The low byte of the initial selected base is propagated to doubled seed plus `0x0d`; doubled seed plus `0x14` receives a 32-bit self-reference. Primary base plus `0x54` is overwritten with the link seed.

A successor address is read from doubled seed plus `0x64`. That successor receives the same low byte at offset `0x0d` and a 32-bit self-reference at offset `0x14`. The primary-linked base is read from primary base plus `4` after those successor writes.

Next, secondary-derived base plus `9` receives the low byte of the initial selected base, and secondary-derived base plus `0x44` receives the quadrupled seed.

### Primary-linked rereads and overlapping fields

The byte at primary-linked base plus `5` is read twice at separate points. These reads must not be treated as one immutable lookup.

Following the first read:

- Doubled seed plus `9` receives the low byte of the secondary-derived base.
- Initial selected base plus `0x44` receives the unsigned byte value, widened to 32 bits.
- Primary base plus `0x14` receives the quadrupled seed.
- Secondary-derived base plus `0x15` receives the low byte of the primary-linked base.
- Secondary-derived base plus `0x44` is overwritten with the primary base.

After the second read, primary base plus `0x15` receives the low byte of the quadrupled seed. The later selected value is then read at the second byte value plus `0x74`.

The subsequent field updates place:

- The low byte of the primary-linked base at primary base plus `0x15`.
- The link seed at primary base plus `0x54`.
- The low byte of the twice-selected base at doubled seed plus `9`.
- The quadrupled seed at primary base plus `0x14`.

The final word store overlaps the preceding byte store at primary base plus `0x15`. Consequently, the byte cannot be described as an independent final field. Its resulting value depends on the word’s byte order and any subsequent aliasing.

3. The unsigned byte read from scaled base plus `4`, widened to 32 bits.

The shared base is loaded from its fixed global slot. A 32-bit `0x20` is then written at absolute address `0x60`.

- Four-times-selected base to doubled link seed plus `0x54`, as 32 bits.
- The low byte of the scaled base to shared base plus `0x19`.

The subsequent repeated groups use eightfold base plus `0x54` as the word destination and the eightfold base as the value at shared base plus `0x34`. Each group retains the order: word destination, shared-base byte, scaled-base byte, shared-base word.

This limits exact transaction-count acceptance; it does not justify collapsing the region to its final memory values.

### Late snapshots and field replacement

After the repeated region, the routine captures a 32-bit value from absolute address `0xa9` and another from four-times-selected base plus `0x74`.

The routine then captures:

A **terminal base** is read from scaled base plus `0x54`. The routine then:

- Again copies the current byte at `0x67` to scaled base plus `9`.
- Stores the low byte of the captured word from four-times-selected base plus `0x74` at terminal base plus `0x0d`.
- Restores the earlier captured word from twice-selected base plus `0x14` into twice-selected base plus `0x54`.
- Captures a word from scaled base plus `0x14`.
- Stores the same low byte used at terminal offset `0x0d` into twice-selected base plus `0x11`.
- Replaces scaled base plus `9` with the low byte of the terminal base.
- Replaces scaled base plus `0x44` with the terminal base.

A **final linked base** is read from twice-selected base plus `4`. A 16-bit `0x0065` is written at twice that address. A **final downstream base** is then read from final linked base plus `0x64`.

Terminal base plus `0x11` receives the low byte of the captured word from scaled base plus `0x14`; terminal base plus `0x54` receives 32-bit decimal `100`.

The routine captures a word from final linked base plus `0x74`, then reads a **final successor base** from twice-selected base plus `0x64`. It stores the low byte of the final linked base at twice-selected base plus `9`, writes the final downstream base at final successor base plus `0x54`, and writes the final successor base at twice the final downstream base.

3. The earlier captured word from twice-selected base plus `0x14`.

### Intermediate stores remain observable

### Unsigned byte-address lookup

If the byte used for a lookup is `0xfe`, the subsequent 32-bit read is at absolute address `0x172`. It is not at a negative displacement and not at an unspecified table base plus a scaled index.

### Byte truncation

If the shared base has low byte `0xab`, its publication into scaled base plus `0x11` stores byte `0xab`. It does not store the full shared-base value or establish that a complete pointer fits in that field.

### Overlapping primary fields

If primary base plus `0x14` receives word `0x11223344` after a byte store at plus `0x15`, the resulting byte at plus `0x15` comes from the word representation. Under little-endian storage it is `0x33`; under big-endian storage it is `0x22`. Neither byte order is established here.

### Separate reads can differ

If an intervening write aliases primary-linked base plus `5`, the second byte lookup must use the updated byte. Acceptance cannot require both lookup reads to match.

### Captured argument survives later field replacement

Absent corruption of execution state, the third indirect-transfer argument is the word captured earlier from twice-selected base plus `0x14`. It is not replaced by the self-reference or restored value later written at offset `0x54`.

### Invalid access has no specified recovery

If a required address is inaccessible, the contract does not promise a status code, normal return, or reversal of prior writes. The precise failure mechanism is environment-dependent.
