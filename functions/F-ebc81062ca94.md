# F-ebc81062ca94

## Purpose

F-ebc81062ca94 conditionally publishes a 32-bit payload into one of three indexed tables, then sets a corresponding bit in an indexed control word.

Two inputs select the destination: an unsigned index identifies the table slot and control record; a signed selector identifies one of three payload tables and one control-bit mask. Unsupported selectors cause an early return without a payload or control-word access.

The apparent intent is to associate a payload with an indexed facility and enable or mark that association. Whether the payload represents a callback, address, identifier, or ordinary data is unknown. Likewise, the control word may be ordinary memory or a device register; the supplied evidence does not establish its external meaning.

## Behavior

### Control-record selection

The control address is selected before the selector is dispatched:

- For index values 0 through 3, the control address is `0x3C700000 + 32 × index`.
- For index values 4 and above, the control address is `alternate control base + 32 × index`.

The alternate branch does **not** subtract 4 from the index. Its first selected record, at index 4, is 128 bytes beyond the alternate base.

The index multiplication is unsigned arithmetic. Under the represented 32-bit model, the offset is the low 32 bits of `32 × index`. No overflow check is present.

For an index of at least 4, determining the control address uses the alternate base even if the selector will subsequently be rejected. This is distinct from accessing the control word: an unsupported selector does not dereference that computed control address.

### Selector mapping

| Selector | Payload destination | Control mask |
|---|---|---|
| 0 | Mode-0 table base + `4 × index` | `0x00004000` |
| 1 | Mode-1 table base + `4 × index` | `0x00001000` |
| 2 | Mode-2 table base + `4 × index` | `0x00002000` |
| Any other value | None | None |

The payload-slot offset is also unsigned arithmetic. Under the represented 32-bit model, it is the low 32 bits of `4 × index`.

Signedness matters only to interpreting the selector input; dispatch uses exact equality with 0, 1, and 2. Negative values and positive values above 2 all take the unsupported-selector path.

### Supported-selector update

For a supported selector, the source-level memory effects have this order:

1. Store the complete 32-bit payload into the selected payload slot.
2. Read the selected 32-bit control word.
3. Form the bitwise OR of that word and the selector’s mask.
4. Store the resulting 32-bit word back to the same control address.

The payload is not read by the function. The old payload-slot contents are not preserved or returned.

The control update sets the selected mask bit while retaining all other bits from the value actually read. It does not clear either of the other two mode-associated bits.

The final control-word store is present even when the selected bit was already set. Therefore, an unchanged final numeric value does not imply that the function performed no write.

This is a read followed by a separate write, not an established atomic bit-set operation. No lock, retry, compare-and-exchange, or explicit memory barrier appears in the supplied evidence.

The listed order is established at the supplied representation’s level. Exact bus transactions, processor ordering, compiler treatment of device memory, and device-visible completion are not established.

### Unsupported selector

For any selector other than 0, 1, or 2, the function returns after control-address selection.

On this path:

- No payload-table slot is written.
- No selected control word is read.
- No selected control word is written.
- No error code is returned.

For index values of at least 4, this path still depends on evaluating the alternate control base. It should not be described as a path with necessarily no memory reads at all.

### Overlapping storage

The evidence provides no guarantee that payload tables are separate from the control region or from one another.

If the selected payload slot is exactly the selected control word, the payload store occurs first. The subsequent control read therefore observes that stored payload, absent intervening agents or unusual memory semantics. The final word becomes the payload ORed with the selected mask, rather than the original control word ORed with that mask.

For partial overlap, behavior depends on byte order, alignment support, and the underlying memory system. The function provides no overlap protection.

### Unsupported selector

### Exact payload/control alias

Given selector 0, payload `0x00000003`, and identical addresses for the selected payload slot and control word, ordinary memory with no concurrent modification ends with `0x00004003`.

The original contents at that address do not supply the control value because the payload write precedes the control read.

### Large-index arithmetic

Under 32-bit address arithmetic, index `0x08000000` produces a control-record offset of zero because `32 × index` wraps modulo \(2^{32}\). Its payload-slot offset is `0x20000000`.

The function performs no bounds or overflow rejection. This example establishes the arithmetic expectation, not that either resulting address is valid.
