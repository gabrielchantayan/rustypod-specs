# F-2be3a530ed78

## Purpose

F-2be3a530ed78 dispatches a 32-bit operation selector against a caller-supplied object. Depending on the selector, it updates an embedded object from formatted data, invokes an indirectly selected operation, obtains a result using a nonnegative signed quantity, or performs no branch-specific work.

On handled, normally returning paths, the function writes one 32-bit result to a caller-provided output location and returns 1. Unhandled selectors, including two explicitly recognized selectors, return 0 without a direct output write.

Every selector first passes through common initialization and context lookup. An unhandled selector therefore does not make the function side-effect-free or safe to call without valid lookup state.

These are static observations from the supplied representation. The apparent meanings of the formatted data and indirect operations are not established.

## Interface

The interface has four arguments and a 32-bit return value:

| Argument | Representation | Role |
|---|---|---|
| Object | 32-bit address-bearing value | Base for embedded-object access, indirect dispatch, or a dependency call, depending on the selector. |
| Discriminator | 32-bit integer value | Must equal a global comparison word for selectors `0x7a09` and `0x7a0a`. Otherwise unused directly. |
| Selector | 32-bit word | Chooses branch behavior. |

The return value is 0 or 1 on visible normal-return paths. It indicates whether a result-producing branch was selected and completed; it does not independently establish that dependencies succeeded semantically.

The visible layout consists of a 32-bit selector copy followed by a pointer represented as 32 bits in the supplied model. The dependency-defined record type, permitted access extent, and ownership rules are unknown. In particular:

### Preconditions

## Behavior

### Common work before dispatch

The function initializes its normal unhandled return value to 0 and prepares the local initialization record. It then performs the following ordered work:

1. Calls F-5b24edfb22c0 with the local record address.
2. Calls F-938c950e5046 with no explicit arguments.
3. Passes that result and a global lookup word to F-9e50c66a96dd.
4. Passes the resulting value and the constant `0x7900` to F-682adfd5a561.
5. Captures a global comparison word.
6. Reads a 32-bit word at lookup-result offset `0x994`.
7. Reads a 32-bit word at lookup-result offset `0x998`.
8. Dispatches using the original selector.

The comparison word captured here is retained for possible use as an argument later. The discriminator checks described below instead read the comparison global again. The two observations must not be treated as one immutable value.

The common field reads occur even when the chosen branch never uses their values.

### Selector `0x7a05`: format values and update an embedded object

This branch processes the value read from offset `0x998` before the value read from offset `0x994`.

For the offset-`0x998` value, the visible order is:

1. Call F-c9e0501fef5b with that value, retaining its 32-bit result.
2. Call F-1c7710595b35 with no explicit arguments.
3. Call F-65f7a4af79d5 with that result and the offset-`0x998` value.
4. Read a global 32-bit adjustment word.
5. Call F-fdb31af1de99 with the preceding combined result and the adjustment word.
6. Call F-c9e0501fef5b again, this time with no explicit argument shown, retaining its result.

For the offset-`0x994` value, it then:

1. Calls F-c9e0501fef5b with that value.
2. Calls F-1c7710595b35 with no explicit arguments.
3. Calls F-65f7a4af79d5 with that result and the offset-`0x994` value.
4. Calls F-fdb31af1de99 with the combined result and the previously captured adjustment word.

The adjustment global is read only once by the visible branch. A dependency changing that global after the read does not change the retained value supplied to the second adjustment call.

Next, F-1f62160dfd52 receives:

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Unknown selector:** Given valid common lookup state and normally returning initialization and finalization, an unlisted selector returns 0 and performs no direct output write. Both lookup-field reads still occur.

2. **Recognized no-action selector:** With selector `0x7a07` or `0x7a08`, the same direct output behavior applies. Neither branch bypasses finalization.

3. **Embedded-object result:** With selector `0x7a05`, if every dependency returns normally, the direct result store contains the input object address plus `0x58`. Finalization follows the store.

4. **Formatting order:** If all four retained formatting values are distinguishable, the formatter receives the pair associated with offset `0x994` before the pair associated with offset `0x998`, despite the latter being processed first.

5. **Captured adjustment:** If the first adjustment dependency changes the adjustment global, the second adjustment call still receives the word captured before the first call.

6. **Negative quantity:** With selector `0x7a09`, a matching discriminator, and a quantity result of −1, F-9dfe5f6048f1 receives zero as its final argument.

7. **Nonnegative boundary:** Under the same conditions, quantity results of zero and 2,147,483,647 are passed unchanged.

8. **Comparison mismatch:** For either checked selector, a mismatch enters F-a817d8d58c10 before the quantity-producing call. No normal return or common finalization is established for that path.

9. **Distinct comparison observations:** If common dependencies change the comparison global before its initial capture, that changed value is captured. Any later difference between the captured word and the branch’s fresh comparison read must remain observable in the arguments and comparison behavior.

10. **Zero indirect result:** If the selected indirect target returns zero normally, the function directly stores zero and subsequently returns 1, subject to finalization returning normally.

11. **Shared indirect slot:** Selectors `0x7a0b` and `0x7a0c` select offset `0x108`; selector `0x7a06` selects offset `0x110`.
