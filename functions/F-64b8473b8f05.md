# F-64b8473b8f05

## Purpose

F-64b8473b8f05 combines a packed, one-bit source image with an existing destination image at a specified horizontal and vertical position. Combination is bitwise OR: source one-bits set destination bits; source zero-bits do not clear destination bits.

The source image’s width and height come from metadata associated with the supplied context, not from explicit dimensions in the call. Source rows are tightly packed into whole bytes. Within each source byte, the most significant bit represents the leftmost pixel.

The function conditionally invokes F-926016a18a4a before reading image metadata or validating placement. A nonzero result from that dependency is returned immediately.

Established behavior is byte-oriented memory modification. Describing the data as an image and the operation as drawing is inferred intent; no display update, presentation operation, or device synchronization is established.

## Interface

The function accepts five arguments:

| Argument | Meaning |
|---|---|
| Context | Address of an object containing a preparation flag, a destination-descriptor pointer, and a source-dimensions pointer. |
| Source start | Address of the first packed source byte. |
| Source limit | Address used as an upper bound for the required source extent. Equality with the calculated end address is accepted. |
| Horizontal position | A 32-bit unsigned value whose signed interpretation is used in parts of validation. |
| Vertical position | A 32-bit signed value, required to be nonnegative by validation. |

The return value is an integer:

- **0:** the combination path completed, including cases with no meaningful pixel changes.
- **3:** local placement or source-extent validation failed.
- **Any nonzero value returned by F-926016a18a4a:** propagated unchanged when that dependency is invoked.

A returned value of 3 is therefore not uniquely attributable to local validation; the dependency could also return 3.

### Source and destination packing

For source width \(w\), each source row occupies:

\[
b=\left\lceil \frac{w}{8}\right\rceil
\]

bytes. The required source extent is \(h b\), where \(h\) is the source height. Its maximum is 8,160 bytes.

There is no source-stride argument. Each row begins immediately after the preceding row’s \(b\) bytes.

For ordinary, valid placement, the destination row begins at the storage base plus the vertical row displacement and the byte displacement \(\lfloor x/8\rfloor\). The horizontal bit offset within that byte is \(x\bmod 8\). Destination rows are separated by the descriptor’s stride, not by a value calculated from destination width.

No ownership transfer is established for any argument or referenced allocation.

## Behavior

### Preparation and metadata acquisition

The first observed context access reads the preparation flag.

If the flag is zero, the function calls F-926016a18a4a with the context:

- A nonzero result terminates this function immediately.
- A zero result allows processing to continue.
- Image metadata is read after the call. The function does not use pre-call copies of the descriptor or dimensions.

If the flag is nonzero, the dependency is skipped.

After preparation, the function reads the destination-descriptor pointer and captures its row stride. It then obtains source width from dimensions offset 1 and source height from dimensions offset 0. The supplied representation accesses the context’s dimensions pointer separately for those two dimension reads; it does not establish one immutable dimensions-object snapshot.

The preparation flag is not rechecked after the dependency returns.

### Validation

Local validation is short-circuited in this order:

1. The signed interpretation of the horizontal position must be nonnegative.
2. The signed interpretation of horizontal position plus source width must be no greater than destination width.
3. Vertical position must be nonnegative.
4. The signed interpretation of vertical position plus source height must be no greater than destination height.
5. Source start plus the required source byte count must compare no greater than source limit.

Failure returns 3 before this function performs destination-byte writes.

The horizontal and vertical end calculations involve unsigned dimension values and then signed interpretation for comparison. They are not established as checked, unbounded integer additions. Overflow-related acceptance must not be replaced with an idealized rectangle-containment rule.

Under nonwrapping arithmetic and valid pointers, the intended accepted rectangle satisfies:

\[
0\le x,\quad x+w\le W,\quad 0\le y,\quad y+h\le H
\]

and the required source interval fits below the supplied limit.

The function does **not** independently check:

- Context, descriptor, dimensions, or storage addresses for nullness.
- Whether the claimed source interval is allocated or readable.
- Whether destination storage covers the calculated byte accesses.
- Whether row stride is positive or large enough.
- Whether destination dimensions are nonnegative.
- Whether source and destination overlap.
- Whether pointer calculations wrap or remain within valid objects.

Source limit is used only for the extent comparison. It is not consulted during copying.

### Destination selection

After all local checks pass, the destination-storage address is read and the initial destination row address is calculated.

This calculation occurs even when source height is zero. A zero-height input therefore avoids pixel-byte reads and writes, but does not bypass preparation, metadata access, validation, or initial address calculation.

### Byte-aligned placement

When the horizontal bit offset is zero, rows are processed in increasing row order.

Within each row:

- Complete source bytes are processed from left to right.
- Each source byte is ORed into its corresponding destination byte.
- If the width has a remainder of one through seven bits, one additional source byte is consumed.
- Only that final byte’s most significant remainder bits contribute to the destination.

Unused low bits in a partial final source byte are ignored.

Each destination update reads the existing destination byte and writes the OR result. A write still occurs when the result equals the previous value.

After each row, the source advances by exactly \(b\) bytes and the destination row address advances by the captured stride.

For zero source width, the aligned path performs no source-byte or destination-byte accesses, regardless of positive source height.

### Non-byte-aligned placement

For horizontal bit offsets from one through seven, source bits are shifted into adjacent destination bytes. Processing remains row-major and left-to-right within each row.

Complete source bytes contribute to the current destination byte and retain bits that may contribute to the next destination byte. A partial final source byte contributes only its most significant valid bits. Retained bits are reset at the beginning of each source row; bits do not carry between rows.

For a positive source width, the number of destination bytes read and written per row is:

\[
\left\lceil\frac{(x\bmod 8)+w}{8}\right\rceil
\]

Each such byte is updated by OR. Bits outside the intended source rectangle remain unchanged in value, assuming no overlapping or externally changing memory.

The row-ending behavior is observable:

- A final destination-byte OR update always occurs on this path.
- An additional destination byte is accessed only when the bit offset plus the remaining source-bit count exceeds eight.
- A sum of exactly eight does not trigger that additional access.
- A width exactly divisible by eight still needs its shifted carry contribution written to a final destination byte.

For **zero width with a nonzero horizontal bit offset**, the function nevertheless reads and writes one destination byte per source row, ORing it with zero. No source byte is read. The stored value is unchanged in ordinary memory, but the access is not absent.

### Access ordering and aliasing

The implementation does not first copy or snapshot source bytes.

Earlier destination writes can therefore alter source bytes read later when the regions overlap. Consequently, the mathematical description “OR the original source image into the destination” requires nonoverlap or another condition ensuring earlier writes cannot change later source reads.

Within complete-byte updates, the source byte and current destination value must both be obtained before the corresponding write. Their exact relative read order is not established for expressions containing both reads.

In the shifted row-ending case that requires another destination byte, the current destination byte is updated before the next destination byte is read and written.

Destination dimensions are used during validation, stride is captured before pixel processing, and the storage base is read after validation. The routine does not reread those descriptor fields for each row.

## Acceptance examples

These are conditional examples derived from static evidence, not runtime test results. Unless stated otherwise, pointers are valid, arithmetic does not overflow, buffers do not overlap, bounds permit placement, and any preparation call returns zero.

1. **Aligned byte combination.**  
   A one-row, eight-bit source byte of `0xA5`, placed at horizontal position zero over destination byte `0x0F`, produces `0xAF` and returns zero.

2. **Ignoring source padding.**  
   A one-row, three-bit source containing `0xFF`, placed at horizontal position zero over `0x05`, produces `0xE5`. The source’s five unused low bits do not contribute.

3. **Shifted full source byte.**  
   An eight-bit source containing `0x81`, placed at horizontal position three over two zero destination bytes, produces `0x10` followed by `0x20`. Both destination bytes are read and written.

4. **Ending exactly at a byte boundary.**  
   A five-bit source containing `0xF8`, placed at horizontal position three over a zero destination byte, produces `0x1F`. The row does not require a second destination-byte access.

5. **Tightly packed source rows.**  
   A nine-bit-wide, two-row source requires four source bytes: two per row. Destination rows advance by the descriptor stride, which need not equal two.

6. **Insufficient source extent.**  
   That nine-bit-wide, two-row source fails local validation with return value 3 if source limit is only three bytes beyond source start. Exactly four bytes satisfies the extent check.

7. **Preparation failure takes precedence.**  
   If the flag is zero and F-926016a18a4a returns 7, the result is 7. No subsequent descriptor validation or pixel processing occurs.

8. **Zero-width access distinction.**  
   With positive height and accepted bounds, zero width at horizontal position zero causes no pixel-byte accesses. Zero width at horizontal position one reads and writes one unchanged destination byte per row.

9. **Zero height.**  
   With accepted bounds and valid metadata, zero height returns zero without source-byte or destination-byte processing. Preparation and initial destination-address calculation still occur.

10. **Negative-position rejection.**  
    A horizontal value of `0xFFFFFFFF` fails the signed-nonnegative check. A vertical position of −1 fails its nonnegative check if validation reaches it. Either local failure returns 3.
