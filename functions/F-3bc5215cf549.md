## Behavior

### Result selection

After the dependency returns normally, the function compares its 32-bit result with zero.

If the dependency result is zero, the lower 32 bits of the function’s return value are zero. On this branch, the function does not perform the identified global read.

If the dependency result is nonzero, the function reads 32 bits from a fixed global storage location. That value becomes the lower 32 bits of the return value. The read occurs after the dependency call, so it can observe a value written by the dependency.

All nonzero dependency results select the same branch. There is no observed distinction among positive values, negative values, or particular nonzero bit patterns. The dependency’s result is not itself copied into the returned value.

A nonzero dependency result does not guarantee a nonzero lower half: the global location may contain zero.

### Retained field behavior

The upper half of the result uses the offset-4 value captured before the dependency call. The function does not reread that field afterward.

Consequently, if the dependency changes the record during its execution, the upper half still reflects the earlier read. The fifth dependency argument likewise reflects that earlier value, not any later record contents.

The offset-8 field is used only as a dependency argument in the visible behavior. It does not independently contribute to either half of the returned value.

### Widths and address arithmetic

Both record accesses have 32-bit width, and their offsets are byte offsets. There is no observed arithmetic on either field before forwarding it.

The supplied representation uses a 32-bit record-address input and adds offsets 4 and 8. It does not establish portable behavior for address overflow, invalid addresses, or misaligned accesses. Callers must not rely on defined wrapping or fault recovery from this evidence alone.
