# F-f8891134cb93

## Purpose

F-f8891134cb93 is a thin wrapper around F-3eaa60da10c7. It forwards selected 32-bit values from an input record and the call arguments, then takes one of two result-dependent actions:

- For a zero result, it invokes F-4fc89ec41a6d with five fixed arguments.
- For a nonzero result, it reads a discriminator from the input record. If that discriminator equals 266, it writes the 32-bit value 1 at byte offset 12 from the address represented by the result.

If execution reaches its return, the wrapper returns the result obtained from F-3eaa60da10c7.

These operations are established by the supplied static evidence. Describing the result as an allocated object, the discriminator as an object type, or the zero-result action as fatal error handling would require additional evidence.

## Behavior

### Dependency invocation

The wrapper obtains the 32-bit words at input-record offsets 8 and 0, then invokes F-3eaa60da10c7 with five arguments in this positional order:

1. The word from input-record offset 8.
2. The word from input-record offset 0.
3. The wrapper’s second argument.
4. The wrapper’s fourth argument.
5. The wrapper’s fourth argument again.

The last two positions receive the same 32-bit argument value. No record word is substituted for either position.

The supplied evidence does not establish the relative order of the two record reads used to prepare this call. Both supply arguments to the dependency invocation; neither should be specified as necessarily preceding the other.

There is one visible invocation of F-3eaa60da10c7 per wrapper execution that reaches this stage. There is no visible retry.

### Zero-result path

If F-3eaa60da10c7 returns zero, the wrapper invokes F-4fc89ec41a6d with these five argument values, in order:

1. 13
2. 113
3. 105
4. 0
5. 0

The wrapper does not consume a return value from this invocation.

If F-4fc89ec41a6d returns normally, the wrapper returns zero. The zero-result path does not perform the discriminator read at input-record offset 4, and it does not perform the conditional result-relative write.

The fixed constants do not establish whether F-4fc89ec41a6d logs, reports an error, terminates execution, changes global state, or performs another action. Its role as an error handler is plausible intent, not an established behavioral guarantee.

### Nonzero-result path

If F-3eaa60da10c7 returns any nonzero 32-bit result, the wrapper does not invoke F-4fc89ec41a6d on that path.

It instead reads the 32-bit word at input-record offset 4 and compares it with 266, equivalently hexadecimal 0x0000010A. The comparison uses the complete 32-bit word; the evidence does not show masking or truncation to a smaller field.

If the word is not 266, the wrapper performs no explicit result-relative write and returns the dependency result.

If the word is 266, the wrapper stores the 32-bit value 1 at byte offset 12 from the address represented by the dependency result, then returns that result.

The store replaces the entire 32-bit destination word. It is not a bitwise update and does not preserve other bits of that word. The wrapper does not visibly read the destination word before overwriting it.

### Ordering and aliasing

The following order is established for operations performed by the wrapper:

1. Obtain the record values needed as dependency arguments.
2. Invoke F-3eaa60da10c7 and receive its result.
3. Select the zero or nonzero path.
4. On the nonzero path, read the discriminator.
5. If the discriminator matches, perform the 32-bit store.
6. Return, provided all preceding operations complete normally.

Consequently, a change to the discriminator made during F-3eaa60da10c7 can affect the branch taken after that dependency returns. The wrapper does not demonstrably use the discriminator’s entry-time value.

No non-aliasing relationship is established between the input record and the address represented by the result. If the conditional store overlaps the input record or other shared storage, the write has its ordinary effect on that storage. The wrapper supplies no visible isolation mechanism.

## Side effects

- Two 32-bit input-record reads used to prepare the primary dependency call.
- A conditional 32-bit discriminator read after that call.
- A conditional 32-bit store of 1 at result-relative byte offset 12.
- The dependency invocations described above.

There is no explicit allocation, deallocation, reference-count adjustment, lock operation, or global-variable access in the supplied wrapper body. This does not constrain side effects inside either dependency.

Ownership is unspecified. The evidence does not establish that the wrapper, its caller, or either dependency owns the input record or the result-associated storage. It also does not establish that a dependency preserves the lifetime of either region.

For a matching nonzero path to complete normally, the result-relative destination must be valid and writable when the store occurs. A nonzero value alone is not a validity check.

The address-offset operation uses a displacement of 12 bytes, not 12 words. The supplied 32-bit representation does not justify defining portable behavior for address-space wraparound, misalignment, inaccessible memory, or an address outside a live object. ## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests.

1. **Argument forwarding:** Given readable record words at offsets 0 and 8, F-3eaa60da10c7 receives the offset-8 word first and the offset-0 word second. The wrapper’s second argument follows, then two copies of its fourth argument. Its third argument is absent from that invocation.

2. **Zero result with returning secondary dependency:** If F-3eaa60da10c7 returns zero and F-4fc89ec41a6d returns normally, the wrapper calls the latter with 13, 113, 105, 0, 0 and returns zero. The wrapper does not read the discriminator on this path.

3. **Nonzero result with nonmatching discriminator:** If the primary dependency returns a nonzero result and the subsequent discriminator read yields 265 or 267, the wrapper returns that result without its conditional store.

4. **Exact discriminator match:** If the primary dependency returns a valid address and the subsequently read discriminator is 266, the wrapper writes the full 32-bit value 1 at address-plus-12. A previous destination value with multiple bits set is replaced, not combined with 1.

5. **Discriminator changed during the dependency call:** If the discriminator begins as a nonmatching value but is 266 when read after the dependency returns, the matching branch applies. Conversely, an entry-time value of 266 does not cause the store if the later read yields a different value.

6. **Invalid nonzero result:** If the discriminator matches but the computed destination is not writable, the evidence supplies no successful-return guarantee or wrapper-level recovery. The nonzero check must not be treated as memory validation.
