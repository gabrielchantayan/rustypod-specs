# F-aa77230061ff

## Purpose

F-aa77230061ff processes an event-like record against a receiver-like object. It combines one immediate action, one conditional preliminary handler, a mandatory dispatch stage for events not already handled, and a conditional final handler.

Its observable result is an integer status:

- One distinguished event causes an action and returns exactly 1.
- A nonzero result from any invoked handler terminates processing and is returned unchanged.
- Processing returns 0 when no invoked handler returns a nonzero result.

The supplied static material establishes the branch conditions, field accesses, call ordering, and return propagation. Descriptions such as “event,” “receiver,” and “handled” are inferred roles, not established domain meanings.

## Interface

### Inputs

The function takes two arguments:

1. **Receiver reference.** A reference to storage containing an initial dispatch-table reference and additional fields.
2. **Event reference.** A reference to storage containing a kind field and, conditionally, a reference to a secondary record.

Both references are passed unchanged to handler calls that take two arguments.

The exposed representation uses integer-sized fields and address-bearing values. The contract below uses the 32-bit field interpretation indicated by the supplied representation. Byte offsets are explicit; independent confirmation of the executable’s pointer width, calling convention, byte order, alignment requirements, and integer-overflow rules is unavailable.

Requirements are path-dependent. For example, the immediate-action path does not require a readable dispatch table because it returns before dispatch-table access.

## Behavior

### 1. Inspect the initial event kind

The first observable field read obtains the event kind at offset 0x04.

That value controls both early special-case checks. The function does not reload the event kind between those checks.

For an initial kind other than 0x16, neither early check dereferences the event’s secondary-record field.

### 2. Perform the immediate action for secondary value 0x7901

When the initial kind is 0x16, the function reads:

1. The secondary-record reference at event offset 0x08.
2. The secondary discriminator at offset 0x04 within that record.

The first special comparison is expressed through subtraction of 0x7901 and a test for zero. For the ordinary representable discriminator value 0x7901, this condition matches.

On a match, the function:

1. Reads the receiver field at offset 0xB0.
2. Passes that value as the sole argument to F-da4129f79d61.
3. Returns exactly 1, provided that call returns normally.

No primary or final handler is invoked on this path. Any return value from F-da4129f79d61 does not determine the enclosing function’s status.

### 3. Optionally invoke F-776e6a3d3e9b for secondary value 0x7902

If the immediate-action condition did not match and the initially read kind was 0x16, the function reads the secondary-record reference and secondary discriminator again. It does not reuse the discriminator from the first check.

The second comparison subtracts 0x7900 from the newly read discriminator and tests the result against 2. For the ordinary representable discriminator value 0x7902, this condition matches.

On a match, F-776e6a3d3e9b receives the receiver reference and event reference.

- A nonzero result is returned immediately and unchanged.
- A zero result permits primary dispatch.

This call is not made for other ordinary discriminator values. In particular, 0x7900 and 0x7901 do not satisfy the second comparison.

The repeated secondary-record reads are part of the observable access sequence. No external call occurs between the first and second early checks, but the supplied material does not establish that the underlying storage is immutable or ordinary, nonvolatile memory.

### 4. Select and invoke the primary handler

If execution has not returned, the function reads the event kind again. This fresh read occurs after F-776e6a3d3e9b when that dependency was called and returned zero.

Selection uses the newly observed state:

- If the kind is 0x16, the function reads the event’s secondary-record reference and that record’s discriminator.
- A kind of 0x16 together with a discriminator of 0x2A selects dispatch-table offset 0x10C.
- Every other case selects dispatch-table offset 0x110.

For a kind other than 0x16, this selection does not dereference the event field at 0x08 as a secondary-record reference.

After selecting the offset, the function reads the receiver’s dispatch-table reference, obtains the target from the selected entry, and invokes it with the receiver and event references.

A nonzero result is returned unchanged. A zero result permits the final stage.

The primary handler is invoked exactly once on every normally continuing path that reaches this stage.

### 5. Optionally invoke the final handler

After a zero primary-handler result, the function reads the event kind again.

If the newly read kind is not 0x0F, it returns 0 without invoking the final handler.

If the kind is 0x0F, it reads, in order:

1. The event value at offset 0x08.
2. The receiver value at offset 0x50.

If these values differ, it returns 0.

If they are equal, the function reads the receiver’s current dispatch-table reference, obtains the target at offset 0xE0, and invokes that target with the receiver and event references.

- A nonzero result is returned unchanged.
- A zero result produces a final return of 0.

The function does not compare against a receiver value cached before primary dispatch. Both the event fields and the receiver comparison field are read after that handler returns.
