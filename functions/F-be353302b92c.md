# F-be353302b92c

## Purpose

F-be353302b92c examines 16 fixed-stride records associated with a supplied base address. For each record whose eligibility flag is set, it may invoke F-f05325f1a2be with the base address and that record’s address.

A zero second argument selects unconditional dispatch of eligible records. A nonzero second argument selects filtered dispatch: an eligible record must have an associated object, pass two flag exclusions, match an association back-reference, and have its identifier selected in a bitmap.

These are established control-flow properties. The business meaning of the records, flags, association, and dispatch operation is unknown.

## Interface

### Arguments

The function takes two 32-bit arguments interpreted as addresses or address-like values:

| Argument | Interpretation |
|---|---|
| Base address | Base of the structure containing the 16 records. Also passed unchanged as the first argument to F-f05325f1a2be. |
| Selection address | Zero selects unconditional mode. Any nonzero value is treated as the base address of a bitmap-bearing structure. |

There is no observed validation of either address. The base address must support the record reads described below even when the selection address is zero.

### Result

There is no explicit return value or status result.

On the normal path, the function returns after examining record indices 0 through 15. A dependency invocation that faults, does not return, or otherwise interrupts execution can prevent completion.

### Record layout

Record indices increase from 0 to 15. Each record begins at:

**base address + 0x14 + index × 0x1c**

Thus the records have a 28-byte stride and begin 20 bytes after the supplied base address. Only these fields are directly used:

| Offset from record start | Width | Interpretation |
|---|---:|---|
| +0x10 | 32 bits | Associated-object address |
| +0x18 | 32 bits | Flags; mask 0x00000100 determines initial eligibility |

Equivalently, these fields occur at base-relative offsets `0x24 + index × 0x1c` and `0x2c + index × 0x1c`.

The last flags read starts at base-relative offset 0x1d0 and occupies four bytes. No direct access beyond that field is established. This does not bound accesses made by the dependency.

### Associated-object layout

When filtered mode requires examination of a nonzero associated-object address, the following fields are used:

| Offset | Width | Interpretation |
|---|---:|---|
| +0x04 | 32 bits | Address of a secondary object |
| +0x08 | 32 bits | Back-reference compared with the current record address |
| +0x10 | 32 bits, unsigned | Identifier used for bitmap selection |
| +0x24 | 32 bits | Flags; mask 0x00010000 excludes the object |

The secondary object is accessed only for its 32-bit flags at offset +0x24.

### Selection layout

The nonzero selection address designates storage with a four-byte prefix followed by 32-bit bitmap words:

- Word zero is at selection address +0x04.
- Identifier values 0–31 use word zero.
- Identifier values 32–63 use word one.
- In general, the word index is the unsigned identifier divided by 32, and the bit position is the identifier modulo 32.

The four-byte prefix is not read by this function. Its meaning is unknown.

### Preconditions

For defined, successful execution:

- Every directly accessed field must be readable at the required width.
- In filtered mode, every secondary-object address reached by the flag checks must support a four-byte read at +0x24.
- Every selected bitmap-word address must be readable.
- Address calculations must resolve to the intended storage without an invalid wraparound or out-of-range access.
- Any requirements imposed by F-f05325f1a2be must also hold.

No length, identifier limit, alignment check, ownership check, or address-range check is visible. Endianness and alignment requirements are not established by the supplied material.

## Behavior

### Traversal and initial eligibility

The function visits exactly 16 record positions in ascending index order, subject to normal continuation of execution. It does not use a stored count, sentinel, or list link.

For each position, it first reads the record’s 32-bit flags. If mask 0x00000100 is clear, it advances to the next position without reading that record’s associated-object field.

If the mask is set, it reads the 32-bit associated-object field before choosing between unconditional and filtered dispatch.

That associated-object read occurs even in unconditional mode, although its value does not affect dispatch in that mode. Consequently, unconditional mode does not eliminate the requirement that this field be readable.

### Unconditional dispatch

When the selection address is zero, each eligible record causes one invocation of F-f05325f1a2be with:

1. The original base address.
2. The current record’s start address.

The associated-object value may be zero or nonzero; neither value suppresses this invocation.

No associated-object fields, secondary-object fields, or bitmap words are read on this path by F-be353302b92c.

### Filtered dispatch

When the selection address is nonzero, an eligible record is dispatched only if all of the following conditions pass, in the stated control-flow order.

1. **Nonzero association.**  
   A zero associated-object address skips the record.

2. **Associated-object exclusion flag clear.**  
   The function reads the associated object’s flags at +0x24. If mask 0x00010000 is set, the record is skipped. In that case, the secondary-object address is not read.

3. **Secondary-object exclusion flag clear.**  
   Only when the first exclusion flag is clear does the function read the secondary-object address at associated-object offset +0x04, then read that secondary object’s flags at +0x24. If mask 0x00010000 is set there, the record is skipped.

   There is no explicit null check on the secondary-object address. A null value does not constitute an ordinary rejection condition; it instead leads to an attempted flags read through that address.

4. **Back-reference matches.**  
   Only after both exclusion flags are clear does the function read the associated object’s back-reference at +0x08. It must equal the current record’s start address, including the base-relative 0x14 displacement. Comparing equal to the containing base address alone is insufficient.

5. **Identifier selected.**  
   Only after the back-reference matches does the function consult the bitmap using the associated object’s unsigned 32-bit identifier at +0x10. The relevant bitmap word must have the identifier’s selected bit set.

If all conditions pass, the function invokes F-f05325f1a2be with the same two arguments used in unconditional mode.

Rejection at any stage advances traversal to the next record. A rejected record does not terminate the scan.

### Integer widths and bitmap interpretation

The identifier is interpreted as unsigned for its right shift by five bits. Its word index therefore ranges from 0 through 0x07ffffff; its bit position ranges from 0 through 31.

For a stable identifier, the bitmap word address is:

**selection address + 4 + 4 × floor(identifier / 32)**

The offset from the selection address ranges from 4 through 0x20000000. The function does not verify that storage of this extent exists.

The intended bit test uses a 32-bit single-bit mask, including bit 31 for identifiers congruent to 31 modulo 32. The supplied expression constructs that mask by shifting the literal one. Its exact language-level signed-shift semantics are not independently established; the observable selection interpretation is a bit test, not a signed numeric comparison.

The identifier field appears in two memory-read expressions: one determines the bitmap-word address, and the other determines the bit position. There is no established cached identifier shared between those expressions. If the field changes during evaluation, the word and bit may correspond to different values.

The supplied representation does not establish the evaluation order between those two identifier reads and the bitmap-word load. The stage ordering described above is established; a finer total order within the bitmap expression is not.

### Continuation after dispatch

After a dependency invocation returns normally, traversal proceeds to the next numerical record position.

The function does not visibly restart the scan, revisit the dispatched record, or skip additional positions based on a dependency return value. There are at most 16 direct invocations of F-f05325f1a2be during one normally completing invocation.

This bound does not constrain recursive or additional activity initiated by the dependency.

## Acceptance examples

These examples are conditional acceptance criteria derived from static evidence. They are not reported runtime results. Unless stated otherwise, all referenced storage is valid and stable, and dependency calls return normally.

1. **No eligible records.**  
   If mask 0x00000100 is clear in all 16 record flags, there are no dependency invocations in either mode. Associated-object fields and the selection structure are not read.

2. **Unconditional dispatch ignores association value.**  
   If only record index 3 is eligible and the selection address is zero, exactly one invocation occurs with the base address and base address +0x68. A zero associated-object value does not prevent the call. The associated-object field itself is still read.

3. **Filtered mode rejects a missing association.**  
   If an eligible record has a zero associated-object address and selection is nonzero, that record produces no dependency invocation and no associated-object or bitmap dereference.

4. **First exclusion flag short-circuits later checks.**  
   If the associated object has mask 0x00010000 set at +0x24, the record is skipped without reading its secondary-object address, back-reference, identifier, or bitmap word.

5. **Secondary exclusion flag suppresses dispatch.**  
   If the first exclusion flag is clear but the secondary object has mask 0x00010000 set, no dispatch occurs. The back-reference and bitmap are not consulted.

6. **Back-reference must identify the record.**  
   With both exclusion flags clear, a back-reference unequal to the current record start rejects the record even if its identifier’s bitmap bit would be set.

7. **Bitmap boundary behavior.**  
   With all earlier checks passing, identifier 31 tests bit 31 of the word at selection address +0x04. Identifier 32 tests bit zero of the word at selection address +0x08. A clear tested bit rejects the record; a set tested bit causes dispatch.

8. **Sparse qualifying records preserve traversal order.**  
   If only indices 1 and 14 qualify, calls occur for record addresses base +0x30 and base +0x19c, in that order.

9. **Traversal has a fixed upper bound.**  
   If all 16 records qualify, there are 16 direct dependency calls. A qualifying-looking record at index 16 is not examined.

10. **Dependency mutation can affect later decisions.**  
    If the first dispatch clears the eligibility mask of a later, not-yet-examined record, that later record is skipped when reached, assuming no intervening change restores the mask.
