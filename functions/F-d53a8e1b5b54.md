# F-d53a8e1b5b54

## Purpose

F-d53a8e1b5b54 returns the unsigned byte addressed by an object’s current-position field. When that field equals the object’s readable-end field, the function first attempts to establish a new readable range. It does not explicitly advance the current position after selecting the byte.

The 32-bit return value is either:

- A byte value zero-extended to the range 0–255.
- `0xffffffff`, shared by eligibility rejection, selected dependency failures, and a refill whose accumulated input count is zero.

Two refill modes are visible: a direct dependency call using an object-derived destination, and staged processing using a 512-byte temporary buffer and an indirect dependency.

“Readable range,” “refill,” and “processing state” describe inferred roles. The supplied source establishes argument construction, return-value handling, local bookkeeping, and explicit memory accesses. It does not establish that dependencies perform transfers, transform data, or relocate bytes as their apparent roles suggest.

This contract is based on static evidence only. No runtime tests have been performed.

## Behavior

### Entry reset and eligibility

The function performs three four-byte stores in this order:

1. Zero to `+0x24`.
2. Zero to `+0x20`.
3. Zero to `+0x28`.

It then calls F-e49ecfc40a9c with the object address and zero. No returned value is used.

After that call, it reads the flags field. If mask `0x00000004` is clear, it returns `0xffffffff` without calling F-cf17a2203afd.

If the mask is set, F-cf17a2203afd receives the object address. A zero result returns `0xffffffff`; any nonzero result permits further processing.

These checks use state observed after the earlier call. Neither rejection path undoes the reset stores or dependency effects.

### Existing range

After eligibility succeeds, the function calculates a target-end address from the base at `+0x08` plus the extent at `+0x0c`. This calculation occurs even if refill is subsequently skipped.

It compares the current position at `+0x18` with the readable end at `+0x1c`.

If they differ, it loads the address from `+0x18`, reads one byte there, and returns that byte zero-extended to 32 bits. It does not explicitly increment the current position.

Inequality alone selects this path. The function does not verify that the current position precedes the end or lies within the buffer.

### Refill preparation

Equality of the two range fields selects refill.

F-3c4be1100386 receives the object address. Its signed result is selected when less than five; otherwise four is selected. The selection is stored at `+0x44`.

If that selection equals the extent then read at `+0x0c`, the function replaces `+0x44` with the extent minus one.

Thus:

- Results of five or greater select four before adjustment.
- Negative results are not rejected.
- Equality with the extent reduces the selection by one.
- An extent and initial selection of zero produce a prefix of negative one, subject to the stated arithmetic limitations.

The following calls then occur in order:

1. F-297517413a88 receives the value at `+0x14` and the current position at `+0x18` minus the prefix at `+0x44`.
2. F-dd25b8fb230c receives the addresses of `+0x3c` and `+0x34`.
3. F-e4011efab98e receives the address of `+0x2c`; its result is retained as a dispatch-object address.
4. F-d5c3c8759d21 is called without explicit arguments.

Only the last two returned values are used here. F-e4011efab98e is called regardless of which refill mode is subsequently selected.

The target end calculated before refill preparation remains the target used for capacity and completion calculations. Later calculations reload selected object fields; no dependency is assumed to preserve them.

### Staged mode: initialization and read requests

A zero result from F-d5c3c8759d21 selects staged mode.

The function establishes:

- A 512-byte temporary input buffer.
- An append address initially at that buffer’s beginning.
- A temporary output-position value initialized from the then-current base plus prefix.
- A four-byte temporary state copied from `+0x38`.
- A four-byte consumed-input-address value initialized to zero.
- A total input count initially zero.

The consumed-input-address value is initialized once, not before every indirect call.

At each loop boundary, the function saves the temporary output-position value **by value**, before the read call. If the live output-position value equals the previously calculated target end, the loop ends.

Otherwise, it determines the buffered count from the append address’s offset within the temporary buffer. The requested count is the signed minimum of:

- Target end minus the output position observed at this boundary.
- 512 minus the buffered count.

F-fca76d969ee7 receives, in order:

1. The address of the object region at `+0x30`.
2. The temporary append address.
3. One.
4. The selected request count.

The function treats the result as a signed count:

- Negative: return `0xffffffff` immediately.
- Zero: exit the staged loop without an indirect processing call for that iteration.
- Positive: add the result to both the buffered-count bookkeeping and total input count, then call the indirect dependency.

### Direct mode

A nonzero result from F-d5c3c8759d21 selects direct mode.

F-fca76d969ee7 receives:

1. The address of `+0x30`.
2. The then-current base plus prefix.
3. One.
4. The saved target end minus the then-current base minus the then-current prefix.

A negative result immediately returns `0xffffffff`.

For a nonnegative result, the function reloads the base and prefix after the call. Their sum becomes the candidate current position; that sum plus the returned count becomes the candidate readable end.

Consequently, the destination argument supplied to the dependency can differ from the address later committed as current position. The source does not establish that the dependency preserves the object or actually initializes either address range.

### Refill commit and final result

1. Reloaded base to `+0x14`.
2. Reloaded base plus prefix to `+0x18`.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless noted otherwise, assume valid storage, representable arithmetic, and no intervening dependency changes beyond those stated.

1. **Required flag absent.** If the flag remains clear after F-e49ecfc40a9c, the reset stores occur in their specified order, F-cf17a2203afd is not called, and the result is `0xffffffff`.

2. **Existing byte.** If eligibility succeeds, the range fields differ, and the current address contains `0xe7`, the result is 231. Refill is skipped; there is no explicit current-position increment. A byte of `0xff` similarly returns 255, not the failure sentinel.

3. **Prefix adjustment.** If F-3c4be1100386 returns seven and the extent is four, the prefix is first stored as four and then replaced with three.

4. **Direct positive result.** With stable base B, extent 16, and prefix two, the direct dependency receives destination B+2 and count 14. If it returns three, the committed current position is B+2, the readable end is B+5, and the accumulator increases by three. If B+2 contains `0x41` when finally read, the result is 65. The returned count alone does not establish that the dependency wrote `0x41`.

5. **Direct zero result.** Under the same stable-field setup, a zero result commits B to `+0x14` and B+2 to both range fields, then returns `0xffffffff` without increasing the accumulator.

6. **Conditional suffix preservation.** If bookkeeping records six buffered bytes and the indirect dependency returns one with a consumed-input address four bytes from the buffer beginning, the external helper receives the buffer beginning, that address, and count two. The next append address is buffer beginning plus two. **Only if the helper’s independent contract relocates those two bytes** may the next iteration rely on them as preserved suffix contents.

7. **Snapshot differs from live position.** Suppose an earlier indirect call retained the live output-position address. At a later loop boundary its value is P, unequal to the target. If the read dependency changes it to Q and returns a positive count, the next indirect call receives P as argument six and the address currently holding Q as argument eight.

8. **Indirect rejection.** An indirect result of two returns `0xffffffff` without normal explicit state or pointer commit. Effects already performed by dependencies remain possible.

9. **Input count without output progress.** If positive read results accumulate, the live output position remains at its initial value, and a later read returns zero, the function commits that position as the end. With a nonzero total count, it still updates the accumulator and attempts the final byte load, even if the committed range is empty.
