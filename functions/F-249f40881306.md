# F-249f40881306

## Purpose

The selected address is the first input plus the second input, minus one. The dependency receives the saved byte as its first argument and the original first input as its second argument.

**Inferred intent:** the temporary zero may delimit a byte sequence for processing. That interpretation is not required by the established behavior. The function does not establish that the selected byte was a terminator, that the preceding bytes form a string, or that the dependency interprets them as text.

The restoration is a normal-path action, not a demonstrated cleanup guarantee. The supplied representation provides no recovery path for a fault, interrupted execution, or dependency invocation that does not return.

## Behavior

### Temporary replacement

The function first computes the selected address from the two inputs. It reads exactly one byte from that address and retains the value for later use.

It then writes a zero byte to that same address. The saved value is the value observed by the initial read, not a later reread of memory.

The direct read precedes the direct zero write. This distinction matters if another actor can modify the location between accesses: the eventual restoration uses the initially observed byte.

No direct read of the bytes between the first input and the selected address is shown. No direct write to those intervening bytes is shown either. The function therefore does not itself scan a sequence, find a terminator, copy a range, or verify a length.

### External operations during replacement

After writing zero, the function performs a software-interrupt operation with selector **0x123456**.

If execution continues from that operation, it invokes F-9b794b5e3b70 with two arguments, in this order:

1. The byte saved before the zero write.
2. The original first input.

The second argument is not the selected address unless the inputs happen to make those values equal. The second input is not forwarded as a separate argument.

The saved byte has one-byte provenance. The exact receiving parameter type and argument-extension convention are not supplied. For values with the high bit set, this evidence does not determine whether the dependency observes an unsigned value, a sign-extended value, or another ABI-specific representation.

The direct ordering is established: the zero write occurs before the software interrupt, and the software interrupt occurs before the dependency invocation. However, it is not established that the selected byte remains zero throughout both operations. The interrupt handler, the dependency, or another actor could modify it.

Accordingly, the contract guarantees that zero has been written before those operations are reached; it does not guarantee that a later observer will still read zero without additional assumptions about intervening effects.

### Restoration and return

After F-9b794b5e3b70 returns, the function writes the originally saved byte to the selected address and returns.

This restoration does not depend on the byte currently stored there. If the dependency or another actor has changed that location, the restoration overwrites that change.

If the original byte was already zero, both direct writes still occur: the function writes zero before the external operations and writes the saved zero afterward. There is no shown branch that skips work for an already-zero byte.

No dependency result is inspected in the supplied representation. A normal dependency return is followed by restoration regardless of any result value it might produce under its own interface.
