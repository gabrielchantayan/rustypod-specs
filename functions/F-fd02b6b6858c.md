# F-fd02b6b6858c

## Purpose

No application-level purpose is established. Repeated access layouts suggest manipulation of structured state, but they do not establish an object type, collection, serialization format, or protocol.

This contract describes the behavior visible in the supplied static representation. It does not establish that the entire sequence is reachable or that the represented control flow accurately describes executable instructions throughout.

### Initial forwarding and word publication

The first call target is derived from the incoming control-link value by adding 0xffe. The call receives:

1. The second explicit input.
2. The incoming unsigned word logically shifted right by twelve.

After additional indirect calls, a returned 32-bit value supplies an index for a word store. The second explicit input is stored at four times that result plus 0x14. The next call receives four times that result, without the 0x14 offset.

No destination validation, bounds check, or allocation is visible.

### First pair of byte publications

After further calls, an unsigned result supplies two byte values.

For the first publication, the function reads a selector byte at the incoming address-like value plus one. It writes the low eight bits of four times the unsigned result at the zero-extended selector plus 0x11. The next call receives the complete 32-bit scaled result.

Several calls intervene before the second publication. A newly returned value is retained for a subsequent argument, while the earlier unsigned result determines:

- A selector-read address of 64 times that unsigned result plus one.
- A stored byte obtained by masking that result with 0x3fffffff, shifting right by twenty, and retaining eight bits.

The selected destination is again the selector plus 0x11. Although the mask-and-shift expression can contain ten significant bits, the byte store retains only original bits 20–27.

The next relevant call receives four times the newly retained result. After more calls, another call receives four times a newer result first and the saved selector second. That selector is not reread for the argument.

### Fourth-input call and zero-byte publication

A later call receives the fourth explicit input shifted left by ten in both argument positions. Exact behavior for negative inputs or overflowing signed shifts remains unresolved.

After the following call, the function reads a selector byte from address one and writes zero at selector plus 0x11. The read address follows from an explicitly zero-valued local calculation; no object base is visible.

The next call receives the additional register output twice, followed by sixteen times that output. Its producer and machine-level lifetime are not established sufficiently to assign it an application meaning.

### Additional-register byte publication

Following further calls, a returned result is retained for a scaled argument. The function reads a selector byte at sixteen times the additional register output plus one.

It writes the low eight bits of that output logically shifted right by twenty-two at selector plus 0x11. The stored byte therefore contains bits 22–29 of the represented output.

The following relevant calls receive:

- Four times the retained call result.
- Later, the selector first and four times a newer result second.

This selector-bearing call reverses the argument order used by the earlier selector-bearing call.

A subsequent two-argument call receives zero twice. Its source value was explicitly set to zero and then shifted left by ten, with no intervening explicit assignment changing it. These arguments are not derived from the fourth explicit input.

### Split-result publications

The next relevant call supplies a 64-bit result. Its upper and lower halves are retained separately.

The function first stores a zero word at four times the upper half plus 0x14. It then calls an unresolved target with the upper half.

After intervening calls, the upper half is stored at four times a newly returned index plus 0x14. The following call receives four times that index.

After more calls, the lower half determines a direct word publication:

- Destination: lower half multiplied by 0x10000000, plus 0x14.
- Stored value: lower half multiplied by 0x04000000.
- Following call argument: the same stored-value expression.

These are unsigned 32-bit calculations. The destination depends only on the lower half’s lowest four bits; the stored value depends only on its lowest six bits.

Later, the lower half masked with 0x1fffffff and logically shifted right by nine is stored at four times another returned index plus 0x14. This stored value contains at most twenty significant bits. The following call receives four times that index.

**Dependence boundary:** for a fixed lower half, these explicit lower-half transformations have fixed values, including the directly calculated destination. This does not establish independence of later call results, indexed destinations, reachability, or overall effects from the upper half. The upper half has already been stored and passed to an unresolved callee. Subsequent calls may observe that value or its effects and return different indices.

### Repeated scaled-word publications

The next portion repeatedly uses two distinct address forms.

For a returned value, the function forms a word equal to four times that value and stores it at sixteen times the original value plus 0x14. A later access at the formed word plus 0x14 is a different address calculation. The publication does not establish the contents of that later access.

Five such publications are visible, with different consumers:

1. **Two-read consumer.** The first is followed by a three-argument call: a word read at the formed word plus 0x14 and shifted right by twelve; the formed word itself; and a separate word read at the same address and shifted left by two. Both read expressions occur before the call, but their relative order and equality of observed values are not established. After intervening calls, the formed word is copied to another indexed destination.

2. **Lower-half consumer.** The second is followed by a call receiving the newly formed word twice and the retained lower half of the 64-bit result shifted left by twenty-six. After intervening calls, the formed word is copied to another indexed destination.

3. **Single-argument consumer.** The third feeds a call receiving the formed word alone, followed after more calls by an indexed copy of that word.

4. **Saved-read consumer.** The fourth is followed by a word read at the formed word plus 0x14. That read precedes a single-argument call and is retained across later calls.

5. **Bit-field consumer.** The fifth feeds the three-argument call described below, then is copied to an indexed destination after intervening calls.

The indexed copies use four times a newly returned index plus 0x14. Their following calls receive four times the corresponding index. Neither those indices nor their destinations are established as independent of preceding callee effects.

### Saved-word extraction and bit-field call

The saved read from the fourth publication is logically shifted right by twelve and stored at four times a new result plus 0x14. The following call receives four times that result.

That result is also retained for later calculations. After further calls, the fifth scaled-word publication occurs. Its following call receives:

1. The previously scaled result masked with 0x3f and shifted left by fourteen.
2. The newly formed word.

The third argument involves a represented signed shift, whose exact overflowing or negative-input semantics remain unresolved.

### Final byte publications and endpoint

After further calls and the indexed copy associated with the fifth publication, a new unsigned result supplies the final byte values.

The first selector read uses an address formed from the retained result that indexed the saved-word extraction: that result multiplied by 0x10000000, plus one. It is not a direct calculation from the earlier 64-bit result’s lower half.

At selector plus 0x11, the function writes the low byte of four times the new unsigned result. The next call receives four times that unsigned result twice, followed by sixteen times it. This call uses target displacement 0xfec rather than the surrounding pattern’s 0xffe.

A subsequent call returns a 32-bit word that is forwarded to another call. More calls intervene before the selector source is read again.

The second selector read is a fresh access to the same represented address expression. Its selected destination receives bits 20–27 of the unsigned result, using the earlier mask, shift, and byte truncation.

Remaining calls include one receiving four times an intervening result and another receiving four times a later result followed by the saved second selector. One additional call precedes the invalid-instruction marker. No ordinary continuation beyond that marker is established.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes the relevant operation is reached, preceding calls return, and required accesses are valid.

1. **Initial indexed store.** With an early returned index of three, the second explicit input is stored as a 32-bit word at 0x20. The following call receives twelve.

2. **Scaled-byte truncation.** An unsigned byte-publication result of 0x43 produces a scaled word of 0x10c. The destination receives byte 0x0c; the following call receives 0x10c.

3. **Mask-and-shift truncation.** For 0x3ff00000, masking with 0x3fffffff and shifting right by twenty produces 0x3ff. The byte store writes 0xff.

4. **Additional-register extraction.** An additional register output of 0xffc00000 produces 0x3ff after a logical right shift by twenty-two. The stored byte is 0xff.

5. **Explicit zero arguments.** The later call fed by the zero-valued expression receives zero in both positions, regardless of the fourth explicit input.

6. **Split-result dependence boundary.** An upper half of two makes the initial zero-word destination 0x1c. With a fixed lower half of three, the explicit lower-half-derived destination is 0x30000014 and its stored value is 0x0c000000. Changing the upper half does not change those two formulas for that fixed lower half. It may change subsequent callee results, indexed destinations, execution reachability, and overall effects; none of those are asserted independent.

7. **Distinct layouts.** For a scaled-word producer returning three, the formed word is twelve and its publication destination is 0x44. A subsequent read at formed word plus 0x14 accesses 0x20, not 0x44.

8. **Fresh selector observation.** If the first late selector read yields five and an intervening callee changes that source byte to nine, the two writes target 0x16 and 0x1a respectively.

9. **Partial execution.** If an early byte store faults, the representation provides no rollback of prior stores or callee effects and no guarantee that later calls occur.
