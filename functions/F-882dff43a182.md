# F-882dff43a182

## Purpose

F-882dff43a182 constructs an eight-byte result from two four-byte components:

- The upper component is derived from a global integer value by subtracting 84.
- The lower component is derived from the supplied integer by shifting it left by one bit.

The components are concatenated rather than added together. In particular, a bit discarded from the lower component does not carry into the upper component.

The supplied material establishes a small, stateless computation apart from its global-data dependency. It does not establish the application meaning of either component. Interpreting the result as a pointer, address, offset, tagged value, or pair of application fields would be inferred intent, not an established contract.

No runtime tests have been performed.

## Behavior

### Component construction

The upper component depends only on the observed global value. The function subtracts decimal 84 from that value and places the resulting four-byte component in the upper half of the return value.

The lower component depends only on the argument. A left shift by one supplies the lower four-byte component. Under a 32-bit bit-vector interpretation:

- Bit 0 of this component is zero.
- Argument bits 0–30 become component bits 1–31.
- Argument bit 31 is discarded.
- Any discarded bit has no effect on the upper component.

The result combines these two components without overlap. Changes to the argument affect only bits 31–0. Changes to the observed global value affect only bits 63–32, provided the respective arithmetic operation has defined semantics in the applicable execution model.

There is no branch, input-dependent selection, retry, loop, or special case in the supplied body.

### Arithmetic widths and limits

The result construction explicitly uses two four-byte components. It does not show a 64-bit shift of the argument or a 64-bit subtraction from the global value.

The distinction matters at boundaries. Treating the argument as an unrestricted mathematical integer and doubling it before forming a 64-bit result would introduce behavior not established by the supplied material. Likewise, borrowing from or carrying into the other component is not part of the construction.

For a conventional signed 32-bit source-language interpretation, both displayed arithmetic operations are unproblematic within this conservative domain:

- Argument: 0 through 1,073,741,823, inclusive.
- Observed global value: −2,147,483,564 through 2,147,483,647, inclusive.

Within those bounds, the left shift produces a representable nonnegative signed value, and subtracting 84 remains within the signed 32-bit range.

Outside that domain, two interpretations must remain distinct:

1. **Fixed-width bit-vector interpretation:** subtraction and shift produce 32-bit components, with any excess bits discarded.
2. **Strict signed source-language interpretation:** shifting a negative value, shifting beyond the signed representable range, or overflowing the subtraction may lack a defined result.

The supplied fragment alone does not resolve which language-level guarantees apply at those boundaries. Accordingly, wrapping behavior outside the conservative domain is conditional, not an unconditional acceptance requirement.
