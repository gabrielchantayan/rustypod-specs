# F-7de4ba5051b5

## Purpose

F-7de4ba5051b5 exports selected fields from 16 fixed-stride source records into a compact destination layout. Each source record contributes one transformed 32-bit packed value and two bytes obtained by truncating separate 32-bit fields.

The packed value contains eight four-bit fields. Only fields whose value is exactly 1 are changed. Each such field becomes either 14 or 15, selected by the corresponding bit of a source mask. All other four-bit values remain unchanged.

The function also copies the least significant eight bits of two source words into the destination. It does not initialize the remaining two bytes in each destination record.

These behaviors are established by the supplied static representation. The application-level meaning of the records, packed fields, and mask is unknown.

## Interface

### Invocation and result

The function receives one argument used as a destination memory address. The supplied representation expresses that argument as an integer rather than a typed buffer pointer.

There is no explicit return value. Results are communicated through memory writes.

The source address is obtained from a global location, not supplied by the caller. The function reads that global location once before processing the records and retains the resulting base address throughout this invocation.

There are no explicit length, capacity, record-count, or error-reporting parameters.

### Width model

The supplied representation uses:

- 32-bit unsigned words for the packed value, mask, and auxiliary source fields.
- Four-bit fields within the packed value.

The behavioral descriptions below use this 32-bit-word, eight-bit-byte interpretation. The original platform ABI, exact pointer representation, and alignment rules are not independently supplied.

A byte store retains only the low eight bits of its source word. Signedness of the intermediate character conversion does not change the resulting eight stored bits.

### Source layout

There are 16 source records, each with a stride of 32 bytes. Relative to the beginning of each record:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 4 bytes | Packed value containing eight four-bit fields |
| 4 | 4 bytes | Selection mask; bit positions 0 through 7 correspond to the eight packed fields |
| 12 | 4 bytes | First auxiliary value; only its low eight bits are exported |
| 16 | 4 bytes | Second auxiliary value; only its low eight bits are exported |

No direct reads of the other source-record bytes appear in the supplied representation.

The last source record begins 480 bytes after the source base. Its second auxiliary word occupies offsets 496 through 499 relative to that base. A conventional allocation containing all 16 complete records would occupy 512 bytes, but the function does not directly read the trailing 12 bytes of that allocation.

The mask word is read only when a packed field equals 1. The other three listed source words are read for every record.

## Behavior

### Record processing order

The function processes exactly 16 records, in increasing index order from 0 through 15.

For each record, the source address advances by 32 bytes per index and the destination address advances by eight bytes per index.

The source base itself is captured once. A later change to the global location holding that base does not cause the function to select a new source base during the same invocation.

### Observable access sequence within a record

The supplied representation establishes the following order of direct accesses:

1. Read the 32-bit source word at record offset 12.
2. Write its low eight bits to destination record offset 4.
3. Read the 32-bit source word at record offset 16.
4. Write its low eight bits to destination record offset 5.
5. Read the 32-bit packed value at source record offset 0.
6. Examine its eight four-bit fields, from least significant to most significant.
7. For each field equal to 1, read the source mask word and use its corresponding bit to choose a replacement.
8. Write the completed 32-bit packed result to destination record offset 0.

The two auxiliary byte writes occur before the packed source word is read. The packed result is written only after all eight fields have been considered.

This order matters when source and destination overlap. It also matters if the underlying memory has externally visible read or write effects. The supplied material does not establish a broader volatile-memory, device-memory, or concurrency contract.

### Packed-field transformation

Number the fields from 0 through 7, with field 0 occupying bits 0–3 of the packed word and field 7 occupying bits 28–31.

For each field:

- A value other than 1 is retained exactly.
- A value of 1 becomes 14 when the corresponding mask bit is zero.
- A value of 1 becomes 15 when the corresponding mask bit is one.

Only mask bits 0 through 7 participate. Higher mask bits do not affect the choice.

The function retains the packed value in working state while processing its fields. Changing one field does not alter another field. The largest field shift is 28 bits, so every selected four-bit range lies within a 32-bit word.

The source mask is not explicitly captured once for the whole record. A separate mask-word access is present for each field requiring replacement. Thus the static access structure contains between zero and eight mask reads per record. If externally changing memory supplies different mask values across those accesses, the supplied representation does not establish that all replacement decisions use a single consistent mask snapshot.

### Auxiliary truncation

Each auxiliary field is read as a full 32-bit word, but only bits 0–7 are written.

For example:

- An auxiliary value of 0x1234ABCD produces destination byte 0xCD.
- An auxiliary value of 0xFFFFFF80 produces destination byte 0x80.

This is numeric truncation. It is not a copy of whichever source byte happens to reside at the lowest address.

### Completion and failures

With valid memory and ordinary execution, all 16 records are processed and the function returns.

There is no explicit validation failure, status code, retry, or rollback. Invalid memory, unsuitable alignment, or unsupported address arithmetic may prevent completion according to the target environment. No particular fault mechanism is established here.

The function does not provide transactional output. Earlier records, or the auxiliary bytes of the current record, may already have been written if execution stops before the packed result is stored.

## Side effects

### Direct writes

The function directly writes:

- One 32-bit packed result per destination record.
- Two auxiliary bytes per destination record.

For a valid destination with distinct record addresses, this is 16 word stores and 32 byte stores, covering 96 distinct bytes.

It does not directly write destination record offsets 6 or 7. With ordinary disjoint buffers and no external writer, those bytes retain their prior contents.

### Overlap effects

The source is not explicitly written through its source address. Nevertheless, destination stores can modify source memory when the regions overlap.

Consequences include:

- An auxiliary byte store can change a source word before that word is read.
- A packed-result store can change data used by a later record.
- The function cannot generally be modeled as reading an immutable snapshot of all source records before writing the destination.

The per-record access order and increasing record order govern such effects.

### Ownership and lifetime

The function performs no visible allocation, deallocation, ownership transfer, or retained registration of the destination.

The source-base global is read, not directly updated. There are no called functions whose hidden effects could establish additional ownership behavior.

The source and destination lifetimes remain external responsibilities. No application-level ownership policy is established by this function alone.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not runtime test results.

### No field requires replacement

Given a source packed value of 0xFEDCBA98, the destination packed value must also be 0xFEDCBA98.

None of its fields equals 1. The mask is therefore not needed for that record, and no mask-word read appears on this path.

### Every field uses a zero mask bit

Given:

- Packed value: 0x11111111.
- Mask low eight bits: 0x00.
- Stable, nonoverlapping memory.

The destination packed value must be 0xEEEEEEEE.

### Every field uses a one mask bit

Given:

- Packed value: 0x11111111.
- Mask low eight bits: 0xFF.
- Stable, nonoverlapping memory.

The destination packed value must be 0xFFFFFFFF.

Mask bits above bit 7 do not change this result.

### Only the matching field changes

Given a packed value of 0x76543210, only field 1 equals 1.

- With mask bit 1 clear, the result must be 0x765432E0.
- With mask bit 1 set, the result must be 0x765432F0.

All other fields must remain unchanged, including field 0, whose value is zero.

### Auxiliary bytes and untouched destination bytes

Given a record whose auxiliary words are 0x1234ABCD and 0xFFFFFF80, the function must write:

- 0xCD at destination record offset 4.
- 0x80 at destination record offset 5.

If destination offsets 6 and 7 initially contain 0x5A and 0xA5, and no overlapping or external operation changes them, they must remain 0x5A and 0xA5.

### Early writes affect an overlapping source mask

Assume ordinary byte-addressable memory with the conventional little-endian word layout, and let the destination base equal the source base.

For the first source record, suppose:

- Packed value is 0x11111111.
- Mask word is initially zero.
- The first auxiliary word has low byte 0x01.
- The second auxiliary word has low byte 0x00.

The first auxiliary store writes 0x01 at source offset 4, changing the low byte of the mask before any mask read. The second store writes zero at source offset 5.

The first packed result must consequently be 0xEEEEEEEF, rather than the 0xEEEEEEEE that an immutable-source interpretation would predict. This example depends on the stated byte order and overlap conditions.

### Fixed record count

For valid storage, exactly 16 destination records are processed. No sentinel value in the packed fields or auxiliary words terminates processing early, and no seventeenth record is processed.
