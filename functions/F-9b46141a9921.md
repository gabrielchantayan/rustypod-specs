# F-9b46141a9921

## Purpose

F-9b46141a9921 conditionally writes a fixed byte into caller-designated memory and returns a 32-bit result.

The decision depends exclusively on whether the second input is zero:

- **Zero:** write the byte value 6 at byte offset 40 from the address represented by the first input, then return 0.
- **Nonzero:** return 14 without accessing memory through the first input.

This is the complete behavior established by the supplied static evidence. The meaning of the modified byte, the meaning of the second input, and the semantic interpretation of the return values are not established.

## Behavior

### Selection of the path

The second input is tested for equality with zero. There is no visible preliminary memory access through the first input, no validation of either input, and no dependency invocation.

No special nonzero value receives separate treatment. In particular, the function does not distinguish positive values, negative values, individual flag bits, or particular nonzero codes.

### Zero second input

When the second input is zero, the function uses the first input as the base for a destination at byte offset 40 and writes the 8-bit value 6 there.

This is an unconditional overwrite on that path:

- The previous destination byte is not read.
- Its previous value does not influence the write or result.
- The operation is not a bitwise update.
- No larger field is visibly loaded or stored.
- No surrounding bytes are visibly accessed.

The write precedes normal return of the 32-bit value 0. A normal zero result therefore follows the attempted state change; it is not returned by an alternative path that skips the write.

The supplied evidence does not show a recovery mechanism for an inaccessible or otherwise invalid destination. If the write cannot complete, ordinary return of 0 is not guaranteed.

### Nonzero second input

When the second input is nonzero, the function returns the 32-bit value 14.

On this path, the first input is not used for a memory access. There is no visible destination read, destination write, or address validation. An unusable first-input address therefore does not, by itself, cause this body to dereference that address on this path.
