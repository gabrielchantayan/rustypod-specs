# F-98458d1dc66a

## Purpose

F-98458d1dc66a conditionally transforms consecutive 32-bit words in place, traversing backward from a supplied end address. Before accessing each candidate through its traversal pointers, it evaluates a stopping score. A negative score terminates processing; a nonnegative score permits transformation.

Each accepted word receives an affine transformation controlled by four global words. The stopping score depends on the second argument, retained initialization observations of another global, two globals consulted during each evaluation, and the candidate’s ordinal.

Bounded backward-buffer processing is **inferred intent**, not an established safety property. The supplied representation contains no explicit allocation length, independently enforced traversal limit, or general termination guarantee.

## Interface

### Arguments and result

The arguments are:

- **End address:** a pointer interpreted as immediately following the first candidate word. The first candidate is one 32-bit word below this address.
- **Control word:** a 32-bit integer used in initialization and stopping calculations. Its interpretation as a length is not established.

Every normal return produces the 32-bit value zero. The result does not report a processed count, final position, or error.

Normal return is not guaranteed if traversal encounters invalid memory, invalid pointer arithmetic, or a stopping sequence that never rejects a candidate.

### Global words and layout

Seven global word locations are referenced. Their descriptive names specify roles, not application-level meanings.

The represented layout places them consecutively in the following order, at four-byte intervals. Offsets are relative to **Origin**, not absolute addresses.

| Relative byte offset | Global role | Use |
|---|---|---|
| 0 | **Origin** | Supplies initialization observations |
| 4 | **Threshold** | Contributes to each stopping score |
| 8 | **Mask** | Has three references in each stopping evaluation |
| 12 | **Inner multiplier** | Multiplies the previous destination value |
| 16 | **Inner offset** | Is subtracted from that product |
| 20 | **Outer multiplier** | Multiplies the resulting difference |
| 24 | **Outer offset** | Is added to obtain the replacement |

This adjacency constrains aliasing examples. In particular, **Outer multiplier occupies the word immediately below Outer offset**. If the first destination aliases Outer offset, the second destination necessarily aliases Outer multiplier, and the third aliases Inner offset. Their initial contents cannot be chosen independently of those globals.

Separate references to one global are not assumed to observe the same value.

### Storage and ownership requirements

For successful processing, each accepted candidate must support a 32-bit read and a 32-bit write. Address calculations must also be valid, including those performed for the candidate that ultimately rejects processing.

Candidate \(n\), numbered from zero, occupies:

\[
\text{end address}-4(n+1).
\]

This formula describes the represented four-byte word spacing. The target address width, required alignment, and byte order are not independently established. Byte order affects the stored byte representation, not the word-level transformation.

No allocation, release, or ownership transfer is expressed. The function operates on caller-supplied storage; it does not establish that the storage is large enough or disjoint from the globals.

## Behavior

### Arithmetic model

The algebraic descriptions and acceptance examples below use the represented 32-bit word interpretation:

- Addition, subtraction, negation, and multiplication retain their low 32 bits.
- Bitwise operations act on 32 bits.
- A score is negative when bit 31 is set.
- The initialization right shift propagates the sign bit through 31 positions, producing zero for a nonnegative word and all ones for a negative word.

These describe the apparent word-level behavior. Some represented expressions have signed types. Portable source-language behavior for signed overflow is not established, and the sign-propagating interpretation of the shift lacks independent target confirmation.

Pointer arithmetic is separate from this word-arithmetic model. In particular, modulo arithmetic on word values does not establish that pointer wraparound or traversal outside an allocation is valid.

### Initialization observations

Initialization references Origin four times:

1. A **control observation**, subtracted from the original control argument.
2. A **successor observation**, used in an increment-by-one calculation.
3. A **shift observation**, shifted right by 31 positions.
4. A **subtraction observation**, used in constructing the initial traversal state.

The control calculation precedes the successor calculation, and both precede construction of the traversal state. The representation does not establish an order between the shift observation and subtraction observation within their shared expression.

Derived initialization values are retained. Later changes to Origin do not refresh them.

### Candidate coordinate

Define a 32-bit **coordinate** for each candidate. For candidate zero, it is the subtraction observation minus the shifted shift observation. Each subsequent candidate’s coordinate is one less, modulo \(2^{32}\).

When every initialization observation of Origin equals a stable word \(B\), candidate \(n\) therefore has coordinate:

\[
B-\operatorname{asr}_{31}(B)-n\pmod{2^{32}}.
\]

The traversal state is advanced during each candidate evaluation, including the terminating evaluation. Destination contents do not directly determine this coordinate.

### Stopping score

The following bit-oriented description is an algebraic characterization, not a required implementation strategy or read sequence.

For a candidate with coordinate \(K\), define three 32-bit words:

- **Control-side word:** \(K\) plus the original control argument, minus the control observation, minus one.
- **Origin-side word:** \(K\) minus the successor observation, minus one.
- **Span word:** the original control argument plus the successor observation, minus the control observation.

Reduce each calculation to 32 bits before selecting its bits.

Each stopping evaluation has one Threshold reference and three Mask references. Distinguish the Mask observations by expression role:

- **Positive-selection observation**.
- **Complement-selection observation**.
- **Final-toggle observation**.

These labels do not specify their runtime read order.

The score is the 32-bit sum of the following contributions:

1. The observed Threshold, plus one, plus \(K\).
2. A word whose bit is set exactly where the span bit is one and the origin-side bit is zero.
3. A word determined independently at each bit position as follows:
   - If either the control-side bit or the origin-side bit is one, select the positive-selection observation’s bit.
   - Otherwise, select the complement of the complement-selection observation’s bit.
   - Toggle the selected bit if either the control-side bit or the span bit is one.
   - Toggle it again if the final-toggle observation’s bit is one.

The contributions are added with carries and 32-bit wraparound. They are not combined using bitwise OR. Two contributions at the same bit position can therefore carry into a higher position.

The decision is:

- **Bit 31 set:** reject this candidate and terminate.
- **Bit 31 clear:** transform this candidate and continue backward.

Zero accepts a candidate.

For the stable configuration in which Origin, the original control argument, and Mask are all zero, the score simplifies to:

\[
R_n=\text{Threshold}-n\pmod{2^{32}}.
\]

Threshold must also remain stable for this expression to describe the complete score sequence.

### Accepted-word transformation

For an accepted candidate, let \(X\) be its previous 32-bit value. Let \(a,b,c,d\) be the values observed from Inner multiplier, Inner offset, Outer multiplier, and Outer offset, respectively.

The replacement is:

\[
c(aX-b)+d\pmod{2^{32}}.
\]

It is stored into the same candidate word.

There is no saturation, range clamp, or explicit overflow report. The store occurs even if the replacement equals the previous value.

Coefficients are referenced in each accepted candidate’s transformation. They are not established to be a snapshot taken at entry.

### Observable ordering

The supplied body establishes these constraints:

- Initialization precedes candidate processing.
- Both traversal pointers move backward before the corresponding stopping decision.
- The stopping decision precedes the candidate read used for transformation.
- Rejection prevents that candidate’s transformation read and write.
- For acceptance, the previous destination value is read before its replacement is stored.
- The completed store precedes the next candidate’s stopping evaluation.

Both traversal pointers begin at the supplied end address and advance identically, so the transformation reads and writes the same candidate word.

The representation does not establish a total order among operand reads within an expression. In particular, it does not fully order the destination read relative to the four coefficient reads, or the Mask observations relative to each other.

Counts of references describe the supplied representation, not independently verified machine-load counts. Volatile, atomic, and synchronization properties are not established.

## Side effects

### Destination footprint

If exactly \(N\) candidates are accepted before normal termination, the transformed words are:

\[
\text{end address}-4,\ 
\text{end address}-8,\ 
\ldots,\ 
\text{end address}-4N.
\]

The next lower candidate is rejected without a transformation access through the traversal pointers.

If the first candidate rejects, no destination transformation read or write occurs. Initialization reads, stopping-global reads, and the preceding pointer calculations still occur.

A rejected candidate’s address might also designate a global location. The absence of a transformation access does not imply that the same address is never read in its global role.

### Aliasing and changing globals

There are no explicit assignments to the global roles. Destination stores can nevertheless change them when the destination region overlaps their storage.

Consequences include:

- A store to Origin does not alter initialization values already retained.
- A store to Threshold or Mask can change subsequent stopping decisions.
- A store to a coefficient can change subsequent transformations.
- When a destination aliases a coefficient, its previous value and the coefficient’s observed value participate in computing the replacement before that replacement is stored.

The fixed global layout remains binding during such overlap. A backward traversal beginning at Outer offset next reaches Outer multiplier, then Inner offset, then Inner multiplier. These destinations cannot simultaneously be treated as unrelated buffer words with independently selected initial values.

External mutation is not excluded by the body. Its legality and visibility depend on an unspecified execution and memory model; the function provides no demonstrated concurrent-access guarantee.

### Errors and partial progress

There is no explicit validation branch, error result, recovery path, or rollback.

Earlier completed stores precede any later invalid access. No visible mechanism undoes them. Exact fault delivery and the effects of an interrupted store are unresolved.

No independent iteration cap is visible. The function does not establish safe behavior after leaving valid storage or encountering invalid address arithmetic.

## Acceptance examples

These are conditional static derivations, not executed tests. They assume valid address calculations, sufficient accessible storage, the stated 32-bit arithmetic interpretation, and no external mutation. Unless an example explicitly specifies overlap, destinations are disjoint from global storage.

### Immediate rejection

Set Origin, the control argument, and Mask to zero. Keep Threshold at \(\texttt{0xFFFFFFFF}\).

The first score is \(\texttt{0xFFFFFFFF}\), which is negative.

Expected behavior:

- No destination transformation read or write.
- No evaluation of a subsequent candidate.
- Normal return of zero.

This does not demonstrate that an arbitrary invalid end address is acceptable: backward pointer calculations precede rejection.

### Zero accepts exactly one word

Keep Origin, the control argument, and Mask at zero. Keep Threshold at zero.

| Candidate | Score | Decision |
|---|---|---|
| 0 | \(\texttt{0x00000000}\) | Transform |
| 1 | \(\texttt{0xFFFFFFFF}\) | Reject |

Exactly the word immediately below the end address is transformed. The next lower word receives no transformation access. Normal return is zero.

This distinguishes negative-only rejection from rejection of all nonpositive scores.

### One-word transformation with wraparound

Use the preceding one-word stopping configuration. Set:

- Inner multiplier to 2.
- Inner offset to 1.
- Outer multiplier to 3.
- Outer offset to 4.

Let the first candidate contain \(\texttt{0x80000000}\). Its inner product has low 32 bits equal to zero, so its replacement is:

\[
3(0-1)+4=1\pmod{2^{32}}.
\]

The first candidate becomes \(\texttt{0x00000001}\). The second candidate rejects.

This result is conditional on the word-arithmetic interpretation; it does not independently establish portable signed-overflow behavior.

### Two accepted words in descending address order

Set Origin, the control argument, and Mask to zero, and keep Threshold at one. The successive scores are one, zero, and \(\texttt{0xFFFFFFFF}\).

Set both multipliers to one, Inner offset to zero, and Outer offset to one.

Expected behavior:

1. Increment the word immediately below the end address, modulo \(2^{32}\).
2. Increment the next lower word.
3. Reject the third candidate without a transformation access.
4. Return zero.

With Threshold instead held at two, three words would be accepted before rejection.

### Adjacent destinations change two coefficients

Use Origin, the control argument, and Mask equal to zero, with Threshold equal to one. Set both multipliers initially to one, Inner offset to zero, and Outer offset to one.

Place the first destination at Outer offset. The represented layout then places:

- Candidate 0 at Outer offset, initially one.
- Candidate 1 at Outer multiplier, initially one.
- Candidate 2 at Inner offset, initially zero.

The first accepted transformation computes:

\[
1(1\cdot1-0)+1=2.
\]

It changes Outer offset from one to two.

The second accepted transformation reads its destination’s previous value as one and observes Outer multiplier as one and Outer offset as two. It computes:

\[
1(1\cdot1-0)+2=3.
\]

It changes Outer multiplier from one to three.

The third candidate rejects because its score is \(\texttt{0xFFFFFFFF}\). Inner offset remains zero, and normal return is zero.

The second destination cannot initially contain ten while Outer multiplier initially equals one: they are the same word. The expected second replacement is three, not twelve.
