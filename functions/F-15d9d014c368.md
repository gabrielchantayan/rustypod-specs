# F-15d9d014c368

## Purpose

F-15d9d014c368 selects a position according to one of five numeric modes, invokes an extraction dependency, and optionally updates a position record and a reported-length output. It also makes output-related dependency calls using values supplied by extraction.

Endpoint selection, forward/backward navigation, and copying extracted data are inferred intent. Established behavior consists of memory accesses, arithmetic, branch decisions, dependency calls, and status handling. The available evidence does not establish that the output-related or descriptor-transition dependencies actually copy memory.

The operation is not transactional. Output writes and dependency effects can precede failure. Common failure handling clears specified fields, not all previously affected state.

The successful finalization path returns zero. **A zero return alone does not establish that extraction, output processing, or successful finalization occurred:** unknown global status values can also produce zero through early-return or common-failure paths.

## Interface

### Arguments and return value

The function accepts five arguments:

1. **Handle reference:** an address containing a 32-bit context address. Its second 32-bit word is accessed only during a particular endpoint-rejection operation.
2. **Mode:** a 32-bit integer. Recognized values are 0, 1, 2, 3, and 4.
3. **Position record:** an optional output address, also passed to F-5b0eaa2a8301 in modes 1, 2, and 4.
4. **Payload destination descriptor:** an optional address containing three 32-bit words.
5. **Reported-length output:** an optional address receiving 16-bit writes.

The represented return type is pointer-shaped, but the visible behavior uses 32-bit status patterns. A null handle reference returns 0xffffffce, equivalent to signed −50. Other returned values arise from dependencies, status globals, or explicit constants. Common failure handling converts selected status 778 or 852 to 32.

No global status value is established as nonzero.

## Behavior

### Initialization and status selection

All three temporary descriptor first words are cleared before either immediate-return path.

A null handle reference returns 0xffffffce without common cleanup or direct clearing of optional outputs.

Otherwise, the first handle word is read as the context address. A zero context causes an immediate read and return of the **invalid-context status global**, again without common cleanup. That value can be zero.

Three other status globals have distinct evaluation points:

- **Unsupported-mode status:** read on entry to the dispatch branch containing mode 3 and unsupported modes. For mode 3, this precedes the endpoint-identifier read even though the sampled status is subsequently replaced.
- **Endpoint-unavailable status:** read after the endpoint identifier, before testing that identifier and before any endpoint-loading call. It is read even for a nonzero identifier.
- **Missing-predecessor status:** read in mode 2 after a link result becomes the working identifier and before testing it for zero. It is read even when a nonzero identifier subsequently permits loading.

These role labels do not establish different values or semantic meanings.

Unsupported modes enter common failure handling with the sampled unsupported-mode status. If it is zero, common cleanup still occurs and the returned status is zero.

### Modes 0 and 3: endpoint selection

Mode 0 reads the working identifier from context offset 0x14.

Mode 3 first reads the unsupported-mode status, then reads the working identifier from context offset 0x18.

Both modes next read the endpoint-unavailable status. A zero identifier enters common failure with that sampled value. Otherwise, F-5f9a16493218 receives the context, working identifier, and current descriptor. A nonzero result selects common failure with that result.

Following a zero loading result:

- Read the marker byte at current-block offset 8.
- Only if that byte is 255, read the unsigned 16-bit count at block offset 10.
- Qualification requires marker 255 and a nonzero count.

For qualifying metadata, mode 0 selects index zero; mode 3 selects count minus one.

If qualification fails, F-b0f922796692 receives the context and current descriptor. A nonzero result becomes the failure status. A zero result instead selects status 36 and performs an indirect 16-bit flag update before common failure.

That update contains **separate pointer-resolution expressions for the value read and the destination write**:

- The value expression reads the handle’s second 32-bit word, reads a 32-bit pointer at offset 4 from that address, and reads the pointed-to 16-bit value.
- The destination expression separately reads the handle’s second 32-bit word and the pointer at offset 4 to locate the 16-bit write.
- The written value is the value-expression result with bit 0 set.

The relative evaluation order of the destination expression and value expression is not established. One resolved pointer must not be assumed to serve both accesses. If the two expressions resolve differently, the write need not target the location supplying the old value.

Common cleanup subsequently calls F-b0f922796692 on the current descriptor again.

### Modes 1, 2, and 4: resolution

F-5b0eaa2a8301 receives, in order, the context, position-record argument, preceding descriptor, current descriptor, following descriptor, and output locations for a working identifier, 32-bit index, and four-byte flag area.

A nonzero result enters common failure.

Subsequent selection consumes the index’s low 16 bits and the flag area’s first byte. A zero dependency result does not independently prove that these outputs or descriptors are valid. Validity of every subsequently consumed output is a precondition.

### Mode 2: backward selection

Otherwise:

1. If the preceding descriptor is absent, call F-4055be9c3f18 with the current block address plus 4.
2. Store the result’s low 32 bits as the working identifier, then read the missing-predecessor status.
3. A zero identifier enters common failure with that status. Otherwise, call F-5f9a16493218 for the preceding descriptor; nonzero fails.
4. If the following descriptor is present, call F-b0f922796692 on it; nonzero fails.
5. Invoke the unmapped transition dependency with following descriptor, current descriptor, and 20.
6. Invoke it with current descriptor, preceding descriptor, and 20.
7. Clear only the preceding descriptor’s first word.
8. Read the unsigned 16-bit count at offset 10 from the address now in the current descriptor’s first word.

The selected working index becomes count minus one using unsigned 32-bit arithmetic. Count zero therefore produces 0xffffffff; extraction receives its low 16 bits, 65535.

The transition calls do not establish descriptor copying. The subsequent current-block address depends on their actual effects. When a preceding descriptor was already present, this branch does not independently refresh the working identifier.

### Mode 1: forward selection

If the flag byte is not 1, call F-4055be9c3f18 with the current block address.

If the result’s low 32 bits are zero, read the block’s unsigned 16-bit count and compare it with the index’s low 16 bits. Equality selects raw status 852 and common failure.

If that failure does not occur, a flag byte of zero causes a further count comparison. If the count differs from the low 16 index bits, proceed to extraction with the existing working index, without incrementing it.

Otherwise, compare the low 16 index bits against count minus one using signed 32-bit comparison. Count zero makes the right operand −1.

- If the index is smaller, select the low 16 index bits plus one.
- Otherwise, attempt advancement through the following descriptor.

Advancement performs these operations:

1. If the following descriptor is absent, call F-4055be9c3f18 with the current block address.
2. Store its low 32 bits as the working identifier. Zero selects raw status 852.
3. For a nonzero identifier, call F-5f9a16493218 for the following descriptor; nonzero fails.
4. If the preceding descriptor is present, call F-b0f922796692 on it; nonzero fails.
5. Invoke the unmapped transition dependency with preceding descriptor, current descriptor, and 20.
6. Invoke it with current descriptor, following descriptor, and 20.
7. Clear only the following descriptor’s first word.
8. Select index zero.

A preexisting following descriptor avoids the link/load step and does not independently refresh the working identifier.

F-4055be9c3f18 can be called twice on this mode’s path. Its results and the state it observes must not be assumed identical.

### Mode 4: resolved-position selection

Flag byte 1 bypasses this local range check. No extraction-boundary guarantee follows from that bypass.

### Extraction and output sequencing

A nonzero result enters common failure before direct output processing.

- Multiply its two capacity factors at 32-bit width, discarding high bits.

- Write the working identifier at offset 4.
- Write the selected index’s low 16 bits at offset 8.

### Finalization and common failure

After output processing, call F-b0f922796692 on the current descriptor. Only if it returns zero, process a present preceding descriptor. Only if those steps succeed, process a present following descriptor.

If every required finalization call returns zero, return zero.

Common failure handling instead:

1. Calls F-b0f922796692 on preceding, current, and following descriptors, in that order, without presence checks.
2. Ignores all three cleanup results.
3. Clears the optional 16-bit reported length.
4. If a position record exists, clears offsets 0, 4, 8, 10, 12, 16, and 18 at their specified widths, then clears 16 bits at offset 28.
