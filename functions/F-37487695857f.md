# F-37487695857f

## Purpose

F-37487695857f conditionally updates three bytes in caller-supplied storage after evaluating up to three candidate values through F-a1e68ae27737. Evaluation stops at the first nonzero dependency result.

The direct state changes are:

- First result nonzero: write 1 at object offset 77, then 0 at offset 78.
- First result zero and second result nonzero: write 1 at offset 78, then 0 at offset 77.
- First two results zero and third result nonzero: write 1 at offset 76.
- All three results zero: perform no direct object write.

The candidate addresses depend on two separate evaluations of a global pointer. The function first saves that pointer. It then evaluates the global pointer again to locate the first candidate. The second and third candidates are located using the saved pointer, not by reevaluating the global.

A single three-entry sequence describes these candidates only if the two initial global-pointer evaluations produce the same address. That stability is not established by this function.

“Success” or “match,” where used below, means only a nonzero dependency result. The evidence does not establish comparison, lookup, validation, or any particular interpretation of the candidates.

The function does not initialize or normalize the three object bytes as a group.

## Behavior

### Initial pointer evaluations

The function first evaluates the global pointer and retains the resulting address for later use.

It then separately evaluates the same global pointer and reads a 32-bit candidate through that second result. Both evaluations occur before the first dependency invocation. No dependency call occurs between them.

The source establishes this evaluation model; it does not establish a synchronized snapshot, a volatile-access guarantee, or a mechanism by which another actor could change the pointer between evaluations. If the pointer remains stable across these evaluations, the two addresses coincide. Otherwise, a common base for all three candidates cannot be assumed.

### Ordered dependency calls

The first call supplies:

1. The original 32-bit query.
2. The 32-bit candidate obtained through the second global-pointer evaluation.

A nonzero result selects the first outcome immediately. The function does not read either later candidate or make another dependency call.

If the first result is zero, the function reads the 32-bit entry at byte displacement 4 from the saved base. It calls F-a1e68ae27737 with the original query and that newly read value.

A nonzero second result selects the second outcome. The third entry is not read.

If the second result is also zero, the function reads the 32-bit entry at byte displacement 8 from the saved base and makes a third call with the original query and that value.

A nonzero third result selects the third outcome. A zero third result produces no direct object write.

Only zero versus nonzero matters. Positive and negative nonzero results select the same branch. Result magnitude is not used as an index, count, address, or stored value.
