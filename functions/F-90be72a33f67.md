# F-90be72a33f67

## Purpose

F-90be72a33f67 searches for a record matching two unsigned 32-bit key components. Depending on an initial gate, caller control, context state, and cache availability, it either performs no lookup, traverses a linked chain, or searches a table of record references.

Its result is a 64-bit aggregate, not merely a record reference. The lower word identifies the selected record or is zero. The upper word depends on the completed lookup path.

The apparent intent is to provide a cached lookup with linked-chain fallback when cache construction does not leave a usable table. This is inferred intent. The supplied representation establishes neither cache-ordering guarantees nor synchronization, allocation, ownership, or lifetime guarantees.

## Interface

### Arguments

The interface has five arguments, each represented by 32 bits.

| Argument | Established interpretation |
|---|---|
| Context | Address of storage containing the fields below. |
| Auxiliary word | Opaque value passed to the table-processing dependency and used in some return paths. |
| First key | Unsigned key component matched against record offset 16. |
| Second key | Unsigned key component matched against record offset 20. |
| Cache control | Zero selects linked traversal; nonzero permits consideration of the cache path. |

Although the context and cache-control arguments have signed representations in the supplied material, their relevant uses are address formation and zero/nonzero testing. No domain-specific signed interpretation is established.

Cached records use the same key offsets. Cache search does not directly inspect their next-record fields.

### Table layout

A table begins with a 32-bit count word. Search interprets that word as signed. Consecutive 32-bit record references follow immediately:

- Entry zero is at byte offset 4.
- Entry one is at byte offset 8.
- Each subsequent entry advances by four bytes.

The processing dependency receives the address four bytes beyond the table base and the table’s first word as separate arguments.

### Global input

The table-processing call also consumes an opaque datum read from global storage. It is not a literal constant or an additional public argument.

The supplied representation does not provide the global’s declaration, independently establish its storage width, or explain its meaning. Its value is evaluated for the processing call after the cache-entry dependency, construction dependency, and publication of the construction result. No preservation of that global across those earlier calls is assumed.

### Return value

The result has the following bit layout:

| Completion path | Bits 0–31 | Bits 32–63 |
|---|---|---|
| Initial gate rejects lookup | Zero | Auxiliary word |
| Direct linked traversal | Matching record reference, or zero | Auxiliary word |
| Linked fallback after cache construction or processing | Matching record reference, or zero | Auxiliary word |
| Search of a usable cached table | Matching record reference, or zero | First key |

This specifies logical bit placement. It does not establish memory byte order or physical return registers.

## Behavior

### Initial gate

The first dependency invocation is F-cd52fcefba54, called without explicit arguments. Its result is tested as a 32-bit zero/nonzero value.

A zero result immediately produces a zero lower return word and the auxiliary word as the upper return word. This function directly reads no context field on that branch.

A nonzero result allows representation selection. The gate dependency itself may affect memory or global state; the early return does not imply that the overall invocation is side-effect-free.

### Representation selection

Cache control is tested first.

When it is zero, linked traversal is selected without reading the context byte at offset 6.

When it is nonzero, the function reads that byte:

- Nonzero selects linked traversal.
- Zero selects the cache path.

No particular nonzero control value has a distinct branch-selection meaning.

### Linked traversal

The function reads the chain head from context offset 12. It follows nonzero record references in chain order.

For each record, the second key field at offset 20 is compared first. The first key field at offset 16 is read for comparison only when the second key matches. If both match, that record is selected without reading its next reference for further traversal.

After a mismatch, the next reference is read from record offset 0. Reaching a zero reference produces a miss.

Consequently:

- The first matching record encountered in chain order wins.
- Later duplicates are not examined after a match.
- An empty chain returns a zero lower word.
- The upper word is the auxiliary word, including when traversal follows cache fallback.

There is no explicit cycle detection, traversal bound, malformed-reference check, or error status. A cycle that never reaches a matching record or a zero reference need not terminate.

### Cache entry

Before inspecting the cached table, the function reads the 32-bit value at context offset 2512 and retains it. F-338d16f9ce72 is called with that retained value.

Only after this call does the function inspect the cached table reference at context offset 2524. Changes made by the dependency can therefore affect whether construction occurs.

The retained boundary-call value is not refreshed from the context. The later F-1333331b2da1 call receives the same retained value even if either dependency changes the context field.

These calls resemble entry and exit operations, but synchronization semantics are not established.

### Table acquisition and processing

If the cached table field is nonzero after the entry call, construction and processing are skipped. The function proceeds toward cache search.

If that field is zero, F-f16e3e6dbf6b is called with the context address. Its 32-bit result is written to context offset 2524, including when the result is zero.

A zero construction result causes fallback without invoking the processing dependency or evaluating its global argument.

For a nonzero construction result, F-b4b5aa4c2f83 is called with seven arguments:

1. The address four bytes beyond the returned table base.
2. The first 32-bit word of that returned table.
3. The opaque datum read from global storage.
4. Zero.
5. The auxiliary word.
6. The first key.
7. The second key.

The argument positions are established; their evaluation order is not. In particular, the supplied representation does not establish whether the global read occurs before or after the count-word read or other argument evaluations. It does establish that evaluation of the global datum for this call occurs after the entry dependency, construction dependency, and publication of the nonzero construction result.

The global must not be treated as a value captured before those earlier calls. Either earlier dependency may have changed it.

The processing dependency’s return value is ignored. After it returns, the function reads the context’s cached table field again:

- Zero causes fallback.
- Nonzero permits cache search.

The processing dependency may have replaced the published table. The subsequent search obtains its table reference from the context, rather than being required to use the construction result.

On fallback, F-1333331b2da1 is called with the retained boundary value before the linked-chain head is read. Thus, linked traversal observes the head available after that call. No retry, direct deallocation, or distinct construction-error result is shown.

### Cached search

The function obtains the cached table reference from the context and reads its first word as a signed 32-bit count.

For ordinary nonnegative counts with representable arithmetic, the candidate interval begins at index zero and ends at count minus one.

While the endpoints differ by more than one, the function examines a midpoint computed from signed endpoint addition followed by division by two. At a midpoint, the represented reads obtain:

1. The record’s first key at offset 16.
2. The record’s second key at offset 20.

Both midpoint key fields are obtained before the match decision. This differs from the short-circuited key reads used in linked traversal and the final candidate scan.

An exact midpoint match selects that entry. Otherwise, unsigned lexicographic comparison determines which endpoint moves:

- The second key is the primary ordering component.
- The first key breaks ties.
- A midpoint pair less than or equal to the requested pair becomes the lower endpoint.
- A greater pair becomes the upper endpoint.

Once no more than two candidate indices remain, the function examines them in increasing index order. Each final candidate is checked second key first; the first key is read for comparison only if the second key matches. The first matching final candidate is selected. Exhausting the interval yields zero.

The supplied expressions reread a midpoint’s table entry when obtaining its separate key fields and again when selecting a midpoint hit. They do not establish a single atomic record snapshot. The final scan obtains a candidate reference before checking that record’s keys. Reliable results require those reads to remain valid and coherent; mutation behavior is not resolved by this function.

Correct lookup for an otherwise valid table requires ascending unsigned order by second key and then first key. The function performs no ordering validation. An unsorted table may contain a matching record that the search misses.

Duplicates do not imply selection of the lowest matching table index: an exact midpoint match can finish the search before the final scan.

After either a cache hit or a cache miss, F-1333331b2da1 is called with the retained boundary value. The result’s upper word is then the first key.

A cache miss does not trigger linked fallback.

### Counts and arithmetic

The following behavior is established when the relevant arithmetic and addresses are valid:

- Count zero produces an empty interval and no entry access.
- Count one examines entry zero.
- Count two examines entry zero, then entry one if the first does not match.
- A negative count produces an empty interval when subtracting one remains representable.

The search uses signed 32-bit arithmetic for count reduction, endpoint differences, endpoint addition, index adjustment, and final-scan advancement. Address formation also depends on four-byte table-entry spacing.

No overflow check is shown. In particular:

- Subtracting one from the minimum signed 32-bit count is not representable.
- Endpoint addition can overflow even for a positive count.
- Index adjustment and address formation must also remain valid.

The supplied representation does not establish portable results for signed overflow. It is therefore not a contract that every malformed count is safely rejected or treated as an empty table.

## Side effects

The only direct context write shown is publication of the construction result at offset 2524. This write occurs before processing and occurs even for a zero construction result.

The function directly performs no record writes, table-entry writes, deallocation, or reference-count operations. Its dependencies are not constrained by that observation: they may change context fields, globals, tables, records, allocation state, or object lifetimes.

The opaque global is read for the processing call, but no direct write to it is shown. This does not imply constancy across dependency calls.

On ordinary cache-path completion:

- F-338d16f9ce72 runs before table inspection.
- F-1333331b2da1 runs after cache search or before linked fallback.
- Both receive the same retained 32-bit value.

No matching-exit guarantee is established for invalid accesses, nonreturning dependencies, exceptions, or other abnormal transfers.

The selected record reference is determined before the cache exit dependency. That dependency may alter or invalidate the referenced record unless a separate contract prevents it. Returning a reference establishes no ownership transfer, retention, release obligation, or lifetime beyond the exit call.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, referenced memory is valid, arithmetic is representable, and dependencies do not invalidate storage needed by subsequent operations.

1. **Gate rejection without direct context access**  
   If F-cd52fcefba54 returns zero and the auxiliary word is `0xAABBCCDD`, the result is `0xAABBCCDD00000000`. This function does not directly read the context.

2. **Caller bypass avoids the flag read**  
   With a nonzero gate result and zero cache control, the function searches the linked chain without directly reading context offset 6 or invoking either cache boundary dependency.

3. **First linked duplicate wins**  
   In an acyclic chain containing two matching records, the earlier record in chain order is returned. The auxiliary word occupies the upper half.

4. **Construction failure publishes zero before fallback**  
   If construction returns zero, the function writes zero to the cache field, skips processing and its global-argument read, calls the exit dependency, and searches the chain.

5. **Processing receives the current global datum**  
   Suppose an earlier cache-entry or construction dependency changes the global datum from one value to another, with no later change before argument evaluation. Processing receives the later value. The datum is not captured at function entry.

6. **Argument evaluation order remains unspecified**  
   For a processing invocation requiring both the table count and global datum, acceptance does not require either read to precede the other. Both belong to argument evaluation after publication of the construction result.

7. **Processing withdraws the cache**  
   If processing leaves the cache field zero, the exit dependency runs and linked traversal follows. The upper return word is the auxiliary word, not the first key.

8. **Processing replaces the table**  
   If processing leaves a different valid nonzero table in the context, search uses the table subsequently read from that field. The original construction result is not necessarily searched.

9. **Empty cache is a completed cache lookup**  
   A valid cached table with count zero produces a zero lower word and the first key as the upper word. A matching record in the linked chain is not consulted.

10. **Unsigned ordering and duplicates**  
    A second key of `0xFFFFFFFF` follows `0x00000001` in the required ordering. If several entries match, a midpoint hit may be returned instead of the lowest-index duplicate.

11. **Path-dependent upper word**  
    With auxiliary word `0x11111111` and first key `0x22222222`, a linked miss returns `0x1111111100000000`; a usable-cache miss returns `0x2222222200000000`.
