# F-07fef63861ea

## Purpose

F-07fef63861ea conditionally decreases a four-byte field in an indirectly referenced object. A resulting value of exactly zero enables a dependency sequence, but only if a second observation of the input slot supplies a nonzero object address.

The central behavioral distinction is between the **updated object**, identified by the initial slot observation, and the **selected object**, identified by the later observation. The updated object receives the decrement. The selected object supplies the dependency arguments. Their addresses need not be equal.

Reference release followed by cleanup is **inferred intent**, not an established ownership contract. The supplied evidence does not establish that the field counts references, that any dependency releases a resource, or that an object is destroyed.

On established ordinary-return paths, the result is the original input slot address. The final dependency carries a nonreturning annotation; successful completion of the entire dependency sequence is not established.

## Interface

### Explicit input and result

The explicit input is an address identifying a slot that contains an address-bearing value. A null slot address is not handled specially: the slot is read before its contents are tested.

Zero **slot contents** are supported and produce an ordinary return without accessing an object. This must not be confused with a zero **slot address**.

Whenever the function returns ordinarily, its result is the input slot address—not the slot contents, a dependency result, or the updated field value. Returning that address does not imply that the referenced storage remains valid.

## Behavior

### Update and activation condition

The function has three established outcomes before dependency processing:

- Empty initial slot contents: no object update and ordinary return.
- Nonzero initial contents with a nonzero decrement result: one field update and ordinary return.
- Nonzero initial contents with a zero decrement result: one field update followed by a fresh selection from the slot.

For a nonzero initial address, the signed 32-bit field at offset 28 is decreased by one and the result is stored at the same location. The stored result controls activation. There is no separate field reread establishing the condition.

The update is not saturating. An initial value of zero becomes −1 and does not activate dependency processing. An initial value of −1 becomes −2 and likewise does not activate it. An initial value of 1 becomes zero and enables the second slot observation.

These statements concern representable arithmetic. Decrementing −2,147,483,648 falls outside the representable signed 32-bit range. The supplied representation does not establish whether the executable wraps, traps, or has some other language- or platform-dependent treatment. This boundary is **documented_only**, rather than assigned a guessed overflow rule.

The write occurs before selection and before any dependency invocation. There is no visible rollback if selection is empty or a later dependency fails to return.

### Selection is a separate observation

A zero decrement result does not itself guarantee a dependency call. The fresh slot observation must also supply a nonzero address.

If that observation supplies zero, processing ends with an ordinary return. The completed field update remains part of the function’s effects.

If it supplies a nonzero address, that address becomes the selection for the entire dependency sequence. There is no equality requirement connecting it to the updated object, and selecting another object does not cause another decrement.

This distinction is observable wherever the surrounding execution legally permits different slot observations. It must not be eliminated by assuming that the initial and selected addresses are interchangeable. It also does not establish that unsynchronized concurrent mutation is supported.

Once selection succeeds, this function does not explicitly read the input slot again. Subsequent changes to the slot alone therefore do not redirect the selected-object field accesses or the final address argument.

### Dependency processing and observation timing

The selected object supplies three field values to three invocations, followed by a final invocation receiving its retained address.

The call order is fixed: F-58ba61416cc9 receives the offset-24 value, F-58ba61416cc9 is invoked again with the offset-8 value, F-56c3b4c706c6 receives the offset-0 value and an external datum, and F-feee9156a257 receives the selected address.

This ordering is conditional on continued execution. Each later invocation is reached only if preceding invocations return and execution proceeds normally.

The argument values are not collected as an entry-time snapshot. The offset-8 value is obtained after the first invocation returns. The offset-0 value and external datum are obtained after both earlier invocations return. Consequently, a dependency’s changes to later argument storage can affect the values subsequently supplied.

The relative observation order of the offset-0 field and the external datum is not established. Their argument positions are established: the selected-object value is first, and the external datum is second.

A zero value in any of the three argument fields does not suppress the corresponding invocation. Whether a dependency accepts zero is a separate, unavailable contract.

The final invocation uses the retained selected address, not a new value from the input slot. It is annotated as nonreturning. The annotation establishes a static expectation, not an observed termination mechanism.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not runtime results. Unless otherwise stated, accesses are valid, arithmetic is representable, and dependencies return whenever continuation is required.

### Empty input contents

For a readable slot containing zero, the result is the input slot address. There is no object-field access, field write, or dependency invocation.

This criterion does not apply to a null or unreadable slot address.

### Decrement without activation

For an initially selected object whose offset-28 field contains 2, that field becomes 1. The function returns the input slot address without a second slot observation or a dependency invocation.

For an initial field of zero, the corresponding result is −1, with the same absence of selection and dependency processing. Treating the original zero as a cleanup trigger would violate the established condition.

### Activation with empty selection

For an initial field of 1, the update stores zero. If the fresh slot observation then supplies zero, there are no dependency invocations and the input slot address is returned.

This example presupposes a valid explanation for the different slot observations. It does not authorize otherwise invalid concurrent access.

### Activation with the same object selected

For an initial field of 1 and a fresh slot observation supplying the same nonzero address, the updated field is already zero when the first dependency begins.

Subject to continued execution, the dependency arguments come from offsets 24, 8, and 0 in the required call order, with the external datum accompanying the offset-0 value. The final dependency receives that object’s address. An ordinary return after the final invocation is not an established expectation.

### Different object selected

If the initial observation identifies object A, A’s field becomes zero, and the fresh observation identifies nonzero object B, only A receives the decrement.

The dependency argument fields are read from B, and the final dependency receives B’s address. B’s offset-28 field is not decremented merely because B was selected.

### Mutations during dependency processing

If the first F-58ba61416cc9 invocation changes the selected object’s offset-8 field and returns, the second invocation receives the changed value, provided the storage remains readable.

If either earlier invocation changes the offset-0 field or external datum, F-56c3b4c706c6 uses values obtained after those earlier invocations. This criterion does not impose a relative read order between its two inputs.

If a dependency changes only the input slot, later processing still uses the retained selection, assuming that selected storage remains valid.

### Zero arguments and interrupted continuation

A zero offset-24 field is passed to F-58ba61416cc9 rather than filtered locally. The dependency’s acceptance of that value remains **documented_only**.

If the first invocation does not return, the offset-8 read and all later invocations are not reached through ordinary continuation. The decrement has already occurred, and no local rollback is established.
