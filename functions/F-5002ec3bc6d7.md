## Behavior

### 1. Initial selector read and byte store

The function first reads an unsigned byte from state base plus one.

It adds `0x11` to that selector and writes one byte to the resulting address. The stored byte is the low eight bits of the payload word.

For example, a payload word ending in hexadecimal `AB` produces a stored byte of `0xAB`, regardless of its higher bits.

The selector read precedes the store. No dependency call is shown before this first store.

### 2. First dependency call

After the initial store, the function invokes **F-U01**. Its target is derived from the implicit initial call base plus `0xFEC`.

Four arguments are visibly supplied, in this order:

1. The second explicit input shifted left by three positions.
2. The same shifted value.
3. The second explicit input unchanged.
4. The first explicit input unchanged.

The two shifted arguments are equal in the visible expression. No separate evaluation with dependency effects between them is shown.

No result from F-U01 is visibly consumed.

Under a 32-bit bit-vector interpretation, each shifted argument is the second input multiplied by eight modulo \(2^{32}\). That interpretation is not evidence that all values are valid under a signed source-language shift rule.

### 3. Four further calls

Assuming preceding calls return, the function next invokes:

1. **F-U02**
2. **F-U03**
3. **F-U04**
4. **F-U05**

No explicit arguments are shown for these calls. That observation does not establish that the underlying calling convention has no additional register or stack inputs.

The result of F-U05 is retained as a represented 32-bit integer and subsequently used. Results of F-U02 through F-U04 are not visibly consumed.

At this point, five dependency calls have occurred, including F-U01.

### 4. Second selector read and byte store

After F-U05 returns, the function reads the selector byte again from state base plus one. It does not visibly reuse the earlier selector value.

The function adds `0x11` to this newly read selector and writes one byte to that address. The stored value consists of bits 22 through 29 of the payload word:

\[

=
\left(\text{payload word} \mathbin{\text{logical right shift}} 22\right)

Bits 30 and 31 do not contribute to the stored byte. The shift leaves ten potentially significant bits, but the byte store retains only the low eight of those bits.

Because the selector is read again after five dependency calls, the second destination need not equal the first. The dependencies must not be assumed to preserve the selector memory.

The two accesses use the same represented implicit state base and payload word. Whether the recovered representation faithfully preserves those values across the calls is not independently established.

### 5. Sixth dependency call

After the second byte store, the function invokes **F-U06** with one visible argument: the F-U05 result shifted left by two positions.

Under a 32-bit bit-vector interpretation, this argument is four times that result modulo \(2^{32}\). The signedness and overflow caveat for the earlier left shift also applies here.

The result of F-U06 is not visibly consumed.

2. **F-U08**

4. **F-U10**

No explicit arguments or consumed results are shown.

The complete visible call order is therefore F-U01 through F-U10, with the second byte store between F-U05 and F-U06.
