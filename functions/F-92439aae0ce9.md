# F-92439aae0ce9

## Purpose

F-92439aae0ce9 transfers selected fields from a source storage region to a destination storage region. It relocates two 16-bit values and five individual bytes. One destination byte is conditionally replaced with the result of adding four to a retained character value.

The established behavior is an ordered series of memory accesses, not an atomic conversion of an entry-state record. Earlier destination writes can affect later source reads when the regions overlap.

Field meanings are unknown. A compact-record transformation is plausible inferred intent, but no record schema, units, or higher-level interpretation are established.

## Interface

### Inputs and output

The function receives two addresses:

- **S:** source address.
- **D:** destination address.

All offsets in this contract are byte offsets. The supplied pointer representation uses 16-bit elements, but several accesses operate on individual 8-bit storage units.

There is no explicit return value, success indicator, or error result. Observable output consists of memory writes and any consequences of those writes for overlapping storage.

## Behavior

### Ordered transfers

For a normal execution, accesses occur in the following order. Each source read samples memory when that read occurs, not necessarily as it existed at entry.

1. Read the 16-bit value at S+0 and write that value at D+2.
2. Read the 16-bit value at S+4 and write that value at D+0.
3. Read the byte at S+8 and write it at D+6.
4. Read the byte at S+9 and write it at D+5.
5. Read the byte at S+10 and write it at D+4.
6. Read and retain the character value at S+6. Write that retained value at D+7.
7. Read and retain the character value at S+7. Write that retained value at D+11.
8. Compare the retained S+7 character value with zero. If it is nonzero, add four to the integer-promoted retained S+6 character value, convert the result back to the character type, and write the converted result at D+7. If it is zero, perform no additional write.

The condition uses the retained S+7 sample. It does not reread S+7 or inspect D+11.

The adjustment uses the retained S+6 sample. It does not reread S+6 or increment the current contents of D+7.

The preliminary write to D+7 occurs even when adjustment is enabled. Consequently, an implementation that performs only the final D+7 write is not equivalent for all observable memory arrangements.

### Result when writes do not affect source reads

When destination writes cannot alter any later source read, the final destination layout on normal completion is:

| Destination offsets | Result |
|---|---|
| 0–1 | The 16-bit value read from source offsets 4–5 |
| 2–3 | The 16-bit value read from source offsets 0–1 |
| 4 | Source byte 10 |
| 5 | Source byte 9 |
| 6 | Source byte 8 |
| 7 | Retained source character 6, or its adjusted and narrowed result |
| 8–10 | No explicit write |
| 11 | Retained source character 7 |

The source character at offset 7 selects whether adjustment occurs.

The 16-bit transfers contain no explicit byte reversal. Their numerical values are preserved by the corresponding reads and writes. On a target using the same ordinary two-byte representation at both addresses, their byte representations are preserved as well. A particular byte order is not independently established.

### Conditional arithmetic and narrowing

The adjustment is **not established as unconditional modulo-256 arithmetic**.

The retained character is first subject to integer promotion. Four is added in the promoted integer type. The result is then converted back to the character type for storage.

The supplied material does not establish whether the character type is signed or unsigned:

- With an unsigned 8-bit character type, conversion back to that type yields the result modulo 256.
- With a signed 8-bit character type, an intermediate result within that type’s range is representable without an out-of-range narrowing issue.
- With a signed character type, conversion of an out-of-range intermediate result is implementation-defined. Eight-bit storage alone does not determine the resulting byte or establish low-eight-bit wrapping.

For example, a retained character value of 126 becomes the promoted integer value 130 after addition. That result fits an unsigned 8-bit character type, but not a signed 8-bit character type whose maximum is 127. A final byte of hexadecimal 82 therefore requires suitable target narrowing semantics; it is not an unconditional requirement of the supplied representation.

By contrast, retained character values 80 and 96 become 84 and 100 respectively. Those sums fit both conventional signed and unsigned 8-bit character ranges.

The explicit write remains one byte wide. The function contains no operation that propagates an arithmetic carry to D+8, and no explicit overflow report or saturation logic. This does not resolve the target’s out-of-range character-conversion behavior.

The condition compares the retained character’s value with zero. It does not test one particular flag bit or require a value of one. Mapping a raw byte representation to a character value remains subject to the target’s character representation.

### Overlap

No overlap check or whole-source snapshot is present. Exact equality of S and D is not equivalent to transforming a saved entry-state record.

Partial overlap must follow the same ordered accesses. Earlier destination writes may change either a later transferred value or a later condition sample. Once the two character samples have been retained, subsequent changes to their source addresses do not replace those retained values.

## Side effects

All explicit stores are destination-relative. There is no separate source-relative store, but overlapping destination storage can also be source-addressed storage.

Before the conditional branch, the function performs two 16-bit stores and five 8-bit stores. A nonzero condition leads to the additional character conversion and, if it completes normally, another 8-bit store at D+7.

For ordinary memory, destination offsets 8–10 are untouched. No explicit access extends beyond destination offset 11. These footprint statements do not establish device-register behavior or other effects of exceptional memory mappings.

There are no explicit calls, global-state accesses, callbacks, logging operations, allocation operations, or release operations.

There is no explicit failure path for null addresses, insufficient storage, unsupported alignment, prohibited writes, or invalid address formation. Platform behavior for such cases is outside the established contract. Earlier writes are not rolled back if a later access fails.

Likewise, no recovery path is supplied for target-specific exceptional behavior during character conversion. The evidence does not establish that such conversion behavior is always an ordinary wrapping store.

No synchronization is explicit. Stable ordinary memory, or external coordination sufficient to make the accesses deterministic, is a precondition for the examples below. Concurrent modification and device-memory semantics are unresolved.

## Acceptance examples

These are conditional acceptance criteria derived from static inspection. They are not runtime test results.

### Disjoint storage, no adjustment

Assume ordinary disjoint storage, valid alignment and addressing, a conventional character representation, and the same ordinary two-byte representation for both 16-bit transfers.

Let the source contain:

| Source offsets | Hexadecimal bytes |
|---|---|
| 0–1 | 10 20 |
| 4–5 | 30 40 |
| 6–10 | 50 00 60 70 80 |

After normal completion:

- Destination offsets 0–7 contain **30 40 10 20 80 70 60 50**.
- Destination offset 11 contains **00**.
- Destination offsets 8–10 retain their previous contents.

The zero character at source offset 7 disables adjustment.

### Nonzero condition, representable adjustment

Use the preceding disjoint-storage example, but change source byte 7 to **80**. Assume that representation denotes a nonzero character value, as it does for ordinary unsigned or two’s-complement signed 8-bit characters.

Then:

- Destination offset 11 contains **80**.
- Destination offset 7 contains **54**.
- All other listed destination results remain unchanged.

The adjusted source character is hexadecimal 50, or decimal 80. Adding four gives decimal 84, which fits either conventional signed or unsigned 8-bit character storage. This example does not depend on out-of-range narrowing.

### Signed-range boundary

Assume disjoint storage, source byte 6 equal to **7E**, and source byte 7 equal to **01**.

The retained character value is 126 under conventional signed and unsigned interpretations. The promoted sum is 130.

- For an unsigned 8-bit character target, destination byte 7 must become **82**.
- For a signed 8-bit character target with low-eight-bit narrowing, destination byte 7 also becomes **82**.
- For a signed 8-bit character target whose out-of-range narrowing rule is unknown, the final result at destination byte 7 is **documented_only**. The supplied material does not justify requiring **82**.

Destination byte 11 receives **01** before the adjustment is attempted. No explicit write targets destination byte 8.

### Wraparound under an explicit target rule

Assume disjoint storage, source byte 6 equal to **FE**, source byte 7 equal to **01**, and target semantics that retain the low eight bits of the adjusted result.

Destination byte 7 finishes as **02**, and destination byte 11 contains **01**.

This is a conditional wrapping example, not proof of a universal narrowing rule. On a conventional two’s-complement signed-character target, **FE** instead denotes −2, whose adjusted value 2 is representable; that interpretation also produces **02** without out-of-range conversion.

### Exact overlap

Assume S and D designate the same ordinary writable region, with valid storage through offset 11. Use the bytes from the first example.

After normal completion:

- Offsets 0–7 contain **30 40 10 20 80 70 60 64**.
- Offset 11 contains **60**.
- Offsets 8–10 remain **60 70 80**.

The earlier transfer from offset 8 writes **60** at offset 6. That newly written value is subsequently retained and written at offset 7. The condition sample therefore reads **60**, not the entry-state **00**.

Adjustment produces decimal 100, hexadecimal **64**, which fits conventional signed and unsigned 8-bit character types.

### Retained-value requirement

For any supported arrangement where an intervening destination write changes S+6 after its character value has been retained, the later adjustment must still use the retained value.

An implementation that rereads S+6 for adjustment does not satisfy the established behavior. This requirement does not remove the separate need to apply the target’s actual narrowing rule.
