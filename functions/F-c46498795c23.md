# F-c46498795c23

## Purpose

F-c46498795c23 replaces an association stored in a primary object, copies association-related metadata, and conditionally updates a four-word geometry record and a one-byte comparison flag.

Its established effects are:

- Conditionally notify the previous associated object.
- Perform two initialization calls when the incoming association is nonnull and an initialization gate is zero.
- Replace two metadata bytes and the stored association.
- Notify the incoming association, including when it is null.
- Publish the original incoming association through a nested object.
- Process geometry from the association present after notification.
- Set a flag according to whether a comparison dependency returns zero.

“Association,” “initialization,” and “geometry” describe inferred roles. They do not establish ownership transfer, reference counting, allocation, destruction, intersection semantics, or the meaning of a comparison result.

## Behavior

### Previous-association notification

The function first reads the current association at primary `0xAE0`. If it is nonzero, it also reads the alternate association at `0xAE4`.

F-ff03c5cac423 is called with the old association and zero exactly when the old association is nonzero and differs from both the alternate association and the original incoming association.

Equality with either suppresses this old-association call. The decision uses the initially captured old association; the field is not re-read to reconsider it.

Subsequent handling continues after a normally returning call. Changes made by that dependency can affect later object reads.

### Initialization and metadata

For null input, the function writes `0xFF` to primary `0x9F6` and selects `0xFF` for the later write to `0x9F7`. It does not read the initialization gate on this path.

For nonnull input, it reads primary byte `0xB52`. A zero value selects initialization:

1. Capture the incoming word at `0x94`, retaining only its low 16 bits.
2. Capture the incoming word at `0x98`, retaining only its low 16 bits.
3. Place the masked second extent in temporary storage and call F-ed68d7fa19d3 with primary, zero, zero, and the masked first extent.
4. Place the captured masked second extent in that temporary storage again and call F-df1570496abe with the same four visible argument values.
5. Write one to primary `0xB52`.

The masked values are zero-extended into 32-bit unsigned values. Both are captured before the first initialization call. Neither dimension is re-read for the second call, and the gate is not rechecked between calls.

The second masked extent’s externally observable purpose is unresolved. Its placement in temporary storage does not justify inventing a fifth argument.

After any initialization calls, nonnull input causes:

- A read of incoming byte `0x64`, followed by its write to primary `0x9F6`.
- A read of incoming byte `0x65`, selected for the next write.

For both null and nonnull input, the selected second byte is then written to primary `0x9F7`. Initialization dependencies can therefore affect the metadata subsequently read.

### Association publication and re-read

After both metadata writes, the function:

1. Stores the original incoming association at primary `0xAE0`.
2. Calls F-ff03c5cac423 with that incoming association and the primary object.
3. Reads the nested-object pointer from primary `0xA8C`.
4. Stores the original incoming association at nested offset `0x34`.
5. Re-reads primary `0xAE0`.

The notification is unconditional, including for null input. It occurs before the nested-pointer read, so it can change which nested object receives the publication.

The value written into the nested object remains the original incoming argument. Geometry instead uses the association obtained by the subsequent re-read. Those values may differ.

If the re-read association is zero, the function performs no subsequent direct writes to geometry or the comparison flag. Thus null input can enter geometry processing if notification installs an association, and nonnull input can skip it if notification clears the field.

The geometry association is captured by this re-read. Later geometry calls do not cause another lookup of primary `0xAE0`.

### Direct geometry mode

With a nonnull re-read association, the function reads primary byte `0x130`. If zero, it copies the associated geometry to the primary output fields.

The established access order is:

1. Read associated words at `0x90`, `0x94`, and `0x98`, in that order.
2. Read associated word `0x8C` and write it to primary `0x9B0`.
3. Write the three captured words to primary `0x9B4`, `0x9B8`, and `0x9BC`, respectively.

This is not an atomic record copy. Aliasing can make the read-before-write order observable.

The later comparison receives the associated object’s geometry address at `0x8C`, not the primary output address.

### Dependency-based geometry mode

A nonzero mode byte selects address-based coordinate and endpoint processing.

First, F-a836bb8e1d17 is called twice:

- Associated first-coordinate address, then primary first-reference-coordinate address.
- Associated second-coordinate address, then primary second-reference-coordinate address.

Their 32-bit results are retained as the first and second output coordinates.

Endpoint processing then uses two distinct 32-bit temporary storage locations. For clarity, these are called **endpoint slot A** and **endpoint slot B**; these names describe storage identity, not additional interface fields.

The first-axis processing is:

- Store associated first coordinate plus associated first extent in slot A.
- Store primary first reference coordinate plus first reference extent in slot B.
- Call F-7e1b17cbc42a with the address of slot A first and the address of slot B second.
- Retain its 32-bit result as the first endpoint result.

The second-axis processing reuses those same locations in this exact overwrite order:

- Overwrite slot B with associated second coordinate plus associated second extent.
- Overwrite slot A with primary second reference coordinate plus second reference extent.
- Call F-7e1b17cbc42a with the address of slot B first and the address of slot A second.

Consequently, the second endpoint call receives the same two addresses as the first call, but in reversed argument positions. There are not four independent endpoint temporaries.

This identity relationship is observable to a dependency that retains operand pointers between calls. A pointer retained from the first call’s first argument identifies the second call’s second operand; a pointer retained from the first call’s second argument identifies the second call’s first operand. Both values have been overwritten before the second call begins.

The two coordinate calls complete before the endpoint sums are formed. Endpoint reads may therefore observe mutations made by those calls. The first endpoint call likewise precedes the reads used to construct second-axis endpoints. The static representation establishes the order of the sum assignments, but not a separately sequenced order between the two operand reads within an individual addition.

The second output extent is the second endpoint result minus the saved second-coordinate result. The first output extent is the first endpoint result minus the saved first-coordinate result. The second subtraction occurs before the first.

The function then writes:

1. First extent to primary `0x9B8`.
2. Second extent to primary `0x9BC`.
3. First coordinate to primary `0x9B0`.
4. Second coordinate to primary `0x9B4`.

A separate temporary comparison record contains the saved coordinates and derived extents in four consecutive 32-bit words. Its extent words are prepared before the primary geometry writes; its coordinate words are filled after those writes. The endpoint slots are not this four-word comparison record.

No clamp, empty-record normalization, widening, or overflow check is visible. Exact overflow behavior is unresolved.

### Comparison flag

After either geometry mode, F-b8d1b6b67fb7 receives:

- The associated geometry address in direct mode, or the temporary four-word record in dependency-based mode.
- Primary address plus `0x108`.

After it returns, zero causes a one-byte write of one to primary `0x9AC`; any nonzero result causes a one-byte write of zero.

## Side effects

Direct effects include metadata replacement, association replacement, nested publication, and conditional writes to the initialization gate, geometry, and comparison flag.

Effects are sequential rather than transactional. Incoming notification occurs after metadata and association writes but before nested publication. Geometry is written before comparison, and the flag is written after comparison returns. A fault or nonreturning dependency can leave a completed prefix of these effects.

Repeated association with the same object still performs metadata handling, incoming notification, nested publication, and selected geometry work. Equality suppresses only the old-association notification.

Null input does not directly clear geometry, clear the flag, or reset the initialization gate.

No visible allocation, deallocation, ownership-transfer operation, rollback, synchronization, or explicit error reporting is established. Dependencies may have additional effects; preservation of globals, pointed-to storage, or object lifetimes must not be assumed.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

### Null input without an installed replacement

Assume incoming notification leaves primary `0xAE0` zero.

Both metadata bytes become `0xFF`; initialization calls are skipped. Incoming notification still receives zero and the primary object. Nested offset `0x34` receives zero. No subsequent direct geometry or flag write occurs.

### Old-notification selection

For a nonzero old association:

- Equality with the incoming association suppresses old notification.
- Equality with the alternate association also suppresses it.
- Difference from both requires old notification before metadata handling.

Incoming notification remains required in all cases.

### Masked initialization dimensions

Assume a zero gate and incoming extent words `0x12345678` and `0xFFFF8001`.

Both initialization calls visibly receive `0x00005678` as their fourth argument. The second captured dimension is `0x00008001`, without sign extension; its use as another argument is not established. If both calls return normally, the function writes one to the gate.

### Direct copying and flag mapping

Assume nonaliasing storage, direct mode, and stable associated geometry `(10, 20, 30, 40)`.

The output becomes `(10, 20, 30, 40)`. Comparison receives the associated geometry address. A zero comparison result yields flag one; a result of seven yields flag zero.

### Endpoint address reuse

Assume dependency-based mode, associated geometry `(10, 20, 30, 40)`, reference geometry `(15, 7, 20, 18)`, and dependencies that do not alter source geometry.

At the first endpoint call, slot A contains `40` and slot B contains `35`; argument order is A, B.

After that call, slot B is overwritten with `60`, then slot A with `25`. The second call’s argument order is B, A. A pointer retained from the first argument of the first call now addresses `25`, not `40`.

### Conditional intersection-like result

Assume separately established dependencies select the larger coordinate and smaller endpoint without modifying operands.

For associated geometry `(10, 20, 30, 40)` and reference geometry `(15, 10, 20, 25)`, the derived record is `(15, 20, 20, 15)`. This outcome is conditional on those dependency semantics, not required by their opaque identities.

### Notification changes the association

If incoming notification installs another valid association, nested publication still uses the original incoming argument. Geometry uses the installed replacement. If notification clears the association instead, geometry and comparison are skipped.
