# F-4e6f05c1f539

## Purpose

It invokes F-5ef10d079522 with two values derived from an input record, an address two bytes into an output region, the address of a mutable local 32-bit value, and a value obtained from global storage. After that dependency returns normally, it encodes selected bits of the local value into the first two bytes of the output region.

The established behavior is this forwarding and encoding sequence. The available evidence does not establish the application-level meaning of the record, output region, global value, or mutable value. In particular, interpreting the final field as a length, count, or status would be inferred intent, not an established contract.

### Final output field

After the dependency returns normally, the function uses the local object’s current value to construct a 16-bit field and stores it at the original output address.

Under the 32-bit bit-vector interpretation of the supplied shift expression:

- Original bit 0 of the local value is discarded.
- Original bits 1 through 16 become output bits 0 through 15, respectively.
- Original bits 17 through 31 do not contribute.
- The resulting 16 bits replace the entire initial two-byte output field.

This is not a saturating conversion and does not preserve all high-order information. Values differing only in discarded bits produce the same final field.

For a 32-bit pattern \(x\), the resulting unsigned field is:

\[
\left\lfloor
\frac{x \bmod 131072}{2}
\right\rfloor
\]

Here \(x\) denotes the unsigned interpretation of the pattern, not a claim that the local object is declared unsigned.

The supplied expression performs a signed left shift before conversion to an unsigned value and a logical right shift. Literal source-language semantics do not provide a portable result for every possible signed input, including negative operands and some overflowing shifts. Consequently, the bit-selection rule above is a conditional description of the intended 32-bit shift behavior, not proof that every such input has defined behavior in every source-language execution model.

No local validation, clamping, range rejection, or alternate result is visible.

### Ordering and aliasing

The final two-byte write occurs after the dependency returns. It therefore supersedes any earlier dependency write to those same bytes, if such a write occurs and execution otherwise remains valid.

The dependency is passed the address two bytes beyond the beginning of the output region. That address alone does not prove that the dependency confines its accesses to later bytes. Its memory-access boundaries remain unknown.

No non-aliasing condition is supplied for the input and output addresses. If the regions overlap, the two record values used for the call have already been read before the dependency begins. The final write can nevertheless overwrite bytes belonging to the input record. The function does not reread either record field after the dependency returns.

The global argument is likewise obtained before dependency entry. A dependency mutation of that global does not retroactively change the value already passed, but the wrapper provides no restoration of global state.

These are conditional acceptance criteria derived from static evidence, not reports of runtime tests. Numeric encoding examples assume ordinary 32-bit bit-vector shift behavior and valid memory.

2. **Initial local value.** If the fourth argument is 10, the local object initially contains 10. If the dependency leaves it unchanged and returns normally, the final field has unsigned value 5.

3. **Dependency update controls the result.** If the fourth argument is 10 but the dependency changes the local object to 14, the final field is 7, not 5.

5. **Upper field bit.** A post-dependency local value of 65,536 produces unsigned field value 32,768. The field is not limited to 15 meaningful bits.

6. **Discarded high bits.** Local values 0 and 131,072 both produce field value 0. These cases also avoid relying on a negative signed-shift operand.

7. **Negative pattern, conditionally.** If the final local pattern is all ones, the bit-vector interpretation produces field value 65,535. This example does not establish portable signed-shift behavior for a negative operand.

8. **Final-write precedence.** If the dependency writes a temporary value into the initial two output bytes, then returns normally with the local value equal to 8, the wrapper replaces those bytes with field value 4.

9. **Unused argument.** Changing only the third argument does not change any explicitly specified read, dependency argument, or final-write calculation.
