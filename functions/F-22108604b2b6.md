## Acceptance examples

These are conditional predictions from static evidence, not executed tests. Each assumes the relevant prefix is reached, required accesses succeed, and arithmetic has the stated interpretation.

### Zero result exposes immediate store/read aliasing

If I5 is zero, both its word address and slot address are 20.

The routine stores a zero four-byte value there and immediately reads W from the same location. For stable ordinary memory without external interference, W is zero. The later four-byte store at slot address(I6) consequently writes zero.

### Nonzero result distinguishes the two address formulas

If I5 is 3, the routine stores 12 at address 68 and reads W from address 32.

If the read yields hexadecimal **ABCDEF01**, the later shifted store writes hexadecimal **000ABCDE** at slot address(I6). Reading address 68 instead would not satisfy the visible behavior.

### Byte truncation remains separate from word stores

If I9 is hexadecimal **0ABCDEF1**, the first byte store writes hexadecimal **C4**. The second writes hexadecimal **AB**.

Both are one-byte writes. Neither adds another four-byte store to the nine-store total.

### Changed lookup values change destinations

Suppose the first lookup returns 5 and the second returns 200.

The first byte destination is address 22; the second is address 217. F-D058 receives 200 as its second explicit argument, regardless of the byte written at address 217.

### The masked argument uses the scaled result

Considering F-D036’s first argument alone, if I6 is 3, its scaled value is 12 and the first argument is 196,608.

Using I6’s unscaled low bits would produce 49,152 and would not match the expression. This example does not establish the outcome of the separate signed shift of I6 by 30.

### A byte store can affect the later lookup

If I6 is zero, the lookup address is 1. The byte-derived destinations remain between 17 and 272, so neither byte store aliases address 1.

That separation follows for this particular value only. It is not a general non-aliasing guarantee for other lookup addresses or for the four-byte stores.

### Failure preserves no rollback guarantee

If the entry store and an early calculated store complete, but a subsequent dependency never returns, those stores have already occurred. Acceptance must not require restoration, later calls, or a status return.
