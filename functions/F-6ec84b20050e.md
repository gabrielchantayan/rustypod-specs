# F-6ec84b20050e

## Purpose

F-6ec84b20050e conditionally issues four rectangle operations against a caller-supplied state object. The rectangles correspond to the left, right, top, and bottom strips of an input rectangle, using a common 32-bit thickness value.

The established behavior is an ordered sequence of dependency calls and temporary-record updates. Interpreting those calls as drawing a border is **inferred intent**, not an established rendering guarantee. The supplied evidence does not establish whether the rectangle operation draws, fills, clips, accumulates, or performs another action.

The function performs no dependency calls unless:

- The first 32-bit word of the state object is nonzero.
- The input rectangle’s fourth coordinate is strictly greater than its second coordinate under signed 32-bit comparison.
- The input rectangle’s third coordinate is strictly greater than its first coordinate under signed 32-bit comparison.

There is no thickness validation and no explicit result value.

## Interface

The function accepts five arguments:

| Argument | Established representation | Role |
|---|---|---|
| State object | Pointer to storage whose first element is a 32-bit integer | Supplies the initial enablement condition and is passed to every dependency |
| Rectangle | Pointer to four consecutive 32-bit integer fields | Supplies rectangle coordinates |
| Thickness | 32-bit integer | Added to or subtracted from selected coordinates |
| Opaque argument A | 32-bit value | Forwarded unchanged to each rectangle-operation call |
| Opaque argument B | 32-bit value | Forwarded unchanged to each rectangle-operation call |

The rectangle layout is:

| Byte offset | Contract name | Established use |
|---|---|---|
| 0 | Left | First coordinate |
| 4 | Top | Second coordinate |
| 8 | Right | Third coordinate |
| 12 | Bottom | Fourth coordinate |

“Left,” “top,” “right,” and “bottom” describe the apparent coordinate roles. Coordinate units, axis orientation, inclusive or exclusive endpoint conventions, and rendering interpretation are not established.

The function has no explicit return value. It provides no direct success indication, error code, or count of completed operations.

### Storage and lifetime requirements

The state pointer must support the initial 32-bit read. A null or otherwise unreadable state pointer is not explicitly checked.

If the initial state word is nonzero, the rectangle must support reads of its bottom and top fields. If those fields pass the vertical comparison, its right and left fields must also be readable. On the active path, additional rectangle reads occur after dependency calls.

The state object must also satisfy the requirements of the dependencies that receive it. Those requirements are unknown.

The function passes a pointer to a temporary, contiguous four-word rectangle record to each rectangle operation. This is the same temporary record reused across all four calls, not four separately allocated records. The supplied evidence establishes no ownership transfer. Safe retention or asynchronous use of that pointer is not established.

No non-aliasing requirement between caller-supplied objects is shown. Aliasing matters because dependencies receive the state pointer and the function subsequently rereads the rectangle.

## Behavior

### 1. Initial eligibility checks

The first observable memory read is the state object’s first 32-bit word.

If that word is zero, the function returns without reading the rectangle and without calling any dependency. A valid rectangle is therefore not required by the visible execution path in this case, although the state read itself must remain valid.

If the state word is nonzero, the function reads:

1. The rectangle’s bottom field.
2. The rectangle’s top field.

It checks whether bottom is strictly greater than top using signed 32-bit comparison semantics. The subtraction-related overflow information in the supplied evidence is part of implementing that comparison; it must not be simplified to testing only the sign of a wrapped difference.

If bottom is equal to or less than top, the function returns. The left and right fields are not read on this rejection path.

If bottom is strictly greater than top, the function next reads:

1. The rectangle’s right field.
2. The rectangle’s left field.

It checks whether right is strictly greater than left using signed 32-bit comparison semantics.

If right is equal to or less than left, the function returns without dependency calls.

Consequently, an enabled state and strictly increasing coordinates in both dimensions are necessary and sufficient to enter the visible call sequence, assuming the reads complete normally. The function does not compute a validated positive width or height for subsequent use.

### 2. Enter the active sequence

After the eligibility checks succeed, the function calls **F-42388505f940**, passing the state pointer.

No temporary rectangle fields have yet been populated for a rectangle-operation call. The input rectangle is read again after this dependency returns. The function therefore does not guarantee that emitted coordinates match the values used for eligibility.

The state word is not explicitly rechecked after this call or between subsequent calls.

### 3. First rectangle operation

After F-42388505f940 returns, the function populates the temporary record in this order:

1. Reads input left and writes temporary left.
2. Reads input top and writes temporary top.
3. Reads input bottom and writes temporary bottom.
4. Rereads input left, adds thickness, and writes temporary right.

It then calls **F-0f96ced27a09** with:

- The state pointer.
- The temporary rectangle pointer.
- Opaque argument A.
- Opaque argument B.

If the input remains unchanged throughout these reads, the requested rectangle is:

**(left, top, left + thickness, bottom)**.

The two left reads are distinct. The function does not expressly guarantee that temporary left and the base used for temporary right come from the same input value.

### 4. Second rectangle operation

After the first rectangle operation returns, the function:

1. Reads input right, subtracts thickness, and writes temporary left.
2. Rereads input right and writes temporary right.

It does not rewrite temporary top or temporary bottom before calling **F-0f96ced27a09** again with the same argument structure.

If the dependency has not modified the temporary record, and the input remains stable, this rectangle is:

**(right − thickness, top, right, bottom)**.

More generally, its top and bottom are the values present in the temporary record after the first rectangle operation returns. The supplied evidence does not establish that the dependency preserves them.

### 5. Third rectangle operation

After the second rectangle operation returns, the function overwrites all four temporary fields in this order:

1. Reads input left and writes temporary left.
2. Reads input top and writes temporary top.
3. Reads input right and writes temporary right.
4. Rereads input top, adds thickness, and writes temporary bottom.

It calls **F-0f96ced27a09** a third time.

For stable input, this rectangle is:

**(left, top, right, top + thickness)**.

Because all four fields are rewritten, changes made to the temporary record during the preceding rectangle call do not directly survive into this call. Changes to the input rectangle can still affect the newly read coordinates.

### 6. Fourth rectangle operation

After the third rectangle operation returns, the function:

1. Reads input bottom, subtracts thickness, and writes temporary top.
2. Rereads input bottom and writes temporary bottom.

It does not rewrite temporary left or temporary right before calling **F-0f96ced27a09** a fourth time.

If the preceding dependency preserves the temporary record and input is stable, this rectangle is:

**(left, bottom − thickness, right, bottom)**.

Without that preservation assumption, left and right are whatever values remain in the temporary record when the third rectangle operation returns.

### 7. Leave the active sequence

After the fourth rectangle operation returns, the function calls **F-d9bb88a0a8d3** with the state pointer, then returns.

The visible successful call order is therefore:

1. F-42388505f940.
2. Four calls to F-0f96ced27a09.
3. F-d9bb88a0a8d3.

This ordering assumes each dependency returns normally. The function contains no visible recovery or compensating action for an interrupted sequence.

- Thickness exceeding a dimension can produce overlapping strips or coordinates outside the input rectangle.
- No clipping, merging, deduplication, or overlap avoidance is visible.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless otherwise stated, arithmetic is representable, dependencies return normally, input remains stable, and rectangle operations do not modify the temporary record.

### Disabled state

Given a readable state word equal to zero:

- The function returns.
- No rectangle field is read.
- No dependency is called.

This remains the visible path even if the rectangle pointer would not support a read.

### Ordinary active case

1. F-42388505f940.
2. F-0f96ced27a09 with **(10, 20, 13, 80)**.
3. F-0f96ced27a09 with **(47, 20, 50, 80)**.

- Rectangle **(10, 30, 50, 20)** is also rejected at that stage.
- Rectangle **(10, 20, 10, 80)** passes the vertical check but fails the horizontal check.

### Zero thickness

For rectangle **(10, 20, 50, 80)** and thickness **0**, all four rectangle operations still occur, using:

- **(10, 20, 10, 80)**.
- **(50, 20, 50, 80)**.
- **(10, 20, 50, 20)**.

Whether these degenerate rectangles have an external effect depends on F-0f96ced27a09.

### Negative thickness

- **(10, 20, 8, 80)**.
- **(52, 20, 50, 80)**.

### Signed-comparison boundary

An enabled rectangle with left **−2,147,483,648**, right **2,147,483,647**, top **0**, and bottom **1** passes both dimension checks. A contract that rejects it merely because a 32-bit right-minus-left difference has a negative wrapped sign would be incorrect.

### Mutation between calls

If the first rectangle operation changes temporary top to **99**, and no other action changes it before the second rectangle call, the second call receives top **99**. The function does not reconstruct that field.

If F-42388505f940 changes the input rectangle, construction uses the post-call reads without repeating eligibility checks.
