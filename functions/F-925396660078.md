## Behavior

### First operation

The represented path derives an unsigned value from the incoming register-associated state by logically shifting it right by 11 bit positions.

Logical right shift discards the lowest 11 bits and introduces zeros at the high end. For an unsigned input \(x\), the resulting numeric value is:

\[
\left\lfloor \frac{x}{2048} \right\rfloor
\]

This description is conditional on the unsigned width supporting the represented shift, as it does under the conventional 32-bit interpretation.

Before issuing the first coprocessor-related operation, the representation assigns zero to the register-associated state used as the source of that shift. The already-derived shifted value remains the fourth operand of the first operation.

That ordering is significant:

1. The incoming value determines the first shifted operand.
2. The represented source state is set to zero.
3. The operation is issued with the previously derived operand.

The first operation does not necessarily receive zero merely because the source state has already been cleared.

The representation does not establish that this assignment is an externally observable write to a particular physical register. Its established role is a state update in the represented computation.

### Repetition

After the operation, control returns unconditionally to the repeated computation.

Within the represented dataflow, the source state is now zero. Shifting zero right by 11 yields zero, so the second and later operations receive zero in their fourth operand position. The source state is assigned zero again before each operation.

The constants in the first three positions do not change. The same two incoming opaque values are represented in the last two positions on every operation; there is no explicit refresh or reassignment of them.
