# F-bc5079bc5666

## Purpose

F-bc5079bc5666 combines two values represented by two unsigned words each and places a two-word result in caller-provided storage.

The representation places the low-order word first and the high-order word second. Under word-width unsigned arithmetic, the result is the sum of the two operands modulo the range of a two-word value. A carry from the low-order addition contributes to the high-order result; overflow beyond the high-order word is discarded.

The supplied material does not define the unsigned word type. Consequently, the exact bit width, byte size, and arithmetic-promotion rules remain unresolved. The ordinary multiword-addition interpretation is conditional on those rules, not an unconditional claim of 64-bit arithmetic.

No execution results are available. This contract distinguishes static observations from conditional arithmetic consequences and inferred intent.

Let the acquired first operand be **(a₀, a₁)** and the acquired second operand be **(b₀, b₁)**.

The destination’s low component is:

**(a₀ + b₀) modulo B.**

The high component receives:

**(a₁ + b₁ + c) modulo B,**

Equivalently, the destination represents the sum of the two input values modulo **B²**.

The low-word carry contribution has only two possible values: zero and one. Equal low operands are handled; equality does not leave the carry decision without a comparison reference.

There is no saturation. A high-word sum outside the word’s range is reduced to the representable unsigned result. No third word, overflow flag, or other output records the discarded overflow.

The unsigned destination representation alone is insufficient to establish every intermediate arithmetic rule. Conversion on storage and arithmetic during the carry decision are separate concerns.

In particular, the carry decision examines an intermediate low sum before the low destination assignment. If a narrower word type is promoted to a wider arithmetic type, that sum may not wrap at B. This is a conditional consequence of such an evaluation model, not a claim that the actual environment uses it.

### Update and overlap behavior

The high destination element is updated first. The low destination element is updated second, using the previously acquired low inputs.

This permits:

- Destination equal to the first operand.
- Destination equal to the second operand.
- Both inputs equal to each other.
- All three arguments equal.
- Other valid overlaps between input and destination elements.

Overlap does not change which acquired input values determine the result. It can, however, change input storage as a consequence of writing the destination.

The operation is not an atomic replacement of a two-word value. Between its two assignments, destination storage may contain the new high word and the previous low word. No coherent snapshot guarantee is provided to concurrent observers.
