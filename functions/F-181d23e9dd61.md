# F-181d23e9dd61

## Purpose

F-181d23e9dd61 writes a caller-supplied 32-bit value, with two control bits forced on, to a selector-dependent address. It then obtains a reference value from a dependency, reads a global offset cell, and polls two selector-dependent locations until one of three conditions ends polling:

- A status word has bit 1 set.
- A command/control word has bit 31 clear.
- A second dependency returns a nonzero result.

Every established normal return produces the 32-bit value `1`. The result does not distinguish which condition ended polling.

The fixed addresses, bit operations, and repeated reads suggest a hardware command-and-poll operation. That is inferred intent, not established device semantics. Neither the meaning of the bits nor the success or failure significance of the termination conditions is provided.

## Interface

The function accepts three 32-bit arguments and returns a 32-bit result.

| Input | Established treatment |
|---|---|
| First argument | Opaque 32-bit value. Not inspected, stored, or explicitly forwarded by the supplied body. |
| Selector | Unsigned 32-bit value. Bit 7 chooses an address arrangement and the number of global-offset reads. Bits 0–6 select an entry. Bits 8–31 do not affect the function’s explicit calculations or branches. |
| Value | Unsigned 32-bit value. Written after bitwise OR with `0x48000000`. |

The normal return is the bit pattern `0x00000001`. There is no established return carrying a status word, an error code, a timeout indicator, or the dependency result.

There are no explicit pointer parameters, caller-buffer parameters, or ownership-transfer parameters. The first argument’s unknown purpose does not establish that it is a pointer.

Normal execution requires that the selected storage support the accesses described below and that the dependencies return normally when called. The body performs no explicit address validation, selector rejection, exception recovery, or dependency-error reporting.

## Behavior

### Address selection and initial write

The fixed address base is `0x38400000`.

The entry index is the selector’s low seven bits, giving an index from 0 through 127. Its byte displacement is the index multiplied by `0x20`, ranging from `0x000` through `0xFE0`. This multiplication does not overflow a 32-bit integer.

The command/control address is the fixed base plus the entry displacement and the following bank offset:

| Selector bit 7 | Command/control bank offset |
|---|---:|
| Clear | `0xB00` |
| Set | `0x900` |

The first explicit external-state access is a 32-bit write to this command/control address. The written value is the third argument ORed with `0x48000000`.

This forces bits 30 and 27 to one and preserves every other input bit. In particular, it does not independently set or clear bit 31. This is not an explicit read-modify-write operation: the destination’s previous contents are not read before the write.

The possible command/control addresses are:

- Bit 7 clear: `0x38400B00` through `0x38401AE0`, in increments of `0x20`.
- Bit 7 set: `0x38400900` through `0x384018E0`, in increments of `0x20`.

These address sets overlap. Distinct selectors therefore need not designate distinct storage. The fixed-base command/control calculations remain within the stated nonwrapping range.

### Reference acquisition

After the initial write, the function calls F-D01 with no explicit arguments. Its 32-bit return value becomes a retained reference.

F-D01 is called exactly once on a normally progressing invocation, including invocations whose first polling read immediately satisfies a termination condition. The function does not inspect the reference before retaining it.

No evidence establishes that F-D01 preserves globals or the addressed storage. In particular, the global-offset reads occur after F-D01 returns, so changes made by that dependency can affect address selection.

### Global-offset reads and retention

After F-D01 returns, the function unconditionally reads the global 32-bit offset cell.

What follows depends on selector bit 7:

| Selector bit 7 | Required offset-cell reads | Offset used for polling |
|---|---|---|
| Set | One read | The value from that read |
| Clear | Two ordered reads of the same cell | The second value plus `0x200` |

For bit 7 clear, the first read still occurs. Its value is discarded; it is not the value to which `0x200` is added. The second read follows the first and precedes the first polling access. No dependency call occurs between these two reads.

The reads must not be collapsed into a single-read contract. The cell’s contents may change between reads, and reading the cell may itself have effects. Neither stability nor absence of read side effects is established.

The resulting offset is retained throughout polling. The function does not reread the global cell on later iterations. Later changes to the cell therefore do not select a new status address within that invocation, although they may have other effects.

The status address is the fixed base plus the retained offset plus the entry displacement.

The supplied evidence does not establish the global cell’s value or valid range. The cell is represented as a 32-bit integer offset, but that alone does not establish safe arithmetic for all possible bit patterns. In particular, neither the addition of `0x200` nor the subsequent address calculation is guaranteed to remain in range for an arbitrary cell value. Overflow handling, address wrapping, and accesses to unsuitable addresses remain unresolved; this contract does not assume modulo arithmetic makes them valid.

### Polling access order

Each iteration begins with one 32-bit read from the selected status address.

1. **Status bit 1 set:** the function immediately returns `1`. That iteration performs no command/control read and no F-D02 call.
2. **Status bit 1 clear:** the function reads one 32-bit word from the command/control address selected for the initial write.
3. **Command/control bit 31 clear:** the function ends polling and returns `1`. F-D02 is not called for that iteration.
4. **Command/control bit 31 set:** the function calls F-D02 with the retained 32-bit reference and the integer value `100`.
5. **F-D02 nonzero:** the function immediately returns `1`.
6. **F-D02 zero:** another iteration begins with a fresh status read.

Only status bit 1 and command/control bit 31 affect these polling decisions. Other bits in those reads are ignored locally.

F-D02’s zero-versus-nonzero result is the only result distinction used. A negative nonzero 32-bit result has the same local effect as a positive nonzero result.

The effective precedence is therefore status termination, then command/control termination, then dependency termination. This precedence controls which accesses and calls occur even though all normal paths return the same value.

The reference and selected status offset remain unchanged across iterations. The initial write is not repeated. Fresh polling reads can nevertheless observe changed storage, including changes caused by a dependency or an external actor.

### Termination and errors

There is no explicit iteration bound, sleep operation, or local timeout counter.

Polling may continue indefinitely if all status reads have bit 1 clear, all command/control reads have bit 31 set, and all F-D02 calls return zero. The literal `100` is a dependency argument, not an established iteration limit or duration.

Normal return is also not guaranteed when a dependency does not return or an access cannot complete. The body provides no explicit recovery path for those cases. It does not establish a distinct error result.

## Side effects

The direct external interactions, in order, are:

1. One 32-bit command/control write.
2. One F-D01 call.
3. One unconditional 32-bit read of the global offset cell.
4. For selector bit 7 clear only, a second 32-bit read of that same cell.
5. Polling reads and conditional F-D02 calls.

For a normal return after \(N\) polling iterations:

- Exactly \(N\) status reads occur.
- Each iteration performs at most one command/control read.
- A command/control read occurs only after a status read whose bit 1 is clear.
- F-D02 is called only after a command/control read whose bit 31 is set.
- The global offset cell is read once for bit 7 set and twice for bit 7 clear, regardless of the number of polling iterations.

No additional direct write, acknowledgement, cleanup, or restoration is shown. The function does not explicitly clear the command/control word on return.

The initial written value need not remain present. The supplied evidence does not constrain device behavior, concurrent mutation, or dependency changes to the addressed storage.

Read side effects are unresolved for both the global offset cell and the polling locations. A discarded first offset value does not make its read behaviorally irrelevant.

No explicit allocation, release, ownership transfer, or caller-buffer mutation appears in the body. This does not establish that the dependencies avoid acquiring or releasing resources.

The access order above describes the supplied body’s explicit operations. Physical transaction ordering, atomicity, byte order, memory barriers, cache behavior, and synchronization with other actors are not established.

## Acceptance examples

These are conditional predictions from static evidence, not executed tests. They assume required accesses and dependency calls complete normally.

### Zero selector and zero value

Given selector `0x00000000` and value `0x00000000`, the function first writes `0x48000000` to `0x38400B00`.

It then calls F-D01 and reads the global offset cell twice because selector bit 7 is clear. The status offset uses the second value plus `0x200`.

If the first status word has bit 1 set, the function returns `1` without a polling command/control read or any F-D02 call. Both offset reads still precede that return.

### Different values on the two offset reads

For selector `0x00`, suppose the first offset read yields `0x100` and the second yields `0x300`.

The retained offset is `0x500`, and the status address is `0x38400500`. The first value is not used to select that address. Any side effect of obtaining the first value remains possible.

For selector `0x80`, if its sole offset read yields `0x100`, the status address is `0x38400100`; there is no second offset read or `0x200` adjustment.

### Offset changes during dependency calls

If F-D01 changes the offset cell before returning, the subsequent offset reads observe the cell according to their actual read results.

For bit 7 clear, F-D01’s last written value is not guaranteed to be the selected value: the cell could change again between the two reads.

If F-D02 later changes the cell, the function does not recapture it. Subsequent iterations continue using the previously selected status address.

### Status-clear, control-clear termination

If a status read has bit 1 clear and the following command/control read has bit 31 clear, the function returns `1`. F-D02 is not called for that iteration, regardless of the other bits in either word.

A value argument with bit 31 clear does not by itself guarantee this path: the later command/control read, rather than the original argument, determines the branch.

### Dependency termination and repetition

If status bit 1 is clear and command/control bit 31 is set, F-D02 receives the original F-D01 result and `100`.

A nonzero result ends the function with return value `1`, without another polling iteration. A zero result leads to another status read, without another initial write, F-D01 call, or offset-cell read.

### Ignored selector bits

Selectors `0x00000081` and `0xFFFF0081` have identical low eight bits. They select the same command/control address, require the same single offset read, and use the same address calculations given the same selected offset value.

This does not assert identical outcomes across executions with different external state.

### Aliasing selectors

Selectors `0x00` and `0x90` both select command/control address `0x38400B00`.

They can also select the same status address. If the second offset read for `0x00` and the sole offset read for `0x90` both yield the same value, each status calculation adds a total displacement of `0x200` to that value and the fixed base.

The selectors are nevertheless not equivalent in access behavior: `0x00` requires two offset-cell reads, while `0x90` requires one. Equal final addresses do not erase that distinction.
