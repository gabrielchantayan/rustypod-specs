# F-e3f9c7956446

## Purpose

F-e3f9c7956446 performs an ordered, teardown-like transition across an input object and an object located through two address-resolution calls. It writes dispatch-like words, conditionally invokes relationship operations, processes an associated record and collection, reconciles context references, and returns the resolved object’s address.

The teardown interpretation is **inferred intent**, not an established ownership contract. Static evidence establishes memory accesses, call ordering, branch conditions, and the returned address. It does not establish destruction, deallocation, reference-count changes, or the meaning of the dispatch-like values.

Three guard-failure sites invoke an unknown helper followed, if that helper returns, by F-feee9156a257. The latter dependency is represented as nonreturning. Diagnostic output from the preceding helpers is not established.

### Initial writes and guards

After the initial global-derived write, the function reads input offset `0x220`.

If nonzero, it calls F-282eebd7c413 and, if that returns, F-feee9156a257. No resolution call occurs on this path.

If zero, it calls F-03144a4f049b with input + `0x168`. After that call returns, it reads the first-anchor dispatch-like global and writes its value at first anchor − `0x168`. It then reads first anchor − `0x0c`.

If this second guard is nonzero, the same helper-and-nonreturning-call sequence occurs. The initial write, first resolution, and first-anchor-relative write have already occurred. The second resolution does not occur.

### Resolved-object transition and candidate relationship

When both guards are zero, the second resolution receives first anchor − `0xc4`. The resolved object is located `0xa4` bytes before the returned address.

The function reads the first resolved-object dispatch-like global and writes it to resolved-object offset `0x00`. It then calls F-d277584d672d with the resolved object.

A null result skips the candidate operations. For a nonnull candidate:

1. Its dispatch pointer is read, and the operation at dispatch byte displacement `0x80` is called with the candidate as an explicit argument.
2. The returned address is compared with the resolved object.
3. Only on equality, the candidate’s dispatch pointer is **read again**, and the operation at displacement `0x7c` is called with the candidate and zero.

The second dispatch lookup must not be replaced by retention of the first dispatch pointer. The `0x80` operation may change the candidate’s dispatch pointer, in which case the `0x7c` operation is selected through the replacement.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Valid storage and normal dependency returns are assumed except where a nonreturning path is specified.

1. **First guard failure:** A nonzero input `0x220` field causes the initial global-derived write, then F-282eebd7c413, then F-feee9156a257 if the helper returns. Neither resolution occurs.

2. **Second guard failure:** With the first guard zero and first-anchor `−0x0c` nonzero, the first resolution and first-anchor write occur before the helper sequence. The second resolution does not occur.

3. **Globals change during calls:** If F-a6fdc7050c77 changes the middle dispatch-like global, the subsequent write uses its changed contents. If the context lookup preceding F-77781c8e0ff9 changes the additional argument global, that call receives the subsequently read value.

4. **Equal dispatch values:** If all five dispatch-like globals contain the same word when read, the five writes still occur at their specified points. No inequality requirement is imposed.

5. **Candidate dispatch replacement:** If the candidate’s `0x80` operation returns the resolved object and replaces the candidate’s dispatch pointer, the conditional `0x7c` call uses the replacement dispatch pointer.

6. **Candidate mismatch:** A nonnull candidate whose `0x80` result differs from the resolved object receives no `0x7c` call. F-a6fdc7050c77 still follows.

7. **Absent record:** A null associated-record pointer at capture skips all record-specific calls and collection processing. The final global read and dispatch-like write still occur.

8. **Changed record or collection:** Replacing resolved-object offset `0x0c` affects the optional fresh record-value read, but not the captured record used for collection processing and F-8349c252c168. Replacing that captured record’s collection pointer during iteration affects the trailing collection operation.

9. **Repeated saved-value processing:** A nonzero record predicate and a later context `0x28` equal to the resolved object cause two F-a82ec4b43e2f calls with the originally saved value.

10. **Changing context selection:** If the `0x24` comparison succeeds but the next lookup returns another context, the latter context’s field is cleared.

11. **Late pointer cleared:** If F-c719314a16bb clears an initially nonnull related pointer, its indirect operation is omitted, but the `0x08` guard is still checked.

12. **Late guard gating:** An initially null related pointer skips the `0x08` check even if that field is nonzero. With an initially nonnull related pointer and a subsequently nonzero `0x08` field, F-c8eefdf96f4b precedes F-feee9156a257 if the helper returns.
