## Acceptance examples

These are conditional acceptance cases, not executed tests.

### Entry condition depends on both sign and overflow

If \(b\) has its high bit clear and the incoming overflow flag is clear, the seven conditional writes occur, \(p=b\), and \(q=a\).

If the same \(b\) is supplied with the overflow flag set, those writes are skipped, \(p=d\), and \(q=s\).

A negative signed interpretation of \(b\) reverses those two outcomes.

### Repeated writes remain observable

Assume valid memory, returning dependencies, no relevant concurrent changes, and no additional aliasing with the destination \(b+p\).

Before F-indirect-01, that destination receives \(q\), then \(b\), then \(b\) again, then \(h\). An implementation that only writes the last value does not preserve the established access sequence.

### Return halves retain their separate roles

If F-indirect-02 returns a value with different low and high halves, the low half is written at \(p+h\), while the high half is written at \(b+h\), at the specified positions in the sequence.

If those destinations alias, the later high-half write supersedes the earlier low-half write, subject to intervening aliases. The contract does not require both values to remain simultaneously stored.

### Shifted result controls distinct destinations

This example assumes execution reaches both writes and that the displayed unsigned shifts have their stated 32-bit interpretation.

### Dependency interruption prevents later effects
