## Behavior

The observable read sequence is:

1. Read the 8-bit selector at base offset `0x5F8`.
2. Inspect bit zero of that value.
3. Read exactly one candidate byte:
   - If bit zero is zero, read offset `0x5EC`.
   - If bit zero is one, read offset `0x2F4`.
4. Return the candidate byte that was read.

The selector’s other seven bits do not affect the choice. Consequently, `0x00`, `0x02`, and `0xFE` all select offset `0x5EC`; `0x01`, `0x03`, and `0xFF` all select offset `0x2F4`.

The decision is based on the selector value obtained by the initial read. The supplied behavior contains no second selector read and no retry. A change to the selector after that initial read does not introduce a specified reselection step.

The candidate read follows the selector read. The operation therefore does not establish a simultaneous snapshot of the selector and both candidate values. If another actor modifies the selected candidate between these reads, the returned value depends on the memory-access semantics of the execution environment. No synchronization mechanism is present in the supplied evidence.

The unselected candidate is not read by the represented operation. Its contents do not affect the result for a fixed selector value. Likewise, the selected byte does not influence which location is chosen.

There is no special treatment for any candidate value. Zero, values with bit seven set, and values equal to the selector are all returned without additional processing.

The offset calculations use the fixed positive byte displacements listed above. No data-dependent index, multiplication, length calculation, or candidate-value arithmetic appears.
