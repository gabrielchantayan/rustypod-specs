# F-5e924a46b559

## Purpose

F-5e924a46b559 performs an ordered preparation phase of indirect calls, derives values from call results and implicit machine state, then mutates memory through computed and loaded addresses. Its final visible action is an unresolved indirect transfer with four explicit argument values.

**Established static evidence:** the supplied representation contains mixed-width memory accesses, bit-field extraction, repeated writes, absolute low-address accesses, address scaling, and an unresolved final destination.

**Inferred intent:** some updates resemble linked-record mutation. Character-valued constants also occur, but they do not establish text generation, an encoding, or an output protocol.

This contract describes the represented behavior, not a verified executable replacement. Unresolved arithmetic, dependency effects, and memory conventions remain **documented_only**. No runtime tests have been performed.

### 2. Field extraction and arithmetic

The incoming unsigned word contributes a left shift by thirteen and a logical right shift by fifteen. The right-shifted quantity supplies:

- Its low fourteen bits, shifted left by three.
- Its low bit moved to bit sixteen.
- A left shift by thirty-one.

Under truncating 32-bit arithmetic, the last operation retains only the original low bit at bit thirty-one. A later left shift by thirty of that already-shifted value produces zero. It is not an additional independent nonzero field.

Other represented transformations extract:

- Bits 8–23 using a twenty-four-bit mask and an eight-bit right shift.
- Bits 11–17 from a high result word.
- Bits 4–16 using a seventeen-bit mask and a four-bit right shift.
- Bits 12–23 using a twenty-four-bit mask and a twelve-bit right shift.

Repeated shifts operate on already-transformed values. Explicitly zeroed intermediates remain zero through subsequent ordinary masks and shifts.

Many left shifts and multiplications involve signed represented quantities. Overflow and negative-value shifts do not have established portable semantics. Conclusions below that depend on truncation are conditional on a 32-bit modular interpretation; they are not runtime findings.

### 4. Clearing, global conversion, and initial links

The scaled base’s word at 0x14 is cleared before an explicit byte read at its offset 0x05. That byte is later zero-extended into a word at scaled base plus 0x34.

The small base’s word at 0x14 is cleared twice, with intervening accesses. The scaled base’s word at 0x14 is read after its clear, and the low byte of that read value is written twice at small base plus 0x15.

The global associated with absolute address 0x05 is then read and converted to unsigned 32 bits. **The source access width remains unresolved.** This event follows the two byte stores at small base plus 0x15 and precedes the byte store at absolute address 0x01.

The converted value becomes a **global-derived base**. It is used for a byte store at offset 0x15 and for later word accesses at offset 0x54. These addresses must not be described as necessarily byte-derived or confined to a low 256-byte range.

The shifted payload is truncated into a byte at scaled base plus 0x11. Between that write and its subsequent clearing, the payload is also stored as a word through the value read from scaled base plus 0x14.

## Acceptance examples

### Packed-field interpretation

### Small-index maximum

A preparation result with its low seven bits set produces small index 508 and small base 1016. Treating 511 as a reachable index would not match the represented expression.

### Ordered byte overwrite

An observable write trace must retain both events and their order.

### Unresolved-width global input

If the actual declaration and memory model allow the global associated with 0x05 to convert to 0x00000123, subsequent addressing uses that converted value, not 0x23. This example does not assert that such a declaration exists.

An acceptance fixture must not impose an 8-bit load or a 0–255 range solely from the visible unsigned conversion.

### Record-base capture before the absolute write

Suppose an environment makes the separate record-base global read return one value before the write to absolute 0x60 and another afterward. The repeated region uses the value captured **before** that write.

Reordering the read after the write would violate the represented sequence.

### Width and partial completion

The 0x3A byte, halfword, and word stores are distinct access widths. Replacing all three with byte stores does not preserve the access behavior.

If an indirect dependency does not return, later direct-memory effects are not required. Earlier effects are not rolled back.
