# F-79494a774e47

## Purpose

F-79494a774e47 accepts one 32-bit input word, writes three 32-bit outputs through caller-supplied addresses, and returns a 64-bit value packing the input and the first output address.

A signed comparison selects between two behaviors:

- A threshold path copies the input to the first output, writes the binary32 encoding of positive one to the second output, and obtains the third output from F-a83966d8599e.
- A computational path constructs fixed-point state, optionally performs table-assisted initialization, performs 32 refinement rounds, and obtains output words through F-1c7710595b35 and F-fdb31af1de99.

**Inferred intent:** The input decomposition and output adjustments resemble floating-point numerical processing. The evidence does not establish the mathematical functions, approximation error, or intended input domain. This contract therefore specifies word-level behavior without assigning mathematical names to the outputs.

All behavioral claims below derive from static evidence. No runtime tests have been performed.

## Behavior

### Threshold selection and direct outputs

The threshold path is selected when the signed interpretation of \(w\) is less than `0x39800001`.

Consequently:

- Every word with bit 31 set takes the threshold path.
- Nonnegative words through `0x39800000` take the threshold path.
- Words from `0x39800001` through `0x7FFFFFFF` take the computational path.

This is not a comparison of absolute magnitudes.

The threshold path has the following observable order:

1. The first output receives the original input bits.
2. The second output receives `0x3F800000`.
3. F-a83966d8599e is called with no explicit arguments shown.
4. The third output receives that dependency’s 32-bit result.
5. The packed return value is returned.

The first output is a bit-preserving copy. `0x3F800000` is the binary32 encoding of positive one. No further floating-point classification is visible.

The dependency executes after the first two stores. Its implicit inputs and memory effects are unknown.

### Computational input state

The computational path derives an exponent-like integer:

\[
e=((w\mathbin{\&}\texttt{0x7FFFFFFF})\gg23)-127.
\]

For inputs reaching this path, \(e\) ranges from −12 through 128.

The initial residual word is:

\[
R=((w\mathbin{\&}\texttt{0x00FFFFFF})
       \mathbin{|}\texttt{0x00800000})\times64.
\]

The mask retains 24 low bits, including bit 23. Replacing it with a conventional 23-bit fraction mask would change the specified behavior.

Two fixed-point state words begin as:

\[
A=\texttt{0x20000000},\qquad B=0.
\]

Define the count-adjustment expression:

\[
H(x)=x-[x>3]-[x>13],
\]

where each bracket contributes one when its signed comparison is true and zero otherwise.

### Negative-exponent table access

When \(e<0\), initialization begins with these ordered reads:

1. Read the 32-bit value of G-01.
2. Form the selected address
   \[
   D=G\text{-}01+K_1-8e.
   \]
3. Read the signed 32-bit initialization count \(n\) at \(D-4\).
4. Read the 32-bit correction word at \(D-8\).
5. Subtract that correction from the residual.

Thus, the count is read before the correction, despite the correction occupying the lower address.

Equivalently, if the address-forming sum is denoted \(P=G\text{-}01+K_1\), the record for \(e=-1\) has its correction at \(P\) and its count at \(P+4\). Each further decrease in exponent advances both field addresses by eight bytes.

The record address uses the value obtained by the single G-01 read. The function does not visibly reread G-01 between the count and correction accesses. The source does not establish that G-01 is immutable or that the resulting records are always accessible.

After correction, the residual is scaled according to:

\[
s=e+H(n)+1.
\]

A positive signed \(s\) selects a left shift by its low eight bits. A negative signed \(s\) selects an arithmetic right shift by the low eight bits of its negation. Zero leaves the residual unchanged. Word-width and oversized-shift qualifications apply.

### Initialization rounds

The initialization index starts at zero and continues while its signed value is less than \(n\). A nonpositive count produces no initialization rounds.

Let \(m\) be the number of completed initialization rounds. With ordinary nonoverflowing loop arithmetic, \(m=n\) for positive \(n\), and \(m=0\) otherwise. The original count \(n\), not \(m\), remains relevant to output construction.

A secondary shift distance starts at one. At each initialization index \(j\), direction is selected by testing whether a one-bit word shifted by \(j\mathbin{\&}255\) intersects `0x81`.

For indices 0 through 31:

- Indices 0 and 7 select addition.
- The other indices select subtraction.

For prior state words \(A,B\) and secondary distance \(q\), an addition round produces:

\[
A'=A+(B\gg(q\mathbin{\&}255)),
\qquad
B'=(B+(A\gg1))\ll\ell.
\]

A subtraction round produces:

\[
A'=A-(B\gg(q\mathbin{\&}255)),
\qquad
B'=(B-(A\gg1))\ll\ell.
\]

Here \(\ell=0\) at indices 3 and 13, and \(\ell=1\) at other initialization indices. Right shifts are arithmetic. Both updates use the previous \(A\), not the newly computed \(A'\).

The secondary distance advances by two after each round except indices 3 and 13. The direction rule remains dependent on target shift behavior when the extracted count is at least 32.

### Refinement setup

For a nonnegative exponent:

- G-01 and the initialization record are not read.
- No initialization rounds execute.
- \(m=0\).
- The retained output-adjustment count is explicitly zero.

For a negative exponent, the retained output-adjustment count is the record’s original \(n\), including when \(n\leq0\).

Refinement starts at table index \(m\). Its two shift distances are:

\[
p=H(m)+m-[m>13]-[m\geq4]+1,
\]

\[
r=m-[m>13]-[m>3]-H(m)+1.
\]

Without overflow, \(r=1\). Both distances start at one on the nonnegative-exponent path. The two distances remain separate state because their initial values need not be equal.

### Thirty-two refinement rounds

Subject to execution continuing normally, exactly 32 refinement rounds occur. Each round advances the table index by one.

At the beginning of every round:

1. Read G-02.
2. Form the coefficient address
   \[
   G\text{-}02+K_2+4k,
   \]
   using that round’s current table index \(k\).
3. Read one signed 32-bit coefficient from that address.

G-02 is therefore read 32 separate times. The evidence does not justify substituting one cached address-forming value for those accesses or assuming every coefficient comes from a single stable table base.

At indices 3 and 13, the coefficient is arithmetically halved and the residual is not doubled. At every other index, the coefficient is unchanged and the residual is doubled using word arithmetic.

Direction depends on the residual’s sign before this doubling or coefficient adjustment. For prior states \(A,B\), shift distances \(p,r\), and the selected coefficient \(T\):

- A negative residual produces
  \[
  A'=A-(B\gg(p\mathbin{\&}255)),\qquad
  B'=B-(A\gg(r\mathbin{\&}255)),
  \]
  with a positive coefficient adjustment to the residual.
- A nonnegative residual produces
  \[
  A'=A+(B\gg(p\mathbin{\&}255)),\qquad
  B'=B+(A\gg(r\mathbin{\&}255)),
  \]
  with a negative coefficient adjustment.

Zero follows the nonnegative branch. Both state updates use the prior state words.

After ordinary rounds, both shift distances advance by one. At indices 3 and 13, neither advances. Exceptional-index behavior depends on the actual table index, not the ordinal position within the 32-round refinement sequence.

### Output construction and scaling reads

Let \(A,B\) now denote the final refinement states. Let \(n=0\) for the nonnegative-exponent path; otherwise retain the original initialization count.

#### First output

F-1c7710595b35 is called with \(B\). After that call, S-01 is read and supplied with the conversion result to F-fdb31af1de99.

If the scaling dependency returns word \(U\), the first output receives two successive stores:

\[
U
\]

followed by

\[
U-H(n)\times\texttt{0x00800000}-\texttt{0x00800000}
\pmod{2^{32}}.
\]

The second store is derived from the returned word, not from a reread of output memory. Both stores are present even if their values coincide.

#### Second output

F-1c7710595b35 is next called with \(A\). After this conversion returns, S-02 is accessed twice, in this order:

1. Its first 32-bit read is retained for the third scaling operation.
2. A separate second 32-bit read supplies the scaling argument for the second output.

F-fdb31af1de99 receives the second conversion result and the **second** S-02 read. Its result is stored at the second output address.

These reads target the same location, but equal values are not established without additional storage-stability assumptions. Neither read occurs before the second conversion call.

#### Third output

The third conversion input is the signed-word combination:

\[
A+(B\gg(H(n)\mathbin{\&}255)).
\]

F-1c7710595b35 receives that combination. F-fdb31af1de99 then receives its result together with the **first**, retained S-02 read.

There is no visible S-02 reread for this third scaling call. Changes to S-02 during intervening dependency calls or output stores do not replace the retained value.

The third scaling result is stored at the third output address, followed by the packed return.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Inclusive threshold boundary.** With valid outputs and normally returning dependencies, input `0x39800000` first writes that same word, then `0x3F800000`, and calls F-a83966d8599e. No refinement coefficient is read.

2. **First computational input.** Input `0x39800001` yields \(e=-12\). If G-01 reads as \(g\), the selected count is read at \(g+K_1+92\), followed by the correction at \(g+K_1+88\), under the applicable address arithmetic.

3. **Sign-bit behavior.** Input `0xBF800000` takes the threshold path and is copied unchanged to the first output. Its apparent binary32 magnitude does not change the signed-word branch.

4. **Special encodings.** `0x7F800000` takes the computational path with \(e=128\); `0xFF800000` takes the threshold path. No explicit infinity or NaN classification occurs.

5. **No initialization.** For `0x3F800000`, G-01 is not read, refinement starts at index zero with both shift distances one, and first-output adjustment subtracts `0x00800000`.

6. **Per-round address selection.** If the applicable storage semantics permit G-02 reads to yield different words on successive rounds, each coefficient address uses its own round’s read. A single cached base is not equivalent.

7. **Distinct scaling reads.** If the first S-02 read yields \(X\) and the second yields \(Y\), the second scaling call receives \(Y\), while the third receives \(X\). Equality must not be assumed.

8. **Retained scaling value.** If the second scaling dependency changes S-02, the third scaling call still receives the value retained before that dependency call, assuming normal preservation of the function’s retained local state.

9. **Nonpositive initialization count.** If a negative-exponent record supplies \(n=-1\), no initialization rounds run and refinement starts at index zero. Output adjustment nevertheless uses \(H(-1)=-1\), not \(H(0)\), provided the other required operations are defined.

10. **Aliased outputs and return.** If all output addresses coincide and dependencies add no writes there, the final stored word is the third result. The return still packs the original input below the first output address.
