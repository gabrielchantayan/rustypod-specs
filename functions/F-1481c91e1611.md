# F-1481c91e1611

## Purpose

F-1481c91e1611 adjusts a signed state value within a caller-supplied object. A mode argument selects either a relative adjustment or an absolute assignment. A second object field supplies an optional upper boundary.

The position-and-bound terminology in this contract describes the observed arithmetic and comparisons. Interpreting these fields as a cursor and an extent is inferred intent, not an established domain meaning.

The function returns a four-byte success indicator. On success, it also writes a separate signed result to caller-provided storage. This auxiliary result is not consistently the actual change in position: relative adjustments always report zero, and some absolute assignments also report zero despite changing the position.

## Interface

### Inputs and object layout

The function receives four arguments:

| Argument | Interpretation |
|---|---|
| Object address | Base address of storage containing the two fields below. |
| Mode | A signed integer. Zero selects relative adjustment; every nonzero value selects absolute assignment. |
| Requested value | A signed integer interpreted as a displacement in relative mode or a requested position in absolute mode. |
| Result address | Address of writable storage for one signed four-byte auxiliary result. |

The relevant object layout is:

| Byte offset from object base | Width | Contract name |
|---|---:|---|
| `0x2B4` | Four bytes | Position |
| `0x2B8` | Four bytes | Boundary |

Both fields are interpreted through signed comparisons. A boundary of zero disables boundary enforcement. A nonzero boundary is active, including a negative boundary.

The supplied representation supports a signed 32-bit interpretation of the fields and integer operations. It does not independently establish the complete calling convention, pointer width, byte order, or alignment requirements of the executing platform.

### Outputs

The return value is:

- **0:** An early rejection occurred. Neither the position nor the auxiliary result is written.
- **1:** The selected update path completed, and the auxiliary result was written.

On success, the auxiliary result is:

- Zero for every relative adjustment.
- Zero for an absolute assignment when the boundary is zero.
- Zero for an absolute assignment when the existing position is negative.
- Otherwise, the selected absolute destination minus the existing position, subject to the arithmetic qualifications below.

The boundary field is not an explicit write target. It can nevertheless change if the result address aliases it.

### Memory preconditions

Every address actually accessed must identify storage readable or writable as required by that access. There is no null check, size check, alignment check, or accessibility check.

The object need not be valid on a path that rejects before reading it: absolute mode with a negative requested value returns immediately. Likewise, the result address is not accessed on either early-rejection path.

No non-aliasing requirement is established by the supplied representation. Exact aliasing between the result address and either object field has observable consequences described below. Behavior for unsupported alignment, invalid storage, or partial-byte overlaps is not established.

## Behavior

### Arithmetic and observation model

All comparisons are signed. The ordinary behavior below assumes that arithmetic results are representable as signed 32-bit values and that object contents do not change independently during the call.

Several expressions can overflow signed 32-bit range:

- Existing position plus relative displacement.
- Boundary minus one.
- Requested position minus existing position.
- Boundary minus existing position, followed by subtraction of one.

The representation does not establish a portable overflow rule for those cases. They must not be interpreted as arbitrary-precision arithmetic, saturation, or an additional rejection condition. Conditional examples below identify results under a wrapping 32-bit execution model without claiming that this model has been independently verified.

### Relative adjustment: mode equals zero

The function first reads the position.

If that position is negative, it returns 0 immediately. It does not read the boundary, write the position, or write the auxiliary result.

Otherwise, it reads the position again, adds the requested displacement, and writes the sum to the position field. This provisional write occurs before boundary enforcement.

The remaining behavior depends on the computed sum:

- **Negative sum:** The function writes zero to the position. It does not read the boundary on this path.
- **Nonnegative sum and zero boundary:** The provisional position remains unchanged.
- **Nonnegative sum below a nonzero boundary:** The provisional position remains unchanged.
- **Nonnegative sum at or above a nonzero boundary:** The function writes boundary minus one to the position.

Finally, it writes zero to the auxiliary result and returns 1.

Consequences:

- A negative displacement is allowed.
- Moving below zero clamps to zero rather than rejecting.
- Reaching or exceeding an active boundary selects boundary minus one.
- Relative mode can perform two position writes.
- A relative adjustment from a negative existing position is rejected even if the displacement would otherwise produce a nonnegative value.
- A negative, nonzero boundary is not treated as disabled or invalid. Any nonnegative computed sum is at or above such a boundary, so boundary-minus-one handling follows.

### Absolute assignment: mode is nonzero

The function first examines the requested value.

If it is negative, the function returns 0 without reading the object or writing the auxiliary result.

Otherwise, it reads the boundary.

#### Boundary equals zero

The requested value is written directly to the position. The old position is not read.

The function then writes zero to the auxiliary result and returns 1.

Thus, an unbounded absolute assignment does not report the displacement, even when the old position was nonnegative.

#### Boundary is nonzero

For stable, valid storage and representable arithmetic, the resulting behavior is:

| Requested value | Existing position | New position | Auxiliary result |
|---|---|---|---|
| Below boundary | Nonnegative | Requested value | Requested value minus existing position |
| Below boundary | Negative | Requested value | Zero |
| At or above boundary | Nonnegative | Boundary minus one | Boundary minus existing position minus one |
| At or above boundary | Negative | Boundary minus one | Zero |

The function writes the selected position first, then writes the auxiliary result, and returns 1.

A negative existing position does not cause absolute mode to fail. Instead, it suppresses displacement reporting.

For a positive boundary, the selected position is therefore the requested value capped at boundary minus one. This description must not be generalized into a guaranteed nonnegative range for every boundary: a negative active boundary can produce a negative position.

### Observable read and write order

The supplied representation establishes these access sequences. They describe source-visible accesses, not guaranteed instruction counts or atomic transactions.

**Relative rejection:**

1. Read position.
2. Return 0 if it is negative.

**Relative success:**

1. Read position for the initial rejection check.
2. Read position again for the addition.
3. Write the computed sum to position.
4. If the sum is negative, write zero to position without reading boundary.
5. Otherwise, read boundary and, when required, write boundary minus one to position.
6. Write zero to the auxiliary result.
7. Return 1.

**Absolute rejection:**

1. Examine the requested argument.
2. Return 0 if it is negative, without object accesses.

**Absolute success with zero boundary:**

1. Read boundary.
2. Write the requested value to position.
3. Write zero to the auxiliary result.
4. Return 1.

**Absolute success with nonzero boundary and stable storage:**

1. Read boundary.
2. Read position to select the applicable case.
3. Read position again, either for a repeated sign check or for the selected arithmetic.
4. Write the selected position.
5. Write the auxiliary result.
6. Return 1.

The representation contains a more elaborate signed-condition path in the nonzero-boundary absolute case. With stable field contents, it does not introduce another normal outcome beyond the table above. An independent change between repeated position reads can invalidate that simplification. No concurrency or synchronization contract is established.

## Side effects

### Object mutation

The position is the only object field explicitly assigned by the function. Relative mode can expose a provisional position before its final clamped value.

On ordinary successful paths, the position write precedes the auxiliary-result write. The function does not roll back a position update if the later result write cannot complete.

### Aliasing

If the result address is exactly the position address, the final auxiliary-result write replaces the selected position.

For example, an absolute assignment may first write the requested destination and then replace it with the reported displacement. In relative mode, successful execution leaves the aliased position as zero because the auxiliary result is always zero.

If the result address is exactly the boundary address, the boundary is overwritten after all boundary-dependent decisions for that call. The overwritten boundary can affect later calls.

These effects follow from write order. They are not evidence that aliasing was intended by the original interface.

### Ownership and external state

The function performs no visible allocation, release, ownership transfer, or external call. It does not retain an argument in any explicit storage shown.

No global access is visible. This does not establish anything about caller synchronization, platform fault handling, or effects outside the supplied representation.

### Error behavior

The two defined rejection conditions are:

- Relative mode with a negative initial position.
- Absolute mode with a negative requested value.

Both return 0 without writing the auxiliary result.

Invalid memory and arithmetic overflow do not have established error-return behavior. In particular, a negative boundary is not rejected.

## Dependencies

No called-function dependency is present in the supplied representation.

The signed-subtraction overflow notation is an arithmetic condition, not an opaque function dependency. No assumptions about another function’s global-state preservation, allocation behavior, or ownership behavior are required.

Additional conditional acceptance cases:

- **Boundary of one:** Relative adjustment from position zero by one writes a provisional one, then writes zero. It returns 1 and reports zero.
- **Nonzero mode equivalence:** Negative and positive nonzero mode values both select absolute assignment.
- **Aliased position output:** With position 4, boundary 10, and an absolute request of 7, using the position address as the result address leaves position 3, not 7.
- **Aliased boundary output:** With position 4, boundary 10, and an absolute request of 7, using the boundary address as the result address leaves position 7 and boundary 3.
- **Early rejection with unusable result storage:** Absolute request −1 returns 0 without accessing that storage. This does not make the same address valid for a successful call.
- **Conditional wrapping addition:** If execution uses wrapping 32-bit addition, relative adjustment from 2,147,483,647 by one produces a negative provisional value and then clamps position to zero without reading boundary.
- **Conditional wrapping boundary decrement:** If execution uses wrapping 32-bit subtraction, absolute request zero with boundary −2,147,483,648 selects position 2,147,483,647. The corresponding overflow behavior is not independently verified.

## Uncertainties

The following remain **documented_only**:

- Exact runtime overflow behavior and its relationship to the supplied high-level representation.
- Full ABI, pointer width, byte order, alignment, and invalid-access behavior.
- Whether callers are intended to supply only positive boundaries or non-aliasing output storage.
- Whether negative positions represent a sentinel, an error, or an ordinary state.
- The domain meaning of the auxiliary result.
- Behavior under concurrent mutation, device-backed memory, or other independently changing storage.
- Any guarantees about observing intermediate writes across threads.

The zero boundary’s disabling effect is established behavior. The belief that a positive boundary represents an extent, with boundary minus one as the last valid position, is inferred intent.

This contract is based solely on static inspection of the supplied representation of F-1481c91e1611.

The simplified absolute-mode outcome table additionally assumes stable field contents during the call. Overflow-dependent examples are explicitly conditional rather than asserted runtime observations.
