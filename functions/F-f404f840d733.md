# F-f404f840d733

## Purpose

The established behavior is a straight-line sequence of memory accesses followed by an unresolved indirect invocation. The routine updates fixed-offset fields, follows addresses read from memory, propagates retained values, and performs several writes to arithmetic-derived addresses.

No application-level purpose is established. Repeated self-address stores and link-like accesses do not establish initialization, collection maintenance, serialization, or ownership transfer.

This contract distinguishes:

- **Established static evidence:** access widths, ordering, value dependencies, and invocation arguments visible in the supplied representation.
- **Inferred intent:** possible interpretations that impose no acceptance requirements.
- **documented_only:** unresolved entry conventions, platform behavior, dependency effects, and other facts not established by that representation.

No runtime tests have been performed.

Offset `0x64` is decimal 100. It is not offset `0x60` or `0x74`. Likewise, the stored numeric value 100 is `0x64`.

Valid completion requires every encountered address, access width, and eventual execution target to be valid under the target platform’s rules. Alignment, endianness, address interpretation, and overflow behavior are documented_only. The representation does not supply an object layout or bounds.

## Behavior

### Ordering and retained values

The visible path has no conditional branch or loop before the indirect invocation.

The following phases form one ordered access sequence. Values described as retained remain the results of their particular reads; subsequent stores do not retroactively change them. A fresh read must not be replaced with an earlier snapshot.

All regions and external cells may alias. Consequently, each read occurs after the preceding described writes, including writes that might change that read’s address or contents. Names such as “hub” and “parent” denote retained addresses, not distinct objects or ownership relationships.

A read of B offset `0x64` supplies the **initial word**. Next come a byte store of `0x74` at A offset `0x10`, a word store of `0x74` at B offset `0x54`, and a word store of `0x74` at A offset `0x10`, in that order.

The routine reads and retains the **original link** from A offset `0x74`. It then stores C at C offset `0x54` and word `0x74` at A offset `0x30`.

The low byte of D is stored at B offset `0x01`; the low byte of the initial word is stored at D offset `0x09`; and the full initial word is stored at B offset `0x74`.

The following interleaving is required: byte `0x74` is stored at B offset `0x11`; A offset `0x60` is read; the low byte of D is stored at B offset `0x11`; the initial word is stored at B offset `0x34`; and the low byte of the retained A-offset-`0x60` read is stored at A offset `0x10`.

The read between the two B-offset-`0x11` stores cannot be moved across either store when aliasing is possible.

### First pointer-dependent updates

An address is read from B offset `0x14`, establishing the **first destination**. The fourth argument is then stored as a byte at C offset `0x11`. C is stored at B offset `0x44`, and the low byte of the initial word is stored at B offset `0x11`.

A fresh read of B offset `0x74` supplies the **intermediate word**. The low byte of C is then stored at B offset `0x0D`.

Through the first destination, word `0x66` is stored at offset `0x10`. C is again stored at B offset `0x44`; byte `0x66` is stored at the first destination’s offset `0x10`; word `0x66` is stored at B offset `0x54`; and word `0x66` is stored at the first destination’s offset `0x60`.

Another fresh B-offset-`0x74` read supplies the **second destination**. B offset `0x74` is then overwritten with C, and word `0x66` is stored at the second destination’s offset `0x40`.

The low byte of the intermediate word is stored at B offset `0x0D` **before** the second destination’s offset `0x44` is read. That read supplies a retained word.

Next, B is stored at B offset `0x54`, and the original link is stored at the original link’s own offset `0x54`. Only after both self-address stores does the routine read the second destination’s offset `0x14`, obtaining a **child address**.

The low byte of the retained offset-`0x44` word is stored at C offset `0x11`. A fresh read of C offset `0x14` then supplies the low byte stored at the child address’s offset `0x15`.

The fourth argument’s earlier byte store is therefore not necessarily the last store to C offset `0x11`.

### Chained traversal and distinct snapshots

C offset `0x14` is freshly read to establish a **root**. B offset `0x64` is read next, producing the **earlier traversal word**. Word `0x73` is stored at the root’s offset `0x20`.

B offset `0x64` is then read again, producing the **later traversal word**. Its low byte is stored at the root’s offset `0x09`. These two B-offset-`0x64` reads are distinct, with the root-offset-`0x20` store between them.

The root’s offset `0x74` supplies a **linked region**. At that region, the routine stores the low byte of B at offset `0x0D`, reads offset `0x54` and writes the same retained word back there, then stores byte `0x74` at offset `0x09`.

The earlier traversal word is stored at B offset `0x44`. B is then stored at the linked region’s offset `0x34`.

The linked region’s offset `0x04` supplies a **continuation**. The later traversal word is stored at its offset `0x24`, followed by the low byte of the earlier traversal word at B offset `0x19`.

A fresh B-offset-`0x74` read supplies a **dispatch root**. Its offset `0x14` is read, and the traversal value is stored at offset `0x54` of the resulting address. The dispatch root’s offset `0x04` is then read, establishing a **branch address**.

The duplicate byte stores remain two separate accesses, even when their values and destinations match.

### Arithmetic-derived writes and invocation

External cell α is read first. B offset `0x74` is then freshly read, producing retained word **Q**.

A halfword store places Q’s low 16 bits at the address formed by Q plus B. Another halfword store places α’s low 16 bits at twice the final destination address.

A character-sized read occurs at the sum of the terminal link and B. Its conversion to an unsigned 32-bit value supplies **U**. The character’s signedness is unresolved; U is not necessarily zero-extended from eight bits.

The routine stores Q’s low 16 bits at α plus Q, then repeats the halfword store at Q plus B. Word `0x45` is next stored at U plus `0x45`.

External cell β is read, followed by external cell γ, followed by a fresh read of B offset `0x44`. These three results are retained independently.

Byte `0x44` is stored at U plus `0x44`. The γ snapshot is stored as a word at twice the β snapshot. Finally, β’s low 16 bits are stored at the sum of the traversal value and β.

The unresolved dependency F-000000000001 is then invoked with three represented 32-bit arguments, in order:

The first argument uses bitwise OR, not addition. The addresses used by the preceding stores involve addition or doubling, not this OR operation.

## Acceptance examples

These are conditional static obligations, not executed tests.

- **Initial interleaving:** If A offset `0x60` aliases B offset `0x11`, its word read occurs after the byte-`0x74` store but before the byte store sourced from D. Moving that read outside this interval does not satisfy the contract.

- **Pointer-chain ordering:** If the hub’s offset `0x34` aliases storage used by the B-offset-`0x44` chain, the chain still reads both addresses before that offset-`0x34` store. The selected address is stored into B offset `0x14` afterward.

- **Fresh late byte:** If the late B-offset-`0x64` read observes `0x123456AB`, both the subsequent B-offset-`0x1D` store and the later B-offset-`0x09` store use byte `0xAB`. Earlier snapshots do not supply these bytes.

- **Payload snapshot:** If the byte destination’s offset `0x50` overlaps its offset `0x11`, the payload read precedes the offset-`0x11` store. Its retained low byte is written at offset zero only after the two intervening B-field stores.

- **Self-store timing:** The hub-offset-`0x74` and hub-offset-`0x14` reads precede the byte destination’s self-address store at offset `0x54`, even if these locations overlap.

- **Halfword narrowing:** If Q is `0x12345678`, each halfword store sourced from Q writes value `0x5678`. Byte order remains platform-dependent.

- **Character conversion:** A character byte `0x80` can produce U equal to `0xFFFFFF80` under signed interpretation, or `0x00000080` under unsigned interpretation. The evidence does not select one.

- **OR argument:** If U is `0x44`, the first invocation argument is `0x44`, not `0x88`.

- **Interrupted execution:** If a required early access fails, no error result or rollback is established, and completion of later accesses is not guaranteed.
