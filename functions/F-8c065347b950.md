# F-8c065347b950

## Purpose

F-8c065347b950 performs one of two operations on a caller-supplied object: a two-callback operation followed by clearing a stored word, or a state-dependent initialization operation that obtains and stores a result.

**Established static behavior:** A zero-valued selector chooses the callback operation. Every nonzero selector chooses the state-dependent operation. In the latter operation, state-byte values 2, 3, and 4 cause an immediate return without the initialization writes or result-producing calls.

**Inferred intent:** The state-byte test appears to prevent initialization in three particular states. The two callbacks in the zero-selector path may represent shutdown or reset actions. These interpretations are not established semantics: the available evidence does not identify the callbacks, the meaning of the stored result, or the lifecycle represented by the state byte.

This contract specifies the observable accesses and calls. It does not assign ownership, resource-management behavior, or application-level meanings to unidentified dependencies.

### Zero-selector path

If the selector equals zero:

1. The function resolves the first callback through the 32-bit pointer at object offset `+0xA8`. Resolution reads that pointed-to object’s first 32-bit word as a dispatch-table address, then reads the callable address at table offset `+0x30`.
2. It invokes that callback. The callback’s returned value is not explicitly used.
3. After the first callback returns, the function independently resolves the second callback through object offset `+0xAC`, using the same dispatch-table offset.
4. It invokes the second callback and retains its 32-bit return value.
5. It writes a 32-bit zero to object offset `+0xB0`.
6. It returns the retained second-callback result.

The second callback is resolved after the first callback completes. Consequently, if the first callback changes the pointer at `+0xAC` or its dispatch information, the second resolution uses the resulting contents, provided those contents remain valid.

The final zero written to `+0xB0` does not replace the returned callback result. This path can return a nonzero word while leaving `+0xB0` equal to zero.

The visible body does not read the state byte or directly clear `+0xA1` through `+0xA4`, `+0xB4`, or `+0xB8` on this path. Dependencies may nevertheless modify those locations.

### Nonzero-selector state gate

If the selector is nonzero, the function reads the unsigned 8-bit value at object offset `+0xA1`.

It subtracts 2 and interprets the result as a 32-bit unsigned value for a comparison against 3. The early-return condition therefore holds exactly for state-byte values 2, 3, and 4:

| State byte | Unsigned 32-bit subtraction result | Outcome |
|---:|---:|---|
| 0 | `0xFFFFFFFE` | Continue initialization |
| 1 | `0xFFFFFFFF` | Continue initialization |
| 2 | 0 | Return 0 |
| 3 | 1 | Return 1 |
| 4 | 2 | Return 2 |
| 5 through 255 | 3 through 253 | Continue initialization |

This is not an 8-bit wrapping subtraction. The width matters for the values 0 and 1.

When the early-return condition holds, the function returns the subtraction result immediately. It performs none of the subsequent direct object writes and calls neither result-acquisition dependency. The common entry dependency has already executed.

### Nonzero-selector initialization path

For every other state-byte value, the function performs these writes in order:

1. An 8-bit zero to `+0xA1`.
2. An 8-bit zero to `+0xA2`.
3. An 8-bit zero to `+0xA3`.
4. An 8-bit zero to `+0xA4`.
5. A 32-bit zero to `+0xB4`.
6. A 32-bit zero to `+0xB8`.

The four adjacent byte writes are separate visible operations, not one specified 32-bit store.

The function then invokes **F-14775aa715ec** and writes its 32-bit result to `+0xB0`.

- If that result is nonzero, the fallback dependency is skipped.
- If that result is zero, the function invokes **F-b96150de7efe** and writes its 32-bit result to `+0xB0`.

The fallback call visibly receives the object address, a zero-valued word, a one-valued word, and the fourth input, followed by four additional 32-bit context values. The provenance and semantic role of those additional values are not established. They must not be treated as extra ordinary caller parameters without further evidence.

Finally, the function reads the 32-bit word at `+0xB0` and returns it.

The fallback decision uses the result returned by F-14775aa715ec, not a separate test of the stored field. The final return, however, is specified as a read of the stored field. No further normalization or nonzero-result enforcement is visible. If the fallback returns zero, zero is stored and, absent intervening modification, returned.

## Side effects

The function’s direct object writes are branch-specific:

| Path | Direct writes |
|---|---|
| Zero selector | One 32-bit zero write to `+0xB0`, after both callbacks. |
| Nonzero selector, state 2–4 | None. |
| Nonzero selector, all other states | Four byte clears, two 32-bit clears, then one or two 32-bit result writes to `+0xB0`. |

On a fallback execution, the first zero result is written to `+0xB0` before the fallback call. The fallback can therefore observe that zero and the preceding cleared fields, unless other actors or dependencies have changed them.

The direct clearing of fields is not transactional. There is no visible rollback if a later dependency fails to return normally. Likewise, in the zero-selector path, `+0xB0` is cleared only after the second callback returns normally.

No direct allocation, deallocation, ownership transfer, locking, logging, or error reporting is established. Clearing or replacing `+0xB0` does not by itself prove that any previously referenced resource is released.

All called dependencies may have additional effects. The evidence does not justify assuming that they preserve globals, preserve object fields, or acquire or release memory. Reentrancy and concurrent mutation are unspecified.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, dependencies return normally, all accessed addresses are valid, and no unrelated actor modifies the relevant storage.

1. **Zero selector preserves the second callback’s result as the return.**  
   If the second callback returns `0x12345678`, the function returns `0x12345678` and directly writes zero to `+0xB0` afterward. The first callback’s result does not determine the return.

2. **Second callback resolution occurs after the first callback.**  
   If the first callback replaces the pointer at `+0xAC` with another valid callback-bearing object, the subsequent resolution uses that replacement.

3. **State 2 takes the early return.**  
   With a nonzero selector, if the state byte is 2 when read after F-9aa3a9791e88, the function returns zero without its initialization writes or result-acquisition calls.

4. **States 3 and 4 return distinct gate values.**  
   Under the same conditions, state 3 returns 1 and state 4 returns 2. Those returns do not imply that `+0xB0` contains the returned value.

5. **State 0 does not satisfy the gate.**  
   Its subtraction result is `0xFFFFFFFE`, so initialization proceeds. State 1 likewise proceeds with subtraction result `0xFFFFFFFF`.

6. **Any nonzero selector selects the state-dependent path.**  
   A selector with bit pattern `0xFFFFFFFF` is treated as nonzero, not as a separate command.

7. **A nonzero primary result skips fallback.**  
   If initialization is reached and F-14775aa715ec returns `0x80000000`, that complete word is stored. F-b96150de7efe is not called. With no intervening modification, the returned unsigned value is `0x80000000`.

8. **A zero primary result is observable before fallback.**  
   If F-14775aa715ec returns zero, `+0xB0` is written as zero before F-b96150de7efe runs. The fallback result then replaces it.

9. **Fallback zero remains permitted.**  
   If both result-producing dependencies return zero, the function stores and returns zero. No additional retry or explicit error branch is visible.

10. **The entry dependency can affect the selected state outcome.**  
    If the state byte initially equals 2 but F-9aa3a9791e88 changes it to 5, a nonzero-selector invocation takes initialization rather than the state-2 early return.
