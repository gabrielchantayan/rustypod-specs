# F-5ca868b1d325

## Purpose

F-5ca868b1d325 conditionally writes a shared 32-bit state word and then conditionally invokes a primary callback.

The established entry path:

- Saves one reading of the global state pointer.
- Reloads that global pointer separately and tests the word selected by this second reading.
- Returns immediately if the tested word is nonzero.
- Otherwise calls F-890414d1fd99 with `(9, 1, 0, 0)`.
- Reads the word at the previously saved address and, if zero, assigns the configured replacement value there.
- Checks a primary callback slot at byte offset 8 and, if nonzero, invokes an offset-8 target with `(10, 1, 0, 0)`.

The initial test and subsequent state processing are not explicitly bound to the same address. They select the same address only if the two initial readings of the global state pointer agree.

The representation also contains negative-selector processing involving conversion, lookup, count decrement, and callbacks. The established entry assigns selector 1, so no route into that processing is demonstrated. It is documented conditionally, not exposed as an additional caller-selectable operation.

“Initialization” and “notification” are possible interpretations, not established application semantics.

### Path-dependent preconditions

Normal completion requires valid storage and callable targets only where execution reaches their use:

- The global state-pointer storage must support two initial reads.
- The address obtained by the **second** pointer read must support the initial 32-bit state read.
- If that state read is nonzero, the saved address need not support a state access: it is not dereferenced on this path. No primary-context access occurs.
- If the initial state read is zero, F-890414d1fd99 must return normally for continuation. The address obtained by the **first** pointer read must then support the post-call state read.

- Reaching a callback check requires the context selected by that check’s global-pointer read to support the relevant slot read.

Context pointers are not visibly validated. A valid context containing a zero optional slot is handled; an invalid context address is not.

## Behavior

### Established entry path: state selection and update

**First pointer read.** The function reads the global state pointer and saves its value. This address is retained across the preliminary dependency call.

**Second pointer read and initial test.** The function separately reloads the global state pointer and reads the 32-bit word through that second value.

If the word is nonzero, the function returns. It does not call a dependency, dereference the saved address, read the replacement, write state, or access a primary context.

If the global state pointer changes between these two loads, the tested address can differ from the saved address. The representation does not combine the loads into one snapshot.

**Preliminary dependency.** If the initial test reads zero, F-890414d1fd99 receives `(9, 1, 0, 0)`.

Its effects on globals, pointed-to storage, lifetimes, and control flow are not established.

**Saved-address reread.** After that call returns, the function reads the state word at the saved address from the first pointer load. It does not reload the global state pointer for this access.

- If the saved-address word is nonzero, it is preserved.
- If it is zero, the function reads the configured replacement and writes that 32-bit value to the saved address.

Thus, a zero read from one address can authorize processing of another address when the initial pointer loads differ. Changes to the global state pointer during the dependency do not redirect the saved-address reread or write.

The replacement is read only when the saved-address word is zero, after the dependency returns. It may itself be zero. A zero replacement still produces a write and does not suppress the callback path.

### Established entry path: primary selection and callback

After state processing, the selector becomes signed value 1.

The function then:

1. Reads the global primary-context pointer and saves it.
2. Tests the selector’s sign.
3. Because the selector is nonnegative, reloads the primary-context global and reads that context’s offset-8 slot.
4. Returns if that slot is zero.
5. Otherwise reloads the primary-context global again, reads its offset-8 target, and invokes it with `(10, 1, 0, 0)`.
6. Returns after the invocation returns.

The saved primary context is not used for the offset-8 check or invocation. Those operations use separate fresh global-pointer reads. Consequently, the checked context and invoked context can differ if the global changes between reads. Even if the context remains the same, the slot contents can change.

No second null check is shown for the target selected for invocation. No indivisibility, synchronization, or stable-snapshot guarantee is established.

The callback result is unused. Any state assignment precedes this invocation; no rollback is shown if the invocation does not return normally.

### Negative-selector material: documented_only

No demonstrated entry transition supplies a negative selector. The following describes the structurally present branch conditional on reaching it with a negative signed 32-bit selector.

#### Primary conversion and callback

At the selector dispatch, the function first saves the global primary-context pointer. For a negative selector, it then reloads that global and checks the offset-24 slot through the fresh value.

A zero slot causes return. Otherwise:

1. F-c103ec6f01cb receives the negative selector.
2. If its result is zero, F-a817d8d58c10 is invoked. The supplied representation marks that dependency as nonreturning; its implementation is unavailable.
3. For the represented nonzero-result continuation, the function reads the offset-24 target from the **saved primary context** and invokes it with `(10, conversion result, 0, 0)`.

The context checked before conversion need not be the saved context used for invocation. The conversion dependency can also alter slots or invalidate storage. The fresh-context nonzero check therefore does not prove the saved-context target safe or nonzero.

#### Secondary selection and index

After the primary callback returns, the function saves the global secondary-context pointer.

For a negative selector, the derived index is the negation of the selector plus one. The addition occurs before negation. Throughout the signed 32-bit negative range, both operations are representable:

- Selector −1 produces index 0.
- Selector −2,147,483,648 produces index 2,147,483,647.

The representation contains a zero-selector guard for this calculation, but zero is outside the negative branch’s established condition.

After saving the secondary context, the function separately reloads the secondary-context global and checks that freshly selected context’s offset-28 slot. A zero slot causes return.

Otherwise, F-890414d1fd99 receives leading arguments `(9, 29, 0, 0)` and four additional 32-bit values from incoming machine state. Their meanings and status as intentional interface arguments are unresolved.

The checked context can differ from the saved secondary context. Subsequent secondary accesses use the saved context, not the context necessarily checked here.

#### Table gate and signed bound

After the dependency returns:

1. The saved secondary context’s offset-4 value is read.
2. If zero, the selector becomes 29 and execution returns to primary dispatch.
3. If nonzero, F-10b760faca36 is called without represented explicit arguments.
4. The derived index is compared with its result as signed 32-bit values.
5. If the index is not smaller, the selector becomes 29 and execution returns to primary dispatch.

That dispatch saves the current primary-context pointer again, then uses fresh global reads for the offset-8 check and invocation. A successful invocation receives `(10, 29, 0, 0)`.

This fallback route does not execute the later F-890414d1fd99 call with `(10, 29, 0, 0)`.

The index is nonnegative. Therefore a nonpositive signed bound cannot admit it. The maximum index, 2,147,483,647, cannot be smaller than any signed 32-bit bound.

#### Lookup, decrement, and selected-entry processing

When the signed bound comparison succeeds, the saved secondary context’s offset-4 value is read again and passed with the index to F-6bbddce1b930. The table-like value used for lookup is not necessarily the value observed before the bound dependency.

If lookup returns a nonnull entry:

- Its signed 32-bit count is read.
- Count minus one is written to offset 0.
- If the decremented value is below 1, F-c2674fa3e73d receives a fresh reading of the saved secondary context’s offset-4 value, the index, and zero. The entry remains selected.
- Otherwise, the local entry selection is cleared.

A count of −2,147,483,648 makes subtraction of one exceed the signed 32-bit range. The supplied representation does not establish a portable result for that boundary.

After the successful-bounds lookup path, F-890414d1fd99 receives `(10, 29, 0, 0)`, even if lookup returned null. If no entry remains selected, the function returns.

If an entry remains selected:

1. The saved secondary context’s offset-28 target is read and invoked with the entry’s offset-4 value followed by two zeros. There is no new null check.
2. After that invocation returns, the global cleanup-context pointer is saved.
3. The cleanup-context global is separately reloaded, and that context’s offset-48 slot is checked.
4. If nonzero, the cleanup-context global is reloaded again; its offset-48 target is invoked with `(entry pointer, 0)`.
5. The **saved cleanup context’s** offset-24 target is read and invoked with the entry pointer, without a null check.
6. The saved cleanup context’s offset-48 target is read and retained.
7. If this final target is zero, the function returns. Otherwise, the retained target receives `(0, 1)`, followed by return.

The initial cleanup check, initial cleanup invocation, and later cleanup operations can address different contexts. The final invocation uses the target retained by the final slot read; it does not perform another global-pointer selection.

- One F-890414d1fd99 call if the initial test reads zero.
- At most one 32-bit state write, through the first saved state pointer.
- At most one primary offset-8 invocation, after state processing.

The initially nonzero path performs none of those calls or writes.

The negative-selector material additionally contains a count write, dependency calls, and indirect invocations as ordered above. There is no directly represented allocation or memory release. This does not limit allocation, release, or other effects inside dependencies.

## Acceptance examples

These are conditional static expectations, not executed tests. Assume valid storage and normal returns wherever the stated continuation requires them.

1. **Nonzero initial test.** If the second state-pointer load selects a word containing 7, the function returns without dereferencing the first saved address or accessing a primary context. The saved address and primary selection need not be valid for this path.

2. **Different initial state addresses.** Suppose the first pointer load saves address A, but the second selects address B. If B contains zero, the preliminary dependency runs. Afterward, A—not B—is inspected for the conditional assignment. No subsequent read of B is shown.

3. **Stable initial selection.** If both initial loads select A, A initially contains zero, and the dependency writes 12 to A, the function preserves 12 and proceeds to the primary callback check.

4. **Zero replacement.** If the initial test is zero and the saved-address word remains zero, a replacement of zero is still written. Callback processing follows. A later invocation can again take a zero-state path, subject to its own pointer readings.

5. **Post-call global redirection.** Changing the global state pointer during the dependency does not redirect the saved-address reread. Changing the primary-context global can affect subsequent primary selection.

6. **Primary check differs from invocation.** If the offset-8 check selects context P with a nonzero slot, but the invocation reload selects Q, the invocation uses Q’s offset-8 target. P’s successful check does not establish Q’s target validity. A zero or invalid target at Q is not handled by another null check.

7. **Valid null primary slot.** If the offset-8 check reads zero from valid storage, the function returns. Any preceding state assignment remains effective.

8. **Hypothetical negative primary mismatch.** Conditional on negative-branch entry, the saved primary context may be P while the offset-24 check selects Q. A nonzero slot at Q permits conversion, but the later invocation reads P’s offset-24 target.

9. **Hypothetical count transitions.** Conditional on a successful negative-branch lookup, count 2 becomes 1 and clears the entry selection. Count 1 becomes 0 and retains it for F-c2674fa3e73d and later processing. Count −2,147,483,648 has no established portable decrement result.

10. **Hypothetical cleanup mismatch.** If cleanup context C is saved, a later fresh selection D supplies the initial offset-48 check, and another selection E supplies its invocation, later offset-24 and final offset-48 operations still use C. No requirement that C, D, and E agree is enforced.
