# F-d5dd567991e2

## Purpose

F-d5dd567991e2 selects and invokes one of two primary callbacks, then conditionally invokes a secondary callback if the primary callback returns zero.

Primary selection depends on a discriminator in the supplied record and, for one discriminator value, a discriminator in a referenced record. Secondary invocation depends on the record’s state **after** the primary callback returns and on a matching value in the supplied context.

A nonzero callback result is returned immediately and unchanged. Otherwise, the function returns zero.

These statements describe the supplied static representation. They do not establish what the discriminator values mean, what the callbacks do, or whether zero represents success, refusal, or another outcome.

## Interface

1. **Context reference.** A reference to storage containing a callback-table reference and an additional comparison field.
2. **Record reference.** A reference to storage containing a discriminator and an overlapping, interpretation-dependent payload field.

The supplied representation uses 32-bit integer-sized storage for the relevant fields and result. Its address-bearing integer operations indicate a 32-bit address model. ## Behavior

### Primary callback selection

The function first reads the record discriminator at byte offset 4.

If that value is decimal 22, it next reads the address-bearing field at record offset 8, then reads the discriminator at offset 4 from the referenced record. These accesses occur before the primary callback-table entry is fetched.

The special primary callback, at table offset 268, is selected only when both of the following hold:

- The initial record discriminator equals decimal 22.
- The referenced record’s discriminator equals decimal 42.

The primary callback at table offset 272 is selected in every other case.

Consequently:

- An initial discriminator other than 22 does not cause a read of record offset 8 during primary selection.
- An initial discriminator of 22 causes the referenced-record access even if the later comparison with 42 fails.
- Failure to meet the special discriminator pair is an ordinary selection of the other primary callback, not an error result.

After making the selection, the function reads the callback-table reference from context offset 0 and obtains the selected callback from that table. It invokes the callback with the original context and record references, in that order.

The selected primary callback is invoked exactly once on any path that reaches a valid callback invocation. There is no attempt to invoke the alternative primary callback afterward.

### Primary result handling

A nonzero primary result ends processing immediately. The function returns that result without:

- Rereading the record discriminator.
- Reading the secondary comparison fields.
- Fetching or invoking the secondary callback.

A zero primary result permits the secondary eligibility check.

No primary result is converted to a Boolean for return. Zero versus nonzero controls the branch, but a nonzero value retains its original value in the function result.

### Secondary eligibility

After a zero primary result, the function rereads the record discriminator at byte offset 4. This is a fresh read, not reuse of the discriminator used for primary selection.

If the new discriminator is not decimal 15, the function returns zero without reading either secondary comparison field.

If the new discriminator is decimal 15, the function performs these reads in order:

1. The record field at byte offset 8.
2. The context field at byte offset 80.

It compares the two 32-bit values for equality. No range test, conversion, dereference of the record value, or arithmetic adjustment is shown.

If they differ, the function returns zero without fetching or invoking the secondary callback.

If they match, the function reads the callback-table reference from context offset 0 again, fetches the callback at table offset 224, and invokes it with the original context and record references.

This fresh callback-table read is significant: if the primary callback changed the context’s table reference, secondary dispatch uses the newly observed reference rather than the table used for primary dispatch.

### Secondary result handling

A nonzero secondary result is returned immediately and unchanged.

A zero secondary result leads to a zero function result. There is no further dispatch, retry, fallback callback, or local state update.

### Mutation-sensitive sequencing

The primary callback lies between the initial selection reads and all secondary eligibility reads. Its mutations may therefore change:

- Whether the post-primary discriminator equals 15.
- The comparison value at record offset 8.
- The comparison value at context offset 80.
- The table reference used for secondary dispatch.
- The secondary callback entry itself.

The function does not restore earlier contents or require that the record retain its initial discriminator.

The argument references passed to callbacks remain the original arguments. Changing data stored inside the context does not replace the context argument itself.
