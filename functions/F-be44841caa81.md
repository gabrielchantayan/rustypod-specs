# F-be44841caa81

## Purpose

F-be44841caa81 performs a fixed sequence of byte-sized state accesses and fourteen calls to externally defined targets. It uses a single unsigned input to produce:

- An initial byte write containing the input’s low eight bits.
- A three-argument dependency call containing the input twice and a scaled form of the input.
- A later byte write containing input bits 22 through 29.
- Two further dependency calls using scaled dependency results, one also receiving a previously read byte.

The supplied representation ends at an undecodable control-flow boundary. It does not establish a normal return, successful completion, or an intentional application-level halt.

The established behavior is therefore the ordered prefix described below, conditional on each preceding operation completing and control continuing as represented. A higher-level purpose—such as device initialization, command dispatch, or data transfer—is not established.

### Address calculation and aliasing

Because each address component is an unsigned byte, each explicit destination address lies between `0x11` and `0x110`, inclusive.

The addition is not an eight-bit wrapping addition. An address component of `0xFF` produces destination address `0x110`, not `0x10`.

The two writes may target the same address or different addresses. They use separate reads of the address component.

No non-aliasing precondition is visible. In particular, an explicit write could affect the context byte if the supplied context address makes those locations coincide. Dependency calls may also modify memory relevant to later operations. The represented sequence must therefore not be simplified on the assumption that either context read is redundant.
