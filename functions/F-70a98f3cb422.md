# F-70a98f3cb422

## Purpose

F-70a98f3cb422 conditionally invokes a dependency for an object identified by its sole argument, then checks a 32-bit field to determine whether execution may proceed to two explicit zero stores.

The established behavior is:

- If the field at byte offset `0x14` is initially zero, return the original argument without invoking any dependency or explicitly writing object storage.
- If that field is initially nonzero, invoke F-25060b4fa60c with the original argument and read the field again.
- If the second read is zero, write zero to the 32-bit fields at offsets `0x10` and `0x14`, in that order, then return the original argument.
- If the second read is nonzero, invoke F-cc6f52873d53 and then, if control returns, invoke F-feee9156a257. The supplied representation marks the latter invocation as non-returning.

An inferred intent is to request some operation on an active object, require that operation to clear a status field, and reset associated state on success. The meanings of “active,” “status,” and “reset” are not established. They are not additional requirements on the dependencies.

## Behavior

### Initial decision

The first direct object access reads four bytes at offset `0x14`.

If that read yields zero:

- No dependency is invoked.
- Offset `0x10` is not read or written.
- Offset `0x14` is not explicitly written.
- The original argument is returned.

Consequently, an initially zero field at offset `0x14` does not cause the field at offset `0x10` to be cleared. That field may retain any existing value.

If the initial read yields any nonzero value, F-25060b4fa60c is invoked with the original argument. Its result, if any, is not used by this function.

### Post-dependency decision

If F-25060b4fa60c returns control, the function performs a fresh four-byte read at offset `0x14`, using the same original base argument. It does not reuse the initial field value.

The second read controls the remaining path. There is no comparison between the first and second nonzero values, and no requirement that the dependency preserve the field’s original bit pattern.

If the second read yields zero, the function performs these explicit writes in order:

1. Four-byte zero at offset `0x10`.
2. Four-byte zero at offset `0x14`.

It then returns the original argument.

The second store is required by the supplied control flow even though the immediately preceding decision read observed zero at offset `0x14`. The function therefore differs from one that merely assumes that field remains zero.

The successful path does not inspect the previous contents of offset `0x10`. Whatever value is present immediately before its explicit store is replaced with zero.

### Persistent nonzero value

If the second read yields a nonzero value, F-cc6f52873d53 is invoked with no explicit arguments.

If that invocation returns, F-feee9156a257 is invoked with no explicit arguments. The supplied representation marks this second invocation as non-returning.

There is no third read of offset `0x14` between these invocations. Therefore, even if F-cc6f52873d53 changes that field to zero, such a change does not prevent the invocation of F-feee9156a257.

On this branch, neither explicit zero store precedes the dependency invocations. Under the represented non-returning behavior, neither store nor the normal return is subsequently reached.

The mechanism of non-return is not established. Process termination, an exception, a nonlocal transfer, or another mechanism must not be selected as the contract’s explanation without additional evidence.

### Dependency interruptions

Later operations are conditional on earlier dependencies returning control. In particular:

- If F-25060b4fa60c does not return normally, the function does not reach its second field read through the shown control flow.
- If F-cc6f52873d53 does not return, F-feee9156a257 is not reached.
- Behavior following an unexpected ordinary return from F-feee9156a257 is not established by the supplied non-returning representation.

## Acceptance examples

These examples are conditional observations, not executed tests. They assume valid accesses, no interfering execution, and the specified dependency behavior.

### Initially zero field

Given zero at offset `0x14` and a nonzero value at offset `0x10`:

- The function invokes no dependency.
- It leaves both fields untouched by direct writes.
- It returns the original argument.

An implementation that unconditionally clears offset `0x10` would not match this behavior.

### Successful dependency effect

Given a nonzero field at offset `0x14`, suppose F-25060b4fa60c returns and the second read observes zero:

- F-25060b4fa60c receives the original argument exactly once.
- The function writes zero at offset `0x10`, then writes zero at offset `0x14`.
- Neither subsequent dependency is invoked.
- The original argument is returned.

If the dependency writes a nonzero value at offset `0x10`, the function’s later store still replaces it with zero.

### Nonzero value changes but remains nonzero

Given an initial value of `1` at offset `0x14`, suppose the dependency returns with that field containing `2`:

- The function takes the persistent-nonzero branch.
- F-cc6f52873d53 is invoked.
- If it returns, F-feee9156a257 is invoked.
- The function has performed neither explicit zero store before these invocations.

Changing between nonzero values does not satisfy the second decision.

### Field cleared during the later dependency

Suppose the second read is nonzero, but F-cc6f52873d53 subsequently clears offset `0x14` and returns:

- F-feee9156a257 is still invoked.
- There is no intervening field recheck.
- The later clear does not redirect execution to the successful stores.
