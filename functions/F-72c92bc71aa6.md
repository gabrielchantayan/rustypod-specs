# F-72c92bc71aa6

## Purpose

F-72c92bc71aa6 selects between two dependency-driven operations:

- A buffer-conversion route calls a dependency and, if that dependency returns zero, exchanges the bytes of a count word and the indicated number of following 16-bit words in place.
- A chained route passes an intermediate result through two further dependencies, conditionally reading a context field before each of those calls.

Established behavior includes selector normalization, route selection using a global dispatch word, dependency argument placement, conditional memory accesses, local byte exchange, and result propagation.

The domain meanings of the context, selector, mode, opaque values, intermediate results, and dispatch word are unknown. Interpreting this function as a particular protocol operation, allocator, lookup, or resource-management operation would exceed the supplied evidence.

## Interface

### Inputs

The function accepts six arguments in this order:

| Position | Contract name | Width and established use |
|---|---|---|
| 1 | Context | A 32-bit value passed to dependencies. On the chained route, it also supplies the base address for a 32-bit field at byte offset 24. |
| 2 | Selector | A signed 32-bit integer. Zero is normalized to one; minus one is rejected. |
| 3 | Mode | A signed 32-bit integer used in route selection and passed unchanged to two chained-route dependencies. |
| 4 | Primary opaque value | A 32-bit value passed to dependencies without local interpretation. |
| 5 | Secondary opaque value | A 32-bit value passed to dependencies without local interpretation. |
| 6 | Word buffer | An address passed to dependencies and, on the conversion route, interpreted locally as a sequence of unsigned 16-bit words. |

The representation establishes 16-bit buffer elements and 32-bit scalar values. It does not independently establish the complete calling convention, pointer ABI, address-space rules, or alignment requirements.

The function does not locally validate buffer capacity, address validity, context structure size, or the semantic validity of the opaque values.

### Output

The result is a signed 32-bit integer. Its possible sources are:

- The fixed value **−50**, with 32-bit representation `0xFFFFFFCE`.
- A nonzero result from F-225627083011, returned unchanged.
- Zero after completion of local buffer conversion.
- Any result from F-d9dbc4057137, returned unchanged.

Neither zero nor −50 uniquely identifies an execution path. The final dependency can return either value independently of the function’s locally generated results.

### Memory-access preconditions

If F-225627083011 returns zero on the conversion route:

- The buffer must support reading and writing its first 16-bit word.
- The converted first word determines the number of additional words accessed.
- Every selected additional word must support a 16-bit read and write.
- The accessed address range must be valid under the execution environment’s addressing and alignment rules.

On the chained route, each executed context-field read requires a readable 32-bit field at context base plus 24 bytes.

These are preconditions for the established local accesses, not checks performed by the function. Dependencies may impose additional requirements that are not supplied.

## Behavior

### Selector normalization and rejection

A selector of zero becomes one before route selection or dependency invocation.

A selector of minus one causes immediate return of −50. This path performs no dispatch-word evaluation, dependency call, local buffer access, or context-field read.

All other selector values proceed, including negative values other than minus one. No additional local range restriction is established.

The chained route contains a further check for selector zero. The earlier normalization and intervening local operations leave no ordinary execution in which that second check changes the selector again.

### Route selection

For a non-rejected selector, the function evaluates whether the sum of the mode and a global 32-bit dispatch word equals zero:

- A zero sum selects the buffer-conversion route.
- A nonzero sum selects the chained route.

This condition is evaluated before any dependency call. The function does not locally reevaluate it afterward. A dependency’s later modification of the dispatch word therefore does not cause local route reselection.

For additions representable under the applicable signed interpretation, the condition is ordinary addition followed by comparison with zero. The supplied representation does not independently settle overflow semantics. Under a 32-bit wrapping interpretation, the condition instead concerns the low 32 bits of the sum. Overflow-dependent route selection remains **documented_only**.

### Buffer-conversion route

The first operation is a call to F-225627083011 with these five arguments, in order:

1. Context.
2. Normalized selector.
3. Primary opaque value.
4. Secondary opaque value.
5. Word-buffer address.

Mode is not passed to this dependency.

If the dependency returns nonzero, the function returns that result unchanged and performs no subsequent local buffer conversion. The function does not undo any writes performed by the dependency; caller-side recovery capabilities are unknown.

If the dependency returns zero, the function converts the buffer in place. For stable ordinary memory, the transformation is:

- Exchange the two bytes of the first 16-bit word.
- Store the converted value back into that first word.
- Use the converted value, interpreted as an unsigned count, as the number of following words to process.
- Exchange the two bytes of each selected following word and store the result at that word’s original location.

The count header occupies byte offsets 0–1 relative to the buffer address. Payload word number one occupies offsets 2–3. Each subsequent payload word follows at the next two-byte position.

The header write precedes payload processing. Payload words are processed in increasing address order, beginning immediately after the header. Each payload word is read before its replacement is written, and that replacement precedes processing of the next payload word.

The loop bound is retained independently of the stored header. A later change to the header does not change the already established traversal count.

The converted count ranges from zero through 65,535:

- A zero count still causes the header conversion and write.
- A zero count causes no local payload access.
- A count of 65,535 causes processing of 65,535 payload words.
- The largest selected region contains 65,536 words, totaling 131,072 bytes including the header.
- At that maximum count, the final payload word begins at byte offset 131,070.

The traversal counter is unsigned and 32 bits wide. Its required range is well below its maximum value, so counter overflow is not necessary for termination. The largest payload index and byte offset also fit within 32 bits; validity of the resulting addresses still requires a suitable buffer region.

Byte exchange produces a 16-bit result. For payload words, storage retains the low 16 bits of the promoted shift-and-combine operation; this yields the same two-byte exchange for every unsigned 16-bit input.

No capacity argument, bounds check, terminator search, or payload-content validation is present. The count is not restricted below 65,535.

After processing all selected words, the function returns zero.

The header expression refers to the first word more than once. The evidence establishes its byte-exchange result for stable ordinary memory, but does not establish an exact machine-load count or ordering among the expression’s constituent reads. It is not a specified volatile-memory or device-register protocol.

### Chained route

The first call is to F-e9e4be5dad47 with six arguments, in order:

1. Context.
2. Normalized selector.
3. Primary opaque value.
4. Primary opaque value again.
5. Mode.
6. Primary opaque value again.

The primary value occupies three distinct argument positions. Neither the secondary value nor the word-buffer address is passed to this dependency.

If F-e9e4be5dad47 returns zero, the function returns −50. No local context-field read or later dependency call occurs.

If it returns nonzero, the function reads the 32-bit context field at byte offset 24, then calls F-e155b614573e with:

1. The value obtained from that context-field read.
2. The result from F-e9e4be5dad47.
3. Mode.
4. The 32-bit value one.
5. The 32-bit value zero.

The nonzero intermediate result is forwarded without a positivity check or local semantic validation. A negative signed result therefore satisfies the nonzero condition and proceeds with its 32-bit value preserved.

If F-e155b614573e returns zero, the function returns −50. F-d9dbc4057137 is not called.

If F-e155b614573e returns nonzero, the function reads the 32-bit context field at offset 24 again. It then calls F-d9dbc4057137 with:

1. The value obtained from this second context-field read.
2. The result from F-e155b614573e.
3. The 32-bit value one.
4. Secondary opaque value.
5. Word-buffer address.
6. The 32-bit value zero.

The second context-field read is distinct from the first and occurs after F-e155b614573e returns. That dependency may have changed the field. The earlier field value cannot be substituted without an independently established preservation guarantee.

The function returns F-d9dbc4057137’s result unchanged. It performs no local buffer byte exchange on this route, even if the final dependency returns zero.

## Side effects

### Direct effects

The established direct effects are:

- Evaluation of the global dispatch word for every non-rejected selector.
- Zero, one, or two context-field reads, depending on chained-route progress.
- Rewriting the count header and selected payload words after a zero result from F-225627083011.

The function has no explicit local allocation, release, ownership transfer, or cleanup operation.

### Dependency effects and ownership

Dependency effects are unknown without separate contracts. In particular:

- A zero or nonzero result does not establish whether a dependency modified memory or global state.
- No dependency is assumed to preserve the context field, dispatch word, buffer, or other shared state.
- An intermediate result is not established to be an address, handle, allocation, or owned resource.
- The absence of a local release does not establish that dependencies retain or release nothing.
- The function performs no local rollback. Caller-side recovery capabilities are unknown.

On the conversion route, local processing uses the buffer contents observed after F-225627083011 returns zero, not necessarily the contents present at function entry.

The visible interface does not prohibit aliasing. Buffer writes may therefore affect other state if the supplied addresses overlap it. Such writes do not trigger route reevaluation, and they do not change the separately retained traversal count.

No recovery behavior is established for invalid addresses, alignment faults, dependency exceptions, or asynchronous interference.
