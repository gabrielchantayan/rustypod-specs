# F-46e088d9606d

## Purpose

F-46e088d9606d performs an ordered series of memory updates using two explicit inputs, two additional entry-state values, and a base address read from global storage. It then invokes an unresolved indirect dependency with four arguments.

The supplied static representation establishes memory effects, not an application-level purpose. In particular, it does not establish that the affected regions are valid objects, that the repeated stores implement initialization, or that the final transfer is an ordinary returning call.

This contract distinguishes:

- **Established static evidence:** accesses and ordering visible in the supplied representation.
- **Inferred interpretation:** a 32-bit address-and-word model consistent with the represented operations.
- **documented_only:** behavior that cannot be resolved from the supplied evidence.

No runtime tests have been performed.

## Interface

### Inputs and entry state

The visible interface has two explicit 32-bit inputs and no declared return value.

| Contract name | Meaning established by use |
|---|---|
| Payload | First explicit input. Stored as a 32-bit value and also used as a base address for a 32-bit read at offset `0x74`. |
| Destination | Second explicit input. Used as a base address for a 32-bit store at offset `0x54`; also stored into a global-selected region. |
| Auxiliary base | Additional 32-bit entry-state value, not supplied by the visible two-input interface. Used as an address, an unsigned arithmetic operand, and a source of low-byte values. |

| Selected base | A 32-bit value read from a global slot at entry. Subsequent operations use this captured value as an address. |

These names describe roles only. They do not establish object types or ownership.

The two additional entry-state values have no visible definitions within the function. Calling through an ordinary two-argument interface alone does not establish valid execution.

### Widths and address interpretation

The represented operations distinguish:

- One-byte reads or writes: 8 bits.
- One halfword store: 16 bits.
- Word reads, stores, and explicit inputs: 32 bits.

The working address model is 32-bit. Doubling the unsigned auxiliary value produces a 32-bit result, retaining the low 32 bits. Byte conversions retain the low eight bits.

Some other address expressions use signed-looking values. Overflow behavior for those expressions is not established as a portable arithmetic contract. Valid execution requires an environment in which their effective addresses and access behavior are defined.

Byte order is unspecified. Consequently, the bytewise effects of overlapping word and byte stores cannot be fully resolved without an additional target assumption.

### Preconditions and outputs

For fault-free execution, every reached memory access must be valid at its actual width and satisfy the target’s alignment requirements. This includes low absolute addresses, addresses derived by doubling values, and addresses loaded indirectly from memory.

There is no visible:

- Null check, bounds check, or alignment check.

The visible output is mutated memory followed by an indirect invocation. A normal return is represented after that invocation, but depends on the unresolved dependency returning normally.

## Behavior

### Entry capture and repeated publication

The function first reads Selected base from its global slot. That read precedes all visible stores.

It then begins a publication sequence involving four locations:

| Location | Width | Published value |
|---|---:|---|
| Destination plus `0x54` | 32 bits | Payload |
| Selected base plus `0x19` | 8 bits | Low byte of Auxiliary base |
| Auxiliary base plus `0x11` | 8 bits | Low byte of Selected base |
| Selected base plus `0x34` | 32 bits | Destination initially; doubled Auxiliary base thereafter |

The initial word publication to Destination precedes the two byte publications and the initial publication of Destination into Selected base.

The remainder of this phase repeatedly publishes Payload to the address formed by doubled Auxiliary base plus `0x54`. Each such publication is followed, in order, by the byte at Selected base plus `0x19`, the byte at Auxiliary base plus `0x11`, and the doubled auxiliary value at Selected base plus `0x34`.

This is a fixed, repeated sequence in the supplied representation, not evidence of an input-dependent traversal. The addresses and values do not advance between repetitions.

The repetitions must not be treated as merely one final-state assignment when individual writes are observable. Memory-mapped devices, aliases, or external observers could distinguish repeated writes from a single write. The exact repetition count is **documented_only** here; this contract does not establish a trace-count acceptance criterion.

Selected base remains the captured value throughout these accesses. Even if a store aliases the global slot from which it was obtained, no subsequent reload of that slot is visible.

### Snapshot reads and low-address state

After the repeated phase, the function captures a 32-bit value from absolute address `0xA9`, then captures a word from Payload plus `0x74`.

It writes one byte to absolute address `0x3A`. That byte is the low eight bits of twice the low byte of Auxiliary base, plus `0x30`. This is an arithmetic byte transformation, not an established decimal-character conversion. Values outside a digit range are not rejected.

Next, it captures:

- A word from Context base plus `0x14`, called the **saved context word** below.
- A word from Auxiliary base plus `0x04`, called the **saved auxiliary word** below.

These reads occur after the `0x3A` byte write, so an alias with that write can affect the values captured.

The function then publishes the low auxiliary byte at Context base plus `0x0D`; the byte `0x6C` at Auxiliary base plus `0x08`; and the low selected-base byte at Auxiliary base plus `0x0D` and plus `0x09`, in that order.

It stores Context base into Context base plus `0x54`, then writes the low byte of the captured `0xA9` word to absolute address `0x67`.

### Linking and overlapping field replacement

A word is read from Context base plus `0x44`; call this the **context link**.

The byte currently at absolute address `0x67` is copied to absolute address `0x21`. This is a read of the current byte, not merely a promise to reuse the earlier captured word.

The context link is published in three forms:

- Its low byte at Auxiliary base plus `0x10`.
- Its full word at Selected base plus `0x54`.
- A shifted low byte at Context base plus `0x01`.

The shift is a signed right-shift expression whose count is the low eight bits of Auxiliary base. For counts within the word width, the treatment of negative operands remains target-dependent. Counts of 32 or greater have no defined result established by this evidence.

The word at Selected base plus `0x54` is then overwritten with Auxiliary base.

A word read from Auxiliary base plus `0x40` is written to Auxiliary base plus `0x10`. Before that write, the saved auxiliary word is published at Selected base plus `0x74`. Thus the earlier single-byte publication at auxiliary offset `0x10` is later covered by a four-byte store beginning at that same offset.

The function next stores Context base at Selected base plus `0x44`, copies the current byte at absolute address `0x67` to Auxiliary base plus `0x09`, and writes the low auxiliary byte to Context base plus `0x09`.

The captured word originally read at `0xA9` is then stored at Auxiliary base plus `0x44`.

### Indirect targets and final updates

A word read from Auxiliary base plus `0x54` supplies the **linked base**. This read occurs after the earlier writes and therefore observes any alias-induced changes.

The current byte at `0x67` is copied again to Auxiliary base plus `0x09`. The low byte of the earlier Payload-plus-`0x74` snapshot is written to Linked base plus `0x0D`.

The saved context word is written to Context base plus `0x54`. Although this replaces the earlier self-address publication at that location, it is not necessarily restoration of an original field: the saved word came from offset `0x14`, not offset `0x54`.

A word is then read from Auxiliary base plus `0x14`; call it the **auxiliary detail**. The payload snapshot’s low byte is published at Context base plus `0x11`. Linked base is published as a byte at Auxiliary base plus `0x09` and as a full word at Auxiliary base plus `0x44`.

The final memory phase uses two additional loaded values:

- **Root base:** read from Context base plus `0x04`.
- **Branch value:** read from Root base plus `0x64`.

Between those reads, the function writes the 16-bit value `0x0065` at twice Root base.

It then writes the low byte of Auxiliary detail to Linked base plus `0x11`, followed by the word value `100` at Linked base plus `0x54`.

Next it captures a word from Root base plus `0x74`, then reads a **destination base** from Context base plus `0x64`. It publishes Root base’s low byte at Context base plus `0x09`, stores Branch value at Destination base plus `0x54`, and stores Destination base as a word at twice Branch value.

### Final invocation

The unresolved indirect dependency, identified here only by the opaque documentation label **F-INDIRECT-UNKNOWN**, receives four arguments in this order:

1. `0x72`.
2. Branch value.
3. Saved context word.
4. The word captured from Root base plus `0x74`.

All visible stores above precede this invocation. No visible memory operation follows it before the represented return.

## Side effects

### Aliasing and observability

No separation between memory regions is established. Different role names may designate overlapping or identical addresses.

Accordingly:

- A store may change the contents of a later read.
- A byte store may partially replace an earlier word.
- A word store may replace several earlier byte fields.
- An earlier value captured into working state is not automatically refreshed when its source memory changes.
- Final-state descriptions for individual fields are conditional on absence of subsequent overlapping writes and dependency effects.

The access ordering described above is the ordering visible in the supplied representation. Hardware transaction atomicity, barriers, and cross-thread visibility are not established.

### Ownership and failure

The function writes through caller-supplied, global-derived, entry-state-derived, and memory-loaded addresses. No evidence establishes authority to mutate those regions beyond the accesses themselves.

There is no explicit allocation or release in the visible body. That does not constrain F-INDIRECT-UNKNOWN: its ownership behavior and effects are unknown.

An invalid access can occur after earlier stores have completed. No recovery or rollback is visible. Platform fault handling, partial hardware stores, and behavior after arithmetic outside the supported target model are **documented_only**.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Disjoint valid storage

Given valid, nonoverlapping ordinary memory regions, valid entry-state bases, and no intervening external mutation, immediately before the indirect invocation:

- Destination plus `0x54` contains Payload.
- Selected base plus `0x34` contains doubled Auxiliary base.
- Selected base plus `0x54` contains Auxiliary base, not the earlier context link.
- Selected base plus `0x74` contains the saved auxiliary word.
- Context base plus `0x54` contains the saved context word.
- Linked base plus `0x54` contains `100`.

These observations do not constrain memory after the dependency executes.

### Byte arithmetic boundary

If the low auxiliary byte is `0x80`, the byte written at `0x3A` is `0x30`: twice `0x80` plus `0x30`, reduced to eight bits. No range error or alternate branch is visible.

This example covers that byte publication only; it does not resolve the separate oversized-shift issue for the same auxiliary low byte.

### Captured value versus later memory

If the word read at `0xA9` is subsequently overwritten through an alias, its previously captured value still supplies the later word publication at Auxiliary base plus `0x44`.

By contrast, later copies from `0x67` use the byte present when each read occurs.

### Overlapping field replacement

If no other access aliases Auxiliary base plus `0x10`, its early byte containing the context link is later replaced by the word read from Auxiliary base plus `0x40`. The final bytes depend on target byte order.

### Dependency arguments

If execution reaches the indirect invocation, its fourth argument is the captured Root-base-plus-`0x74` word, not the earlier Payload-plus-`0x74` snapshot. Its third argument remains the saved Context-base-plus-`0x14` word.

### Invalid early destination

If the first destination store faults, later writes are not guaranteed to occur. The Selected-base global read precedes that store. No successful completion or error return is promised.
