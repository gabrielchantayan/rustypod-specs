# F-96f3ac9db937

## Purpose

F-96f3ac9db937 performs machine-state-dependent calls, bit extraction, direct memory updates, and conditional dispatch. The supplied static representation does not establish an application-level purpose.

Two broad outcomes are represented:

- An optional dispatch followed by an ordinary return, provided the dispatch returns.
- Continued processing that ends at an explicitly truncated bad-instruction boundary.

This is a **documented_only** behavioral contract. It records the supplied static evidence without treating unresolved inputs, low addresses, or incomplete control flow as conventional application behavior.

### Widths and arithmetic

The representation distinguishes:

- 8-bit byte accesses.
- 16-bit halfword accesses.
- 32-bit word accesses, addresses, and most arithmetic.
- 64-bit results divided into low and high 32-bit words.

Unsigned word arithmetic wraps modulo \(2^{32}\). Word doubling, multiplication by four, and address calculations retain their low 32 bits. Halfword stores retain the low 16 bits.

Logical right shifts introduce zeros. Arithmetic right shifts propagate the signed word’s sign bit. Signed halfword reads extend the sign into a 32-bit value.

Some displayed expressions use signed arithmetic. Overflow behavior is not independently established where signed subtraction or addition exceeds its range; those expressions must not be silently converted into unsigned comparisons.

Plain-character signedness, byte order, and alignment requirements are unresolved.

## Behavior

### Initial extraction

F-unresolved-01 is called first. The routine then reads the entry byte and zero-extends it to form a byte-derived base in the range 0–255.

F-unresolved-02 supplies a 64-bit result:

- Its low word becomes a working pointer.
- Bit 15 of its high word becomes a one-bit gate.
- Bits 16–31 of its high word become an unsigned count-like value.

The entry arithmetic word is shifted left by three at 32-bit width.

A zero count reaches a bad-instruction boundary before the working pointer is dereferenced, regardless of the gate.

For a nonzero count, the routine reads the working pointer’s first byte. A zero byte bypasses the optional processing and secondary branches. A nonzero byte enters that processing. No traversal, string length, or terminator search is established.

### Optional processing and dispatch

For a nonzero first byte, a set gate causes one call to F-unresolved-03. Its 32-bit result is stored at the byte-derived base plus `0x10`.

The already-shifted entry arithmetic word is multiplied by eight again. The count and working pointer are cleared. These updates prevent a second iteration of the represented loop.

A nonzero result from F-unresolved-03 selects early dispatch. F-unresolved-04 runs first. F-unresolved-05 then receives:

1. F-unresolved-04’s result.
2. An unsigned byte from the twice-shifted address plus one.
3. The 32-bit value `0xFFFFFFC2`, representing −62.
4. A byte from that same address shifted left by 30 at 32-bit width.

Only the final byte’s low two bits survive in argument bits 30–31. Two byte-read expressions are represented; neither one shared snapshot nor a physical argument-evaluation order is established.

If F-unresolved-05 returns, F-96f3ac9db937 returns.

A zero result from F-unresolved-03 instead continues with the working pointer equal to zero. The following signed-halfword read therefore targets `0x10`.

If the original gate is clear, the call-and-store operation is skipped, and the original working pointer remains in use.

### Secondary branch selection

For a nonzero first byte that does not dispatch, the routine:

- Writes byte `0xBA` at the byte-derived base plus `0x99`.
- Reads a signed halfword at the current working pointer plus `0x10`.
- Selects a branch according to the byte-derived base plus `0x12`.

The sum ranges from 18 through 273. The higher branch is taken when this sum exceeds `0xD1`, equivalently when the base byte is at least 192.

The signed-halfword value initially becomes retained state for a later store. The higher branch subsequently replaces that state with a full 32-bit array word.

### Lower secondary branch

The lower branch makes a sequence of calls beginning with the byte-derived base plus `0x90` as an argument. Later, it reads and forwards one byte selected by the signed interpretation of the working pointer:

- Address `0x10` for a nonnegative pointer word.
- Address `0x11` for a negative pointer word.

An intervening call does not turn this into a pre-call memory snapshot.

The branch’s final dependency result becomes the working word passed into the ordinary call sequence. Its retained arithmetic value is 744, obtained from `0xBA` shifted left by two. Its retained store-address value remains the earlier sign-extended halfword.

### Higher secondary branch

The higher branch has a distinct prefix and bypasses the ordinary sequence before the shared continuation.

Its observable prefix includes, in represented order:

- A call receiving the byte-derived base plus `0x90` and the inbound stack word.
- A 32-bit store of `0x7E` at `0xB6`.
- Another call.
- A 32-bit store of `0x3F0` at `0x3F8`.
- A character read at additional dependency output address state plus the branch-selection sum.
- Word stores of the branch-selection sum at `0x3F0` and the earlier signed-halfword value at `0x3F4`.

- A static-word load retained as an object-like base.

The array reads are represented in the order offsets 0, 8, and 4:

- Offset 0 supplies a later call argument.
- Offset 8 supplies a full 32-bit replacement for the retained signed-halfword state.

The replacement at offset 8 is not truncated to a halfword.

A bad-instruction condition rejects nonzero nonnegative multiplied values. Its associated signed-overflow predicate concerns adding 16 to 186, which does not overflow. Consequently, zero and negative multiplied values continue under the displayed condition.

On the continuing path:

- The low 16 bits of the retained object-like base are stored through additional dependency output address state plus two.
- The represented stack-base state changes.

That last word becomes the input to the shared continuation. Its address uses the retained base, not a guaranteed unchanged static location.

The higher branch’s retained arithmetic value is the replacement word plus 16 plus a one-bit adjustment, at 32-bit width. The adjustment is **bit 29 of the promoted character plus 98**, where addition is unsigned 32-bit arithmetic after character promotion.

2. A byte from `0x10` or `0x11`, selected by a returned signed word’s sign.

## Acceptance examples

These are conditional static examples, not runtime tests. Each assumes preceding calls return and required accesses succeed.

- **Zero count:** A zero initial upper halfword reaches truncation before the pointed-to byte is read, regardless of the gate.

- **Initial zero byte:** With count 5 and a zero pointed-to byte, the first ordinary call receives 10 and 5. The later `0x002F` halfword store targets zero, and the final array address is 255.

- **Lower-branch doubling:** If the lower branch’s final result is `0x80000001`, the first ordinary call receives `0x00000002` and `0x80000001`.

- **Early dispatch:** A set gate and nonzero optional result cause the word store before dispatch. If both dispatch byte reads yield 3, the fourth argument is `0xC0000000`. Return remains conditional on dispatch returning.

- **Zero optional result:** A zero optional result clears the working pointer, making the following signed-halfword read target `0x10`.

- **Threshold:** Base byte 191 selects the lower branch; 192 selects the higher branch.

- **Higher-branch replacement:** If the higher array’s offset-8 word is `0x100`, the final `0x002F` store targets `0x200`, regardless of the earlier signed halfword. Retained arithmetic is `0x110` or `0x111`, depending on the character adjustment; both yield final array address zero.

- **Character promotion:** For character byte `0x80`, signed-character interpretation gives adjustment 1; unsigned-character interpretation gives adjustment 0.

- **Nibble boundaries:** Returned words `0x0FFFFFFF` and `0xF0000000` supply arguments 0 and 15 to F-2cc1255261f3.

- **Final conditional contents:** With selector 8, stack base `0x1000`, retained destination base `0x2000`, and final-array offset-16 word `0x12345678`, the four stack stores contain that word, 8, zero, and `0x2000`. The subsequent halfword at `0x30` contains `0x138C`.

- **Selector boundary:** Selector 9 skips those conditional stores and reaches truncation after the destination-base-plus-`0x68` store. Neither selector outcome establishes successful completion.
