# F-61bf46f10b7c

## Purpose

F-61bf46f10b7c conditionally writes one 16-bit value through a cursor stored in a caller-supplied object. It uses the direct-write path only when an object flag is set and a cursor-to-bound calculation produces a nonzero result. Otherwise, it dispatches through an indirect function entry associated with the object.

The direct path advances the stored cursor before writing the value at the previous cursor address. The fallback path receives the object, the value, a raw dispatch-entry value, the fourth incoming argument, and the object again.

This contract describes the supplied static evidence. No runtime tests have been performed. Interpretations such as “buffer,” “capacity,” and “dispatch table” describe likely roles; they do not establish allocation, ownership, or safety guarantees.

## Interface

| Second | A 16-bit value. The direct path stores this value as a 16-bit memory write. The fallback path forwards it as an argument, subject to the unresolved call ABI. |
| Third | A 32-bit value with no observed use in this function. It is not forwarded to the fallback target. |

The first argument is not validated before dereferencing. A null or otherwise inaccessible object is not a supported ordinary input.

### Object layout

The supplied representation uses four-byte words and 32-bit address-bearing fields:

| Byte offset | Width | Observed role |
|---|---:|---|
| 0 | 32 bits | Address used as the base for an indirect dispatch-entry lookup. |
| 4 | 32 bits | Flags. Bit mask `0x00000008` controls eligibility for the direct path. |

Other object fields are not explicitly accessed by this function.

On the fallback path, a separate 32-bit entry is read at byte offset 40 from the dispatch base obtained through the object’s offset-zero field. This dispatch-entry offset must not be confused with the object’s own bound field, which happens to have the same numeric offset.

### Output and return

The function has no explicit return value.

Its locally visible results are either:

- A cursor-field update followed by a 16-bit write; or
- An indirect call whose effects and return behavior are not established here.

Any return value produced by the indirect target is not explicitly used.

## Behavior

### 1. Test the direct-path flag

The function first examines the 32-bit flags field at object offset 4.

If mask `0x00000008` is clear, it immediately selects fallback dispatch. The cursor and bound fields are not read by the local branch condition on this path.

If the flag is set, the function reads the cursor field and evaluates the cursor-to-bound calculation.

Bits outside the specified mask do not directly influence this decision.

### 2. Evaluate the cursor-to-bound calculation

With the flag set, the function obtains the current cursor from object offset 36 and the bound from object offset 40.

The supplied expression subtracts the cursor address, represented as an integer, from the bound field. It then right-shifts the difference by one bit and compares the shifted result with zero.

- A zero result selects fallback dispatch.
- A nonzero result selects the direct-write path.

This is not an explicit ordered-address check. In particular, it does not establish that the cursor lies below the bound.

For a nonnegative difference that is representable without arithmetic overflow:

- A difference of zero selects fallback.
- A difference of one byte also selects fallback.
- A difference of two or more bytes selects the direct path.

There is no separate alignment check. A positive odd difference of at least three bytes still selects the direct path.

The negative-difference and overflow cases depend on the integer and shift semantics of the intended execution environment. They must not be silently reinterpreted as a safe capacity check.

### 3. Perform the direct write

When the flag is set and the shifted difference is nonzero, the function performs two writes in this order:

1. It stores the address two bytes beyond the original cursor into the object’s cursor field.
2. It stores the incoming 16-bit value at the original cursor address.

The destination of the value write is the cursor captured before the cursor-field update. The payload is not written through a newly reread cursor.

There is no local dispatch call on this path. The third and fourth incoming arguments have no observed effect here.

The update-before-write ordering is part of the behavior. It is not equivalent to writing the value first and advancing the cursor afterward. If the later write faults or overlaps object storage, the final state may differ from the usual nonoverlapping-buffer case.

### 4. Perform fallback dispatch

Fallback occurs when either:

- The direct-path flag is clear; or
- The flag is set and the shifted cursor-to-bound difference equals zero.

The function obtains a raw 32-bit dispatch entry through the object’s offset-zero field. For the call target, it clears the entry’s two lowest bits using mask `0xFFFFFFFC`.

The indirect call is supplied five arguments in this order:

1. The original object address.
2. The incoming 16-bit value.
3. A raw, unmasked 32-bit dispatch-entry value.
4. The fourth incoming argument.
5. The original object address again.

The third incoming argument to F-61bf46f10b7c is not used as the third outgoing argument.

The raw entry used as an argument is expressed as a separate lookup from the one used to select the call target. Static evidence therefore does not justify a requirement that one cached entry value serve both purposes. Under stable memory, both lookups yield the same raw value; with concurrent changes or access-sensitive memory, that equivalence is not established.

The evaluation order among the call-target expression and outgoing argument expressions is not fully specified by the supplied representation. The contract does not impose an unsupported order between the separate dispatch-entry lookups.

The function performs no explicit local cursor update or payload write before making this fallback call. The target itself may perform either operation, other operations, or no such operation.

## Side effects

### Direct path

The explicit local side effects are:

- A 32-bit cursor-field write at object offset 36.
- A subsequent 16-bit write at the original cursor address.

The function does not explicitly modify the flags, bound, or dispatch-base fields on this path. That is not a guarantee that their bytes remain unchanged: the payload destination could overlap those fields.

No atomicity or synchronization is established. The function does not provide a transaction in which cursor advancement and value storage succeed or fail together.

If the original cursor aliases the cursor field, the later 16-bit write can partially overwrite the address just stored there. Consequently, the usual postcondition “cursor equals original cursor plus two” requires a nonoverlapping payload destination.

The byte order of the 16-bit store is not established by this source alone.

Local effects consist of reads and the indirect call. The target’s effects are unknown.

## Acceptance examples

These are conditional acceptance examples derived from static evidence, not executed tests. Unless stated otherwise, assume readable and writable nonoverlapping storage, stable dispatch data, compatible calling conventions, and representable arithmetic.

### Direct write with exactly two bytes remaining

Given:

- Flag mask `0x00000008` is set.
- Cursor address is `0x00001000`.
- Bound address is `0x00001002`.
- Incoming value is `0xA1B2`.

Expected behavior:

- The shifted difference is one, so no fallback call occurs.
- The cursor field is written with `0x00001002`.
- A 16-bit value equal to `0xA1B2` is then written at `0x00001000`.
- This example does not specify the order of the two payload bytes.

### Fallback with one byte of positive separation

Given the flag is set, cursor is `0x00001000`, and bound is `0x00001001`:

- The difference is one.
- Shifting right by one produces zero.
- The function dispatches indirectly.
- It does not locally advance the cursor or perform the payload write.

Effects performed inside the target remain outside this example’s established postconditions.

### Fallback when cursor equals bound

Given the flag is set and cursor equals bound:

- The calculation produces zero.
- Fallback is selected.
- No local direct-path writes occur.

### Flag-clear short circuit

Given the flag mask is clear:

- Fallback is selected without locally evaluating cursor capacity.
- The cursor and bound fields need not be read by this function before dispatch.
- The object’s dispatch information must still support the indirect call.

This does not claim that the target avoids reading cursor or bound fields.

### Low-bit removal and raw-entry forwarding

Given both dispatch-entry lookups observe raw value `0x1234567B`:

- The selected target address is `0x12345678`.
- The third outgoing argument is `0x1234567B`, not the masked target address.
- The first and fifth outgoing arguments are the same original object address.
- The fourth outgoing argument is the fourth incoming argument.

### Odd positive separation

Given the flag is set and bound exceeds cursor by three bytes:

- The shifted difference is one.
- The direct path writes one 16-bit value and advances the cursor by two bytes.
- The function does not reject the odd separation.

### Reversed bounds

Given the bound is below the cursor, rejection is not an established behavior.

Under an execution model with representable signed subtraction and arithmetic right shift, a difference of negative two remains nonzero after shifting and therefore selects the direct path. This conditional example exposes why the branch must not be specified as “write only when the bound is above the cursor.”
