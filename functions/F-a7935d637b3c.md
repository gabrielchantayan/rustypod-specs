# F-a7935d637b3c

## Purpose

F-a7935d637b3c conditionally traverses a linked collection, selects entries whose 32-bit classification value equals a previously captured value, and uses F-1983453691c7 to produce an accumulated result. When extending an existing nonzero result, it subsequently passes the previous result to F-94cb53877c15.

A classification value stored directly in the collection owner provides a bypass: when it equals the captured classification value, the function returns zero without reading the collection head.

**Established behavior:** selection, traversal order, dependency calls, replacement of the accumulated result, and the bypass are visible in the supplied static evidence.

**Inferred intent:** the fixed formatting operands appear intended to construct a name-based selection expression, extending multiple terms with an OR-like operation. Their exact bytes and the formatting dependency’s behavior are not supplied. This contract therefore does not promise a particular textual result.

### Output

The function returns a 32-bit result:

- Zero if the bypass applies.
- Zero if traversal completes without any matching node.
- Otherwise, the current accumulated result, which is the return value of the most recent completed F-1983453691c7 call.

A matching node does not guarantee a nonzero return. A zero result from F-1983453691c7 becomes the current accumulated result and can also be the final return value.

## Behavior

### Initial reads and bypass

The function establishes the following order:

1. Read the root address from the root-reference storage.
2. Read the associated-object address at root offset 8.
3. Read and capture the classification value at associated-object offset 44.
4. Read the classification value at collection-owner offset 76.
5. Compare the two classification values.

If those values are equal, the function returns zero. It does not read the collection head, visit nodes, or invoke either dependency.

The root address and captured classification value are retained for the rest of this invocation. The visible logic does not refresh them after dependency calls.

### Collection traversal

If the bypass comparison is unequal, the function reads the collection head at collection-owner offset 32.

A zero head produces a zero return without dependency calls. Otherwise, traversal starts at that node and proceeds through each visited node’s next field.

For every visited node:

- Its classification field at offset 28 is read and compared with the captured classification value.
- A nonmatching node leaves the accumulated result unchanged and causes no dependency call.
- A matching node invokes F-1983453691c7 using the root address, one of two fixed formatting operands, and the node’s offset-zero value.
- The node’s next address is read at offset 40 after the matching-node processing, including any F-94cb53877c15 call, has completed.

The head is read once. The function does not restart traversal or reread the collection owner between nodes.

### Matching with no current result

The accumulated result initially equals zero.

Whenever a matching node is encountered while that result is zero, F-1983453691c7 receives, in order:

1. The retained root address.
2. The fixed initial-result formatting operand.
3. The matching node’s offset-zero value.

Its return value becomes the accumulated result.

No F-94cb53877c15 call occurs for this case. This remains true even if an earlier matching node had already been processed but returned zero. The decision is based on the current accumulated value, not on a separate count of matches.

### Matching with an existing result

Whenever a matching node is encountered while the accumulated result is nonzero, F-1983453691c7 receives, in order:

1. The retained root address.
2. The fixed extension formatting operand.
3. The previous accumulated result.
4. The matching node’s offset-zero value.

After F-1983453691c7 returns, the function invokes F-94cb53877c15 with the **previous** accumulated result. It then continues with the formatting call’s return value as the current result.

The distinction between the old and new result is essential:

- F-94cb53877c15 receives the old nonzero value, not the newly returned value.
- This call occurs even if F-1983453691c7 returned zero.
- This call also occurs if F-1983453691c7 returned the same value as the old result.
- The return value of F-94cb53877c15 does not determine the accumulated result.

No special handling protects a new result that aliases the previous one. Whether such aliasing is permitted depends on the dependency contracts.

### Completion

Traversal stops when the next node address is zero. The function returns the current accumulated result without making a final F-94cb53877c15 call for it.

Nonmatching nodes do not introduce, clear, or otherwise alter the accumulated result. Matching nodes are processed in linked traversal order; there is no visible sorting, deduplication, or early exit after a successful formatting call.
