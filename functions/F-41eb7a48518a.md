# F-41eb7a48518a

## Purpose

F-41eb7a48518a conditionally writes a computed payload-address bit pattern and a byte count to two caller-provided locations. Publication requires three gates: a context-selected flag bit, a zero descriptor field, and a selected table field equal to exactly one.

After publication, a fresh context observation determines whether the function clears a table field, invokes F-d7be9cfb4000, and replaces an index in an earlier-captured state object.

Every normally completing path makes a final context-dependency call and then returns a freshly read 16-bit descriptor field. The return value is not established as a success indicator.

“State,” “descriptor,” “table,” “payload,” and “index” describe visible structure, not established application semantics.

## Interface

### Arguments and result

| Input | Visible representation | Contract |
|---|---|---|
| First output location | Address of a writable 32-bit slot | Receives the computed payload-address bit pattern if publication occurs. |
| Second output location | Address of a writable 32-bit slot | Receives twice a selected unsigned 16-bit quantity if publication occurs. |
| Third argument | 32-bit value | Unused by the visible body. |
| Fourth argument | Unsigned 32-bit value | Its incoming value does not affect visible behavior. |

When the descriptor gate is zero, the fourth argument’s working storage is replaced with the table eligibility value before that value is tested. A nonzero descriptor gate rejects publication without consulting the incoming fourth argument.

The result is a 16-bit field. Its signed interpretation and caller-side extension are not established.

### Shared root and state object

A shared root supplies a state-object address. The function captures one root value after its first call to D-01, but separately reads the root for publication-related accesses.

| State-object byte offset | Width | Use |
|---|---:|---|
| +4 | 32 bits | Descriptor address |
| +12 | 32 bits | Table address |
| +16 | 32 bits | Payload-base bit pattern |
| +20 | 32 bits | Index |

The captured state-object address anchors advancement and the final descriptor lookup. The initial descriptor, publication table, publication index, and payload base are obtained through separate root observations.

No dependency call intervenes between the initial root capture and the pre-publication root reads. Separate reads are established; intervening mutation is not.

### Descriptor and context

| Descriptor byte offset | Width | Use |
|---|---:|---|
| +0 | 16 bits | Unsigned flags |
| +2 | 16 bits | Initial zero gate and final return source |

D-01 returns an address from which the function reads one context byte at offset +88. The initial and post-publication context observations use separate calls.

### Table layout and selection arithmetic

Two fixed table fields are visible:

| Table byte offset | Width | Use |
|---|---:|---|
| +2 | 16 bits | Helper argument during advancement |
| +4 | 16 bits | Unsigned multiplier for the first output |

Publication selection first doubles the unsigned 32-bit index and retains the low 32 bits:

\[
E=(2\times\text{index})\bmod 2^{32}.
\]

The resulting \(E\) is an offset measured in 16-bit table elements. Eligibility is five elements beyond that selected position; quantity is six elements beyond it. Where the resulting pointer accesses are valid, their byte displacements are:

\[
\text{eligibility}: 2E+10,\qquad
\text{quantity}: 2E+12.
\]

These expressions describe displacement after the unsigned doubling. They do not establish an independent wrapping rule for subsequent pointer-address formation.

For ordinary consecutive indices \(i\) and \(i+1\), without an intervening arithmetic wrap:

- Selection \(i\) has eligibility at table \(+4i+10\) and quantity at table \(+4i+12\).
- Selection \(i+1\) has eligibility at table \(+4i+14\) and quantity at table \(+4i+16\).

The first quantity occupies bytes \(4i+12\) through \(4i+13\); the next eligibility occupies bytes \(4i+14\) through \(4i+15\). These are adjacent, distinct, nonoverlapping 16-bit fields. A selection’s quantity does **not** occupy the next selection’s eligibility location.

Indices separated by \(2^{31}\) produce the same wrapped element offset and therefore select the same eligibility/quantity pair, assuming the same table address. That equivalence does not imply quantity-to-eligibility overlap.

In particular, index `0x80000000` produces \(E=0\), selecting eligibility at table +10 and quantity at table +12. It does not inherently require an out-of-bounds pointer calculation.

The visible body supplies no null, bounds, alignment, overlap, or index validation. It does not establish that the computed payload-address bit pattern refers to an allocation, and it never dereferences that payload address.

Storage lifetime across dependency calls is a prerequisite for normal completion, not a guarantee supplied by this function. Platform byte order, alignment requirements, fault behavior, and synchronization guarantees are unresolved.

## Behavior

### Initial context and flag gate

The function first calls D-01. After that call returns, the established read order is:

1. Read the shared root and retain its state-object address.
2. Read the shared root again and obtain the descriptor address from state offset +4.
3. Read the descriptor’s unsigned 16-bit flags at offset +0.
4. Read the context byte at offset +88 through the first D-01 result.

The context byte selects the required mask:

| Initial context byte | Required mask |
|---|---:|
| 6 | 2 |
| Every other value | 1 |

Publication requires the flags to share at least one bit with the selected mask. Unrelated flag bits do not cause rejection.

A failed bit test skips publication and advancement. The function proceeds to its final D-01 call and return-field lookup.

### Descriptor and eligibility gates

If the flag test passes, the function reads the 16-bit field at descriptor +2 through the descriptor address already obtained.

A nonzero field rejects publication and advancement. The supplied representation converts this value to an address-like form for the zero comparison, but does not dereference that converted value.

If the descriptor field is zero, the function:

1. Rereads the shared root and loads the table address at state +12.
2. Rereads the shared root and loads the unsigned 32-bit index at state +20.
3. Forms the wrapped doubled index described above.
4. Reads the selected 16-bit eligibility field.

Only eligibility equal to **exactly 1** permits publication. Zero and every other value reject publication and advancement.

The retained publication table and index come from separate root observations. Neither is necessarily obtained through the initially captured state-object address.

### Output publication

After all gates pass, the function reads the unsigned 16-bit quantity from the same selected table position. Eligibility and quantity use the same retained table, index, and wrapped element offset.

The quantity is captured before either output write.

Publication performs two ordered 32-bit stores:

1. Write the computed payload-address bit pattern to the first output.
2. Write twice the captured quantity to the second output.

The first output combines:

- The original unsigned 32-bit publication index.
- The unsigned 16-bit multiplier at retained table +4.
- The payload-base bit pattern at state +16, obtained through another fresh shared-root read.

The relative evaluation order of the multiplier load and payload-base load is not established. Both occur before the first output store.

The first output uses the original index, not the wrapped element offset. Its numeric calculation uses unsigned 32-bit arithmetic:

\[
\text{first output}
=
(\text{payload base}
+\text{index}\times\text{multiplier}\times2)
\bmod 2^{32}.
\]

This modular numeric calculation is distinct from pointer-based table selection. It establishes only the stored bit pattern, not payload-address validity.

The second output is twice the unsigned quantity, without 16-bit truncation. Its range is 0 through 131070 inclusive. A zero quantity does not independently suppress publication or advancement.

No payload bytes are read, copied, or transferred.

### Fresh context and advancement

After both output stores, the function calls D-01 again and reads the context byte at +88 through the new result.

Advancement occurs only when this second byte is **0, 1, 5, or 7**. Values **2, 3, 4, and 6**, and every value outside 0 through 7, skip advancement.

The initial context value is not reused.

When advancement occurs, the function uses the state-object address captured after the first D-01 call:

1. Read the current 32-bit index at captured state +20.
2. Read the current table address at captured state +12.
3. Clear the 16-bit field at current table + four times current index +10.
4. Read the 16-bit field at current table +2.
5. Call F-d7be9cfb4000 with current index plus one and the field just read.
6. Store a 32-bit value exposed through an additional post-call result channel at captured state +20.

The current index and table are fresh reads. Output aliasing or the second D-01 call may have changed them since publication.

Advancement does not repeat publication’s unsigned element-offset selection. Its index is represented as signed 32-bit for multiplication by four and addition of one. Boundary behavior for those signed operations is unresolved; the publication wrapping rule must not be transferred to them.

The clear precedes the table +2 read. If those locations overlap under an admissible address calculation, the helper receives the field value present after the clear.

The replacement index is not established to equal current index plus one or to be the helper’s conventional return value.

### Final call and return

Every normally completing path makes one final D-01 call. Its result is ignored.

After that call returns, the function loads the descriptor address at captured state +4, reads the 16-bit field at descriptor +2, and returns it.

This is a fresh descriptor-pointer load and field read, not reuse of the initial descriptor gate. The final dependency call may therefore affect the return value by changing relevant storage.

Changing only the shared root does not redirect this lookup: the captured state-object address remains its anchor.

### Aliasing and mutable storage

No nonaliasing guarantee is established.

If both output arguments identify the same valid 32-bit slot, the second store overwrites the first. Immediately after publication, that slot contains the doubled quantity.

Outputs may overlap the shared root, state, descriptor, or table storage. All inputs required for the two publication stores have been read before the first store, so output aliasing does not change the already captured quantity or the computed first-output value. It may affect later dependency behavior, advancement reads, or the return lookup.

Overwriting the shared root does not change the captured state-object address. Overwriting fields inside the captured object can affect later reads through that address.

Separate root reads do not establish an atomic snapshot or support for concurrent mutation.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless varied explicitly, they assume valid storage, normal dependency completion, disjoint outputs, and no relevant dependency mutation.

1. **Flag rejection.** Initial context 6 and flags 1 fail mask 2. Neither output is written. D-01 is called twice; F-d7be9cfb4000 is not called.

2. **Descriptor rejection.** Initial context 0, flags containing bit 1, and descriptor gate 9 reject publication before table selection. The final return may differ from 9 if the final dependency call changes relevant storage.

3. **Exact eligibility.** After earlier gates pass, eligibility 2 rejects publication; eligibility 1 permits it.

4. **Ordinary publication.** Index 3 produces element offset 6. Eligibility is at table +22 and quantity at table +24. With payload base 4096, multiplier 8, and quantity 5, the ordered outputs are 4144 and 10. Second context 6 skips advancement.

5. **Adjacent selections do not cross-overlap.** Index 3 selects eligibility at +22 and quantity at +24. Index 4 selects eligibility at +26 and quantity at +28. The quantity at +24 occupies bytes +24 and +25; it does not overlap eligibility at +26.

6. **High index selecting offset zero.** Index `0x80000000` doubles to zero in unsigned 32-bit arithmetic. Eligibility is at table +10 and quantity at table +12. With eligibility 1, quantity 5, payload base 4096, multiplier 8, and second context 6, the outputs are 4096 and 10; no advancement calculation occurs.

7. **Repeated pair through unsigned wrap.** Indices 1 and `0x80000001` both select eligibility at table +14 and quantity at table +16. This is repetition of the same pair, not overlap between a quantity and a different eligibility field. With payload base 4096 and multiplier 8, either index produces first output 4112.

8. **Quantity boundaries.** Quantity 65535 produces second output 131070. Quantity zero produces zero and does not independently prevent advancement.

9. **Changed context.** Initial context 6 with flags 2 can permit publication. Second context 0 causes advancement using freshly loaded fields from the captured state object.

10. **Out-of-range context.** Initial context 255 selects mask 1. Second context 255 skips advancement.

11. **Coincident outputs.** Successful publication to one shared output slot leaves the doubled quantity immediately after the second store.

12. **Root replacement.** If the second D-01 call changes only the shared root, advancement and the final descriptor lookup remain anchored to the captured object, provided it remains accessible.

13. **Final descriptor replacement.** If the final D-01 call installs a valid descriptor address in the captured object and that descriptor’s +2 field is 23, the function returns 23.

- Signed advancement arithmetic at boundary values.

Publication’s unsigned doubling and intermediate wrap are established. Ordinary adjacent selections have nonoverlapping eligibility and quantity fields. Repetition for indices separated by \(2^{31}\) selects the same pair; it does not establish cross-field overlap.

Inferred intent: publication followed by optional clearing and index replacement resembles retrieval followed by conditional consumption. This interpretation does not replace the field-level contract.

## Evidence

This contract is based on the supplied static function representation and dependency mapping, not on the prior draft’s assertions.

Established evidence includes access widths and offsets, separate shared-root reads, a retained state-object address, short-circuit gates, unsigned 32-bit doubling before 16-bit-element selection, ordered output stores, fresh context observations, conditional clearing, helper arguments, additional-channel index replacement, and the final descriptor reread.
