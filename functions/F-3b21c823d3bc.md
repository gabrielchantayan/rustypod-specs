# F-3b21c823d3bc

## Purpose

F-3b21c823d3bc conditionally writes zero to individual bytes at regularly spaced addresses derived from its input. Before each write decision, it calls F-bc423dc494b4 with the original input and compares the returned unsigned value with a current index.

Two properties define the behavior:

- The dependency is called again for every decision, including the decision that ends execution.
- After each completed store, the index advances modulo 256.

Consequently, this is not a traversal governed by a bound obtained once. Dependency results can change the number of writes, cause termination, or permit repeated traversal of the same 256 destination locations.

The spacing suggests a byte field within 20-byte records. That is inferred intent, not an established data-model contract. The evidence establishes destination spacing and store size, but not record types, field meaning, or allocation size.

## Behavior

### Initial decision

The function initializes the index to zero and calls F-bc423dc494b4 with the original input.

This first call occurs even if its result will prevent every destination store. A zero result therefore means no explicit destination write, not no observable activity.

After the dependency returns, its unsigned result is compared with the current index:

- A result strictly greater than the index permits the store.
- A result equal to or less than the index ends the function normally.

Equality is terminating.

### Ordering of successful decisions

For every successful decision, the established order is:

1. The dependency is called with the original input.
2. Its returned value is obtained and compared with the current index.
3. One zero byte is stored at the selected destination.
4. The index advances modulo 256.
5. The next dependency call occurs.

A later decision does not reuse a previous result. Even if every observed result happens to be identical, each decision still requires a new call.

The function performs no explicit destination-byte read and no direct check of the destination’s existing value before storing. A permitted store is still performed when the byte already contains zero.

This does **not** establish that existing destination values cannot influence whether a store occurs. F-bc423dc494b4 may read those bytes and choose its result accordingly. Previously written zeros may likewise affect later dependency results. Such indirect influence is unresolved.

### Termination and call counts

Normal termination occurs at the first decision whose unsigned result is no greater than the current index.

If an invocation terminates normally after \(N\) completed stores, it has made \(N+1\) dependency calls: one for each successful decision and one final call for the terminating decision. This count assumes all calls and stores complete normally.

There is no separate termination rule based on the number of completed stores. In particular, completing 256 stores does not itself cause return.

### Wraparound and repeated destinations

A completed store at index 255 is followed by index zero. If the following comparison succeeds, the next store targets displacement 16 again—not a hypothetical destination for index 256.

Thus, across any number of completed cycles, the function’s explicit stores select from the same 256 locations. They may overwrite a location repeatedly.

If every dependency result is at least 256, every comparison succeeds because the index never exceeds 255. Subject to normal dependency returns and successful memory accesses, execution then has no normal terminating decision.

The boundary for results below 256 is different:

- If **every** result is below 256, execution must terminate no later than the decision at index 255.
- Such an execution can complete at most 255 stores from entry.
- Indefinite continuation may include results below 256 at smaller indices, provided each exceeds its associated index.
- Every decision reached at index 255 must return at least 256 to permit another cycle.

Returning at least 256 at index 255 is necessary for repeated cycles, but does not guarantee continuation: a later decision at any other index can still terminate.

### Changes caused by the dependency

The dependency may inspect or change memory before the subsequent comparison and store. The supplied body does not establish that it preserves globals, previously cleared bytes, address validity, or ownership.

Consequently, this function’s store sequence does not by itself establish final memory contents. A later dependency call—including the final call that causes termination—may modify a byte previously written to zero.
