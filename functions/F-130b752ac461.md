# F-130b752ac461

## Purpose

F-130b752ac461 conditionally configures an acquired object for one of eight supported selectors, records that selector in caller-supplied context storage, and optionally performs further object processing.

The active path requires the context gate’s low bit to be set. Configuration additionally requires a supported selector, a nonzero acquisition result, and a recorded selector different from the request.

The return value is path-dependent. It may be a context byte, an acquisition value, zero, one, or a dependency result. No uniform success/failure interpretation is established.

“Context,” “object,” “selector,” and “descriptor” identify observable roles, not established application semantics. All behavior below is derived from static evidence; no runtime tests have been performed.

### Output

The result is unsigned and 32 bits wide. Its source depends on the path:

- Disabled gate: the **second** read of the gate byte, zero-extended.
- Unsupported selector: the acquisition result, unchanged.
- Supported selector with zero acquisition: zero.
- Supported selector already recorded: the recorded byte, zero-extended.
- Changed selector: zero, one, or an unchanged nonzero result from F-25053abc6856.

No separate error channel is visible.

## Behavior

### Gate observations and acquisition

The first visible memory access is an 8-bit read at context offset `0x83C`.

If bit 0 of that first observation is clear:

- The function reads the same byte address again.
- It returns the second observed byte, zero-extended to 32 bits.
- It makes no dependency call and accesses no other context field.

The second observation does not re-evaluate the branch. If its low bit is set, the function still returns that byte rather than entering acquisition. No equality or stability guarantee between the two reads is established.

If bit 0 of the first observation is set, F-50264aad3dd0 is called without explicit arguments. No second gate read is shown on this path. The acquired 32-bit value is retained.

Selector support is checked after acquisition. An unsupported selector causes immediate return of the acquisition value unchanged. Thus, rejecting a request does not avoid acquisition or its possible side effects.

### Zero acquisition and duplicate selection

For a supported selector, a zero acquisition result causes return value zero without reading the recorded selector.

For a supported selector with nonzero acquisition, the function reads the byte at context offset `0x83F` and compares its zero-extended value with the full 32-bit request.

If they are equal, the function returns that byte’s value. No descriptor slot is read, no configuration call occurs, and no acquired-object field is inspected on this path.

The recorded-selector read occurs after acquisition. Any acquisition-induced change to that storage can affect this comparison.

All descriptor reads occur after F-unmapped-01 and before F-c1912e260c49. No dependency call intervenes between these slot reads. Their contents must not be treated as an entry-time snapshot.

Once the final descriptor value has been obtained, the function:

1. Calls F-c1912e260c49 with the acquired object and that descriptor value.
2. Reads the 32-bit context field at `0x2C`.
3. Makes the configuration invocation associated with F-9c31c3e85ab1, supplying three explicit arguments: the object, integer 1, and the context value just read.
4. Writes the requested selector into the byte at context offset `0x83F`.

Neither configuration result is consumed. If the calls return normally, no checked result suppresses the selector write.

The `0x2C` read occurs after both F-unmapped-01 and F-c1912e260c49. Their effects may therefore influence the argument obtained from that field.

Every supported selector fits in eight bits, so the byte write preserves the complete accepted selector value.

### Optional object processing

After the selector write, the function reads the object’s 32-bit field at `0x14`.

If that observation is zero, the function returns zero without reading the byte at `0x24`.

If it is nonzero, the function reads the byte at `0x24`. A clear low bit causes return value zero. The remaining bits do not enable processing.

These are post-configuration observations. They need not match any object state that existed before the configuration dependencies ran.

If both conditions hold, F-8521306e7404 is called with the object:

- A zero result causes return value one.
- Any nonzero signed 32-bit result, including a negative result, enables further processing.

On the nonzero path, F-56fd8d6069bf is called with the object. Its first result is compared as a signed 32-bit value against −1, whose 32-bit bit pattern is `0xFFFFFFFF`.

- If the first result is −1, no repeat call occurs.
- Otherwise, F-56fd8d6069bf is called a second time with the same object. The second result is ignored.

Both cases then reach a two-explicit-argument invocation of F-9c31c3e85ab1 with the object and integer 1. Its result is ignored. F-c152301dad82 is called next with the object.

If F-c152301dad82 returns zero, the function returns zero without calling F-25053abc6856.

For a nonzero F-c152301dad82 result, F-25053abc6856 is called with the object:

- A nonzero result is returned unchanged as a 32-bit value.
- A zero result causes a fresh 32-bit read at object offset `0x14`. That freshly read value is passed to F-ba734f17277e, whose result is ignored. The function returns zero.

There is no new nonzero guard on this final field value. It may differ from the earlier condition value and may be zero.

## Side effects

### Direct memory effects

The only direct write shown is the 8-bit selector update at context offset `0x83F`.

It occurs only after supported-selector, nonzero-acquisition, and differing-recorded-selector checks have succeeded and the configuration calls have returned normally. It precedes all optional-processing field reads and calls.

Later zero results do not undo this write. However, later dependencies may modify the same storage; the write does not establish the context’s final contents after all dependencies return.

Direct reads include:

- One gate-byte read on the active path, or two on the disabled path.
- The recorded-selector byte when reached.
- The complete ordered descriptor-slot sequence for a changed selector.
- The context word at `0x2C`.
- The conditionally reached object fields, including the distinct final reread of `0x14`.

No explicit allocation, copying operation, deallocation, or direct object-field write is shown.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. They assume valid reached accesses and normal return from invoked dependencies. Any required stability is stated explicitly.

1. **Stable disabled gate.** With the gate byte stable at `0xA4` across both reads, the function returns `0x000000A4`. No dependency is called, regardless of the selector.

3. **Unsupported request still acquires.** With the first gate observation enabled, selector 4, and acquisition result `0x12345678`, acquisition occurs once and the result is `0x12345678`. No recorded-selector or descriptor-slot read follows.

4. **High-bit selector remains unsupported.** With an enabled first gate observation and selector `0xFFFFFFFF`, the acquisition result is returned unchanged.

5. **Zero acquisition skips later accesses.** For supported selector 13 and zero acquisition, the result is zero. The recorded selector, descriptor slots, and object fields are not read.

6. **Duplicate selector skips configuration.** For selector 21, nonzero acquisition, and recorded byte 21 as observed after acquisition, the result is 21. No descriptor slot or object field is read.

8. **Selector 13 uses the initial slot alone.** For changed selector 13, S-13 is read after F-unmapped-01, with no additional descriptor-slot read. Its value is passed onward.

9. **Upper selector branch preserves its full sequence.** For changed selector 21, the slot reads are S-13, S-14, S-15, S-21. Only the value from S-21 is passed onward.

10. **Recording precedes skipped optional processing.** For changed selector 3, the configuration path writes 3 at `0x83F` before reading object offset `0x14`. If that field is zero, the result is zero and `0x24` is not read.

11. **Zero first processing result yields one.** If both object conditions hold and F-8521306e7404 returns zero, the result is one. F-56fd8d6069bf is not called.

14. **Final field reread may yield zero.** If optional processing was enabled but the final `0x14` observation is zero, a zero F-25053abc6856 result causes F-ba734f17277e to receive zero. No additional nonzero check intervenes.
