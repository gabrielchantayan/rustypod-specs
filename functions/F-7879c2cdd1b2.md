# F-7879c2cdd1b2

## Purpose

F-7879c2cdd1b2 performs one of two ordered dependency-call sequences, selected by whether its input equals 17. After that sequence completes, it compares the original input with a byte obtained through shared state and returns a 32-bit result: 2 for equality, 0 otherwise.

The comparison is separate from sequence selection. Selecting the sequence for input 17 does not itself imply success; selecting the other sequence does not imply failure. The result depends on the byte observed after the selected calls have returned.

The meanings of the dependency operations and the shared byte are not established. Interpreting this function as configuring a mode and then checking the active mode is plausible intent, not part of the established contract.

## Interface

- One integer argument, treated as a 32-bit integer by the supplied representation.
- The input is compared with the integer value 17 without narrowing it to a byte.
- No input pointer, caller-provided output buffer, explicit length, or ownership-bearing argument is visible.
- No range validation is visible. Values outside the range representable by the shared byte still select a call sequence and reach the final comparison if all preceding operations return normally.

**Output**

- One 32-bit scalar result.
- The only explicit normal-return values are:
  - 2 when the input equals the integer interpretation of the sampled byte.
  - 0 when it does not.

## Behavior

### Sequence selection

The function first decides whether the input equals 17. It selects exactly one of the following two sequences.

For input 17:

1. Invoke F-EXT-02 with the integer argument 35.
2. After that invocation returns, invoke F-9956f7343fc0 with integer arguments 16 and 1, in that order.

For every other input:

1. Invoke F-EXT-01 with the integer argument 12.
2. After that invocation returns, invoke F-EXT-02 with the integer argument 30.
3. After that invocation returns, invoke F-EXT-03 with the integer argument 28.
4. After that invocation returns, invoke F-EXT-04 with the integer argument 30.
5. After that invocation returns, invoke F-EXT-05 with the integer argument 12.

The arguments above are literal integer values, not values derived from the input. The input is used to choose a sequence, but it is not visibly passed to any dependency.

Each sequence is ordered. The supplied representation does not show parallel invocation, deferred dispatch, a retry, or a repeated attempt. If an invocation does not return, subsequent calls and the final comparison are not reached through the visible control flow.

### Post-sequence state sampling

Only after the selected sequence returns does the function evaluate the shared-state comparison.

The visible access relationship is:

1. Obtain the base address from its shared location.
2. Read the byte located one byte after that base.
3. Interpret that byte as an integer according to the applicable character signedness.
4. Compare that integer with the original 32-bit input.

There is no visible pre-sequence snapshot of either the base address or the comparison byte. Consequently, dependency effects on that shared state can affect the result. In particular, dependencies might replace the base address, change the referenced byte, or invalidate the referenced storage. Which of these actions they actually perform is unknown.

The contract must not substitute an entry-time byte for the post-call byte. Nor may it assume that the same base address remains installed across the dependency calls.

### Comparison and result

The input is compared as an integer; the supplied representation does not truncate the input to eight bits before comparison.

For bytes from 0 through 127, signed and unsigned character interpretations produce the same integer. For bytes from 128 through 255:

- Under unsigned interpretation, the comparison values are 128 through 255.
- Under signed 8-bit interpretation, the comparison values are −128 through −1.

Equality produces the 32-bit value 2. Inequality produces the 32-bit value 0.

No addition, subtraction, multiplication, mask, or wraparound transformation is applied to the input. The only visible address arithmetic selects the byte at base plus one. Behavior for an invalid or overflowing address calculation is not specified by the supplied evidence.

### Failure and interruption boundaries

The function does not visibly inspect dependency results or translate dependency failures into an error code. Returning 0 means the final comparison was unequal; it is not an established general-purpose failure report.

No local rollback, cleanup, exception handler, or compensating operation is visible. If an earlier dependency changes state and a later operation fails to return normally, the supplied representation establishes no restoration of the earlier state.

The last case distinguishes integer equality from low-byte equality: 273 has low byte 17, but the input is not narrowed before comparison.

Additional boundary and state-transition cases:

- **Post-call byte change:** If the input is 17, the byte is initially 17, and the selected dependencies leave the final byte as 0, the result is 0. The initial match is not sufficient.
- **Base replacement:** If a dependency replaces the shared base address and the newly referenced byte at offset one equals the input, the result is 2, provided the final access is valid. The old referenced byte does not control the comparison.
- **High-bit byte, signed interpretation:** For input −1 and sampled byte 255, the result is 2 if that byte is interpreted as signed 8-bit −1.
- **High-bit byte, unsigned interpretation:** For the same input and byte, the result is 0 if the byte is interpreted as unsigned 255.
- **Wide input:** Input 256 cannot equal any signed or unsigned 8-bit interpretation, so a valid completed execution returns 0.
- **Interrupted sequence:** If F-EXT-03 does not return normally, the visible path does not reach F-EXT-04, F-EXT-05, or the final comparison. No normal return value is established.
