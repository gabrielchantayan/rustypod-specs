# F-395e6c78b2ba

## Purpose

F-395e6c78b2ba performs an ordered sequence of memory reads and writes using one explicit 32-bit argument and three additional, externally supplied machine-state values. It finishes by invoking an unresolved indirect target with four arguments.

The established behavior is memory mutation and indirect control transfer. No application-level purpose, object model, or successful-result condition is established. In particular, the evidence does not justify describing the routine as initialization, serialization, allocation, or a validated dispatch operation.

The repeated writes, low absolute addresses, overlapping accesses, and unresolved execution context make a conventional standalone API contract inappropriate. This specification therefore describes a conditional machine-state contract: behavior is defined only to the extent that the required incoming state, memory accesses, arithmetic, and indirect target are meaningful on the execution platform.

## Behavior

### 1. Repeated opening mutation

The routine performs eight consecutive repetitions of the same four-write sequence. Each repetition writes, in this order:

| Destination | Width | Value |
|---|---:|---|
| 2 × A + 0x54 | 32 bits | P |
| B + 0x19 | 8 bits | Low byte of A |
| A + 0x11 | 8 bits | Low byte of B |
| B + 0x34 | 32 bits | 2 × A |

There are 32 visible stores in this opening stage.

The multiplication involving A is unsigned 32-bit arithmetic. Its result is reduced modulo 2³². Address construction involving that result must also be interpreted under the actual 32-bit addressing rules.

The eight repetitions must not be collapsed into a single repetition when defining observable behavior. They may matter for memory-mapped devices, instrumented memory, concurrent observation, faults, or overlapping destinations. Even without such observers, overlap between the four destinations can affect the resulting bytes.

### 2. Initial snapshots and absolute-location updates

After the eighth repetition, the routine captures these values in the following order:

1. A 32-bit word from absolute address 0xA9; call this **G**.
2. A 32-bit word from P + 0x74; call this **H**.

It then writes one byte at absolute address 0x3A. The stored byte is the low eight bits of twice the low byte of A, plus 0x30. This is arithmetic byte construction, not an established digit-formatting operation.

Next it captures:

- A 32-bit word from C + 0x14; call this **S**.
- A 32-bit word from A + 0x04; call this **R**.

In order, it then:

- Writes the low byte of A at C + 0x0D.
- Writes byte 0x6C at A + 0x08.
- Writes the low byte of B at A + 0x0D.
- Writes the low byte of B at A + 0x09.
- Writes C as a 32-bit word at C + 0x54.
- Writes the low byte of G at absolute address 0x67.

G, H, S, and R are snapshots. Later writes to their originating locations do not change these captured values.

### 3. Intermediate mutation and overlapping word store

The routine next reads a 32-bit signed value from C + 0x44; call it **X**.

It reads the byte at absolute address 0x67 and copies that byte to absolute address 0x21. This is a read of the location at that point, not an unconditional reuse of the previously captured low byte of G. For example, the intervening read at C + 0x44 could have device-visible effects in a platform-specific memory model.

The next writes occur in this order:

- Low byte of X to A + 0x10.
- X as a word to B + 0x54.
- Low byte of the result of signed right-shifting X by the low byte of A, to C + 0x01.
- A as a word to B + 0x54.

Thus B + 0x54 receives two word writes in this stage. The first must not be discarded from the observable contract merely because the second uses the same address.

The routine then captures a word from A + 0x40; call it **U**. Subsequently it:

- Writes R as a word at B + 0x74.
- Writes U as a word at A + 0x10.
- Writes C as a word at B + 0x44.
- Reads the byte at absolute address 0x67 and writes it at A + 0x09.
- Writes the low byte of A at C + 0x09.
- Writes G as a word at A + 0x44.

The word write at A + 0x10 covers offsets 0x10 through 0x13. It therefore overlaps both the earlier byte at A + 0x10 and the opening-stage byte at A + 0x11. The resulting byte pattern depends on platform byte order.

### 4. First derived address and further snapshots

The routine reads a word from A + 0x54 and uses its bit pattern as an address base; call this **D**.

After that read, it:

- Reads the byte at absolute address 0x67 again and writes it at A + 0x09.
- Writes the low byte of H at D + 0x0D.
- Writes S as a word at C + 0x54.

The two reads of absolute address 0x67 that supply A + 0x09 in this and the preceding stage are distinct accesses. The intervening mutations may affect their results through aliasing or platform-specific memory behavior.

Next the routine captures a word from A + 0x14; call this **V**. It then writes:

- Low byte of H to C + 0x11.
- Low byte of D to A + 0x09.
- D as a word to A + 0x44.

The earlier word G at A + 0x44 is therefore replaced by D at this point, subject to the effects of any intervening aliases.

### 5. Additional derived addresses and final invocation

The routine reads a word from C + 0x04 and treats it as another address-bearing value; call this **E**.

It writes the 16-bit value 0x0065 at address 2 × E. This is a halfword write, not a byte write or a word write.

It then reads a word from E + 0x64; call this **Q**. The offset is decimal 100.

Next it:

- Writes the low byte of V at D + 0x11.
- Writes the word value 100, equivalently 0x00000064, at D + 0x54.
- Reads a word from E + 0x74; call this **W**.
- Reads a word from C + 0x64 and treats it as an address-bearing value; call this **J**.
- Writes the low byte of E at C + 0x09.
- Writes Q as a word at J + 0x54.
- Writes J as a word at address 2 × Q.

The order is significant. For example:

- The halfword write at 2 × E precedes the read at E + 0x64.
- The word write at D + 0x54 precedes both the read at E + 0x74 and the read at C + 0x64.
- The write at J + 0x54 precedes the write at 2 × Q.

Any overlap can therefore change later reads or final memory contents.

Finally, the routine invokes T with the ordered arguments 0x72, Q, S, and W.

### Arithmetic limits

## Acceptance examples

### Repeated opening stores

### Intermediate overwrite remains observable

If B + 0x54 is observable and execution completes the intermediate stage, that location receives X and then A as two separate word writes. An implementation that writes only A does not preserve the established access sequence.

### Snapshot survives later replacement

Suppose the read at C + 0x14 returns 0x11223344, subsequent accesses complete, and no unspecified target behavior intervenes. The later word store to C + 0x54 uses 0x11223344, and the third argument of the final invocation also uses 0x11223344. Neither use reloads C + 0x14.
