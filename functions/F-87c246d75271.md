# F-87c246d75271

## Purpose

F-87c246d75271 requests an address-like result and incorporates that result into a mutable object containing two four-word records and an address table. It selects among three behaviors:

- Establish a table reference and initialize both records.
- Replace the table reference when the first record’s entry address equals the table base.
- Write the address-like result into the entry immediately preceding the first record’s entry address.

The supplied body establishes calls to F-871e64ddc6de with size-like arguments, followed by use of its results as addresses. It does **not** establish that this dependency allocates storage, returns fresh storage, or transfers ownership. References below to allocation-like requests describe the call pattern, not a proven allocation contract.

The apparent intent is front extension of segmented storage. This is an inference from the table and record operations; neither a public container type nor element-level semantics is established.

## Interface

### Arguments and representation

The function receives four arguments:

1. An address of mutable state, called **O** below.
2. Three additional 32-bit words.

Addresses and stored words are represented as 32-bit quantities. Table entries occupy four bytes. The visible object layout is:

| Word index | Byte offset | Observed role |
|---|---:|---|
| 0–3 | 0–15 | First four-word record |
| 4–7 | 16–31 | Second four-word record |
| 8 | 32 | Not directly accessed |
| 9 | 36 | Address-table base |
| 10 | 40 | Table-related size word |

Words 3 and 7 serve as addresses of table entries. The semantic roles of the other record fields are unknown.

Before calling any dependency, the function initializes a writable four-word working tuple, **T**, from the arguments. Its first word is the 32-bit representation of O’s address; its remaining words are the three additional arguments. F-146172650e74 subsequently receives T’s address and can change these words. The additional arguments therefore seed the tuple; they are not necessarily the eventual record contents.

### Result

The normal return value is 64 bits:

- Bits 0–31 contain T’s final first word.
- Bits 32–63 contain T’s final second word.

This is bit concatenation. No signed extension or public pair type is established.

On the replacement path, the return uses T after the second F-146172650e74 call. On the other paths, it uses T after the sole such call.

### Preconditions and failure interface

The visible body does not validate addresses, alignment, storage extents, arithmetic ranges, table consistency, dependency results, or request success. It contains no explicit error return, rollback, or recovery branch.

A safe invocation requires accessible storage for every executed read and write, usable address results, and arithmetic and dependency behavior compatible with the selected path. Object accesses extend through byte offset 43. Table accesses may require additional storage whose extent depends on the state and dependency results.

These are requirements for safe execution, not checks supplied by the function. Failure behavior outside normal dependency returns is **documented_only**.

## Behavior

### Arithmetic and observation rules

Words, address results, and intermediate size calculations are 32 bits wide. Offsets are byte offsets; adding four advances one table entry.

Halving in the initialization path uses an unsigned right shift. The replacement path derives an entry distance using a signed right shift by two after a 32-bit subtraction. Those operations are not interchangeable for high-bit-set inputs.

The formulas below describe ordinary, nonoverflowing cases directly. The supplied representation exposes 32-bit operations but does not establish a portable source-language contract for signed overflow, invalid pointer arithmetic, or address wraparound. No implicit wider arithmetic, saturation, or bounds protection is established.

Each call to F-3087ac887d1d is a separate observation. Its results need not agree. Dependencies are not assumed to preserve O or other reachable state. Where a later operation rereads O, it uses that later state rather than an earlier conceptual snapshot.

### Common request and branch selection

After initializing T, the function calls F-3087ac887d1d. It shifts that result left by two bits and passes the resulting 32-bit size-like word, followed by zero, to F-871e64ddc6de. The returned word is retained as **B** and later used as a block-like address.

This request precedes the call to F-f517d58e1476 with O. Consequently, even a state that selects initialization has already caused the first allocation-like request.

A nonzero predicate result selects initialization. A zero result leads to a comparison of O word 3 with O word 9:

- Equal addresses select replacement.
- Unequal addresses select preceding-entry insertion.

These object reads occur after the predicate call. The comparison does not test address ordering, table capacity, or whether the preceding entry is valid or unused.

### Initialization

This path makes a second allocation-like request. It calls F-3087ac887d1d, shifts the returned word left by two, and calls F-871e64ddc6de with that size-like word and zero. It stores the address-like result into O word 9.

A further F-3087ac887d1d call supplies the word stored into O word 10. Using this result as unsigned, the function writes B to the table entry at:

**current table base + 4 × unsigned half of that result.**

The function then calls F-3087ac887d1d again. This final query occurs **after** the table-entry write. F-146172650e74 receives:

| Argument | Value |
|---|---|
| First | Address of T |
| Second | B + 4 × unsigned half of the latest query result + 4 |
| Third | Current O word 9 + 4 × unsigned half of current O word 10 |

The third argument uses object fields read after the final query. If that query changes relevant state, this address may differ from the entry previously written.

After the helper returns, T’s four words are stored into O words 0–3 in ascending word order. The function then copies the first record into the second through ordered read/write pairs: word 0 to word 4, then 1 to 5, 2 to 6, and 3 to 7. This is not an established atomic record copy.

There are four size-query calls on this path, including the common query. The block request, table request, stored size, and block-interior address derive from distinct observations. No equality among their results is required by the visible body.

No old-table release-like call occurs on this path, regardless of the state present before initialization.

### Replacement

Replacement is selected by equality between the first-record entry address and the table base. Let **A** be the word-3 value used in that comparison.

Before requesting replacement storage, the function reads O word 7 and derives:

- **N:** the signed-right-shift-by-two result of the 32-bit difference between that word and A.
- **M:** N + 1.
- **U:** the 32-bit word formed by doubling M.

It calls F-871e64ddc6de with a size-like argument of **8M** and a second argument of zero. Let its returned address-like word be **R**.

For ordinary nonnegative values, the request corresponds to space for twice M four-byte entries. This interpretation does not establish that storage is actually allocated or that the request is adequate under arbitrary state mutation.

After this dependency returns, the function rereads O word 7 as a saved copy endpoint. It also forms **D** by clearing the low two bits of U. D is used directly as a byte offset: it is **not** multiplied by four.

The copy source starts at the then-current O word 3. The stopping address is the saved endpoint plus four bytes. For a consistent ascending range, both endpoint entries are copied.

Destination placement has an important asymmetry:

- B’s eventual slot is R + D.
- The first copied entry is written at R + D + 4.
- Further copied entries occupy successive four-byte slots.

The destination advances before each termination check, including the final check that performs no write. A source initially equal to the stopping address therefore causes no entry read or write.

The source range is observed after the replacement request, whereas N and U were computed before it. If F-871e64ddc6de changes O, the copied range and the earlier size calculations can disagree.

After copying, the function calls F-ff1bdc376dcd with the then-current O word 9, the then-current O word 10, and zero. It does not pass an independently saved original base and size.

Only after that call returns does the function store R into O word 9 and write B at R + D. It then calls F-3087ac887d1d and invokes F-146172650e74 with T’s address, **B + four times the latest query result**, and **current O word 9 + D**.

The returned T is stored into O words 0–3 in ascending order. A second F-146172650e74 call then receives:

| Argument | Value |
|---|---|
| First | Address of the same T, without resetting it |
| Second | Current O word 4 |
| Third | Current O word 9 + D + 4N + 4 |

N is the earlier saved distance, not a recomputed distance. The current object fields can reflect mutations by intervening dependencies.

The second helper’s resulting T is stored into O words 4–7 in ascending order. O word 10 is then set to U. The return uses the tuple left by this second helper.

Thus the replacement base is installed before the record helpers, but the replacement size word is installed only after both record writes.

### Preceding-entry insertion

When the compared addresses differ, the function subtracts four bytes from the previously read O word 3. It stores this preceding address into O word 3 and writes B to that address.

It next calls F-3087ac887d1d. F-146172650e74 receives T’s address, B plus four times the returned word, and the **current** O word 3.

The table-entry write uses the preceding address calculated before the query. The helper’s third argument rereads O word 3 after the query; the two addresses need not agree if that dependency changes state.

After the helper returns, T is stored into O words 0–3 in ascending order. This path performs no direct writes to words 4–7, 9, or 10. Dependencies may nevertheless affect them.

## Side effects

### Direct effects and dependency-mediated effects

The function directly performs object-field writes, table-entry writes, and, on replacement, entry-by-entry table copying. It also exposes T to F-146172650e74 and invokes dependencies with size-like and address-like arguments.

Storage allocation is **not** an established direct effect. F-871e64ddc6de is called once on preceding-entry insertion and twice on initialization or replacement. Its returned words are used as addresses. If its external contract supplies allocation semantics, these calls may allocate storage; that remains conditional.

Likewise, F-ff1bdc376dcd is release-like only by interpretation. Its actual memory and ownership effects are unknown.

O word 8 is neither directly read nor directly written. No record update, table replacement, or combined base-and-size update is established as atomic.

### Ownership and lifetime

The visible body does not establish freshness, exclusive ownership, transfer of ownership, or reclamation for B or either table result. It does not establish whether returned storage is initialized or disjoint from O, existing table storage, or other reachable memory.

Only replacement calls F-ff1bdc376dcd. That call occurs after copying and before installing R. There is no visible release-like call for B and no explicit cleanup path for an interrupted operation.

These facts do not independently establish a leak, successful reclamation, or valid ownership transfer. Such conclusions require dependency contracts.

No rollback is visible. If execution stops during a dependency or memory access, earlier writes may already have occurred. Which failures are possible, and how they propagate, remain unresolved.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, assume accessible disjoint storage, ordinary returning dependencies, no arithmetic overflow, and no dependency mutations except the specified changes to T.

### Initialization with stable query results

If all four size queries return eight and the predicate is nonzero:

- The first F-871e64ddc6de call receives 32 and zero.
- The second receives 32 and zero.
- O word 10 becomes eight.
- B is written at the returned table base plus 16 bytes.
- F-146172650e74 receives B plus 20 bytes and the table base plus 16 bytes as its address-like arguments.
- Both records receive the helper’s resulting tuple.
- The return places that tuple’s first word below its second word.

These expectations concern call arguments and memory operations. They do not prove either request allocates storage.

### Unequal addresses with an accessible preceding entry

Suppose the predicate returns zero, O word 3 equals the table base plus 12 bytes, and the subsequent size query returns eight.

The function first sets O word 3 to the table base plus eight bytes and writes B there. The record helper receives B plus 32 bytes and that preceding-entry address. Only the first record is directly rewritten afterward. No second F-871e64ddc6de call or F-ff1bdc376dcd call occurs.

The accessibility of that preceding entry is an example precondition, not a result of the inequality check.

### Replacement of a consistent three-entry range

Suppose O word 3 equals the table base and O word 7 is eight bytes beyond it.

N is two, M is three, U is six, and D is four bytes. Accordingly:

- The replacement request receives 24 and zero.
- The existing entries are copied to R plus 8, 12, and 16 bytes.
- B is written at R plus four bytes.
- The first record helper receives R plus four bytes as its table-entry argument.
- The second receives R plus 16 bytes as its third argument.
- O word 10 is finally set to six.

The first helper’s block offset uses four times the full latest query result, without halving.

### Independent initialization query results

Suppose the four initialization-path query results are eight, twelve, ten, and six, respectively.

The first request receives 32, the table request receives 48, and O word 10 becomes ten. B is written at the table base plus 20 bytes. The record helper receives B plus 16 bytes and the table base plus 20 bytes.

This case distinguishes the request size, stored size, and block-position query.

### Replacement return depends on the second helper

Suppose the first helper leaves T’s first two words as P and Q, and the second leaves them as X and Y.

The first record receives the first helper’s tuple. The second record receives the second helper’s tuple. The return contains X in its low 32 bits and Y in its high 32 bits, not P and Q.

A malformed range that cannot reach that address by successive four-byte increments has no established safe outcome. The earlier size calculation does not bound the later copy.
