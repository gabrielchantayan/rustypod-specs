### Field comparison

After a nonzero dependency result, the function reads the unsigned field at the computed address. The supplied representation contains one explicit field-read expression on this path.

The loaded value is combined with the second input using bitwise AND. That masked value is compared for exact equality with the third input.

The expected value is not masked before comparison. Consequently:

- Bits excluded by the mask do not affect the comparison.
- Bits included by the mask must match the corresponding expected bits exactly.
- Any set bit in the expected value that lies outside the mask makes equality impossible for any successfully loaded field value.
- A zero mask yields a masked value of zero, so the comparison succeeds exactly when the expected value is zero.
- Under a fixed-width unsigned interpretation, an all-ones mask makes the comparison equivalent to exact equality with the entire field.

These are equality semantics, not a general “any requested bit is set” test. A nonzero overlap can still fail when it differs from the expected value.

Even when the mask is zero, or the expected value makes equality mathematically impossible, the supplied representation evaluates the field-read expression after a successful dependency gate. It contains no separate shortcut for either case. Whether optimized machine code retains a physical memory transaction in such cases is not established by this representation; volatile or device-memory semantics are not shown.
