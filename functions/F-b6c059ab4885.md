# F-b6c059ab4885

## Purpose

F-b6c059ab4885 dispatches to an indirect target according to a signed integer selector. It acquires a table-base value from external state and chooses one of four fixed-offset target slots.

Selectors 1 and 2 select targets invoked with three explicit argument values: a later-loaded pointer, integer zero, and integer one. Selector 3 and all other selector values select targets with no explicit arguments represented.

For selectors 1 and 2, target selection and first-argument acquisition use separate evaluations of the external base. The selected target therefore need not belong to the same object or state snapshot as the pointer passed to it.

The established behavior is dispatch, not an application-specific operation. The meanings of the selectors, the purposes of the targets, and their effects are not supplied.

The sole explicit input is a selector passed by value and represented as a signed integer. It is compared exactly against 1, 2, and 3. No masking, normalization, range restriction, or unsupported-selector rejection is represented.

## Behavior

### Common acquisition and selection

Every selector path first evaluates G, reads P from the field at A0 plus 4 bytes, and reads B through P. This acquisition precedes target dispatch even for an unrecognized selector.

The captured B supplies the base for exactly one selected target slot:

| Selector | Target-slot offset | Opaque dependency ID | Explicit arguments |
|---|---:|---|---|
| 1 | 120 | F-U01 | Q, zero, one |
| 2 | 124 | F-U02 | Q, zero, one |
| 3 | 144 | F-U03 | None represented |
| Every other signed value | 140 | F-U04 | None represented |

These dependency IDs identify dispatch roles. They do not assert that the slots contain different function addresses. Multiple slots may resolve to the same target.

The selector chooses among fixed offsets. It is not multiplied into an index or otherwise used to calculate a variable slot offset.

After the initial acquisition, B is retained. No further read through P is represented to refresh it. Later changes to the integer stored through P do not cause a new table-base acquisition in the represented flow.

### Selectors 1 and 2

For these selectors, the target-pointer load occurs before the later argument acquisition:

- Selector 1 loads T from the slot at B plus 120 bytes.
- Selector 2 loads T from the slot at B plus 124 bytes.
- After that load, G is evaluated again to obtain A1.
- Q is read from the field at A1 plus 4 bytes.
- The selected target receives Q, integer zero, and integer one as its three explicit argument values.

This is an ordering constraint on observable acquisitions: the initial G evaluation precedes the initial pointer read; that read precedes the integer read through P; the integer read precedes the selected target-pointer read; and the target-pointer read precedes the later G evaluation and pointer-field read.

The dispatcher does not dereference Q while forming the arguments. It passes the pointer value acquired by the later field read. It neither substitutes B for Q nor derives a new target-table base by reading through Q.

There is no equality check between P and Q, between A0 and A1, or between the address represented by Q and the address encoded by B. Any of those values may coincide where the actual layout permits it.

If G changes between its evaluations, the later pointer read may address a different field in a different object. If G remains unchanged but its pointer-bearing field changes, Q may differ from P. Neither case triggers comparison, retry, or target reselection.

Once T has been loaded, subsequent changes to the table slot or external state do not replace the retained target in the represented flow. This describes acquisition and use in the supplied representation, not a guarantee about atomicity or unsynchronized concurrent execution.

### Selector 3

Selector 3 selects the target at B plus 144 bytes and transfers control to it with no explicit arguments represented.

This path has no represented second evaluation of G and no acquisition of Q.

The absence of explicit arguments does not require cleared argument registers, an empty argument area, or any particular inherited machine state. Whether the target interprets such state is unknown.

Like selector 3, this path has no represented second evaluation of G, no Q acquisition, and no explicit target arguments.

If the selected target returns through the represented flow, the dispatcher completes without further represented state acquisition or result processing. If the target does not return or transfers control nonlocally, no subsequent dispatcher behavior is established.
