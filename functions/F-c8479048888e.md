# F-c8479048888e

## Purpose

F-c8479048888e conditionally updates the third word of a caller-provided record and, when the update is accepted, optionally writes two outputs derived from that record.

The decision is based on the low bit of a 32-bit product involving the record’s third word and a shared multiplier. An even product permits the update. An odd product prevents it.

The routine has three return paths:

- A null record returns a shared null-record status value.
- A non-null record whose tested product is odd returns a shared rejection status value.
- An accepted record is updated and returns the literal 32-bit value zero.

The numerical values of the shared multipliers and status values are not supplied. Consequently, the evidence does not establish that the three return paths have distinct numerical results.

An interpretation in terms of claiming a record, consuming an entry, or changing an availability flag is **inferred intent**, not an established contract. The established behavior is the arithmetic decision and the ordered memory effects described below.

## Interface

### Arguments

The routine receives three pointer arguments, in this order:

| Argument | Role | Null handling |
|---|---|---|
| Record pointer | Addresses three consecutive 32-bit words | Explicitly checked; null selects an immediate status return |
| Scaled-output pointer | Optional destination for a 32-bit integer derived from the record’s second word | Null skips this output |
| First-word-output pointer | Optional destination for a copy of the record’s first word | Null skips this output |

The record layout is:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Source for the optional first-word output |
| 4 | 32 bits | Source for the optional scaled output |
| 8 | 32 bits | Decision input and update destination |

The first and third arguments are represented as pointers to four-byte words. The second is represented as a pointer to an integer. This contract treats its destination as a 32-bit integer object, consistent with the supplied representation. Independent confirmation of the target integer ABI is unavailable.

No length, capacity, ownership tag, or record-type discriminator is passed.

### Shared values

For descriptive purposes, the routine accesses five shared values:

- **Null-record status:** returned when the record pointer is null.
- **Decision multiplier:** multiplied by the record’s third word for the parity test and again when forming an accepted update.
- **Update multiplier:** multiplied by the odd-valued intermediate used for the update.
- **Rejection status:** returned when the tested product is odd.
- **Output multiplier:** multiplied by the record’s second word for the optional scaled output.

These are descriptive labels, not additional interface arguments. Their values, mutability, initialization requirements, and relationships are unknown.

### Return value

The return occupies a four-byte value:

- Null record: the null-record status.
- Odd decision product: the rejection status.
- Accepted update: zero.

There is no separate Boolean result, output-validity flag, or returned pointer.

### Preconditions

For a non-null record, the third word must be readable. If acceptance occurs, that word must also be writable.

Additional access requirements depend on which optional outputs are requested:

- A non-null first-word-output pointer requires a writable four-byte destination and a readable first record word.
- A non-null scaled-output pointer requires a writable 32-bit integer destination and a readable second record word.

The routine performs no visible validation of non-null pointers, alignment, allocation size, or lifetime. Invalid accesses have no specified recovery behavior.

No non-overlap requirement is established. Where arguments overlap valid storage, the operation order matters.

## Behavior

### Arithmetic model

Let:

- \(W\) denote a value read from the record’s third word.
- \(D\) denote a value read from the decision multiplier.
- \(U\) denote a value read from the update multiplier.
- \(M\) denote a value read from the output multiplier.

Products used here are interpreted by their low 32 bits. Define:

\[
\operatorname{low32}(x)=x\bmod 2^{32}.
\]

The decision product is:

\[
P=\operatorname{low32}(W\times D).
\]

Its low bit determines the branch. The decision does not test whether the whole product is zero.

For an accepted update, the stored third-word value is:

\[
\operatorname{low32}\left(U\times
\left(\operatorname{low32}(W\times D)\mathbin{\mathrm{OR}}1\right)\right).
\]

The bitwise OR sets bit zero of the intermediate product. It does **not** establish that the final stored word is odd: an even update multiplier produces an even final product.

The scaled output has the low-32-bit result:

\[
\operatorname{low32}(M\times S),
\]

where \(S\) is the second record word as read when that output is processed. No saturation or overflow error is shown. Whether a consumer interprets the stored bit pattern as a negative signed integer depends on the target integer representation.

### Null-record path

The record pointer is checked first.

If it is null:

- The null-record status is read and returned.
- Neither optional destination is written.
- Neither optional output requires a valid destination merely because its pointer is non-null.
- No record word is accessed.
- The decision, update, and output multipliers are not needed on this path.

The routine does not initialize outputs on this path.

### Decision and rejection

For a non-null record, the routine reads the third word and the decision multiplier to form the decision product.

If bit zero of that product is one:

- The rejection status is read and returned.
- The routine performs no explicit memory write.
- Neither optional output is processed.
- The first and second record words are not needed.

The relative evaluation order of the two operands of the multiplication is not established. The contract establishes that the decision reads occur before any accepted-path write, not a particular machine-load ordering between operands.

### Accepted update

If bit zero of the decision product is zero, the routine computes and stores a replacement third word.

The update expression reads the third word and the decision multiplier again. It does not visibly reuse a saved decision product. It also reads the update multiplier.

This distinction matters if shared storage can change between accesses. With stable inputs, the two third-word/decision-multiplier products agree. Without a stability guarantee, the value used to construct the replacement need not equal the value tested by the branch.

The replacement is written to byte offset 8 before either optional output is processed.

### Optional first-word output

After the third-word update, the routine checks the first-word-output pointer.

If non-null, it reads the record word at byte offset 0 and writes that four-byte value to the destination.

This source read occurs after the record update. The routine does not take an initial snapshot of the record’s first word.

### Optional scaled output

After the first-word output has either completed or been skipped, the routine checks the scaled-output pointer.

If non-null, it reads the record word at byte offset 4 and the output multiplier, multiplies them, and stores the 32-bit result at the destination.

This source read occurs after the preceding optional output write. A preceding write that aliases the second record word therefore affects the value used here.

After the requested outputs are processed, the routine returns zero.

### Aliasing and ordering

The established accepted-path write order is:

1. Replacement third word.
2. First-word output, if requested.
3. Scaled output, if requested.

Consequences for valid overlapping storage include:

- If the first-word-output destination is the third record word, it overwrites the newly computed update.
- If the first-word-output destination is the second record word, the scaled output uses the copied first-word value as its source.
- If the scaled-output destination is a record word, that word receives the scaled result after the update and first-word output.
- If both output pointers designate the same compatible destination, the scaled-output write occurs last.

Thus, an accepted call does not unconditionally leave the third record word equal to the update formula: a later output write may overwrite it.

These consequences describe ordering for valid accesses. They do not establish that arbitrary casts, partial overlaps, misalignment, or incompatible object accesses are valid on the target platform.

## Side effects

The routine has no visible allocation, deallocation, callback, I/O, or explicit synchronization operation.

Caller-provided storage remains caller-provided storage. The routine does not visibly retain a pointer or transfer ownership.

On acceptance, one record write is mandatory and up to two output writes follow. On null-record and rejection paths, there are no explicit writes.

The routine directly reads shared values. It does not explicitly write them, although a caller-supplied destination that can legally alias shared storage could affect later reads. No independent guarantee of such aliasability is supplied.

There is no visible rollback mechanism. If an accepted call updates the record and a subsequent output access fails, the evidence does not establish restoration of the record or of an earlier output.

The decision and replacement are separate operations. No atomic compare-and-update, lock, or concurrency guarantee is shown. Treating the routine as a thread-safe claim operation would require evidence beyond this body.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied body. They are not reports of executed tests.

### Null record leaves outputs untouched

Given a null record pointer and otherwise arbitrary output-pointer values:

- The returned value is the null-record status.
- Neither output destination is accessed.
- No decision or record update occurs.

This remains the expected branch behavior even if an unused output pointer would be invalid to dereference.

### Odd decision product rejects without writes

Given valid readable third-word storage containing 3 and a stable decision multiplier of 5:

- The decision product is 15.
- The returned value is the rejection status.
- The record and both output destinations receive no explicit writes.

The first and second record words need not be read.

### Accepted update with no outputs

Given a third word of 2, a stable decision multiplier of 3, an update multiplier of 5, and both output pointers null:

- The decision product is 6, so the update is accepted.
- Setting its low bit produces 7.
- The third word becomes 35.
- The return is zero.

### Requested outputs use their respective sources

Given a record whose first two words are 11 and 7, whose third word is 2, and stable multipliers of 3 for the decision, 5 for the update, and 4 for the output:

- The third word is first written as 35.
- A separate first-word destination receives 11.
- A separate scaled destination receives 28.
- The return is zero.

### Earlier output can change a later source

Given the preceding values, but with the first-word-output destination pointing to the second record word:

- The update first writes 35 to the third word.
- The first-word output changes the second word from 7 to 11.
- A separate scaled destination receives 44, not 28.

### Later output can replace the update

Given the same arithmetic inputs, but with only the first-word output requested and its destination pointing to the third record word:

- The third word is first written as 35.
- It is then overwritten with the first word, 11.
- The call returns zero with a final third word of 11.

### Arithmetic wraps rather than saturates

Given a third word of 4, a decision multiplier of 1, and an update multiplier of \(2^{32}-1\):

- The decision accepts.
- The odd intermediate is 5.
- The stored third-word bit pattern is \(2^{32}-5\).
- No overflow status is produced.
