# F-720d429766cc

## Purpose

F-720d429766cc conditionally initializes an object-associated resource, then selects between a full update and an eligibility-gated partial update.

The established behavior is a sequence of object-field accesses and dependency calls. The apparent intent is to maintain a cached rendering or transfer resource, process either an entire region or a caller-supplied region, and update region-tracking state. Rendering, caching, and region semantics are inferred; the contracts of the dependencies are not supplied.

The function has no explicit return value. Its externally observable results are changes to object state, dependency effects, and whether processing stops at the eligibility gate.

## Interface

### Inputs

The function accepts three arguments:

1. **Object address.** A target-width address represented by a 32-bit value in the supplied evidence. The function accesses fields through byte offsets from this address.
2. **Opaque auxiliary value.** A 32-bit value forwarded unchanged to F-5d3cf0e5d367, and only on the full-update path.
3. **Region-data address.** An address of caller-provided storage. On an admitted partial update, the function directly reads four consecutive 32-bit words, totaling 16 bytes. It also passes this address to dependencies on both update paths.

No explicit null-pointer checks, object-size checks, alignment checks, or buffer-length checks are present.

### Outputs and preconditions

There is no explicit status, resource handle, or error result returned to the caller.

For ordinary successful execution:

- The object must support the accesses listed above.
- Storage passed to dependencies must satisfy their contracts.
- The caller’s region data must provide at least 16 readable bytes if the partial path reaches its direct copy.

These are operational preconditions, not conditions validated by this function.

## Behavior

### 1. Conditional resource initialization

The function first reads the 32-bit resource slot at object offset `0x1a8`.

If it is nonzero, initialization is skipped. If it is zero, the function performs the following sequence:

1. Calls F-960363c07b32 with the object and a 16-byte local region buffer.
2. Calls F-a4c26c2b4842 with separate local context storage.
3. Calls F-7fa874cbac7a with the object and that context storage.
4. Calls F-8157a180d901 with the integer size `0xb8`, equivalent to 184 bytes.
5. Reads a 16-bit value from offset `0x14` relative to an address held in a field at displacement `0x1c` within the local context storage.
6. Calls F-f027f0bfb38b with:
   - the result of F-8157a180d901;
   - the local region-buffer address;
   - the 16-bit value;
   - three trailing zero arguments.
7. Stores the 32-bit result of F-f027f0bfb38b into the object’s resource slot.
8. Calls F-7f4cb9b761d1 with the address at object offset `0x164`, that same result, and the local region-buffer address.
9. Calls F-282eebd7c413 with the local context storage.

The allocation-like request completes before the 16-bit read used by the next call. The supplied representation does not establish the relative evaluation order of all individual argument reads within a call expression.

There is no explicit failure check after either F-8157a180d901 or F-f027f0bfb38b. A zero result from the latter is still stored and forwarded to F-7f4cb9b761d1. Initialization does not loop or retry within the same invocation.

The branch selector at `0x150` is read **after** this sequence. Initialization dependencies therefore run before path selection and may affect which path is subsequently taken. Their preservation of object fields or global state is not established.

### 2. Path selection

The function reads the byte at object offset `0x150`:

- **Zero:** enter the eligibility-gated partial-update path.
- **Nonzero:** enter the full-update path.

The branch decision is based on the value at this point, not necessarily the value present on entry.

### 3. Eligibility-gated partial update

The function calls F-3405f9d47f43 with the object.

If its result is zero, the function returns immediately. Resource initialization, if required, has already occurred. On this early return, the function does not directly copy the caller’s region data, perform the transfer-like call, or update the embedded state at `0x154`.

If the eligibility result is nonzero, processing continues:

1. Read four consecutive 32-bit words from the caller’s region data into a local 16-byte copy, in ascending word order.
2. Call F-d156b0b83eb3 with:
   - the local copy;
   - the arithmetic negation of the 32-bit field at `0x84`;
   - the arithmetic negation of the 32-bit field at `0x80`.
3. Call F-a4c26c2b4842 with a separate context buffer represented as 17 words, or 68 bytes.
4. Call F-7fa874cbac7a with the object and that context buffer.
5. Read the current resource slot and call F-1ade66241a82 with a separate 12-byte temporary area and the resource value.
6. Call F-b774eb6cb163 with:
   - the 68-byte context-buffer address;
   - the result of F-1ade66241a82;
   - the adjusted local region address;
   - that same local region address again;
   - `0xff`;
   - zero.
7. Call F-282eebd7c413 with the 12-byte temporary area.
8. Call F-12cb3c413baa with the embedded-state address at `0x154` and the original caller-supplied region address.
9. Call F-282eebd7c413 with the context-buffer address.
10. Return.

The two region arguments to F-b774eb6cb163 alias the same local storage. They are not independent copies.

F-12cb3c413baa receives the original region address, not the adjusted local copy. Because it is invoked after the transfer and temporary finalization, its input contents are whatever occupy that original address at that time. The function does not take a second snapshot for this call.

The resource slot is read for F-1ade66241a82 after the eligibility and context-preparation calls. It is not necessarily the same value observed at entry or stored during initialization.

### 4. Full update

For a nonzero selector byte, the function performs:

1. Call F-5d3cf0e5d367 with the object, auxiliary value, and original region-data address.
2. Call F-960363c07b32 with the object and a local 16-byte region buffer.
3. Call F-a4c26c2b4842 with local context storage.
4. Call F-7fa874cbac7a with the object and that context storage.
5. Call F-b774eb6cb163 with:
   - the embedded-state address at `0x164`;
   - the local context address;
   - the local region-buffer address;
   - that same region-buffer address again;
   - `0xff`;
   - zero.
6. Write zero to the byte at object offset `0x150`.
7. Call F-ca73cb512206 with the embedded-state address at `0x154`.
8. Call F-282eebd7c413 with the local context storage.
9. Return.

F-5d3cf0e5d367 completes before the region and context preparation. Its effects may therefore influence those later operations.

The selector is explicitly cleared only after F-b774eb6cb163 returns. It is cleared before F-ca73cb512206 and the final F-282eebd7c413 call. Since those dependencies may themselves modify state, a zero selector at final return is not guaranteed solely by the explicit store.

## Side effects

### Direct writes

The function directly:

- Writes the resource slot during initialization.
- Clears the one-byte selector on the full path.
- Writes local region and context storage.

It does not directly write through the caller’s region-data address. This does not guarantee preservation of that memory: dependencies receive the address, and the caller may supply aliased storage.

### Dependency-mediated effects

Dependencies receive the object, embedded-state addresses, local buffers, the resource value, or caller memory. Their transitive effects are unknown. No dependency is established to preserve globals, preserve object fields, avoid callbacks, or leave caller memory unchanged.

An eligibility rejection is therefore not a general “no side effects” outcome. It occurs after any initialization work and after F-3405f9d47f43 has run.

### Ownership and lifetime

The evidence establishes an allocation-like request for 184 bytes and a later stored result, but not the ownership relationship between them. F-f027f0bfb38b may return the supplied address or another value; its behavior is unknown.

F-282eebd7c413 is used in a finalization-like position for context and temporary storage. This does not establish that it frees backing memory or owns any referenced resource.

Local addresses passed to dependencies are valid during their calls. No explicit lifetime extension is provided. Whether dependencies retain those addresses, or are permitted to do so, is documented_only.

No explicit rollback, exception cleanup, resource-slot destruction, or replacement of a preexisting nonzero resource is shown.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume dependencies return normally and do not alter relevant state except where specified.

1. **Existing resource, rejected partial update.**  
   Given a nonzero resource slot, a zero selector, and a zero result from F-3405f9d47f43, no initialization calls occur. The eligibility call is followed by return. The function performs no direct region-data reads.

2. **Missing resource, then rejection.**  
   Given a zero resource slot and a selector that remains zero through initialization, the complete initialization sequence precedes the eligibility call. A zero eligibility result does not undo the resource-slot write or registration call.

3. **Admitted partial update.**  
   Given a zero selector and nonzero eligibility result, four region words are copied before adjustment. If the fields at `0x84` and `0x80` are respectively 7 and −3, the adjustment arguments are respectively −7 and 3. The transfer receives the same adjusted-region address twice. Region-state tracking later receives the original caller address.

4. **Noncanonical true selector.**  
   A selector value of 2 selects the full path just as 1 does. The auxiliary argument is forwarded to F-5d3cf0e5d367. No eligibility call occurs.

5. **Initialization changes the selector.**  
   If the resource slot initially requires initialization and a dependency changes the selector before initialization completes, the subsequent branch follows the newly observed selector value.

6. **Zero initialization result.**  
   If F-f027f0bfb38b returns zero normally, zero is stored and passed to F-7f4cb9b761d1. This invocation does not restart initialization. A later invocation that observes a zero resource slot attempts initialization again.

7. **Full-path completion order.**  
   When dependencies return normally, the full transfer precedes the explicit selector clear; the clear precedes F-ca73cb512206; context finalization follows that call.
