# F-82c5178b7565

## Purpose

F-82c5178b7565 coordinates an operation on a mutable context and a separate output object. A captured one-byte mode selects one of two families:

- Modes 1, 2, and 3 perform position-sensitive processing, using either a fixed-capacity buffer path or a helper-driven path.
- Every other mode records the supplied option byte and performs a separate dependency sequence.

A context status value of 3 rejects the operation before mode handling.

The visible return values are 0, 1, and 3. Zero identifies a successful completion path. One is returned only when a designated final dependency returns 1 in the second family. Three covers immediate rejection and the visible failure paths; it does not identify a particular cause.

The operation is not transactional. Context fields, shared state, dependency-managed state, and output storage may already have changed when it returns 3.

## Interface

### Arguments and result

| Item | Contract |
|---|---|
| Context | Mutable structure containing mode bytes, signed bounds, record information, object references, and an indirect dispatch table. |
| Output object | Mutable object with an indirect dispatch table; also supplied to dependencies. |
| Option | One byte, stored in the context only for captured modes other than 1, 2, and 3. |
| Result | A 32-bit value, visibly restricted to 0, 1, or 3. |

The supplied representation uses 32-bit addresses and four-byte integer fields. Layout and arithmetic below describe that representation, not a portable object model.

There are no explicit null, object-validity, index-range, or storage-capacity checks. Valid execution requires accessible objects, dispatch entries, selected records, and dependency-provided storage.

### Local output slots and published record

The buffer path uses three distinct four-byte local slots:

- A buffer-address slot, initially zero, whose address is supplied to F-d34fa71e963d.
- A metadata slot whose address is supplied to the provider callback at offset `0x28`.
- A position/result slot whose address is supplied first to the provider callback at offset `0x30`, then to the callback at offset `0x28`.

Their addresses escape to dependencies. The visible function does not establish that later dependencies cannot modify them through retained pointers.

On buffer-path success, F-e2669f32f0eb receives the output object and the address of a separate local destination-pointer slot. After that call, four consecutive 32-bit fields are written:

| Output offset | Value read for that write |
|---|---|
| `0x00` | Then-current buffer-address slot contents. |
| `0x04` | Then-current metadata slot contents. |
| `0x08` | Then-current position/result slot contents. |
| `0x0C` | Literal 1. |

These writes occur in the listed order. They do not publish a snapshot taken immediately after the provider callback. Each source slot is read when its corresponding assignment occurs.

The destination must permit at least 16 writable bytes. No dependency result or destination validity is checked before publication.

## Behavior

### Entry rejection and mode transition

The context status is tested first. If its byte value at `0x1390` is 3, the result is 3; no later dependency call or direct write occurs.

Otherwise, the requested mode at `0x1398` is captured and compared with the remembered mode at `0x1399`.

When they differ:

- Captured mode zero causes a shared global cell to be assigned zero.
- Any nonzero captured mode causes that cell to be assigned one, followed by transition preparation.

Nonzero transition preparation has this order:

1. Invoke the context callback at dispatch offset `0x3C`, passing the context.
2. If its result is nonzero, invoke F-fb9b4756e838 with the context. A nonzero result returns 3 immediately.
3. Invoke F-d4c824a654fe with the context and writable addresses of both position bounds. A nonzero result returns 3 immediately.
4. Clear two 32-bit fields for each record selected by the signed count at `0x1080`: first `0x1268 + 0x50 × index`, then `0x126C + 0x50 × index`.

Clearing starts with index zero and advances by one. The count is read again for successive loop conditions. A nonpositive count performs no clearing. No record-capacity check is visible.

After no transition, a transition to zero, or successful nonzero preparation, the captured mode is stored at `0x1399`. Transition failures occur before this direct store, although dependencies may independently modify the field.

The major branch uses the captured mode, not a fresh read of the requested-mode byte.

### Modes 1, 2, and 3: common preparation

The buffer-address slot is initialized to zero. The output-object callback at dispatch offset `0x08` receives the output object and the address of a four-byte local area. Its return value is ignored; only the first byte of that area is tested. A zero byte returns 3.

F-568bd35fa57e then receives the context and output object. A nonzero result returns 3.

Next, the remembered-mode byte determines a retained operation argument:

- Value 1 selects 0.
- Value 2 selects 1.
- Every other value selects 2.

This read follows F-568bd35fa57e. The selected argument need not correspond to the captured mode if a dependency changed the remembered byte.

The next sequence is:

1. Invoke F-f0216cff9365 with the current value at `0x1380` as its sole explicit argument; ignore its result.
2. Invoke the provider callback at dispatch offset `0x30`, passing the provider object and the address of the signed position/result slot.
3. If that callback returns nonzero, invoke F-2bb3dbfa7286 with the then-current `0x1380` value and fixed storage at `0x13A8`, then return 3.
4. Otherwise, invoke F-f0216cff9365 with the current `0x1380` value and the current indexed storage address.
5. A nonzero result returns 3 directly.
6. Invoke F-2bb3dbfa7286 with the current `0x1380` value and fixed storage.

The position/result slot is subsequently compared as a signed 32-bit value against the current bounds. These are later reads, not a guaranteed snapshot of values immediately following the provider call.

The inside interval is lower-inclusive and upper-exclusive. A position is outside when it is below the lower bound or at least the upper bound. Equal or reversed bounds are not normalized.

### Outside the interval

For an outside position:

1. Store zero in the lower bound.
2. Store zero in the upper bound.
3. Invoke F-f0216cff9365 with the current `0x1380` value and fixed storage; ignore its result.
4. Invoke F-d34fa71e963d with the current `0x1060` value, the buffer-address slot’s address, the current indexed value at `0x1240`, and the current `0x1394` value.

Only a zero result from F-d34fa71e963d permits the provider callback at dispatch offset `0x28`. That callback receives:

- The provider object.
- The buffer-address slot’s contents at the time of this call.
- Capacity `0x80000`, exactly 524,288 bytes.
- Addresses of the metadata and position/result slots.
- The previously selected operation argument.

Only a zero provider result enters the success sequence:

1. Invoke F-2bb3dbfa7286 with the current `0x1380` value and fixed storage.
2. Invoke F-20810a394e6a with the buffer-address slot’s contents as read after that preceding call, and capacity `0x80000`.
3. Invoke F-e2669f32f0eb with the output object and the destination-pointer slot’s address.
4. Perform the four output-record writes described under Interface.
5. Return 0.

The three calls before publication have unknown implementations. In particular, the published buffer address is not guaranteed to equal either the address passed to the provider or the address passed to F-20810a394e6a. Likewise, the published metadata and position/result values are not guaranteed to equal the values left by the provider when it returned. Such equalities require the relevant escaped slots to remain unchanged.

No direct comparison constrains either provider output against the fixed capacity.

If F-d34fa71e963d or the provider callback returns nonzero, invoke F-2bb3dbfa7286 first with fixed storage, then with freshly computed current-record storage, and return 3. The zeroed bounds are not restored.

### Inside the interval

For an inside position, perform these calls in order, stopping on the first nonzero result:

1. F-e1cd4dd64631 with the context.
2. F-568bd35fa57e with the context and output object.
3. F-63778c7fb54e with the context and a local four-byte output slot’s address.
4. F-79f3dff566e3 with the context, that slot’s then-current value, and the output object.

Any failure goes directly to final current-record cleanup and returns 3.

If all succeed:

1. Invoke F-f0216cff9365 with the current `0x1380` value and fixed storage; ignore its result.
2. Invoke the provider callback at dispatch offset `0x34` with the provider object and retained operation argument.
3. On zero, invoke F-2bb3dbfa7286 with fixed storage and return 0.
4. On nonzero, invoke F-2bb3dbfa7286 with fixed storage, then perform final current-record cleanup and return 3.

### All other captured modes

For captured modes other than 1, 2, and 3:

1. Store the option byte at `0x1393`.
2. Invoke F-568bd35fa57e with the context and output object. Nonzero returns 3 directly.
3. Invoke F-f0216cff9365 with the current `0x1380` value and current indexed storage. Nonzero returns 3 directly.
4. Invoke F-63778c7fb54e with the context and a local four-byte output slot’s address.
5. Only on zero, invoke F-79f3dff566e3 with the context, that slot’s then-current value, and output object.
6. Only when both calls succeed, write byte value 1 at `0x1084`, then invoke F-c5749e6447fb with the context.

F-c5749e6447fb returning zero causes direct return 0; returning one causes direct return 1. Any other result triggers final current-record cleanup and return 3.

Failure of F-63778c7fb54e or F-79f3dff566e3 also triggers that cleanup. The option and completion-byte writes are not rolled back.

### Final current-record cleanup

Where specified, final cleanup invokes F-2bb3dbfa7286 using a fresh read of `0x1380` and an indexed storage address recomputed from a fresh read of `0x1078`. It then returns 3.

This may address a different record from earlier calls if a dependency changed the index.

## Side effects

Established direct effects are:

- A shared-global assignment on a mode change.
- Remembered-mode storage after successful transition handling.
- Two ordered four-byte clears per selected record.
- Ordered clearing of both bounds on the outside path.
- Option storage in other modes.
- A one-byte completion marker before F-c5749e6447fb.
- Four ordered output-record writes on buffer success.

Dependencies may additionally modify context fields, globals, objects, records, buffers, and escaped local slots. A dependency’s success status does not establish preservation of any such state.

F-f0216cff9365 and F-2bb3dbfa7286 occur in paired-looking patterns, but no ownership or synchronization interpretation is established. Some paths return without a corresponding visible second call; other paths make two calls using different storage addresses.

No explicit buffer release is visible after provider failure. Output publication does not establish ownership transfer, sharing, retention, or lifetime. Passing a local slot’s address establishes possible mutation during the invocation, not permission to access it after the invocation ends.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Immediate rejection.** Status 3 yields result 3 without later calls or direct writes.

2. **Unchanged mode.** Matching requested and remembered modes skip the global assignment and transition preparation. The captured mode is still stored to the remembered byte.

3. **Transition to zero.** A changed requested mode of zero sets the shared cell to zero, skips nonzero transition preparation, and subsequently enters the option-recording family.

4. **Failed nonzero transition.** If the context callback and F-fb9b4756e838 both return nonzero, result 3 follows the global assignment of one. The function has not performed its remembered-mode store; dependency mutations remain possible.

5. **Boundaries.** With position and bounds unchanged before comparison, bounds 10 and 20 classify 10 as inside and 20 as outside. Equal bounds classify every signed position as outside.

6. **Buffer success without later slot mutation.** Given an outside position, zero preparation/provider results, valid storage, and no subsequent mutation of the three escaped source slots, result 0 publishes the prepared buffer address, provider metadata, provider position/result, and literal 1. Both bounds were cleared before buffer preparation.

7. **Buffer success with later slot mutation.** Suppose the provider leaves metadata 7, but a later dependency changes the escaped metadata slot to 9 before its publication read. If the path otherwise completes validly, the published metadata is 9. Similarly, a buffer-slot change after F-20810a394e6a may make the published address differ from that call’s argument.

8. **Inside-path short circuit.** A nonzero F-e1cd4dd64631 result skips the remaining processing calls, performs final current-record cleanup, and returns 3.

9. **Distinct result 1.** Successful other-mode preparation followed by F-c5749e6447fb returning 1 yields result 1. The completion byte was already written; no final cleanup call occurs on that return path.

10. **Mutated remembered mode.** If the first F-568bd35fa57e changes the remembered mode to 2, the operation argument is 1 even when the captured major-branch mode was 1.

## Uncertainties

The following remain **documented_only**:

- Semantic meanings of modes, fields, bounds, and provider outputs.
- Shared-global identity and exact storage width.
- Ownership, allocation, lifetime, synchronization, and failure reclamation.
- The effect of F-20810a394e6a.
- Dependency mutations, including mutations through retained pointers to local buffer, metadata, position, processing-output, and destination-pointer slots.
- The complete calling convention of F-f0216cff9365, represented with differing explicit argument counts.
- Behavior when callbacks report success without initializing required outputs.
- Behavior for invalid pointers, inadequate storage, invalid indices, or overlapping storage.

The record stride is 80 bytes and the index is signed 32-bit. Valid execution requires addressable storage for the selected offsets and representable address calculations. The representation does not establish a portable wrapping-address contract. Extremely large counts may also exceed valid record storage or arithmetic limits.

The position and interval comparisons are signed 32-bit. Other four-byte outputs have no established signed interpretation. Retained-pointer mutation possibilities do not prove that any dependency actually performs such mutations.
