# F-419b965b7fec

## Purpose

F-419b965b7fec conditionally removes a selected node from a pointer-linked, byte-tagged tree, performs structural replacement and conditional tag repair, prepends the detached node to a container-maintained chain, decrements a 32-bit count, and writes a 32-bit result to caller-provided storage.

The structure resembles a red-black tree with a separate header. This is **inferred intent**, not an established guarantee of balancing or dependency behavior. The contract includes unusual repair-candidate choices and unresolved dependency interfaces; these must not be replaced with conventional tree-erasure semantics.

A preliminary dependency can bypass the removal path. On that path, the output is a fresh read of the container’s header address.

On the removal path, the output comes from a private result cell **at final completion**, after structural changes, repair dependency calls, chain insertion, and count decrement. It is not necessarily the selected node, the structurally substituted node, or the value held immediately after either preliminary dependency.

## Interface

The function accepts three arguments:

1. **Result storage:** address receiving one four-byte value on normal completion.
2. **Container address:** address of the container fields described below.
3. **Selection storage:** address containing a four-byte node address.

There is no explicit return value. Result storage is the output channel.

The supplied representation uses 32-bit address-bearing fields and 32-bit scalar fields. It does not establish a portable native-pointer layout.

Zero denotes an absent ordinary child. A distinct, nonzero header is the inferred intended representation.

Repair treats tag 0 as red-like and tag 1 as black-like. Those names describe inferred intent. The exact predicates differ:

- Entry into repair requires the detached node’s tag to be **nonzero**.
- Continued repair requires the candidate’s tag to be **exactly 1**.
- A sibling is treated as red-like only when its tag is **exactly 0**.
- An absent child or a child tagged **exactly 1** satisfies the child conditions described below.

Other tag values are not rejected.

### Preconditions and aliasing

Every address actually dereferenced must identify accessible storage of the required width, including addresses read after dependency calls. Traversals must terminate for normal completion.

No visible validation establishes node membership, consistent links, valid header caches, binary tags, a positive count, or nonnull arguments. Malformed inputs have no specified recovery behavior.

The interface does not prohibit aliasing between argument storage, container fields, and nodes. Consequently, writes may affect subsequent reads when storage overlaps. The branch descriptions below apply to the values actually read, not to a frozen entry-state snapshot.

Earlier dependencies receive addresses of private cells. Their access must not be assumed to end when they return: a retained address may enable later dependency effects to alter the result cell before its final copy.

## Behavior

### Preliminary decision and selection

The function first reads selection storage into a private four-byte result cell. It then reads the container’s header field into a separate private four-byte cell.

F-3b480a32387a receives the addresses of both cells.

If its return is nonzero, the function:

- Rereads the container’s header field.
- Replaces the private result with that value.
- Copies the result to result storage and completes.

No direct structural removal, repair, chain insertion, or count decrement follows on this path. This does not establish that the dependency left the container unchanged.

If the return is zero, F-ce2e2e919fce receives the address of the private result cell. After that call returns, the function rereads selection storage to obtain the node used for removal.

Thus, the initial selection value and the removal selection may differ. Changes to the private result cell do not themselves select the node to remove.

For the remainder of this contract, **selected node** means the node from this second selection read.

### Structural case selection

The selected node’s left link is read before its right link.

- No left child and no right child selects the leaf case.
- Exactly one child selects direct replacement by that child.
- Two children select the leftmost node in the right subtree as the successor.

The successor search repeatedly follows left links until a zero left link is found. It has no visible cycle detection or traversal bound. The successor’s right child becomes the initial repair candidate.

The representation includes repeated reads of some child fields. Those reads are not a promise of atomic snapshot behavior.

### Leaf removal

The selected node’s parent becomes the repair candidate.

If that parent equals the currently read header address, the direct writes occur in this order:

1. Header cached maximum becomes the parent/header address.
2. Header cached minimum becomes that address.
3. Header root becomes zero.

Otherwise, the function reads the parent’s left link to determine the incoming edge:

- Equality with the selected node causes the parent’s left link to be cleared.
- Inequality causes the parent’s right link to be cleared, without validating that it points to the selected node.

Each such clear is represented as four one-byte zero writes in increasing address order.

The function then checks only the corresponding header cache: minimum for left-edge removal, maximum otherwise. If that cache equals the selected node, it is replaced by the parent.

The selected node remains the detached node.

### Exactly one child

The replacement child’s parent field first receives the selected node’s parent.

The incoming tree link is then redirected:

- If the header root equals the selected node, the root becomes the replacement.
- Otherwise, if the selected node equals its parent’s left child, that left link becomes the replacement.
- Otherwise, the parent’s right link becomes the replacement.

Header extrema are processed afterward, minimum before maximum.

If the cached minimum equals the selected node:

- A zero right link in the selected node causes the cache to become the selected node’s parent.
- Otherwise, the cache becomes the leftmost node reached from the replacement.

If the cached maximum equals the selected node:

- A zero left link in the selected node causes the cache to become the selected node’s parent.
- Otherwise, the cache becomes the rightmost node reached from the replacement.

These are the actual conditions, including their dependence on the selected node’s links at those later reads. They are not replaced by a general extrema-recomputation rule.

The selected node remains the detached node. The replacement child is the repair candidate.

### Two children

The successor is structurally moved into the selected node’s position. No payload copy is visible.

The structural writes are ordered as follows:

1. The selected node’s left child is reparented to the successor.
2. The successor’s left link receives the selected node’s left link.
3. The successor’s original position and right-side relationships are adjusted.
4. The selected node’s incoming root or parent link is redirected to the successor.
5. The successor’s parent receives the selected node’s parent.
6. The successor’s and selected node’s tags are exchanged.

The adjustment in step 3 depends on the successor’s original location.

**Immediate right child:** if the successor is the selected node’s right child, its nonzero right child is reparented to the successor. The successor’s right link is otherwise retained.

**Deeper successor:**

- A nonzero successor right child is reparented to the successor’s former parent.
- That former parent’s left link becomes the successor’s right child, including zero.
- The successor’s right link receives the selected node’s right link.
- That right subtree’s root is reparented to the successor.

Incoming-link redirection uses the same root-first, then parent-left, otherwise parent-right selection described for direct replacement.

If the successor’s right child is zero, the successor itself becomes the repair candidate. The function does not retain a null candidate with a separate parent context.

After the tag exchange, the original selected node is the detached node and carries the successor’s original tag. This branch does not explicitly update the header’s minimum or maximum caches.

### Conditional repair

The function first rereads the header address and compares it with the repair candidate. Only if they differ does it inspect the detached node’s tag.

Repair is entered if the candidate differs from that header and the detached node’s current tag is nonzero. If this gate fails, no final candidate-tag write occurs.

During an entered repair sequence, the function first compares the candidate with the root reached through a fresh header read. If they are equal, repair ends without needing the candidate-tag comparison. Otherwise, repair ends if the candidate’s tag is not exactly 1.

Every normal exit from an entered repair sequence writes tag 1 to the **then-current candidate**.

If processing continues, the candidate’s parent is read. Equality between the candidate and the parent’s left link selects the left-side case; all other values select the mirrored case.

#### Candidate is the parent’s left child

The sibling is the parent’s right child.

If a present sibling has tag 0:

- The sibling receives tag 1.
- The parent receives tag 0.
- F-3ed578214a76 is called with the container and parent.
- The candidate’s parent and that parent’s right link are reread.

An absent sibling, either initially or after this call, causes the candidate to receive tag 0. Processing then continues upward from its parent.

For a present sibling:

- If both children are absent or tagged exactly 1, the sibling receives tag 0 and processing continues from the candidate’s parent.
- Otherwise, if the sibling’s right child is absent or tagged exactly 1, its present left child receives tag 1, the sibling receives tag 0, and F-57d09289448f is called at a site visibly supplying only the container. The sibling is then reread through the candidate’s current parent.
- If that reread sibling is absent, repair ends with the final candidate-tag write.
- Otherwise, the sibling receives the candidate’s current parent tag, the parent receives tag 1, and a present sibling right child receives tag 1. F-3ed578214a76 is called with the container and current parent, after which repair ends.

#### Candidate is not the parent’s left child

The sibling is the parent’s left child.

The corresponding operations are mirrored:

- A tag-0 sibling receives tag 1, the parent receives tag 0, and F-57d09289448f is called with container and parent. Parent and sibling links are reread.
- An absent sibling causes candidate tag 0 followed by upward propagation.
- Two absent-or-tag-1 sibling children cause sibling tag 0 followed by upward propagation.
- Otherwise, an absent-or-tag-1 sibling left child triggers recoloring of a present right child to 1, sibling tag 0, and F-3ed578214a76 at a site visibly supplying only the container.
- Following the sibling reread, absence ends repair. Presence leads to copying the parent tag to the sibling, setting parent and present sibling left child to 1, and calling F-57d09289448f with container and current parent.

### Chain insertion, count, and output

After structural processing and any repair, direct operations occur in this order:

1. Read the container’s current chain head and write it to the detached node’s offset-12 field.
2. Write the detached node to the container’s chain-head field.
3. Read the current 32-bit count, subtract one, and write the count field.
4. Copy the private result cell’s **then-current value** to result storage.

The final result is not fixed at F-ce2e2e919fce’s return. Either preliminary dependency may have retained the result-cell address, and subsequent dependency effects may change that cell before step 4.

The count has no positivity check. For a signed 32-bit value whose decrement is representable, the arithmetic result is one less. The supplied representation does not establish defined wraparound at the signed minimum.

Finalization repurposes the detached node’s right-link field as its chain link. It does not clear the node’s parent, left link, tag, or payload.

## Acceptance examples

These are conditional static consequences, not executed tests. Structural examples assume accessible, consistent storage, no interfering aliasing, and dependency effects compatible with the stated conditions.

1. **Bypass:** If F-3b480a32387a returns nonzero and the subsequent header read yields H, output receives H. No direct removal, chain insertion, or count decrement follows.

2. **Changed selection and later result mutation:** Selection initially contains A but contains B when reread after F-ce2e2e919fce. Removal selects B. If the private result cell contains R at that dependency’s return but a later repair dependency changes it to S through retained access, output receives S, provided S remains its value at the final copy. Without a specified final cell value, no particular output value is established.

3. **Single-node tree:** A selected leaf whose parent is the header causes maximum and minimum to become the header, followed by root zero. Repair is skipped because the candidate is the header. The selected node is chained and the count decreases.

4. **Root with only a right child:** The child is reparented to the header before becoming root. If repair is entered and the root still equals that child, repair terminates and writes child tag 1.

5. **Successor without a right child:** For a two-child selection, the successor replaces the selected node, their tags are exchanged, and the successor becomes the repair candidate. The original selected node is subsequently chained.

6. **Zero detached-node tag:** If that tag is zero when evaluated at the repair gate, no repair dependency or final candidate-blackening write occurs. Finalization still follows.

7. **Existing chain:** If the chain-head read during finalization yields Q, the detached node’s offset-12 field receives Q before the container head receives the detached node.

8. **Nonbinary candidate tag:** If repair is entered, the candidate is not the current root, and its tag is neither 0 nor 1, repair exits and writes tag 1. This does not validate nonbinary tags generally.

9. **Zero count:** If finalization reads signed count zero, the decrement produces −1. A count already at the signed 32-bit minimum has unresolved overflow semantics.
