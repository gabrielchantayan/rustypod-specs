# F-9007028027bb

## Purpose

F-9007028027bb repeatedly invokes indirect dependencies and performs ordered byte, halfword, and word accesses through global values, context-relative addresses, fixed addresses, and dependency-produced addresses.

**Established static behavior:** there is no normal return path. Each completed pass begins another pass without a termination test. A software breakpoint interrupts the represented sequence partway through each pass; later operations require execution to continue beyond it.

**Inferred intent:** the accesses may maintain related structures, but no application purpose, device role, record format, or ownership protocol is established. Terms such as **context**, **record**, **selector**, and **attribute** identify access roles only.

This contract describes static evidence. No runtime tests have been performed.

## Interface

### Explicit interface

- No explicit parameters.
- No explicit return value.
- No normal completion path.
- No explicit error-result channel.

### Implicit inputs and state

Execution depends on:

- An incoming **link/control value** used to construct the first indirect target.
- An incoming **auxiliary value** used in a late byte-store address.
- A **context base** used in word accesses and explicitly decreased during each pass.
- Two global locations containing 32-bit address-bearing values: the **primary global base** and **secondary global base**.
- Memory reached through these values, fixed addresses, and dependency results.
- Additional register outputs consumed after certain dependencies, beyond their ordinary displayed results.

These are observed roles, not complete declarations or an established ABI.

The first pass constructs its first target from the incoming link/control value. Near the end of a pass, that value is assigned `0x08712031` **before** the final argument read and final dependency invocation. If the pass completes and the represented state is carried into the next pass, the next first target is `0x0871302F`.

This assignment does not depend on the final argument read succeeding. If that read faults, the assignment has already occurred, although subsequent exception handling and eventual execution state are unknown.

## Behavior

### Dependency notation and ordering

Occurrences **1–37** identify indirect-call sites in execution order within a pass. They do not identify 37 distinct callees. Opaque dependency IDs and established target equalities appear in **Dependencies**.

A call described without explicit arguments has none in the supplied static interface. This does not establish that its target ignores incoming machine state or memory.

All following operations are conditional on earlier operations completing. Dependencies can introduce their own effects between the direct operations described here.

### Initial dispatch and primary-base capture

At the start of each pass, the byte value later used for an initial zero store is set to zero.

Occurrence 1 receives two explicit zero arguments. Its target is the current link/control value plus `0xFFE`.

After occurrence 1, a separate byte contribution used in a later argument calculation is set to zero. Occurrences 2 and 3 then run.

The routine reads the primary global base and retains the resulting value across occurrences 4 and 5. Occurrence 5 supplies a paired result, named the **first low word** and **first high word**.

Occurrence 6 receives:

1. The first low word.
2. The 32-bit sum of the first high word and first low word, with the explicitly zero byte contribution added.

No separate carry argument is represented. The byte copied near the end of an earlier pass does not contribute to this calculation.

After occurrence 6 returns, an additional byte-valued register output is stored at captured primary base plus `0x11`.

Occurrence 7 runs. The routine then stores byte zero at captured primary base plus `0x15`.

Neither store reloads the primary global. Changes to that global after capture do not change these represented address operands. Whether the captured addresses remain accessible is a separate environmental and dependency question.

### Dependency-produced values and context-relative stores

Occurrence 8 returns a halfword. The routine stores it at an address supplied by an additional register output from that occurrence, plus `0x0C`.

Occurrence 9 supplies the **second low word** and **second high word**. Two stores follow in order:

1. Halfword zero at second high word plus `0x2C`.
2. A word at current context base plus `0x26C`, containing the second low word shifted unsigned right by 26 bits.

The second stored value is between 0 and 63 inclusive.

Occurrence 10 runs. A word is read at current context base plus `0x320` and retained as a destination base.

Occurrences 11 and 12 run. The routine stores the second low word, shifted unsigned left by two bits, at that retained destination base plus `0x54`.

The destination base is captured before occurrences 11 and 12. The value remains derived from occurrence 9. No reload of either operand is represented.

### Fixed-address acquisition and breakpoint

Occurrences 13–17 run in order.

The routine reads a zero-extended halfword at fixed address `0x21C48994`. This is the **address halfword**.

Occurrence 18 runs. A word is read at current context base plus `0x280` and passed as the explicit argument to occurrence 19.

Immediately after occurrence 19 returns, a software breakpoint with immediate value `0x92` occurs. It is not a normal return or an ordinary error result. No subsequent operation is reached unless execution continues beyond this breakpoint.

On continuation:

- Occurrence 19’s 32-bit result is shifted left by two bits, producing the **scaled result offset**.
- The fixed unsigned calculation using `0x21C48960`, shifted right by 18 bits and multiplied by four, produces `0x21C4`.
- A word is read at address halfword plus `0x44`, producing the **record base**.

The address halfword is used directly as an address component. No additional structure base or relocation is represented.

### Secondary-base store and lookup acquisition

Occurrences 20 and 21 run. Occurrence 21’s word result is retained.

The routine reads a word at address halfword plus `0x04`. Occurrence 22 receives occurrence 21’s result as its first explicit argument and this newly read word as its second.

The secondary global base is then read and retained.

Occurrence 23 runs. The routine stores the low 16 bits of the captured secondary base at:

**captured secondary base + scaled result offset**

The data is derived from the address value itself; it is not a halfword loaded from that address. The global is not reloaded after occurrence 23.

Occurrence 24 runs. A word is read at fixed address `0x2218`, equivalent to `0x21C4 + 0x54`, and retained as the **lookup base**.

Occurrence 25 returns an address. Halfword `0x21C4` is stored at that address plus `0x04`.

Occurrences 26 and 27 run. A zero-extended halfword is read at lookup base plus `0x34`, producing the **selector**.

### Third paired result and context change

Occurrence 28 supplies the **third low word** and **third high word**.

The routine first stores the third low word as a word at current context base plus `0x258`.

It then reads a halfword at third high word plus `0x14`. This is zero-extended and retained as the **attribute**.

The following derived values are used later:

- **Wide-stride offset:** third low word shifted left by six bits.
- **Scaled address:** third high word multiplied by four.
- **Selector offset:** selector multiplied by four.

The context base is decreased by `0xF4`, or 244 bytes. The earlier store at context offset `0x258` therefore precedes this decrease and uses the pre-decrease context value.

The routine then stores the third low word at selector offset plus `0x74`. This destination does not include either the context base or the lookup base.

No direct restoration of the context base appears before repetition.

### Record stores, byte transfer, and final dispatch

Occurrence 29 runs. The attribute is stored as a word at record base plus `0x54`.

Occurrence 30 runs. The same zero-extended attribute is stored as a word at record base plus `0x64`.

These are separate stores with an intervening dependency invocation, not an atomic pair.

Occurrence 31 runs. The low 16 bits of the record base are stored at wide-stride offset plus an additional register output from occurrence 31.

Occurrences 32 and 33 run. One byte is read at selector plus selector offset, equivalently five times the selector.

Occurrence 34 runs. The captured byte is stored at:

**attribute + incoming auxiliary value + `0x19`**

The source byte is not reread after occurrence 34.

Occurrence 35 runs. The scaled address is stored as a word at record base plus `0x44`.

Occurrence 36 runs. The final sequence is:

1. Assign the represented link/control value `0x08712031`.
2. Read a word at scaled address plus `0x44`.
3. Invoke occurrence 37 with that word as its explicit argument.

The assignment precedes the read. If the read faults, occurrence 37 is not reached on that path, but the assignment has already occurred. No rollback of the assignment is represented.

### Repetition

After occurrence 37 returns, another pass begins unconditionally.

There is no direct cleanup, context restoration, release, rollback, or termination check at this boundary. Globals are read again at their respective points in the new pass rather than permanently retaining the previous pass’s captures.

## Acceptance examples

These are conditional static examples, not runtime observations.

1. **Shared targets.**  
   Occurrences 5 and 6 resolve to the same target despite their different argument and result uses. The same requirement applies separately to 9/13, 17/24, 19/31, and 25/32.

2. **Unsigned extraction and truncation.**  
   If occurrence 9’s low word is `0xFC000003`, the context-relative extraction store contains `63`. The later unsigned left-shifted store contains `0xF000000C`.

3. **Paired-result sum.**  
   If occurrence 5 supplies low word `0xFFFFFFFF` and high word `2`, a 32-bit machine-width interpretation gives occurrence 6 arguments `0xFFFFFFFF` and `1`. No separate carry argument is represented.

4. **Captured primary address.**  
   If the primary global is captured as A and a later dependency changes the global to B, the initial byte destinations remain A plus `0x11` and A plus `0x15`, provided those accesses remain valid.

5. **Secondary address-derived data.**  
   With secondary base `0x12345678` and scaled result offset eight, the halfword store writes `0x5678` at `0x12345680`, assuming valid arithmetic and access.

6. **Zero extension and separation.**  
   Attribute `0xFFFF` produces word value `0x0000FFFF` at record offsets `0x54` and `0x64`. Occurrence 30 executes between those stores and may add effects.

7. **Selector-only addresses.**  
   Selector three gives word destination `0x80` and later byte source `0x0F`. Neither calculation adds the lookup base.

8. **Captured byte.**  
   If the byte read after occurrence 33 is `0xA6`, a change to its source by occurrence 34 does not change the later stored byte.

9. **Breakpoint boundary.**  
   Without continuation beyond the breakpoint, no post-breakpoint operation is reached. This is not normal completion.

10. **Final read fault.**  
    If occurrence 36 returns and the word read at scaled address plus `0x44` faults, the link/control assignment to `0x08712031` has already occurred. Occurrence 37 is not invoked on that path. Any exception-handler changes are outside the established contract.

11. **Completed-pass state.**  
    If dependencies do not otherwise modify the relevant state, a completed pass leaves the context base 244 bytes lower and the next first-call target is `0x0871302F`.
