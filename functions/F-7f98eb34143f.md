# F-7f98eb34143f

## Purpose

F-7f98eb34143f accepts seven 32-bit arguments and returns a 32-bit word. Depending on externally supplied control values, it prepares argument transforms, constructs a four-byte temporary record, invokes F-7462e125e06d, and transforms a candidate result.

Delegation, record initialization, result storage, and termination are conditional. External words determine the initial dispatch, subsequent destinations, arithmetic factors, and a common candidate value. Their contents are unavailable, so the evidence does not establish an unconditional input-to-output mapping.

Encoding, high-bit screening, and result adaptation are inferred purposes. Neither a particular application domain nor an unconditional success/error interpretation is established.

## Interface

Arguments are numbered by position:

| Argument | Established representation and use |
|---|---|
| 1 | Signed 32-bit input used in arithmetic transforms. |
| 2 | Opaque 32-bit value retained for possible forwarding. |
| 3 | Signed 32-bit input tested for zero and retained for possible forwarding. |
| 4 | Unsigned 32-bit input used in arithmetic and bitwise combinations. |
| 5 | Unsigned 32-bit input used in record preparation. |
| 6 | Signed 32-bit input transformed for delegation. |
| 7 | Opaque 32-bit value retained for possible forwarding. |

The return representation is unsigned 32-bit. The wrapper directly dereferences none of these arguments. Arguments 2 and 7 cannot be classified as pointers, handles, or ownership-bearing values from this evidence.

The invocation owns a four-byte local record and a separate 32-bit result slot. The result slot initially contains zero; the record has no explicit initialization.

This contract uses 32-bit word arithmetic: products and sums are described modulo \(2^{32}\), and byte assignments retain the low eight bits. This captures the word-level transformations, not a portable-language guarantee about signed overflow. The exact target treatment of signed overflow, conversion to signed byte, and signed right shift remains documented_only.

- **Candidate** supplies the value used by result storage.

- **Fourth working value** is the mutable value eventually passed as dependency argument 8.
- **Selector** is reused for zero/nonzero and high-bit routing.

These are descriptive contract names, not dependency interfaces.

## Behavior

### Entry and dispatch

The wrapper initializes the result slot, accumulator, candidate, shared word, selector, prepared transforms, retained forwarding values, fourth working value, and three variable record indices to zero. It saves arguments 1–4 separately for preparation. The four record bytes remain uninitialized.

The initial control word is read from \(I\). Every dispatch evaluation separately reads \(K\) and selects on the difference between the current control word and that sampled base.

Explicit offsets are 0 through 11. Every other difference follows the same delegation behavior as offset 6. An unexpected dispatch difference is therefore not automatically an error.

A control destination does not itself identify a fixed phase unless the subsequent read of \(K\) makes the appropriate difference. Even preparation’s assignment of a sampled \(K\) to the control word need not select offset 0 if the next base read differs.

There is no enforced phase ordering. Phases may repeat, be bypassed, or occur before preparation. The descriptions below specify their effects whenever reached.

### Preparation — offset 2

Preparation sets the variable record indices to 1, 2, and 3. It retains arguments 2, 3, 6, and 7 for delegation, sets the selector to 0 or 1 according to whether argument 3 is zero or nonzero, and restores the fourth working value from argument 4.

It establishes these arithmetic states:

| State | Value, using the reads belonging to that expression |
|---|---|
| Fifth seed | \(B \times \text{argument 5}\) |
| First transform | \(A \times B \times \text{argument 1}\) |
| Accumulator | \(B \times \text{argument 1} \times C\) |
| Scaled fifth | \(A \times \text{retained fifth seed}\) |
| Shared word | Argument 5 |

The external-read groups occur in this statement order:

1. One \(B\) read for the fifth seed.
2. Separate \(A\) and \(B\) reads for the first transform.
3. Separate \(B\) and \(C\) reads for the accumulator.
4. One \(A\) read for the scaled fifth.
5. One \(K\) read for the next control word.

No operand-evaluation order is established between external reads within either multi-factor expression. In particular, the three preparation reads of \(B\), and the two reads of \(A\), must not be treated as one cached sample.

The shared word and fourth working value are assigned after preparation’s \(K\) read and before the next dispatch. Preparation does not initialize the record, update the candidate, or call the dependency.

### Zero/nonzero routing — offset 0

This phase uses the current selector, not necessarily a fresh test of argument 3. After preparation it describes argument 3; after a high-bit phase it describes that phase’s high-bit result.

There are two separate reads of \(Z\), one associated with the selector-zero term and one with the selector-one term. Their relative evaluation order is not established. For a selector of 0 or 1:

- Selector 0 chooses the zero-associated sample minus 7.
- Selector 1 chooses the one-associated sample.

Both reads occur in the represented expression. The two possible destinations differ by seven only if those reads yield equal values.

### First high-bit check — offset 10

This phase replaces the shared word with the OR of the first transform and the incoming accumulator. That replacement matters to any later record construction.

It then replaces the accumulator with the fourth working value multiplied by a newly read \(C\). The candidate receives the shared-word OR result, not this new accumulator.

The external-read order is:

1. \(C\), for the replacement accumulator.
2. A first \(H_1\) sample, whose value plus 4 is retained as the clear-high-bit destination.
3. A second \(H_1\) sample, used as the set-high-bit destination.

The selector is replaced by the high-bit decision on the candidate. Under the represented arithmetic-right-shift interpretation, it becomes 1 when bit 31 is set and 0 otherwise.

Thus the decision examines the OR result formed from the **incoming** accumulator, while leaving a different accumulator for subsequent phases. The destinations are separated by four only if the two \(H_1\) samples are equal.

### Second high-bit check — offset 4

This phase first multiplies the fourth working value by a newly read \(A\), replacing that working value.

It obtains a first \(H_2\) sample and retains that sample plus 2 as the clear-high-bit destination. It then replaces the accumulator with the OR of the updated fourth working value and the incoming accumulator, and copies that result to the candidate. A second \(H_2\) sample supplies the set-high-bit destination.

The selector is replaced by the high-bit decision on the candidate. The shared word is unchanged.

The represented external-read order is \(A\), first \(H_2\), then second \(H_2\). The destinations differ by two only if the two control samples are equal.

Neither high-bit phase is an ordinary signed comparison of an original argument. A clear high bit in an OR result requires a clear high bit in both operands. Neither destination can unconditionally be called acceptance or rejection.

### 171 multiplication — offset 7

This phase reads \(T_M\) into the next control word **before** replacing the shared word with:

\[
171 \times \text{retained fifth seed}.
\]

It does not recompute the fifth seed from argument 5. Before preparation, that retained seed is zero.

### Record construction — offset 5

Let \(V\) be the retained scaled fifth. Four byte assignments appear in this order:

1. At offset 0: the low byte of \(D_1 \times (V \mathbin{\mathrm{>>}} 24)\).
2. At the first variable index: the low byte of \(D_2 \times (V \mathbin{\mathrm{>>}} 16)\).
3. At the second variable index: the low byte of a newly computed accumulator.
4. At the third variable index: the low byte of the shared word.

Here \(D_1,D_2,D_3\) are three separate, statement-ordered reads of \(D\). Before the third assignment, the accumulator is replaced with the full word:

\[
(V \mathbin{\mathrm{>>}} 8)\times D_3 \pmod {2^{32}}.
\]

The accumulator is **not** replaced merely by the third byte, nor by a product of only bits 15–8. Its upper bits remain relevant to later validation and record-writing phases.

After the fourth byte assignment, the phase reads \(T_R\) for its next control word.

After preparation, the destinations are offsets 0, 1, 2, and 3. Before preparation, all three variable indices are zero, so all four assignments target offset 0 and offsets 1–3 remain without explicit initialization.

The first three final bytes depend only on the corresponding extracted byte and the low byte of the relevant \(D\) sample. Their retained accumulator effect is wider. The fourth byte comes from the current shared word, which may hold argument 5, the 171 product, a first-check OR result, or a delegation argument transform.

These are ordered byte assignments in the supplied representation. They do not establish four externally observable memory events, target-level store granularity, or atomicity guarantees.

### Delegation — offset 6 and default

Before calling F-7462e125e06d, this phase replaces the shared word with:

\[
A_{\text{pre}} \times B_{\text{pre}} \times \text{retained argument 6}.
\]

The \(A\) and \(B\) reads belong to one expression; their relative evaluation order is unspecified. This shared-word replacement survives the call unless a later phase changes it.

The eight dependency arguments are:

| Position | Value |
|---|---|
| 1 | Literal 4 |
| 2 | Shared word just computed |
| 3 | Address of the four-byte local record |
| 4 | Retained first transform |
| 5 | Retained argument 2 |
| 6 | Retained argument 3 |
| 7 | Retained argument 7 |
| 8 | Current fourth working value |

Preparation is not enforced. Retained forwarding values and transforms can therefore still be zero, and the record can be partially or wholly uninitialized.

After the call returns a 32-bit result \(r\), the accumulator is replaced with:

\[
B_{\text{post},1}\times A_{\text{post}}\times B_{\text{post},2}\times r
\pmod {2^{32}}.
\]

These are three new external reads, all after the call. The two \(B\) occurrences are distinct reads. Their order relative to each other and to the \(A\) read is not established within the expression.

The candidate then receives the accumulator, and only afterward is \(T_C\) read for the next control word. Values retained before delegation must not be substituted for these post-call reads.

### Common candidate — offsets 3, 8, and 9

Each of these offsets reads \(E\) into the candidate, then reads the same control location \(T_C\) used after delegation.

These phases do not replace the accumulator or shared word. \(E\) may be intended as an error-like value, but its value and meaning are unknown.

### Result storage and return — offsets 1 and 11

Offset 1:

- Replaces the accumulator with the candidate multiplied by a fresh \(A\) sample.
- Reads \(T_S\) into the next control word.
- Copies the accumulator into the result slot before the next dispatch.

This accumulator replacement can affect later validation if execution revisits other phases.

Offset 11 returns the current result slot without further arithmetic or delegation.

With stable factors, delegation followed by one result-storage phase and return yields:

\[
A^2B^2r \pmod {2^{32}}.
\]

A common candidate \(E\) followed by that storage-and-return route yields \(AE\). Direct return before any result storage yields zero. These formulas describe conditional routes, not guaranteed execution.

## Side effects

No explicit global write appears in the wrapper. Its explicit writes concern invocation-local state and the temporary record.

External reads are behaviorally significant even when a sampled value contributes zero to a selector expression. Dispatch repeatedly reads \(K\); preparation also reads \(K\) independently. The same \(T_C\) location is read after either delegation or common-candidate selection. The high-bit and zero/nonzero selectors each sample their respective destination location twice.

The dependency may change external state. No preservation guarantee permits collapsing pre-call and post-call arithmetic reads, or treating the control and factor locations as immutable. Concurrent or asynchronous mutation guarantees are also unavailable.

The record is invocation-local storage, not an explicitly allocated heap object. Its lifetime does not extend beyond the wrapper invocation. The wrapper neither explicitly allocates nor releases external resources. Whether the dependency reads, modifies, retains, or otherwise uses the record address is unknown.

The wrapper does not explicitly release resources represented by arguments 2 or 7. Nothing establishes that the dependency preserves or releases them.

No explicit diagnostic, exception mechanism, or external status write is shown. Nontermination, repeated delegation, and delegation with incompletely initialized record storage are not ruled out.

## Acceptance examples

These are conditional static consequences, not runtime observations. Arithmetic examples use the word interpretation described above.

1. **Immediate return.** If the first dispatch selects offset 11, the result is zero. No record assignment or dependency call occurs.

2. **Prepared record.** Suppose preparation, 171 multiplication, and record construction occur in that order without relevant intervening changes. With stable \(A=B=D=1\) and argument 5 equal to hexadecimal 12345678, increasing record offsets contain hexadecimal 12, 34, 56, 28. The accumulator becomes hexadecimal 00123456.

3. **Full-width record accumulator.** Suppose scaled fifth is hexadecimal 80000000 and all three record-phase \(D\) samples equal hexadecimal 00000100. The first three bytes become zero, but the accumulator becomes hexadecimal 80000000. A subsequent second high-bit check with fourth working value zero selects its set-high-bit destination.

4. **Unprepared record construction.** If construction occurs before preparation, all four assignments target offset 0. Offsets 1–3 must not be treated as initialized by that phase.

5. **Delegation changes the fourth-byte source.** With pre-call \(A=B=1\) and retained argument 6 equal to hexadecimal 42, delegation sets the shared word to hexadecimal 42. If record construction follows without another shared-word update, its fourth assignment uses byte 42, not an earlier 171 product.

6. **First check changes the fourth-byte source.** If the first transform is hexadecimal 10 and the incoming accumulator is hexadecimal 03, the first high-bit phase replaces the shared word with hexadecimal 13. Later record construction uses 13 for its fourth assignment unless another phase changes that word.

7. **Unstable branch destinations.** If the first \(H_1\) sample is 100 and the second is 900, the clear-high-bit destination is 104 and the set-high-bit destination is 900. A four-unit separation must not be asserted.

8. **Stable result factors.** If the dependency returns 5, stable \(A=2\), stable \(B=3\), and execution performs one result-storage phase followed by return, the return is 180.

9. **Changed post-call factors.** Suppose the dependency returns 5; both post-call \(B\) reads yield 11; the post-call \(A\) read and storage-phase \(A\) read yield 7. The candidate becomes 4235 and the returned result becomes 29645, regardless of the pre-call factors.

10. **Default dispatch.** A dispatch difference outside 0–11 invokes delegation behavior. It is not specified to return an error candidate.
