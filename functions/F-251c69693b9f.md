# F-251c69693b9f

## Purpose

F-251c69693b9f transforms two interleaved streams of signed 16-bit samples using five shared coefficients and separate persistent histories. It writes interleaved signed 16-bit results and updates the selected history fields.

The established behavior is a five-product recurrence, extraction of a 32-bit window from a 64-bit accumulator, output limiting, and ordered history updates. A fixed-point second-order recursive filter is the inferred intent, not an independently established interface requirement.

Processing uses two passes: every even-indexed sample is processed before any odd-indexed sample. This ordering is observable when memory regions overlap.

## Interface

The function accepts five positional inputs and returns no value.

| Position | Meaning | Representation |
|---|---|---|
| 1 | Base address for coefficient/history selection | 32-bit address representation |
| 2 | Input-sample address | 32-bit address representation |
| 3 | Output-sample address | 32-bit address representation |
| 4 | Frame count | Signed 32-bit integer |
| 5 | Region selector | Signed 32-bit integer |

The selected address is the base address plus 56 times the selector. All offsets below are byte offsets from that selected address. Selector multiplication and address addition have no explicit overflow checks.

### Coefficient layout

Each coefficient occupies four bytes and is interpreted as a signed 32-bit integer.

| Offset | Contract name | Role |
|---|---|---|
| 0x0C | Feedback coefficient 1 | Negated before multiplication by the most recent recursive value |
| 0x10 | Feedback coefficient 2 | Negated before multiplication by the older recursive value |
| 0x14 | Input coefficient 0 | Multiplies the current scaled input |
| 0x18 | Input coefficient 1 | Multiplies the most recent scaled input |
| 0x1C | Input coefficient 2 | Multiplies the older scaled input |

### History layout

Each history field occupies four bytes.

| Offset | Meaning |
|---|---|
| 0x20 | Even stream: most recent scaled input |
| 0x24 | Odd stream: most recent scaled input |
| 0x28 | Even stream: older scaled input |
| 0x2C | Odd stream: older scaled input |
| 0x30 | Even stream: most recent recursive value |
| 0x34 | Odd stream: most recent recursive value |
| 0x38 | Even stream: older recursive value |
| 0x3C | Odd stream: older recursive value |

Scaled-input histories are signed 32-bit values. Recursive histories are transferred as 32-bit bit patterns and interpreted as signed 32-bit values for multiplication.

The selection stride is 0x38 bytes, but the last accessed field occupies offsets 0x3C–0x3F. Consequently, the stride does not establish independent, nonoverlapping records. The selected address must permit the specified accesses through offset 0x3F; no access to every preceding byte is implied.

### Sample layout and ordinary-use preconditions

Each frame contains two consecutive signed 16-bit samples:

- Even stream: sample indices 0, 2, 4, and subsequent even indices.
- Odd stream: sample indices 1, 3, 5, and subsequent odd indices.

For a nonnegative frame count, each sample buffer requires four accessible bytes per frame. An output sample occupies the same index as its corresponding input sample.

Required access permissions are:

- Read access to all five coefficients and eight history fields.
- Write access to all eight history fields.
- Read access to each input sample processed.
- Write access to each output sample produced.

There are no explicit null, bounds, selector, alignment, or overlap checks.

For ordinary bounded processing, the frame count should lie between zero and 0x3FFFFFFF inclusive, and all selector and sample-address calculations must reach valid storage without overflow or wrapping. This count range avoids overflow in the signed doubling used to form the loop bound; it does not independently make address calculations safe.

Allocation provenance, allocation extent beyond the required accesses, and ownership of all supplied storage are unknown.

## Behavior

### Initial reads and retained coefficients

After computing the selected address, the function reads four-byte fields in this order:

1. Input coefficient 0, at 0x14.
2. Input coefficient 1, at 0x18.
3. Input coefficient 2, at 0x1C.
4. Feedback coefficient 1, at 0x0C.
5. Feedback coefficient 2, at 0x10.
6. Even most recent recursive value, at 0x30.
7. Even most recent scaled input, at 0x20.
8. Even older scaled input, at 0x28.
9. Even older recursive value, at 0x38.

All five coefficients are retained for both passes. The function does not reload them before the odd pass. Later writes to their storage therefore do not change the coefficients already selected for this invocation.

### Sample arithmetic

Each iteration reads one signed 16-bit sample. Its scaled input is the sample multiplied by 512, corresponding to a nine-bit left shift in the supplied representation. The resulting mathematical range is −16,777,216 through 16,776,704.

The accumulator combines these five products:

- Current scaled input × input coefficient 0.
- Most recent scaled input × input coefficient 1.
- Older scaled input × input coefficient 2.
- Most recent recursive value × negated feedback coefficient 1.
- Older recursive value × negated feedback coefficient 2.

Each multiplication uses signed 64-bit operands after conversion. Feedback negation occurs at signed 32-bit width before widening. In particular, this is not an unrestricted 64-bit negation of the original coefficient.

Each individual product fits within signed 64-bit range when its signed 32-bit operands are representable. The sum of all five products need not fit. Overflow behavior is unresolved as described under Uncertainties.

The next recursive value is accumulator bits 24 through 55 inclusive, interpreted as a signed 32-bit value. This is a bit-window extraction:

- Bits 0–23 are discarded.
- Bits 24–55 become the retained value.
- Bits 56–63 do not contribute.
- No rounding increment or recursive-value saturation is present.

Under the represented bit interpretation, this is equivalent to shifting the accumulator right by 24 positions and retaining the low 32 bits. The result can therefore differ from a mathematically unbounded shifted result.

### Output conversion

The extracted signed recursive value determines the signed 16-bit output:

| Recursive value | Output |
|---|---|
| At least 16,776,704, or 0x00FFFE00 | 32,767 |
| At most −16,777,216 | −32,768 |
| Otherwise | Recursive value arithmetically shifted right by nine bits |

The lower comparison is strictly below −16,777,215, making −16,777,216 the first lower-limited integer value.

Under arithmetic-right-shift semantics, middle-range negative values round toward negative infinity rather than toward zero. A recursive value of −1 consequently produces output −1.

Only the output conversion is limited. The retained recursive history receives the extracted 32-bit value, not the emitted sample and not a value clamped to the output thresholds.

### Working-history transitions

After producing a sample:

- Its scaled input becomes the most recent scaled input.
- The previous most recent scaled input becomes the older scaled input.
- Its extracted recursive value becomes the most recent recursive value.
- The previous most recent recursive value becomes the older recursive value.

These histories are held in working state during the pass. The persistent fields are committed only after that pass finishes.

### Even pass and transition to the odd pass

The even pass processes sample indices starting at zero and increasing by two while the unsigned index is below the represented doubled frame count. Under the ordinary-use preconditions, it processes exactly one sample per frame.

For each iteration, the input read precedes the corresponding two-byte output write. All even-pass sample operations precede the even-history commit.

The even-history commit writes four-byte fields in this order:

1. Most recent recursive value to 0x30.
2. Most recent scaled input to 0x20.
3. Older scaled input to 0x28.
4. Older recursive value to 0x38.

Only afterward are odd histories read, in this order:

1. Most recent recursive value from 0x34.
2. Most recent scaled input from 0x24.
3. Older scaled input from 0x2C.
4. Older recursive value from 0x3C.

Thus, odd initial histories can reflect earlier output or state writes if the supplied storage overlaps.

### Odd pass and final commit

The odd pass starts at sample index one and increases by two, using the same retained coefficients. Under ordinary-use preconditions, it also processes exactly one sample per frame.

Each odd input read precedes its corresponding output write. After all odd samples, history fields are written in this order:

1. Most recent scaled input to 0x24.
2. Older scaled input to 0x2C.
3. Most recent recursive value to 0x34.
4. Older recursive value to 0x3C.

There is no subsequent even-history commit. In particular, an odd-pass output write that overwrites an already-committed even-history field is not repaired merely by completing the odd pass.

The function then returns without a result value.

### Zero frames

A zero frame count causes neither pass to access sample storage. Coefficients and histories are still read, and all eight history fields are written in the stated order.

With stable ordinary memory and no intervening mutation, those writes preserve the history bit patterns. Zero frames is not a memory-access-free operation.

### Final-history interpretation

The following guarantees require that neither sample buffer overlap coefficient/history storage, that relevant storage remain stable except for this function’s writes, and that arithmetic and address calculations follow the stated interpretation.

After one frame, each stream’s most recent histories contain its newly scaled input and extracted recursive value. Its older histories contain the values that were most recent before that stream began processing.

After two or more frames, each stream retains its final two scaled inputs and final two extracted recursive values.

These final-history guarantees do not apply generally when sample storage overlaps coefficient/history storage. In particular, disjoint input and output buffers alone are insufficient: odd output may overwrite committed even history.

## Acceptance examples

These are conditional static acceptance cases. None has been executed. Unless stated otherwise, arithmetic has the described machine interpretation, all accesses are valid, storage is stable, input and output are disjoint, and neither sample buffer overlaps coefficient/history storage.

### Identity transformation

Assume zero initial histories, input coefficient 0 equal to 0x01000000, and all other coefficients zero.

For one frame containing samples 123 and −456:

- Output is 123 followed by −456.
- Even most recent scaled input and recursive value become 62,976.
- Odd most recent scaled input and recursive value become −233,472.
- All older histories become zero.

The same coefficients preserve samples −32,768 and 32,767. Those endpoint values take the lower and upper limiting branches respectively.

### Negative fractional result

Assume zero histories, input coefficient 0 equal to 0x00800000, and all other coefficients zero.

For a sample of −1:

- Scaled input is −512.
- Extracted recursive value is −256.
- Output is −1 under arithmetic-right-shift semantics.

An output of zero would instead reflect truncation toward zero and would not match this interpretation.

### Output limiting preserves the recursive value

Assume zero histories, input coefficient 0 equal to 0x02000000, and all other coefficients zero.

For a sample of 20,000:

- Extracted recursive value is 20,480,000.
- Output is 32,767.
- The most recent recursive history retains 20,480,000.

Storing either 32,767 or 16,776,704 as that history would not match the recurrence.

### Empty processing

For zero frames and valid coefficient/history storage:

- No input or output sample access occurs.
- Even histories are committed before odd histories are read.
- All eight history fields are written.
- History values remain unchanged absent external mutation.
- No status value is returned.

### Output overlap invalidates a final-history guarantee

Assume zero initial histories and identity coefficients. Let the input be separate from both state and output, but let the output begin at selected-region offset 0x2E. Process one frame containing even sample zero and odd sample one.

The relevant observable order is:

- Even output zero is written at 0x2E.
- Even most recent recursive history is committed as zero at 0x30.
- Odd output one is written as two bytes beginning at 0x30.
- Odd history commits do not rewrite the even field at 0x30.

The final four-byte even recursive field is therefore no longer zero: part of it contains the representation of output one. Its exact numeric value depends on byte order.

Input and output are disjoint, and coefficient storage is unchanged, yet the ordinary final-history guarantee fails.

### Split processing

For disjoint input/output buffers, no sample-buffer overlap with coefficient/history storage, stable coefficients, no external mutation, and consistently defined arithmetic, dividing a frame sequence across successive calls must produce the same samples and final histories as processing that sequence in one call.

This follows from each stream retaining exactly the histories needed for its next sample. It is not a guarantee for overlapping storage: pass ordering and commits can then affect later reads, outputs, or persistent state.
