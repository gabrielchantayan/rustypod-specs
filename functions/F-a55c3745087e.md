# F-a55c3745087e

## Purpose

F-a55c3745087e implements a dependency-driven comparison with two possible ordinary outcomes: zero after an equal-zero result pair, or the arithmetic difference of an unequal result pair. Equal nonzero pairs extend the comparison.

The function establishes call ordering and a termination rule, not the meaning of the compared data. Nothing supplied establishes string inputs, character results, an encoding, locale-sensitive ordering, normalization, or independent traversal contexts.

This contract describes the visible function boundary and its dependency interactions. Dependency behavior is unresolved unless explicitly identified as established. All acceptance examples are conditional deductions from static evidence; no runtime tests have been performed.

### Result

- An equal-zero pair produces zero.
- An unequal pair produces the first result minus the second, subject to the arithmetic qualification below.

The result is not normalized to a three-valued comparison convention. For example, a representable difference of 5 is returned as 5, not replaced with 1.

There is no separately identified error return, output buffer, or status object. Values that a dependency might use as errors receive no special handling in this function.

### Completion and continuation

The function enters its first comparison cycle unconditionally after initialization. There is no early return based solely on either input argument.

An unequal result pair ends the comparison immediately after both results have been obtained. The returned value is their difference, with the first result as the minuend. No additional preparation, result, or finalization call is visible on that return path.

Equality permits continuation only when the common result is nonzero. Equal positive and equal negative pairs both continue. An equal-zero pair returns zero.

Zero has no independent early-stop effect in either result position. A first result of zero does not prevent the second preparation and result calls. A pair containing exactly one zero is unequal and follows the subtraction rule.

Initialization is not repeated between cycles. The same two local address positions recur. The function establishes neither a fresh reset of their contents nor a required persistence interpretation.

If all cycles yield equal nonzero pairs and dependencies continue returning normally, the function continues indefinitely. No iteration limit, timeout, cancellation mechanism, or independent progress check is visible. A dependency that blocks or does not return can also prevent completion, but the dependency conditions producing that outcome are unknown.

## Acceptance examples

The examples below assume valid required memory accesses, ordinary dependency returns, and representable arithmetic unless explicitly stated otherwise. Result pairs refer to successive returns from F-5afffd4d8a24, grouped by comparison cycle.

### Unequal first pair

With a first pair of 9 and 4, the result is 5. Both initialization calls and both preparation/result interactions occur. There is no second cycle. Returning only 1 would contradict the established arithmetic result.

### Equal-zero first pair

With a first pair of 0 and 0, the result is zero. The second preparation and result calls still occur. An implementation that returns after observing only the first zero would not preserve the call behavior.

### Continuation followed by mismatch

With successive pairs of 7/7 and 2/5, the result is −3. The equal nonzero pair requires a second cycle; the unequal pair ends it. Initialization occurs only once.

### Negative equality

A pair of −6/−6 requires another cycle. Negative equality is not a failure condition or termination condition in this function.

### Exactly one zero

A pair of 0/8 returns −8. A pair of 8/0 returns 8. These cases distinguish the equal-zero termination rule from a rule that stops on any zero.

### Persistent equality

An unlimited sequence of 3/3 pairs does not cause an ordinary return while dependencies continue completing normally. A fixed cycle cap would introduce behavior absent from the evidence.
