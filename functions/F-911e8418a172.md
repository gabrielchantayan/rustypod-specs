### Unsigned-value acquisition

The first check shifts the unsigned value right by 24 bit positions and compares the result with hexadecimal 24, which is decimal 36.

This is a comparison of the entire shifted result, not a masked comparison. Under a 32-bit unsigned interpretation, it requires bits 31 through 24 to equal hexadecimal 24. Under a wider unsigned interpretation, any bits above bit 31 would also affect the comparison and must not make the shifted result exceed hexadecimal 24.

### Product comparison

When the first check succeeds, the function compares:

- the unsigned value multiplied by hexadecimal 100000, or decimal 1,048,576; and
- hexadecimal 6400000, or decimal 104,857,600.

The second check is evaluated only after the first check succeeds. Acceptance requires both checks.

The multiplication’s arithmetic width is significant. Under a 32-bit unsigned interpretation, multiplication is reduced modulo \(2^{32}\). It is not an unbounded mathematical product, and the comparison is not an unsigned overflow check.

For a 32-bit unsigned value \(u\), the complete match condition is:

- bits 31 through 24 equal hexadecimal 24; and
- \(u \times 2^{20}\), reduced modulo \(2^{32}\), equals hexadecimal 06400000.

The product condition is equivalent to requiring the lowest 12 bits of \(u\) to equal hexadecimal 064. Multiplication by \(2^{20}\) discards the contribution of all higher input bits in a 32-bit result.

| Bit positions | Required value |
|---|---|

| 23–12 | Unconstrained |
| 11–0 | Hexadecimal 064 |

Thus there are 4096 accepted 32-bit values. The function does not require one exact 32-bit constant, and the middle 12 bits do not affect acceptance.

This reduction is conditional on 32-bit unsigned multiplication. An implementation or specification must not silently replace the multiplication with a low-12-bit comparison unless that width is established independently.
