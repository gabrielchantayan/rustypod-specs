# F-39477b54dbc3

## Purpose

F-39477b54dbc3 is a state-dependent routine whose recovered behavior begins by storing an incoming 32-bit state value into a context record. It then selects further operations according to whether that value is zero and, when nonzero, whether an incoming carry flag is set.

Three paths are visible:

- **Zero state:** skip the substantive branches and invoke an entry-continuation-relative dependency.
- **Nonzero state, carry set:** write a destination byte, copy another byte from the state-derived address, invoke dependencies, and update another context field before a final indirect call.
- **Nonzero state, carry clear:** interleave context writes with dependency calls, perform two halfword reads and a computed-address byte write, and reach an unresolved indirect transfer.

The application-level purpose is **documented_only**. The accesses do not establish that this is a constructor, parser, allocator, or ownership-transfer operation.

This contract describes the recoverable behavior and its ordering, not a verified complete machine-level function. Subsequent operations are conditional on preceding accesses succeeding and dependencies returning.

## Behavior

### Common entry and branch selection

The first visible memory operation stores the incoming state as a 32-bit value at context offset `0x64`. Only afterward does the routine test whether that state is zero.

Consequently, zero state does not suppress the initial memory access. No context-null check is visible.

For any nonzero state, the routine next writes the byte argument at destination offset `0x01`. It then selects the substantive branch using the incoming carry flag represented in the recovery. This is not an established comparison of the explicit arguments.

These preceding writes matter to later reads whenever their locations overlap.

### Zero state

With incoming state equal to zero, the destination writes and both substantive branches are skipped.

The routine invokes F-U14A using a target formed from the entry continuation plus `0x6BE`. If that invocation returns, the recovered stream reaches the invalid-data boundary.

The carry flag does not distinguish additional visible behavior on this path.

### Nonzero state with carry set

After the common context write and destination-offset-`0x01` write, the routine reads one byte from the incoming-state address plus `0x05`. It writes the byte actually read to destination offset `0x05`.

The source read is therefore **not** a snapshot of memory at entry. Either preceding write can change the source byte through aliasing.

F-fa0c227e09d7 is then invoked. After it returns, the routine loads a 32-bit address from work offset `0x54`. It next invokes F-U11, which supplies a recovered 64-bit result.

After F-U11 returns, the routine reads a 32-bit field at offset `0x24` from the previously captured address. F-U12 receives three established arguments:

- The low 32 bits of F-U11’s result.
- The high 32 bits of that result.
- The newly read 32-bit field.

The two reads have different dependency-sensitive timing:

- F-fa0c227e09d7 can affect the address subsequently loaded from work.
- F-U11 can affect the field subsequently read through that captured address.
- The routine does not visibly reload the address from work after F-U11.

After F-U12 returns, the routine stores the incoming state at context offset `0x74`, invokes F-U13, and then invokes F-U14B.

F-U14B uses an internally established continuation plus `0x6BE`, rather than the entry continuation used by F-U14A. The two target expressions are not established to designate the same address.

If these calls return, execution reaches the invalid-data recovery boundary.

### Nonzero state with carry clear

After the common writes, the routine invokes F-U01 through a target derived from the entry continuation plus `0xECC`.

It then interleaves context writes and calls in this order:

| Observable event | Following event |
|---|---|
| Store address/word argument at context offset `0x34` | Invoke F-U02 |
| Store word argument at context offset `0x24` | Invoke F-U03 |
| Store a 32-bit secondary output associated with F-U03 at context offset `0x14` | Invoke F-U04 |

F-U06 is invoked next and supplies a recovered 64-bit result, divided into low and high 32-bit halves.

The routine then writes one byte at:

- The work base plus the already loaded, zero-extended halfword.

The byte value is the low eight bits of the work-base value itself. It is not a byte fetched from the work record.

Next, the routine reads a second 16-bit quantity at the address formed by adding F-U06’s low and high halves. F-U07 receives four established arguments:

- The low half.
- The high half.
- The 32-bit negation of the low half.
- The second halfword.

The first halfword was read before F-U06. Changes by F-U06 to its source location do not change the captured offset.

The second halfword is read after the computed byte write. If that write overlaps the second read’s storage, the read observes the resulting memory contents under the execution environment’s memory rules.

## Acceptance examples

These are conditional consequences of the static representation, not execution results.

### Zero-state dispatch

Given a writable context and zero incoming state, the first visible store writes zero at context offset `0x64`. No direct destination-byte writes occur before F-U14A. Its target uses the entry continuation plus `0x6BE`.

### Carry-set copy with a stable source

Given nonzero state, carry set, byte argument `0xA7`, and a source byte equal to `0x3C` **immediately before the source read**, the routine writes `0x3C` to destination offset `0x05`.

The preceding destination-offset-`0x01` write stores `0xA7`. To derive the source read from an entry-time value of `0x3C`, both that write and the initial context write must leave the source byte unchanged.

Neither result is guaranteed to persist after dependencies execute.

### Carry-set copy with overlapping source and destination

Suppose the incoming-state address is `0x1000`, the destination base is `0x1004`, and the byte argument is `0xA7`. Assume the initial context store is disjoint from these relevant bytes and accesses succeed.

Destination offset `0x01` and source offset `0x05` both designate `0x1005`. The destination-byte write therefore replaces any earlier source value with `0xA7`. The following source read obtains `0xA7`, and the copy writes `0xA7` at destination offset `0x05`, address `0x1009`.

An entry-time source value of `0x3C` does not change this outcome.

### Dependency-sensitive field read

If F-fa0c227e09d7 changes the address stored at work offset `0x54`, the subsequent address load uses that changed value.

If F-U11 then changes the field at the captured address plus `0x24`, F-U12 receives the changed field value, provided the read succeeds.

### Unsigned offset and byte truncation

If the first halfword is `0xFFFE` and the work base is `0x100000AB`, the computed byte write targets `0x100100A9` and stores `0xAB`, under the 32-bit address interpretation.

The offset is 65,534, not −2.

### Negation boundary
