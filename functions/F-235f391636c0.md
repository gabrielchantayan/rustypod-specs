# F-235f391636c0

## Purpose

F-235f391636c0 classifies an integer input into one of three result bit patterns:

- Input equal to 1 produces a 32-bit result of `0x00000001`.
- Input equal to 255 produces a 32-bit result of `0xFFFFFFFF`.
- Every other input produces a 32-bit result of `0x00000000`.

This is an exact-value classification, not a nonzero-to-true conversion, range check, or low-byte extraction. In particular, most nonzero inputs produce zero.

## Behavior

### Classification and decision order

The visible control flow makes the following decisions in order:

1. It determines whether the input is zero.
2. For a nonzero input, it checks equality with 1.
3. Only for a nonzero input that is not 1, it checks equality with 255.
4. Any input not selected by the two special cases produces zero.

Consequently, zero reaches the default result without the later equality checks. Input 1 selects its result before the equality check against 255. Input 255 reaches the second special case.

These checks concern the supplied scalar value. They are not reads from an external memory location or repeated calls to obtain a changing input. No externally observable memory-read sequence is established.

### Exact matching

Both nonzero special cases require equality of the integer value, not equality of a selected byte or subset of bits.

For example, under the working 32-bit input interpretation:

- `0x000000FF` matches 255.
- `0x000001FF` does not match 255, despite having the same low byte.
- `0xFFFFFFFF` does not match 255. Interpreted as a signed 32-bit input, it represents −1 and receives the default result.

The all-ones result for input 255 does not mean that an all-ones input receives that same result.
