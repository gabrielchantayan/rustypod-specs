# F-889d0c8bf3d7

## Purpose

F-889d0c8bf3d7 selects one of four records through two ordered searches. It first seeks a record for which a comparison dependency returns zero. Only if all four comparisons are nonzero does it seek a record for which a separate eligibility dependency returns zero.

Selection causes an explicit increment of a 32-bit record field, followed by a 32-bit write of the selected index to caller-provided storage. A selection in the second search also invokes an update dependency unless the selected record address equals the address of a local temporary object.

The established return statuses are:

| Status | Condition |
|---|---|
| `0` | A record is selected in either search. |
| `0x15` / 21 | The second input is zero. |
| `0x19` / 25 | Both searches finish without selecting a record. |

The structure suggests a preference for an existing match over an available record. The meanings of “match,” “available,” and “update” are inferred intent, not established semantics of the opaque dependencies.

This contract describes static evidence from the supplied representation. It does not establish behavior inside dependencies or report runtime verification.

## Behavior

### Immediate rejection

The value input is checked before any dependency call or record access.

If it is zero, the function returns `0x15`. It performs no dependency call, direct record read, direct record write, or output write on this path.

This status is independent of search exhaustion.

### Preparation for a nonzero value

Preparation occurs before either search, in this order:

1. F-62673223987f is called with the record-region base.
2. One byte is read from its returned address plus `0x254`.
3. F-62673223987f is called again; this invocation has no explicit argument in the supplied representation.
4. F-b9acea4b06ad receives the eight-byte local destination and the second lookup result plus `0x24C`.
5. F-b5f4a3351c2f receives the other local destination, the value input, the eight-byte preparation object, the captured byte, and the auxiliary input, in that order.
6. F-289ec4311c64 is called on the eight-byte preparation object.

The byte is captured before the second lookup and is not reread afterward. Nothing establishes that the two lookups return the same address or that either lookup preserves global or record state.

The captured quantity is one byte wide. Its interpretation and any argument-promotion convention are not established.

The function does not inspect a status from the preparation, construction, or preparation-object finalization calls. If they return normally, searching proceeds without a separate visible success check.

### First search: comparison results

The first search visits candidates 0, 1, 2, and 3 in ascending order, stopping at the first zero comparison result.

For each visited candidate:

- F-338d16f9ce72 is called with the candidate’s `+0x1C` address.
- F-44362605ab79 is called with the constructed local object’s address.
- The 32-bit word at candidate offset `+0x04` is read.
- F-4a6c0bf0740c receives that record word as its first operand and the extraction result as its second operand.
- The comparison result is tested against zero.

The extraction call occurs anew for every visited candidate. Neither its result nor its effects may be assumed stable between visits. The record word is read after extraction returns, so it can reflect mutations performed by that call or earlier calls.

For a nonzero comparison result, F-1333331b2da1 is called with the same candidate’s `+0x1C` address before advancing.

For a zero comparison result, the function:

- Reads the selected record’s 32-bit field at `+0x14`.
- Adds one and writes the result back to that field.
- Writes the selected index to the 32-bit output location.
- Calls F-1333331b2da1 on the selected candidate’s `+0x1C` address.
- Calls F-289ec4311c64 on the constructed local object.
- Returns zero.

No eligibility query or update-dependency call occurs on this success path. Later candidates are not visited.

The increment uses the counter value read after the comparison call returns, not necessarily its value at function entry.

### Second search: eligibility results

The second search begins only after all four first-search comparison results are nonzero. F-1333331b2da1 for the last first-search candidate occurs before the second search begins.

The search restarts at candidate 0 and proceeds in ascending order.

## Acceptance examples

These are conditional specifications, not executed tests. Unless stated otherwise, reached memory operations are valid and dependencies return normally. Specified writes are distinguished from values remaining after subsequent effects.

1. **Zero input.** If the value input is zero, the function returns `0x15` without calling dependencies or accessing records or output storage.

2. **Immediate comparison selection.** If candidate 0’s comparison returns zero and its counter equals 8 immediately before the explicit increment reads it, the function explicitly writes 9 to that counter, then writes index 0. It performs the selected visit’s ending call and constructed-object finalization before returning zero. No later candidate is visited. A final counter value of 9 additionally requires that the output write and subsequent dependency effects do not alter it.

3. **Comparison selection takes precedence.** If comparisons at indices 0 and 1 are nonzero and index 2’s comparison is zero, index 2 is selected. No eligibility call occurs, regardless of what any candidate’s eligibility result would have been.

4. **Second-search selection.** If all comparisons are nonzero, eligibility results at indices 0 and 1 are nonzero, and index 2’s result is zero, index 2 is selected. Its update call occurs only if its address differs from the constructed-object address. Its counter increment follows that conditional call. Index 3 is not queried in this search.

5. **Post-update counter value.** If the selected second-search counter equals 20 immediately before the explicit counter read, the increment explicitly writes 21. This remains true if an earlier update changed the field from 7 to 20. It does not require the field to remain 21 after the output write and ending dependencies.

6. **Update suppression.** If second-search selection occurs and the selected record address equals the constructed-object address, F-151ab4bfe553 is not called. Subject to valid accesses, the remaining successful-path operations still occur.

7. **Exhaustion.** If all four comparison results and all four eligibility results are nonzero, there are eight visits with paired beginning and ending calls. Constructed-object finalization follows, and the function returns `0x19` without an explicit counter or index write.

8. **Counter-output overlap.** If output aliases the selected counter, the explicit increment write is followed by a write of the selected index to that same word. Immediately after the output write it contains that index; its value on return additionally depends on subsequent effects.
