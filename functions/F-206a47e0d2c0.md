# F-206a47e0d2c0

## Purpose

F-206a47e0d2c0 performs an ordered update on an object: it records a supplied value, prepares invocation-local storage, processes a dependency-supplied range into an embedded subobject, applies mode-dependent state, optionally calculates an adjustment, and issues five final virtual calls.

This contract describes observable accesses and dependency interactions established by the supplied static representation. Labels such as “cache,” “pending,” “lookup,” and “notification” identify roles within this contract; they do not establish application-level semantics.

The function has no explicit return value or error result. Its observable outputs are memory writes and dependency calls. There is no explicit rollback, retry, or local error handler.

### Range processing

F-6d03eb593399 receives the embedded address at `+0x0C0`.

F-80474946e6fd then receives the object, the counter address, and the bound address, in that order. Neither range local has a fallback initialization in the representation. Usable values are required before their subsequent reads.

The loop compares the current counter and bound as signed 32-bit values. An iteration is admitted when the counter is less than or equal to the bound.

Each admitted iteration has this observable order:

1. Read the current object field at `+0x0BC` and the current counter for F-3593620aad0a.
2. Call F-3593620aad0a with those values.
3. Call F-01ef5e396f42 with the returned 32-bit value, the local-region address, and the embedded address at `+0x0C0`.
4. Increment the then-current counter by one and store it back.

The field at `+0x0BC` is read anew for each iteration. A previous iteration’s value is not retained for later iterations.

If dependencies preserve the range locals after initialization, the loop traverses an ascending inclusive signed range. An initial counter greater than the bound produces no per-index calls.

Preservation is not established. Dependencies have received the local addresses and may retain them while the invocation remains active. A counter mutation during an iteration affects the later increment, not the index already passed to F-3593620aad0a. A bound mutation affects the next condition. Indices may consequently be skipped or repeated, and termination is not guaranteed.

The increment also occurs after processing an index equal to the bound. Incrementing the maximum signed 32-bit value is an unresolved arithmetic boundary; wraparound or successful termination is not established.

### Completion and mode state

In nonzero mode, F-2197eca7dd3f then receives the main object. It is skipped in zero mode.

- Zero in nonzero mode.

### Optional adjustment

The pending byte at `+0x295` is read. A zero value skips all adjustment work.

If nonzero, the function clears that byte before calling F-938c950e5046. A null result skips the remaining adjustment sequence. This function does not restore the pending flag.

For a nonnull result, the returned receiver’s virtual operation at `+0xE8` receives that receiver and the current lookup-token value. Its result is treated as a target pointer.

After the lookup returns, the current cache-reference source slot is read and retained locally. This capture occurs even when the target is null. A null target then skips all remaining cache and adjustment operations.

For a nonnull target, population is conditional:

1. Read the cache-reference source slot again.
2. Read the unsigned 32-bit word at that reference plus `0x14` and test bit zero.
3. If the bit is set, skip population.
4. Otherwise, read the cache-reference source slot again and pass that reference plus `0x14` to F-b255b26284e6.
5. A zero result skips population.
6. A nonzero result permits calculation of the signed 32-bit difference between target field `+0x8C` and target field `+0x84`.
7. Write that difference to offset `+0x18` of the cache object captured immediately after lookup.
8. Call F-d08d3ca17b81 with the captured cache address plus `0x14`.

The capture, eligibility test, and gate argument use separate represented reads of the same cache-reference source slot. Their values are not guaranteed equal. The write destination and post-write call remain based on the captured reference, even if later reads produce a different reference.

The relative order of the two target-field reads is not established.

Whether population occurs or is skipped, a nonnull target proceeds to adjustment selection:

- Read the represented word at object offset `+0x294` and test its low-byte character value.
- Subsequently read the signed 32-bit value at captured-cache offset `+0x18`.
- If the selector tested zero, use that value unchanged.
- Otherwise, subtract 18.
- Call F-bfa8d5524d41 with the target and resulting adjustment.

The selector read precedes the cache-value read.

A population write does **not** establish the later adjustment value. F-d08d3ca17b81 runs between that write and the selector/cache reads. Its contract is unavailable, so preservation of either the selector or cached contents is unknown. An unchanged cache-reference value does not imply unchanged referent contents.

Neither target-field subtraction nor subtraction of 18 has an explicit overflow check. Saturation, modular arithmetic, and overflow reporting are not established.

### Five final virtual calls

After optional adjustment finishes or is skipped, five calls occur on the main object through virtual-table offset `+0x58`.

| Call | Key argument | Payload argument |
|---|---|---|
| 1 | Direct read of first-key slot | Direct read of common-payload slot |
| 2 | Direct read of middle-key slot | Retained common payload |
| 3 | Retained middle key | Direct read of third-payload slot |
| 4 | Direct read of last-key slot | Direct read of fourth-payload slot |
| 5 | Retained last key | Direct read of fifth-payload slot |

The retained values are captured at these points:

- Common payload: before call 1.
- Middle key: after call 1 and before call 2.
- Last key: after call 3 and before call 4.

The direct reads in calls 1, 2, and 4 remain separate from their respective preceding captures. There is no explicit intervening dependency call, but equality still requires stability over that interval.

Call 1 may change the middle-key source slot before its capture. Call 2 cannot change the value already retained for call 3 merely by changing that slot. Similarly, changing the last-key source slot during call 4 does not change the retained key passed to call 5.

The main-object dispatch pointer is read afresh for each call. Earlier callbacks are not assumed to preserve the object’s dispatch state or external source-slot contents. The representation does not establish a total order among dispatch and argument reads within an individual call expression.

## Acceptance examples

These are conditional static consequences, not runtime tests. Unless stated otherwise, they require valid reached storage, normal dependency returns, preserved range locals, and arithmetic within signed 32-bit limits.

1. **Zero mode, empty range.** A counter of 7 and bound of 6 produce no per-index calls. The zero-mode local operation and embedded completion still occur. F-2197eca7dd3f is skipped, and the direct mode-byte write is one.

2. **Negative mode.** Mode −3 and range 4 through 4 select nonzero behavior and process index 4 once. Embedded completion precedes F-2197eca7dd3f, which precedes the zero write at `+0x0EC`.

3. **Fresh per-iteration field read.** For range 2 through 3, if processing index 2 changes `+0x0BC` and that change persists, F-3593620aad0a receives the changed field for index 3.

4. **Mutable counter and bound.** Starting at counter 2 and bound 3, suppose the first iteration changes them to 5 and 6 through retained addresses. The increment stores 6. If subsequent calls preserve both, the processed indices are 2 and 6.

5. **Pending without a provider.** A nonzero pending byte is cleared before F-938c950e5046 returns null. No target lookup or adjustment follows. Final calls remain reachable, with no pending restoration by this function.

6. **Population and later reads.** Target fields observed as 150 and 50, a clear eligibility bit, and a nonzero gate produce a cache write of 100. If the later selector is `0x00000100` and the later cache read yields 100, the adjustment is 100. With selector `0x00000001` and the same later cache value, it is 82.

7. **Post-write mutation.** Under those population conditions, if F-d08d3ca17b81 changes the captured cache value to 64 and that is subsequently read, adjustment is 64 for a zero selector low byte or 46 otherwise. The earlier write of 100 still occurred.

8. **Skipped population.** A set eligibility bit skips both population dependencies. A zero gate result skips the write and post-write call. Either path still calculates adjustment from the later read of the captured cache.

9. **Retained notification arguments.** If call 1 changes common payload and middle key, call 2 uses the previously captured common payload and the directly read middle key. A middle-key change during call 2 does not replace call 3’s retained key.

10. **Equal values in distinct slots.** First-key and middle-key source slots may both contain 12. They remain separate storage: if call 1 changes only the middle-key slot to 19 and that value remains stable, call 2 uses 19. Equality of the earlier values creates no source-slot aliasing. Possible aliasing of referenced objects is a separate question.
