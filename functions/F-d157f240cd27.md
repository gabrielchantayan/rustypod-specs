# F-d157f240cd27

## Purpose

F-d157f240cd27 performs an ordered sequence of memory mutations using two explicit inputs and three additional entry-state values. It finishes by invoking an unresolved indirect destination with four arguments.

The established behavior is memory manipulation and indirect dispatch. No application-level purpose, object type, protocol, or ownership model is established. In particular, the repeated writes must not be interpreted as initialization that can safely be consolidated: repetition, overlapping destinations, and intermediate values may be observable.

This contract distinguishes:

- **Established static evidence:** operations and ordering represented in the supplied material.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** unresolved properties for which no executable guarantee is available.

No runtime tests have been performed.

## Behavior

### Widths, arithmetic, and interpretation

A byte is 8 bits, a halfword is 16 bits, and a word is 32 bits throughout this contract.

Byte extraction retains the low eight bits. Thus a byte written from an address-like value is not the complete address, nor a checked conversion.

Doubling the primary base is represented as unsigned 32-bit arithmetic. Its numerical result is therefore the low 32 bits of twice that value. This result is used both as stored data and as part of a destination address.

Other address expressions include additions and doubled values represented with signed integer types. Their overflow behavior is not established sufficiently to promise portable wraparound semantics. Examples below avoid these boundaries.

Endianness is not established. Full-word values can be specified independently of endianness; their individual bytes and the consequences of partial overlap cannot.

### Repeated-write prefix

The function first performs repeated writes to four destinations:

| Destination | Access width | Written value |
|---|---:|---|
| Primary base + 0x11 | 8 bits | Low byte of the secondary base |
| Secondary base + 0x34 | 32 bits | Initial word on the first occurrence; doubled primary base on subsequent occurrences |
| Doubled primary base + 0x54 | 32 bits | Payload |
| Secondary base + 0x19 | 8 bits | Low byte of the primary base |

Within each complete group, the writes occur in the order shown. After the complete groups, a final partial group writes the first two destinations, with the doubled primary base used for the second write.

There are no visible intervening memory reads in this prefix. Destination aliasing can nevertheless make its order significant. The initial word is genuinely written even when a later write replaces it.

The exact number of repeated groups is **documented_only** in this contract; no independently validated access count is supplied. This does not authorize replacing the prefix with one write per final destination.

### Initial snapshots and byte publication

Following the prefix, the function reads a 32-bit snapshot from fixed address 0xA9 and a 32-bit snapshot from payload offset 0x74, in that order.

It then writes a byte at fixed address 0x3A. Its bit pattern is the low eight bits of twice the primary base’s low byte, plus 0x30. This arithmetic does not establish a decimal-digit encoding or a character-validation rule.

Next, it reads a word at tertiary-base offset 0x14, followed by a word at primary-base offset 0x04. These are separate snapshots taken after the earlier prefix and fixed-address byte write.

It then makes the following ordered changes:

- Tertiary-base offset 0x0D receives the low byte of the primary base.
- Primary-base offset 0x08 receives 0x6C.
- Primary-base offsets 0x0D and 0x09 each receive the low byte of the secondary base, in that order.
- Tertiary-base offset 0x54 receives the complete tertiary-base value.
- Fixed address 0x67 receives the low byte of the earlier snapshot from address 0xA9.

These operations do not imply that the surrounding storage forms a structure with known fields.

### Loaded-word processing and overlapping updates

The function next reads a signed 32-bit word at tertiary-base offset 0x44. Call this the **loaded control word**.

After this read, fixed address 0x21 receives the byte read from fixed address 0x67. The low byte of the loaded control word is then written at primary-base offset 0x10, and the complete loaded control word is written at secondary-base offset 0x54.

A shifted byte is subsequently written at tertiary-base offset 0x01. Its source is the signed loaded control word shifted right by the low eight bits of the primary base, then reduced to a byte.

For nonnegative loaded control words and shift counts below 32, the mathematical effect is established. The behavior for negative values or counts of 32 through 255 depends on unresolved signed-shift and target-instruction semantics.

Secondary-base offset 0x54 is then overwritten with the complete primary-base value.

The next word read is at primary-base offset 0x40. Only after this read does secondary-base offset 0x74 receive the earlier snapshot from primary-base offset 0x04. The newly read word from offset 0x40 is then written at primary-base offset 0x10.

This last word write covers offsets 0x10 through 0x13, including the location previously updated by a byte write. It can also replace bytes written by the repeated prefix.

The function then:

- Writes the complete tertiary-base value at secondary-base offset 0x44.
- Copies the currently read byte at fixed address 0x67 to primary-base offset 0x09.
- Writes the original word snapshot from fixed address 0xA9 at primary-base offset 0x44.
- Reads a word at primary-base offset 0x54 as the **linked base**.
- Again copies the byte read at fixed address 0x67 to primary-base offset 0x09.

The two copies from address 0x67 are distinct operations. Intervening writes may affect what they read if the addresses alias; equality is not guaranteed solely by their common source address.

### Linked-memory updates and final snapshots

The low byte of the earlier payload-offset-0x74 snapshot is written at linked-base offset 0x0D.

Tertiary-base offset 0x54 is then overwritten with the earlier snapshot from tertiary-base offset 0x14. This replaces the self-address value written there previously.

A word is read at primary-base offset 0x14. Its low byte is retained for a later write. Before that later write:

- Tertiary-base offset 0x11 receives the low byte of the payload-offset-0x74 snapshot.
- Primary-base offset 0x09 receives the low byte of the linked base.
- Primary-base offset 0x44 receives the complete linked base.
- A word is read at tertiary-base offset 0x04 as the **record base**.

The function writes the halfword value 0x0065 at twice the record base. It then reads a signed word at record-base offset 0x64 as the **record value**.

The retained low byte from primary-base offset 0x14 is written at linked-base offset 0x11. Linked-base offset 0x54 then receives the word value 100.

Next, a word is read at record-base offset 0x74 as the **dispatch word**, followed by a word at tertiary-base offset 0x64 as the **destination base**.

Finally, before dispatch:

- Tertiary-base offset 0x09 receives the low byte of the record base.
- Destination-base offset 0x54 receives the complete record value.
- Twice the record value is used as an address at which the complete destination base is written.

The decimal offset 100 and hexadecimal offset 0x64 identify the same offset.

### Indirect invocation

After all preceding accesses, the unresolved destination is invoked with these four arguments, in order:

1. The constant 0x72.
2. The record value.
3. The earlier word snapshot from tertiary-base offset 0x14.
4. The dispatch word read from record-base offset 0x74.

The third argument is a retained snapshot, not a fresh read of tertiary-base offset 0x54 or offset 0x14. The fourth argument is likewise the value read at its specified point, even if a subsequent write aliases its original storage.

## Side effects

### Observable memory behavior

The contract concerns ordered accesses, not merely final memory contents. Intermediate writes matter where memory is shared, externally observed, mapped to devices, or aliased.

There is no visible synchronization, atomicity guarantee, or transaction boundary. A failure partway through execution may leave earlier writes in place; no rollback is shown.

No direct allocation, release, ownership transfer, or resource-management operation is visible. Writing an address-like word does not establish ownership of the referenced storage.

### Fixed-address state

The visible path reads four bytes beginning at address 0xA9 and writes individual bytes at addresses 0x3A, 0x67, and 0x21. It also reads address 0x67 when copying that byte elsewhere.

These addresses must not be treated as necessarily disjoint from computed destinations. The supplied material explicitly cautions about overlapping global storage, but does not provide a complete storage map.

### Errors

No error result, error flag, exception handling, or recovery path is visible. Access faults and failures within the indirect destination have no established handling contract.

## Acceptance examples

These are conditional specification examples, not executed tests.

### Distinguishing the initial write from the final value

Assume all relevant regions are valid, stable, and disjoint. Let the primary base be 0x1000, the secondary base be 0x2000, the payload be 0x3000, and the initial word be 0xDEADBEEF.

The prefix writes 0xDEADBEEF at address 0x2034 before later writing 0x00002000 there. A trace containing only the final value is insufficient to establish preservation of the write sequence.

Each complete prefix group also writes 0x00 at addresses 0x1011 and 0x2019, and writes 0x00003000 at address 0x2054. Later phases can change some of these locations.

### Byte arithmetic boundary

Assume the primary base has low byte 0xF0 and execution reaches the fixed-address write safely. Address 0x3A receives 0x10: the low byte of twice 0xF0 plus 0x30.

No requirement restricts this result to a printable character.

### Shift with an established interpretation

Assume the loaded control word is 0x12345678, the primary base has low byte 8, and no earlier aliasing changes the loaded value.

The byte written at tertiary-base offset 0x01 is 0x56. This example does not settle negative signed shifts or counts at least 32.

### Snapshot preservation across overwrites

Assume tertiary-base offset 0x14 initially yields 0x11223344, and no earlier operation changes it before that read.

The visible path first writes the tertiary-base value at tertiary-base offset 0x54, then later writes 0x11223344 there. The third dispatch argument is also 0x11223344. These requirements concern the saved value even if later writes change its original storage.

### Aliasing changes later reads

If a prefix destination overlaps payload offset 0x74, the later payload-relative snapshot reflects the memory state after the prefix. It is not required to equal the word present on entry.

Likewise, if the halfword write at twice the record base overlaps record-base offset 0x64, the subsequently read record value must reflect that ordering under the applicable memory semantics.
