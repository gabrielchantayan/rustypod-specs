# F-7b23d6f64a0d

## Purpose

F-7b23d6f64a0d conditionally locates a record through two dependent lookups, obtains an intermediate representation, processes that representation into temporary storage, invokes a transfer-like dependency, and publishes two 32-bit fields from the selected record.

Its explicit result is a 32-bit status value: zero for lookup failure or either checked processing failure, and one after the transfer-like dependency returns normally and both field assignments execute. This status does not establish that the transfer-like dependency independently reported success: its return value is not checked.

The interpretation of the temporary representation as encoded data, and of the later operation as a payload transfer, is inferred intent. The established behavior is the dependency sequence, branch conditions, temporary-storage relationships, and ordered field accesses described below.

## Behavior

### Initialization and lookup

The function selects zero as its initial return status, then invokes F-576ea5ba1d23 with the address of the 8-byte temporary region.

Only after that invocation returns does it read the 32-bit word addressed by argument 1. That word and argument 2 are passed to F-b2834716058d.

If the first lookup returns zero:

- The dependent lookup is not invoked.
- Neither processing dependency nor the transfer-like dependency is invoked.
- The function performs no direct writes through arguments 5 or 6.
- Cleanup is invoked, followed by a zero return if cleanup returns normally.

If the first lookup returns nonzero, that result and argument 3 are passed to F-69facf68ac4d. A zero result from this dependent lookup produces the same direct-output and return behavior as initial lookup failure.

A nonzero dependent-lookup result selects the record used for subsequent processing and field reads. No explicit record validation, reference acquisition, or ownership transfer is visible.

### Checked processing stages

A nonzero result from this dependency terminates processing:

- F-e655cd5ea760 is skipped.
- F-b287fa5e8a41 is skipped.
- Neither record field is directly assigned to an output.
- Cleanup is invoked, followed by a zero return if cleanup returns normally.

A zero result permits the next stage. F-e655cd5ea760 receives:

1. The address of the 260-byte temporary region.
2. A literal zero.
3. The address of the 16-bit field preceding the 510-byte region.

Its result is likewise tested against zero. A nonzero result causes cleanup and a zero return, without invoking the transfer-like dependency or directly assigning either output field.

Neither temporary data region is explicitly cleared before its first dependency call. On the continued-success path, the function relies on the dependencies to have established whatever contents their later consumers require.

### Transfer-like operation and publication

1. Argument 4.
2. The address of the 510-byte temporary region.
3. The value read from the adjacent 16-bit field.

The field supplies 16 bits of stored information. The supplied evidence does not establish the signedness of the dependency’s formal parameter or the exact extension applied at its calling boundary. No explicit comparison against the 510-byte region’s capacity appears.

The transfer-like dependency’s result is ignored. If it returns normally, the function selects one as its return status and then performs these accesses in order:

1. Read the 32-bit field at selected-record offset 24.
2. Write that value through argument 5.
3. Read the 32-bit field at selected-record offset 28.
4. Write that value through argument 6.
