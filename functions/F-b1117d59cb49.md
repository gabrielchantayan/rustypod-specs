# F-b1117d59cb49

## Purpose

The established behavior is a straight-line sequence of indirect calls, 32-bit memory transfers, bit-field extraction, byte updates, and a final 16-bit clear followed by a call to address zero.

No application-level purpose is established. The repeated scaled-address stores and byte updates may manipulate an encoded runtime representation, but interpreting them as allocation, object initialization, reference counting, or device control would exceed the evidence.

This contract describes the supplied static representation. It does not establish that the representation accurately models executable instructions, that the referenced addresses are accessible, or that execution can reach the end.

## Interface

### Explicit inputs and result

The displayed interface has:

- A first 32-bit argument with no visible use.
- A second 32-bit argument used as an index for the first store and passed to the first indirect dependency.
- No explicit return value.

The absence of a visible use of the first argument does not establish that dependencies cannot observe its incoming register value.

### Additional entry state

Behavior also depends on machine state not represented by the two explicit arguments:

- An incoming 32-bit word, designated **entry payload**.
- An incoming address-like value, designated **entry base**.
- An incoming link/address value used to calculate the first indirect call target.
- Registers subsequently exposed as secondary outputs of indirect calls.
- Two global storage regions, designated **global A** and **global B**.
- A byte at absolute address 1.
- A three-byte global contribution used in the final update of global B.
- All memory read through computed addresses.

These are dependencies of the observed representation, not a recovered calling convention.

### Width and address notation

For the behavioral description:

- **Word** means 32 bits.
- **Byte** means 8 bits.
- **Halfword** means 16 bits.
- **Pair** means a 64-bit result treated as a low word and a high word.
- A **word slot** for index \(x\) is the address \(4x+20\).
- A **byte-selected location** for selector \(x\) is obtained by reading one byte at address \(x+1\), zero-extending that byte, and adding 17.
- Copying a word into a byte destination retains only the low eight bits.
- Right shifts of values described as unsigned are logical.

Several expressions operate on signed-looking intermediates, including left shifts and multiplication. Exact overflow semantics are not established. Where necessary, examples below explicitly assume 32-bit wrapping arithmetic. The representation does not establish endianness, alignment requirements, or behavior on invalid access.

## Behavior

### Sequencing rule

The following stages are ordered. Every listed dependency call completes before the next listed direct operation, if it returns normally. No branch, loop, explicit error check, or rollback appears.

“No-argument call” means that no arguments are shown in the supplied representation. It does not guarantee that the callee observes no register or memory inputs.

Values described as captured remain local values in this representation even if later dependencies change the memory from which they originated. Conversely, an expressly repeated read is not interchangeable with an earlier captured value.

### 1. Initial write and entry-state capture

1. Store the entry payload as a word in the word slot selected by the second explicit argument.
2. Read a word at entry base plus 20 and retain it as the **entry field**.
3. Invoke an indirect dependency with the second argument.

The initial store precedes the entry-field read. If their addresses overlap, the read observes memory after that store, subject to the execution model.

### 2. First payload propagation

Perform a no-argument call and pass its word result to another call. Perform three further no-argument calls, then another no-argument call whose word result selects a word slot.

Store the entry payload in that slot. Read global A as a word and retain it as the **first global sample**. Invoke a dependency with four times the returned slot index.

Then perform four no-argument calls. The secondary word output associated with the last call supplies the **first secondary index**.

Compute:

- **entry fragment**: entry field shifted right by 22, yielding a value from 0 through 1023.
- **global fragment**: first global sample shifted right by 23, yielding a value from 0 through 511.

Store the entry fragment in the word slot selected by the first secondary index. Invoke a dependency with four displayed arguments: that index twice, then the global fragment, then the entry fragment.

### 3. Repetition of the entry fragment

Perform a no-argument call and forward its result to another call. Perform three no-argument calls, then obtain a slot index from another no-argument call.

Store the entry fragment in that word slot. Invoke a dependency with four times the index.

Perform four no-argument calls. Retain the secondary unsigned word output of the last as the **second secondary index**.

Store zero in its word slot, then invoke a dependency with that index.

A second right shift of the global fragment by 23 is also computed during this stage. Because the global fragment is already at most 511, this second shift is always zero.

### 4. Zero propagation and indexed read

Perform a no-argument call, forward its result to another call, perform three no-argument calls, and obtain another slot index from a no-argument call.

Store zero in that word slot.

Read a word at:

\[
20 + ((\text{second secondary index} \mathbin{\&} \texttt{0x1fffffff}) \gg 19).
\]

The added offset ranges from 0 through 1023. It is not multiplied by four, so word alignment is not guaranteed.

Invoke a dependency with four times the slot index, then perform four no-argument calls.

Shift the captured word right by 22, producing the **indexed fragment**, from 0 through 1023.

Read the byte at absolute address 1, add 17 to its zero-extended value, and store the low byte of the indexed fragment there. This fixed selector follows from the double right shift described above.

Invoke a dependency with a secondary word output repeated three times, followed by zero.

### 5. Byte clear selected by the indexed fragment

Perform a no-argument call, invoke another dependency with zero, perform three no-argument calls, and obtain a word result from another no-argument call.

Read one byte at address \(4 \times \text{indexed fragment}+1\). Store zero at the address obtained by adding 17 to that byte.

Invoke a dependency with the preceding word result shifted left by two.

Perform three no-argument calls and obtain another word result from a fourth. Invoke a dependency with that result shifted left by two in both argument positions.

### 6. First fresh word and fixed-selector clear

Obtain a word from a no-argument call; retain it as the **first fresh word**. Pass it to another dependency, then perform one no-argument call.

Read the byte at absolute address 1 and clear the byte at its zero-extended value plus 17.

Capture a secondary word output as the **retained secondary word**. Invoke a dependency with this word repeated in three displayed argument positions.

### 7. Second fixed-selector clear

Perform a no-argument call. Invoke a dependency with its result and the first fresh word shifted right by 23.

Perform three no-argument calls and obtain another word result from a fourth.

Read the byte at absolute address 1 again, retaining the zero-extended value as the **saved byte base**. Clear the byte at saved byte base plus 17.

Invoke a dependency with the preceding returned word shifted left by two. Perform three no-argument calls, obtain another word result from a fourth, and invoke a dependency with that result shifted left by two twice.

The reads of address 1 in stages 4, 6, and 7 are distinct. Intervening dependencies may change that byte.

### 8. Global B update and first word-to-byte copy

Obtain a word from a no-argument call and retain it as the **published word**. Store it in global B before invoking a dependency with that same captured word.

Perform one no-argument call.

Read a word at saved byte base plus 116, then write its low byte at saved byte base plus 1.

Invoke a dependency with the retained secondary word shifted left by 11.

### 9. Pair forwarding and repeated byte copy

Obtain a pair from a no-argument call. Invoke another dependency with its low word, its high word, and the published word shifted right by 23.

Perform three no-argument calls and obtain an index from a fourth. Scale the index by four and retain the resulting **copy base**.

Read a word at copy base plus 116 and write its low byte at copy base plus 1. Invoke a dependency with copy base.

Perform three no-argument calls and obtain another word result from a fourth. Retain four times that result as the **retained scaled word**.

Read the word at copy base plus 116 again and again write its low byte at copy base plus 1. Intervening dependencies can make this second transfer differ from the first.

Invoke a dependency with:

1. Retained secondary word shifted left by 12.
2. Retained scaled word.
3. Retained scaled word again.
4. The unscaled returned word shifted left by 18.

### 10. Capture and duplicate a full word

Perform a no-argument call and pass its result to another dependency. Perform another no-argument call and forward its result to another dependency.

Perform three no-argument calls and obtain an index from a fourth. Scale it by four.

Read a word at that scaled address plus 116, retaining it as the **copied word**. Write its low byte at the scaled address plus 1.

Invoke a dependency with the scaled address. Perform three no-argument calls and obtain another index from a fourth.

Store the entire copied word at \(16 \times \text{index}+20\). This destination uses a sixteen-byte stride, unlike the ordinary word slots.

### 11. Further word propagation

Invoke a dependency with:

\[
(\text{retained scaled word} \gg 2) \ll 16.
\]

Perform a no-argument call and forward its result to another dependency. Repeat that result-forwarding pair once.

Perform three no-argument calls and obtain an index from a fourth. Store the copied word in its word slot. Invoke a dependency with four times the index.

Perform three no-argument calls and obtain another index from a fourth. Scale it by four and store the scaled value at:

\[
(\text{retained scaled word} \mathbin{\&} \texttt{0xfffffffc})+20.
\]

Invoke a dependency with the newly scaled value twice.

Under wrapping 32-bit arithmetic, the retained scaled word already has its bottom two bits clear. This does not justify removing the mask under an unestablished alternative arithmetic model.

### 12. Zero store and paired-result linkage

Perform a no-argument call and forward its result to another dependency. Repeat that pair once.

Perform three no-argument calls and obtain an index from a fourth. Store zero in its word slot and invoke a dependency with four times that index.

Perform three no-argument calls, then obtain a pair from another call.

Scale the low word by four. Store it in the word slot selected by the high word.

Read global A again, retaining this distinct sample as the **later global base**.

Invoke a dependency with the scaled low word, the high word, and the scaled low word twice more.

### 13. Linkage duplication and later field capture

Perform four no-argument calls, taking an index from the fourth. Store the previously scaled low word in its word slot.

Read a word at later global base plus 20 and retain it as the **later field**.

Invoke a dependency with four times the returned index. Perform three no-argument calls and obtain a pair from a fourth. Retain both halves.

### 14. Two byte-selected writes

Read a byte at:

\[
(\text{copied word} \gg 23)+1.
\]

Write the low byte of the later field at the selected byte’s zero-extended value plus 17.

Invoke a dependency with the latest pair’s high word repeated three times and its low word shifted left by two.

Perform a no-argument call and forward its result to another dependency. Perform three no-argument calls and obtain a word result from a fourth.

Read a byte at:

\[
((\text{latest pair low word} \mathbin{\&} \texttt{0x3fffffff}) \gg 21)+1.
\]

Write the low byte of the later field shifted right by 22 at the selected byte’s zero-extended value plus 17.

Invoke a dependency with the returned word shifted left by two.

### 15. Terminal updates and call

Perform three no-argument calls and obtain a word result from a fourth. Invoke a dependency with that word shifted left by two twice.

Perform one no-argument call, obtain a word from another, forward it to another dependency, and obtain a byte result from the next call.

Then, in order:

1. Store zero through a secondary pointer output associated with the last call.
2. Update global B by concatenating the three-byte global contribution as its upper 24 bits and the returned byte as its lower eight bits.
3. Store a zero halfword at:

   \[
   (\text{latest pair low word} \mathbin{\&} \texttt{0x3fffffff}) \gg 7.
   \]

4. Call address zero with three zero arguments.

A return appears after that call. Normal completion therefore requires the call to address zero to return. The evidence does not establish whether address zero is callable, traps, or transfers control elsewhere.

## Side effects

Direct effects include word stores, byte stores, one halfword clear, two writes to global B, and repeated reads of global A and absolute address 1.

Direct byte-selected destinations range from address 17 through 272. Their selectors may come from a wider source address range. The final halfword destination ranges from 0 through 8,388,607 and need not be aligned.

The storage regions may overlap. Consequently:

- A store can affect a later selector, word read, or global sample.
- Dependencies can modify memory before later explicit reads.
- Global B’s final upper bytes must not be assumed equal to those from its earlier publication.
- No store sequence is established as atomic or transactional.

No direct allocation or release is visible. Ownership transfer, retention, and lifetime effects of dependencies are unknown. The secondary pointer used for the terminal byte clear must designate writable memory for that clear to complete.

No explicit status result, exception handling, validation, synchronization, or recovery is visible. Earlier effects remain observable if execution stops later, subject to the underlying memory and fault model.

## Acceptance examples

These examples are conditional static obligations, not executed tests.

1. **Unused explicit argument.** Changing only the first explicit argument changes no displayed direct operation. This does not prove whole-function equivalence if dependencies observe the incoming argument register.

2. **Entry extraction.** If the captured entry field is `0xffc00000`, the entry fragment is 1023. Both subsequent stores of that fragment write a full word containing 1023.

3. **Double-shift boundary.** If the first global sample is `0xffffffff`, its first fragment is 511 and its second right shift by 23 is zero. The stage-4 selector read therefore still uses absolute address 1.

4. **Selector versus pointer.** If a selector read yields 200, the destination is address 217. It is not an address loaded from a pointer-sized table entry.

5. **Low-byte truncation.** If an indexed fragment is 1023, the associated byte store writes 255. If the copied word is `0x123456ab`, its byte-copy destination receives `0xab`, while its later word destinations receive the entire captured word.

6. **Independent reads.** If dependencies change the byte at address 1 between stages 6 and 7, those stages may clear different destinations.

7. **Repeated source copy.** If a dependency changes the word at copy base plus 116 between the two stage-9 transfers, the second byte write must use the later word.

8. **Pair ordering.** For a pair whose low word is 3 and high word is 7, the stage-12 linkage store writes 12 to address 48, assuming ordinary nonoverflowing address arithmetic.

9. **Terminal ordering.** If the terminal secondary pointer is writable but the halfword destination faults, the pointer clear and preceding global B update have already been attempted; the zero-address call has not yet been reached.

10. **No guaranteed return.** If address zero is nonexecutable in the execution environment, reaching the final call does not produce a normal function return.
