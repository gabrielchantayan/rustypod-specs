# F-6a5a65185132

## Purpose

F-6a5a65185132 interprets a descriptor, obtains a dependency-provided object, validates a range and a variable-width numeric field, and conditionally requests an operation on a second object.

The supplied static representation establishes two ordinary return values:

- **4** for an immediately rejected descriptor selector or certain invalid numeric and range conditions.
- **0** when the numeric field passes validation but the computed range end is not greater than its start.

Other paths reach dependencies marked as non-returning. Consequently, successful dispatch is **not** established as an ordinary return of zero.

The apparent intent is to apply a nonzero value to an object associated with a bounded range. The meaning of that value, the object types, and the meaning of operation identifier **0x41** remain unknown.

## Interface

### Inputs

The function takes two machine-width arguments, each represented as 32 bits:

1. **Context value:** An opaque 32-bit value. It is saved and, on the dispatch path, forwarded unchanged to F-99e0d644698f.
2. **Descriptor address:** A 32-bit address used to access the descriptor below.

The descriptor has these established accessed fields:

| Descriptor offset | Width | Interpretation |
|---|---:|---|
| +8 | 32 bits | Address of a payload |
| +12 | 16 bits, unsigned | Selector controlling rejection and payload decoding |

The function reads the selector first and the payload address second. Both reads occur before the immediate selector-rejection branch. Thus, even a descriptor that is immediately rejected must permit both reads. The payload itself need not be accessible on that immediate-rejection path.

No descriptor length, payload length, or pointer-validity argument is supplied. Valid storage and callable object layouts are preconditions rather than locally enforced properties.

### Payload layout

For selectors that reach numeric validation, the following payload locations matter:

| Payload offset | Width | Interpretation |
|---|---:|---|
| +0 | Dependency-defined | Input location for decoding the range start |
| +4 | Dependency-defined | Input location for decoding the range length |
| +8 onward | One to four bytes on reachable validation paths | Little-endian numeric field |

The number of bytes consumed by either decoding dependency is unknown. The four-byte spacing between their input locations does not establish their read widths.

For selectors 9 through 12, the numeric field occupies respectively one through four bytes beginning at payload offset +8.

### Outputs

The ordinary return is a 32-bit status:

- **4:** Rejection as specified below.
- **0:** A qualifying non-increasing computed range end, after the release-style dependency has been called.

There is no explicit caller-provided output buffer and no direct store into the descriptor or payload in the supplied representation.

### Arithmetic model

The contract uses the representation’s 32-bit integer model:

- The selector is read as an unsigned 16-bit value.
- Range start and object extent are treated as unsigned 32-bit values.
- The decoded length is held as a signed 32-bit value, with **−1** recognized specially.
- Range-end addition is unsigned 32-bit arithmetic, reduced modulo \(2^{32}\).

The distinction between signed selector arithmetic and unsigned range arithmetic is material.

## Behavior

### 1. Initial reads and selector gate

The function reads the unsigned 16-bit selector at descriptor offset +12, followed by the 32-bit payload address at offset +8. It then evaluates whether the selector minus nine is greater than three.

Under the ordinary integer promotions represented by the supplied source, the subtraction and comparison are signed 32-bit operations. Therefore:

- Selectors **13 through 65535** return **4** immediately.
- Selectors **0 through 12** proceed to dependency acquisition.

In particular, this is not equivalent to an unsigned “selector must be between 9 and 12” check. Selectors below nine pass the initial gate, although they do not reach numeric validation.

### 2. Primary object acquisition

For a selector that passes the initial gate, the function saves both input arguments and calls **F-be45cd43f92d** with the argument zero.

If that dependency returns a null pointer, execution reaches **F-a817d8d58c10**, which is marked non-returning.

If it returns a non-null pointer, the function retains that pointer in a local slot. The following accesses require the returned object to contain a valid dispatch-table pointer and callable entries at the offsets described below.

### 3. Range decoding and extent query

With a non-null primary object, calls occur in this order:

1. **F-c25a2fcc75b5** receives the payload address and an explicit zero argument. Its result is interpreted as the unsigned 32-bit range start.
2. **F-c25a2fcc75b5** is called using payload address +4. This call site shows only that address argument. Its result is interpreted as a signed 32-bit range length.
3. The primary object’s indirect entry at dispatch-table offset **0x108** is called. Its result is used as an unsigned 32-bit extent.

The differing visible argument counts at the two calls to F-c25a2fcc75b5 are not resolved by the supplied material. No missing argument value is assumed for the second call.

If the decoded length equals **−1**, it is replaced as follows:

- When the range start is strictly below the extent, the replacement is the 32-bit difference between extent and start.
- Otherwise, the replacement is zero.

All other decoded length values remain unchanged. In particular, other negative signed values are not rejected merely for being negative.

The extent query occurs even for selectors 0 through 8, which subsequently take the default path.

### 4. Selector-specific numeric decoding

After acquisition, both range decodes, the extent query, and any sentinel replacement:

- Selectors **0 through 8** reach F-a817d8d58c10 without consuming numeric-field bytes.
- Selectors **9 through 12** assemble the numeric field.
- Selectors above 12 have already returned.

For selectors 9 through 12, the assembly is little-endian, but individual byte reads occur from the highest included offset down to the lowest:

| Selector | Byte-read order | Assembled value |
|---:|---|---|
| 9 | +8 | One-byte unsigned value |
| 10 | +9, +8 | Two-byte unsigned value |
| 11 | +10, +9, +8 | Three-byte unsigned value |
| 12 | +11, +10, +9, +8 | Four-byte unsigned value |

The representation also contains branches for selectors 13 through 16 that would assemble an additional upper word. Those branches are unreachable through the established initial gate. On every reachable numeric-validation path, the upper word remains zero.

For selector 12, bits 28 through 31 of the assembled lower word must be zero. Equivalently, the byte at payload offset +11 must be below **0x10**. For selectors 9 through 11, those bits are necessarily zero.

The read order matters if the payload is mutable or externally observable. No locking, snapshot mechanism, or atomic multi-byte read is established.

### 5. Validation and return-status selection

The following conditions are evaluated in order, with short-circuit behavior:

1. Reject an assembled value whose lower and upper words are both zero.
2. Reject a lower word with any of bits 28 through 31 set.
3. Reject if the unsigned extent is less than the unsigned 32-bit range end.
4. Otherwise, select status zero and check whether that range end is less than or equal to the range start.

The range end is:

\[
\text{end} = \bigl(\text{start} + \text{length bit pattern}\bigr) \bmod 2^{32}.
\]

If any of the first three conditions rejects the input, the selected status remains **4**. If the fourth condition holds, the selected status is **0**.

For either kind of returning validation outcome, the function calls **F-54033250428c**, passing the address of its local primary-object pointer slot. It then returns the selected status, provided that dependency returns normally.

This produces several important boundaries:

- Zero length ordinarily returns zero only after the numeric-field and extent checks pass.
- A start beyond the extent does not automatically return zero, even when the −1 sentinel becomes zero: the extent comparison may reject first.
- An addition that wraps can return zero if its wrapped end passes the extent comparison.
- A negative length other than −1 participates through its unsigned 32-bit bit pattern.

There is no separate overflow rejection and no independent signed-negative-length rejection.

### 6. Secondary object lookup and conditional dispatch

If validation passes and the computed end is strictly greater than the start, the function calls the primary object’s indirect entry at dispatch-table offset **0x134**.

This call explicitly receives:

- The primary-object pointer.
- The decoded range start.

If the returned secondary-object pointer is null, execution reaches F-a817d8d58c10. The supplied representation does not show a preceding call to F-54033250428c on this path.

If the secondary pointer is non-null:

1. Its indirect entry at dispatch-table offset **+8** is called.
2. If that call returns nonzero, **F-99e0d644698f** is called with these arguments, in order:
   - Saved context value.
   - Secondary-object pointer.
   - Operation identifier **0x41**.
   - Range start.
   - Assembled lower numeric word.
   - Assembled upper numeric word, which is zero on reachable paths.
3. Whether the indirect result was zero or nonzero, **F-feee9156a257** is then called with the secondary-object pointer.

F-feee9156a257 is marked non-returning. The result of F-99e0d644698f is not inspected. The decoded range length is not passed directly to it.

- Calls to dependencies and indirect object entries.

It shows no direct writes to caller-owned descriptor or payload storage.

### Dependency-mediated effects

### Ownership and lifetime

The primary object comes from F-be45cd43f92d; the secondary object comes from an indirect lookup. Their ownership modes are unknown.

Only the returning validation paths visibly call F-54033250428c. Other paths must not be described as releasing the primary object unless dependency behavior supplies that fact.

Likewise, the final call to F-feee9156a257 does not, by itself, establish destruction, ownership transfer, exception propagation, or reference release.

## Acceptance examples

These are conditional static expectations, not observed executions. Unless stated otherwise, pointers and dispatch entries are valid, dependencies return normally where applicable, and the specified decoded values are supplied.

1. **Immediate selector rejection**

   Selector **13** produces return value **4** after the selector and payload-address reads. No acquisition or payload-decoding dependency is called.

2. **Below-range selector is not immediately rejected**

   Selector **8**, with successful primary acquisition, performs both range decodes and the extent query before reaching F-a817d8d58c10. It does not return four merely because eight is below nine.

3. **Zero numeric field**

   Selector **9** with payload byte +8 equal to zero calls F-54033250428c and returns **4**. No secondary lookup occurs.

4. **Reserved high bits**

   Selector **12** with payload bytes +8 through +11 equal to **01, 00, 00, 10** assembles **0x10000001**. It calls F-54033250428c and returns **4**, irrespective of whether the range would otherwise pass.

5. **Zero range length**

   Selector **9**, numeric value **1**, start **20**, length **0**, and extent **100** produce end **20**. The function calls F-54033250428c and returns **0**.

6. **Extent failure precedes non-increasing-end handling**

   With numeric value **1**, start **101**, sentinel length **−1**, and extent **100**, the sentinel becomes zero. End **101** exceeds the extent, so the result is **4**, not zero.

7. **Sentinel spans the remaining extent**

   With numeric value **1**, start **20**, length **−1**, and extent **100**, the replacement length is **80** and end is **100**. The function performs secondary lookup at start **20**.

   If the secondary pointer is non-null and its predicate is nonzero, F-99e0d644698f receives the saved context, secondary pointer, **0x41**, **20**, **1**, and **0**, followed by F-feee9156a257.

8. **Wrapped addition**

   With numeric value **1**, start **0xFFFFFFF0**, length **0x30**, and extent **100**, the 32-bit end is **0x20**. The extent comparison passes, but end is not greater than start. F-54033250428c is called and the function returns **0**.

9. **Negative non-sentinel length**

   With numeric value **1**, start **10**, decoded length **−2**, and extent **100**, unsigned addition yields end **8**. The function calls F-54033250428c and returns **0**.

10. **False secondary predicate**

    For a valid increasing range and non-null secondary object, a zero predicate suppresses F-99e0d644698f. F-feee9156a257 is still called.
