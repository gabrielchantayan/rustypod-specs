# F-c301374bd42e

## Purpose

F-c301374bd42e performs a fixed sequence of indirect calls interleaved with three 32-bit memory stores, two byte reads, and two byte stores. Several call results determine later addresses, stored values, and call arguments.

The available static representation does not establish a higher-level purpose, such as object initialization, serialization, or device configuration. It also does not establish a normal return: the represented sequence ends at an instruction-decoding failure.

This contract describes the visible sequence, subject to the limitations of that representation. It does not treat the apparent terminal failure as an intentional application-level operation.

## Behavior

### Dependency naming and ordering

F-indirect-01 through F-indirect-34 are opaque identifiers assigned here to successive indirect-call sites. They do not assert that the targets are distinct functions or identify their implementations.

The sequence below applies only while each preceding call returns and each preceding memory access completes. No visible branch checks results or handles a failed access.

A call described as having “no explicit arguments” has no argument expressions shown in the static representation. That does not prove that its implementation ignores incoming registers, stack contents, or other ambient state.

### Phase 1: obtain A and perform the first store

1. Invoke F-indirect-01 with **Input**.
2. Invoke F-indirect-02, F-indirect-03, and F-indirect-04, in that order, with no explicit arguments.
3. Invoke F-indirect-05 with no explicit arguments and retain its result as **A**.
4. Compute **word(4 × A)**.
5. Store **Ambient** as a 32-bit value at address **word(4 × A + 0x14)**.
6. Invoke F-indirect-06 with **word(4 × A)**.

The stored payload is not the explicit function input and is not a visible result of F-indirect-05. The destination is calculated directly from A; no separately established allocation base is visible.

### Phase 2: obtain B and perform the second store

1. Invoke F-indirect-07, F-indirect-08, and F-indirect-09, in that order, with no explicit arguments.
2. Invoke F-indirect-10 with no explicit arguments and retain its result as **B**.
3. Store **word(4 × B)** as a 32-bit value at address **word(16 × B + 0x14)**.
4. Invoke F-indirect-11 with these three explicit arguments, in order:
   - **(word(4 × A) AND 0x3F) shifted left by 14**;
   - **word(4 × B)**;
   - **word(A shifted left by 30)**.

The destination in this phase scales B by 16, whereas the stored value scales B by 4. Those different scales are observable and must not be normalized to match.

The first argument to F-indirect-11 occupies only bits 16 through 19. The low six bits of word(4 × A) are multiples of four, so its possible values range from zero through 0xF0000 in increments of 0x10000. The third argument depends only on the low two bits of A.

### Phase 3: obtain C and perform the third store

1. Invoke F-indirect-12, F-indirect-13, and F-indirect-14, in that order, with no explicit arguments.
2. Invoke F-indirect-15 with no explicit arguments and retain its result as **C**.
3. Store **word(4 × B)** as a 32-bit value at address **word(4 × C + 0x14)**.
4. Invoke F-indirect-16 with **word(4 × C)**.

The payload is derived from the earlier result B, not from C. This is a direct store; no visible copy length, ownership transfer, or object construction accompanies it.

### Phase 4: obtain D and perform the first byte update

1. Invoke F-indirect-17, F-indirect-18, and F-indirect-19, in that order, with no explicit arguments.
2. Invoke F-indirect-20 with no explicit arguments and retain its result as **D**.
3. Read one unsigned byte from address **word(A × 0x10000000 + 1)**. Call this byte **P**.
4. Store **byte(4 × D)** at address **P + 0x11**.
5. Invoke F-indirect-21 with these three explicit arguments:
   - **word(D shifted left by 2)**;
   - **word(D shifted left by 2)**;
   - **word(D shifted left by 4)**.

The byte read is zero-extended before address formation. Consequently, the byte-store destination lies between 0x11 and 0x110 inclusive. The operation does not read a full-width pointer from memory.

The source-read address depends only on A’s low four bits and belongs to the set **0x00000001, 0x10000001, …, 0xF0000001**, under the stated 32-bit model.

### Phase 5: forward E, obtain G, and perform the second byte update

1. Invoke F-indirect-22 with no explicit arguments and retain its 32-bit result as **E**.
2. Invoke F-indirect-23 with **E** unchanged.
3. Invoke F-indirect-24, F-indirect-25, and F-indirect-26, in that order, with no explicit arguments.
4. Invoke F-indirect-27 with no explicit arguments and retain its result as **G**.
5. Read one unsigned byte again from **word(A × 0x10000000 + 1)**. Call this independently read byte **Q**.
6. Store **byte((D AND 0x3FFFFFFF) shifted right by 20)** at address **Q + 0x11**.
7. Invoke F-indirect-28 with **word(G shifted left by 2)**.

The second read must not be replaced with P. Intervening callees may have changed the source byte, and no preservation guarantee is available.

Although the masked right shift can produce a value as large as 1023, the byte store retains only eight bits. Its stored payload is therefore bits 20 through 27 of D. Bits 28 and 29 do not survive the byte conversion; bits 30 and 31 are removed by the mask.

If P equals Q, the second byte store targets the same address as the first. If they differ, the two stores target different addresses.

### Phase 6: obtain H and reach the visible boundary

1. Invoke F-indirect-29, F-indirect-30, and F-indirect-31, in that order, with no explicit arguments.
2. Invoke F-indirect-32 with no explicit arguments and retain its result as **H**.
3. Invoke F-indirect-33 with:
   - **word(H shifted left by 2)**;
   - **Q**, zero-extended from its unsigned byte value.
4. Invoke F-indirect-34 with no explicit arguments.
5. Reach the end of the recoverable sequence, marked by an instruction-decoding failure.

No further behavior is established.

## Acceptance examples

These are conditional static examples, not executed tests. They assume valid memory mappings, returning callees, the stated arithmetic model, and no unspecified interference with the observations being described.

### Different address and payload scales

If A is 3, B is 5, C is 7, and Ambient is 0x11223344:

- The first word store writes 0x11223344 at address 0x20.
- F-indirect-06 receives 12.
- The second word store writes 20 at address 0x64.
- F-indirect-11 receives 0x30000, 20, and 0xC0000000.
- The third word store writes 20 at address 0x30.
- F-indirect-16 receives 28.

An implementation that writes the second value at 4 × B + 0x14 does not match this contract.

### Independent byte reads

If A is 3, both byte reads use address 0x30000001. If the first read returns 0x20 and the second returns 0x40:

- The first byte-store destination is 0x31.
- The second byte-store destination is 0x51.
- F-indirect-33 receives 0x40 as its second argument.

Reusing the first byte for the later operations would not match the visible sequence.

### Byte truncation and overwrite

If D is 0x3AB00003 and both byte reads return 0x20:

- The first byte store writes 0x0C at address 0x31.
- The second byte store writes 0xAB at that same address.
- Absent intervening or subsequent modifications, the second write replaces the first byte value.

The intermediate shifted value for the second store is 0x3AB; the stored byte is not a wider write.

### Address wraparound

If A is 0x40000000, word(4 × A) is zero:

- The first word-store address is 0x14.
- F-indirect-06 receives zero.
- The byte-read source address is 0x00000001.

This example requires valid mappings at those addresses; it does not assert that such mappings exist.

### Interrupted progression

If F-indirect-10 does not return, the first word store has already occurred, but the second word store and every later direct operation are not reached. No visible recovery path compensates for the first store.
