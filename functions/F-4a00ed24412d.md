# F-4a00ed24412d

## Purpose

F-4a00ed24412d coordinates one preparation dependency and one of two subsequent dependencies. It supplies the preparation dependency with two mutable 32-bit working values, then uses the low eight bits of those values to form arguments for the selected branch.

A 32-bit selector controls both the branch and the 64-bit result:

- A nonzero selector selects F-abb25c32b119 and returns a concatenation of the selector’s bit pattern and the first input word.
- A zero selector selects F-7392db945a55 and returns the low eight bits of the second prepared working value, zero-extended to 64 bits.

The broader purpose of these operations is unknown. The evidence does not establish that the values represent coordinates, colors, characters, handles, or any other application-level concept.

## Behavior

### Preparation common to both branches

The function initializes the first working word from the first seed and the second working word from the second seed.

It then invokes F-5db6534774fc with five ordered arguments:

1. Address of the first working word.
2. Address of the second working word.
3. The original first seed.
4. The original second seed.
5. The payload word.

Thus, this dependency receives both mutable working storage and separate copies of the original seeds. Even if it changes either working word, the seed arguments supplied to that invocation are the original input values.

The return value of F-5db6534774fc, if any, is not used by the surrounding function. Its writes through the two supplied addresses can affect subsequent arguments and, on the zero-selector branch, the returned value.

The selector does not bypass preparation. Both selector cases invoke F-5db6534774fc before invoking a branch-specific dependency.

### Nonzero selector

After preparation returns normally, a nonzero selector causes an invocation of F-abb25c32b119 with four ordered arguments:

1. The low eight bits of the first working word.
2. The low eight bits of the second working word.
3. Zero.
4. A value obtained through the external data reference used by this branch.

Each masked working value has a numerical range of 0 through 255. Bits 8 through 31 of either working word do not contribute to these two arguments.

The external data access belongs to preparation of this branch-specific invocation, after F-5db6534774fc has returned. Consequently, its value must not be assumed to equal a value that existed before the preparation call. The preparation dependency may have affected external state.

The exact relative evaluation order of the working-word reads and the external data read is not established. The ordered argument positions do not imply an ordered sequence of those reads.

If F-abb25c32b119 returns normally, its return value is ignored. F-4a00ed24412d returns a 64-bit value with:

- Bits 63 through 32 equal to the selector’s original 32-bit bit pattern.
- Bits 31 through 0 equal to the payload word.

Equivalently, if the selector’s bit pattern is interpreted as an unsigned integer \(S\), and the payload word as an unsigned integer \(P\), the result is \(S \times 2^{32} + P\). This expression fits in 64 unsigned bits for every permitted input.

Neither prepared low byte contributes to this result. They still contribute to the observable dependency invocation.

### Zero selector

After preparation returns normally, a zero selector follows a different sequence.

First, the function captures the low eight bits of the second working word in an unsigned 32-bit temporary. The captured value is therefore between 0 and 255.

It then invokes F-7392db945a55 with four ordered arguments:

1. The low eight bits of the first working word.
2. Zero.
3. Zero.
4. Zero.

The second prepared low byte is not supplied to this dependency. It has already been captured for the return value.

If F-7392db945a55 returns normally, its return value is ignored. The function returns the captured value, zero-extended to 64 bits. Bits 63 through 8 of the result are zero.

The capture precedes the branch-specific call. The result is therefore not a fresh read of the second working word after that call, nor is it derived from that dependency’s return value.
