# F-5ee44019e55b

## Purpose

F-5ee44019e55b attempts to establish a descriptor-like resource from a supplied name or locator, a 32-bit option word, and an auxiliary argument. It returns a nonnegative descriptor value on success and −1 on failure.

The visible behavior includes resolving a locator, acquiring a parent-like object, looking up or conditionally creating a target, applying access checks, optionally performing a truncate-like transition, updating target and descriptor metadata, and invoking finalization and status-reporting dependencies.

“Descriptor,” “parent,” “creation,” and “truncation” describe inferred roles. The established contract is the branch logic, dependency calls, memory accesses, and return behavior below. No particular operating-system API or filesystem semantics are established.

## Interface

### Inputs

The function receives four 32-bit arguments:

| Position | Interpretation supported by the supplied representation |
|---|---|
| First | Opaque locator argument. Passed to F-91c65c9d4f51 and F-658f097ae4e8. Its representation, encoding, and validity requirements are unknown. |
| Second | Unsigned 32-bit option word. Individual masks and the low two bits control behavior. |
| Third | Copied into local storage but otherwise unused by visible operations. |
| Fourth | Opaque auxiliary value passed to F-d05b3803629b during target lookup. It is not directly passed to the alternative target-creation dependency. |

The low two option bits define two classes:

- **Zero-low-bits mode:** both bits are clear.
- **Nonzero-low-bits mode:** at least one is set.

The function does not distinguish the three nonzero combinations.

Other observed masks are:

| Mask | Effect |
|---|---|
| `0x004` | Sets bit `0x4` in target state during successful finalization. |
| `0x100` | Allows an alternative target-creation attempt after a null lookup, but only in nonzero-low-bits mode. |
| `0x200` | Requests the truncate-like transition for an existing, validated target. |
| `0x400` | Together with `0x100`, rejects an existing, otherwise valid target. |
| `0x800` | Sets target-state bit `0x2`, but only in nonzero-low-bits mode. |

The full low 16 bits of the option word are eventually stored in the descriptor record. No visible rejection of unknown bits occurs.

### Output and status

A successful call returns the nonnegative value obtained from F-c63d695765b6. Before returning, it calls F-038b46411c0c with zero.

Most failures return −1 after calling F-038b46411c0c with one of these values:

- `0x18`: descriptor allocation returned a negative value.
- `0x02`: resolution, parent qualification, or ordinary lookup failed along specified paths.
- `0x1c`: the alternative creation attempt returned null.
- `0x11`: an existing validated target was encountered with both `0x100` and `0x400` set.
- `0x0d`: target rejection, disallowed creation mode, access rejection, or failure of the truncate-like transition.

These are numeric status arguments, not established named error constants.

There is one exception: if the initial F-91c65c9d4f51 result is negative, the function immediately returns −1 without a visible call to F-038b46411c0c.

## Behavior

### 1. Initial acquisition

The function first calls F-91c65c9d4f51 with the first argument. A negative result causes the immediate failure described above.

It then calls F-c63d695765b6. A negative result causes status `0x18` and return −1. No visible matching release call is made for the earlier nonnegative acquisition result on this path.

For a nonnegative descriptor value, the function:

1. Obtains its record using F-667717e3fb3e with that descriptor and zero.
2. Writes zero to the record’s target-reference field.
3. Calls F-6443787f9616 with the initial acquisition result.

The two dependencies that receive the initial acquisition result resemble an enter/leave pair, but their actual synchronization or ownership semantics are unknown.

### 2. Resolution and parent qualification

The function supplies three local storage regions to F-658f097ae4e8, together with the first argument. The regions have visible capacities of 260, 256, and 4 bytes. They are not visibly initialized beforehand.

A zero result fails with status `0x02`.

After a nonzero result, the function calls F-1cb585febd84 on the 256-byte region, then passes that same region and the returned value to F-ddcbbbbc4a8e. A zero result from the latter fails with status `0x02`.

It next calls F-8dfcd5b8f35c on the 260-byte region. A zero result fails with status `0x02`. A nonzero result becomes the retained parent-like reference.

That reference must satisfy both of the following, evaluated in order:

1. F-e135feff4093 returns nonzero.
2. F-3dacd4ff9d73 returns zero.

A failed condition produces status `0x02`. The second dependency is not called if the first returns zero.

### 3. Target lookup and conditional creation

For a qualified parent, the function calls F-d05b3803629b with six arguments, in this order:

1. Zero.
2. The parent-like reference.
3. The 256-byte resolution region.
4. The 4-byte resolution region.
5. Zero.
6. The fourth caller argument.

A null target has three outcomes:

- If option `0x100` is clear, failure status is `0x02`.
- If `0x100` is set but the low two option bits are both clear, failure status is `0x0d`.
- If `0x100` is set and at least one low option bit is set, F-53f6a8475775 is called with the parent and the latter two resolution regions.

A null result from F-53f6a8475775 produces status `0x1c`.

A nonnull result is written into the descriptor record, then proceeds directly to successful finalization. This path does **not** visibly run the existing-target predicates, the combined `0x100`/`0x400` rejection, the access-byte check, or the `0x200` transition.

### 4. Existing-target validation

A nonnull ordinary lookup result is first written into the descriptor record. It then must satisfy these ordered conditions:

1. F-e135feff4093 on the target returns zero.
2. F-3dacd4ff9d73 on the target returns zero.

The second call is skipped if the first fails its condition. Either rejection produces status `0x0d`.

If both `0x100` and `0x400` are set, the function fails with status `0x11`. This check precedes the access-byte check and any `0x200` transition.

In nonzero-low-bits mode, the function reads the byte at secondary-record offset `+0x0b`. If bit zero is set, it fails with status `0x0d`.

In zero-low-bits mode, this access-byte read is skipped and does not itself prevent success.

### 5. Optional truncate-like transition

For an existing target that passed the preceding checks, option `0x200` selects a state-changing sequence. Without that option, execution proceeds directly to finalization.

The sequence is:

1. Call F-40e4fc419124 with the target’s first and second components; retain its 32-bit result.
2. Read and retain the secondary record’s 32-bit field at `+0x1c`.
3. Call F-27e49f66c358 with the target’s first component, its secondary-record reference, and zero.
4. Write zero to secondary-record offset `+0x1c`.
5. Call F-cb9b1812bac7 with the target reference, one, and one.

If the final call returns nonzero:

1. Call F-01a422616ce4 with the target’s current first component and the retained result from F-40e4fc419124.
2. Read the 16-bit field at offset `+0x78` from the target’s current first component.
3. Pass that field to F-052651f0e13e.
4. Continue to finalization.

If F-cb9b1812bac7 returns zero:

1. Call F-27e49f66c358 again, using the target’s current components and the retained result from F-40e4fc419124.
2. Restore the saved 32-bit value to offset `+0x1c` of the target’s then-current secondary record.
3. Fail with status `0x0d`.

This is a visible partial restoration sequence, not proof of transactional rollback. Dependencies may have additional effects, and target components are reread after intervening calls.

### 6. Successful finalization

All successful paths converge on this ordered sequence:

1. Read the target’s secondary-record reference.
2. If its 32-bit field at `+0x24` equals one, write zero to its state word at `+0x28`.
3. In nonzero-low-bits mode, read the current secondary-record reference and state word, set bit `0x1`, and write the result.
4. In that same mode, if `0x800` is set, write the preceding computed state value with bit `0x2` also set.
5. If `0x004` is set, read the current state word and write it with bit `0x4` set.
6. Store the option word’s low 16 bits at descriptor-record offset `+4`.
7. Write zero at descriptor-record offset `+8`.
8. Call F-56c9e29af49d with the target’s first component and the second component reached through the descriptor record’s target reference.
9. Store its 32-bit result at descriptor-record offset `+32`.
10. Call F-e657f684a3c8 with the descriptor record.
11. Call F-66819ba2201a with the retained parent reference.
12. Call F-591e5dd605b9 with the initial acquisition result.
13. Call F-038b46411c0c with zero.
14. Return the allocated descriptor value.

There is no visible validation of the F-56c9e29af49d result before storage and success.

### 7. Common failure cleanup

Failures after successful descriptor allocation use this order:

1. Call F-b3f16c6113a2 with the allocated descriptor value.
2. If the retained parent reference is nonzero, call F-66819ba2201a with it.
3. Call F-591e5dd605b9 with the initial acquisition result.
4. Call F-038b46411c0c with the selected status.
5. Return −1.

No separate target-release call is visible. Whether descriptor cleanup releases a stored target is unknown.

## Side effects

Established direct writes affect the descriptor record and, after sufficient target validation or successful creation, the target’s secondary record.

Failure does not establish absence of mutation. In particular:

- The descriptor target field is cleared before resolution.
- An existing or newly created target can be stored before a later failure.
- The truncate-like path invokes mutating dependencies and temporarily clears a field.
- Failure cleanup may itself mutate or release state.

Ownership transfer is not established by storing a target reference or invoking cleanup. The parent-like reference is passed to F-66819ba2201a on both ordinary success and common failure, but that dependency’s release semantics are not supplied.

No global-preservation guarantee is available for any dependency. The function’s explicit final status call occurs after the other finalization or cleanup calls.

Arithmetic is limited to fixed offsets, bitwise operations, comparisons, and narrowing the option word to 16 bits. The combined-option test uses the 32-bit complement masked by `0x500`; it is true exactly when both corresponding input bits are set. Signed comparisons determine whether initial acquisition and descriptor allocation failed.

## Acceptance examples

These examples are conditional on valid records, normally returning dependencies, and the stated dependency outcomes. They are not runtime test results.

1. **Initial acquisition failure.** If F-91c65c9d4f51 returns a negative value, the result is −1. Descriptor allocation and the explicit status dependency are not called.

2. **Descriptor allocation failure.** If initial acquisition succeeds but F-c63d695765b6 returns negative, the function reports `0x18` and returns −1. Neither F-6443787f9616 nor F-591e5dd605b9 is visibly called.

3. **Lookup miss without creation permission.** With successful resolution and parent checks, null lookup and clear `0x100` cause common cleanup and status `0x02`.

4. **Creation prohibited by mode.** With null lookup, set `0x100`, and zero low two bits, F-53f6a8475775 is not called. Status is `0x0d`.

5. **Creation bypasses existing-target checks.** With null lookup and options `0x701`, a nonnull alternative acquisition proceeds to finalization. Although `0x100`, `0x200`, and `0x400` are set, neither the existing-target combined-bit rejection nor the truncate-like sequence is executed.

6. **Existing-target exclusion takes precedence.** For a target passing both predicates, options `0x501` produce status `0x11` before reading the access byte, regardless of that byte’s value.

7. **Mode-dependent access rejection.** For an otherwise acceptable existing target whose access byte has bit zero set, options `0x001` produce status `0x0d`. Options zero skip that byte check.

8. **State reset and option application.** If finalization starts with the secondary discriminator equal to one, its prior state word is discarded. Options `0x805` then yield state bits `0x7`, provided the referenced record remains stable.

9. **Preservation without reset.** If the discriminator is not one, state is initially `0x80`, and options are `0x004`, finalization writes `0x84`; it does not set bits `0x1` or `0x2`.

10. **Transition failure.** For an eligible existing target with `0x200` set, a zero F-cb9b1812bac7 result causes the restoration calls and saved-field write, followed by status `0x0d`, not successful descriptor finalization.
