# F-e5a2146f67c3

## Purpose

F-e5a2146f67c3 conditionally advances a caller-maintained byte position and delivers one byte through an output location.

Two scalar inputs act as an equality gate. When they differ, the function returns status 1 without accessing the position, byte storage, or output through the supplied addresses. When they match, the function examines bytes at the current position, advances past bytes satisfying a marker comparison, advances once beyond the first byte that fails that comparison, and writes a byte to the output. A normally completed gated operation returns status 0.

The marker comparison is expressed as a plain-character value compared with −128. Under signed 8-bit character interpretation, this recognizes byte value 0x80. Whether that interpretation holds for the original target is not independently established.

The apparent intent is to skip marker bytes and consume the following byte. That intent is narrower than the observable behavior when the position storage, byte storage, and output overlap.

## Interface

The function has six inputs, described here by role rather than source identifiers.

| Input | Role |
|---|---|
| First scalar | Unused four-byte input. It does not influence any operation shown. |
| Gate-left | Integer scalar compared with gate-right. |
| Gate-right | Integer scalar compared with gate-left. |
| Byte-storage base | Integer-valued base used to form addresses by adding positions. |
| Output address | Address receiving one byte after successful gated processing. |
| Position address | Address of the mutable integer position. |

The return value occupies four bytes:

- **1:** The gate values differ; no pointed-to memory is accessed.
- **0:** The gate values match and processing reaches its normal return.

These are status values, not the delivered byte or a count of skipped bytes.

### Widths and layout

The supplied representation explicitly identifies the unused input and return value as four-byte quantities, and the output element as one byte. Gate values, positions, and the byte-storage base are represented using integer types. A 32-bit interpretation is consistent with that representation, but the supplied material does not independently establish the target integer model or pointer width.

The byte address is formed by adding the position to the integer-valued base. There is no scaling by an element size greater than one. The input therefore describes byte offsets, not indices into an array of wider objects.

The position location is accessed as an integer object. Its required alignment, byte order, and precise representation depend on the target ABI. These details matter if other supplied regions overlap its constituent bytes.

### Preconditions for normal completion

When the gate values match:

- The position location must support the integer reads and writes performed.
- Every examined byte address must support a one-byte read.
- The eventual output location must support a one-byte write.
- Position increments and address formation must remain meaningful under the target arithmetic model.
- Processing must eventually encounter a byte that fails the marker comparison if normal termination is required.

No length, end address, capacity, or maximum iteration count is supplied. The function does not establish these preconditions itself.

When the gate values differ, none of these pointed-to-memory preconditions is needed for the body’s shown behavior, because those addresses are not dereferenced.

## Behavior

### Gate decision

The first behavioral decision compares gate-left with gate-right.

If they differ, the function immediately returns 1. It does not read the position, examine byte storage, or write the output. In particular, this path does not initialize or clear the output.

If they match, processing proceeds regardless of the unused first input.

### Marker scanning

Each scan iteration begins by reading the integer position from its caller-provided location. The function then reads one character-sized byte at the address formed from the byte-storage base plus that position.

If the character value equals −128, the function writes the previously read position plus one back to the position location. It then begins another iteration, including a fresh read of the position.

Under signed 8-bit character interpretation, the comparison recognizes raw byte 0x80. Consecutive such bytes cause repeated position increments and repeated byte examinations.

A byte that fails the comparison ends the scan. The position used for that final examination remains relevant to the subsequent increment.

### Terminal transfer

After the first failed marker comparison, the observable memory sequence is:

1. Read the position location again.
2. Write one more than the position used by the final scan examination to the position location.
3. Read one byte at the byte-storage base plus the position obtained by the additional read.
4. Write that byte to the output address.
5. Return 0.

The position used for the final byte transfer is therefore obtained by a distinct read. The position value written before that transfer is derived from the preceding scan iteration’s read.

For ordinary stable memory with disjoint regions, those two position reads agree. In that case, the function skips a run of marker bytes, outputs the first following non-marker byte, and leaves the position immediately after that byte.

That simplified description is conditional. The additional position read and the position write before the final byte read must not be erased from an alias-sensitive contract.

### Aliasing consequences

No non-overlap requirement appears in the supplied representation.

If byte storage overlaps position storage, a position write can change bytes that will be examined later. The scan therefore operates on the memory values encountered at each read, not on an immutable snapshot.

The terminal byte is also read **after** the position increment has been stored. If that increment changes the addressed source byte through overlap, the delivered value can differ from the value that caused the scan to stop. The delivered value is not necessarily a non-marker value in such a case.

If the output address overlaps position storage, the final one-byte output write can change the position’s object representation after the integer increment. Consequently, the final position need not numerically equal the stopping position plus one.

If the output address overlaps byte storage, the function modifies that storage at the final output step. That write occurs after all scan reads and after the terminal source-byte read.

### Arithmetic boundaries

There is no explicit check for a negative position, an out-of-range address, or integer overflow.

Negative positions are not rejected; they participate directly in address formation. Whether a resulting access is valid depends on the supplied storage and target execution model.

The represented increments use integer addition. The material does not establish defined wraparound behavior at the maximum representable position. A specification consumer must not substitute modular arithmetic merely because a likely machine width is 32 bits.

Likewise, no portable outcome is established for overflowing base-plus-position arithmetic or invalid resulting addresses.

## Side effects

On a gate mismatch, the function performs no pointed-to-memory reads or writes.

On a gate match that completes normally:

- The position is read at the start of every scan iteration.
- Each successful marker comparison causes an integer position write.
- The first failed marker comparison is followed by another position read.
- A final integer position write occurs before the terminal source-byte read.
- Exactly one byte is written to the output.

If there are \(k\) successful marker comparisons before termination, the shown path performs:

- \(k + 2\) integer position reads;
- \(k + 1\) integer position writes;
- \(k + 2\) byte-storage reads;
- one output-byte write.

These counts describe the represented operations on a normally completed path, not a promise about physical memory transactions after compilation.

No allocation, release, ownership transfer, or external function call appears. The function uses caller-supplied locations in place. It neither creates a separate result buffer nor provides cleanup behavior.

There is no explicit global-state access in the supplied body. Caller-supplied addresses can nevertheless refer to global storage or overlapping objects.

If execution cannot continue during scanning or transfer, the function provides no rollback. Earlier position updates may already have occurred. The representation does not define a recoverable error return for invalid memory access, overflow, or an unending marker run.

## Acceptance examples

These are conditional contract examples derived from static evidence, not executed tests.

Unless otherwise stated, examples assume signed 8-bit character interpretation, valid arithmetic and addresses, stable ordinary memory, and disjoint position, source, and output storage.

### Gate mismatch preserves supplied storage

Given unequal gate values and arbitrary existing position and output contents:

- Return value is 1.
- Position is not read or written.
- Byte storage is not read.
- Output remains unchanged.

The unused first scalar does not alter this outcome.

### Immediate ordinary byte

Given equal gate values, position 4, and byte 0x41 at offset 4:

- The scan comparison fails immediately.
- Position becomes 5.
- Output becomes 0x41.
- Return value is 0.

The byte at offset 4 is read once for the scan and again for delivery.

### Multiple marker bytes

Given equal gate values, position 2, and bytes 0x80, 0x80, and 0x2A at offsets 2, 3, and 4:

- Marker processing advances the position to 3 and then 4.
- The comparison at offset 4 terminates the scan.
- The terminal increment makes the position 5.
- Output becomes 0x2A.
- Return value is 0.

### Zero is ordinary data

Given equal gate values and byte 0x00 at the current position:

- Zero does not terminate processing as a string terminator.
- It fails the marker comparison.
- Output becomes 0x00.
- Position advances by one.
- Return value is 0.

### Unsigned plain-character interpretation

If plain characters are unsigned eight-bit values, reading raw byte 0x80 produces value 128 rather than −128.

Under that condition, the marker comparison fails immediately: the function delivers 0x80 and advances once. A conformance claim that requires skipping 0x80 must therefore establish the target character interpretation.

### No accessible non-marker byte

Given equal gate values and an accessible sequence consisting entirely of recognized marker bytes, the function keeps advancing and scanning while execution remains valid.

No finite successful return, bounds error status, or output write is guaranteed. Eventually leaving valid storage is not handled as a normal function error.

### Output overlaps position

Given equal gate values and an output address targeting a byte within the position object:

- The terminal integer increment occurs first.
- The terminal source byte is read afterward.
- That byte is then written into the overlapping position byte.

The final integer value depends on byte order, the selected overlapping byte, and the delivered value. Requiring the final position to equal the consumed offset plus one would be incorrect for this case.
