# F-f99f26ed351b

## Purpose

F-f99f26ed351b performs an ordered sequence of address-dependent memory writes, followed by an unresolved indirect control transfer. The write addresses and values depend on four explicit inputs, three additional incoming execution-state values, and eight shared-storage locations.

The supplied static representation establishes fifteen direct stores with widths of 8, 16, or 32 bits. It does not establish a higher-level operation such as object initialization, table maintenance, or device control. Those interpretations remain **documented_only**.

This contract describes the visible operations and dependencies. It does not guarantee that arbitrary inputs produce valid addresses, that every operation completes, or that the indirect target returns. No runtime tests have been performed.

## Behavior

### Widths and arithmetic

A byte, halfword, and word mean 8, 16, and 32 bits respectively.

For stores narrower than their source values, the contract uses the retained low-order bits. No saturation, truncation diagnostic, or range check is visible. Comparison results contribute zero when false and one when true.

The representation mixes signed integer arithmetic, unsigned 32-bit quantities, and address-like arithmetic:

- C and the retained G4 value are squared using signed-integer expressions.
- Several additions, doublings, and negations also involve signed-integer expressions.
- Boolean comparison results enter some expressions as unsigned quantities.
- The final offset is retained as an unsigned 32-bit value.
- The final G8-based byte-store address is formed by unsigned 32-bit addition in the represented expression.

Signed overflow and conversions from unsigned results into signed intermediate storage are not independently specified. A 32-bit modular interpretation may be used for conditional examples, but must not be promoted into an unconditional rule for all arithmetic. In particular, an unsigned final result does not establish defined wraparound for an earlier signed subexpression.

The byte derived from negating an adjusted value is its negated low-byte pattern. Interpretation of exceptional signed-byte conversions or negation remains subject to the unresolved execution model.

Byte order, alignment requirements, and address validity are unspecified. A multi-byte store is not a promise of any particular sequence of byte transactions.

### Ordered operations

The following sequence describes the ordering visible in the supplied representation. Intermediate names are mathematical labels, not implementation identifiers.

1. **Store the original C.**  
   At C plus B, write the low halfword of C. This precedes every listed shared-storage read and precedes squaring C.

2. **Capture the first shared values.**  
   Read G1 into a first-base snapshot. Then read G2 into a retained 32-bit snapshot.

3. **Capture and store E’s low halfword.**  
   Extract E’s low 16 bits. At E plus A, write that halfword. Retain it for **two subsequent stores**, making three stores total that use this retained fragment.

4. **Derive the first square and adjusted base.**  
   Compute the square of the original C, designated S. Form an adjusted base P from the first G1 snapshot plus 70, with an additional one if T is less than or equal to E.

   The comparison is inclusive. Its address-ordering semantics are not established.

5. **Perform two byte stores, in order.**
   - At twice the first G1 snapshot, write the low byte of the G2 snapshot.
   - At negative twice P, write the low byte associated with negating P.

   The second store remains a separate observable operation even if its destination overlaps the first.

6. **Capture another shared pair.**  
   Read G3 into a retained unsigned 32-bit snapshot. Then read G4 into a retained integer base snapshot.

7. **Repeat E’s retained fragment.**  
   At E plus 68, write the retained low halfword of E.

8. **Derive a second adjusted value and store S’s byte.**  
   Form Q as S plus 65, with an additional one if P equals zero. At S plus the retained G4 snapshot, write the low byte of S.

   The equality test concerns P, including its earlier comparison-derived increment, not the unadjusted G1 snapshot.

9. **Capture G5 and square the retained G4 value.**  
   Read G5 into a word-store base snapshot. Then compute R, the square of the previously retained G4 snapshot. A subsequent change to G4 does not replace this operand.

10. **Perform four stores, in order.**
    - At Q plus R, write the low halfword of R.
    - At the G5 snapshot plus Q, write Q as a full 32-bit value.
    - At S plus R, write E’s retained low halfword.
    - At E plus R, write the low halfword of R.

    The third store is the last use of E’s retained fragment. The fourth stores a fragment of R, not a fragment of E.

11. **Capture late shared values.**  
    Read G6 into a retained 32-bit snapshot. Read G1 again into a second G1 snapshot. Then read G7 into a retained late-base snapshot L.

    The second G1 read cannot be replaced by the first snapshot: intervening stores may have changed its storage.

12. **Use a fresh G7 reference for a byte-store destination.**  
    Reference G7 again. At twice this newly referenced value, write the low byte of the retained G3 snapshot.

    L remains the first G7 snapshot from the preceding step. The fresh reference does not replace L in later calculations.

13. **Write the fixed halfword.**  
    At twice the second G1 snapshot, write the 16-bit value 78.

14. **Capture an argument component and form the final offset.**  
    Read G8 into a retained unsigned 32-bit snapshot U. Form the final unsigned 32-bit offset V from L plus 78, with an additional one if H is less than or equal to the retained G3 snapshot.

    This comparison is unsigned and inclusive. It uses the earlier G3 snapshot, not a fresh G3 reference. The addition of L and 78 appears as a signed subexpression before the unsigned contribution; its overflow behavior remains unresolved.

15. **Perform the final three direct stores, in order.**
    - Reference G8 again. At that newly referenced base plus V, write the low byte of V.
    - At twice L, write the full 32-bit G6 snapshot.
    - At D plus L, write the low halfword of L.

    The first address expression uses unsigned 32-bit addition. The fresh G8 reference does not replace U.

16. **Transfer control through T.**  
    Invoke the unresolved target with one visible argument formed by the bitwise OR of V and U. This is not their sum. No return value from the target is visibly consumed.

17. **Return conditionally.**  
    If the represented invocation returns normally and execution otherwise continues, return without a value.

### Aliasing and repeated references

The fifteen stores are ordered effects, not independent final-state assignments.

A destination may overlap another destination or a shared slot that has not yet been read. Under an ordinary memory interpretation, an earlier write to such a slot changes the value available to a later read. Partial overlap depends on byte order and access semantics.

Retained snapshots remain operands even when their source storage changes. In particular:

- The first G4 snapshot supplies R.
- The first G7 snapshot supplies L.
- The first G8 snapshot supplies U.
- The retained G3 snapshot supplies both its later byte value and the comparison against H.

The repeated G7 and G8 references are not contractually interchangeable with those snapshots. Conversely, their presence in the static representation does not establish a count of physical bus transactions.

No synchronization, atomicity, volatile-access semantics, or immunity to concurrent modification is established.

## Acceptance examples

These are conditional expectations derived from the static representation, not observed executions. They assume valid accesses, an arithmetic model supporting the stated values, and a callable target.

### Original C precedes its square

If C is 4 and B is 4096, the first store writes the 16-bit value 4 at address 4100. Later calculations use S equal to 16. Squaring C does not change the first store retroactively.

### E’s fragment supplies exactly three stores

If E has the bit pattern hexadecimal 12345678, its retained halfword is hexadecimal 5678. That value supplies the stores at:

- E plus A.
- E plus 68.
- S plus R.

If R is hexadecimal 00000144, the store at E plus R instead writes hexadecimal 0144. It does not write hexadecimal 5678.

### The zero increment tests the adjusted base

If the first G1 snapshot is −70 and the T-versus-E comparison is false, P is zero. Q is therefore S plus 66.

With the same snapshot and a true comparison, P is one and Q is S plus 65.

### The final comparison is unsigned and inclusive

If H and the retained G3 snapshot are both hexadecimal FFFFFFFF, their comparison contributes one to V.

If H is hexadecimal FFFFFFFF and the retained G3 snapshot is zero, it contributes zero. Treating H as signed negative one would produce the wrong comparison result in the latter case.

### The final argument uses OR, not addition

Suppose L is hexadecimal D2 and the final comparison contributes zero. V is hexadecimal 120.

If both G8 references yield hexadecimal 110:

- The final byte-store address is hexadecimal 230.
- The stored byte is hexadecimal 20.
- The visible indirect argument is hexadecimal 130.

An argument of hexadecimal 230 would incorrectly substitute addition for bitwise OR.

### A later word store replaces an earlier byte

If both G7 references yield the same value, the G3-derived byte store and the later G6-derived word store begin at the same address.

After the word store completes, that region contains the full G6 snapshot, subject to subsequent effects. The earlier byte is not independently preserved. Which byte of G6 occupies the starting address depends on byte order.

### A changed G7 reference does not replace L

Suppose the first G7 snapshot is 100, its fresh reference is 120, and the final comparison contributes zero.

The G3-derived byte store is at address 240. The later G6 word store is at address 200. V is 178, and the last halfword store is at D plus 100 with value 100.

### Later shared reads can observe earlier writes

If an earlier store changes G1 before its second read, the fixed halfword value 78 is written at twice the second snapshot, not necessarily twice the first.

If a store changes G8 between its first and second references, the byte-store base may differ from U. The indirect argument still uses retained U.
