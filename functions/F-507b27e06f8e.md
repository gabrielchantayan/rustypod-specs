# F-507b27e06f8e

## Purpose

F-507b27e06f8e expands four interleaved pairs of signed integer components into seven pairs in the same storage. It uses three successive levels of pairwise averaging, with integer truncation at every level.

The resulting sequence consists of the original first pair, five derived pairs, and the original fourth pair. The middle derived pair is shared by the two three-interval halves of the output.

**Inferred intent:** This arrangement is consistent with subdividing a planar cubic Bézier control polygon at its midpoint. That interpretation explains the seven-pair layout, but the established behavior is integer component processing. The function neither evaluates a curve nor establishes a geometric interpretation for its input.

## Behavior

### Averaging rule

Define the component average \(M(u,v)\) as the signed integer result of adding \(u\) and \(v\), then dividing that sum by two with truncation toward zero:

\[
M(u,v)=\operatorname{trunc}_0\left(\frac{u+v}{2}\right).
\]

This definition applies only when the addition is representable. The implementation does not first widen the operands or use an overflow-avoiding average.

Consequently:

- An odd positive sum loses its fractional half toward zero.
- An odd negative sum also loses its fractional half toward zero, rather than rounding downward.
- Each level uses already-truncated results from the preceding level.
- A single final rounding of an equivalent real-valued expression is not a substitute for these intermediate truncations.

### Component transformation

The two component positions undergo the same transformation independently.

For either component, let \(a,b,c,d\) denote its original values in input pairs A, B, C, and D. Define three first-level averages:

\[
p=M(a,b), \qquad q=M(b,c), \qquad r=M(c,d).
\]

Define two second-level averages:

\[
s=M(p,q), \qquad t=M(q,r).
\]

Define the shared middle value:

\[
u=M(s,t).
\]

For that component, the seven output values are:

\[
a,\ p,\ s,\ u,\ t,\ r,\ d.
\]

The first component is processed completely before processing of the second component begins. There is no averaging between the two component positions.

### Preservation and replacement

Elements 0 and 1 are not written. They retain the original pair A.

The original pair D is copied into elements 12 and 13, but its two components are copied at different stages. The first component is copied before first-component arithmetic; the second component is copied only after all first-component writes have completed.

The original interior pairs B and C are replaced. Elements 6 and 7, which originally hold D, become the shared middle pair. Callers that need the original four-pair representation after the call must preserve it separately.

### Observable access and write order

The function does not publish all seven output pairs atomically. It performs a first-component phase followed by a second-component phase.

The ordered destination elements are:

| Phase | Destination order |
|---|---|
| First component | 12, 2, 10, 8, 4, 6 |
| Second component | 13, 3, 11, 9, 5, 7 |

In the first phase:

- The original value at element 6 is read and copied to element 12 before any averaging input is consumed.
- All first-level averages for that component are formed before element 2 is overwritten.
- The later arithmetic uses retained intermediate values, rather than rereading the newly written output elements.
- The write to element 6 completes this phase.

The second phase follows the same structure using the odd-numbered elements. It begins by reading element 7 and copying it to element 13. All of its first-level averages are formed before element 3 is overwritten.

The endpoint copy and the corresponding first-level average use separate source reads. Thus, element 6 is read both for its copy and for averaging; element 7 is likewise read separately for those purposes. The two interior source components are each used in two first-level averages.

The supplied expressions do not establish a left-to-right ordering between the two operand reads within an individual addition. The write sequence above is an abstract source-level sequence, not a guarantee of externally visible machine transactions for ordinary non-volatile memory.
