# F-e571c15425a7

## Purpose

F-e571c15425a7 constructs nine 32-bit destination values from nine selected source values, computes a three-term scalar using the partially constructed destination, and conditionally scales the result. A nonzero third argument enables an additional check and possible scaling of a larger, sixteen-word destination region.

**Inferred intent:** the selected offsets, alternating signs, three-term accumulation, and scaling pattern resemble inversion of a three-by-three fixed-point matrix embedded in a four-word-stride layout. The optional path resembles a normalization correction. These interpretations are not established mathematical guarantees: the arithmetic dependencies are unavailable, and one correction dependency receives no explicit arguments.

The contract below distinguishes explicit operations from inferred numerical meaning. In particular, it does not promise a valid inverse, define a singularity error, or assume that any dependency preserves memory or global state.

1. F-e713aa9f4f3b with S[0] and D[0].

### 4. Scale the nine principal destination words

If the accumulated value is nonzero, the function calls F-dc13818ac82a with that 32-bit value. Its 32-bit return value becomes a scale factor.

The function then scales the nine principal destination words in this order:

**D[0], D[4], D[8], D[1], D[5], D[9], D[2], D[6], D[10].**

For each word:

- The current destination value is interpreted as a signed 32-bit integer.
- The scale factor is interpreted as a signed 32-bit integer.
- Their product is formed at signed 64-bit width.
- Product bits 16 through 47 become the stored 32-bit word.

A signed 32-by-32-bit product fits within signed 64-bit storage. The subsequent extraction discards the lowest sixteen bits and every bit above bit 47. There is no visible saturation, overflow report, or round-to-nearest adjustment.

As a bit-level description, this is the low 32 bits of an arithmetic right shift of the signed product by sixteen. For a negative product with discarded nonzero low bits, that corresponds to downward rounding rather than truncation toward zero.

The return value of F-dc13818ac82a is used even if it is zero or numerically unsuitable. No validation of that result is visible.

After the nine writes, the function explicitly writes zero to the single byte at destination byte offset 64. It does not clear the surrounding word.

### 5. Optionally check and correct

If the third input is zero, the function returns after the byte write.

Otherwise, it makes three calls to F-e713aa9f4f3b in this order:

1. D[2] with D[2].
2. D[6] with D[6].
3. D[10] with D[10].

It adds their three 32-bit results and compares the sum with **65,536**, hexadecimal **0x00010000**.

The arguments are separately expressed reads of the indicated destination word. No atomic snapshot is established across these calls.

If the sum equals 65,536, the function performs no further explicit writes.

If the sum differs, it:

1. Calls F-b19479256fec with **no explicit arguments**.
2. Uses that dependency’s 32-bit return value as another signed scale factor.
3. Scales D[0] through D[15] in ascending index order, using the same signed 64-bit product and bits-16-through-47 extraction as the earlier pass.

The correction therefore processes sixteen words, not merely the nine principal words. D[3], D[7], D[11], D[12], D[13], D[14], and D[15] are included despite not being initialized by the preceding construction.

The computed comparison sum is not explicitly passed to F-b19479256fec. Any relationship between that sum and the returned factor would require an implicit-state contract that is not supplied.

There is no second check after correction and no loop attempting convergence.
