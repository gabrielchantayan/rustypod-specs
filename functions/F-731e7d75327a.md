# F-731e7d75327a

## Purpose

F-731e7d75327a compares two explicitly bounded sequences of 16-bit input units after mapping each visited unit through F-3edb5a885790. Only the upper 16 bits of each mapping result participate in the comparison. A zero upper half is ignored.

For the supported selector value, the function returns a signed ordering result:

- **−1:** the first sequence orders before the second.
- **0:** the sequences compare equal.
- **+1:** the first sequence orders after the second.

The observable operation is more specific than a conventional filtered lexicographic comparison. It can continue mapping the first sequence after the second has been exhausted, and it can map additional units from the second sequence after discovering a decisive mismatch. These calls and reads are part of the behavioral contract.

**Inferred intent:** comparison of sequences under a caller-supplied transformation that can discard units.

**Not established:** that the inputs are text, that their units have any particular encoding, or that the transformation is pure, deterministic, or independent of call order.

| 3 | Base address of the second sequence | Address represented by a 32-bit argument |

Each sequence is a contiguous array of 16-bit units with a two-byte stride. Sequence lengths count units, not bytes. There is no terminator check: a zero input unit is still passed to the dependency if reached.

The return value is a signed 32-bit value. On a normally completed invocation with selector 1 and without arithmetic anomalies, it is exactly −1, 0, or +1.

For selectors other than 1, the supplied representation returns an uninitialized incoming register value. That path does not establish a meaningful comparison result.

### Preconditions and supported arithmetic domain

For an ordinary, well-defined comparison:

- Every sequence location actually read must be accessible for a 16-bit load.
- The base addresses and two-byte indexing must produce the intended locations without address wraparound.
- The execution environment must permit the alignment of those loads.
- F-3edb5a885790 must return normally whenever called.

Lengths are not validated. A zero-length sequence does not require its base address to be dereferenced by this function. Whether an otherwise invalid address may safely be passed without dereference is an ABI/environment question.

The sequence bases may alias each other. No distinctness check appears. If the dependency changes either sequence, later loads observe memory at the time they occur; the function does not take an input snapshot.

## Behavior

### Mapping and retained values

For every visited input unit, F-731e7d75327a calls F-3edb5a885790 with:

1. Argument 5 of this function.
2. The currently loaded 16-bit unit.
3. Argument 7 of this function.

It interprets the returned 32-bit value using a logical right shift by 16. The resulting comparison value is therefore an unsigned value in the range 0 through 65,535.

The lower 16 result bits have no effect on filtering, ordering, or retained-unit counts. In particular:

- A result with upper half zero is discarded even if its lower half is nonzero.
- A result with upper half nonzero is retained regardless of its lower half.
- Retained values are compared numerically as unsigned 16-bit magnitudes, not as signed 16-bit values.

A discarded result still entails an input read and a dependency call.

### Initialization

When the selector equals 1, the function initializes:

- Both sequence positions to zero.
- Both retained-unit counts to zero.
- The provisional ordering result to zero.

Positions count all visited units, including discarded ones. Retained-unit counts count only mapping results whose upper halves are nonzero.

### Main traversal

The function first advances through the first sequence until either:

- A retained value is obtained; or
- The first sequence is exhausted.

Discarded first-sequence values do not trigger any second-sequence processing.

On obtaining a retained first-sequence value, the function increments the first retained-unit count. It then advances through the second sequence until either:

- A retained second-sequence value is obtained; or
- The second sequence is exhausted.

If a retained second-sequence value is obtained, the second retained-unit count is incremented and the two retained values are compared.

- Equal values cause the main traversal to continue with the next first-sequence unit.
- A larger first value establishes provisional result +1.
- A smaller first value establishes provisional result −1.

A mismatch ends the main traversal, but does **not** necessarily end input reads or dependency calls.

If the second sequence becomes exhausted while seeking a retained value, the function resumes scanning the first sequence. It does not immediately return an ordering result. Additional retained first-sequence values are counted, but no comparison is made against an absent second value.

Consequently, in a mismatch-free execution, every unit of the first sequence is visited. Units of the second sequence are visited only as needed by the paired traversal and the subsequent tail traversal.

### Second-sequence tail traversal

After the main traversal ends, the function may continue visiting the second sequence.

It does so while both of these conditions hold:

- Unvisited second-sequence units remain.
- The second retained-unit count is less than or equal to the first retained-unit count.

Each visited unit is mapped in the usual way. A nonzero upper half increments the second retained-unit count; a zero upper half does not.

The equality case is significant: if the retained-unit counts are equal, another retained second-sequence value may still be consumed. The tail traversal stops once the second retained-unit count becomes **strictly greater** than the first count, or the second input is exhausted.

This traversal also occurs after a mismatch. In that case it does not replace the established ordering result. It may nevertheless produce observable reads, dependency side effects, or a failure before the function can return.

The function need not consume the entire second sequence. Once its retained-unit count exceeds the first count, remaining second-sequence units are left unread.

### Final result selection

A nonzero provisional result from a paired-value mismatch is returned unchanged after tail processing.

If there was no mismatch and the first sequence has been exhausted, the retained-unit counts determine the result:

- Fewer retained first-sequence values: −1.
- More retained first-sequence values: +1.
- Equal retained-unit counts: 0.

For a stable, deterministic mapping that does not mutate the inputs, this gives the ordinary lexicographic ordering of the two sequences after removing zero-upper-half mapping results. The actual read and call trace remains the traversal described above.

## Side effects

F-731e7d75327a performs direct reads of visited 16-bit sequence units. It has no explicit writes to the input buffers, external objects, or global storage in the supplied representation.

Its observable dependency-call order is:

1. A run of first-sequence calls ending at the next retained value or first-sequence exhaustion.
2. If a retained first value was found, a run of second-sequence calls ending at the next retained value or second-sequence exhaustion.
3. Repetition until mismatch or first-sequence exhaustion.
4. A possible final run of second-sequence calls under the retained-count stopping condition.

Within either sequence, units are visited in increasing index order. No unit is revisited by this function. Each visited unit is loaded before the corresponding dependency call, and that call completes before the next unit is loaded.

The dependency may have additional effects not shown here. In particular, the evidence does not establish that it:

- Preserves global state.
- Leaves either input sequence unchanged.
- Avoids allocation, release, callbacks, or external I/O.
- Preserves the lifetime of objects reachable through the opaque arguments.

The current unit is already loaded when its mapping call starts. Changes made during that call can affect later loads, including loads through an aliased sequence base.

No ownership transfer, allocation, or release is explicit in this function. This does not establish ownership rules for the dependency.

There is no explicit error return, validation failure, or recovery path. Invalid memory accesses and dependency failures have no specified conversion into an ordering result.
