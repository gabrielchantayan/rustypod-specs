The dependency designation **F-unknown** denotes an unresolved callee occurrence. It does not assert that different occurrences resolve to the same function.

## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **Third-argument shift boundary.** If execution reaches the four-argument call, an original third argument of `0x00003fff` contributes zero in its fourth position. An original value of `0x00004000` contributes one.

2. **Unsigned ambient shifts.** For a second ambient word of `0xffffffff`, its eight-bit and sixteen-bit right shifts produce `0x00ffffff` and `0x0000ffff`. These are logical shifts, not signed shifts preserving a leading one bit.

3. **Selector destination.** If a particular selector-byte read returns `0xff`, that write targets address `0x110`. A later selector read is not required to return the same byte.

4. **Byte truncation.** If the unsigned result used for the first shifted byte write is `0x00000041`, its left shift by two gives `0x00000104`; the stored byte is `0x04`.

5. **Repeated writes remain observable.** If a call changes memory between two represented writes to the same location, the later write still occurs. The contract does not permit treating it as redundant.

6. **First loop argument constraint.** Whatever zero-through-31 value is obtained during loop preparation, its right shift by eight is zero. This constrains the first iteration only.

7. **Normal-return exclusion.** If every dependency returns normally and every access succeeds, reaching the final loop does not lead to a normal return in the represented control flow.

8. **Invalid destination.** If a calculated destination is not writable, the supplied representation provides no explicit error result or recovery behavior. The resulting platform behavior remains unspecified.
