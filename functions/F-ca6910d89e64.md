# F-ca6910d89e64

## Purpose

F-ca6910d89e64 dispatches a 32-bit request against an object and, on a handled path, publishes a 32-bit value obtained through shared storage.

Its explicit normal returns are:

- **0:** dispatch rejects the request, or the indexed-state gate fails. The function makes no explicit store to the caller’s output slot.
- **1:** the publication dependency returns, its 32-bit result is stored in the output slot, and the function completes normally.

Returning 1 does not establish that a dependency succeeded, that a result was newly produced, or that shared storage contains a nonempty value. Some handled branches perform no branch-local result update before publication.

A property-query or presentation dispatcher is an **inferred intent**. Concrete object types, property names, text, and ownership conventions are not established.

## Behavior

### Initialization and global captures

Initialization precedes request dispatch, including requests ultimately rejected.

The auxiliary 32-bit value initially equals the incoming request. If bit 0 of the initialization-status word is set, initialization is skipped.

Otherwise, the function calls F-b255b26284e6 with the initialization token. The represented return is 64 bits. After that call, the function performs these observations in order:

1. Reads one opaque initialization argument from global storage.
2. Captures the current shared-result pointer.
3. Takes the upper 32 return bits as the auxiliary value.
4. Tests the lower 32 return bits for zero.

The argument and pointer captures occur even when the lower half is zero. On that zero branch, there are no explicit initialization stores or additional initialization calls.

For a nonzero lower half, the sequence is:

1. Read the shared-result pointer afresh and store the opaque initialization first-word value through that fresh pointer.
2. Store a 32-bit zero at byte offset +4 from the **previously captured** pointer.
3. Call F-804adc29bbfb with the captured pointer, another opaque initialization argument, and the argument captured before the lower-half test.
4. Read the initialization token again and call F-d08d3ca17b81 with it.
5. Replace the auxiliary value with the represented secondary return-register value from that last call.

The first store and the +4 store therefore do not use the same pointer capture. Their destinations coincide only if the relevant pointer observations yield the same value. The argument captured before the test is not refreshed for F-804adc29bbfb.

Subsequent shared-result operations and publication independently read the global shared-result pointer at their call sites. They do not reuse the initialization capture. A dependency that changes that global can affect later destinations.

### Request routing

The indexed operation offset is the incoming request minus 0x36AE, modulo 2³². This offset remains the operation selector even when dispatch uses a different subtraction for a range check.

Routing follows this precedence:

1. Equality with A enters indexed processing.
2. Otherwise, a request signed-less-than A enters indexed processing only if its unsigned operation offset is at most 11; otherwise it returns 0.
3. Otherwise, equality with B selects the first secondary-object direct branch.
4. Otherwise, a request signed-less-than B enters indexed processing only if unsigned wrapping subtraction of 0x36BB yields at most 4; otherwise it returns 0.
5. Otherwise, equality with C selects the object-level F-7df63751aca5 branch.
6. Otherwise, a request signed-less-than-or-equal-to C selects:
   - The alternate secondary-object branch for 0x36C4.
   - The object-level F-7df63751aca5 branch for 0x36DD.
   - Rejection for other values.
7. Remaining requests select F-8bd6adf0eac4 for 0x36DF, the direct F-1f62160dfd52 operation for 0x36E5, or rejection otherwise.

The boundary values are unavailable. No ordering or distinctness between A, B, and C is established. Equality with B alone does not prove entry to its direct branch: equality with A, or the earlier signed-less-than-A branch, can intercept it. The same precedence qualification applies to later fixed-number requests.

### Indexed gate and selection

Indexed processing first reads the 32-bit field at +0xF0.

- If its signed value is negative, the function rejects without reading +0xC4.
- If its signed value is nonnegative, including zero, the function reads +0xC4.
- It rejects if the two fields are equal or if the signed +0xC4 value is less than the signed +0xF0 value.

The effective passing condition is therefore:

**signed +0xF0 ≥ 0 and signed +0xC4 > signed +0xF0.**

Zero at +0xF0 is not an unconditional rejection. Zero followed by a positive signed +0xC4 passes.

After the gate passes, F-5836102a55c4 receives the address object +0xC0. Its returned 32-bit value is the selected item. There is no explicit zero check before item-dependent operations.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initialization zero branch:** If initialization is entered and F-b255b26284e6 returns a zero lower half, the initialization argument and shared-result pointer are still read before that half is tested. Neither explicit initialization store follows.

2. **Distinct pointer observations:** If the initialization capture observes pointer P and the first-store reload observes Q, the first word is stored through Q; the zero at +4 and F-804adc29bbfb use P.

3. **Negative gate:** For an indexed request, +0xF0 = 0xFFFFFFFF rejects without reading +0xC4 or calling F-5836102a55c4.

4. **Zero gate:** For an indexed request, +0xF0 = 0 requires reading +0xC4. A value of 1 there passes; 0 or 0xFFFFFFFF rejects.

5. **Strict comparison:** Indexed fields +0xF0 = 7 and +0xC4 = 7 reject. Changing the latter observation to 8 passes the gate.

6. **Byte predicate:** At offset 2, a readable first byte of 0x80 produces formatting scalar 1, regardless of later bytes.

7. **Unnormalized scalar:** At offset 12, a dependency result of 5 is passed as 5, not normalized to 1.

8. **Repeated count:** At offset 9, successive count results 3 and 2 produce index calls for 1 and 0, with one separator sequence between them.

9. **Zero secondary value:** If routing actually reaches the B direct branch and its post-initialization +0xF8 read observes zero, that branch performs no result-setting or clearing call before publication. Initialization may already have explicitly written zero to shared storage.

10. **Default indexed operation:** If routing reaches indexed processing with an offset outside 0–17 and the gate passes, selection occurs, followed by publication without an indexed-case result operation.

11. **Publication reload:** If an earlier dependency changes the shared-result pointer, publication uses the pointer observed at its own call site, not the initialization capture.

12. **Output order:** On normal handled completion, F-ecd1af0519f9 returns before the explicit output store; the function then returns 1.
