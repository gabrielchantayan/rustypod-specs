# F-629f530c5a82

## Purpose

F-629f530c5a82 performs a two-level lookup using two unsigned 32-bit keys. The first key selects a directory entry. That entry supplies a payload location, a count, and a mode controlling how the second key selects a payload row:

- **Exact-key mode:** binary search over unsigned keys stored in payload rows.
- **Consecutive-key mode:** range-check the second key, then derive a row index from its distance from a starting key.

A successful lookup stores the selected row’s third word through the output address and returns the sum of the context adjustment and the row’s second word. Every explicit lookup miss stores zero and returns zero.

The visible implementation does not provide a separate success indicator. Successful results can contain zero in either or both output channels.

These are static deductions from the supplied representation. Sorted tables and compact representation of consecutive keys are inferred intent, not validated properties.

## Behavior

### Directory search and base reads

The directory count is read once at initialization. The search begins with signed lower bound zero and signed upper bound equal to that count minus one.

Before accessing a candidate entry, the function checks whether the upper bound is below the lower bound. An exhausted interval takes the common miss path.

For a nonempty interval, the midpoint is calculated by signed addition of the bounds followed by a right shift by one. Defined ordinary search behavior requires the addition to remain representable.

Each candidate-key access separately reads the context’s directory-base field. The candidate address uses that base and a signed midpoint multiplication by 16. The candidate’s unsigned key is read once for that probe and retained for the comparisons:

- A smaller first input key narrows the search below the candidate.
- Equality proceeds to entry selection.
- A larger first input key narrows the search above the candidate.

All key comparisons are unsigned.

**Equality does not retain the address used for the candidate-key read.** After equality, the function reads the context’s directory-base field again and combines this new value with the same midpoint displacement to form the selected entry address.

Consequently, if the directory base changes between these reads, the selected entry can belong to a different directory from the one whose key matched. Its own key is not checked again. This is a specific read pattern, not merely an absence of synchronization.

Duplicate keys have no first-match or last-match guarantee. With stable storage, the matching midpoint reached by the search is selected.

A zero directory count misses without reading the directory base or an entry. Negative counts also give an immediately exhausted interval when subtracting one is representable. The most-negative signed count is excluded from that guarantee because the initial subtraction exceeds signed range.

### Payload location and mode selection

After forming the selected entry address, the function obtains a payload pointer by adding:

- The context’s payload-base field.
- The selected entry’s signed displacement at offset 12.

The displacement is already a byte displacement; it is not multiplied by the row stride.

The relative evaluation order of the payload-base read and the entry-displacement read is unspecified. Both contribute to payload-pointer formation before the mode-dependent lookup.

The selected entry’s mode word is then read. Exactly 1 selects consecutive-key mode. Every other bit pattern selects exact-key mode; unsupported-mode rejection does not exist.

The selected entry address and the resulting payload pointer are retained for subsequent operations. The directory base is not reloaded to reinterpret later fields of that selected entry.

### Exact-key mode

The function reads the selected entry’s count once and conducts a signed-bound binary search over payload rows. Each candidate index is a signed integer. Its key access uses a signed multiplication by three to obtain a word offset.

The candidate key is compared as unsigned against the second input key:

- A smaller second key narrows the search below the candidate.
- Equality selects the candidate.
- A larger second key narrows the search above the candidate.

The supplied representation evaluates the candidate-key memory expression once for the less-than comparison and again for equality when the first comparison is false. It does not explicitly retain one key value for both comparisons. Stable storage makes these reads equivalent; changing storage need not.

An exhausted interval takes the common miss path. A zero count misses without reading any payload key, although payload-pointer formation and entry-field reads have already occurred. Negative counts likewise exhaust immediately where the required subtraction is representable.

Duplicate payload keys have no first-match or last-match guarantee.

### Consecutive-key mode

The first payload word is read as an unsigned starting key. This access occurs even if the count is zero or the second key will be rejected.

If the second key is below the starting key, the function misses without reading the entry’s count for endpoint calculation.

Otherwise, it reads the count and computes an inclusive endpoint as:

**starting key + count − 1, modulo 2³²**

Because the starting key is unsigned, the signed count contributes through unsigned conversion. There is no positivity check.

Range acceptance requires both:

- Second key at least the starting key.
- Second key at most the computed endpoint.

This is not a circular-range check. When the endpoint is below the starting key, no key satisfies both comparisons.

After range acceptance, the unsigned 32-bit difference between the second key and the starting key is **assigned to a signed integer**. That signed value becomes the row index.

A difference no greater than 2,147,483,647 is representable without ambiguity in the apparent signed 32-bit model. Conversion of a larger difference is not established by the supplied representation. It must not be described as an unsigned row index used directly for addressing.

Range acceptance therefore does not establish a defined payload access.

### Shared row addressing and success result

Both modes use the same signed row-index arithmetic after selecting an index:

- The output-value access uses the signed index multiplied by three, then signed addition of two.
- The return-contribution access uses the signed index multiplied by three, then signed addition of one.

These intermediate operations must remain representable independently of whether the backing allocation is large enough. For a nonnegative signed 32-bit index, satisfying both selected-word expressions requires an index no greater than **715,827,881**. Pointer scaling and the resulting addresses must also be valid; representable word offsets alone are insufficient.

The success sequence is:

1. Read the selected row’s third word.
2. Store that word through the output address.
3. Evaluate the return sum from the context adjustment and the selected row’s second word.
4. Return the sum through the declared signed result.

The output store precedes evaluation of the return expression. The relative evaluation order of the adjustment read and the selected row’s second-word read is unspecified.

The unsigned row word causes the addition to use unsigned 32-bit arithmetic. The result is then converted to the signed return type. Results within the signed positive range have an unambiguous value. The conversion rule for larger unsigned results remains unresolved.

### Miss result

Every explicit miss path stores one 32-bit zero through the output address and returns zero.

A miss does not preserve the previous output value. It does not read the context adjustment or selected-row return contribution.

Invalid memory access and invalid arithmetic are not additional checked miss cases.

### Output overlap

The output store can overwrite context or table storage because no overlap check exists.

On success:

- Overlap with the context adjustment can change the adjustment subsequently read for the return sum.
- Overlap with the selected row’s second word can change the contribution subsequently read.
- Overlap with the selected row’s third word stores the value already read from that location, assuming ordinary valid memory semantics.
- Overlap with other storage overwrites that storage even if it does not affect the remaining calculation.

These consequences are subject to the actual environment’s memory-access and aliasing rules.

On miss, an overlapping output can still alter context or tables, but the function then returns zero without further lookup reads.

### Changing storage and faults

There is no coherent-snapshot guarantee. In particular, the directory count is captured once, directory bases are read per probe and again after a match, and exact-mode candidate keys have separate comparison evaluations.

The description concerns visible expression-level accesses. Exact physical loads, compiler transformations, and concurrent-access semantics are not independently established.

A fault before an output store can leave the previous output intact. A fault during return evaluation after a successful store can leave the output modified without a completed return. No explicit recovery is provided.
