## Behavior

### Arithmetic interpretation

Unless stated otherwise, the deductions in this section assume 32-bit unsigned address arithmetic reduced modulo 2³².

Define the initial address-like quantity M as A multiplied by 0x400000 under that interpretation. Thus M is zero exactly when the low ten bits of A are zero. A separate doubled-scale quantity, A multiplied by 0x800000, is also zero whenever M is zero.

These products are numeric transformations. They do not allocate storage or establish that the resulting addresses designate objects.

### Initial conditional transfer

When M is nonzero, the initial memory transfer is skipped.

When M is zero, the routine performs a single 16-bit transfer:

1. Compute the destination address as P + C.
2. Read one unsigned 16-bit value from P.
3. Store that value as 16 bits at P + C.

The address arithmetic uses C as a **byte displacement**, not as a count of 16-bit elements. The derived working address subsequently used in comparisons becomes P + C − D.

The read occurs before the write. Consequently, when source and destination are identical, the operation still represents a read followed by a write; it is not established to be optimized away. When the regions overlap, the stored value is the value obtained by the preceding 16-bit read.

This path also computes an address-like value from L, bit 8 of A, and S shifted right by one. Under the 32-bit interpretation, M = 0 implies that bit 8 of A is zero, so this value reduces to L + (S shifted right by one).

There is no bounds, null-address, alignment, or ownership check before the transfer.

### Eligibility for the exceptional memory operation

A sequence of zero-dependent comparisons controls whether a further memory operation occurs. These comparisons have no memory side effects themselves.

Under the stated 32-bit model, reaching that operation requires all of the following:

- M = 0.
- L = 0.
- S shifted right by one = 0.
- C = B.
- P + C − D = D, with address arithmetic reduced modulo 2³².
- E = 0.
- S + 2C = 0 modulo 2³².

The carry input to the final addition is zero on this path. Although the represented expressions include variable shifts, the comparison stages that are actually entered here use a zero shift count: each is entered only after the preceding result was zero. No nonzero shift-count semantics need to be assumed for these comparisons.

The conditions on S and C are particularly restrictive. S shifted right by one = 0 permits only S = 0 or S = 1. Since 2C is even modulo 2³², S + 2C = 0 excludes S = 1. Therefore this path requires:

- S = 0.
- C equal to either 0 or 0x80000000.
- B equal to that same C.

This is a conditional arithmetic deduction, not evidence that an executable environment supplies a usable stack at address zero.

### Exceptional memory operation

If the preceding conditions hold and execution reaches this operation:

1. A special machine-state location is assigned a value derived from S multiplied by 64.
2. The routine derives a revised link-based address as L + 64S.
3. It reads a 16-bit unsigned value at L to obtain a numeric destination address.
4. It stores a 16-bit value, equal to the value read at L plus 15 modulo 2¹⁶, at that numeric destination address.

The represented expression references the 16-bit value at L both to select the destination and to form the stored value. It does not establish one shared read for both purposes, nor a definite order between those two reads. This distinction matters for volatile, device-backed, or concurrently modified memory. For stable ordinary memory containing H, the destination is the zero-extended address H and the stored halfword is H + 15 modulo 2¹⁶.

Under the eligibility conditions already derived, L = 0 and S = 0. The revised link-based address therefore remains zero, and the special-state assignment receives zero.

There is no check that address zero is readable, that the destination obtained from its contents is writable, or that either address has suitable alignment.

### Later represented memory branches are unreachable under this model

The supplied material contains further conditional reads and writes involving 32-bit values, signed 16-bit values, and additional address transformations. They are not accepted as reachable behavior merely because they appear textually.

Their prerequisite chain fails:

- Without entry into the exceptional operation, the enabling condition for the next chain is false.
- With entry into that operation, M is zero and the earlier stack-derived comparison value is zero.
- A separate address-like quantity is then advanced by one 16-bit element, making its numeric value 2.
- The next comparison that would continue the chain requires 2 to equal zero.

Consequently, the later memory-access blocks cannot execute under the stated model. This also excludes the later address-derived shift with a potentially large count from reachable behavior.

If the actual machine semantics differ from this model, reachability must be reassessed rather than treating this deduction as unconditional.

### Indefinite call-and-interrupt phase

After the conditional prefix, the routine enters a loop with no represented exit.

Each completed iteration has this order:

1. Invoke the first indirect dependency at the current base address plus 0xEB6 bytes.
2. Invoke the second indirect dependency using the fixed raw target value 0x0857A94B.
3. Perform a software-interrupt operation with immediate 0x5B.
4. Set the base for the next iteration to 0x083D4CC2.

The first indirect call receives these three explicit 32-bit argument values:

- First argument: 0.
- Second argument: 0.
- Third argument: 0xFFFFFFA5.

The third argument is a bit pattern. Its interpretation as signed −91 or as an unsigned value is determined by the unknown callee interface.

The second indirect call has no explicit arguments in the supplied representation. This does not prove that it consumes no register, stack, or global state.

For the first iteration, the base is L. The exceptional prefix does not change that result under its derived eligibility conditions, because both L and S must be zero.

For subsequent iterations, the first raw call target is therefore 0x083D5B78.

The loop progresses only if both calls return and the interrupt operation permits continuation. No preservation of registers, globals, memory, resources, or ownership is guaranteed for these dependencies.
