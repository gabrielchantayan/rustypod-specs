# F-0a08bd5d35c9

## Purpose

F-0a08bd5d35c9 traverses a selector-dependent collection, evaluates eligible entries, and publishes an ordered array of 32-bit values in a caller-supplied context. It can also construct a remapping table. A nullable observer receives notifications for eligible entries, including entries that produce no output.

The inferred purpose is cached grouping by adjacent extracted values. The established behavior is narrower: candidate selection depends on extraction status, comparison results, selector-specific flags, and additional matching rules. This is not global deduplication. Equal extracted values separated by a different retained value can produce multiple outputs.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and return value

The function accepts five arguments:

1. **Context:** a 32-bit address of writable state.
2. **Opaque argument:** a 32-bit value saved initially but not otherwise consumed by the visible logic.
3. **Primary selector:** a 32-bit bit pattern; dispatch includes signed comparisons.
4. **Secondary selector:** a 32-bit bit pattern tested for exact equality.
5. **Observer:** a nullable callable address.

The 32-bit result is:

| Result | Established condition |
|---|---|
| `0` | Normal completion, a cache shortcut, or an initially empty collection |
| `0xffffffce` | F-267f68fe54d6 returns a null collection address |
| `0xffffff94` | A requested value-array or remapping allocation returns null |

The nonzero results represent −50 and −108 under signed 32-bit interpretation. Other failure mechanisms are not translated into these results.

## Behavior

### Startup, cache guards, and extractor snapshots

The initial dependency order is:

1. F-7e4f952e879e.
2. F-5be08f0e0319, retaining its result as a mode snapshot.
3. F-8ff48652068d with the context, retaining the auxiliary address.
4. F-267f68fe54d6 with the context, retaining the collection address.

A null collection returns −50 before any cache guard is read.

For a recognized route, a nonzero cache guard returns success immediately. Existing counts and addresses are not validated.

After a zero guard, the function reads a route-specific global callable-pointer slot:

| Route | Global-pointer snapshot |
|---|---|
| Primary `4` | Its dedicated text-like extractor slot |
| Primary `2` or `0x80000000` | A shared text-like extractor slot |
| Primary `0x40` | A distinct text-like extractor slot |
| Primary `0x04000000` | Another distinct text-like extractor slot |
| Primary `0`, secondary `0x8000` | Its own text-like extractor slot |
| Primary `0`, secondary `0x10000` | Its own text-like extractor slot |
| Primary `0`, secondary `0x20000` | Its own numeric-like extractor slot |

There are seven distinct slots across these routes. Every read occurs after its cache guard and before classification. For primary `2` or `0x80000000`, the global pointer is read **before** context `+0xe38` is read to select index `6` or `7`.

The resulting callable address is retained for traversal. Later dependency calls can change the global slot without changing this snapshot; no preservation of those globals is assumed.

Next, F-a540fc83a3ef receives both selectors and a local buffer of ten 16-bit elements. Its first 16-bit element controls extraction. The descriptor count is then read. Zero returns success without allocation, traversal, notifications, or direct cache publication.

### Allocation and traversal bounds

A general value array is requested through F-f195b74c9758 if classification is `3`, or if primary is `0x80000000` and secondary is zero. Otherwise, classification `5` requests a separate numeric-route array. Other cases allocate neither value array.

Each requested size is four times a freshly read unsigned 16-bit descriptor count. The maximum size is 262,140 bytes; this multiplication cannot overflow 32 bits. A null result returns −108.

The optional remapping-source pointer is then read. If nonnull, its first 32-bit word is passed to F-beb2daa7838d. A null result returns −108. Otherwise, the first 32-bit word of the returned destination is written as zero.

F-94b6eb7b70a5 then receives the current auxiliary `+0xf60` value. Only after this call is the descriptor count read and retained as the traversal bound.

The initial emptiness check, allocation-size reads, and traversal-bound read are separate observations. Their equality is not guaranteed. Safe execution requires allocated capacity to cover every later output write.

Traversal uses unsigned ordinals from zero to one less than the retained bound. Each ordinal is passed to F-f8ec0897aceb with the collection, selected index, and zero. Null entries are skipped. A nonnull entry proceeds only if F-fe9998d8ffdf, called with context, entry, and zero, returns nonzero.

For each eligible entry, F-875f8fbbb5eb is called with the entry to obtain metadata. Extraction follows that call.

### Text-like candidate selection

Classification `3` uses the retained text-like extractor. Classification `12` also uses it, but only for primary `0x80000000` with secondary zero.

For each eligible entry, the reported 32-bit length starts at zero. The extractor receives the entry and output locations for a payload address and length. Only return zero permits candidate selection.

Retained text state consists of a 16-bit length, initially zero, and a 510-byte local buffer whose initial contents are not established. Successful extraction is a candidate if:

- The reported length differs from the retained length; or
- Lengths agree and F-aa53e7865743 returns nonzero.

The comparison receives a fresh read of auxiliary `+0xf00`, the retained buffer, its zero-extended length, the new payload address, and the reported length. A first successful zero-length extraction therefore reaches the comparator; equality is not assumed automatically.

Only after candidate selection is a reported length above 255 clamped to 255. Consequently, repeated reported lengths above 255 can remain candidates because comparison is against the previously retained, clamped length.

After flag filtering and remapping, an accepted nonzero length causes F-ad023a375886 to receive the payload address, local buffer address, and twice the clamped length. The retained length becomes the clamped length. Interpreting this as retaining up to 255 two-byte units is inferred; transfer direction and encoding are unknown.

An accepted classification-`3` candidate with zero length does not append a value. It still updates retained length and can update remapping. Classification `12` has no corresponding empty-length suppression.

A rejected text candidate does not update retained text state.

### Numeric-like candidate selection

Classification `5` invokes the numeric-like extractor with the entry and an output location for a 32-bit comparison value.

On successful extraction:

- The first value is a candidate.
- Later values are candidates only when unequal to the preceding successfully extracted value.
- The preceding-value state updates before flag filtering, even when filtering prevents output.

Failed extraction does not update that baseline.

The numeric callable is visibly initialized only for primary `0`, secondary `0x20000`. Conversely, that route does not visibly initialize a text callable. No fallback or compatibility validation exists.

Numeric processing enters the common acceptance path with text length zero. It performs no payload transfer and sets the retained text length to zero. Its appended value is selected separately from the extracted comparison value.

Other classifications produce no candidates, except the classification-`12` case described above.

### Flag filtering

A candidate is rejected when all of the following hold:

- The startup mode snapshot is nonzero.
- Primary is `4`.
- Secondary is zero.
- Metadata flag bit `0x02` is set.

For primary `0x80000000` with secondary zero, admission instead requires metadata flag bit `0x02` to be set. This path reads the flag byte twice; the second read determines that requirement.

No corresponding restriction is established for primary `2`, or for primary `0x80000000` with nonzero secondary.

### Remapping selection and write order

Accepted candidates reach remapping before payload retention and before deciding whether an output value will be appended.

The source is addressed as 32-bit words:

- Word zero: record count.
- Record number \(r\): payload at word \(2r+1\), boundary at word \(2r+2\).

The destination has the same count-plus-two-word-record arrangement.

The function retains a **selected-record cursor**, initially zero, and a threshold initially `0xffffffff`. An update requires a nonnull destination, the retained cursor below the currently read source count, and threshold less than or equal to the current ordinal under **signed 32-bit comparison**. The initial threshold therefore acts as −1.

The scan provisionally selects the retained cursor’s record. It does **not** first test that record’s own boundary against the ordinal. Instead, it examines the **following record’s boundary**, advancing the selection while following boundaries are less than or equal to the ordinal under **unsigned 32-bit comparison**.

Two positions must remain distinct:

- The retained cursor identifies the selected record.
- The one-record-ahead index identifies the stopping boundary and participates in the source-count equality check.

After scanning, the threshold becomes `0x7fffffff` if the one-ahead index equals the source count read for this update. Otherwise, it becomes the following boundary, read again. The retained cursor remains on the selected record, not one record beyond it.

Thus the first update can select record zero even if record zero’s own boundary exceeds the current ordinal.

For the destination record, observable writes are:

1. Selected source payload.
2. Selected source boundary.
3. Current output count, overwriting the just-written destination boundary.
4. Incremented destination record count.

The source boundary is therefore a transient destination value, not the final second field.

The scan has no visible internal count check. It reads a following boundary even when the one-ahead index reaches the declared source count. Safe storage must supply a stopping boundary and any required look-ahead words. Source count, record-index arithmetic, and destination indexing are 32-bit; unlike descriptor-sized allocation arithmetic, these operations have no established small bound or overflow validation.

|---|---|
| Primary `4` | Metadata `+0x2c` |
| Primary `2` or `0x80000000` | Metadata `+0x34` |
| Primary `0x40` | Metadata `+0x40` |
| Primary `0x04000000` | Metadata `+0x3c` |
| Primary `0`, secondary `0x10000` | Nested metadata `+0x0c` |
| Primary `0`, secondary `0x20000` | Nested metadata `+0x20`, written into the numeric-route array |

Primary `0`, secondary `0x8000` instead performs a full secondary scan, using the retained traversal bound and F-9acdf12faed2. Each scanned item’s nested object must have flag bit `0x01` set and a `+0x28` value equal to the current entry’s `+0x28`.

If context `+0xe30` is nonzero, an additional F-875f8fbbb5eb call participates in qualification. Its argument convention is unresolved. Qualification then requires a nonnull result, a nonzero 32-bit word at result `+0xbc`, and nonzero overlap with a fresh context `+0xe30` read.

The scan continues after finding a match. If any item qualifies, the current entry’s `+0x28` is read and appended once. Otherwise nothing is appended.

Only actual appends increment the output count. Remapping and retained comparison state can advance without an append.

### Observer and completion

After extraction and candidate handling, each eligible entry invokes the observer if enabled. Arguments, in order, are context, the observer’s own callable address, primary, secondary, ordinal, entry, metadata, and a first-notification indicator.

The indicator is `1` on the first actual invocation and `0` thereafter. Return zero disables subsequent notifications without stopping traversal.

Notifications still occur after extraction failure, equal-value suppression, flag rejection, or failure to append. Skipped or ineligible entries do not notify.

After traversal, F-0b8b101e723b receives a fresh auxiliary `+0xf60` read. The context writes in the interface table follow, without another cache-guard check. Normal completion returns zero.

## Side effects

Direct effects include global extractor-pointer reads, dependency calls, allocations, array writes, transient and final remapping writes, observer calls, and final cache publication.

The traversal-bracketing calls may represent synchronization, but their guarantees are unknown. Allocation precedes the first call; publication follows the second.

Published arrays and remapping destinations are not visibly released on recognized successful routes. This establishes retention, not ownership transfer or a destruction policy.

If remapping allocation fails, a previously allocated value array is not visibly released.

For **all three primary-zero secondary routes**—`0x8000`, `0x10000`, and `0x20000`—a remapping destination can be allocated and populated but is neither published nor visibly released on normal completion. The `0x20000` route publishes only its numeric-route array and count.

Unknown callees and observers must not be assumed to preserve globals, context fields, counts, source contents, or allocation lifetimes. The ordering above is not an atomicity guarantee. Aliasing can also affect repeated count reads and writes; ordinary record descriptions require compatible, noninterfering storage.

## Acceptance examples

These are conditional static cases, not executed tests. Unless stated otherwise, they require valid addresses, compatible classification, adequate capacity, and terminating remapping look-ahead.

- **Missing collection:** A null F-267f68fe54d6 result returns `0xffffffce` before cache or extractor-slot reads.
- **Cached route:** Primary `4` with a nonzero guard returns zero without reading that route’s global extractor slot or invoking classification.
- **Extractor snapshot:** For primary `2`, the shared extractor pointer is read before context `+0xe38`. If classification subsequently changes the global slot, traversal still invokes the retained pointer.
- **Initially empty collection:** A zero count after classification returns zero without allocation or publication.
- **Allocation failure:** A null required value-array allocation returns `0xffffff94` before traversal.
- **Adjacent text suppression:** With faithful retention and a comparator returning zero for equality, consecutive identical nonempty accepted text values append only once. Both eligible entries still notify an enabled observer.
- **Long reported text:** A retained length of 255 and a subsequent successful reported length of 300 produce a candidate before clamping, even if their leading payload units match.
- **Numeric grouping:** On the `0`/`0x20000` route with classification `5`, successful comparison values `7, 7, 9` select the first and third entries. Outputs come from their nested metadata `+0x20`, not necessarily from values `7` and `9`.
- **Provisional first remap record:** Suppose the source count is one, record zero’s boundary is `100`, and the following boundary is unsigned `0xffffffff`. An accepted candidate at ordinal zero selects record zero despite its boundary exceeding zero. The final destination second field is the pre-append output count; the next threshold becomes `0x7fffffff`.
- **Empty text remapping:** An accepted classification-`3` zero-length candidate can append a remap record without appending an output value.
- **Unpublished numeric-route remap:** A populated remapping destination on the `0`/`0x20000` route is not written into the context and is not visibly released during normal completion.
- **Observer disable:** Return zero on the first notification prevents later notifications but does not prevent remaining extraction or final publication.
