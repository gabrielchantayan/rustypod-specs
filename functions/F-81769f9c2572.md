# F-81769f9c2572

## Purpose

F-81769f9c2572 obtains a new block and updates a caller-supplied state object through one of three paths:

- Initialize a pointer table and publish two matching position descriptors.
- Append the block pointer to the next slot of the existing table.
- Allocate a replacement pointer table, relocate an active range of pointers, append the new block pointer, and rebuild both descriptors.

The replacement table is **not necessarily larger** than the previous table. Its requested capacity depends on twice the active-range count calculated before allocation, not twice the previous capacity.

The layout suggests a segmented container with two position descriptors. That is **inferred intent**, not an established public type. The function directly manipulates block pointers and descriptors; it does not visibly construct elements, destroy elements, or copy block payloads.

## Interface

### Inputs and representation

The function receives:

1. A pointer to a writable state object.
2. Three additional 32-bit values.

The additional values initialize part of temporary descriptor storage. Their semantic types are unknown; they must not be assumed to be counts, indices, or non-address integers.

The visible representation uses 32-bit words and 32-bit address values. The state object exposes at least 44 bytes:

| Byte offset | Directly observed role |
|---|---|
| 0–15 | First four-word descriptor |
| 16–31 | Second four-word descriptor |
| 32–35 | No direct access |
| 36–39 | Pointer-table base |
| 40–43 | Table capacity/count field |

Each descriptor’s final word, at relative offset 12, is used as a table-slot address. The first descriptor’s first word is also supplied to a descriptor dependency during replacement. The remaining meanings are unresolved.

Before any dependency call, temporary four-word descriptor storage is initialized with the state-object address followed by the three additional arguments, in argument order. This temporary storage is reused, without reinitialization, across descriptor-dependency calls.

### Result

Normal completion returns a 64-bit bit pattern assembled from the temporary descriptor:

- Bits 0–31: its first word.
- Bits 32–63: its second word.

These are the values remaining after the last descriptor-dependency call on the selected path. The result is not established as a status code, allocation address, or state-object address. No signed interpretation is established.

### Preconditions and errors

Ordinary safe execution requires valid writable state storage, valid addresses for all accessed table entries, and dependency behavior compatible with continued execution.

Replacement additionally requires a copy range whose endpoint is reachable by successive four-byte increments, sufficient destination storage, and arithmetic compatible with the intended layout. These properties are not checked.

There is no visible null-result check, explicit error return, rollback, or retry. Dependency failure conventions and abnormal exits are **documented_only**. A returned zero address is not explicitly rejected.

## Behavior

### Common allocation and branch selection

The first dependency call is F-dc2ad11623f8. Its 32-bit result is scaled by four and supplied to F-871e64ddc6de, with zero as the second argument. The returned address-like value is retained as the new block address.

Only after this allocation does F-341a4429b84a receive the state-object pointer:

- Nonzero selects initialization.
- Zero selects extension or replacement.

The predicate’s semantic meaning is unknown. In particular, nonzero is not established to mean “empty.”

Each invocation of F-dc2ad11623f8 is independent. Neither equal results nor preservation of state is guaranteed.

### Initialization

Initialization obtains another value from F-dc2ad11623f8 and publishes it in the capacity field. It then requests a table allocation of four times that value from F-871e64ddc6de, again with zero as the second argument, and publishes the returned table base.

The new block pointer is written into that returned allocation at the slot selected by unsigned halving of the capacity field **read after the allocation dependency returns**. With an unchanged capacity \(c\), the slot index is \(\lfloor c/2\rfloor\).

This write uses the retained allocation result as its base.

A third call to F-dc2ad11623f8 supplies a separate quantity for positioning within the block. F-90765f0620f8 then receives:

1. The temporary descriptor’s address.
2. The block address plus four times the unsigned half of this latest query result.
3. The table-slot address calculated from the state object’s table base and capacity as read after that query.

Consequently:

- Block allocation size, table allocation size, and block-relative position can derive from different query results.
- The slot written before the third query and the slot passed afterward need not agree if that query changes the relevant state fields.

After the descriptor dependency returns, its temporary descriptor is written into the first stored descriptor, first word through fourth word. The first stored descriptor is then read and copied into the second descriptor in the same word order.

Only one table entry is explicitly initialized. No previous table is passed to F-ff1bdc376dcd on this path.

### Extension within the current table

For a zero predicate result, the function compares the second descriptor’s final word with:

\[
\text{table base}+4\times\text{capacity}-4
\]

This is address equality, not a bounds or validity check.

If unequal, the function advances that descriptor word by four bytes and stores the advanced address back into the state. It writes the new block pointer through that advanced address.

F-90765f0620f8 then receives the temporary descriptor address, the block address without midpoint adjustment, and the slot address re-read from the second descriptor.

The resulting temporary descriptor replaces the second descriptor in increasing word order. This replacement can overwrite the slot-address word advanced before the call.

There are no direct writes to the first descriptor, table base, or capacity on this path. Dependencies may nevertheless modify them.

### Replacement-table sizing

Replacement is selected only when the second descriptor’s slot address equals the calculated final table slot.

The sizing calculation uses descriptor boundaries present **before** the replacement allocation. Define:

- \(d\): the signed 32-bit difference between the second and first descriptor slot addresses, shifted right by two.
- \(n=d+1\): the derived inclusive count, represented as a 32-bit unsigned quantity for subsequent sizing.

Interpreting \(d\) as a slot distance requires suitable alignment, ordering, and representable arithmetic.

F-871e64ddc6de receives \(8n\) as its byte quantity and zero as its second argument. For ordinary non-overflowing counts, this requests \(2n\) four-byte slots.

The copy destination begins at a byte offset derived by doubling \(n\) and clearing the lowest two bits. For ordinary nonnegative counts, this is:

\[
O=4\left\lfloor n/2\right\rfloor
\]

Neither the requested capacity nor this offset is derived from the old capacity. A replacement can therefore have fewer slots than the previous table.

### Replacement copying and publication

After the allocation dependency returns, the function reads the second descriptor’s slot address as the copy’s final slot, then reads the first descriptor’s slot address as the starting cursor.

These post-allocation boundaries need not match those used to calculate \(d\) and \(n\).

The copy proceeds in increasing four-byte address order:

- Each source word is read before the corresponding destination word is written.
- The destination starts at the retained new allocation plus \(O\).
- Copying stops when the source cursor equals four bytes beyond the captured final slot.

This is a forward word copy, not a snapshot of the source range. Overlapping storage can affect later source reads. A reversed or misaligned range may fail to reach the stopping address or access invalid storage.

After copying, F-ff1bdc376dcd receives the state object’s then-current table base, then-current capacity, and zero. Only after that dependency returns is the retained replacement allocation published as the table base.

The new block pointer is written at an append position derived from the **pre-allocation** distance and count. For ordinary nonnegative, non-overflowing counts, its replacement-table index is:

\[
\left\lfloor n/2\right\rfloor+n
\]

This slot immediately follows the copied range only when the post-allocation copy range has the expected length \(n\). Unchanged source boundaries are sufficient for that condition. If the allocation dependency changes the boundaries, the append can overwrite a copied entry, leave a gap, or encounter insufficient destination storage.

### Descriptor rebuilding and final capacity

After publishing the replacement table and writing the new block pointer, the function calls F-90765f0620f8 with:

1. The temporary descriptor address.
2. The current first word of the first stored descriptor.
3. The current table base plus retained offset \(O\).

The resulting four words replace the first stored descriptor in increasing word order.

A second call uses the same temporary descriptor storage, the retained block address, and a slot address formed from the **current** table base plus \(O+4d+4\).

The table base is read again after the first descriptor call. If that dependency changes the field, the second call can refer to a different base from the retained allocation used for copying and the block-pointer write.

The temporary descriptor is not reset between calls. Words not overwritten by the second call retain their preceding temporary values.

After the second call, its four-word result replaces the second stored descriptor. The capacity field is then written with \(2n\). The return value is assembled from the temporary descriptor’s first two words.

Thus the final capacity remains derived from the pre-allocation count, even when the actual copy used changed boundaries.

### Width-sensitive arithmetic

All table entries, descriptor words, stored addresses, and relevant arithmetic quantities are 32 bits.

The visible calculations include:

- Fourfold scaling of query results.
- Unsigned halving for initialization positions.
- Signed address subtraction and right shift for the replacement distance.
- Eightfold allocation sizing and doubling of the derived count.
- Clearing the two lowest bits of the doubled count for the copy offset.
- Masking the count with `0x7fffffff` before unsigned halving in the block-pointer append calculation.

Specifically, the block-pointer append byte offset is formed from four times the sum of \(d\) and that masked half-count, followed by an additional four bytes. The later descriptor slot uses \(O+4d+4\). Both reduce to the ordinary append position above for coherent in-range counts.

There is no visible arithmetic validation. These observations do not establish portable signed-overflow behavior or safe wrapped addressing. Out-of-range behavior is **documented_only**.

## Side effects

### Direct mutations

Depending on the branch, direct writes affect:

- One or both stored descriptors.
- The table base and capacity.
- The new block-pointer slot.
- Replacement-table entries receiving copied pointers.

Descriptor publication consists of four separate word writes, not an established atomic update. Bytes 32–35 receive no direct access; dependencies are not guaranteed to preserve them.

No direct block-payload initialization or copying is visible.

### Allocation and ownership

Every normally completed path invokes F-871e64ddc6de for the new block. Initialization and replacement each invoke it once more for table storage.

Only replacement invokes F-ff1bdc376dcd. Its arguments identify the current table and capacity, but this does not establish that it frees storage or acquires ownership.

Allocation exclusivity, ownership transfer, required eventual releases, and abnormal-exit cleanup are unknown. There is no explicit release of the newly obtained block or visible local recovery after a later failure.

### Intermediate states

The operation is not visibly transactional:

- Initialization publishes capacity and table base before descriptor publication.
- Extension advances the stored slot address before invoking the descriptor dependency.
- Replacement copies entries and calls F-ff1bdc376dcd before publishing the new table.
- Replacement publishes the table and descriptors before the final capacity write.

No dependency is assumed to preserve globals or reachable state. Later field reads observe values present at those reads; retained allocation addresses and sizing values are not recomputed automatically.

Thread safety, reentrancy, and safe concurrent observation are not established.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless a case states otherwise, dependencies return normally, provide sufficient valid storage, and do not modify state except through the supplied temporary descriptor.

### Initialization with stable quantities

If all three query results are 8 and the predicate is nonzero:

- The block and table allocation requests are each 32 bytes.
- Capacity is set to 8.
- Table slot 4 receives the block pointer.
- The descriptor dependency receives a block position 16 bytes from the block base and a slot address 16 bytes from the table base.
- Both stored descriptors receive its resulting four words.
- The result contains its first word in the low half and second word in the high half.

### Initialization with different quantities

If the successive query results are 12, 8, and 6:

- The block request is 48 bytes.
- The table request is 32 bytes.
- The pointer is written into table slot 4.
- The descriptor’s block-position argument is 12 bytes from the block base.

The function does not reconcile the three quantities.

### Extension without replacement

With capacity 8 and the second descriptor pointing to slot 5:

- The calculated final slot is slot 7, so extension is selected.
- Slot 6 receives the new block pointer.
- The second descriptor’s slot word identifies slot 6 before the descriptor dependency.
- That dependency receives the block base and slot 6 address.
- Its result replaces only the second descriptor through direct descriptor writes.
- No table allocation or F-ff1bdc376dcd call occurs.

### Replacement that increases capacity

With a six-slot table and an active range spanning slots 2–5, \(n=4\):

- The replacement request is 32 bytes, representing eight slots.
- Existing pointers move to replacement slots 2–5.
- Replacement slot 6 receives the new block pointer.
- F-ff1bdc376dcd is called after copying and before publication of the replacement base.
- Both descriptors are rebuilt.
- Capacity becomes 8 after descriptor publication.

### Replacement that decreases capacity

With an eight-slot table and an active range spanning slots 6–7, \(n=2\):

- The branch still selects replacement because slot 7 is the final slot.
- The request is 16 bytes, representing four slots.
- Existing pointers move to replacement slots 1–2.
- Slot 3 receives the new block pointer.
- Final capacity is 4, smaller than the previous capacity of 8.

### Allocation changes the copy boundary

Start with the preceding eight-slot configuration, but let the replacement allocation dependency change the first descriptor’s slot address from slot 6 to slot 5, leaving the final slot at 7.

Then:

- The retained sizing count remains \(n=2\).
- The replacement request remains 16 bytes.
- The post-allocation copy reads three pointers, from old slots 5–7, into replacement slots 1–3.
- The retained append calculation still selects replacement slot 3.
- The new block-pointer write overwrites the last copied pointer.
- Final capacity remains 4.

The append position does not move to follow the changed copy range.

### Invalid address unequal to the final slot

An invalid second-descriptor slot address that differs from the calculated final slot selects extension, not rejection. The function advances it and uses the result for a write. No safe outcome is promised.
