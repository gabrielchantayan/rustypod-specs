# F-ef7568180f91

## Purpose

F-ef7568180f91 describes an indefinitely repeating sequence of indirect calls, byte accesses, and 32-bit memory accesses. Its visible behavior is dominated by values returned from unresolved dependencies and by execution state not represented in its four-argument interface.

The supplied representation establishes no higher-level purpose such as allocation, serialization, device control, or object construction. Repeated offsets and shifts suggest structured state manipulation, but assigning a particular data model would be inferred intent rather than an established contract.

There is no visible normal return, termination condition, validation path, or error result. Completion of one repetition leads directly into the next repetition with updated carried state.

This is a static, conditional contract. It describes the visible operations if execution reaches them and dependencies return normally. It does not establish that the represented entry state is valid, that all indirect calls are executable, or that any complete repetition can occur.

### Memory widths and notation

The visible direct accesses are:

- Unsigned one-byte reads.
- One-byte writes.
- Four-byte reads and writes.

The following mathematical names describe observed values, not source-level objects:

- \(L_n(x)\): the low 32 bits of \(x\) shifted left by \(n\), under a 32-bit bit-vector interpretation.
- \(E(x)\): \((x \mathbin{\&} \text{0x3fffffff}) \gg 20\).
- \(P(x)\): \(L_{28}(x \gg 22)\), with an unsigned right shift.

A byte write retains only the low eight bits of its supplied value. Consequently, writing \(E(x)\) as a byte retains bits 20–27 of \(x\); the intermediate expression can contain ten bits.

These equations describe the apparent fixed-width transformations. The exact machine semantics of signed shifts, overflowing signed multiplication, and address calculation require confirmation beyond the supplied representation.

## Behavior

### Execution and ordering

Every visible repetition has the following order:

1. Store the current carried word.
2. Perform an initial call-and-selector sequence.
3. Perform several dependency-driven word stores.
4. Clear and rewrite selector-related bytes.
5. Read a selected 32-bit word and a shared 32-bit value.
6. Perform a second call-and-selector sequence.
7. Derive and install the next repetition’s state.
8. Continue unconditionally.

There is no direct comparison, conditional branch, bounds check, null check, retry condition, or explicit error branch in this sequence.

Calls remain observable even when their results are ignored. A run of result-ignored calls must not be removed from the behavioral contract: those calls may change memory, shared state, or the conditions under which later operations execute.

### Initial carried-state store and selector update

The first direct operation writes the carried 32-bit word at offset `0x14` from the incoming store base. This occurs before the first dependency call.

The first indirect call receives the current first argument. Three further calls follow before a fifth call produces a 32-bit result. Call this result the **first index**, and call its fourfold value the **first scaled index**.

Next:

- An unsigned byte is read at offset 1 from the incoming selector base.
- That byte is used directly as an address component.
- A byte is written at address `0x11` plus that selector.
- The byte value is the truncated \(E\) field of the current fourth argument.

This is not visibly a base-relative access into the selector-bearing object. The zero-extended byte itself determines an address between `0x11` and `0x110`.

Subsequent calls receive, in order, the carried word shifted left by 12, a dependency-produced 32-bit value paired with the first index shifted left by 30, and the low and high 32-bit halves of a dependency-produced 64-bit value.

After additional intervening calls, a dependency supplies a new 32-bit result. Before that result, shifted left by two, is passed onward, the selector byte at the incoming selector base plus 1 is read again and the corresponding selected byte is cleared.

The second selector read is distinct from the first. Any dependency that executes between them may have changed the selector.

### First group of word stores

The next portion contains six dependency-driven 32-bit stores. Their order and address relationships are significant.

| Order | Address | Stored value |
|---|---|---|
| 1 | `0x14` plus the first scaled index multiplied by `0x1000` | Four times a newly returned dependency result |
| 2 | `0x14` plus four times a later returned index | The same value as store 1 |
| 3 | `0x14` plus sixteen times a newly returned index | Four times that new index |
| 4 | `0x14` plus four times a later returned index | The same value as store 3 |
| 5 | `0x14` plus sixteen times a newly returned index | Four times that new index |
| 6 | `0x14` plus four times a later returned index | The same value as store 5 |

Dependencies execute between these stores.

After store 1, one call receives four arguments: twice the first scaled index multiplied by `0x400`, the first index shifted left by 14, and the stored value.

After stores 3 and 5, a call receives three identical arguments, each equal to that store’s value. Other intervening calls receive a fourfold index or have no explicit arguments in the supplied representation.

The index used for store 5 also determines a **byte-region base** by multiplication by `0x40000000`. Under 32-bit bit-vector arithmetic, only the index’s low two bits survive this calculation.

### Repeated byte clears and selected-word read

After store 6, a dependency returns another 32-bit value, the **lookup token**.

Two direct byte writes then occur:

1. Zero at the byte-region base plus `0x11`.
2. Zero at the byte-region base plus 1.

A call receives four times the lookup token. Further calls include a 32-bit result forwarded to another dependency. A later dependency result is multiplied by four and passed onward, but only after the same two byte locations have been cleared again, in the same order.

These repeated clears are separate writes. Intervening calls prevent treating them as redundant.

A later dependency supplies an index for a 32-bit store at `0x14` plus sixteen times that index. The value stored is an earlier index shifted left by 31. Under the bit-vector interpretation, the result is either zero or `0x80000000`.

Only after this store does the function perform a direct 32-bit read at:

\[
\text{0x14} + E(\text{lookup token})
\]

The possible starting addresses are `0x14` through `0x413`. No alignment rounding is visible.

The function then:

- Passes four times the latest index to a dependency.
- Captures a later dependency result for use substantially later in the repetition.
- Passes \(P\) of the selected 32-bit word to a dependency.

Under the bit-vector interpretation, \(P\) retains only bits 22–25 of the selected word and places them in bits 28–31.

### Selector rewrites and shared-state capture

A subsequent dependency-provided index determines a 32-bit zero store at `0x14` plus four times that index. A following call receives that fourfold index.

A later dependency result, the **selector payload**, drives several operations:

1. Read the unsigned byte at byte-region base plus 1.
2. Write the low byte of four times the selector payload at `0x11` plus that selector.
3. Pass four times the selector payload to a dependency.
4. Pass a dependency-produced 32-bit value and the selector payload shifted left by 30 to another dependency.
5. After intervening calls, read the selector at byte-region base plus 1 again.
6. Write the truncated \(E\) field of the selector payload at `0x11` plus the newly read selector.
7. After further calls, write four times the previously captured dependency result as a 32-bit word at `0x14` plus that same saved selector.

The selector used for the last word store is the value saved in step 5. It is not reread immediately before the word store.

The next direct read obtains a shared 32-bit value from a fixed storage location. Its semantics and ownership are unknown. This read occurs after the selector-based word store and before the following call sequence. The shared value must not be assumed equal to any earlier observation of that storage.

### Second call-and-selector sequence

A dependency subsequently returns a 64-bit result. Its low half, multiplied by four, becomes the **second scaled index**.

The function rereads the selector at byte-region base plus 1 and writes the low byte of the captured shared value shifted right by 22 to the selected byte location. This write retains bits 22–29 of the shared value.

The high half of the 64-bit result is passed to a dependency. Further calls include a pair consisting of a dependency result and the second scaled index shifted left by 28.

After more calls, the selector is reread and its selected byte is cleared.

A later dependency result, multiplied by four, is passed twice to one call. Subsequent calls produce a **second carried word**, equal to four times a returned 32-bit result. That word is stored at:

- `0x14` plus the second scaled index multiplied by `0x1000`.
- Later, `0x14` plus four times another dependency-provided index.

A call between those stores receives the second scaled index shifted left by 14.

Another dependency produces a 64-bit result. Its low half, multiplied by four, becomes the **final scaled index**. Before its high half is passed onward, the function:

- Reads a selector byte at offset 1 from the second scaled index multiplied by `0x4000`.
- Writes the truncated \(E\) field of the second carried word to `0x11` plus that selector.

A later 64-bit result has both halves passed together to another dependency.

### Final clears and next-repetition state

The remaining selector clears occur at three distinct points:

- Using a selector read from offset 1 of the final scaled index multiplied by `0x10000000`.
- Using a selector read from offset 1 of four times the final scaled index.
- Again using a fresh selector read from that latter location, after intervening calls.

Each selected byte is written as zero.

Between these clears, dependencies receive values including:

- A returned result shifted left by two.
- The final scaled index shifted left by 10.
- A dependency result paired with the earlier captured result shifted left by 28.

A dependency result obtained in this portion determines the **next carried word** by a left shift of 14. That word is written at `0x14` plus its fourfold, unshifted precursor multiplied by `0x1000`.

The next carried word becomes both the carried word and the fourth explicit argument for the next repetition. A subsequent call receives the fourfold precursor shifted left by 14.

Another call receives the next carried word shifted left by 28 together with the insufficiently specified register-derived value. Under 32-bit bit-vector arithmetic, that first argument is necessarily zero: the next carried word already has its low 14 bits clear.

Finally, a dependency returns a 32-bit result that is shifted left by two. This becomes both:

- The next repetition’s first explicit argument.
- The next repetition’s initial store base.

The next selector base is four times the final scaled index. The first-call target state is also replaced with a fixed value established by the visible sequence. Execution then repeats without a visible exit test.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Early field truncation.** If the fourth argument is `0x3ff00000`, the early field expression is `0x3ff`; the byte written is `0xff`, assuming execution reaches the write.

2. **Changing selector.** If the initial selector read yields 7 and a dependency changes it to 9 before the clearing read, the first selected write targets `0x18`, while the later clear targets `0x1a`.

3. **Unaligned selected read.** If the lookup token is `0x00100000`, the selected word read begins at `0x15`. The contract does not round it down to `0x14`.

4. **High-bit word.** If the index feeding the shift-by-31 store is odd, its stored bit-vector value is `0x80000000`; if even, it is zero.

5. **Saved selector.** If the selector saved before the late word store is 5, that store targets `0x19` even if an intervening dependency changes the selector-bearing memory.

6. **Next-state field.** Under 32-bit bit-vector arithmetic, shifting the next carried word left by 28 produces zero regardless of the dependency result from which that word was derived.

7. **No completed repetition.** If the first dependency never returns, the initial carried-word store has occurred, but none of the subsequent direct accesses is reached.
