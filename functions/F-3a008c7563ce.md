# F-3a008c7563ce

## Purpose

F-3a008c7563ce adjusts a requested pair of signed displacements against two four-component coordinate records, conditionally invokes an operation with those adjusted displacements, and reports a four-bit relationship between a subsequently obtained coordinate record and the object’s current stored limits.

The supplied static evidence establishes the calculations and call ordering. It does not establish that the records are rectangles, that the requested operation actually moves anything, or that the final reporting dependency publishes a particular kind of event.

**Inferred intent:** the function appears to adjust movement against spatial limits and then report which sides remain outside those limits. This interpretation must not replace the actual arithmetic. In particular, one adjustment branch uses a difference from the other coordinate axis.

## Behavior

### 1. Capture the initial stored limits

The function first reads the object’s four coordinate fields, in increasing offset order: `0x80`, `0x84`, `0x88`, then `0x8c`.

These values form the **initial limits**. Later dependency calls do not cause this initial snapshot to be refreshed for the displacement calculations.

There is no evidence that these four reads are atomic as a group.

### 2. Obtain and transform an initial coordinate record

The function calls F-756b664b4a2c with the object and the address of a local four-component record.

It then calls F-d156b0b83eb3 with:

1. The address of that same record.
2. The original first displacement.
3. The original second displacement.

The four components present after F-d156b0b83eb3 returns are the **transformed coordinates** used in the adjustment calculations.

The output record has four consecutive signed 32-bit components, at relative byte offsets 0, 4, 8, and 12.

The supplied evidence does not establish whether either dependency changes the object or any global state. The initial limits nevertheless remain the values read before both calls.

### 3. Form coordinate differences

Define four signed differences:

- **Left difference:** initial left limit minus transformed left coordinate.
- **Top difference:** initial top limit minus transformed top coordinate.
- **Right difference:** initial right limit minus transformed right coordinate.
- **Bottom difference:** initial bottom limit minus transformed bottom coordinate.

The horizontal width comparison used below compares:

- Transformed right minus transformed left.
- Initial right limit minus initial left limit.

These subtractions are also performed at the recovered signed integer width. Overflow behavior is not established.

The first displacement is not modified until after the second-displacement adjustment has been selected.

### 4. Adjust the second displacement

The function selects a horizontal correction as follows:

| Condition | Correction added to the second displacement |
|---|---|
| Left difference is negative; right difference is zero or positive | Left difference |
| Both differences are negative, and transformed width is less than initial-limit width | Smaller of the left and right differences |
| Both differences are negative, and transformed width is not less than initial-limit width | Larger of the left and right differences |
| Left difference is zero or positive; right difference is positive | Smaller of the left and right differences |
| Left difference is zero or positive; right difference is zero or negative | Zero |

The width comparison in this table is a strict signed comparison.

When all relevant subtractions are mathematically representable, the two “both negative” cases both produce the left difference. Their expanded form is retained here because the supplied control flow explicitly performs a width comparison; treating all arithmetic as unbounded would conceal the overflow uncertainty.

No conventional “keep the rectangle inside the bounds” rule should be substituted for these cases. For example, transformed coordinates strictly inside the initial limits can still produce negative corrections.

### 5. Adjust the first displacement

The function selects the other correction as follows:

| Condition | Correction added to the first displacement |
|---|---|
| Top difference is negative; bottom difference is zero or positive | Top difference |
| Top and bottom differences are both negative | Larger of the **right difference** and the top difference |
| Top difference is zero or positive; bottom difference is positive | Smaller of the top and bottom differences |
| Top difference is zero or positive; bottom difference is zero or negative | Zero |

The use of the **right difference** in the second row is established by the supplied static evidence. It is not the bottom difference.

Consequently:

- A positive right difference can produce a positive first-displacement correction even when both top and bottom differences are negative.
- Changing the transformed right coordinate can change the first-displacement correction.
- The cross-axis calculation uses the previously computed right difference, not the adjusted second displacement.

Whether this behavior is intentional is unknown.

### 6. Conditionally perform the requested operation

The condition is evaluated using the **adjusted** displacements.

If both adjusted displacements are zero, the function skips all temporary-context calls and skips F-66a173856508.

If either adjusted displacement is nonzero, the function performs these calls in order:

1. F-538044b67754 receives a local 20-byte temporary area, the object address plus `0xa8`, and the 32-bit value `0xfffffffe`.
2. F-6e4651b532dc receives that temporary area and an output address for a four-byte value.
3. F-66a173856508 receives the object, adjusted first displacement, adjusted second displacement, original auxiliary word, and extracted four-byte value.
4. F-944b595e25e9 receives the temporary area.

The bit pattern `0xfffffffe` is −2 under signed 32-bit interpretation. Its semantic meaning is unknown.

The four-byte extracted value has no visible initialization before F-6e4651b532dc. Normal defined behavior therefore depends on that dependency producing a usable value.

The final temporary-context call occurs only after F-66a173856508 returns normally. The excerpt contains no visible exceptional cleanup or recovery path.

### 7. Obtain final coordinates and current limits

Regardless of whether the conditional operation ran, the function calls F-756b664b4a2c again, using a separate local four-component output record.

Only after that call returns does the function reread the object fields at `0x80`, `0x84`, `0x88`, and `0x8c`, in that order.

These are the **final limits**. They are not necessarily equal to the initial limits. Any earlier dependency, including the second coordinate-query call itself, could have changed the object.

The final coordinate record is not passed through F-d156b0b83eb3.

### 8. Compute and report the final mask

The function constructs an eight-bit mask from four strict signed comparisons:

| Bit value | Set when |
|---|---|
| `0x01` | Final left coordinate is less than the final left limit |
| `0x02` | Final right coordinate is greater than the final right limit |
| `0x04` | Final top coordinate is less than the final top limit |
| `0x08` | Final bottom coordinate is greater than the final bottom limit |

Equality does not set a bit.

Only the low four bits are produced, so the numeric mask is between 0 and 15 inclusive. The comparisons are evaluated in left, top, right, bottom order.

The function calls F-1cf78c395e57 once with this mask on every normally completed path, including paths where no conditional operation was performed. It then returns without an explicit result.

## Acceptance examples

These are conditional acceptance examples derived from static evidence. They are not runtime observations. Assume signed 32-bit values, no arithmetic overflow, initialized dependency outputs, and normal returns.

### Zero adjusted request skips the conditional operation

Initial limits and transformed coordinates are both `(0, 0, 100, 100)`. Both original displacements are zero.

All differences and corrections are zero. The temporary-context sequence and F-66a173856508 are skipped.

The final coordinate query and mask report still occur.

### An original zero request can become nonzero

Initial limits are `(0, 0, 100, 100)`. Transformed coordinates are `(10, 20, 90, 80)`. Both original displacements are zero.

The differences are:

- Left: −10.
- Top: −20.
- Right: +10.
- Bottom: +20.

The adjusted first displacement is −20; the adjusted second displacement is −10. The conditional-operation sequence runs with those values.

### A nonzero request can be canceled

Use the same limits and transformed coordinates, but original first displacement 20 and original second displacement 10.

The corrections cancel both original displacements. The conditional operation is skipped even though the original request was nonzero.

### Opposite-sign differences can leave the request unchanged

Initial limits are `(0, 0, 100, 100)`. Transformed coordinates are `(-10, -20, 110, 120)`.

The left and top differences are positive; the right and bottom differences are negative. Both corrections are zero.

The conditional-operation decision therefore depends only on whether either original displacement is nonzero.

### The cross-axis branch can reverse the expected correction direction

Initial limits are `(0, 0, 100, 100)`. Transformed coordinates are `(10, 20, 80, 120)`. Both original displacements are zero.

The top and bottom differences are both −20, while the right difference is +20.

The first-displacement correction is the larger of +20 and −20: **+20**. The second-displacement correction is −10.

F-66a173856508 therefore receives adjusted displacements `(20, −10)`. Replacing the first correction with −20 would violate the supplied behavior.

### Final reporting uses newly read limits

Suppose an earlier dependency changes the object’s coordinate fields. The final comparisons must use the values read after the second F-756b664b4a2c call, not the initial snapshot.

This remains true when the conditional operation was skipped.

### Final mask boundaries are strict

With final limits `(0, 0, 100, 100)`:

- Final coordinates `(0, 0, 100, 100)` produce mask `0`.
- Final coordinates `(-1, -2, 101, 102)` produce mask `15`.
- Final coordinates `(-1, 0, 100, 101)` produce mask `9`.
