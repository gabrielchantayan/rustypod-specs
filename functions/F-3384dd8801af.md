# F-3384dd8801af

## Purpose

F-3384dd8801af performs an ordered sequence of indirect dependency calls, byte-selector updates, word stores, dependent memory reads, and global assignments. Its final visible actions include a byte clear, a composite global assignment, a halfword clear, and an attempted call through address zero.

No application-level purpose is established. The evidence does not justify classifying the routine as initialization, allocation, serialization, dispatch, or cleanup.

This contract separates:

- **Established static evidence:** explicit operations, widths, value dependencies, and ordering in the supplied representation.
- **Inferred intent:** possible interpretations, not behavioral requirements.
- **documented_only:** unresolved behavior for which the available evidence is insufficient.

Every operation is conditional on execution reaching it. A dependency may fault, modify memory, transfer control elsewhere, or never return.

## Behavior

### Ordering model

The visible body contains no explicit loop or conditional branch. It is a long, ordered path contingent on returning dependencies and successful memory accesses.

Calls with no explicit arguments remain observable and cannot be discarded as inert. Each selector update includes a fresh selector read. Intervening dependencies may change selector bytes, globals, or pointed-to memory; repeated expressions do not establish repeated values.

Saved values and fresh memory reads must be distinguished. A saved address remains derived from its captured value, even if a dependency later changes the global from which it originated. Memory at that saved address may nevertheless change.

### Entry and early selector updates

Before any dependency call, the routine reads the selector at the incoming address plus one and stores the first input’s low byte at the selected destination.

It then invokes F-000000000001 with the full first input and proceeds through position-derived calls in F-000000000002.

After the first call group, it reads a selector at the fourth input’s unsigned right shift by 19, plus one, and clears the selected byte.

Early call groups forward results multiplied by four. Argument arrangements include a single scaled result, zero followed by a scaled result, and duplicated secondary results followed by zero. The byte at address one also serves repeatedly as a selector source.

### Byte forwarding and early packed results

### First word-slot sequence: distinct result generations

## Acceptance examples

These examples are conditional static criteria, not executed tests.

- **Initial truncation:** With first input 0x123456AB and initial selector five, the initial byte write stores 0xAB at address 22 before F-000000000001.

- **Unsigned input shift:** With fourth input 0xFFFFFFFF, the early selector-read address is 8,192, not an address produced by sign extension.

- **Different result generations:** If the earlier unsigned result is 0x00040000, its two selector clears read selectors at address 1,025. If the newer unsigned result is 0x00080000, the word read after the self-indexed store uses address 2,068, not 1,044. That word is then shifted right by 19 for the dependency argument.

- **Fresh selectors:** If a dependency changes a selector from three to seven, otherwise similar selector updates target addresses 20 and 24 respectively.

- **Byte-field replacement:** If both offset-13 stores are reached, the second stores four. The earlier store remains observable before intervening calls.

- **High-bit offset:** Under 32-bit bitvector arithmetic, bit 19 clear selects offset zero for the described saved-word read; bit 19 set selects offset 0x80000000.

- **Global mutation versus saved address:** If the terminal capture of Global A yields 0x1000, and intervening calls change Global A to 0x2000, the dependent word read still uses 0x1014. If those calls change the word at 0x1014, the read can observe that changed word.

- **Low-byte copy:** An offset-116 word value of 0xA1B2C3D4 causes its associated base-plus-one byte store to write 0xD4.

- **No guaranteed final clearing:** Dependencies may overwrite previously cleared storage. A final state in which every earlier selector destination is zero is not required.

- **Terminal failure ordering:** If address zero is not callable, the attempted transfer occurs after the final byte clear, composite assignment, and halfword clear, provided those operations completed.
