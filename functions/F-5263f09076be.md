# F-5263f09076be

1. Read a designated external 32-bit datum and copy it into the first four bytes of caller-supplied storage.
2. Call F-77e4bfecf7cf with an address 24 bytes beyond the supplied base.
3. Use the dependency’s returned value as an address and write six consecutive 32-bit zeros, beginning four bytes beyond that address.

## Behavior

### Established sequence

The supplied static representation establishes this order:

1. Read the external 32-bit datum and store that value at B.
2. Invoke F-77e4bfecf7cf once, passing B + 24.
3. If the call returns normally, perform six 32-bit zero stores in ascending destination order: R + 4, R + 8, R + 12, R + 16, R + 20, and R + 24.
4. Return without an explicit result.

There are no visible branches, loops, retries, validation steps, or alternative success paths.

The initial write precedes the dependency invocation. The dependency may therefore observe that write if it accesses the affected storage. This does not establish that it reads the field or preserves its contents.

All six zero stores follow the dependency call. If that call does not return normally, none of those stores is reached through the visible sequence.

The external datum is not reread after the call. A dependency-side change to the datum does not cause another copied-value store.

### Direct-write footprint and exclusions

The combined direct-write footprint is the union of:

- B through B + 3.
- R + 4 through R + 27.

No relationship between these regions is guaranteed. They may be separate, adjacent, or overlapping.

The **six post-call zero stores**, considered independently of the initial store:

- Do not write R through R + 3.
- Do not write beyond R + 27.
- Do not clear an entire caller-supplied region merely because the dependency receives B + 24.

These are not exclusions from the function’s combined direct-write footprint. For example:

- If B equals R, the initial store directly writes the four-byte field at R.
- If B lies beyond R + 27, the initial store directly writes memory beyond the zero-store range.
- If a zero-store destination overlaps B + 4 through B + 23, those bytes can be directly zeroed despite lying before the dependency argument.

The dependency may additionally write any of these locations or other storage. Its effects are separate from the function’s seven explicit stores.

### Aliasing and read behavior

No alias check or disjointness guarantee is visible.

If a later zero store overlaps the initial destination, the later store replaces the overlapping bytes. The copied value is not restored afterward. Partial overlaps likewise follow the visible write order, subject to the execution environment’s rules for the relevant accesses.

Each of the six zero-store operations writes a zero value without an explicit destination read or read-modify-write operation.

That does **not** establish that the destination storage was never read earlier by this function. The initial external-datum read may access storage that later becomes a zero-store destination. The dependency may also read or write that storage.
