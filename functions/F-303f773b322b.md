## Behavior

### Source-word capture

The function reads the three source words in first, second, third order and saves each in its corresponding local word position.

These are separate reads. No synchronization, atomic snapshot, or consistency check is shown. If another actor can change the source locations during capture, the resulting triple need not represent one simultaneous external state.

The subsequent transformations use the saved local copies. No direct write back to the three source locations is shown.

### Independent unsigned transformation

After capturing all three values, the function transforms the local words in reverse positional order:

1. Third word.
2. Second word.
3. First word.

Each transformation is a logical right shift of a 32-bit unsigned value by one bit. For an input \(x\), the result is \(\lfloor x/2 \rfloor\).

Consequences include:

- The original least significant bit is discarded.
- The new most significant bit is zero.
- Sign extension does not occur.
- Each result lies between 0 and 0x7FFFFFFF.
- No bit is transferred between words.

This is three independent word transformations, not one shift of a 96-bit aggregate.

The recovered local layout and traversal support exactly these three word positions. They do not support extending the transformation into the trailing storage or workspace.

### Following-byte initialization

After completing all three shifts, the function writes zero to the byte immediately following the third word, at prepared-region offset 12.

It does not visibly clear the remaining seven bytes of the trailing area or initialize the workspace.

The zero is compatible with a terminator-like role, but terminator semantics are not established. The prepared words may themselves contain zero bytes. Therefore, neither a fixed-length binary format nor a zero-terminated text format can be guaranteed from this caller alone.
