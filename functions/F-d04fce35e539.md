# F-d04fce35e539

## Purpose

F-d04fce35e539 conditionally copies an unsigned 16-bit memory value, may perform a second 16-bit write whose destination comes from memory contents, and then enters a repeating dispatch sequence containing two calls and software interrupt 0x5B.

No application-level purpose is established. The effective interface consists of incoming machine state and accessible memory, not a verified parameterless calling convention.

Under the supplied representation’s 32-bit arithmetic model, the conditional arithmetic and store blocks after the content-addressed write are unreachable. They do not contribute reachable memory effects or change the dispatch base.

## Behavior

### Initial selection and ordered transfer

The initial derived address is the low 32 bits of the control word multiplied by 2²¹. The initial carry-like condition reflects control-word bit 9.

The derived address is zero exactly when the control word’s low 11 bits are zero. A nonzero control word can therefore select the transfer.

If the derived address is nonzero, the initial transfer and the later conditional update are skipped. Execution reaches dispatch with the incoming link address as its base.

If the derived address is zero, the represented progression has this order:

1. Calculate the stack/link-derived address: the link address plus the initial carry-like bit plus the stack reference logically shifted right by one.
2. Calculate the doubled-control address: the low 32 bits of the control word multiplied by 2²².
3. Calculate the transfer destination: the original source address plus the offset word, modulo 2³².
4. Read an unsigned 16-bit value at the original source address.
5. Replace the tracked source address with the transfer destination minus the adjustment word, modulo 2³².
6. Write the previously read 16-bit value at the transfer destination.
7. Select the incoming link address as the value used by the next gate.

Thus all three address calculations precede the initial memory read. The tracked-source replacement occurs **after that read but before the destination write**.

This ordering matters for partial progress. If the source read faults, the preceding address calculations have occurred, but the tracked-source replacement and destination write have not. If the destination write faults, the tracked-source replacement has already occurred in the represented sequence. Whether any internal value is recoverable or externally inspectable after a fault is **documented_only**; this ordering does not establish an exception ABI.

The read value is captured before the write. Coincident or overlapping source and destination addresses do not suppress either selected access. The transfer destination remains the previously calculated address; replacing the tracked source does not redirect the pending store.

Entry into this branch establishes that control-word bit 9 is zero. Both control-derived addresses are also zero.

### Gates preceding the content-addressed update

Progress beyond the initial transfer requires the incoming link address to be zero.

Subsequent gates form a dependent chain. Failure of a predecessor prevents later gates from independently restarting progression.

Several stages obtain a shift count from the low eight bits of the preceding result. Each executed stage requires that preceding result to be zero. Those executed shifts consequently have count zero, and the relevant exclusive-or conditions reduce to equalities.

Under the 32-bit model, the content-addressed update requires all of these conditions:

- The control word’s low 11 bits are zero.
- The incoming link address is zero.
- The stack/link-derived address is zero.
- The auxiliary word equals the offset word.
- The replaced tracked source address equals the adjustment word.
- The accumulator word is zero.
- The stack reference plus twice the offset word is zero modulo 2³².

The source equality can also be expressed as twice the adjustment word equaling the original source address plus the offset word, modulo 2³².

Because the link and initial carry-like bit are zero, the stack/link-derived condition requires the stack reference logically shifted right by one to be zero. The stack reference is therefore either 0 or 1.

The final addition excludes 1: twice a 32-bit word is even, so adding 1 cannot produce zero modulo 2³². Consequently, reaching the update requires:

- Stack reference 0.
- Offset word either 0 or 0x80000000.
- Auxiliary word equal to that offset.

The masked control contribution and incoming carry-like contribution to the accumulator gate are zero on this path. Its zero-result condition therefore requires accumulator word 0 and leaves no outgoing carry contribution to the final addition.

These are numeric reachability conditions. They do not establish that an ordinary execution environment permits a zero stack reference.

### Content-addressed 16-bit update

When all gates succeed, the represented sequence:

- Assigns the special register-like state the stack reference multiplied by 64.
- Calculates a replacement link address equal to the old link address plus 64 times the stack reference, in bytes.
- Evaluates the old link address’s unsigned 16-bit contents to determine a write destination and a stored value.
- Performs the resulting 16-bit write.
- Advances the initial derived 16-bit-element pointer by one element.
- Clears the tracked carry-like state.
- Adopts the replacement link address.

On every reachable entry to this block, the old link address and stack reference are zero. The special-state assignment and replacement link address are consequently zero. The advanced derived pointer becomes address 2.

For stable ordinary memory, let \(x\) be the unsigned 16-bit value read at the old link address. The write stores

\[
(x+15)\bmod 2^{16}
\]

at address \(x\), with \(x\) zero-extended to the address width. The destination is determined by the **contents** at the old link address; it is not necessarily the old link address itself.

The destination expression and stored-value expression separately depend on those contents. Their relative evaluation order and physical load count are not established for externally changing memory. If separate evaluations observe different values, the value selecting the destination need not equal the value used in the addition.

The reads required to determine the destination and value precede the resulting write. The special-state assignment and replacement-link calculation precede these memory operations. A fault during them can prevent the later derived-pointer advance, carry clearing, and adoption of the replacement link.

The earlier initial transfer can affect this update through aliasing. In particular, the contents observed at address zero are those available after the initial transfer, not necessarily the contents present on entry.

### Exclusion of the later conditional blocks

Only successful entry into the content-addressed update can enable the following gate chain.

At that point, the initial derived address and stack/link-derived address are both zero. The update changes the derived pointer used by the second comparison to address 2 and leaves the replacement link address zero.

The first post-update exclusive-or result is therefore zero. The next compares the advanced pointer value 2 with the zero stack/link-derived address, producing 2. That nonzero result closes the chain.

If the update is skipped, the enabling condition remains false. No subsequent gate independently reopens the chain.

Accordingly, all later conditional arithmetic and store blocks before dispatch are unreachable under the stated model. This conclusion does not depend on finding or excluding additional unusual memory contents.

### Transfer ordering and a destination fault

Assume control word 0, original source address 0x200, offset word 0x10, adjustment word 0x100, and nonzero link address.

The stack/link-derived address, doubled-control address, and destination 0x210 are calculated before reading address 0x200. If that read succeeds, the tracked source becomes 0x110 before the attempted store at 0x210.

If the store faults, the represented tracked-source replacement has already occurred. Dispatch is not reached through the shown continuation. External observation of that internal value remains unspecified.

If the store succeeds, the nonzero-link gate blocks the deeper update, and dispatch uses the incoming link address.

### Stack reference blocking the update

With a zero initial derived address, zero link address, and stack reference 0x1000, the stack/link-derived address is 0x800.

The initial transfer still occurs. The deeper gates close, so the content-addressed update and all later conditional stores do not occur.

### Numerically reachable content-addressed update

Assume:

- Control, auxiliary, offset, accumulator, link, and stack-reference values are zero.
- Original source address is 0x200.
- Adjustment word is 0x100.
- Address zero contains stable unsigned 16-bit value 0x0040.
- All selected accesses and the first dispatch target are permitted.

The initial transfer destination is 0x200. After reading there, the tracked source becomes 0x100; only then is the captured value written back at 0x200.

The derived pointer becomes address 2. The next two enabled exclusive-or results are zero and 2, closing the remaining conditional region. The first dispatch target is 0xEB6.
