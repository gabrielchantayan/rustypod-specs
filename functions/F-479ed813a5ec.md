# F-479ed813a5ec

## Purpose

F-479ed813a5ec traverses a two-level collection and makes two ordered destination calls for each processed inner entry. One destination is embedded in the caller-supplied object. The other is embedded in an object selected once for each processed outer entry.

An initially empty outer collection takes a path identified by the supplied static evidence as non-returning. An empty inner collection is permitted: destination selection and inner initialization still occur, followed by inner finalization, but no payload calls occur for that outer entry.

“Collection,” “selection,” “destination,” and “payload” describe inferred roles. The established behavior consists of memory accesses, dependency calls, arithmetic, comparisons, and explicit finalization order. The body does not establish that destination calls insert, copy, transfer ownership, or retain anything successfully.

Both loops have finite arithmetic limits, even when their queried bounds change. This does not guarantee function completion: dependencies may fail to return, the initial empty path is designated non-returning, and invalid storage or unsupported indices may prevent defined execution.

## Interface

The function accepts one 32-bit address-valued argument identifying a caller-supplied object. It exposes no result value. On the normal path, it returns after finalizing the outer collection.

The body performs no explicit null checks, storage-bounds checks, or recoverable error reporting. Defined execution requires valid storage for every direct access and dependency results suitable for their subsequent uses.

### Outer condition, counter, and index conversion

The outer counter starts at zero. Before every possible iteration, including the first, F-d0b90560f1fd queries the outer collection again. The current counter and returned bound are compared as unsigned 32-bit values. An iteration proceeds only when the counter is strictly less than the bound.

The initial nonempty query is not a saved iteration bound. Later results can shorten or extend traversal.

For outer indexed access through F-0ff4e60503e7, the counter is narrowed to its low 16 bits and interpreted as signed:

| Unsigned outer counter | Supplied index |
|---|---|
| 32767 | 32767 |
| 32768 | −32768 |
| 65535 | −1 |
| 65536 | 0 |

This conversion affects the supplied index, not the stored counter. Thus indexed access can receive negative and repeated indices even while the outer counter increases.

After an outer entry’s inner collection is finalized, the outer counter advances by unsigned 32-bit addition.

The largest possible bound is 4294967295. When the counter reaches that same value, its strict comparison fails for every possible bound. Consequently, assuming dependency calls return and execution remains defined, the outer loop executes at most **4,294,967,295 iterations**. It cannot execute an iteration at counter value 4294967295 or wrap back to zero during traversal. Changing query results alone cannot make this loop infinite.

### Inner condition and payload processing

The inner counter starts at zero. Before every possible iteration, F-d0b90560f1fd queries the inner collection. The counter and returned bound are compared as unsigned 32-bit values. The iteration proceeds only if the counter is strictly less than the bound.

Each entered iteration performs these operations in order:

1. F-0ff4e60503e7 receives the inner work area and current counter representation.
2. A 32-bit value is read from offset +8 of the returned entry and written into the payload slot.
3. F-4e08ae872034 receives caller-object offset +16 and the payload-slot address.
4. F-4e08ae872034 receives selected-object offset +20 and the same payload-slot address.

The caller-object destination call precedes the selected-object destination call. No explicit result check or conditional branch separates them.

The payload is not reloaded from the inner entry between the calls. If the first call modifies the slot, the second receives that same slot with its modified contents. The function does not restore the original value.

Selection occurs once per outer entry, not once per payload. All inner iterations for that entry use the captured selected-object address.

### Inner counter arithmetic and termination limit

After a completed inner iteration, the incremented counter is reduced to its low 16 bits and sign-extended to a 32-bit representation. Loop comparison nevertheless remains unsigned.

The reachable counter sequence is:

- 0 through 32767;
- then 4294934528 through 4294967295, representing signed values −32768 through −1.

In particular, the increment following counter 32767 produces `0xffff8000`, whose unsigned value is 4294934528. It does not produce positive 32768.

For a stable bound of 32769, indices 0 through 32767 are processed. The next comparison fails because 4294934528 is not less than 32769.

Larger bounds can admit counter representations corresponding to negative signed-16-bit values. Unlike outer indexed access, the inner call site applies no additional explicit narrowing conversion to the current counter.

The terminal representation `0xffffffff` is unsigned 4294967295. No unsigned 32-bit bound is larger. Therefore, if traversal reaches that counter, the condition necessarily fails before another inner iteration.

The inner loop can execute at most **65,535 iterations**: 32,768 iterations for counters 0 through 32767, followed by at most 32,767 iterations for representations `0xffff8000` through `0xfffffffe`. It cannot execute an iteration at `0xffffffff` or increment that value back to zero during traversal.

This limit holds even if query results change on every condition check, provided dependencies return and execution remains defined. Changing bounds alone cannot make the inner loop infinite.

### Finalization and normal return

When an inner condition fails, F-3a8de16627bf finalizes the inner work area. Only afterward does the outer counter advance.

When the outer condition fails, F-3a8de16627bf finalizes the outer work area, and the function returns.

An inner collection whose first query returns zero is still initialized and finalized. Selection, both temporary finalizations, and the inner-selector read have already occurred, but neither payload destination call occurs for that outer entry.

Ownership and retention remain unspecified:

## Acceptance examples

All examples are conditional static consequences, not observed executions. Unless stated otherwise, they require dependencies to return normally and all relevant accesses and indices to remain valid.

1. **Initially empty outer collection.**  
   If the first outer query returns zero, context acquisition and outer initialization have occurred. F-a817d8d58c10 is called without prior explicit outer finalization. No inner-selector read occurs.

2. **Outer collection becomes empty before iteration.**  
   If the initial query returns one and the first loop-condition query returns zero, no outer entry is accessed. The outer work area is finalized normally.

3. **Context acquisition changes initialization inputs.**  
   If F-ea223a7ae124 changes the outer-selector value from A to B, and B remains until the subsequent read, outer initialization receives B.

4. **Selection changes later-read fields.**  
   If selection or either temporary finalization changes the inner-selector location or descriptor field at +0, inner initialization receives the values observed afterward. Those arguments are not captured before selection.

5. **Selector locations contain equal values.**  
   If both locations contain A when read, both initializations may receive A. Distinct storage does not require unequal values.

6. **Inner selector changes between outer entries.**  
   If one initialization reads A and a later dependency changes the inner-selector location to B before the next initialization’s read, the next initialization receives B.

7. **Empty inner collection.**  
   If its first condition query returns zero, selection, temporary finalization, inner initialization, and inner finalization still occur. Neither payload call occurs.

8. **Two ordinary inner entries.**  
   For a stable inner bound of two, destination order is caller destination for entry 0, selected destination for entry 0, caller destination for entry 1, selected destination for entry 1.

9. **First payload call modifies the slot.**  
   If the first destination call changes the slot from A to B, the second receives the same slot containing B. The body does not restore A.

10. **Different counter boundaries.**  
    If the outer bound admits counter 32768, outer indexed access receives −32768. With a stable inner bound of 32769, inner traversal instead stops after processing counter 32767.

11. **Maximum inner traversal.**  
    If every inner query returns 4294967295 and all admitted indices are supported, the loop executes exactly 65,535 iterations. The next counter is `0xffffffff`, and its condition fails. There is no wraparound iteration at zero.

12. **Changing bounds cannot bypass the terminal counter.**  
    At inner or outer counter `0xffffffff`, every possible 32-bit unsigned bound causes termination of that loop. Changing bounds may alter earlier exit points but cannot produce infinite traversal by itself.
