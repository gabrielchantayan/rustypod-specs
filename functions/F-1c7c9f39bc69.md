# F-1c7c9f39bc69

## Purpose

F-1c7c9f39bc69 transforms a sequence of rows containing 16-bit elements into an equally packed sequence of output rows. For ordinary positive row widths, each output element except the last combines two adjacent input elements. The combination favors the left element and uses bit masks that prevent certain bit positions from participating in the intermediate shifts. The last input element of each row is copied without this combination.

The masks are consistent with packed-color interpolation, possibly for a 16-bit color format. That interpretation is inferred intent, not an established interface requirement. The established behavior is the integer transformation described below; it is not an ordinary arithmetic average of two unsigned 16-bit values.

A nonpositive row count produces no input or output memory accesses. A row width of one or less does **not** generally produce an identity transformation or an empty row. It follows a distinct path that reads one input element and writes a value derived from the original destination address.

## Behavior

### Entry condition

The row count is checked before any source element is read or destination element is written.

If the row count is zero or negative, the function returns without accessing either buffer. This includes calls whose buffer addresses would be invalid if dereferenced.

If the row count is positive, processing begins with the first source and destination positions.

### Element-combination rule

For two unsigned 16-bit input patterns, let \(a\) be the left element and \(b\) the right element. Both are zero-extended to 32 bits for the unsigned operations below.

Define the 32-bit intermediate:

\[
m =
\left[
(a \mathbin{\&} b)
+
\left(
\bigl((a \mathbin{\oplus} b)
\mathbin{\&} \text{0xFFFFF7DF}\bigr)
\mathbin{\gg} 1
\right)
\right]
\mathbin{\&} \text{0xFFFEFFFF}.
\]

The output pattern is:

\[
q =
\operatorname{low}_{16}
\left[
(a \mathbin{\&} \operatorname{low}_{16}(m))
+
\left(
\bigl((a \mathbin{\oplus} m)
\mathbin{\&} \text{0xFFFFF7DF}\bigr)
\mathbin{\gg} 1
\right)
\right].
\]

Here:

- \(\mathbin{\&}\) is bitwise AND.
- \(\mathbin{\oplus}\) is bitwise exclusive OR.
- \(\mathbin{\gg}1\) is a logical unsigned right shift.
- \(\operatorname{low}_{16}\) retains the least significant 16 bits.
- Hexadecimal constants are masks, not signed quantities.

The mask 0xFFFFF7DF clears bit positions 5 and 11, counting from zero. The mask 0xFFFEFFFF clears bit position 16.

The second combination uses the original left element \(a\), not the original right element \(b\). Consequently, exchanging the two inputs can change the result.

The destination’s signed element type does not imply saturation or rejection of high-bit-set results. The established output is the stored 16-bit pattern.

### Rows with width at least two

For each row:

1. The first input element is read and retained as the left element.
2. The next input element is read.
3. The combination rule is applied to the retained left element and the newly read right element.
4. The resulting 16-bit pattern is written to the next destination position.
5. The newly read right element becomes the retained left element for the next pair.
6. Adjacent-pair processing continues until every pair in the row has been processed.
7. The last input element is written unchanged to the final destination position.

Thus, for a row of width \(W \geq 2\):

- Exactly \(W\) source elements are read.
- Exactly \(W\) destination elements are written.
- The first \(W-1\) output elements use the combination rule.
- The final output element is a bit-for-bit copy of the final source element.

The next row begins immediately after those \(W\) source elements and \(W\) destination elements. There is no padding, separate row pitch, or processing of a pair across a row boundary.

For disjoint buffers, each nonfinal output position depends only on the corresponding source element and its immediate right neighbor. The final position depends only on the last source element.

### Width of one, zero, or a negative value

For widths satisfying “width minus one is nonpositive,” the adjacent-pair loop is skipped. This includes width one, width zero, and representable negative widths other than the signed minimum discussed above.

Each row still:

- Reads one source element.
- Writes one destination element.
- Advances the source by one 16-bit element.
- Advances the destination by one 16-bit element.

The source value read on this path does not determine the stored output. Instead, every row writes the low 16 bits of the **original destination address**, under the recovered pointer-to-integer interpretation.

The original destination-address value is not replaced with the advancing row destination. Therefore, all such rows receive the same 16-bit pattern, even though their output addresses differ.

This behavior is established by the supplied representation. Whether it reflects an intended supported use is unknown. It must not be silently replaced with copying the source, writing zero, or skipping rows.

### Read/write order and aliasing

For widths of at least two, the first two source elements are read before the first destination write. Thereafter, each next source element is read before the corresponding combined output is written.

The last source value is retained and used for the final copy; it is not reread for that copy.

Exact in-place operation—source and destination beginning at the same address—does not overwrite a source element before that element has been consumed and retained. Under otherwise valid memory conditions, it therefore produces the same result as disjoint buffers holding the same initial input.

Other overlaps are order-sensitive. For example, a destination beginning two elements after the source can overwrite an element before that element is read. Later computation then consumes the overwritten value rather than the original buffer contents.

No whole-row or whole-buffer snapshot is made.

## Side effects

The visible side effects are 16-bit writes to the destination sequence. If source and destination overlap, these writes also mutate storage reachable through the source address.

For a positive width and positive row count, the function processes the mathematical product of width and row count in elements. It does not visibly calculate that product as a single signed integer expression. Validity nevertheless requires all incrementally reached addresses to remain accessible.

For the degenerate-width path, the access count is one source read and one destination write per positive row, regardless of the width’s magnitude.

The function does not visibly:

- Allocate or release memory.
- Call another function.
- Read or write a named global.
- Return an error code.

If a memory access fails, no recovery behavior is established. Earlier writes may already have occurred.

No atomicity, synchronization, volatile-access semantics, or guarantees concerning concurrent modification are established.
