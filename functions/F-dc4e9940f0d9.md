# F-dc4e9940f0d9

## Purpose

F-dc4e9940f0d9 obtains a record, examines its payload reference, conditionally updates three four-byte state fields, and forwards records with nonzero payload references through an additional dependency sequence. Both payload paths converge on guarded finalization.

Dispatch depends on a signed 32-bit payload key and an opaque global discriminator. The discriminator has **two separate read sites**: an equality comparison reads it first; only a failed equality comparison leads to a second read for signed ordering. Stability between those reads is not established.

The terms **record**, **payload**, **mode**, **count**, and **value** describe observed structural roles. They do not establish application semantics, object ownership, or synchronization.

Execution then enters common finalization. This path bypasses dispatch and the entire nonzero-payload continuation, including F-8157a180d901 and the returned-storage write.

### Discriminator sampling and branch selection

For a nonzero payload reference, the function reads the signed 32-bit key at payload `+0x04`. This sampled key is used throughout dispatch.

Selection observes the opaque signed 32-bit global discriminator as follows:

- **First discriminator read:** compare the key for equality with this sample. Equality selects the equality action immediately. The second discriminator read is not reached.
- **Second discriminator read:** performed only after the first comparison fails. Compare the key with this new sample using signed less-than. A true result selects the **lower region**.
- **Remaining region:** selected when the first equality comparison failed and the key is not less than the second sample.

The remaining region therefore means **greater than or equal to the second sample**, subject to inequality with the first sample. It is not necessarily a strictly greater-than region: the discriminator may change so that the second sample equals the key.

No preservation, synchronization, or snapshot guarantee establishes that the two samples agree. No dependency call is shown between these two read sites, but that does not establish global stability.

If both samples have one stable value, the familiar partition applies: equality, strictly less than, or strictly greater than that value. Any single-discriminator interpretation of the tables below requires this stability condition.

### Equality action

Equality with the **first** discriminator sample writes four-byte value `1` to mode.

No direct count or value write occurs in this action. A matching literal key does not override equality selection. The function proceeds to the nonzero-payload continuation without taking the second discriminator sample.

### Lower-region actions

For either count-adjustment case, the function first reads count and compares it with signed `-1`. If equal, it calls F-87be4aa684d1, obtains the returned object’s virtual target at table offset `+0x16c`, invokes that target, and writes its four-byte result to count. No explicit arguments are shown for this virtual invocation; its complete calling convention remains unresolved.

The increment action then reads count again, adds one, and writes the result to count. When resolution occurred, its result write precedes this later read and increment write. No upper bound or saturation check appears. The represented arithmetic and destination are 32-bit; behavior on signed overflow is not established.

The decrement action reads count for a signed comparison with zero. Only a strictly positive result causes another count read, subtraction of one, and a count write. These are distinct reads. With stable contents, positive values decrease by one without crossing the signed range boundary; zero and negative values do not receive a decrement write. Without stability, the positivity test does not establish the value of the later subtraction operand.

A resolution-result write remains observable even if no decrement follows.

## Acceptance examples

These examples describe conditional static behavior, not observed execution. All require valid reached accesses and normally returning dependencies. Persistent outcomes additionally require no later overwrites or relevant alias effects.

1. **Zero payload.** A valid nonzero record contains a zero payload reference. Its virtual operation at `+0x04` receives the record, followed by common finalization. Dispatch and returned-storage processing are bypassed.

2. **First-sample equality.** The key and first discriminator sample are both `0x66000014`. Mode receives `1`; the count-increment literal is not selected. No second discriminator read occurs.

3. **Changed discriminator, second-sample equality.** The key is `0x6600001a`, the first sample is `0x66000019`, and the second sample is `0x6600001a`. First equality fails; signed less-than against the second sample is false. The remaining region selects the mode-zero action, despite equality with the second sample.

4. **Changed discriminator selects the lower region.** The key is `0x66000014`, the first sample is `0x66000013`, and the second sample is `0x66000015`. Equality fails and the second comparison selects the lower region. The count-increment action applies even though the key exceeds the first sample.

5. **Stable discriminator and ordered reset.** Both discriminator reads have one stable value greater than `0x6600000d`. That key selects the lower-region reset: count receives `0` before mode receives `0`. The corresponding `0x66000017` case requires a stable discriminator greater than that literal.

6. **Count resolution and increment.** Lower-region key `0x66000014` sees count `-1`. Resolution returns `4`; count receives `4`, is read again as `4`, and receives `5`. With an initial count of `7`, resolution is bypassed and a subsequent read of `7` produces `8`.

7. **Decrement boundaries.** For lower-region key `0x66000015`, stable count `1` becomes `0`. Stable counts `0` and `-2` receive no decrement write. If resolution returns `0`, its write occurs even though no decrement follows.

8. **Mode resolution without unconditional storage.** Remaining-region key `0x6600001b` sees mode `-1`. A resolved effective mode of `2` causes a write of `1`; a result of `7` causes no direct mode write.

9. **Indirect copy and unmatched dispatch.** Remaining-region key `0x66000024` copies four readable source bytes into value. Separately, a key unmatched in its selected region causes no direct dispatch write. Both paths still perform the complete nonzero-payload continuation.

10. **Returned storage and final guards.** A valid returned reference receives the record reference at `+0x04` before being passed to F-37efbe955e3e, whether fresh or reused. Later, a zero finalization reference suppresses its dereference and the indirect operation; a nonzero reference with a zero first word suppresses only the indirect operation.
