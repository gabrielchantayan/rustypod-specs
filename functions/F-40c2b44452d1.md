# F-40c2b44452d1

## Purpose

F-40c2b44452d1 coordinates a transfer across a sequence of fixed-stride descriptors. It delegates each transfer step, accumulates reported progress in a caller-supplied counter, advances between completed descriptors, and updates a context-level accounting field on normal completion.

The visible behavior distinguishes:

- **Exhaustion detected at entry:** set a 16-bit context field to one and return −24.
- **A transfer dependency returning a nonzero status:** return that status immediately, without the normal final accounting update.
- **Normal loop termination:** add the caller counter’s current value to a context field and return zero.

The interpretation as a segmented transfer is inferred intent. The established contract is the sequence of field accesses, dependency calls, arithmetic, and returns described below.

## Interface

### Arguments

Four arguments are supplied:

1. **Context address.** Addresses a mutable structure containing the fields listed below.
2. **Transfer address value.** Passed to the transfer dependency and advanced by each successfully reported progress value. This function does not directly dereference it.
3. **Requested amount.** Passed to the transfer dependency and reduced by each successfully reported progress value. Zero stops the transfer loop, but does not bypass entry processing.
4. **Counter address.** Addresses a writable 32-bit quantity. Successful transfer steps add their reported progress to its existing value. The function does not initialize it.

These are descriptive argument names, not requirements about the larger application’s type definitions.

### Return value

The visible return value is a 32-bit integer:

| Value | Meaning established here |
|---|---|
| −24 | Entry-time last-descriptor completion condition was satisfied. |
| Any nonzero status from F-0d3bc7e98dd1 | That dependency returned the status; it is propagated immediately. |
| 0 | The loop ended without a nonzero dependency status, and final accounting was performed. |

A return of zero does not establish that the requested amount was fully transferred. The loop can also terminate because the unsigned current index is not below the unsigned descriptor count, or because the last descriptor is complete.

A returned −24 is not uniquely attributable to entry-time exhaustion: F-0d3bc7e98dd1 could independently return the same numeric status.

## Behavior

### 1. Entry sentinel processing

Before testing exhaustion or the requested amount, the function reads the 32-bit field at context offset 300.

If that field is not all-one bits, interpreted as −1:

1. Call F-4d499d26dca0 with the context address.
2. After the call returns, store all-one bits into context offset 300.

The dependency’s result is not inspected. Its effects on other state are unknown. Subsequent exhaustion processing reads context fields after this call; it does not rely on their pre-call values.

If offset 300 already contains all-one bits, this call and store are skipped.

Consequently, a zero requested amount does not suppress this entry action.

### 2. Entry-time exhaustion detection

The function compares the current descriptor index with descriptor count minus one.

Only when those values are equal does it access the selected descriptor’s second 32-bit field and compare that value with the context’s current position.

If both equalities hold:

- Store one using a 16-bit write at context offset 332.
- Return −24 immediately.

This branch does not directly initialize or increment the caller counter, call the transfer dependency, or update the accounting field at offset 336. Any earlier effects of F-4d499d26dca0 remain.

This check precedes the loop’s unsigned range guard. Therefore, a malformed count/index pair can cause a descriptor access here even when a later range comparison would have rejected the index.

The completion field at offset 332 is not otherwise written by the visible body. In particular, normal execution does not clear an existing value.

### 3. Transfer-loop admission

If entry-time exhaustion was not detected, the loop checks:

- Whether the descriptor count is less than or equal to the current index, using an **unsigned 32-bit comparison**.
- Whether the remaining requested amount equals zero.

If either stopping condition holds, the loop ends and final accounting occurs.

The requested amount is tested for zero, not positivity. A nonzero value with its high bit set is not rejected by a visible negative-length check.

The loop guard reloads count and index from the context. Changes made by dependencies, or through overlapping storage, can therefore affect later admission decisions.

### 4. Delegated transfer step

For each admitted iteration, the function initializes a local progress-report slot to zero and calls F-0d3bc7e98dd1 with:

1. The context address.
2. The current transfer address value.
3. The current remaining requested amount.
4. The address of the local progress-report slot.

The slot is a 32-bit quantity in the apparent representation. Although its recovered type is pointer-like, its contents are subsequently used as a numeric progress value.

If the dependency returns a nonzero status, this function returns that status immediately.

On this error path, the visible body does not:

- Subtract the slot value from the remaining amount.
- Advance the transfer address value.
- Add the slot value to the caller counter.
- Perform descriptor-transition processing.
- Perform final accounting.

Writes already performed by dependencies or earlier successful iterations are not rolled back. A dependency may also have changed shared state before returning its error.

### 5. Successful progress accounting

When F-0d3bc7e98dd1 returns zero, this function uses the reported slot value in this sequence:

1. Subtract it from the remaining requested amount.
2. Add it to the transfer address value.
3. Add it to the existing 32-bit value at the caller counter address and write that sum back.

The remaining amount and transfer address value are internal running values; no direct writeback of those arguments is shown.

No visible validation establishes that reported progress is positive, no greater than the request, or representable without overflow. Such guarantees would need to come from the dependency contract or caller preconditions.

### 6. Descriptor transition

After the caller-counter update, the function reads the current index and examines the selected descriptor’s second 32-bit field.

A transition occurs only if:

- That descriptor field equals the context’s current position; and
- The captured current index is below descriptor count minus one, using an unsigned comparison for the transition bound.

When both conditions hold, the following ordered actions occur:

1. Store current index plus one at context offset 312.
2. Store zero at context offset 316.
3. Read the value at context offset 320 and call F-674655f0e759 with it.
4. Read offset 320 again and call F-c019388e82bf with that value and the preceding dependency’s result plus eight.

The second call does not necessarily receive the same first argument as the first call: F-674655f0e759 may change the context or reachable shared state.

Neither dependency supplies a checked error branch in this function. The result of F-c019388e82bf is ignored.

Only one explicit descriptor transition is performed per successful transfer iteration. There is no separate loop that skips an arbitrary run of completed or zero-length descriptors.

### 7. Post-step exhaustion and loop continuation

After successful progress accounting and any transition, the function checks last-descriptor completion again, using freshly read context state.

If the current index equals descriptor count minus one and the selected descriptor field equals the current position, the transfer loop terminates.

Unlike the entry-time exhaustion branch, this termination:

- Does not directly set the 16-bit field at offset 332.
- Does not return −24.
- Proceeds to final accounting and returns zero.

Otherwise, execution returns to the loop-admission checks.

### 8. Final accounting

On every normal loop exit, the function adds the caller counter’s **current entire value** to the 32-bit field at context offset 336, stores the result there, and returns zero.

This is not necessarily the progress made during this invocation. If the caller counter starts nonzero, that starting value is included.

Final accounting also occurs when the transfer loop performs no iterations, provided entry-time exhaustion did not return early.
