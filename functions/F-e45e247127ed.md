# F-e45e247127ed

## Purpose

F-e45e247127ed obtains a value through an object's indirect operation and conditionally invokes a second operation before producing a 16-bit result.

After the first operation succeeds, the primary temporary's low 16 bits determine whether the second operation is required:

- **0x0081–0x009F**, inclusive: invoke the second operation.
- **0x00E0–0x00FC**, inclusive: invoke the second operation.
- All other values: store the primary value's low 16 bits directly.

Successful two-operation assembly uses the primary temporary's value **after the second operation returns**, not a preserved copy of the value used for classification. The first operation receives that temporary's address and could make it available to the second operation through shared state. Whether the dependencies actually do so is unknown.

A zero status from either operation produces failure. Failure of the second operation additionally causes a one-byte object-state write.

**Inferred intent:** The qualifying ranges and eight-bit shift suggest assembly of a two-unit encoded character. No particular encoding, byte-sized input constraint, or encoding-validity guarantee is established.

## Interface

### Arguments

| Position | Role | Established representation |
|---|---|---|
| First | Object reference | References an object whose first field supplies the dispatch base. |
| Second | Output reference | References storage for one 16-bit result. |
| Third | Secondary seed | Unsigned 32-bit initial value of the temporary passed to the optional second operation. |
| Fourth | Primary seed | Unsigned 32-bit initial value of the temporary passed to the first operation. |

The two seeds initialize distinct writable 32-bit temporaries before the first dependency call. They are behaviorally significant: a dependency is not required by the visible function to replace the temporary it receives.

The primary temporary remains alive across both calls. Its address is explicitly passed only to the first operation, but the function does not prevent that operation from making the address accessible to the second operation.

### Return value

The established ordinary returns are 32-bit values:

- **0:** an invoked dependency returned zero.
- **1:** all required dependencies returned nonzero, and the function performed its output store.

Dependency statuses are tested only for equality to zero. Positive and negative nonzero statuses both permit continued execution; their original values are not returned.

These outcomes assume normal completion of the relevant accesses and calls. Faults, exceptions, or non-returning dependencies have no established conversion into a return value.

## Behavior

### Initialization and first operation

The function initializes the secondary temporary from the third argument, then the primary temporary from the fourth argument.

It reads the object's dispatch base, selects the entry at offset 0x24, and calls **F-indirect-A** with:

1. The object reference.
2. A reference to the writable 32-bit primary temporary.

If F-indirect-A returns zero, the function immediately returns 0. It performs no second call, output store, or marker-byte store on that path. Dependency effects already performed are not rolled back.

If the status is nonzero, execution proceeds to classification.

### Classification

Classification examines the primary temporary after F-indirect-A returns. Only its low 16 bits participate.

The second operation is selected exactly for either inclusive interval:

- 0x0081–0x009F.
- 0x00E0–0x00FC.

The underlying subtraction and comparison operate in unsigned 32-bit arithmetic. A subtraction below a lower endpoint wraps in that domain and does not cause the value to qualify.

The classification is not based solely on the low byte:

- 0x00000081 qualifies.
- 0xABCD0081 qualifies because its low 16 bits are 0x0081.
- 0x00000181 does not qualify because its low 16 bits are 0x0181.

This decision controls whether the second operation occurs. It does **not** freeze the primary temporary for subsequent assembly.

### Single-operation success

If the classification is outside both intervals, the function performs one 16-bit output store containing the primary temporary's low 16 bits, then returns 1.

There is no intervening dependency call between classification and this store. The function does not directly write the marker byte on this path.

### Second dispatch and call

For a qualifying classification, the function reads the object's dispatch base again and selects its entry at offset 0x20. It calls **F-indirect-B** with:

1. The object reference.
2. A reference to the writable 32-bit secondary temporary.

The second dispatch lookup occurs after F-indirect-A returns. Consequently, changes made by F-indirect-A to the dispatch-base field or dispatch contents can affect the second call's target. The first lookup does not fix that target.

F-indirect-B is directly given the secondary temporary's address, not the primary temporary's address. Nevertheless, F-indirect-A already received the primary address. The dependencies could share that address while the temporary remains alive. The visible function establishes no preservation guarantee for the primary temporary across F-indirect-B.

### Second-operation failure

If F-indirect-B returns zero, the function:

1. Writes the byte value 1 at object offset 4.
2. Returns 0.

It performs no direct output store.

The marker write occurs after the failed call. It overwrites that byte with 1 regardless of the byte's prior value, including a value written by the dependency. This action directly writes only one byte.

Any changes to either temporary, the object, or other dependency-accessible state are not rolled back.

### Two-operation success

If F-indirect-B returns nonzero, the function uses the **then-current** values of both temporaries.

The stored 16-bit value is:

\[
\bigl((S_{\mathrm{after}}\mathbin{\&}0xFFFF)
\mathbin{|}
((P_{\mathrm{after}}\mathbin{\&}0xFFFF)\ll 8)\bigr)
\mathbin{\&}0xFFFF
\]

Here:

- \(P_{\mathrm{after}}\) is the primary temporary's value after F-indirect-B returns.
- \(S_{\mathrm{after}}\) is the secondary temporary's value after F-indirect-B returns.

The shift and OR are performed in the unsigned 32-bit domain before narrowing. The masked primary value shifted left eight bits fits within 24 bits. Narrowing discards the shifted contribution above bit 15.

In terms of numeric result bytes:

- The low byte is the secondary temporary's low byte.
- The high byte is the bitwise OR of the primary temporary's current low byte and the secondary temporary's bits 8–15.

This is not necessarily byte concatenation: secondary bits 8–15 can add set bits to the result's high byte.

The primary temporary is read again after the second call. For example, classification may select the second operation using 0x0081, yet assembly may use 0x0082 if that operation changes the primary temporary through a shared alias. With secondary value 0x0040, the result is then **0x8240**, not 0x8140.

There is no reclassification after the second call. A changed primary value need not remain in either qualifying interval. Its current low byte still contributes to assembly.

The function updates its local primary temporary with the combined value, performs one 16-bit output store, then returns 1. It does not explicitly reset the marker on success.

## Side effects

### Direct effects

The visible function performs:

- Initialization of two local 32-bit temporaries.
- A first indirect call on every normally entered path.
- A second indirect call only after first-operation success and qualifying classification.
- A one-byte store of 1 at object offset 4 only after second-operation failure.
- A local primary-temporary update on two-operation success.
- One 16-bit output store only on success.

It performs no explicit allocation, deallocation, resource release, or rollback.

The numeric output value and store width are established. The byte order of that store depends on the execution environment.

### Observable ordering

The established ordering is:

1. Temporary initialization.
2. First dispatch lookup and call.
3. First status check.
4. Classification after a nonzero first status.
5. Either direct success output, or a fresh second dispatch lookup and call.
6. After the second call, either the failure-marker store or successful assembly and output store.
7. Return.

The source establishes that successful two-operation assembly reads the primary temporary after F-indirect-B returns. It does not require an observable relative evaluation order between the two operand reads used to form the combined value. Concurrent mutation and synchronization semantics remain unknown.

### Aliasing and preservation

Neither dependency is established to preserve object fields, dispatch contents, globals, reachable resources, or storage accessible through independent aliases.

Accordingly:

- “No output store on failure” describes this function's direct behavior, not a guarantee that output storage remains unchanged.
- The first operation may expose the primary temporary's address through shared state.
- The second operation may use such an alias to change the primary temporary before successful assembly.
- Output/object overlap is not checked. A successful output store may alter object bytes, including the marker byte if the locations overlap.

Success therefore means no **explicit marker update**, not necessarily no change to the marker's storage.

### Ownership and lifetime

No ownership transfer of the object or output storage is established.

Each dependency receives an address into the current invocation's local storage. That storage is not a persistent buffer supplied by this function. In particular, sharing the primary temporary's address between the two calls is possible while it remains alive; that does not establish any right to use the address after the invocation ends.

Whether dependencies retain addresses, release resources, or manage other memory remains **documented_only**.

Additional conditional requirements:

- If F-indirect-A succeeds without changing the primary temporary, classification uses the primary seed's low 16 bits.
- If the secondary temporary remains equal to its seed through both calls, successful assembly uses that seed's low 16 bits.
- A nonzero second status does not establish that the primary temporary retained its classified value.
- If F-indirect-A changes the object's dispatch base, the second lookup uses the subsequently read base.
- An existing marker value of 1 is not explicitly cleared on success. It remains unchanged only if dependencies and overlapping stores also leave it unchanged.
