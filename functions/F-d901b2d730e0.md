# F-d901b2d730e0

## Purpose

F-d901b2d730e0 traverses a source range in eight-byte steps and conditionally transfers selected portions of each source slot into a corresponding destination slot. It returns the destination cursor after traversal.

Each transfer covers seven bytes of an eight-byte slot: offsets 0–4 and 6–7. Offset 5 is neither read from the source nor written to the destination by this function.

The established behavior is a sequence of fixed-width scalar transfers, not a complete eight-byte copy. An interpretation as copying records with an unused or padding byte is plausible intent, but neither a record type nor the meaning of the omitted byte is established.

The destination null check applies independently to each iteration. It does not make the function a general-purpose null-safe range operation.

## Interface

The function has three pointer-valued inputs and one pointer-valued result:

- **Source cursor:** the address of the first source slot to process.
- **Source limit:** an address compared with the current source cursor before every iteration. It is an equality sentinel, not an inclusive final slot.
- **Destination cursor:** the address associated with the first destination slot. Its current value determines whether the iteration performs transfers.

The supplied representation uses pointers to four-byte units. Advancing either cursor by two such units gives an eight-byte stride.

The result is the final destination cursor. It is not the initial destination address, a source address, a count, or a status code.

For a finite traversal of \(N\) iterations, with valid and representable pointer advancement, the result is:

\[
D_{\mathrm{final}} = D_{\mathrm{initial}} + 8N
\]

The source cursor advances by the same byte distance, but its final value is not separately returned.

### Slot layout

For every iteration whose current destination cursor is non-null, the slot has the following observable treatment:

| Byte offset | Width | Treatment |
|---|---:|---|
| 0–3 | 32 bits | Read from source, then written to destination |
| 4 | 8 bits | Read from source, then written to destination |
| 5 | 8 bits | Not accessed by this function |
| 6–7 | 16 bits | Read from source, then written to destination |

The 32-bit and 16-bit portions are transferred as scalar values. There is no explicit byte-order conversion, sign extension, arithmetic transformation, or interpretation of their contents.

### Preconditions for an ordinary successful transfer

A caller requiring defined, finite copying behavior must provide:

- A source limit reachable from the initial source cursor by an integral number of valid eight-byte advances.
- Readable source storage for every field actually accessed.
- Writable destination storage for every field actually accessed.
- Alignment and object-access conditions sufficient for the represented 32-bit and 16-bit accesses.
- Cursor advances that remain valid in the execution environment.

The function does not establish or check these conditions. A null destination in one iteration suppresses that iteration’s field accesses, but does not establish the validity of subsequent cursor values.

## Behavior

### Range selection and termination

The first operation affecting traversal is a comparison of the current source cursor with the source limit.

If they are equal, the function returns the current destination cursor immediately. It performs no source-field reads, destination-field writes, or cursor advances.

Otherwise, it processes one source position. After that iteration, both cursors advance by eight bytes, and the source equality comparison occurs again.

There is no less-than comparison, range-length computation, or check for passing the source limit. A limit at an address numerically above the start is insufficient by itself: it must be reached by the repeated eight-byte progression under the applicable pointer model.

A limit before the source cursor does not request reverse traversal. A limit not on the progression does not request a partial final slot. Neither case has an explicit rejection path.

### Transfer order within an iteration

When the current destination cursor is non-null, the established logical order is:

1. Read the 32-bit source portion at offset 0 and write that value to destination offset 0.
2. Read the 8-bit source portion at offset 4 and write that value to destination offset 4.
3. Read the 16-bit source portion at offset 6 and write that value to destination offset 6.

Each destination write precedes the next listed source read. The function does not first capture all seven source bytes into an independent snapshot.

After the transfers, the destination cursor advances by eight bytes. The source cursor then advances by eight bytes before the next source-limit comparison.

When the current destination cursor is null, all three transfers are skipped. The destination and source cursor advances still occur.

This describes the ordering represented by the supplied source. It does not establish processor instruction selection, bus transactions, volatile-memory semantics, atomicity, or synchronization guarantees.

### Empty ranges

An initially empty range returns the destination cursor unchanged, including when that cursor is null.

No source or destination storage is accessed in this case. The function does not explicitly reject null source values when the initial source cursor equals the source limit.

This empty-range behavior must not be generalized to a nonempty range: the function checks no source cursor for nullness before reading fields.

### Aliasing and overlap

There is no overlap detection and no change in traversal direction.

If source and destination are exactly the same valid address, each selected field is read and written back to itself. The omitted byte remains untouched.

For other overlaps, an earlier destination write can affect a later source read. This can occur within one iteration or across iterations. Consequently, the contract is an ordered sequence of transfers from the memory contents present at each read, not a promise to preserve the original source range.

The function does not provide general overlapping-range copy semantics.

### Null destinations

The null check is repeated using the current destination cursor. It is not a one-time choice to disable copying for the entire range.

A null destination therefore suppresses the current iteration only. The subsequent eight-byte advance may produce a non-null address under an address-arithmetic interpretation, after which another iteration attempts ordinary transfers.

The supplied source does not establish that advancing a null pointer is valid in the target language or runtime. Acceptance of such behavior requires an explicitly defined address model; it must not be assumed from the presence of the null check.

## Side effects

The explicit memory effects are the destination-field writes described above and their corresponding source reads.

For a valid, nonoverlapping traversal of \(N\) slots with non-null destination cursors throughout, the selected field widths total seven bytes per slot. This is a logical access-width total, not a guarantee about the number or width of physical memory transactions.

Destination offset 5 in each slot retains its previous value unless some separate overlapping access or external activity changes it. The function does not initialize, clear, validate, or normalize that byte.

No allocation, deallocation, ownership transfer, reference-count adjustment, logging, or explicit global-state access appears in the supplied body. The input pointers remain caller-provided storage references; no release operation is shown.

The function has no explicit error return. Invalid memory access, invalid alignment, invalid pointer arithmetic, or an unreachable limit is not converted into a documented failure status. The exact consequences of those conditions depend on the execution environment and are not established here.

There is no rollback mechanism. If execution is interrupted or fails after a write, the body contains no operation restoring earlier destination contents.

## Acceptance examples

The following are conditional acceptance cases derived from static inspection. They have not been executed.

### Empty source range

Given equal initial source and limit addresses, and any destination cursor:

- The returned cursor equals the initial destination cursor.
- No slot fields are read or written.
- No cursor advancement occurs.

### One valid, nonoverlapping slot

Given a source limit exactly eight bytes after the source cursor, a valid non-null destination, and source bytes at offsets 0 through 7 of:

10, 11, 12, 13, 14, 15, 16, 17

If the destination initially contains 90 at every offset, then on a conventional byte-addressed target with ordinary scalar load/store behavior, the resulting destination bytes are:

10, 11, 12, 13, 14, 90, 16, 17

The result cursor is eight bytes after the initial destination. Source offset 5 does not supply the preserved destination byte.

### Two valid slots

Given a source limit sixteen bytes after the initial source cursor and sufficient nonoverlapping storage:

- Transfers occur at source and destination slot offsets 0 and 8.
- Destination offsets 5 and 13 remain unchanged.
- The returned cursor is sixteen bytes after the initial destination.

There is no extra transfer at the limit address.

### Identical source and destination

Given the same valid source and destination start and a reachable limit:

- Selected fields are written back with the values just read.
- The cursor still advances normally.
- The function is not guaranteed to avoid writes merely because the addresses coincide.

### Order-sensitive overlap

Assume an execution environment that permits the required accesses when the destination starts four bytes after the source.

The first 32-bit destination write then covers source offsets 4–7. The subsequent read of source offset 4 observes the memory after that write, rather than necessarily observing the original byte at offset 4.

An implementation that snapshots all selected source fields before any write would not preserve this represented access sequence.

### Null destination with a nonempty range

On a runtime that explicitly defines null-address advancement as numeric address advancement, a one-slot range skips all field transfers and returns the address eight bytes beyond null.

This example does not establish portable validity. With two or more iterations under that same model, a later non-null destination cursor can trigger actual accesses; the initial null value does not suppress the whole operation.
