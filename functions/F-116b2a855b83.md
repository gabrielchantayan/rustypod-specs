# F-116b2a855b83

## Purpose

F-116b2a855b83 conditionally detaches a selected entry from a doubly linked structure, invokes F-93092e17776d on an address within that entry, and places an entry onto an owner-associated singly linked chain. It writes a 32-bit result to caller-provided storage.

When the selected address matches the owner’s distinguished address, the function skips the detachment, counter update, dependency call, and chain insertion. The result is then the distinguished address read from the owner.

For an ordinary selected entry, the result is its forward-link value captured before detachment. After the dependency returns, the function rereads the selection slot to determine which entry to place on the owner-associated chain. Consequently, the captured result and the entry ultimately inserted onto that chain need not refer to the same entry if intervening effects change the selection slot.

The structure resembles a linked container with a sentinel and a reusable-entry chain. Those roles are inferred intent. The established behavior is the sequence of address comparisons, memory accesses, arithmetic, and the dependency call described below.

## Interface

The function has three arguments and no explicit return value:

| Argument | Meaning established by direct use |
|---|---|
| Result destination | Address at which one 32-bit value is written on normal completion. |
| Owner address | Base address used to access fields at byte offsets 4, 16, and 20. |
| Selection slot | Address of a 32-bit value interpreted as an entry address. The slot is read repeatedly rather than copied once for the entire operation. |

The visible representation uses 32-bit words and 32-bit address values. This contract does not imply equivalent layouts on a platform with wider pointers.

### Owner fields

| Byte offset | Width | Direct use |
|---|---:|---|
| 4 | 32 bits | Head address of an owner-associated chain. Read and replaced after the dependency returns. |
| 16 | 32 bits | Distinguished address used to decide whether to skip removal. Also supplies the result on the skip path. |
| 20 | 32 bits | Counter decremented once on the removal path, before the dependency call. |

No owner fields at other offsets are directly accessed by the visible body.

### Entry fields

| Byte offset | Width | Direct use |
|---|---:|---|
| 0 | 32 bits | Forward-link address during detachment; later reused to hold the previous owner-chain head. |
| 4 | 32 bits | Backward-link address during detachment. |
| 16 | Address formation only | An address at this offset is passed to F-93092e17776d. The visible body does not itself read a payload value there. |

These are minimum access descriptions, not complete structure definitions. In particular, no payload size, allocation size, or meaning for entry offsets 8 through 15 is established.

### Preconditions

For the intended, non-aliasing use:

- The result destination must permit a 32-bit write.
- The selection slot must permit the required 32-bit reads.
- The owner must expose the fields needed by the selected branch.
- On the removal path, the selected entry must expose its two link words.
- The backward-link address must permit a 32-bit write at offset 0.
- The forward-link address must permit a 32-bit write at offset 4.
- The counter must support the decrement within the applicable arithmetic model.
- The address formed by adding 16 to the selected address must be acceptable to F-93092e17776d.
- After that dependency returns, the address then present in the selection slot must permit a 32-bit write at offset 0.

There are no visible null checks, membership checks, link-consistency checks, counter checks, or alignment checks. The function does not establish these preconditions itself.

## Behavior

### 1. Select the branch

The function reads the entry address from the selection slot and compares it with the 32-bit distinguished address stored at owner offset 16.

This comparison is by address value. It does not inspect the entry’s contents or establish that the entry belongs to the owner.

The visible body contains repeated reads of both the selection slot and selected entry fields. It does not establish one immutable selected-entry address for all subsequent operations.

### 2. Distinguished-address path

If the comparison finds equal addresses:

1. The function reads the owner’s distinguished-address field again.
2. It retains that value as the result.
3. It writes the retained value to the result destination.
4. It returns normally.

On this path, the function does not directly:

- Dereference the selected entry.
- Modify either neighbor link.
- Read or decrement the counter.
- Call F-93092e17776d.
- Read or update the owner-associated chain head.

The distinguished address therefore need not identify a dereferenceable entry for this path alone. The selection slot, owner field, and result destination still require valid access.

The final output write can itself modify owner or entry storage if the caller aliases the result destination with such storage. Thus “no structural updates” describes the skipped removal operations, not a guarantee against all structural changes under aliasing.

### 3. Capture the removal result

If the compared addresses differ, the function reads the first 32-bit word of the entry addressed by the selection slot and retains it as the eventual result.

Under the linked-structure interpretation, this is the selected entry’s successor.

This result is captured before the neighbor-link writes, counter decrement, and dependency call. It is not recomputed after those operations.

### 4. Reconnect the neighboring entries

The function performs two 32-bit writes in this order:

1. It writes the selected entry’s forward-link value into offset 0 of the entry addressed by the selected entry’s backward-link value.
2. It writes the selected entry’s backward-link value into offset 4 of the entry addressed by the selected entry’s forward-link value.

With stable, consistent links and noninterfering storage, these operations make the predecessor point forward to the successor and the successor point backward to the predecessor.

The first write completes before the second operation. Accordingly, storage aliases can affect values read for the second operation. The selection slot is also read again during these operations; it is not guaranteed to retain the address used for the branch comparison or result capture.

The visible evidence establishes ordering between these operations. It does not establish a finer total order for all operand reads within an individual assignment expression. A contract requiring such an order would need additional evidence.

No direct operation clears both links of the removed entry. Its offset-0 word is overwritten later during chain insertion; its offset-4 word is not explicitly cleared.

### 5. Decrement the owner counter

After the two neighbor-link writes, the function reads the 32-bit field at owner offset 20, subtracts one, and writes the result back to that field.

For a positive representable count, the visible effect is a decrease by exactly one.

No guard prevents removal when the counter is zero or otherwise inconsistent with the structure. The supplied representation treats this field as an integer, but does not justify a universal promise of unsigned wraparound or defined signed-overflow behavior at every boundary. Those boundary semantics are documented_only.

This update precedes the dependency call. There is no visible rollback mechanism.

### 6. Invoke the dependency

The function rereads the selected address from the selection slot, adds 16 bytes, and calls F-93092e17776d with that address as its sole visible argument.

The dependency is therefore invoked after:

- The result has been captured.
- Both neighbor-link writes have occurred.
- The counter has been decremented.

Its return value is not used.

No guarantee is established that the dependency preserves the owner, selection slot, entries, or other reachable state. Nor is it established that the dependency releases memory, preserves memory, destroys an object, or leaves the argument storage usable.

If the dependency does not return normally, the later chain insertion and result write are not shown as occurring. Earlier writes have already occurred; the visible body provides no recovery path.

### 7. Insert an entry onto the owner-associated chain

After the dependency returns, the function:

1. Rereads the address stored in the selection slot.
2. Reads the owner-chain head at owner offset 4.
3. Writes that head value into offset 0 of the entry identified by the reread address.
4. Writes that entry address into the owner-chain head field.

The dependency may have changed either the selection slot or the head field. The function uses their post-call values.

With a stable selection slot, the detached entry becomes the new chain head and its first word points to the prior head. With a changed selection slot, a different entry can be inserted.

The address chosen for this insertion is retained for the head update. Thus, if writing that entry’s first word aliases and changes the selection slot, the final head update still uses the entry address selected immediately after the dependency returned.

### 8. Publish the result

Finally, the function writes the previously retained 32-bit result to the result destination and returns.

On the removal path, this is the forward-link value captured before detachment. It is not the post-call chain head and is not necessarily the current forward link of any entry.

This is the last explicit write. If the result destination aliases a structural field, the output write can overwrite a value established earlier in the operation.

## Side effects

The removal path directly performs:

- One write to a predecessor’s forward-link word.
- One write to a successor’s backward-link word.
- One counter decrement.
- One call to F-93092e17776d.
- One write to the post-call selected entry’s first word.
- One replacement of the owner-chain head.
- One final result write.

The distinguished-address path directly performs only the final result write.

No direct allocation or memory release is visible. Placing an entry on a chain does not prove transfer of ownership, deallocation, or permission for the caller to release it. The dependency’s ownership effects remain unknown.

The function is not established as atomic, synchronized, or reentrant. Its intermediate structural states are not hidden by any visible locking mechanism. No concurrent-use guarantees can be derived from the supplied body.

There is no status result, error code, or explicit invalid-input branch. Invalid addresses, inconsistent links, unsupported arithmetic, or dependency failures have no defined recovery behavior in the visible evidence.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless an example states otherwise, assume valid aligned storage, representable arithmetic, distinct nonoverlapping fields, consistent links, and a dependency that returns without changing relevant state.

### Distinguished address selected

Given a selection slot equal to the owner’s distinguished address:

- The result receives the distinguished address reread from the owner.
- No entry-link dereference is required.
- The counter and owner-chain head are not directly updated.
- F-93092e17776d is not called.

### Ordinary entry removal

Given an entry between a predecessor and successor, an owner count of 3, and an existing chain head:

- The predecessor’s forward link becomes the successor address.
- The successor’s backward link becomes the predecessor address.
- The count becomes 2.
- F-93092e17776d receives the selected entry address plus 16.
- The selected entry’s first word becomes the former chain head.
- The owner-chain head becomes the selected entry address.
- The result receives the original successor address.

### Single ordinary entry with a shared neighboring sentinel

Suppose both links of the selected entry identify the same sentinel, and that sentinel provides distinct forward- and backward-link words.

The two reconnection writes target the sentinel’s offset-0 and offset-4 words respectively. Both become the sentinel address. If the initial count is 1, it becomes 0.

This example depends on the stated topology; the function does not validate it.

### Dependency changes the selection slot

Suppose the dependency changes the selection slot from the detached entry to another writable entry.

On return, the other entry receives the current owner-chain head in its first word and becomes the new head. The result still receives the successor captured from the original entry before detachment.

### Dependency changes the chain head

Suppose the selection slot remains stable but the dependency replaces the owner-chain head.

The inserted entry links to that replacement head, not to the head that existed before the call.

### Result destination aliases the head field

Suppose the result destination is the owner-chain head field.

The function first installs the post-call selected entry as the head. Its final output write then replaces that head with the captured result. No alias protection prevents this.
