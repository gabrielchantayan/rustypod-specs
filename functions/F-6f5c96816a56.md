# F-6f5c96816a56

## Purpose

F-6f5c96816a56 selects one of two candidate byte sequences, uses the selected sequence’s first byte as an unsigned byte displacement, and returns the address at that displacement. When a candidate is selected, it also reads the byte at the returned address and stores that value, widened to an unsigned integer, through an output pointer.

Selection depends on an effective mode. Ordinarily, this is the supplied mode argument. An incoming processor condition can instead cause the mode to be loaded from an implicit memory address.

The first candidate is eligible only when the effective mode is nonzero. The second candidate is the fallback when the mode is zero or the first candidate is null. If the applicable candidates are null, the function returns null without updating the output.

This describes the visible selection and byte-access behavior. Any higher-level interpretation—such as a record lookup, length-prefixed field, or encoded descriptor—is not established.

## Interface

### Explicit inputs

1. **Candidate-table address**

   An address identifying two consecutive four-byte entries. Each entry is interpreted as a candidate byte-sequence address:

   - First entry: byte offset 0 from the table address.
   - Second entry: byte offset 4 from the table address.

   These are address-bearing entries, not inline byte sequences. A zero entry denotes a null candidate.

   The supplied representation explicitly makes the table entries four bytes wide. Its interpretation as native addresses therefore depends on the address model represented by the source.

2. **Unsigned-result destination**

   An address at which the function writes the selected byte’s numeric value when a nonnull candidate is found.

   The visible destination type is an unsigned integer. Under the represented 32-bit integer model, this is a four-byte store, not a one-byte store. The stored numeric value is always between 0 and 255.

   The destination is not read before being written. It is not accessed at all when selection produces no nonnull candidate.

3. **Mode**

   A signed integer input whose only relevant property is whether it equals zero. Positive and negative nonzero values have identical selection effects.

   This explicit argument is ignored when the incoming condition described below requires a replacement mode.

### Implicit inputs

- **Incoming zero-condition flag.** If set, it causes the effective mode to be loaded from an implicit address before candidate selection.
- **Implicit mode-source address.** When the incoming flag is set, this address is dereferenced to obtain an integer replacement mode. When the flag is clear, this address is not accessed by the visible function.

These hidden inputs are part of the observed entry-state dependency. The supplied material does not establish a conventional callable interface that lets an ordinary caller specify them independently.

### Output

The return value is either:

- Null, when candidate selection finds no nonnull candidate; or
- The selected candidate’s base address plus its first byte’s unsigned value.

A nonnull return is accompanied by a write of the byte at the returned address to the unsigned-result destination, assuming all required accesses complete normally.

There is no separate status output.

### Access preconditions

For normal completion:

- If the incoming zero-condition flag is set, the implicit mode-source address must support the integer read.
- The candidate-table entry or entries reached by the selection path must be readable.
- A selected nonnull candidate must support a byte read at its base and another byte read at the computed address.
- When a candidate is selected, the result destination must support the unsigned-integer write with the width and alignment required by the target execution model.
- The address calculation must be valid under that model.

The function performs no visible bounds, accessibility, or alignment checks.

## Behavior

### Effective mode

The incoming zero-condition flag is examined before candidate-table processing.

If the flag is set, an integer is read from the implicit mode-source address and replaces the explicit mode. Otherwise, the explicit mode is used without that memory read.

Only the resulting zero/nonzero distinction affects selection. The mode is not used as an index, offset, length, or arithmetic operand.

### Candidate selection

The selection order is asymmetric:

| Effective mode | First candidate | Candidate used |
|---|---|---|
| Zero | Not read | Second candidate, if nonnull |
| Nonzero | Nonnull | First candidate |
| Nonzero | Null | Second candidate, if nonnull |

If the effective mode is zero, the first table entry is skipped entirely. Its value does not affect the result.

If the effective mode is nonzero, the first entry is read. A nonnull first entry completes selection; the second entry is not read. A null first entry causes the second entry to be read.

A null second entry ends selection unsuccessfully. There is no further fallback and no attempt to use a null candidate as a byte-sequence address.

Consequently, this is not “choose the second entry whenever it exists.” A nonnull first candidate takes precedence whenever the effective mode is nonzero, regardless of the second entry’s contents.

### Displacement and byte extraction

For a selected nonnull candidate:

1. The byte at the candidate’s base address is read as an unsigned value between 0 and 255.
2. That value is used as a byte displacement from the same base address.
3. The byte at the resulting address is read.
4. Its unsigned numeric value is stored to the result destination.
5. The resulting address is returned.

The displacement is the first byte’s value, with no added header size. A displacement of 1 addresses the next byte. A displacement of 255 addresses the byte 255 positions after the base.

The address calculation is not eight-bit arithmetic. The displacement’s range is eight-bit, but adding it to an address does not imply reducing the resulting address modulo 256.

A displacement of zero is valid in the visible logic. It makes the returned address equal to the candidate base. The offset-byte read and the subsequent result-byte read then address the same location.

The first byte is not independently checked as a length or validated against an allocation size. Its use as an offset does not establish that the selected object actually contains the addressed byte.

### No-candidate result

When selection yields no nonnull candidate:

- The return value is null.
- No candidate byte is read.
- The result destination is not written.

The destination’s previous contents therefore remain unchanged on this path, assuming no external modification.

A successful byte value of zero does not indicate selection failure. It produces a nonnull computed address and writes numeric zero to the destination, provided the address computation remains valid.

## Side effects

### Observable access order

The visible logical order is:

1. Read the implicit replacement mode, only if the incoming condition requires it.
2. Read the first candidate entry, only if the effective mode is nonzero.
3. Read the second candidate entry, only if the effective mode is zero or the first candidate is null.
4. Read the selected candidate’s first byte, if a nonnull candidate was selected.
5. Read the byte at the computed address.
6. Write that byte’s widened value to the result destination.

The second entry is not read speculatively in the visible logic when the first entry has already supplied a nonnull candidate.

This order describes the supplied representation. Hardware transaction details, compiler reordering, atomicity, and memory-mapped I/O guarantees are not established.

### Writes and aliasing

The only explicit memory write is to the unsigned-result destination. The function does not explicitly modify either candidate sequence or either table entry unless the destination aliases that memory.

For an aliasing destination, all selection and byte reads visibly precede the output write. Thus the output is based on the value read before that write, not on bytes subsequently overwritten by the write.

The returned address has already been computed before the output store. Overwriting a table entry or the selected candidate through an alias does not cause the function to repeat selection or recompute its return value.

This ordering does not establish that every overlapping layout is legal under the target language, alignment, or memory model.

### Ownership and lifetime

No allocation, release, ownership transfer, reference-count update, or lifetime extension is visible.

### Errors

There is no explicit error handler, exception translation, diagnostic output, or error-code store.

An invalid access or invalid address calculation has no specified recovery behavior in the supplied material. Null candidate entries are handled by selection; invalid nonnull addresses are not.

- A null candidate-table address is not a supported empty-table representation.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes readable input storage, a valid address calculation, and a writable destination whenever a write is required.

### First candidate takes precedence

Given a clear incoming zero-condition flag, a nonzero explicit mode, and a nonnull first candidate whose initial byte is 3:

- The first candidate is selected.
- The second table entry is not read.
- The byte three positions after the first candidate’s base is read.
- Its unsigned value is written to the destination.
- That byte’s address is returned.

A negative explicit mode has the same effect as a positive nonzero mode.

### Zero mode bypasses the first entry

Given a clear incoming flag and an explicit mode of zero:

- The first table entry is not read.
- A nonnull second candidate is selected even if the first entry would also be nonnull.
- The second candidate’s initial byte determines the returned address and output-byte location.

### Null first candidate falls back

Given a nonzero effective mode, a null first candidate, and a nonnull second candidate:

- Both table entries are read, first then second.
- Byte extraction uses only the second candidate.

### No candidate preserves the destination

Given either a zero effective mode with a null second candidate, or a nonzero effective mode with both candidates null:

- The return is null.
- No candidate bytes are read.
- The destination retains its previous value.

### Incoming condition overrides the argument

Given a set incoming zero-condition flag, an explicit mode of zero, and a nonzero integer at the implicit mode-source address:

- The replacement integer determines selection.
- A nonnull first candidate is selected.

Conversely, a zero replacement integer bypasses the first entry even when the explicit mode is nonzero.

### Zero displacement

Given a selected candidate whose first byte is zero, with stable memory during the reads:

- Both byte reads address the candidate base.
- Numeric zero is written to the destination.
- The candidate base is returned.

### Maximum displacement and unsigned result

Given a selected candidate whose first byte is 255:

- The addressed byte is 255 positions after the base, not one position before it.
- If that byte contains 255, the destination receives unsigned numeric 255, not a negative value.
