# F-d9dea262321d

## Purpose

F-d9dea262321d conditionally converts one byte from a caller-supplied memory region into a restricted numeric value and writes that value to an optional output location.

The function always invokes F-fca51b715561 after preparing its arguments. Only an exactly zero result from that dependency, together with a nonnull output pointer, enables the function’s subsequent byte read and output store.

The accepted byte values are 0x30 through 0x36, inclusive. They map to the 32-bit unsigned values zero through six. Every other byte maps to zero. A stored zero therefore does not distinguish the accepted byte 0x30 from an unaccepted byte.

A global state-record pointer participates in two distinct ways:

- Its initial value is retained for a possible post-call field read.
- It is independently evaluated when obtaining each of the dependency’s two record-derived arguments.

These evaluations are not an atomic snapshot. If the global pointer changes during argument preparation, the retained record and the records supplying the two dependency arguments can differ.

The visible behavior establishes neither the input format nor the dependency’s purpose. Describing the dependency as a validator would be inferred intent, not an established contract.

## Behavior

The dependency receives three arguments:

1. The original first input, unchanged.
2. The four-byte field at offset +8 from a record selected by a new evaluation of the global pointer.
3. The signed four-byte field at offset +20 from a record selected by another new evaluation of the global pointer, reduced by two.

The retained record address is not used to obtain either record-derived dependency argument.

The relative evaluation order of the dependency’s second and third arguments is not established. Consequently, the contract does not assign an order to their independent global-pointer evaluations or associated field reads. Both argument values are obtained before the dependency is entered.

If the global pointer remains unchanged throughout preparation, all three pointer evaluations select the same record. That is a conditional consequence of stability, not a snapshot guarantee.

If the global pointer changes during preparation, any of the following distinctions can matter:

- The retained record can differ from the record supplying the +8 field.
- The retained record can differ from the record supplying the +20 field.
- The two record-derived arguments can come from different records.

### Post-call record selection and address calculation

This is a fresh field read. It does not reuse the signed field value passed to the dependency.

The extraction address is mathematically the original first input plus this freshly read signed field, minus two, subject to the arithmetic limitations below.

This selection has several consequences:

- Changes to the retained record’s +20 field during the dependency call can change the extraction address.
- The extraction displacement can differ from the dependency’s third argument.
- Replacing the global pointer during the dependency call does not redirect the extraction-field read.

There are no dedicated writes to the global state pointer or record fields. Nevertheless, the output store itself can modify either when the output pointer aliases that storage. It would therefore be incorrect to attribute every possible state change exclusively to the dependency.

- Overwriting the retained record’s +20 field with the converted value.
- Overwriting a record’s +8 field.
- Overwriting the global pointer’s storage.

The resulting byte representation of a four-byte write depends on the target’s memory representation. This contract does not infer a usable pointer from a converted integer written into pointer storage.

No allocation or release operation is directly visible. No ownership transfer is established. In particular, the dependency cannot be assumed to preserve the input memory or retained record.
