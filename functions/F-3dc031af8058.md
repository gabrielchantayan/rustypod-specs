# F-3dc031af8058

## Purpose

F-3dc031af8058 performs an ordered sequence of memory updates and snapshots, followed by an unresolved indirect invocation with four visible arguments. Its observable behavior includes overlapping fields, repeated stores to unchanged destinations, accesses associated with fixed low addresses, and later address selection through memory.

No application-level purpose is established. Character-like constants do not establish formatting, and address-like values do not establish valid objects or ownership relationships.

This contract describes static evidence from the supplied representation. It does not establish executable behavior where declarations, arithmetic semantics, address interpretation, or the indirect target are unresolved.

## Behavior

### Initial capture and overlapping fields

The first visible memory access captures N from B + 0x74 as a signed four-byte value. Subsequent writes do not cause this saved value to be reloaded.

The initial stores occur in this order:

1. The additional entry byte is stored at C + 0x15.
2. E is stored as four bytes at C + 0x54.
3. D is converted to plain character type and stored as one byte at A + 0x09.
4. P is stored as four bytes at C + 0x14.

The payload store spans C + 0x14 through C + 0x17, including the earlier byte at C + 0x15. With ordinary memory and successful accesses, that earlier byte is overwritten. Byte order determines which portion of P occupies offset 0x15.

The plain-character conversion does not establish character signedness or an out-of-range signed conversion rule.

### Constant destinations and sampled value

Three stores carry numeric value 0x3A:

| Destination | Established store width |
|---|---:|
| Q | One byte |
| Signed product of N and 8 | Two bytes |
| Q advanced by 0x20 bytes | Four bytes |

These destinations are computed absolute addresses, not offsets from A, B, or C.

At S + 0x20, four successive four-byte stores carry:

- 0x20;
- 0x2F;
- the unsigned, zero-extended value of a byte sampled from S + 0x04;
- 0x20 again.

The sampling read occurs after the second store and before the third. Aliasing or externally observable memory can make each operation significant.

Only afterward is the separate global read to obtain G. The global associated with fixed address 0x60 then receives numeric value 0x20. Its storage width and any destination conversion are unresolved.

### Repeated unchanged destinations

A first group stores Q as four bytes at twice E + 0x54. It then stores:

- the low eight bits of S at G + 0x19, as one byte;
- the low eight bits of G at S + 0x11, as one byte;
- twice E at G + 0x34, as four bytes.

The following repeated groups use T instead of twice E. Each group stores Q as four bytes at T + 0x54, repeats the same two byte stores in the same order, and stores T as four bytes at G + 0x34.

No destination advances between repetitions. No input-dependent loop condition appears in the supplied representation. The repeated stores must not be interpreted as traversal of successive elements or silently collapsed when individual memory accesses are observable.

Exact repetition multiplicity remains **documented_only** in this contract. No exact aggregate access count is asserted.

### Later snapshots and fixed-address assignment

After the repeated region, a read of the global associated with fixed address 0xA9 supplies a saved 32-bit value through assignment or conversion. The global’s actual read width, signedness, and conversion to that saved value are unresolved.

Next, a four-byte snapshot is captured from Q + 0x74.

The global associated with fixed address 0x3A then receives an expression evaluated in this order:

- R is converted to plain character type.
- That converted value undergoes integer promotion.
- It is multiplied by 8.
- Numeric value 0x30 is added.
- The result is assigned to the undeclared global.

There is no explicit final byte conversion in this expression. Plain-character signedness and conversion behavior are unresolved, as are the destination’s width and assignment conversion. Only under an additional byte-destination assumption, with a specified narrowing rule, can a final byte result be asserted.

Two further four-byte snapshots are then captured, first from D + 0x14 and then from S + 0x04.

The next field updates, in order, place the low byte of S at D + 0x0D, 0x6C at S + 0x08, and the low byte of G at S + 0x0D and then S + 0x09. Each is a one-byte store. D is then stored as four bytes at D + 0x54.

The saved 32-bit value obtained through the 0xA9 global is explicitly narrowed to eight bits and assigned to the global associated with fixed address 0x67. This establishes the assigned expression’s width, not the global store’s width.

### Shift-sensitive update and overlapping replacement

A signed four-byte snapshot is read from D + 0x44. After that read, the current value of the 0x67 global is read and assigned to the global associated with 0x21. Neither global access width is established; the destination may convert the source value.

The D + 0x44 snapshot is then used for three effects:

- Its plain-character conversion is stored as one byte at S + 0x10.
- Its full signed value is stored as four bytes at G + 0x54.
- Its signed right-shift result, converted to plain character type, is stored as one byte at D + 0x01.

The shift count is S masked to its low eight bits, giving a value from 0 through 255. No reduction to five bits is shown. Counts of 32 or greater have no established defined result under the represented 32-bit expression semantics. Right shifting a negative value is also unresolved here.

G + 0x54 is subsequently overwritten with S as four bytes.

A four-byte snapshot is read from S + 0x40. The earlier S + 0x04 snapshot is stored as four bytes at G + 0x74, followed by the S + 0x40 snapshot at S + 0x10. That latter store spans offsets 0x10 through 0x13, replacing both the earlier byte at S + 0x10 and the repeatedly stored byte at S + 0x11.

Next, G + 0x44 receives D as four bytes. A fresh read of the 0x67 global supplies the value converted for a one-byte store at S + 0x09. The low byte of S is stored at D + 0x09. Finally, the saved 32-bit value obtained through the 0xA9 global is stored as four bytes at S + 0x44.

### Selected address and final address chain

A signed four-byte value is read from S + 0x54; designate it the selected address.

After this capture, the 0x67 global is read again and its value converted for another one-byte store at S + 0x09. This is a fresh read, not reuse of an earlier global sample.

The low eight bits of the saved Q + 0x74 snapshot are stored at selected address + 0x0D. D + 0x54 is then overwritten with the saved four-byte snapshot from D + 0x14.

A four-byte snapshot is captured from S + 0x14. The same saved low byte from Q + 0x74 is stored at D + 0x11. A plain-character conversion of the selected address replaces the byte at S + 0x09, and the full selected address replaces the four-byte field at S + 0x44.

The final chain proceeds through three signed four-byte values:

- The **chain base**, read from D + 0x04.
- The **chain value**, read from chain base + 0x64.
- The **destination base**, read later from D + 0x64.

Between capturing the chain base and reading the chain value, a two-byte value of 0x65 is stored at twice the chain base. This store can affect the later read through aliasing.

After capturing the chain value, a plain-character conversion of the saved S + 0x14 snapshot is stored as one byte at selected address + 0x11. Numeric value 100 is then stored as four bytes at selected address + 0x54.

A four-byte snapshot is captured from chain base + 0x74 before the destination base is read. The final visible stores then place:

- a plain-character conversion of the chain base at D + 0x09, as one byte;
- the chain value at destination base + 0x54, as four bytes;
- the destination base at twice the chain value, as four bytes.

These destinations are not isolated from earlier fields, globals, or memory relevant to the final target.

## Acceptance examples

These are conditional review criteria, not executed tests.

### Payload overlap

Given ordinary accessible memory and execution through the payload store, C + 0x14 through C + 0x17 contain P’s four-byte representation immediately afterward. The prior entry-byte store does not independently survive at C + 0x15. Final-state claims additionally require excluding later aliases and target-side writes.

### Unsigned offsets after a defined signed product

If R is −1, its signed product by four is −4 and S becomes 0xFFFFFFFC. The unsigned expression S + 0x20 yields 0x0000001C. This establishes the integer expression’s result, not the validity of an access at that address.

If the signed multiplication itself overflows, later assignment to S does not establish a defined wrapped product.

### No unconditional byte narrowing at 0x3A

If R is 32, its plain-character conversion preserves 32 under either ordinary eight-bit signedness choice. Multiplication and addition produce 304.

If the destination is unsigned eight-bit storage, assignment produces 48. If it is sufficiently wide integer storage, it can preserve 304. The supplied representation does not choose between these destination contracts.

### Fixed-global conversion versus width

Even though the expression assigned to the 0x67 global is explicitly eight-bit, acceptance must not require that only one byte is written. A wider declared destination could receive a converted value through a wider store.

Likewise, capturing a 32-bit saved value from the 0xA9 global does not require that the underlying read cover four bytes.

### Sampled byte zero-extension

If S + 0x04 contains byte 0xE3 when sampled, the third four-byte store at S + 0x20 carries numeric value 0x000000E3, not 0xFFFFFFE3. The next store carries 0x20.

### Snapshots and repeated destinations

Changing D + 0x14 after its capture does not change the third visible invocation argument. Repeated Q stores continue targeting T + 0x54 rather than successive elements. An observer of individual accesses may distinguish these stores from one consolidated write.

### Shift and partial completion

For a nonnegative snapshot and count below 32, the shift-derived store uses the plain-character conversion of the right-shift result. No result is specified here for excessive counts or negative operands.

If a later access fails, acceptance must not require rollback of earlier successful writes.
