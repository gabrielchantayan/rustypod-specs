# F-faed39796004

## Purpose

F-faed39796004 selects a 32-bit result using a dependency-produced value, the zero/nonzero result of a second dependency, and one of three subsequent data sources.

The established selection rule is:

- If the second dependency returns zero, return a value read from a fixed global location.
- If it returns nonzero, read a 32-bit object field twice. If the second read is zero, return a value read from a different fixed global location. Otherwise, return the value obtained by the first field read.

The routine therefore does not necessarily return the field value used in its zero test. Under stable memory, the distinction disappears. If the field changes between the two reads, it matters.

A more specific application-level purpose is not established. In particular, neither the meaning of the object nor the nature of the second dependency’s test can be determined from the supplied source alone.

## Behavior

### Dependency sequence

The routine first computes B + 0x28 and passes that address to F-44362605ab79.

The first dependency produces a four-byte value. The routine then passes that value as the first argument to F-000000000001. The second argument is the address of a fixed static datum.

The contents, length, encoding, termination, and interpretation of that static datum are not established. The source’s symbolic naming is insufficient evidence that it contains any particular text or that the dependency performs a string comparison.

The dependency calls occur in this order:

1. F-44362605ab79.
2. F-000000000001.

The second call depends on the first call’s returned value. If the first call does not return normally, the second call and the later selection logic are not reached.

### Zero result from the second dependency

If F-000000000001 returns zero, the routine reads the zero-result global and returns that value.

On this path:

- There is no direct read of B + 0x2c by this routine.
- The field-fallback global is not directly read.
- The zero-result global is read after both dependency calls have returned.

This does not establish that the dependencies leave the object field or either global untouched. It establishes only which reads the routine itself performs.

### Nonzero result from the second dependency

If F-000000000001 returns any nonzero integer, the routine performs the following source-visible sequence:

1. Read the 32-bit value at B + 0x2c and retain it.
2. Read the 32-bit value at B + 0x2c again.
3. Test the second value for equality to zero.
4. If the second value is zero, read the field-fallback global and return that global value.
5. Otherwise, return the retained value from the first field read.

The magnitude and sign of the dependency result do not otherwise affect selection. A negative result follows the same branch as a positive nonzero result.

When the field is stable across the two reads, this reduces to a simpler rule: return the field if it is nonzero, otherwise return the field-fallback global. That simpler rule is conditional on stability and is not a complete description of the supplied access sequence.

### Read ordering and changing state

Both dependency calls finish before the routine directly reads either the field or a selected global. A dependency that changes those locations can therefore affect the eventual return value.

The two field reads have separate roles:

- The first supplies the candidate returned value.
- The second determines whether that candidate is replaced by the field-fallback global.

Consequently, if the first read produces zero and the second produces a nonzero value, the routine returns zero from the first read. It does not return the second value.

Conversely, if the first read produces a nonzero value and the second produces zero, the routine returns the field-fallback global, not the first value.

These are descriptions of the supplied source-level access sequence. They do not establish synchronization, atomicity, or guaranteed physical load counts in the executable.
