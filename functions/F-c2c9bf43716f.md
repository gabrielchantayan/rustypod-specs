# F-c2c9bf43716f

## Purpose

F-c2c9bf43716f specifies an operation that interacts with unresolved dependencies, writes individual bytes to calculated addresses, reads two halfwords, publishes one word through a retained pointer, and assigns a derived value to a global destination. Its represented endpoint is exceptional rather than an ordinary successful return.

No application-level purpose is established. In particular, repetition, address scaling, and the global assignment do not establish initialization, reset, decoding, device configuration, or a buffer-processing protocol.

This contract distinguishes:

- **Established static evidence:** access widths, value origins, argument relationships, and ordering visible in the supplied representation.
- **[INFERENCE]:** consequences that require an explicitly stated arithmetic or execution model.
- **documented_only:** unresolved behavior for which no definite executable outcome is specified.

All obligations are conditional on reaching the relevant interaction. An earlier dependency may not return, an access may fault, or the represented entry boundary may not be a valid runtime entry point.

## Behavior

### Ordering and dependency boundaries

The supplied representation describes a sequential path without an explicit ordinary loop or conditional branch. This supports relative ordering along that path, not unconditional execution or guaranteed completion.

The broad effect order is:

1. Initial dependency interactions, followed by incoming-byte writes and further interactions.
2. Six explicit zero-byte writes.
3. A byte write whose value comes from its own destination address.
4. A family of writes using a retained derived byte, including the first halfword-read boundary and the global assignment.
5. A separate extracted-field write.
6. A final family of writes using a retained three-bit value, including an unresolved arithmetic boundary, pointer-related accesses, and word publication.
7. Further dependency interactions and the exceptional endpoint.

This phase description does not authorize coalescing intervening calls. Calls remain distinct observable interactions even when their primary results are unused. Unknown dependencies may inspect or alter shared state.

A common dependency relationship passes four times a 32-bit primary result to another interaction. Other boundaries instead forward an unscaled result or forward the result returned by a scaling consumer. These relationships are not interchangeable: an argument supplied to a dependency is not necessarily the value that dependency returns.

### Stored-value families

The contract distinguishes stored values by origin, not merely numerical equality.

| Family | Required value |
|---|---|
| Incoming-byte family | The represented eight-bit entry value |
| Explicit-zero family | Zero, independently of the entry byte |
| Address-derived family | Low eight bits of that write’s calculated numeric destination |

The unsigned sample and the operand supplying the three-bit family have different origins. Neither may be replaced by a newer primary result.

The extracted-field value excludes original bits 27 and 28. Although a wider intermediate includes those bits, narrowing the stored value to eight bits removes them.

The three-bit family contains unsigned values from zero through seven. Its origin is the retained operand’s most significant byte, reduced by a factor of 32. Subsequent reuse does not extract bits from newer dependency outputs.

### Incoming-byte and zero-byte effects

Ordinary incoming-byte destinations are numeric addresses equal to eight times the applicable result. Every such access writes one byte; address scaling does not imply an eight-byte write, an array element size, or an allocation base.

The first incoming-byte write precedes a dependency receiving four times its address-producing result. That interaction supplies a paired result. Its following consumer receives three displayed arguments: low 32 bits, high 32 bits, then low 32 bits again.

Most subsequent incoming-byte boundaries have a following consumer receiving two equal values, each 16,384 times the result used for the destination. The established exceptions matter independently:

- One write uses twice a newly returned result as its destination; its following equal arguments are each 4,096 times that result.
- One consumer has four displayed arguments. The first, second, and fourth contain the same 16,384-scaled value. The third contains the independent entry state scaled by 1,024.
- The interaction immediately following that four-argument boundary consumes a secondary output scaled by eight.
- The last incoming-byte boundary before the zero family uses equal arguments scaled by four.

Two additional paired-result consumers occur during the incoming-byte portion. Each receives low portion, high portion, high portion. Their duplicated portion therefore differs from that of the first paired-result consumer.

The explicit-zero family contains six byte writes. Each uses an eight-times-scaled destination and precedes a consumer with two equal 16,384-scaled arguments from the corresponding result.

An incoming byte of zero does not merge these effect families. Their dependency boundaries and ordering remain distinct.

### Address-derived and retained-byte effects

The address-derived write follows the zero family. It stores the low eight bits of its own eight-times-scaled destination. Its following consumer receives two equal 16,384-scaled values and, as its third argument, the full represented destination value rather than the narrowed byte.

The retained-byte family begins with a newly obtained unsigned sample. Its first destination is sixteen times that sample; the following consumer receives two equal values scaled by 32,768.

Later writes retain this byte while obtaining destinations from other operands. Important destination relationships include:

- A retained early scaled operand multiplied by 65,536, followed by equal arguments scaled by 134,217,728.
- Three subsequent result-based destinations scaled by 8,192, each followed by equal arguments scaled by 16,777,216.
- A further retained operand multiplied by 4,096, followed by equal arguments scaled by 8,388,608.
- A separate 8,192-scaled destination associated with the first halfword read.
- Later destinations scaled by eight.

The retained early operand originates at a late incoming-byte boundary and already contains a factor of 16,384. The further retained operand is obtained from it using another factor of 32,768. These are staged, represented-width calculations. They are not an unrestricted-precision product.

The most significant byte of the further retained operand is retained separately for the three-bit family. Its extraction is represented after the consumer associated with the 4,096-scaled write.

### First read and global assignment

At the first halfword-read boundary, one primary result supplies two different address scales:

- The retained byte is written at 8,192 times the result.
- The 16-bit read occurs at 4,096 times the result, plus byte offset 56.
- The following consumer receives the 4,096-scaled basis and the read quantity.

The byte write precedes the halfword read. No dependency invocation intervenes. The read precedes its consumer. Any extension of the 16-bit quantity into a wider argument is **documented_only**.

Later, the retained byte is assigned to the global destination immediately before an interaction receiving two zero arguments. This establishes assignment-before-invocation ordering, not reset semantics or persistence.

Six further byte-write boundaries after the global assignment continue using the retained byte at eight-times-scaled destinations. The first five have following equal arguments scaled by 16,384; the sixth uses equal arguments scaled by four. A subsequent ordinary scaling consumer uses a factor of two rather than four.

The extracted-field write occurs after these retained-byte effects and before the three-bit family. Its destination is eight times its own applicable result, and its following consumer receives equal values scaled by four.

### Three-bit effects and unresolved arithmetic

Most writes in the final family place the three-bit value at eight times an applicable primary result. Many are followed by consumers receiving two equal 16,384-scaled arguments. This is not universal: some writes are followed by interactions with no displayed arguments.

A boundary near the beginning of this family applies a right shift of 32 positions to a represented 32-bit intermediate that has already been scaled by four. The supplied representation does not establish a width-safe executable result.

Consequently, the shift outcome, its twice-scaled byte destination, and its following equal arguments scaled by 4,096 are **documented_only**. This contract does not select zero, sign propagation, or masked shift-count behavior.

After this boundary and intervening calls, another paired result is consumed as two displayed arguments: low 32 bits followed by high 32 bits. There is no third duplicated argument at that interaction. Reaching it remains conditional on the unresolved earlier boundary.

### Pointer and secondary-output distinctions

The retained pointer-like secondary output has three separate address uses:

| Use | Address relationship |
|---|---|
| Three-bit byte write | Numeric pointer value multiplied by 256 |
| Second halfword read | Numeric pointer value multiplied by 128, plus byte offset 32 |
| Direct word publication | Unscaled pointer value |

The pointer-scaled byte-write consumer receives two equal arguments, each the numeric pointer value multiplied by 524,288.

A different secondary output is retained after that boundary. It later supplies a three-bit byte destination scaled by 2,048, with following equal arguments scaled by 4,194,304. That same retained value is subsequently passed unchanged alongside newly scaled primary results at several interactions. It is not reconstructed from those newer results.

Other late interactions forward secondary outputs unchanged. Matching widths do not permit substitution of an adjacent primary result.

At the second halfword-read boundary, a three-bit byte write occurs first. The read then uses the scaled pointer address described above, and its contents become the following dependency’s displayed argument. No dependency invocation intervenes between that write and read. The read is not taken from the pointer’s unscaled address.

### Word publication and endpoint

At the word-publication boundary, one primary result determines both an eight-times-scaled byte destination and a word payload equal to four times that result.

The observable order is byte write, direct 32-bit write through the retained pointer, then dependency invocation with the word payload in all three displayed argument positions. No dependency call intervenes between the two writes.

The destinations are not established as disjoint. The word write can therefore overwrite the preceding byte.

A later interaction duplicates a newly returned 32-bit value into two displayed arguments. Additional calls and byte writes follow. Another consumer receives a newly scaled primary result together with the retained word payload.

The endpoint invokes F-unknown-05 with immediate zero and a fixed location operand. The represented result supplies the target of F-unknown-06. Neither ordinary return nor successful execution of the transfer is established.
