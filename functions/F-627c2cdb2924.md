# F-627c2cdb2924

## Purpose

F-627c2cdb2924 acknowledges a pending marker associated with a recorded position, then attempts to process at most one candidate from a 44-position sequence. A nonzero candidate-processing result triggers writes to selector-addressed record storage. A zero result triggers a control-word update and a reset-state write.

The returned value reports whether the pending marker was nonzero when read. It does **not** report candidate-processing success.

“Candidate,” “acknowledgment,” and “publication” describe inferred roles. The established behavior consists of the accesses, calls, branches, and values specified below; no larger protocol, ownership transfer, or atomic operation is established.

### Record layout

A selector observation supplies either:

- A bank choice from bit 7.
- An index from bits 0–6, ranging from 0 through 127.
- For F-5c256682e106, the entire eight-bit value.

The record stride is 0x20 bytes. Addresses combine the fixed base, a field offset, and the index multiplied by 0x20.

| Bank choice | Control offset | Descriptor offset |
|---|---:|---:|
| Bit 7 clear | 0xB00 | 0xB10 |
| Bit 7 set | 0x900 | 0x910 |

The result field uses a global offset selected by the retained publication-bank decision.

The two bank layouts are not disjoint address spaces. For example, the control address for bit-clear index 0 equals that for bit-set index 16. Unknown result offsets may also overlap descriptor fields, control fields, or other storage.

## Behavior

### 1. Initial dependency invocation

The function first calls F-9c06a5856a0f with the five arguments specified above. Its result is unused.

Only after that call returns does the function read the current position through its global pointer. Consequently, acknowledgment and candidate selection use the position observed after the call, not necessarily the position present at function entry.

No preservation of global pointers or pointed-to contents is assumed across this or any later dependency call.

### 2. Pending-marker acknowledgment

If the observed position is nonnegative, the function reads its 32-bit pending-marker entry and writes zero to the corresponding indexed marker location. The zero write occurs even if the value read was already zero.

The return value becomes 1 exactly when the marker value read was nonzero. It otherwise remains 0.

There is no upper-bound check before marker indexing. The later candidate wrap rule does not protect this access. A nonnegative position of 44, for example, first causes marker entry 44 to be accessed.

If the position is negative, no marker entry is accessed and the return value remains 0.

The marker addressing expressions reference the marker-array base for the read and write. Identical destinations require that base to remain stable between those evaluations. No intervening dependency call appears.

### 3. Candidate selection

After acknowledgment, the function retains the candidate-argument and candidate-descriptor array bases for possible successful-path clearing. It increments its locally retained signed position by one.

For an incremented value that is nonnegative:

- Values 0 through 43 select that candidate.
- Values greater than 43 select candidate 0.

If the incremented value remains negative, the function skips candidate processing, writes zero through the completion/reset destination pointer, and returns the acknowledgment result.

For representable signed arithmetic:

| Position read after the initial call | Candidate selection |
|---|---|
| −2 or less | Skipped |
| −1 | 0 |
| 0 through 42 | Next position |
| 43 or any greater value below the signed maximum | 0 |

The maximum signed 32-bit value is excluded from the last row because its increment is not representable as a signed 32-bit integer. The supplied representation does not settle the applicable overflow semantics.

Candidate positions that reach processing are between 0 and 43. Their four-byte entry displacement is therefore between 0 and 172 bytes. This bounds the selected index, not the validity of the array allocation or address arithmetic generally.

### 4. Candidate dependency and pointer capture

For a selected position, the function reads the candidate descriptor and retains its 32-bit value. It then obtains the candidate argument and invokes F-31a73855c184 with:

1. The candidate argument.
2. The retained descriptor.

The descriptor read precedes the candidate-argument read used for this call. The read expressions use the corresponding global array bases; the earlier retained bases are used for later successful-path clearing.

F-31a73855c184 returns a 32-bit value:

- Zero selects the unsuccessful path.
- Any nonzero bit pattern selects the successful path, including a pattern that would represent a negative signed value.

After this call returns, the function captures the selector pointer and then the current-position pointer from their globals.

**All subsequent selector observations use this captured selector pointer.** Later dependency calls may change the byte it addresses. Changes to the global selector pointer itself do not redirect those later observations. Similarly, the successful current-position write uses the current-position pointer captured after F-31a73855c184.

### 5. Successful candidate processing

#### Consume entries and record the candidate position

On a nonzero candidate result, the function directly performs these writes in order:

1. Zero to the selected descriptor entry, using its retained pre-call array base.
2. Zero to the selected argument entry, using its retained pre-call array base.
3. The selected position to the captured current-position destination.

These writes do not establish release, destruction, or ownership transfer of the former entry values.

#### Inspect a record

The inspection uses two separate selector-byte observations through the captured pointer:

1. A **bank observation**, whose bit 7 determines the control and descriptor offsets.
2. An **index observation**, whose low seven bits determine the record index.

The function reads the 32-bit control word using that bank/index pair and retains it as a snapshot. It then reads the descriptor field using the same retained bank decision and index.

The bank and index need not originate from one selector value. For example, bit 7 can come from one observation and the low seven bits from a later, different observation.

If the descriptor word read is nonzero, the function calls:

1. F-9c06a5856a0f with visible arguments 1 and 2.
2. F-5c256682e106 with a newly read full selector byte from the captured selector pointer.

Both results are ignored. The selector passed to the second call is not necessarily either selector value used for inspection.

#### Publish the descriptor and candidate result

After the conditional calls, publication uses another two separate selector observations:

1. A new bank observation.
2. A new index observation.

The function writes the retained candidate descriptor to the descriptor field addressed by this pair.

It then performs the following result-offset sequence:

1. Unconditionally reads the bit-clear bank’s result-offset global.
2. If the retained publication-bank decision is bit-set, reads the bit-set bank’s result-offset global and substitutes that value.
3. Writes the nonzero candidate result using the chosen offset and the retained publication index.

Thus, the bit-clear result-offset read occurs **after the descriptor write on every successful path**, including paths that ultimately use the bit-set offset. No new selector observation occurs between descriptor publication and result publication.

If the chosen result address overlaps the descriptor address, the later result write can replace the descriptor just written. Simultaneous persistence of both values is not guaranteed without suitable layout assumptions.

#### Construct and write the control value

After result publication, the function calls F-9c06a5856a0f with visible arguments 1 and 2.

The additional control contribution initially equals zero. The function then reads the optional-value enable byte:

- Zero: no call to F-adc5296da4e0.
- Nonzero: call F-adc5296da4e0 without visible arguments and use its 32-bit result as the contribution.

The final control destination uses two further, separate selector observations through the captured pointer:

1. A bank observation.
2. An index observation.

The written 32-bit value is the bitwise OR of:

- The control snapshot retained during inspection.
- The additional contribution.
- 0x84000000, setting bits 31 and 26.

There is no fresh destination-control read for this write. The final destination can differ from the inspected record, and any intervening destination contents are not merged.

The function then returns the acknowledgment result. There is no explicit completion/reset write on this path, although another direct write or a dependency could affect that storage if it aliases an accessed destination.

### 6. Zero candidate result

If F-31a73855c184 returns zero, the function does not directly clear the candidate entries or write the selected position.

It first calls F-9c06a5856a0f with visible arguments 1 and 2. It then performs:

1. One selector observation to choose the control-field bank.
2. A selector-index observation for the control-word read.
3. A distinct selector-index observation for the control-word write.
4. A control-word write containing the loaded word OR 0x08000000.
5. A zero write through the completion/reset destination pointer.
6. Return of the acknowledgment result.

The bank decision is retained for both control addresses. The two index observations are not one retained index: without stability, the read and write can address different records within that bank.

The source establishes separate index evaluations but does not settle the relative evaluation order of the destination-index expression and the read-index expression. The control-word load supplies the value for the subsequent store.

Consequently, this is a same-address read/modify/write only under a selector-index stability assumption. Otherwise, it copies a control value from one indexed address to another while setting bit 27.

## Side effects

The function directly exposes:

- One unconditional initial dependency call.
- Conditional marker reading and clearing.
- At most one candidate-processing call.
- Successful-path candidate clearing and position recording.
- Record-field reads and writes.
- Conditional replacement-related dependency calls.
- A conditional optional-contribution call.
- A completion/reset zero write on skipped and zero-result paths.

There is no explicit allocation, release, rollback, retry, timeout, exception handler, or propagated dependency error code.

Acknowledgment is not undone when processing fails. Successful-path candidate clearing precedes subsequent inspection, dependency calls, and publication. A later invalid access or nonreturning dependency can therefore occur after earlier state changes.

Aliasing can connect nominally different state roles. A reset write can overwrite current-position state; a record write can affect a selector byte or offset global if the memory layout permits it. The behavioral sequence does not imply independent final states.

No atomicity, synchronization, volatile-access semantics, or hardware ordering guarantee is established.
