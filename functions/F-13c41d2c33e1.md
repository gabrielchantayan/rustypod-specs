# F-13c41d2c33e1

## Purpose

F-13c41d2c33e1 performs a forward, element-by-element transfer of 32-bit storage units from a source cursor toward an exclusive source endpoint. It returns the destination cursor reached after those iterations.

The distinguishing behavior is a per-iteration destination-null check. When the current destination cursor is non-null, the function reads the current source unit and writes that value to the current destination unit. When the current destination cursor is null, it skips that iteration’s transfer but still advances both cursors.

This is not established as a general-purpose, overlap-safe memory move. Transfers proceed forward, so an earlier destination write can change a source value read in a later iteration. Nor is a null destination established as a supported count-only mode: the function advances the null cursor, and the meaning of that advancement is not fully specified by the available evidence.

## Interface

The function accepts three pointer-valued inputs:

- **Source start:** the address of the first 32-bit unit considered for transfer.
- **Source endpoint:** an exclusive stopping cursor, compared with the current source cursor using equality.
- **Destination start:** the initial destination cursor.

It returns a pointer-valued destination cursor. There is no separate element count, byte count, status result, or error result.

**Element width.** Each transferred unit occupies four bytes and contains 32 bits. The transfer does not establish a signed, unsigned, floating-point, or structured interpretation of those bits.

**Pointer width.** The available evidence does not establish the pointer representation or its width. A four-byte element size does not imply four-byte pointers.

**Layout.** Successive source and destination units are separated by one four-byte element. No header, terminator, length field, or per-element metadata is inspected.

**Ordinary successful-call preconditions.** For a conventional nonempty transfer:

- The source endpoint must be reachable from the source start by a finite number of forward, four-byte element advances.
- Every source unit actually read must be accessible for a four-byte read.
- Every destination unit actually written must be accessible for a four-byte write.
- Cursor advancement and the resulting cursor values must be valid under the applicable execution model.
- Alignment must satisfy the requirements of the target execution environment; support for unaligned access is not established.

These are conditions for a well-defined successful use, not checks performed by the function.

For an empty range, source start and source endpoint are equal. The destination is then returned unchanged without a source read, destination write, or cursor advance.

## Behavior

### Range selection and termination

The function tests whether the current source cursor equals the supplied source endpoint before each iteration.

Equality ends processing immediately. Any inequality permits another iteration; there is no established less-than comparison, range-length calculation, or check that the endpoint lies above the current source address.

Consequently, the endpoint is a stopping value, not a validated bound. An endpoint that cannot be reached by valid forward element advances does not produce a documented error or a guaranteed early return.

For a valid range containing \(n\) units, the function performs exactly \(n\) iterations. Here, \(n\) is a mathematical description of the range, not an integer parameter or an established internal counter.

### Per-iteration transfer

Within each entered iteration, the observable transfer behavior is:

1. The current destination cursor is checked against null.
2. If it is non-null, the current source unit is read and that value is written to the current destination unit.
3. The destination cursor advances by one four-byte unit.
4. The source cursor advances by one four-byte unit before the next endpoint comparison.

The destination-null check guards both the source read and the destination write. There is no source-value inspection on the skipped-transfer branch.

For ordinary valid memory, each transferred value is therefore taken from the source as it exists during that iteration. The function does not establish a snapshot of the entire source range before writing.

The evidence establishes this logical read/write ordering. It does not establish machine instruction selection, atomicity, volatile-access behavior, or synchronization guarantees.

### Destination progression and return value

Destination advancement occurs once per iteration, including iterations in which the destination-null check suppresses the transfer.

For a conventional valid range of \(n\) units and a valid destination progression, the returned cursor is \(n\) elements beyond the destination start. Its byte displacement is therefore \(4n\).

This relationship does not authorize pointer wraparound. No particular pointer-width modulus, overflow result, or integer-to-pointer behavior is established.

The return value is the advanced destination cursor, not the original destination, the source endpoint, the final transferred value, or a count.

### Null destination

A null destination has two distinct cases:

- **Empty source range:** the initial source equality check terminates processing. The function returns the null destination unchanged.
- **Nonempty source range:** the first iteration skips both the source read and destination write, then attempts to advance the null destination cursor.

The second case cannot be specified as a portable successful transfer. Advancing a null pointer has no established valid meaning in the supplied evidence. The function does not simply return null or suppress every subsequent write.

Conditionally, if a particular execution model defines the advancement and produces a non-null destination cursor, a later iteration would take the transfer branch. That is a consequence of checking the current cursor each time, not a guarantee that such an execution is valid.

### Overlap and aliasing

The function contains no overlap detection or change of transfer direction.

If destination and source start are identical, each entered transfer reads a unit and writes that value back to the same unit. Under ordinary memory semantics, the stored bit patterns remain unchanged, but the reads and writes still occur.

If destination begins inside the source range at a higher address, an earlier write can overwrite a source unit that has not yet been read. Later iterations then use the overwritten value.

If destination begins below the source start, forward copying can preserve the original source sequence for ordinary contiguous overlapping ranges: writes affect positions behind subsequent reads. This is a consequence of address placement and forward order, not a separate overlap-handling mechanism.

### Failure behavior

No explicit validation failure, exception translation, status code, or rollback is established.

An inaccessible source, unwritable destination, invalid cursor advance, or unreachable endpoint can prevent normal completion. The precise manifestation depends on the execution environment and is documented_only.

If execution stops after some iterations, the function provides no mechanism to undo destination writes already performed.

## Side effects

The established data-memory effects are four-byte destination writes, each preceded by the corresponding source read, on iterations whose destination cursor is non-null.

The source is not explicitly written through the source cursor. It can nevertheless be modified by destination writes when the two regions alias.

The function:

- Advances its working source and destination cursors.
- Does not write updated pointer values back into caller-owned pointer variables merely because those pointers were passed as arguments.
- Does not establish allocation, deallocation, ownership transfer, or object-lifetime management.
- Does not establish global-state reads or writes.
- Does not establish I/O, logging, callbacks, locking, or error reporting.

The caller remains responsible for supplying suitable storage and managing its lifetime. No ownership or release behavior should be inferred from the returned pointer.

Concurrent access to the same storage is outside the established contract. In particular, a four-byte transfer is not evidence of atomic access or freedom from data races.

## Acceptance examples

The following are conditional acceptance cases derived from static evidence. They have not been executed. Unless stated otherwise, assume ordinary accessible memory, valid cursor arithmetic, appropriate alignment, and no concurrent mutation.

### Empty range

Source start equals source endpoint. Destination start points to some location \(D\).

Expected result:

- No source unit is read.
- No destination unit is written.
- Neither cursor advances.
- The returned pointer equals \(D\).

This remains true when \(D\) is null. Equality of the source cursors is sufficient to bypass all transfer behavior.

### Three disjoint units

The source range contains three units with bit patterns \(A\), \(B\), and \(C\). The destination is a separate writable range.

Expected result:

- Destination units receive \(A\), then \(B\), then \(C\).
- Each source read occurs before its corresponding destination write.
- The return value is three elements, or twelve bytes, beyond the initial destination.
- A fourth source unit is not read.

### Identical source and destination

Source and destination start at the same address, and the range contains two units.

Expected result:

- Each unit is read and written back to its own address.
- The ordinary stored values remain unchanged.
- The returned destination cursor equals the source endpoint.

Acceptance must not substitute “no accesses occur” for “the final values are unchanged.”

### Destination one unit ahead

A contiguous region initially contains \([A, B, C, D]\). The source range covers its first three units. Destination starts at the second unit.

Expected result:

- The first transfer replaces \(B\) with \(A\).
- The next source read observes that replacement.
- The final region is \([A, A, A, A]\).
- The returned destination cursor is immediately beyond the fourth unit.

This distinguishes the function from a transfer that preserves the original source sequence under all overlaps.

### Destination one unit behind

A contiguous region initially contains \([X, A, B, C]\). The source range covers the last three units. Destination starts at the first unit.

Expected result:

- The final region is \([A, B, C, C]\).
- The returned destination cursor points to the fourth unit.
- Forward ordering does not overwrite any source unit before that unit is read in this example.

### Nonempty range with null destination

Source start differs from source endpoint, and destination starts null.

Established initial behavior:

- The first iteration performs no source read or destination write.
- Destination advancement is then attempted.

No portable successful return value or subsequent memory effect is specified. A contract claiming that the entire range is safely ignored would be inconsistent with the visible control flow.

### Unreachable endpoint

The source endpoint is not reachable through valid forward four-byte advances.

Expected contractual outcome:

- There is no explicit argument-rejection path.
- Successful termination is not guaranteed.
- No fixed failure result may be required from the available evidence.

## Evidence

The established static evidence consists of an exclusive source-cursor equality test, a destination-null guard around a four-byte transfer, unconditional per-iteration destination advancement, forward source advancement, and return of the resulting destination cursor.

That evidence supports:

- Four-byte element progression.
- Forward transfer order.
- Skipping both transfer accesses when the current destination is null.
- Immediate completion for equal source cursors.
- Overlap effects caused by reading each source value only when its iteration is reached.
- Absence of visible validation, rollback, allocation, release, and external calls.

The inferred intent is forward range copying with a returned destination endpoint. Intent does not establish overlap safety, a supported null-destination mode, or behavior for invalid pointer arithmetic.
