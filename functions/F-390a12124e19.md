# F-390a12124e19

## Purpose

F-390a12124e19 performs an ordered, partial transfer between two caller-supplied memory regions. It transfers two 32-bit values, then reads one additional source byte and writes that byte’s least significant bit as a full destination byte.

The operation is not an unrestricted structure copy: the third transfer discards seven bits, and no trailing bytes are explicitly copied. It is also not a snapshot copy. Each source read occurs at its corresponding transfer stage, so an earlier destination write can affect a later source read when the regions overlap.

**Established static behavior:** two 32-bit transfers followed by one masked 8-bit transfer, in that order.

**Inferred intent:** transfer two payload fields and normalize a one-byte flag. No field names, enclosing object type, or semantic interpretation of the payload values is established.

## Interface

The function has two pointer inputs and no returned value:

| Input | Role | Explicitly accessed relative offsets |
|---|---|---|
| First pointer | Destination base | Writes at offsets 0–3, 4–7, and 8 |

Offsets are measured in bytes. The first two fields are each 32 bits wide. The final field is 8 bits wide.

## Behavior

### Ordered transfers

The function performs three stages:

1. It reads the 32-bit value at source offset 0 and writes that value at destination offset 0.
2. It then reads the 32-bit value at source offset 4 and writes that value at destination offset 4.
3. It then reads the 8-bit value at source offset 8, retains only bit 0, and writes the resulting 8-bit value at destination offset 8.

Each stage obtains its source value before performing its corresponding destination write. The first stage completes before the second begins; the second completes before the third begins.

There is no initial capture of all source fields. Describing the result solely in terms of the source’s entry-state contents is therefore correct only when earlier writes cannot change subsequent reads.

### Value transformation

The first two transfers preserve their respective 32-bit values without explicit arithmetic, masking, comparison, or interpretation.

The third transfer produces exactly one of two byte values:

- `0x00` when the byte read at source offset 8 has bit 0 clear.
- `0x01` when that byte has bit 0 set.

This is a low-bit extraction, not a nonzero test. For example, `0x02` produces `0x00`, despite being nonzero; `0x03` produces `0x01`.

The final operation replaces the entire destination byte at offset 8. It does not merely update that byte’s least significant bit while preserving its other seven bits.

No signed interpretation is needed to specify this result. Masking an 8-bit input with one yields a value representable in 8 bits, so the final store has no truncation ambiguity. No size multiplication, length calculation, or counter arithmetic is present.

### Overlap and identity

With disjoint regions, the destination receives the source’s two 32-bit values and the masked source byte, assuming the source is not independently modified during execution.

With identical pointers, the first two stores write back the values just read. The byte at offset 8 is then reduced to either zero or one. Even in this case, the supplied representation contains all three writes; it does not contain an early return for identical pointers.

With partial overlap, later reads observe the storage as it exists after earlier writes. In particular, an earlier word transfer may overwrite the location of a later source word or the final source byte.

The function supplies neither general snapshot-copy semantics nor overlap repair. A caller requiring entry-state source values must arrange storage so that the ordered writes do not change later source reads, or provide that protection outside this function.

## Acceptance examples

These are conditional acceptance examples derived from static inspection, not executed tests. Unless stated otherwise, assume valid ordinary memory, suitable alignment, no concurrent modification, and no external mutation between stages.

### Disjoint regions

Given source 32-bit fields `0x12345678` and `0x90ABCDEF`, with source byte `0xFE` at offset 8:

- Destination offset 0 receives `0x12345678`.
- Destination offset 4 receives `0x90ABCDEF`.
- Destination offset 8 receives `0x00`.

If the source byte is instead `0xFF`, the final destination byte is `0x01`.

These expectations concern numeric word values and do not require choosing a byte order.

### Entire final byte is replaced

Given an initial destination byte of `0xAA` at offset 8:

- A source byte of `0x02` replaces it with `0x00`.
- A source byte of `0x03` replaces it with `0x01`.

Neither case preserves the destination byte’s high bits.

### Identical pointers

Given both inputs designate the same region, with byte `0x82` at offset 8:

- The two 32-bit fields retain their values.
- Byte 8 becomes `0x00`.
- Bytes beyond offset 8 are not explicitly accessed.

With byte `0x83` instead, byte 8 becomes `0x01`.

### Overlap affects later reads

Let the destination begin four bytes after the source. Assume the shared storage is valid for every resulting access.

Suppose the initial bytes at source offsets 0–12 are:

`10 20 30 40 55 66 77 88 FE 99 AA BB CC`

All values in this sequence are hexadecimal.

The first transfer places `10 20 30 40` at shared offsets 4–7. The second transfer consequently reads those newly written bytes and places them at offsets 8–11. The final source-byte read therefore obtains `0x10`, not the original `0xFE`, from shared offset 8. Its low bit is zero, so shared offset 12 receives `0x00`.

The resulting shared byte sequence is:

`10 20 30 40 10 20 30 40 10 20 30 40 00`

This example distinguishes ordered transfers from a snapshot of the original nine source bytes.

### Trailing storage remains untouched

For disjoint ordinary regions, if destination offsets 9–11 exist and initially contain sentinel values, those values remain unchanged. The final store is one byte wide, not a third 32-bit store.
