## Behavior

### Default selection

Before invoking the dependency, the function resolves the first input and then the second input.

If the first input is zero, it obtains a replacement from the shared default source. If the second input is zero, it independently obtains a replacement from that source.

The visible order therefore places any first-side default read before any second-side default read. There is no dependency invocation between those selections.

The function does not check whether a replacement is itself zero. A zero default is passed onward as state rather than rejected, recursively substituted, or treated as immediate completion.

When both inputs request the default, the visible representation contains two default accesses, not an explicit single captured value reused for both sides. ### State preparation

After default selection, the function initializes two local integer state cells from the resolved inputs. The visible initialization order is second-side state followed by first-side state.

These cells persist across comparison iterations. The function does not restore them from the original inputs before subsequent calls. Mutations performed through the dependency’s state pointer therefore participate in later iterations.

No explicit comparison of the initial input values or state-cell values occurs. Equal inputs, including identical nonzero inputs, still enter the dependency-driven comparison.

### Paired evaluation

The function always performs at least one pair of dependency invocations:

1. F-d3922c7fe0ec receives the address of the first-side state cell, and its integer result is captured.
2. F-d3922c7fe0ec receives the address of the second-side state cell, and its integer result is captured.
3. The captured results are compared.

This order is part of the behavioral contract. The second invocation occurs after the first invocation has completed and may observe global or external changes made by the first.

The first result is captured before the second invocation. The comparison uses that captured result; it does not obtain a fresh first-side result after processing the second side.

### Unequal results

If the two captured results differ, the function returns their ordered arithmetic difference: first-side result minus second-side result.

This mismatch decision precedes the zero-termination decision. Therefore:

- A zero result on the first side does not prevent the second call.
- Zero on the first side and nonzero on the second side constitutes a mismatch.
- Nonzero on the first side and zero on the second side also constitutes a mismatch.
- Neither mismatch case starts another iteration.
