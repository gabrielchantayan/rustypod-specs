# F-035e63b8c0f2

## Purpose

F-035e63b8c0f2 dispatches an integer operation selector against an object containing scalar control fields and a pointer to auxiliary state.

Supported operations inspect or modify selected fields, conditionally update auxiliary state, invoke a dependency before replacing the attached state pointer, or acknowledge a request without further direct changes. The return value is operation-specific: some operations return a fixed status, while others return a stored integer that may itself be zero.

**Established behavior:** the dispatch conditions, field accesses, direct writes, dependency invocation sites, and return values described below are visible in the supplied static source.

**Inferred intent:** the auxiliary state may represent a position, a quantity, and a boundary. The source does not establish those meanings. This contract therefore uses neutral field names.

**Unknown:** the complete object layout, allocation rules, dependency effects, and application-level meaning of the selectors are not supplied.

## Interface

The function accepts four arguments:

### Width and representation

The recovered interface uses integer fields and integer-sized pointer representations consistent with a **32-bit target model**. Auxiliary-state elements are spaced four bytes apart. Selector comparisons are signed; the flags test treats its field as unsigned.

This contract describes integer field values as 32-bit quantities and auxiliary elements as four-byte slots. The supplied text does not independently establish the original compiler, calling convention, alignment rules, or signed-overflow policy. In particular, conversion of a pointer into an integer must not be silently generalized to a wider-pointer environment.

### Memory preconditions

Every invocation first reads the attached-state pointer from the object at offset +32. The object must therefore support that read even for a selector that otherwise returns a constant or is unsupported.

Additional validity requirements depend on the selected operation:

- Selectors 1, 2, 3, and 10 may dereference the entry-loaded attached-state pointer.
- Selectors 8, 9, 114, and 130 access the indicated object fields.
- Selector 3 writes through a non-null pointer argument.
- Selector 115 writes through a non-null pointer argument but does not dereference the attached state.
- Selector 114 stores the pointer argument without checking it or dereferencing the newly supplied state.

There is no explicit validation of non-nullness, alignment, accessibility, object extent, or ownership. Invalid memory use has no defined error result in the supplied source.

## Behavior

### Entry and dispatch

Before testing the selector, the function loads the attached-state pointer from object offset +32. References below to the **entry-loaded state** mean this captured pointer, not a fresh read of that object field.

Supported selectors are:

| Selector | Direct behavior | Return |
|---|---|---|
| 0 | No further direct action | 0 |
| 1 | Conditional auxiliary-state update | 1 |
| 2 | Test first state value | 1 if zero; otherwise 0 |
| 3 | Read first state value; optionally output second | First state value |
| 4–7 | No further direct action | 0 |
| 8 | Read control value | Control value |
| 9 | Write control value | 1 |
| 10 | Read first state value | First state value |
| 11 | No further direct action | 1 |
| 12 | No further direct action | 1 |
| 114 | Invoke dependency, then replace control value and attached-state pointer | 1 |
| 115 | Optionally output entry-loaded attached-state pointer | 1 |
| 130 | Write secondary control value | 1 |
| Any other selector | No further direct action | 0 |

Negative selectors are unsupported and return 0 after the entry pointer read.

### Selector 1: conditional auxiliary-state update

The function first reads the second state value.

If it is zero, the function returns 1 immediately. It does not read the flags field, invoke the external dependency, or directly modify auxiliary state on this path.

Otherwise, it reads the flags field and tests bit 0x200.

**When bit 0x200 is set:**

1. The first state value is read and used as the arithmetic reference.
2. The second state value is replaced by its previous value minus the difference between the third state value and that reference.
3. After that write, the third state value is read again.
4. The value from that final read is written to the first state slot.
5. The function returns 1.

For stable, non-overflowing values, the second-state update is:

second after = second before − (third before − first before).

The third state value participates in an arithmetic read and a later read after the second-state write. Those reads must not be collapsed into an unconditional single snapshot when describing observable accesses.

The source establishes that the second-state write precedes the final third-state read, and that the final third-state read precedes the first-state write. It does not establish a left-to-right order among all operands read within the arithmetic expression.

**When bit 0x200 is clear:**

1. The function invokes dependency D-01.
2. After that dependency returns, it writes zero to the first slot of the entry-loaded state.
3. It returns 1.

No explicit arguments are visible at the D-01 call site. Its effects are unknown. In particular, the absence of a direct write to the second state slot on this branch does not establish that its value remains unchanged across the call.

The integer value argument has no effect on selector 1. On the flagged branch, the arithmetic reference comes from the first state value, not from the supplied value.

### Selector 2: zero test

The first state value is read.

- Zero produces return value 1.
- Any nonzero value produces return value 0.

No direct writes or dependency calls occur.

### Selector 3: paired read with optional output

If the pointer argument is non-null, the function reads the second state value first. It then reads the first state value, writes the captured second value through the pointer argument, and returns the captured first value.

If the pointer argument is null, it reads and returns only the first state value. It does not access the second state value on that path.

The reads precede the optional output write. Consequently, aliasing the output with a state slot does not change the already captured return value.

### Selectors 8, 9, and 10

Selector 8 reads and returns the control value at object offset +16.

Selector 9 writes the value argument to that control field and returns 1.

Selector 10 reads and returns the first value of the entry-loaded state.

These operations do not validate or normalize the stored integer values.

### Selector 114: dependency followed by replacement

The function performs these actions in order:

1. Calls F-f299fac040dd with the object address.
2. Writes the value argument to object offset +16.
3. Writes the pointer argument to object offset +32.
4. Returns 1.

The dependency’s return value is not used. The two direct stores occur only if the dependency returns normally.

The entry-loaded attached-state pointer is not passed as an explicit argument and is not directly dereferenced on this branch. The dependency receives the object address and may inspect or change it; its actual behavior is unknown.

The replacement pointer may be null. This function neither validates the replacement state nor copies its contents.

### Selector 115: optional pointer output

If the pointer argument is null, the function returns 1 without an output write.

Otherwise, it converts the entry-loaded attached-state pointer to the integer representation and writes that integer through the pointer argument, then returns 1.

The output is a pointer representation, not the first value stored in the auxiliary state. The attached state itself need not be readable for this operation.

### Selector 130: secondary control write

The value argument is written to object offset +28. The function returns 1.

### Constant-result and unsupported selectors

Selectors 11 and 12 return 1 after the entry pointer read.

Selectors 0 and 4 through 7, and all unsupported selectors, return 0 after that read.

These paths perform no further direct memory accesses or dependency calls in the supplied source.

## Side effects

Direct side effects are limited to the writes identified above:

- Auxiliary-state updates under selector 1.
- Optional output writes under selectors 3 and 115.
- Control-value writes under selectors 9 and 114.
- Attached-state pointer replacement under selector 114.
- Secondary-control write under selector 130.

Dependency effects are additional and unknown.

The function contains no explicit allocation or deallocation. That does **not** establish that dependencies allocate nothing, release nothing, or preserve object and auxiliary-state storage.

For selector 1’s dependency branch, the entry-loaded state must remain writable when the post-call zero write occurs. For selector 114, the object must remain writable when the post-call field stores occur. The supplied function does not verify either condition.

No synchronization, atomic-operation contract, rollback, or explicit error reporting is visible. Concurrent mutation is not specified. Memory faults and dependency failures are not converted into status codes by visible handling.

## Acceptance examples

These examples are conditional static acceptance cases, not reports of execution. They assume valid memory and stable values unless stated otherwise.

1. **Zero second state short-circuits selector 1.**  
   With second state value zero, selector 1 returns 1. It performs no flags read and no direct state write, and it does not invoke D-01.

2. **Flagged arithmetic update.**  
   With first, second, and third state values 20, 100, and 35, and flag 0x200 set, selector 1 changes the second value to 85 and the first value to 35, then returns 1. This example involves no signed overflow.

3. **The value argument is not the arithmetic reference.**  
   Under the preceding conditions, changing the value argument to 999 does not change the direct arithmetic result.

4. **Unflagged update follows the dependency.**  
   With second state nonzero and flag 0x200 clear, selector 1 calls D-01. If it returns and the entry-loaded first slot remains writable, that slot is then set to zero. No expectation is imposed on other values that D-01 may modify.

5. **Selector 2 distinguishes zero from nonzero.**  
   A first state value of zero yields 1. A first state value of −7 yields 0.

6. **Selector 3 permits output aliasing.**  
   With first state value 7 and second state value 19, and the output address pointing to the first state slot, selector 3 returns 7 and leaves that slot containing 19.

7. **A null selector-3 output suppresses the second read.**  
   With a null pointer argument, selector 3 returns the first state value without reading the second state slot.

8. **Stored zero is not necessarily failure.**  
   If the control value is zero, selector 8 returns zero. Selector 9 can successfully store zero while returning 1.

9. **Replacement occurs after the dependency.**  
   For selector 114, if F-f299fac040dd returns normally and the object remains writable, the function then stores the supplied control value followed by the supplied attached-state pointer. A null replacement pointer is stored without rejection.

10. **Pointer output does not read pointed-to state.**  
    Selector 115 with a valid output address returns 1 and outputs the entry-loaded pointer representation, even if that pointer is null. It does not read an auxiliary-state element.

11. **Unsupported selection still requires the object read.**  
    Selector −1 returns 0, but only after the attached-state pointer has been loaded from object offset +32.
