# F-a78a7790af0e

## Purpose

F-a78a7790af0e selects one of two operations using a byte in a caller-supplied state object:

- When the byte is zero, it conditionally requests an operation for the positive difference between two 32-bit state fields, checking whether a successful dependency reports the full requested amount.
- When the byte is nonzero, it first obtains a status and a second 32-bit value from a preparation dependency, then passes that value and two caller-supplied words to another dependency.

A final state-processing dependency is called on all zero-selector paths, including dependency failures, and on the nonzero-selector path only after both preceding dependencies succeed.

These are established control-flow properties. Interpreting the branches as particular kinds of I/O, or the final call as cleanup, reset, commit, or release, is inferred intent rather than an established contract.

## Interface

| Argument | Established interpretation |
|---|---|

| Second | A 32-bit word that is not used by the visible function body. |

The third argument’s local copy is addressable storage for a 32-bit word. The fourth argument’s local copy is addressable storage for a signed 32-bit value. Neither local copy is itself a caller-visible output parameter.

The source does not establish whether any argument word represents a pointer, handle, length, token, or other domain-specific value, except where it is explicitly used as an address.

### Output

The return value is a signed 32-bit status:

- Zero indicates that the visible status checks succeeded or that no branch-specific operation was required.
- A nonzero dependency status is propagated on the paths described below.
- The function generates decimal **−34** when the zero-selector operation reports success but its returned amount differs from the amount requested.

Zero does not independently establish a complete external transaction. In particular, the final dependency’s effects and failure behavior are not visible.

### Preconditions

The state address must support the accesses taken by the selected path. The zero-selector branch reads both difference fields, even when their difference is not positive. The field at +8 is read only when a branch-specific dependency call needs it.

Dependencies must accept their supplied arguments and return normally for the corresponding normal-return behavior to apply. Null addresses, invalid storage, concurrent mutation, arithmetic overflow, and abnormal dependency exits have no visible recovery mechanism.

## Behavior

### Entry and selector decision

The function initializes its eventual zero-selector return status to zero and copies the third and fourth arguments into local storage. It then reads the selector byte at offset +5.

Only zero versus nonzero matters. The supplied body does not distinguish individual nonzero byte values.

The branch is chosen from this initial read. A dependency changing the selector later does not cause the visible function to reconsider the branch.

### Zero-selector branch

The function reads the 32-bit fields at offsets +24 and +28 and forms their signed difference:

- The field at +24 is the minuend.
- The field at +28 is the subtrahend.
- The result is used as a signed 32-bit quantity.

The source establishes these operand roles, but not an independently reliable order between the two field reads.

If the difference is zero or negative:

- The field at +8 is not needed by this branch.
- F-edf0d9c5fd88 is not called.
- F-36c2c2b132fa is called with the state address.
- The function returns zero after that call returns normally.

If the difference is positive:

1. The positive difference replaces the local copy of the fourth argument.
2. The field at +8 is read.
3. F-edf0d9c5fd88 is called with that field’s 32-bit value and the address of the local signed 32-bit amount.
4. Its returned status becomes the function’s pending result.
5. If that status is zero, the local amount after the call is compared with the original difference.
6. If the amounts differ, the pending result becomes −34.
7. F-36c2c2b132fa is called with the state address.
8. The pending result is returned.

The amount comparison is an equality check, not merely a check for a smaller amount. A successful dependency that reports a larger amount, zero, or a negative amount also causes −34 whenever that value differs from the original positive difference.

If F-edf0d9c5fd88 returns nonzero, its status is preserved. Any amount it reports does not replace that status with −34.

The comparison uses the difference computed before the dependency call. There is no visible reread of the fields at +24 and +28 to recompute the expected amount afterward.

### Nonzero-selector branch

The function calls F-cdf60417d657 with:

- The state address.
- The address of the local 32-bit copy of the third argument.

Its result is represented as 64 bits and is consumed as two 32-bit portions:

- The low 32 bits are interpreted as the status.
- The high 32 bits provide an additional argument for the next dependency.

If the low 32-bit status is nonzero, the function returns that status immediately. Neither F-7ef43f7b70dc nor F-36c2c2b132fa is called on that path.

If the low status is zero, the function reads the field at +8 **after** F-cdf60417d657 returns. It then calls F-7ef43f7b70dc with four arguments, in this order:

1. The current 32-bit field value at +8.
2. The high 32-bit portion of F-cdf60417d657’s result.
3. The current contents of the local third-argument copy, including any replacement made by F-cdf60417d657.
4. The local fourth-argument value, which this branch has not explicitly changed.

Thus, a state-field update by F-cdf60417d657 can affect the first argument supplied to F-7ef43f7b70dc. The contract must not substitute a field value cached before the preparation call.

If F-7ef43f7b70dc returns nonzero, that status is returned immediately, without calling F-36c2c2b132fa.

If it returns zero, F-36c2c2b132fa is called with the state address, and the function returns zero after that call returns normally.

### Integer-width constraints

All ordinary arguments, state word accesses, branch-specific statuses, and amount values are represented as 32-bit quantities. The preparation result is represented as 64 bits, with its halves used separately.

The subtraction is shown as signed 32-bit arithmetic. For inputs whose mathematical difference is outside the signed 32-bit range, the supplied representation does not establish a portable result. A wrapping interpretation, a wider subtraction, and overflow rejection must not be silently treated as equivalent contracts.

For a difference representable in signed 32 bits, the positive, zero, and negative branch behavior is established.

## Side effects

### Direct effects

The function directly writes only its local storage in the supplied body. It does not visibly assign a state-object field.

It exposes addresses of local storage to dependencies:

- F-cdf60417d657 receives the address of the third-argument copy.
- F-edf0d9c5fd88 receives the address of the amount initialized from the positive difference.

These locations are local to the invocation. The visible body does not grant persistent ownership, allocate replacement storage, or define a valid lifetime beyond the invocation.

### Indirect effects

The dependencies may have externally observable effects. Their implementations are unavailable, so the following are not established:

- Whether they mutate the state object or other reachable memory.
- Whether the field at +8 identifies a resource with ownership semantics.
- Whether any dependency allocates, retains, releases, or transfers memory or resources.
- Whether dependencies change global state.
- Whether an error leaves partial progress.
- Whether F-36c2c2b132fa can fail, signal, or terminate execution.

The visible function performs no rollback after a dependency error.

F-36c2c2b132fa is not a universal exit action: early errors in the nonzero-selector branch bypass it. Conversely, a nonzero status from F-edf0d9c5fd88 does not bypass it.

## Acceptance examples

These are conditional behavioral examples, not observed runtime results. Each assumes valid accesses, representable arithmetic, and normally returning dependencies.

- The computed difference is zero.
- F-edf0d9c5fd88 is not called.
- F-36c2c2b132fa is called once.
- The function returns zero.

- The difference is −5.
- No amount-based operation is requested.
- F-36c2c2b132fa is called.
- The function returns zero.

### Zero selector, exact successful amount

- F-36c2c2b132fa is called.
- The function returns zero.

- F-36c2c2b132fa is still called.
- The function returns −34.
