# F-a49a3de492d0

## Purpose

F-a49a3de492d0 selects a record, invokes a preparation dependency, repeatedly evaluates a second dependency using a scaled input, and then publishes the accepted result and its associated iteration value into the selected record. It finishes by writing a fixed control value and setting one bit in another record field.

The established acceptance condition is an unsigned result no greater than 65,535, but this condition is effective only when the unsigned iteration counter is between 0 and 1,024 inclusive. In the ordinary initial pass, evaluation starts at counter value 1. Results obtained at counter values 1,025 through 4,294,967,295 cannot terminate the loop, regardless of their size. After counter wraparound, counter value 0 can terminate it.

A likely intent is to find a scaled input whose evaluated result fits in 16 bits and then activate a record. The dependency’s mathematical operation and the record’s hardware or software meaning are not established. In particular, the implementation does **not** establish a 1,024-call limit.

## Behavior

### Record selection precedes preparation

The function first resolves the destination record address.

For selectors 0 through 3, address selection uses the fixed base. For larger selectors, it reads the alternate-base configuration and adds the selector’s 32-byte displacement.

This address selection occurs before F-c2147d93773d is called. Consequently, a change to the alternate-base configuration during that call does not cause this invocation to select a new address. The previously selected address remains the destination.

That does not imply that the destination remains valid or unchanged: the dependency’s effects on memory and mappings are unknown.

### Preparation precedes evaluation-configuration capture

### Evaluation sequence

The unsigned counter starts at zero. Each evaluation uses the counter after incrementing it, so the first evaluation uses 1.

For each evaluation, F-d7be9cfb4000 receives:

1. The captured evaluation-configuration value.
2. The scale input multiplied by the current counter, reduced modulo \(2^{32}\).

The returned value is treated as an unsigned 32-bit result.

The multiplication does not clamp, saturate, or report overflow. Under the recovered 32-bit unsigned arithmetic model, a negative scale input contributes its unsigned bit pattern. For example, a scale input of −1 produces second-argument bit patterns `0xFFFFFFFF`, `0xFFFFFFFE`, and `0xFFFFFFFD` at counter values 1, 2, and 3.

The function makes at least one evaluation call if preparation returns normally and execution reaches the loop.

### Acceptance and continuation

The continuation rule depends on both the current counter and the returned result:

| Current unsigned counter | Continuation rule |
|---|---|
| 0 through 1,024 | Continue exactly when the result exceeds 65,535 |
| 1,025 through 4,294,967,295 | Continue regardless of the result |

Thus, during the initial progression:

- Counter values 1 through 1,024 can produce an accepted result.
- A result of 65,535 is accepted at an eligible counter value.
- A result of 65,536 is rejected.
- At counter value 1,024, a rejected result does not terminate the search or produce an error.
- Once the counter reaches 1,025, even a zero result cannot terminate the loop until the counter wraps into the eligible range.

The counter increments modulo \(2^{32}\). After its maximum value, the next evaluation uses zero. Its scaled argument is then zero for every scale input.

At counter value zero, the ordinary result threshold applies. If that result is rejected, evaluation proceeds with counter value 1 and continues through another cycle.

There is no explicit iteration cap, timeout, failure return, or fallback. Nontermination is possible.

### Publication after acceptance

When an evaluation is accepted, the function directly performs these operations in order:

1. Writes the accepted 32-bit result at byte offset 8.
2. Writes the counter value immediately preceding that evaluation at byte offset 16.
3. Writes `0x00000040` at byte offset 0, replacing the entire field.
4. Reads the 32-bit field at byte offset 4.
5. Writes that field back with bit 1 set, using mask `0x00000002`.

The value written at offset 16 is one less than the accepted counter, modulo \(2^{32}\). In particular:

- Acceptance at counter 1 stores 0.
- Acceptance at counter 1,024 stores 1,023.
- Acceptance at counter 0 after wraparound stores `0xFFFFFFFF`.

Every accepted result is numerically representable in 16 bits, but its destination write is 32 bits wide.

The final read-modify-write preserves all bits present in the value actually read at offset 4 except that bit 1 is forced to one. It does not preserve a snapshot from function entry: the read occurs after all three preceding writes and after every dependency call.
