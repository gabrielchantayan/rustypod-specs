# F-57246425e749

## Purpose

F-57246425e749 selects a range from a byte-backed value and submits that range to one of two dependencies. A captured discriminator byte selects the representation:

- Discriminator equal to 4: obtain a length and a byte pointer from separate dependencies, normalize the requested range, and submit a pointer-plus-length range.
- Any other discriminator: obtain a zero-terminated byte sequence, count and traverse loosely UTF-8-shaped units, then submit the selected bytes.

The function does not itself construct or return a result object. Its observable result is the downstream call, together with any effects of its dependencies. A null data pointer causes an early return before index decoding or submission.

Interpreting this as a substring or slice operation is inferred intent. The established behavior is the range normalization, byte traversal, and dependency interaction described below. The text traversal is not UTF-8 validation.

## Interface

### Inputs

The interface has three inputs, each represented by a 32-bit machine value:

| Input | Interpretation |
|---|---|
| Context | An address passed to the submission dependency. It also supplies the default requested length when the selector is not exactly 3. |
| Selector | A signed 32-bit value. Exactly 3 selects an explicitly decoded requested length; every other value selects a context-derived length. |
| Argument vector | An address of 32-bit entries. Entry 0 supplies an object address, entry 1 supplies the start operand, and entry 2 supplies the length operand when required. |

The object initially addressed by argument entry 0 must permit a byte read at offset 30. That byte is captured once and determines the branch for the entire invocation.

When the selector is not 3, the context must permit:

1. A 32-bit address read at offset 24.
2. A 32-bit value read at offset 80 from the resulting address.

These reads occur only after successful data acquisition and start decoding.

### Output

There is no explicit return value. On the ordinary completion paths, the function invokes one submission dependency and then returns. Any return value from that dependency is unused.

The function supplies no explicit status for an absent source, an empty range, malformed text, or an invalid address. A null acquisition result is handled locally; other failures are not locally translated into a result.

### Widths and addressing

The visible model uses:

- 8-bit discriminator and source-byte reads.
- 32-bit argument entries, addresses, decoder results, and raw counts.
- Two-word arithmetic for normalized start and length, interpreted as signed 64-bit quantities.
- A 32-bit byte-span argument for text submission.

A raw count with its highest bit set is sign-extended for normalization rather than treated as an unsigned value between \(2^{31}\) and \(2^{32}-1\). This distinction also applies to the counted text length.

The complete validity requirements of each dependency are unknown. Valid accesses by this function are not sufficient to establish that a dependency will accept the supplied arguments.

## Behavior

### 1. Capture the representation

The first observable reads are argument entry 0 and the discriminator byte at offset 30 of the addressed object.

The discriminator is retained across all later dependency calls. It is not reread if a dependency changes the argument vector or the object.

### 2. Acquire the source and its raw length

#### Discriminator equal to 4

The order is:

1. Call F-8e8cd22930fb with no explicit arguments and retain its 32-bit result as the raw length.
2. Reread argument entry 0.
3. Pass that entry to F-005c8b552c2d to obtain a source-byte address.
4. Return immediately if that address is null.

The second read of entry 0 matters: F-8e8cd22930fb may have changed the entry or memory influencing it. No preservation guarantee is established.

This branch does not inspect the source bytes locally and does not search for a terminator.

#### Any other discriminator

The order is:

1. Call F-95b79f0a129e with no explicit arguments.
2. Return immediately if its result is null.
3. Scan the returned bytes to the first zero byte, accumulating a 32-bit unit count.

A scan unit is defined as follows:

- A zero byte terminates scanning and is not counted.
- A nonzero byte below 192 occupies one unit by itself.
- A byte from 192 through 255 begins a unit containing that byte and every immediately following byte whose top two bits are `10`.

The continuation bytes recognized by the last rule have values 128 through 191. They are absorbed only when following a byte of at least 192. An isolated byte in the range 128 through 191 is therefore a separate unit.

No constraints on valid leading bytes, continuation counts, Unicode scalar values, overlong encodings, or incomplete encodings are enforced. For example, byte 255 followed by several continuation bytes is treated as one unit.

The count increments modulo \(2^{32}\). The scan itself continues until a zero byte is encountered; it does not stop when the counter wraps.

### 3. Obtain the requested start and length

After successful acquisition—and, in the text branch, after the complete counting scan—the function:

1. Reads argument entry 1 and calls F-75a3efca3d72 with that value.
2. Interprets the returned 32-bit bit pattern as signed and sign-extends it to form the requested start.
3. Obtains the requested length:
   - If the selector is exactly 3, it reads argument entry 2 and calls F-75a3efca3d72 again.
   - Otherwise, it reads the context-derived value through offsets 24 and 80 described in the interface.
4. Interprets the length’s 32-bit bit pattern as signed and sign-extends it.

The length operand or context field is read after the first decoder call, not before it. Consequently, mutations made by that call can affect the requested length.

The raw source length is also sign-extended from 32 bits for the following normalization.

### 4. Normalize the range

Let:

- \(L\) be the signed, extended source length.
- \(S\) be the signed, extended requested start.
- \(N\) be the signed, extended requested length.

The established normalization rules are:

1. **Negative requested start:** add \(L\) to \(S\). If the resulting start is still negative, add that negative remainder to \(N\), then replace \(S\) with zero.
2. **Nonnegative requested start:** subtract one if it is nonzero. Zero stays zero.
3. **Upper endpoint restriction:** if \(S+N>L\), replace \(N\) with \(L-S\).

Thus positive starts use a one-based convention, while zero also selects the beginning. Negative starts are relative to the signed source length.

There is no general lower clamp for the requested length. The endpoint comparison is signed. Its addition and comparison retain the high words; they are not merely comparisons of wrapped 32-bit low words.

For ordinary nonnegative lengths below \(2^{31}\), these rules have familiar range-selection behavior. Nevertheless:

- A start beyond the end is not independently clamped to the end.
- Such a start can produce a negative normalized length.
- A negative requested length is not interpreted as an endpoint.
- Source lengths whose raw high bit is set enter normalization as negative values.

The representation branch determines what happens to a negative normalized length.

### 5. Submit a non-4 representation

This branch traverses the source again after the decoder calls and normalization.

First, it advances from the acquired source address while both conditions hold:

- The current byte is nonzero.
- The normalized start counter is nonzero.

Each advance skips exactly one unit using the same byte-grouping rule as the counting scan and decrements the two-word start counter.

The resulting address is the selected beginning. From there, the function advances again while:

- The current byte is nonzero.
- The normalized length counter is nonzero.

Each advance skips one unit and decrements the two-word length counter. This produces the selected end.

Both traversal conditions use **nonzero**, not **positive**, counters. In particular, a negative normalized length does not suppress traversal. For a stable finite source, it consumes the remaining units through the terminator rather than becoming an empty selection.

The function then calls F-475af1e83e55 with four arguments:

1. Context.
2. Selected beginning address.
3. The 32-bit address difference between the selected end and beginning.
4. The 32-bit all-ones value.

The submitted span excludes the terminating zero byte. An empty selection still causes this call.

This branch counts units but submits a byte length. Multibyte-shaped units can therefore contribute more than one byte to the submitted span.

### 6. Submit a discriminator-4 representation

If the normalized length is negative, this branch replaces the submitted length with zero.

It then calls F-11fa31a6deb4 with seven arguments, in order:

1. Context.
2. Acquired source address plus the low 32 bits of the normalized start.
3. The low 32 bits of the normalized length, after any negative-length clamp.
4. The 32-bit all-ones value.
5. Context again.
6. Selector.
7. Argument-vector address.

The address calculation does not clamp an excessive start. Even with a zero submitted length, the supplied pointer can be beyond the acquired range. Whether the dependency accepts that combination is unknown.

## Side effects

No direct writes to the argument vector, context, object, or acquired source bytes are visible in this function.

Observable activity consists of:

- Reading the discriminator, arguments, optional context fields, and text bytes.
- Calling acquisition and decoding dependencies.
- Calling exactly one submission dependency after successful acquisition, provided intervening accesses and calls complete.
- Returning without submission when acquisition yields null.

Dependency effects remain unrestricted by the supplied evidence. In particular:

- No dependency is established to preserve globals, the argument vector, context fields, or source storage.
- No acquisition result is established to be owned, borrowed, immutable, or permanently valid.
- No release operation is visible.
- No local allocation is visible.
- Passing a pointer to a submission dependency does not establish copying or ownership transfer.

The text source is counted before decoding and traversed after decoding. If a decoder mutates or invalidates that source, the later traversal need not match the earlier count. The function neither snapshots the bytes nor recounts them.

A conventional safe-use precondition is that the acquired storage remains readable for every subsequent access. For the text branch, reachable zero termination is additionally required. For the discriminator-4 branch, any stronger pointer or extent requirements depend on F-11fa31a6deb4.

## Acceptance examples

These are conditional static expectations, not runtime test results. Unless stated otherwise, assume stable readable storage, no relevant dependency mutations, and successful dependency completion.

### Null acquisition

- With discriminator 4, a null result from F-005c8b552c2d causes return after the length helper and acquisition call. No decoder or submission call follows.
- With another discriminator, a null result from F-95b79f0a129e causes return without counting, decoding, reading the default length, or submitting.

### Positive and zero starts

Given text `ABCDE`, decoded start 1, and explicit length 2, F-475af1e83e55 receives the address of `A` and byte span 2.

With the same source and length, decoded start 0 produces the same selection. Decoded start 2 selects `BC`.

### Negative starts

Given text `ABCDE`, decoded start −2, and requested length 2, normalization produces start 3 and length 2. The selected bytes are `DE`.

Given the same source, start −7, and requested length 4, adding source length leaves a start remainder of −2. The length is reduced to 2 and the start becomes zero. The selected bytes are `AB`.

### Endpoint truncation

Given text `ABCDE`, start 4, and requested length 99, normalization restricts the length to 2. The selected bytes are `DE`.

Given start 8 and requested length 1, normalization produces start 7 and length −2. The text start traversal reaches the terminator, so submission has a zero byte span.

For discriminator 4 with raw length 5 and the same decoded operands, submission instead receives the source address plus 7 and length zero.

### Negative requested length

Given text `ABCDE`, start 2, and requested length −1, normalization retains a negative length. The text traversal selects `BCDE` through the terminator.

With discriminator 4, raw length 5, and the same operands, the submitted pointer is the source address plus 1, but the submitted length is zero.

### Byte grouping

Given bytes `41 C2 A2 42 00`, the counted length is three units. Start 2 and length 1 select bytes `C2 A2`, with submitted byte span 2.

Given bytes `80 81 41 00`, the counted length is three units, not two: both initial continuation-shaped bytes stand alone.

### Read ordering

If the first decoder changes argument entry 2, selector 3 causes the second decoder to receive the changed entry.

If the first decoder changes the context’s default-length field, a selector other than 3 causes the later default-length read to observe that changed field, subject to normal memory validity.
