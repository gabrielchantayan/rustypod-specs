# F-8246b81c51c0

## Purpose

F-8246b81c51c0 validates an indexed selection within a caller-supplied context and, when a nonzero output address is supplied, performs a sequence of dependency calls before writing a one-byte status derived from the selected record.

The established status rule is:

- Write zero only when two 32-bit record fields compare equal and bit 3 of a separate record byte is clear.
- Write one otherwise.

A valid index returns the 32-bit value zero, including when no output is requested. An invalid index returns the 32-bit bit pattern `0xFFFFFFCE`, equivalent to −50 when interpreted as a signed 32-bit integer.

The meaning of the dependency sequence is not established. Numeric conversion, numeric processing, and stateful setup are possible interpretations, but none is required by the available evidence.

## Behavior

### Index acceptance

The index is accepted only when both conditions hold:

1. Its signed 32-bit interpretation is nonnegative.
2. Its unsigned value is strictly less than the unsigned 32-bit count read from the context.

Thus, an accepted index must lie between zero and `0x7FFFFFFF`, inclusive, and must also be below the current count. A count greater than `0x80000000` does not make high-bit-set indices acceptable.

The signed test is evaluated first. When the index has its high bit set, rejection occurs without reading the count. When the signed test passes, the count is read to evaluate the unsigned upper bound.

If either condition fails, the function returns `0xFFFFFFCE`. It performs no selected-entry traversal, dependency calls, or output write on that path.

### Selected-record resolution

After accepting the index, the function resolves the selected record by:

- Reading the table address from the context.
- Reading the selected entry address from a four-byte table slot.
- Reading the record address from offset `+0x20` of that entry.

This resolution occurs even when the output address is zero.

The resulting record address is retained for subsequent operations. Later dependency calls are not followed by a fresh table traversal or a fresh read of the entry’s record-address field.

If the output address is zero, no further processing is visible: the function returns zero after resolving the record address. In particular, the record’s status fields and the auxiliary-object chain are not read on that path.

### Dependency sequence when output is requested

For a nonzero output address, the following call sequence is established:

1. Read the auxiliary-object address from the context, then its byte at `+0x904`. Supply that byte to F-9e5e664c8ae7 and retain its 64-bit result.
2. Read the selected record’s 32-bit field at `+0x5C`. Supply it to F-00b046cf541b and retain the 32-bit result.
3. Read the selected record’s 32-bit field at `+0x68`. Supply it to F-00b046cf541b and retain the 32-bit result.
4. Call F-450415463608 with the result originating from `+0x68` first and the result originating from `+0x5C` second.
5. Call F-0ec3a2a1b51e with no explicit arguments and retain its 64-bit result.
6. Call F-c4b34006a13c with four 32-bit arguments: the low half of that result, its high half, and the two fixed-location data values in their established argument positions. Retain the 64-bit result.
7. Call F-c6bfc9d0fb36 with four 32-bit arguments: the low and high halves of the F-c4b34006a13c result, followed by the low and high halves of the earlier F-9e5e664c8ae7 result.

### Status calculation and output

After F-c6bfc9d0fb36 returns, the function compares the 32-bit fields at record offsets `+0x90` and `+0x9C`.

- If the fields differ, it writes one to the output byte. The byte at `+0x8F` is not read.
- If the fields are equal, it reads the byte at `+0x8F`.
  - If mask `0x08` is clear, it writes zero.
  - If mask `0x08` is set, it writes one.

Other bits in the flag byte do not affect the result.

The ordering of the two comparison-operand reads is not established by the supplied expression. Both occur after the dependency sequence. Their values are therefore not necessarily the values present at function entry.

The output write is one byte wide and occurs after all dependency calls and all status reads required by the selected branch. Normal completion then returns zero.
