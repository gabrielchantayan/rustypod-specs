# F-13d998268402

## Purpose

F-13d998268402 prepares an opaque target, copies a four-component region, conditionally replaces its first component, replaces its second component using a separate query, and invokes a final operation with the resulting local region.

The apparent intent is to configure and position a drawable or text-like object. That interpretation is inferred. The established behavior consists of dependency calls, reads from context and global storage, arithmetic, local writes, and final argument forwarding.

Three preparation arguments come from **three distinct global data locations**, designated **global A**, **global B**, and **global C**. Their contents are read at different stages of execution. They are not established constants, entry-time snapshots, or resource references supplied by the caller. Earlier dependencies may change the values subsequently read.

The function has no explicit return value, success check, cleanup operation, or restoration operation.

### Region capture

Only after F-ccb5d9751852 returns does the function copy the caller’s region into local storage.

The four reads occur in component order:

1. Left.
2. Top.
3. Right.
4. Bottom.

Consequences:

- The region is not captured at entry.
- Changes made by earlier dependencies can affect the copied values if those dependencies can reach the caller’s region.
- The function’s subsequent arithmetic uses its local copy rather than rereading the caller’s region.
- Copying all four components at entry would not preserve the established ordering.

The function itself does not write the caller’s region. This is not a guarantee that dependencies leave that storage unchanged.

### Conditional left replacement

The function calculates a signed 32-bit span as copied right minus copied left. It then invokes F-7ec5c59748e6 with the target and compares the signed result with that span.

If the first result is greater than or equal to the span:

- No second query occurs.
- Local left remains the copied left value.

If the first result is strictly less than the span:

- The span is calculated again from local right and local left.
- F-7ec5c59748e6 is invoked a second time with the target.
- Local left becomes one plus the signed integer quotient of the span minus the **second** result, divided by two.

For representable operands and intermediate results, division truncates toward zero. The first query result controls branch selection only; it is not reused as the replacement operand.

The copied left value is not added to the replacement. Accordingly, this expression does not generally produce an absolute center position within a region whose left component is nonzero.

The second result is not compared against the span. It can equal or exceed the span, or differ otherwise from the first result, without causing a new branch or rejection. There is no clamp, containment check, or nonnegative-result requirement.

The arithmetic includes separate signed subtractions and an addition. Their intermediate results matter: a mathematically representable final value does not establish defined execution if an earlier signed operation is outside range. Portable wraparound behavior is not established.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless otherwise stated, they assume valid storage, normally returning dependencies, adequate scratch initialization, and representable arithmetic.

### Global B changes during preparation

Suppose global B initially contains a value designated B-old. F-33ca0546dba1 changes it to B-new before returning, and no intervening activity changes it again.

F-6489b8f5efca receives B-new as its second argument. Passing an entry-time snapshot of B-old would violate the read contract.

### Global C changes in the preceding dependency

Suppose F-6489b8f5efca changes global C to C-new before returning, with no further change before its read.

F-ccb5d9751852 receives C-new. A value captured before F-6489b8f5efca would not be an acceptable substitute merely because global C appears resource-like.

### Initial global read

This does not establish an order between that read and the reads of context fields `0x38` and `0x44`. An acceptance criterion requiring a particular relative order would exceed the evidence.

### Smaller query result

For copied region `(10, 20, 110, 90)`, the span is `100`.

If both target queries return `60`, the second query occurs and local left becomes `21`. It does not become `31`; the original left is not added.

If scratch offsets `4` and `12` contain `7` and `30`, the region supplied to the final operation is `(21, 19, 110, 90)`.

### Equality and larger first results

For the same copied region, a first query result of `100` or `120` causes no second query. Left remains `10`.

The scratch query, top replacement, and final operation still occur.

### A changing second result

For span `100`, a first result of `60` selects the replacement branch. If the second result is `80`, left becomes `11`.

If the second result instead is `105`, the difference is `−5`; division by two truncates to `−2`, and left becomes `−1`. No recheck or clamp occurs.

### Odd difference

For span `101` and both results equal to `60`, the difference is `41`. Its quotient by two is `20`, so left becomes `21`.

### Top ignores copied top

If scratch offsets `4` and `12` contain `20` and `10`, top becomes `−14`, irrespective of the copied top value.

### Region changes before capture

If a preparation dependency changes the caller’s region and that change is visible before copying, the changed components are copied. Capturing the region before preparation would not preserve this behavior.

### Arithmetic outside range

If right minus left exceeds the signed 32-bit range, these examples impose no wrapped-result requirement. Such a case remains outside the established portable arithmetic contract.
