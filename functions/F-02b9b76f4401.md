# F-02b9b76f4401

## Purpose

F-02b9b76f4401 coordinates a stateful, multi-pass operation over records embedded in a caller-supplied object. It performs an entry check, conditionally initializes and processes eligible records, updates lifecycle and completion flags, and performs common exit processing.

The established behavior is a control-flow and memory-update contract. The application meaning of the records, lifecycle states, and dependency results is not established. Terms such as “pending,” “retry,” and “completion” below describe their observed control-flow roles, not confirmed domain semantics.

## Interface

**Input:** one pointer to a mutable object.

**Output:** a 32-bit integer result. Locally selected results are 0, 3, 5, and 6. Nonzero results from F-ded3a296d24a can also become the returned result, subject to the common exit check overriding them with 3.

The supplied representation uses 32-bit integers and pointer-bearing fields, with byte accesses to selected locations. Offsets below are byte offsets from the object pointer. A byte write changes only that byte, not the surrounding 32-bit field.

## Behavior

### 1. Entry check and initial classification

The function first reads the 32-bit value at 0x1380 and passes it to F-f0216cff9365.

If that dependency returns nonzero, the function returns 3 immediately. None of this function’s common exit writes or exit calls occur on that path. Effects of the entry dependency itself remain possible.

After a zero entry result, the tentative result is 3.

The function then checks:

1. Whether the byte at 0x1390 equals 3.
2. Only if that comparison is false, whether the byte at 0x123D is nonzero.

Either condition routes directly to common exit processing with tentative result 3.

Otherwise, the lifecycle byte at 0x1384 determines the next action:

- **4:** common exit with tentative result 6.
- **0 or 1:** perform initialization and record processing.
- **3:** common exit with tentative result 0.
- **2 or any value above 4:** common exit with tentative result 3.

The lifecycle value used for this classification is read once at this point.

### 2. Initialization

For lifecycle 0 or 1, direct writes occur in this order:

1. Set 0x1392 to 0.
2. Set 0x13B8 to 0.
3. Set lifecycle 0x1384 to 2.

If the byte at 0x106C equals 2, processing stops here and common exit runs with tentative result 3.

Otherwise, the 32-bit field at 0x1070 is cleared, and the primary indirect dependency at table displacement 0x34 is called with the object.

If that indirect call returns nonzero, the remaining setup calls are skipped, but processing continues with the progress-flag update below. Its nonzero result is not propagated as an error.

If it returns zero:

- Read the enable byte at 0x0010.
- Only when enabled, read the value at 0x001C.
- If enabled and that value is nonzero, call F-c28c816f21e1 with that value and the address at 0x0058. Its result is not used.
- Call the secondary-object dependency at table displacement 0x08, passing the secondary object and the address at 0x0058.
- If successful, call the secondary-object dependency at displacement 0x18 with the address at 0x1088.
- If successful, call the secondary-object dependency at displacement 0x10 with the 32-bit value at 0x1058.
- If successful, call F-dde43ad891e7 with the main object.

The latter four calls are short-circuited in that order: any nonzero result prevents subsequent setup calls and routes to common exit with tentative result 3. The secondary-object pointer is obtained for each indirect call; it is not established as immutable across calls.

After successful setup, or after the primary indirect call returns nonzero, set 0x1385 to 1.

If 0x1391 is **exactly 1**, common exit runs with tentative result 5. Other nonzero byte values do not take this early branch.

Otherwise, read the unsigned 32-bit field at 0x108C. Values greater than 0x493E0 cause a write of 1 to 0x13B0. An unconditional write of 1 to 0x13B0 follows. Thus, in ordinary memory, the resulting value is 1 regardless of the inspected value; the high-value case has two explicit stores.

### 3. Initial record passes

First, scan records in ascending index order. Whenever a discriminator equals 1, clear 0x13C7. This flag is not set by this function, including when no matching record exists.

Next, process records in ascending index order:

- Skip discriminators 2 and 3.
- Clear the eligible record’s byte at 0x128D + 0x50 × index.
- Call F-ded3a296d24a with the object, index, and mode 0.
- On a nonzero result, enter common exit with that exact 32-bit result.
- On success, read the record’s pending indicator. Any nonzero value makes the aggregate “all clear” condition false for this pass.

The aggregate is sticky within a pass: a later clear record does not undo an earlier pending observation.

After the entire pass succeeds, set 0x1392 to 1 and then 0x13B8 to 1.

If all eligible records were clear, perform an ascending completion pass. For each currently eligible record:

1. Call F-344a964dedb2.
2. Only on zero, call F-0f331775ec1e.

A nonzero result from either dependency routes to common exit with result 3, not the dependency’s numeric result.

After a successful completion pass, set 0x106D to 0 and proceed to the lifecycle completion write.

### 4. Pending records and retry passes

If the initial record pass observed any pending record, set 0x106D to 1.

Read 0x13B0. If it is nonzero, perform up to four retry passes. Although this function previously wrote 1 there, intervening dependencies may have changed it.

Each retry pass:

- Traverses records in descending index order.
- Skips discriminators 2 and 3.
- Calls F-ded3a296d24a with mode 0.
- Immediately propagates a nonzero result through common exit.
- Reads each successfully processed record’s pending indicator and accumulates whether all eligible records are clear.

If a retry pass observes all eligible records clear, run the ascending completion pass described above. Successful completion clears 0x106D.

If a retry pass still observes pending records, write 1 to 0x106D. After four unsuccessful passes, proceed to the fallback pass. If 0x13B0 was zero, proceed directly to that fallback.

A reverse pass starts from the record count read at that pass’s entry. It does not re-read the count to extend or shorten that already-started traversal.

### 5. Fallback processing

The fallback pass traverses records in descending order. For each eligible record, call:

1. F-6bae58038ce6.
2. F-ded3a296d24a with mode 1.
3. F-344a964dedb2.
4. F-0f331775ec1e.

Each call occurs only if the preceding call succeeded.

A nonzero result from F-ded3a296d24a is propagated exactly. A nonzero result from any of the other three dependencies becomes result 3.

After all four calls succeed for a record, read its pending indicator. On successful completion of the whole fallback pass, write 0 to 0x106D if all eligible records were clear; otherwise write 1.

Whether records remain pending does not itself make this path fail.

### 6. Lifecycle completion and common exit

After successful record processing, write lifecycle 0x1384 to 4 and select tentative result 0.

Every path except a failed entry check then performs common exit processing:

1. Clear byte 0x13B1.
2. Traverse records in ascending order, regardless of eligibility. For each record, clear 0x128D + 0x50 × index, then clear 0x128C + 0x50 × index.
3. Call F-2bb3dbfa7286 with the current 32-bit value at 0x1380 and the address at 0x13A8.

If this exit dependency returns nonzero, return 3 immediately. No subsequent status write or special-exit call occurs. Earlier writes remain in place.

Otherwise:

- If the tentative result equals 5, or the current byte at 0x1391 is nonzero, set lifecycle 0x1384 to 3 and call F-80af6d494137. Do not directly write 0x1390 on this branch. The return value of this dependency is ignored.
- On the other branch, if the tentative result equals 3, first set lifecycle to 0. Then write the low eight bits of the tentative result to 0x1390.

Return the full 32-bit tentative result.

The final special-exit decision is made after the exit dependency, so mutations made by that dependency can affect it. The result-5 condition short-circuits the read of 0x1391.

## Side effects

The function mutates the supplied object incrementally. Failure does not roll back initialization flags, record bytes, completed dependency effects, or lifecycle changes.

Important partial-state cases include:

- Initialization can leave lifecycle 2 before failing.
- A record-processing error can leave 0x1392 and 0x13B8 at 0 if it occurs during the initial processing pass.
- A later error can leave both flags at 1.
- An exit-dependency failure can return 3 while lifecycle remains 4 from successful processing.
- Common exit clears record bookkeeping bytes even for records excluded from processing.
- 0x1385 and 0x13C7 are not reset unconditionally.

Ascending loops compare against the current signed record count on each iteration. Dependency mutations to that count can therefore alter the remaining traversal. Reverse loops use a count read at the beginning of each pass.

No synchronization, exception recovery, diagnostic output, or direct memory allocation is established. Dependencies may have additional effects on memory or global state; preservation is not assumed.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless specified otherwise, dependencies return zero, preserve relevant fields, and all memory accesses are valid.

1. **Entry check fails.**  
   F-f0216cff9365 returns nonzero. The result is 3. No direct object writes or common exit call follow it.

2. **Lifecycle already 4.**  
   Early rejection flags are clear and lifecycle is 4. Record processing is skipped, but common exit clears bookkeeping bytes. The result is 6; 0x1390 becomes 6 when the special-exit indicator remains zero.

3. **Lifecycle already 3.**  
   Early rejection flags are clear. Processing is skipped, common exit runs, and the result is 0. Lifecycle remains 3 and 0x1390 becomes 0.

4. **Primary indirect setup call returns nonzero.**  
   Initial lifecycle is 0 or 1. The optional setup sequence is skipped, but processing continues after setting 0x1385. That return alone does not force result 3.

5. **Exact special-exit value 1 during initialization.**  
   Initialization reaches the check at 0x1391 and reads 1. Tentative result becomes 5; no record pass occurs. After successful common exit, lifecycle is set to 3 and F-80af6d494137 is called. The result remains 5.

6. **Initially clear eligible records.**  
   Initial mode-0 calls succeed and every observed pending byte is zero. The ascending completion calls run; no retry or fallback pass runs. Successful completion sets 0x106D to 0 and lifecycle to 4.

7. **Pending state persists through all retries and fallback.**  
   The retry-enable byte remains nonzero. Four reverse mode-0 passes run after the initial ascending pass. Fallback then runs in reverse order. If its calls succeed but pending bytes remain nonzero, the function still returns 0, with 0x106D equal to 1 and lifecycle equal to 4.

8. **Propagated result versus stored byte.**  
   F-ded3a296d24a returns 0x123. With successful common exit and a zero special-exit indicator, the returned integer is 0x123, while 0x1390 receives 0x23.

9. **Completion dependency fails.**  
   F-344a964dedb2 returns a nonzero value other than 3. The subsequent F-0f331775ec1e call for that record is skipped. The tentative result is normalized to 3.

10. **Exit operation fails after processing succeeds.**  
    Processing has written lifecycle 4. F-2bb3dbfa7286 returns nonzero. The result is 3, but the later lifecycle reset and stored-result update do not occur.

11. **Zero records.**  
    With count zero and ordinary successful setup, record passes make no indexed calls. The aggregate is clear, 0x106D becomes 0, and lifecycle becomes 4. Common exit still clears 0x13B1 and calls F-2bb3dbfa7286.
