# F-3c3879b3cad3

## Purpose

F-3c3879b3cad3 reads selected fields from a caller-supplied record, obtains six converted values, and performs a mode-dependent sequence of dependency calls. It translates a selected status into one of three 32-bit return words.

On mode 0 success, it additionally calls an external dependency, reads a global-held base address, writes a four-byte result at that base plus four bytes, then calls another external dependency with a separately loaded global value, the original record pointer, and integer 12.

The final external call is **not established to be a copy operation**. Its argument directions, memory-access extent, and interpretation of 12 are unknown.

The field selection and subtraction of 2000 suggest date/time-related intent. Field meanings, calendar validity, encoding, and units are not established.

This contract distinguishes static evidence from inferred intent and unresolved dependency behavior. All execution descriptions assume the preceding operations return normally and their memory accesses are valid.

## Behavior

### Common reads and conversions

The function performs six calls to F-b1cd68c6839f before testing the mode. Unsupported modes therefore do not bypass this phase.

The ordered read-and-call pairs are:

1. Read the unsigned 16-bit field at offset 0; subtract 2000; call the dependency.
2. Read the unsigned 16-bit field at offset 2; narrow it to a plain character; call the dependency.
3. Read the byte at offset 3; call the dependency.
4. Read the unsigned 16-bit field at offset 8; narrow it to a plain character; call the dependency.
5. Read the byte at offset 9; call the dependency.
6. Read the unsigned 16-bit field at offset 10; narrow it to a plain character; call the dependency.

Each returned value supplies one stored eight-bit result. These stores occur in conversion order, not in increasing address order.

Reads and calls are interleaved. The function does not capture the record before making the calls. If a dependency changes storage that aliases the record, a later field read can observe that change. In particular, the overlapping reads at offsets 2–3 and 3, or at offsets 8–9 and 9, need not observe a mutually consistent snapshot.

The ordered success sequence is:

3. Store the four-byte result returned by D-01 at the address given by the loaded base plus four bytes.

## Side effects

### Directly established effects

The visible body:

- Reads the selected record fields in the stated order.
- Stores six eight-bit conversion results in local storage.
- Passes local addresses to dependencies.
- Reads the shared-argument global once in either supported branch.
- On mode 0 success, calls D-01, reads the state-base global, performs one four-byte write, reads the final-argument global, and calls D-02.

Mode 0 success therefore contains three distinct global-value read sites; mode 0 failure and mode 1 contain only the shared-argument read site. This count excludes any reads performed inside dependencies.

No direct write to the record through its input pointer is visible. Record immutability nevertheless is not guaranteed: dependency effects and aliases are unknown. The computed four-byte destination is not established to be disjoint from the record or any global storage.

### Ownership and lifetime

The converted record and work areas are invocation-local storage. Their addresses are supplied to dependencies during execution.

No explicit allocation, release, or ownership transfer appears in the visible body. Dependency names, pointer arguments, and call ordering do not establish whether callees allocate, release, retain pointers, or preserve globals.

No direct release of the caller’s record is visible. Whether a dependency accesses, retains, modifies, or releases storage associated with an argument is documented_only. Safe use of retained local addresses after return is not established.

### Errors and partial progress

The function has no visible rollback.

A nonzero selected status does not undo earlier calls or their effects. In mode 0, the preparation and three-argument calls have already occurred before status translation.

On mode 0 success, the four-byte write precedes D-02. If D-02 does not return normally, no restoration of that write is visible. D-02’s ordinary return value cannot change the final zero result because it is ignored.

Invalid addresses, invalid computed destinations, dependency traps, nonlocal termination, and out-of-bounds dependency accesses have no explicit handling here. Their outcomes are documented_only.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Conversion placement and boundaries

If the six conversion results have low bytes 11, 22, 33, 44, 55, and 66 respectively, the converted record contains 66, 55, and 44 at offsets 0–2, and 33, 22, and 11 at offsets 4–6. This function establishes no value at offset 3.

For first-field values 1999, 2000, and 65535, the first conversion arguments are respectively −1, 0, and 63535 under the represented integer model. None is visibly rejected before conversion.

### Interleaved record reads

If conversion call 2 changes the record byte at offset 3 through an alias, conversion call 3 receives the subsequently read byte, not necessarily the byte present during the preceding 16-bit read.

### Mode 1 status and global timing

If F-1b1da0aa8204 changes the shared-argument global from one value to another before returning, the subsequent F-d8ce763ae82c call uses the later loaded value as argument two.

If F-3a5feb164526 returns `0x15`, the final result is `0xFFFFFFFA`. If it returns zero, the result is zero. Neither case invokes the explicit mode 0 success sequence.

### Mode 0 failure

If F-a8da4de9bd1d returns `0x15`, both subsequent F-1b1da0aa8204 calls and F-d8ce763ae82c still occur, including the late shared-argument load. The function then returns `0xFFFFFFFA` without calling D-01 or D-02 and without performing the explicit four-byte write.

### Mode 0 success and late state selection

If F-a8da4de9bd1d returns zero, a nonzero F-d8ce763ae82c return does not convert the invocation into a failure. That return becomes D-01’s argument.

If D-01 changes the state-base global before returning, the store uses the base loaded after that change.

If the four-byte store changes the final-argument global through an alias, D-02 receives the value loaded after the store.

D-02 must receive the original record pointer and integer 12 in argument positions two and three. No acceptance criterion requires a 12-byte copy or any particular record access by D-02.

### Unsupported mode

For mode 2, the six common conversions still occur. No deterministic return value can be required from the supplied evidence.
