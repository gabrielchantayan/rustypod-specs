## Acceptance examples

### Input forwarding and widths

Given input 0x89ABCDEF and a valid initial target, F-unknown-01 receives that exact 32-bit pattern.

Given a byte-store source of 0x1234ABCD, that access writes 0xCD only. Given an explicitly unsigned byte capture of 0xFE, its 32-bit stored value is 0x000000FE.

### Initial aliasing and reload

Given observable memory accesses, the secondary 0x14 clear occurs between the primary 0x05 byte capture and primary 0x34 store. A primary 0x14 reload follows that store and precedes the second secondary clear and both duplicate byte writes.

If secondary offset 0x14 aliases primary offset 0x34, the later secondary clear can overwrite the just-stored zero-extended byte. Moving both secondary clears together would not preserve this behavior.

### Retained base

Given the read at 0x087FBBBC produces base 0x2000, and the subsequent 0x60 write changes that source storage through environmental behavior, the repeated group still uses 0x2000. Its relevant retained-base destinations remain 0x2019 and 0x2034.

### Captured word versus fresh bytes

Given the 0xA9 capture is 0x12345678, the explicit 0x67 write supplies 0x78. If an intervening observable operation changes 0x67 to 0xAB before the copy to 0x21, that copy uses 0xAB.

If later aliasing writes change 0x67 again, each subsequent reload uses the byte available at its own position. The working-offset-0x44 word write still uses captured 0x12345678.

### Failure and terminal arguments

Given normal arrival at F-unknown-03, the captured third argument is not replaced with a reload of companion offset 0x14, even if that field changed.
