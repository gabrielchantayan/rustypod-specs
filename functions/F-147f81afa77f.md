# F-147f81afa77f

## Purpose

F-147f81afa77f classifies an input record against state held by a receiver and conditionally invokes one of two indirect operations on that receiver.

The established behavior has three outcomes:

- Return the 32-bit value **0** when the record has an unsupported discriminator or matches neither accepted condition.
- Invoke the receiver’s indirect operation at dispatch-table byte offset **0xD4**, then return the 32-bit value **1**, when the primary condition matches.
- Obtain a one-byte value from **F-5710a8628cba**, pass that value to the receiver’s indirect operation at dispatch-table byte offset **0xA0**, then return the 32-bit value **1**, when the secondary condition matches.

Primary matching takes precedence. Once the primary operation is invoked, the secondary condition is not examined.

A return value of 1 establishes that the selected indirect operation returned normally. It does not establish that the operation succeeded internally: this function does not inspect its return value.

The interpretation of the record as an event or message, and the interpretation of either operation as a particular application action, are inferred intent rather than established behavior.

## Interface

### Inputs

The function receives two inputs:

1. **Receiver:** an address used to access receiver state and an indirect-dispatch table.
2. **Record:** an address used to read three 32-bit fields.

The supplied representation supports a 32-bit address-and-integer model. The contract below uses byte offsets and 32-bit field widths. Portability to another pointer width is not established.

### Receiver layout

| Byte offset | Width | Established use |
|---|---:|---|
| 0x00 | 32 bits | Address of an indirect-dispatch table |
| 0x40 | 32 bits | Primary comparison word |
| 0x44 | 32 bits | Primary comparison key |
| 0x98 | 32 bits | Secondary comparison key |
| 0x9C | 32 bits | Secondary-enable field; zero disables the secondary path |

The two dispatch-table entries used are:

| Table byte offset | Established invocation |
|---|---|
| 0xD4 | Invoked with the receiver as its sole explicit argument |
| 0xA0 | Invoked with the receiver and a one-byte value obtained from F-5710a8628cba |

Other receiver fields and dispatch-table entries are not directly accessed by this function.

### Record layout

| Byte offset | Width | Established use |
|---|---:|---|
| 0x04 | 32 bits | Discriminator; must equal 0x00000013 |
| 0x08 | 32 bits | Comparison word used by either matching path |
| 0x0C | 32 bits | Comparison key, initially read once and retained for matching |

The field at offset 0x00 is not read by this function. Its meaning is unknown.

### External comparison data

Two distinct external 32-bit words participate in matching:

- **Primary alternate word:** an additional accepted value for the record word on the primary path.
- **Secondary required word:** the required value for the record word on the secondary path.

Their values, initialization, mutability, and relationship are not supplied. They must not be treated as known constants or assumed equal.

### Output

On normal return, the result is exactly one of these 32-bit values:

- **0:** no selected operation was invoked.
- **1:** one selected operation was invoked and returned normally.

The function exposes no separate error result.

### Preconditions

All memory accesses actually reached must be valid for their stated widths. Any reached indirect-dispatch entry must identify a callable target compatible with its invocation.

The function performs no explicit null, bounds, alignment, object-type, or callable-target validation. The record discriminator must be readable even on a rejected input.

Later preconditions are path-dependent. For example, rejection by discriminator does not require readable receiver fields or a valid dispatch table.

## Behavior

### 1. Discriminator gate

The first observable data read is the 32-bit discriminator at record offset 0x04.

If it is not 0x00000013, the function returns 0 immediately. On that path, it does not read receiver state, the other record fields, either external comparison word, or any dispatch entry.

If the discriminator matches, processing continues.

### 2. Primary key comparison

The function reads the 32-bit record key at offset 0x0C, then reads the receiver’s primary key at offset 0x44.

The record key read here is retained. The secondary path, if reached, compares this retained value rather than rereading record offset 0x0C.

If the keys differ, primary word matching is skipped. In particular, the primary path does not then read:

- Record offset 0x08.
- Receiver offset 0x40.
- The primary alternate word.

Processing instead advances to the secondary condition.

### 3. Primary word comparison

When the primary keys match, the function reads the record word at offset 0x08, then the receiver’s primary comparison word at offset 0x40.

The primary condition accepts either:

- Equality between those two words; or
- Equality between the record word and the external primary alternate word.

The external primary alternate word is read only when the record word differs from the receiver’s primary comparison word. Direct equality therefore avoids that external read entirely.

These are 32-bit equality comparisons. No range test, signed ordering, masking, normalization, or arithmetic transformation is applied.

### 4. Primary dispatch

When the primary condition accepts, the function:

1. Reads the dispatch-table address from receiver offset 0x00.
2. Resolves the callable entry at table byte offset 0xD4.
3. Invokes that entry with the receiver.
4. Returns 1 after the invocation returns normally.

The secondary-enable field is not read on this path. The secondary helper and secondary dispatch operation are not invoked.

The indirect operation’s return value, if any, is ignored.

### 5. Secondary enable and key comparison

The secondary path is reached only when the primary condition did not accept.

The function first reads the 32-bit field at receiver offset 0x9C. Any nonzero bit pattern enables the path; the field is not required to equal 1.

If the enable field is zero, the function returns 0 without reading the secondary key, the secondary required word, or any dispatch entry.

If enabled, the function reads the receiver’s secondary key at offset 0x98 and compares it with the retained record key.

If those keys differ, the function returns 0. It does not perform the secondary record-word read or read the external secondary required word.

### 6. Secondary word comparison

When the secondary path is enabled and its key matches, the function reads:

1. The 32-bit record word at offset 0x08.
2. The external 32-bit secondary required word.

These values must be equal for secondary acceptance. Otherwise, the function returns 0.

This access to record offset 0x08 is a new read. If primary word matching was attempted and failed, the same record field has already been read once earlier. The supplied behavior does not combine those accesses into a single retained value.

Consequently, reasoning that both comparisons necessarily observe the same word requires an additional stability assumption. The function itself does not provide a snapshot, lock, or other synchronization.

### 7. Secondary helper and dispatch

When the secondary condition accepts, the function invokes F-5710a8628cba with no explicit arguments.

It retains a one-byte value from that invocation. Only that byte is carried forward as the second explicit argument of the secondary dispatch operation. The supplied representation does not establish the helper’s full return width or the precise machine-level argument-extension convention.

After the helper returns, the function:

1. Reads the receiver’s dispatch-table address at offset 0x00.
2. Resolves the callable entry at table byte offset 0xA0.
3. Invokes that entry with the receiver and the retained byte.
4. Returns 1 after the invocation returns normally.

The dispatch-table lookup occurs **after** F-5710a8628cba returns. The contract must not assume that the helper preserves the receiver, its dispatch-table address, or globals. A valid post-helper lookup is a precondition for normal completion of this path.

Neither the helper’s byte nor the indirect operation’s return value is tested for success or failure.

## Side effects

### Direct effects

F-147f81afa77f performs no explicit writes to receiver fields, record fields, or the external comparison words.

It conditionally performs one of these call sequences:

- One primary indirect invocation.
- F-5710a8628cba followed by one secondary indirect invocation.
- No invocation.

At most one of the two indirect operations is selected during a normal execution.

The absence of direct writes does not make the function side-effect-free. Its reached dependencies may mutate state or perform externally visible actions.

### Ownership and lifetime

No allocation, deallocation, reference-count adjustment, or ownership transfer is explicitly performed by this function.

The receiver is passed to the selected indirect operation. The record address is not explicitly passed to either indirect operation or to F-5710a8628cba.

No ownership or lifetime guarantee can be inferred for the dependencies. In particular:

- They are not established to preserve receiver storage.
- They are not established to preserve globals.
- They are not established to retain or release any resource.
- Their access to state through implicit mechanisms is unknown.

For normal secondary completion, receiver storage and the dispatch target must remain valid through the lookup and invocation following F-5710a8628cba.

### Errors and abnormal control flow

No explicit error handling surrounds memory reads or dependency invocations.

The supplied evidence does not establish behavior for invalid addresses, invalid dispatch entries, dependency failures, nonlocal exits, or dependencies that never return. Such cases must not be assigned a normal result of 0 or 1 merely because the function has only those normal return values.

There is no loop, retry, or fallback after a selected operation is invoked.

## Acceptance examples

These examples are conditional behavioral expectations derived from static evidence, not executed tests. Unless an example concerns early rejection, assume every reached access is valid and every reached invocation returns normally.

### Unsupported discriminator

Given a discriminator of 0x00000012:

- Result: 0.
- No receiver access.
- No key or comparison-word access.
- No dependency invocation.

### Direct primary match

Given discriminator 0x00000013, equal primary keys, and equal record and receiver primary words:

- Invoke the operation at dispatch offset 0xD4 with the receiver.
- Return 1.
- Do not read the primary alternate word.
- Do not inspect secondary enablement.

### Alternate primary match

Given matching primary keys, a record word different from the receiver’s primary word, and an equal primary alternate word:

- Read the primary alternate word.
- Invoke the operation at dispatch offset 0xD4.
- Return 1.
- Do not attempt secondary matching.

### Primary key mismatch with disabled secondary path

Given a supported discriminator, different primary keys, and a zero secondary-enable field:

- Return 0.
- Do not read record offset 0x08.
- Do not read either external comparison word.
- Do not read the secondary key.

### Enabled secondary path with a different key

Given primary rejection, any nonzero enable value, and a secondary key different from the retained record key:

- Return 0.
- Do not perform the secondary read of record offset 0x08.
- Do not read the secondary required word.
- Do not invoke F-5710a8628cba.

### Full secondary match

Given primary rejection, enabled secondary matching, an equal secondary key, and a record word equal to the secondary required word:

- Invoke F-5710a8628cba once.
- Retain its one-byte result.
- Resolve dispatch offset 0xA0 after the helper returns.
- Invoke that operation with the receiver and retained byte.
- Return 1, including when the retained byte is zero.

### Both conditions would accept

Given values under which primary matching accepts and secondary matching would also accept if examined:

- Only the primary operation is invoked.
- The secondary-enable field and secondary matching data are not read.
- F-5710a8628cba is not invoked.

### Record word changes between reads

Conditionally, in an execution environment where intervening changes to the record word are valid and observable:

- A failed primary word comparison does not fix the value used by secondary matching.
- Secondary matching uses its later read.
- The key comparison still uses the initially retained record key.

This example does not establish a concurrency or memory-mapped-I/O model.
