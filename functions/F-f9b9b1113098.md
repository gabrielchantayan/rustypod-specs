# F-f9b9b1113098

## Purpose

F-f9b9b1113098 conditionally copies one 32-bit word from a source record to a caller-supplied destination.

The operation succeeds only when:

- The source pointer is non-null.
- The source record’s first 32-bit word equals a separately stored 32-bit reference value.
- The destination pointer, converted to an unsigned 32-bit integer for the acceptance check, is nonzero.

On success, the function copies the source word at byte offset 8 into the destination and returns zero. Otherwise, it returns the 32-bit value 26 without writing through the destination.

The comparison suggests a record-validity or type-marker check, but that interpretation is inferred intent. The established behavior is an equality comparison against mutable external storage, not proof that the source is allocated, accessible, correctly typed, or otherwise safe.

| Argument | Role | Required accessible storage when used |
|---|---|---|
| Source | Identifies a record whose first word is checked and whose third word may be copied | Four readable bytes at offset 0 for the check; four readable bytes at offset 8 on the success path |
| Destination | Identifies the location receiving the copied word | Four writable bytes on the success path |

The source record has the following relevant layout:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Compared with the external reference word |
| 4 | 32 bits | Not accessed by this function |
| 8 | 32 bits | Read and copied on success |

No record length, destination capacity, alignment indicator, or ownership descriptor is passed.

The destination’s existing contents are not read by this function.

### External input

A separate storage location supplies the 32-bit reference word used to accept or reject the source. Its value is not specified by the supplied evidence.

This location is accessed only when the source pointer is non-null. There is no visible initialization, refresh, or update of that location within this function, except for the possibility that the caller supplies a destination that aliases it.

### Return value

The return value is 32 bits:

- **0:** The acceptance checks passed and the destination assignment completed.
- **26**, equivalently **0x0000001A:** The source pointer was null, the source’s first word did not match the reference word, or the destination failed the unsigned 32-bit address check.

No symbolic error name is established. In particular, the numeric value must not be assigned an operating-system or library-specific meaning without additional evidence.

### Width and address-model constraints

The visible operations use 32-bit record words and a 32-bit unsigned conversion of the destination pointer. The copy preserves the entire 32-bit payload, including its high bit. There is no arithmetic interpretation, sign extension, narrowing, or byte-order conversion of that payload.

If pointers can be wider than 32 bits, the observed predicate instead depends on the converted 32-bit address value. A non-null pointer whose conversion produces zero would be rejected. The supplied evidence does not independently establish a wider-address execution model or its pointer-conversion rules.

## Behavior

### Source classification

The function first classifies the source:

1. A null source is rejected without reading source storage or the reference word.
2. For a non-null source, the first 32-bit source word is compared with the external reference word.
3. Equality accepts the source for the subsequent destination check; inequality rejects it.

The source-word and reference-word reads both precede any successful payload copy. Their relative evaluation order is not established by the supplied expression and should not be made part of a portable contract.

A non-null source is not necessarily safe to read. If the first word is inaccessible, the attempted comparison may fault or otherwise fail outside the function’s explicit return-value mechanism.

### Destination acceptance

Source acceptance is represented by a binary condition. The function combines an all-zero or all-one 32-bit mask derived from that condition with the destination’s unsigned 32-bit address representation.

The resulting behavior is:

| Source condition | Converted destination value | Result |
|---|---|---|
| Null source | Any value | Return 26; no destination write |
| Non-null source, first word mismatches | Any value | Return 26; no destination write |
| Non-null source, first word matches | Zero | Return 26; no destination write |
| Non-null source, first word matches | Nonzero | Attempt the payload copy; return 0 if it completes |

This check does not establish destination writability. It also does not establish that the destination points to an allocated object of sufficient size.

A matching source with a rejected destination does not cause the payload at offset 8 to be read.

### Successful transfer

After both acceptance conditions pass, the function:

1. Reads the 32-bit source word at byte offset 8.
2. Writes that value into the 32-bit destination word.
3. Returns zero.

The payload read precedes the destination write. There is no visible recheck of the source’s first word or the external reference value between classification and transfer.

The function does not read the source word at offset 4 and does not explicitly modify either source word used by the operation. A source modification can nevertheless result from destination aliasing.

### Failure and exceptional access

The explicit rejection paths return 26 and perform no destination write. They do not clear, initialize, or restore the destination.

An invalid memory access is distinct from explicit rejection. The function contains no visible mechanism for converting an inaccessible source word, inaccessible reference word, inaccessible payload, or unwritable destination into return value 26. No normal return is guaranteed after such an access fails.

There is no visible rollback mechanism.

## Side effects

The only explicit memory write is the successful 32-bit destination assignment.

For an ordinary non-aliasing call:

- Source storage is unchanged.
- The external reference storage is unchanged.
- Destination storage is overwritten only on success.
- No allocation, release, ownership transfer, logging, or external function call is visible.

Aliasing changes which storage the destination assignment affects:

- **Destination aliases source offset 0:** The payload replaces the source’s first word after the original first word has passed comparison.
- **Destination aliases source offset 8:** The payload is read and written back to that location.
- **Destination aliases source offset 4:** The otherwise unused middle word is overwritten with the payload.
- **Destination aliases the external reference word:** The reference value is overwritten after its use in the comparison, potentially changing later calls.

These cases remain conditional on the relevant accesses being valid under the execution environment. The evidence does not establish support for misaligned or partially overlapping word accesses.

The function supplies no visible synchronization, lock, or atomicity guarantee. Concurrent changes to the source or reference can separate the checked state from the copied state. The source marker and payload are not established as a coherent snapshot.
