# F-3ad089816aa7

## Purpose

F-3ad089816aa7 searches a linked, ordered structure using an incoming 32-bit value and conditionally delegates insertion. It returns a 32-bit result together with a one-byte indication of whether the insertion path was taken.

The established behavior is narrower than a complete container contract:

- Search direction depends on whether a comparison dependency returns zero or nonzero.
- A control byte can bypass duplicate checking.
- With duplicate checking enabled, the function may return an existing candidate without invoking insertion.
- Both insertion paths use the last node visited during the initial search, not necessarily the candidate later examined for duplication.

**Inferred intent:** this resembles ordered-tree insertion with optional uniqueness enforcement. The link traversal resembles predecessor selection, and the nonzero control-byte mode resembles duplicate-permitting insertion. These interpretations are not prerequisites for describing the actual branches. Comparator ordering, sentinel conventions, and insertion semantics remain dependency contracts.

## Interface

### Inputs

The function receives three arguments:

1. **Result destination:** an address at which the function directly writes:
   - A 32-bit result at byte offset 0.
   - An 8-bit status at byte offset 4.

2. **Container address:** a 32-bit address used to locate structure fields and embedded comparison state.

3. **Incoming value:** an opaque 32-bit quantity forwarded to comparison and insertion dependencies. The function does not directly dereference it.

There is no explicit return value.

### Result layout

| Offset | Width | Established meaning |
|---|---:|---|
| 0 | 32 bits | Candidate address on the no-insertion path, or a word obtained from an insertion dependency’s output slot |
| 4 | 8 bits | 0 for the candidate-return path; 1 after an insertion dependency returns |

The function does not directly write bytes beyond offset 4. No full size, alignment, or ownership contract for the caller’s result object is established beyond these accesses.

A status of 1 records that an insertion dependency returned and its output was copied. It is not independently validated evidence that allocation or insertion succeeded.

### Container fields accessed directly

| Byte offset | Width | Use |
|---|---:|---|
| 16 | 32 bits | Address of a header or sentinel-like object |
| 24 | 8 bits | Zero enables duplicate checking; nonzero bypasses it |
| 25 | Address only | Embedded state address passed to the comparison dependency |

The extent and representation of the comparison state beginning at offset 25 are unknown.

### Header and node fields accessed directly

Addresses stored in the structure are treated as 32-bit pointers.

| Object | Byte offset | Width | Use |
|---|---:|---:|---|
| Header | 4 | 32 bits | Initial search node |
| Header | 8 | 32 bits | Boundary value supplied to a helper |
| Node | 0 | 8 bits | Marker examined during candidate adjustment |

The header and node roles may overlap. The function relies on structural conventions that make its sentinel-related dereferences valid.

### Preconditions

For defined execution, every address actually read or written on the selected path must be valid for the indicated access. This includes dependency-visible objects and any parent or child links followed during candidate adjustment.

The function performs no null check on the result destination, container, or header before use. A null search-node pointer is an accepted termination condition; null is not generally accepted for other dereferences.

Termination requires the initial search and any subsequent link walks to reach their respective stopping conditions. Malformed cycles can prevent termination.

## Behavior

### 1. Establish the search position

The function starts with a nonzero comparison state, numerically 1.

It reads the header address from container offset 16, then reads the initial node from header offset 4. It separately reads container offset 16 again to establish the fallback last-visited address.

Thus, for an empty initial search, the fallback is the header obtained by that second read. The two header reads are distinct in the supplied evidence; the function does not explicitly enforce a stable snapshot.

### 2. Descend through the structure

For every nonnull search node, the function:

1. Resets two local 32-bit scratch words to zero.
2. Calls F-a073c1bc0f3f with:
   - The address at container offset 25.
   - The incoming value.
   - The address at node offset 16.
3. Records that node as the last visited node.
4. Reads the next link from the node:
   - Comparison result zero: follow offset 12.
   - Comparison result nonzero: follow offset 8.

Only zero versus nonzero matters. Negative and positive nonzero return values select the same branch.

The payload address is passed to the dependency rather than read directly by this function. The next link is read after the comparison returns, so mutations by that dependency can affect the next search step.

When a null link terminates the search, the function retains the final comparison result and last visited node. If no node was visited, these remain the initial nonzero state and fallback header address.

### 3. Read the duplicate-check control byte

After the search, the function reads the byte at container offset 24.

- **Nonzero:** proceed directly to the general insertion path.
- **Zero:** perform the candidate and duplicate checks below.

This read occurs after all initial-search comparison calls. The function does not cache this byte before those calls.

### 4. Establish a candidate when duplicate checking is enabled

The candidate initially becomes the last visited address.

If the final comparison result is zero, no boundary helper or candidate adjustment is performed.

If the final comparison result is nonzero, the function:

1. Reloads the header address from container offset 16.
2. Reads the 32-bit field at header offset 8 into a local word.
3. Calls F-3ee46ff4f2dc with the address of the local candidate slot and the address of that local word.

Both arguments are addresses of local storage. The function subsequently uses the candidate slot as it exists after the helper returns; candidate preservation is not established.

If the helper returns nonzero, the function takes the early insertion path immediately. It does not extract a candidate value or perform the final comparison.

If the helper returns zero, the function adjusts the candidate through node links.

### 5. Adjust the candidate after a zero boundary-helper result

The adjustment begins by reading the candidate’s first byte.

If that byte is zero, the function reads the candidate’s offset-4 link and then the offset-4 link of the resulting object. If this second link equals the candidate address, the candidate is replaced by its offset-12 link, completing the adjustment.

Otherwise, including when the first byte is nonzero, the function uses the ordinary link-walk branch:

- Read the candidate’s offset-8 link.
- If it is nonnull, enter that linked node and repeatedly follow offset-12 links until the current node’s offset-12 link is null. The terminal node becomes the candidate.
- If the offset-8 link is null, read the offset-4 link and ascend. At each step, compare the prospective parent’s offset-8 link with the previous candidate, then promote that parent to candidate. Continue ascending while the comparison matches.

**Inferred intent:** this resembles predecessor selection using a sentinel special case, descent into one subtree, or ascent through parents. The established acceptance condition is the exact link behavior above, not an independently verified ordering property.

The walk has no explicit depth bound or malformed-structure recovery.

### 6. Compare the candidate with the incoming value

Unless the boundary helper selected early insertion, the function calls F-f8ae48a15441 with the current candidate address.

It passes that dependency’s 32-bit return value to F-a073c1bc0f3f as follows:

- First argument: address at container offset 25.
- Second argument: extracted candidate value.
- Third argument: incoming value.

This differs from the initial search calls, where the incoming value is the second argument and a node payload address is the third.

If this final comparison returns zero:

1. Write the current candidate address to result offset 0.
2. Write status byte 0 to result offset 4.
3. Return without calling the insertion dependency.

If the comparison returns nonzero, take the general insertion path.

The candidate address returned here is the locally held candidate. The extraction or comparison dependencies may have changed the structure; this function does not revalidate that address afterward.

### 7. Delegate insertion

There are two insertion call sites, both invoking F-f4fac0eb5185 with:

1. Address of a local 32-bit output slot.
2. Container address.
3. A literal zero.
4. Last visited address from the initial search.
5. Incoming value.

The early path is selected by a nonzero boundary-helper result. The general path is selected by either a nonzero control byte or a nonzero final candidate comparison.

After the insertion dependency returns, the function copies the local output word to result offset 0, then writes status byte 1 to result offset 4.

The two sites use different local output slots. The wrapper neither validates the returned word nor exposes a separate insertion error channel.

## Side effects

### Direct writes

Outside dependency execution, the established caller-visible writes are:

1. A 32-bit write to result offset 0.
2. A subsequent 8-bit write to result offset 4.

The function does not directly update container or node fields.

Local scratch storage is modified during execution and exposed by address to the boundary and insertion dependencies. These dependencies may therefore affect later behavior by changing that storage.

### Indirect effects and ownership

Dependencies receive container state, candidate addresses, payload addresses, and local output addresses. Their mutation, allocation, release, callback, and global-state behavior is not established here.

In particular:

- No dependency is assumed to preserve the container or its links.
- No allocation or deallocation is directly visible in this function.
- Ownership transfer of the incoming value is undocumented.
- Ownership and lifetime of the 32-bit result depend on the selected path and dependency contracts.
- A returned candidate address is not copied into a new node by this function.

No alias checks are present. If the result destination overlaps the container or a node, the final result writes can modify that structure. Such aliasing is not established as supported.

### Errors and arithmetic

The function provides no explicit error return or recovery branch. It does not validate allocation outcomes, detect cycles, or guard invalid memory accesses.

Direct address arithmetic consists of fixed byte offsets. There is no visible element-count arithmetic or multiplication. Behavior when a required address-plus-offset is not valid in the target address space is not established.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid memory, terminating links, and dependencies that return normally.

### Duplicate checking bypassed

Given a nonzero control byte after the initial search:

- Neither the boundary helper nor the candidate-extraction dependency is called.
- The insertion dependency receives the last initial-search position and incoming value.
- Its output word is written before status 1.

### Empty search with duplicate checking bypassed

Given a null initial node and a nonzero control byte:

- No search comparison occurs.
- The fallback header from the second header read is supplied as the insertion position.
- The wrapper writes the insertion output followed by status 1.

### Early insertion selected

Given a zero control byte, a nonzero final search comparison, and a nonzero boundary-helper result:

- Candidate adjustment and final candidate comparison are skipped.
- Insertion uses the original last search position, even if the helper changed the local candidate.
- Status is 1 after the dependency returns.

### Existing candidate returned

Given a zero control byte and a final candidate comparison result of zero:

- The current candidate address is returned.
- Status is 0.
- The insertion dependency is not called.

This applies whether the candidate required link adjustment or was used directly after a zero final search comparison.

### Candidate permits insertion

Given duplicate checking enabled, no early insertion, and a nonzero final candidate comparison:

- The general insertion dependency is called.
- Its position argument remains the last initial-search position, not the adjusted candidate.
- The copied insertion result is followed by status 1.

### Nonboolean comparison result

Given a search comparison result of −1:

- The function follows node offset 8, exactly as for any other nonzero result.
- No signed-order interpretation is applied by this function.
