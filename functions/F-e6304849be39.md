# F-e6304849be39

## Purpose

F-e6304849be39 copies six 32-bit values obtained through an indirect object graph into six positions in a caller-supplied object. It also clears one adjacent 32-bit field for each copied value.

The established behavior is a sequence of reads and writes, not an atomic initialization or snapshot operation. The object graph is traversed again for each value. Destination writes can therefore affect later reads if the supplied storage overlaps the graph.

An initialization or refresh operation is a plausible intent, but the meanings of the six values and their adjacent cleared fields are not established.

## Behavior

### Graph traversal

For each transfer, the function:

- Reads the address-bearing field at destination + `0x128`.
- Uses that address to read one source-node address from the corresponding intermediate-object offset.
- Reads the source node’s four-byte value at offset `0x04`.

The intermediate-object address is not captured once and reused for all six transfers. Each transfer begins by reading it again. The same is true of the selected source-node addresses: their values are obtained when their respective transfers are reached.

If the graph is stable and does not overlap destination writes, all six traversals use the same intermediate object. Stability and non-overlap are caller conditions, not checks performed by the function.

### Normal completion with a stable, disjoint graph

If all accesses succeed, the graph remains unchanged, and graph storage does not overlap the written destination fields:

- Each copied-value field contains the value from its corresponding source node.
- All six cleared fields contain zero.
- No other destination bytes are explicitly written.
- Intermediate-object fields and source nodes are only read.

A copied value of zero is accepted without special treatment. Repeated source-node addresses are also accepted: the same source field is read again for each applicable transfer.

### Aliasing and changing memory

The function performs no overlap detection and creates no six-value snapshot.

Earlier destination writes can alter intermediate address fields or source values used later if storage overlaps. Later transfers then follow the addresses and values present when those reads occur. The resulting behavior can differ from copying six values from the graph as it existed on entry.

The source-level sequence also permits a destination clear to overwrite the source field just read for the same transfer. That transfer still uses the captured value, provided execution remains otherwise valid.

External mutation is not handled by synchronization in this function. Without the surrounding memory model, concurrent reads and writes cannot be assigned a stronger guarantee.
