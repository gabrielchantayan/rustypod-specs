# F-610221d5244d

## Purpose

F-610221d5244d conditionally creates a record, obtains two dependency-produced values, associates one of those values with a separately obtained handle, and invokes a final configuration operation. It returns the record only when the explicitly checked stages succeed. Otherwise, it returns a null pointer after the applicable cleanup calls.

The established behavior is a sequence of dependency calls, three record-field writes, conditional branches, and cleanup operations. The supplied evidence does not establish the application-level meaning of the record, its fields, or the handle.

The apparent intent is staged construction with failure cleanup. That interpretation does not establish ownership transfer, complete resource reclamation, or successful configuration beyond the conditions this function actually checks.

## Behavior

### Initial acquisition

The function first obtains an argument from a shared location and calls F-e12621595ccc with it.

If that call returns a null pointer, the function immediately returns a null pointer. No other dependency is called on this path, and no record field is written.

If it returns a non-null pointer, that pointer becomes the candidate record. The function does not initialize the record before invoking the next dependency.

### Record initialization

The following events occur in order:

1. F-83fcd2d25cd8 is called with the first input argument.
2. Its 32-bit result is written to the record at byte offset 0.
3. A 32-bit zero is written at byte offset 4.
4. F-c141a8d8555e is called with no explicit arguments.
5. Its 32-bit result is written at byte offset 8.

There is no failure check on the result of F-83fcd2d25cd8. In particular, a zero result at offset 0 does not itself prevent further construction or a successful return.

The zero written at offset 4 is an initialization write, not an established postcondition for every return. Later dependencies have unknown side effects and may have access to shared state or aliases.

### Checked construction stages

The result returned by F-c141a8d8555e is tested against zero after being stored.

- If it is zero, the function proceeds directly to record cleanup.
- If it is nonzero, F-c810c23e5619 is called with no explicit arguments.

The result of F-c810c23e5619 is then tested against zero.

- If it is zero, the function proceeds to record cleanup without calling the association dependency.
- If it is nonzero, F-754616bec4de is called with two arguments: the value read from record offset 8 at that point, and the nonzero result returned by F-c810c23e5619.

The read from offset 8 is significant. The first association argument is not necessarily identical to the earlier return from F-c141a8d8555e if an intervening dependency has changed that field through an alias. The supplied evidence does not establish that such modification occurs, but it also does not establish that dependencies preserve record contents or shared state.

The return from F-754616bec4de is tested against zero:

- Zero selects cleanup.
- Any nonzero value selects the final configuration call.

These are zero/nonzero tests, not positive/negative tests. A negative signed interpretation of a checked result does not by itself select failure.

### Final configuration and success

After a nonzero return from F-754616bec4de, the function calls F-75e0e102872c with:

- The nonzero handle-like result previously returned by F-c810c23e5619.
- The second original argument.
- The third original argument.

The function does not inspect a return value from this call. If the call returns normally, F-610221d5244d returns the candidate record pointer.

There is no explicit write of the handle into the three-word record, and there is no explicit change to the zero-initialized field at offset 4 during this success sequence. Any relationship established between the record and the handle must arise through dependency behavior, external state, or mechanisms not shown in the supplied evidence.

No cleanup dependency is called on the normal success path.

### Failure cleanup

After any failure following a non-null initial acquisition, F-ac669dc5909f is called with:

- The candidate record pointer.
- The value obtained from the shared location at cleanup time.

That shared value is read again for cleanup. The function does not retain and reuse the value supplied to the initial acquisition call. If an intervening dependency changes the shared location, the two calls can receive different values.

After F-ac669dc5909f returns, the function checks whether a nonzero handle was obtained from F-c810c23e5619. If so, it calls F-09da5253a1e1 with that handle. It then returns a null pointer.

Consequently:

- Failure of F-c141a8d8555e causes record cleanup only.
- A zero return from F-c810c23e5619 causes record cleanup only.
- A zero return from F-754616bec4de causes record cleanup followed by handle cleanup.
- Record cleanup precedes handle cleanup whenever both occur.

The function performs no explicit separate cleanup of the values stored at offsets 0 and 8. Whether record cleanup releases anything associated with those values is unknown.

## Side effects

- The result of F-c141a8d8555e is stored before F-c810c23e5619 can be called.
