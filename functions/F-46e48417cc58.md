# F-46e48417cc58

## Purpose

F-46e48417cc58 classifies an address-based record using a one-byte selector and one of three four-byte integer fields.

The result is a 32-bit value in the set {0, 1, 2, 3}. A nonzero result identifies the selected field, but only when that field has the numeric value 160. The result is zero when the selector is unsupported or the selected field has any other value.

This is a selective predicate, not an aggregate search. It does not check whether any field equals 160. It checks only the field designated by the selector, and a matching unselected field cannot produce a nonzero result.

The supplied static representation establishes these branches and accesses. It does not establish an application-level meaning for the selector, the fields, or the constant 160.

## Behavior

### Selector observation

The first explicit record access reads one byte at offset 0xA4.

That observed byte determines the remainder of the operation. There is no second explicit selector read, including after a selected integer field has been read.

The supported selector values are exactly 1, 2, and 3. Every other byte value produces a zero result without an explicit read of any of the three integer fields.

Whether the one-byte type is interpreted as signed or unsigned does not change this classification: only the representations for 1, 2, and 3 enter recognized branches.

### Selected-field evaluation

For selector 1, the function reads the four-byte integer at offset 0x50. It returns 1 if that integer is exactly 160; otherwise it returns 0.

For selector 2, the function reads the four-byte integer at offset 0x54. It returns 2 if that integer is exactly 160; otherwise it returns 0.

For selector 3, the function reads the four-byte integer at offset 0x58. It returns 3 if that integer is exactly 160; otherwise it returns 0.

Each recognized-selector path contains exactly one explicit four-byte field read. There is no fallback to another field after a mismatch and no scan across all three fields.

### Equality and arithmetic

The field condition is exact equality to 160. Values such as 159, 161, zero, or a negative integer do not satisfy it.

No field value is added, multiplied, narrowed, or masked before comparison. In particular, a four-byte integer with a low byte of 0xA0 is insufficient unless the complete integer value is 160.

The record offsets are fixed byte displacements. No selector-derived multiplication or index calculation is present.
