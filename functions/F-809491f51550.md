# F-809491f51550

## Purpose

F-809491f51550 conditionally submits a requested byte range to an external transfer operation, targeting storage described by an indexed collection of fixed-stride records. It maintains per-record counts, advances a current-record index at particular boundaries, and increments an aggregate counter on the successful control-flow path.

The apparent intent is a synchronized write into a circular collection of 512 KiB buffers. That interpretation is inferred, not established: the supplied body establishes the descriptor accesses, transfer calls, counter changes, and dependency-call order, but does not establish the external operation’s copy semantics, the synchronization protocol, or ownership of the storage.

A return equal to the requested amount means the function reached its completion path. It does not independently certify that the external operation transferred that many bytes.

## Interface

The function receives three 32-bit values:

| Input | Role established by use |
|---|---|
| State address | Base address for synchronization-related storage, an enable byte, descriptor records, an index, an index limit, and an aggregate counter. |
| Requested amount | Initially used as the first transfer amount; also used to calculate any remainder, update the aggregate counter, and form the successful return value. |
| Source address | Passed to the first transfer operation. For a second transfer, the address is advanced by the first transfer amount. |

The return is a 32-bit integer:

- Zero on either explicit rejection path.
- The original requested amount on the completion path.

Consequently, a zero return does not distinguish rejection from a completed zero-length request.

## Behavior

### 1. Entry and enable check

The function first calls F-338d16f9ce72 with the state address plus `0x14`.

Only after that call returns does it read the enable byte at `0x1c`.

If the byte is zero, the function calls F-1333331b2da1 with the same derived address and returns zero. It performs no direct descriptor or aggregate-counter write on this path. The dependencies’ own side effects remain unknown.

### 2. Initial descriptor selection and admission

If enabled, the function reads the current index, selects that descriptor, and reads its count. It initially chooses the entire requested amount as the first transfer amount.

It compares the unsigned 32-bit representation of the initial count plus the requested amount against `0x80000`, or 524,288.

If the sum is at most 524,288, the function performs no availability check and retains the full requested amount for the first transfer.

If the sum is greater than 524,288, processing is rejected when either of these conditions holds:

1. A freshly read current index is unsigned-less-than the upper limit, and the next descriptor’s count is nonzero.
2. Descriptor zero’s count is nonzero.

The reads are short-circuited:

- The next descriptor’s count is read only if the index is less than the limit.
- Descriptor zero’s count is read only if the first condition did not already establish rejection.

On rejection, the function calls F-1333331b2da1 and returns zero before making a transfer call or directly updating counts.

If the over-capacity request passes this check, the first transfer amount becomes 524,288 minus the initial descriptor count.

This admission rule must not be replaced with a general claim that “the next destination is empty.” In particular, when the current index is below the limit and the next count is zero, descriptor zero must still have a zero count.

### 3. First external transfer and count update

The first external transfer receives:

- Destination: the initially selected descriptor’s destination base plus its initially read count.
- Source: the original source address.
- Amount: the selected first transfer amount.

This call occurs even when that amount is zero. The body does not inspect a return value.

After the call returns, the function reads the current index again and computes the remaining amount as the original request minus the first transfer amount. It then reads and increments the count belonging to the newly selected current descriptor.

The descriptor receiving this count update is therefore not guaranteed by the body alone to be the descriptor whose destination was passed to the external operation. Equality requires the index to remain stable across the external call.

Likewise, the increment uses the count read after the call, not necessarily the initial count used to form the destination address.

### 4. Optional second transfer

If the remaining amount is nonzero, the function advances the current index:

- It reads the current index and adds one.
- It stores the incremented value.
- It reads the upper limit.
- If that limit is unsigned-less-than the incremented value, it stores zero as the current index.

The upper limit is inclusive. Index increment overflow is not checked.

The second external transfer receives:

- Destination: the selected descriptor’s base address, with no count offset added.
- Source: the original source address plus the first transfer amount.
- Amount: the remaining amount.

After this call returns, the function reads the current index again and adds the remaining amount to that descriptor’s current count.

The second destination is its base even if its existing count is nonzero. The subsequent count update adds to the existing count rather than replacing it.

The function then calls F-b04b07123c28 with the state address. If its result, interpreted as unsigned, is less than `0x180001`, it calls these dependencies in order:

1. F-c26f463fe480.
2. F-17e8aa45bba7.

The threshold includes results from zero through `0x180000`, or 1,572,864. A result equal to `0x180001` does not qualify.

### 5. Exact-capacity advancement

After the optional second-transfer sequence and its dependency calls, the function reads the current index and that descriptor’s count.

If the count equals exactly 524,288, it advances the index using the same increment, store, upper-limit comparison, and optional reset-to-zero sequence.

It then calls F-b04b07123c28 and applies the same unsigned threshold rule for calling F-c26f463fe480 followed by F-17e8aa45bba7.

This condition tests equality, not “at least capacity.” A count greater than 524,288 does not trigger this advancement.

A split request can cause two calls to F-b04b07123c28: one after the second transfer and another if the current descriptor subsequently has an exact-capacity count. Dependencies in the first sequence may affect the state observed by the later equality check.

There is no loop for splitting a request across arbitrarily many descriptors. The body makes at most two external transfer calls and performs at most two explicit index-advancement sequences.

### 6. Completion

After all applicable transfer, advancement, and threshold-dependent calls, the function:

1. Reads the aggregate counter.
2. Adds the original requested amount and stores the result.
3. Calls F-1333331b2da1 with the state address plus `0x14`.
4. Returns the original requested amount.

There is no rollback path after the first transfer begins.

## Side effects

Direct state writes may include:

- Adding the first transfer amount to a descriptor count.
- Storing an incremented current index, then possibly storing zero.
- Adding the remaining amount to a descriptor count.
- A second index advancement.
- Adding the original request to the aggregate counter.

Where wrap-to-zero occurs, the incremented index is stored before zero is stored. Treating advancement as a single atomic replacement would omit an observable write.

The function passes destination and source addresses to an external operation, but the operation’s memory-access order, overlap behavior, zero-length behavior, completion guarantees, and error behavior are unknown.

The body contains no explicit allocation or deallocation and does not directly replace descriptor destination pointers. It does not establish ownership transfer, borrowing rules, or whether dependencies retain, modify, or release referenced storage.

The entry and exit dependency pairing suggests synchronization. Neither mutual exclusion nor a particular lock type is established. The contract must not assume those calls preserve other state.

There is no explicit recovery from dependency failure, invalid addresses, or transfer failure. If a dependency does not return normally, subsequent state changes, the exit call, and the nominal return are not established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume ordinary non-overflowing 32-bit arithmetic, valid storage, normally returning dependencies, and no dependency-induced changes to the relevant state.

1. **Disabled state.**  
   If the enable byte is zero after the entry dependency returns, the function calls the exit dependency and returns zero. No transfer occurs, and the body makes no direct counter write.

2. **Request fitting within one descriptor.**  
   With current count 100 and request 20, the external operation receives destination base plus 100 and amount 20. The count becomes 120, the aggregate increases by 20, and the function returns 20. No advancement or F-b04b07123c28 call occurs.

3. **Exact fill without a second transfer.**  
   With current count 524,280 and request 8, the first transfer amount is 8. The resulting count is 524,288, so the index advances and F-b04b07123c28 is called. Descriptor-zero occupancy is not an admission condition because the initial sum does not exceed capacity.

4. **Split into a second descriptor.**  
   With current index 1, upper limit 2, current count 524,280, request 20, and zero counts for descriptors 2 and 0, admission succeeds. The transfers have amounts 8 and 12. The second starts at descriptor 2’s base and source plus 8. Its count becomes 12. One post-split F-b04b07123c28 call occurs.

5. **Descriptor zero prevents admission.**  
   Under the preceding split conditions, making descriptor zero’s count nonzero causes rejection even though descriptor 2 is empty. No transfer or direct count update occurs.

6. **Wrap at the inclusive limit.**  
   With current index equal to the upper limit, an admitted split advances through an intermediate index of limit plus one and then stores zero. The second transfer uses descriptor zero.

7. **Second descriptor fills exactly.**  
   With current index 1, upper limit 2, initial count 524,280, request 524,296, and zero counts for descriptors 2 and 0, the transfer amounts are 8 and 524,288. The post-split dependency sequence occurs, then exact-capacity advancement produces another F-b04b07123c28 call.

8. **Threshold boundary.**  
   A result of 1,572,864 from F-b04b07123c28 triggers both no-argument dependencies in order. A result of 1,572,865 does not.

9. **Zero-length admitted request.**  
   With count 100 and request zero, the first external call still occurs with amount zero. The count and aggregate undergo add-zero updates, and the function returns zero through the completion path.

10. **Oversized remainder.**  
    With current count zero, request 1,048,577, and admission otherwise permitted, the selected amounts are 524,288 and 524,289. The body does not split again or reject the oversized second amount. If storage is sufficient, the second count exceeds capacity and fails the exact-equality advancement check.
