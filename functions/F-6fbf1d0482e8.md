# F-6fbf1d0482e8

## Purpose

F-6fbf1d0482e8 dispatches either of two operations according to a 32-bit selector and reports two distinct results:

- Its direct return value indicates whether the selector selected a supported operation.
- A caller-provided 32-bit output receives a Boolean normalization of the selected dependency’s return value.

The supported selectors are `0x36E1` and `0x36E2`. An unsupported selector causes no dependency invocation and produces a direct return of zero.

A supported selector produces a direct return of one if the selected dependency returns normally and the subsequent output write completes. This remains true when the dependency returns zero. The direct return therefore must not be interpreted as the dependency’s success status.

The operational meaning of either dependency, including whether its nonzero return denotes success, is unknown.

## Behavior

### Output initialization precedes dispatch

The function first writes the 32-bit unsigned value zero to the output destination. This occurs before the selector-dependent dispatch and before either dependency invocation.

Consequently, unsupported selectors still require a valid output destination. Initialization is not deferred until the function determines that an operation is supported.

The output object is not read by the wrapper. Its incoming contents do not affect the wrapper’s dispatch decision or its final Boolean calculation.

### Selector `0x36E1`

After initialization, the function invokes F-1e2086823720 once, supplying:

1. The first payload.
2. The second payload.

The selector and output destination are not supplied as explicit arguments to this invocation. That does not establish that the dependency cannot access the output object through some other alias or shared state.

The dependency result is interpreted as a 32-bit integer and compared with zero. After the dependency returns normally, the function writes:

- Zero if the dependency result equals zero.
- One if the dependency result is nonzero.

The function then returns the 32-bit value one.

No other dependency invocation is visible on this path.

### Selector `0x36E2`

After initialization, the function invokes F-db3f0eaaaeb2 once, supplying only the first payload.

The second payload is not forwarded on this path and does not participate in any visible wrapper-side calculation or memory access. The function does not visibly dereference either payload.

After the dependency returns normally, its 32-bit integer result is normalized into the same unsigned output values:

- Zero for a zero dependency result.
- One for any nonzero dependency result.

The function then returns one. F-1e2086823720 is not invoked on this path.

### Any other selector

After writing the initial zero, the function returns zero without invoking either listed dependency.

This is exact selector matching, not a range, mask, or bit-field interpretation. Negative values and values adjacent to either supported selector take the unsupported path unless they equal one of the two constants.

### Widths and result interpretation

There is no visible selector arithmetic, payload arithmetic, accumulation, or size computation.

Normalization is an equality-to-zero decision rather than a copy, truncation, sign test, or extraction of a low bit. All nonzero 32-bit dependency results produce output one, including negative results and values whose least significant bit is zero.

The final output write occupies the full 32-bit unsigned object. It is not merely a byte-sized Boolean update.

There is no separate propagation of a dependency error code. If a dependency uses zero or a negative value to represent an error, the wrapper still applies the same normalization and returns one for the supported selector, provided execution completes normally.

## Side effects

The wrapper’s directly established memory side effects are limited to writes through the output destination:

| Path | Ordered wrapper writes |
|---|---|
| Unsupported selector | One write of zero |
| Supported selector, dependency returns zero | Initial write of zero, then another write of zero after the dependency returns |
| Supported selector, dependency returns nonzero | Initial write of zero, then a write of one after the dependency returns |

Thus, the zero-result supported path still contains two writes. Equal initial and final values do not make its write sequence identical to the unsupported path.

A dependency may observe or change memory and global state. Its implementation is unavailable, so this contract does not assert that globals, payload-associated resources, or the output object remain unchanged during the call. If a dependency changes the output object through an alias and then returns normally, the wrapper subsequently attempts to overwrite that object with the normalized return value.

No allocation, release, ownership transfer, or resource retention is directly established in the wrapper. Conversely, no preservation or ownership guarantee is established for either dependency.

The initialization is not a rollback mechanism. If a dependency fails to return normally, no final output write or ordinary direct return is established. The output might still contain zero, or it might have been changed by the dependency or another actor.

No synchronization, atomicity, or inter-thread visibility guarantee is established. The ordering described here is the visible execution order, not a promise that concurrent observers can safely inspect intermediate states.
