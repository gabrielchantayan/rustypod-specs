# F-1c432b999060

## Purpose

F-1c432b999060 constructs a local, zero-zone-formatted representation of an input time value, obtains a second representation from F-2da2dda406cc using a zone-derived adjustment, and compares the two.

The established behavior is narrower than a validated date/time comparison API:

- It recognizes two input layouts according to a descriptor tag.
- It supplies absent seconds as two ASCII zero bytes.
- It discards a fraction after explicitly supplied seconds.
- It replaces the zone suffix in its local representation with `Z` and a zero terminator.
- It derives an adjustment from the original zone suffix and passes that adjustment to F-2da2dda406cc.
- For one tag, it compares two-digit years using a pivot of 50 before invoking the final comparison dependency.
- It maps an exact zero result from the final comparison dependency to −1.

Several malformed inputs pass the visible checks. The zone-sign handling is especially unusual: an initial minus sign is not, by itself, sufficient for acceptance.

**Inferred intent:** comparison of compact time encodings with optional seconds, fractional seconds, and zone offsets.

**Established limitation:** neither complete syntax validation nor the semantics of the external copy and comparison operations are supplied.

## Interface

### Inputs

The function takes two arguments:

1. A pointer to a descriptor containing three consecutive 32-bit words.
2. An opaque 32-bit value forwarded unchanged to F-2da2dda406cc.

The descriptor layout visible to this function is:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Input length or extent field |
| 4 | 32 bits | Format tag |
| 8 | 32 bits | Address of input bytes |

The length field is interpreted differently in the two format branches:

- For tag `0x17`, the acceptance test uses unsigned 32-bit subtraction.
- For every other tag, the rejection test is a signed 32-bit comparison against 13.

The input address is captured before the initial tag and length checks. Subsequent reads of the descriptor tag are distinct reads; the function does not consistently use a single saved tag value.

### Return value

The visible return type is a signed 32-bit integer.

Possible results are:

- **0:** an initial length check or zone-suffix check rejects the input.
- **−1:** the special-format year comparison orders the input earlier, or the final comparison dependency returns zero.
- **1:** the special-format year comparison orders the input later.
- **Any nonzero result of the final comparison dependency:** returned unchanged.

Consequently, this function does not establish the conventional comparison contract “zero means equal.” A zero result from the final dependency becomes −1, and dependency results are not normalized to −1 or 1.

### Preconditions and ownership

The descriptor must be readable at all three word positions. The input address must support every byte read made by the selected parsing path.

The advertised length does not bound all later reads. In particular, the function may inspect bytes beyond that length while examining seconds, fractions, or a zone suffix.

No allocation, deallocation, ownership transfer, or retention operation is visible in the function itself. It passes pointers to local storage into dependencies. Whether a dependency retains those pointers or modifies other memory is unknown.

## Behavior

### 1. Initial reads and format selection

The function first reads the input address from descriptor offset 8, then reads the format tag.

For tag `0x17`, it evaluates the unsigned 32-bit difference between the length field and 11. A difference greater than 6 causes an immediate return of 0.

This accepts exactly the 32-bit length values 11 through 17 inclusive. Values below 11 wrap during subtraction and are rejected.

For every other tag, a signed length less than 13 causes an immediate return of 0. Thus, negative signed lengths are rejected in this branch; lengths of 13 or greater pass this check. No upper bound is imposed.

A rejected length prevents the copy dependency and all later dependencies from being called.

### 2. Prefix transfer request

The function invokes an external dependency with a local destination, the captured input address, and a byte count:

| Initial format selection | Requested byte count | Initial suffix position |
|---|---:|---:|
| Tag `0x17` | 10 | Input offset 10 |
| Any other tag | 12 | Input offset 12 |

The dependency is consistent with a byte-copy operation, but its implementation is unavailable. The subsequent local layout describes the arguments and the function’s own writes; preservation of the requested prefix bytes depends on that dependency’s behavior.

Let the beginning of the local normalized representation be offset 0.

- In the `0x17` branch, appended seconds occupy local offsets 10 and 11.
- In the other branch, appended seconds occupy local offsets 12 and 13.

The destination of this call is distinct from the local output region later passed to F-2da2dda406cc.

### 3. Seconds selection

The function reads the byte at the initial suffix position.

If it is any of:

- `Z` (`0x5A`);
- minus (`0x2D`);
- plus (`0x2B`);

the function writes ASCII `00` into the local seconds positions. The input cursor remains at that suffix byte.

Otherwise, the function:

1. Writes the current byte into the first local seconds position.
2. Reads and writes the following input byte into the second local seconds position.
3. Advances the input cursor by two bytes.
4. Examines the resulting input byte for a period (`0x2E`).

There is no visible validation that either supplied seconds byte is a decimal digit, or that the resulting numeric seconds value is in range.

### 4. Fraction skipping

If a period follows explicitly supplied seconds, the function advances at least once beyond the period and continues advancing while the newly read byte, after integer promotion and subtraction of ASCII `0`, is less than 10.

Under the displayed byte and integer types, this is a signed comparison. Its accepted continuation range is therefore byte values `0x00` through `0x39`, not just ASCII digits `0` through `9`.

Observable consequences include:

- ASCII decimal digits are skipped.
- A second period is also skipped.
- Plus and minus signs are skipped.
- A zero byte is skipped rather than acting as a terminator.
- Bytes `0x3A` and above stop this scan.

There is no length check or terminator-specific stopping rule in the loop. A suitable stopping byte must be reachable in readable memory for the scan to terminate safely.

This fraction scan is not performed when seconds were omitted.

### 5. Local zone normalization

After selecting seconds, the function writes:

1. `Z` immediately after the two local seconds bytes.
2. A zero byte immediately after that `Z`.

The function’s own final writes to the local normalized representation therefore end at:

- Offset 13 for the initial `0x17` branch.
- Offset 15 for the other branch.

These writes occur before the original suffix is accepted or rejected. A later rejection does not undo them, although they are writes to local storage rather than a visible caller buffer.

### 6. Original suffix acceptance and adjustment

The function reads the current input byte.

If it is `Z`, the adjustment value is zero. No following byte is inspected by this zone-processing branch, and there is no requirement that `Z` be the end of the advertised input.

For any other current byte:

- If it is plus, the suffix passes the sign gate without a read at relative offset 5.
- Otherwise, the function reads the byte at relative offset 5 and requires that byte to be minus.
- Failure of that requirement returns 0.

Thus:

- A leading plus is sufficient to pass the gate.
- A leading minus is accepted only if another minus occurs at relative offset 5.
- A leading byte other than plus, minus, or `Z` can also pass, provided relative offset 5 contains minus.

After this gate, the function reads the four bytes at relative offsets 1 through 4. Define their unsigned byte values as \(b_1,b_2,b_3,b_4\). It forms the signed integer quantity

\[
M = 60\bigl(10(b_1-48)+(b_2-48)\bigr)
    +10(b_3-48)+(b_4-48).
\]

These bytes are not validated as digits. There are no visible hour or minute range checks.

If the current suffix byte is minus, the function negates \(M\). Otherwise, it leaves \(M\) unchanged, including when the gate accepted a different leading byte.

The adjustment passed to F-2da2dda406cc is then \(-60M\).

For arbitrary unsigned byte values, the unnegated expression lies between −32,208 and 138,897. Negation and multiplication by −60 therefore fit in signed 32-bit arithmetic. There is no signed overflow in this arithmetic under the displayed byte widths.

### 7. Call to F-2da2dda406cc

The function prepares a local three-word descriptor:

| Word | Supplied value |
|---|---|
| First | `0x18`, or decimal 24 |
| Second | A fresh read of the caller’s format tag |
| Third | Address of local output storage |

It then invokes F-2da2dda406cc with:

1. The address of that local descriptor.
2. The signed adjustment described above.
3. The unchanged second argument of F-1c432b999060.

Any return value from F-2da2dda406cc is ignored.

The first descriptor word is visibly 24. Treating that value as a buffer capacity, output length, or required representation length would require the dependency’s contract; that meaning is not established here.

### 8. Optional two-digit-year comparison

After F-2da2dda406cc returns, the function reads the caller’s format tag again.

If this current value is `0x17`, it interprets the first two bytes of each local representation using:

\[
Y = 10(b_0-48)+(b_1-48).
\]

For each representation independently, if \(Y < 50\), it adds 100. No digit validation precedes this operation.

It then compares the transformed values:

- Input-side value less than dependency-output value: return −1.
- Input-side value greater than dependency-output value: return 1.
- Equal values: continue to the final comparison dependency.

For decimal year pairs, this establishes the order 50 through 99, then 00 through 49.

This branch depends on the tag read after the dependency call, not necessarily the tag that selected the initial input layout.

### 9. Final comparison

If no earlier return occurs, the function passes the local normalized representation first and the local dependency-output representation second to the final comparison dependency.

It returns that dependency’s result unchanged unless the result is exactly zero. An exact zero becomes −1.

No visible length argument accompanies this call.

## Side effects

The function directly performs:

- Reads of the caller’s descriptor.
- Reads of the input bytes according to the selected path.
- Writes into its local normalized representation.
- Writes into a local descriptor used for F-2da2dda406cc.
- Calls to external dependencies that receive local addresses.

It contains no explicit write through the caller’s descriptor pointer or the captured input pointer.

That does **not** prove caller memory or global state is unchanged. The external dependencies are unavailable, and their effects must not be assumed absent.

The distinct tag reads are behaviorally relevant if a dependency changes the caller’s descriptor through an alias or other state:

1. Initial tag selects prefix length and seconds placement.
2. A later tag supplies the descriptor passed to F-2da2dda406cc.
3. A post-call tag determines whether the two-digit-year comparison runs.

The function does not check that these three observations agree.

## Acceptance examples

These examples are conditional on readable memory and normal dependency return. Where representation contents matter, they additionally assume F-000000000001 copies exactly the requested bytes.

1. **Special-format lower boundary.**  
   Initial tag `0x17` and length 10 return 0 before any dependency call. Length 11 passes the initial length gate.

2. **Special-format upper boundary.**  
   Initial tag `0x17` and length 18 return 0. Length 17 passes the initial gate.

3. **Other-format boundary.**  
   A tag other than `0x17` and signed length 12 return 0. Signed length 13 passes the gate, but does not guarantee sufficient memory for subsequent reads.

4. **Omitted seconds with `Z`.**  
   If the byte immediately after the selected prefix is `Z`, the local representation receives `00Z` followed by a zero byte. F-2da2dda406cc receives adjustment 0.

5. **Explicit seconds with a fraction.**  
   If the bytes after the prefix are `12.345Z`, the function retains seconds `12`, skips the fraction, appends local `Z` and a zero byte, and supplies adjustment 0.

6. **Non-digit fraction continuation.**  
   If the bytes after the prefix are `12..Z`, both periods are traversed and `Z` stops the scan. This follows from the visible signed comparison, not decimal-fraction validation.

7. **Positive offset.**  
   A suffix beginning `+0130` passes the sign gate. Its computed \(M\) is 90, so the adjustment is −5,400.

8. **Conventional negative offset followed by zero.**  
   A suffix whose bytes are `-0130` followed by a zero byte is rejected: relative offset 5 is zero, not minus.

9. **Negative offset with the required extra byte.**  
   A suffix beginning `-0130-` passes the gate. Its signed \(M\) is −90, so the adjustment is +5,400.

10. **Unexpected accepted leading byte.**  
    A suffix beginning `X0130-` passes the same gate. Because the leading byte is not minus, its adjustment is −5,400.

11. **Year pivot.**  
    If the post-call tag is `0x17`, the input begins with year `99`, and the produced representation begins with year `00`, the transformed values are 99 and 100. The function returns −1 without calling the final comparison dependency.

12. **Final equality result.**  
    If execution reaches F-000000000002 and that dependency returns zero, F-1c432b999060 returns −1, not zero.
