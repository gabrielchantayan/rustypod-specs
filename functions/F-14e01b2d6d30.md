# F-14e01b2d6d30

## Purpose

F-14e01b2d6d30 returns a 32-bit Boolean-like result after a sequence of eligibility checks and dependency calls. Success requires all of the following:

- The second argument, interpreted as a signed 32-bit value, is nonnegative and strictly below a signed bound stored in the first argument’s object.
- An object obtained for that value has a 64-bit dependency-produced value equal to that of an embedded object.
- A separately constructed temporary object passes a predicate.
- A final comparison involving two derived temporary values returns nonzero.

The inferred intent is to determine whether a selected entry corresponds to embedded state and satisfies an additional context-dependent comparison. The evidence does not establish domain meanings such as identity, selection, authorization, or membership. Those meanings are not part of this contract.

## Interface

### Arguments

**Owner**

A pointer to an object whose storage is accessed at these byte offsets from its base:

| Offset | Access |
|---|---|
| `0x00` | Read as a dispatch-table pointer when the owner’s virtual operation is invoked. |
| `0x3C` | Read as a 32-bit bound and interpreted as signed. |
| `0x58` | Address passed to an object predicate and, conditionally, a 64-bit value operation. |
| `0x1FC` | Address passed to a provider-resolution dependency. |

These offsets describe observed accesses, not a complete object layout. The sizes, invariants, and ownership of the embedded regions are unknown.

**Candidate**

A pointer-shaped, 32-bit argument whose bits are also interpreted as a signed 32-bit integer. This function does not dereference it directly.

Its numeric interpretation controls admission. Its original argument value is subsequently passed to an indirect dependency. It must not be assumed to identify readable memory merely because its recovered type is pointer-shaped.

### Return value

A 32-bit quantity:

- `0`: admission failed, a required predicate returned zero, the 64-bit values differed, or the final comparison returned zero.
- `1`: the final comparison was reached and returned nonzero.

A nonzero dependency result is normalized to exactly `1`; arbitrary dependency return values are not forwarded.

### Preconditions

For a negative candidate, the visible path does not dereference the owner.

For a nonnegative candidate, the owner must permit the bound read at `0x3C`, even when the candidate is zero or will subsequently be rejected.

For an admitted candidate, the owner and all dependency-produced receivers must support the accesses and calls described below. There are no explicit null checks on those receivers or their dispatch-table pointers.

Any further validity requirements imposed by dependencies are unknown. In particular, the numeric admission check does not establish that the candidate is a valid pointer.

### Widths and arithmetic

The supplied representation establishes:

- 32-bit argument and pointer representations;
- signed 32-bit comparisons for admission;
- 32-bit predicate and comparison results tested against zero;
- two 64-bit values compared for equality;

There is no visible increment, subtraction, multiplication, or other numeric transformation of the candidate or bound. Admission uses signed ordering, not unsigned address ordering.

## Behavior

### 1. Admission

A candidate whose signed 32-bit interpretation is negative is rejected with return value `0`. The owner’s bound is not read on that path.

For a nonnegative candidate, the function reads the owner’s 32-bit bound at `0x3C`. It rejects equality and requires the candidate to be less than or equal to that bound. Together, these conditions admit exactly:

**signed candidate ≥ 0 and signed candidate < signed bound.**

Consequences include:

- A negative or zero bound admits no candidate.
- A candidate equal to a positive bound is rejected.
- Candidate zero is admitted when the bound is positive.

Although the supplied representation contains an initial zero-candidate check, that check is replaced by the bound-equality check for every nonnegative candidate, including zero. Therefore, zero is not independently excluded.

No provider-resolution call or temporary-object construction occurs after admission fails.

### 2. Obtain the candidate-associated object

For an admitted candidate, the function:

1. Passes the address at owner offset `0x1FC` to F-7d964f24a044.
2. Uses the returned value as a dispatch receiver.
3. Invokes unresolved dependency V-0284 through that receiver’s dispatch table at byte offset `0x284`.

V-0284 receives, in the observed argument order:

- an output address for a local 20-byte region;
- its receiver;
- the original candidate argument.

This region is the **candidate object**. The caller subsequently uses it as input to object operations and eventually passes it to F-c1466ea05103.

The caller does not test a separate construction result before using this object. A usable result is therefore a dependency precondition, not an error condition handled here.

### 3. Test embedded state and compare 64-bit values

The function calls F-b7abcf60c990 with the address at owner offset `0x58`.

If the result is zero, it skips the value comparison and all context-related work, finalizes the candidate object, and returns `0`.

If the result is nonzero, it performs these operations in order:

1. Calls F-d3b5bb23607f on the candidate object, retaining its 64-bit result.
2. Calls F-d3b5bb23607f on the embedded object at owner offset `0x58`.
3. Compares the two complete 64-bit results for equality.

Unequal values cause the function to skip the remaining eligibility checks, finalize the candidate object, and return `0`.

The equality comparison itself is unambiguous. Whether the compared values are identifiers, addresses, handles, timestamps, or another representation is unknown.

The embedded object is not snapshotted before these calls. Earlier dependencies may have changed owner state or other state used by the later value operation. No dependency is assumed to preserve globals or owner contents.

### 4. Construct and test a context object

Only when the 64-bit values are equal does the function invoke unresolved dependency V-00A4 through the owner’s dispatch table at byte offset `0xA4`, passing the owner as receiver.

Its 32-bit result is passed to F-1c06d0a5910b together with:

- an output address for a second local 20-byte region;
- a literal zero third argument.

This second region is the **context object**.

The function calls F-b7abcf60c990 on the context object. A zero result skips the final comparison. Whether this predicate means “valid,” “nonempty,” or something else is unknown.

After this predicate and any work it permits, the context object is finalized with F-c1466ea05103.

### 5. Obtain comparison operands and compare

When the context predicate returns nonzero, the following calls occur in order:

1. F-87be4aa684d1 returns a receiver.
2. F-961dd3c5e67e receives an output address for a local 16-byte region and the context object.
3. V-0140 is invoked through the receiver returned by F-87be4aa684d1, using dispatch-table byte offset `0x140`.
4. The result of V-0140 is used as the receiver for V-0008 at dispatch-table byte offset `0x08`.
5. V-0008 receives an output address for another local 16-byte region, followed by its receiver.
6. F-d45d65316ed3 compares the output of V-0008 as its first argument against the output of F-961dd3c5e67e as its second argument.

The order matters. F-87be4aa684d1 runs before F-961dd3c5e67e, but V-0140 runs afterward. The intervening call may affect state observed by V-0140; preservation cannot be presumed.

A nonzero result from F-d45d65316ed3 sets the eventual return value to `1`. A zero result leaves it at `0`.

No symmetry or equality semantics are established for this comparison. Reversing its arguments is not justified.

### 6. Normal-path finalization

On normal return:

- The context object is finalized if its construction call was reached.
- The candidate object is finalized on every admitted path.
- When both exist, context finalization precedes candidate finalization.
- Finalization still occurs after the final comparison selects success.

There are no visible explicit finalization calls for the two 16-byte comparison operands.

## Side effects

The function has no visible direct write into the owner. It does write local output regions through dependencies and invokes dependencies that may modify externally observable state.

Observable call ordering includes:

- The bound read precedes all admitted-path dependency calls.
- Candidate-object construction precedes the embedded-object predicate.
- The candidate’s 64-bit value is obtained before the embedded object’s value.
- Owner dispatch V-00A4 occurs only after those values compare equal.
- Context finalization precedes candidate finalization.

All dependency side effects must be treated as possible unless separately specified. This includes mutation of owner state, global state, referenced objects, or memory reachable from supplied addresses.

Passing the two 20-byte objects to F-c1466ea05103 establishes a finalization protocol at this call site. It does not establish whether that operation frees memory, releases references, unregisters resources, or performs another action.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, all reached dependencies are assumed to return normally and satisfy their own preconditions.

1. **Negative candidate:** A candidate with signed value `−1` returns `0`. The owner’s bound is not read, and no dependency is called.

2. **Equality with bound:** Candidate `7` and bound `7` return `0` without provider resolution.

3. **Above bound:** Candidate `8` and bound `7` return `0`.

4. **Zero admitted:** Candidate `0` and bound `1` reach provider resolution and V-0284. This does not guarantee success or establish that the downstream dependency accepts a null-shaped candidate.

5. **Nonpositive bound:** Candidate `0` with bound `0` or `−1` returns `0` after reading the bound.

6. **Signed interpretation:** Candidate bits `0x80000000` are negative under the observed comparison and are rejected without reading the bound.

7. **Embedded predicate fails:** An admitted candidate whose embedded-object predicate returns zero returns `0` after candidate finalization. Neither 64-bit value operation is called.

8. **Values differ:** If the embedded predicate is nonzero but the 64-bit results differ, V-00A4 is not called. Candidate finalization occurs, and the return is `0`.

9. **Context predicate fails:** If the 64-bit values match but the context predicate is zero, the comparison-provider chain is skipped. Context finalization occurs before candidate finalization, and the return is `0`.

10. **Successful final comparison:** If every earlier gate passes and F-d45d65316ed3 returns any nonzero 32-bit value, both reached finalizers run in the stated order and the function returns exactly `1`.

11. **Final comparison fails:** Under the same earlier conditions, a zero comparison result produces `0`, with the same finalization order.
