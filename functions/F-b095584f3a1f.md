# F-b095584f3a1f

## Purpose

F-b095584f3a1f searches a singly linked structure for the first record whose 32-bit key matches the requested key. On a match, it selects a cleanup path according to a byte in the record.

The supplied static representation marks calls to F-feee9156a257 as non-returning. This is a material part of the contract: a matching record can lead to termination of normal control flow before any list link is updated. The function must not be described simply as “remove a matching record and return success.”

Established normal-return behavior is narrower: an empty list, or a finite list containing no matching key, produces a 32-bit zero result without explicit writes by this function.

The apparent intent is resource cleanup followed, where reachable, by unlinking and disposal of a record. Actual resource ownership, disposal semantics, and the reason for non-returning calls are unknown.

## Interface

### Inputs

The function receives two values:

- **Head-slot address:** an address of a writable 32-bit slot containing the list-head address. A zero slot value represents an empty list.
- **Search key:** a 32-bit value compared for equality against the key field of each visited record.

The head-slot address itself is dereferenced without a null check. It must designate readable storage even when the list is empty. Writable access is required if execution reaches the head-replacement path.

The supplied representation uses 32-bit words for record fields and address-bearing values. It does not establish portability to a different pointer width, an external serialization format, or an ABI beyond that representation.

### Record layout

Each visited list record must support these accesses:

| Byte offset | Width | Observed use |
|---|---:|---|
| 0 | 32 bits | Argument passed to F-8349c252c168 on the direct cleanup path |
| 4 | 32 bits | Search key |
| 12 | 8 bits | Cleanup-path selector |
| 16 | 32 bits | Address of an auxiliary object |
| 20 | 32 bits | Address of the next list record |

The field at offset 8 is not explicitly accessed. Bytes following the selector byte and preceding offset 16 are not explicitly accessed as part of the selector.

A zero selector byte chooses direct cleanup. Any nonzero selector byte chooses the auxiliary-object path.

### Auxiliary-object layout

When the auxiliary address is nonzero, the function accesses:

| Byte offset | Width | Observed use |
|---|---:|---|
| 0 | 32 bits | Optional argument to F-8349c252c168 |
| 8 | 32 bits | Unsigned loop bound |
| 12 | 32 bits read; 8 bits written | Activity test and subsequent byte clearing |

The activity test converts the 32-bit value read at offset 12 to a character-sized value and tests that result against zero. Under an 8-bit truncating interpretation, this tests the low eight numeric bits. The subsequent write instead clears the byte located at address offset 12. Those descriptions must not be silently treated as interchangeable across unknown byte orders or character-conversion rules.

### Output and completion

The only explicit normal return is a 32-bit zero.

No separate result distinguishes an empty list from a completed search with no match. No explicit normal-return success status is provided for cleanup.

Calls marked non-returning have no modeled normal continuation. Whether they terminate a process, transfer control elsewhere, or have another effect is not established.

## Behavior

### Entry and traversal

The function first reads the head slot and compares its value with zero.

If the slot contains zero, it returns zero. It does not inspect a record or invoke either dependency.

If the slot is nonzero, the function reads the head slot again to obtain the initial record address. It initializes an internal predecessor reference to “none.”

For each visited record, it reads the 32-bit key at offset 4 and compares it with the search key. Equality is a full 32-bit comparison, not a comparison of a byte or a signed ordering relation.

When the key does not match:

1. The function reads the current record’s next address at offset 20 and saves it as the candidate for the next iteration.
2. It records the current record as the predecessor.
3. It reads the current record’s next field again to determine whether traversal continues.

With stable memory, a zero next address ends the search and produces the zero return. A nonzero next address continues traversal at the previously saved candidate address.

The repeated reads matter if storage changes asynchronously. No synchronization, consistency check, or concurrent-modification handling is present. In particular, the continuation test and the saved next address need not agree under concurrent mutation.

There is no cycle detection. A cycle containing no matching key has no established terminating path.

### Match with a zero selector byte

After a key match, the function reads the selector byte at offset 12.

If it is zero, the function reads the record’s 32-bit value at offset 0 and calls F-8349c252c168 with:

- that value as the first argument;
- the constant 55, hexadecimal 0x37, as the second argument.

The first argument is passed even if it is zero. This path does not consult the auxiliary-address field before the call.

If the dependency returns normally, execution proceeds to the unlink stage. Its effects are not known. In particular, the function does not establish that the dependency preserves the current record, predecessor record, head slot, or next field.

### Match with a nonzero selector byte

If the selector byte is nonzero, the function reads the auxiliary address at offset 16.

A zero auxiliary address skips auxiliary processing and proceeds directly to the unlink stage.

For a nonzero auxiliary address, the function:

1. Reads the 32-bit field at auxiliary offset 12 and tests its character-sized conversion.
2. If that converted value is nonzero, executes an empty-body loop using a 32-bit unsigned counter and the field at auxiliary offset 8 as an unsigned bound.
3. Writes zero to the single byte at auxiliary offset 12.
4. Reads the 32-bit value at auxiliary offset 0 and checks whether it is zero.
5. If it is nonzero, reads that field again and calls F-8349c252c168 with the resulting value and the constant 3.
6. Calls F-feee9156a257 with the auxiliary address.

The final call in this sequence is marked non-returning. Under that supplied control-flow model, no unlinking of the matching list record follows this auxiliary-object path.

The empty loop has no represented body effects. It does not process elements, release entries, or call a dependency. If its bound is stable, a bound of zero performs no body iterations. A bound of \(2^{32}-1\) entails that many empty-body iterations; the loop exits when the counter reaches the bound, before an increment could wrap it to zero. A bound whose highest bit is set is still a large unsigned bound, not a negative value.

The bound is represented as a read in the loop condition. Actual machine-level load frequency and execution cost cannot be established from this representation alone.

### Unlink stage

The unlink stage is reachable after:

- a zero-selector match, if F-8349c252c168 returns normally; or
- a nonzero-selector match with a zero auxiliary address.

At this stage, the function reads the matching record’s next address at offset 20.

If there is no predecessor, it writes that next address into the supplied head slot. Otherwise, it writes the next address into the predecessor record’s field at offset 20.

It then calls F-feee9156a257 with the matching record address. That call is also marked non-returning.

The next address is read at the unlink stage, not snapshotted before cleanup. If an earlier dependency changes it and leaves the record readable, the changed value is the one used for the link update.

Under the marked control flow, the function does not continue searching after a match and does not normally return after unlinking.

## Side effects

Explicit writes by this function are limited to:

- Clearing one byte at offset 12 of a nonzero auxiliary object on the matching auxiliary path.
- Replacing the head slot when the unlink stage is reached for the head record.
- Replacing the predecessor’s next field when the unlink stage is reached for a later record.

The function does not explicitly clear a matching record’s own next field, key, selector, or auxiliary address.

The auxiliary-byte clear occurs before any optional F-8349c252c168 call with second argument 3, and before the non-returning auxiliary call to F-feee9156a257. Thus that byte write is observable even on a path that never reaches list unlinking.

The list-link write occurs before the record-address call to F-feee9156a257.

Dependency effects are additional and unknown. The evidence does not establish allocation, deallocation, reference counting, logging, global-state changes, or ownership transfer. The caller cannot infer that an object remains usable after passing it to either dependency.

There is no explicit validation of addresses, record extent, alignment, link integrity, or memory lifetime. Invalid storage may prevent completion; the exact failure mode is not documented.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume valid, stable storage and no relevant mutation by dependencies.

1. **Empty list.** The head slot contains zero. The function returns 32-bit zero without dependency calls or explicit writes.

2. **Finite list with no matching key.** Traversal reaches a zero next address. The function returns zero. Selector bytes and auxiliary objects are not consulted merely because records are visited.

3. **Head match, zero selector.** F-8349c252c168 receives the head record’s offset-0 value and 55. If it returns normally and preserves the required storage, the head slot is replaced by the matching record’s then-current next address. F-feee9156a257 is then called with the matching record and has no modeled normal return.

4. **Later match, zero auxiliary address.** The selector is nonzero, but the auxiliary address is zero. No F-8349c252c168 call occurs on this path. The predecessor’s next field is replaced by the matching record’s next address, then F-feee9156a257 receives the matching record.

5. **Nonzero auxiliary address, inactive auxiliary state.** The activity conversion tests zero. The empty loop is skipped, but the byte at auxiliary offset 12 is still cleared. Optional cleanup depends on auxiliary offset 0. F-feee9156a257 receives the auxiliary object. No list-link write is reached under the non-returning model.

6. **Active auxiliary state with zero bound.** The activity conversion tests nonzero, but the unsigned bound is zero. No empty-body iteration occurs. The byte clear and subsequent auxiliary processing still occur.

7. **Zero direct resource value.** A zero-selector match still calls F-8349c252c168 with first argument zero and second argument 55. This differs from the auxiliary path, where a zero resource field suppresses that call.

8. **Dependency changes the next field.** On the direct path, if F-8349c252c168 returns and changes the matching record’s next field while preserving readable storage, the unlink stage uses that changed field. It does not use a pre-call snapshot.

9. **Duplicate keys.** The first encountered match enters cleanup. Under the supplied non-returning model, later matching records are not visited.
