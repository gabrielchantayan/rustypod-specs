# F-8abcf9166a45

## Purpose

F-8abcf9166a45 conditionally dispatches one of two receiver-associated operations. Selection depends on the zero/nonzero results of an external operation applied to an opaque input and one or two fixed textual keys. A shared state value can suppress dispatch while still producing a successful return.

The function has three normal outcomes:

- Return **0** when both external selection checks produce nonzero results.
- Return **1** without dispatch when the selected branch’s shared-state comparison matches the supplied integer.
- Invoke one selected receiver operation, then return **1** if that invocation returns normally.

A return of 1 therefore does not establish that an operation was invoked or that any external operation succeeded.

**Inferred intent:** the textual keys suggest selection and highlight-related handling. The supplied evidence does not establish that the external dependency performs string equality, that the shared state represents a current selection, or that either dispatched operation changes a selection.

## Interface

### Inputs

The function accepts three arguments:

1. **Receiver reference.** A pointer to a receiver whose first represented machine word supplies the base address of a dispatch table. The receiver is also passed unchanged as the first argument to a selected indirect operation.
2. **Opaque selection input.** A four-byte value passed unchanged to the external selection dependency. Its interpretation is not established. It may represent an address or another kind of handle, but neither interpretation is required by the visible body.
3. **Candidate value.** An integer compared against shared state and passed unchanged as the second argument to a selected indirect operation.

The supplied representation indicates a 32-bit target model: four-byte opaque values, integer values, and address-bearing words. The contract describes dispatch-table entries as four-byte entries under that model. The original ABI, byte order, and complete type declarations are unavailable; these details are **documented_only** where the representation alone does not establish them.

### Output

The normal return value is four bytes wide and is always either:

- **0:** both selection checks returned nonzero.
- **1:** a selected branch either suppressed dispatch because its comparison matched, or completed an indirect invocation.

The indirect operation’s return value, if any, does not affect the result.

### Referenced state and layout

The following labels are descriptive contract labels, not source symbols:

| Label | Meaning |
|---|---|
| **G-01** | Shared integer state read for comparison with the candidate value. |
| **F-D01** | External selection dependency called with the opaque selection input and a fixed textual key. |
| **F-D02** | Indirect operation obtained from dispatch-table byte offset **292**, hexadecimal **0x124**. |
| **F-D03** | Indirect operation obtained from dispatch-table byte offset **296**, hexadecimal **0x128**. |

F-D02 and F-D03 identify dispatch roles. The evidence does not prove that they resolve to different executable addresses.

The receiver layout required on a dispatching path is:

- At receiver offset zero: an address-bearing word identifying a dispatch-table base.
- At the selected table offset: an address-bearing entry identifying a callable operation.

Only the selected entry is read. No other receiver fields or table entries are accessed directly by this function.

### Preconditions

For normal completion:

- F-D01 must be callable and must return normally on every invocation that the selected path reaches.
- G-01 must be readable at every comparison-state read described below.
- On a dispatching path, the receiver, its table-base word, the selected table entry, and the selected operation must be valid for their respective accesses or invocation.
- The selected indirect operation must accept the receiver and candidate value in the calling convention used by the function.

The function performs no explicit receiver-validity, table-validity, callable-entry, or selection-input checks. Requirements internal to F-D01 are unknown.

A nondispatching path does not directly dereference the receiver. That fact alone does not establish that an arbitrary invalid receiver is safe in every surrounding execution environment.

## Behavior

### Initial selection check and shared-state snapshot

The first external action is an invocation of F-D01 with:

- The opaque selection input, unchanged.
- The fixed textual key **“HandleSelect”**.

The function then reads G-01 and retains that value as a snapshot. This read occurs after the first dependency invocation and before branching on its result.

The snapshot is read even on paths where its retained value is not subsequently used. The visible ordering must not be simplified into an entry-time snapshot or a read performed only when the first check fails.

Only zero versus nonzero matters for the selection result. No particular positive or negative nonzero value receives separate treatment.

### First check returns zero

When the first F-D01 result is zero:

1. The function reads G-01 again for comparison with the candidate value.
2. If that comparison is equal, the function returns 1.
3. If the comparison is unequal, the function obtains the receiver’s dispatch-table base, reads the entry at byte offset 292, and invokes F-D02 with the receiver and candidate value.
4. If F-D02 returns normally, the function returns 1.

The earlier snapshot is not used for this branch’s equality decision. The two G-01 reads are distinct in the supplied representation, although they can produce the same value.

The second selection key is not checked on this branch.

### First check returns nonzero

When the first F-D01 result is nonzero, the function invokes F-D01 again with:

- The same opaque selection input, unchanged.
- The fixed textual key **“HandleGameHilited”**.

The snapshot of G-01 has already been captured before this second invocation.

If the second result is nonzero, the function returns 0 immediately. It performs no receiver dereference or indirect invocation on that path.

If the second result is zero:

1. The function compares the candidate value against the previously captured snapshot.
2. If equal, it returns 1 without indirect dispatch.
3. If unequal, it obtains the receiver’s dispatch-table base, reads the entry at byte offset 296, and invokes F-D03 with the receiver and candidate value.
4. If F-D03 returns normally, the function returns 1.

There is no fresh G-01 read for this final comparison. Changes to G-01 during the second F-D01 invocation do not replace the retained snapshot.

### Dispatch timing and argument preservation

The receiver’s table-base word and selected table entry are read only after selection checks and the relevant equality comparison permit dispatch. They are not cached before the dependency calls.

Consequently, a dependency’s side effects may affect which table or target is observed later, provided the receiver remains valid. This function does not establish that dependencies preserve receiver-associated memory or global state.

Both indirect operations receive exactly the receiver and candidate value supplied to this function. The opaque selection input and textual key are not passed to them by the visible invocation.

At most one indirect operation is invoked per execution. There is no retry, fall-through to the other dispatch role, or post-dispatch state check.

### Integer behavior

The candidate value and shared-state value are used only for equality comparison. The function performs no increment, decrement, range check, normalization, truncating conversion, or arithmetic on them in the supplied representation.

Under the indicated 32-bit model, equality is a comparison of the represented integer values. Signed ordering and overflow do not affect these branches because neither ordering nor integer arithmetic is performed.

The dispatch offsets are byte offsets from the table base. They are not integer-array indices 292 and 296.

## Side effects

### Direct effects

The visible body directly:

- Calls F-D01 once or twice.
- Reads G-01 once or twice, depending on the branch.
- Optionally reads the receiver’s initial address-bearing word.
- Optionally reads one dispatch-table entry.
- Optionally invokes one indirect operation.

It contains no explicit writes to G-01, receiver fields, dispatch-table entries, or the opaque selection input. It performs no visible allocation, deallocation, reference-count adjustment, or ownership transfer.

### Dependency-mediated effects

F-D01, F-D02, and F-D03 may have effects not shown in the supplied body. Their preservation of global state, receiver contents, memory ownership, or resources must not be assumed.

The function does not explicitly release or compensate for anything acquired by a dependency. That absence is not evidence that dependencies acquire resources, nor that they do not.

### Failure behavior

No explicit error translation, exception handler, recovery branch, or cleanup sequence is visible.

A zero return is the ordinary outcome of two nonzero selection results; it is not a general report of dependency failure. Invalid memory access, an invalid indirect target, nonreturning dependency behavior, or dependency-originated exceptional control flow has no specified recovery here.

The promised normal return after dispatch is conditional on the selected operation returning normally.

## Acceptance examples

These are conditional consequences of the static evidence, not executed tests.

### First check selects, comparison matches

Assume the first F-D01 call returns zero and the subsequent comparison read of G-01 equals the candidate value.

Required behavior:

- Capture the initial post-call snapshot.
- Read G-01 again for the branch comparison.
- Return 1.
- Do not make the second F-D01 call.
- Do not access the receiver’s dispatch table or invoke either dispatch role.

### First check selects, comparison differs

Assume the first F-D01 call returns zero and the branch comparison read differs from the candidate value.

Required behavior:

- Invoke only F-D02, using the entry at byte offset 292.
- Pass the original receiver and candidate value.
- Return 1 if that invocation returns normally, regardless of its returned value.

### Neither check selects

Assume both F-D01 calls return nonzero, regardless of whether the values are positive, negative, or different from one another.

Required behavior:

- Read G-01 between the two calls.
- Return 0 after the second result.
- Do not perform an additional shared-state comparison read or receiver dispatch.

### Second check selects with matching snapshot

Assume the first result is nonzero, the captured G-01 value is 17, the candidate value is 17, and the second result is zero.

Required behavior:

- Return 1 without indirect dispatch.

This remains the required outcome if the second F-D01 call changes G-01 to another value. The comparison uses the captured 17.

### Second check selects after a state change

Assume the captured G-01 value is 17, the candidate value is 23, and the second F-D01 call changes G-01 to 23 before returning zero.

Required behavior:

- Invoke F-D03 because the candidate differs from the retained snapshot.
- Do not suppress dispatch based on the newer shared value.
- Return 1 if F-D03 returns normally.

### First branch observes its second state read

Assume the first result is zero, the initial post-call snapshot is 17, and the later comparison read supplies 23 while the candidate is 23.

Required behavior:

- Return 1 without dispatch.
- Do not use the initial snapshot to force dispatch.

Whether such differing reads can occur in the actual execution environment is not established.
