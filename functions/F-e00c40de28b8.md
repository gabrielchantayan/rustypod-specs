# F-e00c40de28b8

## Purpose

F-e00c40de28b8 processes a record through an ordered sequence of specialized handlers and dynamically selected callbacks. A nonzero handler result terminates processing and becomes the function’s result. Zero permits the next applicable stage; if no stage returns nonzero, the function returns zero.

The established behavior has three stages:

1. For a record initially tagged `0x0F`, attempt one of two specialized dependencies when its payload matches a corresponding context field.
2. Unless a specialized dependency has already returned nonzero, invoke one of two callbacks selected from the current record contents.
3. If that callback returns zero, conditionally invoke a final callback for a current `0x0F` record whose payload matches another context field.

The meanings of the tags, context fields, and callback results are not established. Treating nonzero as “handled” is inferred intent, not a proven application-level interpretation. In particular, negative results are propagated just as positive results are.

## Behavior

### 1. Initial specialized handling

The function first reads the tag at record offset `0x04`.

If that tag is not `0x0F`, it skips both specialized dependencies and proceeds directly to main callback selection. It does not read either initial context comparison field on this path.

If the initial tag is `0x0F`, the function:

1. Reads the record payload at offset `0x08`.
2. Reads the context value at offset `0xB0`.
3. Compares those values.

If they match, it invokes **F-ddc1f063183b** with the context and record addresses.

If they do not match, it performs a second comparison using fresh reads:

1. Reads the record payload at offset `0x08` again.
2. Reads the context value at offset `0xB4`.
3. Compares those values.

If this second comparison matches, it invokes **F-d24b74f2421d** with the context and record addresses. If it does not match, it invokes neither specialized dependency.

The first comparison has precedence. If the payload and both context fields all have the same value, only F-ddc1f063183b is selected. F-d24b74f2421d is not a second attempt after F-ddc1f063183b returns zero.

For either specialized dependency:

- A nonzero result is returned immediately, unchanged.
- A zero result advances to main callback selection.

The tag is not reread between the first and second initial comparisons. The payload is reread for the second comparison.

### 2. Main callback selection and invocation

This stage is reached when no specialized dependency was selected or the selected specialized dependency returned zero.

The function reads the record tag at offset `0x04` again. This is a new classification, not reuse of the initial tag.

If the current tag is `0x16`, it:

1. Reads the address at record offset `0x08`.
2. Reads the secondary tag at offset `0x04` of that nested object.
3. Selects table offset `0x10C` if the secondary tag equals `0x2A`.
4. Otherwise selects table offset `0x110`.

For every current tag other than `0x16`, it selects table offset `0x110` without dereferencing a nested-object address.

After completing this classification, it reads the callback-table address from context offset `0x00`, reads the selected callable entry, and invokes it with the context and record addresses.

A nonzero callback result is returned immediately and unchanged. A zero result advances to the final conditional stage.

The callback-table address is obtained after any specialized dependency has run. Consequently, a specialized dependency that changes the record or the context’s table address can affect this stage even when it returns zero.

### 3. Final conditional callback

After the main callback returns zero, the function reads the record tag at offset `0x04` again.

If the current tag is not `0x0F`, the function returns zero. It does not read the final comparison field or invoke the final callback.

If the current tag is `0x0F`, the function:

1. Reads the current payload at record offset `0x08`.
2. Reads the current context value at offset `0x50`.
3. Compares them.

If they differ, it returns zero.

If they match, it reads the callback-table address from context offset `0x00` again, obtains the callable entry at table offset `0xE0`, and invokes it with the context and record addresses.

A nonzero result from this callback is returned unchanged. A zero result produces a final result of zero.

This stage uses post-main-callback state. A main callback can therefore enable or disable the final callback by changing the record tag, payload, or comparison field. It can also change which table supplies the final callable entry.

### Result and ordering guarantees

On a normally completing invocation:

- At most one initial specialized dependency runs.
- Exactly one main callback runs unless a specialized dependency returns nonzero.
- At most one final callback runs.
- The first nonzero result encountered in this order becomes the function’s result.
- No result values are combined, normalized, or converted into Boolean values.
- Zero is returned only after the applicable stages have completed without producing a nonzero result.

If an invoked dependency fails to return normally, subsequent behavior is not established by this function’s normal return paths.

## Side effects

### Direct effects

That does not establish that the overall operation is read-only. Invoked dependencies and callbacks may modify memory or external state.

### Observable access order

The following order matters for dependencies that mutate reachable state and for any valid execution environment in which reads are observable:

- The initial tag is read before either initial comparison field.
- For the first initial comparison, the payload is read before context offset `0xB0`.
- If the first comparison fails, the payload is read again before context offset `0xB4`.
- After a zero specialized result, the main-stage tag is read again.
- For main-stage tag `0x16`, the nested address and nested secondary tag are read before the callback-table address.
- After a zero main callback result, the final-stage tag is read again.
- The final-stage payload is read before context offset `0x50`.
- The final callback-table address is read only after the final comparison succeeds.

The context’s table address is not guaranteed to remain constant across calls. Nor are the record fields or context comparison fields cached across stages.
