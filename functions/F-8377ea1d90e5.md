# F-8377ea1d90e5

## Purpose

F-8377ea1d90e5 conditionally processes a mutable container descriptor using a fixed unsigned 16-bit index read from a separate control record and a temporary descriptor passed to dependencies.

The established behavior consists of dependency calls, repeated comparisons against the container count, a conditional predecessor-word sentinel test, and a possible direct decrement of the count. The supplied body does not establish an abstract operation such as insertion, removal, copying, swapping, or ownership transfer.

The selected index never advances during this invocation. Repetition continues while the current count exceeds that fixed index. Termination therefore depends on dependency effects or other changes to the observed state; the visible body does not itself make progress inside the repetition.

## Behavior

### Initialization and initial gate

The function first calls F-e2836660e375 with no explicit arguments. It next calls F-c41e7e373603 with the temporary descriptor’s address.

Only after both calls does it read the index at control-record offset 4. It retains this selected value for the remainder of the invocation.

It then reads the container’s unsigned 16-bit count:

- If the selected index exceeds the count, the function returns.
- If the selected index is less than or equal to the count, it proceeds to the repetition condition.

Both initialization calls occur even when the initial gate rejects further processing. Their effects are unknown and must not be treated as absent. Any changes they make to subsequently read state can affect the selected index or initial count.

### Repetition

The function checks whether the fixed index is strictly less than the current count. While that condition holds, each repetition performs the following actions in order:

1. Obtain the temporary descriptor’s 32-bit field at offset 4 and the container’s 32-bit backing-address field. Call D-01 with those values as its first and second arguments, and four times the widened selected index as its third argument.
2. Write the original selected 16-bit index to temporary-descriptor offset 0.
3. Call F-c5cc0d64a43b with the temporary descriptor’s address.
4. Call F-eca0b6384dc0 with the widened selected index followed by the container descriptor’s address.
5. Fetch the 16-bit auxiliary field at control-record offset 6 and call F-7d066c616443 with that value followed by the container descriptor’s address.
6. Call F-5d01188e4589 with the temporary descriptor first and the container descriptor second.
7. Recheck the strict comparison using a fresh count read.

The ordering between separate calls and the intervening write is established. The representation does not establish an evaluation order between the separate argument reads for D-01.

The third argument supplied to D-01 is calculated from the unsigned 32-bit index by multiplication by four. Its possible range is 0 through 262,140, so that calculation does not overflow 32 bits. Its meaning is unknown: the body does not establish that it is a byte count, offset, length, capacity, or element count.

There is no direct count update within the repetition and no change to the selected index. Consequently:

- Dependency effects can reduce the count to the index or below it, ending repetition.
- If every completed repetition leaves the count greater than the index, another repetition follows.
- If that condition persists and every dependency returns, repetition continues indefinitely.
- Later changes to the control record’s index field do not alter the retained index.
- Later changes to its auxiliary field may affect subsequent calls because that field is fetched again.
- Changes to the temporary’s tail field or the container’s backing address may affect later D-01 calls because those fields are read again.

### Post-repetition predicate

After repetition ends, the function reads the count to form an equality predicate: whether the count equals the selected index.

It then reads the count again for a separate less-than-or-equal check. If the selected index is less than or equal to that count, it replaces the equality predicate with the result of a sentinel test:

- Read the container’s current backing address.
- Calculate the address at that backing address plus four times the selected index, minus four.
- Read a 32-bit word at the calculated address.
- Set the predicate according to whether that word is the all-ones pattern, displayed as signed −1.

If the less-than-or-equal check fails, the previously formed equality predicate remains unchanged. These are distinct count accesses, not one cached observation.

With stable count storage throughout these checks, repetition has ended with the count no greater than the index. The outcomes then simplify to:

| Count relative to index | Sentinel access | Final predicate |
|---|---|---|
| Equal | Read predecessor word | Whether it is all ones |
| Below | None | False |

These simplified outcomes depend on stable intervening count reads. They do not replace the actual sequence of accesses.

For a positive index, the sentinel word is at displacement four times the index minus four. At index zero, the address calculation selects the word immediately preceding the backing address in the displayed 32-bit address arithmetic; the displacement is represented as 0xFFFFFFFC. No zero-index guard is present.

The arithmetic does not establish that the resulting address is valid. In particular, a zero index does not justify an unconditional empty-container return or omission of the sentinel read.

### Conditional final phase

If the post-repetition predicate is false, the function returns without additional visible actions.

If it is true, the function:

1. Calls F-e25ca5aeb3ea with the container descriptor first and the temporary descriptor second.
2. Reads the auxiliary 16-bit field at control-record offset 6.
3. Calls F-e2836660e375 with that auxiliary value followed by the container descriptor.
4. Reads the count and compares it with the fixed index.

If the index is strictly less than this count, the function reads the count again, subtracts one, and stores the result into the 16-bit count field. It then calls F-c5cc0d64a43b with the container descriptor.

Otherwise, it calls F-e25ca5aeb3ea with the argument order reversed: temporary descriptor first, container descriptor second. This branch has no direct count decrement.

The preceding dependency calls may change the count or other state. Their effects cannot be omitted when determining the final branch.

With stable count storage between the final comparison and subtraction, the decrement applies to a count of at least one. The stored result is therefore within 0 through 65,534. The subtraction uses another count read rather than the comparison’s value. If that read instead supplies zero, storing its decremented result in the 16-bit field produces 65,535 under the displayed integer conversion. This observation does not establish support for concurrent mutation or any particular concurrency memory model.

## Acceptance examples

These are conditional consequences of static control flow, not executed tests. Unless stated otherwise, assume valid accessed storage, normally returning dependencies, and stable state except for the specified mutations.

1. **Initial rejection.** After initialization, the selected index is 7 and the count is 6. Both initialization calls have occurred. No repetition, sentinel read, or final-phase call follows.

2. **Equality with a nonmatching sentinel.** The index and count are both 3. Repetition is skipped. The function reads the word at backing-address displacement 8. If that word is not all ones, it returns without the final phase or a direct decrement.

3. **Equality with a matching sentinel.** The index and count are both 3, and the predecessor word is all ones. The function calls F-e25ca5aeb3ea with container then temporary, then calls F-e2836660e375 with the freshly fetched auxiliary value and container. If the count remains 3, it calls F-e25ca5aeb3ea with temporary then container. It does not directly decrement the count.

4. **Count increased during the final phase.** Begin with the preceding matching-sentinel case. If the first two final-phase calls leave the count at 5, the final strict comparison succeeds. The function stores 4 and calls F-c5cc0d64a43b with the container. The reversed-argument F-e25ca5aeb3ea call does not occur.

5. **One repetition reaches equality.** The fixed index is 2 and the initial count is 4. D-01 receives 8 as its third argument. The temporary’s first slot is then written with 2 before the remaining repetition calls. If those calls leave the count at 2, repetition ends and the sentinel word at displacement 4 is tested.

6. **Repetition overshoots below the index.** The fixed index is 2. A repetition leaves the count at 1. With stable subsequent reads, the final predicate is false, no sentinel word is read, and the final phase is skipped.

7. **No progress.** The index is 2 and every repetition leaves the count at 4. If dependencies keep returning, repetition continues with the same index and the same D-01 third argument of 8. Advancing the index would not match the visible behavior.

8. **Zero-index boundary.** The index and count are both zero. The function reaches the sentinel test and reads the predecessor word relative to the backing address. Normal completion requires that reached access to be valid; emptiness alone does not suppress it.

9. **Maximum index arithmetic.** The selected index is 65,535. The initial count cannot exceed it, so repetition is not entered. If the count is also 65,535, the sentinel displacement is 262,136. A hypothetical repetition’s third-argument calculation would be 262,140, but that repetition is unreachable with the displayed 16-bit count.
