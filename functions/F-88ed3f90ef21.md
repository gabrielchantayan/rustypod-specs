## Side effects

The body contains no explicit writes to caller-provided memory or global storage. Its visible direct memory operations are reads used to obtain arguments.

That is not a purity guarantee. Any dependency may modify global state, modify reachable memory, allocate or release resources, block, or terminate execution. None of those behaviors can be excluded from this body alone.

The conditional field read occurs after the first three dependency calls. Consequently, if a dependency changes the storage at the first input’s offset-4 address and returns normally, the final call receives the value read afterward, not an earlier snapshot.

Likewise, the conditional global-derived argument is read after F-afb630a7107c returns. This contract does not assume that preceding dependencies preserve the referenced global storage.

No ownership transfer, retention, release, reference-count change, or lifetime extension is established. The nonzero intermediate result is forwarded to the final dependency, but forwarding alone does not establish who owns any associated resource.

There is no visible retry, cleanup, rollback, logging, or recovery branch. An invalid read or abnormal dependency exit is not converted into an explicit error result by this function.

1. **Zero disables the final operation.**

3. **Negative nonzero is not rejected.**  
   If F-afb630a7107c returns −1 under the represented integer convention, the final dependency is still called. The body does not reinterpret that value as an error requiring an early return.

   If F-a66a9be680df returns zero, F-c5a232e4455b is still called with zero and 12. If that dependency also returns zero, F-afb630a7107c is still called.

5. **The field is not captured before the dependencies run.**  
   Suppose the offset-4 field initially contains X, and one of the first three dependencies changes it to Y before F-afb630a7107c returns nonzero. If no further modification intervenes, the final dependency receives Y.

6. **Invalid memory is not validated.**  
   An inaccessible offset-4 address on the nonzero path does not have a specified successful outcome. The contract does not substitute zero, skip the final call as recovery, or promise a particular fault mechanism.
