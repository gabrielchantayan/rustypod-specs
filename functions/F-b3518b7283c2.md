# F-b3518b7283c2

## Purpose

F-b3518b7283c2 conditionally checks an object-associated state, resolves a signed 32-bit position request, and invokes an ordered sequence of object-specific operations for an accepted position.

The established behavior is narrower than a named collection operation:

- An optional preliminary dispatch can divert execution into a nonreturning dependency.
- The request value 2,147,483,647 selects the last position when the object’s signed count is positive.
- Other requests pass through a validation dependency.
- An accepted position other than −1 can trigger a range-oriented dispatch, followed by a second dispatch and a final dependency call.
- Normal completion returns the resolved position. Validation failure returns −1.

The sequence suggests an operation that changes a position-indexed structure, but the supplied evidence does not establish whether it removes an element, moves elements, updates bookkeeping, or performs another operation. Those interpretations are not part of this contract.

## Interface

### Inputs

The function receives two explicit inputs:

1. **Object address.** An address supporting the reads and indirect calls described below.
2. **Position request.** A signed 32-bit integer.

The supplied representation treats object fields as 32-bit integer words. The following locations are relevant:

| Object-relative location | Established use |
|---|---|
| Byte offset 0 | Dispatch-table address used to resolve indirect calls |
| Byte offset 4 | Signed 32-bit count-like value |
| Byte offset 16 | Word converted to a character-sized value for the preliminary-state condition |

The conversion at offset 16 tests a character-sized portion of the word, not whether the entire 32-bit word is nonzero. Under the apparent eight-bit character model, the test is nonzero exactly when the word’s low eight bits are nonzero. The source does not independently establish character width or byte order; this must not be restated as a read of the lowest-addressed byte.

The dispatch table is accessed at these byte offsets:

| Dispatch-table offset | Explicitly established call inputs |
|---|---|
| 64 | Object address and original position request |
| 184 | Object address, resolved position plus one, current count minus one, a 32-bit all-ones value, and four additional machine-state-derived values |
| 188 | Object address and a 32-bit all-ones value |

These offsets describe table locations, not object-field offsets.

### Output

On normal return, the result is a signed 32-bit integer:

- **−1** when the validation dependency returns zero.
- Otherwise, the resolved position:
  - the positive count minus one for the special maximum-integer request; or
  - the unchanged original request for the validated path.

A return value of −1 is not a unique failure indicator. A request of −1 that passes validation also returns −1, while skipping the later position-processing calls.

The preliminary-state path may enter a dependency identified in the supplied evidence as nonreturning. That path has no established normal result.

## Behavior

### 1. Optional preliminary-state processing

The function first reads the word at object offset 16 and tests its character-sized conversion.

If the converted value is zero, it skips this phase entirely.

If the converted value is nonzero:

1. It resolves and invokes the indirect operation at dispatch-table offset 64.
2. It passes the object address and the original position request. The maximum-integer request has not yet been converted to a last position.
3. It treats the returned value as an address and reads its first 32-bit word.
4. If that word is zero, execution continues to position resolution.
5. If that word is nonzero, it calls F-e0a692eba8b7 with that value plus four, then calls F-feee9156a257 with the original nonzero value.

The second dependency is annotated as nonreturning in the supplied evidence. If F-e0a692eba8b7 itself does not return, the subsequent call is not reached.

No null check precedes the read through the preliminary dispatch result. A zero payload word and a null returned address therefore have different consequences: the former permits continuation; the latter does not provide valid storage for the required read.

The semantic meaning of the nonzero word is unknown. It must not be described definitively as an exception object, allocation, error code, or owned resource.

### 2. Position resolution and validation

After the preliminary phase, the function examines the position request.

If both of the following hold:

- the request equals 2,147,483,647; and
- the signed count at object offset 4 is greater than zero,

the function replaces the request with the count minus one. It does not call F-402eef64af83 on this path.

Otherwise, it calls F-402eef64af83 with the object address and the unchanged request.

- A zero result causes an immediate return of −1.
- Any nonzero result permits execution to continue.
- The validator’s result is not substituted for the position.

The maximum-integer request therefore has conditional sentinel behavior. A zero or negative count does not cause the function to resolve it to −1 or report failure directly; the unchanged maximum value is passed to validation.

The count is not captured before preliminary dispatch. Any count change made by that dispatch can affect subsequent sentinel resolution.

The positive-count check and the count used to compute the last position are separate accesses in the supplied expression structure. The function supplies no locking or stable-snapshot guarantee.

### 3. Accepted position equal to −1

If the resolved or validated position is −1, the function returns −1 without invoking:

- the dispatch at offset 184;
- the dispatch at offset 188; or
- F-d6032bc0598f.

This does not undo any preliminary dispatch or validation effects already incurred.

### 4. Conditional range-oriented dispatch

For an accepted position other than −1, the function tests whether:

**resolved position plus one < current signed count**

If the condition is true, it invokes the indirect operation at dispatch-table offset 184 with:

- the object address;
- the resolved position plus one;
- the current count minus one;
- a 32-bit all-ones value, numerically −1 when interpreted as signed;
- four additional values represented as incoming register or return-link state.

The function body does not assign ordinary application-level meanings to those four additional values. Their exact ABI interpretation is **documented_only**.

The count used as a call argument is read separately from the count used for the condition. The body does not establish a single immutable count spanning these reads.

The apparent range endpoints do not establish whether the indirect operation uses inclusive bounds, exclusive bounds, or a range at all. What is established is the argument sequence and its conditional invocation.

If the condition is false, this dispatch is skipped.

### 5. Mandatory later operations for a non−1 position

After the conditional range dispatch returns, or immediately when it is skipped, the function:

1. Invokes the indirect operation at dispatch-table offset 188 with the object address and a 32-bit all-ones value.
2. Calls F-d6032bc0598f with the object address and the resolved position.
3. Returns the resolved position.

The dispatch at offset 188 is resolved after the earlier range dispatch, if any. The evidence does not justify assuming that an earlier callback preserves the dispatch-table address.

The function does not use a return value from either indirect operation in this phase or from F-d6032bc0598f to choose its normal return value.

Later calls occur only if earlier calls return normally. No rollback, compensation, or local error recovery is present in the supplied body.

### Arithmetic boundaries

The visible comparisons use signed integer values.

For a stable positive count, converting the maximum-integer sentinel to count minus one produces a value from zero through 2,147,483,646. The corresponding position-plus-one calculation is representable in signed 32-bit arithmetic.

Other validated requests are not locally constrained to that safe range:

- If validation accepts 2,147,483,647, the subsequent position-plus-one calculation exceeds the signed 32-bit range.
- If a range dispatch is reached while the count is −2,147,483,648, computing count minus one exceeds that range.
- Adding four to a nonzero preliminary payload also requires a valid arithmetic and address interpretation.

The supplied representation does not establish whether such cases wrap at the machine level, are outside the intended preconditions, or reflect limitations of the recovered integer types. Their outcomes are **documented_only**; this contract does not invent wraparound behavior.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid addresses, representable arithmetic, normal return from called operations, and no unmentioned mutation of relevant fields.

Given a zero preliminary condition, count 5, and request 2,147,483,647:

- Validation is skipped.
- The resolved position is 4.
- The range condition is false because 5 is not less than 5.
- The offset-188 dispatch receives the object and the all-ones value.

- Validation receives 2,147,483,647 unchanged.
- If validation rejects it, the function returns −1.

### Preliminary count mutation
