# F-98c73c666ec8

## Purpose

F-98c73c666ec8 initializes caller-supplied storage and constructs two byte-mapping tables using classifications provided by F-3e0e547bb25a.

The first table conditionally maps bytes in the ASCII lowercase range to their uppercase counterparts. The second conditionally maps bytes in the ASCII uppercase range to their lowercase counterparts. Conversion requires classification approval for both the original byte and its proposed counterpart. All other entries retain their original byte value.

Each table covers an inclusive interval selected by classification queries. A table may contain unchanged entries between its endpoints; the interval is not a compact list of qualifying bytes.

These are established operations. Interpreting the routine as a constructor for a character-classification or case-conversion object is inferred intent. The meanings of the classification selectors, the initialized header, and the auxiliary input remain unknown.

## Interface

### Inputs

The function receives four arguments:

1. **Destination storage.** A pointer to writable object storage. The function returns this same pointer on normal completion.
2. **Configuration value.** A 32-bit value tested for equality with zero. A nonzero value is stored directly. Zero selects a value read from an external location.
3. **Mode byte.** An 8-bit value stored when the configuration input is nonzero. When the configuration input is zero, this byte is initially written and then overwritten with zero.
4. **Auxiliary value.** An opaque 32-bit value copied into the object.

No null-pointer, storage-capacity, alignment, or aliasing validation is visible. Valid destination storage is a precondition for defined execution.

## Behavior

### Initialization and configuration selection

The direct initialization sequence is significant:

1. Store 32 at offset 4.
2. Store zero at offset 8.
3. Store the auxiliary input at offset 12.
4. Read the external header value.
5. Store the original configuration input at offset 20.
6. If that input is zero, read the external default configuration.
7. Store the previously read header value at offset 0.
8. Store the mode input at offset 24.
9. If the original configuration input was zero, overwrite offset 20 with the external default and overwrite offset 24 with zero.

Default selection depends on whether the **original input** is zero, not on whether the retrieved default is zero. A zero default does not cause another lookup.

In particular, the header is read before the original configuration is stored, but written into the object afterward. The default configuration, when needed, is read after the initial zero configuration has been written. This read/write order can matter if external storage aliases the destination or is otherwise observable.

No dependency calls occur during these initialization steps.

### First interval selection

The first interval uses selector 16 with F-3e0e547bb25a. Every classification call receives:

- The destination pointer.
- The selector.
- A byte value represented in the low eight bits of the third argument.

Zero means “not qualifying” for the caller’s branch decision. Any nonzero result means “qualifying”; the function does not require the result to equal one.

The lower-end search queries byte values in ascending order, beginning at 0 and ending at 254. It stops at the first nonzero result.

If a qualifying byte is found:

- That byte becomes the lower endpoint.
- The upper-end search starts at 255.
- While the upper candidate exceeds the lower endpoint, the function queries it with selector 16.
- A zero result moves the upper candidate down by one.
- A nonzero result stops the search.
- Reaching the lower endpoint stops the search without querying that endpoint again.

If none of bytes 0 through 254 qualifies, both endpoints become 255. In this case, byte 255 is **not queried** by the endpoint search. This produces the interval `[255, 255]` regardless of how selector 16 would classify byte 255.

Consequently, the first interval is always nonempty and contains between 1 and 256 byte values.

The function writes the lower endpoint at offset 28, then the upper endpoint at offset 32.

### First allocation and table population

The function calls F-fab3799b3190 with the inclusive interval size:

**upper endpoint − lower endpoint + 1**

The returned address is written at offset 44 before any table entries are written.

Entries are produced in ascending byte order. Entry zero corresponds to the selected lower endpoint; subsequent entries correspond to successive byte values.

For each byte:

- Values outside 97 through 122 are written unchanged, without a classification call for that entry.
- For values 97 through 122, the function queries the original byte with selector 16.
- If that query returns zero, the original byte is written.
- Otherwise, the function queries the byte 32 positions lower with selector 8.
- If the second query returns nonzero, the lower-valued counterpart is written.
- Otherwise, the original byte is written.

Thus, for example, byte 97 can become byte 65 only when both relevant calls return nonzero. Qualification of the original byte alone is insufficient.

An entry’s classification is queried again during population even if that byte was previously queried during interval selection. No result is cached. Changes in dependency state or results can therefore affect population independently of endpoint selection.

Each entry is a single-byte write. No terminator, padding entry, or extra sentinel is appended.

### Second interval selection

Only after the first table has been fully populated does the function begin selecting the second interval.

This search follows the same endpoint rules, but uses selector 8:

- Ascending queries cover 0 through 254 until a nonzero result is found.
- If a lower qualifying byte is found, descending queries begin at 255 and stop at a qualifying upper byte or at the lower endpoint.
- If no byte from 0 through 254 qualifies, the interval is `[255, 255]`, without a query of byte 255.

The second lower and upper endpoints are written at offsets 36 and 40, respectively.

Because these calls happen after the first allocation and population, the second interval is determined by dependency behavior at that later time. The function does not establish that both intervals reflect one immutable classification snapshot.

### Second allocation and table population

F-fab3799b3190 is called with the second inclusive interval size. Its returned address is written at offset 48 before population.

Entries again correspond to ascending byte values:

- Values outside 65 through 90 are written unchanged, without classification calls for those entries.
- For values 65 through 90, the original byte is queried with selector 8.
- A zero result preserves the original byte.
- Otherwise, the byte 32 positions higher is queried with selector 16.
- A nonzero counterpart result selects that higher-valued byte.
- A zero counterpart result preserves the original byte.

For example, byte 65 can become byte 97 only when both applicable classifications return nonzero.

After the last second-table entry is written, the function returns the destination pointer.

### Integer widths and bounds

The endpoint and iteration calculations use 32-bit unsigned values in the supplied representation.

The alphabetic-range checks use unsigned subtraction:

- Subtracting 97 and comparing against 26 selects exactly 97 through 122.
- Subtracting 65 and comparing against 26 selects exactly 65 through 90.

Values below the range wrap in unsigned arithmetic and fail the comparison. They are not accidentally treated as alphabetic.

Selected endpoints remain between 0 and 255, inclusive. The upper endpoint never becomes less than the lower endpoint. Allocation sizes therefore range from 1 through 256 and do not wrap.

After processing byte 255, an iteration value can become 256. It remains a 32-bit value; it does not wrap to zero. Each table population consequently terminates after the inclusive interval has been written.

Mapped values also remain within 0 through 255. The stored bytes are their low eight-bit representations; textual signedness of a byte type does not change those stored bit patterns.

## Side effects

The function directly:

- Initializes the listed object fields in the stated order.
- Reads an external header value once.
- Reads an external default configuration once only when the original configuration input is zero.
- Makes classification calls while selecting intervals and populating mappings.
- Makes two storage-acquisition calls on the normal completing path.
- Stores each returned storage address into the object.
- Writes every byte of each selected table interval.

It does not directly initialize offset 16 or the three bytes following the mode byte. It does not clear the whole object.

### No qualifying byte below 255

- Its requested storage size is one byte.
- Its sole entry is 255.
- No first-table classification query is made for byte 255.

- The descending search rejects bytes 255 through 101.
- The upper endpoint becomes 100 without re-querying it during that descending search.
- The allocation request is one byte.
- During population, byte 100 is queried again with selector 16.
- Its entry becomes 68 only if selector 8 also accepts byte 68; otherwise it remains 100.

### Conventional ASCII letter classifications

- The first interval is 97–122, with 26 entries containing 65–90.
- The second interval is 65–90, with 26 entries containing 97–122.

### Rejected counterpart

Likewise, byte 65 remains 65 in the second table when selector 8 accepts it but selector 16 rejects byte 97.

### Gaps between qualifying endpoints

- The default remains selected even if its retrieved value is itself zero.
