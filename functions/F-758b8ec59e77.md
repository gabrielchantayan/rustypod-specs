# F-758b8ec59e77

## Purpose

F-758b8ec59e77 performs two ordered searches over fixed-stride records in a supplied state block:

- A forward search uses the first query and visits one collection in increasing record order.
- A backward search uses the second query and visits a separate collection in decreasing record order.

Each search selects at most one record. Acceptance is reported through a shared result mask and a direction-specific payload slot.

A record that reaches the final acceptance decision terminates its search whether accepted or rejected. Rejection at that decision does not cause another candidate to be examined.

The comparisons suggest directional boundary selection with a tolerance and an additional acceptance limit. This is inferred intent, not an established domain interpretation. The visible behavior establishes numerical comparisons, traversal, and output updates without establishing what the boundaries or payloads represent.

## Behavior

### Initialization and retained state

The first explicit memory operation is a write of zero to result word 0. Neither payload slot is initialized.

After clearing the mask, the function reads and retains, in order:

1. The full mode value from state word 520.
2. The forward count from state word 0.

It then forms the position of the first forward record.

The retained mode is converted to a character when a terminal candidate’s final acceptance condition is evaluated:

- A zero conversion result selects ordinary acceptance checking.
- A nonzero conversion result bypasses the acceptance-limit check.

The mode field is not reread. The backward count is not read until the forward phase ends.

A low-byte interpretation requires an additional conversion assumption. If character conversion retains the low eight bits, a zero low byte selects ordinary mode and a nonzero low byte selects bypass mode. Integer and byte widths alone do not establish how every out-of-range signed-character conversion behaves.

### Forward search

Let the first query be \(A\).

At each iteration, a zero remaining count ends the forward phase without reading record fields. Otherwise, the function reads the current tolerance and then the current record’s boundary \(V\). It computes the signed difference:

\[
d=A-V
\]

The initial exclusion condition is:

\[
(-d\ne T)\ \text{and}\ (d\le -T)
\]

The second comparison is evaluated only when the first comparison is true. If the conjunction holds, the forward phase ends immediately.

When all evaluated signed operations are representable, the exclusion condition is equivalent to:

\[
d<-T
\]

Thus, equality at \(d=-T\) survives this check. This mathematical equivalence does not eliminate the actual negations evaluated by the function.

For a surviving record, the function reads boundary \(U\) and checks:

\[
A\le U+T
\]

This uses the tolerance already read for that record.

If the comparison is false, the remaining count is decremented and the record position advances by eight words. The next iteration checks the updated count.

If the comparison is true, the record is the terminal forward candidate. It is accepted when either:

- The retained mode converts to a nonzero character; or
- The mode converts to zero and \(d\le M\).

In bypass mode, the acceptance-limit field is not read. In ordinary mode, \(M\) is read at this decision, rather than captured at entry.

On forward acceptance, the observable memory operations occur in this order:

1. Write result word 0 as exactly 1.
2. Read the candidate payload.
3. Convert the signed payload to the unsigned result type and write result word 1.

On rejection, no forward-selection write occurs.

Either acceptance or rejection ends the forward phase. A later forward record is never considered after a terminal candidate.

### Backward search

Let the second query be \(B\).

After all forward-phase activity, the function reads the backward count \(N\). It then forms the initial record position at state word:

\[
122+8N
\]

For positive \(N\), this is the start of backward record \(N\). Position formation occurs before the zero-count check. A zero count therefore prevents record-field reads but does not bypass that calculation.

At each iteration, a zero remaining count returns immediately. Otherwise, the function reads the current tolerance and then boundary \(U\). It computes:

\[
e=U-B
\]

The initial exclusion condition is:

\[
(-e\ne T)\ \text{and}\ (e\le -T)
\]

The second comparison is evaluated only when the first is true. If the conjunction holds, the function returns immediately.

With representable evaluated arithmetic, this is equivalent to:

\[
e<-T
\]

Equality at \(e=-T\) survives.

For a surviving record, the function reads boundary \(V\) and checks:

\[
V-T\le B
\]

If false, the remaining count is decremented and the record position moves backward by eight words.

If true, this record is the terminal backward candidate. In ordinary mode, it is rejected when:

\[
M\le e
\]

Ordinary-mode backward acceptance therefore requires:

\[
e<M
\]

The equality boundary differs from the forward search: forward acceptance permits \(d=M\), while backward acceptance rejects \(e=M\).

Bypass mode skips the acceptance-limit read and rejection comparison. It does not bypass either preceding boundary check.

On backward acceptance, the observable memory operations occur in this order:

1. Read the current result mask.
2. Write that mask with bit 1 set.
3. Read the candidate payload.
4. Convert the signed payload to the unsigned result type and write result word 2.
5. Return.

On backward rejection, the function returns without writing result word 2. It does not continue to an earlier record.

### Result interpretation

For valid execution without external interference:

| Final mask | Meaning |
|---:|---|
| 0 | Neither search accepted a record. |
| 1 | Only the forward search accepted a record. |
| 2 | Only the backward search accepted a record. |
| 3 | Both searches accepted a record. |

Each unselected payload slot retains its incoming value. The function has no write to that slot unless the corresponding search accepts.

State/result overlap can change which records are visited or accepted and which payload value is read. It does not make the three result words overlap or permit a write to one result word to modify another.

Consumers must use the mask to identify selected payloads.

## Side effects

The only explicit writes target result storage:

- Result word 0 is always cleared first.
- Forward acceptance overwrites result word 0 with 1, then writes result word 1.
- Backward acceptance sets bit 1 in result word 0, then writes result word 2.

There are no visible external calls, allocations, releases, logging operations, or explicit ownership transfers.

### Read timing and aliasing

The state is not snapshotted. Significant sequencing includes:

- Mask clearing precedes the mode and forward-count reads.
- The full mode and forward count are retained.
- The backward count is read after the forward phase.
- Tolerance is read separately for every visited record.
- The acceptance limit is read only for an ordinary-mode terminal candidate.
- Each accepted payload is read after the corresponding mask write.

If state and result storage overlap validly, a result write can change a location subsequently read as a state field.

For example:

- Initial mask clearing can change an overlapping mode or forward-count field before that field is read.
- A forward payload write can change the subsequently read backward count.
- If an accepted record’s payload occupies the same storage as result word 0, its payload read observes the preceding mask write.

These effects arise from overlap between a state field and a result word. They do **not** imply overlap between result words. For valid result storage, writing word 0 cannot directly modify word 1 or word 2, and writing either payload slot cannot directly modify the other result words.

Consequently, overlapping-state behavior follows the actual read/write sequence, not an assumed immutable state snapshot. No synchronization or coherent concurrent-update behavior is established.

### Arithmetic and conversions

Signed arithmetic is used for:

- Query/boundary differences.
- Difference and tolerance negations.
- Boundary/tolerance addition or subtraction.
- Remaining-count decrements.
- Multiplication of the backward count by eight.

Address formation and pointer movement are unchecked.

Potential invalid operations include a subtraction outside the signed range, negation of the minimum signed value, an unrepresentable tolerance adjustment, count multiplication overflow, or pointer movement outside its permitted range.

Traversal position changes occur after a failed candidate comparison even when decrementing the remaining count reaches zero. A subsequent zero-count check does not undo an invalid position calculation.

Short-circuit behavior matters. The initial exclusion condition evaluates the negated difference first; negation of the tolerance is reached only if the first comparison is true. A simplified mathematical condition must not be used to excuse an invalid operation that the function actually evaluates.

No overflow detection, saturation, or guaranteed signed wrapping is established. The numerical rules above apply only when the operations actually evaluated are valid.

Payload conversion is from the signed integer type to the unsigned result type. Under the 32-bit model, payload −1 is written as 4,294,967,295.

If the retained mode converts to a nonzero character, the preceding forward candidate with \(d=4\) is accepted without reading \(M\).

### Payload conversion and overlap

An accepted payload of −1 becomes 4,294,967,295 under the 32-bit unsigned-result model.

Separately, if a forward candidate’s payload validly overlaps result word 0, forward acceptance first writes 1 to that word. The subsequent payload read therefore obtains 1, which is written to result word 1. Result word 2 remains unchanged unless the backward search accepts; the write to word 1 cannot itself modify word 2.
