# F-3fd89e053ff6

## Purpose

F-3fd89e053ff6 returns a Boolean-like compatibility result for two integer selectors and a third integer value.

The two selectors must be equal, and neither may be the sentinel −1. Once those conditions hold, the result depends on the common selector:

- Selectors 0, 1, and 2 require the third value to match a shared comparison datum.
- Selectors 3 and 5 additionally admit the value 0x8363, subject to the arithmetic qualification below.
- Selectors 4, 6, and 7 additionally admit 0x8033 and 0x8034.
- Every other selector passes without inspecting the third value or the shared datum.

This summary assumes that the shared comparison datum remains unchanged throughout a call. The supplied representation contains repeated evaluations of that datum. If those evaluations can observe different values, the more precise behavior under **Behavior** applies.

The application-level meaning of the selectors, sentinel, third value, and shared datum is unknown. “Compatibility” describes the shape of the predicate, not an established domain interpretation.

## Behavior

### Initial rejection and dispatch

The function applies these gates before examining the selector-specific rules:

1. If the first selector is −1, it returns 0.
2. Otherwise, if the second selector is −1, it returns 0.
3. Otherwise, if the selectors differ, it returns 0.
4. Otherwise, the first selector determines the remaining behavior.

Consequences:

- Two selectors both equal to −1 are rejected despite being equal.
- Matching is exact integer equality, not range membership or bit-mask compatibility.
- A mismatch is rejected even when both selector values would independently belong to the same selector group.
- None of these early-rejection paths evaluates the shared datum.

There is no visible validation restricting matching selectors to the range 0 through 7. Matching selectors outside that range are accepted, except for −1.

### Acceptance with an unchanged shared datum

Let **D** denote the shared datum’s value throughout the call.

| Common selector | Third values accepted |
|---|---|
| 0, 1, 2 | D only |
| 3, 5 | D or 0x8363 |
| 4, 6, 7 | D, 0x8033, or 0x8034 |
| Any other value except −1 | Every third value |
| −1 | None |

The decimal equivalents of the fixed accepted values are:

- 0x8363 = 33635.
- 0x8033 = 32819.
- 0x8034 = 32820.

These are exact values, not interval endpoints. For example, the presence of 0x8033 and 0x8034 does not establish acceptance of 0x8032 or 0x8035.

If D equals one of the fixed accepted values, the alternatives overlap without changing the result.

### Selectors 0, 1, and 2

The third value is compared with the shared datum once in the visible expression structure.

- Equality returns 1.
- Inequality returns 0.

There are no additional numeric alternatives for this group.

### Selectors 3 and 5

This group contains two evaluations of the shared datum and a conditional arithmetic operation.

The first comparison determines whether to form an intermediate difference: the third value minus 0x8300. The second comparison determines whether that difference must equal 99 for acceptance.

When both datum evaluations observe the same value:

- A third value equal to the datum is accepted.
- Otherwise, acceptance requires the difference to equal 99.
- The corresponding third value is 0x8300 + 99 = 0x8363.

This arithmetic matters independently of the simplified equality rule. In mathematical signed 32-bit arithmetic, subtracting 0x8300 from sufficiently negative inputs falls outside the signed 32-bit range. The lowest third value for which the subtraction remains representable is −2147450112. The supplied representation does not establish whether execution uses wrapping machine arithmetic or another interpretation of signed overflow.

Under 32-bit wrapping subtraction, the difference-equals-99 condition selects exactly the bit pattern 0x00008363. Under a signed-language interpretation that does not define overflow, the compact rule must not be treated as an independently proven contract for overflowing subtraction cases.

Changing observations of the shared datum expose a further limitation:

- If the second comparison observes equality, acceptance occurs without inspecting the intermediate difference.
- If the first comparison observes inequality and the second also observes inequality, the difference controls the result.
- If the first comparison observes equality but the second observes inequality, the visible representation reaches a comparison against an incoming scratch value rather than a difference computed on that path.

The last case cannot be specified solely from the three explicit inputs and the two observed datum values. The origin and meaning of the incoming scratch value are unresolved. It is not justified to assign it zero, assume that it retains a value from another call, or treat it as a documented fourth argument.

### Selectors 4, 6, and 7

This group also contains two evaluations of the shared datum.

The first evaluation establishes an acceptance flag based on whether the third value equals either the first observed datum or 0x8033.

The second evaluation may replace that flag. Replacement occurs only when the third value differs from both the second observed datum and 0x8033. In that case, the replacement flag indicates whether the third value equals 0x8034.

Therefore, even without assuming a stable datum:

- A third value of 0x8033 is accepted.
- For any other third value, if the second datum observation differs from it, the result is 1 exactly when the third value is 0x8034.
- For any other third value, if the second datum observation equals it, the result retains the first comparison’s outcome.

One consequence is that 0x8034 is not unconditionally accepted under changing observations. If the first observed datum differs from 0x8034 but the second equals it, the initially false flag is retained and the function returns 0.

These changing-observation cases describe the supplied evaluation structure. They do not establish that concurrent mutation is supported or that separate physical memory loads necessarily occur.

### Other selectors

This path does not evaluate the shared datum, perform the conditional subtraction, or restrict the third value.
