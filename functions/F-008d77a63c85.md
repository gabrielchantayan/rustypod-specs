# F-008d77a63c85

## Purpose

F-008d77a63c85 conditionally updates one bit in a packed array of 32-bit words and adjusts an associated 32-bit counter when its dependency reports that a change is needed.

A zero requested-state value selects clearing; every nonzero value selects setting. Before changing storage, the function queries F-88658862e573. Its return value determines whether this function returns immediately or performs a counter update followed by a bit update.

The apparent intent is to maintain a bitmap and a count of set bits. That interpretation is **inferred intent**, not an unconditional invariant: the supplied evidence does not establish the dependency’s semantics, initial consistency, bounds, or freedom from side effects.

## Behavior

### Bit selection

The function derives two values from the unsigned bit index:

- A word index equal to the bit index divided by 32, discarding the remainder.
- A bit position equal to the remainder after division by 32.

The word index ranges from 0 through 134,217,727. The bit position ranges from 0 through 31.

A single-bit mask is formed for that position. Under the represented 32-bit bit-vector interpretation, position 0 selects the least significant bit and position 31 selects the most significant bit. The mask is computed before the dependency call.

The selected word’s byte offset is four times the word index. Its maximum is 536,870,908, which fits in an unsigned 32-bit value. Adding that offset to a storage address still requires valid target address arithmetic and accessible backing memory.

### Dependency query and branch selection

Exactly one call to F-88658862e573 appears on every ordinary execution path. It receives, in order:

1. The supplied object address.
2. The derived word index.
3. The derived bit position.

Its return is interpreted only as zero or nonzero. No specific nonzero value is required.

The requested state is likewise interpreted only as zero or nonzero. The magnitude or sign of a nonzero requested-state value has no further effect.

### Clear request

For a zero requested state:

- If F-88658862e573 returns zero, the function returns immediately. It performs no subsequent direct counter or word access.
- If the dependency returns nonzero, the function decreases the counter by one, then updates the selected word by toggling the selected bit.

The latter operation is an exclusive-or with the mask, not an unconditional clear. It clears the bit only if that bit is set when the word is actually read.

Consequently, “clear the bit” is a conditional interpretation of the operation. It requires the dependency’s nonzero result to correspond to a bit that remains set until the word read. If the dependency reports nonzero while the subsequently read bit is clear, this function sets that bit while decreasing the counter.

### Set request

For any nonzero requested state:

- If F-88658862e573 returns nonzero, the function returns immediately. It performs no subsequent direct counter or word access.
- If the dependency returns zero, the function increases the counter by one, then updates the selected word using inclusive-or with the mask.

The selected bit is therefore set in the stored word. Other bits retain the values obtained from the word read.

Unlike the clear path, the bit operation itself remains a set operation even if the dependency’s answer does not match the subsequently observed bit. In that case, however, the counter can increase even though the selected bit was already set.

### Direct memory-access order

On either update path, the visible direct accesses occur in this order, after the dependency returns:

1. Read the 32-bit counter at object offset 4.
2. Write the adjusted counter to that same location.
3. Read the storage address at object offset 8.
4. Read the selected 32-bit word from that storage.
5. Write the updated 32-bit word to the same selected location.

The storage address is not cached before the dependency call or before the counter write. Counter and storage values used by the update are therefore those available at their respective access points, not guaranteed entry-time values.

There is no second dependency query and no verification after the word write.

### Counter arithmetic

The counter is represented as a signed 32-bit field. Ordinary non-boundary updates increase or decrease its value by exactly one.

The supplied evidence does not settle overflow semantics. In particular, it does not justify promising portable signed wraparound when incrementing 2,147,483,647 or decrementing −2,147,483,648. Such boundary behavior is **documented_only** pending target-level evidence.
