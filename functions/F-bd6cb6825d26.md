# F-bd6cb6825d26

## Purpose

F-bd6cb6825d26 transforms two 32-bit input words into one 32-bit result. Processing begins with dependency calls and carry-dependent admission. Admitted inputs undergo field extraction and word-level arithmetic or, if the arithmetic path is not selected, fallback classification and possible configuration-dependent dispatch.

The field arrangement and sign-dependent handling suggest a conversion from a floating-point-like encoding to an integer-like result. This is **inferred intent**, not an established numerical API. The contract below specifies the represented operations without assuming a particular floating-point standard, rounding policy, saturation rule, or exception model.

Several behaviors remain **documented_only**: the provenance of carry state, large-shift semantics, unresolved data values, and the identity and semantics of indirect transfers. Ordinary shifts with counts below 32 do not depend on the large-shift uncertainty.

### Field and significand construction

For admitted inputs, define the **signed upper field** as the second input arithmetically shifted right by 20. Its range is \(-2048\) through \(2047\).

Two unsigned words are constructed:

- The **low significand word** is the first input shifted left by 11, retaining 32 bits.
- The **high significand word** is the bitwise OR of:
  - the second input shifted left by 11, retaining 32 bits; and
  - the first input logically shifted right by 21.

If the signed upper field is nonzero, bit 31 of the high significand word is set.

These are word-level constructions. They do not establish a conventional 64-bit integer interpretation of the original arguments.

### Negative-field selection

For a negative signed upper field, the function first clears bit 31 of the high significand word if the field equals \(-2048\). This clearing occurs after the earlier conditional setting of that bit.

The proposed shift distance is:

\[
d=-\text{signed upper field}-962.
\]

The negative arithmetic path is selected only when both conditions hold:

1. The signed upper field plus 1008 is less than 47.
2. Either \(d\ne0\), or the low significand word is zero and the high significand word is exactly `0x80000000`.

The first condition is equivalent to a signed upper field at most \(-962\). Over that selected range, \(d\) lies between 0 and 1086.

Consequently:

- Fields below \(-962\) satisfy the nonzero-distance part of the second condition.
- Field \(-962\) selects this path only for the stated exact significand condition.
- Negative fields greater than \(-962\) proceed to fallback classification.

For a selected path, distances greater than 79 are replaced by 80. The function performs the word-combination operation below, then returns the unsigned modular negation of its result.

### Nonnegative-field selection

For a nonnegative signed upper field, the proposed shift distance is:

\[
d=1086-\text{signed upper field}.
\]

The arithmetic path is selected only when:

- The represented distance is nonzero.
- The signed upper field minus 78 is less than 1009.

Together, these conditions select fields 0 through 1085, inclusive. The corresponding distances range from 1086 down to 1.

Field 1086 fails the nonzero-distance condition. Larger fields fail the signed comparison. Those cases proceed to fallback classification; a wrapped unsigned distance must not make them eligible.

### Word-combination operation

Let \(s\) be the selected distance after capping.

The initial contribution is the low significand word logically shifted right by the low eight bits of \(s\).

The high-word contribution is:

| Capped distance | High-word contribution |
|---|---|
| 0 through 31 | High significand word shifted left by \(32-s\) |
| 32 through 80 | High significand word logically shifted right by \(s-32\) |

The shift counts for these contributions also use their low eight bits. The two contributions are combined by bitwise OR, retaining a 32-bit result.

Important boundaries are:

- At \(s=0\), the high-word contribution requests a left shift by 32.
- At \(s=32\), the low-word contribution requests a right shift by 32, while the high-word contribution uses a shift of zero.
- At \(s=80\), the low and high words request right shifts by 80 and 48, respectively.

Those large-shift outcomes remain **documented_only**. This operation must not be silently replaced by an ordinary 64-bit shift.

For counts below 32, discarded high bits do not reappear elsewhere. For example, shifting `0x80000000` left by 17 and retaining 32 bits produces zero.

No rounding increment, sticky-bit adjustment, or discarded-bit examination is represented.

### Fallback classification

If no arithmetic path returns, construct a 32-bit discriminator:

\[
D=\left(2\times\text{second input bit pattern}
+\mathbf{1}_{\text{first input}\ne0}\right)\bmod 2^{32}.
\]

The indicator is one for a nonzero first input and zero otherwise.

If \(D\le\texttt{0xFFE00000}\), return the 32-bit complement of the second input arithmetically shifted right by 31:

- Nonnegative second input: `0xFFFFFFFF`.
- Negative second input: `0x00000000`.

The representation separately compares values below `0xFFE00000` and the value equal to it, but both branches return the same expression. Equality does not enter exceptional dispatch.

Only \(D>\texttt{0xFFE00000}\) reaches configuration-dependent dispatch.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Arithmetic examples assume admission succeeds.

1. **Admission rejection.** If carry is clear at the second admission decision, the result is `0x00000000`. No field processing or configuration dispatch follows.

2. **Carry can change across the conditional dependency.** If the first carry decision is set, F-c6bfc9d0fb36 is invoked. If carry is clear at the second decision, the function returns zero despite the earlier set state.

3. **Positive zero result with ordinary shift counts.** For first input `0x00000000` and second input `0x42F00000`, the signed upper field is 1071 and the distance is 15. The low significand word is zero and the high significand word is `0x80000000`. The low contribution is zero shifted right by 15. The high contribution is `0x80000000` shifted left by 17, which is zero after retaining 32 bits. The returned word is therefore **`0x00000000`**.

4. **Negative zero result with ordinary shift counts.** For first input `0x00000000` and second input `0xC2F00000`, the signed upper field is \(-977\), again giving distance 15, low word zero, and high word `0x80000000`. Both contributions are zero. Unsigned modular negation of zero remains **`0x00000000`**. Neither this example nor the preceding one depends on large-shift semantics.

5. **A surviving low-word contribution.** For first input `0x00010000` and second input `0x42F00000`, the distance is 15, the low word is `0x08000000`, and the high word is `0x80000000`. The low contribution is `0x00001000`; the retained high contribution is zero. The result is `0x00001000`. Changing only the second input to `0xC2F00000` selects modular negation and yields `0xFFFFF000`.

6. **Zero-distance negative boundary.** At signed upper field \(-962\), the negative arithmetic path requires low word zero and high word exactly `0x80000000`. If selected, the calculation requests a high-word left shift by 32. Its result remains **documented_only**.

7. **Inclusive fallback threshold.** With first input zero and second input `0x7FF00000`, fallback is reached and the discriminator is exactly `0xFFE00000`. The result is `0xFFFFFFFF`; configuration dispatch is not reached. With second input `0xFFF00000` instead, the same discriminator produces `0x00000000`.

8. **Mode 8 replacement retains earlier reads.** If exceptional dispatch selects mode 8, the subsequent `0x40` test is clear, and the later `0x10` test is set, the final argument pair is zero followed by the replacement data value. The initial first-argument and shared second-argument reads still precede the replacement.

9. **Mode 9 expression order.** Suppose mode 9 is selected, the following read has bit `0x100000` set, and the separate argument-construction read returns zero. The represented arguments are 8 and `0xFFFFFFFE`. This is conditional on differing configuration reads being possible; it does not establish such a change at runtime.
