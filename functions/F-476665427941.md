# F-476665427941

## Purpose

F-476665427941 acquires a primary object, loads source data into associated storage, converts the object, populates a working context from a parsed collection, and processes a final collection against shared state. Its result is a 32-bit status.

An import or application operation involving eight-byte verification is inferred intent, not established semantics. The contract below specifies observable calls, memory accesses, ordering, decisions, and cleanup obligations.

The operation is not demonstrably transactional. Context population and final-entry processing can precede failure. No rollback is visible.

### Widths, layouts, and preconditions

Arguments, pointer-shaped values, size slots, counts, and indices are 32 bits. The comparison value occupies eight bytes. The final-entry work area occupies 116 bytes. Byte order is not established.

The source-size bound uses an unsigned comparison. Both collection loops use signed 32-bit comparisons and increment their indices by one. No explicit overflow protection is visible.

Dependencies must provide storage sufficient for the accesses described below. Several pointer chains are dereferenced without null checks. Invalid memory, exceptional transfers, and non-returning calls have no established numeric outcome.

An addressable 32-bit slot serves first as the source-size output and later as the population-element slot. Its address is exposed to dependencies during loading. Later uses are fresh reads, not necessarily reads of an immutable value.

## Acceptance examples

These are conditional criteria, not executed tests. Calls return normally and accessed storage is valid unless stated otherwise.

1. **Primary acquisition failure:** Zero primary acquisition returns 13 without descriptor initialization.

2. **Checked boundary:** A successful query whose slot reads 4097 at the bound check selects 1 without allocation. Reads of zero or 4096 pass. If the slot then remains stable through allocation argument evaluation, allocation receives that checked value; otherwise this equality is not required.

3. **Post-check size mutation:** If metadata access changes the escaped slot from 4096 to 5000, and it remains 5000 until allocation argument evaluation, allocation receives 5000 without another bound check. If allocation subsequently changes it to 6000 and it remains stable through transfer argument evaluation, both metadata size words and the transfer-size argument are 6000.

4. **Allocation failure and transfer:** Zero allocation is written into metadata offset 4 and selects 13. For nonzero allocation, a failure-shaped transfer return alone does not prevent descriptor finalization and conversion.

5. **Retained handle input:** If handle acquisition changes the global used for its argument, preparation and parsing still receive the earlier retained capture. Zero context still causes that capture but skips handle acquisition.

6. **Separate element reads:** If retrieval stores value A, the first conversion receives A. If that call changes the escaped slot to B before returning, the second conversion receives B. With no intervening slot modification, both receive A.

7. **Construction restoration:** If the second conversion changes the upper temporary word, that change is overwritten by the retained construction value before F-f810eeb2dd14. This restoration does not restore the size/element slot.

8. **Collection changes:** A first population count of −1 skips population. If a positive count call redirects the collection path, indexed retrieval uses the reloaded path.

9. **No final iterations:** With successful preparation and nonzero initial shared field, a first final count of zero or −1 leaves status 4.

10. **Shared-base redirection:** If successful entry processing redirects the shared base, lookup receives offset 8 from the newly loaded base, even if that field is now zero.

11. **Persistent comparison:** A missing first lookup selects 3. A missing lookup following a successful comparison passes; if iteration then ends, status is 0.

12. **Mismatch and processing failure:** A record length other than 8 selects 3 without comparison. A nonzero comparison return also selects 3. A signed processing return below one instead invokes the notification dependency and skips lookup.
