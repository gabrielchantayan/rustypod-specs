# F-21694508aea9

## Purpose

F-21694508aea9 calls two dependencies and performs two ordered destination-memory writes:

1. A 32-bit numeric write at byte offset 4 from a freshly read global pointer.
2. An 8-bit write through an address saved from an earlier read of that same global pointer.

The numeric value is 60 times the sum of two signed components taken from temporary storage after the first dependency returns. The final byte comes from the second dependency.

The two global-pointer reads are distinct. Their values need not be equal, and unequal values do not imply disjoint destination ranges. In particular, the saved byte destination can fall within the four bytes written by the numeric store. The final byte write can therefore alter the numeric field or incidentally restore its calculated value after an intervening modification.

Multiplication by 60 suggests a possible unit conversion, but neither units nor domain meaning are established. That interpretation is not part of the behavioral contract.

## Interface

### Inputs

The function accepts three 32-bit arguments.

| Argument | Established direct use |
|---|---|
| First | Unused by the supplied body. |
| Second | Unused by the supplied body. |
| Third | Its complete 32-bit pattern initializes one temporary cell before the first dependency call. |

The first two arguments are not explicitly passed to either dependency.

The full third argument is made available to the first dependency through temporary storage. Only the low 8 bits of that cell’s **post-call** contents contribute directly to the numeric calculation.

### Temporary storage

Two distinct 32-bit temporary cells are initialized and passed by address to F-59067e4d309c:

| Temporary cell | Initial contents | Dependency argument position |
|---|---|---|
| Zero-initialized cell | 32-bit zero | First |
| Argument-initialized cell | Complete third-argument pattern | Second |

Because addresses are passed, the dependency can access the cells through those addresses. Its actual reads, writes, retention of addresses, and other effects are unknown.

The initial contents are not guaranteed to survive the call.

### Outputs and destination layout

The function has no explicit return value. Its direct destination writes are:

| Destination base | Offset | Width | Written value |
|---|---:|---:|---|
| Second global-pointer read | 4 bytes | 32 bits | Calculated numeric result |
| First global-pointer read, saved | 0 bytes | 8 bits | Consumed result of F-c6cc9d37012f |

For discussion, let **B** denote the saved byte destination and **N** denote the base obtained by the second global-pointer read. These labels describe pointer values, not allocations or ownership.

The numeric write covers the four bytes beginning at N + 4. The final byte write targets B.

- If B equals N, the two direct write ranges are disjoint: offset 0 versus offsets 4 through 7.
- If B equals N + 4, N + 5, N + 6, or N + 7, the final byte write overlaps the numeric field.
- Other unequal pointer values do not, by themselves, establish allocation identity, separation, or valid access.

Pointer width and byte order are not established. The numeric field’s byte representation must not be inferred from the arithmetic value alone.

### Preconditions for ordinary completion

The global pointer storage must be readable at both access points.

The saved destination B must support the final one-byte write after the numeric store and second dependency call. Saving the address does not keep its storage alive.

The second destination must support a 32-bit write beginning at N + 4 when that write occurs. The required accesses are separate: this body does not additionally require a numeric write at B + 4 or a byte write at N.

Temporary storage must remain valid for accesses made during the invocation. Required alignment, access permissions, synchronization, and dependency-specific conditions are environmental obligations. No checks enforce them.

## Behavior

### Temporary initialization and first call

The function first initializes the zero-initialized cell, then initializes the argument-initialized cell from the third argument.

It invokes F-59067e4d309c once, passing the zero-initialized cell’s address first and the argument-initialized cell’s address second. No ordinary return value from this dependency is consumed.

After a normal return, the numeric calculation uses the cells’ resulting contents. The dependency is not assumed to preserve their initial values.

Both global-pointer reads occur after this call returns. Changes the dependency makes to the global pointer can therefore affect either destination.

### Saving the final byte destination

The function reads the global pointer and saves its value as B.

This read precedes the numeric-store expression. It does not select the numeric destination, which uses a separate global-pointer read.

Later changes to the global pointer do not themselves redirect the final byte write. They also do not establish that B remains valid.

### Numeric calculation

The calculation consumes:

- The low 16 bits of the post-call zero-initialized cell, interpreted as a signed 16-bit integer.
- The low 8 bits of the post-call argument-initialized cell, interpreted as a signed 8-bit integer.

Both components are extended to the 32-bit calculation width. Their sum is multiplied by 60:

**Numeric result = 60 × (signed low-16-bit component + signed low-8-bit component).**

The upper 16 bits of the first cell and upper 24 bits of the second cell do not contribute directly to this expression. They may still affect the first dependency’s behavior.

| Quantity | Minimum | Maximum |
|---|---:|---:|
| Signed 16-bit component | −32,768 | 32,767 |
| Signed 8-bit component | −128 | 127 |
| Sum | −32,896 | 32,894 |
| Product | −1,973,760 | 1,973,640 |

Every possible sum and product fits within signed 32-bit arithmetic. Overflow or wrapping is not required to explain this calculation.

Low-byte patterns hexadecimal 80 through FF contribute −128 through −1, rather than unsigned values 128 through 255.

### Selecting and writing the numeric destination

The numeric-store expression reads the global pointer again, obtaining N. It writes the calculated 32-bit value beginning at N + 4.

The relative evaluation order of this second pointer read and the independent temporary-cell reads within that expression is not established. The established constraints are:

- F-59067e4d309c has returned.
- B has already been saved.
- The numeric operands and destination are obtained before the numeric write completes.
- The numeric write completes before F-c6cc9d37012f is invoked.

The numeric field’s previous value is not explicitly read or combined with the result.

A change between the two global-pointer reads can produce different destination bases. This describes the access structure; it does not establish that an unsynchronized external change is valid on the execution platform.

### Second call and final byte write

After the numeric write, the function invokes F-c6cc9d37012f once without explicit arguments.

An 8-bit result from that call is written through B. The function does not reread the global pointer to select this final destination.

The dependency is not assumed to preserve either destination’s contents, ownership, or lifetime.

After the call:

- There is no subsequent explicit 32-bit restoration store.
- The final byte store still occurs through B on the ordinary path.
- If B lies within the numeric field, that store replaces one of its four bytes.
- That replacement may leave the numeric value unchanged, change it, or restore the calculated value after the dependency modified it.

Restoration is possible, for example, when the dependency changes only the numeric-field byte at B and returns that byte’s value from immediately before the change. Provided the other numeric-field bytes remain intact, the final byte store restores the complete calculated field.

The function returns after the byte write, with no further explicit work.

## Side effects

### Observable ordering

The body establishes this sequence:

1. Initialize the zero-initialized 32-bit temporary.
2. Initialize the argument-initialized 32-bit temporary.
3. Call F-59067e4d309c with their addresses in that order.
4. After normal return, read the global pointer and save B.
5. Evaluate the numeric-store expression, including another global-pointer read and the relevant temporary-cell reads.
6. Write the calculated 32-bit value at N + 4.
7. Call F-c6cc9d37012f.
8. Write the consumed byte through B.
9. Return.

The independent reads within step 5 have no established relative order.

There is no explicit assignment to the global pointer itself. This does not rule out dependency effects or indirect modification if destination storage aliases other state.

### Overlap and final state

The writes do not form an atomic or transactional update. A dependency call separates them.

Equal pointer values yield disjoint direct writes within a common base-relative layout. Unequal pointer values can yield either overlapping or nonoverlapping write ranges.

Consequently, even if F-c6cc9d37012f preserves the numeric field, the final byte write can change it when B lies within its four-byte range. Conversely, a dependency modification can be undone incidentally by that byte write.

The calculated result is guaranteed as the value supplied to the numeric store on the ordinary path, not unconditionally as the numeric field’s value at function return.

### Ownership and lifetime

The temporary cells belong to the invocation. Passing their addresses does not establish ownership transfer or extend their lifetime beyond the invocation.

Whether F-59067e4d309c retains either address is unknown. Retention alone would not make later access valid.

The body contains no explicit allocation or release of destination storage. It does not establish destination ownership. Neither dependency may be assumed to preserve allocations, avoid releasing memory, or preserve global state.

### Errors and interrupted execution

The body contains no explicit null checks, bounds checks, dependency-status checks, rollback, or recovery.

- If the first dependency does not return normally, the later pointer reads and destination writes are not established to occur.
- If the numeric write faults, the second call and final byte write are not established to occur.
- If the second dependency does not return normally, the numeric write may already have occurred, but the final byte write is not established to occur.
- If B becomes invalid before the final write, no validity check intervenes.

Exact fault, exception, and invalid-access behavior remains platform-dependent.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests. Unless stated otherwise, they assume normal dependency returns, valid ordinary-memory accesses, and no additional modifications. Numeric results identify the value written by the 32-bit store.

### Zero result with a common base

If both post-call cells are zero, both pointer reads yield the same base, and the second dependency supplies hexadecimal byte 2A:

- A 32-bit zero is written at base offset 4.
- The second dependency is called.
- Byte 2A is written at base offset 0.

The direct writes are disjoint. The numeric field remains zero if intervening effects preserve it.

### Signed low byte

If the first cell’s low 16 bits are hexadecimal 0001 and the second cell’s low 8 bits are FF, the components are 1 and −1. The numeric store writes zero.

Writing 15,360 by treating FF as unsigned 255 would not satisfy the signed calculation.

### Ignored upper portions

If the post-call cell patterns are hexadecimal ABCD0002 and 12345603, the numeric store writes 300.

Changing only the first cell’s upper 16 bits or second cell’s upper 24 bits does not change this arithmetic, provided their relevant low bits remain unchanged.

### Arithmetic limits

Low portions 8000 and 80 produce −1,973,760.

Low portions 7FFF and 7F produce 1,973,640.

Both results fit signed 32-bit storage.

### Different, nonoverlapping destinations

If B and N differ and B lies outside the numeric field:

- The numeric store writes at N + 4.
- The final byte store writes at B.

The function performs no explicit numeric write at B + 4 or byte write at N merely because those addresses are associated with the two pointer values.

### Different, overlapping destinations

If B equals N + 5, the numeric store writes four bytes beginning at N + 4, and the final byte store replaces the second byte of that field.

If the dependency preserves the field and returns a byte different from the byte currently at B, the final field differs from the calculated field. Which numerical bits that byte represents depends on byte order.

### Pointer changed by a dependency

If F-59067e4d309c changes the global pointer and both later reads yield the new value, both writes use that common base.

If F-c6cc9d37012f changes the global pointer after the reads while preserving the required storage, neither direct destination is redirected: the numeric write has already used N, and the final byte write still uses B.

### Numeric modification without restoration

If B lies outside the numeric field and F-c6cc9d37012f changes that field, the final byte write does not restore it.

If B lies inside the field, lack of an explicit 32-bit restoration store is insufficient to determine the final numeric contents. The returned byte and the dependency’s modifications must also be considered.

### Incidental restoration

Suppose B equals N + 6. After the numeric store, the second dependency changes only the byte at B and returns that byte’s original value.

If the other three numeric-field bytes remain unchanged, the final byte write restores all four bytes to their post-numeric-store contents. The calculated numeric value is thereby restored without another 32-bit store.
