# F-b8e104d8a382

## Purpose

F-b8e104d8a382 updates a 32-bit word located at byte offset `0x48` from a caller-supplied base address.

The update clears bits 13 and 14 of the previous word, then combines the result with the entire 32-bit value of the second argument using bitwise OR. Bit numbering starts at zero for the least significant bit.

The second argument is **not restricted to bits 13 and 14**. It can set any bit in the destination word. Consequently, describing this operation solely as a replacement of a two-bit field would omit observable behavior.

A possible intent is to update a two-bit option field while preserving surrounding state. That interpretation is inferred, not established: the supplied material gives no semantic names for the word or its bits.

## Behavior

\[
R = (W \mathbin{\&} \texttt{0xFFFF9FFF}) \mathbin{|} U

### Bit-level guarantees

For bits 13 and 14, the result depends only on the corresponding bits of the update value:

\[
R_i = U_i \quad \text{for } i \in \{13,14\}
\]

The previous values of these two bits do not survive the clearing operation.

For every other bit, the result is the logical OR of the previous value and the update value:

\[
R_i = W_i \lor U_i \quad \text{for } i \notin \{13,14\}

This establishes several important boundaries:

- A zero update value clears bits 13 and 14 while preserving all other bits.
- An update value restricted to `0x00006000` replaces exactly those two bits and preserves the rest.
- An update value containing other set bits also sets those destination bits.
- The operation cannot clear a bit outside positions 13 and 14.
- An all-ones update value produces an all-ones result, regardless of the old destination value.

These are guarantees about the value computed from the observed read. They do not establish that another execution context cannot subsequently change the location.
