## Behavior

### Request and zero-result path

### Nonzero-result path

When the dependency returns a nonzero record address, the direct memory operations appear in this order:

1. Store the original input value into returned-record offset `0x00`.
2. Read the context field at offset `0x8C` and test whether that value is nonzero.
3. If the test is nonzero, read the context field again and use that address to write the returned record’s address at offset `0x04`.
4. Read the context field again and store the resulting 32-bit value into returned-record offset `0x08`.
5. Store zero into returned-record offset `0x04`.
6. Read the shared 32-bit value.
7. Store the returned record’s address into context offset `0x8C`.
8. Store the previously read shared value into returned-record offset `0x44`.
9. Return without an explicit result.

This is the source-level sequencing established by the supplied material. It is not evidence of atomicity, memory barriers, or an externally enforced processor-level access trace.

### Repeated context reads

The context field is not captured once and reused throughout the operation.

The nonzero branch tests one read and obtains its write destination from another read. A later read supplies the value stored at returned-record offset `0x08`.

Under ordinary conditions—distinct objects, stable memory, and no intervening external mutation—these reads identify the same former head. Under those conditions, the net effect is:

- The new record identifies the context at offset `0x00`.
- The former head, when present, identifies the new record at offset `0x04`.
- The new record identifies the former head at offset `0x08`.
- The new record contains zero at offset `0x04`.
- The context identifies the new record at offset `0x8C`.
- The new record contains the sampled shared value at offset `0x44`.

If memory aliases or changes between reads, that simplified outcome is not guaranteed. In particular, the conditional write target need not equal the value later stored at returned-record offset `0x08`.

### Shared-value sampling and publication

The shared value is read after returned-record offset `0x04` is cleared, but before the context field is replaced.

The write to returned-record offset `0x44` occurs after the context has been made to identify the returned record. Thus the visible source does not finish every record-field write before updating the context’s reference.

The value finally written at offset `0x44` is the value sampled before that context update. It is not a fresh read performed afterward. This distinction matters if storage overlaps or another actor changes the shared location.
