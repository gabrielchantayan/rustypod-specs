# F-72abaf665585

## Purpose

F-72abaf665585 repeatedly performs indirect calls, reads and writes memory through computed addresses, updates implicit execution state, and executes a software breakpoint. The supplied representation contains no normal return or loop-termination condition.

The established behavior is a sequence of state transfers, not a resolved application operation. Some values obtained from calls become addresses; others become stored data or later call arguments. The material does not establish an object model, initialization protocol, or synchronization guarantee.

Every operation after a call depends on that call returning. Operations after the breakpoint additionally depend on execution resuming. Neither condition is guaranteed by the available evidence.

## Interface

### Explicit and implicit inputs

The declared interface has no parameters and no return value. Execution nevertheless depends on:

- A current link-like value used to calculate the first call target.
- Current frame-like state used for four memory accesses and an explicit subtraction.
- An implicit register-like value contributing to a late byte-store address.
- Two external cells supplying 32-bit base values.
- Memory reached through fixed addresses, call results, and calculated addresses.
- Ordinary and secondary result channels from indirect calls.

These inputs are not checked locally. Their validity, initialization, lifetime, and calling-convention roles are unresolved.

There is **no captured common frame base**. Each frame-relative access uses the frame-like state current at that access. Intervening calls may change that state. The explicit subtraction likewise operates on the state current when the subtraction occurs.

## Behavior

The dependency IDs below denote call sites in execution order. “No explicit arguments” does not exclude hidden register or memory inputs. The ordering describes the supplied representation, not a concurrency or memory-barrier guarantee.

### Early calls and first-base stores

Each iteration starts with a byte-valued working value set to zero.

F-U01 receives two explicit zero arguments. Its target is the current link-like value plus `0xFFE`. After that call, a separate byte contribution is set to zero.

F-U02 and F-U03 run without explicit arguments. The first base is then read from its external cell, followed by F-U04. Thus, effects of F-U01 through F-U03 can influence the captured first base. Later changes to the external cell do not themselves replace that captured value.

F-U05 supplies Pair A. F-U06 receives:

1. Pair A’s lower half.
2. The represented sum of Pair A’s upper half, its lower half, and the zero byte contribution.

The addition includes signed-looking intermediate operations; unrestricted overflow behavior is unresolved. F-U05 and F-U06 have equal represented targets, but their observed argument and result uses differ.

A byte from F-U06’s secondary result channel is stored at first base plus `0x11`. It is not established as a byte extracted from an ordinary return value.

F-U07 runs. The zero-valued working byte is then stored at first base plus `0x15`.

### Early halfword and word stores

F-U08 supplies a halfword result and a secondary address-bearing result. The halfword is stored at the secondary result plus `0x0C`.

F-U09 supplies Pair B. Two stores follow, in order:

- A zero halfword at Pair B’s upper half plus `0x2C`.
- A word containing Pair B’s lower half logically shifted right by 26, at current frame-like state plus `0x26C`.

The latter stored value ranges from 0 through 63.

F-U10 runs. A word is then read at current frame-like state plus `0x320`, capturing the destination for a later store. This access does not necessarily use the frame-like value used for the preceding store.

F-U11 and F-U12 run. Pair B’s lower half, shifted left by two as an unsigned 32-bit quantity, is stored at captured destination plus `0x54`. The destination is not reloaded after those calls.

F-U13, F-U14, F-U15, F-U16, and F-U17 run in that order.

### Fixed read, frame argument, and breakpoint

An unsigned halfword is read at fixed word plus `0x34`, namely address `0x21C48994`. Its zero-extended value becomes the first index.

F-U18 runs. A word is then read at current frame-like state plus `0x280` and supplied as the explicit argument to F-U19. That call provides a 32-bit result.

A software breakpoint with operand `0x92` follows.

All remaining operations are conditional on continuation after the breakpoint. Its handling may stop execution or alter relevant machine state; no handler contract is available.

### Post-breakpoint address calculations and stores

If execution continues, the captured F-U19 result is shifted left by two to form an offset. This is a signed-looking shift, so arbitrary input values are not assigned guaranteed wrapping semantics here.

Separately, logically shifting the fixed word right by 18 and multiplying by four produces `0x21C4`.

A word read at first index plus `0x44` captures the record base.

F-U20 runs, then F-U21 supplies a 32-bit value. F-U22 receives that value and a freshly read word from first index plus `0x04`. This second read occurs after F-U21, not when the record base was captured.

The second base is read from its external cell. F-U23 runs. A halfword is then stored:

- **Destination:** captured second base plus the shifted F-U19 result.
- **Contents:** the low sixteen bits of the captured second base.

The stored contents are address-derived bits. No identifier, count, or pointer-encoding meaning is established.

F-U24 runs. A word is read at `0x21C4 + 0x54`, or `0x2218`, capturing another address-bearing value.

F-U25 supplies an address-bearing result. A halfword containing `0x21C4` is stored at that result plus `0x04`.

F-U26 and F-U27 run. An unsigned halfword is then read at the previously captured address-bearing value plus `0x34`. Its zero-extended value becomes the second index. The address-bearing word is not reloaded after F-U25 through F-U27.

### Pair C and frame-state update

F-U28 supplies Pair C.

Pair C’s lower half is stored as a word at current frame-like state plus `0x258`. This is the fourth independently evaluated frame-relative access; no earlier frame-base snapshot controls it.

An unsigned halfword is read at Pair C’s upper half plus `0x14`, becoming the zero-extended captured field.

The representation derives:

- Pair C’s lower half shifted left by six.
- Pair C’s upper half multiplied by four.
- Second index multiplied by four.

The Pair C calculations use signed-looking operations; unrestricted overflow and invalid-shift behavior remain unresolved. Multiplying the unsigned 16-bit second index by four produces a value from 0 through 262140 without 32-bit overflow.

The frame-like state is explicitly reduced by `0xF4`, or 244 bytes, from its then-current value. There is no explicit compensating addition later in the iteration. This does not establish an overall per-iteration frame change because dependencies and breakpoint handling may also change that state.

Pair C’s lower half is stored as a word at four times second index plus `0x74`.

### Record writes, byte transfer, and repetition

F-U29 runs. The captured field is stored as a word at record base plus `0x54`.

F-U30 runs. The same captured field is stored as a word at record base plus `0x64`. It is not reloaded between these stores. Both stores therefore contain a value from 0 through 65535, zero-extended to 32 bits.

F-U31 supplies a secondary address component. A halfword containing the low sixteen bits of the record base is stored at the sum of that component and Pair C’s lower half shifted left by six.

F-U32 and F-U33 run. A byte is read at second index plus four times second index. This address equals five times second index and ranges from 0 through 327675.

F-U34 runs before that captured byte is stored. Its destination is the sum of the captured field, the implicit register-like input, and `0x19`. No local assignment to that implicit input is represented. Its machine-state interpretation and preservation across dependencies are unresolved.

F-U35 runs. Four times Pair C’s upper half is stored as a word at record base plus `0x44`.

F-U36 runs. The link-like state is explicitly assigned `0x08712031`.

A word is freshly read at four times Pair C’s upper half plus `0x44` and supplied to F-U37. This is a read through the derived address, not through the record base. It need not retrieve the value just stored at record base plus `0x44`.

The loop repeats without a represented termination test. If F-U37 leaves the assigned link-like value unchanged, the next F-U01 target calculation produces `0x0871302F`. Preservation is conditional, not established.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each assumes preceding operations complete and required accesses and arithmetic are valid.

1. **Store accounting.** An iteration reaching its end performs three byte stores, five halfword stores, and seven word stores: fifteen direct stores in total. Calls may add unknown memory effects, but those are not direct stores of this function.

2. **Pair A arguments.** With lower half 3 and upper half 5, F-U06 receives 3 and 8. Its represented target equals F-U05’s despite the different call-site uses.

3. **Unsigned Pair B transformations.** With lower half `0xFC000003`, the current-frame `+0x26C` store contains 63. The captured-destination `+0x54` store contains `0xF000000C`.

4. **Independent frame evaluation.** If F-U10 leaves current frame-like state at `0x1000`, the subsequent captured-destination read uses `0x1320`, regardless of the frame-like value used by the earlier store.

5. **Captured destination.** If that read supplies `0x4000`, later changes by F-U11 or F-U12 to the source cell or frame-like state do not themselves replace the captured destination. The subsequent store uses `0x4054`.

6. **Secondary byte result.** If F-U06 supplies secondary byte `0xA7`, first base plus `0x11` receives `0xA7`. A different ordinary return value does not redefine that store.

7. **Small post-breakpoint offset.** If F-U19 supplies 3 and the second base is `0x12340`, the later halfword store uses address `0x1234C` and contents `0x2340`.

8. **Unsigned field propagation.** If the halfword through Pair C is `0xFFFF`, the record stores at `+0x54` and `+0x64` each contain `0x0000FFFF`, not a sign-extended word.

9. **Current-state subtraction.** If frame-like state is `0x2000` at the explicit subtraction, it becomes `0x1F0C`. An iteration-entry value does not determine this result.

10. **Index boundaries.** A second index of 7 gives byte-read address 35. A second index of `0xFFFF` gives address 327675.

11. **Breakpoint non-continuation.** If execution stops at the breakpoint, none of the post-breakpoint reads, writes, or calls occurs. Earlier effects have no represented rollback.

12. **Fresh final argument.** If the final computed read address differs from record base plus `0x44`, and the locations do not overlap, the final argument comes from the computed read location, not from the preceding record store.

13. **Conditional repetition state.** If F-U37 preserves the assigned link-like value, the next first-call target is `0x0871302F`. If two iterations complete without other frame-state changes, and subtraction remains valid, their explicit subtractions total 488 bytes.
