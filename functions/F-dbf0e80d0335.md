# F-dbf0e80d0335

## Purpose

F-dbf0e80d0335 classifies a 32-bit input word and conditionally invokes two dependencies. **Every normally returning path in the supplied representation returns the original input word unchanged.** Shared-data reads and dependency calls remain observable parts of the contract.

The classification uses bits 23–30 as an exponent-like field and subtracts 127. This resembles examination of an IEEE 754 binary32 encoding, but the visible operations are on integer representations. No floating-point conversion, arithmetic, rounding, or exception behavior is established.

The sign bit does not affect the initial classification. Whether it affects dependency selection on the mask-dependent path depends on the effective 32-bit mask. The shared operand used to produce that mask has no supplied declaration, so its width, signedness, promotions, and right-shift semantics must not be assumed.

Rounding-related intent is plausible from unreachable input-adjustment operations. It is not the established behavior.

## Behavior

### Classification

Bits are numbered from zero at the least significant bit to 31 at the most significant bit.

The initial classification extracts bits 23–30, excluding bit 31. The extracted field ranges from 0 through 255. Subtracting 127 produces an unsigned 32-bit result, which is then interpreted as signed for branch comparisons.

Under the represented signed interpretation, the classification ranges from −127 through 128:

| Extracted field | Signed classification | Behavior class |
|---|---:|---|
| 0–126 | −127 through −1 | Unconditional dependency processing |
| 127–149 | 0 through 22 | Mask-dependent processing |
| 150–255 | 23 through 128 | Immediate return |

For fields below 127, the subtraction wraps in the unsigned 32-bit representation before the signed comparison. Treating the comparison as unsigned would change the behavior.

Changing only bit 31 cannot change this classification.

### Fields 150–255: immediate return

The function returns the input word unchanged without reading either shared item or directly invoking either dependency.

Under a binary32 interpretation, this class includes finite values with unbiased exponent at least 23, infinities, and NaNs. Selecting the path does not require evaluating the input as a floating-point value.

### Fields 0–126: unconditional dependency processing

The shared mask operand is not read.

The observable sequence is:

1. Read the shared call-argument datum for the first call.
2. Invoke F-a83966d8599e with the original 32-bit input word and that datum.
3. If the first call returns normally, invoke F-1ba216d0a747 with its actual four-byte result and integer zero.
4. If the second call returns normally, return the original input word.

The second dependency’s result, if any, is not consumed.

Both zero encodings select this sequence. Under a binary32 interpretation, the class also includes all subnormal encodings and finite nonzero values of magnitude below one.

### Fields 127–149: mask-dependent processing

The function reads the shared mask operand and right-shifts it by the classification value, restricted to its low eight bits. Reachable shift counts are 0 through 22, so the low-eight-bit restriction does not change them.

The expression is evaluated using the shared operand’s actual type and applicable promotions. Its result is then converted to an unsigned 32-bit effective mask.

The following distinctions are essential:

- The effective mask is established to be unsigned and 32 bits wide.
- The shared operand’s declaration is absent.
- Assignment to the effective mask does not retroactively make the preceding shift a logical 32-bit shift.
- A wider operand can shift high-order bits into the low 32 bits before conversion.
- A signed operand can require different right-shift semantics, particularly for negative values.
- The validity and exact result of the expression depend on the missing declaration and applicable language rules.

When conversion of an integer expression to the unsigned 32-bit destination is defined, it retains the value modulo \(2^{32}\).

- If the intersection is nonzero, perform the same ordered dependency sequence as for fields 0–126, then return the original word.

### Sign sensitivity

For two inputs differing only in bit 31:

- **Fields 0–126:** both select dependency processing.
- **Fields 150–255:** both return without shared reads or dependency calls.
- **Fields 127–149:** both use the same classification and shift count, but dependency selection can differ if the effective mask retains bit 31 and the shared lower input bits do not intersect it.

The final case remains dependent on the shared operand’s missing declaration and value. There is no unconditional sign-independence guarantee for fields 128–149.

A narrower conclusion is available under an explicit additional assumption: **if the shift operates on an unsigned 32-bit operand**, counts 1–22 clear bit 31 of the effective mask. Under that assumption, fields 128–149 are sign-independent for call selection. Count zero, corresponding to field 127, can retain bit 31 and remains sign-sensitive.

That assumption cannot be generalized to wider operands. For example, an unsigned 64-bit operand with value `0x0000000100000000`, shifted right by one and then converted to unsigned 32 bits, produces effective mask `0x80000000`. Inputs `0x40000000` and `0xC0000000` then select different paths despite both having classification one.

These comparisons assume the same relevant shared state for the compared executions. They do not assert stability under concurrent modification.
