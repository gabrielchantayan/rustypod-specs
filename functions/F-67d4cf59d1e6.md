# F-67d4cf59d1e6

## Purpose

F-67d4cf59d1e6 examines a byte-addressed structure consisting of a declared extent, a 256-entry directory, and records. It derives a record-iteration count from the greatest directory index, checks selected bounds and field restrictions, and conditionally examines 16-bit values following record headers.

Validation is the inferred intent, not a guarantee of complete structural validity or memory safety. In particular:

- The declared extent does not bound every header read.
- A displacement-derived address is checked, but value scanning starts at a different address.
- Scanning can change where subsequent record headers are read.
- Error reporting is delegated; termination is not established.

On reaching its return, the function produces a 64-bit bit pattern containing the original context address in its upper 32 bits and zeros in its lower 32 bits. It does not return a separate validation status.

## Behavior

### Declared extent

The extent bytes at structure offsets +2 and +3 are read and decoded before the first boundary check. The decoded extent is retained for later use; later checks do not reload it.

Error code **8** is reported if either:

- The context boundary is below the structure base plus the decoded extent.
- The decoded extent is less than 518.

The boundary comparison precedes the minimum-size alternatives in the source-level condition. An extent of 518 satisfies the minimum-size requirement.

This check does not independently prove that the extent field or directory is readable. Nor does it establish that every later record lies inside the declared extent.

### Directory pass

Exactly 256 entries are processed, beginning at structure offset +6 and advancing by two bytes per entry.

For each entry, the source-level sequence is:

1. Capture the entry’s second byte.
2. Capture its first byte.
3. Read the context mode.
4. If the mode exceeds 1 and the captured second byte has any low-three-bit set, report code **8**.
5. Derive the index from the captured byte pair by shifting the decoded entry right by three.
6. Retain the greatest index encountered.

A returning error dependency does not cause that entry to be decoded again. Its captured bytes still determine its index.

The maximum index begins at zero. An all-zero directory therefore still selects one subsequent record iteration. The possible maximum index is 0 through 8191.

After the directory pass, the completed cursor is compared with structure offset +518. If unequal, the function invokes F-540af0155702. At that stage, it supplies an assertion-related address and a value read from a global data location. The latter is not established as a fixed constant.

Under ordinary, valid address arithmetic, the 256 two-byte advances produce the expected cursor. The assertion branch nevertheless remains part of the represented behavior.

### Nominal table bound

Let **M** be the maximum directory index. The nominal table end is:

**structure base + 518 + 8 × (M + 1)**

A fresh read of the context boundary is compared with this end. A boundary below it causes code **8**; equality passes.

The nominal record count is 1 through 8192, and its nominal header span is 8 through 65,536 bytes. The comparison uses the context boundary, not the declared structure end.

This bound describes a nominal sequence of eight-byte headers. It does not account for additional cursor advancement caused by scanning.

### Record fields and strict checks

The function performs **M + 1** record iterations, starting at structure offset +518.

For each record, it first captures:

- The count byte pair.
- The adjustment’s second byte, then its first byte.
- The displacement’s second byte, then its first byte.

The address eight bytes beyond the record cursor is the **post-header address**. Count, adjustment, and displacement are retained from these captures; they are not reloaded after a returning error call within that iteration.

A mode read then controls the strict start/count check. If mode exceeds 1:

- The start is reconstructed from the two bytes at record offsets +0 and +1 and compared with 255.
- Only if that comparison passes is the start reconstructed again for comparison of start plus the cached count with 256.

Either failure produces code **8**. The sum is not reduced to 16 bits; two unsigned 16-bit operands can sum to 131,070.

The two start reconstructions are separate source-level references to the field. They are not a single cached start value. If memory changes, the start used for the sum need not equal the start that passed the first comparison. The representation does not establish that these references necessarily become distinct machine loads.

Modes 0 and 1 skip these start-field accesses and restrictions.

### Displacement checks

A zero displacement skips both displacement checks and scanning. The next record cursor becomes the post-header address.

For a nonzero displacement, define the checked target as:

**post-header address + displacement − 2**

Code **9** is reported if either:

- The checked target is below the nominal table end.
- The checked target plus twice the cached count exceeds the declared structure end.

Equality passes both comparisons. If the first comparison fails, the second comparison is short-circuited, and the combined check reports once.

The declared end uses the originally decoded extent. The nominal table end uses the retained maximum directory index.

Displacement 1 has no independent rejection rule. In ordinary arithmetic, its target is one byte before the post-header address. Its acceptance depends on the stated comparisons.

Most importantly, the checked target is not the scanning address.

### Scanning and traversal

For nonzero displacement, a fresh mode read determines whether scanning occurs:

- Zero mode: no scan.
- Any nonzero mode: scan from the post-header address.

With ordinary nonwrapping address arithmetic, scanning visits **count** consecutive two-byte positions. It does not begin at the checked target.

At each position:

1. The first, high-order byte is captured.
2. The second byte is referenced to construct a value for the zero test.
3. If that value is zero, no limit comparison occurs.
4. Otherwise, the context limit is referenced, and the second byte is referenced again to construct the value used in the adjustment calculation.
5. The adjustment is added, the result is narrowed to unsigned 16 bits, and code **16** is reported if that result is greater than or equal to the 32-bit context limit.

The high byte is cached across the zero test and calculation. The second byte is not represented by one shared cached value. Its two source-level references can therefore matter under mutation, although distinct machine loads are not established.

The relative evaluation order between the limit access and the second-byte reference within the comparison is not established.

Under stable memory, this reduces to the simpler rule: zero values are exempt; nonzero values are adjusted modulo 65,536 and must be strictly below the context limit. A nonzero input whose adjusted result becomes zero is still compared.

The next record cursor is:

| Displacement | Scanning mode | Next cursor |
|---|---|---|
| Zero | Any | Current cursor +8 |
| Nonzero | Zero | Current cursor +8 |
| Nonzero | Nonzero | Current cursor +8 +2 × count |

Count zero produces no value accesses and advances only eight bytes, even when scanning is selected.

Subsequent headers are read at this resulting cursor, not necessarily at fixed eight-byte positions in the nominal table.

1. Extent-byte accesses and initial boundary comparison.
2. Directory-byte captures and repeated mode reads.
3. Directory-cursor assertion check; conditionally, a global-data read for the assertion dependency’s argument.
4. A new context-boundary read for the nominal table check.
5. Per-record field captures, conditional repeated start-field references, displacement checks, and conditional scanning.
6. Return, if reached.

The source representation does not establish an atomic 16-bit access for explicitly assembled fields or a complete machine-level ordering within every compound expression.

No synchronization or snapshot guarantee is shown.

## Acceptance examples

These are conditional static consequences, not runtime observations. Unless specified otherwise, they assume readable reached addresses, stable memory, ordinary nonwrapping address arithmetic, and no earlier dependency invocation.

1. **One straightforward record.**  
   Extent 526, all-zero directory, boundary at or beyond offset +526, and an all-zero first header produce one record iteration without a described error in any stable mode.

2. **Minimum extent and separate table bound.**  
   Extent 517 causes code 8. Extent 518 passes the minimum check. With a zero directory, the nominal table still ends at +526. A boundary at +526 can permit a zero-displacement header even though it extends past declared offset +518.

3. **Directory restrictions depend on mode.**  
   Entry value 1 contributes index zero. Its low bits cause code 8 in mode 2, but not in mode 1.

4. **Strict start/count boundary.**  
   In stable mode 2, start 255 and count 1 pass. Start 255 and count 2 fail. Start 256 fails even with count zero, without reaching the second start reconstruction.

5. **Repeated start references are significant.**  
   If the first reconstruction observes start 255 and passes, a changed field can supply a different start to the sum check. The contract does not require that second value to remain 255. This is a mutation-sensitive source-level distinction, not proof of separate physical loads.

6. **Displacement equality.**  
   If the post-header address equals the nominal table end, displacement 2 makes the checked target equal that end. If target plus twice count also equals the declared end, both displacement comparisons pass.

7. **Checked region differs from scanned region.**  
   A displacement greater than 2 places the checked target after the post-header address. With nonzero mode, scanning still begins immediately after the header. Passing target bounds does not establish bounds for those scan reads.

8. **Adjustment wrap and zero exemption.**  
   Stable scanned value 65,535 with adjustment 1 yields compared result zero. It passes with limit 1 and fails with limit zero. Stable scanned value zero bypasses the comparison even with limit zero.

9. **Low-byte mutation during scanning.**  
   If the cached high byte is zero and the zero-test low-byte reference observes 1, comparison is enabled. If the calculation’s low-byte reference instead observes zero, adjustment zero produces compared result zero. The calculation is not required to use the value that enabled comparison. If the zero test observes zero, the calculation and limit access are skipped.

10. **Mode changes later header locations.**  
    With nonzero displacement and count 3, stable mode zero advances eight bytes. Stable nonzero mode scans three values and advances fourteen bytes.
