# F-522ecb0fe768

## Purpose

F-522ecb0fe768 reads a 32-bit word through a cursor held in a caller-supplied state object, passes the observed word to a dependency, and selects one of two state-update paths.

Both paths expose a temporary four-word record to a dependency and subsequently write that record into state words 4–7. The nonzero-result path additionally copies state words 4–7 into state words 0–3 and makes a final dependency call. Normal return produces a 64-bit value containing temporary-record words 0 and 1.

The cursor update precedes the read through the original cursor. Consequently, when the original cursor overlaps the updated state field, the word read can differ from the word present at function entry. Later state writes can also modify memory addressed by the original cursor.

These are established operations, not evidence of a particular application role. A descending stack cursor, saved execution context, or resource-management operation would be **inferred intent**, not an established interface guarantee.

## Behavior

### Initial cursor operation

The function first reads state word 7 and retains that value as the original cursor.

It then writes the representation of an address one 32-bit word lower into state word 7. In the supplied layout, this is a decrease of four bytes.

Only after that write does it read a 32-bit word through the original cursor. The word passed onward is the value observed by this read, not necessarily the value stored there at entry.

The sequence is therefore:

1. Read the original cursor from state word 7.
2. Write the decremented cursor into state word 7.
3. Read through the original cursor.

There is no separate write explicitly addressed through the retained original cursor. That does **not** establish that its target remains unchanged:

- The cursor-field write changes the target if it overlaps state word 7.
- Subsequent state writes can change the target if it overlaps their destinations.
- Dependencies may also change the target.

In particular, if the original cursor points exactly to state word 7, the consumed-word read observes the newly written decremented-address representation, subject to valid addressing and representation. It does not observe the entry cursor representation.

Once read, the consumed word is retained as a value for the first F-ff1bdc376dcd call. Later changes to the memory from which it was read do not constitute a reread by this function.

### Temporary-record initialization

After the consumed-word read, the function initializes the four record words from the state address and the three scalar inputs.

The record is local to the invocation, but its address is later exposed to F-db05bcc6b488. Its contents are therefore dependency-observable and potentially dependency-modified. The visible representation does not establish a dependency write boundary or retention contract.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Unless stated otherwise, addresses and arithmetic are valid, dependencies return normally, and dependencies have no effects beyond those described.

### Non-overlapping original cursor

Suppose state word 7 initially contains address \(P\), and the 32-bit word at \(P\) contains \(X\). Suppose that word does not overlap state word 7.

The initial cursor write must store \(P-4\) into state word 7 before the consumed-word read. Because that write does not overlap the target, the read observes \(X\), and the first F-ff1bdc376dcd call must receive \(X\) as its first argument.

The word at \(P-4\) is not used for this initial read merely because the cursor field has been decremented.

### Original cursor aliases its own field

Suppose the original cursor points exactly to state word 7.

The cursor update replaces that field before the consumed-word read. The first F-ff1bdc376dcd argument must therefore be the newly stored decremented-address representation, not the entry cursor representation.

This example establishes why an unconditional promise to preserve or consume the entry contents of the cursor target would be incorrect.

### Later writes modify the original target

Suppose the original cursor points to state word 4, which initially contains \(X\). The initial cursor-field write does not overlap state word 4, so the consumed word is \(X\).

Suppose F-db05bcc6b488 subsequently leaves record word 0 equal to \(A\). On either branch, the later write to state word 4 replaces the contents at the original cursor address with \(A\).

The first dependency call still receives the previously read \(X\). Preserving that argument value does not imply preserving its source memory.

### Nonzero branch commits both state ranges

Suppose F-18dde3a4696c returns −1 and F-db05bcc6b488 leaves the record containing \(A,B,C,D\).

Before the final dependency call, state words 4–7 must contain \(A,B,C,D\), and state words 0–3 must also contain \(A,B,C,D\).

The final F-ff1bdc376dcd call must use state words 9 and 10 as read after those writes, followed by zero. If that call preserves the record, the return has \(B\) in its upper 32 bits and \(A\) in its lower 32 bits.

### Zero branch uses the later cursor

### Zero branch does not directly copy into words 0–3

Suppose the zero branch is selected and F-db05bcc6b488 supplies \(A,B,C,D\).

The function must write those values to state words 4–7. It must not itself perform the additional copies into words 0–3 or the final F-ff1bdc376dcd call.

### Return preserves bit patterns
