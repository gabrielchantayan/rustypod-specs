# F-d3c13ee31768

## Purpose

F-d3c13ee31768 is a state-mutating routine that combines a long, ordered sequence of indirect calls with byte, halfword, and word accesses at computed addresses. It forwards its explicit input to the first indirect call, subsequently uses call results and incoming machine state to compute addresses and values, and ends by attempting a call to address zero.

The supplied static representation establishes these operations, but not their application-level purpose. It does not establish that the routine initializes a conventional object, manages a particular resource, or implements a supervisor operation. Such interpretations would require evidence about the execution environment and callees.

This contract describes the visible path conditionally: each later operation is reached only if earlier calls and memory accesses complete normally. No runtime tests have been performed.

- No meaningful return value is specified.
- A normal return is shown only after a three-argument call to address zero returns.

These describe address calculations, not validated arrays or established object layouts.

The representation includes signed left shifts and signed multiplications. Their language-level overflow behavior is not a portable arithmetic contract. Where overflow matters, the actual machine instruction behavior remains a prerequisite for resolving the result.

## Behavior

### Execution model

The visible path is straight-line: no explicit conditional branch or loop appears. Indirect calls occur throughout, including calls whose explicit return values are unused. Those calls remain observable and must not be treated as no-ops.

The following stages preserve the order of explicit memory effects and the significant value flow between them. “Following calls” means intervening indirect calls execute before the next described access; it does not imply that those calls preserve memory or registers.

### 1. Initial forwarding and byte mutation

1. Forward the explicit 32-bit input to the first indirect call.
2. Execute additional indirect calls and obtain a 32-bit result.
3. Read a byte at the incoming address-bearing register plus 1.
4. Write the incoming byte-bearing register’s low byte to the address selected by that byte plus 17.
5. Pass the earlier 32-bit result shifted left by two to a subsequent call.

The read selects an absolute low address between 17 and 272. It does not select a field relative to the incoming address.

### 2. Initial scaled results and first clearing write

Following further calls:

1. Obtain a result and shift it left by two. Call this the **initial scaled value**.
2. Pass that value to a call.
3. Obtain an unsigned 32-bit result, the **initial packed value**, and pass it unchanged to another call.
4. Obtain another 32-bit result, the **primary address value**.
5. Write one zero byte at `9 + 8192 × initial scaled value`.
6. Invoke a call with:
   - the primary address value;
   - the initial packed value shifted right by 22;
   - the unshifted initial packed value.

The clearing address involves both the earlier left shift and a later multiplication. It is not simply an unscaled index.

### 3. Primary-address mutation and paired-result forwarding

After another returned-value forwarding sequence and further calls:

1. Obtain a represented 64-bit result.
2. Write the low byte of the primary address value at primary address value plus 9.
3. Read a 32-bit word at primary address value plus 52.
4. Invoke the next call with:
   - the paired result’s low word shifted left by two;
   - its high word;
   - the word just read.

The byte write precedes the word read. If the relevant storage aliases other state, that ordering remains significant.

### 4. First word-link propagation

Following more calls, obtain a secondary-register output, the **first secondary value**.

1. Store the primary address value in the word slot for the first secondary value.
2. Read a word at first secondary value plus 20; retain it as the **first link word**.
3. Pass the first secondary value to a call.
4. Execute a returned-value forwarding sequence and further calls.
5. Obtain a new result and store the primary address value in its word slot.
6. Read a word at `(first link word shifted right by 22) + 20`; retain it as the **second link word**.
7. Pass four times the new result to a call.

The write address in step 1 and read address in step 2 use different scaling. They are not interchangeable descriptions of one field.

### 5. Shifted word-link propagation

After further calls, obtain a result, the **link payload source**.

1. Shift the second link word right by one to obtain the **half-link value**.
2. Store the link payload source shifted left by two in the word slot for the half-link value.
3. Read a word at the unshifted second link word plus 20; retain it as the **third link word**.
4. Pass the half-link value to a call.
5. Execute a forwarding sequence and further calls.
6. Obtain another result and store the same shifted payload in its word slot.
7. Read global A as a 32-bit value; retain this as the **first global snapshot**.
8. Pass four times the latest result to a call.

The global read occurs after the second payload store.

### 6. Global-derived extraction and zero stores

1. Shift the third link word right by 22, producing the **extracted link value**.
2. Shift the first global snapshot right by 23, producing the **global fragment**.
3. Store the extracted link value in the word slot for the secondary-register value.
4. Invoke a call with that secondary value twice, followed by the global fragment and extracted link value.
5. Execute a forwarding sequence.
6. Compute the global fragment shifted right by 23 again.
7. Following more calls, store the extracted link value in another returned result’s word slot.
8. After another call sequence, obtain a further secondary-register value, the **masked selector**.
9. Store a zero word in its word slot.
10. Pass the masked selector to a call.
11. Execute another forwarding sequence and further calls.
12. Store the global fragment shifted right by 23 in another returned result’s word slot.
13. Read a word at `20 + ((masked selector AND 0x1fffffff) shifted right by 19)`.

The repeated shift in steps 6 and 12 yields zero for every 32-bit first global snapshot: its first right shift leaves at most nine significant bits. This is a consequence of the visible arithmetic, not an assumed default.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial byte selection.** If the first selector read returns 200, the subsequent byte write targets address 217. If the incoming byte-bearing value has low byte `0xab`, that is the stored byte.

2. **Distinct scaled and unscaled addresses.** If the first secondary value is 3, its word-slot store targets address 32, while the immediately following word read targets address 23. A model that reads back address 32 is incorrect.

3. **Repeated global shift.** If the first global snapshot is `0xffffffff`, its right shift by 23 is 511. Shifting that result right by 23 yields zero. The later selector read using that twice-shifted result therefore addresses byte 1.

4. **Byte truncation.** If a final payload word is `0x12345678`, its direct byte-routing store writes `0x78`. Its right-shift-by-22 byte-routing store writes `0x48`.

5. **Retained base.** If the retained byte base is 40 and a later callee changes address 1 to 90, the subsequent word-to-byte copy still reads address 156 and writes address 41.

6. **Fresh reread.** If a callee changes the word at first copy base plus 116 between its two explicit reads, the second byte copy uses the changed word.

7. **Termination boundary.** If execution reaches the final call and address zero is not executable, normal return is not demonstrated. All earlier reached writes, including the halfword clear, precede that attempted call.
