# F-6b7191fe7569

## Purpose

F-6b7191fe7569 selects an indexed result using an object, discriminator, selector, and index. Depending on dispatch, it resolves a configured or table-provided identifier, updates shared storage, obtains a direct conversion result, returns a shared-buffer address, or delegates the request.

**Established static behavior:** conditional initialization precedes output clearing and request validation. Ordinary completion returns the 32-bit value 1. Explicit local rejection returns 0. One delegated path returns its dependency’s result unchanged.

**Inferred intent:** several dependencies appear to manipulate string-like values or formatting state. Their text semantics, encoding, and ownership contracts are not established.

This contract specifies explicit accesses, call boundaries, and result handling. It does not assume unknown dependencies preserve globals, leave caller-accessible memory unchanged, or allocate or release memory.

Returns:

- **1:** ordinary completion, including paths that skip an update.

No explicit validation protects the object, output slot, table addresses, subordinate addresses, or callable targets. Every accessed location and invoked target must be valid for the relevant operation. A return of 1 does not establish a nonzero output, textual content, independent ownership, or stable lifetime.

### Local storage and arithmetic

Before conditional initialization, three 32-bit local words receive, respectively, the incoming discriminator, selector, and index. The supplied representation places them consecutively in that order: the index-seeded word immediately follows the selector-seeded word.

Later calls receive the address of either the discriminator-seeded word or the selector-seeded word. Thus the represented layout contains an index-seeded word four bytes after the latter address and eight bytes after the former. This establishes initialization and relative placement, **not** a dependency’s access extent, a complete temporary-object layout, or a guarantee that the initial contents survive intervening calls.

Arithmetic and addressing use 32-bit widths. Scaling an index by eight, adding a base, adding a record’s four-byte second-word displacement, and the specified formatting addition can wrap. Address validity remains a precondition even when a numeric range check succeeds.

## Behavior

### Initialization and retained configuration

After seeding all three local words:

1. Read a shared control pointer and test bit 0 of the word at control offset `0x0C`.
2. If clear, read the initialization-token argument and call F-b255b26284e6.
3. After that call, capture the configured third initialization argument, then the shared-object/descriptor pointer.
4. Test the token operation’s result.

The two captures occur even if the token operation returns zero. They are skipped when the flag was already set.

For a nonzero token result:

- Read the configured first-word value and write it through the shared-pointer global used as the descriptor address.
- Write zero at offset four through the captured descriptor pointer.
- Read the configured second initialization argument after both writes.
- Call F-804adc29bbfb with the captured pointer, newly read second argument, and captured third argument.
- Reread the token argument and call F-d08d3ca17b81.

Descriptor writes can therefore affect the second argument through aliasing. F-804adc29bbfb can affect the token argument read afterward. The captured third argument and descriptor pointer remain the earlier values for that call.

The descriptor pointer comes from the same global used for later shared-object operations; distinct allocations are not established. No explicit write setting the tested flag appears here.

Next, capture the selector threshold, then the configured discriminator. Separately read the threshold for equality with the incoming selector. Clear the output slot to zero afterward. The captured threshold controls signed partitioning; the separate threshold read controls equality dispatch.

### Dispatch and completion

Threshold equality has precedence. Otherwise, signed selector comparison against the captured threshold selects a partition:

- At or above the threshold: recognize `0x6215`, `0x6216`, and `0x6217`.
- Below the threshold: recognize `0x6206`, `0x6207`, and `0x6213`.

A named selector receives its described handling only when it reaches that partition without interception by threshold equality. Unrecognized selectors return 0.

Every recognized path requires discriminator equality, including delegation. The position of that check varies.

**Ordinary completion** reads the shared-object pointer, calls F-44362605ab79 with it, writes the returned 32-bit value to the output slot, and returns 1.

**Resolution and assignment** use F-9d0ecc5f6adf to obtain context, F-c0b020cd3882 with that context and an identifier, then F-151ab4bfe553 with the resolved result and a shared pointer read after resolution. Ordinary completion rereads that pointer after assignment. Assignment and completion can therefore use different objects.

Local rejection makes no further explicit output-slot write. Intervening dependencies may nevertheless have modified that slot. No additional ordering is established among separate argument reads within one call.

### Threshold-equality path

Validate in this order:

1. Reject a signed-negative index.
2. Reject an index at or above the unsigned count at object offset `0x9C`.
3. Reject a discriminator mismatch.

Call F-9d0ecc5f6adf. After it returns, read the table base at `0x98` and the first word of the indexed eight-byte record. Resolve that word, assign the result, and complete ordinarily.

The count is read before the context call; the table base and record are read afterward. They need not describe an unchanged table.

### Selector `0x6215`

### Selector `0x6216`

Reject a discriminator mismatch first. Read the signed count at subordinate offset `0x1C` through the pointer at object offset `0xC8`.

If the count is less than or equal to the signed index, skip the update and complete ordinarily.

Otherwise:

1. Call F-78db0cbe9071 with the selector-seeded local address, subordinate object, and original index bits.
2. Read the shared pointer and call F-46f0b3cb316e with it and that local address.
3. Call F-289ec4311c64 with the same local address.
4. Complete ordinarily using a fresh shared-pointer read.

The index-seeded word immediately follows the addressed selector-seeded word in the supplied layout. No dependency access to that adjacent word is established.

There is no explicit nonnegative-index check. A signed-negative index can reach F-78db0cbe9071; that dependency’s acceptance remains unknown.

### Selector `0x6217`

After discriminator validation, invoke the indirect dependency at subordinate dispatch offset `0x1AC`, reached through object offset `0xA8`. No explicit arguments are shown.

Interpret its result as unsigned 32-bit. Subtract one when nonzero; otherwise retain zero. This produces the update limit.

If the unsigned index is below that limit:

1. Call F-f7cb977a5079 with the main object.
2. Reread the subordinate pointer at `0xA8`.
3. Invoke its dispatch slot `0x15C` with the subordinate object, original index, and shared pointer read after F-f7cb977a5079.

Otherwise, skip both calls. Both cases complete ordinarily. Being outside the update limit is not rejection.

The two indirect calls need not use the same subordinate object. Completion can use a different shared object from the update.

### Selector `0x6206`

For other indices:

## Side effects

Initialization can occur even for a request ultimately rejected. Explicit writes include all three local seeds, descriptor preparation, output clearing, and final output assignment. Dependencies can additionally modify supplied local storage, shared objects, buffers, globals, or aliased storage.

Aliasing is unchecked:

- Descriptor writes can change configuration read afterward.
- Output clearing can change object fields or configuration accessed later.
- Dependencies can replace globals before their documented rereads.
- Dependencies can change the output even when no later explicit output write occurs.

Passing a local address establishes neither the complete extent of a temporary object nor which adjacent initialized words a dependency accesses. Setup and finalization calls do not establish construction, ownership transfer, or release.

No caller release obligation or returned-value lifetime is established. Shared-object and buffer outputs must not be assumed stable across subsequent operations. The initialization sequence alone establishes neither synchronization nor thread safety.

## Acceptance examples

These are conditional static consequences, not executed tests. Assume valid accessed storage and routing to the named path. Claims of unchanged memory additionally require dependency noninterference.

1. **Entry initialization:** even an ultimately rejected request seeds three 32-bit words with discriminator, selector, and index before checking initialization state. The index seed is immediately after the selector seed.

2. **Threshold path, index equal to count:** rejects before resolution. A signed-negative index rejects before the count read.

3. **`0x6215`, accepted index 3:** resolves the first word at table base plus 24, assigns, and completes.

4. **Wrapped addressing:** an otherwise accepted index `0x20000000` produces zero displacement when multiplied by eight at 32 bits.

5. **`0x6216`, count 4, index 4:** skips temporary processing and completes ordinarily.

6. **`0x6216`, count 4, index `0xFFFFFFFF`:** reaches F-78db0cbe9071 with those index bits. Its local-address argument points to the selector-seeded word, followed by the index-seeded word. This does not prove either word’s contents at dependency entry or any read of the adjacent word.

7. **`0x6217`, indirect result 1:** the limit becomes zero. Every index skips updating, but ordinary completion still returns 1.

8. **`0x6206`, index 2, zero lookup result:** returns 0 without another explicit output write. Output remains zero only absent intervening modification.

9. **`0x6207`, index 1:** mismatch prevents delegation; a matching discriminator permits propagation of any delegate result, including values other than 0 or 1.

10. **`0x6207`, bound word 3:** indices 2–4 pass; 5 fails. Bound word `0x7FFFFFFE` wraps the upper bound negative and admits no signed index of at least 2.

11. **`0x6213`, index 0, count 0:** rejects before resolving the special identifier.

12. **Shared-pointer replacement:** if assignment replaces the shared-pointer global, completion uses the replacement.

13. **Initialization aliasing:** if the descriptor’s second word aliases the second-argument configuration, the zero write affects the later argument read. The third argument remains captured.
