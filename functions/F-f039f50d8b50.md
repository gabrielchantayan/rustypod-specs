# F-f039f50d8b50

## Purpose

F-f039f50d8b50 performs an ordered, alias-sensitive series of memory observations and mutations, prepares invocation-local storage, invokes an entry-supplied indirect dependency, and then invokes F-cdec09f5d432. If both calls return, the represented path reaches a terminal operation marked nonreturning.

No application-level purpose is established. Repeated displacements suggest structured-state manipulation, but that is **inferred intent**, not evidence of a particular container, allocation scheme, or ownership model. Signed halfwords, loaded words, and multiplication results all become address components.

This contract describes static evidence. It does not establish that the represented entry boundary is independently callable or that a valid execution environment exists for every input.

## Behavior

### Ordering and captured values

The following phases describe the represented order. Earlier writes may affect later reads, including reads used to form addresses. Captured values remain distinct from later observations of the same location.

“Captured static base” means the value obtained from a static update source for that stage’s displacement-0x14 destination. The replacement value is separately referenced from that source. Equality between those two observations must not be assumed if the source can change.

The description preserves access order without asserting an otherwise unspecified concurrency, volatility, or device-memory model.

### Entry and first replacement

The operation first reads a signed halfword at the sum of the anchor and companion. It then reads a byte at the second input plus that signed halfword.

The following writes occur in order:

1. The anchor’s low byte to displacement 0x01 of the first input.
2. The second input’s low byte to displacement 0x0d of the anchor.
3. The full payload word to displacement 0x44 of the anchor.
4. The anchor’s low byte to displacement 0x0d of the address represented by the initial byte.
5. The initial byte, converted to a halfword, to the anchor plus the initial signed halfword.

Only afterward is the anchor’s displacement-0x44 word reloaded and saved. That observation is not replaceable by the earlier payload value.

The companion then receives its own address as a word at displacement 0x54. The first static base is captured. The first static source supplies a replacement word at displacement 0x44 of the byte-derived address. The saved anchor-relative word is transferred to displacement 0x14 of the captured first static base. Finally, the fourth input is written to the companion’s displacement-0x11 byte.

The initial byte’s signedness is unresolved. Its address interpretation and halfword conversion are therefore not fixed for high-bit-set values.

### Second replacement: ordered observations

Between the first and second replacements, these reads occur in this exact order:

1. The first input’s displacement-0x64 word.
2. The companion’s displacement-0x44 word, retained as the **second replacement destination base**.
3. A signed halfword at the companion plus the captured first static base.
4. A displacement-0x74 word through the saved anchor-relative reload, retained as the **second traversal value**.
5. The companion’s displacement-0x14 word, retained as the **working base**.

The second traversal value’s low byte is written at displacement 0x0d of the second replacement destination base. A halfword containing that destination base’s low 16 bits is then written at the sum of the saved signed halfword and second traversal value.

After both writes, the second traversal value’s displacement-0x44 word is captured as the next **transfer value**. The working base receives itself as a word at displacement 0x54.

The second static base is then captured. Its separately referenced replacement value is written to displacement 0x44 of the second replacement destination base. The saved transfer value is written to displacement 0x14 of the captured second static base. The working base’s displacement-0x11 byte receives the low byte of the first input-relative displacement-0x64 capture.

### Third replacement: captures before mutations

Before the next mutations, the operation reads:

- The working base’s displacement-0x44 word, retained as the **third replacement destination base**.
- A signed halfword at the working base plus the captured second static base.

Using the existing transfer value, it writes the second static base’s low byte to displacement 0x15 of that transfer value. It then writes the full transfer value to displacement 0x44 of the second static base.

Only after those writes does it read displacement 0x74 through the saved third replacement destination base. A halfword containing that destination base’s low 16 bits is written at the newly observed displacement-0x74 value plus the saved signed halfword. Neither of the two earlier captures is reread for this calculation.

After the halfword store, displacement 0x44 of the new traversal value is captured as the next transfer value. The working base receives a displacement-0x54 self-address word store.

The third static base is captured. The third static source separately supplies a replacement word at displacement 0x44 of the third replacement destination base. The saved transfer value is written to displacement 0x14 of the captured third static base.

The working base’s displacement-0x11 byte then receives the low byte of twice that working base. This byte is not derived from an input-relative capture.

### Fourth replacement

The first input’s displacement-0x64 word is read for the second time. Next, the operation reads the working base’s displacement-0x44 word as the **fourth replacement destination base**, followed by a signed halfword at the working base plus the third static base.

A word at displacement 0x14 of that signed-halfword-derived address is read as a **new working base**. The following effects occur in order:

1. The fourth replacement destination base receives itself at displacement 0x54.
2. The full payload word is stored at the third static base plus the preceding transfer value.
3. The fourth replacement destination base is stored at displacement 0x14 of the third static base.
4. A fresh payload-relative displacement-0x44 word is read, and its low byte is stored at displacement 0x0d of the third static base.
5. The fourth replacement destination base’s low byte is stored at displacement 0x0d of the new working base.
6. That destination base’s low 16 bits are stored at the saved signed halfword plus the third static base.

The third static base’s displacement-0x44 word is then captured as the next transfer value. The new working base receives itself at displacement 0x54.

The fourth static base is captured. Its separately referenced replacement value is written to displacement 0x44 of the fourth replacement destination base. The transfer value is written to displacement 0x14 of the fourth static base. The new working base’s displacement-0x11 byte receives the low byte of the second input-relative displacement-0x64 capture.

This new working base is the current working base for the next phase.

### Fifth replacement

The first input’s displacement-0x64 word is read for the third time. The operation then reads the current working base’s displacement-0x44 word as the **fifth replacement destination base**, followed by a signed halfword at the current working base plus the fourth static base.

Before the signed-halfword-derived displacement-0x14 read, three writes occur:

1. Displacement 0x54 of the preceding transfer value receives the **current working base**, not necessarily its own destination base.
2. The current working base’s displacement-0x11 byte receives the low byte of the third input-relative capture.
3. Displacement 0x44 of the fifth replacement destination base receives the fourth static base.

The word at displacement 0x14 of the saved signed-halfword-derived address is then read as the **next working base**. Subsequent effects occur in order:

1. The fifth replacement destination base receives itself at displacement 0x54.
2. The full payload word is stored at the fourth static base plus the preceding transfer value.
3. The fifth replacement destination base is stored at displacement 0x14 of the fourth static base.
4. A fresh payload-relative displacement-0x44 word supplies the byte written at displacement 0x0d of the fourth static base.
5. The fifth replacement destination base’s low byte is stored at displacement 0x0d of the next working base.
6. Its low 16 bits are stored at the saved signed halfword plus the fourth static base.

The fourth static base’s displacement-0x44 word is then captured for transfer. The next working base receives itself at displacement 0x54, before the fifth static source is captured.

The fifth replacement is written at displacement 0x44 of the fifth replacement destination base. The captured transfer word is stored at displacement 0x14 of the captured fifth static base. The next working base’s displacement-0x11 byte receives the same saved byte from the third input-relative capture.

Thus, the two fifth-stage input-derived byte writes share one capture despite intervening reads and writes.

### Product-derived traversal

The operation reads the next working base’s displacement-0x44 word, then a signed halfword at that working base plus the fifth static base. The widened signed halfword is retained for addressing and multiplication.

The following pair occurs twice consecutively:

- Store the retained signed-halfword value as a word at displacement 0x54 of its own derived address.
- Store the working base’s low byte at displacement 0x11 of the fifth static base.

Both occurrences are represented.

The retained signed halfword is multiplied by the saved working-base-relative word. Starting at that product-derived base, successive word reads at displacements 0x44, 0x74, and 0x14 produce a destination address. Its displacement-0x14 word is read and saved, then replaced with twice the working base.

A word at displacement 0x14 of the saved old value is read and multiplied by the retained signed halfword, producing a new product base. Next come a signed-halfword-derived displacement-0x54 self-address store and a fifth-static-base displacement-0x11 byte store from the saved old value.

The new product base’s displacement-0x74 word is captured as the **retained traversal result**, including a copy in invocation-local storage. Multiplying that product base again by the retained signed halfword produces the **further product base**. Another signed-halfword-derived self-address store follows, then the fifth static base’s displacement-0x11 byte receives the retained traversal result’s low byte.

### Final memory updates

The operation reads displacement 0x44 of the further product base, then displacement 0x74 of the first input.

The retained traversal result is written as a word at displacement 0x64 of the fifth static base. The initial further-product-relative capture supplies that static base’s displacement-0x09 byte.

Displacement 0x44 of the further product base is then read again. This later observation supplies the byte stored at displacement 0x11 of the further product base. Intervening overlapping writes can make it differ from the first capture.

Another signed-halfword-derived displacement-0x54 self-address store follows. The retained traversal result’s low byte is stored at displacement 0x11 of twice the further product base.

Next, a word is captured at displacement 0x44 of the retained signed halfword multiplied by the further product base. The first input’s displacement-0x14 word is then captured.

The final three nonlocal byte writes are, in order:

1. The earlier first-input-relative displacement-0x74 capture’s low byte, at displacement 0x01 of the retained traversal result.
2. The multiplication-relative capture’s low byte, at displacement 0x11 of the first input’s captured displacement-0x14 value.
3. The low byte of twice the further product base, at displacement 0x09 of that same captured value.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Early truncation.** If the anchor ends in 0xAB and the initial accesses complete, the first input’s displacement-0x01 byte receives 0xAB. Later overlap may replace it.

2. **Signed initial offset.** An initial halfword of −2 offsets the second input by −2 for the byte read, subject to actual address rules. An initial byte of 0x80 does not establish whether its subsequent interpretation is 128 or −128.

3. **Second-stage observation order.** An access-sensitive environment must observe the input-relative 0x64 read before the companion-relative 0x44 read, then the signed-halfword read, then the saved-anchor-derived 0x74 read, and finally the companion-relative 0x14 read.

4. **Third-stage saved addresses.** If the displacement-0x15 or static-relative displacement-0x44 write overlaps either preceding capture, the subsequent traversal still uses the saved destination base and signed halfword. Rereading either after those writes is not equivalent.

5. **Fifth-stage non-self store.** If the preceding transfer value and current working base differ, displacement 0x54 of the transfer value receives the current working base. The later two displacement-0x54 stores use their respective destination bases as values and occur at the specified boundaries.

6. **Independent static observations.** If a static source changes between capture and replacement reference, the transfer destination base need not equal the replacement word.

7. **Capture reuse and duplicate writes.** Changes to the first input’s displacement-0x64 word after its third capture do not change either fifth-stage byte derived from that capture. Both repeated product-stage store pairs remain represented.

8. **Late overlap.** If a fifth-static-base store modifies the further product base’s displacement-0x44 word, the later byte derived from its reread may differ from the earlier displacement-0x09 byte.

9. **Nonreturning dependency.** If the first indirect call does not return, the later local writes and F-cdec09f5d432 call do not occur. If both calls return, the next established endpoint is the terminal operation, not normal return.
