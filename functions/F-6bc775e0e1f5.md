# F-6bc775e0e1f5

## Purpose

F-6bc775e0e1f5 conditionally performs a halfword copy and a more narrowly gated halfword update, then enters an unconditional dispatch cycle containing two indirect invocations and a software interrupt.

No application-level purpose is established. The supplied representation does not justify identifying this operation as initialization, decoding, error handling, or a conventional callable service.

The contract distinguishes:

- Reachable effects under the explicit 32-bit interpretation below.
- Additional represented operations excluded by that interpretation’s gate conditions.
- Unknown platform and dependency behavior, retained as documented_only.

The excluded operations include an address calculation involving conversion to plain char. Neither that character type’s width nor its signedness is established. It must not be described as a signed 8-bit conversion.

## Behavior

### Initial selection and copy

The initial selector is the low 32 bits of the control word multiplied by \(2^{22}\). It is zero exactly when the control word’s low ten bits are zero.

When the selector is nonzero:

- No prefix memory access occurs.
- The conditional memory-manipulation prefix is bypassed.
- The first terminal invocation uses the incoming link address plus byte offset `0xeb6`.

When the selector is zero, the routine performs an initial halfword copy.

The destination address is:

\[
\text{source address}+\text{displacement word}\pmod{2^{32}}.
\]

A 16-bit unsigned value is read from the incoming source address, then that value is written as a 16-bit value to the destination address. The read precedes the write. Identical source and destination addresses do not eliminate either represented access.

Between that read and write, the represented source-address state is changed to:

\[
\text{destination address}-\text{adjustment word}\pmod{2^{32}}.
\]

This is a change to working machine state. It does not establish a write to caller-owned pointer metadata.

The path also derives a working address from the link address, the unsigned stack address shifted right by one, and a control-bit contribution. Because entry requires the low ten control bits to be zero, that contribution is zero. A second control scaling, by \(2^{23}\), is also zero.

If the incoming link address is nonzero, no further prefix memory access occurs.

### Gates admitting the exceptional operation

After the copy, additional work is admitted through successive zero-result gates.

Under the width model above, the exceptional operation requires all of these conditions:

1. The control word’s low ten bits are zero.
2. The incoming link address is zero.
3. The stack address is zero.
4. The auxiliary word equals the displacement word.
5. The updated source-address value equals the adjustment word.
6. The accumulator word is zero.
7. Twice the displacement word is zero modulo \(2^{32}\).

The final condition allows exactly two displacement values: `0x00000000` and `0x80000000`.

The updated-source equality is equivalently:

\[
\text{source address}+\text{displacement word}
\equiv 2\,\text{adjustment word}\pmod{2^{32}}.
\]

The stack-address condition follows from the combined gates, not from the right shift alone. With the link address zero, the earlier shifted-stack gate allows stack address zero or one. The later requirement that the stack address plus twice the displacement be zero excludes one, because twice a 32-bit word is even modulo \(2^{32}\).

The accumulator gate contributes no carry on a successful exceptional path. The earlier control-derived addend and incoming carry contribution have already been forced to zero.

The right shifts used by these zero-gated comparisons receive a zero shift count whenever the corresponding gate is entered. No independently variable shift count is needed to derive these reachable-path conditions.

These conditions describe represented values. They do not prove that a real caller can supply them or that the associated addresses are mapped.

### Exceptional halfword operation

When all preceding gates admit execution, the following effects are represented:

- The auxiliary state location is written with the stack address multiplied by 64.
- A halfword read through the incoming link address supplies a zero-extended destination address.
- Another halfword use through that link address supplies the value to be increased by fifteen and stored at the derived destination.

On this path, both the stack address and link address are zero. Consequently:

- The auxiliary-state value written is zero.
- The halfword operation depends on reading address zero.
- The derived destination lies between `0x00000000` and `0x0000ffff`.
- The stored value is reduced to 16 bits.

The auxiliary-state write precedes the halfword operation. Its destination’s architectural meaning is unknown; it must not be interpreted as a known register or ordinary memory location.

The representation contains two uses of the link-address dereference in the assignment. It does not establish a shared snapshot or an ordering between those operand reads. If the reads observe values \(H_{\text{address}}\) and \(H_{\text{value}}\), respectively, the resulting store is:

- Destination: the zero-extended value \(H_{\text{address}}\).
- Value: \((H_{\text{value}}+15)\bmod 2^{16}\).

The simpler description “write the halfword plus fifteen through that halfword” therefore requires both reads to observe the same value. Volatile, device-backed, or externally changing storage cannot be assumed stable.

The exceptional path also advances a zero-valued halfword-oriented working address by one element, yielding byte address two.

### Exclusion of the later conditional region

If the exceptional operation is not entered, the gate starting the later chain is false.

If it is entered, the next chain initially permits a zero result. Its following comparison combines the newly advanced byte address two with a working address already forced to zero. Their exclusive-or result is two, so the next zero gate fails.

Thus, under the stated 32-bit interpretation, the subsequent conditional memory-manipulation region cannot execute.

Its represented operations nevertheless require accurate documentation. They include:

### Terminal dispatch cycle

Every prefix path that completes under the stated model reaches an unconditional cycle.

For the first iteration, the dispatch base is the incoming link address. The exceptional path leaves it zero, equal to that path’s required incoming link address.

Each iteration has the following observable transfer order:

1. Invoke the target at the dispatch base plus byte offset `0xeb6`, with explicit argument values zero, zero, and `0xffffffa5`.
2. If that invocation returns, invoke the target at absolute address `0x0857a94b`.
3. If that invocation returns, issue software interrupt immediate `0x5b`.
4. If execution resumes, replace the dispatch base with `0x083d4cc2` and repeat.

The first target in every subsequent iteration is therefore `0x083d5b78`.

The third explicit argument has the 32-bit bit pattern `0xffffffa5`. Whether the recipient interprets it as unsigned 4294967205 or signed −91 is unknown.

No returned result is explicitly consumed. The second invocation has no explicit arguments in the representation, but this does not prove that it consumes no incoming register, stack, or global state.

The computed targets are not evidence that executable code exists at those addresses. Architectural preservation across the transfers is also not established independently of the represented control flow.
