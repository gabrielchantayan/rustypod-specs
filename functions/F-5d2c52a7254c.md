# F-5d2c52a7254c

## Purpose

F-5d2c52a7254c computes indices and a final extent for a layout containing:

- An optional four-position shared region.
- An optional single-position item.
- Up to two eligible entries, each occupying two positions.

The established computation has two passes over exactly two entries. The first folds configuration into four logical channels and determines whether the shared region exists. The second independently checks entry eligibility and assigns entry indices.

“Position,” “entry,” and “shared region” describe the observed arithmetic. Resource allocation is inferred intent; no backing allocation, resource creation, or application-specific meaning is established.

## Interface

**Input:** one 32-bit address-valued argument identifying an object with readable input fields and writable result fields.

**Output:** five 32-bit fields written into that object. No return value is provided.

The supplied representation uses 32-bit addresses and integer fields, with byte-sized configuration reads. Byte order and alignment requirements are not established.

### Object layout

| Object-relative offset | Width | Meaning |
|---|---:|---|
| `0x38` | 32 bits | Associated address for entry 0 |
| `0x3C` | 32 bits | Associated address for entry 1 |
| `0x40` | 32 bits | Configuration-storage address |
| `0x6C` | 32 bits | Final extent |
| `0x70` | 32 bits | Shared-region index |
| `0x74` | 32 bits | Optional single-position index |

An absent index is represented by the exact 32-bit pattern `0xFFFFFFFF`. Signed −1 is one interpretation of this pattern, not an additional result value.

Let **S** denote the configuration address read from object offset `0x40` at function entry. During the first pass, entry 0 uses configuration origin S, and entry 1 uses S + `0x24`.

### Entry-relative configuration

| Offset from entry origin | Width | Meaning |
|---|---:|---|
| `0x20` | 8 bits | Enable flag; zero disables the entry |

- `0x84`, `0x8C`, and `0x7F`: shared-region qualification inputs.

An eligible entry with primary operation 1 also reads a subtype byte at its associated address plus `0x0C`.

### Preconditions and ownership

Every address actually read or written must identify accessible storage. The function does not check the object address, configuration address, storage bounds, or associated-address validity. An associated address is checked only for being nonzero.

There is no allocation, release, ownership transfer, or visible external call. Referenced storage remains caller-provided; the function establishes no ownership rights over it.

Address computations use the supplied 32-bit representation without visible overflow checks. The bounded position arithmetic described below does not overflow. Behavior for invalid or overflowing address computations is not established as a supported contract.

## Behavior

### First-pass eligibility and initial state

The first pass maintains four logical channels, designated **A**, **B**, **C**, and **D**:

| Channel | Initial value |
|---|---|
| A | True |
| B | True |
| C | False |
| D | False |

Entry 0 is processed before entry 1. Each entry receives the channels produced by the preceding entry.

An entry is eligible when its enable byte is nonzero and its associated address is nonzero. The enable byte is read first. The associated-address field is read only if the enable byte is nonzero.

An ineligible entry preserves all four channels and does not read its primary operation, selectors, terms, or associated subtype.

### Primary operations

For an eligible entry, the operation byte determines the outgoing channels:

| Operation | Outgoing A | Outgoing B | Outgoing C | Outgoing D |
|---|---|---|---|---|
| 0 | False | Incoming B | False | False |
| 1, subtype 0 | Incoming A | False | False | False |
| 1, subtype 1, 3, or 5 | False | Incoming B | False | False |
| 1, any other subtype | False | False | False | False |
| 2, 3, or 4 | Incoming A | Incoming B | False | False |
| 5 | Paired-term result | Paired-term result | Paired-term result | Paired-term result |
| Any other operation | False | False | False | False |

The subtype byte is read only for operation 1. Subtypes 2 and 4 are included among the subtype values that clear every channel.

An unrecognized operation is therefore observably different from an ineligible entry: it clears the channels rather than preserving them.

### Operation 5: terms and predicates

Operation 5 starts all outgoing channels false, then combines selected contributions with logical OR. Contributions use the entry’s incoming channel values, not partially accumulated outgoing values.

The terms are paired as follows:

| Term | Status offset | Value offset |
|---|---|---|
| First-group term 0 | `0x28` | `0x2E` |
| First-group term 1 | `0x29` | `0x2F` |
| First-group term 2 | `0x2A` | `0x30` |
| Second-group term 0 | `0x2B` | `0x31` |
| Second-group term 1 | `0x2C` | `0x32` |
| Second-group term 2 | `0x2D` | `0x33` |

A **low value** is unsigned byte value 0 or 1. A **high value** is exactly 2 or 3. Values 4 through 255 are neither low nor high.

A status **admits an incoming channel** when the status is 2, or when the status is 3 and that channel is true. No other status admits a channel.

#### First group

The first selector, at entry-relative offset `0x26`, selects terms in this order:

| Selector | Terms evaluated |
|---|---|
| 0 | Term 0 |
| 1, 2, 3, 5, 6, or 7 | Term 1, then term 0 |
| 4 or any other byte value | Term 2, then term 1, then term 0 |

Each selected term contributes:

- To A when its status admits incoming A and its value is low.
- To C when its status admits incoming B and its value is high.
- Also to C when its status admits incoming C and its value is low.

The two contributions to C are OR-combined.

Status 2 can therefore create A or C even when the corresponding incoming channels are false. In particular, a selected status-2 term with a low value contributes to both A and C.

#### Second group

After the first group, the selector at entry-relative offset `0x27` selects:

| Selector | Terms evaluated |
|---|---|
| 0 | Term 0 |
| 1, 2, 3, or 5 | Term 1, then term 0 |
| 4 or any other byte value | Term 2, then term 1, then term 0 |

Each selected term contributes:

- To B when its status admits incoming B and its value is high.
- To D only when incoming D is true, its status is exactly 3, and its value is high.

Status 2 cannot independently create D. Selectors 6 and 7 include term 2 in this group, unlike the first group.

#### Final substitution

After both groups, the first selector at `0x26` is read again. If this later read equals 7:

- B is replaced by the computed C.
- D is replaced by the computed A.
- A and C remain unchanged.

The second group is still evaluated before this replacement. Its reads are not skipped merely because the selector previously read as 7.

### Shared-region qualification

After the two entries, two results are computed in order.

The **first qualification result** is true if final A is true, or if final D is true and the additional qualification bytes contain a nonzero value.

The **second qualification result** is true if final C is true, or if final B is true and those additional bytes contain a nonzero value.

Whenever an additional-byte check is needed, it reads:

1. S + `0x84`.
2. S + `0x8C`, only if the preceding byte was zero.
3. S + `0x7F`, only if both preceding bytes were zero.

The first result performs no such reads when A is true or D is false. The second performs no such reads when C is true or B is false.

The second result is evaluated even when the first is already true. If both results need additional-byte checks, each performs its own reads; the first check is not reused as a snapshot.

The shared region exists if either result is true.

Consequently, when both entries are ineligible, initial A survives and guarantees a shared region regardless of the additional-byte values. Initial B also survives, so the second qualification result still checks those bytes.

### Position assignment

After qualification, the function reads the optional-item byte at S + `0x18`, before writing any output.

If the shared region exists, the shared index is 0 and the next available position is 4. Otherwise, the shared index is absent and the next available position is 0.

If the previously read optional-item byte is nonzero, the optional index receives the next position and advances it by 1. If zero, the optional index is absent and the position does not advance.

The function then processes entry 0 and entry 1 again:

- For each entry, it rereads the object’s configuration-address field.
- It reads that entry’s enable byte through the newly read address.
- Only for a nonzero enable byte does it reread the associated-address field.
- An eligible entry receives the current position and advances it by 2.
- An ineligible entry receives the absent sentinel and does not advance it.

First-pass eligibility is not cached. Primary operations and subtypes do not affect second-pass eligibility and are not reread during position assignment.

Finally, the current position is stored as the final extent. It counts positions, not bytes. The maximum is 9: four shared positions, one optional position, and two positions for each of two entries. All position increments and assigned indices fit within 32 bits.

## Side effects

### Ordered writes

On normal completion, the function performs five 32-bit output stores in this order:

1. Shared index at object offset `0x70`.
2. Optional index at `0x74`.
3. Entry 0 index at `0x78`.
4. Entry 1 index at `0x7C`.
5. Final extent at `0x6C`.

Existing result values are overwritten. They are not read or accumulated as result inputs.

All first-pass reads, qualification reads, and the optional-item read precede the first output store. Entry 0’s second-pass reads occur after the first two stores. Entry 1’s second-pass reads occur after entry 0’s result store.

Aliasing can therefore affect subsequent reads. The function does not establish an entry-time snapshot of the entire object or configuration.

### Conditional and repeated reads

Within operation 5, term evaluation has observable ordering:

- All selected first-group terms precede the second-selector read.
- Within each first-group term, the A predicate precedes the high-value C predicate, which precedes the low-value C predicate.
- Within each second-group term, the B predicate precedes the D predicate.
- The final reread of the first selector follows both groups.

A status-admission predicate checks status 3 only when its incoming channel is true. If that does not establish admission, it checks status 2. These checks can reread the status byte.

Value bytes are read only after the corresponding status/channel condition permits a contribution. A high-value check first compares against 2 and, if that fails, reads again for comparison against 3. Separate contribution predicates may reread the same term fields.

Selected terms remain evaluated even when an earlier term already made an outgoing channel true. Unselected terms are not evaluated. These access distinctions must not be replaced with an unconditional read of every term field.

Support for device-backed or concurrently changing storage is not established. The static read ordering is documented without asserting a synchronization model.

## Acceptance examples

These are conditional predictions from static evidence, not executed tests. Unless stated otherwise, storage is valid, stable throughout the call, and does not alias output fields.

1. **Both entries disabled; additional bytes all zero; optional item disabled.**  
   The channels remain A=true, B=true, C=false, D=false. A makes the first qualification result true without additional-byte reads for that result. The second result checks all three additional bytes and is false. The shared index is 0; optional and entry indices are `0xFFFFFFFF`; extent is 4.

2. **Both entries disabled; first additional byte nonzero; optional item disabled.**  
   A already guarantees the shared region. The second qualification result reads S + `0x84`, finds it nonzero, and does not read the other two qualification bytes. The shared index is 0; the other indices are absent; extent is 4. The nonzero byte changes qualification reads and the second result, not the final layout.

3. **Both entries disabled; optional item enabled.**  
   A survives, so a layout without the shared region is impossible under these conditions. The shared index is 0, the optional index is 4, both entry indices are absent, and extent is 5, regardless of the additional-byte values.

4. **Both entries eligible with operation 2; additional bytes zero; optional item disabled.**  
   A remains true through both entries. The shared index is 0, entry indices are 4 and 6, the optional index is absent, and extent is 8.

5. **Both entries eligible with unrecognized operations; optional item enabled.**  
   Both operations clear the channels. Neither qualification result needs additional-byte reads. The shared index is absent, the optional index is 0, entry indices are 1 and 3, and extent is 5. Unrecognized operations do not prevent entry-position assignment.

6. **Entry 0 enabled but associated address zero; entry 1 disabled; optional item disabled.**  
   Both entries are ineligible and preserve the initial channels. Neither receives an entry index. No subtype is read through the zero address. The shared index is 0 and extent is 4.

7. **Selected first-group term with status 2 and value 0.**  
   Under operation 5, that term contributes true to both A and C regardless of their incoming values. Replacing its value with 255 removes both contributions from that term.

8. **Selector asymmetry.**  
   First-group selector 6 omits first-group term 2. Second-group selector 6 includes second-group term 2. The corresponding term-2 reads and contributions therefore differ between groups.

9. **Selector-7 replacement.**  
   If the first group computes A=true and C=false, and the final selector reread yields 7, outgoing D becomes true and B becomes false regardless of the second group’s computed results. Its evaluation and reads still occur.

10. **Maximum extent.**  
    With a shared region, enabled optional item, and both entries eligible in the second pass, the shared index is 0, optional index is 4, entry indices are 5 and 7, and extent is 9.
