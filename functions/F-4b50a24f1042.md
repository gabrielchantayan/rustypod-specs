# F-4b50a24f1042

## Purpose

F-4b50a24f1042 conditionally replaces the character-sized value at a caller-supplied address. Under valid, stable access conditions, it has three outcomes:

- An initial value of 1 is replaced with 2.
- An initial value of 3 is replaced with 4.
- Every other value is left unchanged.

The operation affects the supplied location directly and returns no value. It does not scan a buffer, interpret a string, or access a subsequent element.

These replacements are established behavior. Any interpretation of the values as application states, flags, protocol tokens, or lifecycle stages is inferred intent, not part of the established contract.

## Interface

**Input:** One pointer identifying a character-sized storage location.

**Output:** No return value. The observable result, when a replacement occurs, is the updated value at the supplied address.

**Storage layout and width:**

- The accessed region is one character-sized unit at offset zero from the supplied address.
- No record layout, length field, alignment-sensitive multibyte field, or trailing terminator is inspected.
- The source establishes character-width access, not the implementation’s number of bits per character. On an eight-bit-byte implementation, the accessed region is one octet; that platform property is not independently established by the supplied material.
- The numeric values 1, 2, 3, and 4 are representable regardless of whether plain character storage is signed or unsigned. Consequently, the two replacement rules do not depend on character signedness.
- No pointer arithmetic, integer addition, subtraction, multiplication, shifting, or width conversion determines the replacement values.

**Caller obligations:**

The pointer must designate live storage that may legally be read through a character pointer. If execution selects a replacement, that storage must also be writable. A caller seeking a precondition sufficient for every possible input should provide readable and writable character storage.

A null pointer, dangling pointer, inaccessible address, or otherwise invalid access is outside the contract’s defined operating conditions. The function supplies no validation or recoverable error result for such cases.

The interface contains no size argument. A larger allocation is not required by this operation, but any surrounding storage remains the caller’s responsibility.

## Behavior

### Read and decision order

The function first reads the character-sized value at the supplied address and compares it with 1.

If that comparison succeeds, it selects 2 as the replacement. It does not evaluate the comparison against 3 on this path.

If the first comparison does not succeed, the function evaluates the value at the same address again, comparing it with 3.

- If this second comparison succeeds, it selects 4 as the replacement.
- If this second comparison does not succeed, the function returns without assigning to the supplied location.

The source therefore contains one evaluated dereference for the first decision and, only when that decision fails, another evaluated dereference for the second decision. These are source-level access semantics. The interface does not designate volatile storage, so this contract does not promise a corresponding count of physical memory transactions after compilation.

### Write and return order

For either selected replacement, the function assigns the replacement to the same character-sized location that was inspected. It then returns without a value.

There is at most one source-level assignment through the supplied pointer during an invocation:

| Decision outcome | Assigned value | Assignment performed |
|---|---:|---|
| First comparison matches 1 | 2 | Yes |
| First comparison does not match 1; second comparison matches 3 | 4 | Yes |
| Neither comparison matches | None | No |

The write follows the comparison or comparisons that selected it. No additional read of the supplied location is expressed after that write.

### Stable-input result

When the supplied location remains stable throughout the decision phase, the externally relevant transformation is exactly 1 to 2, 3 to 4, and identity for every other representable character value.

For example, 2 is not advanced to 3, and 4 is not advanced to 5. Zero is not treated as an error or terminator; it simply does not select a write. Values outside the four small positive constants likewise receive no special treatment.

The two replacement rules do not form a cascading operation within one invocation. A selected replacement is written once, with no subsequent examination of that result.

### Repeated invocation

Under the same valid, stable-access assumptions, the operation is idempotent with respect to the final stored value:

- After 1 becomes 2, another invocation leaves 2 unchanged.
- After 3 becomes 4, another invocation leaves 4 unchanged.
- An initially unrecognized value remains unchanged across repeated invocations.

This follows from the replacement values not being recognized input values. It does not establish synchronization, transactional execution, or protection against an external writer.
