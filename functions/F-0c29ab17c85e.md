# F-0c29ab17c85e

## Purpose

F-0c29ab17c85e is represented as a nonterminating sequence of indirect calls, computed-address memory accesses, and updates to state carried into the next iteration.

The established behavior is structural rather than domain-specific: obtain values from unresolved dependencies, scale or extract portions of those values, write words and bytes to computed addresses, and repeat. The evidence does not establish that these operations implement initialization, rendering, decoding, allocation, or any other application-level service.

There is no visible success result, error result, normal return, or explicit termination condition. Completing one iteration is not completion of the function.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional arithmetic interpretation:** results under a 32-bit, low-word machine-arithmetic interpretation.
- **Documented-only unknowns:** entry-state requirements, dependency behavior, target validity, and other properties not established by the evidence.

## Behavior

### Arithmetic model and sequencing

The following description preserves the visible order of explicit calls and memory operations. It does not assert that dependencies have no additional reads, writes, exceptions, or nonlocal control flow.

For compactness, a “fourfold result” means a dependency-produced 32-bit value shifted left by two positions. Arithmetic reductions below are conditional on retaining the low 32 bits. The representation contains signed shifts and multiplications whose language-level overflow behavior is not independently established.

All unresolved call targets are referenced collectively as **F-unknown**. This is an opaque dependency-set identifier, not a claim that the calls reach one function.

### 1. Enter the iteration and publish the current third argument

Three indirect calls occur before the first explicit memory store. The first target depends on the entry-call anchor; the following two use represented fixed anchors with displacement-based target formation.

The function then:

1. Stores the current third argument shifted left by two into the word-store base plus `0x14`.
2. Reads the global word.
3. Calls F-unknown with the current fourth argument.
4. Executes three further indirect calls.
5. Makes another indirect call represented as producing a 64-bit result.

The low half of this result, shifted left by two, becomes the **first scaled result**. The high half is retained for a subsequent call.

The global read occurs after the initial word store. If their storage overlaps, the read can observe that store. No non-aliasing guarantee is supplied.

### 2. Publish and clear an initial selector-derived byte

The function reads the unsigned selector byte at byte-state base plus `1`. At the address equal to that selector plus `0x11`, it stores the low byte of the global word shifted right by 22.

It then calls F-unknown with the high half of the preceding 64-bit result, obtains another dependency result, and passes that result together with the first scaled result shifted left by 28 to another dependency.

After further calls, a dependency produces a word result. The function rereads the selector at byte-state base plus `1` and stores zero at that selector plus `0x11`. It then calls F-unknown with the newly produced word shifted left by two.

The selector read for the zero store is a new read. Intervening dependencies may have changed it, so the zero need not clear the same address as the preceding nonzero store.

After another group of calls, a dependency result is shifted left by two and passed twice to one call.

### 3. Write the first pair of scaled words

Following additional calls, a dependency result is shifted left by two to form the **first payload**.

The function:

1. Stores the first payload at first scaled result times `0x1000`, plus `0x14`.
2. Calls F-unknown with the first scaled result shifted left by 14.
3. Executes intervening indirect calls.
4. Obtains another word result.
5. Stores the same first payload at that result times `4`, plus `0x14`.
6. Calls F-unknown with that result times `4`.

The payload is retained across the intervening calls in the represented flow. This does not imply that the calls preserve the global word or either destination’s contents.

### 4. Publish a payload-derived byte

A subsequent indirect call produces another represented 64-bit result. Its low half shifted left by two becomes the **second scaled result**.

Before passing the high half to a dependency, the function:

1. Reads a selector byte at first scaled result times `0x4000`, plus `1`.
2. Stores a byte at selector plus `0x11`.
3. Derives that byte from the first payload masked with `0x3fffffff`, shifted right by 20, then truncated to eight bits.

The masked-and-shifted intermediate has ten bits; the byte store retains only its low eight bits.

Following more calls, another 64-bit dependency result has its low and high halves passed as two arguments to a later dependency.

### 5. Perform three selector-derived zero stores

A dependency produces a word result. Before forwarding its fourfold value, the function reads a selector at second scaled result times `0x10000000`, plus `1`, and stores zero at selector plus `0x11`.

Another dependency sequence produces the **third source result**. Its fourfold value becomes the **third scaled result**.

The function then reads a selector at second scaled result times `4`, plus `1`, and stores zero at selector plus `0x11`.

It calls a dependency with the second scaled result shifted left by 10. A later call receives another dependency result and the current third explicit argument shifted left by 28.

After more calls produce another result, the function again reads the selector at second scaled result times `4`, plus `1`, stores zero at selector plus `0x11`, and forwards the newly produced result shifted left by two.

These are distinct selector reads and distinct stores, even though two use the same address formula.

### 6. Write the second pair of words

The **second payload** is the third source result shifted left by 14.

The function:

1. Stores it at third scaled result times `0x1000`, plus `0x14`.
2. Calls F-unknown with third scaled result shifted left by 14.
3. Makes another indirect call.
4. Calls a dependency with the second payload shifted left by 28 and an additional machine-produced argument.

The additional argument in step 4 has no established producer or meaning in the supplied representation.

### 7. Publish another payload byte and write the third pair of words

A following call receives four arguments, in order:

2. The same value again.
3. The unscaled source of the fourth scaled result shifted left by 14.

### 8. Perform two repeated word-publication groups

During the second occurrence, the byte-state base is replaced by the new source result times `0x40000000`. Under the conditional 32-bit arithmetic model, this base has only four possible values: zero, `0x40000000`, `0x80000000`, or `0xc0000000`.

The repeated stores remain observable; intervening dependencies may have modified either location.

### 10. Replace loop arguments and read a computed word

2. Stores a prior destination-producing result shifted left by 31 at the new result times `0x10`, plus `0x14`.

After further calls, the function stores a zero word at a returned result times `4`, plus `0x14`, then passes that result times `4` to a dependency.

A subsequent result becomes the **final byte source**. The function:

1. Reads the selector at byte-state base plus `1`.
2. Stores the low byte of final byte source shifted left by two at selector plus `0x11`.
3. Calls F-unknown with final byte source shifted left by two.
4. Obtains another dependency result.
5. Passes that result and final byte source shifted left by 30 to another dependency.

## Side effects

Explicit effects include word stores, byte stores, selector-byte reads, one global-word read per reached iteration, and one computed-address word read.

No rollback or transaction boundary is visible. If a dependency fails, does not return, or an access faults, earlier effects may already have occurred.

Memory regions may alias. In particular:

- Selector-derived byte stores target addresses from `0x11` through `0x110`.
- A later selector read can observe an earlier byte write.
- Word destinations can overlap byte destinations.
- The final selector-derived word-store base makes the next initial word-store address fall between `0x14` and `0x113`.
- Dependencies can change explicitly accessed storage between reads.

No synchronization, atomicity, memory-order guarantee, bounds check, alignment check, or access-permission check is visible.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Each assumes the relevant calls return and required memory accesses are valid.

1. **Initial word publication:** With third argument `3`, the first explicit word store writes `12` at the incoming word-store base plus `0x14`, after the three initial calls.

2. **Unsigned selector addressing:** A selector value of `0xff` selects byte address `0x110`, not a negative offset.

3. **Global extraction:** A sampled global word of `0x0fc00000` yields byte `0x3f` for the initial selector-derived store.

4. **Byte truncation:** A masked extraction of `0x3ff` stores byte `0xff`, not a ten-bit value.

5. **Repeated selector reads:** If a dependency changes the selector between a publication and its subsequent clearing operation, the clear targets the newly selected address. Reusing the earlier selector would not match the represented behavior.

6. **Unaligned word read:** An extracted index of `1` produces a word-read address of `0x15`. Whether this succeeds is platform-dependent and undocumented.

7. **Zero-producing shift:** Under 32-bit low-word arithmetic, the second payload’s subsequent left shift by 28 supplies zero regardless of its source.

8. **Loop continuation:** Reaching the final call does not return to the caller. If that call returns, execution starts another iteration using the updated state.
