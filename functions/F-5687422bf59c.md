# F-5687422bf59c

## Purpose

The supplied static representation describes a stateful, call-heavy operation that writes words and bytes to computed addresses, extracts bit fields from 32-bit values, and eventually enters an unconditional loop.

No application-level purpose is established. In particular, the evidence does not establish that this is a decoder, allocator, serializer, device driver, or ordinary callable routine. The representation reports invalid instruction data and discarded control-flow regions. Consequently, this contract distinguishes behavior expressed by that representation from behavior independently established for an executable.

The principal expressed behavior is:

- Capture a 32-bit value from an implicit input address.
- Make an ordered sequence of unresolved calls and computed-address writes.
- Use selected call results as both address components and stored values.
- Perform several byte-indirected stores.
- Enter a loop with no represented exit or normal return.

## Behavior

### 1. Initial store, capture, and calls

The first explicit memory operation writes the implicit 32-bit value to the first implicit base plus `0x14`.

The next explicit memory operation reads a 32-bit word from the second implicit base plus `0x14`. Call this captured word **W**. The ordering matters: if the two locations overlap, the read can observe the preceding write.

An unresolved no-argument call follows. Its target depends on the entry control value.

The operation then executes two producer/consumer pairs:

1. A no-argument call produces a 32-bit value.
2. The following call receives that value as its one explicit argument.

After these pairs, three no-argument calls precede another no-argument call whose result is used as an integer scale source.

The initial 32-bit store is then repeated. It uses the same represented base and stored value, rather than a new memory read of either. A dependency receives four times the scale-source result.

### 4. Byte-indirected writes

Define the unsigned index:

**Q = ((4 × J) AND `0x7fffffff`) >> 7**.

The byte phase obtains a new unsigned 32-bit result, **U**, and computes four times that result.

It then performs the following operations in order:

1. Read one byte at `Q + 1`.
2. Zero-extend that byte to an address component.
3. Store the low eight bits of `4 × U` at that component plus `0x11`.

This is a byte-valued address indirection, not a pointer-width load. The resulting store address is between `0x11` and `0x110`, inclusive.

A dependency receives three identical arguments, each equal to `4 × U`. Further producer/consumer and no-argument calls follow.

The operation rereads the byte at `Q + 1` and stores the low eight bits of:

**(U AND `0x3fffffff`) >> 20**

at the newly selected address plus `0x11`.

The second byte read must not be replaced by reuse of the first. Intervening calls or earlier aliasing stores may have changed its value.

After more calls, another unsigned result, **V**, is obtained. The operation:

1. Stores the low eight bits of `4 × V` at `(W >> 31) + 0x1c`.
2. Rereads the byte at `Q + 1`.
3. Stores zero at that byte value plus `0x11`.

A dependency then receives `W >> 31`. After another call, a dependency receives:

**(V AND `0x3fffffff`) >> 6**.

Following further calls, the byte at `Q + 1` is read again and used for another zero store at the byte-selected address plus `0x11`.

Thus, the direct store based on **W** targets only `0x1c` or `0x1d`. That location can overlap the byte-selected store range.

### 5. Transition to the unconditional loop

A later call result is reduced to:

**M = (result AND `0x3fffffff`) >> 25**.

This initial **M** is between 0 and 31.

Define a second byte-read address:

**Z = (4 × V) × `0x400` + 1**.

Before loop entry, the operation:

1. Reads one byte at **Z**.
2. Stores zero at that byte value plus `0x11`.
3. Calls a dependency with `M << 1`.
4. Calls a no-argument dependency to obtain an initial carried value.

Each loop iteration then:

1. Calls a dependency with the carried value and `M >> 8`.
2. Executes four no-argument calls, the last supplying an intermediate result.
3. Reads a byte at **Z** and stores zero at that byte value plus `0x11`.
4. Calls a dependency with four times the intermediate result.
5. Executes four no-argument calls, the last supplying the next result.
6. Sets the next carried value to that result shifted left by 2.
7. Sets the next **M** to that result shifted left by 26.
8. Repeats without a represented exit condition.

The first loop iteration supplies zero as its second argument because the initial **M** is at most 31.

Under 32-bit truncating shift semantics, later iterations supply `(next result AND 0x3f) << 18` as that second argument. The initial 0–31 bound does not apply after the first iteration.

The initial loop-head call target and the target retained for subsequent iterations are represented by different call sites. Their semantic equivalence is not established.

## Acceptance examples

These examples are conditional static expectations, not executed tests. They assume valid accesses, returning dependencies, and the stated arithmetic semantics.

1. **Initial aliasing:** If the two implicit bases are equal, the initial read captures the value just written at offset `0x14`.

2. **Captured-word extraction:** If **W** is `0x89abcdef`, then **H₁₆** is `0x89ab`, `W >> 24` is `0x89`, and `W >> 31` is 1. The direct byte store based on **W** targets `0x1d`.

3. **Third argument:** If the original third argument is `0xffffffff`, its four-argument-call contribution is `0x7ff`. Values below `0x00200000` contribute zero.

4. **No implicit byte mask:** With **W** equal to `0x12345678`, **P** is `0x0091a2b0`. The expression uses all 24 bits surviving the right shift, not merely one byte.

5. **Fresh byte selection:** If successive reads at `Q + 1` return 3 and 9, their corresponding stores target `0x14` and `0x1a`. Reusing the first destination would violate the represented behavior.

6. **Byte truncation:** If **U** is `0x12345678`, the first byte-indirected store writes `0xe0`. The later store based on `(U AND 0x3fffffff) >> 20` writes `0x23`.

7. **Loop transition:** The first loop-head second argument is zero. If a later loop result is 3, 32-bit shift semantics produce a carried value of 12 and a next loop-head second argument of `0x000c0000`.

8. **No normal completion:** If calls keep returning and accesses remain valid, observing a normal return after any finite number of loop iterations would contradict the represented terminal control flow.
