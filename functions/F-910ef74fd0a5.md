## Behavior

The object pointer is passed to the selected operation. No other explicit argument is shown for this call. No result from the call is consumed by F-910ef74fd0a5.

The dispatch reference and target are selected before entering the indirect operation. If that operation changes the object’s leading word or changes the dispatch entry, this function does not perform another dispatch lookup afterward.

### Byte update

After the indirect operation returns, the function writes a single byte containing 255, equivalently 0xFF, at object byte offset 32.

The offset follows from advancing eight elements in the represented 32-bit integer layout: eight times four bytes equals 32 bytes. The store itself is one byte wide; it is not a 32-bit store.

Consequences of that width include:

- The explicit store does not overwrite the three following bytes.
- No prior read of the destination byte is represented.
- Its previous value does not affect the value written.
- If the indirect operation changed that byte, this store replaces its value with 255.
- If the destination byte already contains 255, the store is still part of the represented execution.

The write uses the original object pointer. It does not derive a new destination from the object’s potentially modified dispatch reference.

The dependency’s effects must not be assumed harmless. If it releases the storage, invalidates access to it, or otherwise makes this location unwritable, the subsequent store cannot be assumed valid. F-910ef74fd0a5 supplies no visible recovery mechanism for that case.
