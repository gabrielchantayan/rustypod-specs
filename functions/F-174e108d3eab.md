## Behavior

### Indirect invocation and transformation phase

The initial indirect invocation receives the first input, the second input, and the first input again, in that order. Its target is derived from incoming control-link state with an added displacement of 0xffe. The represented primary result is shifted left by eight positions and passed to the next invocation.

A long invocation sequence follows, with no visible conditional branch selecting among its calls. Calls consume combinations of:

- Shifted primary results.
- Low and high words of represented 64-bit results.
- Explicit zero arguments.
- Retained values from earlier calls.
- Secondary call-result state whose complete ABI meaning is unresolved.

A displayed invocation without explicit arguments does not establish that it consumes no machine state. An ignored visible result does not establish an absence of side effects. Retaining a value across calls does not imply that those calls preserve globals or referenced memory.

Transformations include masks retaining low-bit fields of several widths, including 24, 22, 20, 19, 18, 17, 14, 13, 12, and 11 bits. Unsigned right shifts discard bits without sign extension.

Some right shifts apply to an entire represented 64-bit result. Shifts by 34, 36, and 44 positions, followed by narrowing to 32 bits, select the high word shifted right by 2, 4, and 12 positions respectively. They do not select shifted low-word bits.

### Arithmetic model

Many left shifts and address calculations pass through signed 32-bit intermediates. Portable signed arithmetic does not supply a reliable full-domain interpretation for all represented operations.

**[INFERENCE — conditional bit-vector model]:** Where this contract derives numerical ranges or address relationships, it assumes 32-bit results retain their low 32 bits, with arithmetic evaluated modulo 2³². This is an analytical interpretation, not runtime verification.

Truncation at intermediate widths matters. Under this model, shifting a 32-bit value left by 28 twice yields zero. It is not equivalent to retaining an unlimited-precision intermediate.

The same qualification applies to scaling by 2, 4, 8, 256, and 2²⁵, and to subtraction by 150 before further scaling.

### Cleared-word relationship

**Under the conditional 32-bit bit-vector model and ordinary, stable memory, the read of encoded-base offset 0x14 yields zero.** The intervening accesses do not supply an aliasing counterexample.

Between its clear and its read, the represented stores are only:

- A zero word at small-base offset 0x14.
- The captured byte, promoted to a word, at encoded-base offset 0x34.

The two encoded-base word destinations are separated by 0x20 bytes. Their four-byte ranges are disjoint under modular 32-bit address arithmetic. The captured-byte word therefore cannot overlap the cleared word, even if its value is nonzero.

The small-base store writes zero. Any overlap it could have with the cleared word cannot introduce nonzero contents. More specifically, under the derived base constraints, both word starts are aligned, and their coincidence requires both bases to be zero.

There is no intervening represented dependency invocation in this interval. Earlier dependency effects can determine prior contents, but do not themselves invalidate propagation of the subsequent clear through this interval.

Consequently, for ordinary, stable memory, both byte stores at small-base offset 0x15 write zero. The read value is also used later as a base for a word store at offset 0x54; under the same assumptions, that destination is absolute address 0x54 and receives the shifted word.

This conclusion does **not** establish stable readback for device-backed storage, concurrent modification, read-triggered behavior, or physically aliased mappings not captured by numerical address equality. Those environmental possibilities remain documented_only. They are separate from aliasing among the represented stores.

## Acceptance examples

These are conditional review criteria, not executed tests.

### Input forwarding

Given distinct inputs 0x11223344 and 0xaabbccdd and a resolvable initial target, the initial invocation presents 0x11223344, 0xaabbccdd, and 0x11223344 in argument positions one through three.

### Width conversion

Given a value of 0x123456ab, an 8-bit store writes 0xab. Given an unsigned byte read of 0xff, promotion for a 32-bit store produces 255, not −1.

### Cleared-word propagation with a nonzero capture

Assume the conditional bit-vector model, valid ordinary memory, no external modification, and a captured byte of 0xff at encoded-base offset 0x05.

The later word store at encoded-base offset 0x34 writes 255. It cannot overlap the word at encoded-base offset 0x14. The intervening small-base word store writes only zero. The read at encoded-base offset 0x14 therefore yields zero, and both following byte stores at small-base offset 0x15 write zero.

Rejecting this result solely because the represented destinations might alias is incorrect.

### Coincident zero destinations

If encoded base and small base are both zero, the two clears at offset 0x14 address the same word. That coincidence preserves zero; it does not introduce a nonzero value. The captured-byte word destination remains 0x34 and is disjoint.

### Externally changing memory

If the cleared-word location has device-specific readback behavior or another agent modifies it before the read, zero readback is not guaranteed by this contract. This exception requires an environmental premise; the visible intervening stores do not establish it.

### Paired-result shift

Given a represented 64-bit result with high word 0x00000100, shifting the whole result right by 36 and narrowing yields 0x00000010, regardless of its low word.

### Intermediate truncation

Under the conditional 32-bit model, two successive left shifts by 28 produce zero. Unlimited-precision intermediate arithmetic is not equivalent.

### Repetition and incomplete execution

Where write events are observable, repeated stores remain separate effects. Matching only the final memory image is insufficient. If a dependency does not return, later effects need not occur, and no rollback or successful completion status may be inferred.
