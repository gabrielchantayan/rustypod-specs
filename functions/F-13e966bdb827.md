## Behavior

### Input classification

For classification, each input’s **magnitude pattern** is its low 31 bits, with the high bit discarded.

The arithmetic and signed tests establish this partition:

| Magnitude patterns | Selected behavior |
|---|---|
| Both less than `0x7F800000` | Return the original first word |
| At least one equals `0x7F800000`, and neither exceeds it | Construct the comparison-related result |
| At least one exceeds `0x7F800000` | Enter configuration-controlled dispatch |

The partition follows from the integer operations, including their 32-bit truncation. It does not depend on interpreting the inputs as floating-point values.

Consequences under a binary32 interpretation:

- Pairs containing only finite encodings return the first word unchanged, including signed zeros and subnormals.
- An infinity encoding reaches the comparison-related path unless either input has a NaN magnitude pattern.
- Either sign of any NaN magnitude pattern reaches dispatch.
- Quiet and signaling NaN patterns are not distinguished by this classification.

A finite pair is not numerically compared. Returning the first word does not mean that it is a minimum, maximum, or preferred numerical operand.

No shared configuration or payload read is visible before dispatch classification succeeds.

This path requires both magnitude patterns to be at most `0x7F800000`, with at least one equal to that threshold.

### Initial dispatch selection

All dispatch forms target the masked incoming continuation address. The unresolved dependency is designated **F-unknown**.

Each selected invocation ends the visible local selection process. If F-unknown returns normally, its 32-bit result is returned unchanged.

The first dispatch-stage configuration read tests mask `0x000D0000`.

- If any masked bit is set, enter the common dispatch stage with the original first and second words.

|---|---|

| `0x8` | Paired-argument dispatch |

| Any other value | Invoke F-unknown with no explicit arguments shown |

### Single-argument payload dispatch

For low nibble `0xA`, the single-argument payload is read before a subsequent configuration reference tests bit `0x40`.

- If bit `0x40` is clear, the argument is the loaded payload.
- If bit `0x40` is set, the argument is `0x80000000`.

The payload read occurs even when its value is discarded in favor of the constant.

### Paired-argument dispatch

For low nibble `0x8`, a subsequent configuration reference tests bit `0x40`.

If that bit is set, F-unknown receives two zero arguments. Neither paired-call payload is read on this path.

If that bit is clear:

- The paired-call first payload is read.
- A later configuration reference tests bit `0x10`.
- With bit `0x10` clear, the arguments are the loaded first payload and the original second word.
- With bit `0x10` set, the replacement second payload is read; the arguments are zero and that replacement payload.

The first payload is read even when bit `0x10` causes its value to be discarded.

### Common dispatch stage

This stage is reached either through the initial mask gate or through low nibble `0x9`. In the latter case, the current first word is `8`; otherwise it remains the original first word. The second word is unchanged.

A configuration reference tests bit `0x00100000`.

#### Bit `0x00100000` clear

F-unknown receives one argument: zero.

#### Bit `0x00100000` set

A further configuration reference tests mask `0x00070000`.

If all masked bits are clear, F-unknown receives three arguments, in order:

1. `0x30000000`.
2. The original second word.
3. `0x30000000`, additionally containing bit 27 exactly when incoming status bit 0 is set.

The third argument is therefore either `0x30000000` or `0x38000000`. No other status bit affects it.

If any masked bit is set, a further configuration read supplies the value used to construct the second argument. F-unknown receives:

1. The current first word.
2. A 32-bit transformed configuration value.

The transformation order is significant: the configuration value is shifted left by 15 with 32-bit truncation; **that shifted word is complemented**; the complemented word is then shifted left by one with 32-bit truncation. The complement is not applied to the configuration before the first shift.

The resulting second argument has this exact layout:

| Argument bits | Value |
|---|---|
| 31–16 | Complement of the configuration read’s low 16 bits |
| 15–1 | All ones |
| 0 | Zero |

Equivalently, its upper halfword is the complemented low configuration halfword, and its lower halfword is always `0xFFFE`. Configuration bits 31–16 do not affect this argument.

For a construction read of `0x00110000`, the second argument is `0xFFFFFFFE`, not `0xFFFF0000`.
