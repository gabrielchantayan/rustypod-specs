# F-a4941d24d0bd

## Purpose

F-a4941d24d0bd conditionally acquires a working result, forwards associated values to caller-supplied destinations, optionally constructs a derived result, and returns a 32-bit status.

The explicit return values are:

- **1:** acquisition succeeded, the first mode-dependent operation returned nonzero, and a subsequent check receiving argument 3 returned zero.
- **0:** the initial gate rejected, acquisition failed, the first mode-dependent operation returned zero, or the subsequent argument-3 check returned nonzero.

Return 0 does not imply unchanged destinations. After successful acquisition, operations targeting arguments 3, 4, 5, and 7 occur before the final status decision. A further operation targeting argument 3 may also occur.

Return 1 does not guarantee a transfer toward argument 6. That operation requires additional nested conditions.

“Acquisition,” “destination,” “mutation,” and “cleanup” describe observed usage, not established dependency semantics.

## Side effects

The function directly reads configuration fields, context fields, and the word at argument 3 offset 4. Destination changes are delegated to dependencies; no direct store to caller destination memory is visible.

Configuration observation has two distinct properties:

- The shared pointer is first saved and then separately reread for the initial offset-12 access, with no intervening dependency call.
- Later fields are read through the saved first pointer when their branches are reached. The shared pointer is not reloaded for those accesses.

The two entry observations need not identify the same object. Conversely, even if they do, later dependencies may alter its contents. No immutability, synchronization, or lifetime protection is established.

Observable ordering includes:

- All four operations targeting arguments 3, 4, 5, and 7 precede the final success decision.
- The direct argument-3 field read follows those operations.
- The possible argument-3 mutation precedes its explicit F-6d70e45e29c9 check.
- Argument 6 is targeted only in the deepest optional branch.
- Cleanup follows destination activity and does not visibly undo it.

Aliasing among destinations, configuration storage, or dependency-managed objects can affect later observations. No supported-aliasing guarantee is established.

All described returns and cleanup sequences assume reached dependencies return normally. No exception or nonlocal-exit recovery is established.

## Acceptance examples

These are conditional static scenarios, not executed tests. Each assumes valid reached storage and normal dependency returns.

1. **Distinct entry configuration observations.** If the first shared-pointer observation identifies object A and the second identifies object B, initial construction receives B’s offset-12 field. Later comparison and conditional configuration reads use A. No dependency call occurs between the pointer observations.

2. **Gate rejection.** A zero gate result produces initial construction, initial-temporary cleanup, and return 0. Acquisition setup and destination operations are absent.

3. **Acquisition failure.** A nonzero gate followed by zero from F-086cb6e3869b produces common cleanup and return 0, without destination-directed operations.

4. **Nonzero acquisition option.** Argument 2 equal to −1 selects option 4, just as argument 2 equal to 1 does. Zero selects option 0.

5. **Independent context values.** A first upper half of 19 and second upper half of 19 select mode 3 and a true flag. A first upper half of 11 and second upper half of 7 select mode 1 and a false flag. Lower halves do not affect either result.

6. **Destination activity before failure.** Successful acquisition followed by zero from F-5aee41788c02 still reaches all four destination operations and the conditional mutation stage. The explicit argument-3 check is skipped; cleanup precedes return 0.

7. **Exact mutation guard.** With zero from F-634a31ef9eb5, a result of 2 from F-c453b9ccc22e causes the mutation call; a result of 1 suppresses it. A nonzero comparison result skips that guard call entirely.

8. **Success without argument-6 transfer.** A nonzero first mode-dependent result and zero explicit argument-3 check establish the success branch. If F-5890564a944d returns zero, or its later no-explicit-argument check returns nonzero, return 1 occurs without F-f5c1d5368335.

9. **Derived construction after mutation call.** If optional construction is reached and the mutation call occurred, its final construction input is the then-current offset-24 field through the saved first configuration pointer. The alternative F-44362605ab79 call is skipped.

10. **Derived construction without mutation call.** If optional construction is reached without that call, F-a0e79973fd13 is called a second time, followed by F-44362605ab79. Construction, argument-6 transfer, optional-temporary cleanup, and common cleanup follow in that order.
