# F-4f3684cbc02d

## Purpose

F-4f3684cbc02d selects a configuration path using an unsigned 32-bit selector, records the selector’s low byte in shared state, updates a word-addressed region, and completes accepted configurations with a zero write followed by a read-modify-write that sets bit 0.

Selectors 0 and 1 execute the same path. Selector 2 executes a different path. Every other selector returns `0xFFFFFFFF`, but rejection occurs **after** shared-state mutation and configuration-seed reads. Rejection is not transactional or side-effect-free.

The function reads the shared state-pointer location twice. The first value supplies the base for later condition-byte reads; the second supplies the base for the selector-byte write. These bases need not be equal.

Likewise, the configuration seed is not sampled once. The represented behavior contains seven seed-global reads. Treating the derived values as transformations of one common seed is valid only under an explicit stability assumption.

“Configuration” and “register-like region” describe inferred intent. The established evidence consists of memory accesses, arithmetic, branching, and return values. It does not establish a particular device or successful hardware activation.

### Shared storage and addressing roles

The function uses three shared storage locations:

- A location supplying the base of the word-accessed region.
- A location supplying a state-region address, read twice.
- A location supplying a 32-bit configuration seed, read seven times.

This contract names the captured address values as follows:

| Name | Meaning |
|---|---|
| **R** | Word-region base obtained from the first shared-pointer read. |
| **Condition base** | Value obtained from the first read of the shared state-pointer location. Retained for later condition-byte reads. |
| **Record base** | Value obtained from the second read of that same state-pointer location. Used to address the selector-byte store. |

The two state-pointer reads are distinct even when they return equal values. Subsequent condition accesses do not reload the state-pointer location.

Relevant byte offsets are:

| Address | Width | Role |
|---|---:|---|
| Condition base + `0x02` | 8 bits | First condition input, used only for selectors 0 and 1. |
| Condition base + `0x03` | 8 bits | Second condition input, read only when the first equals 1. |

## Behavior

### Access-order interpretation

The following describes the accesses represented by the supplied source. It preserves repeated reads and writes rather than replacing them with an entry-time snapshot or a final-state formula.

Whether each represented access becomes a distinct externally observable machine or bus transaction is **documented_only**. Volatile qualifications, compilation behavior, and device-memory semantics are not established.

Except where the final seed expression leaves operand order unspecified, the sequence below gives the represented order. Each described control-word update uses a fresh read at that step.

### Common prefix

Every selector follows this prefix before acceptance or rejection:

1. Read the shared word-region pointer and retain its value as R.
2. Read the shared state-pointer location and retain its value as the condition base.
3. Read the shared state-pointer location again, obtaining the record base.
4. Store the selector’s low eight bits at record base + `0x04`.
5. Read the 32-bit control word at R + `0x08`, retain only bits selected by `0x0000003F`, and write the masked result back.
6. Perform the seed reads and derive the six configuration values described below.
7. Select a path using the full unsigned 32-bit selector.

The initial control update preserves bits 0 through 5 of its sampled value and clears all higher bits.

The record store precedes the control-word read. The control-word write precedes the seed reads. Consequently, aliasing or access-triggered effects can affect later observations. A model that snapshots all shared inputs at entry is not equivalent.

### Seed reads and derived values

Five successive seed-global reads supply five separate derived values:

| Read position | Derived value | Definition |
|---:|---|---|
| 1 | Base | The 32-bit value returned by this read. |
| 2 | Plus-109 | This read’s value plus `0x6D`. |
| 3 | Plus-35 | This read’s value plus `0x23`. |
| 4 | Plus-8 | This read’s value plus `0x08`. |
| 5 | Plus-39 | This read’s value plus `0x27`. |

Each addition produces a 32-bit result, wrapping modulo \(2^{32}\). Overflow does not produce a reported error.

After those five reads, the Folded expression references the seed-global location twice more:

- One read supplies an unshifted 32-bit operand.
- Another read supplies an operand interpreted as signed 32-bit and shifted right by seven positions.
- Folded is the bitwise OR of the unshifted operand and the shifted operand’s resulting bit pattern.

The supplied expression does **not** establish the relative evaluation order of these last two reads. Neither operand may be identified as necessarily receiving the earlier observation. The two reads also need not return equal values.

Thus there are seven represented seed reads, producing six retained values. These reads occur even for a selector that will subsequently be rejected.

If all seven reads return a stable common value K, the familiar simplification is valid: Base is K; the four additions use K; and Folded combines K with a signed-right-shifted interpretation of K. That simplification is conditional, not the general access model.

Sign propagation for negative signed operands is not independently established. For a shifted operand below `0x80000000`, this uncertainty does not affect the result.

### Selectors 0 and 1

Selectors 0 and 1 perform identical operations:

- Read the byte at condition base + `0x02`.
- Only if that byte equals exactly 1, read condition base + `0x03`.
- Write `0x00000200` to R + `0x34` if both bytes equal exactly 1; otherwise write zero.

A byte value other than 1 fails the comparison, including other nonzero values. The second condition byte is not read when the first fails.

The function then performs four successive read/write updates at R + `0x08`:

| Update | Value written from that update’s fresh read |
|---:|---|
| 1 | The value read, unchanged. |
| 2 | The value read, unchanged. |
| 3 | The value read OR `0x00000200`. |
| 4 | The value read OR `0x00001000`. |

It next reads the status word at R + `0x03E00004` once. The selected values are written in ascending destination order:

| Sampled status bit `0x00000100` | R + `0x28` | R + `0x2C` | R + `0x30` |
|---|---|---|---|
| Clear | Folded | Plus-39 | Plus-8 |
| Set | Plus-35 | Plus-109 | Base |

Other bits of that status sample do not affect the choice. The successful-path completion sequence follows.

### Selector 2

Selector 2 does not explicitly read either condition byte. It writes zero to R + `0x34`, then performs four successive updates at R + `0x08`:

| Update | Value written from that update’s fresh read |
|---:|---|
| 1 | The value read OR `0x00000040`. |
| 2 | The value read, unchanged. |
| 3 | The value read OR `0x00040000`. |
| 4 | The value read OR `0x00200000`. |

It then reads the status word once and writes the selected triplet in ascending destination order:

| Sampled status bit `0x00000100` | R + `0x1C` | R + `0x20` | R + `0x24` |
|---|---|---|---|
| Clear | Plus-39 | Plus-8 | Folded |
| Set | Plus-109 | Base | Plus-35 |

The successful-path completion sequence follows.

### Successful-path completion

All accepted selectors finish with this sequence:

1. Write the 32-bit value zero to R + `0x00`.
2. Read that location.
3. Write the read value OR `0x00000001` back to that location.
4. Return zero.

For stable ordinary memory without interference, the final value is 1. In the general access model, the second write depends on the actual readback; it is not necessarily the constant 1.

### Rejected selectors

Any unsigned selector greater than 2 returns `0xFFFFFFFF` after the common prefix.

Such a call has already performed both state-pointer reads, the selector-byte store, the initial control-word mask, and all seven represented seed reads. It does not explicitly perform condition-byte reads, access the status word, write R + `0x34`, write either triplet, or execute successful-path completion.

No rollback occurs. A selector such as `0x00000102` is rejected despite recording the byte `0x02`.

## Side effects

The function mutates shared memory before validating the selector.

Under stable, non-aliased ordinary-memory conditions with no external modification, let C be the control word immediately before its initial mask:

| Selector | Final control word |
|---|---|
| 0 or 1 | `(C AND 0x0000003F) OR 0x00001200` |
| 2 | `(C AND 0x0000003F) OR 0x00240040` |
| Rejected | `C AND 0x0000003F` |

These formulas do not replace the intermediate accesses when reads or writes have externally significant effects.

The unselected triplet receives no explicit writes. This is not a general guarantee that its contents remain unchanged under aliasing, device side effects, or concurrent modification.

No explicit synchronization, polling, waiting, retry, timeout, or error recovery appears. A zero result establishes traversal of the represented successful path, not device readiness or acceptance.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. **No runtime tests have been performed.** Unless a case states otherwise, assume accessible, distinct ordinary-memory locations, no interference, stable pointer and seed storage, and reads returning the most recently written value.

### Selector 1 with matching condition bytes

Given a stable seed of `0x00000100`, initial control word `0xFFFFFFFF`, both condition bytes equal to 1, and the status bit clear:

- Record base + `0x04` receives `0x01`.
- R + `0x34` receives `0x00000200`.
- The final control word is `0x0000123F`.
- R + `0x28`, `0x2C`, and `0x30` receive `0x00000102`, `0x00000127`, and `0x00000108`.
- Completion writes zero, then 1, to R + `0x00`.
- The return value is zero.

### Different state-pointer observations

Suppose the first state-pointer read returns address A and the second returns distinct address B. With selector 0:

- The selector byte is stored at B + `0x04`.
- The first condition byte is read from A + `0x02`.
- If that byte equals 1, the second condition byte is read from A + `0x03`.
- Bytes at B + `0x02` and B + `0x03` do not supply these condition inputs.

Later changes to the shared state-pointer location do not redirect the saved condition base.

### Nonmatching first condition byte

For selector 0, if condition base + `0x02` contains 2:

- Condition base + `0x03` is not read.
- R + `0x34` receives zero.
- The remaining selector-0 configuration and completion still occur.

### Distinct seed observations

Suppose the first five seed reads return, respectively, `0x100`, `0x200`, `0x300`, `0x400`, and `0x500`. Suppose the Folded expression’s unshifted operand receives `0x600` and its signed-shift operand receives `0x700`, without assuming their evaluation order.

The retained values are:

- Base: `0x100`.
- Plus-109: `0x26D`.
- Plus-35: `0x323`.
- Plus-8: `0x408`.
- Plus-39: `0x527`.
- Folded: `0x60E`.

For selector 0 or 1 with the status bit clear, the triplet is `0x60E`, `0x527`, `0x408`. This result cannot be modeled by one common seed sample.

### Selector 2 with the status bit set

Given a stable seed of `0x100`, initial control word zero, and the status bit set:

- Neither condition byte is read.
- R + `0x34` receives zero.
- The final control word is `0x00240040`.
- R + `0x1C`, `0x20`, and `0x24` receive `0x16D`, `0x100`, and `0x123`.
- Completion runs and the result is zero.

### Rejected selector and arithmetic boundaries

For selector `0x00000102` with initial control word `0xFFFFFFFF`, the recorded byte is `0x02`, the masked control word is `0x3F`, all seed reads still occur, and the result is `0xFFFFFFFF`. Selector-2 configuration does not run.

With a stable seed of `0xFFFFFFF0`, Plus-109 is `0x0000005D` and Plus-35 is `0x00000013`. Accepted paths selecting those values write the wrapped results without overflow rejection.

### Nonzero completion readback

If the completion read returns `0x00000080` despite the preceding zero write, the following write is `0x00000081`, not 1.
