# F-975a185a9ca9

## Purpose

F-975a185a9ca9 prepares fields and embedded structures in a caller-supplied object, replaces three stored references with embedded addresses, derives a 32-bit selector, and conditionally publishes an embedded node into a selected table entry.

Preparation and reference replacement occur even when publication is subsequently skipped. The function provides no explicit status result, validation, or rollback.

The interpretation as bucketed linked-list insertion is **inferred intent**. The established behavior is the ordered calls, reads, comparisons, arithmetic, and writes described below. Object types, ownership rules, and dependency semantics are not established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### 4. Selector derivation and later dereference

The function reads unsigned 32-bit values from B + `0x500`, B + `0x518`, and B + `0x554`, in that order.

Their unsigned maximum is M. The function writes \((M + 1) \bmod 2^{32}\) to B + `0x530`.

The earlier zero writes do not guarantee that the eventual selector inputs at `0x500` and `0x518` are zero: intervening dependencies may modify them. This function does not directly initialize `0x554`.

Next, the function reads four bytes **at G1**, obtaining T. This is a dereference of the originally captured pointer, not another read of S and not necessarily a dereference of G2.

Only after obtaining T does the function reread B + `0x530` and subtract one with a 32-bit result, obtaining I.

If the selector field remains unchanged between its write and reread, I equals M, including when the increment wraps. Without that stability assumption, the gate and table offset use the value reconstructed from the reread, not necessarily M.

### 5. Insertion gate

The first gate interprets I as signed 32-bit:

- If bit 31 is set, insertion is skipped without a direct read of the flag byte.
- Otherwise, the function reads the byte at B + `0x53C` and tests bit 0.
  - A set bit skips insertion.
  - A clear bit permits insertion.

With a stable selector field, unsigned maxima from `0x80000000` through `0xFFFFFFFF` therefore suppress insertion. M = `0x7FFFFFFF` passes the signed gate.

Both early-return paths occur after all preparation calls, conditional calls, reference replacement, selector storage, and the read of T at G1. Those effects are not undone.

### 6. Ordered insertion accesses

When insertion is permitted, the accesses occur in this order:

1. Write four-byte zero to B + `0x534`.
2. Read four bytes at E.
3. Write the value just read to B + `0x538`.
4. Write N to E.
5. Reread the byte at B + `0x53C`, set bit 0, and write the resulting byte back.
6. Read four bytes at B + `0x538` for a nonzero test. Call this observation **Q**.
7. If Q is zero, finish without a further read of `0x538` or final destination write.
8. If Q is nonzero, read four bytes at B + `0x538` again. Call this observation **D**.
9. Write N to the four-byte location at D + `0x0C`.

The final branch tests Q, but the final write address is derived from D. D is not checked again. A nonzero Q followed by a zero D therefore produces a represented write to address `0x0000000C`, subject to address validity.

Under stable, valid, non-aliasing storage, Q and D both equal the table-entry value saved earlier. In that restricted case, a nonzero prior head receives N at offset `0x0C`. Without those assumptions, neither the destination-base observation nor the final destination is guaranteed to identify that prior head.

The flag update preserves bits other than bit 0 from its **update-time reread**, not necessarily from the earlier gate read.

Publication to E precedes the flag update and final conditional destination write. No synchronization or atomic multi-field transaction is visible. There is no capacity check, duplicate-node search, cycle check, or validation of the stored pointer values.

## Side effects

Direct effects include:

- Copying and clearing object fields.
- Replacing three references with embedded addresses.
- Writing the selector field even when insertion is skipped.
- On insertion, clearing `0x534`, saving a table-entry value at `0x538`, publishing N, and setting flag bit 0.
- When Q is nonzero, writing N through the address derived from the separate D observation.

Aliasing may cause any direct write to influence later reads. The saved table-entry value, Q, and D are not unconditionally equal.

The function directly reads S twice but does not directly write it. Dependency side effects may change S, its pointed-to storage, or other state. A later change to S does not replace the already captured G1.

No direct allocation or deallocation is visible. Replacing references with embedded addresses does not establish ownership transfer, and conditional dependency calls do not establish release of old references. Whether dependencies retain arguments or allocate, release, or destroy resources is unknown.

There is no explicit error result or recovery path. A dependency that does not return, or an invalid memory access, can prevent completion after earlier effects have already occurred. Partially published links are possible if execution stops during insertion.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid non-aliasing storage, normally returning dependencies, and stability between relevant reads. Selector inputs mean the values observed during selector derivation.

1. **Empty selected entry.**  
   Inputs `2`, `7`, and `5` produce `8` at `0x530` and I = `7`. With flag bit 0 clear and E containing zero, insertion clears `0x534`, stores zero at `0x538`, publishes N, and sets flag bit 0. Q is zero, so there is no D read or final destination write.

2. **Stable existing head.**  
   With an eligible I, clear flag bit 0, and a nonzero prior head H, the function saves H at `0x538` and publishes N. After the flag update, the condition read obtains Q = H and the separate destination-base read obtains D = H. The final write stores N at H + `0x0C`.

3. **Different late observations.**  
   If Q is nonzero but the next read obtains a different D, the final write targets D + `0x0C`, not Q + `0x0C`. If D is zero, the represented destination is `0x0000000C`; successful execution requires writable storage there. This does not establish supported concurrent-mutation behavior.

4. **Flag suppresses insertion only.**  
   With eligible I and gate-time flag byte `0xA5`, insertion is skipped. Preparation, reference replacement, selector storage, and the read at G1 still occur. The insertion stage makes no writes.

5. **Flag preservation uses the reread.**  
   If the gate permits insertion and the flag-update reread obtains `0xA4`, the written byte is `0xA5`. Other bits are preserved from this reread.

6. **Signed boundary and wraparound.**  
   M = `0x80000000` produces `0x80000001` at `0x530` and is rejected before the flag read. M = `0xFFFFFFFF` produces zero, but decrement reconstructs `0xFFFFFFFF`, so insertion is still rejected. M = `0x7FFFFFFF` passes the signed gate despite producing `0x80000000` at `0x530`.

7. **Independent global-pointer reads.**  
   Suppose the first read of S obtains G1 = P, while the second obtains G2 = R. If the four-byte value at R is X, F-03b9616af95f receives X as its first argument. Later, the function reads T at P. It does not use R for that later read merely because R supplied the dependency argument.

8. **Changed contents or later global replacement.**  
   Even if G1 and G2 both equal P, the value passed to F-03b9616af95f and the later T may differ if storage at P changes. Conversely, changing S after G1 has been captured does not redirect the later read away from P. P must remain readable at that later point.
