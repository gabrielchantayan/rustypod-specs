# F-481e9fb33804

## Purpose

F-481e9fb33804 conditionally scans a sequence of indexed results associated with an input object. It returns normally when scanning is disabled, when the captured scan bound is nonpositive, or when every result examined contains a zero first word. The first result whose first word is nonzero triggers a call to F-289ec4311c64, followed—if that call returns—by a call to F-feee9156a257.

The supplied static representation marks the final call as nonreturning. It does not establish whether that dependency terminates execution, transfers control elsewhere, or performs another nonlocal action.

The apparent intent is to detect a nonzero condition among indexed entries and enter an exceptional path. That interpretation is inferred. The meanings of the enabling field, the indexed results, and the two direct dependencies are not established.

## Interface

### Input and result

The function accepts one argument: a pointer to storage represented as an array of integer-width words. That storage is also used as an object-like argument to an indirect call.

The function has no explicit return value. On its ordinary return paths, it provides no status code or result pointer.

No null check, storage-length check, dispatch validation, or returned-pointer validation is present in the supplied representation.

### Relevant input layout

The function directly uses three locations relative to the input pointer:

| Location | Interpretation in this function |
|---|---|
| Integer-word offset 0 | A value used as the base address of a dispatch structure. |
| Integer-word offset 1 | A signed scan bound, captured once when scanning is enabled. |
| Integer-word offset 4 | A value converted to a character-width quantity to determine whether scanning is enabled. |

The dispatch entry is obtained at byte offset 0x40, or 64 bytes, from the dispatch-structure base.

Under a conventional 32-bit interpretation of the supplied representation, the object fields above are at byte offsets 0, 4, and 16. The scan bound and inspected result word are then 32-bit integers. The byte-offset mapping depends on the represented integer width; the supplied material does not independently provide an ABI declaration.

The enabling check converts the integer value at word offset 4 to a character-width value. It does not compare the entire integer directly with zero. Under an 8-bit truncating character conversion, only the low eight bits determine whether scanning is enabled. This is a value-conversion rule, not an established claim that the function directly loads the lowest-addressed byte of that field.

### Indirect-call interface

For each examined index, the indirect dependency receives:

1. The original input pointer.
2. The current signed integer index, starting at zero.

Its returned value is treated as a pointer to an integer-width word. The function immediately reads that word and compares it with zero.

No opaque ID was supplied for this indirect dependency. Its identity is determined through the input object's dispatch structure and may differ between iterations.

## Behavior

### Disabled path

The first decision is whether the character-width conversion of the field at word offset 4 equals zero.

If it equals zero, the function returns immediately. On this path, it does not inspect the scan bound, resolve the indirect dependency, inspect any indexed result, or call either named direct dependency.

A nonzero full-width enabling field can therefore still select this path if its character-width conversion is zero. The exact conversion behavior depends on the target's character width and integer-conversion rules.

### Capturing the scan bound

If scanning is enabled, the function reads the signed integer at word offset 1 and retains that value as the scan bound for the invocation.

The bound is not reread by the surrounding scan logic. Changes to the object's bound field during a dependency call do not alter the captured bound used by subsequent comparisons.

The initial index is zero. Before any indirect call, the function compares the captured bound with the current index. If the bound is less than or equal to the index, the function returns normally.

Consequently, an enabled invocation with a zero or negative bound performs no indirect calls.

### Resolving and calling each indexed dependency

For each index admitted by the bound check, the function resolves the indirect target through the original input object:

1. It obtains the dispatch-structure base from the object's first integer-width word.
2. It obtains the callable entry at byte offset 64 from that base.
3. It invokes the entry with the original object pointer and the current index.
4. After a normal return, it reads the first integer-width word at the returned pointer.

The dispatch target is resolved again for each iteration. It is not captured once at the beginning of the scan. A dependency that changes the object's dispatch base or relevant dispatch entry can therefore affect later iterations, provided the subsequent accesses remain valid.

The supplied representation establishes the dependency chain between these accesses. It does not establish machine-instruction-level loading details or a complete language-level argument-evaluation order.

### Handling a zero result word

If the inspected word equals zero, the function increments the index by one and repeats the bound check.

Only the first word at the returned pointer is inspected. No size, length, tag, or additional field is checked. The pointer is not explicitly retained for a later iteration.

For a stable positive captured bound and normally returning dependencies whose inspected words are all zero, the function examines indices from zero through one less than the bound, in increasing order, then returns normally.

### Handling a nonzero result word

If the inspected word is nonzero, scanning stops immediately. Both positive and negative nonzero values select this path.

The function then calls F-289ec4311c64 with no explicit arguments in the supplied representation. If that call returns, the function calls F-feee9156a257, also with no explicit arguments.

There are no further indexed calls after the first nonzero result. The matching index and inspected value are not explicitly passed to either named dependency.

The final call is marked nonreturning in the supplied static material. No ordinary continuation after it is shown. A normal return from that dependency is therefore outside the established continuation of this function; behavior in that situation is documented_only.

If F-289ec4311c64 itself does not return, F-feee9156a257 is not reached. Nothing in the supplied material independently guarantees that the first dependency returns.

### Integer boundaries

The bound comparison is signed in the supplied representation. A negative bound is not reinterpreted as a large unsigned iteration count.

For an integer width with maximum signed value \(M\), the visible index progression does not require an increment beyond \(M\). An increment occurs only after an iteration whose index is less than the captured bound. Even when the bound equals \(M\), the last possible increment advances the index from \(M-1\) to \(M\), after which the next bound check returns.

This conclusion concerns the function's own index progression. It does not constrain arithmetic or side effects inside dependencies.

## Acceptance examples

These are conditional contract examples derived from the static representation. No runtime tests have been performed.

1. **Disabled invocation.**  
   If the enabling field converts to character-width zero, the function returns without reading the scan bound or invoking any dependency. Dispatch and result-storage preconditions are not exercised on this path.

2. **Enabled invocation with a negative bound.**  
   If the enabling conversion is nonzero and the captured bound is −1, the function returns without an indirect call. The signed comparison prevents treating −1 as a large count.

3. **One zero result.**  
   If the captured bound is 1 and the index-zero dependency returns a valid pointer to a zero word, the function calls that dependency once and returns normally. Neither named direct dependency is reached.

4. **All results zero.**  
   If the captured bound is 3 and all three inspected words are zero, the indexed calls occur at 0, 1, and 2, in that order. There is no call at index 3.

5. **Early nonzero result.**  
   If the captured bound is 4, index 0 yields zero, and index 1 yields a nonzero word, no indexed calls occur at 2 or 3. F-289ec4311c64 is called next. F-feee9156a257 follows only if the first named dependency returns.

6. **Negative result word.**  
   A valid inspected word of −1 selects the same nonzero path as a word of 1. The function distinguishes zero from nonzero, not positive from nonpositive.

7. **Bound mutation during scanning.**  
   Suppose the captured bound is 3 and the first indirect call changes the object's bound field to zero while returning a zero word. Subject to valid subsequent accesses, the scan still proceeds to index 1 because it uses the captured bound.

8. **Dispatch mutation during scanning.**  
   If an indirect call changes the dispatch information and returns a zero word, the next iteration resolves the target from the then-current dispatch information. Reusing the previous target without resolving it again would not match the visible behavior.

9. **Character-width truncation.**  
   Under an 8-bit truncating character model, an enabling-field value of 256 selects the disabled path, whereas 257 selects the enabled path. These particular values are conditional on that width and conversion model.
