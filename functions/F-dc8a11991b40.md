# F-dc8a11991b40

## Purpose

F-dc8a11991b40 conditionally modifies memory. Incoming carry and zero conditions select one of two mutually exclusive behaviors:

- **Placement:** acquire an unsigned two-byte selector and use its value to locate a four-byte write.
- **Replacement:** write the single byte 0x84 at a fixed displacement from an incoming base.

Replacement is selected only when carry is set and zero is clear. Every other combination selects placement.

These names describe observable effects, not an established application purpose. The supplied static evidence establishes neither a conventional public interface nor a useful return value. Normal completion of either path is unresolved.

### Placement: ordered interactions and accesses

The established placement prefix is:

1. Enter F-000000000001 at the target derived from the incoming link-associated value plus 0x5B0.
2. If progress continues, enter F-000000000002 at **0x08572F35**.
3. If progress continues, enter F-000000000003 at **0x08572F15**.
4. Read the unsigned two-byte selector at the selector-acquisition base available after F-000000000003, plus 0x24.
5. Enter F-000000000004 at **0x08572EFD**.
6. If progress continues, write the four-byte payload beginning at the acquired selector’s numerical value plus 0x24.
7. After that write completes, enter F-000000000005 at **0x085726AD**.

These are ordering requirements for the established execution prefix, not guarantees that interactions return or later operations are reached.

### Placement: destination and payload

The selector-acquisition base locates the selector only. **It is not added to the payload destination.**

The payload destination begins at:

- the acquired selector’s unsigned numerical value;
- plus the constant byte displacement 0x24.

Consequently:

| Property | Minimum | Maximum |
|---|---:|---:|
| Acquired selector | 0 | 0xFFFF |
| Destination start | 0x24 | 0x10023 |
| Last byte of four-byte destination | 0x27 | 0x10026 |

These are numerical bounds, not evidence of allocation or accessibility. In particular, selector 0xFFFF produces destination start 0x10023, not 0x23.

No comparison with existing destination contents or unchanged-value optimization is established. A completed placement includes the write even if the destination already contains the payload.

### Placement: dependency interference

The acquired selector determines the pending destination even if F-000000000004 subsequently modifies the selector’s original storage. No second selector read is established.

This retained numerical value does not preserve the lifetime, mapping, permissions, or contents of any storage. F-000000000004 may change destination accessibility or invalidate storage before the write. Completion is not promised if the destination is no longer writable.

F-000000000005 may modify the destination after placement. The required effect is the earlier completed four-byte write, not permanent retention of the payload as the final memory state.

Selector-read ordering does not establish payload-read ordering. If a dependency modifies payload backing storage, the evidence does not resolve whether earlier or later bytes supply the eventual write.

### Replacement

Replacement writes 0x84 to the byte at the incoming replacement base plus 0x1A. Completion of that write precedes entry to F-000000000006.

No preceding destination read, comparison, or conditional suppression is established. The write is required even if the byte already equals 0x84.

F-000000000006 is associated with operand values 0xEC and 0x08571FB0. Their formal widths and operational meanings are **documented_only**. Neither is established as the replacement destination or a guaranteed subsequent interaction target.

Effects of F-000000000006 do not remove the requirement for the earlier completed byte write.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Completed-access examples assume suitable storage, supported address calculations, and dependencies permitting the stated progress.

### Selection

- Carry set and zero clear selects replacement, regardless of selector or payload contents.
- Carry clear selects placement for either zero condition.
- Carry set and zero set selects placement.
- An inaccessible replacement destination does not authorize placement as a fallback.

### Placement targets and ordering

If all placement interactions and accesses permit progress, the established order is:

- F-000000000001 at the incoming link-associated value plus 0x5B0.
- F-000000000002 at 0x08572F35.
- F-000000000003 at 0x08572F15.
- Selector acquisition.
- F-000000000004 at 0x08572EFD.
- Four-byte payload write.
- F-000000000005 at 0x085726AD.

Merely entering four unspecified fixed targets in that order is insufficient: the four established target values are part of the contract.

If the incoming link-associated value is 0x1000, the first placement target is numerically 0x15B0, subject to supported address interpretation and target executability.

### Dependency-sensitive behavior

- If the base available after F-000000000003 is 0x2000, selector acquisition begins at 0x2024. An earlier base value is not a substitute.
- If the acquired selector is 0x1200 and F-000000000004 changes its original storage to represent zero, the pending destination remains 0x1224.

- If F-000000000005 overwrites the destination, final contents need not equal the payload; the earlier write remains required.
- If a dependency modifies payload backing storage, neither earlier nor later bytes may be prescribed without additional evidence resolving acquisition timing.

### Replacement and arithmetic

With replacement base 0x1000, address 0x101A receives 0x84 before F-000000000006 is entered. This applies even if the byte initially equals 0x84. A later overwrite is compatible with that prefix. Acceptance requires neither execution nor proven unreachability of F-000000000007.

Under the conditional signed 32-bit model, each arithmetic-table boundary yields starting value 0x7FFFFFFF. That alone does not establish a readable selector, writable byte, or executable target. An input one greater exceeds the signed maximum mathematically; no wrapped address or mandatory runtime fault is prescribed.
