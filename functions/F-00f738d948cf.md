# F-00f738d948cf

## Purpose

F-00f738d948cf is a state-dispatched wrapper around two dependencies. It transforms three numeric inputs, retains two opaque input words, and can invoke operations on an object obtained by dereferencing the sixth argument. A separate dependency receives the sixth argument itself.

The function’s intended application-level operation is not established. Its dispatch configuration, operation selectors, numeric scaling constants, and result constants are held in global storage whose values are absent from the supplied evidence. Consequently, the evidence establishes conditional behavior, not a single unconditional call sequence or success convention.

The function can return a 32-bit unsigned result, continue dispatching indefinitely, or encounter invalid memory access if a reached operation dereferences an unsuitable pointer. No explicit argument validation, exception handling, or error reporting is visible.

## Behavior

### Entry and dispatch

Before dispatching, the function:

1. Captures entry scale.
2. Captures entry polarity.
3. Reads the polarity global again and negates that read.
4. Initializes its return accumulator, numeric working state, retained opaque words, and retained pointer to zero or null.
5. Reads the initial dispatch control.

The input arguments are not installed into working state automatically at entry. Installation occurs only when the input-loading phase is selected.

Each dispatch selection adds the current control value to a global dispatch offset and selects a numbered phase. The offset is read again for each dispatch selection; it is not an entry snapshot.

The explicitly recognized phase numbers are 0 through 11. Phase 7 and all otherwise unrecognized selector values execute the input-loading behavior. Thus an out-of-range selector is not rejected.

Every continuation control described below is obtained from global storage. Neither the values of these controls nor the dispatch offset are provided. A named continuation therefore identifies a destination control source, not a guaranteed next phase.

### Input installation and reset behavior

The input-loading phase:

- Sets the retained operand to entry scale multiplied by argument 2.
- Sets the primary operand to entry scale multiplied by argument 1.
- Sets the secondary operand to entry scale multiplied by argument 3.
- Retains arguments 4 and 5 as opaque words.
- Sets the working value to negated polarity multiplied by the retained operand.
- Retains argument 6 as the pointer used by later phases.
- Selects an input-loading continuation from global storage.

Reaching this phase again reloads these fields from the original arguments. It does not reset the return accumulator or every other internal field.

Because dispatch can begin elsewhere, a reached dependency can receive zero-initialized operands or a null pointer without any preceding input-loading phase.

### Three object-operation phases

Phases 10, 4, and 3 each call F-b09db3398a5a with five arguments. In each case:

- The first argument is a fresh read of the first 32-bit word at the retained pointer.
- The fourth argument is literal zero.
- The fifth argument is a phase-specific global operation selector.
- The operation result contributes to both subsequent numeric state and branch selection.

The three forms differ as follows:

| Phase | Second dependency argument | Third dependency argument | State retained from the result |
|---|---|---|---|
| 10 | Primary operand | Secondary operand | Secondary operand becomes negated polarity × entry scale × dependency result. |
| 4 | Retained operand | Secondary operand | Primary operand becomes entry scale × dependency result; secondary operand becomes negated polarity × that new primary operand. |
| 3 | Working value | Literal zero | Secondary operand becomes negated polarity × entry scale × dependency result. |

Phase 3 also replaces the retained operand with negated polarity multiplied by the secondary operand’s **pre-call** value. After its result and branch calculation, it multiplies the existing primary operand by negated polarity.

These distinctions are observable if dispatch reaches more than one operation phase: later calls can receive transformed results or retained values from earlier phases rather than the original arguments.

For phases 10 and 3, define the two branch products as:

- Negated polarity × entry scale × dependency result.
- Entry polarity × entry scale × dependency result.

For phase 4, the products are negated polarity and entry polarity, respectively, multiplied by the newly updated primary operand.

Each operation phase takes the bitwise complement of the bitwise OR of its two branch products. This complemented word becomes the raw result and the working value.

The most significant bit of that complemented word chooses the continuation:

- High bit set: use the phase’s unadjusted continuation control.
- High bit clear: use its adjusted continuation control.

The adjustments are:

| Phase | Adjustment to the continuation control when the high bit is clear |
|---|---|
| 10 | Subtract 2 |
| 4 | Subtract 8 |
| 3 | Subtract 1 |

The continuation global is read once for the adjusted alternative and again for the unadjusted alternative. These are separate reads. If that storage changes between reads, the alternatives need not differ by precisely the listed amount.

This branch must not be described unconditionally as “success versus failure” or “zero versus nonzero.” Such interpretations depend on unprovided numeric constants and arithmetic behavior.

### Pointer-oriented dependency phase

Phase 0 calls F-34d9c1aebced with:

1. The retained pointer itself, not its first word.
2. The retained fourth argument.
3. A global coefficient multiplied by the current primary operand.
4. The retained fifth argument.

After the dependency returns, its result is multiplied by entry scale, negated polarity, and a separate global result coefficient. That result becomes both the raw result and working value. A global continuation control is then selected.

The third-argument coefficient is read before the dependency call. The result coefficient and continuation control are read after the call. They must not be assumed to retain earlier global values if the dependency changes global storage.

### Arithmetic boundaries

The unsigned complement and right shift are word operations. The shift by 31 produces exactly zero or one under the 32-bit word model.

Unsigned arithmetic retains the low 32 bits. However, some multiplication chains, negation, dispatch addition, and continuation adjustments are expressed using signed integers. The supplied evidence does not establish a portable rule for signed overflow.

Accordingly:

- Do not replace products by mathematical integers without checking range.
- Do not assume that negating the minimum signed value is portable.
- Do not simplify the branch products using opposite signs without establishing the relationship between the two entry polarity reads and the applicable overflow behavior.
- A machine-level modulo-\(2^{32}\) interpretation may be appropriate for the original executable, but that is not independently established for every signed expression here.

## Side effects

The wrapper visibly reads global configuration, invokes dependencies, and conditionally reads memory through the retained pointer. It contains no explicit write through an input pointer and no explicit assignment to global storage.

That does **not** establish a side-effect-free API:

- Either dependency may change global storage.
- F-34d9c1aebced receives the pointer directly and may read or modify reachable memory.
- F-b09db3398a5a receives the pointer’s current first word, which may identify an object with mutable state.
- Either dependency may allocate, release, retain, or invalidate memory; its contract is unavailable.
- Later global reads and pointer dereferences occur after earlier calls and can observe their effects.

Each object-operation phase reads the first word anew. The wrapper does not snapshot that word during input loading and does not visibly refresh the retained pointer after calls. If a dependency invalidates that pointer, a later dereference may be invalid.

The wrapper performs no visible allocation, deallocation, ownership transfer protocol, cleanup, retry limit, or rollback. Ownership consequences of the dependencies are documented_only.

Relative ordering between independent operands within a single expression or dependency argument list is not established. The sequencing between completed calls and subsequent statements is established.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Immediate return.** If the initial control plus the first dispatch-offset read selects phase 9, the result is zero. Neither dependency is called, and argument 6 is not dereferenced.

2. **Input loading is not validation.** If the selected phase is 7 or outside the explicit phase range, input values are installed as described. A null sixth argument is retained without an immediate dereference.

3. **Pointer versus pointee.** If phase 0 follows input loading, F-34d9c1aebced receives argument 6 itself. If phase 10 follows input loading instead, F-b09db3398a5a receives the current first word at argument 6.

4. **Numeric input mapping.** With stable entry scale equal to 1 and stable polarity equal to 1, input loading gives the primary operand argument 1, the retained operand argument 2, the secondary operand argument 3, and the working value the negation of argument 2, provided the operations are representable.

5. **Zero-result conditional branch.** If an object-operation dependency returns zero and all associated signed operations are defined, both branch products are zero. Their complemented OR is all ones, so the unadjusted continuation is selected. This establishes the branch choice, not the ultimate return value.

6. **Conditional nonzero illustration.** With entry scale 1, entry polarity 1, negated polarity −1, and dependency result 1, the two branch products are −1 and 1. Under the 32-bit representation, their complemented OR is zero. The adjusted continuation is selected.

7. **Fresh object-word read.** If one dependency changes the first word at the retained pointer, and execution later reaches another object-operation phase with that pointer still valid, the later call receives the changed word.

8. **Accumulator persistence.** If phase 5 establishes a return accumulator and execution later passes through input loading before phase 9, the earlier accumulator remains the return value unless phase 5 is reached again.

9. **No termination guarantee.** A configuration whose continuations repeatedly select nonterminal phases can prevent return. The wrapper imposes no iteration bound.
