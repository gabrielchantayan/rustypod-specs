# F-ddf87590e714

## Purpose

F-ddf87590e714 resolves the first argument as a byte-oriented format, prepares a working record from the remaining arguments, validates supported directives, selects output storage, and renders the format. On the completion path, it writes a terminating NUL and passes the output-buffer address to F-475af1e83e55.

The directive vocabulary suggests date/time formatting. That interpretation is inferred intent, not an established contract for calendar fields, epochs, units, rounding, or textual representations.

This specification describes statically established operations separately from unknown dependency behavior. In particular, neither bounded formatting nor numerical-operation semantics are established merely by call shapes.

## Interface

### Inputs and completion

| Input | Representation | Established use |
|---|---|---|
| Context | 32-bit value used as an address | Passed to preparation, error, and publication dependencies; supplies a nested limit on the allocation path. |
| Argument count | 32-bit integer | Decreased by one for preparation. |
| Argument-array address | 32-bit address of 4-byte slots | First slot supplies the resolver input; remaining slots are passed to preparation. |

There is no explicit scalar return value. Completion is observable through dependency calls and memory effects.

The first argument slot is read without a preceding local count or pointer check. A zero or negative argument count does not prevent that read. The count decrement uses represented 32-bit integer arithmetic; behavior at signed overflow is not established.

Successful completion calls F-475af1e83e55 with the context, output-buffer address, and 32-bit value `0xffffffff`. The last argument’s meaning is unknown.

### Preconditions and storage layout

Ordinary successful execution requires:

- A readable first argument slot.
- A nonzero resolved address identifying readable format bytes through NUL.
- Sufficiently stable format storage for validation to constrain rendering.
- Record preparation and processing compatible with subsequent field reads.
- Readable nested context fields if allocation is required.
- Output writes and position increments compatible with the selected storage.

These are integration requirements, not locally enforced guarantees.

The working record has the following directly relevant fields:

| Byte offset | Observed use |
|---|---|

| 8–11 | A 32-bit explicit formatting operand for `%Y`. |

For `%j` and `%W`, an external dependency receives temporary-record and working-record addresses with a size argument of 48. This does not, by itself, establish that 48 bytes are copied or that the full record layout is known.

## Behavior

### Resolution and preparation

F-95b79f0a129e receives the 32-bit contents of the first argument slot. A zero result causes immediate return.

A nonzero result is subsequently used as the format address. F-ebbc2d941666 then receives, in order:

1. The context.
2. The argument count decreased by one.
3. The argument-array address advanced by four bytes.
4. The working-record address.

A nonzero preparation result causes immediate return, without a local error-reporting or publication call. Earlier dependency effects are not rolled back.

### Validation and estimate

Validation scans the resolved format bytewise before selecting output storage or performing the three subsequent record-processing calls.

The estimate begins at one. Ordinary non-NUL bytes add one. A percent introduces a directive and consumes its following byte.

| Accepted directive | Total estimate contribution |
|---|---:|
| `%%`, `%w` | 1 |
| `%H`, `%M`, `%S`, `%W`, `%d`, `%m` | 2 |
| `%j` | 4 |
| `%Y`, `%f` | 9 |
| `%J`, `%s` | 51 |

Every other directive causes immediate return during validation. A trailing percent is rejected because its following NUL is not accepted as a directive. These paths do not publish an output prefix.

The estimate comprises two unsigned 32-bit words. Low-word additions propagate carry into the high word. High-word overflow is not checked; this is finite two-word arithmetic, not an unbounded size calculation.

Format indices and output positions are represented as signed 32-bit integers. Their increments and address calculations have no explicit overflow checks. The supplied body does not establish safe behavior at their overflow boundaries.

### Storage selection

Local 100-byte storage is selected exactly when the estimate’s high word is zero and its low word is strictly below 100. Estimate 99 selects local storage; estimate 100 enters the allocation path.

On the allocation path, the function reads a 32-bit address at context offset 24, then a 32-bit limit at offset 80 from that address. It sign-extends the limit into two words and compares the estimate against that representation using unsigned word comparisons.

If the estimate exceeds the represented limit, F-bb73abb30feb receives the context, followed by return.

Otherwise, F-391e3d30e634 receives only the estimate’s low 32-bit word. A zero result causes F-251588f6a575 to receive the context, followed by return. A nonzero result becomes the output-buffer address.

A negative stored limit produces an all-ones high word. Consequently, the comparison can admit an estimate with a nonzero high word even though allocation receives only its low word. The body neither rejects negative limits nor checks this narrowing.

### Rendering iteration and direct output

Format and output positions begin at zero.

At the start of every rendering iteration, the record pair at offsets 32–39 is cached before the current format byte is read. This also happens on the iteration that encounters the terminating NUL.

An ordinary non-NUL byte is written at the current output position, which advances by one.

For a percent, the format position first advances to the directive byte. After directive handling, it advances again. Stable input therefore consumes two bytes per directive.

On encountering NUL, the function writes NUL at the current output position and calls F-475af1e83e55. It does not establish that preceding fragments lack embedded NULs, that every preceding byte was initialized, or that output stayed within storage bounds.

### Fraction path

For `%f`, F-c6bfc9d0fb36 receives the current record pair at offsets 32–39 first and the fraction pair second.

After that call, the pair cached at rendering-iteration entry is assigned to the local formatting-argument area. The dependency’s displayed result is not assigned there. Even if that dependency changes the working record, these explicit assignments still use the earlier cached pair.

An alternative assignment from the fraction-pair storage is unreachable for the accepted lowercase `f` byte because its guarding comparison has already selected the other outcome.

These observations establish the explicit assignments, not how F-ea27adaa2931 interprets that area or any implicit machine state.

For `W`, the function instead supplies the current leading working-record pair first and a newly read shared scaling pair second to another F-1b22d7e17791 call. F-baa332e06e32 is called without displayed explicit arguments, and its result and 7 are passed to F-870c4fcf7295.

## Side effects

Direct writes include output bytes, the final NUL, local formatting-argument assignments, and temporary-record modifications. Dependencies receive addresses and may produce additional effects not established here.

The format is read in two passes separated by storage selection and record processing. It is not locally copied. The temporary-record paths also reread the directive byte after numerical dependencies. Mutation can therefore invalidate the relationship between validation, allocation, and rendering.

The nested context limit is read only when local storage is not selected.

No explicit release occurs for the resolved format or allocated output. Publication receives either local or allocated storage. Local storage is not valid after return, so safe retention requires dependency behavior not supplied here. Heap-buffer ownership, copying, retention, transfer, and release are documented_only.

No local recovery is visible for dependency failures other than the tested resolver, preparation, and allocation results. Limit rejection and allocation failure invoke distinct dependencies. Earlier effects are not rolled back.

## Acceptance examples

These are conditional static criteria, not runtime results.

1. **Resolution rejection:** A zero resolver result prevents preparation, validation, record processing, and publication.

2. **Preparation rejection:** A nonzero preparation result prevents validation and rendering.

3. **Empty stable format:** Successful preparation selects local storage. After the three record-processing calls return normally, the function caches the record pair, reads NUL, writes NUL at output position zero, and publishes.

4. **Literal percent:** Stable `%%` has estimate two and directly emits percent followed by the final NUL.

5. **Invalid directive:** Stable `abc%q` or a trailing percent returns during validation without publishing a prefix.

6. **Storage boundary:** 98 ordinary bytes produce estimate 99 and use local storage. 99 ordinary bytes produce estimate 100 and enter the limit path.

7. **Distinct errors:** Estimate 100 against nonnegative limit 99 invokes F-bb73abb30feb without allocation. A permitted allocation returning zero invokes F-251588f6a575 without subsequent record processing.

8. **Fixed advancement:** If the rendering dependency writes only one byte for `%H`, output nevertheless advances by two. The function does not repair any gap; this does not establish that such dependency behavior is valid.

9. **Returned advancement:** If F-1cb585febd84 returns four after `%Y`, output advances by four regardless of the rendering dependency’s actual writes.

10. **Fraction cache:** If F-c6bfc9d0fb36 changes the record pair, the explicit subsequent formatting-area assignments still use the iteration-entry cached pair.

11. **Scaling reread:** If shared scaling storage changes between `%W`’s two uses, the second call receives the reread contents.

12. **Seconds operand order:** If F-8a693c103d1c returns pair A and the second seconds region supplies pair B, F-c4b34006a13c receives A first and B second. If it returns pair C and the shared scaling region supplies pair D, F-1b22d7e17791 receives C first and D second. No acceptance criterion treats reversal as equivalent.

13. **Conditional digit:** If `%w`’s character-sized auxiliary value represents 0 through 6, the emitted byte is the corresponding digit. No weekday numbering or range guarantee follows.
