# F-01844383d2b2

## Purpose

F-01844383d2b2 processes four selector-associated groups of 32-bit context fields, stores selected dependency results into a four-word output region, conditionally invokes an adjustment dependency, and finally clears bit `0x20` in a context status word.

The established behavior is an ordered sequence of dependency calls, result stores, comparisons, and conditional adjustments. The meanings of the four selectors and their associated fields are not established. Interpreting the output as coordinates, bounds, or dimensions would be inferred intent, not part of this contract.

A significant detail is that **zero does not trigger either initial selector-order override**. The effective override values are specific high-bit-set 32-bit patterns.

## Interface

The function takes two arguments and has no explicit return value:

- **Context address:** an address represented by the supplied 32-bit interface. The function directly reads and writes fields at fixed byte offsets from this address.
- **Output address:** an address to a region containing at least four consecutive 32-bit words. The function passes this address to dependencies and directly reads and writes words in this region.

The four output words are designated:

| Output word | Byte offset | Associated selector |
|---|---:|---:|
| R1 | `0x00` | 1 |
| R2 | `0x04` | 2 |
| R3 | `0x08` | 3 |
| R4 | `0x0C` | 4 |

The context contains these directly accessed fields:

| Offset | Width | Role established by this function |
|---|---:|---|
| `0x48` | 32 bits | Status word whose bit `0x20` is cleared at completion |
| `0x50`, `0x54`, `0x58` | 32 bits each | Three arguments for selector 1 |
| `0x5C`, `0x60`, `0x64` | 32 bits each | Three arguments for selector 2 |
| `0x68`, `0x6C`, `0x70` | 32 bits each | Three arguments for selector 3 |
| `0x74`, `0x78`, `0x7C` | 32 bits each | Three arguments for selector 4 |

The words at `0x54`, `0x60`, `0x6C`, and `0x78` also participate in bit-based conditions. Their full semantic interpretation is unknown.

The function additionally reads a global four-entry table of 32-bit selector values.

## Behavior

### 1. Capture the selector sequence

The function reads the global selector table’s four words into a private four-entry sequence, in entry order.

The copied sequence is then conditionally modified using two context fields:

1. Read the 32-bit word at `0x54`.
2. If its bit pattern is exactly `0x80000008` or `0x80000028`, replace sequence entry 0 with selector 3 and entry 2 with selector 1.
3. Read the 32-bit word at `0x60`.
4. If its bit pattern is exactly `0x80000004` or `0x80000024`, replace sequence entry 1 with selector 4 and entry 3 with selector 2.

The bit-pattern sets above account for the signed comparison and the masking operation in the supplied evidence. Zero is excluded. Positive values are excluded. Other negative 32-bit values are also excluded.

These decisions occur before the selector-processing dependency calls. A later dependency mutation of `0x54` or `0x60` does not revise the already captured sequence.

The default sequence itself is unknown. There is no established guarantee that it is a permutation of selectors 1 through 4.

### 2. Process exactly four sequence entries

The function visits the private sequence in order, once per entry. The loop executes four iterations. The visible narrow counter arithmetic does not wrap during these four iterations.

For each entry:

| Selector value | Context words supplied to F-bb8ca4eb0799 | Destination for its 32-bit result |
|---:|---|---|
| 1 | `0x50`, `0x54`, `0x58` | R1 |
| 2 | `0x5C`, `0x60`, `0x64` | R2 |
| 3 | `0x68`, `0x6C`, `0x70` | R3 |
| 4 | `0x74`, `0x78`, `0x7C` | R4 |

Each recognized selector causes one call to F-bb8ca4eb0799 with six arguments:

- Context address.
- Output address.
- The three 32-bit words associated with that selector.
- The selector value.

The three context words are obtained for that invocation, not snapshotted for all four invocations at function entry. Consequently, changes made by earlier calls or overlapping output stores can affect later call arguments.

The dependency’s returned 32-bit value is stored in the designated output word after the call returns. This store overwrites any value the dependency itself left in that same output word.

An unrecognized selector causes no call and no direct output store for that iteration. Repeated recognized selectors cause repeated calls and repeated stores to the same destination. A destination not selected is not initialized by this phase.

The supplied evidence does not fix the relative evaluation order of the three context argument reads within one call expression. It does establish that the call completes before the result store and before processing the next sequence entry.

### 3. Decide whether adjustment processing is eligible

After all four iterations, the function reads R2 and R4 and compares them as signed 32-bit integers.

- If R2 is greater than R4, adjustment processing is skipped.
- If R2 is less than or equal to R4, it reads R1 and R3 and compares them as signed 32-bit integers.
  - If R1 is greater than R3, adjustment processing is skipped.
  - Otherwise, adjustment processing is entered.

Thus entry into adjustment processing requires both signed relations:

- R2 ≤ R4.
- R1 ≤ R3.

The supplied representation expresses parts of this decision using subtraction and signed-overflow indicators. The effective relation is signed comparison, not a sign test on a wrapping subtraction result. In particular, comparisons across the signed 32-bit extremes must retain their normal signed ordering.

The R1/R3 comparison is not reached when the initial R2/R4 comparison rejects adjustment processing.

### 4. Perform the first pair of conditional adjustments

This phase is reached only when both relations above pass.

If the R1 and R3 values captured by the eligibility comparison are equal, the function evaluates two separate conditional calls, in order.

**First condition:**

- The current word at `0x54` has at least one bit in mask `0x80000002` set, **or** its low byte is zero.
- The current word at `0x6C` has bit `0x20` clear.

If both requirements hold, call F-d156b0b83eb3 with the output address and a 32-bit zero argument.

**Second condition:**

- The current word at `0x6C` has at least one bit in mask `0x80000002` set, **or** its low byte is zero.
- The current word at `0x54` has bit `0x20` clear.

If both requirements hold, call F-d156b0b83eb3 with the output address and a 32-bit zero argument.

These are independent conditions, not alternatives. Both calls may occur.

The equality deciding entry into this pair uses the previously captured R1/R3 comparison values. It is not rechecked after the first adjustment call. The second condition does, however, read its context fields after the first call has returned. Dependency side effects can therefore change whether the second call occurs.

### 5. Perform the second pair of conditional adjustments

Still within the eligible adjustment block, the function reads R4 and R2 again and tests equality. These are fresh output reads, after any first-pair adjustment calls.

If they are equal, it evaluates two further independent conditions in order.

**Third condition:**

- The current word at `0x60` has at least one bit in mask `0x80000002` set, **or** its low byte is zero.
- The current word at `0x78` has bit `0x20` clear.

If both requirements hold, call F-d156b0b83eb3 with:

- The output address.
- The 32-bit negation of the current word at `0x64`, interpreted as a signed quantity.

**Fourth condition:**

- The current word at `0x78` has at least one bit in mask `0x80000002` set, **or** its low byte is zero.
- The current word at `0x60` has bit `0x20` clear.

If both requirements hold, call F-d156b0b83eb3 with the output address and the current 32-bit word at `0x7C`.

The R4/R2 equality is tested once before this pair. It is not rechecked between its two potential calls. The fourth condition and its argument reads occur after the third call returns.

For all four conditions, evaluation is short-circuited:

- A true masked-bit test avoids the alternative low-byte test.
- A false combined first requirement avoids the other field’s `0x20` test.
- The offset argument for a conditional call is read only if the call is reached.

Where the masked-bit test fails, the low-byte alternative is represented as another access to the same context field. These accesses must not be assumed to constitute an atomic snapshot.

### 6. Clear the completion status bit

After the adjustment block, or immediately after eligibility rejection, the function reads the current 32-bit status word at `0x48`, clears bit `0x20`, and writes the result to `0x48`.

All other bits of the value read at this final step are preserved. This is not based on an entry-time status snapshot.

This update is the last directly visible operation before normal return. It is not guaranteed to occur if an earlier access fails or a dependency does not return normally.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime observations.

1. **Zero does not override the sequence.**  
   Given `0x54 = 0` and `0x60 = 0`, both selector-order overrides are absent. The copied table determines all four processed entries.

2. **Both overrides determine all four entries.**  
   Given `0x54 = 0x80000028` and `0x60 = 0x80000004`, the processed sequence is 3, 4, 1, 2, regardless of the table’s initial values. Calls and result stores occur in that order.

3. **Unrecognized selectors leave direct initialization incomplete.**  
   Given a copied sequence of 1, 1, 9, 4 with neither override active, F-bb8ca4eb0799 is called for selectors 1, 1, and 4. R1 receives two successive result stores; R4 receives one. This phase makes no direct store to R2 or R3. Later comparisons still access those words.

4. **Signed extremes reject adjustment correctly.**  
   If the completed output has R2 equal to `0x7FFFFFFF` and R4 equal to `0x80000000`, adjustment processing is skipped because signed R2 is greater than signed R4. A wrapping difference must not reverse that result.

5. **Strict inequalities permit entry but do not themselves trigger calls.**  
   Assuming output remains stable during the relevant reads, R2 < R4 and R1 < R3 allow entry into the adjustment block, but neither equality-based pair runs. The status bit is still cleared.

6. **All four adjustment calls can occur.**  
   Suppose both output pairs compare equal, the four condition fields are zero, `0x64` holds 7, `0x7C` holds 9, and dependencies preserve the fields relevant to later decisions. The adjustment arguments are, in order, 0, 0, −7, and 9.

7. **Adjustment side effects affect later eligibility.**  
   If a first-pair call changes R4 so that the fresh R4/R2 equality fails, neither second-pair call occurs. Conversely, that call can make the fresh equality true even if R2 and R4 were unequal during the initial eligibility comparison.

8. **Final status uses the latest value.**  
   If the status word is `0xA5` when the final update is reached, the stored value is `0x85`. A dependency’s earlier status changes are retained except for bit `0x20`.
