# F-2920e73aa586

The established behavior is a memory transformation followed by an indirect control transfer represented as a call. No application-level purpose, object model, allocation policy, or ownership transfer is established. ## Behavior

### Initial write and primary sampling

The first visible memory effect is a two-byte write of the value 101, hexadecimal 0x0065, at the address formed by doubling the primary base. This destination is twice the address-related value, not the primary base plus two and not a field selected from an established object layout.

Only after that write does the routine read the primary sample from primary base plus 100. The sample therefore reflects any overlap between the initial write and that read. It is retained for later use as stored data, as an address-calculation operand, and as an invocation argument.

### Secondary-base updates and remaining sampling

After the primary sample has been obtained, the routine writes the entry byte at secondary base plus 17. It then writes the four-byte value 100, hexadecimal 0x00000064, at secondary base plus 84.

The forwarded sample is read next, from primary base plus 116. Consequently, either preceding secondary-base write can affect this sample if the relevant byte ranges overlap.

The tertiary sample is then read from tertiary base plus 100. This read follows the initial two-byte write and both secondary-base writes, so it too can observe their effects through aliasing.

All three word reads have occurred before the remaining three writes.

### Final memory updates

The routine next writes one byte at tertiary base plus 9. That byte is the least significant eight bits of the primary base. The stored bit pattern does not require assigning the byte a signed or unsigned application meaning.

It then writes the four-byte primary sample at tertiary sample plus 84. Here, the retained tertiary sample determines the destination, while the retained primary sample supplies the data.

Finally, it writes the four-byte tertiary sample at twice the primary sample. This is a doubled sampled value, not a fixed-offset access.

The last two writes can overlap each other or any earlier location. They do not trigger a reread of either sample. If their destinations overlap, the final write supplies the later effect on the overlapping bytes, subject to the target environment’s memory semantics.

## Acceptance examples

These are conditional deductions, not executed tests. Except where overlap is specified, assume accessible, appropriately aligned, non-overlapping regions; address calculations that do not encounter unresolved overflow behavior; no external memory modification; and an indirect target that returns normally.

### Independent regions

Suppose the reads produce:

- Primary sample: 0x00005000.
- Tertiary sample: 0x00007000.
- Forwarded sample: 0x12345678.

Suppose the entry byte is 0xAB.

| Destination | Stored value and width |
|---|---|

The invocation arguments are 114, 0x00005000, the unchanged third explicit parameter, and 0x12345678, in that order. These six writes account for 16 bytes of write width.

### An earlier write determines a later argument

Suppose secondary base plus 84 equals primary base plus 116, giving exact four-byte overlap, with no other relevant overlap.

The four-byte write of 100 precedes the forwarded-sample read. The fourth invocation argument must therefore be 100, rather than the word present at that location on entry.

This conclusion does not depend on byte order because the read covers the same four bytes as the preceding same-width write.

### A later byte write does not revise a sample

Suppose tertiary base plus 9 overlaps one byte of the primary-sample location.

The primary sample has already been retained when that byte is written. The second invocation argument and the operand used for the final doubled destination remain based on the earlier sample, even though memory at its original source location has changed.

### Final destinations coincide

Suppose the primary sample is 0x00005000 and the tertiary sample is 0x00009FAC. Then tertiary sample plus 84 and twice the primary sample both designate 0x0000A000.

The first of the final two word writes stores 0x00005000 there. The next stores 0x00009FAC at the same location. Immediately before the indirect invocation, absent external interference, that location therefore contains 0x00009FAC.

The second invocation argument remains 0x00005000.
