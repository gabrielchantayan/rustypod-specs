# F-438f5c7311f2

## Purpose

F-438f5c7311f2 searches a globally described sequence of 32-bit integer entries for an input value. The scan stops at the first matching entry, the first zero entry, or the current scan limit.

Under stable global state and stable sequence contents, the function returns the index of a matching nonzero entry encountered before either stopping boundary. Otherwise, it returns the scan limit. Zero acts as a terminator rather than a successfully searchable value.

A significant part of the contract is an unconditional entry read after scanning stops. The scan limit does not protect this final read. In particular, reaching a limit of \(L\) causes an entry read at index \(L\), and a zero limit still causes an entry read at index zero.

These conclusions describe the supplied static representation. No runtime tests have been performed.

## Interface

### Input

The function accepts one signed 32-bit integer search value.

The value is compared for equality against signed 32-bit sequence entries. Negative values are eligible matches. No ordering comparison is performed between the input and an entry.

An input of zero does not make a zero entry a successful match: the zero-termination condition takes precedence.

### Output

The function returns an unsigned 32-bit integer.

With stable globals and stable sequence contents, the result is:

- The zero-based index of the first matching nonzero entry, if it occurs before a zero terminator and before the scan limit.
- The scan limit otherwise.

The return value contains no separate success flag or error indication. Callers must interpret it using the applicable limit and the stability assumptions described below.

### Global inputs and layout

The function obtains two values from a global descriptor:

1. A base value used to locate sequence storage.
2. A limit value in the descriptor’s next indexed slot.

The supplied representation establishes that these are distinct descriptor fields and that the limit is accessed as the second indexed element. It does not independently establish the descriptor’s full declared type, allocation size, alignment, or ABI-level field offsets.

Sequence entries have a four-byte stride. For an index \(i\), the function accesses the 32-bit integer entry at the current base plus the computed offset \(4i\). The sequence may contain positive integers, negative integers, and zero.

The limit participates in an unsigned 32-bit comparison. A stored value whose high bit is set is therefore not treated as a negative scan limit; its bit pattern contributes a large unsigned limit.

### Preconditions for defined, fault-free access

The descriptor must be readable whenever the function accesses it. Each effective sequence address actually used must support a readable 32-bit integer access.

For stable state with limit \(L\):

- If scanning stops at a zero or match before \(L\), the stopping entry must also remain readable for the final reread.
- If scanning reaches \(L\), entry \(L\) must be readable, despite being outside the set of indices admitted by the scan’s strict upper-bound comparison.
- If \(L=0\), entry zero must nevertheless be readable.

The representation contains no checks for null bases, inaccessible storage, insufficient allocation, or unsuitable alignment. It does not establish the platform’s behavior for invalid accesses.

## Behavior

### Scan order

The scan begins at index zero.

At each scan decision, the function reads the current limit and compares the unsigned index against it. Only when the index is strictly less than that observed limit does it read the base and fetch the entry for that index.

For an entry fetched during scanning:

- Zero stops the scan immediately.
- A value equal to the search input stops the scan immediately.
- Any other nonzero value advances the index by one.

The next scan decision reads the limit again. The limit is not captured once at function entry. Likewise, the base is obtained again for each entry access rather than being fixed for the entire call.

The scan therefore stops for one of three reasons:

1. The current index is not below the limit observed for that decision.
2. The fetched entry is zero.
3. The fetched entry equals the input.

No later entry is examined by the scan after a zero or matching entry stops it.

### Final selection and unconditional read

After scanning stops, the function first reads the limit again and retains that observed value as the prospective return value.

It then obtains the base again and unconditionally reads the entry at the stopping index. This read occurs even if the scan stopped because its index was not below the limit.

The final entry read controls the return selection:

- If that entry is zero, the function returns the limit retained immediately before this read.
- If that entry is nonzero, the function returns the stopping index.

The final check does not compare the entry with the search input. Consequently, outside a stable-state assumption, a returned index is not proof that the final entry read matched the input.

### Stable-state interpretation

If the descriptor and sequence remain unchanged throughout the call, the return behavior simplifies:

- A match before any zero and before the limit returns its index. The matching entry is necessarily nonzero.
- A zero before any match returns the limit.
- Exhaustion at the limit returns the limit regardless of whether the final entry at that index is zero or nonzero.

The last case has identical return values on both branches: the stopping index and the retained limit are equal. The final read remains part of the behavior even though its contents do not change the result under these conditions.

For input zero, the function advances only over nonzero entries and stops upon the first zero or upon limit exhaustion. Under stable state, it always returns the limit.

### Repeated reads and changing state

The supplied representation contains no synchronization or snapshot mechanism. Its distinct reads must not be collapsed into an assumption of stable state.

If changes between reads are permitted by the execution environment, the following conditional outcomes follow from the represented order:

- An entry that originally stopped the scan because it matched may become zero before the final read. The function then returns the subsequently retained limit.
- An entry that originally stopped the scan because it was zero may become nonzero before the final read. The function then returns that index, without rechecking equality against the input.
- A changed base can make the final entry read refer to different storage from the entry that stopped the scan.
- A changed limit can make the final retained limit differ from the limit that ended scanning.

These describe consequences of distinct observations, not a guarantee that unsynchronized concurrent mutation is supported. The applicable memory model and permitted mutation mechanisms are not established.

### Integer widths and address arithmetic

The index and result are unsigned 32-bit quantities. The entry stride is four bytes.

The index increments by one only after an entry is observed to be nonzero and unequal to the input. With an unsigned 32-bit limit, the scan cannot increment beyond the maximum unsigned 32-bit value: at that index, no representable limit can satisfy the strict comparison.

The scaled offset is a different concern. Its represented unsigned 32-bit multiplication by four wraps modulo \(2^{32}\). Large indices can therefore produce repeated offsets. In particular, indices separated by \(2^{30}\) have the same scaled 32-bit offset.

There is no overflow rejection or checked-address calculation. The ultimate validity and interpretation of adding the offset to the base depend on the address representation and execution environment. This contract does not promise a distinct reachable entry for every possible unsigned index.

## Side effects

No explicit writes to the descriptor, sequence, or other memory appear in the supplied representation.

The function performs no explicit allocation, deallocation, ownership transfer, logging, or callback invocation. It does not take ownership of the search input or the storage it reads.

Its relevant memory-access effects are:

- Repeated limit reads during scanning.
- Base and entry reads only after a successful scan-bound comparison.
- A separate limit read after scanning stops.
- An unconditional final base and entry read.

If the storage has read-sensitive behavior, these accesses can matter independently of the returned number. The source does not establish that such storage is supported, nor does it establish volatile or atomic access semantics.

An invalid final read is not converted into a normal failure result. Platform-specific fault handling is outside the established contract.

## Acceptance examples

The following are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume stable descriptor values, stable entries, and valid addresses for every read.

1. **Match at the beginning.** With limit 3, input 12, and entry zero containing 12, the function returns 0. It reads that entry during scanning and again during final selection.

2. **Match after a nonmatch.** With limit 4, input −9, and initial entries 6, −9, and 0, the function returns 1. Negative values are ordinary searchable nonzero entries.

3. **Terminator before a later match.** With limit 4, input 12, and initial entries 6, 0, and 12, the function returns 4. The entry containing 12 is not reached.

4. **Zero input.** With limit 3, input zero, and initial entries 6 and 0, the function returns 3, not 1. The zero entry terminates the scan.

5. **Limit exhaustion.** With limit 2, input 12, and entries zero and one containing 6 and 7, the scan reaches index 2. The function reads entry 2 and returns 2 whether that entry is zero or nonzero.

6. **Zero limit.** With limit zero, no entry is fetched by the scan condition. The function nevertheless reads entry zero during final selection and returns zero if that read completes.

7. **Insufficient storage at exhaustion.** With limit 2 and only entries zero and one readable, two nonmatching nonzero entries cause an attempted read at index 2. A normal return is not guaranteed.

8. **Changed stopping entry.** If an allowed intervening change replaces a matching entry with zero before the final read, the function returns the final retained limit rather than the match index.

9. **Changed terminator.** If an allowed intervening change replaces the stopping zero with a nonzero value before the final read, the function returns the stopping index even if the replacement differs from the search input.
