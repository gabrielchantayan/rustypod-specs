# F-73016b3a5c11

## Purpose

The established behavior is an ordered sequence of indirect calls, word-sized memory transfers, byte-sized updates, two writes to a global location, a final halfword clear, and an attempted call to address zero.

The supplied static representation does not establish a higher-level purpose. In particular, it does not justify describing this routine as an allocator, serializer, object initializer, operating-system service, or successful shutdown operation. Names attached to global storage are not evidence of its meaning.

This contract describes the explicit operations and their ordering, conditional on control reaching them. Most call targets, several incoming machine-state values, and some results carried outside ordinary return-value notation are unresolved. Consequently, the routine is not established as a self-contained three-argument API.

No runtime tests have been performed.

## Behavior

### Execution model and dependency notation

The following phases preserve the order of explicit memory effects. Calls occur between these effects and may themselves read or write memory, change globals, fault, or fail to return.

For dependency identification:

- **F-000000000001** denotes the first unresolved indirect-call occurrence.
- **F-000000000002** denotes the other unresolved indirect-call occurrences collectively. Each occurrence has an independently unresolved target; this identifier does not assert a shared callee.
- **F-000000000003** denotes the final call through address zero.

Descriptions such as “returned index” identify values by their role in this contract, not source-level symbols. They do not establish that a value is valid, bounded, or actually an index into an allocated object.

### 1. Initial word writes

The first call, F-000000000001, receives the second argument. Its target depends on the incoming control-link state.

Subsequent calls include a no-explicit-argument call whose 32-bit result is passed to the next call. Further calls produce an index-like value. The routine writes the incoming 32-bit register value to the address obtained by multiplying that result by four and adding 20.

It then passes the four-times-scaled value to another call. After further calls, it writes a 32-bit zero to an address formed by multiplying an additional register output by four and adding 20. That additional output is subsequently passed to a call.

These are two separate word stores. There is no check that their destinations differ, belong to the same structure, or are writable.

### 2. Third-argument field and first byte update

Another result-forwarding sequence and several calls produce a new index-like result. The routine writes the third argument shifted right by 23 to the address at four times that result plus 20.

After that store, it reads a 32-bit word from an address constructed from an additional register output: retain its low 29 bits, shift right by 19, then add 20. The offset before adding 20 ranges from 0 through 1023. It is not necessarily divisible by four.

The routine then passes the earlier scaled index to a call and performs further calls. It shifts the saved word right by 22, yielding a value from 0 through 1023.

The next explicit memory operations are:

- Read one unsigned byte at the address equal to the third argument shifted right by 23, plus one.
- Add 17 to that byte value to obtain a destination address.
- Write the low eight bits of the saved shifted word to that destination.

The byte-read address is therefore between 1 and 512 inclusive. The resulting byte-store address is between 17 and 272 inclusive.

A subsequent call receives the same additional 32-bit output in its first three explicit argument positions and zero in the fourth.

### 3. Byte clears and repeated-argument calls

After another call, a following call receives zero: its argument is derived by shifting a value explicitly set to zero.

Further calls produce an index-like result. Before passing its four-times-scaled form onward, the routine:

- Reads a byte at four times the saved shifted word plus one.
- Writes zero to the address obtained by adding 17 to that byte.

Because the saved shifted word is at most 1023, this byte-read address lies between 1 and 4093.

Another sequence produces a result whose four-times-scaled value is supplied twice to a call. A later call returns a new 32-bit value, which is passed to another call.

The routine then reads the byte at address 1 and writes zero to that byte’s value plus 17. A following call receives an additional register output three times. That same output is retained for later left shifts.

Another result-forwarding call receives two explicit values: a newly returned 32-bit value and the previously saved 32-bit value shifted right by 23.

Following more calls, the routine reads the byte at address 1 again, saves this newly read byte as a base, and writes zero at that base plus 17. This is a fresh read; it must not be replaced with the earlier value read from address 1.

### 4. First global write and word-to-byte copies

Further calls include a call with the same scaled index supplied twice. A later 32-bit return value is written to the global word location identified here as **G1**. The same returned value is then passed to a call.

After another call, the routine reads a 32-bit word at the saved byte-derived base plus 116 and writes its low byte at that base plus one.

A subsequent call receives the retained additional register output shifted left by 11. Another call supplies a 64-bit result. The next call receives:

1. Its low 32 bits.
2. Its high 32 bits.
3. The value previously written to G1, shifted right by 23.

Additional calls produce an index-like result. Its four-times-scaled value becomes a new base. The routine reads a 32-bit word at that base plus 116 and writes the low byte at that base plus one, then passes the base to another call.

After further calls produce another index-like result, the routine retains its four-times-scaled value for later use. It nevertheless repeats the word-to-byte copy using the **preceding base**, not this newly produced value.

The repeated copy is a new word read followed by a new byte write. Intervening calls can change the source word; reusing the earlier word would not preserve the visible behavior.

A following call receives four explicit arguments: the retained register output shifted left by 12, the newly scaled value twice, and the unscaled new result shifted left by 18.

### 5. Saved word propagation and linking stores

Following another result-forwarding sequence, calls produce a further index-like result. The routine scales it by four, reads a 32-bit word at that base plus 116, saves the full word, and writes its low byte at that base plus one.

It passes the base to a call. Further calls produce another result, and the routine writes the saved full word at sixteen times that result plus 20. This destination uses a stride of 16, not four.

A subsequent call receives a value derived from the earlier retained scaled value: logical right shift by two, followed by left shift by 16. Under 32-bit bit-vector arithmetic, this is not an unrestricted multiplication of the original unscaled value; earlier scaling can already have discarded upper bits.

After additional calls and forwarding, another index-like result is used to write the same saved word at four times that result plus 20.

Further calls produce a value that is shifted left by two. That shifted value is written as a 32-bit word at the address obtained by clearing the low two bits of the earlier retained scaled value and adding 20. The shifted value is then passed twice to a call.

### 6. Zero store, paired-result stores, and global-based read

More calls produce an index-like result. The routine writes a 32-bit zero at four times that result plus 20, then passes the scaled result onward.

A later call supplies a 64-bit result. Its low half is shifted left by two; its high half supplies an index-like value. The routine writes the shifted low half at four times the high half plus 20.

It then reads the separate global location identified as **G2**, saving its value as an address base. This read precedes a call receiving four explicit arguments: the shifted low half, the high half, and the shifted low half twice more.

After further calls produce another index-like result, the routine writes that same shifted low-half value at four times the new result plus 20. It next reads a 32-bit word at the saved G2-derived address plus 20.

The G2 location is not reread for this access. However, the word reached through its saved value is read only after the intervening calls.

### 7. Final indirect byte updates

Further calls supply another 64-bit result. Both halves are retained.

The routine reads a byte at one plus the word saved in phase 5 shifted right by 23. It then writes the low byte of the word read through G2 to that byte’s value plus 17.

The next call receives the high half of the latest 64-bit result three times, followed by its low half shifted left by two.

After more calls, the routine performs another byte-directed write:

- Take the low 30 bits of that retained low half.
- Shift right by 21 and add one to obtain a byte-read address.
- Read the unsigned byte there.
- Write the low eight bits of the G2-derived word shifted right by 22 to the byte’s value plus 17.

The byte-read address is between 1 and 512. Both byte-directed destinations remain between 17 and 272.

Additional calls receive one scaled result, then a later scaled result twice.

### 8. Terminal writes and zero-address call

Near the end, a no-explicit-argument call returns a 32-bit value that is forwarded to another call. The next call produces an 8-bit result.

The routine then performs these explicit effects in order:

1. Write zero through a pointer supplied as an additional call output.
2. Form a 32-bit value whose low byte is the 8-bit call result and whose upper 24 bits come from the separate three-byte global datum associated with address 9; write that value to G1.
3. Write a 16-bit zero at the address obtained by retaining the low 30 bits of the saved low half from phase 7 and shifting right by seven.
4. Attempt F-000000000003 at address zero with three explicit zero arguments.

The halfword destination ranges from zero through 8,388,607 and need not be aligned. There is no explicit validation before this store or the final call.

The return following F-000000000003 is reachable only if that call returns.

## Side effects

All direct writes described above are unconditional along the displayed straight-line path, but reaching them depends on earlier accesses and calls completing.

The routine provides no explicit:

- Bounds, null, or alignment checks.
- Error-code handling or success indicator.
- Rollback after a partial update.
- Allocation, release, reference-count adjustment, or ownership transfer.
- Synchronization or atomic transaction boundary.

Absence of explicit allocation or release does not establish that the dependencies perform neither. Likewise, callees cannot be assumed to preserve G1, G2, low-address memory, or any destination used by this routine.

Overlapping addresses are significant. A byte write can change a later byte-derived address or part of a later word read. The three-byte global datum used in the final G1 composition must not be assumed unchanged by earlier calls or overlapping stores.

An invalid access or nonreturning call can leave any earlier writes visible. Failure behavior depends on the execution environment; the body specifies no recovery path.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Each assumes execution reaches the relevant operation and all stated accesses are supported.

1. **Third-argument extraction.** A third argument of zero produces a stored extracted value of zero and an initial byte-read address of 1. A third argument of hexadecimal FFFFFFFF produces an extracted value of 511 and a byte-read address of 512.

2. **Ten-bit extraction narrowed to a byte.** If the word read in phase 2 is hexadecimal FFFFFFFF, shifting right by 22 produces 1023. The byte written through the initial byte-directed destination is 255, not a preserved ten-bit quantity.

3. **Word-to-byte truncation.** If a word read at a base plus 116 is hexadecimal 123456AB, the write at that base plus one stores hexadecimal AB. The later propagation described in phase 5 retains the full word when it explicitly saves and stores that word.

4. **Distinct strides.** Given a returned index value of three, the stride-16 destination in phase 5 is address 68. A stride-four destination with the same numerical index is address 32. These destinations are not interchangeable.

5. **Fresh reads after calls.** If an intervening dependency changes the word at the repeated-copy base plus 116, the second copy uses the changed word. It cannot reuse the value from the first copy.

6. **Final G1 composition.** If the final 8-bit result is hexadecimal 7E and the three-byte datum has value hexadecimal 123456, the composed 32-bit value is hexadecimal 1234567E. This example specifies numeric composition, not memory byte order.

7. **Partial completion.** If the final halfword store fails, earlier writes—including the final G1 write—may already have occurred. The zero-address call is not reached along that failing execution.
