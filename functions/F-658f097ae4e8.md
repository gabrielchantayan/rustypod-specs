# F-658f097ae4e8

## Purpose

F-658f097ae4e8 partitions a zero-terminated byte sequence into two separately terminated outputs, using three externally configured separator bytes.

For stable, non-overlapping storage and representable lengths, its principal behavior is:

- Find the last occurrence of any configured separator.
- Place the bytes after that occurrence in the second output.
- Place the preceding portion in the first output, including the final separator when exactly one separator occurrence was counted, but excluding it when more than one occurrence was counted.
- If no separator occurs, produce an empty first output and copy the entire input to the second output.
- Add an independent integer argument to an externally referenced counter before examining the input.
- Return the four-byte value 1 after completing both outputs.

The asymmetric treatment of one versus multiple separator occurrences is established behavior. An interpretation such as splitting a pathname is only inferred intent; neither particular separator values nor a pathname-specific contract is established.

## Behavior

### 1. Capture separator addresses and adjust the counter

Before scanning the input, the function captures the addresses used for the third and second separator bytes, in that order. These are captured addresses, not snapshots of the separator byte values.

It then reads the externally referenced counter, adds the third argument, and writes the result back to that counter object.

Consequences:

- The counter adjustment occurs even for an empty input.
- The adjustment is not based on the number of bytes copied or separators found.
- The adjustment precedes every input scan read.
- If the counter aliases input or separator storage, this write can affect subsequent scanning.
- If the counter aliases the global references for the second or third separators, those separator addresses have already been captured. No equivalent early capture of the first separator address is shown.

The exact counter access width, conversion rules, overflow behavior, and atomicity remain undocumented.

### 2. Scan the input without writing output

The function scans input positions in ascending order, beginning at offset zero. At each position it reads one byte. A zero byte ends the scan immediately and is not classified as a separator.

For each nonzero byte, separator classification uses ordered, short-circuit comparisons:

1. Read and compare the first configured separator byte.
2. Only if that comparison fails, read and compare the second separator byte through its previously captured address.
3. Only if both comparisons fail, read and compare the third separator byte through its previously captured address.

A match against any one separator makes the first classification successful.

On first-classification success, the function records the offset immediately after the current input byte as the latest split position. It then repeats separator classification against the same already-read input byte, using the same comparison order and short-circuit rules. Only a successful second classification increments the separator-occurrence count.

The distinction is observable in the access sequence:

- A successful first classification updates the split position.
- It does not by itself increment the occurrence count.
- The second classification rereads separator values.
- The input byte being classified is not reread for that second classification.
- A failed first classification causes no second classification.

With stable separator state, both classifications agree. In that ordinary case, the recorded split position is immediately after the last matching byte, and the count equals the number of matching input positions.

No output bytes are written during this scan.

### 3. Determine the first output length

The scan starts with a split position of zero and an occurrence count of zero.

After scanning, the first output receives:

- The number of bytes indicated by the split position, if the occurrence count is zero or one.
- One fewer byte than the split position, if the occurrence count is greater than one.

For stable state and ordinary representable lengths, let:

- \(L\) be the input length before its terminating zero;
- \(N\) be the number of separator-matching input positions;
- \(P\) be zero when no separator matches, or the offset immediately after the last separator otherwise.

Then the first output length is:

\[
A = P - \begin{cases}
1 & N > 1 \\
0 & N \leq 1
\end{cases}
\]

This is not a general “remove all trailing separators” operation. It omits exactly the last matched separator when the count exceeds one, while retaining earlier bytes, including earlier separators.

### 4. Copy the first output

The function copies input bytes beginning at offset zero to the first output, in increasing offset order, for the selected first-output length.

Each iteration reads a source byte and writes a destination byte. This phase does not stop at a zero byte encountered during copying; its bound comes from the earlier scan.

The first output is not yet terminated at the end of this phase.

### 5. Copy and terminate the second output

The second output starts from input offset \(P\), regardless of whether the first output omitted the last separator.

The function examines successive source bytes beginning at that offset:

- A zero byte ends the suffix copy.
- Otherwise, the source byte is read for assignment, written to the current second-output position, and both positions advance.

The loop condition and assignment contain separate source reads. A contract involving changing or side-effectful storage cannot assume a single read per copied suffix byte.

After the suffix loop ends, the function writes a zero byte to the second output’s current position.

### 6. Terminate the first output and return

Only after terminating the second output does the function write a zero byte at the end of the first output.

It then returns 1.

For stable, disjoint buffers, the second output length is \(L-P\). Required capacities are therefore at least:

- First output: \(A+1\) bytes.
- Second output: \(L-P+1\) bytes.

These formulas describe the ordinary stable-storage case, not a guarantee for overlapping or externally changing storage.

## Side effects

### Established ordering

The source establishes this sequence:

1. Capture the third separator address.
2. Capture the second separator address.
3. Read, adjust, and write the counter.
4. Scan the input and classify separator occurrences.
5. Copy the first-output payload.
6. Copy the second-output payload.
7. Write the second-output terminator.
8. Write the first-output terminator.
9. Return 1.

No earlier output initialization is shown. A failure after the counter write can therefore leave the counter changed and outputs untouched or partially written.

### Aliasing and overlap

No overlap detection or protective buffering is shown.

The scan completes before output payload copying, but copying reads the input again. Consequently, overlap can change the bytes ultimately produced:

- First-output writes can modify bytes later read during that same prefix copy.
- First-output writes can modify the suffix before the suffix copy begins.
- Second-output writes can modify later suffix bytes or its terminator.
- The final first-output terminator can overwrite an already-produced second-output byte if the destinations overlap.

Thus, the simple partition formulas require noninterfering storage. The routine is not established as an overlap-safe copy operation.

Output storage may also alias global state. Such writes are not prevented, although the separator scan has already completed when output copying begins.

### Ownership and resource use

No allocation, deallocation, ownership transfer, or retention of an output address is shown. The caller supplies the storage used by this invocation.

The function contains no explicit synchronization. Atomicity and behavior under concurrent mutation are not established.

## Acceptance examples

The examples below are conditional acceptance cases, not executed tests. Unless stated otherwise, they assume stable separator bytes `/`, `\`, and `:`, distinct valid buffers, sufficient capacities, representable arithmetic, and a counter adjustment valid for the counter object.

Displayed output strings exclude their terminating zero bytes.

| Input | Counted separator positions | First output | Second output |
|---|---:|---|---|
| Empty string | 0 | Empty string | Empty string |
| `leaf` | 0 | Empty string | `leaf` |
| `/leaf` | 1 | `/` | `leaf` |
| `dir/leaf` | 1 | `dir/` | `leaf` |
| `dir/` | 1 | `dir/` | Empty string |
| `a/b/c` | 2 | `a/b` | `c` |
| `a//b` | 2 | `a/` | `b` |
| `//` | 2 | `/` | Empty string |
| `a:b/c` | 2 | `a:b` | `c` |

Additional acceptance conditions:

- **Repeated configuration values:** If all three separator bytes are `/`, input `a/b` has one counted separator position. The outputs are `a/` and `b`; it is not counted three times.
- **Zero-valued separator:** A separator configured as zero does not match the input terminator. Scanning stops before classifying that byte.
- **Embedded zero:** Storage containing the bytes for `a`, zero, `/`, `b`, zero is treated as input `a`. Bytes beyond the first zero are not part of the scan or ordinary suffix copy.
- **High-bit bytes:** Matching is byte-based, with no case folding, locale processing, or text decoding. A high-bit byte that does not equal any configured separator is ordinary input data.
- **Counter independence:** Empty input still triggers the counter adjustment. A negative adjustment is not explicitly rejected; its exact effect depends on the undocumented counter type and arithmetic.
- **Termination order:** With an empty input and independent destinations, the second destination receives its zero byte before the first destination does.

## Uncertainties

### Documented-only representation limits

The integer-shaped input address and the loop variables are represented as 32-bit values in the supplied source view. The exact ABI and address-conversion semantics are not provided.

The first-output bound subtracts an unsigned zero-or-one quantity from the recorded split position and converts the result to signed integer form for the loop comparison. For ordinary nonnegative, representable lengths, this gives the behavior described above.

Behavior at integer limits is not established:

- Scan-index advancement can exceed the signed range.
- Recording the offset after a separator can exceed that range.
- The separator-occurrence count can exceed that range.
- Unsigned subtraction followed by signed conversion can produce target-dependent results outside the ordinary domain.
- Address arithmetic can become invalid.

No wrapping, saturation, rejection, or large-input safety guarantee is inferred.

### Mutable external state

The repeated classification reads are established. Whether an actual environment permits separator values or references to change between those reads is not established. Concurrent or side-effectful-memory scenarios are documented only; they are not assigned invented synchronization semantics.

Similarly, the exact effects of counter aliasing depend on the unavailable counter type, object layout, and surrounding memory model.

### Inferred intent

The output structure resembles a directory/name split. That interpretation does not establish a separator set, filesystem semantics, root handling, normalization, encoding, or validation. The byte-level behavior remains the contract.
