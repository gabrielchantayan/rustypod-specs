# F-21e174dfd3c0

## Purpose

F-21e174dfd3c0 selects an entry from a caller-supplied, fixed-stride table by comparing a normalized query against signed 32-bit thresholds.

For a stable table with thresholds in nondecreasing signed order, the selected entry is the last entry whose threshold is less than or equal to the normalized query. A query below the first threshold produces a zero return value. Equality does not stop the search, so equal thresholds are passed over until a strictly greater threshold or the end of the table is reached.

This ordered-table interpretation is inferred intent. The established behavior is a forward scan that stops at the first strictly greater threshold. The function neither checks ordering nor searches beyond that stopping point.

The function also has an established empty-table edge case: a zero entry count takes the end-of-table path, rather than the below-first-threshold path. Under 32-bit modular address arithmetic, that path returns the supplied base address and optionally writes an index bit pattern of `0xffffffff`.

| Table base | Address of the table header and entries | Address carried in a 32-bit integer representation |
| Query | Value to compare with entry thresholds | Signed 32-bit integer |
| Flags | Controls query adjustment | Unsigned 32-bit value |
| Optional index destination | Receives the selected index on applicable return paths | Null, or a writable location for one 32-bit integer |

### Table layout

Offsets below are byte offsets from the table base.

| Offset | Width | Meaning established by the supplied representation |
|---|---:|---|
| 0 through 3 | 4 bytes | Not accessed by this function |
| 4 through 7 | 4 bytes | Unsigned entry count |
| 8 plus 8 times the entry index | 4 bytes | First word of the entry; not read by this function |
| 12 plus 8 times the entry index | 4 bytes | Signed threshold used for comparison |

Entries therefore have an eight-byte stride. A successful selection returns the address of the entry’s first word, not the address of its threshold.

The contents and meaning of the first entry word are unknown. This function does not establish that it is a pointer, identifier, payload, or independently valid object.

### Outputs

The return value is an address encoded in the integer return type, or zero on the explicit below-first-threshold path.

When an entry with index \(j\) is selected:

- The return value is the table base plus \(8 + 8j\) bytes.
- If the optional index destination is non-null, it receives the 32-bit representation of \(j\).
- The index write occurs before the return.

When the first entry’s threshold is strictly greater than the normalized query:

- The return value is zero.
- The optional index destination is not written.

The return value is not accompanied by a status code that distinguishes all possible outcomes. In particular, an address computation that produces zero would be indistinguishable from the explicit zero-return path by return value alone.

### Preconditions for ordinary valid-table use

For ordinary, well-defined table selection, the caller must provide:

- A readable entry-count word at offset 4.
- Readable threshold words for every entry the scan reaches.
- A non-null index destination that is writable for four bytes, if an index result is requested.
- Address and size values that do not cause unintended address wraparound.
- Stable table contents during the call, if deterministic selection against a single table state is required.

A nonzero count is necessary if the caller requires the result to denote an actual entry. Nondecreasing thresholds are necessary for the “last threshold less than or equal to the query” interpretation, but not for the function’s mechanical first-greater scan.

The function does not validate these preconditions.

## Behavior

### Query normalization

Normalization occurs before any table access.

First, a query of zero is replaced with one. No other query value is changed by this step.

Next, the function examines only bit `0x80000000` of the flags argument:

- If that bit is clear, no further adjustment occurs.
- If that bit is set, decimal 50 is added to the query after zero replacement.
- All other flag bits are ignored.

The ordering matters. A query of zero with the high flag bit set becomes 51, not 50. A query of −50 with that bit set becomes zero; the function does not then replace that resulting zero with one.

The addition is represented as a signed integer addition. For inputs where adding 50 exceeds the signed 32-bit range, the supplied material does not establish a portable outcome. Such cases are `documented_only`; wrapping, trapping, or another platform-specific outcome must not be assumed.

### Forward scan

The scan starts at entry index zero and advances by one only after the current threshold comparison fails to find a stopping point.

Each iteration has the following source-visible access order:

1. Read the unsigned count at offset 4 and retain that value for a possible end-of-table result.
2. Read the count at offset 4 again for the bounds comparison.
3. If the second count is less than or equal to the current unsigned index, take the end-of-table path without reading a threshold.
4. Otherwise, read the signed threshold at offset \(12 + 8i\), where \(i\) is the current index.
5. If the normalized query is strictly less than that threshold, stop before the current entry.
6. Otherwise, advance to the next index.

The comparison between the query and a threshold is signed. The bounds comparison between the index and the count is unsigned.

The two count reads are distinct in the supplied representation. A contract for concurrently modified or device-backed storage must not collapse them into a guaranteed single snapshot. Conversely, the supplied representation does not independently prove the number or ordering of physical memory transactions in an optimized executable.

### Stopping at a strictly greater threshold

If the first strictly greater threshold occurs at index zero, the function returns zero immediately. It does not write the optional index destination.

If the first strictly greater threshold occurs at a positive index \(i\), the selected index is \(i - 1\). The function optionally writes that index, then returns the address of the preceding entry.

The current entry’s threshold is read before this result is produced. No later threshold is read.

Equality does not trigger this path. Consequently, in a nondecreasing table containing repeated equal thresholds, a query equal to that threshold advances past every equal entry until a larger threshold or the table boundary is encountered.

### Reaching the table boundary

If the bounds comparison ends the scan, the result uses the count retained from the first count read of that iteration.

For stable storage with a positive count \(n\):

- The selected index is \(n - 1\).
- The optional index destination receives \(n - 1\).
- The returned address is the start of entry \(n - 1\).
- No threshold at index \(n\) is read.

The function does not obtain a new count after deciding to return.

If the count changes between the two reads, the retained count and the count used to decide termination can differ. The result then follows the retained count, not necessarily the second count or the current scan index. No consistency repair or retry is present.

### Empty-table behavior

With a stable count of zero, the first iteration terminates before any threshold read.

The retained unsigned count is zero, so subtracting one produces the 32-bit unsigned value `0xffffffff`. If the index destination is present, that bit pattern is written there. In the usual signed 32-bit interpretation, it represents −1.

Using 32-bit modular address arithmetic, the return-address calculation reduces to the original table base: subtracting one entry, multiplying by eight, and then adding the eight-byte header offset cancel modulo \(2^{32}\).

This is not an explicit “empty table returns the base” branch, nor is it a validated entry selection. Exact portability of the integer-to-address interpretation remains `documented_only`.

### Unordered thresholds

The function does not compute a global maximum qualifying threshold.

For an unordered table, a strictly greater threshold stops the scan even if later entries would have thresholds less than or equal to the query. Entries after that first stopping threshold have no influence on the result.

## Side effects

The only explicit memory write is the optional four-byte index result.

That write occurs on:

- Selection of the entry preceding a strictly greater threshold at a positive index.
- End-of-table termination, including the zero-count case.

It does not occur when the first threshold is strictly greater than the query.

No table field is explicitly modified. However, the caller can supply an index destination that aliases the table. In that case, the result write modifies the overlapping table bytes. All table reads used for the decision precede that write, and the function performs no subsequent table read before returning.

The function performs no explicit allocation, deallocation, reference-count operation, or ownership transfer. A returned entry address refers into caller-supplied storage; its validity and lifetime depend on that storage remaining valid.

There are no explicit global accesses, external calls, logging operations, or error-reporting side effects in the supplied body.

Invalid memory, insufficient storage, and invalid alignment are not detected or converted into a defined error return. Their execution consequences depend on the surrounding platform.

Additional boundary and normalization examples:

- **Zero replacement:** With thresholds 0, 1, and 2, an input query of zero and a clear high flag bit is treated as one. Entry 1 is selected.
- **Adjustment after replacement:** With thresholds 1, 50, 51, and 52, an input query of zero and a set high flag bit selects entry 2, whose threshold is 51.
- **No second replacement:** With thresholds 0 and 1, an input query of −50 and a set high flag bit becomes zero and selects entry 0.
- **Ignored flag bits:** Changing any flags except `0x80000000` leaves normalization and selection unchanged.
- **Optional output omitted:** Passing a null index destination does not change which address is returned and causes no index write.
- **Failure preserves output:** If the first threshold is greater than the normalized query and the index destination initially contains 77, it still contains 77 after the zero return.
- **Single entry:** A one-entry table returns zero below its threshold and that entry’s address at or above its threshold.
- **Empty table:** With count zero, no threshold is read. Under the stated modular arithmetic conditions, the return is the table base and a supplied index destination receives `0xffffffff`.
- **Changing count:** If the first count read in an iteration yields 5, the second yields 0, and the current index is zero, termination uses retained count 5. Subject to address validity, it returns entry 4’s computed address and writes index 4 without reading a threshold in that iteration.

These are contract examples derived from static evidence, not records of executed tests.
