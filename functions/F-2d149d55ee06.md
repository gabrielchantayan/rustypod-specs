# F-2d149d55ee06

The contract’s numerical examples use that interpretation; confirmation of the target ABI and all shared-object declarations remains **documented_only**.

Under the 32-bit unsigned interpretation:

- Complement affects all 32 bits.

### Input capture and presence gates

**Selector 3** first replaces the active quantity with the scale multiplied by the fourth input. It then sets the predicate from whether the first input is nonzero and reads the input continuation. It subsequently saves the second, third, first, and fifth inputs into their working roles.

It does not reset the transformed extent, transformed second quantity, candidate, or retained result. Repeated input capture can therefore coexist with transformed values retained from earlier iterations.

**Selector 11** uses the existing predicate without recomputing it. It reads the primary gate base once to form the destination adjusted by minus five, then reads that base again for the unchanged destination. Predicate zero selects the first; predicate one selects the second. The active quantity and candidate are unchanged.

**Selector 8 and every unmatched selector** first replace the predicate with whether the saved third input is nonzero. They then read the secondary-presence gate base for the plus-two destination and read it again for the unchanged destination. The active quantity and candidate remain unchanged.

An unmatched selector is not an error return. It follows this ordinary presence-gate transition and may do so repeatedly.

### Extent transformation

**Selector 6** performs these transformations:

- A fresh multiplier read times the incoming active quantity becomes the transformed extent.
- A separate, later multiplier read times the current second-input working quantity becomes the transformed second quantity.
- Two further multiplier reads contribute to a factor: one is XORed with the signed representation of the other shifted right by 27.
- The active quantity becomes the OR of the transformed extent and the incoming active quantity multiplied by that factor.

The two reads within the factor are distinct occurrences. Their relative evaluation order within that expression is not established.

The new active quantity’s bit 31 becomes the predicate. Only after extracting that predicate does the selector read the extent gate base for the plus-one destination, then read it again for the unchanged destination.

After those reads, the active quantity is copied to the candidate. Predicate zero selects the adjusted first read; predicate one selects the unchanged second read.

This is a predicate over transformed representations, not an established validation of original input signs, bounds, or lengths.

### Primary dependency operation

**Selector 7** first replaces the second-input working quantity with a fresh multiplier read times the saved fifth input. This replacement precedes the call and persists afterward.

F-b09db3398a5a receives five arguments, in order:

1. Saved first input.
2. Transformed second quantity.
3. Newly replaced fifth-input-derived working quantity.
4. Literal zero.
5. Transformed extent.

The return contributes its word representation to subsequent products. The multiplier cached at dispatch entry—not a new post-call multiplier read—is used in both post-call transformations.

The established post-call order is:

1. Read the scale used to replace the transformed extent with the cached multiplier times that scale times the dependency result.
2. Read the primary-result gate base to form the destination adjusted by minus two.
3. Evaluate the complemented expression using two further scale reads.
4. Extract the predicate from bit 31.
5. Read the primary-result gate base again for the unchanged destination.
6. Copy the active quantity to the candidate and select the next state.

The complemented expression produces the active quantity as the complement of the OR of:

- The newly transformed extent.
- The dependency result multiplied by a further scale read and by the cached multiplier XOR another scale read shifted right by 27.

The two scale occurrences in that expression are separate reads; their relative evaluation order is not established. The first gate-base read is nevertheless established to occur before both, and the second occurs after predicate extraction.

Predicate zero selects the first gate read minus two. Predicate one selects the second gate read unchanged. A dependency that changes the multiplier does not change the cached multiplier, but changes to scale or gate configuration can affect subsequent reads.

### Secondary sign gate and operation

### Candidate loading, capture, and termination

**Selectors 1, 9, 10, and 13** read the fallback value into the candidate and continue through the captured common continuation.

**Selector 4** does the same using the alternate value.

These selectors do not update the active quantity or retained result.

**Selector 0** reads a fresh multiplier and replaces the active quantity with that multiplier times the candidate. It then reads the result continuation, and afterward copies the active quantity to the retained result.

- Candidate changes after the final capture do not change the return.
- Repeated captures replace, rather than accumulate into, the retained result.
- Configuration can produce repeated dependency calls or indefinite dispatch without a return.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations. They assume the stated selector sequence is produced, required arithmetic is defined, and the 32-bit model applies where numerical values are given.

1. **Immediate termination.** If the first selector is 5, the return is zero and neither dependency executes. The iteration-entry multiplier and selector-offset reads still occur.

The selected destination is the **second** primary-result gate-base read, unchanged; the first read still occurs.

6. **Independent gate reads.** At selector 7, suppose the first primary-result gate-base read yields 40 and the second yields 90. Predicate zero selects 38; predicate one selects 90. The destinations are not required to differ by two.

7. **Secondary gate interleaving.** At selector 12, suppose the first gate-base read yields 100, the subsequent sign-factor computation produces predicate one, and the second gate-base read yields 200. The selected destination is 200. If that computation instead produces predicate zero, the selected destination is 102, while the second read still occurs.

9. **Secondary result scaling.** If F-ec4c12102158 returns 5, the post-call multiplier read is 2, and both scale reads are 3, the candidate becomes 90. A subsequent capture with multiplier 2 yields retained result 180.

10. **Uncaptured inputs.** If selector 2 executes before selector 3 and no intervening selector has changed its argument fields, F-ec4c12102158 receives three zeros regardless of the supplied inputs.

11. **Unmatched selection.** An unmatched selector tests the saved third input and performs both secondary-presence gate-base reads. It does not implicitly return an error.

12. **Nontermination.** If configuration repeatedly routes a fallback-loading selector through the captured common continuation back to itself, the function can continue without returning or calling either dependency. No visible iteration limit interrupts it.
