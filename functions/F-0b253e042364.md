### F-D41 arguments

F-D41 receives these three explicit arguments, in order:

1. The low six bits of \(W(4 \times \text{result 7})\), shifted left by 14 positions.
2. \(4 \times \text{result 8}\).
3. Result 7 shifted left by 30 positions.

Under the 32-bit interpretation, the first argument depends only on result 7’s low four bits. Its bits below position 16 are zero. Applying the six-bit mask directly to unscaled result 7 would produce a different result.

Under the same interpretation, the third argument places result 7’s low two bits in positions 30 and 31 and discards its other bits.

### First byte operation

The read address is:

\[
A = W(2^{28} \times \text{result 7} + 1).
\]

The operation reads one unsigned byte from \(A\). If that byte’s numeric value is \(b_1\), the operation writes the low eight bits of \(W(4 \times \text{result 10})\) to address:

\[
b_1 + 17.
\]

The byte is used as a numeric address component. There is no established enclosing object or allocation.

### Second byte operation

After F-D51 through F-D57, the body independently reads another unsigned byte from \(A\). It does not reuse the first byte-read value.

If this second byte is \(b_2\), the operation:

- Retains \(b_2\) for the second explicit argument to F-D63.
- Writes one byte at address \(b_2 + 17\).
- Derives the stored byte by masking result 10 with hexadecimal `3fffffff`, logically shifting right by 20 positions, and retaining the low eight bits.

The second stored byte is therefore result 10’s bits 20 through 27. Bits 28 and 29 survive the mask and shift but not the byte-width store.

### Byte-address separation

Under the stated 32-bit interpretation, the read address belongs to the set:

\[
A = 1 + k \times 2^{28}, \qquad 0 \leq k \leq 15.
\]

Each write destination is between 17 and 272 inclusive because each unsigned read byte is between 0 and 255.

These sets are disjoint. Neither direct byte write targets the byte-read address. In particular, the read address is either 1 or at least \(2^{28}+1\), neither of which lies in the byte-write destination range.

Two separate reads remain required because intervening dependencies may modify the memory at \(A\). The direct first byte write is not a justification for such a modification. The two byte-write destinations may equal each other if the two reads return the same byte.

### Independent byte reads

Suppose result 7 is zero and result 10 is hexadecimal `abcdefff`.

- Both byte reads address location 1.
- If the first read returns 7, the first byte write stores hexadecimal `fc` at address 24.
- If the second read returns 9 after the intervening dependencies, the second byte write stores hexadecimal `bc` at address 26.
- F-D63 receives 9 as its second explicit argument.

### Byte-address boundaries

If result 7’s low four bits are zero, the read address is 1. If they are fifteen, the read address is hexadecimal `f0000001`.

For either read address:

- A read byte of zero selects write address 17.
- A read byte of 255 selects write address 272.

Neither endpoint, nor any destination between them, equals a possible byte-read address.

This illustrates the six-bit contribution retained by that interpretation. It does not resolve the semantics of every signed left shift in the supplied representation.
