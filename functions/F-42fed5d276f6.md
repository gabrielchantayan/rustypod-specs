# F-42fed5d276f6

## Purpose

The supplied static representation describes an ordered sequence of indirect dependency calls, computed-address memory reads, and byte or 32-bit memory writes. It does not establish a higher-level service such as allocation, serialization, object construction, or device initialization.

The visible sequence repeatedly stores scaled dependency results at computed addresses, updates byte-selected locations, clears several locations, and forwards selected values to unresolved dependencies. Its final visible operation is a truncation associated with an invalid-instruction warning, not an ordinary return.

This contract distinguishes:

- **Established static evidence:** operations and ordering visible in the supplied representation.
- **Inferred intent:** possible interpretations that are not required behavior.
- **documented_only:** matters the representation cannot resolve.

All behavioral descriptions are conditional on execution reaching the relevant operation, preceding dependency calls returning, and memory accesses completing. The representation itself warns that control-flow recovery encountered invalid instruction data. Consequently, this is a contract for the represented execution trace, not proof that the original executable follows that trace.

## Side effects

### Memory layout and aliasing

The representation does not establish a conventional object layout. Offsets `0x14`, `0x24`, `0x44`, and `0x74` recur, but their bases are independently computed and sometimes use different scaling factors.

Byte-selected writes use an unsigned eight-bit selector as the entire base. Consequently:

- Selector-plus-`0x11` addresses range from `0x11` through `0x110`.
- Selector-plus-`0x44` addresses range from `0x44` through `0x143`.
- Some four-byte accesses may be unaligned.
- Computed addresses may alias each other or absolute address `0x24`.

The four explicit writes of zero to absolute address `0x24` are separate events. They cannot be collapsed into a single final-state requirement: intervening dependencies may observe or modify the location.

### Ownership and state

No allocation, release, ownership transfer, or lifetime guarantee is established. Dependency results used as address components are not thereby proven to be valid pointers, allocated objects, or owned memory.

Dependencies may mutate memory or global state. Retained scalar values remain the values already obtained in the represented trace; later memory reads observe memory again and may differ.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Input reduction boundary.** Fourth arguments zero through seven all produce reduced input zero. Their direct reduced-input calculations coincide. This does not establish identical total behavior because unresolved dependencies may consume unrecovered state.

2. **Discarded low input bits.** Fourth arguments eight and fifteen both produce reduced input one. The early scaled store therefore targets `0x200014` and writes `0x00080000`, assuming execution reaches it without address reinterpretation.

3. **Selector changes between reads.** If the first read at reduced input plus one yields five and the second yields nine, the first selected byte write targets `0x16`; the next targets `0x1a`. Later retained-selector calculations use nine, not five.

4. **Byte truncation.** If the initial payload is `0x00100040`, its fourfold value is `0x00400100`. The first payload-byte write stores zero; its upper-fragment byte write stores one.

5. **Distinct scaled addresses.** If step 13’s result is three, its 32-bit store targets `0x44` and writes twelve. Its following 32-bit read targets `0x20`, not `0x44`.

6. **Upper-fragment truncation.** A payload of `0x3ff00000` has upper fragment `0x3ff`; a byte write stores `0xff`. The fragment is not guaranteed to fit in eight bits.

7. **Repeated clearing remains observable.** If a dependency changes absolute address `0x24` between two explicit zero stores, the later store must still occur. Final-state equivalence alone is insufficient.

8. **64-bit result use.** In step 24, the low half supplies the first dependency argument, while the retained high half supplies the subsequent zero-store address. The additional register-derived output used afterward is a separate dependency output.

9. **Final read independence.** The last selector read uses eight times the last payload plus one, not final selector base plus one. Equal addresses require particular values; they are not a general invariant.
