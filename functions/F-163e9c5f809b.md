# F-163e9c5f809b

## Purpose

F-163e9c5f809b performs an ordered state transition on an input object and a derived result object. It writes dispatch-related fields, checks two input gates, invokes dependent operations, conditionally processes associated state and a collection, and either returns the derived pointer or reaches a designated non-returning dependency.

**Established static behavior:** the body specifies field accesses, address transformations, conditional calls, indirect dispatches, and return construction. The intermediate and final dispatch writes each obtain their value from a distinct external 32-bit location when that stage is reached. Neither value is captured at function entry.

**Inferred intent:** the dispatch transitions and sequence of operations resemble composed teardown. This does not establish destruction, deallocation, ownership transfer, registration removal, or reference-count semantics.

The returned pointer need not equal the input pointer. Its derivation depends on opaque dependency results.

## Behavior

### 1. Entry writes and gate checks

The function first reads the initial dispatch source and retains that 32-bit value. It then reads the same external location again and writes the second value to input `+0x00`. It writes the retained first value plus `0xA0` to input `+0x18`.

The two external reads are distinct. The two values need not match if the location changes between reads.

Next, the function reads input `+0x1C`:

- Nonzero: call F-feee9156a257, designated non-returning.
- Zero: continue to read input `+0xB8`.

If input `+0xB8` is nonzero, call F-54385ab29a1f and, if it returns, F-feee9156a257. The normal processing chain is reached only when both gates are zero.

Both input writes precede either gate check. No rollback is shown.

### 2. Initial dependent operations

With both gates zero, the function performs these operations in order:

1. Read input `+0xC0` and pass that word to F-936a8728139d.
2. Read input `+0xC0` again and pass that word to F-a3740f6ffd69.
3. Call F-b7af80e829ec to obtain an object pointer.
4. Read that object's dispatch-table pointer and invoke the entry at table byte offset `+0x04`, explicitly passing the obtained object and the address of input `+0x18`.

The first dependency may change input `+0xC0`; the second call uses the later read, not a saved copy.

The returned object, its dispatch table, and the selected entry are used without explicit validation.

### 3. Address transformation

Four calls to F-03144a4f049b form the first chain:

- The first receives the address of input `+0x2FC`.
- Each subsequent call receives the preceding result minus `0xB8`.

The fourth result becomes a retained reference for three calls to F-3cdbb43c2646, receiving, in order:

1. Reference minus `0x04`.
2. Reference minus `0x08`.
3. Reference minus `0x0C`.

Those three return values do not update the reference or feed subsequent arguments.

Four calls to F-289ec4311c64 form the next chain:

- The first receives the retained reference minus `0x28`.
- Each subsequent call receives the preceding result minus `0x08`.

The result object is the fourth result of this chain minus `0x94`. No equality with the original input is required or established.

### 4. Intermediate dispatch write and subsequent calls

After all address-transformation calls, the function reads the **intermediate dispatch source** and writes that 32-bit value to result `+0x00`.

This is a stage-local external read. Any earlier dependency may have changed its source location. The value is not an entry snapshot, and the body does not establish an immutable dispatch constant.

The function then:

1. Calls F-408b56b8b7c8 with the result object.
2. Calls F-3fdd14ecd250.
3. Reads the returned object's `+0x1C` word.
4. Calls F-77781c8e0ff9 with that word, the value read from the separate registration argument source, and the result object.

The supplied representation does not establish the relative evaluation order of the two argument-source reads in the last call. Both supply that invocation, after the getter returns.

Only afterward does the function read result `+0x0C`.

### 5. Optional associated record

Otherwise, retain the pointer as the **associated record**, and save its 32-bit word at `+0x04` as the **saved identifier**. Both retained values remain in use across later calls.

Call F-a1a48bd3fbde with the result object.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid reached accesses and returning dependencies except where a terminal call is specified.

1. **First gate rejects.** With input `+0x1C` nonzero, both entry writes precede F-feee9156a257. The second gate and transformation chain are not reached.

2. **Second gate rejects.** With the first gate zero and the second nonzero, F-54385ab29a1f precedes F-feee9156a257. Neither input `+0xC0` call occurs.

3. **Initial source changes between reads.** If the initial source first yields `0x1000` and then `0x2000`, input `+0x00` receives `0x2000`, while input `+0x18` receives `0x10A0`.

4. **Intermediate source changes during transformation.** If an address-transformation dependency changes the intermediate source to `0x3300`, and it remains so until the scheduled read, result `+0x00` receives `0x3300` before F-408b56b8b7c8. An earlier source value is not used instead.

5. **Final source changes during associated processing.** If F-8349c252c168 changes the final source to `0x4400`, the subsequent final dispatch write uses `0x4400`. It does not reuse the intermediate write's value or an entry snapshot.

6. **Input field changes between calls.** If F-936a8728139d changes input `+0xC0`, F-a3740f6ffd69 receives the later read.

7. **No associated record or optional object.** If the relevant reads of result `+0x0C` and `+0x04` are zero, their processing is skipped. Both stage-specific dispatch-source reads and writes still occur, and the derived pointer returns.

8. **Predicate false, collection present.** A zero predicate skips only its controlled block. Collection processing, manager comparisons, the completion F-65528ded3450 call, and F-8349c252c168 remain reachable.

9. **Null collection item.** A nonzero iterator result with a zero first slot causes no item dispatch; iteration continues.

10. **Optional object cleared.** If its initial field read is nonzero but F-c719314a16bb clears it, the object dispatch is skipped and the guard is still examined.

11. **Guard without optional object.** If the initial optional-object read is zero, a nonzero guard does not trigger F-c8eefdf96f4b.
