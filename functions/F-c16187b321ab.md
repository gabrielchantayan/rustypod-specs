# F-c16187b321ab

## Purpose

F-c16187b321ab conditionally updates a 16-bit destination using a table-selected coefficient, a 16-bit source value, and an indirect transformation dependency.

Three behaviors are established:

- A coefficient of zero leaves the destination untouched by this function and invokes no dependency.
- A coefficient of 256 transforms the source once and stores the resulting 16-bit value.
- Any other coefficient transforms the existing destination, combines three masked fields of that result with corresponding source fields, transforms the combined value, and stores the resulting 16-bit value.

The field layout is consistent with RGB565 color data: five high bits, six middle bits, and five low bits. Color blending is inferred intent, not an independently established semantic requirement. The observable contract is expressed in terms of bit fields and arithmetic.

The coefficient table contains unsigned 16-bit entries. Although 0 through 256 forms a natural interpolation range, the supplied representation does not restrict entries to that range. Values above 256 take the general arithmetic path, including its 32-bit wraparound behavior.

## Interface

The function has five inputs and no explicit return value or status result.

| Input | Representation | Role |
|---|---|---|
| Selector address | Address of an unsigned 8-bit value | Selects one coefficient-table entry. |
| Coefficient-table address | Address carried in a 32-bit integer-shaped input | Base of a table of unsigned 16-bit entries, spaced two bytes apart. |
| Source address | Address of a 16-bit unsigned value | Supplies the source word on nonzero-coefficient paths. |
| Transformation target | Indirect callable address | Invoked with one integer-valued argument on nonzero-coefficient paths. |
| Destination address | Address of a 16-bit storage location | Receives the final result and, on the general path, supplies the initial destination word. |

The transformation dependency is designated **F-indirect-01** in this document. This is a local opaque designation for the supplied callable, not an independently verified dependency identity.

### Storage and layout

The selector is read as one byte. If its value is \(s\), the selected coefficient occupies the two bytes beginning at table base plus \(2s\).

Consequently:

- The selector range is 0 through 255.
- Entry starting offsets range from 0 through 510 bytes.
- A table supporting every possible selector requires 512 readable bytes.
- For a particular invocation, only the selected entry must be readable by this function.
- The table entry is an unsigned 16-bit quantity, with range 0 through 65,535.

Source and destination accesses are 16 bits wide. The supplied representation does not establish byte order or the target’s requirements for aligned 16-bit accesses.

The table-base input is an address representation, not a table length or coefficient value. Address calculation uses the represented 32-bit address arithmetic. Valid execution requires the resulting entry address to identify readable storage; no bounds checking is shown.

### Branch-specific preconditions

All paths require readable selector and selected-table-entry storage.

For a zero coefficient, this function does not dereference the source, destination, or callable inputs. Those inputs therefore need not designate usable objects for this function’s direct behavior on that path.

For a coefficient of 256, the source must be readable, the callable must be invocable, and the destination must be writable when the final store occurs.

For every other nonzero coefficient:

- The destination must be readable before the first dependency invocation.
- The source must remain readable when accessed after that invocation.
- The dependency must support both invocations.
- The destination must be writable after the second invocation returns.

These are execution preconditions, not conditions checked by the function.

## Behavior

### Selection and early exit

The function first reads the selector byte and then the selected unsigned 16-bit coefficient. That coefficient is retained for the rest of the invocation.

If the coefficient is zero, execution returns immediately. There is no direct source read, destination read, destination write, or dependency invocation.

Later modifications to the selector or table, including modifications made by the dependency on other paths, do not change the already selected coefficient.

### Coefficient equal to 256

For a coefficient of exactly 256, the function:

1. Reads the 16-bit source.
2. Invokes F-indirect-01 with that source value.
3. Uses the dependency result as a 16-bit value.
4. Stores that value at the destination address.

There is no direct read of the previous destination value.

The source value is captured before the dependency runs. If the dependency modifies source storage, that modification does not alter the argument already supplied. If it modifies destination storage and returns normally, the function’s subsequent store replaces the 16-bit value then present at the destination.

This branch does not perform the field arithmetic described below. In particular, it is not implemented as the general path with a coefficient of 256: it has a different number of calls, different input to the dependency, and different memory-read ordering.

### Other nonzero coefficients

For any nonzero coefficient other than 256, the observable sequence is:

1. Read the 16-bit destination word.
2. Invoke F-indirect-01 with that word.
3. Capture the returned value in a 32-bit unsigned representation.
4. Read the 16-bit source word.
5. Compute a new packed word from the captured dependency result, the source, and the retained coefficient.
6. Invoke F-indirect-01 with that packed word.
7. Use the second result as a 16-bit value.
8. Store it at the destination address.

The source read occurs **after** the first dependency invocation. Moving it earlier would change behavior when the dependency can modify the source or storage aliased with it.

Only three fields of the first dependency result participate in the calculation:

| Field | Mask | Bit positions |
|---|---:|---|
| High | 0xF800 | 15–11 |
| Middle | 0x07E0 | 10–5 |
| Low | 0x001F | 4–0 |

Bits above bit 15 of that returned value do not affect the packed result.

### Field arithmetic

Let:

- \(w\) be the retained unsigned 16-bit coefficient.
- \(S\) be the source word read after the first dependency invocation.
- \(T\) be the first dependency result in its 32-bit unsigned representation.
- \(m\) be one of the three masks above.

For each field, the calculation uses the masked values in their existing bit positions. It does not first shift them down to an unpositioned component value.

The field’s 32-bit product bit pattern is:

\[
P_m=\bigl(w\cdot((S\mathbin{\&}m)-(T\mathbin{\&}m))\bigr)\bmod 2^{32}.
\]

Interpret that bit pattern as a signed two’s-complement 32-bit integer \(p_m\). The field adjustment is:

\[
q_m=\operatorname{trunc}_{0}(p_m/256),
\]

where \(\operatorname{trunc}_{0}\) means truncation toward zero.

The supplied signed-shift and correction expression establishes this rounding rule: nonnegative products are shifted down by eight bits; negative products receive a correction of 255 before the arithmetic right shift. Thus, for example, a signed product of −1 gives an adjustment of zero, not −1.

The field contribution is the original transformed-destination field plus that adjustment, masked back to the field:

\[
B_m=((T\mathbin{\&}m)+q_m)\mathbin{\&}m.
\]

The argument to the second dependency invocation is the bitwise union of the three contributions. It lies between 0 and 65,535 because the masks are disjoint and cover exactly the low 16 bits.

There is no explicit saturation or clamping. Field masks discard bits outside their respective fields, including carries or borrows into adjacent fields.

### Width and overflow consequences

The product uses 32-bit arithmetic before its bit pattern is interpreted as signed. It must not be specified as an unlimited-precision signed multiplication for all possible table entries.

For coefficients from 1 through 255, all three field products fit in signed 32 bits. Coefficient 256 takes the separate branch.

For unrestricted 16-bit coefficients, the high-field product can exceed the signed 32-bit range. Its largest positive mathematical magnitude is:

\[
65{,}535\times63{,}488=4{,}160{,}686{,}080.
\]

The middle- and low-field products remain within signed 32-bit range for every possible coefficient, but the high-field product need not. A mathematically positive high-field product can therefore become negative under signed interpretation of its 32-bit bit pattern.

This wraparound is part of the established arithmetic behavior. Whether such coefficients occur in intended use is unknown.

## Side effects

The function’s only direct write shown is a single 16-bit destination store on either nonzero-coefficient path.

Its direct reads are path-dependent:

| Coefficient | Direct reads, in order | Dependency calls | Direct writes |
|---|---|---:|---|
| 0 | Selector, selected coefficient | 0 | None |
| 256 | Selector, selected coefficient, source | 1 | Destination once, after the call |
| Other nonzero | Selector, selected coefficient, destination, source | 2 | Destination once, after the second call |

On the general path, the first dependency invocation occurs between the destination and source reads.

These counts exclude any reads, writes, or nested execution performed by F-indirect-01.

No allocation, deallocation, ownership transfer, or direct global-variable access is shown. That does not establish that the dependency has none of those effects. The function neither explicitly releases its input objects nor explicitly transfers their ownership.

### Aliasing and mutation

No non-aliasing condition is established.

If source and destination identify the same 16-bit storage on the general path, the initial destination word is captured first. The dependency can then modify that storage before the later source read. The two inputs to the arithmetic therefore need not represent the same value.

If source and destination alias on the coefficient-256 path, the source is read before the dependency runs, and the final store occurs afterward.

If destination storage overlaps the selector or coefficient table, the final store can modify those objects for subsequent invocations. It does not cause the current invocation to repeat selection.

If a dependency invocation does not return normally, the function’s later operations are not established to occur. In particular, there is no recovery path or guaranteed final destination store.

## Dependencies

### F-indirect-01

The caller supplies this dependency as an indirect callable target.

Established uses:

- At coefficient 256: one invocation with the source word.
- At other nonzero coefficients: one invocation with the initial destination word, followed by one invocation with the computed packed word.
- At coefficient zero: no invocation.

All supplied arguments have values within the unsigned 16-bit range. The actual calling-convention argument width and formal parameter type are not established by the supplied representation.

On the general path, the first result is consumed in a 32-bit representation. On either storing path, the final result is consumed as a 16-bit value.

Unknown dependency properties include:

- Whether it represents byte-order conversion, color conversion, or another operation.
- Whether it is deterministic or preserves its input.
- Whether repeated invocations with the same argument return the same result.
- Whether it modifies source, destination, table storage, globals, or other state.
- Whether it allocates, releases, retains, or transfers memory.
- Whether it returns normally.

Correctness must not depend on unestablished purity, global-state preservation, or ownership behavior.

## Acceptance examples

These are conditional analytical examples, not executed tests. Unless otherwise stated, they assume readable and writable storage as required, normal dependency returns, and a dependency that returns its argument unchanged without side effects.

### Zero coefficient

Given any selector whose selected entry is zero, the function returns after reading that entry.

The destination remains unchanged by this function. No dependency invocation or direct source/destination access occurs.

### Exact source branch

Given coefficient 256, source 0x1234, and any previous destination value, the dependency receives 0x1234 once and the final destination becomes 0x1234.

The previous destination is not directly read.

### Half-weight positioned fields

Given coefficient 128, source 0xFFFF, and destination 0x0000, the final destination is 0x7BEF.

The high, middle, and low field contributions are respectively 0x7800, 0x03E0, and 0x000F after arithmetic and masking.

### Negative low-field rounding

Given coefficient 1, source 0x0000, and destination 0x0001, the low-field signed product is −1. Truncation toward zero produces a zero adjustment, so the final destination remains 0x0001.

An implementation that rounds this division downward would produce a different result.

### Source mutation during the first call

Given coefficient 128, an initial destination of zero, and an initial source of zero, suppose the first dependency invocation returns zero but changes the source to 0xFFFF. Suppose the second invocation returns its argument unchanged.

The calculation uses source 0xFFFF, and the final destination is 0x7BEF. Reading the source before the first invocation would violate the established ordering.

### Coefficient above the interpolation range

Given coefficient 512, source 0x001F, and destination zero, the low-field adjustment is 62. Masking it to five bits produces 30, so the final destination is 0x001E.

There is no saturation to 0x001F and no rejection of coefficient 512.

### Wrapped high-field product

Given coefficient 65,535, source 0xF800, and destination zero, the high-field mathematical product is 4,160,686,080. Its signed 32-bit interpretation is −134,281,216.

After division toward zero and high-field masking, the packed result is 0xF800. Under the stated identity-dependency assumptions, that becomes the final destination.
