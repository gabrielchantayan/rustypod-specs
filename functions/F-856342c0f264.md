# F-856342c0f264

## Purpose

No application-level purpose is established. The evidence does not justify calling this operation a constructor, parser, collection update, serializer, or resource-management routine. ## Behavior

### Widths and interpretation

Byte, halfword, and word accesses have represented widths of 8, 16, and 32 bits. Byte and halfword stores retain the low eight and sixteen bits respectively. Their widths remain material even when the stored value would fit in a smaller access.

Unsigned calculations explicitly involving 32-bit values use 32-bit results. This does not establish universal wraparound for signed address arithmetic. Byte order, alignment behavior, pointer ordering, signed overflow, and oversized shifts remain execution-model dependencies.

The sequence below describes represented access order. Captured values retain their identity despite subsequent writes to their source locations. Conversely, a later field read must not be replaced by an earlier captured value without proving that intervening writes and aliasing cannot affect it.

### Initial captures, offset, and four stores

Two fixed-location words are captured first: a **comparison word**, followed by an **auxiliary word**.

The initial offset combines the additive seed, the second argument, and a one-bit adjustment. That adjustment is one when either:

- The unsigned index seed exceeds `0xFFFFFFA6`; or
- Adding the incoming carry to the 32-bit result of index seed plus `0x59` produces an unsigned carry.

Otherwise, the adjustment is zero.

An unsigned comparison tests whether the comparison seed is less than or equal to the comparison-word source. The representation accesses that fixed-location source again for this comparison; the halfword store below uses the previously captured word. No intervening store by this operation separates those reads.

The first four stores occur in this order:

1. A halfword containing the initial offset is written at third argument plus initial offset.
2. After adding the comparison seed to the offset, a halfword containing the updated offset is written at third argument plus updated offset.
3. A halfword containing the captured comparison word is written at twice the second argument.
4. Byte `0x45` is written at index seed plus incoming carry plus `0x9E`.

The following discussion calls the second halfword destination the **mixed-width location**. Its address remains based on the updated offset.

### Early fixed-location captures and overlapping accesses

Immediately after those four stores, the operation captures a fixed-location **control-block address**, then captures a separate fixed-location **halfword contribution**.

Both captures precede the first word read from the mixed-width location and its resulting byte store. Their order cannot be moved across those accesses merely because their sources are fixed locations: calculated destinations may alias those sources.

The first word read from the mixed-width location supplies an address. Byte `0x45` is written at that address plus `0x45`. The operation then repeats the halfword write of the updated offset at the mixed-width location.

Next, a halfword is written at control-block offset `0x45`. Its low-sixteen-bit result combines:

- The captured auxiliary word.
- The separate halfword contribution.
- One when the unresolved destination compares below address value `0x46`, otherwise zero.

The meaning of that destination comparison is not independently established.

Only after this control-block halfword store is the mixed-width location read as a word again. Call this second captured address the **early target**. Word `0x45` is written at early-target offset `0x45`.

Finally, a byte is written at control-block offset `0x45`. Its value is the fourth argument plus `0x53` plus the earlier unsigned-comparison result, truncated to eight bits. This overlaps, but does not necessarily replace all of, the preceding halfword.

Both word reads from the mixed-width location occur after halfword writes there. Neither is necessarily an untouched input pointer. Moreover, the two word reads need not agree: intervening stores may affect the location through aliasing.

### Root capture and first address graph

The next captures and mutations have a material ordering:

- The **root** is read as a word from third-argument offset `0x14`.
- That captured root is written as a word at updated offset plus `0x34`, without adding the third argument.
- Only then is the **primary** address read from control-block offset `0x74`.
- An address is then read from early-target offset `0x14`, before writing the early target at primary offset `0x54`.

These constraints matter independently. The root store can change the subsequently read primary address if the locations alias. Likewise, the write at primary offset `0x54` could change early-target offset `0x14`; the represented operation captures that field first.

The address captured from early-target offset `0x14` receives its own address at offset `0x54`. Primary offset `0x44` receives the root. Early-target offset `9` receives the primary address’s low byte.

### Final accesses and indirect invocation

After the final decimal-100 group and further byte and word propagation, a fixed-location 32-bit **closing contribution** is captured.

A word read from anchor offset `0x74` supplies both an address and a low-sixteen-bit value. The final mixed-width sequence is ordered as follows:

1. Store that halfword at captured address plus anchor.
2. Store the closing contribution’s low halfword at twice the final decimal-100 record’s address.
3. Read a signed byte at an earlier captured linked address plus anchor.
4. Store the first halfword at closing contribution plus captured address.
5. Repeat the first halfword store at captured address plus anchor.
6. Store word `0x45` at signed-byte-derived unsigned address plus `0x45`.

The signed byte is converted to an unsigned 32-bit value. Negative values therefore become large unsigned values, not zero-extended bytes.

Next, a fixed-location **final address value**, a fixed-location **final payload**, and the word at anchor offset `0x44` are captured, in that order. The operation then writes:

- Byte `0x44` at signed-byte-derived address plus `0x44`.
- The final payload as a word at twice the final address value.
- The final address value’s low halfword at its sum with the retained linked address.

The terminal dependency receives three represented arguments:

1. The signed-byte-derived unsigned value, bitwise ORed with `0x44`.
2. The final address value.
3. The captured anchor-offset-`0x44` word.

Bitwise OR sets the specified bits; it is neither addition nor replacement of the remaining bits.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Adjustment boundary.** With incoming carry zero, index seed `0xFFFFFFA6` produces adjustment zero. Index seed `0xFFFFFFA7` produces adjustment one.

2. **Carry contribution.** At index seed `0xFFFFFFA6`, the 32-bit sum with `0x59` is `0xFFFFFFFF`. Incoming carry one makes the carry condition true.

3. **Equality and truncation.** If the comparison reads a word equal to the comparison seed, its contribution is one. With fourth-argument bit pattern `0xFF`, the resulting control-block byte is `0x53`.

4. **Early capture aliasing.** If the first indirect byte store aliases the control-address source, the already captured control address remains in use. Moving its read after that byte store would not preserve the represented sequence.

5. **Root-store ordering.** If updated offset plus `0x34` equals control-block offset `0x74`, the primary read observes the preceding root store, subject to the target memory model.

6. **Early-target field ordering.** If primary offset `0x54` aliases early-target offset `0x14`, the latter address is captured before the former is overwritten.

7. **Nonconstant linked byte.** If the retained primary word is `0x123456AB`, the first decimal-100 group writes byte `0xAB` at the linked record’s offset `0x11`, followed by byte `0x64` at offset `0x10`, assuming no intervening external modification.

8. **Mixed-width input.** A preceding halfword write supplies the low half of a later same-address word read under little-endian interpretation, but the high half under big-endian interpretation. Neither byte order is established.

9. **Negative terminal byte.** A signed-byte result of minus one converts to `0xFFFFFFFF`; OR with `0x44` leaves the first terminal argument unchanged.

10. **Repeated access and failure.** An access-sensitive observer can distinguish the consecutive identical anchor-byte stores. If a later access faults, no represented action undoes preceding stores.
