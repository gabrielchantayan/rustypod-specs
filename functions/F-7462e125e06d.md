# F-7462e125e06d

## Purpose

F-7462e125e06d conditionally invokes a dependency and, if that dependency returns zero, copies a caller-specified byte range into a descriptor-backed destination while transforming every byte. It can also report a dependency-supplied offset through an optional output pointer.

The established behavior has three stages:

1. Reject certain descriptor states using two bit tests.
2. Invoke F-5c8c9e1af152 for descriptors that pass those tests.
3. On a zero dependency result, perform the transformed copy and optionally write the offset output.

The apparent intent is to prepare or locate a destination region and populate it with encoded bytes. That interpretation is inferred; the meaning of the descriptor, the offset, and the transformation is not established.

This contract describes static evidence only. No runtime tests have been performed.

These requirements are conditional. For example, a null descriptor prevents direct source access, and a nonzero dependency result prevents the direct copy and offset-output write.

## Behavior

### Initial state and first rejection

The function initializes a private signed 32-bit offset temporary to zero. It also reads an initial static status value before testing descriptor eligibility.

If the descriptor pointer is null, the function returns that initial status. It does not invoke the dependency, read descriptor contents, copy bytes, or write the offset output.

If the descriptor pointer is nonnull, its first 32-bit word is read. If that word is zero, the function returns the initial status with no dependency invocation, byte copy, or offset-output write.

The initial nonzero test does not establish the validity or size of the referenced destination storage.

### First bit test

For a nonnull descriptor with a nonzero first word:

- A second static status is selected.
- The descriptor word at byte offset 8 is multiplied by a static multiplier.
- Bit 0 of the product is tested.

If bit 0 is set, processing stops and the second status is returned.

Only the tested product bit affects this decision. The operation does not establish that the descriptor word itself is a bit-field.

### Second bit test

If the first product test has bit 0 clear:

- A third static status is selected.
- The descriptor word at byte offset 8 and the static multiplier are evaluated again.
- Bit 1 of this product is tested.

If bit 1 is set, processing stops and the third status is returned.

The two tests are separate evaluations. Their behavior must not be specified as one atomic snapshot of the descriptor field and multiplier.

If those values remain stable, reaching the dependency requires both low product bits to be clear: the product is congruent to zero modulo four. This equivalence is conditional on stable values and the applicable arithmetic model.

Within each product evaluation, the relative ordering of the descriptor-field read and multiplier read is not established by the supplied representation.

### Dependency invocation

When both tests pass, the function invokes F-5c8c9e1af152 with these arguments, in this positional order:

1. Descriptor pointer.
2. Opaque value D.
3. Opaque value B.
4. Pointer to the private offset temporary, initially zero.
5. Opaque value C.
6. Length.
7. Opaque value A.

This specifies the dependency’s argument positions, not a machine-level argument-evaluation order.

The dependency’s result becomes the eventual return status. Its side effects are not undone by this function.

Only an exact unsigned result of zero enables the copy. A result of one skips it, and every unsigned result greater than one also skips it. Thus high-bit-set results are nonzero results and do not enable copying.

On every nonzero dependency result, this function performs no subsequent direct byte copy and no direct offset-output write. This does not imply that the dependency left memory unchanged.

### Destination calculation

After a zero dependency result, the function reads the descriptor’s first word again. It does not reuse the value from the initial eligibility check.

It calculates a destination start from:

- The newly read descriptor base value.
- The current private offset value.
- An additional displacement of 20 bytes.

The offset is added in byte-address arithmetic, not multiplied by the descriptor word size.

There is no second nonzero check on the descriptor base, no check that the offset is nonnegative, and no bounds check against a capacity field. A dependency that changes the base or offset can therefore change where the copy writes.

The arithmetic is expressed through signed 32-bit intermediates, followed by an unsigned comparison of the destination start against the source address. The supplied evidence does not settle out-of-range signed arithmetic or all address-wrap behavior. Nonoverflowing, valid-address cases are the unambiguous core of this contract.

### Byte transformation

Each visited source byte is multiplied by negative 117, and the result is stored as one byte.

Under the ordinary eight-bit byte-storage model, the stored byte is the low eight bits of that product. Equivalently, it is the source byte multiplied by 139 modulo 256.

For example:

| Source byte | Stored byte |
|---:|---:|
| 0 | 0 |
| 1 | 139 |
| 2 | 22 |
| 128 | 128 |
| 255 | 117 |

Whether a loaded plain character is sign-extended does not change these low-eight-bit results under that model. The transformation is multiplicative, not an exclusive-or, addition, or plain copy.

### Copy direction and observable ordering

The computed destination start is compared with the source address as an unsigned value.

- If the destination start is lower, bytes are processed from index zero upward.
- Otherwise, bytes are processed from the final index downward to zero.

For each index, the source byte is read and the transformed byte is then written to the destination at the same relative index. That iteration finishes before the next index is processed.

Equal source and destination starts take the descending branch. For ordinary valid, nonwrapping ranges, this transforms the range in place.

The direction selection also supports overlapping ranges: a lower destination uses ascending traversal, while a higher destination uses descending traversal. This supports an inferred intent to preserve unread source bytes during overlap. There is no temporary copy or general source snapshot.

For a zero length, neither traversal performs a byte access. The post-dependency descriptor read, destination calculation, and direction comparison still occur.

### Optional offset output and completion

After the copy loop finishes, a nonnull offset output pointer receives the private offset value. A null output pointer is ignored.

This write occurs after all direct destination-byte writes, including when the length is zero. It is not performed on an early rejection or a nonzero dependency result.

The reported value is the offset temporary, not the destination address and not the offset plus 20. If the dependency leaves the temporary unchanged, its value remains zero, absent other aliasing effects.

The output word is not constrained to be separate from the descriptor, source, or destination. If it overlaps copied destination bytes, its final word write can overwrite part of the transformed result.

## Side effects

### Directly established effects

Depending on the branch taken, this function:

- Reads static status values and a static multiplier.
- Reads descriptor words.
- Passes the descriptor and a writable temporary to the dependency.
- Reads source bytes and writes transformed destination bytes.
- Writes one optional 32-bit offset output after copying.

No direct write to a static location is shown. No direct allocation, deallocation, handle close, logging operation, or synchronization operation is shown.

Those absences do not constrain the dependency.

### Ownership and lifetime

No ownership-transfer or release operation is directly established.

The descriptor, byte ranges, and optional output location must remain usable for the accesses actually performed. Their state after the dependency call cannot be assumed unchanged.

The dependency receives a pointer to function-local temporary storage. This function supplies no durable storage for that pointer beyond the invocation. Whether the dependency retains the pointer, or follows any ownership convention, is unknown.

### Aliasing, faults, and partial effects

There is no rollback mechanism.

If an access fails after earlier destination writes, those earlier writes are not explicitly undone. An invalid offset output can fail after the complete byte copy has already occurred.

There are no explicit synchronization measures. Concurrent mutation, unusual memory mappings, and aliases involving state exposed to the dependency are not established as supported. In particular, the routine does not promise that its returned status implies unchanged memory on rejection or failure.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Unless stated otherwise, memory is valid, arithmetic does not overflow, and no concurrent or unexpected aliasing mutation occurs.

1. **Null descriptor.**  
   Regardless of length or source address, the function returns the initial static status. It does not call the dependency or directly write the offset output.

2. **Zero descriptor base.**  
   With a nonnull descriptor whose first word is zero, the function returns the initial static status. The descriptor word at byte offset 8 is not needed on this path.

3. **First test rejects.**  
   If the first evaluated product has bit 0 set, the function returns the second static status. It does not perform the second product test or call the dependency.

4. **Second test rejects.**  
   If the first product has bit 0 clear and the second product has bit 1 set, the function returns the third static status without invoking the dependency.

5. **Dependency returns one.**  
   After both tests pass, a dependency result of one is returned unchanged. This function performs no subsequent byte copy or offset-output write.

6. **Dependency returns zero and selects an offset.**  
   Suppose the dependency supplies offset 12 and leaves a valid descriptor base. The destination starts 32 bytes beyond that base. A source sequence of byte values 1, 2, and 255 produces destination values 139, 22, and 117. A nonnull output receives 12 after the byte writes.

7. **Dependency changes the base.**  
   If the dependency returns zero after replacing the descriptor’s first word, the copy uses that replacement value. The pre-call base does not determine the destination.

8. **Zero-length copy.**  
   With passing gates and a zero dependency result, no source or destination bytes are accessed. The destination calculation still occurs, and a nonnull output receives the offset.

9. **Higher overlapping destination.**  
   For a valid destination beginning one byte above the source, a multi-byte copy proceeds from the highest index downward. Under the stated assumptions, writes do not replace source bytes before those bytes are consumed.

10. **Output overlaps destination.**  
    If the output word overlaps the transformed destination, the offset write occurs last. The final destination contents must reflect that later write.
