# F-8f3cd6356d31

## Purpose

F-8f3cd6356d31 conditionally retrieves one 32-bit value from storage addressed through a global base value. Only selectors 1 and 2 select storage. Every other selector returns a 32-bit zero without accessing that global base or the selected storage.

The first argument does not participate in the supplied function’s behavior. The function does not distinguish an unsupported selector from a supported selector whose stored value is zero.

This is a static behavioral contract derived from the supplied source representation. No runtime tests have been performed. The application meaning of the selected values is unknown.

## Interface

| Input | Width and interpretation | Behavioral role |
|---|---|---|
| First argument | Opaque 32-bit value | Unused. Its bits do not affect selection, addressing, or the returned value. |
| Selector | 32-bit integer; the selection check uses unsigned 32-bit arithmetic | Selects storage only when its value is exactly 1 or 2. |

The first argument has no demonstrated pointer, handle, ownership, or validity requirements. In particular, the function does not dereference it. Its name and application-level purpose are not established.

The selector is presented as a signed integer in the supplied representation, but its admission check is unsigned. This distinction matters when reasoning about zero and negative values; it does not expand the accepted set beyond 1 and 2.

### Output

The function returns one opaque 32-bit value:

- For selector 1, the 32-bit value stored 288 bytes beyond the global base.
- For selector 2, the 32-bit value stored 564 bytes beyond the global base.
- For every other selector, zero.

The selected value is returned without an explicit mask, sign conversion, scaling, or other transformation. No Boolean interpretation is established: any 32-bit stored pattern can be returned.

## Behavior

### Selector admission

The admission decision subtracts one using unsigned 32-bit arithmetic and compares the result with two.

Consequently:

- Selector 1 produces an admission value of zero and is accepted.
- Selector 2 produces an admission value of one and is accepted.
- Selector 0 wraps to the maximum unsigned 32-bit value and is rejected.
- Negative signed selectors are rejected.
- Positive selectors greater than 2 are rejected.

There is no clamping, normalization, modulo selection, or fallback to another stored entry. Unsupported values take the zero-return path.

The unsigned subtraction is important to the boundary behavior. Selector 0 is not accepted as a consequence of subtracting one. Likewise, a negative selector does not select storage preceding the base.

### Unsupported-selector path

For every selector other than 1 or 2, the function returns zero.

On this path, the supplied body does not read the global base and does not read a field through it. Therefore, the validity of that base and its selected storage is not a precondition for the function’s own data access on this path.

No error indicator accompanies the zero result. The function provides no way to determine, from the returned value alone, whether zero means “unsupported selector” or “stored value is zero.”

### Supported-selector path

For selector 1 or 2, the function:

1. Obtains the global base value.
2. Uses the selector, the 276-byte stride, and the 12-byte field displacement to identify the selected address.
3. Reads one 32-bit value from that address.
4. Returns the value read.

The global-base read precedes the selected-field read because the field address depends on the base. There is no intervening dependency call in the supplied body.

For the two admitted selectors, the displacement arithmetic produces 288 or 564 without overflowing a 32-bit integer. This does not prove that adding the displacement to an arbitrary base yields a valid address. Storage validity remains a caller or environment precondition.

There is no explicit check for a null base, an insufficient allocation, an unreadable field, or an unsuitable alignment. If a selected read cannot be performed, the supplied function establishes no recovery behavior or defined substitute result.

### Preconditions for a normal selected return

A normal return for selector 1 or 2 requires:

- A readable global base value.
- A base representation usable for the demonstrated address calculation.
- A readable four-byte field at the selected displacement.
- Any alignment and memory-access conditions required by the execution environment.

These are access preconditions, not validations performed by the function.

The source does not establish a requirement that both selected fields be readable for either individual call. A selector-1 call reads the selector-1 field; a selector-2 call reads the selector-2 field.

No allocation, deallocation, ownership transfer, reference-count change, callback, logging operation, or dependency call appears in the supplied body. The returned value is simply a 32-bit result; returning its bits does not establish ownership of any resource those bits might represent.
