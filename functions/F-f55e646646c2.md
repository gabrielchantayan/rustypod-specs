# F-f55e646646c2

## Purpose

F-f55e646646c2 overwrites a 16-byte state using one of two lookup-based transformations:

- A zero selector chooses a fixed arrangement of lookups through a global base-address object.
- Any nonzero selector chooses a configurable transformation through a supplied table with a 4,096-byte logical extent.

Both modes process four interleaved groups. Group \(g\) consists of state offsets \(g\), \(g+4\), \(g+8\), and \(g+12\), for \(g\) from 0 through 3.

The established behavior consists of byte reads, lookup reads, exclusive-OR combinations, and byte writes. A mixing or cryptographic purpose is plausible but inferred. No particular algorithm, invertibility property, or inverse relationship between the modes is established.

## Behavior

### Common group processing

Groups are processed in ascending order, from 0 through 3. Within each group, input bytes are gathered in increasing state-offset order.

The function retains the four gathered bytes in temporary storage before computing that group’s outputs. This is a per-group snapshot, not a snapshot of the entire state or lookup storage. An earlier group’s writes precede the next group’s gathering.

The auxiliary value’s initial contents do not affect the visible transformation: all four temporary bytes are overwritten before their first use as transformation inputs. This conclusion concerns output values and lookup selection; it does not assert anything about calling-convention effects outside the supplied body.

### Zero selector: global-table mode

For each group, the visible sequence is:

1. Read and retain the global lookup base.
2. Gather the group’s four state bytes.
3. Read the global lookup base again and calculate an address 256 bytes beyond that observed value.
4. Compute and write the first output, including a further global-base read in its lookup expression.
5. Compute and write the second output.
6. Compute and write the third output.
7. Compute and write the fourth output.

The function therefore does not establish a single global-base snapshot, either for the whole invocation or for an individual group.

For a precise description, define:

- \(P\): the base captured before gathering the group.
- \(Q\): the base read after gathering the group.
- \(R\): the base read while computing the first output.
- \(x_0,x_1,x_2,x_3\): the saved bytes in increasing temporary-address order.
- \(\ell\): the low-order eight bits of the saved four-byte word.
- \(T_A[b]\): the lookup byte read at address \(A+b\).

The output bytes at the group’s four locations are:

| Output position | Value written |
|---|---|
| 0 | \(T_R[\ell]\oplus T_{Q+256}[x_1]\oplus x_2\oplus x_3\) |
| 1 | \(\ell\oplus T_P[x_1]\oplus T_{Q+256}[x_2]\oplus x_3\) |
| 2 | \(\ell\oplus x_1\oplus T_P[x_2]\oplus T_{Q+256}[x_3]\) |
| 3 | \(T_{Q+256}[\ell]\oplus x_1\oplus x_2\oplus T_P[x_3]\) |

Here \(\oplus\) denotes bitwise exclusive OR.

Every lookup index is an unsigned eight-bit value, bounded by 0 and 255. Lookups through the second region therefore use offsets 256 through 511 from its observed base. These bounds do not establish that adding the offsets to an arbitrary address is safe.

Each output expression completes before its associated byte write. The four output writes occur in the listed order. The supplied expression representation does not establish the relative order of separate operand reads within one XOR expression.

### Nonzero selector: caller-table mode

This branch does not visibly read the global lookup base.

For each group, gathering and initialization are interleaved:

1. Read the first state byte into the first temporary byte, then write zero to that state location.
2. Read the second state byte into the second temporary byte, then write zero to its state location.
3. Repeat for the third and fourth bytes.

Thus all four destinations are zeroed before any lookup accumulation for the group begins. The function does not first gather all four inputs and then perform all four zeroing writes.

It next processes output positions 0 through 3. For each output position, it processes saved input positions 0 through 3. Each input contribution causes a separate read-modify-write of the destination byte.

The caller table has four output blocks of 1,024 bytes. Each block contains four 256-byte subtables, one for each saved input position. Define:

\[
U_{r,j}[b]
=
\text{byte at caller-table offset }1024r+256j+b,
\]

where \(r,j\in\{0,1,2,3\}\) and \(b\in\{0,\ldots,255\}\).

Under stable, nonoverlapping lookup storage, the final output is:

\[
y_r=U_{r,0}[x_0]\oplus U_{r,1}[x_1]
     \oplus U_{r,2}[x_2]\oplus U_{r,3}[x_3].
\]

Operationally, each contribution is XORed with the destination’s current byte and written back immediately. This entails four destination reads and four destination writes per output, after its initial zeroing write.

The lookup-byte read and current-destination-byte read both precede their XOR write. Their relative order within the expression is not established.

The table-offset arithmetic is bounded:

\[
0\leq1024r+256j+b\leq4095.
\]

The internal block and subtable offsets fit comfortably within 32 bits. Adding them to the supplied address may still encounter environment-dependent address overflow or inaccessible memory. No check prevents either condition.
