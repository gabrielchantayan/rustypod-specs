## Behavior

### Replacement guarantee

On successful completion, the selected ordinary-memory byte contains the input’s eight-bit pattern.

The previous contents do not participate in calculating the replacement. The function does not establish masking, merging, accumulation, comparison, Boolean normalization, or preservation of selected old bits.

The represented behavior has no input-dependent alternative. Supplying zero does not select a no-op. Supplying the byte already present does not select an equality-based early exit. This describes the represented operation; it does not guarantee a separately observable physical transaction when ordinary-memory contents remain unchanged.

Only one byte is an established write target. With valid ordinary memory and no interfering activity, adjacent bytes retain their contents. That narrow storage footprint does not determine physical bus transaction width or the semantic effects of writing into a larger externally interpreted object.

### Access ordering

Destination selection supplies the address used for the replacement and therefore logically precedes the write. The replacement does not require the previous destination byte to be read.

The established access order is limited to obtaining the configured destination and writing the supplied byte through it. No exact processor-load count, bus-access count, memory barrier, or atomic pointer-read guarantee follows.

There is no represented cross-invocation destination cache. If external activity changes the configured pointer between completed calls, and the new state is available to the next invocation under the applicable execution rules, that invocation uses the newly configured destination.

Concurrent pointer changes are different: the function provides no coordination protocol from which to determine which destination an overlapping invocation will use. Concurrent modification of the destination likewise prevents an unconditional claim about its subsequently observed contents.

### Aliasing and layout

The effect on a later invocation depends on the pointer representation and the byte changed. The resulting pointer might remain usable or become unusable. Neither outcome is established.

Overlap with another significant object has the same limitation: the established write remains one byte, but changing that byte may alter the interpretation of the larger object. The function supplies no object-level invariant beyond the replacement itself.
