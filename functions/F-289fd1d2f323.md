# F-289fd1d2f323

## Purpose

The supplied representation does not establish a higher-level purpose. In particular, it does not justify describing the operation as initialization, allocation, serialization, device control, or object management.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.

- **Documented-only unknowns:** executable validity, indirect-callee behavior, architectural details, and recovery artifacts that cannot be resolved from the supplied material.

The detailed behavior below is conditional on execution reaching the represented operations and on the indirect calls returning normally.

## Side effects

### Memory and aliasing

Explicit writes are byte or 32-bit word writes. No explicit bulk copy, allocation, release, or ownership transfer is represented.

All addresses may alias. In particular:

- A byte-selected destination can overlap another explicit access.
- Address arithmetic can wrap under the modular interpretation.
- A dependency can change a byte-selection location before its next reload.
- A word store may affect a later byte lookup if their addresses overlap.

Repeated zero stores remain observable operations. They cannot be eliminated merely because a previous operation wrote zero: intervening callees may alter memory, and the destination may be externally observable.

The ordering of direct clears at base plus 17 and base plus 1 is significant.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial byte truncation.** If the initial lookup returns 7 and the carried value ends in hexadecimal `AB`, the first explicit store writes byte `AB` at address 24. If execution reaches the later third-argument store, its destination remains address 27 even if intervening calls changed the lookup byte.

2. **Fresh lookup after calls.** If a later lookup returns 9 rather than the earlier 7, the corresponding byte store targets address 26. Reusing the earlier lookup would not match the represented behavior.

3. **Third-argument scaling.** With third argument 3, the opening word store carries value 12. With bit pattern `0x40000001`, the modular result is 4; no overflow rejection is represented.

4. **Global snapshot.** If the sampled global word is `0xFFC00000`, its later byte store carries `FF`. A change to the global after the sample does not alter that retained value.

5. **Payload extraction.** If the first payload is `0x12345678`, its masked right-shifted value is `0x123`; the byte store retains `23`.

6. **Compounded shift.** The second payload shifted left by 28 is zero under the stated 32-bit interpretation, regardless of the middle result.

7. **Direct-clear ordering.** When both late direct-clear sites are reached, each writes base plus 17 before base plus 1. Callee effects between those sites are not assumed absent.

8. **Loop-state replacement.** A result of 5 at the next-fourth-argument preparation site produces next fourth argument 20. The next third argument comes from the later call result, not from this multiplication.

9. **No completion guarantee.** If an indirect callee never returns, the function need not reach the next store or repetition. No timeout or alternative completion path is represented.
