# F-a73b589c0c07

## Purpose

No application-level purpose is established. In particular, the evidence does not establish that the routine implements a serializer, allocator, device protocol, or ordinary object update. Such interpretations would require information about its dependencies and memory map.

This contract describes the operations visible in the supplied representation. It does not certify that the representation faithfully captures the executable: the supplied material explicitly reports invalid instruction data, removed unreachable regions, and overlapping global symbols. All acceptance examples below are conditional static expectations, not runtime results.

### 1. Initial result and two word destinations

F-unknown-001 is invoked first, with no explicit arguments displayed.

F-unknown-002 is then invoked with:

1. The third explicit argument logically shifted right by seven.
2. The first dependency’s represented 32-bit result shifted left by 25.

Its low 32-bit result is retained as the **initial word**. Its high 32-bit half is shifted left by three to form an early call argument.

The first explicit data-memory store writes the initial word to the fourth argument’s address plus `0x74`.

A subsequent dependency receives four arguments: the shifted high half twice, then the initial word twice. Further calls include two separate result-to-next-call forwarding pairs, followed by additional calls. A later dependency result supplies a computed destination: four times that result plus `0x74`. The initial word is written there.

Thus, the initial word is written to two independently derived destinations. The evidence does not establish that they are distinct, belong to the same allocation, or represent fields of one type.

### 2. First masked extraction and indirect-byte pair

A later dependency supplies a new unsigned 32-bit value. Two quantities are retained from it:

- Its low 30 bits, shifted right by five.
- Its low 30 bits, shifted right by six.

The first quantity is written to an address equal to 16 times the dependency result plus `0x14`. After intervening calls, that same retained quantity is written to four times another dependency result plus `0x14`.

Another dependency supplies the **first byte-source word**. The routine reads an unsigned byte from the second retained quantity plus one. It adds `0x11` to the byte value and writes the low byte of the first byte-source word shifted left by two to that computed address.

After more calls, it performs another byte read from the same selector address and stores the low byte of the first byte-source word’s low 30 bits shifted right by 20.

These are two separately resolved indirect destinations. A dependency or aliasing store may change the selector byte between reads. The second store is not necessarily to the first store’s destination.

### 3. Global capture and repeated store

It computes a destination from the initial word: logically shift that word right by seven, multiply by four, then add `0x14`.

The captured global-derived word is written to that destination twice, with a sequence of dependency calls between the stores. The destination and stored value are retained across that sequence. The global object is not visibly reread for the second store.

The underlying global read width is not conclusively established because the object’s declared type is absent and the supplied material warns about overlapping symbols.

### 4. Capture of a working word

A dependency result next supplies an index-like value. The routine:

- Writes four times that value to 16 times that value plus `0x14`.
- Reads a 32-bit word from four times that value plus `0x14`.
- Retains that read as the **working word**.
- Forms a separate 32-bit value by shifting the dependency result left by 26.

The store precedes the read. If those addresses alias, the working word reflects the preceding write, subject to the target’s access semantics.

An ensuing dependency receives, in order, the 16-times value, the four-times value, the shifted-by-26 value, and the four-times value again. Other calls follow, including result-forwarding calls. The original 16-times destination is then written again with the original four-times value.

The second write uses retained operands, not a freshly selected destination.

### 7. Secondary result channel and high-byte processing

### 8. Second indirect-byte sequence

An ensuing dependency receives that shifted word three times. Further calls occur. The routine then rereads the selector byte and stores the low byte of the second byte-source word’s low 30 bits shifted right by 20.

### 9. Transition into clearing and looping

The routine then performs these effects in order:

1. Stores the low byte of the terminal scaled word at `0x1c` plus the original working word’s top byte shifted right by seven.
2. Rereads the second selector byte and stores zero at the selected byte address plus `0x11`.
3. Makes dependency calls, including one receiving the terminal source word’s low 30 bits shifted right by six.
4. Rereads the same selector byte and performs another zero store.
5. Obtains a new dependency word, masks it to 30 bits, and shifts it right by 25.

### 10. Unconditional loop

- The control quantity becomes that result shifted left by 26.

## Acceptance examples

These examples are conditional on dependencies returning the stipulated values, accesses being valid, and execution reaching the relevant milestone.

1. **Initial argument extraction.** If the third explicit argument is `0x000001ff`, the first argument displayed for F-unknown-002 is `3`. Its low seven input bits do not contribute to that argument.

2. **Early result placement.** If the low half of F-unknown-002’s result is `0x12345678`, the first explicit store writes that exact 32-bit word at the fourth argument plus `0x74`. It is not derived from the high half.

3. **Masked extraction boundary.** If the first masked-extraction source is `0xffffffff`, its two retained quantities are `0x01ffffff` and `0x00ffffff`. The mask removes the upper two bits before either shift.

4. **Byte truncation.** If a byte-source word is `0x123456ab`, the shifted-left byte store writes `0xac`; the masked-right-shift byte store writes `0x23`. Each destination is resolved from a separate selector read.

5. **Selector mutation.** If a selector byte reads as `4`, its selected destination is `0x15`. If an intervening dependency changes it to `9`, the next selected destination is `0x1a`. Reusing the earlier destination would violate the visible read sequence.

6. **Global capture.** If the global-derived word is captured as `7`, an intervening change of that global to `8` does not itself change the second repeated store: the displayed second store still uses captured value `7`.

7. **Late direct destination.** A working word whose top byte is `0x7f` selects direct address `0x1c`; a top byte of `0x80` selects `0x1d`.

8. **Loop control distinction.** The first loop invocation receives zero as its second argument. Under 32-bit shift semantics, a later supplying result of `1` produces control quantity `0x04000000`, so the following iteration receives `0x00040000` as that argument.

These are analytical acceptance conditions only. None has been executed.
