# F-e9688fa05d53

## Purpose

F-e9688fa05d53 processes a supplied binary region and requests construction of an output object. The region contains a fixed-size outer header followed by records. Each record selects either direct payload insertion or recursive processing of its payload.

An optional callback can reject direct records before insertion. A separate record flag requests an additional parent-object operation after successful insertion.

The established contract consists of field accesses, dependency calls, status handling, address calculations, and output-slot writes. Describing the output as a hierarchical container is inferred intent; its concrete representation and ownership model are not established.

The visible function does not establish safe parsing of arbitrary bytes. It checks initial arguments and two outer-header fields, but does not visibly enforce record boundaries, payload extents, arithmetic safety, or recursion limits.

| Callback | Nullable callable address | Invoked only for direct records. |
| Caller context | Opaque 32-bit value | Forwarded to callbacks and recursive invocations. |
| Output-slot address | Nullable address of a writable 32-bit slot | Cleared initially when nonnull; passed to the constructor dependency. A null address is rejected. |

The result is a 32-bit status:

- `0`: no checked operation reported failure.
- `-50`: an initial argument check or outer-header check failed.
- `-108`: the temporary-allocation dependency returned a null address.
- Other nonzero values: statuses propagated from construction, a callback, recursion, insertion, or the optional post-insertion operation.

Every nonzero checked status is a failure, including positive values. Callback failure aborts processing; it does not mean “skip this record.”

The callback receives four arguments:

1. The record’s 32-bit field at offset 0.
2. The payload address at record offset 56.
3. The record’s 32-bit payload-length field at offset 52.
4. The caller context.

The length is subsequently used as an unsigned 32-bit quantity for recursive input size and record-span arithmetic. No independent signedness contract for the callback’s corresponding parameter is supplied.

## Behavior

### Entry and initial rejection

A nonnull output-slot address is written with zero before the other argument checks.

The function returns `-50` if the output-slot address is null, the input address is zero, or the unsigned input size is below 136. No allocation dependency is called on these paths.

A null output-slot address is not dereferenced. With a valid output slot but invalid input arguments, the explicit zero write still occurs.

There is no visible overlap rejection. If the output slot overlaps the input region, this early write can alter input bytes before the initial transfer.

### Temporary-buffer setup

After the initial checks pass:

1. F-f195b74c9758 receives the input size.
2. A null result causes return status `-108`.
3. Otherwise, F-ad023a375886 receives the input address, allocation address, and input size.
4. F-af6890137acf receives the allocation address.
5. The prepared outer header is checked.

The results of F-ad023a375886 and F-af6890137acf are not checked as statuses.

The outer header passes only when its first word matches the external expected value and its unsigned 16-bit field at offset 4 is zero or one. The comparison is conditional: a first-word mismatch prevents the second header condition from being needed.

Header rejection selects `-50`, then calls F-1137792fba7d with the allocation address before returning. This establishes a cleanup-dependency call, not actual deallocation.

### Construction

For an accepted header, F-7b9683882e71 receives:

1. Whether the byte at outer-header offset 15 is nonzero.
2. The caller’s output-slot address.

If construction returns nonzero, record processing does not begin. The allocation address is passed to F-1137792fba7d, and the constructor’s status is returned.

There is no explicit parent cleanup call or output-slot reset on constructor failure. Any constructor-written value remains subject to subsequent dependency effects; the function does not guarantee the slot’s final value.

### Record iteration and observations

After successful construction, the current record address starts at outer-header offset 136 and the unsigned 32-bit record index starts at zero.

Each loop condition compares the index with a fresh read of the outer-header record-count word. The function does not establish an immutable count captured before processing. Changes to that word by dependencies or callbacks can therefore affect later iteration.

For each reached record, F-ebb362b154c9 is called with the record address before interpretation. The function then reads the 32-bit word at record offset 8, converts it to the target character type, and tests the converted value against zero:

- Zero selects direct handling.
- Nonzero selects recursive handling.

Record accesses following preparation observe storage as it then exists. They are not guaranteed to reflect the original input bytes.

The source establishes call sequencing, but not a total evaluation order among separate argument expressions within a single call.

### Direct handling

If the discriminator converts to zero, the callback is invoked when nonnull.

A nonzero callback status immediately selects processing-failure cleanup. No insertion or post-insertion operation is attempted for that record.

With no callback, or after callback success, F-ce027bf4e122 receives:

1. The value read from the parent output slot.
2. The record field at offset 4.
3. The record field at offset 0.
4. The payload address.
5. The payload-length field at offset 52.

Its nonzero status selects processing-failure cleanup.

The record fields used for insertion are read after the callback returns. The function does not preserve a complete pre-callback snapshot. A callback that can modify record storage may therefore change the insertion arguments, including the length or identifier fields.

### Recursive handling

If the discriminator converts to nonzero, F-e9688fa05d53 is recursively invoked with:

- The enclosing record’s payload address.
- Its payload length as the nested input size.
- The same callback.
- The same caller context.
- A separate local 32-bit output slot.

The enclosing nested record does not itself trigger the callback. Direct records reached within the nested region may do so.

A nonzero recursive status selects parent processing-failure cleanup without attempting nested insertion.

After recursive success, F-dcd359011f5e receives:

1. The current value read from the parent output slot.
2. The enclosing record’s field at offset 4.
3. The value read from the nested-result slot.

After that insertion call returns, the nested-result slot is **read again**, and that read supplies the argument to F-8f27efea2b2d. Preservation of the earlier nested-result value is not established. If F-dcd359011f5e changes accessible storage containing the slot, the two calls can receive different values.

F-8f27efea2b2d is called on this path regardless of whether nested insertion succeeded. Its return value is not used to replace the saved insertion status. That insertion status determines whether processing continues.

These calls do not establish whether insertion copies, borrows, retains, or consumes the nested result, or what F-8f27efea2b2d does with its argument.

### Optional post-insertion operation

Only after successful direct or nested insertion does the function explicitly read the byte at record offset 9.

If that byte is nonzero, F-1f1297e0b8fd receives:

1. The current parent output-slot value.
2. The zero-based record index.
3. Zero.

A nonzero result selects processing-failure cleanup.

The flag is observed after insertion and, for nested handling, after the nested-result cleanup call. Earlier values of the flag are not authoritative if intervening calls modify it.

### Record advancement and conditional transfer

After insertion and any requested post-insertion operation succeed, the payload length is read again.

The nominal span is:

- Payload length plus 56 when the length is even.
- Payload length plus 57 when the length is odd.

The calculations are 32-bit. Span and address arithmetic can wrap; no overflow check is visible.

The current address advances by that span. If bit value 2 of the resulting address is set, F-ad023a375886 receives:

1. The advanced address.
2. The advanced address minus two.
3. The original input size minus the advanced address’s offset from the allocation base.

The size subtraction also uses unsigned 32-bit arithmetic and can wrap. After the call, the current record address moves back two bytes.

The initial use of F-ad023a375886 suggests source-then-destination transfer order, making backward tail movement a plausible intent. Transfer direction, overlap support, and actual byte movement remain unknown.

Advancement and conditional transfer occur even after the last record selected by the current count. There is no preceding “another record remains” check.

### Completion and failure

A zero record count leads directly from successful construction to the final F-1137792fba7d call and a zero status, without record preparation or insertion.

When a checked record-processing operation fails, the function:

1. Reads the parent output slot and passes that value to F-8f27efea2b2d.
2. Explicitly writes zero to the parent output slot.
3. Stops record iteration.
4. Calls F-1137792fba7d with the temporary-allocation address.
5. Returns the selected failure status.

The zero write precedes F-1137792fba7d. A zero value on return is guaranteed only if subsequent activity preserves the slot.

For every ordinary return after a nonnull allocation result, this invocation calls F-1137792fba7d once with that allocation address. On successful processing, it makes no explicit parent cleanup call and no final output-slot write.

## Acceptance examples

These are conditional static cases, not executed tests. Storage is assumed valid, calls return normally, and unspecified earlier operations succeed.

1. **Short input:** With a writable output slot and size 135, the function writes zero and returns `-50`, without allocation.

2. **Null output slot:** The function returns `-50`, without an output write or allocation call.

3. **Null allocation result:** Valid initial arguments followed by a null F-f195b74c9758 result produce `-108`. The initial zero write occurred; the slot remains zero only if the allocation call and other activity preserve it.

4. **Rejected header field:** A matching first word and unsigned 16-bit value 2 at offset 4 produce `-50`. Construction is not called. F-1137792fba7d receives the allocation address.

5. **Empty accepted region:** Successful construction followed by a zero count produces no record-preparation, callback, or insertion calls. F-1137792fba7d is called before return status zero. The output retains the constructor-produced value only if later activity preserves it.

6. **Discriminator conversion:** A 32-bit discriminator word of zero converts to zero and selects direct handling. A word of one converts to nonzero and selects recursion. Cases involving other word bits must follow the target’s character-conversion semantics; they cannot be decided solely by inspecting the byte at offset 8 without representation assumptions.

7. **Callback rejection:** Callback status 7 prevents direct insertion. The current parent value is passed to F-8f27efea2b2d, the output slot is explicitly zeroed, F-1137792fba7d is called, and status 7 is returned. The final slot value is zero only if subsequent activity preserves that write.

8. **Nested insertion failure:** After recursive success, nested insertion status 9 is followed by a fresh nested-slot read for F-8f27efea2b2d. Parent processing-failure cleanup follows, including the explicit zero write before F-1137792fba7d. Status 9 is returned.

9. **Nested-slot modification:** If nested insertion changes the accessible nested-result slot, the subsequent F-8f27efea2b2d argument is the changed value, not necessarily the value supplied to insertion.

10. **Post-insertion failure:** A nonzero explicit flag byte after successful insertion triggers F-1f1297e0b8fd. Its failure selects parent cleanup; insertion has already been attempted successfully, and no rollback is established.

11. **Constructor failure after writing output:** A constructor-written nonzero value is not explicitly cleared or passed to parent cleanup. F-1137792fba7d is still called. Final output contents depend on those calls’ effects.

12. **Small spans:** Without overflow, lengths 0, 1, and 2 produce nominal advances of 56, 58, and 58 bytes. The possible two-byte adjustment depends on the advanced address’s bit value 2 and can occur after the final record.
