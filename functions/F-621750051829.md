# F-621750051829

## Purpose

F-621750051829 populates three selected regions of caller-supplied storage: an unadjusted integer result, an integer result increased by 32, and a two-byte marker with numeric value 1024.

The two integer results depend on separate observations of the same external signed integer. The adjusted result uses the earlier observation; the unadjusted result uses the later observation. Consequently, the results differ by 32 only when those observations are equal and the addition is representable.

**Established static evidence:** the operation writes three regions, leaving gaps in its explicit destination coverage.

**Inferred intent:** these writes may populate fields within a larger object. Neither complete-object initialization nor an application meaning for the values is established.

This contract describes source-facing behavior and conditional deductions. No runtime tests have been performed.

## Behavior

### Result dependencies

The unadjusted result must reflect the later external observation. The adjusted result must reflect the earlier external observation increased by 32. The marker is independent of both observations and has numeric value 1024.

An implementation conforming to these dependencies cannot substitute the later observation into the adjusted result merely because the external source is the same. Conversely, the earlier observation is not the specified source for the unadjusted result.

When the source remains stable throughout the observations, the two integer outputs have the familiar relationship “adjusted equals unadjusted plus 32.” That relationship is conditional, not an unconditional invariant.

### Ordering and visibility

The represented ordering establishes these constraints:

- Both external observations precede destination modification.
- The unadjusted-result write precedes evaluation of the adjustment and the adjusted-result write.
- The marker write follows the adjusted-result write.

These constraints matter for legal overlap and for any environment in which the individual accesses have observable effects. In particular, destination writes cannot retroactively change either observation already used to determine the results.

The ordering describes the supplied static representation. It does not establish two physical load instructions, three indivisible hardware writes, or an externally visible transaction.

No volatile access, atomic access, synchronization, or cross-thread visibility guarantee is established. Separate physical reads are not required where the applicable execution rules permit equivalent accesses to be combined.

### Arithmetic

The adjusted result uses signed addition of positive 32. There is no represented range check, saturation, explicit wrapping rule, or recoverable overflow result.

For a signed type with maximum value \(M\), the earlier observation must be no greater than \(M - 32\). Adding positive 32 cannot cause lower-bound overflow for an otherwise representable input.

The marker’s numeric value is 1024. Under an eight-bit-byte interpretation, it fits both conventional signed and unsigned 16-bit representations. Its access signedness and exact byte sequence are not established.

### Untouched storage

For valid ordinary memory, with no independent writers or additional access effects, bytes outside the three written regions retain their preceding contents.

Under the four-byte-integer layout, this includes offsets 8–11 and, where present, offsets 14–15. The marker does not initialize the latter two bytes.

A consumer reading a four-byte quantity beginning at offset 12 would therefore include bytes not initialized by this operation. Such a read cannot be justified as reading a fully initialized field on the basis of this function alone.
