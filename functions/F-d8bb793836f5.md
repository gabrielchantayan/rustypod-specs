# F-d8bb793836f5

## Purpose

F-d8bb793836f5 exposes a recovered sequence of indirect calls, two word-sized stores, several byte-sized stores, and an unconditional repeating call-and-store cycle. The supplied material does not establish a higher-level application purpose.

The visible behavior combines:

- Address calculations derived from the first and fourth explicit inputs and additional machine state.
- Byte-selected destinations in a low-address range.
- Values obtained from indirect dependencies.
- Bit extraction and scaling of those returned values.
- An infinite loop with no visible normal return.

**Evidence limitation:** the supplied representation reports invalid instruction data and removed unreachable regions. This contract describes the visible recovered behavior, not a validated executable interpretation. Address validity, actual calling conventions, and the reliability of the recovered control flow remain unresolved.

## Behavior

### Arithmetic model and notation

This description uses descriptive names for values, not implementation identifiers:

- **Scaled first input:** the first input multiplied by four.
- **Entry selector base:** the additional incoming word logically shifted right by eight.
- **Fourth-input base:** the fourth input logically shifted right by seven.
- **Selected-byte destination:** read one unsigned byte at a specified base plus one, then add hexadecimal `0x11` to the byte value.

Every selected-byte destination therefore lies from hexadecimal `0x11` through `0x110`, inclusive. It is not the address of the selector byte itself.

For unsigned 32-bit values, masks, logical right shifts, and low-byte truncation have their ordinary bit-vector meanings. Left shifts and multiplication involving recovered signed values require qualification: the material does not establish whether the executable implements wrapping 32-bit arithmetic in every case. Examples involving such operations assume the stated 32-bit machine interpretation or values that avoid the ambiguity.

Dependency IDs below identify **call sites**, not proven distinct functions. The numbering is local to this contract and conveys no trusted external identity.

### Initial word writes and first result

The finite prefix begins with a word store of the first input at the address obtained by adding hexadecimal `0x14` to the scaled first input.

The entry selector base is then derived from the additional incoming word, before the first indirect call. The first dependency receives the scaled first input. Four further dependency calls follow; the last supplies a word-sized result.

After those five calls return, the same word-store address is written again, this time with the scaled first input rather than the original input.

The resulting order matters:

1. The first word store occurs before any visible dependency call.
2. Five dependency calls occur between the two word stores.
3. The second word store uses the previously calculated scaled value.

An intervening dependency may observe or alter the stored memory. The second store overwrites whatever occupies that location when execution reaches it.

### First selected-byte updates

The first returned result is shifted left by two and passed to the next call. Four further calls follow, with the last producing a result referred to here as the **first extracted word**.

The function then:

- Reads a selector byte at the entry selector base plus one.
- Stores the low byte of the first extracted word shifted left by two at the resulting selected-byte destination.
- Calls a dependency with three explicitly supplied arguments, each equal to that shifted word.
- Obtains an opaque 32-bit result from the following dependency and passes it unchanged to the next one.
- Executes four more calls, the last returning another word-sized result.

After those calls, it reads the selector byte again and writes a second value to the selected-byte destination. This value is the low byte of the first extracted word masked with hexadecimal `0x3FFFFFFF` and logically shifted right by twenty.

The second selector read is fresh. The earlier selected destination is not cached across calls. If a dependency changes the selector byte, the two stores can target different addresses.

Although this extraction initially produces ten bits, the byte store retains only eight. Its stored value is therefore determined by bits 20 through 27 of the first extracted word.

### Fourth-input-derived store and zeroing

The result from the last call in the preceding phase is shifted left by two and passed into another five-call sequence. The final call produces the **second extracted word**.

Next, in this order:

1. The low byte of the second extracted word shifted left by two is stored at the fourth-input base plus hexadecimal `0x1C`.
2. A fresh selector byte is read at the entry selector base plus one.
3. Zero is stored at that selected-byte destination.
4. A dependency is called with the fourth-input base.
5. One further call occurs.
6. A dependency receives the second extracted word masked with hexadecimal `0x3FFFFFFF` and logically shifted right by six.
7. Four further calls occur, the last producing another word-sized result.
8. The entry selector byte is read again, and zero is stored at its newly selected destination.

The fourth-input-derived byte-store address ranges from hexadecimal `0x1C` through `0x200001B`, inclusive.

The two zero stores are distinct observable accesses even when they select the same address.

### Transition into the repeating cycle

The most recent call result is shifted left by two and passed to another five-call sequence. Its final result supplies the **initial loop field**: mask with hexadecimal `0x3FFFFFFF`, then logically shift right by twenty-five.

This field ranges from 0 through 31.

A different selector base is now used. It is formed by multiplying the previously retained, left-shifted second extracted word by hexadecimal `0x400`. Under wrapping 32-bit arithmetic, this equals the second extracted word shifted left by twelve, with high bits discarded.

The function:

- Reads a selector byte at this alternate selector base plus one.
- Stores zero at its selected-byte destination.
- Calls a dependency with twice the initial loop field.
- Calls another dependency and retains its result as the first loop-carried argument.

The alternate selector base remains fixed throughout the visible loop. The byte read from that base does not remain fixed: it is reread for each loop zero store.

### Repeating cycle

Each iteration contains two five-call groups separated by a selector read and zero store.

The first group receives two explicit arguments on its first call:

- The current loop-carried argument.
- The current loop field logically shifted right by eight.

Its fifth call returns a word-sized result. The function then rereads the alternate selector byte and stores zero at the selected destination.

The second group receives that result shifted left by two on its first call. Its fifth call returns the word used to prepare the next iteration:

- The next loop-carried argument is that word shifted left by two.
- The next loop field is that word shifted left by twenty-six.

The loop then repeats without a visible condition.

There is an important call-target distinction: the first call of the **first** iteration uses F-I37; the corresponding call in **all later** iterations uses F-I47. The remaining loop call sites are unchanged.

For the first iteration, the second argument is necessarily zero because the initial loop field is at most 31. Under wrapping unsigned 32-bit shifts, later iterations pass the previous terminal result’s low six bits shifted left by eighteen as their second argument. This follows from the left shift by twenty-six followed by a logical right shift by eight; it is not a direct right shift of the original result.

## Side effects

### Direct memory effects

Before the loop, the visible body performs:

- Two word stores to the first-input-derived address.
- Six byte stores:
  - Two nonconstant stores selected through the entry selector base.
  - One nonconstant store derived from the fourth input.
  - Two zero stores selected through the entry selector base.
  - One zero store selected through the alternate selector base.

Each completed loop iteration performs one additional selector read and one zero-byte store.

There is no visible validation of any address. There are no visible bounds checks, null checks, alignment checks, or explicit failure branches.

### Aliasing and access order

The contract does not require the memory regions to be disjoint. The word-store location, selector bytes, selected destinations, and fourth-input-derived destination may overlap.

If a store changes a selector byte, a later selector read must observe the memory state then in effect. If a dependency changes that byte, subsequent selection likewise uses the changed value. Assuming one stable selector or one stable destination would omit visible reads.

No atomicity, synchronization, volatility, or memory-mapped-device semantics are established.

The first store targets hexadecimal `0x13`; the second targets hexadecimal `0x18`. Reusing the first destination for both updates would not match the visible access sequence.

- Its first selected-byte store writes hexadecimal `0xE0`.
- Its later selected-byte store writes hexadecimal `0x23`.

### Fourth-input-derived destination

### Loop arguments and target transition

- Next loop-carried argument: 12.

- Next iteration’s second argument: hexadecimal `0x000C0000`.

That next iteration uses F-I47, not F-I37.
