## Side effects

The function visibly performs seventeen word stores before entering the byte-oriented portion. It then performs several byte stores and repeats another byte store indefinitely if execution continues.

The stores can alias each other, selector bytes, or memory used by dependencies. No disjointness guarantee is present. In particular:

- A selector must be re-read at every displayed occurrence.
- An earlier low-address store can change a later selector if their addresses coincide.
- An intervening dependency may change either selector memory or a destination.
- A repeated computed address does not imply repeated observed contents.

No explicit allocation, release, ownership transfer, locking, input/output operation, or global-state restoration is identified. Dependencies may perform any of these; their absence cannot be assumed.

Offset 20 is a recurring four-byte access location relative to several calculated bases. It is not sufficient evidence for a single common structure layout, a field type, or a minimum allocation size.

Invalid call destinations, inaccessible memory, unaligned word accesses, or overflow-sensitive addresses can prevent progress. The visible body contains no explicit recovery path.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Third-argument shift width.** If the third explicit input is 16,383, the later four-argument call receives zero in its fourth position. If it is 16,384, that position receives one. Treating the transformation as only one seven-bit shift is inconsistent with the displayed behavior.

2. **First word store.** If Input A is 4,294,967,295 and Base identifies accessible aligned storage, the first word store writes 16,777,215 at Base + 20.

3. **Repeated store is observable.** If a dependency between stores 4 and 5 changes their destination, store 5 overwrites that change with the previously calculated value. Removing store 5 is not behaviorally justified.

4. **Selector is not a pointer base.** If Selector base + 1 contains the byte 200, the next selector-based store targets address 217. It does not target Selector base + 217.

5. **Selector changes are respected.** If a dependency changes that selector byte from 200 to 3 between two stores, their respective destinations are 217 and 20.

6. **Byte truncation.** If Byte result A is 65, its two-bit-left-shifted value is 260; the first byte store writes 4.

7. **Masked byte extraction.** If Byte result A is 1,073,741,823, the later masked-and-shifted value is 1,023, whose stored low byte is 255.

8. **First loop argument constraint.** Whatever the result used to form Initial loop quantity, the loop’s first opening call receives zero in its second argument position.

9. **No normal completion promise.** With returning dependencies and successful accesses, reaching the tail entails continued iterations rather than a successful return.

All examples requiring memory or calls are conditional on those accesses and transfers being valid.
