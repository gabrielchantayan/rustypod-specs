# F-8fe91a385499

## Purpose

F-8fe91a385499 conditionally performs operations on a descriptor using a position and an adjustment calculated from two caller-supplied values. It checks two dependency results, obtains an extent-like value, validates an adjusted remainder, and selects an operation order according to the adjustment’s sign.

**Established behavior:** dependency invocation order, field reads, scalar conversions, conditional arithmetic, fixed rejection results, and propagation of a narrowed dependency status.

**Inferred intent:** the descriptor’s first field represents a backing address; one dependency obtains an extent and another requests an extent change. The evidence does not establish whether the overall operation inserts, removes, moves, resizes, allocates, or releases anything.

This contract describes the supplied static representation. It does not establish successful storage manipulation merely from a zero return.

## Interface

### Inputs and representation

The function receives four inputs:

| Input | Supplied representation | Visible role |
|---|---|---|
| Descriptor | Pointer to a signed 32-bit integer field | Null selects an immediate return path. Otherwise, its first field supplies address-like dependency arguments. |
| Position | Signed 32-bit integer | Compared with the extent and used in remainder and address calculations. |
| Baseline | Signed 32-bit integer | Compared with the target and subtracted from it. |
| Target | Signed 32-bit integer | Compared with the baseline; target minus baseline determines the adjustment. |

The supplied representation additionally uses:

- An 8-bit plain-character destination for the first state-query result.
- An unsigned 32-bit destination for the second state-query result.
- A signed 16-bit destination for the extent-changing dependency’s result.
- A signed 32-bit function result and initial global value.

These widths describe the supplied representation, not an independently verified public ABI. In particular, the character destination’s signedness and the target’s out-of-range conversion rules are unresolved.

Only the descriptor’s first integer field is explicitly accessed. No complete descriptor size, additional field layout, storage extent, or alignment contract is established.

### Result

| Reached condition | Returned result |
|---|---|
| Null descriptor | Global value captured at entry |
| State condition fails | −117 |
| State condition passes and baseline equals target | 0 |
| Extent validation rejects the request | −50 |
| Extent-changing dependency is called | Its result converted to signed 16-bit form, then sign-extended to the function result width |

In the positive-adjustment branch, a converted-zero status permits a subsequent dependency call. Its result is ignored, and the function returns zero if that call returns control.

A dependency’s full-width nonzero result is not necessarily a nonzero function result: the signed 16-bit conversion determines the status used here.

### Preconditions

A null descriptor is explicitly supported. A non-null descriptor must be valid for every first-field read actually reached. Dependency calls may impose additional requirements that the supplied evidence does not establish.

The caller cannot rely on this function to independently reject:

- A negative position, baseline, or target.
- A negative extent-like result.
- A zero or otherwise invalid address-like first field.
- An overflowing arithmetic operation.
- Invalid addresses passed to dependencies.

Such inputs may be rejected by the visible comparisons, may reach dependency calls, or may exceed the established arithmetic model.

## Behavior

### Entry global read

The first explicit operation reads a global signed integer and retains its value as the prospective result. This occurs before the descriptor-null check.

If the descriptor is null, the captured value is returned. No descriptor field is read and no listed dependency is explicitly called on this path.

The global’s meaning, initialization, synchronization, and relationship to errors are **documented_only**. The function does not explicitly reread it before returning.

### Two state queries

For a non-null descriptor, the function calls F-c19b4c0cb7f7 twice in sequence. Each argument is constructed by reading the descriptor’s current first field and adding 10.

These are separate field reads. The first dependency call can therefore affect the second call’s argument if it changes the field and leaves the descriptor valid for the subsequent read.

The results receive different treatment:

1. The first result is converted to the represented plain-character type.
2. The second result is converted to unsigned 32-bit form.

Both calls complete before the combined state condition is evaluated. A failing first result does not suppress the second call.

The condition is evaluated in this order:

1. Compare the character-converted first result with zero.
2. Only if it equals zero, test whether masking the unsigned second result with 0x0000FF00 produces zero.

If either required test fails, return −117. No extent query or later operation is explicitly invoked.

The established first condition concerns the **character-converted result**, not an unconditional extraction of the original result’s low byte. An 8-bit width alone does not establish conversion of every out-of-range value. Under a target conversion that retains the low eight bits, only those bits determine whether the converted result is zero. Without that conversion rule, this interpretation remains conditional.

The second condition is established directly: only bits 8 through 15 of the unsigned 32-bit result affect its mask test. Other bits need not be zero.

The two calls are separate observations; no atomic snapshot or consistent-state guarantee is established.

### Equal baseline and target

After successful state checks, the baseline and target are compared.

If equal, the function returns zero without querying the extent or invoking either later dependency. Position is not validated on this path.

Consequently, an otherwise invalid or negative position does not independently prevent this return. The initial global read and both state-query calls still occur.

### Extent query and adjustment

For unequal baseline and target, the function calls F-48d3618d091a with the descriptor. Its signed result is used directly as an extent-like value.

After this call returns, the function calculates:

**Adjustment = target − baseline.**

No separate error classification is applied to the extent result. A negative value enters the same validation as any other signed result.

The adjustment calculation precedes the validation below. An early rejection within that validation does not suppress the earlier subtraction of baseline from target.

### Ordered validation

Validation has an observable short-circuit boundary:

1. Compare extent with position.
2. If extent is smaller, return −50 without calculating the remainder expression.
3. Otherwise, subtract position from extent, then add adjustment.
4. If the resulting adjusted remainder is negative, return −50.
5. Otherwise, select the adjustment-sign branch.

The subtraction and subsequent addition must not be treated as unconditional operations performed before the first comparison.

For example, with extent −2147483648 and position 1, the first comparison rejects the request. Subtracting 1 from that extent is not evaluated. This avoids that particular otherwise out-of-range subtraction on this execution path, but does not establish general overflow safety.

For representable arithmetic, successful validation establishes:

- Position does not exceed extent.
- The adjusted remainder is nonnegative.

It does not independently establish a nonnegative position, nonnegative extent, representable requested new extent, or valid later address arguments.

### Nonpositive-adjustment branch

After validation, an adjustment less than one selects this branch. Operations occur in this order:

1. Read the descriptor’s current first field.
2. Add position to that value, then subtract adjustment.
3. Call F-70a021fc7c24 with that single visible argument.
4. Call F-a5bc00364bd0 with the descriptor and the previously obtained extent plus adjustment.
5. Convert the latter result to signed 16-bit form.
6. Sign-extend that converted status and return it.

The result of F-70a021fc7c24 is ignored.

Under ordinary representable subtraction, this is the negative-adjustment case: equal baseline and target have already returned, so zero adjustment is not produced by the remaining unequal inputs. The actual branch comparison nevertheless includes zero.

The first operation occurs before the extent-changing status is known. A nonzero returned status does not trigger an explicit rollback.

Only one argument is visible for F-70a021fc7c24 on this path. The evidence does not authorize inventing another argument or assigning it a default value.

### Positive-adjustment branch

For a positive adjustment:

1. Call F-a5bc00364bd0 with the descriptor and the previously obtained extent plus adjustment.
2. Convert its result to signed 16-bit form and sign-extend the status.
3. If that status is nonzero, return it without calling F-70a021fc7c24.
4. If the status is zero, call F-70a021fc7c24 with two visible arguments:
   - The current descriptor first-field value plus position.
   - The current descriptor first-field value plus position, then plus adjustment.
5. Return zero after that call returns control.

The first-field reads for this final call occur after F-a5bc00364bd0 returns. The function does not reuse a backing value captured before that call.

The two argument expressions contain separate field reads. Their relative evaluation order is not established. Both use the same backing value only if the field remains stable across those reads.

The final call’s result is ignored. A zero function result on this path establishes a converted-zero extent-changing status and return of control from the final call, not a checked success result from that final call.

### Arithmetic and conversion limits

No explicit overflow check is shown for:

- First field plus 10.
- Target minus baseline.
- Extent minus position, when reached.
- Adjusted remainder addition.
- Extent plus adjustment.
- Address-like argument construction.

The order of arithmetic remains significant. The validation subtracts position before adding adjustment. The nonpositive-branch argument adds position before subtracting adjustment.

This contract does not replace these operations with wider, saturating, or arbitrary-precision arithmetic. Behavior outside the supported target range is **documented_only**.

Conversion uncertainty applies separately to:

- The first state-query result’s plain-character conversion, including signedness and out-of-range handling.
- The extent-changing result’s signed 16-bit conversion.

For the latter, the converted status—not the original full-width result—controls both the returned value and positive-branch continuation.

### State continuity and failure

An error result does not imply an unchanged object:

- −117 follows two state-query calls.
- −50 follows those calls and an extent-query call.
- The nonpositive branch invokes F-70a021fc7c24 before obtaining the status it returns.

## Acceptance examples

These are conditional static acceptance cases, not observed runtime results. Unless stated otherwise, state checks pass, dependencies return control, and reached arithmetic and memory operations are valid.

1. **Null descriptor.** If the entry global read yields 23 and the descriptor is null, return 23 without explicitly invoking any listed dependency.

2. **First converted result fails.** If the first query’s character-converted result is nonzero, the second query still occurs. Return −117 without evaluating its mask test.

3. **Conditional low-byte interpretation.** If the target’s character conversion retains the low eight bits, a first query result of 0x00000100 converts to zero. With a second unsigned result of 0x00000001, both checks pass. Without that target conversion rule, the first outcome is **documented_only**; the second mask outcome remains established.

4. **Second mask rejects.** If the first converted result is zero and the second unsigned result is 0x00000100, return −117 because the mask selects a nonzero value.

5. **Equal values bypass validation.** Equal baseline and target produce zero after successful state checks, even with a negative position. No extent query occurs.

6. **Position exceeds extent.** Extent 8 and position 9 produce −50 at the first validation comparison. Do not evaluate the remainder or call either later dependency.

7. **Signed-boundary short circuit.** With extent −2147483648, position 1, baseline 0, and target 1, calculate adjustment +1, then reject with −50. Do not evaluate extent minus position, the remainder addition, requested-extent arithmetic, or mutation arguments.

8. **Negative adjusted remainder.** Extent 10, position 8, baseline 5, and target 2 give adjustment −3. The first comparison passes; the remainder becomes −1. Return −50.

9. **Negative adjustment at the boundary.** Extent 10, position 8, baseline 5, and target 3 give adjustment −2 and adjusted remainder zero. Call F-70a021fc7c24 with current first field plus 10, then F-a5bc00364bd0 with requested extent 8. Return the latter’s converted status.

10. **Positive adjustment fails.** Extent 10, position 4, baseline 1, and target 4 request extent 13. If the converted status is −7, return −7 without calling F-70a021fc7c24.

11. **Post-call field reads.** For the preceding positive adjustment, if the extent-changing dependency produces converted zero and changes the first field, the final arguments use post-call field reads plus 4 and plus 7. A shared backing value requires stability across those reads.

12. **Negative position may pass.** Extent 10, position −1, and adjustment +1 give adjusted remainder 12. Validation passes; later address validity remains a separate unresolved requirement.

13. **Narrowed status controls continuation.** If the target converts a full-width result of 65536 to signed 16-bit zero, the positive branch proceeds to F-70a021fc7c24. This example is conditional on that conversion rule. Any nonzero converted status instead returns immediately.
