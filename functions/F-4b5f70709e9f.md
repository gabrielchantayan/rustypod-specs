# F-4b5f70709e9f

## Purpose

F-4b5f70709e9f performs selector-dependent updates to a globally addressed, word-oriented state block.

Selectors 2 and 4 execute an extended sequence containing two dependency calls, configuration writes, a 35-word read–modify–write sweep, repeated writes to one command-like location, and a final bit-setting update. Selector 1 performs a short update. Selector 3 clears one bit. Other selector values return after reading the global base slot.

The sparse layout and repeated writes suggest hardware configuration, but that interpretation is not established. This contract specifies accesses, values, and ordering without assigning device-specific meanings. Repeated writes are distinct operations in the supplied representation, not merely a description of the final stored value.

## Interface

### Input and result

The function accepts one integer selector and distinguishes exactly 1, 2, 3, and 4. All other representable values follow the default return path.

There is no explicit return value, status output, or error result.

### Width and layout model

The accessed words are represented as unsigned integers. The masks and four-byte sweep stride support a 32-bit-word interpretation. This contract uses that interpretation for byte offsets, bit numbers, and arithmetic examples.

Definitive type widths, pointer widths, and ABI details are **documented_only** unknowns. Consequently, the 32-bit layout and modular-arithmetic examples are conditional on that interpretation rather than independently verified binary properties.

Bit numbers start at zero. All offsets below are byte offsets. A word at B + 0x014 is therefore the sixth 32-bit word beginning at B.

### Global sources and address notation

| Label | Meaning |

| **B** | Address captured from the base slot at function entry. |
| **First argument pointer slot** | Global storage containing the address from which the first dependency argument is read. |

B remains the entry-captured address for accesses expressed relative to B. Early selector-specific accesses described as occurring “through the base slot” instead use that global address source at the reached operation. The contract does not assume that the base slot remains unchanged or that all evaluations of it necessarily produce the same address.

- Each argument pointer to address a readable word when evaluated.

- Address formation to remain valid in the actual execution model.
- Both dependencies to return normally.

There are no explicit validity checks, range checks, timeouts, or recovery operations.

## Behavior

### Dispatch and initial base capture

The function captures B before selector-dependent processing. This read occurs even for unsupported selectors.

| Selector | Direct path |
|---|---|
| 1 | Short update through the base slot, write at B + 0x014, return. |
| 2 | Extended sequence, including both additional command groups. |
| 3 | Single-bit clear through the base slot, return. |
| 4 | Preliminary full-word write through the base slot, then the extended sequence without the additional command groups. |
| Other | Return without an explicit addressed-word access or dependency call. |

### Selector 1

The first word addressed through the base slot undergoes a read–modify–write operation. Its replacement value is:

**(read value AND 0xF0FFFFFF) OR 0x0A100000**

Under the 32-bit interpretation, this replaces bits 24–27 with 0xA, sets bit 20, and preserves all other bits.

The function then writes 0x00000001 to B + 0x014 and returns. It does not execute either dependency, the sweep, the command writes, or the final extended-path update.

If the base slot changes or aliases writable storage, the first operation and the later B-relative write need not address the same block. The representation does not establish an atomic capture of the base slot across all evaluations within the first operation.

### Selector 3

The first word addressed through the base slot undergoes a read–modify–write operation with mask 0xFFEFFFFF.

This clears bit 20 and preserves the other 31 bits. The function then returns without any further explicit state-block write or dependency call.

As with selector 1, stability of the base slot during the operation is not guaranteed by the function.

### Extended entry: selectors 2 and 4

Selector 4 first writes 0x00000011 to the first word addressed through the base slot. Selector 2 has no corresponding preliminary write.

Both selectors then read the word at B and write back:

**(read value AND 0x00000007) OR 0x00000808**

This preserves bits 0–2, sets bits 3 and 11, and clears all remaining bits.

For selector 4, the result is 0x00000809 only if the preliminary write and this read address the same ordinary-memory word and no intervening effect changes its readable value. Device readback semantics or a changing base slot can invalidate that simplification.

### Argument evaluation and dependency calls

After the extended-entry update, the function evaluates the arguments for **F-unresolved-01**:

- The first argument is obtained by reading the first argument pointer slot, then reading the word addressed by that pointer.
- The second argument is obtained by reading the second argument pointer slot, then reading the word addressed by that pointer.

For each argument, the pointer-slot read precedes its dependent pointee read. The supplied representation does not establish a relative evaluation order between the two arguments. No stronger cross-argument ordering is specified.

These pointer slots and pointees are evaluated at this stage, not snapshotted at function entry. Earlier writes can therefore change an argument pointer or argument value if the relevant storage aliases a written location.

The function calls F-unresolved-01 with those two values in the stated argument positions. After it returns, the function calls **F-73ad38c1c987** with no explicit arguments.

Neither call has an explicitly consumed result. This does not establish whether either dependency returns a value. Neither dependency is assumed to preserve globals, preserve addressed memory, or retain its validity.

### Two configuration reads

After both dependencies return, the function performs two distinct reads of the configuration source:

1. It captures the first reading as a snapshot.
2. It reads the same global source again to obtain the value written to B + 0x200.

The second reading need not equal the snapshot. There is no explicit intervening write by this function, but concurrency, externally changing storage, or read side effects are not excluded.

Only B + 0x200 uses the second reading. The other configuration-derived writes below use the first snapshot, including both additions.

| 3 | B + 0x210 | 0x00001800 |

The snapshot remains the source for its listed uses even if the configuration global changes afterward, including through an aliasing write at B + 0x200.

Under 32-bit unsigned arithmetic, adding 0x40 wraps modulo 2³². There is no checked-addition error path.

The auxiliary source is read later than both configuration reads; it is not captured with them.

Next, B + 0x314 undergoes a read–modify–write operation with mask 0xFFFFFFEF, clearing bit 4 and preserving the other bits.

### Thirty-five-word sweep

After the B + 0x314 update, the function reads and captures the sweep address source.

It processes exactly 35 words in ascending address order:

- First word: captured sweep address.
- Stride: four bytes.
- Last word: captured sweep address + 0x88.

Each word is read and then written with its read value AND 0xFEFFFFFF. This clears bit 24 and preserves the remaining bits.

The write for one word occurs before the next word is processed. There is no bulk snapshot of the region.

Under the 32-bit-word interpretation, the highest byte accessed is at the captured sweep address + 0x8B. The sweep itself does not access the following word at +0x8C.

The source provides no range or address-overflow guard. Exact integer-to-address semantics and the behavior of invalid address arithmetic remain **documented_only** unknowns; safe completion requires valid address formation.

### Post-sweep updates

After the sweep, the function:

1. Writes 0x00000540 to B + 0x1CC.
2. Reads B + 0x1D4 and writes back that value OR 0x00000080.

The second operation sets bit 7 and preserves all other bits of its read value.

### Selector-2-only command groups

Selector 2 continues with two groups. Selector 4 skips both.

The first group performs:

1. A write of 0x00000033 to B + 0x00C.
2. A write of 0x00000133 to B + 0x004.
3. Three successive writes of 0x00000033 to B + 0x004.

The second group performs:

1. A read of the alternate source and a write of that value to B + 0x00C.
2. A write of 0x00000133 to B + 0x004.
3. Three successive writes of 0x00000033 to B + 0x004.

The alternate source is read at this late stage, after the first group. Earlier writes or dependency effects can affect it through aliasing.

### Final extended-path update

Both extended selectors finish by reading B + 0x008 and writing back that value OR 0x00061000.

This sets bits 12, 17, and 18 while preserving all other bits of the value read at that point. The function then returns.

## Side effects

Direct effects consist of global-source reads, indirect argument reads, the specified addressed-word operations, and the two extended-path calls.

Selector 1 performs two explicit addressed-word writes. Selector 3 performs one. Unsupported selectors perform none. Selectors 2 and 4 perform their complete extended sequences, with selector 4 adding its preliminary write and selector 2 adding its two command groups.

The function explicitly performs no allocation, deallocation, ownership transfer, locking, interrupt masking, or error reporting. This observation does not constrain dependency effects or device behavior. No ownership transfer is established merely by supplying the dependencies with values read through pointers.

Read–modify–write operations are not established as atomic. Concurrent updates between a read and its write can be overwritten.

Aliasing is not excluded among the state block, global sources, argument pointer slots, argument pointees, and sweep region. Accordingly:

- Extended-entry writes can change subsequently evaluated argument pointers or pointees.
- A write at B + 0x200 can affect later global reads without changing the already captured configuration snapshot.
- The sweep can modify locations accessed later.
- Multiple operations can target the same physical storage.

Such cases follow the represented access order; destinations must not be treated as independent final assignments.

The representation establishes an explicit access sequence, not independently verified machine instructions, bus transactions, barriers, or hardware visibility guarantees.

## Acceptance examples

These are conditional consequences of static evidence, not runtime results.

### Short update

Given selector 1, a stable base slot, ordinary memory, and an initial first word of 0xFFFFFFFF:

- The first word becomes 0xFAFFFFFF.
- B + 0x014 receives 0x00000001.
- Neither dependency executes.

### Single-bit clear

Given selector 3 and a stable ordinary-memory target initially containing 0x00100005, the replacement is 0x00000005. No further explicit addressed-word write occurs.

### Unsupported selector

Given selector 0:

- The base slot is read for the initial capture.
- No addressed word is explicitly read or written.
- Neither dependency executes.

The same behavior applies to every representable selector outside 1–4.

### Selector-4 entry

Given selector 4, a stable base slot, ordinary memory, and no intervening modification:

- The first word receives 0x00000011 and then 0x00000809.
- Argument pointer slots and their pointees are evaluated afterward.
- Both dependencies execute in order.
- The common 14-write sequence occurs.
- Neither selector-2-only group occurs.
- The final B + 0x008 update still occurs.

### Argument indirection affected by an earlier write

Suppose selector 4's preliminary write aliases the first argument pointer slot. If the replacement pointer value denotes a valid readable word in the actual address model, the first argument comes from that new target, not the pointer value present at entry.

No relative order between evaluation of the first and second arguments may be required by an acceptance check.

### Distinct configuration readings and unsigned wrap

Assume 32-bit unsigned words. If the first configuration reading is 0xFFFFFFE0 and the second is 0x12345678:

- B + 0x200 receives 0x12345678.
- B + 0x204, B + 0x220, and B + 0x224 receive 0xFFFFFFE0.
- B + 0x230 and B + 0x234 receive 0x00000020.

If both readings instead equal 0xFFFFFFE0, B + 0x200 also receives that value. Equality must be an explicit scenario assumption, not a requirement imposed by the contract.

### Sweep boundary

For valid ordinary-memory sweep storage:

- A visited word containing 0xFFFFFFFF becomes 0xFEFFFFFF.
- A visited word containing 0x01000000 becomes zero.
- The word at +0x88 is processed.
- The sweep itself does not process the word at +0x8C.

### Dependency changes to globals

If a dependency changes the configuration source, both configuration reads occur after that dependency returns.

If a dependency changes the base slot, subsequent B-relative accesses still use the entry-captured B. Completion requires that B remain valid; dependency preservation of its storage is not assumed.
