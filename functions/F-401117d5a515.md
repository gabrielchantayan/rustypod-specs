# F-401117d5a515

## Purpose

F-401117d5a515 describes an indefinitely repeated sequence of two indirect calls followed by a software interrupt. The first indirect-call target depends on an entry-associated value for the initial iteration and on a fixed value for subsequent iterations. The second indirect-call target is fixed in every iteration.

The supplied representation establishes the sequence and its lack of a normal exit. It does not establish the operation’s application-level purpose. In particular, the interrupt must not be classified as termination, a system call, a scheduler operation, or a debugging trap without additional platform evidence.

This contract distinguishes:

- **Established static evidence:** operations and control-flow relationships directly present in the supplied representation.
- **Inferred intent:** interpretations consistent with that representation but not proven by it.
- **documented_only unknowns:** unresolved interface, execution-environment, and dependency behavior.

No runtime tests have been performed.

## Behavior

### Initial iteration

On entry, the function begins an unconditional repetition. Before the first indirect call of each iteration, it establishes a working target base of `0x08579C95` for the second call.

For the initial iteration, the first indirect-call target is formed from **E** plus `0xEB6`, followed by interpretation of the resulting value as a callable address.

The function invokes that target with the three argument expressions specified in the interface. It does not inspect a result before proceeding.

If this first call returns normally to the represented continuation, the function invokes the second indirect-call target. That target is formed from the working base `0x08579C95` plus `0xCB6`.

The mathematical sum for this second target is `0x0857A94B`. This establishes the address expression, not the validity of the destination or its instruction-set interpretation.

If the second call returns normally, the function executes a software-interrupt operation with immediate value `0x5B`.

If execution continues normally after the interrupt operation, the function sets the base used by the first call to `0x083D4CC2`, then begins the next iteration.

### Subsequent iterations

For every iteration reached after that post-interrupt assignment, the first indirect-call target is formed from `0x083D4CC2` plus `0xEB6`.

The mathematical sum is `0x083D5B78`. Under ordinary 32-bit arithmetic, this particular constant addition does not overflow. Its interpretation as an executable destination remains platform-dependent.

The first call again receives zero, zero, and `0xFFFFFFA5`, in that order. If it returns, the second call again uses the address expression resolving mathematically to `0x0857A94B`. If that call returns, the software interrupt with immediate `0x5B` occurs again.

Normal continuation after each interrupt reestablishes `0x083D4CC2` as the first-call base for the following iteration. No counter, exit condition, or data-dependent loop termination is represented.

### Ordering and reachability

Within an iteration, the established order is:

1. Establish the fixed working base for the second call.
2. Invoke the first indirect target.
3. If it returns, invoke the second indirect target.
4. If it returns, execute the software interrupt.
5. If execution continues, assign the base for the next iteration.
6. Repeat.

Later operations are conditional on earlier operations returning or resuming into the represented continuation. The unconditional loop does not prove that multiple iterations occur in an actual execution.

A nonreturning first call prevents the second call and interrupt from being reached in that iteration. A nonreturning second call prevents the interrupt from being reached. An interrupt that does not resume prevents the next-base assignment and subsequent iteration from being reached.

There is no visible branch based on a callee result, error indicator, global value, or interrupt result.
