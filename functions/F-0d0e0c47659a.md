# F-0d0e0c47659a

## Purpose

The supplied static representation describes a routine that interleaves four byte writes with eighteen indirect function invocations. The first two writes select portions of an unsigned input. The last two write zero to destinations selected through a signed input. Three dependency results are shifted and passed to later dependencies.

No application-level purpose is established. In particular, the representation does not establish that these operations implement a device protocol, serialization, initialization, or memory cleanup.

The representation ends at an explicitly marked invalid-instruction boundary. It does not establish a normal return or the actual behavior beyond that boundary. This contract therefore specifies the observable prefix represented in the supplied material, conditional on execution reaching each operation successfully.

### Address and value layouts

Two selector mechanisms appear:

1. **Implicit-base selector:** read one unsigned byte at the implicit base plus one.
2. **Indexed selector:** read one unsigned byte at an address calculated as the signed input multiplied by 1024, then increased by one.

In both cases, add 17 to the byte that was read. The result is the destination address of a one-byte write. The byte is an address selector, not an offset added back to the original base.

Consequently, whenever a selector read succeeds, its selected destination lies numerically between 17 and 272 inclusive. This bound does not establish that those addresses are mapped, writable, ordinary memory, or safe to access.

The indexed selector’s own address has no comparable bound established here. Its calculation depends on signed arithmetic and the target address model.

### Selection and repeated reads

All four selector reads occur separately. No selector-byte snapshot is established across dependency invocations.

The two implicit-base writes therefore need not target the same address. Likewise, the two zero writes need not target the same address. Dependencies may change selector memory before a later read.

Aliasing can also matter without dependency intervention. A selected destination may overlap memory used by a later selector read. A write can consequently alter later address selection. The representation contains no alias check or protection against this.

The implicit base is represented as the same implicit input at both uses. Whether the actual calling convention preserves the machine state carrying that value across the intervening invocations is not independently established.

### Unsigned-input extraction

The first write stores the unsigned input modulo 256.

The second write first shifts the unsigned input right by 22, then retains the low eight bits of that result. It therefore stores original bits 22 through 29:

- Original bits 0 through 21 do not affect this write.
- Original bits 30 and 31 are discarded by the final one-byte conversion.
- The represented unsigned right shift is logical, not sign-extending.

No additional writes of the remaining input bits are shown. The two writes must not be described as a complete four-byte encoding of the input.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. They assume all required accesses succeed, relevant arithmetic is valid, and preceding dependencies return.

### Byte extraction

For an unsigned input of hexadecimal `FFFFFFFF`:

- The first direct write stores 255.
- The second direct write stores 255.

For an unsigned input of hexadecimal `C0000000`:

- The first direct write stores zero.
- The second direct write also stores zero.

The latter case distinguishes extraction of bits 22 through 29 from extraction of the top byte.

For an unsigned input of hexadecimal `004000AB`:

- The first direct write stores 171.
- The second direct write stores one.

### Selector bounds

These examples do not assert that either destination is usable on the execution platform.
