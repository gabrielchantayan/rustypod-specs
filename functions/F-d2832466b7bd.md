# F-d2832466b7bd

## Purpose

F-d2832466b7bd searches a dependency-supplied sequence of records for a matching key and a preferred 32-bit value. It returns a record address, or zero when traversal ends without a retained match.

The first input is an enable gate: zero disables the search; any nonzero value enables it. The function does not use that input as a record address, sequence handle, or argument to either dependency.

For enabled searches, the selection rules are:

- Consider only records whose key equals the requested key.
- Return immediately for a qualifying special value when the requested value is zero.
- Otherwise return immediately for an exact value match.
- In the absence of an immediate match, retain a candidate whose value is no greater than the requested value under unsigned comparison, replacing it only with a strictly greater eligible value.
- Return the retained candidate when traversal reports its end.

The description “greatest eligible value” assumes record fields remain stable during the search. The implementation rereads a retained candidate’s value when comparing later records; it does not preserve a separate snapshot of that value.

## Behavior

### Disabled search

When the enable gate is zero, the function returns zero immediately.

This path:

- Makes no calls to either listed dependency.
- Reads no record fields.
- Does not inspect the requested key or requested value to select a result.

### Starting and advancing traversal

With a nonzero gate, the function first calls F-63a239e63e43 without explicit arguments. Its return supplies the initial record address or zero.

A zero traversal result ends the search and returns the currently retained candidate, initially zero.

After a nonzero record has been processed without an immediate return, the function calls F-bbc912f1c01e without explicit arguments. Its return supplies the next record address or zero. This repeats until an immediate selection occurs, traversal reports zero, or execution otherwise fails to progress.

The function does not supply the current record address to the advancement dependency. Any relationship between successive results is therefore implemented through dependency behavior or state not exposed in this interface.

### Key filtering

For each nonzero current record, the first visible record-field read is the key at offset 8.

If this key differs from the requested key:

- The current record is not selected.
- Its value at offset 12 is not read by this function during that iteration.
- Any previously retained candidate remains retained.
- Traversal advances.

A nonmatching key does not terminate the search.

### Zero-request special selection

For a matching key and a requested value of zero, the function first reads the current record’s value field using the signed interpretation.

If that read yields −1, the function immediately returns the current record address.

Consequences:

- This special selection is available only for a zero request.
- Under the 32-bit model, the selected field has bit pattern `0xFFFFFFFF`.
- This case bypasses unsigned fallback eligibility: `0xFFFFFFFF` would otherwise be greater than zero.
- No advancement call follows this immediate return.
- The function does not continue searching for a later exact-zero record.

If this signed read does not yield −1, the function proceeds to a separate unsigned read of the same field.

### Exact selection

For every matching-key record that did not trigger the special return, the function reads the value field as unsigned and compares it with the requested value.

If the values are equal, the current record address is returned immediately.

This immediate return takes precedence over any previously retained fallback candidate. No later record is examined, and no advancement call follows the selection.

For a nonzero request, there is no preliminary signed special-value read. The unsigned value read is the first value-field read for that record.

For a zero request, the signed special check and the unsigned exact check are distinct reads. The supplied representation does not establish volatility, synchronization, or compiler-level guarantees about externally observable machine accesses. At the level of the represented operations, however, the two checks do not share a saved field value.

### Fallback candidate retention

If a matching-key record does not return immediately, its unsigned value is considered for fallback selection.

The current record is eligible only if its unsigned value is no greater than the requested value.

For an eligible record:

- If no candidate is retained, retain the current record address.
- Otherwise, read the retained candidate’s value field at offset 12 as unsigned.
- Replace the retained candidate only if that reread value is strictly less than the current record’s unsigned value.

An equal value does not replace the candidate. With stable records, ties therefore favor the earliest retained record in traversal order.

The visible representation includes an additional internal condition that remains true throughout execution. It does not introduce another externally selectable mode or disable fallback retention.

No subtraction, distance calculation, signed ranking, or wraparound-based ranking is performed. The fallback rule uses unsigned “no greater than” and “strictly less than” comparisons.

### End of traversal

When either traversal dependency returns zero, the function returns the retained candidate address, or zero if none has been retained.

Before returning a retained candidate at traversal end, the function does not:

- Reread its key.
- Revalidate its value against the request.
- Check that its contents are unchanged.
- Check ownership or lifetime.
- Copy the selected record.

Consequently, returning a pointer does not itself establish that the pointed-to record still satisfies the conditions under which it was retained.

### Ordering and mutable records

The observable operation order represented by the supplied material is significant:

1. Test the gate.
2. For an enabled search, invoke the initial traversal dependency.
3. For each nonzero result, read its key.
4. Only for a matching key, perform the applicable value reads and selection checks.
5. Read a retained candidate’s value only when a current record reaches fallback comparison and a candidate already exists.
6. Invoke the advancement dependency only if no immediate return occurred.

Dependency calls may change record contents or other state; no preservation guarantee is established. In particular, a candidate retained before an advancement call can have a different value when reread afterward.

The stable-data characterization—first special or exact match, otherwise the greatest eligible value—is therefore conditional. The established operation is comparison against the candidate’s value at the time of each later reread.
