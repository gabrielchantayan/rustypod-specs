# F-448a9f3886bd

## Purpose

F-448a9f3886bd dispatches an operation on a secondary object according to an initial virtual predicate and, when that predicate is nonzero, a subsequently obtained 32-bit classification. It prepares branch-specific arguments, invokes one of two secondary-object virtual operations, performs branch-dependent finalization calls, and returns a 64-bit concatenation of two local words.

The established contract concerns call selection, argument values, storage exposure, read timing, and finalization order. The application-level meanings of the predicate, classifications, and secondary-object operations are unknown.

On the nonzero-predicate branch, classification preparation consumes a value loaded from a global location. That value is not established as constant. The load occurs after the predicate returns, so effects of the predicate may influence the value supplied to classification preparation.

Classifications `0x23` and `0x40` select a distinct secondary operation and bypass an explicit finalization call performed for all other classifications.

## Interface

### Inputs and representation

The function accepts four arguments:

| Argument | Visible representation | Established use |
|---|---|---|
| First | Object pointer represented in 32 bits | Initial virtual-call receiver, source of subsequent object-field reads, and initial lower return word |
| Second | Opaque 32-bit word | Initial upper return word |
| Third | Opaque 32-bit word | Initializes storage later passed by address to dependencies |
| Fourth | Opaque 32-bit word | Initializes the word immediately following the third-argument storage |

The supplied representation uses four-byte object words, 32-bit pointers, and four-byte virtual-table entries. The first word of an object supplies its virtual-table pointer. The contract does not establish portability to a different pointer width or native calling convention.

No input is explicitly checked for validity.

### Exposed local storage

Before the first dependency call, the function initializes four consecutive 32-bit words in this order:

| Relative byte offset | Initial contents |
|---|---|
| `+0` | First argument’s pointer representation |
| `+4` | Second argument |
| `+8` | Third argument |
| `+12` | Fourth argument |

Two addresses into this storage are passed to dependencies:

- **Return-storage address:** points to the word at `+0`.
- **Working-storage address:** points to the word at `+8`.

These names identify storage positions, not proven object types. In particular, adjacency does not establish that either address designates a two-word object, an ownership-bearing pair, or a particular handle representation. The bounds and interpretation of dependency accesses remain dependent on contracts not supplied here.

The original first argument remains the receiver used for the visible object-field accesses. A dependency’s modification of the word at `+0` does not, by itself, redirect later accesses to the original object.

### Return value

Normal completion returns a 64-bit value composed as follows:

- Bits 31–0 contain the final 32-bit word at `+0`.
- Bits 63–32 contain the final 32-bit word at `+4`.

Both words are read after the last explicit finalization call. Their initial contents are not guaranteed to survive dependency calls.

The construction is bit concatenation. It does not sign-extend the lower word or use signed arithmetic. For example, final words `0x11223344` and `0x55667788`, respectively, produce `0x5566778811223344`.

### Preconditions

A defined, normally completing execution requires all accesses and calls reached on the selected path to be valid:

- The first object must support the initial virtual-table lookup and invocation at byte offset `0x1F8`.
- Object fields must remain readable at the times they are accessed.
- On the nonzero-predicate branch, the classification-argument global must be readable when loaded.
- Each captured secondary object must support the selected virtual-table lookup and invocation.
- Dependencies must accept the supplied storage addresses, argument representations, and current state.

There is no visible null check, bounds check, status-based recovery, or error translation.

## Behavior

### Initialization and initial predicate

The four local words are initialized from the four inputs before the initial virtual invocation.

The function reads the first object’s virtual-table pointer, resolves the entry at byte offset `0x1F8`, and invokes it with the original first argument as receiver. Its 32-bit result selects the branch:

- Exactly zero selects the direct branch.
- Every nonzero 32-bit pattern selects the classification branch.

No preservation contract for this predicate is supplied. It may affect the original object, reachable objects, or globals. All subsequent object-field reads and the classification-argument global load occur after it returns.

### Direct branch: zero predicate

The direct branch performs these operations in order:

1. Read and retain the secondary-object pointer from byte offset `0xE8` of the original first object.
2. Invoke **F-398e0e9a318a** with the working-storage address and a fixed address-valued operand.
3. Retain its 32-bit result as the prepared argument.
4. Read the captured secondary object’s virtual-table pointer and resolve the entry at byte offset `0x98`.
5. Invoke that entry with the captured receiver, a 32-bit zero, and the prepared argument.
6. Invoke **F-289ec4311c64** with the working-storage address.
7. Return the final two return words as the specified 64-bit concatenation.

The receiver is captured before preparation, but its virtual-table lookup occurs afterward. Consequently:

- A preparation-time change to the original object’s field at `0xE8` does not replace the captured receiver.
- A preparation-time change to the captured object’s virtual-table pointer can affect the subsequent lookup, assuming continued validity.

This branch does not explicitly load the classification-argument global or the field at `0x1A0`. It does not explicitly finalize the return-storage address.

The fixed operand supplied to F-398e0e9a318a is an address value. The visible caller passes that address; it does not establish the contents, mutability, or interpretation of the addressed storage.

### Classification preparation: nonzero predicate

The classification branch forms the arguments to **F-5710a8628cba** using three reads:

- The secondary-object field at byte offset `0xE8` of the original first object.
- A 32-bit value loaded from the classification-argument global.
- The 32-bit field at byte offset `0x1A0` of the original first object.

All three reads occur after the initial predicate returns and before F-5710a8628cba is invoked. Their relative evaluation order is not established.

F-5710a8628cba receives the values in this argument order:

1. The value read from the secondary-object field.
2. The loaded global value.
3. The value read from the field at `0x1A0`.

The middle argument is therefore a loaded value, not the global’s address and not a proven immutable constant. Its load is distinct from the fixed address-valued operand passed to F-398e0e9a318a.

After forming and making that call, the function proceeds in order:

1. Pass the working-storage address and the 32-bit result of F-5710a8628cba to **F-7afe554bcf62**.
2. Invoke **F-abb7a1ff7712** with the working-storage address and a 32-bit zero.
3. Invoke **F-9e5fecb2740f** with the working-storage address.
4. Use its 32-bit result as the classification.

The returns of F-7afe554bcf62 and F-abb7a1ff7712 are not explicitly consumed.

### Classification `0x21`

For the exact classification `0x21`, the function:

1. Reads and captures the current secondary-object pointer from offset `0xE8` of the original object.
2. Invokes F-398e0e9a318a with the return-storage address and the same fixed address-valued operand used on the direct branch.
3. Resolves virtual entry `0x98` on the captured secondary object after preparation.
4. Invokes that entry with the captured receiver, a 32-bit zero, and the 32-bit preparation result.
5. Invokes F-289ec4311c64 with the return-storage address.
6. Invokes F-289ec4311c64 with the working-storage address.
7. Returns the final return words.

The preparation address differs from the direct branch: this path supplies return storage rather than working storage.

### Classifications `0x23` and `0x40`

For either exact value, the function:

1. Reads and captures the current secondary-object pointer from offset `0xE8`.
2. Resolves its virtual entry at byte offset `0x9C`.
3. Invokes that entry with the captured receiver, a 32-bit one, and a 32-bit zero.
4. Invokes F-289ec4311c64 with the working-storage address.
5. Returns the final return words.

Neither classification causes a subsequent call to F-398e0e9a318a or F-bfbdead17716. Neither causes an explicit F-289ec4311c64 call with the return-storage address.

### Every other classification

Every classification other than `0x21`, `0x23`, and `0x40` follows this sequence:

1. Read and capture the current secondary-object pointer from offset `0xE8`.
2. Invoke **F-bfbdead17716** with the return-storage address and the classification.
3. Resolve virtual entry `0x98` on the captured secondary object after preparation.
4. Invoke that entry with the captured receiver, a 32-bit one, and the 32-bit preparation result.
5. Invoke F-289ec4311c64 with the return-storage address.
6. Invoke F-289ec4311c64 with the working-storage address.
7. Return the final return words.

This includes classification zero and every high-bit-set 32-bit pattern. There is no visible range check or arithmetic transformation of the classification before forwarding it.

### Completion and failures

The secondary virtual operations’ return values and finalization calls’ return values are not explicitly consumed. Their memory effects can still influence the final return.

These sequences describe normal completion. The supplied representation does not establish recovery or mandatory finalization if a dependency faults, fails to return, or transfers control nonlocally.

## Side effects

### Explicit writes

The caller initializes the four local words. It performs no further explicit writes to those words, the original object, the secondary object, or the classification-argument global.

Dependency-mediated writes remain possible. Passing a local address does not establish the dependency’s write bounds, ownership behavior, or preservation of adjacent words.

### Explicit reads

The caller explicitly reads:

- The original object’s virtual-table pointer and initial dispatch entry.
- The original object’s field at `0xE8` at branch-specific capture points.
- The field at `0x1A0` during classification preparation only.
- The 32-bit classification-argument global during classification preparation only.
- A captured secondary object’s virtual-table pointer and selected dispatch entry.
- The final two return words after the last working-storage finalization call.

On the classification branch, the global and both initial object-field arguments are read after the predicate returns. Their mutual read order is unspecified. Nothing establishes that the global retains an earlier value across the predicate call.

The secondary-object field used for classification preparation is read again after classification has been obtained. Intervening calls can therefore cause the later dispatch to use a different secondary object.

### Ownership and lifetime

No direct allocation, deallocation, reference-count operation, or ownership transfer is established.

“Preparation” and “finalization” describe call placement, not proven constructor or destructor semantics. In particular, omission of return-storage finalization for `0x23` and `0x40` must not be interpreted as either a leak or a justified ownership transfer without dependency evidence.

Both exposed addresses designate local storage valid during the calls. Whether dependencies retain them, and whether any later use would be valid, is unknown.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Zero predicate:** With valid objects and a zero predicate result, preparation receives the working-storage address. Secondary entry `0x98` receives flag zero and the preparation result. Working storage is then explicitly finalized once; return storage is not explicitly finalized.

2. **Global changed by predicate:** Suppose the classification-argument global initially contains `0x11111111`, and the nonzero-returning predicate changes it to `0x22222222`. If it remains at that value until the caller’s load, F-5710a8628cba receives `0x22222222` as its second argument. The earlier value is not preserved by this caller.

3. **Argument-read ordering:** An execution must not require the global load to precede or follow either classification-preparation object-field read. All three supply F-5710a8628cba after the predicate; their relative order remains unspecified.

4. **Classification `0x21`:** Classification preparation completes before F-398e0e9a318a receives return storage. Secondary entry `0x98` receives flag zero. Finalization order is return storage, then working storage.

5. **Classification `0x23` or `0x40`:** Secondary entry `0x9C` receives one and zero after its receiver. Only working storage is explicitly finalized.

6. **Classification zero:** A nonzero predicate followed by classification zero calls F-bfbdead17716 with return storage and zero. Secondary entry `0x98` receives flag one. The function does not switch to the direct branch.

7. **Return preservation:** If the first pointer representation is `0x12345678`, the second input is `0x9ABCDEF0`, and all calls preserve the two return words, the result is `0x9ABCDEF012345678`.

8. **Return mutation:** If the final return words are `0x11223344` and `0x55667788`, the result is `0x5566778811223344`, regardless of their initial values.

9. **Receiver capture:** If preparation changes the original object’s secondary-object field after capture, the ensuing operation still uses the captured receiver. If preparation instead changes that receiver’s virtual-table pointer, the subsequent lookup uses the changed pointer, provided all accesses remain valid.
