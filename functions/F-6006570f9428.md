# F-6006570f9428

## Purpose

F-6006570f9428 separates a nonzero finite binary64-shaped value into a signed fraction and an integer power-of-two exponent. It accepts the value as two 32-bit words, returns the fraction in the same two-word representation, and writes the exponent through a caller-supplied pointer.

For inputs whose exponent field is neither zero nor all ones, the separation is established directly by the visible bit operations. The returned fraction has the input sign and fraction field, with its exponent field replaced by 1022. Its magnitude is therefore at least one half and less than one.

Nonzero inputs with an all-zero exponent field first pass through F-9f634613286e with an additional argument of 54. The visible operations suggest that this dependency scales the value to normalize a subnormal input. That interpretation is inferred intent, not an established dependency contract. The behavior below specifies both the unconditional word-level processing and the numerical result conditional on that scaling interpretation.

Signed zeros, infinities, and NaN encodings are returned unchanged, with zero written to the exponent destination.

No runtime tests have been performed.

## Behavior

### Entry and classification

The first explicit memory operation is a 32-bit store of zero to the exponent destination. This happens for every input, before any possible call to F-9f634613286e.

For classification, the function clears the sign bit of the original high word. Call the resulting unsigned 31-bit quantity the magnitude high word.

The transformation path is taken exactly when both of the following hold:

1. The magnitude high word is less than hexadecimal `7FF00000`.
2. At least one of the magnitude high word and the original low word is nonzero.

Under the binary64 interpretation, this selects every finite nonzero input, regardless of sign.

Although the supplied representation expresses the first condition through 32-bit arithmetic and signed-overflow predicates, its complete effect is the unsigned threshold above. In particular, the intermediate split at hexadecimal `6FFFFFFF` does not create a separate semantic category or exclude ordinary finite inputs.

### Unchanged-return cases

If the transformation path is not taken:

- The returned low word equals the original low word.
- The returned high word equals the original high word.
- The exponent destination retains the zero written at entry.
- F-9f634613286e is not called.

This covers:

- Positive zero.
- Negative zero.
- Positive and negative infinity.
- Every encoding with an all-ones exponent field and a nonzero fraction field.

For NaN encodings, the sign and all payload bits are preserved in the returned representation. The function performs no visible payload canonicalization or quiet-bit modification on this path.

### Finite inputs with a nonzero exponent field

If the selected input has a nonzero exponent field, no dependency is called.

Let \(E\) denote the original 11-bit exponent field. On this path, \(E\) ranges from 1 through 2046.

The function:

1. Preserves the original low word.
2. Writes \(E - 1022\) to the exponent destination.
3. Constructs the returned high word by preserving the original sign bit and upper 20 fraction bits, and replacing the exponent field with 1022.

The destination therefore receives an exponent from −1021 through 1024, inclusive.

Under the binary64 interpretation, if the input value is \(x\), the returned value is \(f\), and the stored exponent is \(n\), this establishes:

\[
x = f \times 2^n,\qquad \frac12 \leq |f| < 1.
\]

This path performs representation changes rather than floating-point multiplication or division. The original fraction bits are retained exactly.

### Finite nonzero inputs with an all-zero exponent field

For a selected input whose magnitude high word is less than hexadecimal `00100000`, the function calls F-9f634613286e.

The dependency receives, in order:

1. The original low word.
2. The original high word, including its sign.
3. The integer value 54.

The dependency’s 64-bit return becomes the working representation. The original input words are no longer the source of the returned fraction fields.

After the dependency returns, the function writes −54 to the exponent destination. This store occurs even if the dependency itself changed that destination through some other accessible reference.

Let \(E'\) be the 11-bit exponent field extracted from the dependency’s returned high word after clearing its sign bit. The function then reads the exponent destination and writes its adjusted value. In an ordinary execution without intervening external modification, that value is:

\[
E' - 1076.
\]

The returned representation is constructed as follows:

- Its low word is the dependency’s returned low word.
- Its sign bit is the dependency’s returned sign bit.
- Its 52 fraction bits are the dependency’s returned fraction bits.
- Its exponent field is replaced with 1022.

There is no second classification of the dependency’s result. A returned zero, infinity, or NaN encoding is processed by these same rules rather than being returned unchanged.

Consequently, for any dependency result with well-defined returned bits, the final representation has an exponent field of 1022. Since \(E'\) can range from 0 through 2047, the corresponding final exponent calculation ranges from −1076 through 971. These calculations fit within a signed 32-bit integer.
