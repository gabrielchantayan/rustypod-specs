# F-09e1642715d3

## Behavior

The established normal-path behavior has the following order:

1. Form the address of the input-relative field at byte offset 48.
2. Read the integer-sized value stored in that field.
3. Use the value just read as the base for a second byte offset of 3,832.
4. Store the one-byte numeric value 1 at the resulting destination.
5. Return without a value.

This is an externally relevant ordering contract, not a guarantee about the number or shape of processor instructions.

The destination is **not** input base plus 3,880. The first offset locates a field whose contents supply another base address. Adding the two offsets directly would omit the required indirection and would generally select a different location.

There is no explicit read of the destination’s previous contents. The store is unconditional once its destination has been obtained: the routine does not compare the old value with zero, test whether the field is already set, or preserve selected bits. For ordinary byte-addressable memory, a previous byte of any value is replaced by 1.

Only one address-bearing field read is expressed. If the destination overlaps that field, the store can modify part of the field after its value has already been used to calculate the destination. No subsequent reread or corrective update is shown.

There are no explicit branches, loops, dependency calls, or alternate normal paths. In particular, the routine contains no null check, bounds check, object-type check, or access-permission check.

## Acceptance examples

These examples are conditional specifications, not reports of execution.

1. **Ordinary destination update**

   Given a valid input-relative slot containing an address to a writable region, and a destination byte at that region’s offset 3,832 currently equal to 0, normal completion leaves that byte equal to 1.

2. **Replacing a nonzero byte**

   Given the same valid layout with a destination byte initially equal to 255, normal completion leaves it equal to 1, not 255 and not a bitwise combination of the old value with 1.

3. **Destination already contains 1**

   Given a destination byte already equal to 1, the routine still expresses a store of 1. Its ordinary-memory final value is unchanged; the contract does not authorize skipping an otherwise observable write.

4. **Indirection determines the destination**

   Given two valid input bases whose slots contain the same address, both calls select the same destination byte, provided those slot contents remain stable. Different input bases do not by themselves imply different destination locations.

5. **Neighboring bytes**

   Given an ordinary writable memory region with no concurrent modification, normal completion changes only the selected destination byte through the routine’s explicit store. Adjacent bytes are not cleared or assigned as part of a wider destination write.

6. **Slot and destination overlap**

   Given an execution environment in which the derived destination is a writable byte within the address-bearing slot, the routine first obtains the slot’s value and then writes 1 at the derived location. The stored slot representation may therefore differ afterward. No second slot read is required.

7. **Unreadable input-relative slot**

   Given an inaccessible slot at input-relative offset 48, successful normal completion is not promised. No explicit error return or fallback destination is specified.

8. **Unwritable derived destination**
