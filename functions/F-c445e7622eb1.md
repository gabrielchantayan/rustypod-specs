# F-c445e7622eb1

## Purpose

F-c445e7622eb1 performs an ordered sequence of byte, halfword, and word memory updates, derives additional addresses from memory, and then transfers control to an unresolved indirect dependency.

The supplied static evidence establishes these memory operations and the four arguments supplied to the indirect dependency. It does not establish a higher-level purpose, a conventional object model, or a complete calling convention. In particular, several essential incoming values are not represented by the four explicit parameters. Consequently, this is a conditional contract for the supplied representation, not a claim that an ordinary four-argument invocation is sufficient.

No allocation, resource acquisition, ownership transfer, or memory release is directly established. Whether the final dependency performs any such operation is unknown.

## Behavior

### Interpretation rules

The visible widths are one byte, two bytes, and four bytes. A byte write retains the low eight bits of its source. A word write transfers all 32 bits. The two-byte write transfers the value 0x0065.

Byte order is not established by the supplied material. Thus a four-byte write that overlaps an earlier byte write is established to replace the overlapping storage, but the resulting individual byte values cannot be specified without the target byte order.

The following phases describe the required observable access order. They are not independent transactions: later phases consume memory after earlier writes have occurred. Unless explicitly conditioned on non-aliasing, values are those present when each read happens.

### Initial updates and first loaded word

The first two operations are byte writes to the primary region, at offsets 0x0D and 0x09, in that order. Both receive the low byte of the secondary base.

Next, a four-byte write at tertiary offset 0x54 stores the tertiary base itself. Global byte A then receives the low byte of the second explicit parameter.

A word is read from tertiary offset 0x44. Call this the **initial loaded word**. Global byte A is then read and its value written to global byte B. The low byte of the initial loaded word is written at primary offset 0x10.

The initial loaded word is next written as a full word at secondary offset 0x54. A shifted byte derived from that same loaded word is then written at tertiary offset 0x01.

The shift count is the low eight bits of the primary base. The representation applies a right shift to a signed 32-bit value before narrowing the result to a byte. For counts from zero through 31, the operation is identifiable as a signed right shift in the representation, although the exact target rule for negative operands is not independently established. Counts from 32 through 255 require architecture-specific evidence; this contract does not assume a masked count, a zero result, or sign saturation.

### Primary-region replacement and linked-address capture

The next word write at secondary offset 0x54 replaces the earlier stored initial loaded word with the primary base.

A word is read from primary offset 0x40. After that read, the auxiliary word is written at secondary offset 0x74. The word previously read from primary offset 0x40 is then written at primary offset 0x10, replacing the four bytes starting there, including the earlier byte write at that offset.

The tertiary base is written as a word at secondary offset 0x44. Global byte A is read again and written to primary offset 0x09. A byte write at tertiary offset 0x09 then stores the low byte of the primary base.

The full second explicit parameter is written at primary offset 0x44. A word is subsequently read from primary offset 0x54; this becomes the **linked base**.

Global byte A is read once more and written to primary offset 0x09. The fourth explicit parameter is then written as one byte at linked offset 0x0D.

These repeated writes are part of the visible behavior. They cannot generally be collapsed into one final assignment: intervening operations may alias those locations or observe them through address-dependent accesses.

### Linked-region updates and doubled-address write

The third explicit parameter is written as a word at tertiary offset 0x54.

A word is read from primary offset 0x14. Call it the **captured primary word**. The fourth explicit parameter is then written as a byte at tertiary offset 0x11.

Next, primary offset 0x09 receives the low byte of the linked base. Primary offset 0x44 receives the linked base as a full word, replacing the earlier full-width write of the second explicit parameter to that same location.

A word is read from tertiary offset 0x04. Call it the **index base**. A two-byte value of 0x0065 is written to the address obtained by doubling the index base. This is an absolute derived address, not an offset within a separately established allocation.

A word is then read from index offset 0x64, where 0x64 is decimal 100. Call it the **loaded destination value**. The timing matters: if the preceding two-byte write overlaps this read, the read observes the resulting memory rather than the earlier contents.

The low byte of the captured primary word is written at linked offset 0x11. A full word containing decimal 100 is then written at linked offset 0x54.

### Final reads, writes, and indirect invocation

A word is read from index offset 0x74. This becomes the **captured call word**.

A word is then read from tertiary offset 0x64. Call it the **final base**. Tertiary offset 0x09 receives the low byte of the index base.

The loaded destination value is written as a word at final offset 0x54. After that, the final base is written as a word to the address obtained by doubling the loaded destination value.

Only after these memory operations does the function invoke the unresolved indirect dependency. Its four visible arguments, in order, are:

1. The value 0x72, or decimal 114.
2. The loaded destination value.
3. The third explicit parameter.
4. The captured call word.

The fourth argument is the previously captured value, not an established reread of index offset 0x74 immediately before invocation. Intervening writes may therefore change the memory location without changing this argument.
