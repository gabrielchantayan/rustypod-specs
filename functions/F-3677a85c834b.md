# F-3677a85c834b

## Purpose

F-3677a85c834b selects a 32-bit value from a signed input and two externally supplied fallback values, stores the selection in a caller-designated object, and passes a four-byte representation through two dependencies before invoking a third dependency with an object-associated destination.

The selection is range-based replacement, not established saturation. Inputs from −32767 through 32767 are retained. Inputs below that interval select a lower-range fallback; inputs above it select an upper-range fallback. The fallback values themselves are not available in the supplied evidence and are not shown to satisfy the interval.

The dependency sequence suggests construction and submission of a value-bearing item. That interpretation is inferred intent only. Allocation, serialization, delivery, and memory ownership are not established by the visible operations.

## Behavior

### Selection and external reads

The lower-range fallback is read first, regardless of the input’s value. This read occurs even when that fallback will not be selected.

The signed input then determines which value is selected:

| Input condition | Selected value |
|---|---|
| Input less than −32767 | Lower-range fallback |
| Input from −32767 through 32767, inclusive | Input itself |
| Input greater than 32767 | Upper-range fallback |

If the input is below −32767, the upper-range fallback is not read by the visible selection path.

Otherwise, the upper-range fallback is read before the upper-bound decision completes. Consequently, an in-range input still causes both fallback locations to be read, even though neither fallback determines the selected value.

The interval is intentionally described exactly as observed. Its lower endpoint is −32767, not −32768. Thus −32768 takes the lower-fallback path, whereas −32767 is retained.

The comparisons are signed 32-bit comparisons. No narrowing to 16 bits, masking, absolute-value calculation, or arithmetic adjustment of the input is shown. A selected fallback is used as a complete 32-bit value without a second range check.

### Initial state update

After selection, the function writes the selected value to the object’s four-byte field at byte offset 32.

This store precedes all three dependency invocations. The visible function does not defer the store until construction or submission succeeds, and it contains no rollback path.

The selection also remains in a local four-byte storage location whose address is later supplied to F-afb630a7107c. The object field and this local storage are separate locations. Writing the object field is not the same operation as passing its address to the dependency.

### Dependency sequence

After the object store, the function invokes the dependencies in this order:

1. **F-0a77364c41cc** receives the integer value 12. Its four-byte result becomes an input to the next dependency.
2. **F-afb630a7107c** receives that result, the construction descriptor, the address of the local selected-value storage, and the integer value 4. Its four-byte result becomes an input to the final dependency.
3. **F-2cb84dcba01a** receives the four-byte value read from the object at byte offset 4 and the result of F-afb630a7107c.

The construction descriptor is obtained for the second invocation after the first dependency returns. The object’s offset-4 field is read for the final invocation after the second dependency returns. Neither value is established as a snapshot taken before the dependency sequence.

This timing matters if a dependency can affect shared state. In particular, the destination supplied to F-2cb84dcba01a is the value observed after F-afb630a7107c returns, not necessarily the value present on entry to this function.

The local selected-value storage initially contains the value written to offset 32. F-afb630a7107c receives its address, however, so the visible evidence does not establish that the dependency only reads it or that its contents remain unchanged during the call.

After the final invocation returns normally, this function returns without an explicit result.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests. They assume valid accessible storage and normal returns from dependencies.

### Inclusive range boundaries

For an input of −32767, the selected value is −32767. For an input of 32767, it is 32767.

In both cases, the lower-range fallback is read first and the upper-range fallback is also read. The input, rather than either fallback, is written to offset 32 before F-0a77364c41cc is invoked.

### First values outside the interval

For an input of −32768, the lower-range fallback is selected. The upper-range fallback is not read by the selection path.

For an input of 32768, the upper-range fallback is selected. Both fallback reads occur.

These cases distinguish the behavior from both signed-16-bit narrowing and clamping to the numeric interval endpoints.

### Fallback outside the accepted interval

Suppose the lower-range fallback contains −100000 and the input is −40000. The selected value is −100000, not −32767.

Likewise, if the upper-range fallback contains 100000 and the input is 40000, the selected value is 100000. There is no visible revalidation of either fallback.

### Destination changed during construction

### Dependency returns zero
