# F-681bb0b88f0d

## Purpose

F-681bb0b88f0d coordinates mode-dependent processing of a descriptor-backed memory region. It optionally performs common-header and trailing-table processing, dispatches according to a one-byte discriminator, and optionally performs common processing after dispatch.

The established behavior is the ordering of explicit memory accesses, dependency invocations, arguments, and return-value propagation. The implementations of the dependencies are unavailable. In particular, the supplied evidence does not establish that an address-taking dependency swaps byte order, validates data, or confines its effects to the addressed field.

**Inferred intent:** the paired entry and exit processing, together with address-taking operations at apparent 16-bit and 32-bit fields, suggests representation conversion around discriminator-specific handling. This interpretation is not required to describe the observable contract.

## Behavior

### 1. Capture the entry address

The function reads the region address from descriptor offset 0 and retains it as the entry address. It initializes its return value to zero.

All later references to the entry address use this captured value, not an automatically refreshed descriptor address.

### 2. Perform entry common processing only when mode is 0

For mode 0, the following dependency calls occur in order:

1. F-bb2eb79124b3 receives the entry address.
2. F-bb2eb79124b3 receives the entry address plus 4.
3. F-df70a2b0a7d8 receives the entry address plus 10.

Only after these calls does the function read the unsigned 16-bit count at entry offset 10.

It then reads the size-like word at descriptor offset 12 as an unsigned 32-bit value and rereads the region address at descriptor offset 0. These values form a snapshot for trailing-table addressing.

Let:

- \(N\) be the count read after the three calls.
- \(L\) be the unsigned size-like word.
- \(B\) be the region address reread from the descriptor.

The first trailing-table address is:

\[
T = B + L - 2N - 2
\]

Address arithmetic uses the 32-bit model. The count contribution ranges from 0 through 131,070 before the additional subtraction of 2.

The function compares \(N\) with \(\lfloor L/16 \rfloor\), obtained by an unsigned right shift of the size-like word by four bits.

- If \(N \leq \lfloor L/16 \rfloor\), it does not explicitly change the count.
- If \(N > \lfloor L/16 \rfloor\), it writes a 16-bit zero at entry offset 10.

**The starting address \(T\) is calculated from the original count snapshot. Clearing the stored count does not recalculate that address.**

The function next processes trailing entries in ascending two-byte address steps. Before each iteration it rereads the unsigned 16-bit count at entry offset 10. An iteration with index \(j\), starting at zero, occurs only while:

\[
j < \text{current stored count} + 1
\]

For each admitted iteration, F-df70a2b0a7d8 receives \(T + 2j\).

Consequences:

- If the stored count remains \(N\), there are \(N+1\) calls, not \(N\).
- If the excessive-count condition clears the count and dependencies do not change it again, there is still one call, at the address calculated using the original \(N\).
- The loop bound is dynamic. Dependency effects on entry offset 10 can change the remaining number of calls.
- The starting address and descriptor-derived base are not refreshed within the loop.
- The maximum possible number of iterations is 65,536 because each reread count is an unsigned 16-bit value. Adding one is not a 16-bit operation and does not wrap 65,535 to zero.

### 3. Read and dispatch on the discriminator

After any entry common processing, the function reads the discriminator byte at entry offset 8. Thus, for mode 0, effects of the preceding dependencies can influence dispatch.

Only one discriminator read controls this dispatch.

#### Discriminator 0x00 or 0xFF

The selector determines the dependency:

- Selector equal to zero: call F-eb7059546694 with the descriptor, context, and mode, in that order.
- Selector nonzero: call F-3afc0660a2da with no explicit arguments shown in the supplied call.

The selected dependency’s 32-bit return value replaces the initialized zero result.

The selector’s magnitude and sign otherwise have no effect. The context is forwarded only on the selector-zero branch.

#### Discriminator 0x01

The function rereads the region address from descriptor offset 0 once. Using that refreshed address as a fixed base for this entire sequence, it makes these calls in order:

| 5 | F-bb2eb79124b3 | 28 |

#### All other discriminator values

No discriminator-specific dependency is called. In particular, discriminator 0x02 is not routed to the discriminator-1 sequence.

The initialized return value remains zero.

### 4. Perform exit common processing only when mode is 1

For mode 1, this phase occurs after discriminator-specific work, including any delegated call.

The function first calls:

1. F-bb2eb79124b3 with the entry address.
2. F-bb2eb79124b3 with the entry address plus 4.

It then reads, in order:

1. An unsigned 16-bit count at entry offset 10.
2. The size-like word at descriptor offset 12.
3. The region address at descriptor offset 0.

Using those snapshots, it calculates the trailing-table start by the same address relationship:

\[
T = B + L - 2N - 2
\]

Unlike mode 0, this phase does not compare the count against the size-like value and does not explicitly clear the count.

It then calls F-df70a2b0a7d8 on successive addresses \(T + 2j\). As in mode 0, the loop condition rereads the count at entry offset 10 before each iteration and admits indices less than the current count plus one. The starting address continues to use the original count snapshot even if the stored count changes.

After the loop, F-df70a2b0a7d8 receives the entry address plus 10.

This ordering places the count-address operation **before** the table loop in mode 0, but **after** it in mode 1.

### 5. Return

The function returns:

- The selected delegated result for discriminator 0x00 or 0xFF.
- Zero for every other discriminator value.

Mode-1 exit processing occurs before return and does not intentionally replace the saved result. There is no explicit error-result synthesis.

These return statements describe paths on which all reached accesses and dependencies complete normally. Behavior after invalid memory access or a dependency that does not return normally is not established.

## Side effects

### Direct effects

The only explicit region write performed by this function is a 16-bit zero to entry offset 10 when mode 0 observes a count exceeding the unsigned size-like value divided by 16.

It explicitly reads:

- Descriptor offset 0 on entry.
- Additional descriptor fields at the points described above.
- The discriminator at entry offset 8.
- The count at entry offset 10, including repeated loop-condition reads.

Dependency invocations can have additional effects that are not constrained by the available evidence.

### Address identity and mutation

The function deliberately uses several address snapshots:

- Common-header operations, discriminator access, and loop-bound reads use the entry address.
- Each common table phase rereads the descriptor’s address once for table addressing.
- The discriminator-1 sequence separately rereads the descriptor’s address once.

These addresses need not remain equal if a dependency mutates the descriptor.

For example, after a discriminator-specific dependency changes the descriptor’s address, mode-1 header operations still target the entry address, while its later table-address snapshot can use the changed address.

No assumption is justified that dependencies preserve global state, descriptor contents, count fields, or allocations.

## Acceptance examples

These are conditional static examples, not runtime test results. Unless otherwise stated, assume dependency calls return normally, preserve relevant descriptor and count values, and do not change the discriminator.

1. **Mode 0, ordinary count.**  
   Suppose the post-helper count is 2 and the unsigned size-like value is 64. The count is not cleared because \(2 \leq 64/16\). Relative to the table-phase base, trailing calls receive offsets 58, 60, and 62. The discriminator is read afterward. No exit common processing occurs.

2. **Mode 0, excessive count.**  
   Suppose the post-helper count is 5 and the size-like value is 64. The function clears the stored count because \(5 > 4\). It nevertheless uses the original count to calculate the first table address, at relative offset 52. With the cleared count unchanged, exactly one trailing call occurs there.

3. **Zero count and insufficient size.**  
   With count zero, one table call is still admitted. If the size-like value is zero, its address is two bytes before the table-phase base under the 32-bit address calculation. The function does not reject this case.

4. **Mode 1 ordering and result retention.**  
   For discriminator 0x00, selector zero, and a normally returning F-eb7059546694 result \(R\), delegation occurs first. Exit header operations, table operations, and the final count-address operation follow. The returned value is \(R\), subject to valid continued execution.

5. **Discriminator 0x01 with another mode.**  
   With mode 7 and discriminator 0x01, neither common phase runs. The eleven discriminator-specific calls occur in the listed order using one refreshed base. The function returns zero.

6. **Unrecognized discriminator.**  
   With mode 7 and discriminator 0x02, the function reads the entry address and discriminator, performs no dependency calls, and returns zero.

7. **Dynamic count change.**  
   In either table loop, if the first trailing call changes the entry count from 2 to 0, the next condition rejects index 1. Only the first call occurs. Its address was calculated using the count snapshot of 2.

8. **Largest count.**  
   If a table loop begins with count 65,535 and that count remains unchanged, it admits 65,536 iterations. This example requires that the mode-0 size check, if applicable, does not clear the count and that every calculated address is valid.
