# F-762936c3f077

## Purpose

F-762936c3f077 performs a fixed partial update of a caller-supplied destination after invoking F-304d68214672. Its direct effects are to clear three 32-bit words, force three bits in another word, write a fixed leading value, and derive two words from input bytes and external data.

This is not a complete destination initialization. The existing destination word used in the bitwise update affects the result. Other destination locations receive no direct writes from this function, although the dependency’s effects are unknown.

An initialization-like purpose is plausible, but the application meaning of the destination, selectors, flags, and external values is not established. This contract describes static evidence only; no runtime tests have been performed.

### Input layout

Offsets are byte offsets from the input base.

| Offset | Access width | Role |
|---|---:|---|
| `0x5C` | 8 bits | Zero/nonzero selector for the final destination word |
| `0x61` | 8 bits | Zero/nonzero selector between an external baseline and the value `8` |

The two selectors distinguish zero from every nonzero byte value. Whether a selector byte is interpreted as signed does not change that decision. The augmentation byte is explicitly treated as unsigned, giving a range of 0 through 255.

### Destination layout

All direct destination accesses are 32 bits wide.

| Byte offset | Word index | Direct operation |
|---|---:|---|

The word at `0x18` must support reading and writing. The other listed words must support writing. Input locations and external data must support the reads described below. These requirements apply when each access occurs, including after the dependency returns.

## Behavior

### Dependency boundary

### Ordered destination preparation

After normal dependency return, the direct operations occur in this order:

1. Clear the 32-bit destination word at `0x58`.
2. Read the destination word at `0x18` and replace it with its bitwise OR with `0x24000001`.
3. Clear the destination word at `0x5C`.
4. Write `0x00001700` at destination offset `0x00`.
5. Clear the destination word at `0x60`.

The flag update forces bits 29, 26, and 0 to one. Every other bit retains the value observed by that read. It is not replacement of the whole word with the mask.

This ordering describes the explicit accesses in the supplied representation. It does not establish atomicity, synchronization, or a cross-thread visibility guarantee.

### Baseline selection and augmentation

After the preparation writes, the function reads the external baseline word. This read occurs even when the following selector causes that value to be discarded.

The function then reads the input byte at `0x61`:

- Zero selects the previously read external baseline.
- Any nonzero value selects the 32-bit constant `0x00000008`.

The selected baseline is written to destination offset `0x64`.

Only after that first write does the function read the unsigned byte at input offset `0x62`. It widens that byte to a 32-bit unsigned quantity, shifts it left by 18 positions, and combines it with the selected baseline using bitwise OR. The combined value is written to destination offset `0x64`, replacing the earlier write.

The second value is formed from the retained selected baseline. There is no explicit destination read at `0x64`, and no second external-baseline read is shown.

The shift places the eight input bits in positions 18 through 25. Its possible values range from `0x00000000` to `0x03FC0000`, so no input bit is lost within the 32-bit result.

This is an OR augmentation, not replacement of a cleared field. Existing baseline bits in positions 18 through 25 remain set even when the corresponding augmentation bits are zero. Other baseline bits also remain unchanged.

When the selector chooses `8`, the selected baseline contains only bit 3. That bit does not overlap the shifted byte.

### Final-word selection

After both writes at destination offset `0x64`, the function reads the input byte at `0x5C`.

- A zero byte selects the 32-bit value zero without reading the external conditional word.
- Any nonzero byte causes a read of the external conditional word and selects the value observed by that read.

The selected value is written to destination offset `0x68`. Normal completion follows this write.

There is no visible validation, retry, cleanup, rollback, or explicit error-reporting branch.

### Overlapping storage

No non-overlap check is visible. The input bytes are read at different points after earlier destination writes. If the execution environment permits the relevant overlapping accesses, those writes can therefore change later input values.

For example, when the input and destination bases designate the same ordinary byte-addressed storage:

- The clear at destination `0x60` zeros bytes `0x60` through `0x63` before the input reads at `0x61` and `0x62`.
- The clear at destination `0x5C` zeros bytes `0x5C` through `0x5F` before the input read at `0x5C`.

Absent intervening mutation, both selectors and the augmentation byte then read as zero. The function selects the external baseline, adds no augmentation bits, and writes zero at destination `0x68`.

This consequence does not require the dependency to preserve entry-time input bytes: the relevant clears occur after the dependency returns. It does require valid overlapping accesses and no subsequent mutation that changes the bytes before they are read.

Other storage relationships, including possible overlap with external data, are not ruled out. In such cases, the stated access order and actual values read govern the result; independent stable storage must not be assumed.

## Side effects

- One invocation of F-304d68214672.
- Eight 32-bit destination writes across seven distinct locations.

### A nonzero baseline selector overrides the sampled external value

Suppose the reads at input offsets `0x61` and `0x62` observe `0x80` and `0xFF`, respectively.

Destination offset `0x64` first receives `0x00000008`, then `0x03FC0008`. The external baseline is still read before the selector, regardless of the value returned by that read.

These results depend on the bytes actually observed, not on bytes supplied before the dependency invocation.

### Augmentation preserves overlapping baseline bits

Suppose the baseline read observes `0x00040020`, the selector read at `0x61` observes zero, and the augmentation read at `0x62` observes `0x02`.

Destination offset `0x64` first receives `0x00040020`, then `0x000C0020`. The baseline’s existing bit 18 survives while the augmentation sets bit 19. Replacing the entire eight-bit field would produce a different result.

### Any nonzero final selector enables the conditional read

Suppose the read at input offset `0x5C` observes `0xFF`, and the subsequent external conditional-word read observes `0xDEADBEEF`.

Destination offset `0x68` receives `0xDEADBEEF`. A selector value of one is not required.

If the selector instead reads zero, the destination receives zero and the conditional word is not read.

### Earlier writes can determine later input reads

Suppose the input and destination bases coincide, the overlapping accesses are valid, and no mutation intervenes after the relevant clears.

The reads at input offsets `0x61`, `0x62`, and `0x5C` observe zero because of the function’s earlier writes. Destination offset `0x64` ends with the sampled external baseline, and `0x68` ends with zero.

Nonzero bytes present at entry, or even immediately after dependency return, do not change this consequence when the subsequent clears overwrite them before their reads.
