# F-7606ddc32527

## Purpose

F-7606ddc32527 traverses a linked structure using a supplied 32-bit value, then either selects a candidate word or delegates to F-84549ebf9997.

On normal completion, it writes a four-byte result word followed by a one-byte discriminator:

- **0:** the final comparison returned zero; the result word was loaded from the candidate slot after that comparison.
- **1:** F-84549ebf9997 was called; the result word was loaded from the local word passed to that dependency, after the call returned.

Discriminator 1 does **not** establish successful insertion, allocation, or even that F-84549ebf9997 wrote the forwarded word. Depending on the path, that local word previously contained zero, a boundary value, a value changed through an escaped address, or no established initialized value.

The traversal resembles ordered-tree search and predecessor selection. An insertion operation with conditional duplicate suppression is **inferred intent**, not an established semantic guarantee.

## Behavior

### Initial traversal

The function initializes the remembered comparison result to a nonzero value. It then:

1. Reads the container’s header pointer.
2. Reads that header’s offset-4 field as the current node.
3. Separately rereads the container’s header pointer as the retained attachment candidate.

These are separate header-pointer loads, not a single guaranteed snapshot.

For each nonnull current node:

- Both local scratch words are set to 32-bit zero.
- F-bcefa5957e76 receives the container address plus 25, the original supplied value, and the current node address plus 16.
- The current node becomes the retained attachment candidate.
- A zero comparison result selects the node’s offset-12 link.
- A nonzero result selects its offset-8 link.

The selected link is read **after** the dependency returns. Dependency changes to the node can therefore affect traversal.

Traversal stops when the selected node is null. The retained attachment candidate is the last visited node, or the separately loaded header if no node was visited. The remembered comparison remains nonzero for an empty traversal.

Every completed search iteration explicitly zeros both scratch words before its comparison call. An empty traversal performs neither initialization.

### Mode selection

After traversal finishes, the function reads the mode byte at container offset 24.

A nonzero mode proceeds to common delegation. It does not skip the traversal; it skips only boundary checking, predecessor-like navigation, extraction, and the final comparison.

A zero mode initializes a local candidate slot from the retained attachment candidate.

### Boundary checking

If the remembered search comparison is zero, candidate processing proceeds directly to extraction.

If it is nonzero:

1. The container’s header pointer is reread.
2. That header’s offset-8 word is loaded into the **second scratch word**.
3. F-c7e5bb3c4e39 receives the addresses of the candidate slot and the second scratch word.

Both addresses escape to the dependency. Neither object may thereafter be treated as preserved across other dependency calls without an additional contract.

If F-c7e5bb3c4e39 returns nonzero, immediate boundary delegation occurs:

- F-84549ebf9997 receives the address of the **first scratch word**.
- Its attachment argument is the original retained attachment candidate, regardless of changes to the candidate slot.
- No predecessor navigation, extraction, or final comparison occurs.

If it returns zero, predecessor-like navigation begins from the candidate slot’s then-current value.

### Predecessor-like navigation

The function first reads the candidate’s marker byte.

If the marker is zero, it reads the candidate’s parent-like link and then that parent’s offset-4 link. If this second link equals the candidate, the candidate slot is replaced with the candidate’s offset-12 link. This special branch performs no further descent.

Otherwise, navigation uses the offset-8 child:

- The offset-8 field is loaded once to obtain a possible descent starting point.
- The same field is loaded again to decide whether to descend or climb.

With stable links, a nonnull child causes descent into that child, followed by repeated offset-12 traversal. Each descent step assigns the current node to the candidate slot, reads its offset-12 link for the next node, and rereads that field for the continuation decision. With stable links, the selected candidate is the last node whose offset-12 link is null.

With a null offset-8 child, navigation climbs:

- Load the candidate’s parent-like link.
- Compare that parent’s offset-8 link with the current candidate.
- Replace the candidate slot with the parent regardless of the comparison result.
- Continue upward only while the comparison was equal.

Thus the terminating unequal comparison still advances the candidate to the examined parent.

The repeated child-field reads are distinct accesses. If their values change between reads, the ordinary stable-tree description need not hold. No synchronization, cycle detection, null-parent protection, or traversal bound is shown.

### Extraction, final comparison, and the live candidate slot

Before extraction, a separate local four-byte word is cleared. It is not the delegation output word, and no dependency receives its address in the shown calls.

The function loads the candidate slot and passes that value to F-8f2b48d3598c. It then calls F-bcefa5957e76 with:

1. The container address plus 25.
2. The 32-bit value returned by F-8f2b48d3598c.
3. The original supplied value.

This operand order differs from the initial traversal.

If the final comparison returns zero, the function **loads the candidate slot again after the comparison returns** and writes that word to result offset 0. It does not return a saved copy of the candidate supplied to extraction.

This distinction matters on the boundary-check path: F-c7e5bb3c4e39 received the candidate slot’s address and may retain it. F-8f2b48d3598c or the final F-bcefa5957e76 call may modify that slot through previously escaped state or other dependency interactions. Consequently, the returned word need not equal:

- The retained attachment candidate.
- The candidate produced by navigation.
- The argument supplied to extraction.

After the result-word write, the discriminator becomes zero and is written at result offset 4.

If the final comparison is nonzero, common delegation follows.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume the required memory accesses are valid and dependencies return normally.

### Nonzero mode after a nonempty search

If the mode is nonzero after a terminating nonempty search:

- Boundary checking and extraction do not occur.
- Delegation receives the second scratch word’s address and the last visited node.
- If that scratch word remains zero and delegation leaves it unchanged, the result word is zero with discriminator 1.

The zero result does not demonstrate a dependency-produced output.

### Empty search with nonzero mode

If the initial node is null and mode is nonzero:

- No search comparison or scratch initialization occurs.
- Delegation receives the second scratch word’s address and the separately loaded header.
- If delegation does not define that word, no determinate result word is established.
- Normal completion still selects discriminator 1.

### Immediate boundary delegation

If zero mode, a nonzero remembered comparison, and a nonzero boundary result select immediate delegation:

- Delegation receives the first scratch word’s address.
- Changes to the candidate slot do not change its attachment argument.
- After a nonempty search, if the first scratch word remains at its initialized zero and delegation does not change it, the forwarded word is zero.
- After an empty search, that word has no established initialization.

### Escaped boundary word reused as output storage

Suppose boundary checking returns zero, later dependencies change the second scratch word to a particular 32-bit word, and the final comparison returns nonzero.

Common delegation receives that same word’s address. If delegation leaves it unchanged, the changed word is forwarded with discriminator 1.

### Candidate changed after extraction begins

- Result offset 0 receives the later slot value.
- Discriminator 0 is written.
- No delegation occurs.

### Stable predecessor navigation

- That unequal comparison still updates the candidate slot to the examined parent.
