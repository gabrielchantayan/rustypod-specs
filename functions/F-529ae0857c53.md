# F-529ae0857c53

## Purpose

F-529ae0857c53 routes an event-like record through callbacks associated with a receiver-like object. Its result is the first nonzero result returned by an applicable result-bearing callback, or zero if no such callback returns a nonzero result.

The routine has four ordered stages:

1. An optional notification to F-55421ad0a76a.
2. An optional preliminary callback.
3. One mandatory primary callback, selected from two alternatives.
4. An optional final callback.

The optional notification does not supply the routine’s return value. Its side effects can nevertheless affect every subsequent stage.

“Event,” “receiver,” and “notification” describe inferred roles, not established application semantics. The supplied material does not identify the event protocol, the receiver’s concrete type, or the meaning of a nonzero result.

## Behavior

### 1. Optional notification

The routine first reads the record discriminator at offset `0x004`.

If it equals `0x16`, the routine:

1. Reads the nested-object address from record offset `0x008`.
2. Reads the four-byte selector at nested-object offset `0x004`.
3. Subtracts `0x2500` from that selector and tests whether the result equals `2`.

When that test succeeds, the routine reads the four-byte word at receiver offset `0x10C`, converts it to a character-width value, and calls F-55421ad0a76a with:

- The receiver address.
- The converted character value.

Under the apparent 32-bit machine-word interpretation, the selector condition selects `0x2502`. The acceptance examples below use that unambiguous value. The supplied material does not independently establish the signed-overflow rules of the original implementation language.

The character conversion does not pass the entire four-byte receiver word. Its exact signedness and call-boundary extension are unresolved. Under an eight-bit character interpretation, only eight bits are retained, but whether a retained high bit represents a negative value is not established.

No result from F-55421ad0a76a is inspected. After it returns, processing continues.

### 2. Optional preliminary callback

The routine rereads the record discriminator. It does not reuse the value tested before the notification.

If this fresh discriminator equals `0x16`, the routine reads the current nested-object address and then the current selector. If that selector is zero, the routine:

1. Reads the receiver’s dispatch-table address.
2. Resolves F-unresolved-A from table offset `0x124`.
3. Calls it with the receiver address and record address.

If F-unresolved-A returns nonzero, that exact value becomes the routine’s return value. No primary or final callback is then invoked.

If the preliminary callback is skipped or returns zero, processing continues.

This stage uses state available after F-55421ad0a76a returns. It can therefore become applicable even when the selector originally triggering the notification was `0x2502`, provided the notification changes relevant state.

### 3. Mandatory primary callback

The routine rereads the record discriminator again.

If this discriminator equals `0x16`, it reads the current nested-object address and selector. It then chooses:

- F-unresolved-B, at dispatch-table offset `0x10C`, when the selector equals `0x2A`.
- F-unresolved-C, at dispatch-table offset `0x110`, otherwise.

A discriminator other than `0x16` selects F-unresolved-C without reading the nested-object selector in this stage.

The routine resolves the selected entry from the receiver’s dispatch table and calls it with the receiver address and record address.

If the selected primary callback returns nonzero, that exact value becomes the routine’s return value. The final stage is not evaluated.

If the selected primary callback returns zero, processing continues.

Exactly one primary callback is invoked on any normal path that reaches this stage. It is skipped only when the preliminary callback has already returned nonzero.

### 4. Optional final callback

After a zero primary result, the routine rereads the record discriminator.

If it equals `0x0F`, the routine reads:

- The four-byte value at record offset `0x008`.
- The four-byte value at receiver offset `0x050`.

If those values are equal, the routine resolves F-unresolved-D from dispatch-table offset `0x0E0` and calls it with the receiver address and record address.

A nonzero result from F-unresolved-D is returned unchanged. If this callback returns zero, or if its conditions are not satisfied, the routine returns zero.

For this stage, record offset `0x008` is used as a comparison value, not dereferenced as a nested-object address. The discriminator determines which interpretation applies.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not reports of executed tests. Unless a case states otherwise, assume valid storage, normally returning dependencies, and no dependency mutation of relevant state.

1. **Ordinary default dispatch.**  
   A record discriminator other than `0x16` and `0x0F` skips the notification and preliminary callback, invokes F-unresolved-C, and returns zero if that callback returns zero. No nested-selector read is required.

2. **Notification followed by default dispatch.**  
   With discriminator `0x16` and selector `0x2502`, F-55421ad0a76a is called first using the converted receiver word. With state unchanged afterward, F-unresolved-A is skipped and F-unresolved-C is invoked. The notification itself does not determine the returned integer.

3. **Preliminary termination.**  
   With discriminator `0x16` and selector zero, F-unresolved-A is invoked. If it returns `7`, the routine returns `7`; neither primary callback nor the final callback is invoked.

4. **Preliminary fall-through.**  
   Under the same classification, if F-unresolved-A returns zero and leaves relevant state unchanged, F-unresolved-C is invoked next.

5. **Special primary selection.**  
   With discriminator `0x16` and selector `0x2A`, the routine invokes F-unresolved-B rather than F-unresolved-C. If it returns a nonzero negative integer, that same integer is returned; it is not converted to a positive flag.

6. **Matching final-stage values.**  
   With discriminator `0x0F`, F-unresolved-C runs first. If it returns zero and record offset `0x008` equals receiver offset `0x050`, F-unresolved-D is invoked. A nonzero result from it is returned unchanged.

7. **Primary termination suppresses the final stage.**  
   Even when a record would satisfy the final-stage comparison, a nonzero primary result is returned before that comparison is evaluated.

8. **Notification mutation is visible.**  
   Suppose the initial discriminator is `0x16` and selector is `0x2502`. If F-55421ad0a76a changes the relevant state so that the preliminary-stage rereads see discriminator `0x16` and selector zero, F-unresolved-A becomes applicable.

9. **Preliminary mutation changes primary selection.**  
   Suppose F-unresolved-A returns zero after changing the selector to `0x2A`, while leaving a valid nested-object layout and discriminator `0x16`. The primary-stage rereads select F-unresolved-B.

10. **Primary mutation enables the final stage.**  
    Suppose a primary callback changes the record discriminator to `0x0F`, establishes matching comparison values, and returns zero. The final callback is then applicable even if the record had a different discriminator on entry.
