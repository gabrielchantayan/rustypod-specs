# F-89649c54a383

## Purpose

F-89649c54a383 searches a descriptor-backed sequence for a requested integer, rejects an existing match, and otherwise attempts to place the integer into the first zero-valued slot within a subsequently observed search range.

The routine has two distinct failure-to-insert cases that share the return value −1:

- The requested value already occurs during the initial duplicate search.
- No zero-valued slot is found during the later free-slot search.

An intervening call to F-41af98a03025 is made when two descriptor fields compare equal. That call occurs before the free-slot search, but after duplicate checking.

The established behavior is not conventional append behavior: on a successful slot selection, this routine increments the descriptor’s third field and leaves its second field directly unchanged. It does not select a slot outside the second field’s search range merely because additional storage might exist.

A likely intent is insertion into a sparse integer collection with zero marking an unused slot. That interpretation is inferred, not an independently established collection invariant.

## Interface

### Inputs

The routine accepts:

1. A descriptor address.
2. A requested integer value.

The supplied representation uses three consecutive integer-sized descriptor fields:

| Byte offset | Contract name | Observed role |
|---|---|---|
| 0 | Storage address | Supplies the base address for indexed integer reads and the eventual element write. |
| 4 | Search bound | Controls the initial duplicate search and, after any dependency call, supplies the later search limit. |
| 8 | Auxiliary field | Compared with the search bound before the dependency call; incremented before a successful element write. |

These offsets and the four-byte element stride describe the represented 32-bit layout. The storage address occupies an integer-sized field rather than an independently established native-width pointer field. A wider-pointer ABI or a different integer layout is not established by the supplied evidence.

Elements are four-byte integers at successive four-byte offsets from the storage address. Comparisons with the requested value and with zero are integer equality comparisons. Search control uses signed comparisons.

### Output

The normal return value is an integer:

- **−1:** either an initial duplicate was found or the later search found no zero slot.
- **A nonnegative index:** the first zero slot found by the later search, after the auxiliary-field update and element write have been attempted.

A nonnegative return does not establish that the stored element differs from zero: the requested value itself may be zero.

No separate status identifies whether F-41af98a03025 ran, whether it changed the descriptor, or which of the two −1 cases occurred.

### Preconditions for defined ordinary use

The caller must supply valid, appropriately aligned descriptor storage. Every descriptor and element access actually reached must refer to accessible memory with the necessary read or write permissions.

For ordinary non-overlapping collection behavior:

- The storage address must identify a valid array covering every index inspected.
- Descriptor storage and element storage must not overlap.
- The descriptor and relevant elements must not be concurrently modified.
- Address calculations and the auxiliary-field increment must remain within the implementation’s defined arithmetic domain.

The routine does not validate any of these conditions. In particular, it does not check that the search bound fits an allocation or that the auxiliary field accurately describes available storage.

## Behavior

### Initial duplicate search

The routine first searches from index zero upward while the index is less than the descriptor’s current search bound.

At each visited index, it reads the corresponding element and compares it with the requested value. The first equality causes an immediate return of −1.

This return precedes:

- The equality check between the auxiliary field and search bound.
- Any call to F-41af98a03025.
- Any direct descriptor or element write by this routine.

Zero is not treated specially during this phase. If the requested value is zero, the first zero element is an existing match and causes immediate rejection.

The search bound is obtained from the descriptor during loop control rather than being explicitly captured once for this phase. The storage address is likewise obtained through the descriptor for element access. Under the ordinary preconditions, these values remain stable because this phase contains no direct writes or dependency calls. Behavior under unsynchronized external changes is not established.

If the initial search bound is zero or negative, this phase performs no element reads.

### Conditional dependency call

If the duplicate search finishes without a match, the routine compares the auxiliary field with the search bound.

When they are equal, it calls F-41af98a03025 with the descriptor address. Otherwise, it proceeds without calling that dependency.

The dependency’s return value is not used. There is no explicit success check, rollback, or alternate branch based on that result.

The dependency may change descriptor fields or element storage. Consequently, the later search must be described using the state after the call, not using assumptions about the state observed during duplicate checking.

There is no second duplicate search after this call. If the dependency introduces the requested value into the collection, this routine does not explicitly detect that newly introduced duplicate before attempting insertion.

### First-zero search

After the optional dependency call, the routine reads the search bound and retains that value as the limit for the free-slot search.

It searches indices in ascending order, starting at zero and stopping before that retained limit. At each visited index, it reads the element using the descriptor’s storage address and checks whether the element equals zero.

The search outcome is:

- The index of the first zero element, if one exists within the retained range.
- −1 if the range contains no zero element or the retained limit is nonpositive.

No elements beyond the retained range are searched. In particular, increasing only the auxiliary field or enlarging an allocation does not by itself extend this search.

### Successful selection and write order

For an ordinary successful search, the selected index is nonnegative and strictly less than the retained limit. The routine then performs these observable operations in order:

1. Reads the descriptor’s auxiliary field.
2. Adds one to that value.
3. Writes the incremented value back to the auxiliary field.
4. Reads the descriptor’s storage address.
5. Writes the requested integer at the selected element index.
6. Returns the selected index.

The auxiliary-field write precedes the element write. There is no compensating decrement if the later access cannot complete.

The descriptor’s search bound is not directly incremented or otherwise directly written by this routine. Any change to that field must come from the dependency, overlapping storage, or external activity.

The storage address used for the final write is read after the auxiliary-field update. This ordering matters if the caller supplies overlapping or otherwise unusual storage. The ordinary collection interpretation requires non-overlap rather than assuming those effects cannot occur.

### No available zero slot

If the free-slot search finds no zero, the routine returns −1 without performing its auxiliary-field increment or element write.

That does not imply the call was side-effect-free: F-41af98a03025 may already have run and changed state.

### Arithmetic boundaries

Indexing uses a four-byte stride. Defined use requires the indexed address calculations to remain valid and to refer to accessible elements.

The successful path adds one to the auxiliary field. The supplied representation does not establish a portable overflow policy. In particular, the contract does not promise wraparound from the maximum positive 32-bit signed value to the minimum negative value.

Negative search bounds are not converted into large unsigned lengths in the represented control flow. They produce empty searches. Equal negative descriptor fields can nevertheless trigger the dependency call before the later bound is read.

## Side effects

### Direct effects

Under ordinary non-overlapping storage, this routine directly changes state only when it finds a zero slot:

- The auxiliary field increases by one.
- The selected zero element is replaced with the requested integer.

The initial duplicate-rejection path performs neither change.

The no-zero path performs neither direct change, although it may include dependency effects.

### Indirect effects and ownership

F-41af98a03025 receives the descriptor address. Its allocation behavior, ownership rules, global-state effects, and preservation guarantees are unknown.

This routine contains no explicit allocation, release, ownership transfer, or lifetime-management operation outside that dependency call. That observation does not establish that the dependency preserves the original allocation, keeps external aliases valid, or leaves unrelated state unchanged.

The caller must not rely on the pre-call storage address remaining valid after the dependency call without a separate contract for that dependency.

### Errors and abnormal completion

There is no explicit handling for:

- An invalid descriptor address.
- An invalid or insufficiently sized element allocation.
- Unwritable descriptor or element memory.
- Arithmetic overflow.
- A dependency that fails, does not return, or leaves unusable descriptor contents.

No normal return value is reserved specifically for these conditions. Their consequences are outside the established normal-completion contract.

Because the auxiliary field is written before the selected element, an abnormal interruption during the final element access can leave the auxiliary update already visible.
