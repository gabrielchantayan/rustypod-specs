# F-4a49af03f35b

## Purpose

F-4a49af03f35b processes candidate descriptors associated with a context and a mutable position. It enters a context-associated region, checks the context, prepares two request words, and repeatedly requests and processes candidates. Ordinary completion occurs when the current position is observed as zero, preparation rejects the request, or continuation after a null candidate is rejected.

For each accepted candidate, the function advances the current position, updates a descriptor field, and invokes a processing dependency. It retains the first nonzero processing-result value observed at its retention steps. Zero-valued observations leave that retained result eligible for replacement.

The application-level meanings of the positions, extents, descriptors, and results are not established. “Preparation,” “processing,” and “cleanup” below describe call placement and data flow, not proven allocation, ownership, or resource-management semantics.

## Interface

### Inputs

The interface contains four 32-bit arguments:

| Input | Established use |
|---|---|
| Context | Address-like value supplied to dependencies. The address at byte offset 40 is computed once and supplied to the entry and ordinary-exit helpers. |
| Initial position | Copied into an address-exposed, mutable 32-bit word. Preparation can modify it. After successful preparation, its then-current value initializes a separate current-position word. |
| Request word | Copied into an address-exposed, mutable 32-bit word. Each candidate request receives its then-current value by value. |
| Auxiliary word | Opaque 32-bit value passed by value to preparation and candidate requests. |

The initial-position word and current-position word are distinct storage. The former is not an immutable baseline: preparation receives its address, and no supplied contract prohibits retaining that address and modifying the word during later calls.

Likewise, the request word is not necessarily fixed at the value left by preparation. A later dependency may modify it through an address retained from preparation.

### Output

Ordinary completion returns a 32-bit value:

- Zero if preparation returns zero.
- Zero if continuation after a null candidate returns zero, regardless of the retained result.
- The retained result if a loop-entry check observes a zero current position.

The retained result begins at zero and may remain zero. Consequently, a zero return does not uniquely identify failure, an empty request, abandonment, or successful processing with no nonzero retained result.

Three conditions invoke F-a817d8d58c10, represented as nonreturning:

- A zero context-check result.
- A candidate-header mismatch.
- A failed strict extent comparison.

No ordinary return is established for those paths.

### Memory requirements

For defined execution along the exercised path:

- The context and context-offset address must be acceptable to the invoked dependencies.
- A non-null candidate must permit a 32-bit read at byte offset 0.
- A candidate reaching the update step must permit a 32-bit write at byte offset 8.
- Dependencies must supply valid values for every exposed word before the function consumes it, including the reported extent on a non-null candidate path.
- Any retained pointer used by a dependency must still designate valid storage when used.

The body contains no independent context-null, alignment, bounds, or candidate-lifetime validation. Complete layouts, byte order, and synchronization requirements are undocumented.

## Behavior

### Entry and preparation

The function computes the address at context byte offset 40 and calls the entry helper with that address. It then calls F-194cdec98e23 with the context.

If the context check returns zero, F-a817d8d58c10 is invoked immediately. The ordinary-exit helper is not called first.

Otherwise, F-dc43a4a5b3fb receives:

- The context.
- The address of the mutable initial-position word.
- The address of the mutable request word.
- The auxiliary word by value.

If preparation returns zero, the exit helper is called with the previously computed context-offset address, and the function returns zero. F-080c1b708a86 is not called on this path.

After nonzero preparation:

- The processing-result word is initialized to zero.
- The current-position word is initialized from the initial-position word as read at this point.
- The retained result is initialized to zero.

Only this initialization copies the initial-position word into the current-position word. Subsequent changes to either word do not automatically update the other.

### Mutable storage and snapshots

Several dependencies receive addresses of temporary words. Their supplied contracts do not prohibit retaining those addresses for use during subsequent calls within the invocation.

Accordingly:

- Later calls may change the initial-position word through its preparation-exposed address.
- Each candidate request receives the request word’s value as read for that call, not necessarily the value left by preparation.
- Later calls may change the current-position word through an address exposed by an earlier candidate request.
- Later calls may change the processing-result word through an address exposed by an earlier processing call.
- A candidate request’s reported extent can be changed before its later capture, including during candidate validation.

These possibilities do not imply that such changes occur. They prevent unconditional stability claims.

In contrast, the captured extent and retained result are value snapshots. Their storage addresses are not passed to dependencies by this body. A later write to an exposed word does not retroactively change a previously captured value.

### Loop-entry check and candidate request

At each loop entry, the function reads the current-position word.

If it is zero, the exit helper is called and the retained result is returned. No candidate request or continuation call occurs for that iteration.

If it is nonzero, F-7f52c3bdf9f5 receives:

- The context.
- The address of the current-position word.
- The then-current request word by value.
- The auxiliary word by value.
- The address of a 32-bit unsigned reported-extent word.

The dependency returns either a null value or an address-like candidate value. It may modify the current position directly. Subsequent dependencies may also modify that position through a retained address; the returned position is not treated as immutable.

### Null candidate and continuation

For a null candidate, F-5b388fb5179e receives the context and the current position as read when its arguments are formed.

A nonzero continuation result returns control to the loop-entry check. The next check reads the current-position word anew. The continuation dependency may have changed that word through a retained pointer, so the argument passed into continuation need not equal the value observed afterward.

A zero continuation result takes the abandonment path. After continuation returns, the function compares:

- The then-current initial-position word.
- The then-current current-position word.

If those read-time values differ, it calls F-080c1b708a86 with the context and retained result. If they are equal, it skips that call. It then calls the exit helper and returns zero.

This comparison is not necessarily against either the caller’s original initial position or the value first produced by preparation. Equating it with either requires additional preservation assumptions.

The cleanup decision also does not count processed candidates. Dependency writes alone can produce inequality without processing any candidate. Conversely, the two words can compare equal after earlier processing.

There is no independent progress guarantee. Repeated null candidates, nonzero continuation results, and a repeatedly nonzero current position can sustain iteration indefinitely.

### Non-null candidate validation and extent capture

For a non-null candidate, the observable order is:

1. F-96f882ae0f9f is called with the candidate.
2. After it returns, the reported-extent word is read and captured.
3. The candidate’s 32-bit word at byte offset 0 is read.
4. That descriptor word is compared with the validation dependency’s returned value.

The validation dependency may modify candidate storage or previously exposed words. Thus, both the captured extent and descriptor-header read reflect state after that call, not necessarily state immediately after the candidate request.

If the header and returned value differ, F-a817d8d58c10 is invoked. No position advance, extent query, descriptor update, or processing call follows on this path.

### Position advance and extent checks

After a matching header comparison, the function advances the current-position word by the reported extent.

The addition reads the current-position word at this step, including changes made during validation. The reported-extent word is read again for the addition; no dependency call or explicit write to that word intervenes between its capture and this use. In the absence of independently occurring writes, the added extent equals the captured extent.

The arithmetic produces a 32-bit result without visible saturation or overflow rejection. For example, adding `0x10` to `0xfffffff0` produces the zero bit pattern. This does not establish that a later loop check will observe zero: intervening dependencies may modify the position.

The function next calls F-a1885c38e61e with the candidate and interprets its result as an unsigned 32-bit value.

- A result strictly greater than the captured extent passes.
- A result equal to or less than the captured extent invokes F-a817d8d58c10.

The position advance precedes this call and decision. On failure, no second extent query, descriptor-field write, or processing call occurs. The query itself may have additional effects, including changes through retained pointers.

### Descriptor update

After a passing first extent query, F-a1885c38e61e is called again with the same candidate.

The function subtracts the captured extent from this second result and writes the resulting 32-bit pattern to candidate byte offset 8. The first result controls acceptance; the second controls the stored value. No equality or consistency check connects them.

Subtraction retains only the 32-bit result. A second result smaller than the captured extent therefore produces a wrapped value. For example, a second result of 8 and captured extent of 16 produce `0xfffffff8`.

Changes to the reported-extent word during either query do not replace the captured extent used by the comparison and subtraction.

### Processing and retention

After the descriptor write, F-efd0aa934fd7 receives:

- The context.
- The address of the processing-result word.
- The candidate.

The descriptor write occurs before this call. The processing dependency may subsequently modify that descriptor, other state, or exposed temporary words.

After the call returns:

- If the retained result is zero, the function reads the processing-result word and copies its value into the retained result.
- If the retained result is already nonzero, it remains unchanged.

The processing-result word is initialized only once, not before each candidate. Its observed value may reflect earlier processing or later dependency writes through a retained pointer. Leaving it unchanged during the current processing call does not imply that it still has the value left by the previous processing call.

A copied zero leaves retention open. Once a nonzero value is retained, later processing-result changes do not replace it.

Control then returns to the loop-entry check, which rereads the current-position word after all intervening dependency effects.

## Side effects

### Entry and exit region

The entry helper precedes the context check. Every visible ordinary return calls the exit helper using the context-offset address computed at entry.

A synchronization interpretation is inferred from this pairing. The supplied material does not establish lock type, blocking behavior, recursion rules, memory ordering, or recovery on nonlocal exits.

None of the three visible failure calls is preceded by the exit helper. No explicit release is established on those paths.

### Writes and external effects

The direct nonlocal write established by this body is the 32-bit store to candidate byte offset 8.

Dependencies may also modify context state, candidate storage, exposed temporary words, globals, or other external state. No supplied dependency contract establishes general preservation of such state.

The entry and exit helpers may themselves have effects. In particular, the function does not recheck candidate contents or exposed words after the exit helper returns.

### Ownership and lifetime

No explicit allocation or deallocation operation appears in the body.

Neither the processing call nor the abandonment call proves ownership transfer, release, or retention. Candidate lifetime after these calls is documented_only. The retained result is an opaque 32-bit value, not an established owned pointer, handle, count, or status.

Passing temporary addresses establishes exposure during the invocation, not permission to use them after return.

## Acceptance examples

These are conditional static deductions, not executed tests. All assume valid memory, dependencies returning normally unless designated nonreturning, and no unmentioned independent writes during the described reads. Relevant dependency-write assumptions are stated explicitly.

1. **Preparation rejects.**  
   The context check returns nonzero and preparation returns zero. The function calls the exit helper and returns zero. It makes no candidate request and no F-080c1b708a86 call.

2. **Preparation produces an empty position.**  
   Successful preparation leaves the initial-position word at zero. The function copies zero into the current position and observes it at the first loop check. It exits with zero without requesting a candidate.

3. **One candidate reaches zero and retains 37.**  
   The candidate request leaves the current position at `0xfffffff0`. Validation leaves that position unchanged, leaves the extent at `0x10` through its capture and addition, and produces a matching header comparison. Both extent queries return `0x20`. The descriptor field receives `0x10`. Processing leaves the result word at 37. The queries and processing preserve the advanced zero current position through the next loop check. The function then returns 37 after the exit helper.

4. **Extent equality fails after advancement.**  
   Validation produces a matching header and captured extent 16. The first extent query returns 16. F-a817d8d58c10 is invoked after the position-advance step. There is no second query, descriptor write, or processing call.

5. **The two extent results disagree.**  
   The captured extent is 16. The first extent query returns 32; the second returns 8. The descriptor store writes `0xfffffff8`. Later changes to the reported-extent word do not alter this subtraction.

6. **The next request uses a later request-word value.**  
   Preparation leaves the request word at 4. During a later call, a dependency uses its retained preparation pointer to change that word to 9. If execution reaches another candidate request with the word still 9, that request receives 9, not 4.

7. **A zero observation permits later retention.**  
   The first retention step reads zero. A later retention step reads 91 after processing returns. The retained result becomes 91 and remains 91 despite subsequent processing-result changes.

8. **Abandonment uses both post-continuation operands.**  
   Earlier processing retained 91. A later candidate request returns null and continuation returns zero. If the initial-position word and current-position word compare unequal when read afterward, F-080c1b708a86 receives 91. If they compare equal, that call is skipped. In either case, ordinary return is zero.

9. **Mutation can trigger cleanup without a candidate.**  
   The first request returns null, and continuation returns zero. At the ensuing comparison, the initial-position word is 100 and the current-position word is 120. Cleanup receives zero even though no candidate was processed. If continuation instead changes the initial-position word to 120 before returning, cleanup is skipped.

10. **A zero continuation argument does not guarantee termination.**  
    A null candidate request leaves the current position at zero, so continuation receives zero by value. If continuation returns nonzero and leaves the position zero, the next check exits with the retained result. If it changes the position to a nonzero value through a retained pointer, the next check instead permits another request. If it returns zero, abandonment rules apply.
