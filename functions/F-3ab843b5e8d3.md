## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Input quantization.** Third-input values zero through 127 supply zero to Initial; 128 through 255 supply one. The maximum unsigned 32-bit input supplies `0x01ffffff`.

2. **Pair splitting.** If Initial supplies low half `0x11223344` and high half `0x20000001`, the first write stores `0x11223344`. A.1 receives `8, 8, 0x11223344, 0x11223344` under 32-bit truncation.

3. **Call multiplicity.** Between the first seed write and its index-selected repetition, A.1 through A.9 must all occur in order if they return. The forwarding calls A.3 and A.5 cannot be omitted because their primary results are unused.

4. **Byte narrowing and rereading.** A first byte payload of `0xffffffff` produces byte values `0xfc` and `0xff`. If the two selector reads yield `0x20` and `0x40`, their destinations are `0x31` and `0x51`.

5. **Saved global.** If the fixed-address read converts to A and a dependency later changes that global to B, both explicit writes in that phase still use saved A.

6. **Direct destination.** A saved data word with its highest bit clear selects `0x1c`; with that bit set, it selects `0x1d`.

7. **Loop target transition.** If execution reaches two iterations, their LH.1 targets are respectively `0x08833787` and `0x088337c5`. A third iteration again uses `0x088337c5`. This does not establish different ultimate dependency behavior.

8. **Loop argument boundary.** Initial loop control always yields zero as LH.1’s second argument. If an iteration’s new word is `0x0000003f`, the next such argument is `0x00fc0000`; if it is `0x00000040`, that argument is zero.
