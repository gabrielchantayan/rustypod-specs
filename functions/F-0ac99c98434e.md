# F-0ac99c98434e

## Purpose

F-0ac99c98434e conditionally populates a caller-supplied output region using values obtained from four dependencies. It processes an initial header, an optional selector-dependent payload, and an optional extended suffix.

The established behavior is an ordered sequence of dependency calls, output writes, and continuation checks. A value is written to the output **before** its associated continuation check. Failure therefore leaves partial output rather than restoring the original contents.

The function returns a 32-bit value of either zero or one on its explicit return paths. Zero does not uniquely identify a failed continuation check: one fully traversed suffix also returns zero, even when every preceding check permits continuation.

**Inferred intent:** the dependencies appear to extract encoded values and advance or validate an input position. Neither the encoding nor those dependency semantics is established here. This contract describes their observable call relationships without assigning them an unproven format.

There are no explicit null, capacity, alignment, or input-range checks.

The local working storage includes the copied inputs, zero-initialized state, and a separate 32-bit metadata slot that has no explicit initialization before its address is first passed to a dependency. A further 32-bit slot is initialized to zero but has no explicit subsequent access in the supplied function body. ### Result

- **One:** the function reaches its ordinary successful exit after the required continuation checks.
- **Zero:** a checked dependency returns zero, or the function completes the specific extended suffix described below.
- **No return:** possible if a dependency does not return, an invalid memory operation prevents progress, or the wrapping payload loop continues indefinitely.

The result is not a byte count, output size, or amount of consumed input.

## Behavior

### Dependency-call conventions

Three extraction operations occur:

- **Byte extraction:** F-2b01710262ca receives addresses of working state, metadata, and shared auxiliary state. Its result is stored as one byte.
- **Fixed-width extraction:** F-d54421325734 receives the working-state address, an explicit width argument of one or two, and the auxiliary-state address. Its result is stored as one byte.
- **Word extraction:** F-6609d7dd09ad receives the working-state, metadata, and auxiliary-state addresses. Its result is stored as 32 bits.

The explicit width arguments are dependency arguments, not established output ranges. For example, passing one does not by itself prove that the returned byte is limited to zero or one.

After each extraction and output store, F-8a872239bf2c is called:

- After byte or word extraction, it receives the current metadata value.
- After fixed-width extraction, it receives the same explicit width argument used for that extraction.
- It also receives the working-state and auxiliary-state addresses.

Except for the final call in the extended suffix, a zero result stops processing and returns zero. Any nonzero result permits continuation; it need not equal one.

The output store occurs before this check is called. Thus the checker can observe the updated output if it has access through some independent alias.

### Initial fields

The function obtains and stores two byte-extraction results at offsets 0 and 1, checking each in order.

It then obtains a fixed-width result with width argument one, stores it at offset 2, and checks it.

If all three checks permit continuation:

- A nonzero byte at offset 2 skips every remaining output field and returns one.
- A zero byte at offset 2 enters the extended header and payload path.

The discriminator is read from output storage after the corresponding check, not merely retained from the extraction result.

### Extended header and payload selection

On the zero-discriminator path, the function writes and checks:

1. A fixed-width result with width argument one at offset 3.
2. A byte-extraction result at offset 4.

If the byte at offset 4 is zero, offset 5 and every selector-specific payload are skipped. Processing continues at offset 44.

Otherwise, the function writes a byte-extraction result at offset 5 and checks it. It then reads offset 5 to select a payload case.

Selectors 0, 2, 3, 4, 5, and 6 have explicit handling. Every other selector skips the payload without an explicit error and proceeds to offset 44.

### Selector 0: inclusive byte sequence with wrapping index

Starting with index zero, the function writes checked byte-extraction results at offset 6 plus the index. The loop continues while the index is less than or equal to the unsigned byte at offset 4.

The index is held in a 32-bit unsigned quantity, but each increment is masked to eight bits. Its effective sequence is therefore 0 through 255, then 0 again.

With an unchanged count:

- Counts 1 through 254 produce count-plus-one payload writes.
- Count 255 does not terminate through the loop condition. It repeatedly writes offsets 6 through 261 until a continuation check returns zero or another event interrupts execution.

A zero count does not enter this selector path under ordinary stable-memory execution, because it skips selector processing before offset 5 is read.

### Selector 2: interleaved writes to two potentially overlapping ranges

For each index starting at zero and strictly less than the unsigned count byte at offset 4:

1. Extract and store a byte at offset 14 plus the index; check it.
2. Extract and store a byte at offset 22 plus the same index; check it.

The index uses the same eight-bit-masked increment as selector 0. With a stable count of at most 255, the strict comparison terminates before the increment would wrap.

The call and write order is interleaved by index, not all of the first range followed by all of the second range.

Counts greater than eight cause the ranges to overlap. For example, at count nine, the second write for index zero targets offset 22, and the first write for index eight later overwrites that same byte. No overlap rejection is present.

### Selectors 3, 4, and 5

All three selectors have the same behavior:

1. Store a fixed-width result with width argument one at offset 30; check it.
2. Store a byte-extraction result at offset 31; check it.

The count at offset 4 does not control a repetition count for these selectors.

### Selector 6: word-sized count and inclusive fixed-width sequence

A byte-extraction result is masked to its low eight bits and stored as a full 32-bit word at offset 32. The associated continuation check follows that store.

The function then uses a signed 32-bit index starting at zero. While that index is less than or equal to the signed 32-bit word read at offset 32, it:

- Stores a fixed-width result with width argument one at offset 36 plus the index.
- Checks that extraction.
- Advances the index by one.

If the count word remains as initially stored, it lies between zero and 255, and the loop performs between one and 256 iterations. A zero count therefore still produces one payload byte.

The bound is read from output storage during loop evaluation. Modification of that word through an external alias can change the iteration count; the initial mask alone does not establish a permanent bound under such mutation.

### Common continuation and optional suffix

After any completed or skipped selector payload, the function writes and checks:

1. A byte-extraction result at offset 44.
2. A byte-extraction result at offset 45.
3. A fixed-width result with width argument one at offset 46.

A nonzero byte at offset 46 ends processing with result one.

If offset 46 is zero, the function obtains a fixed-width result with width argument two, stores it at offset 47, and checks it. A nonzero byte at offset 47 ends processing with result one.

If both offsets 46 and 47 are zero, processing continues through:

1. Three checked word extractions stored at offsets 48, 52, and 56.
2. Two checked fixed-width extractions, each with width argument one, stored at offsets 60 and 61.
3. One final fixed-width extraction with width argument one, stored at offset 62.
4. One final call to F-8a872239bf2c with width argument one.

The return value of that final check is ignored. The function returns zero after the call, regardless of whether that check returns zero or nonzero.

## Side effects

### Partial writes and overwrite order

There is no output initialization, rollback, or clearing of skipped fields.

Every extraction that returns normally reaches its output store before the associated checker runs. A failed checker therefore leaves that extraction’s store and all earlier stores in place, subject to dependency side effects.

Payload overlap is observable:

- Selector 0 can reach offsets later used by the common continuation and suffix.
- Selector 2 can overlap its own two ranges and later fixed fields.
- Selector 6 can reach offset 44 and beyond when its count is at least eight.
- Later common or suffix writes replace earlier payload bytes at the same addresses.

Output bytes that are never targeted retain their previous contents unless a dependency changes them.

### Storage requirements

The function has no capacity argument and enforces no maximum payload count smaller than the extracted byte values.

Under stable counts and without additional dependency-originated output writes:

- The final suffix can touch byte offset 62, requiring 63 accessible bytes.
- Selector 0 with count 254 can touch offset 260, requiring 261 bytes.
- Selector 0 with count 255 repeatedly touches through offset 261, requiring 262 bytes merely to accommodate its direct stores; this does not make the loop terminate.
- Selector 2 with count 255 can touch offset 276, requiring 277 bytes.
- Selector 6 with count 255 can touch offset 291, requiring 292 bytes.

These are direct-store bounds, not unconditional safety guarantees. Unknown dependency behavior or mutation of loop bounds can invalidate them.

### Ownership and external state

The body contains no explicit allocation, release, ownership transfer, or cleanup operation. It does not return the address of local working storage.

Dependencies receive addresses into local storage. Whether they retain those addresses, modify global state, acquire or release resources, or access the output through aliases is **documented_only**. No preservation or ownership guarantee is inferred for them.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, dependencies return normally, do not independently modify output, and every relevant continuation check returns nonzero.

1. **Short successful path.** The value stored at offset 2 is nonzero. Only offsets 0, 1, and 2 are written by this function. Three extraction/check pairs occur. The result is one.

2. **Initial failure retains the first byte.** The first extraction returns a byte, and its checker returns zero. Offset 0 contains that byte; this function performs no later output stores. The result is zero.

3. **Zero payload count.** Offset 2 is zero, offset 4 is zero, and offset 46 is nonzero. Offset 5 and all selector payloads are skipped. Offsets 3, 4, 44, 45, and 46 are written after the initial fields. The result is one.

4. **Unhandled selector.** Offset 4 is nonzero and offset 5 is seven. No selector-specific extraction occurs. Processing proceeds directly to offset 44 rather than rejecting seven.

5. **Selector 0 inclusive bound.** The count is two and the selector is zero. Three payload bytes are written at offsets 6, 7, and 8 before common continuation processing.

6. **Selector 0 wrapping boundary.** The count is 255 and remains unchanged. With every checker continuing, the loop repeatedly visits offsets 6 through 261 and does not reach offset 44 as a subsequent processing stage.

7. **Selector 2 overlapping ranges.** The count is nine. The payload produces eighteen checked byte stores. Offset 22 is written first by the second extraction of index zero, then overwritten by the first extraction of index eight.

8. **Selector 6 zero secondary count.** The selector is six and its extracted count is zero. A 32-bit zero is stored at offset 32, followed by exactly one payload store at offset 36.

9. **Failure between paired writes.** In selector 2, the checker after an iteration’s first extraction returns zero. That iteration’s first byte remains stored; its second extraction and store do not occur.

10. **Complete suffix still returns zero.** Offsets 46 and 47 are zero, and every suffix extraction completes. All three words and bytes 60–62 are stored. Whether the final checker returns zero or nonzero, the function returns zero.

## Uncertainties

The following remain **documented_only**:

- The semantic meaning of the two 32-bit inputs and the output fields.
- The source encoding, input extent, and amount consumed by any dependency.
- The local working-state layout expected by dependencies.
- Whether dependencies initialize metadata before every subsequent use.
- Whether dependencies preserve globals, retain addresses, or own or release memory.
- Native byte order and alignment requirements for the word stores.
- Behavior after invalid addresses, insufficient storage, or unsupported alignment.
- Whether external mutation of output or local state is possible in the intended environment.
- Whether the wrapping selector-0 loop and unconditional zero return after the full suffix are intentional.

No speculative correction is part of this contract. In particular, it does not replace an inclusive bound with an exclusive one, widen the wrapping index, reject overlapping payloads, or reinterpret the final zero return as success.
