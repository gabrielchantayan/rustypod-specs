# F-5ece5055925e

## Purpose

F-5ece5055925e coordinates a fixed sequence of dependency calls and conditionally transfers a 16-bit field between two objects. It returns the 32-bit result of its central dependency call, not the results of subsequent calls.

The established behavior has three parts:

1. Obtain a value from F-fdd8589eca2d and pass it, the first input, and a literal zero to F-3e5212464798.
2. Invoke F-a3c410f12096 with both inputs and retain its result. When the second input is nonzero, invoke F-5c5958cfd5fe.
3. Under the field and mode conditions described below, obtain another object through F-fdd8589eca2d and copy a 16-bit field into it.

The roles of the objects, the meaning of the fields, and the business purpose of the calls are unknown. Descriptions such as “source object” and “destination object” identify their roles in the visible memory operation, not ownership or domain semantics.

## Behavior

### Initial calls

The first observable dependency call is to F-fdd8589eca2d, with no explicit arguments.

Its result becomes the first argument of F-3e5212464798. The other arguments are, in order:

- The first input.
- A literal zero.

F-3e5212464798 is called unconditionally after that initial lookup returns normally. No visible check rejects a zero or otherwise invalid lookup result before passing it to this dependency.

Next, F-a3c410f12096 is called with the first and second inputs, in that order. Its 32-bit result is retained as the eventual return value.

These calls precede every directly visible field access by F-5ece5055925e. Their effects may therefore influence all later field observations.

### Conditional intervening call

If the second input is nonzero, F-5c5958cfd5fe is called with no explicit arguments.

If the second input is zero, this call is skipped.

The call, when made, completes before the source-field condition is evaluated. There is no static basis for assuming that it preserves either relevant object, a global lookup target, or any other state.

### Source-field gate

After the preceding calls, the function reads the 16-bit field at offset `0xE6` from the address represented by the first input.

This read occurs even when the second input is zero. The visible condition examines the source field before checking the second input within that condition; consequently, zero mode does not provide a no-dereference path for the first input.

Further processing requires both:

- The observed source field is nonzero.
- The second input is nonzero.

If the source field is zero, no further lookup is made. If the source field is nonzero but the second input is zero, no further lookup is made.

### Destination-field gate

When both gates pass, the function calls F-fdd8589eca2d again.

It reads the 16-bit field at offset `0x80` from the address returned by this call. If that field is nonzero, the transfer is skipped.

If that field is zero, the transfer path is entered. The address used for this zero test is not retained as the explicit destination of the subsequent write.

### Transfer path

The transfer path calls F-fdd8589eca2d a third time.

Using the address returned by this latest call as the destination base, the function reads the source field at offset `0xE6` again and writes its 16-bit value to destination offset `0x80`.

Two distinctions are material:

- The destination written is selected by the third lookup, not necessarily the second lookup.
- The copied source value is obtained by a new read, not by reusing the value that passed the initial nonzero test.

Therefore, the visible behavior does not guarantee that the written destination was observed to contain zero. It also does not guarantee that the copied value is nonzero. Those properties require additional assumptions about dependency effects and state stability.

After the transfer, or after any branch that skips it, the retained F-a3c410f12096 result is returned.
