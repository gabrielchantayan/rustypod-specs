## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Input forwarding:** If both inputs contain arbitrary 32-bit patterns and F-D001 is reached, its first two argument positions receive those patterns unchanged and in order.

2. **Selector indirection:** If an initial computed base plus 1 contains 0x23 at the instant of the selector read, the associated zero-byte write targets absolute address 0x34, not base plus 0x11.

3. **Selector reread:** If an intervening dependency changes that selector from 0x23 to 0x24, the later write targets 0x35. Reusing the earlier selector would violate the represented order.

4. **Byte truncation:** If an unsigned result is 0x100, its fourfold value is 0x400, and a byte store of that value writes 0x00. It does not store a word or clamp to 0xFF.

5. **Mask-before-shift:** For 0xFFFFFFFF, masking to 30 bits and shifting right by 20 yields 0x3FF. Storing that result as a byte writes 0xFF.

6. **Bounded extraction:** For any unsigned 32-bit dependency result, shifting right by 20 and then shifting that retained result right by 21 yields zero.

7. **Shared-state mutation:** If a dependency changes G-A after the explicit zero store, a later G-A read uses the changed value. Assuming perpetual zero is unacceptable.

8. **Word-to-byte copy:** If a word read at a selected base plus 0x74 has numerical value 0x123456AB, the corresponding byte write at base plus 1 writes 0xAB.

9. **Final publication:** If the last byte result is 0x7E and the three-byte shared value is numerically 0x123456, the final concatenated G-B value is 0x1234567E, subject to the represented concatenation semantics.

10. **Final ordering:** If execution reaches the ending sequence, the zero-byte store precedes the final G-B update; that update precedes the zero-halfword store; all precede F-D003.
