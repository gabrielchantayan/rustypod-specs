# F-4f1b961063bb

## Purpose

F-4f1b961063bb constructs one of two output-record forms from a discriminator, a selector, and an input record. It writes a branch-specific tag, obtains a 32-bit value from a dependency, publishes a length, and invokes a dynamically selected callable with an output address, an input address, and a count-derived quantity.

The discriminator selects the form:

- A 16-bit value equal to `0x482B` selects the first form.
- Every other value selects the second form.

The final callable is selected by reading a global function-pointer slot **after the branch-specific operations and count calculation**. Its identity is not established at entry. Earlier dependencies may change that slot.

The established contract is the ordered sequence of accesses and calls below. Initialization, conversion, and data copying are plausible dependency roles, not established semantics.

## Interface

The function accepts five arguments and has no explicit return value.

| Argument | Role | Established use |
|---|---|---|

| Selector | Represented 32-bit integer | Compared with exactly 1 |

## Behavior

### Common entry sequence

The function first calls F-opaque-01 with:

1. Output base.
2. Integer quantity 520.

Only after that call returns does it read the 16-bit discriminator at discriminator offset 2.

Consequently, the branch uses the discriminator as it exists after F-opaque-01. There is no established entry-time snapshot. If the dependency changes overlapping discriminator storage, the branch may reflect that change.

The read is represented as signed 16-bit, but `0x482B` is positive and representable in that width. The equality condition therefore identifies exactly that 16-bit value.

### First form: discriminator equals `0x482B`

The branch performs the following ordered operations:

1. Write the 16-bit tag at output offset 0:
   - 3 if the selector equals 1.
   - 4 otherwise.
2. Call F-4055be9c3f18 with input offset 2.
3. Write its 32-bit result at output offset 4.
4. Write 520 to the 32-bit length location.
5. Read an unsigned 16-bit count at input offset 6.
6. Replace the length with twice that count plus 10.
7. Read an unsigned 16-bit count at input offset 6 again.
8. Calculate the final quantity as twice one more than the second reading.
9. Continue to the common final dispatch with output offset 8 as destination and input offset 6 as source.

The count is read twice. The replacement length uses the first reading; the final quantity uses the second. These values need not agree if intervening writes, aliasing, or external mutation affect the count.

If both reads yield the same value \(n\):

- Replacement length: \(2n + 10\).
- Final quantity: \(2(n + 1)\).
- Count range: 0 through 65,535.
- Replacement-length range: 10 through 131,080.
- Final-quantity range: 2 through 131,072.

The arithmetic is evaluated beyond 16-bit width. The addition does not wrap at 65,535, and neither result is truncated to 16 bits. All resulting values fit in a signed 32-bit integer.

| Output offset | Width or extent | Established operation |
|---|---:|---|
| 0 | 2 bytes | Tag write |
| 2 | 2 bytes | No explicit direct write |
| 4 | 4 bytes | Write of F-4055be9c3f18 result |
| 8 | Unknown | Destination passed to the final selected callable |

“No explicit direct write” does not mean unchanged storage: dependency effects remain unknown.

3. Call F-946cac4b59bc with:

For count \(n\):

### Common final dispatch

After the selected branch has completed its dependency calls, explicit writes, count reads, and final-quantity calculation, the function reads a global function-pointer slot.

It invokes the callable selected by that read with:

1. The branch-specific destination address.
2. Input offset 6.
3. The already-calculated final quantity.

This document labels that invocation role F-opaque-02. The label does **not** identify one fixed callable across invocations.

The distinction between slot and callable is material:

- The slot is global state read by this function.
- Its contents select the callable used for the final invocation.
- The selected callable’s internal behavior is unknown.
- F-opaque-01, F-4055be9c3f18, and, in the second form, F-946cac4b59bc may change the slot before it is read.
- The function does not visibly capture or preserve the slot’s entry value.

The final quantity has already been computed before this dispatch read. The late target selection does not entail another count read or a quantity recalculation.

This establishes the recovered operation order, not atomicity, synchronization, or a hardware memory-barrier guarantee.

### Completion and errors

If the final selected callable returns normally, F-4f1b961063bb returns without an explicit result.

There is no visible validation failure, returned error status, retry, fallback callable, rollback, or cleanup path. Invalid dispatch targets, dependency failures, invalid memory accesses, exceptions, and non-returning dependencies have no established handling contract here.

Length values are explicit writes made before final dispatch. They are not unconditional guarantees about the length location at return: the selected callable may modify that location.

## Side effects

### Observable ordering

The established ordering includes:

- F-opaque-01 precedes the discriminator read.
- The tag write precedes F-4055be9c3f18.
- In the first form, the 32-bit result write precedes both length writes.
- The first-form length write of 520 precedes the first count read and count-derived replacement.
- The replacement length write precedes the second count read.
- In the second form, F-946cac4b59bc precedes the length write and count read.
- All branch-specific operations and the final-quantity calculation precede the global dispatch-slot read.
- That read selects the callable subsequently invoked.

In particular, an earlier dependency’s change to the dispatch slot must not be ignored by substituting an assumed entry-time target.

### Aliasing and mutable state

No non-overlap requirement is enforced by the visible operations.

Relevant consequences include:

- Initial dependency effects may change the discriminator before selection.
- Tag or result writes may change input data when storage overlaps.
- F-4055be9c3f18 may change count storage or the dispatch slot.
- F-946cac4b59bc may change count storage or the dispatch slot before their later reads.
- Length writes may change count storage if the length location overlaps input offset 6.
- Other overlapping direct writes may affect the dispatch slot before its late read.
- The final callable may change output, length storage, input, globals, or other state; its effects are not constrained by the supplied evidence.

Stable-count examples are therefore conditional. The function must not be described as taking an early snapshot of input fields or global dispatch state.

### Ownership and lifetime

The function directly allocates and releases no memory in the supplied evidence.

No dependency is established to borrow, retain, allocate, release, or transfer ownership. Passing the 32-bit result to F-946cac4b59bc does not establish that it represents owned storage or that ownership changes.

Dependencies are not assumed to preserve globals, the dispatch slot, or caller memory outside their explicit arguments.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations. Unless an example says otherwise, assume valid storage, normal dependency returns, valid dispatch, and no mutation of relevant memory beyond the specified operations.

### First form: zero count

With discriminator `0x482B`, selector 1, and both count reads equal to zero:

- The tag write is 3.
- F-4055be9c3f18 receives input offset 2.
- Its result is written at output offset 4.
- The length writes are 520, then 10.
- After calculating quantity 2, the function reads the global dispatch slot.
- The selected callable receives output offset 8, input offset 6, and quantity 2.

Zero count does not suppress dispatch.

### First form: other selector and maximum count

With selector −1 and both count reads equal to 7:

- The tag is 4.
- The replacement length is 24.
- The final quantity is 16.

With both count reads equal to 65,535:

- The replacement length is 131,080.
- The final quantity is 131,072.
- Neither value wraps to 16 bits.

If the selected callable is independently established to copy exactly that many bytes, the maximum-count destination ends at output offset 131,080, exclusive. That conditional extent exceeds 520; no visible capacity check rejects it.

### First form: differing reads

If the first count read yields 1 and the second yields 2:

- The replacement length is 12.
- The final quantity is 6.

Dispatch uses quantity 6, not a quantity derived from the first reading.

### Second form: boundaries

With a nonmatching discriminator, selector 1, and count zero:

- The tag is `0x0300`.
- F-946cac4b59bc receives the preceding result and output offset 10.
- The length write is 46.
- The final selected callable receives output offset 14, input offset 6, and quantity 1.

For selector 2, the tag is `0x0400`. Counts 31, 32, and 255 produce quantities 32, 33, and 256 respectively; the explicit length write remains 46.

If the selected callable copies that many bytes, counts 31 and 32 give exclusive destination endpoints of 46 and 47 respectively. The visible function does not reject the latter.

### Late dispatch-slot update

Suppose the dispatch slot selects one callable at entry, but F-4055be9c3f18 changes it to select another. If no subsequent operation changes the slot before its final read, the second callable is selected.

The same rule applies to a change made by F-946cac4b59bc in the second form. An implementation that unconditionally snapshots the target at entry would not preserve this behavior.

### Count capture versus target selection

Suppose the second form reads count 5 and calculates quantity 6. If the dispatch slot changes before its late read, the callable selected by that read still receives the already-calculated quantity 6. Target selection does not imply a fresh count read.
