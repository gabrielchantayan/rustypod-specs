# F-ab9e57042805

## Purpose

F-ab9e57042805 scans a caller-supplied table, selects records using an eight-bit discriminator, and traverses the selected records’ linked nodes. For each reached node, it calls F-fc01ae5793b0 with position-related values and a reusable pool of eight descriptors. It then dispatches through F-55af5f2f333f while a live result-count slot remains nonzero.

The number of dispatch calls is not necessarily the count initially supplied by F-fc01ae5793b0. Each dispatch can potentially change that count through an alias previously exposed by F-fc01ae5793b0. The function subsequently decrements the then-current count and tests it again.

The meanings of the positions, modes, auxiliary values, and descriptor payloads are not established. Selection, traversal, argument construction, and read/write ordering are established.

The only explicit normal return is the 32-bit value zero. It means the table scan reached its current bound, not that either dependency reported success.

|---|---|
| First | Opaque 32-bit value forwarded to both dependencies. |
| Second | Address of a table header: unsigned 32-bit record count at byte offset 0, followed by a 32-bit record-storage address at offset 4. |
| Third | Opaque 32-bit value forwarded to F-fc01ae5793b0. |
| Fourth | Address of a context containing a 32-bit word at offset 0 and a 32-bit discriminator source at offset 4. The context address is also passed to F-55af5f2f333f. |

The supplied representation uses 32-bit addresses and pointer-bearing fields. The layouts below must not be widened by substituting larger pointer fields.

Each record has a 12-byte stride:

| Byte offset | Width | Accessed meaning |
|---|---:|---|
| 0 | 1 byte | Kind. |
| 1 | 1 byte | Selection discriminator. |
| 2–7 | 6 bytes | Not directly interpreted here. |

Each local descriptor has two four-byte fields: a payload address followed by a next-descriptor address. Initially, eight descriptors form a chain whose final link is zero. Each initially addresses a distinct 24-byte local payload region.

These are access layouts, not claims about caller allocation sizes, object types, ownership, or byte order.

No explicit validation checks pointers, alignment, record-storage bounds, node chains, descriptor chains, or result counts. Defined memory access requires every field actually reached to be accessible, including fields selected after dependency-induced mutations.

## Behavior

### Invocation-local preparation

Before inspecting the table count, the function constructs the eight-descriptor chain and its payload addresses. The payload regions total 192 bytes. Their contents are not explicitly initialized.

The chain is initialized once per invocation, not once per record or node. Changes made to descriptor fields during one node’s processing can therefore affect later nodes unless a dependency restores them.

Other local working storage includes:

- A 32-bit mode word.
- A 32-bit adjusted-position slot.
- A 32-bit auxiliary-value slot.
- A four-byte live result-count slot.
- A separate four-byte scratch region.

The result count and scratch region are not explicitly initialized before the first dependency call. The function also does not reset the result count before subsequent calls. Correct dispatch therefore depends on the count left by the dependency or by earlier activity.

The mode word is not fully initialized before its first possible use.

A 32-bit position offset starts at zero and can persist between matching records.

### Table traversal and selection

The unsigned record index starts at zero.

Before each candidate record, the function reads the current table count. If the index is greater than or equal to that count, it returns zero.

Otherwise, it reads the current record-storage address and forms a candidate address using the index and a 12-byte stride. It compares the candidate’s discriminator byte with the low eight bits of the context word at offset 4.

Only these eight-bit patterns determine equality. Character signedness does not change whether the patterns are equal.

For a nonmatching candidate, the function advances the record index without directly reading that record’s kind or first-node field.

For a matching candidate, it:

1. Reads the record-storage address again and obtains the kind using that newly read base.
2. Obtains the first-node address from offset 8 of the previously calculated candidate address.
3. Resets the per-record node ordinal to zero.
4. Applies the kind-dependent state changes.
5. Processes the resulting node chain.

Thus, kind and first-node reads need not use the same storage base if the header changes between the two base reads. The function does not establish a stable table or context snapshot.

### Kind-dependent state

**Kind 0**

The function sets the mode word’s low eight bits to zero, preserving its upper 24 bits.

For an empty chain, it resets the position offset to zero and makes no node-processing calls.

For a nonempty chain, it logically shifts the unsigned context word at offset 0 right by two and subtracts the first node’s position. The resulting 32-bit pattern becomes the position offset for that record.

The first node’s position is read for this anchoring calculation and is read again during node processing. Its adjusted position equals the shifted context word modulo \(2^{32}\) only if the relevant values remain unchanged between those reads.

**Kind 1**

The function sets the mode word’s low eight bits to one, preserves its upper 24 bits, and resets the position offset to zero.

**Kind 2**

The function sets the mode word’s low eight bits to two, preserves its upper 24 bits, and resets the position offset to zero.

**Every other kind**

Neither the mode word nor the position offset is assigned for that record. A nonempty node chain is nevertheless processed.

An unrecognized kind therefore inherits the existing offset and mode contents. If it precedes every recognized kind, this function has not established even the mode word’s low byte. The offset still begins at zero.

The full 32-bit mode word is passed onward. The source does not establish that a dependency ignores its upper 24 bits.

### Per-node preparation and first dependency call

For each reached nonzero node address, the function reads the node’s position, adds the current position offset, and stores the adjusted position. It then reads and stores the auxiliary value at node offset 8.

It calls F-fc01ae5793b0 with these arguments in order:

1. Original first argument.
2. Complete 32-bit mode word.
3. Adjusted 32-bit position.
4. Node auxiliary value.
5. Original third argument.
6. Capacity value eight.
7. Address of the first local descriptor.
8. Address of the final descriptor’s payload-address field.
9. Address of the live result-count slot.
10. Address of the four-byte scratch region.

The eighth argument is not a separate pointer-output slot. Writing through it changes the final descriptor’s payload-address field.

No return value from F-fc01ae5793b0 is inspected.

### Live-count result dispatch

After F-fc01ae5793b0 returns, descriptor traversal starts at the original first descriptor. This starting address is selected afresh for each node; the descriptor contents are not reinitialized.

The function tests the live result-count slot for nonzero. When it is nonzero, it reads the current descriptor’s payload-address field and calls F-55af5f2f333f with:

1. Original first argument.
2. Current node address.
3. Current descriptor’s payload-address value.
4. Current per-record node ordinal.
5. Current position offset.
6. Original context address.

After that call returns, the ordering is:

1. Read the current descriptor’s next link.
2. Advance the descriptor cursor to that link.
3. Decrement the then-current value in the result-count slot.
4. Test the updated count before another dispatch.

The decrement does not necessarily operate on the value observed before the dispatch. F-fc01ae5793b0 receives the count slot’s address and could expose it to F-55af5f2f333f. Preservation of that slot cannot be assumed merely because it is not an explicit argument to F-55af5f2f333f.

For example, an initial count of two can produce one dispatch if that dispatch changes the live count to one. The following decrement makes it zero.

Similarly, the descriptor payload address is read before dispatch, but its next link is read afterward. A dependency with an alias to the descriptor can affect subsequent traversal.

There is no enforced maximum of eight dispatches and no null-descriptor check before reading a payload-address field. Passing capacity eight to F-fc01ae5793b0 does not establish either bound locally.

The count is tested for nonzero, not positivity. High-bit-set values are not rejected.

### Node and record advancement

Once the live count reaches zero, the function increments the node ordinal. It then reads the current node’s next-node field and follows that address.

This link read occurs after both dependency phases. Changes made during processing can affect which node is visited next.

A node producing no dispatch calls still consumes one ordinal. The ordinal resets for each matching record, not for each descriptor.

A zero node address ends the chain. The record index then advances, and the next iteration reads the table count again.

No cycle detection, traversal limit, or dependency timeout is present.

### Arithmetic and completion

Positions, offsets, addresses, counts, and counters use four-byte quantities in the supplied representation. Position addition and offset subtraction concern their low 32-bit results, not arbitrary-precision or saturating arithmetic.

Record address formation uses the index multiplied by 12. The source provides no overflow check for that calculation, counter advancement, or result-count decrement. Portable language-level behavior for every overflowing signed operation is not independently established by this representation.

Normal completion requires the table scan, node chains, live-count loops, and dependency calls all to terminate.

## Side effects

The function directly initializes and updates its local working storage. It contains no explicit allocation, deallocation, or direct write to caller-owned table, node, or context fields.

This does not establish externally read-only behavior. Dependencies receive caller-derived values and pointers, and F-fc01ae5793b0 receives writable addresses into local storage. Dependency effects can influence later reads.

Significant read timing includes:

- Table count reread before each candidate.
- Record-storage address reread for a matching record’s kind.
- Context discriminator read for each comparison.
- Context offset-0 word read for kind 0 only when the chain is nonempty.
- First-node position read during anchoring and again during processing.
- Descriptor payload address read before dispatch.
- Descriptor next link read after dispatch.
- Live count decremented using its value after dispatch.

No synchronization or concurrent-mutation guarantee is visible. These access-order facts do not establish that arbitrary concurrent writes are safe.

Local descriptors, payload regions, count storage, and scratch storage exist only during the invocation. The function itself does not explicitly transfer ownership or release them. Whether dependencies retain, expose, own, or release supplied addresses is unknown. Retention cannot extend the visible lifetime of local storage.

No explicit error return, rollback, exception handler, or recovery path is present.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initially empty table.** If the first count read is zero, the function returns 32-bit zero without reading record storage, context fields, or nodes and without calling either dependency. Local descriptor initialization still occurs first.

2. **Discriminator truncation.** A record discriminator of hexadecimal AB matches a context discriminator word of hexadecimal 123456AB. A nonmatch causes no direct kind or first-node read for that candidate.

3. **Kind-0 anchoring.** Suppose the context word is 400 and the selected chain has positions 30 and 45. If relevant values remain unchanged and processing terminates normally, the offset is 70, adjusted positions are 100 and 115, and node ordinals are zero and one.

4. **Modulo position arithmetic.** A shifted context value of 10 and first-node position of 20 produce offset pattern hexadecimal FFFFFFF6. With unchanged inputs, the first adjusted position is 10 modulo \(2^{32}\).

5. **Kinds 1 and 2.** These kinds reset the offset to zero and set only the mode word’s low byte to one or two. Node positions are forwarded unchanged as 32-bit patterns; the mode’s upper bits remain unestablished unless established elsewhere.

6. **Unrecognized kind.** If an earlier record established offset 70, a later matching kind-3 record retains that offset absent an intervening change. Kind 3 does not itself establish any mode bits.

7. **Zero count.** If F-fc01ae5793b0 leaves the count at zero and nothing changes it before the initial test, no dispatch occurs for that node. Node advancement still increments the ordinal.

8. **Two stable results.** If F-fc01ae5793b0 leaves count two, the first two descriptors remain valid with unchanged payload fields and links, and each dispatch returns without changing the live count, exactly two dispatches occur. They use the same node, ordinal, and offset, and the two successive payload-address values.

9. **Nine results with the original chain.** If the initial count is nine, all eight dispatches return without changing the live count, and the original descriptor chain remains unchanged and valid through those calls, the eighth dispatch is followed by traversal to the terminal zero link and a decrement to one. The next iteration attempts to read a payload-address field through a zero descriptor address. There is no explicit ninth-result rejection; a ninth dispatch call is not guaranteed.

10. **Dispatch reduces the live count.** If the initial count is two and the first dispatch changes it to one, the subsequent decrement makes it zero. Assuming the required descriptor-link read is valid and no further mutation intervenes, only one dispatch occurs.
