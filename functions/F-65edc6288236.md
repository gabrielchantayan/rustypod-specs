# F-65edc6288236

## Purpose

F-65edc6288236 conditionally performs byte writes, invokes software interrupt `0xDE`, initializes computed memory locations, and executes a sequence of dependency calls and word writes. If all preceding operations complete and execution reaches the end of the represented body, it enters an unconditional infinite loop.

No normal return, success value, recoverable error result, allocation contract, or release contract is established. The behavioral contract concerns represented memory accesses, call arguments, retained values, and control flow.

An application-level purpose is **documented_only**. Initialization or state mutation is plausible intent, but the supplied static evidence does not establish a subsystem, valid object model, or successful completion condition.

### Widths and address calculations

The representation distinguishes 8-bit byte accesses, 32-bit word accesses, and one 64-bit dependency result split into low and high 32-bit words. Address-valued stores are 32 bits.

Arithmetic results used as addresses or words retain their low 32 bits. This includes multiplication, addition, subtraction, and left shifts. Logical right shifts introduce zero bits. Byte stores retain the low eight bits; byte reads used as words are zero-extended.

Offsets are byte displacements. Adding a logically quartered address-like value does not introduce an additional multiplication by four. Explicit entry-object displacements include `0x14`, `0x3C`, and `0x54`; these do not establish a complete layout.

The entry predicate tests overflow of signed 32-bit subtraction. It is not unsigned borrow or an ordinary signed less-than test.

These rules describe the represented calculations, not guaranteed processor behavior for invalid addresses or exceptional operations. Byte order and unaligned-access behavior remain unresolved.

## Behavior

### 1. Entry state and predicate

The represented sequence:

1. Obtains Word from the word-valued global.
2. Obtains Base from the first address-valued global.
3. Computes Origin as the low 32 bits of the scaling input multiplied by `0x800`.
4. Initializes Cursor and Offset to zero.
5. Evaluates whether signed 32-bit subtraction of the comparison input from Origin overflows.
6. Captures Token from the second address-valued global.

Without overflow, execution proceeds directly to setup. With overflow, it executes the conditional sequence below.

### 2. Overflow-only accesses and calls

The first conditional byte store obtains its destination through another reference to the second address-valued global. This reference occurs after predicate evaluation and Token capture, and before the byte store at Origin.

The represented order is:

1. Reference the second address-valued global and store an 8-bit zero through the resulting address.
2. Store an 8-bit zero at Origin.
3. Read a 32-bit word at Origin; retain it as **Derived**.
4. Invoke software interrupt `0xDE`.

The first store is not specified as a store through retained Token. Token remains the earlier captured value until its explicit replacement later in this path. A change to the global does not itself refresh Token.

The two references to that global do not establish two physical loads or guarantee equal values. If the global is stable and both references have ordinary consistent semantics, the captured address and conditional-store address agree. Otherwise their relationship is **documented_only**.

Derived is read after the byte write at Origin. It need not be zero: other bytes, byte order, aliasing, and memory semantics affect the word.

If the interrupt returns, continue in this order:

1. Store Base at entry-object offset `0x14`, three times.
2. Store Word at entry-object offset `0x3C`.
3. Store Derived at entry-object offset `0x54`, twice.
4. Read a word at Derived plus `0x14`; retain it as **Descriptor**.
5. Read an address-like word at Derived plus `0x74`; retain it as **Secondary**.
6. Read a word at Word plus `0x6C`, then store its low byte at Secondary plus `0x17`.
7. Store the low byte of Derived at Word plus `0x15`.
8. Read and retain a byte at Word plus `5`.
9. Read a byte at Secondary plus `7`, zero-extend it, and replace Word.

These reads can observe preceding writes where addresses overlap.

Call F-7aee1fc5f275 with three 32-bit arguments, in order:

- Descriptor logically shifted right eight bits, then shifted left 12 bits.
- Descriptor unchanged.
- Descriptor logically shifted right eight bits, then shifted left 24 bits.

Call F-U01 with the low 32 bits of that result shifted left 12 bits. A secondary register word exposed after F-U01 supplies F-U02’s three arguments, transformed in the same way as Descriptor.

After F-U02 returns:

- Base becomes its result shifted left eight bits.
- Offset becomes its result shifted left 12 bits.
- Token becomes `0x007F8000`, replacing the entry capture.
- Selected initially becomes the retained byte read before Word was replaced.

The sign bit of replacement Base selects the next path:

- **Clear:** skip setup. Cursor remains zero and Selected remains the retained byte.
- **Set:** Selected receives the intermediate value `0x08911110`, Origin becomes `0x0891111C`, and setup executes.

Setup overwrites that intermediate Selected value before the common writes use it. The two represented sign comparisons use the same Base with no intervening dependency call.

### 3. Setup

Setup executes on the no-overflow path and on the overflow path whose replacement Base has its sign bit set.

Perform these 32-bit stores in order:

| Order | Destination | Value |
|---|---|---|
| 1 | Entry-object address + Offset | Token |
| 2 | Base + Offset | Origin |
| 3 | Token + Offset | Origin |
| 4 | Origin + Offset | Offset |
| 5 | Base + (Offset logically shifted right two bits) | Offset |
| 6 | Offset + Base | Base |
| 7 | Token + Base | Offset logically shifted right two bits |

Then set Cursor to Base and Selected to Offset.

Stores 2 and 6 have the same computed destination but remain separate represented writes. Other stores can alias them.

On the no-overflow path, setup uses captured Token. On the overflow path, setup uses replacement Token, `0x007F8000`, not either earlier reference to its originating global.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes required preceding accesses complete and dependencies return.

### No subtraction overflow

If Origin minus the comparison input does not overflow signed 32-bit arithmetic:

- The conditional global reference, byte writes, interrupt, and first three calls are absent.
- Setup executes with Offset zero.
- Its first store writes captured Token at the entry-object address.
- Cursor becomes entry Base and Selected becomes zero.
- F-U03 uses the entry-link-derived target.

### Separate conditional global reference

Suppose Token captures address `0x1000`, while the later overflow-only reference to the same global resolves to `0x2000`.

The first conditional byte store targets `0x2000`, not `0x1000`. Token remains `0x1000` until explicitly replaced by `0x007F8000`. If overflow-path setup executes, that replacement is the setup Token.

This example does not assert that differing observations occur, or that two physical loads are performed. Equal observations require appropriate stability and memory semantics; they are not guaranteed merely by the repeated global reference.

### Overflow with setup bypass

If overflow occurs and F-U02’s result shifted left eight bits has bit 31 clear:

- Setup is skipped.
- Cursor remains zero.
- Selected remains the retained byte.
- The common writes include a word store of Base at address zero.

Redirecting that store would change the represented behavior.

### Overflow with setup

If the shifted Base has bit 31 set:

- Origin becomes `0x0891111C`.
- Setup executes using Token `0x007F8000`.
- Cursor becomes replacement Base.
- Selected becomes Offset, not the intermediate `0x08911110`.

### Shift truncation

If F-U02 returns `0x01000000`, shifting it left eight bits or 12 bits produces zero after 32-bit truncation. Setup is therefore skipped despite the unshifted result being nonzero.

### Split result and overwrite

If F-U04’s low result word is `0x00000010`, the subtraction store writes `0xFFFFFFFA` at twice Cursor. Later stores of Cursor at that destination still occur and can overwrite it.

### Late global overwrite

Suppose Result is `0x00000100` and F-U10 returns zero. SixteenthResult is `0x00000010`, so the second post-call store writes that value at `0x0000003C`.

If the global then remains stable and both final references observe it consistently, the final assignment stores `0x00000010` at `0x00000028`, regardless of an earlier dependency’s different global value. Physical read count and operand evaluation order remain unresolved.
