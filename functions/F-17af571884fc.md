# F-17af571884fc

## Purpose

F-17af571884fc performs a fixed sequence of low-level memory writes, including updates to several global storage locations and writes through addresses obtained from inputs or global state. The supplied representation ends at an invalid-instruction boundary rather than at an ordinary return.

The established behavior is the write sequence and its data dependencies. A broader purpose—such as initialization of exception-related state—is only inferred from annotations in the supplied material. Those annotations do not establish the actual roles of the affected locations.

This contract is conditional on the supplied representation accurately describing executable instructions up to its truncation point. The supplied material explicitly warns of bad instruction data and overlapping global symbols. Consequently, this document does not certify that all represented operations execute on the original target.

## Behavior

### Ordered effects

The supplied body establishes the following order, subject to successful completion of each preceding operation.

1. **Store a narrowed form of A.**  
   Write 16 bits at the address formed from A plus 0x0C. The value is A converted to a signed 16-bit quantity.

   A low-16-bit truncation is the expected machine-level interpretation. However, conversion of an out-of-range signed value is not fully specified by the supplied representation alone. Portable acceptance of arbitrary A values therefore requires an explicit narrowing convention.

2. **Store the implicit 16-bit input.**  
   Write H as a 16-bit quantity at the address formed from C plus 0x2A.

3. **Clear a byte at an address derived from E.**  
   Logically shift unsigned E right by 26 positions, subtract 0xD0 using the represented unsigned arithmetic, and write one zero byte at the resulting address.

   For unsigned 32-bit arithmetic:

   - The shifted value is between 0 and 63 inclusive.
   - The resulting address value is between 0xFFFFFF30 and 0xFFFFFF6F inclusive.
   - Only E's top six bits affect this address.
   - The remaining 26 bits do not affect this operation.

   These are high numeric address values under the unsigned 32-bit interpretation, not evidence that the target permits such accesses.

4. **Clear a word through G1.**  
   Read the current value of G1 and write a 32-bit zero at that value plus 0x0C.

5. **Copy G2 into G3.**  
   Read G2 and assign that value to G3.

6. **Clear G4.**  
   Assign zero to G4.

7. **Clear G5.**  
   Assign zero to G5.

8. **Set G6.**  
   Assign the constant represented as 0xFFFFFFA0 to G6. In a signed 32-bit interpretation, that bit pattern represents −96.

9. **Write through a fresh read of G2.**  
   Read G2 again and write the 32-bit value 0x000004B0 at that value plus 0x10.

   This address is not necessarily based on the value copied in step 5. Intervening writes may have changed G2 through overlapping storage.

10. **Assign Q's address to G7.**  
    Store the address of Q in G7. No contents of Q are read.

11. **Write a shifted value through G3.**  
    Use the current G3 value as an address base, adding 0x14, and write a 32-bit result obtained by shifting the current G3 value right by 29 positions.

    The representation does not establish the signedness of G3 or the right-shift rule for negative values. Under a logical 32-bit shift, the result is in the range 0 through 7. Under an arithmetic signed 32-bit shift, the result is in the range −4 through 3.

    The expression contains references to G3 for both destination formation and value calculation. Their relative evaluation order is not established. No intervening call or explicit write occurs between those references, but volatile, externally changing, or device-backed behavior is not characterized.

12. **Assign Q's address to G8.**  
    Store the same statically referenced address in G8.

13. **Reach the invalid-instruction boundary.**  
    The supplied representation stops here. It does not establish a successful return or any subsequent behavior.

### Aliasing and observation order

All explicit stores before a given step precede that step in the represented sequence. This order matters because the destinations are not proven disjoint.

For example:

- The first store may alter bytes used by the second store.
- The byte clear may overlap a global later read or written.
- The store through G1 may change G2 before its first represented read.
- Assignments to G4, G5, or G6 may change G2 before its second read.
- The store through G2 or the assignment to G7 may change G3 before step 11.
- The store through G3 may affect G8 before the final assignment.

These are conditional consequences of possible overlap, not claims that particular overlaps exist.

An implementation of this contract must not replace later global reads with earlier snapshots unless non-aliasing and stability have been established separately.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

### E selects the lower endpoint

Given unsigned 32-bit E equal to zero, and assuming the first two stores complete, the third operation attempts an 8-bit zero store at numeric address 0xFFFFFF30.

The same address is selected for any E whose top six bits are zero.

### E selects the upper endpoint

Given E equal to 0xFFFFFFFF, the shifted value is 63. Under unsigned 32-bit arithmetic, the third operation attempts an 8-bit zero store at 0xFFFFFF6F.

This example does not imply that the address is writable.

### Earlier stores have disjoint destinations

Assume A is 0x00001000, C is 0x00002000, H is 0xA55A, and the relevant memory is writable and suitably aligned.

The first store writes the 16-bit value 0x1000 at 0x0000100C. The second writes the 16-bit value 0xA55A at 0x0000202A. Their byte order follows target endianness.

The 16-bit narrowing in this example is in range, so it does not require an out-of-range signed-conversion rule.

### G2 changes between reads

Assume step 5 reads G2 as address X. If an intervening write changes G2 to address Y, step 9 uses Y plus 0x10, not X plus 0x10.

G3 initially receives the value read at step 5. Whether it retains that value until step 11 depends on intervening overlap.

### G3 has its high bit set

Assume G3 remains 0x80000000 through both references in step 11, the destination address is valid, and address addition produces 0x80000014.

- With logical 32-bit right shift, the stored value is 0x00000004.
- With arithmetic signed 32-bit right shift, the stored bit pattern is 0xFFFFFFFC.

Neither alternative is unconditionally required until the missing type and shift semantics are established.

### An early access faults

If the second store cannot complete, the represented normal sequence does not reach the byte clear or later assignments. The first store may already have occurred.

The exact fault delivery and any partial effects of the failing store remain target-dependent.
