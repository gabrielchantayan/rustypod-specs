# F-a23d3b60a679

## Purpose

F-a23d3b60a679 performs a dependency-gated, stateful dispatch. It first calls F-be069eb566cb with the caller’s second argument and a fixed argument of 1. The dependency’s result determines whether this function returns a sampled global value or examines the caller-provided object.

When the dependency returns zero, the function checks an eight-bit portion of an object field. If that portion is zero, the function writes a one-byte marker and invokes an indirect callback associated with the object. A callback result of exactly 7 maps to a return value of zero; every other normally returned callback result maps to 9.

The marker appears intended to prevent repeated dispatch. That interpretation is inferred, not an unconditional guarantee: the check and write have an endianness qualification, and the callback may modify the object.

This contract describes behavior supported by the supplied static representation. No runtime tests have been performed.

## Behavior

### Dependency call and global sampling

The first represented operation with external behavior is a call to F-be069eb566cb. It receives the context value followed by 1.

Only after that dependency returns does F-a23d3b60a679 sample the 32-bit global value. Consequently, any changes F-be069eb566cb makes to that global before returning can affect the sampled value.

The global sampling appears on both dependency-result paths in the supplied representation. On the zero-result path, the sampled value is subsequently discarded. This establishes source-level evaluation order; it does not independently establish whether a compiled execution must perform a physical memory read when its value is unused, because volatility and optimization constraints are unavailable.

### Nonzero dependency result

If F-be069eb566cb returns any nonzero integer value:

- The sampled global value is returned unchanged.
- The marker field is not read.
- No marker write is performed.
- The indirect callback is not looked up or invoked.

The dependency result itself is not returned. Its only established role here is selecting between the zero and nonzero paths.

### Zero dependency result and marker check

If F-be069eb566cb returns zero, the function sets its pending return value to zero and reads the integer word beginning at object byte offset 28.

That word is narrowed to a character-sized value for comparison with zero. Under the represented 32-bit-word, eight-bit-character interpretation, the condition depends on the low-order eight bits of the integer value. Signed versus unsigned character interpretation does not affect whether this narrowed value is zero.

If those eight bits are nonzero:

- The function returns zero.
- No marker write occurs.
- No callback lookup or invocation occurs.

The remaining 24 bits of the field do not independently prevent dispatch. A nonzero 32-bit field whose low-order eight bits are zero takes the dispatch path.

### Marker write and callback dispatch

If the narrowed value is zero, the function first writes byte value 1 at object byte offset 28.

Only after that write does it obtain the dispatch-table base from the first object word, read the callback address from the table’s byte-offset-28 slot, and invoke that callback with the object reference as its explicit argument.

This order matters:

- The marker write precedes callback execution.
- The first object word used for dispatch is read after the marker write.
- The callback receives the same object reference supplied to this function.
- The function does not restore the marker after the callback.

The representation checks a narrowed integer value but writes the first addressed byte of the integer field. These refer to the same eight bits on a little-endian target. They need not refer to the same eight bits on a big-endian target. The intended repeated-dispatch prevention therefore requires either the matching byte order or an additional layout guarantee not supplied here.

### Callback result mapping

After a normal callback return:

- A result exactly equal to integer 7 leaves the function’s return value at zero.
- Every other integer result produces return value 9.

Zero, negative values, and positive values other than 7 all take the latter case. The callback result is not propagated unchanged.

The function does not reread the global value after the callback. Callback changes to that global therefore do not alter the zero-or-nine return selection on this path.

There is no shown recovery path if the dependency or callback fails to return normally.
