# F-9f6766cf56e4

## Purpose

F-9f6766cf56e4 performs a conditional 32-bit equality check on state reached through its first input. It invokes F-bb2fbec1af57 before checking that state and invokes F-fd58bea73663 on every explicit normal-return path.

The returned value is:

- **1** when a 32-bit primary field reads as exactly 1 and a subsequently obtained 32-bit secondary field equals the second input.
- **0** otherwise.

Both outcomes require the final dependency call to return normally before this function returns. A fault or nonreturning dependency is not represented by a separate error result.

The primary condition is read after F-bb2fbec1af57 returns. The secondary field, when required, is read after F-2a80d6dba434 returns. Thus, the function does not compare a snapshot of state taken at entry.

“Primary,” “secondary,” “preparation,” and “finalization” below are descriptive labels. They do not establish object types, resource acquisition, ownership transfer, or resource release.

## Behavior

### Preparation and argument construction

The temporary is first initialized with the fourth input.

F-bb2fbec1af57 is then called once with five arguments, in the following logical argument positions:

1. The address of the writable 32-bit temporary.
2. The 32-bit value read from the primary location at offset 0x1c.
3. The third input.
4. The original fourth input.
5. The third input again.

The duplicate third-input arguments are part of the visible interface. The fourth argument is the original fourth input, not a later read of the writable temporary.

The primary field at offset 0x1c is read before preparation begins. Its value is not directly used in either subsequent equality check. No return value from F-bb2fbec1af57 participates in the visible decision.

Passing the temporary’s address permits F-bb2fbec1af57 to change its contents. It also means that subsequent effects cannot be characterized solely as “whatever preparation wrote”: the dependency may make that address reachable through shared state, and an intervening dependency may then modify the temporary indirectly. No dependency-preservation guarantee is supplied.

### Primary condition

After F-bb2fbec1af57 returns, the function reads the 32-bit primary field at offset 0x14 and compares it with exactly 1.

If the value is not 1:

- F-2a80d6dba434 is skipped.
- This caller performs no secondary-field read.
- The normal-return outcome is 0, subject to finalization returning normally.

All non-1 values take this path. In particular, another nonzero value does not qualify merely because it is nonzero.

If the value is 1, the function proceeds to the secondary comparison.

### Secondary comparison

F-2a80d6dba434 is called once with the first input as its sole argument. Its result is interpreted as a base address.

After that dependency returns, the caller reads the 32-bit field at offset 0x10 from the returned base and compares it with the second input:

- Equal values select the normal-return outcome 1.
- Unequal values select the normal-return outcome 0.

The primary condition is not re-read after F-2a80d6dba434. Changes that dependency makes to the primary field therefore do not cause this caller to repeat or reverse the primary branch decision.

The dependency may also change the secondary storage before returning. The comparison uses the field value read after that return, not any earlier value.

### Finalization and return

Each explicit normal-return path invokes F-fd58bea73663 once with a single 32-bit argument.

**That argument is the temporary’s value when the finalization argument is evaluated.** It is not necessarily:

- The original fourth input.
- The value the temporary held immediately after preparation.
- A value preserved across F-2a80d6dba434.

In particular, if preparation exposes the temporary’s address through shared state, F-2a80d6dba434 may modify the temporary through that retained address. Finalization then receives the value present at its argument evaluation, including such an intervening modification.

A replacement written during preparation is the finalization argument only if no intervening modification occurs. This remains a condition even on a path that skips F-2a80d6dba434; skipping that dependency is not, by itself, a general guarantee against every possible intervening modification.

F-fd58bea73663 receives the value by value, rather than receiving the temporary’s address at this call site. A later change to the temporary does not retroactively change the scalar argument already supplied.

There is no visible zero-value check or special-case omission of finalization. Its return value is unused. If it returns normally, this function returns the outcome selected by the comparisons. It performs no further object comparison or retry.

This establishes finalization only on the explicit normal paths. It does not establish finalization after a failed memory access, a dependency that does not return, or another nonlocal departure.

### Widths and arithmetic

The primary comparison accepts only the 32-bit representation of 1. For the secondary equality check, interpreting the same 32-bit representations as signed or unsigned does not change equality.

The offsets are measured in bytes. Address formation adds 0x1c, 0x14, or 0x10 to the relevant base. No count arithmetic, multiplication, length computation, or data-value increment is visible.

The supplied representation does not establish a portable rule for overflowing address formation, misalignment, or access outside valid storage. Such cases must not be assigned a wrapping or recovery guarantee.

## Side effects

The caller’s explicit data write initializes its invocation-local temporary. The visible body does not directly write either inspected object field.

This does not establish preservation of caller-visible state:

- F-bb2fbec1af57 receives the temporary’s writable address and other opaque arguments.
- F-2a80d6dba434 receives the primary base and may access state made reachable by earlier calls.
- F-fd58bea73663 receives the temporary’s value at argument evaluation.
- None of these dependencies is established to preserve globals, object contents, allocations, or shared state.

The significant visible ordering is:

1. Initialize the temporary from the fourth input.
2. Read the primary field at offset 0x1c for preparation.
3. Invoke F-bb2fbec1af57.
4. Read the primary field at offset 0x14.
5. If that field equals 1, invoke F-2a80d6dba434 and then read the secondary field at offset 0x10.
6. Read the temporary to obtain the finalization argument.
7. Invoke F-fd58bea73663.
8. If finalization returns normally, return the selected 0 or 1.

This ordering is not a synchronization, atomicity, or coherent-snapshot guarantee.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. **No runtime tests have been performed.** Except where a departure is explicitly described, the examples assume required accesses are valid and invoked dependencies return normally.

1. **Primary field is zero.**  
   If the post-preparation primary field at offset 0x14 reads as 0, F-2a80d6dba434 is skipped. Finalization receives the temporary’s value at argument evaluation, and the function returns 0.

2. **Primary field is another nonzero value.**  
   A primary field value of 2 takes the same branch as 0. It does not enable the secondary lookup.

3. **Both conditions qualify.**  
   If the primary field reads as 1 and the secondary field read after F-2a80d6dba434 equals the second input, finalization occurs and the function returns 1.

4. **Secondary equality fails.**  
   If the primary field reads as 1 but the secondary field differs from the second input, finalization still occurs and the function returns 0.

5. **Preparation changes the primary field.**  
   An entry value of 0 followed by a preparation change to 1 enables the secondary lookup. An entry value of 1 followed by a preparation change to 0 skips it. The observed post-preparation read controls the branch.

6. **Preparation replaces the temporary without a later modification.**  
   Suppose the fourth input is 7 and preparation changes the temporary to 9. If no modification occurs between that change and finalization argument evaluation, finalization receives 9. This condition applies whether the secondary dependency runs or is skipped. Preparation’s fourth argument remains the original value 7.

7. **An intervening dependency changes the retained temporary.**  
   Suppose preparation changes the temporary to 9 and makes its address reachable through shared state. If the primary field qualifies and F-2a80d6dba434 uses that address to change the temporary to 12, finalization receives 12, provided no further modification occurs before its argument is evaluated. Receiving 9 is not guaranteed merely because preparation wrote 9.

8. **Finalization changes inspected state.**  
   If the comparisons select 1 and finalization then changes either inspected field, the caller does not re-evaluate either comparison. It returns 1 if finalization returns normally.

9. **Finalization does not return normally.**  
   Selecting either comparison outcome does not guarantee an actual return. If finalization does not return, this function does not reach its explicit return.

10. **Secondary access is unnecessary.**  
    When the primary field is not 1, this caller neither requests a secondary base nor reads a secondary field. Earlier primary accesses and preparation still occur.
