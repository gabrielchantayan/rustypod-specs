# F-6ae49257d390

## Purpose

F-6ae49257d390 obtains a two-field result for an object-associated index. A context field selects between a dependency-backed operation and a local-table lookup.

Established behavior includes validation order, repeated context resolution on one path, conditional memory reads, output writes, fixed-width arithmetic, and status propagation. The domain meanings of the index and result fields are not established.

The local-table comparisons suggest a range-to-value lookup. That is inferred intent, not a guarantee of ordered boundaries, complete coverage, or valid table structure.

### Preconditions and output guarantees

The first output field is written before output validation. It must therefore be writable even for an invocation that subsequently rejects the index. A null output reference is not safely rejected before access.

The second output field is not initialized at entry.

A completed local-table operation directly writes both fields. A returning dependency-backed operation directly writes the first field after its dependency returns; the dependency receives the second field’s address, but its writing behavior is unknown.

All storage actually accessed must support those accesses for ordinary completion. No non-aliasing requirement is established. Output writes may alter later object, context, or table reads if their storage overlaps. Neither dependency is assumed to preserve reachable memory or globals.

## Behavior

### Entry and initial validation

The first observable operation is a 16-bit zero write to the first output field.

F-8ff48652068d is then called with the object reference. Its result supplies the initial context.

Validation follows in this short-circuit order:

1. Reject a null output reference.
2. Reject an index whose signed 32-bit interpretation is negative.
3. Read the unsigned bound at object offset `0xE78`; reject an index greater than or equal to that bound.

A detected failure returns `0xFFFFFFCE`.

Consequences include:

- Context resolution precedes all index rejection.
- Index patterns from `0x80000000` through `0xFFFFFFFF` fail the signed check.
- A signed-negative index does not require a bound read.
- A zero bound admits no index.
- The earlier output write is not undone.
- Dependency effects or aliasing may change memory beyond the function’s direct writes.

After successful validation, the function reads the initial context’s field at `0xE74`. Zero selects the dependency-backed path; nonzero selects the local-table path. There is no explicit null-context check before this access.

### Dependency-backed path: repeated validation

The function clears the first output field again and calls F-8ff48652068d again with the same object reference.

It then repeats the output-null, signed-index, and unsigned-bound checks in the same logical order. The bound is freshly read when the preceding checks permit that read.

Failure returns `0xFFFFFFCE` without calling F-5ef10d079522.

The second context may differ from the first. Its field at `0xE74` is not checked again before proceeding.

### Dependency-backed path: arguments and address arithmetic

After successful repeated validation, a temporary unsigned 32-bit quantity is initialized to the index.

F-5ef10d079522 receives four arguments:

1. The address-bearing quantity at offset `0xF60` in the second context, advanced by `0x118` bytes.
2. A four-byte value read using the object’s base field at `0xE70` and the index.
3. The address of the second output field.
4. The address of the temporary quantity.

The second argument’s address calculation has established unsigned 32-bit wrapping semantics. Let \(I\) be the index and \(B\) the 32-bit pattern loaded from object offset `0xE70`. The byte offset \(D\) and effective address \(A\) are:

\[
D=(4I)\bmod 2^{32}
\]

\[
A=(B+D)\bmod 2^{32}.
\]

A four-byte value is read at \(A\). Both multiplication and addition are unsigned 32-bit operations. The base field’s signed representation does not turn this addition into signed arithmetic.

This is not necessarily access to the mathematically indexed element of an unbounded array. An index can pass both validations while its scaled offset wraps. In particular, index `0x40000000` has byte offset zero and therefore accesses the address held in the base field.

There is no explicit rejection of offset overflow, base-addition overflow, a zero effective address, or an inaccessible effective address. Wrapping determines the address; it does not establish that the resulting access is valid.

The relative evaluation order of the separate argument-producing memory reads is not established. The context-derived argument’s addition by `0x118` is distinct from the unsigned array-address arithmetic; its overflow semantics are not established here.

### Dependency-backed path: return and output encoding

After F-5ef10d079522 returns, the function writes an encoding of the temporary’s then-current value to the first output field.

For unsigned 32-bit temporary value \(T\), the resulting 16-bit pattern is:

\[
\left\lfloor T/2\right\rfloor\bmod 2^{16}.
\]

Thus original temporary bits 1 through 16 become output bits 0 through 15. Bit 0 and bits 17 through 31 do not contribute.

The dependency’s status is returned unchanged. The first-field write occurs regardless of the external success or failure meaning of that status.

There is no direct second-field write on this path. If the dependency leaves that field unchanged, this function does not fill it afterward. Predicting the first field from the original index requires the additional condition that the dependency leave the temporary unchanged.

### Local-table setup

The local-table path writes 1 to the first output field, then rereads the initial context’s field at `0xE74`.

This is a separate observation from path selection. In particular, an overlapping first-field write may change the reread address.

The function rejects, in order:

1. A null reread table address.
2. A null computed address for the second output field.

Either detected failure returns `0xFFFFFFCE`. The first-field write of 1 has already occurred.

The conditions under which the second-field address can be null after a valid entry write are unresolved.

The reread table address defines this four-byte-word layout:

| Word position | Role |
|---|---|
| 0 | Signed 32-bit record count |
| \(2j+1\) | Value associated with record ordinal \(j\) |
| \(2j+2\) | Boundary associated with ordinal \(j\) |

Boundary comparisons use unsigned 32-bit interpretations.

The lower search ordinal starts at zero. The upper ordinal is the signed count minus one. A retained ordinal starts at zero.

For a nonempty interval, the retained ordinal becomes the midpoint formed by signed addition of the lower and upper ordinals followed by a right shift by one. For nonnegative bounds with representable addition, this is the lower midpoint. Extreme signed arithmetic and negative-shift behavior are not generalized beyond the representation.

### Ordered local-table observations

The following describes separate reads, not cached values.

For current midpoint ordinal \(j\), the first boundary read is word \(2j+2\).

**If that observation is at most the index:**

- Word \(2j+2\) is read again.
- If the index is at most this second observation, ordinal \(j\) is selected.
- Otherwise, word \(2j+4\), the following boundary, is read.
- If the index is strictly below this observation, ordinal \(j\) is selected.
- Otherwise, word \(2j+4\) is read again.
- If this latest observation equals the index, ordinal \(j+1\) is selected.
- Otherwise, the lower search ordinal becomes \(j+1\), and interval processing continues.

The following boundary is not read when the second current-boundary comparison selects the current record. Its equality read occurs only after its strict comparison fails.

**If the first current-boundary observation is greater than the index:**

- Word \(2j\) is read as a preceding boundary.
- If that unsigned observation is at most the index, ordinal \(j-1\) is selected.
- Otherwise, the upper search ordinal becomes \(j-1\), and interval processing continues.

This branch does not perform the second current-boundary read or either following-boundary read.

Repeated observations of one address are not required to agree. For example, a current boundary observed first below the index and then above it selects the current record.

### Stable-boundary interpretation

With stable observations:

- Equality with the current boundary selects the current record without reading the following boundary.
- A current boundary strictly below the index leads to following-boundary comparisons:
  - A following boundary above the index selects the current record.
  - A following boundary equal to the index selects the following record.
  - A following boundary below the index advances the lower search ordinal.
- A current boundary above the index leads instead to the preceding-boundary comparison.

Stability does not imply increasing boundaries. Equality with a following boundary matters only if execution reaches that comparison. A conventional increasing-range interpretation requires additional invariants that this function does not check.

### Local-table completion and irregular shapes

On selection, the function reads the selected ordinal’s value word, writes its low 16 bits to the second output field, and returns zero. There is no saturation or value-range validation.

If the search interval becomes empty without selection, the retained midpoint ordinal is still used for the result read. There is no distinct “not found” return.

If the interval is empty before any midpoint is formed, the retained ordinal remains zero and word 1 is used. This includes count zero and negative counts for which subtracting one is representable.

Two unguarded cases are significant:

- At ordinal zero, the preceding-boundary read accesses word 0, the count. If its unsigned comparison succeeds, ordinal −1 is selected and the value read accesses word −1.
- At the last nominal record, the following boundary is word \(2j+4\), beyond the count’s nominal value/boundary pairs.

Accessible surrounding storage or additional input invariants may be needed for ordinary completion. Neither is established.

1. **Index equals bound.** Index 7 and bound 7 produce the entry zero write, one context-resolution call, and return `0xFFFFFFCE`. There is no direct second-field write.

4. **Scaled-offset wrapping.** Index `0x40000000` passes the signed check and passes a bound of `0x40000001`. On the dependency-backed path, its scaled byte offset is zero. 5. **Base-addition wrapping.** With index 1 and loaded base `0xFFFFFFFC`, the scaled offset is 4 and the effective address is zero. The function attempts the four-byte read there without an explicit address check. An ordinary dependency call or return is conditional on that access being valid.

6. **Status and encoding.** If F-5ef10d079522 returns `0x12345678` and leaves the temporary at `0x00020003`, the first field becomes 1 and the returned status remains `0x12345678`.

7. **Untouched second field.** With index 6, an unchanged temporary, and no dependency modification of the second field, the first field becomes 3 and the second retains its prior contents.

12. **Changing observations.** With index 20, current-boundary observations of 10 then 30 select the current record. Alternatively, current observations both 10 and following observations of 20 then 21 advance the lower ordinal.
