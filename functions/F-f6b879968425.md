# F-f6b879968425

## Purpose

F-f6b879968425 conditionally updates an object’s numeric state, performs either a normal embedded-state update or a boundary transition, and then runs a guard-release protocol whose result becomes the function’s return value.

The established behavior has two distinct parts:

1. An update body, skipped when the object’s associated-object field is zero.
2. A common exit protocol, reached after the update body or its omission.

The exit result does not directly report whether the numeric update succeeded, reached a boundary, or was skipped. Names such as “guard,” “owner,” “counter,” and “configuration” describe apparent roles inferred from access patterns; they are not independently established domain semantics.

## Interface

### Inputs and return value

The function accepts:

- **Object address:** an address used as the base of a mutable, word-oriented object layout. Words and stored addresses are represented as 32-bit quantities.
- **Mode argument:** a 32-bit integer. Its low eight bits are stored in the object during an active update. Separately, its full 32-bit value is compared with zero when selecting a boundary flag.

The return value is a 32-bit integer produced by the common exit protocol:

- `26` on an explicit null-derived-guard branch.
- A nonzero result returned by F-621dae46a146, when that helper is invoked and returns nonzero.
- `5` on an ownership-identity mismatch.
- `0` on certain successful or deferred-release paths.
- Otherwise, the result of F-259d2fe281b0.

No separate numeric-update result is returned.

### Preconditions

The supplied object must support every reached memory access and indirect call. For the active body, this includes valid associated-object, configuration, and dispatch-table addresses.

There are no explicit validation branches for:

The explicit null-derived-guard branch occurs after an entry helper and possible body activity. It is not a general null-object check.

## Behavior

### 1. Entry and update eligibility

The function first derives the guard address at object offset `0xA4C` and passes it to an entry helper whose opaque identity is not supplied.

After that call returns, it reads the associated-object field at `0x054`.

- If the field is zero, it skips the entire update body and proceeds to the common exit protocol.
- Otherwise, it calls F-6ac70711bbb5, then F-5d641e9c768c, with no explicit arguments shown.

Only after those two calls does it:

1. Increment the 32-bit counter at `0x954`.
2. Store the low eight bits of the mode argument at `0x943`.
3. Invoke the associated object’s dispatch slot at `0x118`.

The associated-object address used for that dispatch is read after the two direct helper calls. The contract must not assume those helpers preserved the field or any other object state.

### 2. Gate selecting the update path

The result of the associated-object query is tested for zero.

- If it is zero, the function selects the arithmetic-update path without reading the gate byte at `0x944`.
- If it is nonzero, the function reads the low byte at `0x944`.
  - A zero byte selects the arithmetic-update path.
  - A nonzero byte selects the bypass path.

Thus, only the low byte of that gate field matters. Nonzero upper bytes alone do not activate the bypass.

### 3. Bypass path

On the bypass path, the counter is compared with `17` using an unsigned 32-bit comparison.

- If the counter is greater than `17`, the function writes `66` to the 32-bit field at `0x95C`.
- Otherwise, it leaves that field unchanged.

It then performs the shared embedded-state update described below. It does not execute the arithmetic update or the explicit boundary-flag write.

### 4. Counter clamp and adjustment calculation

On the arithmetic-update path, the function reads the configuration address at `0x960`.

It compares the configuration limit with the counter using unsigned 32-bit comparison. If the counter is greater than the limit, it replaces the counter with the limit.

It then calls F-d7be9cfb4000 with two 32-bit arithmetic expressions:

- First argument: counter squared, multiplied by the configuration base amount, multiplied by `3`.
- Second argument: configuration limit squared.

The helper’s 32-bit return value is the **adjustment** used below.

These are not established as widened, arbitrary-precision calculations. The expressions use 32-bit operands and intermediates in the supplied representation. Large counters, limits, or base amounts can exceed that width. Any mathematical interpretation requiring non-overflowing products therefore needs an additional input constraint.

The configuration address used for the clamp and helper arguments is obtained before F-d7be9cfb4000 is called. Later base-amount reads use the object’s configuration field again and can therefore observe a different configuration.

The helper’s name, arithmetic operation, signedness rules, rounding behavior, and behavior on a zero denominator are not established by the supplied evidence.

### 5. Direction selection and downward update

After obtaining the adjustment, the function invokes the object’s dispatch slot at `0x198`, explicitly supplying the object address.

A zero result selects the downward path:

1. Invoke the object’s slot at `0x17C`, explicitly supplying the object address.
2. Read the base amount through the configuration address currently stored at `0x960`.
3. Form a 32-bit candidate by subtracting the base amount and then the adjustment from the returned value.
4. Interpret the candidate as signed for the branch test.

If the signed candidate is nonnegative:

- Invoke the object’s slot at `0x100` with the object address and candidate.
- Perform the shared embedded-state update.

If the signed candidate is negative:

- Invoke slot `0x100` with the object address and zero.
- Invoke slot `0x0FC` with the object address.
- Perform the boundary-flag write.
- Skip the shared embedded-state update.

The branch tests the signed interpretation of the represented 32-bit result. It is not an independently established mathematical underflow check for all possible inputs.

### 6. Upward update

A nonzero result from slot `0x198` selects the upward path:

1. Invoke the object’s slot at `0x17C`. This call has no explicit arguments in the supplied representation, unlike the downward call at the same slot.
2. Read the base amount through the configuration address currently stored at `0x960`.
3. Form a 32-bit candidate by adding the returned value, base amount, and adjustment.
4. Invoke the associated object’s slot at `0x0A0` to obtain a comparison bound.
5. Compare the candidate and bound as unsigned 32-bit values.

If the candidate is less than or equal to the bound:

- Invoke the object’s slot at `0x100` with the object address and candidate.
- Perform the shared embedded-state update.

If the candidate exceeds the bound:

- Invoke the object’s slot at `0x0FC` with the object address.
- Invoke the object’s slot at `0x108` with the object address and the value `3`.
- Perform the boundary-flag write.
- Skip the shared embedded-state update.

Unlike the downward boundary path, this upward boundary path does not explicitly call slot `0x100` to assign a clamped value.

The associated-object address for the bound query is read after the preceding callbacks. It need not be the same address used for the earlier gate query.

### 7. Boundary-flag write

Both arithmetic boundary paths write exactly one byte at `0x942`:

- Full mode argument equal to zero: write `1`.
- Full mode argument nonzero: write `0`.

This comparison is independent of the earlier low-byte store. A nonzero mode argument with a zero low byte stores zero at `0x943` but still writes zero to the boundary flag.

No direct write to the boundary flag occurs on the bypass or accepted-candidate paths.

### 8. Shared embedded-state update

The bypass path and both accepted-candidate paths converge on this sequence:

1. Call F-6904f7699031 with the embedded address at `0x964` and the current 32-bit value at `0x95C`.
2. Call F-ec4cfa552cce with the embedded address at `0x964`.

Both return values are ignored.

On an accepted-candidate path, the value at `0x95C` is obtained after the setter callback returns. The contract does not assume the callback preserved it.

### 9. Common exit protocol

All normally returning body paths enter this protocol.

First, if the derived guard address is zero, return `26`.

Otherwise, compare the first 32-bit word at that address with a distinguished global value. If they match, call F-621dae46a146 with the guard address and zero.

- If that helper returns nonzero, return its result immediately.
- If it returns zero, continue.
- If the initial comparison does not match, continue without calling it.

Next:

1. Read and retain the 16-bit flags at `0xA5A`.
2. Call F-196812b4b122 with no explicit arguments.
3. Compare its 32-bit result with the owner field at `0xA50`, read after that call.

If the values differ, return `5`. The supplied function performs no further direct owner or count writes on this branch.

If they match, extract bits 4–5 from the previously sampled flags.

- If those bits do not equal binary `10`, perform the final-clear sequence below.
- If they equal binary `10`, decrement the 16-bit count at `0xA5E` and store the 16-bit result.
  - If the stored result is nonzero, return `0` without the final-clear sequence.
  - If it is zero, perform the final-clear sequence.

The final-clear sequence is:

1. Write 16-bit zero to `0xA5E`.
2. Write 32-bit zero to `0xA50`.
3. Call F-259d2fe281b0 with the embedded address at `0xA60`.
4. Return that helper’s result.

The flags are sampled before F-196812b4b122, but the count is read afterward when needed. A dependency-induced flags change does not replace the sampled flags for this invocation.

## Acceptance examples

These examples are conditional specifications, not executed tests. Assume valid memory, returning dependencies, and no intervening mutations except those stated.

1. **Inactive object:** With `0x054` equal to zero after the entry helper, no body helper, counter increment, or mode-byte store occurs. The exit protocol still executes.

2. **Gate byte matters:** With a nonzero associated query result and a gate word of `256`, the low byte is zero, so arithmetic updating is selected. A nonzero upper byte is insufficient for bypass.

3. **Bypass threshold:** With bypass selected and an incremented counter of `18`, the function writes `66` at `0x95C`, then calls the two embedded-state helpers in order. At an incremented counter of `17`, it does not directly replace that field.

4. **Accepted downward candidate:** If slot `0x198` returns zero, slot `0x17C` returns `20`, the subsequent base amount is `5`, and the adjustment is `3`, the candidate is `12`. The function calls slot `0x100` with `12`, then performs the shared embedded-state update.

5. **Downward boundary:** With corresponding values `7`, `5`, and `3`, the candidate represents `−1`. The function calls slot `0x100` with zero, then slot `0x0FC`, writes the boundary flag, and omits the shared embedded-state update.

6. **Inclusive upward bound:** An upward candidate equal to the unsigned bound is accepted. A candidate one greater than that bound takes the upward boundary path, subject to 32-bit arithmetic representation.

7. **Full-width mode distinction:** A mode argument of `256` stores zero at `0x943`. If a boundary is reached, it writes zero—not one—at `0x942`.

8. **Deferred release:** With matching identity, sampled flag bits equal to binary `10`, and count `2`, the function stores count `1` and returns zero without explicitly clearing the owner or calling F-259d2fe281b0.

9. **Final nested release:** Under the same conditions with count `1`, the decrement stores zero, the final-clear sequence writes zero to count and owner, and the function returns F-259d2fe281b0’s result.

10. **Zero nested count:** With the nested flag pattern and an initial count of zero, the represented 16-bit decrement produces all-one bits. That result is nonzero, so the function does not treat this as a final release.

11. **Early exit-helper result:** If the distinguished-word comparison matches and F-621dae46a146 returns a nonzero value, that value is returned without the later flags read, identity query, or explicit final-clear sequence.
