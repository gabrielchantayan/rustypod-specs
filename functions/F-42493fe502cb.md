# F-42493fe502cb

## Purpose

F-42493fe502cb conditionally processes an attached object referenced by a caller-supplied context. It always invokes an entry dependency and, if that call returns normally, clears a context field. Further processing requires a nonnull attached-object address and a strictly positive signed activation value.

Active processing prepares one attached-object field, then selects between two paths using a byte in a captured parent object:

- A nonzero byte selects delegation to F-30162766ee7c.
- A zero byte selects an optional packed-position update followed by formatting-associated, catalog-related, and instruction-like calls.

Virtual-table creation is **inferred intent**, supported by labels associated with supplied formatting and catalog data. The established contract is the sequence of accesses, calls, writes, and return construction below. The dependency implementations and complete referenced data are unavailable.

The return combines two 32-bit components into a 64-bit value. It is not established as a conventional success or failure result.

### Preconditions and validity

There is no local null check for the context. Every reached access must designate storage valid for its width and operation.

A nonnull attached object causes a context-parent read before the activation read. Thus, even an inactive attached object requires that context-parent field to be readable; the parent itself is not dereferenced unless active processing reaches a parent access.

Optional-span requirements are path-dependent:

- Inactive paths do not dereference it locally.
- Delegation forwards it unchanged; the dependency’s requirements are unknown.
- The nondelegated path skips the packed-position update when it is null.
- A nonnull span on that path supplies two readable 32-bit words.

Captured objects must remain usable across intervening calls wherever later accesses depend on them. No dependency-preservation guarantee is established.

Descriptor selection has no local bounds check. No alignment, disjointness, concurrency, or complete object-size contract is supplied.

## Behavior

### Entry and activation

F-68e888673254 is invoked first, with no explicit arguments. After normal return, context offset 0x190 receives zero. The attached-object address is then read from context offset 0x180.

If that address is null, local processing ends.

Otherwise, the parent address is read from context offset 0x000, followed by the attached object’s signed 32-bit activation value at offset 0x044. Only values greater than zero enter shared preparation. Zero and negative values return the original packed address pair.

The activation value is a gate, not an established iteration count. The parent-address read occurs even when activation fails.

The entry call precedes all these explicit context accesses. The body does not establish that it preserves context-reachable state or global values.

### Shared preparation

For an active attached object, the address at attached-object offset 0x048 is read, then one 32-bit value is read through that address. This indirect value is captured and passed to F-1cb585febd84.

F-a09bb08bf954 receives, in argument-position order:

1. The captured parent address plus 0x0F4.
2. The captured indirect value.
3. The preceding F-1cb585febd84 result.

Its result is written to attached-object offset 0x03C. Only afterward is the branch-selector byte at captured-parent offset 0x080 read.

A nonzero byte selects delegation. Zero selects the nondelegated sequence.

The attached-object and parent addresses used here are captured values. Replacing their corresponding context fields during a dependency call does not redirect subsequent operations through those captures. Invalidation or modification of the captured storage remains a separate lifetime risk.

### Delegated path

The pre-call read order is explicit:

1. Read and capture the attached object’s name-like field at offset 0x000.
2. Read and capture its secondary-object address at offset 0x04C.
3. Call F-1cb585febd84 with the captured name-like value.

The two field reads occur in separate, ordered operations. They are not unordered reads within one argument list.

F-30162766ee7c then receives:

| Position | Argument |
|---:|---|
| 1 | Captured secondary-object address plus four bytes |
| 2 | Captured name-like value |
| 3 | Preceding signed 32-bit dependency result incremented by one |
| 4 | Captured attached-object address |
| 5 | Original context address |
| 6 | Original optional-span address |
| 7 | Opaque argument A |
| 8 | Opaque argument B |

The result is tested for zero:

- **Zero:** reread the context parent at offset 0x000; store that fresh value at captured-secondary-object offset 0x060; then clear context offset 0x180.
- **Nonzero:** write byte value 1 to offset 0x01E of the earlier captured parent.

The zero-result target remains the previously captured secondary object, even if a dependency replaces the attached object’s secondary-object field. The stored parent value is fresh. Conversely, the nonzero-result target is the earlier captured parent, not a newly read context parent.

Both outcomes return the original packed address pair and bypass the nondelegated sequence.

Clearing the attached-object field does not establish destruction, release, ownership transfer, or invalidation of other references.

### Nondelegated packed-position update

A null optional span skips this explicit update. Otherwise, the replacement uses both span words, the signed context base at offset 0x168, and the previous packed value at offset 0x16C.

Let:

- \(P\) be the previous packed 32-bit value.
- \(S_0\) be the signed first span word.
- \(S_1\) be the second span word’s 32-bit pattern.
- \(B\) be the signed context base.

Where the signed subtraction is representable, define:

\[
U =
\left(
\operatorname{uint32}(S_0-B)
+
(S_1 \gg 1)
\right)
\bmod 2^{32},
\]

where the right shift is logical. The stored bit pattern is:

\[
(P \mathbin{\&} 1)
\mathbin{|}
\left((2U)\bmod 2^{32}\right).
\]

The subtraction is represented as signed 32-bit arithmetic. Conversion of the second span word to unsigned occurs before its right shift. The subsequent addition and multiplication use unsigned 32-bit arithmetic.

Consequently, the previous packed value contributes only bit zero; doubling supplies the remaining bits and clears bit zero before combination.

Later unsigned wrapping does not resolve an earlier overflowing signed subtraction. Such inputs remain **documented_only**.

The expression does not establish a total order among its operand reads. The destination write follows evaluation of the replacement. Aliasing is not prohibited, but no broader aliasing or concurrent-mutation guarantee is supplied.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes reached accesses are valid, dependencies return normally, and relevant signed arithmetic is representable.

1. **Absent attachment.** If context offset 0x180 is null after the entry dependency, context offset 0x190 is cleared and the original packed address pair is returned. No optional-span word is read locally.

2. **Activation boundary.** Activation values 0, −1, and bit pattern 0xFFFFFFFF skip shared preparation. With a nonnull attached object, the context-parent read still precedes the activation read.

3. **Ordered delegated capture.** Once delegation is selected, the explicit access trace reads attached-object offset 0x000 first, then offset 0x04C, then calls F-1cb585febd84 with the captured name. A trace reversing those two reads does not match the supplied body.

4. **Mutation during delegated length-like processing.** If that F-1cb585febd84 call changes either attached-object field, F-30162766ee7c still receives the name and secondary-object address captured before the call.

5. **Delegated span forwarding.** The original span address is forwarded unchanged without local span-word reads. This does not establish that an unreadable span is acceptable to F-30162766ee7c.

6. **Delegated zero with replaced references.** If delegation replaces the context parent and attached-object secondary reference, then returns zero, the fresh context parent is stored into the previously captured secondary object. The attachment field is cleared afterward.

7. **Delegated nonzero with replaced parent.** A nonzero result writes byte 1 into the earlier captured parent, even if delegation replaced the context parent field. No explicit attachment clear follows.

8. **Packed position.** Previous packed value 0xA5, first span word 100, base 90, and second span word 7 produce 27. Changing only the previous packed value to 0xA4 produces 26.

9. **Logical shift.** With first span word equal to the base and second span pattern 0x80000000, the shifted contribution is 0x40000000. Doubling produces 0x80000000, combined with the previous packed value’s low bit.

10. **Conditional global mutation.** If the global is writable and F-49f750c2c596 changes it before argument preparation, the later read observes that changed value absent intervening modification. If it is constant-backed, the same call sequence can instead read the constant. Neither storage property is established.

11. **Catalog choice is not bounds validation.** Index 1 selects the temporary-catalog argument; index 0 selects the ordinary-catalog argument. A negative index also selects the ordinary argument, but its descriptor access is unchecked.

12. **Final capture.** If the last F-1cb585febd84 changes the name field, the subsequent read supplies the final call’s name argument and return high component. A further mutation by the final call does not change that captured return component.
