# F-70ab9b8c0f53

## Purpose

F-70ab9b8c0f53 selects between two result-producing paths using a field in a caller-supplied object:

- If the field is initially nonzero, it calls F-8c219ee345dc, then combines that dependency’s result with a **fresh read** of the field using unsigned right shifts and multiplication.
- If the field is initially zero, it calls F-1ec05f1e044b with the original object value and the integer selector 1, then obtains its result through an indirect operation selected from the returned structure.

The established behavior is this selection, calculation, and dispatch. The application-level meaning of the object, field, shifts, selector, and result is not established. In particular, the field must not be assumed to represent a count, size, rate, or ownership flag.

This contract separates behavior directly supported by the supplied static representation from properties that depend on an unavailable ABI or dependency implementation. No runtime tests have been performed.

## Behavior

### 1. Initial branch selection

The function first reads the field at byte offset 20 and compares its signed integer interpretation with zero.

Only equality with zero matters. Every nonzero pattern selects the arithmetic path, including patterns that would represent negative signed values.

The initial value selects the path; it is not retained as the arithmetic operand. Once selected, the path is not reconsidered even if a dependency subsequently changes the field.

### 2. Initially nonzero field: dependency followed by calculation

The function calls F-8c219ee345dc with the original input value.

If that dependency returns normally, its result is captured as an unsigned value. The function then reads the field at byte offset 20 again, this time as an unsigned value.

Let:

- \(A\) be the unsigned value obtained from this **second** field read.
- \(B\) be the dependency result after conversion to the represented unsigned width.

The unsigned calculation is:

\[
P = (A \mathbin{\mathrm{logical\ right\ shift}} 1)
    \times
    (B \mathbin{\mathrm{logical\ right\ shift}} 9)
    \pmod{2^{32}}.
\]

Equivalently, for unsigned values:

\[
P =
\left\lfloor \frac{A}{2} \right\rfloor
\left\lfloor \frac{B}{512} \right\rfloor
\pmod{2^{32}}.
\]

Both shifts occur before multiplication. This is not generally equivalent to multiplying the original values and then shifting the product.

Consequences include:

- The low bit of the freshly read field does not contribute.
- The low nine bits of the dependency result do not contribute.
- A freshly read field value of 0 or 1 produces zero.
- A dependency result in the unsigned range 0 through 511 produces zero.
- A field value with its high bit set is shifted logically, not arithmetically.
- The multiplication retains only the low 32 bits in the represented unsigned model.

The function returns the calculated value through its integer return interface.

#### Dependency mutation matters

F-8c219ee345dc is not known to preserve the field, the object, or global state. Its mutations cannot be ignored when interpreting the second read.

For example, if the initial field is nonzero but the dependency changes it to zero, the function remains on the arithmetic path and calculates zero. It does not switch to the indirect path.

Conversely, if the dependency changes the field to another nonzero value, the calculation uses that later value rather than the value that selected the path.

The fresh read also requires the storage to remain valid after the dependency returns. No preservation or ownership guarantee is established by the visible caller.

### 3. Initially zero field: dependency followed by indirect operation

The function calls F-1ec05f1e044b with:

1. The original input value.
2. The integer selector 1.

If this dependency returns normally, its result is treated as an address of a structure. The function then performs a two-stage lookup:

1. Read a pointer-like value from the beginning of the returned structure.
2. Read an indirect-operation target at byte offset 12 from that pointer-like value.

The second lookup is relative to the value read in the first lookup, not relative to the original input object or directly to the dependency’s returned address.

In the represented 32-bit pointer model, the lookup layout is:

| Location | Access |
|---|---|
| Returned address, offset 0 | Read a pointer-like table base |
| Table base, offset 12 | Read the target used for indirect execution |

This resembles a table-based dispatch, but the object model, table format, and meaning of the selected entry are not established.

The indirect operation is represented as producing an integer result. That result becomes the function’s result, with no visible arithmetic adjustment.

The representation shows no explicit arguments to the indirect operation. This is insufficient to establish that the original target has a truly argument-free interface. An implicit receiver, register-carried argument, or other ABI-specific state is **documented_only**.

The supplied material explicitly marks this indirect transfer as uncertainly reconstructed. Its exact call-versus-jump behavior is therefore not established by the static representation alone.

### 4. Path separation

The visible paths remain distinct:

- An initially nonzero field causes F-8c219ee345dc to be called, not F-1ec05f1e044b.
- An initially zero field causes F-1ec05f1e044b to be called, not F-8c219ee345dc.
- The zero path does not visibly reread the original field after its dependency returns.
- A dependency’s mutation of the original field does not cause branch reselection.
- There is no visible retry, fallback path, or error recovery.

These statements concern the calls made directly by this function. The unavailable dependencies might themselves call other operations.
