# F-08a778c50842

## Purpose

F-08a778c50842 compares two integer sequences using shared scaling state. It returns one of three signed integer values: −1, 0, or +1.

The comparison has two levels:

1. Compare transformed values from the first element of each input.
2. If those transformed values are equal, use their common magnitude to determine how many additional elements to compare, proceeding from the highest selected index toward index 1.

During the second level, transformed elements are compared as **unsigned** values. A negative common first-level value reverses the direction of the second-level result.

This resembles a comparator for a sign-bearing, variable-length representation. That interpretation is inferred intent, not an established data-format guarantee. The supplied source does not establish that the inputs represent numbers, that they are normalized, or that this comparator defines a consistent ordering under changing shared state.

## Interface

### Inputs

The function receives two pointers to signed integer storage.

For this contract, the inputs are called the **left sequence** and **right sequence**. These are descriptive names, not source identifiers.

Each sequence has:

- A signed integer at index 0, called its **header**.
- Potentially additional signed integers at indices 1 and above, called **payload elements**.

The interface supplies no allocation sizes, element counts, capacity fields, or nullability indicators. Any required bounds must be satisfied by the caller.

The pointers need not refer to distinct allocations. No restriction against identical or overlapping input storage is established by the supplied source.

### Shared inputs

The function also reads two shared values:

- A **header multiplier**, used separately when transforming each header.
- A **payload multiplier**, used separately when transforming each payload element.

Their declarations, storage qualifications, and update rules are not supplied. Their exact integer types are therefore unknown.

### Output

The return type is signed integer. On defined, normally terminating execution, the returned value is exactly:

- **+1:** the selected comparison favors the left sequence.
- **−1:** the selected comparison favors the right sequence.
- **0:** the selected comparison finds equality.

“Favors” is deliberately narrower than a claim about numerical greater-than. In particular, a negative common transformed header reverses the direction used for payload comparisons.

### Widths and layout

The supplied representation distinguishes signed `int` from unsigned `uint`, but does not independently establish their numerical widths or the declarations of the shared multipliers.

Let:

- **Wₛ** denote the width of the signed integer storage and signed intermediates.
- **Wᵤ** denote the width of the unsigned payload-comparison intermediates.

The concrete values of Wₛ and Wᵤ are **documented_only** unknowns. A 32-bit signed/unsigned interpretation is possible, but is not made unconditional by this contract.

Sequence indexing advances by one signed-integer element, not one byte. The byte offset of index *k* is *k* times the size of that integer type. The function performs no byte-order conversion.

Unsigned comparison uses the stored unsigned intermediate values. Conversion of a representable negative product into an unsigned intermediate produces its value modulo 2^Wᵤ. ## Behavior

### 1. Transform the headers

The function first obtains a signed transformed value for the left header by multiplying it by the header multiplier and assigning the result to a signed intermediate.

It then independently obtains the corresponding signed transformed value for the right header.

The left transformation precedes the right transformation at the source-expression level. The header multiplier is referenced separately for each transformation; the source does not establish a single captured multiplier shared by both.

Call these resulting signed values **L** and **R**.

The ordering of the multiplier read and header read *within* either multiplication expression is not established. Nor does the supplied source establish that every source-level reference produces a separate physical memory load.

### 2. Resolve unequal transformed headers

The function first evaluates a signed subtraction, L − R, and tests whether it is nonzero.

If that test succeeds, it checks whether R is less than or equal to L. If so, it immediately returns +1.

If that return does not occur, it again checks whether R is less than or equal to L:

- If false, it returns −1.
- If true, it enters payload comparison.

For executions in which the relevant arithmetic has ordinary, defined signed semantics, these branches reduce to:

| Relationship | Result |
|---|---|
| L > R | Return +1 without reading payload elements |
| L < R | Return −1 without reading payload elements |
| L = R | Continue to payload comparison |

The subtraction is significant even though a direct relational comparison could express the same ordering over mathematical integers. A contract that silently replaces it with an overflow-free comparison would omit an arithmetic hazard present in the supplied source.

### 3. Derive payload count and comparison direction

Payload comparison is reached when the transformed headers compare equal under the defined-arithmetic interpretation above.

The common transformed header determines both the count and the direction:

- If L is nonnegative, the selected payload count is L and the direction is +1.
- If L is negative, the selected payload count is −L and the direction is −1.

The count is held in a signed integer intermediate.

The most-negative signed value is a special precondition concern: its positive magnitude is not representable in the same signed type. The source supplies no handling for that case.

### 4. Visit selected payload elements in descending order

Starting at the selected count, the function considers indices in this order:

**count, count − 1, …, 1**

Index 0 is not part of this payload scan.

Before each payload access, it evaluates the signed expression “current index minus one” and checks whether that result is negative. If so, it returns 0.

Consequently, when the selected count is zero:

- Neither payload is read.
- The payload multiplier is not referenced by the loop.
- The function returns 0.

For a positive valid count, the highest selected index is examined first. Lower indices cannot affect a result once a difference has been found.

### 5. Transform and compare each payload pair

At each selected index, the function:

1. Forms the left payload product using the payload multiplier.
2. Stores that result in an unsigned intermediate.
3. Forms the right payload product using a separate reference to the payload multiplier.
4. Stores that result in another unsigned intermediate.
5. Compares the resulting unsigned values.

The left product assignment precedes the right product assignment. Within each multiplication, the relative evaluation order of the multiplier and payload operands is not established.

Call the unsigned results **Uₗ** and **Uᵣ**.

The comparison outcome is:

| Unsigned relationship | Returned value |
|---|---|
| Uₗ > Uᵣ | The direction selected from the common transformed header |
| Uₗ < Uᵣ | The negation of that direction |
| Uₗ = Uᵣ | Continue to the next lower index |

The source implements the greater-than case through an unsigned less-than-or-equal test followed by an unsigned nonzero-difference test. Unsigned subtraction wraps modulo 2^Wᵤ and therefore does not have the signed-overflow hazard of the header subtraction.

On the equality and less-than paths, the internal index is decremented before the less-than return decision. That decrement does not itself read the next payload element.

If all selected payload pairs compare equal, the function returns 0.

### Equality is limited to selected transformed values

A return value of 0 does not prove that the input allocations or original elements are identical.

It means only that:

- The transformed headers reached the payload-comparison path; and
- No difference was found among the selected unsigned transformed payload values.

Different original elements may transform to the same unsigned value. Elements beyond the selected count are not examined. A zero common transformed header causes equality without any payload examination.

Expected result: **0**. Payload contents and the payload multiplier do not affect this path.

### Highest selected index takes precedence

Both headers are 2.

- Left payload: index 1 is 9; index 2 is 3.
- Right payload: index 1 is 1; index 2 is 4.

Expected result: **−1** because index 2 is compared first. The values at index 1 do not affect the result and are not read.

### A tie permits the next lower index

Both headers are 2.

- Left payload: index 1 is 3; index 2 is 7.
- Right payload: index 1 is 9; index 2 is 7.

Expected result: **−1**. Index 2 ties; index 1 determines the result.

### Negative common header reverses payload ordering

Both headers are −2, with the same payloads as in the preceding example.

Expected result: **+1**. The selected count remains 2, but the negative common transformed header reverses the result of the first unequal unsigned payload comparison.

### Unsigned payload comparison

Both headers are 1.

- Left payload at index 1 is −1.
- Right payload at index 1 is 1.

With a payload multiplier of 1, the products are representable before conversion. The left unsigned intermediate becomes 2^Wᵤ − 1.

Expected result: **+1**, not −1.

### Payload differences can be erased by transformation

Expected result: **0**, regardless of different readable payload values, provided the multiplication and conversion behave normally. Both selected payload locations are still evaluated; a zero multiplier does not establish permission to supply invalid payload storage.
