## Behavior

### Selection contract

Positions are considered in ascending order, beginning with zero. A position qualifies only when it is strictly below the signed count consulted for that decision.

Each qualifying position causes exactly one invocation of F-69c583ebb334, provided the required reads and argument preparation complete. The first argument is the selected entry’s leading 32-bit payload. The second is the unchanged forwarded argument.

Normal return from that invocation permits consideration of the next position. Previously considered positions are not revisited, and changes to collection fields do not restart traversal.

Normal completion occurs when a position fails the count comparison. That unsuccessful selection causes no dependency invocation and no entry-storage access. There is no completion callback or explicit cleanup.

A null reference completes normally without reading collection memory. A readable count of zero or any negative signed value also completes normally without dispatch. Nonpositive counts are not reported as errors.

### Required access ordering

The following relationships are established for ordinary sequential execution:

- The count read authorizing a position precedes the storage-address and payload reads for that position.
- The storage-address read supplies the location used for that position’s payload read.
- The payload is obtained before the corresponding dependency invocation.
- A normally returning dependency invocation precedes the count read used to decide whether the next position qualifies.
- A rejected position causes no storage-address or payload read.

The dependency therefore receives an already-obtained payload. A change it makes to the entry during that invocation cannot retroactively change the argument it received.

These relationships describe the represented function’s accesses and call boundaries. They do not establish an atomic-memory protocol, synchronization barriers, a fixed machine-instruction sequence, or device-memory semantics.

### Effects of mutation

The count consulted after one invocation may differ from the count that authorized it. A reduction can end traversal sooner; an increase can authorize additional positions beyond the original count.

The next position is not reset by either change. For example, after the first dispatch, a count of one ends traversal, while a count of three permits the second position if all necessary accesses remain valid.

Entry storage is likewise obtained again for every selected position. Replacement storage is used at the position already reached, not from its beginning. If storage changes after the first invocation and the second position still qualifies, the next payload comes from 12 bytes into the replacement storage.

Changes to future payloads can affect later arguments. There is no established initial capture of all entry values.

Mutation does not waive validity requirements. If a dependency invocation invalidates the collection, a subsequent count read may be invalid. If it leaves a count authorizing another position but invalidates the corresponding storage, the subsequent storage or payload access may be invalid. No special recovery is provided for either condition.

## Acceptance examples

These examples are conditional requirements derived from static evidence, not observed test results.

### Null reference

Given a null collection reference and any forwarded 32-bit value, the function returns normally without collection-memory reads or dependency invocations.

This outcome does not require any entry storage to exist.

### Nonpositive count

Given a non-null reference with a readable count of zero or a negative signed value, the function dispatches no entries and returns normally.

The address field and entry storage need not be readable for this path. An unreadable count does not meet the preconditions, even if the intended count is nonpositive.

### Stable collection with three entries

Assume a count of three, stable control data and payloads, valid accesses, representable address arithmetic, and normally returning dependency invocations.

Exactly three invocations occur, receiving the leading payloads at displacements 0, 12, and 24 bytes, in that order. Every second argument equals the caller’s forwarded value. The next position is rejected, with no fourth payload read or invocation.

### Count reduced after the first dispatch

Assume the first position qualifies. Its dependency invocation changes the count to one and returns normally, leaving the collection readable.

No second invocation occurs. The next position is one, which does not qualify under the replacement count. This applies whether the original positive count was one or greater.

### Count increased beyond its original value

Assume an initial count of one. The first invocation changes the count to three and returns normally. Thereafter the count and storage remain stable, later invocations return normally, and accesses are valid.

The second and third positions are also dispatched. The initial count is not a fixed upper bound.

### Storage replaced without restarting positions

Assume the first invocation replaces the stored address and returns normally. The next count read permits the second position, and the replacement storage is valid.

The next invocation receives the payload 12 bytes into the replacement storage. It does not receive the replacement storage’s first payload merely because the address changed.

### Future payload changed

Assume two positions qualify and storage remains valid. The first invocation changes the second entry’s payload before returning normally.

The second invocation receives that changed payload. No earlier snapshot overrides the later read.

### Invalid storage or interrupted continuation

A positive count with unreadable selected payload storage does not require graceful rejection, an error code, or skipping the entry.

If the first dependency invocation never returns normally, the contract does not require a second invocation or final cleanup. The particular fault, nonlocal transfer, or nontermination mechanism remains unspecified.
