# F-ef0c624f111f

## Purpose

F-ef0c624f111f conditionally copies a halfword, may perform a second halfword write and a special-machine-state assignment under restrictive entry conditions, and then enters an unconditional indirect-call and interrupt loop.

The supplied representation does not establish an application-level purpose. In particular, it does not establish decoding, allocation, serialization, or record construction as reachable behavior.

A significant control-flow constraint limits the contract: the region containing later word-sized reads, record writes, and a potentially oversized shift cannot be reached through the represented entry flow. After the second halfword-write block, the next guarded progression necessarily fails. Those later operations must not be advertised as possible effects of an ordinary invocation under the stated 32-bit address model.

There is no represented normal return or structured error result. Reaching the final loop does not guarantee continued execution: either indirect call, the interrupt, or an earlier memory access may transfer control elsewhere or fault.

## Behavior

### Entry selection

Only the second argument’s low byte determines whether the initial copy is enabled.

If that byte is nonzero:

- No preliminary data-memory read or write is represented.
- No special-machine-state assignment occurs.
- All guarded preliminary progressions are disabled.
- Execution proceeds toward the final loop with the incoming link address as its dispatch base.

The upper 24 bits do not override a zero low byte. This follows from the 32-bit multiplication used for the entry test: only the original low byte survives that multiplication.

Although bit 6 is sampled separately, it introduces no additional reachable memory behavior. It is necessarily clear on the zero-low-byte path, and the guarded progression is disabled on the other path.

### Initial halfword copy

If the low byte is zero, the function attempts one halfword copy:

1. Read 16 bits from the incoming source address.
2. Write those same 16 bits to the source address plus the copy displacement.

The displacement is measured in bytes. Address addition uses the 32-bit interpretation stated above.

The read precedes the write. The destination may equal the source, and the representation contains no overlap, alignment, bounds, or permission check. Even when source and destination coincide, a read and a write remain represented effects.

For subsequent numeric comparisons, the adjusted source address is the copy destination minus the adjustment value. This adjustment does not cause another memory read.

If the initial read or write faults, subsequent behavior is not established. No recovery path is represented.

### Conditions for the second halfword-write block

After the initial copy, a chain of zero-result conditions determines whether a second memory-write block is entered.

Under the 32-bit numeric interpretation, entry to that block requires all of the following:

- The second argument’s low byte is zero.
- The incoming link address is zero.
- The fifth-argument slot address is zero.
- The additional addend is zero.
- The comparison value equals the copy displacement.
- The copy displacement is either `0x00000000` or `0x80000000`.
- The adjusted source address equals the adjustment value.

The last condition can equivalently be expressed as: the source address plus the copy displacement equals twice the adjustment value, with both sides reduced to 32 bits.

These conditions describe numeric eligibility, not memory validity. The initial copy must also have completed before this block can be reached.

Several details matter to this reduction:

- Each early right-shift count comes from a value already required to be zero. Every such executed shift therefore has count zero.
- Carry entering the relevant additions is clear on this path.
- An early condition restricts the fifth-argument slot address to zero or one.
- The later zero-result addition combines that address with twice the copy displacement. Because the doubled displacement is even, the address-one case cannot pass.
- Doubling the copy displacement is a 32-bit operation. Both zero and `0x80000000` therefore produce zero. A hypothetical 33-bit multiplication would give a different condition and is not the represented operation.

Failure of any condition disables the remaining guarded progression. It does not merely skip one operation and permit a later guarded memory block to execute.

### Second halfword write and special state

When the preceding conditions succeed, the following effects occur before dispatch:

1. A special machine-state quantity is assigned.
2. Two 16-bit reads are represented through the incoming link address.
3. One read supplies a zero-extended destination address.
4. The other supplies a value to which 15 is added.
5. The low 16 bits of that sum are stored at the derived destination.

For every entry to this block under the stated numeric model:

- The incoming link address is zero.
- The fifth-argument slot address is zero.
- The assigned special-state value is therefore zero.
- Both represented halfword reads are through address zero.
- The derived destination lies numerically between `0x00000000` and `0x0000FFFF`.

The two reads must not be collapsed into one contractual observation. Their relative evaluation order is not established, and changing or device-backed memory could supply different values. Both precede the resulting store.

If the source halfword remains stable, the same halfword value supplies the destination address and the value before addition. Stability is an additional condition, not a function guarantee.

The 16-bit addition wraps on storage. For example, a value of `0xFFF8` produces a stored halfword of `0x0007`.

The special-state assignment precedes these reads. Consequently, a fault on a read through address zero need not leave special machine state unchanged.

### Why later record operations are unreachable

The represented body contains additional guarded operations after this block, including word-sized reads and stores. They do not contribute reachable effects under the stated entry model.

There are two cases:

- If the second halfword-write block was not entered, the condition enabling the next progression remains false.
- If it was entered, an address-derived quantity has already been required to equal zero, while a separate working address is advanced by one halfword from zero to two. The next progression can pass its first comparison, but its following exclusive-or comparison necessarily produces two rather than zero.

Thus the progression stops before the later shift, address adjustments, pointer-sized read, or record stores.

This exclusion does not depend on the values returned by the address-zero halfword reads. Those values affect the indirect halfword write, but not the contradictory comparison.

Consequences for the entry contract:

- No reachable 32-bit data-memory read is established.
- No reachable two-word record write is established.
- The later signed-character conversion does not affect reachable behavior.
- The later potentially oversized left shift is not evaluated.
- Later dispatch-base adjustments cannot affect the final loop.

These are control-flow conclusions from the supplied representation, not claims about unexamined machine instructions.

### Final indirect-call and interrupt loop

Every represented execution that completes the enabled preliminary operations enters the same unconditional loop.

The initial dispatch base is the incoming link address. The only reachable preliminary reassignment of that address occurs on a path where it is already zero and remains zero.

Each iteration performs these interactions in order:

| Order | Interaction |
|---:|---|
| 1 | Invoke F-000000000001 at the current dispatch base plus 3,766 bytes. |
| 2 | If that invocation returns, invoke F-000000000002 at numeric address `0x0857A94B`. |
| 3 | If the second invocation returns, issue software interrupt 91 through F-000000000003. |
| 4 | If execution resumes, set the next dispatch base to `0x083D4CC2`. |

F-000000000001 receives three explicit 32-bit argument patterns: `0x00000000`, `0x00000000`, and `0xFFFFFFA5`.

No explicit arguments are shown for F-000000000002. That does not establish the absence of implicit register, memory, or machine-state inputs.

The first target displacement is 1,883 halfword elements, equivalent to 3,766 bytes. After an iteration completes through the interrupt, the next first target is therefore `0x083D5B78`.

There is no represented loop exit, timeout, retry bound, or normal return. The ordering above is conditional on each preceding interaction returning or resuming.

## Acceptance examples

These examples are conditional static obligations, not executed tests.

### Nonzero low byte

With a second argument of `0x00000001`:

- No preliminary data-memory access or special-state assignment occurs.
- The first dependency target is the incoming link address plus 3,766 bytes.
- Its explicit argument patterns are zero, zero, and `0xFFFFFFA5`.

Executable-target validity and dependency return are separate preconditions.

### Nonzero upper bits with a zero low byte

With a second argument of `0x00000100`, the initial halfword copy is attempted.

An implementation that skips the copy merely because the whole argument is nonzero would not match the represented behavior.

### Byte displacement and dispatch

Given a zero low byte, source address `0x1000`, copy displacement 6, and a nonzero link address:

- Read the source halfword at `0x1000`.
- Write it at `0x1006`, not `0x100C`.
- Do not enter the second halfword-write block.
- Use the incoming link address as the first dispatch base.

Both memory accesses must be valid for execution to continue.

### Restrictive deep path

Consider a synthetic address environment where the slot address, link address, source address, copy displacement, comparison value, adjustment value, and additional addend are all zero. Assume the required accesses are valid and the halfword at zero remains `0xFFF8` until the deep reads.

Then:

- The initial copy reads and writes the halfword at zero.
- The special machine-state assignment writes zero.
- Two further halfword reads through zero are represented.
- The indirect halfword store writes `0x0007` at address `0x0000FFF8`.
- No later word-sized read or record write occurs.
- The first dispatch target is numeric address `0x00000EB6`.

This example does not assert that an ordinary process can place an argument slot at zero.

### High-bit displacement

A copy displacement of `0x80000000` is not excluded by the doubled-displacement condition: its 32-bit double is zero.

For example, source address `0x80000000` and adjustment value zero produce copy destination zero and adjusted source address zero. The remaining deep-path conditions and memory-validity requirements still apply.

### Address-zero fault

If the deep block is reached but reading address zero faults:

- The special-state assignment has already occurred.
- The indirect halfword store is not required to complete.
- Reaching the dispatch loop is not required.
- No recovery behavior is established.

### Continuing dispatch

If both indirect dependencies return and interrupt 91 resumes:

- The interrupt follows both calls.
- The following iteration uses dispatch base `0x083D4CC2`.
- Its first target is `0x083D5B78`.
- No normal completion occurs through the represented loop.
