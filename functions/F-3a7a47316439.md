# F-3a7a47316439

## Purpose

F-3a7a47316439 stores the least significant 16 bits of a 32-bit input into two consecutive destination bytes, with bits 8–15 first and bits 0–7 second.

The established behavior is a two-byte store, not a full 32-bit serialization. Bits 16–31 do not contribute to either stored byte.

Interpreting the result as a big-endian encoding of a 16-bit quantity is **inferred intent**. The byte values and their destination order are established by the supplied static evidence, independent of that interpretation.

## Interface

The function accepts two inputs:

| Input | Contract |
|---|---|
| Destination address | Address of the first of two consecutive writable bytes. |
| Value | A 32-bit input whose least significant 16 bits determine the output. |

The function has no return value.

### Destination requirements

For a normal, defined completion, both the byte at the destination address and the immediately following byte must be writable. The caller must supply storage for both bytes; the function neither creates nor enlarges that storage.

There is no visible null check, bounds check, accessibility check, or destination validation. A null, inaccessible, read-only, or insufficiently sized destination does not have a supported error result.

The visible accesses are byte-sized. No wider destination access or explicit alignment test appears in the supplied evidence. Requirements imposed by a particular execution environment remain outside the established contract.

### Value interpretation

The input has a width of 32 bits. Its treatment is bit-oriented: the first stored byte is obtained using an unsigned right shift followed by narrowing to one byte, and the second stored byte is obtained by narrowing the original input to one byte.

The contract therefore does not depend on assigning a signed numeric meaning to the entire input. For example, the 32-bit pattern `0xFFFFFFFF` produces the same two bytes regardless of whether a caller informally describes that pattern as a large unsigned value or as a negative signed value.

## Behavior

### Output layout

On normal completion, the destination has this layout:

| Byte offset from destination | Stored bits from the input | Numeric byte value |
|---|---|---|
| 0 | Bits 8 through 15 | Input divided by 256 with the fractional part discarded, then reduced modulo 256 |
| 1 | Bits 0 through 7 | Input reduced modulo 256 |

Bit 0 is the least significant input bit.

Equivalently, if the input is treated as an unsigned integer \(V\) in the range \(0\) through \(2^{32}-1\), the first byte is \(\lfloor V/256 \rfloor \bmod 256\), and the second is \(V \bmod 256\).

The input’s upper 16 bits are discarded. There is no saturation, range rejection, rounding, or carry between the two output bytes. Every 32-bit input pattern has a defined pair of byte values when the destination preconditions hold.

### Order of effects

The visible operation order is:

1. Store the byte derived from bits 8–15 at offset 0.
2. Store the byte derived from bits 0–7 at offset 1.
3. Return without a result value.

Neither destination byte is read before it is overwritten. Its prior contents do not influence the output.

The two assignments establish a source-level order. They do not establish a two-byte atomic update, a synchronization boundary, or a hardware memory-ordering guarantee for concurrent observers.

### Scope of the write

The visible implementation targets exactly two byte locations. It contains no explicit access to an earlier byte, a later byte, or any other object.

The resulting byte order is explicit rather than dependent on the host representation of a 16-bit integer. The evidence does not show a wider integer store whose byte order would depend on host endianness.

### Completion and errors

If an access fails because the destination does not satisfy the preconditions, the evidence does not specify the resulting fault mechanism or whether any partial change is observable.
