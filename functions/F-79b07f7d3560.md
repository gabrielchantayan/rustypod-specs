# F-79b07f7d3560

## Purpose

F-79b07f7d3560 attempts to advance a recorded 32-bit position by a requested amount. If its boundary calculation requires additional units, it discovers a sufficiently long run, constructs links within that run, and attaches it before updating the position.

**Established static behavior:** the function accesses position metadata, chain links, search hints, and a counter. No argument is directly used as a payload-buffer address. Failure does not imply rollback.

**Inferred intent:** the units appear to represent storage allocation. Several dependencies appear to perform status reporting, synchronization, or metadata maintenance. These meanings are not independently established dependency contracts.

Two address-exposed storage locations affect conditional guarantees: candidate-check output storage is later reused as the construction counter, and search-output storage is reread for attachment after intervening calls. Pointer retention and preservation are unknown.

## Behavior

### Initial handling and context entry

A zero requested amount returns zero without dependency calls, lookup, selector-based dereferences, or mode validation.

For a nonzero amount:

1. F-038b46411c0c receives 28.
2. F-667717e3fb3e receives the selector and 3.
3. A null lookup result causes F-038b46411c0c to receive 9, followed by ordinary failure. No context entry or exit occurs.

After a nonnull lookup, the function obtains and retains the context pointer through the associated record. It reads context offset 120 and passes that 16-bit value to F-6443787f9616. It then calls F-e657f684a3c8 with the lookup result. Both returns are ignored.

Only afterward does it read the position through the lookup result’s current associated-record and metadata pointers, followed by the mask from the retained context. Later associated-record and metadata accesses reload their pointer chains; the retained context is not replaced.

### Position arithmetic and mode validation

Let the initial position be \(P\), the requested amount \(L\), and the mask \(M\). Define 32-bit quantities:

\[
E=(P+L)\bmod 2^{32}
\]

\[
A=((P+M)\bmod 2^{32})\mathbin{\&}\neg M
\]

\[
B=((E+M)\bmod 2^{32})\mathbin{\&}\neg M
\]

The complement is restricted to 32 bits. No overflow rejection is visible.

Mode 4 requires all of the following:

- \(B=E\);
- \(P=A\);
- the explicit starting unit is nonzero.

Failure reports 22 through F-038b46411c0c, exits the context, and returns ordinary failure. Other modes skip these checks.

For a conventional contiguous low-bit mask, these conditions enforce aligned initial and final positions. That interpretation is inferred; the mask’s form is not validated.

### Required unit count

After mode validation, the function reads unsigned 16-bit encoding \(H\) from retained-context offset 462. The effective shift count is

\[
s=(H+9)\bmod256.
\]

The low eight bits are retained after addition. Thus \(H=247\) yields \(s=0\), and \(H=65535\) yields \(s=8\).

For \(0\le s<32\), the required count is

\[
N=\bigl((B-A)\bmod2^{32}\bigr)\gg s,
\]

using an unsigned right shift.

Execution semantics for effective counts 32 through 255 remain **documented_only**. No additional shift-count masking is assumed.

When \(N=0\), the function skips traversal, discovery, construction, attachment, and allocation synchronization, but still performs position finalization.

### Existing-chain traversal

The last nonzero unit becomes the retained tail. An initially zero unit gives a zero tail.

### Direct candidate checking

Mode 4 checks candidates beginning at the explicit starting unit. Other modes use direct checking when a position reread after traversal differs from \(A\); their first candidate is the retained tail plus one.

For each candidate, F-c9f1dc723c52 receives:

1. the retained context;
2. the candidate;
3. the address of the candidate-output/counter slot.

Acceptance requires a nonzero return and a zero output value. A zero return rejects the candidate without reading the output.

Accepted candidates advance consecutively using 32-bit arithmetic. Checking ends at the first rejection or after \(N\) acceptances. Rejection retains the accepted prefix length for the insufficient-run result; no links are constructed for that prefix.

After complete acceptance, the run-base slot receives the explicit start in mode 4, or the retained tail plus one otherwise. The discovery length becomes \(N\). Direct checking performs no direct writes to context offsets 492 or 496.

### Search-based discovery

Other modes use search-based discovery when the position reread equals \(A\).

F-61cbc152a8ee receives, in order:

1. the retained context;
2. a candidate search position;
3. the run-base slot’s address;
4. \(N\);
5. the selection mode.

A nonzero retained tail supplies the first candidate. With a zero tail, context offset 492 supplies it; zero skips the search call.

The returned length is unsigned:

- All ones causes immediate ordinary failure, bypassing direct hint writes.
- A length at least \(N\) establishes a sufficient run.
- Smaller lengths contribute to the maximum insufficient length observed.

After an insufficient call, context offset 492 is read. Search progression is:

- If the candidate equals the retained tail and the hint also equals that tail, the next candidate is 2.
- If the candidate equals the retained tail but the hint differs, offset 492 is read again. This second value supplies the next candidate; zero ends discovery.
- If the candidate differs from the retained tail, another call at 2 occurs only when the hint equals the candidate and is not 2. Otherwise discovery ends.

Termination is not guaranteed. A tail of 2 with a persistently equal hint can repeatedly select 2.

On normal completion, the run-base slot is written to context offset 496, then offset 492, for both sufficient and insufficient outcomes. The maximum insufficient length is retained separately; the base associated with that maximum is not retained.

If both the tail and initial hint are zero, these writes occur without a search call initializing the run-base slot. The written value is not established.

### Insufficient-run result

If discovery provides fewer than \(N\) units, the function constructs no new links and performs no direct position finalization.

Let \(K\) be the accepted direct-check prefix length or maximum insufficient search length. The function rereads the current position and unsigned 16-bit shift encoding. Calling these \(P_{\mathrm{current}}\) and \(H_{\mathrm{current}}\), define

\[
s_{\mathrm{current}}=(H_{\mathrm{current}}+9)\bmod256.
\]

For a count below 32, it calculates

\[
Q=\left(A-P_{\mathrm{current}}+
(K\ll s_{\mathrm{current}})\right)\bmod2^{32}.
\]

The left shift retains the low 32 bits. After context exit, \(Q\) is returned sign-extended to 64 bits.

The relative evaluation order of the position and encoding reads is not established. Dependencies may have changed either field. \(A\) remains the initially calculated boundary. Shift counts of 32 or greater remain unresolved.

Calling \(Q\) an available extension amount is inferred intent, not an established external meaning.

### Construction

While the slot’s unsigned value is less than \(N-1\), F-2b2cf4a4fe41 receives the retained context, current unit, and current unit plus one. Zero causes ordinary failure and context exit.

- the current unit advances by one;
- context offset 500 is tested and, if nonzero, decremented;

If no external activity modifies that slot, successful loop completion makes exactly \(N-1\) ascending link calls. Prior candidate-output values do not affect the count because construction resets the slot.

On direct-check paths, however, F-c9f1dc723c52 has received this same slot’s address. If retained-pointer activity modifies it during construction, the number of calls is not established. Mutation can shorten or lengthen construction; repeated mutation or wraparound can prevent termination. The current unit advances once per successful link call independently of the counter’s value.

After the loop, **F-3fb99b56c861 receives the retained context followed by the current terminal unit**. This unit is the expected end of the run only under the unmodified-counter condition. Zero causes ordinary failure. Nonzero is followed by another conditional decrement of context offset 500.
