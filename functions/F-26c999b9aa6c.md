# F-26c999b9aa6c

## Purpose

F-26c999b9aa6c produces two one-byte outputs by interpreting results from two dependencies. The first output has three possible production paths: a constant byte of one, a byte obtained from a third dependency, or a constant byte of zero. The second output is normalized to either zero or one.

Both primary dependencies receive the same two input values and access to the same mutable pointer slot. The first dependency can change that slot before the second dependency receives it. The output writes themselves use the original output destinations, not the possibly changed pointer stored in the slot.

The function returns a 32-bit zero after completing both output writes. That return value does not distinguish dependency outcomes and is not evidence that either output indicates success.

**Established static evidence:** the calls, branch conditions, byte writes, conditional context access, and constant return described below.

**Inferred intent:** the outputs may represent two related predicates or properties. The supplied evidence does not establish their domain meaning, and the first output is not necessarily Boolean.

## Behavior

### First dependency and shared pointer state

Before calling a dependency, the function creates an internal mutable pointer slot initialized with the first output destination.

It calls F-558efbcbde2c with, in order:

1. Shared input A.
2. Shared input B.
3. A reference to that pointer slot.

The third argument is therefore not simply the first output pointer. It permits the dependency to inspect or replace the pointer value held in the slot. Any replacement survives into the later call to F-2825b5baa71d; the wrapper does not reset the slot between calls.

The first dependency may also access memory or change other state according to its own behavior. Those effects are not specified by the supplied body.

### First output selection

After F-558efbcbde2c returns, its integer result is compared against two exact values:

- **Exactly one:** write the byte value one to the original first output destination.
- **Exactly two:** read the 32-bit integer through the context reference, add 84, and call F-c505095befe7 with that computed value and the constant three. Write the one-byte result from F-c505095befe7 to the original first output destination.
- **Any other result:** write the byte value zero to the original first output destination.

These are exact-value comparisons, not a general zero-versus-nonzero interpretation. Negative results and positive results other than one or two select the zero-output path.

The context read occurs only on the result-two path and only after the first dependency has returned. If the first dependency changes the memory referenced by the context argument, the subsequently read value is the changed value, subject to ordinary memory-access semantics.

The result from F-c505095befe7 is used as a byte without Boolean normalization. A returned byte such as `0x7E` remains `0x7E`.

Changing the shared pointer slot does not redirect this output write. The wrapper writes through the original first output destination regardless of the pointer value currently held in the slot.

### Second dependency and second output

After the first output byte has been written, the function calls F-2825b5baa71d with:

1. Shared input A.
2. Shared input B.
3. A reference to the same mutable pointer slot used in the first call.

The slot contains whatever pointer value remains after the earlier dependency activity. The wrapper does not substitute the original first output pointer again.

The second dependency executes after the first output write. It can therefore observe that write if it accesses the relevant memory. If F-c505095befe7 was called, that call has also completed before the second dependency begins.

After F-2825b5baa71d returns:

- A result exactly equal to one causes a byte value of one to be written to the original second output destination.
- Every other result causes a byte value of zero to be written there.

A second-dependency result of two has no special handling.

The function then returns the 32-bit value zero. It does not read back either output to validate the final memory contents.

## Side effects

The wrapper directly performs two one-byte stores on a normal return path, in this order:

1. First output destination.
2. Second output destination.

There is always a call to F-2825b5baa71d between these stores. There is no direct output clearing before F-558efbcbde2c executes.

The wrapper also directly performs the conditional context read and maintains the internal mutable pointer slot. That slot is temporary storage used across the two primary calls. Its final contents are not returned.

No allocation, explicit release, ownership transfer, or global access is visible in the wrapper itself. This does not establish that the dependencies allocate nothing, release nothing, or preserve global state. Likewise, passing the pointer slot to dependencies does not establish whether they retain it; retaining access beyond the slot’s lifetime would require a separate dependency-level lifetime contract.

If the output destinations are identical, the final wrapper write is the second output byte, so it overwrites the first output at that address. The earlier first-output value may still have been observed by the second dependency before being overwritten.

For distinct output destinations, the wrapper does not rewrite the first output after the second dependency call. Consequently, the first output’s final value is not guaranteed solely by its earlier store if that dependency can also modify the same memory.

There is no transactional guarantee. If a dependency fails to return, or an access faults, earlier dependency effects and completed stores are not rolled back by any visible mechanism.

## Acceptance examples

These are conditional static acceptance cases, not results of runtime tests. Assume valid required memory, normally returning dependencies, and no additional dependency writes that alter the stated final bytes.

1. **Both exact-one results.**  
   If F-558efbcbde2c returns one and F-2825b5baa71d returns one, distinct output destinations receive one and one. F-c505095befe7 is not called, and the wrapper does not read the context value.

2. **Non-one values are not generally true.**  
   If the first dependency returns negative one and the second returns two, both output stores contain zero. Neither result is treated as a generic true value.

3. **Byte-valued first output.**  
   If the first dependency returns two, the context value is 4096, and F-c505095befe7 returns `0x7E`, that dependency receives 4180 and three. The first output store contains `0x7E`, not one.

4. **Pointer-slot replacement persists.**  
   If the first dependency changes the mutable pointer slot from the first output address to another valid address, the second dependency receives access to the changed slot. The first wrapper output store still targets the original first output address.

5. **Deferred context read.**  
   If the first dependency updates the context value to 100 before returning two, F-c505095befe7 receives 184 as its first argument. The wrapper does not use a context value captured before that dependency call.

6. **Aliased outputs.**  
   If both output destinations identify the same byte, the first dependency returns one, and the second returns zero, the shared byte is first written as one and later as zero. The second dependency runs between those writes.

7. **Context not directly needed on other branches.**  
   If the first dependency returns zero, the wrapper does not directly dereference the context reference. This does not independently make arbitrary arguments safe, because dependency requirements remain unknown.

8. **Constant wrapper return.**  
   If the dependencies return values that cause both output stores to be zero, the wrapper still returns zero. No separate wrapper error code is produced.
