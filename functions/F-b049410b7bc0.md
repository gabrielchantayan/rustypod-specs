# F-b049410b7bc0

## Purpose

F-b049410b7bc0 validates attributes of a pending column addition and performs associated definition-text preparation.

Established behavior includes an early dependency-mediated check, ordered rejection of certain column attributes, optional default processing, acquisition and backward modification of definition text, a catalog-related submission, and two final preparation calls.

The apparent intent is to prepare an addition to an existing table. The supplied function does not establish that a database change is executed, committed, atomic, or visible to other operations.

**Contract status: documented_only.** Direct behavior is specified below. Dependency semantics and missing environmental invariants remain unresolved.

## Interface

### Inputs and result

The function takes two pointer-like inputs:

1. A mutable operation context.
2. A definition descriptor containing two 32-bit words.

It returns no value. There is no direct success or failure result. Observable outcomes consist of dependency calls, diagnostics, a connection-byte write on one failure path, and modifications to acquired storage.

The supplied representation has 32-bit words and pointer-bearing fields. The layouts below describe observed memory accesses, not a portable serialization format. Byte order is not established.

## Behavior

### Initial suppression and resolution

A nonzero suppression field causes immediate return. On that path, the function does not read the context's table or connection reference and calls no dependency.

Otherwise, the established sequence is:

1. Retain the table and connection references.
2. Call F-49f750c2c596 with the connection and table field at offset 76.
3. Use the returned index to select a 24-byte database record through the connection field at offset 8; retain its first word.
4. Retain the table's name-like word.
5. Determine the final column-record location and capture its default reference.
6. Call F-4e77314e8c36 with the connection, retained name-like value, and retained database word.
7. Read the returned object's first word.
8. Call F-0055bebe0706 with the context, selector 26, retained database word, lookup object's first word, and zero.

A nonzero return from F-0055bebe0706 stops processing immediately. No local restriction diagnostic, definition acquisition, or final preparation follows.

The early check's semantic purpose is unresolved. Authorization or another prerequisite check is plausible but not established.

The retained database index, database word, name-like word, lookup reference, and selected record location are not refreshed after subsequent calls.

### Effective default and restriction precedence

After the early check returns zero, a nonnull captured default reference is inspected. If its current first byte is 0x5C, the effective default becomes absent.

This changes only the locally retained reference. There is no direct write to the column's stored default-reference field. The leading-byte convention does not establish treatment of any other textual representation.

Restrictions are evaluated in this order:

1. A nonzero PRIMARY KEY-related byte selects the PRIMARY KEY rejection.
2. Otherwise, a nonzero table word at offset 16 selects the UNIQUE rejection.
3. Otherwise, a nonzero NOT NULL-related byte with no effective default selects the missing-default rejection.
4. Otherwise, an effective default is processed if present.

Each rejection calls F-2022b0f73f3b with the context and the corresponding diagnostic, then returns. Diagnostic categories are established; complete wording is not prescribed here.

Default normalization precedes the PRIMARY KEY check. A nonnull default reference therefore must be readable even when the column will subsequently be rejected as PRIMARY KEY.

A nullable column with no effective default proceeds without default processing. No existing-row inspection or empty-table exception is visible.

### Default processing

For a present effective default, F-4d9289c8cc5e receives:

- The retained connection.
- The effective default reference.
- Numeric arguments 1 and 98.
- The address of a 32-bit result slot.

Its direct return and result slot control separate branches:

| Outcome | Subsequent behavior |
|---|---|
| Direct return is nonzero | Write 1 to connection byte offset 30, then return. |
| Direct return is zero; result slot is zero | Report the nonconstant-default category through F-2022b0f73f3b, then return. |

The result slot is not visibly initialized before the call. Defined use of the zero-direct-return paths therefore requires the dependency to supply a meaningful result-slot value.

On a nonzero direct return, this function calls neither its diagnostic dependency nor F-c70de8d2b40e. Effects already performed by F-4d9289c8cc5e are not undone.

The diagnostic suggests a constant-default restriction. Accepted syntax, conversions, evaluation rules, and result-slot meaning remain unknown. Cleanup is only an inferred role for F-c70de8d2b40e.

### Definition acquisition

If acquisition returns null, trimming, catalog submission, and buffer handoff are skipped. Both final preparation calls still occur.

### Backward suffix modification

For a nonnull buffer, examination begins one byte before the end position determined by the second decoded count.

A candidate is removed by writing a zero byte when either of these conditions holds:

- Its address is strictly greater than the buffer start and its byte value is 0x3B.
- The classification entry for its byte value has bit 0 set.

The first condition is evaluated first. When it succeeds, classification is bypassed.

When classification is needed, the function calls F-2a4c402ba617. It reads the returned object's first word as a classification-table base and uses the candidate byte, interpreted as unsigned 8-bit, to select a one-byte table entry. The classification-path candidate read occurs after this dependency call.

After each zero write, examination moves backward one byte. Processing stops at the first candidate for which neither removal condition holds.

This ordering has several consequences:

- A semicolon strictly after the buffer start can be removed without a classification call.
- A semicolon at the first byte is not removed by the semicolon condition, but may be removed by classification.
- If a semicolon comparison fails and classification is then consulted, a dependency can change the candidate before its classification-path read.
- Classification state and buffer contents are not established to remain stable across calls.
- Classification has no lower-bound guard.
- Removing the first byte allows the next examination to occur before the buffer.
- A zero trimming count starts examination before the buffer.

The classification table's contents are unknown. “Whitespace trimming” is inferred intent, not an established byte-set contract.

There is no explicit terminator write at the original end position. If no candidate is removed, this function writes no zero terminator. Any required termination must come from acquisition or an external invariant.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, assume accessible storage, valid object lifetimes, and normally returning dependencies.

1. **Suppression:** A nonzero suppression field produces immediate return without dependency calls.

2. **Early refusal:** A nonzero F-0055bebe0706 result prevents local restriction diagnostics, acquisition, and final preparation, even when column attributes would otherwise cause rejection.

3. **Restriction precedence:** With readable default storage and both PRIMARY KEY and UNIQUE indicators set, the PRIMARY KEY diagnostic is selected. Default processing is not called.

4. **Absent effective default:** A NOT NULL indicator with a default beginning with 0x5C produces the missing-default rejection, provided earlier restrictions do not apply. The stored default-reference field is not directly changed.

5. **Default-processing failure:** A nonzero direct result from F-4d9289c8cc5e causes the connection-byte write and return, without a local diagnostic or final preparation.

6. **Nonconstant result:** A zero direct result and zero result slot produce the nonconstant-default diagnostic. F-c70de8d2b40e is not called.

7. **Length decoding:** Encoded words 8 and 9 both decode to four. If the descriptor length remains unchanged during acquisition, acquisition and trimming use the same count.

8. **Changed length:** If acquisition receives a decoded count of four and changes the encoded descriptor word to 12 before returning nonnull, trimming uses six. Safe examination additionally requires storage supporting that range.

9. **Trailing removals:** With decoded count five, stable bytes `x;;; `, and stable classification marking space removable but not `x`, four backward zero writes occur. The three semicolons bypass classification calls.

10. **First-byte semicolon:** A one-byte semicolon remains unchanged if its classification entry lacks bit 0. Classification is consulted despite the semicolon-specific lower-bound protection.

11. **Null acquisition:** Null acquisition skips submission and F-94cb53877c15 but still reaches both final preparation calls.

12. **Late global observation:** If an earlier dependency changes the opaque global datum and that value remains stable through submission argument evaluation, F-66c61ffd0a02 receives the changed value as its second argument. A value observed before that change is not retained by this function.

13. **Unsigned increment boundary:** If both submission-time reads of the offset-48 field yield 0xFFFFFFFF, the direct field argument is 0xFFFFFFFF and the incremented argument is zero. This establishes arithmetic and argument values, not acceptance by F-66c61ffd0a02.

14. **Buffer handoff:** After a returning submission call, the same acquired-buffer reference is passed to F-94cb53877c15 before final preparation. Deallocation is not required by the established evidence.

15. **Fresh lookup word:** If F-f4f1b1e2d10b changes the lookup object's first word while preserving its validity, F-a3e6de7b5aa3 receives the changed word.
