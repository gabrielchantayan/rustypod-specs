## Behavior

### 1. Capture the base value and read a byte

The function first reads the base cell and retains that value for the second memory write.

It then doubles the index state and uses the result directly as an address for a one-byte read. No separate allocation base or array base is added in the visible expression.

Consequences:

- This is a byte read at a computed address, not an established access to a bounded array.
- No range check is visible.
- The read occurs before all three represented writes.
- The byte is retained for subsequent use; the representation does not show a later reread of that location.

The loaded byte is represented as a plain character value. Whether values with bit 7 set are interpreted as negative or nonnegative when promoted is unresolved. That distinction affects both the first write’s address and the first indirect argument.

### 2. Write a 16-bit value

The first write is a 16-bit store.

Its destination is formed by adding the promoted loaded character to the base-cell value used in this expression. Its data is the base-cell value converted to a 16-bit quantity.

The supplied representation refers to the base cell again for this operation rather than exclusively using the earlier retained value. For ordinary stable memory, both accesses may yield the same value. That stability is not guaranteed by the supplied material.

The following distinctions matter:

- **Address contribution:** the promoted character contributes to the destination address.
- **Stored data:** only the low 16-bit representation of the base value is retained.
- **Destination extent:** two bytes are written, subject to the target platform’s representation and access rules.
- **Byte order:** not established.

The representation does not determine the order between separate base-cell evaluations within this single store expression. It does establish that the earlier byte load has already supplied the character used here.

No alignment adjustment, bounds validation, or explicit error branch is shown.

### 3. Write the implicit byte value

The second write stores the one-byte byte-state value at an address equal to twice the initially retained base value.

This write uses the base value captured before the initial byte read. It does not visibly reload the base cell for its address.

Accordingly, if the first write changes the base cell through aliasing, the second write still uses the earlier captured value for its destination calculation.

The access width is one byte. No content comparison or conditional suppression is shown.

### 4. Write the narrowed index value

The third write stores a character-sized conversion of the index state.

Its destination is the sum of:

1. The value supplied by the address cell.
2. Offset state A.
3. Offset state B.

The write affects one byte. Operationally, the intended narrowing retains the index state’s low eight-bit representation; the supplied material does not independently establish every language-level rule for out-of-range signed-character conversion.

The address-cell value is referenced after the preceding two writes in the visible sequence. If those writes modify its storage through aliasing, the third destination can therefore depend on those earlier effects.

There is no visible range check, alignment check, or overflow check on the destination calculation.

### 5. Transfer control indirectly

After the three writes, the function invokes an unresolved target with three visible arguments, in this positional order:

1. The previously loaded character, promoted to the represented integer width.
2. The value supplied by the argument cell.
3. Twice the third explicit input, plus the incoming carry converted to an unsigned value.

The first argument reuses the retained character. It is not loaded again from the initial read address.

The argument cell is referenced after the writes. If an earlier write aliases that cell, the target can receive the modified value. The supplied material does not establish the relative evaluation order of all call-argument expressions.

The third argument is a 32-bit-scale arithmetic expression. The evidence does not justify imposing a universal wrapping rule on signed multiplication overflow. For values whose doubling is representable, the represented result is twice the third explicit input plus the unsigned incoming carry, subject to the final expression’s integer-conversion rules.

The representation treats the unresolved transfer as a call and shows a return afterward. It does not establish that the real target returns, that the transfer is an ordinary ABI-conforming call, or that its return value has a meaningful type. No target return value is visibly consumed.
