# F-cf5e789374f9

## Purpose

F-cf5e789374f9 selects a 32-bit result through two ordered dependency checks, followed, when neither check succeeds, by a field-based fallback.

The established behavior is a precedence rule:

1. A zero result from the first comparison selects the first global return value.
2. Otherwise, a zero result from the second comparison selects the second global return value.
3. Otherwise, a field at byte offset `0x2c` supplies the result, subject to a separate zero check that can select a third global return value.

This describes selection behavior, not the meaning of the selected values. The supplied evidence does not establish that the comparisons test strings, identify types, validate objects, or perform any other particular semantic operation. Likewise, it does not establish that the returned values are pointers, status codes, identifiers, or owned resources.

The distinction between the field value saved for return and the field value tested for zero is observable in the supplied representation. They are separate reads and must not be silently treated as one read in this contract.

### Field-based fallback

This stage is reached only when both comparisons returned nonzero.

The supplied representation specifies the following sequence:

1. Read a 32-bit integer at base plus 44 bytes and save that value as the prospective return value.
2. Read a 32-bit integer from the same address again and test this second sample for zero.
3. If the second sample is zero, replace the prospective result with the third global return value.
4. Return the prospective result.

The second sample controls whether the fallback global is selected. The first sample supplies the result when that fallback is not selected.

For stable memory, this reduces to the familiar behavior of returning a nonzero field or substituting a global when the field is zero. That simplification is conditional on both samples agreeing. It is not a complete description when successive reads can differ.
