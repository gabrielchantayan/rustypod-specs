# F-935e0a16a948

## Purpose

F-935e0a16a948 dispatches a request encoded in caller-supplied context storage. Its established behaviors are:

- Calling a fixed dependency and propagating its 32-bit result.
- Selecting a target and invoking an indirect method with a pointer into the original context.
- Updating a context byte before issuing a notification.
- Performing an indexed operation, optionally followed by a shared-table access and another call.
- Writing two shared 16-bit fields before submitting a five-argument request.
- Returning zero for unsupported requests, null targets, or a particular lookup-failure sentinel.

These descriptions identify observable operations, not application semantics. Locally returned one indicates completion of the selected branch’s ordinary control flow; it does not establish application-level success of dependencies whose results are ignored.

## Interface

### Arguments and result

The interface has four arguments:

| Argument | Established use |
|---|---|
| Context | Pointer to storage accessed through overlapping 8-bit, 16-bit, and 32-bit fields |
| Second argument | 32-bit value; not used by this function |
| Third argument | 32-bit value; not used by this function |

The return value is 32 bits. Locally selected returns are zero or one. Results from the three class-zero direct operations and the indirect method are propagated without Boolean normalization.

The supplied representation uses 32-bit addresses and address-bearing fields. The complete external calling convention is not independently established.

### Context layout

All offsets are byte offsets from the context address.

| Offset | Access width | Role |
|---|---:|---|
| 0x34 | 32 bits | Opaque first argument to notification dependencies |
| 0x90 | 8 bits | Initial unsigned operation class |

Byte-offset fields and numeric slices of packed words are distinguished throughout this contract. Their usual correspondence assumes little-endian storage, but byte order is not independently confirmed by architecture documentation supplied here.

### Shared storage and object layout

Two shared address-bearing locations are relevant:

- **Shared pointer A:** read before the initial operation-class read. Class 0x40 uses this entry-time value and a separate, later read of the same shared location.
- **Shared table pointer B:** read after F-8b341d935c06 returns on one class-two path. The table has a 24-byte entry stride; the selected value is the 32-bit field at entry offset four.

An indirect-call target is interpreted as having an address-bearing 32-bit first word. That word identifies a dispatch table whose callable entry is at byte offset 0x24.

No sizes, allocation origins, lifetimes, or synchronization rules for these regions are established.

### Preconditions

The context must be valid for every read and write reached on the selected path. There is no null check before its initial operation-class byte is read.

Additional requirements are path-dependent:

- Class zero, selector five requires a writable byte at context offset 0xC0.
- Indirect invocation requires a valid target, its first-word dispatch-table reference, and a callable entry at table offset 0x24.
- Successful class-two lookup requires valid table-address arithmetic and a readable selected 32-bit field.
- Supported class 0x40 requires valid writable destinations derived from both relevant observations of shared pointer A.

The function does not validate these requirements. Invalid addresses, unsupported alignment, expired objects, and out-of-range table accesses have no established local recovery behavior.

## Behavior

### Entry and initial dispatch

The function first reads shared pointer A and captures its value. It then reads the unsigned byte at context offset 0x90.

Initial classes 0x00, 0x01, 0x02, 0x20, 0x21, 0x22, and 0x40 have supported branches. Every other initial class returns zero without a branch-specific dependency call. The initial shared-pointer read still occurs.

### Class 0x00: fixed operations and byte notification

The selector is read as one byte at context offset 0x91.

| Selector | Operation | Result |
|---|---|---|
| 1 | Call F-82acf5f20c15 with no explicit arguments | Propagate its 32-bit result |
| 3 | Call F-167d2b3628ce with no explicit arguments | Propagate its 32-bit result |
| 5 | Perform the byte update and notification below | Return one |
| 9 | Call F-e057994d7e78 with no explicit arguments | Propagate its 32-bit result |
| Other | No branch-specific call | Return zero |

For selector five, a 16-bit read at offset 0x92 supplies its low eight numeric bits to a byte write at offset 0xC0. After that write completes, F-987b5e3d700b is called with:

1. The 32-bit field at context offset 0x34.
2. The low eight bits of another 16-bit read at context offset 0x92.
3. The integer one.

The notification result is ignored, and the function returns one if the call returns normally.

The two reads at offset 0x92 are separate evaluations. The notification argument is not required to come from the value used for the byte write. The source establishes no relative evaluation order between the two context reads used as notification arguments.

The absence of explicit arguments to the other three dependencies does not imply that those dependencies lack access to shared state.

### Class 0x01: resolve and invoke

The function reads 16 bits at context offset 0x94, masks the value to its low eight bits, and calls F-7c98cdf9320e with the context and that index.

A null result causes a zero return. Otherwise, the returned target undergoes the indirect invocation described below. The method’s 32-bit result is returned unchanged.

### Class 0x02: indexed operations

The selector is read as an unsigned byte at context offset 0x91.

#### Selector one

The function reads 16 bits at context offset 0x92 and examines their high eight numeric bits.

If those bits are nonzero, it returns one immediately. There is no lookup, notification, or table access on this path.

If those bits are zero:

1. A 16-bit read at offset 0x94 supplies its low eight bits as an index to F-36a285714182, alongside the context.
2. The returned value is treated as a signed 32-bit lookup result.
3. A result of exactly minus one causes a zero return.
4. Every other result permits a call to F-8b341d935c06 with the current 32-bit field at offset 0x34, the low eight bits of a new 16-bit read at offset 0x94, and zero.
5. After that call returns, the function reads shared table pointer B and selects the 32-bit field at the saved lookup result’s entry, using a 24-byte stride and field offset four.
6. It passes that field to F-5bcae2eff9a7 and returns one.

The lookup index and notification index need not match: the latter is read after F-36a285714182 returns. The table selection nevertheless uses the saved lookup result, not either context index.

Shared table pointer B is obtained after the notification, not at function entry or before lookup. The results of the notification and F-5bcae2eff9a7 do not determine the returned one.

Only minus one is explicitly rejected. Other negative values and large positive values are not bounded. The address calculation uses a signed 32-bit lookup result and a stride of 24 in the supplied 32-bit representation. No overflow check or portable out-of-range arithmetic behavior is established.

#### Selector three

The function reads 16 bits at context offset 0x92.

- If their high eight bits are zero, it calls F-8b341d935c06 with the 32-bit field at offset 0x34, the low eight bits of a 16-bit read at offset 0x94, and one. It then returns one, ignoring the call result.
- If their high eight bits are nonzero, it returns zero without that call.

#### Other selectors

The function returns zero. These selectors do not cause the 16-bit condition read at offset 0x92.

### Initial classes 0x20, 0x21, and 0x22: shared target dispatch

These initial classes enter the same target-selection region. Selection uses later packed-word reads, not solely the initial class byte.

First, the function reads the 32-bit word at context offset 0x90 and compares its truncated low byte with 0x21.

- If it equals 0x21, F-7c98cdf9320e is called with the context and the low eight bits of a 16-bit read at offset 0x94. Its result becomes the target. There is no second packed-word comparison.
- If it does not equal 0x21, the context is the default target, and the function separately reads the 32-bit word at offset 0x90 again. This second read’s truncated low byte is compared with 0x22.
  - If it equals 0x22, F-74af3c64851d is called with no explicit arguments, and its result replaces the default target.
  - Otherwise, the context remains the target.

The two comparisons must not be modeled as using one cached packed-word value. The second read occurs only after the first comparison fails.

With stable context contents, initial class 0x20 selects the context, class 0x21 resolves a target, and class 0x22 obtains a target through F-74af3c64851d. Without that stability assumption, selection follows the particular later reads described above.

A null selected target produces zero. A nonnull target undergoes indirect invocation, whose result is propagated.

### Indirect method invocation

For a nonnull selected target, the function obtains the dispatch-table reference from the target’s first 32-bit word and selects the callable entry at table byte offset 0x24.

The invocation receives:

1. The selected target.
2. A pointer to context offset 0x90.

The second argument aliases the original context. It is not a copied request and need not point into the selected target.

Only target nullness is explicitly checked. There is no visible check of the dispatch-table reference or callable entry. The method’s effects, lifetime requirements, and full calling convention remain unresolved.

### Class 0x40: shared-field writes and submission

This path first reads the complete 32-bit word at context offset 0x94 and saves it. That read occurs even if the following selector comparison fails.

The function then reads the 32-bit word at context offset 0x90 and compares numeric bits 8–15 with 0x40. A mismatch returns zero without either shared-field write or the submission call.

After a match, the first shared-field assignment involves two further observations:

- A new read of the 32-bit word at context offset 0x90 supplies numeric bits 16–31.
- A new read of shared pointer A supplies the destination base; the destination is at byte offset two.

The source does not establish which of these two observations occurs first. Both belong to the first assignment after the selector comparison succeeds. The stored 16-bit value therefore comes from the new packed-word read, not from the selector-check snapshot.

After that first 16-bit store completes, a second 16-bit store writes the low 16 bits of the saved word from offset 0x94 to byte offset four from the entry-time shared pointer A.

The two completed stores have a defined order: the offset-two store precedes the offset-four store. Their bases need not identify the same allocation if the shared pointer’s observed value differs between entry and the later read.

Next, the full 32-bit field at context offset 0xC4 is read:

- Zero selects the numeric argument 100.
- Any nonzero value selects 500.

F-713822eb4f24 is then called with, in order:

1. The context.
2. The selected number.
3. The entry-time shared pointer A.
4. The fourth incoming argument.
5. The context again.

The dependency result is ignored. Normal return from the call is followed by a return value of one.

## Side effects

Established direct writes are limited to:

- One 8-bit context write at offset 0xC0 for class zero, selector five.
- Two ordered 16-bit shared-storage writes on the supported class-0x40 path.

All other mutations are delegated. No dependency is assumed to preserve context fields, shared pointers, table contents, target objects, or object lifetimes.

No explicit operation has established allocation, release, or ownership-transfer semantics. In particular, passing a table-associated 32-bit value to F-5bcae2eff9a7 does not establish that the value is an owned allocation or that the dependency releases it.

The embedded request pointer used for indirect invocation aliases caller-provided storage. No local copying or ownership isolation is established.

There is no visible rollback, locking, retry, exception handling, or translation of dependency failures. Behavior following a dependency’s failure to return normally is documented_only.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. All require valid storage and normal dependency returns unless stated otherwise.

1. **Unsupported request:** Initial class 0x03 returns zero after the entry shared-pointer read and class-byte read. No branch-specific dependency is invoked.

2. **Unnormalized result:** Class zero, selector one propagates a dependency result of 0x80000002 exactly, rather than returning one.

3. **Byte truncation:** For class zero, selector five, stable value 0x12AB at offset 0x92 produces a byte write of 0xAB at offset 0xC0 before notification with second argument 0xAB and third argument one.

4. **Null target:** Class one with a null resolver result returns zero without indirect invocation.

5. **Immediate indexed success:** Class two, selector one, with value 0x0100 at offset 0x92 returns one without lookup or notification.

6. **Lookup sentinel:** In the same branch with a zero high byte, lookup result minus one returns zero without notification or table access. A different negative result is not rejected locally; valid resulting address arithmetic remains a prerequisite.

7. **Mutation during lookup:** If lookup uses context index seven, returns table index two, and changes the context index to nine, notification uses nine while table selection uses saved index two. The table base is read after notification returns.

8. **Selector-three boundary:** Values 0x0000 and 0x00FF at offset 0x92 permit notification with final argument one. Value 0x0100 produces zero without notification.

9. **First shared-dispatch match:** If the first packed-word comparison sees low byte 0x21, the resolver is selected. No second packed-word comparison is required, regardless of a hypothetical later value.

10. **Conditional second comparison:** If the first comparison sees 0x20 and the separate second comparison sees 0x22, F-74af3c64851d supplies the target. If the second instead sees 0x21, the context remains the target; the resolver is not selected retroactively.

11. **Aliased method request:** Stable class 0x20 with a valid context dispatch layout invokes the context’s method with the context and a pointer to context offset 0x90. Its return value is propagated unchanged.

12. **Fresh submission value:** Suppose the class-0x40 selector-check read has bits 8–15 equal to 0x40 and bits 16–31 equal to 0x1111, but the later packed-word read supplies bits 16–31 equal to 0x2222. The first shared store writes 0x2222, not 0x1111.

13. **Distinct shared bases:** If the entry-time shared pointer identifies one valid region and the later read identifies another, the first store uses the later base plus two; the second uses the entry base plus four. The first store completes before the second. No ordering is asserted between obtaining the first store’s base and its source value.

14. **Submission boundaries:** A saved offset-0x94 word of 0xABCD5678 supplies 0x5678 to the second store. A full offset-0xC4 value of zero selects 100; 0x00010000 selects 500. A failed selector comparison still follows the initial 32-bit read at offset 0x94 but causes neither store nor submission.

Examples involving differing successive reads describe conditional observations only; they do not establish that unsynchronized concurrent mutation is supported.
