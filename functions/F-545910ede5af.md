# F-545910ede5af

## Purpose

The represented procedure performs address-derived memory writes, conditionally replaces part of its working state, and enters nested repetition containing computed calls, further writes, and a software breakpoint. No normal return is represented.

An application-level purpose is not established. The operations do not justify identifying the procedure as an initializer, allocator, decoder, or device interface. Its behavior depends on explicit inputs, implicit machine state, fixed-address storage, the address of an argument’s local storage, and unresolved dependencies.

This contract describes static evidence and its limits. It does not assume that computed addresses are valid, that dependencies preserve memory, or that suspicious arithmetic has a uniquely recoverable machine interpretation. No runtime tests have been performed.

## Behavior

### Widths, arithmetic, and state terminology

Explicit accesses include 8-, 16-, 32-, and 64-bit stores and 32-bit pointer or word reads. Pointer values are represented as 32 bits. Narrow stores retain only their stated width.

Unsigned 32-bit calculations admit modulo-\(2^{32}\) interpretation where their types are unambiguous. Signed left shifts, signed arithmetic overflow, pointer conversions, and an apparent signed right shift by 32 remain qualified. This contract does not silently replace those expressions with well-defined unsigned arithmetic.

For clarity, the repeated phase has several distinct state roles:

- **Word pointer:** supplies a word read and is later replaced through a dependency-derived address.
- **Write destination:** receives the outer overlapping stores and later the three-word record.
- **Accumulator destination:** receives the outer accumulator store.
- **Accumulator value:** updated separately from its destination.
- **Running value:** participates in self-addressed writes and subsequent state changes.
- **Stride state:** initially derived from a selected base; later overwritten by a word read and, on one path, by four times the running value.
- **Working value:** supplies the outer 32-bit overlapping store and later a derived store address.
- **Call-target base and call argument:** determine F-U03’s next invocation.

These are descriptive roles, not claims that memory aliasing is harmless.

### Initial writes and destination selection

The first operation stores the first input as a 32-bit value at the address represented by that same input. F-U01 is then invoked with the first input shifted left by two.

F-U01’s primary result is treated as a pointer to 16-bit storage. Before writing through it, the procedure stores one byte at the sum of that pointer and the implicit incoming register-derived value. The byte comes from F-U01’s additional result component.

If the represented overflow condition is clear, the 16-bit destination is replaced by the fourth input shifted left by thirteen. Otherwise, F-U01’s pointer remains selected. Two 16-bit stores then write the doubled third input: first at the selected destination, then fourteen bytes later.

Next, a 16-bit store writes `0x0010` at:

\[
(\text{fourth input}\mathbin{\&}\texttt{0x7fffffff}) \gg 1.
\]

These are numeric address constructions, not validated offsets within an object.

### Local-storage-derived writes and conditional setup

The address of the fifth input’s local storage is used in two ways. A left shift by four supplies the initial word pointer. A logical right shift by twelve supplies both a byte value and another address component.

The procedure writes the low byte of the right-shifted address at absolute address `0x0000000b`, then writes 16-bit `0xed38` six bytes beyond the right-shifted address.

It captures a 32-bit shared value from `0x0897ede0`, then stores pointer value `0x97ed3800` as a 32-bit value at address `0x97ed3800`.

Default setup selects:

- Working word `0xffffff0b`.
- Base `0x97ed3800`.
- Zero control value.
- Address component equal to the fourth input shifted left by fourteen.
- Metadata pointer `0x000000a1`.

The conditional setup executes exactly when the fourth input’s low fifteen bits are nonzero. In represented order, it:

1. Writes `0x10` to shared storage at `0x225fb880`, then `0x18` to a named interrupt-related location.
2. Reads the shared index at `0x0897ede0` and writes byte `0xce` at `0x97ed3800` plus that index.
3. Reads the shared quantity at `0x0ce00026` into the working word, then clears shared storage at `0x0ce00000`.
4. Invokes F-U02 with the masked low fifteen bits shifted right once, `0xc0`, and address `0x0ce00000`.
5. Replaces the word pointer with twice the shared value captured before the conditional setup; selects base `0x0897eca0`.
6. Reads a 32-bit shared value at `0x0897eca4` and multiplies it by `0x20`.
7. Writes 16-bit `0xeca0` at four times F-U02’s additional result component, then writes the same value six bytes beyond the product from the preceding step.

The resulting metadata pointer is zero, the control value is `0x10`, and the shifted-input address component is zero.

The index read in the conditional setup is distinct from the earlier captured read. Neither shared-memory stability nor preservation across F-U02 is established. Widths of the named shared-object accesses are unresolved where the representation does not specify them explicitly.

### Common metadata writes and loop preparation

After either setup path, the procedure writes the low 16 bits of the shifted-input address component at that component plus `0x30`. It then stores the 32-bit product of the control value and `0x02000000` at that product plus `0x40`.

At the metadata pointer, it performs a byte-zero store followed by a 32-bit working-word store at the same address. It next stores 32-bit `0x40` at offset forty and the metadata pointer’s own 32-bit value at offset forty-four. The overlapping byte store remains part of the access sequence even where the following word store supersedes its ordinary-memory contents.

The accumulator value becomes the working word bitwise-ANDed with the selected base. The running value becomes eight times that base minus two.

A sum is then formed from the word pointer’s numeric value, the fifth-input local’s value **at this evaluation**, and eight. The sum is stored as a 32-bit value at twice itself. Its use of the local is not evidence that the entry pointer survived preceding writes and calls.

The derived write destination is the selected base multiplied by `0x01000000`. The remaining preparation writes, in order, are:

- The selected base as a 32-bit value four bytes beyond the metadata pointer.
- The low byte of the running value twenty bytes beyond the derived write destination.
- An assignment of the derived write destination to the address-taken fifth-input local.

The stride state becomes the selected base multiplied by `0x02000000`; the working value is zero. Both the write destination and accumulator destination initially select the derived destination. F-U03’s initial target base is `0x08bfed9a`.

The local assignment is an actual represented state change. There is no later explicit read of that local, but aliasing may make the assignment externally relevant.

### Outer write sequence

At the outer re-entry point, the current write destination receives, in order:

1. A zero byte.
2. The low 16 bits of the running value.
3. The 32-bit working value.

The accumulator value is then increased by the stride state and stored as 32 bits through the accumulator destination.

Control next enters an enclosing repetition that resets F-U03’s argument to zero. This reset point is distinct from the outer write sequence.

### Inner iteration through F-U07

At each inner iteration, the procedure first saves the low byte of the stride state. It invokes F-U03 at the current target base plus `0x0a1e`, using the current argument.

Let F-U03’s result have low and high 32-bit components. The following accesses occur in order:

- Store the low component’s low 16 bits at the address represented by that low component.
- Store the 32-bit running value multiplied by `0x40` at the address equal to that product.
- Read a 32-bit word through the current word pointer; this replaces the stride state.
- Store, at running-value-plus-four, the low 16 bits of the **old word pointer’s numeric value plus four**.
- Read a replacement 32-bit word pointer eighty bytes beyond F-U03’s high result component.

The last store uses the word pointer before replacement. It does not store the fetched word.

F-U04 and F-U05 are then called, in that order. F-U06 receives the previously read word. F-U07 receives that word logically shifted right by three.

F-U07’s high result component becomes the write destination. Its low component multiplied by `0x20` becomes the working value and is stored as 32 bits at the address equal to that scaled value.

An unsigned comparison tests whether this scaled value is below `0x14`. Under 32-bit wrapping multiplication, it is a multiple of 32, so the condition holds only when the product is zero.

**Small-result transition:** control repeats the enclosing repetition, resetting the next F-U03 argument to zero without executing the outer overlapping-write sequence or accumulator addition. The next F-U03 target base is `0x0897edf1`. The just-completed read remains the stride state; the later updates described below do not occur on this path.

### Non-small path, F-U09, and state updates

When the scaled result is not below `0x14`, a 32-bit store at scaled-result-plus-`0x58` receives the running value. A 16-bit store at running-value-plus-`0x0e` receives the low 16 bits of the current, replacement word pointer.

The stride state becomes the running value shifted left by two. A named reset-related byte receives the byte saved before F-U03. F-U08 is called with the current word pointer’s numeric value logically shifted right by two, followed by F-U09 with no explicit arguments.

Let F-U09’s low and high 32-bit result components be its address component and upper component, respectively. The procedure performs these stores in order:

1. At twice the address component, store the byte saved before F-U03.
2. At address-component-plus-eight, store the low byte of the upper component.
3. At twice the current accumulator value, store the 32-bit pointer supplied by F-U07’s high component.
4. At the address component, store the full 64-bit F-U09 result, with that address component as its low half and the upper component as its high half.

The accumulator destination becomes F-U09’s upper component. The accumulator value becomes F-U07’s high component shifted left by two. The running value becomes the current word pointer shifted left by eight.

The destination supplied by F-U07 then receives three 32-bit stores at offsets zero, four, and eight: the updated stride state, the updated running value, and the current word pointer, respectively.

The working value becomes the updated stride state multiplied by `0x100`.

### Oversized-shift decision and remaining transitions

The branch quantity is represented by shifting the signed interpretation of the current word pointer left by 31, shifting that signed result right by 32, converting to unsigned 32 bits, and logically shifting right by twenty. Its exact value is **documented_only**: both the signed left shift and the width-sized right shift prevent an unconditional arithmetic contract.

Two transitions must remain distinct:

- **Zero branch quantity:** the write destination becomes null and execution returns to the outer write sequence. F-U03’s target base is `0x0897ee1d`. The outer writes and accumulator update occur before the next argument reset and call.
- **Nonzero branch quantity:** a 32-bit store at working-value-plus-`0x20` receives the branch quantity. F-U03’s next target base becomes `0x08790d52`, and its next argument becomes the signed working value shifted right by 29. Software breakpoint number four executes. If execution resumes, the running value becomes the signed interpretation of the accumulator destination shifted right by eighteen, and execution continues directly in the inner loop without an argument reset or outer write sequence.

There is no represented return on any of these transitions.

## Side effects

Memory writes may target null, low absolute addresses, shared storage, argument storage, or dependency-derived addresses. Several accesses overlap. Aliasing may make earlier writes affect later reads, including the fifth-input local’s later evaluation.

The described order is the represented access order, not a guarantee of physical bus transaction size, atomicity, barriers, or device semantics. In particular, the 64-bit store’s atomicity and byte layout are not established.

Dependencies may modify globals, argument storage, or referenced memory, and may terminate or divert execution. Their preservation and ownership behavior is unknown. No lock, transaction, rollback mechanism, or explicit memory barrier is represented.

## Acceptance examples

These are conditional static-contract examples, not executed tests. Earlier operations and calls must complete.

1. **Narrow doubling:** third input `3` yields two 16-bit stores of `0x0006`, fourteen bytes apart. For `32767`, represented narrowing yields `0xfffe`.

2. **Setup predicate:** fourth input `0x00008000` skips conditional setup. Fourth input `1` takes it but supplies zero as F-U02’s first argument.

3. **Metadata overlap:** on default setup, address `0x000000a1` receives a zero byte before 32-bit `0xffffff0b`. Conditional setup instead selects null for these stores; no null check is represented.

4. **Mutable fifth-input local:** if earlier effects replace its stored value, the later address sum uses that replacement. Preparation subsequently assigns the derived write destination to the local.

5. **Old versus replacement word pointer:** with running value `0x100` and old word pointer `0x2000`, the 16-bit store at `0x104` receives `0x2004`. A later pointer replacement does not change that stored value.

6. **Non-small stores:** if F-U07’s low component is `1`, the scaled result is `0x20`. The self-addressed store occurs at `0x20`; the subsequent store at `0x78` receives the running value, and the 16-bit store at running-value-plus-`0x0e` receives the replacement word pointer’s low half.

7. **F-U09 outputs:** for low component `0x1000`, high component `0x203b`, and saved byte `0x5a`, ordered byte stores write `0x5a` at `0x2000` and `0x3b` at `0x1008`. The pointer store follows, then the 64-bit pattern `0x0000203b00001000` is stored at `0x1000`, subject to unresolved endianness.
