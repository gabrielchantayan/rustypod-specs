# F-8139900602e2

## Purpose

F-8139900602e2 traverses a dependency-controlled sequence, maintains a remembered address and a Boolean history condition, and conditionally clears or sets bit `0x10` in an 8-bit field at address offset `0x18`.

Its directly established outcomes are:

- Zero or more flag-byte clears, followed by termination without a flag set.
- Zero or more clears, followed by one terminating flag set and two completion calls.
- Continued traversal without termination if dependencies keep returning values that avoid the terminating branches.

Every explicit return calls F-d0d3f100effc. Its placement suggests cleanup, but its actual resource effects are unknown.

A critical distinction is that the current-item address resides in an exposed mutable slot. Categorization, secondary predicate evaluation, and direct flag access need not concern the same address. The routine reloads that slot across dependency calls. The interpretation that it processes one unchanged item throughout an iteration is valid only under an additional slot-stability assumption.

Application-level meanings such as selection, boundary detection, or item eligibility are inferred intent, not established behavior.

## Behavior

### Initialization

Before the first dependency call, the routine:

- Sets the history condition to false.
- Initializes the current-item slot from the second argument.
- Initializes the two traversal words from the third and fourth arguments, respectively.

It calls F-8ca21d3a8cca with the traversal-storage address and the first argument. After that call returns, it initializes the remembered address to zero.

The initialization result is not tested.

### Traversal and ordered slot observations

Each iteration starts by calling F-b38a3aba0e18 with the traversal-storage address and the current-item-slot address.

A zero 32-bit result terminates traversal. A nonzero result enters item processing, using the slot contents then available. A nonzero traversal result does not independently prove that the slot was updated or that it contains a valid address.

For an iteration entering item processing, the relevant observations occur in this order:

1. The routine reads the current-item slot to supply the argument to F-87ad59f6eb14.
2. After F-87ad59f6eb14 returns, its result selects one of two branches.
3. The routine reads the slot again to supply the argument to F-f86ec6aaf357.
4. After F-f86ec6aaf357 returns, any direct current-item flag access uses the slot contents then available.

Consequently, categorization can receive address A, the secondary predicate can receive address B, and subsequent direct flag access can target address C. The branch still depends on the categorization result obtained for A and the predicate result obtained for B.

For example, F-87ad59f6eb14 could cause the slot to change through a previously retained pointer before returning. F-f86ec6aaf357 would then receive the changed value. A further change during that predicate call could redirect the subsequent flag access again.

No visible dependency call intervenes between a candidate’s qualification-byte read, recording the current address, and its possible immediate flag set. Under ordinary sequential execution without asynchronous mutation, these operations therefore concern the same post-predicate slot value. That does not make it necessarily equal to either dependency’s argument.

### Persistent history

Two pieces of state control later behavior:

- **History condition:** initially false. It becomes true when the clearing branch reaches its direct clear while the remembered address is zero. It is never explicitly reset.
- **Remembered address:** initially zero. On the candidate branch, a nonzero low-32-bit predicate result followed by a flag-byte read with bit `0x01` set causes the current slot value to be remembered.

“Remembered” therefore means recorded by this control-flow condition. It does not prove that the recorded address itself was supplied to either categorization or the predicate.

An iteration failing candidate qualification leaves the remembered address unchanged. A qualifying current address of zero can, however, replace a previously nonzero remembered address with zero if access to byte address `0x18` is valid in the environment. There is no explicit rejection of that case.

### Traversal termination

When F-b38a3aba0e18 returns zero:

- If the remembered address is zero, the routine calls F-d0d3f100effc with the traversal-storage address and returns.
- Otherwise, it reads the byte at remembered address plus `0x18`, writes that byte with bit `0x10` set, calls F-eea3e31f6354, then F-bf8276908a13, then F-d0d3f100effc, and returns.

The current-item slot is not used to choose the flag target on this path. The remembered address is used directly.

Exhaustion is not exposed as an error. Its effects depend on the remembered-address sentinel.

### Nonzero categorization result: clearing branch

A nonzero result from F-87ad59f6eb14 selects this branch. The routine then invokes F-f86ec6aaf357 with the slot value read after categorization returns.

If the predicate’s low 32 bits are nonzero, the routine calls F-d0d3f100effc and returns immediately:

- No direct flag access occurs for this iteration.
- No remembered-address flag set occurs.
- Neither completion dependency is called.

This bypass applies even if a nonzero address was previously remembered.

If the predicate’s low 32 bits are zero:

1. If the remembered address is zero, the history condition becomes true.
2. The routine reads the flag byte addressed through the post-predicate current-item slot and writes it with bit `0x10` cleared.
3. If the remembered address is zero, traversal continues.
4. Otherwise, the routine sets bit `0x10` at the remembered address, calls both completion dependencies in order, calls cleanup, and returns.

The clear precedes the remembered-address set. If their effective byte addresses alias, the direct operations clear and then set bit `0x10`.

### Zero categorization result: candidate branch

A zero result from F-87ad59f6eb14 selects this branch. The routine then invokes F-f86ec6aaf357 with the newly read slot value.

If the predicate’s low 32 bits are zero, traversal continues without a direct current-item flag read or write. The remembered address is unchanged.

Otherwise, the routine reads the flag byte addressed through the post-predicate current-item slot:

- If bit `0x01` is clear, traversal continues without changing the remembered address.
- If bit `0x01` is set, the current slot value becomes the remembered address.

After that assignment:

- If the history condition is false, traversal continues without a direct flag write.
- If the history condition is true, the routine reads the current-item flag byte again, writes it with bit `0x10` set, calls F-eea3e31f6354, then F-bf8276908a13, then cleanup, and returns.

This immediate marking decision tests the history condition, not whether the newly remembered address is nonzero. Thus, a qualifying zero current address can still take the immediate setting path, subject to valid access at effective address `0x18`.

### Widths, arithmetic, and access boundaries

All direct item-memory operations are byte-wide.

- Clearing preserves the seven other bits from the byte read and forces bit `0x10` to zero.
- Setting preserves the seven other bits from the byte read and forces bit `0x10` to one.
- Qualification tests only bit `0x01`.

The candidate qualification read and an immediate setting read are separate accesses. The setting write is not based on the earlier qualification byte.

Only the low 32 bits of F-f86ec6aaf357’s represented result affect decisions. Although one branch represents the result with 64 bits, a nonzero high half alone does not count as true.

The address expression adds `0x18` to a 32-bit address representation. There is no explicit overflow check or invalid-address handling. The supplied representation does not establish a portable signed-overflow or address-wrap contract. Safe use requires that the effective address resolve to the intended accessible byte.

## Side effects

### Direct effects and their limits

The routine can directly clear bit `0x10` on multiple flag bytes and execute at most one terminating flag set per invocation. A clear or set remains a read followed by a write even when the target bit already has the requested value.

Earlier clears are not rolled back when a later iteration exits without marking.

Dependency calls may modify traversal storage and the exposed current-item slot. Their other memory and global-state effects are unknown. In particular, neither remembered-address validity nor flag-byte stability is guaranteed across calls merely because the routine itself retains an address.

The body contains no explicit allocation, deallocation, item destruction, or ownership transfer. It does not establish that dependencies lack such effects.

### Completion and cleanup order

Every marking exit has the following visible order:

1. Flag-byte read and setting write.
2. F-eea3e31f6354.
3. F-bf8276908a13.
4. F-d0d3f100effc with traversal storage.
5. Return.

A nonmarking exit calls cleanup without either completion call.

Results from initialization, completion, and cleanup are not tested. No explicit error recovery is provided for dependency failures, memory faults, exceptions, or nonlocal control transfer.

Cleanup is called exactly once on each explicit return path. This does not guarantee cleanup if a dependency does not return, an access faults, or traversal continues forever.

### Concurrency and retained storage

The visible byte updates are ordinary read-modify-write operations, not established atomic operations. No synchronization is visible.

Passing the slot address permits dependency-mediated mutation that matters even in otherwise sequential execution. Concurrent or asynchronous mutation introduces additional uncertainty, including whether separate slot observations within direct expressions identify the same byte. No synchronization or lifetime contract for retained pointers is supplied.

## Acceptance examples

These are conditional static deductions, not executed tests.

Unless an example explicitly states slot changes, assume:

- All dependencies return normally.
- Traversal updates the current-item slot only to the stated addresses.
- No other dependency, retained-pointer holder, or concurrent actor changes that slot.
- All effective flag addresses are valid and arithmetic identifies the intended bytes.
- Flag bytes remain stable except for the specified direct operations.
- Named item addresses are nonzero.

1. **Immediate exhaustion.** The first traversal call returns zero. No item byte is directly accessed. Cleanup is called once; neither completion dependency is called.

2. **Candidate followed by exhaustion.** One iteration has zero categorization result, nonzero low-32-bit predicate result, and flag byte `0x05`. That address is remembered. Exhaustion changes its byte to `0x15`, followed by both completion calls and cleanup.

3. **Nonqualification preserves the remembered address.** A qualifies. B then has zero categorization result and zero low-32-bit predicate result. Exhaustion marks A. B receives no direct flag access.

4. **Latest qualifying address wins.** A and B qualify without an intervening clearing branch. Exhaustion sets bit `0x10` on B, not A.

5. **Earlier clear enables immediate marking.** A takes the clearing branch with a zero predicate result, changing `0xB7` to `0xA7`. B later qualifies with byte `0x03`. Its byte becomes `0x13`; completion and cleanup occur without another traversal call.

6. **Clear after remembering.** A is remembered. B takes the clearing branch with a zero predicate result. B is cleared before A is set, then completion and cleanup occur.

7. **Aliasing targets.** The remembered address and a later clearing address are equal. A byte initially `0x11` is written as `0x01`, then `0x11`, before completion.

8. **Predicate-triggered nonmarking exit.** A is remembered. The next categorization result is nonzero, and the secondary predicate’s low 32 bits are nonzero. Cleanup occurs without marking A or calling either completion dependency.

9. **Clears without completion.** Clearing-branch iterations with zero predicates are followed by exhaustion, with no qualifying candidate. Their clears remain; no direct set or completion call occurs.

10. **High-half-only predicate result.** On the candidate branch, a represented predicate result with zero low 32 bits and nonzero upper bits produces no direct flag read and no remembered-address change.

11. **Different categorization, predicate, and access addresses.** Traversal supplies A. Categorization receives A, returns zero, and changes the exposed slot to B before returning. The predicate receives B, returns a nonzero low half, and changes the slot to C. C has byte `0x05`. With no history condition, C becomes remembered; exhaustion marks C as `0x15`. This does not establish that C was passed to either decision dependency.

12. **Redirected clearing access.** A is already remembered. Categorization receives B and returns nonzero. The predicate receives C, returns zero, and leaves D in the slot. D is directly cleared, then A is directly set. B and C need not receive any direct byte access.

13. **Qualifying zero replaces the sentinel state.** Relax the nonzero-address assumption and allow effective byte address `0x18` to be valid. After A is remembered, a candidate iteration uses current address zero with a qualifying byte and nonzero predicate. With no history condition, the remembered address becomes zero. Subsequent exhaustion performs cleanup without marking A.
