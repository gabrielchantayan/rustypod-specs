# F-775b20758785

## Purpose

F-775b20758785 performs indirect dispatch using a numeric value obtained from caller-supplied storage. A fixed displacement of 292 determines where a callable reference is stored. The function invokes the callable identified by that reference.

The entry location is data containing a callable reference; it is not itself treated as the executable target. Selection depends on the stored integer, not on the address of the caller-supplied storage.

The established behavior is limited to selection and invocation. The evidence does not identify an application-level operation, establish an object model, or demonstrate an implicit receiver. A table-like dispatch arrangement is a plausible interpretation, not an additional contract.

## Behavior

Consequently, relocating the input storage without changing its contents does not, by itself, change the selection relationship. Changing the stored integer can change the selected entry. Different entries can still identify the same callable.

There is no represented lookup by name, entry comparison, search, alternate displacement, retry, or fallback. A valid callable reference at a neighboring location does not compensate for an unusable reference at the required entry.

### Observable ordering

The wrapper represents one read of the input integer and one read of the selected callable reference. Their dependency establishes the relevant order: the input read determines which entry is read, and the entry read determines which callable is invoked.

These are semantic accesses, not promises about the number of machine instructions, bus transactions, speculative accesses, or cache operations. They also exclude accesses performed by the selected callable.

The wrapper makes one direct invocation if execution reaches the call. After a normal return, it performs no explicit input reread, entry reread, second dispatch, or result-dependent action.

Changes made by the callable to selection-related storage therefore do not cause this activation to select another target. A nested invocation caused by reentrancy would be a separate activation.
