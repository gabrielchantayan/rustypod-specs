# F-f370660ffa4f

## Purpose

F-f370660ffa4f conditionally invokes a callback associated with a first object, then records selected low-order bits in a state word associated with a second object.

The decision is based on overlap, not full containment: if either of the two relevant bits is already present in both the supplied mask and the second object’s state word, the function performs no callback and no state write. Otherwise, it resolves and invokes the callback, then merges the supplied mask’s bottom two bits into the second object’s state word.

**Established behavior:** callback dispatch precedes the state update. The state word is read again after the callback returns.

**Inferred intent:** the bottom two bits appear to represent categories of work or notification already handled. The dispatch representation resembles an adjusted receiver with either a direct callback address or a table-selected callback. Neither interpretation establishes a broader object model, event protocol, or ownership convention.

## Behavior

### 1. Initial state gate

The first observable data access is a 32-bit read at offset `0x90` from the second argument.

The function examines the intersection of:

- That state word;
- The supplied 32-bit mask;
- The constant mask `3`, selecting bits 0 and 1.

If this intersection is nonzero, the function returns immediately.

Consequences of this rule:

- Either overlapping low bit is sufficient to suppress dispatch.
- A request for both low bits is suppressed even if only one of them is already recorded.
- Bits 2 through 31 do not affect suppression.
- A mask with neither low bit set does not suppress dispatch, regardless of the state word.
- On the suppressed path, no dispatch field is read and no state write is performed by this function.

This is not a “dispatch any missing bits” operation. It also is not a “skip only when every requested bit is already set” operation.

### 2. Dispatch-mode sampling

When the gate permits dispatch, the function reads the 32-bit word at offset `0xA98` from the first argument. Bit 0 of this read determines the dispatch mode.

That mode decision is retained for subsequent target selection:

- Bit 0 clear selects direct dispatch.
- Bit 0 set selects table-based dispatch.

In table-based mode, the function next reads the 32-bit value at offset `0xA94`. This value supplies the selector used for locating the callback in the table.

In direct mode, the callback address at offset `0xA94` is not read yet.

### 3. Adjusted receiver calculation

The word at offset `0xA98` is read again. This is a distinct read from the one used to decide the dispatch mode.

The entire second-read value is interpreted as a signed 32-bit integer and shifted right arithmetically by one bit. Thus, a set high bit produces a negative adjustment; this is not an unsigned division by two.

The adjusted receiver address is the first argument’s base address plus that signed byte adjustment.

Important consequences:

- The adjustment is in bytes, not in units of table entries or words.
- The shift removes the bottom bit while retaining the sign.
- The mode comes from the earlier read, while the adjustment comes from the later read.
- If the field changes between reads, the selected mode and adjustment need not describe a single coherent field snapshot.

No synchronization or consistency check is visible.

The arithmetic shift yields an adjustment between −1,073,741,824 and 1,073,741,823 inclusive. Whether adding that adjustment to a particular base address wraps, faults later, or falls outside a valid object cannot be determined solely from the supplied representation.

### 4. Callback target resolution

#### Direct mode

The function reads the callback address from offset `0xA94` of the first object.

It invokes that callback with:

1. The adjusted receiver address;
2. The original second argument;
3. The original, complete 32-bit mask.

The shown function does not dereference the adjusted receiver merely to resolve a direct target. The callback may dereference it.

#### Table-based mode

The function reads a 32-bit table-base value from the adjusted receiver address.

It clears bits 0 and 1 of the previously read selector. The resulting unsigned 32-bit value is used as a **byte offset** from the table base. The callback address is read at that resulting address.

This is not a selector multiplied by an entry size. Clearing the bottom two bits makes the offset a multiple of four but does not establish the alignment or validity of the table base itself.

The selected callback receives the same three arguments, in the same order, as in direct mode.

The selector’s high bits are retained. There is no visible range check, table-length check, or signed-index conversion before target lookup.

### 5. Post-callback marking

Only after the callback returns normally does the function update the state word.

It performs a fresh 32-bit read at offset `0x90` from the original second argument, combines that value with the supplied mask’s bottom two bits using bitwise OR, and writes the resulting 32-bit value back to the same location.

This establishes the following behavior:

- Bits already present in the post-callback state are preserved.
- Requested bits 0 and 1 are set.
- No higher mask bits are introduced by this function.
- Callback changes to the state word are incorporated rather than replaced with the pre-callback value.
- The state address is derived from the original second argument, not from the adjusted receiver.

For a zero low-bit mask, the function still performs this read and write after a normal callback return. The written value equals the value just read.

The update is an ordinary read followed by a write in the supplied representation. No atomic read-modify-write operation, lock, or memory-ordering primitive is shown.

The requested bits are not marked before callback entry. A reentrant invocation therefore does not automatically see the outer invocation as completed.

For example, if the callback reenters with the same second object and mask before changing the state word, the nested invocation can pass the gate again.

Concurrent access is not protected. The two reads of the dispatch word may observe different values, and a concurrent state update between the final state read and write may be lost. No thread-safety guarantee follows from this function.

### Abnormal completion
