## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Entry ordering:** If the primary `0x74` read fails after a successful context-`0x09` store, the input-byte store has already occurred. Graceful recovery or rollback is not an acceptance requirement.

2. **Corrected working-base effects:** If the primary snapshot is `0x123456ab`, working `0x54` receives that entire four-byte value during the initial mutable-region phase. Working `0x09` first receives the working address’s low byte and later the early working-link snapshot’s low byte. Working `0x11` receives the later working-link snapshot’s low byte twice, separated by the specified working-`0x09` and mutable-`0x1c` writes.

3. **Separated duplicate stores:** The mutable-region `0x00` stores use the same captured low byte. Nevertheless, a fresh working-`0x14` read, a further-region-`0x11` store, and a mutable-region-`0x44` store occur between them. They are not adjacent duplicate accesses.

4. **Terminal payload retention:** If the terminal link snapshot is `0x12345678`, terminal accesses 1, 4, and 5 each store numeric halfword `0x5678`. An earlier terminal store aliasing retained-base `0x74` does not change those captured payloads.

5. **Plain-character conversion:** For a terminal character byte with all eight bits set, the character-derived value is 255 on an unsigned-plain-character target, or `0xffffffff` on a signed-plain-character target with the represented 32-bit conversion. Neither interpretation is selected without target evidence.

6. **Width and OR:** A four-byte `0x74` store affects four bytes. Separately, a character-derived value of `0x45` produces first terminal argument `0x45`, whereas the earlier four-byte store’s address is `0x8a` under ordinary representable addition.

7. **Aliasing:** If an intervening store changes a link before a specified fresh read, the fresh read uses the changed contents. Earlier captured links remain earlier values.
