# F-0c055762858c

## Purpose

F-0c055762858c performs an ordered sequence of indirect calls, calculated-address word stores, byte reads, and byte stores, then enters an unconditional repeating call-and-store sequence.

The supplied static representation does not establish an application-level purpose. In particular, it does not establish initialization, serialization, allocation, device control, or a named protocol.

No normal return is represented. If every dependency returns and every memory operation succeeds, execution continues indefinitely in the repeating sequence.

This contract distinguishes:

- **Established static evidence:** operations, widths, data dependencies, and ordering present in the supplied representation.
- **Inferred intent:** no higher-level intent is assigned.

The supplied material reports invalid instruction data and removal of unreachable regions. This contract therefore describes the represented path, not a verified reconstruction of all executable behavior.

## Behavior

### 1. Initial word store and scaled result

The first explicit memory operation writes the incoming unspecified register word to the address formed from the first input plus 20.

Five indirect calls follow:

1. A call whose target depends on the incoming link register, with the first input as its sole shown argument.
2. Three calls with no shown arguments.
3. A fifth call with no shown arguments, retaining its returned signed integer.

The function multiplies the retained result by 4 and retains that quantity as an unsigned 32-bit **initial scaled word**. It writes that word to the address formed by multiplying the same returned integer by 16 and adding 20.

The multiplications are represented through signed arithmetic before or alongside conversion to unsigned storage. Overflow behavior remains documented-only.

### 2. Forwarded results and complete fourth-input storage

The function performs the following calls in order:

1. A call receiving the initial scaled word.
2. A no-shown-argument call, followed by a call receiving its result.
3. Another no-shown-argument call, followed by a call receiving its result.
4. Four no-shown-argument calls, retaining the fourth result as a signed integer.

It writes the complete fourth input as a 32-bit word to the address formed from this latest retained result multiplied by 4, plus 20.

A call then receives that retained result multiplied by 4.

No validation of the result, address, alignment, or destination extent is represented.

### 3. Two word stores to one calculated slot

Four more no-shown-argument calls occur. The fourth supplies a signed integer used to derive:

- A **scaled base**, equal to that result multiplied by 16.
- A word value equal to that result multiplied by 4.

The function writes the word value to the scaled base plus 20.

It also derives a **first selector** from the initial scaled word by clearing its highest bit and logically shifting right by 7. Later selection-byte reads use the first selector plus 1 as their address.

The next call has three shown arguments, in order:

1. The scaled base.
2. The same scaled base.
3. The third input logically shifted right by 7.

Four no-shown-argument calls follow. After the fourth returns, the function writes the scaled base itself as a 32-bit word to the same scaled-base-plus-20 slot.

A call then receives the latest returned integer shifted left by 2.

The two stores to this slot are separated by five dependency calls. The first store cannot be treated as unobservable merely because a later store uses the same address: intervening callees may read or modify that memory.

### 4. First byte-selected store

Four no-shown-argument calls follow. The fourth supplies an unsigned 32-bit result retained for two byte values.

The function then:

1. Reads an unsigned byte from the first selector plus 1.
2. Uses that byte’s numeric value plus 17 as the destination address.
3. Stores the low eight bits of the retained result shifted left by 2.

The selected destination is between numeric addresses 17 and 272 inclusive. It is not the selection-byte address plus 17.

A call follows with three identical shown arguments, each carrying the retained result shifted left by 2. The unsigned shift has 32-bit truncation; its subsequent signed representation is subject to the conversion uncertainty described above.

### 5. Second byte-selected store

The next calls are:

1. One no-shown-argument call.
2. One call receiving that result.
3. Four no-shown-argument calls, retaining the fourth result as a signed integer.

The function rereads the unsigned byte at the first selector plus 1. It stores a byte at the newly selected destination, again the read byte’s value plus 17.

The stored value comes from the unsigned result retained in the preceding stage: clear its highest two bits, logically shift right by 20, and retain the low eight bits for the store. Consequently, the stored byte represents original bits 20 through 27.

A call then receives the latest signed result shifted left by 2.

The two selected stores need not target the same address. They use separate reads, with dependency calls between them.

### 6. Fourth-input-derived store and two clears

Four no-shown-argument calls occur. The fourth supplies a new unsigned 32-bit result.

The function retains this result shifted left by 2 as a **saved shifted value**, then performs these memory operations without an intervening call:

1. Stores the saved shifted value’s low byte at the fourth input logically shifted right by 7, plus 28.
2. Reads the unsigned byte at the first selector plus 1.
3. Writes zero at the read byte’s value plus 17.

The first store precedes the selection-byte read. If their addresses alias, the read can observe the byte just written.

Three calls follow:

1. A call receiving the fourth input logically shifted right by 7.
2. A call with no shown arguments.
3. A call receiving the new unsigned result with its highest two bits cleared, logically shifted right by 6.

Four further no-shown-argument calls occur. The fourth supplies a signed integer result.

The function rereads the byte at the first selector plus 1 and writes zero to the destination selected by that byte plus 17.

A call then receives the latest signed result shifted left by 2.

These two selector-based clears are separate observable stores. Their destinations may differ because calls occur between their selection-byte reads.

### 7. Final pre-repetition clear and entry state

Four no-shown-argument calls follow. The fourth supplies an unsigned result.

Clearing that result’s highest two bits and logically shifting right by 25 produces an **initial control value** between 0 and 31 inclusive.

The saved shifted value from stage 6 supplies the **second selection-byte address**: multiply that saved value by 1,024, then add 1. This calculation involves signed arithmetic, so overflow behavior is unresolved.

The function reads an unsigned byte at this second address and writes zero to the byte’s numeric value plus 17.

It then makes:

1. A call receiving the initial control value shifted left by 1.
2. A no-shown-argument call whose signed result becomes the first argument retained for repetition.

The saved shifted value is not explicitly updated afterward.

### 8. Unconditional repeating sequence

Each iteration performs these operations in order:

1. Calls a dependency with two shown arguments:
   - The currently retained signed integer.
   - The current unsigned control value logically shifted right by 8.
2. Makes four no-shown-argument calls, retaining the fourth signed result.
3. Reads an unsigned byte using the second selection-byte address calculation.
4. Writes zero to the read byte’s numeric value plus 17.
5. Calls a dependency with the retained signed result shifted left by 2.
6. Makes four no-shown-argument calls, retaining the fourth signed result for the iteration update.

The next iteration’s first argument is this final result shifted left by 2. Its control value is this same final result shifted left by 26, then held as unsigned.

There is no represented exit condition.

For the first iteration, the opening call’s second argument is zero: the initial control value is at most 31, and its logical right shift by 8 is zero.

For later iterations, **if** the signed left shift by 26 is interpreted as retaining the low 32 bits, the opening call’s second argument equals the preceding final result’s low six bits shifted left by 18. This is conditional, not an established signed-overflow rule.

Each iteration contains ten indirect calls, one explicit byte read, and one explicit byte store. The saved operand of the second selection-byte address calculation remains unchanged in the representation. The selected destination can nevertheless change because the byte is reread.
