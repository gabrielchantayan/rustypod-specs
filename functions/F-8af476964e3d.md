# F-8af476964e3d

## Purpose

F-8af476964e3d performs a four-byte cursor retreat, submits the value at the cursor’s former address to a dependency, and then selects one of two state-update paths.

Both paths expose a four-word temporary frame to a transformation dependency and copy the resulting frame into a caller-supplied state record. The nonzero-selection path additionally copies that state into the record’s first four words and submits two other state words to a dependency.

The returned 64-bit value combines the first two words of the temporary frame.

These are established structural behaviors. Describing the cursor operation as a “pop,” the first submission as “release,” or the four-word frame as a particular domain object would require evidence not present here.

## Interface

### Inputs

The function receives four arguments:

| Argument | Established representation | Use |
|---|---|---|
| State record | Pointer to a record addressed in 32-bit words | Supplies and receives state; also becomes the initial first word of the temporary frame |
| Second argument | 32-bit integer | Initial second frame word |
| Third argument | 32-bit integer | Initial third frame word |
| Fourth argument | 32-bit integer | Initial fourth frame word |

The source representation stores addresses in 32-bit record words and converts the state-record pointer into a 32-bit frame word. This contract therefore describes the represented 32-bit address model. It does not establish behavior for addresses that cannot be represented in those words.

### State-record layout

Offsets below are byte offsets from the state-record address:

| Offset | Word index | Established use |
|---|---:|---|
| 0–12 | 0–3 | Written only by the nonzero-selection path’s explicit copy |
| 16–28 | 4–7 | Receive the four transformed frame words on either path |
| 28 | 7 | Also supplies the initial cursor and, on the zero-selection path, a later address |
| 32 | 8 | No direct access established |
| 36 | 9 | Read for the final dependency call on the nonzero-selection path |
| 40 | 10 | Read for the same call |

The initial direct access requires word 7 to be readable and writable. The former cursor address must be readable as a 32-bit word after the cursor update. Later accesses impose additional path-dependent requirements.

A contiguous, suitably aligned, writable record of at least 44 bytes is a straightforward sufficient layout for all direct record accesses, but it is not a complete safety guarantee: dependencies may impose further requirements, and pointer-valued words must designate valid memory when dereferenced.

### Temporary frame

The function initializes a four-word temporary frame, in order, with:

1. The state-record address represented as a 32-bit word.
2. The second argument.
3. The third argument.
4. The fourth argument.

A pointer to the first word is passed to F-3d8e7dd29be8. The subsequent copies treat these four words as the transformation’s resulting frame.

The visible call does not pass a frame length. What memory that dependency actually reads or writes is not established by this function alone.

### Output

Normal completion returns a 64-bit concatenation:

- Bits 0–31: first temporary-frame word.
- Bits 32–63: second temporary-frame word.

This is a bit-pattern composition, not a signed extension or arithmetic sum. The third and fourth frame words do not directly contribute to the return value.

The frame words are read for the return after any path-specific dependency calls. The returned bits are therefore not unconditionally guaranteed to equal words previously copied into the state record if a later dependency can modify the frame through an alias.

## Behavior

### 1. Retreat the stored cursor and read its former location

The function first reads state word 7 as an address.

It then stores an address four bytes lower into state word 7. Only after that store does it read a 32-bit value from the original address.

This order is observable when memory aliases. The implementation does not first save the pointed-to value and then update the cursor.

There is no visible check for:

- A null cursor.
- Misalignment.
- An invalid cursor address.
- A lower address falling outside a valid object.
- Arithmetic underflow or pointer-range violations.

No portable wraparound behavior is established for invalid pointer arithmetic.

### 2. Initialize the temporary frame and perform the first submission

After the old cursor location has been read, the function initializes the temporary frame from the four input arguments.

It then:

1. Calls F-5d8a0091da0c without explicit arguments.
2. Calls F-ff1bdc376dcd with:
   - The 32-bit value read from the original cursor address.
   - The 32-bit result of F-5d8a0091da0c.
   - A zero third argument.

The value submitted as the first argument is the previously captured word. Changes made by either dependency to the old cursor location do not cause that word to be read again.

No return value from this F-ff1bdc376dcd call is used.

### 3. Select a path

The function calls F-be518f1dc9cf with the original state-record pointer.

A zero result selects the zero-selection path. Any nonzero 32-bit result selects the nonzero-selection path; there is no distinction between positive and negative nonzero results.

This call occurs after the initial cursor update and first submission. Consequently, the selector can observe those effects, subject to the behavior of the preceding dependencies.

The state record is not snapshotted before these calls. Dependency changes to it can affect later reads.

### 4. Nonzero-selection path

The function calls F-3d8e7dd29be8 with three explicit arguments:

1. The temporary-frame address.
2. Zero.
3. Zero.

When that call returns normally, the function copies the four frame words into state words 4, 5, 6, and 7, in that order.

It then performs a second ordered copy:

1. Read current state word 4 and write state word 0.
2. Read current state word 5 and write state word 1.
3. Read current state word 6 and write state word 2.
4. Read current state word 7 and write state word 3.

These are direct sequential assignments, not an atomic record replacement.

Next, it calls F-ff1bdc376dcd with:

- Current state word 9.
- Current state word 10.
- Zero.

The two state words are read for this call after the preceding copies. Their relative argument-evaluation order is not established by the supplied representation.

Finally, the function returns the 64-bit concatenation of the first two frame words.

On this path, F-5d8a0091da0c is called once in total, and F-ff1bdc376dcd is called twice.

### 5. Zero-selection path

The function calls F-5d8a0091da0c a second time.

After that call returns, it reads the then-current state word 7 as an address and reads a signed 32-bit integer from that address. This is not necessarily the cursor value originally stored by the function: intervening dependencies may have changed state word 7.

The function forms an integer argument from:

- The signed 32-bit integer read through current state word 7.
- Plus four times the second F-5d8a0091da0c result, interpreted here as a signed 32-bit integer.

The multiplication is applied to the dependency result before the addition. This expression uses the contents at the cursor, not the cursor address itself.

The source representation shows signed 32-bit arithmetic. For operands whose multiplication or addition exceeds the signed 32-bit range, the supplied evidence does not establish a portable result. Acceptance claims about this calculation should therefore use representable operands unless additional execution-level evidence resolves overflow behavior.

The function then calls F-3d8e7dd29be8 with two explicit arguments:

1. The temporary-frame address.
2. The computed integer.

Unlike the nonzero-selection call, this call does not visibly supply a third argument. The discrepancy must not be normalized into an assumed zero third argument.

After that call returns normally, the function copies the four frame words into state words 4–7, in order, and returns the concatenation of the first two frame words.

There is no direct copy into state words 0–3 and no second F-ff1bdc376dcd call on this path.

## Side effects

### Direct memory effects

The function explicitly performs:

- One initial write to state word 7, before reading the former cursor location.
- Four writes to state words 4–7 after the transformation call, on either path.
- Four additional writes to state words 0–3 on the nonzero-selection path.

The initial cursor retreat is therefore an intermediate state change. On normal completion, its stored value has been replaced by the fourth transformed frame word.

On the zero-selection path, the function does not directly write state words 0–3. This is not a promise that those words remain unchanged: dependencies receive the state-record pointer or may have other aliases.

There is no direct write to state words 8–10, though words 9 and 10 are read on the nonzero-selection path.

### Dependency effects and ownership

The function passes:

- The state-record pointer to F-be518f1dc9cf.
- A pointer to temporary frame storage to F-3d8e7dd29be8.
- Several 32-bit values, including values potentially representing addresses, to F-ff1bdc376dcd.

The visible body does not explicitly allocate, free, or transfer ownership of memory. It does not establish that any dependency allocates, releases, retains, or merely observes an argument.

The temporary frame has function-local lifetime. Whether F-3d8e7dd29be8 retains its address, and whether later dependencies can reach that frame through retained aliases, is unknown. No lifetime-extension guarantee is established.

Likewise, no dependency is known here to preserve globals, the state record, or memory reachable through supplied values.

### Errors and partial updates

There is no explicit error result, rollback, validation branch, or exception recovery in the visible behavior.

The selector’s nonzero result chooses a path; it is not established as an error indication.

If a dependency fails to return normally, or a memory access faults, normal completion is not established. Effects already performed may remain. In particular, the initial state-word-7 write precedes even the first cursor-target read.

No synchronization, atomicity, or concurrent-observer guarantees are established.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid required memory, normal dependency returns, and no dependency effects beyond those stated.

### Zero-selection path with representable arithmetic

Suppose the selector returns zero. After the second provider call, current state word 7 points to a signed word containing 100, and the provider returned 3.

The integer supplied as the transformation’s second explicit argument is 112.

If the transformation leaves frame words equal to 10, 20, 30, and 40, respectively:

- State words 4–7 become 10, 20, 30, and 40.
- State words 0–3 receive no direct writes.
- The return is `0x000000140000000A`.
- There is no final submission using state words 9 and 10.

### Nonzero selection, including a negative result

Suppose the selector returns −1 and the transformation produces frame words 1, 2, 3, and 4.

The nonzero-selection path applies:

- State words 4–7 become 1, 2, 3, and 4.
- State words 0–3 then become 1, 2, 3, and 4.
- The final submission uses the values subsequently read from state words 9 and 10, with zero as its third argument.
- If that submission does not alter the frame, the return is `0x0000000200000001`.

A selector result of positive one chooses the same path.

### Cursor target aliases the cursor field

Suppose the original cursor address is exactly the address of state word 7, with a representable address and valid surrounding storage.

The function first writes the address four bytes below that location into state word 7. It then reads from the original cursor address, which is the same field.

Accordingly, the captured word is the newly stored lower address, not the field’s original contents. That captured word becomes the first argument of the initial submission.

### A dependency changes the cursor

Suppose the selector returns zero and changes state word 7 to a different readable address. The second provider preserves that field.

The later signed-word read uses the replacement address. It does not use a saved copy of the initial cursor or the function’s initial decremented value.

### Negative provider result

Suppose the zero-selection path reads 20 through current state word 7, and the second provider result is interpreted as signed −2.

The transformation’s second argument is 12. This example remains within signed 32-bit arithmetic range.

### Return-word signedness

Suppose the frame’s first word is `0xFFFFFFFF` and its second word is `0x00000001` at return time.

The result is `0x00000001FFFFFFFF`, not a sign extension of the first word.

### Invalid initial cursor

If state word 7 contains an invalid cursor, no successful-return requirement follows. The record-field update occurs before the cursor-target read, so an access failure does not imply the record was left unchanged.
