# F-83d4d1c362b6

## Purpose

F-83d4d1c362b6 scans a byte region, translates each consumed byte through externally addressed storage, and accumulates the translated bytes into a rolling 32-bit unsigned value. Ordered comparisons against eight externally stored 32-bit values control local recognition state and early termination.

The function returns either when its cursor equals a calculated end address or when a terminal comparison succeeds without a higher-priority recognition transition taking effect.

There is no returned recognition result and no explicit write to external storage. Established observable behavior consists of the external-data evaluations, input consumption, and termination behavior. An interpretation as a byte-pattern recognizer is plausible, but particular token spellings, encodings, or recognition categories are not established.

## Interface

**Argument:** A pointer to a record containing at least two consecutive 32-bit words.

| Record offset | Width | Interpretation |
|---|---:|---|
| 0 bytes | 32 bits | Stored address representation used to initialize the scan cursor and calculate the end address |
| 4 bytes | 32 bits | Unsigned encoded length; logical right shift by one supplies the byte count |

The first field is a 32-bit stored address representation, not a native-width pointer field of unspecified size. A wider-address implementation would need an explicit mapping for that representation rather than silently changing the record layout.

**Output:** No return value, output parameter, or explicit status code.

**External inputs:**

- An externally stored translation-base address value.
- Bytes reached through that translation base.
- Eight 32-bit comparison values, designated **K0** through **K7**, at consecutive four-byte offsets from a comparison-data region.

The supplied representation does not declare the translation-base object's storage type or width. Its role as an address-bearing value is established; its exact storage layout is not.

**Ownership and lifetime:** No allocation, deallocation, pointer retention, or ownership transfer is present. The function borrows access to the record, scanned bytes, translation-base storage, reached translation bytes, and reached comparison values.

For ordinary bounded operation, all reached storage must be readable, address arithmetic must remain valid, and the record must remain stable. Stable external recognition data is additionally required for examples that treat K0–K7 and the translation mapping as fixed values. None of these conditions is validated by the function.

## Behavior

### Initialization and boundary calculation

The local recognition state begins at decimal 99. The rolling unsigned 32-bit value begins at zero. The cursor is initialized from the record's first word.

Before each byte consumption, the function tests exact equality between the cursor and an end address calculated from the record:

**End address = stored beginning address + (unsigned second word logically shifted right by one).**

The record participates again in each boundary expression. The function does not explicitly preserve both fields as an immutable range snapshot.

For a stable unsigned second word \(n\), the nominal byte count is \(\lfloor n/2 \rfloor\):

- Zero and one both encode zero bytes.
- Two and three both encode one byte.
- Seven encodes three bytes.
- The largest 32-bit unsigned value encodes 2,147,483,647 bytes.

The low bit has no effect on this calculation. Its meaning elsewhere, if any, is unknown.

If the boundary comparison succeeds, the function returns before consuming another byte, evaluating the translation-base value for that byte, looking up a translated byte, or evaluating any recognition value.

The boundary test is equality, not an ordering or bounds check. It does not reject a cursor beyond the calculated end. Address overflow, invalid pointer arithmetic, and changes to the end address do not have a separately defined recovery path.

### Translation and rolling arithmetic

On a non-boundary iteration, a one-byte successor address is formed from the current cursor. The byte at the current cursor supplies an unsigned index from 0 through 255.

The translation lookup has three external dependencies:

- The current input byte.
- The externally stored translation-base address value.
- The byte at that base plus the unsigned input-byte index.

The translation-base value is referenced anew in the source expression for every consumed byte. There is no explicit invocation-wide snapshot of that value.

The expression does **not** establish whether the translation-base value or the input byte is evaluated first. Both are needed to determine the address of the translated-byte access. This dependency does not imply separate physical memory transactions or any particular machine instruction order.

The translated unsigned byte updates the rolling value according to:

\[
R_{\mathrm{new}}=(256R_{\mathrm{old}}+\text{translated byte})\bmod 2^{32}.
\]

After one through three bytes, the translated bytes occupy the populated low-order byte positions in consumption order, with the earliest byte most significant among those positions. After four or more bytes, the value contains only the most recent four translated bytes in that order.

The rolling value is never reset by a recognition transition.

A complete readable 256-byte translation region is sufficient for any input-byte index, provided the base remains suitable. Only reached entries are required for a particular invocation. Neither identity translation nor any character-folding behavior is established.

### First comparison group: evaluations and decision

Each updated rolling value first undergoes the K0–K2 comparison group. Its source-level external evaluations are more specific than a simple three-way membership test:

1. K0 is evaluated for an initial inequality comparison with the rolling value.
2. K0 is evaluated again unconditionally for a local assignment.
3. K1 is evaluated only if the initial inequality was true.
4. K2 is evaluated only if that initial inequality was true and the rolling value differs from the loaded K1 value.

The initial inequality result remains controlling; the second K0 evaluation does not replace it. The second K0 value does not affect recognition: when the initial comparison matched, later comparisons are short-circuited; when it differed, the assigned value is replaced by the K1 value.

After these conditional evaluations, the cursor is advanced to its previously formed successor. Thus the input byte and translated byte have already been read, and the first comparison group's external evaluations have already occurred, before that cursor assignment.

The group sets recognition state to decimal 97 if any of these conditions holds:

- The initial K0 comparison matched.
- The initial K0 comparison differed, but the loaded K1 matched.
- Both preceding comparisons differed, but the loaded K2 matched.

A successful group immediately continues to the next boundary test. K3–K7 are not evaluated on that iteration.

With stable comparison storage, the decision is equivalent to matching any of K0, K1, or K2. The repeated K0 evaluation remains part of the source-level access description even though its assigned value does not affect the decision. These evaluations do not prove that separately emitted machine loads exist.

### Remaining recognition priority

If the first group does not cause a transition, recognition proceeds in this order:

| Stage | Transition condition | Effect |
|---|---|---|
| K3 | Rolling value equals the evaluated K3, and state is 99 or 101 | Set state to 98; continue at the boundary test |
| K4–K6 | A reached comparison matches, and state is 99 | Set state to 101; continue at the boundary test |
| K7 | No earlier transition occurred, and the low 24 bits of the rolling value equal the complete K7 value | Return |
| No match | None of the preceding conditions takes effect | Preserve state; continue at the boundary test |

K3 is evaluated before its state eligibility is checked. A K3 mismatch bypasses the state test. A K3 match in an ineligible state does not prevent processing of K4–K6.

Within the K4–K6 group, both value-comparison order and state-dependent short-circuiting matter:

- K4 is evaluated first, before checking whether state is 99.
- If K4 matches and state is 99, the transition occurs without evaluating K5 or K6.
- Otherwise K5 is evaluated. A K5 match with state 99 suppresses K6.
- Otherwise K6 is evaluated.
- If state is not 99, all three values are evaluated once this group is reached, even though no transition from this group is possible.

A mismatch at any position makes that position fail without needing its state check. A match in an ineligible state also makes that position fail, so evaluation continues.

K7 is evaluated only when no earlier stage causes a transition. Merely matching K3 or K4–K6 in an ineligible state does not suppress the terminal comparison.

### State consequences

The only assigned states are 99 initially, followed by possible assignments of 97, 98, or 101.

- State 99 can become 97, 98, or 101.
- State 101 can become 97 or 98.
- State 98 can become 97.
- State 97 remains 97 until return.

These transitions remain subject to comparison priority. For example, a value matching both K0 and K3 takes the first-group transition to 97.

No transition restores state 99. Terminal recognition is possible in every state, but only on an iteration without a higher-priority transition.

The state is not directly exposed to the caller. It affects whether subsequent matches cause transitions or permit terminal recognition.

### Terminal comparison and termination

The terminal comparison masks only the rolling value:

\[
(R \mathbin{\&} \text{hexadecimal }00FFFFFF)=K7.
\]

K7 remains a complete 32-bit operand. Consequently:

- A stable K7 greater than 16,777,215 cannot match.
- Once three bytes have been consumed, the masked value represents the most recent three translated bytes.
- A match can occur after only one or two consumed bytes when K7 matches the corresponding zero-extended value.
- No terminal comparison occurs before the first byte.

On terminal return, the triggering byte has already been translated and incorporated, and the cursor has advanced locally. No subsequent input byte is consumed.

On a stable valid range without terminal recognition, the function consumes the encoded number of bytes and returns at the next boundary check.

## Side effects

There are no explicit external-memory writes. In particular, the function does not modify the record, input bytes, translation-base storage, translation bytes, or comparison values. Cursor, rolling-value, and recognition-state changes are local.

The established source-level access ordering is:

1. Initial cursor acquisition from the record.
2. Boundary-expression accesses to the record.
3. If not at the boundary, the input-byte and translation-base evaluations, without an established order between those two.
4. The selected translation-byte access and rolling-value update.
5. The first comparison group's K0 evaluation, unconditional second K0 evaluation, and conditional K1 and K2 evaluations.
6. Local cursor advancement.
7. Any reached K3, K4–K6, and K7 evaluations, with the short-circuit rules above.
8. Return or repetition from the boundary test.

The supplied expression does not establish an evaluation order between the two record-field reads within a boundary calculation.

## Acceptance examples

These are conditional static examples, not executed tests. Unless otherwise stated, all reached storage is readable, address arithmetic is valid, and external data remains stable. An “evaluation” below refers to the source representation, not necessarily a distinct emitted load.

1. **Empty encoded range.**  
   A second record word of zero or one causes the initial boundary comparison to succeed. No input byte, translation-base value, translation entry, or recognition value is evaluated afterward.

2. **Odd encoded length.**  
   A second word of seven yields three bytes. If terminal recognition never succeeds, exactly three input bytes are consumed before boundary return.

3. **Rolling truncation.**  
   If successive translated bytes are hexadecimal 11, 22, 33, 44, and 55, the rolling values are hexadecimal 00000011, 00001122, 00112233, 11223344, and 22334455, provided scanning reaches all five bytes.

4. **Initial K0 match.**  
   If the rolling value equals K0, K0 is nevertheless evaluated twice. K1–K7 are not evaluated on that iteration. State becomes 97, and scanning proceeds to the boundary test.

5. **K1 match after a K0 mismatch.**  
   K0 is evaluated twice, followed by K1. If K1 matches, K2 and all later recognition values are skipped, and state becomes 97.

6. **Complete first-group mismatch.**  
   If the rolling value differs from K0, K1, and K2, the evaluation sequence is K0, K0, K1, K2, followed by K3. The repeated K0 assignment does not introduce an additional matching opportunity.

7. **Eligible K3 suppresses later reads.**  
   With state 101 and no first-group match, a K3 match changes state to 98. K4–K7 are not evaluated, even if K7 would otherwise match the masked rolling value.

8. **Ineligible state still reaches all of K4–K6.**  
   With state 97 and no first-group transition, K3 cannot cause a transition. Once the next group is reached, K4, K5, and K6 are all evaluated, regardless of which values match. K7 is then evaluated.

9. **Eligible K4 suppresses K5 and K6.**  
   With state 99, no earlier transition, and a K4 match, state becomes 101. K5, K6, and K7 are skipped.

10. **One-byte terminal recognition.**  
    If the first translated byte is hexadecimal 2A, K7 is hexadecimal 0000002A, and no higher-priority transition occurs, the function returns after that byte. This does not require three consumed bytes.

11. **Out-of-range terminal value.**  
    If K7 is hexadecimal 01000000, terminal recognition cannot succeed. A stable valid bounded invocation ends at its boundary.

12. **Transition on the final byte.**  
    If the last available byte causes a recognition transition, the next boundary check returns without another input-byte or translation lookup. The final state is not reported.
