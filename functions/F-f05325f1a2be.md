# F-f05325f1a2be

The selection process can invoke F-5c41f627540d one, two, or three times. These invocations are distinct observations: the function does not obtain one value and clamp that same value to a range.

The supplied evidence does not establish the packed value’s downstream meaning, whether the second dependency emits anything, or what bit 8 represents.

## Behavior

### 1. Select a 32-bit word

The function first calls F-5c41f627540d with the context base and opaque argument.

After that call returns, it reads the first fallback word. This read occurs even when the first result will cause the function to continue into further dependency calls.

The first dependency result is interpreted as a signed 32-bit integer:

- If it is less than or equal to −4096, selection stops. The selected word is the first fallback word already read.
- If it is greater than −4096, the function calls F-5c41f627540d again with the same two argument values.

After the second call returns, the function reads the second fallback word. This read occurs regardless of whether the second result passes the next comparison.

The second result is interpreted as a signed 32-bit integer:

- If it is greater than or equal to 4096, selection stops. The selected word is the second fallback word.
- If it is less than 4096, the function calls F-5c41f627540d a third time with the same two argument values. The complete 32-bit result of this third invocation becomes the selected word.

No range check is applied to the third result.

Consequently, there is no established guarantee that the selected word represents a value between −4095 and 4095. Such a guarantee would require additional assumptions about the fallback words and the behavior of F-5c41f627540d.

In particular:

- A first result of 4096 still permits the second call because the first comparison checks only the lower boundary.
- A second result of −4096 permits the third call because the second comparison checks only the upper boundary.
- A third result at either signed extreme is accepted without further checking.

The fallback words’ contents are unknown. They must not be replaced in this contract with presumed clamp endpoints.

### 2. Form the magnitude-like word

The selected word is interpreted as signed 32-bit data for the sign decision.

- If its signed interpretation is nonnegative, the magnitude-like word is the selected word unchanged.
- If its signed interpretation is negative, the magnitude-like word is its unsigned 32-bit negation.

Unsigned negation is modulo \(2^{32}\). Thus:

- −1 produces `0x00000001`.
- −4096 produces `0x00001000`.
- The bit pattern `0x80000000`, representing the minimum signed 32-bit value, produces `0x80000000` again.

The minimum signed value is therefore not converted into a positive signed 32-bit value. The operation produces a 32-bit unsigned bit pattern.

There is no mask restricting this result to a nominal displacement or magnitude field.

### 3. Construct the packed argument

The packed argument is the bitwise OR of four contributions:

1. The magnitude-like word.
2. The unsigned byte read from state base + 12, widened to 32 bits and shifted left by 12 bit positions.
3. A sign-dependent contribution.
4. The fixed word `0xE50B0000`.

Under the arithmetic signed-right-shift interpretation expressed by the source’s sign construction, the sign-dependent contribution is:

- `0x00800000` for a nonnegative selected word, including zero.
- Zero for a negative selected word.

The effective fixed pattern is therefore `0xE58B0000` for nonnegative selections and `0xE50B0000` for negative selections, before OR-ing the other contributions.

The byte contributes to bits 12 through 19. Its full eight bits participate; it is not reduced to four bits. Several of those bits overlap bits already present in the fixed pattern.

These contributions are combined by OR, not by arithmetic addition or replacement of isolated fields. Overlap matters:

- A bit already set by the fixed pattern cannot be cleared by the byte.
- Magnitude bits can overlap the byte contribution, the sign-dependent contribution, or the fixed pattern.
- A negative selected word can still produce a final packed word with bit 23 set if its magnitude-like word supplies that bit.

The sign-dependent contribution alone therefore does not guarantee the final value of bit 23 for arbitrary selected words.

### 4. Call F-80812c986798

The function calls F-80812c986798 with two 32-bit arguments:

1. The word read from context base + 16.
2. The constructed packed word.

The context field and the state byte are both read after selection has completed and before this call begins. The supplied expression does not establish their relative evaluation order.

The context base itself is not the first argument to this dependency; the word stored at context base + 16 is.

No dependency return value is used.

### 5. Clear the state bit

After F-80812c986798 returns, the function reads the current 32-bit word at state base + 24. It clears bit 8 by AND-ing that word with `0xFFFFFEFF`, then writes the result to the same location.

All other bits from that particular read are preserved.

This is a post-call read-modify-write, not an update based on a snapshot taken before the call. Changes made by a dependency to this field before the final read can therefore affect the stored result.

The function then returns without a specified value.
