# F-403518fa0b76

## Purpose

The established observable behavior is an optional 16-bit memory copy followed by a nonterminating dispatch sequence. A narrowly constrained intermediate path can also perform a 16-bit indirect write and update an unidentified machine-state location.

No application-level purpose is established. The supplied representation contains extensive conditional arithmetic and pointer manipulation, but much of that material is unreachable under the consistent 32-bit interpretation described below. It does not establish a parser, allocator, serializer, or other higher-level service.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional deductions:** reachability and simplified behavior under a 32-bit, byte-addressed machine model.
- **documented_only unknowns:** calling convention, execution environment, exceptional behavior, and dependency effects not established by that material.

No runtime tests have been performed.

### Width and arithmetic model

The behavioral reductions below assume:

- Addresses and unsigned arithmetic values are 32 bits.
- Ordinary address arithmetic wraps modulo \(2^{32}\).
- A 16-bit unsigned load yields a value from 0 through 65,535.
- A 16-bit store retains the low 16 bits.
- Arithmetic through a 16-bit-element pointer advances two bytes per element.
- The Stack address is interpreted as an unsigned address for its logical right shift.

These assumptions match the widths suggested by the supplied representation, but the target ABI and instruction semantics were not independently supplied. They are not a claim that arbitrary pointer arithmetic has portable language-level meaning.

## Behavior

### 1. Initial copy decision

The copy occurs exactly when the low four bits of Selector are zero, under the 32-bit model.

When enabled, its observable memory order is:

1. Read one unsigned 16-bit value from Source address.
2. Write that value to the address formed by adding Displacement to Source address, in bytes.

The destination calculation wraps at 32 bits. This is a single-element transfer, not a buffer copy.

The function also derives an address-like value equal to the copy destination minus Adjustment. That calculation does not itself read or write the derived address.

When the copy is disabled, neither of these memory accesses occurs.

### 2. Conditional arithmetic and exceptional side path

Following the copy decision, the representation contains a sequence of zero-result gates. Their intermediate values are used as address-sized arithmetic values; merely forming them does not establish a memory access.

Under the stated 32-bit model, the only additional memory-writing path before dispatch requires all of the following:

- The copy is enabled.
- Link address is zero.
- Stack address is zero.
- Companion word equals Displacement.
- Displacement is either `0x00000000` or `0x80000000`.
- The updated address-like value, copy destination minus Adjustment, equals Adjustment modulo \(2^{32}\).
- Auxiliary word is zero.

The address equality can equivalently be expressed as:

\[
\text{Source address}+\text{Displacement}
\equiv 2\times\text{Adjustment}\pmod{2^{32}}.
\]

These conditions describe arithmetic reachability only. They do not guarantee that preceding or subsequent memory accesses succeed.

If this exceptional path is reached:

1. An unidentified machine-state location is assigned Stack address multiplied by 64. Under the conditions above, the assigned numeric value is zero.
2. A 16-bit value is obtained from Link address.
3. That loaded unsigned value is used as a zero-extended destination address.
4. A 16-bit value equal to the loaded value plus 15, reduced modulo \(2^{16}\), is written to that destination.

Because this path requires Link address to be zero, the 16-bit read is from address zero. The destination of the subsequent write is therefore somewhere in the first 65,536 bytes of the address space.

The representation uses the same 16-bit memory expression for the destination and stored-value calculations. It does not establish instruction-level read multiplicity or an ordering between those operand evaluations. The arithmetic result described here assumes stable ordinary memory; volatile, device-memory, or concurrent-change behavior is **documented_only**.

The initial copy precedes this path. If that copy changes memory at address zero, the exceptional path observes the resulting memory state rather than an automatically preserved entry value.

### 3. Reachability boundary for later represented operations

The representation includes further apparent pointer loads, signed 16-bit loads, paired wider stores, and address adjustments. Under the stated model, those operations are unreachable.

The relevant reasoning is:

- Entering the exceptional block requires Link address to be zero.
- An earlier zero gate then requires the logical right shift of Stack address by one to be zero, limiting Stack address to zero or one.
- A subsequent zero test adds Stack address to an even quantity modulo \(2^{32}\). Stack address equal to one cannot satisfy it.
- Therefore Stack address must be zero.
- On leaving the exceptional block, one address-like value has advanced by one 16-bit element, giving the numeric value two, while the other relevant zero-gated value remains zero.
- Their next required equality cannot hold.

If the exceptional block is not entered, the later operations likewise have no enabled path through the represented gates.

Consequently, a conforming interpretation of this 32-bit model must not perform the later apparent record reads or wider stores merely because they appear textually in the supplied material.

This is a conditional static deduction, not runtime proof. A different target-width or pointer-arithmetic interpretation requires reassessing it.

### 4. Repeating dispatch sequence

After the preceding operations complete, execution enters a loop with no represented normal exit.

Each iteration attempts these events in order:

1. Invoke an indirect target with three arguments.
2. If that invocation returns, invoke a second target with no explicit arguments.
3. If that invocation returns, issue software interrupt number `0x5B`.
4. If execution resumes after the interrupt, set the dispatch base to `0x083D4CC2` and begin another iteration.

The first invocation’s arguments are:

- First argument: 32-bit zero.
- Second argument: 32-bit zero.
- Third argument: the 32-bit pattern `0xFFFFFFA5`.

The third argument may be interpreted as signed −91 by a compatible callee, but its signedness and semantic meaning are not established.

On the first iteration, the first target address is:

\[
\text{Link address}+\texttt{0xEB6}\pmod{2^{32}}.
\]

On each iteration after a returning interrupt, that target is `0x083D5B78`.

The second target address is `0x0857A94B` on every iteration.

These are address calculations, not claims about symbol identity or whether a target-address bit has instruction-set significance.

There is no represented consumption of either invocation’s return value. There is also no represented recovery branch if a call, memory operation, or interrupt fails.

The absence of an exit does not guarantee unlimited execution: a target or interrupt may not return, transfer control elsewhere, or terminate execution.

## Side effects

### Memory

The function’s own established memory effects are:

- Zero or one initial 16-bit read and corresponding 16-bit write.
- On the exceptional path, a 16-bit read at address zero and a 16-bit indirect write derived from the loaded value.
- No reachable later record-oriented memory operations under the stated model.

The copy’s source and destination may alias. With zero Displacement, the read precedes a write of the loaded value to the same address. This can remain observable for device memory even though the numeric value is unchanged.

Partially overlapping two-byte regions are not handled specially. Endianness and alignment behavior are not specified.

## Acceptance examples

These are conditional acceptance criteria derived statically. They are not executed tests.

### Copy disabled

Given Selector equal to `0x00000001`, and assuming executable dispatch targets:

- No initial 16-bit copy occurs.
- The exceptional memory-writing path is not entered.
- The first attempted invocation is F-D01 at Link address plus `0xEB6`, with arguments `0`, `0`, and `0xFFFFFFA5`.

This example does not require Source address to be readable, because the represented function does not read it on this path.

### Copy enabled with ordinary dispatch

Given:

- Selector equal to `0x00000010`.
- Source address `0x00001000`.
- Displacement equal to 6.
- A stable 16-bit value `0x1234` at the source.
- A nonzero Link address.

The required memory order is a 16-bit read at `0x00001000`, then a 16-bit write of `0x1234` at `0x00001006`. The exceptional path is not entered. Dispatch follows if the accesses complete.

### Copy aliases its source

Given a copy-enabled Selector and zero Displacement, the function must read the source before writing the loaded value back to that same address. It must not omit the store solely because the addresses are equal.

### Exceptional low-address write

Assume an environment where address zero and stack address zero are meaningful, with:

- Selector zero.
- Source address `0x00002000`.
- Displacement and Companion word zero.
- Adjustment `0x00001000`.
- Auxiliary word zero.
- Link address and Stack address zero.
- A stable unsigned 16-bit value `0x0030` at address zero.

After the initial self-copy at `0x00002000`, the exceptional path assigns numeric zero to the unidentified machine-state location and writes `0x003F` as a 16-bit value at address `0x00000030`.

This is an arithmetic acceptance case, not evidence that an ordinary process can legally use such addresses.

### Repeated dispatch after returning dependencies

If both invocations return and interrupt `0x5B` resumes execution, the next first invocation targets `0x083D5B78`. The second invocation remains at `0x0857A94B`. The same three argument patterns are used for F-D01.

### Nonreturning dependency

If F-D01 does not return, F-D02 and interrupt `0x5B` are not reached during that iteration. The function provides no independent timeout or escape mechanism.
