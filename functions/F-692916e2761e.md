# F-692916e2761e

## Purpose

F-692916e2761e is a dispatcher-controlled wrapper around F-976b3710d232. Depending on global control values, it can capture thirteen caller arguments, write caller-supplied storage, prepare addresses for single-byte writes, prepare dependency arguments, invoke the dependency, and return a scaled result.

**Established static evidence:** Operations are selected using global reads. The supplied representation does not establish the global contents, a normal operation sequence, mandatory argument capture, mandatory dependency invocation, bounded write extent, or termination.

**Inferred intent:** The storage layout and argument rearrangement suggest preparation of a structured context. That interpretation does not establish a public object type, allocation size, initialization guarantee, or success convention.

This contract describes conditional behavior. Listing an operation does not establish that it is reachable during any particular invocation.

After each normally returning dependency invocation, the saved result is replaced by the product of the entry-time scale, a fresh post-call step read, and the dependency result, subject to the arithmetic qualifications below.

An explicit return operation or an unrecognized dispatch value returns the current saved result. A return before any completed dependency invocation therefore yields zero.

No success, failure, or error-code interpretation is established.

## Behavior

### Entry state and dispatch

The function first reads a scale global and retains that value for the invocation. It subsequently reads an initial selector.

Each dispatch iteration reads the step global and then selects an operation using the current selector plus a separately read dispatch bias. Recognized dispatch values are 0 through 14. Other values return the saved result. The step and bias reads therefore occur even on an iteration that returns immediately.

Invocation-local state initially contains:

- Zero-valued saved caller arguments and saved result.
- Two zero-valued, signed-looking 32-bit counters.
- A separate zero-valued unsigned 32-bit byte offset.
- A zero-valued prepared first dependency argument.
- A null working storage pointer.
- A null pending byte-write base.
- A distinct null active byte-write base.

The first counter is used for one arithmetic-control operation. The second counter is both an arithmetic input and an offset for one byte-store operation.

The pending base and active base are independent state. Selecting a storage-relative base changes only the pending base. Completing either arithmetic-control operation copies the pending base into the active base.

|---|---|
| 0 | Select pending base at storage byte offset 52. |
| 1 | Store a zero byte using the second counter as offset; update the first counter. |
| 2 | Perform the zero-word group; select pending base at offset 36. |
| 3 | Prepare a scaled caller-derived argument and perform arithmetic control. |
| 4 | Transition only. |
| 5 | Write a global-supplied word at storage offset 68. |
| 6 | Capture caller arguments. |
| 7 | Transition only. |

| 9 | Transition only. |

Most operations obtain the next selector from a global read after their work. Dispatch values 4, 7, and 9 only read their respective next-selector globals and continue.

The first-counter reset and first-counter update use the same next-selector global. The second-counter reset and second-counter update likewise share a next-selector global.

The operation numbers do not imply execution order. Capture need not precede storage access, pending-base selection need not precede activation, and return need not be reached.

### Argument capture and sampling

Capture refreshes the saved caller values and adopts argument 7 as working storage.

Dependency argument 9 is prepared using argument 3 and a **fresh read of the step global during capture**. The step value already read at the beginning of that iteration is not used for this product.

The following sampling points are distinct:

1. The step read at the beginning of every dispatch iteration.
2. The additional step read during argument capture.
3. The additional step read after a normally returning dependency call.

Their values cannot be equated without an external stability assumption.

Capture does not reset either counter, the unsigned offset, the prepared first dependency argument, either byte-write base, or the saved result. Replacing the working storage pointer does not rebase a previously selected pending or active base.

Within capture, the next-selector read follows the fresh step read and precedes assignment of the working storage pointer. Capture itself performs no caller-memory store.

### Byte stores and counter changes

Both byte-store operations write exactly one zero byte through the active base.

Dispatch 1 uses the current second counter as its signed-looking offset. After the store, it replaces the first counter with the product of the iteration’s cached step, the entry scale, and the sum of the previous first counter and that cached step.

Dispatch 12 uses the independent unsigned offset. After the store, it updates the second counter using the corresponding product of cached step, entry scale, and previous second counter plus cached step.

Each address is determined before its following counter update. Neither byte-store operation changes the unsigned offset.

The reset operations independently set the first or second counter to zero. They do not reset the unsigned offset, either base, or the prepared dependency argument.

These operations do not establish an increasing, consecutive, bounded, or terminating clearing loop. Offsets may repeat or become negative, and arithmetic may exceed the represented signed range.

The main product in each operation combines its selected counter with a shared global multiplier.

|---|---|---|
| Counter used for main product | First counter | Second counter |
| Prepared dependency argument 1 | Entry scale multiplied by saved caller argument 1 | Main product increased by 15, retained as a 32-bit value |

The prepared first dependency argument is not invariably caller-derived. It begins at zero and subsequently reflects whichever preparation operation most recently executed.

### Control decision and global sampling

Each arithmetic-control operation derives a signed 32-bit control result from:

- Its selected counter.
- The shared main-product multiplier.
- A second shared counter multiplier.
- An operation-specific additive global.
- Operation-specific inner and outer mask globals.
- Fixed arithmetic and bit-selection constants.

The calculation combines arithmetic with bitwise operations. It is not established as a simple counter comparison, length check, or range test. The control-result preparation does not directly depend on a selector sample. Entry scale and saved caller argument 1 affect other prepared state; they are not direct inputs to this control calculation.

This contract deliberately does **not** reproduce the nested control expression. Its exact input-to-sign predicate remains **documented_only**. Consequently, the contract specifies what happens for either control sign, but does not determine that sign for arbitrary counter and global values.

The relevant reads must not be merged into one global snapshot. In dispatch 3, the outer-mask read used to prepare the unsigned offset precedes the control calculation. That prepared offset also contributes to the control calculation; it is not replaced by another outer-mask read there. Dispatch 13 reads its outer mask within its own control calculation.

Reads within a compound calculation do not establish a total ordering among all operand reads. The two selector reads, however, have a visible sequence:

- Dispatch 3 first reads its selector global and prepares an alternative increased by 8. It then updates the second counter and reads the selector global again for the unadjusted alternative.
- Dispatch 13 first reads its selector global and prepares an alternative decreased by 8, then reads the same global again for the unadjusted alternative.

Under the represented arithmetic-right-shift interpretation, a negative control result selects the adjusted alternative; a nonnegative result selects the later, unadjusted sample.

Both selector reads occur regardless of the eventual selection. The alternatives differ by exactly 8 only when both reads return equal values and the relevant arithmetic has the assumed interpretation.

After selection, both operations copy the pending base into the active base. This activation is independent of the selected alternative, provided execution reaches the common completion.

## Acceptance examples

These are conditional static deductions, not runtime observations. Each assumes the stated operations are selected, required accesses are valid, and the illustrated arithmetic is representable under the applicable execution model.

1. **Immediate default return.** If the first selector-plus-bias value is unrecognized, the function returns zero after reading the entry globals and that iteration’s step and bias. It performs no caller-memory store or dependency call.

2. **Noncontiguous zeroing.** Capture followed by dispatch 2 clears the eight listed words, leaves offset 20 untouched by that operation, and selects pending offset 36. The active base remains unchanged.

3. **Selection without activation.** If the active base is address \(B\), selecting pending storage offset 52 leaves the next byte store based at \(B\). Completion of an arithmetic-control operation activates the pending base.

4. **Initially null active base.** Selecting pending offset 36 or 52 does not make a subsequent zero-offset byte store storage-relative. Without intervening activation, that store attempts the address derived from the null active base.

5. **Fresh capture sample.** With caller argument 3 equal to 3, iteration-start step equal to 5, and capture-time step equal to −2, dependency argument 9 is prepared as −6. The earlier sample of 5 does not determine this value.

6. **Two offset changes.** If dispatch 3 uses first counter 1, main multiplier 1, outer mask 2, entry scale 3, and saved caller argument 1 equal to 9, it prepares dependency argument 1 as 27, sets the second counter to 3, and sets the unsigned offset to 18. If the activated base is storage offset 52, a later dispatch-12 store targets storage offset 70. This example does not determine the control result’s sign.

7. **Distinct selector samples.** If dispatch 3 reads selector values 100 and then 200, its alternatives are 108 and 200. A negative control result selects 108; a nonnegative result selects 200. The example is conditional on the sign, not a specification of its exact predicate.

8. **Post-call sampling.** Saved values 17 and 29 are written at offsets 4 and 8 in that order. If the dependency returns 7, entry scale is 2, and the post-call step sample is 3, the saved result becomes 42. A subsequent return yields 42 unless another invocation replaces it. Preservation of the written fields by the dependency is unknown.
