# F-b5164379c09e

## Purpose

F-b5164379c09e searches an ordered, globally referenced record table and invokes a caller-selected callback on objects obtained through F-4506e248f6d1.

Its preferred result is a callback-accepted object associated with the greatest unsigned record key not exceeding a supplied limit. If that search leaves no nonzero selected object address, it scans the table again and accepts the first record whose callback returns a nonzero value, without applying the key limit.

Successful completion returns the selected object’s **unadjusted address**. Optional outputs receive that address, an associated 32-bit metadata value, and the low 16 bits of the callback result.

The greatest-key description expresses the behavior when records remain stable during execution and accepted object addresses are nonzero. Zero object addresses and mutation by dependencies introduce qualifications described below.

## Interface

The function has six inputs and one 32-bit return value. The supplied representation uses 32-bit integers and addresses, with a separate 16-bit output store.

| Input | Width and interpretation |
|---|---|
| Callback argument | Opaque 32-bit value passed as the callback’s second argument. |
| Key limit | Unsigned 32-bit value used by the preferred search. |
| Callback descriptor | 32-bit callable address or encoded dispatch offset, interpreted according to the adjustment descriptor. |
| Adjustment descriptor | 32-bit value combining a signed address adjustment with a dispatch-mode bit. |
| Optional pair output | Null or an address permitting two consecutive 32-bit stores. |
| Optional short output | Null or an address permitting one 16-bit store. |

The return value is a 32-bit object address, represented by a signed integer in the supplied signature. Zero means that the function did not reach its output-writing success path. A high-bit-set nonzero address is not rejected merely because its signed interpretation is negative.

### Table layout

A global location supplies the table’s starting address. A null starting address produces an immediate zero return.

Each record occupies 12 bytes:

| Byte offset | Content |
|---|---|
| 0 | Unsigned 32-bit key. |
| 4 | 32-bit address-like dependency argument; zero terminates traversal. |
| 8 | A third 32-bit field that this function does not read. |

The terminating record is identified by its field at offset 4, not by its key. There is no separate count or bounds check.

For a selected record, the function reads a 32-bit metadata value at byte offset 8 from the address stored in that record’s offset-4 field. This metadata is **not** the table record’s own third field.

### Dependency and callback interfaces

F-4506e248f6d1 receives:

1. The record’s nonzero offset-4 value, captured before the call.
2. The record key narrowed to its low 16 bits, interpreted as a signed 16-bit integer and sign-extended to 32 bits.

Its 32-bit result is treated as an object base address. The full unsigned key remains relevant to preferred-search eligibility and ranking; the narrowed signed key is used only as this dependency argument.

The callback receives:

1. An adjusted object address.
2. The unchanged opaque 32-bit callback argument.

Its result is interpreted as a 32-bit integer. Any nonzero result is acceptance; there is no positive-only restriction.

### Address adjustment and dispatch

The adjustment descriptor is first interpreted as signed 32-bit, then arithmetically shifted right by one. The resulting signed byte displacement is added to the object base address.

The descriptor’s low bit selects dispatch:

- **Low bit clear:** invoke the callback descriptor directly as a callable address.
- **Low bit set:** read a 32-bit word at the adjusted object address. Clear the callback descriptor’s low two bits and add the resulting value to the word just read. Read a callable address from that computed location and invoke it.

The adjusted address is the callback’s first argument in either mode. Neither the return value nor the first optional output is replaced with that adjusted address.

Address computations are expressed through 32-bit values. The supplied evidence does not establish portable behavior for invalid addresses, address-space wraparound, misalignment, or a target ABI different from the one represented.

## Behavior

### 1. Acquire the starting address

The function reads the global table reference once and retains the resulting starting address.

If it is null, the function returns zero without invoking F-4506e248f6d1 or the callback and without writing either optional output.

Changing the global reference during a dependency call does not redirect the retained starting address. Changes to the memory reachable through that retained address can affect subsequent reads.

### 2. Search records eligible under the limit

Beginning at the retained start, the function traverses records in increasing address order, advancing by 12 bytes.

For each record:

1. It reads the field at offset 4.
2. If that value is zero, the preferred traversal ends. The terminating record’s key is not needed for this decision.
3. Otherwise, it reads the full unsigned key and compares it with the unsigned limit.
4. If the key exceeds the limit, it advances without calling either dependency for that record.
5. If the key is eligible, it obtains the object base from F-4506e248f6d1, computes the adjusted address, resolves the callback if necessary, and calls it.

The key used for the dependency argument is read separately from the eligibility comparison. Consequently, the evidence does not establish a single atomic key snapshot.

A zero callback result cannot select the record.

For a nonzero callback result, selection occurs if either:

- The currently selected object base is zero; or
- The unsigned distance from the limit to the current key is strictly smaller than the saved best distance.

When selection occurs, the function saves:

- The unsigned distance.
- The 32-bit metadata read from the captured dependency-argument address plus 8.
- The unadjusted object base.
- The full 32-bit callback result.

The metadata read occurs after the callback returns and only when this record replaces the current selection.

Under stable records, unsigned eligibility ensures that subtracting the key from the limit does not underflow. Minimizing that distance chooses the greatest eligible key. Equal distances do not replace an existing nonzero selection, so the first accepted record at a tied key wins.

The preferred traversal continues through the sentinel even after finding an accepted candidate. Eligible records with worse keys still cause dependency and callback invocations.

### 3. Decide whether to use the fallback traversal

If the preferred traversal ends with a nonzero selected object base, the function proceeds to optional output writes.

If the selected base remains zero, the function restarts traversal at the retained table start.

The base address itself is the “selection present” indicator. A nonzero callback result paired with a zero object base therefore does not establish a successful preferred result. Such a record can temporarily update saved metadata, result, and distance, yet the selection still counts as absent. A later accepted candidate can replace it without satisfying the strict distance comparison.

### 4. Search without the key limit

The fallback traversal reads each record’s offset-4 field in table order until it encounters zero.

Every nonterminating record is evaluated, regardless of its full key:

- Obtain its object base from F-4506e248f6d1 using the same signed-16-bit key conversion.
- Compute the same adjusted address and dispatch.
- Invoke the same callback with the same opaque argument.

The first nonzero callback result stops this traversal. Before stopping, the function reads and saves metadata from the captured dependency-argument address plus 8, and saves the callback result.

Fallback acceptance is based on the callback result alone. After stopping, however, the function checks the corresponding unadjusted object base:

- A nonzero base proceeds to output writes and is returned.
- A zero base produces a zero return without output writes. The scan does not continue to later records.

If fallback reaches the sentinel without a nonzero callback result, the function returns zero without output writes. In particular, a nonzero base returned for a callback-rejected record does not become a successful return merely because it was the last base examined.

Eligible records rejected in the preferred traversal can be evaluated again in fallback. No result caching or duplicate-call suppression is present.

### 5. Write optional outputs

Only a nonzero final object base reaches this phase.

Writes occur in this order:

1. If the pair output is nonnull, write the unadjusted base to its first 32-bit slot.
2. Write the saved metadata to its second 32-bit slot.
3. If the short output is nonnull, write the low 16 bits of the saved callback result.

The function then returns the unadjusted base.

The short output is a truncation, not a Boolean normalization. For example, a callback result of 65,536 accepts a record but produces a short output of zero.

## Side effects

### Reads and calls

Directly established activity includes:

- One read of the global table reference.
- Sequential reads of nonterminating table records.
- F-4506e248f6d1 calls for evaluated records.
- Indirect reads for encoded callback dispatch, when selected.
- Callback invocations.
- Metadata reads when a preferred candidate replaces the current selection or a fallback callback accepts.

The preferred ranking reads the key after callback execution. When comparing against an existing nonzero selection and replacing it, the key is read for the comparison and again for saving the distance. No immutable record snapshot is established.

The offset-4 dependency argument is captured before calling F-4506e248f6d1. The later metadata read uses that captured address, even if a dependency changes the table record’s offset-4 field.

### Writes and aliasing

The function’s explicit data writes are limited to the optional outputs. It does not explicitly update the global table reference, table records, or object memory.

Dependencies may have additional effects. Their mutation, allocation, release, reentrancy, and ownership behavior are not established here.

The two optional output regions are not checked for overlap. If they overlap, the later 16-bit store can overwrite bytes previously written by a 32-bit pair-output store. Exact resulting byte interpretation depends on target byte order and overlap.

No output-pointer validation occurs. A nonnull output address must support its prescribed stores whenever success is possible.

### Ownership and lifetime

No explicit allocation, release, retain, or ownership transfer appears in this function. Its return value is an address supplied by F-4506e248f6d1, not evidence that the caller acquires ownership.

The caller and dependencies must provide readable table and dispatch memory, callable targets, and writable output storage as applicable. The function contains no recovery path for invalid memory or an invalid callable address.

## Acceptance examples

These examples are static contract cases, not executed tests. Except where stated otherwise, assume valid memory, stable records, successful callable dispatch, and nonzero object bases for accepted records.

### Preferred ranking and ties

Given table keys 4, 11, 9, and 11, a limit of 11, and nonzero callback results for all four records:

- All four records are evaluated in the preferred traversal.
- The first key-11 record is selected.
- The second key-11 record does not replace it.
- The returned address is that record’s unadjusted base.
- Metadata and the truncated callback result come from that selection.

### Greater key rejected by callback

Given keys 6 and 10 with limit 10, if the key-6 callback accepts and the key-10 callback returns zero, the key-6 record remains selected. Key proximity alone cannot override callback rejection.

### No eligible keys

Given keys 20 and 30 with limit 10:

- Neither record is evaluated in the preferred traversal.
- Fallback starts at key 20.
- If its callback accepts, key 30 is not evaluated.
- If its callback rejects, fallback evaluates key 30.

### Repeated evaluation

Given eligible records whose callbacks all return zero in the preferred traversal, fallback evaluates those records again in order. Callback behavior may differ on the second invocation; the function does not require repeatability.

### Signed narrowing differs from ranking

For key 65,535 and limit 65,535:

- The record is eligible under the unsigned comparison.
- F-4506e248f6d1 receives −1 as its second argument.

For key 65,536 and the same limit value of 65,536, the dependency receives zero. The preferred comparison still uses 65,536, not the narrowed value.

### Accepted result truncates to zero

If a selected callback returns 65,536 and the final base is nonzero, the function succeeds and writes zero to a nonnull short output. That output alone is not a success indicator.

### Zero base during fallback

If the first fallback callback returning nonzero corresponds to a zero object base, the function returns zero, leaves optional outputs unwritten, and does not try later records. This case assumes callback execution with the computed adjusted address is itself valid.

### Null or empty table

A null table start returns zero immediately. A nonnull table whose first offset-4 field is zero returns zero without dependency calls. Neither case writes optional outputs.

### Negative adjustment

An adjustment descriptor interpreted as signed −2 has a clear low bit and an arithmetic half of −1. It selects direct dispatch and passes an address one byte before the dependency’s returned base. The return value and pair output still use the unadjusted base.
