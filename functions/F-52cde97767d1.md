# F-52cde97767d1

## Purpose

F-52cde97767d1 conditionally inserts an opaque 32-bit value at the front of a selected word-based record. On the insertion path, it shifts existing words toward higher addresses, updates a metadata word, and transfers control to an unresolved indirect dependency with argument zero.

The apparent intent is to support two front-insertion collections behind a shared enable flag. This is inferred intent, not an established bounded-collection contract. The admission checks reject equality between count-like and limit-like fields; they do not reject every count exceeding a limit. Some admitted counts cause shifting to overwrite metadata or extend beyond the apparent record.

Record selection includes a significant observation-order requirement: after the enable gate, the global storage reference is observed once unconditionally. Selector `1` causes a second observation, and selection uses that second value plus 72 bytes. Other selectors retain the first observed value. The two observations are not required to agree.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Explicit inputs

| Input | Width and interpretation | Role |
|---|---|---|
| Value | Opaque 32-bit word | Written to word 0 of the selected record on insertion. |
| Selector | Signed 32-bit integer | Exactly `1` selects using a second observation of the storage reference plus 72 bytes. Every other value selects using the first observation without an offset. |

The value is copied without content validation. The function does not visibly dereference it. An address or handle interpretation, if applicable to callers, is not established here.

### Ambient inputs and storage layout

The function uses:

- A global reference through which it reads an enable byte.
- A global storage reference that supplies the record-selection base.
- An unresolved indirect control-transfer target.

The apparent record layout is:

| Word index | Byte offset | Observed role |
|---|---:|---|
| 0–15 | 0–60 | Apparent element storage |
| 16 | 64 | Count-like field |
| 17 | 68 | Limit-like field |

Each word occupies four bytes. The selector-dependent displacement is 18 words, or 72 bytes.

With a stable global storage reference, the two selectable record bases are therefore adjacent at a spacing of 72 bytes. If that reference changes between its two observations, selector `1` need not select a record adjacent to the first observed base.

The layout does not establish an allocation type, allocation size, alignment guarantee, or enforced storage boundary. Pointer width is not independently established.

### Return value

The result is a 32-bit word.

| Result | Condition |
|---|---|
| `1` | The observed enable byte is zero. |
| `4` | The first observation of the selected limit-like word is nonpositive as a signed 32-bit integer, or the subsequent equality comparison finds the captured count equal to a later observation of that limit-like word. |
| `3` | The initial limit test passes, the equality comparison finds different words, and the captured count is negative as a signed 32-bit integer. |
| Dependency result | Local insertion completes and the indirect dependency returns normally. |

No distinct successful-insertion status is established. The dependency may return any 32-bit result, including `1`, `3`, or `4`.

## Behavior

### Enable gate

The function first obtains the enable reference and reads the byte it addresses.

A zero byte produces an immediate return of `1`. This path does not observe the global storage reference, access either record, write record storage, or invoke the indirect dependency.

Any nonzero byte permits further processing; the byte need not equal one.

The enable reference must permit the byte read even when the operation is disabled. No null check or invalid-reference recovery is visible.

### Record selection and storage-reference observations

After the enable gate passes, selection proceeds in this source-level order:

1. Observe the global storage reference and retain that first value.
2. Determine whether the selector equals `1`.
3. For selector `1`, observe the same global storage reference again, discard the first value for selection, and use the address 72 bytes beyond the second value.
4. For every other selector, retain the first value as the selected record base, without another storage-reference observation in this selection sequence.

Thus, selector `1` uses the second observed reference, not necessarily the first reference plus an offset. No agreement between the observations is established.

These are two source-level observations on the selector-`1` path. The supplied representation does not establish whether they correspond to two distinct machine loads, nor does it establish volatile, atomic, or synchronization semantics.

Reading the first reference does not itself dereference the record it names. On the selector-`1` path, no record access through that discarded first value is visible.

Negative selectors, zero, and positive selectors other than one all use the first observed reference. There is no selector range check.

Once selected, the record base is retained for subsequent local record operations. No later refresh from the global storage reference is visible.

### Admission checks and read order

The selected record is examined in the following order:

1. Read word 17 and interpret it as signed 32-bit.
2. If that observation is zero or negative, return `4`.
3. Otherwise, read word 16 and capture its 32-bit value as the count.
4. Read word 17 again and compare that observation with the captured count.
5. If the words are equal, return `4`.
6. Otherwise, interpret the captured count as signed 32-bit. If negative, return `3`.
7. A nonnegative captured count proceeds to insertion.

The two observations of word 17 are not required to agree. The first must be positive to continue; the later observation is used for equality and is not independently required to be positive.

For stable fields, the admission rule simplifies to: positive limit, count different from limit, and nonnegative count. The actual observation sequence remains as stated above.

In particular, the function does not require the count to be less than the limit. A stable count greater than a positive limit is admitted when the two differ.

### Descending shift

Let \(n\) denote the captured count on an admitted path. Its signed interpretation is nonnegative.

For \(n=0\), the function performs no shift.

For \(n>0\), it shifts exactly \(n\) words one position toward higher addresses. The first operation reads word \(n-1\) and writes it to word \(n\). Subsequent operations proceed toward lower indices, ending with a read of word 0 and a write to word 1.

Each source read precedes its corresponding destination write. The descending order preserves the lower-index source words during an ordinary in-place shift.

After shifting, the supplied value is written to word 0.

For admitted counts from zero through fifteen, these writes stay within the apparent element region. Larger admitted counts are not specially protected:

- At \(n=16\), the first destination is word 16, so the shift overwrites the count-like field with the original word 15.
- At \(n\geq17\), the shift also writes word 17, replacing the limit-like field with the original word 16, absent external mutation.
- At \(n\geq18\), shift accesses extend beyond the apparent 18-word record.

The function performs no visible allocation, growth, bounds repair, or rollback.

The descending index arithmetic does not itself require signed overflow for an admitted count. Starting from a nonnegative signed 32-bit count, the successive decrements reach zero and then negative one, which terminates shifting. Address validity for large indices remains a separate requirement.

### Count-field update

After writing the supplied value to word 0, the function reads the then-current word 16, adds one, and writes the result to word 16.

The update is therefore based on the field’s contents after shifting, not necessarily on the captured count.

With stable storage and \(0\leq n\leq15\), shifting has not changed word 16, so the stored count becomes \(n+1\).

With stable storage and \(n\geq16\), shifting has replaced word 16 with the original word 15. The update increments that replacement value instead.

The update writes a 32-bit word. No saturation, overflow check, or overflow-specific return is visible. Low-32-bit wraparound is a machine-word interpretation; exact overflow semantics are not independently resolved by the supplied static representation.

### Indirect completion

After the count-field write, execution reaches the unresolved indirect dependency designated **F-indirect-01**.

Its visible argument is numeric zero. If it returns normally, its 32-bit result is returned without visible transformation.

The representation leaves the underlying control transfer unresolved. It does not establish the target’s identity, full calling convention, or whether the original machine transfer was an ordinary call.

All local record writes precede this transfer. No local rollback or recovery is visible if the dependency cannot be invoked, does not return, or modifies the same state.

## Side effects

### Local reads and writes

The fixed-result paths perform no explicit record writes and do not invoke F-indirect-01. Their reads differ:

- Disabled: only the enable-reference and enable-byte access sequence is needed.
- Enabled: the storage-reference observation sequence occurs before record admission checks.
- Nonpositive first limit observation: word 16 need not be read.
- Positive first limit observation: word 16 is read, followed by another observation of word 17.

The insertion path performs local writes in this order:

1. Descending shift writes, if the captured count is positive.
2. The supplied-value write to word 0.
3. A read and increment of the current word 16, followed by its write.
4. The indirect transfer.

These operations are not established as atomic. A fault partway through shifting can leave a partially modified record. A failure after insertion can leave the inserted value and metadata changes in place.

### Ownership and lifetime

The function visibly copies 32-bit words. It does not visibly allocate storage, release storage, clone an object, or dereference the inserted value.

This does not establish ownership of a pointer-valued word. Retention, transfer, release obligations, and required object lifetime remain unknown.

F-indirect-01 is not assumed to preserve globals, either record, backing storage, or objects represented by stored words. Its allocation and release behavior are unresolved.

### Access preconditions

Normal execution requires valid accesses for the path actually taken:

- The enable reference must permit its byte read.
- Enabled execution must permit the required observations of the global storage reference.
- The selected base must permit the applicable metadata reads.
- Insertion must permit all source and destination word accesses through index \(n\), as well as the word-16 update.
- The indirect transfer must be valid if reached.

For selector `1`, the first observed storage-reference value is discarded before record access. It need not itself identify accessible record storage merely to complete this function’s local selection behavior. The second observed value determines the selected address.

No visible checks validate alignment, storage extent, address arithmetic, or the indirect target. Invalid accesses are not assigned one of the documented numeric results.

## Acceptance examples

These are conditional static expectations, not runtime observations. Unless stated otherwise, references and record contents remain stable during the local operation, all accesses are valid, and the dependency’s effects are considered separately.

### Disabled operation

With enable byte zero, any value and selector produce result `1`.

The global storage reference is not observed. Neither record needs to be accessible for this branch alone.

### Selector-dependent observation sequence

For an enabled operation with selector `1`, suppose the first storage-reference observation yields address \(A\), and the second yields address \(B\).

The selected record begins at \(B+72\) bytes. It is not selected relative to \(A\). No record dereference through \(A\) is required.

For an enabled operation with selector `2`, selection uses the first observed address \(A\) directly. The selector-`1` second observation does not occur.

These expectations describe the source-level observations without requiring distinct machine loads.

### Stable reference and exact selector behavior

When the storage reference remains \(A\):

- Selector `1` selects \(A+72\) bytes.
- Selectors `0`, `2`, and `-1` select \(A\).

No selector directly chooses a third offset.

### Nonpositive limit takes precedence

With an enabled operation and a first signed observation of word 17 equal to zero or a negative value, the result is `4`.

Word 16 and a second observation of word 17 are not needed. No local record writes occur.

### Equality rejection

With stable limit `5` and count `5`, the result is `4`. There is no shift, insertion, or indirect invocation.

### Separate limit observations

Suppose the first observation of word 17 is `5`, the captured count is `1`, and the later observation of word 17 is `0`.

The admission checks permit insertion: the first observation was positive, the later observation differs from the count, and the count is nonnegative. A rule requiring the later observation to remain positive would add an unsupported check.

### Negative count

With stable limit `5` and count bit pattern `0xFFFFFFFF`, the count is signed-negative and differs from the limit. The result is `3`, with no local record writes.

### Empty record

With limit `5` and count `0`, there is no shift. The value is written to word 0, and word 16 becomes `1`.

F-indirect-01 is then reached with argument zero. If it returns `9`, the function returns `9`. State after that dependency executes cannot be specified without its contract.

### Ordinary insertion

With limit `8`, count `3`, and initial words \(A,B,C\), the local writes produce \(V,A,B,C\), where \(V\) is the supplied value.

Shift destinations are written in order 3, 2, 1. Word 0 is written next, and word 16 becomes `4` before the dependency is reached.

### Count greater than limit

With limit `2` and count `3`, insertion is admitted. The function shifts three words, inserts the value, and updates the count to `4`.

Rejecting this state solely because the count exceeds the limit would not match the visible behavior.

### Metadata overwrite

With limit `20`, count `16`, and original word 15 equal to `7`, insertion is admitted.

The first shift writes `7` to word 16. After shifting and insertion, the count-field update stores `8`, not `17`. Word 17 is not overwritten by this shift.

With limit `20` and count `17`, shifting also overwrites word 17 with the original word 16, namely `17`, before reaching the dependency.

## Evidence

The supplied static representation establishes:

- An initial enable-byte test returning `1` for zero.
- One unconditional storage-reference observation after that gate.
- A second storage-reference observation only for selector `1`, with selection displaced 18 four-byte words from that second value.
- Retention of the first observed reference for all other selectors.
- A signed-positive test of word 17, followed by capture of word 16 and another observation of word 17 for equality.
- Return `4` for failed positivity or equality admission, and return `3` for a subsequently detected negative count.
- Descending word copies, insertion at word 0, and an increment based on the current contents of word 16.
- An unresolved indirect transfer with visible argument zero and propagated result.

The 72-byte displacement, metadata-overwrite cases, and admission of counts greater than the limit follow from those operations.

No runtime testing, tracing, target recovery, or independent dependency analysis has been performed.
