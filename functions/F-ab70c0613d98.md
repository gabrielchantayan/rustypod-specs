# F-ab70c0613d98

## Purpose

F-ab70c0613d98 recognizes a small set of selector values and, for a recognized selector, writes one integer result to caller-provided storage. It returns a Boolean indicating selector recognition, not whether the written value is nonzero or whether a dependent operation succeeded.

The recognized selectors are:

- `0x368f`: obtain a dependency result and add three.
- `0x3695` and `0x369a`: return the integer stored at object offset `0xc4`.
- `0x36c0`: conditionally obtain a dependency result after examining two object fields and consulting another dependency.

For a normally completed recognized request, the output is written exactly once directly by this function and the return value is true. An unrecognized request returns false without a direct output write.

These are structural observations from the supplied representation. The semantic meanings of the selectors, object fields, and dependent operations are not established.

## Interface

### Inputs

The function has three inputs:

1. **Object address.** An integer-valued address used as the base of an object containing fields at fixed byte offsets. Only some selectors access this object.
2. **Selector.** An integer identifying the requested operation.
3. **Output address.** An address at which one integer result is stored for a recognized request.

The output address is not an input value source: this function does not directly read the integer already stored there.

### Output and return value

The return value is Boolean:

- **True:** the selector is recognized and execution reaches the final output store and return.
- **False:** the selector is not recognized.

A true return does not distinguish a successful dependent operation from a branch that deliberately produces zero. In particular, `0x36c0` can return true while writing zero because a field comparison failed or a dependency returned zero.

The integer result may be zero, positive, or negative. There is no visible range check on values copied from the object or obtained from dependencies.

## Behavior

### Selector dispatch

Selector handling proceeds without an initial output write. Zero is the default result for the conditional selector, but it is retained internally until the final store.

The first distinguished selector is `0x368f`. If the selector differs, the function distinguishes `0x3695` and uses a subtraction by `0x3600` to recognize `0x369a`. Remaining selectors are checked against `0x36c0`.

Subject to the arithmetic qualifications below, all selectors other than these four return false. They do not directly read the object, invoke a dependency, or write the output.

### Selector `0x368f`

The function:

1. Calls F-b99fc9942296 with no explicit arguments.
2. Adds three to its integer result.
3. Stores the resulting integer at the output address.
4. Returns true.

There are no direct object-field reads on this path.

The dependency runs before the final output write. If it can reach the output through some other reference, its effects are not constrained by this function’s visible interface. On normal continuation, the final store writes the calculated result regardless of earlier contents.

### Selectors `0x3695` and `0x369a`

For either selector, the function reads the integer-sized value at object offset `0xc4`, stores that value at the output address, and returns true.

No dependency is called. The field read precedes the output write.

The output may alias this field if the underlying memory and access rules permit it. In that case, the value is read before the store; the function does not first clear the output.

Although the result behavior is the same for these two selectors, their dispatch arithmetic differs: `0x3695` bypasses the selector subtraction, whereas `0x369a` is recognized through it.

### Selector `0x36c0`

This selector begins with an internally retained result of zero.

The function first reads the address-valued field at object offset `0xf0` and interprets it as a signed integer for branch decisions.

If that interpretation is negative:

- The field at offset `0xc4` is not directly read.
- Neither dependency used by this selector is called.
- Zero is written to the output.
- The function returns true.

If the interpretation is nonnegative, the function next reads the address-valued field at offset `0xc4`.

A dependency call is eligible only when the two captured field values satisfy both conditions:

- The value from `0xf0` is not equal to the value from `0xc4`.
- The signed value from `0xf0` is less than or equal to the signed value from `0xc4`.

Together with the earlier nonnegative requirement, this is equivalent to:

**The signed value from `0xf0` is nonnegative and strictly less than the signed value from `0xc4`.**

This is a signed comparison of captured address representations. It does not establish that either field points into a valid allocation, that both belong to the same allocation, or that the interval between them is readable.

If the comparison fails, the function writes zero and returns true.

If the comparison passes:

1. F-5836102a55c4 is called with the address at object offset `0xc0`.
2. If that dependency returns zero, no further dependency is called and the result remains zero.
3. If it returns any nonzero integer, F-2dd850db91b3 is called with no explicit arguments. Its integer return becomes the output result.
4. The selected result is written to the output address.
5. The function returns true.

A negative return from F-5836102a55c4 counts as nonzero and therefore enables F-2dd850db91b3.

There is no visible re-read of either captured object field after F-5836102a55c4. That dependency may nevertheless modify the object or other state; no preservation guarantee is available.

### Zero and signed-address edge cases

A zero value at offset `0xf0` is **not** an unconditional rejection.

Because zero is nonnegative, the function reads offset `0xc4` and uses the comparison between the two fields. If `0xc4` has a strictly positive signed value, the dependency path is eligible even though the first field is zero.

Under the inferred 32-bit model, a value with its high bit set has a negative signed interpretation. Such a value at offset `0xf0` suppresses the second field read and both dependency calls. A high-bit-set value at offset `0xc4` cannot exceed a nonnegative first value in the signed ordering.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid accesses, returning dependencies, and representable arithmetic unless otherwise stated.

1. **Unrecognized selector.** With selector `0x3600`, return false. Do not directly read object fields, call dependencies, or modify output.

2. **Adjusted dependency result.** With selector `0x368f`, if F-b99fc9942296 returns 10, write 13 and return true. No direct object read occurs.

4. **Direct field retrieval.** With either `0x3695` or `0x369a`, if the integer at offset `0xc4` is −7, write −7 and return true.

5. **Negative first field.** With selector `0x36c0` and a negative signed representation at offset `0xf0`, write zero and return true without directly reading offset `0xc4`.

6. **Equal fields.** With selector `0x36c0` and both comparison fields equal to a nonnegative value, call neither dependency, write zero, and return true.

7. **Descending fields.** With selector `0x36c0`, first field 200 and second field 100, call neither dependency and write zero.

8. **Zero first field remains eligible.** With selector `0x36c0`, first field zero and second field 100, call F-5836102a55c4 with object base plus `0xc0`. A blanket rule rejecting a zero first field would violate the observed behavior.

9. **Dependency rejects.** With eligible fields, if F-5836102a55c4 returns zero, do not call F-2dd850db91b3. Write zero and return true.

10. **Nonzero dependency return.** With eligible fields, if F-5836102a55c4 returns −1 and F-2dd850db91b3 returns 42, write 42 and return true.

11. **Zero from the final dependency.** With eligible fields and a nonzero first dependency result, a zero return from F-2dd850db91b3 is written as zero. The Boolean return remains true.
