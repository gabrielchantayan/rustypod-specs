# F-2884b93238c7

## Purpose

F-2884b93238c7 resolves a token through one of two paths:

- An ordered table lookup, returning the matched record’s 32-bit value and writing a dependency-derived quantity to an output location.
- A numeric conversion selected by a `#` byte at offset 1 of a dependency-provided byte region, returning the accumulated value and writing the offset at which forward scanning stopped.

The supplied representation establishes these operations, but not a complete token grammar. In particular, the function does not check offset 0, require a closing delimiter, enforce a maximum input length, or reject an empty numeric field.

The apparent intent is named-token and decimal/hexadecimal numeric-reference resolution. That intent is inferred. The actual scanning predicates, including their unusual acceptance of some non-digit bytes, govern this contract.

## Interface

### Inputs

The function has three arguments:

1. **An opaque 32-bit value.** No use of this argument is visible.
2. **An opaque 32-bit input handle.** It is passed to F-44362605ab79 and, during named lookup, to F-a21141daa905. Its representation and ownership are unknown.
3. **An output address for one 32-bit integer.** Numeric scanning writes this location repeatedly. A successful named lookup writes it once directly. An unsuccessful named lookup does not directly write it.

F-44362605ab79 returns a value used as the address of a byte region. All offsets below are relative to that returned address, not necessarily relative to the original input handle.

The representation uses 32-bit integers and four-byte pointer-like fields. Byte reads used for numeric processing are unsigned eight-bit reads. Address calculations use those 32-bit quantities.

### Return value

The return value is a 32-bit integer:

| Path | Return value |
|---|---|
| Named lookup succeeds | The selected record’s value field, read after the output write |
| Named lookup terminates without a match and offset 1 is still not `#` | `-1` |
| Numeric conversion | The accumulated numeric result, including zero when no positions contribute |

No separate status distinguishes a successful value of `-1` from lookup failure, or a valid numeric zero from an empty numeric field.

## Behavior

### Initial resolution and dispatch

The function first calls F-44362605ab79 with the second argument. It retains the returned byte-region address.

After that call, it reads a global table-base value and retains that base for subsequent table traversal. Consequently, changes made by F-44362605ab79 can affect the captured base. Later changes to the global table-base slot do not, by themselves, replace the retained base.

It then reads the byte at offset 1:

- If that byte is `#`, table lookup is skipped.
- Otherwise, it attempts ordered table lookup.

Offset 0 is neither inspected nor validated.

### Ordered named lookup

The table is traversed in records of 12 bytes, starting at index zero.

| Record offset | Width | Visible use |
|---|---:|---|
| 0 | 4 bytes | Not read by this function |
| 4 | 4 bytes | Dependency argument representing a name or key |
| 8 | 4 bytes | Integer value returned on a match |

For each record, the observable sequence is:

1. Read the four-byte field at record offset 4.
2. Call F-1cb585febd84 with that field.
3. If its result is zero, stop traversal.
4. Otherwise, read the field at offset 4 again.
5. Call F-a21141daa905 with the original second argument, the newly read field, and a third argument of zero.
6. If that result is nonzero, advance to the next 12-byte record.
7. If that result is zero, read the current record’s field at offset 4 again and call F-1cb585febd84 again.
8. Write that last dependency result to the output location.
9. Read the current record’s field at offset 8 and return it.

Zero from F-a21141daa905 selects a match. Zero from F-1cb585febd84 on the first call for a record terminates traversal before comparison.

The repeated field reads and dependency calls are significant. The function does not retain the first name-field value or reuse the first F-1cb585febd84 result as the output. If dependencies mutate the table, the calls can receive different values. The final F-1cb585febd84 result is written even if it differs from the earlier nonzero result.

The returned record value is fetched **after** the output write. An overlapping output location can therefore change the value ultimately returned.

When traversal terminates without a match, the function reads byte offset 1 again:

- If it is still not `#`, return `-1`.
- If it is now `#`, continue into numeric processing.

Thus, a dependency-induced change to that byte can switch a failed named lookup into numeric conversion. The retained byte-region address is reused; F-44362605ab79 is not called again.

### Numeric mode selection

Numeric processing reads the byte at offset 2.

- Lowercase `x` or uppercase `X` selects hexadecimal processing, beginning at offset 3.
- Every other byte selects decimal processing, beginning at offset 2.

Neither mode requires at least one digit. Neither mode consumes or validates a closing delimiter.

### Hexadecimal forward scan

For each examined position, the function first writes that position’s offset to the output location, then reads the byte at that position.

The forward scan accepts either:

- ASCII `0` through `9`; or
- Any byte in the inclusive ASCII range `A` through `f`.

That second interval is broader than the usual hexadecimal alphabet. It includes:

- `A` through `F`;
- `G` through `Z`;
- `[`, backslash, `]`, `^`, `_`, and the grave accent;
- `a` through `f`.

The first byte outside both intervals stops the scan. The output location has already been written with that stopping position’s offset.

For a stable, non-overlapping output and input, an immediately rejected byte at offset 3 leaves an output value of 3 and yields a numeric result of zero.

### Hexadecimal accumulation

After forward scanning stops, the function reads the output location back to obtain the stopping offset. It processes positions in reverse order, ending at offset 3.

The accumulator starts at zero. The positional multiplier starts at one.

For each position:

- `0` through `9` contribute values 0 through 9.
- `a` through `f` contribute values 10 through 15.
- `A` through `F` contribute values 10 through 15.
- Any other byte contributes nothing.

After every position, including a position that contributes nothing, the multiplier is shifted left by four bits.

Consequently, the extra bytes accepted by the forward scan occupy hexadecimal positions rather than being removed. For example, a stable field containing `1G2` produces the same positional result as `102`: the middle position contributes zero but still advances the multiplier.

The reverse pass rereads the bytes. It does not use a saved copy of the forward-scan observations.

### Decimal forward scan

For each examined position, the function writes the current offset to the output location before reading the byte.

The supplied representation tests the byte after subtracting the integer value of ASCII `0`, using a comparison against 10 without an explicit unsigned conversion in this forward-scan expression. Under the displayed byte type and ordinary integer promotion, this accepts **every byte from 0 through ASCII `9`**, not merely `0` through `9`.

Accordingly:

- ASCII decimal digits continue the scan.
- Bytes below ASCII `0`, including NUL, also continue the scan.
- A byte greater than ASCII `9` stops the scan.

This signedness-sensitive behavior is established at the supplied-representation level. Whether it exactly reflects the underlying executable’s comparison is documented_only; no instruction-level or runtime evidence was supplied.

A conventional NUL terminator is therefore not a safe stopping condition under the displayed expression.

The stopping offset is written to the output location before the stopping byte is read.

### Decimal accumulation

The function reads the stopping offset back from the output location, then processes positions in reverse order through offset 2.

The accumulator starts at zero and the positional multiplier at one.

At each position, it subtracts ASCII `0` and converts the result to a 32-bit unsigned quantity for the digit test:

- Values 0 through 9 contribute the corresponding decimal digit times the current multiplier.
- Every other value contributes nothing.

The multiplier is multiplied by 10 after every position, even when that position contributes nothing.

Thus, a low-valued non-digit accepted by the forward scan still occupies a decimal position. A slash followed by `2`, for example, contributes zero in the tens position and two in the units position.

### Arithmetic widths and limits

The visible accumulator and multiplier are 32-bit quantities. There is no wider accumulator, overflow check, saturation, or numeric-range error.

Hexadecimal processing repeatedly shifts the multiplier left by four bits. Decimal processing repeatedly multiplies it by 10. Scan indices and table indices also use 32-bit integer arithmetic.

For values and intermediate operations within their representable ranges, the positional behavior above is directly established. For overflow cases, the representation contains a mixture of signed quantities, unsigned expressions, and signed shifts. A portable modulo-\(2^{32}\) contract cannot be derived uniformly from this representation alone. Exact overflow results are documented_only.

## Side effects

### Direct writes

The only explicit writes by this function are to the supplied output location:

- One write on successful named lookup.
- One write before every forward-scan byte read in numeric mode, including the stopping read.
- No direct write on named lookup failure that returns `-1`.

The numeric result itself is returned, not written to that location.

The output is therefore not simply a success-only result. It exposes scan progress through repeated stores. The function subsequently reads that same location to determine the reverse-pass starting point.

### Reads and ordering

Observable reads include:

- One global table-base read after F-44362605ab79 returns.
- Byte offset 1 before dispatch, and again after unmatched table termination.
- Byte offset 2 to select numeric mode.
- Forward-scan byte reads after corresponding output writes.
- Reverse-pass byte reads in descending address order.

These orderings matter when storage aliases or dependencies mutate shared state.

There is no explicit null check, bounds check, malformed-input exception, or recoverable memory-access error path. Invalid addresses or an unterminated scan can lead to invalid memory access rather than a reported parse failure.

Dependency side effects are unknown. In particular, none is assumed to preserve global state, table contents, the byte region, or the output location.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume valid disjoint storage, stable byte contents, no dependency mutation, a valid table, and no arithmetic overflow. Quoted byte sequences begin at offset 0.

1. **Decimal field with an explicit stopping byte.**  
   For `&#12;`, numeric mode is decimal. Offsets 2 and 3 are accepted; `;` stops the scan at offset 4. The function returns 12 and leaves 4 in the output.

2. **Unchecked first byte.**  
   For `Q#12;`, the result is also 12 with output 4. The first byte is not required to be `&`.

3. **Empty decimal field.**  
   For `&#;`, the byte at offset 2 immediately stops decimal scanning. The function returns zero and leaves 2 in the output.

4. **Ordinary hexadecimal field.**  
   For `&#x1Af;`, the function returns 431 and leaves 6 in the output. Uppercase `X` selects the same mode.

5. **Empty hexadecimal field.**  
   For `&#x;`, the function returns zero and leaves 3 in the output.

6. **Non-hexadecimal letter accepted as a position.**  
   For `&#x1G2;`, the scan accepts `G`. The reverse pass gives it no contribution but retains its position. The function returns 258 and leaves 6 in the output.

7. **Low-valued decimal non-digit.**  
   Under the displayed decimal comparison semantics, `&#/2;` returns 2 and leaves 4 in the output. The slash occupies a zero-contribution tens position.

8. **NUL after decimal digits.**  
   If `&#12` is followed by NUL, no result may be asserted from those bytes alone. Under the displayed decimal expression, scanning continues past NUL until a byte greater than ASCII `9` is read.

9. **Named match.**
