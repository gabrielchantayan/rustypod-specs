# F-78db0cbe9071

## Purpose

F-78db0cbe9071 conditionally processes an entry selected from a supplied container, passes temporary storage to dependencies, and performs operations involving a retained destination.

The function calls F-151ab4bfe553 at most twice. Separately, it calls F-efdae002d289 once whenever entry processing reaches that stage. Consequently, the fully enabled path makes **three calls with the retained destination as an argument**: two to F-151ab4bfe553 and one to F-efdae002d289.

Entry processing requires a successful signed index comparison followed by a nonzero word obtained through an indirect dependency. The result of F-efdae002d289 determines whether the final F-151ab4bfe553 call occurs.

The return value is a 64-bit concatenation of two local words initially copied from the second and first arguments, respectively. The return uses their current contents, not necessarily their initial values. Dependencies receive addresses of local storage, and their write footprints are unknown.

These are structural semantics. Application-level interpretations such as assignment, comparison, conversion, destruction, or fallback handling are not established.

## Interface

### Arguments

The function accepts four 32-bit arguments.

| Argument | Established use |
|---|---|
| First | Copied into a local word whose address is later passed to dependencies. Its current contents supply return bits 31–0. |
| Second | Used as a container address and interpreted as a signed 32-bit value in the supplied representation. Also copied into a local word whose current contents supply return bits 63–32. |
| Third | Interpreted as a signed 32-bit index for the bound comparison and indirect call. Also copied into local storage whose address is passed to dependencies. |
| Fourth | Copied into a local word. That word is read after F-b9acea4b06ad returns and supplies the second argument of the first possible F-151ab4bfe553 call. |

The original second and third arguments supply the container address and index used for selection. Those uses are distinct from later reads of the initialized local storage.

### Local storage and exposure

The supplied representation places the first-initialized word immediately before the second-initialized word. It likewise places the third-initialized word immediately before the fourth-initialized word.

This placement does not establish complete temporary-object boundaries:

- F-b9acea4b06ad receives the third-initialized word’s address. Its valid write extent, including whether it can affect the neighboring fourth-initialized word, is unknown.
- F-398e0e9a318a and F-289ec4311c64 receive the first-initialized word’s address. Preservation of the neighboring second-initialized word is not established.
- A dependency receiving one of these addresses is not thereby restricted to reading or writing a single 32-bit word.

The local storage remains available during the visible calls. No post-return lifetime guarantee or permission to retain its addresses is established.

### Container and dispatch layout

Only the following container-relative fields are established:

| Offset | Access width | Role |
|---|---:|---|
| +0x18 | 32 bits | Dispatch-table pointer for an embedded object beginning at this offset. |
| +0x1c | 32 bits | Signed bound for the index comparison. |

The indirect callable is obtained from dispatch-table offset +0x40. It receives the embedded-object address, container address plus 0x18, followed by the original index.

Its result is treated as an address of a readable 32-bit word. That word is tested for zero. On the nonzero path, it is read again for a subsequent argument calculation.

The representation uses 32-bit address-bearing values. It does not establish a portable interface for another pointer width.

### Return value

On normal completion:

- Bits 63–32 contain the current second-initialized local word.
- Bits 31–0 contain the current first-initialized local word.

This is bit concatenation. A high bit set in the low word does not sign-extend into the upper half.

No dependency result is directly returned as a status. In particular, F-efdae002d289 supplies a branch condition, not the function’s return value.

### Preconditions

Safe execution requires valid accesses and compatible dependency invocations on the path actually reached. These requirements include:

- A readable 32-bit bound at container offset +0x1c.
- On a successful index comparison, a readable dispatch pointer and callable slot.
- A compatible indirect-call target.
- A readable 32-bit word at the indirect target’s returned address.
- Storage, alignment, object extent, lifetime, and aliasing conditions required by each reached dependency.

There is no explicit null check, nonnegative-index check, or validation of the selected word’s use as an address-bearing value. Additional dependency requirements remain **documented_only**.

## Behavior

### Initialization and destination acquisition

The function first initializes four local words from the four arguments.

It then calls F-5b24edfb22c0 without explicit arguments and retains its result as the destination. This call occurs before the container-bound read, including on paths that subsequently skip all entry processing.

The destination is obtained once. Later changes to global state do not cause this function to reacquire it.

### Signed index gate

After destination acquisition, the function reads the signed 32-bit bound at container offset +0x1c. It compares the original third argument against this bound using strict signed less-than.

If the comparison fails, execution proceeds to return assembly. No dispatch lookup, indirect entry call, or subsequent processing dependency is reached.

Consequences include:

- An index equal to the bound fails the gate.
- A negative index can pass.
- A negative bound is interpreted as negative, not as a large unsigned capacity.
- There is no separate lower-bound requirement.

The bound is observed after F-5b24edfb22c0 returns. Its value cannot be assumed to equal a value present before that dependency ran.

### Indirect selection and selected-word reads

If the gate succeeds, the function:

1. Obtains the dispatch-table pointer from container offset +0x18.
2. Obtains the callable from table offset +0x40.
3. Calls that target with the embedded-object address and original index.
4. Reads a 32-bit word at the returned address and tests it for zero.

A zero tested word skips the remaining entry-processing sequence and leads to return assembly.

A nonzero tested word enables another read from the same selected-word address. Four is added to this second read’s value for the second argument to F-b9acea4b06ad.

The argument is not established as using a saved copy of the tested value. The source representation contains two reads. Whether those reads can differ in a supported execution environment remains unresolved.

The addition operates on a 32-bit value represented as signed. There is no visible overflow or address-range check. Portable wraparound behavior at signed-overflow boundaries is not established.

### Third-initialized storage and first destination operation

F-b9acea4b06ad receives:

- The address of the third-initialized local.
- The selected word’s second-read value plus four.

After that dependency returns, the retained destination is compared with the third-initialized local’s address.

If the addresses differ, F-151ab4bfe553 is called with:

- The retained destination.
- The current contents of the fourth-initialized local.

If the addresses are equal, this F-151ab4bfe553 call is skipped.

The fourth-initialized local is read after F-b9acea4b06ad has received the neighboring local’s address. Its argument value therefore cannot be specified unconditionally as the original fourth argument.

The function then calls F-289ec4311c64 with the third-initialized local’s address. This call occurs whether the first destination operation ran or was skipped, provided preceding operations completed normally.

### First-initialized storage and destination-dependent condition

Next, F-398e0e9a318a receives:

- The address of the first-initialized local.
- A fixed data address.

The fixed data’s contents and application-level role are unavailable. Passing its address does not establish its mutability or ownership.

The 32-bit result of F-398e0e9a318a becomes the second argument to F-efdae002d289. The first argument is the retained destination.

After F-efdae002d289 returns, its result is retained while F-289ec4311c64 is called with the first-initialized local’s address. Only after that call completes does the function test the retained result for zero.

Thus, F-efdae002d289 is itself a destination-bearing call, regardless of whether either F-151ab4bfe553 call occurs.

The address-taking calls in this stage can affect the eventual return storage. Neither preservation of the first-initialized word nor preservation of its neighboring second-initialized word is established.

### Conditional final destination operation

A zero F-efdae002d289 result skips the final sequence. Any nonzero 32-bit result enables it, including a value interpreted as negative.

On the enabled path:

1. F-9d0ecc5f6adf is called without explicit arguments.
2. Its 32-bit result supplies the first argument to F-5710a8628cba.
3. Two 32-bit words from distinct fixed data locations supply that dependency’s second and third arguments in their respective positions.
4. F-151ab4bfe553 is called with the retained destination and the 32-bit result of F-5710a8628cba.

The two fixed-word locations are distinct from the fixed address passed to F-398e0e9a318a. Their relative read order is not established.

These reads occur for the F-5710a8628cba invocation after F-9d0ecc5f6adf returns. Their values must not be assumed to remain unchanged across earlier dependency calls.

There is no destination-versus-temporary equality guard on this final F-151ab4bfe553 call.

### Return assembly

After the selected path completes, the current second-initialized word is concatenated above the current first-initialized word.

The function contains no explicit later assignment to the second-initialized word. That absence does not prove preservation: neighboring storage has been exposed to dependencies with unknown write footprints.

## Side effects

### Visible effects and call counts

The visible body initializes local words, reads container and selected-entry storage, reads fixed data, and invokes dependencies. It contains no explicit store into the container, selected entry, retained destination, or fixed data.

On a normally completing active path:

- F-efdae002d289 receives the retained destination exactly once.
- F-151ab4bfe553 receives it zero, one, or two times.
- Therefore, the total number of these destination-bearing calls is one, two, or three.

The three-call case requires both an unequal destination-versus-temporary comparison and a nonzero F-efdae002d289 result. If entry processing is skipped, none of these destination-bearing calls occurs, although destination acquisition still occurs.

### Dependency-mediated state and ownership

Dependencies may have externally visible effects not described by the supplied body. Their mutation, allocation, release, retention, synchronization, and global-state behavior are unknown.

The positions of the F-289ec4311c64 calls suggest finalization of temporary storage, but do not establish destruction, deallocation, reference-count changes, or ownership release.

There is no explicit deallocation of the destination, the indirect target’s returned address, or any resource represented by the selected word. This does not establish whether dependencies release or retain those resources.

No unknown dependency is assumed to preserve globals, fixed data, container state, selected-entry state, or neighboring local words. Conversely, the supplied body does not prove that any particular dependency changes them.

### Errors and abnormal completion

There is no visible error-status convention, exception handler, rollback, retry, or explicit validation-failure report.

If an access fails or a dependency does not return normally, later operations are not guaranteed. The F-289ec4311c64 calls are therefore not established as unconditional cleanup.

Failure of the signed gate and a zero selected word are ordinary control-flow outcomes in this representation, not explicitly classified errors.

## Acceptance examples

These examples are conditional specifications, not executed tests. Each assumes valid reached accesses and normal dependency completion.

1. **Equal index and bound.** With index 7 and a bound observed as 7, destination acquisition occurs, but entry selection does not. If the return-source words retain first argument 0x11223344 and second argument 0x00102030, the return is 0x0010203011223344.

2. **Negative index passes.** With index −1 and observed bound 0, the gate succeeds and the indirect dependency receives −1. Introducing an additional nonnegative-index requirement would change the established behavior.

3. **Zero selected word.** With index 2 and bound 3, suppose the indirect dependency returns a readable address whose tested word is zero. No subsequent processing dependency is called, including F-efdae002d289 or either F-151ab4bfe553 invocation.

4. **Post-call fourth-word value.** Suppose the selected word’s second read is 0x00004000. F-b9acea4b06ad receives 0x00004004. If the destination differs from the third-initialized local’s address and the fourth-initialized word subsequently contains 0x55667788, the first F-151ab4bfe553 call receives 0x55667788, irrespective of the incoming fourth argument.

5. **Three destination-bearing calls.** Suppose entry processing is enabled, the destination differs from the third-initialized local’s address, and F-efdae002d289 returns nonzero. The destination is passed first to F-151ab4bfe553, then to F-efdae002d289, and finally to F-151ab4bfe553 again.

6. **Equality skips only the first destination operation.** If the destination equals the third-initialized local’s address, the first F-151ab4bfe553 call is skipped. F-efdae002d289 still occurs. A nonzero result still enables the final F-151ab4bfe553 call.

7. **Zero versus negative condition.** A zero F-efdae002d289 result prevents the final sequence. A result represented as −1 enables it. In either case, the second F-289ec4311c64 invocation precedes the condition test.

8. **Current return storage.** If the second-initialized word contains 0x12345678 and the first-initialized word contains 0xaabbccdd at return assembly, the result is 0x12345678aabbccdd, even if either word differs from its initial value.

## Uncertainties

The following remain **documented_only**:

- Application-level meanings of the arguments, container, destination, fixed data, and return fields.
- Complete local-object layouts and dependency read/write footprints.
- Preservation of the fourth-initialized word after neighboring storage is exposed.
- Preservation of both return-source words during dependency execution.
- Ownership, allocation, release, retained-pointer permissions, and lifetime rules.
- Dependency failure, exception, synchronization, and global-state behavior.
- Whether differing selected-word reads are possible in a supported environment.
- Overflow and address-boundary behavior for the visible 32-bit calculations.
- Relative ordering of the two fixed-word reads for F-5710a8628cba.
- Target-specific alignment and calling-convention requirements.

**Inferred intent:** the address-taking calls followed by F-289ec4311c64 suggest temporary-object processing. The F-151ab4bfe553 calls suggest destination updates. Neither inference establishes required semantics, object extent, or ownership.

## Evidence

Established behavior derives from static inspection of the supplied function representation and opaque dependency mapping: argument widths, local initialization and placement, signed comparison, container and dispatch offsets, selected-word reads, address-equality guard, argument positions, dependency-call order, and 64-bit concatenation.

The destination appears explicitly as an argument in two possible F-151ab4bfe553 calls and in the intervening F-efdae002d289 call. This establishes three destination-bearing calls on the fully enabled path, while retaining the two-call maximum specifically for F-151ab4bfe553.

Dependency implementations, complete temporary-object layouts, and fixed-data contents were not supplied. Their effects and preservation guarantees remain unresolved.
