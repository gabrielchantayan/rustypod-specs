# F-c9ee018573ab

## Purpose

F-c9ee018573ab processes the low 17 bits of a requested-event mask against three recipient slots. For each requested bit, it examines recipients in ascending slot order:

- If a recipient’s eligibility word does not contain that bit, the function sets the corresponding bit in that recipient’s pending word.
- If the eligibility word contains that bit, the function constructs a temporary event payload, invokes a dependency chain, and clears the corresponding pending bit afterward.
- A nonzero result from the final dependency stops further processing, but only after the current recipient’s pending-bit clear has been written.

This establishes a bit-oriented notification mechanism. Describing the words as “eligibility” and “pending” is inferred intent; their offsets, bit operations, traversal order, and dependency interactions are established static behavior.

The function does not expose a return value. Its externally visible effects are memory updates and dependency calls.

## Behavior

### Event and recipient order

The function traverses event indices from 0 through 16, inclusive. Each event corresponds to the 32-bit mask containing only that index’s bit.

For an event whose bit is absent from the requested-event mask, the function performs no recipient-word access or dependency call for that event.

For an event whose bit is present, it traverses recipient slots 0, 1, and 2 in that order, unless a preceding eligible-recipient operation has produced a nonzero continuation status.

Consequently, traversal is event-major, not recipient-major. In a run without early termination, all three slots for a lower requested event index are processed before any slot for a higher requested event index.

The largest generated bit is bit 16. The shifts do not approach or exceed the 32-bit operand width. Although the supplied expression masks the shift count to eight bits, the actual loop range remains 0 through 16.

### Ineligible recipient

For the current recipient and requested event, the function first reads the recipient’s eligibility word.

If the event bit is clear in that word:

1. It reads the recipient’s pending word.
2. It forms a new word by setting the current event bit.
3. It writes that new word to the same pending-word address.

There is no dependency call on this branch.

Other bits in the pending word are preserved relative to the value read by this operation. The store still occurs when the event bit was already set.

This branch does not reread eligibility after deciding that the event is ineligible.

### Eligible recipient

If the event bit is set in the eligibility word, the function performs the following observable sequence:

1. It reads the descriptor-table base and determines the current event’s 12-byte descriptor address.
2. It writes the event index, narrowed to one byte, into the first byte of a temporary payload region.
3. It invokes F-U01 with:
   - the address immediately after that first payload byte;
   - the descriptor’s 32-bit field at offset 4;
   - the descriptor’s byte at offset 8.
4. After F-U01 returns, it reads the descriptor byte at offset 8 again and retains that value for the later length calculation.
5. It invokes F-U02 without explicit arguments.
6. It invokes F-b37968c9f644 with:
   - the F-U02 result advanced by four bytes;
   - the current recipient index, represented in 32 bits.
7. It invokes F-cd7e1905512f with six arguments:
   - the result from F-b37968c9f644;
   - zero;
   - three;
   - nine;
   - the address of the temporary payload’s first byte;
   - the retained descriptor byte, interpreted through the supplied character representation, plus one.
8. It invokes F-256e8a77aa59 with the result from F-cd7e1905512f and a second argument of zero.
9. It retains the result of F-256e8a77aa59 as the continuation status.
10. It reads the current recipient’s pending word, clears the current event bit, and writes the resulting word back.

The relative evaluation order of the descriptor’s two field reads used as arguments to F-U01 is not established. Both supply that call; the separate read of the offset-8 byte occurs after the call.

The pending word is read only after the entire dependency chain returns. Thus, pending-word changes made by dependencies before that read are included in the final read-modify-write. The function does not restore a pre-call pending-word snapshot.

The clear is unconditional with respect to the final dependency’s result. A nonzero result stops subsequent work but does not prevent the current clear.

### Stopping behavior

The continuation status begins at zero. Only the eligible-recipient dependency chain replaces it with the result from F-256e8a77aa59.

A zero result permits processing to continue with the next recipient, or with the next requested event after recipient 2.

A nonzero result prevents all subsequent recipient and event processing. Before termination, however, the pending-word clear for the operation that produced that result is completed.

The function also terminates normally after event index 16 has been considered.

## Side effects

### Direct memory effects

The function directly:

- Reads the recipient-state base global once at entry.
- Reads eligibility words for visited recipient-event combinations.
- Reads and writes the corresponding pending words.
- Reads the descriptor-table base and descriptor fields on eligible branches.
- Writes the event-index byte in temporary storage.

It does not directly modify eligibility words or the descriptor table.

For each visited recipient-event combination, one pending-word store occurs if execution reaches the end of that branch. This includes stores whose resulting value equals the prior value.

Bits outside the current event bit are preserved by each individual pending-word transformation. That guarantee is relative to the value read immediately before the store, not necessarily to the value at function entry.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, dependencies return normally and do not mutate the recipient state or descriptors.

### No supported event requested

With a requested-event mask of zero, the function reads the recipient-state base but performs no eligibility-word access, pending-word access, or dependency call.

The same behavior applies when only bits 17 through 31 are set.

### One requested event, no eligible recipients

If only event 4 is requested and bit 4 is absent from all three eligibility words:

- Pending bit 4 is set for recipients 0, 1, and 2, in that order.
- Other pending bits are preserved by each update.
- No dependency is invoked.

An already-set pending bit remains set, but its word is still written.

### One eligible recipient followed by ineligible recipients

If only event 2 is requested, recipient 0 is eligible, recipients 1 and 2 are ineligible, and F-256e8a77aa59 returns zero:

- Recipient 0’s dependency chain runs first.
- Its payload-leading byte is 2.
- Its pending bit 2 is cleared after the chain.
- Recipients 1 and 2 then have pending bit 2 set.

### Early termination after an eligible recipient

If recipient 0 is ineligible, recipient 1 is eligible, and recipient 1’s final dependency returns nonzero:

- Recipient 0’s pending bit is set.
- Recipient 1’s dependency chain runs and its pending bit is cleared.
- Recipient 2 is not examined.
- No higher event index is processed.

There is no rollback of recipient 0’s update.

### Multiple requested events

If events 1 and 6 are requested and all continuation results are zero, the function processes recipients 0, 1, and 2 for event 1 before beginning event 6.

Events 2 through 5 cause no recipient processing.

### Pending-state mutation during a dependency

If a dependency sets an unrelated bit in the current pending word, and that value remains present until the function’s post-call read, the subsequent clear preserves that unrelated bit while clearing the current event bit.

### Descriptor-byte mutation

If F-U01 changes the selected descriptor’s offset-8 byte from 5 to 7, the later length calculation uses 7 and therefore yields 8. The earlier F-U01 invocation received the value read for its own argument, not the later reread.
