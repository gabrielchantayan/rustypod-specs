# F-6f809112d043

## Purpose

F-6f809112d043 attempts to construct an output byte sequence by scanning a retained source address and substituting replacement spans for accepted search matches. It has no explicit return value. Completion is exposed through a dependency call receiving the output address, payload length, context, and metadata.

Under stable-input, non-aliasing, conventional comparison, and output-preservation assumptions, the operation is left-to-right, non-overlapping byte replacement. Those assumptions are not established by this function. In particular, output addresses supplied by dependencies are not proven disjoint from input storage, and dependencies are not proven to preserve memory or global state.

Processing is length-directed. The first search byte must initially be nonzero, but subsequent comparison and copying use reported lengths. The function writes an additional zero byte after the constructed payload.

“Allocation,” “resize,” “release,” and “publication” below describe inferred dependency roles, not independently established ownership contracts.

## Interface

### Arguments

The function receives:

1. **Context:** a 32-bit value passed to several dependencies and used as an address for a nested limit lookup.
2. **Unused argument:** a 32-bit value not directly consumed by the supplied body.
3. **Operand-array address:** an address whose first three 32-bit entries identify the source, search, and replacement operands, respectively.

Operand entries are passed to address-query and length-query dependencies. They are not themselves used directly as byte-buffer addresses.

The function reads entries as needed rather than taking an initial snapshot. The address query and length query for one logical operand therefore need not receive the same entry value if an intervening dependency or an aliased write changes the array.

### Results

There is no explicit status or result return.

On the completed path, F-475af1e83e55 receives, in argument-position order:

- Context.
- Current output-buffer address.
- Constructed payload length, excluding the final zero byte.
- Metadata read from static storage near the end of the operation.

No direct release follows that call. Whether it copies, retains, consumes, or rejects the buffer is unknown.

### Widths and arithmetic

The supplied representation establishes:

- 32-bit addresses, operand entries, lengths, positions, and capacity words.
- One-byte payload reads and writes.
- A 64-bit result from the replacement length query.
- Use of that result’s low 32 bits as replacement length.
- Passage of its high 32 bits to the initial allocation-role dependency.
- A two-word capacity accumulator with explicit low-word carry and signed comparison against a sign-extended 32-bit limit.

Source and search lengths are consumed as 32-bit values without direct range validation.

The initial capacity is formed from the 32-bit sum of source length and one; its high word is the sign extension of the resulting low word. This is not an independently widened source-length-plus-one calculation.

The metadata declaration is not supplied. Its width and interpretation should not be inferred merely from its use as an argument.

### Preconditions

Memory-safe execution requires validity of every location actually reached, including operand entries, queried byte spans, output storage, and the nested context limit.

The function does not check the operand-array address or reject a zero context before passing it to dependencies. Context is directly dereferenced only if a match reaches the limit check.

No disjointness checks are present. To obtain ordinary replacement semantics, a caller or surrounding dependency contract must additionally establish suitable non-aliasing and preservation properties. Memory validity alone does not establish those semantics.

## Behavior

### Operand acquisition

The following acquisition order is established:

1. Read source entry 0 and pass it to F-95b79f0a129e.
2. If the returned address is zero, return.
3. Read entry 0 again and pass it to F-8e8cd22930fb for the source length.
4. Read search entry 1 and pass it to F-95b79f0a129e.
5. If the returned search address is nonzero, read its first byte.
6. Return if the search address is zero or that byte is zero.
7. Read entry 1 again and query its length through F-8e8cd22930fb.
8. Read replacement entry 2 and query its address through F-95b79f0a129e.
9. If the returned replacement address is zero, return.
10. Read entry 2 again and obtain the 64-bit replacement length result through F-8e8cd22930fb.

These rejection paths contain no direct reporting call.

The source’s first byte is not validated. Neither is the replacement’s first byte. A replacement with a nonzero address and zero reported length is not explicitly rejected.

The search’s first-byte rejection precedes its length query. A zero first byte causes rejection even if a subsequent query would have reported a positive length.

Retained source, search, and replacement address values are then used throughout construction. This does not imply that the storage they address remains unchanged.

### Initial output request

The initial low capacity word is source length plus one in 32-bit arithmetic. The high capacity word is its sign extension.

F-8abb19edfca0 receives:

- Context.
- The high 32 bits of the replacement length result.
- The initial low capacity word.

A zero return causes an immediate return, without a direct reporting or release call.

A nonzero return is retained as the output address. Success alone does not establish allocation size, initialized contents, disjointness from other objects, or preservation of any existing memory.

The auxiliary high word’s meaning is unknown.

### Candidate scanning

Source and output positions start at zero.

The scan continues while the source position is less than or equal to the signed 32-bit expression representing source length minus search length. With ordinary nonnegative lengths and no overflow, this considers positions where a complete search span can fit.

At each candidate, the function evaluates these two byte reads:

- The byte at the retained source address plus the current source position.
- The first byte at the retained search address.

**Their relative evaluation order is not established.** Both occur before any comparison-dependency call for that candidate.

If the bytes differ, no comparison dependency is called. If they are equal, F-7f14f1ab6851 receives the candidate source address, retained search address, and reported search length. Its zero return selects the match branch; a nonzero return selects the non-match branch.

The first search byte is reread at each candidate. Its initial validation value is not cached for later comparisons.

On the non-match branch, the function reads the current source byte again and writes that byte at the current output position. Consequently, if the comparison dependency ran and changed the source before returning nonzero, the copied byte can differ from the byte used in the initial equality test.

Both positions then advance by one. This branch contains no capacity-limit lookup or resize request.

### Capacity accounting on a match

Before copying a replacement span, the function:

1. Forms the 32-bit difference between replacement length and search length.
2. Adds that difference to the low capacity word.
3. Updates the high word using the difference’s sign extension and low-word carry.
4. Reads a 32-bit address from context byte offset 24.
5. Reads a 32-bit limit from byte offset 80 relative to that address.
6. Compares the accumulated signed two-word capacity with the sign-extended limit.

A capacity greater than or equal to the limit is rejected. Equality is not permitted.

On rejection, the function calls F-bb73abb30feb with context, then F-94cb53877c15 with the retained current output address, then returns. It does not perform that match’s resize or replacement copy and does not publish a result.

The nested limit is freshly read on every match. There is no such direct read during initial allocation, a non-match iteration, or completion without matches. Earlier dependency effects or aliased output writes can therefore affect a later limit lookup.

For ordinary bounded lengths without overflow, after a given number of matches the capacity is:

**source length + 1 + match count × (replacement length − search length).**

The extra one accounts for the final zero byte. Outside that range, this unbounded formula is not a substitute for the actual word-width arithmetic.

### Resize and replacement copy

If the updated capacity is below the current limit, F-0ee6114cab5e receives the current output address and the updated low capacity word.

This request occurs on every accepted match, including equal-size replacements, shrinking replacements, and zero-length replacements. The accumulator’s high word is not passed to this dependency.

If the return is zero, the function calls F-251588f6a575 with context, then F-94cb53877c15 with the output address supplied to the failed request, then returns without publication.

Otherwise, an unidentified external byte-copy dependency receives:

- Destination: returned output address plus current output position.
- Source: retained replacement address.
- Count: low 32 bits of the replacement length result.

The returned output address is used for subsequent output operations. The output position advances by replacement length, and the next source position advances by search length.

For positive search lengths, accepted spans are skipped rather than reconsidered at interior positions. Established scanning follows the retained source address; it does not switch to the returned output address.

The stronger statement that inserted replacement bytes are never searched requires additional assumptions. If output overlaps the retained source span, a replacement write can change bytes at future source positions. Likewise, output overlap with search or replacement storage can change later comparisons or copies.

### Suffix, terminator, and publication

When scanning ends, the external copy dependency is called for the remaining suffix:

- Destination: current output address plus output position.
- Source: retained source address plus source position.
- Count: source length minus source position.

The call is made even when this count is zero. Whether zero-count calls permit otherwise invalid addresses is not established.

The function then:

1. Adds the suffix length to the output position.
2. Writes one zero byte at that resulting output position.
3. Reads the publication metadata from static storage for the final call.
4. Calls F-475af1e83e55 with context, output address, payload length, and metadata.

The metadata read occurs **after the suffix-copy dependency returns and after the final zero-byte write**. Its value is not captured at entry. Dependencies may have changed the storage before this read; immutability is not established.

With ordinary stable inputs, search longer than source skips candidate scanning and copies the whole source as the suffix. With no accepted matches, no match-triggered limit lookup or resize occurs.

## Side effects

### Direct memory accesses

The function directly reads:

- Reached operand-array entries, including repeated reads around calls.
- The initial first search byte.
- The source/search byte pair at each candidate, without an established order within that pair.
- A further source byte on each non-match branch.
- The two nested context words on each match.
- Publication metadata after suffix copying and terminator writing.

It directly writes:

- One output byte per non-match iteration.
- The final zero byte.

Replacement spans and the suffix are written through the external copy dependency. Comparison and copying can introduce further accesses whose internal order is not visible here.

All direct writes are expressed through output addresses. **This does not prove that source, search, replacement, operand-array, context, or static metadata storage is unchanged:** those addresses are not established to be disjoint. Dependencies may also mutate any storage or global state available to them.

### Ownership and lifetime

The function contains no explicit release-role call targeted at the retained source, search, or replacement address. This does not prove those allocations survive: an aliased output address or dependency side effect can affect them.

F-94cb53877c15 is explicitly called after:

- Capacity-limit rejection.
- A zero resize result.

The reporting call precedes the release-role call in both cases. Its effects on memory and allocation validity are unknown.

The supplied body does not establish:

- Whether a successful resize preserves earlier output bytes.
- Whether successful resizing invalidates the previous address.
- Whether failed resizing leaves its input allocation valid.
- Whether publication transfers ownership.
- Whether the release-role dependency actually frees storage.

### Failure surface

Observable control-flow outcomes include:

- Early return after a rejected queried address.
- Early return after a zero initial search byte.
- Early return after a zero initial allocation result.
- Limit reporting followed by release-role invocation.
- Resize-failure reporting followed by release-role invocation.
- Completed construction followed by publication.

No explicit error code distinguishes these outcomes. Exceptions, traps, non-returning calls, and internal dependency failures remain outside the established contract.

## Acceptance examples

These are conditional expectations, not executed tests.

For examples promising final payload contents, assume all of the following:

- Queried addresses and lengths consistently describe the stated bytes.
- Lengths, positions, capacities, and addresses remain within valid, non-overflowing ranges.
- Output storage is suitably sized and disjoint from all inputs, operand entries, context, and metadata storage.
- Dependencies do not make intervening mutations that affect the stated computation.
- Comparison returns zero exactly for equal requested byte spans.
- Copies produce the requested bytes without damaging unrelated required storage.
- Successful resize requests preserve all previously written output bytes.
- Initial allocation and every resize succeed.
- Every encountered capacity check passes.
- Dependencies return normally.

Under those assumptions, publication receives the following payload and a zero byte immediately after it:

1. **Separated matches:** Source `ab--ab`, search `ab`, replacement `X` gives `X--X`, length 4.

2. **Overlapping candidates:** Source `aaa`, search `aa`, replacement `X` gives `Xa`, length 2. The accepted first match advances the source position by two.

3. **Replacement containing the search:** Source `a`, search `a`, replacement `aa` gives `aa`, length 2. Under the non-aliasing assumptions, written replacement bytes do not alter the source scan.

4. **Deletion:** Source `banana`, search `na`, replacement length zero at a nonzero address gives `ba`, length 2. Both matches still request resizing and invoke the replacement copy dependency with count zero; this example additionally requires that dependency to support those calls.

5. **Search longer than source:** Source `ab`, search `abcd` gives `ab`, length 2. No candidate comparison, match-triggered limit lookup, or resize occurs.

6. **No occurrences:** Source `abc`, search `z`, replacement `Q` gives `abc`, length 3. The direct nested capacity limit is never consulted.

7. **Embedded zero:** Source bytes `a`, zero, `b`; search `b`; replacement bytes zero, `c` gives payload bytes `a`, zero, zero, `c`, length 4, followed by the additional terminator.

The following examples concern control flow rather than final payload guarantees:

8. **Initial zero search byte:** If the search query returns a nonzero readable address containing zero as its first byte, the function returns before querying search length or acquiring replacement.

9. **Exact capacity boundary:** With source length 3, search length 1, replacement length 2, initial capacity is 4 and first-match capacity is 5. If an accepted comparison reaches a current signed limit of 5, the function calls F-bb73abb30feb, then F-94cb53877c15, without copying that replacement. A limit of 6 permits the resize request at that match, not necessarily eventual completion.

10. **Resize failure:** If a match passes its limit check and F-0ee6114cab5e returns zero, F-251588f6a575 precedes F-94cb53877c15. The latter receives the address supplied to the failed resize, and publication is not reached.
