# F-246b041db33f

## Purpose

F-246b041db33f performs a fixed sequence of indirect calls interleaved with word stores, a word load, byte-addressed transfers, a global assignment, and final zeroing operations. Its last explicit action is a call through address zero with three zero arguments.

The supplied static representation does not establish a higher-level purpose. In particular, it does not establish that the routine initializes an object, allocates storage, serializes a record, or handles a supervisor request. Such interpretations would require information about its dependencies and execution environment.

This contract describes the visible sequence conditional on each preceding operation completing normally. It does not guarantee that execution reaches the end.

## Interface

| A | 32 bits, represented as signed | Scaled by four to form the first store address and first call argument |

- **L:** an incoming machine-state value used to derive the first indirect call target.

R, S, and L are not explicit parameters in the supplied interface. A callable interface cannot be fully specified without their entry-state requirements.

### Output

There is no explicit return value. A return is represented after the final call, but normal return requires that the call through address zero itself return.

The observable outputs are memory writes, dependency calls and their arguments, and the assignment to T.

### Width and address conventions

The representation distinguishes:

- 32-bit word loads and stores;
- 8-bit loads and stores;
- a final 16-bit zero store;
- 64-bit dependency results split into low and high 32-bit halves.

For compactness, this contract uses:

- **scale(x):** the represented 32-bit result of multiplying x by four or shifting x left by two.
- **slot(x):** the address formed by adding hexadecimal `0x14` to scale(x).

For a 32-bit machine interpretation, scale(x) retains the low 32 bits of the mathematical product. The source uses signed expressions for some of these operations; exact overflow, pointer-conversion, and fault semantics require confirmation from the execution environment. No portable signed-overflow guarantee is asserted.

Right shifts of the values explicitly described below as unsigned are logical shifts.

## Behavior

### 1. Initial store and first value-producing chain

1. Store S as a 32-bit word at slot(A).
2. Invoke F-U01 with scale(A). Its target is derived from L.
3. Invoke F-U02, F-U03, and F-U04, in that order, with no explicit arguments.
4. Invoke F-U05 and capture its represented 32-bit result, X.
5. Compute V = scale(X).
6. Store V as a 32-bit word at the address formed by clearing C’s lowest two bits and adding hexadecimal `0x14`.
7. Invoke F-U06 with two explicit arguments, both V.

The initial store precedes every dependency call. The C-derived store occurs after F-U05 and before F-U06.

Clearing C’s low two bits is an address transformation, not validation of an object pointer or proof that sufficient storage exists.

### 2. Two result-forwarding pairs

8. Invoke F-U07 and pass its represented 32-bit result to F-U08.
9. Invoke F-U09 and pass its represented 32-bit result to F-U10.

No explicit direct memory operation is interposed within either pair. Dependencies may nevertheless access memory or global state.

### 3. Store a field extracted from incoming state

10. Invoke F-U11, F-U12, and F-U13 in order.
11. Invoke F-U14 and capture its represented 32-bit result, Y.
12. Store the unsigned value R shifted right by 23 bits as a 32-bit word at slot(Y).
13. Invoke F-U15 with scale(Y).
14. Invoke F-U16, F-U17, and F-U18 in order.

The stored field is nine bits wide, with values from zero through 511. It is written as a complete 32-bit word.

### 4. Split a wide result and capture a global base

15. Invoke F-U19 and capture a represented 64-bit result.
16. Let P be its low 32-bit half and H its high 32-bit half.
17. Compute W = scale(P).
18. Store W as a 32-bit word at slot(H).
19. Read G and retain its current contents as base address K.
20. Invoke F-U20 with four explicit arguments, in order: W, H, W, W.
21. Invoke F-U21, F-U22, and F-U23 in order.
22. Invoke F-U24 and capture its represented 32-bit result, J.
23. Store W as a 32-bit word at slot(J).
24. Load a 32-bit unsigned word from K plus hexadecimal `0x14`; retain it as D.
25. Invoke F-U25 with scale(J).

The read of G and the later load through K are separate events. F-U20 through F-U24 occur between them. Consequently, the load uses the captured base K, but reads the memory contents present when the later load executes.

The store to slot(J) precedes the load of D. If those addresses overlap, the load may observe that store, subject to the environment’s memory semantics.

### 5. First byte-addressed transfer

26. Invoke F-U26, F-U27, and F-U28 in order.
27. Invoke F-U29 and capture a represented 64-bit result.
28. Let U be its low 32-bit half and N its high 32-bit half.
29. Load an unsigned byte from address R + 1.
30. Add hexadecimal `0x11` to that byte’s value and use the result as an address.
31. Store D’s low eight bits as one byte at that address.
32. Invoke F-U30 with four explicit arguments: N, N, N, scale(U).

The destination is formed from the byte’s numerical value. It is not an address relative to R. Before any environmental remapping, that destination lies between hexadecimal `0x11` and `0x110`, inclusive.

### 6. Second byte-addressed transfer

33. Invoke F-U31 and pass its represented 32-bit result to F-U32.
34. Invoke F-U33, F-U34, and F-U35 in order.
35. Invoke F-U36 and capture its represented 32-bit result, E.
36. Compute an unsigned byte-source address by clearing U’s highest two bits, shifting the remaining value right by 21 bits, and adding one.
37. Load an unsigned byte from that address.
38. Add hexadecimal `0x11` to the loaded byte’s value and use the result as a destination address.
39. Store the low eight bits of D shifted right by 22 bits at that destination.
40. Invoke F-U37 with scale(E).

The byte-source address is between 1 and 512, inclusive. The transferred byte consists of bits 22 through 29 of D. Bits 30 and 31 do not contribute.

D is the word captured earlier; it is not reloaded. U is likewise the previously captured low half of F-U29’s result.

### 7. Final calls, assignment, and zeroing

42. Invoke F-U41 and capture its represented 32-bit result, Z.
43. Invoke F-U42 with scale(Z) twice.
44. Invoke F-U43.
45. Invoke F-U44 and pass its represented 32-bit result to F-U45.
46. Invoke F-U46 and assign its represented result to T.
47. Store one zero byte through Q.
48. Clear U’s highest two bits, shift right by seven bits, and use the result as an address.

The assignment to T precedes both zero stores. The byte store through Q precedes the halfword store, which precedes the call through address zero.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Each assumes the required addresses are accessible and all preceding dependencies return.

1. **Initial scaled destination.** With A equal to 3, the first word store targets hexadecimal `0x20`. It writes S before F-U01 is invoked, and F-U01 receives 12.

2. **C alignment mask.** C values from hexadecimal `0x100` through `0x103` produce the same C-derived store destination, hexadecimal `0x114`. The written value is scale(X), not C.

3. **Nine-bit field extraction.** With R equal to hexadecimal `0xffffffff`, the store associated with F-U14 writes 511. This says nothing about whether the later byte read through R + 1 is valid.

4. **Captured base, delayed contents.** If G contains hexadecimal `0x2000` when captured, and a dependency subsequently changes G to hexadecimal `0x3000`, D is still loaded from hexadecimal `0x2014`. A dependency write to hexadecimal `0x2014` before that load can affect D.

5. **First selected byte destination.** If the byte loaded from R + 1 equals hexadecimal `0x20`, the first byte transfer writes to hexadecimal `0x31`. With D equal to hexadecimal `0xa5c1237e`, it writes hexadecimal `0x7e`.

6. **Second selected byte destination.** With U equal to hexadecimal `0x00200000`, the second selector is read from address 2. If that byte is 7, the destination is hexadecimal `0x18`. With D equal to hexadecimal `0x3fc00000`, the stored byte is hexadecimal `0xff`.

7. **Unaligned final address.** With U equal to hexadecimal `0x80`, the final halfword-store address is 1. The routine performs no visible alignment correction. Whether the store succeeds is environmental.

8. **Failure boundary.** If the byte store through Q fails after T has been assigned, the visible sequence provides no rollback of T and does not establish execution of the halfword store or F-U47.
