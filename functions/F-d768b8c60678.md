# F-d768b8c60678

## Purpose

F-d768b8c60678 searches a nominal 32-slot structure for a slot whose status byte is zero. It starts at a stored search cursor, searches toward the end of the slot range, and then searches from the beginning up to the cursor.

If the first search attempt finds no eligible slot, the function invokes F-70ed53ae2fa0 once and repeats the search. A successful search reports the selected index and advances the stored cursor. Two unsuccessful attempts produce a failure result.

The function does not explicitly mark the selected slot as occupied. “Find an available slot” is a supported interpretation of the zero-byte test; “allocate a slot” would imply additional behavior not established here.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

The function takes two arguments:

1. **Structure base:** an address identifying the structure containing slot status bytes and the search cursor.
2. **Result address:** an address at which the function can write a 32-bit unsigned slot index.

The supplied representation models the first argument as a 32-bit integer used for addressing and the second as a pointer to a 32-bit unsigned value. Exact calling convention, platform ABI, alignment requirements, and pointer provenance requirements are not established independently.

## Behavior

### Entry normalization

The function first reads the stored cursor as an unsigned 32-bit value.

If the value exceeds 31, it writes zero to the cursor before searching. Otherwise, it leaves the cursor unchanged.

Consequently, every out-of-range initial value is normalized, including values whose highest bit is set. This entry comparison is unsigned.

Normalization happens only at entry. It is not repeated after the dependency call.

### Search order within an attempt

An attempt has two search segments.

**Forward segment:** The function reads the stored cursor and examines status bytes beginning at that index, in increasing index order, while the index is less than 32.

**Wraparound segment:** If the forward segment finds no zero byte, the function starts at index zero and examines status bytes in increasing order while the index is less than the stored cursor under a signed 32-bit comparison.

The wraparound bound is read from the stored cursor for each loop condition. It is not represented as a single immutable snapshot for the entire segment.

With a stable cursor in the range 0 through 31, the attempt therefore examines each nominal slot at most once:

- Cursor 0: indices 0 through 31.
- Cursor 7: indices 7 through 31, then 0 through 6.
- Cursor 31: index 31, then indices 0 through 30.

The first zero status byte encountered wins. Later status bytes are not examined after a match.

Only equality to zero matters. A status byte with value 1, 128, or 255 is equally ineligible; signed versus unsigned interpretation of that byte does not change the zero test.

### Success transition

When a zero status byte is found, the observable order of direct operations is:

1. Write the selected index as a 32-bit unsigned value to the result address.
2. Write the selected index plus one as a 32-bit value to the stored cursor.
3. Return 0.

The function does not reread the selected status byte between these stores. It does not explicitly write that status byte or any other slot field.

For an ordinary successful selection, the reported index is between 0 and 31, and the resulting cursor is between 1 and 32. Selecting index 31 stores cursor value 32 rather than immediately wrapping it to zero. A later invocation normalizes that value to zero at entry.

The two stores must not be treated as interchangeable. If the result address is exactly the cursor address, the final stored value is the selected index plus one, because the cursor store occurs last. Such aliasing prevents the caller from retaining a separate index result at that location.

### First unsuccessful attempt

If both segments finish without finding a zero status byte, the function calls F-70ed53ae2fa0 with the structure base.

This call occurs at most once. No dependency return value is used to decide whether to retry or which index to select.

After the call returns, the function makes a second search attempt. It reads the cursor and status bytes again; it does not reuse a previously computed availability result.

### Second unsuccessful attempt

If the second attempt also finds no zero status byte, the function returns 1.

There is no third attempt and no second call to F-70ed53ae2fa0.

With stable ordinary memory and a cursor that remains within range, each failed attempt reads all 32 status bytes once. Both failed attempts therefore account for 64 direct status-byte reads, excluding any accesses made by the dependency.

### Cursor changes made by the dependency

The second attempt uses the cursor state present after F-70ed53ae2fa0 returns. The function does not restore the entry cursor or normalize the dependency’s replacement value.

This distinction affects both search order and memory safety:

- A cursor in the range 0 through 31 produces the ordinary cyclic search order.
- A cursor of 32 skips the forward segment, then searches indices 0 through 31 in the wraparound segment.
- A cursor from 33 through 2,147,483,647 skips the forward segment. With a stable bound, the wraparound segment can examine indices beyond 31.
- A cursor from 2,147,483,648 through 4,294,967,295 skips the forward segment and is interpreted as negative for the wraparound comparison. Its first wraparound condition is false, so that attempt performs no status-byte reads.

Thus, the nominal 32-slot limit is protected by entry normalization, not by a complete validation of cursor state after the dependency.

A dependency-written cursor of 33, for example, can cause a status read for index 32 if all preceding tested bytes are nonzero. Whether that address is valid is not established.

### Arithmetic and widths

Slot offsets use a 20-byte stride. Cursor values, reported indices, and cursor stores are 32-bit quantities.

For nominal indices 0 through 31, the offset calculations and cursor increment remain comfortably within 32-bit range.

The signed wraparound comparison differs materially from the unsigned entry check and forward-segment limit. They must not be replaced by a single assumed unsigned bounds rule when describing dependency-modified state.

For very large non-nominal indices, address arithmetic may exceed ordinary 32-bit bounds. Exact machine-address behavior in those cases is not established by this representation; valid backing storage must not be inferred merely from the arithmetic expression.

## Side effects

### Direct memory effects

The function can directly:

- Read the stored cursor.
- Write zero to the cursor during entry normalization.
- Read individual slot status bytes.
- Write a selected index to the result address.
- Write the next cursor value after a successful match.

It performs no explicit memory allocation, release, slot clearing, or non-status slot-field update.

This is not a whole-call guarantee against those effects: F-70ed53ae2fa0 has an unknown implementation.

### Aliasing

No non-aliasing condition is checked.

If the result address overlaps the structure, its successful 32-bit store can modify structure bytes. In particular, it may overlap one or more status bytes or the cursor. Partial overlap can produce effects dependent on byte order and access behavior, neither of which is specified here.

Even on a returned failure, an output location aliasing the cursor may have changed because entry normalization writes the cursor.

### Ownership and state lifetime

The function itself does not establish ownership transfer for either argument. It retains no explicit pointer in the visible operations.

Whether the dependency retains references, releases memory, changes unrelated state, or preserves globals is unknown. Callers cannot derive such guarantees from this function alone.

### Atomicity and concurrent access

No locking, atomic access, or transaction boundary is visible.

The search and the result/cursor stores are separate operations. The function therefore provides no established guarantee that a selected slot remains eligible after its status byte is read.

Behavior under concurrent or otherwise asynchronous mutation is not specified. In particular, the repeatedly read wraparound bound must not be assumed stable without an external guarantee.
