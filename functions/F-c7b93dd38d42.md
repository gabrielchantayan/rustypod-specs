# F-c7b93dd38d42

## Purpose

F-c7b93dd38d42 coordinates an associated-handle update, a primary operation, and a final conditional dispatch.

Its established behavior has three stages:

1. Depending on whether the selector is zero, process and clear an existing associated handle or obtain and store a replacement.
2. Invoke a primary operation with three words held in a local record.
3. If that operation returns a nonzero handle, construct a packed record and select between two final actions using an unsigned threshold comparison.

The function returns a 32-bit value. A zero primary result leads to an explicit zero return. Otherwise, the selected final action supplies the return value, which may itself be zero.

Interpreting the records as dates or times, the increment of 60 as a duration, or the actions as scheduling is **inferred intent**, not established behavior.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Initialization and branch selection

The three non-object inputs are copied into the local record before the selector branch.

The branch tests the original selector argument. Later modification of the first record word does not retroactively change that branch choice.

### Zero selector: process an existing associated handle

The function first reads the associated-handle slot at object offset `0xC0`.

If it is zero, this entire processing stage is skipped. In particular, there is no direct write to that slot on this path before the primary operation.

If it is nonzero, the following ordered actions occur:

1. Obtain the associated-handle value through the object slot and read a 32-bit value at offset eight from that handle.
2. Invoke F-dee541b2a059 with the value read and the address of the local record’s first word.
3. Invoke F-938c950e5046 with no explicit arguments.
4. After that call returns, read the global value.
5. Invoke F-5710a8628cba with the result of F-938c950e5046 and the value just read from the global.
6. Invoke F-b8274406a146 with the local record’s starting address and mode 1.
7. Invoke F-b8274406a146 with the result of F-5710a8628cba and mode 1.
8. Compare the two conversion results as described below.

The global is not shown as captured at function entry or before F-938c950e5046. Changes made by F-dee541b2a059 or F-938c950e5046 can therefore affect the value supplied to F-5710a8628cba.

Let the first mode-1 conversion result be \(P\) and the second be \(Q\). The predicate is:

\[
((P + 60) \bmod 2^{32}) \leq Q
\]

The comparison is unsigned and inclusive.

Only if this predicate passes does the function reread object offset `0xC0` and pass its current value to F-2b9d47918562. This is not necessarily the handle observed before the preceding calls.

Only if F-2b9d47918562 returns exactly zero does the function invoke the callback at table offset `0xDC`, passing the object and the address of its region at `0xB4`. Other return values suppress that callback.

After this nonzero-handle processing branch, the function writes zero to object offset `0xC0`, irrespective of either predicate’s outcome.

That clear occurs after the calls, not before them. It is guaranteed only if the preceding execution returns normally.

### Nonzero selector: replace the associated handle

For any nonzero selector, the function:

1. Invokes the callback at table offset `0xC0`, passing the object.
2. Stores its 32-bit result into object offset `0xC0`.
3. Invokes F-9b1fcfb958de with that result and the address of object region `0xB4`.

There is no local zero-result check. A zero callback result is both stored and passed to F-9b1fcfb958de.

No explicit processing or release of the old slot value precedes the overwrite. F-9b1fcfb958de may have further effects; the stored value is not guaranteed to remain unchanged after it returns.

### Primary operation

After either selector branch, F-fd8692810e8b receives:

- The object.
- The current first local-record word.
- The current second local-record word.
- The current third local-record word.

In the zero-selector, nonzero-associated-handle case, a preceding dependency has received the record address. The three values passed here therefore cannot generally be specified as the original inputs.

### Zero primary result

If F-fd8692810e8b returns zero, the function:

1. Writes zero to object offset `0xC4`.
2. Invokes F-f2b8332efb8a with integer 3.
3. Returns zero if that call returns normally.

The dependency’s result does not determine the function’s return value.

Earlier associated-handle effects are not rolled back. The direct clear of `0xC4` precedes F-f2b8332efb8a, so that dependency may observe or further modify the field.

### Nonzero primary result

If F-fd8692810e8b returns a nonzero handle, the function performs these actions in order:

1. Invoke F-ebc906d2c2d5 with the returned handle.
2. Invoke F-dee541b2a059 with that dependency’s result and the address of the local record’s second word.
3. Invoke F-6132bda8e448 with the eight-byte scratch-region address.
4. Invoke F-b8274406a146 with the address of the local record’s second word and mode 0.
5. Form a threshold by adding 60 to that 32-bit conversion result modulo \(2^{32}\).
6. Invoke F-dee541b2a059 with the threshold and the address of the local record’s second word.
7. Construct the eight-byte packed record from the resulting second and third record words.
8. Store the original nonzero primary-result handle into object offset `0xC4`.
9. Invoke F-b8274406a146 with the scratch-region address.
10. Compare that conversion result against the threshold using unsigned strict less-than.

The final F-b8274406a146 invocation has only one explicit argument in the supplied representation. Its mode, if the actual calling convention requires one, is not established.

The final comparison uses the threshold derived from the saved mode-0 conversion result. It does not reconvert the record after the threshold-processing call.

If the scratch conversion result is less than the threshold, F-910df819391b receives integer 1 and the packed-record address. Its 32-bit result is returned.

Otherwise, including equality, the callback at table offset `0xE8` receives the object and integer 2. Its 32-bit result is returned.

### Packed-record layout

Let **A** and **B** denote the second and third local-record words after F-dee541b2a059 processes the threshold.

Byte numbers below identify numeric significance: byte 0 is bits 7–0; byte 3 is bits 31–24.

| Packed word | Bits 7–0 | Bits 15–8 | Bits 23–16 | Bits 31–24 |
|---|---|---|---|---|
| First | B byte 2 | B byte 3 | B byte 0 | A byte 3 |
| Second | A byte 2 | A byte 1 | A byte 0 | Zero |

B byte 1 is omitted. The second word is a zero-extended 24-bit construction.

On a little-endian target, the columns also describe successive memory bytes within each word. The numeric construction does not itself establish target byte order.

The packed record is constructed even when final dispatch selects the object callback and does not pass the record onward.

## Side effects

### Direct writes and observable ordering

The function directly writes:

- The initialized three-word local record.
- Object offset `0xC0` when clearing a processed associated handle or storing the replacement callback result.
- The packed local record on every nonzero-primary-result path.
- Object offset `0xC4` on both primary-result branches.

These writes are not transactional. Dependencies can observe intermediate object state.

On the nonzero-primary-result path, several dependencies run before `0xC4` is updated. The scratch conversion and final action run after that update. On the zero-primary-result path, F-f2b8332efb8a runs after the clear.

The function visibly reads the global but shows no direct write to it. This does not establish global stability: dependencies may modify it or other shared state.

No final object-field value is guaranteed against subsequent callee mutation merely because the function previously wrote that field.

### Ownership and lifetime

No allocation, retain, release, destruction, or ownership transfer is established by these call sites.

Clearing a handle slot does not prove destruction of its referent. Storing a returned handle does not prove acquisition of ownership.

Local record addresses are valid local storage during the invocation. The function provides no visible lifetime extension. Whether dependencies retain those addresses, and whether retention is permitted, remains unknown.

### Errors and abnormal termination

The only explicit primary-operation failure handling is the zero-result sequence described above.

There is no visible local recovery for invalid pointers, invalid callback entries, conversion failures, exceptions, or nonlocal exits. No status checks are added around the record-processing dependencies.

If any dependency fails to return normally, later calls and writes are not guaranteed.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid reached accesses, normal returns, and no unspecified side effects that invalidate its stated setup.

1. **Zero selector and zero associated handle.**  
   Associated-handle processing is skipped, including the global read. The primary operation receives the initialized record words. If it returns zero, `0xC4` is cleared, F-f2b8332efb8a receives 3, and the function returns zero.

2. **Global changed by the immediately preceding dependency.**

If no intervening modification occurs, F-5710a8628cba receives R and Y, not X. This distinguishes the required late read from an entry-time snapshot.

3. **Nonzero selector and zero replacement result.**  
   The `0xC0` callback returns zero. The function stores zero in the associated-handle slot and still invokes F-9b1fcfb958de with zero and the embedded-region address.

4. **Inclusive first boundary.**  
   The mode-1 conversion results are 100 and 160. The first predicate passes. F-2b9d47918562 receives the then-current associated handle. The `0xDC` callback runs only if that dependency returns zero. The slot is subsequently cleared.

5. **Below the first boundary.**  
   The mode-1 results are 100 and 159. F-2b9d47918562 and the `0xDC` callback are skipped. The associated-handle slot is nevertheless cleared.

6. **Unsigned wraparound.**  
   A relevant conversion result of `0xFFFFFFF0` produces threshold `0x0000002C` after adding 60. The comparison uses that wrapped value, not an unbounded sum or signed ordering.

7. **Strict final boundary.**  
   A nonzero primary result produces threshold 260. A scratch conversion result of 259 selects F-910df819391b. A result of 260 selects the `0xE8` callback with argument 2.

8. **Packed-byte mapping.**  
   If A is `0x11223344` and B is `0x55667788` after threshold processing, the packed numeric words are `0x11885566` and `0x00443322`.

9. **Return forwarding.**
