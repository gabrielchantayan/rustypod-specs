# F-4b437e67169f

## Purpose

The supplied static representation describes a sequence of indirect calls, 8-bit and 32-bit memory accesses, and 32-bit arithmetic. It does not establish an application-level purpose.

The observable contract is therefore an ordered memory-and-call protocol, conditional on execution following the represented path. It must not be characterized as an allocator, serializer, object initializer, or device operation without additional evidence.

The representation begins with a warning about invalid instruction data and ends at a truncated control-flow boundary. Consequently, this document distinguishes behavior represented on that path from behavior established for an actual executable. No normal completion, useful return value, or successful operation is established.

### Width and address conventions

Unless otherwise stated:

- Words and address calculations are 32 bits.
- Byte reads produce unsigned values from 0 through 255.
- Byte writes retain only the least significant eight bits.
- Right shifts explicitly applied to unsigned values are logical.
- A 64-bit dependency result is treated as a low 32-bit word and a high 32-bit word.
- Scaled addresses and left shifts are described by their 32-bit bit-pattern results.

Some displayed arithmetic uses signed types. A portable signed-language overflow contract cannot be inferred from that notation. Where overflow matters, the intended machine-width interpretation is conditional, not proof of the executable’s arithmetic semantics.

Memory byte order and alignment requirements are not established. A word-to-byte conversion selects the numeric low byte; it is not evidence that the first addressed byte of that word is selected.

## Side effects

The directly represented effects include:

- Byte stores through zero-extended byte selectors.
- Word reads at offsets including `0x04` and `0x74`.
- Word stores at offsets including `0x14`, `0x24`, and `0x34`.
- Byte stores at offsets including `0x01`, `0x07`, `0x0d`, and `0x11`.
- Direct byte writes to addresses `0x0d` and `0x11`.
- Numerous indirect calls with unknown external effects.

A byte selector plus `0x11` addresses the range `0x11` through `0x110`; it is not a pointer-sized load or an implicitly dereferenced pointer table.

No rollback, validation, locking, allocation, release, or ownership transfer is explicitly established. Dependencies may perform any of these, but that remains unknown. Earlier stores may remain observable if a later access or call fails.

Aliasing is unrestricted by the evidence. A dependency or earlier write may change memory used by a later fresh read. Retained selector values and payload words are not automatically refreshed.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial byte extraction:** If incoming bits is `0xffffffff`, the first represented selector-backed store writes `0xff`: the right shift produces `0x3ff`, and the byte store truncates it.

2. **Zero-extended selector:** If a selector read yields `0xff`, the corresponding destination is address `0x110`. Treating the selector as signed and targeting `0x10` would violate the represented behavior.

3. **Numeric low byte:** If a word read for a word-to-byte transfer yields `0x12345678`, the byte written is `0x78`, independent of an unstated memory byte order.

4. **Different packed projections:** If packed source is `0x80000000`, the duplicated packed arguments are zero because their nine-bit mask excludes the extracted top bit. The later word store from that packed source is also zero under 32-bit truncation. This does not imply that all packed-source bits are unused.

5. **Fresh selector reads:** If a dependency changes a selector byte between two listed fresh reads, the later destination follows the changed byte. Reusing the earlier selector would not satisfy the protocol.

6. **Retained saved selector:** After saved selector is captured, subsequent calculations using twice saved selector use that captured value, even if its original memory location changes.

7. **Visible overwrite ordering:** Address `0x0d` receives saved selector before later receiving `0xc0`. Observers or intervening dependencies may distinguish these writes; replacing them with only the final write is not equivalent.

8. **Partial execution:** If a word read faults after an earlier byte write, no represented error handler restores the byte. Acceptance of a successful end-to-end outcome cannot be inferred.
