# F-6dafbb420982

## Purpose

F-6dafbb420982 transforms a 64-bit value supplied as two 32-bit words and returns a 64-bit result.

The input partition matches the sign, exponent, and fraction fields of an IEEE 754 binary64 encoding. For positive, finite, normal inputs, the function performs an integer digit-extraction calculation consistent with square root and applies a rounding rule consistent with round-to-nearest, ties-to-even.

That mathematical interpretation is **inferred intent**, not a verified numerical specification. Established behavior includes several departures from a general-purpose binary64 square-root contract:

- Both signed zero encodings are preserved.
- Every nonzero subnormal input produces positive zero, including negative subnormals.
- Positive infinity is preserved.
- Negative normal values and negative infinity produce a result whose high word comes from shared storage and whose low word is 1.
- NaN encodings enter a configuration-dependent indirect transfer rather than returning through the ordinary numerical path.

No runtime tests have been performed.

| Input | Width | Meaning |

| Low input word | 32 bits | Bits 31–0 of the input encoding |
| High input word | 32 bits | Bits 63–32 of the input encoding |

The returned value is 64 bits. For direct returns, the high and low result words occupy bits 63–32 and 31–0, respectively. This specifies bit placement, not memory byte order or a platform calling convention.

The input fields are:

- Sign: bit 31 of the high word.
- Exponent: bits 30–20 of the high word, an unsigned 11-bit field.
- Fraction: bits 19–0 of the high word followed by all 32 bits of the low word, forming a 52-bit field.

No explicit input is a pointer or an owned resource.

## Behavior

### 1. Classify exponent-zero encodings first

Exponent-zero inputs are handled before sign-dependent rejection or exceptional-value dispatch.

If the complete fraction is zero, the function returns the original input words unchanged. Consequently, positive zero and negative zero remain distinct.

If the fraction is nonzero, the function returns the all-zero 64-bit encoding. The sign does not change this outcome.

Thus:

- Positive subnormal → positive zero.
- Negative subnormal → positive zero.
- Neither case visibly reads the configuration or exceptional-result words.

There is no visible normalization of subnormal inputs and no visible report of their loss of magnitude.

### 2. Classify all-ones exponents

When the exponent is 2047, the fraction determines the next action.

#### Nonzero fraction: NaN dispatch

Every nonzero fraction enters the same dispatch structure, regardless of:

- Input sign.
- Fraction payload.
- Whether the encoding would conventionally be classified as quiet or signaling.

The explicit input payload is not visibly supplied as an argument to the indirect target. This does not prove that the target cannot observe residual machine state.

The first configuration read selects a mode using its low four bits. Subsequent branch decisions visibly consult the shared configuration again. A single stable snapshot must not be assumed.

The indirect target is formed by clearing the low two bits of the incoming link-state value. Its logical dependency ID in this document is **F-000000000001**. That ID denotes an unresolved transfer role, not a recovered implementation identity.

If the indirect operation returns, its 64-bit result becomes this function’s result without a visible transformation.

#### Zero fraction: infinity

Positive infinity is returned unchanged.

Negative infinity reaches the same exceptional-result path as negative finite normal values.

### 3. NaN mode behavior

The following describes visible argument lists. It does not assert a recovered target prototype or establish that unlisted argument registers contain meaningful values.

#### Mode 9

The function next tests configuration bit 20.

If that bit is clear, it transfers to F-000000000001 with:

1. A zero word.
2. The value read from auxiliary word A.

If configuration bit 20 is set, the function next tests whether any of bits 18–16 are set.

If at least one is set, it transfers with:

1. The word 8.
2. A value derived from a further configuration read.

For that second argument, take the 32-bit configuration value, shift it left by 15, complement all 32 bits, then shift left by one. All discarded bits are lost. Equivalently, the result is the 32-bit complement of the configuration shifted left by 16, with bit 0 cleared.

If bits 18–16 are all clear, it transfers with:

1. `0x30000000`.
2. The value read from auxiliary word A.
3. `0x30000000` with bit 27 additionally set exactly when incoming processor-state bit 0 is set.

The evidence does not establish an evaluation order between the independent reads used to prepare separate arguments.

#### Mode 10

The function tests configuration bit 6 and transfers with one visible argument:

- Bit 6 clear: zero.
- Bit 6 set: `0x80000000`.

#### Mode 8

The function tests configuration bit 6.

If bit 6 is set, it transfers with two zero arguments and does not visibly fetch A, B, or C for this branch.

If bit 6 is clear, the visible read sequence is:

1. Read auxiliary word B.
2. Read auxiliary word A.
3. Test configuration bit 4.

If bit 4 is clear, the argument pair is the previously read B value followed by the previously read A value.

If bit 4 is set, those earlier reads still occur, but the arguments become:

1. Zero.
2. A subsequent read from auxiliary word C.

The discarded reads matter if shared-memory access itself is observable.

#### Other modes

Any mode other than 8, 9, or 10 transfers to F-000000000001 with no explicit arguments visible in the supplied representation.

This does not establish that the target receives a clean or empty machine-level argument state.

### 4. Reject negative nonzero, non-subnormal values

A negative finite input with a nonzero exponent and an exponent below 2047 does not enter the numerical extraction path.

Its result has:

- High word: the value read from the shared exceptional-result word.
- Low word: 1.

Negative infinity has the same behavior.

The result therefore cannot be identified as a particular NaN encoding without knowing the shared word. No visible configuration test modifies this direct return.

Negative zero and negative subnormals do not reach this path because exponent-zero classification takes precedence.

### 5. Process positive finite normal values

Only sign-clear inputs with exponents from 1 through 2046 reach the ordinary numerical path.

This path uses the explicit input words and local integer arithmetic. It contains no visible shared-state reads or indirect transfers.

Its externally relevant numerical structure is:

- The 52-bit fraction is extended with the implicit leading significand bit.
- Exponent parity determines whether the significand is doubled before extraction.
- An integer square-root-style extraction retains both a candidate result and a remainder.
- A first extraction phase makes 29 bit-position decisions.
- A second phase makes 23 further bit-position decisions.
- The extracted words are packed with an exponent contribution derived from half the adjusted input exponent.
- A guard bit and the residual remainder determine final rounding.

The initial exponent adjustment adds 253 to the encoded input exponent. Its low bit controls significand doubling. The later exponent contribution uses the logical right shift of that adjusted quantity by one, followed by an addition of 384.

The final high-word construction also includes extracted significand bits. The exponent contribution alone must not be mistaken for the complete encoded output exponent.

The extraction includes cross-word carry and borrow handling. In particular, sign-propagating shifts are used to move a word’s former top bit into the adjacent arithmetic. Replacing those operations with ordinary logical shifts would change the calculation.

#### Final rounding

Before the return, the function has an unrounded high/low result pair, a guard bit, and a residual remainder.

The established final rounding behavior is:

- Guard clear and remainder zero: return the packed pair unchanged.
- Guard clear and remainder nonzero: also return the packed pair unchanged.
- Guard set and remainder nonzero: increment the low word by one and propagate carry into the high word.
- Guard set and remainder zero: increment by one, propagate carry, and clear the resulting low word’s least significant bit.

The last case selects an even low bit at an exact halfway point. This supports the inferred ties-to-even interpretation.

There is no visible configuration-dependent rounding selection on this path.
