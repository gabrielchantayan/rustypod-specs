# F-83f2b64ff30b

**Established static evidence:** The supplied representation contains four formal parameters, three additional incoming register values, several direct and indirect memory writes, one global read used as a pointer, and one indirect call. It has no explicit return value.

## Behavior

   The offset is 32 two-byte units, therefore 64 bytes. The destination is reinterpreted as a pointer-containing slot. Under the supported 32-bit pointer interpretation, this writes four bytes containing B.

4. **Store the low 16 bits of B at B.**  
   This is a two-byte store. It does not preserve a previous value at that location.

5. **Form C and store C at C.**  
   C is obtained by multiplying the fourth formal input by 16 and adding 17. The destination receives the same value used as its address, through a signed 32-bit destination type. This is a four-byte store.

### Indirect call arguments

## Side effects

### Memory and aliasing

The function writes to addresses derived from entry state, several global cells, and a destination obtained from a global read. It does not establish that any of these regions are disjoint.

Aliasing consequences include:

- The write at B + 64 can overlap a later destination.
- The four-byte store at C can overwrite part or all of another destination.
- D may equal B, B + 2, a global address, or another accessed address.
- Earlier writes may modify the pointer-source global before it is read.
- The four-byte store through V may overlap memory already written.

Accordingly, a conforming account must evaluate the pointer-source read at its stated position. It must not substitute an entry-time snapshot.

The final contents of memory after the indirect call are not determined solely by this body. The dependency may modify the same locations.

### Pointer-source aliasing

Suppose an earlier destination overlaps the pointer-source global. If execution reaches its read, V is obtained from the cell as it exists then. The contract does not permit using its original entry value merely because the cell is described as global.

### First call argument without signed overflow

Suppose the pointer-source conversion yields V = `0x00000100`, all prior operations complete, and the call target is valid. Advancing V by 16 gives `0x00000110`; multiplying by `0x01000000` produces `0x110000000`, outside signed 32-bit range.

Therefore, the evidence alone does **not** establish a portable first argument for this case. Under explicitly assumed 32-bit wraparound, it would be `0x10000000`.

By contrast, V = `0x00000000` yields the arithmetic first argument `0x10000000` without signed overflow, provided the preceding four-byte write at address zero is permitted by the environment.
