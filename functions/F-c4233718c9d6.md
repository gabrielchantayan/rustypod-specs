## Behavior

### Entry and condition evaluation

The function first captures the global pointer. That captured pointer determines the destination of the conditional store and the source of the final return read.

The condition then evaluates the global pointer and reads the integer it selects. The supplied representation therefore distinguishes the entry capture from the pointer evaluation used by the condition.

Under ordinary execution in which the global pointer does not change between those evaluations, both refer to the same cell. If an external agent could change the pointer between them, the condition could concern a different cell from the eventual write and return. Whether such an execution is defined is not established; this observation does not imply support for concurrent mutation.

Only an exact zero takes the conditional branch. There is no distinction among nonzero values at this gate. In particular, a representable negative integer is nonzero and does not independently trigger initialization.

### Nonzero condition

If the condition read is nonzero:

- Neither dependency is called by this invocation.
- No explicit cell write occurs.
- The function reads through the captured pointer and returns that read value.

The return is a separate read, rather than reuse of the value that determined the branch. With stable storage, the returned value equals the nonzero value observed by the condition. With intervening mutation, that equality is not guaranteed by the visible logic.

### Zero condition

If the condition read is zero, the established order is:

1. F-8157a180d901 is invoked with the integer argument 60.
2. Its integer result is retained.
3. F-505141fe54e3 is invoked without explicit arguments.
4. After that dependency returns, the retained result is written through the pointer captured at entry.
5. The cell addressed by that captured pointer is read, and the resulting integer is returned.

The second dependency is called regardless of whether the first dependency returns zero or nonzero. There is no visible validity check on the first result before the second call.

The write occurs after both calls have returned. Consequently, F-505141fe54e3 cannot rely on this function having already published the retained result to the captured cell. It may observe a value left there by earlier state or by a dependency, but that value is outside this function’s guarantees.

There is no second zero check after either dependency. If a dependency changes the captured cell, the subsequent assignment still writes the retained result over its then-current contents. If a dependency redirects the global pointer, the assignment still uses the pointer captured before the calls.

### Final read and repeated calls

The return value comes from the final read of the captured cell, not directly from the retained result.

In a normal, stable-memory execution of the zero branch, the final read observes the just-stored result. If defined external interference can occur between the store and read, the visible logic does not require the return value to equal the dependency result.

A zero result is stored without special handling. If it remains zero until a later invocation checks the cell, that later invocation takes the zero branch again. A nonzero result remaining in the checked cell causes later invocations to bypass the dependencies.

Thus the wrapper does not establish one-time initialization. Repeated execution depends on the observed cell value, not on a separate record that initialization was attempted.
