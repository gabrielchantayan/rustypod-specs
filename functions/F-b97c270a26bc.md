# F-b97c270a26bc

## Purpose

F-b97c270a26bc converts an incoming 32-bit value, then either stores a compact encoding in context-selected storage or delegates the operation to F-375c8199e7c2. Two exceptional selectors invoke F-e4e2db384d33 before conversion.

Direct behavior depends on the category, selector, converted value, and externally stored values. Selector recognition alone does not guarantee a direct write: enclosing comparisons and value-mapping conditions must also succeed.

The apparent intent is translation of externally represented settings into internal state. Setting names and object semantics are inferred, not established.

## Interface

### Arguments and result

| Argument | Visible width and interpretation | Role |
|---|---|---|
| Context | 32-bit address-valued integer | Supplies the storage base and is forwarded to fallback. |
| Category | 32-bit integer | Selects the dispatch family. |
| Selector | 32-bit integer | Selects an operation; some unsuccessful mappings normalize it before fallback. |
| Incoming value | Opaque 32-bit quantity | Passed unchanged to F-c9e0501fef5b. |

The conversion dependency supplies a 32-bit integer, called the **converted value** below. Relational integer comparisons use the signed interpretation in the supplied representation.

There is no visible return value or success indicator. Normal completion follows a direct store or return from fallback.

### Addressing and layout

Let **B** denote the context address. At a successful direct-write path, the function reads a 32-bit signed index **J** from **B + 0x24c**. The destination is described using:

**R = B + 0x944 + J × 0x24**

| Offset from R | Width | Meaning established by the write |
|---|---:|---|
| 0x25 | 1 byte | Selector 0x2200 encoding |
| 0x26 | 1 byte | Selector 0x8571 encoding |
| 0x27 | 1 byte | Selector 0x8572 encoding |
| 0x28 plus displacement | 1 byte | First four-value family |
| 0x2b plus displacement | 1 byte | Second four-value family |
| 0x2e plus displacement | 1 byte | Third four-value family |
| 0x31 plus displacement | 1 byte | Two-value family |
| 0x34 | 4 bytes | Converted value without narrowing |
| 0x38 | 4 bytes | Store behind an earlier nonreturning path |
| 0x42 | 1 byte | Zero/nonzero encoding |

The 0x24 stride does not establish a bounded 0x24-byte record. Several offsets exceed it. Symbolically selected families may also produce displacements outside the ordinary three-selector ranges.

These formulas describe the visible address relationships, not permission to assume unlimited-precision arithmetic or freely reassociate overflowing expressions. Exact overflow and address-wrap behavior remain unresolved.

## Behavior

### Entry and conversion

Selector 0x0d1c invokes F-e4e2db384d33. Otherwise, the function evaluates selector minus 0x8500 and invokes that dependency if the result is 0x73, identifying selector 0x8573 under ordinary representable arithmetic.

F-e4e2db384d33 is marked nonreturning. Under that contract, either exceptional selector prevents conversion, direct storage, and fallback. Behavior if the dependency returns is unresolved.

Every other selector causes exactly one visible call to F-c9e0501fef5b with the incoming value. Conversion precedes category-specific external reads and the index read for any direct write. It occurs even for unknown categories and operations that eventually fall back.

The function then forms the context-derived base used by direct writes. This address computation is not itself a read of context memory.

### Category 0x2300: ordered selector dispatch

Dispatch uses ordered comparisons, not an unconditional selector lookup table.

**Primary boundary.** First, the selector is compared for equality with a fresh reading of K1 plus 0x11. Equality enters the second four-value family. If equality fails, a separate K1 reading supplies another K1 + 0x11 expression for a signed less-than comparison:

- A true less-than result enters the lower branch.
- A false result enters the upper branch.

With changing external data, failure of equality followed by failure of less-than does not establish that the selector exceeds the value used in the first comparison.

**Lower branch.** The selector is first compared for equality with a fresh K2 reading. Equality stores the converted value at R + 0x34 as four bytes and returns. If equality fails, a separate K2 reading is compared against the selector:

- If that reading is less than the selector, selectors 0x8580, 0x8581, and 0x8582 enter the first four-value family. Other selectors fall back unchanged.
- Otherwise, the remaining lower-selector dispatch applies.

The remaining lower-selector dispatch recognizes:

- **0x0d1c:** a four-byte store at R + 0x38 is present, but unreachable under the earlier nonreturning contract.
- **0x2200:** its dedicated encoding below.
- **Every other selector:** first capture a fresh K4 reading plus 0x8d as threshold **T**; only then distinguish selectors 0x8571 and 0x8572. Those selectors use their respective encodings. All others fall back unchanged after this threshold evaluation.

Thus, T is computed even for selectors in this branch that match neither encoding. It is not computed on the 0x2200 path, including when that encoding fails.

**Upper branch.** The selector is first compared for equality with a fresh K6 reading. Equality enters the third four-value family. If equality fails, a separate K6 reading supplies a signed selector-less-than comparison:

- If true, selectors 0x8589 and 0x858a enter the second four-value family; otherwise selectors 0x8590 and 0x8591 enter the third four-value family. Other selectors fall back unchanged.
- If false, selectors 0x8598, 0x8599, and 0x859a enter the two-value family. Other selectors fall back unchanged.

Named literal selectors remain subject to all enclosing comparisons. The arithmetic-based recognition of 0x858a and 0x8591 has the same arithmetic qualifications as the exceptional-selector recognition.

### Four-value and two-value families

Tables list checks in precedence order. A successful check performs one byte store and returns. Later checks, including external reads, are skipped.

**First and second four-value families:**

| Ordered converted-value match | Stored byte |
|---|---:|
| 0x1702 | 0 |
| Fresh K1 reading minus 1 | 1 |
| Another fresh K1 reading | 2 |
| 0x8578 | 3 |

| Family | Selector displacement | Destination | Selector passed to fallback if unmatched |
|---|---|---|---|
| First | Original selector − 0x8580 | R + 0x28 + displacement | Displacement |
| Second | Original selector − 0x8588 | R + 0x2b + displacement | Displacement |

K1 reads inside these mappings are separate from the earlier boundary reads and from each other. Entry to the second family through K1 + 0x11 does not constrain its displacement to zero through two.

**Third four-value family:**

| Ordered converted-value match | Stored byte |
|---|---:|
| 0x0300 | 0 |
| 0x0301 | 1 |
| Fresh K5 reading minus 1 | 2 |
| Another fresh K5 reading | 3 |

Its displacement is original selector minus 0x8590. The destination is R + 0x2e + displacement. If unmatched, fallback receives the displacement. Entry through equality with K6 does not establish a small displacement.

**Two-value family:**

| Ordered converted-value match | Stored byte |
|---|---:|
| Fresh K5 reading minus 1 | 2 |
| Another fresh K5 reading | 3 |

Its displacement is original selector minus 0x8598. The destination is R + 0x31 + displacement. If unmatched, fallback receives the displacement.

For these families, normalization affects the selector sent to fallback, not the caller’s argument storage. It introduces no visible memory write.

### Selector 0x2200

This encoding writes at R + 0x25.

- Converted value 0x2100 stores 4.
- Otherwise, a converted value less than 0x2101 is checked in order against:
  - 0x0104, storing 3;
  - 0x0be2, storing 2;
  - a fresh K3 reading, storing 1.
- Otherwise, the checks are:
  - 0x2101, storing 0;
  - 0x8570, storing 5.

Failure falls back with selector 0x2200 unchanged. K3 is read only after both earlier checks in the lower-value branch fail.

### Selector 0x8571

This encoding writes at R + 0x26 and uses **T captured before the selector test**.

- Equality between the converted value and T stores 3.
- Otherwise, if T is less than the converted value, the ordered literal checks are:
  - 0x8575, storing 4;
  - 0x86ae, storing 6;
  - 0x86af, storing 7.
- Otherwise, the ordered checks are:
  - 0x0104, storing 2;
  - a fresh K3 reading, storing 0;
  - 0x2100, storing 1;
  - a fresh K4 reading, storing 5.

T is reused for both its equality and ordering comparisons; those comparisons do not reread K4. The final K4 check is a new read and need not equal the value from which T was formed.

Failure falls back with selector 0x8571 unchanged.

### Selector 0x8572

This encoding writes at R + 0x27. T has already been captured, but the first comparisons obtain additional K4 readings:

- Equality with a fresh K4 reading stores 5.
- If equality fails, a separate K4 reading is tested for being less than the converted value.
  - If true, equality with retained T stores 3; otherwise equality with 0x8575 stores 4.
  - If false, the ordered checks are 0x0104 → 2, a fresh K3 reading → 0, and 0x2100 → 1.

The false ordering branch means the converted value is less than **or equal to the second K4 reading**. With unstable data, it cannot be described simply as “below K4”: equality with that second reading is possible despite failure against the first.

Failure falls back with selector 0x8572 unchanged.

This mapping lacks the explicit 0x86ae and 0x86af literal cases present in the 0x8571 mapping. Those numeric converted values are not categorically excluded: unresolved tokens can equal them.

### Category 0x8861

After conversion, the function reads K7 and retains that value before testing the selector.

- Selector 0x8862 stores one byte at R + 0x42: 0 for a zero converted value, otherwise 1.
- Every other selector invokes fallback using the retained K7 value as its operation argument.

The K7 read therefore occurs even on the successful direct-write path.

### Fallback and other categories

Any other category converts the incoming value and then falls back without category-specific external reads.

Fallback calls F-375c8199e7c2 with this visible argument sequence:

1. Original context.
2. Operation argument 0x0500, except unmatched category 0x8861 uses its captured K7 value.
3. Original selector, or the displacement from a failed normalized family.
4. Converted value.
5. The same converted value again.
6. Three further machine-state-derived quantities whose origins and meanings are unresolved.

The original category is not forwarded as a visible argument. The function makes no explicit direct memory store before fallback.

## Side effects

Every successful direct path performs exactly one store and then returns without fallback. The context index is read only when such a store is reached, after conversion and all mapping comparisons needed for that path. No visible update of the index occurs.

The external-read order is source-visible: boundary equality precedes a separate ordering evaluation; mapping reads occur only when earlier checks fail; T is captured before the 0x8571/0x8572 selector distinction; and K7 is captured before the 0x8862 test. This does not establish hardware-level load timing, volatility, atomicity, or synchronization.

Safe direct execution requires a readable index field and a writable computed destination for the relevant width. No context-null check, index-range check, destination-bound check, or recovery path is visible. Four-byte byte order and alignment requirements are unresolved.

There is no visible allocation, release, ownership transfer, or rollback. Dependency calls may have additional effects. In particular, conversion is not assumed to preserve the context, index, external data, or any memory referenced by the incoming value.

## Acceptance examples

These are conditional criteria, not executed tests. Arithmetic examples assume representable calculations and valid storage.

1. **Exceptional selector dominates.** With selector 0x8573 and any category, F-e4e2db384d33 precedes conversion. If its nonreturning contract holds, nothing later occurs.

2. **Conversion affects destination selection.** If conversion changes the context index and a direct write follows, the destination uses the subsequently read index, not an entry-time snapshot.

3. **Unknown category still converts.** Category 0x1234 with a nonexceptional selector converts once, then falls back with operation 0x0500 and the original selector.

4. **Boolean encoding and early K7 acquisition.** Category 0x8861 and selector 0x8862 read K7 before writing. Converted value −1 stores byte 1 at R + 0x42; zero stores 0. Neither case invokes fallback.

5. **Separate primary-boundary readings.** Suppose selector 0x8580 first encounters K1 = 0x856f, then K1 = 0x8570. The first boundary expression is 0x8580, so equality immediately selects the second family; the second reading is never reached. A contract that snapshots both comparisons or always performs both reads fails this criterion.

6. **Threshold acquisition on an unrecognized selector.** If a nonexceptional selector reaches the remaining lower-selector branch, is not 0x2200, and matches neither 0x8571 nor 0x8572, K4 + 0x8d is still evaluated before unchanged-selector fallback.

7. **Retained threshold differs from later K4.** If selector 0x8571 reaches its encoding with captured T = 0x2200 and converted value 0x2000, its lower branch can store 5 when its later K4 reading is 0x2000, provided earlier checks fail. T is not recomputed.

8. **Separate K4 comparisons in 0x8572.** With captured T = 0x2100 and converted value 0x2100, suppose the equality-stage K4 reading is 0x2000 and the ordering-stage reading is 0x2100. Equality first fails, the ordering comparison is false, and the lower branch can store 1 after earlier checks fail. It does not take the retained-T mapping to 3.

9. **No categorical exclusion of 0x86ae.** If stable K4 equals 0x86ae and selector 0x8572 reaches its encoding, converted value 0x86ae stores 5 at R + 0x27.

10. **Normalized failure.** If selector 0x8581 reaches the first family but matches no token, fallback receives selector 1, operation 0x0500, and two copies of the converted value.

11. **Symbolic entry permits a large displacement.** Entry through the primary K1 equality uses selector minus 0x8588 for the second family. No further displacement bound is imposed.

12. **Ordered collisions.** If a reached four-value family has K1 − 1 equal to 0x1702, converted value 0x1702 stores 0. The earlier literal match prevents the K1 mapping reads.
