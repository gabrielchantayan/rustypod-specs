# F-d4b7b65a5369

## Purpose

F-d4b7b65a5369 validates two selectors, obtains a service object, selects a two-word operation descriptor, and conditionally invokes its target with an adjusted receiver. Some selectors also trigger service calls or shared-state changes independently of whether an operation is invoked.

The supplied static representation establishes **four distinct normal return values**:

| Return value | Established condition |
|---|---|
| 0 | A selected operation returned a result whose low 32 bits were zero. |
| 1 | Prerequisites succeeded, selection did not reject the argument, and no callable descriptor was selected. |
| 2 | A selected operation returned a result whose low 32 bits were nonzero. |
| 4 | Initial validation failed, or selector 5 rejected the argument against an unsigned limit. |

These conditions describe normal completion, including the return of any required cleanup call. Prerequisite failure instead invokes F-a817d8d58c10, represented as non-returning.

Terms such as “service object,” “descriptor,” and “state block” describe structural roles. Their application-level meanings are not established.

## Interface

### Inputs and result

The function accepts four quantities represented with 32-bit widths:

| Input | Interpretation |
|---|---|
| Receiver address | Address used for receiver-relative accesses and as the basis of an adjusted operation receiver. |
| Operation selector | Unsigned integer; valid values are 1 through 9 inclusive. |
| Qualifier | Unsigned integer; valid values are 0 through 9 inclusive and 255. |
| Argument | Unsigned integer supplied to the selected operation, subject to selector-1 normalization and selector-5 rejection. |

The normal result is a 32-bit status. There is no explicit output buffer.

The receiver address is not validated for nullness, alignment, accessible extent, or lifetime. Required validity depends on the accesses reached. Some paths never dereference it; others read a byte at offset `0x2EC`, dereference an adjusted address, or pass it to another function.

### Referenced layouts

All offsets below are byte offsets.

| Structure | Established layout |
|---|---|
| Descriptor table | Reached through a global pointer; selected entries contain two consecutive 32-bit words. |
| State block | Reached through a global pointer; a byte at `0x04` and a 32-bit field at `0x1C` are written on separate paths. |
| Service object | Its first 32-bit word supplies a dispatch-table address. Service calls load targets from that table. |

No broader structure layout, allocation size, alignment guarantee, ownership relationship, or byte order is established.

The descriptor’s first word encodes a direct target or a virtual-table byte offset. Its second word combines a signed receiver adjustment with a low-bit dispatch flag.

## Behavior

### Validation and prerequisite acquisition

Both selector checks precede service acquisition. An operation selector outside 1–9, or a qualifier outside 0–9 and 255, causes an immediate return of 4. No dependency call, descriptor read, or receiver-relative read is shown on that path.

The comparisons are unsigned. A selector or qualifier with bit pattern `0xFFFFFFFF` does not become an accepted negative value.

For valid inputs, both local descriptor words begin at zero. F-be45cd43f92d is called with a 32-bit zero argument, and its returned service pointer is retained both for subsequent calls and in a local slot later exposed to cleanup.

A null service pointer causes F-a817d8d58c10 to be invoked. The readiness function and normal cleanup are not reached first.

For a non-null service pointer, the observable order is:

1. Call F-b7af80e829ec.
2. Retain the current global state-block pointer.
3. Retain the current global descriptor-table pointer.
4. Test the readiness result.

A zero readiness result invokes F-a817d8d58c10. Thus, in the supplied representation, both global-pointer reads occur even when readiness fails.

A nonzero readiness result allows descriptor selection, with provisional status 1.

The retained pointers have distinct later uses: successful operation handling uses the retained state-block pointer, while selector 5 loads its descriptor through the retained descriptor-table pointer. Other descriptor-selection paths reference the global table pointer at selection time.

### Descriptor locations and selector behavior

Descriptor words are loaded in first-word, then second-word order.

| Selector | First-word offset | Second-word offset | Additional behavior |
|---|---:|---:|---|
| 1 | `0x4C` | `0x50` | Normalize argument `0xFFFFFFFF` to zero. |
| 2 | `0x54` | `0x58` | Conditional receiver-byte read. |
| 3 | `0x5C` | `0x60` | Conditional receiver-byte read. |
| 4 | `0x64` | `0x68` | Conditional receiver-byte read. |
| 5 | `0x6C` | `0x70` | Unsigned limit check and optional service call before descriptor loading. |
| 6 | `0x74` | `0x78` | No additional selector-specific action shown. |
| 7 | `0x7C` | `0x80` | Excluded from the success follow-on call. |
| 8 | `0x84` | `0x88` | Conditional state write and service call after descriptor loading. |
| 9 | `0x8C` | `0x90` | No additional selector-specific action shown. |

These reads do not establish an atomic descriptor snapshot or protection against concurrent mutation.

**Selector 1.** An argument of `0xFFFFFFFF` becomes zero before descriptor loading. Every other argument remains unchanged. No other selector performs this normalization.

**Selectors 2, 3, and 4.** Qualifier 255 causes a byte read at receiver offset `0x2EC`, before descriptor loading. Other accepted qualifiers do not cause that read on these paths.

If the byte equals 2, the supplied representation distinguishes argument values 0 through 4 in branches without differentiated observable actions. It establishes no argument remapping, additional call, or write for those branches. The receiver-byte read remains an observable access even though no subsequent behavioral distinction is shown.

**Selector 5.** Before loading a descriptor, the function invokes the service dispatch entry at offset `0x108`, with the acquired service pointer as receiver. Its result is interpreted as an unsigned 32-bit limit.

An argument greater than or equal to that limit is rejected. Status becomes 4, both descriptor words remain zero, and processing reaches cleanup without invoking a selected operation. The optional service call described below is also skipped.

For an argument below the limit, qualifier 255 causes a service call through dispatch offset `0xAC`. That call receives the service pointer and the address of a local 32-bit value initialized to 1. Neither the call’s result nor the local value’s subsequent contents affects the visible control flow.

After the limit check and any optional call, the descriptor is loaded through the table pointer retained after readiness. A service call that changes the global descriptor-table pointer therefore does not redirect this selector’s descriptor reads.

**Selector 8.** Both descriptor words are loaded before reading the receiver byte at `0x2EC`. This byte read occurs for every accepted qualifier.

If the byte equals 2, the function writes the 32-bit value 3 at offset `0x1C` through the then-current global state-block pointer. It then invokes the service dispatch entry at offset `0x74`, passing the acquired service pointer.

The write precedes the service call. Both precede descriptor eligibility testing, so they can occur even when the descriptor cannot invoke an operation. The state write uses the global pointer at this point, not explicitly the pointer retained after readiness.

### Descriptor eligibility and target resolution

A descriptor permits invocation when its first word is nonzero **or** the low bit of its second word is set. A nonzero, even second word alone is insufficient.

If neither condition holds, no selected-operation call occurs. Status remains 1 unless selector 5 already changed it to 4.

For an eligible descriptor, the second word is interpreted as signed 32-bit data and arithmetic-right-shifted by one bit. The resulting signed adjustment is added to the original receiver address in the represented 32-bit address arithmetic. The low dispatch flag is therefore excluded from the adjustment.

No explicit check guards address overflow, alignment, accessible memory, or receiver validity.

Target resolution depends on the second word’s low bit:

- **Clear:** The first descriptor word is used directly as the call target.
- **Set:** The first 32-bit word at the adjusted receiver supplies a table address. Clearing the low two bits of the first descriptor word yields a byte offset into that table; the 32-bit target is loaded there.

The virtual form permits a zero first descriptor word: it selects table offset zero rather than suppressing invocation.

After target resolution, provisional status becomes 2. The target receives the adjusted receiver, the originally acquired service pointer, and the effective argument. The effective argument differs from the input only for selector 1’s `0xFFFFFFFF` normalization.

### Operation result and success handling

The operation result is represented as 64 bits. Only its low 32 bits determine the path:

- A nonzero low word leaves status 2 and proceeds to cleanup.
- A zero low word causes a zero-byte write at offset `0x04` through the retained state-block pointer and establishes status 0.

After that success write, selectors other than 5 and 7 invoke F-c5890456f563 with the **original, unadjusted** receiver address and the **originally acquired** service pointer.

Selectors 5 and 7 omit this follow-on call but still perform the success-byte write and select status 0.

The high 32 bits of the operation result do not determine success and are not substituted for the service pointer passed to F-c5890456f563.

### Cleanup and completion

All normal paths following successful prerequisite checks invoke F-54033250428c with the address of the local service-pointer slot. This includes:

- Non-callable descriptors.
- Selector-5 bound rejection.
- Selected-operation failure.
- Selected-operation success.

The cleanup result is not used to select a status. If cleanup returns normally, the previously established status is returned.

Initial validation failure bypasses cleanup. Neither prerequisite-failure path shows cleanup before its non-returning dependency call.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each normal-return example assumes all reached accesses are valid and all reached dependencies return normally.

1. **Invalid selectors:** Operation selector 0 or 10 returns 4 without acquiring a service object. Qualifier 10 also causes immediate rejection; qualifier 255 passes validation.

2. **Null acquisition:** With valid inputs and null acquisition, F-a817d8d58c10 is invoked. Readiness and normal cleanup are not reached, and no normal status is established.

3. **Zero readiness:** With non-null acquisition and readiness result zero, the state and descriptor global pointers are read before F-a817d8d58c10 is invoked.

4. **Zero descriptor without rejection:** With satisfied prerequisites, selection completed without selector-5 bound rejection, and both selected descriptor words zero, no operation is invoked. Cleanup occurs and the return is 1. Selector-specific effects may already have occurred.

5. **Zero descriptor after rejection:** For selector 5, if the argument fails its unsigned bound check, the initialized descriptor words remain zero, but cleanup is followed by return 4—not 1.

6. **Even adjustment alone:** A zero first word and second word 4 do not permit invocation. Without selector-5 rejection, cleanup is followed by return 1.

7. **Normalization:** Selector 1 with argument `0xFFFFFFFF` supplies zero to an invoked operation. Other selectors do not normalize that pattern; selector 5 may reject it.

8. **Unsigned boundary:** A selector-5 limit of 8 accepts argument 7 and rejects argument 8. Rejection skips the optional `0xAC` call and descriptor loading. A limit of zero rejects every argument.

9. **Direct positive adjustment:** A nonzero direct target and second word 8 invoke that target with the receiver advanced by four bytes.

10. **Virtual offset zero:** First word zero and second word 1 permit invocation through offset zero of the original receiver’s dispatch table.

11. **Negative adjustment:** Second word `0xFFFFFFFC` has a clear dispatch flag and yields an adjustment of −2 bytes.

12. **Low-word success:** A result with zero low word and nonzero high word selects success. It clears the retained state byte and invokes the follow-on dependency unless the selector is 5 or 7. A nonzero low word selects status 2 and omits both success actions.

13. **Selector-8 effects without invocation:** With receiver byte 2 and a non-callable descriptor, selector 8 writes state value 3, invokes service entry `0x74`, then cleans up and returns 1.

14. **Pointer replacement:** If selector 5’s service calls replace the global descriptor-table pointer, descriptor loading still uses the retained pointer. If selector 8’s service call replaces the global state pointer, a later successful operation still clears the byte through the earlier retained state pointer.
