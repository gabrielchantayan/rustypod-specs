# F-70b23748c374

## Purpose

F-70b23748c374 repeatedly searches a mutable, length-prefixed data object for a pattern and invokes a mutation dependency at each discovered position. It terminates normally when its search produces the sentinel position −1.

The apparent intent is repeated replacement: find a pattern, replace the matched extent with another object, and search again. That interpretation is **inferred intent**, not a complete established contract. The comparison and mutation dependencies are not defined by the supplied evidence. In particular, their names, data semantics, allocation behavior, and termination guarantees cannot be inferred.

Established behavior includes these important restrictions:

- Searching begins at offset zero.
- After a match and mutation call, searching resumes at the same numerical offset, not after the replacement and not necessarily from the beginning.
- Pattern and replacement metadata are obtained through caller-supplied slots.
- A pattern-length diagnostic does not itself establish an early return.
- There is no explicit progress check, replacement-count limit, or empty-pattern special case.

The supplied representation uses 32-bit integers, unsigned integers, and address-bearing words. The behavioral description below uses that 32-bit model. It does not establish portability to a different pointer width or ABI.

### Referenced object layout

Each slot supplies a data address. A four-byte metadata word is accessed immediately before that address:

| Relative location | Observed interpretation |
|---|---|
| Data address − 4 bytes | A 32-bit metadata word |
| Data address onward | Data passed to dependencies |

The pattern metadata is treated as an unsigned 32-bit length during searching. The target metadata is also treated as an unsigned 32-bit length for the candidate-bound check.

The replacement metadata is loaded as an address-shaped value and forwarded to the mutation dependency. Although it occupies the same relative position as the other metadata words, this function does not independently establish that it is a byte count.

The function does not establish:

- A terminator requirement.
- Character encoding.
- Element type beyond the byte-offset addressing used for candidate positions.
- Metadata endianness independently of the execution platform.
- Allocation capacity or a complete object-header format.

### Preconditions for defined execution

For every access actually reached:

- The relevant slot must be readable and contain a usable data address.
- The four-byte metadata word preceding that address must be readable.
- Candidate addresses and dependency accesses must be valid under the execution environment.
- Metadata and data must remain coherent enough for the dependencies to operate safely.

There are no visible null checks, bounds-fault recovery paths, or allocation-failure checks. The function does not validate these preconditions.

The target slot is exposed to a dependency that may update it. Whether the slot must be writable, and what other memory must be writable, depends on that dependency’s actual contract.

## Behavior

### Search state

The function maintains a signed 32-bit search-position value, initially zero.

It also maintains two diagnostic-context values:

- Initially, the first is the address of the pattern slot.
- Initially, the second is the address of the replacement slot.

These values change after a successful search and are relevant if a later pattern-length diagnostic occurs.

### Pattern snapshot and diagnostic

At the beginning of each search cycle, the function:

1. Reads the pattern-data address from the pattern slot.
2. Reads the unsigned 32-bit pattern length from four bytes before that data address.
3. Retains that address and length for the current search cycle.

If the pattern length is greater than 0xFFFFFFF1, the function calls F-5829ec5988c0.

The diagnostic call receives, in order:

- The value 8.
- An opaque static address.
- That same opaque static address again.
- The captured unsigned pattern length.
- The threshold 0xFFFFFFF1.
- The current first diagnostic-context value.
- The current second diagnostic-context value.

Thus, lengths from 0xFFFFFFF2 through 0xFFFFFFFF trigger the diagnostic. A length of exactly 0xFFFFFFF1 does not.

No explicit return, retry, or length correction follows the diagnostic call. If the dependency returns normally, searching continues using the pattern address and length already captured for that cycle. Changes made by the diagnostic to the pattern slot do not cause those captured values to be refreshed immediately.

Whether F-5829ec5988c0 normally returns, raises an exception, terminates execution, or performs other actions is unknown.

### Candidate eligibility and comparison

For each candidate position, the function obtains the current target-data address and reads its preceding unsigned 32-bit length word.

A candidate is eligible when:

**the unsigned 32-bit sum of the search position and captured pattern length is less than or equal to the current target length.**

The addition in this comparison is unsigned 32-bit arithmetic because the pattern length is unsigned. Consequently, the sum is reduced modulo 2³². This is not an unbounded mathematical addition or an independently checked bounds calculation.

For an eligible candidate, the function calls F-7f14f1ab6851 with:

- A target candidate address formed from the then-current target-data address plus the search position in bytes.
- The captured pattern-data address.
- The captured unsigned pattern length.

A comparison result of zero is treated as a match. Every nonzero result is treated as a mismatch; its sign and magnitude are otherwise ignored.

On a mismatch, the signed search position is incremented by one, and eligibility is tested again. The next eligibility test rereads the target slot and target length. The pattern address and pattern length remain the cycle’s captured values.

On a zero result, the search stops at that position without incrementing it.

The target address used for a comparison is loaded separately from the target address used to locate the length for the preceding eligibility test. The function does not guarantee that these reads observe the same address if state changes between them.

### Exhaustion and normal return

If the current candidate is not eligible, the function assigns −1 to the search position.

After leaving the search, a position equal to −1 causes an immediate normal return. In this case, no mutation call is made for that cycle.

This sentinel is checked as a signed value. The implementation does not maintain a separate “found” flag.

### Mutation dispatch

If the search position is not −1, the function prepares a mutation call.

It first:

1. Reads the current replacement-data address from the replacement slot.
2. Reads the four-byte metadata immediately preceding that address.
3. Retains that metadata word as the second diagnostic-context value.
4. Sets the first diagnostic-context value to zero.

It then invokes F-07b885b63fa9 with:

- The target-slot address.
- The current search position.
- A freshly read four-byte pattern metadata word, obtained through the current pattern slot.
- A freshly read replacement-data address, obtained through the current replacement slot.
- The previously captured replacement metadata word.

The pattern metadata forwarded here is **not necessarily** the length used for the successful comparison. It is read again through the pattern slot after the search.

Likewise, the replacement-data address forwarded to the dependency is read separately from the address used to obtain the replacement metadata. If the slot changes between those accesses, the two values need not describe the same object.

The supplied evidence does not establish an evaluation order between the separate argument-expression reads of the pattern metadata and replacement-data address. It does establish that the replacement metadata capture and diagnostic-context updates occur before the mutation call.

After the dependency returns normally, the next search cycle begins. The search position retains its existing numerical value. The pattern address and length are captured again.

### Progress and termination

A successful mutation does not automatically advance the search position. This permits another match at the same offset, including a match introduced by the mutation.

It also creates a possible nontermination condition. If the dependencies repeatedly report a match at that position and do not change the relevant state enough to prevent another match, the function can continue indefinitely.

There is no explicit treatment of a zero-length pattern. Such a pattern participates in the same eligibility check and is passed to the comparison dependency with length zero.

## Side effects

The function directly performs slot and metadata reads. It does not itself visibly write into the target, pattern, or replacement objects.

Observable mutations are delegated to dependencies:

- F-5829ec5988c0 may have diagnostic or exceptional effects.
- F-7f14f1ab6851 determines whether a candidate is accepted.
- F-07b885b63fa9 receives the target-slot address and may alter state used by subsequent cycles.

No dependency is known to be pure. The function must not be described as preserving globals, preserving the pattern and replacement objects, or leaving unrelated state unchanged merely because it does not directly write those locations.

There are no explicit allocation, release, or ownership-transfer operations in this function. Passing a data address or slot address does not establish whether a dependency borrows, retains, reallocates, or releases the referenced storage.

Aliasing is not rejected. The three slots, their referenced objects, or their metadata may overlap. The effects of such overlap depend on the dependencies and the actual read/write sequence; snapshot consistency is not guaranteed.

If a dependency fails to return normally, later search steps and mutation calls are not guaranteed to occur. No rollback mechanism is visible.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not runtime-test results.

### No eligible initial candidate

Given a stable target length of 3 and a captured pattern length of 4, the initial unsigned sum is 4.

Expected behavior:

- No comparison call occurs.
- No mutation call occurs.
- The function returns normally.

This case assumes all required slot and metadata reads are valid.

### First match occurs after one mismatch

Given stable metadata, target length 5, and pattern length 2:

- If the comparison at offset 0 returns nonzero, the next candidate is offset 1.
- If the comparison at offset 1 returns zero, the mutation dependency receives position 1.
- Following a normal mutation return, the next search starts at position 1, with pattern address and length recaptured.

The next search does not automatically begin at position 3.

### Last ordinary eligible candidate

Given stable target length 5 and pattern length 2, without arithmetic overflow:

- Offsets 0 through 3 are eligible.
- If every comparison returns nonzero, offset 4 fails eligibility.
- The function returns without a mutation call.

### Diagnostic boundary

For a captured pattern length of 0xFFFFFFF1, no length diagnostic is triggered.

For a captured pattern length of 0xFFFFFFF2:

- F-5829ec5988c0 is called before the candidate search.
- If it returns normally, the function continues with the captured length 0xFFFFFFF2.
- The diagnostic alone does not force normal return.

### Empty-pattern behavior

Given a captured pattern length of zero and an initial position of zero, the initial candidate is eligible for every unsigned target length, including zero.

If F-7f14f1ab6851 returns zero:

- The mutation dependency is called at position zero.
- After normal return, another search begins at position zero.
- Termination depends on subsequent metadata and dependency behavior.

### Pattern metadata changes during comparison

Suppose the comparison dependency changes the pattern slot or its metadata and then returns zero.

Expected behavior:

- The comparison itself used the cycle’s captured pattern address and length.
- The mutation call obtains its pattern metadata through a fresh read.
- The mutation argument may therefore differ from the length used for matching.

This caller supplies no consistency check between those values.

### Diagnostic context after a mutation

If one mutation call has already been prepared and completed, and the next cycle captures an oversized pattern length, the diagnostic receives:

- Zero as its first context value.
- The replacement metadata captured before the preceding mutation as its second context value.

Those context values are not restored to the original slot addresses.
