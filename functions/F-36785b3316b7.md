# F-36785b3316b7

## Purpose

F-36785b3316b7 replaces three references in a target record, derives a 32-bit value from the referenced records, and conditionally inserts the target into an indexed list.

The established behavior is an ordered sequence of dependency calls, memory accesses, and conditional updates. Dependencies run before the existing reference slots are inspected or replaced. Their effects can therefore change subsequent observations.

**Inferred intent:** the references may describe child relationships, the derived value may represent height or rank, and the indexed lists may group records by that value. Dependency calls may participate in reference accounting. These interpretations do not establish ownership, lifetime, or structural consistency.

**Arithmetic limitation:** deriving the value uses unsigned arithmetic, but recovering the insertion index uses a signed subtraction. If the reread derived field represents the minimum signed 32-bit integer, that subtraction overflows. Wrapping behavior at that point is not established without additional machine-level evidence.

## Interface

### Arguments and result

The function accepts four arguments represented as 32-bit words:

| Argument | Established role |
|---|---|
| Target | Address of the record being modified. |
| First reference | Passed to a dependency, stored at target +32, and read at reference +8. |
| Second reference | Passed to a dependency, stored at target +24, and read at reference +8. |
| Third reference | Passed to a dependency, stored at target +28, and read at reference +8. |

The representation uses these words as addresses and stored references. This contract uses its apparent 32-bit integer and address model; it does not independently establish an ABI.

There is no explicit return value. Observable results consist of dependency effects, field changes, and possible indexed-list insertion.

### Record layout

Offsets are byte offsets from the indicated address.

| Target offset | Width | Established use |
|---|---:|---|
| +8 | 32 bits | Receives the derived unsigned value; subsequently reread as signed for index subtraction. |
| +12 | 32 bits | Cleared during insertion; also the field updated in a successor. |
| +16 | 32 bits | Receives the previous indexed head and is reread for the successor update. |
| +20 | 8 bits | Bit 0 gates insertion and is set during insertion. |
| +24 | 32 bits | Second-reference slot. |
| +28 | 32 bits | Third-reference slot. |

Each supplied reference must support the reached 32-bit read at offset +8. The table contains 32-bit entries with four-byte spacing.

These accesses do not establish complete record sizes, allocation boundaries, alignment requirements, endianness, or ownership.

### Global indirection

A global pointer identifies a cell containing a 32-bit word. The function evaluates this pointer twice before the first dependency call:

1. It captures the pointer value for a later cell read.
2. It separately evaluates the global pointer again and reads the cell selected by that second evaluation.

The second evaluation supplies the first argument to F-03b9616af95f. That argument is not explicitly obtained through the captured pointer.

Later, the function reads through the captured pointer to obtain the potential insertion table base. It does not reevaluate the global pointer then.

The two initial evaluations select the same cell only under a stability assumption. Even if they select the same cell, dependencies can change its contents before the later read.

### Preconditions and errors

There is no explicit validation, error result, or recovery path.

Successful execution requires valid storage for every access when reached:

- Target reference slots and the derived-value field.
- All three supplied references at offset +8, even when insertion is skipped.
- The cell selected by the second initial global-pointer evaluation.
- The cell selected by the captured initial pointer.
- The flags byte when the index passes the signed gate.
- Target link fields and the selected table entry when insertion proceeds.
- The successor’s +12 field when the final link check requires an update.

Capturing a pointer does not itself dereference its cell. The two global-cell validity requirements are independent.

Valid storage alone is insufficient to establish defined execution: signed arithmetic, pointer interpretation, and dependency-specific requirements must also be satisfied. In particular, the signed index subtraction must not overflow unless a separately established machine-level contract supplies wrapping semantics.

## Behavior

### 1. Capture global state and invoke dependencies

The function captures the global pointer, then separately reads a word through a fresh evaluation of that pointer.

It calls F-03b9616af95f with:

1. The word obtained through the fresh global-pointer evaluation.
2. The target address.

It then calls F-2609ef4ae406 three times, with the first, second, and third references, in that order.

There is no deduplication or explicit null check. Equal references still cause three calls.

These calls precede every explicit inspection of the target’s existing reference slots. Their implementations are unavailable. They must not be assumed to preserve the target, supplied records, global pointer, captured cell, or other relevant memory.

Changing the captured cell’s contents can change the later table base. Changing only the global pointer after capture does not redirect the later read through the captured pointer.

### 2. Inspect existing reference slots

After those calls return, the function performs these conditional actions in order:

1. Read target +32; call F-029930293dcb if nonzero.
2. Read target +24; call F-029930293dcb if nonzero.
3. Read target +28; call F-029930293dcb if nonzero.

Each later read occurs after any preceding conditional call returns. The checks therefore do not form a snapshot.

Between zero and three calls occur. No explicit arguments are supplied to F-029930293dcb. In particular, the observed old reference is not explicitly passed to it.

The slots are not explicitly cleared before these calls. Release, destruction, and hidden-argument behavior remain unknown.

### 3. Replace references

The function performs three 32-bit writes in this order:

1. Store the second reference at target +24.
2. Store the third reference at target +28.
3. Store the first reference at target +32.

These are separate writes, not an atomic replacement. Their order matters when storage overlaps or intermediate states are observed.

### 4. Derive the new value

After replacing all three slots, the function reads unsigned 32-bit values in this order:

1. Second reference +8.
2. Third reference +8.
3. First reference +8.

It selects their unsigned maximum and writes that maximum plus one to target +8.

If the observed maximum is \(M\), the stored value is:

\[
D=(M+1)\bmod 2^{32}.
\]

This increment is unsigned. Its wrap at `0xFFFFFFFF` is established under the represented 32-bit model.

Values with bit 31 set exceed values with bit 31 clear in the maximum comparison. The observations occur after reference replacement, not at entry. Aliasing with modified storage can therefore affect them.

### 5. Read the table base and attempt to recover the index

After writing the derived value, the function:

1. Reads a 32-bit word through the captured pointer.
2. Retains that word as the potential table base.
3. Rereads target +8 as a signed 32-bit integer.
4. Subtracts signed one.
5. Assigns the subtraction result to an unsigned 32-bit index.

The unsigned destination does **not** make the preceding subtraction unsigned.

Under a two’s-complement 32-bit interpretation:

- Every signed reread other than −2,147,483,648 permits subtraction of one without signed overflow.
- A reread word of `0x80000000` represents −2,147,483,648. Subtracting one overflows the signed range.
- Conversion of a valid negative subtraction result to unsigned produces its corresponding modulo-\(2^{32}\) value.

With non-overlapping storage and no intervening mutation, the index equals \(M\) whenever this subtraction is defined. That includes \(M=\texttt{0xFFFFFFFF}\): the derived field is zero, signed subtraction produces −1, and unsigned conversion produces `0xFFFFFFFF`.

The exceptional maximum is `0x7FFFFFFF`. Its unsigned increment stores `0x80000000`, making the subsequent signed subtraction overflow. The representation alone does not establish a resulting index, insertion decision, or completed execution for that case.

Under an **additional wrapping machine-level interpretation**, that subtraction would produce index `0x7FFFFFFF`. This is conditional behavior, not an established guarantee. Any aliasing or mutation that makes the reread field `0x80000000` creates the same unresolved boundary, regardless of the earlier maximum.

### 6. Gate insertion

For an index obtained without the unresolved overflow, the representation converts the unsigned index to signed and tests whether it is nonnegative.

Under the conventional two’s-complement interpretation:

- If bit 31 is set, insertion is skipped without reading the flags byte.
- Otherwise, the function reads target +20.
- If bit 0 is set, insertion is skipped.
- If bit 0 is clear, insertion proceeds.

For high-bit-set unsigned values, the exact unsigned-to-signed conversion behavior is target-dependent. The high-bit description relies on the represented target’s conventional signed interpretation, not on a universally portable conversion rule.

The captured-cell read and target +8 reread occur before either ordinary insertion-skip path. Skipping insertion does not undo dependency effects, reference replacement, or the derived-value write.

The signed gate is not a capacity check.

### 7. Insert into the indexed list

For an insertion path with a valid index, the entry address is formed from the table base plus four times the index. The unsigned scaling and combination use 32-bit arithmetic in the represented model. This does not establish valid storage at the resulting address.

The explicit access order is:

1. Write a zero 32-bit word to target +12.
2. Read the selected table entry.
3. Store that entry’s value at target +16.
4. Store the target address in the selected table entry.
5. Read target +20 and write that byte back with bit 0 set.
6. Read target +16.
7. If nonzero, reread target +16 and write the target address at offset +12 of the record selected by this final read.

The flag update preserves the other seven bits as observed by its own read. It is a byte write.

With non-overlapping storage and no intervening mutation, the target becomes the indexed head, its previous link is zero, its next link is the old head, and a nonzero old head receives the target as its backlink.

For overlapping storage, the access sequence controls. The final successor address is reread from target +16; it is not guaranteed to remain the original table-entry value.

## Side effects

Before the insertion decision, the represented sequence writes target +24, +28, +32, and +8.

On an ordinary insertion-skip path, there are no later explicit writes. On an insertion path, it additionally writes:

- Target +12 and +16.
- The selected table entry.
- Target’s flags byte.
- A successor’s +12 field, conditionally.

These sequence descriptions do not supply a defined-execution guarantee for the signed-overflow case.

There is no explicit allocation, deallocation, table growth, bounds check, lock, transaction, rollback, or removal from a previous list. Unknown dependencies may have additional effects.

Storing references does not establish ownership transfer. Neither dependency family establishes acquisition, release, or destruction without its implementation. Storage needed later must remain valid; no dependency preservation guarantee is available.

An already-set insertion flag suppresses only insertion. References and the derived value are still replaced on an otherwise defined execution. If the flag denotes membership, this function does not establish that existing membership remains consistent with the new value.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, assume valid non-overlapping storage, stable global-pointer evaluations, dependencies preserving relevant memory, no concurrent mutation, sufficient table storage, and the represented conventional 32-bit signed interpretation.

1. **Empty-entry insertion.**  
   Referenced values are 2, 5, and 3. Old slots are zero, flag bit 0 is clear, and entry 5 is zero. The target receives the supplied references and derived value 6. Entry 5 becomes the target; both target links become zero; flag bit 0 becomes set. F-029930293dcb is not called.

2. **Insertion before an existing head.**  
   The maximum is 4, flag bit 0 is clear, and entry 4 identifies a different valid record. The derived value becomes 5. The target’s +16 receives the old head, its +12 becomes zero, entry 4 receives the target, and the old head’s +12 receives the target.

3. **Existing membership flag.**  
   The maximum is 7 and flag bit 0 is set. References are replaced and the derived value becomes 8. The captured cell is read, but no insertion writes occur.

4. **High-bit index without subtraction overflow.**  
   The maximum is `0x80000000`. The derived value becomes `0x80000001`. Signed subtraction is representable and produces the unsigned index `0x80000000` after conversion. Under the stated signed-conversion interpretation, insertion is skipped without a flags-byte read.

5. **Unsigned increment wrap.**  
   The maximum is `0xFFFFFFFF`. The derived value becomes zero. Signed subtraction yields −1, converted to unsigned index `0xFFFFFFFF`. Insertion is skipped under the stated signed-conversion interpretation.

6. **Signed-overflow boundary: unresolved without additional evidence.**  
   The maximum is `0x7FFFFFFF`. The unsigned derivation produces `0x80000000`, but its signed reread followed by subtraction of one overflows. No resulting index or insertion outcome is established. If wrapping machine arithmetic is separately established, the index would be `0x7FFFFFFF`; with flag bit 0 clear, insertion would then proceed. Its four-byte displacement would be `0xFFFFFFFC` modulo \(2^{32}\), which still supplies no bounds guarantee.

7. **Old-slot checks observe changes.**  
   Target +32 is nonzero and causes F-029930293dcb to run. If that call changes target +24 to zero, the next check observes zero and makes no call for that slot.

8. **Duplicate references retain call multiplicity.**  
   All supplied references are equal. F-2609ef4ae406 still receives three calls, and all three slots receive that address.

9. **Captured-cell contents change.**  
   Both initial global evaluations select cell A. A dependency changes A’s word before the later read. The first dependency receives A’s earlier word; the potential table base comes from its later word.

10. **Initial evaluations select different cells.**  
    Conditional on an environment permitting the pointer to change between evaluations, capture selects A and the second evaluation selects B. The first dependency receives B’s word; the later table-base read uses A. This does not establish defined concurrent-access semantics.

11. **Global pointer changes after capture.**  
    Both initial evaluations select A. A dependency changes only the global pointer to identify B. The later table base is still read from A.
