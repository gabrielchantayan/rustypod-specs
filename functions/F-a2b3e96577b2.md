# F-a2b3e96577b2

## Purpose

F-a2b3e96577b2 conditionally replaces one four-byte field in an indexed record collection associated with an object.

The established behavior is a guarded memory update: a null object address, a negative index, an index at or beyond a stored signed bound, or a zero collection address prevents the write. An accepted index selects a record with a 20-byte stride, and the function writes the supplied four-byte value at byte offset 8 within that record.

Interpreting the stored bound as a record count and the records as an array is inferred intent. The supplied representation establishes the comparisons and address calculation, but does not establish the surrounding object type, allocation sizes, or semantic meaning of the updated field.

The function returns no result and provides no explicit success or failure status.

### Preconditions for defined memory access

A zero object address requires no accessible object storage. Likewise, a negative index does not require object storage to be readable, because that path does not dereference the object.

For a nonzero object address and nonnegative index, the four-byte field at object offset 12 must be readable. If the index passes the bound check, the four-byte field at object offset 20 must also be readable.

If the collection address check succeeds and the write is reached, the resulting target field must be writable, and the address arithmetic must be meaningful in the execution environment. The function does not independently establish these conditions.

There is no established alignment, allocation-extent, or concurrency guarantee.

## Behavior

### Early rejection

A zero object address causes immediate return. The function does not read the bound, inspect the collection address, or write the replacement value on this path.

For a nonzero object address, a negative index also causes return without accessing object memory. The fourth argument does not provide an alternative bound for this case.

These are behavioral no-ops, not reported errors.

### Bound inspection and index eligibility

For every nonnegative index and nonzero object address, the function reads the signed four-byte bound at object offset 12.

Eligibility requires both:

- The index is nonnegative.
- The index is strictly less than the bound.

The upper boundary is exclusive. An index equal to the bound is rejected, even though a separate comparison in the supplied representation also considers whether the index is no greater than the bound.

Consequences include:

- A positive bound permits indices from zero through one less than that bound.
- A zero bound permits no indices.
- A negative bound permits no indices.
- Index zero is accepted only when the stored bound is positive.
- No interpretation of the index or bound as unsigned is supported by the supplied comparisons.

An ineligible index causes return before any collection-address read. Reading the bound does not itself authorize access to the records.

The caller-supplied fourth argument is not consulted as an effective bound. On nonnegative-index paths, the stored bound determines eligibility; on negative-index paths, the function returns without using that argument to authorize a write.

### Collection-address inspection

After the index is accepted, the function reads the four-byte collection-address field at object offset 20 and compares it with zero.

If that read yields zero, the function returns without writing any record field.

If that read yields a nonzero value, the supplied representation reads the collection-address field again while forming the write destination. Thus, the shown behavior contains two collection-address reads on the write path: one for the nonzero check and another for destination calculation.

There is no explicit second nonzero check on the address used for the destination calculation. If the collection-address field can change between those reads, the first check does not establish the validity of the later address. The supplied material provides no synchronization mechanism or stability guarantee. Whether a particular compiled execution retains both reads is not established by this representation alone.

### Destination and update

For an accepted index and a successful collection-address check, the intended destination is:

- The collection address obtained for destination calculation;
- Advanced by 20 bytes for each indexed record;
- Advanced by a further 8 bytes to reach the selected field.

The function writes exactly four bytes of replacement data at that destination in the supplied operation model. It does not first read the previous field value.

The replacement value is not range-checked, decoded, merged with existing bits, or used to select a write width. No other record field is intentionally updated.

After the write, the function returns.

### Arithmetic boundaries

The index and stored bound are compared as signed 32-bit quantities. The record stride is 20 bytes, and the final field displacement is 8 bytes.

The signed eligibility check alone does not prove that address calculation is safe. For a sufficiently large accepted index, multiplying by 20, adding the field displacement, or adding the resulting displacement to the collection address may exceed the relevant integer or address range.

The supplied representation does not establish a checked-arithmetic policy, a reliable wrapping rule, or a defined outcome for such cases. A caller requiring predictable memory access must provide an index and addresses for which the calculation is valid and the target lies within writable storage. Large-index overflow behavior remains documented_only rather than an acceptance guarantee.

The visible access order is:

## Acceptance examples

These are conditional acceptance criteria derived from static inspection, not runtime test results. Unless stated otherwise, addresses are readable or writable as required, arithmetic is valid, and the collection-address field remains stable.

1. **Absent object.** With a zero object address, any index, replacement value, and fourth argument produce a return without object or record access.

2. **Negative index.** With a nonzero object address and index −1, the function returns without reading the bound or collection address. The object need not be dereferenceable for this path.

3. **Empty collection.** With index zero and stored bound zero, the function reads the bound and returns. It does not read the collection address.

4. **Negative bound.** With index zero and stored bound −1, no index is accepted. The collection-address field is not read.

5. **Exclusive upper boundary.** With stored bound 3 and index 3, the function returns after reading the bound. No record is written.

6. **First record.** With stored bound 3, index zero, and a nonzero collection address, the replacement is written to the four-byte field 8 bytes after the collection base.

7. **Last eligible record.** With stored bound 3 and index 2, the selected field begins 48 bytes after the collection base: two 20-byte strides plus the 8-byte field offset.

8. **Missing collection storage.** With stored bound 3, index 1, and a zero collection-address field, the function returns without writing. Bound eligibility does not override the zero-address check.

9. **Fourth-argument independence.** Under otherwise identical valid conditions, changing only the fourth argument does not change eligibility, destination, or replacement data.

10. **Replacement bits.** On a valid write path, an all-zero four-byte replacement is written as zero bits; it is not treated as a request to skip or delete the record.
