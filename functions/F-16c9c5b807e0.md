# F-16c9c5b807e0

## Purpose

F-16c9c5b807e0 evaluates a predicate over five fields in a supplied memory object. On normal completion, it returns either zero or one.

The predicate consists of two condition groups. Each group contains two alternatives evaluated with short-circuit semantics. The function returns zero only when both groups succeed; otherwise it returns one.

**Established behavior:** the predicate combines signed comparisons, signed addition, unsigned 32-bit subtraction, and conversion of one unsigned subtraction result to a signed value.

**Inferred intent:** the fields might describe positions, extents, adjustments, or bounds. Those meanings are not established. This contract uses descriptive field labels solely to distinguish the accesses. Neither return value is established as meaning “valid,” “inside,” “visible,” or “error.”

## Behavior

### First condition group

The first group succeeds if either of the following is true, in this order:

1. The signed sum of Extent and Adjustment is less than or equal to signed Position.
2. Signed Extent is less than one.

The second alternative is evaluated only if the sum comparison is false.

Consequences:

- Equality between Position and the sum satisfies the group.
- If the sum comparison fails, zero or negative Extent still satisfies the group.
- A nonpositive Extent does not avoid evaluation of the preceding addition.
- If the sum comparison fails and Extent is positive, the group fails. The function returns one without evaluating the second group.

The addition is not shown as checked or saturating. This contract does not assign wrapping semantics to an out-of-range signed sum.

### Second condition group

The second group is evaluated only when the first group succeeds. It succeeds if either of the following is true, in this order:

1. Signed Position is less than or equal to the signed conversion of the unsigned 32-bit difference between Limit and Adjustment.
2. The unsigned 32-bit difference between Count and one is less than or equal to unsigned Limit.

The Count-based alternative is evaluated only if the Position-based comparison is false.

The arithmetic domains differ between these alternatives.

For the first alternative:

- Adjustment is converted to unsigned 32-bit form.
- It is subtracted from unsigned Limit.
- The subtraction is modulo \(2^{32}\).
- The unsigned result is converted to signed form.
- Position and that converted result are compared as signed values.

For the second alternative:

- Count is converted to unsigned 32-bit form because the subtraction uses an unsigned one.
- Subtracting one is modulo \(2^{32}\).
- The result is compared with Limit as an unsigned value.

A negative stored Count therefore does not remain a negative operand in the final comparison. Likewise, a negative Adjustment participates in the unsigned subtraction through its unsigned conversion.

### Result selection and short-circuiting

The return selection is:

| First group | Second group | Result |
|---|---|---:|
| Fails | Not evaluated | 1 |
| Succeeds | Fails | 1 |
| Succeeds | Succeeds | 0 |

Within either group, a successful first alternative skips its second alternative.

Consequently, Count is relevant only when the first group succeeds and the first alternative of the second group fails. Limit participates only after the first group succeeds.

No separate error path, diagnostic emission, or third return value is shown.

### Integer boundaries

Unsigned subtraction wraps modulo \(2^{32}\); underflow is not a checked error.

Specific consequences include:

- Count equal to zero produces `0xffffffff` after subtracting one. The final unsigned comparison then succeeds only when Limit is also `0xffffffff`.
- Count equal to one produces zero. If this alternative is reached, it succeeds for every unsigned Limit.
- Count stored as −1 converts to `0xffffffff`, then becomes `0xfffffffe` after subtraction.
- Limit minus Adjustment can wrap even when the signed addition in the first group is representable.
- Converting a negative Adjustment to unsigned and subtracting it can produce a small positive result. For example, Limit zero minus Adjustment −1 produces unsigned one.

The signed conversion following Limit minus Adjustment is a separate boundary:

- Results from zero through `0x7fffffff` are representable as signed 32-bit values.
- Results from `0x80000000` through `0xffffffff` require the target’s conversion rule.

Same-width two’s-complement reinterpretation would make the latter values negative, but that rule is not independently established by the supplied evidence. The contract therefore does not silently apply it.

Likewise, signed overflow in Extent plus Adjustment remains unresolved. A later successful comparison of Extent against one does not remove that earlier arithmetic issue.
