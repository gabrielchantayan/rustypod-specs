# F-e1c0335c1ea5

## Purpose

F-e1c0335c1ea5 exposes a software-interrupt boundary followed, if execution returns normally to the continuation, by construction of a 64-bit result.

The established behavior is narrow:

- An eight-byte automatic storage object is represented within the invocation.
- A software interrupt is requested with selector `0x123456`.
- After normal continuation, the result’s low 32 bits are `0x0000000A`.
- The result’s high 32 bits are formed from the address-like value associated with that automatic storage object.

The source does not establish the interrupt’s purpose, the meaning of the constant ten, or a useful external interpretation of the address-derived field. In particular, the function must not be described as returning an interrupt status, an eight-byte buffer, or a pointer to retained storage.

This is a source-facing behavioral contract. It records what the supplied representation supports, distinguishes interpretation from evidence, and leaves runtime-dependent behavior unresolved. No runtime tests have been performed.

## Behavior

### Invocation-local storage

The representation declares an automatic object with a total size of eight bytes. Its elements have one-byte storage width.

There is no explicit initialization of this object and no represented assignment to its contents. There is also no represented operation that reads its elements to construct the result.

The distinction between the object’s contents and its address is essential. The return construction uses the array expression as an address-like operand for a four-byte field. It does not visibly load four or eight bytes from the object.

Consequently, the source does not support describing the upper result field as an uninitialized byte sequence read from the object. It supports an address-derived interpretation, subject to the limitations of the supplied representation.

The declaration appears before the interrupt request. This is not evidence of a particular physical stack-allocation instruction, allocation size after alignment, or ordering of stack-pointer adjustments in executable code.

The interrupt’s outcome is not examined. There is no represented status comparison, success check, retry, fallback, or conversion of an interrupt result into the low return field.

### Normal continuation and result construction

If the interrupt returns normally and execution proceeds to the represented return operation, the function combines:

1. An address-derived four-byte value as the upper 32 bits.
2. The constant ten as the lower 32 bits.

The low field is fixed on this path. The representation does not make it conditional on a status code, memory contents, or any explicit output from the interrupt.

The upper field is invocation-dependent insofar as it reflects an automatic object’s address. The source supplies no fixed address and no rule requiring different invocations to produce distinct upper fields. Reuse of an address across calls is not excluded.

The representation also does not establish how an address wider than 32 bits would be converted into the upper field. It would be unjustified to prescribe truncation, rejection, or any particular pointer conversion for an unspecified wider-address environment.
