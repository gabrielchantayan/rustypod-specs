# F-665f1a441b03

## Behavior

### Null descriptor

If the second argument is null, the function returns immediately.

On this path, it does not read descriptor memory, read a record, or invoke F-cf8121d269c4. The other arguments do not affect this decision.

### Traversal and termination

For a non-null descriptor, traversal begins at index zero. The index is local traversal state; it is not stored in the descriptor.

Before each potential iteration, the function reads the descriptor’s current signed count and compares the index against it. An iteration proceeds only while the index is strictly less than that count.

Consequently:

- An initial count of zero produces no dependency calls.
- An initial negative count produces no dependency calls.
- A positive count permits traversal, subject to later count reads and valid memory access.
- The function does not convert a negative count into an unsigned large count.
- The function does not cache the initial count as a fixed traversal limit.

For each iteration that proceeds, the function reads the current record-storage base from descriptor offset 12. It selects the record at that base plus 12 times the current index, then reads exactly one 32-bit value from the selected address.

It invokes F-cf8121d269c4 with these positional arguments:

1. The original first argument.
2. The selected record’s first 32-bit value.
3. The original third argument.
4. The original fourth argument.

The dependency receives the record value, not an explicitly constructed pointer to the record. That value may itself represent an address, but this function does not establish or inspect such a meaning.

After a dependency invocation returns normally, the traversal index advances by one. The next loop condition reads the descriptor count again. Any dependency result is ignored by this function.

When the index is no longer less than the latest count, the function returns without a further dependency call.

### Observable access order

The relevant order for a single iteration is:

1. Read the descriptor count for the loop condition.
2. If the comparison permits traversal, read the descriptor’s record-storage base.
3. Read the first 32-bit value of the selected record.
4. Invoke F-cf8121d269c4.
5. After normal return, advance the index and evaluate the next loop condition.

The count read that admits an iteration occurs before its dependency call. A dependency-induced count change therefore affects a later condition, not the already admitted call.

The record value is also read before the dependency invocation. If the dependency changes that record during the invocation, the argument already supplied to that invocation remains the previously read value.

The function contains no explicit descriptor or record writes. This does not establish that those objects remain unchanged across dependency calls.

### Mutation during traversal

Because count and base reads are repeated, dependency side effects can alter traversal:

- Reducing the count can terminate traversal earlier than the original count would suggest.
- Increasing the count can admit additional iterations.
- Replacing the base can redirect later record reads to another region.
- Changing a future record’s first word can change the argument supplied when that index is reached.

A base change does not reset the index. If the first dependency invocation changes the base, the next iteration uses index one relative to the replacement base, not index zero.

No snapshot, restart, deduplication, or consistency check is present. The function does not establish safety if the dependency invalidates memory needed by a later read. It also provides no explicit synchronization for concurrent mutation.

The record stride is 12 bytes, and each selected payload is 32 bits. These are distinct: traversal does not treat records as a packed array of four-byte values.

The count and index comparison are signed in the supplied representation. The record displacement is formed by multiplying the index by 12.

These are conditional acceptance criteria derived from static evidence, not executed tests. Non-null examples assume valid storage and representable arithmetic unless stated otherwise.

### Zero or negative initial count

### Count reduced after the first call

Given an initial count of three, suppose the first dependency invocation changes the count to one and returns normally.

The index then becomes one. The next comparison against count one terminates traversal. Exactly one dependency call occurs.

### Count increased after the first call

Given an initial count of one, suppose the first dependency invocation changes the count to three and returns normally. If the count then remains three and the required storage is valid, calls for indices one and two also occur.

This distinguishes live-count traversal from an initial-count snapshot.

### Base replaced after the first call

Given initial count two, suppose the first invocation replaces the base while leaving the count at two.

The second record read uses the replacement base plus 12 bytes. It does not use the replacement base itself, and it does not continue from the old base.

### Future payload changed

Given count two, suppose the first invocation changes the first word of the record at index one. The second invocation receives that changed word if no intervening action changes it again.

### Storage invalidated by the dependency

Suppose a dependency invocation makes the descriptor unreadable before the next condition is evaluated. The function has no visible guard against the subsequent count read. No graceful return or recovery is guaranteed by this contract.
