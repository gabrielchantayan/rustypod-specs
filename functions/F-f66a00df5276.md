# F-f66a00df5276

## Purpose

F-f66a00df5276 conditionally locates an indexed record in a caller-supplied memory region and reports three values: the record’s address, an address calculated from its encoded length, and a signed 16-bit difference between that calculated position and a neighboring directory value.

The apparent intent is to separate a length-prefixed portion of a record from a remaining span. That interpretation is inferred. The established behavior is address calculation and memory access; the function does not validate a complete record format or establish that the reported span belongs to a valid object.

The function returns zero after performing the successful-path writes. It returns `0x20` when the unsigned index is not less than a stored 16-bit count. No other ordinary return path is shown.

## Interface

The interface has six arguments:

| Position | Contract role | Width and interpretation |
|---|---|---|
| 1 | Descriptor address | Address represented by a 32-bit argument. Descriptor fields are read at byte offsets `0x1c` and `0x30`. |
| 2 | Region base address | Address represented by a 32-bit argument. The count, directory entries, and record data are accessed relative to this base. |
| 3 | Record index | Unsigned 32-bit integer. |
| 4 | Record-address destination | Address of a writable 32-bit output slot. |
| 5 | Calculated-address destination | Address of a writable 32-bit output slot. |
| 6 | Difference destination | Address of a writable 16-bit output slot, exposed as a signed 16-bit result. |

The return value is a 32-bit quantity:

- `0`: all three output writes have been reached and completed normally.
- `0x20`: the index failed the count comparison.

The first two arguments identify storage but carry no explicit storage lengths. The function performs no null, alignment, accessibility, or region-size checks.

Relevant memory fields are:

| Location | Width | Interpretation |
|---|---:|---|
| Region base + `0x0a` | 16 bits | Unsigned record count. |
| Descriptor + `0x1c` | 16 bits | Unsigned directory anchor offset. This field is read separately at two points on the successful path. |
| Descriptor + `0x30` | 32 bits | Flags. Only mask `0x00000002` controls the length interpretation. |
| Directory locations | 16 bits each | Region-relative offsets. The first is interpreted unsigned; the later one is loaded as signed for the difference calculation. |
| Located record address | 16 bits in the supplied expression | Length-bearing value. Depending on the flag, either its low eight bits or all sixteen bits contribute to the calculation. |

Multi-byte byte order is not established by the supplied material. The contract therefore describes integer values after interpretation according to the target’s memory representation, rather than prescribing serialized bytes.

Callers must provide readable and writable storage for the accesses actually taken. For the successful path, this includes the directory entry beyond the selected entry, even when selecting the last count-permitted record.

## Behavior

### 1. Index gate

The function first reads the unsigned 16-bit count at region base + `0x0a` and compares the unsigned 32-bit index against that count.

If the index is greater than or equal to the count:

- The function returns `0x20`.
- None of the three output destinations is written.
- No descriptor field or directory entry is read by the shown path.
- No record length is read.

A zero count rejects every index. An index with its high bit set remains a large unsigned index; it is not treated as a negative index.

### 2. Record lookup and first output

For an accepted index, the function reads the unsigned 16-bit directory anchor at descriptor + `0x1c`.

The selected directory entry is located:

- Relative to the region base;
- At the directory anchor;
- Minus two bytes for each unit of the index;
- Minus a further two bytes.

Thus, index zero selects the 16-bit value immediately before the anchor. Increasing the index by one moves the directory read backward by two bytes.

The selected entry is read as an unsigned 16-bit region-relative record offset. The record address is the region base plus that offset.

The function immediately writes this record address to the first, 32-bit output destination. This write precedes both the flag read and the record-length read.

The selected offset is not checked against a region size, the directory location, the count field, or any other limit.

### 3. Length interpretation

After writing the record address, the function reads the 32-bit flags at descriptor + `0x30`.

The length calculation has two modes:

- **Mask `0x00000002` clear:** use the low eight bits of the 16-bit value at the record address, then add one.
- **Mask `0x00000002` set:** use the full unsigned 16-bit value at the record address, then add two.

The apparent interpretation is a one-byte or two-byte length prefix whose own size is included in the resulting amount. That interpretation is inferred; no payload semantics are supplied.

In the clear-bit mode, the initial amount ranges from 1 through 256. In the set-bit mode, it ranges from 2 through 65,537.

The shown expression dereferences a 16-bit record value even in the clear-bit mode and then retains its low byte. It does not establish a one-byte-only memory-access guarantee for that mode.

### 4. Even adjustment and bit clearing

The initial amount is processed using the 32-bit mask `0xfffeffff`.

This mask clears **bit 16 only**. It is not a general 16-bit truncation mask.

The function first clears that bit from the initial amount. If the original initial amount is odd, it adds one to the masked amount and applies the same mask again.

For the reachable input ranges, the resulting amount is even and lies between 0 and 65,534 inclusive. The large length cases can therefore wrap to zero or another small value rather than producing a large forward advance.

In particular, in the full-width length mode:

| Stored unsigned length | Amount after adding two | Final even amount |
|---:|---:|---:|
| 0 | 2 | 2 |
| 65,532 | 65,534 | 65,534 |
| 65,533 | 65,535 | 0 |
| 65,534 | 65,536 | 0 |
| 65,535 | 65,537 | 2 |

The even adjustment applies to the amount, not to the absolute record address. An odd record offset remains odd after adding the even amount.

### 5. Calculated address and second output

The function adds the even amount to the previously loaded unsigned record offset, then applies `0xfffeffff` to the sum.

Before this mask, the sum cannot exceed 131,069. Within that range, clearing bit 16 has the same result as retaining the low sixteen bits. Consequently, the calculated region-relative position lies between 0 and 65,535.

The function writes the region base plus this calculated position to the second, 32-bit output destination.

This calculation does not guarantee that the reported address is at or after the record address. A large offset or length can cause the calculated position to wrap within the 16-bit offset range.

### 6. Neighboring directory value and final output

After writing the second output, the function reads descriptor + `0x1c` again. It does not necessarily reuse the earlier directory anchor value.

Using this newly read anchor, it reads the 16-bit directory value located two bytes before the entry position corresponding to the selected index. Relative to this anchor, its location is:

- The region base plus the anchor;
- Minus two bytes for each unit of the index;
- Minus a further four bytes.

This value is loaded as signed 16-bit data.

The function subtracts the calculated region-relative position, converted to signed 16 bits, from that signed directory value. It then stores the result in the 16-bit difference destination.

Under the target-style low-16-bit narrowing represented by the supplied listing, the stored bit pattern is the low sixteen bits of:

**neighboring directory value − calculated region-relative position**

The signed interpretation of that stored pattern may be negative. The function does not reject negative differences, reversed entries, or arithmetic wraparound.

After this write, the function returns zero.

## Side effects

The successful path has three ordered output writes:

1. The 32-bit record address.
2. The 32-bit calculated address.
3. The 16-bit difference.

The intervening reads matter when storage overlaps:

- The first output write occurs before the flags and record-length reads. If it overlaps either location, the later calculation can use the overwritten bytes.
- The second output write occurs before the second directory-anchor read and the neighboring-entry read. If it overlaps those fields, the final difference can reflect the overwritten contents.
- The first directory anchor and record offset have already been consumed before the first output write. Later overwrites do not retroactively change those saved values.
- Output destinations may overlap each other. Later stores can overwrite bytes written by earlier stores; the function does not preserve three independent final results in that case.

For ordinary independent results, callers should keep the outputs disjoint from each other and from all input fields accessed during the call. Non-overlap is a caller-side requirement for those simple semantics, not a check performed by the function.

The function contains no explicit allocation, release, ownership transfer, callback, or external function call. It does not take responsibility for releasing the region, descriptor, or output storage.

Invalid memory can fault during a read or write. No recovery or rollback is shown. In particular, a failure after the first output write can leave that output changed without producing the later outputs or a normal return.

## Acceptance examples

These examples are conditional on valid storage, a compatible 32-bit target representation, the stated integer field values, and no aliasing or concurrent mutation unless explicitly described. They are analytical acceptance cases, not executed tests.

1. **Rejected index preserves outputs.**  
   With count 3 and index 3, the return value is `0x20`, and all three output destinations retain their prior contents. The same applies to index `0xffffffff`.

2. **Zero count needs no successful-path inputs.**  
   With count 0 and index 0, the function returns `0x20` after reading the count. The shown path does not access the descriptor or write any output.

3. **Low-byte mode ignores the upper byte numerically.**  
   With the mode bit clear, a record value whose low byte is 4 produces an initial amount of 5 and an even amount of 6. A different upper byte does not change this arithmetic result.

4. **Ordinary low-byte calculation.**  
   With record offset 100, low-byte length 4, and neighboring directory value 120, the outputs are region base + 100, region base + 106, and signed difference 14.

5. **Maximum low-byte length.**  
   With the mode bit clear and low-byte length 255, the amount is 256. No additional increment is applied because this amount is already even.

6. **Full-width mode differs from low-byte mode.**  
   With stored length 4, the full-width mode produces an amount of 6. With stored length 5, it produces 8. Both include the two-byte addition before even adjustment.

7. **Large full-width length collapses to zero advance.**  
   With full-width length 65,533 or 65,534 and record offset 100, the calculated position is 100. Both address outputs identify region base + 100.

8. **Offset addition wraps.**  
   With record offset 65,530 and final even amount 10, the calculated position is 4. The second output is region base + 4, not region base + 65,540.

9. **Negative difference is successful.**  
   With calculated position 106 and neighboring directory value 100, the difference output is −6 and the return value is zero.

10. **Signed interpretation follows the stored 16-bit pattern.**  
    Under low-16-bit narrowing, neighboring value 0 and calculated position 40,000 produce stored difference bits representing signed value 25,536. The function does not report the mathematical difference −40,000 as a wider result.

11. **Last permitted index still requires another entry.**  
    With a positive count and index equal to count minus one, the index gate succeeds. The function still reads the neighboring directory value two bytes beyond the selected entry in the backward-moving directory order.

12. **Overlapping first output can change mode selection.**  
    If the first output destination overlaps the flags field, the flags read occurs after the record-address store. Mode selection therefore uses the post-store field contents, not necessarily the flags present at entry.

## Uncertainties

The following remain **documented_only**:

- The semantic names and complete layouts of the descriptor, region, directory, and records.
- Whether callers guarantee non-overlap, directory monotonicity, valid terminal entries, or consistency between offsets and lengths.
- The intended meaning of the final difference: remaining payload, slack space, a boundary distance, or another quantity.
- Whether the bit-16-clearing behavior is intentional format arithmetic or an artifact of the recovered representation.
- Target byte order, alignment requirements, and exact physical access widths after compilation.
- Language-level guarantees for out-of-range signed narrowing. The acceptance examples involving wrapped signed results explicitly assume low-16-bit narrowing.
- Address behavior outside valid target storage. The recovered expressions use 32-bit address arithmetic, but this does not justify promises about overflowing signed address expressions or unmapped addresses.
- Any concurrency contract or permissible mutation by other execution contexts.

The repeated directory-anchor read is established by the supplied body. Its reason is unknown; it must not be replaced in this contract with an assumption that the anchor remains unchanged.
