# F-5ede754866d8

## Purpose

F-5ede754866d8 looks up an unsigned 32-bit key in a caller-supplied memory table and returns an associated signed 32-bit value. It optionally transforms a selected value using the table’s record count.

Selection combines midpoint comparisons with an ascending scan of the remaining candidate range. This is not a general first-match lookup: an equality encountered at a midpoint normally takes precedence over earlier equal keys.

The value −1 is both an admissible stored value and the internal unresolved-result marker. Its role affects selection, not merely the interpretation of the return value. A midpoint match containing −1 permits a subsequent scan; a scan match containing −1 ends the search.

The established behavior is the lookup and arithmetic described below. Sorted-table lookup and reverse-position conversion are inferred purposes, not independently established caller requirements.

## Behavior

### Search range and comparison rules

The initial signed count determines a candidate range from index zero through count minus one, inclusive. The unresolved result is −1.

A range with at least three candidates is subject to midpoint comparison. The midpoint uses signed endpoint addition followed by division by two. For nonnegative endpoints with representable arithmetic, an odd endpoint sum selects the lower central index.

Keys are compared as unsigned 32-bit quantities. Thus a key with its high bit set is greater than every key below 2³¹; it is not treated as a negative search key.

A midpoint equality selects that record’s associated value and stops midpoint narrowing. Otherwise, the comparison retains the half that can contain the requested key in a sorted table. The tested midpoint remains an endpoint of the retained range rather than being removed from it.

This endpoint retention matters observably: a previously compared key can be read again during the later scan.

### Selection precedence and the −1 marker

The search has two distinct selection rules:

- A midpoint equality yielding a value other than −1 completes selection without an ascending scan.
- If midpoint narrowing has not produced a non-−1 value, an ascending scan examines the retained range and stops at its first key equality.

The scan’s stopping rule depends on key equality, not on whether the associated value is useful. A scan equality yielding −1 ends the scan; later duplicates are not considered.

A midpoint equality yielding −1 behaves differently. It permits the scan to start at the retained range’s lower endpoint. The scan may therefore select an earlier equal-key record, including one with a non-−1 value.

A stable, sorted table preserves all matching records inside the retained range during unsuccessful midpoint comparisons. Consequently, when the ascending scan is reached under those conditions, it selects the earliest matching record in the entire table. This does not make the function generally first-match: a non-−1 midpoint match can take precedence over an earlier duplicate.

For unsorted or changing contents, the scan guarantees only ascending selection within the retained range. An earlier matching record outside that range need not be considered.

### Optional transformation

Transformation is performed only when both conditions hold:

- The transformation flag is nonzero.
- The selected value is not −1.

The mathematical result is:

**reread record count − selected value − 1**

The record count is read from the table again. Transformation does not necessarily use the initial count that established the search range.

The operation uses the stored associated value, not the selected record’s index. There is no visible validation that the value denotes a position. Negative values other than −1, values equal to the count, and values larger than the count are all eligible.

The arithmetic first subtracts the selected value from the reread count, then subtracts one. Both intermediate and final arithmetic must be representable for the ordinary mathematical interpretation to apply.

A transformed result of −1 is returned as-is. It does not trigger another scan, retry, or alternative selection.

## Side effects

### Observable read ordering

The count observation precedes record observations. Midpoint comparisons, when needed, precede fallback-scan comparisons.

Each record comparison reads the key before reading its associated value. A nonmatching record’s value is not read. Selection does not require prefetching or inspecting unrelated associated values.

During midpoint narrowing, the observed key determines the retained range unless equality ends narrowing. During fallback, keys are observed in ascending index order until the first equality or range exhaustion.

A fallback scan can revisit a key previously observed at a midpoint. If a midpoint equality supplied −1, the fallback can also reread that record’s value. The function does not promise to reuse the earlier observation.

The final count reread occurs only for an enabled transformation of a non-−1 selected value. It follows selection. Neither absence of a match nor selection of −1 requires that reread.

### Empty table

For one record with key 12 and value 6:

- Searching for 12 with transformation disabled returns 6.
- Searching for 13 returns −1 and does not read the associated value.
- Searching for 12 with transformation enabled returns −6.

The last result is 1 − 6 − 1. It demonstrates that transformation uses the associated value, not the record’s index.

If the associated value is instead −1, a matching search returns −1 without transformation or a transformation count reread, regardless of the flag.

### Two-record access order

- Searching for 10 reads the first key and its value; the second record is not needed.
- Searching for 20 reads both keys and then the second value.
- Searching for 15 reads both keys, reads neither associated value, and returns −1.

No midpoint comparison occurs in any of these cases.

### Non-sentinel midpoint precedence

For three equal keys with associated values 10, 20, and 30, a search for that key with transformation disabled returns 20.

The middle record supplies a non-−1 value. The earlier duplicate does not take precedence.

### Sentinel midpoint followed by fallback

For values −1, −1, and 30, that scan stops at the first record and returns −1. It does not continue to the later value 30.

- Transformation disabled returns 3.
- Transformation enabled returns −1.

The transformed −1 is final even though selection found a matching record.
