# F-4bbc6df31641

## Purpose

F-4bbc6df31641 conditionally invokes a preliminary dependency, selects one of two indirect handlers, and, if that handler returns zero, may invoke an additional indirect handler.

The selected primary handler always runs on a normally completing invocation. The preliminary and additional handlers are conditional. A nonzero primary-handler result is returned immediately; otherwise, the additional handler can supply a nonzero result. All other normally completing paths return zero.

**Inferred intent:** this resembles receiver-based event dispatch, with special handling for particular event categories and payload values. The supplied evidence does not establish application-level meanings for those values or for the return codes.

## Interface

### Inputs

The function accepts two inputs:

- **Receiver:** an address used both as a word-addressable object and as the first argument to each dependency.
- **Event:** an address used to inspect a discriminator and, conditionally, a payload reference or comparison value. It is passed unchanged as the second argument to indirect handlers.

No null checks, bounds checks, type checks, or pointer-validity checks are visible.

### Width and layout model

The supplied representation uses integer-sized accesses and pointer values carried through integer-sized fields. The following layout describes its apparent 32-bit target model:

The layout is sparse: the evidence does not describe the contents, ownership, or validity requirements of intervening fields.

### Output

The result is an integer of the represented `int` width, apparently 32 bits.

- Any nonzero result from the primary handler is returned unchanged.
- If the primary handler returns zero and the additional handler is invoked, any nonzero result from that handler is returned unchanged.
- Otherwise, the result is zero.

Nonzero includes negative values. The function does not normalize nonzero results to one or establish that they represent errors.

In particular:

- A discriminator of 0x16 requires a readable nested reference and nested field during each applicable inspection.
- The receiver’s dispatch-table reference and the selected dispatch entry must be readable.
- Conditional receiver fields must be readable when their respective branches are reached.
- Calls must obey the target ABI and the actual dependency contracts.

These requirements apply at the time of each access. Dependencies can change what later accesses observe.

## Behavior

### 1. Preliminary condition and optional call

The function first reads the event discriminator at offset 0x04.

If it is not 0x16, this preliminary check does not read the nested reference or its field and does not invoke the preliminary dependency.

If it is 0x16, the function:

1. Reads the nested-object address from event offset 0x08.
2. Reads the integer at nested-object offset 0x04.
3. Subtracts 0x2500 from that integer.
4. Tests whether the result is 2.

For ordinary, representable arithmetic, the qualifying nested value is 0x2502, or decimal 9474. The subtraction is part of the supplied evidence; it should not be silently replaced by an assumption about overflow behavior for every possible integer input.

If the condition qualifies, the function reads the word at receiver offset 0xEC, converts that value to a character-sized value, and calls **F-b949e599157b** with:

- the original receiver address;
- the converted character-sized value.

The call’s result is not used to decide continuation or the final return value. This does not establish that the dependency has no result or no side effects.

For an eight-bit character representation, the conversion selects a value corresponding to the low eight bits, subject to the target’s character signedness and conversion rules. For example, the handling of a low byte of 0xFF cannot be specified as definitely positive 255 or definitely negative one from the supplied evidence alone.

### 2. Fresh inspection and primary-handler selection

After the preliminary phase, including any completed preliminary call, the function reads the event discriminator again.

This is a fresh observation, not reuse of the first discriminator or nested value.

- If the newly read discriminator is 0x16, it reads the current nested-object address at event offset 0x08 and then the current nested field at offset 0x04.
- If that nested field equals 0x2A, or decimal 42, it selects the dispatch entry at offset 0x10C.
- In every other case, it selects the dispatch entry at offset 0x110.

The function then reads the receiver’s dispatch-table address and the selected entry. It calls that target with the original receiver and event addresses.

Consequently, the selected target can reflect mutations made by F-b949e599157b to the event, nested data, receiver, or dispatch table. The evidence does not permit assuming that any of these are preserved by that dependency.

If the primary handler returns a nonzero integer, the function returns that value immediately. There are no subsequent local event checks on that path.

### 3. Conditional additional handling

Only after a zero primary-handler result does the function read the event discriminator again.

If the discriminator is not 0x0F, or decimal 15, the function returns zero without locally reading the comparison operands for this phase.

If the discriminator is 0x0F, the function reads, in order:

1. The integer at event offset 0x08.
2. The integer at receiver offset 0x50.

It compares these two values for equality. Here, event offset 0x08 is used directly as a comparison value; it is not dereferenced as a nested-object address.

If they differ, the function returns zero.

If they are equal, the function reads the receiver’s current dispatch-table address, obtains the target at offset 0xE0, and calls it with the original receiver and event addresses.

- A nonzero result is returned unchanged.
- A zero result leads to a zero return.

There is no further dispatch after this call.

### Consequences of repeated reads

The function does not take a stable snapshot of the receiver or event.

Without intervening mutation, the preliminary special case and special primary-handler selection require different nested values: 0x2502 and 0x2A, respectively. With mutation by F-b949e599157b, both can occur in the same invocation.

Likewise, an event need not initially have discriminator 0x0F to qualify for additional handling. The decisive observation is the discriminator read after a zero primary-handler result.

The maximum number of directly invoked dependencies on a normally completing path is three:

1. F-b949e599157b;
2. one primary handler;
3. the additional handler.

The minimum is one: the primary handler.

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

1. **Ordinary default dispatch.**  
   Given readable storage, no relevant mutation, an initial discriminator other than 0x16 and 0x0F, and a default primary handler returning zero: F-b949e599157b is not called, the 0x110 entry is called once, the additional handler is not called, and the result is zero.

2. **Special primary selection.**  
   Given discriminator 0x16, nested field 0x2A, and no intervening mutation: the preliminary dependency is not called, and the primary target comes from offset 0x10C. Its nonzero return, if any, is propagated unchanged.

3. **Preliminary call without mutation.**  
   Given discriminator 0x16 and nested field 0x2502: F-b949e599157b is called first. If it leaves the relevant fields unchanged, the primary target comes from offset 0x110, not 0x10C.

4. **Preliminary call changes selection.**  
   Given the same initial qualifying preliminary state, if F-b949e599157b changes the nested field to 0x2A while preserving a discriminator of 0x16 and valid storage, the subsequent primary target comes from offset 0x10C.

5. **Nonzero primary result suppresses later processing.**  
   If the selected primary handler returns −7, the final result is −7. The function performs no post-primary discriminator read and does not call the additional handler.

6. **Additional-handler match.**  
   If the primary handler returns zero, the subsequently observed discriminator is 0x0F, and event offset 0x08 equals receiver offset 0x50, the target at offset 0xE0 is called. Its result determines the final result.

7. **Additional-handler mismatch.**  
   Under the preceding conditions except for unequal comparison values, the additional handler is not called and the result is zero.

8. **Primary mutation enables additional handling.**  
   An initially different discriminator does not prevent additional handling if the primary handler returns zero and changes the event to the matching 0x0F state before returning.

9. **Character conversion requires ABI qualification.**  
   If the word at receiver offset 0xEC has low byte 0xFF, acceptance must use the target’s established character-conversion behavior. Requiring either 255 or −1 without that prerequisite would exceed the evidence.
