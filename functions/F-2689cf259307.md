# F-2689cf259307

## Purpose

F-2689cf259307 obtains an object pointer, initializes selected fields, transfers shared state, creates and activates an associated handle, updates control fields, and invokes a descriptor-based operation. On normal completion, it returns the pointer value originally supplied by F-ff29814bf4cc.

The operation is not transactional. Object initialization and the shared-state transfer precede the explicit handle-failure check. No direct rollback or object-release operation is visible.

**Inferred intent:** this resembles object initialization and registration with a shared subsystem. The object’s application-level type, the transferred data’s meaning, and the handle’s resource semantics are not established.

Returning the saved pointer does not establish that it still designates a live object. Dependencies execute after the last direct object access, and their lifetime effects are unknown.

## Behavior

### Object acquisition and initial writes

The descriptor is initialized before F-ff29814bf4cc is called. That dependency receives no visible arguments. Its result is saved as the object pointer.

The following object writes occur in order:

| Object byte offset | Width | Value |
|---|---:|---|
| `0x000` | 32 bits | Current value of a shared initialization word |
| `0x2dc` | 32 bits | `0xffffffff` |
| `0x2e0` | 8 bits | Zero |
| `0x2e4` | 32 bits | Zero |
| `0x2e8` | 32 bits | Zero |

The shared initialization word is read after F-ff29814bf4cc returns. A change made by that dependency can therefore affect the value written at object offset zero.

Only the byte at `0x2e0` is cleared; bytes `0x2e1` through `0x2e3` are not directly cleared by that operation.

F-fad3b80e9250 is then called with the object pointer, followed by F-ee0ee79aa445 with the same pointer. Their return values are not consumed. Neither dependency is assumed to preserve the initialized fields or shared state.

### Shared-state transfer

The transfer consists of 26 eight-byte groups implemented through 32-bit memory accesses. With stable shared references, the source extent is `0x08` through `0xd7`, and the destination extent is `0x110` through `0x1df`: 208 bytes in total.

The initial group has distinct reference-evaluation behavior:

1. The source reference is captured.
2. The destination reference is captured.
3. The source global is evaluated again, and the 32-bit word at offset `0x0c` from that newly obtained reference is read and saved.
4. The first-word transfer reads the source word at offset `0x08` and writes destination offset `0x110`. This assignment evaluates both the source global and the destination global again.
5. The saved second word is written at offset `0x114` from the previously captured destination reference.

The supplied representation does not establish an evaluation order between the source-side and destination-side operands of the first-word assignment. It does establish that the second source word is saved before that assignment and that the second destination store follows it.

Consequently, the first group is not necessarily read entirely from the captured source reference or written entirely through the captured destination reference. If shared references vary between evaluations, its two words can involve different referenced regions.

The remaining 25 groups use the captured source and destination references, without further evaluations of those globals for their transfer accesses. For group index \(n\), with \(1 \leq n < 26\):

- The source group begins at `0x08 + 8n`.
- The destination group begins at `0x110 + 8n`.
- The second source word is read and saved first.
- The first source word is read and written to the first destination word.
- The saved second word is written to the second destination word.

Groups proceed in increasing offset order. There are 52 direct 32-bit destination stores.

This is neither a demonstrated atomic 64-bit transfer per group nor an atomic snapshot of the whole block. If ranges alias, earlier destination writes can affect later source reads. The saved second word of a group is not reread after that group’s first destination write.

The nominal source and destination extents above describe offsets relative to the references used. They do not guarantee one contiguous source or destination region when the first group’s global evaluations yield different bases.

### Handle creation, publication, and failure

U-01 is evaluated without visible arguments. F-c930571cdede receives, in argument order:

- That context result.
- `0x60`, or 96.
- The saved object pointer.
- `1`.

Its 32-bit result is the handle.

After this call, the shared control reference is captured. The subsequent handle store separately evaluates the control global and writes the handle at offset `0x08` through that evaluated reference. Thus, the captured control pointer and the publication destination are distinct evaluations, although they ordinarily coincide when the global is stable.

The handle is stored before it is compared with `0xffffffff`.

For that exact failure value, F-a817d8d58c10 is invoked. Under the supplied non-returning classification, execution does not reach the subsequent byte clears, activation, subsystem operation, descriptor operations, or normal return. Earlier direct writes have already occurred, with no visible rollback.

Every other 32-bit handle value passes this comparison, including zero and signed-negative values other than −1. Passing this comparison does not establish that dependencies consider such a handle valid.

### Activation and subsequent field updates

On the nonfailure path, byte `0x01` of the captured control block is set to zero.

U-01 is called a second time. Its result need not equal its first result. After this second call returns, the function reads the 32-bit word at offset `0x08` of the captured control block and passes that word, together with the second U-01 result, to F-23aadb16b673.

This is a fresh memory read, not reuse of the handle result saved from creation. U-01 can affect the supplied handle by modifying the captured block’s word. Changing only the control global does not redirect this read, because it uses the captured pointer.

U-02 is then called without visible arguments. Its result is held as a signed 32-bit integer. The addition of four is evaluated in that signed 32-bit representation before the result is passed onward. F-379efa3ca9d1 receives:

- The result of that addition.
- `3`.
- `0x6d`, or 109.

For a representable sum, the first argument is U-02’s represented result plus four. The evidence does not establish what happens on signed overflow. Neither widened address arithmetic nor guaranteed modular wrapping is part of this contract.

After F-379efa3ca9d1 returns, the following writes occur in order:

| Destination | Width | Value |
|---|---:|---|
| Object offset `0x2d0` | 32 bits | Zero |
| Captured control offset `0x03` | 8 bits | Zero |
| Captured control offset `0x00` | 8 bits | Zero |

These accesses use the saved object pointer and captured control pointer. The control byte at `0x01` is not cleared again; intervening dependencies may have changed it.

### Descriptor dispatch and return

F-7a117b899bf6 receives the descriptor’s address.

After it returns, the descriptor’s current first word is used as the base for a target lookup at byte offset `0x0c`. The resulting indirect target, U-03, receives:

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Stable successful path

Given valid accesses, stable source and destination references and contents during the transfer, nonoverlapping transfer ranges, returning dependencies, and a nonfailure handle:

- Source bytes `0x08` through `0xd7` are transferred to destination bytes `0x110` through `0x1df`.
- Handle publication precedes activation.
- The late object and control clears precede descriptor processing.
- Normal return yields the original saved object pointer value.

Final memory contents require the additional condition that subsequent dependencies and aliases do not overwrite them.

### Initial transfer reference reevaluations

Suppose the captured source reference designates region A and the captured destination reference designates region B. If the later source-global evaluation for the first group’s second word yields region C, that saved word comes from C at `0x0c`, not A.

If the first-word assignment evaluates the source global as region D and the destination global as region E, its transfer is from D at `0x08` to E at `0x110`. The saved second word is then written to B at `0x114`.

Later groups use A and B. This criterion does not require either operand of the first-word assignment to be evaluated first.

### Exact-width clearing

Given distinct values in object bytes `0x2e0` through `0x2e3`, with no other modifications to them, the direct clear changes only byte `0x2e0`. Clearing all four bytes would exceed the established write width.

### Failure and zero handles

For handle `0xffffffff`, that word is published before F-a817d8d58c10 is called. Under its supplied non-returning classification, later operations do not execute. Earlier writes are not directly undone.

For handle zero, the explicit failure branch is not taken. Activation still reads the captured control block afresh; zero reaches activation only if that read yields zero.

### Control-reference distinction

If the control pointer capture yields block A but the subsequent publication evaluation yields block B, the handle is written to B. The byte clears and activation read use A.

If the second U-01 call modifies A’s word at `0x08`, activation receives the modified word. Replacing only the control global does not redirect that read.

### Signed addition boundary

If U-02 returns signed value `2147483643`, the representable addition result passed to F-379efa3ca9d1 is `2147483647`.

For values whose addition of four exceeds the signed 32-bit range, no wrapped or widened result is specified by this contract.

### Descriptor mutation and pointer lifetime

If F-7a117b899bf6 replaces the descriptor’s first word with another valid target-bearing value, U-03 is selected through that replacement.

If a dependency after the last object write invalidates the object but returns normally, the visible body still returns the saved pointer value. That return does not establish usable storage.

### Overlap

If transfer ranges overlap, acceptance follows the ordered word accesses, including each second-word read before its group’s first-word transfer. A whole-block snapshot or an overlap-safe copy is not an established substitute.
