# F-e45cbf248471

## Purpose

F-e45cbf248471 performs an ordered series of memory reads and writes using implicit entry-state values, a memory-loaded base, and several fixed-address locations. It then invokes an unresolved indirect destination with four arguments.

The established behavior is memory mutation followed by indirect dispatch. The supplied evidence does not establish a higher-level purpose such as initialization, device configuration, object linking, or instruction execution. Repeated stores and low-address accesses could be significant to an external observer; they must not be treated as redundant merely because ordinary memory would retain the same final value.

This contract distinguishes:

- **Established static evidence:** access widths, address relationships, value dependencies, and ordering represented in the supplied material.
- **Inferred intent:** possible interpretations that are not requirements.
- **documented_only:** behavior whose details cannot be established from that material.

No runtime tests have been performed.

### Widths and address notation

“Low byte” means the least significant eight bits of a value, not a byte at a particular memory address. Byte order is not established.

Primary-base doubling and addition are represented as unsigned 32-bit operations. Their bit-pattern results wrap modulo 2³². Several other calculations are represented as signed 32-bit operations; overflow behavior for those calculations is not established and must not be silently equated with unsigned wrapping.

## Behavior

### Opening access sequence

At primary base plus 0x20, the function makes three successive word writes:

1. The value 0x2F.
2. The zero-extended byte read from primary base plus 0x04.
3. The value 0x20.

The byte read occurs after the first word write and before the second. Consequently, its value is not necessarily the value present at function entry if the address space aliases these locations or gives accesses external effects.

After the third write, the function reads the loaded base from its fixed source location. It then writes the word value 0x20 at absolute address 0x60.

These are distinct accesses. The final value at primary base plus 0x20 does not describe the complete behavior.

### Repeated association writes

Define the **doubled secondary value** as twice the secondary base, subject to the signed-arithmetic limitation above.

The first association group has four ordered effects:

- A word write of the doubled secondary value at twice the initial index plus 0x54.
- A byte write of the primary base’s low byte at loaded base plus 0x19.
- A byte write of the loaded base’s low byte at primary base plus 0x11.
- A word write of twice the initial index at loaded base plus 0x34.

The function then performs a long, fixed series of analogous groups. Each later group writes:

- The doubled secondary value as a word at twice the primary base plus 0x54.
- The primary base’s low byte at loaded base plus 0x19.
- The loaded base’s low byte at primary base plus 0x11.
- Twice the primary base as a word at loaded base plus 0x34.

Within every group, the access order is the order listed above. The addresses and values do not advance between later groups. This is repeated access to the same derived locations, not established traversal of an array.

The supplied material establishes a finite, statically repeated sequence, not a data-dependent termination condition. Its exact repetition count is **documented_only** in this contract; an exact transaction-count acceptance requirement needs independent enumeration. This limitation does not permit collapsing the sequence into one group.

The loaded base and the two low-byte values are retained values. Writes that alter their original memory sources do not cause those values to be reloaded during this phase.

### Capture and initial publication

After the repeated groups, the function captures a word beginning at absolute address 0xA9, then a word at doubled secondary value plus 0x74.

It next writes a byte at absolute address 0x3A. That byte is the low eight bits of twice the primary base’s low byte plus 0x30.

After that byte write, it reads:

- A word at secondary base plus 0x14.
- A word at primary base plus 0x04.

The latter is a full-word read, distinct from the opening byte read at the same starting offset.

The next publication phase writes the primary base’s low byte at secondary base plus 0x0D. In the primary region, it writes 0x6C at offset 0x08 and the loaded base’s low byte at offsets 0x0D and 0x09, in that order. It then writes the secondary base itself as a word at secondary base plus 0x54.

The low byte of the captured word from absolute address 0xA9 is written at absolute address 0x67.

### Word replacement and shift-dependent byte

The function reads a signed word from secondary base plus 0x44. Before publishing that word elsewhere, it reads the byte at absolute address 0x67 and writes that byte at absolute address 0x21.

The signed word then participates in three effects:

- Its low byte is written at primary base plus 0x10.
- The whole word is written at loaded base plus 0x54.
- A right-shift-derived byte is written at secondary base plus 0x01.

The shift count is the primary base’s low byte, giving a represented range of 0 through 255. The operand is represented as signed. Counts of 32 or greater, and right shifts of negative values, require target-specific clarification; this contract does not invent count masking or sign-fill behavior.

After the shift-dependent byte write, the word at loaded base plus 0x54 is overwritten with the primary base itself.

The function then reads a word from primary base plus 0x40. It publishes the previously captured word from primary base plus 0x04 at loaded base plus 0x74, then writes the newly read word at primary base plus 0x10.

That word write covers offsets 0x10 through 0x13, including the earlier byte writes at offsets 0x10 and 0x11. Their earlier occurrence remains part of the access history.

### Pointer-derived mutations

The function writes the secondary base as a word at loaded base plus 0x44. It then reads absolute byte 0x67 and writes it at primary base plus 0x09, followed by a byte write of the primary base’s low byte at secondary base plus 0x09.

The captured word from absolute address 0xA9 is written at primary base plus 0x44. The function then reads a word from primary base plus 0x54; this contract calls that retained value the **linked base**.

After obtaining the linked base:

- Absolute byte 0x67 is read again and written at primary base plus 0x09.
- The low byte of the earlier word captured from doubled secondary value plus 0x74 is written at linked base plus 0x0D.
- The earlier word captured from secondary base plus 0x14 is written back at secondary base plus 0x54.

The two later reads of absolute byte 0x67 are separate reads. They are not specified as reuse of the byte read for the write at absolute address 0x21.

The function next reads a word at primary base plus 0x14. It writes the low byte of the captured scaled-secondary word at secondary base plus 0x11, then writes the linked base’s low byte at primary base plus 0x09. Finally, it writes the full linked base at primary base plus 0x44.

These replacements mean neither the captured absolute-address word nor the absolute byte necessarily remains in those primary-region destinations.

### Final derived accesses and dispatch

A word read from secondary base plus 0x04 supplies another pointer-like value, called the **terminal base** here.

The final phase has the following ordered dependencies:

- A halfword value 0x0065 is written at twice the terminal base.
- A word is read at terminal base plus 0x64; call this retained value the **dispatch value**.
- The low byte of the previously captured primary-region word from offset 0x14 is written at linked base plus 0x11.
- The word value 100, equivalent to 0x64, is written at linked base plus 0x54.
- A word is read at terminal base plus 0x74 for use as the fourth dispatch argument.
- A word is read at secondary base plus 0x64; call this value the **final destination base**.
- The terminal base’s low byte is written at secondary base plus 0x09.
- The dispatch value is written as a word at final destination base plus 0x54.
- The final destination base is written as a word at twice the dispatch value.

The unresolved indirect destination is then invoked with these four represented arguments, in order:

| Position | Value |
|---|---|
| 1 | 0x72 |
| 2 | Dispatch value |
| 3 | Earlier word captured from secondary base plus 0x14 |
| 4 | Word captured from terminal base plus 0x74 |

The final two word writes occur before this invocation. No explicit post-invocation memory operation is shown.

## Side effects

### Memory and aliasing

No non-aliasing guarantee is established. In particular:

- Derived regions may overlap each other or fixed-address storage.
- A byte write may change a later word read.
- A word write may overwrite several previously written bytes.
- Captured values remain captured even if their source storage is later overwritten.
- If a write overlaps storage not yet read, that later read observes the resulting memory state, subject to the environment’s memory semantics.

Final-state descriptions therefore apply only under stated aliasing assumptions.

## Acceptance examples

These examples are conditional specifications, not executed tests.

### Opening transaction history

Assume valid, non-overlapping ordinary memory and a byte value of 0xAB at primary base plus 0x04.

An observer must see word writes of 0x2F, 0x000000AB, and 0x20 at primary base plus 0x20, in that order. Checking only the final word value would miss two required writes and the intervening byte read.

### Low-byte truncation

Assume the primary base’s low byte is 0xF0.

The byte written at absolute address 0x3A is 0x10: the low eight bits of 0xF0 doubled and increased by 0x30. This does not imply any particular meaning for the remaining bits of the primary base.

### Initial versus repeated association

Assume the initial index differs from the primary base and the relevant arithmetic is defined.

The first association targets twice the initial index plus 0x54 and publishes twice the initial index at loaded base plus 0x34. Later groups instead use twice the primary base. Replacing the initial group with a later-group copy would violate the contract.

### Width-sensitive replacement

Assume non-overlapping ordinary memory except for the explicitly shared primary-region offsets.

The word write at primary base plus 0x10 replaces the earlier bytes at offsets 0x10 and 0x11. Their final byte values depend on byte order and the word read from offset 0x40. An acceptance check must not require those bytes to retain their earlier values.

### Dispatch arguments survive source replacement

Assume execution reaches dispatch without faults.

The third argument is the retained word originally read from secondary base plus 0x14. It is not a fresh read of secondary base plus 0x54 or of any later-mutated location.

The fourth argument is the later read from terminal base plus 0x74, not the earlier read from doubled secondary value plus 0x74.

### Unsupported arithmetic case

If the primary base’s low byte is 40, the represented signed right shift has a count exceeding the word width. No specific resulting byte is accepted by this contract without additional target evidence. This case is **documented_only**, not implicitly a shift by eight.
