# F-30af0f278435

## Purpose

F-30af0f278435 handles a state-dependent interaction that can request an unlock layout, request a main-menu screen, or report an incorrect combination.

The established behavior is a branch-driven sequence of receiver-state reads, dependency calls, a possible one-byte state update, and indirect dispatch of a constructed value. Every normally returning path returns the 32-bit value 1.

The screen and layout meanings are inferred from resource labels. The supplied material does not establish that this function itself changes the displayed screen, verifies a particular credential format, or schedules an operation in a known unit of time.

## Interface

### Inputs

The recovered interface contains four arguments:

1. **Receiver reference.** A reference to writable storage accessed through 32-bit words. It also supplies an indirect dispatch table.
2. **Second argument.** An uninterpreted 32-bit value forwarded to F-c4a767154623 on the already-active branch.
3. **Third argument.** An uninterpreted 32-bit value:

   - made available by address through the local slot when F-9b9c1c7483f4 is called.
4. **Fourth argument.** An uninterpreted 32-bit value copied into a separate local 32-bit slot at entry. The address of that slot is passed to both F-9b9c1c7483f4 and, afterward, F-8a5aadac202f.

No input range checks, null checks, or storage-size checks are established.

## Behavior

### Entry preparation and initial condition

Before selecting a branch, the function initializes two local 32-bit slots from the third and fourth arguments.

It then reads the 32-bit word at receiver offset `0xBC` and tests its narrowed 8-bit character value against zero.

### Initial condition is zero

When the narrowed value is zero:

1. The function selects the resource associated with the apparent unlock-layout label.
2. It writes the byte value 1 at receiver offset `0xBC`.
3. It performs the common construction-and-dispatch sequence described below.
4. It returns 1.

On this branch, the function does not itself access the subordinate-object field, call F-c4a767154623 or F-f0c29a6e58c5, or call F-979606fd565e.

The state write precedes construction and dispatch. There is no established rollback if a later operation fails or does not return.

### Initial condition is nonzero

When the narrowed value is nonzero:

1. The function obtains the subordinate-object reference from receiver offset `0xB4`.
2. It reads and retains the 32-bit integer at subordinate-object offset `0x68`.
3. It calls F-c4a767154623 with:
   - the subordinate-object reference obtained from the receiver field;
   - the second argument;
   - the third argument.
4. It selects the next path using both the return value and the retained integer.

The comparison uses the integer sampled **before** F-c4a767154623. It does not reread subordinate-object offset `0x68` to make this decision.

#### Zero dependency result and retained integer equal to 1

If F-c4a767154623 returns zero and the retained integer equals exactly 1:

1. The function selects the resource associated with the apparent main-menu label.
2. It performs the common construction-and-dispatch sequence.
3. It returns 1.

This path performs no explicit write to receiver offset `0xBC`. It does not call F-f0c29a6e58c5 or F-979606fd565e.

#### Nonzero dependency result or retained integer not equal to 1

If either condition holds, the function calls F-f0c29a6e58c5.

Its argument is obtained by reading receiver offset `0xB4` again after F-c4a767154623 returns. This matters if that dependency changes the receiver’s subordinate-object reference: the later call is not specified to use the earlier object.

There are two outcomes.

**F-f0c29a6e58c5 returns nonzero:**

- The function immediately returns 1.
- It performs no subsequent explicit state-byte write.
- It performs no local construction, indirect dispatch, cleanup call, or F-979606fd565e call.

This says nothing about changes already made by the dependencies.

**F-f0c29a6e58c5 returns zero:**

1. The function writes byte value 0 at receiver offset `0xBC`.
2. It constructs and dispatches a value using the resource associated with the apparent incorrect-combination label.
3. It calls F-8a5aadac202f for the local slot used by construction.
4. It calls F-979606fd565e with the receiver and integer 1000.
5. It returns 1.

The constant 1000 is established. Its units and meaning are unknown.

### Common construction-and-dispatch sequence

Each of the three dispatching paths performs the following ordered operations:

1. Call F-9b9c1c7483f4 with:
   - the address of the local slot initially containing the fourth argument;
   - the selected resource reference;
   - the address of the local slot initially containing the third argument.
2. Retain its returned 32-bit value.
3. Read the receiver’s dispatch-table reference and invoke the callable entry at table byte offset `0x11C`, passing:
   - the receiver;

4. Call F-8a5aadac202f with the address of the local slot initially containing the fourth argument.

The dispatch-table lookup occurs after F-9b9c1c7483f4 returns. The function does not establish that this dependency preserves the receiver, its table reference, or other shared state.

There is no visible conditional check between construction and dispatch, or between dispatch and cleanup. Thus, if F-9b9c1c7483f4 returns zero normally, the visible behavior is still to pass zero to the callback.

## Acceptance examples

These are conditional behavioral criteria derived from static evidence, not executed tests. They assume valid required storage and normally returning callees.

1. **Initial zero condition.**  
   If narrowing the receiver word at `0xBC` yields zero, the function writes byte 1 there before construction, selects the unlock-associated resource, dispatches the constructed result, performs cleanup, and returns 1. Neither subordinate-check dependency is called.

2. **Main-menu selection.**  
   If the initial condition is nonzero, the sampled subordinate integer is 1, and F-c4a767154623 returns zero, the function selects the main-menu-associated resource. It dispatches and cleans up without its own state-byte write or a call to F-f0c29a6e58c5.

3. **Pre-call sample controls the branch.**  
   If the sampled integer is 1 and F-c4a767154623 subsequently changes that integer to 2 while returning zero, the main-menu path still applies. Conversely, a sample of 2 followed by a change to 1 still leads to F-f0c29a6e58c5.

4. **Nonzero result overrides a sample of 1.**  
   If the sampled integer is 1 but F-c4a767154623 returns any nonzero value, F-f0c29a6e58c5 is called.

5. **Early completion without dispatch.**  
   If F-f0c29a6e58c5 returns nonzero, the function returns 1 without subsequently writing the state byte, constructing a value, dispatching, cleaning up a constructed value, or calling F-979606fd565e.

6. **Incorrect-combination ordering.**  
   If F-f0c29a6e58c5 returns zero, the required order is: write byte 0, construct with the incorrect-combination-associated resource, dispatch the returned value, clean up the local slot, call F-979606fd565e with 1000, return 1.

   If F-c4a767154623 changes receiver offset `0xB4` and the next branch requires F-f0c29a6e58c5, the latter receives the reference read after that change.

8. **Construction returns zero.**
