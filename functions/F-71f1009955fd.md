# F-71f1009955fd

## Purpose

F-71f1009955fd performs an ordered state update and conditional dispatch for a caller-supplied entity identifier.

On the normal-return path, it:

- Stores the low two bits of a 32-bit input in an entity-associated object.
- Obtains a 32-bit selection value from F-3e1cbf8608fb.
- Calls dependencies selected by the low five bits of that value, in a fixed order.
- Stores the 32-bit value 7 in a separately resolved entity-associated object.

The dispatch choices are independent, not mutually exclusive. One dependency can be called twice during a single invocation.

This is a static behavioral contract. It does not establish the application-level meaning of the identifier, either destination field, the selection bits, or the value 7.

## Interface

### Inputs

The function accepts two 32-bit arguments:

| Input | Established use |
|---|---|
| Entity argument | Its low 16 bits, interpreted as signed, select entries for the two direct stores. Its complete 32-bit value is forwarded unchanged to every dependency called by this function. |
| Requested value | Its low two bits become the value of the initial 32-bit store. The other 30 bits have no direct effect in the supplied body. |

The signed index ranges from −32,768 through 32,767. Bits 16–31 of the entity argument do not affect the direct entry selection, but remain available to dependencies through the forwarded argument.

Consequently, two entity arguments with identical low 16 bits select the same direct entries under unchanged global state, yet may produce different dependency behavior.

### Output

There is no defined return value or explicit success/failure result.

Successful completion is observable through memory writes and dependency calls. A normal return means execution reached and completed the final store; it does not independently certify that dependencies succeeded according to their own contracts.

### Required memory environment

The supplied body uses two global address sources. This contract calls them the **initial table source** and the **final table source**. These names distinguish their roles without asserting that their values, backing storage, or selected objects differ.

For each direct store, the effective signed index is multiplied by 396 bytes. The resulting displacement selects an entry relative to the corresponding table base. A 32-bit object address is read at the start of that entry.

The direct destinations are:

| Store | Table source | Offset within selected object | Width |
|---|---|---:|---:|
| Initial | Initial table source | 2,460 bytes | 32 bits |
| Final | Final table source | 2,136 bytes | 32 bits |

Safe normal completion requires the necessary table-address reads and entry reads to be valid, and both destination locations to be writable when accessed. No validation of these conditions appears in the supplied body.

## Behavior

### 1. Resolve and perform the initial store

Before calling any dependency, the function resolves the initial destination:

- It obtains the initial table base.
- It selects the entry using the signed low-16-bit index and a 396-byte stride.
- It reads that entry’s object address.
- It writes the requested value masked to its low two bits at object offset 2,460.

The stored value is therefore exactly one of 0, 1, 2, or 3. This is a full 32-bit assignment, not a two-bit update preserving the previous field contents.

The initial destination is resolved before the dependency sequence. Later changes to table state do not redirect a store that has already occurred.

### 2. Obtain the dispatch selection

The function calls F-3e1cbf8608fb exactly once on the normal path, forwarding the complete entity argument.

Its 32-bit result is retained as the selection value for all subsequent dispatch decisions. The function does not call this dependency again to refresh the selection between groups.

The initial store precedes this call. F-3e1cbf8608fb can therefore observe the updated field if its own behavior accesses that storage and the execution environment makes the write visible. Its actual reads and other effects are not supplied.

### 3. Dispatch selected groups in order

The function examines five bits of the retained selection value. Every selected group executes in the following order:

| Selection bit | Calls, in execution order |
|---:|---|
| 0, mask 0x01 | F-a7c7afa4b061 |
| 1, mask 0x02 | F-abbb5f0f1e49, then F-bc094a25dffa |
| 2, mask 0x04 | F-43f8f156d0c4, then F-1f0f08ed1151 |
| 3, mask 0x08 | F-5333b2c1b9c9, then F-74d4f3276870 |
| 4, mask 0x10 | F-74d4f3276870 |

Every call receives the complete original entity argument.

Bits 5–31 of the selection value cause no additional calls or branches in this function. If all low five bits are clear, no dispatch-group dependency is called, even when higher bits are set.

Both calls in a selected two-call group occur in the listed order, provided the first returns normally. There is no intervening selection refresh and no visible check of a return value.

When bits 3 and 4 are both set, F-74d4f3276870 is called twice. The first call belongs to the bit-3 group; the second belongs to the bit-4 group. These calls are consecutive in this function’s call sequence.

### 4. Resolve and perform the final store

After all selected groups return normally, the function resolves the final destination using the final table source and the same signed low-16-bit index.

It reads the selected entry’s object address and writes the 32-bit value 7 at object offset 2,136.

This address resolution occurs after the dependency calls. It is not a reuse of the initially resolved object address. Changes made by dependencies to relevant table state can therefore affect the final destination.

The function then returns without a defined result value.

## Side effects

### Direct writes

The supplied body establishes two direct 32-bit writes on every normally completed invocation:

1. The masked requested value at the initial destination.
2. The value 7 at the final destination.

These stores are unconditional with respect to the selection bits. The second remains dependent on all preceding execution completing normally.

There is no direct read of either destination’s previous field value and no merge with its previous contents.

### Indirect effects

F-3e1cbf8608fb and the selected dispatch dependencies may have effects beyond the two direct writes. Their bodies and behavioral contracts are not supplied.

Do not assume that these dependencies:

- Preserve global table bases or entry contents.
- Preserve either destination object.
- Allocate, retain, transfer, or release memory in any particular way.
- Leave the initially stored field unchanged.
- Return normally.
- Are idempotent, reentrant, or safe to invoke twice.

The supplied body contains no explicit allocation, release, rollback, synchronization, or recovery mechanism. Its pointer accesses do not by themselves establish ownership.

### Failure and partial completion

No explicit argument rejection, bounds check, null check, error return, or rollback is visible.

If an access fails or a dependency does not return normally, later calls and the final store are not guaranteed to occur. Earlier completed effects are not explicitly undone.

The body establishes ordering within this invocation. It does not establish atomicity, concurrency safety, or visibility guarantees to other threads, devices, or asynchronous observers.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed test results. Unless stated otherwise, they assume valid memory accesses, normally returning dependencies, and no concurrent interference.

### Masked initial value

For a requested value of 0xFFFFFFFE, the initial 32-bit store must contain 2. For 0xFFFFFFFF, it must contain 3. No upper input bits may remain in the directly assigned field.

A later dependency may overwrite that field; its final contents are therefore not guaranteed solely by this criterion.

### No selected groups

If F-3e1cbf8608fb returns 0, the observable sequence is the initial store, the selection-producing call, and the final store.

A result of 0x80000000 produces the same dispatch-group sequence because all five relevant bits are clear.

### Multiple selected groups

For a selection value of 0x05, the dispatch calls must be:

1. F-a7c7afa4b061.
2. F-43f8f156d0c4.
3. F-1f0f08ed1151.

No bit-1, bit-3, or bit-4 action is selected.

### Repeated dependency

For a selection value of 0x18, the dispatch calls must be:

1. F-5333b2c1b9c9.
2. F-74d4f3276870.
3. F-74d4f3276870 again.

Deduplicating the repeated dependency would change the established behavior.

### Signed indexing and full-width forwarding

Entity arguments 0x00000001 and 0xABCD0001 both produce direct index 1. Dependencies must nevertheless receive their respective complete argument values.

An entity argument of 0x0000FFFF produces direct index −1, not 65,535. Whether that entry is valid is an environmental precondition, not a check performed here.

### Final destination changed by a dependency

If a returning dependency validly changes the final table source or its selected entry, and no later action reverses that change, the final store must use the destination resolved from that changed state.

### Interrupted execution

If a selected group’s first dependency does not return, the group’s second dependency and the final store are not required to occur. The earlier initial store is not explicitly rolled back.
