# F-7aa404df27a8

## Purpose

The established behavior is a predicate-directed interval search. A zero dependency result retains the lower portion of the current candidate set; any nonzero result discards the selected candidate and everything before it.

A conventional boundary-search interpretation is **inferred intent**, not an unconditional guarantee. That interpretation requires an appropriate initial count from F-870c4fcf7295, valid address arithmetic, and a predicate that partitions the records consistently. The supplied evidence does not establish those dependency contracts.

## Behavior

The evidence does not establish a public layout joining those two local words. In particular, the address passed to F-e46aba7df1fa must not be specified as the beginning of a larger initialized structure merely because another initialized word exists nearby in the recovered representation.

The function forms the difference between the second and first arguments and calls F-870c4fcf7295 with:

- That difference as its first argument.
- The integer value 12 as its second argument.

This dependency call occurs once, even when the supplied endpoints are equal or appear reversed.

The dependency’s returned value becomes the initial signed candidate count. Its actual operation is unknown. Although the argument shape suggests conversion of a byte distance into a record count, the evidence does not establish division, rounding behavior, validation, or handling of negative distances.

The second argument is not used again after this initial difference is formed. The function does not subsequently compare candidate addresses or its return value with the original upper endpoint.

### Candidate selection and predicate call

A search iteration occurs only while the current count is strictly positive.

For each such iteration:

- The function obtains the integer half of the current count. Because the count is positive, this is its mathematical half rounded down.
- It selects the candidate at that many 12-byte strides from the current lower address.
- It calls F-e46aba7df1fa using the local search-state address, the candidate address, and the unchanged opaque context value.

The local search-state word is initialized once, not once per iteration. Every predicate call receives the address of the same word.

The function does not explicitly read or interpret that word after initialization. A dependency may nevertheless read or modify it through the supplied address. Any such changes remain in that storage for later calls; this function does not restore the original fourth-argument value.

### Zero and nonzero outcomes

Only the distinction between zero and nonzero matters.

If F-e46aba7df1fa returns zero:

- The current lower address remains unchanged.
- The next count is the previously computed half-count.

If it returns any nonzero value:

- The current lower address becomes the selected candidate address plus 12.
- The next count is the old count minus the half-count minus one.

Negative nonzero results therefore take the same branch as positive nonzero results. The function does not interpret a negative result as an error or use the magnitude of the result.

There is no equality-specific exit. The function continues narrowing until its count is no longer positive.

### Termination and returned address

A zero or negative initial count causes no call to F-e46aba7df1fa. The function returns the original first argument after the initial F-870c4fcf7295 call completes.

For a positive count, either branch strictly reduces the count:

- The zero branch retains the lower half.
- The nonzero branch retains the portion after the selected candidate.

Thus, assuming ordinary arithmetic and returning dependency calls, the count progression terminates. This remains true even if predicate outcomes vary unpredictably, although the returned address may then have no useful boundary-search meaning.

The return value is the final lower address representation. There is no separate success indicator, found flag, or not-found sentinel.

Under the additional assumptions of a correct record count and a stable predicate that is nonzero on a prefix and zero thereafter, the return identifies the first zero-result record. If all records produce nonzero results, the return is the address immediately after the final record. If all produce zero, it is the original lower address.
