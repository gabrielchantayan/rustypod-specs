# F-4b9706cf1b41

## Purpose

F-4b9706cf1b41 performs a synchronous polling-and-update sequence over storage reached through a global pointer:

1. Capture the pointer’s initial value.
2. Wait until a 32-bit field reached through the global pointer reads as zero.
3. Set six bits in another 32-bit field reached through that global pointer.
4. Wait until a 32-bit field reached through the captured pointer reads as zero.
5. Read the first 32-bit field through the captured pointer and assign that value back to the same location.

The distinction between the **current global pointer** and the **captured pointer** is part of the behavior. They initially identify the same storage, but the supplied representation does not establish that the global pointer remains unchanged.

An initialization, synchronization, or device-control purpose is plausible but inferred. The established behavior is the access sequence above. The evidence does not identify a device, protocol, register definition, or higher-level completion condition.

## Behavior

### 1. Capture the initial base

Before the first polling phase, the function obtains the global pointer’s value and retains it as the captured base.

Later operations do not all use this captured value. In particular, the first polling condition and the bit-setting operation reference the global pointer directly.

No field read or write is shown before this capture.

### 2. Poll through the global pointer

The first polling phase repeatedly examines the 32-bit element at offset +16 through the global pointer.

The condition is evaluated at least once. A zero value ends this phase; any nonzero 32-bit value causes another iteration. No individual bit or subset of bits is tested.

The loop has an empty body. It contains no explicit delay, scheduler yield, callback, timeout, retry limit, or error path.

At the source-expression level, this phase uses the global pointer rather than the captured base. If the environment permits an externally changed pointer to be observed, successive condition evaluations can therefore refer to different objects. Whether such changes are actually reloaded and observable is not established by the supplied representation.

The function cannot reach the update step unless this polling phase ends.

### 3. Set bits through the global pointer

After the first polling phase ends, the function updates the 32-bit element at offset +32 through the global pointer.

The assigned value is the value read from that field, bitwise ORed with `0x00003F00`. For a stable base and ordinary storage, this means:

- Bits 8–13 of the stored value are one.
- Every other bit equals the corresponding bit in the value read for this update.
- Bits already set within the mask remain set.
- No other bit is intentionally cleared or set.

This is a read-modify-write expression, not an established atomic operation. An external writer can therefore invalidate any expectation that unrelated concurrent changes are preserved.

The destination address and the value-producing address both depend on the global pointer. The evidence does not establish one indivisible pointer snapshot shared by those evaluations. If the pointer changes during the expression, it is not justified to promise that the read and write address the same object.

The first successful zero observation also does not lock the pointer or the polled object. It need not describe the object subsequently reached by the update.

### 4. Poll through the captured pointer

After the update, the second polling phase examines the 32-bit element at offset +16 through the captured base.

This condition is evaluated at least once, even if the first polling phase already observed zero at the same address. Zero ends the phase; every nonzero value repeats it.

The second phase does not intentionally adopt a later global-pointer value. If the global pointer has been redirected since entry, this wait still concerns the initially captured object.

As with the first phase, there is no explicit timeout, cancellation mechanism, delay, or error result. The final assignment is unreachable until this phase ends.

### 5. Read and assign back through the captured pointer

After the second phase ends, the function reads the 32-bit element at offset +0 through the captured base and assigns that value back to the same location.

For stable ordinary memory without intervening modification, the stored numerical value is unchanged. This does not establish that the operation is observationally inert:

- A device-backed read or write may have side effects.
- An external change between the read and write may be overwritten.
- Whether the apparent read and write survive compilation depends on access properties not supplied here.

The assigned value is taken from offset +0 at this final stage. It is not a value saved before either polling phase.

The function then returns without a value.

## Side effects

The supplied representation explicitly contains two assignments to referenced storage:

1. The masked update at offset +32 through the global pointer.
2. The read-back assignment at offset +0 through the captured pointer.

It does not explicitly write offset +16 or assign a new value to the global pointer.

The intended expression-level sequence is:

- Capture the base.
- Complete the first polling phase.
- Perform the masked update.
- Complete the second polling phase.
- Perform the final read-back assignment.
- Return.

A polling phase that never ends prevents every later action. The function can therefore perform the offset +32 update and still never reach the final assignment or return.

There is no explicit allocation, release, ownership transfer, logging, exception construction, or resource cleanup. The function retains a pointer for its own execution, but nothing establishes that it acquires ownership or extends the referenced storage’s lifetime.

These statements describe the visible operations in the supplied representation, not guaranteed physical bus transactions. Memory-mapped behavior, caching, compiler transformations, and concurrent access rules remain unresolved.

## Acceptance examples

These are conditional contract examples, not runtime test results. Unless stated otherwise, they assume valid ordinary storage, a stable global pointer, no concurrent modification, and access semantics that execute the represented operations.

### Both polling observations are zero

Suppose offset +16 reads as zero in both phases, offset +32 initially contains `0x80000001`, and offset +0 contains `0x12345678`.

Expected behavior:

- The first polling phase ends on its first condition evaluation.
- Offset +32 receives `0x80003F01`.
- The second polling phase ends on its first condition evaluation.
- Offset +0 is read and assigned its read value, `0x12345678`.
- The function returns without a value.

### Mask bits are already set

Suppose offset +32 contains `0xA5A53F5A`, and both polling phases end.

The update assigns `0xA5A53F5A`: the OR does not change the numerical value. This does not establish that the write has no observable effect on device-backed storage.

### First polling phase never observes zero

Suppose every condition evaluation in the first phase observes a nonzero value.

The function remains in that phase. It does not perform the offset +32 update, enter the second phase, execute the final assignment, or return.

### Second polling phase never observes zero

Suppose the first phase ends, the masked update executes, and every condition evaluation through the captured base subsequently observes a nonzero value.

The update has occurred, but the function remains in the second phase. The final assignment and return do not occur.

### Global pointer redirects after capture

Suppose the captured base identifies object A. Before the first polling observation, the global pointer changes to object B and then remains stable. Assume the environment makes that change observable.

If B’s offset +16 reads as zero:

- The first phase ends based on B.
- The masked update targets B’s offset +32.
- The second phase polls A’s offset +16.
- If that phase ends, the final assignment targets A’s offset +0.

This example demonstrates why the two base-selection rules must not be collapsed into a single-object contract.

### Final read-back overlaps an external update

Suppose the final read obtains one value, then an external actor writes another value before the function’s assignment.

Without additional synchronization, the function’s assignment can overwrite that intervening value with the value it previously read. Numerical self-assignment is therefore not a guarantee of concurrency safety.
