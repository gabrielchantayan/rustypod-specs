# F-445198130f42

## Purpose

F-445198130f42 maps an unsigned input to an unsigned result using two distinct rules:

- Inputs below 12 select a byte from externally supplied storage.
- Inputs of 12 or greater produce half the input’s distance from 12, rounded down.

The first rule is data-dependent. The second is independent of the table and does not access it.

**Established static evidence:** The supplied representation contains one unsigned argument, one unsigned result, a comparison against 12, a byte-sized lookup for the lower range, and subtraction followed by a one-bit right shift for the upper range.

**Inferred intent:** The function appears to combine a small exceptional mapping with a regular arithmetic mapping. No application-level meaning for either range is established.

## Interface

One unsigned integer value.

The supplied representation names its integer type as `uint`, but does not include the declaration that fixes that type’s width. This contract therefore distinguishes:

- **Width-independent behavior:** Valid for an unsigned input type of width \(W\), provided that type can represent 12.
- **32-bit interpretation:** Concrete bounds and examples assuming `uint` denotes a 32-bit unsigned integer.

Negative values are not part of the function’s represented input domain. Any conversion from a signed or wider caller value occurs outside the behavior shown here.

### Output

One unsigned integer result of the same represented integer type as the input.

For inputs below 12, the result is the selected byte’s unsigned numeric value. Assuming an 8-bit byte, this is between 0 and 255 inclusive.

For inputs of 12 or greater, the result is:

\[
\left\lfloor \frac{x-12}{2} \right\rfloor

where \(x\) is the input value.

There is no separate status result, error indicator, or returned pointer.

### External storage

The supplied representation establishes neither the table’s contents nor its allocation size. It also does not establish whether the base or table can change between calls.

## Behavior

### Branch selection

The input is compared with 12 using unsigned ordering.

- Inputs from 0 through 11 take the lookup branch.
- Input 12 and every larger representable input take the arithmetic branch.

The two branches are alternatives. The arithmetic branch does not fall back to the table, and the lookup branch does not apply the arithmetic mapping to the selected byte.

### Lookup branch

For an input below 12, the function obtains the external base and uses the input as a byte offset from that base. It reads one byte at the resulting address and returns that byte as an unsigned integer.

The effective layout is a sequence of individually addressable bytes:

- Offset 0 corresponds to input 0.
- Offset 1 corresponds to input 1.
- This correspondence continues through offset 11 for input 11.

There is no element-size multiplier beyond the byte-addressed offset. The lookup is not represented as an array of multi-byte integers.

The selected byte is interpreted as unsigned. Under the 8-bit-byte interpretation, a stored value with its high bit set still yields a nonnegative result between 128 and 255; it is not sign-extended.

Only the selected byte is required by the represented operation. No scan, terminator search, adjacent-entry lookup, or table-wide validation is shown. Byte order does not affect the numeric interpretation of a single-byte entry.

### Arithmetic branch

For an input of at least 12, subtraction occurs before shifting. The function subtracts 12 and shifts the resulting unsigned value right by one bit.

Because this branch requires the input to be at least 12, the subtraction does not underflow. The shift is an unsigned right shift, so its numeric effect is division by two with any fractional part discarded.

Consequently, adjacent pairs of inputs produce the same result:

- Inputs 12 and 13 produce 0.
- Inputs 14 and 15 produce 1.
- Inputs 16 and 17 produce 2.

More generally, inputs \(12+2k\) and \(13+2k\) both produce \(k\), whenever those inputs are representable.

The result depends only on the argument. Table contents and base validity do not participate in this branch.
