# F-e549ea198d52

## Purpose

F-e549ea198d52 conditionally replaces an entry in a caller-held collection or adds a new entry when no match is found. Matching uses a 32-bit value obtained from the first word of each examined entry through a dependency.

The established behavior is a sequence of dependency calls and accesses to caller-provided storage. Interpreting the operation as an “insert or replace by key” operation is inferred intent: the actual collection representation, meaning of the matching value, and effects of replacement and insertion are not established here.

The function returns the 32-bit value `1` after either its replacement path or its insertion path completes normally. This value does not distinguish insertion from replacement and does not report a dependency’s success or failure.

## Interface

The function accepts four arguments:

| Argument | Role | Established representation |
|---|---|---|
| Collection-handle slot | Address of caller-provided storage containing the current collection handle | A pointer to a location accessed as a 32-bit integer |
| Requested match value | Value compared against the result of extracting an entry’s match value; also passed to entry construction | 32-bit integer, compared for equality |
| First construction value | Forwarded to the construction dependency | Opaque 32-bit word |
| Second construction value | Forwarded to the construction dependency | Opaque 32-bit word |

The return value is a 32-bit word with the value `1` on every explicit normal return.

### Storage and layout requirements

The collection-handle slot must be readable at entry. If its initial contents are zero, the function also writes that slot. The supplied body contains no check for an invalid slot address.

A nonzero handle is passed to collection dependencies without local validation. Zero is treated specially only by the initial branch; the function does not establish that zero can never be passed to a later dependency.

Each examined entry is obtained as a pointer-like result from F-6bbddce1b930. The function directly reads one 32-bit word at offset zero from that result. No other entry offsets are directly accessed.

Consequently, a normally executing search requires each examined result to permit that first-word read. The function does not check whether an entry result is null or otherwise invalid. Alignment requirements and behavior on inaccessible memory are not established.

### Ownership

The interface does not establish ownership of the collection, entries, or construction values.

In particular:

- Passing the matching entry pointer to F-5d1b5e970d51 does not, by itself, prove that the dependency frees it.
- Passing a constructed 32-bit value to an insertion or replacement dependency does not prove that ownership transfers.
- The function performs no explicit rollback or cleanup if construction or a later collection operation fails.
- Whether either construction value denotes memory, an identifier, or an immediate value is unknown.

## Behavior

### Initial handle decision

The function first reads the collection-handle slot and compares its contents with zero.

If the value is zero:

1. It calls F-c141a8d8555e without arguments.
2. After that call returns, it writes the returned 32-bit value into the collection-handle slot.
3. It proceeds directly to construction and insertion.

There is no search in this branch. Even if the returned handle designates an existing or populated collection, that collection is not examined before insertion.

The returned handle is stored without a success check. If F-c141a8d8555e returns zero, zero is still stored, and the construction-and-insertion path is still attempted.

If the initial slot value is nonzero, the function searches through the collection dependencies.

### Search order and bounds

The search begins with a 32-bit signed index of zero.

Before each possible entry examination, the function:

1. Reads the current handle from the caller’s slot.
2. Calls F-10b760faca36 with that handle.
3. Interprets the returned value as the signed bound used in the comparison.
4. Continues only if the current index is strictly less than that bound.

The bound is obtained again for every iteration. It is not a snapshot taken before the search. A negative or zero first bound prevents any entry examination.

When an iteration is admitted, the function:

1. Reads the handle slot again.
2. Calls F-6bbddce1b930 with that handle and the current index.
3. Reads the first 32-bit word from the returned entry pointer.
4. Calls F-2eb743f270d1 with that word.
5. Compares the dependency’s 32-bit result with the requested match value.

A mismatch advances the index by one and returns to the bound query. A match immediately takes the replacement path.

Thus, for a stable collection and stable dependency results, entries are examined in increasing index order and only the first matching entry is acted upon. No later entry is examined after a match.

The index increment is 32-bit signed arithmetic in the supplied representation. The body supplies no explicit overflow handling. No wraparound-based search behavior is promised for an execution that reaches signed overflow.

### Replacement path

When an examined entry matches, the function performs these operations in order:

1. Calls F-5d1b5e970d51 with the entry pointer returned for that iteration.
2. Calls F-610221d5244d with the requested match value and both construction values, preserving their argument positions and 32-bit contents.
3. Reads the current handle from the caller’s slot.
4. Calls F-c2674fa3e73d with that handle, the matched index, and the 32-bit result of construction.
5. Returns `1`.

The existing entry is therefore passed to F-5d1b5e970d51 before the replacement value is constructed. There is no locally implemented transactional safeguard that preserves or restores the prior entry if construction fails.

The index supplied to replacement is the index that matched. It is not recalculated after F-5d1b5e970d51 or F-610221d5244d returns.

The entry pointer is not directly dereferenced again after the call to F-5d1b5e970d51.

### Construction-and-insertion path

This path is taken either after initial handle creation or after the search terminates without a match.

The function:

1. Calls F-610221d5244d with the requested match value and the two construction values.
2. Reads the current handle from the caller’s slot.
3. Calls F-754616bec4de with that handle and the constructed 32-bit value.
4. Returns `1`.

There is exactly one construction call on every normal path. The function does not interpret the constructed value before passing it onward. A zero result is passed onward just like any other 32-bit result.

### Mutable state between calls

The handle slot is not copied into a single persistent local handle for the operation. It is read separately for bound queries, entry retrieval, and the final insertion or replacement.

Accordingly, the handle used for a bound query need not equal the handle used for the immediately following entry lookup if intervening activity changes the slot. Likewise, the final mutation may target a different handle from the one through which the matching entry was obtained.

The supplied body does not prove that dependencies can access or modify this slot, but it also provides no basis for assuming that they preserve it. Dependencies could affect reachable state through aliasing, shared state, or callbacks. The ordered rereads remain part of the contract regardless of whether such changes occur in a particular integration.

### Error behavior

There is no explicit error return, exception handler, retry, or rollback.

The function does not inspect a status from:

- Handle creation before storing its result.
- Entry handling through F-5d1b5e970d51.
- Construction before forwarding its result.
- Final insertion or replacement.

The return value `1` therefore means only that execution reached an explicit return. If a dependency does not return normally, or a direct memory access cannot complete, this body does not establish an outcome.

## Side effects

Direct effects established by the supplied body are limited to:

- Reading the caller’s collection-handle slot.
- Writing the creation result to that slot when its initial value is zero.
- Reading the first 32-bit word of each examined entry.
- Invoking dependencies in the order described above.

All other state changes are dependency-mediated.

In particular, actual collection allocation, entry destruction, resource release, collection resizing, insertion, and replacement are not independently established. Their names in this document describe their apparent roles in the call sequence, not verified internal effects.

The initial handle write occurs before construction. On the replacement path, F-5d1b5e970d51 is invoked before construction. These effects are not delayed until the final collection operation succeeds.

The function contains no direct writes to an entry’s contents, no direct element-array update, and no explicit deallocation operation outside the opaque dependency calls.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied static body, not results of runtime tests. Each example assumes valid direct memory accesses and normally returning dependencies unless stated otherwise.

### Initially absent collection

Given a slot initially containing zero, F-c141a8d8555e returns handle H, and construction returns value V:

- H is written into the slot before construction.
- No bound query, entry lookup, matching-value extraction, or existing-entry handling occurs.
- Construction receives the three supplied construction inputs in their original positions.
- If the slot still contains H after construction, insertion receives H and V.
- The function returns `1` after insertion returns.

### Nonzero handle with no searchable entries

Given a nonzero initial handle and a first bound result of zero or a negative signed value:

- The bound dependency is called once.
- No entry pointer is requested or dereferenced.
- No existing-entry handling call occurs.
- One construction call and one insertion call occur.
- The function returns `1`.

### Match at the second entry

Given stable state, bounds sufficient to examine indices zero and one, a mismatch at zero, and a match at one:

- The bound is queried before each of those two examinations.
- Entry zero’s first word is processed before entry one’s first word.
- Only entry one’s pointer is passed to F-5d1b5e970d51.
- That call precedes construction.
- Replacement receives index one and the construction result.
- No insertion call and no examination of index two occur.

### Duplicate match values

Given stable state with matching entries at indices zero and two:

- The match at zero ends the search.
- Replacement is requested at index zero only.
- The duplicate at index two is not examined or handled.

### Bound changes during search

Given that index zero does not match, the index advances to one, and the next bound query returns one:

- The comparison fails because one is not strictly less than one.
- Index one is not retrieved.
- Construction and insertion follow.

This behavior requires no fixed initial collection size.

### Handle changes before final mutation

Given a match through handle H and a subsequent dependency changes the caller’s slot to J before the final replacement call:

- Replacement receives J, the previously matched index, and the construction result.
- The function does not revalidate that index against J or repeat the match.

This example specifies the observable reread, not a claim that any particular dependency performs such a change.

### Zero construction result

Given construction returns zero:

- Zero is forwarded to the selected insertion or replacement dependency.
- No local failure branch is taken.
- If the final dependency returns normally, the function returns `1`.
