# F-86bbe4b762d8

## Purpose

F-86bbe4b762d8 traverses an object's indexed entries, invokes a caller-supplied callback for eligible terminal entries, and recursively processes eligible nested objects. It returns a 32-bit status and communicates a separate result through a caller-supplied byte.

Traversal stops on an error, exhaustion of the current object's entries, or a successful entry operation whose result byte satisfies the current object's stopping rule. That rule depends on bit 0 of a 32-bit object field.

**Established behavior:** the function performs ordered validation and preparation calls, clears the result byte, visits entries in ascending unsigned index order, and calls an exit dependency when leaving an initialized traversal.

**Inferred intent:** the object flag and shared result byte appear to support two different aggregation or short-circuit modes. The available evidence does not establish domain-specific meanings such as “match,” “success,” “all,” or “any.”

## Interface

### Inputs

The interface has six arguments, in this order:

1. **Object reference.** A 32-bit value used both as an argument to object-related dependencies and as the base address for direct field reads. The function does not explicitly reject zero before passing it to the first dependency.
2. **First callback argument.** A 32-bit value required to be nonzero. Forwarded unchanged to callbacks and recursive invocations. Whether it represents an address, handle, or scalar is unknown.
3. **Second callback argument.** A 32-bit value required to be nonzero. Forwarded unchanged in the same manner. Its interpretation is unknown.
4. **Callback address.** A required, non-null callable address. Each terminal-entry invocation receives five arguments: a temporary entry-record address, the first callback argument, the second callback argument, the opaque argument described next, and the result-byte address.
5. **Opaque callback argument.** A 32-bit value forwarded unchanged. Zero is permitted by this function.
6. **Result-byte address.** A required, non-null address at which the function writes and reads one byte. The caller must provide writable storage for that byte and maintain its validity across callbacks and recursion.

The exact calling convention and callback type beyond the observed argument list and returned status are not established.

### Outputs

The function returns a signed 32-bit status:

- **−50** when either required callback argument is zero, the callback address is null, or the result-byte address is null.
- A nonzero status returned by a preparation dependency, entry-fetch dependency, callback, or recursive invocation.
- **0** for entry exhaustion or a result-dependent early stop following a successful entry operation.

The result byte is a separate output channel. Zero and nonzero have distinct control-flow meanings; the function does not normalize nonzero values to one.

A zero return does not, by itself, establish that an entry was visited or that the result byte is nonzero.

### Directly accessed object fields

The function directly reads two fields relative to the object reference:

| Byte offset | Width | Interpretation in this function |
|---|---:|---|
| 12 | 32 bits | Flags; only bit 0 affects traversal stopping |
| 16 | 32 bits | Unsigned entry-count bound |

These reads require valid, suitably accessible storage. The function does not itself establish the complete object layout, allocation size, alignment contract, or lifetime.

### Temporary entry record

The entry-fetch dependency receives the address of a stack-resident temporary record. The supplied representation supports this working layout:

| Relative byte offset | Width | Use |
|---|---:|---|
| 0–7 | 8 bytes | Not directly interpreted by this function |
| 8 | 1 byte | Terminal-versus-nested discriminator |
| 9 | 1 byte | Eligibility discriminator |
| 10–11 | 2 bytes | Not directly interpreted |
| 12–15 | 4 bytes | Nested object reference when recursive processing is selected |

This layout is reconstructed from the supplied stack representation, not independently verified as a public record ABI. The two discriminator bytes are tested only for zero versus nonzero.

## Behavior

### Argument checks and preparation

The function first rejects any call in which the first callback argument, second callback argument, callback address, or result-byte address is zero. Such a call returns −50 without invoking any dependency and without writing the result byte.

For arguments that pass those checks, the function invokes:

1. F-cf176702439d with the object reference.
2. F-f3fb3c9e6fe1 with the object reference, but only if the first dependency returned zero.

A nonzero result from either dependency is returned immediately. The second dependency is not called after a failure of the first. Neither failure path invokes F-e7fa8e2c3df9, and neither performs the function's explicit result-byte initialization.

Those dependencies may themselves have side effects. Thus, “no explicit initialization” does not imply that the result byte or other reachable storage remains unchanged.

Only after both preparation calls return zero does the function set the traversal index to zero, write zero to the result byte, and begin traversal.

### Entry enumeration

Before each entry fetch, the function reads the current unsigned 32-bit entry-count field at object offset 16.

If the current index is greater than or equal to that count, traversal ends with status zero through the exit dependency.

Otherwise, F-21c1171f3c98 is called with:

- The current object reference.
- The current unsigned 32-bit index.
- The address of the temporary entry record.

A nonzero fetch status terminates traversal with that status. The function does not inspect the fetched record on this failure path.

On a zero fetch status, the function examines the record's eligibility byte:

- **Zero:** skip the record. Do not invoke the callback or recurse, and do not evaluate the result-dependent stopping rule for that record.
- **Nonzero:** process the record according to its terminal-versus-nested discriminator.

The temporary storage is reused across iterations. No explicit initialization of the record occurs before each fetch. Successful fetching must therefore provide the fields subsequently consumed; otherwise, their values are not established by this function.

### Terminal and nested processing

For an eligible record with a zero discriminator, the function invokes the callback. The callback receives the temporary record address and the four forwarded arguments described in the interface.

For an eligible record with a nonzero discriminator, the function instead recursively invokes F-86bbe4b762d8. The nested object reference is taken from the record's 32-bit field at relative offset 12. All other arguments are forwarded unchanged.

There is no independent null check of that nested reference before recursion. The recursive invocation performs its own argument checks and preparation calls.

A nonzero callback or recursive status immediately ends the current traversal through F-e7fa8e2c3df9. The result-dependent stopping rule is not evaluated on that path.

### Result-dependent stopping

After an eligible record has been processed with status zero, the function reads the current flags field at object offset 12. It then reads the result byte and applies this rule:

| Current flag bit 0 | Result byte | Action |
|---|---|---|
| Clear | Zero | Stop with status zero |
| Clear | Nonzero | Continue |
| Set | Zero | Continue |
| Set | Nonzero | Stop with status zero |

The flags read occurs after callback execution or recursive completion. The function therefore does not use a cached entry-time flag value.

The result byte is also read after that operation. It may have been changed by the callback, recursive processing, or any side effects within their dependencies. A nested invocation that successfully completes its own preparation clears this same byte before beginning its traversal; the caller's earlier byte value is not preserved automatically.

If traversal continues, the index advances by one and the next iteration reloads the count field. Ineligible records also advance the index.

The index arithmetic is unsigned 32-bit arithmetic. Under the displayed count-bound check, the increment cannot wrap: an index of the maximum 32-bit unsigned value cannot be less than any representable count, so it cannot reach the increment through a valid bounded iteration.

### Traversal exit

Every normal return path after traversal initialization invokes F-e7fa8e2c3df9 once for that invocation's object.

This includes:

- Count exhaustion, including an initial count of zero.
- Entry-fetch failure.
- Callback failure.
- Recursive failure.
- Result-dependent early termination.

The exit dependency's return value is ignored. The traversal status selected before that call is returned.

A nested invocation that reaches initialized traversal performs its own exit call. If it returns a nonzero status, the parent then performs its exit call before returning that same status.

These guarantees concern the displayed ordinary control flow. They do not establish behavior if a dependency fails to return normally.

## Side effects

The function explicitly writes zero to the result byte once per invocation that passes both preparation calls. It makes no other direct writes to caller-owned object fields in the supplied representation.

Callbacks, recursion, and dependencies can introduce additional writes and other effects. Their effects are not constrained by this function.

Observable ordering includes:

- Both preparation calls precede explicit result-byte initialization.
- Result-byte initialization precedes the first count-field read.
- The count-field read precedes the corresponding fetch.
- Successful fetching precedes discriminator inspection and entry processing.
- Successful entry processing precedes the flags read and stopping-rule result-byte read.
- The exit dependency precedes the ordinary return from initialized traversal.

The count is reloaded on every iteration. Changes made by callbacks or dependencies can therefore affect subsequent enumeration. The flags are reloaded after each successful eligible operation and can likewise reflect intervening changes.

The function contains no explicit allocation or deallocation. That does not establish that its dependencies allocate nothing, release nothing, or preserve object lifetime.

The temporary record belongs to the current invocation's stack storage. A callback receives access during its invocation, but the evidence provides no ownership transfer or right to retain that address. Later iterations reuse the storage, and return ends its lifetime.

The function does not check cycles, enforce a recursion-depth limit, or validate the complete reachable object graph. Termination requires suitable dependency behavior and a traversable structure that does not produce unbounded recursive descent.

Aliasing restrictions are unknown. If the result-byte address aliases object fields or other dependency-visible storage, the explicit zero write may affect later reads. The evidence does not justify silently assuming disjoint storage.

## Acceptance examples

These examples are conditional predictions from static evidence, not executed tests. Except where stated otherwise, dependencies return normally, required storage remains valid, and unmentioned side effects do not occur.

1. **Invalid required callback argument.**  
   If either required callback argument is zero, the function returns −50. It performs no dependency calls and no explicit result-byte write.

2. **First preparation failure.**  
   If the first preparation dependency returns 7, the function returns 7. The second preparation dependency and exit dependency are not called.

3. **Second preparation failure.**  
   If the first preparation dependency returns zero and the second returns −3, the function returns −3 without explicit result-byte initialization or an exit call.

4. **Empty object.**  
   If preparation succeeds and the count read is zero, the function writes zero to the result byte, fetches no entries, invokes the exit dependency, and returns zero.

5. **Ineligible record.**  
   If a successful fetch marks a record ineligible, neither callback nor recursion occurs for it. The result-dependent stopping rule is not applied, even if the existing result byte would otherwise satisfy that rule.

6. **Terminal short-circuit with bit 0 clear.**  
   If an eligible terminal callback returns zero and leaves the result byte zero, a subsequently read clear flag bit 0 causes immediate exit with status zero. No later entry is fetched.

7. **Terminal continuation with bit 0 set.**  
   If that callback leaves the result byte zero and the subsequently read flag bit 0 is set, traversal advances to the next index, subject to the next count check.

8. **Noncanonical nonzero byte.**  
   If a successful callback writes the byte value 128 and flag bit 0 is set, traversal stops. The comparison treats 128 as nonzero; the function does not require the value one.

9. **Callback error takes precedence.**  
   If a callback writes a nonzero result byte but returns −9, the function invokes the exit dependency and returns −9 without evaluating the stopping rule.

10. **Nested initialization replaces an earlier result.**  
    If an eligible nested object's preparation succeeds and its count is zero, the nested invocation clears the shared result byte and returns zero after its exit call. The parent then evaluates its own current flag against that zero byte.

11. **Changed count affects continuation.**  
    If successful entry processing changes the count to one while index zero is being processed, and the stopping rule permits continuation, the next index is one. The next count read ends traversal without fetching index one.

12. **Exit return does not replace traversal status.**  
    If a fetch returns 12 and the exit dependency returns a different value, the function still returns 12.

## Uncertainties

- Whether callbacks may retain record addresses, alter traversal structure, reenter the function, or modify global state under a broader API contract.
- Behavior under concurrent mutation, invalid addresses, malformed successful fetches, cyclic nesting, or abnormal dependency termination.
- A final result-byte guarantee independent of the exit dependency: because that dependency runs after the stopping decision and its effects are unknown, it cannot be assumed to preserve the byte.
