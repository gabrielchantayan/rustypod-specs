# F-90ffec85402c

## Purpose

After that dependency returns, it obtains an indirect target through a structure located 20 bytes into the supplied object and invokes that target with three arguments.

A significant aspect of the behavior is the timing of the shared-state and dispatch reads:

- A 32-bit shared value is saved before the first dependency call.
- A separate read of that same shared location supplies the first dependency’s second argument.
- The indirect target is selected only after the first dependency returns.
- The indirect invocation receives the earlier saved value, not a fresh post-dependency read.

## Behavior

### 1. Preserve an initial shared-state value

The wrapper first reads the shared 32-bit location and retains that value for later use.

This saved value is independent of any subsequent contents of the shared location. A change made by F-069a1d444a2d does not cause the wrapper to refresh the saved value before the indirect invocation.

The retained value is forwarded without an explicit arithmetic operation, range check, mask, or other visible transformation. Its 32-bit representation is the established property; signedness and semantic interpretation are not.

### 2. Invoke the first dependency

The wrapper reads the same shared location again and invokes F-069a1d444a2d with:

1. The original, unadjusted input argument.
2. The value obtained by this second shared-state read.

The saved value from the first read and the value passed to this dependency are therefore sourced from distinct reads.

No intervening call or explicit write appears between those reads. They would ordinarily agree if the storage remains unchanged, but equality is not an unconditional guarantee. External mutation, special storage behavior, or execution conditions not described by the supplied material could make them differ. The source alone establishes neither an atomic snapshot nor a synchronization guarantee.

The wrapper waits for this dependency to return before performing its dispatch-related object reads. If the dependency does not return normally, the ordinary path to the indirect invocation is not established.

### 3. Resolve the indirect target from post-dependency state

After F-069a1d444a2d returns, the wrapper reads a 32-bit dispatch-base value from the original input address plus 20 bytes.

It then reads the executable target from that dispatch base plus 20 bytes.

This timing is observable. The wrapper does not cache either the dispatch base or the executable target before the first dependency call. If that dependency changes the embedded dispatch-base field, or changes the relevant entry in the dispatch structure, the subsequent lookup uses the state available after the dependency returns.

Conversely, there is no visible adjustment to the original input argument based on the dependency’s return value. The wrapper continues to calculate the embedded-region address from the original argument.

The dispatch-base read must precede the target-entry read because the latter address depends on the former. The source does not establish synchronization against concurrent changes to either location.

### 4. Invoke the selected target

1. The original input address advanced by 20 bytes.
2. The shared 32-bit value saved before F-069a1d444a2d was called.
3. Zero.

The first argument is an interior address within the original object, not the original object address. The second argument is not a post-dependency shared-state read. The third argument is a constant zero, not a value obtained from object storage.

The recovered representation presents the third argument as an integer zero, consistent with a 32-bit integer argument in this context. The target’s actual parameter declarations, signedness, and interpretation of zero are unknown.

No additional explicit wrapper operation follows this invocation except return.
