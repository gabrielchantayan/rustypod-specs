# F-467db564e65a

## Purpose

F-467db564e65a checks a structured record against a size-bearing context and returns a 32-bit unsigned result.

The established behavior is a sequence of validations with early termination:

- A record field must be one of seven permitted values.
- A context field must be zero.
- A decoded record value, multiplied by the permitted field, must match another context field under 32-bit modular arithmetic.
- Four further decoded values must each be strictly less than the first decoded value.
- The record’s first 16-bit field must be at most 16.
- The low eight bits of a later 16-bit field select either success or a value obtained from global state.

The fixed rejection result is 37, hexadecimal 0x25. The final byte-valued check differs from earlier checks: values other than 0, 128, and 255 return a global-derived result rather than necessarily returning 37.

The likely intent is validation of size and position metadata. That interpretation is inferred; the record’s domain, field names, and units are not established.

## Behavior

### Initial permitted-value check

The function first reads the unsigned 16-bit record field at offset 18 and retains its value.

Exactly these values pass:

- 512, hexadecimal 0x0200
- 1024, hexadecimal 0x0400
- 2048, hexadecimal 0x0800
- 4096, hexadecimal 0x1000
- 8192, hexadecimal 0x2000
- 16384, hexadecimal 0x4000
- 32768, hexadecimal 0x8000

Every other value produces an immediate result of 37. On that path, there is no dependency call and no context-field read in the supplied body.

The permitted value is retained locally. A later dependency-induced change to the record field at offset 18 does not replace the already captured multiplier.

### Primary decoded value and context checks

After the permitted-value check succeeds, the function calls F-4055be9c3f18 with the record address advanced by 22 bytes. Its result is treated as an unsigned 32-bit value and retained as the primary decoded value.

Only after that call returns does the function read the context field at offset 20.

- If that field is nonzero, the result is 37.
- If it is zero, the context field at offset 16 is read and checked against the retained multiplier times the primary decoded value.

The product is evaluated modulo \(2^{32}\). Acceptance of this comparison requires the context field’s 32-bit bit pattern to equal that wrapped product. Equivalently, subtracting the context field from the product must yield zero modulo \(2^{32}\).

This is not a checked multiplication and not a comparison against an unbounded mathematical product. Overflow does not independently cause rejection.

The context reads occur after the first dependency call. Consequently, the function observes any relevant memory changes made by that call; the evidence does not justify treating the context as a snapshot taken at entry.

### Four strict bounds checks

If both context checks pass, the function makes up to four additional calls to F-4055be9c3f18:

| Order within this phase | Record-relative argument address |
|---:|---:|
| 1 | 26 |
| 2 | 2 |
| 3 | 10 |
| 4 | 14 |

Each returned value is treated as unsigned 32-bit and must be strictly less than the retained primary decoded value.

A result equal to or greater than the primary value causes immediate return of 37. No subsequent call or later direct record-field read is performed by this body on that path.

The comparisons are independent upper-bound checks. The function does not establish that these four values are sorted, mutually distinct, nonzero, or otherwise related.

The primary value remains the result captured from the initial call at offset 22. Later calls do not refresh it, even if they change the record or shared state.

### First-field check

After all four strict bounds checks pass, the function reads the unsigned 16-bit record field at offset 0.

Values from 0 through 16 inclusive pass. Values from 17 through 65535 cause return of 37.

This read occurs after all five dependency calls. It is not an entry-time snapshot and can therefore observe changes made during those calls.

### Final low-eight-bit check

After all preceding checks pass, the function reads the unsigned 16-bit record field at offset 36 and converts it to an unsigned eight-bit value.

Only the low eight numeric bits matter:

- 0 produces result 0.
- 128 produces result 0.
- 255 produces result 0.
- Every other extracted value selects a global-derived result.

The upper eight bits of the 16-bit field do not affect this decision. This is a low-numeric-byte operation; without an established byte order, it must not be described as necessarily selecting the byte at the lower memory address.

For an accepted extracted value, this body does not evaluate the global-value expression. For a different extracted value, it obtains the global value and uses its conversion or assignment into the unsigned 32-bit result.

There is no further validation after this selection.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime observations. Unless stated otherwise, assume all reached accesses are valid, the dependency returns normally, and no intervening side effect changes a stated field.

1. **Immediate rejection without dependency calls.**  
   If the record field at offset 18 is 256, the result is 37. Context contents, dependency behavior, and later record fields are not examined by this body.

2. **Ordinary success.**  
   Suppose the permitted value is 512 and the initial dependency call returns 100. Context offset 20 is zero and offset 16 contains 51200. The subsequent dependency results, in order, are 99, 0, 25, and 75. Record offset 0 contains 16, and the low eight bits at offset 36 are 128. The result is 0.

3. **Context high-field rejection.**  
   With a permitted initial value, the first dependency call occurs. If context offset 20 is then nonzero, the result is 37. Context offset 16 and all remaining dependency calls are skipped.

4. **Equality fails a bounds check.**  
   If the primary decoded value is 100 and the call at offset 26 returns 100, the result is 37. The calls at offsets 2, 10, and 14 are not made.

5. **Zero primary value cannot complete successfully.**  
   A primary value of zero may pass the context checks when the compared context value is also zero. The first subsequent unsigned result cannot be strictly less than zero, so that check rejects with 37.

6. **Wrapped multiplication can pass.**  
   A permitted value of 32768 and a primary decoded value of 131072 have mathematical product \(2^{32}\), whose unsigned 32-bit result is zero. Context fields at offsets 20 and 16 both containing zero therefore pass the context checks. Later checks still determine the final result.

7. **First-field boundary.**  
   After all dependency comparisons pass, record offset 0 containing 16 permits the final check. The same field containing 17 causes result 37 without reading the final field.

8. **Upper bits of the final field are irrelevant.**  
   A final 16-bit field value of 0xAB80 yields extracted value 128. If every preceding check passes, the result is 0.

9. **Fallback need not indicate failure.**  
   If every preceding check passes and the extracted value is 1, the result is the global-derived value. If that value converts to zero, the function returns zero despite the extracted value not belonging to the three-value accepted set.
