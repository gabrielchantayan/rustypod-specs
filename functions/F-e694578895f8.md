# F-e694578895f8

## Purpose

F-e694578895f8 records an input byte and two flag bytes in an object. For an eligible object, it publishes the object address, selects a handle, constructs a temporary descriptor, and invokes one of two submission sequences.

A mode read after descriptor-related calls determines the submission sequence:

- Mode 4 submits three object-held values. If the first is zero, three allocation-like calls and a format-selected conversion-like call precede submission.
- Other modes submit an object value captured earlier, after format-selected setup.

“Descriptor,” “dimension,” “allocation,” “conversion,” and “submission” describe apparent roles. The established behavior is the accesses, arithmetic, branches, arguments, and call ordering below; actual rendering or allocation semantics are not established.

## Interface

The inputs are an object address in a 32-bit address space and an 8-bit value. There is no returned value or explicit error status.

- Two 32-bit format-comparison values, designated **A** and **B**.

## Behavior

### Entry, rejection, and publication

Every invocation first performs these writes, in order:

1. Input byte to object +0x3f.
2. Byte value 1 to object +0xec.
3. Byte value 1 to object +0xed.

The function then captures the global current-object base for possible final clearing.

It reads object +0xfc as a signed 32-bit value. A value of −1 causes immediate return. Otherwise, it reads +0x54; zero also ends processing. These exits retain the three initial byte writes but perform no publication, dependency call, or clearing.

For an eligible object, the function rereads the global base and writes the object address to that base’s +0x14 slot. Publication therefore uses a fresh global read, whereas final clearing uses the earlier captured base. The two writes can target different structures if the global changes.

Next, in order, it:

1. Calls F-5b4ae75440ab with object +0xf4 and the low eight bits of a new +0xfc read, zero-extended to 32 bits.
2. Retains the returned 32-bit handle-like value.
3. Calls F-abc658b0bf5e with the temporary descriptor address.
4. Captures global B, then global A.
5. Captures object +0x50.
6. Reads object +0x100 for descriptor-kind selection.

F-abc658b0bf5e is not established to initialize the descriptor, preserve it, or refrain from retaining its address.

### Descriptor kind and dimension stores

If the first mode read equals 4, the function writes descriptor kind 0 without checking the resource format.

Otherwise, it reads the resource address and its unsigned 16-bit format. Equality with a current read of global A selects kind 2. Failing that comparison, equality with a current read of global B selects kind 3. Neither match causes immediate return without clearing the published slot.

These comparisons use global reads at descriptor selection, not the retained A and B used later. A has precedence when both match.

After writing the selected kind, the function rereads the resource address and calculates the embedded-entity address at +0x98. It writes descriptor byte +0x01 as 3.

The dimension sequence is specifically:

1. Call F-19fde5f06ccc with the calculated embedded-entity address.
2. Store its signed 32-bit result at descriptor +0x14.
3. Call F-b01436b9ce2b with the same calculated address.
4. Store its signed 32-bit result at descriptor +0x18.

The embedded-entity address is not recomputed between calls.

The first result’s store occurs **before** the second call. Because F-abc658b0bf5e already received the descriptor address and may have retained it, F-b01436b9ce2b cannot be assumed unable to modify descriptor +0x14. The subsequent horizontal-span calculation reads that field’s then-current signed 32-bit contents; it does not necessarily use the original F-19fde5f06ccc result.

### Placement and clipping

Placement processing starts after the second dimension result has been stored.

Horizontal placement is read first:

- A nonnegative value is stored as destination horizontal position; horizontal source offset becomes zero.
- A negative value causes destination horizontal position to become zero. Horizontal source offset becomes the negation of a **fresh** read of object +0x30.

Vertical placement is then processed identically using +0x34. Thus, negative branches reread their placement fields; the negated value need not equal the value that selected the branch.

The initial horizontal span is the **then-current signed 32-bit descriptor +0x14 value** minus horizontal source offset. The initial vertical span is the descriptor +0x18 value minus vertical source offset. The latter field was assigned the second dimension result after the second call returned; no further dependency call precedes span construction.

The function reads object +0xf8 to choose bounds:

| Selector | Horizontal bound | Vertical bound |
|---|---:|---:|
| Zero | 720 | 576 |
| Nonzero | 320 | 240 |

Horizontal clipping precedes vertical clipping. Each axis uses a signed comparison of destination position plus span against its bound. Only a strictly greater sum causes replacement of the span by bound minus destination position.

There is no lower-bound clamp, negative-span rejection, or validation that source offsets fit the dimension-like values. Signed-overflow cases remain unresolved.

After writing the 16-bit zero at descriptor +0x30, the function calls:

1. F-dcb90cca1e28 with the retained handle and descriptor address.
2. F-c9bd3b9286da with the handle and 32-bit zero.

Only after both calls does it reread object +0x100. This second mode read selects submission independently of the earlier descriptor-kind choice. Either call may change the object or other accessible state.

### Mode-4 preparation

When the second mode read equals 4, the function reads object +0x104.

A nonzero value bypasses all preparation calls and conversion-format checks. Neither +0x108 nor +0x10c is validated.

For zero +0x104, the function subtracts the horizontal extent start from its end, subtracts the vertical extent start from its end, and multiplies the differences. The operands and arithmetic are signed 32-bit; the result is then held as unsigned 32 bits.

For signed arithmetic that remains representable, conversion to unsigned follows modulo 2³². This does not establish a result for preceding signed overflow.

Preparation proceeds as follows:

1. Call F-638beded7699 with the unsigned quantity and 0x35.
2. Logically shift the retained unsigned quantity right by two.
3. Store the first returned value at object +0x104.
4. Call F-638beded7699 with the shifted quantity and 0x35; store its result at +0x108.
5. Call F-638beded7699 with the same retained shifted quantity and 0x35; store its result at +0x10c.

The shifted quantity is not recomputed from the object between calls. No return value is checked for failure. Neither byte units nor actual allocation are established.

The function then rereads the resource address and its unsigned 16-bit format. Conversion dispatch has this precedence:

| Match | Dependency |
|---|---|
| Fixed format 0x65 | F-9e62624e89e5 |
| Retained A | F-28199ab2af9a |
| Retained B | F-c0ab5b5d32b8 |

No match causes immediate return, retaining the three stored results and leaving the current-object slot uncleared.

Each selected conversion dependency receives six arguments in this positional order:

1. Newly calculated vertical extent difference.
2. Newly calculated horizontal extent difference.
3. Resource +0x04, using the resource address captured for this dispatch.
4. Current object +0x104.
5. Current object +0x108.
6. Retained result of the third F-638beded7699 call.

The final argument is not a fresh +0x10c read. Dimensions are recalculated after the preparation calls and may differ from those used for the product. Argument positions do not establish the evaluation order of independent argument reads.

### Submission and normal completion

Following mode-4 conversion, or the nonzero-+0x104 bypass, calls occur in this order:

1. F-25dd705719a1 with the handle.
2. F-460b2abbbbbe with the handle and a fresh read of object +0x3f.
3. F-307b5e43b9f5 with the handle, fresh reads of +0x104, +0x108, and +0x10c, and zero.

Earlier dependencies may therefore affect the submitted byte and buffer-like values.

If the second mode read is not 4, the function instead rereads the resource address and unsigned 16-bit format:

- Retained A match: call F-25dd705719a1, then F-460b2abbbbbe with the handle and freshly read +0x3f.
- Otherwise, retained B match: call F-f3f14c3b9ccd with the handle, without passing the stored byte.
- Neither match: return without final clearing.

A has precedence over B. Either accepted other-mode branch then calls F-1d891874186d with the handle and the +0x50 value captured before descriptor-kind selection.

Normal completion of either submission sequence writes 32-bit zero to +0x14 of the global base captured near entry. It does not restore a previous slot value.

## Side effects

Direct object writes comprise the three initial bytes and, conditionally, the three preparation-result fields. Other direct writes affect temporary descriptor storage and the current-object slot.

Unsupported formats can leave the current-object publication uncleared:

- Descriptor-kind rejection occurs before dimension and descriptor-submission calls.
- Mode-4 conversion rejection occurs after all three preparation results have been stored.
- Other-mode rejection occurs after both descriptor-related calls.

There is no explicit rollback, release, invalidation, or consistency check. Reuse depends solely on +0x104 being nonzero, not on dimensions, resource identity, or the other two values.

Dependency effects are additional and unknown. They may include mutation through retained addresses. The descriptor address escapes before the dimension calls, so its earlier stores cannot generally be treated as preserved across those calls.

The descriptor has temporary local lifetime. Safe retention beyond that lifetime is not established. Ownership transfer or release responsibility is not established for any handle, resource, descriptor address, or preparation result.

## Acceptance examples

These are conditional static predictions, not executed tests. They assume accessible storage, normally returning calls, representable signed arithmetic, and stable relevant values except for stated mutations.

1. **Sentinel rejection.** With +0xfc equal to −1, the input byte and both flag bytes are written before return. No dependency runs; no slot is published or cleared.

2. **Disabled processing.** A non-sentinel +0xfc and zero +0x54 produce only the initial three writes and relevant entry reads.

3. **Selector truncation.** A +0xfc value of 0x1234 at handle selection supplies selector 0x34.

4. **Stable dimensions and larger bounds.** If the first result is 100, descriptor +0x14 remains 100, the second result is 80, placement is (−10, 550), and +0xf8 is zero, destination becomes (0, 550), source offsets become (10, 0), and spans become (90, 26).

5. **Intervening dimension-field mutation.** Suppose the first call returns 100 and that value is stored at descriptor +0x14. If the second call changes +0x14 through an available alias to 60 and returns 80, stable placement (−10, 0) and larger bounds produce horizontal span 50, not 90. Afterward, +0x14 contains 60 and +0x18 contains 80, absent further mutation.

6. **Smaller bounds.** With preserved dimension fields 100 and 80, placement (300, 230), and nonzero +0xf8, spans become (20, 10).

7. **Negative span.** Horizontal placement 800, current horizontal dimension field 100, and horizontal bound 720 produce span −80. The descriptor is still passed onward.

8. **Preparation quantities.** Stable extents of 8 by 6 produce F-638beded7699 quantity arguments 48, 12, and 12, each accompanied by 0x35. A product of 15 instead produces 15, 3, and 3.

9. **Representable negative product.** Extent differences −1 and 4 produce signed product −4, then unsigned quantity 4294967292. The shifted quantity is 1073741823. No extent-sign check rejects this case.

10. **Existing values.** Second mode 4 and nonzero +0x104 skip preparation and conversion. If later calls preserve the fields, zero +0x108 or +0x10c values are still submitted.

11. **Unsupported preparation format.** Second mode 4, initially zero +0x104, and no conversion-format match leave three results stored but perform no conversion, submission, or final clearing.

12. **Other-mode B.** A non-4 second mode with a format matching retained B but not A calls F-f3f14c3b9ccd, then F-1d891874186d. F-460b2abbbbbe is not called.

13. **Mode mutation.** Descriptor kind 0 does not require mode-4 submission. If the mode read after both descriptor-related calls is non-4, the other-mode branch runs.

14. **Unassigned bytes.** Without an independent F-abc658b0bf5e contract, acceptance cannot require otherwise unassigned descriptor bytes to be zero or initialized.

## Uncertainties

In particular, negating the minimum signed 32-bit value is not assigned a mathematical result here. Signed wraparound is not assumed.

- **Descriptor initialization and retention — documented_only.** The initial descriptor-address call establishes neither initialized bytes nor non-retention.
- **Intervening mutation — established possibility; occurrence documented_only.** The second dimension call follows the first-result store. Its preservation of +0x14 is unknown. Horizontal span uses the field’s current contents regardless of whether mutation actually occurs.

- **Concurrency and reentrancy — documented_only.** No synchronization or global-preservation guarantee is established. Repeated reads must remain distinct.
