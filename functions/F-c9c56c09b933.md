# F-c9c56c09b933

## Purpose

F-c9c56c09b933 is a state-directed dispatcher. It repeatedly reads a one-byte selector at byte offset 8 from a caller-supplied base address and invokes the dependency associated with that selector. Dependency results determine whether dispatch continues.

The established behavior has two distinct termination paths:

- A dependency produces an unsigned 32-bit continuation value greater than 3. The function returns without reading the selector again.
- The selector has a value other than 0, 1, 2, or 3. The function writes zero to the selector byte and returns.

A selector value of zero is an active dispatch state, not a termination condition. Likewise, a continuation value of zero permits further dispatch.

The likely intent is to coordinate a state machine whose transitions are performed by dependencies. That interpretation is inferred. The supplied source establishes dispatch behavior, but not the meanings of the states or of the continuation values.

## Behavior

### Continuation control

Each invocation begins with an unsigned 32-bit continuation value of 3.

Before every selector read, the function checks whether the current continuation value is greater than 3 using an unsigned comparison:

- Values 0, 1, 2, and 3 permit a selector read and another dispatch decision.
- Values 4 through 4,294,967,295 cause immediate return.

The first check necessarily permits dispatch because the initial continuation value is 3.

This continuation value and the selector byte are independent controls. The continuation value gates whether the selector is read at all. The selector then determines which dependency sequence runs.

Consequently, an intermediate value greater than 3 does not itself terminate dispatch. Only the final result of the selected dependency sequence becomes the continuation value tested before the next selector read.

### Read and call ordering

For each dispatch decision, the established order is:

1. Check the unsigned continuation value.
2. If permitted, read the selector byte.
3. Invoke the selected dependency sequence, or reset an unsupported selector and return.
4. If the dependency sequence returns normally, check its resulting continuation value before any further selector read.

There is no selector reread between the two calls in a paired sequence. A selector change made by the first dependency does not change which second dependency is invoked.

There is also no early exit between those paired calls based on the first result. Provided the first call returns normally, the second call is reached with that result even if it resembles a termination value.

After a completed dependency sequence, the function does not retain the earlier selector for the next dispatch decision. If the continuation permits another iteration, it reads the selector again. Changes made by dependencies can therefore affect subsequent dispatch.

### Termination and persistence

A continuation greater than 3 terminates the invocation without a direct selector write. Whatever selector state exists at that point is left untouched by this function.

An unsupported selector terminates the invocation only after a direct one-byte write of zero. That path does not immediately dispatch selector 0; a later invocation would be needed to act on the reset value.

There is no iteration limit, progress check, or requirement that a dependency change the selector. If dependencies keep returning continuation values within 0 through 3, dispatch may continue indefinitely, including repeatedly dispatching the same selector.

Each new invocation restarts its local continuation at 3. The function does not directly persist continuation values across invocations.
