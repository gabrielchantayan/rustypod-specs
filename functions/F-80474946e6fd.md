# F-80474946e6fd

## Purpose

F-80474946e6fd produces two integer outputs using a selector stored in a caller-supplied context.

The selector value −1 chooses a dependency-assisted path: the first output is set to zero, and the second is computed by subtracting one from the result of F-5fca8e42aa3d. Any other selector value chooses a direct path: the first output receives the selector, and the second receives a subsequent read of the selector.

The distinction between the two direct-path reads is observable when output storage aliases the context or the context can otherwise change between accesses. This contract therefore describes the access order rather than assuming the outputs always match.

The apparent intent is to report a lower and upper bound, with −1 requesting a derived upper bound. That interpretation is inferred, not established. No semantic names, units, or validity constraints for the resulting values are available.

## Interface

### Inputs

The function accepts three arguments:

| Argument | Role | Required accessible storage |
|---|---|---|
| Context address | Identifies storage containing the selector and dependency argument | A readable integer field at byte offset 0xF4; on the dependency-assisted path, a readable four-byte field at byte offset 0xBC |
| First output address | Destination for the first result | Storage writable as one integer |
| Second output address | Destination for the second result | Storage writable as one integer |

Offsets are byte offsets from the context address. The four-byte field at 0xBC occupies bytes 0xBC through 0xBF. Under the 32-bit integer interpretation used by the supplied representation, the selector occupies bytes 0xF4 through 0xF7.

The dependency argument is established as a four-byte value. The selector, output values, and dependency result are represented as integer values in the supplied evidence. A 32-bit interpretation is consistent with that representation, but no independent type declaration or target ABI was supplied. Exact pointer width, alignment requirements, byte order, and address-arithmetic behavior remain platform prerequisites rather than independently established facts.

No additional context fields are directly accessed by this function.

### Outputs and return

The function has no value-bearing return result. On normal completion, it has performed:

- One integer write to the first output destination.
- One integer write to the second output destination.

Those writes occur in that order, with intervening work determined by the selected branch.

The function does not expose a separate success flag or error code. The numerical outputs do not independently indicate whether a dependency result represents success or failure.

## Behavior

### Branch selection

The first relevant action is an integer read from context offset 0xF4. The function compares that value with −1.

This initial read selects the branch for the entire invocation. Later writes or changes to the selector do not cause the branch condition to be evaluated again.

### Direct path: initial selector is not −1

The observable source-level sequence is:

1. Read the selector again from context offset 0xF4.
2. Write that value to the first output destination.
3. Read the selector again from context offset 0xF4.
4. Write that value to the second output destination.
5. Return normally.

Including the branch-selection read, this path contains three selector reads. It does not call F-5fca8e42aa3d and does not directly read the field at offset 0xBC.

For a stable context with ordinary, non-overlapping storage, both outputs equal the selector. Negative selector values other than −1 take this path without visible rejection. Zero and positive values also take this path without visible range checks.

The initial branch-selection value is not retained as the mandatory value for either output. Consequently, the strongest unconditional statement is that each output receives the value from its designated later selector read—not that both receive the initial value.

These are source-level access requirements. The evidence does not establish hardware bus transactions, atomicity, or behavior under a language-level data race.

### Dependency-assisted path: initial selector is −1

The observable sequence is:

1. Write integer zero to the first output destination.
2. Read the four-byte value at context offset 0xBC.
3. Pass that value as the single argument to F-5fca8e42aa3d.
4. After the dependency returns, subtract one from its integer result.
5. Write the computed value to the second output destination.
6. Return normally.

The zero write precedes both the dependency-argument read and the dependency call. This ordering matters if the first output overlaps the context field at offset 0xBC: the dependency receives the field value after that write, not necessarily its value at function entry.

This path does not reread the selector after the branch decision. If the first output overlaps the selector and replaces −1 with zero, execution still remains on the dependency-assisted path.

### Arithmetic

The dependency result is decremented by exactly one. There is no visible clamping, saturation, special handling for zero, or validation of negative results.

For representable, non-overflowing integer results:

- A dependency result of 1 produces a second output of 0.
- A dependency result of 0 produces a second output of −1.
- A dependency result of −1 produces a second output of −2.

If the result is the minimum signed 32-bit integer, decrementing it is not representable as a signed 32-bit integer. The supplied representation alone does not establish whether the executable wraps, traps, or follows another applicable rule. Wraparound to the maximum signed value must not be treated as established behavior.

## Side effects

### Output and context writes

The only direct writes shown are to the two caller-supplied output destinations. There is no separate direct context update.

Nevertheless, an output destination may overlap the context. In that case, an output write also changes the overlapping context bytes. Such changes can affect later reads:

- A first-output write overlapping offset 0xBC can change the argument passed to F-5fca8e42aa3d.
- A first-output write overlapping the selector precedes the direct path’s final selector read.
- A second-output write overlapping either context field changes that storage after the function has finished its own relevant reads.

Partial overlap is not normalized or specially handled. Its meaning depends on the target’s valid-access rules, integer representation, and byte order.

### Output aliasing

If both output addresses identify the same valid integer storage, the second write supersedes the first, assuming no intervening dependency action changes that storage or prevents completion.

On the dependency-assisted path, shared output storage is first set to zero and later set to the decremented dependency result. The initial zero is an observable intermediate state, not necessarily the final value.

On a stable direct path, shared output storage ends with the value obtained by the final selector read.

### Dependency effects and ownership

No allocation, deallocation, ownership transfer, or explicit resource acquisition is shown in F-80474946e6fd itself.

The four-byte dependency argument is passed by value. Its meaning is unknown: it may represent an integer, handle, address-like value, or another encoded quantity. Passing it does not establish any ownership rule.

F-5fca8e42aa3d may have side effects not described by the supplied evidence. In particular, it must not be assumed to preserve globals, leave output storage unchanged, or preserve the lifetime of any reachable storage. On the dependency-assisted path, this function does not rewrite the first output after the call. Therefore, “the first output is zero on return” requires the additional condition that the dependency does not modify it and that the second output write does not overlap it.

### Failure behavior

There is no visible recovery or rollback.

If execution fails after the first output write but before the second, the first write may already have occurred while the second has not. This includes failure during the dependency-argument read, the dependency call, arithmetic, or the final write. Exact fault, exception, and non-return behavior is not established.
