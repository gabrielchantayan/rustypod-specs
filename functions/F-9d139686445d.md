# F-9d139686445d

## Purpose

F-9d139686445d performs ordered dependency invocations and memory publications, then selects either a restricted return-capable path or a shared terminal path. Selection depends on a signed selector derived from the fourth explicit input and an unsigned threshold comparison captured after the first invocation.

Effects are incremental, not transactional. Earlier assignments, memory writes, and dependency effects may remain observable when a later access or invocation prevents further progress. No rollback or application-level success result is represented.

This contract distinguishes explicit static relationships from conditional arithmetic deductions and unresolved behavior. No runtime tests have been performed.

The selector retains a 32-bit pattern. Under arithmetic signed right shift, its signed interpretation ranges from −128 to 127. It is therefore not equivalent to extracting an unsigned top byte.

### Widths and arithmetic model

The representation explicitly distinguishes byte, 16-bit, 32-bit, pointer-typed, and 64-bit operations. Two dependency results are 64 bits and are separated into high and low 32-bit halves.

Concrete numerical examples use the following **conditional model**:

- Retained 32-bit integer patterns and address calculations wrap modulo \(2^{32}\).
- Signed right shifts are arithmetic; unsigned right shifts are logical.
- Pointer representations occupy 32 bits.
- Unsigned 16-bit reads are zero-extended.
- Left shifts and multiplication retain the low 32 bits.

Offsets are in bytes. This model does not resolve actual target rules for signed overflow, negative left shifts, pointer conversion, alignment, or wrapping.

In particular, assuming 32-bit pointers gives the common pointer-typed store a four-byte footprint. It does **not** establish the widths of the three undeclared global destinations. Byte order remains unresolved.

## Behavior

### Common sequence

The following order is represented on every path:

1. Derive the selector from the fourth input.
2. Read a 32-bit word at the ambient read base displaced by the selector.
3. Invoke F-U01 with `0x26`, explicit inputs two and three, and the captured word.
4. Capture whether the unsigned threshold is strictly greater than `0xFFFFFFC7`.
5. Store one byte at the threshold displaced by `0x3C`. Its value is obtained by converting the referenced data object to a character-sized value.
6. Read and capture a 32-bit saved address at selector-relative offset `0x34`.
7. Invoke F-f96e6bdb2333, obtaining a 64-bit result.
8. Convert that result’s high 32-bit half to a character pointer and store the pointer at selector-relative offset `0x28`.

The width of the referenced data object’s source read is not supplied. Only the destination byte width is explicit.

The ordering allows aliasing to matter. For example, the byte store may affect the subsequent saved-address read if their storage overlaps. Conversely, later mutation of the saved address’s original storage does not replace the already captured address.

The captured comparison determines the branch even if subsequent operations change the threshold’s storage. These captured-value relationships describe represented dataflow, not a general promise that dependencies preserve globals or registers.

### Path selection

The restricted path requires both:

- The captured unsigned comparison is true.
- The selector interpreted as signed 32 bits is strictly greater than `0x59`.

Under the conditional arithmetic model, eligibility requires a threshold in `0xFFFFFFC8`–`0xFFFFFFFF` and a fourth-input top byte in `0x5A`–`0x7F`.

All other combinations take the shared path. Negative selectors fail the signed eligibility comparison.

### Restricted path

F-U02 executes before either restricted-path global assignment.

The following publication order is explicit:

1. Assign global A from the saved address reduced by `0x5A`.
2. Read one byte through the pointer derived from F-f96e6bdb2333’s high half.
3. Assign global B from a pointer-derived expression.

The source for global A is a represented 32-bit signed arithmetic expression. The source for global B is formed by converting the captured pointer to signed 32 bits, shifting right by 16, and shifting left by 20.

Neither assignment establishes its destination width or the final stored representation. An undeclared destination could require a conversion that truncates, extends, or otherwise changes the source value. Those conversions are **documented_only**.

A failure during the intervening byte read can leave global A’s assignment completed while preventing global B’s assignment. The number of bytes changed by either assignment remains unresolved.

F-U03 then receives the pointer-derived expression and the captured pointer. Its expression is supplied directly from the captured pointer; it is not established as a readback of global B. An unknown assignment conversion at global B therefore does not redefine F-U03’s represented argument.

F-U04 through F-U13 follow in order. F-U06 uses the byte captured before global B’s assignment, not a fresh pointer read.

Character signedness affects F-U06’s second argument:

- With unsigned character interpretation, promotion followed by a right shift of nine produces zero.
- With signed 8-bit character interpretation and arithmetic right shift, bytes `0x80`–`0xFF` produce −1; lower bytes produce zero.

F-U13 is an unresolved indirect transfer. A return continuation is represented, but the transfer’s actual behavior is unknown. Ordinary completion requires control to reach that continuation.

### Shared path: anchor and address capture

The captured threshold decision selects an anchor and F-U14’s argument:

| Captured comparison | Anchor | F-U14 argument |
|---|---:|---|
| False | `0x08573680` | Low 32-bit half of the common 64-bit result, shifted left by 20 |
| True | `0x2B` | Selector logically shifted right by eight, then shifted left by 20 |

The true case reaches this path only when the signed selector is at most `0x59`.

Before F-U14, the selector is written as a 32-bit word at selector-relative offset `0x10`. A subsequent 32-bit read captures an indirect address from the saved address displaced by `0x30`.

The selector write precedes that read. Overlap can therefore change the indirect address obtained. The base of that read remains the previously captured saved address.

F-U14 and F-U15 execute next, in that order. The routine then:

1. Writes a zero 16-bit value at anchor-relative offset `0x9A`.
2. Reads an unsigned 16-bit value at indirect-address-relative offset `0x43`, capturing its zero-extended value.
3. Assigns the global associated with address `0x20` from a register-carried 16-bit source.
4. Invokes F-U16.

The third operation is an assignment to an undeclared global, **not an established halfword store**. Its source is 16 bits, but its destination width and any assignment conversion are unknown. The representation also does not establish that source as F-U15’s ordinary return value.

F-U17 and F-U18 follow F-U16. After F-U18 returns, the routine writes a zero 16-bit value at the **numeric value** of the captured unsigned halfword displaced by `0x20`.

This destination is not relative to the halfword’s source address. A captured value of `0xFFFF` gives destination `0x1001F` under the conditional model. Later mutation of the source storage does not redirect this write.

### Shared path: generated base and termination

F-U18 supplies the second 64-bit result. Its high half is interpreted as signed 32 bits and multiplied by `0x10000000` to produce a generated base.

Under the conditional wrapping model, only that high half’s lowest four bits contribute to the generated base. Actual signed-overflow behavior remains unresolved.

After the value-derived zero-halfword write, F-U19 executes. The routine then writes a 32-bit word at generated-base-relative offset `0x54`. The value is the selected anchor increased by `0x6A`:

- `0x085736EA` for a false captured threshold comparison.
- `0x95` for a true captured threshold comparison.

F-U20, F-U21, and F-U22 follow in order.

F-U23 is the terminal primitive. It receives immediate `0x5F` and location operand `0x085732C6`; its represented result supplies F-U24’s invocation target. The terminal sequence is annotated as non-returning.

The location operand does not itself establish a memory read or write. No particular architectural exception, operating-system signal, process exit, or caller-visible error code is established.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes the stated arithmetic model and completion of earlier required operations.

1. **Threshold equality selects the shared path.** A threshold of `0xFFFFFFC7` makes the comparison false for every selector. The byte-store destination wraps to `0x03`, and the anchor is `0x08573680`.

2. **Eligibility boundaries are strict.** Threshold `0xFFFFFFC8` and fourth input `0x5A000000` select the restricted path. Changing only the fourth input to `0x59000000` selects the shared path with anchor `0x2B`.

3. **Negative selectors remain ineligible.** Threshold `0xFFFFFFFF` and fourth input `0x80000000` produce selector bits `0xFFFFFF80`, interpreted as −128. The shared selector-word destination is `0xFFFFFF90`, and F-U14 receives `0xFFF00000`.

4. **Zero does not eliminate an invocation.** With a true comparison and selector 89, F-U14 receives zero. Its invocation and possible effects remain required.

5. **Captured addresses are retained.** If the saved address is `0x1000`, later modification of its original storage does not redirect the indirect-address read away from `0x1030`.

6. **Aliasing follows operation order.** If the selector-word destination overlaps that indirect-address source, the address read occurs after the selector write and may observe its effects.

7. **Unsigned capture controls the later destination.** A captured halfword of `0xFFFF` produces a zero-halfword write at `0x1001F`, not `0x1F`.

8. **Generated-base truncation matters.** If F-U18’s high half is `0x1234567A`, the conditional generated base is `0xA0000000`, and the later word destination is `0xA0000054`.

9. **Restricted publication can be partial.** Failure during the pointer-derived byte read occurs after global A’s assignment but before global B’s assignment and F-U03. This establishes assignment order, not either global’s write width.

10. **Global assignment is not source-width storage.** A 16-bit source pattern of `0xABCD` establishes the source supplied to the assignment associated with `0x20`. It does not establish a two-byte store, the resulting wider value, or preservation of adjacent bytes.

11. **Character interpretation remains conditional.** Captured byte `0x80` gives F-U06 a byte-derived argument of zero under unsigned-character interpretation and −1 under signed-character arithmetic shifting.

12. **Completion differs by path.** Restricted-path return requires F-U13 to reach the represented continuation. The shared terminal sequence establishes neither ordinary return nor a particular error outcome.
