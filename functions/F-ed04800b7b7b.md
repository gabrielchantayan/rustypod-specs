# F-ed04800b7b7b

## Purpose

F-ed04800b7b7b invokes one dependency twice, in a fixed order, and then compares a 20-byte region beginning 60 bytes after each of two supplied addresses.

For valid memory that remains stable during the comparison, the result is an unsigned-byte lexicographic comparison:

- Zero means all 20 corresponding bytes are equal.
- A negative result means the first differing byte in the first region is smaller.
- A positive result means the first differing byte in the first region is larger.
- A nonzero result is the numerical difference between the two differing unsigned byte values, not merely a normalized sign.

The dependency calls precede all comparison reads. Consequently, this result describes post-call contents, not necessarily contents present at function entry.

The fixed offset and length suggest a field within a larger object. That interpretation is **inferred intent**; neither an object type nor the meaning of the field is established.

The aligned comparison path rereads its last examined word pair. For changing or read-sensitive memory, the result need not describe any single snapshot. In particular, after five initially equal word pairs, the function returns zero even if the repeated comparison observes inequality.

## Behavior

### Path selection

The function checks whether both comparison-region addresses are divisible by four.

If either is misaligned, the function skips word scanning and starts byte comparison at region position zero with 20 bytes remaining.

If both are aligned, it enters the word scan. Since 60 is divisible by four, alignment of each region matches alignment of its supplied address, subject to valid address formation.

### Aligned word scan

The scan examines corresponding four-byte words at region positions 0, 4, 8, 12, and 16, stopping at the first unequal pair or after all five pairs compare equal.

For each examined pair, the current positions advance by four bytes before the equality outcome is acted upon:

- An equal pair reduces the remaining count by four.
- An unequal pair stops the scan without reducing that count.

Thus, if an initial mismatch follows \(k\) equal words, where \(k\) is from zero through four, the remaining count is \(20 - 4k\), while the current positions have advanced past the mismatching word.

Word comparison is used only for equality. The numerical ordering of unequal four-byte words does not determine the result. With stable memory, target byte order therefore does not change the unsigned-byte lexicographic result.

### Repeated word comparison and the zero-count gate

After the scan, the function performs another four-byte equality comparison at the last word positions examined. This happens both after an initial mismatch and after five initially equal word pairs.

If this repeated comparison observes inequality, both current positions are reset to the beginning of that last examined word pair. If it observes equality, the already advanced positions are retained. The repeated comparison does not alter the remaining count.

The function then checks the remaining count:

- If the count is zero, it returns zero immediately.
- Only if the count is nonzero does it enter byte comparison.

This distinction is essential. When all five initial word comparisons were equal, the count is already zero. A subsequent unequal repeated comparison rewinds the positions but does **not** cause byte reads or change the zero result.

Under stable memory, the ordinary aligned cases are:

- Five equal word pairs: reread the final pair, then return zero.
- An unequal word pair: reread that pair, reset to its beginning, then compare bytes from there because the remaining count is positive.

### Byte comparison

Byte comparison reads successive positions in ascending address order. At each position, it reads the first region’s byte before the second region’s byte and interprets both as unsigned.

The first unequal pair terminates comparison. Its numerical difference supplies the result.

Matching bytes are processed in pairs. After two equal bytes, the remaining count decreases by two. If that exhausts the count, the function returns zero; otherwise, it continues with the next pair. A mismatch at either position ends comparison immediately.

For stable memory following a word mismatch, byte comparison begins at the start of the mismatching word. Earlier equal words are not reread through the byte path. The remaining count includes the entire mismatching word and all later bytes through region position 19.

There is no terminator handling and no special treatment for zero-valued bytes.
