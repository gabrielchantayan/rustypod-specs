# F-019e779587ab

## Purpose

F-019e779587ab updates a four-bit field in an externally located 32-bit word according to a 32-bit selector. It reports success for six selector values and failure for all others.

The central behavioral requirement is that **the field is cleared before the selector is accepted or rejected**. A failure return therefore does not mean that state was left unchanged. Under stable, ordinary-memory conditions, a rejected selector leaves the field cleared.

The established behavior is a bit-field update. Interpreting the field as a device mode, peripheral setting, or other domain-specific configuration is inferred intent, not established evidence.

## Interface

### Inputs

The function accepts two 32-bit arguments:

| Argument | Established role |
|---|---|
| First argument | Unused by the visible body. Its value does not select a target, affect the update, or affect the return value. |
| Second argument | Selector tested against the exact values listed below. |

No dereference of either argument is visible. In particular, the first argument is not used as a pointer by this function.

The selector is considered as a complete 32-bit value. There is no visible narrowing to a byte or masking to a smaller selector range. A value whose low byte matches an accepted selector is not accepted merely for that reason.

### External state and layout

The target address is obtained from a global storage location. The relevant layout is:

| Location | Meaning established by the visible body |
|---|---|
| Global storage location | Supplies a base address. |
| Base address plus byte offset 12 | Holds the 32-bit word to be modified. |
| Bits 8–11 of that word | Field cleared and then, for accepted selectors, assigned an encoded value. |
| Bits 0–7 and 12–31 | Outside the field targeted by this operation. |

Bit numbering starts at zero for the least significant bit. The field mask is `0x00000F00`; its complement within 32 bits is `0xFFFFF0FF`.

The body uses 32-bit accesses to the target word. Its byte order, alignment requirements, address-space properties, and physical interpretation are not established by the supplied evidence.

### Output

The result is a 32-bit value:

| Condition | Result |
|---|---|
| Selector is accepted | `0x00000000` |
| Selector is rejected | `0xFFFFFFFF` |

The failure result is an all-ones 32-bit pattern. A caller interpreting that pattern as a signed two’s-complement 32-bit integer would see −1; the visible interface does not establish that caller-side interpretation.

### Preconditions

For ordinary completion, the global location must be readable, and the target word must support the reads and writes described below. A stable base address and absence of interfering writers are additional preconditions for the simple final-state guarantees in this contract.

There is no visible check for a null base, an invalid address, insufficient storage, access permissions, or alignment. Address addition at offset 12 is not visibly guarded against overflow. The behavior of invalid or unsupported accesses is outside the established return-value contract.

## Behavior

### Field encoding

The selector-to-field mapping is exact:

| Selector | Accepted? | Field value in bits 8–11 | Value combined with the word after clearing |
|---:|:---:|---:|---:|
| 0 | Yes | 2 | `0x00000200` |
| 1 | Yes | 3 | `0x00000300` |
| 2 | No | No replacement value | None |
| 3 | Yes | 4 | `0x00000400` |
| 4 | Yes | 5 | `0x00000500` |
| 5 | Yes | 6 | `0x00000600` |
| 6 | No | No replacement value | None |
| 7 | Yes | 7 | `0x00000700` |
| Any other 32-bit value | No | No replacement value | None |

The mapping is not a general arithmetic conversion of the selector. Selectors 2 and 6 are explicitly rejected despite lying between accepted selector values.

### Observable ordering

The visible body establishes the following sequence at the level of its represented memory operations:

1. It obtains and retains a base address from the global storage location.
2. Before selector-dependent success or failure is determined, it clears bits 8–11 of a 32-bit word addressed through that global location. This clearing operation reads the word, retains all bits outside `0x00000F00`, and writes the resulting 32-bit value.
3. For an accepted selector, it reads the word at offset 12 from the retained base address, combines that read value with the selector’s replacement pattern, and writes the result back to that same address.
4. It returns zero after the accepted-path write.
5. For a rejected selector, it returns `0xFFFFFFFF` after the initial clearing operation, without the accepted-path read or replacement write.

Thus, the represented ordinary path contains:

- One target-word read and one target-word write for a rejected selector.
- Two target-word reads and two target-word writes for an accepted selector.

These counts describe the accesses represented in the supplied body. They do not establish bus transaction counts, compiler-level volatility, memory barriers, or atomicity.

### Stable-state result

If the global base remains stable, target reads return the current stored value, writes behave as ordinary memory writes, and no other actor modifies the word during the call:

- Every selector clears the previous field value.
- An accepted selector then installs its mapped field value and returns zero.
- A rejected selector leaves the field at zero and returns `0xFFFFFFFF`.
- All bits outside the field retain their entry values.

For an accepted selector, there is an intermediate stored state in which the field is zero. The update is not represented as a single replacement write.

### Significance of the second read

The accepted path reads the target word again after the clearing write. It does not simply reuse the value computed for that first write.

Consequently, preserving all non-field entry bits is conditional on the absence of intervening changes and unusual read/write semantics. If another actor modifies the word before the second read, the final write is based on what that second read supplies.

The final operation combines the read value with the replacement pattern using bitwise OR. It does not independently clear bits 8–11 a second time. If those bits become set again between the initial clearing write and the accepted-path read, the final field can contain the OR of those intervening bits and the mapped replacement value.

### Base-address stability

The initial clearing expression uses the global base source directly, while the later accepted-path access uses the base address retained at entry.

With an unchanged global base, these accesses refer to the same word. If the global location can change during execution, that equivalence is not guaranteed by the visible body. The supplied evidence does not establish synchronization, the exact evaluation order of global references inside the clearing expression, or a coherent snapshot across those references.

No contract should therefore promise that all accesses target one location when the global base changes during the call.

## Side effects

The function writes externally addressed state even when the selector is invalid.

Under stable, ordinary-memory conditions:

- Rejected selectors cause one full-width 32-bit write with the field cleared.
- Accepted selectors cause that clearing write followed by a second full-width 32-bit write containing the selected encoding.
- The first argument has no visible side effects.
- The global storage location is read but is not visibly assigned a new value.
- No other field or object is explicitly accessed by the visible body.

The full-width writes matter even when the computed stored value equals the current value. For example, rejecting a selector when the field is already zero still reaches the clearing write. Whether writing the same value has external consequences depends on the target memory.

No allocation, release, ownership transfer, callback, logging, or explicit synchronization is visible. The function does not visibly assume ownership of the target storage or release it. The caller and surrounding system remain responsible for its lifetime and accessibility.

If the target is memory-mapped hardware, read side effects, write-one-to-clear behavior, asynchronous changes, or other register-specific semantics could change the practical effect of these accesses. None of those properties is established here.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not runtime test results. Unless stated otherwise, each example assumes a stable base, ordinary readable and writable memory, no concurrent modification, and successful accesses.

### Accepted selectors replace the complete field

Given an initial word of `0xA5A5FFFF`, the outcomes must be:

| Selector | Final word | Return value |
|---:|---:|---:|
| 0 | `0xA5A5F2FF` | `0x00000000` |
| 1 | `0xA5A5F3FF` | `0x00000000` |
| 3 | `0xA5A5F4FF` | `0x00000000` |
| 4 | `0xA5A5F5FF` | `0x00000000` |
| 5 | `0xA5A5F6FF` | `0x00000000` |
| 7 | `0xA5A5F7FF` | `0x00000000` |

Each accepted call first writes `0xA5A5F0FF`, then writes its final value. This distinguishes the operation from directly merging the replacement into the original field.

### Rejection changes state

Given an initial word of `0xA5A5FFFF`, each selector in the following set must produce final word `0xA5A5F0FF` and return `0xFFFFFFFF`:

- 2
- 6
- 8
- `0xFFFFFFFF`

There is no rollback restoring the original field.

### Selector matching is full-width

Given an initial word of `0x00000F00` and selector `0x00000100`, the result must be failure, with final word `0x00000000`.

The selector is not treated as selector 0 merely because its low byte is zero.

### Bits outside the field survive ordinary execution

Given an initial word of `0x80000001` and selector 3, the final word must be `0x80000401`, with a zero return value.

This example checks preservation of both a high bit and a low bit outside the target field.

### The first argument is irrelevant to the visible operation

For identical selector and external state, varying the first 32-bit argument must not change the represented target accesses, final word, or return value.

This criterion does not imply that an enclosing calling convention has no requirements; it describes the visible body.

### An intervening change can affect the final encoding

Suppose selector 0 is accepted, the initial clearing write leaves `0x00000000`, and an external actor changes the word to `0x00000801` before the accepted-path read. If that read returns `0x00000801` and no further interference occurs, the final write is `0x00000A01`.

The final field is then `0xA`, not the nominal encoding 2. This follows from the second read and OR operation, rather than from a guaranteed isolated field assignment.
