# F-6ca9d664149b

## Purpose

The final invocation is gated by two values: a pointer-sized field at byte offset 12 in the supplied object, and a 32-bit word at the address held in that field. Both must be nonzero.

This is an observable sequencing contract, not a claim about the object’s domain or the dependencies’ purposes. The supplied evidence does not establish that the routine waits for completion, drains a queue, destroys an object, releases a resource, or performs any other particular lifecycle operation.

### 2. Check-and-action loop

Its result is treated as a 32-bit integer:

- If the result equals zero, F-777d470d5b21 is invoked with the same original input value.
- After that invocation returns, F-0c8e9589c9ed is invoked again.
- If the check result is nonzero, the loop ends immediately, without an action call for that result.

The distinction is exactly **zero versus nonzero**. No positivity test is present. A negative 32-bit result ends the loop just as a positive result does.

Consequently:

- The check dependency is called at least once whenever the initial dependency returns and execution reaches the loop.
- The action dependency may be called zero times.
- Every action invocation is preceded by a check result of zero.
- Every returning action invocation is followed by another check before the final field inspection.

There is no visible iteration bound, delay, backoff, cancellation check, or timeout. Progress depends on the dependencies and relevant state. An endless sequence of zero results produces an endless loop if the calls continue returning normally.

### 3. Post-loop field inspection

Only after a nonzero check result does the routine directly read the pointer field at input offset 12.

This is a fresh read after all preceding dependency calls. It is not a saved value from before the initial call or from an earlier loop iteration. Any changes those dependencies make to the field can therefore affect the final decision.

The loaded pointer is then used as follows:

- If it is zero, no target-word read occurs and the indirect dependency is not invoked.
- If it is nonzero, the routine reads one 32-bit word from the address it identifies.
- If the word is zero, the indirect dependency is not invoked.
- If the word is nonzero, the indirect dependency is invoked.

The target word is tested only for zero. Its sign, magnitude, individual bits, and possible interpretation as another address do not affect this routine’s visible branch decision.

The observed sequence contains one post-loop pointer-field read and, conditionally, one target-word read. It does not reread the pointer field to confirm that it is unchanged.

The word read through the object’s pointer is a **gate**, not the demonstrated source of the call target. The supplied evidence does not show the routine calling that word as a function pointer or passing it as an explicit argument.
