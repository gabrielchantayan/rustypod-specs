# F-f3e591052de3

## Purpose

F-f3e591052de3 extracts selected fields from a primary object and an associated secondary record into fourteen caller-provided output locations. It copies two 32-bit fields, supplies fixed values, widens several small fields, normalizes one flag, and conditionally transforms four additional 32-bit fields.

The conditional group is enabled only when a secondary-record flag is nonzero and at least one of four source words is nonzero. Otherwise, the group’s flag and four values are cleared.

The routine also returns a 64-bit concatenation of the first two argument values. That return is not an observed success or failure indicator.

These behaviors are established by the supplied static representation. The application-level meanings of the fields—such as whether they describe dimensions, channels, coordinates, or bounds—are not established.

## Behavior

### Initial extraction

The initial operations occur in this order:

1. Read the 32-bit primary field at `0x17C` and write it through argument 2.
2. Read the 32-bit primary field at `0x180` and write it through argument 3.
3. Obtain the secondary address from primary offset `0x194`, read its unsigned byte at `0x58`, widen it, add one, and write the 32-bit result through argument 6.
4. Write the byte value 8 through argument 7.
5. Write 32-bit zero through argument 5.
6. Write 32-bit zero through argument 4.
7. Obtain the secondary address again, read the unsigned 16-bit field at `0x7E`, and write its zero-extended 32-bit value through argument 9.
8. Obtain the secondary address again, read the unsigned 16-bit field at `0x80`, and write its zero-extended 32-bit value through argument 10.
9. Obtain the secondary address again and inspect the byte at `0x7C`. Write byte zero through argument 8 if the source is zero; otherwise write byte one.

With stable, nonoverlapping storage:

- Argument 6 receives a value from 1 through 256, inclusive.
- Argument 7 receives exactly 8.
- Arguments 4 and 5 receive zero.
- Arguments 9 and 10 each receive a value from 0 through 65,535.
- Argument 8 receives exactly zero or one; nonzero source encodings are not preserved.

### Conditional-group eligibility

After writing argument 8’s destination, the routine obtains the secondary address again. This particular address is retained for the gate and eligibility checks.

The byte at secondary offset `0x67` is inspected first:

- If zero, the conditional group is inactive. None of the four source words is needed for eligibility.
- If nonzero, the four source words are checked for an all-zero condition.

The all-zero check uses short-circuit reads in this order:

1. Offset `0x68`.
2. Offset `0x6C`, only if the first word was zero.
3. Offset `0x70`, only if the first two words were zero.
4. Offset `0x74`, only if the first three words were zero.

The group is active when the gate is nonzero and at least one inspected source word is nonzero. The test is against the original source words, not their transformed results.

### Active conditional group

For an active group, the following writes occur:

1. Write byte one through argument 11.
2. Reload the secondary address from primary offset `0x194`, read the 32-bit word at `0x68`, shift it left by one, and write the 32-bit result through argument 12.
3. Reload the secondary address, read the word at `0x6C`, shift it left by one, and write the result through argument 13.
4. Reload the secondary address, read the word at `0x70`, shift it left by one, and write the result through argument 14.
5. Reload the secondary address, read the word at `0x74`, shift it left by one, and write the result through argument 15.
6. Read argument 13’s destination. If it is nonzero, read its current value for the addition and write that value plus one back to the same destination.
7. Apply the same conditional read, addition, and write to argument 15’s destination.
8. Return the 64-bit address concatenation.

The source words used for transformation are freshly read. They are not the values retained from eligibility checking.

For stable, nonoverlapping storage and nonnegative source values no greater than 1,073,741,823:

- The first and third transformed outputs are twice their corresponding source values.
- The second and fourth outputs are zero when their corresponding source is zero.
- Otherwise, the second and fourth outputs are twice their corresponding source values plus one.

This range avoids negative signed shifts and signed overflow in the displayed operations. Behavior outside that range is discussed under **Uncertainties**.

### Inactive conditional group

When the gate is zero, or when the gate is nonzero and all four source words are zero, the routine writes:

1. Byte zero through argument 11.
2. 32-bit zero through argument 15.
3. 32-bit zero through argument 14.
4. 32-bit zero through argument 13.
5. 32-bit zero through argument 12.

It then returns the same address concatenation as the active path.

The reverse order of the four zero writes is observable when output destinations overlap.

## Side effects

### Memory mutation

All explicit writes are through the supplied output addresses. No separate write to the primary or secondary object appears.

That does not guarantee the source objects remain unchanged: an output may point into either object. Such a write can alter a field or nested address before the routine reads it.

There is no staging buffer, rollback, or atomic commit. Initial outputs are written before conditional eligibility is evaluated. If a later access fails, earlier writes may already have occurred; no recovery behavior is shown.

### Aliasing and repeated reads

The routine does not establish a snapshot of the secondary record:

- The secondary address is reloaded for each initial secondary-field extraction.
- One address is retained for the gate and eligibility check.
- The secondary address is then reloaded separately for each active-path transformation.
- Arguments 13 and 15 are read back after all four initial transformed outputs have been written.

Consequently, overlapping outputs can affect later source reads and post-adjustments. For example, if arguments 12 and 13 share a 32-bit destination, the second transformed write replaces the first before the conditional increment. Both arguments then designate the same final value.

If an output overlaps primary offset `0x194`, a write may change which secondary record is used by subsequent reloads.

The ordering described here is the ordering shown in the supplied static representation. Hardware-level atomicity, memory barriers, and cross-thread visibility are not established.
