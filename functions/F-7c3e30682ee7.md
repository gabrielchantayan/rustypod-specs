# F-7c3e30682ee7

## Purpose

F-7c3e30682ee7 performs a conditional two-location update using a caller-supplied object address and a 32-bit payload. It calls one dependency before the update and another afterward. It then inspects an object-held pointer and, conditionally, that pointer’s first 32-bit value. If both are nonzero, it obtains an indirect invocation target from a separate global location and transfers control through that target.

The object-held pointer, its pointee value, and the globally supplied invocation target have distinct roles. The first two gate the invocation; neither supplies its destination.

A linked-structure append followed by notification is plausible **inferred intent**, not an established semantic contract. The established behavior consists of the calls, accesses, conditions, and ordering described below. No direct allocation, release, payload dereference, or initialization of the payload’s own link is shown.

## Behavior

### 1. Initial dependency

The first visible action calls F-338d16f9ce72 with the address of object offset `0x14`.

All subsequent behavior requires this call to return normally. The branch selector is read afterward, so the update uses post-call memory rather than an entry-time snapshot.

No preservation contract is supplied. This dependency may affect the object, other memory, or the global target slot. Its placement does not establish locking, retention, or any other particular semantic effect.

### 2. Branch-dependent first store

After the initial dependency returns, the function reads the 32-bit value at object offset `0x28` and compares it with zero.

**When that value is zero:**

- The payload is stored at object offset `0x28` as a 32-bit value.
- No address load from offset `0x2c` is shown on this branch.
- No store through a separately loaded address is performed on this branch.

**When that value is nonzero:**

- A 32-bit address is loaded from object offset `0x2c`.
- The payload is stored as a 32-bit value at that address plus byte offset `0x18`.
- No direct store to object offset `0x28` is shown on this branch.

The branch selector is used only for its zero/nonzero condition. It is not the destination base for the external store. That base comes from offset `0x2c`.

There is no visible check for a duplicate payload, an already-linked element, consistency between the two object fields, or validity of the loaded destination address.

### 3. Common second store

After the branch-specific store completes, the function stores the payload as a 32-bit value at object offset `0x2c`.

Thus, with non-overlapping storage and absent intervening external mutation:

- The zero branch writes the payload to object offset `0x28`, then to offset `0x2c`.
- The nonzero branch writes the payload to the loaded address plus `0x18`, then to object offset `0x2c`.

These are two ordered stores, not an atomic combined update.

Aliasing is not excluded. If the branch-derived destination overlaps an object field, the global target slot, or another relevant location, the first write can affect later observations. Claims that a particular field remains unchanged are therefore conditional on non-aliasing and on callee behavior.

### 4. Second dependency

After both direct stores, the function calls F-b8a325ddd21b with the address of object offset `0x1c`.

The payload is not shown as a separate argument. The dependency’s meaning and effects remain unknown.

This dependency precedes all final pointer inspection and the conditional global target read. It cannot be assumed to preserve:

- The fields just written.
- The pointer at object offset `0x14`.
- Memory reached through that pointer.
- The separate global target slot.

Consequently, the two direct stores establish intermediate effects, not unconditional final-state guarantees. If this dependency does not return normally, the later reads and invocation are not established as occurring.

### 5. Final pointer and pointee checks

After the second dependency returns, the function loads the 32-bit pointer at object offset `0x14`.

If the pointer is zero, the function returns without reading a pointee or the global invocation target.

If the pointer is nonzero, the function reads one 32-bit value at that address:

- A zero value leads to return without reading the global invocation target.
- A nonzero value enables the global target read and indirect invocation.

Both conditions are nonzero tests, not positivity tests. A 32-bit pointee value whose high bit is set satisfies the value condition.

The pointer and pointee are not visibly cleared or otherwise modified by these checks. The pointer is loaded once in the shown final inspection; there is no second object-field read to revalidate it before use.

### 6. Global target read and indirect invocation

Only after both final checks succeed does the function obtain the invocation target from the separate global target slot and invoke it.

The relevant order is:

1. Both dependencies return, with the update between them.
2. The final object-held pointer is loaded and found nonzero.
3. Its first 32-bit value is read and found nonzero.
4. The global target slot supplies the indirect destination.
5. Control transfers through that destination.

The global source of the destination is **established static evidence**. The destination’s identity and full calling contract are not established.

No earlier target read or cached entry-time target is shown. An entry-time snapshot is not an established equivalent because either dependency may change the global slot before the invocation path reads it.

No explicit arguments are shown at the indirect invocation. This does not establish a complete register, stack, or argument contract. No separate zero check of the fetched function pointer is shown.
