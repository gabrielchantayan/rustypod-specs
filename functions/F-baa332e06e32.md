# F-baa332e06e32

## Purpose

F-baa332e06e32 transforms two 32-bit input words into one 32-bit result. Its ordinary paths reconstruct a magnitude from selected input bits, shift that magnitude toward an integer representation, and apply a sign. Inputs outside the directly accepted range ordinarily produce a sign-dependent boundary value. A subset of exceptional input encodings instead enters a control-word-dependent indirect-transfer path.

**Inferred intent:** the two input words appear to encode an IEEE 754 binary64 value, with the first word holding the low bits and the second word holding the high bits. The ordinary behavior resembles conversion to a signed 32-bit integer with truncation toward zero and saturation on overflow.

That interpretation is not a complete established contract. In particular:

- Some represented shifts have counts of 32 or greater; their actual machine behavior is not established by the supplied material.
- Exceptional-path transfers were not reliably recovered as ordinary calls.
- The external control word and external data words have no supplied definitions.
- No runtime tests have been performed.

The bit-level behavior below is authoritative within those limitations; the floating-point interpretation is explanatory.

## Behavior

### 1. Construct the magnitude and determine the sign path

The function first obtains an exponent-and-sign field by arithmetically shifting the second word right by 20 bits, retaining the result as a 32-bit unsigned word.

It also constructs a 32-bit magnitude from:

- The second word shifted left by 11 bits, with overflow discarded.
- The first word logically shifted right by 21 bits.
- The bitwise union of those two contributions.

If the exponent-and-sign field is nonzero, the magnitude’s most significant bit is set.

This construction retains the 20 low bits of the second word and the 11 high bits of the first word. The first word’s lower 21 bits do not enter this magnitude.

The signed interpretation of the exponent-and-sign field selects the negative or nonnegative path. Under the arithmetic-shift interpretation, this is equivalent to testing the second word’s sign bit.

### 2. Negative-input direct conversion

For a negative input, the function starts with a candidate result of zero.

It extracts an 11-bit exponent by masking the exponent-and-sign field with `0x7FF`. If that exponent is zero, it clears the magnitude’s most significant bit. Thus, the previously inserted high bit is removed for negative zero and negative subnormal-like encodings.

The conversion uses:

- An adjusted exponent equal to the 11-bit exponent minus 896.
- A shift distance equal to 158 minus that adjusted exponent, equivalently 1054 minus the 11-bit exponent.

Direct conversion is considered only when the adjusted exponent is less than 159, equivalently when the exponent is at most 1054.

Within that range:

- If the shift distance is less than 256, the candidate is the 32-bit modular negation of the logically right-shifted magnitude.
- If the shift distance is 256 or greater, the candidate remains zero.
- The shift expression uses the low eight bits of the distance. For this branch’s accepted distances below 256, that masking does not reduce the distance further.

The candidate is returned only if its signed interpretation is less than 1: zero or a negative signed value.

Otherwise, processing continues to the common fallback.

This signed-result check matters at the boundary. A magnitude of exactly `0x80000000` with shift distance zero produces candidate `0x80000000`, which is accepted. Larger unsigned magnitudes at the same distance negate into positive signed values and are rejected by this direct-return check.

### 3. Nonnegative-input direct conversion

For a nonnegative input, the exponent-and-sign field is the nonnegative exponent-like value.

The shift distance is computed as the 32-bit result of 1054 minus that value. Direct return requires both:

- The shift distance is not zero.
- The signed adjusted exponent, obtained by subtracting 896, is less than 159.

For ordinary nonnegative exponent encodings, these requirements select exponents at most 1053.

Within this direct-return path:

- If the signed shift distance is less than 256, the magnitude is logically shifted right by the distance’s low eight bits.
- Otherwise, the returned result is zero.
- The resulting word is returned without an additional signed-range check.

A shift distance of zero is deliberately excluded from this path. Consequently, the exponent band corresponding to positive values from \(2^{31}\) upward proceeds to fallback rather than returning the unshifted magnitude.

### 4. Common fallback classification

If direct conversion does not return, the function forms a 32-bit classifier:

- Twice the second input word, with 32-bit wraparound.
- Plus one if the first input word is nonzero.

The comparison against `0xFFE00001` is unsigned.

If the classifier is less than `0xFFE00001`, the function returns a sign-dependent boundary:

| Sign of second word | Returned word | Signed interpretation |
|---|---:|---:|
| Nonnegative | `0x7FFFFFFF` | 2147483647 |
| Negative | `0x80000000` | −2147483648 |

The represented control flow contains a further comparison inside this range, but both outcomes return the same boundary expression. It creates no distinct result or external access in the supplied representation.

Under the binary64 interpretation, this fallback covers finite out-of-range values and both infinities.

If the classifier is at least `0xFFE00001`, processing enters the exceptional dispatch described next. Under the binary64 interpretation, this condition distinguishes NaN encodings from infinities, including NaNs whose nonzero payload occurs only in the first word.

### 5. Exceptional dispatch

The function reads the control word and extracts its low four bits as a mode. Subsequent control-bit tests are represented as additional reads of that word, not as reuse of a guaranteed snapshot.

The following argument descriptions are limited to the arguments visible in the supplied representation. They do not establish that other machine state is irrelevant.

| Mode | Additional condition | Represented arguments to F-unresolved-indirect |
|---|---|---|
| 10 | Control bit `0x40` clear | One word: zero |
| 10 | Control bit `0x40` set | One word: `0x80000000` |
| 8 | Control bit `0x40` set | Two words: zero, zero |
| 8 | Control bit `0x40` clear; later bit `0x10` clear | Two words: data word B, data word A |
| 8 | Control bit `0x40` clear; later bit `0x10` set | Two words: zero, data word C |
| 9 | Control bit `0x100000` clear | Two words: zero, data word A |
| 9 | Control bit `0x100000` set | Two words: 8, a transformed control word |
| Any other low-four-bit value | No further represented condition | No explicit arguments recovered |

For mode 9 with bit `0x100000` set, the second argument is obtained from another control-word read: shift left by 15 with 32-bit truncation, complement all 32 bits, then shift left by one with 32-bit truncation. In particular, the result’s low bit is zero.

The target is represented as the incoming return/link state with its low two bits cleared. Every exceptional branch returns the 32-bit value represented as coming back from that transfer, if the transfer returns normally.

Because the transfer recovery is explicitly uncertain, this does not establish that the machine operation is an ordinary returning function call.

- No external data reads on paths that return through direct conversion or the common boundary fallback.

Absence of explicit stores in this representation is not a guarantee that the unresolved dependency preserves memory or global state.

### Exceptional-path read order

The represented access sequence is significant:

1. Read the control word to obtain the mode.
2. Read additional control bits as required by that mode.
3. Read selected external data words or another control-word value.
4. Perform the unresolved transfer.

More specifically:

- **Mode 10:** read the control word for bit `0x40`; then transfer.
- **Mode 8, bit `0x40` set:** read that bit; then transfer without represented data-word reads.
- **Mode 8, bit `0x40` clear:** read data word B, then data word A, then read the control word for bit `0x10`. If that bit is set, read data word C and replace the prepared argument pair with zero and that value. The earlier reads of B and A still occur in the represented sequence.
- **Mode 9, bit `0x100000` clear:** read that bit, then read data word A.
- **Mode 9, bit `0x100000` set:** read that bit, then read the control word again for the transformed second argument.
- **Other modes:** no additional external reads are represented before the transfer.

If these locations can change between reads, argument selection need not correspond to any single control-word snapshot. Volatility, atomicity, synchronization, and concurrent access rules are not supplied.

### Zero and large-shift boundaries

- Both positive and negative zero return zero through the explicit shift-distance-at-least-256 handling.
- With exponent field 798, the distance is 256 and the direct path explicitly yields zero.
- With exponent field 799, the distance is 255 and a shift is represented. Its result is documented only until the underlying large-shift semantics are established.
- Values whose direct conversion requires a shift distance of 32 likewise must not be assigned a portable result solely from this representation.

### Exceptional encodings

For `0x00000001, 0x7FF00000`, the nonzero first word raises the classifier above the infinity boundary, so exceptional dispatch is selected.

Conditional checks include:

- Mode 10 with bit `0x40` set transfers the visible argument `0x80000000`.
- Mode 8 with bit `0x40` clear reads B and A before testing bit `0x10`, even if that later test causes their values not to be passed.
- Mode 9 with bit `0x100000` clear passes zero and data word A.
- If F-unresolved-indirect returns normally with a particular 32-bit word, that word is returned unchanged.

No fixed numerical result is established for an exceptional encoding without resolving the selected dependency.
