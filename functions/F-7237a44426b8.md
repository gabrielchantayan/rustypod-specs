# F-7237a44426b8

## Purpose

F-7237a44426b8 conditionally attaches a supplied node to an owner-level sequence or to a parent node’s child sequence. The operation selects an insertion position, rewrites bidirectional links and sequence endpoints, updates counts, and conditionally invokes a dependency for two owner-associated state slots.

**Established static behavior:** two dependency results gate all direct structural changes. Once both gates succeed, the function performs the attachment without validating membership, ownership consistency, duplicate insertion, or acyclicity.

**Inferred intent:** the linked structures represent ordered roots and ordered children within a hierarchy. The counters appear to track direct children, descendants, and total attached nodes. These semantic names are useful interpretations of the offsets and updates, not independently established type definitions.

The function returns no result. Gate rejection is a silent return; successful attachment is not reported separately.

## Interface

### Inputs

The function receives:

| Input | Representation | Meaning |
|---|---|---|
| Node | Address carried in a source-level integer | Record to attach. Its owner reference is obtained from offset `0x0c`. |
| Placement descriptor | Nullable address of two consecutive four-byte words | Selects the parent and insertion position. A null descriptor requests owner-level placement using the owner’s current endpoint. |

A non-null placement descriptor has this layout:

| Offset | Field | Interpretation |
|---|---|---|
| `0x00` | Parent reference | Zero selects the owner-level sequence; nonzero selects a parent’s child sequence. |
| `0x04` | Position selector | Zero requests insertion at the beginning. The 32-bit value `0xffffffff`, interpreted as `-1`, selects the current endpoint of the selected sequence. Any other nonzero value is treated as a node reference. |

The sentinel comparison applies only to the descriptor’s position word. An endpoint subsequently loaded from an owner or parent is not checked again for the sentinel.

## Behavior

### 1. Gate the operation

The first action is a call to F-3b037d560480 with no explicit arguments.

If it returns zero, the function returns immediately. In particular, this function has not yet read the supplied node’s owner field, inspected the descriptor, or directly changed any records. The dependency may itself have side effects; an immediate return is not a guarantee of globally unchanged state.

After a nonzero result, the function reads the owner reference from the node at offset `0x0c`. It then calls F-06f4ceb6a4f2 with that reference as its sole explicit argument.

If this second dependency returns zero, the function returns without directly changing the structure or reading the placement descriptor.

The owner reference captured before the second call remains the reference used by the rest of this function. The node’s owner field is not reloaded after that call. Consequently, any dependency mutation of that field does not redirect the later owner accesses.

### 2. Resolve parent and insertion position

Placement is resolved only after both gates succeed:

- **Null descriptor:** select no parent and load the position from the owner’s last-node endpoint at `0x38`.
- **Non-null descriptor:** read the parent word first, then the position word.
- **Position word equal to `-1`:**
  - With no parent, load the position from the owner’s last-node endpoint.
  - With a parent, load the position from that parent’s last-child endpoint at `0x28`.
- **Any other position word:** use it directly, including zero.

The selected parent is then stored into the supplied node at offset `0x10`, before the function writes its sequence links.

The descriptor is not consulted again. Values read from it are not checked against the node’s owner, the selected sequence, or existing membership.

### 3. Attach at the beginning when the resolved position is zero

The supplied node’s following link at `0x18` is first set to zero.

For owner-level placement:

- The owner’s first-node endpoint is copied into the supplied node’s preceding link.
- If the owner’s first endpoint is nonzero, the record currently identified by that endpoint receives the supplied node in its following link.
- The owner’s first endpoint is replaced with the supplied node.
- If the owner’s last endpoint is zero, it is also replaced with the supplied node.

For placement under a parent, the same pattern uses that parent’s first-child and last-child endpoints.

Under a stable, well-formed sequence, the field interpretation is that the new node becomes the first element: its preceding link reaches the former first element, while its following link is zero. Thus “preceding” and “following” here name the operational link directions; they do not impose a conventional forward-traversal orientation.

The endpoint used for the neighboring-node update is read again rather than guaranteed to be the value initially copied into the supplied node. This distinction matters if records overlap or storage changes during execution.

### 4. Attach relative to a nonzero position

For a nonzero resolved position:

- The supplied node’s following link receives the position reference.
- Its preceding link receives the position node’s existing preceding link.
- The position node’s preceding link is replaced with the supplied node.
- The supplied node’s preceding link is then read again.

If that re-read link is zero, the supplied node replaces the selected sequence’s last endpoint: owner offset `0x38` or parent offset `0x28`.

If that re-read link is nonzero, the referenced record’s following link is replaced with the supplied node.

Under non-overlapping, stable records, this inserts the supplied node between the selected position and the node formerly reached through that position’s preceding link. An explicit position does not itself need to be an endpoint.

The re-read of the supplied node’s preceding link is significant. If the supplied node aliases the selected position, the intervening write can change the value observed by this branch. No alias protection is present.

### 5. Update counts

For owner-level placement, parent and ancestor counters are skipped.

For a nonzero selected parent:

1. The selected parent’s direct-child count at `0x20` is incremented once.
2. Its ancestor-propagated count at `0x1c` is incremented once.
3. The parent link at `0x10` is read to select the next ancestor.
4. Each nonzero ancestor receives the same increment at `0x1c`, followed by a read of its parent link.

Only the initially selected parent receives the direct-child increment. Every visited record, including that parent, receives an ancestor-propagated increment.

The function does not count or inspect any descendants already attached beneath the supplied node. Each relevant counter is increased by one, not by an existing subtree size.

After parent-chain processing, or immediately after owner-level link processing, the captured owner’s total count at `0x30` is incremented once.

These are four-byte read-modify-write operations. The supplied text does not establish signed-overflow semantics. Ordinary acceptance examples therefore require representable increments. Modulo-\(2^{32}\) behavior at a boundary requires additional target-level evidence; it is not guaranteed solely by the signed source representation.

### 6. Process owner state slots

After the total-count increment, the function examines the owner’s state slots in this order:

1. Read offset `0x910`. If nonzero, call F-1137792fba7d with no explicit arguments, then write zero to offset `0x910`.
2. Read offset `0x914`. If zero, return. If nonzero, call F-1137792fba7d with no explicit arguments, then write zero to offset `0x914` and return.

The second slot is read after any first invocation and after the first slot’s zeroing. Its decision therefore reflects the value present at that later time, including any dependency-induced change.

Each conditional invocation precedes the corresponding zero store. The slot value is not passed as an explicit argument.

## Side effects

### Direct writes

When both gates succeed and execution reaches completion, the function directly changes:

- The supplied node’s parent and two sequence links.
- Selected neighboring-node links.
- A first or last endpoint when required by the insertion case.
- The selected parent’s direct-child count, if a parent was selected.
- The ancestor-propagated count of each visited parent-chain record.
- The owner’s total count.
- Each state slot found nonzero when it is inspected, by clearing it after a dependency call.

The node’s owner field is not directly changed. The function does not directly initialize the supplied node’s child endpoints or its own counts.

### Ownership and lifetime

The function visibly links existing records; it contains no explicit allocation or deallocation operation.

F-1137792fba7d must not be described as releasing either state slot’s contents on this evidence. It receives no explicit slot value, and its memory-ownership effects are unknown.

No local rollback is present. Link and count changes occur before the final dependency calls. If execution fails, does not return from a dependency, or follows an invalid parent chain, completed writes are not locally undone.

### Concurrency and reentrancy

No locking, atomic update, or reentrancy protection is visible. Several fields are re-read during attachment, and the ancestor chain is followed incrementally rather than snapshotted.

A stable-sequence interpretation therefore requires suitable external synchronization and dependency behavior. Concurrent modification is not established as supported.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Except where stated otherwise, they assume stable, non-overlapping records, returning dependencies, well-formed chains, representable counter increments, and no dependency mutation of relevant state.

### Initial gate rejects

Given F-3b037d560480 returns zero:

- F-06f4ceb6a4f2 is not called.
- The node’s owner field and placement descriptor are not read by this function.
- No direct record writes occur.

Any effects of the first dependency remain outside that guarantee.

### Owner gate rejects

Given the first gate succeeds and F-06f4ceb6a4f2 returns zero:

- The owner reference has been read and supplied to the second gate.
- The descriptor is not inspected.
- No links, counters, or state slots are directly written by this function.

### Default placement into an empty owner sequence

Given a null descriptor and both owner endpoints equal zero:

- The supplied node receives a zero parent and two zero links.
- Both owner endpoints become the supplied node.
- The owner total count increases by one.
- No parent-chain counters change.
- State-slot processing follows afterward.

### Explicit beginning placement into a nonempty owner sequence

Given a descriptor with zero parent and zero position:

- The node becomes the owner’s first endpoint.
- Its preceding link identifies the former first endpoint.
- Its following link is zero.
- The former first node’s following link identifies the supplied node.
- The existing nonzero last endpoint remains unchanged.

### Sentinel placement under a parent

Given a nonzero parent and a descriptor position of `-1`, with a well-formed nonempty child sequence:

- Placement uses that parent’s current last-child endpoint.
- The new node becomes the last-child endpoint.
- Its following link identifies the former last child.
- Its preceding link is zero.
- The former last child’s preceding link identifies the new node.
- The parent’s direct-child count increases once.
- The parent and all ancestors receive one ancestor-propagated increment each.
- The owner total count increases once.

### Explicit interior placement

Given a selected position whose preceding link identifies another node:

- The supplied node’s following link identifies the position.
- Its preceding link identifies the formerly preceding node.
- The position’s preceding link and that other node’s following link both identify the supplied node.
- Neither endpoint changes.

### State changed by the first post-attachment call

Given the first state slot is nonzero, and its dependency call clears the second slot:

- The first call occurs.
- The first slot is explicitly zeroed afterward.
- The later read of the second slot observes zero.
- No second call occurs.

### Cyclic parent chain

Given a selected parent chain that cycles and no intervention changes that chain:

- Ancestor propagation does not terminate normally.
- Repeated increments may encounter overflow.
- The owner total increment and subsequent state-slot processing are not reached through normal completion.

No cycle detection is provided.
