# F-450024eac262

## Purpose

F-450024eac262 obtains a record address through two owner-associated lookups, updates selected record fields, invokes one of two object-producing dependency sequences, stores the selected sequence’s result in the record, and returns the record address.

“Owner,” “record,” “context,” and “object” describe call-site roles, not established types or ownership relationships. The interpretation that the two object-producing dependencies perform construction is inferred intent. Their internal behavior is unavailable.

Both paths call F-8157a180d901 with the integer `0x130` and pass its result as the first argument to the selected object-producing dependency. The source does **not** establish that F-8157a180d901 allocates memory, that its argument is a byte count, or that its result denotes allocated storage. This contract therefore calls it the **preparation dependency** and its return value the **preparation result**.

### Optional source acquisition

| Source-enable selector | Full mode selector | Byte written at `0x10` | Word subsequently written at `0x14` |
|---|---|---:|---|
| Zero | Any | `0` | `0` |
| Nonzero | Zero | `1` | Result of F-50934d32ec63 with the conversion input |

In the enabled cases, the byte at `0x10` is written before the selected dependency call. F-3fdd14ecd250 has no arguments in the supplied representation. Its returned address is dereferenced at offset `0x1C`, and that word becomes the selected source value.

The selected 32-bit value is written to record offset `0x14` after acquisition and any dependent memory read. Disabled acquisition makes neither source-acquisition call.

Mode truncation and mode selection are distinct. For example, mode `0x00000100` stores a zero byte at `0x18` but takes the nonzero-mode acquisition branch when acquisition is enabled.

### Four-word transfer

After source selection, the function transfers four 32-bit words into record offsets `0x00`, `0x04`, `0x08`, and `0x0C`.

The established access order is:

1. Read source offsets `0x04`, `0x08`, and `0x0C`, in that order.
2. Read source offset `0x00`.
3. Write that last-read word to record offset `0x00`.
4. Write the retained words to record offsets `0x04`, `0x08`, and `0x0C`, in that order.

All four source reads precede the first transfer write. The source is not captured at function entry: the owner write, lookup calls, record-preparation calls, and source-selection operations have already occurred.

Aliasing can therefore affect the values read. In particular, source data overlapping earlier record writes may already have changed before this transfer begins. No general overlap-safety guarantee beyond the stated access ordering is established.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. They assume valid required memory and normally returning dependencies unless stated otherwise.

1. **Disabled acquisition still transfers source words.** With source-enable zero, source selection writes zero at `0x10` and `0x14`, and neither acquisition dependency is called. The four-word source transfer still occurs.

2. **Conversion result.** With acquisition enabled and mode zero, F-50934d32ec63 receives the conversion input. If it returns `0x12345678`, that word is written to `0x14` after the source-kind byte is written as one. Later dependency mutations are not excluded.

3. **Full-width mode.** With acquisition enabled and mode `0x00000100`, the stored mode byte is zero, but F-3fdd14ecd250 is selected instead of F-50934d32ec63.

4. **Transfer ordering.** If the four source reads observe words A, B, C, D at offsets `0x00`, `0x04`, `0x08`, `0x0C`, the transfer writes A, B, C, D to the corresponding record offsets. Reads occur in the order B, C, D, A, before any transfer write.

5. **Preparation-result forwarding.** If F-8157a180d901 returns an opaque value P, the selected object-producing dependency receives P as its first argument. This also applies if P is zero; there is no visible conditional bypass. It does not establish that the receiving dependency accepts zero.

6. **Different capture times.** If the default-path preparation call changes the first word of the captured table, F-c656f96f1369 receives the changed word. If the alternate-path preparation call changes descriptor storage, F-b0c43715d8d1 still receives the four words captured before that call.

7. **Post-configuration condition.** On the default path, zero at `0x84` when inspected causes all four conditional calls in their specified order. A nonzero value skips all four.

8. **Object-field mutation.** If F-df6da5bd408b changes record offset `0x7C` from X to Y, the following F-c57b56681a78 call receives Y, not necessarily X.

9. **Alternate selection.** Any nonzero construction-path selector chooses F-b0c43715d8d1 with trailing constants `0x2D0`, `0x240`, without the default table write or condition read.
