# F-4756a9fdee45

## Purpose

F-4756a9fdee45 records a 32-bit selection through an associated object, invokes an embedded-state dependency, and clears a flag. Unless the retained selection is the sentinel 65,535, it performs further configuration and may insert an embedded node into a linked list.

The established behavior includes:

- Writing the supplied selection before any dependency call.
- Retaining a selection snapshot before the first dependency call.
- Clearing a one-byte flag even on the sentinel-return path.
- Distinguishing selections greater than 30 using unsigned ordering.
- Passing the unadjusted retained selection to a configuration dependency.
- Writing the retained selection minus 30 on the greater-than-30 path.
- Conditionally calculating a deadline-like value and publishing an embedded list node.
- After a release-like call, rereading the **same global pointer used as the earlier acquisition-like argument**, dereferencing its current value to obtain a head, and conditionally invoking an indirect target.

Scheduling, timer registration, reset, acquisition, and release are inferred interpretations. The contract below establishes the accesses, conditions, and call ordering without requiring those interpretations.

## Interface

### Inputs and output

The function receives:

1. A 32-bit object address.
2. An opaque 32-bit selection value.

The retained selection is interpreted as unsigned for the sentinel comparison, threshold comparison, and subtraction.

There is no explicit return value or success indicator. Observable results are direct memory writes and dependency effects. No visible handling exists for dependency failures, faults, exceptions, or nonlocal exits.

Every address actually accessed must remain valid for its access. There are no visible null checks for the input object, associated object, or global pointer slots. The null checks described below apply only to particular list-head and successor values.

### List and global roles

An existing insertion-list node exposes a 32-bit successor at offset `0` and a comparator operand beginning at offset `8`. The embedded node therefore has its corresponding operand at object offset `0x68`. The comparator operand’s full width and interpretation are unknown.

The following descriptive labels distinguish global roles without assigning undocumented meanings:

- **Shared-head pointer global:** its 32-bit pointer value is supplied to F-338d16f9ce72. After F-5bcae2eff9a7, this same global is read again; dereferencing the freshly obtained pointer yields the final head address.
- **Insertion-head-slot global:** supplies the pointer to the head slot used for insertion. Its value is captured separately.
- **Release-argument global:** supplies the argument to F-5bcae2eff9a7.
- **Indirect-target global:** supplies the eventual indirect target.

The shared-head pointer global and insertion-head-slot global are distinct global locations. Their pointer values or referenced storage are not established to be distinct or equal.

## Behavior

### Initial write, retained selection, and sentinel

The function first reads the association at object offset `0x28` and writes the supplied 32-bit selection to the associated field at offset `0x48c`.

It then reads the association again and reads that associated field into a retained unsigned 32-bit selection snapshot. This snapshot controls all later selection-dependent decisions. It is not replaced by subsequent reads of the associated selection field.

There is no intervening dependency call between the initial write and snapshot read. With a stable association and ordinary nonoverlapping storage, the snapshot equals the supplied selection. The contract nevertheless distinguishes the write from the subsequent reads; it does not impose an otherwise unstated nonaliasing guarantee.

The function next:

1. Calls F-936a8728139d with the address of the embedded region at object offset `0x60`.
2. Writes zero to the byte at object offset `0x8c`.
3. Returns if the retained snapshot equals `0x0000ffff`, or 65,535.

The sentinel path therefore still performs the initial write, the first dependency call, and the flag clear. It performs none of the later configuration or registration operations.

The first dependency may change the association, associated selection, other object fields, or globals. Such changes do not alter the retained selection snapshot.

### Selection-dependent configuration

For a nonsentinel snapshot, the function computes a 32-bit product using the retained selection and an opaque global multiplier. This occurs before F-f36c23c5ba7b.

F-f36c23c5ba7b receives:

- The associated-object address freshly read from object offset `0x28`.
- The retained, unadjusted selection.

After that call, the retained selection is compared with 30 using unsigned ordering.

For values from 0 through 30 inclusive:

- No adjusted-selection write occurs.
- No direct flag write occurs at this stage.
- The previously computed product remains the next configuration argument.

For values greater than 30, excluding the sentinel:

1. The flag at offset `0x8c` is set to one.
2. An opaque global 32-bit value is read to replace the product as the configuration argument.
3. The associated-object address is read again.
4. The retained selection minus 30 is written to that associated object’s field at offset `0x48c`.

F-f36c23c5ba7b may change the association or alternate configuration global before these later reads. The adjusted write need not target the object used for the initial write or the preceding call.

The subtraction uses the retained unsigned value. Since this branch requires a value greater than 30, subtraction does not underflow. High-bit values are included: `0xffffffff` takes this branch and produces `0xffffffe1`.

### Embedded configuration and registration gate

F-6904f7699031 receives the embedded-region address and the selected 32-bit configuration value.

F-936a8728139d is then called a second time. No explicit argument is recoverable for this invocation. The argument of its first invocation must not be assumed to describe the second.

After the second invocation returns, an opaque global 32-bit value is read and written to object offset `0x80`.

Only then is the 32-bit registration gate at offset `0x7c` read:

- Nonzero: return without entering registration.
- Zero: enter registration.

The gate is therefore evaluated after the configuration calls and metadata write, not at entry. Earlier dependencies may determine the value observed.

### Registration entry and quantity inspection

On the zero-gate path, the function reads the shared-head pointer global and passes its current pointer value to F-338d16f9ce72.

It then calls F-add44d4e9aaa with the embedded-region address. Only after this call does it read the 32-bit quantity at object offset `0x64`.

If the quantity is zero, the function skips deadline calculation, insertion metadata, traversal, insertion, and its direct write of one to the gate. It still proceeds to F-5bcae2eff9a7 and the final head inspection.

If the quantity is nonzero, that read value is retained across the next dependency call.

### Deadline-like calculation and insertion search

For a nonzero retained quantity, the function calls the result-provider dependency identified below as F-opaque-01.

After that call returns, the function:

1. Reads and retains the pointer from the insertion-head-slot global.
2. Writes a 32-bit result at object offset `0x68`, formed from the provider result plus 1,000 times the retained quantity.
3. Reads an opaque global value and writes it to object offset `0x78`.
4. Reads the insertion head through the retained head-slot pointer.

The quantity is not reread after F-opaque-01. Conversely, the insertion-head-slot pointer is read after that call, so dependency changes to that global affect the pointer captured.

For every non-null current node, F-0d70d6f9010c receives, in order:

- The address at current-node offset `8`.
- The address at object offset `0x68`.

A zero result continues traversal. Any nonzero result stops traversal before that current node. Positive and negative nonzero results are not distinguished; no ascending or descending numeric ordering is established.

When the comparator returns zero, the current node’s successor is read **after** the call. Mutations made by the comparator can therefore alter the next node visited. The current node becomes the retained predecessor.

The captured head-slot pointer is not reacquired during traversal. Comparator changes to its originating global do not redirect a later head insertion. Comparator changes to referenced storage may still affect traversal and writes.

### Insertion writes

Search stops at either a null successor or a node whose comparator result is nonzero.

The embedded node is inserted at the head if no predecessor was retained, or after the retained predecessor otherwise. Direct writes occur in this order:

1. Write the embedded-node address into the captured head slot or predecessor’s successor field.
2. Write one to object offset `0x7c`.
3. Write the stopping node address, possibly null, into the embedded successor at offset `0x60`.

The embedded node is published before its successor is assigned. This ordering alone provides no concurrency-safety guarantee.

There is no visible independent membership check. If dependencies or callers arrange for the node to be present while the gate is zero, this body does not establish that reinsertion is safe.

### Release-like call and final dispatch

Whether insertion occurred or the quantity was zero, the registration block next reads the release-argument global and calls F-5bcae2eff9a7 with that value.

After the call returns, the function performs a **fresh read of the shared-head pointer global**—the same global location whose earlier value was supplied to F-338d16f9ce72. It dereferences this freshly obtained pointer to read the final head address.

This is not equivalent to retaining the earlier acquisition-like argument. Intervening dependencies may change:

- The pointer stored in the shared-head pointer global.
- The head stored at either the old or new pointed-to location.
- The first word of the eventual head node.

If the final head is null, no node-word read or indirect call occurs. If the head is non-null, its first 32-bit word is read. The indirect target is invoked only if that word is also nonzero.

The first word is a dispatch condition, not an established target address. The target comes from the separate indirect-target global. No explicit arguments are recoverable for this invocation.

## Side effects

Direct writes affect the described object fields, associated-object selection fields, and insertion-list links. Dependencies may have additional effects not bounded by this body.

No allocation or explicit deallocation is visible. The published node is embedded in the input object. If a list retains that address, the object must remain valid for subsequent uses of the node. Ownership transfer, unlinking, and eventual release are not established.

No dependency is assumed to preserve globals, object fields, list contents, association pointers, or storage lifetimes. Every later access requires valid storage despite any earlier dependency effects.

F-338d16f9ce72 and F-5bcae2eff9a7 occupy acquisition-like and release-like positions, but they receive operands from different globals. Their names here do not establish locking or a matched resource protocol. The established shared-global relationship is specifically between the argument source for F-338d16f9ce72 and the fresh pointer read used for the final head lookup.

## Acceptance examples

These are conditional static examples, not executed tests. Unless an example says otherwise, dependencies return normally, preserve relevant storage and values, and the initial selection write does not alias the association field.

1. **Sentinel:** Selection 65,535 causes the initial write, first F-936a8728139d call, and flag clear, then returns. No later dependency runs.

2. **Threshold 30:** F-f36c23c5ba7b receives 30. F-6904f7699031 receives the product computed before that call. No adjusted-selection write occurs.

3. **Selection 31:** F-f36c23c5ba7b receives 31. Afterwards the flag is set, the alternate global configuration value is read, and 1 is written through the then-current association.

4. **High-bit selection:** Selection `0xffffffff` is nonsentinel and unsigned-greater-than-30. The adjusted selection is `0xffffffe1`.

5. **Changed association:** If F-f36c23c5ba7b changes the association and the retained selection is 31, the adjusted value 1 is written through the new association, not necessarily to the initially selected object.

6. **Nonzero gate:** A nonzero gate when checked suppresses registration, the release-like call, and final dispatch inspection. Configuration and the `0x80` write have already occurred.

7. **Zero quantity:** With a zero gate and zero quantity after F-add44d4e9aaa, no direct insertion or gate-setting write occurs. F-5bcae2eff9a7 and final head inspection still occur.

8. **Empty insertion list:** For a nonzero quantity and null insertion head, no comparator call occurs. The head slot receives the embedded address, the gate receives one, and the embedded successor receives null, in that order.

9. **Comparator position:** Zero results for two nodes followed by a nonzero result for a third insert the embedded node after the second and before the third, provided successors remain as assumed.

10. **Changed shared pointer:** Suppose F-338d16f9ce72 receives a pointer to one head slot, but before final inspection the shared-head pointer global is changed to point to another valid slot. Final inspection reads the second slot. A null head there suppresses dispatch even if the earlier slot contains a dispatch-eligible head.

11. **Changed referenced head:** If the shared pointer remains unchanged but F-5bcae2eff9a7 changes its referenced head to null, final dispatch is suppressed. A cached pre-call head would not satisfy the contract.

12. **Dispatch condition:** A non-null final head whose first word is zero suppresses the indirect call. If both are nonzero, F-opaque-02 is invoked through the separate target global.
