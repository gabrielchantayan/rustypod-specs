# F-94f32633f626

## Purpose

F-94f32633f626 derives an unsigned index from a selector, stores that index in an existing object, and conditionally stores an object-relative address value in another field.

Selectors `0x84C0` and `0x84C1` produce indices zero and one without invoking a dependency. Other selectors invoke F-375c8199e7c2 before the index store, provided the initial arithmetic has defined behavior under the interpretation described below. A normal return from that dependency leads to continued processing; the visible body does not restrict subsequent stores to indices zero and one.

A discriminator read after the index store determines whether the derived-address value is stored. The discriminator is not captured before the dependency call.

These are structural observations. The object’s domain meaning, the significance of the constants, and the dependency’s purpose are not established.

## Behavior

### Index selection

The function subtracts `0x84C0` from the selector and converts the result to the unsigned index.

For representable signed subtraction:

- Selector `0x84C0` produces index zero.
- Selector `0x84C1` produces index one.
- A smaller selector produces a negative signed result, then its corresponding unsigned value.
- A larger selector produces an index greater than one.

The unsigned index is compared with one. If it exceeds one, the function invokes F-375c8199e7c2 with the original object base followed by `0x500`.

The index is computed before this invocation. It is not recomputed from object state afterward, and no returned value is visibly used to replace it.

### Dependency continuation

The dependency call is not a visible rejection branch. If it returns normally and the subsequent arithmetic and accesses remain valid, execution proceeds to the index store even for indices outside zero and one.

If the dependency does not return normally, the visible control flow does not require the later accesses to occur. The supplied material does not establish whether nonreturn is possible or what mechanism it would use.

### Index store

The function forms the address at offset `0x24C` and writes the unsigned index there.

This write occurs on every continuing path, regardless of whether the dependency was invoked. If the dependency changed this field before returning, the direct write replaces its contents.

The address formation has its own signed-arithmetic constraint. A defined selector subtraction and a valid unsigned index do not, by themselves, make this field address valid.

### Discriminator read

After the index write, the function forms the address at offset `0x104` and reads a four-byte signed discriminator.

If the value read equals `0x1702`, execution reaches the conditional write. Otherwise, the visible body performs no write to offset `0x34`.

The value relevant to this decision is the value read at this point, not necessarily its value at entry. In particular, a dependency-induced change can affect the decision.

### Conditional derived-address store

When the discriminator equals `0x1702`, the function stores a value equal to the object base plus twelve times the unsigned index plus `0x1C`, reduced modulo `2³²` under the stated unsigned interpretation.

For the two distinguished indices:

- Index zero yields the object base plus `0x1C`, modulo `2³²`.
- Index one yields the object base plus `0x28`, modulo `2³²`.

The same arithmetic is applied to other indices if execution reaches this point. There is no visible additional index check.

The destination field remains the location formed by the separate signed addition of `0x34` to the object base. The unsigned calculation of the value being stored does not relax the destination-address precondition.

### Observable order

The established direct-access sequence is:

1. Compute the index.
2. Invoke F-375c8199e7c2 if the unsigned index exceeds one.
3. Form the `0x24C` field address and write the index.
4. Form the `0x104` field address and read the discriminator.
5. If the discriminator matches, form the `0x34` field address and write the derived-address value.
6. Return without a value.

This is the source-level access order. It establishes no atomicity, synchronization, or cross-thread visibility guarantee.
