# F-e74d4356644c

## Purpose

F-e74d4356644c conditionally updates a 32-bit state word within a caller-supplied object and returns a Boolean result. Its decision combines opaque dependency results with a signed comparison of two object fields.

Two paths return true:

- A first dependency invocation returns nonzero, and the signed value at object offset +0x18 is less than or equal to the signed value at +0x50. The function then clears bits 0 and 20 of the state word.
- That direct path is not taken, a second dependency invocation returns zero, and a third invocation using a different selector returns nonzero. The function invokes another dependency, then clears bit 16 of the state word.

All other normal returns are false.

These are established control-flow properties, not interpretations of the application’s intent. The meanings of the selectors, fields, cleared bits, and Boolean result are unknown.

**Output:** A Boolean value. The logical results are true and false; the physical return-register representation is not established.

## Behavior

### First decision and direct success

The first observable operation is a call to F-900e57cefc4b with:

- The original object argument.
- The selector value 0x00040000.

If that invocation returns zero, the function performs no direct object-field read at this stage and proceeds to the second decision.

If it returns nonzero, the function reads the 32-bit field at +0x18, then reads the 32-bit field at +0x50. It compares the two values as signed 32-bit integers, with +0x18 as the left operand.

The signed interpretation is significant. A field value with its high bit set participates as a negative value, not as a large positive unsigned value. Equality qualifies for success.

If the left value is less than or equal to the right value:

1. The function reads the state word at +0x44.
2. It clears bit 0 and bit 20, counting the least significant bit as bit 0.
3. It writes the resulting 32-bit word back to +0x44.
4. It returns true.

The mask is 0xFFEFFFFE. Every other bit retains its value from that state-word read.

This path makes no further dependency call. In particular, it does not invoke F-408b92e1ab86.

If the signed comparison fails, the function proceeds to the second decision without directly reading or writing +0x44.

### Second decision

Whenever direct success has not occurred, the function calls F-900e57cefc4b again with the original object argument and selector 0x00040000.

This is a distinct invocation, not reuse of the first result. It occurs both when the first invocation returned zero and when the first invocation returned nonzero but the comparison failed.

If this second invocation returns nonzero, the function returns false immediately. It performs no direct state-word write.

The earlier comparison, when present, does not determine this second dependency result. No stability or purity guarantee is established for the dependency.

### Third decision and fallback success

If the second invocation returns zero, the function calls F-900e57cefc4b with:

- The original object argument.
- The selector value 0x00010000.

If this third invocation returns zero, the function returns false without a direct state-word write.

If it returns nonzero:

1. The function reads the 32-bit value at object offset +0x04.
2. It passes that value as the sole argument to F-408b92e1ab86.
3. After that call returns normally, it reads the state word at +0x44.
4. It clears bit 16 using mask 0xFFFEFFFF.
5. It writes the resulting word back to +0x44.
6. It returns true.

No return value from F-408b92e1ab86 is used.

The state-word read occurs **after** that dependency call. Consequently, the final masked value is based on the state present after the call, not a snapshot taken beforehand. If the dependency changes other bits in the state word and leaves the object accessible, those bits survive this function’s mask.

### Return conditions and write behavior

On normal completion, true means that one of the two local state-word update paths completed. It does not establish any broader application-level success.

Each true path performs one direct read and one direct write of +0x44. The write still occurs if the targeted bits were already clear.

Each false path performs no direct write to the object. That does not imply that the object, globals, or external resources remain unchanged: invoked dependencies may have side effects.

There are no retries, loops, error codes, or alternate recovery paths visible in this function.

## Side effects

The direct side effect is a single 32-bit write to +0x44 on either success path:

| Path | Bits forcibly cleared | Other bits |
|---|---|---|
| Direct comparison success | 0 and 20 | Retained from the preceding state-word read |
| Fallback success | 16 | Retained from the post-dependency state-word read |

The function does not directly set any bit.

Observable direct-access ordering is:

- On direct success: first dependency call, read +0x18, read +0x50, read +0x44, write +0x44.
- On fallback success: preliminary decision calls and any comparison reads, third decision call, read +0x04, call F-408b92e1ab86, read +0x44, write +0x44.

No local rollback is visible. Side effects produced by an earlier dependency remain possible even if the function later returns false.

No synchronization or atomic read-modify-write mechanism is established. A concurrent change between a state-word read and its write may be overwritten. Exact memory-ordering guarantees are documented_only unknowns.

## Acceptance examples

These are conditional, statically derived examples, not runtime test results. Each assumes that dependencies return normally and all reached memory accesses are valid.

1. **Direct success at equality.**  
   The first selector invocation returns nonzero. Both comparison fields contain signed value 7. With state word 0xFFFFFFFF, the function writes 0xFFEFFFFE and returns true. Neither a second selector invocation nor F-408b92e1ab86 occurs.

2. **Signed comparison accepts a high-bit value.**  
   The first selector invocation returns nonzero. The +0x18 field contains 0xFFFFFFFF, representing −1, and +0x50 contains zero. The direct path succeeds because −1 is less than or equal to zero.

3. **Signed comparison rejects the reverse ordering.**  
   The first selector invocation returns nonzero. The +0x18 field contains zero and +0x50 contains 0xFFFFFFFF. The comparison fails. A second 0x00040000 invocation is required; the function has not yet directly accessed the state word.

4. **Second result stops evaluation.**  
   The first invocation returns zero and the second returns nonzero. The function returns false. It does not directly read the listed object fields, invoke the 0x00010000 selector, or write +0x44. Dependency accesses remain unspecified.

5. **Third result rejects fallback.**  
   The first and second invocations return zero, and the 0x00010000 invocation also returns zero. The function returns false without calling F-408b92e1ab86 or directly writing the state word.

6. **Fallback uses post-call state.**  
   Direct success does not occur, the second invocation returns zero, and the third returns nonzero. F-408b92e1ab86 leaves +0x44 containing 0x00010003. The function subsequently writes 0x00000003 and returns true.

7. **Already-cleared bits do not suppress the write.**  
   Direct success occurs with state word 0x00000002. The function writes 0x00000002 back and returns true. Likewise, fallback success with bit 16 already clear still performs its write.
