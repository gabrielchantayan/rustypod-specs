The following notation names externally relevant values and layouts, not implementation-local identifiers:

- **Word slot** at index \(x\): address \(4x + 0x14\).
- **Expanded slot** at index \(x\): address \(16x + 0x14\).
- **Clear field** at base \(x\): address \(x + 0x44\).
- **Selector read** at base \(x\): an unsigned byte read at \(x + 1\).
- **Selected byte location** for selector \(s\): absolute address \(s + 0x11\).

These are address formulas, not verified structure definitions. In particular, the selected byte location is formed from the byte value itself; it is not a pointer loaded from a table. Its possible addresses range from `0x11` through `0x110`.

All explicitly identified byte writes affect eight bits. Word writes affect 32 bits. Byte loads are zero-extended before subsequent unsigned arithmetic. A byte store retains only the low eight bits of its value.

The visible unsigned masks and right shifts have definite bit meanings:

- The fourth input shifted right by three lies in \(0\) through `0x1fffffff`.
- Masking with `0x3fffffff` retains bits 0–29.
- That masked value shifted right by one lies in \(0\) through `0x1fffffff`.
- That masked value shifted right by 20 lies in \(0\) through `0x3ff`; storing it as a byte retains original bits 20–27, not bits 28–29.
- Masking with `0x3fffff` retains 22 bits. Scaling that result by 128 produces at most `0x1fffff80`; scaling it by 16 produces at most `0x03fffff0`.

Other displayed multiplications and left shifts may overflow a 32-bit quantity. For examples below that require bit-vector arithmetic, truncation to 32 bits is an explicit condition, not a claim about the correctness of recovered signed expressions.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Fourth-input extraction.** If execution reaches the corresponding word-slot write, a fourth input of `0xffffffff` produces the 32-bit stored value `0x1fffffff`. An input of seven produces zero.

2. **Byte truncation.** If the first encoding value is `0x12345678`, its initial fourfold byte write stores `0xe0`. Its later high-fragment byte write stores `0x23`. The two destinations may differ.

3. **Selector reload.** If the first selector observation is two and the second is nine, the corresponding byte destinations are `0x13` and `0x1a`. Reusing the first selector for both writes would not match the visible behavior.

4. **Distinct slot layouts.** For an index of three, the expanded-slot destination is `0x44`, while the word-slot address is `0x20`. A read from the latter cannot be replaced with the value just written to the former without additional aliasing evidence.

5. **Low-address overlap.** Selector `0x13` directs a byte write to absolute address `0x24`. A later 32-bit clear there can overwrite that byte. Intervening dependency effects remain unconstrained.

6. **Masked scaling.** If the reduced object value is `0x00400001`, its low-22-bit-scaled-by-128 payload is `0x80`, and its corresponding scale-by-16 argument is `0x10`.

7. **64-bit result halves.** If the represented 64-bit result has low half three and high half five, the relevant dependency receives 12 and the subsequent clear targets `0x4e`, provided those addresses and accesses are valid.

8. **Conditional wrapping.** Under a 32-bit wrapping arithmetic model, reduced object value 64 produces a late base of zero because multiplication by `0x4000000` discards all higher bits. This example does not establish that the recovered signed arithmetic is trustworthy.
