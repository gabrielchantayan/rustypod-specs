# F-6c51845cbba1

An application-level purpose is not established. Identifying the routine as a loader, parser, initializer, or ownership operation would exceed the evidence.

Possible intent is not an acceptance requirement.

## Interface

### Invocation and implicit inputs

The represented interface has no explicit parameters and no return payload. It nevertheless depends on:

- Incoming link-related machine state used to form the first call target.
- Two inherited 32-bit machine values: one supplies a halfword-store address; the other supplies a source-address calculation.

- An unsigned limit word read at absolute address **0x08400198**.

- Four source words accessed through a computed low address.
- Runtime stack placement.

There are no represented checks that these implicit inputs are initialized, that call targets are executable, or that accessed memory is mapped.

### Widths and interpretation

A **word** is a 32-bit bit pattern; a **wide result** is 64 bits. Byte and halfword accesses are 8 and 16 bits respectively. Addresses and pointer values are represented at 32-bit width.

“Low word” and “high word” mean the numerical low and high 32 bits of a wide result. They do not establish memory byte order.

Bit numbers start at zero. Single-bit arguments are unsigned values of zero or one. The later high-nibble argument ranges from zero through fifteen.

Unsigned subtraction explicitly described below wraps modulo \(2^{32}\). Signed subtraction and signed address multiplication require separate treatment: their overflow semantics are not established by the representation.

### Completion and failures

No normal-return path is established. Observable outcomes include dependency calls, memory effects, and arrival at either invalid-instruction endpoint.

No error code, exception class, recovery action, or rollback protocol is represented. An unsuccessful call or memory access may prevent subsequent events while leaving earlier effects visible.

### Destination-base capture, C127, and limit sampling

C127 then receives, in order:

1. The source word read at offset 0.
2. The auxiliary word also stored at 0xc3.
3. The numerical address 0xc3.
4. The source word read at offset 4.

After C127 returns, the routine:

1. Reads and saves the unsigned 32-bit limit at **0x08400198**.
2. Stores another auxiliary register word at the captured destination base plus 0x68.
3. Compares the saved limit with eight, unsigned.

If the limit exceeds eight, execution reaches the first invalid-instruction endpoint. The base-plus-0x68 store has already occurred.

The sampling distinction is mandatory: **the base is captured before C127; the limit is sampled after C127**. A C127 modification to 0x08400240 does not replace the captured base. A C127 modification to 0x08400198 can affect the subsequent comparison.

### Accepted tail

For a saved limit from zero through eight, inclusive, C128 executes. After it returns, the represented effects occur in this order:

1. Store the saved limit’s low byte at the captured base plus 0x0f.
2. Store a halfword at absolute address 0x28 plus the saved limit.
3. Assign zero to a local 32-bit stack slot. The represented derivation is the numerical address 0xc3 shifted right by fourteen.
4. Assign the earlier offset-16 source word to another local 32-bit stack slot.
5. Execute C129.
6. Reach the second invalid-instruction endpoint.

The halfword value is the low sixteen bits of the address of the local slot assigned zero, plus 0x398. It depends on runtime stack placement. Its destination ranges from 0x28 through 0x30; odd accepted limits produce odd halfword destinations.

C128 may modify the original limit location, but the explicit tail stores use the previously saved limit. No reread is represented.
