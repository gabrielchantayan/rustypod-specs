# F-6818a4117cbb

## Purpose

F-6818a4117cbb returns a signed, 32-bit value selected or derived from fields in a caller-supplied record. A control word determines whether the operation is permitted, which fields supply the result, and whether a positive result is reduced by one.

If neither of the control word’s two lowest bits is set, the function instead obtains a destination from F-4af36158f863, writes the 32-bit value `1` there, and returns `-1`, provided that the dependency returns normally and the write succeeds.

**Established static behavior:** the function performs field reads, integer arithmetic, and, on the rejected path, one explicit write through a dependency-provided address.

**Inferred intent:** the fields may represent a position, extent, or buffered count, with an optional one-unit adjustment. Those interpretations are not needed to describe the behavior and are not established by the available evidence. This contract therefore assigns no application-level meaning to the returned number.

## Behavior

### 1. Read and classify the control word

The first observable record read is the 32-bit control word at offset `0x0C`.

The operation is accepted if at least one bit in mask `0x00000003` is set. Thus the low-two-bit patterns `01`, `10`, and `11` are all accepted. The function does not distinguish among those three patterns for subsequent processing.

If both low bits are clear, the operation follows the rejected path. Other bits do not override that rejection.

All later decisions use the initially read control word. There is no explicit second read of that field.

### 2. Rejected path

When the control word masked with `0x00000003` is zero, the function:

1. Calls F-4af36158f863 without explicit arguments.
2. Treats its returned value as an address suitable for a 32-bit write.
3. Writes the 32-bit integer `1` at that address.
4. Returns `-1`.

No record fields other than the control word are explicitly read on this path.

The destination is not checked for nullness, alignment, writability, or aliasing before the write. Successful completion therefore requires the dependency to return a destination at which the write can complete.

The function does not explicitly release the returned destination or retain it for later use. This observation does not establish the destination’s ownership or lifetime.

The dependency can have effects not visible in the supplied body. In particular, the evidence does not establish that it preserves global state, avoids the input record, returns fresh storage, or returns the same destination across calls.

### 3. Select an accepted result

For accepted control words, bit `0x00000020` chooses between two result sources.

#### Bit `0x00000020` clear: arithmetic result

The explicit record reads occur in this order:

1. Read the signed, 32-bit field at offset `0x04`.
2. Read the signed, 32-bit field at offset `0x18`.
3. Read the signed, 32-bit field at offset `0x10`.

The provisional result is:

\[
(\text{value at }0x04 + \text{value at }0x18) - \text{value at }0x10
\]

The addition precedes the subtraction in the supplied expression. There is no explicit bounds check, saturation, or wider intermediate.

For inputs whose addition and subtraction both remain within the signed 32-bit range, the mathematical result is established. The supplied representation alone is insufficient to promise portable behavior when an intermediate overflows. Such cases remain **documented_only**, rather than being assigned assumed wraparound or saturation semantics.

The field at `0x28` is not read on this path.

#### Bit `0x00000020` set: direct result

The function reads the signed, 32-bit field at offset `0x28` and uses it as the provisional result.

The fields at `0x04`, `0x18`, and `0x10` are not explicitly read on this path. Incoming values of the second and third arguments do not affect this selection or its result.

### 4. Apply the positive-only adjustment

After obtaining the provisional result, the function examines bit `0x00080000` in the original control word.

- If the bit is clear, the provisional result is returned unchanged.
- If the bit is set and the provisional result is strictly greater than zero under a signed comparison, the function returns that result minus one.
- If the bit is set and the provisional result is zero or negative, the function returns it unchanged.

The adjustment cannot itself overflow a signed, 32-bit value: it applies only to positive values. For example, `1` becomes `0`, while `0`, `-1`, and the minimum signed, 32-bit value remain unchanged.

No other control bits are explicitly tested.
