# F-39d92c7f75ce

## Purpose

F-39d92c7f75ce conditionally performs a polling sequence, selects one of three 32-bit result values, waits for a separate state word to become zero, and sets a bit in a shared state word before returning.

The polling sequence is entered only when bit `0x20` is set in one state word and bit `0x100` is clear in another. Once entered, polling combines repeated state inspection with calls to opaque dependencies. The result depends on a final dependency call and, conditionally, another state inspection—not simply on the observation that ended the loop.

An apparent intent is to wait for a condition or limit, then mark a terminal state. That interpretation is **inferred intent**, not an established meaning for the bits, dependencies, argument, or return values.

The function accepts one opaque 32-bit value.

If the conditional polling sequence is entered, this value is passed unchanged as the second argument to every invocation of F-730b695a8642. No direct arithmetic, validation, dereference, or interpretation of the input is visible.

The input is not passed to any other dependency.

### Output

On normal return, the function produces one of these 32-bit values:

| `0x00000000` | The initial polling gate fails; or polling was entered, the final F-730b695a8642 call returns zero, and the subsequent state gate fails. |
| `0x00000015` | Polling was entered, the final F-730b695a8642 call returns zero, and the subsequent state gate passes. |

These are numeric results. Their meanings as success, timeout, cancellation, or error codes are not established.

No result is returned until the final zero-wait and state-bit update have completed.

## Behavior

### 1. Capture state and evaluate the initial gate

The function captures the state base from the global reference and initializes its prospective result to zero.

It then evaluates an initial gate in this order:

1. Read the 32-bit word at offset `+0x04` and test bit `0x20`.
2. Only if that bit is set, read the 32-bit word at offset `+0x20` and test whether bit `0x100` is clear.

The gate passes only when both conditions hold. Other bits in either word do not affect this decision.

The supplied representation expresses these initial field accesses through the global reference, whereas later accesses use the captured base. There is no intervening dependency call during the initial gate. Whether repeated global-reference expressions correspond to separate physical loads is not established.

If the initial gate fails, the function skips all four dependencies and proceeds directly to the final zero-wait. It does not return immediately.

### 2. Obtain one opaque polling value

If the initial gate passes, the function calls F-c84c3e66ec8d once, with no explicit arguments.

Its 32-bit result becomes an opaque polling value. The same value is passed as the first argument to every subsequent F-730b695a8642 call during this invocation. It is not refreshed between iterations or before the final check.

The visible function neither interprets this value nor performs visible ownership management on it.

### 3. Repeat the polling sequence

Each loop-condition evaluation proceeds in this order:

1. Read the captured state's word at `+0x04`.
2. If bit `0x20` is clear, exit the loop without reading `+0x20` for this condition and without calling F-730b695a8642 for this condition.
3. Otherwise, read the word at `+0x20`.
4. If bit `0x100` is set, exit the loop without calling F-730b695a8642 for this condition.
5. Otherwise, call F-730b695a8642 with the saved polling value and the original input.
6. If its result is nonzero, exit the loop.
7. If its result is zero, execute the loop body.

The loop body calls F-60f3f46b16bc with no explicit arguments.

- If its result is zero, no further dependency is called in that iteration.
- If its result is nonzero, F-6750d7407908 is called with the numeric arguments zero and one, in that order.

The result of F-6750d7407908, if any, is not used by this function.

After the loop body, execution returns to the state checks at the start of the loop condition. A zero result from F-60f3f46b16bc does not terminate polling. A nonzero result only triggers F-6750d7407908; it does not directly select a return value or terminate polling.

There is no visible iteration count, delay operation, or independent timeout calculation in this function. Any time-related behavior of the dependencies remains unknown.

### 4. Perform a separate final dependency check

After leaving the loop, the function calls F-730b695a8642 again, using the same saved polling value and original input.

This call occurs regardless of why the loop ended. It occurs even if:

- A state bit prevented the loop body from running at all.
- A loop-condition call to F-730b695a8642 just returned nonzero.
- A dependency changed state so that the loop's next state gate failed.

Consequently, a dependency result that ends the loop is not reused as the final result check.

The prospective result is then selected as follows:

- A nonzero final dependency result selects `0x1F`. No additional state gate is evaluated for this selection.
- A zero final dependency result causes another ordered state gate:
  - Read `+0x04` and test bit `0x20`.
  - Only if set, read `+0x20` and test that bit `0x100` is clear.
  - Select `0x15` if both conditions hold.
  - Otherwise retain zero.

Changes made by dependencies can therefore affect the state reads that follow them. The contract does not assume that any dependency preserves the global reference or the contents of the captured state region.

### 5. Wait for the separate word to become zero

Whether or not the initial polling gate passed, the function next reads the 32-bit word at offset `+0x10` from the captured state region.

It repeats this read until the entire word equals zero. The first read occurs unconditionally upon reaching this phase.

No dependency is called inside this wait. The function does not visibly modify this word, impose a retry limit, or revise the previously selected result while waiting.

If the word never becomes zero as observed by execution, the function does not reach its final write or return.

### 6. Set the final state bit and return

After observing zero at `+0x10`, the function reads the 32-bit word at `+0x20`, combines it with `0x100` using bitwise OR, and writes the resulting 32-bit word back to the same location.

At the level of this read-modify-write operation, bit `0x100` is set and every other bit retains its value from that final read.

The function then returns the selected result. There is no further visible state check after the write.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. They assume valid storage and normally returning dependencies unless stated otherwise.

### Initial bit `0x20` is clear

The initial `+0x04` read observes bit `0x20` clear.

Expected behavior:

- The initial gate does not read `+0x20`.
- No dependency is called.
- The result remains zero.
- The function still waits for `+0x10` to be zero.
- It then sets bit `0x100` at `+0x20` and returns zero.

### Initial bit `0x100` is already set

The initial `+0x04` read observes bit `0x20` set, and the following `+0x20` read observes bit `0x100` set.

Polling is skipped. Once `+0x10` is observed as zero, the final read-modify-write is still performed, even if bit `0x100` remains set already. The returned value is zero.

### A nonzero loop check does not determine the final result

The initial gate passes. F-c84c3e66ec8d returns a value, and the first loop-condition state gate passes. The first F-730b695a8642 call returns nonzero.

The loop body does not run, but F-730b695a8642 is called again. If that final call returns zero and the subsequent state gate passes, the selected result is `0x15`, not `0x1F`.

### A state change ends polling, but the final check wins

A loop body executes, after which bit `0x20` is clear at the next loop-condition read.

That condition exits without calling F-730b695a8642. The separate final call still occurs. If it returns nonzero, the selected result is `0x1F`, despite the cleared state bit.

### Loop-body action is conditional

A loop-condition state gate passes and F-730b695a8642 returns zero.

F-60f3f46b16bc is called once. A zero result skips F-6750d7407908; any nonzero result causes one call with arguments zero and one. Both cases then return to the loop-condition state checks.

### Final wait can prevent all completion effects

A result has been selected, but every subsequent read of `+0x10` is nonzero.

The function remains in that wait. It does not perform the final `+0x20` write and does not return the selected result.

### Final write uses the latest read word

After the zero-wait, suppose the final `+0x20` read yields `0x00000005`, with no intervening external write.

The function writes `0x00000105`. It does not restore an earlier value observed during polling.
