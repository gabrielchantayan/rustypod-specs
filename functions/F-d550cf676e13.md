# F-d550cf676e13

## Purpose

F-d550cf676e13 obtains an initial signed position, then either retrieves an item directly or examines successive positions using mutable candidate processing and a conditional predicate.

The established contract concerns dependency calls, memory accesses, local state, and construction of a 64-bit result. A conditional lookup or search is plausible intent, not an established semantic guarantee.

The result is not established to be an ordinary pointer or success/error code. Its lower 32-bit word contains either an item word or zero. Its upper 32-bit word comes from a local item word that is not explicitly initialized on every path.

## Interface

### Inputs

The function takes two arguments:

1. **Context word:** a 32-bit value supplied to the initial-position, bound, and retrieval dependencies. Its interpretation as an address, handle, or other value is unknown.
2. **Selection-state pointer:** an address used to access 32-bit state words.

The function initially copies the supplied pointer into invocation-local storage. Candidate processing receives the address of that local pointer and can replace it. Such replacement changes the pointer used by this invocation; it does not itself replace a pointer variable belonging to the caller.

The relevant state layout is:

| Offset from current state pointer | Width | Visible use |
|---|---|---|
| Zero | 32 bits | Selects iteration initially and controls predicate use after candidate processing. Exactly one has special treatment. |
| Four bytes | 32 bits | Supplies the predicate’s second argument when the post-processing first word is one. |

An iterative item is held in a local 32-bit word. On the predicate path, that word is also interpreted as an address representation:

| Location | Width | Visible use |
|---|---|---|
| Address represented by item word, plus four bytes | 32 bits | Supplies the predicate’s first argument. |

This is not evidence for a complete object layout. No other fields or minimum object sizes are established.

### Result

The result is represented as 64 bits. The following table separates its upper and lower 32-bit words.

| Exit condition | Upper word | Lower word |
|---|---|---|
| Initial position is minus one | No established initialized value | Zero |
| Initial position is not minus one and initial state word is not one | No established initialized value | Direct retrieval result |
| Iterative candidate is accepted because post-processing state is not one | Local item word at return | Same local item word |
| Predicate returns zero | Local item word after the predicate returns | Same local item word |
| Candidate processing returns nonzero | Local item word after candidate processing returns | Zero |
| A bound comparison stops iteration after at least one candidate | Local item word after the terminating bound query returns | Zero |
| First bound comparison stops iteration | No established initialized value | Zero |

On iterative paths, later dependencies may modify the local item word through an alias retained after candidate processing receives its address. Consequently, the upper word on exhaustion is not necessarily the last retrieval result, the rejected item word, or the value left by candidate processing.

“No established initialized value” does not mean zero, a stable sentinel, or a safely usable value. The supplied representation does not establish a defined whole-result value on those paths.

The intended public interpretation of the 64-bit representation remains unknown.

### Preconditions

Ordinary defined execution requires that dependencies accept their supplied arguments and that each memory access actually reached is valid.

In particular:

- If the initial position is not minus one, the current state pointer must permit a 32-bit read.
- After candidate processing returns zero, the possibly replaced state pointer must permit another 32-bit read.
- If that word is one, the second state word and the candidate-associated word must both be readable.
- Any dependency use of references to invocation-local storage must respect that storage’s lifetime.
- Addresses, alignment, and pointer operations must satisfy the target’s requirements.

The function does not visibly validate these conditions or establish a recovery result when they fail.

## Behavior

### Initial position and branch selection

The first dependency call is F-8fbbf5288d61, with the context word and original selection-state pointer. Its result is treated as a signed 32-bit position.

If the result is exactly minus one, the function proceeds directly to its zero-lower-word return. It performs no direct state read, bound query, item retrieval, or candidate processing.

Any other position, including other negative values, causes a 32-bit read through the current local state pointer. This read follows the initial-position call, so changes that call makes to the referenced state can affect branch selection.

If the word read is not one, F-6bbddce1b930 is called with the context word and initial position. Its 32-bit result becomes the lower result word. This direct path does not query a bound or invoke candidate processing or the predicate.

Only an initial state word equal to one selects iteration.

### Bound checks and retrieval

Every attempted iteration begins by calling F-10b760faca36 with the context word. The current position and the returned bound are compared as signed 32-bit values.

- If the position is strictly less than the bound, retrieval proceeds.
- Otherwise, iteration ends.

The bound is queried again for each attempt, including the final unsuccessful attempt on exhaustion. It is not cached.

There is no independent nonnegative-position check. A position below zero, other than the initial minus-one sentinel, can reach retrieval when it is less than the signed bound.

For an admitted position, F-6bbddce1b930 is called with the context word and current position. Its 32-bit result is assigned to the local item word. This assignment overwrites any previous value of that word, including a value changed during the preceding bound query.

### Candidate processing

After retrieval, F-ff4aeaa3fa12 receives:

- The address of the local item word.
- The address of the local selection-state pointer.

Both refer to writable invocation-local storage. The dependency can change either value. Subsequent behavior uses the resulting values, not necessarily those supplied by retrieval or the caller.

If candidate processing returns nonzero, iteration ends immediately. No post-processing state read or predicate call follows for that candidate. The lower result word is zero; the upper word is the item word after the processing call returns.

If candidate processing returns zero, the function reads the first word through the then-current state pointer.

### Acceptance without a predicate

If the post-processing state word is not one, the candidate is accepted immediately. The current local item word supplies both halves of the result.

This path does not read the candidate-associated word or the second state word and does not call F-ed04800b7b7b.

A zero item word can therefore be accepted without attempting a candidate-associated read at address four.

### Predicate evaluation

If the post-processing state word is one, two 32-bit values are obtained:

1. The word at the address represented by the current item word plus four bytes.
2. The word four bytes beyond the current state pointer.

F-ed04800b7b7b receives the candidate-associated value first and the state-associated value second. The supplied representation does not establish which of those two memory reads occurs first.

The candidate-address addition uses a 32-bit unsigned item word. Its integer result wraps modulo \(2^{32}\). This arithmetic fact does not establish that the resulting address is valid or readable. The separate state-pointer offset also requires a valid target pointer operation and readable storage.

If the predicate returns zero, the function accepts and returns the local item word as it stands **after the predicate returns**, duplicated into both result words. There is no second state check.

This distinction matters because the predicate might access a retained alias to the item word or local state pointer. Its explicit arguments are copied 32-bit values, but the caller provides no guarantee against additional alias-mediated effects.

If the predicate returns nonzero, the candidate is rejected. The position advances by one, and another bound query follows.

### Increment safety and termination

The position increment cannot overflow a signed 32-bit integer in this loop.

An increment is reached only after a successful signed comparison in which the position was strictly less than a signed 32-bit bound. Thus, before incrementing, the position is at most \(2^{31}-2\); afterward it is at most \(2^{31}-1\).

Under ordinary defined execution with dependencies that return, iteration is finite:

- Acceptance or nonzero candidate-processing status exits immediately.
- Every rejected candidate advances the position by one.
- No signed 32-bit bound can admit a candidate once the position reaches \(2^{31}-1\).

Changing bounds or selection-state contents alone cannot produce infinitely many loop iterations. A dependency that never returns is a separate source of nontermination, not an infinite loop in this function.

### Exhaustion and retained aliases

When a bound comparison stops iteration, the lower result word is zero.

If at least one candidate was processed, the upper result word is the local item word **after the terminating bound query returns**. Once candidate processing has received that word’s address, later dependencies are not established to preserve it. A predicate or later bound query could modify it through a retained alias.

If the first bound check fails, no visible assignment has initialized the local item word.

There is no separate visible exhaustion status. A zero lower word can also arise from the initial sentinel, nonzero processing status, direct retrieval of zero, or acceptance of a zero item word.

## Side effects

### Direct effects

The visible body:

- Maintains a local signed position.
- Maintains a local selection-state pointer.
- Assigns iterative retrieval results to a local item word.
- Exposes writable references to the item word and local pointer.
- Reads the state and conditional candidate-associated fields described above.
- Calls dependencies in the stated order.
- Constructs the 64-bit return representation.

It does not directly write the contents of caller-supplied state storage. It does not directly allocate, release, retain, or transfer ownership of an object.

### Dependency-mediated effects and ownership

No dependency is established to preserve globals, context contents, state storage, candidate objects, or previously exposed local storage.

In particular:

- The initial-position dependency receives the original state pointer and may affect reachable storage.
- Candidate processing may rewrite both local values passed by reference.
- Retained aliases may allow later calls to modify those local values.
- Predicate-side changes to the item word affect an accepted result.
- Changes made by the terminating bound query affect the upper word returned on exhaustion.

The absence of explicit allocation or release in this function establishes no overall ownership guarantee. Dependency ownership behavior is unknown.

The two exposed references designate invocation-local storage. Their lifetime is not guaranteed beyond the invocation. Whether dependencies retain them, and whether they use them only while valid, is not established.

### Errors and abnormal execution

Minus one is the only explicit initial-position sentinel. Its semantic meaning—absence, error, or another condition—is unknown.

There is no visible conversion of invalid memory access, invalid pointer replacement, ownership violation, or dependency failure into a defined error result.

A dependency that does not return prevents this function from completing. This is distinct from the finite iteration behavior described above.

## Acceptance examples

These are conditional consequences of static control flow, not execution results.

1. **Initial sentinel.** If F-8fbbf5288d61 returns minus one, no direct state read or further dependency call follows. The lower result word is zero; the upper word is unestablished.

2. **Direct retrieval.** If the initial position is seven and the subsequent state read yields two, retrieval occurs at position seven without a bound query. A retrieval result of `0x12345678` becomes the lower word. The upper word is unestablished.

3. **Initially exhausted range.** If the position is four, the initial state is one, and the first bound is four, no candidate is retrieved. The lower word is zero; the upper word is unestablished.

4. **Processing replaces both decision inputs.** Suppose processing writes `0x11223344` into the item word, replaces the local state pointer, and returns zero. If the replacement state’s first word is zero, the result is `0x1122334411223344`, without a predicate call.

5. **Processing stops iteration.** If processing leaves the item word as `0x55667788` and returns nonzero, the result is `0x5566778800000000`. No state read follows that call.

6. **Rejection followed by exhaustion without alias writes.** Suppose the item word is `0x12345678`, processing returns zero, the current state is one, and the predicate rejects. Explicitly assume that processing, the predicate, and the next bound query leave that item value unchanged. If the next bound check stops iteration, the result is `0x1234567800000000`.

7. **Exhaustion with an alias write.** Suppose a rejected candidate leaves `0x12345678` in the item word, but the terminating bound query changes it through a retained alias to `0x89ABCDEF`. The result is `0x89ABCDEF00000000`.

8. **Acceptance uses the post-predicate item.** Suppose the predicate’s arguments have been read, then the predicate changes the item word through a retained alias to `0xAABBCCDD` and returns zero. The result is `0xAABBCCDDAABBCCDD`.

9. **Zero accepted without a candidate-associated read.** If processing returns zero with a zero item word and a current state word other than one, acceptance produces an all-zero result without reading address four.

10. **Signed boundary.** A position of \(2^{31}-2\) can pass a bound of \(2^{31}-1\). Rejection advances it safely to \(2^{31}-1\). The next bound query cannot admit another candidate, regardless of the signed bound it returns.
