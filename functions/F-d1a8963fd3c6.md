# F-d1a8963fd3c6

## Purpose

F-d1a8963fd3c6 performs a stateful byte-return operation on a caller-supplied record. Depending on flags, counts, and dependency results, it consumes a byte at the current cursor, returns an embedded byte, prepares a destination for data acquisition, or returns one of two distinguished 32-bit values.

Buffering and resource-positioning terminology expresses inferred intent. The visible body does not establish that `0xFFFFFFFF` means end-of-input, that `0xFFFFFFFE` means an error, or that an address-producing dependency allocates owned storage.

This contract describes static evidence. No runtime tests have been performed.

## Interface

### Input record

The sole explicit input is a writable record address. Visible accesses require storage through byte offset `0x33`, inclusive.

| Byte offset | Access width | Descriptive field |
|---|---:|---|
| `0x00` | 32 bits | Count |
| `0x04` | 32 bits | Cursor |
| `0x08` | 32 bits | Auxiliary count |
| `0x0C` | 32 bits | Flags |
| `0x10` | 32 bits | Buffer-base |
| `0x14` | 32 bits | Resource argument |
| `0x18` | 32 bits | Position |
| `0x1C` | 32 bits | Capacity |
| `0x25` | 8 bits | Embedded byte |
| `0x2C` | 32 bits | Buffer-end |
| `0x30` | 32 bits | Saved-capacity |

Pointer-bearing fields contain 32-bit addresses. Resource argument is a 32-bit dependency argument whose external interpretation is unknown.

No visible null, alignment, bounds, capacity, or address-validity checks protect accesses. Every executed record access and byte dereference must be valid. Dependencies may require additional preconditions.

The record and byte storage need not be disjoint according to any visible check. Returned bytes are read after preceding record mutations. Consequently, a byte that aliases a written record field can change before its final read.

### Result

The result is an unsigned 32-bit value:

- `0x00000000` through `0x000000FF`: a zero-extended byte;
- `0xFFFFFFFE`: a flag-dependent distinguished outcome;
- `0xFFFFFFFF`: an outcome reached through several different failure-like or exhausted paths.

Returning byte value zero is distinct from receiving a zero data-acquisition result.

### Configuration and arithmetic

Five global 32-bit configuration values are used: an availability mask, availability match, auxiliary-mode mask, read-mode mask, and fallback mask. Their concrete values are unavailable.

Maximum-address selection uses unsigned comparisons. Working counts, positioning results, and relevant capacity differences use signed 32-bit comparisons. Acquisition completion distinguishes zero from nonzero, not positive from negative.

Calculations use 32-bit operands or addresses. No overflow checks are visible. Original-language behavior for overflowing signed arithmetic and out-of-range pointer arithmetic remains **documented_only**. The formulas below describe the supplied representation; they do not establish unbounded arithmetic or universally valid wrapping pointer operations.

## Behavior

### Entry and initial working count

The function reads the availability mask, availability match, and entry Flags, then writes Flags with `0x00400000` set. **Entry flags** below always means the retained original Flags value.

If entry flag `0x01000000` is clear, the initial working count is read from Count. A positive Count on this path does not immediately consume a byte.

If that entry flag is set, an availability calculation supplies the working count:

- The entry flags, with `0x00400000` added, must satisfy the captured availability mask and match. Otherwise the result is zero.
- If entry flag `0x00001000` is set, an initial unsigned maximum comparison between Cursor and Buffer-end can finish the calculation with zero when that maximum is no greater than Cursor.
- Otherwise, including when that initial comparison does not finish the calculation, the result is Cursor minus the unsigned maximum of Cursor and Buffer-end, using the field reads made for that calculation.

Only on this entry-flag-set path does a positive signed working count cause immediate byte consumption. Ordinary non-wrapping address differences are nonpositive, but the positive-result branch is present.

**Byte consumption** retains Cursor, writes Cursor advanced by one byte, then reads and returns the byte at the retained address. It does not itself decrement Count. The cursor write occurs before the byte read, including when the byte aliases the record.

### Embedded-byte completion

If immediate consumption did not occur and entry flag `0x00080000` is set, no dependency is called.

Flags are first written from entry flags with `0x00080000` cleared and `0x00400000` set.

When entry flag `0x01000000` is clear:

1. Count receives the availability calculation described above, evaluated using these constructed flags and the captured availability configuration.
2. The auxiliary-mode mask is consulted. Unless the constructed flags masked by it equal `0x00400002`, Auxiliary count becomes zero.
3. If that comparison succeeds, the ordinary auxiliary value is Cursor minus Buffer-base minus Saved-capacity. When both entry flags `0x00002000` and `0x00010000` are set, and signed Saved-capacity is no greater than Cursor minus Buffer-base, the value is instead Saved-capacity minus that offset.

When entry flag `0x01000000` is set, both count updates are skipped.

Finally, Flags are reconstructed from entry flags: clear `0x00080000`, set `0x00600000`, and preserve the other entry bits. The embedded byte at offset `0x25` is then read and returned. Cursor is not advanced.

### Ordinary mode selection

Without entry flag `0x00080000`, Flags are written from entry flags with `0x00200000` cleared and `0x00400000` set.

If entry flag `0x00000020` is set, F-69a489b3ae68 receives the record. Its result is ignored; its state effects are not constrained.

The function then reads the fallback mask, captures current Flags, and compares those flags masked by the read-mode mask against `1`.

If the comparison fails:

- Count is set to zero if captured flag `0x01000000` is clear.
- If the captured flags select no bit in the fallback mask, F-b66fa5cebc4a receives the record, followed by return of `0xFFFFFFFF`.
- Otherwise, Flags are written from the captured value with `0x00005000` cleared and `0x00000040` set. Auxiliary count becomes Cursor minus Buffer-base minus Saved-capacity, and the result is `0xFFFFFFFF`.

There is no further direct record write after the failure dependency returns.

### Address acquisition and negative working counts

After successful mode selection, Buffer-base is read. If it is zero and the flags captured for mode selection have `0x00010000` clear, F-d33f6d597e5d receives Capacity.

Its result is 64 bits. The low 32 bits are written first to Buffer-base and then to Cursor. The high 32 bits are extracted but have no established subsequent observable use.

Current Flags are then read and written with `0x00000800` set. If neither bit in `0x00000300` was present in that read, a further Flags write also sets `0x00000100`. A zero or unusable returned address is not visibly rejected.

If the initial working count is negative, the function takes a consumption path rather than acquiring data:

- Current flag `0x01000000`, evaluated here after any preceding dependencies, determines whether Count is written.
- If that flag is clear, a fresh Count read is transformed into the negative of that value plus one, with the negation applying to the entire sum. Thus a fresh value of `−3` produces `2`.
- If the flag is set, Count is not directly written on this path.
- Current Flags have `0x00001000` set, Auxiliary count becomes zero, and byte consumption follows.

The retained working count selects this branch; it need not equal the fresh Count used in the transformation. Entry flag `0x01000000` being clear does not guarantee that the later transformation occurs.

### Resource transition

For a nonnegative working count, current Flags and Resource argument are captured.

If captured flag `0x00000010` is set:

- With captured flag `0x00010000` clear, captured flag `0x00040000` first causes F-965c979b2a9c to receive the captured resource argument. Afterward, that bit is cleared in current Flags.
- F-e1c0335c1ea5 then receives the captured resource argument and current Cursor minus current Buffer-base plus current Position.
- A negative signed result causes F-b66fa5cebc4a to receive the record, followed by return of `0xFFFFFFFF`.
- With captured flag `0x00010000` set instead, F-21a58352eb84 receives the record.

Flags are subsequently reread for destination selection. A dependency can therefore change which destination branch follows.

### Destination and requested amount

**Current flag `0x00010000` clear**

The destination is retained from Buffer-base, and the requested amount is retained from Capacity. Position is increased by Cursor minus the retained base. Buffer-end is written to that base, then Cursor is written to the same base.

**Current flag `0x00010000` set**

A used extent is calculated as the unsigned maximum of Buffer-end and Cursor, minus Buffer-base. Remaining capacity is Capacity minus that extent.

If remaining capacity is zero, F-21a58352eb84 receives the record. Capacity is then reread and retained as the requested amount.

If remaining capacity is nonzero, it remains the retained requested amount, even when negative:

- Position is saved, F-21a58352eb84 receives the record, and the saved Position is restored.
- If current flag `0x00040000` is set, F-965c979b2a9c receives the previously captured resource argument. That bit is then cleared in current Flags.
- F-e1c0335c1ea5 receives the captured resource argument and current Position plus the retained used extent.
- A negative result invokes F-b66fa5cebc4a and returns `0xFFFFFFFF`.
- Otherwise, current Flags have `0x00020000` set. If the flags read for this update contained `0x00800000`, Position is increased by the retained used extent.

In both remaining-capacity cases, the destination is subsequently calculated as:

**current Buffer-base + (current Capacity − retained requested amount)**

These Buffer-base and Capacity reads occur after the applicable dependencies. In the nonzero case, dependency changes to Capacity do not replace the retained requested amount. In the zero case, that amount specifically comes from the Capacity reread after F-21a58352eb84.

### Refill preparation and distinguished result

With destination and requested amount retained, Flags are read and written with `0x00000010` cleared.

If either bit in `0x00000600` was present in that pre-clear value, F-03f8150bcc7b receives the record.

Flags are then reread. This reread controls all of the following:

- Flags are written with `0x00001000` set.
- Auxiliary count becomes zero if `0x01000000` was clear.
- If `0x00800000` was set, Buffer-end is written from current Buffer-base, Cursor is written from another Buffer-base read, and the result is `0xFFFFFFFE`.

No data-acquisition call occurs on that distinguished path. Presence of `0x00800000` before F-03f8150bcc7b is insufficient if the dependency clears it.

### Data acquisition and completion

Otherwise, F-b4ea9751e416 receives the retained destination, retained 32-bit requested amount, and record.

After its signed 32-bit result is returned:

1. Buffer-end is written as retained destination plus that result.
2. Current Capacity is read and copied to Saved-capacity.
3. Zero and nonzero completion diverge.

**Nonzero result, including a negative result**

If current flag `0x01000000` is clear, Count becomes result minus one. Cursor becomes retained destination plus one. Current Flags have `0x00020000` set. Only then is the byte at the retained destination read and returned.

There is no positive-result check or visible validation that the byte remains readable. Any record writes that alias the destination affect the byte ultimately returned.

**Zero result**

Flags are captured, then written with `0x00001000` cleared and `0x00000040` set. If captured flag `0x01000000` is clear, Count becomes zero. Cursor is written to the retained destination.

The captured flags then determine completion:

- With `0x01000000` set, return `0xFFFFFFFF` without another direct count update.
- Otherwise, with either bit in `0x00000600` set, zero Auxiliary count and return `0xFFFFFFFF`.
- Otherwise, write Auxiliary count as retained destination minus current Buffer-base minus the Capacity snapshot previously copied to Saved-capacity, then return `0xFFFFFFFF`.

The last subtraction uses the retained Capacity snapshot, not a fresh Saved-capacity read.

## Side effects

Record mutations begin before most decisions and are not rolled back on failure. They include flag changes, cursor advancement or reset, buffer-address replacement, count changes, Position accumulation or explicit restoration, and capacity snapshotting.

Observable ordering includes:

- Cursor advancement before a consumed-byte read.
- Final Flags replacement before the embedded-byte read.
- Buffer-end and Saved-capacity writes before acquisition completion.
- Optional Count, Cursor, and Flags updates before the acquired-byte read.
- Failure-dependency calls followed by return without another direct record write.

Dependencies may change the record, globals, addressed memory, or external resources. Retained arguments survive as described; other state must not be assumed preserved. Only the specified Position restoration explicitly undoes a dependency’s change to that field.

No direct release is visible. Ownership, lifetime, synchronization, and reentrancy guarantees are not established.

## Acceptance examples

These are conditional static examples, not executed tests. All accessed storage must be valid, arithmetic must remain within its established domain, and the stated configuration and dependency conditions must hold.

1. **Embedded byte with preserved counts.** Entry flags contain `0x00080000` and `0x01000000`; the availability calculation does not produce a positive count. The embedded byte is `0xA7`. The result is `0x000000A7`. Count and Auxiliary count are untouched; final Flags clear `0x00080000` and set `0x00600000`. No dependency is called.

2. **Negative-count consumption with a current-state condition.** Entry flags exclude `0x01000000` and `0x00080000`, and initial Count is `−3`. Mode selection succeeds without address acquisition. At the later transformation check, current flag `0x01000000` remains clear and the fresh Count read is still `−3`. Cursor addresses a byte `0xE2` in storage disjoint from the record, unchanged through the final byte read. Count becomes `2`, Auxiliary count becomes zero, `0x1000` is set, Cursor advances, and `0xE2` is returned without data acquisition. If F-69a489b3ae68 instead sets `0x01000000` while preserving Count and Cursor and permitting mode selection, the negative branch still runs, but its Count transformation is skipped.

3. **Destination with retained nonzero remainder.** The flag-set destination branch starts with Buffer-base `0x1000`, maximum cursor/end address `0x1020`, and Capacity `0x80`. Used extent is `0x20`; retained requested amount is `0x60`. If transition dependencies leave Buffer-base `0x2000` and Capacity `0x100`, and positioning succeeds, destination is `0x20A0`: the new base plus `0x100 − 0x60`.

4. **Destination after zero remainder.** Used extent and Capacity are both `0x80`. F-21a58352eb84 leaves Buffer-base `0x3000` and Capacity `0x40`. Requested amount is reread as `0x40`; destination is `0x3000`.

5. **Nonzero acquisition without alias interference.** F-b4ea9751e416 receives destination B, returns `3`, and leaves byte `0x7C` at B. B addresses storage disjoint from the record, and that byte remains unchanged through completion. If post-call flag `0x01000000` is clear, completion writes Buffer-end as B plus three, snapshots Capacity into Saved-capacity, writes Count `2` and Cursor as B plus one, sets `0x20000`, then returns `0x7C`. Without the disjointness or unchanged-byte condition, the dependency’s initial byte value alone does not establish the return value.

6. **Zero acquisition with auxiliary reset.** Acquisition returns zero; completion captures flags excluding `0x01000000` but including `0x200`. Completion clears `0x1000`, sets `0x40`, zeroes Count and Auxiliary count, writes Cursor to the destination, and returns `0xFFFFFFFF`.

7. **Distinguished result controlled by reread flags.** Flags reread after any F-03f8150bcc7b call contain `0x00800000`. The function sets `0x1000`, resets Buffer-end and Cursor from Buffer-base, and returns `0xFFFFFFFE` without acquisition. If that dependency clears the bit, its earlier presence does not prevent acquisition.

8. **Positioning failure.** An executed F-e1c0335c1ea5 returns a negative signed result. F-b66fa5cebc4a receives the record, followed by return of `0xFFFFFFFF`. Earlier mutations remain unless that dependency changes them.
