# F-87bf9031895e

## Purpose

F-87bf9031895e conditionally invokes F-ad023a375886 with two positions in a 16-bit-element buffer and a computed byte quantity, then reduces the buffer’s leading 16-bit value.

The arithmetic suggests removal of a span from a length-prefixed sequence, potentially including relocation of a trailing element. That is **inferred intent**, not an established description of the dependency. The available evidence does not establish which pointer the dependency treats as a source or destination, whether it copies data, or how it handles overlapping regions.

The established behavior is narrower: two early-return conditions, one dependency invocation on the remaining path, and one leading-value update after that invocation returns normally.

## Interface

The function has three inputs and no return value:

| Input | Interpretation established by the supplied representation |
|---|---|
| Buffer pointer | Pointer to 16-bit unsigned elements. A null pointer is explicitly accepted. The element at offset zero is used as a numeric field. |
| Position | Signed integer used as an element displacement and in unsigned quantity arithmetic. |
| Amount | Signed integer used as an additional element displacement, in unsigned quantity arithmetic, and through a signed 16-bit conversion during the final update. |

For the descriptions below:

- **P** denotes the buffer pointer.
- **A** denotes the position.
- **B** denotes the amount.
- **H** denotes a value read from the leading element.

These are contract notation, not source identifiers.

The arithmetic description uses the represented 16-bit element and 32-bit integer model:

- A leading-element read produces a value from 0 through 65,535.
- Unsigned quantity calculations wrap modulo \(2^{32}\).
- A stored leading-element result is reduced modulo \(2^{16}\).
- Pointer displacements are measured in 16-bit elements, not bytes.

The supplied representation does not independently establish the pointer width or the complete target ABI. Conversion of an out-of-range signed integer to signed 16-bit form also requires a target-specific rule, discussed under **Uncertainties**.

### Storage and validity preconditions

A null P requires no accessible buffer storage.

For a non-null P, the leading element must be readable whenever execution reaches a leading-element read. If the dependency returns normally, that element must subsequently be readable and writable.

On the dependency path, both displaced pointers must be valid to form under the applicable execution model. Any additional storage requirements come from F-ad023a375886 and are not available here.

A leading value is not evidence that an allocation is large enough. This function performs no allocation-size check and no general validation of A or B.

## Behavior

### 1. Null-pointer return

If P is null, the function returns immediately.

This path:

- Does not read the leading element.
- Does not invoke F-ad023a375886.
- Does not update buffer storage.
- Does not use A or B to form displaced pointers.

There is no return status distinguishing this case from other returns.

### 2. Conditional early return

For non-null P, the next condition depends on whether A equals zero.

If A is nonzero, this condition does not read the leading element and cannot cause an early return.

If A is zero, the function reads the leading element and compares it, as an unsigned value, against:

\[
T=(B-1)\bmod 2^{32}.
\]

If the leading value is strictly less than T, the function returns immediately.

On this return path, the function itself performs no buffer write and makes no dependency call.

The threshold is unsigned. In particular:

- B equal to zero produces a threshold of 4,294,967,295. Every possible 16-bit leading value is below it, so the function returns.
- B equal to one produces a threshold of zero. No leading value is below it, so this condition permits the dependency path.
- For B from one through 65,536, the condition permits the dependency path exactly when the leading value is at least \(B-1\).
- Negative signed 32-bit values of B produce thresholds greater than every possible leading value, so they cause this early return when A is zero.
- Positive values of B greater than 65,536 likewise cause this early return when A is zero.

The guard is not a general range check. It is entirely bypassed for nonzero A.

### 3. Dependency arguments

If neither early return applies, the function prepares one invocation of F-ad023a375886.

Its arguments, in order, are:

1. The pointer obtained by advancing P by A elements and then by B elements.
2. The pointer obtained by advancing P by A elements.
3. A 32-bit unsigned quantity Q computed from a leading-element read:

\[
Q=2(H-A-B+1)\bmod 2^{32}.
\]

For Q, both signed inputs participate in unsigned 32-bit arithmetic. Negative values therefore do not remain negative quantities in that calculation; they contribute their values modulo \(2^{32}\).

The final multiplication by two also wraps modulo \(2^{32}\). Q is consequently always even, but it need not be small or proportionate to the available allocation.

The two pointer arguments are displaced by elements. Q is a separate numeric argument whose multiplication by two is consistent with a byte quantity for 16-bit elements. Its exact interpretation by the dependency remains unknown.

#### Distinct pointer and quantity arithmetic

Unsigned wrapping in Q does not make invalid pointer arithmetic valid.

The first pointer is formed by two successive pointer displacements. The evidence does not establish that arbitrary signed inputs can be combined into a valid final pointer, nor that an invalid intermediate displacement is harmless.

The function supplies no bounds information to validate either pointer.

#### Reads before the call

When A is zero and the guard permits continuation, there are two source-level uses that read the leading element before the dependency:

- The guard read.
- The read used to compute Q.

When A is nonzero, there is no guard read; the pre-call leading-element read is the one used for Q.

The function performs no intervening write of its own. For ordinary stable storage, these pre-call reads therefore observe the same value. The contract does not introduce support for concurrent unsynchronized changes or special memory semantics.

The evaluation order among the call’s argument expressions is not established. All arguments are evaluated before the dependency begins, and the function itself makes no buffer write while preparing them.

### 4. Dependency invocation

The function invokes F-ad023a375886 exactly once on this path, including when Q is zero.

A zero quantity does not bypass the call. It also does not establish that the dependency performs no access or side effect.

No dependency result is used to choose a later branch or to determine whether the leading-element update should occur.

If the dependency fails to return normally, the supplied function establishes no later update or recovery behavior.

### 5. Leading-element update

After F-ad023a375886 returns normally, the function reads the leading element again.

This is a post-call read. The calculation does not necessarily use the value that supplied Q or the earlier guard value.

The update consists of:

1. Converting B to a signed 16-bit value.
2. Subtracting that converted value from the post-call leading value.
3. Storing the result in the unsigned 16-bit leading element.

Let R be the post-call leading value and S be the signed 16-bit conversion of B. The stored value is:

\[
(R-S)\bmod 2^{16}.
\]

For B in the range −32,768 through 32,767, S equals B exactly. Within that range, the promoted subtraction cannot overflow a signed 32-bit integer: its result lies between −32,767 and 98,303.

Outside that range, S depends on the target’s signed-narrowing rule. A low-16-bit, two’s-complement interpretation would make the stored result congruent to \(R-B\) modulo \(2^{16}\), but that narrowing rule is not independently established here.

There is no check preventing the leading field from wrapping, and no special treatment of a zero quantity. After the store, the function returns without a status value.
