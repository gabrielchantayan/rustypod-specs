# F-846c856c19bd

## Purpose

F-846c856c19bd describes a partially recovered, call-heavy operation that reads and writes externally addressed memory, derives addresses from dependency results and incoming machine state, and repeatedly updates byte and 32-bit fields.

**Established static evidence:** the supplied representation contains a single linear sequence of explicit operations, numerous unresolved calls, and a terminal bad-instruction marker. It does not establish a successful return.

**Inferred intent:** several offsets and scaling operations resemble indexed records or packed references. That interpretation is not sufficient to assign record types, ownership, application meaning, or valid address ranges.

This contract specifies the visible sequence conditionally: each later event requires earlier calls and memory accesses to complete. It does not assert that the entire sequence is executable or that the recovered function boundary is correct.

## Side effects

Explicit stores are either one byte or four bytes. Four-byte stores preserve the designated 32-bit bit pattern; byte stores retain only the low eight bits.

Several explicit stores target absolute or small numerical addresses:

- Absolute `0x11` and `0x0d`.
- Byte-selected destinations from `0x11` through `0x110`.
- A destination from `7` through `1030`, because small index ranges from 0 through 1023.
- Addresses derived from twice an unsigned byte.

These accesses must not be silently interpreted as safe object-relative fields. Whether they designate ordinary memory, special mapped storage, or artifacts of incorrect recovery is unknown.

Aliasing is unrestricted by the evidence. An explicit write can overlap another field, a subsequent read, or storage used by a dependency. Calls can also mutate memory between repeated reads.

No allocation, release, ownership transfer, lock operation, or resource lifetime is explicitly established. Dependencies may perform such operations; their effects are unknown.

If an access or dependency fails, only the preceding completed prefix is supported. There is no visible transaction or compensating action.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Initial argument order.** If the initial context word is `0x12345678`, the first explicit byte store writes `0x78`. F-U01a receives `0x12345678`, input two, input three, input one.

2. **Packed-width truncation.** If packed input is `0xffffffff`, packed slice is `0x3ff`. F-U03b receives `0x3fe00000` in both shifted argument positions. The subsequent packed-slice store writes `0xff800000` under 32-bit truncation.

3. **Masking does not retroactively change a store.** If record index is `0xc0000001`, record token is `4`, while masked record is `1`. The earlier record-index-derived store uses the original index expression; later masked-record consumers receive `1`.

4. **Fresh reads can select different destinations.** If the two reads at next record address + `1` observe 5 and 9, stage 8 writes at `0x16`, while stage 9 clears `0x1a`. The second read must not reuse 5.

5. **Byte-selected clearing is not word-sized.** If a selector byte is `0xff`, the selected clear destination is `0x110`, and the explicit clear affects one byte only.

6. **64-bit half distinction.** If F-U05g presents `0x1122334455667788`, the word written at layout-eight + `0x34` is `0x11223344`; F-U05h receives `0x5599de20`.

7. **Repeated terminal clears remain separate.** If intervening dependencies change the final selector byte, the two clears in stage 14 can target different addresses. Both reads and both writes remain required.

8. **Failure does not imply rollback.** If an initial context byte store completes and F-U01a then fails, the supplied evidence provides no restoration of that byte and no guaranteed later event.
