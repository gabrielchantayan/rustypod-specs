# F-f4a84f390a23

## Purpose

F-f4a84f390a23 transfers eighteen consecutive 32-bit words from a caller-selected source address to a destination address obtained from one global location. The resulting transfer spans 72 bytes.

The transfer is an ordered sequence of individual word reads and writes, not an established snapshot operation. Each source word is read immediately before its corresponding destination word is written. Consequently, overlapping source and destination ranges can change values read later in the same invocation.

The first argument is unused by the supplied static representation. The function has no explicit return value, validation path, allocation, or dependency call.

These statements describe the supplied static evidence. They do not establish runtime validity of any address or a higher-level purpose for the transferred data.

## Behavior

### Destination selection

Before transferring any word, the function reads the destination-address global and retains that value for subsequent address calculations.

This ordering matters if the destination range overlaps the global location itself. Such a write may change global state visible to later invocations, but it does not change the destination base already captured for this invocation.

### Transfer extent and layout

The effective word positions are 0 through 17, inclusive. Each position occupies four bytes. The corresponding source and destination byte offsets are:

0, 4, 8, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 64, and 68.

The last access begins at offset 68 and covers four bytes. Thus, each range spans offsets 0 through 71 relative to its base.

### Access order

For each word position in ascending order, the function:

1. Reads the 32-bit value at that position in the source range.
2. Writes that value to the corresponding position in the destination range.
3. Proceeds to the next position.

All eighteen positions are processed on the normal path. There is no data-dependent early exit and no comparison of source values.

Only the current word is visibly retained before its corresponding write. The function does not visibly read the complete source range before modifying the destination.

This is the access order established by the supplied representation. It does not establish hardware memory barriers, externally observable transaction boundaries, or atomicity with respect to other execution agents.

### Value treatment

The supplied evidence does not specify byte order. It establishes matching-width word reads and writes without an explicit conversion.

### Arithmetic boundaries

### Overlap

Overlap is not detected.

If source and destination are identical, each word is read and then written back to the same address. The accesses still occur; no identity-based shortcut is visible.

If the destination begins one word after the source, the first destination write overwrites the next source word before that word is read. With ordinary memory and no outside changes, the first source word consequently propagates through all eighteen destination positions.

If the destination begins one word before the source, each destination write affects a word below the next unread source position. Under those same conditions, the eighteen original source values are transferred without this forward-propagation effect.

Partial-word overlap is not separately handled. Its exact consequences depend on address validity, alignment support, byte order, and the memory model. The evidence is insufficient to specify those consequences portably.
