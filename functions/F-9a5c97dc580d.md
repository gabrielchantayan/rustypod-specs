# F-9a5c97dc580d

## Purpose

F-9a5c97dc580d conditionally invokes one of two dependencies using a value obtained through a context pointer chain. A nonzero dependency result is returned unchanged. Otherwise, the function optionally invokes an indirect operation on the supplied object and returns zero.

The function also supports selection of a default target when the caller supplies a zero target value. Context traversal occurs before that default selection, even when the selected target will ultimately be zero.

This contract describes statically established behavior. Names such as “object,” “context,” and “target” distinguish roles; they do not establish domain meaning, ownership, or type identity.

## Interface

### Inputs

The interface has five positional inputs:

| Position | Contract name | Representation and observed use |
|---|---|---|
| 1 | Object | A pointer, possibly zero, to storage whose first word supplies an indirect-operation table address. Also placed in a temporary record passed to one dependency. |
| 2 | Context | A 32-bit address-bearing value used for an unconditional three-read pointer traversal. Also placed in that temporary record. |
| 3 | Selector | A 32-bit integer tested only for equality with zero. Zero selects F-fc918c3355aa; every nonzero value selects F-8801c242b41b when invocation is otherwise eligible. |
| 4 | Target | A 32-bit value. Zero requests default-target selection. A nonzero value is used without default selection. |
| 5 | Auxiliary word | An opaque 32-bit value explicitly supplied only to F-fc918c3355aa. |

The supplied representation uses 32-bit integer and pointer-bearing words. This is a contract for that represented environment, not a portable native-pointer interface for arbitrary architectures.

No arithmetic interpretation of the target, extracted context value, or auxiliary word is established beyond the operations described below. In particular, a negative 32-bit target is nonzero and does not request default selection.

### Output

The function returns a 32-bit integer:

- A nonzero result from the selected invocation dependency is returned unchanged.
- Every path that completes normally without such a result returns zero.
- The result of the optional indirect object operation does not determine the returned value.

There is no separately established status field, exception translation, error object, or output buffer.

### Preconditions

Normal completion requires valid storage for every memory access actually reached.

The context pointer chain must be readable on every invocation. A zero object, a zero target, or a context-derived zero value does not remove that requirement.

If default-target selection is reached, F-3fdd14ecd250 must return a value from which a 32-bit word at byte offset 28 can be read. There is no intervening zero check on that returned value.

If the indirect object operation is reached with a nonzero object, the object’s first word must identify readable table storage, and the table entry at byte offset 4 must identify a callable operation compatible with receiving the object pointer.

Dependencies may impose further requirements not visible here. The function does not validate these requirements or provide a defined recovery path for violations.

## Behavior

### 1. Extract the context-derived value

Before testing the target or selector, the function performs this sequence of 32-bit reads:

1. Read an address-bearing word at byte offset 16 from the context.
2. Read another address-bearing word at byte offset 12 from the address obtained by the first read.
3. Read the context-derived value at byte offset 28 from the address obtained by the second read.

These are dependent reads, not a single flattened offset into the original context. No intermediate address is checked for zero.

The resulting value is retained for the later invocation decision and, in one branch, supplied as an argument. It is not explicitly reread after default-target selection.

The offsets are byte offsets. The pointer arithmetic’s behavior for invalid or wrapping addresses is not established as a supported input case.

### 2. Select the target

If the supplied target is nonzero, default-target selection is skipped.

If the supplied target is zero:

1. Invoke F-3fdd14ecd250 with no explicit arguments.
2. Read a 32-bit target value at byte offset 28 from its returned value.
3. If that target value is zero, proceed directly to the optional indirect object operation and then return zero.

Default selection occurs even when the previously extracted context-derived value is zero. Consequently, a zero context-derived value does not suppress F-3fdd14ecd250 or the subsequent read from its result.

There is no repeated lookup, retry, or second default if the selected target remains zero.

### 3. Decide whether to invoke a dependency

Dependency invocation requires both:

- A nonzero selected target.
- A nonzero context-derived value.

If either requirement fails, neither F-fc918c3355aa nor F-8801c242b41b is invoked. The function proceeds to the optional indirect object operation.

When both requirements hold, the function prepares temporary automatic storage with this visible layout:

| Byte offset | Width | Established content |
|---|---:|---|
| 0 | 32 bits | A value loaded from a fixed data location. |
| 4 | 32 bits | No initialization shown. |
| 8 | 32 bits | No initialization shown. |
| 12 | 32 bits | The context input. |
| 16 | 32 bits | The object input. |

The visible storage spans five consecutive 32-bit words. The source establishes these offsets and writes, but not the semantic type of the complete record.

The words at offsets 4 and 8 must not be treated as zero, reserved values, or valid initialized fields. No initialization of them is shown.

The visible record writes occur in this order: the word at offset 0, the context at offset 12, and the object at offset 16.

### 4. Invoke according to the selector

For a zero selector, the function invokes F-fc918c3355aa with four explicit arguments, in this order:

1. The selected target.
2. The previously extracted context-derived value.
3. The address of the temporary record.
4. The auxiliary word.

For a nonzero selector, the function invokes F-8801c242b41b with no explicit arguments in the supplied representation.

The temporary storage is prepared before either branch. However, no explicit record pointer, target, context-derived value, or auxiliary word is shown as an argument to F-8801c242b41b. An undocumented implicit convention must not be substituted for that missing evidence.

The selected dependency’s result is tested for equality with zero:

- A nonzero result causes an immediate return of that exact result.
- A zero result proceeds to the optional indirect object operation.

This distinction includes all 32-bit nonzero results, not merely positive values.

### 5. Perform the optional indirect object operation

This step is reached when:

- Default selection produces a zero target;
- The context-derived value is zero; or
- The selected invocation dependency returns zero.

If the object input is zero, no object access occurs at this step, and the function returns zero.

If the object input is nonzero, the function:

1. Reads the first 32-bit word of the object as a table address.
2. Reads the callable entry at byte offset 4 from that table.
3. Invokes that entry with the object pointer as its explicit argument.
4. Returns zero if the indirect operation returns normally.

The object and table reads occur at this late stage. They are not performed before the earlier dependencies. Any relevant memory changes caused by those dependencies can therefore affect the eventual indirect dispatch.

No fallback is shown for an invalid table or a zero callable entry.

## Side effects

### Directly established effects

The function performs:

- The unconditional context-chain reads.
- Conditional default-selection and invocation calls.
- Temporary-record writes when invocation is eligible.
- Conditional object-table reads and an indirect call.
- No explicit write to caller-owned object or context storage.
- No explicit heap allocation or deallocation.

Dependency calls and the indirect operation can have additional side effects. Their absence from this function’s visible body does not establish their absence at runtime.

### Ownership and lifetime

The temporary record resides in automatic storage associated with this invocation. Its lifetime is not established beyond the active function call.

For F-fc918c3355aa, the record address is explicitly made available during the dependency call. Whether that dependency retains the address, accesses all five words, or invokes anything identified by the first word is unknown.

The indirect object operation resembles a terminal or cleanup-like action because it occurs on zero-result paths and is skipped on immediate nonzero returns. That is inferred intent only. The evidence does not establish that it releases memory, decrements a reference count, transfers ownership, or destroys the object.

Likewise, a nonzero dependency result does not by itself prove that ownership of the object or any other value has transferred.

### Failure and interruption

No local error handling is shown for invalid addresses, failed indirect dispatch, dependency exceptions, nonlocal exits, or nonreturning calls.

If an earlier read or call does not complete normally, later steps are not established to occur. In particular, the indirect object operation is not guaranteed cleanup after an abnormal dependency exit.
