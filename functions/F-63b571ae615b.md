# F-63b571ae615b

## Purpose

F-63b571ae615b operates on a caller-supplied object address. Its established behavior is an ordered sequence of dependency invocations and conditional memory reads:

1. Pass the address of an embedded field to an unconditional dependency.
2. Read a marker byte and, if it is an asterisk, invoke two dependencies in order.
3. Load a pointer from the embedded field.
4. If that pointer is non-null, read its first integer-sized word.
5. If that word is nonzero, read an indirect target from separate fixed global storage and invoke that target.

The indirect-target read is conditional and late. The function uses the target present in the global storage after the preceding dependencies and the pointee read, not a target cached before those operations.

This is an operational contract. The supplied representation does not establish cleanup, destruction, notification, or any other application-level purpose. All subsequent behavior is conditional on earlier operations completing and invoked dependencies returning control.

## Behavior

### Initial embedded-field operation

The function first invokes **F-338d16f9ce72**, supplying the address at object base plus `0xFC`.

The argument is the field’s address, not the pointer value stored there. The local body does not first load the field’s contents or read the marker.

This distinction permits the dependency to inspect or modify the field before its contents are loaded later. Whether it actually does so is unknown.

### Marker-dependent sequence

After F-338d16f9ce72 returns, the function reads one byte at object offset `0x104` and compares it with an asterisk. Under the apparent character encoding, the comparison value is `0x2A`, decimal 42.

If the comparison matches, the function invokes:

1. **F-3f8871ddd523**, with no explicit arguments shown.
2. **F-4c955ebbbc0d**, with the original object-base argument, integer 43 (`0x2B`), and integer zero, in that order.

The second invocation occurs only if the first returns control. If the marker does not match, both invocations are skipped.

The marker is tested once. A change to the marker during either conditional dependency does not cause a second branch decision. In particular, once F-3f8871ddd523 has been selected and returns normally, F-4c955ebbbc0d follows without a marker retest.

The marker value used for selection is the value read after F-338d16f9ce72, not necessarily the value present on entry.

### Pointer-field read

After the marker-dependent sequence finishes or is skipped, the function reads the pointer at object offset `0xFC`.

The loaded value governs the remaining local decisions. No second read of that object field is shown. Changes made by any earlier dependency can therefore determine which pointer is used.

If the pointer is null:

- No pointee word is read.
- No indirect-target value is read from the fixed global storage.
- No indirect invocation occurs.
- The function returns, provided preceding operations completed normally.

A null pointer does not bypass the initial dependency or marker processing; those operations precede the pointer load.

### Pointee-word read and gate

For a non-null loaded pointer, the function reads the integer-sized word at that address.

If the word is zero, the function returns without reading the indirect-target global or invoking its contents.

If the word is nonzero, the function proceeds to the indirect-target read. Only zero versus nonzero matters. The word is not visibly used as an address, dispatch index, length, or explicit call argument.

Under the apparent 32-bit word model, every nonzero bit pattern satisfies this gate, including values whose signed interpretation is negative.

A non-null pointer receives no further local validation before dereference. An inaccessible pointee does not produce a specified local error result or fallback.

### Late indirect-target read and invocation

Only after the non-null pointer has been dereferenced and its word has been found nonzero does the function read the function-pointer value from the separate fixed global storage.

This read is a distinct operation from the object-field load and the pointee-word read. Its established ordering is:

1. All preceding dependency invocations complete.
2. The object’s pointer field is loaded.
3. The non-null pointer’s first word is read.
4. The nonzero-word condition is satisfied.
5. The indirect-target value is read from global storage.
6. That loaded target is invoked.

The selected target is the value present at step 5. No earlier snapshot of that global is established or permitted as a substitute for this late read. In particular, any preceding dependency may modify the global, and the function must not assume that it preserves the target.

On either untaken path—null object-field pointer or zero pointee word—the local body does not read the indirect-target global.

No explicit arguments to the indirect invocation are shown. That does not establish the absence of hidden inputs, register inputs, or calling-convention-specific state.

There is no visible null or validity check on the loaded target. If the gate succeeds but the target is unusable, the function provides no local recovery behavior.

The supplied representation identifies uncertainty in recovering this indirect control transfer. Its presentation as an invocation followed by return supports the ordering above, but the exact machine-level transfer and calling convention remain unresolved.

### Arithmetic boundaries

The visible object-address calculations add fixed byte offsets `0xFC` and `0x104` to the original argument. There is no variable-length calculation, multiplication, or arithmetic involving the pointee word.

No overflow handling is shown. Valid-input requirements must account for address representability and accessible storage. The representation does not establish a portable outcome for overflowing address arithmetic; wraparound, invalid arithmetic, and resulting access behavior must not be guessed.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each normal-return example assumes valid reached accesses and normal return from invoked dependencies.

### Nonmatching marker and null pointer

If the marker read does not match an asterisk and the later pointer-field read yields null:

- F-338d16f9ce72 is invoked.
- Both marker-dependent dependencies are skipped.
- Neither the pointee word nor the indirect-target global is read.

The last receives the original object base, 43, and zero. No pointee or indirect-target read follows the null pointer result.

### Non-null pointer to zero

If the final field value is non-null and its first word is zero, that word is read, but the indirect-target global is not. The indirect dependency is not invoked, regardless of the target value stored globally.

### Non-null pointer to nonzero

If the final field value is non-null and its first word is nonzero, the function subsequently reads the indirect-target global and invokes the value obtained by that read.

A negative signed interpretation of the word does not suppress invocation.

### Earlier dependency changes the marker

If F-338d16f9ce72 changes a nonmatching entry-time marker to an asterisk before returning, the conditional pair is selected. If it changes an asterisk to a nonmatching byte, the pair is skipped.

### Earlier dependency changes the pointer field

If a preceding dependency replaces the pointer field, the subsequent field load uses the replacement. An entry-time pointer does not independently control the final gate.

### Earlier dependency changes the indirect target

Suppose the global initially contains one callable target, and a reached dependency replaces it with another before the final pointer inspection.

If the pointer and word gates succeed and the replacement remains present at the late global read, the replacement target is invoked. Calling the entry-time target instead would violate the established read ordering.

If the gates fail, neither target is loaded by the local body.

### Invalid reached storage

A non-null unreadable pointee causes an attempted word read without local recovery. If the word read succeeds and is nonzero but the indirect-target storage or loaded target is invalid, the function supplies no guaranteed successful return or specific failure mechanism.
