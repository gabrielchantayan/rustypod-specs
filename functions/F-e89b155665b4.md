# F-e89b155665b4

## Purpose

F-e89b155665b4 exposes a partially recovered sequence of memory accesses and calls driven by incoming machine state. The supplied representation does not establish a coherent application-level purpose, a complete calling convention, or a valid return path.

The established behavior is an ordered prefix that reads two words, writes one byte, reads another word, invokes two indirect dependencies, and attempts a word write through the second dependency’s result. A subsequent branch either reaches an undecodable boundary or enters a longer sequence of memory accesses and calls.

The longer sequence is conditional on execution continuing after a word write to address zero. Under an ordinary memory model in which that write faults, the longer sequence cannot execute. It must not be presented as an ordinary successful path without an explicit environmental assumption.

This contract describes the supplied static representation, not verified machine execution. Application intent, memory ownership, and behavior beyond the undecodable boundaries remain **documented_only**.

## Behavior

### 1. Ordered entry prefix

The following order is established by the supplied representation:

1. Read the first source word.
2. Read the second source word.
3. Write the low byte of the first source word to the address formed by adding the index/address value to the base value.
4. Read the saved target base from the base value plus 96 bytes.
5. Invoke an indirect dependency whose target is formed from the incoming link-derived value plus 2,740 bytes.
6. If that call returns, invoke another indirect dependency at a fixed target recovered from local address arithmetic.
7. Interpret the second call’s result as a paired result. Attempt to store the entire second source word at the address represented by its low component.
8. Only after that store, test whether the low component is zero.

The first two source reads precede the initial byte write. Consequently, an overlap between that byte destination and either source word does not change the already-read source values in the displayed sequence.

Similarly, the saved target base is read before either indirect call. A dependency’s later modification of its backing memory does not by itself imply a reread.

These ordering claims concern the recovered operations. They do not establish that unknown dependencies preserve registers, globals, source storage, or other live state. The physical mechanism by which values survive the calls is not shown.

### 2. Nonzero-result branch

If the first paired result’s low component is nonzero, and the preceding word store completes:

1. Form an address by adding the second source word to the saved target base.
2. Store the low sixteen bits of the second source word at that address.
3. Reach an undecodable boundary.

The second source word serves both as a byte displacement and as the value being truncated for the halfword store. It is not scaled by the size of the store. For example, a displacement of six advances the address by six bytes, not twelve.

No postcondition beyond the halfword write is established.

### 3. Zero-result continuation

5. Invoke F-00cd69d10a06.

8. Store the low sixteen bits of the difference at the incoming index/address value plus 14 bytes.

### 4. Arithmetic constraints

Several distinctions materially affect the contract:

- The earlier right shift treats the index/address value as signed. The later right shift treats the same incoming bit pattern as unsigned.
- For an unsigned 32-bit value, shifting right by 19 produces a value from zero through 8,191. Its mathematical negation ranges from zero through −8,191. In a modular 32-bit address model, negative results correspond to high address-space bit patterns.
- The stack-derived value is both shifted left by three and multiplied by eight. These express the same mathematical scaling only when interpreted under compatible overflow rules.
- Left-shifting a negative signed value, overflowing signed arithmetic, or overflowing an address calculation cannot be assigned portable source-language semantics from this representation alone.
- No explicit overflow, bounds, alignment, null, or address-validity checks are shown before the relevant accesses.

Exact machine wraparound and shift behavior require instruction-level or platform evidence not supplied here. The recovered expressions do not establish a checked-arithmetic interface.

These are conditional static acceptance examples, not executed tests. Each assumes that all earlier accesses and calls needed to reach the described point complete.

The function first writes the 32-bit value six at P. It then writes the 16-bit value six at B plus six bytes and reaches the first undecodable boundary.

### Zero is not a protective check

Given a first paired result whose low component is zero:

- The function attempts the 32-bit store to address zero.
- If the environment faults on that store, the longer continuation is not reached.
- If the environment permits that store and continues execution, the zero-result continuation becomes eligible.

A contract stating “null skips the store” would contradict the evidence.

### Signed and unsigned shift distinction

For an incoming index/address bit pattern of hexadecimal FFFFFFFF, a conventional 32-bit arithmetic right shift by 19 yields negative one. The earlier word-read address would therefore be 67.

The later logical right shift yields 8,191; negating it yields −8,191 before any conversion to an address representation.

This example is conditional on conventional arithmetic-right-shift semantics. It demonstrates why the two shifts cannot be merged into one unsigned operation.
