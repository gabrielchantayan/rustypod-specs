# F-d88070c38f62

## Purpose

F-d88070c38f62 wraps a delegated numeric conversion with leading-byte classification, optional sign handling, end-position adjustment, and signed 64-bit range enforcement.

The established behavior is:

- Skip leading nonzero bytes whose classification entry has bit 0 set.
- Consume at most one subsequent `+` or `-` byte.
- Invoke F-c4e0ec1bb29e on the resulting input position.
- If a supplied end-position slot reports that the delegated conversion consumed nothing, replace that position with the original input address.
- Interpret the delegated result as a 64-bit magnitude for sign application and range checking.
- Return a signed 64-bit result, saturating to the appropriate signed endpoint and writing the 32-bit value `2` through a dependency-provided address when the magnitude exceeds the permitted range.

A signed integer text-conversion role is inferred intent. The accepted digit syntax, meaning of the third argument, and detailed delegated error behavior are not established here.

## Interface

### Inputs

1. **Input address**

   An address of byte-addressable input storage. Each inspected byte is read as an unsigned 8-bit value, from `0` through `255`.

   The wrapper does not validate this address. It must permit all reads actually reached by the wrapper and by F-c4e0ec1bb29e. A zero byte terminates the wrapper’s leading-byte scan, but the complete memory requirements of the delegated conversion are unknown.

2. **Optional end-position slot**

   Either a null address or an address of a readable and writable 32-bit slot representing an input pointer.

   The wrapper forwards this argument unchanged to F-c4e0ec1bb29e. When it is nonnull, the wrapper subsequently reads its contents and may overwrite them with the original input address.

   This is one pointer-sized slot in the evidenced 32-bit layout, not a buffer of end positions.

3. **Opaque 32-bit conversion argument**

   A 32-bit value forwarded unchanged to F-c4e0ec1bb29e.

   Its interpretation and valid range are undocumented here. A radix or conversion-mode interpretation is plausible but not established.

### Output

A 64-bit return value with signed range:

- Minimum: −9,223,372,036,854,775,808.
- Maximum: 9,223,372,036,854,775,807.

The delegated result is split into two 32-bit words for arithmetic. The wrapper’s sign and range behavior is most clearly specified by treating the delegated bit pattern as an unsigned 64-bit magnitude, denoted **M**:

| Sign recognized by this wrapper | Magnitude range | Returned value |
|---|---:|---:|
| No minus sign | 0 through 2⁶³−1 | M |
| No minus sign | 2⁶³ through 2⁶⁴−1 | 2⁶³−1, with range-error write |
| Minus sign | 0 through 2⁶³ | −M |
| Minus sign | 2⁶³+1 through 2⁶⁴−1 | −2⁶³, with range-error write |

This table describes what the wrapper does with the returned bits. It does not establish that F-c4e0ec1bb29e always returns a mathematical magnitude or that its own overflow behavior preserves such a value.

- Every classification lookup returns a usable address containing a usable 32-bit table address.
- Each classification table entry reached by an unsigned byte index is readable.
- A nonnull end-position slot is readable and writable.
- On a saturation path, F-4af36158f863 returns a writable address for a 32-bit value.

Ownership, retention, allocation, release, and global-state behavior inside the dependencies are unknown. The wrapper’s lack of explicit ownership operations does not constrain those dependencies.

## Behavior

### Leading-byte scan

The wrapper begins at the original input address.

For each scan position, it reads one byte and computes the following byte address. The just-read byte determines the next action:

- If the byte is zero, the scan stops without a classification dependency call for that byte.
- Otherwise, the wrapper calls F-2a4c402ba617.
- It reads a 32-bit table address from the storage identified by that call’s result.
- It reads the one-byte table entry indexed by the previously read unsigned input byte.
- If bit 0 of that entry is set, scanning continues at the following input byte.
- If bit 0 is clear, the scan stops at the just-read byte.

Classification is obtained separately for each nonzero byte examined. There is no visible caching of the classification table address across iterations.

The wrapper does not itself define whitespace. “Skipped leading bytes” means precisely those nonzero bytes for which the observed classification-entry bit is set. Whether these are spaces, tabs, locale-dependent characters, or another class depends on F-2a4c402ba617 and its returned table.

The byte value used for classification and sign selection is the value already read. If a dependency changes the input storage after that read, the wrapper does not visibly reread that byte before making those decisions.

### Sign recognition and delegated input position

After the scan stops, the wrapper examines the byte that stopped it:

- Byte value `0x2B`, conventionally `+`: consume that byte; do not set the negative-sign state.
- Byte value `0x2D`, conventionally `-`: consume that byte; set the negative-sign state.
- Any other value, including zero: do not consume that byte.

The sign decision therefore applies only to the first byte not skipped by classification. A plus or minus byte classified with bit 0 set is skipped rather than recognized as a sign at that position.

The wrapper consumes no second sign and performs no additional leading-byte scan after consuming a sign. It passes the position immediately following a recognized sign directly to F-c4e0ec1bb29e.

For a stopping zero byte, the delegated input address points to that zero byte, not one byte beyond it.

### Delegated conversion

The wrapper calls F-c4e0ec1bb29e exactly once if execution reaches this stage, passing:

1. The input position selected above.
2. The original optional end-position-slot address.
3. The original opaque 32-bit conversion argument.

Its 64-bit return bit pattern is captured before the wrapper adjusts the end position or handles saturation.

The wrapper does not independently inspect digits, validate a radix, recognize prefixes, or determine whether conversion succeeded. Those matters are delegated.

### End-position normalization

After F-c4e0ec1bb29e returns, and before any saturation-related dependency call, the wrapper handles the optional slot:

- If the slot address is null, there is no wrapper-side slot read or write.
- Otherwise, the wrapper reads the 32-bit pointer value currently stored there.
- If that value equals the exact input address supplied to F-c4e0ec1bb29e, the wrapper writes the original input address into the slot.
- If the values differ, the wrapper leaves the slot unchanged.

The test is address equality, not a check of the returned magnitude or the character at the reported position.

Consequently, a delegated “no progress” indication is normalized back across any leading bytes and optional sign consumed by the wrapper. A zero numeric result alone does not cause this normalization.

The comparison uses the slot’s actual post-call contents. The wrapper does not establish that the dependency wrote them. A dependency that leaves a nonnull slot uninitialized or stale can therefore affect this branch.

### Sign application and range enforcement

For a recognized minus sign, the wrapper forms the two’s-complement 64-bit negation of the delegated result using 32-bit word operations, including carry between the words. Its additional condition detects magnitudes strictly greater than 2⁶³.

Thus:

- Zero remains zero.
- Magnitudes up to 2⁶³−1 become ordinary negative results.
- Exactly 2⁶³ becomes the signed minimum without a wrapper-generated range-error write.
- Larger unsigned magnitudes produce the signed minimum and a range-error write.

Without a recognized minus sign, the wrapper treats any delegated bit pattern with the top bit set as exceeding the signed positive range. It then returns the signed maximum and performs the range-error write.

A consumed plus sign follows this same nonnegative path.

These boundaries follow from the full 64-bit result, not merely from whether its low 32-bit word is nonzero.

### Range-error write

On either saturation path, the wrapper:

1. Calls F-4af36158f863.
2. Writes the 32-bit value `2` to the returned address.
3. Uses the appropriate signed endpoint as its final return value.

The displayed calls supply two 32-bit values: the low word of the delegated result and its original high word. In the negative path, the high word is recovered through the intermediate word arithmetic. Whether these supplied values are meaningful parameters to F-4af36158f863 is undocumented.

There is no visible null-result check before the write.

On nonsaturating paths, the wrapper neither calls this dependency nor explicitly clears a previously stored error value.

## Side effects

### Directly established accesses

The wrapper directly performs:

- Ordered reads of input bytes during the leading scan.
- A classification dependency call for each nonzero byte examined by that scan.
- A read of the returned classification-table address and then an indexed one-byte classification read.
- One call to the delegated conversion dependency.
- A conditional 32-bit end-position-slot read.
- A conditional 32-bit write of the original input address to that slot.
- On saturation only, a range-error dependency call followed by a 32-bit write of `2`.

The end-position adjustment precedes the range-error dependency call. Therefore, the slot is already normalized when that dependency is invoked. The wrapper does not recheck it afterward; dependency-side changes could alter the final observable slot value.

### State not established by this evidence

No direct input-byte writes are visible. This is not a guarantee that the dependencies leave the input unchanged.

No direct global-state reset, allocation, deallocation, synchronization, or exception-handling operation is visible. Dependency behavior in these areas is unknown.

Aliasing among the input, end-position slot, classification storage, and error destination is not explicitly prohibited or handled. The visible access order remains relevant if callers provide overlapping storage, but this evidence does not establish that such configurations are supported.

## Acceptance examples

These are conditional acceptance cases, not executed tests. Unless stated otherwise, assume valid storage, stable relevant classification entries, and dependencies that return normally without unrelated mutations.

1. **Positive magnitude within range**

   No minus sign is recognized. F-c4e0ec1bb29e returns magnitude `42`. The wrapper returns `42` without calling F-4af36158f863.

2. **Negative magnitude within range**

   A minus sign is recognized. The delegated result is `42`. The wrapper returns `−42` without a range-error write.

3. **Exact negative endpoint**

   A minus sign is recognized. The delegated bit pattern represents unsigned magnitude `9,223,372,036,854,775,808`. The wrapper returns `−9,223,372,036,854,775,808` without a wrapper-generated range-error write.

4. **First positive overflow**

   No minus sign is recognized. The delegated magnitude is `9,223,372,036,854,775,808`. The wrapper calls F-4af36158f863, writes `2` to its returned destination, and returns `9,223,372,036,854,775,807`.

5. **First negative overflow**

   A minus sign is recognized. The delegated magnitude is `9,223,372,036,854,775,809`. The wrapper performs the range-error write and returns `−9,223,372,036,854,775,808`.

6. **No delegated progress after leading bytes and sign**

   Classification skips two leading bytes, and the next byte is a minus sign with a clear classification bit. The delegate receives the address after the sign. If it stores that same address in the supplied slot, the wrapper replaces it with the original input address, including the skipped bytes.

7. **Zero result with actual progress**

   The delegate returns zero but stores an end position different from its input address. The wrapper does not normalize that slot merely because the result is zero.

8. **Empty input**

   The first input byte is zero. There is no classification call for that byte. The delegate receives the original input address.

9. **Two consecutive signs**

   The first sign stops classification and is consumed. The delegate receives the second sign. The wrapper neither consumes that second sign nor decides whether it is valid.

10. **Null end-position slot**

    The wrapper forwards null to the delegate and performs no subsequent slot access. This does not establish whether the delegate accepts null.

11. **Classification treats a sign as skippable**

    If the observed entry for a leading minus byte has bit 0 set, that byte is skipped. It does not establish negative-sign state merely because its value is `0x2D`.
