# F-09c5a4de906c

## Purpose

F-09c5a4de906c converts a sequence of unsigned 32-bit values into a sequence of unsigned 64-bit squares, represented as pairs of 32-bit words.

For each input value, the output pair contains the low word followed by the high word. This is a word-index layout, not a claim about byte endianness.

The squaring interpretation is established algebraically under the 32-bit unsigned arithmetic model described below, provided the two source read expressions for each element observe the same value. The supplied representation contains two read expressions per element rather than an explicit single-read snapshot.

The operation processes elements in increasing index order, in groups of up to four. Its output store order is not uniform: the first element of each group is written low word first; the remaining elements are written high word first. That distinction matters for overlapping buffers and observers capable of seeing intermediate stores.

## Behavior

### Count handling

A count below one causes an immediate return with no represented source reads or destination writes.

For a positive count, exactly that many elements are processed, assuming all accesses and execution complete normally. The function does not interpret the count as a byte length or an output-word count.

Processing is organized into groups of four:

- A remaining count of one stops after the first element of the group.
- A remaining count of two stops after the second.
- A remaining count of three stops after the third.
- Otherwise, all four elements are processed, and the remaining count is reduced by four.
- If elements remain, processing continues at the next four source words and next eight destination words.

For valid positive counts, the decrement cannot make the remaining count negative: values one through three terminate before that decrement, while values at least four produce a nonnegative remainder.

### Per-element arithmetic

Let \(L\) be the low 16 bits obtained from the first source read expression for an element. Let \(H\) be the upper 16 bits obtained from the second source read expression for that element.

Thus:

\[
0 \le L,H \le 65535.
\]

Define:

\[
P=HL,
\qquad
T=(2^{17}P)\bmod 2^{32},
\]

\[
W_{\mathrm{low}}=(L^2+T)\bmod 2^{32}.
\]

The carry indicator is one when the unsigned low-word addition wraps, and zero otherwise. Equivalently:

\[
C=
\begin{cases}
1,&W_{\mathrm{low}}<T,\\
0,&W_{\mathrm{low}}\ge T.
\end{cases}
\]

The high output word is:

\[
W_{\mathrm{high}}
=
H^2+\left\lfloor\frac{P}{2^{15}}\right\rfloor+C.
\]

The represented unsigned operations reduce their results modulo \(2^{32}\). In this particular calculation, the final high-word value fits within 32 bits; no additional high-word overflow is needed to interpret the result.

The relevant bounds and truncations are:

- \(H^2\), \(L^2\), and \(HL\) each fit within an unsigned 32-bit word.
- Multiplication of \(HL\) by \(2^{17}\) intentionally retains only its low 32 bits.
- The discarded portion of that shifted cross product is accounted for by \(\lfloor HL/2^{15}\rfloor\).
- The low-word addition may wrap, and its carry is explicitly added to the high word.

When both source reads observe the same word \(x\),

\[
x=2^{16}H+L,
\]

and therefore:

\[
x^2=2^{32}W_{\mathrm{high}}+W_{\mathrm{low}}.
\]

This is an exact unsigned square, not a saturating result, signed square, or truncated 32-bit square.

### Output layout

For input element \(i\), numbered from zero:

- Destination word \(2i\) receives \(W_{\mathrm{low}}\).
- Destination word \(2i+1\) receives \(W_{\mathrm{high}}\).

The two words are separate stores. The representation does not establish an atomic 64-bit write.

### Read and write order

At the supplied representation level, each element has this access ordering:

1. Read the current source word to extract its low half.
2. Read that same source word again to extract its high half.
3. Compute both output words.
4. Store both output words before reading the next element.

The output store order depends on the element’s position in its four-element group:

| Element index modulo four | First store | Second store |
|---|---|---|
| 0 | Low output word | High output word |
| 1 | High output word | Low output word |
| 2 | High output word | Low output word |
| 3 | High output word | Low output word |

### Overlap

There is no overlap check and no whole-input snapshot.

Nonoverlapping buffers with stable source contents provide the straightforward sequence-of-squares behavior. Overlap can cause earlier destination writes to replace source words that have not yet been read. Later results then reflect the overwritten values rather than the source’s entry-time contents.

An individual element’s two source read expressions precede both of its destination writes. However, this does not make forward expansion safe in place: two destination words are produced for every source word consumed.

The function is not established as overlap-safe. Exact overlap behavior depends on valid aliasing, address relationships, and the represented access sequence.
