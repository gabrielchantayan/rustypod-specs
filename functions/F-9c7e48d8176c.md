# F-9c7e48d8176c

## Purpose

F-9c7e48d8176c conditionally selects a byte-string pointer from an indexed record table, scans leading bytes according to a classification dependency, positions a conversion pointer around one optional sign, and returns a dependency-produced 32-bit integer. Failed eligibility or bound checks return the caller’s fallback.

A post-conversion status value of exactly 2 controls two decisions: whether to restore a previously saved status value and whether to apply a consumed minus sign.

**Established static evidence:** field accesses, index comparisons and transformation, dependency-call order, scan mechanics, pointer positioning, status-slot writes, and return selection.

**Inferred intent:** the classification bit may identify whitespace, and the status slot may report conversion errors. Neither interpretation is required for the behavior below.

The function establishes conversion-pointer positioning, not preservation of the selected string. Dependencies may mutate accessible memory. The retained status slot may also overlap the string, descriptor, or table; disjointness is not established.

## Interface

The function has three arguments and one result:

| Item | Representation | Role |
|---|---|---|
| Descriptor | Pointer to a structure with an initial 32-bit handle and a second 32-bit word | Supplies eligibility information, mode information, and access to table metadata |
| Requested index | Unsigned 32-bit integer | Participates in eligibility, the first bound check, and record selection |
| Fallback | Signed 32-bit integer | Returned on a failed eligibility or bound check |
| Result | Signed 32-bit integer | Fallback or the conversion result with conditional negation |

There is no separate success indicator. A conversion result can equal the fallback.

The supplied representation uses the following layout:

| Object | Offset or stride | Observed use |
|---|---:|---|
| Descriptor | 0 bytes | 32-bit handle |
| Descriptor | 4 bytes | One byte used for eligibility |
| Descriptor | 4 bytes | A 32-bit word narrowed to a character-sized value for comparison with 2 |
| Handle-referenced object | 20 bytes | 32-bit table-pointer field |
| Record table | 40-byte stride | Record selection |
| Selected record | 16 bytes | String-pointer field |
| Status slot | 0 bytes | Signed 32-bit value |
| Classification dependency’s returned object | 0 bytes | 32-bit classification-table base |
| Classification table | One-byte entries | Bit 0 tested at an unsigned byte index |

The eligibility-byte read and the narrowing of the second word are separate operations. Their relationship depends on target representation; they are not interchangeable by contract.

### Preconditions

Each reached memory access requires valid storage for that access:

- The descriptor must support its reached byte and word reads.
- A handle used for metadata access must identify storage containing the table-pointer field.
- Record-address arithmetic must produce an accessible string-pointer field.
- The selected string must support all reached scan reads and the conversion dependency’s accesses.
- The status dependency must return storage supporting the required 32-bit reads and writes.
- The retained status pointer must remain usable through classification, conversion, and final status handling.
- Each classification dependency result must support reading a table base, and that base must support the selected byte access.

These are validity requirements, not non-aliasing requirements. Overlap is not rejected.

There is no explicit null-descriptor check, null-string check, allocation check, or local recovery for invalid memory. Passing the bound comparisons does not independently prove table capacity.

## Behavior

### Eligibility reads and first bound check

Eligibility is evaluated through separate reads rather than an immutable descriptor snapshot.

An eligibility quantity initially has the requested index’s unsigned 32-bit value. The function first reads the descriptor handle. If that read is nonzero, it replaces the eligibility quantity with the unsigned byte at descriptor offset 4.

The function then reads the descriptor handle again. It proceeds only if this second handle read is nonzero and the eligibility quantity is nonzero. Otherwise, it returns the fallback.

For stable descriptor contents, this requires both a nonzero handle and a nonzero eligibility byte. If the two handle reads differ, that simplified rule is insufficient. In particular, an initial zero handle leaves the requested index as the eligibility quantity; a later nonzero handle can therefore permit progression when that index is nonzero. Concurrent modification and synchronization guarantees are undocumented.

After eligibility succeeds, the function calls F-e84094e554a6 with no explicit argument. It interprets the returned bound as unsigned 32-bit and compares the original requested index against it:

- Requested index less than or equal to the bound: continue.
- Requested index greater than the bound: return the fallback.

Equality is accepted. No exclusive-count interpretation is established.

### Mode-dependent index selection

After the first bound check succeeds, the function reads the descriptor’s second 32-bit word and narrows it to a character-sized value.

If the narrowed value equals 2, the selected index is:

**(2 × requested index + 1) modulo 2³².**

Otherwise, the selected index is the original requested index.

The first comparison therefore checks the original index, not the transformed index. Transformation overflow is not rejected.

The mode read occurs after the first dependency call. It need not reflect descriptor contents from before that call.

### Second bound check and table lookup

The function reads the descriptor’s current handle and passes it explicitly to F-e84094e554a6.

It compares the selected index with this second unsigned 32-bit bound:

- Selected index less than or equal to the bound: continue.
- Selected index greater than the bound: return the fallback.

The two bound calls are distinct operations with different visible argument forms. Their return values need not agree.

After the second check succeeds, the function reads the descriptor handle again. Through that handle, it reads the table pointer at offset 20. It then reads the string pointer at:

**table base + 40 × selected index + 16 bytes.**

The represented arithmetic is 32-bit; the unsigned index makes the record displacement subject to 32-bit arithmetic. There is no separate overflow or object-bound check. A wrapped address is not thereby established to identify valid storage.

Neither the handle passed to the second bound call nor an earlier descriptor state is guaranteed to be the one used for the eventual table lookup.

### Status acquisition and byte scanning

After selecting the string pointer, the function calls F-4af36158f863. It retains the returned status-slot pointer and saves the signed 32-bit value read from that slot.

It then scans from the selected string address. Each iteration has this observable order:

1. Read one byte at the current scan address.
2. Advance the provisional address by one byte.
3. If the observed byte is zero, stop scanning without a classification call.
4. Otherwise, call F-2a4c402ba617.
5. Read a classification-table base through the returned pointer.
6. Read the classification entry indexed by the previously observed unsigned byte.
7. Continue scanning only if bit 0 of that entry is set.

The byte index is zero-extended to the range 0–255. Classification calls occur only for nonzero observed bytes, so those calls use indices 1–255.

The classification dependency is called for every examined nonzero byte, including the byte that ultimately stops scanning because its classification bit is clear. The table base is read anew after every such call.

The input byte is observed before its classification call. A dependency may subsequently alter that byte or other storage, but the classification index and subsequent sign decision use the already observed byte value.

A zero byte stops scanning regardless of any table entry for zero. A plus or minus byte whose classification bit is set is skipped rather than consumed as a sign.

### Conversion-pointer positioning

The observed byte that stops scanning determines the conversion-start address:

| Observed stopping byte | Conversion-start address | Pending negation |
|---|---|---|
| 43, plus | Address immediately after the observed byte | No |
| 45, minus | Address immediately after the observed byte | Yes |
| Any other value, including zero | Address of the observed byte | No |

Only one sign is consumed by this function. It does not locally process a second sign, numeric prefix, digit sequence, or trailing text.

These rules specify addresses, not unchanged contents. Classification calls may have modified the string. The later status-slot zero write may also modify string storage if the two overlap. Thus an address selected because it contained a digit, sign successor, or terminator need not contain that same byte when conversion begins.

### Conversion and final status handling

Immediately before conversion, the function writes a 32-bit zero through the retained status pointer.

It calls F-eef3bf576bc2 with three explicit arguments:

1. The conversion-start pointer.
2. Zero.
3. Zero.

The conversion result is treated as signed 32-bit. The meaning of the two zero arguments is not established.

After the call returns, the function reads the retained status slot once. That observed value controls both remaining decisions:

| Observed post-conversion status | Status action | Returned value |
|---|---|---|
| Exactly 2 | No restoration write | Conversion result without local negation |
| Anything other than 2 | Restore the saved pre-scan value | Negated conversion result if minus was consumed; otherwise the conversion result |

Restoration does not cause the status condition to be reevaluated. If the observed post-conversion status was not 2, restoring a saved value of 2 does not suppress pending negation.

The saved value predates classification. Classification-time changes to the status slot are superseded by the pre-conversion zero write and, when restoration occurs, by the saved value.

Status 2 does not cause fallback. Neither empty input nor a nonnumeric input causes a local fallback decision. Their conversion results and status effects depend on F-eef3bf576bc2.

Negation is represented as signed 32-bit negation. Portable behavior for negating −2,147,483,648 is not established.

## Side effects

The explicit local write target is the retained status-slot pointer:

- One 32-bit zero write before conversion.
- One 32-bit restoration write if the observed post-conversion status is not 2.

The descriptor, metadata, table, classification data, and selected string are not explicit write targets. **Their disjointness from the status slot is undocumented.** A status-slot write may therefore also change one of those objects when storage overlaps.

In particular, overlap with string storage can alter what conversion reads after scanning has finished. Restoration can change that storage again after conversion. Overlap does not change the already retained conversion pointer or observed sign decision.

The function explicitly reads descriptor fields, metadata, the selected record field, input bytes, the status slot, and classification data. Dependencies may introduce additional reads, writes, or other effects.

No allocation, deallocation, ownership transfer, release, logging, or external I/O is explicitly performed by the local body. This does not establish their absence inside dependencies.

Returned pointers are retained and used, but no ownership or lifetime guarantee is supplied by the visible calls. No dependency is assumed to preserve globals, descriptor contents, string contents, table contents, or memory ownership.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations. Memory validity and any stated stability or dependency behavior are prerequisites.

1. **Stable absent handle.** With a descriptor handle remaining zero across both eligibility reads, return the fallback. No dependency is called.

2. **Stable disabled eligibility.** With a stable nonzero handle and a zero eligibility byte, return the fallback before the first bound call.

3. **Distinct initial handle observations.** If the first handle read is zero, the second is nonzero, and the requested index is 3, the eligibility quantity remains 3. Execution reaches the first bound call without having read the eligibility byte.

4. **Inclusive first bound.** If eligibility succeeds and the first bound is 7, requested index 7 reaches mode handling. Requested index 8 returns the fallback.

5. **Mode transformation and second bound.** With narrowed mode 2 and original index 3 passing the first check, the selected index is 7. A second bound of 6 rejects it; a second bound of 7 accepts it.

6. **Transformation wraparound.** If original index 2,147,483,648 passes the first check and mode transformation applies, the selected index is 1. The second comparison uses 1.

7. **No consumed sign.** If scanning stops on an observed, unclassified digit, conversion receives that byte’s address rather than the following address. Its contents at conversion time are not guaranteed by pointer positioning alone.

8. **Minus and ordinary status.** If scanning stops on minus, conversion receives the following address. If conversion returns 12 and the observed status is 0, restore the saved status and return −12.

9. **Minus and status 2.** Under the same positioning conditions, if conversion returns 12 and the observed status is 2, return 12 without restoration.

10. **Saved status 2 does not suppress negation.** If the saved status is 2, a minus was consumed, conversion returns 12, and post-conversion status is 4, restore 2 and return −12.

11. **Observed terminator.** If scanning stops on zero, conversion receives the address where zero was observed. If no intervening mutation changes that byte, conversion sees an empty starting sequence. There is no local empty-input fallback.

12. **Classification changes a stopping byte.** Suppose the scan observes minus, the classification dependency changes that string byte to a digit, and the selected classification entry has bit 0 clear. Pointer positioning still consumes the observed minus and records pending negation.

13. **Status slot overlaps conversion input.** Suppose valid writable storage begins with bytes representing “123” followed by zero, the status slot starts at that same address, and scanning stops at the first digit. The pre-conversion 32-bit zero write makes those four bytes zero. Conversion receives the original starting address but sees zero there. If conversion leaves status 0, the saved 32-bit value is subsequently restored.
