# F-811b21c0e819

## Purpose

F-811b21c0e819 selects between two observable action sequences using the result of an indirect query on an object obtained from F-eea3e31f6354:

- A zero query result causes a value to be constructed and passed to an indirect operation on the caller-supplied object.
- A nonzero query result causes two ordered calls involving a field of the caller-supplied object, with the first call also receiving the integer value 1000.

Every path that reaches the function’s normal return produces the 32-bit value 1. This is not evidence that either action sequence succeeded: no downstream status is explicitly checked.

The apparent intent is to choose between a generated-value update and a separate two-operation action. That interpretation is inferred. The meanings of the objects, fields, generated value, and numeric constants are not established.

## Behavior

### 1. Obtain and query the additional object

The function first calls F-eea3e31f6354 without explicit arguments and retains its returned object reference.

It then resolves an indirect operation through that object’s dispatch-table pointer at byte offset 0 and the dispatch entry at byte offset 0xA4. The operation receives the queried object as its explicit argument.

The query result is compared with zero:

- Exactly zero selects the generated-value path.
- Any nonzero value selects the two-call path.

There is no distinction between positive and negative nonzero results in the recovered 32-bit representation.

The query is a call boundary. Its effects are unknown. In particular, it must not be assumed to preserve object fields, global state, or object lifetimes. Subsequent accesses occur after it returns.

### 2. Zero query result: select and construct a value

On the zero-result path, the function reads the queried object’s 32-bit discriminator at byte offset 0x4E4.

That read chooses between two distinct global 32-bit value sources:

- A zero discriminator selects the **zero-discriminator global**.
- Any nonzero discriminator selects the **nonzero-discriminator global**.

These labels identify two source locations; their values and meanings are not supplied.

After choosing the branch, the function calls F-ef0964bd9b8a without explicit arguments. It retains the returned 32-bit value as a construction input.

Only after that call returns does it read the selected global. This timing is material:

- The discriminator determines which global is selected before F-ef0964bd9b8a executes.
- The selected global’s value is obtained after F-ef0964bd9b8a executes.
- Changes made by that dependency to the selected global can therefore affect the construction input.
- A change to the discriminator during that dependency does not cause the branch selection to be repeated.

Let the selected global’s value at that read be **S**, and let the return from F-ef0964bd9b8a be **T**. The function calls F-1958950ee503 with four arguments, in this positional order:

1. T.
2. The recovered 32-bit decrement of S by one.
3. S itself.
4. The integer zero.

The second and third arguments derive from the same captured global value. They are not established as two independently timed global reads.

For values safely within an ordinary signed 32-bit range, the second argument is S − 1. At a signed-overflow boundary, the recovered expression alone does not settle the original language’s overflow rules. A fixed-width implementation would produce the low 32 bits of S − 1, but that boundary behavior requires confirmation rather than an assumption about source-language arithmetic.

The return value from F-1958950ee503 becomes the generated value.

### 3. Zero query result: deliver the generated value

2. The dispatch entry at byte offset 0xD0.

The receiver’s dispatch target is resolved after value construction, not before it. Dependencies called earlier may therefore affect the state from which this dispatch is resolved, if they can reach that state.

### 4. Nonzero query result: perform two ordered calls
