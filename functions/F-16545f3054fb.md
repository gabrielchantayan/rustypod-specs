It publishes a primary value, transfers four descriptor words, initializes additional state words, stores a dependency result, makes a call associated with the label “WindowManager,” invokes another dependency, and clears a late-selected word.

Initialization and registration are inferred intent. The established contract is the access and call sequence below; the application-level meanings of the stored values and dependency operations are not established.

A central distinction is between retained addresses and separately read write targets. The primary-value write does not explicitly use the retained state base. Similarly, the first descriptor write does not explicitly use the retained descriptor-destination base. Those targets coincide only when the corresponding selector reads produce equal addresses.

## Behavior

It then reads the state selector again and writes the primary input as a 32-bit word through this second result.

These are distinct selector reads with distinct uses:

### Descriptor writes

The first descriptor write stores the source-offset-0 value through the separately read descriptor-destination selector.

The remaining writes use the retained descriptor-destination base, in this order:

1. Captured source-offset-4 value to retained destination offset 4.
2. Captured source-offset-8 value to retained destination offset 8.
3. Captured source-offset-12 value to retained destination offset 12.

Thus, all four descriptor source words are read before the first descriptor write, but the four destination writes are not unconditionally directed to one contiguous region. A contiguous four-word transfer requires the two destination-selector reads to yield equal addresses.

The read-before-write ordering gives a narrow overlap property: descriptor writes cannot overwrite a source word still awaiting its descriptor read. It does not guarantee a snapshot of entry-time descriptor contents. Preparation, the primary-value write, or external activity may already have changed the source before its reads.

The evidence establishes individual 32-bit accesses, not an atomic 16-byte transfer.
