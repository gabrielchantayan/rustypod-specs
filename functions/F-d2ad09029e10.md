## Acceptance examples

These are conditional static examples, not executed tests.

1. **Call placement:** After F-A06 returns, F-A07, F-A08, F-A09, and F-A10 occur before the second selector clear. F-A11 follows that clear; F-A12–F-A15 then precede the first word store.

2. **Selector indirection:** A selector value of 7 produces byte destination 24, not selector-address plus 17. If a fresh read instead returns 9, that access targets 26.

3. **Saved selector:** If phase I saves selector 9, its later word store targets 29 even if dependencies change the selector location to 12.

4. **Single-bit provenance:** If \(R_{\mathrm{F04}}=2\) and \(R_{\mathrm{F09}}=1\), the persistent base is \(0x80000000\), while phase H stores \(0x80000000\) because of F-F09’s result. Substituting F-F04’s even result would incorrectly store zero.

6. **Shared sampling:** A dependency changing the shared word after phase I does not change phase J’s sampled publication. Selector reads in phase J remain fresh.

7. **Cross-iteration arguments:** If F-H06 returns 5, phase I publishes word 20. On the next completed loop transition, the early third-argument shift uses 5.

8. **Cross-iteration link:** If the incoming link value differs from the phase-L replacement token, the first iteration’s F-A01 uses the incoming value plus 4094; later F-A01 calls use the replacement token plus 4094, provided execution reaches them.

9. **Partial progress:** If a dependency never returns after a store, later events are not required. No visible mechanism undoes the completed store.
