# F-439afd1f5b71

## Purpose

F-439afd1f5b71 replaces a four-byte value at an indirectly selected memory location and returns the value previously held there.

The destination is selected using two values read from caller-accessible memory: a base-address value obtained through the first argument and a displacement obtained four bytes beyond the address represented by the third argument. The second argument supplies the replacement value.

**Established behavior:** destination selection, one logical read of the selected value, replacement of that value, and return of the saved value.

**Inferred intent:** an exchange operation on a field or slot within a caller-selected memory region. This description does not imply an atomic exchange, a particular object layout, or a synchronization primitive.

## Interface

The function has three inputs and a four-byte result.

| Item | Meaning | Width and interpretation |
|---|---|---|
| First argument | Address of storage containing the destination’s base-address value | Pointer to an integer-sized value; the supplied representation supports a 32-bit interpretation |
| Second argument | Replacement value | Exactly four bytes; no signedness or higher-level type is established |
| Third argument | Address-bearing value identifying storage that contains a displacement at byte offset four | Represented as an integer rather than a typed pointer |
| Result | Destination contents captured before replacement | Exactly four bytes; returned without an established numeric interpretation |

The second argument is passed as a value, not as an address from which the function fetches replacement data. In particular, a replacement bit pattern that resembles a pointer is still only copied into the destination.

The first argument does not directly identify the destination. Its referenced contents participate in calculating the destination.

The third argument does not directly supply the displacement. The function accesses memory four bytes beyond the address it represents and reads the displacement from there. No meaning is established for bytes at offset zero through three of that storage.

### Caller obligations

For a normal, completed invocation:

- The first argument must designate readable storage for the base-address value.
- The address represented by the third argument, advanced by four bytes, must designate readable storage for the displacement.
- Their combination must produce a destination at which a four-byte read and a four-byte write are valid.
- The participating memory must satisfy any target-specific alignment and access restrictions.
- Any concurrent access must be controlled externally if the caller requires a stable destination calculation or an indivisible exchange.

No ownership transfer is expressed. The caller remains responsible for the lifetime and accessibility of all participating storage.

## Behavior

### Destination selection

The function obtains a base-address value by reading through its first argument. It also obtains a displacement by reading an integer-sized value at byte offset four from the address represented by its third argument.

These are address-selection reads. Both must supply their values before the selected destination can be read. The supplied representation does not establish which of these two reads occurs first; callers must not depend on their relative order.

The destination is formed by adding the base-address value and the displacement, then treating the result as the address of four-byte storage.

This is byte-address arithmetic. There is no evidence that the displacement is scaled by four, multiplied by an element size, or interpreted as an array index. A displacement of four selects an address four bytes beyond the base, not sixteen bytes beyond it.

### Exchange at the selected destination

Once the destination has been determined, the function:

- Captures the four bytes currently stored at that destination.
- Writes the second argument’s four-byte value to that same destination.
- Returns the captured value.

The destination read precedes the destination write. The returned value is the saved pre-write value, not a subsequent reread of the destination.

There is no condition that skips the write when the replacement equals the previous contents. Such an invocation still includes a logical write, although the resulting bytes are unchanged.

The function performs no visible comparison, validation, branching, retry, or error conversion.

### Widths and arithmetic boundaries

The old value, replacement, and result are all four-byte quantities. No widening, narrowing, sign extension, byte swapping, or field extraction is expressed for that exchange.

The address-selection values are represented as integer values in the supplied evidence. A 32-bit address-arithmetic interpretation is supported by that representation, but the execution architecture, pointer-conversion rules, and overflow semantics are not independently provided.

Accordingly:

- Ordinary cases whose address calculations remain representable have an established destination.
- A negative displacement selects an address below the base if the execution environment interprets the stored displacement as a signed 32-bit integer.
- Cases requiring arithmetic overflow, address truncation, or wraparound remain **documented_only**. The function must not be credited with portable modulo-address behavior on this evidence alone.
- Advancing the third argument by four bytes is itself an address calculation subject to the same unresolved boundary concerns.

### Aliasing

No distinctness requirement between the destination and the address-selection storage appears in the supplied behavior.

If the destination is exactly the base-address storage, the function captures that storage’s old contents and then replaces them. The destination was already selected; changing the stored base does not trigger recalculation during this invocation.

Likewise, if the destination is exactly the displacement storage, the displacement participates in selection before being overwritten. There is no subsequent displacement read or second destination selection.

For valid ordinary memory, overlapping storage does not introduce an additional logical read after the write. Partial overlap, unusual alignment, and platform-specific access behavior require the execution environment’s memory rules.

## Side effects

A normally completed invocation has one explicit logical memory write: replacement of the selected destination’s four bytes.

The function also explicitly reads:

- The base-address storage referenced by the first argument.
- The displacement storage four bytes beyond the third argument’s represented address.
- The selected destination before replacement.

“Logical” describes the behavior established by the supplied representation, not the number or indivisibility of physical memory transactions. Instruction selection, bus access width, compiler transformations, and memory-mapped device behavior are not established.

There is no explicit allocation, deallocation, reference-count operation, ownership transfer, synchronization operation, or separate global-state access. However, the selected destination may itself be global storage, shared storage, or memory used by another component. Its mutation is not restricted to any particular ownership domain.

The read followed by the write is not established as atomic. Another observer may be able to access the destination between them. No locking, memory fence, ordering protocol, or conflict detection is shown.

There is no explicit error result. Every four-byte return pattern can represent a successfully captured prior value; none is reserved as a failure indicator.

Invalid addresses, inaccessible memory, misalignment, or arithmetic problems are not checked. Whether they cause a trap, another execution-environment response, or behavior outside a valid execution contract is **documented_only**. The supplied evidence does not establish recovery or rollback.

## Acceptance examples

These are conditional contract examples, not observed executions. They assume valid ordinary memory, stable address-selection values, permitted alignment, and representable address calculations.

### Ordinary replacement

The first argument references storage containing base address `0x2000`. The third argument represents address `0x3000`, and the displacement stored at `0x3004` is `0x10`.

The selected destination is `0x2010`.

If that destination initially contains the four-byte value `0x11223344` and the replacement is `0xAABBCCDD`, the function returns `0x11223344` and leaves `0xAABBCCDD` at `0x2010`.

### Zero displacement

If the stored displacement is zero, the selected destination is the stored base address itself. This does not normally mean the destination is the first argument’s storage: that storage contains the base address but may reside elsewhere.

### Byte displacement

If the base is `0x2000` and the displacement is four, the selected destination is `0x2004`. Selecting `0x2010` would incorrectly apply element scaling.

### Replacement equals the previous value

If the destination and replacement both contain `0xDEADBEEF`, the result is `0xDEADBEEF`, and the destination retains that value. The contract still includes the write.

### Destination aliases base storage

Suppose the first argument points to `0x1000`, the stored base is `0x1000`, and the displacement is zero. The destination is therefore the base-address storage itself.

With replacement `0x55667788`, the function returns the old four-byte base value and writes `0x55667788` at `0x1000`. It does not follow the newly written value as another address.

### Negative displacement

If the environment interprets the displacement as signed 32-bit data, a base of `0x2000` and displacement of negative four select `0x1FFC`, provided the resulting access is valid.

This example establishes no behavior for overflowing subtraction or invalid destination storage.
