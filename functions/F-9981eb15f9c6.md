## Behavior

The following phases preserve the represented ordering of memory events. Within each phase, “then” denotes order, not merely a final-state relationship. Descriptive names identify retained values, not memory locations that are implicitly reread.

Aliasing is unrestricted by the supplied evidence. Consequently, an earlier store may affect any later read whose address overlaps it.

### 1. Initial association and five repetitions

The first four writes occur in this order:

1. Four bytes containing the first argument at second argument plus `0x54`.
2. The primary base’s low byte at secondary base plus `0x19`.
3. The secondary base’s low byte at primary base plus `0x11`.
4. Four bytes containing the second argument at secondary base plus `0x34`.

Next come five repetitions of the same ordered four-write group:

- First argument, four bytes, at doubled primary base plus `0x54`.
- Primary low byte at secondary base plus `0x19`.
- Secondary low byte at primary base plus `0x11`.

The doubled base uses the unsigned arithmetic described above. The repeated byte values derive from the incoming bases, not from reads of the destinations.

These repetitions are part of the represented access sequence. They cannot be collapsed solely because ordinary, non-aliased memory would retain the same final values.

### 2. Early captures with an intervening global write

The function first reads the four-byte global source at `0xA9`, retaining a **global snapshot**. It then reads four bytes at first argument plus `0x74`, retaining the **argument payload**.

Only after both reads does it write the formula result to global byte `0x3A`. The formula doubles the primary base’s character-sized low-byte interpretation and adds decimal `48`, then stores a byte. No digit-range check or textual-formatting contract is established.

After that global write, it reads and retains:

- The **saved tertiary payload**, four bytes at tertiary base plus `0x14`.
- The **saved primary payload**, four bytes at primary base plus `0x04`.

Their order is significant: the formula write precedes both captures and can change either captured value through aliasing. Neither the global snapshot nor the argument payload is reread after that write.

### 3. Initial ambient mutations and global-byte copy

The next writes occur in this order:

- Primary low byte at tertiary base plus `0x0D`.
- Byte `108` at primary base plus `0x08`.
- Secondary low byte at primary base plus `0x0D`.
- Secondary low byte at primary base plus `0x09`.
- Tertiary base, four bytes, at tertiary base plus `0x54`.

The function then writes the global snapshot’s low byte to `0x67`.

Next, it reads four bytes at tertiary base plus `0x44`, retaining the **tertiary field**. Only after that read does it read byte `0x67` and copy that freshly read byte to `0x21`.

Thus, the tertiary self-association precedes the write to `0x67`, and the tertiary-field read lies between that global write and the global-byte copy. The copied byte is obtained from storage at that moment, not directly from the retained global snapshot.

### 4. Tertiary-field propagation and overlapping primary write

The retained tertiary field supplies, in order:

- Its low byte to primary base plus `0x10`.
- Its full four-byte value to secondary base plus `0x54`.
- A shifted result’s low byte to tertiary base plus `0x01`.

The shift uses the tertiary field as a signed 32-bit value and the primary base’s low eight bits as the count. Counts outside `0` through `31`, and right shifts of negative values, require an unavailable machine-arithmetic contract.

Next, secondary base plus `0x54` receives the primary base as four bytes, replacing the earlier tertiary-field association at that address if no intervening aliasing changes the interpretation.

The function then:

- Reads and retains four bytes at primary base plus `0x40`.
- Writes the saved primary payload to secondary base plus `0x74`.
- Writes the just-retained value as four bytes at primary base plus `0x10`.

The read at primary offset `0x40` therefore precedes the secondary-offset-`0x74` store, which precedes the primary-offset-`0x10` store. Aliasing can make that distinction observable.

The last store covers primary offsets `0x10` through `0x13`, including the earlier byte stores at offsets `0x10` and `0x11`.

### 5. Two separate global-byte reads around target loading

The function writes the tertiary base as four bytes at secondary base plus `0x44`.

It then performs the **first fresh read** of global byte `0x67` used for primary offset `0x09`, and writes that byte to primary base plus `0x09`.

Next, it writes the primary low byte to tertiary base plus `0x09`, followed by the retained global snapshot as four bytes at primary base plus `0x44`.

It then reads four bytes at primary base plus `0x54`, retaining the **primary target**.

### 6. Primary-target propagation and tertiary restoration

After that write, tertiary base plus `0x54` receives the saved tertiary payload as four bytes.

The function then reads four bytes at primary base plus `0x14`, retaining the **late primary payload**. This read follows both preceding stores. It occurs before the argument payload’s low byte is written to tertiary base plus `0x11`.

Next:

- Primary base plus `0x09` receives the primary target’s low byte.
- Primary base plus `0x44` receives the primary target as four bytes.
