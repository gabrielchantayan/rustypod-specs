# F-2bc23d9db473

## Purpose

F-2bc23d9db473 selects one of two fixed displacements from a supplied base value, or returns zero, according to a directional compatibility check between two records.

The established behavior examines an unsigned 16-bit field at byte offset 28 in each record. It compares those fields against three externally stored comparison values and, on one path, against the fixed values `0xC420` and `0xC422`.

The result is one of:

- Zero, indicating rejection by the comparison logic.
- The supplied base plus 40 bytes.
- The supplied base plus 48 bytes.

“Compatibility,” “record,” and “base” are descriptive terms. The supplied evidence does not establish a domain-specific type system, the meaning of the selected locations, or whether the result is subsequently used as an address.

## Behavior

### Initial classification

The function first reads the left record’s unsigned 16-bit field at byte offset 28. The resulting value is retained for subsequent left-side comparisons.

The first comparison is against A. This gives A priority over B, C, and the two fixed values when external comparison values overlap.

If the left field equals A:

1. The right record’s field is read and compared against A.
2. Equality immediately selects the base-plus-40 result.
3. Otherwise, the function reaches a final right-field comparison against C.
4. Equality with C selects base plus 40; inequality returns zero.

Consequently, for stable external values and stable record contents, a left field equal to A permits a right field equal to either A or C.

The failed comparison against A does not retain a right-field snapshot for the final comparison. The supplied representation performs another right-field load for the comparison against C. If the right record can change between those reads, the second observation may differ from the first.

### B classification

If the left field does not equal A, the function compares it against B.

If it equals B:

- A right field equal to B selects base plus 40.
- A right field unequal to B returns zero immediately.

This path does not fall back to accepting a right field equal to C. If B and C differ, a left field equal to B and a right field equal only to C are rejected.

When A and B have equal stable values, the earlier A path controls; the B-specific rejection rule is not reached.

### C classification

If the left field matched neither A nor B, it is compared against C.

A match proceeds to the final right-field comparison against C:

- Equality selects base plus 40.
- Inequality returns zero.

Before entering fixed-value handling, the represented logic also includes another comparison of the retained left value against A when the preceding comparison against C failed. Under stable external values, this repeated comparison cannot newly succeed: the initial comparison against A already failed. It must nevertheless not be treated as evidence that A is immutable or that an external read can always be eliminated.

If that later comparison observes equality with A, execution reaches the final right-field comparison against C.

### Fixed-value classification

Fixed-value handling is reached only after the preceding classification comparisons fail.

This path accepts only left-field values `0xC420` and `0xC422`. All other left-field values return zero without reading the right record’s field on this path.

For either accepted fixed left value:

- The right field must equal the retained left field.
- Equality selects base plus 48.
- Inequality returns zero.

The two fixed values are not mutually compatible. A left field of `0xC420` and a right field of `0xC422`, or the reverse pairing, is rejected when this path is reached.

The represented arithmetic includes an unsigned subtraction by `0xC000` when the left value is not `0xC422`. Comparison of the result with `0x420` recognizes `0xC420`. For a left field in the unsigned 16-bit range, this check introduces no additional accepted values. Inputs below `0xC000` are not accepted by unsigned wraparound.

Recognition of `0xC422` bypasses that subtraction.

### Stable-state decision table

The following table assumes that the external comparison values and record fields remain stable throughout the call. Rows are evaluated in order; “otherwise” means no preceding row matched.

| Left-field classification | Required right field | Result |
|---|---|---|
| Equal to A | A or C | Base plus 40 |
| Otherwise, equal to B | B | Base plus 40 |
| Otherwise, equal to C | C | Base plus 40 |
| Otherwise, `0xC420` | `0xC420` | Base plus 48 |
| Otherwise, `0xC422` | `0xC422` | Base plus 48 |
| Otherwise | No right-field requirement can accept | Zero |

A row whose required right-field condition fails returns zero.

This is a directional relation, not an established symmetric one. In particular, acceptance of a left A/right C pair does not imply acceptance of a left C/right A pair.

## Acceptance examples

These examples are conditional specifications, not executed tests. Unless stated otherwise, external values and record contents remain stable, the record loads are valid, and result arithmetic is representable.

1. **A accepts itself.**  
   If the left and right fields both equal A, return base plus 40. Overlap between A and other comparison values does not change this result because the A classification has priority.

2. **A permits C.**  
   If A differs from C, the left field equals A, and the right field equals C, return base plus 40 after the initial right-field comparison against A fails.

3. **The reverse pairing need not pass.**  
   If A, B, and C are distinct, a left field equal to C and a right field equal to A return zero.

4. **B does not inherit A’s alternative.**  
   If A, B, and C are distinct, a left field equal to B and a right field equal to C return zero. Equal B fields return base plus 40.

5. **Each fixed value requires exact pairing.**  
   If neither fixed value is captured by an earlier classification, equal `0xC420` fields return base plus 48, and equal `0xC422` fields also return base plus 48. Mixing the two returns zero.

6. **External values can override fixed-value treatment.**  
   If A is `0xC420`, equal `0xC420` fields return base plus 40, not base plus 48.

7. **Unrecognized left values reject early.**  
   If the left field matches none of A, B, C, `0xC420`, or `0xC422`, return zero without reading the right field.

8. **Aliased record arguments are allowed by the shown logic.**  
   If both record arguments designate the same valid field and it is stable, a recognized field passes its corresponding equality condition. An unrecognized field still returns zero.

9. **Concrete non-overflowing base.**  
   For a base of `0x1000`, an accepting 40-byte branch returns `0x1028`; an accepting 48-byte branch returns `0x1030`.
