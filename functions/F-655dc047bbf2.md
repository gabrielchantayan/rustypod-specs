# F-655dc047bbf2

## Purpose

F-655dc047bbf2 performs a stateful transition for a channel resolved from an input descriptor. It captures descriptor fields, reads a selector and a requested-bit position, performs preparation, and evaluates admission.

A rejected request produces a notification and returns zero. An accepted request resolves and activates a selector-specific object, updates masks and conditional status, reports or stores state, and normally returns one.

“Channel,” “selector,” “permission,” and “status” describe observed roles, not established application-domain meanings. Rejection is not transactional: counter increments, calls, and writes occur before admission and are not comprehensively reversed.

## Interface

### Arguments and descriptor

The two arguments are:

| Argument | Observed representation and use |
|---|---|
| Context | Opaque 32-bit value forwarded to dependencies. |
| Descriptor | Address represented as 32 bits; passed to channel resolution and directly dereferenced. |

The descriptor fields used are:

| Byte offset | Width | Use |
|---|---:|---|
| +8 | 32 bits | Address of selector data. |
| +12 | Unsigned 16 bits | Captured length, zero-extended to 32 bits. |

The data address is captured first, followed by the length. Both captures precede F-5f5f14cedda3 and F-a2715f79cdcc.

Only after those two calls does the function perform two separate reads through the captured data address:

1. Read one byte and interpret it as signed 8-bit, sign-extended to a 32-bit selector.
2. Read the byte again, interpret it as unsigned, and use it as the shift count for a 32-bit single-bit mask.

Equality of these two observed bytes requires stability between the reads. Neither the earlier dependencies nor concurrent mutation may be assumed harmless. Changes to the descriptor’s pointer field do not redirect these reads, because the data address has already been captured.

There is no initial null check or minimum-length check. Even a captured length of zero does not suppress either initial byte read. Selector 5 can cause a later read at captured data address +3, but only when the captured length is at least four.

For shift counts 0–31, the requested mask contains the corresponding bit. Behavior outside that range is not established. A negative signed selector is not itself rejected by the upper-bound comparison.

### Results, errors, and preconditions

The ordinary result is a 32-bit value:

- **0:** rejected after preparation and a failure notification.
- **1:** accepted path reaches its end.

A null selector-specific object invokes F-a817d8d58c10, identified as non-returning. No ordinary fallback result is established.

Required execution conditions include readable input memory, valid channel-indexed storage, valid shared-state and object pointers, callable virtual targets, and defined shift behavior. Channel indices are not visibly range-checked. Address calculations use channel-scaled offsets; behavior outside valid backing storage is not established.

Most dependency results are ignored. No general exception, rollback, or dependency-error translation contract is visible.

The function performs no explicit heap allocation or direct memory release. It supplies temporary-memory addresses to dependencies. Copying, retention, mutation, ownership transfer, and lifetime requirements of those dependencies remain unknown.

## Behavior

### Preparation before admission

After channel resolution and token acquisition, and after the two selector-data reads, separate shared-state accessor calls supply arguments for:

1. F-62d1a359629f, saving the original channel mask.
2. F-c1e400b68436, saving the original channel mode.
3. F-40c28640bfd1, obtaining a related-channel identifier.

The first two receive an accessor-derived subobject at offset +4. Accessor results are not guaranteed identical across calls.

A per-channel 32-bit counter is incremented through signed access. Signed-overflow behavior is unresolved. A later comparison reads this storage as unsigned.

Preparation then proceeds in this order:

1. For channel 1, call F-704f99fd5e22 with context, channel 1, pointers to 32-bit values `0xFFFF` and `0x36`, and a final zero.
2. For every channel, call it with context, the selected channel, pointers to `0xFFFFFFFF` and `0x38`, and zero.
3. Call F-352a899fb784 with context, the captured token, and 1.
4. Obtain an object through F-15643c36365d and invoke its virtual target at byte offset +72.
5. If that query returns nonzero, obtain an object again and invoke its virtual target at +68 with that object and zero. The second object is not guaranteed to equal the first.
6. Call F-ebd9fed2fee8 with newly obtained shared state and the selected channel.
7. Call F-ca1c4e2f14bb with context, channel, and 1.
8. Write `0xFF` at byte +4 of the channel’s 36-byte table entry.
9. Call F-2250ce450b3d with newly obtained shared state, channel, and `0xFFFFFFFF`.
10. Call F-646d64bbe501 with context, channel, and 1.

If the captured related-channel identifier is nonzero:

- Obtain its mask through F-62d1a359629f and store it in the third word of a three-word temporary array.
- Call F-334068ea5e0c using another accessor-derived +4 subobject, then F-ebd9fed2fee8 using another accessor result, both for the related channel.
- Write `0xFF` at byte +4 of that channel’s 36-byte entry.
- Test the temporary array’s third word for nonzero.
- If nonzero, initialize the first two words to `0xFFFFFFFF` and `0x3B`. Call F-704f99fd5e22 with context, the **original channel**, pointers to those first two words, and zero.
- Subsequently call F-da3be2b0546d with context, the **related channel**, and a **reread of the third word**.

The last argument is not guaranteed to equal the originally retrieved related-channel mask. F-704f99fd5e22 receives pointers into the array, and no preservation contract establishes that its third word remains unchanged.

Finally, separate accessor calls supply +4 subobjects for F-334068ea5e0c and F-67b16ca5ec28 on the original channel; the latter also receives 1.

### Admission and rejection

After preparation, the function captures a shared-state base for subsequent rejection classification.

Admission short-circuits in this order:

1. Reject channel 4.
2. Reject a signed selector above 5 for channel 1, or above 0 for any other channel.
3. Reject if the requested bit is absent from the 32-bit permission mask at shared-state offset +40.
4. Otherwise call F-87c09191bebe with context, channel, and requested mask; reject if its result is zero.

The recorded predicate result initially equals one. Skipping the predicate leaves that value unchanged.

On rejection, F-a6e52da0a17c receives the channel and saved original-channel mask. Only afterward does rejection classification read masks through the captured shared-state base. The reason is selected in this priority order:

| Priority | Condition | Reason |
|---|---|---:|
| 1 | Requested bit present at +44 | 1 |
| 2 | Recorded predicate result is zero | 5 |
| 3 | Signed selector below 13 and requested bit absent at +40, or channel is 4 | 3 |
| 4 | Otherwise | 4 |

These later mask reads may differ from admission-time contents, including because F-a6e52da0a17c can mutate state. Replacing the global shared-state base does not redirect reads through the already captured base.

The function explicitly initializes the failure-record fields described under **Side effects**, submits 20 bytes through F-c6c589453fa8 with two leading zero arguments, and returns zero.

### Accepted object and masks

F-9266831caef7 receives a newly obtained shared-state +4 subobject and the signed selector. A null result invokes F-a817d8d58c10.

F-da3be2b0546d is then called with context, channel, and a mask derived from the saved original-channel mask:

- If saved mode is not 1, pass the saved mask unchanged.
- If saved mode is 1, clear requested bits except bit 4. Preserve bit 4 only if it was already set; do not newly set it.

The function derives:

- **Working mask:** initially the requested mask.
- **Companion mask:** initially the requested mask with bit 0 added.

Channel 1 adds bit 2 to both masks. For channel 1 with selector 4, F-f82bb660a2ac receives a newly obtained +4 subobject and argument 3. Its result is compared as unsigned; a result below 2 adds bit 3 to both masks.

F-1cd96d01ddae receives channel and working mask; F-9ef7726bf517 receives channel and companion mask. Each uses a separately obtained +4 subobject.

For channel 1, F-2708b7c79728 receives 1 and a pointer to a 32-bit temporary containing signed selector plus 16. An unidentified external operation then receives `0x23`. The addition remains within signed 32-bit range for every sign-extended input byte.

### Activation, reporting, and status transition

The function captures the address of a global object slot. If its current object is nonzero, it invokes that object’s virtual target at +28 and afterward clears the **captured slot**. Ownership effects are unknown.

The selector-specific object is invoked through its virtual target at +12 with object, 4, and channel.

Next, the function captures a shared-state base, calls the acquire-like operation with its +92 handle, and reads the 32-bit field at +52. It narrows that value to its low eight bits and interprets those bits as signed. This captured value is the reported state.

After F-88707f7d96dd receives context and channel:

- If captured reported state is 100, write 1 at captured base +32 + channel, prepare a nearby 32-bit temporary containing 2000, and call F-43ce968102ca with context, channel, a global opaque argument, `0x38`, and zero. Store a pending notification in the channel’s 20-byte slot.
- Otherwise, initialize and immediately submit the ordinary-success temporary record.

The comparison uses the captured reported state, not a post-call reread.

The status-transition gate first reads the channel’s unsigned status byte. Its first condition succeeds if that value is no greater than proposed status, or proposed status is 2. If that condition succeeds, another status-byte read must be below 4. With stable storage, this permits status 3 to become 2 but prevents replacement of statuses 4 or higher.

After a permitted transition, write proposed status and perform the applicable effects:

- **Proposed status 2:** prepare a 32-bit temporary of 800, changing it to 1 if the current unsigned counter exceeds 3. Call F-43ce968102ca with code `0x37` and the working mask.
- **Proposed status 4:** set a separate per-channel flag to 1.
- **Proposed status at least 4:** if captured signed reported state exceeds 15, set another channel flag; submit a reason-14 record with field +4 rewritten to 100.

Finally, reread the +92 handle through the captured reporting-phase base, call the release-like operation, and return one. Equality with the earlier acquisition handle is not guaranteed.

## Side effects

### Notification initialization and reuse

Records occupy 20 bytes in target representation:

| Offset | Width | Failure initialization | Initial success initialization |
|---|---:|---|---|
| +0 | 8 bits | Selected failure reason | 0 |
| +1–+3 | Three bytes | Not explicitly initialized | Not explicitly initialized |
| +4 | 32 bits | 16 | Captured signed reported state, represented in 32 bits |
| +8 | 32 bits | Channel | Channel |
| +12 | 32 bits | Zero | Zero |
| +16 | 32 bits | Original requested mask | Working mask |

Immediate submission passes all 20 bytes, including bytes +1–+3. Pending storage explicitly writes the same success fields, with reported state 100, but does not initialize its three intervening bytes.

The later reason-14 submission reuses the temporary record. It explicitly rewrites **only**:

- Reason byte at +0 to 14.
- 32-bit field at +4 to 100.

It does not restore +8, +12, or +16. On ordinary success, F-c6c589453fa8 has already received this same temporary record. Without a nonmutation contract, the later submission cannot be guaranteed to contain the original channel, zero, or working mask in those fields. The same limitation applies to the record’s other retained bytes.

On the reported-state-100 path, the first notification is stored separately rather than submitted. The temporary’s +8, +12, and +16 fields are nevertheless initialized before possible reason-14 reuse.

### Persistent state

Direct writes include the counter increment, channel-entry markers, captured object-slot clearing, special-state flag, pending-record fields, conditional status replacement, and additional status flags. Table bases loaded later need not match earlier bases if intervening dependencies mutate globals.

Dependency effects are additional and unspecified. No complete rollback is visible.

## Acceptance examples

These are conditional static expectations, not executed tests. Assume valid memory, defined arithmetic, and returning dependencies unless stated otherwise.

1. **Separate selector observations:** If the signed read observes 1 and the following unsigned read observes 4, admission uses signed selector 1 and requested mask `0x10`. Equality is not an invariant without input stability.

2. **Channel 4:** Preparation still occurs, but the predicate is skipped. Rejection reason is 1 if the +44 mask contains the requested bit at classification time; otherwise 3.

3. **Channel 1, selector 6:** With stable selector data, defined shift, permission present, and no rejection-mask bit, the ceiling rejects before the predicate. Reason is 4.

4. **Predicate failure:** For channel 1, selector 1, permission present, and predicate result zero, reason is 5 unless the later +44 mask gives reason 1 priority.

5. **Related-array mutation:** If the retrieved third word is nonzero but F-704f99fd5e22 changes it to zero, F-da3be2b0546d receives zero. The earlier nonzero test is not repeated.

6. **Selector 4 masks:** Accepted channel 1, selector 4, and query result 1 produce working mask `0x1C` and companion mask `0x1D`. Query result 2 omits bit 3.

7. **Saved mode 1:** Saved mask `0x15` with requested bit 0 produces `0x14`; requesting bit 4 leaves `0x15`.

8. **Captured selector-4 base:** If acquisition replaces the global base, the conditional +52 read still uses the captured base. If the optional operation changes that base’s +92 handle, release receives the changed handle.

9. **Record reuse:** If ordinary-success submission changes field +8 and a reason-14 submission follows, this function does not restore +8. Only reason 14 and field +4 equal to 100 are explicitly reestablished.

10. **Status 3 to 2:** With stable status storage, proposed status 2 replaces 3. The `0x37` call occurs; the nearby temporary is 1 when the unsigned counter exceeds 3, otherwise 800.

11. **Null selector object:** The non-returning dependency is invoked after preparation and admission. A zero-result fallback is not established.
