# F-343f48b6323a

## Purpose

F-343f48b6323a examines an input, optionally searches a collection through a special lookup operation, and otherwise invokes a processing dependency. A caller-controlled flag enables a second collection search after a zero processing result and a separate dependency call after a nonzero processing result.

The signed 32-bit return value has several distinct origins:

- A positive value written by the initial dependency.
- The captured collection’s current signed count plus one, when the initial dependency selects an immediate return but its output is nonpositive. This result can be positive, zero, or negative without overflow: a count of −3 produces −2.
- The shared index slot’s current value plus one after a search selects a match. Interpreting this as the matched entry’s one-based position requires dependencies to preserve that slot as described below.
- Explicit −1 on two failure branches.
- Zero after processing paths that do not return a search-derived value.

Consequently, −1 is not uniquely an explicit failure indication: a count of −2 also produces −1 through the initial fallback. Likewise, zero does not establish successful processing.

“Lookup,” “processing,” and “match” describe roles in this caller. Their application-level meanings are inferred, not established. This contract is based on static evidence only; no runtime tests have been performed.

## Interface

The function accepts six arguments.

| Argument | Observed representation | Established use |
|---|---|---|
| Owner | Pointer to 32-bit words | Passed to processing-related dependencies; its first word is read for special lookup. |
| Collection holder | Pointer to 32-bit words | Its first word supplies the captured collection address. Its word at byte offset 12 is later copied into the processing context. |
| Input | Byte-addressable pointer | Passed to dependencies; its first byte selects a branch. A field at byte offset 20 participates in special lookup. |
| Unused argument | 32-bit value | Not read or forwarded by the visible function. |
| Handling/search flag | Signed 32-bit integer | Zero disables the post-processing search and the failure-handling call. Every nonzero value enables them on their respective branches. |
| Optional marker | Nullable pointer to one byte | Conditionally receives byte value 1. Never explicitly cleared. |

The return representation is signed 32-bit. Pointer-bearing fields occupy 32-bit words in the supplied representation; this does not establish portability to a different address model.

### Collection representation

The collection address is captured from the holder before the first dependency call. Subsequent collection accesses use that captured address rather than reloading the holder’s first word.

| Collection byte offset | Access |
|---|---|
| 0 | Signed 32-bit count |
| 12 | 32-bit entry-array address |

Entries have a 12-byte stride.

| Entry byte offset | Access |
|---|---|
| 0 | 32-bit value supplied to F-728a4665dcf4 |
| 4 | 32-bit value tested against zero and, if nonzero, supplied to F-e6db2171781a |
| 8 | Not directly accessed |

The count and entry-array address are not snapshotted for either search.

### Input representation

The function directly accesses:

- The tag byte at offset 0.
- For tag `X`, the pointer-valued field at offset 20 and the first byte at its stored address.
- For special lookup, the address of the field at offset 20, passed to F-e7c4e7dd076d.

Passing the field’s address is distinct from passing the pointer value stored there. No complete input layout, string extent, or encoding is established.

### Shared output/index storage

One local signed 32-bit slot serves three roles:

1. Output storage passed by address to F-f0a3db50e317.
2. The special-search index.
3. The post-processing-search index.

The slot is not initialized before the initial call. Each search explicitly resets the same slot to zero before testing its loop condition.

Whether F-f0a3db50e317 retains the address is unknown. Later dependencies therefore cannot be assumed to preserve the slot merely because it is not explicitly passed to them.

### Preconditions

The function performs no explicit pointer, bounds, or lifetime validation. Storage must be valid for every access actually reached, including accesses selected by dependency-modified state.

In particular:

- The holder must permit the initial address load.
- The captured collection must remain valid when its fields are accessed.
- The input must satisfy F-f0a3db50e317’s requirements even if execution returns before tag inspection.
- Reached tag and pointed-byte reads require readable storage.
- Reached owner and holder field reads require readable 32-bit words.
- Each entry access requires valid storage at the address calculated from the then-current array address and index.
- A reached marker write requires a writable byte.
- The initial dependency must define its output slot if it selects the immediate-return branch.

Negative collection counts are not excluded by these preconditions. Dependency-specific requirements remain unknown.

## Behavior

### Initial check and immediate return

The first visible operation captures the collection address from the holder. The function then calls F-f0a3db50e317 with the input and the shared slot’s address.

If the dependency returns nonzero:

- A positive signed slot value is returned directly.
- Otherwise, the function reads the captured collection’s current signed count and returns that count plus one.

This branch performs no tag classification, special lookup, context construction, marker write, or collection search. The count is read after the dependency call, so a dependency-side count change can affect the fallback result.

If the dependency returns zero, its slot output does not determine the next branch. Any search subsequently reached initializes the slot independently.

### Special-lookup selection

After a zero initial result, special lookup is selected by either condition:

- The input tag is hexadecimal `17`.
- The tag is `X` and the first byte addressed by the pointer field at input offset 20 is not an apostrophe.

The conditions short-circuit. Tag hexadecimal `17` does not require the pointed-byte read for classification. Tags other than hexadecimal `17` and `X` go directly to processing. Tag `X` requires the pointed-byte read.

Special lookup calls F-e7c4e7dd076d with:

1. The owner’s current first 32-bit word.
2. The address of the input field at byte offset 20.

A zero return causes an immediate explicit −1 return, regardless of the handling/search flag. Processing is not attempted.

### Special search

A nonzero lookup result is held for the search and the subsequent F-94cb53877c15 call.

The function writes zero into the shared index slot. Before each entry access, it compares the slot’s current signed value with the captured collection’s current signed count. If the index is not less than the count, the search ends.

For a passing condition, the function obtains the collection’s entry-array address and uses the slot’s current value with the 12-byte stride to read the entry field at offset 4. A zero field skips the comparison call. A nonzero field is passed to F-e6db2171781a as the first argument, with the lookup result second.

A zero comparison result selects a match. The function then:

1. Calls F-94cb53877c15 with the lookup result.
2. Reads the shared slot after that call.
3. Returns that value plus one.

It does not save the accessed entry’s index for the return. Both the comparison call and F-94cb53877c15 may affect the slot if dependencies have retained access to it.

If the entry is skipped or the comparison returns nonzero, the function increments the slot’s then-current value by one, writes the result back, and repeats the condition check. The increment is not necessarily based on the index used to access the preceding entry.

On ordinary exhaustion, F-94cb53877c15 is called with the lookup result before processing begins. Thus each normally completing path after a nonzero lookup result makes exactly one such call, whether it finds a match or falls through. This establishes neither ownership nor release semantics.

**Conditional traversal guarantee:** if dependencies preserve the shared slot, the search visits eligible entries in increasing index order from zero, and a match returns the accessed entry’s one-based position. Without that assumption, later indices and the return are determined by the slot’s current contents. Count and array-address mutations can independently affect traversal.

### Processing-context preparation

Processing is reached directly from tag classification or after an exhausted special search.

An unidentified initialization dependency receives the address of local context storage and the numeric size 36. The visible function then performs these context writes in order:

| Order | Context byte offset | Write |
|---|---:|---|
| 1 | 4 | Holder’s current 32-bit word at byte offset 12 |
| 2 | 20 | Byte value 1 |
| 3 | 16 | 32-bit zero |
| 4 | 0 | Owner address |
| 5 | 8 | Captured collection address |

The holder field is read at this stage, not when the collection address was captured.

The context byte at offset 21 is inspected later on one branch but is not explicitly initialized by this function. The initializer’s effect on that byte is unknown.

F-efc2c252d6ce is then called with the context address and input.

### Zero processing result

If F-efc2c252d6ce returns zero, the function first reads context byte offset 21. If it is nonzero and the optional marker is non-null, the function writes byte value 1 through the marker.

This write precedes any post-processing search. If the marker aliases collection or input storage, its direct write may affect subsequent behavior.

With a zero handling/search flag, the function then returns zero.

With a nonzero flag, it resets the shared index slot to zero and searches the captured collection. Each iteration:

- Tests the slot’s current signed value against the collection’s current signed count.
- On a passing condition, reads the entry-array address and uses the slot’s current value to obtain the entry’s offset-0 field.
- Calls F-728a4665dcf4 with that field and the input, including when the field is zero.

A nonzero predicate result causes an immediate return of the shared slot’s value **after the predicate returns**, plus one. No post-call index validation occurs.

A zero predicate result causes the slot’s then-current value to be incremented by one before the next condition check. Exhaustion returns zero.

Increasing entry order and a one-based matched position are guaranteed only if dependencies preserve the slot. The count and array address remain dynamically read fields.

### Nonzero processing result

If F-efc2c252d6ce returns nonzero:

- A zero handling/search flag causes an explicit −1 return.
- A nonzero flag causes a call to F-225d0f6e8fad with the owner address, followed by a zero return. Its result is ignored.

This branch does not inspect context offset 21, directly write the marker, or run the post-processing search.

### Integer and address boundaries

Counts, the shared slot, comparisons, increments, and return additions use signed 32-bit representations. Entry addressing uses a 12-byte stride.

With a preserved index and an unchanged nonpositive count, either search performs no entry accesses. Without index preservation, a negative index can satisfy the signed condition against a nonnegative count; there is no separate lower-bound check.

The initial fallback permits negative results without overflow. For example, count −3 yields −2, and count −1 yields zero. Count equal to the signed 32-bit maximum makes its addition by one exceed the signed range.

A dependency-modified slot may likewise make an increment, return addition, or entry-offset calculation exceed representable bounds. The static representation does not establish wrapping, saturation, trapping, or another portable outcome. These cases remain documented_only.

## Side effects

Direct writes comprise local context writes, shared-slot writes, and the conditional marker write. The function does not directly assign owner fields, holder fields, collection fields, entries, or input fields, except where the marker aliases such storage.

This does not establish immutability:

- F-f0a3db50e317 receives the shared slot’s address.
- F-e7c4e7dd076d receives an input field’s address.
- F-efc2c252d6ce receives a context containing owner and collection addresses.
- Dependencies may access shared state through other means.

No dependency is assumed to preserve globals, collection storage, input, or the shared slot. Retention of local addresses, its legality, and any use after this invocation are unresolved. The contract supplies no extended lifetime for local storage.

The marker is sticky only with respect to direct writes by this function: it can be set to 1 but is never explicitly cleared. Dependencies and aliasing may still change the same byte.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid reached storage, representable arithmetic, normal dependency returns, and no state mutations beyond those described.

1. **Positive initial output.** F-f0a3db50e317 returns nonzero and writes 7. The function returns 7 without inspecting the tag.

2. **Negative initial fallback.** The initial dependency returns nonzero and writes zero. The captured collection’s count is −3 when read. The function returns −2, not an explicit failure constant.

3. **Overlapping numeric outcomes.** With a nonpositive initial output, count −2 yields −1 and count −1 yields zero. These values arise without special lookup or processing.

4. **Lookup failure.** The initial result is zero, tag is hexadecimal `17`, and F-e7c4e7dd076d returns zero. The function returns explicit −1 regardless of the handling/search flag.

5. **Ordinary special match.** Dependencies preserve the index. The first entry is skipped or compares nonzero; the second compares zero. F-94cb53877c15 is called, then the function returns 2 without processing.

6. **Special-match return uses the modified slot.** A comparison on index zero returns zero. Through retained access to the slot, F-94cb53877c15 changes it to 6 before returning. The function returns 7, even though the accessed entry was index zero.

7. **Nonmatch increment uses the modified slot.** A comparison on index zero returns nonzero after changing the slot to 1. The loop increments it to 2. If the count is 3 and storage remains valid, the next accessed entry is index 2; index 1 is skipped.

8. **Apostrophe bypass.** The initial result is zero, tag is `X`, and the pointed-to byte is an apostrophe. Processing begins without special lookup.

9. **Marker precedes search.** Processing returns zero, context byte 21 is nonzero, and the marker is non-null. The marker receives 1 before any enabled post-processing predicate call.

10. **Post-processing return uses the modified slot.** F-728a4665dcf4 is called for index zero, changes the retained slot to −3, and returns nonzero. The function returns −2; it does not recheck bounds before returning.

11. **Processing outcome depends on the flag.** A nonzero processing result yields explicit −1 with a zero flag. With a nonzero flag, F-225d0f6e8fad is called and the function returns zero.

12. **Empty special search still makes the follow-up call.** With a nonzero lookup result and an unchanged nonpositive count, no entry comparison occurs. F-94cb53877c15 is nevertheless called before processing.
