# F-8ce98f7f0631

## Purpose

F-8ce98f7f0631 obtains an object pointer from F-e8a212ddd880, performs three direct initialization writes, invokes three additional initialization operations on interior addresses, and returns the original object pointer.

The established behavior is an ordered initialization sequence. It is not sufficient evidence that the function allocates memory, constructs a particular class, clears an entire object, or transfers ownership to its caller. Those interpretations depend on contracts that are not available.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred intent:** plausible interpretations that are not required behavior.
- **documented_only unknowns:** properties that cannot be established without dependency contracts, calling-convention information, or runtime evidence.

No runtime tests have been performed.

2. **Install the global initialization word.**  
   Read the global initialization word after F-e8a212ddd880 has returned, and write that 32-bit value at offset 0x000.

   This ordering matters: if F-e8a212ddd880 changes that global, the represented operation uses the value available after that call, not a value captured before it.

3. **Clear one byte.**  
   Write the byte value zero at offset 0x11E. This is a one-byte write, not an established clearing of an adjacent word or larger region.

4. **Store the incoming word.**  
   Write the incoming 32-bit value at offset 0x0F8.

   Invoke F-6d1a8c02b947 with:

### Meaning of the three interior-address calls

The three starting offsets are separated by exactly 11 bytes:

- 0x107 − 0x0FC = 11.
- 0x112 − 0x107 = 11.

Each call also receives the value 11. This supports an inference that the calls concern three adjacent, equally sized regions. It does not establish that interpretation as a dependency contract.

**Conditional layout interpretation:** if each dependency treats its second argument as a byte count and accesses exactly that many bytes beginning at its first argument, the regions would be:

| Call | Conditional byte interval |
|---|---|
| First | 0x0FC–0x106 |
| Second | 0x107–0x111 |
| Third | 0x112–0x11C |

Under that interpretation, the regions are adjacent and non-overlapping. Offset 0x11D lies immediately after the third region, and the explicitly cleared byte at 0x11E lies one byte farther on.

The supplied evidence does not establish that these operations are fills, copies, string operations, constructors, or bounded writes. It also does not establish that the numeric argument is a byte count, a length, or an extent. Those meanings remain documented_only.

### Final-state limits
