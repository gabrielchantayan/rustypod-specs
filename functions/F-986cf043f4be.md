# F-986cf043f4be

## Purpose

F-986cf043f4be conditionally dispatches a request through an externally obtained service and, on one branch, passes decoded request values and an optional object-produced value to F-043b2a28b7b3.

The established behavior has two distinct outcomes:

- If the request discriminator is not 10, or the service’s status operation returns a nonzero value, the function returns a 64-bit result containing the original request address in the upper 32 bits and the constant 4 in the lower 32 bits.
- If the discriminator is 10 and the service’s status operation returns zero, the function decodes three values, performs an object lookup, optionally invokes F-043b2a28b7b3, and calls F-feee9156a257. That final dependency is identified in the supplied evidence as non-returning.

The apparent intent is to handle one request category when a service permits it. The meanings of the discriminator, service status, decoded fields, and terminal operation are not established.

## Behavior

### 1. Read the request fields

The function first loads the 32-bit payload-base field at request offset +8. It then reads the 16-bit discriminator at offset +12.

The discriminator is represented as a signed 16-bit value in the supplied evidence. Equality with 10 selects the same bit pattern whether interpreted as signed or unsigned.

If the discriminator differs from 10, no explicit dependency call occurs. The function returns the normal packed result.

Although the payload base is loaded on this path, the function does not visibly dereference that base before returning.

### 2. Obtain the service and query status

For discriminator 10, the function calls F-b7af80e829ec with no explicit arguments.

The returned value is treated as a service-object address. The function reads the object’s operation-table pointer and invokes the operation at byte offset +0x120 in that table, passing the service object as the explicit argument.

The status result is tested as a 32-bit integer:

- Any nonzero result causes a normal return.
- Zero enables decoding and lookup.

A negative status is therefore nonzero and follows the normal-return path. No interpretation beyond zero versus nonzero is established.

### 3. Decode three values

After a zero service status, the function makes the three decoding calls in the order specified in the interface.

Each result is captured as a 32-bit value. All three calls complete before the service lookup operation is invoked.

The payload base used for these calls comes from the initial request-field read. The function does not visibly reload request offset +8 between dependency calls. Changes to that request field by a dependency therefore do not redirect the later calls in this invocation.

The function does not validate or branch on any decoded result before lookup. Zero-valued results are not locally rejected.

### 4. Look up an object

After all three decoded values have been obtained, the function invokes the service operation at operation-table byte offset +0xF4.

Its explicit arguments are:

1. The service object obtained earlier.
2. The first decoded 32-bit value.

The second and third decoded values are not passed to this lookup operation.

The service’s operation-table pointer is accessed again for this call. The contract therefore does not assume that the operation table remained unchanged across earlier dependency calls.

The lookup result becomes the object value used by the remaining operations and passed to F-feee9156a257.

### 5. Optionally obtain an object-produced value and dispatch

If lookup returns null, the function skips both subsequent object operations and skips F-043b2a28b7b3.

If lookup returns nonnull, the function invokes the operation at byte offset +8 in that object’s operation table. The supplied call site shows no explicit arguments, including no explicit object argument.

The result is tested as a 32-bit integer:

- Zero skips the value-producing operation and F-043b2a28b7b3.
- Any nonzero value enables both.

For a nonzero result, the function invokes the operation at byte offset +12 in the object’s operation table. This call also shows no explicit arguments. Its result is treated as a 64-bit value.

The function then calls F-043b2a28b7b3 with six arguments, in this order:

1. The original context word.
2. The original request address.
3. Bits 0–31 of the object-produced 64-bit value.
4. Bits 32–63 of that value.
5. The second decoded 32-bit value.
6. The third decoded 32-bit value.

Both halves of the object-produced value retain their 32-bit bit patterns. The high half is obtained through an unsigned 64-bit shift, so its extraction is not an arithmetic sign extension.

The supplied evidence does not use a result from F-043b2a28b7b3.

### 6. Enter the terminal dependency

After lookup, the function calls F-feee9156a257 with the lookup result. This occurs whether lookup returned null, the object’s +8 operation returned zero, or dispatch through F-043b2a28b7b3 occurred.

When F-043b2a28b7b3 is invoked, it precedes this terminal call.

F-feee9156a257 is marked non-returning in the supplied evidence. Its name here does not imply destruction, deallocation, exception throwing, process termination, or any other particular mechanism.

## Acceptance examples

These examples are conditional observations, not executed tests.

1. **Different discriminator.** Given readable request fields and a discriminator of 9, the payload-base field is still read first. No dependency is called. The result contains 4 in its low 32 bits and the request address in its high 32 bits.

2. **Nonzero service status.** Given discriminator 10 and a service status of −1, the function obtains the service and queries its status, then returns normally. No decoding, lookup, dispatch, or terminal call occurs.

3. **Null lookup result.** Given discriminator 10, zero service status, and a lookup result of null, all three decoding calls occur before lookup. No lookup-object operation or F-043b2a28b7b3 call occurs. F-feee9156a257 receives null.

4. **Object condition is zero.** Given a nonnull lookup result whose +8 operation returns zero, the +12 operation and F-043b2a28b7b3 are skipped. The nonnull lookup result is passed to F-feee9156a257.

5. **Dispatch with a split value.** Given an enabling object condition, an object-produced value of 0x1122334455667788, a second decoded value of 7, and a third decoded value of 9, F-043b2a28b7b3 receives the original two inputs followed by 0x55667788, 0x11223344, 7, and 9. F-feee9156a257 is called afterward if the preceding dependencies complete.

6. **Invalid payload base on an unselected request.** Given readable request fields and a discriminator other than 10, the function returns without passing the payload base to a decoder. This does not permit an invalid request address: the request fields themselves are still read.
