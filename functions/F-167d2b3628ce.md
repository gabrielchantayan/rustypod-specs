# F-167d2b3628ce

## Purpose

F-167d2b3628ce conditionally transfers the upper eight bits of a 16-bit field into a 32-bit field in an indirectly referenced object.

The operation is gated by a separate 16-bit field in the input object. When that field equals 2, the function performs the transfer and returns 1. Otherwise, it returns 0 without accessing the indirect destination.

These are established behaviors. Interpreting the fields as a mode, status, channel, or other application concept would be inferred intent; no such interpretation is needed for this contract.

## Interface

The function accepts one argument and produces one 32-bit result.

### Input argument

The argument is represented as a 32-bit integer used as a memory address. For this contract, it identifies the **input object**. There is no supplied object size, type definition, nullability annotation, or ownership annotation.

The following offsets are relative to the input object's address:

| Offset | Access width | Interpretation | Access condition |
|---|---:|---|---|
| `0x34` | 32 bits | Address of the destination object | Only when the gate equals 2 |
| `0x92` | 16 bits | Signed gate value | Every invocation that reaches the first memory access |
| `0x94` | 16 bits | Unsigned source value | Only when the gate equals 2 |

On the taken path, the function uses the address stored at offset `0x34` to identify the **destination object**. Its output field is:

| Offset | Access width | Interpretation |
|---|---:|---|
| `0x88` | 32 bits | Unsigned transferred value |

These offsets specify accesses, not complete object layouts. The evidence does not establish the meaning, validity, or existence of other fields.

### Result

For an invocation that completes normally:

- **0** means the gate did not equal 2 and no destination write was attempted.
- **1** means the gate equaled 2 and the destination write completed before the function returned.

There is no separate result for an invalid address, alignment problem, inaccessible page, or failed memory write.

### Preconditions

Every normal invocation requires the 16-bit gate field to be readable.

When the gate equals 2, normal completion additionally requires:

- The 32-bit address field at offset `0x34` to be readable.
- The 16-bit source field at offset `0x94` to be readable.
- The resulting 32-bit destination field at destination offset `0x88` to be writable.
- Address calculations and memory accesses to be valid under the execution environment's addressing and alignment rules.

The function does not establish these conditions through explicit checks.

## Behavior

### Gate evaluation

The first established memory operation is a 16-bit read at input offset `0x92`. The function interprets that value as signed and compares it with 2.

Signedness does not introduce additional matching values: only the 16-bit representation of positive 2 selects the transfer path.

If the gate differs from 2, the function returns 0. On that path, it does not read the address field at `0x34`, read the source field at `0x94`, or write the destination field.

Consequently, a readable nonmatching gate does not require the indirect destination to be valid. This does not make a wholly invalid input argument safe: the gate read itself remains required.

### Value transfer

If the gate equals 2, the function obtains:

- The destination object's address from the 32-bit field at input offset `0x34`.
- An unsigned 16-bit source value from input offset `0x94`.

It discards the source value's lower eight bits and retains its upper eight bits. The retained value is converted to an unsigned 32-bit value and written to destination offset `0x88`.

The stored value is therefore always between 0 and 255, inclusive. Its upper 24 bits are zero. The operation replaces the complete 32-bit destination field; it does not preserve any portion of that field's previous value.

The source extraction uses a nonnegative unsigned 16-bit value. The shift by eight positions therefore cannot introduce sign bits. Whether the language implementation promotes the value before shifting does not change the established numerical result for the stated widths.

After completing the store, the function returns 1.

### Access ordering

The supplied evidence establishes this partial order:

1. The gate read precedes the branch decision.
2. A nonmatching decision leads to return without the conditional accesses.
3. On a matching decision, both the destination-address read and source-value read precede the destination store.
4. The destination store precedes the successful return.

The relative order of the destination-address read and source-value read is not established. A consumer must not require one to precede the other.

No destination-value read is expressed. The previous destination value is not an input to the transfer.

These are source-level access facts. The evidence does not establish hardware transaction sizes, atomicity, volatile semantics, synchronization, or ordering guarantees between threads.

### Aliasing

No non-aliasing restriction is supplied.

If the destination field overlaps the input object, the store can modify input bytes, including bytes associated with fields used earlier in the invocation. Both the destination address and the source value have already been obtained before that store. The function does not subsequently reload the gate or source to decide its return value.

Thus, provided overlapping accesses are valid in the execution environment, a store that changes the gate does not retroactively change this invocation's successful result.

### Address and byte-order limits

The supplied representation uses 32-bit address-bearing values. No checked address addition, overflow handling, or portable wraparound behavior is established. Invalid address calculations are outside the normal-completion contract.

Field contents are interpreted as numerical values using the execution environment's byte order. “Upper eight bits” describes the numerical source value, not a fixed byte offset within its two-byte storage. Exact byte sequences require a separately established byte order.

## Side effects

On the nonmatching path, the only explicit memory access is the gate read. There is no explicit memory write.

On the matching path, the explicit effects are the gate read, destination-address read, source-value read, and one 32-bit destination write.

No allocation, release, ownership transfer, reference-count adjustment, logging, I/O call, or explicit global-variable access is present. Existing storage is accessed directly.

This does not guarantee that global state remains unchanged: the destination address could identify globally shared storage, and aliasing could expose the write through other references. Device-backed memory could also attach effects to accesses, but no device-memory contract is supplied.

The function provides no explicit locking or memory barriers. Concurrent mutation and observation are not assigned deterministic semantics by this contract.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence. They have not been executed.

| Conditions | Required result |
|---|---|
| Gate is 0 and its field is readable | Return 0; do not access the source or destination-address fields; perform no destination write. |
| Gate is −1 and its field is readable | Return 0 with the same skipped accesses. |
| Gate is 2, source is `0xABCD`, and all required accesses are valid | Store `0x000000AB` in the 32-bit destination field; return 1. |
| Gate is 2 and source is `0x00FF` | Store `0x00000000`; return 1 after the store. |
| Gate is 2 and source is `0xFF00` | Store `0x000000FF`; return 1 after the store. |
| Gate is 2, source is `0x1234`, and the destination previously contains `0xDEADBEEF` | Replace the complete destination value with `0x00000012`; return 1. |

Additional boundary conditions:

- With a readable nonmatching gate, an invalid value in the unused destination-address field must not by itself trigger an access through that value.
- With a matching gate, an inaccessible destination does not have a specified 0 return. The function attempts the write; abnormal-access behavior belongs to the environment.
- With valid overlapping storage, the destination write may change the input object. A completed transfer still returns 1.
- Sources that share the same upper eight bits produce the same stored value, regardless of their lower eight bits.
