# F-93d385598c40

## Purpose

F-93d385598c40 writes a sequence of 16-bit results derived from source elements, then unconditionally invokes an indirect dependency with two destination-derived pointers and a width-derived integer.

For width \(W \ge 2\) and height \(H \ge 2\), the local transformation produces \(H-1\) rows of \(W\) elements. Most columns combine an upper source element with a lower-right source element through two stages. The final column uses one stage and reuses the lower operand retained from the preceding column.

The masks are consistent with component-aware interpolation of packed 16-bit values. That is **inferred intent**, not an established pixel format or color-space contract. The established behavior is the numerical transformation, pointer progression, memory-access ordering, and final invocation described below.

Widths at most one do not follow the ordinary rectangular rule. If the outer loop executes, they produce address-dependent results and still perform source-relative pointer arithmetic.

The function accepts four inputs and has no explicit return value.

## Behavior

### Numerical transformation

Let \(M\) be the unsigned 32-bit mask `0xFFFFF7DF`. Define:

\[
A(x,y)=(x\mathbin{\&}y)+
\left(((x\mathbin{\oplus}y)\mathbin{\&}M)\gg1\right).
\]

The right shift is logical. For 16-bit operands, the mask clears bits 5 and 11 before the shift. This operation is not an unrestricted arithmetic average.

For an ordinary non-final column, both inputs \(a\) and \(b\) are unsigned 16-bit source values. The intermediate value is:

\[
T=A(a,b)\mathbin{\&}\texttt{0xFFFEFFFF}.
\]

The destination receives the low 16 bits of:

\[
B(a,b)=
\left(b\mathbin{\&}(T\bmod 2^{16})\right)
+
\left(((b\mathbin{\oplus}T)\mathbin{\&}M)\gg1\right).
\]

For these operand widths, \(A(a,b)\) fits within 16 bits. Clearing bit 16 therefore does not change its value. The mask remains part of the established calculation.

The final column receives:

\[
E(a,b)=A(a,b)\bmod 2^{16}.
\]

It does not perform the second combination with \(b\).

These definitions concern bit patterns only. They do not establish channel layout, color interpretation, or a perceptual rounding rule.

### Ordinary rectangular processing

Assume \(W \ge 2\), \(H \ge 2\), valid arithmetic and storage, and source contents unaffected by destination writes.

Let \(S[k]\) denote source element \(k\) relative to the original source position. For each output row \(r\), where \(0\le r<H-1\):

- Columns \(0\le c<W-1\) receive
  \[
  B\left(S[rW+c],S[(r+1)W+c+1]\right).
  \]
- Column \(W-1\) receives
  \[
  E\left(S[rW+W-1],S[(r+1)W+W-1]\right).
  \]

Local destination writes proceed in increasing element order: across each row, then through subsequent rows.

The lower row’s first element is not used for that output row. Its final element is used twice: as the lower-right operand for the penultimate output column, then as the retained lower operand for the final column.

Each completed local row advances the current source and destination positions by \(W\) elements.

### Pointer formation and access ordering

Before the height condition is evaluated, the function forms a forward source position equal to the original source position plus \(W\) elements.

At the beginning of every executed outer iteration, that forward position advances by one element.

During each ordinary inner operation:

- The next upper and forward source positions are formed.
- The lower-right source element is loaded and retained.
- The current upper source element is read for the intermediate calculation.
- The destination element is written.
- Processing continues with the advanced positions.

The upper element appears more than once in the numerical expression. The supplied representation does not establish the relative order of those references or require a particular number of physical loads.

For the final column, the lower operand is reused from the last inner operation. There is no fresh lower-source load. The upper final-column source element is referenced, and the final result is written.

The final-column expression also references its upper source element more than once. The numerical descriptions assume those references observe the same value; no synchronization or volatile-access contract is established.

In the ordinary case, the forward position after processing row \(r\) is at source offset \((r+2)W\). After the last locally processed row, it is at offset \(HW\), one element past the complete source rectangle. That position is formed but not dereferenced.

The routine does not snapshot source storage. With overlap, an earlier destination write can affect later upper or lower source reads. A retained lower operand remains the value already obtained; subsequent writes do not reload it.

### Heights that skip local processing

If the signed comparison against \(H-1\) does not select the outer loop:

- No source element is dereferenced locally.
- No destination element is written locally.
- The initial source-plus-width pointer is nevertheless formed.
- The final indirect invocation still occurs.

For representable subtraction, \(H\le1\) skips the outer loop. The minimum signed 32-bit height is excluded from that simple rule because calculating \(H-1\) overflows portable signed arithmetic.

Skipping local processing does not make arbitrary pointers or widths valid. Initial pointer formation, final width negation, and final size calculation remain relevant.

### Widths that skip the inner loop

If the outer loop executes but the comparison against \(W-1\) does not select the inner loop, each outer iteration:

- Advances the forward source position by one element without dereferencing it.
- Reads the current upper source element for the final-column calculation.
- Writes one destination element.
- Advances the current upper source and destination positions by one element.

The retained operand initially comes from the original destination address, not from source storage. Subsequent iterations retain the full result of the preceding combination through integer-to-pointer and pointer-to-integer conversions.

Under a 32-bit, bit-preserving conversion model, let \(P\) be the retained unsigned 32-bit value and \(a\) the current unsigned 16-bit source value. The next retained value is:

\[
P'=(a\mathbin{\&}P)+
\left(((a\mathbin{\oplus}P)\mathbin{\&}M)\gg1\right).
\]

The destination receives \(P'\bmod 2^{16}\). The next iteration uses the full retained value, not just the stored 16 bits.

For representable \(W-1\), this path applies to \(W\le1\). With \(H\ge2\), it writes \(H-1\) destination elements, independent of the width.

Its pointer-formation requirements are separate from its dereference requirements. If \(S\) is the original source position, the forward positions formed are:

\[
S+W,\quad S+W+1,\quad \ldots,\quad S+W+(H-1).
\]

None is dereferenced on this path, but each must still be valid under the applicable pointer model. Readability of the \(H-1\) upper source elements alone does not prove this.

This behavior must not be replaced by conventional one-column interpolation or by treating zero width as a no-op.

### Final indirect invocation

After local processing, including when it is skipped, the function invokes the indirect dependency with:

1. The current destination position.
2. The current destination position offset by the **signed negation of \(W\)** destination elements.
3. The signed expression \(W\ll1\).

The second argument is not merely mathematical subtraction: the signed negation is an intermediate operation. Negating the minimum signed 32-bit width has no portable defined result, even if no local loop executes.

For ordinary positive widths with defined arithmetic, the second argument is one row before the first, and the third argument equals \(2W\). Because destination elements occupy two bytes, that integer matches a row’s byte extent. This correspondence does not prove that the dependency copies bytes.

After ordinary rectangular processing, the first argument is immediately after the locally produced rows, and the second is the start of the last locally produced row.

If the outer loop is skipped, the first argument is the original destination position and the second is \(W\) elements before it, subject to valid negation and pointer formation.

The function returns only if the dependency returns normally. No particular ordering among evaluation of the final call’s argument expressions is established.

### Two-by-two input

Let \(W=2\), \(H=2\), with source rows:

- First row: `0x0000`, `0x0000`.
- Second row: `0x1234`, `0xFFFF`.

The first output uses upper `0x0000` and lower-right `0xFFFF`.

Its intermediate value is `0x7BEF`. The second stage adds `0x7BEF` and `0x4208`, producing **`0xBDF7`**.

The final output uses the single-stage calculation with upper `0x0000` and retained lower `0xFFFF`, producing **`0x7BEF`**.

The lower-left value `0x1234` contributes to neither result.

The indirect invocation receives the destination position advanced by two elements, the original destination position, and integer four.
