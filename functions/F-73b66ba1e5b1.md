# F-73b66ba1e5b1

## Purpose

F-73b66ba1e5b1 conditionally reads records from a stream and applies scaled adjustments to a context-associated array of 16-bit elements.

The established behavior is selective: only records with explicit coordinates reach scale evaluation, and only records with both a nonzero scale and a payload-enable flag reach payload decoding. Other records still contribute to record traversal and payload positioning.

The apparent intent is variation-driven adjustment of a control-value table. That interpretation is inferred from data flow, not an independently established external format contract.

## Interface

The function accepts a context address and a stream address and returns a 32-bit status. The supplied representation uses 32-bit addresses.

### Context access requirements

| Byte offset | Observed use |
|---|---|
| `0x1f8` | Indirect callback address for table selection. |
| `0x280` | Unsigned 32-bit destination element count. |
| `0x284` | Address of destination storage containing two-byte elements. |
| `0x2a0` | Address of a blend configuration whose first four bytes hold an unsigned dimension count. |

These are accessed fields, not a complete context layout. Neither argument is directly checked for nullness or accessibility.

A zero blend address or zero destination address prevents table selection and decoding. Such paths still permit diagnostics and perform temporary-buffer release calls.

### Stream access requirements

| Byte offset | Observed use |
|---|---|
| `0x00` | Base address for stream-relative position calculations. |
| `0x1c` | Allocation/release context, captured at entry. |
| `0x20` | Current cursor address. |

The function directly changes the cursor for payload processing. Reader and stream-management dependencies may perform additional changes.

### Diagnostic state

A global address identifies a diagnostic object. A signed 32-bit control field at offset `0x6c` enables diagnostics when its value is greater than one.

The function uses both an entry-time captured object address and a separate global-address read. Their distinction is observable if dependencies replace the global pointer.

### Return and storage conventions

Normal completion and locally suppressed table-selection, table-entry, or version failures return zero. A nonzero status written by a temporary-array allocation dependency selects an error-return path.

Three temporary arrays use four-byte elements. Point-selection entries are unsigned 16-bit indices; delta entries are signed 16-bit values. Destination writes retain only 16 bits.

Reader return widths and byte order are not established by this function. Masks and conversions applied after reader calls are established independently of those unknowns.

## Behavior

### Entry captures and diagnostic ordering

The entry sequence is:

1. Capture the diagnostic-object address from the global pointer.
2. Capture the allocation/release context from the stream.
3. Initialize all three temporary-array addresses to zero.
4. Capture the blend-configuration address from the context.
5. Separately read the diagnostic-object address from the global pointer, read that object’s control field, and emit the general entry diagnostic if the signed value exceeds one.

Subsequent diagnostic conditions do not reload the global object address. Each rereads the control field through the address captured in the first step.

Consequently:

- Replacing the global pointer during the entry diagnostic does not redirect later diagnostic checks.
- Changing the original object’s control field can change later diagnostic decisions.
- The captured object must remain accessible for any later diagnostic check that is reached.
- The captured blend address remains the one used after the entry diagnostic, even if that dependency changes the context’s blend field.

These captures do not constitute a snapshot of the entire context. In particular, the destination-address gate occurs after the entry diagnostic.

### Initial gates and table access

If the captured blend address is zero, the function skips table selection. It conditionally emits a missing-blend diagnostic using the captured diagnostic-object address.

Otherwise, it reads the context’s destination address. If that address is zero, it skips selection and conditionally emits a missing-destination diagnostic.

If both gates pass, the context callback receives:

- The context address.
- A fixed four-byte table identifier.
- The stream address.
- An output address for a 32-bit value used by the stream-entry dependency.

The identifier’s exact bytes are not independently supplied.

A nonzero callback result prevents stream entry and decoding. A missing-table diagnostic is conditional on the captured diagnostic object’s current control field. The callback’s status is suppressed rather than returned.

A zero callback result leads to F-d036abe1e536 with the stream and callback-produced value. A nonzero result from that dependency also prevents decoding and is suppressed. There is no direct diagnostic on that branch.

Only successful stream entry leads to version decoding. Every path reaching version decoding subsequently calls F-9787e15c337d before releasing the temporary arrays. Paths that do not successfully enter the stream do not call that finalizer.

### Version and allocation

After successful entry, the function captures the current cursor and then the stream base. These captures precede the version-reader call to F-77339711215b.

Only version `0x00010000` is accepted. Any other value:

- Conditionally emits a bad-version diagnostic through the captured diagnostic object.
- Performs no temporary-array allocations.
- Performs no direct destination adjustment.
- Selects a zero return status.
- Still finalizes stream access and releases the three zero temporary-array addresses.

For an accepted version, three ordered calls to F-6dd003795db7 request the coordinate arrays. Each receives:

- The captured allocation context.
- Element size four.
- A zero argument.
- The dimension count read through the captured blend address.
- Another zero argument.
- An address at which to write allocation status.

The dimension count is read separately for each allocation. It need not remain equal across calls.

Each returned address is retained before its status is checked, including a result accompanied by failure. Allocation two occurs only after allocation one reports zero status; allocation three occurs only after allocation two reports zero status. Header decoding requires all three statuses to be zero.

A failing allocation status is retained for return after finalization and cleanup. The function does not independently validate the returned addresses or initialize their contents. Safe execution requires dependencies not to invalidate the escaped status storage or unexpectedly change it after establishing the intended result.

### Header decoding and payload offsets

After successful allocation, two calls to F-7efb5338f0fa provide:

1. A value whose low 12 bits determine the record count.
2. A value whose low 16 bits determine the initial payload displacement.

The running payload position is the captured pre-version cursor-minus-base offset plus that displacement. It is relative to the captured pre-version position, not the cursor after header decoding.

The function processes the resulting record count, at most 4095. Each record begins with two reader calls: payload size, then flags. Flags are narrowed to 16 bits.

After each record’s coordinate and possible payload processing, the running payload position increases by the low 16 bits of that record’s payload-size result. This happens even for records whose payload is skipped. There is no early termination merely because a record has no effect.

The position arithmetic is 32-bit and unchecked. Exact overflow behavior of signed intermediate operations is not established beyond the supplied representation.

### Coordinate handling and scale

Three flag masks have established control effects:

| Mask | Effect |
|---|---|
| `0x8000` | Enables explicit-coordinate loading and scale evaluation. |
| `0x4000` | Enables two additional coordinate sequences, or coordinate discarding when explicit coordinates are absent. |
| `0x2000` | Permits payload processing when the scale is nonzero. |

When `0x8000` is clear, no scale call or payload processing occurs. If `0x4000` is set, coordinate-reader results are discarded until an unsigned counter reaches twice the dimension count. That bound is recomputed from the blend’s current dimension count at every condition evaluation. Doubling uses a 32-bit unsigned left shift, so large counts can wrap. Without `0x4000`, no coordinate reads occur on this branch.

When `0x8000` is set, one sequence fills the first temporary array. Each reader result is shifted left by two and stored as a four-byte value.

If `0x4000` is also set, two more sequences fill the second array and then the third array. Each coordinate loop rereads the dimension count on every condition evaluation. Allocation sizes therefore do not guarantee adequate storage if dependencies increase the count.

F-29e0f2d2fa66 then receives the captured blend address, full 16-bit flags, and all three array addresses. Its result is the record’s scale.

Without `0x4000`, the second and third arrays are not populated for this record. They may contain allocator-provided contents or values from earlier records. Whether the scale dependency ignores those contents is unknown.

### Payload entry and decoding

Payload processing requires both a nonzero scale and flag `0x2000`.

Before entering the payload, the function saves the current cursor-minus-base offset using the stream’s then-current fields. It then writes the cursor to the then-current base plus the running payload position.

F-1fc61b314574 receives the stream and an output address for an unsigned 32-bit point count. Its result is interpreted as:

- Zero: no usable point selection.
- `0xffffffff`: an all-elements sentinel.
- Any other value: an address of unsigned 16-bit indices.

The point-count output storage has escaped to this dependency. The function does not establish that subsequent calls cannot change it.

F-f6968fd5e8be is called regardless of the selection result. Its requested count is the point count read after selection decoding, except that zero causes a read of the context’s current destination count instead. This requested count is chosen before delta decoding; it is not automatically reconciled with later loop-bound changes.

The result is treated as a signed 16-bit delta-array address, with zero indicating no usable delta buffer.

### Destination updates and repeated bounds

No direct adjustment occurs unless both the selection result and delta-buffer address are nonzero.

For the all-elements sentinel, an unsigned counter starts at zero. Every condition evaluation rereads the context’s destination count at `0x280`. The bound is not captured once.

For explicit selection, every condition evaluation rereads the point-count output storage. That bound is also not captured once. A dependency retaining its output address can therefore change how many iterations occur.

The explicit-selection iteration has this observable order:

1. Read the unsigned 16-bit selected index for the current iteration and retain that value.
2. Read the corresponding signed 16-bit delta and sign-extend it for the adjustment call.
3. Call F-74efb2674226 with that delta and the record’s scale.
4. Narrow the result to a signed 16-bit adjustment.
5. Read the destination-array address from the context.
6. Read the destination element selected by the retained index.
7. Add the adjustment and store the low 16 bits.

The selected index is not reread after the adjustment call. Changes that call makes to the current index-array entry do not redirect the current write. In contrast, changing the context’s destination pointer during that call can redirect it.

The all-elements path follows the same delta-call-destination-read-write ordering but uses the iteration counter as the destination index.

Repeated indices accumulate sequentially; there is no deduplication. There is no saturation, index bounds check, buffer-length check, or reconciliation between decoded delta count and a later loop bound. Safe execution requires accessible storage for every read and write actually reached.

### Payload cleanup and final cleanup

After a processed payload, F-bf7242c98d06 receives:

1. The point-selection result, unless it is the all-elements sentinel.
2. The delta-buffer result, unconditionally.

Thus zero selection results are passed for release, the sentinel is not, and zero delta results are passed. Selection release precedes delta release.

The cursor is then restored to the stream’s base as read at restoration time plus the saved header-relative offset. Restoration preserves an offset, not necessarily the earlier absolute cursor address.

After all records, or after an entered-stream version/allocation exit, stream finalization occurs. The three temporary-array addresses are then offered for release in first-array, second-array, third-array order. All paths perform these three release calls, including paths retaining only zero addresses.

Destination changes are not transactional. No direct rollback restores earlier writes.

## Side effects

Established direct effects include conditional diagnostic calls, dependency-driven stream reads, cursor writes, temporary-coordinate stores, in-place destination updates, allocation calls, release calls, and stream finalization after successful entry.

The function does not directly release the supplied context, stream, blend configuration, or destination array. Passing temporary and decoded-buffer results to F-bf7242c98d06 establishes release-call behavior, not an independently known ownership model or allocator family.

The allocation context used for all releases is the entry-time capture. Later stream-field changes do not replace it.

Dependencies are not established to preserve globals, context fields, stream fields, escaped output storage, or buffer contents. Statements about this function’s direct writes do not exclude additional dependency effects.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless mutation is expressly part of an example, dependencies are assumed to leave relevant storage unchanged and supply accessible buffers.

1. **Missing blend.** A captured zero blend address prevents selection and decoding. Three zero temporary addresses are passed for release. The return is zero; diagnostics remain conditional.

2. **Diagnostic pointer replacement.** The captured diagnostic object is A. The entry diagnostic replaces the global pointer with B. A subsequent missing-blend diagnostic condition reads A’s current control field, not B’s.

3. **Diagnostic control mutation.** The entry diagnostic changes A’s control field from two to zero. A later diagnostic condition through A does not emit a message merely because the entry check passed.

4. **Selection or entry failure.** A nonzero selection result prevents stream entry. A nonzero entry result prevents version decoding. Both select zero return status, and neither path finalizes an unsuccessfully entered stream.

5. **Unsupported version.** Successful entry followed by another version performs finalization and zero-buffer cleanup without allocation or direct destination updates.

6. **Second allocation failure.** A nonzero status from allocation two prevents allocation three and header decoding. Finalization precedes release of the retained first and second results and zero third result. The allocation status is returned.

7. **Discarded coordinates.** With flags `0x6000` and a stable dimension count of three, six coordinate-reader calls are discarded. No scale or payload call occurs.

8. **Zero scale.** An explicit-coordinate record yielding zero scale skips payload decoding but still advances the running payload position by its masked payload size.

9. **Retained explicit index.** An iteration reads index four. Its adjustment call changes that index-array entry to nine. The current write still targets index four, using the destination pointer read after the call.

10. **Changing all-elements bound.** An all-elements iteration changes the destination count from three to one during its adjustment call. After completing index zero, the next condition reads one and terminates.

11. **Changing explicit bound.** Selection initially reports three points. The first adjustment call changes the escaped point count to one. The first write completes; the next condition terminates the loop.

12. **Repeated index and wrap.** Two selections of index four with adjustments three and negative one change ten to thirteen and then twelve. Separately, adding one to destination bit pattern `0x7fff` stores `0x8000`, without saturation.

13. **Missing selection.** A zero selection result does not suppress delta decoding. It prevents direct adjustment, then zero selection and the delta result are released before cursor restoration.
