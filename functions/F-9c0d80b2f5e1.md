# F-9c0d80b2f5e1

## Purpose

F-9c0d80b2f5e1 performs an initial selected byte write, invokes a sequence of opaque dependencies, and enters an unconditional loop containing further calls and selected zero-byte writes. Dependency results supply arguments for subsequent calls.

The loop’s leading call changes target after its first invocation: the first iteration uses a target established before loop entry; every subsequent iteration uses a different constant-derived target established near the preceding iteration’s end. These targets have separate opaque dependency IDs below. Their behavior is not established to be equivalent.

No normal return, completion result, or explicit error-handling path is visible. The application-level purpose is unknown; descriptions such as device initialization, polling, or protocol processing would be inferred intent rather than established behavior.

The supplied representation includes warnings about invalid instruction data and removed unreachable regions. This contract describes the represented operations and their dataflow, not a verified complete execution model.

### Widths and memory layout

Every explicit memory access operates on one byte. No structure, buffer extent, allocation, or ownership layout is established.

The routine uses two selector locations:

- The **initial selector location** is one byte beyond the implicit incoming base.
- The **repeated selector location** is at the address represented by Argument 4 multiplied by 1024, plus one.

Each selector is read as an unsigned eight-bit value. Adding 17 to that value determines the destination of a one-byte write. This addition is not an eight-bit addition: selector values from 0 through 255 select numerical addresses from 17 through 272, inclusive, or `0x11` through `0x110`.

Under defined integer arithmetic, the repeated selector address is congruent to 1 modulo 1024. The same congruence holds under a 32-bit wrapping interpretation of its address calculation. None of the possible selected destinations, 17 through 272, has that congruence. Under either interpretation, the repeated selector therefore cannot alias any destination of an explicit byte write in this routine.

The initial selector’s location has no comparable established alignment restriction. It may alias a selected destination or the repeated selector location, subject to the actual address semantics.

## Behavior

### Initial selected write

The routine first reads the initial selector byte, then writes the incoming implicit eight-bit value to the address selected by that byte plus 17.

The selector read precedes the write, with no intervening dependency call. If the initial selector location aliases the selected destination, the write still uses the selector value obtained before the write.

No prior destination value is read for restoration.

### Initial dependency sequence

After the initial write, the following calls occur in order:

1. F-000000000001 receives Argument 1.
2. F-000000000002 has no explicit argument shown.
3. F-000000000003 has no explicit argument shown.
4. F-000000000004 has no explicit argument shown.
5. F-000000000005 has no explicit argument shown and supplies a captured 32-bit result.

The first target is derived from the incoming link-like value plus `0xFFE`. The other four targets are constant-derived.

The first four return values are not explicitly consumed. This does not establish that those calls have no effects or no other outputs.

The result from F-000000000005 is treated as an unsigned 32-bit word. The routine retains bits 25 through 29, numbering from zero at the least significant bit. This **initial field** ranges from 0 through 31. Bits 0 through 24 and bits 30 through 31 do not contribute.

### First repeated clear and loop initialization

The routine then performs these interactions in order:

1. Reads the repeated selector.
2. Writes one zero byte to the selected address.
3. Calls F-000000000006 with twice the initial field.
4. Calls F-000000000007 and retains its signed 32-bit result as the initial **carried word**.

The argument to F-000000000006 is an even value from 0 through 62. This doubling has no overflow ambiguity at the represented width.

The first repeated-selector read occurs after all five initial calls. Those dependencies may therefore affect the selector value observed by this read; the routine does not take an earlier snapshot of it.

Before F-000000000007 is invoked, the routine establishes the constant-derived target used by the first iteration’s leading call, F-000000000008.

The initial **control word** is the initial field, held as an unsigned 32-bit value.

Thus:

- F-000000000008 is reached only at the first loop entry.
- F-000000000012 is reached at every later loop entry.
- Both occupy the same leading call position and receive arguments formed by the same rules.
- Matching call position and argument formation do not establish matching dependency behavior.
- Later iterations continue to select F-000000000012; the represented body does not alternate back to F-000000000008.

The first control word is at most 31. Its unsigned right shift by eight is therefore zero. F-000000000008 receives the result of F-000000000007 as its first explicit argument and zero as its second.

### Feedback arithmetic

For the next iteration, the represented arithmetic forms:

- A carried word from the feedback word shifted left by two bits.
- An unsigned 32-bit control word from the feedback word shifted left by 26 bits.

Both left-shift expressions operate on represented signed 32-bit values before any conversion to unsigned storage. Their behavior for negative operands or results outside the signed range is not established as portable signed-language behavior.

Under the explicitly conditional interpretation that these operations are 32-bit wrapping shifts:

- The carried word has the bit pattern of four times the feedback word modulo \(2^{32}\).
- Only the feedback word’s low six bits survive in the control word.
- The next leading call’s second argument is those low six bits shifted left by 18.
- That second argument ranges from zero through `0x00FC0000`, in increments of `0x00040000`.

The right shift of the control word is unsigned. Uncertainty concerns the preceding signed left shifts, not whether this right shift propagates a sign bit.

There is no visible loop exit condition. Selector values and dependency results do not select an explicit exit branch.

### Read/write ordering and overlap

The repeated selector is reread once before loop initialization and once during each reached iteration. Its value and resulting destination are not cached across clears.

Within an iteration, the leading dependency and F-000000000009 through F-00000000000c precede the selector read. F-00000000000d through F-000000000011 follow the zero write.

Under the address interpretations described above, explicit selected writes cannot modify the repeated selector itself. Opaque dependencies or external activity may nevertheless change it between reads.

Different selector reads may select the same destination. In particular, a later zero write can overwrite the initial byte write if both selectors choose the same numerical address. An opaque dependency may also overwrite that address. The supported persistence statement is only that no dedicated restoration of the initial destination’s previous contents is visible.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume the relevant accesses succeed and preceding dependencies return normally.

### Initial selection and byte width

If the initial selector returns 5 and the incoming byte is `0xA7`, the routine writes exactly that byte at address 22 before F-000000000001.

If the selector returns 255, the destination is address 272, not address 16. Destination selection does not wrap at eight bits.

### Initial field boundaries

If F-000000000005 returns `0x3FFFFFFF`, the initial field is 31 and F-000000000006 receives 62.

If it returns `0xC0000000`, the field is zero and F-000000000006 receives zero.

In both cases, F-000000000008 receives zero as its second explicit argument.

### Leading target transition

If execution reaches three loop entries, their leading targets are, in order:

1. F-000000000008.
2. F-000000000012.
3. F-000000000012.

Invoking F-000000000008 at all three entries would not match the represented target transition, even if the supplied arguments were otherwise correct.

### Selector changes between clears

If the first repeated-selector read returns 4, the routine writes zero at address 21.

If a dependency changes the repeated selector to 9 before its next read, the next clear targets address 26. Reusing the previous destination without rereading would not match the represented behavior.

### Repeated-selector location and non-aliasing

With Argument 4 equal to zero, the repeated selector location is address 1. If that byte contains 4, the selected write goes to address 21; it does not clear the selector at address 1.

With Argument 4 equal to one, the selector location is address 1025. Its selected destination still lies between addresses 17 and 272.

Placing the repeated selector at address 21 is not supported under defined arithmetic or the stated 32-bit wrapping interpretation. No repeated-selector self-clearing example follows from those interpretations.

### Overwriting the initial write

If the initial selector and a later repeated-selector read both return 5, the initial incoming byte is written at address 22 and the later clear writes zero at address 22.

The initial stored value therefore need not persist. This sequence does not restore whatever value occupied address 22 before the routine’s initial write.

### Feedback propagation

Under 32-bit wrapping shift semantics, feedback equal to 1 causes the next F-000000000012 invocation to receive first argument 4 and second argument `0x00040000`.

Under the same interpretation, feedback equal to 64 produces first argument 256 and second argument zero. Bit six contributes to the carried word but not the control word.

### Interrupted execution

If F-00000000000c does not return, that iteration’s selector read and clear are not reached.

If the selector read faults after F-00000000000c returns, the following zero write and F-00000000000d call are not established as occurring. No local recovery path is visible.
