# F-e40599e38246

## Purpose

F-e40599e38246 is a globally controlled state machine accepting one 32-bit argument. Depending on the states reached, it reads object-relative fields, calls F-5e3309c9d083, and writes individual bytes to calculated addresses.

The static evidence does not establish an unconditional operation such as releasing an object, clearing a structure, or erasing a complete buffer. Global control and arithmetic data determine the executed states, destinations, byte values, and termination.

Cleanup or overwriting intent is inferred from the combination of field-derived call arguments and byte stores. Allocation ownership, release semantics, valid write bounds, and complete overwrite coverage remain unknown.

## Interface

### Argument and return

The sole argument is a 32-bit integer-valued quantity. A particular state adopts its bit pattern as the active object address. Until that state executes, the active object address is zero, independently of the argument.

There is no explicit return value. Relative selector 18 returns normally. Neither its reachability nor eventual termination is established for general inputs.

### Object-relative layout

Reached states access the following fields relative to the active object address:

| Byte offset | Read width | Established use |
|---|---:|---|
| +0x14 | 32 bits | Zero test, dependency argument, retained addressing value |
| +0x18 | 32 bits | Candidate or extent-like value |
| +0x100 | 32 bits | Zero test, dependency argument, retained addressing value |
| +0x104 | 32 bits | Operand in a candidate or extent-like calculation |

“Addressing value” and “extent-like” describe observed uses, not declared field types. Pointer, length, capacity, and ownership interpretations are unproven.

There are no explicit four-byte stores resetting these fields. Calculated byte stores could nevertheless overlap them.

### Path-dependent preconditions

Each executed field load requires the corresponding four-byte region to be readable. Each executed byte store requires its calculated destination to be writable. Calls must satisfy F-5e3309c9d083’s unknown requirements.

Normal completion additionally requires global data and dependency behavior that lead to the return state. Nonzero input alone establishes none of these conditions.

No alignment, allocation-size, synchronization, or ownership contract is supplied.

## Behavior

### Widths and notation

The representation uses 32-bit signed and unsigned quantities, four-byte field loads, and one-byte stores. The decision states explicitly inspect bit 31 of a subtraction result through an unsigned right shift.

The formulas below describe the apparent 32-bit bit-vector behavior: arithmetic results retain their low 32 bits where applicable, bitwise operations act on 32-bit values, and stored bytes retain their low eight bits. Some represented signed expressions can overflow; portable language-level overflow behavior and the target’s precise address-conversion rules are not independently established.

The following names describe retained state, not source identifiers:

- \(b\): first entry-cached arithmetic coefficient.
- \(a\): second entry-cached arithmetic coefficient.
- \(p\): current position.
- \(x\): progression value.
- \(k\): candidate value, also used for extent-like results and byte-pattern products.
- \(A\): active object address.
- \(R\): retained argument/addressing value.
- \(W\): retained write base.
- \(z\): retained entry-derived seed.

A named global parameter denotes a read at the specified operation, not an immutable constant. Independent reads must remain independent unless stability is separately guaranteed. No ordering among operand reads within a single expression is established unless stated below.

### Entry initialization

The relevant entry events occur in this order:

1. Read the first coefficient global and cache it as \(b\).
2. Read the second coefficient global and cache it as \(a\).
3. Initialize \(p\) to zero.
4. Read the second coefficient global again and multiply that independently obtained value by the 32-bit integer representation of the address of \(p\), retaining the result as \(z\).
5. Read the initial-control global.

The seed therefore need not equal \(a\) multiplied by the address of \(p\). The cached coefficient and seed coefficient come from separate reads.

Before the first dispatch, \(A\), \(R\), \(W\), \(x\), and \(k\) are zero, and the argument is retained separately. The cached coefficients and seed are not explicitly refreshed later.

The internal address contributes to arithmetic state. Invocation placement cannot be assumed irrelevant if that state reaches a store calculation.

### Dispatch and control selection

Every dispatch performs two distinct reads of the same dispatch-base global:

1. Retain the first read as a possible next-control value.
2. Independently read the global again and subtract that second value from the current control to obtain the relative selector.

Selectors 5 and 8 use the **first** dispatch-base read as their next control. Selector selection uses the **second** read. These values need not agree.

Selectors 0 through 24 have explicit cases. Selector 18 returns. Selector 11 and all selectors outside that range share a byte-writing operation. An unexpected selector is therefore not an established error or stop condition.

Global values are unavailable, so the state sequence cannot be reduced to a fixed cleanup order.

### Object adoption and tests

Selector 9 reads its next-control global, then installs the retained input as \(A\).

Selector 24 tests \(A\) itself without dereferencing it. Selector 3 reads and tests the four-byte field at \(A+0x14\). Selector 14 similarly tests \(A+0x100\).

Each test is followed by two independent reads of its transition global. The first supplies an adjusted zero-branch candidate; the second supplies the nonzero-branch candidate:

| Selector | Tested quantity | Zero-branch control | Nonzero-branch control |
|---|---|---|---|
| 3 | Field at +0x14 | First transition read minus 8 | Second transition read |
| 14 | Field at +0x100 | First transition read minus 10 | Second transition read |
| 24 | Active address | First transition read plus 13 | Second transition read |

Both transition reads occur regardless of which branch is selected. The branch controls differ by the listed adjustment only when those two reads agree.

These tests do not establish general null safety. Unknown transitions could reach a field access or store before any protective test.

### Field-loading and base-selection states

Selector 22 performs the following ordered accesses:

1. Read the four-byte field at \(A+0x18\) into \(k\).
2. Read its next-control global.
3. Read the field at \(A+0x14\) into \(R\).
4. Read that same field again into \(W\).

The repeated +0x14 loads are distinct. Their results need not be equal under changing or specially behaved memory.

Selector 23 first calculates

\[
k=b\bigl(h\,L+j\bigr),
\]

where \(L\) is the four-byte field at \(A+0x104\), and \(h\) and \(j\) are two global operands. It then reads its next-control global and finally reads the field at \(A+0x100\) into \(R\). No ordering is established among the operand reads within the extent calculation itself. This state does not explicitly replace \(W\).

Selector 13 reads its next-control global, then copies \(A\) into both \(R\) and \(W\). Subsequent writes can therefore target the object itself rather than a field-referenced region.

### Dependency calls

Exactly three explicit states call F-5e3309c9d083:

| Selector | Argument preparation |

| 10 | Pass the currently retained \(R\) |

At each site, the dependency call occurs before the next-control global is read. Any return value is ignored; no error status is explicitly inspected.

No caller-side field reset or post-call validity check is present. The dependency may change globals or memory. Its behavior must not be assumed to preserve later transition data or the validity of retained addressing values.

### Byte-writing states

Selectors 4, 5, and 11, together with the default path, each perform exactly one explicit byte store per visit.

First, the position becomes

\[
p'=b(ap-a).
\]

Using the pre-update progression \(x\), the candidate becomes

\[
k=
\left(a\left((xw_0-1)\mathbin{\mathrm{OR}}\text{0xFFFFFE8B}\right)+w_1+x\right)
w_2(x+w_3),
\]

where \(w_0,w_1,w_2,w_3\) are four global arithmetic parameters read for the expression.

The destination displacement is \(abp'\). Selector 4 uses base \(R\); the other writing paths use \(W\). The stored byte is the low eight bits of \(69k\).

After the store, the progression becomes

\[
x'=ab(x+a).
\]

The control and base-update ordering differs:

- **Selector 4:** store the byte; read its next-control global; advance \(x\); copy \(R\) into \(W\).
- **Selector 5:** store the byte; adopt the first dispatch-base read as next control, without a new transition-global read; advance \(x\).
- **Selector 11/default:** store the byte; read its next-control global; advance \(x\).

The position and candidate updates precede the store. No ordering among reads inside the byte-product expression is established.

Because writing also replaces \(k\), a later state using the candidate can consume a prior byte-product result rather than an earlier extent.

There is no explicit per-store capacity check or write-result check. Sequential addressing, zero filling, complete erasure, and a fixed write count are not established.

### Arithmetic decision states

Selectors 0, 6, and 19 calculate a candidate and select a branch using bit 31 of a subtraction. They share the following mathematical form, with distinct global parameter families for each selector:

\[
r=bap,\qquad t=gap+1,\qquad u=r-1,
\]

\[
k=
\left(((r+\alpha)-(t\mathbin{\mathrm{OR}}\beta))
\mathbin{\mathrm{XOR}}\gamma\right)+1
+
\left[
\mathop{\mathrm{NOT}}(u\mathbin{\mathrm{OR}}\eta)
\mathbin{\mathrm{XOR}}
\left(((\delta-r)+(t\mathbin{\mathrm{OR}}\epsilon))
\mathbin{\mathrm{OR}}u\right)
\mathbin{\mathrm{XOR}}
\mathop{\mathrm{NOT}}(u\mathbin{\mathrm{OR}}\phi)
\right].
\]

Here \(g\) comes from a shared multiplier global, while the seven Greek-letter operands come from the corresponding selector’s parameter family.

The calculation of \(t\) precedes the candidate expression. Selector 19 additionally materializes \(u\mathbin{\mathrm{OR}}\phi\), including its global-mask read, before evaluating the rest of that expression. The representation does not otherwise establish an ordering among global operand reads within the candidate expression.

The decision bit is bit 31 of the 32-bit result \(k-r\). It is not generally interchangeable with an ordinary signed or unsigned less-than comparison.

After computing the bit, each state independently reads its transition global twice:

| Selector | Control when decision bit is zero | Control when decision bit is one |
|---|---|---|
| 0 | First transition read plus 15 | Second transition read |
| 6 | First transition read plus 10 | Second transition read |
| 19 | First transition read plus 3 | Second transition read |

Both reads occur before branch selection. Fixed control distances exist only if the corresponding reads agree.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Immediate return.** If the first dispatch selects 18, initialization and both dispatch-base reads occur, followed by return. No explicit object-field load, byte store, or dependency call occurs.

2. **Different seed coefficient.** If the cached second-coefficient read yields one value and the later seed-coefficient read yields another, arithmetic using \(a\) uses the former, while \(z\) uses the latter multiplied by the internal position address.

3. **Changing dispatch base.** If a dispatch’s first base read differs from its second, selector calculation uses the second. If that calculation selects 8, the next control uses the first, while the state sets \(p\) to 284 and restores the seed.

4. **Active-address test before adoption.** If selector 24 executes before selector 9, it tests the initial zero active address without dereferencing it, even for a nonzero input argument. Both transition reads still occur.

5. **Ordered field loading.** If selector 22 executes, its +0x18 load precedes the next-control read, which precedes both +0x14 loads. The two latter loads independently establish \(R\) and \(W\).

6. **Fresh call argument.** If selector 17 executes with readable object memory, it loads +0x100 into \(R\), calls F-5e3309c9d083 with that value, and reads next control only after the call returns.

7. **Zero field with changing control data.** If selector 3 reads zero, its next control is its first transition read minus 8. It still performs the second read. The selected control is eight below the nonzero candidate only if both reads agree.

8. **Store/control ordering.** For selector 4 with a writable destination, one byte is stored before the transition-global read, and progression advances afterward. Selector 5 instead uses its already retained dispatch value.

9. **Unlisted selector.** If selector subtraction produces an unlisted value, the default path performs the documented byte-writing operation using retained state; it does not take an established error path.

10. **Post-call global mutation.** If the dependency changes the global subsequently used for next control, the caller observes that later read rather than a guaranteed pre-call snapshot. The entry-cached coefficients are not refreshed.
