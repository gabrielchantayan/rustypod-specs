# F-26c6d02840b5

## Purpose

F-26c6d02840b5 performs a potentially unbounded sequence of indirect calls, address calculations, and memory updates. It returns a packed 64-bit result when either an early bit test succeeds or a later global-state test observes zero.

The available static evidence does not establish an application-level purpose. In particular, it does not justify identifying this operation as allocation, initialization, rendering, parsing, or resource management.

This contract distinguishes the visible operation order from effects delegated to unknown dependencies. It does not assume that those dependencies preserve global values, validate addresses, allocate storage, or release memory.

## Interface

### Explicit inputs

The recovered interface contains four 32-bit argument slots:

| Position | Interpretation established by the visible behavior |
|---|---|
| First | No direct use is visible. |
| Second | Used as a 32-bit address-like value, passed to a dependency, incremented by ten, and used in subsequent arithmetic. Replaced on each continuing iteration by a dependency-produced 32-bit value. |
| Third | No direct use is visible. |
| Fourth | Written as a 32-bit value at an offset from the second argument. On continuing iterations, replaced by a calculated product. |

The lack of visible use of the first and third inputs does not establish that they are irrelevant to the actual machine-level calling convention. The recovered calls leave parts of that convention unresolved.

### Additional entry state

The visible behavior also depends on values outside the four explicit arguments:

- An incoming 32-bit link-like value used to calculate the first indirect-call target.
- An incoming 32-bit register value passed as the first argument to that call.
- Another incoming 32-bit register value used later as an address addend.
- Accessible stack storage whose address is passed to the first dependency.
- Global storage used for an XOR operand, a later call argument, a continuation condition, and the upper half of the return value.
- Additional dependency-produced register values that are not represented as ordinary function returns.

These are part of the observed interface, not safely ignorable implementation details.

### Output

On a normal return, the result is 64 bits:

- Bits 31 through 0 contain a selected 32-bit value shifted left by one, retaining only its low 32 bits.
- Bits 63 through 32 contain a 32-bit global value minus `0x54`, retaining only its low 32 bits.

The selected value differs between the two return paths. The global value is read at the shared return operation; it must not be assumed to equal any earlier value.

There is no visible conventional success code, error code, exception handler, or null-result protocol.

### Arithmetic and memory interpretation

The calculations below describe 32-bit bit-vector behavior, with address calculations wrapping at 32 bits. Left shifts discard bits beyond the 32-bit result. Right shifts described as arithmetic propagate the sign bit.

This interpretation captures the apparent recovered machine operations; it is not a claim that signed overflow would be valid in a high-level language implementation.

Memory accesses have explicit widths of 8, 16, or 32 bits. Endianness, alignment support, memory permissions, and fault behavior are not established by the supplied representation.

## Behavior

### 1. Start an iteration and obtain a two-part result

Each iteration first invokes dependency **F-D01** with three visible arguments:

1. The current register-carried first-call value.
2. The current second argument.
3. The address of a local stack region.

The target for this invocation is calculated by clearing the low two bits of the current link-like value and adding `0x4A8`.

On the first iteration, both the link-like value and first-call value come from entry state. On a continuing iteration, they have been replaced as described below.

The function then invokes **F-D02**, which supplies a 64-bit result. Its low and high 32-bit portions are used separately.

After that call, the function:

1. Calculates the current second argument plus ten, modulo \(2^{32}\).
2. Writes the current fourth argument as a 32-bit value to the address formed by adding `0x3E` to the current second argument.
3. Tests bit 15 of the incremented value.

The recovered expression performs this test through a left shift by 16 followed by a signed-negative comparison. Under the 32-bit interpretation, the branch depends on bit 15, not on whether the entire original address or incremented value is negative.

### 2. Early return

If that bit is set, the function immediately takes the shared return path.

The lower return word is twice the low 32-bit portion supplied by **F-D02**, modulo \(2^{32}\). The upper return word is the return-global value minus `0x54`, modulo \(2^{32}\).

The preceding 32-bit write at offset `0x3E` has already occurred. None of the remaining operations in this iteration occurs on this path.

### 3. Perform the initial narrow writes and calls

If the early-return bit is clear, the function writes the low 16 bits of the **F-D02** result to the address formed from that result’s high 32 bits plus `0x3C`.

It then invokes **F-D03**, followed by **F-D04**.

The result from **F-D04** is treated as a 32-bit address-like value. The function writes the 16-bit value `0x0026` at offset two from it.

No visible check establishes that either destination is non-null, suitably aligned, mapped, or writable.

### 4. Derive a working address

Using the current second argument plus ten, the function calculates a signed shift-derived offset:

- Shift the incremented value left by 28 bits, retaining 32 bits.
- Interpret that result as signed and shift it right arithmetically by nine.

Only the low four bits of the incremented value influence this offset. Its possible values are multiples of `0x80000`, ranging from `−0x400000` through `0x380000`.

The function adds this offset to the incremented value, modulo \(2^{32}\). It then reads a 32-bit XOR-global value.

Next it invokes **F-D05** with two visible arguments:

- Twice the address-like result previously supplied by **F-D04**, modulo \(2^{32}\).
- The incremented value shifted left by 16 bits, then reduced by `0x51`, modulo \(2^{32}\).

Only after **F-D05** returns does the function XOR the previously calculated sum with the previously read XOR-global value. The result is the **working address** for the remaining operations.

This ordering matters: a change to the XOR-global during **F-D05** does not replace the already-read operand.

The signed shift-derived offset is also increased by `0x2F`, modulo \(2^{32}\), producing the **adjusted offset**.

The working address is stored as a 32-bit value in a local stack slot at offset `0x130`.

### 5. Read a byte, call a dependency, and update the working region

The function reads one byte at working address plus one and invokes **F-D06** with four visible arguments:

1. The fixed address-like constant `0x085734E8`.
2. The byte just read.
3. The adjusted offset.
4. An additional register value associated with the preceding **F-D05** call.

The representation does not establish the byte argument’s extension convention beyond identifying the memory access as an 8-bit read.

After **F-D06** returns, the function writes the adjusted offset as a 32-bit value at working address plus `0x24`.

The write is later than the call. A dependency that accesses overlapping storage therefore need not observe the post-call value during its invocation.

### 6. Calculate the next carried value and perform the final calls

The function invokes **F-D07** and uses an additional 32-bit register result from that call. It adds `0x30` to that result, modulo \(2^{32}\), producing an **adjusted register value**.

It then:

- Sets the next iteration’s first-call value to twice the working address, modulo \(2^{32}\).
- Replaces the current fourth argument with the product of two copies of twice the adjusted register value, modulo \(2^{32}\).

The product is consequently a multiple of four in its low 32-bit representation. It is not necessarily nonzero, and it must not be interpreted as a non-overflowing mathematical square.

Next, in order, the function:

1. Invokes **F-D08** with the working address plus the entry-carried address addend, modulo \(2^{32}\).
2. Reads a separate 32-bit global value.
3. Invokes **F-D09** with that read value.
4. Sets the link-like state to `0x08573459`.
5. Invokes **F-D10**.
6. Reads the continuation global and compares it with zero.

The entry-carried address addend has no visible update within the function. Its preservation across unknown calls is a calling-convention uncertainty, not an independently established dependency guarantee.

### 7. Late return or continuation

If the continuation global is zero, the function takes the shared return path:

- It interprets the additional 32-bit register result associated with **F-D10** as signed and shifts it right arithmetically by nine.
- It doubles that shifted value, retaining 32 bits, for the lower return word.
- It reads the return-global value and subtracts `0x54`, retaining 32 bits, for the upper return word.

The final iteration-ending write described below does not occur on this path.

If the continuation global is nonzero, the function instead:

1. Writes the newly calculated fourth-argument value as 32 bits to twice the adjusted register value plus `0x34`, modulo \(2^{32}\).
2. Replaces the second argument with the additional 32-bit register result associated with **F-D10**.
3. Starts another iteration.

The next iteration’s first indirect-call target is calculated from the assigned link-like value. Its first-call argument is the doubled working address calculated in the preceding iteration.

No iteration bound is visible. Normal termination requires reaching one of the two return conditions.

## Acceptance examples

These are conditional static acceptance cases, not results of runtime testing.

### Early return still performs the first write

Suppose the current second argument is `0x00007FF6`. Adding ten produces `0x00008000`, whose bit 15 is set.

If the first two dependencies return normally and the destination is writable:

- The current fourth argument is written as 32 bits at `0x00008034`.
- The function returns through the early path.
- The 16-bit write based on the high part of **F-D02** does not occur.

If **F-D02** supplied low word `0x80000003` and the return-global read yields `0x00000060`, the packed return is `0x0000000C00000006`.

### The early condition is not an overall signed-address test

Suppose the current second argument is `0x0000FFF6`. Adding ten produces `0x00010000`.

Bit 15 is clear, so the early return is not taken. For this incremented value, the shift-derived offset is zero and the adjusted offset is `0x2F`.

Subject to valid accesses and returning dependencies, the later 32-bit write at working address plus `0x24` therefore stores `0x0000002F`.

### XOR uses the earlier read

Suppose the XOR-global is read as value A, and **F-D05** changes that global to value B.

The current iteration’s working address uses A. A later iteration may read B or another value, depending on intervening effects.

### Late return omits the continuation write

Suppose **F-D10** supplies additional register bits `0xFFFFFE00`, and the subsequent continuation-global read yields zero.

The arithmetic right shift by nine produces `0xFFFFFFFF`; doubling produces lower return word `0xFFFFFFFE`.

The final write at twice the adjusted register value plus `0x34` does not occur. Earlier writes in the same iteration remain observable.

### Nonzero continuation carries calculated state forward

Suppose the adjusted register value is three. The replacement fourth argument is 36, because twice three multiplied by twice three is 36.

If the continuation global is nonzero:

- A 32-bit value of 36 is written at address `0x0000003A`.
- The next iteration uses **F-D10**’s additional register result as its second argument.
- The next iteration’s offset-`0x3E` write uses 36, unless execution fails before that write.

This example is conditional on the low address being writable; it does not establish that such an address is valid.
