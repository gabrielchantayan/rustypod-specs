# F-ae76420a25e7

## Purpose

F-ae76420a25e7 constructs a word by OR-combining three shifted inputs with an unshifted input, then writes that word to one of three selector-dependent destinations. It returns success for selectors 0, 1, and 2, and an all-ones failure value for every other selector.

The established behavior is word construction and a selected store. Interpreting the destinations as configuration registers, or interpreting the inputs as hardware fields, is inferred intent only. The supplied material does not identify the destination object, its ownership, or any device-level meaning of a write.

This contract distinguishes the directly visible behavior from assumptions about the execution environment. No runtime tests have been performed.

| 3 | Middle contribution | Signed integer | Contributes through a left shift of 16 bits. |
| 4 | Lower contribution | Signed integer | Contributes through a left shift of 12 bits. |

These names describe the interface; they do not establish independent, nonoverlapping fields.

The recovered interface is consistent with 32-bit signed integers, 32-bit unsigned integers, and a 32-bit return value. The offsets are eight bytes apart. Under the 32-bit-word interpretation, the function writes four bytes at the chosen offset; it does not explicitly write the intervening four bytes.

## Behavior

### Word construction

The visible expression combines four contributions by bitwise OR:

- High contribution shifted left by 28.
- Middle contribution shifted left by 16.
- Lower contribution shifted left by 12.
- The complete seed word, unshifted.

There is no explicit masking, clamping, range validation, or normalization of any contribution. In particular:

- The high contribution is not explicitly restricted to four bits.
- The middle contribution is not explicitly restricted to twelve bits.
- The lower contribution is not explicitly restricted to four bits.
- The seed word is not explicitly restricted to twelve bits.

Consequently, this is not an unconditional promise to replace four independent fields. Where contributions overlap, a one bit from any contribution makes the resulting bit one. A contribution cannot clear a bit supplied by another contribution.

Under the 32-bit interpretation, nonnegative inputs in the following ranges avoid signed-left-shift overflow in the displayed expressions:

| Contribution | Range avoiding signed-left-shift overflow |
|---|---|
| High | 0 through 7 |
| Middle | 0 through `0x7FFF` |
| Lower | 0 through `0x7FFFF` |

These are arithmetic limits for the displayed signed shifts, not validated application limits. The function contains no checks enforcing them.

A narrower, field-like input convention is suggested by the shift positions: four high bits, twelve middle bits, four lower bits, and twelve seed bits. That interpretation is not enforced. In particular, a high contribution from 8 through 15 would require behavior beyond the ordinary defined range of the displayed 32-bit signed shift. Such inputs must not be assigned a portable result solely from this representation.

### Selection and store

The combined-word expression appears before selector handling.

For selector 0, the function explicitly stores the combined word at base plus `0xD8`.

For selector 1, it explicitly stores the combined word at base plus `0xE0`.

For selector 2, it explicitly stores the combined word at base plus `0xE8`.

After the selected store, the function returns success.

For every other selector, the function returns the all-ones failure value without an explicit destination store. Negative selectors are unsupported in the same way as positive selectors outside 0 through 2.

Because word construction precedes selector rejection in the supplied representation, an unsupported selector is not evidence that problematic shift operands are safely bypassed. The unconditional failure behavior is established only where evaluating the preceding expression is well-defined, or where lower-level execution semantics have independently been established.

### Read and write ordering

The visible operation sequence is:

1. Construct the combined word from the scalar inputs.
2. Determine whether the selector identifies a supported destination.
3. On a supported selection, use the global base reference to address that destination and perform the store.
4. Return the corresponding result.

No destination-word read is explicit. The update is therefore an overwrite, not a read-modify-write that preserves the destination’s previous contents.

The supplied representation does not establish the evaluation order among the individual contributions. They contain no explicit calls or memory accesses, so no distinction between their evaluation orders is visible here.

These are source-visible ordering facts. They do not establish compiler-level access scheduling, memory barriers, hardware transaction order, or synchronization with other execution contexts.

## Side effects

For a supported selector and a completing memory access, the function performs one explicit unsigned-word store at the selected base-relative address.

It does not explicitly:

- Read the old destination value.
- Update either of the other two destinations.
- Change the global base reference.
- Allocate, release, or transfer ownership of memory.
- Invoke another function.
- Report an error through a separate state field.

The destination must be writable with the required word width. Address validity, alignment requirements, and permission checks are external preconditions. The function does not visibly validate them.

No recoverable outcome is established for an invalid base reference or a failed store. In particular, the success return must not be treated as guaranteed when the memory operation cannot complete.

There is no explicit synchronization. Atomicity, visibility to other threads or processors, and behavior during concurrent changes to the global base reference remain unspecified. The presence of one word-sized store does not independently establish any of those guarantees.

## Acceptance examples

These examples are conditional static expectations, not observed test results. They assume the 32-bit interpretation, valid destination storage, stable access to the global base reference, and completion of the memory operation.

### Ordinary composition

Given:

- Selector 1.
- High contribution 2.
- Middle contribution `0x345`.
- Lower contribution 6.
- Seed word `0x789`.

The combined word is `0x23456789`. The function writes that value at base plus `0xE0` and returns `0x00000000`. No explicit store targets the other two destinations.

All three shifted inputs in this example remain within the signed-shift limits described above.

### Zero overwrites the selected word

With selector 0 and all four contributions zero, the function writes zero at base plus `0xD8` and returns success.

This remains an overwrite even if the destination previously held nonzero data. No old bits are explicitly retained.

### Seed bits are unrestricted

With selector 2, all shifted contributions zero, and seed word `0x80000001`, the function writes `0x80000001` at base plus `0xE8`.

The seed’s upper bit is not removed by a low-field mask.

### A contribution extends beyond its apparent field

With selector 0, high and middle contributions zero, lower contribution `0x10`, and seed word zero, the stored word is `0x00010000`.

The lower contribution reaches bit 16 because no four-bit mask is applied before its shift.

### Overlapping contributions combine by OR

With selector 2, high contribution 1, middle contribution `0x1000`, and the other contributions zero, both shifted contributions set bit 28. The stored word is `0x10000000`, not their arithmetic sum.

### Unsupported selector

With selector 3 and all contributions zero, the function returns `0xFFFFFFFF` and performs no explicit destination store. The same expectation applies to selector −1 with those contribution values.

### Signed-shift boundary requiring further evidence

With a high contribution of 8, the displayed signed shift exceeds the positive signed 32-bit range. No portable acceptance value is established here. A requirement that this input produce a particular top-bit pattern needs additional evidence about the actual execution semantics.
