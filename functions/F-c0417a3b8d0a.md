# F-c0417a3b8d0a

## Purpose

F-c0417a3b8d0a coordinates a long sequence of externally dependent calls and memory accesses. Its established effects include computed-address word stores, byte-selected byte stores, forwarding of loaded values to dependencies, consumption of paired 32-bit results, shared-storage publication, and a terminal halfword clear followed by an attempted call to address zero.

No application-level purpose is established. The available evidence does not justify describing the routine as object construction, subsystem initialization, a supervisor operation, or successful termination.

This contract describes static behavior only. Reaching any operation requires all preceding accesses and calls to complete normally. No runtime tests have been performed.

### Width and arithmetic conventions

A **byte**, **halfword**, and **word** mean 8-, 16-, and 32-bit accesses respectively. A represented 64-bit result has a low 32-bit half and a high 32-bit half; this description does not establish the actual return ABI.

Byte stores retain only the low eight bits. Unsigned byte loads produce values from 0 through 255. Unsigned word right shifts insert zeros.

Numerical examples assume 32-bit machine arithmetic, with the low 32 bits retained after additions, multiplications, and left shifts. That assumption is not a claim that every signed expression in the supplied representation has defined language-level overflow behavior.

## Behavior

### Execution order and dependency boundaries

The represented body has no explicit loop or conditional branch. Its normal path is one fixed sequence, but a faulting access or nonreturning dependency can prevent any later operation.

Calls are observable boundaries. Their memory effects are unknown. Consequently, a shared value cleared earlier need not remain zero, and separately performed loads must not be merged merely because their address expressions match.

A retained value is different from a repeated memory load. The late snapshot of address 1 described below is explicitly reused; it is not refreshed after intervening calls.

### Initial stores and dispatch

Before invoking any dependency, the routine writes the first input as a word at four times that input plus 20.

F-unknown-001 then receives four explicit arguments in this order: first input, first input, third input, first input. Its target is derived from incoming link state plus 4094.

Further computed-target calls produce an index. The routine stores the first input at four times that index plus 20, then invokes a dependency with four times the index.

Later call chains produce indices used for:

- A word store of four times an index at sixteen times that same index plus 20.
- A subsequent word zero store at four times another index plus 20.

These are absolute-address calculations. No allocation base, array extent, or object boundary is established.

### Byte-selected writes and early forwarding

A recurring operation first reads an unsigned byte from a computed selector address, then writes a byte at the loaded value plus 17. Each such destination is therefore within addresses 17 through 272.

The first occurrence uses a dependency-produced unsigned word. Its selector address is obtained by retaining the low 30 bits, shifting right by 16, and adding one. The stored byte is the low byte of four times the original word.

After intervening calls, a related selector uses the same retained word with a right shift of 17 instead; its selected destination is cleared.

Later selectors use other retained values, masks, shifts, additions, and multiplications. Unless a snapshot is explicitly retained, each selector load occurs separately and can observe intervening memory changes.

A later dependency receives a scaled call result and the third input shifted left by 31. Under 32-bit arithmetic, the latter argument depends only on input parity: zero for an even input, or bit 31 set for an odd input.

The routine also:

- Reads an unsigned byte at eight times the earlier retained word and supplies it in all four argument positions of a call.
- Clears additional byte-selected destinations, including one selected directly by the byte at address 1.
- Supplies two copies of a scaled index and the earlier widened byte shifted left by 31 to another call.
- Calls a dependency with a secondary-channel word shifted right by 18, then forwards the resulting word four times.

### Paired results and dependent reads

For the first represented 64-bit result, the required relative order is:

1. Capture its low 32-bit half for later use.
2. Read a selector byte at one plus a previously available secondary-channel word shifted right by 9.
3. Clear the byte at that selector value plus 17.
4. Only then invoke the dependency consuming the paired result’s high 32-bit half.

The high-half consumer therefore runs after the clearing store and may observe or modify the selected memory. Moving that call before the store changes the established ordering.

After further calls and another selector clear, the routine reads a word using the retained low half as a base. Its displacement is obtained by shifting that low half right by 19 and then left by 31. Under 32-bit arithmetic, the displacement is either zero or `0x80000000`, selected by bit 19 of the retained low half. The loaded word is supplied four times to a dependency.

Another region reads a byte at offset 14 from a secondary-channel address and forwards it in four positions. A later paired result supplies a retained low-half value used for selector addresses, including that value multiplied by 4096 plus one.

The routine subsequently passes the same stack-local address in all four explicit argument positions of one call. Neither initialized contents nor the extent of storage accessible through that address is established.

### Byte-to-halfword addressing and indexed publication

A further paired result supplies a retained low-half address base. After intervening calls, a byte is read at that base plus a secondary-channel displacement. Its unsigned value is forwarded four times.

A later secondary-channel word is shifted right by 19. The routine reads a halfword at the sum of that shifted value and the previously captured unsigned byte. The halfword is forwarded in all four explicit positions of a call.

The next paired result has two distinct uses:

- Its high half selects a word destination at four times that half plus 20. The stored value is the earlier secondary-channel word shifted right by 19.
- Its low half supplies the base for two byte writes at offset 13.

A later call-produced index receives the same shifted word through another four-times-index-plus-20 destination.

The offset-13 stores occur in this order: first the low byte of twice the retained base, then, after intervening calls, the constant 4. Dependencies between them may observe the first value.

Associated word loads use four times a call-produced unsigned word plus 68, and the low 30 bits of that word shifted right by 20 plus 68. These are distinct address expressions.

### Repeated scaled storage and retained fields

The middle portion repeatedly alternates indexed stores, scaled arguments, and externally dependent calls. Important access forms include:

| Access | Address | Stored or loaded significance |
|---|---|---|
| Word store | Four times an index plus 20 | Retained input, result, byte widened to a word, shifted field, or zero |
| Word store | Sixteen times an index plus 20 | Often four times that index |
| Word store | 256 times an index plus 20 | Four times an earlier retained word |
| Word clear | Sixteen times a retained index plus 36 | Zero |
| Word load | Sixteen times that retained index plus 116 | Supplies a subsequent base |
| Word store | That loaded base plus 36 | A dependency-produced unsigned word shifted right by 20 |
| Word load | That same base plus 116 | Forwarded to a dependency |

Multipliers of 4, 16, and 256 are not interchangeable. Aliasing requires particular values, wraparound, or overlapping storage.

The word shifted right by 20 is retained for later operations. Shifting that intermediate value right by another 21 necessarily yields zero. Multiplying the intermediate value by 1024 for selector addressing does not generally yield zero.

Several bytes are read at offset 21 from secondary-channel addresses and passed to dependencies. One captured byte is also written as a full unsigned word at a secondary-channel-derived indexed destination.

### Shared clearing and zero-derived accesses

The routine explicitly clears shared word A. Calls and additional indexed stores occur before its later reads; the clear does not establish those later reads as zero.

Separately, retained unsigned values are explicitly assigned zero. Their subsequent represented local transformations remain zero until reassignment. This causes zero arguments, zero-valued indexed stores, and selector reads at address 1.

Some address-1 selections are independent reads separated by calls. They may select different destinations. A later byte captured from another address is itself used as the address component of a read at that byte value plus one.

Established width consequences include:

- An unsigned byte masked to 22 bits and shifted right by 12 yields zero.
- An unsigned word shifted right by 19 and then right by 22 yields zero.
- A captured unsigned shared word shifted right by 23 and then by another 23 yields zero, regardless of the captured value.

These facts do not eliminate the surrounding calls, loads, or stores.

### Late traversal and shared-state reads

A later region clears a byte at offset 9 from a scaled computed address. Another byte store writes the low byte of a retained address-like value at that value plus 9. A word at offset 52 from the latter base is read and passed to a dependency.

The following traversal mixes scaled destinations and unscaled loads. In particular, a store at four times a secondary-channel value plus 20 is followed by a load at that secondary-channel value plus 20. Those are not generally the same address.

Further loads use right-shifted words plus 20, while another store uses four times a right-shifted word plus 20.

Shared word A is captured in this region. Its captured contents are used in shifts and dependency arguments; they cannot be replaced with the earlier explicit zero. A separate indexed load supplies a shifted value used in subsequent byte-selected stores.

### Late address-1 snapshot and first publication to shared word B

Near the end, after an earlier independent address-1-selected clear and additional calls, the routine captures the unsigned byte at absolute address 1. This captured byte has a specific retained role:

1. Clear the byte at the captured value plus 17.
2. Retain the captured value across subsequent dependency calls.
3. Obtain a call-produced word and publish it to shared word B.
4. Invoke the next dependency with that published word.
5. After another call, read a full word at the captured byte value plus 116.
6. Store the low byte of that word at the captured byte value plus one.

The addresses in the final two steps use the retained byte, not a fresh load from address 1. A dependency changing address 1 after capture does not change those address calculations.

The word at captured-value-plus-116 is nevertheless loaded later, after the intervening calls. Its contents are not snapshotted when address 1 is read.

Subsequent offset-116-to-offset-1 transfers use other bases. One new base is obtained by scaling a call result by four; two word loads from that base plus 116, separated by calls, each supply a byte store at that base plus one. Another scaled base supplies a further transfer whose loaded word is retained for indexed publication.

### Final shared-state use and termination

Additional indexed stores follow. A later paired result supplies a low half scaled by four and a high-half index; the scaled low half is stored through that index and subsequently through another call-produced index.

Shared word A is captured again. After intervening calls, a word is loaded at that captured value plus 20. Its low byte and a right-shifted portion supply later byte-selected stores.

The final visible sequence is:

1. Obtain a dependency result with byte-width significance.
2. Clear one byte through a secondary-channel pointer.
3. Overwrite shared word B with a composite word: the result byte supplies bits 0–7, and a separately referenced three-byte quantity supplies bits 8–31.
4. Clear a halfword at the address obtained by retaining the low 30 bits of a retained word and shifting right by 7.
5. Attempt F-unknown-005 with three zero arguments.
6. Return only if that call returns.

The composite assignment is not established as preserving shared word B’s own previous upper bytes.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid accesses and normally returning preceding dependencies.

1. **Initial ordering.** First input 3 causes a word store of 3 at address 32 before F-unknown-001.

2. **Parity extraction.** Under 32-bit arithmetic, shifting third input 2 left by 31 produces zero; input 3 produces `0x80000000`.

3. **Selector range and truncation.** A selector byte of 255 selects address 272. A byte-store value of `0x1234` publishes `0x34`.

4. **First paired-result ordering.** If the relevant selector byte is 5, address 22 is cleared before the dependency consuming the first paired result’s high half runs. That dependency may observe the cleared byte.

5. **Fresh selector reads.** If a dependency changes a selector byte from 5 to 9 between independent occurrences, the later selected destination is address 26 rather than 22.

6. **Retained late snapshot.** If the late address-1 capture is 5, the immediate clear targets address 22. Even if a later dependency changes address 1 to 9 before shared word B is first published, the subsequent word load uses address 121 and its low-byte store targets address 6.

7. **Snapshot does not freeze source contents.** In the preceding example, a dependency changing the word at address 121 before its later load changes the byte eventually stored at address 6.

8. **Separate scaled-base loads.** If the two offset-116 loads using the same later base observe different words because of an intervening dependency, their offset-1 stores may publish different low bytes.

9. **Temporary publication.** A dependency between the offset-13 stores may observe the first truncated value before the later constant 4.

10. **Terminal failure.** If address zero is not callable, normal return is not established. The preceding shared-word overwrite and halfword clear have already occurred.
