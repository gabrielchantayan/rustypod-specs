# F-463e2b74e59b

## Behavior

### Established operation order

The supplied static representation establishes the following sequence:

1. The function evaluates the shared base value and retains that value for the second destination.
2. It evaluates the shared base value again to obtain the base used for the first destination.
3. It writes the first input as a four-byte value at offset 8 from the base used by that second evaluation.
4. It writes the second input as a four-byte value at offset 12 from the base retained by the initial evaluation.
5. It returns without an explicit result.

The retained base is therefore used for the **second write**, not necessarily both writes. There is no explicit reread of the shared base between the first write and the second write.

This is the order expressed by the supplied representation. Exact generated load instructions, compiler transformations, and hardware visibility order are not established.

### Stable-base behavior

When the two base evaluations produce the same address B, and both writes complete:

- The four-byte field at B + 8 contains the first input.
- The four-byte field at B + 12 contains the second input.
- The first field is written before the second in the represented execution order.

The offsets differ by four bytes. Consequently, under ordinary nonwrapping address arithmetic, these are adjacent, nonoverlapping four-byte destinations.

No read of either field’s previous contents is shown. The operation replaces each field rather than combining the input with the previous value.

### Changing-base behavior

The two base evaluations must not be silently treated as one guaranteed snapshot.

If the first evaluation yields address A and the second yields address B, the represented destinations are:

- First input: B + 8.
- Second input: A + 12.

This conditional behavior does not establish that an unsynchronized concurrent modification is valid on the target. It identifies which evaluation supplies each address if differing evaluations occur in a supported execution environment.

Similarly, changing the shared base as a consequence of the first write would not, by itself, redirect the second write: the second destination uses the already-retained value.
