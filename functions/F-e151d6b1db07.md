# F-e151d6b1db07

## Purpose

F-e151d6b1db07 conditionally performs a state update when a supplied signed 32-bit value is strictly greater than a signed 32-bit reference value obtained through an object.

When the condition is satisfied, the function increments an object word, invokes two dependencies in order, replaces another object word with the second dependency’s result, and changes a separate object word from zero to one if it is still zero at the final check.

A null comparison pointer, an equal value, or a smaller signed value prevents those explicit writes and dependency calls. These cases do **not** prevent all reads: the reference value is read even when the comparison pointer is null.

The meaning of the object, its counter-like word, the reference value, and the dependency result is not established. Descriptions such as “counter” and “flag” below identify observed operations, not application-level semantics.

## Interface

### Inputs

The recovered interface has three arguments:

1. **Object pointer.** A pointer to storage accessed as an array of 32-bit words. No null check is shown.
2. **Optional comparison pointer.** Either null or a pointer from which one signed 32-bit value is read.
3. **Opaque 32-bit value.** A four-byte value copied into temporary storage for the second dependency. No interpretation or validation of its bits is shown.

The function has no explicit return value. Its observable results are memory effects and dependency calls.

### Object layout used by this function

Offsets are byte offsets from the object pointer.

| Offset | Width | Observed use |
|---|---:|---|
| `+0x00` | 4 bytes | Address-bearing word, read to locate the reference value and read again for the second dependency |
| `+0x04` | 4 bytes | State word checked after the second dependency; changed to one only if zero |
| `+0x08` | 4 bytes | Argument to the first dependency; later replaced with the second dependency’s result |
| `+0x40` | 4 bytes | Incremented once on the accepted path |

The address-bearing word at `+0x00` identifies storage containing a signed 32-bit reference value at byte offset `+0x58`.

This is a description of accessed locations, not proof of a complete object layout. The object need not have meaningful fields at every intervening offset.

## Behavior

### Initial reads and decision

The visible access order is:

1. Read one four-byte value from a global location. Preserve this value for a possible later dependency call.
2. Determine whether the comparison pointer is null.
3. If it is nonnull, read its signed 32-bit comparison value.
4. Read the object’s address-bearing word at `+0x00`.
5. Read the signed 32-bit reference value at `+0x58` relative to that address.

The global read and reference read occur before the early-return decision. In particular, a null comparison pointer does not make an invalid object pointer or invalid reference address safe.

The function proceeds only when the comparison pointer is nonnull and its captured signed value is strictly greater than the captured signed reference value.

The recovered condition uses a subtraction result together with a signed-overflow indication. Its effect is a signed comparison, not a test of the subtraction’s sign bit alone. Thus:

- Equality is rejected.
- A smaller signed value is rejected.
- A greater signed value is accepted.
- Unsigned ordering is not the decision rule.
- A subtraction that crosses the signed 32-bit range does not by itself reverse the ordering decision.

The captured comparison and reference values determine this decision. Neither value is reread to reconsider acceptance.

### Rejected path

If the comparison pointer is null, or its value is less than or equal to the reference under signed 32-bit ordering, the function returns.

On this path, the visible body:

- Makes no calls to either listed dependency.
- Does not increment the word at `+0x40`.
- Does not explicitly write the words at `+0x04` or `+0x08`.
- Still performs the initial reads described above, except for dereferencing a null comparison pointer.

“No explicit writes” does not mean “no observable effects” for memory with read-sensitive behavior.

### Accepted path

When the comparison value is strictly greater than the reference, the following operations occur in order:

1. Read the object word at `+0x40`, add one, and write the result to that location.
2. Copy the third argument into the first word of a temporary argument area. The adjacent second word contains the reference value captured earlier.
3. Read the object word at `+0x08` and pass it as the sole visible argument to **F-94cb53877c15**.
4. After that dependency returns, reread the object word at `+0x00`.
5. Invoke **F-adee04f6d176** with:
   - The newly read address-bearing word.
   - The four-byte global value captured before the acceptance decision.
   - The address of the temporary argument area.
6. After that dependency returns, write its 32-bit result to the object word at `+0x08`.
7. Read the object word at `+0x04`.
8. If that word is zero, write the 32-bit value one there. If it is nonzero, leave it unchanged.
9. Return without an explicit result.

The temporary area has the following visible arrangement at the point the second dependency is called, absent intervening modification:

| Offset from supplied temporary-area address | Width | Contents |
|---|---:|---|
| `+0x00` | 4 bytes | Opaque third argument |
| `+0x04` | 4 bytes | Initially captured signed reference value |

The arrangement supports describing two adjacent words. It does not establish a named structure, byte order, an access bound for the dependency, or a persistent allocation.

### Timing and mutation-sensitive behavior

Several values are deliberately distinguishable by when they are read:

- The global value is captured before either dependency runs. A later change to that global does not cause this function to reload the second dependency’s corresponding argument.
- The address-bearing word is read once for the reference lookup and again after the first dependency returns. The second dependency can therefore receive a different address-bearing value from the one used for the initial reference lookup.
- The state word at `+0x04` is tested only after the second dependency returns. Its entry value does not determine the final conditional write.
- The word at `+0x08` is read for the first dependency and overwritten only after the second dependency returns.
- The increment occurs before both dependency calls. There is no visible rollback if a dependency does not complete normally.

No dependency is assumed to preserve globals or object storage.

### Arithmetic widths

The comparison values, reference value, accessed object words, opaque argument, and dependency result are represented as four-byte quantities.

The strict-greater-than decision is a signed 32-bit comparison, including at the signed extremes. For example, the greatest signed 32-bit value is greater than the least signed 32-bit value even though a four-byte subtraction can overflow.

The increment is shown as a 32-bit signed addition followed by storage into a four-byte word. For values below the signed maximum, the ordinary increment is established. At the signed maximum, the source rendering alone does not settle the language-level overflow contract. A wrapping machine increment is a plausible interpretation, but is not promoted here to an established guarantee.

No saturation, range check, explicit overflow error, or widening operation is shown.

## Side effects

### Direct memory effects

On the accepted path, the function explicitly:

- Increments the word at object offset `+0x40`.
- Writes the second dependency’s result at `+0x08`.
- Writes one at `+0x04` only if the value read there after the second dependency is zero.
- Initializes temporary storage used as a dependency argument.

On the rejected path, none of these explicit writes occurs.

These statements describe operations performed by this function. They do not bound additional memory effects produced by either dependency.

### Ownership and lifetime

The function contains no explicit allocation or deallocation operation.

The first dependency receives the current four-byte value at object offset `+0x08`. That call could have resource-management significance, but release, destruction, reference counting, and ownership transfer are not established.

The second dependency receives a pointer to temporary local storage. The visible function does not create a persistent copy of that area or establish a valid post-return lifetime for it. Whether the dependency copies its contents, modifies them, or retains the pointer is unknown.

Replacing the word at `+0x08` does not, by itself, establish ownership of either the old value or the replacement.

### Errors and interruption

If a dependency fails to return normally, subsequent operations are not established to occur. In particular, the counter-like update precedes both calls, while the result replacement and final state-word check follow the second call.

Atomicity, synchronization, reentrancy, and concurrent mutation behavior are not established.

## Acceptance examples

These are conditional contract examples derived from static evidence, not executed tests. Unless otherwise stated, they assume valid memory, ordinary storage, normally returning dependencies, and no relevant dependency-induced mutation.

1. **Null comparison pointer.**  
   The function reads the global value and reference value, then returns. Neither dependency is called, and the object receives no explicit writes. An invalid reference address can still prevent normal completion.

2. **Equal values.**  
   With comparison and reference both equal to 12, the function rejects the update. The counter-like word, replacement word, and state word are not explicitly changed.

3. **Signed ordering differs from unsigned ordering.**  
   With comparison value −1 and reference value 0, the function rejects the update. Treating the comparison bits as a large unsigned value would produce the wrong result.

4. **Accepted negative values.**  
   With comparison value −2 and reference value −3, the function accepts. Signed negativity alone does not prevent the update.

5. **Signed-extreme comparison.**  
   With comparison value 2,147,483,647 and reference value −2,147,483,648, the function accepts. Reversing those values causes rejection. The ordering must account for signed subtraction overflow.

6. **Ordinary successful update.**  
   With comparison 9, reference 8, counter-like word 20, and final state word zero, the explicit effects are: counter-like word becomes 21; the dependencies run in order; the second dependency’s result replaces the word at `+0x08`; and the state word becomes one.

7. **Nonzero state is preserved.**  
   If the word at `+0x04` is −7 when the final check occurs, this function leaves it at −7. It does not normalize every nonzero value to one.

8. **First dependency changes the address-bearing word.**  
   If the first dependency changes object offset `+0x00` and returns, the second dependency receives that changed value. The temporary reference word still originates from the earlier lookup; the function does not repeat that lookup.

9. **Dependency changes the global input.**  
   If the first dependency changes the global location, the second dependency still receives the value captured before the comparison decision.

10. **Second dependency changes the state word.**  
    If it leaves `+0x04` nonzero, no final write occurs there. If it leaves that word zero, the function writes one, regardless of the word’s entry value.
