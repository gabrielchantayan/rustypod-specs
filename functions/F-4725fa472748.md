# F-4725fa472748

## Purpose

F-4725fa472748 generates interleaved, two-channel signed 16-bit frames by fixed-point linear interpolation. Generated frames are written into storage beginning at byte offset 48 from a supplied state address. A separate output-count location is cleared and then incremented for each completed output frame.

The function first processes an interval between a historical frame held in the state and the first input frame. It then processes intervals between supplied input frames. On normal completion, it saves the final supplied frame as history and updates the phase for a subsequent invocation.

**Established static behavior:** sample layout, interpolation arithmetic, phase progression, output writes, count updates, terminal state changes, and the packed result.

**Inferred intent:** streaming two-channel sample-rate conversion. Channel meanings, the rate convention, and the surrounding streaming protocol are not established.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

| Argument | Represented width | Role |
|---|---:|---|
| State address | 32-bit integer address representation | Identifies mutable phase, historical samples, and embedded output storage. |
| Input address | 32-bit address component in the result | Identifies interleaved signed 16-bit input samples. |
| Input frame count | Signed 32 bits | Supplies the input-block length used in interval checks and terminal indexing. |
| Output-count address | Address of signed 32-bit storage | Receives zero initially, then one increment per completed output frame. |

Each input frame occupies four bytes:

| Frame-relative offset | Width | Meaning |
|---:|---:|---|
| 0 | Signed 16 bits | First channel |
| 2 | Signed 16 bits | Second channel |

Frames are contiguous. No independent channel or frame stride is supplied.

The state-address argument and packed result establish a 32-bit address representation for this operation. They do not establish portability to a wider address space.

### State layout

Offsets are measured in bytes from the state address.

| Offset | Width | Explicit access | Meaning |
|---:|---:|---|---|
| 36 | 32 bits | Initial read; terminal write | Unsigned fixed-point phase |
| 40 | 32 bits | Initial read | Signed increment whose addition to the phase uses unsigned arithmetic |
| 44 | Signed 16 bits | Initial read; terminal write | Historical first-channel sample |
| 46 | Signed 16 bits | Initial read; terminal write | Historical second-channel sample |
| 48 onward | Four bytes per generated frame | Sequential writes | Interleaved output frames |

No output-capacity value is read. No other state fields are explicitly accessed, apart from accesses that coincide because of overlapping storage or invalid address arithmetic.

### Result

The result is 64 bits:

- Low 32 bits: original state-address bit pattern.
- High 32 bits: original input-address bit pattern.

The result contains neither an output count nor an error status. It does not return an advanced input address.

### Safe-use conditions

The ordinary bounded-buffer interpretation requires:

- Readable state phase, increment, and historical samples.
- Writable terminal phase and historical-sample fields.
- At least one readable input frame, including when the supplied count would otherwise imply no input.
- Writable output-count storage.
- Sufficient writable output storage for every generated frame.
- Suitable alignment and valid address calculations for all accesses.
- Arithmetic values that avoid unsupported signed overflow and out-of-range representation conversions.
- An increment and starting position that reach the terminal condition before exhausting output storage.

Disjoint input, output, state metadata, and count storage are needed for the ordinary interpretation without alias-dependent interference. The function does not enforce disjointness.

These are safe-use conditions, not validation rules. The function has no explicit rejection path for invalid arguments.

## Behavior

### Initialization and observable access order

The initial accesses appear in this order:

1. Read the 32-bit phase from state offset 36.
2. Read the 32-bit increment from state offset 40.
3. Store zero through the output-count address.
4. Read and sign-extend the historical first-channel sample.
5. Read and sign-extend the first input frame’s first-channel sample.
6. Read and sign-extend the historical second-channel sample.
7. Read and sign-extend the first input frame’s second-channel sample.

Consequently, a zero or negative frame count does not prevent the initial input reads.

The phase, increment, and these samples are retained internally. The phase and increment fields are not reread during generation. Overlapping writes to those fields therefore do not change the retained values.

Output begins at state offset 48.

### Phase and interpolation arithmetic

The phase is an unsigned 32-bit quantity interpreted as having 16 fractional bits. One interval corresponds to 65,536 phase units.

Within a selected interval, let:

- \(a\) be the signed 16-bit starting sample, sign-extended to 32 bits.
- \(b\) be the signed 16-bit ending sample, sign-extended to 32 bits.
- \(r\) be the fractional phase, from 0 through 65,535.
- \(f=\lfloor r/2\rfloor\), from 0 through 32,767.

For each channel, the computed sample is:

\[
a+\left\lfloor\frac{(b-a)f}{32768}\right\rfloor.
\]

This formula reflects arithmetic right shifts in the represented computation. Negative products round toward negative infinity rather than toward zero. The least significant fractional phase bit does not affect the sample.

The widths are sufficient for ordinary interpolation:

- The difference \(b-a\) lies between −65,535 and 65,535.
- The product magnitude is at most 2,147,385,345, within signed 32-bit range.
- The interpolated result remains between the two signed 16-bit endpoints.

Thus valid interpolation does not itself require a wider product or produce an out-of-range sample.

### Output range selection

Each channel’s computed value passes through range selection:

- At least 32,768: select an externally stored upper replacement value.
- Below −32,768: select an externally stored lower replacement value.
- Otherwise: select the computed value.

The selected value is stored as 16 bits. The replacement values are not supplied; conventional saturation constants must not be assumed.

The static representation reads the upper replacement value for each channel before completing the selection. The lower replacement value is read only on the below-range path. Valid signed-16-bit interpolation does not select either replacement, although the represented upper-value read remains present.

These are representation-level access statements, not guarantees about independently observable machine reads from nonvolatile storage.

### Per-frame output effects

For every generated frame:

1. Compute and select the first-channel value.
2. Write its 16-bit representation.
3. Compute and select the second-channel value.
4. Write its 16-bit representation.
5. Advance the internal output position by four bytes.
6. Read the output count, add one, and store the result.

Phase advancement has a stage-specific position:

- In the historical interval, phase advancement follows the count increment.
- In supplied-input intervals, phase advancement occurs after advancing the output position and before the count increment.

The count is read from its storage for each increment; it is not merely written from a private accumulated total. Aliasing can therefore change subsequent count values.

There is no rollback mechanism. A failure between channel stores can leave a partially written frame.

### Historical interval

While the initial or advanced phase is below 65,536, the endpoints are:

- Starting frame: the historical state samples.
- Ending frame: the first supplied input frame.

The fractional position is the entire phase during this stage. Each output uses the interpolation rule above.

After each frame, the phase advances by the retained increment. Because the phase is unsigned, addition is modulo \(2^{32}\), including when the increment’s signed interpretation is negative.

Once the phase is at least 65,536, the function subtracts 65,536 using unsigned arithmetic. It performs this subtraction even when the historical loop generated no output.

This subtraction changes the phase origin to the intervals within the supplied block. The state’s phase field is not updated at this point.

### Supplied-input intervals

The adjusted phase’s upper 16 bits select an interval index, from 0 through 65,535. A sentinel forces the first selected index to undergo the boundary check and, if usable, an endpoint load.

When the selected index changes, the function compares it against the unsigned 32-bit value of the frame count minus one. For an ordinary positive count, an interval is usable only when its index is strictly less than the count minus one.

For a usable interval, sample reads occur in this order:

1. Indexed frame, first channel.
2. Indexed frame, second channel.
3. Immediately following frame, first channel.
4. Immediately following frame, second channel.

The endpoints remain cached while the integer phase index is unchanged. They are not reread for each generated frame.

Interpolation uses the fractional phase. The frame is written, the phase advances modulo \(2^{32}\), and the count is incremented. A large increment can skip intervals without reading their endpoints.

### Terminal state update

When a newly selected interval fails the boundary check, the function:

1. Reads the final supplied frame’s first-channel sample.
2. Stores that sample at state offset 44.
3. Reads the final supplied frame’s second-channel sample.
4. Stores that sample at state offset 46.
5. Forms a whole-interval distance beyond the final supplied frame.
6. Retains the current phase’s low 16 bits.
7. Adds the whole-interval distance scaled by 65,536 only if the represented signed distance is positive.
8. Stores the resulting phase at state offset 36.
9. Returns the packed original addresses.

The first historical store precedes the second terminal input read. Overlapping storage can therefore affect the second value.

For a positive frame count and representable terminal arithmetic, let \(P\) be the current adjusted phase and \(n\) the frame count. The distance is the selected interval index minus \(n-1\), and the saved phase is:

\[
P-65536(n-1).
\]

This preserves fractional progress and representable whole-interval overshoot. The subtraction of \(n-1\) intervals is distinct from subtracting \(n\) intervals.

The direct terminal construction remains authoritative outside that ordinary case: it preserves the fractional part and adds a scaled distance only when the represented signed distance is positive.

Terminal history always comes from the final supplied frame, even if no output used that frame as an interpolation endpoint. Terminal updates do not increment the output count.

### Integer and termination boundaries

The interval boundary uses unsigned arithmetic for the count-minus-one expression:

- Count one permits no interval between supplied frames.
- Count zero produces a boundary of 4,294,967,295.
- Negative counts are not rejected and do not receive ordinary length semantics.

Terminal input indexing uses signed expressions involving twice the frame count. Large counts can overflow those expressions.

The terminal distance is formed through unsigned arithmetic and assigned to a signed 32-bit quantity. Results outside signed range require target-specific interpretation. Its subsequent multiplication by 65,536 is signed in the supplied representation; a positive distance above 32,767 exceeds signed 32-bit range. The normal saved-phase formula must not be extended across that boundary as though this multiplication were unconditionally defined modulo \(2^{32}\).

The cached interval base also involves conversion of an unsigned shifted index to signed storage. Indices at least 32,768 raise a representation-conversion issue. Behavior beyond the ordinary representable range is **documented_only**.

Termination is not guaranteed. With zero increment in an active interval, the function keeps writing frames and incrementing the count until an external interruption, invalid access, or unsupported arithmetic condition occurs. Other increments can wrap the phase instead of moving monotonically toward completion. There is no capacity-based stop.

## Side effects

- Initial clearing and per-frame updates of the output count.
- Sequential output sample stores.
- Terminal historical-sample replacement.
- Terminal saved-phase replacement.

The increment field is not explicitly written. Intermediate phase values are not stored in the state header.

No allocation, deallocation, or explicit ownership-transfer operation is visible; ownership of the supplied storage is not established.

Input storage is not explicitly written, but overlapping output, count, or state storage can modify it indirectly. Such changes can affect later interval loads and terminal history reads. No synchronization protects these accesses.

## Acceptance examples

These examples are conditional static expectations, not runtime observations. They assume valid, disjoint storage; sufficient output capacity; the represented arithmetic-shift behavior; and representable address and signed arithmetic.

### Historical endpoint with one input frame

Given:

- Initial phase 0.
- Increment 65,536.
- Historical frame \((100,-100)\).
- One input frame \((300,-300)\).

Expected:

- Output exactly \((100,-100)\).
- Output count 1.
- Historical state becomes \((300,-300)\).
- Saved phase becomes 0.
- Result contains the original address components.

The input frame is not emitted as a second frame.

### Halfway interpolation and negative rounding

Given:

- Initial phase 32,768.
- Increment 65,536.
- Historical frame \((0,0)\).
- One input frame \((3,-3)\).

Expected:

- Output exactly \((1,-2)\).
- Output count 1.
- Saved phase 32,768.
- Historical state becomes \((3,-3)\).

The negative result distinguishes arithmetic-shift rounding from truncation toward zero.

### Adjacent fractional positions with identical output

Given the preceding endpoints, increment, and count, compare initial phases 32,768 and 32,769.

Expected:

- Both invocations output \((1,-2)\), because the interpolation factor discards the low fractional bit.
- Their saved phases differ: 32,768 and 32,769 respectively.

Discarding that bit for sample generation does not discard it from phase state.

### Internal input interval

Given:

- Initial phase 65,536.
- Increment 32,768.
- Input frames \((100,200)\) and \((300,600)\).

Expected:

- No historical-interval output.
- Output frames \((100,200)\), then \((200,400)\).
- Output count 2.
- Historical state becomes \((300,600)\).
- Saved phase becomes 0.

### Completion without output

Given initial phase 65,536 and one valid input frame:

- Output count becomes 0.
- No output frame is written.
- Historical samples become the input frame.
- Saved phase becomes 0.

The increment does not affect this result. Initial input and historical sample reads still occur.

### Whole-interval overshoot

Given initial phase 262,144 and two valid input frames:

- No output is generated.
- The final input frame becomes history.
- Saved phase becomes 131,072.

This retains two whole intervals of overshoot.

### Zero increment in an active interval

Given initial phase 0 and increment 0:

- The historical interval does not finish.
- Output writes and count increments repeat.
- No normal terminal state update occurs.

No finite output capacity makes this an indefinitely safe invocation.
