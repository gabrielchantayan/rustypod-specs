# F-e4b8fbd83183

## Purpose

The supplied static representation describes a call-heavy operation that interleaves indirect dependency invocations with byte and 32-bit memory accesses. It scales and extracts bits from supplied or dependency-produced values, writes derived values to calculated addresses, and explicitly invokes F-674e75a953e8 once.

A higher-level purpose—such as constructing an object, decoding a record, or updating a device—is **not established**. Repeated address patterns do not establish an array, object layout, allocator, or ownership protocol.

The representation carries an invalid-instruction warning and ends at an undecoded control-flow boundary. This contract therefore specifies the visible prefix and its limitations, not a proven complete implementation or successful-return behavior.

### Arithmetic interpretation

For describing address and bit calculations below:

- A byte read is unsigned, with range 0 through 255.
- A byte write retains the low eight bits of its value.
- Word reads and writes are 32 bits.
- \(W(x)\) denotes reduction modulo \(2^{32}\).
- Right shifts of unsigned values are logical.
- Address arithmetic is described using 32-bit wrapping bit-vector calculations where applicable.

Several operations are represented using signed integers. Signed overflow and left shifts of negative or overflowing signed values do not establish portable source-language behavior. The wrapping interpretation captures the apparent 32-bit calculation; it is not proof of the original language semantics or the underlying instruction stream.

For compactness, define these **descriptive address expressions**, not inferred data structures:

- Byte-selected destination: an unsigned byte value \(b\) selects address \(b+17\).
- Word destination: a value \(x\) selects address \(W(4x+20)\).
- Expanded word destination: a value \(x\) selects address \(W(16x+20)\).

A byte-selected destination lies between addresses 17 and 272. These are absolute calculated addresses, not offsets into an established caller-owned object.

## Behavior

### Ordering rules

The visible prefix is linear: no explicit conditional branch or loop appears. That does not mean dependency execution is linear or guaranteed to return.

The phases below occur in the listed order, conditional on each preceding access and invocation completing. Intervening indirect invocations remain observable events; they cannot be removed merely because their return values are unused.

A dependency may change memory between accesses. A saved byte selector is reused where indicated; elsewhere a fresh byte read is required. Repeated reads must not automatically be collapsed.

Names introduced below identify values for this contract only. They are not source identifiers or additional parameters.

### 1. Initial calls and first byte update

The first indirect invocation receives the first explicit argument. Its target depends on the incoming control-link value plus a fixed displacement.

Further indirect invocations follow. The fifth invocation in this initial sequence supplies a 32-bit result.

After that result is obtained:

1. One byte is read from the incoming address-bearing state plus one.
2. The incoming byte value is written to the byte-selected destination.
3. The saved call result, shifted left by two, is passed to the next indirect invocation.

Several more indirect invocations occur. Another call-produced value, shifted left by two, is then passed together with the previously saved byte selector to a two-argument indirect invocation.

The selector is not re-read for this two-argument invocation.

### 2. Third-argument transformation and first clear

Let \(T\) be the third explicit argument shifted left by 26, and let \(Z=W(T\times1024)\).

After another indirect invocation, two 32-bit reads from address \(W(T+28)\) supply the two arguments to a subsequent indirect invocation. Both argument expressions refer to the same address. Their relative evaluation order is not established.

Under the 32-bit wrapping interpretation, \(Z=0\): shifting by 26 and subsequently multiplying by \(2^{10}\) discards all original bits. This does **not** make the earlier reads use address 28; those reads use \(T+28\), before the additional scaling.

Following another invocation:

- A byte is read at \(W(Z+1)\).
- Zero is written to its byte-selected destination.
- A subsequent indirect invocation receives zero, an unresolved 32-bit secondary output, and \(Z\).

Under the wrapping interpretation, this byte read is at address 1 and the third argument to that invocation is zero.

After further indirect invocations, the byte at \(W(Z+1)\) is read again. The byte-selected destination receives the low eight bits of the unresolved secondary output shifted right by 22. The fresh selector read may differ from the selector used for the preceding clear.

A later invocation receives a newly obtained result shifted left by two. Another receives \(Z\) shifted left by 26 together with another newly obtained result shifted left by two.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial selector:** If the first selector read returns 5 and the incoming byte is `0xab`, the first direct byte write targets address 22 and stores `0xab`.

2. **Selector range:** A selector of 255 selects address 272. A selector of zero selects address 17, not a null destination.

3. **Third-argument truncation:** Under 32-bit wrapping, a third argument of 1 produces \(T=\texttt{0x04000000}\) and \(Z=0\). The paired word reads use `0x0400001c`; the later selector read uses address 1.

4. **Repeated selector read:** If an intervening dependency changes the byte at address 1, the later byte update uses the new selector. Reusing the earlier selector would not preserve the represented behavior.

5. **Byte truncation:** If \(U=64\), the byte written from \(4U\) is zero. A byte write does not retain the ninth bit.

6. **Split result:** If \(H=3\), the first word write after the split result stores zero at address 32. The low half \(L\) does not select this write’s destination.

7. **Logical extraction:** If the captured word \(D\) is `0x80000000`, the later right-shift-by-12 write stores `0x00080000`, not a sign-extended value.

8. **Interrupted execution:** If a dependency fails after a direct write, acceptance does not require rollback. The visible prefix establishes no rollback mechanism.
