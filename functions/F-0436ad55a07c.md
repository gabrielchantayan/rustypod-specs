# F-0436ad55a07c

## Purpose

F-0436ad55a07c prepares and submits an update using one of four record layouts selected by an earlier dependency. After successful submission, it conditionally refreshes a context field and invokes a final context operation.

The established behavior is an ordered sequence of dependency calls, selected record-field writes, status translations, and context updates. The semantic meanings of the records, selectors, and context fields are not established. Interpreting the operation as a persistent-record update is inferred intent, not a guarantee of persistence or atomicity.

## Interface

The function accepts five arguments and returns a 32-bit status value:

| Argument | Contract |
|---|---|
| Context | Address of a readable and, on some paths, writable context. It is accessed through 16-bit and 32-bit fields described below. |
| Argument A | Opaque 32-bit value passed to dependencies. |
| Argument B | Opaque 32-bit value passed to dependencies. |
| Argument C | Opaque 32-bit value passed to dependencies, including the submission operation. |
| Input record | Address of a record whose required readable extent depends on the selected layout. Some fields are read again after submission. |

Offsets below are byte offsets. Multi-byte values use the execution environment’s native representation unless a dependency performs a conversion. The supplied evidence does not establish byte order or alignment tolerance.

### Context fields

| Offset | Width | Observed use |
|---|---:|---|
| `0x00` | 16 bits | Read-modify-written with mask `0xFF00` when refresh is required. |
| `0x02` | 16 bits | Compared with `0x482B` once, before any dependency call. |
| `0x08` | 32 bits | Unsigned comparison threshold; later possibly replaced. |
| `0x158` | 32 bits | Read and passed as the first submission argument. |
| `0x160` | 32 bits | Read as a multiplication factor in layout `0x0200`. |

The initial comparison at context offset `0x02` produces a saved mode distinction:

- **Matching mode:** the initial value equals `0x482B`.
- **Nonmatching mode:** the initial value differs from `0x482B`.

Later changes to that context field do not change the saved distinction.

### Working storage

The function supplies dependencies with:

- A 520-byte workspace.
- A four-byte auxiliary region.
- A local record region whose first 16-bit field is the layout selector.

The first preparation call receives the workspace but not the local record or auxiliary region. The next dependency receives all three. There is no explicit blanket initialization of these regions in the visible function.

Successful continuation therefore relies on dependency behavior for any bytes subsequently consumed without being explicitly overwritten.

## Behavior

### 1. Preparation

After saving the mode distinction, the function calls F-a0c5d57d1d48 with, in order:

1. Context.
2. Argument A.
3. Argument B.
4. Zero.
5. Workspace address.
6. Zero.

Any nonzero result is returned immediately and unchanged. In particular, `0x20` is **not** translated at this stage.

On success, F-ae00f06fa2b4 is called with:

1. Context.
2. Argument C.
3. Workspace address.
4. Local record address.
5. Auxiliary-region address.

Its result controls fallback and error handling:

- If the result is `0x30` in nonmatching mode, return `0x30`.
- If the result is `0x30` in matching mode, invoke F-f6310772ddb8 with context, Argument A, Argument B, zero, workspace address, local record address, and auxiliary-region address. Use this replacement result.
- Translate the effective result `0x20` to return value `0x30`.
- Return every other nonzero effective result unchanged.
- Continue only for effective result zero.

Thus the fallback is available only for the initial matching mode and only for result `0x30`.

### 2. Select and modify the local record

The first 16-bit local-record field selects a layout. Supported values are `0x0001`, `0x0002`, `0x0100`, and `0x0200`. Any other value causes immediate return of `0x30`, with no submission or final context operation.

The following offsets describe the local submission record as well as the input record. Unless stated otherwise, each scalar assignment transfers 32 bits.

Fields not explicitly overwritten are not necessarily zero, preserved input fields, or padding. They retain whatever contents exist after the preceding dependency calls.

#### Layout `0x0200`

### 3. Submit the local record

For every supported layout, F-43299a5b3b0c is called with:

1. The current 32-bit context field at `0x158`.
2. Workspace address.
3. Argument C.
4. Local record address.
5. Selected byte length.
6. Auxiliary-region address.

Its result is handled as follows:

- `0x20` becomes return value `0x30`.
- Any other nonzero value is returned unchanged.
- Zero permits post-submission processing.

No rollback is visible if submission has side effects and then returns an error.

### 4. Conditionally refresh context, then finalize

After successful submission, the function freshly reads the input’s 32-bit field at `0x10` and compares it, unsigned, with the current context field at `0x08`.

- If input `0x10` is greater, refresh is required.
- Otherwise, nonmatching mode requires no refresh.
- Otherwise, matching mode reads input `0x14` and compares it, unsigned, with context `0x08` again. Refresh is required only if that second input value is greater.

Consequently, input `0x14` is not read during this phase when the first comparison already requires refresh or when the saved mode is nonmatching.

When refresh is required:

1. Read the current 16-bit context field at `0x00`.
2. Write it back ORed with `0xFF00`.
3. Call F-49743e74136c with no arguments.
4. Store its 32-bit result at context `0x08`.

The flag write precedes the dependency call. The dependency is not assumed to preserve context or globals.

Whether refresh occurs or not, the function then calls F-92a758c7556d with the context and returns its result unchanged. A final result of `0x20` is therefore returned as `0x20`, not translated.

## Side effects

The visible function directly modifies only its local storage and, conditionally, context offsets `0x00` and `0x08`. It does not directly write the input record.

Dependencies receive addresses into the context, input record, workspace, auxiliary region, or local record as described above. Their indirect effects are unknown unless separately specified. In particular:

- Input immutability across dependency calls is not guaranteed.
- Workspace contents may change between stages.
- A successful submission does not establish that finalization will succeed.
- A failure return does not establish that no external state changed.
- No explicit allocation, release, or ownership transfer appears in the visible function.

Local storage is invocation-scoped. Whether any dependency retains supplied addresses is unknown; the visible function provides no lifetime extension or release protocol.

There are no visible null checks, bounds checks, alignment checks, or selector-independent validation of the input record. Valid accessible storage for the executed path is a precondition.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Preparation failure:** If F-a0c5d57d1d48 returns `0x20`, the function returns `0x20`. No later dependency is called.

2. **Fallback disabled:** If the initial context field at `0x02` differs from `0x482B` and F-ae00f06fa2b4 returns `0x30`, the function returns `0x30` without calling F-f6310772ddb8.

3. **Fallback result translation:** In matching mode, an initial result `0x30` invokes fallback. If fallback returns `0x20`, the function returns `0x30` without submission.

4. **Unsupported selector:** If preparation succeeds but the selector is `0x0003`, the function returns `0x30` without reading layout-specific input fields or invoking submission.

5. **Partial field replacement:** For layout `0x0200`, if local offset `0x02` initially contains `0xABCD` and the input field is `0x1234`, the resulting local field is `0xAB34`, before any possible later dependency mutation.

6. **Narrowing:** For layout `0x0200`, an input value `0x12345678` at `0x68` produces the 16-bit value `0x5678` at local `0x4A`. No narrowing error is returned by this step.

7. **Equality does not trigger refresh:** In nonmatching mode, if the post-submission input field at `0x10` equals context `0x08`, refresh is skipped regardless of input `0x14`.

8. **Matching-mode second threshold:** In matching mode, if input `0x10` is at most the current threshold but input `0x14` is greater, refresh occurs before finalization.

9. **Finalization status is unmodified:** If submission succeeds and F-92a758c7556d returns `0x20`, the overall result is `0x20`.
