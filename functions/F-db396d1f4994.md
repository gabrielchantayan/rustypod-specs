The operation then reads an unsigned byte at offset 1 from the incoming address-like value. It adds 17 to that byte’s numerical value and stores the incoming byte there. ## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Selector range:** If a selector read yields 255, the corresponding selected-byte store targets numerical address 272. It must not use a full-width pointer loaded from the selector location.

2. **Fresh selectors:** If an early selector is 3, then an intervening dependency changes it to 9, the initial store targets 20 and the later clear targets 26. Reusing the earlier selector is incompatible with the represented order.

3. **Byte truncation:** If a word used for a left-by-2 byte store is 65, 32-bit bit-vector arithmetic gives 260, and the byte stored is 4.

4. **Masked extraction:** For an unsigned word of all one bits, masking to 30 bits and shifting right by 20 yields 1023; its stored low byte is 255.

5. **High-bit displacement:** Under 32-bit bit-vector arithmetic, shifting an odd word left by 31 gives `0x80000000`; shifting an even word gives zero. Treating this expression as a wider unbounded integer changes the represented address.

6. **Repeated offset-116 reads:** If a dependency changes the word at a retained base’s offset 116 between two read-and-store operations, the later offset-1 byte store uses the later word’s low byte.

7. **Shared-word mutation:** Clearing the shared word does not justify replacing its later reads with zero when intervening dependencies may modify it.

8. **Terminal fault:** If numerical address zero is not callable, completion is not required. Earlier byte and halfword stores remain part of the observable prefix; no rollback is represented.
