# F-3981370d380f

## Purpose

F-3981370d380f normalizes a requested selector to one of three values and compares it with a selector stored in a record. If the values differ, it writes the normalized selector, obtains four words from the corresponding entry, invokes an indirect dependency with a local copy of those words, and then calls F-92bea7c30bd6.

The established normal-return values distinguish execution paths:

- **0:** The stored selector already equals the normalized request. No selector write or dependency call occurs.
- **1:** The selectors differed, the update path was taken, and both dependency invocations returned normally.

These values are not established dependency success or failure codes. The routine does not inspect either dependency’s result.

Applying one of three configurations is a plausible interpretation of the operation. That is **inferred intent**, not an established meaning of the selector or payload.

## Interface

### Arguments and result

| Input | Recovered representation | Established role |
|---|---|---|
| Record address | Address carried in a 32-bit integer representation | Base for fixed-offset memory accesses |
| Requested selector | Signed 32-bit integer | Value normalized before comparison and entry selection |
| Third argument | Opaque 32-bit word | No observable influence on a reachable execution path |
| Fourth argument | Opaque 32-bit word | No observable influence on a reachable execution path |

The result is a 32-bit word. Its only established normal-return values are 0 and 1.

The record address is used as an address, not as a numerical identifier. Exact pointer representation and calling convention remain **documented_only**.

The trailing arguments appear in preparation for an alternative payload path, but that path requires a normalized selector other than 0, 1, or 2. Normalization excludes that condition. Every reachable changed-selector path replaces all four payload words with values read from the selected entry.

### Record layout

Offsets are byte offsets from the record address.

| Offset | Width | Role |
|---|---:|---|
| 0x138 | 4 bytes | Current selector |
| 0x13C | 4-byte address-bearing slot | Dispatch-object address |
| 0x140 | 4-byte address-bearing slot | Entry address for selector 0 |
| 0x144 | 4-byte address-bearing slot | Entry address for selector 1 |
| 0x148 | 4-byte address-bearing slot | Entry address for selector 2 |

The current selector is represented as a signed 32-bit integer. Its stored value is not normalized before comparison.

On an update, only the entry-address slot corresponding to the normalized selector is read directly by this routine. The other two entry-address slots are not read directly on that invocation.

### Selected-entry layout

The selected entry supplies a four-word payload:

| Entry-relative offset | Width | Payload position |
|---|---:|---|
| 0x80 | 4 bytes | First |
| 0x84 | 4 bytes | Second |
| 0x88 | 4 bytes | Third |
| 0x8C | 4 bytes | Fourth |

The first two words are represented as signed 32-bit integers; the last two are opaque 32-bit words. No arithmetic, range check, or semantic conversion is applied to their values. The payload passed to the indirect dependency is a local 16-byte copy in that order.

### Path-specific preconditions

**For either normal-return path**, the current-selector field at record offset 0x138 must be readable, and its address must resolve to the intended storage. Normalization itself requires no entry or dispatch access.

**For the unchanged-selector path returning 0**, no additional memory or dependency preconditions are established. In particular:

- The selector need not be writable.
- Entry-address slots and entry payloads need not be readable.
- The dispatch-object field, object, table, and target need not be valid.
- Neither dependency needs to be callable or capable of returning normally.

Those unused fields may contain invalid addresses without preventing the visible equality path from returning 0. This does not remove the requirement that the selector read itself be valid.

**Only for the changed-selector path returning 1**, the following additional conditions are required:

- The current-selector field must be writable.
- The selected entry-address slot must be readable.
- The selected entry’s four payload words must be readable.
- The dispatch-object field and the object’s dispatch-table field must be readable.
- The dispatch-table target at byte offset 0x68 must be readable and callable with the established arguments.
- The indirect dependency must return normally.
- F-92bea7c30bd6 must be callable with the original record address and return normally.

Any requirements imposed by the dependencies themselves remain **documented_only**. Their implementations are unavailable.

No explicit null, alignment, bounds, lifetime, or ownership validation is visible. Address calculations use fixed byte offsets; the source does not establish portable overflow or address-wrap semantics. Valid address formation is therefore a condition of the relevant memory access, not a checked property.

## Behavior

### Request normalization

The requested selector is interpreted as a signed 32-bit integer.

| Requested value | Normalized selector |
|---|---:|
| Less than 0 | 2 |
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| Greater than 2 | 0 |

This operation is neither modulo reduction nor nearest-endpoint clamping. Out-of-range requests do not produce an explicit error.

Normalization uses comparisons and replacement values, not arithmetic on the request. The minimum signed 32-bit value, −2,147,483,648, maps to 2 without negation. The maximum, 2,147,483,647, maps to 0.

### Equality path

After normalization, the routine reads the four-byte current selector at record offset 0x138.

If the stored value equals the normalized selector, the routine returns 0 immediately. It does not:

- Write the selector.
- Read any entry-address slot or entry payload.
- Read the dispatch-object field or resolve a dispatch target.
- Invoke either dependency.

Consequently, an invalid unused entry or dispatch address does not itself obstruct this return. The visible routine never accesses it.

The comparison is against the normalized request. A negative request therefore produces no change when the stored selector is 2. A request greater than 2 produces no change when the stored selector is 0.

### Changed-selector path

If the stored selector differs from the normalized request, the observable sequence is:

1. The normalized selector is written as a four-byte value at record offset 0x138.
2. The corresponding entry address is read from record offset 0x140, 0x144, or 0x148.
3. The selected entry’s four payload words are read at offsets 0x80, 0x84, 0x88, and 0x8C, in that order, and copied into local payload storage.
4. The indirect dependency is resolved through the dispatch object and invoked with the object, the local payload address, and zero.
5. After that invocation returns normally, F-92bea7c30bd6 is called with the original record address.
6. After F-92bea7c30bd6 returns normally, the routine returns 1.

The selector write precedes entry-address acquisition, payload acquisition, and both calls. No rollback is visible if a later operation faults, exits nonlocally, or does not return.

A stored selector outside 0, 1, and 2 cannot equal a normalized request. It therefore takes the changed-selector path and is overwritten. The routine does not separately diagnose an invalid stored selector.

### Indirect dispatch

Record offset 0x13C supplies the dispatch-object address. The first address-bearing word of that object supplies the dispatch-table address. The callable target is obtained from table byte offset 0x68.

The indirect call receives:

| Argument position | Value |
|---|---|
| First | Dispatch-object address |
| Second | Address of the local four-word payload |
| Third | Zero |

All four payload reads precede the invocation.

The supplied representation references the dispatch-object field both for target resolution and for the object argument. It does not establish the relative evaluation order of those accesses or guarantee that one stable snapshot supplies both uses. The contract therefore does not require a particular ordering between them.

The indirect call’s result is ignored. Its normal return, rather than any returned status value, allows execution to continue to F-92bea7c30bd6.

## Side effects

### Direct memory effects

On the changed-selector path, the routine explicitly writes the normalized selector to record offset 0x138. This is its only explicit write to externally supplied storage.

It also writes the local payload copy. It does not explicitly copy changes from that local payload back into the selected entry.

On the equality path, the routine performs no explicit writes and invokes no dependencies.

No allocation, deallocation, resource acquisition, resource release, or ownership transfer is visible in the routine itself.

### Dependency effects and final state

Neither dependency’s implementation is supplied. Either may modify accessible memory or global state, subject to its unknown contract. No preservation guarantee is established for:

- The record or its selector.
- The selected entry.
- The dispatch object or dispatch table.
- The local payload contents.
- Any global state.
- The lifetime of objects passed to, or reachable by, a dependency.

A return value of 1 consequently does not guarantee that the final stored selector still equals the normalized request. It establishes that the visible changed-selector path reached its normal return.

After the indirect dependency returns, the routine passes the original record address to F-92bea7c30bd6 without visible revalidation. It does not establish that the first dependency preserved that record’s validity.

### Payload ownership and lifetime

The indirect dependency receives the address of a local copy, not the address of the selected entry’s payload fields. Modifying that copy does not, by itself, constitute a direct write back to the entry.

No ownership transfer or extended lifetime is established. The local payload is available during the indirect invocation; its address is not established to remain usable after F-3981370d380f returns. Whether a dependency retains the address is unknown, not an authorized lifetime extension.

### Aliasing and concurrency

The selector write occurs before the entry-address and payload reads. If accessed storage aliases the selector field, later reads may observe the newly written value. The routine provides no alias protection.

No synchronization or coherent-snapshot mechanism is visible. Concurrent mutation, including mutation between dispatch-object reads, has no established contract here. The ordered accesses described above do not imply atomicity.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Update examples assume valid accessed storage, stable relevant values during reads, and dependencies that return normally unless the example states otherwise. Equality examples require only the memory actually read on that path.

### Unchanged selector despite invalid unused addresses

Given a readable stored selector of 2 and a request of −1:

- The request normalizes to 2.
- The routine returns 0.
- No selector write occurs.
- No entry or dispatch field is read.
- Neither dependency is invoked.

This result does not require valid entry addresses, a valid dispatch object, or callable dependencies. The selector field may also be nonwritable, provided its read is valid.

The same conclusions apply to a request of −2,147,483,648.

### High request with no change

Given a readable stored selector of 0 and a request of 3, the normalized request is 0 and the routine returns 0 without further record accesses.

A request of 2,147,483,647 behaves identically. Invalid unused entry and dispatch addresses do not affect this path.

### Selecting entry 1

Given a stored selector of 0 and a request of 1:

- The selector is written to 1 before the selected entry address is read.
- Record offset 0x144 supplies the entry address.
- Entry offsets 0x80, 0x84, 0x88, and 0x8C supply the four payload words.
- The indirect dependency receives a local copy of those words and a zero third argument.
- F-92bea7c30bd6 runs afterward with the original record address.
- Normal completion returns 1.

The entry-address slots at offsets 0x140 and 0x148 need not be valid for the routine’s direct accesses on this path.

### Selecting entry 2 from a negative request

Given a stored selector of 1 and any negative signed 32-bit request, the routine writes 2 and selects the entry address at offset 0x148. The dependency order is indirect target first, F-92bea7c30bd6 second.

Negativity alone is not an error condition.

### Replacing an out-of-range stored value

Given a stored selector of 7 and a request of 0, the comparison fails. The routine writes 0, selects the entry at record offset 0x140, and returns 1 if the remaining accesses and both calls complete normally.

### Changing trailing arguments

For invocations with otherwise identical inputs, stable accessed storage, and identical dependency behavior, changing only the third and fourth arguments does not alter the selected payload, dependency arguments, or return path.

### Dependency mutation

If the indirect dependency changes the stored selector and returns normally, the routine does not restore the normalized value. It proceeds to F-92bea7c30bd6. If that call also returns normally, the result is 1 regardless of the selector value left by the dependencies.

### Invalid entry on an update

If the selectors differ but the selected entry’s payload cannot be read, the selector write has already occurred before the attempted payload access. No defined error return or rollback is established.

This differs from the equality path, where the same invalid unused entry would not be accessed.
