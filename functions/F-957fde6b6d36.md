# F-957fde6b6d36

## Purpose

F-957fde6b6d36 subtracts a two-word quantity from a two-word value held in an indirectly referenced state object. A dependency determines whether the quantity is first rounded upward to a multiple of 16.

The visible arithmetic supports the following contract under the 32-bit word model:

- If the dependency leaves a local control word equal to zero, subtract the supplied quantity unchanged.
- If the dependency leaves that word nonzero, round the supplied quantity upward to the next multiple of 16, including an already aligned value itself, and then subtract it.
- Both the rounding and the subtraction wrap modulo \(2^{64}\).
- Store the result as a low 32-bit word followed by a high 32-bit word, with the low-word store occurring first.

This is an arithmetic and memory-update description. The visible evidence does not establish what the state represents. Interpretations such as an allocation balance, capacity counter, or accounting total are inferred intent, not part of the contract.

## Behavior

### 1. Obtain the adjustment control

Before reading the outer object, the function initializes a local 32-bit control word to zero.

It then calls F-9a5273e4fe78 with:

1. The integer value zero.
2. The address of that local control word.

Any return value from the dependency is ignored. The function subsequently reads the control word and tests whether it is zero.

The test is a zero/nonzero distinction. Positive and negative nonzero bit patterns select the same adjustment path.

The local initialization means that if the dependency returns normally without changing that word, the unadjusted path is selected. This does not establish that leaving it unchanged is a supported behavior of the dependency; it only describes the caller’s visible behavior in that case.

### 2. Determine the quantity to subtract

If the control word is zero, the effective quantity is exactly \(A\).

If the control word is nonzero, the effective quantity is

\[
A_{\mathrm{effective}}
=
\left(16\left\lceil\frac{A}{16}\right\rceil\right)
\bmod 2^{64}.
\]

Equivalently,

\[
A_{\mathrm{effective}}
=
\left(
A + ((16-(A\bmod 16))\bmod 16)
\right)
\bmod 2^{64}.
\]

This equivalence follows from the visible 32-bit arithmetic; it is not an assumption about the dependency’s purpose.

Important boundaries are:

- Zero remains zero.
- An already aligned quantity remains unchanged.
- An unaligned quantity increases by between 1 and 15.
- Rounding may carry from the low word into the high word.
- Rounding may wrap the entire two-word quantity to zero.

More specifically, the effective low word is the supplied low word rounded upward to a multiple of 16, modulo \(2^{32}\). The effective high word increases by one, modulo \(2^{32}\), exactly when the supplied low word lies from `0xFFFFFFF1` through `0xFFFFFFFF`, inclusive.

A supplied low word of zero does **not** decrement or increment the effective high word. Although the visible calculation uses an intermediate subtraction with a borrow at that boundary, the subsequent high-word adjustments cancel it.

### 3. Resolve the target after the dependency call

Only after the dependency returns and the optional adjustment is completed does the function read the indirect state address from the outer object at offset `0xF00`.

Consequences:

- The dependency runs before this address is read.
- If the dependency changes the address field through some independently available reference, the later read observes the field as it exists after that call.
- The function does not preserve a pre-call copy of that field.
- Once loaded, the indirect address is reused for both target-word accesses; the outer field is not reread between them.

The dependency’s ability to make such changes is unknown. The ordering is established; any particular dependency side effect is not.

### 4. Subtract and write the two-word result

Let:

- \(S_L\) be the low word read from the indirect state at offset `0xC20`;
- \(S_H\) be the high word read from offset `0xC24`;
- \(E_L\) and \(E_H\) be the low and high words of the effective quantity.

The low-word result is

\[
R_L = (S_L-E_L)\bmod 2^{32}.
\]

The borrow is one exactly when the unsigned comparison \(S_L<E_L\) is true; otherwise it is zero.

The high-word result is

\[
R_H=(S_H-E_H-\mathrm{borrow})\bmod 2^{32}.
\]

For stable memory, this is equivalent to

\[
R=(S-A_{\mathrm{effective}})\bmod 2^{64},
\qquad
S=S_L+2^{32}S_H.
\]

The visible source-level access order is:

1. Read the indirect state address.
2. Read the stored low word.
3. Write the new low word.
4. Read the stored high word.
5. Write the new high word.

In particular, the high-word read occurs after the low-word write. The function does not first obtain a two-word snapshot and then replace it.

The borrow is based on the saved original low-word value and the effective low-word subtrahend, not on a second read of the low word after its replacement.

### 5. Complete without arithmetic error reporting

Underflow is represented by modular wraparound. It is not rejected, saturated, or reported.

Likewise, upward rounding that overflows the full 64-bit quantity wraps to zero rather than producing an error.

The function contains no explicit recovery path for an invalid address or a failure within the dependency. The consequences of such failures belong to the dependency and execution environment, not to a visible error-handling contract here.

The function also has no visible protection against another actor changing either word during execution. Therefore:

- The combined arithmetic formula assumes stable target memory.
- If the high word changes after the low-word operation but before its read, the high-word calculation uses the value obtained by that later read.
