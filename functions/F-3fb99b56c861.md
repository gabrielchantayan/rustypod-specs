# F-3fb99b56c861

## Purpose

F-3fb99b56c861 selects a marker and delegates an entry update according to a format selector in a caller-provided context. It sets a context field to one, initializes a four-byte scratch buffer, and either modifies selected buffer bits directly or passes the buffer to a preparation helper before an access call.

**Established behavior:** marker selection, ordered context accesses, fixed-width arithmetic, local byte transformations, dependency calls, conditional early termination, and result normalization.

**Inferred intent:** the paths appear to support packed 12-bit entries, a two-byte representation, and a representation using a 28-bit marker. These interpretations do not establish the dependencies’ actual storage layout, access semantics, or persistence guarantees.

## Behavior

### Entry accesses and path selection

The visible order is:

1. Read the default 32-bit marker from a global location.
2. Read the context’s 16-bit selector at offset `0x6c`.
3. If that read equals 8, replace the selected marker with `0x0fffffff`.
4. Write the 32-bit value 1 at context offset `0x88`.
5. Initialize the local four-byte scratch buffer from the fourth argument.
6. Read the selector again. A value of 3 selects the packed path.
7. If that read is not 3, read the selector once more. A value of 8 selects the four-byte-helper path; every other value selects the two-byte-helper path.

The default-marker read occurs even if the first selector read equals 8 and supersedes its value.

Marker selection and path selection use separate selector reads. There is no explicit snapshot or synchronization. If the selector changes between reads, the observed sequence determines the marker and path independently. For example, the four-byte-helper path can receive the default marker if the first selector read was not 8 but the later path-selection read is 8.

Once selected, the marker remains local. The function does not reload the default-marker global following a dependency call.

### Packed path

The packed path computes:

- Position as the low 32 bits of three times the entry index, then shifted right by two.
- Remainder as the entry index masked with 3.

Thus Position is the floor of `((3 × index) modulo 2^32) / 4`, and Remainder is in the range 0–3. Overflow reduction precedes division.

First, call F-6801f4e9392e with the original context, Position, scratch-buffer address, and operation selector 0.

If this call returns zero, return 0 immediately. No packed modification or later dependency call occurs. The context field has already been written.

After a nonzero result, use the applicable transformation below. Preserved bits and bytes refer to the buffer’s state after the latest dependency call, not necessarily its initial contents.

#### Remainder 0

Prepare the buffer as follows:

- Byte 0 becomes marker bits 0–7.
- Byte 1 preserves its upper nibble and receives marker bits 8–11 in its lower nibble.
- Bytes 2 and 3 remain unchanged by this local transformation.

Call F-6801f4e9392e with the context, Position, buffer address, and operation selector 1. Return 0 for a zero result and 1 for a nonzero result.

#### Remainder 1

Next position is `(Position + 1) modulo 65536`.

Before the first update call:

- Preserve byte 0.
- Preserve byte 1’s lower nibble.
- Replace byte 1’s upper nibble with marker bits 0–3.
- Leave bytes 2 and 3 unchanged locally.

Call F-6801f4e9392e at Position with operation selector 1. If it returns zero, return 0 without accessing Next position.

Otherwise, call F-6801f4e9392e at Next position with operation selector 0, using the same buffer address. If it returns zero, return 0 without the final update.

After that call succeeds, replace byte 0 with marker bits 4–11. Preserve bytes 1–3 as left by that latest dependency call.

Finally, call F-6801f4e9392e at Next position with operation selector 1. Normalize its result to 0 or 1.

The marker bits used for the final replacement are derived from the locally retained marker; they do not reflect later changes to the default-marker global.

#### Remainder 2

Next position has the same 16-bit reduction.

Before the first update call:

- Preserve byte 0.
- Replace byte 1 with marker bits 0–7.
- Leave bytes 2 and 3 unchanged locally.

Call F-6801f4e9392e at Position with operation selector 1. A zero result returns 0 immediately.

On success, call the same dependency at Next position with operation selector 0. A zero result returns 0 without the final update.

- Replace byte 0’s lower nibble with marker bits 8–11.

## Side effects

### Direct effects

The function directly reads the default-marker global, reads the context selector multiple times, writes 1 to context offset `0x88`, and initializes and modifies local scratch storage.

The context write precedes every dependency invocation. No direct restoration of the previous field value is visible. A dependency may subsequently change the field, so its value at function return is not guaranteed solely by the direct write.

No dynamic allocation, deallocation, or explicit ownership-transfer operation is visible in this function. The scratch buffer is local storage whose address is supplied to dependencies.

Local storage does not establish a complete dependency ownership contract. Whether a dependency retains an address, releases another resource, or modifies unrelated memory remains unknown. No post-return validity of the scratch address is established.

### Dependency effects and partial progress

Dependency side effects may include changes to the buffer, context, globals, or an external resource. The supplied body does not bound those effects or establish preservation guarantees.

A failed checked call does not cause explicit rollback. For packed remainders 1 and 2, the operation-selector-1 call at Position can succeed before the subsequent call at Next position fails. Earlier effects remain uncompensated by this wrapper.

Accordingly:

- Result 0 does not establish absence of state changes.
- Result 1 establishes only the nonzero outcomes of checked calls, not successful outcomes for unchecked helpers.
- Neither result establishes atomicity, durability, or underlying resource correctness.
- Ignoring a helper’s return value does not mean the helper has no effects. Its buffer or other state changes can influence the later checked call.
