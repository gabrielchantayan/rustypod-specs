# F-e3c9745f1d36

## Purpose

F-e3c9745f1d36 replaces the first 32-bit word of a supplied memory region with a value read from global storage. It then tests the region’s second 32-bit word as a pointer. If that test is nonnull, it evaluates the second word again, uses the resulting address to read a signed 32-bit integer, adds 4 to that integer, converts the result to an address, and reads and invokes a callable entry there.

On normal completion, the function returns its original input pointer.

The replacement precedes the null test and all dispatch-path accesses. The indirect callee therefore executes after the replacement, but may change or invalidate the affected storage. The function does not restore the replacement after that call.

The region’s conceptual role is not established. An object-header update followed by virtual dispatch is a possible interpretation, not a behavioral guarantee.

## Interface

### Input and directly accessed layout

The function accepts one pointer. Its directly accessed region contains consecutive four-byte words:

| Byte offset | Width | Access and role |
|---|---:|---|
| 0 | 32 bits | Written with a value obtained from global storage |
| 4 | 32 bits | Read for a pointer-null test; evaluated again on the selected dispatch path |

The prior contents at offset 0 are not explicitly read. No meaningful initial value is required there, provided the write itself is permitted.

For ordinary successful execution, the input must support the first-word write and the subsequent second-word access. No input-pointer null check, bounds check, or alignment check is visible. A null input is not a supported no-operation case.

A second-word value that compares equal to a null pointer selects the no-call path. A nonnull test result selects further evaluation and indirect dispatch; it does not establish that any subsequent address is valid.

### Output

If execution reaches the return, the result is the original input pointer value. It is not:

- The value copied from global storage.
- A pointer obtained from the second word.
- The indirect callee’s return value.
- A success or failure status.

Returning that pointer does not guarantee that its referent remains allocated, accessible, or unchanged.

### Widths and representations

The directly accessed input words and the global replacement value are 32 bits wide. The referenced record’s first word is read as a **signed 32-bit integer**.

The dispatch-address computation is integer arithmetic before address conversion:

1. Read the referenced signed 32-bit integer.
2. Add the integer value 4.
3. Convert the integer result to an address.
4. Read a callable pointer through that address.

The addition is not pointer arithmetic. In an ordinary, representable address case, it selects a location four bytes beyond the address represented by the integer. It does not advance four table entries.

The callable entry is accessed as a function pointer. Its exact representation and storage width are not independently specified by an explicit-width scalar type in the supplied expression. The four-byte displacement alone must not be used to infer the pointer width of a replacement implementation’s host environment.

Byte order, integer-to-pointer conversion details, alignment requirements, and behavior outside valid address and arithmetic ranges remain unresolved.

## Behavior

### Established source-level sequence

The visible order is:

1. Read the 32-bit replacement value from global storage.
2. Write that value to input offset 0.
3. Access the 32-bit word at input offset 4 and compare its pointer interpretation against null.
4. If the comparison is null, skip the dispatch path.
5. If the comparison is nonnull, evaluate the word at input offset 4 again to obtain the referenced-record address.
6. Read the first word at that address as a signed 32-bit integer.
7. Perform integer addition of 4 to that signed value.
8. Convert the result to an address and read a callable entry there.
9. Invoke the selected entry.
10. If all selected operations complete normally, return the original input pointer.

The two evaluations of input offset 4 are distinct **source-level accesses**. This is not evidence of two measured machine loads. No instruction trace or generated machine-code analysis is supplied. The contract must neither collapse the expressions into a guaranteed cached value nor promise that two physical loads occur.

### First-word replacement

The first-word update is unconditional. The function does not first inspect the second word or validate the dispatch chain.

The update replaces all 32 bits. There is no visible preservation or combination of the destination’s prior value. No helper is called between the global read and this write.

The global value is sampled before the indirect call. If the callee later changes that global storage, the function does not visibly reread it or refresh the input’s first word.

The supplied representation does not establish that global storage and caller-supplied storage are disjoint. Any reasoning that requires nonaliasing must state that condition. In particular, the later second-word test observes storage after the first-word replacement, not a guaranteed entry-time snapshot.

### Null test and second-word re-evaluation

If the first evaluation compares equal to null, there is no dispatch-path re-evaluation, no referenced-record read, and no indirect call. The global read and first-word write have already occurred.

If that evaluation compares nonnull, the dispatch expression evaluates the second input word again. The record address comes from this second evaluation, rather than from a specified saved copy of the test value.

There is no additional null check after the second evaluation. Consequently, the visible guard does not establish that the address used by the subsequent record read is nonnull if the two evaluations can observe different values.

This distinction does not establish that concurrent modification is safe, supported, or observable on any particular compilation. It describes the supplied expression structure without inventing synchronization or machine-load behavior.

### Dispatch-address calculation

The dispatch lookup has three memory stages:

| Stage | Established access |
|---|---|
| Input region | Re-evaluate the second 32-bit word to obtain the record address |
| Referenced record | Read its first word as a signed 32-bit integer |
| Callable-entry storage | Read a function pointer at the address obtained after signed integer addition of 4 and address conversion |

The signed interpretation matters. A record word with its high bit set is not simply specified as an unsigned table address. Nor is the calculation specified as unsigned modular addition.

For a signed 32-bit value, adding 4 remains within the signed range only when the value is at most 2,147,483,643. Larger positive values exceed that range. The supplied evidence does not resolve the consequences of such overflow. It does not authorize guaranteed wraparound, saturation, or a particular failure.

Negative signed values do not themselves cause overflow when 4 is added. Whether the resulting integer converts to a meaningful address is a separate, unresolved issue. Arithmetic representability alone does not validate the dispatch location.

### Indirect invocation

The call expression supplies no explicit arguments. This does not prove that no useful context reaches the callee: register contents, an implicit receiver convention, and the precise calling convention are not established. In particular, neither the input pointer nor the second word may be specified as an explicitly passed argument.

The function does not visibly use the target’s return value. After a normal return from the target, it performs no further visible data-memory update before returning the original input pointer.
