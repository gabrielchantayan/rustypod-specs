# F-81c45e7142cf

## Purpose

The structure and repair rules are consistent with red-black-tree insertion. That is inferred intent, not a guarantee about the dependencies or the validity of the supplied structure. The established contract is the observable access and call behavior below.

The function does not visibly search for an insertion position, validate ordering, or reject duplicates. The caller supplies the prospective parent and a hint affecting insertion-side selection.

## Behavior

### 1. Obtain a node, copy payload, and increment the count

F-55371306f405 is called once with the container address. Its returned address is retained as the value eventually written to the output slot, regardless of subsequent movement of the repair-current position.

The payload-copy guard tests whether the address obtained by adding `0x10` to the returned address is nonzero. It does not test the returned address itself for null.

When that derived address is nonzero, the function:

1. Reads the first 32-bit word at the payload address.
2. Stores it at obtained-node offset `+0x10`.
3. Reads the second 32-bit word at payload offset `+0x04`.
4. Stores it at obtained-node offset `+0x14`.

These are ordered copies, not an established snapshot of both source words. The first destination write precedes the second source read.

When the derived address is zero, both payload copies are skipped, but count and structural processing continue. The address-arithmetic conditions under which this can occur are not established. It is not a supported allocation-failure path.

Next, the function reads the 32-bit count-like field at container offset `+0x14`, adds one, and writes the result back. This precedes insertion-side selection and any comparison call. Although the field is 32 bits wide, defined modulo arithmetic must not be assumed: the supplied representation treats this addition as signed, and its overflow semantics are unresolved.

### 2. Select the insertion side and auxiliary call operands

The function reads the header address from container offset `+0x10`.

It selects the left-link path without comparison if either:

- The supplied parent equals that header address; or
- The insertion hint is nonzero.

On this path, two auxiliary operands retain the original insertion hint and supplied parent address.

Otherwise, both auxiliary operands become zero, and F-bcefa5957e76 is called with these address operands in order:

1. Container address plus `0x19`.
2. Original payload address.
3. Supplied parent address plus `0x10`.

A nonzero result selects the left-link path. A zero result selects the right-link path.

No key type, ordering relation, or comparator semantics beyond this zero/nonzero decision is established. In particular, the comparator receives the original payload address, not the address of the copied payload. The earlier copy and the comparison can therefore observe different contents if intervening writes or dependency effects change the source.

### 3. Install the initial links

On the **left-link path**, the first structural store writes the obtained node address to supplied-parent offset `+0x08`.

The function then reloads the header address.

- If this header differs from the supplied parent, it reads the header’s `+0x08` link and replaces it with the obtained node address only when its current value equals the supplied parent.
- If this header equals the supplied parent, it writes the obtained node address to that header’s `+0x04` root field. It then reloads the header address again and writes the obtained node address to that header’s `+0x0c` field unconditionally.

Thus, with a stable header and the parent equal to that header, the initial parent-left store supplies the header’s left-boundary link, followed by the root and right-boundary stores.

On the **right-link path**, the first structural store writes the obtained node address to supplied-parent offset `+0x0c`. The function then reloads the header address and reads its `+0x0c` link. That header link is replaced only when its current value equals the supplied parent.

After either path, supplied parent is written to obtained-node offset `+0x04`.

The function does not visibly initialize the obtained node’s child links or initial color byte. Any required initialization must already exist or be performed by a dependency. It must not be presumed from the allocation-like appearance of F-55371306f405.

### 4. Repair ancestors

The repair-current node initially equals the obtained node.

At each loop condition, the function reloads the header and reads its `+0x04` root link. If that root equals the repair-current node, repair exits without inspecting the current node’s parent color.

Otherwise, it reads the current node’s parent address and that parent’s color byte. A nonzero parent color exits repair. A zero parent color leads to inspection of the parent’s parent, treated as the grandparent.

#### Parent equals the grandparent’s left-child link

The grandparent’s right-child link supplies the uncle.

If the uncle is nonnull and its color byte is zero:

1. The selected parent receives color `1`.
2. The selected uncle receives color `1`.
3. The grandparent reached by rereading the current node’s parent chain receives color `0`.
4. The repair-current node advances to the grandparent obtained through another parent-chain read.
5. The loop condition is evaluated again.

The parent and uncle for the first two writes are already selected addresses. The later ancestor operations reread links; they are not guaranteed to use an unchanged ancestor snapshot under aliasing.

If the uncle is null or its color is nonzero:

- When the current node equals the selected parent’s right-child link, F-e6761820c62c is called with the container address and selected parent address. After the call returns, repair-current becomes that previously selected parent address.
- The parent reached from the resulting repair-current node receives color `1`.
- The grandparent reached through a fresh parent-chain read receives color `0`.
- F-81b2e9c93c15 is called with the container address and a grandparent address obtained through another parent-chain read.

The dependency may change links before those subsequent reads. Its effects are not restricted by this function’s visible body.
