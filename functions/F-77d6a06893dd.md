# F-77d6a06893dd

## Purpose

F-77d6a06893dd propagates a zero-versus-nonzero mode request through several dependencies, conditionally changes a byte in an associated object, and, when that byte changes, performs additional global-parameter processing and context bookkeeping.

The operation is not transactional. Earlier dependency calls and the associated-object byte write remain observable even when later processing returns early or records an error. Repeating a request can suppress the associated-object transition without suppressing the initial dependency calls.

This contract describes the supplied static evidence. Dependency implementations, complete calling conventions, global definitions, and runtime observations are unavailable. Unresolved behavior is marked **documented_only** rather than filled in by assumption.

## Interface

### Inputs and result

The visible interface has two 32-bit inputs:

| Input | Interpretation |
|---|---|
| Owner address | Address used as the base of an object containing several 32-bit fields. |
| Requested mode | Zero selects one branch; every nonzero value selects the other. |

There is no explicit result value. Observable results consist of dependency invocations, memory writes, and any effects produced by those dependencies.

The owner address is represented as a 32-bit integer in the supplied evidence. Treating it as a valid object address is a caller precondition, not a check performed by this function.

### Owner layout

Offsets are byte offsets from the owner address.

| Offset | Width | Established use |
|---|---:|---|
| `0x54` | 32 bits | Read and passed to the first F-2d9eb483b9a4 invocation in the zero-mode branch. |
| `0x94` | 32 bits | Tested for zero after the first branch-specific dependency call. A nonzero value causes another call. |
| `0xD4` | 32 bits | Tested for zero after the preceding calls. A nonzero value causes another call. |
| `0xD8` | 32 bits | Read after the initial calls and treated as an associated-object address. Zero causes an early return. |

The first branch-specific call is unconditional. The fields at `0x94` and `0xD4` are guards, but the visible evidence does not establish that their values are passed as arguments to the calls they enable.

### Associated-object layout

The object reached through owner offset `0xD8` has a one-byte state field at offset `0x0B`.

- Zero-mode processing accepts any nonzero byte as eligible for a transition to zero.
- Nonzero-mode processing accepts only a zero byte as eligible for a transition to one.
- Existing nonzero values are not normalized to one by a nonzero-mode request.

### Context and derived-object layouts

F-7fba0909c452 returns either zero or an address used as a context pointer. If nonzero, its first 32-bit word is an error slot.

For one target value, F-1411dcc31aed is called with that context pointer. Its result is treated as an address with writable one-byte fields at offsets `0x105` and `0x107`.

The function visibly checks neither the validity nor the nullness of this derived address.

### Preconditions

Defined execution requires valid, appropriately accessible memory for each access actually reached. In particular:

- The owner must remain usable through the initial dependency calls.
- A nonzero associated-object address must permit a byte read and, when a transition occurs, a byte write at `0x0B`.
- A nonzero context result must permit the error-slot accesses reached on its path.
- The derived address must permit the applicable byte write on successful bookkeeping paths.

Alignment requirements, pointer provenance rules, and invalid-address behavior are **documented_only**.

## Behavior

### 1. Initial mode propagation

For a zero requested mode, the function invokes F-2d9eb483b9a4 once, explicitly passing the 32-bit owner field at `0x54`.

It then reads the owner field at `0x94`. If that field is nonzero, it invokes F-2d9eb483b9a4 again. After that invocation returns, or immediately if the field was zero, it reads the owner field at `0xD4`. If that field is nonzero, it invokes F-2d9eb483b9a4 once more.

For a nonzero requested mode, the same guard and ordering structure applies, but the invoked dependency is F-dbbd0e22ccce. No arguments are explicitly established for its invocations in the supplied evidence.

The arguments to the second and third F-2d9eb483b9a4 calls are also unresolved. Missing displayed arguments are not evidence that those calls take no arguments.

These calls precede both the associated-object null check and the state-byte check. Consequently, an absent associated object or an already-satisfied state does not eliminate the initial calls.

The owner fields are read when their respective decisions are reached, rather than being collected into an entry snapshot. A preceding dependency can therefore affect a later field read. This contract does not assume that dependencies preserve owner memory or globals.

### 2. Associated-object transition

After the initial calls, the function reads the 32-bit address at owner offset `0xD8`.

If that address is zero, the function returns immediately.

Otherwise, it reads the byte at associated-object offset `0x0B`:

| Requested mode | Existing byte | Result |
|---|---|---|
| Zero | Zero | Return without the transition-stage calls. |
| Zero | Any nonzero byte | Write zero and continue. |
| Nonzero | Any nonzero byte | Return without the transition-stage calls. |
| Nonzero | Zero | Write one and continue. |

The state write occurs before F-8a2b303ae860 is invoked. There is no visible rollback of this write.

Only the associated-object address read at this stage is used for the byte check and write. There is no later reload of owner offset `0xD8` in the visible path.

### 3. Global-parameter operation

After changing the state byte, the function invokes F-8a2b303ae860. It then obtains branch-specific values from globals and invokes F-9db809c408f4 with three 32-bit arguments.

For clarity, the global roles below are descriptive labels, not assertions about their external meaning.

| Branch | First argument | Second argument | Third argument | Retained bookkeeping value |
|---|---|---|---|---|
| Zero mode | Zero-mode target global | Zero-mode argument global | `0x2600` | `0x2600` |
| Nonzero mode | Nonzero-mode target global | Nonzero-mode value global plus `0x200` | Nonzero-mode value global | Captured nonzero-mode value |

A branch-specific target value is also retained for the later comparison with `0x0DE1`.

The global reads occur after F-8a2b303ae860 returns. Thus, its effects on those globals can affect both the arguments and the retained values.

In the nonzero branch, the target and bookkeeping value are captured before F-9db809c408f4 is called; the call arguments are formed from global reads as shown above. In the zero branch, the target is captured before that call and the retained bookkeeping value is the constant `0x2600`.

Subsequent dependency effects on globals do not retroactively change those retained local values. By contrast, globals read later during context bookkeeping are not entry-time snapshots.

The addition of `0x200` is a 32-bit operation in the supplied representation, with no visible overflow check. Whether overflow is defined as wrapping by the original implementation is **documented_only**. A contract requiring defined signed arithmetic must restrict this input value to a nonoverflowing range.

### 4. Context lookup and early exit

After F-9db809c408f4 returns, the function invokes F-7fba0909c452.

If its result is zero, the function returns. This does not undo the state-byte transition or preceding dependency effects. No error-slot access occurs on this path.

If its result is nonzero, processing continues using that context address.

### 5. Target-dependent bookkeeping

If the retained target is not `0x0DE1`, the function skips the derived-object processing and proceeds to error recording.

If the retained target equals `0x0DE1`, the function calls F-1411dcc31aed with the context address. It then reads a global selector.

#### Selector equal to `0x2800`

The function invokes F-63f3c76ed3e0 with the retained bookkeeping value.

- A result equal to signed 32-bit `-1` causes processing to fall through to error recording.
- Every other result causes its low eight bits to be stored at derived-object offset `0x107`, followed by an immediate return.

There is no visible range check beyond exclusion of exactly `-1`. For example, a result of `0x00000102` produces byte `0x02`; a result of `-2` produces byte `0xFE` in the represented byte store.

#### Selector greater than `0x2800`

If the equality test fails, the visible code reads the selector again for a signed 32-bit greater-than comparison.

When that comparison succeeds, the retained bookkeeping value is mapped as follows:

1. A value equal to `0x2600` maps to byte `1`.
2. Otherwise, a value equal to a separately read alternate-match global maps to byte `2`.
3. Otherwise, the mapping fails.

A successful mapping writes the byte at derived-object offset `0x105` and returns immediately. A failed mapping proceeds to error recording.

The `0x2600` comparison has precedence. If the alternate-match global also equals `0x2600`, the result is still byte `1`, not byte `2`.

The alternate-match global is consulted only after the `0x2600` comparison fails.

#### Other selector values

A selector that is neither equal to `0x2800` at the equality test nor greater than `0x2800` at the subsequent signed comparison leads to error recording.

The two selector reads must not be treated as an explicitly atomic snapshot. Synchronization and concurrent mutation behavior are **documented_only**.

### 6. Error recording

All paths that reach error recording read the first 32-bit word of the context.

- If it is zero, the function writes `0x0500`.
- If it is nonzero, the function leaves it unchanged.

This is first-error-preserving behavior at this function’s explicit write site. It does not establish that earlier dependencies preserve the error slot.

Successful writes to either derived-object byte return before this error-slot read. The function neither clears a preexisting error on success nor uses the error slot as its return value.

## Side effects

### Direct writes

The visible direct writes are limited to:

- Associated-object offset `0x0B`: zero or one, when a transition is required.
- Derived-object offset `0x107`: low byte of a successful conversion result.
- Derived-object offset `0x105`: byte one or two after successful direct mapping.
- Context offset zero: 32-bit `0x0500`, only when error recording is reached and the existing word is zero.

These writes are path-dependent, not an all-or-nothing update.

### Ordering guarantees

The established ordering relevant to observers is:

- Initial branch-specific dependency calls occur before the associated-object address and state checks.
- The state-byte write occurs before F-8a2b303ae860.
- F-8a2b303ae860 precedes the branch-specific global reads.
- F-9db809c408f4 precedes context lookup.
- A successful derived-byte write precedes immediate return and bypasses error recording.
- Error-slot preservation is decided from the value read at the final error-recording stage.

No stronger inter-thread visibility, atomicity, or memory-order guarantee is established.

### Ownership and lifetime

No allocation, release, reference-count change, or ownership transfer is directly established by the visible operations.

That absence does not constrain dependency internals. In particular, dependencies must not be assumed to retain or release memory, preserve globals, or preserve objects merely because their implementations are unavailable. Safe continued execution requires that addresses used afterward remain valid.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, dependencies return normally, accessed memory is valid, and dependencies do not alter the example’s relevant inputs or fields.

1. **Absent associated object still permits propagation.**  
   With zero mode, owner fields `0x94` and `0xD4` both zero, and owner field `0xD8` zero, exactly one F-2d9eb483b9a4 call occurs. No transition-stage dependency is reached.

2. **Optional calls precede an already-satisfied state.**  
   With nonzero mode, both optional guard fields nonzero, and associated byte `7`, three F-dbbd0e22ccce calls occur. The byte remains `7`; F-8a2b303ae860 is not called.

3. **Clearing accepts noncanonical nonzero state.**  
   With zero mode and associated byte `0x80`, the byte becomes zero before F-8a2b303ae860. F-9db809c408f4 receives `0x2600` as its third argument.

4. **Setting normalizes only a zero state.**  
   With requested mode `-1` and associated byte zero, the byte becomes one. The mode’s sign and magnitude do not select a separate branch.

5. **Context absence does not roll back.**  
   If a transition occurs and F-7fba0909c452 returns zero, the transition and both preceding transition-stage calls still occurred. No context error is written.

6. **Retained target mismatch records an error.**  
   With nonzero context, retained target other than `0x0DE1`, and an initially zero error slot, the slot becomes `0x0500`. F-1411dcc31aed is not invoked.

7. **Conversion writes a byte, not a bounded enumeration.**  
   With target `0x0DE1`, selector equal to `0x2800`, and conversion result `0x102`, derived offset `0x107` receives `0x02`. This path does not inspect the context error slot.

8. **Conversion failure preserves a prior error.**  
   Under the same selector condition, conversion result `-1` reaches error recording. An existing error `0x1234` remains `0x1234`.

9. **Direct mapping precedence is fixed.**  
   With target `0x0DE1`, selector greater than `0x2800`, retained value `0x2600`, and alternate-match global also `0x2600`, derived offset `0x105` receives byte one.

10. **Alternate match writes two.**  
    With the same target and selector conditions, a retained value different from `0x2600` but equal to the alternate-match global produces byte two at offset `0x105`.

11. **Unsupported selector retains the state transition.**  
    With target `0x0DE1` and a stable selector below `0x2800`, no successful bookkeeping-byte write occurs. Error recording is reached, but the earlier state transition remains in effect.
