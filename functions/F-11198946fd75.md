# F-11198946fd75

## Purpose

F-11198946fd75 writes selected fixed-width fields into an initial destination region, calls F-f5ad044082e5, and then writes additional source fields relative to the address returned by that dependency.

The established behavior is not a whole-record copy. The first destination field comes from a global slot rather than the source. Two bytes between initial fields receive no explicit write. The final destination base is supplied by the dependency and is not established to equal either input address.

Initial writes describe state established **before the dependency call**, not unconditional contents on return. F-f5ad044082e5 may modify those locations. Later writes may also overlap them if the returned base selects overlapping storage.

A constructor-like or copy-initialization purpose is inferred intent only. Record semantics and the dependency’s operation remain unknown.

## Behavior

### Initial field transfers

The first operation obtains Global A as a 32-bit value and writes it at destination offset 0x00. The source field at offset 0x00 is not explicitly read.

The following transfers then occur in table order. Each source read supplies its corresponding write before the next row is processed.

| Source offset | Destination offset | Width |
|---:|---:|---:|
| 0x04 | 0x04 | 32 bits |
| 0x08 | 0x08 | 32 bits |
| 0x0c | 0x0c | 32 bits |
| 0x10 | 0x10 | 32 bits |
| 0x14 | 0x14 | 16 bits |

The last row writes only destination offsets 0x14 and 0x15. This routine has no explicit initial write to offsets 0x16 or 0x17.

### Staged initial group

Four subsequent 32-bit fields have the following mapping:

| Source offset | Destination offset |
|---:|---:|
| 0x18 | 0x18 |
| 0x1c | 0x1c |
| 0x20 | 0x20 |
| 0x24 | 0x24 |

Their read timing is significant. Values at source offsets 0x1c, 0x20, and 0x24 are captured, in that order, before the read at source offset 0x18. The value from offset 0x18 is then written first, followed by the three captured values in table order.

Thus, writes within this group cannot change the already captured values. Earlier operations outside the group can still affect what the group reads when storage aliases.

### Global argument capture and remaining initial fields

After the staged group, the routine reads Global B once as a 32-bit value.

It then performs two 32-bit read/write pairs, in order:

| Source offset | Destination offset |
|---:|---:|
| 0x28 | 0x28 |
| 0x2c | 0x2c |

The dependency receives the captured Global B value. There is no second read at the call boundary. If either destination write aliases Global B’s storage, that change does not refresh the already captured argument.

### Dependency boundary

### Aliasing and temporal guarantees

The routine is not established to provide snapshot-copy or general overlap-safe behavior.

An earlier write may alter a later source read when the addresses overlap. Staged values retain what was read before their group’s writes, but this protection does not extend to fields read later.

Likewise, an initial write is not necessarily a final postcondition. It may be superseded by the dependency or by overlapping post-call writes. Final contents of initial destination fields require explicit preservation and non-overlap assumptions.

These ordering statements describe accesses in the supplied representation. They do not establish machine-instruction boundaries, atomicity, volatile semantics, or inter-thread synchronization.
