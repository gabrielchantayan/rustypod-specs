# F-8e2a731476b8

## Purpose

F-8e2a731476b8 is a four-argument routine with externally controlled dispatch, conditional argument checks, prefix-dependent arithmetic, and a repeatable byte-processing action. It returns a 32-bit word if execution reaches its return action.

Each execution of the processing action invokes F-d7be9cfb4000 three times, reads an input byte twice, and writes one byte through each of two caller-supplied destination addresses. The two reads are separated by a dependency call and the first output store; they are not interchangeable with one cached read.

**Established limitation:** the supplied representation omits the values and declarations of the external data controlling dispatch and arithmetic. It therefore does not establish a complete input-to-output mapping, validation order, output size, success convention, or termination guarantee.

A bounded transformation into two output streams is plausible inferred intent, not an established contract. Neither the meaning of the input prefix nor a particular encoding is established.

## Behavior

### Entry, captured data, and dispatch

A later external read supplies the initial control-state value. At every subsequent dispatch, the routine reads a separate external dispatch adjustment and combines it with the current state to select an action.

These have distinct contracts:

- **Entry-captured factor:** later changes to its backing storage do not replace the retained factor.
- **Initial state:** read to establish the initial control state, not reread automatically at every dispatch.
- **Dispatch adjustment:** referenced anew on each dispatch.
- **Other external operands:** read where their expressions occur, except where a calculated value is explicitly retained for later use.

Working quantities, saved destination bases, the working input pointer, and predicates initially contain zero or false values. Available actions subsequently capture arguments, compare values, perform arithmetic, prepare iteration state, process bytes, select results, or return.

An unrecognized dispatch value selects a prefix-arithmetic action that dereferences the working input pointer. It is not represented as a safe unsupported-state error. If reached before input capture, that pointer is still null.

Some transitions use zero/nonzero predicates; others use high-bit extraction or a sign-derived selector. Some narrow a selector to character width before choosing the next state. Missing external values prevent resolving these into one unconditional execution sequence.

### Processing action: captures and observable order

The following order applies whenever the processing action is reached with usable working state. “Retained” means reused from an earlier computation rather than reread from its original external storage.

1. **Prepare retained values before the first call.**  
   The routine calculates a displacement-scaled intermediate from the retained entry factor, the current destination displacement, and 256. It then reads an external multiplier and retains that multiplier’s product with the scaled intermediate, minus one. Both calculated values remain available after dependency calls.

2. **Make the first dependency call.**  
   F-d7be9cfb4000 receives the current destination displacement and the prepared auxiliary word, each represented as 32 bits. The routine consumes a 32-bit secondary-register result.

3. **Select and read the input byte.**  
   Using that result, the retained entry factor, and a newly referenced external factor, the routine calculates an input displacement. It reads one unsigned byte at the working input base plus four plus that displacement. The resulting input address is reused for the second byte read later in this action.

4. **Prepare the first byte-producing call.**  
   The byte is transformed into a low-eight-bit intermediate and then combined with wider arithmetic and bitwise operations. Argument preparation uses both retained pre-call intermediates and additional external reads. These later reads must not be replaced wholesale with the values seen before the first call.

5. **Capture the iteration subtraction before the second call.**  
   After preparing byte-dependent intermediates, the routine reads an external word and retains the current iteration quantity minus that word. This retained subtraction result is used for the later iteration update. It is not first calculated after the output stores.

6. **Make the second dependency call.**  
   Two calculated 32-bit arguments are supplied. Further external operands are referenced in their preparation, including a separate occurrence of the external word involved in the retained subtraction.

7. **Write the fourth-argument output.**  
   The character-sized secondary result from the second call is transformed and stored at the saved fourth-argument base plus the current destination displacement.

8. **Read the input byte again.**  
   The routine rereads the same previously calculated input address. It recomputes the byte-dependent arithmetic from this new read, using external operands referenced at this later point.

9. **Make the third dependency call.**  
   A different calculated pair of 32-bit arguments is supplied. Argument preparation uses retained intermediates and further external reads.

10. **Capture an update factor before the final store.**  
    After the third call returns, the routine reads an external factor and retains it for the iteration update.

11. **Write the first-argument output.**  
    The character-sized secondary result from the third call is transformed and stored at the saved first-argument base plus the same destination displacement.

12. **Prepare continuation.**  
    After that store, the next iteration quantity is calculated from the retained entry factor, the factor captured after the third call, and the subtraction result captured before the second call. The routine then reads an external transition word, records the current destination displacement as the working result, retains the calculated next iteration quantity, and dispatches again.

These boundaries are observable through dependency effects and aliasing. In particular:

- The first call cannot retroactively change the already retained scaled intermediate or multiplier-derived value.
- The second and third calls cannot retroactively change the retained iteration subtraction.

- That final store can affect a later transition-word read if their storage overlaps.
- Every subsequent dispatch still rereads the dispatch adjustment.

### Aliasing and mutable external data

No non-aliasing guarantee is supplied.

If both output addresses coincide, the second store determines the final byte, assuming no subsequent interfering effect. The first store still occurs.

If the first store overlaps the input address, the second input read can observe the newly written byte. Dependency calls may also alter input memory before either read.

Aliasing with external data is sensitive to capture boundaries. Retained values remain retained; later external reads can observe intervening changes. Neither “all external data is immutable” nor “every use reloads external data” preserves the established behavior.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Output-byte mapping.**  
   A byte-producing secondary result with low byte zero produces 236. Low byte one produces 137.

2. **Entry factor survives mutation.**  
   If a dependency changes the backing storage of the entry-captured factor, later calculations still use the captured factor. A separately referenced external operand can observe a later value.

3. **Dispatch adjustment is not frozen.**  
   If an intervening effect changes the dispatch adjustment, the next dispatch uses the value read at that dispatch, subject to the unresolved arithmetic semantics.

4. **Pre-call captures remain distinct from later reads.**  
   If the first call changes the multiplier used before that call, the retained multiplier-derived intermediate remains unchanged. Later explicit references to that multiplier can observe the change.

5. **Iteration subtraction precedes later effects.**  
   If the second or third call changes the external word used in the retained iteration subtraction, the later update still uses the earlier subtraction result. Other occurrences of that external word are separate reads.

6. **Final-store aliasing respects the capture boundary.**  
   If the final store overlaps the update factor’s storage, the current update uses the factor captured before that store. If it overlaps transition-word storage, the subsequent transition read may observe the write.

7. **The second byte read is real.**  
   If the first output store changes the input byte being reread, the second byte-dependent calculation uses the value present at the second read, not a cached first value.

8. **Coincident destinations preserve both stores.**  
   If both destinations identify the same valid byte, the second store determines its final value after the action. Eliminating the first store is not equivalent because it precedes the second input read.

9. **Null input and twenty are not complete rules.**  
   A null third argument establishes a false nonnull predicate when captured, not a guaranteed safe return. A prefix equal to twenty establishes neither acceptance nor a twenty-byte output.
