### Payload evolution

The byte-write behavior has several distinct payload sources.

**Ambient payload.** Early writes use the ambient eight-bit value. No visible success test conditions these writes.

**Literal zero.** A later region contains six explicit zero-byte writes, each at an individually derived scale-by-eight address. Each has a following paired scale-by-16,384 interaction, with further dependencies between boundaries. These writes do not establish a contiguous clear or a complete reset.

**Address-derived payload.** After the zero region, one write stores the low eight bits of its own scale-by-eight address. The following dependency receives two equal scale-by-16,384 arguments and that scale-by-eight address as a third argument. Under low-32-bit arithmetic, the byte’s lowest three bits are zero; the byte itself need not be zero.

**Retained derived payload.** A later unsigned 32-bit result supplies a byte consisting of the low eight bits of eight times that result. Its first destination is sixteen times the same result, followed by paired arguments at 32,768 times that result. The byte is retained for later writes rather than recomputed from newer results.

**Extracted middle bits.** A subsequent byte write uses bits 19 through 26 of that retained unsigned result. The represented mask limits the intermediate to 29 bits, but byte truncation discards the remaining higher selected bits. The following paired arguments use four times the current address-producing result.

**Reduced high-bit payload.** Another retained quantity supplies its top byte, which is reduced to a value from zero through seven. This reduction selects the original quantity’s bits 29 through 31. It is a different source from the unsigned result supplying the retained derived byte and middle-bit payload.

The reduced payload is reused across many later writes. Its eventual retention in another byte-sized value does not apply the reduction twice. Later stores continue using the same zero-through-seven value.
