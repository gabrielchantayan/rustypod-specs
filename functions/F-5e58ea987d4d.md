## Acceptance examples

These are conditional static criteria, not executed tests.

- **Opening overlap:** With valid, otherwise noninterfering destinations, the input-byte store replaces only the first addressed byte of the opening halfword. Reconstructing the resulting numeric halfword requires byte order.

- **Captured versus later storage:** If the S14-selected halfword store overlaps S15, the subsequent S15 capture observes the modified storage. A remains its earlier captured value.

- **Distinct S15 reads:** Suppose unsigned state is 5, captured S15 is 3, and the later S15 read is 7. The halfword at twice D receives 3, while b is one. With captured S03’s low byte `0x10`, the V + `0x45` byte is `0x64`, not `0x63`. This scenario requires the stated differing reads; their stability is not guaranteed.

- **Carry retention:** For k equal to zero, A equal to zero and A equal to `0x80000000` both produce D equal to zero, but c differs. Retaining D alone loses behavior.

- **Threshold boundary:** With stable S17 reads of `0xffffffa6`, q is zero for c = 0 and one for c = 1. Adding `0x59` first reaches `0xffffffff`. Stable S17 equal to `0xffffffa7` makes the threshold term true.

- **Opening graph interleaving:** An access observer must see object written to hub + `0x54`, then initial neighbor written to its own + `0x54`, then seed written to hub + `0x44`. Grouping the hub stores changes the represented sequence.

- **Leaf interleaving:** After leaf’s byte-`0x11` store, the required order is leaf byte `0x10`, center word `0x54`, leaf word `0x60`. Moving the last store before the center store is not equivalent under the contract.

- **Buffer transition:** Under ordinary non-aliasing memory assumptions, buffer’s `0x10` word successively receives `0x73`, `0x6e`, and captured buffer payload. Its byte `0x14` separately receives `0x73`.

- **Final argument capture:** If a last-three store aliases center + `0x44`, the third invocation argument remains the value captured before those stores.

- **Terminal promotion:** Loaded byte `0x20` yields Q = `0x20` and first argument `0x64`. For byte `0x80`, unsigned-byte promotion yields Q = `0x80`; signed 8-bit promotion followed by unsigned conversion yields Q = `0xffffff80`. Which applies remains **documented_only**.

- **Partial failure:** If the opening store succeeds and the following address load faults, the opening mutation is not rolled back by any represented action.
