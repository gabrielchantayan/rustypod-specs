# F-1e3293f9e6c9

## Purpose

F-1e3293f9e6c9 selects a processing path for an indexed record and supplies five caller-designated output destinations.

Established behavior:

- Selector byte 1 causes one evaluation with the caller’s output addresses.
- Every other selector byte causes four evaluations with invocation-local output addresses, followed by combination of components one through four and an explicit zero store to output five.

Direct sampling versus four-neighbor filtering is **inferred intent**. Neither the numerical interpretation of intermediate words nor the formulas implemented by dependencies are established.

## Interface

The function accepts ten positional inputs and returns no value.

| Position | Meaning | Represented width |
|---|---|---|
| 1 | Owner address | 32-bit address-bearing integer |
| 2 | Resource context | Opaque 32-bit word |
| 3 | Processing context | Opaque 32-bit word |
| 4 | Record index | Signed 32-bit integer |
| 5 | Input-table base address | 32-bit address-bearing integer |
| 6–10 | Output addresses for components one through five | Each designates a four-byte destination |

The representation establishes a 32-bit integer/address model, not a complete ABI. Alignment, endianness, pointer provenance, and exact arithmetic-overflow rules remain unresolved.

Dependency-produced words may represent values, handles, or references. Their width establishes neither ownership nor allocation.

### Referenced layout

Let \(i\) denote the record index, \(B\) the input-table base, and \(T\) a table address read from the owner.

| Location | Access |
|---|---|
| Owner + 8 | Read a four-byte table address |
| \(B + 4i + 12\) | Read first input word |
| \(B + 4i + 20\) | Read second input word |
| \(B + 4i + 56\) | Read descriptor word |
| \(T + 36i + 60\) | Read path-selector byte |
| \(T + 36i + 63\) | Read first mode byte |
| \(T + 36i + 64\) | Read second mode byte |
| \(T + 36i + 32\) | Form the address supplied to evaluation |

Offsets are bytes. The 36-byte stride does not establish an isolated 36-byte record; referenced offsets exceed that stride.

The input-table base is first adjusted by \(4i\). Defined execution requires valid intermediate arithmetic, not merely an accessible final address. Arbitrary modular wrapping is not established.

The owner’s table-address field is reloaded for every selector access, every mode access, and every evaluation-address construction. The descriptor word is reread before every descriptor-access call. These are not entry-time snapshots.

### Preconditions and output validity

Successful defined execution requires valid address arithmetic, readable referenced storage, writable output storage at each actual access, and valid dependency arguments. Every temporary word subsequently read must have a defined value at that read.

There are no explicit null, bounds, negative-index, alignment, resource-failure, or dependency-success checks. Negative indices are not separately rejected.

In the single-evaluation path, output initialization and completeness are dependency-defined. In the four-evaluation path, normal completion explicitly writes all five outputs, but defined values for the first four depend on valid temporary reads and dependency behavior.

## Behavior

### Conventions and entry reads

The first input word is read before the second. Both reads precede path selection. Those captured words, rather than subsequent input-table rereads, supply the construction inputs.

The selector is compared with exactly 1. Values 0, 2, and 255 therefore select the four-evaluation path regardless of unresolved byte-widening signedness.

The following descriptive roles apply:

- A **request** calls F-b35e541ebc78 with the resource context and literal zero.
- **Materialization** calls F-fbf0cbff8cb3 with the processing context, selector 40, a destination word, and a supplied word.
- An **operation** calls F-915779408ccb with the processing context, a selector, a destination word, and two ordered input words.
- A **conversion** calls F-95cebfad139d with both contexts, a source word, a destination word, a limit word, and an integer-widened mode byte.

Request labels below identify returned words by request occurrence, numbered separately within each path. They do not imply distinct values, interchangeable destinations, or separate allocations.

**All operation, materialization, and conversion return values are unused.** Their destination arguments remain the previously requested words. Any effects on state represented by those words are dependency-defined.

### Evaluations and temporary storage

A fresh descriptor read supplies one offset-0 access. Its returned word is reused for all four evaluations; there is no further descriptor access between them.

F-2d9b6ef1d9a1 receives candidates \(Q_{27},Q_{28},Q_{29},Q_{30}\), in that order. Each call also receives the owner, both contexts, a freshly formed record-associated address, the retained offset-0 result, and five temporary output addresses.

There are twenty distinct four-byte temporary destinations: four evaluation rows, each with five components. This logical organization does not establish a public row-major layout.

Each evaluation-address construction reloads the owner’s table-address field. An earlier dependency may therefore affect a later evaluation address.

Temporary contents are not immutable snapshots. Dependencies receive temporary addresses and may retain them; later calls may consequently affect values read from earlier evaluation rows.

Two selector-3 operations target \(Q_{32},Q_{33}\), with ordered pairs \((Q_8,Q_{31})\), \((Q_9,Q_{31})\). **The combination weights are the request-returned words \(Q_{32}\) and \(Q_{33}\), not returns from these operations.**

For each component one through four:

1. F-64d421fad3f9 receives both contexts, the component’s words from rows one and two, and \(Q_{32}\).
2. A second call receives the component’s words from rows three and four, and \(Q_{32}\).
3. A third call receives the preceding two returned words in order, and \(Q_{33}\).
4. The third return is immediately stored to that component’s caller output.

There are twelve combination calls. Each three-call group and its output store finish before processing the next component.

Temporary words are read for their respective calls, not frozen after evaluation. The first combination may affect words read by the second; earlier component processing may affect later components.

After output four is stored, output five receives the literal 32-bit value zero. No dependency call follows.

## Side effects

Direct reads include the initial input words, repeated owner-table and metadata reads, repeated descriptor reads, and one external-constant read in the selected path.

The four-evaluation path directly writes outputs one through five in order. Publication is sequential, not atomic. The single-evaluation path delegates output access to F-2d9b6ef1d9a1.

Unknown dependencies have no established preservation guarantee for globals, contexts, referenced objects, or other accessible memory.

No explicit release, ownership transfer, or reference-count operation is established outside dependency calls. Request results must not be classified as owned allocations merely because they are requested.

Temporary storage lasts only for the invocation. Dependency retention of its addresses, and avoidance of post-lifetime access, remain **documented_only**.

Output overlap is unchecked. Overlapping destinations receive sequential stores in the four-evaluation path; intervening dependencies may observe or modify accessible memory.

There is no explicit error return, failure branch, rollback, or recovery protocol. Faults or dependency failures may leave partial effects or partially published outputs.

## Acceptance examples

These are conditional static criteria. No runtime tests have been performed.

### Path selection

With valid accesses and normally returning dependencies, selector 1 produces ten requests and one evaluation using caller outputs. Selectors 0, 2, and 255 each produce 33 requests, four evaluations using temporary outputs, and twelve combination calls.

### Request identity is observable

If single-path requests 4–10 return distinguishable words, the first selector-6 destination must be request 4, its subsequent selector-3 destination request 5, and the second selector-6 destination request 6. Materializing 16 into request 5 instead of request 10 violates the established argument relationships.

In the four-evaluation path, the first conversion targets request 19, not request 23. Request 23 is the alternate-first-coordinate destination. Interchanging these roles is not justified even if a particular dependency happens to tolerate it.

### Neighboring order

The selector-6 operations targeting \(Q_{15}\) and \(Q_{17}\) both precede the selector-13 operations targeting \(Q_{16}\) and \(Q_{18}\). Reordering operations into request-number order changes the established call sequence.

### Weight identity

If final requests return distinguishable words \(Q_{31},Q_{32},Q_{33}\), materialization targets \(Q_{31}\); row-pair combinations use \(Q_{32}\); final combinations use \(Q_{33}\). Selector-3 return values do not replace either weight.

### Mutable inputs to later calls

If a conversion changes the mode byte used by a later conversion, the later call receives its own freshly read byte. If one evaluation changes the owner’s table address, the next evaluation uses the later table value.

For a component with row values \(a,b,c,d\), unchanged until argument reads, the combinations receive \((a,b,Q_{32})\), then \((c,d,Q_{32})\), then the two returned words with \(Q_{33}\). If the first call changes \(c\) before the second call reads it, the second receives the changed value. No weighted-average formula is implied.

### Fifth components and overlap

Temporary fifth components are never read by this function or passed by it to combination. Dependencies may independently access retained temporary addresses.

If all caller outputs designate the same valid writable word, execution completes normally, and no independent writer intervenes, the final zero store leaves that word equal to zero. No analogous store-order guarantee is established for the single-evaluation path.
