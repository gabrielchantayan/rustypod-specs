# F-2f5f1ef62c46

## Purpose

F-2f5f1ef62c46 is a configuration-driven dispatcher. Depending on global configuration and dependency results, it can invoke F-a1e5ead1c5b9 using descriptor words 0 and 1, invoke F-1661479163f4 using descriptor word 2, alter internal working state, loop, or return.

**Established static evidence:** each dependency-call action produces a full 32-bit carried word. Its most significant bit selects a continuation, but does not replace the carried word. Later actions can preserve, overwrite, multiply, or return the full word.

**Inferred intent:** the two F-a1e5ead1c5b9 call sites may operate on regions separated by 24 units, followed by a different operation through F-1661479163f4. Neither that sequence nor the meaning of the units is established without configuration values and dependency contracts.

This contract describes the supplied static representation. It does not establish a successful-operation convention or guarantee termination.

## Interface

### Inputs and descriptor layout

The function accepts:

- **Initial destination:** a 32-bit integer, installed into working state only when the setup action executes.
- **Descriptor:** a pointer to storage accessed as 32-bit words.

The descriptor accesses are:

| Word | Byte offset | Use |
|---|---:|---|
| 0 | 0 | Third argument to one F-a1e5ead1c5b9 call site |
| 1 | 4 | Third argument to the other F-a1e5ead1c5b9 call site |
| 2 | 8 | Second argument to F-1661479163f4 |

There is no eager descriptor copy. Each word is read when its call action executes.

A path that accesses all three words requires the corresponding 12-byte region to remain readable at those accesses. A path accessing only one word requires that particular four-byte region. Alignment requirements and access-fault behavior are **documented_only**.

Some configurations can return or loop without reading the descriptor. Consequently, descriptor readability on entry is not an unconditional requirement of every path.

### Return representation

The supplied representation constructs a 64-bit return:

- Bits 0–31 are the incoming carried word captured by the terminating dispatch iteration.
- Bits 32–63 come from a four-byte local value with no established initialization.

The upper half is **documented_only**. It must not be treated as zero, a dependency result, or a defined status. Whether it is a meaningful caller-visible return component or an artifact of the recovered interface is unresolved.

The low half is a general 32-bit word, not a Boolean. In particular, a dependency result classified with continuation bit 1 can produce low word `0xFFFFFFFF`, not 1.

## Behavior

### Entry capture

The established global-read order is:

1. Capture the multiplier.
2. Capture the coefficient.
3. Read the coefficient again and negate that second reading.
4. Read the entry state and add 2 to establish the fallback state.
5. Read the entry state again to establish the initial dispatch state.

The function also initializes the carried word, working destination, and working stride to zero, and the working descriptor pointer to null.

The captured multiplier, coefficient, negated coefficient, and fallback state are reused rather than refreshed during subsequent dispatch iterations.

The two coefficient readings can differ. Likewise, the initial state need not equal the fallback state minus 2 if the entry-state location changes between its reads.

### Dispatch cycle

Each iteration:

- Saves the incoming carried word as a snapshot.
- Reads the dispatch origin and subtracts it from the current state to obtain the selector.
- Establishes the captured multiplier as the default outgoing carried word.
- Establishes the captured fallback state as the default next state.
- Performs the selected action.

The action may override those defaults. There is no iteration limit.

| Selector | Action |
|---:|---|
| 0 | Return with the incoming snapshot as the low 32-bit word |
| 1 | Read descriptor word 0, call F-a1e5ead1c5b9 with the working destination, 24, and that word, then compute the carried result and continuation |
| 2 | Continue with both defaults |
| 3 | Read descriptor word 2, call F-1661479163f4 with 1 and that word, then compute the carried result and continuation |
| 4 | Add the working stride to the working destination; read descriptor word 1; call F-a1e5ead1c5b9 with the updated destination, 24, and that word; then compute the carried result and continuation |
| 5 | Set the stride to 24, preserve the full incoming snapshot as the outgoing carried word, read the setup continuation, and install the caller’s descriptor and initial destination |
| 6 | Set the outgoing carried word to zero and retain the fallback next state |
| 7 | Multiply the full incoming snapshot by a freshly read return multiplier, then read the dispatch origin for the next state |
| Any other value | Continue with both defaults |

Selector 0 returns the saved incoming word, not the default multiplier assigned during that iteration.

Selectors 2 and unrecognized selectors do not report an explicit error. They replace the carried word with the captured multiplier and route to the captured fallback state. Repeated selection can therefore loop indefinitely.

### Setup and destination state

Selector 5 is the only shown action that installs the caller’s descriptor and initial destination into working state. Within that action, stride assignment and carried-word preservation precede the setup-continuation read; installation of the descriptor and destination follows that read.

Before setup:

- The working descriptor is null.
- The working destination is zero.
- The working stride is zero.

A descriptor-reading action reached before setup attempts to access the corresponding offset through the null working descriptor. No validation or defined application-level error result is shown.

After setup, each selector-4 action advances the destination by 24 before calling its dependency. Repeated visits accumulate that advancement. A later setup action resets the destination to the original input and the stride to 24.

There is no rollback of the destination advancement based on a dependency result.

### Full carried result and continuation bit

All three dependency-call actions use the same arithmetic.

Let:

- \(a\) be the first captured coefficient, interpreted by its 32-bit representation.
- \(b\) be the separately captured negated coefficient.
- \(m\) be the captured multiplier.
- \(r\) be the dependency result consumed by the 32-bit arithmetic.

Define two products, each reduced to 32 bits:

\[
P_b = bmr \pmod{2^{32}}, \qquad
P_a = amr \pmod{2^{32}}.
\]

The **outgoing carried word** is the full 32-bit complement:

\[
W = \operatorname{NOT}_{32}(P_b \mathbin{\mathrm{OR}} P_a).
\]

A separate continuation bit is extracted:

\[
q = W \mathbin{\mathrm{logical\ shift\ right}} 31.
\]

Thus:

- \(W\) can be any value permitted by the products; it is not restricted to 0 or 1.
- \(q\) is exactly 0 or 1.
- The next iteration receives \(W\), not \(q\), as its carried word.
- \(q\) is used only to select the next state in these call actions.

For every dependency-call action, the dependency returns before either continuation read. The first continuation reading supplies the offset candidate. The full carried word and continuation bit are then computed, followed by the second continuation reading for the unmodified candidate.

| Call action | Outgoing carried word | Next state if \(q=0\) | Next state if \(q=1\) |
|---|---|---|---|
| Word 0 | \(W\) | First word-0 continuation reading plus 5 | Second word-0 continuation reading |
| Word 1 | \(W\) | First word-1 continuation reading minus 1 | Second word-1 continuation reading |
| Word 2 | \(W\) | First word-2 continuation reading plus 2 | Second word-2 continuation reading |

Both continuation reads occur on a normally completed call action, regardless of which candidate is selected. The selected candidate is formed arithmetically using \(q\) and its complement.

If both coefficient reads observe the same value and its negation is representable or has the expected 32-bit result, then \(b=-a\) modulo \(2^{32}\). Under that condition:

\[
q=1 \quad\Longleftrightarrow\quad amr \equiv 0 \pmod{2^{32}}.
\]

In this case \(q=1\) also means \(W=\texttt{0xFFFFFFFF}\). It does **not** mean that the outgoing carried word is 1.

This classification is not generally a zero-result test. A zero coefficient, zero multiplier, or modular product equal to zero can produce \(q=1\) for a nonzero dependency result.

### Propagation and return scaling

The distinction between \(W\) and \(q\) remains observable after the dependency action:

- A following selector 0 returns \(W\) in the low half.
- A following setup action preserves all 32 bits of \(W\).
- A following selector 7 multiplies all 32 bits of \(W\), not just its most significant bit.
- A following selector 6 replaces it with zero.
- A following default or selector-2 action replaces it with the captured multiplier.
- A following dependency action replaces it with that call’s newly computed full word.

Selector 7 reduces its unsigned product to 32 bits. It then reads the dispatch origin and installs that reading as the next state. If the origin remains unchanged until the next selector calculation, the next selector is zero and the product is returned. Origin changes can instead route execution elsewhere.

### Descriptor visibility and arithmetic boundaries

Descriptor reads occur separately at their call sites. A dependency mutation of descriptor storage can affect a later read, including a repeated visit to the same call site.

Dependencies can also affect later continuation, return-multiplier, or dispatch-origin reads. Entry-captured values are not refreshed.

The dependency-product and return-scaling arithmetic have established 32-bit unsigned behavior. Entry-state addition, candidate-offset arithmetic, dispatch subtraction, destination addition, and coefficient negation appear as 32-bit signed operations. Their behavior at signed-overflow boundaries is **documented_only** without instruction-level or ABI evidence. Examples involving those operations assume representable values.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume required accesses and dependency calls complete normally.

### Immediate termination

If the first selector is 0, the returned low word is zero. No descriptor word is read and neither dependency is called. The upper return word remains unspecified.

### Configured three-operation sequence

Assume representable, stable state arithmetic and configuration routing through setup, word 0, word 1, and word 2.

With initial destination 1000, the calls are:

1. F-a1e5ead1c5b9 with 1000, 24, and descriptor word 0.
2. F-a1e5ead1c5b9 with 1024, 24, and descriptor word 1.
3. F-1661479163f4 with 1 and descriptor word 2.

This order is conditional on routing; it is not guaranteed by the function alone. Each call computes a new full carried word.

### Zero result produces an all-ones carried word

With stable coefficient 1, captured multiplier 1, and dependency result 0:

- Both products are zero.
- \(W=\texttt{0xFFFFFFFF}\).
- \(q=1\), selecting the second continuation reading.

If the next selector is 0, the returned low word is `0xFFFFFFFF`, not 1.

If setup intervenes and then termination occurs without another carried-word replacement, the returned low word remains `0xFFFFFFFF`.

### Continuation bit zero need not mean carried word zero

With stable coefficient 1, multiplier 1, and dependency result 2:

- The products are `0x00000002` and `0xFFFFFFFE`.
- Their OR is `0xFFFFFFFE`.
- \(W=\texttt{0x00000001}\), while \(q=0\).

The offset continuation is selected, but immediate subsequent termination returns low word 1.

For dependency result 1 under the same captures, \(W=0\) and \(q=0\).

### Nonzero result can take the bit-1 continuation

With stable coefficient 2, multiplier 1, and dependency result \(2^{31}\), both reduced products are zero. Therefore \(W=\texttt{0xFFFFFFFF}\) and \(q=1\), despite the nonzero dependency result.

With captured multiplier zero, every dependency result produces that same full carried word and continuation bit.

### Scaling uses the full word

Suppose a dependency action produces `0xFFFFFFFF`, configuration next selects action 7, and the return multiplier is 9.

The outgoing scaled word is `0xFFFFFFF7`, the low 32 bits of \((2^{32}-1)\times9\). If the next selector is 0, that is the returned low word. It is not 9.

### Mutable descriptor and repeated advancement

If the word-0 dependency changes descriptor word 1, a later word-1 action observes the changed word.

After setup at destination 1000, two visits to action 4 without another setup pass destinations 1024 and 1048. An intervening setup restores the starting destination to 1000.

### Descriptor action before setup

If configuration selects a descriptor-reading action before setup, the attempted read uses the null working descriptor plus the applicable offset. No defined application-level failure value is established.
