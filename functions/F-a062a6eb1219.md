# F-a062a6eb1219

## Purpose

F-a062a6eb1219 derives four fields from a 32-bit unsigned input and writes them into a caller-designated record. The fields occupy byte offsets 3, 4, 6–7, and 8. It uses a temporary, three-word record and three opaque dependencies to perform the calculation.

**Inferred intent:** the arithmetic and field arrangement are consistent with converting a serial day value into calendar components: a year-like value, a month-like byte, a day-like byte, and a weekday-like byte. The weights 400, 100, and 4, two temporary boundary evaluations, and a conditional predicate support that interpretation. They do not establish the epoch, calendar, valid range, or field encodings.

**Established behavior:** the exact contract is the argument handling, dependency-call sequence, arithmetic, narrowing, and ordered writes below. Calendar terminology is descriptive, not a substitute for those rules.

## Interface

### Inputs

The function receives four 32-bit arguments:

1. **Serial input:** an unsigned 32-bit value.
2. **Destination address:** a 32-bit value represented as a signed integer in the supplied representation, but used as a memory address for the final writes. Its bit pattern is also copied into the first word of the temporary record.
3. **Seed word:** an opaque 32-bit value copied into the second word of the temporary record.
4. **Trailing seed word:** an opaque 32-bit value copied into the third word of the temporary record.

The seed arguments are not dereferenced by this function. Their surviving bytes are nevertheless exposed to F-9a770d6f49ee through the temporary-record pointer. They cannot be treated as unused arguments without knowing that dependency’s behavior.

### Outputs

There is no explicit return value. The direct result consists of these stores relative to the destination address:

| Offset | Width | Stored value |
|---|---:|---|
| 6 | 16 bits | Low 16 bits of the computed year-like value |
| 4 | 8 bits | Byte extracted from the later scaling call |
| 3 | 8 bits | Serial input minus the low byte of the final boundary result, plus one, reduced to 8 bits |
| 8 | 8 bits | Secondary byte exposed by the final F-d7be9cfb4000 call |

The stores occur in the order shown, not in increasing address order.

### Preconditions

The destination must permit the 16-bit write at offset 6 and the byte writes at offsets 4, 3, and 8. Any alignment requirement for the 16-bit store is target-dependent and is not established by the supplied material.

All dependencies must support the actual argument values and temporary-record access used here. The function performs no visible argument validation, destination validation, or range check before those operations.

There is no established numerical validity range for the serial input. In particular, zero is not rejected before subtracting one.

## Behavior

### 1. Construct the temporary record

The function reserves three consecutive 32-bit words for temporary state:

| Temporary offset | Initial contents |
|---|---|
| 0–3 | Destination-address word |
| 4–7 | Seed word |
| 8–11 | Trailing seed word |

This record is separate from the destination. The function later passes its address to F-9a770d6f49ee three times.

Before the first such call, selected portions of the first two words are overwritten. Other portions retain their seed-derived contents unless changed by a dependency.

### 2. Obtain a chained numerical decomposition

Four calls to F-d7be9cfb4000 use four separately referenced external 32-bit values. Denote those values, in order, as the first through fourth decomposition constants. Their numerical contents are unavailable.

The calls are chained as follows:

- The first receives the serial input minus one and the first decomposition constant. The subtraction is unsigned 32-bit subtraction; a serial input of zero therefore supplies `0xffffffff`.
- The second receives the high 32-bit half of the first result, interpreted as a signed 32-bit argument, and the second decomposition constant.
- The third receives the high 32-bit half of the second result, interpreted as a signed 32-bit argument, and the third decomposition constant.
- The fourth receives the high 32-bit half of the third result, interpreted as a signed 32-bit argument, and the fourth decomposition constant.

The first three results are consumed as 64-bit quantities with separately accessible low and high halves. Only a 32-bit result from the fourth call is used.

This does **not** establish that either half is a quotient or remainder. That interpretation requires the dependency contract.

### 3. Compute the year-like value

The low 32-bit portions of the first three results are treated as signed 32-bit values. The function forms a weighted sum using:

- 400 times the first low portion;
- 100 times the second low portion;
- 4 times the third low portion;
- the fourth call’s 32-bit result.

It then increments that sum by one only when both of these conditions hold:

- The second low portion is not equal to 4.
- The fourth call’s result is not equal to 4.

Either equality suppresses the increment.

The resulting 32-bit quantity is the year-like value used later. The supplied representation uses signed integer operations here; it supplies neither a non-overflow proof nor a checked-overflow path. A normal-range mathematical interpretation must therefore be distinguished from the exact target behavior if these operations overflow.

### 4. Evaluate two temporary boundaries

Before the first boundary call, the temporary record is modified so that:

- The upper 16 bits of its second word contain the low 16 bits of the year-like value.
- The low byte of its second word is 1.
- The high byte of its first word is 1.

In the byte-oriented record interpretation exposed by the supplied representation, these are the year-like field at offsets 6–7, a byte value of 1 at offset 4, and a byte value of 1 at offset 3. The middle byte of the second word remains seed-derived at this point.

F-9a770d6f49ee is then called with the temporary-record address. Its 32-bit result is retained as the **first boundary result**.

After that call, the function changes only the low byte of the temporary record’s second word to 3. It does not reconstruct the record from the original arguments. Consequently, any other changes made by the first boundary call remain available to the second call.

F-9a770d6f49ee is called again with the same temporary-record address. Its result is used as an unsigned 32-bit **second boundary result**.

### 5. Choose an adjustment

The adjustment is selected using an unsigned comparison:

- If the serial input is less than the second boundary result, the adjustment is 0. F-6985300e27da is not called.
- Otherwise, F-6985300e27da is called with the full 32-bit year-like value:
  - A zero result selects adjustment 2.
  - Any nonzero result selects adjustment 1.

The predicate receives the full computed value, not merely the 16-bit version previously placed in the temporary record.

No error interpretation is attached to the predicate’s result. Any nonzero return follows the same branch.

### 6. Derive another field byte

A fifth external 32-bit value is used in both arguments of another F-d7be9cfb4000 call.

Its first argument combines:

- The serial input minus the first boundary result;
- The selected adjustment;
- Multiplication by 12;
- Addition of that external value.

Its second argument is the same external value minus 6.

The serial-input subtraction participates in unsigned 32-bit arithmetic. The relevant additions and multiplication therefore have 32-bit wraparound behavior in the supplied expression; there is no visible saturation or range rejection.

The function retains only the low byte of this call’s result. This byte is the field later stored at destination offset 4.

The numerical external value is unknown. Neither the divisor-like argument nor the resulting byte can be replaced with a conventional calendar formula on the available evidence.

### 7. Evaluate the selected temporary boundary

The retained byte replaces the low byte of the temporary record’s second word. Other temporary-record contents are retained as they exist after the preceding dependency calls.

F-9a770d6f49ee is called a third time with the same temporary-record address. Only the low byte of this result is used.

The byte destined for output offset 3 is the low eight bits of:

- The serial input’s low byte;
- Minus the third boundary result’s low byte;
- Plus one.

The supplied representation passes through character-sized values. Whether plain characters are signed does not change this final modulo-256 byte result.

### 8. Write the destination and obtain the final byte

The function performs three destination stores:

1. The low 16 bits of the year-like value at offset 6.
2. The retained field byte at offset 4.
3. The calculated difference byte at offset 3.

Only after these stores does it call F-d7be9cfb4000 with the original serial input and the constant 7.

The function then writes a byte exposed through a secondary result channel from that call to destination offset 8. The ordinary primary result of this final call is not used.

The supplied material does not establish what this secondary byte means. In particular, it must not be specified as a remainder merely because the second argument is 7.

## Side effects

### Direct memory effects

The function directly writes five destination bytes: offsets 3, 4, 6, 7, and 8. It does not directly initialize the destination’s other bytes.

The year-like field is stored as a native 16-bit quantity. Its numeric value is narrowed to 16 bits without a visible range check. A portable byte-order promise is not established independently of the target representation.

The final dependency call occurs after the first four destination bytes have been written and before offset 8 is written. This ordering is observable if dependencies, shared state, or external observers can access the destination.

### Temporary-state exposure

F-9a770d6f49ee receives a pointer to the temporary three-word record. The pointer does not designate the output record, although its initial first word contains the output-address bits.

The temporary record’s lifetime is limited to this invocation. No ownership-transfer or retention guarantee is visible. A dependency that retains the pointer beyond its valid lifetime would require an external lifetime contract.

The supplied function does not allocate or explicitly release dynamic memory.

### Dependency effects and failures

Dependencies may have side effects that are not described here. No assumption is made that they preserve globals, leave the temporary record unchanged, or avoid accessing other memory.

The function has no explicit recovery, rollback, or error-return path. If the final helper fails or does not return, the earlier destination stores have already occurred. If an earlier dependency does not return, the later direct stores are not reached.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Zero serial input:** the first decomposition call receives `0xffffffff` as its first argument. No input-rejection branch precedes that call.

2. **Increment suppression:** if the second decomposition result’s low 32 bits equal 4, the weighted sum is not incremented. The same holds if the fourth result equals 4. The increment occurs only when neither equals 4.

3. **Unsigned boundary ordering:** if the serial input is `0xffffffff` and the second boundary result is 1, the “less than” condition is false. The predicate is called, regardless of how those bit patterns would compare as signed integers.

4. **Strict boundary comparison:** equality between the serial input and the second boundary result does not select adjustment 0. It selects the predicate-dependent path.

5. **Predicate interpretation:** on the predicate-dependent path, a result of zero selects adjustment 2; a result of −1 selects adjustment 1. There is no special handling for negative results.

6. **Year-field narrowing:** if the computed year-like value is 65,537, the destination’s 16-bit field receives numeric value 1. If called, the predicate still receives 65,537.

7. **Eight-bit difference:** if the serial input’s low byte is 0 and the third boundary result’s low byte is 2, output offset 3 receives 255.

8. **Temporary mutation retention:** if the first boundary call modifies temporary offset 5, the caller does not restore that byte before the second boundary call. An implementation that recreates the temporary record between those calls would not preserve the established behavior.

9. **Partial output visibility:** immediately before the final helper call, destination offsets 6–7, 4, and 3 already contain their new values. Offset 8 has not yet been directly written by this invocation.

10. **Secondary-channel distinction:** if the final helper’s primary result and secondary byte differ, offset 8 receives the secondary byte, not a byte selected from the primary result.
