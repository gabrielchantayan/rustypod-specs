# F-f745b39706b1

## Purpose

F-f745b39706b1 selects and returns one of three signed integer inputs. Its result is determined by two ordered comparisons:

- If the first input is strictly less than the second, the result is the second input.
- Otherwise, if the third input is strictly less than the first, the result is the third input.
- Otherwise, the result is the first input.

When the second input is no greater than the third, this behavior is consistent with constraining the first input to an inclusive interval whose lower endpoint is the second input and whose upper endpoint is the third input.

That interval interpretation is **inferred intent**, not an additional requirement. The established behavior also covers reversed endpoints, and the ordering of the comparisons matters in that case. The function does not reject, reorder, or normalize its inputs.

## Behavior

### Comparison priority

The first decision compares the candidate with the lower reference using strict signed less-than.

If that comparison is true, the function returns the lower reference immediately. The upper-reference comparison is not evaluated on this path. In particular, a conflicting upper reference cannot override this result.

If the first comparison is false, the function compares the upper reference with the candidate, again using strict signed less-than.

- If the upper reference is less than the candidate, the function returns the upper reference.
- Otherwise, the function returns the candidate.

This priority is part of the contract. Implementations that rearrange the decisions must preserve the same result for every representable input triple, including reversed reference values.

### Ordered references

When the lower reference is less than or equal to the upper reference:

- A candidate below the lower reference produces the lower reference.
- A candidate between the references, inclusive, produces the candidate.
- A candidate above the upper reference produces the upper reference.

Under this condition, the result is always within the inclusive interval described by the references.

Equality does not satisfy either strict comparison. A candidate equal to the lower reference bypasses the first return. A candidate equal to the upper reference does not cause the second comparison to select that reference. With ordered references, both cases still return a value numerically equal to the candidate.

### Equal references

When the references are equal, the result is always their common value:

- A smaller candidate selects the lower reference.
- An equal candidate remains unchanged.
- A larger candidate selects the upper reference.

No special equality branch is needed to obtain this behavior.

### Reversed references

When the lower reference is greater than the upper reference, the function still has defined selection behavior:

- Every candidate strictly below the lower reference returns the lower reference.
- Every candidate equal to or greater than the lower reference returns the upper reference.

The second statement follows because such a candidate is necessarily greater than the upper reference.

This creates a sharp transition at the lower reference. Immediately below it, the lower reference wins; at equality, the upper reference wins. The function does not promise an interval-containment property for reversed references.

### Extreme values

The selection rules apply unchanged to the smallest and largest representable signed values. Since the function only compares and selects existing values, it does not need to calculate a distance between references or adjust an endpoint.

This matters for extreme input combinations: a conforming implementation must not replace the comparisons with arithmetic whose overflow could change the result.
