# F-0e1b14afd571

## Purpose

F-0e1b14afd571 performs a lookup associated with a caller-supplied context, examines a signed two-word quantity and two selector bytes in the returned record, and either returns immediately or updates a result area within that context.

Its established behavior includes five distinct outcomes after a successful lookup:

- Return the 32-bit negation of the quantity’s low word when the quantity is nonpositive.
- Mark the context and delegate to F-518be8877b82 when the first selector byte is nonzero.
- Produce an address-valued result when the second selector byte is nonzero and F-c87e8125aeb8 returns nonzero.
- Store one captured pair of words and return 2 when that dependency returns zero.
- Store a different captured pair of words and return 1 when both selector bytes are zero.

The field meanings are not established. Interpretations such as “status,” “type,” “payload,” and “result object” are useful descriptive labels, not evidence of an external data model.

## Interface

### Input and return representation

The function takes one 32-bit argument, treated as a context address. It returns one 32-bit value.

The return value is not uniformly an error code or uniformly a pointer. Depending on the selected path, it is:

- Zero.
- A negated 32-bit record word.
- The return value of F-518be8877b82.
- The address eight bytes beyond the context base.
- The integer 2.
- The integer 1.

No independent return tag distinguishes these cases. A caller must use the surrounding protocol and context state to interpret the result. Numeric collisions between these categories are possible.

The visible interface provides no null-context rejection, size argument, or bounds checking.

## Behavior

### 1. Obtain the record

The first dependency call is F-ee46d7dc6aa5, with the original context argument and a second argument equal to zero.

If its result is null, the function returns zero immediately. No context or record field is directly accessed after that result.

This path does not guarantee absence of side effects: the lookup dependency has already run.

### 2. Check the two-word quantity

For a nonnull record, the function reads its word at offset 16 and then its word at offset 20.

The visible sign-and-overflow condition is equivalent to selecting the immediate-return path when:

- The high word is negative as a signed 32-bit value; or
- The high word is zero and the low word is zero.

Equivalently, this path is selected when \(Q \leq 0\). It is not a test of the low word alone.

On that path, the function returns the 32-bit negation of the captured low word. At the word-representation level, the result is

\[
R = (-L) \bmod 2^{32}.
\]

For example, a low word of zero produces zero even when the high word is negative. A low word of `0x80000000` produces the same 32-bit bit pattern under word negation. This describes the supplied width-specific operation, not a portable signed-language overflow guarantee.

Neither selector is read on this path, and this function performs no direct context write.

Only a strictly positive \(Q\) reaches selector handling.

### 3. Give the first selector priority

The function next reads the byte at record offset 24.

If it is nonzero:

1. The 32-bit context field at offset 52 is written with 1.
2. F-518be8877b82 is called with:
   - The address at context offset 8.
   - A fixed callback designator embedded in the function.
   - The 32-bit value `0xffffffff`.
   - The value 1.
3. The dependency’s return value becomes this function’s return value.

The second selector is not read on this path. No payload pair is copied directly, and no later control-field or discriminator write is performed by this function.

The marker write precedes the dependency call. Thus the dependency can observe that write, subject to its own behavior and the execution environment. There is no visible rollback if the dependency returns a value conventionally interpreted as failure.

The callback body and its behavior are not established by the supplied material.

### 4. Handle a nonzero second selector

If the first selector is zero, the function reads the byte at record offset 25.

If that byte is nonzero, it captures the record words at offsets 0 and 4, in that order, and calls F-c87e8125aeb8 with those two captured words.

#### Nonzero dependency result

If F-c87e8125aeb8 returns any nonzero value:

1. The current 16-bit context field at offset 36 is read.
2. Its upper eleven bits are preserved, and its lower five bits are replaced with binary value 1.
3. The resulting 16-bit field is written back.
4. The byte at context offset 38 is written with 5.
5. The function returns the address at context offset 8.

The transformation is

\[
T_{\text{new}} = (T_{\text{current}} \mathbin{\&} \texttt{0xffe0}) \mathbin{|} 1.
\]

The preserved bits come from the field as read **after** F-c87e8125aeb8 returns. They are not necessarily the bits present at function entry.

This branch performs no direct payload-pair write and does not call F-74b5a05d0094.

#### Zero dependency result

If F-c87e8125aeb8 returns zero:

1. F-74b5a05d0094 is called without visible arguments; its return value is ignored.
2. The previously captured first word is written at context offset 16.
3. The previously captured second word is written at context offset 20.
4. The 16-bit field at context offset 36 is replaced with 8.
5. The byte at context offset 38 is written with 2.
6. The function returns 2.

The pair is not reread from the lookup record after either dependency call. A dependency’s modification of that record therefore does not change the captured values used for these stores.

Unlike the nonzero-result branch, this branch does not preserve any bits of the previous 16-bit control field.

### 5. Handle two zero selectors

If both selector bytes are zero:

1. The record words at offsets 8 and 12 are captured, in that order.
2. F-74b5a05d0094 is called without visible arguments; its return value is ignored.
3. The captured first word is written at context offset 8.
4. The captured second word is written at context offset 12.
5. The 16-bit field at context offset 36 is replaced with 4.
6. The byte at context offset 38 is written with 1.
7. The function returns 1.

F-c87e8125aeb8 is not called on this path.

## Side effects

### Direct memory effects

The function directly modifies only the context-relative fields identified above. Which fields are written depends on the selected path.

Null lookup and nonpositive-quantity paths have no direct stores. Other paths write only their specified fields; there is no visible clearing of unused payload locations, the marker, or stale discriminators from previous invocations.

For example, writing the payload pair at offsets 16 and 20 does not directly clear the pair at offsets 8 and 12.

### Ordering and partial updates

The supplied representation establishes the branch-local access and call order described in the behavior section. It does not establish atomic publication of an entire result.

In the pair-writing branches, payload words are stored before the control field, and the discriminator is stored last. In the delegated branch, the marker is stored before the call.

If a memory access faults or a dependency fails to return normally, no recovery or rollback is visible. The completed prefix of effects may remain observable.

These are local execution-order observations, not a synchronization contract for concurrent readers.

### Aliasing and dependency interference

No non-aliasing guarantee is supplied between the lookup record and the context. Capturing a pair before a dependency call ensures that subsequent stores use those captured values even if overlapping record storage changes.

Conversely, dependencies may modify context fields before this function resumes. Only subsequent explicit stores constrain the final contents of those locations. Untouched fields must not be assumed unchanged across a dependency call.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not executed tests. Unless a case states otherwise, assume valid accessible storage, normally returning dependencies, and no unmentioned dependency mutations.

1. **Null lookup result.**  
   If F-ee46d7dc6aa5 returns null, the result is zero. This function performs no later direct reads or writes.

2. **Zero two-word quantity overrides both selectors.**  
   If both quantity words are zero, the result is zero even if both selector bytes are nonzero. Neither selector is read.

3. **Negative high word with zero low word.**  
   If the high word is `0xffffffff` and the low word is zero, \(Q\) is negative and the return is zero. A zero return therefore does not uniquely identify a null lookup or a zero quantity.

4. **Negative quantity with nonzero low word.**  
   If the high word is `0xffffffff` and the low word is 1, the immediate-return result has bit pattern `0xffffffff`. No selector-controlled action occurs.

5. **Positive quantity despite a signed-negative low word.**  
   If the high word is zero and the low word is `0x80000000`, selector handling is reached. The low word is unsigned for the two-word comparison.

6. **First selector takes precedence.**  
   For positive \(Q\) and a nonzero first selector, the context marker becomes 1 before F-518be8877b82 runs. Its return is forwarded regardless of the second selector’s stored value.

7. **Preserve upper control bits on a nonzero predicate result.**  
   With positive \(Q\), first selector zero, second selector nonzero, and F-c87e8125aeb8 returning nonzero, suppose the control field is `0xabde` when subsequently read. It becomes `0xabc1`; the discriminator becomes 5; the result is the context-offset-8 address.

8. **Replace the control field on a zero predicate result.**  
   Under the same selector conditions, if F-c87e8125aeb8 returns zero, the pair captured from record offsets 0 and 4 is written at context offsets 16 and 20 after F-74b5a05d0094 returns. The control field becomes exactly 8, the discriminator becomes 2, and the return is 2.

9. **Both selectors zero.**  
   For positive \(Q\) and two zero selectors, the pair captured from record offsets 8 and 12 is written at context offsets 8 and 12 after F-74b5a05d0094 returns. The control field becomes exactly 4, the discriminator becomes 1, and the return is 1.

10. **Record mutation after capture.**  
    In either pair-writing branch, if a dependency changes the selected record words after they were captured, the stored pair still contains the captured values. Other dependency effects remain unconstrained.
