# F-246821290652

## Purpose

F-246821290652 processes an address-like record and submits its contents to a destination obtained from a caller-supplied 32-bit value. It submits two initial fields directly, processes a street field, chooses between combined and separate presentation of city/state/postal fields, and finally processes a country field.

The combined presentation is selected only when queries against separately prepared city and state values both return nonzero. The postal value does not participate in that decision.

**Established static evidence:** The supplied body establishes field offsets, dependency-call order, selection of two alternative sets of five configuration values, conditional evaluation, and explicit cleanup calls.

**Inferred intent:** The field markers suggest address rendering. The dependencies appear to prepare text-like objects, inspect them, format them, submit them, and clean them up. Their implementations are unavailable, so these interpretations do not establish exact text, output encoding, emptiness rules, ownership, or allocation behavior.

## Behavior

### Entry and configuration capture

The function first calls F-a2527c9526b8 with no explicit arguments. It then calls F-5b24edfb22c0 with the destination selector and retains its 32-bit result for all subsequent submission calls.

Next, it reads five default configuration values from global storage, in this order:

1. Country configuration.
2. Postal configuration.
3. State configuration.
4. City configuration.
5. Street configuration.

Each captured configuration value is 32 bits.

Only after these reads does the function inspect the record’s selector byte. If that byte is nonzero, it reads five alternative global values in the same order and replaces the captured defaults. If the byte is zero, no alternative values are read.

Consequently, the default reads occur even when the alternative set is ultimately used. They must not be described as skipped on the alternative path.

Configuration selection is completed before the first field-submission call. Later calls use the captured values rather than visibly rereading the configuration globals. This does not imply that dependencies preserve global state; their effects on globals are unknown.

### Initial submissions and street processing

The function submits the address of the first record field to F-34e302dc2e9a, followed by the address of the second field. Both calls use the retained destination value.

It then asks F-ccd301234b69 to prepare a temporary value using:

- The literal marker `<<<addr_street>>>`.
- The captured street configuration.
- A caller-provided temporary destination.

The resulting temporary is submitted to F-34e302dc2e9a, then passed to F-289ec4311c64 for cleanup.

These operations precede the city/state decision. The function has therefore already made three submission calls before it determines which presentation branch to use.

The supplied body does not establish whether preparation performs substitution, fallback selection, normalization, copying, or another transformation.

### City/state decision

The function prepares a temporary city value using F-ccd301234b69, the city source, `<<<addr_city>>>`, and the captured city configuration.

It then calls F-d8cbf9aa79a9 with a 32-bit word taken from four bytes into that temporary’s apparent storage. The returned 32-bit integer is tested only for zero versus nonzero.

- If the city query returns zero, the state decision temporary is not prepared or queried. The separate-presentation branch is selected.
- If the city query returns nonzero, the function prepares a state temporary using the state source, `<<<addr_state>>>`, and the captured state configuration. It queries the corresponding word at offset four through F-d8cbf9aa79a9.
- The combined-presentation branch is selected only if this state query also returns nonzero.

Negative query results count as nonzero. No positive-only comparison is present.

The decision temporaries are cleaned up before either presentation branch runs. If a state temporary was created, it is cleaned up first; the city temporary is cleaned up afterward. If no state temporary was created, only the city temporary is cleaned up.

The selected branch is retained across those cleanup calls. The decision is not queried again afterward.

### Combined presentation

1. Initializes a temporary from a static formatting resource through F-398e0e9a318a.
2. Calls F-5b24edfb22c0 on a distinct temporary intended to receive the combined result. This call’s return value is not used.
3. Prepares a postal temporary, then obtains a 32-bit derived value from it through F-44362605ab79.
4. Prepares a state temporary, then obtains its derived value.
5. Prepares a city temporary, then obtains its derived value.
6. Obtains a derived value from the formatting temporary.
7. Calls F-1f62160dfd52 with the result temporary, followed by the derived format, city, state, and postal values.

Thus preparation occurs in **postal, state, city** order, while the final formatting arguments occur in **city, state, postal** order after the format argument.

After formatting, cleanup occurs in this order:

1. City temporary.
2. State temporary.
3. Postal temporary.

The combined-result temporary is then submitted to F-34e302dc2e9a and cleaned up. The formatting temporary is cleaned up afterward.

The city and state values prepared for the earlier decision are not reused. Both fields are prepared again for combined presentation. No purity or repeatability guarantee is visible for preparation; the later values are not proven identical to those queried earlier.

### Separate presentation

If either required query returns zero, the function prepares, submits, and cleans up city, state, and postal values individually, in that order.

For each field, preparation uses its field address, corresponding marker, and captured configuration:

- City: `<<<addr_city>>>`.

Even if the city query returned zero, city is prepared again and submitted. State and postal are also prepared and submitted. A zero query result selects presentation; it does not suppress an individual field’s submission at this level.

It submits the country temporary, cleans it up, and returns.

Under normal completion, the number of F-34e302dc2e9a calls is:

## Acceptance examples

### Zero selector

Given a valid record whose selector byte is zero, the function reads the five default configuration values before that byte and uses those captured values in subsequent preparation calls. It does not read the five alternative values on this path.

### Nonzero selector

Given a selector byte of `0x80`, the alternative set is selected just as it would be for `0x01`. Default reads still occur first, followed by alternative reads after the byte test.

### Both queries nonzero

Given city and state query results of `1` and `-1`, respectively, combined presentation is selected. The postal field is not queried for this decision. Combined preparation occurs postal first, then state, then city; formatting receives city before state before postal.

Five submission calls occur on normal completion.

### City query zero

Seven submission calls occur on normal completion.

### State query zero
