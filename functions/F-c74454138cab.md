# F-c74454138cab

## Purpose

The supplied static representation establishes a sequence of seventy indirect-call occurrences, one identified direct call, eleven processor-specific register-transfer operations, and an attempted 16-bit memory write. The represented path then ends at an invalid-instruction stop rather than an ordinary return.

A subsystem-level purpose is **documented_only**. The evidence does not establish device initialization, decoding, memory management, or another specific application purpose.

This contract describes the visible path, conditional on each preceding operation completing and returning where required. Invalid-instruction and truncated-control-flow warnings prevent treating that path as a complete, independently validated executable function.

### Phase 6: Final memory write and stop

After F-i070 returns, the path attempts a 16-bit store of numeric value `0x00CD`.

The saved \(R_6\gg41\) value is at most \(2^{23}-1\). Consequently, its subsequent signed 32-bit interpretation is nonnegative, and the following right shift by eleven extracts the top twelve bits of \(R_6\).

Define:

\[
N=R_6\gg52,\qquad
D=N+\left\lfloor N/4\right\rfloor.
\]

The store destination is address \(D\), without an added base pointer or an explicit validity check.

\[
0\le N\le4095,\qquad 0\le D\le5118.
\]

The addition does not overflow 32 bits. The possible starting addresses are not contiguous: addresses congruent to four modulo five are skipped within the bounding interval. Both aligned and unaligned destinations are possible.

Bits 0–51 of \(R_6\) do not affect \(D\). Only bits 0–31 of \(R_6\) are explicitly passed to F-i067; bits 32–51 are not included in that argument.

The store occupies two bytes in a byte-addressed interpretation. Their ordering, the applicable address space, and access behavior are unresolved. The upper bound 5118 describes the starting address, not the last byte touched.

An invalid-instruction stop follows the store in the representation. A store fault would prevent reaching that stop.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes execution reaches the relevant event and uses the stated fixed-width interpretation.

1. **Third-argument low-bit exclusion.** With identical relevant hidden state and earlier results, \(P=4\) and \(P=7\) both produce \(A=8192\). F-i004 receives the same third explicit argument. Whole-function equivalence is not established.

2. **Discarded high input bit.** \(P=0\) and \(P=2^{21}\) both produce \(A=0\), because the latter value’s set bit is discarded by the 32-bit left shift.

3. **Fourth-argument parity.** An even \(Q\) supplies zero as F-i009’s first argument. An odd \(Q\) supplies the bit pattern `0x80000000`.

4. **Signed shift boundary.** If F-i025 returns `0x04000000`, arithmetic signed-right-shift semantics make F-i033’s second argument `0xFC000000`, not `0x04000000`.

5. **Transfer sequence.** Reaching F-i058 through the visible path entails eleven preceding processor transfers. Two consume the F-i037 result consecutively; two zero-data transfers occur after F-i056; the last follows F-i057.

6. **Minimum destination.** If \(R_6\)’s top twelve bits are zero, the final write attempts to store `0x00CD` at address zero. No null-address rejection is shown.

7. **Address spacing.** If those top twelve bits equal four, the destination is five, not four. Alignment cannot be assumed.

8. **Maximum destination and distinct bit uses.** If those top twelve bits equal 4095, the starting destination is 5118. Changing bits 0–51 does not change that destination. F-i067 explicitly receives only bits 0–31, not all 52 lower bits.

9. **Interrupted execution.** If F-i070 does not return, neither the final store nor the terminal stop is reached. If the store faults, the represented following stop is not reached.
