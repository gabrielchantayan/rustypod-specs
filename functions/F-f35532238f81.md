# F-f35532238f81

## Purpose

F-f35532238f81 performs two dependent traversals over a caller-supplied, pointer-linked structure and writes two 32-bit results to caller-provided storage. Both traversals use F-98d1a792da29 to choose between links at node offsets +8 and +12. The dependency receives the same opaque query value in both traversals, but its position relative to the node-associated address is reversed.

The established behavior is a pair of comparison-directed searches with unusual candidate updates: when a candidate is updated, it becomes the selected **child**, not the node just examined. Consequently, either result can be zero, a header address, or a node address.

A possible intent is to locate two search boundaries in a tree-like container. That interpretation is **inferred intent**, not an established contract. The available evidence does not establish ordering rules, comparator semantics, balancing invariants, or whether the results represent a valid range.

## Interface

### Inputs

The function accepts three arguments:

1. **Output address.** An address designating storage for two consecutive 32-bit values. The first result is written at offset +0 and the second at offset +4.
2. **Structure address.** An address used to locate a header pointer and to form an opaque address supplied to the dependency.
3. **Opaque query word.** A 32-bit value forwarded unchanged to F-98d1a792da29. Its interpretation as a scalar, pointer, handle, or encoded value is unknown.

There is no explicit return value.

### Widths and address interpretation

The supplied representation uses 32-bit integer-sized fields for links, header references, traversal state, and results. These words are used as addresses when accessing the linked structure. The observable contract is therefore expressed in terms of 32-bit address-valued words, not host-native pointer widths.

Offsets are byte offsets. Address calculations include:

The node-associated address at +16 is passed onward; this function does not directly read the contents at that address. Likewise, the structure-associated address at +25 is formed and passed onward without a direct read by this function.

## Behavior

### First traversal: initialization

The first traversal begins with the following ordered reads:

1. Read the header address from structure +16.
2. Read the initial-node address from that header +4.
3. Read the header address again from structure +16 and retain this second value as the first candidate.

The two reads of structure +16 are distinct in the supplied representation. The initial node comes from the header used for the first read chain; the candidate comes from the later header read. No dependency call occurs between these initialization reads.

If the initial-node address is zero, the first traversal makes no dependency calls and retains its initialized candidate.

### First traversal: node processing

For each nonzero current-node address, the function calls F-98d1a792da29 with these ordered arguments:

1. Structure address +25.
2. Current-node address +16.
3. The opaque query word.

The dependency’s 32-bit result is tested only for equality to zero.

- **Zero result:** Read the link at current node +8. Use that link as both the next current node and the new first candidate.
- **Nonzero result:** Read the link at current node +12. Use that link as the next current node, leaving the first candidate unchanged.

The selected link is read **after** the dependency returns. Thus, if the dependency changes that link in memory, the traversal observes the changed value rather than a value captured before the call.

The candidate update on a zero result includes zero links. If the selected +8 link is zero, the first candidate becomes zero and the traversal terminates.

A nonzero dependency result includes negative as well as positive values. The function does not distinguish their signs or magnitudes.

### Second traversal: independent initialization

After the first traversal terminates, the function starts again from structure memory:

1. Read the header address from structure +16.
2. Read the initial-node address from that header +4.
3. Read the header address again from structure +16 and retain this second value as the second candidate.

The second traversal does not reuse the first traversal’s original root or original header. Changes made during dependency calls in the first traversal can therefore affect the second traversal’s initialization.

If the newly read initial-node address is zero, the second traversal makes no dependency calls and retains its initialized candidate.

### Second traversal: node processing

For each nonzero current-node address, the function calls F-98d1a792da29 with these ordered arguments:

1. Structure address +25.
2. The opaque query word.
3. Current-node address +16.

Relative to the first traversal, the query word and node-associated address exchange positions.

The return value again controls a zero-versus-nonzero decision:

- **Zero result:** Read the link at current node +12. Use it as the next current node, leaving the second candidate unchanged.
- **Nonzero result:** Read the link at current node +8. Use it as both the next current node and the new second candidate.

As in the first traversal, the selected link is read after the dependency returns. A qualifying update to a zero +8 link sets the candidate to zero and terminates the traversal.

### Candidate semantics

Each result is determined by candidate initialization and subsequent qualifying updates:

| Traversal | Initial candidate | Candidate-update condition | New candidate |
|---|---|---|---|
| First | Header address from its second initialization read | Dependency returns zero | Newly read +8 link |
| Second | Header address from its second initialization read | Dependency returns nonzero | Newly read +8 link |

An update does not retain the current node or substitute the header when the child is zero. A later iteration that takes the +12 link leaves the preceding candidate intact.

This distinction is essential. Replacing these rules with conventional lower-bound, upper-bound, or current-node candidate tracking would change observable results.

### Output publication

Only after both traversals terminate does this function directly write its results:

1. Write the first candidate to output +0.
2. Write the second candidate to output +4.

There is no direct partial output publication between the traversals. Nevertheless, the dependency may have its own effects on output storage if it can reach that storage.

The writes are ordered, not transactional. No rollback is shown if the first write succeeds and the second write fails. Likewise, failure or nontermination during either traversal prevents the function from reaching its direct output writes.

## Side effects

### Direct effects

The function directly:

- Reads header and root words during each traversal’s initialization.
- Calls F-98d1a792da29 once per visited nonzero node.
- Reads one selected child-link word after each returning dependency call.
- Writes two 32-bit result words after both traversals finish.

It does not directly allocate, free, retain, or copy an object. Writing an address-valued result is not evidence of ownership transfer.

The function does not directly modify the header or node links. This statement does not constrain changes made by the dependency.

### Dependency effects and mutable state

F-98d1a792da29’s side effects are unknown. It must not be assumed to preserve globals, keep the structure unchanged, or avoid releasing memory.

Relevant consequences include:

- A changed selected child link can affect the very next traversal step.
- A changed header or root can affect the second traversal.
- Releasing the current node before the subsequent link read can invalidate that read.
- Releasing or invalidating the structure can invalidate later initialization or dependency operations.

The function supplies no visible synchronization, lifetime protection, mutation detection, or recovery mechanism.

### Aliasing

No explicit non-aliasing check is present. Output storage may overlap structure memory at the representation level, but such a call is safe only if all accesses and dependency behavior remain valid.

Because the function’s direct output writes occur after both traversals, those writes do not themselves alter earlier traversal decisions. They can, however, overwrite header, node, or other caller-owned storage at the end of the call if addresses overlap.

## Acceptance examples

These are conditional static examples, not runtime test results. Unless stated otherwise, assume valid storage, a fixed header address **H**, no dependency mutation, and normal dependency returns.

### Empty structure

- Neither traversal calls the dependency.
- The first output is H.
- The second output is H.

The function does not replace H with zero merely because the structure is empty.

|---|---|---|---|

| Zero | Nonzero | Zero | Zero |
| Nonzero | Zero | H | H |
| Nonzero | Nonzero | H | Zero |

### Candidate retained after a later opposite branch

Let N’s +8 link be **L**, and let L’s +12 link be zero.

If the first traversal receives zero at N and nonzero at L, it:

- Updates its candidate to L.
- Visits L.
- Terminates through L’s +12 link.
- Returns L as its first result.

If the second traversal receives nonzero at N and zero at L, its second result is also L.

The zero terminal +12 links do not clear either retained candidate.

### Link mutation during a dependency call

Suppose the current node’s +8 link initially contains L. The dependency changes that word to zero and returns a value that selects the +8 branch.

The applicable traversal reads zero after the call, sets its candidate to zero, and terminates. It does not continue to L based on the old link.

### Header replacement before the second traversal

Suppose a dependency call during the first traversal changes structure +16 from H to another valid header **J**, whose root is zero.

The second traversal initializes from J and, absent further changes, produces J as its result without dependency calls. Its initialization is not tied to H.

### Cyclic selected links

If dependency outcomes repeatedly select links forming a cycle, and nothing changes those links or outcomes, the traversal does not terminate. The function does not reach its direct result writes.
