# F-180a7626efbe

## Purpose

F-180a7626efbe describes a recovered, state-dependent operation that routes bytes through byte-selected addresses, writes and reads 32-bit words at calculated addresses, and invokes unresolved indirect dependencies.

The established behavior is a sequence of observable accesses and calls, not an application-level function such as allocation, serialization, or device control. The supplied representation reports invalid instruction data and ends at a truncated control-flow boundary. Consequently, this contract specifies the recovered sequence without certifying executable validity or normal completion.

If the entire visible sequence is reached, it contains **three direct byte writes and fourteen direct word writes**. Dependency-internal effects are additional and unknown.

### Widths and arithmetic

The recovered representation distinguishes:

- Eight-bit byte accesses.
- 32-bit word accesses and ordinary dependency results.
- One 64-bit dependency result, separated into low and high 32-bit halves.
- Logical right shifts of unsigned 32-bit values.

This contract uses **conditional 32-bit bitvector arithmetic** for calculated examples: additions, multiplications, and left shifts retain their low 32 bits; calculated addresses are interpreted using those resulting bits. This convention makes examples precise without resolving signed-overflow or actual machine-address semantics.

Unsigned arithmetic visible in the representation supports modulo-width interpretation. Calculations represented with signed integers require additional caution: their machine behavior is not independently established.

A byte write retains only the low eight bits of its payload. A word write supplies 32 bits. Endianness, alignment requirements, address mapping, and access permissions are **documented_only**.

The offsets `0x11` and `0x14` do not establish a structure layout. Unless stated otherwise, each destination below is an absolute calculated address, not a displacement within a proven object.

## Behavior

### Ordering and dependency notation

Opaque dependency IDs identify call occurrences. Distinct IDs do not prove distinct implementations or nonoverlapping targets.

### 1. Initial byte routing and result acquisition

The first direct read obtains an unsigned byte from the incoming address-bearing value plus 1. This byte is the **initial selector**. Before any listed dependency call, the operation writes the incoming byte to initial selector plus `0x11`.

The subsequent dependency order is:

1. F-D01a, F-D01b, F-D01c, and F-D01d, with no explicit arguments.
2. F-D01e, with no explicit arguments, producing the **first result**.
3. F-D01f, receiving the zero-extended initial selector and the first result shifted left by 2.
4. F-D01g, with no explicit arguments.
5. F-D01h, receiving two copies of the incoming 32-bit value shifted left by 10.
6. F-D01i, with no explicit arguments, producing a 64-bit result.

The shifted incoming value is called the **shifted input**. The low 32 bits of the wide result form the **packed word**; its high 32 bits form the **upper result**.

The first indirect target uses incoming return-link state plus `0xFFE`. Later targets are formed from embedded address-like anchors. Target validity is not established.

### 2. Upper-result transport

The operation writes the shifted input as a word to:

**4 × upper result + `0x14`**

F-D02a then receives the upper result. F-D02b, F-D02c, and F-D02d follow with no explicit arguments. F-D02e, also without explicit arguments, supplies the **first forwarding index**.

A second word write stores the upper result at:

**4 × first forwarding index + `0x14`**

F-D02f then receives 4 × first forwarding index.

This stage contains two word writes. Each stage from 3 through 14 contains one.

### 3. High-positioned packed fragment

**packed word × `0x10000000` + `0x14`**

The operation also retains the packed word masked with `0x1FFFFFFF` as the **masked packed word**. Under 32-bit arithmetic, the stored value depends only on the packed word’s low six bits, and its destination depends only on the low four bits.

## Acceptance examples

These are **conditional static examples**, not runtime tests. They assume accessible addresses, preceding operations that permit continuation, and the stated 32-bit arithmetic model.

1. **Absolute byte destination.** If the initial selector is `0xFF` and the incoming byte is `0xA7`, the first direct write places `0xA7` at address `0x110`. The incoming address-bearing value affects the selector read, not the destination’s base.

2. **Wide-result split.** If F-D01i returns `0x00000003_12345678` and the shifted input is `0x400`, the first stage-2 store writes `0x400` at `0x20`. F-D02a receives 3; the packed word is `0x12345678`.

3. **Fragment truncation.** For a packed word of `0x3F`, stage 3 writes `0xFC000000` at `0xF0000014`. For a packed word of `0x40`, both the fragment value and the variable portion of its address wrap to zero, producing a zero word at `0x14`.

4. **Distinct store and read locations.** If the first scale index is 2, stage 5 writes 8 at `0x34`, while its word-read expressions address `0x1C`. If both expressions observe `0x12345678`, F-D05e receives `0x12345`, 8, and `0x48D159E0`. Equal observations are an example condition, not a guarantee.

5. **Captured-value timing.** If stage 11 captures `0xABCDEF01`, stage 12 stores `0xABCDE` at retained scaled index plus `0x14`. A later change to the original read location by F-D11e does not constitute a reread.

6. **Index-fragment widths.** If the retained index is 3, the retained scaled index is 12. F-D13e receives `0x30000` as its first argument and `0xC0000000` as its third argument.

7. **Late selectors may differ.** For a late packed value of `0x1234567F`, the stage-15 byte payload is `0xFC` and the stage-16 payload is `0x23`. Selector reads of 2 and then 5 route those bytes to `0x13` and `0x16`. F-D17e receives 5 as its second argument.

8. **Complete direct-write count.** If every stage is traversed, there are fourteen direct word writes and three direct byte writes, regardless of destination aliasing. Dependency-internal writes are not included.

9. **Interrupted traversal.** If F-D04b does not return, later direct writes are not required. Earlier completed writes have no visible rollback guarantee.
