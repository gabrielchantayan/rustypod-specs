### Arithmetic and access notation

The following notation describes bit patterns without asserting portable signed-arithmetic semantics:

- **Lₙ(x)**: multiply a 32-bit pattern by \(2^n\), retaining its low 32 bits.
- **E(x)**: retain bits 0–29 of a 32-bit pattern, then shift logically right by 20. Its range is 0–1023.
- **low** and **high**: the lower and upper 32-bit halves of a reported 64-bit result.
- **Selector read at a base**: read one unsigned byte at base plus 1.
- **Selected-byte store**: use the selector byte as a numeric address component, adding `0x11`.

Thus, a selected-byte store targets an address from `0x11` through `0x110`. It does not dereference a full pointer recovered from the selector location.

Byte stores retain eight bits; word stores write 32 bits. Address sums and products below use the apparent low-32-bit machine arithmetic model. Exact address-width conversion, byte order, alignment requirements, and fault behavior remain unresolved.

## Acceptance examples

These are conditional static criteria under the documented arithmetic model, not executed tests.

1. **Byte truncation.** An initial word of `0x00000040` produces a first stored byte of zero: L₂ yields `0x00000100`.

2. **Selector width.** A selector of `0xff` makes its selected-byte destination `0x110`, irrespective of adjacent memory bytes.

3. **Retained selector.** If phase 2 reads `0x20` and F-C03 changes the selector source to `0x80`, its word store still targets `0x34`.

4. **Fresh selector.** A selector changed before an explicitly fresh read controls the subsequent selected-byte destination.

5. **Global snapshot.** A sampled global value of `0xffc00000` produces byte `0xff` in phase 3, even if a subsequent dependency changes that global.

6. **Extraction truncation.** If E(first payload) is `0x300`, phase 5 stores byte zero. The extraction yields ten bits; the store retains eight.

7. **Retained-index parity.** If the retained duplicate index is odd, phase 12 stores `0x80000000`; if it is even, it stores zero. An odd index with an even terminal word still stores `0x80000000`. An even index with an odd terminal word still stores zero.

8. **Separate terminal-word role.** A terminal word of `0x00100000` makes the phase-12 word-read address `0x15`. It does not determine the preceding store’s parity-dependent value. Successful execution requires that address to support the word read.

9. **Restricted next base.** After phase 10, the ambient base is one of `0`, `0x40000000`, `0x80000000`, or `0xc0000000`.

10. **No normal completion.** Successful completion of phase 12 starts another iteration rather than returning.
