# F-7cab40c7b130

## Purpose

The second input controls two related choices:

- Whether F-dc13818ac82a is invoked with no explicit argument or with a signed, right-shifted argument.

The returned value is not a saturated result or a checked mathematical conversion. Under the width and shift model described below, it consists of product bits 16 through 47, inclusive.

**Established behavior:** conditional argument transformation, one dependency invocation on a normally completing path, signed multiplication, and extraction of a 32-bit product slice.

**Inferred intent:** the operations resemble fixed-point scaling with a precision-reduction branch. The available evidence does not establish a numerical format, physical unit, or application-level meaning.

## Behavior

### Branch selection

The function first examines the second input after a signed right shift by 24 bits.

It selects the unchanged-input branch when that shifted value is either zero or negative one. With 32-bit signed arithmetic shifts, this is exactly the inclusive interval:

\[
-16{,}777{,}216 \leq \text{second input} \leq 16{,}777{,}215.
\]

This interval is asymmetric around zero because the lower endpoint is included and the corresponding positive magnitude is excluded.

All other second-input values select the precision-reduction branch.

The test is not equivalent to “nonnegative versus negative,” nor does it merely test whether the most significant byte is zero. Both a zero upper byte and an all-one upper byte select the unchanged-input branch.

### Unchanged-input branch

For a second input within the interval above:

1. F-dc13818ac82a is invoked with no explicit argument in the supplied representation.
2. Its signed result is used as one multiplicand.
3. The first input is used unchanged as the other multiplicand.

The second input contributes no explicit argument to that dependency invocation. It still determines which invocation form is selected.

“No explicit argument” does not establish that the dependency has no inputs. It may depend on global state, machine state, an implicit calling convention, or other information not described here.

### Precision-reduction branch

For a second input outside the interval above:

1. The second input is shifted right by eight bits using a signed shift.
2. F-dc13818ac82a is invoked with that shifted value as its explicit argument.
3. After the dependency returns, the first input is shifted right by eight bits using a signed shift.
4. The dependency result and shifted first input become the two multiplicands.

For a signed arithmetic shift, a negative value that is not divisible by 256 rounds toward negative infinity. For example, shifting negative one by eight bits leaves it equal to negative one.

This branch discards eight low-order bits from the first input before multiplication. Those bits do not participate in the product and cannot later be recovered by the result extraction.

There is no visible compensating adjustment to the final extraction for this branch. Both branches select the same product-bit positions.

- Discards the lowest 16 product bits.
- Retains the next 32 bits.
- Discards all product bits above bit 47.

The returned unsigned value can therefore wrap relative to the mathematical scaled product. It can also be zero when the exact product is nonzero.

No rounding increment, clamping, saturation, error flag, or range check is visible.
