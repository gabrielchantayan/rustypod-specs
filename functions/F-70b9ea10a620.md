# F-70b9ea10a620

## Purpose

F-70b9ea10a620 advances an integer-valued position by a scaled product and publishes both the computed position and the position observed before the update.

The established behavior is a single integer read, arithmetic using three scalar inputs and a fixed factor of four, and three ordered integer writes. Two output destinations receive the computed value; the third receives the initially read value. Destination aliasing can overwrite an earlier result.

Interpreting the values as positions, offsets, dimensions, or allocation boundaries is inferred intent, not an established interface guarantee. The supplied evidence does not show an allocation, buffer access, capacity check, or address dereference based on the computed integer.

## Interface

The function has six inputs and no explicit return value:

| Input | Role |
|---|---|
| Updated-value destination | Pointer to an integer object that receives the computed value in the first write. Its prior contents are not read through this input. |
| Current-value location | Pointer to an integer object whose initial value supplies the arithmetic base. This object receives the computed value in the second write. |
| Previous-value destination | Pointer to an integer object that receives the initially observed base in the third write. Its prior contents are not read through this input. |
| First scalar factor | Integer multiplied by the other factors and four. |
| Second scalar factor | Integer multiplied by the other factors and four. |
| Third scalar factor | Integer multiplied by the other factors and four. |

These names identify interface roles, not separate storage requirements. Two or all three pointer inputs may designate the same integer object; the resulting overwrite behavior is specified below.

**Integer representation.** The supplied representation declares the scalar inputs, pointed-to objects, and arithmetic temporaries as signed `int`. A 32-bit signed interpretation is plausible, but the evidence does not independently establish the target ABI or the width of `int`. Pointer width is also not established. Consequently:

- The established interface is expressed in signed-`int` units.
- A binding that requires exact binary compatibility must establish integer width, pointer width, alignment, and calling convention separately.
- The literal factor four is established. It does not, by itself, establish the byte size of an integer object or any external element type.

**Preconditions for defined ordinary execution.**

- The other two pointer inputs must support integer writes.

No non-null checks, range checks, overflow checks, or pointer-validity checks are present. Null pointers are not optional-output markers.

## Behavior

### Value calculation

Let **base** denote the integer read from the current-value location at entry.

The displacement is formed by multiplying, in this grouping:

1. The third scalar factor by the second scalar factor.
2. That intermediate result by the first scalar factor.
3. That intermediate result by four.

The computed value is **base plus displacement**.

The grouping matters when considering overflow. It is not sufficient that the mathematical final result fit the integer range; each signed multiplication intermediate and the final addition must also be representable for the ordinary signed-integer interpretation to remain defined.

The arithmetic is integer arithmetic, not pointer arithmetic. The function does not read or write memory at an address derived from the computed value.

### Memory-access order

For executions with valid memory and defined arithmetic, the established logical access sequence is:

1. Read the integer at the current-value location.
2. Calculate the computed value from that saved integer and the three scalar factors.
3. Write the computed value to the updated-value destination.
4. Write the computed value to the current-value location.
5. Write the saved base to the previous-value destination.

There is no reread of the current-value location between the writes. In particular, an aliasing first write does not change the saved base or cause the arithmetic to be recomputed.

This sequence describes the function’s abstract behavior. It is not a guarantee of machine-instruction order, atomic publication, synchronization, or externally observable fault timing.

### Distinct destinations

When all three pointer inputs designate distinct integer objects, successful completion leaves:

- The updated-value destination containing the computed value.
- The current-value location containing the computed value.
- The previous-value destination containing the base read before either update.

Initial contents of the two output-only destinations do not affect the result.

### Aliasing

The final write takes precedence wherever destinations alias.

| Aliasing relationship | Final contents after successful completion |
|---|---|
| Updated-value destination equals current-value location; previous-value destination is separate | Shared object contains the computed value; separate object contains base. |
| Updated-value destination equals previous-value destination; current-value location is separate | Shared object contains base, overwriting its earlier computed value; current-value location contains the computed value. |
| Current-value location equals previous-value destination; updated-value destination is separate | Shared object ends with base, undoing its intermediate update; separate object contains the computed value. |
| All three designate the same object | The object ends with base. The two preceding writes of the computed value are overwritten. |

These cases concern pointers designating the same valid integer object. Arbitrary partially overlapping storage is not established as supported.

### Zero and negative factors

No branch treats zero or negative factors specially.

If any factor is zero and all arithmetic intermediates remain defined, the displacement is zero and the computed value equals base. The read and all three writes still belong to the specified behavior.

A zero appearing late in the multiplication grouping does not make an earlier overflowing intermediate valid. For example, a zero first factor does not eliminate the requirement that the preceding product of the third and second factors be representable.

Negative factors participate in signed multiplication. The function does not reject them, clamp the result, or enforce forward-only movement.

## Acceptance examples

These are conditional contract examples, not runtime test results. Each assumes valid integer objects, no conflicting concurrent access, and representable arithmetic intermediates.

### Distinct destinations and positive displacement

Given a base of 100 and first, second, and third factors of 2, 3, and 4:

- The displacement is 96.
- The computed value is 196.
- The updated-value destination and current-value location finish at 196.
- The previous-value destination finishes at 100.

Prior contents of the two output-only destinations do not change these results.

### Negative displacement

Given a base of 100 and factors of −2, 3, and 4, with distinct destinations:

- The displacement is −96.
- Both updated-value outputs finish at 4.
- The previous-value destination finishes at 100.

This establishes signed calculation, not a policy that the result must remain nonnegative.

### Zero displacement

Given a base of 37 and factors of 5, 0, and 7, with distinct destinations:

- All multiplication intermediates are representable.
- The computed value is 37.
- All three destinations finish at 37.
- The function still specifies all three writes; it does not take an early-return path.

### Previous-value destination aliases the current-value location

Given a base of 100, factors of 2, 3, and 4, and a separate updated-value destination:

- The separate destination finishes at 196.
- The shared current/previous location finishes at 100.
- Its write of 196 is overwritten by the final write of the saved base.

A contract that promises the current-value location always finishes with the computed value would be incorrect.

### All destinations alias

Given the same arithmetic inputs but a single shared integer object for all pointer inputs:

- The base is read before any write.
- The shared object receives 196 twice, then 100.
- Its final value is 100.

### Conditional 32-bit boundary

If the execution environment establishes 32-bit signed integers, a base of 2,147,483,643 with all three factors equal to one produces 2,147,483,647.

Under ordinary signed-integer semantics, increasing that base by one makes the final addition overflow. No wraparound result, diagnostic, or recovery behavior is specified here.
