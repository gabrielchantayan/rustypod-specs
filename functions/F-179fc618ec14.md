# F-179fc618ec14

## Purpose

F-179fc618ec14 conditionally copies a 16-bit value between computed addresses, may perform a second 16-bit update using a low-memory destination, and then enters an unconditional call-and-interrupt loop.

No application-level purpose is established. The supplied representation depends on incoming machine state and a stack-associated address in addition to its explicit argument. It does not establish a conventional function interface that can be invoked correctly using that argument alone.

This contract distinguishes:

- **Established static evidence:** operations, widths, and control-flow relationships visible in the supplied representation.
- **Conditional deductions:** consequences of interpreting word arithmetic and addresses as 32-bit quantities.
- **documented_only unknowns:** architectural, calling-convention, dependency, and execution details not established by the supplied material.

No runtime tests have been performed.

## Behavior

### Entry classification

The entry decision uses

\[
A=(P\cdot 2^{19})\bmod 2^{32}.
\]

Therefore,

\[
A=0\quad\Longleftrightarrow\quad(P\bmod 8192)=0.
\]

This is not simply a test for \(P=0\). Every argument whose low 13 bits are zero takes the zero-product path.

If \(A\neq0\), all conditional data-memory updates are bypassed. The function proceeds to the dispatch loop with initial base \(L\).

If \(A=0\), the initial halfword transfer occurs before the remaining eligibility decisions can enable the additional update.

### Initial halfword transfer

The destination is the numerical byte address

\[
D=(H+Y)\bmod 2^{32}.
\]

The observable memory order is:

1. Read an unsigned 16-bit value from address \(H\).
2. Write that value as 16 bits to address \(D\).

The displacement \(Y\) is measured in bytes. It is not multiplied by two when forming \(D\).

The source-derived address retained for subsequent comparisons is

\[
H'=(H+Y-Z)\bmod 2^{32}.
\]

This is internal address state, not a write to a caller-provided output parameter.

No readability, writability, alignment, range, or overlap check precedes the transfer. Source and destination may coincide. In particular, \(Y=0\) still describes a read followed by a write, rather than an omitted operation.

If the read faults, this transfer has not yet written its destination. If the write faults, the source read has already occurred. No rollback is specified.

### Eligibility for the additional update

Under the stated 32-bit model, reaching the additional update requires all of the following:

\[
P\bmod8192=0,
\]

\[
L=0,
\]

\[
S=0,
\]

\[
X=Y,
\]

\[
Y\in\{0,\;0x80000000\},
\]

\[
W=0,
\]

\[
H+Y=2Z\pmod{2^{32}}.
\]

These are eligibility conditions for the later update, not preconditions for the initial transfer. The transfer has already been attempted when these later conditions reject an invocation.

The simplification follows from several constraints in the displayed gates:

- The zero entry product forces the low 13 bits of \(P\), including bit 11, to zero.
- The other argument-derived products used by the gates consequently reduce to zero.
- Every executed shift in the eligibility chain has shift count zero because entry to each such gate requires the preceding tracked result to be zero.
- An early gate requires \(L=0\), followed by \(S\mathbin{\mathrm{>>}}1=0\). The latter initially permits only \(S=0\) or \(S=1\).
- The word comparisons require \(X=Y\) and \(H'=Z\). Substituting the definition of \(H'\) gives \(H+Y=2Z\) modulo \(2^{32}\).
- The addition involving \(W\) reduces to \(W=0\).
- The final zero-result addition requires \(S+2Y=0\) modulo \(2^{32}\). An odd \(S=1\) cannot satisfy this equation. With \(S=0\), the permitted values of \(Y\) are zero and `0x80000000`.

The relevant incoming carry is zero along this successful chain. No additional carry-dependent exception to the conditions above is established.

A nonzero ordinary stack address cannot satisfy \(S=0\). Whether a real invocation can present the required state is documented_only.

### Additional halfword update

If every eligibility condition holds and the initial transfer has completed, the representation displays these operations:

1. Assign a stack-address-derived value to an architectural-state location.
2. Derive an updated link-address value from \(L\) and \(S\).
3. Perform a halfword update whose destination and value are obtained through halfword references at \(L\).

The architectural-state assignment has numerical value

\[
64S\bmod2^{32}.
\]

The link-address derivation also adds \(64S\) bytes to \(L\), because its displayed halfword-pointer displacement is scaled by two.

Eligibility forces \(L=S=0\). Thus the architectural-state assignment is numerically zero, the updated link address remains zero, and the halfword references use numerical address zero.

For ordinary stable memory, let \(v\) be the unsigned halfword at address zero after the initial transfer. The additional update writes

\[
(v+15)\bmod2^{16}
\]

as a halfword at numerical address \(v\).

The destination is the zero extension of a 16-bit memory value. It is neither address \(L\) itself nor a pointer-width value loaded from \(L\). Its numerical range is 0 through 65,535.

The supplied expression contains repeated halfword references when forming the destination and stored value. It does not establish a unique machine-level order or count for those reads. Consequently, the stable-memory description must not be treated as an exact device-memory access trace. If separate reads can return different values, the destination and value need not derive from the same observed halfword.

The displayed architectural-state assignment precedes this update. Its architectural meaning, validity, and possible effects on execution remain documented_only.

### Exclusion of later conditional memory regions

The supplied representation includes further conditional arithmetic, loads, and multiword writes. They are unreachable under the 32-bit model used here.

The exclusion follows from the gates immediately after the additional update:

- Without that update, the flag enabling the following gate remains false.
- With that update, the tracked halfword address initially equal to \(A=0\) advances by one halfword, becoming numerical address two.
- Eligibility has already forced the other address used by the first following comparison to zero.
- The first comparison therefore succeeds, but the next comparison produces two rather than zero.
- That nonzero result prevents entry into all subsequent conditional memory regions.

Accordingly, the later apparent record writes and signed-halfword-derived stores are not included among reachable direct effects.

This is a deduction about the supplied representation under the stated model. It does not establish that an original executable intentionally contains dead code or that its machine execution must match every displayed construct.

### Dispatch loop

The initial dispatch base is \(L\). On the additional-update path, the displayed link-address adjustment leaves that value unchanged because eligibility requires \(L=S=0\).

Each iteration attempts, in order:

1. Call **F-INDIRECT-01** at the numerical code address equal to the current base plus `0xEB6` bytes, modulo \(2^{32}\). The three explicit 32-bit arguments are zero, zero, and `0xFFFFFFA5`.
2. If that call returns, call **F-INDIRECT-02** at numerical code address `0x0857A94B`. No explicit arguments are displayed.
3. If that call returns, issue **F-INTERRUPT-01**, software interrupt selector `0x5B`.
4. If execution resumes after the interrupt, replace the dispatch base with `0x083D4CC2` and repeat.

The first call uses a computed code address directly; the representation does not load its target from a table entry at that address.

The third explicit argument to F-INDIRECT-01 is unsigned 4,294,967,205, or −91 when interpreted as a signed 32-bit value. The callee’s interpretation is unknown.

After one completed iteration, every subsequent first-call target is `0x083D5B78`. The second-call address and interrupt selector remain fixed.

There is no displayed exit condition, delay, target validation, retry policy, or error recovery.

- The conditional memory regions are skipped.

### Additional update with stable low memory

Assume:

\[
P=8192,\quad L=S=W=0,
\]

\[
H=\texttt{0x80002000},\quad Z=\texttt{0x1000},
\]

\[
X=Y=\texttt{0x80000000}.
\]

The required address equality holds:

\[
H+Y=\texttt{0x00002000}=2Z\pmod{2^{32}}.
\]

Also, \(H'=\texttt{0x1000}=Z\). Thus all arithmetic eligibility conditions are satisfied.

Assume all addressed locations are valid stable ordinary memory and the architectural-state assignment permits execution to continue. Then:

- The initial transfer copies a halfword from `0x80002000` to `0x00002000`.
- If the halfword at address zero is subsequently `0x0020`, the additional update writes `0x002F` to address `0x0020`.
- The first dispatch target is `0x00000EB6`.
- No later conditional record-writing region is reached.

### Similar values that do not qualify

Retain the preceding example’s other inputs but set \(H=\texttt{0x1000}\).

Then

\[
H+Y=\texttt{0x80001000},
\qquad
2Z=\texttt{0x00002000}.
\]

These are unequal. The initial transfer is still attempted, now to `0x80001000`, but the additional update is skipped. A write of `0x002F` to `0x0020` is not supported by these inputs.

### Halfword overflow

If the additional update is eligible and stable memory at address zero contains `0xFFF8`, it writes `0x0007` as a halfword to numerical address `0xFFF8`, provided that destination is writable.

### Repeated dispatch

If both calls return and the interrupt resumes normally:

- The first iteration uses the incoming dispatch base.
- The second and subsequent iterations call F-INDIRECT-01 at `0x083D5B78`.
- Every iteration then calls F-INDIRECT-02 and issues interrupt `0x5B`, in that order.
