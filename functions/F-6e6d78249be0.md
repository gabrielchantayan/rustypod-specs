# F-6e6d78249be0

## Purpose

F-6e6d78249be0 performs ordered dispatch using an event record, a context object, direct handlers, and context-selected indirect callbacks.

Dispatch has five stages:

1. An optional preliminary notification.
2. Initial event-specific handling.
3. Intermediate handling or a terminal context-only action.
4. A general callback.
5. An optional final callback.

For every result-producing handler, zero means continue to the next applicable stage; a nonzero result is returned immediately. The context-only action instead causes a fixed return of 1.

The function rereads event and context fields at defined points rather than taking one immutable snapshot. A dependency that changes those fields can therefore change subsequent dispatch. Processing does not restart at an earlier stage after such a change.

These mechanics are supported by the supplied static representation. The application-level meanings of the event codes, context fields, and return values remain unknown.

## Interface

### Arguments and return value

The represented interface has three arguments:

| Argument | Established use |
|---|---|
| Context address | Identifies an object containing a dispatch-table address and 32-bit comparison or configuration fields. |
| Event address | Identifies a record containing a 32-bit event type and a 32-bit payload. |
| Third argument | An incoming 32-bit integer whose original value does not affect this function’s dispatch decisions. |

The return value is a 32-bit integer:

- A nonzero handler or callback result is returned unchanged.
- The context-only terminal action is followed by return value 1.
- If no selected result-producing call returns nonzero and no terminal action occurs, the result is 0.

Negative results are not distinguished from other nonzero results: they also terminate dispatch and propagate unchanged.

The original third argument is not passed to any dependency. On paths that use its working storage for a comparison, that storage has first been replaced with a context field. It is therefore not an independent selector.

## Behavior

### Preliminary notification

The first read obtains the event type.

If the type is 0x16, the function reads the payload as an address and then reads the 32-bit nested code at address +0x04. It issues a notification only when that code equals 0x2503.

The represented condition also tests that the code differs from 0x2502. Because the same already-read code must equal 0x2503, that exclusion does not add another effective case or another nested-code read.

For a qualifying event, F-154012b1fe61 receives:

- The context address.
- The context word at +0x11C converted to a character-sized value.

The configuration word is read only when the notification is selected. Its character conversion narrows the argument; the exact character width, signedness, and out-of-range conversion interpretation are not established by the supplied material.

The notification’s result is not inspected. A normal return always proceeds to initial handler selection. Any mutation performed by the notification can affect that selection because the event type is read again.

### Initial handler selection

A fresh event-type read determines this stage. At most one initial handler is selected.

| Event type | Direct dependency |
|---|---|
| 0x7F25 | F-797cea55670f |
| 0x7F26 | F-0a7f20df1ee8 |
| 0x7F27 | F-c6caa612109c |
| 0x7F28 | F-419055d1a52b |
| 0x7F29 | F-1b11e78559d0 |

Each receives the context and event addresses. A nonzero result terminates the function; zero proceeds to the intermediate stage.

For type 0x0F, selection instead follows two ordered comparisons:

1. Read the event payload, then the context word at +0xDC. Equality selects F-d877349ec46b.
2. Only if the first comparison fails, read the payload again, then the context word at +0xE4. Equality selects F-72986797cad8.

These dependencies also receive context and event and follow the nonzero-return rule.

The first matching comparison wins. Selecting F-d877349ec46b suppresses the second comparison and its handler even if the selected handler returns zero. When both context comparison words equal the payload, only F-d877349ec46b is selected here.

If neither comparison matches, or the event type has no initial handler, execution proceeds without an initial call.

### Intermediate selection and terminal action

This stage is reached only if initial handling has not returned a nonzero result. It begins with another event-type read.

Selection is ordered as follows:

1. **Type 0x0F matching context +0xB8.**  
   Read the payload and then the context word at +0xB8. Equality selects the indirect entry at dispatch-table offset +0x134.

2. **Otherwise, type 0x7F24.**  
   Invoke F-c6fc31cde97f.

3. **Otherwise, type 0x0F matching context +0xC4.**  
   Read the payload again and then the context word at +0xC4. Equality selects F-8ac0302a48ef.

4. **Otherwise.**  
   Proceed directly to general dispatch.

The +0x134 callback and F-c6fc31cde97f receive context and event. A nonzero result terminates dispatch; zero advances directly to the general callback.

F-8ac0302a48ef receives only the context. When it returns normally, this function returns 1 without invoking the general or final callbacks. Any value produced by that dependency is not used.

A +0xB8 match suppresses the +0xC4 comparison and action. Returning zero from the +0x134 callback does not reopen the intermediate selection. Likewise, returning zero from F-c6fc31cde97f proceeds to general dispatch rather than checking a newly mutated event for the terminal action.

### General callback

General dispatch begins with a fresh event-type read.

- For type 0x16, read the payload address and then its nested 32-bit code at +0x04.
- If that nested code is 0x2A, select dispatch-table entry +0x10C.
- For every other case reaching this stage, select entry +0x110.

The function reads the context’s dispatch-table address, obtains the selected entry, and invokes that target with context and event.

A nonzero result is returned immediately. Zero advances to the final stage.

This nested-code read is independent of the preliminary notification’s read. No saved preliminary code controls general dispatch. Changes made by earlier dependencies can therefore alter the general callback selection, including whether a nested dereference is required.

A non-0x16 event selects +0x110 without reading a nested code.

### Final optional callback

This stage is reached only after the general callback returns zero.

The function rereads the event type. If it is 0x0F, it reads the payload and then the context word at +0x50. Equality selects the indirect entry at dispatch-table offset +0xE0.

The selected callback receives context and event:

- A nonzero result is returned unchanged.
- A zero result leads to return value 0.

If the type or comparison does not qualify, the function returns 0 without this callback. There is no later fallback.

### Ordering and reread boundaries

A terminating result prevents all later-stage reads and calls.

Event types are reread between stages, but a type already obtained for a stage controls that stage’s selection. Payloads may be read more than once when ordered comparisons require them. The preliminary and general nested-code reads are also separate.

Each indirect invocation obtains its table address from the context when that invocation is selected. The function does not establish one table snapshot for all callbacks.

Mutation does not restart dispatch. For example, an initial handler that changes the event type and returns zero influences intermediate selection, not a second initial selection.

The representation establishes these control-flow and field-access relationships. It does not establish atomic reads, synchronization, memory barriers, or behavior under concurrent mutation.
