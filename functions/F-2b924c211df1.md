# F-2b924c211df1

## Purpose

F-2b924c211df1 searches a linked structure and produces a two-field result: a 32-bit word and a one-byte indication of whether an insertion-like dependency was called.

A container policy byte selects between two behaviors:

- **Nonzero:** search to a null link, then call the insertion dependency without an existing-entry check.
- **Zero:** perform additional boundary and comparison work that may return an existing cursor instead of calling insertion.

**Inferred intent:** ordered-tree insertion with optional duplicate suppression. Ordering, equivalence, balancing, allocation, and successful insertion are not established by this function alone.

This contract distinguishes observable operations from structural interpretations. Dependency names identify call targets, not guarantees about their behavior.

## Behavior

### Initial search

The last-comparison state initially holds a nonzero value.

The function performs these structural reads in order:

1. Read the container’s header pointer.
2. Read that header’s pointer at offset 0x04 as the initial search node.
3. Separately reread the container’s header pointer as the initial saved insertion candidate.

These are distinct header-field reads. A changing header field can therefore supply the search root from one header and the initial candidate from another.

For each nonnull search node:

- Two separate four-byte scratch words are cleared.
- F-a1e786bd6046 receives, in order:
  - The container address plus 0x19.
  - The supplied value.
  - The current node address plus 0x10.
- The current node becomes the saved insertion candidate.
- The comparison result determines the next link read: zero selects offset 0x0C; nonzero selects offset 0x08.

The child-link read occurs after the comparison returns. Dependency-mediated link changes can therefore affect the next search node.

Search ends upon a null selected link. An initially null root causes no search comparisons or scratch clearing. The initial nonzero comparison state and separately read header candidate remain in effect.

### Policy selection

After search termination, the function reads the byte at container offset 0x18.

A nonzero byte selects common insertion immediately. A zero byte selects the existing-entry decision process.

The policy is not captured before search. Changes made during search dependencies can affect this decision.

### Boundary decision under zero policy

The saved candidate is copied into a local, addressable cursor slot.

If the last search comparison was zero, the boundary call and cursor traversal are skipped. Execution proceeds to extraction and final comparison.

If the last search comparison was nonzero:

1. The container’s header pointer is reread.
2. The four-byte word at that header’s offset 0x08 is copied into one of the scratch words.
3. F-425cd6ff9d42 receives the address of the cursor slot and the address of that scratch word.

Both arguments identify writable local storage. The cursor value after this call need not equal the saved candidate.

A nonzero boundary result selects **early insertion**. F-117e11c4474b receives an output-word address, the container, a literal zero, the saved search candidate, and the supplied value. The output word is then copied to the result destination, followed eventually by status `1`. No cursor traversal, extraction, or final comparison occurs.

A zero boundary result selects the traversal below, starting from the cursor slot’s post-call value.

### Cursor traversal and distinct link reads

The traversal first reads the byte at cursor offset 0x00 and tests whether it is zero. That byte is zero-extended for the test; it is not used as a node address.

Only if the byte is zero does the function read the cursor’s pointer at offset 0x04, then read offset 0x04 through that pointer. If this second pointer equals the cursor, the cursor slot is replaced by the pointer at cursor offset 0x0C. This completes the traversal.

Otherwise, the traversal has two alternatives. Its repeated reads are significant:

- First, the pointer at cursor offset 0x08 is read and saved.
- Then, that same field is read again to decide between the upward and downward alternatives.

The second read determines the branch; the first value supplies the initial downward destination.

**Upward alternative:** if the second offset-0x08 read is null, the saved first value is discarded. The cursor’s offset-0x04 pointer supplies the initial parent-like object. At each upward step:

- That object’s offset-0x08 pointer is compared with the current cursor.
- The cursor slot is replaced by the parent-like object, whether the comparison succeeds or fails.
- Equality causes the traversal to continue using that object’s offset-0x04 pointer. Inequality ends traversal.

Consequently, the final cursor includes the parent assignment from the terminating, unequal step.

**Downward alternative:** if the second offset-0x08 read is nonnull, the cursor slot is replaced by the value saved from the first read. At each downward step:

- The pointer at the new cursor’s offset 0x0C is read and saved as a prospective next destination.
- The same offset-0x0C field is read again to determine whether to continue.
- A nonnull second read continues using the saved first value.
- A null second read stops with the current cursor retained.

The function does not reconcile disagreements between these paired reads. For example, a null first offset-0x08 read followed by a nonnull second read enters downward traversal with a null saved destination. Likewise, a null first offset-0x0C read followed by a nonnull second read can cause a subsequent null dereference. Conversely, a nonnull saved offset-0x0C pointer is not followed if the second read is null.

With stable links, these operations resemble predecessor traversal: enter one subtree and follow its opposite links, or ascend parents. That simplification is valid only when the relevant repeated reads agree. Stability is not established here.

### Extraction, final comparison, and escaped cursor storage

After boundary handling and any traversal, a separate four-byte local word is cleared. No subsequent read of that word is visible.

F-2abf4e01dbe2 receives the cursor value read for its argument. Its 32-bit result becomes the second argument to F-a1e786bd6046. The other arguments are the container address plus 0x19 and the original supplied value.

This differs from search comparison: search supplies the original value followed by a node-interior address; final comparison supplies the extractor’s result followed by the original value.

The local cursor slot may already have escaped through F-425cd6ff9d42. Nothing visible prevents that dependency from retaining its address or later dependencies from using such a retained address. Therefore distinguish:

- **Extraction-time cursor:** the word supplied to F-2abf4e01dbe2.
- **Output-time cursor:** the word read from the cursor slot after extraction and final comparison return.

Those words need not be equal. Neither extraction nor comparison is assumed to preserve the escaped slot.

If final comparison returns zero, the function reads the cursor slot at that point, writes that word to result offset zero, then writes status `0`. No insertion dependency is called.

If final comparison returns nonzero, execution selects common insertion.

### Common insertion and output storage

Common insertion is reached by nonzero policy or a nonzero final comparison.

F-117e11c4474b receives:

1. An address of four-byte local output storage.
2. The container address.
3. A literal zero.
4. The saved search candidate.
5. The supplied value.

Cursor adjustment does not replace the saved insertion candidate. An escaped cursor-slot mutation likewise does not, by itself, update that separate candidate.

After insertion returns, the output word is read and written to result offset zero. Status `1` is then written at offset four.

Early insertion and common insertion use different local output words. Both words are cleared on each nonempty search iteration. The common-insertion word is also the scratch word supplied to the boundary dependency after being populated from header offset 0x08. The early-insertion word is not initialized by that boundary preparation.

Thus, if insertion returns without writing its output:

- An empty-search, nonzero-policy common insertion has no established initialized output word.
- Empty-search early insertion likewise has no established initialized output word.
- Other paths can expose earlier scratch contents or dependency modifications rather than a meaningful insertion result.

No output-validity check is visible. Status `1` means the insertion dependency was called and returned along that branch, not that it allocated, mutated the structure, or created a new entry.

## Side effects

### Direct writes

Outside local storage, the function directly writes four bytes at result offset zero and one byte at result offset four, in that order.

It does not directly target container fields or node links for writing. If result storage aliases such fields, however, the result writes can modify them.

Bytes beyond result offset four are not directly written. Preservation against dependency-mediated writes requires an additional assumption.

### Dependency effects and ownership

Dependencies receive context, values, node-derived arguments, or local-storage addresses. Their global effects, callbacks, allocation, release, and ownership behavior are not established.

The function contains no visible allocation, deallocation, retain, release, or destruction operation. There is no established ownership or lifetime guarantee for either the supplied value or the returned word.

The boundary dependency receives addresses into this invocation’s local storage. Their escape does not extend that storage’s lifetime beyond the invocation. Behavior of retained addresses after return is not established.

### Failure and interruption

There is no explicit error handling or rollback. Invalid accesses, nonterminating traversals, dependency failures, and nonlocal exits have no defined recovery here.

Output is published only after the relevant dependencies return. A dependency can nevertheless mutate externally visible state before failing to return. The result pair is not a transaction boundary.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests.

### Nonzero policy

Given a terminating valid search and a nonzero policy byte when read, no boundary or extraction call occurs. Insertion receives the saved search candidate. If it writes a specified output word and returns, that word is published with status `1`.

### Empty search with early insertion

Given a null initial root, zero policy, and a nonzero boundary result, no search comparison occurs. The separately loaded header pointer is the saved candidate. Insertion receives that candidate, even if the boundary call changed the local cursor. A dependency-written output is published with status `1`.

### Existing-entry branch without boundary handling

Given a zero last search comparison and zero policy, boundary handling and traversal are skipped. The candidate initializes the cursor used for extraction. A zero final comparison selects status `0` and publication of the cursor slot’s output-time value. Equality with the extraction-time cursor requires preservation of that slot.

### Adjusted cursor with retained-address mutation

Given zero policy, a nonzero last search comparison, and a zero boundary result, traversal adjusts the cursor. Suppose extraction receives one cursor word, and the final comparison changes the escaped cursor slot through an address retained by the boundary dependency before returning zero. The published result is the changed slot value, not necessarily the extraction argument or traversal result.

### Disagreeing structural reads

Suppose traversal reaches the paired offset-0x08 reads. If the first yields one valid node and the second yields a different nonnull node, downward traversal starts at the first node. The second node only determines that the branch is nonnull.

During downward traversal, a saved nonnull offset-0x0C pointer followed by a null reread causes termination at the current cursor, without following the saved pointer.

### Insertion after cursor adjustment

Given a nonzero final comparison after traversal, insertion receives the original saved search candidate, not the adjusted or subsequently modified cursor slot. A dependency-written output is published with status `1`.

### Result-byte preservation

Given valid result storage and dependencies that do not modify it independently, the function overwrites offsets zero through four and leaves later bytes unchanged.
