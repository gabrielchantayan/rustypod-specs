# F-291aa4790762

## Purpose

F-291aa4790762 stores the low eight bits of an unsigned argument into a byte field of a caller-supplied object, then conditionally performs further state writes and invokes F-231941f10f3a.

The established behavior is narrower than a conventional “update if changed” operation:

- The initial byte store occurs before the eligibility check.
- Two fields are compared against reads made during this invocation, not against a separately supplied desired state.
- The stored argument byte is compared against the complete 32-bit argument, not merely its low eight bits.
- With stable ordinary memory, an eligible object and an argument from 0 through 255 produce return value 0 without invoking the dependency.
- With stable ordinary memory, an eligible object and an argument above 255 enter the additional-write path.

An interpretation as a state-change notification routine is inferred intent only. The supplied material does not establish field names, object type, or the meanings of its numeric status values.

## Behavior

### Initial effects and eligibility

The first visible operation stores the low eight bits of the unsigned input at offset +0x9B. This occurs for every invocation that reaches that operation, including invocations that subsequently return 6.

The function then reads the byte at +0x9A and retains its value for later comparison and possible restoration.

Only after those operations does it read the eligibility byte at +0x90:

- If the byte is zero, the function returns 6 immediately.
- If the byte is nonzero, processing continues.

Consequently, return value 6 does not mean “no state changed.” The +0x9B store has already occurred. The +0x9A read has also occurred, even though its captured value is unused on that return path.

### Comparison sequence

For an eligible object, the function next reads +0x99 and compares that value against another read of +0x99.

If those two readings differ, the combined comparison fails. The function does not perform the later comparison-stage reads of +0x9A or +0x9B.

If the two +0x99 readings agree, the function reads +0x9A again and compares this reading with the byte captured before the eligibility check.

If those +0x9A readings differ, the combined comparison fails, and the comparison-stage read of +0x9B does not occur.

If both preceding comparisons agree, the function reads +0x9B as an unsigned byte and compares it with the full unsigned input.

The last comparison is sensitive to width:

- The byte read has a numeric range of 0 through 255.
- The input has a numeric range of 0 through 4,294,967,295.
- An input above 255 cannot equal the unsigned-byte reading, even when that byte contains exactly the input’s low eight bits.

No masking of the input to eight bits is shown for this equality comparison.

If all three comparisons succeed, the function returns 0 without entering the additional-write path. In particular, it does not read +0x98 or +0x94 on that path.

### Additional-write path

Failure of any comparison causes the following operations, in order:

1. Read the current byte at +0x99 and write that reading back to +0x99.
2. Write the initially captured +0x9A byte back to +0x9A.
3. Store the low eight bits of the unsigned input at +0x9B again.
4. Read the dependency gate at +0x98.

The +0x99 write is not a restoration of the first comparison reading. It uses a new reading made on this path.

The +0x9A write has different semantics: it writes the value captured before the eligibility check. If that location has changed since the initial read, this write can overwrite the newer value.

These writes precede any dependency invocation. They also occur when the dependency gate is zero and no call is made.

### Dependency invocation and completion

If the dependency gate at +0x98 is zero, the function returns 0 after the additional writes.

If it is nonzero, the function reads the four-byte value at +0x94 and calls F-231941f10f3a with that value as its sole visible argument.

- A zero dependency result produces return value 0.
- A nonzero dependency result produces return value 7.

The dependency result is treated only as zero versus nonzero; it is not forwarded unchanged.

No object-field read, restoration, retry, or explicit rollback is shown after the dependency returns. The supplied function therefore does not undo its preceding writes when returning 7. Any changes made by the dependency itself are outside the established direct behavior.

### Stable-memory consequence

For ordinary memory that is not changed externally during the invocation:

- The two +0x99 readings agree.
- The two +0x9A readings agree.
- The +0x9B reading equals the low eight bits just stored.

Under those conditions, an eligible invocation enters the additional-write path exactly when the input exceeds 255.

This consequence does not require the object’s incoming +0x9B byte to match the input. The incoming byte is overwritten before any comparison of that field.

These examples are conditional specifications, not executed tests. Unless stated otherwise, assume valid ordinary storage, no external changes during the invocation, and normal completion of every executed operation.

- The result is 6.

- The dependency gate is not read, even if its stored value is nonzero.

- Input 256 stores zero at +0x9B but compares that zero against 256, so it takes the additional-write path.

- The additional +0x99 and +0x9A writes occur.
- F-231941f10f3a receives the four-byte value read from +0x94.

Under the same conditions, if F-231941f10f3a returns zero, the outer result is 0. The additional writes and dependency invocation still occurred.
