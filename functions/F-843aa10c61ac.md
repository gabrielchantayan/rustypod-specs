# F-843aa10c61ac

## Purpose

F-843aa10c61ac selects one of two initialization sequences using the zero/nonzero result of F-30953398b064, performs path-specific dependency calls and memory writes, and returns a pointer.

The zero-result path returns the pointer obtained from F-1c551e4bc8d8. The nonzero-result path obtains a second pointer from F-e194f3fbdfaa, passes addresses derived from that pointer to F-793b94643d2e, and returns an address 132 bytes before that second pointer.

**Established static evidence:** branch selection, explicit dependency-call order, argument values, memory-access widths and offsets, three distinct global word sources, and return-address calculations.

**Inferred intent:** the sequences resemble initialization of two related object forms, with additional embedded-structure initialization and registration on the nonzero path. These interpretations do not establish allocation, construction, registration, or ownership contracts.

**Unknown:** field meanings, dependency semantics, relationships among returned addresses, storage ownership, and failure behavior beyond the visible absence of checks.

## Interface

### Input

The function accepts one opaque 32-bit value.

- On the nonzero path, it passes this value unchanged as the third argument to F-8e605db71b8f.
- On the zero path, no visible operation uses the value.
- This function does not directly dereference, validate, transform, or release the input.

Whether the value represents an integer, address, handle, or another representation is documented_only. Any use or retention by F-8e605db71b8f is also documented_only.

### Output

The function returns a pointer in the apparent 32-bit address model of the supplied representation.

- **Zero path:** exactly the pointer returned by F-1c551e4bc8d8.
- **Nonzero path:** the pointer returned by F-e194f3fbdfaa minus 132 bytes.

There is no explicit status result, error return, or null-return branch. This does not establish that every execution returns a valid pointer.

The displayed pointer arithmetic uses four-byte elements. All offsets in this contract are expressed in bytes after accounting for that element width.

### Preconditions for normal completion

Normal completion requires dependencies to return normally and every explicit memory access to address valid storage for its stated width.

The applicable requirements are:

- On either path, the initial pointer from F-1c551e4bc8d8 must permit a four-byte write at offset 0 and a one-byte write at offset 112.
- On the nonzero path, that initial pointer must additionally permit a one-byte write at offset 113.
- On the nonzero path, the result of F-8e605db71b8f must permit a four-byte write at offset 12.
- On the nonzero path, the secondary pointer from F-e194f3fbdfaa must permit four-byte writes at offsets 0 and 20 and a one-byte write at offset 16.
- There are **three distinct global word sources**. On the zero path, the zero-path source must be readable for four bytes at its read step. On the nonzero path, the extended initial source and extended secondary source must each be readable for four bytes at their respective read steps.
- Addresses supplied to dependencies must satisfy those dependencies’ actual requirements. Those requirements are not supplied.
- Address calculations must be meaningful in the execution environment. Boundary, overflow, and invalid-pointer behavior are not established.

The global-read requirements apply when the reads occur, not merely at function entry. Earlier dependencies may alter global values or their accessibility.

No visible checks enforce these preconditions. A dependency may also invalidate storage previously obtained; preservation of storage validity across calls is not established.

## Behavior

### Selection

The first visible operation is a call to F-30953398b064 with no explicit arguments.

- A zero result selects the shorter sequence.
- Any nonzero result selects the extended sequence.

The selector is evaluated once. The function does not visibly reconsider its branch after subsequent dependency calls or external-state changes.

### Zero-result sequence

The following observable operations occur in order:

1. Call F-8157a180d901 with the value 116.
2. Call F-1c551e4bc8d8 with no explicit arguments and retain its returned pointer as the initial base.
3. Read the four-byte word from the zero-path global source and store that word at offset 0 from the initial base.
4. Store one zero byte at offset 112 from the initial base.
5. Call F-ea67aeaf4d96 with no explicit arguments.
6. Return the retained initial base.

Results from F-8157a180d901 and F-ea67aeaf4d96 are not visibly used.

The function itself writes only offsets 0–3 and offset 112 on this path. It does not explicitly clear offset 113, intervening bytes, or any remaining storage.

F-ea67aeaf4d96 runs after both stores. Its effects are unknown, so the stored values are not guaranteed to remain present at return. If execution reaches the return, the returned address is nevertheless the address retained from F-1c551e4bc8d8; validity of the storage at that point is a separate, unresolved matter.

## Acceptance examples

The following are conditional static acceptance examples, not executed tests. Each assumes normal dependency returns and valid storage for all operations it requires.

1. **Zero selection.**  
   With a zero selector result, F-8157a180d901 receives 116. The function reads the zero-path global source, writes its four-byte value at the initial base, clears the single byte at offset 112, calls F-ea67aeaf4d96, and returns the initial base. Neither extended-path global source is explicitly read.

2. **Any nonzero selection.**  
   Selector results of one and another nonzero value select the same sequence. F-8157a180d901 receives 156, and F-8e605db71b8f receives the original input unchanged in its third argument.

3. **Distinct address results.**  
   Suppose the initial base is 4096, F-8e605db71b8f returns 8192, and F-e194f3fbdfaa returns 12288. The extra four-byte clear targets 8204, and F-e194f3fbdfaa receives 8208. F-793b94643d2e receives 12272 and 12284 in its second and fourth argument positions. The function returns 12156, not 4096.

4. **One-byte clearing.**  
   If initial-base offset 113 contains a nonzero byte, the zero path does not itself change that byte. It remains unchanged only if no dependency or aliased write changes it. The nonzero path explicitly clears both offsets 112 and 113 using separate one-byte stores.

5. **Path-specific global readability.**  
   A zero-path execution requires the zero-path source to be readable at its read step; it does not require the two unused extended sources to be readable for this function’s explicit operations. A nonzero execution requires both extended sources to be readable at their separate read steps; it does not explicitly read the zero-path source.

6. **Global mutation between calls.**  
   If F-e194f3fbdfaa changes the extended secondary global word before returning, the following store uses the value read after that return, not a value assumed from function entry. The same timing rule applies to each other applicable global source.

7. **Mutation after initialization.**  
   If F-ea67aeaf4d96 changes the initial storage, the function does not restore the earlier values. On the nonzero path, changes by F-8f6053ffecbf or F-793b94643d2e are likewise not followed by restorative writes.

8. **Invalid address result.**  
   An unusable address result does not trigger a visible clean-null-return or rollback path. Any requirement for such recovery would exceed the supplied evidence.
