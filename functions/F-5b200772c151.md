# F-5b200772c151

## Purpose

F-5b200772c151 performs an ordered sequence of memory mutations using two explicit inputs and three additional entry-state values, then invokes an unresolved indirect target with four arguments.

The supplied static representation establishes low-level accesses, not a reliable application-level purpose. It does not establish that the affected regions are objects, that the stores initialize a valid structure, or that the indirect invocation represents successful completion.

This contract distinguishes:

- **Static evidence:** accesses and data dependencies visible in the supplied representation.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** unresolved behavior requiring additional evidence.

No runtime tests have been performed.

## Behavior

### Widths and arithmetic

A byte means 8 bits; a halfword means 16 bits; a word means 32 bits.

Byte stores retain the low eight bits of their source. Thus, using X or Y as a byte source does not store the full address-sized value.

Let:

- **x-byte** mean the low eight bits of X.
- **y-byte** mean the low eight bits of Y.
- **D** mean twice X, reduced to 32 bits.

Unsigned doubling of X is a 32-bit operation. D is not a checked mathematical address and is not guaranteed to point within any allocation.

Offset calculations involving values represented as signed integers introduce a separate uncertainty: the supplied representation does not establish the intended overflow semantics for those expressions. Address wraparound and signed-overflow behavior must not be generalized from the unsigned doubling operation.

Word and halfword stores use the target’s memory byte order. That byte order is not supplied.

### Initial mutation phase

The first visible memory effect is a word store of V at B + 0x54.

The function next establishes two byte relationships:

- Y + 0x19 receives x-byte.
- X + 0x11 receives y-byte.

It then stores B as a word at Y + 0x34.

A long, fixed sequence of repeated writes follows. Its recurring observable pattern is:

| Relative order within a repetition | Destination | Width | Value |
|---:|---|---:|---|
| 1 | D + 0x54 | 32 bits | V |
| 2 | Y + 0x19 | 8 bits | x-byte |
| 3 | X + 0x11 | 8 bits | y-byte |
| 4 | Y + 0x34 | 32 bits | D |

The supplied representation shows repeated occurrences without an intervening condition, address advance, or memory read. This is not evidence of an array traversal. The writes repeatedly target the same computed locations.

For ordinary non-overlapping memory, repetitions after the first do not change the resulting values. They remain relevant to an access trace, memory-mapped devices, fault timing, and overlapping destinations. Exact repetition multiplicity is **documented_only** in this contract; no exact total-access-count acceptance claim is made.

In particular, the initial B stored at Y + 0x34 is subsequently replaced by D, unless overlapping writes alter the interpretation of that location.

### Capture and mutation phase

After the repeated prefix, the function captures a word from G-source and a word from V + 0x74, in that order.

It then writes a derived byte to G-derived. The intended byte-level result visible in the expression is twice x-byte plus 0x30, reduced to eight bits. Whether the intermediate character is treated as signed does not change that low-byte result under the represented byte truncation.

Next, it captures:

1. A word from Z + 0x14.
2. A word from X + 0x04.

These captured words remain the sources for later operations even if their original memory locations are overwritten.

The following effects then occur in order:

- Z + 0x0D receives x-byte.
- X + 0x08 receives 0x6C.
- X + 0x0D and then X + 0x09 receive y-byte.
- Z + 0x54 receives Z as a word.
- G-stage receives the low byte of the earlier G-source capture.

The function then reads a word from Z + 0x44; call this captured value **T**.

G-copy receives the byte read from G-stage. This is a memory read of G-stage, not a guaranteed substitution of the earlier captured byte: aliases or external memory behavior can distinguish the two.

Next:

- X + 0x10 receives the low byte of T.
- Y + 0x54 receives T as a word.
- Z + 0x01 receives the low byte of a right-shifted T.
- Y + 0x54 receives X as a word, replacing the preceding word store when the accesses refer to ordinary memory.

The shift count is the low eight bits of X. The shifted operand is represented as signed. Counts of 32 or greater, and right shifts of negative values, are **documented_only** beyond the visible expression; the contract does not assume a processor-specific count mask or a particular signed-shift rule.

The function next captures a word from X + 0x40. It then:

- Writes the previously captured word from X + 0x04 to Y + 0x74.
- Writes the capture from X + 0x40 as a word at X + 0x10.
- Writes Z as a word at Y + 0x44.
- Reads G-stage and writes that byte at X + 0x09.
- Writes x-byte at Z + 0x09.
- Writes the original G-source capture as a word at X + 0x44.

The word store at X + 0x10 covers offsets 0x10 through 0x13. It can therefore replace the earlier byte stores at X + 0x10 and X + 0x11. Their final byte values depend on byte order and subsequent aliases; they must not be treated as independently preserved fields.

### Pointer-derived tail

The next word read is from X + 0x54. Call its captured value **P**. It is the value present at that time, after all preceding writes.

The function then:

- Reads G-stage again and writes that byte to X + 0x09.
- Writes the low byte of the earlier V + 0x74 capture to P + 0x0D.
- Restores Z + 0x54 from the previously captured Z + 0x14 word.
- Captures a word from X + 0x14; call it **U**.
- Writes the low byte of the V + 0x74 capture to Z + 0x11.
- Writes the low byte of P to X + 0x09.
- Writes P as a word at X + 0x44.

It next reads a word from Z + 0x04; call this **Q**.

A halfword containing 0x0065 is written at twice Q. The supplied representation uses signed arithmetic for this doubling; overflow behavior is not established.

Only after that halfword store does the function read a word at Q + 0x64. Call this **R**. Aliasing can make R depend on that preceding store.

The remaining memory effects and reads have this order:

1. P + 0x11 receives the low byte of U.
2. P + 0x54 receives the word value 100.
3. A word is captured from Q + 0x74; call this **W**.
4. A word is captured from Z + 0x64; call this **S**.
5. Z + 0x09 receives the low byte of Q.
6. S + 0x54 receives R as a word.
7. Twice R receives S as a word.

The final doubling is also represented as signed arithmetic, with unresolved overflow behavior.

### Final invocation

The function invokes an unresolved indirect target with these four arguments, in positional order:

| Position | Value |
|---:|---|
| 1 | 0x72 |
| 2 | R |
| 3 | The word captured earlier from Z + 0x14 |
| 4 | W |

No target result is visibly consumed. No further memory operation is visible after the invocation.

## Side effects

The function mutates caller-addressed memory, memory reached through loaded values, and fixed-address storage. It provides no visible transaction boundary or rollback.

If an access fails, earlier successful writes may already have changed state. There is no established recovery behavior or promise that the indirect target is reached.

Aliasing is material throughout:

- A destination may overlap a later read source.
- Byte writes may alter part of a later pointer-sized read.
- Word writes may replace multiple earlier byte writes.
- Computed addresses may coincide with fixed-address storage.
- Distinct contract names do not imply distinct allocations.

For these reasons, final-state formulas that assume disjoint regions are conditional, not universal.

No allocation or release operation is explicitly visible before the final invocation. This establishes neither ownership transfer nor lifetime safety. Ownership, retention, release, and further mutations by the unresolved target are unknown. The target must not be assumed to preserve globals or any affected region.

Concurrency guarantees, atomicity, memory barriers, and device-access semantics are not established. The ordering described here is the ordering in the supplied static representation, not a verified hardware trace.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Distinct valid regions

Assume all accessed regions are valid, non-overlapping, ordinary memory; arithmetic is representable where signed operations occur; and the indirect target returns normally.

The initial prefix must leave:

- V at B + 0x54.
- V at D + 0x54.
- x-byte at Y + 0x19.
- y-byte at X + 0x11.
- D at Y + 0x34.

These are prefix observations, not unconditional final-state claims. Later writes include a word store covering X + 0x11.

### Byte truncation

If X has low byte 0xE3, each prefix byte store to Y + 0x19 uses 0xE3, not the full X value.

Under the represented eight-bit reduction, G-derived receives 0xF6 because twice 0xE3 plus 0x30 has low byte 0xF6. This example does not authorize an otherwise invalid shift count or address.

### Captured value survives source replacement

Assume Z + 0x14 initially contains a word H and no preceding alias changes it before its capture.

The later store to Z + 0x54 uses H, and the third indirect-call argument is H. Neither use requires re-reading Z + 0x14.

### Transient write remains observable

Under distinct ordinary-memory destinations, Y + 0x54 receives T and later X.

An observer recording accesses must distinguish those stores. A final-memory-only observer sees X there, subject to later aliasing. An implementation that promises access-trace equivalence cannot simply omit the T store.

### Tail alias affects a later read

If the halfword destination at twice Q overlaps Q + 0x64, the captured R must reflect the memory state after the halfword write, according to target byte order and access semantics. Using a value read before that write would violate the represented ordering.

### Unresolved shift boundary

If x-byte is 32 or greater, no portable shifted-byte result is accepted by this contract. That case is **documented_only**, not an implicit request to mask the count.
