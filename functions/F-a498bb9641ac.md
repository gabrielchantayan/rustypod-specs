# F-a498bb9641ac

## Purpose

F-a498bb9641ac performs two passes over item references, counts qualifying items in the first pass, requests storage sized from that count, and writes qualifying references during the second pass.

The passes use different enumeration dependencies. Only the first pass makes conditional per-item calls. The function does not establish that the passes encounter the same items, use the same order, or produce the same number of qualifying items.

The destination reference is recorded in the supplied context. This establishes where the result is stored, not who owns or must release its storage.

All behavior below derives from static evidence. Dependency semantics and application-level intent remain separate from directly observable operations.

## Interface

### Input and layouts

The function accepts one context address in a 32-bit address model. It performs no entry validation.

| Context-relative offset | Width | Observed role |
|---|---:|---|
| `0xF60` | 32 bits | Collection reference, read repeatedly |
| `0xF6C` | 32 bits | Destination reference, replaced with the storage dependency’s result |
| `0xF70` | 32 bits | First-pass count, reset and conditionally incremented |

When obtaining the indexed bound, a collection reference is dereferenced at offset `0x30` for a signed 32-bit value.

Each processed item has the following accessed fields:

| Item-relative offset | Width | Observed role |
|---|---:|---|
| `0x40` | 32 bits | Associated-record reference |
| `0x18C` | 8 bits | Flag byte tested against `0xC0` |
| `0x1A8` | 32 bits | Eligibility mask |
| `0x1AC` | 8 bits | Alternative captured flags and first-pass action trigger |

The associated record is accessed at offset `0x2E` for an unsigned 16-bit **record value**. No domain meaning is established for this value.

All destination entries are four-byte item references. Item records themselves are not copied.

### Return value

The return is a 32-bit status:

- `0xFFFFFF94`, equivalent to signed `−108`, if F-f195b74c9758 returns zero.
- Zero if that dependency returns nonzero and the indexed phase completes normally.

The status does not report the number of entries written. No separate status handles inconsistent enumeration, arithmetic overflow, invalid memory, or an insufficient destination.

### Preconditions for memory-safe completion

The function does not enforce the following requirements:

- The context must support all stated reads and writes.
- Each processed item must support the field reads performed on its path.
- Each associated-record reference actually dereferenced must support the two-byte read at `0x2E`.
- Indexed lookups must return usable nonzero item references. Item fields are read before the later nonzero eligibility condition.
- The collection reference used for the indexed-bound dereference must remain valid, including across the two distinct context-field reads described below.
- Count, size, and destination-offset arithmetic must be suitable for the actual memory supplied.
- Destination storage must accommodate every qualifying item encountered during the indexed pass.
- Dependencies must not invalidate memory before subsequent accesses that require it.

The context’s collection field need not be nonzero at entry for execution to begin: its value is passed directly to the initial traversal dependency.

## Behavior

### Count reset and traversal

The first direct state change is a four-byte zero write to context offset `0xF70`.

The function then reads the collection reference at `0xF60` and passes it to F-65fe7bd54a4b. A zero result ends the first pass. Each nonzero result is processed as an item.

After processing an item, the function calls F-986cc6891b07 with that item reference. The returned reference becomes the next traversal result. This continues until a zero result is obtained.

No collection-length read or direct iteration limit bounds this traversal.

### First-pass flag reads and conditional calls

For each traversal item, the function first reads the byte at item offset `0x18C` and captures whether its `0xC0` bits are both clear.

- If either bit is set, that byte remains the captured flag byte.
- If both bits are clear, the function reads the byte at `0x1AC` and uses it as the captured flag byte instead.

Both the high-bit decision and the selected flag byte remain captured for the later eligibility decision. They are not refreshed after dependency calls.

The function then performs two further byte reads at `0x1AC`:

1. An unconditional read whose value does not supply the eventual record-value test for a normal nonzero traversal item.
2. A separate read whose bit `0x01` controls the conditional calls.

If the second of these reads has bit `0x01` set, the function calls:

1. F-8b9bcb0f31ce with the item reference and zero.
2. F-79349ab3b643 with the item reference.

These calls occur before the remaining eligibility reads. They are not suppressed because the captured `0x18C` condition already fails, because the record value will be zero, or because the mask will reject the item.

The return from F-79349ab3b643 is superseded by the associated-record value for a nonzero traversal item. Its side effects remain observable.

Separate reads of `0x1AC` need not observe the same value under mutation. In particular, the captured flags and the action-trigger decision are not a single snapshot.

### First-pass eligibility and count update

After any conditional calls, the function reads the item’s associated-record reference at `0x40`, then reads the unsigned 16-bit record value at associated-record offset `0x2E`.

It next evaluates the eligibility-mask condition:

- Read the 32-bit mask at item offset `0x1A8`.
- If that read is zero, the mask condition passes without another mask read.
- Otherwise, read the mask again and require at least one bit from `0x62`.

An item qualifies only if all of the following hold:

- The mask condition passes.
- The item reference is nonzero.
- The record value is nonzero.
- The captured `0x18C` high-bit decision passed.
- Neither bit `0x10` nor bit `0x20` is set in the captured flag byte.

For a qualifying item, the captured flag byte necessarily came from `0x1AC`. Its forbidden bits can therefore be summarized as `0x30`, but this does not eliminate the separate `0x18C` requirement.

A zero mask passes. A stable nonzero mask with no `0x62` bits fails. If the mask changes between reads, the first read determines whether the second is performed; the second determines the intersection result when required.

For each qualifying item, the function reads the current count from context offset `0xF70`, adds one, and writes it back. It does not maintain a separate authoritative count immune to dependency changes to that field.

The record access precedes the mask test. A rejecting mask therefore does not protect an invalid associated-record reference from being dereferenced.

### Storage request and failure

After traversal ends, the function reads the current context count and forms the size argument by shifting that 32-bit value left by two. This expresses four bytes per counted item within the represented arithmetic.

It calls F-f195b74c9758 with that size and writes the returned 32-bit value to context offset `0xF6C`, replacing the previous destination reference.

The replacement occurs even if the result is zero.

If the result is zero, the function returns `0xFFFFFF94` immediately. No indexed-bound read or indexed lookup follows. Earlier writes and dependency effects are not rolled back.

There is no zero-count special case. A count of zero still causes a zero-size request. A zero result fails; a nonzero result proceeds.

No visible release operation accompanies replacement of an existing destination reference.

### Indexed-bound acquisition: two distinct collection reads

Following a nonzero storage result, the indexed phase begins with output position zero and an initial bound of zero.

The function first reads context offset `0xF60` solely for a nonzero check.

- If this first read is zero, the bound remains zero. There is no second collection-field read for bound acquisition and no collection-length dereference.
- If this first read is nonzero, the function reads context offset `0xF60` again. It uses this second value as the collection address for the signed 32-bit read at offset `0x30`.

There is no additional null check on the second value.

Thus the checked reference and dereferenced reference are not necessarily identical. If the context field changes between reads, the length can be read from another collection. If the second read becomes zero, the function still attempts the offset-`0x30` access; it does not convert that case into an empty indexed phase.

Only the resulting signed bound is captured once. It is obtained after F-f195b74c9758 returns and need not describe the collection used by the first pass.

A zero or negative bound produces no indexed lookups.

### Indexed filtering and destination writes

For each signed index beginning at zero and less than the captured bound, the function calls F-3218115b204e with:

- A freshly read collection reference from context offset `0xF60`.
- The current index.
- A third argument of one.

The collection is read again for every lookup. It is not fixed to either reference involved in bound acquisition.

For each returned item, the function captures the `0x18C` condition and, when appropriate, the `0x1AC` byte using the same selection rule as in the first pass.

It then reads the associated-record reference and unsigned 16-bit record value when the item reference is nonzero. The mask reads and final eligibility requirements are the same as in the first pass.

This phase does not perform the first pass’s additional `0x1AC` reads for action triggering and does not call F-8b9bcb0f31ce or F-79349ab3b643.

A zero lookup result is not safely skipped: the initial flag read already accesses an item-relative address before the explicit nonzero condition, and the mask evaluation also precedes that condition.

For every qualifying item, the function reads the current destination reference from context offset `0xF6C` and writes the four-byte item reference at four times the current output position. That position advances by one. Rejected items consume no destination slot.

Writes preserve the encounter order of qualifying indexed results. Because the destination field is reread for each write, mutation of that field can redirect later entries.

The function does not update the context count to the actual number written, compare those quantities, initialize unused slots, or append a terminator. It returns zero after the indexed loop completes.

## Side effects

The directly established writes are:

1. Resetting the context count.
2. Incrementing that count for qualifying first-pass items.
3. Replacing the destination field with the storage dependency’s result.
4. Writing qualifying second-pass item references into destination slots.

Dependencies may produce additional effects. Their preservation of context fields, item fields, collection state, globals, or memory lifetime is not established.

Failure is nontransactional. Allocation failure leaves the destination field zero and does not itself undo the first-pass count or earlier per-item effects.

There is no visible retain, reference-count increment, release, or ownership-transfer operation associated with storing item references. Whether replacing old destination storage leaks memory depends on unavailable ownership and dependency contracts.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Except where stated otherwise, referenced memory is valid, relevant state remains stable, and arithmetic and destination capacity are adequate.

### One qualifying item

Both enumerations produce one item with clear `0xC0` bits at `0x18C`, clear `0x30` bits in the captured `0x1AC` byte, nonzero record value, and zero eligibility mask.

The count becomes one. The size request is four bytes. A nonzero storage result permits the item reference to be written in the first slot, followed by status zero.

### Stable mask boundaries

With the other conditions satisfied, masks `0`, `0x02`, `0x20`, and `0x40` pass. Mask `0x01` fails.

If an initial nonzero mask read is followed by a second read containing `0x02`, the mask condition passes regardless of whether the initial value contained that bit.

### Conditional calls despite rejection

An item has `0x80` at `0x18C`, while the action-trigger read at `0x1AC` has bit `0x01` set.

Both conditional dependencies are called in order. The item still fails the captured high-bit condition.

### Captured flags survive later mutation

The captured `0x1AC` byte is `0x11`, and the action-trigger read causes both conditional calls. Those calls clear bit `0x10` in memory.

The item still fails this pass’s captured-flag test. Conversely, a record value changed by these calls is read afterward and can affect eligibility.

### Empty first traversal

The initial traversal dependency returns zero without modifying the count. The storage request is zero bytes.

A zero storage result returns `0xFFFFFF94`. A nonzero result proceeds to bound acquisition; an empty first traversal alone does not imply zero indexed results.

### Different checked and dereferenced collections

The first `0xF60` read during bound acquisition observes a nonzero reference to collection A. The second observes a valid reference to collection B.

The bound is read from B at offset `0x30`, not from A. Later lookups use their own fresh collection-field reads.

If the second read instead observes zero, there is no second null guard. Safe empty-loop behavior must not be assumed.

If the first read observes zero, the bound remains zero even if the field becomes nonzero afterward.

### Nonpositive bound

The acquired signed bound is zero or negative. No indexed lookup occurs, and the function returns zero after the nonzero storage result.

### Pass disagreement

The first pass counts two items, but the indexed phase writes one. The count remains two absent dependency mutation, and the unused slot is not initialized by this function.

If indexed filtering produces more entries than the destination can hold, no internal capacity check prevents an out-of-bounds write.

### Storage failure

F-f195b74c9758 returns zero. The destination field is overwritten with zero, no indexed lookup occurs, and the function returns `0xFFFFFF94`. Prior effects remain.

## Uncertainties

### Inferred intent

The count-derived size and four-byte writes suggest construction of an allocated array of qualifying item references. The first-pass conditional calls may prepare item state. Neither interpretation establishes ownership or application semantics.
