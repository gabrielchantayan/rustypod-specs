# F-b3217e1f8522

## Purpose

F-b3217e1f8522 has a recovered execution path that performs two ordered byte writes, then repeatedly issues a coprocessor-directed operation without a visible normal exit.

The first write transfers the low byte of an incoming register value to an address derived from another incoming register. The second writes zero to an address derived from the same value used as the first write’s data. A related arithmetic result supplies the first coprocessor operation’s data operand. Subsequent iterations supply zero.

No higher-level purpose is established. Initialization, device control, or entry into a persistent hardware state are possible interpretations, not behavioral guarantees. In particular, the operation must not be described as a conventional buffer update, cache operation, synchronization primitive, or shutdown routine without additional evidence.

The available representation carries explicit warnings about invalid instruction data and removed unreachable regions. This contract therefore distinguishes the visible recovered path from claims about the complete original execution.

## Behavior

### Ordered byte writes

The first visible memory effect is a one-byte write at the address four bytes beyond the incoming base address. The stored data is the low byte of the incoming register 4 value.

Only that byte is explicitly written. There is no visible read of the destination and no explicit write of neighboring bytes. The signedness of a plain character does not change the low-eight-bit pattern transferred under the conventional 8-bit interpretation.

The function then derives an unsigned working quantity by multiplying the register 4 value by 1,024 and subtracting 104.

Next, it writes one zero byte at an address obtained by multiplying the same register 4 value by 1,024 and subtracting 94.

Consequently, under a common machine-width arithmetic interpretation, the second destination is ten bytes above the value represented by the working quantity, with any address-width wrapping taken into account. This arithmetic relationship does not establish that either value identifies an allocated object.

The two writes are ordered in the recovered path: the incoming low byte is written first; zero is written second. If the destinations alias, the zero write follows the data write. This distinction may matter even when ordinary RAM ultimately contains only the second value, because a device-mapped destination may observe both transactions.

No explicit memory read is shown between the writes.

### First coprocessor operation

After the second byte write, the function logically shifts the unsigned working quantity right by 11. It then sets that working quantity to zero before issuing the coprocessor-directed operation.

The first operation therefore receives:

- The shifted arithmetic result as its data operand.
- Fixed selector values 8, 5, and 4 in their displayed operand positions.
- The two additional coprocessor-associated values obtained from entry state.

The evidence establishes the operand values and their order within the recovered operation. It does not establish the architectural meanings of the selectors or additional operands.

The working quantity is cleared before this operation is issued, not after it returns. That ordering is part of the visible local-state behavior, although the local state’s observability during a fault or interruption is unknown.

### Subsequent iterations

If the coprocessor operation completes and execution follows the displayed loop:

- The next shifted data operand is zero.
- The working quantity is again set to zero.
- Another operation is issued with the same fixed selectors and the same represented additional operands.

This repeats without a visible termination condition.

The byte writes are outside the loop and are not repeated by its visible back edge. The first arithmetic data operand is not recalculated from the original input on every iteration.

The recovered representation reuses the two coprocessor-associated entry values. It does not show explicit updates to them. This is not a guarantee that the coprocessor operation preserves physical registers, globals, memory, or other processor state.

### Failure boundaries

The ordering determines which effects may already have occurred when execution is interrupted:

- If the first write faults, no later effect is established.
- If the second write faults, the first write has already been attempted and may have taken effect.
- If the first coprocessor operation faults, both byte writes precede that operation in the visible path.
- If a later coprocessor operation faults, at least one earlier coprocessor operation has been issued.

There is no visible rollback, retry handler, error return, or cleanup path. Whether a particular faulting operation partially takes effect is architecture- and device-dependent.

## Acceptance examples

These examples are conditional acceptance criteria, not observed executions. They assume 32-bit modular arithmetic, 8-bit bytes, valid destinations, and a coprocessor operation that completes and allows execution to continue.

### Input value of three

- The first destination is the incoming base plus 4, and its stored byte is 3.
- The second destination is address 2,978, which receives zero.
- The pre-shift working value is 2,968.
- The first coprocessor data operand is 1.
- Every subsequent coprocessor data operand is zero.

The two stores occur before the first coprocessor operation.

### Input value of one

- The second destination is address 930.
- The working value is 920.
- The first shifted data operand is zero.

Thus, a zero first data operand does not establish that the input value was zero.

### Zero input

With register 4 containing zero:

- The first stored byte is zero.
- The second destination is address `0xFFFFFFA2`.
- The working value is `0xFFFFFF98`.
- The first shifted data operand is `0x001FFFFF`.

This example relies on unsigned conversion and modular address interpretation. It does not imply that the high address is writable. If the second store faults, the coprocessor loop is not reached through the visible path.

### Aliased destinations

With register 4 containing 3 and an incoming base address of 2,974, both byte stores target address 2,978.

The required visible order is a write of 3 followed by a write of zero. For ordinary RAM with no interfering writer, the resulting byte is zero. For device-mapped memory, both writes may have distinct effects.

### Failed second write

If the first destination is writable but the second destination rejects the write, the first write is not undone by any visible mechanism. There is no basis for expecting a returned error code or a coprocessor operation afterward.
