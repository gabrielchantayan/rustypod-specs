# F-31b5c270b688

## Purpose

F-31b5c270b688 performs an ordered dispatch over an object-like structure and a record-like structure. It conditionally invokes F-87ff73d6c0d0, optionally offers the record to an initial indirect handler, invokes one of two primary indirect handlers, and may invoke a final indirect handler.

A nonzero result from any result-bearing handler terminates dispatch and becomes the function’s result. A zero result permits the remaining stages to proceed. F-87ff73d6c0d0 does not participate in this result-selection rule: its result, if any, is not inspected.

The record and object are reread between stages. Consequently, callbacks can affect later dispatch decisions by changing the record, the object, or their referenced storage. The function does not establish an immutable snapshot of either input.

“Object,” “record,” “type,” and “subtype” below are descriptive labels for observed layouts, not established application-level meanings.

## Interface

### Inputs

The function receives two machine-level arguments:

1. **Object address.** An address used both as a base for fixed-offset field reads and as the first argument to every dependency.
2. **Record address.** An address used as a base for fixed-offset field reads and as the second argument to every indirect handler.

The supplied representation uses 32-bit integer words and represents addresses in 32-bit values. The offsets and access widths below describe that representation. Portability to a different pointer width or ABI is not established.

### Object layout accessed by this function

| Byte offset | Access | Observed use |
|---|---|---|
| 0 | Read one 32-bit address | Address of an indirect-dispatch table |
| 80, hexadecimal `0x50` | Read one 32-bit word | Comparison value for the final conditional handler |
| 296, hexadecimal `0x128` | Read one 32-bit word, then narrow to a character-sized value | Second argument to F-87ff73d6c0d0 |

The field at offset 296 is not merely read as a byte. The represented operation reads a complete 32-bit word and then converts its value to the character type used by the dependency call.

### Record layout accessed by this function

| Byte offset | Access | Observed use |
|---|---|---|
| 4 | Read one 32-bit word | Type discriminator |
| 8 | Read one 32-bit word | Nested-record address when the type is `0x16`; comparison value when the type is `0x0f` |

When a current type check finds `0x16`, the word at record offset 8 is interpreted as an address. The function then reads a 32-bit subtype at offset 4 from that nested address.

When the current type is `0x0f`, the word at record offset 8 is compared directly with the object word at offset 80. It is not dereferenced in that stage.

No field at record offset 0 is directly accessed by the supplied body.

### Indirect-dispatch table layout

The object’s first word supplies the table address. Four byte offsets within that table identify callable entries:

| Table byte offset | Role |
|---|---|
| `0x124` | Initial handler for type `0x16`, subtype zero |
| `0x10c` | Primary handler for type `0x16`, subtype `0x2a` |
| `0x110` | Primary handler for every other case |
| `0xe0` | Final handler for a matching type-`0x0f` record |

Each selected indirect handler receives the original object address and original record address. The function inspects each such handler’s result as a 32-bit integer.

### Output

The return value is:

- The first nonzero 32-bit result produced by an invoked indirect handler, in dispatch order; or
- Zero if no invoked indirect handler returns a nonzero result.

Negative nonzero results are returned just as positive nonzero results are. There is no visible normalization to a Boolean, translation into a separate error code, or aggregation of results.

## Behavior

### 1. Conditional preliminary dependency

The function first reads the record type at offset 4.

If that value is not `0x16`, this stage does not read a nested subtype and does not call F-87ff73d6c0d0.

If it is `0x16`, the function:

- Reads the nested address from record offset 8.
- Reads the nested subtype at nested offset 4.
- Subtracts `0x2500` from that subtype and compares the represented result with 2.

The triggering subtype is therefore `0x2502`, decimal 9474. On that match, the function reads the object word at offset 296, narrows it to the character-sized argument, and calls F-87ff73d6c0d0 with the object address and that argument.

The subtraction is represented as 32-bit integer arithmetic. The triggering value is unambiguous and does not require signed overflow. The evidence does not establish a portable source-language overflow policy for all other possible subtype values.

After this call, execution continues regardless of any result the dependency might produce. The supplied body does not save or inspect such a result.

### 2. Optional initial indirect handler

The function rereads the record type. This is a new read after any preliminary dependency call.

If the current type is `0x16`, it rereads the nested address and then the nested subtype. If that current subtype is zero, it:

1. Reads the object’s current table address.
2. Obtains the handler at table offset `0x124`.
3. Calls that handler with the object and record addresses.

A nonzero result is returned immediately. A zero result allows dispatch to continue.

If the current type is not `0x16`, or its nested subtype is not zero, this handler is skipped.

Thus a preliminary dependency can enable or disable this handler by changing the record or nested subtype. The first stage’s discriminator values are not reused here.

### 3. Mandatory primary dispatch

Unless the optional initial handler has already returned a nonzero result, the function performs another record-type read.

If the current type is `0x16`, it reads the current nested address and current nested subtype. It selects:

- Table offset `0x10c` when the current subtype is `0x2a`, decimal 42.
- Table offset `0x110` otherwise.

A current type other than `0x16` selects table offset `0x110` without a nested-subtype access in this stage.

The function obtains the selected entry from the object’s current table and calls it with the object and record addresses. Exactly one of these two primary entries is invoked on any execution that reaches this stage.

A nonzero result is returned immediately. A zero result permits the final stage.

### 4. Optional final indirect handler

After a zero primary result, the function rereads the record type.

Only a current type of `0x0f`, decimal 15, enables the remaining comparison. For that type, the function reads:

1. The 32-bit word at record offset 8.
2. The 32-bit word at object offset 80.

If these words are equal, the function obtains the current object table’s entry at offset `0xe0` and calls it with the object and record addresses.

A nonzero result is returned immediately. A zero result leads to the function’s final zero return.

If the type is not `0x0f`, the comparison fields are not read in this stage. If the comparison fails, the final handler is not invoked.

### Ordering and reread consequences

The possible dependency-call order is:

1. F-87ff73d6c0d0.
2. The optional entry at `0x124`.
3. Exactly one primary entry, at `0x10c` or `0x110`.
4. The optional entry at `0xe0`.

Entries earlier in this list can prevent later result-bearing calls by returning nonzero, except that F-87ff73d6c0d0 has no inspected result.

The object and record addresses passed to callbacks remain the original argument values. Their contents need not remain unchanged. The body does not cache the table address across callbacks or retain an earlier record-type decision for later stages.

   The current type is `0x0f`, the record word at offset 8 equals the object word at offset 80, and primary entry `0x110` returns zero. Entry `0xe0` is invoked. Its nonzero result becomes the function result; its zero result leaves the function result zero.
