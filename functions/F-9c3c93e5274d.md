# F-9c3c93e5274d

## Purpose

F-9c3c93e5274d selects between an activation-like path and a fallback path for an object containing an embedded linked-list node.

The activation-like path refreshes the embedded state, records a global status value, and may insert the node into a global list using a computed 32-bit deadline. The fallback path performs global preparation, conditionally invokes an operation involving the embedded node, and writes a different status value.

“Activation,” “deadline,” and “fallback” describe inferred roles, not established domain semantics. The established contract is the sequence of calls, reads, writes, branches, and list-link changes below. In particular, the fallback path does not visibly clear the membership field or directly unlink the node.

## Behavior

### Path selection

A zero control value skips all eligibility dispatch calls and enters the fallback path.

For a nonzero control value:

1. Invoke the dispatch entry at offset `0x12C`, passing the object.
2. If its 32-bit result is zero, enter the fallback path. The eligibility word at object offset `0x174` is not read by this eligibility check.
3. Otherwise, read the word at offset `0x174` and narrow it to an 8-bit character.
4. Continue on the activation-like path only if that narrowed value is nonzero. Otherwise, enter the fallback path.

Under the represented 8-bit narrowing, only the low byte determines this second condition. A word with higher bits set but a zero low byte does not satisfy it. The signedness of the character type does not change the zero/nonzero outcome.

### Activation-like preparation

After successful eligibility:

1. Read the flags word at `0x170`.
2. If bit `0x00040000` is set, invoke the dispatch entry at `0x124`, passing the object. Its return value is unused.
3. Invoke the dispatch entry at `0x12C` again.
4. Pass the embedded-region address and this second dispatch result to F-6904f7699031.
5. Invoke F-936a8728139d with no explicit arguments.
6. Read G-E and write it to object offset `0x19C`.
7. Read the membership-like field at `0x198`.

The first and second dispatch results are not interchangeable. The first controls eligibility; the second is passed to F-6904f7699031. The second result is not checked for zero.

If the membership-like field is nonzero at step 7, return immediately. This early return occurs **after** both preparation dependencies and the status write. It skips all subsequent list preparation, deadline calculation, notification, and common completion processing.

No assumption is made that the intervening calls preserve the object fields, dispatch table, or globals. The membership check uses the value present after those calls.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Zero control value.** The object dispatch entries are not called for eligibility. The fallback dependencies run in order, the status marker is written, and common completion is evaluated.

2. **First dispatch returns zero.** The eligibility word is not read by the eligibility test. Processing enters fallback without calling the `0x124` dispatch entry or the activation preparation dependencies.

3. **Low eligibility byte is zero.** A nonzero first dispatch result combined with an eligibility word of `0x00000100` selects fallback under the represented narrowing. Higher bits do not make the character nonzero.

4. **Second dispatch returns zero.** If initial eligibility succeeded, the zero second result is still passed to F-6904f7699031. It does not independently redirect execution to fallback.

5. **Already marked as a member.** If the membership-like field is nonzero when checked after preparation, the status has already been written from G-E. The function then returns without list preparation or common completion.

6. **Zero quantity.** If the membership check passes and the quantity read after F-add44d4e9aaa is zero, no deadline computation or explicit insertion occurs. F-5bcae2eff9a7 and common completion still occur.

7. **Empty-list insertion.** With a nonzero quantity and an initially null head, no comparator call occurs. The head is written to the embedded node, membership becomes `1`, and the embedded next pointer becomes null, in that order.

8. **Insert before the first node.** If the first comparator call returns any nonzero value, the embedded node becomes the head and its next pointer is set to the former first node.

9. **Append after all nodes.** If each comparator returns zero and traversal reaches null, the former last node’s next pointer is changed to the embedded node, membership is set to `1`, and the embedded next pointer is set to null.

10. **Fallback status mismatch.** If the status does not equal G-G when compared, F-77781c8e0ff9 is skipped. The G-I marker write still occurs.

11. **Inactive completion structure.** A null pointer in the selected completion cell causes return without dereferencing it. A non-null pointer whose first word is zero causes return without the final indirect transfer.
