# F-51a26611e3e2

## Purpose

F-51a26611e3e2 initializes a caller-supplied object, discovers two services, and invokes a subordinate initializer. After successful subordinate initialization, a negative face index ends processing successfully, a positive index is rejected, and index zero triggers name selection, an associated-object open request, metric transfers, flag updates, and optional table-driven operations.

The interpretation as a font-face initializer is inferred from the operations and descriptive labels. It does not establish external object types or dependency contracts.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Initial state and service discovery

The function first writes zero to destination `0x1F4`, then writes `1` to destination `0x00`.

It then performs these operations in order:

1. Reads destination word `0x60` and passes it, with a fixed character-map-related service-key address, to F-c79a29304dfd.
2. Saves the returned 32-bit value locally and writes it to destination `0x1E0`.
3. Rereads destination `0x60`, reads word `0x04` of the referenced object, and passes that word with an auxiliary-service-key address to F-36f29e709002.
4. Saves that result locally and writes it to destination `0x1E4`.
5. Calls F-f305974cbcf3 with the destination.

Neither lookup result is checked before the subordinate initializer. These operations occur for every face index.

Later service gating uses the locally saved results, not fresh reads of destination `0x1E0` and `0x1E4`. The second lookup’s context is obtained after the first lookup returns; the function does not assume the first lookup preserved the context chain.

### 2. Initializer result and index handling

A nonzero F-f305974cbcf3 result ends processing immediately and becomes the return value.

On zero:

- A negative face index returns zero without index-zero metadata work.
- A positive index invokes F-4457a9a44a68 with an invalid-index diagnostic address, then returns `6`.
- Index zero continues below.

The function performs no rollback on either early-return path. A diagnostic dependency’s return value does not replace status `6`.

### 3. Preliminary metadata and external flag reads

For index zero, the visible sequence is:

1. Read destination `0x19C` and write its word to destination `0x10`.
2. Unconditionally read a first external 32-bit flag word and retain its value.
3. Write zero to destination `0x24`.
4. Write zero to destination `0x04`.
5. Write the retained first flag value to destination `0x08`.
6. Read the byte at destination `0x9C`.
7. If that byte is nonzero, read an alternate external 32-bit flag word and overwrite destination `0x08` with it.
8. Read destination `0x90` and write its word to destination `0x14`.
9. Write a fixed default-style string address to destination `0x18`.

Both external flag locations are memory sources, not established immutable constants. Their numerical contents and aliasing relationships are unknown.

The first flag read and first `0x08` write occur even on the alternate path. Thus this behavior is not equivalent, under unknown aliasing, to reading the selector first and assigning only the selected value. The alternate flag read occurs after the first `0x08` write.

The default-style address is identified as regular-style text by a source label; exact string bytes are not independently established.

### 4. Family and style selection

The function next obtains the family reference from destination `0x14`.

If it is null, destination `0x168` is checked. A nonzero value there is read and installed at `0x14`. This fallback does not trigger comparison with the full name, and no suffix-style assignment occurs on this branch.

With a nonnull initial family reference, the function reads the full-name reference at destination `0x8C`. If that reference is null, no comparison occurs.

For two nonnull references, matching advances through their bytes:

- Each iteration first reads the current full-name byte. NUL ends matching without assigning a suffix.
- Otherwise, the current family byte is read.
- Equal bytes advance both positions.
- Unequal bytes with a full-name space or hyphen advance only the full-name position.
- Otherwise, a family space or hyphen advances only the family position and restarts comparison at the same full-name position.
- If neither mismatching byte is a space or hyphen, the current family byte is read again. If that read is NUL, destination `0x18` receives the current full-name address. Matching then ends regardless.

Only literal space and hyphen bytes receive special treatment. Case folding and general whitespace normalization are not visible.

A selected style is an interior reference into existing full-name storage. Equal complete strings retain the default style because the full-name NUL is tested before the family byte.

After name processing, the function writes zero to destination `0x1C`, then zero to destination `0x20`.

### 5. Associated-object open request

A local request descriptor is prepared:

| Descriptor offset | Established contents |
|---|---|
| `0x00` | Initially `1`; overwritten with `0x11` for a nonzero parameter count |
| `0x04` | Word read from destination `0x1EC` |
| `0x08` | Word read from destination `0x1F0` |
| `0x18` | Parameter count, written only when nonzero |
| `0x1C` | Parameter-data address, written only when count is nonzero |

The two source words are read after name processing and before opening. Other descriptor bytes are not established as initialized. On the parameter-bearing branch, the parameter-data address is stored before the count.

F-589adbc0f0a7 receives:

1. Word `0x04` of the object obtained by rereading destination `0x60`.
2. The request descriptor address.
3. Zero.
4. The address of destination `0x1F4`.

A negative parameter count is not rejected here. It selects flags `0x11` exactly as any other nonzero count does.

If opening returns nonzero, the function returns that status without subsequent metadata extraction or caller-side rollback. Earlier writes occurred, but their values are not guaranteed to survive the dependency: it receives an output-slot address and has undocumented mutation effects.

### 6. Post-open call and metric transfers

After a zero open result, the function reads destination `0x1F4`, reads word `0x58` of that associated object, and passes the word to F-af298c80e6df. Its return value is not used. No ownership or release meaning is established.

After that call, destination `0x1F4` is reloaded. From this reloaded associated-object reference, the function:

1. Reads words `0x38`, `0x3C`, and `0x40`, retaining them.
2. Reads word `0x34` and writes it to destination `0x34`.
3. Writes the retained words to destination `0x38`, `0x3C`, and `0x40`, respectively.

It then performs six separate 16-bit read/write transfers, in the listed order:

| Associated-object offset | Destination offset |
|---|---|
| `0x44` | `0x44` |
| `0x46` | `0x46` |

### 7. Flag composition

The function:

1. Writes zero to destination word `0x0C`.
2. Reads destination word `0x98`; if nonzero, writes `1` to `0x0C`.
3. Reloads the associated-object reference and tests bit `0x02` of its word `0x0C`. If set, it reads the current destination `0x0C`, ORs in `0x02`, and writes it back.
4. Reloads the associated-object reference and tests bit `0x20` of its word `0x08`. If set, it reads the current destination `0x08`, ORs in `0x20`, and writes it back.

The directly constructed value at destination `0x0C` is therefore `0`, `1`, `2`, or `3`. This is not a guarantee that subsequent dependencies preserve it.

The update at `0x08` uses its current contents, not a cached external flag value.

### 8. Optional table-driven operations

This phase occurs only when both saved lookup results are nonzero.

The function reads a table pointer from offset `0x14` of the saved auxiliary-service result. That table pointer is retained across the first F-e504f72ffcc9 call; table contents are not assumed preserved.

| Offset | Contents |
|---|---|

| `0x04` | Value read from an external tag-word location |

| Selector | Selected table offset | Prepared packed value | External tag source |
|---|---:|---:|---|
| `1` | `0x08` | `0x00020007` | Selector-1 tag-word location |
| `2` | `0x00` | `0x00000007` | Selector-2 tag-word location |

These tags are externally stored words, not established immutable constants. The first tag is read before the first call; a recognized selector’s tag is read after it. Dependency-induced changes must not be replaced with an assumption of earlier caching or stability. ## Side effects

Initialization is incremental, not transactional:

- The incoming associated-object slot is cleared without a visible release of its previous contents.
- Service-reference writes precede subordinate initialization.
- Initializer failure and negative-index completion do not undo earlier operations.
- Positive-index rejection follows successful subordinate initialization.
- Preliminary metadata writes precede the open call.
- An open error causes no restoration or clearing by this function afterward. The dependency may already have changed those fields or other state.
- After successful opening, F-af298c80e6df runs before metric extraction.
- Optional table-driven calls follow metric and flag construction and may have undocumented mutation effects.

No direct allocation, string copying, or memory-release operation is established. Dependencies may allocate, release, modify reachable storage, or change global state. Nothing here establishes their preservation of externally stored flags, tags, contexts, tables, or destination fields.

## Acceptance examples

These are conditional static expectations, not observed executions. Successful-path examples require valid reached references and returning dependencies.

1. **Initializer failure takes precedence.** If F-f305974cbcf3 returns `9` with face index `2`, the result is `9`; neither the invalid-index diagnostic nor opening occurs.

2. **Negative index stops early.** With initializer result zero and index `-1`, the function returns zero after initial writes and service discovery, without index-zero metadata work.

3. **Positive index is rejected after initialization.** With initializer result zero and index `2`, the diagnostic call occurs and the result is `6`.

4. **The first flag read precedes clearing.** If the first external flag location aliases destination `0x24`, its incoming word is saved before `0x24` is cleared and is subsequently written to `0x08`.

5. **The alternate path includes the initial write.** With a nonzero selector byte at `0x9C`, the first flag value is still written to `0x08` before the alternate flag word is read. If that alternate location aliases `0x08`, it reads the value just written.

6. **Suffix selection retains storage.** With stable family text “Example” and full-name text “Example-Bold”, the style becomes the address of “Bold” within the full-name storage. Equal complete names instead retain the default style.

7. **Fallback family skips comparison.** A null initial family reference with a nonzero replacement at `0x168` installs that replacement without deriving a full-name suffix.

8. **Negative count remains parameter-bearing.** A count of `-1` selects request flags `0x11` and stores the count and parameter-data address.

9. **Open failure provides no preservation guarantee.** If opening returns an error, preliminary writes have already occurred, and this function does not restore or clear them afterward. Whether their values remain intact depends on undocumented dependency effects.

10. **Missing service disables both optional calls.** If either saved lookup result is zero, neither F-e504f72ffcc9 invocation occurs.

11. **Post-call values govern selection.** If the first map call changes the selector to `2` and changes the selector-2 tag word, subsequent processing reads that selector and the changed tag word, then reads table offset `0x00`.

12. **Unknown selector and ignored statuses.** With both services present, selector `5` observed after the first map call suppresses the second call and returns zero. A returned error value from a reached map call is not propagated.
