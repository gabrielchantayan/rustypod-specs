# F-69006fcb11f9

## Purpose

F-69006fcb11f9 constructs and publishes a value derived from a sign-prefixed sequence of 16-bit input units.

The established numeric behavior is a three-position calculation: the first converted value contributes a factor of 3600; an eligible second value also contributes a factor of 3600; an eligible third value contributes without scaling. A leading minus sign negates the combined result. A leading plus sign is consumed without changing its sign.

The apparent intent is delimiter-separated numeric parsing followed by object construction. The delimiter supplied to the parsing dependency is a colon. This does **not** establish a conventional hours/minutes/seconds conversion: the second contribution is multiplied by 3600, not 60.

Tokenization, numeric conversion, component eligibility, allocation, construction, and publication are delegated. Their complete semantics are not available.

### Input representation

The input is accessed through a pointer to 16-bit units. The function recognizes the unit values:

- `0x002d`: minus sign.
- `0x002b`: plus sign.

Consuming a sign advances the local pointer by one 16-bit unit, or two bytes. The function does not itself establish a text encoding, terminator convention, length representation, or complete input grammar.

The input pointer and the adjacent 32-bit field are copied into local storage before sign handling. The address of the local pointer field is later passed to the parsing dependency. The adjacent field is therefore visible as part of the supplied local layout, but its interpretation is unknown.

## Behavior

### 1. Capture input state and recognize a leading sign

The function first reads the input pointer from context offset `+0x0c`, then reads the 32-bit field at `+0x10`.

It begins with a positive multiplier. It reads the first input unit and compares it with the minus-sign value.

- If that comparison succeeds, it selects a multiplier of −1 and advances the local input pointer by two bytes.
- Otherwise, it reads the first input unit again and compares it with the plus-sign value. If that comparison succeeds, it advances the local pointer by two bytes.
- Otherwise, it leaves the pointer unchanged.

Consequently, an ordinary non-minus input causes two visible reads of the initial unit. This is not necessarily equivalent to one read when the backing storage can change between reads.

Only one leading sign is handled directly. Whitespace, repeated signs, signs inside components, and subsequent syntax are delegated.

No explicit write restores the locally advanced pointer to the context.

### 2. Initialize delegated parsing state

The function calls F-8f7023d4928d with:

1. The address of a 24-byte local workspace.
2. The address of the local input-pointer field.
3. The value `0x3a`, corresponding to a colon.
4. The value `0x7fffffff`, or 2,147,483,647.
5. The value `1`.

The visible evidence establishes these argument values and storage relationships. It does not establish whether the fourth argument is a count, limit, sentinel, or other control, nor what the fifth argument selects.

### 3. Obtain and convert the first value

It then passes that output address to F-64292cfbfab8 and treats the returned value as a 32-bit integer. There is no eligibility check before this first conversion.

The initial accumulator is the first conversion result multiplied by 3600.

The first output occupies storage subsequently handled as an eight-byte record, consisting of two 32-bit words. Its internal representation is unknown.

### 4. Examine the second value

The function calls F-f970f3b0ebd4 again, this time supplying a separate eight-byte local output area and the same parsing workspace.

It copies both 32-bit words from that output area into the record used for subsequent checking and conversion. It then calls F-d5d68dc4e17c with the copied record’s address.

If the predicate returns zero, the second contribution is omitted.

If the predicate returns any nonzero value, the function passes the **same record**, after the predicate call, to F-64292cfbfab8. It adds that conversion result multiplied by 3600 to the accumulator.

The predicate may modify the record; preservation is not established. The conversion therefore cannot be specified as necessarily receiving the exact bytes originally produced by F-f970f3b0ebd4.

### 5. Examine the third value

The function performs a third call to F-f970f3b0ebd4, again using the separate output area and the same parsing workspace. It copies the two output words into the checking/conversion record and calls F-d5d68dc4e17c.

If the predicate returns zero, the third contribution is omitted.

If the predicate returns nonzero, F-64292cfbfab8 receives the record as it exists after the predicate call. Its result is added directly to the accumulator, without scaling.

This third retrieval occurs regardless of whether the second predicate succeeded. A rejected second value does not terminate processing.

There is no fourth retrieval call and no explicit check for unconsumed input.

### 6. Allocate, construct, and publish

After accumulating the contributions, the function calls F-8157a180d901 with the argument `0x20`, or 32.

Only after that call returns does the function compute and store a local 32-bit signed result by multiplying the accumulator by the selected sign multiplier.

It then calls F-6911fe60f7c0 with:

1. The value returned by F-8157a180d901.
2. The address of the local signed result.

The return value from F-6911fe60f7c0 is passed to F-3034e350c6fb together with the destination address at context offset `+0x14`.

The construction return value, rather than necessarily the original allocation return value, is published.

## Acceptance examples

The following are conditional contract examples, not runtime test results. They assume valid memory, returning dependencies, and arithmetic within signed 32-bit range.

1. **All three numeric contributions enabled.**  
   If the conversion results are 2, 3, and 4, and both predicates return nonzero, the construction dependency receives a pointer to 18,004. A result of 7,384 would incorrectly impose a factor of 60 on the second contribution.

2. **Leading minus sign.**  
   Under the same dependency results, an initial `0x002d` advances the parser’s local input pointer by two bytes and produces −18,004 for construction.

3. **Leading plus sign.**  
   An initial `0x002b` advances the local pointer by two bytes and leaves the calculated sign positive.

4. **Second contribution rejected, third accepted.**  
   If the first conversion returns 2, the second predicate returns zero, the third predicate returns nonzero, and the third conversion returns 4, the result is 7,204. There are still three retrieval calls and two predicate calls, but only two conversion calls.

5. **Both later contributions rejected.**  
   If the first conversion returns 2 and both predicates return zero, the result is 7,200. The first conversion still occurs without a predicate.

6. **Predicate mutation.**  
   If an accepting predicate changes the record, the subsequent conversion receives that changed record. Reconstructing the record from its earlier copy before conversion would change the visible behavior.

7. **Different construction return value.**  
   If construction returns a value different from its first argument, publication receives the construction return value.

8. **Overflow boundary.**  
   If a multiplication, accumulation, or final sign application exceeds the signed 32-bit range, these examples impose no wraparound or error-result expectation. That case remains documented_only.
