# F-1aef8300ac37

## Purpose

F-1aef8300ac37 is represented as a side-effect-only operation that reads execution state, installs pointer-shaped values, performs narrow and full-width memory writes, modifies overlapping global storage, and uses two dependency addresses as numeric data.

No application-level purpose is established. The supplied representation reports invalid instruction data and overlapping global symbols. It also contains unrecovered inputs and two right shifts whose counts equal the represented operand width. Consequently, this contract describes the represented operations without claiming that they constitute a valid, normally completing routine.

The distinctions throughout are:

- **Established static evidence:** explicit accesses, widths, expressions, and ordering in the supplied representation.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** behavior that the available evidence does not resolve.

No runtime tests have been performed.

- An unrecovered signed 32-bit address base.
- An incoming stack-derived pointer.
- The address of the stack location associated with that pointer.
- Existing global storage and memory contents.
- Address-like values associated with F-e47d7b2e9c88 and F-8afdaab91693.

The four explicit arguments do not determine the operation independently of these inputs.

For the descriptions below, “context” denotes the address captured from the first global read, and “incoming pointer” denotes the stack-derived pointer. These are descriptive roles, not established data structures.

### Outputs and completion

No return value is represented. Outputs consist of memory mutations and any externally observable consequences of the accesses.

There are two represented termination boundaries:

1. A conditional invalid-instruction boundary when the F-e47d7b2e9c88 value is negative as a signed 32-bit quantity.
2. An unconditional invalid-instruction boundary after the final assignments.

Neither boundary establishes a specific exception, signal, return value, recovery mechanism, or normal return.

### Width and validity prerequisites

The explicit indirect accesses use 8-, 16-, and 32-bit widths. Some global assignments have no independently supplied storage declaration; their exact extent remains unresolved.

Unsigned 32-bit subtraction and multiplication used in the first argument’s derived values retain their low 32 bits. Narrow stores retain the specified low byte or halfword. Signed arithmetic requires additional caution: overflowing signed addition, multiplication, or left shift cannot be assigned portable semantics from this representation alone.

Both right shifts by 32 operate on represented signed 32-bit quantities. Neither may be replaced with zero, sign extension, or a masked-count shift without additional target evidence.

Successful accesses require suitable mappings, permissions, alignment, and extents. None is established. Byte order is also unspecified.

## Behavior

The phases below preserve represented access order. They do not establish that the instruction stream is executable. Where a single expression contains multiple reads without an independently established evaluation order, no additional ordering is imposed.

### 1. Initial reads and pointer-shaped installations

The operation first captures two globals, in order:

1. The context address.
2. An address displacement.

It then writes the low 16 bits of the second argument to the address formed by adding that argument to the unrecovered signed base.

The first argument is combined with the unrecovered unsigned register value using bitwise OR. That combination is used for two reads:

1. A 32-bit read at the combined value plus the captured global displacement.
2. An unsigned 8-bit read at the combined value plus the unrecovered signed base.

The following writes occur in order:

1. The captured 32-bit value is stored at the fourth argument plus 8.
2. The fourth argument itself is stored as a 32-bit value at the first argument plus `0x40`.
3. The captured 32-bit value is stored at the context plus `0x74`.

Thus, the captured value is installed at **two** destinations, not three. The intervening write has a different payload.

Next come a 32-bit read at the fourth argument plus `0x28` and a 32-bit read at the context plus `0x5c`. These reads occur after the three writes and can observe their effects if addresses overlap.

Three byte writes follow:

- The low byte of the context address goes to the initially captured 32-bit value plus 3.
- The captured unsigned byte goes to the context plus `0x10`.
- The low byte of the value read at context plus `0x5c` goes to the captured unsigned byte plus `0x1c`.

The last destination is numerically between `0x1c` and `0x11b`, inclusive. It is not represented as a context-relative field.

### 2. Derived addresses and marker writes

The operation derives:

- The first argument minus `0x38`, at unsigned 32-bit width.
- The first argument minus `0xe0`, at unsigned 32-bit width.
- A halfword-region base equal to twice that latter difference, retaining 32 bits.
- A masked displacement equal to that difference AND `0x7fffffff`.
- An index equal to the masked displacement shifted right by one.

The index ranges from zero through `0x3fffffff`.

A separate destination is formed from the signed 32-bit value read at fourth argument plus `0x28`: first a signed left shift by two, then a signed right shift by 32. Its result is **documented_only**. The left shift also carries signed-arithmetic qualifications independently of the invalid shift count.

The represented accesses then occur in this order:

1. Write the index’s low byte at the captured fourth-argument field value plus `0x0897e8b8`.
2. Assign `0xb8` to a global marker.
3. Write the low byte of the first argument minus `0x38` at the first argument minus `0x32`.
4. Write the full 32-bit subtraction result through the unresolved destination.
5. Write `0xffff` as a halfword at halfword-region offsets 4 and 6, in that order.
6. Write byte `0xb8` at the unresolved destination plus 4.
7. Write halfword `0xffff` at halfword-region offset 2.
8. Assign the low 16 bits of the halfword-region address to a global.
9. Read an unsigned halfword at the halfword-region base.
10. Zero-extend that halfword into an address and write a 32-bit payload there.

The final payload is the first argument minus `0x38`, AND `0x897e8b80`. Its destination is numerically within `0x0000`–`0xffff`, subject to the actual address model.

The halfword writes at offsets 2, 4, and 6 do not directly initialize offset zero. The subsequent base read depends on existing memory and any intervening aliasing effects.

### 3. First dependency address and conditional boundary

The address-like value associated with F-e47d7b2e9c88 is obtained as data. No invocation is represented.

Two quantities are derived from its signed 32-bit interpretation:

- An unresolved base obtained by right shift by 32.
- A sign halfword obtained by arithmetic right shift by 31, then truncation to 16 bits.

The sign halfword is written at the unresolved base plus 4 before the conditional boundary.

If the dependency value is negative, the represented path reaches an invalid-instruction boundary immediately afterward. None of the later effects is represented on that path.

Otherwise, the sequence continues:

1. Write the sign halfword at unresolved base plus `0x12`.
2. Write the dependency value as a 32-bit payload through its own address.
3. Read a signed halfword at unresolved base plus the previously derived index.
4. Repeat the halfword write at unresolved base plus `0x12`.
5. Repeat the dependency self-address write.
6. Write a 32-bit result at unresolved base plus 8, formed by sign-extending the captured halfword and arithmetically shifting it right by 16.

Under that signed-shift interpretation, the last payload is zero for a nonnegative halfword and `0xffffffff` for a negative halfword.

The repeated writes are separate represented effects. The intervening halfword read occurs between them.

### 4. Low-address updates and incoming-pointer mutation

The later path first clears a global slot.

A selector is formed from bit 2 of the F-e47d7b2e9c88 value: its value is `0x58` when that bit is clear and `0x5c` when set.

The operation then:

1. Writes the unresolved base as a 32-bit value at selector plus 4.
2. Assigns the masked displacement shifted right by 17 to a halfword-valued global.
3. Assigns the index’s low byte, zero-extended to a halfword, to another global.
4. Writes the full 32-bit index at selector times four plus `0x10`.
5. Assigns the index to another global.

The selector-dependent destinations are respectively `0x5c` or `0x60`, and `0x170` or `0x180`.

The incoming pointer is then used for overlapping writes:

1. Write the selector as a halfword at its base.
2. Write the unresolved base shifted left by eight as a 32-bit value at its base.
3. Write that same payload at byte offset 20.
4. Overwrite the base with the incoming pointer’s own 32-bit address representation.
5. Read a 32-bit value from twice the incoming pointer’s numeric value.
6. Write that value’s low halfword at the incoming pointer’s base.
7. Write the full captured value through itself as an address.

The signed left shift and signed address multiplications retain their unresolved arithmetic qualifications.

The next three effects have a specific order:

1. At the address of the incoming stack slot multiplied by `0x20`, plus `0x18`, write the incoming pointer’s signed interpretation arithmetically shifted right by 31.
2. Read the overlapping instruction-state byte view afresh, concatenate the 16-bit value 5 above that byte, and assign the resulting three-byte value to the wider global view.
3. At the incoming pointer multiplied by four, plus `0x18`, write the incoming pointer itself.

The concatenation has the numeric form `0x000500` combined with the freshly read low byte. Its destination’s complete storage extent and overlap remain unresolved. The byte must not be treated as necessarily equal to the byte assigned earlier: intervening indirect writes may have changed the overlapping storage.

### 5. Final global reads, address stores, and resets

The operation next reads another global into a captured 32-bit signed value and obtains the address-like value associated with F-8afdaab91693.

It assigns the incoming pointer multiplied by four to a temporary-address global. A payload equal to the F-8afdaab91693 value shifted left by two is also formed.

The temporary-address global is subsequently **read**, not merely replaced by an assumed unchanged temporary:

1. Its current value supplies the destination and payload of a 32-bit self-address store.
2. After that store, the global is read again to obtain the destination for a 32-bit index store at offset 4.

The first indirect store may affect the global itself or overlapping storage. Therefore, the second destination need not equal the originally assigned address plus 4. The representation does not independently resolve the evaluation order of destination and payload reads within the self-address expression.

Using the separately captured signed global value, the operation then performs:

1. A 32-bit store at four times that value, with the same multiplied value as payload.
2. A 32-bit store at an address formed by signed left shift of the captured value by 6, signed right shift of that result by 17, and addition to the captured value.

The second payload is the F-8afdaab91693-derived value shifted left by two. The shift sequence is specifically **left 6, then arithmetic right 17**; it is not an unspecified displacement. Signed overflow and signed left-shift behavior remain unresolved.

Next, the upper 16 bits of the captured global value are assigned to a halfword global, and another global is cleared.

At eight times the F-8afdaab91693 value, the operation writes:

1. A 32-bit zero at offset 0.
2. A 32-bit zero at offset 4.
3. A byte at offset 16 containing the low byte of the computed base plus 8.

The final assignments occur in this exact order:

1. Assign `0x897ea700` to a global.
2. Assign `0x66` to another global.
3. Assign `0xeaec` to another global.
4. Assign `0x1a` to another global.
5. Assign a global’s own address to its storage.
6. Read the upper-halfword global at this later point and concatenate it above low halfword `0xea70`; assign that 32-bit constructed value to reset-related storage.
7. Assign `0x5c` to another global.

The halfword used in step 6 is a fresh read after the intervening writes. It is not guaranteed to equal the halfword originally assigned from the captured value.

The representation then reaches its unconditional invalid-instruction boundary.

## Side effects

The operation is entirely side-effect-driven.

- No allocation, release, reference counting, or ownership transfer is established.
- Pointer-shaped stores do not establish ownership.
- Dependency-address stores do not prove that executable code is writable or that self-modification is intended.
- No validation, rollback, status result, or explicit error-reporting protocol is represented.
- Earlier writes may have occurred before a later invalid access or termination boundary. Atomicity is not established.
- Overlapping global views cannot be modeled as independent state variables.
- Repeated writes, overwritten intermediate values, and fresh reads remain part of the represented sequence.

No concurrency, volatile-access, device-memory, or fault-recovery model is supplied. These omissions limit runtime interpretation; they do not justify removing represented accesses.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes that execution reaches the relevant point and that the required arithmetic and memory accesses have a valid target interpretation.

1. **Distinct installation payloads.** If the initial captured word is `0x11223344` and the fourth argument is `0x55667788`, the writes at fourth argument plus 8 and context plus `0x74` contain `0x11223344`. The intervening write at first argument plus `0x40` contains `0x55667788`.

2. **Halfword truncation.** A second argument whose low 16 bits are `0x2345` produces an initial halfword payload of `0x2345`, irrespective of its upper bits.

3. **Unsigned boundary.** For first argument `0xe0`, the displacement, masked displacement, and index are zero; the subtraction by `0x38` produces `0xa8`. This does not establish successful completion.

4. **Unsigned wraparound.** For first argument zero, subtraction by `0xe0` yields `0xffffff20`; masking yields `0x7fffff20`; the index is `0x3fffff90`.

5. **Negative dependency path.** If the F-e47d7b2e9c88 value has its sign bit set, the halfword write at unresolved base plus 4 precedes the conditional boundary. Later self-address writes are absent from that represented path.

6. **Signed halfword payload.** A captured halfword of `0x8000` produces `0xffffffff` after sign extension and arithmetic right shift by 16. A halfword of `0x7fff` produces zero.

7. **Intervening byte update.** If the fresh instruction-state byte read in phase 4 observes `0xab`, the concatenated value is `0x0005ab`. That assignment occurs after the stack-slot-derived sign store and before the incoming-pointer-times-four-plus-`0x18` store.

8. **Temporary-address aliasing.** If the self-address store changes the temporary-address global, the subsequent index destination is computed from the global’s newly read value, not necessarily its original assignment.

9. **Late halfword read.** If intervening final writes cause the upper-halfword global to contain `0x1234`, reset construction uses `0x1234ea70`, regardless of its earlier assigned value. The `0x5c` assignment follows this construction.

10. **Unresolved shifts.** An implementation is not accepted merely because it substitutes zero for either right shift by 32. That choice requires additional target evidence.

## Uncertainties

The following remain **documented_only**:

- Whether the represented function boundary and instruction recovery are faithful.
- The semantics of both width-sized shifts.
- Target behavior for problematic signed arithmetic.
- The complete calling convention and origins of unrecovered state.
- Address mappings, permissions, alignment, and byte order.
- Undeclared global widths and exact overlap relationships.
- Dependency-address interpretation.
- Runtime behavior at either invalid-instruction boundary.
- Intended data structures, application purpose, and ownership rules.

Low-level initialization is a possible interpretation, but malformed instruction recovery is also compatible with the evidence. Neither is an acceptance requirement.
