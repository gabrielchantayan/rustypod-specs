# F-936416edf8a5

## Purpose

F-936416edf8a5 accepts two 32-bit word patterns and produces a 64-bit pattern. Depending on an upper-word field and external state, it either preserves the input or clears a selected portion of the lower word. Some paths also invoke a pair of dependencies, including paths that leave the returned pattern unchanged.

This contract describes observable word-level behavior. A floating-point rounding purpose is plausible, but neither a floating-point format nor a particular mathematical rounding rule is established. Dependency calls must not be treated as dispensable merely because their results do not determine the returned pattern.

All behavior below is based on static evidence. No runtime tests have been performed.

| **Upper** | 32 bits | Input pattern occupying the upper half of an unchanged result; also supplies the field and sign-bit tests used for decisions. |

The result is 64 bits wide. Result bits 0–31 contain the returned lower word; bits 32–63 contain the returned upper word. This is a logical bit layout, not an assertion about byte order, register placement, or memory serialization.

Bit positions within a word are numbered from 0, the least significant bit, through 31. “Sign bit set” means bit 31 is one; it does not require interpreting the complete input pair as a signed number.

Unsigned word additions wrap modulo \(2^{32}\). Signed selector comparisons use a 32-bit two’s-complement interpretation. Complements and masks are confined to 32 bits.

## Behavior

### Selector and decision regions

The selector is a 32-bit word formed from:

- Upper bits 20–30, interpreted as an unsigned 11-bit field; and
- the selector offset, added with 32-bit wraparound.

The extracted field ranges from 0 through 2047. Upper bit 31 and Upper bits 0–19 do not contribute to this field.

The selector’s signed interpretation determines the principal region:

| Selector region | Observable result policy |
|---|---|
| Negative | Invoke the small-selector dependency pair; preserve both input words. |
| 0–19 | Consult the upper-selection mask and Lower; either preserve without calls or preserve after the small-selector dependency pair. |
| 20–50 | Consult selected Lower bits; either preserve without calls or invoke the large-selector dependency pair and transform the returned words. |
| 51 | Consult Lower bit 0; possibly invoke the large-selector dependency pair, but always preserve the input words. |
| 52–\(2^{31}-1\) | Preserve both input words without dependency calls. |

A selector whose 32-bit pattern has bit 31 set belongs to the negative region, even if its unsigned interpretation is large. Selector construction does not saturate or reject overflow.

### Shared dependency protocol

There are two possible first-stage dependencies:

- **F-1b22d7e17791** for the negative and 0–19 regions.
- **F-387e686c467e** for the 20–51 region.

Whenever a first-stage call is required, its four argument positions contain Lower, Upper, and the first-call argument pair, in that order. The supplied input words are the original words, before any result transformation.

The first-stage dependency produces a 64-bit result. Its lower 32 bits and upper 32 bits become, respectively, the first and second argument positions of **F-c6bfc9d0fb36**. The second-call argument pair occupies the remaining two positions.

Those first two second-stage arguments are represented as signed 32-bit quantities in the supplied representation. The forwarding contract concerns their 32-bit patterns; a word with bit 31 set must not be described as necessarily arriving as a positive numeric value.

The second-stage return value does not contribute to this function’s result. The first-stage result is used for forwarding only, not as a replacement for either returned input word.

### Negative selector

Every negative selector requires the small-selector dependency pair. There is no exemption for an all-zero input or for an Upper word containing only its sign bit.

After normal completion of both calls, the original Lower and Upper are returned.

The supplied representation also contains a continuation that would modify the words and read another external value. A fixed true condition prevents that continuation from being reached. Its contents therefore do not establish observable behavior for this region.

### Selectors 0–19

For this region, a selection mask is obtained by logically shifting the upper-selection mask right by the selector value. Zeroes enter at the high end; bits shifted beyond the low end are discarded. The shift distance is between 0 and 19.

The dependency decision depends on two independent conditions:

- whether any Upper bit selected by that shifted mask is set; and
- whether Lower is nonzero.

If neither condition holds, the result is the original pair and no dependency is invoked. If either condition holds, the small-selector dependency pair is invoked and the result is still the original pair.

Consequently:

- A nonzero Lower requires the calls regardless of the external mask.
- A zero Lower does not by itself exempt the call; selected Upper bits may require it.
- The external mask influences call occurrence, not the returned pattern.
- A dependency changing external storage does not cause this function to repeat the mask decision.

An apparent later transformation is unreachable because the intervening condition is fixed true. It is not part of the observable contract.

### Selectors 20–51: selection of Lower bits

The tested portion of Lower is a contiguous low-order region. Its width is \(52-\text{selector}\) bits:

| Selector | Tested Lower bits |
|---:|---|
| 20 | All 32 bits |
| 21 | Bits 0–30 |
| 50 | Bits 0–1 |
| 51 | Bit 0 |

Intermediate selectors reduce the region by one bit for each increase in selector.

If all tested bits are zero, the function returns the original pair without calls or transformation. This bypass applies regardless of Upper’s sign bit.

If any tested bit is set, the large-selector dependency pair is required. Any result modification described below takes place only after both calls complete normally.

The mask-building shifts range from 0 through 31; no reached mask operation requires shifting a 32-bit word by 32 or more.

### Selector 51

The call decision depends solely on Lower bit 0:

- Bit 0 clear: no calls.
- Bit 0 set: invoke the large-selector dependency pair.

Both cases return the original Lower and Upper. In particular, a call-producing selector-51 input is not rounded or truncated by this function.

### Selectors 20–50 with Upper’s sign bit clear

After the required dependency pair, the selected low-order portion of Lower is cleared. All unselected Lower bits are retained, and Upper is unchanged.

At selector 20, the selected portion is the entire lower word, so the returned lower word is zero. At selector 50, only its lowest two bits are cleared.

The initial all-zero-selected-bits bypass remains controlling: it avoids calls and returns the original pair.

### Selector 20 with Upper’s sign bit set

For a nonzero Lower, the function invokes the large-selector dependency pair, returns zero as the lower word, and increments Upper by one with 32-bit wraparound.

This boundary has no separate addition to Lower.

When Lower is zero, the earlier bypass applies: no calls occur and Upper is not incremented.

### Selectors 21–50 with Upper’s sign bit set

For a call-producing input, the lower-word adjustment is a single-bit increment immediately above the selected low-order region. Its bit position is \(52-\text{selector}\), ranging from bit 31 at selector 21 to bit 2 at selector 50.

The lower-word addition wraps to 32 bits. A carry is detected by comparing the wrapped sum with the original Lower as unsigned words. If the sum is smaller, Upper is incremented by one, also with 32-bit wraparound.

The returned lower word is the adjusted lower word with the originally selected low-order region cleared. This is not merely clearing bits in the original Lower: the addition may change retained bits or carry into Upper.

For selectors 22–50, the increment is representable as a positive signed 32-bit value. Selector 21 instead places the increment in bit 31. The word-level interpretation yields `0x80000000`, but the supplied representation uses a signed unit operand for that shift. The exact executable semantics of this boundary remain a documented uncertainty; the selector-21 acceptance example below is conditional on that word-level interpretation.

### Selectors 52 and above

For nonnegative selectors of at least 52, neither dependency pair is invoked. Both input words are preserved. No selection mask is needed for this region.

Within either pair of external call arguments, the supplied evidence does not establish which word is read first.

Changing external storage inside a dependency does not cause the visible function to recalculate its selector, reread its selection mask, or substitute a dependency result for an input word.
