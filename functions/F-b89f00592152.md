# F-b89f00592152

## Purpose

F-b89f00592152 selects between two protocols combining direct memory accesses with opaque dependency invocations. Selection uses a signed interpretation of an implicit 32-bit selector.

The **high-selector protocol** observes a character, publishes two 32-bit fields, and forwards argument-derived and dependency-derived values through a call chain. Normal completion is represented after its final invocation.

The **low-selector protocol** mutates numerically addressed storage, retains observations for later addressing, and processes a 64-bit dependency result. Its endpoint involves an exceptional operation with unresolved continuation semantics.

No application-level purpose, success indicator, transaction boundary, or recovery policy is established. This contract describes static evidence and its conditional consequences. No runtime tests have been performed.

## Behavior

### Selection and arithmetic

The selector is converted to signed 32-bit form and compared with 89:

- Greater than 89 selects the high protocol.
- Otherwise, the low protocol is selected.

Selectors 89 and 90 therefore select different protocols. Conversion of unsigned values above the signed maximum is not assumed to produce negative values; the applicable conversion behavior is **documented_only**.

Unsigned 32-bit calculations wrap modulo \(2^{32}\). Unsigned right shifts are logical. Negative signed right shifts, out-of-range signed conversions, and plain-character interpretation remain **documented_only** where relevant.

The ordering below describes direct accesses and invocation boundaries. It does not establish atomicity, synchronization, or absence of effects inside dependencies.

### High protocol: observation and publication

F-D01 is invoked first, using the entry-context-relative destination identified under Dependencies. No direct data-memory access precedes it on this protocol.

After F-D01 returns, one 8-bit plain character is observed. Its numeric address is the unsigned 32-bit sum of:

- The second explicit argument converted to unsigned 32 bits.
- The highest four bits of the storage reference’s unsigned 32-bit conversion.

The reference-derived contribution ranges from 0 through 15. The addition can wrap.

The character observation precedes these writes, in order:

| Destination | Width | Value |
|---|---|---|
| Storage offset 0 | Signed 32 bits | Fourth argument minus 90 |
| Storage offset 4 | Signed 32 bits | Second argument shifted right by 16, then left by 20, using signed operations |

The subtraction requires representability. The second calculation is not unsigned bit-field extraction: negative right-shift behavior and signed left-shift validity matter.

The observed character is retained. Overlap between its original storage and either field does not cause a reread.

### High protocol: dependency pipeline

After both writes, invocation order is F-D02 through F-D12, conditional on each preceding invocation returning.

The significant argument and output relationships are:

- **F-D02:** receives the signed shift calculation used for offset 4, followed by the original second argument. The first argument is calculated from the argument, not obtained by reading the field.
- **F-D03:** receives an associated unsigned 32-bit output from F-D02, logically shifted right by 17.
- **F-D04:** supplies a 32-bit return with unspecified signedness.
- **F-D05:** receives F-D04’s return unchanged, followed by the retained character converted to signed 32 bits and shifted right by 9.
- **F-D06:** supplies an associated signed 32-bit output.
- **F-D07:** receives that output shifted right by 18 and returns a signed 32-bit value.
- **F-D08:** receives F-D07’s return and that return shifted right by 14.

A nonnegative character contributes zero to F-D05’s second argument. Under signed-character interpretation with arithmetic right shift, a negative character contributes −1. Those interpretation choices are not universally established.

F-D06 and F-D08 invoke the **same represented fixed destination**, F-T06. Their positions and argument roles differ; their target identity does not.

F-D09 through F-D12 have no represented explicit arguments. No further direct data-memory access is represented after the two field writes, although dependencies may access memory.

If F-D12 returns normally, F-b89f00592152 returns without a data value. Its destination is unresolved, so completion is conditional.

### Low protocol: opening mutation and retained addressing

The first direct effect is a 32-bit write of the complete unsigned selector at numeric address selector plus 16. The address calculation uses unsigned 32-bit arithmetic and may wrap. This write precedes every low-protocol invocation.

Before F-D13, two values are established:

- A signed 16-bit value formed by converting the highest byte of the storage reference’s unsigned 32-bit conversion to plain character, then to signed 16 bits.
- A signed 32-bit word read at numeric address fourth argument plus 48.

The character-derived value comes from reference bits, not a memory read through that reference. The word-read address uses signed addition and requires representability.

The word observation follows the selector write. Overlap can therefore make the write affect the observed word.

F-D13 receives an unsigned 32-bit argument containing original selector bits 8 through 19 in positions 20 through 31; every other bit is zero. Its destination is entry-context-relative. F-D14 follows.

### Low protocol: publication and halfword observation

After F-D14 returns, these direct accesses occur in order:

1. The retained character-derived signed 16-bit value is assigned at numeric address 197.
2. An associated 16-bit output from F-D14 is written at storage offset 32.
3. An unsigned 16-bit halfword is read at numeric address retained signed word plus 67.

The destination type at address 197 is unavailable. Its assignment conversion, write width, and affected byte range are **documented_only**. A 16-bit source does not prove a 16-bit write. The odd destination address does not establish valid alignment.

The halfword-read address requires representable signed addition. It depends on the retained word, not a new observation of the word’s original storage.

Both preceding writes can affect the halfword observation through overlap. Complete overlap analysis is unavailable without the address-197 destination type.

The halfword observation precedes F-D15, which receives 33. F-D16 then receives zero. Its signed 32-bit return, minus 113, is passed to F-D17. That subtraction requires representability.

### Low protocol: wide-result processing

F-D17 supplies a 64-bit quantity used in three distinct ways:

| Use | Interpretation |
|---|---|
| First argument to F-D18 | Conversion of the complete 64-bit quantity to signed 32 bits |
| Second argument to F-D18 | Logical extraction of the upper 32 bits, conversion to signed 32 bits, then signed right shift by 20 |
| Retained product | The same converted signed upper portion multiplied by 268,435,456 using signed 32-bit arithmetic |

Conversion of the complete quantity is not unconditionally equivalent to selecting its low 32 bits. Out-of-range signed conversion behavior remains unresolved.

The product is representable exactly when the converted upper portion lies between −8 and 7 inclusive. Outside that interval, wrapped continuation is not established.

After forming the product, the operation writes a 16-bit zero at numeric address retained unsigned halfword plus 32. This address ranges from 32 through 65,567. The halfword is not reinterpreted as signed.

The zero write precedes F-D18. After F-D18 returns, a 32-bit value of 149 is written at numeric address retained product plus 84. That addition is representable for every representable product identified above.

F-D19 follows the write. F-D20 receives zero and the retained product—not the write address—and returns a signed 32-bit value. F-D21 receives that return plus 89, requiring representable signed addition.

Neither the retained halfword nor the product is refreshed from memory.

### Low protocol: exceptional endpoint

A further indirect invocation, F-D22, is represented through the exceptional operation’s result. Its reachability depends on that operation producing a continuation and usable destination.

An annotation describes the endpoint as non-returning, but does not establish exception delivery, interception, resumption, or destination production. Consequently:

- Ordinary low-protocol completion is not established.
- An unconditional runtime non-return guarantee is not independently established.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes valid reached accesses, applicable arithmetic and conversions, compatible invocations, and required dependency returns.

1. **Selection boundary.** Selector 89 selects the low protocol; selector 90 selects the high protocol.

2. **Wrapped opening address.** If selector 0xFFFFFFFF converts to signed −1, the low protocol writes the complete selector at address 15.

3. **Field and argument consistency.** Second argument 65,536 produces 1,048,576 for offset 4 and F-D02’s first argument. The dependency argument is not read back from the field.

4. **Retained character.** An overlapping later field write cannot replace the observed character. Under signed-character interpretation and arithmetic right shift, observed −128 contributes −1 to F-D05; a nonnegative character contributes zero.

5. **Logical-shift boundary.** Associated F-D02 outputs 0x0001FFFF and 0x00020000 produce F-D03 arguments zero and one.

6. **Fixed target identity.** If the high pipeline reaches both F-D06 and F-D08, both invoke numeric destination 0x08573EB1, despite their different argument roles.

7. **Relative target distinction.** Resolving the entry invocation basis resolves F-D01 and F-D13 through their respective offsets. It does not by itself resolve F-D07, whose target instead depends on F-A01.

8. **Unknown assignment extent.** Highest reference byte 0x80 can yield 128 or −128 under applicable plain-character rules. Neither result determines the assignment width at address 197.

9. **Retained addressing.** Changing the original word’s storage after observation does not change the later halfword address. Changing bytes at that address before observation can change the halfword.

10. **Unsigned halfword boundary.** Retained halfword 0xFFFF directs the zero write to address 65,567, not an address derived from signed negative one.

11. **Distinct wide conversions.** For result 0x0000000100000002, the extracted upper portion is 1. F-D18’s first argument is 2 only if the complete-quantity conversion produces 2 under applicable rules.

12. **Product versus destination.** Converted upper portion 1 gives product 268,435,456. The value 149 is written at address 268,435,540; F-D20 receives 268,435,456 as its second argument.

13. **Product bounds.** Converted upper portions −8 and 7 permit representable products. Portions −9 and 8 do not establish modular continuation.

14. **Partial progress.** If F-D15 does not return, the selector write, address-197 assignment, offset-32 write, and halfword observation have occurred. The halfword-directed zero write has not.

15. **Endpoint distinction.** Return from F-D21 proves neither invocation of F-D22 nor ordinary return from F-b89f00592152.
