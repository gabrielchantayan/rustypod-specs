# F-cb070e01b6e4

## Purpose

F-cb070e01b6e4 performs an unconditional indirect operation on an object obtained from F-5fc88e95783f, then conditionally invokes an indirect operation on its own receiver.

The condition uses the low eight bits of a receiver word and, only when those bits are zero, a separate receiver byte. If either tested value is nonzero, the receiver operation is invoked. On ordinary completion, the function returns a 32-bit zero regardless of the return values of the invoked operations.

This is a static behavioral contract. No runtime tests have been performed. The business meaning of the two operations and the receiver fields is not established.

## Interface

### Inputs

The function has two explicit inputs:

1. **Receiver:** an address used as the base of a word-addressed object. The function uses this address for field reads and, conditionally, as the first argument of an indirect operation.
2. **Forwarded value:** an opaque 32-bit value passed unchanged to the operation on the object returned by F-5fc88e95783f. The function does not interpret it as a number, pointer, handle, or ownership token.

There is no explicit length, allocation size, status destination, or error-output argument.

### Result

On a path where all required accesses and calls complete normally, the result is the 32-bit value zero.

The results of F-5fc88e95783f and the first indirect operation have different roles:

- The result of F-5fc88e95783f supplies the address used for the first indirect dispatch.
- The return value of that indirect operation is discarded.
- The return value of the optional receiver operation is also discarded.

There is no result-dependent error translation.

### Width and layout model

The supplied representation uses four-byte words and 32-bit address arithmetic. The relevant layout is:

| Object | Byte offset | Use |
|---|---:|---|
| Object returned by F-5fc88e95783f | 0 | Read to obtain an indirect-dispatch table address |
| That dispatch table | 16 | Callable entry used for the unconditional operation |
| Receiver | 36 | Four-byte word read; its low eight value bits form the primary condition |
| Receiver | 37 | One-byte secondary condition, read only if the primary condition is zero |
| Receiver | 0 | Read to obtain its dispatch-table address, only when the receiver operation is required |
| Receiver dispatch table | 40 | Callable entry used for the conditional receiver operation |

The primary test is expressed as a word read followed by conversion to a character-sized value. It must not automatically be reinterpreted as a one-byte read at offset 36. In particular, the represented read spans offsets 36 through 39.

The word at offset 36 and the byte at offset 37 occupy overlapping storage. That overlap does not, by itself, establish that the secondary byte contributes to the primary test: the primary test uses the low eight **value bits**, whose physical byte position depends on byte order.

### Preconditions

For defined ordinary execution, the following must hold at the points where each resource is used:

The contract does not establish alignment requirements beyond those imposed by the actual execution environment. It does not establish behavior for invalid addresses, missing dispatch entries, incompatible call targets, or expired object lifetimes.

## Behavior

### Unconditional acquisition and dispatch

The first operation is a call to F-5fc88e95783f with no explicit arguments.

Its returned address is then used as an object address. The function reads the object's dispatch-table address and selects the callable entry at byte offset 16 within that table.

That entry is invoked with three explicit arguments, in this order:

1. The object address returned by F-5fc88e95783f.
2. The caller-supplied 32-bit forwarded value, unchanged.
3. Zero.

The supplied representation establishes a literal zero as the third argument. It does not establish whether the callee interprets it as a flag, integer, null address, or another category of value.

No null check, readiness check, or status check precedes this dispatch. The function does not inspect the operation's result before proceeding.

### Receiver condition

Only after the unconditional indirect operation returns does the function inspect the receiver condition.

It reads the four-byte receiver word at byte offset 36 and reduces it to a character-sized value. For the zero/nonzero decision, the relevant part is the low eight bits under the represented machine conversion. Signedness does not affect that decision: any nonzero eight-bit result qualifies.

The subsequent behavior is short-circuited:

- If the primary value is nonzero, the separate byte at offset 37 is not read for the condition. The receiver operation is required.
- If the primary value is zero, the byte at offset 37 is read.
- If that secondary byte is nonzero, the receiver operation is required.
- If both tested values are zero, the receiver operation is skipped.

Consequently, nonzero bits elsewhere in the four-byte word do not necessarily make the primary condition true. They matter only if they contribute to the low eight bits selected by the conversion or to the separately read byte at offset 37.

The timing of these reads is material. The function does not capture the receiver condition before calling F-5fc88e95783f or before invoking the unconditional operation. If either preceding call changes receiver storage through an alias, the later condition is evaluated from the storage then encountered.

### Conditional receiver dispatch

When the condition requires the receiver operation, the function reads the dispatch-table address from receiver offset 0 and selects the callable entry at byte offset 40 within that table.

It invokes that entry with the receiver address as its sole explicit argument.

There is at most one such invocation per ordinary execution. The function does not recheck the condition afterward, retry the operation, or use its return value.

If both tested values are zero, this dispatch-table lookup and call are omitted.

### Completion

After the condition has been evaluated and any required receiver operation has returned, the function returns a 32-bit zero.

There is no alternative explicit return value. There is also no local recovery path for a dependency that fails to return normally.

### Ordering

On a normally completing execution, the significant ordering is:

1. F-5fc88e95783f completes.
2. The acquired object's indirect operation completes.
3. The receiver word is read and its primary value tested.
4. If needed, the secondary receiver byte is read and tested.
5. If required, the receiver's indirect operation completes.
6. Zero is returned.

The receiver's dispatch-table address is not captured before the unconditional operation. If that earlier operation changes the receiver's dispatch state through an alias, the conditional dispatch uses the state encountered afterward.

No atomicity, locking, memory barrier, or thread-safety mechanism is established. Concurrent mutation is therefore outside the supported deterministic examples below unless an external synchronization contract supplies the missing guarantees.
