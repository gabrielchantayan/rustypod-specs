# F-7be55d1d3d55

## Purpose

F-7be55d1d3d55 has two represented behaviors: a finite sequence of address-dependent writes followed by an indirect transfer, and an indefinitely repeated processing sequence involving memory accesses, dependency calls, and a conditional software breakpoint.

No application-level purpose is established. In particular, the available evidence does not establish allocation, object construction, device control, validation, or recovery as responsibilities.

This contract describes observable access ordering and state transitions. It does not supply machine semantics where the static evidence is incomplete. Unresolved requirements are marked **documented_only**. No runtime tests have been performed.

Successful continuation requires every executed memory access and indirect transfer to be valid under the applicable machine model. There are no represented bounds, alignment, permission, null-address, or dependency-success checks. Address zero is not excluded.

## Behavior

### Entry and path selection

The first direct memory operation writes the seed as a 32-bit word to output offset 0.

The finite path is selected only when the scale’s high bit is set and its unsigned doubled value is nonzero. All other scales select processing. Consequently, `0x80000000` selects processing, whereas `0x80000001` selects the finite path with an initial byte destination of address 2.

A fault after the entry write does not undo that write.

### Finite path

The finite path uses the unsigned doubled scale as its first destination. It writes the byte payload there. Advancing that destination by the seed produces a second destination.

The next ordered effects are:

| Access location | Width | Written value |
|---|---:|---|
| Incoming pointer plus 2 | 16 bits | Low 16 bits of the base |
| Second destination plus `0x40` | 32 bits | Second destination’s address representation |
| Second destination | 16 bits | Low 16 bits of that address |
| Address obtained from scale times 32 plus `0x11` | 32 bits | That calculated address |

The last calculation begins with unsigned arithmetic; its subsequent signed address representation remains machine-dependent.

A masked value is then formed from the numeric operand and the second destination’s 32-bit address representation. Doubling this mask uses unsigned arithmetic. The doubled result is interpreted as signed and right-shifted by 10 to obtain another destination.

Two consecutive 16-bit writes place that destination’s low 16 bits at the destination itself. Both writes are required, even when they leave identical ordinary-memory contents. A subsequent 16-bit write places `0x0050` at the masked value plus 2.

For the remaining global operations, this contract assigns storage-role labels:

- **G-A:** first finite-path global assignment.
- **G-B:** shared finite-path and extended-processing assignment destination.
- **G-C:** final finite-path global assignment.
- **G-D:** global value subsequently used as an address.
- **G-E:** separately represented 24-bit operand used during extended processing.

These labels do not imply separate allocations or nonoverlapping storage.

The finite path assigns `0xf430` to G-A, `0x0897f430` to G-B, and zero to G-C, in that order. It then reads G-D, converts the obtained value to a 32-bit destination, and writes `0x0897f430` through that destination as an explicitly 32-bit access.

The widths of the three global assignments and the physical width of the G-D read are **documented_only**. Their constants do not establish their destination widths. The G-D read occurs after all three assignments and can observe their effects if storage overlaps.

F-D01 is then invoked through a target derived from the transfer displacement. Its four represented arguments are:

1. The G-D-derived destination advanced by 16 bytes, interpreted as signed, then multiplied by `0x01000000`.
2. Zero.
3. `0x5000`.
4. `0x56`.

The first argument has unresolved signed-overflow and address-conversion cases. No later direct work is represented. If F-D01 returns normally, this function returns.

### Processing state and initialization

Processing uses several evolving roles:

| State role | Initial relationship |
|---|---|
| Current pointer | Incoming pointer |
| Working quantity | Eight times the numeric operand, minus two |
| Accumulator | Seed bitwise-AND numeric operand |
| Increment | Numeric operand times `0x02000000` |
| Primary destination | Numeric operand times `0x01000000` |
| Accumulator destination | Initially equal to the primary destination |
| Word payload | Numeric operand shifted left by 28 |

These initial numerical relationships use unsigned 32-bit arithmetic. The two destination roles remain distinct even though they initially coincide.

Initialization first writes the 32-bit value `0x40` at base plus `0x28`, then the 32-bit base value at base plus `0x2c`.

It next combines the incoming pointer’s signed representation, the displacement, and 8. At twice that intermediate value it writes the intermediate value as a 32-bit word. Signed overflow and address interpretation are unresolved.

Finally, output offset 4 receives the numeric operand as a 32-bit word, and primary-destination offset `0x14` receives the working quantity’s low byte. This completes initialization; subsequent repetition does not restore these initial values.

### Outer write transaction

The outer transaction performs three writes at the primary destination, in order: an 8-bit zero, the working quantity’s low 16 bits, and the 32-bit word payload.

It then adds the increment to the accumulator using unsigned arithmetic and writes the updated accumulator as a 32-bit word at the accumulator destination.

When the destinations coincide in ordinary memory, the accumulator write determines the final word. Earlier accesses remain observable through device behavior, faults, or overlapping storage.

The outer transaction leads to a dependency transaction with argument zero.

### Dependency transaction and short retry

At the start of every dependency transaction, the low byte of the current increment is captured. This captured byte is retained separately from the increment, which is subsequently replaced by a memory-read result.

F-D02 receives one represented 32-bit argument and returns a represented 64-bit result. Before another dependency is invoked, the function performs the following ordered accesses:

1. A 16-bit write through the result’s low-half address, containing that address’s low 16 bits.
2. A 32-bit self-value write at the unsigned product of the working quantity and `0x40`.
3. A 32-bit read through the current pointer, whose result becomes the increment.
4. A 16-bit write at working quantity plus 4, containing the previous current pointer’s low 16 bits plus 4, narrowed to 16 bits.
5. A pointer-width read at the result’s high-half address plus `0x50`, establishing the replacement current pointer.

The last address calculation passes through signed representation and addition. Its exceptional cases are **documented_only**.

This order matters under aliasing. The current-pointer read can observe the preceding self-value write. The replacement-pointer read can observe the intervening 16-bit write.

F-D03 and F-D04 follow in that order with no represented arguments. F-D05 then receives the retained 32-bit word read through the previous current pointer. F-D06 receives that same word logically shifted right by 3 and returns a represented 64-bit result.

The signed interpretation of F-D06’s low half, multiplied by 32, forms a candidate address. A 32-bit write of the candidate’s own address representation occurs at that address **before** the unsigned candidate is compared with `0x14`.

A candidate below `0x14` causes a short retry: dependency processing repeats with argument zero, without outer writes. The replacement current pointer, new increment, and other surviving state remain in effect.

If signed multiplication is interpreted as retaining the low 32 bits, candidate addresses are multiples of 32, so only zero satisfies this comparison. That conclusion is conditional on the arithmetic interpretation; it is not a portable signed-overflow rule.

### Extended processing

A candidate whose unsigned representation is at least `0x14` enters extended processing.

Candidate offset `0x58` first receives the working quantity as a 32-bit word. Working-quantity offset `0x0e` then receives the current pointer’s low 16 bits. Four times the working quantity, using an unsigned left shift, becomes the increment.

G-B next receives a combined value whose upper 24 bits come from G-E and whose low byte is the byte captured before F-D02. The right-hand side is a 32-bit value. The destination assignment width is not established.

G-E is obtained at this point: after F-D02 through F-D06 and after the two extended-processing writes, but before F-D07. It is not an established entry snapshot. Its physical read width, overlap with G-B, and preservation across earlier calls are **documented_only**.

F-D07 receives the current pointer’s unsigned representation logically shifted right by 2. F-D08 follows with no represented arguments and returns a represented 64-bit result.

The next ordered accesses are:

| Location | Width | Written value |
|---|---:|---|
| Twice F-D08’s low-half address | 8 bits | Captured byte |
| F-D08’s low-half address plus 8 | 8 bits | Low byte of F-D08’s high half |
| Twice the existing accumulator | 32 bits | F-D06’s high-half address |
| F-D08’s low-half address | 64 bits | Complete F-D08 result |

The first doubling uses signed arithmetic; accumulator doubling uses unsigned arithmetic. Overlap and byte order can affect the resulting memory contents.

F-D08’s high half becomes the accumulator destination. F-D06’s high-half address, shifted left by two using signed representation, becomes the accumulator. The current pointer, shifted left by eight using signed representation, becomes the working quantity.

Three consecutive 32-bit writes at F-D06’s high-half address then store, at offsets 0, 4, and 8 respectively:

- The increment derived from the preceding working quantity.
- The newly derived working quantity.
- The current pointer’s address representation.

The word payload becomes the increment multiplied by `0x100`, using unsigned arithmetic.

### Continuation and breakpoint behavior

The continuation selector is derived from the current pointer by a signed left shift of 31, a signed right shift of 32, conversion to unsigned, and a logical right shift of 20.

The signed shift by 32 has no established portable result for the represented width. Acceptance must not replace this expression with an assumed pointer-bit test.

If the selector resolves to zero, the primary destination becomes zero and the outer transaction repeats. The accumulator destination remains F-D08’s high-half address; it does not become zero merely because the primary destination does.

If the selector resolves to nonzero, the function writes it as a 32-bit word at word-payload plus `0x20`. It then selects a different F-D02 target configuration and prepares an argument from the signed interpretation of the word payload right-shifted by 29. Software breakpoint number 4 executes.

Only if execution resumes does the signed interpretation of F-D08’s high half, right-shifted by 18, become the working quantity. Dependency processing then resumes directly at F-D02, without outer writes.

F-D02 has distinct represented target configurations for initial entry, short retry, outer restart, and breakpoint resumption. Equal arguments do not establish identical targets. No normal exit is represented for processing.

## Acceptance examples

These are conditional static requirements, not executed tests.

1. **Entry ordering.** With writable output storage, the seed write occurs before either path’s later destination accesses. A subsequent fault does not imply rollback.

2. **Branch boundary.** Scale `0x80000000` selects processing because its unsigned double is zero. Scale `0x80000001` selects the finite path and first attempts a byte write at address 2 after the entry write.

3. **Repeated observable access.** A finite execution reaching the shift-derived destination performs two separate 16-bit writes there. An implementation that merges them need not preserve device-visible behavior.

4. **Global overlap.** G-A, G-B, and G-C receive their respective assignment values before G-D is read. If they overlap G-D, that read may reflect the assignments. Exact affected bytes cannot be required without access-width and layout evidence.

5. **Zero candidate.** If F-D06’s low half is zero, the candidate is zero without multiplication overflow. A 32-bit write at address zero precedes the short-retry decision. If that write faults, retry is not reached.

6. **Overflow-dependent candidate.** For F-D06 low half `0x08000000`, a machine interpretation that wraps the signed product to zero produces a short retry after the address-zero write. The static representation alone does not require that arithmetic interpretation.

7. **Captured-byte lifetime.** If the increment ends in `0xa5` before F-D02 and the later current-pointer read yields a word ending in `0x3c`, extended processing uses `0xa5` for both the G-B combination and the first F-D08-derived byte write.

8. **Combination value and observation time.** If G-E supplies `0x123456` when obtained and the captured byte is `0xa5`, the combined value is `0x123456a5`. Its destination byte footprint remains unresolved. An earlier dependency’s change to G-E is relevant if no intervening effect replaces it.

9. **Separate restart destinations.** When the selector resolves to zero, the next primary writes target address zero. The subsequent accumulator write still targets F-D08’s high-half address, unless that address also happens to be zero.

10. **Resumed breakpoint path.** When the selector resolves to nonzero and breakpoint handling resumes, F-D02 receives the signed-shift-derived argument through the breakpoint-specific configuration. No outer transaction intervenes.
