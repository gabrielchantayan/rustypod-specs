# F-997af9da7975

## Purpose

The indirect-operation path first stores a caller-supplied 32-bit value into the supplied object, obtains another object through a dependency, and dispatches through that returned object's table.

These are established control-flow effects. The meanings of the predicates, stored fields, status values, and preparation/finalization operations are not established. In particular, the evidence does not establish that this function implements locking, reference counting, resource release, or any specific application operation.

## Behavior

### Preparation precedes all selection

The function first copies the fourth argument into a local 32-bit storage slot. It then calls **F-3794f888f18b**, supplying:

1. The address of that storage.
2. The first argument.

The first predicate is not evaluated until this preparation call returns normally. Because the storage address is supplied, preparation may replace its contents. Finalization therefore receives the slot's later value, not necessarily the original fourth argument.

No preservation guarantee for the supplied object, globals, or other accessible state can be inferred from this call.

### Initial rejection

After preparation, the function calls **F-867a1fcaaaab** with the first argument.

If that dependency returns any nonzero value:

- The secondary predicate is not called by this function.
- None of the object-field accesses listed above is performed directly by this function.
- F-fd58bea73663 is called with the current contents of the preparation storage.
- The function returns 32-bit value **2**, provided finalization returns normally.

The predicate's nonzero magnitude and sign do not affect this selection.

### Stored-result selection

If the initial predicate returns zero, the function calls **F-56e2874b0016** with the first argument.

If this second predicate returns zero:

- The function reads the 32-bit field at object offset **+0x1c**.
- It retains that value as the selected result.
- It calls F-fd58bea73663 with the current preparation-storage value.
- It returns the retained result if finalization returns normally.

This path does not directly inspect the gate byte at +0x14, write +0x20, call F-a6226d4de001, or perform the indirect dispatch.

The result is read after both predicates have returned. It is not a snapshot of the field at entry. Any changes those dependencies make to the field can affect the returned value.

### Secondary rejection

If the second predicate returns nonzero, the function next reads the single byte at object offset **+0x14**.

- The function does not perform its +0x20 write.
- It does not call F-a6226d4de001 or the indirect target.
- It calls F-fd58bea73663 with the current preparation-storage value.
- It returns 32-bit value **0x15** if finalization returns normally.

Only zero versus nonzero matters. A byte whose high bit is set is still nonzero; no signed ordering comparison is involved.

1. The second argument is written as a 32-bit value to object offset **+0x20**.
2. **F-a6226d4de001** is called with the first argument and numeric argument **1**.
3. The returned address is used as an object address for indirect dispatch.
4. The function obtains that object's table reference from offset zero and selects the callable entry at table byte offset **+0x28**.

   - The object returned by F-a6226d4de001.

The +0x20 argument is a later field read, not a guaranteed direct forwarding of the second argument. F-a6226d4de001 executes between the write and that read and may alter the field. Its behavior is unknown.

Likewise, +0x18 is read after acquisition. No entry-time snapshot of that field is established.

The evidence establishes that acquisition precedes the dispatch-related reads and call. It does not establish a portable relative evaluation order among the callable-entry lookup and the two original-object argument reads. A contract must not impose a finer order without additional evidence.
