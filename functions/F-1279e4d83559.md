# F-1279e4d83559

## Purpose

F-1279e4d83559 performs an ordered series of memory writes using four explicit argument words, two additional ambient machine words, an incoming carry bit, and seven fixed-location memory cells. It then invokes an unresolved indirect dependency with one visibly constructed argument.

The supplied representation establishes a sequence of arithmetic operations, memory accesses, and an indirect transfer. It does not establish a higher-level purpose such as initialization, decoding, device control, or object mutation. In particular, the unusual address calculations are not evidence that their destinations are valid buffers or ordinary writable memory.

This contract describes the supplied representation independently of any intended algorithm. It does not claim that the recovered function boundary, calling convention, or indirect-transfer interpretation has been verified against executable behavior.

## Interface

### Explicit arguments and result

The visible interface has four explicit arguments:

| Argument | Visible width | Direct use |
|---|---:|---|
| Argument 1 | 32 bits | No explicit use in the visible body |
| Argument 2 | 32 bits | No explicit use in the visible body |
| Argument 3 | 32 bits | Address arithmetic, a byte value, and a stored word value |
| Argument 4 | 32 bits | Base for the final halfword write |

No result value is explicitly returned. The visible representation invokes an indirect dependency and then returns if that invocation returns normally.

The absence of explicit uses of Arguments 1 and 2 does not prove that their incoming register or stack contents are unavailable to the indirect dependency. Its complete machine-level interface is unknown.

### Additional entry state

The body also depends on:

- An **ambient address word**, 32 bits wide. It supplies both addresses and truncated halfword values.
- An **ambient comparison word**, 32 bits wide, interpreted as unsigned for one comparison.
- An **incoming carry bit**, used as zero or one in one addition.
- An **unresolved indirect destination**, whose origin and validity are not established.

These are effective inputs even though they are not represented as ordinary parameters.

### Fixed-location memory inputs

| Cell | Visible read width | Use |
|---|---:|---|
| Cell A | 32 bits | Initial byte payload and unsigned-comparison operand |

### Widths and memory representation

The visible operations use:

- Byte writes: 8 bits.
- Halfword writes: 16 bits.
- Word writes: 32 bits.
- Working words and address expressions: apparently 32 bits.

A byte or halfword conversion retains the low 8 or 16 bits respectively. Signedness does not change those retained bit patterns.

The incoming comparison is explicitly unsigned. Other arithmetic is represented using a mixture of signed and unsigned 32-bit expressions. Exact overflow behavior is not established independently of the supplied representation; this matters for addition, multiplication, doubling, and effective-address formation.

Endianness and unaligned-access behavior are not supplied.

## Behavior

### Derived values

For clarity, the following names describe values, not additional storage:

- **Adjusted argument**: Argument 3 plus hexadecimal `0x41`, plus the incoming carry bit.
- **Squared displacement**: the initially read value of Cell B multiplied by itself.
- **Comparison increment**: one when the ambient comparison word is unsigned-less-than-or-equal-to the initially read value of Cell A; otherwise zero.
- **Late offset**: the value read from Cell F plus hexadecimal `0x4E`, plus the comparison increment.
- **Transfer argument**: the bitwise inclusive OR of the late offset and the captured value of Cell G.

The comparison uses the full initial word from Cell A, not its truncated byte and not a later reread of that cell.

For ordinary inputs whose arithmetic is representable without overflow, these definitions are direct. If the execution environment uses wrapping 32-bit machine arithmetic, the corresponding results are reduced to 32 bits. That wrapping interpretation is conditional, not an independently verified property of the executable.

### Ordered memory operations

Subject to successful execution of every preceding access, the visible body performs the following sequence.

1. **Capture Cell A and Cell B.**  
   Read Cell A first, then Cell B, as 32-bit values.

2. **Write an ambient-derived halfword.**  
   At the address given by the ambient address word plus `0x44`, write the low 16 bits of the ambient address word.

3. **Calculate the adjusted argument and write an argument-derived byte.**  
   Form the adjusted argument using the incoming carry bit. At the address Argument 3 plus the captured, unsquared Cell B value, write the low 8 bits of Argument 3.

4. **Capture Cell C and calculate the squared displacement.**  
   Read Cell C after the preceding byte write. Calculate the squared displacement from the already captured Cell B value. The square does not cause another read of Cell B.

5. **Perform four writes using the adjusted argument and squared displacement.**  
   Their order is:

   | Order | Destination | Width | Payload |
   |---:|---|---:|---|
   | 1 | Adjusted argument + squared displacement | 16 bits | Low 16 bits of squared displacement |
   | 2 | Captured Cell C + adjusted argument | 32 bits | Adjusted argument |
   | 3 | Argument 3 + squared displacement | 16 bits | Low 16 bits of ambient address word |
   | 4 | Squared displacement + ambient address word | 16 bits | Low 16 bits of squared displacement |

6. **Capture three later memory values.**  
   Read Cell D, then Cell E, then Cell F. These reads occur after all four writes above. Any overlap between those writes and these cells therefore affects the values subsequently used.

7. **Write a byte at a doubled destination.**  
   At twice the captured Cell F value, write the low 8 bits of the initially captured Cell A value.

8. **Write a constant halfword at another doubled destination.**  
   At twice the captured Cell E value, write the 16-bit value `0x004E`.

9. **Capture Cell G and calculate the late offset.**  
   Read Cell G after both preceding writes. Calculate the late offset from captured Cell F and the unsigned comparison increment.

10. **Write a late-offset byte.**  
    Write the low 8 bits of the late offset at an address formed from Cell G’s value plus the late offset.

    The supplied representation contains both a capture of Cell G for the eventual transfer argument and another reference to Cell G in this destination expression. Under ordinary stable-memory conditions they have the same value. Whether these represent distinct physical loads, and their behavior with volatile or asynchronously modified memory, is not established.

11. **Write a word at the earlier doubled destination.**  
    At twice the captured Cell F value, write the captured 32-bit value from Cell D.

    This has the same starting address as step 7. It supersedes that earlier byte in ordinary memory, but the earlier byte access still occurs and may be externally observable.

12. **Perform the final halfword write.**  
    At Argument 4 plus the captured Cell F value, write the low 16 bits of that captured Cell F value.

13. **Invoke the unresolved indirect dependency.**  
    Invoke F-UNRESOLVED-01 with the transfer argument as its one visibly supplied argument. If it returns normally, the visible body then returns without further explicit work.

### Aliasing and ordering

No non-overlap requirement is visible. Computed destinations may overlap:

- Other computed destinations.
- Fixed-location input cells.
- Storage relevant to the indirect destination.
- Memory whose access has device-specific effects.

Where writes overlap ordinary memory, the later write determines the final bytes in the overlap. Where an earlier write overlaps a cell read later, the later read obtains the resulting contents, subject to the platform’s memory model.

The two writes beginning at twice captured Cell F must not be collapsed into a single final word write. Their access widths and their position relative to the intervening operations are part of the visible behavior.

## Side effects

Before invoking the indirect dependency, the body explicitly attempts:

- Three byte writes.
- Six halfword writes.
- Two word writes.

Those eleven writes need not target eleven distinct regions.

There is no visible allocation, deallocation, ownership transfer, lock operation, validation branch, or error-reporting operation. Reading a word and later storing it does not establish ownership of memory identified by that word.

The indirect dependency may have additional side effects. No assumption is justified that it preserves global memory, retains or releases resources, preserves ambient registers, or returns.

### Preconditions and failures

Normal completion requires:

- Every executed fixed-cell read to be permitted.
- Every computed write to be permitted at its actual width.
- Applicable alignment requirements to be satisfied, or the platform to support those accesses.
- A valid indirect destination with a compatible calling convention.

The body contains no visible recovery or rollback. If an access faults, earlier completed writes are not undone by this body. The exact exception, signal, trap, or faulting-write atomicity is platform-dependent.

Neither zero nor a negative signed value receives special treatment. A zero-valued input may still generate a nonzero destination; doubling a zero-valued Cell E or Cell F produces a zero destination before any target-specific address interpretation.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

### Carry affects the adjusted argument

With Argument 3 equal to `0x1000`, the adjusted argument is:

- `0x1041` when incoming carry is zero.
- `0x1042` when incoming carry is one.

The earlier byte destination using unsquared Cell B remains unchanged between those cases. The adjusted-argument destinations and stored adjusted word change accordingly, assuming no resulting fault or alias-induced change to later inputs.

### Equality includes the comparison increment

If captured Cell F is `0x100` and initial Cell A is `0x200`:

- Ambient comparison word `0x200` gives late offset `0x14F`.
- Ambient comparison word `0x201` gives late offset `0x14E`.

The corresponding byte payloads are `0x4F` and `0x4E`. This criterion distinguishes unsigned “less than or equal” from strict “less than.”

### Incoming values are not uniformly snapshotted

If an early computed write overlaps Cell D, its resulting contents are eligible to become the captured Cell D value because that cell is read later.

By contrast, overwriting Cell A after its initial read does not change either the captured byte payload or the comparison operand used later.

### The earlier byte write remains observable

Assume captured Cell F is `0x1000`, initial Cell A ends in byte `0x5A`, and captured Cell D is `0x11223344`.

The body first writes byte `0x5A` at address `0x2000`. Later it writes the word `0x11223344` at the same starting address. An access observer must be able to distinguish these two writes and their widths. The final four-byte arrangement depends on endianness.

### The transfer argument uses OR

If the late offset is `0x140` and captured Cell G is `0x1000`, the visible transfer argument is `0x1140`.

That argument is formed by bitwise OR, not by adding Cell G to the late offset. The late byte-write address uses addition instead; those two operations must not be conflated when their operands have overlapping set bits.

### Failure preserves the completed prefix

If the final halfword write faults after all earlier accesses succeed, the visible body has already performed the preceding ten writes. No rollback is specified, and the indirect invocation has not yet occurred.
