# F-e03d34f0b7e4

## Purpose

F-e03d34f0b7e4 modifies one byte in caller-provided storage. Its effect combines a selected-bit clear with a shifted contribution from an unrestricted integer input. The represented operation includes an intermediate destination write before the final destination write.

**Established static behavior:** the input value is not normalized to a Boolean. Depending on its value and the shift count, it can set several destination bits. The operation is therefore not generally equivalent to assigning a single flag.

**Inferred intent:** the function appears suitable for updating a flag in a packed byte when callers supply only zero or one and a stable bit position from zero through seven. Those caller restrictions are not enforced by this function.

This contract describes the supplied body’s memory accesses and conditional arithmetic behavior. It does not establish a particular instruction sequence or behavior for invalid arithmetic or inaccessible memory. No runtime tests have been performed.

## Behavior

### Effective byte update

For a stable position from zero through seven, the operation first removes the selected bit from the original destination value. The final destination value retains that cleared result and adds any set bits contributed by the shifted input.

This distinction matters for inputs other than zero or one:

- Zero contributes no set bits, so the selected bit remains cleared.
- One contributes exactly the selected bit, so that bit becomes set.
- A larger input can contribute additional set bits above the selected position.
- A zero bit in the contribution does not clear an existing destination bit, except for the independently selected bit cleared earlier.

The contribution is limited to its low eight bits only **after** the integer shift. Bits outside the destination byte are discarded. This narrowing does not make an otherwise invalid integer shift valid.

For a nonnegative input and a defined shift, the contribution corresponds to the low eight bits of the input scaled by the appropriate power of two. The function does not reject an input merely because that contribution contains multiple set bits.

### Intermediate state and ordering

The represented operation has two destination assignments. Its access ordering is:

| Observation | Ordering guarantee |
|---|---|
| Original destination read | Before the intermediate destination write |
| First position read | Before the intermediate destination write; its order relative to the original destination read is not established |
| Intermediate destination write | Before the second position read |
| Second position read | Before the final destination write |
| Final destination write | Uses the retained intermediate byte rather than an explicit destination reread |

The intermediate byte has the selected bit cleared when the first position identifies a bit from zero through seven. This intermediate assignment exists even when its value equals the original destination.

The second position is read afresh. The function does not require it to equal the first position, compare the two readings, or retry if they differ.

The final assignment also exists when its value equals the intermediate byte. There is no early exit for an unchanged value.

These are source-level access properties. The supplied accesses are not declared volatile or atomic, so the material does not prove that an optimized executable performs two externally observable physical stores or two physical position loads.

### Independently sampled positions

The first position controls the clearing operation; the second controls placement of the input contribution.

If a valid surrounding execution permits different values at the two reads, the byte can therefore lose a bit at one position and gain bits at another. It is not an update based on a single retained position.

The function provides no synchronization establishing that such changes are safe. The independent reads do not themselves authorize unsynchronized concurrent writes to the descriptor.

### Positions above seven

A position outside the destination’s bit range is not necessarily outside the integer shift range.

For a position of eight or greater, a valid shift of integer one has no set bit within the low eight bits. The intermediate assignment consequently leaves the destination byte unchanged.

If the second position is also eight or greater and shifting the supplied value is defined, a nonnegative shifted value likewise contributes no low-byte bits. The final destination then remains unchanged.

This is an arithmetic consequence, not validation or an explicit no-operation branch. Both represented destination assignments remain present.

The same conclusion cannot be extended to negative counts, counts at least as large as the relevant integer width, or shifts violating signed representability requirements.

### Arithmetic boundaries

Both shifts occur at integer width before byte narrowing.

Important boundaries are:

- A negative signed position is not assigned a portable shift result.
- A count must be smaller than the width of the promoted left operand.
- A negative input is not assigned a defined result by this contract without applicable language-rule evidence.
- Even with a permitted count, a nonnegative input may exceed the range allowed for a signed left shift.
- The shift used to select the clearing bit has its own signed-shift boundary.
- No processor-specific masking of excessive shift counts is established.

For an illustrative signed 32-bit interpretation using strict signed-result representability requirements, shifting positive one by 31 is not a safe portable case. Smaller counts can still be invalid for sufficiently large input values.

That illustration does not establish the actual target width or resolve language-version differences at signed-shift boundaries.

## Side effects

### Memory changes

Only the destination byte is explicitly written. Its first assigned value is the cleared intermediate byte; its second assigned value includes the input contribution.

There is no explicit read of the destination between these assignments. Consequently, a destination change occurring between them is not incorporated through a fresh load. If a surrounding execution legally permits such interference, the final assignment is based on the retained intermediate value instead.

The function contains no explicit access to named global state, synchronization primitive, logging facility, or external service.

### Aliasing

No explicit non-aliasing restriction is present.

If the computed destination and position addresses coincide, the destination assignments also address the storage used for position reads. Such storage cannot be treated as a separate immutable descriptor merely because it serves that role as an input.

The second position access remains sequenced after the intermediate assignment. Whether particular aliasing inputs satisfy all arithmetic and object-access requirements must be assessed under the applicable target rules; unrestricted aliasing is not a separate safety guarantee.

### Ownership and lifetime

The caller must maintain the required storage for all accesses. The byte-level accesses establish no ownership of a larger containing object.

### Errors and completion

Under valid arithmetic and memory conditions, completion follows the final destination assignment. An invalid address may fault or otherwise invalidate execution under platform rules. Invalid shifts and invalid address arithmetic have no specified replacement result here.
