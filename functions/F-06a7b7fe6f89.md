# F-06a7b7fe6f89

## Purpose

F-06a7b7fe6f89 copies four-byte words from seven ordered source descriptors into a single contiguous destination region.

Each descriptor supplies a source address and a signed word count. A positive count contributes that many words; a zero or negative count contributes none. Contributions appear in descriptor order, with no destination padding between them.

This is a forward, word-at-a-time copy. It does not establish snapshot semantics for overlapping memory. Earlier writes can affect later source reads or descriptors that have not yet been read.

The behavior below is established from the supplied static representation unless explicitly marked as inferred or unknown. No runtime tests have been performed.

## Interface

### Invocation and result

- No returned value.
- No explicit success indicator, copied-word count, or error status.
- Inputs and outputs are supplied indirectly through global state and addressed memory.

### Implicit inputs

Two global slots provide:

1. A descriptor-table base address.
2. A destination base address.

The function reads the descriptor-table base first and the destination base second. Each is captured once for use during the invocation. These are separate reads, not an established atomic snapshot.

The global-slot locations themselves are outside the supplied behavioral description.

### Descriptor layout

The descriptor table contains exactly seven consecutive records, each eight bytes wide:

| Byte offset within a record | Width | Meaning |
|---|---:|---|
| 0 | 4 bytes | Source-address representation |
| 4 | 4 bytes | Signed word count |

Records begin at byte offsets 0, 8, 16, 24, 32, 40, and 48 from the captured table base. The last record’s count occupies bytes 52 through 55.

The count is measured in four-byte words, not bytes. The copy treats each source word as an uninterpreted four-byte value; it performs no element-level conversion, filtering, or arithmetic.

The supplied representation uses integer-based addressing and signed integer loop state. This contract describes its apparent 32-bit model: four-byte address fields, signed 32-bit counts, and signed 32-bit indices. The exact machine pointer rules and overflow behavior remain documented uncertainties.

## Behavior

### Initial state

After capturing the two base addresses, the function begins with:

- The first descriptor selected.
- Zero destination words written.

The captured destination base remains the basis for all destination accesses. The destination word position advances across descriptor boundaries; it does not restart for each source.

### Descriptor processing

All seven descriptors are visited in ascending record order.

For each descriptor, the function performs these observable reads in this order:

1. Reads the signed count from the record’s second four-byte field.
2. Reads the source-address representation from the record’s first four-byte field.

Both fields are read even when the count is zero or negative. Thus, a descriptor with no copied words still requires its two fields to be readable. Its source address is obtained, but no source data is dereferenced for that descriptor.

The captured count and source address are then used throughout that descriptor’s contribution. The function does not reread either field between its source words.

For a positive count, source words are processed in ascending order from the captured source address. Consecutive words are four bytes apart. For each word:

- Its four-byte value is read from the current source location.
- That value is written to the current destination location.
- The destination word position advances by one.

The destination location for a word is the captured destination base plus four times the number of words already written.

Only after the current descriptor’s contribution is finished does processing advance to the next descriptor.

### Counts and output size

A signed count greater than zero produces that many word copies. A count of zero or less produces none.

If descriptor contents remain unchanged until read, the total number of destination words written is the sum of the positive counts across all seven descriptors. Negative counts contribute zero, not their unsigned interpretation.

For example, counts of 2, 0, −3, 1, 0, 4, and 0 produce seven destination words, provided all accesses and arithmetic are valid.

When destination writes can change descriptor memory, the relevant counts are those actually read when each descriptor is reached. A sum computed from the table’s entry-state contents need not describe the resulting execution.

The function writes no terminator, length header, separator, or alignment padding. It does not clear destination memory after the final copied word.

### Ordering and aliasing

The copy observes memory incrementally. It does not first gather all source values or cache the entire descriptor table.

This establishes several alias-sensitive behaviors:

- A destination write may change a source word that will be read later.
- A write during one descriptor may change source data used by a later descriptor.
- A write may change a later descriptor’s count or source-address field before that descriptor is read.
- A write to a current descriptor field after its value has been captured does not replace the captured value for that descriptor.
- A write to either global base-address slot does not replace the base already captured by this invocation.

Forward overlap is therefore not equivalent to a general overlap-safe bulk move. A destination beginning inside a source range at a higher address may overwrite data before the function reads it.

These observations concern the represented access order. They do not establish language-level synchronization, atomicity, volatile-access guarantees, or the behavior of concurrent modification.

### Arithmetic boundaries

The source word position starts at zero for each descriptor and is compared with that descriptor’s signed count. The destination word position accumulates all copied words across descriptors.

For a valid signed 32-bit count, a nonpositive value does not enter the copying portion. In particular, a negative count is not converted into a large positive copy size.

The supplied representation does not establish safe behavior when:

- The accumulated destination word position exceeds the signed index range.
- Multiplication of a word position by four overflows the applicable arithmetic.
- Descriptor-offset or source-offset addition overflows.
- An effective address wraps, becomes invalid, or crosses an inaccessible region.

Such cases are outside the fully specified valid-operation envelope. No saturation, rejection, or bounds check is visible. Machine wrapping must not be assumed as a portable substitute for a missing arithmetic guarantee.

## Side effects

The intended writes are consecutive four-byte destination stores, beginning at the captured destination base.

If the valid execution copies a total of \(N\) words, these stores occupy destination byte offsets 0 through \(4N-1\). There is no destination write when \(N=0\).

The function has no separately visible assignment to its global input slots. However, destination aliasing may cause those slots, descriptor fields, or source memory to be modified by ordinary destination stores.

### Reads

Observable data reads comprise:

- The two global base-address slots, once each.
- Both fields of each of the seven descriptors, when that descriptor is reached.
- One source-word read for each destination-word write.

No source-data read is performed for a nonpositive count.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, they assume stable descriptor contents, valid memory, valid arithmetic, and no interfering aliasing.

### Ordered concatenation

Suppose the seven counts are 2, 0, −1, 1, 0, 0, and 2. The contributing sources contain:

- First descriptor: words A and B.
- Fourth descriptor: word C.
- Seventh descriptor: words D and E.

The destination must receive A, B, C, D, and E in five consecutive four-byte locations. Descriptors with nonpositive counts introduce no gaps. Memory after those five destination words is not cleared by this operation.

### All nonpositive counts

Suppose every count is zero or negative.

The function must still read both fields of all seven descriptors, with each count field read before its source-address field. It must perform no source-data reads and no destination writes.

Under that condition, an unusable source address does not itself cause a source-data access. An unreadable descriptor field remains outside the valid-operation preconditions.

### Destination position spans descriptors

Suppose the first descriptor contributes three words and the second contributes two.

The second descriptor’s first word must be written at destination byte offset 12, followed by its second word at offset 16. It must not restart at destination offset zero.

### Forward-overlap propagation

Suppose the first source contains three adjacent words A, B, and C, the first count is three, and the destination starts one word after the source. Let all later counts be zero.

With ordinary readable and writable memory:

- The first copy reads A and overwrites the original B location.
- The second source read therefore obtains A and overwrites the original C location.
- The third source read also obtains A.

The three destination words become A, A, and A. Requiring A, B, and C would incorrectly impose snapshot semantics.

### Modification of a later descriptor

Suppose an early destination write aliases a later descriptor’s count field and stores the valid representation of zero there.

When that later descriptor is reached, its count read observes the modified field under ordinary sequential-memory assumptions. It contributes no words, regardless of its entry-state count.

Its source-address field is still read.

### Modification of captured configuration

Suppose a destination store changes the global destination-address slot after the initial capture.

Subsequent stores continue to use the captured destination base. The modified global slot is not reread by this invocation.

This does not prevent the same store from affecting later behavior if it also aliases some other memory subsequently read.
