# F-0a40b63db184

## Purpose

F-0a40b63db184 selects one of two context-and-selector pairs, invokes F-c45cb3f8e7fd once, and, if the caller supplied a result-word address and the dependency returns normally, replaces the word at that address with its unsigned value shifted right by one bit.

Selection depends on a primary selector stored in the input object and, when that selector is nonzero, a byte reached through two pointer-bearing fields. The fourth input does not influence the selected call or the final result-word transformation.

The established behavior is dispatch followed by in-place postprocessing. The meaning of the contexts, selectors, forwarded payload, and result word is unknown. Interpreting the operation as a particular protocol, resource operation, or status conversion would exceed the available evidence.

### Outputs

No return value is exposed.

For a nonzero result-word address, the function performs a post-call unsigned 32-bit transformation:

- Read the word currently stored at that address.
- Discard its least significant bit.
- Shift the remaining bits down one position.
- Write the resulting 32-bit word back to the same address, with the most significant bit cleared.

This describes the function’s own postprocessing. The dependency may have changed that word, other reachable storage, or wider program state before the transformation occurs.

## Behavior

### Dispatch decision

The first established field read obtains the 32-bit primary selector at object offset `0x30`.

If that selector is zero:

- The flag lookup is skipped entirely.
- The fallback context and fallback selector are selected.
- The auxiliary input does not enable the primary path, even if it is nonzero.

If the primary selector is nonzero:

1. The function reads the referenced base from object offset `0x00`.
2. It reads a 32-bit address at referenced-base offset `0x08`.
3. It reads one unsigned byte at offset `0xB0F` from that address.
4. A nonzero byte selects the primary context and the previously read primary selector.
5. A zero byte selects the fallback context and fallback selector.

The flag is a nonzero test, not a test for one particular enabled value. All byte values from `0x01` through `0xFF` select the primary path when the primary selector is nonzero.

Likewise, the primary selector is tested only for zero versus nonzero. Its high bit does not disable the primary path. No positivity requirement or selector-range check is visible.

### Dependency arguments

Exactly one call to F-c45cb3f8e7fd is present on every normally reached dispatch path.

| Selection | First argument | Second argument | Third argument | Fourth argument |
|---|---|---|---|---|
| Primary | Referenced base + `0x170` | Primary selector already read from object + `0x30` | Original opaque payload | Original optional result-word address |
| Fallback | Referenced base + `0x118` | Fallback selector from object + `0x2C` | Original opaque payload | Original optional result-word address |

The selected selector is forwarded as its 32-bit value. The evidence does not establish its interpretation by the dependency.

On a primary selection, the context uses the same referenced base that was obtained for the flag lookup.

On a fallback selection, the call construction reads the object’s first word. Consequently, when a nonzero primary selector leads to a zero flag, the earlier base lookup for the flag does not establish that a cached base must be used for the fallback call. For stable input storage this distinction has no effect. No thread-safety, volatile-memory, or synchronization semantics are established for changing storage.

The source representation does not establish a complete machine-level order among the reads used to prepare fallback call arguments. In particular, this contract does not impose an order between reading the fallback selector and reading the base for the fallback context. Both precede the dependency invocation.

### Post-call transformation

After F-c45cb3f8e7fd returns normally, the function checks the original optional result-word address.

If that address is zero, the function performs no result-word read or write of its own and returns.

If it is nonzero, the function reads the unsigned 32-bit word then present at that address, shifts it right by one bit, writes the shifted value back, and returns.

The transformed value is the post-dependency value, not a value captured before the call. The function does not initialize the result word before invoking the dependency.

The dependency’s return value, if any, is not examined by the visible logic. There is no visible success-dependent branch protecting the shift. Normal return from the dependency is sufficient for postprocessing to proceed.

If the dependency does not return normally, the shown postprocessing is not reached. No retry, cleanup path, or alternate call is visible.

- The fallback selector is not needed by this function.

- The primary selector is not forwarded as the selected selector.

Unlike the zero-primary case, this case requires readable intermediate flag storage.
