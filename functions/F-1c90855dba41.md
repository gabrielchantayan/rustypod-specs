# F-1c90855dba41

## Purpose

F-1c90855dba41 conditionally updates a word-addressed image buffer and invokes operations on two associated objects when a tracked 32-bit value changes.

The buffer operation preserves the lower 24 bits of each affected word and modifies its upper eight bits. Its addressing describes 240 rows of 320 words, with changes placed symmetrically around column 160. Interpreting the upper byte as opacity, and the operation as a visual transition or mask, is inferred intent rather than an established external contract.

A changed value selects one of three behaviors:

- Derived position zero: no image-buffer words are accessed.
- Derived position 1 through 159: selected upper bytes are cleared, followed by a symmetric, outward-increasing byte ramp.
- Derived position 160: the image-buffer update is bypassed and two additional dependency calls occur.

Every changed-value path then records the derived position and performs three further dependency calls. An unchanged value causes none of these updates or calls.

The function returns the 32-bit value 1 whenever it reaches its normal return.

## Behavior

### Change detection

The function first reads the address at state offset 0x50, then reads the tracked value at offset 0x04 within that referenced record. It compares that value with the cached value at state offset 0x54.

If the values are equal:

- No state field is written.
- The buffer-address field at offset 0x58 is not read.
- The previous-position field at offset 0x5C is not read.
- No image word is accessed.
- No dependency is called.
- The function returns 1.

Change detection uses the complete tracked value, not merely the position derived from it. Two distinct tracked values that produce the same position still take the changed-value path.

### Position derivation and initial state update

For a changed value, the function adds 0x7FFF to the tracked value, shifts the result right by 16 bits, and interprets the resulting position as unsigned. Any unsigned result greater than 159 is replaced by 160.

For a nonnegative tracked value whose addition is representable as a signed 32-bit value, the position before capping is:

\[
\left\lfloor\frac{\text{tracked value}+32767}{65536}\right\rfloor.
\]

The bias is 32767, not 32768. For example, a tracked value of 32768 produces position zero, whereas 32769 produces position one.

The supplied representation uses a signed 32-bit addition and shift before assigning the result to an unsigned value. Overflow behavior and the precise signed-shift semantics are documented uncertainties; the formula above is not a portable promise outside its stated range.

After deriving the position, the function:

1. Writes the newly observed tracked value to state offset 0x54.
2. Reads the buffer address from state offset 0x58.
3. Selects the position-dependent operation.

Consequently, the cached tracked value is already updated before any image-word access or dependency call. There is no observed rollback if subsequent processing does not complete.

### Buffer layout and addressing

For an ordinary position from 1 through 159, the buffer is treated as 240 rows, each containing 320 consecutive 32-bit words.

For a row numbered from zero through 239 and a displacement from the center, the two addressed word indices are:

- Left: row × 320 + 160 − displacement.
- Right: row × 320 + 160 + displacement.

Word indices are converted to byte offsets by multiplying by four.

Rows are processed in increasing order. Within each row, the clearing phase precedes the ramp phase.

Only displacements below 160 are processed. Thus, affected columns fall between 1 and 319 inclusive. Column zero is never changed by the shown buffer operation.

Each word modification preserves bits 0 through 23 and replaces or clears bits 24 through 31. Describing these as word bits does not establish byte order in memory.

### Clearing phase

At the start of each row’s clearing phase, the function reads the previous position from state offset 0x5C as an unsigned 32-bit value.

If that previous position is less than the new position, the function processes consecutive displacements beginning at the previous position and ending immediately before the new position. Because this branch requires the new position to be below 160, all such displacements are within the horizontal limit.

At each displacement, the observable sequence is:

1. Read the left word.
2. Write that word with its upper eight bits cleared.
3. Read the right word.
4. Write that word with its upper eight bits cleared.

If the previous position is greater than or equal to the new position, this phase performs no buffer accesses.

At displacement zero, left and right identify the same word. The function nevertheless performs both read-modify-write operations; the second reads the word after the first has cleared it.

The previous-position field is read separately for each row. In ordinary nonoverlapping storage, it retains its old value throughout the rows because this function updates it only after buffer processing.

### Ramp phase

For every processed row, the ramp begins at the new position. It processes up to 32 displacements, stopping earlier if a displacement would reach 160.

At ramp offset \(k\), starting from zero, the written upper-byte value is \(8k\). The possible values are therefore 0, 8, 16, and so on through 248.

For each displacement, the function:

1. Reads the left word.
2. Writes it with its lower 24 bits preserved and its upper byte replaced by the current ramp value.
3. Reads the right word.
4. Writes it with its lower 24 bits preserved and the same upper-byte value.

The next displacement uses the next ramp value. The ramp restarts at zero for every row.

For an ordinary position \(p\), its displacement range is:

\[
p \text{ through } \min(p+31,159).
\]

The function does not extend the final ramp value across the remainder of the row. Words outside the clearing and ramp ranges retain their prior values unless affected through aliasing or external activity.

### Position zero

When the derived position is zero, both buffer phases are skipped entirely.

The changed tracked value has still been cached, and the buffer-address field has still been read. The function subsequently records position zero and performs the common dependency calls.

### Position 160

When the derived position is 160, no image-buffer words are accessed. Instead, the function calls, in this order:

1. F-25dd705719a1 with the current 32-bit value from state offset 0x20.
2. F-460b2abbbbbe with a fresh value from state offset 0x20 and a second argument of zero.

The meaning of these operations is unknown. Neither is established as a release, reset, disable, or ownership-transfer operation.

### Common changed-value completion

After the selected position-dependent operation, the function:

1. Writes the derived position to state offset 0x5C.
2. Calls F-460b2abbbbbe with the value from state offset 0x24 and the 32-bit value 255.
3. Calls F-1d891874186d with the values from state offsets 0x20 and 0x1C.
4. Calls F-1d891874186d with the values from state offsets 0x24 and 0x18.
5. Returns 1.

These calls occur in the listed order. The state fields supplying call arguments are read for their respective calls; their values must not be assumed to survive earlier dependency calls unchanged. The relative evaluation order of the two field reads within an individual two-argument call is not established.

## Side effects

The function directly writes:

- State offset 0x54 on every changed-value path.
- Selected image words for positions 1 through 159.
- State offset 0x5C after the position-dependent operation on every changed-value path.

It performs three dependency calls for changed positions below 160 and five for position 160. It performs none for an unchanged tracked value.

There is no explicit allocation, deallocation, ownership transfer, synchronization, or error reporting in this function. Dependencies may have such effects, but their behavior is not provided.

There is no null check, buffer-length check, or validation of the previous position. A previous position greater than or equal to the new position simply skips clearing; it does not prevent the ramp phase.

No transactional behavior is established. Cache writes, partial row updates, and completed dependency effects can precede a fault or abnormal dependency exit.

## Acceptance examples

The following are conditional acceptance examples derived from static evidence, not executed tests. Unless stated otherwise, assume valid nonoverlapping storage, stable external state, representable arithmetic, and dependencies that return normally.

### Unchanged tracked value

If the indirect tracked value equals the cached value, the result is 1. Neither cache field changes, no buffer word is accessed, and no dependency runs.

This remains true even if the buffer-address field contains an unusable address: that field is not read on this path.

### Changed value producing position zero

If the tracked value changes to 32768, the derived position is zero.

The tracked-value cache becomes 32768, no buffer word is read or written, and the previous-position field becomes zero. The common three dependency calls occur in order.

A later change to another tracked value producing zero still performs these cache writes and calls.

### Increasing position

If the previous position is 2 and the changed tracked value produces position 5, each row has:

- Upper bytes cleared at displacements 2, 3, and 4 on both sides.
- A ramp at displacements 5 through 36.
- Ramp values zero through 248 in steps of eight.
- Lower 24 bits preserved for every affected word.

The previous-position field becomes 5 after all rows are processed.

### Decreasing position

If the previous position is 40 and the new position is 5, no clearing phase accesses occur. Each row receives the ramp at displacements 5 through 36.

Words at larger displacements are not cleared merely because the position decreased.

### Right-edge truncation

If the new position is 159, each row’s ramp affects only columns 1 and 319, using upper-byte value zero.

If clearing applies, it occurs first. Column zero remains untouched.

### Previous position zero

If the previous position is zero and the new position is one, each row’s center word at column 160 is cleared twice through the two symmetric accesses. The ramp then starts at columns 159 and 161.

### Capped position

A tracked value of 10,485,760 produces position 160 under the stated arithmetic assumptions.

The function updates the tracked-value cache, reads the buffer-address field without accessing image words, invokes the two position-160 calls, records position 160, and invokes the common three calls. The normal result remains 1.

## Uncertainties

The following remain **documented_only**:

- Signed-addition overflow behavior and exact signed-right-shift semantics outside the explicitly qualified arithmetic domain.
- Address-wrap behavior, alignment requirements, and memory-fault handling.
- Endianness and the semantic interpretation of the lower 24 bits and upper byte.
- Whether the inferred 320-by-240 organization matches an externally declared image format.
- Dependency behavior, including mutation of state, global changes, memory release, retained references, or nonlocal exit.
- Concurrency and reentrant access to the state or image buffer.

No nonaliasing guarantee is present in the supplied evidence. If state fields, the tracked-value record, and the image buffer overlap, earlier writes can affect later reads. In particular, the initial cache write precedes the buffer-address read, and each row rereads the previous-position field. The examples above exclude such overlap rather than assuming the function detects or prevents it.
