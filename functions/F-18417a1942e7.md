# F-18417a1942e7

## Purpose

F-18417a1942e7 prepares a temporary collection, traverses its string-like records, and conditionally converts and compares selected records against a caller-supplied value. A successful comparison ends processing without invoking the completion callback. A nonpositive collection length or traversal exhaustion instead invokes completion.

This search interpretation is inferred intent. Established behavior consists of the observable field and global reads, dependency calls, callback dispatches, arithmetic, cleanup ordering, and return-value selection described below. The application meaning of the collection and of a match is unknown.

Three operands come from global storage: an initial-preparation operand, a callback-error status, and a record-preparation operand. They are read at distinct points during execution. Their values and immutability are not established; preceding dependencies or callbacks may change them.

## Interface

### Inputs and representation

The function accepts:

- A pointer to readable storage containing an object address.
- An opaque 32-bit value.

The supplied representation uses 32-bit addresses and 32-bit ordinary integer operands. The first argument is dereferenced initially, and that object address is retained. On the positive-length path, the caller-held object pointer is read again for one field access. A change to the caller-held pointer can therefore affect that access without changing the retained object used elsewhere.

The opaque value is passed unchanged to initial preparation, completion, and, when reached, comparison. Its use as a comparison operand suggests a string-related interpretation, but neither its complete type nor its validity requirements are established.

### Return value

The return is a 32-bit status selected as follows:

- `7` if either allocation returns zero.
- The nonzero result of a checked preparation, length-query, population, or conversion operation.
- The value read from the callback-error-status global if the record callback returns neither `0` nor `1`.
- `0` after a successful early match.
- The completion callback’s result when completion is reached.

The callback-error-status global is not established to contain a nonzero value. An unexpected record-callback result can therefore select status `0` without representing the early-match path.

Cleanup-call results, if any, are ignored.

Successful allocations must accommodate all subsequent dependency writes and address calculations. Comparison requires an acceptable second operand and suitable converted output. The body does not establish these conditions through validation.

No invalid-input recovery, exception handling, or memory-fault contract is visible.

## Behavior

### Initial allocation and preparation

The function first reads and retains the object address through the first argument.

It reads the retained object’s `+4` field, forms a 32-bit left-shift-by-one allocation operand, and calls F-391e3d30e634 with that single visible operand.

After the allocation returns, the function reads the retained object’s `+4` field again. It adds this newly read value to the returned allocation address to form a secondary-region address. This calculation occurs before testing whether the allocation address is zero.

The two field reads are distinct. If the allocation dependency changes the field, allocation sizing uses the earlier value while secondary-region placement uses the later value.

If the allocation address is zero, the function selects `7`, calls F-94cb53877c15 with zero, and returns. It does not read the initial-preparation global on this path.

For a nonzero allocation, the function reads the initial-preparation operand from global storage and calls F-b83d21bf80f6 with:

- The retained object.
- The caller’s opaque value.
- The initial allocation address.
- The value just read from the initial-preparation global.
- Zero.

This global read follows the allocation call, the `+4` reread, and the nonzero check. No entry-time snapshot or preservation of its value across the allocation call is established.

If preparation returns nonzero, the function releases the initial allocation through F-94cb53877c15 and returns that status. F-b8b7f726dd02 is not called on this failure path.

### Length query and nonpositive length

After successful initial preparation, F-da5096269123 receives the initial allocation and writable output storage for two adjacent 32-bit words.

On success, those words supply the low and high halves of a signed 64-bit collection length. Their arithmetic roles are established; the body alone does not independently establish byte endianness or the dependency’s complete output contract.

If the query returns nonzero, the function calls F-b8b7f726dd02 on the initial allocation, then F-94cb53877c15 on it, and returns the query status.

If the query succeeds with a signed length less than or equal to zero, no traversal allocation or population occurs. The function reads and dispatches the retained object’s completion callback at `+0x1c`, passing:

- The retained object.
- The caller’s opaque value.
- Zero.

The completion result is retained through initial-allocation cleanup and returned.

### Positive-length allocation and population

For a positive signed length, the function rereads the object pointer through the first argument. It reads that object’s `+8` field and adds one to form a 32-bit capacity-like quantity.

This field access can use a different object from the retained object if earlier calls changed the caller-held pointer. Preparation and callbacks continue to use the retained object.

The traversal allocation receives two visible 32-bit operands:

- The low word of the collection length plus the capacity-like quantity, retaining the low 32 bits.
- The high word of the collection length, plus the sign extension of that quantity interpreted as signed 32-bit, plus the carry from the low-word addition.

Thus, a capacity-like quantity with its top bit set contributes a negative high-word adjustment. The calculation must not be described as unconditional unsigned addition.

If allocation returns zero, the selected status is `7`; initial-allocation finalization and release follow.

Otherwise:

- The traversal address starts at the new allocation’s base.
- The conversion-output address is formed by adding only the collection-length low word to that base.
- Two extra record-callback operand words are initialized to zero.
- F-779a651c5cc8 receives the initial allocation, traversal-buffer base, and collection-length low word.

A nonzero population result causes traversal-buffer release, initial-allocation finalization, initial-allocation release, and return of that result. Completion is not called.

The two-word allocation arithmetic does not establish 64-bit addressing or a 64-bit population extent. Output placement and population use the low word only.

### Traversal and record callback

Traversal continues while the current offset is less than the signed 64-bit collection length.

The offset is formed from the 32-bit difference between the current traversal address and the traversal-buffer base, then sign-extended for the comparison. It is not an independently maintained 64-bit counter.

Each visited record dispatches through the retained object’s `+0x20` callback slot. The visible argument positions contain:

1. The retained object.
2. The current record address.
3. Zero.
4. A callback address read from the retained object’s same `+0x20` slot.
5. A zero-valued word.
6. Another zero-valued word.

The relative machine-level order of the callback-slot reads is not established.

The callback result determines subsequent behavior:

- **Result `0`:** No callback-error-status global read occurs. Conversion is skipped, and processing proceeds to record advancement.
- **Any nonzero result:** The function first reads the callback-error-status global and selects that loaded value as the tentative status.
- **Nonzero result other than `1`:** The selected global value becomes the return status after cleanup. Completion is skipped.
- **Result `1`:** The global read has already occurred, but its loaded value does not determine the eventual result. Processing continues into record preparation.

An implementation omitting the callback-error-status read for result `1` would not preserve the established read sequence.

### Record preparation, conversion, and comparison

On the result-`1` path, the function resets the first extra callback operand word to zero. No assignment of a nonzero value to either extra word is visible.

It then reads the record-preparation operand from its global location and invokes F-b83d21bf80f6 with four visible arguments:

- The retained object.
- The current record address.
- The secondary-region address calculated within the initial allocation.
- The newly read record-preparation global value.

The record callback may have changed either global before these reads. The callback-error status is read first; the record-preparation operand is read later, on the result-`1` branch.

The initial and record-preparation calls have different visible argument counts. A single fixed prototype, variadic contract, or particular calling convention is not established.

If record preparation returns nonzero, its result is returned after buffer cleanup. The secondary region is not passed to F-b8b7f726dd02 on this failure branch.

On successful preparation, F-973bb4e26f5d receives the secondary region, conversion-output address, and previously computed 32-bit capacity-like quantity. F-b8b7f726dd02 is then called on the secondary region before the conversion status is tested.

A nonzero conversion result is propagated after cleanup. For a zero conversion result:

- A zero first output byte skips comparison and continues traversal.
- A nonzero first output byte causes a comparison call with the conversion-output address and caller’s opaque value.
- Comparison result zero terminates immediately with status `0`.
- A nonzero comparison result continues traversal.

The output-byte read occurs after secondary-region finalization. No guarantee that this finalization preserves other reachable memory or global state is supplied.

An early match invokes neither record advancement nor completion.

### Advancement and completion

For a record that does not terminate processing, F-1cb585febd84 receives the current record address. The next address is formed by adding its 32-bit result and one to the current address.

No independent record-boundary validation, negative-length rejection, or progress check is visible. Invalid record extents, wraparound, or nonprogress can therefore prevent the intended traversal behavior.

When the traversal comparison becomes false, the retained object’s completion callback is invoked with the retained object, opaque value, and zero. Its result becomes the return status. Traversal-buffer release and initial-allocation cleanup follow.

## Acceptance examples

These are conditional criteria from static evidence, not executed tests.

1. **Initial allocation failure:** If the first allocation returns zero, reread `+4` and calculate the secondary-region address before selecting `7`. Call F-94cb53877c15 with zero. Do not read the initial-preparation global or invoke preparation.

2. **Changed initial operand:** If allocation changes the initial-preparation global and succeeds, initial preparation receives the value read after allocation, the `+4` reread, and the nonzero check—not an assumed entry-time value.

3. **Initial preparation failure:** A nonzero preparation result is returned after initial release, without initial finalization.

4. **Nonpositive length:** A successful query yielding zero or a negative signed length invokes completion without traversal allocation or population.

5. **Changed caller-held object:** If an earlier dependency replaces the caller-held object pointer, positive-length processing reads `+8` from the replacement while retaining the original object for preparation and callbacks.

6. **Callback result zero:** Skip the callback-error-status and record-preparation global reads, skip conversion, and advance the record.

7. **Callback result one:** Read the callback-error-status global before distinguishing this result from other nonzero results. Then read the record-preparation global and invoke record preparation. The first loaded value does not replace a later preparation or conversion result.

8. **Unexpected callback result:** If the callback returns `2` and the callback-error-status global contains `23` when read, return `23` after cleanup. If that global instead contains zero, return zero through the same error branch. Neither case invokes completion.

9. **Empty converted output:** Successful conversion followed by a zero first output byte skips comparison and advances. Empty output is not an early match.

10. **Early match:** Nonempty output and comparison result zero produce status `0` after cleanup, without advancing that record or invoking completion.

11. **Conversion failure:** Finalize the prepared secondary region before testing and propagating the nonzero conversion status.

12. **Completion result:** If traversal exhausts and completion returns a nonzero value, return that value after cleanup rather than forcing success.
