## Behavior

### Branch classification

Two independent properties determine the represented path:

1. Whether the zero-condition state is set.
2. Whether the negative- and overflow-condition states are equal.

The main interrupt groups are selected whenever either:

- The zero-condition state is set; or
- The negative- and overflow-condition states differ.

The two coprocessor loads are selected whenever the negative- and overflow-condition states are equal, independently of the zero-condition state.

A separate software interrupt is selected whenever the zero-condition state is clear.

These conditions overlap. In particular, a set zero-condition state does **not** exclude the coprocessor loads.

The following ordering describes the static representation. Progress from one operation to the next is conditional on the earlier operation permitting continuation. Interrupt handlers, coprocessor faults, and other exceptional behavior may prevent later operations from being reached.

### Opening operations

When the main interrupt condition holds, the function requests software interrupt `0x1ddf1d` nine times consecutively.

Otherwise, it performs a coprocessor transfer operation with:

- Selector operands `0xf`, `5`, and `0`.
- Word C and word D as the remaining represented operands.

The exact architectural source, destination, and effects of that transfer are unknown.

Next, if the negative- and overflow-condition states are equal, the function performs the earlier coprocessor long-load operation:

- Coprocessor selector: `5`.
- Opaque operand: word A.
- Address expression: first address base plus 608.

The supplied representation establishes the operation's position and operands. It does not establish the amount of memory read, alignment requirements, address writeback, destination state, or transfer atomicity.

### Middle interrupt operations

If the main interrupt condition holds, the function next requests software interrupt `0x1ddf1d` four more times consecutively.

After that conditional group, if the zero-condition state is clear, it requests software interrupt `0x1edf1d` once.

This single request is independent of negative/overflow equality. Thus it is represented on both paths with a clear zero-condition state, including the path that otherwise uses the two coprocessor transfers.

### Later branch

If the main interrupt condition holds, the following ordered sequence is represented:

1. Seven consecutive software-interrupt requests with immediate `0x1cdf1c`.
2. A coprocessor transfer with selector operands `0xf`, `7`, and `0`, using word C in both remaining operand positions.
3. One software-interrupt request with immediate `0x1cdefc`.
4. One software-interrupt request with immediate `0x1dcebb`.
5. Ten consecutive software-interrupt requests with immediate `0x1ddf1d`.

The repeated occurrence of word C in the transfer is part of the represented operand relationship. It does not prove that the operation preserves that word or any associated machine state.

If the main interrupt condition does not hold, the function instead performs a coprocessor transfer with:

- Selector operands `0xf`, `5`, and `0`.
- Word B and word D as the remaining represented operands.

### Closing operations

If the negative- and overflow-condition states are equal, the function next performs the later coprocessor long-load operation:

- Coprocessor selector: `5`.
- Opaque operand: word A.
- Address expression: second address base plus 604.

If the main interrupt condition holds, four consecutive requests for software interrupt `0x1cdf1c` follow.

Every represented path then reaches the invalid-instruction termination marker. No cleanup, successful return, or result publication is shown before that marker.
