# F-707e8b830f5c

## Purpose

F-707e8b830f5c applies an ordered set of width-sensitive memory mutations, exposes partially prepared stack storage to an inherited call target, and, if that call returns, invokes F-cdec09f5d432. If both calls return, control reaches a represented terminal mechanism rather than an ordinary return.

This is a memory-and-control-flow contract. The available static evidence does not establish an application purpose, object model, ownership protocol, or successful operating domain. Recurring offsets do not by themselves identify links, records, or fields of a known structure.

All later effects are conditional on earlier accesses and calls completing. There is no established validation, rollback, or recovery path.

### Inherited inputs

Four additional 32-bit entry values have distinct roles:

- **Payload base:** supplies the opening halfword data and receives an installation at offset 68.
- **Displacement base:** contributes to the opening destination and supplies the initial word at offset 68.
- **Initial working base:** receives early writes and participates in subsequent selections.
- **Carried word:** serves both as stored data and as an address for later offset-68 reads.

These are descriptive roles, not established types. A captured word may subsequently be treated as an address.

Other effective inputs include an inherited indirect call target, six fixed-location replacement sources, a separate fixed-location argument source for F-cdec09f5d432, and reachable memory. Stack bytes not explicitly assigned also remain part of the exposed state.

### Widths and layout conventions

Offsets are in bytes. Words are 32 bits, halfwords 16 bits, and bytes 8 bits. Narrow stores retain the destination-width portion of the supplied value.

Halfwords used in dependent addressing are signed and widened before use. The address-bearing byte’s signedness is unresolved; this affects both its address interpretation and its conversion to halfword data.

Address expressions and working integers are represented at 32-bit width. Overflow, signed shifts, multiplication overflow, and conversion of arithmetic results into addresses are documented_only. Neither unlimited-precision arithmetic nor unconditional modulo-\(2^{32}\) behavior is established.

Valid execution requires every reached access and call target to be usable under the target environment’s rules. Alignment, byte order, memory extent, and disjointness are not supplied.

## Behavior

### Ordering and observation rules

The contract concerns ordered effects, not an entry-time snapshot. Earlier stores can affect later reads through any alias, including argument-relative memory, replacement sources, stack storage, or carried-word-derived addresses.

Repeated reads therefore remain distinct observations. Repeated writes remain distinct represented effects even when they leave identical bytes. This does not establish atomicity, volatile semantics, physical transaction counts, or concurrency guarantees.

Each replacement stage obtains a retained reference and separately evaluates the fixed-location source for its installation value. Equality between those values requires source stability; it is not an unconditional property.

The stages below are conceptual partitions, not transactions.

### Opening and first replacement

The first memory effect is a halfword store at the sum of the third argument and the displacement base. Its data is the payload base’s low halfword.

The initial displaced word is then captured from the displacement base’s offset 68. Before the first replacement is retained, the initial working base receives its own value at offset 84. The installation goes to the payload base’s offset 68; the retained replacement’s offset 20 receives the displaced word.

The initial working base next receives the low byte of its doubled value at offset 17. The first argument’s offset-100 word is sampled for the first of four times.

Dependent addressing then obtains a signed halfword from the sum of the initial working base and retained replacement, followed by a byte from the sum of that widened halfword and the displaced word. The byte’s extended value becomes another address-bearing base.

The following store order is required:

1. Replacement-derived byte at the first argument’s offset 1.
2. Displaced-word-derived byte at the replacement’s offset 13.
3. Carried word at the replacement’s offset 68.
4. Replacement-derived byte at the byte-derived base’s offset 13.
5. Byte-derived halfword data at the sum of the signed halfword and replacement.

The last destination is not the address from which the byte was read.

### Second and third replacements

For the second stage, the displaced word is freshly read from the preceding replacement’s offset 68. The initial working base receives another offset-84 self-value store before the next replacement is retained. That replacement is installed at the byte-derived base’s offset 68, and its retained base receives the captured word at offset 20.

The first offset-100 sample supplies the initial working base’s offset-17 byte before the second offset-100 sample is taken.

Three selections then matter:

- An offset-68 word from the initial working base selects a destination base.
- A signed halfword comes from the sum of that working base and the second replacement.
- An offset-116 word from the displaced-word-derived base selects another base.

An offset-20 read from the initial working base selects the working base for the third stage. The offset-68 selection receives the offset-116 selection’s low byte at offset 13. A halfword store combines the signed halfword with the offset-116 selection for its destination and uses the offset-68 selection as data.

For the third stage, the offset-116 selection’s offset 68 supplies the next displaced word. The newly selected working base receives its own value at offset 84. The third replacement is installed through the preceding offset-68 selection; its retained base receives the displaced word at offset 20. The working base’s offset 17 receives the second offset-100 sample’s low byte.

After a new offset-68 selection and signed-halfword read, a byte is written at offset 21 of the displaced-word-derived base. Only afterward is that displaced word stored at offset 68 of the third replacement. A subsequent offset-116 read through the new offset-68 selection determines the halfword-store destination together with the signed halfword. The selection itself supplies the halfword data.

This late offset-116 read must reflect preceding writes when they overlap its storage.

### Fourth and fifth replacements

The fourth stage captures its displaced word from offset 68 of the third stage’s late offset-116 selection. The current working base receives an offset-84 self-value store. The fourth replacement is installed through the preceding offset-68 selection, and its retained base receives the displaced word at offset 20.

The working base’s offset 17 receives its doubled value’s low byte before the third offset-100 sample. A fresh offset-68 selection and signed-halfword read follow. A word read at offset 20 of the widened halfword’s address selects the next working base.

The fourth stage then performs a mutation group with this ordering:

- The offset-68-selected base receives its own value at offset 84.
- The carried word is stored at the sum of replacement and displaced-word values.
- The replacement’s offset 20 receives the offset-68 selection.
- A fresh offset-68 read through the carried word supplies the replacement’s offset-13 byte.
- The halfword-derived offset-20 selection receives the offset-68 selection’s low byte at offset 13.
- A halfword store at the sum of signed halfword and replacement receives the offset-68 selection’s low halfword.

The fifth stage captures a displaced word from the fourth replacement’s offset 68. The halfword-derived working base receives an offset-84 self-value store. The fifth replacement is installed through the fourth stage’s offset-68 selection and receives the displaced word at its retained base’s offset 20.

The fifth stage has two offset-17 writes to its working base. The first uses the third offset-100 sample. The fourth sample is then taken, followed by a fresh offset-68 selection and signed-halfword read.

Before the second offset-17 write, the displaced-word-derived base receives the current working base at offset 84. This is not necessarily a self-value store. The second offset-17 write uses the fourth sample’s low byte.

The offset-68-selected base then receives the retained fifth replacement at offset 68. Only afterward is the next working base selected by the signed-halfword-derived offset-20 read. The mutation group described for the fourth stage follows, using the fifth stage’s values and a separate fresh read through the carried word.

Consequently, the two carried-word reads need not agree, and the two summed-address stores need not target disjoint storage.

### Sixth replacement and multiplication-dependent addressing

The sixth stage captures a word from the fifth replacement’s offset 68. The current working base receives its own value at offset 84. The final replacement is installed through the preceding offset-68 selection; its retained base receives the captured word at offset 20.

The current working base’s offset 17 receives the fourth offset-100 sample’s low byte. A fresh offset-68 word and a signed halfword from the sum of working base and final replacement establish the multiplication inputs.

Before the first product-addressed read, two complete repetitions occur of the same ordered pair:

- The widened-halfword-derived base receives its own value at offset 84.
- The final replacement receives the current working base’s low byte at offset 17.

The first product combines the signed halfword with the captured working-base offset-68 word. Addressing then follows an offset-68 word read, an offset-116 word read through that result, and an offset-20 word read through the next result.

At the resulting base, the existing offset-20 word is captured before that location receives the doubled current working-base value. An offset-20 read through the captured word then supplies the other operand for a new multiplication by the signed halfword.

Another halfword-derived offset-84 self-value store precedes a final-replacement offset-17 byte store derived from the captured old word. The new product’s offset-116 word is then captured at stack offset 264.

A further multiplication of that product by the same signed halfword establishes the product base used below. After another halfword-derived self-value store, the final replacement’s offset 17 receives the stack-captured value’s low byte.

The remaining memory effects preserve these dependencies and order:

- A product-base offset-68 word is read before the first argument’s offset-116 word.
- The captured value is stored at the final replacement’s offset 100; the earlier product-base read supplies its offset-9 byte.
- A fresh product-base offset-68 read supplies that product base’s offset-17 byte.
- Another halfword-derived offset-84 self-value store precedes an offset-17 byte store through twice the product base. Its data comes from the captured value.
- A further offset-68 read uses the product of signed halfword and current product base.
- The first argument’s offset-20 word selects the final byte-store base.
- The captured-value-derived base’s offset 1 receives the earlier first-argument offset-116 value’s low byte.
- The final selected base receives the last multiplication-addressed read’s low byte at offset 17, then the doubled product base’s low byte at offset 9.

Intervening stores can change either of the repeated product-base offset-68 reads.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Opening truncation:** A payload whose low halfword is BEEF produces that halfword pattern at the opening destination if the access completes. Upper payload bits are excluded.

2. **Four input observations:** If an earlier store changes the first argument’s offset-100 word before a later sample, that sample uses the changed storage. One entry-time sample is not equivalent.

3. **Replacement instability:** If a fixed replacement source changes between retention and installation evaluation, the retained base and installed value may differ.

4. **Signed halfword:** A halfword pattern FFFF contributes negative one after widening. Address validity and product behavior remain conditional on target arithmetic.

5. **Byte interpretation:** A byte with its high bit set does not establish either a positive or negative address contribution without the missing signedness information.

6. **Fifth-stage asymmetry:** If displaced-word-derived and working bases differ, the offset-84 store through the former still contains the latter.

7. **Aliased late read:** A third-stage store overlapping the later offset-116 read affects that read according to target byte order and memory semantics.

8. **Repeated effects:** Identical final bytes do not justify removing either of the two initial multiplication-phase store pairs.

9. **Early capture:** Stack offset 264 is assigned before the remaining product-derived accesses and final preparation. Those intervening accesses may alias it.

10. **Non-returning indirect call:** No post-call stack assignment, F-cdec09f5d432 call, or terminal operation is reached.

11. **Changed dependency source:** If the indirect target changes the fixed source used by F-cdec09f5d432, the later call is not required to receive its pre-call value.

12. **Returning calls:** If both calls and intervening operations complete, the terminal path is reached rather than an ordinary return.
