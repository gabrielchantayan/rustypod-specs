# F-138fe096430e

## Purpose

F-138fe096430e retrieves a 32-bit value through one of two resolution paths. It first attempts a conditional lookup through F-932a35189ea0. If that lookup is disabled or returns a null result, it calls F-95394d899f4d. Each successful path selects an intermediate record and returns the 32-bit field at byte offset 8 within that record.

The function also returns zero when F-95394d899f4d returns null. Consequently, a zero return value does not distinguish resolution failure from successful retrieval of a field containing zero.

This contract describes behavior established by the supplied static representation. The interpretation of the operation as a lookup or resolution is inferred intent; the meanings of the input, records, and returned field are not established.

## Interface

### Input

The function accepts one 32-bit input word.

No signedness, encoding, object type, ownership convention, or valid-value range is established for that word. The function does not directly dereference it. Instead, it copies its bits into temporary storage made available to its dependencies.

### Output

On a normal return, the function produces one 32-bit word:

- The field at byte offset 8 of the record selected through F-932a35189ea0, when that dependency returns a non-null result.
- The field at byte offset 8 of the record selected through a non-null result from F-95394d899f4d.
- Zero when F-95394d899f4d returns null.

No separate status, error code, or ownership indicator accompanies the result.

## Behavior

### 1. Prepare temporary argument storage

The function creates a local pointer referring to the start of its seven-word temporary argument storage. It copies the input word into the first word of that storage.

It does not explicitly initialize the remaining six words. Those words therefore have no specified initial values under this contract. They are not established as zero-filled, valid additional arguments, or safe input for a dependency to inspect.

The local pointer is itself addressable. This matters on the fallback path, which receives the address of that pointer rather than simply the address of the argument storage.

### 2. Check whether to attempt the optional lookup

The function reads the 32-bit field at byte offset 4 of the object reached through the optional-lookup global reference.

- If that field is zero, the function skips F-932a35189ea0 and proceeds to fallback resolution.
- If that field is nonzero, it prepares the two-word lookup descriptor and calls F-932a35189ea0.

The descriptor contains the word 1 followed by a pointer to the temporary argument storage. Its first referenced argument is therefore the original input word.

For the lookup call, the function reads the optional-lookup state field again and passes that value as the first dependency argument. The second argument is a pointer to the descriptor.

The gating read and the call-argument read are distinct accesses in the supplied representation. The function does not establish synchronization or guarantee that the two reads observe the same value. In particular, the call is enabled by the first read; no second nonzero check is performed on the value passed to the dependency.

### 3. Interpret the optional lookup result

If F-932a35189ea0 returns a nonzero pointer:

1. The function reads the 32-bit pointer-bearing field at byte offset 4 of that result.
2. It treats the field as the address of the selected record.
3. It reads the 32-bit word at byte offset 8 of that record.
4. It returns that word.

F-95394d899f4d is not called on this path.

There is no null check on the embedded record pointer. A non-null lookup result containing an invalid or zero record pointer does not cause a controlled fallback.

If F-932a35189ea0 returns zero, the function proceeds to fallback resolution. The function does not translate any other lookup result into failure.

### 4. Invoke fallback resolution

Fallback resolution occurs when either:

- The initial optional-lookup state read is zero; or
- F-932a35189ea0 was called and returned zero.

F-95394d899f4d receives five arguments, in this positional order:

| Position | Value |
|---|---|
| 1 | Address of the local pointer to temporary argument storage |
| 2 | First opaque fallback global value |
| 3 | Second opaque fallback global value |
| 4 | Literal 32-bit value 4 |
| 5 | Third opaque fallback global value |

The argument positions are established. The relative evaluation order of the separate global argument values is not established by the supplied representation.

Because the first argument addresses a pointer slot, the dependency can access or alter that slot if its implementation does so. The caller does not explicitly read the slot after the fallback call.

If the optional lookup was attempted first, fallback occurs after that call. No preservation guarantee is established for dependency-accessible memory or global state. This function does not restore the argument storage before invoking fallback.

### 5. Interpret the fallback result

If F-95394d899f4d returns zero, the function immediately returns the 32-bit value zero.

If it returns a nonzero pointer:

1. The function reads the first 32-bit word at that address.
2. It treats that word as the selected record address.
3. It reads the 32-bit word at byte offset 8 of the selected record.
4. It returns that word.

As on the lookup-success path, the embedded record pointer is not checked before use.

### Widths and address calculations

The input, output, descriptor words, pointer-bearing fields, and literal arguments are represented as 32-bit quantities. Null checks compare pointer-like values against zero. No sign-dependent branch is present.

The offsets 4 and 8 are byte offsets. The function performs no input-dependent multiplication, range calculation, saturation, or arithmetic-overflow check. It assumes that the required fixed-offset accesses are valid.

The literal fallback argument 4 is distinct from the 28-byte temporary storage extent. Neither the storage size nor the number of initialized words establishes what that literal means to F-95394d899f4d.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes valid storage for every access taken.

1. **Optional path disabled; fallback succeeds.**  
   The initial optional-state field is zero. F-932a35189ea0 is not called. F-95394d899f4d returns a non-null object whose first word identifies a record containing `0x12345678` at offset 8. The function returns `0x12345678`.

2. **Optional lookup succeeds.**  
   The initial optional-state field is nonzero. F-932a35189ea0 returns a non-null object whose field at offset 4 identifies a record containing 9 at offset 8. The function returns 9 without calling F-95394d899f4d.

3. **Optional lookup misses; fallback fails.**  
   The initial optional-state field is nonzero, F-932a35189ea0 returns zero, and F-95394d899f4d returns zero. Both dependencies are called in that order. The function returns zero.

4. **Successful retrieval contains zero.**  
   Either successful path selects a valid record whose field at offset 8 is zero. The function returns zero, indistinguishable by return value alone from a null fallback result.

5. **Non-null lookup result contains a null record pointer.**  
   F-932a35189ea0 returns a non-null result whose field at offset 4 is zero. The function attempts to read through that embedded address at offset 8. It does not invoke fallback because of the null embedded pointer. Normal completion is not guaranteed.

6. **The optional-state reads differ.**  
   The gating read is nonzero, but the subsequent read used as the first lookup argument is zero. The lookup call still occurs and receives zero as its first argument. This example is conditional on the execution environment permitting that state change.

7. **Input bits are preserved.**  
   An input of `0xFFFFFFFF` is copied unchanged into the first temporary argument word. This function performs no signed conversion, rejection, or normalization of those bits before making them available to a dependency.
