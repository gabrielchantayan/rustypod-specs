# F-1e2f295ee27c

## Purpose

F-1e2f295ee27c transforms a 32-bit input value into four consecutive destination bytes. A second 32-bit input selects the transformation after one selector bit is cleared.

Supported behavior includes selecting an externally supplied four-byte record, producing inverted grayscale values, expanding packed bit fields, rearranging input bytes, and looking up four independently indexed bytes. Unsupported selectors use a default record without reporting an error.

The output layout is consistent with color-component conversion, but that application-level meaning is inferred rather than established. This contract uses **channel 0** through **channel 3**, corresponding to destination offsets 0 through 3.

The contract describes the access order visible in the supplied static representation. It does not establish machine-level atomicity, synchronization, or behavior under concurrent modification.

## Interface

| Item | Contract |
|---|---|
| Value | Unsigned 32-bit input. Depending on the selector, the transformation uses the entire value or selected low-order fields. |
| Selector | Unsigned 32-bit input. Bit 13 is cleared before dispatch; all other bits remain significant. |
| Destination | Address of at least four writable bytes. Output channels occupy offsets 0, 1, 2, and 3. |

The normalized selector is the selector masked with `0xFFFFDFFF`. Selectors differing only by `0x2000` therefore select the same behavior.

The selector is a numeric dispatch code. No selector-derived address is dereferenced.

On normal completion, the function performs exactly four destination-byte stores, ordered from offset 0 through offset 3. Record fallback is not distinguishable through a separate status result.

## Behavior

### Initial reads and dispatch

Before selector-specific processing, the external record pointers are read and retained in this order:

1. Record D pointer.
2. Record C pointer.
3. Record B pointer.
4. Record A pointer.

These reads occur even when the selected transformation does not subsequently access record bytes.

Dispatch uses the normalized selector. Only bit 13 is discarded; other high bits can prevent a selector from matching a supported code.

### Record-copy behavior

Every record-copy path uses two sources of pointer information:

- Channel 0 uses the selected record pointer reread from its external pointer slot.
- Channels 1–3 use the selected record pointer retained during the initial reads.

The selected slot is reread **before the first destination write**. The byte-access sequence is:

1. Read source byte 0 through the reread pointer, then write destination offset 0.
2. Read source byte 1 through the retained pointer, then write destination offset 1.
3. Read source byte 2 through the retained pointer, then write destination offset 2.
4. Read source byte 3 through the retained pointer, then write destination offset 3.

There is no further selected-pointer-slot read between these stores.

Consequently, destination writes overlapping an external pointer slot **cannot by themselves make the channel-0 pointer differ from the entry-retained pointer during this invocation**. Both pointer reads have already occurred when the first destination write happens. Later writes may alter the pointer slot’s stored bytes, but they do not replace either pointer value already obtained.

Independent mutation between the initial pointer read and the selected-slot reread could produce different pointer values. That possibility is conditional on execution and concurrency semantics not established here; it is not a synchronization guarantee.

Record-byte aliasing has a separate effect. Because source-byte reads and destination writes are interleaved, an earlier destination write can overwrite a record byte before a later read obtains it. A four-byte snapshot copy is therefore not an equivalent replacement for all overlapping inputs.

### Normalized selector `0x1`

The complete 32-bit value determines the record:

- Zero selects record B.
- Any nonzero value selects record A.

This is not a low-bit or low-byte test.

### Normalized selector `0x2`

Selection has the following precedence:

1. A zero value selects record B.
2. Otherwise, equality with match value C selects record C.
3. Otherwise, equality with match value D selects record D.
4. Otherwise, record A is selected.

The comparisons use the complete value.

Match value C is not read on the zero path. Match value D is read only if the value is nonzero and does not match C. Zero therefore wins over zero-valued match constants, and C wins when both match constants equal the same nonzero value.

The selected record is copied using the access behavior above.

### Normalized selector `0x4`

Only the low nibble participates. Let \(n\) be that nibble and \(M\) the multiplier after conversion to an unsigned 64-bit value. The computed grayscale byte is:

\[
g =
\left(
\left\lfloor
\frac{(15-n)\times255\times M}{2^{35}}
\right\rfloor
\right)\bmod256
\]

The output is:

\[
[g,\ g,\ g,\ 255]
\]

The initial factor \((15-n)\times255\) lies between 0 and 3825, so its calculation does not overflow a 32-bit unsigned value. The subsequent multiplication is expressed at unsigned 64-bit width, followed by a right shift of 35 positions. The result is converted through an unsigned integer to a byte; the final output retains its low eight bits rather than saturating.

If the external multiplier is an unsigned 32-bit quantity, the 64-bit product cannot overflow. The external multiplier’s declaration is absent from the supplied material; wider or signed external representations remain an uncertainty. The stated formula applies directly when the 64-bit product does not overflow. Otherwise, unsigned 64-bit multiplication retains the product modulo \(2^{64}\) before the shift.

The multiplier is obtained and the output byte computed before any destination write. Higher input bits do not participate.

| Output | Index from input |
|---|---|

Consequently, this invocation’s destination writes cannot alter a table value before that invocation reads it: all four selected bytes have already been read. This remains true when the destination overlaps table entries.

The table-base expression is referenced separately for each lookup. A single retained base value for all four lookups is not established.

Bits 16–31 are ignored. The table’s contents are unknown; nibble replication, monotonicity, and particular endpoint values are not guaranteed.

### Remaining selectors

This includes `0x0`, `0x3`, `0x5`, `0x6`, `0x7`, and unsupported larger values. Fallback is ordinary completion, not a reported error.

## Side effects

The explicit modifications are four byte stores to the destination, always in ascending offset order.

No external pointer slot, match value, multiplier, or table entry is explicitly assigned as external state. Destination aliasing can nevertheless modify any such object whose storage overlaps the destination.

For record-copy paths, distinguish two effects:

- Overwriting a pointer slot happens after the selected-slot reread and does not redirect this invocation’s remaining record reads.
- Overwriting record-byte storage can change a later source-byte read, because those reads are interleaved with destination writes.

For the table path, all selected table bytes are read before any destination store. Overlap may change the table’s subsequent contents but not the already-obtained output bytes.

There are no explicit function calls, callbacks, allocation operations, releases, or I/O operations.

The function provides no rollback mechanism. If an access fails, earlier destination stores may already have occurred. The exact fault, exception, or language-level consequence of invalid access is not established.

No synchronization is shown. The access description does not authorize concurrent mutation or establish that such mutation has defined behavior.
