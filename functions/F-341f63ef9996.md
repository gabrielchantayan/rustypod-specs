# F-341f63ef9996

## Purpose

F-341f63ef9996 searches up to 21 indexed record positions for a requested 32-bit selector, chooses an index, and delegates an operation using a payload obtained at that index. It then passes the selected selector-field address to another dependency, conditionally dispatches an operation through an optional object, and unconditionally attempts a final object dispatch.

The table-base global is read separately for every selector access and again after the search to form the selected-record address. Consequently, selection is a search of one consistent table only if those reads yield a stable base and the relevant contents remain stable.

Failure to find a match is not an explicit error. It selects index 0 while retaining the selector read during the final search iteration. The payload and selector-field address subsequently come from index 0 relative to the newly read base; the selector argument passed to the first dispatch remains the last value examined.

The established behavior is ordered selection and delegation. Application-level meanings such as configuration change, persistence, notification, or refresh are not established.

### Record layout and search reads

The function considers indices 0 through 20, inclusive. At each index, it uses a stride of 12 bytes and the following field offsets:

| Offset within an indexed record | Width | Visible role |
|---|---:|---|
| `0` | 4 bytes | Not read as a record field by this function. |
| `4` | 4 bytes | Payload for the first dispatch, read after selection. |
| `8` | 4 bytes | Selector read during search; the selected field’s address is later passed to F-ca0f66276073. |

This describes an addressing layout, not proof that one fixed allocation contains 21 initialized records.

For each examined index, the function:

- Reads the table-base global for that selector access.
- Reads the four-byte selector at that base plus the index displacement and `8`.
- Compares the resulting value with the requested selector.

Indices are examined in ascending order. The first observed equality stops the search and selects that index. Otherwise, all 21 indices are examined and index 0 is selected.

The function retains the last selector value actually read. On a match, that retained value equals the requested selector. On a complete unsuccessful scan, it is the value read at index 20.

A search examining \(n\) indices performs \(n\) table-base global reads during selection, where \(1 \leq n \leq 21\). There is no intervening explicit dependency call in this search. Nevertheless, the supplied representation does not establish synchronization or a stable global base.

Under a stable base and stable selector contents, this is an ordinary first-match search over one table. Without those assumptions, each comparison can concern a different backing table. A matching index identifies where equality was observed using that iteration’s base; it does not bind later accesses to that same backing storage.

The index arithmetic is bounded. The largest examined or selected index is 20, giving a record displacement of 240 bytes. The furthest selector read begins at offset 248 and occupies offsets 248 through 251. With a stable base and nonwrapping address calculations, 252 readable bytes cover all possible record-field reads. These small displacements do not establish that adding them to an arbitrary 32-bit base cannot overflow.

### Selected-record address formation

After the search, the function reads the table-base global again. It forms the selected-record address using that newly read value and the selected index.

This additional read is distinct from every base read used to search. A search examining \(n\) indices therefore uses \(n+1\) table-base global reads through selected-address formation.

The retained selector and the selected-record address need not refer to the same backing table:

- A successful search can retain a matching selector from one base, then form the selected address using a different base.
- An unsuccessful search retains the selector observed at index 20, then forms an index-0 address using the newly read base.

The selected-record address is retained across the first dispatched operation. There is no subsequent visible table-base reread to replace that address before F-ca0f66276073 receives its selector-field address.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless a case states otherwise, assume valid accesses, callable targets, normal returns, and a stable table base and record contents throughout search and selected-address formation.

### First-position match

If index 0 contains the requested selector:

- Only index 0’s selector is searched.
- The table-base global is read once for that selector and again for selected-address formation.
- The first dispatch receives index 0’s payload and the requested selector.
- F-ca0f66276073 receives index 0’s selector-field address.

### Later match and duplicate selectors

If indices 0 through 2 do not match and indices 3 and 12 both contain the requested selector:

- Search reads selectors at indices 0 through 3.
- Index 3 is selected.
- Index 12 is not searched.
- The first dispatch receives index 3’s payload and the requested selector.

Without the nonmatching condition for indices 0 through 2, index 3 is not guaranteed to win; an earlier matching index takes precedence.

### No match

If none of the 21 selectors matches:

- All 21 selector positions are searched.
- There are 22 table-base global reads through selected-address formation.
- Index 0 supplies the payload and selector-field address.
- The first dispatch’s fourth explicit argument is the selector read at index 20.
- No explicit “not found” result is produced.

Substituting index 0’s selector for the retained index-20 value would change this behavior when those values differ.

### Base changes between search and address formation

Suppose indices 0 through 6 do not match, and the selector read at index 7 matches using one base. Suppose the subsequent base read used for selected-address formation yields a different base.

Then:

- The selected index remains 7.
- The retained selector remains the matching value already read.
- The payload is read at index 7 relative to the later base.
- The address supplied to F-ca0f66276073 is that later base plus 92 bytes.
- No new selector comparison validates the record at the later base.

If the base instead changes between search iterations, each selector read uses its own iteration’s base. The contract does not combine those observations into a search of a single backing table.

### Mutation during the first dispatch

If the first dispatch changes the context field and both subsequent global inputs, the later request obtains their post-dispatch values.

If it changes the selected selector field, the selector argument already supplied to that dispatch remains the earlier search value. F-ca0f66276073 receives an address rather than that saved value.

If it changes only the table-base global, the selected-field address still derives from the address formed before dispatch, provided that storage remains valid.

### Optional object absent

If F-38aa1bb9efd0 returns zero, there is no dispatch-table access through that result. F-7059d7649c5a and the final transfer are still reached, assuming preceding operations return normally.

### Required object absent

If F-682adfd5a561 or F-7059d7649c5a returns zero, no visible check converts that result into a successful no-op. Normal completion is not guaranteed; the precise invalid-access outcome is unknown.

### Unused argument variation
