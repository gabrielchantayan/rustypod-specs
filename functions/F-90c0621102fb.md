# F-90c0621102fb

## Purpose

F-90c0621102fb is a gated byte-comparison predicate. It checks two flag conditions in a supplied object, conditionally invokes an indirect function selected through that object, and compares the first byte at the returned address with an unsigned 16-bit input.

The normal result is a 32-bit value containing exactly zero or one. One requires all of the following:

- The first flag observation has mask `0x04` set.
- The subsequent flag observation has mask `0x08` clear.
- The indirect invocation returns a non-null address.
- The unsigned byte read from that address equals the full unsigned 16-bit comparison value.

The apparent intent is to test a condition associated with an enabled, non-excluded object. The meanings of the flags, object, returned storage, and comparison value are not established.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Flag gating

The first relevant operation reads the byte at object offset `0x04` and tests mask `0x04`.

If that mask is clear, the function returns zero. It does not proceed to the second flag condition, resolve the indirect callable, invoke it, or read returned storage.

If the first mask is set, the function evaluates the flag byte again and tests mask `0x08`.

If this second mask is set, the function returns zero without resolving or invoking the indirect dependency.

Only these two bits affect the gate. Other bits in the byte do not independently change the decision.

The supplied representation contains two separate flag-byte evaluations. It does not establish a single captured flag value shared by both conditions. With stable memory, the gate is equivalent to requiring bit `0x04` set and bit `0x08` clear. If the byte changes between evaluations, the two conditions concern their respective observations.

This describes the represented evaluation sequence, not a guarantee of two physical bus transactions or any particular synchronization behavior.

### Indirect dependency selection and invocation

After both flag conditions pass, the function obtains an address from the beginning of the object. It then obtains a callable address from offset `0x20` relative to that address and invokes the selected callable.

The call site shows no explicit arguments. It does not establish that the object is passed as a receiver or that any particular hidden argument is supplied.

There is one indirect invocation per execution that reaches this stage. The function has no retry or alternate-call path.

The selected callable’s result is interpreted as a byte address. A null result causes an immediate normal return of zero. No returned-byte read occurs on that path.

### Returned-byte comparison

For a non-null indirect result, the function reads exactly the first byte at that address. The byte is treated as unsigned, so its value is from 0 through 255.

The function compares that value with the complete unsigned 16-bit comparison input. Ordinary integer promotion preserves both operands’ nonnegative values; this is not a comparison against only the input’s low byte.

Equality produces one. Inequality produces zero.

There is no scan, length check, string interpretation, terminator check, or access to a second returned byte.

### State changes during the call

The flag conditions are evaluated before the indirect invocation. They are not checked again afterward.

The selected callable may change the object, flag byte, indirect-entry storage, or other state. Nothing in the supplied representation establishes that it preserves them. Such changes do not cause this function to repeat its gate or resolve another callable.

The compared byte is read after the indirect invocation returns. If the returned address aliases the object or another location modified by the dependency, the comparison uses the byte available at that post-call address, subject to valid-memory and execution assumptions.

### Arithmetic and bounds

The visible address calculations use fixed offsets. There is no input-dependent index, loop, count multiplication, or arithmetic on the comparison input.

No visible bounds or overflow checks protect those address calculations. Safe execution therefore depends on valid layout and addressability, rather than on checks performed here.
