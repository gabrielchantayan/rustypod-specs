# F-91363075c02b

## Purpose

F-91363075c02b conditionally performs preliminary calls and halfword accesses, follows a pointer obtained through a working base, and executes a loop containing a zero halfword store, a dependency call, and three halfword reads. After the loop, it invokes F-29405a9c1b17, performs two indexed stores, and invokes F-880399f1f568 with a shifted dependency result.

A polling or readiness-wait interpretation is plausible but inferred. The established behavior is the represented sequence of accesses and calls, including two separately expressed reads of the same status address. There is no visible iteration limit.

The supplied static representation reports invalid instruction data and ends at an invalid-instruction boundary. This contract describes that representation; it does not establish that the recovered interface and control flow faithfully describe an executable routine.

## Behavior

### 1. Select and execute the preliminary path

The incoming overflow condition controls the first branch. No visible computation derives that condition from the explicit arguments.

When the condition is clear:

- The preliminary calls and stores are skipped.
- Argument 3 remains the working base.
- The incoming first-store contribution remains in use.
- The common-path call argument is `0x0856f1e0`.

When the condition is set, the following operations occur in order, subject to each preceding call and access completing:

1. Subtract `0x3c` from the second incoming quantity using unsigned 32-bit arithmetic, then logically shift the result right by eight. Call this the **preliminary shift value**.
2. Invoke F-indirect-01 with `0x0856f1e0`. Its target is formed from the incoming link-related value plus `0xffe`.
3. Invoke F-indirect-02 with no explicit arguments and obtain a represented 32-bit result.
4. Add `0x31` to that result and multiply by two. Call the resulting quantity the **derived value**. Store a zero halfword at the derived value plus `0x002cffb0`.
5. Read a signed halfword at **twice the quantity obtained by subtracting `0x50` from the derived value**. The address grouping is:

   **2 × (derived value − `0x50`)**

   Under 32-bit wrapping arithmetic, this is **2 × derived value − `0xa0`**, not 2 × derived value − `0x50`.

   Sign-extend the loaded halfword to 32 bits, reinterpret those bits as unsigned, and logically shift right by 29. Call this the **sign-derived value**.
6. Replace the first-store contribution with the preliminary shift value interpreted as signed and arithmetically shifted right by its own low eight bits.
7. Invoke F-indirect-03 with three arguments: the sign-derived value shifted left by 14, that value shifted left by 13, and a 32-bit value obtained from the preliminary-argument global source.
8. Invoke F-indirect-04 with no explicit arguments.
9. Obtain the replacement-base global value for use as the working base. The representation also specifies a halfword store whose address is that global datum’s value plus ten and whose payload is the low 16 bits of that datum’s value.
10. Shift the captured replacement base left by eight to form the working base, and select zero as the common-path call argument.

The replacement-base datum appears separately in the base acquisition, store address, and store payload expressions. Exact machine-load count and ordering among those references are not established. They must not be collapsed into one immutable snapshot without further evidence.

The sign-derived value is zero for a nonnegative signed halfword and seven for a negative signed halfword. Consequently, the first two F-indirect-03 arguments are either both zero or respectively `0x0001c000` and `0x0000e000`.

The preliminary shift value is at most `0x00ffffff`, but its low eight bits can still specify a shift count greater than 31. The concrete result of such a shift is unresolved; count masking or a particular zero/sign-fill result is not established.

### 2. Execute common calls and follow the working-base pointer

The working base is captured before the next two calls.

First, invoke F-indirect-05:

- On the ordinary path, its target derives from the incoming link-related value plus `0xffe`, and its argument is `0x0856f1e0`.
- On the preliminary path, its target derives from a fixed code-location value plus `0xffe`, and its argument is zero.

Next, invoke F-indirect-06 with no explicit arguments.

Only after both calls does the routine:

1. Read a 32-bit pointer representation from the captured working base plus `0x40`.
2. Read a signed halfword through that pointer.
3. Construct two arguments and invoke F-indirect-07.

The first argument depends on the sign of the signed 32-bit sum of the pointer representation and the sign-extended halfword. Where that sum and the shifts have an unambiguous ordinary two’s-complement interpretation, the argument is:

- Zero if the sum is nonnegative.
- `0xff000000` if the sum is negative.

The second argument is the pointer representation interpreted as signed and arithmetically shifted right by 28. Under that interpretation, it ranges from −8 through 7.

No result from F-indirect-07 is explicitly consumed. This does not establish that the dependency has no effects on memory or other machine state.

### 3. Execute the halfword-access loop

Before the first iteration:

- The address index is the working base multiplied by `0x02000000`.
- The loop-call argument is zero.
- The store contribution is the incoming or preliminary-path replacement contribution shifted left by nine.

Each iteration has the following represented order:

1. Store a zero halfword at the current store contribution multiplied by `0x1000`, plus `0x1e`.
2. Invoke F-indirect-08 with the current loop-call argument.
3. Reset the store contribution to zero.
4. Read an unsigned halfword at four times the current address index, plus `0x1c`. Retain this **data halfword** as the next loop-call argument and, if the loop exits, as the base for a later byte read.
5. Read an unsigned halfword at the dependency-exposed register value plus `0x14`. Multiply it by two to obtain the next address index.
6. Read an unsigned halfword again at that register-derived address.
7. Repeat if the second status read is zero; otherwise exit.

The two status reads are distinct in the supplied representation. The first determines the next index and the eventual third argument to F-29405a9c1b17. The second controls termination. Their values need not agree.

Under 32-bit wrapping arithmetic:

- The first zero-store address is the original selected contribution shifted left by 21, plus `0x1e`.
- Every later zero-store address is `0x0000001e`.
- The first data-halfword address is the working base shifted left by 27, plus `0x1c`.
- Each later data-halfword address is eight times the preceding iteration’s first status-halfword value, plus `0x1c`.

The loop executes at least once if reached. It has no visible timeout, retry bound, cancellation check, or alternate exit.

F-indirect-08 may change memory or external state before the reads. The exposed register is not established to be a conventional return value, a valid object pointer, or stable between calls.

### 4. Read the byte and invoke F-29405a9c1b17

After loop exit, read one 8-bit quantity at the terminating iteration’s data halfword plus `0x1a`.

Invoke F-29405a9c1b17 with:

1. Argument 5 unchanged.
2. Argument 6 logically shifted right by 28.
3. Twice the terminating iteration’s **first** status-halfword value.
4. The byte just read, represented as an 8-bit quantity.

The second argument ranges from 0 through 15. The third ranges from 0 through 131070 and can be zero even when the loop exits. The fourth represents a byte value from 0 through 255.

The byte address depends on the data-halfword read, not either status read.

### 5. Perform final stores and invoke F-880399f1f568

If F-29405a9c1b17 returns, retain its represented 32-bit result. The remaining order is:

1. Read the 32-bit final-payload global datum.
2. Store the low 16 bits of argument 8 multiplied by eight at argument 8 multiplied by eight, plus `0x34`.
3. Store the previously read 32-bit global value at argument 9 multiplied by eight, plus `0x74`.
4. Invoke F-880399f1f568 with the retained dependency result shifted left by 20.
5. Encounter the invalid-instruction termination marker if that call returns.

The final global read occurs after F-29405a9c1b17; that dependency must not be assumed to preserve its value.

The final store payload is captured before either final store. If the halfword store aliases the global datum, the subsequent 32-bit store still uses the already captured payload.

Under 32-bit wrapping shift evaluation, the argument to F-880399f1f568 depends only on the retained result’s low 12 bits. The representation does not independently settle signed-left-shift semantics for every possible result.

## Side effects

Established direct memory modifications are:

- A preliminary-path zero halfword store.
- A preliminary-path halfword store based on the replacement-base datum.
- One zero halfword store per loop iteration.
- One final indexed halfword store.
- One final indexed 32-bit store.

Reached dependencies may introduce additional effects. Their preservation, mutation, ownership, error, and termination behavior is unknown.

No explicit allocation, deallocation, reference counting, ownership transfer, rollback, or error-result construction is visible. Passing a value or derived address does not establish borrowing, retention, release, or ownership by a dependency.

All reached memory accesses require suitably accessible storage, and every reached call requires a valid executable target. No visible null check, bounds check, alignment check, or address validation precedes these operations.

Aliasing is not excluded. Direct stores can affect later reads; dependencies can alter subsequently accessed data; global-looking sources may overlap storage. In particular, the two status reads must not be assumed equal merely because their represented addresses match.

A fault or nonreturning dependency can prevent all subsequent operations. No recovery path is visible. Stores completed before that interruption are not visibly undone.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes execution reaches the described point and all preceding required operations complete.

1. **Ordinary path.** With the incoming overflow condition clear, F-indirect-01 through F-indirect-04 and both preliminary stores are skipped. Argument 3 remains the working base, and F-indirect-05 receives `0x0856f1e0`.

2. **Correct preliminary read grouping.** If F-indirect-02 supplies zero, the derived value is `0x62`. The signed-halfword read address is twice (`0x62` minus `0x50`), namely `0x24`. It is not `0x74`, which would result from subtracting only after doubling.

3. **Negative preliminary halfword.** If the halfword at the correctly grouped preliminary read address is −1, the sign-derived value is seven. F-indirect-03 receives `0x0001c000` and `0x0000e000` as its first two arguments.

4. **Upper-nibble extraction.** If argument 6 is `0xa1234567`, F-29405a9c1b17 receives 10 as its second argument.

5. **Exit with zero third argument.** If the terminating iteration’s first status read is zero and its second is one, the loop exits. F-29405a9c1b17 receives zero as its third argument.

6. **Continue with differing status values.** If the first status read is five and the second is zero, another iteration occurs with index ten. Under wrapping address arithmetic, that iteration reads its data halfword at `0x44` and performs its zero halfword store at `0x1e`.

7. **Byte-source distinction.** If the terminating data halfword is `0x120` and the first status halfword is five, the byte is read at `0x13a`; the third argument to F-29405a9c1b17 is ten. These values have separate sources.

8. **Final indexed stores.** If arguments 8 and 9 are three and two respectively, the halfword store writes 24 at `0x4c`, followed by the captured 32-bit global payload at `0x84`, assuming both destinations are writable.

9. **Shifted result.** If F-29405a9c1b17 returns `0x12345abc`, wrapping 32-bit shift evaluation yields `0xabc00000` as the argument to F-880399f1f568.

10. **Persistent zero termination reads.** If every termination read is zero and all operations continue completing, the loop continues without a visible bound. Neither identified post-loop dependency is reached.
