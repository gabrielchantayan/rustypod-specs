# F-0938f691948f

## Purpose

F-0938f691948f dispatches operations against caller-supplied mutable state. Its established behavior includes storing and resolving a selected identifier, clearing a matching selection, draining records, emitting notifications, submitting mapped commands, and conditionally clearing timed-state fields.

These are descriptive labels, not established domain meanings. The supplied source does not establish what the identifiers, handles, records, or notifications represent.

Normally returning paths return zero except for operation 1, which can return a nonzero result from F-799b69a6c06d. Certain rejected inputs and a zero lookup result lead to F-a817d8d58c10, marked nonreturning in the supplied source.

This contract distinguishes the function’s own reads and writes from dependency effects. No dependency is established to preserve the selected identifier, associated handle, timed fields, or global root.

## Interface

### Arguments and result

The interface has three 32-bit arguments:

| Argument | Interpretation |
|---|---|

| Operation selector | Selects operations 1, 4, 8, or 32. Other values return zero. |

There is no explicit null check, storage-size check, address validation, or handle validation. Accessible storage and dependency-specific valid objects are preconditions wherever accessed. The behavior of invalid addresses is not established.

### Global-root access

At entry, the function captures the address identifying a global pointer slot. On paths using the root object, it subsequently reads the pointer stored in that slot.

| Root-relative offset | Established use |
|---|---|
| `+0x2D8` | Address supplied to notification-bracketing dependencies. |
| `+0x2F4` | 32-bit reference read during the timed-state comparison. |

The root object is not established to be the supplied state object. The timed check reads its reference through the global root but writes expiry fields through the supplied state address.

### Integer rules

- Operation 4 accepts arguments whose **signed 32-bit** interpretation is less than 3, including negative values.
- Operation 8 accepts only arguments **unsigned-less-than 3**.
- Operation 1 passes its initial gate when the selected identifier’s **signed 32-bit** interpretation is at most 2, including negative values.
- Mask operations use 32-bit values, including a 32-bit complement.
- Timed subtraction uses unsigned 32-bit wraparound.
- The timed comparison uses only the low 32 bits of a produced 64-bit value. Its upper half participates separately in a later dependency argument.

## Behavior

### Operation 4: store and resolve a selection

First, write the operation argument to the selected-identifier field. This precedes validation and every dependency call.

If the original argument has signed value at least 3, invoke F-a817d8d58c10. This branch performs no local handle write before that invocation.

Otherwise:

1. Invoke U-01, the unmapped provider.
2. Call F-b37968c9f644 with the provider result plus four bytes and a fresh read of the selected identifier.
3. Store the returned 32-bit value in the associated-handle field.
4. If that returned value is zero, invoke F-a817d8d58c10.
5. Otherwise, invoke U-01 again.
6. Call F-c1e400b68436 with the new provider result plus four bytes and another fresh selected-identifier read.

The zero test concerns the lookup result, not a later reread of the handle. Likewise, identifiers passed to dependencies need not equal the original argument if preceding dependencies changed the field.

If F-c1e400b68436 returns anything other than exactly 1, return zero without further local writes to the selection or handle. This does **not** establish their final contents: preceding dependencies may have changed them.

For a return of exactly 1, construct a 20-byte notification:

| Byte offset | Width | Contents |
|---|---:|---|
| 0 | 1 byte | 3 |
| 1–3 | 3 bytes | Not initialized by this function |
| 4 | 32 bits | `0x11` |
| 8 | 32 bits | Selected identifier read during construction |
| 12 | 32 bits | 0 |
| 16 | 32 bits | 3 |

The first four bytes are not established to represent the integer 3; three of them remain unspecified.

Call F-c6c589453fa8 with leading arguments 0 and 0, the notification address, and length 20. Its result is not used.

After that call, reread the selected identifier. If it equals 1, initialize a separate 32-bit temporary to 100 and call F-2708b7c79728 with another selected-identifier read and the temporary’s address.

Thus, an original argument of 1 does not by itself guarantee this call. Conversely, another original argument does not prevent it if the post-notification identifier is 1.

Finally, write `0x7FFFFFFF` to the selected identifier, then zero to the associated handle, and return zero. There is no intervening dependency call between these final writes and return.

### Operation 8: clear a matching selection and drain

Test the operation argument as unsigned.

- If it is at least 3, invoke F-a817d8d58c10.
- Otherwise, compare it with the selected identifier.
- If they differ, return zero without dependency calls or local state writes.

For a match, write `0x7FFFFFFF` to the selected identifier, then zero to the associated handle.

Repeatedly call F-704f99fd5e22 with the supplied state address, the original operation argument, and three writable 32-bit temporary addresses. Before every call, initialize their values, in argument order, to:

1. `0x0000FFFF`
2. `0x0000FFFF`
3. 0

Repeat while the dependency returns zero. Its first nonzero result ends the loop, after which the function returns zero.

The temporary outputs are not otherwise examined. No iteration bound or timeout is present. If every call returns zero, this operation does not terminate.

Selection clearing occurs before draining. The function does not clear the fields again after the drain; dependency mutations during draining may therefore determine their final contents.

### Operation 32: drain records and check timed state

Before each drain call, initialize four writable 32-bit slots, in argument order, to:

1. A fresh selected-identifier read.
2. `0x0000FFFF`.
3. `0x0000FFFF`.
4. 0.

Call F-e08f888de5db with the supplied state address and those four addresses.

A nonzero result ends draining. For a zero result, inspect the low 16 bits of the third slot:

- If they equal 6, emit no notification and continue draining.
- Otherwise, construct and emit an eight-byte notification.

The notification contains:

| Byte offset | Width | Contents |
|---|---:|---|
| 0 | 32 bits | 4 |
| 4 | 32 bits | `0x00000F00` combined with the third slot’s low byte |

The filter uses 16 bits; notification construction uses only eight. Bits above the low byte do not enter the notification’s second word.

For each emitted notification:

1. Read the global-root pointer and calculate its `+0x2D8` address.
2. Call U-02 with that address.
3. Call F-c6c589453fa8 with leading arguments 1 and 0, the notification address, and length 8.
4. Call U-03 with the same saved address.

Both bracketing calls use the same address even if a dependency changes the global-root pointer. A later emitted notification calculates its address anew. No synchronization semantics are established merely by these calls.

There is no drain iteration limit. The timed check is reached only when F-e08f888de5db returns nonzero.

Then read the supplied state’s byte at `+0x2F8`. If zero, return zero without the timed-object calls. Otherwise:

1. Call F-7a117b899bf6 with a temporary-object address.
2. Interpret the temporary’s first 32-bit word as an address. Read an indirect call target at that address plus `0x0C`, and invoke U-04 with the temporary-object address and a separate output address.
3. Call F-bf18a6a8124b with that output address, obtaining a 64-bit value.
4. Read the current global-root pointer and its 32-bit reference at `+0x2F4`.
5. Subtract that reference from the produced value’s low half, modulo \(2^{32}\).
6. If the unsigned difference exceeds 499, write zero to the supplied state’s byte at `+0x2F8`, then zero to its 32-bit field at `+0x2F4`.
7. Call F-ec22bd8215d3 with the temporary-object address and the produced upper half minus the low-half borrow.
8. Return zero.

The borrow is 1 precisely when the produced low half is unsigned-less-than the sampled reference; otherwise it is 0. The second argument’s resulting bit pattern is 32 bits, including wraparound when subtracting the borrow.

F-ec22bd8215d3 is called whether or not expiry writes occur. A difference of 499 causes no local expiry write; 500 does. Neither outcome guarantees final timed-field contents because dependencies may modify those fields, including after the local expiry writes.

### Operation 1: issue a mapped command

Otherwise:

1. Invoke U-01.
2. Call F-bc2b33235f5b with its result plus four bytes and a fresh selected-identifier read. Save the 32-bit result as status flags.
3. Invoke U-01 again.
4. Call F-be95475fc79f with its result plus four bytes and another selected-identifier read. Save the 32-bit result as the original mask.

These queries occur before rejecting an unsupported operation argument.

Map supported arguments as follows:

| Argument | Command value | Candidate mask when `(status flags masked by 0xC) = 0x4` |
|---:|---:|---:|
| 1 | 2 | 1 |
| 2 | 3 | 0 |
| 3 | 0 | 1 |
| 4 | 1 | 0 |

For command value 0 only, perform this ordered sequence before command submission:

1. F-bd3e4559b3e7 with one temporary-object address.
2. F-799bc49cafe5 with another temporary address and 250.
3. F-98a2c6875ccd with those two addresses.
4. F-3e5f2a992ae5 with the first address.

No duration or blocking guarantee is established for this sequence.

- Invoke U-01 again.
- Call F-4944ce526800 with its result plus four bytes, a fresh selected-identifier read, constant 1, and the candidate mask.

The missing-bit test is the 32-bit expression “original mask AND complement of candidate mask is nonzero.” It uses saved query results, not a mask reread after submission.

## Side effects

Direct writes target the listed supplied-state fields and temporary storage. No direct global-root write is shown. Dependencies may have additional effects.

Established ordering includes:

- Operation 4 stores the argument before validation and lookup.
- Its completion notification precedes the fresh identifier comparison and final selection clearing.
- Operation 8 clears selection before draining.
- Operation 32 finishes draining before sampling the timed flag.
- Timed expiry clears the flag before clearing the supplied-state reference field.
- Operation 1 submits the combined mask before submitting the command; only failure handling submits the candidate mask afterward.

A local write is not a preservation guarantee across a dependency call. Fresh reads may observe dependency mutations. This distinction applies to selection fields, handles, timed fields, and global-root identity.

## Acceptance examples

These are conditional static expectations, not runtime results. There is no blanket dependency-preservation assumption.

1. **Unknown selector.** A selector outside 1, 4, 8, and 32 returns zero without dependency calls or supplied-state writes.

2. **Selection without completion.** For operation 4, argument 2, nonzero lookup, and predicate result 0, the function locally writes identifier 2 and then the lookup result to the handle. It emits no notification and performs no later local selection clearing. Identifier 2 is guaranteed to remain stored only if both provider calls and both selection dependencies preserve that field after its initial write. A final handle equal to the lookup result additionally requires subsequent dependencies to preserve the handle.

3. **Selection completion.** For operation 4, argument 1, nonzero lookup, and predicate result 1, the function emits the 20-byte notification. If the relevant calls preserve identifier 1 through the post-notification comparison, F-2708b7c79728 is called with a value initialized to 100. Without that preservation condition, the call depends solely on the fresh comparison. Normal completion ends with local sentinel and zero-handle writes.

4. **Mutation suppresses the conditional call.** Under the preceding completion conditions, if F-c6c589453fa8 leaves the selected identifier equal to 2, F-2708b7c79728 is not called. Final local selection clearing still occurs.

5. **Signed boundary.** Argument `0xFFFFFFFF` reaches lookup under operation 4 because its signed value is −1. The same argument under operation 8 reaches F-a817d8d58c10.

6. **Nonmatching clear.** Operation 8 with argument 1 and sampled identifier 2 returns zero without clearing or draining.

7. **Record truncation.** An operation-32 drain return of zero with third output `0x00000106` produces notification second word `0x00000F06`. The low 16 bits are not 6, despite the low byte being 6.

8. **Expiry boundary.** With the timed branch entered, produced low half 1000, and sampled reference 501, no local expiry writes occur. A sampled reference of 500 causes local flag-zero and reference-zero writes, in that order. “Fields remain unchanged” in the first case requires preservation by all intervening dependencies; “fields remain zero” in the second additionally requires preservation by F-ec22bd8215d3.

9. **Unsigned wrap.** Produced low half 10 and sampled reference 20 yield difference `0xFFFFFFF6`, causing local expiry writes. F-ec22bd8215d3 receives the produced upper half minus 1, modulo \(2^{32}\).

10. **Command success and failure.** For operation-1 argument 1, saved status satisfying the mask condition, and original mask 2, the candidate is 1 and the first submitted mask is 3. A nonzero submission followed by follow-up result 7 returns 7 without candidate-mask submission. Submission result zero instead triggers the 100-parameter sequence, submits candidate mask 1, and returns zero.
