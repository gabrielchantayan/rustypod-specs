# F-703c13b20bf3

## Purpose

F-703c13b20bf3 conditionally replaces the two least-significant bits of a working value and submits the result to a second dependency. Modification and submission occur only when the first dependency returns zero.

The selector determines the replacement low-bit pattern:

| Selector | Replacement bits 1–0 |
|---|---|
| 1 | `11` |
| 6 | `01` |
| 7 | `10` |
| Every other 32-bit value | `00` |

The transformation also clears bits 31–8. It preserves only bits 7–2 of the working value supplied by the first dependency.

**Established static behavior:** the function invokes an initial dependency, tests its return value, and conditionally transforms a local 32-bit value before invoking a second dependency.

**Inferred intent:** the fixed arguments and low-bit manipulation suggest a read–modify–submit operation on a selected external resource. Neither the resource type nor the meanings of the low-bit patterns are established.

The second and third arguments have no direct effect on the visible control flow, working value, or dependency arguments. They are not interpreted as pointers or forwarded to either dependency.

The fourth argument is not merely unused input. It supplies the working cell’s initial contents. Its eventual influence depends on whether, and how much, the first dependency overwrites that cell.

The working cell is a local unsigned 32-bit scalar. Both dependencies receive its address. The pointer therefore designates the same four-byte object during both calls, when the second call occurs.

No byte order is established by the supplied evidence. Integer bit positions are nevertheless well defined: bit 0 is the least-significant bit and bit 31 is the most-significant bit. A dependency that accesses individual bytes may introduce endianness-sensitive behavior not specified here.

No caller-provided output buffer is accepted. The function does not return the transformed value, either dependency’s result, or an explicit success indication.

### Transformation after a zero result

The transformation operates on the working cell’s contents **after** F-b3e2a11b7207 returns. It does not restore the fourth argument before modifying the cell.

The function first retains only bits selected by the 32-bit mask `0x000000FC`:

- Bits 7–2 retain their values.
- Bits 1–0 become zero.
- Bits 31–8 become zero.

This mask is not a full-width “clear the lowest two bits” mask. High-order bits are discarded even if they were present in the initial fourth argument or written by the first dependency.

The selector then determines the low two bits:

- Selector 1 sets both bits.
- Selector 6 sets bit 0 only.
- Selector 7 sets bit 1 only.
- Every other selector leaves both bits clear.

Selectors 0, 2, 3, 4, and 5 are explicitly represented as leaving the low bits clear. Values outside 0–7 also leave them clear because no selector-specific modification applies.

Immediately before the second dependency call, the working cell therefore has these invariants:

- Its value is between 0 and 255 inclusive.
- Bits 31–8 are zero.
- Bits 7–2 match the corresponding bits present after the first dependency returned.
- Bits 1–0 match the selector table.

The visible transformation uses masking and bit setting, not addition or subtraction. There is no arithmetic carry, borrow, or overflow to resolve.
