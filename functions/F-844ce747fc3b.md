# F-844ce747fc3b

## Purpose

F-844ce747fc3b obtains a candidate through a service, checks its eligibility, and conditionally processes a fixed table of 33 records. Each processed record receives a one-byte classification result. Records with nonzero associated handles also trigger two dependency calls.

After processing the table, the function may prepare temporary local storage and supply it to two operations on a separately resolved target.

On normal completion, the function returns the original candidate. Failed candidate lookup or failed eligibility returns zero.

“Candidate,” “record,” “classification,” and “target” describe data-flow roles, not established application semantics.

## Interface

### Input and return value

The single argument is represented as a 32-bit integer and used as a context address. Its only direct dereference is a four-byte read at offset `0x378`, performed separately for each record with a nonzero handle, after that record’s first dependency call.

The input is therefore not dereferenced on every path. Valid context storage is required whenever execution reaches one of those reads; no explicit context-validity check is present.

The return value is represented as a 32-bit integer:

- Zero when candidate lookup returns zero.
- Zero when candidate eligibility returns zero.
- Otherwise, the original candidate value, provided subsequent processing completes normally.

Results from later dependencies do not replace the retained candidate as the normal return value.

## Behavior

### Candidate acquisition and eligibility

F-938c950e5046 is called without explicit arguments. Its result is used as a service-object address.

The function obtains the service’s dispatch-table address from offset zero and calls the entry at dispatch-table offset `0xF8`, passing the service object and a value read from global lookup-selector storage. No explicit null check protects the service object, dispatch table, or call target. The relative evaluation order of the selector read and dispatch-address accesses is not established by the call expression.

A zero lookup result immediately returns zero. No eligibility call, table processing, or optional-stage gate follows.

For a nonzero candidate, F-682adfd5a561 receives that candidate and the literal `0x1700`. After this call returns, the function reads the global table-base value. It then branches on the eligibility result:

- Zero: return zero.
- Nonzero: process the table.

The table-base read therefore occurs even when eligibility rejects the candidate. This is a read of the global base value, not a dereference of the table it designates.

### Record traversal

The function processes records in ascending index order, from 0 through 32 inclusive. The table base is captured once before the eligibility-result branch and retained throughout the loop.

Changing the global table-base location during a callback does not redirect later iterations. This does not guarantee that the captured table storage remains valid.

For each record, the observable sequence is:

1. Read the four-byte classification value at offset `0x04`.
2. Evaluate the classification comparisons described below.
3. Write one byte, zero or one, at offset `0x10`.
4. Read the four-byte handle at offset `0x00`.
5. If the handle is nonzero, perform both record dependency calls.

There is no record-content-based early exit. A zero handle suppresses the calls, not classification or the flag write.

### Classification: exact primary-global read schedule

The classification value is captured once per record. The primary comparison global is not captured once and reused throughout classification.

Each record has this primary-global access schedule:

1. Read the primary global for the initial equality comparison against the record’s captured classification value.
2. Read the primary global again unconditionally, including when the initial equality succeeds.
3. If the initial equality failed, perform two additional primary-global reads. One supplies the unshifted operand of a bitwise OR; the other supplies the operand interpreted as signed 32-bit and arithmetically shifted right by 25 bits. The relative evaluation order of these two operand reads is not established.

Thus, classification performs exactly two primary-global reads when the initial equality succeeds, and exactly four when it fails.

When the initial comparison fails, the value obtained by the unconditional second read is replaced before the next equality comparison. It does not supply either operand of the OR expression.

When the initial comparison succeeds, the second read still occurs and its value participates in a further equality comparison. Regardless of that comparison’s result, the already-successful initial comparison establishes acceptance.

For an initial mismatch, the transformed-pattern comparison uses the OR of two separately obtained values. It is not necessarily the transformation of the initial read, the unconditional second read, or any single captured primary value.

These distinctions matter when global storage changes between reads. No dependency call occurs within this classification computation, but the source supplies no synchronization or consistent-snapshot guarantee.

### Classification: remaining comparisons and stable-storage meaning

If neither the initial equality nor the transformed-pattern equality succeeds, the function consults six additional comparison globals in order.

The first five fallback globals are each read only after all preceding acceptance comparisons have failed. The sixth and final fallback global is read only if acceptance has not already been established. Some intervening equality checks reuse an already obtained comparison value; they do not imply additional global reads.

If any comparison succeeds, the flag written is one. Otherwise, it is zero.

When all comparison globals remain stable during a record’s classification, this is equivalent to membership in eight 32-bit patterns:

- The primary global.
- The primary global ORed with its signed 32-bit arithmetic-right-shift-by-25 result.
- Each of the six fallback globals.

This eight-pattern description is conditional on stable comparison storage. It is not an unconditional replacement for the read schedule.

All equality comparisons use complete 32-bit bit patterns. The record’s classification value is unsigned; the signed interpretation applies specifically to the shifted operand.

For the shift:

- A primary value with its high bit clear produces a shifted value from zero through `0x3F`.
- A primary value with its high bit set produces a sign-extended shifted value from `0xFFFFFFC0` through `0xFFFFFFFF`.
- OR combines the resulting 32-bit patterns.
- Accepted patterns may coincide; eight distinct values are not required.

Callbacks after a record’s classification may change globals used by subsequent records.

### Per-record calls

For a nonzero handle, the first, unresolved record-operation dependency receives:

- The handle just read.
- The byte read back from the record’s flag at offset `0x10`.

The flag write precedes this call and the flag argument is read from storage, rather than supplied solely from a retained comparison result.

After that dependency returns, F-bce3eafc6f93 receives:

- A four-byte value from input-context offset `0x378`.
- A four-byte value from the current record’s offset `0x0C`.

Both argument reads occur after the first dependency returns. Their relative order is not established.

Consequently, changes made by the first dependency to the context field or record payload can affect the second call. The second call does not receive payload values captured before the first call.

Neither dependency’s return value is inspected. If either fails to return normally, later processing is not established.

### Optional post-loop stage

After all 33 records, F-3fac671648b8 is called without explicit arguments. Further processing requires these conditions, evaluated in order:

1. F-3fac671648b8 returns nonzero.
2. The candidate byte at offset `0xA0` is zero.
3. A byte accessed through a global address is nonzero.

Evaluation short-circuits. Failure of the first condition suppresses both later checks. A nonzero candidate byte suppresses the global-addressed byte check.

When all conditions pass:

1. The related-object value at candidate offset `0x34` is read and retained.
2. F-e57b05520b65 receives a temporary-local-storage address and the address at candidate offset `0x80` twice.
3. If the retained related-object value is nonzero, F-ee8733a08210 receives the same temporary-storage address and that retained value plus `0xD0`.
4. F-ffe0d92c57b7 receives the candidate and returns a target value.
5. For a nonzero target, F-c9b5d17d8d1e receives that target and the temporary-storage address.

Changes to candidate offset `0x34` during temporary preparation do not change the retained related-object value. Likewise, the second target operation does not re-resolve the target after the first operation.

The temporary storage may change between calls. Reusing its address does not establish identical contents.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, accessed storage is valid, dependencies return normally, and no interfering mutation changes the stated conditions.

### Lookup and eligibility rejection

If dispatch lookup returns zero, the result is zero; eligibility, record processing, and the optional-stage gate do not occur.

If lookup succeeds but eligibility returns zero, the global table base is still read. No record is dereferenced by the loop, no flag is written, and the result is zero.

### Zero handles

If eligibility succeeds and every handle is zero when read, all 33 flags are still written. Neither per-record dependency is invoked, and the context field is not read by the loop. F-3fac671648b8 is called afterward.

### Initial primary match still requires a second read

If the record value equals the first primary-global read, classification accepts it even if the unconditional second primary-global read differs.

Exactly two primary-global reads occur for that record. The OR-expression operand reads and all fallback-global reads are skipped.

### Initial mismatch requires four primary reads

If the initial primary comparison fails, the unconditional second read still occurs, followed by two separate OR-operand reads. This remains true if the transformed-pattern comparison then succeeds.

Changing only the value returned by the unconditional second read cannot change that record’s classification: its value is replaced before the transformed-pattern comparison.

### Stable arithmetic examples

With a stable primary value of `0x02000000`, the transformed pattern is `0x02000001`. Either pattern is accepted.

With a stable primary value of `0x80000000`, the transformed pattern is `0xFFFFFFC0`, not the result of a logical right shift.

A value matching neither stable primary pattern nor any fallback pattern receives zero.

### Different OR operands

Suppose the record value is `0x02000002` and the first primary read is zero, so the initial comparison fails. If the unshifted OR operand reads `0x02000000` and the signed-shift operand reads `0x04000000`, their combination is `0x02000002`, so classification accepts.

This example assigns values by operand role; it does not assert which operand is evaluated first. The unconditional second read does not supply either operand.

### Callback timing

For a nonzero handle, the flag write precedes the first record operation. If that operation changes the payload at offset `0x0C`, F-bce3eafc6f93 receives the subsequently read payload.

If a callback changes only the global table-base value, later iterations continue using the previously captured table base.

### Optional-stage outcomes

If all optional gates pass, the related-object value is zero, and target resolution succeeds, temporary preparation occurs, augmentation is skipped, and both target operations occur in order.

If target resolution instead returns zero, both target operations are skipped. Earlier temporary preparation and any augmentation remain performed. The normal return is still the original candidate.
