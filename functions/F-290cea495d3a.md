# F-290cea495d3a

## Purpose

F-290cea495d3a coordinates a stateful operation involving a receiver, a selector object, a context, and a resource obtained through an output parameter. It returns a 32-bit success indicator and updates receiver fields, resource flags, and dependency-managed state.

The established behavior is orchestration: select an initial object, publish it into receiver-managed storage, obtain a resource, perform one of two operation variants, apply attributes, update bookkeeping, and finalize a context-associated transfer.

The domain meaning of these objects is unknown. Terms such as “receiver,” “context,” “resource,” and “status” below distinguish their roles without asserting application semantics.

A return of zero is not transactional failure: initialization, dependency calls, and some receiver writes may already have occurred.

## Behavior

The first visible action is a call to F-f255bd5793eb with no displayed arguments. A local auxiliary 32-bit word is then initialized to zero.

If the explicit context argument is zero, the effective context is read from receiver offset `0x9A8` **after** attribute preparation. Otherwise, the supplied context is used.

The effective context is then retained for subsequent calls. Later reads of receiver offset `0x9A8` are separate reads and need not equal this retained value.

### 2. Select the initial object

The selector’s query at virtual-table offset `0x0C` is invoked with the selector as its receiver.

- If the query returns zero, F-267f68fe54d6 is called with the effective context. Its result becomes the selected object.
- If the query returns nonzero, the selected object is read from selector offset `0x04` after that query.

A zero selected-object value takes the failure exit described below. There is no attempt to obtain a fallback object when the query returns nonzero but the selector field is zero.

### 3. Publish the selected object and attempt resource acquisition

1. F-1c06d0a5910b receives a local temporary region, the selected object, and zero.
2. Its result is passed to F-047d22db5c73 together with the address at receiver offset `0x74`.
3. F-c1466ea05103 receives that temporary region.

The function next writes a Boolean byte at receiver offset `0x93F`. The comparison is between the selected object and a 32-bit value reached through a global pointer chain: load the global root, load its pointer at offset `0x30`, then load a word at offset `0xF40`.

F-6aa326f23bb0 then receives:

- a fresh read of receiver offset `0x9A8`, not necessarily the retained effective context;

A nonzero return takes the failure exit. Zero advances to the success path. The output slot is not visibly initialized before the call.

Thus, acquisition failure can occur after the selected-object storage operation and Boolean write.

### 6. Apply mode and resource flags

Mode 3 skips both calls. It does not skip subsequent flag or attribute processing.

The function then updates the resource flag byte at offset `0x1AC`:

1. Read the context pointer from receiver offset `0x9A8`, then its byte at `0xF4C`.
2. Read the resource flag byte.
3. Clear bit `0x10` if the context byte is zero; otherwise set it.
4. Write the resulting flag byte.
5. Read receiver offset `0x9A8` again, then that context’s byte at `0xF4D`.
6. Modify bit `0x20` in the byte computed in step 3: clear for zero, set for nonzero.
7. Write the flag byte again.

The second update uses the previously computed byte rather than a fresh read of the resource flag byte. Both writes occur even when their respective bit already has the requested value. All other bits are preserved from the original resource-byte read.

F-310d2f160390 then receives the resource word and the first byte of each attribute buffer.

F-6fa4e01d8d29 is called with the auxiliary word, the selected value, and zero, and its result overwrites receiver offset `0x5C`.

## Acceptance examples

These are conditional conformance examples, not executed tests. They assume valid memory and normally returning dependencies.

1. **No selected object.** If the selector query returns nonzero and selector offset `0x04` contains zero, the function calls the failure-exit dependency and returns 0. It does not call the fallback provider or resource-acquisition dependency.

2. **Acquisition failure after publication.** If selection produces a nonzero object but F-6aa326f23bb0 returns nonzero, selected-object processing and the comparison-byte write have already occurred. Resource-operation, resource-flag, and finalization steps do not occur.

3. **Distinct context sources.** If the explicit context is nonzero and differs from receiver offset `0x9A8`, fallback selection and operation calls use the explicit context. Resource acquisition and flag copying use the separately read receiver context.

4. **Flag replacement.** Given an original resource flag byte of `0xAF`, a zero context byte at `0xF4C`, and a nonzero byte at `0xF4D`, the first resource write is `0xAF` and the second is `0xAF`. Conversely, original `0x10` with those same context bytes produces writes of `0x00` and `0x20`. The unchanged-value writes remain part of the behavior.

5. **Mode suppression.** Mode 3 skips mode conversion and its resource application, while successful flag, attribute, status, and finalization processing still occurs. If another mode produces a conversion result of `0x12345678`, the resource application receives the 16-bit value `0x5678`.

6. **Status normalization.** If no intervening dependency changes the relevant field, a status of −1 becomes zero. An ordinary nonzero status can remain unchanged for variant zero when no auxiliary conversion runs. Any nonzero variant ultimately forces status to zero.

7. **Changing receiver-query results.** With a nonzero auxiliary word, a nonzero query result can enable the later conversion branch, while a subsequent zero query result causes that conversion to receive discriminator 1.
