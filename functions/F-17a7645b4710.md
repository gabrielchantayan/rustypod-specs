# F-17a7645b4710

## Purpose

F-17a7645b4710 transfers four individual bytes from a fixed-offset region of an address-bearing input into a caller-supplied destination.

The established behavior is an ordered sequence of four byte reads and four byte writes. Each source read is followed by its corresponding destination write before the next source read occurs. This ordering matters when the two regions overlap or refer to storage with externally observable access behavior.

The operation is not established as an overlap-safe block copy or an atomic four-byte transfer. Its broader application purpose and the meanings of the four bytes are unknown.

## Behavior

### Address selection and transfer order

The function uses four fixed source offsets. It does not obtain a length, follow a pointer stored in the source region, or inspect any of the transferred bytes to select a path.

Its visible access order is:

| Order | Access |
|---|---|
| 1 | Read one byte at source base plus 21. |
| 2 | Write that byte at destination offset 0. |
| 3 | Read one byte at source base plus 22. |
| 4 | Write that byte at destination offset 1. |
| 5 | Read one byte at source base plus 23. |
| 6 | Write that byte at destination offset 2. |
| 7 | Read one byte at source base plus 24. |
| 8 | Write that byte at destination offset 3. |

All four transfers occur on the visible normal path. No byte value causes early termination. A zero byte is copied like any other byte; it is not a terminator.

Each write receives the value obtained by its immediately preceding read. The function does not visibly read all four source bytes before beginning to write. Consequently, a later read can observe a value written by an earlier transfer if the addresses overlap.

For valid, disjoint, stable ordinary memory, the destination receives the four source bytes in their original address order. Destination bytes outside offsets 0 through 3 are not directly accessed by this function.

### Overlap

The relevant source region begins at source base plus 21, not at the source base itself. Overlap must therefore be evaluated against that four-byte region.

If the destination begins at the first selected source byte, each transfer reads and then writes the same address. The stored values remain unchanged in stable ordinary memory, but the read and write operations still exist in the supplied behavior.

If the destination begins one byte after the first selected source byte, the first write replaces the byte needed by the second read. That newly written value can then propagate through the remaining transfers. The result is not generally the original four-byte source sequence.

If the destination begins one byte before the first selected source byte, each write targets an address below its corresponding read. In stable ordinary memory, those writes do not replace any source byte that has yet to be read, so the original four source values are transferred.

These conclusions follow from access order, not from a separate overlap-handling mechanism.

## Side effects

The direct memory effects are four single-byte destination writes, interleaved with four single-byte source reads.

For disjoint ordinary memory, the function does not directly modify the selected source bytes. With overlap, destination writes can modify that same storage. Thus, “the source remains unchanged” is not an unconditional guarantee.

The function has no visible allocation, deallocation, ownership transfer, resource acquisition, or resource release. The caller supplies the storage. Nothing in the evidence grants the function ownership of either region or establishes any lifetime change after return.

No explicit global-variable access, callback, input/output operation, or synchronization operation appears. Nevertheless, numeric addresses can identify shared storage or storage treated as global elsewhere. The absence of named global access is not a guarantee that global state is unchanged.

No atomicity or concurrency guarantee is established. The four-byte result must not be treated as a single indivisible update. If other agents modify the source between accesses, the evidence provides no snapshot guarantee.

For memory-mapped or otherwise special storage, reads and writes may have effects beyond ordinary byte storage. Such effects, access permissions, and hardware ordering are not specified by this function’s supplied representation.

## Acceptance examples

The following are conditional acceptance examples derived from static evidence. They are not runtime test results. Unless stated otherwise, they assume valid address arithmetic, stable ordinary memory, and no concurrent access.

1. **Disjoint regions preserve byte order.**  
   If the selected source bytes are hexadecimal `12`, `34`, `56`, and `78`, the destination bytes at offsets 0 through 3 become `12`, `34`, `56`, and `78`, respectively. Adjacent destination bytes are not directly written.

2. **Zero and high-bit bytes are transferred unchanged.**  
   If the selected bytes are `00`, `FF`, `80`, and `01`, those same four byte patterns appear at the destination. The initial zero does not stop the operation.

3. **Source bytes outside the selected window are not selected.**  
   Changing only source-base offsets 20 and 25 does not change the transferred values, provided those changes have no separate effect on the selected storage. The function directly reads neither offset.

4. **Exact overlap preserves stored values but still accesses storage.**  
   If the destination begins at source base plus 21, ordinary memory retains the same four byte values. Acceptance must not require the function to skip its writes.

5. **Forward overlap can propagate the first byte.**  
   Suppose the selected source bytes initially contain `11`, `22`, `33`, and `44`, and the destination begins at source base plus 22. The destination’s four bytes become `11`, `11`, `11`, and `11`. Requiring the original sequence `11`, `22`, `33`, `44` would contradict the established interleaving.

6. **Backward overlap preserves unread source values in this case.**  
   With the same initial selected source sequence, a destination beginning at source base plus 20 receives `11`, `22`, `33`, and `44`. The writes occur behind the remaining unread source addresses.

7. **Invalid storage has no specified error result.**  
   If a required address is unreadable or unwritable, acceptance cannot require a status return, a particular fault type, or an unchanged destination. None is established.
