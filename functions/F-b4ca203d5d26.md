# F-b4ca203d5d26

## Purpose

F-b4ca203d5d26 performs condition-selected memory publication followed by indirect execution and processor-specific interactions. Two routes publish four consecutive 32-bit fields. A third route publishes three consecutive 32-bit fields and reaches a separate terminal boundary.

The established contract concerns access widths, value relationships, ordering, and conditional continuation. It does not establish a public object type, successful return, allocation service, or ownership transfer.

Three evidence categories apply:

- **Established:** directly supported by the supplied static representation, conditional on execution reaching the relevant operation.
- **Inferred intent:** a possible interpretation that imposes no additional requirement.
- **documented_only:** behavior not resolved by the available evidence.

No runtime tests have been performed.

Every listed field occupies four bytes. The four-field region therefore spans 16 bytes; the three-field region spans 12 bytes. Neither layout establishes byte order, padding outside the region, or a language-level object type.

### Numeric interpretation

Destination-bearing quantities are represented as signed 32-bit values. Lookup entries are read as signed 16-bit values and widened before use as addresses.

F-0001 supplies a represented 64-bit result:

- Its numerical upper 32 bits are converted to signed 32 bits to obtain the destination.
- Its lower 32 bits supply the publication payload.
- A separate signed 16-bit conversion of the entire result supplies an auxiliary halfword.

These are numerical relationships, not a declaration of memory byte order.

Signed overflow, right shifts of negative signed values, out-of-range signed conversions, and integer-to-address interpretation remain **documented_only**. The contract does not silently replace them with unsigned modular arithmetic or low-bit truncation.

## Behavior

### Selection and entry observation

Every route includes the 32-bit read at `0x083fedb4` before route-specific effects. A route that does not otherwise use the entry capture still performs that read.

| Incoming conditions | Selected route |
|---|---|
| Overflow indicator nonzero | Direct four-field publication |
| Overflow indicator zero, with carry clear or zero set | Dependency-result four-field publication |
| Overflow indicator zero, carry set, zero clear | Three-field publication |

The overflow indicator takes precedence. No comparison establishing these incoming conditions is shown.

### Four-field publication contract

Both four-field routes publish the destination’s own signed 32-bit address value at offset 0. Offset 8 receives a separately sampled word, not the lookup halfword itself.

The route-specific values are:

| Property | Direct route | Dependency-result route |
|---|---|---|
| Destination | Second input | Converted upper half of F-0001’s result |
| Second field | Fourth input | Lower-slot value plus `0x7f` |
| Final payload | Incoming opaque payload | Lower half of F-0001’s result |
| Lookup origin | Incoming lookup base | Entry-capture-derived base |
| Data operand for F-0006 | Third input | Higher-slot value |

The address repeated in the first field may suggest a self-describing structure. That interpretation is **inferred intent**; it establishes neither object identity nor an ownership protocol.

### Lookup, sampling, and publication visibility

The destination shifted right by three determines a byte displacement. There is no additional element-size scaling.

Three accesses establish the word to publish:

| Access | Relationship |
|---|---|
| Preparatory halfword write | Address is the displacement plus `0x24`; value is the destination converted to signed 16 bits |
| Signed halfword lookup | Address is the route’s lookup origin plus the displacement |
| Word sampling | Address is the widened signed lookup result |

The preparatory write does not include the lookup origin in its address. The lookup result is used as an absolute address value, not added to the destination or lookup origin.

The observable ordering constraints are:

1. The preparatory halfword write precedes the lookup read.
2. The lookup read precedes sampling the selected 32-bit word.
3. Word sampling precedes all four publication writes.
4. Publication writes occur at offsets 0, 4, 8, and 12 in that order.
5. F-0003 follows all four publication writes.

These constraints matter when regions overlap. The preparatory write can affect the lookup result if their storage overlaps. A sampled word overlapping the publication region is obtained before publication changes that region.

No overlap check is established. Partial-overlap values additionally depend on byte order and memory behavior.

### Dependency-result preparation

F-0001 is selected using the incoming link value plus `0xd08`. Before invocation, the represented link state is replaced with `0x083fea7d`. The replacement does not select this invocation’s target.

F-0001 receives two displayed arguments: the first explicit input and the incoming auxiliary value shifted right by 24. The interpretation of that shift for negative values is unresolved.

If F-0001 continues back into this function, the entry capture is scaled by eight before F-0005 is invoked with immediate `0x10`. The route’s explicit auxiliary writes occur only after continuation through F-0005.

The auxiliary word destination is the scaled entry capture plus eight. It receives two distinct 32-bit writes in order:

- The third input.
- The destination derived from F-0001’s result.

Both writes are established effects, even though the second replaces the first under ordinary memory behavior.

A subsequent 16-bit write targets the higher-slot value plus `0x30`. Its value is the signed halfword conversion of F-0001’s entire result. This write follows both auxiliary word writes and precedes the common lookup accesses.

The lookup origin is four times the sum of the scaled entry capture and `0x6a`. The second publication field is the lower-slot value plus `0x7f`. The higher-slot value supplies the later F-0006 data operand.

These relationships use the entry capture, not a second read of the fixed cell. A dependency changing that cell does not replace the captured value in the represented computation. This is not a guarantee that dependencies preserve other memory, registers, or processor conditions.

### Three-field publication

The first input supplies both the destination and the first field. The incoming auxiliary value and incoming opaque payload supply the next two fields.

The three writes occur in increasing offset order before F-0002. Its target is selected using the incoming link value plus `0xdca`; no explicit arguments are displayed.

The represented guard for this interaction requires carry set. That condition already selects this route, and no intervening condition update is represented. Consequently, the supplied evidence does not establish a carry-clear continuation from this prefix into four-field publication.

If F-0002 returns, F-0005 is invoked with immediate `0x10`. Continuation through that interaction reaches F-0008, the invalid-instruction-data boundary.

No fourth-field write is established on this route. No particular exception, process termination, recovery action, or normal return is established beyond the boundary.

### Four-field continuation

F-0003’s target is selected using the link state applicable at that interaction plus `0xdbc`.

The direct route has no earlier external invocation or explicit link replacement. The dependency-result route has an earlier invocation, link replacement, and processor interrupt interaction. Their complete preservation rules are unknown; a concrete later target must not be derived by assuming they preserve link state.

If F-0003 returns, F-0006 uses selectors 9, 7, and 5. Its displayed data operands are, in order:

- The route-selected data operand.
- The opaque operand associated with number 11.
- The opaque operand associated with number 6.

F-0007 follows, with immediate `0x6d` and address constant `0x083feab8`. Its represented result supplies the target invoked at F-0004.

The ending is marked nonreturning. That establishes no specific nonreturn mechanism and no behavior after an unexpected return from F-0004.

## Acceptance examples

These examples are conditional static consequences, not observed executions. Unless otherwise stated, they assume usable addresses, defined arithmetic and conversions, no intervening memory modification, and continuation through earlier interactions.

### Direct publication and address calculation

With a nonzero overflow indicator, second input `0x1000`, and lookup origin `0x2000`:

- The displacement is `0x200`.
- The preparatory halfword destination is `0x224`, not `0x2224`.
- The lookup address is `0x2200`.

If the lookup returns signed value `0x3000` and the word there is `0x55667788`, publication is:

| Address | Value |
|---|---|
| `0x1000` | `0x1000` |
| `0x1004` | Fourth input |
| `0x1008` | `0x55667788` |
| `0x100c` | Incoming opaque payload |

F-0003 follows the final write. Carry and zero do not alter this route selection.

### Dependency-result preparation and conversion limits

With overflow zero and carry clear, suppose the entry capture is `0x100`, the result’s upper 32 bits are `0x1000`, its lower 32 bits are `0x5678`, the lower-slot value is `0x6000`, and the higher-slot value is `0x5000`.

After F-0005 continues:

- Address `0x808` receives the third input and then `0x1000`.
- The lookup origin is `0x21a8`.
- The destination is `0x1000`.
- The second field is `0x607f`.
- The payload is `0x5678`.
- The F-0006 data operand is `0x5000`.
- The auxiliary halfword destination is `0x5030`.

The entire 64-bit result exceeds signed 16-bit range. A halfword value of `0x5678` is therefore conditional on an environment defining that conversion as low-bit narrowing. It is not an unconditional consequence of the low halfword being positive.

### Overlap and sampling order

On the direct route, destination `0x1000` and lookup origin `0x24` make the preparatory write and lookup read coincide at `0x224`.

If the lookup observes `0x1000`, it selects the destination itself as the word source. If that word is `0x55667788` when sampled, offset 8 receives `0x55667788`, even though publication subsequently replaces the source word at offset 0.

Sampling only after the offset-0 write would violate the established ordering.

### Signed lookup addresses

Halfword patterns `0xffff`, `0x8000`, and `0x7fff` represent signed lookup values −1, −32768, and 32767. Their widened 32-bit patterns are respectively `0xffffffff`, `0xffff8000`, and `0x00007fff`.

Zero-extension of either negative entry would not satisfy the lookup relationship. Address usability remains unresolved.

### Selection and interrupted publication

With overflow zero, carry set and zero set select dependency-result publication. Carry set and zero clear instead select three-field publication.

For the latter route, first input `0x4000` produces writes at `0x4000`, `0x4004`, and `0x4008` before F-0002. If F-0002 does not return, the subsequent F-0005 interaction is not reached.

On a four-field route, a failed lookup read can occur after the preparatory write but before any publication field is written. No rollback is established.
