## Behavior

### Condition model

Two predicates describe the visible branching:

- **Selected condition:** the zero-condition input is true, or the negative-condition input differs from the overflow-condition input.
- **Matching condition:** the negative-condition input equals the overflow-condition input.

These predicates are not complements. If the zero-condition input is true and the other two inputs match, both predicates hold. That case executes both selected-condition groups and both conditional loads.

The representation repeatedly refers to the same incoming condition values. It does not explicitly show assignments to those values between operations.

This supports a static description using a fixed input tuple. It does **not** establish that real interrupt handlers or coprocessor operations preserve architectural condition flags.

### Ordered operation sequence

The following sequence specifies observable ordering in the supplied representation, subject to continuation after each event.

#### 1. Initial conditional group

When the selected condition holds:

1. Request software interrupt **0x1ddf1d** twice, in order.
2. Perform a coprocessor transfer operation with selector tuple **(6, 7, 7)**. Both operand positions receive the shared transfer operand.
3. Request software interrupt **0x1ddf1d** once.
4. Request software interrupt **0x1dcebc** once.
5. Request software interrupt **0x1ddf1d** ten more times, sequentially.

Thus, this group contains **13 requests for 0x1ddf1d**, one request for **0x1dcebc**, and one coprocessor transfer.

When the selected condition does not hold, perform one coprocessor transfer with selector tuple **(15, 5, 0)**, using the shared transfer operand followed by the paired transfer operand.

These alternatives are mutually exclusive within the initial group.

#### 2. Earlier conditional load

When the matching condition holds, perform a long coprocessor-load operation with:

- Coprocessor selector **5**.
- The load operand.
- An address expression consisting of the first address-base input plus **608**.

The load follows the entire initial group. It does not precede that group or occur within one of its interrupt runs.

When the matching condition does not hold, this load is absent.

#### 3. Intermediate interrupt group

When the selected condition holds, request software interrupt **0x1ddf1d** four times, sequentially.

Otherwise, this group has no represented operation.

#### 4. Independent nonzero interrupt

When the zero-condition input is false, request software interrupt **0x1edf1d** once.

This condition is independent of whether the negative-condition and overflow-condition inputs match. Consequently, this interrupt can occur either after the alternate transfer and earlier load, or after the selected initial group without that load.

When the zero-condition input is true, this interrupt is absent.

#### 5. Later conditional group

When the selected condition holds:

1. Request software interrupt **0x1cdf1c** seven times, sequentially.
2. Perform a coprocessor transfer with selector tuple **(15, 7, 0)**. Both operand positions receive the shared transfer operand.
3. Request software interrupt **0x1cdefc** once.
4. Request software interrupt **0x1dcebb** once.
5. Request software interrupt **0x1ddf1d** ten times, sequentially.

When the selected condition does not hold, perform one coprocessor transfer with selector tuple **(15, 5, 0)**, using the alternate transfer operand followed by the paired transfer operand.

This alternate transfer differs from the initial alternate transfer in its first operand. The two operations must not be treated as identical merely because their selector tuples match.

#### 6. Later conditional load

When the matching condition holds, perform another long coprocessor-load operation with:

- Coprocessor selector **5**.
- The load operand.
- An address expression consisting of the second address-base input plus **604**.

This occurs after the later conditional group and before the final interrupt group.

#### 7. Final interrupt group

When the selected condition holds, request software interrupt **0x1cdf1c** four times, sequentially.

Otherwise, this group has no represented operation.
