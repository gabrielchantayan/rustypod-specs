# F-b782a0ff4f07

## Purpose

F-b782a0ff4f07 returns a 32-bit result through one of two paths selected by an indirect operation on the supplied object:

- A nonzero selector result causes a call to F-53c1191c069e, followed by selection between an object-associated value and a global fallback.
- A zero selector result causes an ordered traversal of linked objects. Each visited object receives a shared argument, an object-associated context value, and access to a writable result slot. Traversal stops at the first nonzero callback result or at the end of the chain. The function returns the result slot, not the callback’s return value.

These are established control-flow behaviors. Interpreting the first path as initialization, or the second as a search or query, would be inferred intent rather than an established semantic contract.

## Interface

### Input

The function accepts one object address.

The supplied representation uses 32-bit integer words and address-bearing fields. The layouts below describe that representation; they do not establish portability to other pointer widths or object layouts.

The input object must support these accesses when their respective paths are taken:

| Byte offset | Width | Role |
|---|---:|---|
| `0x00` | 32 bits | Address of a dispatch table |
| `0x38` | 32 bits | Address of the first linked object on the traversal path |
| `0x44` | 32 bits | Context value passed unchanged to traversal callbacks |
| `0x110` | 32 bits | Object-associated result inspected after F-53c1191c069e |

The dispatch table reached through the input object contains a callable address at byte offset `0x120`. That indirect target receives the input object address and returns a value tested against zero.

Each linked object used during traversal must support:

| Byte offset | Width | Role |
|---|---:|---|
| `0x00` | 32 bits | Address of that object’s dispatch table |
| `0x14` | 32 bits | Address of the next linked object |

A linked object’s dispatch table contains a callable address at byte offset `0x64`, or 100 decimal. That target receives four arguments:

1. The current linked object address.
2. A captured 32-bit global value.
3. The captured 32-bit context value from the input object.
4. The address of a writable 32-bit result slot local to this invocation.

The two global storage locations are designated **G-01** and **G-02** in this contract. These are specification-local references, not source symbols:

- G-01 supplies the shared argument captured after the selector call.
- G-02 supplies the fallback return value on the nonzero-selector path.

### Output

The function returns a 32-bit integer value.

On the nonzero-selector path, the return is either the object-associated result at offset `0x110` or G-02.

On the traversal path, the return is the current contents of the writable result slot, initially zero.

No output is identified as a length, Boolean, status enumeration, pointer, or ownership transfer. Although some returned bit patterns might be used that way elsewhere, this function’s visible behavior does not establish such an interpretation.

### Preconditions

For normal completion:

- The input object and its initial dispatch table must be readable.
- The selector target must be callable with the expected calling convention.
- Any path-specific object fields and global locations that are read must be accessible.
- Every visited linked object must provide readable dispatch information.
- A next-object field must be readable whenever its callback returns zero.
- Called functions must return normally for execution to continue as described.

There is no explicit null check on the input object. A null initial linked-object address, by contrast, is a supported empty-chain condition.

## Behavior

### Common prefix

The function first obtains the input object’s dispatch table and calls the indirect target at table offset `0x120`. This dependency is designated F-000000000001 below.

After that call returns, the function reads G-01 into a captured 32-bit value. This read precedes selection of either visible branch. Consequently:

- Changes to G-01 made during F-000000000001 can affect the captured value.
- The G-01 read also occurs when the selector result is nonzero and the captured value is not subsequently used as a callback argument.
- The selector can change the object or other accessible state before either branch performs its own reads.

Only whether the selector result equals zero matters. Positive and negative nonzero values select the same branch.

### Nonzero-selector path

When F-000000000001 returns nonzero:

1. F-53c1191c069e is called with the original input object address.
2. After that call returns, the function obtains the object-associated result from byte offset `0x110`.
3. A nonzero object-associated result is returned.
4. A zero object-associated result causes G-02 to be read and returned instead.

No return value from F-53c1191c069e participates in the visible selection.

The object-associated result is inspected after F-53c1191c069e, so that dependency’s writes can affect the result. The global fallback is likewise read after the dependency returns and only when the object-associated result is zero. It is not a fallback captured at entry.

G-02 is returned without an additional nonzero requirement. If both the object-associated result and G-02 are zero, this path returns zero.

The linked-object head and traversal context are not read by this path’s visible operations. Dependencies may independently access them; their bodies are not available here.

### Zero-selector path

When F-000000000001 returns zero, the function:

1. Reads the initial linked-object address from input-object offset `0x38`.
2. Reads the context value from input-object offset `0x44`.
3. Initializes a local 32-bit result slot to zero.
4. Traverses the chain starting at the captured initial address.

The head and context are therefore obtained after the selector call. Changes made by the selector can affect both.

For each non-null current object, its dispatch target at table offset `0x64` is called. This indirect dependency is designated F-000000000002. It receives the current object, the captured G-01 value, the captured context, and the address of the result slot.

After a callback:

- A nonzero callback return immediately ends traversal.
- A zero callback return causes the next-object address to be read from the current object at offset `0x14`.
- Traversal continues if that next address is non-null.
- A null current address ends traversal without another callback.

The function then returns the result slot.

The result slot is initialized only once. It is not cleared between callbacks. A callback’s write remains available to later callbacks and to the final return unless another callback changes it.

The callback return and the result slot have separate roles:

- The callback return controls continuation.
- The result slot controls the function’s returned value.

A nonzero callback return does not imply a nonzero function result. Similarly, a callback may write a nonzero result but return zero, allowing traversal to continue.

### Capture and mutation semantics

G-01 and the context field are captured once for traversal. Later changes to their source storage do not cause this function to refresh those arguments.

The next-object address is different: it is read after a zero-returning callback. A callback that changes its own object’s next field can therefore alter the subsequent traversal.

The initial head is not reread. Changing the input object’s head field during traversal does not itself restart or redirect the current chain walk.

When a callback returns nonzero, this function does not read that object’s next field. This matters if the callback invalidates or otherwise makes that field inaccessible.

### Arithmetic and termination

The visible function performs fixed-offset address accesses, zero comparisons, and linked traversal. It contains no result arithmetic, length calculation, or numeric accumulation.

There is no iteration count, cycle detection, or maximum traversal bound. A cycle whose callbacks continue returning zero can prevent normal completion indefinitely. A callback returning nonzero can terminate traversal even within a cyclic structure.

## Side effects

The only direct data write established by the visible function is initialization of its local result slot to zero. The function also exposes the address of that slot to traversal callbacks, enabling them to change the eventual return value.

No direct allocation, deallocation, ownership transfer, or persistent object-field update is visible in this function. That observation does not constrain dependency behavior.

In particular, the available evidence does not establish that any called function:

- Preserves global storage.
- Preserves object fields or dispatch tables.
- Leaves linked objects allocated.
- Avoids retaining supplied addresses.
- Avoids callbacks, reentrancy, I/O, or other external effects.

The local result address supports synchronous access while this invocation is active. Retaining it does not extend the storage lifetime. Use after the invocation returns is not supported by the visible lifetime.

On a zero callback return, the current object must remain valid for the subsequent read of its next field. On a nonzero return, this function performs no further explicit field access to that current linked object.

No synchronization or concurrent-mutation policy is visible. Behavior under concurrent updates is documented_only.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid required memory, normally returning dependencies, and no additional mutations beyond those stated.

1. **Nonzero selector with an object result.**  
   The selector returns `1`. After F-53c1191c069e returns, offset `0x110` contains `27`. The function returns `27`; it does not obtain the fallback from G-02.

2. **Nonzero selector with a fallback.**  
   The selector returns `-1`. After F-53c1191c069e returns, offset `0x110` is zero and G-02 contains `42`. The function returns `42`. A negative selector result does not select traversal.

3. **Dependency changes the fallback.**  
   The object-associated result is zero. F-53c1191c069e changes G-02 from `4` to `9`. With no later change, the function returns `9`, demonstrating that the fallback is read after the dependency call.

4. **Empty chain.**  
   The selector returns zero and the captured head is null. No traversal callback runs. The function returns zero.

5. **Stop without writing a result.**  
   The first callback leaves the result slot unchanged and returns a nonzero value. The function returns zero. It does not read that node’s next field.

6. **Continue after writing a result.**  
   The first callback writes `11` and returns zero. The second callback leaves the slot unchanged and returns nonzero. The function returns `11`.

7. **Exhaustion after a write.**  
   A callback writes `19`, returns zero, and has a null next field when that field is subsequently read. The function returns `19`; no callback needs to report nonzero for a nonzero final result.

8. **A later write replaces an earlier result.**  
   One callback writes `8` and continues. A later callback writes zero and stops. The function returns zero, not `8` and not the later callback’s nonzero return.

9. **Traversal follows an updated link.**  
   A callback changes its current object’s next field and returns zero. The function reads the changed field and follows that address.

10. **Captured arguments remain stable.**  
    After the function captures G-01 and the context, a callback changes their source storage. Subsequent callbacks still receive the originally captured values.

11. **Nonterminating cycle.**  
    The reachable links form a cycle and every callback returns zero. No bounded-completion guarantee applies.
