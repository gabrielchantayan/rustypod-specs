# F-9b2e29b4a81c

## Purpose

F-9b2e29b4a81c selects a 32-bit value, stores it in one of two temporary slots, passes that slot’s address to a consumer dependency, and then passes the same address to a cleanup dependency if the consumer returns normally.

Selection depends on the low 32 bits of an initial dependency result:

- A zero low half selects a value obtained by a second read of shared storage.
- A nonzero low half enters a path that may construct a replacement value, optionally invoke an external operation, and otherwise use an earlier capture of the shared value.

**Established static behavior:** the two shared-storage reads on the zero-low-half path are distinct operations. The first occurs unconditionally after the initial probe; the second supplies the value assigned on that branch. Their observed values are not required by this contract to agree.

**Inferred intent:** the selected values may represent resources, and the final dependency may perform resource cleanup. Neither interpretation establishes ownership, allocation, release, or validity guarantees.

## Behavior

### Initial probe and unconditional shared read

The function initializes both temporary slots and calls F-14a841015476 with the second argument.

The initial result is represented as 64 bits:

- Bits 0 through 31 determine whether the zero or nonzero branch is taken.
- Bits 32 through 63 are used as an argument to a second probe only on the nonzero branch.

After the initial probe returns, the function unconditionally reads a 32-bit value from shared storage. Call this the **initial shared capture**.

This read occurs on both branches. Its value is retained as the fallback for the nonzero-low-half branch. It is not the value assigned to the second slot on the zero-low-half branch.

Any change the initial probe makes to the shared location can affect this first read. Preservation of shared storage by that dependency is not assumed.

### Zero-low-half branch

When the initial result’s low 32 bits are zero, the function reads the same shared 32-bit location again. Call this the **branch shared read**.

The second slot is overwritten with the value obtained by this second read. The earlier initial shared capture does not supply this assignment.

The remaining sequence is:

1. Call F-f4fd698ba468 with the first argument and the address of the second slot.
2. If the consumer returns normally, call F-8a5aadac202f with the address of the second slot.
3. Return normally if cleanup returns normally.

There is no intervening dependency call between the two shared reads, but that fact does not establish equal values. Concurrency, synchronization, and the shared location’s access semantics remain unspecified. Neither read may be omitted from the source-facing description merely because the first result is unused on this branch.

This branch does not directly perform the offset-8 read, second probe, exceptional-range call, construction call, or conditional external operation. The first slot is not passed to the consumer or cleanup.

The fourth argument’s initial value is replaced without a visible cleanup call for that initial value.

### Nonzero-low-half branch

When the initial result’s low 32 bits are nonzero, there is no second direct read of the shared location.

The function first reads and saves the 32-bit field at byte offset 8 from the second argument’s address. It then calls F-14a841015476 again with two arguments:

1. The original second argument.
2. The high 32 bits of the initial probe result, represented as a 32-bit integer.

The second result is used as an unsigned 32-bit quantity.

The supplied representation uses F-14a841015476 with different argument counts and result-width usage. This establishes the represented interactions, not a definitive unified callable prototype.

### Exceptional unsigned range

The second probe result is compared, unsigned, with `0xFFFFFFF1`.

For results strictly greater than that boundary—`0xFFFFFFF2` through `0xFFFFFFFF`, inclusive—the function:

- Replaces the final argument reserved for construction with the 32-bit representation of −15, `0xFFFFFFF1`.
- Calls F-5829ec5988c0 with the value 8 and an address of static data.

For all other results, the final construction argument remains the original second argument.

Equality with `0xFFFFFFF1` does not invoke F-5829ec5988c0. The exceptional comparison does not clamp or otherwise replace the second probe result itself.

There is no visible early return after F-5829ec5988c0. If it returns normally, execution continues. Whether that dependency ordinarily reports, throws, terminates, or returns is unresolved.

### Optional construction and selection

If the second probe result is nonzero, F-ee3e41a62db4 is called with five arguments, in this order:

1. The address of the first slot.
2. Zero.
3. The unsigned 32-bit second probe result.
4. That same unsigned 32-bit result again.
5. The original second argument, or `0xFFFFFFF1` if selected by the exceptional-range check.

No explicit local overwrite of the first slot occurs between its initialization from the third argument and this construction call. The dependency receives its address and may inspect or alter it according to an unknown contract.

The construction dependency’s 32-bit return becomes the selected value.

If the second probe result is zero, construction is skipped. The selected value is instead the initial shared capture obtained immediately after the first probe. Changes to shared storage during the second probe do not cause a direct reread by this function.

## Acceptance examples

The following are conditional static acceptance cases, not executed tests.

1. **Zero low half with different shared observations.**  
   Suppose the initial result’s low half is zero, the initial shared capture observes `0x11`, and the branch shared read observes `0x22`. The second slot receives `0x22`. The consumer and then cleanup receive its address. This case does not assert that any particular concurrency model permits those observations.

2. **Shared value changed by the initial probe.**  
   A change made by the initial probe can affect the subsequent unconditional capture. On the zero-low-half path, the selected value still comes from the later branch shared read, not necessarily that capture. On the nonzero-low-half path with a zero second result, the initial capture supplies the fallback.

3. **Zero low half with nonzero high half.**  
   The high half does not force the nonzero branch. Two shared reads occur, and no direct offset-8 read or second probe occurs.

4. **Nonzero low half, zero second result.**  
   With an initial shared capture of `0x31`, construction is skipped and the first slot receives `0x31`. A change to shared storage during the second probe does not replace this fallback. A nonzero saved offset-8 field still causes F-U1 to run.

5. **Ordinary construction.**  
   A second result of 12 causes construction to receive 12 twice and the original second argument as its final argument. Its return is written into the first slot. F-U1 runs only if the saved field is nonzero.

6. **Exact exceptional boundary.**  
   A second result of `0xFFFFFFF1` does not invoke F-5829ec5988c0. Construction runs with the original second argument as its final argument.

7. **First exceptional result.**  
   A second result of `0xFFFFFFF2` invokes F-5829ec5988c0. If it returns normally, construction receives `0xFFFFFFF2` twice and `0xFFFFFFF1` as its final argument.

8. **Construction mutates its slot.**  
   If construction writes one value into the first slot but returns another, the subsequent explicit write places the returned value in the slot.

9. **Saved field changes later.**  
   A later dependency’s change to the offset-8 source field does not change the saved condition or argument supplied to F-U1.

10. **Consumer replacement or zero construction return.**  
    A consumer-written replacement is present at the slot address later passed to cleanup. Separately, a zero construction return is not rejected locally: it is stored and forwarded under the ordinary branch conditions.
