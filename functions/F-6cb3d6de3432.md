# F-6cb3d6de3432

## Purpose

F-6cb3d6de3432 coordinates processing between a source object and a destination selected through a dependency. It requests two initial transfers, reconciles the objects, and, on success, propagates metadata, invokes source-directed operations, optionally processes entries, and performs final processing.

The destination selection is **live state**, not a destination object fixed at acquisition return. Acquisition receives addresses of two local 32-bit slots: one identifies the destination, and the other holds an associated value. No supplied dependency contract prevents those addresses from being retained and used to modify the slots during later calls.

Consequently, successive destination-directed operations can concern different objects. In contrast, the backing-data addresses captured for the two initial transfer requests remain the addresses used by those requests.

The apparent intent is to construct or update a destination representation. Transfer semantics, object ownership, and the meaning of terminal processing are not established. Source-directed calls also prevent treating this function as an established read-only operation on the source.

## Interface

| Position | Established use |

| Second | Opaque 32-bit value, unused by this function. |
| Third | Opaque 32-bit value used to initialize the associated-value slot. |

Zero selects continuation at checked dependency calls. A nonzero status is returned without translation on the corresponding failure path. The terminal dependency’s result does not replace the saved status.

Acquisition receives addresses of local slots, not addresses of the caller’s original argument storage. Slot changes therefore do not directly update those original arguments. They can nevertheless affect later execution inside this invocation.

### Escaped local slots

The two slots have distinct roles:

- **Destination-selection slot:** later destination-object expressions read its current value. These reads occur when forming dependency arguments, accessing destination fields, and checking the entry-loop bound.
- **Associated-value slot:** read when forming the arguments to F-cfb711b78946. That value need not equal either the original third argument or the value present immediately after acquisition.

Passing the slot addresses to F-66c60373345b makes later indirect mutation possible unless excluded by an external contract. None is supplied. This function does not visibly restore, freeze, or validate either slot after acquisition.

A value already loaded from a slot, or an address already computed from it for a particular operation, is distinct from a later slot read. Slot mutation does not retroactively redirect an already formed argument.

## Behavior

### Acquisition

The function first captures the source’s context address from `+0x40`. It initializes the associated-value slot from the third argument and the destination-selection slot from the fourth argument.

F-66c60373345b receives:

1. The captured context address.
2. The address of the destination-selection slot.
3. The address of the associated-value slot.
4. The source’s 32-bit field at `+0x4c`.

If this dependency returns nonzero, the function returns that status immediately. No later transfer, reconciliation, metadata operation, source-directed operation, final processing, or terminal call occurs.

On zero, processing continues using the slots as live local state. Success does not establish that either slot changed, that a selected address is valid, or that ownership transferred.

The captured context address is retained independently of subsequent changes to source `+0x40`.

### Initial transfer requests

Following successful acquisition, the function captures:

- The source backing-data address from `+0x44`.
- The unsigned 16-bit endpoint from captured context `+0x1e`.
- A selected source-region address formed by adding source `+0x08`, read as an unsigned byte, to that backing-data address.

It reads the selected region’s bytes at `+5` and `+6`. The former supplies the high byte and the latter the low byte of an unsigned 16-bit split offset. For example, `0x12` and `0x34` yield `0x1234`. This establishes byte significance, not a required order between those two reads.

It then reads the backing-data address at `+0x44` of the destination selected at that point. That backing-data address is retained for **both** initial transfer calls.

F-external-01 receives two requests, in order:

| Request | Destination address | Source address | Length |
|---|---|---|---|
| First | Captured destination backing address | Selected source-region address | Source `+0x0e` plus twice source `+0x14`, minus source `+0x08` |
| Second | Captured destination backing address plus split offset | Captured source backing address plus split offset | Captured endpoint minus split offset |

The first length uses unsigned 16-bit observations of the two length fields and an unsigned 8-bit observation of the region offset. The offset is read again for this expression; it is not specified to reuse the observation that formed the selected-region address.

Both length expressions use 32-bit unsigned arithmetic. The largest first-length sum before subtraction is 196,605. Subtraction is not clamped: mathematical underflow produces a large unsigned length. The second length likewise wraps modulo $2^{32}$ when the split offset exceeds the endpoint.

Neither transfer result is checked.

A dependency changing a backing-data field or the destination-selection slot during the first transfer does not redirect the second transfer. Its two backing-data bases, split offset, and endpoint have already been captured. Such a slot change can, however, change the destination supplied to reconciliation.

These are address-and-length requests. Actual copying, overlap handling, and error behavior are unknown.

### Reconciliation

After both transfer calls, F-8338e532dca9 receives the **current** destination-selection value and the source-object address.

If reconciliation returns nonzero, the function skips metadata propagation, source-directed operations, context processing, entry processing, and final processing. It invokes F-6cc778185718 with the destination-selection value read for that terminal call, then returns the reconciliation status.

Reconciliation can itself change the escaped destination slot through effects not excluded by the supplied contracts. Its destination argument and the terminal call’s destination argument therefore need not identify the same object.

No rollback of the initial transfers is visible.

### Metadata propagation

On zero reconciliation status, F-external-02 receives:

- Destination: current destination selection plus `0x18`.
- Source: source-object address plus `0x18`.
- Length: source `+0x02`, read as an unsigned byte, multiplied by eight.

The length ranges from zero through 2,040 bytes. The call occurs even for zero length. Its result is ignored.

After the call returns, the function reads source `+0x02` again. It writes that byte to `+0x02` of the destination selected for the write. If the captured byte is nonzero, it also writes a 16-bit zero to `+0x12` using the destination-selection expression for that write. If zero, it makes no direct write to `+0x12`.

Two distinctions are required:

- The count determining transfer length can differ from the count subsequently stored.
- The destination receiving the metadata transfer can differ from the destination receiving the later direct writes, because F-external-02 can cause an escaped-slot change.

The source count used for the byte write also controls the conditional clear; the condition does not reread the source count. No dependency call separates the two direct writes. The representation nevertheless contains separate destination-selection expressions, not a destination snapshot retained across this entire stage.

### Source-directed operations

The function next reads backing-data `+0x44` through the destination-selection value current for that expression. It reads the first byte at that backing-data address and clears bit `0x08` in the argument value, preserving the other seven bits.

F-f6da3c4a0ea5 receives the **source object** and that masked value. The visible function does not directly store the masked byte in either backing store.

After that call, the function freshly reads source backing-data `+0x44` and the unsigned region-offset byte at `+0x08`. F-cfb711b78946 receives:

1. Their sum, plus eight.
2. The associated-value slot’s value when this call’s arguments are evaluated.

The second argument is not necessarily the value left at acquisition return. A preceding dependency can have modified the escaped slot.

Both source-directed dependency results are ignored.

### Optional context and entry processing

The function reads captured context `+0x16`. A zero byte skips context and entry processing and proceeds to final processing.

A nonzero byte causes F-97f36d1a1364 to receive:

1. The captured context address.
2. Field `+0x4c` from the destination selected for this argument expression.
3. The value five.
4. The source’s current field at `+0x4c`.

A nonzero result skips entries and final processing. The function invokes F-6cc778185718 using the destination selection current for that call and returns the context-processing status.

A zero result starts entry processing at index zero. Before each iteration, the function freshly reads unsigned 16-bit `+0x14` through the current destination selection. It proceeds only while the index is less than that bound.

For each admitted index, F-22ff747b8f8d receives the destination selection evaluated for its call and the index. A nonzero return causes an immediate return from F-6cb3d6de3432, **without final processing or F-6cc778185718**.

After zero, the index increases by one. There is no index reset when the destination slot changes. A dependency can change the next bound either by modifying the selected object or by selecting a different object. Later entries can therefore concern a different destination at a continuing index.

The 16-bit bound permits admitted indices from zero through 65,534. Even a changing bound cannot admit index 65,535; index wrap is not required for loop termination.

### Final processing and terminal operation

If reconciliation and all enabled context and entry processing succeed, F-04e88acdee4c receives the destination-selection value current for its call.

After it returns, F-6cc778185718 receives a newly evaluated destination-selection value. These calls need not target the same object: final processing may cause an escaped-slot mutation.

The function returns the saved F-04e88acdee4c status, whether zero or nonzero. The terminal call does not replace it.

The terminal dependency is absent on acquisition failure and entry-processing failure. It occurs on reconciliation failure, context-processing failure, and every normally returning final-processing path.

## Side effects

The direct nonlocal writes visible in this function are:

- One byte at selected destination `+0x02`.
- Conditionally, a 16-bit zero at selected destination `+0x12`.

Acquisition is also given writable access to the two local slots. The lifetime and permitted use of any retained slot addresses are not established by a dependency contract.

Every dependency may have additional effects. No supplied contract establishes preservation of global state, source fields, destination fields, backing storage, or escaped slots.

The function visibly performs no allocation, deallocation, rollback, synchronization, or exception handling. F-6cc778185718 is not established as a deallocator, and acquisition is not established as an ownership transfer.

Failure is not transactional. Prior transfer requests, metadata writes, and source-directed operations remain observable unless a dependency independently reverses them.

Normal completion requires valid addresses for the direct accesses and whatever validity the dependencies require for their arguments. The function does not enforce capacities, non-overlap, destination consistency, or a split offset bounded by the endpoint.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, memory is valid, dependencies return normally, and relevant state remains unchanged.

1. **Acquisition rejection.** If F-66c60373345b returns 7, the function returns 7 without invoking any later dependency.

2. **Ordinary lengths.** With source region offset 8, source length fields 40 and 3, split offset 32, and endpoint 100, the initial lengths are 38 and 68. The second request starts 32 bytes into each captured backing-data base.

3. **Unsigned underflow.** A split offset of 101 and endpoint of 100 produce second length 4,294,967,295. No rejection or clamping occurs in this function.

4. **Selection changes during the first transfer.** Suppose the destination backing address is captured from object A, then the first transfer causes the destination slot to select B. The second transfer still uses A’s captured backing address. Reconciliation receives B if the slot remains B until its arguments are evaluated.

5. **Reconciliation changes selection before failure cleanup.** Suppose reconciliation receives A, changes the escaped slot to B, and returns −3. Metadata and later success-path processing are skipped. The terminal operation receives B, and the function returns −3.

6. **Metadata count and destination both change.** Suppose the metadata call is formed for A with source count two, requesting 16 bytes. If that call changes the source count to zero and selects B, the subsequent byte write stores zero at B `+0x02`. No direct clear of `+0x12` occurs.

7. **Associated value changes after acquisition.** Suppose acquisition leaves associated value 10, but a later dependency changes that slot to 20 before F-cfb711b78946’s arguments are evaluated. That call receives 20, not 10.

8. **Masked byte.** If the selected destination’s freshly read backing byte is `0xff`, F-f6da3c4a0ea5 receives the source and `0xf7`. This alone establishes no backing-byte write.

9. **Entry failure.** If context processing succeeds and the admitted entry at index zero returns 12, the function returns 12 without final processing or the terminal operation.

10. **Changing destinations does not reset the index.** If entry zero on A succeeds and selects B, the next comparison uses B’s count. With B’s count equal to two, entry one is processed on B; entry zero is not repeated on B.

11. **Final and terminal targets differ.** If final processing receives A, changes the slot to B, and returns 9, the terminal operation receives B and the function returns 9.

The following remain **documented_only**:

- Whether acquisition or other dependencies retain slot addresses, and whether later calls actually mutate those slots.
- Any restrictions on slot retention, indirect access, or use after this invocation returns.
- Ordering among independent reads within a single argument expression where the representation does not establish it.
- Transfer semantics, overlap rules, zero-length pointer requirements, and dependency error behavior.
- Capacities, aliasing permissions, ownership, and lifecycle obligations.
- Whether destination changes across stages are intended, forbidden by an unavailable contract, or merely not excluded.
- Meanings of the counts, endpoint, split offset, associated value, and operation value five.
- Whether omission of the terminal operation after entry failure is intentional.
- Behavior on invalid addresses, address-arithmetic overflow, dependency faults, nonreturn, or unsynchronized external mutation.

Escaped-slot mutation is an unresolved dependency-contract issue, not an assertion that such mutation occurs. Neither stability nor mutation is assumed unconditionally.
