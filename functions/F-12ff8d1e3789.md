# F-12ff8d1e3789

## Purpose

F-12ff8d1e3789 interprets a descriptor containing a payload address and a length-like field, obtains a range limit from a service object, and conditionally dispatches an operation using a decoded starting position and an additional numeric operand.

Its observable outcomes are:

- A normal 32-bit return value of **4** for an initially rejected descriptor or certain failed operand/range checks.
- A normal 32-bit return value of **0** when the operand and upper-bound checks pass but the computed range is not strictly increasing.
- A path through a dependency represented as non-returning after processing a strictly increasing, accepted range.
- A separate exceptional path through another dependency represented as non-returning for certain descriptor-field values.

The supplied representation establishes the branching and data flow. It does not establish the application-level meaning of the descriptor, the numeric operand, the service, or the status values.

## Interface

### Inputs

The function receives two arguments:

1. **Context value:** an opaque 32-bit value. The function does not interpret it locally. It is forwarded to F-99e0d644698f only on the dispatch path.
2. **Descriptor address:** an address represented by a 32-bit integer in the supplied representation.

The descriptor fields used are:

| Offset from descriptor | Width | Interpretation |
|---|---:|---|
| +8 | 32 bits | Address of a payload |
| +12 | 16 bits, unsigned | Length-like selector controlling admission and operand-byte reads |

The function reads the 16-bit selector first, then the payload address. Both reads occur before the initial rejection decision. Thus, even an immediately rejected descriptor must support both reads.

The payload is used as follows:

| Offset from payload | Use |
|---|---|
| +0 | Address passed to the first invocation of F-c25a2fcc75b5 |
| +4 | Address passed to the second invocation of F-c25a2fcc75b5 |
| +8 through +11 | Individually read bytes used to form a numeric operand, depending on the selector |

The access width, encoding, and validation performed by F-c25a2fcc75b5 are unknown. Passing addresses four bytes apart does not itself prove that each invocation reads exactly four bytes.

### Output and termination

The normal output is a 32-bit value, either 0 or 4 on the visible returning paths.

Two dependencies are represented as non-returning:

- F-a817d8d58c10 on the exceptional selector path.
- F-feee9156a257 after an accepted strictly increasing range has been processed.

Their actual termination mechanisms are unknown. They must not be described specifically as process termination, exception throwing, or ordinary resource release without additional evidence.

### Preconditions

The function performs no visible null-pointer, accessibility, alignment, or payload-size validation.

Defined operation therefore requires:

- Readable descriptor fields at the offsets above.
- Payload accessibility sufficient for both decoding calls and all subsequent selected byte reads.
- A valid service object and callable virtual entries when service acquisition is reached.
- Valid returned object representations for any non-null object used on the dispatch path.

The selector is not used to verify the actual allocation size of the payload.

## Behavior

### 1. Capture descriptor fields and apply the initial gate

The function captures the unsigned 16-bit selector and the payload address, in that order.

The initial gate compares 3 with the selector minus 9. Under the ordinary 32-bit integer promotions expressed by the supplied types, the subtraction is signed: every unsigned 16-bit selector value is representable as a signed 32-bit integer.

Consequently:

- Selectors **13 through 65535** return 4 immediately after the two descriptor reads.
- Selectors **0 through 12** continue.

This is not a conventional admission test limited to selectors 9 through 12. Values below 9 pass this first gate and subsequently reach the exceptional selector path.

The selector and payload address are captured values. Later dependency calls do not cause these descriptor fields to be re-read.

### 2. Decode the starting position and extent

For a selector that passes the gate, the function performs these operations in order:

1. Calls F-c25a2fcc75b5 with the payload address.
2. Calls F-c25a2fcc75b5 with the payload address plus 4.
3. Calls F-b7af80e829ec to obtain a service object.
4. Invokes the service object's virtual operation at table offset +236, passing the service object.

The first decoding result is treated as an unsigned 32-bit starting position.

The second decoding result is held as a signed 32-bit value. Its all-ones value, interpreted as −1, is a sentinel.

The service operation's result is treated as an unsigned 32-bit limit. The function retains this result for the later comparisons; it does not query the limit again.

For the −1 sentinel:

- If the starting position is less than the limit, the effective extent becomes the unsigned difference between limit and start.
- Otherwise, the effective extent becomes zero.

A non-sentinel result supplies its 32-bit pattern directly to the later arithmetic. The function does not visibly reject other negative signed values.

The later sum uses unsigned 32-bit arithmetic. The contract therefore treats the effective extent as a 32-bit pattern at that point, not as an independently validated nonnegative mathematical integer.

### 3. Decode the additional operand

The selector then controls individual byte reads from the captured payload address.

For reachable selectors, the operand has the following layout and read order:

| Selector | Byte-read order | Resulting low 32-bit word |
|---:|---|---|
| 9 | +8 | Byte at +8 |
| 10 | +9, then +8 | Byte at +8 plus byte at +9 in bits 8–15 |
| 11 | +10, then +9, then +8 | Bytes +8 through +10 in ascending significance |
| 12 | +11, then +10, then +9, then +8 | Bytes +8 through +11 in ascending significance |

All individual bytes are unsigned and zero-extended before shifting. The resulting value is little-endian in significance, although the observable reads occur from the highest selected address down to +8.

A separate high 32-bit word remains zero for every selector admitted to these normal decoding cases.

Selectors **0 through 8** instead call F-a817d8d58c10. This happens after both decoding calls, service acquisition, the limit query, and any sentinel adjustment. No additional-operand byte is read on that path.

The supplied representation contains operand-extension cases for larger selectors, but the initial gate excludes all of them. They do not establish reachable support for wider operands.

### 4. Validate the operand and computed range

After operand construction, the function checks the following conditions in order:

1. The combined operand is nonzero. Because the high word is zero on reachable normal cases, the low word must be nonzero.
2. The top four bits of the low word are clear.
3. The unsigned 32-bit sum of starting position and effective extent is no greater than the captured limit.

If any of these checks fails, the function returns 4.

For selector 12, the top-four-bit restriction means the byte at payload offset +11 must be at most 15. For selectors 9 through 11, that restriction is automatically satisfied.

The accepted operand range on the reachable decoding paths is therefore **1 through 268,435,455**, with narrower maxima imposed by shorter selectors.

The end position is computed modulo \(2^{32}\). There is no separate checked-addition operation.

Once all three checks pass, the prospective return status becomes 0. The function then requires the starting position to be strictly less than the computed end position:

- If this comparison fails, it returns 0 without requesting a range object.
- If it succeeds, it continues to the dispatch path.

This distinction matters for both zero extents and wrapping arithmetic. A wrapped end position can pass the upper-bound check but fail the strict-increase check, producing 0 rather than 4.

The visible checks do not compare the operand's magnitude with the extent or the service limit.

### 5. Obtain an object and conditionally dispatch

For an accepted strictly increasing range:

1. The function invokes the retained service object's virtual operation at table offset +244.
2. It passes the service object and the starting position. The extent, computed end position, and decoded operand are not arguments to this operation.
3. If the returned object is null, it skips the object's virtual operation and skips F-99e0d644698f.
4. If the object is non-null, it invokes that object's virtual operation at table offset +8.
5. If that operation returns zero, it skips F-99e0d644698f.
6. If that operation returns nonzero, it calls F-99e0d644698f with, in order:
   - The original opaque context value.
   - The returned object.
   - The fixed value 67.
   - The starting position.
   - The operand's low 32-bit word.
   - The operand's high 32-bit word, which is zero on reachable paths.

The supplied representation shows no explicit argument for the object's +8 virtual operation. Its calling convention or implicit object context is not established.

After these steps, provided the intervening calls return, the function calls F-feee9156a257 with the returned object. This occurs even when the object is null or its +8 operation returned zero.

F-feee9156a257 is represented as non-returning, so this path has no established normal return value.

## Side effects

The visible function body contains no direct stores to the descriptor, payload, or service objects.

Its direct observable reads include:

- The two descriptor-field reads.
- Virtual-table and virtual-entry reads needed for the calls.
- Selected individual payload-byte reads.

All dependency calls may have additional effects not established here.

In particular, the function does not establish that the decoding calls, service operations, object operation, or dispatch helper preserve payload contents or global state. Operand bytes are read only after several such calls, so they may reflect intervening changes rather than the payload state at function entry.

Likewise, a later virtual call resolves through the object's then-current table representation; the evidence does not justify assuming earlier calls preserve that representation.

Ownership is **documented_only**:

- The service object's ownership and lifetime are unknown.
- The returned range object's ownership and lifetime are unknown.
- Passing an object to F-99e0d644698f does not prove transfer of ownership.
- Passing an object to F-feee9156a257 does not prove destruction or release.
- The null argument permitted on the latter call must not be interpreted as evidence of a general null-safe release API.

## Acceptance examples

These are conditional behavioral examples derived from the supplied representation, not runtime test results. They assume valid memory and returning dependencies except where non-returning behavior is stated.

1. **Early rejection:** With selector 13, the function reads the selector and payload address, then returns 4. It does not call either decoder or acquire the service.

2. **Below-range selector:** With selector 8, the function performs both decoding calls, acquires the service, obtains the limit, and then reaches F-a817d8d58c10. It does not simply return 4 at the initial gate.

3. **Zero operand:** With selector 9 and payload byte +8 equal to zero, the function returns 4 after the prerequisite dependency calls and the byte read. No range object is requested.

4. **Disallowed high nibble:** With selector 12 and payload byte +11 equal to 16, the operand fails the top-four-bit check regardless of the lower three bytes. The result is 4.

5. **Zero extent:** Suppose start is 20, extent is zero, limit is 100, and the operand is 1. The end is 20, so the upper-bound check passes but strict increase fails. The function returns 0 without requesting an object.

6. **Ordinary dispatch:** Suppose start is 20, extent is 5, limit is 100, and the operand is 1. The function requests an object using start 20. If the object is non-null and its +8 operation returns nonzero, F-99e0d644698f receives context, that object, 67, 20, 1, and 0. If it returns, F-feee9156a257 is then called with the object.

7. **Null object:** Under the same accepted range, if the object request returns null, neither the object's +8 operation nor F-99e0d644698f is called. F-feee9156a257 is still called with null.

8. **Sentinel extent:** With decoded extent −1, start 20, and limit 100, the effective extent is 80. A valid nonzero operand therefore reaches the object-request path. If start instead equals 100, the effective extent is zero and the function returns 0.

9. **Wrapping end:** With start 4,294,967,280, extent 32, limit 100, and operand 1, the unsigned end is 16. It passes the upper-bound comparison but fails strict increase. The function returns 0.

10. **Other negative extent:** With start zero, decoded extent −2, and limit 4,294,967,295, the effective unsigned end is 4,294,967,294. A valid operand reaches the object-request path; the visible function does not independently reject the negative decoded value.
