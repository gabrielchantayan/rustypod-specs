# F-44b989814b8a

## Purpose

F-44b989814b8a reports whether either of two 32-bit input bitsets contains a bit absent from its corresponding stored mask.

The report is written through a caller-supplied output pointer. The normal return value is always zero; it does not carry the report.

The established behavior is a pair of bitwise membership checks combined by logical OR. Interpreting the stored masks as permissions, capabilities, or supported features is inferred intent, not an established domain meaning.

Both bitsets are passed by value. The function does not modify the caller’s original scalar objects through those arguments.

## Behavior

### Ordered accesses and computation

The following order is established by the supplied representation:

1. Read and capture the global state reference.
2. Write the 32-bit value zero to the output destination.
3. Read the first 32-bit mask from offset `0x48` of the captured reference.
4. Determine whether the first bitset contains any bit not set in that mask.
5. Write that first comparison result to the output destination, encoded as a 32-bit `0` or `1`.
6. Read the second 32-bit mask from offset `0x4C` of the same captured reference.
7. Determine whether the second bitset contains any bit not set in that mask.
8. Write the logical OR of the two comparison results to the output destination, again encoded as a 32-bit `0` or `1`.
9. Return zero.

The second mask is read and the second comparison is evaluated even when the first comparison is already true. The expression places the second comparison before the saved first result in the logical OR; the earlier true result therefore does not bypass that read.

The first comparison result is retained independently of the output destination. The final result does not require reading the intermediate output value back from memory.

### Bit semantics and widths

Each comparison operates over 32 bits. A bit contributes to a positive comparison precisely when it is:

- set in the corresponding input bitset; and
- clear in the mask read for that comparison.

Mask complementation is confined to the 32-bit unsigned value. There is no established signed interpretation of either input and no wider-bit participation in the comparison.

Consequently:

- A zero input never produces a positive comparison.
- An all-ones mask never produces a positive comparison.
- A zero mask produces a positive comparison for every nonzero input.
- Bit 31 is treated as an ordinary bit, not as a sign indicator.
- The output reports the existence of an unmatched bit, not its position, count, or value.

No mask combination is written back to state. There is no addition, subtraction, or accumulation involving the input bitsets. Address calculations for the two fields are separate from the 32-bit bitset operations; their overflow or invalid-address behavior is not established.

### Captured state reference

Both mask addresses derive from the state reference captured at entry. The global reference is not reloaded between the mask reads.

This matters if the output destination overlaps the storage holding that reference: subsequent output writes do not replace the already captured address used for this invocation. Such overlap can still change persistent global storage.

The two mask values are read at different stages. The function does not establish an atomic snapshot of the pair.

### Aliasing

The supplied behavior contains no explicit non-aliasing check. When the environment permits the relevant overlap, the ordering of output writes and mask reads affects the result.

In particular:

- If the output destination is the first mask field, the initial zero write occurs before the first mask read.
- If the output destination is the second mask field, both the initial zero write and the first-result write occur before the second mask read.
- If the output destination overlaps other state storage, the three output writes can modify that storage as an incidental consequence of aliasing.

The general rule is to evaluate each mask using the value present when its ordered read occurs. A contract that reads both masks before touching the output would not preserve this behavior.

Whether a particular overlap is valid under the actual language, ABI, memory mapping, or device model remains environment-dependent.
