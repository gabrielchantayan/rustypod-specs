# F-f7b4a9381e48

## Purpose

F-f7b4a9381e48 repeatedly examines two gate words and conditionally executes an ordered set of memory writes, dependency calls, and optional callbacks. Within each admitted iteration, a separate pair of words supplies a fixed action-bit snapshot.

Admission and repetition use different conditions:

- The action sequence executes only when both gate words contain bit `0x40`.
- Another iteration begins whenever the gate words share **any** set bit.

The two gate addresses are derived using **different observations of a global base address**. Their adjacency is conditional on those observations being equal; it is not an unconditional property of this function.

“Gate,” “action,” and “state” identify structural roles only. Their application-level meanings are not established. The function may return, repeatedly execute actions, or repeat indefinitely without executing actions.

## Interface

**Explicit inputs:** None.

**Explicit output:** None. Normal completion returns without a value.

**Implicit inputs:**

- An initialization dependency.
- A global location supplying a state-object address.
- A global location supplying a main-word base address, read twice.
- Memory reached through the captured and derived addresses.
- Two optional callback slots in the state object.

For this contract:

- **State base** is the value read from the state-address global after initialization.
- **Retained main base** is the value obtained from the first subsequent read of the main-base global.
- **Independent gate base** is the value obtained from the second read of that same main-base global.

These names distinguish observations, not necessarily different numerical values.

### Referenced layout

The supplied representation uses unsigned 32-bit words. The following byte offsets use that represented width.

| Region | Address | Direct access |
|---|---|---|
| Main word | Retained main base | Read; conditionally overwritten |
| Adjacent main word | Retained main base plus 4 bytes | Read |
| First gate word | Independent gate base minus `0x60000` bytes | Read; conditionally overwritten |
| Second gate word | Retained main base minus `0x5FFFC` bytes | Read |
| First callback slot | State base plus `0x5C` bytes | Tested; conditionally read for invocation |
| Second callback slot | State base plus `0x60` bytes | Tested; conditionally read for invocation |
| State byte | State base plus 1 byte | Conditionally overwritten with zero |

The first gate displacement is negative `0x18000` words, equivalent to negative `0x60000` bytes. The second gate displacement is negative `0x17FFF` words, equivalent to negative `0x5FFFC` bytes.

If the two observed main-base values are equal, the second gate word is four bytes after the first. Otherwise, their separation is determined by both observed values. The source does not require the observations to agree.

Callback slots contain callable addresses, but their storage width and the complete state-object layout are not independently established. The state address is represented by an integer-typed value; its actual address representation and ABI remain unresolved.

The function contains no explicit validation of these conditions and returns no error indication.

## Behavior

### Initialization and ordered global reads

The first operation is a call to F-1db1c9fa8f5b.

After that call returns, the supplied representation performs these global reads in order:

1. Read the state-address global and retain the state base.
2. Read the main-base global and retain the main-word pointer.
3. Read the main-base global again and derive the first gate pointer by subtracting `0x18000` words from this second observation.

The second gate address instead uses the retained main-word pointer, at negative `0x17FFF` words. It does not use the independent gate base.

Initialization can affect all three observations. No intervening dependency call is shown between these reads, but that does not establish equality of the two main-base observations. The contract preserves both reads rather than replacing them with a single capture.

Once captured or derived, these addresses remain fixed for the invocation. Later changes to the address globals do not redirect them. Referenced contents and storage lifetimes are not thereby fixed: dependencies, callbacks, or other permitted memory effects may change them.

### Iteration entry and admission

The loop executes at least once. There is no gate test that can bypass the first iteration entirely.

At the start of each iteration, the function reads:

- The first gate word through the independently derived first gate address.
- The second gate word through the retained-main-base-relative second gate address.

It admits the action sequence only if the intersection of those words contains `0x40`.

If admission fails, it skips the entire action sequence, including the final first-gate write, and proceeds to the continuation test.

The supplied expression does not establish the relative evaluation order of the two gate-word reads. It does not establish an atomic combined observation.

### Action snapshot

On admission, the function reads the main word and its adjacent word and takes their 32-bit bitwise intersection.

This value is the action snapshot for that iteration. Every action condition uses that same snapshot, including conditions evaluated after writes and calls.

Consequently:

- Clearing a selected bit in memory does not cancel a later action selected by the snapshot.
- Setting an additional bit in memory does not select a new action in the current iteration.
- A later admitted iteration reads a new snapshot.

The relative order of the two reads forming the snapshot is not established by the supplied expression.

### Ordered actions

All matching conditions execute independently, in the following order, provided intervening calls return normally.

| Order | Snapshot bit | Action |
|---:|---:|---|
| 1 | `0x100` | Overwrite the main word with `0x100`. |
| 2 | `0x80` | Overwrite the main word with `0x80`. |
| 3 | `0x20` | Overwrite the main word with `0x20`. |
| 4 | `0x10` | Call F-f80f1d4c41e3 with no explicit argument shown. |
| 5 | `0x08` | Overwrite the main word with `0x08`. |
| 6 | `0x04` | Overwrite the main word with `0x04`. |
| 7 | `0x02` | Call F-0167d0317c8a with no explicit argument shown. |
| 8 | `0x01` | Overwrite the main word with `0x01`. |
| 9 | `0x40` | Execute the first callback sequence. |
| 10 | `0x02` | Execute the second callback sequence. |

Each main-word write replaces the full 32-bit word. It is not a bit set, bit clear, or masked update.

Later selected direct assignments replace earlier selected assignments. That alone does not determine the word’s final value: subsequent calls, aliasing writes, or other permitted effects may also modify its storage.

Snapshot bits outside `0x1FF` select no direct action. Unknown bit meanings are not needed to determine this ordering.

### First callback sequence

If the snapshot contains `0x40`:

1. Call F-234db1b27977 with scalar value `0x40`.
2. After that call returns, test the callback slot at state offset `0x5C`.
3. If the slot is nonzero, invoke through that slot with no explicit arguments shown.
4. After the optional callback returns, overwrite the single byte at state offset 1 with zero.

The byte clear occurs even when the callback slot is zero. It is not reached if the preceding dependency or selected callback does not return normally.

F-234db1b27977 can affect the slot before its test. The representation contains a slot access for the nonzero test and a separate slot access for invocation; it does not establish one cached target shared between them. If those observations differ, the nonzero test alone does not guarantee that the subsequently invoked value remains valid.

### Second callback sequence

Snapshot bit `0x02` selects both the earlier call in the action table and this later sequence:

1. Call F-0167d0317c8a with scalar value 2 shown.
2. After that call returns, test the callback slot at state offset `0x60`.
3. If nonzero, invoke through that slot with no explicit arguments shown.

There is no explicit state-byte clear in this sequence.

When both `0x40` and `0x02` are selected, the first callback sequence, including its byte clear, completes before the later F-0167d0317c8a call and second callback.

The two displayed call forms for F-0167d0317c8a differ. This contract preserves that evidence without asserting a compatible prototype or supplying an unshown argument.

### Final gate write and continuation

After all admitted actions complete normally, the function overwrites the entire first gate word with the 32-bit value `0x40`.

This write:

- Targets the address derived from the **second** main-base-global observation.
- Occurs even if the action snapshot selects no actions.
- Does not occur when admission fails.

At the end of every iteration, the function reads the same two separately derived gate locations again and tests their full bitwise intersection:

- Zero intersection: return.
- Nonzero intersection: begin another iteration.

The continuation condition is not masked by `0x40`. Its two operand reads have no established relative evaluation order.

Under stable gate contents and no relevant intervening effects:

- Disjoint gate bits cause a return after the first skipped action sequence.
- A common bit other than `0x40`, with no common `0x40`, causes indefinite repetition without admitted actions.
- Common `0x40` admits actions; after the first-gate write, repetition continues if the second gate still contains `0x40`.

These rules apply to the actual captured gate addresses, whether adjacent or not. There is no explicit timeout, sleep, iteration bound, or progress error.

## Side effects

The function directly writes through three destination roles:

- Main word: selected full 32-bit replacements.
- First gate word: full 32-bit replacement with `0x40` after admitted actions.
- State byte: one-byte zero write during the first callback sequence.

It contains no explicit write through the adjacent-main-word or second-gate-word expressions. This is not a guarantee that their storage remains unchanged: separately derived addresses may alias, state storage may overlap, and callees may modify memory.

No explicit allocation, release, ownership transfer, or cleanup is shown. Callee ownership behavior is unknown. Capturing an address does not retain its allocation or prevent a dependency from invalidating it. Subsequent accesses require the relevant storage to remain valid.

Dependencies and callbacks may also affect globals or external state. Their results, if any, are not consumed by this function.

No explicit atomic operation, lock, or synchronization primitive is shown. The read ordering described here is structural evidence, not a supported concurrent-memory protocol or an independent machine-level ordering guarantee.

## Acceptance examples

These are conditional static examples, not executed tests. They assume valid address calculations and storage, and normally returning calls unless otherwise stated. Claims about unchanged storage additionally assume no relevant aliasing or external mutation.

1. **Different base observations.**  
   Suppose the retained main base is `0x100000`, while the second main-base-global observation is `0x200000`. The main snapshot is read at `0x100000` and `0x100004`. The first gate is at `0x1A0000`; the second is at `0x0A0004`. Admission and continuation use those nonadjacent gate locations. An admitted final gate write targets `0x1A0000`, not `0x0A0000`.

2. **Equal base observations.**  
   If both main-base reads yield `0x100000`, the first gate is at `0x0A0000` and the second at `0x0A0004`. Only under this equality do the two gate roles form the adjacent pair implied by those offsets.

3. **Return without admission.**  
   If the captured first gate contains `0x40` and the captured second gate remains zero, admission fails and continuation returns. No action-selected direct write or call occurs.

4. **Repetition without actions.**  
   If both captured gate words remain `0x02`, admission always fails, but continuation always succeeds. The function repeatedly reads the gates without executing the action sequence.

5. **Empty action snapshot.**  
   If both gates contain `0x40` but the main-word intersection is zero, no snapshot-selected action executes. The independently derived first gate is nevertheless overwritten with `0x40`.

6. **Ordered replacement writes.**  
   For an admitted snapshot of `0x181`, the main word receives `0x100`, then `0x80`, then `0x01`. No dependency is selected by those bits. If the final gate write does not alias the main word and there are no other modifying effects, the main word remains `0x01` at iteration end.

7. **Two calls selected by one bit.**  
   For an admitted snapshot of exactly `0x02`, F-0167d0317c8a is called twice in the documented order. Only after the later call returns is the second callback slot tested.

8. **Snapshot retained across mutation.**  
   If an admitted snapshot contains `0x10` and `0x01`, F-f80f1d4c41e3 may clear both main words, but the subsequent direct write of `0x01` still occurs.

9. **Callback replacement before inspection.**  
   If F-234db1b27977 replaces the first callback slot, the later test uses the slot after that call. If it remains a valid nonzero target through invocation, that callback runs before the state byte is cleared.

10. **Dependency-driven termination.**  
    If an admitted action sets the second gate to zero and it remains zero, the function still writes `0x40` to the first gate. Continuation then returns, provided that final write does not alias and change the second gate.

11. **Nonreturning first callback.**  
    If the selected first callback never returns, the state-byte clear, later `0x02` callback sequence, final gate write, and continuation test are not reached.
