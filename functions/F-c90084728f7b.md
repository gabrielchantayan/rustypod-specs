# F-c90084728f7b

## Purpose

F-c90084728f7b traverses a context-referenced sequence of entry addresses. For each visited slot, it constructs four temporary selection objects, enumerates the fourth, and dispatches operations according to a signed 32-bit field of each selected record.

The first three selections supply ordered inputs to accumulation dependencies. Depending on the dispatch branch, the function passes one or two accumulated values to a final dependency, invokes a direct operation, or performs no dispatch call.

“Selection,” “accumulation,” and “finalization” describe call-site roles, not established domain semantics. Neither the context’s ownership of the sequence nor the dependencies’ ownership of any referenced object is established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and result

The function accepts:

- **Context:** a 32-bit address-bearing argument. The function reads traversal addresses from this object and passes the argument unchanged to several dependencies.
- **Auxiliary value:** an opaque 32-bit value supplied to the second selection constructor on every outer iteration.

There is no explicit return value, success indicator, or error result.

## Behavior

### Shared value and traversal

Before reading the initial sequence address, the function calls F-ea223a7ae124 once. Its opaque 32-bit result is cached and reused for all selection constructions during this invocation.

This call occurs even if the sequence is empty.

After the call returns, the function reads context offset `0x10` to establish the current slot address. At every outer-loop condition, it reads context offset `0x14` and compares that value with the current slot address. Equality ends traversal.

The initial address is not visibly refreshed from `0x10`. The end address is refreshed at each condition. Consequently, changes made by dependencies can affect the traversal limit without resetting the current position.

### Selection construction

For each visited slot, the function constructs and queries four selections in A, B, C, D order. Each construction call to F-326b1fb00786 is immediately followed by a query of that same selection through F-d0b90560f1fd.

The constructor receives, in order, the selection’s backing address, the cached shared value, the selection-specific input, a tag value read from external data, and zero.

| Selection | Selection-specific input | Query result |
|---|---|---|
| A | Word at entry offset `0x08` | Cached 32-bit descriptor |
| B | Auxiliary argument | Cached 32-bit descriptor |
| C | Word at entry offset `0x00` | Cached 32-bit descriptor |
| D | Word at entry offset `0x04` | Cached unsigned 32-bit enumeration bound |

The four constructor tags come from distinct external data locations. Their values, equality relationships, and stability are unknown. The representation does not establish that these tag values are cached across outer iterations.

The slot is dereferenced separately when obtaining the entry-dependent input for A, C, and D. There is no single cached entry address shared by those three constructions. If an intervening dependency changes the slot, later constructions can use a different entry.

Selection B is reconstructed on every outer iteration despite receiving the same explicit auxiliary argument.

### Enumeration and accumulator initialization

Selection D is enumerated using an unsigned 32-bit index beginning at zero. An iteration occurs while that index is less than D’s cached unsigned bound.

F-0ff4e60503e7 receives D’s address and an index argument formed by narrowing the loop index to signed 16 bits, then promoting that narrowed value to the argument’s integer width.

After F-0ff4e60503e7 returns, the caller performs the following operations in this order:

1. Writes zero to the first-result cell.
2. Writes zero to the second-result cell.
3. Writes zero to the seeded-result cell.
4. Reads the record address from offset `0x08` of the returned enumeration-result address.
5. Reads the signed 32-bit discriminator from record offset `0x4c`.

The zero writes therefore precede the record-address read. They must not be treated as interchangeable with that read: the dependencies’ retained references and aliasing behavior are unknown.

All three cells are initialized on every enumeration iteration, including iterations that ultimately use no accumulator.

Under the represented two’s-complement signed-16-bit interpretation, the index argument has these boundary values:

|---:|---:|
| 32,767 | 32,767 |
| 32,768 | −32,768 |
| 65,535 | −1 |

Thus, large bounds permit repeated argument values and negative arguments. No visible restriction limits D’s bound to 32,768 or establishes that the enumeration dependency accepts negative indices.

D’s bound remains cached throughout enumeration. After each normally completed dispatch, including an unmatched dispatch, the loop index advances by one.

### Dispatch data and read sensitivity

The dispatch uses these symbolic names for external 32-bit data:

| Symbol | Role |
|---|---|
| T | Primary threshold |
| L | Lower-subtree adjustment |
| M | Additional lower-subtree adjustment |
| N | Final lower-subtree comparison value |
| U | Initial upper-subtree adjustment |
| V | Second upper-subtree adjustment |
| W | Third upper-subtree adjustment |
| X | Final upper-subtree comparison value |

Their numeric values are unavailable.

These symbols designate data locations, not invocation-stable constants. In particular:

- T is read for the equality comparison.
- If equality fails, T is read again for the signed less-than comparison.
- If that comparison also fails, T is read again for the subtraction used to enter the upper subtree.
- In the lower subtree, M is read for the comparison against zero. If that comparison fails, M is read again for the comparison against N.

The lower subtree is selected by the second threshold comparison, not by the earlier equality read. The upper subtree is selected when both preceding comparisons fail. Calling these simply “below T” and “above T” assumes that the relevant T reads observe one stable value. Without that assumption, the upper subtree need not correspond to a discriminator greater than the T value used in the equality comparison or subtraction.

The representation establishes these repeated source-level accesses. It does not establish atomicity, synchronization, permitted concurrent mutation, or an exact machine-level ordering between separate operand reads within one expression.

### Equality branch

If the discriminator equals the T value read by the first comparison, F-015b24a070ee is called for A, then B, then C.

Each call receives:

- Context.
- Current selection address.
- That selection’s cached descriptor.
- A fresh read of record offset `0x30`.
- The address of the second-result cell.

That cell was initialized to zero before the record address was read. The caller does not reset it between these calls.

After all three calls return, F-9b5aeabc6401 receives the record address and the current second-result value.

### Lower subtree

If equality fails and the discriminator is signed-less-than the freshly read T value, the discriminator is adjusted by adding L. This adjusted value is retained for the following ordered decisions:

| Priority | Condition | Action |
|---:|---|---|
| 1 | Adjusted value equals zero | Two-result accumulation, followed by F-319c5e56ac66 |
| 2 | Adjusted value equals `0x3fe` (1,022) | F-f5cd16faac60 receives zero, zero |
| 3 | Adjusted value plus the M value read for this condition equals zero | F-174ef6619c99 is called without explicit arguments |
| 4 | Adjusted value plus a newly read M value equals N | F-8baff88e54ab receives record offset `0x5c`, zero, zero |

Only the first matching action executes. If none matches, there is no dispatch call for the record.

The fourth condition does not reuse the sum tested by the third condition. It adds M again to the retained adjusted value, using a separate M read.

For two-result accumulation, F-6b95b2531e9d processes A, B, and C in order. Each call receives context, selection address, cached descriptor, a fresh read of record offset `0x30`, and the first-result and second-result addresses in that order. The caller does not reset either cell between calls.

F-319c5e56ac66 then receives context, record address, first-result value, and second-result value.

### Upper subtree

If both threshold comparisons fail, the discriminator is reduced by another freshly read T value and then increased by U. The resulting first adjusted value controls the following prioritized cases:

1. **First adjusted value equals zero.**  
   The seeded-result cell is assigned the word read from record offset `0x5c`. F-65ef5e55cbb1 processes A, B, and C in order using that cell. F-ea7dc5204e42 then receives its resulting value.

2. **After adding V, the adjusted value equals zero.**

3. **After subsequently adding W, the adjusted value equals zero.**  
   The seeded-result cell is assigned the word read from record offset `0x5c`. F-65ef5e55cbb1 processes A, B, and C in order. F-98101d29daa9 then receives its resulting value.

4. **The value after adding W equals X.**  
   F-6b95b2531e9d performs the same ordered two-result accumulation described above. F-f870ebbca40f then receives context, record address, first-result value, and second-result value.

If no case matches, no dispatch dependency is called.

Each F-65ef5e55cbb1 call receives context, selection address, cached descriptor, a fresh read of record offset `0x30`, and the seeded-result address. The seed is read once for the selected branch, before its first accumulation call.

### Accumulation invariants and completion

Across every three-selection accumulation path:

- A completes before B begins; B completes before C begins.
- Record offset `0x30` is read separately for each call.
- The record address, discriminator, and cached descriptors are not refreshed.
- The caller ignores accumulation return values and uses the addressed cells for final-operation arguments.
- No arithmetic combination of accumulated results is performed by the caller.

A dependency changing record offset `0x30` can therefore affect the next accumulation call without causing redispatch.

After D’s enumeration finishes normally, F-3a8de16627bf receives D, C, B, and A in that order. This reverse-order finalization also occurs when D’s bound is zero.

The current sequence-slot address then advances by four bytes before the next outer-loop condition.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Arithmetic examples assume representable signed intermediate results.

1. **Empty sequence.** If the initial slot address equals the end address at the first condition, F-ea223a7ae124 has still executed once. No selections are constructed.

2. **Zero enumeration bound.** All four construction/query pairs execute in A–D order. No enumeration call occurs. Finalization executes in D–A order.

3. **Initialization ordering.** After an enumeration call returns, the caller writes first-result zero, second-result zero, and seeded-result zero before reading the returned object’s record-address field. A behavioral model that moves that field read earlier does not satisfy this ordering.

4. **Equality accumulation.** If the equality branch is selected and successive F-015b24a070ee calls leave the second-result cell at 5, 12, and 9, F-9b5aeabc6401 receives 9. The caller does not sum those observations.

5. **Fresh threshold comparisons.** If the discriminator is 10, the equality read of T yields 9, and the subsequent less-than read yields 11, execution enters the lower subtree. The first T observation is not reused.

6. **Fresh threshold subtraction.** If the discriminator is 10, the equality read yields 9, the less-than read yields 8, and the subtraction read yields 12, execution reaches the upper subtree and computes its initial adjustment using subtraction of 12, not 9 or 8.

7. **Repeated lower adjustment.** Suppose the lower adjusted value is 5. If the first M read yields 1, the zero condition fails. If the next M read yields −5 and N yields zero, the final lower condition matches and invokes F-8baff88e54ab.

8. **Mutable record input.** If accumulation through A changes record offset `0x30`, accumulation through B receives the subsequently read value.

9. **Seed retention.** If a seeded branch reads `0x12345678` and all three accumulation calls preserve that cell, its final dependency receives `0x12345678`.

10. **Index boundary.** With D’s bound equal to 32,769, the iteration at unsigned index 32,768 passes −32,768 to F-0ff4e60503e7.

11. **Priority and unmatched records.** If multiple predicates would match under stable external data, only the earliest reached match executes. If none matches, enumeration still advances normally.
