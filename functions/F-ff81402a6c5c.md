# F-ff81402a6c5c

## Purpose

F-ff81402a6c5c prepares a temporary word-buffer object, processes advancing windows through an opaque dependency, propagates local carries, trims high zero words, and copies a shifted range into a destination object. Two final dependencies select the result after the copy.

**Inferred intent:** The operation resembles Montgomery reduction over 32-bit limbs, with a final comparison and possible subtraction. The supplied body does not establish those dependencies’ numerical meanings or an overall mathematical reduction guarantee.

The result is a 32-bit zero or one. One does not necessarily mean that the destination was populated: a zero-count path clears the temporary logical length and returns one without locally writing the destination. Zero does not imply rollback.

## Behavior

### Entry and preparation

The selected result starts at zero.

First, F-ea92bf179106 receives the context token; its return is ignored. F-834e12b6dfde then receives that token and supplies the temporary object.

If acquisition returns null, preparation and subsequent local operand processing are skipped. The ordinary-exit dependency is called, and the function returns zero.

For a nonnull temporary object, F-cec6695e396c receives the temporary object and source operand. A zero return selects ordinary failure. A nonzero return permits count processing. The call site does not establish what preparation copies, allocates, normalizes, or preserves.

### Counts and exceptional early success

After preparation succeeds, parameter offset 0 is converted to a signed word-shift count by division by 32 with truncation toward zero. Thus:

- 31 and −31 produce zero.
- 32 produces one.
- −32 and −33 produce −1.

The signed iteration count is then read from parameter offset 28.

If either count is exactly zero, the temporary logical length is written as zero and the function immediately returns one. F-4bd8a1faf697 is **not** called on this path.

This path makes no direct destination write. Effects from earlier dependencies or aliases remain possible. Negative nonzero counts do not select this early return.

### Capacity decisions

For nonzero counts, the requested capacity is:

**iteration count + word-shift count + 1**

The temporary capacity is compared with this request using signed comparison. If smaller, F-08bc2fc94856 receives the original temporary object address and requested capacity. A null return causes ordinary failure.

Only after the temporary capacity decision succeeds is the destination capacity checked. If smaller than the same request, F-08bc2fc94856 receives the destination object and request. A null return causes ordinary failure.

A nonnull growth return is only a success indication. The function continues using the original object address rather than adopting the returned address. Successful growth must therefore leave that original object usable for subsequent accesses.

There is no local rejection of a negative request or explicit overflow handling for the count sum.

### Metadata and zero extension

After both capacity decisions succeed, the source metadata at byte offset 12 and parameter value at byte offset 36 are XORed as 32-bit values. The result is stored in temporary metadata. The body establishes both input reads before that store, but does not establish a sequencing requirement between those two input reads.

Next, the function captures the value at parameter offset 24, then captures the temporary buffer address. This captured buffer address is retained for window processing.

Zero extension begins at the temporary object’s current signed logical length and continues through the word immediately below the requested capacity. Each selected word is set to zero.

**The temporary buffer-address field is reloaded for every zero-fill store.** The fill does not use the retained window-processing address. Consequently, a store that aliases and changes the buffer-address field changes the address used by a later fill store. It does not change the retained address used for window processing.

The fill index advances independently of subsequent changes to the logical-length field. If the initial length is already at least the request, no zero-fill stores occur.

After filling, temporary logical length is set to the request. Only then is the multiplication factor read from parameter offset 64.

### Window processing and carry propagation

A positive iteration count produces exactly that many calls to F-ff479513efd3. A negative iteration count produces none.

The first window begins at the temporary buffer address captured before zero extension. Each subsequent window begins one word higher. Each call receives:

1. The current window address.
2. The captured value from parameter offset 24.
3. The captured iteration count.
4. The low 32 bits of the product of the captured multiplication factor and the current first window word.

The fourth argument discards higher product bits. The current first word is read for each call; it is not captured once for the entire phase.

The dependency return is treated as an unsigned 32-bit value. No return value selects a local failure branch.

After the call, the function reads the target word located one iteration-count beyond the current window start. Helper changes to that target therefore affect the addition. The return value is added to the target modulo \(2^{32}\), and the result is stored.

Carry is detected when the unsigned result is less than the helper return. On carry, the next higher word is incremented modulo \(2^{32}\). If that increment wraps to zero, propagation continues to the following word. Propagation stops at the first increment producing a nonzero value.

There is no capacity check, bound check, or growth call during propagation. The requested extra word does not independently prove sufficient headroom.

The window address and corresponding addition target advance using retained addresses, not by reloading the temporary buffer field after each opaque call.

### High-zero trimming

After window processing, the temporary logical length is read again. If positive, a descending scan address is formed from the then-current temporary buffer address and length.

The scan reads the highest selected word first. A nonzero word ends trimming. A zero word causes the current logical-length field to be reread and decremented by one. Scanning continues downward while the resulting length remains positive.

The descending scan address is retained rather than reconstructed from the buffer field for every read. Header aliasing can therefore distinguish the scan address from the changing logical length.

Trimming neither clears discarded words nor changes metadata locally.

### Metadata transfer and shifted copy selection

Temporary metadata is read and written to destination metadata **before** the temporary buffer and length are read for copy selection.

This ordering matters when headers overlap. The destination-metadata write can change temporary length, temporary buffer address, or other subsequently accessed storage through aliasing. Reaching length zero during trimming does not alone guarantee a zero selected destination length.

After that metadata write:

1. The copy-source address is formed from the then-current temporary buffer address plus four times the captured word-shift count.
2. The then-current temporary length is compared with the word-shift count using signed comparison.
3. If temporary length is smaller, selected destination length is zero. Otherwise, it is temporary length minus the word-shift count.
4. The destination buffer address is captured.
5. The selected destination length is stored in the destination header.

The source address is formed even when selected length is zero. A negative word-shift count is not rejected and can move this address below the buffer base.

The destination-length store occurs after both copy-buffer addresses have been captured. If that store aliases a buffer-address field, it does not redirect the subsequent copy. If it aliases source words, those changed words may be read by the copy.

### Copy order

Copying proceeds toward increasing indices using the captured source and destination addresses.

A four-word group executes only when its starting index is **strictly less than selected length minus four**. Group starts advance by four. Remaining words are copied individually.

Consequences include:

- Length four: four individual copies.
- Length five: one four-word group, then one individual copy.
- Length eight: one four-word group, then four individual copies.

Within each group, source words at relative offsets one, two, and three are loaded in that order before the first destination store. Source word zero is then read and stored. The three retained values are subsequently stored at destination offsets one, two, and three.

An individual copy reads its source word and writes its destination word before advancing.

This is not an established overlap-safe move. Group boundaries and preload order can change results for overlapping ranges. No words beyond the selected length are locally cleared.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Memory effects are stated at the indicated local phase, before later opaque calls unless preservation is explicitly assumed.

1. **Acquisition failure.** If F-834e12b6dfde returns null, preparation is skipped, F-4bd8a1faf697 is called, and the result is zero.

2. **Preparation failure.** If F-cec6695e396c returns zero, count processing is skipped and ordinary exit returns zero.

3. **Zero quotient.** After successful preparation, a size value of 31 or −31 yields a zero word-shift count. Temporary length becomes zero, and the function returns one without the ordinary-exit dependency or a direct destination write.

4. **Zero iterations.** A nonzero word-shift count with iteration count zero takes the same early-success path.

5. **Temporary growth failure.** If required temporary growth returns null, destination capacity is not checked. Ordinary exit returns zero.

6. **Zero-fill buffer reload.** Suppose initial temporary length is zero, requested capacity is at least two, and the temporary buffer points to its own header. The first fill store clears the buffer-address field. The next fill store attempts address four rather than the original header address plus four. Validity of that access is not established.

7. **Carry propagation.** If a helper returns one and the post-call target contains all ones, the target becomes zero. The next higher word is incremented, with propagation continuing through any further wrapping words.

8. **Shifted selection.** If the word-shift count is two and temporary length is five **when read for copy selection**, selected destination length is three. The copy uses source indices two through four relative to the temporary buffer value read at that phase.

9. **Four-word overlap.** With selected length four, destination beginning one word above the copy source, no header aliasing, and first source word A, individual copying produces destination words A, A, A, A.

10. **Five-word overlap.** Under the same overlap arrangement, initial source words A, B, C, D, E produce destination words A, B, C, D, D. Group preloads retain B, C, and D; the final individual read encounters an overwritten source word.

11. **Negative final gate.** A negative F-c0985d8666ae return skips F-e3b26f245f4c and selects result one, irrespective of any unestablished numerical relationship.

12. **Final failure after writes.** A nonnegative final-gate return followed by a zero F-e3b26f245f4c return selects zero. Earlier destination writes are not locally undone.

13. **Fully trimmed, unchanged length.** If trimming reaches zero, the subsequent destination-metadata store leaves temporary length unchanged, and the word-shift count is positive, selected destination length is zero. Metadata transfer and the final gate still occur.

14. **Fully trimmed, overlapping headers.** Suppose trimming reaches zero, temporary metadata is five, and the word-shift count is two. If the destination begins eight bytes before the temporary object, destination metadata aliases temporary length. The metadata transfer writes five into that length before copy selection. Subject to valid accesses and the other stated phase conditions, selected destination length is therefore three, not zero.
