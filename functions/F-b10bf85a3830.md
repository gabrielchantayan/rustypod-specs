# F-b10bf85a3830

## Purpose

F-b10bf85a3830 conditionally prepares a context-owned byte string, invokes two dependencies, and records a classification in context state bytes.

The established behavior has three distinct outcomes:

- A null context or zero source address returns the 32-bit error value `0xFFFFFFCE`.
- A context whose state byte is already `1` returns zero without preparing or classifying the string, although a nested context value is read first.
- Otherwise, the function copies a bounded source region with two byte substitutions, invokes dependencies, and records either state `1` or state `2`.

A suffix resembling “`.aa`”, with either letter independently upper- or lowercase, activates an additional identifier-membership decision. Other suffixes take the state-`1` path.

The interpretation of the copied bytes as a name, the state values as acceptance or rejection, and the identifier table as an authorization list is inferred intent, not an established external contract. In particular, state `2` still returns zero.

## Interface

### Inputs

The observed interface has three 32-bit arguments:

| Argument | Observed interpretation |
|---|---|
| Context address | Address of a mutable context structure. Zero is explicitly rejected. |
| Source address | A 32-bit address used to read individual bytes. Zero is explicitly rejected. |
| Source limit | A signed 32-bit value used as an exclusive source-offset limit, not as the number of bytes copied. |

The source limit is compared with `55` using signed ordering. Values greater than `55` are reduced to `55`. Negative values are not converted into large unsigned lengths; they cause no source bytes to be copied.

### Return value

The return is a 32-bit value:

- `0xFFFFFFCE` when either of the first two arguments is zero. Interpreted as signed two’s-complement, this is `-50`.
- `0` on every other normally completed path, including the path that records state `2`.

No separate error return is established for an invalid nonzero address, an invalid nested pointer, a dependency failure, an unterminated dependency-modified string, or a malformed table.

### Context layout used by this function

Offsets are byte offsets from the context address.

| Offset | Width | Use |
|---|---:|---|
| `0x00` | 32 bits | Address of a linked object. |
| `0x16` | 8 bits | State byte; entry value `1` suppresses processing after the initial nested read. |
| `0xB0` | 32 bits | Unsigned identifier examined only when the suffix condition matches. |
| `0xC0` onward | Bytes | Destination string region and later suffix-inspection region. |
| `0xE4` | 8 bits | Written to `1` on the state-`1` completion path. |
| `0xE5` | 8 bits | Written to `1` on the state-`1` completion path. |

The linked-object layout used for nested access is:

1. Read a 32-bit address at context offset `0x00`.
2. Read another 32-bit address at offset `0x08` in that linked object.
3. Read a 32-bit value at offset `0xBE0` in the resulting object.

The first such value is passed to a dependency. On a later conditional path, the same address chain is traversed again and its final value is interpreted as a table address.

### Memory preconditions

For normal completion, every address actually accessed must be valid for the indicated read or write. The explicit null checks do not establish this validity.

If processing occurs, the context must permit writes through destination offset `0xE3` at the largest copy bound. The state-`1` path additionally writes offsets `0xE4` and `0xE5`. Dependency requirements may be stronger.

The function performs no allocation or release directly. It neither establishes ownership transfer nor proves that dependencies leave ownership unchanged.

## Behavior

### 1. Validate the two address arguments

If the context address is zero, or the source address is zero, the function returns `0xFFFFFFCE`.

No context, source, or nested-object read precedes this rejection.

A zero source address is rejected even if the source limit would cause an empty copy, and even if a valid context would otherwise have state `1`.

### 2. Read the nested value before testing state

With both addresses nonzero, the function traverses the context’s linked-object chain and captures the 32-bit value at the final `0xBE0` location.

Only after that read does it inspect the byte at context offset `0x16`.

Consequently, entry state `1` does not make the nested pointers irrelevant. They must still support the initial read for normal completion.

If the state byte equals exactly `1`, the function returns zero. It performs no source-byte copy, dependency call, suffix check, or direct context write on this path.

Any other state-byte value enters processing.

### 3. Copy a bounded byte region with substitutions

The signed source limit is capped above at `55`. Copying begins at source offset `20`, and continues while the source offset is strictly less than the capped limit.

For each copied byte:

- `0x5C`, conventionally backslash, becomes `0x5F`, conventionally underscore.
- Otherwise, `0x3A`, conventionally colon, becomes `0x5C`, conventionally backslash.
- Every other byte is copied unchanged.

The substitutions are alternatives, not a repeated transformation. A colon becomes a backslash and remains a backslash; it is not subsequently changed to an underscore.

Destination writes begin at context offset `0xC0` and advance one byte per copied source byte. A zero byte is then written immediately after the copied region.

The number of copied bytes is:

- Zero when the source limit is at most `20`.
- The source limit minus `20` when the source limit is from `21` through `55`.
- `35` when the source limit exceeds `55`.

Thus the largest direct destination-string write is the terminator at context offset `0xE3`. The largest source offset read by this stage is `54`.

Embedded zero bytes do not stop copying. The bound, rather than string termination, controls the copy.

Each source byte is read before its corresponding destination byte is written. The source and destination are not checked for overlap. If an earlier destination write changes a source byte that has not yet been read, later copying observes that changed byte. No snapshot or overlap-safe move behavior is established.

### 4. Invoke dependencies in order

After writing the destination terminator, the function calls F-c77f56a4934d with:

1. The context address.
2. The nested 32-bit value captured before the entry-state check.

Its return value is not used by this function.

The function then calls F-1cb585febd84 with the address at context offset `0xC0`. Its result is treated as an unsigned 32-bit quantity for subsequent comparisons and address calculations.

The result is length-like in its use, but the supplied evidence does not establish that F-1cb585febd84 computes a conventional string length.

Neither dependency may be assumed to preserve the context, its linked objects, the destination bytes, or global state. In particular:

- The suffix check examines memory after both dependency calls.
- The identifier is read after both dependency calls.
- Any table access follows a fresh traversal of the nested address chain.
- The initially captured nested value is not refreshed before being passed to F-c77f56a4934d.

### 5. Evaluate the conditional suffix

The provisional classification is the state-`1` path.

The identifier-membership decision is entered only if all of the following hold:

1. The unsigned result from F-1cb585febd84 is greater than `3`.
2. The byte one position before that result, relative to context offset `0xC0`, is `0x61` or `0x41`.
3. The byte two positions before that result is also `0x61` or `0x41`.
4. The byte three positions before that result is `0x2E`.

These reads are short-circuited and occur from the final byte backward: last letter, preceding letter, then dot. A failing earlier condition suppresses the later reads.

The strict result threshold matters. A result of `3` does not activate this decision, even if the destination contains exactly “`.aa`”.

No upper bound is imposed on the dependency result before suffix-relative reads. Safe access therefore depends on the dependency result and the resulting addresses. The function’s own 35-byte copy bound does not independently bound this later inspection.

### 6. Evaluate the identifier and optional table

When the suffix condition matches, the function reads the unsigned 32-bit identifier at context offset `0xB0`.

The classification becomes:

- Identifier `0`: state-`2` path, without a table lookup.
- Identifier `1`: state-`1` path, without a table lookup.
- Identifier greater than `1`: initially state-`2`, then changed to state-`1` if a matching table entry is found.

For an identifier greater than `1`, the function traverses the nested address chain again. The final 32-bit value is now used as a table address.

The table has this observed layout:

| Table offset | Width | Meaning in this function |
|---|---:|---|
| `0x00` | 32 bits | Unsigned entry count. |
| `0x04` | 32 bits | First identifier entry. |
| `0x08` | 32 bits | Second identifier entry. |
| Subsequent multiples of four | 32 bits each | Remaining identifier entries. |

Entries are examined in ascending index order. Before each entry read, the loop compares the unsigned index with the count read from the table header. A matching entry ends the search immediately and selects state `1`.

A zero count produces no entry reads and leaves state `2` selected.

The table pointer is captured once for this search; the header count is read again for successive loop conditions rather than being captured once. The source supplies no validation of the count, table extent, or entry-address arithmetic. Extremely large counts cannot be treated as a guaranteed safe traversal.

### 7. Publish the selected state

For the state-`1` path, direct writes occur in this order:

1. Write byte `1` at context offset `0xE4`.
2. Write byte `1` at context offset `0x16`.
3. Write byte `1` at context offset `0xE5`.

For the state-`2` path:

1. Write byte `2` at context offset `0x16`.
2. Do not directly write either `0xE4` or `0xE5` at this stage.

The latter path does not clear those two flag bytes. Their final values may retain prior state or dependency modifications.

The function then returns zero.

## Side effects

Direct effects are limited to the destination bytes, their appended terminator, and the state or flag bytes described above. Additional effects through either dependency are unknown.

Important observable distinctions are:

- A successful return does not imply state `1`.
- State `2` does not reset the auxiliary flags.
- Entry state `1` suppresses direct writes but not the initial nested read.
- Copying is completed before either dependency is called.
- Final classification writes happen after both dependencies.
- The source is not directly written as a source object, but aliasing can make destination writes modify the same storage.

No synchronization or atomic publication of the three state-`1` writes is established. No concurrency guarantees follow from this evidence.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume valid accessible memory, dependencies that return normally, and no dependency mutation of the illustrated bytes or fields.

1. **Null input rejection.**  
   A zero context address, or a zero source address, produces `0xFFFFFFCE` with no direct memory access or dependency call.

2. **Already-selected state.**  
   With nonzero arguments, valid nested pointers, and entry state `1`, the nested value is read and the result is zero. No source bytes are read and no state bytes are written.

3. **Empty copied region.**  
   A source limit of `20`, `0`, or a negative signed value causes no source-byte reads. A zero byte is written at context offset `0xC0`, followed by both dependency calls. If the second dependency returns zero, the final state and both auxiliary flags become `1`.

4. **Substitution order.**  
   With source limit `23` and source offsets `20` through `22` containing backslash, colon, and `X`, the destination receives underscore, backslash, and `X`, followed by zero.

5. **Maximum copy extent.**  
   A source limit of `100` copies exactly source offsets `20` through `54`. It writes 35 destination bytes and a terminator at context offset `0xE3`; it does not read source offset `55`.

6. **Three-byte suffix excluded.**  
   If the destination is “`.aa`” and F-1cb585febd84 returns `3`, the identifier is not consulted. Final state and both auxiliary flags become `1`.

7. **Matching suffix with identifier zero.**  
   If the destination is “`x.Aa`”, the dependency returns `4`, and the identifier is zero, final state becomes `2`. No table is read, and this function does not overwrite the auxiliary flags during publication.

8. **Identifier one bypasses the table.**  
   With the same matching suffix and identifier `1`, final state and both auxiliary flags become `1`, without a table lookup.

9. **Membership distinguishes otherwise identical inputs.**  
   With a matching suffix and identifier `7`, a table containing `7` selects state `1`; a valid table without `7` selects state `2`. An empty table also selects state `2`. All three cases return zero.

10. **Processing does not use an immutable entry snapshot.**  
    If F-c77f56a4934d changes the identifier or nested table link, the later decision uses the changed values. The dependency still received the nested value captured before that change.
