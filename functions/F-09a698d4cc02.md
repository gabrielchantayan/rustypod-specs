# F-09a698d4cc02

## Purpose

F-09a698d4cc02 performs an index-producing search through consecutive four-byte integer elements. It compares each admitted element with a supplied target and returns the index of the first observed match. If the current index is not admitted by a dynamically obtained unsigned bound, it returns the 32-bit failure value 4,294,967,295.

The bound is obtained from F-168d7d8f17dc before every potential element read. It is not captured once at entry. The element-storage pointer, by contrast, is loaded once before the first dependency call and is not subsequently reloaded.

The established behavior is therefore a search governed by repeated bound queries, not necessarily a search over a fixed-size, immutable collection. Treating the dependency as a collection-size accessor is inferred intent, not an established dependency contract.

## Interface

### Inputs

The function receives two integer-valued arguments:

- **Container address:** An address-bearing value identifying storage with a pointer-bearing field at byte offset 4.
- **Target:** The integer value to compare against each examined element.

The supplied representation supports a 32-bit integer model: elements occupy four bytes, the running index and bound comparison are unsigned, and the failure result is the all-ones 32-bit value. An independently verified calling convention, native pointer width, and byte order are not available.

### Relevant layout

Only the following layout is established:

| Location | Required interpretation |
|---|---|
| Container address plus 4 bytes | Storage from which the initial element pointer is loaded |
| Initial element pointer plus four times an admitted index | Four-byte integer element read for comparison |

No meaning is established for the first four bytes of the container or for any other container fields.

The address of the field at offset 4—not the element pointer loaded from that field—is passed to F-168d7d8f17dc.

The number of bytes occupied by the pointer-bearing field is not independently established. Its offset and its use as a pointer source are established.

### Output

The result is a 32-bit unsigned value:

- **0 through 4,294,967,294:** The index of a matching element.
- **4,294,967,295:** Search termination because the queried bound was less than or equal to the current index.

The failure value is not a distinct error object or exception. It does not distinguish an empty collection, exhaustion, a decreasing bound, or any other reason that the dependency returned a non-admitting bound.

### Preconditions for defined execution

The following conditions are required for the described behavior to complete normally:

- The pointer-bearing field at container offset 4 must be readable at entry.
- Forming that field address must be valid under the applicable address and integer-arithmetic rules.
- Every element actually examined must be readable as a four-byte integer through the captured pointer.
- Each pointer advance performed after a mismatch must be valid under the applicable pointer-arithmetic rules.
- F-168d7d8f17dc must accept the supplied field address and return normally for each call needed to reach the result.

No explicit validation establishes these conditions. The function does not provide a defined failure result for invalid addresses, inaccessible storage, or a dependency that fails to return.

## Behavior

### Entry and pointer capture

Before querying any bound, the function reads the pointer-bearing field at container offset 4 and captures its value. The running index begins at zero.

This initial pointer-field read occurs even if the first dependency call will return zero and no element will be examined. A zero bound therefore does not eliminate the requirement that the pointer field itself be readable.

The captured pointer determines the element sequence for the entire invocation. Later changes to the pointer field do not redirect the search.

### Per-position admission

Before each possible element comparison, the function calls F-168d7d8f17dc with the address of the field at container offset 4.

It interprets the dependency result as an unsigned bound and compares it with the current unsigned index:

- If the bound is less than or equal to the index, the function immediately returns 4,294,967,295.
- If the bound is greater than the index, the current element is read and compared with the target.

The dependency call and bound decision precede the corresponding element read. An element whose index is not admitted is not read by this function.

A bound value with its high bit set is a large unsigned value, not a negative bound. For example, the 32-bit all-ones bound admits index zero.

### Comparison and progress

For an admitted index, the function reads the integer at the current captured-storage position and compares it with the target.

If the values are equal, the function returns the current index immediately. It does not advance the pointer or call the dependency again.

If the values differ:

1. The traversal position advances by one four-byte element.
2. The unsigned index increases by one.
3. A new dependency call determines whether the next element may be read.

The equality comparison is exact integer equality, with no ordering, normalization, conversion to text, or approximate matching.

Only one pass is made through the admitted positions. Earlier positions are not revisited if the dependency changes the bound or mutates element contents.

### Stable-bound interpretation

If every dependency call returns the same bound and neither the dependency nor another actor changes the relevant elements, the function behaves as a conventional first-match search over indices starting at zero and strictly less than that bound.

For a successful result at index \(k\):

- The dependency has been called exactly \(k+1\) times.
- The function has read exactly \(k+1\) elements.
- Every earlier examined element differed from the target.

For an unsuccessful search with a stable bound \(n\), assuming all required memory operations are valid:

- The dependency is called \(n+1\) times.
- Exactly \(n\) elements are read.
- The final dependency call rejects index \(n\).

These counts describe calls and reads performed by F-09a698d4cc02. They do not include any operations performed internally by the dependency.

### Changing bounds and contents

Each dependency return independently controls admission at the current index. There is no saved original bound and no requirement that successive bounds agree.

Consequences include:

- A decreasing bound can terminate the search before a position that an earlier bound would have admitted.
- An increasing bound can admit later positions beyond an earlier returned bound.
- Once a bound rejects the current index, the function returns immediately. It does not retry in anticipation of later growth.
- A dependency mutation of an element can affect the comparison because the element is read after the dependency returns.
- A dependency mutation of the pointer-bearing field does not change the captured traversal pointer.
- A dependency that invalidates the captured storage can make a subsequent admitted read invalid.

A successful result identifies the first matching position among the positions as actually observed in order. It does not establish that the returned position is the first match in an entry-time or return-time snapshot.

### Integer limits

The admission rule prevents the index from wrapping during normal execution under the 32-bit unsigned model.

The largest possible bound is 4,294,967,295. Consequently:

- The largest index that can be admitted is 4,294,967,294.
- After a mismatch there, the index becomes 4,294,967,295.
- The next bound query must reject that index, regardless of its returned 32-bit value.

Thus the failure value cannot also be a successfully returned index.

This index property does not establish memory safety for very large bounds. The captured storage and every required pointer advance must still be valid. In particular, the pointer is advanced after a mismatch before the next bound query, even when that next query will terminate the search.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Except where mutation is explicitly described, assume readable storage, valid pointer arithmetic, a normally returning dependency, and unchanged element contents.

| Conditions | Required result and observations |
|---|---|
| The first bound is zero. | Return 4,294,967,295. Read the pointer field and call the dependency once; read no element. |
| The first bound is positive and the first element equals the target. | Return 0 after one dependency call and one element read. No subsequent bound query occurs. |
| Elements are 12, 25, and 38; every bound is 3; target is 25. | Return 1 after two dependency calls. Examine the first two elements only. |
| Elements are 12, 25, and 38; every bound is 3; target is 99. | Return 4,294,967,295 after four dependency calls and three element reads. The fourth call rejects index 3. |
| Elements are 7, 7, and 9; every bound is 3; target is 7. | Return 0. The later duplicate is not examined. |
| The first bound is 3; the first element mismatches; the second bound is 1. | Return failure at index 1 without reading the second element, even if that element would match. |
| The first bound is 1; the first element mismatches; the second bound is 3; the second element matches. | Return 1. The earlier bound of 1 is not retained as a fixed limit. |

Additional state-sensitive cases:

- **Pointer-field replacement:** If a dependency call replaces the container’s pointer field with a different array pointer and returns an admitting bound, the next comparison still uses the originally captured storage. This criterion is conditional on that original storage remaining valid.
- **Element mutation:** If a dependency call changes the next examined element to equal the target and admits the index, the subsequent read observes that changed value, provided the write is visible under the applicable execution model.
- **Unsigned bound:** A first bound of 4,294,967,295 admits index zero; it is not treated as a negative value or immediate failure.
- **All-ones target:** Under the 32-bit integer model, an admitted element with the same all-ones representation as a target value of negative one compares equal. The result is the element’s index, not the failure sentinel.
- **Rejected next position:** After a mismatch, the traversal pointer advances before the next dependency call. A rejecting next bound prevents another element read, but does not undo or eliminate that pointer advance.
