# F-8094c3d72052

## Purpose

F-8094c3d72052 returns a 32-bit Boolean-like result after evaluating a selected candidate and, conditionally, a fixed fallback candidate.

A candidate is accepted when both of these conditions hold:

- F-eac694802fc1 returns zero.
- A subsequent call to F-9316cc774c14 returns zero.

The second dependency is not called when the first returns nonzero. The fallback candidate is evaluated only when the selected candidate is not accepted.

The function returns **1** if either evaluated candidate is accepted. It returns **0** if both candidates are evaluated and neither is accepted.

“Candidate,” “selected,” and “fallback” describe the observable structure. The supplied material does not establish the application-level meaning of these objects or whether dependency results represent errors, comparisons, availability, or another condition.

## Interface

### Inputs

The function receives four arguments:

| Argument | Representation | Established use |
|---|---|---|
| Base | Address-bearing integer, modeled as 32 bits | Supplies the origin for selector, candidate, and fallback address calculations. Also initializes one mutable scratch cell. |
| Context | Opaque 32-bit value | Passed unchanged as the third argument to each invocation of F-81ba24aad07e. Also initializes a separate scratch cell. |
| Initial candidate | Address-bearing integer, modeled as 32 bits | Initializes the mutable scratch cell supplied to the first invocation of F-81ba24aad07e and the first invocation of F-eac694802fc1. |
| Initial companion | Opaque 32-bit value | Initializes another scratch cell. An explicit memory read replaces its value before the first invocation of F-eac694802fc1. |

The supplied representation explicitly identifies the opaque values and return value as four bytes. It represents addresses and address arithmetic using integers. The contract therefore uses a 32-bit address-bearing model, while the precise target ABI and language-level signed-overflow rules remain undocumented.

### Output

On normal completion, the function returns exactly one of:

- **1:** the selected candidate or the fallback candidate was accepted.
- **0:** neither candidate was accepted.

No other normal return value is visible.

There is no explicit output-buffer argument. Dependencies receive addresses of mutable local storage, so they can affect subsequent evaluation through that storage.

### Required storage

The following byte offsets are relative to Base:

| Offset or calculation | Access |
|---|---|
| `0x54` / 84 | Read as a 32-bit selector, on two separate occasions during selected-candidate processing. |
| Base plus selector × `0x1c` / 28 | Passed as the selected-candidate address to F-81ba24aad07e. |
| Base plus selector × 28 plus `0x10` / 16 | Read as a 32-bit companion value after that dependency returns. |
| `0x38` / 56 | Passed as the fallback-candidate address to F-81ba24aad07e, if fallback evaluation is reached. |

These accesses establish an address calculation with a 28-byte stride. They do **not** establish an allocation size, array length, object type, valid selector range, or complete record layout.

For normal completion, each explicitly reached read must address readable storage under the target’s access rules. Each dependency must also receive storage valid for its own requirements, which are not supplied.

## Behavior

### Initial state

Before any dependency call, the function initializes four mutable, 32-bit local values from the four arguments.

Two are used for selected-candidate processing:

- A candidate cell initialized from Initial candidate.
- A companion cell initialized from Initial companion.

Two are used for fallback processing:

- A candidate cell initialized from Base.
- A companion cell initialized from Context.

These names identify roles, not externally defined structures. The evidence does not establish a public aggregate layout, permissible cross-cell access, or a dependency’s authority to read beyond the particular cell whose address it receives.

### Selected-candidate preparation

The function reads the 32-bit selector at Base plus 84. It calculates a selected address by multiplying that selector by 28 and adding Base.

It then calls F-81ba24aad07e with:

1. The address of the selected candidate cell.
2. The calculated selected address.
3. The original Context argument.

The dependency’s return value is not used by this function. Its effects can still matter: in particular, it receives mutable access to the candidate cell.

After this call returns, the function **reads the selector again** from Base plus 84. It calculates an address from that newly read selector using the same 28-byte stride, adds 16, and reads a 32-bit companion value there. This read replaces the selected companion cell’s current value.

The two selector reads are not interchangeable. A dependency can potentially alter the selector or the storage from which it is read. Consequently:

- The address passed to F-81ba24aad07e can correspond to one selector value.
- The companion value subsequently loaded can correspond to a different selector value.

No stability check or consistency repair is visible.

### Selected-candidate evaluation

The function calls F-eac694802fc1 with the addresses of the selected candidate cell and selected companion cell.

Its return is interpreted only as zero versus nonzero:

- **Nonzero:** the selected candidate is not accepted, and fallback processing begins immediately. F-9316cc774c14 is skipped for this candidate.
- **Zero:** the function calls F-9316cc774c14.

For that latter call, the argument is the **current value of the selected candidate cell plus 20 bytes**. It is not necessarily Initial candidate plus 20, nor the selected address previously calculated from Base.

Both preceding dependencies received the address of the selected candidate cell. If either changed it, the updated value is used.

The result from F-9316cc774c14 is also interpreted only as zero versus nonzero:

- **Zero:** the selected candidate is accepted. The function returns 1 without evaluating the fallback.
- **Nonzero:** the selected candidate is not accepted, and fallback processing begins.

### Fallback preparation

When fallback processing is reached, the function calls F-81ba24aad07e with:

1. The address of the fallback candidate cell, initially seeded with Base.
2. Base plus 56.
3. The original Context argument.

The third argument is not taken from the mutable fallback companion cell.

After the dependency returns, the function reads a 32-bit value at Base plus 72 and writes it into the fallback companion cell. This load is unconditional once the fallback preparation call has returned.

The fallback companion read uses a fixed offset. It does not consult the selector.

### Fallback evaluation

The function calls F-eac694802fc1 with the addresses of the fallback candidate and companion cells.

- If it returns nonzero, the function returns 0 immediately. F-9316cc774c14 is skipped for the fallback.
- If it returns zero, the function calls F-9316cc774c14 with the current fallback candidate value plus 20.

The final dependency result determines the normal return:

- Zero produces 1.
- Nonzero produces 0.

There is no third candidate, retry, or visible recovery path.

### Arithmetic and boundaries

The explicitly visible address calculations use:

- A 32-bit selector interpreted as an integer.
- A stride of 28 bytes.
- Fixed offsets of 16, 20, 56, 72, and 84 bytes.

There is no visible check for:

- Negative selectors.
- Selectors outside an allocation.
- Overflow in selector multiplication.
- Overflow in address addition.
- Null or otherwise invalid base or candidate values.
- Read alignment.
- Candidate values changed to invalid addresses by dependencies.

The supplied representation is insufficient to define portable behavior when signed arithmetic overflows or an address calculation leaves valid storage. Such cases are **documented_only**, not assigned a successful result or a particular failure mode.

## Side effects

### Explicit memory activity

Outside dependency calls, the function visibly:

- Initializes and updates local 32-bit scratch storage.
- Reads the selector twice.
- Reads one selected companion value.
- Conditionally reads one fallback companion value.

It contains no explicit write to Base-relative storage.

This does not imply that the overall operation is read-only. Dependencies may modify supplied storage, other reachable memory, or global state.

### Observable ordering

For normal execution, the selected-candidate operations occur in this order:

1. First selector read.
2. F-81ba24aad07e.
3. Second selector read and selected companion read.
4. F-eac694802fc1.
5. F-9316cc774c14, only if the preceding result was zero.

If needed, fallback operations follow:

1. F-81ba24aad07e.
2. Fallback companion read.
3. F-eac694802fc1.
4. F-9316cc774c14, only if the preceding result was zero.

The maximum normal call counts are two per dependency. F-9316cc774c14 may be called zero, one, or two times.

The caller does not visibly restore dependency-modified memory, undo selected-candidate effects before fallback, or roll back effects before returning 0.

### Ownership and lifetime

The function performs no explicit allocation, deallocation, ownership transfer, or resource release.

It passes addresses of its local storage to dependencies. Those cells are available during the invocation; retaining their addresses for use after return has no established validity.

Dependency ownership behavior is unknown. In particular, the evidence does not establish whether a dependency allocates memory, releases an object identified by a candidate value, retains pointers, or modifies shared state. Neither a return of 0 nor a return of 1 proves that any resource remains owned or live.

### Errors and abnormal completion

The function exposes no separate error code. It reduces dependency results to zero/nonzero branch conditions, without preserving their original values.

There is no visible handling for invalid memory accesses or dependency failures that do not return normally. If a dependency aborts, faults, or otherwise does not return, the function’s subsequent reads and return are not established.

## Acceptance examples

These are conditional contract examples, not runtime observations. They assume valid reached memory accesses and normally returning dependencies.

1. **Selected candidate succeeds.**  
   The first F-eac694802fc1 returns zero, and the following F-9316cc774c14 returns zero. The result is 1. No fallback preparation or fallback companion read occurs.

2. **Immediate selected rejection, successful fallback.**  
   The first F-eac694802fc1 returns any nonzero integer. The selected F-9316cc774c14 call is skipped. If fallback F-eac694802fc1 and F-9316cc774c14 both return zero, the result is 1.

3. **Selected post-check rejects, fallback also rejects immediately.**  
   Selected F-eac694802fc1 returns zero, selected F-9316cc774c14 returns nonzero, and fallback F-eac694802fc1 returns nonzero. The result is 0. No fallback F-9316cc774c14 call occurs.

4. **Both post-checks reject.**  
   Each F-eac694802fc1 returns zero, and each F-9316cc774c14 returns nonzero. Both candidates are fully evaluated, and the result is 0.

5. **The selector changes during preparation.**  
   If the first selector read yields 2, the selected preparation address is Base plus 56. If that dependency changes the selector to 4, the subsequent companion read is at Base plus 128: 4 × 28 + 16. The function does not force that read back to the record selected initially.

6. **Evaluation changes the candidate value.**  
   If F-eac694802fc1 changes the selected candidate cell to an address Q and returns zero, the next dependency receives Q plus 20. It does not receive the original candidate value plus 20.

7. **Selected and fallback addresses coincide.**  
   With a first selector value of 2, selected preparation uses Base plus 56, the same address used by fallback preparation. If fallback is reached, the function still performs the fallback calls. It does not deduplicate them. Distinct scratch state and dependency side effects mean equal source addresses do not establish equivalent outcomes.
