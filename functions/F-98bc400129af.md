# F-98bc400129af

## Purpose

F-98bc400129af searches a linked, tree-shaped representation using an opaque comparison dependency. It then either returns a candidate value from local storage or invokes a separate processing dependency and returns that dependency’s result.

The caller-visible result consists of:

- A 32-bit word at output offset `+0`.
- A one-byte discriminator at output offset `+4`.

Discriminator zero identifies the path that returns the candidate-slot value without invoking F-896114e013fb. Discriminator one identifies a path that invokes F-896114e013fb. Neither value establishes allocation success, ownership transfer, or a particular structural modification.

The apparent intent is tree insertion with mode-dependent duplicate suppression. That interpretation is inferred. The established behavior is the sequence of reads, dependency calls, branches, and writes below.

## Interface

The function has three logical arguments:

The incoming operand’s meaning is unknown: it may represent an address, key, handle, or immediate value.

### Preconditions and limits

Defined, terminating execution requires:

- Writable output storage covering the two explicit writes.
- A readable container and a valid header-like object at each header dereference.
- Valid node and parent-like pointers wherever the selected path dereferences them.
- Dependency-compatible arguments.
- Links and dependency behavior that permit all selected walks to terminate.

The function explicitly checks traversal and some adjustment links against null. Those checks control descent or adjustment; they do not constitute general pointer validation. In particular, the function does not validate the required container or header address before dereferencing it, and the parent-chain adjustment has no separate null termination check.

There is no explicit bounds checking, cycle detection, or structural consistency validation.

No general non-aliasing contract is established. Output overlapping container or node storage may alter that storage at completion. Such overlap is not demonstrated to be supported.

## Behavior

### Initial reads and search

The remembered comparison result starts at the nonzero value one.

The function first:

1. Reads the header pointer from container offset `+0x10`.
2. Reads the initial traversal pointer from that header’s `+0x04` field.
3. Separately reads container offset `+0x10` again to initialize the remembered attachment candidate.

Thus, an initially null traversal pointer skips all search comparisons. The fallback attachment candidate comes from the second header-pointer read, and the remembered comparison result remains nonzero.

For each non-null traversal node:

- Two internal 32-bit temporary words are cleared.
- F-bcefa5957e76 is called with the comparison-context address, the incoming operand, and the current node address plus `0x10`.
- The current node becomes the remembered attachment candidate.
- The next traversal pointer is read from the current node:
  - `+0x0c` if the comparison result is zero.
  - `+0x08` if the comparison result is nonzero.

The selected link is read after the comparison call. A dependency can therefore affect the link subsequently used for descent.

The search ends when the selected traversal pointer is null. There is no separate equality outcome: comparison results are classified only as zero or nonzero.

### Mode selection

After the search, the function reads the byte at container offset `+0x18`.

- Nonzero mode proceeds directly to the common F-896114e013fb call.
- Zero mode initializes a local candidate slot with the remembered attachment candidate and enters candidate checking.

Because mode is read after the search comparisons, changes made by those dependencies can affect this branch.

### Boundary processing in zero mode

If the final remembered search comparison is zero, boundary processing and candidate adjustment are skipped.

If the remembered comparison is nonzero, the function:

1. Reloads the header pointer from container offset `+0x10`.
2. Reads the word at that header’s `+0x08`.
3. Stores that word in an internal boundary slot.
4. Calls F-54610eed0112 with the address of the candidate slot and the address of the boundary slot.

Both arguments are addresses of mutable storage. Neither slot’s preservation is established.

A nonzero return from F-54610eed0112 immediately selects an F-896114e013fb call. Its arguments are:

- An internal 32-bit result-slot address.
- The container address.
- Literal zero.
- The original remembered attachment candidate.
- The incoming operand.

After normal return, the result-slot word is written to output `+0`, then one is written to output `+4`. No candidate extraction or final comparison occurs on this path.

A zero return selects candidate adjustment using the candidate slot’s value after F-54610eed0112 returns.

### Candidate adjustment

Adjustment first reads the byte at offset `+0x00` of the candidate identified by the slot.

If that byte is zero, the function reads the candidate’s `+0x04` pointer and then reads the referenced object’s `+0x04` pointer. If this second pointer equals the candidate, the candidate slot is replaced with the candidate’s `+0x0c` pointer, and adjustment ends.

If the byte is nonzero, or the zero-byte case does not satisfy that pointer equality, adjustment follows the other branch:

- The candidate’s `+0x08` pointer is loaded.
- The same field is read again for the null test.

When that null test is false, the function enters the subtree using the first loaded pointer. At each iteration, it stores the current node into the candidate slot, loads that node’s `+0x0c` pointer, and separately rereads `+0x0c` for the continuation test. With stable links, the terminal node whose `+0x0c` is null remains in the candidate slot.

When the `+0x08` null test is true, adjustment ascends:

- It reads the candidate’s `+0x04` parent-like pointer.
- It compares that parent’s `+0x08` pointer with the candidate-slot value.
- It stores the parent into the candidate slot regardless of the comparison outcome.
- If equal, it advances through the parent’s `+0x04` pointer and repeats.
- If unequal, adjustment ends with the parent just examined in the candidate slot.

There is no independent stop-at-null condition in this ascent. A malformed chain can fault or fail to terminate.

These operations resemble predecessor selection in a sentinel-based tree. That interpretation is not required by the established pointer behavior.

### Final candidate comparison and output reread

Unless boundary processing already selected immediate processing, zero mode next performs:

1. A read of the candidate slot to obtain the argument for F-21bc8dd43451.
2. A call to F-21bc8dd43451, returning an opaque 32-bit value.
3. A call to F-bcefa5957e76 with the comparison-context address, that returned value, and the incoming operand.

If this comparison is nonzero, execution proceeds to the common processing call.

If it is zero, the function **reads the candidate slot again**, writes that current value to output `+0`, and writes zero to output `+4`.

The extraction argument and output word are not unconditionally the same pointer. On the boundary path, F-54610eed0112 has received the candidate slot’s address. Its retention of that address is not excluded. A later extraction or comparison dependency could modify the still-live slot through a retained address or other dependency interaction.

Consequently:

- The extraction argument is the slot value read before F-21bc8dd43451.
- The zero-discriminator output word is the slot value read after the final comparison returns.
- Equality between those values requires a preservation assumption not established by this body.
- No new extraction or comparison is performed merely because the slot changed.

### Common processing call

The common F-896114e013fb call is selected when:

- The mode byte is nonzero; or
- Zero mode reaches a nonzero final candidate comparison.

It receives:

- An internal 32-bit result-slot address.
- The container address.
- Literal zero.
- The original remembered attachment candidate.
- The incoming operand.

The adjusted candidate slot does not replace the original attachment argument.

After normal return, the function copies the result-slot word to output `+0`, then writes one to output `+4`.

The common result slot is also used as the boundary-word slot on paths that perform boundary processing. Its prior contents therefore depend on the executed path and dependency effects. Search iterations clear it, but an initially empty search performs no such clearing. The function supplies no universal zero fallback if F-896114e013fb does not initialize its result.

### Completion and interruption

On every visible normal completion path, the 32-bit output write precedes the discriminator-byte write.

No completed result is established if a dependency fails to return normally, a memory access faults, or a walk does not terminate. There is no local rollback or error-recovery branch.

## Side effects

### Direct writes

The function explicitly writes:

- Internal temporary storage, including storage passed by address to dependencies.
- One 32-bit output word.
- One output discriminator byte.

It does not directly rewrite container fields, node links, or node payloads.

### Dependency-mediated effects

Dependency calls may modify accessible state. The function establishes no general preservation guarantee for globals, container memory, node memory, or shared dependency state.

F-54610eed0112 can modify either passed slot. The source also does not exclude its retaining those addresses for use while the slots remain live. This matters both for later candidate reads and for the boundary slot’s later reuse as processing-result storage.

Passing temporary storage by address does not establish ownership transfer or permission to use that storage after its lifetime ends.

No allocation, release, reference-counting, borrowing, or object-lifetime contract can be assigned to the incoming operand or returned word from this function alone.

### Errors and success interpretation

There is no explicit local error code.

Discriminator one means F-896114e013fb was invoked and returned normally far enough for the output writes. It does not prove insertion or allocation succeeded.

Discriminator zero means the final comparison returned zero and the candidate slot was subsequently copied. It does not independently establish key equality or the continued identity of the extraction argument.

## Acceptance examples

These are conditional static acceptance examples, not runtime observations. Unless stated otherwise, they assume valid memory, stable links during adjustment, terminating walks, and normally returning dependencies.

### Populated search with nonzero mode

Suppose three nodes are visited and mode is nonzero when read.

- Three search comparisons occur.
- Zero results select `+0x0c`; nonzero results select `+0x08`.
- Neither F-54610eed0112 nor F-21bc8dd43451 is called.
- F-896114e013fb receives the third visited node as attachment.
- Its result-slot word is written before discriminator one.

### Initially empty search

Suppose the initial traversal pointer is null and mode is nonzero.

- No search comparison occurs.
- The attachment argument is the header pointer obtained by the separate fallback read.
- F-896114e013fb is called once.
- Discriminator one is written.
- The result word depends on the result slot’s contents after that call, not on guaranteed local zero initialization.

### Zero final search comparison

Suppose the final search comparison is zero and mode is zero.

- Boundary processing and adjustment are skipped.
- F-21bc8dd43451 receives the candidate-slot value initially set to the last visited node.
- A zero final comparison causes a fresh candidate-slot read for output, followed by discriminator zero.
- If the slot is preserved through both calls, the output word is the last visited node’s pointer.
- A nonzero final comparison instead selects F-896114e013fb with the original attachment.

### Boundary-directed processing

Suppose zero mode follows a nonzero remembered search result, and F-54610eed0112 returns nonzero.

- The boundary word comes from the reloaded header’s `+0x08`.
- Extraction and final comparison are skipped.
- F-896114e013fb receives the original attachment, regardless of changes to the candidate slot.
- Its result word is returned with discriminator one.

### Adjusted candidate with slot preservation

Suppose boundary processing returns zero, adjustment selects a different node, and the final comparison returns zero. Assume the candidate slot is preserved during extraction and comparison.

- F-21bc8dd43451 receives the adjusted node.
- The output word is that node’s pointer.
- The discriminator is zero.
- F-896114e013fb is not called.

### Candidate slot changed after extraction

Suppose F-54610eed0112 retains the candidate-slot address and returns zero. Adjustment leaves value A in the slot, so extraction receives A. During a later dependency call, the still-live slot is changed to B, and the final comparison returns zero.

- The output word is B, as read after the comparison.
- The discriminator is zero.
- No extraction or comparison of B is required by this path.
- No dereference of B is required merely to copy it to output.

### Adjusted candidate rejected

Suppose adjustment selects a node different from the original attachment and the final comparison is nonzero.

F-896114e013fb receives the original attachment, not the adjusted candidate. Its result-slot word is returned with discriminator one.

### Noncanonical nonzero results

A comparison result of two or a negative nonzero 32-bit value selects the same branch as one. No sign-based or three-way ordering decision is made.
