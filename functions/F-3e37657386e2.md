# F-3e37657386e2

## Purpose

F-3e37657386e2 prepares a caller-provided output buffer using one of two layouts and, for supported operation selectors, writes a corresponding 32-bit size value to a separate output location.

The layout family is selected by a 16-bit value read at byte offset 2 from the first argument. A value of `0x482B` selects the matching-marker family; every other value selects the alternate family. Within either family, only selectors 1 and 2 reach the final size write.

This is a source-derived behavioral contract. The supplied static representation establishes the explicit accesses, dependency calls, and their order. It does not establish the semantics of the external buffer operation or the internal behavior of any dependency. In particular, the initial buffer operation must not be treated as proven zero-initialization.

## Interface

The function accepts six arguments and has no explicit return value.

| Argument | Role | Established width or interpretation |
|---|---|---|
| Source reference | Base address used for the marker read; also passed to a dependency in the matching-marker family | Address-like argument. A 16-bit read occurs at byte offset 2. |
| Operation selector | Chooses the output variant | 32-bit integer in the supplied representation. Only exact values 1 and 2 are supported by the visible branches. |
| Context value | Passed to a dependency and copied into matching-marker outputs | Opaque 32-bit value |
| Output buffer | Destination for the initial external operation and subsequent layout writes | Address supporting 16-bit and 32-bit accesses at the offsets described below |
| Size destination | Receives the selected output size on supported paths | Address of a writable 32-bit location |
| Supplied value | Copied directly or passed to a conversion dependency, depending on the layout | Opaque 32-bit value |

Argument roles do not establish ownership or a higher-level type. In particular, the context and supplied values may encode addresses, handles, numbers, or other data; the visible function does not distinguish these possibilities.

### Memory and execution preconditions

For an execution to complete without invalid accesses:

- The initial external operation must be able to accept the output-buffer address and the integer `0x208`, decimal 520.
- When reached, the marker read must be valid at source byte offsets 2–3.
- All reached explicit output writes and dependency accesses must be valid.
- The size destination must be writable for four bytes if the final size write is reached.
- Alignment and address-representation requirements must match the target execution environment.

A caller should not infer the required output-buffer capacity from the final size value alone. The initial external operation receives 520 before the layout is selected, and its actual access extent is undocumented. Conversion dependencies also have undocumented destination extents.

There are no visible null checks, capacity checks, overlap checks, or dependency-status checks.

## Behavior

### Common entry sequence

Every invocation first calls an unidentified external dependency with:

1. The output-buffer address.
2. The integer `0x208`.

Only after that call returns does the function read the 16-bit marker at source byte offset 2.

This order matters when memory overlaps or the external operation has broader side effects. The marker is the value observed after the external call, not necessarily the value present at function entry.

No explicit clearing, filling, or copying semantics can be assigned to that external call from the supplied evidence.

### Matching-marker family

If the observed marker equals `0x482B`, the function:

1. Calls F-49743e74136c with no explicit arguments and retains its 32-bit result.
2. Calls F-7103344f7722 with the source reference and context value, in that order.
3. Examines the operation selector.

Both dependency calls occur even when the selector is unsupported.

For the following descriptions, “captured value” means the result already returned by F-49743e74136c. Later calls do not cause this function to obtain that result again.

#### Selector 1

The function performs these explicit output-buffer writes in order:

| Order | Byte offset | Width | Value |
|---|---:|---:|---|
| 1 | 0 | 16 bits | `0x0001` |
| 2 | 12 | 32 bits | Captured value |
| 3 | 8 | 32 bits | Supplied value |
| 4 | 16 | 32 bits | Captured value |
| 5 | 24 | 32 bits | Captured value |
| 6 | 20 | 32 bits | Captured value |
| 7 | 80 | 32 bits | Context value |

It then writes `0x58`, decimal 88, as a 32-bit value to the size destination.

The explicit buffer writes are not performed in ascending address order. In particular, the write at offset 24 precedes the write at offset 20.

#### Selector 2

The function first performs these explicit writes:

| Order | Byte offset | Width | Value |
|---|---:|---:|---|
| 1 | 0 | 16 bits | `0x0002` |
| 2 | 12 | 32 bits | Captured value |
| 3 | 8 | 32 bits | Supplied value |
| 4 | 16 | 32 bits | Captured value |
| 5 | 24 | 32 bits | Captured value |
| 6 | 20 | 32 bits | Captured value |

It next reads the 16-bit field at output byte offset 2, sets mask `0x0002`, and writes the resulting 16-bit value back to the same location. All other bits of the value observed by this read are retained.

It then writes the 32-bit context value at output byte offset 80 and finally writes `0xF8`, decimal 248, as a 32-bit value to the size destination.

The field at offset 2 is not unconditionally assigned the value 2. That outcome requires its other bits to be clear when the read occurs.

#### Unsupported selector

For any selector other than 1 or 2, the function returns after the two family-specific dependency calls.

It performs none of the layout writes listed above and does not explicitly write the size destination. The initial external operation and both dependencies have nevertheless already run.

### Alternate family

If the marker does not equal `0x482B`, the function calls F-a6d8da5ce64b with the integer argument 1 and retains its 32-bit result. It then examines the selector.

This dependency call occurs even for unsupported selectors.

#### Selector 1

The function writes the 16-bit value `0x0100` at output byte offset 0.

It then calls F-946cac4b59bc three times, in this order:

| Call | First argument | Second argument |
|---|---|---|
| 1 | Supplied value | Output address at byte offset 6 |
| 2 | Captured result from F-a6d8da5ce64b | Output address at byte offset 10 |
| 3 | The same captured result | Output address at byte offset 14 |

The destination addresses are four bytes apart. That spacing does not establish the number of bytes each call reads or writes, nor does it prove the destination regions are disjoint.

After all three calls return, the function writes `0x46`, decimal 70, as a 32-bit value to the size destination.

There is no visible inspection of dependency results before proceeding. The visible function does not establish that these calls are pure conversions, that they preserve earlier output fields, or that they leave global state unchanged.

#### Selector 2

The function performs these explicit output writes in order:

| Order | Byte offset | Width | Value |
|---|---:|---:|---|
| 1 | 0 | 16 bits | `0x0200` |
| 2 | 44 | 32 bits | Captured result from F-a6d8da5ce64b |
| 3 | 20 | 32 bits | Supplied value |
| 4 | 48 | 32 bits | Captured result from F-a6d8da5ce64b |

It then writes `0x66`, decimal 102, as a 32-bit value to the size destination.

No call to F-946cac4b59bc occurs on this path.

#### Unsupported selector

For any selector other than 1 or 2, the function returns after F-a6d8da5ce64b returns.

No explicit layout write or size-destination write occurs. The initial external operation has still run.

### Widths, layout, and arithmetic

All offsets above are byte offsets, including destinations passed to dependencies.

The marker, leading layout field, and selector-2 flag field use 16-bit accesses. Captured results, directly copied input values, and the final size use 32-bit accesses. There is no visible truncation of a 32-bit input into an explicitly written 16-bit field.

The marker comparison is against a positive value representable in a signed 16-bit quantity. Its result does not depend on whether that particular value is interpreted as signed or unsigned.

The function does not derive sizes arithmetically from input values. Its four final sizes are fixed constants. Its only explicit bit transformation is the 16-bit OR with `0x0002`.

Byte order is not established. For example, a numeric 16-bit write of `0x0100` must not be specified as a particular two-byte sequence without an additional target-endianness contract.

## Side effects

The function directly modifies caller-supplied memory and invokes dependencies that may have additional effects.

The final size write happens after all explicit layout operations on each supported path. If the size destination overlaps the output buffer, that final write can overwrite previously produced output bytes. No overlap prevention is visible.

Other aliasing can also affect results:

- Overlap between the source and output buffer can allow the initial external operation to affect the marker subsequently read.
- Dependencies receiving a source or output address may modify memory that later operations observe.
- In matching-marker selector 2, the flag update preserves the other bits present at the time of its read, regardless of how those bits were produced.

The function contains no visible allocation, deallocation, reference-count adjustment, or ownership-transfer operation. This does not establish the absence of such behavior inside dependencies.

There is no explicit error result and no rollback. Unsupported selectors are silent early-return paths, not side-effect-free rejection paths. Faults, non-returning dependencies, or other abnormal dependency behavior are not handled by the visible function.

## Acceptance examples

These are conditional static acceptance cases, not reports of executed tests.

### Matching marker, selector 1

Assume the marker read observes `0x482B`, all reached calls return normally, and the size destination is disjoint from the output buffer. Let F-49743e74136c return a particular 32-bit value.

The explicit writes must put that same captured value at offsets 12, 16, 24, and 20; the supplied value at offset 8; and the context value at offset 80. The leading 16-bit field must be assigned 1. The size destination must finally receive 88.

This case does not establish contents in gaps between written fields.

### Matching marker, selector 2 with existing flags

Assume the 16-bit field at output offset 2 contains `0x0040` when the flag read occurs. The function must write `0x0042` back to that field.

If it instead contains `0xFFFF`, the resulting field remains `0xFFFF`. The operation sets a bit; it does not replace the entire field with 2.

The final size write must be 248.

### Alternate marker, selector 1

Assume the marker read observes any value other than `0x482B`, and dependencies return normally.

F-a6d8da5ce64b must receive 1 before any conversion call. F-946cac4b59bc must then receive the supplied value with destination offset 6, followed by the captured result with destination offset 10, followed by that same result with destination offset 14. The final size write must be 70.

The bytes produced by those three calls cannot be accepted or rejected under this contract alone.

### Alternate marker, selector 2

Under normal completion, the explicit leading field must be `0x0200`; the captured result must be written at offsets 44 and 48; and the supplied value must be written at offset 20. The final size must be 102.

### Unsupported selector

For selector 0, the initial external call still occurs. If the marker matches, both matching-family dependencies still occur; otherwise, F-a6d8da5ce64b still receives 1.

No explicit size write occurs. If dependencies and aliases do not affect the size destination, its entry value remains unchanged. Unconditional preservation of that location is not established.
