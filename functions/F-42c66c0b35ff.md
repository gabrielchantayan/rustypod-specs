# F-42c66c0b35ff

## Purpose

F-42c66c0b35ff performs a fixed sequence of three dependency calls and four direct memory stores. It passes the constant 252 to the first dependency, passes that dependency’s result and the first input to the second, installs a global-sourced 32-bit value at the second dependency’s returned address, and invokes the third dependency with an address displaced by 192 bytes. Three fields are then written relative to the third dependency’s returned address.

The established contract concerns call ordering, argument values, a global read, address calculations, and exact-width stores. Allocation, object construction, and initialization of an embedded component are plausible interpretations, not established guarantees.

There is no explicit return value. Observable results are the direct memory effects and whatever effects the dependencies produce. The two addresses used for stores need not be equal, disjoint, or related by the displacement supplied to the third dependency.

### Layout and complete direct-write footprint

The final three stores write field-relative bytes 48–51, 54–55, and 56. They do not themselves write bytes 52–53, bytes 0–47, or bytes beyond 56.

That limitation applies only to those three stores. The earlier four-byte store at the primary address remains part of the function’s direct-write footprint.

The complete direct-write footprint is the union of:

- Four bytes beginning at the primary address.
- Field-relative bytes 48–51.
- Field-relative bytes 54–55.
- Field-relative byte 56.

No established relationship between the primary and field addresses excludes overlap. For example:

- If the addresses are equal, the earlier store writes field-relative bytes 0–3.
- If the primary address is 52 bytes beyond the field address, the earlier store writes field-relative bytes 52–55. The later 16-bit store replaces bytes 54–55.
- If the primary address is 60 bytes beyond the field address, the earlier store writes field-relative bytes 60–63, beyond the final stores’ extent.

Dependencies may write additional memory. Absence from the direct-write footprint does not establish preservation of entry contents across the whole call.

## Side effects

### Direct reads and writes

The visible direct effects are one global-sourced 32-bit read and four stores. The global installation occurs between the second and third calls; the remaining stores follow the third call.

The third dependency may overwrite the initial installation. Later stores may also overlap it, depending on the address relationship. There is no second installation of the global value after the third dependency returns. Consequently, the primary address need not still contain that value at function return.

No separation between destination memory and the global source is established. If a destination overlaps global storage, the corresponding write may change that global’s contents.

### Ownership, lifetime, and publication

The function contains no explicit release operation and returns no explicit ownership result. It does not establish whether any dependency allocates, retains, transfers, publishes, or releases memory.

The first dependency’s result, primary region, and field region may refer to one resource, overlapping resources, or separate resources. Their ownership and lifetime remain unresolved.

Absence of an explicit release is not evidence of either a leak or correct cleanup elsewhere.

### Failures and partial effects

There is no visible error detection, rollback, cleanup, or translation of dependency failure into a status result.

If a dependency does not return normally, subsequent operations are not reached through the shown sequence. A normally returning dependency result is used without a visible failure-value check.

Invalid accesses or arithmetic may fault or have other target-specific consequences; the supplied representation does not define them. Earlier effects are not explicitly undone. Failure during the final stores can leave earlier stores completed, and the representation does not establish atomic completion of an individual multibyte access.

No transactional or all-or-nothing guarantee is supported.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume normal dependency returns, valid non-wrapping calculations, valid accesses, and no interfering activity.

### Distinct destination regions

Suppose the primary and field addresses designate separate writable regions.

The dependencies must be invoked in the stated order with request 252 and constant third argument 1. The global installation must precede the third call. The final stores must target the returned field address even when it differs from the primary address plus 192 bytes.

### Returned field address matches the supplied address

Suppose the field address equals the primary address plus 192 bytes.

The final stores must target primary-relative bytes 240–243, 246–247, and 248. They must not be broadened to clear bytes 244–245.

Preservation of those two bytes across the whole function still depends on dependency effects.

### Allocation containment requires the matching base

Suppose 252 requests a 252-byte allocation, but F-64d3c0a71540 returns an address different from that allocation’s base. Even if the field address equals the primary address plus 192 bytes, containment within the original allocation cannot be concluded without the missing address relationship.

If instead the primary address is established to be that same allocation’s base, and all calculations are valid and non-wrapping, the direct writes occupy only allocation-relative bytes 0–3, 240–243, 246–247, and 248. That conditional conclusion does not constrain dependency writes.

### Equal primary and field addresses

Suppose both returned addresses are equal.

The earlier store writes field-relative bytes 0–3. The later stores still target bytes 48–51, 54–55, and 56. A whole-function claim of no direct writes below field offset 48 would fail this case.

### Earlier store overlaps the gap

Suppose the primary address is 52 bytes beyond the field address and the third dependency leaves the installation intact.

The earlier store writes bytes 52–55 relative to the field address. The later 16-bit store replaces bytes 54–55. Bytes 52–53 are not written by the final three stores, but they do not retain their entry contents merely because they are in that gap.

### Global changed by a dependency

Suppose F-64d3c0a71540 changes the global source before returning.

The installation must use the value read after that return. A value captured before the dependency sequence would not satisfy the contract.

### Exact-width field values

Suppose the third input is 0x11223344 and the fourth is 0xA1B2.

After the final stores, the field at offset 48 represents the specified 32-bit value, the field at offset 54 represents the specified 16-bit value, and byte 56 is zero. No particular ordering of the multibyte values’ constituent bytes is required without target-endianness evidence.

### Third dependency replaces the installation

Suppose F-9563b8df22d3 overwrites the four bytes at the primary address.

The function does not reinstall the global value afterward. Final contents there depend on the dependency’s write and any overlap with the subsequent stores.
