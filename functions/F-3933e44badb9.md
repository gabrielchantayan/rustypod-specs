# F-3933e44badb9

## Purpose

F-3933e44badb9 performs a fixed visible sequence of indirect calls and memory accesses. Call results supply addresses, stored values, and arguments to subsequent calls. The explicit memory operations comprise **seven 32-bit stores, one 32-bit load, two 8-bit loads, and two 8-bit stores**.

No application-level purpose is established. The address scales and repeated offsets do not, by themselves, identify an array, object layout, allocation scheme, serialization format, or device protocol.

The supplied representation includes an instruction-recovery warning and ends at an invalid-instruction boundary rather than a visible normal return. This contract distinguishes:

- **Established static evidence:** operations, data dependencies, and ordering explicitly represented.
- **Conditional interpretation:** results that depend on interpreting arithmetic as 32-bit machine operations.

No runtime tests have been performed.

## Behavior

### Call-site identity

Opaque identifiers **F-D01** through **F-D50** identify indirect call sites in execution order. They do not establish 50 distinct implementations.

“No explicit arguments” describes the recovered call expression only. It does not establish the absence of implicit register, stack, or global inputs.

The following ordering applies only while execution continues through the represented path.

### Initial payload placement

F-D01 is invoked using the target derived from the incoming return-link value plus 4094. Its result is A.

Before any subsequent call, the body writes R as a 32-bit word at S(A) + 20. F-D02 then receives S(A). F-D03, F-D04, and F-D05 follow, each with no explicit arguments. F-D06 follows them and supplies B.

There is no visible validation between obtaining A and performing the store. F-D02 occurs after the store, not before it.

### Propagation through B and C

The body forms S(B), writes that value at W(B) + 20, and passes S(B) to F-D07.

F-D08, F-D09, and F-D10 then execute with no explicit arguments. F-D11 supplies C. The body writes the previously formed S(B) at S(C) + 20 and passes S(C) to F-D12.

F-D13, F-D14, and F-D15 follow with no explicit arguments. F-D16 supplies D.

The two stores in this phase have different destination scales: sixteen times B versus four times C. Their addresses need not describe related storage.

### Word capture and shifted propagation

The body forms S(D) and writes it at W(D) + 20. It then immediately reads Q as an unsigned 32-bit word from S(D) + 20, with no intervening call.

These accesses generally target different locations. The loaded Q must not be replaced with S(D) merely because the store precedes the load.

F-D17 receives S(D). F-D18, F-D19, and F-D20 follow with no explicit arguments. F-D21 supplies E.

The body writes Q logically shifted right by 12 bits at S(E) + 20, then invokes F-D22 with S(E). F-D23, F-D24, and F-D25 follow with no explicit arguments. F-D26 supplies F.

Q is captured before F-D17 through F-D21 execute. Under the recovered dataflow, later changes to its source location do not change the value used for the shifted store.

### Three-argument call and propagation through G

The body forms S(F) and writes it at W(F) + 20. F-D27 then receives three arguments, in this order:

1. The low six bits of S(E), shifted left by 14.
2. S(F).
3. E shifted left by 30.

The first argument uses the scaled E value, not Q and not the value stored by the preceding shifted-word operation. Under the 32-bit machine interpretation, its potentially set bits are positions 16 through 19, numbering the least significant bit as position zero.

The third argument depends only on E’s lowest two bits under that interpretation. Its recovered signed left shift does not independently establish portable overflow behavior.

F-D28, F-D29, and F-D30 follow with no explicit arguments. F-D31 supplies G. The body writes the previously formed S(F) at S(G) + 20 and passes S(G) to F-D32.

F-D33, F-D34, and F-D35 follow with no explicit arguments. F-D36 supplies unsigned 32-bit H.

### First byte-indirect write

The body forms H shifted left by two bits. It reads P₁ as an unsigned byte from L(E), then writes the low byte of the shifted H value at P₁ + 17.

P₁ is the entire variable component of this store address. It is not an offset added to L(E). Consequently, the explicit destination is between 17 and 272 inclusive.

F-D37 then receives:

1. H shifted left by two.
2. The same shifted value again.
3. H shifted left by four.

These shifts originate from unsigned 32-bit H and discard bits beyond that width. The first two argument bit patterns are identical in the recovered dataflow.

F-D37 uses a displacement of **4076** from its recovered local target base. The other locally derived call targets use **4094**. This difference is observable in the representation and must not be normalized away.

F-D38 follows with no explicit arguments and supplies T. F-D39 receives T without a visible intervening transformation. F-D40, F-D41, and F-D42 then execute with no explicit arguments. F-D43 supplies J.

### Second byte-indirect write and final calls

After F-D43 returns, the body independently reloads P₂ as an unsigned byte from L(E). It writes a second byte at P₂ + 17.

The supplied value is H masked to its low 30 bits, then logically shifted right by 20. Truncation to an 8-bit store means the byte actually written consists of H’s original bits 20 through 27. Original bits 28 and 29 survive the mask and shift but not the final byte truncation.

P₂ is not a reuse of P₁. Calls and the first byte write intervene between the two reads; no stability guarantee is established. The second write therefore need not overwrite the first.

F-D44 receives J shifted left by two. F-D45, F-D46, and F-D47 follow with no explicit arguments. F-D48 supplies K.

F-D49 receives K shifted left by two as its first argument and zero-extended P₂ as its second. F-D50 then executes with no explicit arguments.

The visible representation ends at the invalid-instruction boundary after F-D50. It does not establish what executable behavior, if any, follows that point.

These are conditional consequences of the static contract, not executed test results. Each assumes execution reaches the relevant operations and the accesses succeed.

This establishes no real-platform accessibility for address 32 and no byte ordering for the word.

- The store using B writes 8 at address 52.
- The store using C writes the captured 8 at address 32.
- F-D07 receives 8.

### The word load remains independent

If Q is 0xABCDEF01 and E is 4, the later shifted-word store writes 0x000ABCDE at address 36. Changes to address 28 by intervening calls do not alter that captured Q under the recovered dataflow.

### Three-argument packing

Assuming 32-bit machine arithmetic, E equal to 5 and F equal to 3 produce these F-D27 arguments:

- 0x00050000.
- 12.
- 0x40000000.

These values do not depend on the contents of the shifted-word destination.

### Independent byte destinations

If H is 0x12345678, P₁ is 40, and the later reload yields P₂ equal to 41:

- The first byte write stores 0xE0 at address 57.
- The second byte write stores 0x23 at address 58.
- F-D49 receives 41 as its second explicit argument.

### Byte-address arithmetic boundary

This is a conditional arithmetic result, not evidence that the address is mapped or that signed arithmetic is portable.
