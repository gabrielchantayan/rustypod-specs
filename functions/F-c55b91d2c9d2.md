# F-c55b91d2c9d2

## Purpose

F-c55b91d2c9d2 reads two 32-bit values, evaluates a condition derived from its second argument, and, if that condition permits progress, writes a five-word record through an implicit destination pointer. The record contains an arithmetic result, the two captured values, a representation of its own destination address, and a shifted condition value.

The supplied static representation does not establish a higher-level purpose for this record. In particular, it does not establish that the record is a queue entry, descriptor, saved execution context, or persistent object.

Two limitations are central to the contract:

- The destination pointer is an incoming machine-state dependency that is absent from the displayed argument list.
- The represented control flow ends at an undecodable instruction boundary. Successful return, a particular processor exception, and subsequent behavior are not established.

## Behavior

### Initial reads

The represented order begins with two reads:

1. Read the fixed-address 32-bit cell and retain its value.
2. Read the 32-bit word at byte displacement 76 from the third argument and retain its value.

Both reads occur before the loop. Consequently, an input that does not permit the loop to terminate still reaches these reads first, assuming neither read prevents execution from continuing.

The subsequent record uses the captured values. There is no represented reread of either location during the loop or during record construction. A change to either source location after its read therefore does not, by itself, change the captured value written later.

The exact address-arithmetic behavior of the third argument plus 76 is not established beyond the represented address expression. Address wrapping, pointer validity rules, and fault behavior are not independently specified.

### Arithmetic definitions

For this contract, define:

- **Input**: the signed 32-bit second argument.
- **Result**: the low 32 bits of Input minus 14, interpreted as an unsigned 32-bit value.
- **Quotient**: Result shifted right logically by 15 bits.
- **Overflow**: signed 32-bit subtraction overflow when subtracting 14 from Input.

Result uses modulo-\(2^{32}\) arithmetic. It is not a saturating subtraction.

The right shift is logical because its operand is the unsigned subtraction result. Quotient therefore ranges from 0 through 131,071. It is not a one-bit Boolean flag.

Overflow is a signed-overflow condition, not an unsigned-borrow condition. For this subtraction, it is true precisely when Input lies in the inclusive range:

**−2,147,483,648 through −2,147,483,635.**

### Loop and progress condition

The loop computes Quotient at least once. It repeats while both of the following are true:

- Quotient is nonzero.
- Overflow is false.

Thus execution leaves the loop when either Quotient is zero or signed subtraction overflow is true.

No represented loop operation modifies Input, and the loop does not reread either captured memory value. Under the represented, stable-input execution model, repeating the loop does not move the computation toward completion.

There are exactly two classes of Input that permit progress:

1. **Ordinary arithmetic interval:** Input is between 14 and 32,781 inclusive. Result is then between 0 and 32,767 inclusive, so Quotient is zero.
2. **Signed-underflow interval:** Input is between −2,147,483,648 and −2,147,483,635 inclusive. Overflow is true, allowing progress despite a nonzero Quotient.

All other signed 32-bit inputs remain in the represented loop indefinitely. In that case, none of the five destination writes is reached.

This is a statement about the supplied static control flow, not a claim that interrupts, faults, external execution control, or unrepresented machine behavior cannot interrupt execution.

### Record construction

After leaving the loop, the function performs the following 32-bit writes in the represented order:

| Byte offset from destination | Stored value |
|---:|---|
| 0 | Result |
| 4 | Captured word from the third argument’s base plus 76 |
| 8 | Captured value from the fixed-address cell |
| 12 | Destination address converted to a 32-bit unsigned value |
| 16 | Quotient shifted left by 6 bits |

The record occupies 20 bytes. Its fields are described as words; byte order is not established by the fragment.

The fourth field is the destination’s own address representation. It is not the address of a later field and is not visibly dereferenced after being stored. The represented conversion produces 32 bits. If a wider address model were applied, only the resulting 32-bit representation would be established; the fragment does not justify assuming preservation of wider address bits.

For the inputs that reach the writes, the fifth field has only two established values:

- **0** for Input from 14 through 32,781.
- **4,194,240**, or **0x003FFFC0**, for Input from −2,147,483,648 through −2,147,483,635.

In the second interval, Result ranges from 0x7FFFFFF2 through 0x7FFFFFFF. Every value in that range produces Quotient 65,535, making the shifted field constant across that interval.

### Final control-flow boundary

After the fifth write, the supplied representation stops at an instruction it cannot interpret.

The contract therefore establishes neither:

- A normal return to the caller.
- A particular return-register value.
- A specific exception or termination mechanism.
- Any subsequent read, write, cleanup, or continuation.

The record writes precede this boundary in the represented flow. The boundary does not imply that earlier writes are rolled back.

## Side effects

The visible side effects are:

No destination read is visible. There is no represented bounds check, synchronization operation, allocation, deallocation, or explicit error report.

If an access fails, the fragment provides no recovery path. The exact fault mechanism and the visibility of any preceding successful accesses remain environment-dependent and undocumented.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless an example says otherwise, assume readable source locations, a writable destination, and execution consistent with the supplied representation.

### Lower ordinary boundary

With Input **14**, a third-argument-relative captured word **0x11223344**, and a fixed-cell captured value **0x55667788**:

- Result is 0.
- Quotient is 0.
- Execution leaves the loop after its first evaluation.
- The five words are written as: 0, 0x11223344, 0x55667788, the destination’s 32-bit address representation, and 0.
- Execution then reaches the undecodable boundary; normal return is not an acceptance requirement.

### Upper ordinary boundary

With Input **32,781**:

- Result is 32,767.
- Quotient is 0.
- Record construction is reached.
- The first word is 32,767 and the fifth word is 0.

With Input **32,782**:

- Result is 32,768.
- Quotient is 1.
- Signed subtraction does not overflow.
- The represented loop continues without reaching any destination write.

### Value immediately below the ordinary interval

With Input **13**:

- Result is 0xFFFFFFFF.
- Quotient is 131,071.
- Signed subtraction does not overflow.
- The initial reads occur, but the destination writes are not reached.

This case distinguishes unsigned result arithmetic from a signed right-shift interpretation.

### Signed-underflow interval

With Input **−2,147,483,648**:

- Result is 0x7FFFFFF2.
- Quotient is 65,535.
- Signed subtraction overflow permits loop exit.
- The first destination word is 0x7FFFFFF2.
- The fifth destination word is 0x003FFFC0.

With Input **−2,147,483,635**, the first word is instead 0x7FFFFFFF, while the fifth word remains 0x003FFFC0.

### Value immediately beyond the overflow interval

With Input **−2,147,483,634**:

- Result is 0x80000000.
- Quotient is 65,536.
- Signed subtraction does not overflow.
- The destination writes are not reached.

### Source and destination overlap

If the destination overlaps a source word, and both initial reads complete before record construction, the corresponding output field uses the previously captured value. No reread is required or represented.

### Invalid destination with a non-progressing input

If Input is **13**, the represented execution never accesses the destination. Destination invalidity alone therefore does not introduce a destination-access failure on that path. Either initial source read may still fail independently.
