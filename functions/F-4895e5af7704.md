# F-4895e5af7704

## Purpose

F-4895e5af7704 performs an ordered sequence of indirect calls, six 32-bit stores, byte-addressed reads and writes, and an unconditional loop containing further calls and byte writes.

The supplied static representation establishes no domain-level purpose. Describing the routine as an initializer, serializer, allocator, or device controller would require evidence not supplied here.

The visible loop has an important dependency transition: the first execution of call site F-U065 uses one numeric target address; every later execution uses another. The call-site identity remains F-U065, but its target is not constant across loop entry.

**Established static evidence:** explicit argument transformations, access widths, call and memory-access ordering, the F-U065 target transition, and absence of a visible normal return.

**Inferred intent:** the repeated call groups and narrow writes might implement a structured protocol. Neither that interpretation nor the meaning of its fields is established.

**Evidence limitation:** the supplied representation reports invalid instruction data and removal of unreachable regions. This contract describes its visible path, not independently verified executable behavior.

### Aliasing, layout, and order

No disjointness between computed addresses is established. A word store or byte store may affect a later selector read. A selector-based store can also alias its own selector location, affecting subsequent reads.

The contract therefore preserves access and call ordering rather than specifying only a final memory image. In particular, the two stores to the derived slot and the repeated zero writes cannot be collapsed.

The word stores have 32-bit width. Their byte layout is not established because endianness is unknown. Alignment requirements and the treatment of unaligned accesses are also unknown.

## Acceptance examples

These examples are conditional deductions from static evidence, not executed tests. Assume all preceding calls return normally and required accesses complete.

1. **First store and call.** With input 1 equal to 3, the first explicit access stores the 32-bit value 3 at address 32. F-U001 subsequently receives 3.

2. **Derived-slot overwrite.** If the fourth index is 2, a 32-bit store writes 8 at address 52. After F-U029 through F-U033, another writes 32 at address 52. Dependency effects between those stores remain unrestricted.

3. **Fresh destination resolution.** If one byte-selector read yields 5, its store targets address 22. If a subsequent read yields 9, that store targets address 26, even though both reads use the same retained selector address.

4. **Byte truncation.** If the first byte-source word is 0x12345678, the first byte-selector write stores 0xe0. The second stores 0x23.

5. **Fourth-input addressing.** With input 4 equal to 128, the direct byte store targets address 29, and F-U051 receives 1.

6. **Initial loop boundary.** If the loop-seed word is 0xffffffff, the initial loop field is 31. F-U063 receives 62. The first F-U065 receives zero as its second argument and targets **0x08833787**.

7. **First-to-second target transition.** If the first iteration completes normally, the second execution of F-U065 targets **0x088337c5**, not 0x08833787. This holds regardless of F-U074’s result.

8. **Later arguments and stable later target.** If F-U074 returns 1, the next F-U065 receives 4 and 262144. If it returns 64, the next arguments are 256 and zero. In either case, that next call targets **0x088337c5**.

9. **Persistent selector can change destinations.** If its pre-loop read yields 255, the pre-loop zero store targets address 272. If the next read yields zero, the first iteration’s zero store targets address 17.

10. **No visible recovery.** If a selector read cannot complete, no fallback destination or error return is represented. Resulting machine or environment behavior is unspecified.
