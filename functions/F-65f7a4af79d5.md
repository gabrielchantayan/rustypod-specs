# F-65f7a4af79d5

## Purpose

F-65f7a4af79d5 accepts two 32-bit words and returns one 32-bit word. Their fields are interpreted in the layout of binary32 floating-point values.

**Inferred intent:** compute the second operand minus the first using integer operations, with special handling for zeros, very small operands, infinities, NaNs, rounding, and overflow.

**Established limitation:** the visible behavior is not a complete IEEE 754 subtraction contract. In particular:

- Operands with zero exponent fields are treated specially rather than processed as ordinary subnormal numbers.
- Some small results are returned as positive zero.
- One exceptional result comes from an unavailable data value.
- NaN handling transfers control to an unresolved indirect dependency.
- Several rounding decisions depend on target shift semantics that are not fully specified by the supplied representation.

The exact observable rules below take precedence over the inferred arithmetic purpose.

## Interface

### Inputs

Two positional inputs, each an unsigned 32-bit word:

1. **First operand:** the value intended to be subtracted.
2. **Second operand:** the value from which the first is intended to be subtracted.

The bit layout of either operand is:

| Bits | Width | Interpretation |
|---|---:|---|
| 31 | 1 | Sign |
| 30–23 | 8 | Exponent |
| 22–0 | 23 | Fraction |

Useful encodings and classes:

- Positive zero: `0x00000000`.
- Negative zero: `0x80000000`.
- Zero-exponent class: exponent is zero, including signed zeros and subnormals.
- Ordinary finite class: exponent is between 1 and 254.
- Infinity: exponent is 255 and fraction is zero.
- NaN encoding: exponent is 255 and fraction is nonzero.

These classifications describe bit patterns; the interface does not require native floating-point arguments or perform an observable floating-point conversion.

### Output

The return value is a single 32-bit word. There is no separate status result.

For most paths, the word is constructed locally or selected from the inputs. Exceptions are:

- An exceptional equal-infinity case returns an unavailable data value.
- A NaN-containing case returns the result of an unresolved indirect call, if that call returns.

## Behavior

### Classification and precedence

The function first determines whether either operand has an exponent consisting entirely of zeros or entirely of ones. This classification precedes sign changes and significand arithmetic.

If both operands have ordinary finite exponents, execution proceeds to the ordinary arithmetic path.

Otherwise, exceptional handling has this precedence:

1. If neither operand has an all-ones exponent, apply the zero-exponent rules.
2. If at least one operand is a NaN encoding, invoke the unresolved indirect dependency.
3. Otherwise, handle infinities.

Consequently, a NaN encoding is not overridden by an accompanying zero, subnormal, finite value, or infinity.

### Zero-exponent operands

This branch applies when at least one operand has exponent zero and neither has exponent 255.

The following rules are ordered:

1. If the second operand has a nonzero exponent, return the second operand unchanged.
2. Otherwise, if the first operand has a nonzero exponent, return the first operand with its sign bit toggled.
3. Otherwise, both operands have zero exponents. Return negative zero only when the second operand is exactly negative zero and the first operand is not exactly negative zero. Return positive zero in every other case.

Important consequences:

- A subnormal first operand is ignored when the second operand is ordinary finite.
- A subnormal second operand is ignored when the first operand is ordinary finite; the returned first operand has its sign reversed.
- When both exponents are zero, fraction bits do not contribute to a nonzero result.
- Exact negative-zero identity matters. A negative subnormal is not treated as the negative-zero encoding for the final sign rule.

This behavior does not provide gradual arithmetic over subnormal inputs.

### NaN-containing inputs

If either operand is a NaN encoding, the function performs an indirect call through a destination derived from the incoming link-state value, with its lowest two bits cleared.

The returned 32-bit result of that call becomes the result of F-65f7a4af79d5.

The supplied evidence does not establish:

- The destination’s opaque function ID.
- An explicit argument contract.
- NaN payload selection.
- Quieting of signaling NaNs.
- Exception flags or other global state changes.
- Whether the dependency returns normally.

The function must therefore not be specified as returning a canonical NaN or propagating a particular input payload on this path.

### Infinity inputs without NaNs

After NaNs have been excluded:

- If only the second operand is infinite, return the second operand unchanged.
- If only the first operand is infinite, return the first operand with its sign bit toggled.
- If both operands are infinite with opposite signs, return the second operand unchanged.
- If both operands are infinite with the same sign, return the unavailable exceptional data value.

The last case is consistent with an invalid arithmetic result, but the returned word is not available in the supplied evidence. Its bit pattern and classification are documented_only.

### Ordinary finite inputs

This path begins by toggling the first operand’s sign bit. That establishes the inferred operation as addition of the second operand and the sign-reversed first operand.

The subsequent path depends on whether those effective signs agree.

#### Effective signs differ

This corresponds to subtracting magnitudes. The operands are rearranged, when necessary, to put the greater magnitude first while retaining the required result sign.

The function then:

- Obtains an exponent difference.
- Forms 32-bit significand work values with an explicit leading bit and eight low-order working bits.
- Right-aligns the smaller significand according to the exponent difference.
- Subtracts the aligned significands.
- Selects a normalization and rounding path according to the high bits of the difference.

Observable result cases include:

- A result already having its leading bit in the expected position.
- A result requiring one additional leftward normalization step.
- A result requiring leading-zero counting and a larger normalization adjustment.
- Positive zero for exact cancellation or specified small-result cases.

The multi-position normalization path uses a leading-zero count, a masked rotation distance, and an exponent-range condition before constructing a result. If that range condition fails, it returns positive zero. It does not visibly construct a general subnormal result.

The exponent work value includes the sign bit because it is obtained from the complete word shifted right by 23. It is therefore nine bits wide, not merely the eight-bit exponent field. This distinction affects normalization checks and packed-result construction.

#### Effective signs agree

This corresponds to adding magnitudes. The operands are ordered before alignment.

The function forms significand work values, aligns the smaller one, and adds them. A carry out of the 32-bit addition selects a different normalization path from a non-carry result.

The result is assembled from:

- The retained significand bits.
- An exponent contribution in units of `0x00800000`.
- A possible one-unit rounding increment.

Some branches return directly. Others examine discarded information and possible overflow before returning.

### Rounding and discarded information

The arithmetic paths visibly use eight low-order working bits. A bit at position 7 frequently controls an initial rounding increment.

Where additional discarded bits establish that the result is not an exact midpoint, the incremented result may be returned directly.

At selected midpoint-sensitive boundaries, the function also examines information discarded during alignment:

- Some exact-tie paths clear the least significant bit of the assembled result.
- Some magnitude-subtraction paths instead subtract one from the provisional result when alignment discarded nonzero information.

**Inferred intent:** implement nearest-value rounding with even-result tie handling, accounting for the different error direction of addition and subtraction.

**Contract boundary:** the supplied evidence is insufficient to claim universal equivalence to IEEE round-to-nearest, ties-to-even. Alignment shifts can reach or exceed the word width, and those cases depend on target semantics.

### Overflow

The magnitude-addition path checks the assembled result against the all-ones exponent boundary using a one-bit-left-shifted comparison.

When its overflow handling is selected, the return expression has:

- All eight exponent bits set.
- All 23 fraction bits clear.
- A sign bit derived from the preceding result and a fixed numeric term represented as `0xA0000000`.

Under the literal 32-bit numeric interpretation of that final expression, the sign is preserved and the result is signed infinity.

The expression’s address-like presentation prevents treating the numeric interpretation as independently verified target semantics. The infinity-shaped output fields are established; the precise sign mapping remains conditional on that interpretation.

### Integer widths and shifts

The visible calculations use 32-bit unsigned words except where a signed interpretation is explicitly used for a sign test or arithmetic right shift.

Relevant arithmetic properties:

- Ordinary unsigned addition, subtraction, multiplication, and left shifts retain only the low 32 bits.
- One significand addition explicitly observes carry out of bit 31.
- A signed comparison with zero tests bit 31.
- The rounding increment is one unit of the packed result, not one unit of the significand work value.
- Some alignment distances retain their low eight bits.
- The rotation-style normalization distance retains its low five bits.

Masking a shift distance to eight bits does not bound it to 0–31. Shifts by 32 or more, and a rotation-style expression containing a shift by 32, require target semantics. They must not silently be assigned host-language behavior.
