# F-95eaa634a1d5

## Purpose

F-95eaa634a1d5 conditionally invokes a dependency using an input-derived address, a 32-bit value read from another input-relative location, and caller-provided output storage. It then writes a 16-bit value derived from a mutable 32-bit working value into the beginning of that output storage.

The established behavior is a sequence of stores, calls, and one explicit input-relative load. The semantic meanings of the input object, output contents, and final 16-bit field are not established. In particular, the final field must not be described as a length, status, count, or identifier without additional evidence.

A null output pointer causes an immediate return. Otherwise, the function first writes a zero halfword to the output, calls a gating dependency, and proceeds only if that dependency returns a nonzero value.

## Behavior

### Null-output path

If the output pointer is null, the function returns immediately.

On this path, the function performs no explicit memory reads or writes and invokes neither dependency. It does not validate the input value.

### Initial output store and gate

For a nonnull output pointer, the function first stores a 16-bit zero at the output address. It then calls F-3b037d560480 with the original input value.

The dependency’s return value controls continuation:

- A zero return causes an immediate return from F-95eaa634a1d5.
- Any nonzero return permits the remaining processing.

No specific nonzero value is distinguished.

The initial zero store precedes the call. Consequently, any behavior inside F-3b037d560480 that can access the same storage may observe that store or overwrite it.

A zero gate result does **not** establish that the output still contains zero when this function returns. That conclusion additionally requires that F-3b037d560480 did not alter the output, directly or through an alias. The established guarantee is that this function performs no further explicit write after a zero gate result.

### Continuing path

After a nonzero gate result, the function initializes a mutable 32-bit working value from the original input value.

It then calls F-5ef10d079522 with four arguments, in this order:

1. The address derived from the input value plus byte offset `0x128`.
2. The 32-bit value read from the address derived from the input value plus byte offset `0x180`.
3. The output address plus two bytes.
4. The address of the mutable 32-bit working value.

The working value is initialized after the gating call. It is initialized from the input argument’s value, not from an input-relative memory field and not from the gate’s return value.

The 32-bit field load occurs after the gating dependency returns. Therefore, if F-3b037d560480 modifies that field, the second dependency receives the subsequently loaded value rather than a value captured before the gate.

No ordering among the independent argument-preparation operations is established beyond their completion before the second call. In particular, this contract does not impose an additional evaluation order between the input-relative field load and the other argument calculations.

The second dependency’s return value is not used to select behavior or construct the final output.

### Final halfword derivation

After F-5ef10d079522 returns, the function uses the then-current 32-bit working value. The dependency can affect this value through the writable address it received.

The final output halfword is bits 1 through 16 of that 32-bit value, shifted into positions 0 through 15. Bit numbering starts at zero for the least significant bit.

For a 32-bit bit pattern interpreted as an unsigned value \(u\), the final 16-bit value is:

\[
\left\lfloor \frac{u \bmod 2^{17}}{2} \right\rfloor
\]

This has the following consequences:

- Original bit 0 is discarded.
- Original bits 1 through 16 determine the entire stored halfword.
- Original bits 17 through 31 do not affect that halfword.
- Original bit 16 becomes the stored halfword’s most significant bit.
- No saturation or range check is performed.

The function stores this result at output byte offset zero and returns.

This description captures the fixed-width bit effect shown by the supplied representation. It does not depend on treating a signed left shift as portable source-language arithmetic.
