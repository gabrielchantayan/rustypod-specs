# F-3758cd3e9bd2

## Purpose

F-3758cd3e9bd2 searches a sentinel-terminated sequence of two-integer records. It returns the second integer from the first record whose first integer is accepted by an external comparison dependency against a supplied query.

Acceptance is defined solely by the dependency returning zero. The function does not itself establish numerical equality, string equality, ordering, or any other meaning for that result.

Zero is also the function’s result when searching is disabled or when the terminating record is reached without an accepted record. Consequently, a zero result does not distinguish absence from a successful match whose associated value is zero.

The record-search interpretation is inferred intent. The observable traversal, dependency calls, and result selection are established by the supplied static evidence.

## Interface

The interface has two inputs and one integer result:

- **Record-sequence address:** An address interpreted as a pointer to integer storage. A null address is permitted and produces zero without accessing the sequence.
- **Query:** An integer supplied by value. A zero query disables searching and produces zero without accessing the sequence or calling the dependency.
- **Result:** An integer. On acceptance, this is the associated value read from the accepted record. Otherwise, it is zero.

Each logical record contains two consecutive integer elements:

| Position within a record | Meaning |
|---|---|
| First integer | Candidate supplied to the comparison dependency; zero terminates the search |

Records are adjacent, with no additional fields or explicitly described padding between their integer elements. Advancing to the next record advances by two integer elements.

## Behavior

### Search eligibility

The sequence address is checked for null before the query’s nonzero condition is relevant to entry into the search.

If the sequence address is null, the result is zero. If the query is zero, the result is also zero, even when the sequence address is nonnull. Neither case reads the pointed-to storage or calls the comparison dependency.

Thus, a nonnull address need not designate readable storage when the query is zero, because this function does not dereference it on that path.

### Sentinel and candidate processing

For an enabled search, records are considered in their stored order, starting at the supplied address.

The first integer of the current record is read to determine whether it is zero. A zero candidate ends the search immediately with result zero:

- The dependency is not called for the terminating record.
- The terminating record’s associated value is not read by this function.
- Records following the terminator are not inspected.

For a nonzero candidate, the function obtains the candidate argument from the current record and calls the comparison dependency with:

1. The current record’s first integer.
2. The supplied query.

The static expression structure contains a candidate access for the sentinel test and another candidate access for the dependency argument. It does not establish a synchronized snapshot of the sequence. No concurrent-mutation or volatile-access guarantees are supplied.

The dependency’s result is interpreted only as zero or nonzero:

- **Zero:** The current record is accepted. Its associated value is read and returned immediately.
- **Nonzero:** The associated value is not read by this function. Traversal proceeds to the next two-integer record.

Negative and positive nonzero dependency results are treated alike. There is no ordering-based early exit and no attempt to select a “best” match.

### Selection and result timing

The first accepted record wins. Once a dependency call returns zero, no subsequent candidate is inspected and no additional comparison call is made by this function.

The associated value is read after the dependency returns. It is not captured before the call. If the dependency validly changes that associated value through some separately available access, the later read observes the value then present, subject to the execution environment’s memory rules.

A zero associated value is returned unchanged. It is not rejected, replaced, or treated as a reason to continue searching. Negative associated values are likewise returned without a special check.

### Traversal limits and failure boundaries

The function performs no integer arithmetic on candidate values, associated values, or the query. Those values are tested, passed, or returned.

The traversal calculation advances the address by two integer elements after each rejected record. It has no explicit overflow check, maximum-record count, or recovery path for an invalid address. A usable sentinel or an earlier accepted record is therefore necessary for a defined, terminating execution over finite accessible storage.

Missing termination does not establish a guaranteed infinite loop: traversal may instead encounter invalid storage. The supplied evidence provides no defined result for that situation.

## Side effects

External calls remain observable side effects. For a well-formed execution with stable records, the dependency is called once for each nonzero candidate encountered up to and including the first accepted record, or once for every nonzero candidate before the terminator if none is accepted.

The function does not explicitly allocate, release, retain, or transfer ownership of storage. The sequence remains caller-provided storage for the accesses described above.
