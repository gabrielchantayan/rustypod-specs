# F-5eef95027166

## Purpose

F-5eef95027166 validates selected properties of a typed input record, constructs a local 72-byte event image for accepted type-and-length combinations, performs certain type-0 actions, and conditionally passes the image to a submission dependency.

The established behavior includes:

- Identity and payload-null checks before eligibility evaluation.
- Type-specific length checks after eligibility succeeds and the event initializer runs.
- Type-0 actions that precede, and are not undone by, a later submission-suppression decision.
- An ordinary-exit handoff of the input record, followed by a dependency marked non-returning.

“Event,” “eligibility,” and “submission” describe visible roles, not established protocol semantics. The implementation of each dependency is unavailable. In particular, passing an image address to a dependency does not establish how that dependency modifies, copies, retains, or releases the image.

## Interface

### Inputs and storage requirements

The function receives a context address and an input-record address. The supplied representation uses 32-bit address-bearing values and the following concrete accesses:

| Object | Byte offset | Width | Established use |
|---|---:|---:|---|
| Context | `0x2D0` | 32 bits | Identity compared with the record identity |
| Context | `0x2D4` | 32 bits | Argument to several dependencies |
| Context | `0x2D8` | Address only | Subobject passed to operations surrounding submission |
| Context | `0x2FC` | 8 bits | Conditionally read and cleared by a type-0 action |
| Input record | `0x00` | 32 bits | Record identity |
| Input record | `0x08` | 32-bit address | Payload address |
| Input record | `0x0C` | Unsigned 16 bits | Declared payload length |
| Input record | `0x10` | Unsigned 16 bits | Record type |

Other portions of these objects have no established meaning here.

The input record must be readable before validation: the function reads its type, length, and payload address before checking identity. A null record address is not a supported empty-input operation. The later null check at ordinary exit does not protect these initial accesses.

The context and payload must provide all storage accessed on the selected path. Declared-length validation does not prove the existence, readability, or alignment of the corresponding allocation. Additional requirements imposed by dependencies are unknown.

### Result and termination

The apparent result has 32-bit integer width. The visible paths select these status values:

| Condition | Selected status |
|---|---:|
| Eligibility returns zero | `11` |
| Eligibility succeeds, but type or length is rejected | `62` |
| Accepted record bypasses ordinary processing | `0` |
| Ordinary processing returns zero | `0` |
| Ordinary processing returns nonzero | That dependency’s result |

These are **exit-path status values**, not established normal return values. With a non-null input record, ordinary exit calls F-09ba55c206ac and then F-feee9156a257; the latter is marked non-returning.

Identity mismatch or a null payload instead calls F-a817d8d58c10, also marked non-returning. No ordinary cleanup is shown before that call.

### Event image and processing objects

The function supplies a local image address and size `72` to U-01, then explicitly writes the low eight bits of the captured type to image byte `0`.

Subsequent explicit writes use image offsets `4` and `8`. Bytes not explicitly assigned retain whatever preceding operations produced; initialization to zero is not established.

For types 29 and 33, the entire image address is subsequently passed to F-57148e458427. Its effects are unknown, so even image byte `0` is not guaranteed to retain the type at submission.

A separate 32-bit selector and two 32-bit processing fields accompany ordinary processing. They are not established as part of the submitted image.

## Behavior

### Initial reads, rejection, and eligibility

The visible initial sequence is:

1. Read the record’s unsigned 16-bit type.
2. Read its unsigned 16-bit length and widen that length to unsigned 32 bits.
3. Read its payload address.
4. Compare the context identity with the record identity.
5. Invoke F-a817d8d58c10 if the identities differ or the captured payload address is null.
6. Otherwise, call F-5a5d7959eb80 without explicit arguments.

The relative evaluation order of the two identity operands is not established. The identity comparison precedes the payload-null condition in the visible short-circuit expression.

If eligibility returns zero, event initialization, dispatch, ordinary processing, and submission are skipped. Ordinary exit uses status `11`.

If eligibility returns nonzero, the function selects default rejection status `62`, initializes the selector to decimal `37`, calls U-01 with the image and size `72`, writes image byte `0`, and dispatches using the captured type and length. Rejected types and lengths therefore still reach U-01.

| 25 | 1 | 37 | Payload byte 0 at image offset 4 |

A “conversion result” is the 32-bit value returned by F-c25a2fcc75b5 when passed the payload address. Its actual read extent, byte order, and interpretation are unknown. The declared lengths are not evidence of the callee’s implementation.

For type 2, the conversion call completes before the raw 16-bit payload read at offset `4`. For types 10 and 19, it completes before the payload-byte read at offset `4`. If the conversion dependency modifies payload storage, these later reads observe the resulting storage.

Single-byte image assignments preserve the other bytes of the containing field. The raw type-2 assignment writes only two bytes at image offset `8`.

### Types 29 and 33

For either type, acceptance uses unsigned 32-bit subtraction of two from the widened length, followed by comparison with decimal `66`. Lengths below two underflow and fail. The exact accepted interval is `2` through `68`.

After acceptance, F-57148e458427 receives, in argument order:

1. The context address.
2. The captured original payload address, not that address advanced by two.
3. The entire event-image address.
4. The length minus two, masked to its low 16 bits.

The supplied count is therefore `0` through `66`. The return value is ignored.

No implementation is supplied for this dependency. The call does not establish that it populates variable-length data, preserves the image header, limits its writes to a particular image region, or leaves the image unchanged.

### Type-0 basic fields

Type 0 accepts lengths `2` and `6`. It reads payload byte `1` as an unsigned value and uses that value as the selector.

The image field beginning at offset `4` receives:

- Payload byte `1` in its low byte.
- Payload byte `0` in its next byte.
- No explicit replacement of its upper two bytes.

The extended action occurs only if the captured length is `6` and the payload byte read for the extension condition equals `6`. Length `6` remains accepted when this byte is not `6`; in that case, the explicit extension path does not access payload offsets `2` through `5`.

### Type-0 extended action and pointer indirection

The extension first calls F-c25a2fcc75b5 with payload address plus two. Its 32-bit result is saved in a local argument object and written at image offset `8`.

The following address distinctions are essential:

- A global reference supplies the address of a pointer slot.
- The function captures that **slot address** locally before calling F-43ce968102ca.
- Loading the slot’s contents yields an **object pointer**.
- Later object loads use the captured slot address; they do not freshly resolve the global reference.

The gate call to F-43ce968102ca receives five arguments:

1. An object pointer loaded through the global pointer-slot reference.
2. The context field at `0x2D4`.
3. A 16-bit value read at an address formed by adding an unresolved global displacement to an object address loaded through the global pointer-slot reference.
4. The low byte of the image field at offset `4`.
5. Zero.

The first and third arguments involve separate reads of the global pointer-slot reference and its contents. Their evaluation order is not established, nor is their order relative to the other argument evaluations. They must not be collapsed into one shared object-pointer snapshot.

The displacement used for the 16-bit read is unresolved. No fixed object-field offset is established for that read.

If the gate returns nonzero, the following state-update sequence is skipped. If it returns zero:

1. F-7a117b899bf6 receives a local temporary object.
2. The function loads an object pointer through the previously captured slot address.
3. The 16-bit field at that object’s offset `0x2FA` is incremented and stored at 16-bit width.
4. U-05, obtained through the temporary object’s dispatch structure at offset `0x0C`, receives the temporary object and converted-value object.
5. F-bf18a6a8124b receives the converted-value object.
6. The function again loads an object pointer through the same captured slot address.
7. The returned 32-bit value is stored at that object’s offset `0x2F4`.
8. Byte `0x2F8` of that same loaded object is set to `1`.
9. F-ec22bd8215d3 receives the temporary object.

The increment wraps modulo `65536`.

A dependency can change the contents of the captured slot, causing the two later loads to identify different objects. Changing only the global reference to identify a different slot does not redirect these later loads: they still use the captured slot address. Continued validity of that slot is a precondition for those accesses.

### Type-0 selector-5 action

After any extension, the selector is reduced to unsigned 16 bits and compared with `5`. Only on equality is context byte `0x2FC` read.

If that byte equals exactly `1`:

1. U-02 is called.
2. F-4944ce526800 receives U-02’s result plus four bytes, the context field at `0x2D4` read for this call, `7`, and `0`.
3. Context byte `0x2FC` is cleared.

Other flag values do not trigger this action. Clearing occurs after F-4944ce526800 returns. Ordinary-processing failure does not undo this action.

### Ordinary processing and submission

Every accepted path initializes one 32-bit processing field to zero and another to all ones, and selects status zero.

The selector is tested after reduction to unsigned 16 bits:

- Above `36`: ordinary processing is bypassed and submission is attempted.
- At most `36`: F-704f99fd5e22 is called.

That dependency receives, in argument order:

1. Context address.
2. Context field at `0x2D4`.
3. Address of the all-ones processing field.
4. Address of the 32-bit selector.
5. Address of the zero processing field.

Its zero result permits submission. Its nonzero result suppresses submission and supplies the exit-path status. Any selector modification made during this call is not followed by a new range decision.

Submission consists of:

1. U-03 with context address plus `0x2D8`.
2. F-c6c589453fa8 with `7`, `0`, image address, and `72`.
3. U-04 with context address plus `0x2D8`.

Return values from these operations are not used. Their pairing suggests synchronization but does not establish it. If an earlier operation fails to return, later operations are not guaranteed to execute.

## Side effects

Explicit nonlocal writes are limited to:

- Context byte `0x2FC` on the selector-5 path.
- Object field `0x2FA` on the successful extension path.
- Object fields `0x2F4` and `0x2F8` later on that path.

The objects receiving the counter update and the later two writes need not be identical because the saved slot’s contents are loaded twice.

The visible body does not directly overwrite the input record or payload. Dependencies may modify storage available to them, including the image passed to F-57148e458427. No dependency is assumed to preserve globals or pointed-to objects.

Every ordinary exit with a non-null record calls F-09ba55c206ac with that record, followed by F-feee9156a257. This establishes a handoff, not allocation ownership, freeing, or payload disposal.

The image and temporary objects are local storage. No visible action establishes a lifetime extension. Whether submission copies the image synchronously or retains its address is unknown.

No explicit validity checks cover the global slot, loaded objects, unresolved-displacement address, provider result, or indirect dispatch structure. Fault handling for invalid addresses is not established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume readable and writable storage as required, matching identities, non-null payload, successful eligibility, and normal return from dependencies not marked non-returning.

1. **Eligibility declines.** If F-5a5d7959eb80 returns zero, U-01, ordinary processing, and submission are skipped. Status `11` precedes ordinary-exit calls.

2. **Rejected length.** Type 10 with length `4` reaches image initialization but not conversion, ordinary processing, or submission. Its selected rejection status is `62`.

3. **Accepted converted record.** Type 10 with length `5` stores the conversion result at image offset `4`, then reads payload byte `4` into image offset `8`. Selector `9` reaches ordinary processing; submission requires its zero result.

4. **Default-selector bypass.** Type 25 with length `1` writes image byte `4` and submits without F-704f99fd5e22 because its selector is `37`.

5. **Variable-length boundaries.** Type 29 at lengths `2` and `68` calls F-57148e458427 with counts `0` and `66`. Lengths `1` and `69` do not call it.

6. **Unknown image mutation.** If F-57148e458427 changes image byte `0` for accepted type 33, no later explicit assignment restores the type there. Submission is attempted without ordinary processing.

7. **Non-extension length-six record.** Type 0 with length `6` and extension-condition byte other than `6` is accepted without the extended conversion or state updates.

8. **Selector-5 action survives suppression.** With selector `5` and context flag `1`, the provider/action calls and flag clear precede ordinary processing. A later nonzero processor result suppresses submission, not those earlier effects.

9. **Slot reference changes.** Suppose the captured slot address is S, and a dependency subsequently changes the global reference to a different slot T. Later extended updates still load through S, assuming S remains valid.

10. **Slot contents change.** If S contains object A after F-7a117b899bf6 and object B after F-bf18a6a8124b, A receives the counter increment while B receives the `0x2F4` and `0x2F8` writes. An A counter of `65535` becomes zero.

11. **Unresolved displacement.** The gate’s 16-bit argument comes from its loaded object address plus the unresolved displacement. No acceptance condition requires a read at any particular fixed offset.

12. **Null payload.** A matching-identity record with a null payload invokes F-a817d8d58c10 before eligibility. Ordinary cleanup is not shown on this path.
