# F-2202f6bea913

## Purpose

F-2202f6bea913 selects one of two dependencies, supplies it with a shared context value and a mutable 32-bit location value, and returns the dependency’s status. On a zero status, it reads an unsigned 16-bit field from the resulting location and publishes that field as a 32-bit unsigned output.

If the selector returns neither of the two supported values, the function directly writes zero to the output and returns 19.

This contract describes the supplied static evidence. The application meaning of the selector values, shared context, location, field, and status codes is unknown. No runtime tests have been performed.

## Interface

The function has four inputs and one 32-bit integer return value.

The second and third inputs do not influence any visible branch, dependency argument, or direct memory access. This does not establish their intended application role or any compatibility policy for future implementations.

The fourth input is represented as an integer, but its eventual value is used as a memory address. Its signed integer representation does not imply that negative values are rejected: no sign test or range validation is visible.

The return value is:

- Exactly 19 when the selector returns neither 2 nor 3.
- The selected dependency’s status, without visible conversion or translation, on either supported-selector path.

A zero return on a supported path causes the function to attempt the field read and output write before returning. It does not guarantee that those memory operations are valid.

## Behavior

### Initialization and selection

The function first copies the fourth input into local 32-bit mutable storage. It then invokes F-ccde8fa781e9 with no explicit arguments.

The selector’s return value determines the subsequent path:

| Selector result | Action |
|---|---|
| 2 | Read the shared context value and invoke F-87f3118a2e5f. |
| 3 | Read the shared context value and invoke F-c439699f0cde. |
| Any other value | Directly write 32-bit zero to the output and return 19. |

Only one selected dependency is invoked. There is no visible fallback from one selected dependency to the other, no retry, and no second selector invocation.

The shared context value is not visibly loaded before the selector call. Consequently, a selector-induced change to the shared state can affect the context value subsequently obtained on a supported path.

On the unsupported path, the function does not directly read the shared-context slot or dereference the fourth input. It still invokes the selector before writing the output.

### Supported-selector paths

For either supported selector result, the function reads a 32-bit value at byte offset 8 from the shared base. That value is supplied as the first argument to the selected dependency.

The second argument is the address of the local 32-bit storage initialized from the fourth input. This makes the location value mutable by the selected dependency. The function does not itself overwrite that local value between initialization and the dependency call.

The selected dependency’s return value is then tested for exact equality with zero.

If the status is nonzero:

- The function does not directly read the field at the resulting location.
- The function performs no direct output write after the dependency returns.
- The function returns the same status.

If the status is zero:

1. The function uses the current value in the local storage as the location.
2. It reads an unsigned 16-bit quantity at byte offset 16 from that location.
3. It converts that quantity to a 32-bit unsigned value by zero extension.
4. It writes the resulting 32-bit value through the first input.
5. It returns zero.

The location used for the successful read is the value present after the selected dependency returns. It need not equal the fourth input. If the dependency leaves the local storage unchanged, the initial value remains the location used.

1. Initialize the local location storage.
2. Invoke the selector.

4. Invoke the selected dependency.
5. If its status is zero, read the 16-bit field.

On the unsupported path, the selector invocation precedes the zero output write, which precedes return of 19.

These constraints describe this function’s direct actions. Each dependency may perform additional operations during its invocation; their effects are not specified by the supplied body.

If the output overlaps the successful-path field, the field read still precedes the 32-bit output write. The visible function has no overlap check. This observation does not establish that dependencies or the surrounding environment permit such aliasing.
