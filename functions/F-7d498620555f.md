# F-7d498620555f

## Purpose

F-7d498620555f performs a mode-gated operation on a 32-bit requested value using a context associated with an object. After initial acquisition and validation, it either processes the request directly or follows a selected-value path that can update the caller’s output and submit an adjusted value to a final dependency.

The established contract concerns field accesses, dependency calls, mutable-slot reads and writes, branch conditions, and returned statuses. Descriptions such as “acquisition,” “validation,” “cleanup,” and “selection” identify apparent roles, not proven domain semantics.

The operation is not demonstrably transactional. Output writes and dependency effects can precede a returned failure. No rollback is visible.

## Interface

| Requested value | A pointer-shaped 32-bit quantity used numerically and passed to dependencies. This function does not directly dereference it. |
| Output address | Identifies a writable 32-bit output location. Its address value also initializes an internal selected-value slot. |

The result is a 32-bit status. Zero permits continuation after status-producing dependencies. Nonzero statuses generally terminate the current path, sometimes after a cleanup-like call. The function also produces fixed statuses 1, 6, and 8.

### Preconditions and aliasing

Addresses must support the accesses actually reached. The context address is loaded before the mode check. Unsupported modes still require the context byte at offset 17 to be readable.

The output must support a 32-bit write when initialization is reached. No explicit null, alignment, range, or overlap check is present.

No non-aliasing guarantee is established. Output writes may alter subsequently read object or context fields if their storage overlaps. Dependencies may modify reachable memory or global state.

Three internal 32-bit slots matter:

- An initial-handle slot, initialized to zero.
- A secondary-handle slot, initialized to the requested value before acquisition.
- A selected-value slot, initialized to the output address itself, not the output’s contents.

Their addresses are passed to dependencies at different points. In particular, the selected-value slot’s address escapes to F-70fe47664dff. Later dependencies cannot be assumed to preserve that slot. Its subsequent reads are observable parts of the contract.

## Behavior

### Entry checks

The initial-handle slot is initialized to zero. The function then reads the context address and the object’s mode byte.

If the mode is not 2, the context byte at offset 17 determines the result:

- Zero produces status 1.
- Nonzero produces status 8.

These paths call no dependencies and perform no direct output write.

For mode 2, a nonzero 32-bit context field at offset 8 produces status 6, also without dependency calls or direct output writes. A zero field permits acquisition.

### Initial acquisition and validation

The secondary-handle slot receives the requested value. The selected-value slot receives the output address’s 32-bit representation.

F-14f40f321d22 is called with the cached context, requested value, initial-handle slot address, zero, and object address.

A nonzero result is returned immediately. No cleanup-like call follows this failure, even if the dependency wrote the handle slot.

On success, F-fab37d187ad5 is called with the object and requested value. If it returns nonzero, F-6cc778185718 is called with the initial-handle slot’s current contents, and the validation status is returned.

Only after both calls return zero does the function directly write zero to the caller’s output.

### Signed low-value path

The requested value is compared with 2 as a signed 32-bit integer.

For values less than 2:

1. F-f6da3c4a0ea5 receives the current initial handle and constant 9.
2. F-6cc778185718 receives the initial handle read for that later call.
3. The function returns zero.

The operation’s result is ignored. This path includes 0, 1, and every bit pattern representing a negative signed 32-bit value. It does not read context offset 22.

Because the handle slot’s address previously escaped, the two calls are not guaranteed to receive identical handle values if an intervening dependency changes the slot.

### Direct-processing path

For signed requested values at least 2, the function reads context byte 22 after output initialization.

If that byte is zero, F-ff6acbee5e19 is called with the current initial handle. F-6cc778185718 is then called with the initial handle read at that point. The processing status is returned.

There is no selected-value operation or final adjustment on this path.

### Selection and branch choice

If context byte 22 is nonzero, F-70fe47664dff receives the object, constant 4, and selected-value slot address.

A nonzero result causes cleanup of the current initial handle, followed by return of that status.

On success, the selected-value slot is read and compared with the original requested value. Success does not establish that selection wrote the slot. If no dependency has changed it, it still contains the output address’s representation.

This equality comparison chooses a path; it does not freeze the slot’s value. Later calls can change the slot, including calls not explicitly passed its address if the address has been retained or otherwise made reachable.

### Equal-selection path

When the comparison finds equality, F-ff6acbee5e19 is called at a site showing no explicit arguments. F-6cc778185718 is then called with the current initial handle.

A nonzero processing status is returned after cleanup. A zero status proceeds to final adjustment.

The missing explicit arguments are an unresolved interface detail. Neither a zero-argument machine interface nor receipt of the initial handle is established.

This path performs no second direct output write. It also does not guarantee that the selected-value slot still equals the request when final adjustment begins: processing and cleanup occur between the equality test and the adjustment’s snapshot.

### Unequal-selection path

When the comparison finds inequality, the following order applies:

1. F-6cc778185718 receives the current initial handle.
2. F-14f40f321d22 receives the context, the selected-value slot’s then-current contents, the secondary-handle slot address, zero, and object address.
3. A nonzero acquisition result returns immediately, without cleanup for that failed acquisition.
4. On success, F-0b1f5fa1e52e receives the context, current secondary handle, constants 1 and 0, and original requested value.
5. F-6cc778185718 receives the secondary handle read after that operation.
6. A nonzero operation status is returned after cleanup.
7. F-14f40f321d22 receives the context, the selected-value slot’s then-current contents, the secondary-handle slot address, and zero. This site shows four explicit arguments.
8. A nonzero acquisition status returns immediately, without another cleanup call.
9. On success, F-ff6acbee5e19 receives the current secondary handle.
10. F-6cc778185718 receives the secondary handle read after processing.
11. A nonzero processing status is returned after cleanup.

The selected values supplied to the two acquisitions and written to output need not be identical. Each is read after intervening calls. Even the first secondary acquisition need not receive the value used in the earlier inequality comparison, because initial-handle cleanup occurs between them.

The output write precedes final adjustment and contains no adjustment performed directly by that later stage.

### Final adjustment: saved values and mutable-slot reloads

Both successful selection paths reach this stage. Its behavior distinguishes saved pre-call values from the selected-value slot’s mutable contents.

First, the function saves the slot’s current 32-bit value. It computes a one-unit numerical decrement of that saved value and writes the result back into the slot. The decrement is by one byte numerically, not by the size of a four-byte element.

The context’s 16-bit field at offset 28 is then read. F-d7be9cfb4000 receives constant `0x40000000` and that field value.

After the call:

- Its result plus one is compared with the **saved pre-call value minus one**.
- The comparison does not reload the selected-value slot as its right-hand operand.
- On equality, the slot is overwritten with the **saved value minus two**, replacing any slot mutation made during the call.
- On inequality, no replacement is performed. The slot retains its then-current contents, including any dependency mutation.

Next, the slot’s current contents are read as the candidate argument to F-c76bdec3f9e1, together with the context.

After that dependency returns, its 32-bit result is compared with the slot’s **post-call contents**, not with a saved copy of its argument:

- If equal, the post-call slot value is decremented by one and stored back.
- If unequal, the post-call slot value remains unchanged.

Finally, F-676079dace64 receives the object, constant 4, and the slot’s resulting contents. Its status is returned directly.

Consequently, final adjustment is not necessarily a deterministic sequence of decrements from the value originally selected or written to output. For example, if F-c76bdec3f9e1 receives 99, changes the retained slot to 80, and returns 99, equality fails and the final dependency receives 80.

The represented arithmetic uses 32-bit quantities without explicit overflow or lower-bound guards. Bytewise numerical adjustment is established; portable signed-overflow behavior is not.

## Side effects

### Direct writes and their timing

Beyond internal-slot updates, the only explicit memory writes are to the caller’s 32-bit output:

- Zero after successful initial acquisition and validation.
- The selected-value slot’s current contents after successful unequal-path processing and cleanup.

There is no explicit write to the listed object or context fields, though output aliasing can make those stores affect such fields.

A late failure does not undo either output write. Dependencies may independently change the output, so “output remains zero” requires an explicit nonmutation assumption.

### Mutable slots and lifetime

Selected-value mutation is relevant throughout the selected path, not only during selection. Each secondary acquisition argument, the unequal-path output store, the adjustment snapshot, the F-c76bdec3f9e1 argument, its post-call comparison, and the final argument use the reads described above.

The handle slots are likewise passed by address. Cleanup arguments use their current contents at the call sites, not guaranteed original acquisition results.

The supplied body does not establish that dependencies retain slot addresses, but it also does not establish that they refrain from doing so. Safe use of any retained address after the enclosing invocation ends is not demonstrated.

### Ownership and cleanup

F-6cc778185718 occupies cleanup-like positions. Its actual ownership effect is unknown.

Visible call ordering establishes:

- Failed acquisitions are not followed by cleanup for those failures.
- Successful initial acquisition leads to one initial-handle cleanup call on each subsequent visible path.
- Successful secondary acquisitions are followed by cleanup after their associated operations.
- Cleanup results do not determine the enclosing status.

These are call obligations, not proof of freeing, reference counting, unlocking, or rollback.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, assume valid accesses, no relevant aliasing, successful preceding calls, and no dependency mutations beyond those specified.

1. **Unsupported mode:** Mode other than 2 returns 1 when context byte 17 is zero and 8 otherwise. No dependency or direct output write occurs.

2. **Blocked state:** Mode 2 with nonzero context field 8 returns 6 without acquisition or output initialization.

3. **Initial acquisition failure:** Status 12 is returned without cleanup or direct output initialization, even if acquisition changed its handle slot.

4. **Validation failure:** Validation status 5 is returned after initial-handle cleanup. The function has not directly written output.

5. **Signed boundary:** Request 1 takes the constant-9 path; request 2 reaches the byte-22 choice. Bit pattern `0xFFFFFFFF` takes the constant-9 path because its signed interpretation is −1.

6. **Ignored operation result:** A nonzero result from the constant-9 operation does not change the enclosing zero result. Cleanup still occurs.

7. **Direct-processing failure:** With request 2 and byte 22 zero, processing status 7 is returned after cleanup. The direct output store was zero.

8. **Reload between acquisitions:** Suppose inequality is detected with selected value 100. If initial-handle cleanup changes the retained selection slot to 120, the first secondary acquisition receives 120, not 100.

9. **Output reload:** If the last secondary cleanup changes the selection slot to 130 and processing succeeded, the direct output store writes 130. Final adjustment then snapshots the slot at its own read.

10. **Adjustment without mutations:** With adjustment-entry value 100, the slot becomes 99. A first adjustment result of 98 triggers replacement with 98. If F-c76bdec3f9e1 returns 98 without changing the slot, the final argument is 97.

11. **First adjustment mutation, nonmatch:** With saved value 100, suppose F-d7be9cfb4000 changes the slot to 80 and returns 10. The comparison is 11 against saved value 99; it fails. The next dependency receives 80.

12. **First adjustment mutation, match:** Under the same saved value, a result of 98 matches saved value 99 after addition. The function overwrites a dependency-written 80 with 98.

13. **Post-call comparison:** If F-c76bdec3f9e1 receives 99, changes the slot to 80, and returns 99, the final argument is 80. If it instead returns 80, the comparison succeeds and the final argument is 79.

14. **Late failure:** If the unequal path writes output 100 and the final dependency returns 9, status 9 is returned without restoring output.

15. **Selection leaves slot untouched:** If selection succeeds without any slot mutation, the equality test uses the output address’s representation. Success alone supplies no replacement value.
