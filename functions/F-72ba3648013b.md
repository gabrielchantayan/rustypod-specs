# F-72ba3648013b

## Purpose

F-72ba3648013b constructs and initializes an object-like region from four 32-bit input values and returns an address displaced from the region used for most initialization.

The established behavior is a sequence of dependency calls, explicit four-byte stores, and copies between two four-word field groups. The routine supplies the label `iMAPhraseDict` to one dependency. That label suggests a phrase-dictionary-related role, but the supplied evidence does not establish dictionary operations, lookup behavior, or the semantic meaning of the four inputs.

Two address bases must remain distinct:

- **Storage base:** the address returned by F-6e6e5f6a241c.
- **Initialization base:** the address-like result returned by F-8e605db71b8f.

The returned address is the initialization base minus 24 bytes. The evidence does not establish that the initialization base is the storage base plus 24 bytes, even though that interior address is passed to F-8e605db71b8f.

## Behavior

### 1. Preserve the inputs locally

Before the first dependency call, the routine initializes the local four-word region with the four input bit patterns in argument order.

This local region remains the source of the values eventually stored at initialization-base offsets 28 through 40. There is no visible restoration of the original input values after a dependency changes the region.

### 2. Obtain and initialize the storage base

The routine calls F-6e6e5f6a241c with no explicit arguments and uses its result as the storage base.

After that call returns, the routine:

1. Reads one 32-bit value from a global location and stores it at storage-base offset 0.
2. Stores 32-bit zero at storage-base offset 20.

The global read occurs after F-6e6e5f6a241c returns. Consequently, the stored value is the global value available at that point; the routine does not visibly cache it before the call.

The semantic role of that global word is unknown. It could be a type-related or dispatch-related value, but the evidence does not establish that interpretation.

### 3. Obtain the initialization base

The routine calls F-8e605db71b8f with these arguments, in order:

2. Storage base.
3. The string label `iMAPhraseDict`.

The dependency’s result becomes the initialization base. All subsequent object-field accesses in this routine are relative to that result, not directly to the storage base.

Immediately after the dependency returns, the routine stores 32-bit zero at initialization-base offset 52.

No visible check compares the returned base with the first argument, verifies non-nullness, or examines a status value.

### 4. Process the local input region

The routine calls F-9e3528e6ab0e with:

1. The address of the first word of the local input region.
2. Zero.
3. Zero.

No result from this call is visibly used. Its effect on the local region is not established by the supplied evidence.

|---|---|

Each row represents a four-byte read followed by a four-byte write, with rows processed in the listed order. These copies use the just-populated object fields as their sources.

Under ordinary execution without intervening external modification, the two four-word groups therefore contain identical bit patterns when this copy phase finishes.

### 5. Clear additional fields

2. 48

The zero store at offset 52 occurred earlier, before F-9e3528e6ab0e. It is not part of this later clearing sequence.

### 6. Initialize interior regions

1. Calls F-b00260d1087a with initialization base plus 64 bytes.
2. Calls F-046c66ae6de2 with initialization base plus 72 bytes.
3. Stores 32-bit zero at initialization-base offset 76.

No return value from either dependency is visibly consumed.

The arguments identify starting addresses only. They do not establish the sizes or boundaries of the regions those dependencies access. In particular, the call at offset 72 does not prove that its effects are confined below offset 76.

The store at offset 76 occurs after both calls. If either dependency writes that four-byte field and returns normally, this routine’s later zero store supersedes that write. The same ordering applies to the field at offset 84.

### 7. Return the displaced address

No further dependency call, explicit release, or visible validation occurs before return.
