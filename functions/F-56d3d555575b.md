# F-56d3d555575b

## Behavior

### Numeric interpretation

The supplied representation uses 32-bit integer operations for the state comparisons, differences, and increment. The carried argument remains an uninterpreted four-byte value.

The routine distinguishes:

- Equality between a candidate and a captured anchor.
- An outer candidate-to-anchor difference of exactly two.
- An inner candidate-to-anchor difference of exactly one.
- An increment of the first inner-seed snapshot by one.

The subtraction and increment can encounter signed-overflow boundaries. The supplied material does not establish the applicable overflow semantics sufficiently to make a portable claim for those cases. The behavioral descriptions below apply directly where the relevant arithmetic is representable. Wraparound-specific behavior is documented_only unless separately established.

### Entry snapshots

At entry, the routine reads the external state in this order:

1. The inner anchor source, captured for the entire invocation.
2. The outer anchor source, captured for the entire invocation.
3. The outer anchor source again, supplying the initial outer candidate.

The second and third reads are distinct. Their values are not guaranteed to match if the location can change between reads.

The carried value initially consists of four zero bytes.

Neither captured anchor is refreshed during this invocation. Later dependency calls may modify the underlying state locations, but such modifications do not replace the already captured anchors.

### Outer evaluation

An outer evaluation preserves the incoming carried value for possible use by the inner phase. It compares the current outer candidate against the captured outer anchor.

Every such evaluation reads the outer refresh source and installs the input argument as the new carried value. This read occurs even when the current candidate will cause termination.

Two cases follow:

- **Candidate equals the captured outer anchor:** The routine immediately performs another outer evaluation using the just-read refresh value. The value preserved by that next evaluation is consequently the input argument.
- **Candidate differs from the captured outer anchor:** The routine examines the difference calculated from that candidate.

A difference of exactly two causes normal return. No inner-seed or exit-candidate read is required for that terminating outer evaluation.

Any other nonzero difference enters the inner phase. In particular, a difference of one is not a separate outer action; it enters the same inner phase as other nonzero differences except two.

The termination decision concerns the candidate that existed before the outer refresh read. The newly read refresh value does not override that decision.

### Inner initialization

On entry to the inner phase, the routine:

- Reads the inner seed source and forms a successor by adding one.
- Reads the inner seed source again to obtain the initial inner candidate.
- Initializes the inner carried value to zero.

The two inner-seed reads are separate observations. The successor is derived from the first; the initial candidate comes from the second.

The inner phase retains the value preserved by the outer evaluation that entered it. That retained value is either zero or the original input argument.

### Inner evaluation and calls

Every inner evaluation reads the exit-candidate source, including an evaluation that ends the inner phase. Its value becomes the outer candidate available when the inner phase finishes.

The inner candidate is compared with the captured inner anchor.

- **Equal:** The inner phase finishes without executing a call for that evaluation.
- **Different, with a difference of exactly one:** The next inner candidate becomes the previously computed successor. No dependency call occurs on that evaluation.
- **Different, with any other representable difference:** The routine calls F-79f3dd4d913f with the current inner carried value. If the call returns normally, the next inner candidate is forced to equal the captured inner anchor.

A dependency call is therefore followed by one more inner evaluation before the inner phase finishes. That final evaluation reads the exit-candidate source again. Its value, rather than an earlier read from the same phase, supplies the next outer candidate.

The first possible dependency call within an inner phase receives zero. A call reached after a difference-of-one evaluation receives the value retained from the entering outer evaluation.

If arithmetic and control flow remain within the described model and the dependency returns normally, each inner phase makes at most one dependency call.

### Return to the outer evaluation

After the inner phase finishes:

- The next outer candidate is the value from the final exit-candidate read.
- The carried value is restored to the value retained by the entering outer evaluation.
- Both captured anchors remain unchanged.

Consequently, dependency-induced changes to the outer refresh source, inner seed source, or exit-candidate source can affect later reads. Changes to the anchor sources do not update the captured anchors.

### Nontermination

There is no iteration bound, timeout, cancellation check, or explicit error return.

Two directly identifiable unbounded behaviors are:

- Outer evaluations can repeat indefinitely while each candidate equals the captured outer anchor.
- Inner evaluations can repeat indefinitely when the initial candidate is one greater than the captured inner anchor and the fixed successor is also one greater than that anchor.

In the latter case, the routine repeatedly reads the exit-candidate source but does not use that value to decide whether the inner phase finishes. Changing only that source cannot release this inner loop.

A dependency that does not return prevents subsequent progress. Repeated completed inner phases can also produce an unbounded sequence of dependency calls.

## Acceptance examples

These examples are conditional static consequences, not runtime results. Unless stated otherwise, arithmetic is representable, external values remain stable during the example, and any dependency call returns normally.

### Immediate outer termination after entry refresh

Suppose the outer anchor source supplies an anchor, and the outer refresh source is always two greater than that anchor.

The initial candidate equals the anchor because both entry reads agree. The first outer evaluation therefore repeats after reading the refresh source. The second evaluates the difference of two, reads the refresh source again, and returns.

Expected observations:

- Two outer-refresh reads.
- No inner-seed reads.
- No exit-candidate reads.
- No dependency calls.

### Inner phase with no call

Suppose:

- The outer refresh source is one greater than the outer anchor.
- The inner seed source equals the inner anchor.
- The exit-candidate source is two greater than the outer anchor.

The first inner candidate equals the captured inner anchor, so that phase finishes after one exit-candidate read without calling the dependency. The next outer evaluation returns after its mandatory outer-refresh read.

### Dependency receives the original argument

Use the preceding outer and exit-candidate conditions, but make the inner seed source one greater than the inner anchor.

The initial inner difference is one, so no call occurs on the first inner evaluation. The successor is two greater than the inner anchor, causing a call on the second evaluation.

Expected observations:

- One dependency call, receiving the original input bit pattern.
- Three exit-candidate reads: before the first decision, before the call-producing decision, and during the final equality evaluation.
- Subsequent outer termination.

### Dependency receives zero

Use the same outer and exit-candidate conditions, but make the inner seed source three greater than the inner anchor.

The initial inner difference is neither zero nor one. The dependency is called immediately with zero, regardless of the original argument.

After normal dependency return, the final inner evaluation reads the exit-candidate source again and finishes.

### Distinct entry reads change the forwarded value

Suppose the two entry reads of the outer anchor source differ. The captured anchor comes from the first of those reads; the initial candidate comes from the second.

If that initial candidate differs from the captured anchor by neither zero nor two, the routine enters the inner phase without first repeating an equal outer evaluation. Its retained outer value is therefore still zero.

If the inner path later reaches a call after a difference-of-one evaluation, that call receives zero rather than the original argument.

### Inconsistent seed snapshots produce an inner loop

Suppose the first inner-seed read equals the captured inner anchor, while the second is one greater.

The computed successor and the initial candidate are both one greater than the anchor. Inner evaluations repeat indefinitely, reading the exit-candidate source each time and never calling the dependency.

### Dependency mutation affects the next outer candidate

Suppose an inner phase reaches a dependency call. During that call, F-79f3dd4d913f changes the exit-candidate source.

After the call returns, the mandatory final inner evaluation reads the updated value. That observation supplies the next outer candidate, subject to any further external mutation before the read.

The previously captured anchors remain unchanged.
