# F-3c883910e11f

## Purpose

F-3c883910e11f dispatches a query using a category selector and a property selector. Three selector pairs are recognized:

- Category `0x2300`, property `0x0D1C`: retrieve one indexed 32-bit word and write it to the caller’s output destination.
- Category `0x2300`, property `0x8573`: retrieve a different indexed 32-bit word and write it to that destination.
- Category `0x2300`, property `0x2201`: read four indexed bytes, compute four separate 32-bit local values, and call F-01be51f7fed7 with the address of the first local value.

The component path does **not** establish that the four local values form an array, occupy consecutive addresses, or are all accessible to the dependency through the supplied pointer.

Every other selector pair invokes F-375c8199e7c2 with the context and `0x500`, then returns zero if that call returns normally.

These are mechanically established operations. Application-level meanings for the retrieved words, components, and `0x500` remain unknown.

## Behavior

### Dispatch

The function first determines whether the category is `0x2300`.

If it is not, the function calls F-375c8199e7c2 with the supplied context and the constant `0x500`. It then returns `0`, conditional on normal completion of that call.

For category `0x2300`, properties `0x0D1C`, `0x2201`, and `0x8573` select the operations below. Any other property follows the same unsupported-request path.

No direct index read, indexed data read, or output store occurs on the unsupported path.

### Property `0x0D1C`: word retrieval

The function reads the index at context offset `0x24C`, then reads the 32-bit word at:

\[
\text{context} + 0x97C + 0x24i.
\]

It writes that word to the caller’s output destination and returns `1`.

The transfer preserves the word’s 32-bit pattern. No scaling, masking, range validation, or semantic interpretation is visible. Neither dependency is called.

The index and source word are obtained before the output write.

### Property `0x8573`: word retrieval

This path performs the same read-and-write operation using:

\[
\text{context} + 0x978 + 0x24i.
\]

For the same index, this location is four bytes below the source used by property `0x0D1C`.

The function reads the index, reads the selected word, writes that word to the output destination, and returns `1`. Neither dependency is called.

For both word paths, an output destination overlapping context storage can change that storage. The selected word is read before this overwrite, and no subsequent context read is visible on the path.

### Property `0x2201`: component computation

The function reads the index once and uses it to select four component bytes. Their source-read order is:

1. Offset `0x965 + 0x24 × i`.
2. Offset `0x966 + 0x24 × i`.
3. Offset `0x967 + 0x24 × i`.
4. Offset `0x968 + 0x24 × i`.

Each byte is treated as unsigned. For a byte value \(b\), the corresponding computed value is:

\[
E(b)=257b+\left\lfloor b/128\right\rfloor.
\]

The repeated-byte contribution \(257b\) ranges from zero through `65535`. The added term is zero below `0x80` and one from `0x80` upward. Consequently, the complete result ranges from zero through `65536`, inclusive. It must not be truncated to 16 bits.

The source describes four separate 32-bit local values, corresponding respectively to the four input bytes. The visible preparation order is:

- Read the first and second bytes.
- Compute the first local value.
- Read the third and fourth bytes.
- Compute the second, third, and fourth local values, in that order.
- Call F-01be51f7fed7 with the address of the first local value.

All four computations precede the dependency call. However, the only explicit argument is the address of the first local value. The source does not establish a four-element array, adjacency of the separate locals, a 16-byte readable region beginning at that address, or access by the dependency to the other three values.

After F-01be51f7fed7 returns normally, the function returns `1`. It does not directly write to the caller’s output destination.

The separated reads do not establish atomic snapshot behavior. Concurrent changes to context storage could matter, but supported concurrency semantics are unknown.

No direct context write is otherwise visible. The unsupported path performs no direct output write.
