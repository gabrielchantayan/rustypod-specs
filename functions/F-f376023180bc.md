# F-f376023180bc

## Purpose

F-f376023180bc performs an indexed operation against state associated with a supplied context. For an index that passes its range checks, it delegates the operation to F-5ef10d079522, supplies an output region beginning two bytes after the caller’s output address, and replaces the output’s first two bytes with a value derived from a dependency-controlled 32-bit word.

The function returns the delegated operation’s 32-bit result unchanged. If the index fails validation, it returns the bit pattern `0xFFFFFFCE`.

This is a source-facing contract based on static evidence only. The operation’s application-level meaning, the meaning of its output payload, and the interpretation of its return codes are not established.

## Interface

The function has three inputs and one 32-bit return value:

| Input | Established role |
|---|---|
| Context address | Identifies memory containing a table pointer and an unsigned entry count. Also passed to F-8ff48652068d. |
| Index | A 32-bit unsigned value. Validation additionally interprets its bit pattern as a signed 32-bit value. |
| Output address | An address used immediately for a two-byte zero write. For accepted indices, the following bytes are exposed to F-5ef10d079522 as an output region. |

The recovered representation uses 32-bit address-bearing values and four-byte table entries. The output’s leading field is two bytes wide. No byte order is established by the supplied evidence.

The following offsets are observable:

F-8ff48652068d returns an address-like value. A further 32-bit address-bearing value is read at offset `0xF60` from that returned location. Adding `0x118` to the loaded value produces the first argument supplied to F-5ef10d079522.

These offsets establish accessed locations, not complete structure definitions. No layout, ownership, or meaning is established for intervening memory.

### Output layout

The output is treated as:

- A two-byte leading field at the supplied output address.
- A dependency-accessible region starting at output address + `2`.

There is no output-capacity argument. The required size of the second region cannot be determined from this function alone.

### Preconditions

For ordinary completion, the output address must support the initial two-byte write. This requirement applies even when the index will be rejected.

The context and the memory accessed by F-8ff48652068d must satisfy that dependency’s requirements. For index validation to reach the count comparison, context + `0xE78` must be readable. For the accepted path, the table entry, the returned-state field, and all memory required by F-5ef10d079522 must also be valid.

A null output address is not a safely handled error input: it is written through before the function checks whether it is null.

## Behavior

### Initial output write and preliminary dependency

The first observable operation is a two-byte zero write at the output address.

After that write, the function calls F-8ff48652068d with the context address. This call occurs before index validation, including for an index whose signed interpretation is negative or whose unsigned value is outside the entry count.

The initial write therefore cannot be treated as occurring after validation. Likewise, the preliminary dependency cannot be omitted merely because an index is known to be invalid.

If the output aliases context memory or other state used by the preliminary dependency, that dependency encounters the state after the initial zero write. No non-aliasing precondition is established by the supplied evidence.

### Index validation

After F-8ff48652068d returns, validation requires all of the following:

1. The output address is non-null.
2. The index, interpreted as a signed 32-bit value, is nonnegative.
3. The index, interpreted as an unsigned 32-bit value, is strictly less than the 32-bit count read at context + `0xE78`.

The conditions are short-circuited in that order. In particular, an index with bit 31 set fails the signed comparison without requiring the count read.

The accepted numeric index range is therefore the intersection of:

- `0` through `0x7FFFFFFF`; and
- values strictly below the observed unsigned count.

A count greater than `0x80000000` does not make indices with bit 31 set acceptable.

The count is read after the preliminary dependency returns. Its value is not captured before that call. If the dependency changes the count, validation uses the subsequent value.

If validation fails and execution reaches the explicit return, the function returns `0xFFFFFFCE`. Under a signed 32-bit interpretation, that bit pattern represents −50. No application-specific name for this result is established.

F-5ef10d079522 is not called on this rejected path.

### Accepted-index delegation

For an accepted index, the function initializes a private 32-bit working word to the original index. It then calls F-5ef10d079522 with four arguments:

1. The address formed by loading the address-bearing field at offset `0xF60` from the preliminary dependency’s result, then adding `0x118`.
2. The 32-bit value loaded from the context’s table at the selected index.
3. The output address advanced by two bytes.
4. The address of the private 32-bit working word.

The fourth argument permits the dependency to read or modify that word. Consequently, the leading output field is not necessarily derived from the original index.

The table pointer and selected entry are read after the preliminary dependency has returned and after index validation has succeeded. They must not be assumed to retain values that existed before the dependency call.

The supplied representation does not establish a left-to-right evaluation order among the independent memory reads used to construct arguments for F-5ef10d079522. It does establish that those argument values are obtained before the delegated call and that the leading output field’s final write occurs afterward.

### Leading-field transformation and return

After F-5ef10d079522 returns normally, the function transforms the then-current 32-bit working word and stores a two-byte result at the original output address.

The transformation selects bits 1 through 16 of the working word and places them in bits 0 through 15 of the output field. Bit 0 is discarded, as are bits 17 through 31.

Equivalently, for an unsigned working value \(w\), the stored 16-bit bit pattern is:

\[
\left\lfloor \frac{w \bmod 2^{17}}{2} \right\rfloor
\]

This follows from a 32-bit unsigned left shift by 15 followed by a logical right shift by 16. It is not an arithmetic right shift, a full-width division by two, or saturation.

The delegated result does not control whether this final write happens. After a normal return from F-5ef10d079522, the write occurs regardless of the returned 32-bit value.

The function then returns that delegated result unchanged.

## Side effects

The function directly performs:

- An unconditional two-byte zero write to the output before any dependency call.
- A call to F-8ff48652068d before validation.
- Conditional reads of the count, table pointer, selected table entry, and dependency-derived address field.
- On the accepted path, a call to F-5ef10d079522.
- After that call returns, a two-byte write replacing the output’s leading field.

The initial zero is not necessarily the output’s final value on a rejected path. F-8ff48652068d may have access to aliased or shared memory; its side effects are unknown. Similarly, the bytes following the leading field must not be described as unchanged merely because F-5ef10d079522 was not called.

No direct allocation, release, or ownership transfer is visible in this function. That observation does not establish that either dependency avoids allocating, releasing, retaining addresses, or modifying shared state.

The working word has a lifetime local to this invocation. The evidence establishes that its address is passed to F-5ef10d079522, but does not establish whether the dependency retains it. Safe behavior requires that the dependency not use that address after its lifetime ends.

If memory accesses fault or a dependency does not return normally, the source provides no recovery path or rollback guarantee. The initial write and any completed dependency side effects may already have occurred.

## Acceptance examples

These examples are conditional on valid memory and normally returning dependencies. Dependency behavior stated in an example is an explicit condition, not an inferred guarantee.

1. **Index equal to count.**  
   With index `4` and a count of `4` observed after F-8ff48652068d, validation fails. The initial zero write and preliminary dependency call occur. F-5ef10d079522 is not called, and the returned bit pattern is `0xFFFFFFCE`.

2. **High-bit index.**  
   With index `0x80000000`, validation fails the signed nonnegative condition even if the stored count is `0xFFFFFFFF`. The count comparison is not reached. The preliminary dependency has nevertheless already been called.

3. **Zero count.**  
   With index `0` and observed count `0`, validation fails because the comparison is strict. A zero index is accepted only if the observed count is positive.

4. **Unmodified working word.**  
   With index `6`, an observed count greater than `6`, and a delegated call that leaves the working word unchanged, the final leading field is `0x0003`. The function returns the delegated result unchanged.

5. **Dependency changes the working word.**  
   With any accepted index, if the delegated call leaves the working word as `0x00020003`, the final leading field is `0x0001`. Bit 17 is discarded; the result is not `0x00010001`.

6. **Maximum leading-field pattern.**  
   If the delegated call leaves the working word as `0xFFFFFFFF`, the final leading field is `0xFFFF`. A signed interpretation of that two-byte field is separate from its established stored bit pattern.

7. **Failure-like delegated result.**  
   If the delegated call returns `0xFFFFFFCE` normally and leaves the working word as `2`, the function still stores `0x0001` in the leading field and returns `0xFFFFFFCE`. The return value alone cannot identify which path produced it.

8. **Count changed by the preliminary dependency.**  
   If the count is initially `1` but F-8ff48652068d changes it to `3`, index `2` passes the subsequent count check, provided all other conditions and memory requirements hold.

9. **Null output address.**  
   No graceful rejection is promised. The first attempted operation is a two-byte write through that address, before the null check or preliminary dependency call.
