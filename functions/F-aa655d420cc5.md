# F-aa655d420cc5

## Purpose

F-aa655d420cc5 initializes or updates a caller-supplied output object, then performs a selector-dependent output operation or fallback action.

Two 32-bit input fields control the behavior:

- The field at byte offset `+0x18` selects the initial operation and, when initially nonzero, supplies a subsequently reread formatting argument.
- The field at byte offset `+0x08` selects one of four later operations or the fallback path.

The function reads an external table-pointer global twice before its first dependency call. The entry read supplies the retained table address for recognized-selector lookups. A separate read, after the initial numeric-field test, supplies the table address for the initial lookup. These addresses are not established to be equal.

Output construction, formatting, replacement, and clearing are useful descriptions of the apparent intent. Only the calls, arguments, direct memory operations, ordering, and return propagation specified below are established. Dependency implementations and external data contents are unavailable.

## Interface

### Arguments and representation

The function accepts:

1. **Input-object address:** identifies an object with readable 32-bit fields at offsets `+0x08` and `+0x18`.
2. **Output-object address:** passed to output-related dependencies. On fallback paths, its first word is directly read as a backing-storage address and may be overwritten.

The supplied representation uses 32-bit integer, pointer-bearing, and table-slot accesses. This contract describes that representation; behavior under a wider pointer model is not established.

| Location | Access width | Established role |
|---|---:|---|
| Input `+0x08` | 32 bits | Selector compared with up to four external values |
| Input `+0x18` | 32 bits | Initial zero/nonzero test; reread for formatting on the nonzero branch |
| Output `+0x00` | 32 bits | Backing-storage pointer on fallback paths |
| Backing storage `−0x0C` | 32 bits | Zero/nonzero test on one fallback path |
| Backing storage `−0x04` | 32 bits | Argument to a dependency, or destination of a zero write |

No other input-object fields are directly accessed.

## Behavior

### 1. Retain the selector-table address

The function first reads the external table-pointer global and retains the resulting 32-bit address.

This retained address is used only if the later selector matches one of the four recognized values. Retaining the address does not retain a snapshot of table contents: the selected table slot is read later, after the initial-output dependencies have executed.

### 2. Select and perform the initial output operation

After retaining the entry table address, the function reads the input field at `+0x18` and tests whether its 32-bit value is zero.

It then rereads the external table-pointer global on whichever branch was selected. The initial table lookup uses this second global read, not the address retained at entry:

| Initial field value | Slot read through the second table address |
|---|---:|
| Zero | `+0x14` |
| Nonzero | `+0x18` |

The established order is:

1. Read the table-pointer global for later selector use.
2. Read and test the input field at `+0x18`.
3. Read the table-pointer global again.
4. Read the selected initial slot through that second address.
5. Call F-0fdd13c3e50f with the output-object address and the slot’s 32-bit value.

There is no dependency call between the two global reads. Nevertheless, the supplied representation contains two reads; it does not establish that they necessarily observe the same address. The permitted mechanisms for changes between these reads, including any concurrency rules, remain undocumented.

If the initial field was zero, the initial-output stage ends after F-0fdd13c3e50f.

If it was nonzero, the function continues in this order:

1. Call F-5732b2d5ea03 with the output-object address and a fixed external data address.
2. Reread the input field at `+0x18`.
3. Call F-95f1655a5c87 with the local 64-byte buffer, a second fixed external data address, and the reread 32-bit field value.
4. Call F-5732b2d5ea03 with the output-object address and the temporary-buffer address.

All dependency return values in this stage are ignored.

The numeric value passed to F-95f1655a5c87 is not necessarily the value that selected the nonzero branch. Earlier dependencies could modify the input through an alias or other reachable state. Such a change does not cause branch selection to be repeated: a later zero value is still passed through the nonzero branch’s formatting sequence.

The temporary buffer is not explicitly initialized before the formatting call. Its written extent, contents, termination, and failure-state contents are dependency-defined.

### 3. Classify the selector

After the entire initial-output stage, the function reads the 32-bit selector at input offset `+0x08`.

It compares this captured selector against four external 32-bit values in order. The comparison values occupy consecutive four-byte positions in an external region. Later comparisons are reached only if earlier comparisons fail.

The first equality selects a table slot:

| First matching comparison | Slot relative to the entry-retained table address |
|---|---:|
| First | `+0x04` |
| Second | `+0x08` |
| Third | `+0x0C` |
| Fourth | `+0x10` |

The selected 32-bit table value is read at this stage. The function calls F-5732b2d5ea03 with the output-object address and that value, then returns the dependency’s result.

The external table-pointer global is not reloaded for this lookup. A dependency changing that global during initialization does not redirect the recognized-selector lookup. A dependency changing the selected slot within the entry-retained table can affect the value subsequently read.

The comparison values are not established to be distinct. Duplicate matches resolve to the earliest comparison. Equality operates on the 32-bit values; no signed ordering or numeric conversion is involved.

The selector itself is read only after initialization, so initialization dependencies can affect which selector branch is taken.

### 4. Handle an unrecognized selector

If all four comparisons fail, the function calls F-1cb585febd84 with a fixed fallback-data address. That address is 16 bytes after the start of the comparison-value region.

After the call returns, the function reads the backing-storage pointer from the output object’s first word. This read occurs before branching on the probe result.

#### Nonzero probe result

The function:

1. Reads the 32-bit word four bytes before the just-read backing address.
2. Calls F-5aa61f6c87d1 with, in order:
   - The output-object address.
   - Zero.
   - The metadata word just read.
   - The fixed fallback-data address.
3. Returns that dependency’s result.

No direct fallback-clearing writes occur on this branch.

The metadata might represent a length, and the operation might replace a range beginning at zero. These are inferred interpretations, not established dependency semantics.

#### Zero probe result and zero metadata at `−0x0C`

The function reads the 32-bit word 12 bytes before the backing address. If that word equals zero, it:

1. Writes a 32-bit zero four bytes before the previously read backing address.
2. Rereads the backing pointer from the output object’s first word.
3. Writes one zero byte at the newly read backing address.
4. Returns the original output-object address.

The order and pointer reread are part of the contract. The byte write must not be described as necessarily using the earlier backing address: aliasing could make the intervening metadata write affect the output object’s pointer word.

#### Zero probe result and nonzero metadata at `−0x0C`

If the metadata word is nonzero, the function:

1. Calls F-8a5aadac202f with the output-object address.
2. Reads an external 32-bit reset-pointer value after that call returns.
3. Writes the value into the output object’s first word.
4. Returns the original output-object address.

Any nonzero 32-bit metadata representation selects this branch, including one that would be negative under a signed interpretation.

The function makes no direct write to the old backing storage on this branch. Effects of F-8a5aadac202f remain unknown.

## Side effects

### Direct memory effects

The visible function can directly write:

- A 32-bit zero at backing offset `−0x04`.
- A zero byte through a freshly reread output backing pointer.
- An external reset-pointer value into the output object’s first word.

These direct writes occur only on zero-probe fallback paths. Initialization and recognized-selector output changes are dependency-mediated.

The local temporary buffer is supplied as a destination to F-95f1655a5c87 and then as an argument to F-5732b2d5ea03.

### Observable state timing

These statements establish sequencing, not concurrency safety.

No ownership transfer is established for the input object, output object, table values, fixed data, or backing storage.

## Acceptance examples

The following are conditional acceptance criteria from static evidence, not executed tests.

### Distinct addresses from the two table-global reads

Suppose the entry global read yields table address A, the second read yields table address B, and all relevant accesses are valid.

With an initially zero numeric field and a later selector matching the first comparison:

- F-0fdd13c3e50f receives the value read from B at `+0x14`.
- The final F-5732b2d5ea03 call receives the value read from A at `+0x04`.
- The final call’s result is returned.

This example does not assert a supported mechanism for changing the global between reads. It specifies the consequences if the reads observe different addresses.

### Global and table changes during initialization

Suppose both early global reads yield A. During initialization, a dependency changes the global to B and changes A’s fourth selector slot.

If the eventual selector first matches the fourth comparison:

- The selector lookup still uses A at `+0x10`, not B.
- It observes the slot value when that later lookup occurs, rather than an entry-time snapshot.

### Numeric field changed before formatting

Suppose the initial numeric field is nonzero and an initialization dependency changes it to zero before the formatting-argument reread.

The nonzero initialization sequence still runs. F-95f1655a5c87 receives zero, and the selector is read only after the temporary-buffer output call.

### Duplicate comparisons

If the first and fourth comparison values equal the captured selector, the first comparison wins. The selector-table slot is `+0x04` relative to the entry-retained address.

### Nonzero fallback probe

If no selector matches and the probe returns nonzero:

- The backing pointer is read after the probe.
- Metadata at backing offset `−0x04` is passed unchanged as the third argument to F-5aa61f6c87d1.
- Its second argument is zero.
- Its result is returned without direct clearing writes.

### Zero probe with zero clearing metadata

If the probe returns zero and metadata at `−0x0C` is zero, the 32-bit metadata zero write precedes the backing-pointer reread and zero-byte write. F-8a5aadac202f is not called. The original output-object address is returned.

### Zero probe with nonzero clearing metadata

If the probe returns zero and metadata at `−0x0C` is nonzero, F-8a5aadac202f runs before the external reset pointer is read. If that dependency changes the reset pointer, the subsequent read supplies the value stored into the output object. The original output-object address is returned.
