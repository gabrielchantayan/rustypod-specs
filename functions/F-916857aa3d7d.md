## Behavior

### Call-sequence conventions

All calls described here are indirect. Their identities and contracts are unresolved.

A **five-call sequence** consists of an initial call with the specified arguments, followed by four calls with no explicit arguments shown. The fifth call produces the named result.

A **nine-call forwarding sequence** consists of:

- An initial call with the specified argument.
- A no-explicit-argument call whose result is passed to the next call.
- Another no-explicit-argument call whose result is passed to the following call.
- Four further no-explicit-argument calls, the last producing the named result.

A **seven-call forwarding sequence** consists of an initial call with the specified arguments, a no-explicit-argument call producing a result, a call receiving that result, and four further no-explicit-argument calls. The seventh call produces the named result.

These descriptions specify visible argument and result flow, not shared helper implementations. “No explicit arguments” does not exclude hidden machine-state inputs.

### Initial word stores

The first direct memory operation is a 32-bit store:

- Address: second input multiplied by \(2^{26}\), plus 20.
- Value: scaled input.

This store precedes every indirect call.

The subsequent order is:

| Stage | Calls and result | Immediately following direct operation |
|---|---|---|
| 1 | Five-call sequence starting with the scaled input; result **A** | Store the scaled input at \(4A+20\) |
| 2 | Five-call sequence starting with \(4A\); result **B** | Store \(4B\) at \(16B+20\) |
| 3 | Nine-call forwarding sequence starting with \(4B\); result **C** | Store \(4B\) at \(4C+20\) |
| 4 | Five-call sequence starting with \(4C\); result **D** | Store \(4D\) at \(16D+20\) |
| 5 | Nine-call forwarding sequence starting with \(4D\); result **E** | Store the reduced input at \(4E+20\) |
| 6 | Five-call sequence starting with \(4E\); result **G** | Store \(4G\) at \(16G+20\) |

Every listed store is 32 bits. Results **A**, **B**, **C**, **D**, **E**, and **G** are represented through signed 32-bit intermediates. The bit pattern of \(4D\) is also saved as an unsigned 32-bit quantity for later selector calculation.

The first call’s target is formed from incoming link-related state plus 4094. Later targets are formed from embedded address bases and offsets. Neither their argument values nor repeated call shapes establish that their identities are equal.

### Saved selector and repeated word destination

After stage 6, define:

- **Record address:** \(16G\).
- **First selector index:** the unsigned saved bit pattern of \(4D\), masked with \(0x7fffffff\), then logically shifted right by 7.
- **First selector address:** first selector index plus 1.

A five-call sequence starts with three arguments:

1. Record address.
2. Record address again.
3. Third input logically shifted right by 7.

Let its final signed 32-bit result be **H**.

The next direct operation stores the record address as a 32-bit value at record address plus 20. This repeats the destination used immediately after stage 6, but changes the supplied value from \(4G\) to \(16G\).

The intervening calls may observe or modify that location. No preservation of its earlier contents is assumed.

A further five-call sequence starts with **H** shifted left by 2. Its final result, **J**, is represented as unsigned 32 bits.

### First two byte-selected writes

The function reads one unsigned byte from the first selector address. For the byte \(b\) actually read, it stores the low byte of \(4J\) at address \(b+17\).

A seven-call forwarding sequence then starts with three equal arguments, each carrying the 32-bit pattern of \(4J\). Its final result is **K**, represented as signed 32 bits.

The function reads the first selector address again. For this newly read byte \(b\), it stores the low byte of

at address \(b+17\).

These are separate selector reads. Intervening calls, aliasing stores, or external activity may change the selector byte. The second destination is not required to equal the first.

Although the masked shift can produce a value larger than 255, the byte store retains only its low 8 bits.

### Third-input-derived write and two clears

A five-call sequence starts with **K** shifted left by 2. Its final result, **L**, is represented as unsigned 32 bits.

The next direct operations are ordered as follows:

1. Store the low byte of \(4L\) at address \((\text{third input}\gg15)+28\).
2. Read one unsigned byte from the first selector address.
3. Store zero at that byte’s value plus 17.

The address shift is logical. It is equivalent to shifting the saved reduced input right by another 7.

The next seven calls have a distinct argument pattern:

- First call: third input logically shifted right by 15.
- Second call: no explicit arguments.
- Third call: \((L\mathbin{\&}0x3fffffff)\gg6\).
- Four further calls: no explicit arguments.

The seventh call produces signed 32-bit result **M**. No forwarding of the second call’s result into the third call is shown.

After these calls, the function reads the first selector address again and stores zero at the newly read byte’s value plus 17.

The two clears cannot be merged: each has its own selector read, and seven calls intervene. The first clear can also alter a later selector read if its destination aliases the selector address.

### Second selector and loop entry

A five-call sequence starts with **M** shifted left by 2. Its final result, **N**, is represented as unsigned 32 bits.

The function derives:

- **Initial loop field:** \((N\mathbin{\&}0x3fffffff)\gg25\).
- **Second selector address:** the saved 32-bit pattern of \(4L\), held in a signed intermediate, multiplied by 1024, then increased by 1.

Under the conditional 32-bit bit-pattern model, the latter address calculation is equivalent to retaining the low 32 bits of \(4096L+1\). Its actual signed-overflow and address-conversion behavior remains unresolved.

One byte is read from the second selector address, and zero is stored at that byte’s value plus 17.

The initial loop field is in the inclusive range 0 through 31. Execution then makes:

1. A call receiving twice the initial loop field.
2. A no-explicit-argument call producing the initial signed 32-bit **loop value**.

No direct store separates those two calls.

### Unconditional loop and target transition

Each iteration has this observable order:

1. Call an indirect target with the current loop value and the current loop field logically shifted right by 8.
2. Make four no-explicit-argument calls; the last produces signed 32-bit result **P**.
3. Read one byte from the fixed second selector address.
4. Store zero at that byte’s value plus 17.
5. Call an indirect target with **P** shifted left by 2.
6. Make four no-explicit-argument calls; the last produces signed 32-bit result **Q**.
7. Use **Q** shifted left by 2 as the next loop value.
8. Use the 32-bit pattern of **Q** shifted left by 26 as the next unsigned loop field.
9. Repeat without a visible termination condition.

**The target in step 1 changes after the first iteration.** On first entry, it is formed from the target base established immediately before the loop. During the iteration, that target-forming state is overwritten; the final overwrite supplies the base used by step 1 of the next iteration.

Consequently:

- The first iteration uses an entry-specific target.
- The second and all subsequent iterations use a different, recurring target.
- The recurring base is 62 bytes above the entry-specific base, and both use the same added displacement.
- The recurring target does not continue advancing each iteration: the same embedded base is installed again on every pass.

This distinction is established by visible target formation; it does not require resolving either dependency’s identity or behavior. Architectural interpretation of executable addresses remains unknown.

Each completed iteration contains ten indirect calls, one direct byte read, and one direct byte store.

The first iteration’s second explicit argument is zero because the initial loop field is at most 31. Under the conditional 32-bit bit-pattern model, subsequent iterations receive:

\[
(Q_{\text{previous}}\mathbin{\&}63)\ll18
\]

as that second argument.

The second selector address is retained across iterations. Its byte is reread each time; its contents are not cached.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes all preceding calls return and relevant accesses succeed. Overflow-dependent examples additionally assume the stated 32-bit bit-pattern model.

### Initial zero input

If the second input is zero, the first direct operation stores a 32-bit zero at address 20, before any indirect call.

If the third input is also zero, its shifts by 7, 8, and 15 are zero. Later call-derived addresses need not be zero.

### Selector rereading

Suppose **J** is \(0x01234541\), and the first selector read produces 3. The first byte-selected store writes \(0x04\) at address 20.

If the intervening calls change the selector byte to 9, the next selector-based store writes \(0x12\) at address 26. It does not reuse the earlier selector value.

### Repeated word destination

If **G** is 2, the store immediately after stage 6 writes 8 at address 52. After the next five-call sequence, the repeated-destination store writes 32 at address 52.

The calls between those stores are not required to preserve address 52.

### Maximum third input

For a third input of \(0xffffffff\):

- Reduced input is \(0x00ffffff\).
- The record-address sequence receives \(0x01ffffff\) as its third argument.
- The direct third-input-derived byte-store address is 131099.

These calculations do not establish address validity.

### Loop state and target transition

For every possible **N**, the first loop iteration receives zero as its second explicit argument and uses the entry-specific target.

If that iteration finishes with **Q** equal to 1, the second iteration uses the recurring target, receives loop value 4, and receives second argument \(0x00040000\).

If an iteration finishes with **Q** equal to 64, the next loop value is 256 and the next second argument is zero under 32-bit bit-pattern arithmetic.

Every iteration after the first uses the recurring target, regardless of these result values.
