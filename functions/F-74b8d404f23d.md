# F-74b8d404f23d

## Purpose

F-74b8d404f23d derives a subdivision count from three two-dimensional coordinate pairs and a dependency-supplied adjustment. It then either submits two coordinate pairs directly or processes a quadratic-style subdivision through scratch storage embedded in a caller-supplied context.

The established observable behavior is an ordered sequence of context reads and writes and calls to F-870c4fcf7295 and F-7ed325e66f98. No return value is exposed.

**Inferred intent:** approximate a quadratic curve, traversing from the context’s existing endpoint toward a supplied endpoint. The vertical-range check appears to avoid further subdivision outside a relevant vertical interval. It does **not** discard those portions: they still generate coordinate submissions.

These geometric interpretations do not establish what either dependency does with coordinates, whether coordinates represent pixels, or whether submissions update the context’s current position.

## Interface

The function accepts four arguments:

1. **Context address.** A writable address represented by a 32-bit integer in the supplied representation. The function accesses fields at fixed byte offsets.
2. **Control-pair address.** An address from which two consecutive signed 32-bit coordinate words can be read.
3. **Endpoint-pair address.** An address from which two consecutive signed 32-bit coordinate words can be read.
4. **Auxiliary word.** An opaque 32-bit value forwarded unchanged to F-870c4fcf7295.

The coordinate pairs are ordered horizontal component first, vertical component second.

### Context layout

| Byte offset | Width | Established use |
|---|---:|---|
| +0x14 | 32 bits | Signed lower vertical comparison bound |
| +0x18 | 32 bits | Signed upper vertical comparison bound |
| +0x38 | 32 bits | Horizontal current-coordinate field |
| +0x3C | 32 bits | Vertical current-coordinate field |
| +0x44 onward | 32-bit words | Overlapping coordinate-subdivision records |

The coordinate scratch records contain three consecutive coordinate pairs, but successive records begin only 16 bytes apart. Adjacent records therefore share a coordinate pair. They are not independent 24-byte objects.

Under ordinary execution with valid arithmetic and without dependencies disturbing traversal state:

- At most 17 subdivision-count entries are needed, spanning +0x34C through +0x38F.
- Coordinate scratch can extend through +0x15B.
- The field at +0x4E0 must be readable before the adjustment dependency is called.

These bounds describe this function’s direct accesses, not additional memory requirements of either dependency.

### Preconditions and return

The function performs no explicit pointer, alignment, length, capacity, or context-validity checks. All addresses actually used must support the corresponding 32-bit accesses. The representation does not establish byte order.

The function returns without an explicit result. It has no local allocation or deallocation operation.

Aliasing is not rejected. However, overlapping input pairs with context fields or scratch memory can change behavior because some inputs are saved early while others are reread after context writes. The ordinary geometric interpretation requires those interactions not to corrupt the intended data.

## Behavior

### Arithmetic conventions

Coordinates, bounds, subdivision counts, and dependency results are treated as signed 32-bit quantities.

The supplied representation distinguishes:

- Arithmetic right shifts by two or eight bits.
- Signed comparisons.
- Division by two with truncation toward zero.
- Division by four implemented with a negative-value correction before an arithmetic shift, also producing truncation toward zero when the arithmetic is representable.

An arithmetic shift by two is not interchangeable with signed division by four for negative values. For example, shifting −1 right by two produces −1, whereas division of −1 by four with truncation toward zero produces 0.

Overflow behavior is not safely established by the supplied source representation. Sums, negation, multiplication, and left shifts must not be silently replaced by unbounded mathematical arithmetic. The behavioral formulas below apply directly when their signed intermediate values are representable. Overflow cases are documented under uncertainties.

### 1. Capture initial coordinates

The initial reads occur in this order:

1. Endpoint horizontal component.
2. Context current horizontal component at +0x38.
3. Control horizontal component.
4. Endpoint vertical component.
5. Context current vertical component at +0x3C.
6. Control vertical component.

These values are saved for the initial deviation calculation and, if selected, the direct-submission branch.

For each axis, the function forms:

- The saved endpoint component.
- Plus the saved context component arithmetically shifted right by two.
- Minus twice the saved control component.

It takes the signed magnitude of each result and selects the larger magnitude. Call that selected deviation **D**.

The calculation uses the context component shifted before addition. It does not first combine all three terms and then divide their total.

### 2. Obtain and convert the adjustment result

F-870c4fcf7295 is called once, with arguments in this order:

1. D.
2. The 32-bit context word read from +0x4E0.
3. The original endpoint-pair address.
4. The auxiliary word.
5. The original control-pair address.

The returned value is treated as a signed 32-bit integer.

A subdivision count begins at one. While the returned value, or its successively shifted replacement, is strictly positive, the count increases by one and that value is arithmetically shifted right by two.

Consequently:

| Dependency result | Subdivision count |
|---|---:|
| Zero or negative | 1 |
| 1 through 3 | 2 |
| 4 through 15 | 3 |
| 16 through 63 | 4 |
| Largest positive signed 32-bit value | 17 |

For a positive result, the count is two plus the integer base-four logarithm rounded downward.

No dependency error convention is recognized. In particular, a negative return does not cause an error return; it selects count one.

### 3. Direct-submission branch

When the count is less than two, no subdivision scratch fields are initialized by this function.

Using only the coordinate values saved before F-870c4fcf7295, the function constructs:

- A scaled endpoint pair equal to four times the saved endpoint.
- An intermediate horizontal value equal to the saved context horizontal component, plus four times the saved endpoint horizontal component, plus eight times the saved control horizontal component.
- The corresponding intermediate vertical value.

It calls F-7ed325e66f98 twice:

1. Context address, intermediate horizontal value divided by four toward zero, intermediate vertical value divided by four toward zero.
2. Context address, scaled endpoint horizontal component, scaled endpoint vertical component.

It then returns.

The second coordinate pair is retained across the first submission. A context or input mutation by the first submission does not cause this branch to recompute that second pair.

Changes made by F-870c4fcf7295 to the input pairs or current-coordinate fields likewise do not replace the initial coordinate snapshots used by this branch.

### 4. Initialize subdivision state

For a count of at least two, initialization occurs after F-870c4fcf7295 returns, in the following order:

1. Store the count at +0x34C.
2. Reread endpoint horizontal and store its value shifted left by two at +0x44.
3. Reread endpoint vertical and store its value shifted left by two at +0x48.
4. Reread control horizontal and store its value shifted left by two at +0x4C.
5. Reread control vertical and store its value shifted left by two at +0x50.
6. Read the current context horizontal field and copy it to +0x54.
7. Read the current context vertical field and copy it to +0x58.

Unlike the direct branch, this branch uses post-dependency reads for its initial subdivision coordinates. Mutations by F-870c4fcf7295 can therefore affect the initialized records.

Traversal begins at depth zero and the coordinate record beginning at +0x44. Describe each record’s three pairs as **A**, **B**, and **C**, in address order.

### 5. Decide whether to submit or split

Each iteration reads the subdivision count for the current depth.

A count below two selects terminal processing immediately, without a vertical-range check.

For a count of at least two, the function reads the vertical components of A, B, and C and determines their signed minimum and maximum. It then checks:

- Whether the minimum, arithmetically shifted right by eight, is greater than or equal to the upper bound at +0x18.
- If that first condition is false, whether the maximum, arithmetically shifted right by eight, is less than the lower bound at +0x14.

Either condition selects terminal processing. Otherwise the record is split.

The comparisons define an upper-exclusive and lower-inclusive overlap test. A minimum exactly at the upper bound terminates subdivision. A maximum exactly at the lower bound does not terminate it through the lower-bound condition.

No horizontal-range check is present. The bounds are read during traversal rather than snapshotted once.

### 6. Terminal processing

For a terminal record, the function saves A and computes a submission pair using:

- The context’s then-current coordinate pair.
- Plus A.
- Plus twice B.
- With each resulting component divided by four toward zero.

It calls F-7ed325e66f98 with that pair, then calls it again with the saved A pair.

C is not used directly in this terminal formula. Any relationship between C and the context’s current-coordinate fields depends on the context state and dependency behavior.

After both submissions, traversal moves back one depth and one 16-byte coordinate-record stride. If the depth becomes negative, the function returns. Otherwise it processes the pending record at the shallower depth.

### 7. Splitting and traversal order

For a record requiring subdivision, define component-wise midpoint pairs:

- **AB:** the sum of A and B divided by two toward zero.
- **BC:** the sum of B and C divided by two toward zero.
- **M:** the sum of AB and BC divided by two toward zero.

The current record becomes the pending half A, AB, M. The next overlapping record becomes M, BC, C.

Both depth entries receive the previous count minus one. The traversal advances to the next record, so the M, BC, C half is processed first. The A, AB, M half remains pending until traversal returns.

The coordinate writes occur in a specific order:

1. Preserve C’s horizontal component in the next record’s endpoint slot.
2. Store BC’s horizontal component.
3. Replace B’s horizontal component with AB’s horizontal component.
4. Store M’s horizontal component in the shared pair.
5. Preserve C’s vertical component in the next record’s endpoint slot.
6. Store BC’s vertical component.
7. Replace B’s vertical component with AB’s vertical component.
8. Store M’s vertical component in the shared pair.
9. Store the decremented count for the pending record.
10. Advance the coordinate-record position and store the same count for the newly active record.

This establishes depth-first processing of the C-side half before the A-side half. Each terminal record produces two submissions, even when vertical exclusion caused its termination.

## Side effects

Direct side effects are:

- One call to F-870c4fcf7295.
- Two or more calls to F-7ed325e66f98.
- For the subdivision branch, writes to coordinate scratch and subdivision-count storage.

The direct branch makes exactly two submission calls. The subdivision branch makes two calls per terminal record. With no vertical early termination and an initial count of N, ordinary undisturbed execution produces 2 raised to N−1 terminal records and 2 raised to N submission calls.

There is no rollback, scratch clearing, state restoration, or explicit error reporting.

The function does not directly write through the input-pair addresses as such, although context writes can affect them if they alias context storage. Both input addresses are passed to F-870c4fcf7295.

No ownership transfer is established. Neither dependency may be presumed to preserve globals, preserve context fields, retain or release memory, or leave input storage unchanged. Continued execution requires the memory this function subsequently accesses to remain valid.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, arithmetic is representable, storage is valid, input and scratch regions do not alias, and dependencies preserve scratch state.

1. **Zero adjustment with origin context.**  
   Initial context coordinates are (0, 0), endpoint is (3, −2), control is (1, 4), and F-870c4fcf7295 returns zero. The count is one. The submission pairs must be (5, 6), then (12, −8). This function must not initialize subdivision scratch.

2. **Negative adjustment.**  
   With any otherwise valid coordinates, a negative adjustment result selects the same direct branch as zero. It is not treated as a locally reported error.

3. **Negative quarter division.**  
   In the direct branch, let the context pair be (−1, −1), with endpoint and control both (0, 0). Each intermediate component is −1. The first submitted pair is (0, 0), not (−1, −1), because this division truncates toward zero.

4. **Adjustment threshold.**  
   A result of three produces count two; a result of four produces count three. These counts are determined by repeated two-bit shifts, not by repeated one-bit shifts.

5. **Upper-bound terminal processing.**  
   If a record’s minimum vertical component shifted right by eight equals the upper bound, the record produces two submissions without splitting. It is not silently discarded.

6. **Lower-bound equality.**  
   If the shifted maximum equals the lower bound and the upper-bound condition is false, the lower comparison does not force terminal processing. A count of at least two therefore permits a split.

7. **One split with stable current coordinates.**  
   Let the initialized record be A = (8, 0), B = (4, 0), C = (0, 0), count two, and bounds −1 and 1. If submissions leave the current context pair at (0, 0), the halves are (8, 0), (6, 0), (4, 0) and (4, 0), (2, 0), (0, 0). The C-side half is processed first, producing submissions (2, 0), (4, 0), followed by (5, 0), (8, 0).

8. **Dependency mutation distinguishes branches.**  
   If F-870c4fcf7295 changes endpoint storage, the direct branch still uses the original saved endpoint. The subdivision branch rereads that storage during initialization and can use the changed endpoint.
