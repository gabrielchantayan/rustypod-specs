# F-96302b838514

## Purpose

F-96302b838514 performs a range-gated lookup selected by the low eight bits of an input value. It obtains a block through F-2a608085a170, checks the selected value against an encoded range, and conditionally reads a two-byte entry. A nonzero entry is combined with a two-byte adjustment; the result retains only the low 16 bits.

The established behavior is a numeric lookup. The application-level meaning of the block, entries, adjustment, and result is unknown. Interpreting them as character mappings, resource identifiers, addresses, or another domain-specific format would be inferred intent.

Zero is not a unique failure indicator. It can result from a null dependency result, range rejection, a disabled lookup, a zero entry, or adjustment of a nonzero entry to zero modulo 65,536.

The displacement field has three distinct expression evaluations: one for the enable check and one for each entry-byte address. A single-displacement, adjacent-byte description applies only when the displacement bytes remain stable across those evaluations.

### Consumed block layout

Each two-byte field is assembled with the byte at the lower address contributing the most significant eight bits.

| Offset from block base | Width | Use |
|---|---:|---|
| 0 | 2 bytes | Range start |
| 2 | 2 bytes | Range count |
| 4 | 2 bytes | Result adjustment |
| 6 | 2 bytes | Lookup enable value and entry displacement |

All four fields have unsigned values from 0 through 65,535.

The displacement is relative to offset 6, not to the block base or the end of the eight-byte header. For stable displacement bytes and candidate index \(i\), the selected entry occupies:

\[
6+d+2i
\quad\text{and}\quad
7+d+2i
\]

where \(d\) is the displacement.

That adjacent-byte layout is conditional on displacement stability. Without it, the function independently calculates the two entry-byte addresses using potentially different displacement values.

The block fields and entry are assembled from byte accesses, so the visible behavior does not require aligned two-byte loads. Alignment requirements for the initial four-byte read remain platform-dependent.

## Behavior

### 1. Obtain the block

The function initializes its eventual result to zero, reads the four-byte field at offset 16 from the first input, and calls F-2a608085a170 with the loaded value.

This call occurs before any range decision. It is made even when the eventual range would reject the second input.

If the dependency returns null, the function returns zero. No block header or entry bytes are accessed on that path.

The initial field is not visibly loaded again after the call. Later lookup accesses use the returned block address.

### 2. Calculate and check the candidate index

For a non-null block, define:

- \(c\): the second input masked to eight bits, between 0 and 255.
- \(s\): the unsigned 16-bit value assembled from block offsets 0 and 1.
- \(n\): the unsigned 16-bit value assembled from offsets 2 and 3.

The candidate index is calculated by unsigned 32-bit subtraction:

\[
i=(c-s)\bmod 2^{32}
\]

The lookup proceeds only when the unsigned comparison \(i<n\) succeeds.

For fixed values of the sampled range fields, this is equivalent to requiring both \(c\geq s\) and \(c-s<n\). Subtraction below the start does not wrap into a valid eight-bit or 16-bit index: it produces a large unsigned 32-bit value, which cannot be less than a 16-bit count.

Consequences:

- A count of zero rejects every input.
- A start greater than 255 rejects every input.
- The upper boundary is exclusive.
- A sufficiently large count can accept every remaining low-byte value from the start through 255.
- Every accepted index is at most 255.
- Inputs having the same low byte have the same selection behavior when the dependency result and sampled block values are otherwise equivalent.

Range rejection returns zero before evaluating the displacement field, entry, or adjustment.

The range fields are assembled from separate byte accesses. Their interpretation does not imply atomic sampling or a consistent snapshot under mutation.

### 3. Evaluate the displacement for the enable check

After range acceptance, the function assembles the two-byte value at offsets 6 and 7 and tests it against zero.

If this evaluation yields zero, the function returns zero without accessing an entry or the adjustment.

If it yields a nonzero value, entry access proceeds. The value used for this check is not visibly retained as the displacement for both entry-byte addresses. Instead, the same field is evaluated independently within each address expression.

There are therefore three displacement-field evaluations on the enabled path:

1. The zero/nonzero check.
2. The calculation of the address supplying the entry’s most significant byte.
3. The calculation of the address supplying the entry’s least significant byte.

Each evaluation itself assembles two bytes. Neither field-level atomicity nor a physical ordering among all constituent reads is established.

### 4. Read and assemble the entry

Let:

- \(d_H\) be the displacement value obtained within the address expression for the entry’s most significant byte.
- \(d_L\) be the displacement value obtained independently within the address expression for the entry’s least significant byte.

The entry-byte offsets are:

\[
\text{most-significant-byte offset}=6+d_H+2i
\]

\[
\text{least-significant-byte offset}=7+d_L+2i
\]

The two sampled bytes are combined into an unsigned 16-bit entry.

If the displacement bytes remain stable throughout the three evaluations, the enable check and both address calculations use the same value \(d\). Only under that condition does the entry occupy the adjacent pair beginning at \(6+d+2i\).

If storage changes, neither address calculation is required to use the value that passed the enable check. The two bytes need not be adjacent, and they need not share one displacement. An address-producing evaluation may yield zero even though the earlier enable check yielded a nonzero value; no additional nonzero check is visible for either address-producing evaluation.

These are distinctions between expression evaluations, not a claim about exact physical load order. The representation does not establish which entry byte is physically read first, which displacement byte is read first, or whether a compiler or execution environment combines particular accesses.

A zero assembled entry causes a zero return without reading the adjustment.

No visible validation requires the entry to lie after the header. Small displacements can select header bytes. There is also no allocation-size or table-extent check. Passing the range check does not establish that either selected entry-byte address is readable.

### 5. Apply the adjustment

For a nonzero assembled entry, the function reads the two-byte adjustment at offsets 4 and 5 and returns:

\[
(\text{entry}+\text{adjustment})\bmod 65{,}536
\]

The result is represented as an unsigned 32-bit value with zero upper bits.

The supplied representation temporarily uses an address-like representation for the entry and its adjustment. No memory access through the numeric entry value is visible. The observable numeric result is the low 16 bits of the addition.

Both operands are at most 65,535, so their ordinary numeric sum is at most 131,070. The final truncation, not saturation or rejection, determines the return value. A nonzero entry may therefore produce zero.
