# F-e711a790ae5e

## Purpose

F-e711a790ae5e traverses selected linked record structures and conditionally sets bit 2, mask `0x00000004`, in their 32-bit flag words.

A descriptor is selected when its unsigned selection count exceeds three. For a selected descriptor, the function finds a noncoincident forward displacement, obtains a reference token from F-39d3b95c505b, and searches backward for a different token. It then scans forward, comparing successive distinct tokens through F-88d01431784d. A change in bit 31 between consecutive comparison results causes an inclusive forward span to be marked.

This is an established traversal and flag-update contract. Interpreting the tokens as directions or angles, the comparisons as geometric turns, or the flags as a geometric classification is **inferred intent**, not established behavior.

## Interface

### Arguments and completion

The function accepts four arguments:

| Argument | Width | Visible use |
|---|---:|---|
| Collection address | 32 bits | Identifies the collection descriptor |
| Opaque value | 32 bits | Neither inspected nor forwarded |
| Opaque value | 32 bits | Neither inspected nor forwarded |
| Scratch-compatible value | 32 bits | Incoming value does not affect the computation |

The fourth argument’s storage is reused internally for coordinate values. It is not an output parameter.

There is no explicit return value, status code, or error result. Normal completion occurs when the unsigned descriptor index is at least the collection count read at the beginning of an iteration.

### Collection and descriptor layouts

The collection supports these reads:

| Byte offset | Width | Meaning |
|---|---:|---|
| `+4` | 32 bits | Unsigned descriptor count |
| `+12` | 32 bits | Descriptor-array address |

Each descriptor occupies eight bytes:

| Byte offset | Width | Meaning |
|---|---:|---|
| `+0` | 32 bits | Anchor-record address |
| `+4` | 32 bits | Unsigned selection count |

Selection counts zero through three skip processing. Counts four through `0xffffffff` select processing. No relationship between the selection count and the number of reachable records is established.

### Record layout

| Byte offset | Width | Meaning |
|---|---:|---|
| `+0` | 32 bits | Backward-link address |
| `+4` | 32 bits | Forward-link address |
| `+12` | 32 bits | Mutable flags |
| `+36` | 32 bits | First coordinate |
| `+40` | 32 bits | Second coordinate |

“Forward” and “backward” identify the link fields used by this function; they do not imply geometric orientation or reciprocal links.

Coordinate equality is exact equality of 32-bit values. Coordinate differences supplied to F-39d3b95c505b are 32-bit subtraction results, not widened mathematical differences. Under the represented 32-bit machine arithmetic, only the low 32 bits of each difference are available to the dependency. Its interpretation of those bits is unknown.

The descriptor index and its increment are unsigned 32-bit values. Descriptor addressing uses an eight-byte stride in the represented 32-bit address space. The function provides no bounds or address-overflow protection.

### Preconditions and ownership

Every accessed collection field, descriptor field, record field, and link target must support the corresponding read. Every flag field reached by marking must support a 32-bit read and write.

The function performs no visible allocation, release, ownership transfer, null check, bounds check, or structural repair. It neither establishes ownership nor guarantees the lifetime of memory used by its dependencies.

Validity must persist for the accesses actually performed, including accesses after dependency calls. The evidence does not establish that either dependency preserves the traversed memory.

## Behavior

### 1. Select descriptors in ascending index order

The descriptor index begins at zero. At the beginning of each iteration, the function reads the collection’s current unsigned count. If the index is at least that count, it returns.

Otherwise, it obtains the descriptor-array address and reads the indexed descriptor’s selection count. A count no greater than three skips the descriptor without reading its anchor for traversal.

For a selected descriptor, the array address is obtained again to read the anchor. Consequently, the selection-count access and anchor access are not guaranteed to use one cached array address.

After skipping or completing a descriptor, the index advances by one. The collection count is reread for the next iteration. There is no collection-wide snapshot guarantee.

### 2. Find an initial noncoincident forward target

Starting at the anchor, the function follows forward links one at a time.

For each candidate:

1. It compares the candidate address with the anchor address.
2. If they are equal, processing of this descriptor ends.
3. Otherwise, it reads the candidate’s first coordinate and the anchor’s first coordinate.
4. Only if those coordinates are equal does it read and compare their second coordinates.
5. A coincident candidate is skipped; the first noncoincident candidate ends the search.

Thus, returning to the anchor is checked **before reading that candidate’s coordinates**.

If the search returns to the anchor before finding a noncoincident candidate, this descriptor produces no dependency calls and no direct flag writes.

For the first noncoincident candidate, F-39d3b95c505b receives:

- candidate first coordinate minus anchor first coordinate;
- candidate second coordinate minus anchor second coordinate.

The coordinate fields are accessed again to form these arguments; the initial equality check is not a snapshot of all argument values. The supplied expression does not establish a total evaluation order between the two argument expressions.

The low 32 bits of the result become the **reference token**. The candidate remains the starting cursor for the later forward scan.

### 3. Search backward for a different token

The backward cursor starts at the anchor. Each step retains the record being left and follows that record’s backward link.

The function first checks whether the backward target is the anchor. If so, descriptor processing ends immediately, before reading the target’s coordinates or obtaining a token for that edge.

Otherwise, it reads the target’s first coordinate and the record-being-left’s first coordinate. If they match, it reads their second coordinates. Coincident endpoints cause another backward step without a dependency call.

For a noncoincident edge, F-39d3b95c505b receives the displacement from the backward target to the record being left:

- record-being-left first coordinate minus target first coordinate;
- record-being-left second coordinate minus target second coordinate.

The first-coordinate values come from the preceding comparison. The second-coordinate argument preparation includes further reads.

If the returned low-word token equals the reference token, backward traversal continues. The first different token ends the search.

Both this search and the initial forward search check for return to the anchor **before reading the target’s coordinates**. They differ from the later forward scan, which reads both first-coordinate components before checking its stop marker.

If backward traversal returns to the anchor without a different token, there are no direct flag writes and no call to F-88d01431784d for this descriptor. Earlier F-39d3b95c505b calls remain observable.

On finding a different token:

- the record being left, not the backward target, becomes the fixed **stop marker**;
- that same record becomes the initial **span start**;
- F-88d01431784d is called with the different backward token first and the reference token second.

The low 32 bits of that comparison result become the initial **comparison state**.

### 4. Scan forward for token changes

Forward scanning starts from the noncoincident candidate retained from the initial search.

For each edge, the function retains the current record as the **edge origin** and obtains the next record through its forward link. It then:

- reads the next record’s first coordinate;
- reads the origin’s first coordinate;
- checks whether the next record is the stop marker.

If the next record is the stop marker, a latch is set. That latch remains set for the remainder of this descriptor’s processing. Setting it does not immediately stop scanning.

If the first coordinates match, the function reads the origin’s second coordinate and then the next record’s second coordinate. A coincident edge is skipped without a token call.

For a noncoincident edge, F-39d3b95c505b receives:

- next first coordinate minus origin first coordinate;
- next second coordinate minus origin second coordinate.

The first-coordinate values are retained from the earlier reads; the second-coordinate argument preparation reads the fields again as needed.

A token equal to the current reference token is skipped. Scanning continues until a noncoincident edge produces a different low-word token.

The stop-marker latch can therefore be set on a coincident edge or an equal-token edge without ending the scan.

### 5. Compare and optionally mark a span

For a newly obtained token different from the reference token, F-88d01431784d receives:

1. the current reference token;
2. the new forward token.

The function XORs the low 32-bit comparison result with the prior comparison state and tests bit 31.

- Bit 31 clear: no direct flag writes for this decision.
- Bit 31 set: mark the forward span from the current span start through the edge origin, inclusive.

Each marking operation reads the record’s flag word, ORs it with `0x00000004`, and writes the result back.

Marking writes the span start first, then reads its forward link. It continues in forward-link order until it reaches the endpoint and writes that endpoint’s flags. The endpoint is included.

**Equal start and endpoint does not mean a one-record span.** The traversal first writes the start and advances at least once. It stops when advancement reaches the endpoint address, then writes the endpoint again. For an unchanged finite simple circular ring, this marks the entire ring and writes the starting record twice.

After either marking or declining to mark:

- the edge origin becomes the next span start;
- the new forward token becomes the reference token;
- the new comparison result becomes the comparison state.

The next comparison state is not the XOR value and is not a flag value.

The function then checks the stop-marker latch. If set, descriptor processing ends. Otherwise, forward scanning resumes from the destination of the edge just classified.

Accordingly, encountering the stop marker is insufficient for termination: a later token change, comparison, and marking decision may still be required.

## Side effects

### Direct writes

The function’s explicit persistent stores target 32-bit record flag fields at offset `+12`. There are no explicit stores directed at collection fields, descriptor fields, links, or coordinates.

Each flag update preserves all bits other than setting bit 2, relative to the value read for that update. It still writes when bit 2 was already set. Overlapping spans or repeated processing can therefore repeat writes without changing the final bit pattern.

No non-aliasing guarantee is established. The field-relative description of store targets does not prove that unusually overlapping objects cannot expose those stores through another layout.

Marking is not transactional. Earlier writes are not rolled back if a later access fails or traversal does not terminate.

### Dependency effects

Calls occur in traversal order: initial token, backward-search tokens, initial comparison, then forward-search tokens and subsequent comparisons interleaved with optional marking.

No flag-marking dependency is called inside the marking traversal itself.

Neither dependency is established to be pure, deterministic, nonallocating, nonreleasing, or preserving shared memory. Dependency effects occur before subsequent accesses by this function. Cached pointers and values coexist with later field rereads; the operation does not restart or validate its structure after a call.

### Errors and nontermination

There is no explicit diagnostic, recovery path, malformed-list report, or allocation-failure handling.

Invalid addresses can make required accesses invalid. Traversal can fail to terminate when an anchor, marking endpoint, or qualifying token change is never reached. These are absent guarantees, not handled error outcomes.

## Dependencies

### F-39d3b95c505b

**Visible inputs:** two 32-bit coordinate differences.

**Visible result representation:** 64 bits.

**Consumed result:** low 32 bits, used for exact token equality and as arguments to F-88d01431784d. The upper half does not determine token equality or the marking decision.

The function skips a token call when its preceding coordinate check classified an edge as coincident. This does not establish that token zero is impossible, nor that later argument reads must observe unchanged coordinates.

**documented_only:** token meaning, normalization, signedness, overflow interpretation, determinism, side effects, ownership behavior, and failure mechanisms.

### F-88d01431784d

**Visible inputs:** two 32-bit tokens.

**Consumed result:** a 32-bit comparison value.

The initial call receives backward token then reference token. Later calls receive reference token then new forward token. No symmetry is assumed.

The initial result seeds comparison state. Each subsequent result participates in the bit-31 XOR test and replaces that state.

**documented_only:** comparison semantics, result range, determinism, side effects, ownership behavior, and failure mechanisms. Results are not established to be restricted to negative one, zero, and positive one.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, memory is valid and remains unchanged except for direct flag updates.

### Empty collection

With initial collection count zero, the function reads that count and returns without accessing a descriptor or calling either dependency.

### Selection boundary

A selection count of three skips anchor traversal. A count of four enables traversal but does not guarantee a token comparison or flag write. A selection count of `0xffffffff` is also eligible because selection is unsigned.

### Anchor checks in both searches

If the initial forward link points back to the anchor, descriptor processing ends before reading coordinates through that target.

If the backward search reaches the anchor, it likewise ends before reading that target’s coordinates or requesting a token for the returning edge.

By contrast, reaching the later forward scan’s stop marker occurs only after the scan has read the destination’s and origin’s first-coordinate fields.

### All candidates coincide

If every forward candidate before return to the anchor has the anchor’s coordinates, the descriptor produces no dependency calls and no direct flag writes.

### No different backward token

Suppose the initial reference token is A. If every examined noncoincident backward edge produces A and the backward search returns to the anchor, no comparison call or direct flag write occurs.

### Sign-bit transition

If comparison state is `0x00000000` and the new result is `0x80000000`, marking occurs. A marked flag word read as `0x00000010` is written as `0x00000014`.

If state is `0x80000001` and the new result is `0x80000002`, their XOR is `0x00000003`; no marking occurs for that decision.

### Comparison-state progression

After state `0x80000000` and new result `0x00000000`, marking occurs and the next state becomes `0x00000000`. A following result of `0x00000000` does not trigger another marking decision. Carrying the previous XOR forward would violate this behavior.

### Equal span endpoints

If marking begins and ends at the same record in a stable three-record forward ring, writes occur to the start, the other two records in forward order, and the start again.

### Stop marker on a skipped edge

If the stop marker is reached on a coincident edge, scanning continues. Processing ends only after a different token is found and its comparison and optional marking finish. If no different token is ever found, the set latch alone does not terminate processing.

### Difference width

A component subtraction of `0x80000000` minus `0x00000001` supplies the 32-bit pattern `0x7fffffff`. No wider mathematical difference is passed. The dependency’s interpretation remains unspecified.

## Uncertainties

The following remain **documented_only**:

- Application-level meanings of coordinates, counts, tokens, comparisons, and flags.
- Whether links are reciprocal or form simple circular rings.
- Whether selection counts match reachable record counts.
- Dependency determinism, shared-memory effects, allocation, release, and failure behavior.
- External synchronization and object-lifetime guarantees.
- A total order for reads occurring within separate argument expressions.
- Dependency interpretation of wrapped coordinate differences.

Termination requires more than apparent circularity. The searches must reach their required anchor or qualifying edge; marking must reach its endpoint; forward scanning must eventually find a token different from the current reference, including after the stop marker is encountered.
