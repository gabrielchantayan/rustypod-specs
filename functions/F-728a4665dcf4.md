# F-728a4665dcf4

## Purpose

F-728a4665dcf4 performs an ordered, recursive comparison of two pointer-linked objects and returns a 32-bit Boolean result: 1 for acceptance and 0 for rejection.

The comparison is selective rather than a complete comparison of object storage. It examines a one-byte discriminator, one selected flag bit, two recursive links, an optional collection of recursive links, several fixed-width fields, and a final conditional predicate. Some fields are deliberately bypassed by earlier decisions.

**Inferred intent:** the function resembles a structural compatibility or equivalence predicate.

**Established limitation:** acceptance must not be interpreted as general equality. The final decision is asymmetric, some storage is ignored, and even an object compared with itself can be rejected. No identity shortcut exists for non-null pointers.

The function receives two object pointers, referred to here as the **first object** and **second object**. Either may be null.

There is no separate error result, diagnostic output, or established recovery mechanism for invalid memory.

## Behavior

### 1. Null handling

Null handling occurs before object contents are inspected.

- Two null pointers produce 1.
- Exactly one null pointer produces 0.
- Two non-null pointers proceed to content comparison, even when their addresses are identical.

No object-memory read is needed for either null-result case.

### 2. Initial discriminator and flag checks

For two non-null objects, the function first compares their unsigned 8-bit discriminators at offset +0. A mismatch produces 0 and prevents the later comparison stages.

If the discriminators match, it reads the 16-bit fields at offset +2 and compares only bit 0x0010. All other bits of those fields are excluded from this comparison.

A mismatch in the selected bit produces 0. Matching flag bits permit recursive-link comparison.

Within a paired comparison, the evidence does not establish a portable left-versus-right memory-read ordering. It does establish that the flag stage is conditional on matching discriminators.

### 3. Ordered recursive links

The objects referenced at offset +8 are compared by a recursive invocation of F-728a4665dcf4.

- A zero result rejects the current pair.
- A nonzero result permits comparison of the pointers at offset +12.

The offset +12 pair is then compared recursively.

- A zero result rejects the current pair.
- A nonzero result permits collection processing.

Thus, the first link comparison completes before the second link comparison begins. Both complete before the current pair’s collection stage.

Null child pointers use the same null rules as top-level inputs. Both children being null therefore pass that recursive comparison; only one child being null fails it.

The function does not cache successful object pairs. Repeated references can cause repeated traversal.

### 4. Optional collection comparison

After both fixed recursive links accept, the function examines the collection-descriptor pointers at offset +16.

- If both descriptor pointers are null, collection comparison passes without count or record access.
- If exactly one descriptor pointer is null, the function returns 0.
- If both are non-null, their signed 32-bit counts must compare equal.

A count mismatch rejects before any record comparison.

For matching counts, collection traversal begins at index zero and advances in increasing index order. The loop condition compares the signed index with the first descriptor’s signed count. For each visited index, the object pointers at the beginnings of the corresponding 12-byte records are compared recursively.

The first rejecting element produces 0 immediately. Later elements and the current objects’ remaining fields are not examined by this invocation.

Important consequences:

- A matching count of zero visits no records.
- Matching negative counts also visit no records. The function does not explicitly reject negative counts.
- A null descriptor and a non-null descriptor with count zero are different and reject.
- The stride is 12 bytes, not the pointer width.
- The first descriptor’s count is read for the loop condition rather than being established as an immutable snapshot.

Recursive invocations may have effects through their dependencies. The contract therefore cannot assume that descriptor pointers, record-storage pointers, or counts remain unchanged across recursive calls. The straightforward “compare exactly the original count of elements” interpretation requires stable input storage.

The supplied evidence does not establish a safe policy for address arithmetic overflow or for record storage too short for the requested count. Valid storage and address calculations are preconditions, not conditions enforced by this function.

### 5. Required zero fields and exact-value fields

After collection comparison passes, the function checks the first object’s 32-bit field at offset +56.

If that field is nonzero, the current pair rejects. In that case, this stage does not need to read the second object’s offset +56 field.

If the first field is zero, the second object’s corresponding field is read and must also be zero. Equal nonzero values do not pass.

Only when both fields are zero does the function compare the 32-bit fields at offset +36. A mismatch rejects without proceeding to the offset +40 comparison.

If offset +36 matches, the 32-bit fields at offset +40 must also match.

The offset +36 and +40 comparisons are exact 32-bit equality checks. Their signed interpretation does not affect equality.

### 6. Terminal decision

After all preceding stages pass, the function rereads the first object’s 8-bit discriminator.

If this newly read discriminator equals 0x95, the function returns 1 immediately. Neither terminal gate nor shifted-value comparison is required on this path.

For any other discriminator, the first object’s 32-bit field at offset +20 is read:

- If it is zero, the function returns 1.
- If it is nonzero, additional conditions must pass.

Those additional conditions, in order, are:

1. The second object’s 32-bit field at offset +20 must be nonzero.
2. The unsigned 32-bit fields at offset +24 must match after each is logically shifted right by one bit.
3. F-abcb7c332db0 must return zero.

If any of these conditions fails, the result is 0. If all pass, the result is 1.

The shifted comparison discards exactly the least significant bit. It retains the other 31 bits and does not sign-extend. For example, values 4 and 5 match under this comparison; values 5 and 6 do not.

F-abcb7c332db0 is not called if an earlier condition rejects or if either immediate-acceptance branch applies.

This terminal rule is asymmetric. A zero offset +20 field on the first object accepts without requiring the second object’s corresponding field to be zero. Reversing the inputs can therefore change the result.

The discriminator reread is also significant: if nested processing changes the first object’s discriminator, the terminal branch uses the new value, not necessarily the value that passed the initial discriminator comparison.
