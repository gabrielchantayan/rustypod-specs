## Behavior

Opaque dependency IDs **F-D01** through **F-D37** identify call sites in execution order. Different IDs do not necessarily denote different target addresses.

### 1. Capture primary storage and publish initial values

Establish a zero byte before **F-D01**. Invoke **F-D01** with two explicit zero arguments, using the target calculated from the current link-like control value.

After that call, establish a separate unsigned zero byte for later arithmetic.

Continue in this order:

1. Invoke **F-D02**.
2. Invoke **F-D03**.
3. Read the primary base as a 32-bit word from the first global location.
4. Invoke **F-D04**.
5. Invoke **F-D05**, retaining a represented 64-bit result.
6. Invoke **F-D06** with two arguments derived from that result.

The first **F-D06** argument is the low word converted to a signed 32-bit value. For the second argument, the high and low words are each converted to signed 32-bit values and added first. Only afterward does the unsigned 32-bit conversion of the zero byte participate in addition.

Consequently, when the signed intermediate sum is representable, adding unsigned zero produces its corresponding unsigned 32-bit value. The unsigned operand does not retroactively give wrapping semantics to an overflowing signed intermediate addition.

After **F-D06**, store its associated auxiliary byte at primary base + `0x11`.

Then:

1. Invoke **F-D07**.
2. Store the zero byte established before **F-D01** at primary base + `0x15`.
3. Invoke **F-D08**, obtaining a 16-bit result and an auxiliary address-like output.
4. Store the 16-bit result at auxiliary address + `0x0c`.

Both primary-relative stores use the captured primary base. Its global location is not explicitly reread between them. This retained-value relationship does not guarantee that the referenced storage survives intervening calls.

### 2. Publish portions of a second paired result

Invoke **F-D09**, retaining another represented 64-bit result.

In order:

1. Store a zero halfword at the signed-high-word-derived address + `0x2c`.
2. Store the low word logically shifted right by 26 at context base + `0x26c`, using a 32-bit store.
3. Establish the unsigned constant `0x21c48960`.
4. Invoke **F-D10**.
5. Read the object address as a 32-bit word at context base + `0x320`.
6. Invoke **F-D11**.
7. Invoke **F-D12**.
8. Store the low word shifted left by two at object address + `0x54`, using a 32-bit store.

The right-shift result is between `0` and `63`. The left shift is unsigned 32-bit arithmetic and discards the highest two input bits.

Both publications use the same retained low word. The object address is captured before **F-D11**, rather than reread at the store.

### 3. Read a halfword-derived base and encounter the breakpoint

Invoke **F-D13**, **F-D14**, **F-D15**, **F-D16**, and **F-D17**, in that order.

Read an unsigned halfword at `0x21c48960 + 0x34`, equivalently `0x21c48994`. Retain its zero-extended value as the halfword-derived base.

Then:

1. Invoke **F-D18**.
2. Read a 32-bit argument at context base + `0x280`.
3. Invoke **F-D19** with that argument, retaining its signed 32-bit result.
4. Execute a software breakpoint with immediate `0x92`.

The breakpoint is unconditional. Operations following it are required only if execution resumes.

After resumption:

- Shift the retained signed **F-D19** result left by two.
- Compute the unsigned constant expression obtained by shifting `0x21c48960` right by 18 and multiplying by four. Its value is `0x21c4`.
- Read the record address as a 32-bit word at halfword-derived base + `0x44`.

The signed shift is not established for arbitrary negative or excessively large results.

### 4. Perform intermediate halfword stores and capture the index

Continue in this order:

1. Invoke **F-D20**.
2. Invoke **F-D21**, retaining its 32-bit result.
3. Read a 32-bit value at halfword-derived base + `0x04`.
4. Invoke **F-D22** with the **F-D21** result first and the loaded word second.
5. Read the secondary base as a 32-bit word from the second global location.

7. Store the secondary base narrowed to 16 bits at secondary base + the shifted **F-D19** result.

The last operation is a halfword store, not a full-width address store. The destination uses a signed addition; unrestricted wrapping is not established.

Next:

No explicit bounds or validity check precedes these accesses.

### 5. Capture the final paired result and decrease the context base

## Acceptance examples

These are conditional static expectations, not runtime observations.

1. **Defined mixed arithmetic.** If **F-D05** supplies low word `0xffffffff` and high word `2`, and the signed conversion interprets the low word as `−1`, the signed intermediate sum is `1`. **F-D06** receives first argument `−1` and second argument unsigned `1`.

2. **Signed overflow is unresolved.** Signed operands `0x7fffffff` and `1` overflow at their intermediate addition. The later unsigned zero does not establish `0x80000000` as a guaranteed second argument. This case is **documented_only**.

3. **Unsigned publications.** A **F-D09** low word of `0xfc000003` produces a word value of `63` at context + `0x26c` and `0xf000000c` at captured object + `0x54`.

4. **Narrow intermediate store.** With secondary base `0x12345678`, shifted **F-D19** result zero, valid storage, and ordinary low-16-bit narrowing semantics, the intermediate halfword store targets `0x12345678` and carries `0x5678`. It does not write a full word.

5. **Full-width record publication.** A retained halfword of `0xffff` produces word value `0x0000ffff` at both record + `0x54` and record + `0x64`.

6. **Index boundary.** Index `65535` yields indexed word-store address `0x40070` and byte-source address `0x4fffb`. Neither bound guarantees mapped storage.

7. **Captured byte survives source mutation.** If the source byte is `0xa7` when read and **F-D34** changes that source to `0x12`, the following byte store still uses captured `0xa7`, provided execution and destination validity permit it.

8. **Breakpoint prevents later operations.** If breakpoint handling never resumes the continuation, no post-breakpoint store or call is required.

9. **Context transition and complete store count.** With initial context base \(B\), applicable arithmetic, returning dependencies, breakpoint continuation, and no interfering state changes, the context result store uses \(B+0x258\), the next pass uses \(B-0xf4\), and a fully reached pass performs all 15 direct stores, including the indexed word store at four times the index + `0x74`.
