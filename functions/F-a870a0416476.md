# F-a870a0416476

## Purpose

F-a870a0416476 conditionally writes a shared selection and performs ordered operations using fields from indexed records.

A 32-bit control value determines whether processing occurs and, when it does, a requested target of 1, 2, or 3. After an initial dependency call, the function obtains selection-related references and values. If the observed old selection differs from the target, it writes the target, conditionally invokes adjustment operations, applies two byte-sized configuration values, and may issue a zero-origin notification.

**Established static behavior:** the memory accesses, comparisons, call ordering, and return composition described below.

**Inferred intent:** the records appear to describe selectable configurations, with adjustments before and after a central configuration operation. The domain meaning and physical effects are not established.

The function does not obtain a coherent snapshot of all shared state. In particular, the reference retained for later selection reads, the reference used to load the old selection, and the reference used for the selection write are obtained separately. Likewise, the first table comparison does not use the table base retained for later accesses.

## Interface

- No explicit arguments.
- One unsigned 32-bit result.

|---|---|---|

The auxiliary byte is not an explicit argument. Its origin and calling-convention status are unknown; it must not be assumed to contain only one meaningful bit.

### Record layout

Each indexed record has a 16-byte stride:

| Offset | Access width | Use |
|---|---:|---|
| 0 | 32 bits | Unsigned comparisons; low byte also used by the final adjustment call |
| 4 | 32 bits | Low byte becomes the first central-operation argument |
| 8 | 32 bits | Low byte becomes the second central-operation argument |
| 12 | 32 bits | Unsigned comparisons for another adjustment category |

Masking a field to eight bits does not make its memory access byte-sized. Offsets 4 and 8 are loaded as full 32-bit words before reduction to values from 0 through 255.

Byte order, alignment requirements, record count, field units, and storage ownership are not established.

### Preconditions and ownership

Every reference and field actually accessed must be valid for its access width. Every effective record address used must be accessible. Dependencies must return normally for execution to reach subsequent phases.

There are no visible bounds checks, null checks, allocations, deallocations, ownership transfers, or recovery mechanisms. Supplying values to dependencies does not establish resource ownership.

Address calculations use 16-byte scaling in the represented 32-bit address model. Scaling and addition do not provide bounds protection and can wrap. The function establishes no safe behavior for inaccessible resulting addresses.

## Behavior

### Control gate

The function first reads the unsigned 32-bit control value.

If it is greater than 2, the function returns that exact value immediately. It does not call any listed dependency, capture a selection reference, write the selection, access table records, or add status bits.

Otherwise, the requested target is the control value plus one. The only reachable targets are therefore 1, 2, and 3. This addition cannot overflow on the processing path.

The target remains derived from this original control read even if a dependency subsequently changes the control cell.

### Initial call and distinct selection observations

For a control value of 0, 1, or 2, the function first calls F-f120802e6343 without explicit arguments. Its 32-bit result is retained for the final return.

After that call, the function performs two distinct observations:

1. It reads the global selection-cell reference and retains that reference for later current-selection reads.
2. It independently reads the global selection-cell reference again and loads the old selection through this separately obtained reference.

The old selection is **not necessarily loaded through the retained reference**. If the global reference changes between these observations, they can designate different cells. The retained reference and old selection are separate captured inputs.

The function compares the old selection with the requested target.

If they are equal:

- No selection write occurs.
- No table-base or table-record access occurs.
- No further dependency is called.
- The retained initial result is returned with the equal-path status contribution.

This path is not necessarily side-effect-free: F-f120802e6343 has already executed.

### Selection write

If the old selection differs from the target, the function independently obtains the global selection-cell reference for the write and stores the 32-bit target through it.

This write reference is distinct as an observation from both:

- The reference retained for later current-selection reads.
- The reference used to load the old selection.

All three may designate the same cell under stable conditions, but equality is not enforced.

The write precedes table comparisons and the central configuration operation. There is no rollback if later execution fails.

Throughout the remaining phases, **current selection** means a fresh 32-bit load through the retained selection-cell reference. It does not mean a fresh read of the global reference, and it need not equal the requested target or the observed old selection.

### Table-base capture and first comparison

After the selection write, the function reads and retains the global table-base reference.

The first offset-0 comparison nevertheless obtains its operands using **two additional, independent reads of the global table-base reference**:

- One operand loads offset 0 at the base observed for that operand, indexed by a current-selection read.
- The other loads offset 0 at the base observed for that operand, indexed by the captured old selection.

Neither operand is required to use the retained base. The two operand bases can differ from each other and from the retained base.

The evidence does not establish the relative evaluation order of the comparison operands. It therefore does not establish which operand’s global base read occurs first. No stronger ordering among the accesses inside those operand expressions is specified here.

The comparison is unsigned, over full 32-bit fields. If the current-indexed operand is less than the old-indexed operand, the function calls F-4e12fc80816d with the two supplied arguments **0, 3**.

### Remaining pre-operation comparison

After the first comparison and any resulting call, the function forms and retains the address of the old record’s offset-0 position using:

- The previously retained table base.
- The captured old selection.
- The 16-byte record stride.

It then compares:

- Offset 12 at that retained old-record address.
- Offset 12 of a record selected by another current-selection read, using the retained table base.

If the old field is less than the current field, it calls F-4e12fc80816d with **8, 3**.

This comparison occurs after the first adjustment call, if that call occurs. Later loads can therefore observe changes made by that call. Retention of the old-record address does not retain the contents of that record.

All table accesses after the first offset-0 comparison use the retained table base, not fresh reads of the global table-base reference.

### Central configuration operation

The function reads the current selection again and determines one record address using the retained table base.

From that selected record it loads:

- The 32-bit field at offset 4, reduced to its low eight bits.
- The 32-bit field at offset 8, reduced to its low eight bits.

It calls F-000000000002 with those values as its first and second arguments, respectively.

The record address is shared by these two field accesses. Their relative load order is not established.

Assuming normal completion of preceding accesses and calls, F-000000000002 is called exactly once on the changed-selection path and never on the other paths.

### Post-operation comparisons

After the central operation returns, the function compares offset 12 from:

- A record selected by another current-selection read, using the retained table base.
- The retained old-record address.

If the current field is less than the old field, it calls F-4e12fc80816d with **8, 3**.

Next, the function reads a current selection again and loads that record’s offset-0 field using the retained table base. It retains this field value.

It compares offset 0 of the old record, also using the retained table base, against that retained current field value. If the old field is less than the current field, it calls F-4e12fc80816d with three supplied arguments:

1. **0**
2. **3**
3. The low eight bits of the retained current field value

The third argument comes from the same full-width value used in this comparison. It is not obtained by rereading the field after the comparison.

The evidence presents both two-argument and three-argument calls to F-4e12fc80816d. Their distinction is established; the dependency’s true signature is not.

### Zero-origin notification

After the comparison and configuration phases, the function calls F-000000000001 with the supplied notification value if the captured old selection was zero.

The decision uses that captured value, not any subsequent selection read. The notification follows the central operation and all applicable adjustment calls.

Because every reachable target is nonzero, an old selection of zero always takes the changed-selection path.

### Return composition

Every processing path returns the bitwise OR of:

- The retained 32-bit result of F-f120802e6343.
- A status contribution.

The status contribution is formed by combining four Boolean conditions with the incoming auxiliary byte, reducing the combination to eight bits, then shifting it left by 27 within a 32-bit result.

| Position before shifting | Condition |
|---|---|
| Bit 4 | Negative-result condition |
| Bit 3 | Zero-result condition |
| Bit 2 | Carry-like condition |
| Bit 1 | Signed-subtraction-overflow condition |

The auxiliary byte is ORed into this combination without a demonstrated single-bit restriction.

Consequently:

- The four conditions contribute result bits 31, 30, 29, and 28.
- Auxiliary-byte bit 0 contributes result bit 27.
- Auxiliary-byte bits 1 through 4 can also set result bits 28 through 31.
- Auxiliary-byte bits 5 through 7 do not survive the 32-bit shifted result.

No bits are cleared from the retained dependency result. This is overlapping bitwise composition, not necessarily disjoint-field packing.

On the equal-selection path, the conditions are negative false, zero true, carry-like true, and overflow false. With an auxiliary byte of zero, the contribution is **0x60000000**.

On the changed-selection path, the conditions correspond to subtracting one from the captured old selection in 32-bit arithmetic:

- Negative: bit 31 of the wrapped subtraction result.
- Zero: old selection equals 1.
- Carry-like: old selection is nonzero.
- Overflow: old selection equals **0x80000000**.

These conditions do not describe dependency success or failure.

## Side effects

The only explicit persistent data write established locally is the conditional selection write. There are no separate stores to table fields or the control cell. Aliasing is not ruled out, so the selection write could affect another described resource if their storage overlaps.

Dependencies have unspecified effects. They must not be assumed to preserve globals, referenced cells, table contents, or external resources.

The access distinctions have observable consequences:

- A changed global selection reference does not redirect later reads through the already retained reference.
- The old-selection load and target write may concern different cells.
- The first comparison may read from two table bases different from the base used by every later table access.
- Changing the global table-base reference after its capture does not, by itself, redirect later saved-base accesses.
- Mutating records at the retained base can affect later comparisons and configuration arguments.
- Mutating the cell addressed by the retained selection reference can change later record choices.

Under stable data and non-mutating dependencies, each field category can cause at most one of its before/after adjustment calls. Without those assumptions, both calls in either category can occur. There are four conditional adjustment sites in total.

No explicit error handling, retry, rollback, or completion status is visible. Results from adjustment, configuration, and notification calls are unused. Abnormal dependency termination or invalid memory access has no locally specified recovery path.

### Three different selection cells

Given control **0**, suppose the separate reference observations designate:

- Cell A for the retained reference, containing **7**.
- Cell B for the old-selection load, containing **2**.
- Cell C for the write.

If these observations occur and the cells remain otherwise stable:

- The old selection is **2**.
- The function writes **1** to cell C.
