# F-5019c7ea8fd4

## Purpose

F-5019c7ea8fd4 adapts a descriptor and four opaque 32-bit argument words into one invocation of F-940bdd7a50cc. It determines a 32-bit selection value, constructs an optional pointer into the descriptor’s surrounding storage, and sign-extends a descriptor field for forwarding.

The contract includes both the selected value and the reads performed while obtaining it. Some fallback categories cause an external data read whose value is discarded. In particular, fallback category 32 causes two external reads, in order, even though only the second value is forwarded.

**Established static behavior:** descriptor field accesses, selection rules, conditional external-slot reads, optional-pointer construction, signed extension, and dependency argument placement.

**Inferred intent:** the descriptor appears to hold an explicit selector, fallback category, signed numeric field, and presence indicator for an inline region. These labels describe their use here; they do not establish application-level meaning.

**Unknown:** the dependency’s semantics, the external slots’ meanings, and the contents and required extent of the optional inline region.

The function has no explicit return value. Its principal externally visible action is the dependency invocation, together with the effects of the reads that precede it and any effects of the dependency itself.

## Behavior

### Selection and external reads

The function first reads the 16-bit explicit selector and widens it without sign extension. It then reads the 16-bit fallback category, regardless of whether the explicit selector is zero.

A nonzero explicit selector becomes the selected 32-bit value unchanged. Thus an explicit selector of 0xFFFF selects 65,535, not −1. Neither external slot is read on this path.

When the explicit selector is zero, the following table specifies both the selected value and the external reads. Slots A and B designate two distinct fixed external data locations. Their addresses and semantic meanings are outside this contract.

| Fallback category as an unsigned 16-bit value | External reads, in order | Selected 32-bit value |
|---|---|---|
| 0 | A | Value read from A |
| 1 | None | 1 |
| 2 | None | 2 |
| 3 | None | 0 |
| 4 | None | 4 |
| 8 | None | 8 |
| 16 | B | Value read from B |
| 32 | B, then A | Value read from A |
| 5 through 32,767, excluding 8, 16, and 32 | B | 0 |
| 32,768 through 65,535 | None | 0 |

Consequently:

- Slot A is read exactly when the explicit selector is zero and the fallback category is 0 or 32.
- Slot B is read exactly when the explicit selector is zero and the fallback category is between 5 and 32,767 inclusive, except category 8.
- Slot B’s value is retained as the selected value only for category 16.
- For category 32, B is read first, its value is discarded, and A is then read and selected.
- For every other category that reads B, the fetched value is discarded and the selected value is zero.

The range boundary follows from interpreting the category as signed 16-bit for the range comparison. Patterns 0x8000 through 0xFFFF represent negative values for that comparison and do not enter the B-reading path. None of those patterns matches another recognized category, so each selects zero without reading either slot.

Categories are exact values, not combinable flags. For example, category 3 does not combine selections 1 and 2, and category 5 does not combine selections 1 and 4.

External values enter the 32-bit selection path without visible clamping or normalization. No evidence establishes that either slot is constant, nonzero, or different in value from the other.

A discarded read remains part of the represented behavior. Returning the correct selected value while omitting the B read for category 5, 32, or 64 would not satisfy this access contract.

### Optional inline-region pointer

After resolving the selection, including any external reads, the function reads the 32-bit presence indicator at descriptor offset 24.

- Zero produces a null third dependency argument.
- Any nonzero bit pattern produces the descriptor base plus 28 bytes as that argument.

This is not an equality-to-one test or a signed-positive test. Both 1 and 0x80000000 take the nonzero branch.

The function does not read the inline region’s contents, allocate replacement storage, or copy the region. The pointer aliases the descriptor’s surrounding storage.

A null optional pointer does not suppress the dependency invocation.

### Signed numeric field

For the dependency invocation, the function reads the 16-bit field at offset 4 and sign-extends it to 32 bits.

| Stored 16-bit pattern | Forwarded signed value |
|---|---:|
| 0x0000 | 0 |
| 0x0001 | 1 |
| 0x7FFF | 32,767 |
| 0x8000 | −32,768 |
| 0xFFFF | −1 |

This differs from the unsigned widening of the explicit selector. Equal 16-bit patterns in those two fields need not produce equal 32-bit values.

### Dependency invocation

No dependency result is exposed by this function. If the dependency returns normally, this function returns without an explicit value.

There is no locally represented retry, alternative dependency call, or failure dispatch.

### Observable access order

The supplied representation establishes this direct-access order:

1. Read the explicit selector at descriptor offset 0.
2. Read the fallback category at descriptor offset 6.
3. Perform the selection-path external reads, if any.
4. Read the presence indicator at descriptor offset 24.
5. Determine the optional pointer.
6. Read and sign-extend the field at descriptor offset 4 for the invocation.
7. Invoke F-940bdd7a50cc.

The external-read step has four possible forms: no read, A alone, B alone, or B followed by A. The last form occurs for zero explicit selector and category 32.

This is the ordering represented by the supplied static material. It is not a guarantee of synchronization, atomicity, or a coherent snapshot across fields and slots.

## Side effects

The function contains no explicit writes to descriptor storage or either external slot. It contains no visible allocation, deallocation, inline-region copy, logging, or error-recovery operation.

It does perform external reads even when their values do not survive into the dependency arguments. The contract does not permit those reads to be inferred away merely because the final selected value is zero or comes from the other slot.

The absence of direct writes does not establish end-to-end immutability:

- A nonnull third dependency argument aliases storage beginning at descriptor offset 28.
- No local ownership transfer, retention permission, or lifetime extension is expressed.
- No local release of descriptor storage is shown.
- The dependency’s ability to mutate, retain, or release supplied storage is unknown.
- The dependency’s effects on slots A and B or other global state are unknown.

A slot value retained for forwarding is obtained before the dependency invocation. A later dependency-side change to that slot does not retroactively replace the already supplied argument.

There is no explicit error result for invalid descriptor storage, an inaccessible external slot, an invalid inline region, or dependency failure. Fault handling, exception propagation, and termination behavior are not defined by the supplied material.

In particular, an inaccessible B slot cannot be treated as irrelevant on category 32 merely because A supplies the eventual selected value. The represented B read precedes the A read. No recovery or guarantee of reaching A or the dependency is established if that earlier read cannot complete.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless otherwise stated, they assume valid required accesses and normal progress to the dependency invocation.

### Explicit selection takes precedence

Given explicit selector 0xFFFF, fallback category 32, zero presence indicator, and signed field 0xFFFF:

- The fallback category is still read.
- Neither slot is read.
- Dependency argument 3 is null.
- Argument 4 is −1.
- Argument 5 is 65,535.

### Category 0 reads only A

With a zero explicit selector and category 0, slot A is read once for selection and slot B is not read. Argument 5 receives the value obtained from A.

### Category 16 retains B

With a zero explicit selector, category 16, and B containing 0x80000000 at its read, argument 5 receives that 32-bit pattern. A is not read, and the result is not replaced with literal 16.

### Category 32 reads B before A

With a zero explicit selector and category 32:

- B is read first.
- A is read next.
- Argument 5 receives the value obtained from A, regardless of the value obtained from B.

If B and A contain different values, forwarding B’s value is incorrect. Omitting the B read is also incorrect.

### Discarded B reads still occur

With a zero explicit selector, each of categories 5, 64, and 32,767 reads B, discards its value, and selects zero. None reads A.

This criterion holds regardless of whether B contains zero, a small positive value, or a high-bit 32-bit pattern.

### Unrecognized categories without external reads

With a zero explicit selector, each of categories 3, 0x8000, and 0xFFFF selects zero without reading A or B.

In particular, category 0x7FFF reads B and selects zero, whereas category 0x8000 selects zero without that read. The equal selected results do not make their access behavior equivalent.

### Literal categories avoid slots

With a zero explicit selector, categories 1, 2, 4, and 8 select their corresponding literal values without reading either slot.

Category 8 is the exception within the otherwise B-reading positive range beginning at 5.

### Presence and signed extension are independent

With presence indicator 0x80000000 and signed field 0x8000, dependency argument 3 is the descriptor base plus 28 bytes, and argument 4 is −32,768.

Changing only the presence indicator to zero makes argument 3 null. It does not suppress selection-path reads, the signed-field read, or the dependency invocation.

### Opaque words retain their positions

For arbitrary original input words in positions 1, 2, 4, and 5, the dependency receives those same values in positions 1, 2, 6, and 7 respectively.
