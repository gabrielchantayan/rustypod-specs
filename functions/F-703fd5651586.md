# F-703fd5651586

## Purpose

F-703fd5651586 constructs a 64-bit result from two 32-bit input words and a 32-bit shift argument.

The supplied static representation is consistent with an **arithmetic right shift of a signed 64-bit quantity represented by two words**, for ordinary shift distances from 1 through 63. That interpretation depends on arithmetic signed-right-shift semantics and fixed-width treatment of the left-shifted contribution.

The representation does not establish a complete, portable shift contract for all possible arguments. In particular, a shift argument of zero produces an intermediate shift count of 32, and arguments outside the ordinary 0–63 range can produce other unsupported 32-bit shift counts. Those cases must not be silently assigned conventional 64-bit shift behavior.

This document distinguishes:

- **Established static evidence:** argument widths, branch selection, count extraction, result layout, and represented operations.
- **Inferred intent:** an arithmetic right shift of a two-word signed value.
- **Documented-only unknowns:** execution-platform shift rules, source-language validity, and behavior where a represented 32-bit shift count is 32 or greater.

No runtime tests have been performed.

## Behavior

### Branch selection

The function subtracts 32 from the unsigned 32-bit shift argument, then interprets that 32-bit result as signed for comparison with zero.

Under the fixed-width interpretation indicated by the representation, subtraction wraps modulo \(2^{32}\). The first branch is selected when the wrapped difference has its top bit set.

Consequently, the first branch applies to both of these unsigned ranges:

- 0 through 31.
- `0x80000020` through `0xFFFFFFFF`.

The second branch applies to:

- 32 through `0x8000001F`.

Thus, the branch condition is **not equivalent to an unsigned “shift argument less than 32” comparison over the entire input domain**. It behaves that way only within a restricted ordinary range.

The exact source-language rules behind conversion of an out-of-range unsigned value to signed are not supplied. The ranges above describe the evident 32-bit bit-pattern interpretation.

### First branch: two-word combination

In the first branch, the upper result word is obtained by right-shifting the signed upper input word. Its shift count is the least significant eight bits of the shift argument.

The lower result word combines two contributions using bitwise inclusive OR:

1. The unsigned lower input word, right-shifted by the least significant eight bits of the shift argument.
2. The upper input word, left-shifted by the least significant eight bits of the 32-bit difference between 32 and the shift argument.

The count masking is to **eight bits**, not five bits. The represented operations therefore do not themselves guarantee counts in the range 0–31.

For ordinary shift distances 1–31:

- The right-shift count is the supplied distance.
- The left-shift count is 32 minus that distance.
- The lower word receives surviving bits from the original lower word and incoming bits from the original upper word.
- The upper word receives the shifted original upper word.

If signed right shift replicates the sign bit and the left-shifted contribution is treated as a 32-bit bit pattern, this produces the arithmetic-right-shift interpretation.

At distance zero:

- Both right-shift counts are zero.
- The left-shift count is 32.
- No special case removes or bypasses that left shift.

An identity result at distance zero is therefore inferred intent, not established behavior.

### Second branch: upper-word-only result

In the second branch, the lower input word does not contribute to the result.

The upper result word is the signed upper input word right-shifted by 31.

The lower result word is the signed upper input word right-shifted by the least significant eight bits of the 32-bit difference between the shift argument and 32.

For ordinary shift distances 32–63:

- The lower-word shift count ranges from 0 through 31.
- The upper result word becomes all zero bits for a nonnegative upper input, assuming arithmetic signed right shift.
- The upper result word becomes all one bits for a negative upper input under the same assumption.

At distance 32, the lower result word is the original upper input word’s bit pattern.

At distance 63, both result words are derived from shifting the signed upper input word by 31. Under arithmetic signed right shift, the complete result is zero for a nonnegative conceptual input and all ones for a negative conceptual input.

### Large shift arguments

The represented function does not perform an explicit range check or saturation step.

For the second branch, a represented lower-word count is within 0–31 exactly when the least significant byte of the shift argument is between 32 and 63 inclusive. Thus some arguments greater than 63 reuse the same counts as ordinary distances.

For example, shift argument 288 selects the second branch and gives a lower-word count of zero. Under the stated signed-shift assumptions, it behaves like distance 32, not like a saturating arithmetic shift by 288.

In the first branch, both represented counts are within 0–31 when the least significant byte of the shift argument lies between 1 and 31 inclusive. That can also occur in the large unsigned range selecting this branch.

These observations establish count reuse. They do not establish a general modulo-64 shift policy.

### Arithmetic and width constraints

The following distinctions are material:

- The lower input is unsigned, so its right shift is represented as a logical right shift.
- The upper input is signed, so its right shifts require a signed-right-shift interpretation.
- The upper input also supplies the left-shifted contribution in the first branch.
- Both result components occupy 32-bit fields.
- Concatenation places the component bit patterns into the 64-bit result; it does not add them numerically.
- The OR operation combines contributions only within the lower result word.

The representation does not settle whether left shifting a negative upper input, or left shifting a nonnegative upper input beyond its signed representable range, is a valid fixed-width machine operation or an invalid operation under an originating language’s rules. A behavioral implementation must not resolve that distinction merely by assuming the displayed representation is portable source.
