# F-7405054f15fb

## Purpose

F-7405054f15fb searches selected records in a container for a record whose associated payload matches a query payload. It returns a zero-based ordinal for the first accepted match, or the 32-bit value `0xffffffff` when the search is disabled or terminates without a match.

The search visits every second physical record, starting with physical record zero. Matching requires:

- A nonzero result from a record-eligibility dependency.
- Equal payload-length metadata at an initial comparison.
- A zero result from a payload-comparison dependency.
- Equal payload-length metadata again after that dependency returns.

These are established operations. Interpreting the payloads as strings, the eligibility check as a type check, or the container as a particular collection class would be inferred intent, not established behavior.

## Interface

### Inputs

The function accepts four arguments:

1. **Descriptor address.** An address of a structure containing:
   - At byte offset 0: a container-address word.
   - At byte offset 4: a word whose low eight bits determine whether searching is enabled.

2. **Query-reference address.** An address of a word containing the query-payload address. The query length is obtained from the word immediately before the referenced payload, at payload address minus four bytes.

3. **First auxiliary unsigned word.**

4. **Second auxiliary unsigned word.**

The two auxiliary words initialize local scratch values, but neither initial value controls a subsequent read address, comparison, dependency argument, or return value. Both scratch values are overwritten before they are used to select a comparison length. No externally observable use of the original auxiliary values is established.

### Widths and layouts

The supplied representation uses a 32-bit word and address model:

| Location or value | Width and interpretation |
|---|---|
| Container address in the descriptor | 32-bit address-bearing word |
| Descriptor discriminator | Low eight bits of the word at offset 4 |
| Query-payload address | 32-bit address-bearing word |
| Payload length | 32-bit unsigned word at payload address minus 4 |
| Container record-storage address | Address-bearing word at container offset `0x14` |

The search discriminator is tested after narrowing to eight bits. Upper bits of its containing word do not participate.

Endianness, alignment requirements, calling convention, and a portable language-level interpretation of all address arithmetic are not established by the supplied material. This contract describes the represented 32-bit memory operations, not a portable source-language interface.

### Output

- On a match: the physical record index shifted right by one bit.
- Otherwise, if execution reaches the ordinary failure return: `0xffffffff`.

The function does not return a record address or payload address.

## Behavior

### 1. Search gate

The low eight bits of the descriptor word at offset 4 are examined first.

- If they are not equal to 2, the function returns `0xffffffff`.
- Otherwise, the container-address word at descriptor offset 0 is read.
- If that word is zero, the function returns `0xffffffff`.

Neither disabled case invokes a dependency or dereferences the query-reference argument.

A nonzero container address enables the search; it does not establish that the container or its records are valid.

### 2. Bound acquisition and record selection

The physical search index begins at zero.

Before every potential iteration, F-e84094e554a6 is called with the container address currently read from the descriptor. Its unsigned result is the bound for that particular condition check.

If the current physical index is not less than that result, searching stops with `0xffffffff`.

Otherwise, the function reads the container’s record-storage address at offset `0x14` and selects the record at:

**record-storage address + physical index × 40 bytes**

The container address and storage address used for this selection are read after the bound dependency returns. They are not guaranteed to identify the same state that the dependency inspected.

After a nonmatching iteration, the physical index advances by two. Consequently, the ordinary visited physical indices are 0, 2, 4, and so on. With stable storage, successive visited record addresses are 80 bytes apart.

The bound is not cached. F-e84094e554a6 is called again even for the condition check that ultimately ends the search.

### 3. Eligibility filtering

For each selected record, F-2fb175a232ca is called with:

- The selected record address.
- A fixed address supplied by this function.

A zero result rejects that record immediately. The function does not itself read that record’s payload-address field or the query payload on this path.

A nonzero result permits payload matching. The selected record address remains the one calculated before the eligibility call. If that dependency changes the descriptor or container storage, this function does not reselect the record before accessing its payload field.

The purpose, signature, and effects of the fixed-address object are unknown. Its use as a callback is possible but not established.

### 4. Initial payload-length check

For an eligible record, the function:

1. Reads the candidate payload address from record offset `0x10`.
2. Reads the unsigned candidate length from four bytes before that payload.
3. Reads the query payload address through the query-reference argument and obtains its length from four bytes before that payload.
4. Continues only if the two lengths compare equal.

An initial length mismatch skips the payload-comparison dependency and advances to the next selected record.

There is no special null-payload case. Reaching a zero payload address still leads to an attempted header read relative to that address.

### 5. Comparison-length selection and payload comparison

After the initial equality check succeeds, the function retains the previously read candidate length, rereads the query length into scratch storage, and rereads the query length again for a selection condition.

The comparison count is:

- The retained candidate length if it is less than or equal to the query length observed by the selection condition.
- Otherwise, the query length from the preceding scratch-storage read.

For stable memory, both lengths equal the initially matched length, and that common value is passed as the comparison count.

For changing memory, the selection must not be simplified to a minimum of two current lengths. Its condition and its alternative value come from separate query-header reads.

F-7f14f1ab6851 is then invoked with:

- The candidate payload address captured before the initial length check.
- The query payload address read for this dependency call.
- The selected unsigned comparison count.

The query address is not cached for the whole operation. Different reads through the query-reference argument may therefore identify different payloads.

A nonzero comparison result rejects the record. The sign or magnitude of that result does not otherwise affect searching.

### 6. Post-comparison length check

A zero comparison result is not sufficient for success.

The function rereads the candidate payload-address field from the selected record, then reads the length header associated with that newly obtained address.

It compares this candidate length against a newly read query length:

- If the candidate length is less, the record is rejected.
- Otherwise, the query address and length are read again for an equality check.
- Equality at that second check accepts the record.
- Inequality rejects it.

Thus, with stable memory, zero from the comparison dependency and equal lengths produce a match. With mutation during the dependency, the comparison may have examined different payload addresses or lengths from those used by the final acceptance check.

There is no second payload comparison after those rereads.

### 7. Return and arithmetic boundaries

On acceptance, the function returns the current physical index divided by two through an unsigned right shift.

The successful return occurs before incrementing the index or acquiring another bound.

The physical index is a 32-bit unsigned value. Advancing it by two wraps modulo \(2^{32}\). In particular, a stable bound of `0xffffffff` does not force termination: every even index is below that bound, and the index eventually wraps to zero if no match or other interruption occurs.

The index-times-stride calculation also requires address-range care. The function establishes no overflow guard or record-storage extent check. A numerically large bound is not evidence that the corresponding computed addresses are usable.

For a stable finite bound \(N\) no greater than `0xfffffffe`, and otherwise valid execution without a match, the function visits \(\lceil N/2\rceil\) records before stopping.

## Acceptance examples

These examples are conditional static expectations, not runtime results. Except where stated otherwise, assume valid storage, stable memory, normally returning dependencies, and usable address calculations.

1. **Discriminator disables searching.**  
   If the discriminator’s low byte is 1, the return is `0xffffffff`. No dependency is called, regardless of query-reference contents.

2. **Upper discriminator bits are ignored.**  
   A discriminator word of `0x00000102` passes the byte test. Searching still requires a nonzero container address.

3. **Enabled discriminator with absent container.**  
   A low byte of 2 and a zero container-address word produce `0xffffffff` without a bound call or query read.

4. **Empty bound.**  
   If the first bound result is zero, no record is inspected. The result is `0xffffffff`.

5. **Only alternate physical records participate.**  
   With a stable bound of 5, the function considers physical records 0, 2, and 4. A matching record at physical index 1 alone cannot cause success.

6. **Returned ordinal differs from physical index.**  
   If physical record 0 fails and physical record 2 is the first accepted match, the return is 1.

7. **Eligibility prevents direct payload inspection.**  
   If eligibility returns zero for every visited record, this function does not directly read their payload fields or the query payload. Dependency-internal reads remain unspecified.

8. **Unequal lengths avoid comparison.**  
   A stable candidate length of 3 and query length of 4 reject the record without invoking F-7f14f1ab6851.

9. **Equal lengths do not guarantee a match.**  
   With stable equal lengths of 4, a nonzero comparison result rejects the record.

10. **Zero-length matching still invokes the dependency.**  
    Stable zero lengths pass the initial check and produce a comparison call with count zero. Acceptance still requires that dependency to return zero and the final lengths to agree.

11. **Mutation after comparison can reject a candidate.**  
    Suppose the dependency returns zero but leaves the candidate’s final length at 3 and the query’s final length at 4. The record is rejected.

12. **The bound is reacquired.**  
    If the initial bound is 3, record 0 fails, and the next bound result is 2, the new physical index 2 fails the bound check. Physical record 2 is not inspected.

13. **Maximum bound permits cycling.**  
    With a constant bound of `0xffffffff`, no accepted record, and otherwise sustainable execution, unsigned index wraparound permits repeated traversal rather than guaranteeing the failure return.
