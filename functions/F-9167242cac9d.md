# F-9167242cac9d

## Purpose

F-9167242cac9d obtains a signed value from F-aa672b15efb7 and conditionally limits its magnitude according to a one-byte selector read from a caller-supplied memory region.

For values whose magnitude is representable as a signed 32-bit integer:

- Selector values **1 and 4** impose a magnitude limit of **4**.
- Selector values **2, 3, and 11** impose a magnitude limit of **7**.
- Every other selector value leaves the dependency’s result unchanged.
- Limiting preserves the original sign.

This is the established observable transformation, not a claim about the application-level meaning of either the selector or the dependency’s result. The supplied material does not establish whether these values represent positions, rates, priorities, or another quantity.

The most-negative signed 32-bit value requires separate treatment: its positive magnitude is not representable in the same signed width. The supplied representation does not establish a portable result for that case.

## Behavior

### Observable access and call order

The function first reads the four-byte field at offset 0x98. It passes the value obtained by that read to F-aa672b15efb7, making one visible call to that dependency.

Only after the dependency returns does the function read the selector byte at offset 0x2D.

This ordering is part of the contract. The selector is not an entry-time snapshot. If F-aa672b15efb7 changes the selector in a way visible to the subsequent read, the changed selector controls the result.

Conversely, the dependency argument is obtained before the call. A change to the field at offset 0x98 during the dependency call does not cause this function to load a replacement argument or call the dependency again.

The supplied body shows no additional memory reads after the selector access. The remaining visible work consists of signed comparisons and arithmetic on the returned value and the captured selector.

This establishes ordering within the supplied function. It does not establish synchronization, atomicity, or a cross-thread consistency guarantee.

### Sign and magnitude handling

The function distinguishes negative dependency results from zero and positive results.

For a negative result, it selects a negative sign factor. For zero or a positive result, it selects a positive sign factor. It then multiplies the dependency result by that factor to obtain a magnitude-like intermediate.

For every signed 32-bit input except −2,147,483,648, this intermediate is the ordinary nonnegative absolute magnitude. The selector determines whether an upper bound is applied to that intermediate. The previously selected sign is then applied to produce the return value.

The sign is selected from the dependency’s result, not from the selector or any memory field. No sign is reread from memory.

### Selector groups

The selector groups are exact:

| Selector values | Magnitude handling |
|---|---|
| 1, 4 | Limit to at most 4 |
| 2, 3, 11 | Limit to at most 7 |
| 0, 5–10, 12–255 | No limit |

The upper-bound comparisons are strict. A magnitude equal to the limit is not reduced. For example, +4 and −4 remain unchanged under selector 1; +7 and −7 remain unchanged under selector 3.

No selector is rejected as invalid. Values outside the two limited groups take the unlimited path rather than producing an error or a default limit.

For ordinary representable magnitudes:

- The limit-4 group returns a value in the inclusive interval −4 through +4.
- The limit-7 group returns a value in the inclusive interval −7 through +7.
- The unlimited group returns the dependency’s original value.
