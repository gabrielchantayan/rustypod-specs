# F-83d365b3a517

## Purpose

The established behavior is a single visible sequence of indirect calls and memory accesses. Three explicit inputs, additional register-derived state, and dependency results determine the addresses, stored values, and call arguments.

No application-level purpose is established. Repeated clearing and population of storage might indicate initialization or reconfiguration, but that is inferred intent, not a contractual guarantee. The evidence does not identify ordinary objects, arrays, containers, allocator metadata, or hardware registers.

The supplied static representation terminates at an invalid-instruction boundary. It does not establish a normal return, successful completion, or recoverable error result.

Every event below is conditional on execution reaching it: preceding accesses must complete, dependencies must return, and execution must continue as represented.

## Interface

| **B** | 32 bits | Used in address arithmetic, written as a word, and passed directly and shifted to dependencies. |

Observing the entire sequence requires valid reached memory accesses, callable targets compatible with the actual execution environment, and returning dependencies. The evidence supplies no validation of these conditions.

### Width and arithmetic notation

- A **word** access transfers 32 bits; a **byte** access transfers eight bits.
- **W(x)** means the low 32 bits of x.
- **low8(x)** means the low eight bits.
- **field(x)** means `low8((x AND 0x3fffffff) logically shifted right by 20)`.
- A byte used to select an address is zero-extended, not interpreted as a pointer-sized load.
- Address formulas use W to express their represented 32-bit bit patterns.

This notation is not a claim that every displayed signed multiplication or left shift has defined source-language semantics for every input. Exact instruction behavior at those ambiguities remains unresolved.

Endianness, alignment requirements, memory permissions, and misaligned-access behavior are not established. A word destination describes one 32-bit access, not four independently ordered byte writes.

### 1. Publish A and B

1. Write A as a word at **W(4B + 0x14)**.
2. Read a word at **W(A + 0x14)** and logically shift its unsigned 32-bit value right by three.
3. Call **F-D01a** with that shifted value, B, C, and **W(B shifted left by 6)**.
4. Call **F-D01b–F-D01e** without explicit arguments. Capture the last 32-bit result as **J**.
5. Write B as a word at **W(4J + 0x14)**.
6. Call **F-D02a** with **W(4J)**.
7. Call **F-D02b–F-D02e** without explicit arguments. Capture the last unsigned 32-bit result as **U**.

The first store precedes the read through A. If their accessed storage aliases, the read can observe that store.

### 2. Publish C and perform the first selected byte write

2. Call **F-D03a** with P and **W(U shifted left by 2)**.
3. Call **F-D03b–F-D03e** without explicit arguments.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes preceding events complete and any stated memory conditions hold.

1. **Initial aliasing.** If A equals W(4B), the initial store and following read address the same word. With ordinary memory and no intervening mutation, F-D01a receives the stored A bit pattern logically shifted right by three as its first argument—not the pre-entry word.

2. **Zero U.** If U is zero, P and Q are zero. The P-based C store targets `0x24`, the subsequent word read targets `0x74`, P-selector reads target `0x01`, and the direct Q-derived byte clear targets `0x0f`. Address validity is a separate condition.

3. **Fresh selectors.** If the first P-selector read yields `0x20` and the second yields `0x40`, their byte destinations are `0x31` and `0x51`. Reusing the first selector for the clear would violate the sequence.

4. **Retained selector.** If β is `0x7f`, its byte clear targets `0x90` and its later word clear targets `0xc3`. A dependency changing H-based selector storage between those writes does not change the captured word destination.

5. **Byte truncation.** If U₂ is `0x12345678`, its first final-stage byte value is `0xe0`; its later field value is `0x23`. These writes have intervening calls and separate selector reads.

6. **Maximum masked scale.** If M is `0x3fffff`, S is `0x1fffff80`, and M shifted left by four is `0x03fffff0`. Neither requires sign extension from a narrower field.

7. **Selector passed rather than stored value.** If γ is `0x20` and U₃ is 3, the associated store writes `0x0c` at `0x31`, while F-D22a receives `0x20`.

8. **Access accounting.** If the entire represented sequence is reached, it has 27 direct writes and ten direct reads: two word reads and eight byte reads. Aliasing does not reduce those event counts.

9. **Failure and termination.** If the first store faults, no later call is established as occurring. If every listed call completes, successful return still is not established because the terminal instruction behavior remains unresolved.
