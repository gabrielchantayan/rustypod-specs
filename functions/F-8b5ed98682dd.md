# F-8b5ed98682dd

## Purpose

F-8b5ed98682dd performs selection-dependent dispatch. It captures a selection from its input object, obtains a related object, passes temporary storage through several dependencies, and branches on a returned 32-bit classification. The resulting path either delivers a resource-associated value to the input object or performs a separate sequence involving global inputs, a service object, and optional object configuration.

Normal return values have a narrow meaning:

- **0:** the captured selection was −1; no dependency was called.
- **1:** a non-sentinel path reached the final dependency call and returned normally.

Return value 1 does not establish successful notification, activation, resolution, allocation, or cleanup. Some paths return 1 without obtaining a service object or resolving a destination.

**Inferred intent:** symbolic resource labels suggest unavailable-information, loading, and feature-start actions. These interpretations do not establish resource contents or dependency effects. “Notification” and “activation” below name observable call paths, not guaranteed user-visible outcomes.

### Entry and common sequence

The first object-field read shown in the body captures the selection at input offset 0xD4.

If it equals −1, the function returns 0 immediately. No related-object lookup, dispatch-table access, temporary-region dependency call, or global-input read occurs.

Every other 32-bit selection proceeds without a visible local range check, including negative values other than −1.

The common sequence is:

1. F-6da76fc58c80 receives the input object and returns the related-object address.
2. F-ba5a4c1e0746 receives the descriptor-region address, zero, and zero.
3. F-ec8e3558572e receives the related object and captured selection.
4. F-3676a46d9aec receives the related object, the result of F-ec8e3558572e, and the descriptor-region address.
5. F-504b664a4c49 receives the related object and descriptor-region address. Its result selects the subsequent branch.

No null check is visible for the related-object result. Passing it to dependencies does not itself prove that they dereference it; classification-zero paths subsequently dereference it for dynamic dispatch.

Calling F-ba5a4c1e0746 “preparation” or F-4e292a3dd745 “finalization” would describe inferred roles only. The established facts are their arguments and placement in the call sequence.

### Classification 1 and classification 2

Classification 1 selects R1. Classification 2 selects R2.

Both then follow the same notification path:

1. F-9b9c1c7483f4 receives the value-region address and selected resource address.
2. Its returned 32-bit value is supplied to the input object’s dynamic method at byte offset 0x11C, with the input object as receiver.
3. F-8a5aadac202f receives the value-region address.
4. F-4e292a3dd745 receives the descriptor-region address.
5. The function returns 1.

The notification method’s result is ignored. Nothing in this body proves that F-9b9c1c7483f4 writes the value region or that its return value represents an object stored there.

These paths do not invoke the related-object methods at 0x9C, 0xA8, or 0xAC.

### Classification 0: preliminary result and 64-bit branch

The related object’s method at dispatch-table byte offset 0x9C is invoked with that object as receiver and no additional visible argument. Its 32-bit result is retained.

F-40819ce9a421 is then called without visible arguments.

If the lower 32 bits of its 64-bit result are zero, R3 is selected and the notification path described above runs. The upper half has no further use on this path. F-4e6b58fde38f is not called.

If the lower half is nonzero, F-4e6b58fde38f receives:

1. The retained result of related-object method 0x9C.
2. The upper 32 bits of the result from F-40819ce9a421.

The lower half is not passed separately. The body establishes no relationship tested between these arguments; it establishes only that the dependency’s returned value is checked for zero versus nonzero.

### Classification 0: zero result from F-4e6b58fde38f

R2 is then selected, followed by the notification path, the call to F-4e292a3dd745, and return value 1.

The method at 0xAC precedes F-9b9c1c7483f4. Its effect is unknown. The activation path is not taken.

## Side effects

### Established reads and ordering

The globals are consumed at their respective call sites:

- G1 is read after F-9b9c1c7483f4 returns.
- G2 is read after F-10655c9db871 and F-938c950e5046 return.

G3 precedes G4 in the resolver’s **argument positions**. The supplied representation does not establish the relative evaluation order of those two reads within the call’s argument evaluation. No such read order is required by this contract.

## Acceptance examples

These examples are conditional static contracts, not executed tests. Unless otherwise stated, assume valid required addresses and normally returning dependencies.

1. **Sentinel:** Selection −1 returns 0 without dependency calls or activation-global reads.

2. **Other negative selection:** Selection −2 proceeds through the common sequence and reaches F-ec8e3558572e unchanged. No local range rejection occurs.

3. **Selection mutation:** If F-6da76fc58c80 changes the input selection, F-ec8e3558572e still receives the entry-time value.

4. **Classification 1 or 2:** Classification 1 supplies R1 to F-9b9c1c7483f4; classification 2 supplies R2. The returned value reaches input-object method 0x11C, followed by F-8a5aadac202f and F-4e292a3dd745. This does not prove that temporary storage was written or released.

5. **Unsupported classification:** Classification 3 reaches F-a817d8d58c10. Neither a normal result nor the final descriptor-region call is promised.

6. **Zero lower half:** A 64-bit result of 0x0000000100000000 selects R3 notification despite its nonzero upper half. F-4e6b58fde38f is skipped.

7. **Nonzero lower half:** A result of 0x8000000000000001 causes F-4e6b58fde38f to receive second-argument bits 0x80000000. The upper half’s sign bit is not an availability gate.

8. **Zero branch result:** If F-4e6b58fde38f returns zero, related-object method 0xAC precedes the R2 notification sequence. Method 0xA8 and service acquisition are skipped.

9. **Global mutation before consumption:** If the activation-path F-9b9c1c7483f4 call changes G1, F-4b9875325552 receives G1’s subsequently read value, not an entry snapshot. Likewise, changes to G2 before the service-method call affect that argument.

10. **Resolver mapping:** With a nonzero service result, the resolver receives G3 from 0x08226194 in its second position and G4 from 0x08226190 in its third. No relative order between those two reads is promised.

11. **Zero service result or resolution:** A zero service result skips the resolver, G3/G4 reads, and configuration. A zero resolver result skips configuration only. Both paths still call F-4e292a3dd745 and return 1.

12. **Configuration table mutation:** A nonzero resolved address receives `(0, 1)` before `(2, 1)`. If the first method changes that object’s dispatch table, the second dispatch uses the table read for the second call, not a guaranteed cached target.
