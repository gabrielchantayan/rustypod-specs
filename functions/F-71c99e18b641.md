# F-71c99e18b641

## Purpose

F-71c99e18b641 returns a 32-bit unsigned result through one of two paths selected by the first input byte.

- When that byte is `0x1E`, the function parses subsequent bytes as high-nibble-first numeric tokens, applies a decimal scale, and assembles integer and fractional contributions.
- Otherwise, it calls F-f089df22028c, transforms that dependency’s result, and either returns zero or invokes an unresolved indirect dependency whose result becomes the return value.

The marked representation recognizes decimal digits, a decimal-point marker, two exponent markers, and a negative marker. It does not enforce a conventional numeric grammar. Some markers terminate parsing in particular phases, and termination generally requires an encountered non-digit rather than exhaustion of the supplied range.

A scaled fixed-point conversion is the inferred intent. The complete numeric interpretation is not established: two dependencies have unavailable implementations, and the fractional-digit acceptance comparison uses a shared object whose declaration is absent.

## Behavior

### Initial dispatch and read order

The visible order is:

1. Read the initial address from the first descriptor word.
2. Read the end address from the second descriptor word.
3. Read the byte at the initial address.
4. Select marked parsing only if that byte equals `0x1E`.

The initial byte read is unconditional with respect to the range boundary.

On the non-marked path, the visible body performs no additional input-buffer reads. On the marked path, the initial marker byte contributes no numeric nibbles.

### Non-marked path

F-f089df22028c is called once with no explicit arguments.

Its result is multiplied by 65,536 and assigned to a 32-bit unsigned intermediate. Under the represented 32-bit bit-vector interpretation, this retains the dependency result’s low 16 bits in the intermediate’s upper half and discards its original upper half.

If the intermediate is zero, the function returns zero without invoking the indirect dependency.

Otherwise, the function derives a sign mask, forms an unsigned magnitude, applies a conversion scaled by 1,000, restores the sign, and passes the resulting 32-bit value as the sole visible argument to the unresolved indirect dependency.

The visible conversion includes a small-magnitude branch with a bound of 2,049. Under the same bit-vector interpretation, every reachable nonzero magnitude is a multiple of 65,536, so that branch is unreachable. The remaining expression gives an indirect-call argument equivalent to:

\[
1000 \times \operatorname{signed16}(\text{dependency result's low 16 bits}).
\]

Its mathematical range is −32,768,000 through 32,767,000. Negative values are supplied as their 32-bit representations.

This equivalence describes the argument, not the final return. The indirect dependency can transform it or have other effects.

The initial multiplication is represented as a signed operation before unsigned assignment. Consequently, the low-16-bit reduction is not a portable guarantee for executions involving signed overflow; such cases remain **documented_only** without established execution arithmetic.

### Marked-path state and traversal

Marked parsing initializes:

- Integer accumulator to zero.
- Fractional numerator to zero.
- Fractional denominator to one.
- Decimal scale to three.
- Negative flag to false.

These numeric accumulators and the scale are represented as signed 32-bit integers. Extracted nibbles are unsigned.

Parsing begins at the byte after `0x1E`. Before reading that byte, the function advances its private pointer and compares it with the end address. If the advanced pointer reaches or exceeds the end, the function returns zero.

Each payload byte supplies its high nibble before its low nibble. Each nibble extraction visibly reads the current byte; the representation does not show a cached payload byte shared by both extractions.

Whenever traversal needs another byte, it advances the pointer and checks the boundary before reading. It does not read at or beyond the end following a failed boundary check.

A terminating high nibble can finish parsing without processing the low nibble. Conversely, digits ending exactly at the boundary do not complete a number: if another nibble is needed to find termination, exhaustion returns zero.

### Integer phase

The integer phase interprets nibbles as follows:

| Nibble | Behavior |
|---|---|
| `0`–`9` | Multiply the integer accumulator by ten and append the digit |
| `E` | Set the negative flag and continue |
| `A` | Enter fractional processing |
| `B` | Enter positive-exponent processing |
| `C` | Enter negative-exponent processing |
| `D`, `F` | End numeric collection and begin scaling |

The negative flag is sticky. Repeated `E` markers do not toggle it. An `E` after integer digits still sets the flag.

No integer digit is required before a decimal marker, exponent marker, or terminator.

### Fractional phase and shared comparison

After `A`, consecutive decimal nibbles are consumed as fractional digits.

For each digit, the function reads a shared object and evaluates a less-than comparison between the current fractional denominator and that object.

- If the comparison evaluates true, it appends the digit to the fractional numerator, then multiplies the denominator by ten.
- If the comparison evaluates false, it consumes the digit without changing either accumulator.

**The shared object’s declaration is not supplied. Its width and signedness are not established.** Although the denominator is represented as a signed 32-bit accumulator, that fact alone does not determine the comparison’s promotions or ordering semantics.

Accordingly, the established acceptance rule is the truth value of the represented comparison. Describing acceptance as “the denominator is mathematically below the threshold” requires an additional assumption that the missing declaration and applicable conversions preserve that ordinary ordering for the values involved.

The comparison occurs before either update. Even under ordinary numeric ordering, acceptance does not ensure that the updated denominator remains below or equal to the shared value.

The shared read occurs for each fractional digit rather than once at phase entry. The representation does not establish the object’s initialization, synchronization, volatility, or behavior under concurrent modification.

The first non-digit ends fractional processing:

- `B` or `C` starts exponent processing.
- Every other non-digit proceeds directly to scaling.

In particular, fractional-phase `E` does not set the negative flag, and a second `A` does not restart fractional processing.

Discarded digits still consume input. Exhaustion before a terminating non-digit returns zero regardless of whether fractional digits were accepted or ignored.

### Exponent phase

An exponent begins only at `B` or `C` encountered in the integer phase or as the first non-digit after the fraction.

The exponent accumulator starts at zero. Consecutive decimal digits are appended by multiplication by ten and addition.

The first following non-digit is consumed as the exponent terminator. It is not reinterpreted as a negative marker, decimal marker, or further exponent marker.

For non-overflowing arithmetic, the resulting scale is:

- Three plus the accumulated exponent after `B`.
- Three minus the accumulated exponent after `C`.

An immediate non-digit is an accepted empty exponent and leaves the scale at three.

There is no visible exponent-length or overflow check. Exhaustion after an exponent marker or its digits, before a non-digit terminator, returns zero.

### Scale application

Scaling begins only after numeric collection terminates.

For every positive scale step, the function:

1. Multiplies the integer accumulator by ten.
2. Multiplies the fractional numerator by ten.
3. Decrements the scale toward zero.

The denominator remains unchanged.

For every negative scale step, the function:

1. Calls F-870c4fcf7295 with the current integer accumulator and ten.
2. Replaces the integer accumulator with that return value.
3. Multiplies the fractional denominator by ten.
4. Increments the scale toward zero.

The numerator remains unchanged during negative scaling. F-870c4fcf7295 is called once per step even when the integer accumulator is zero.

Repeated integer division by ten is inferred intent, not an established dependency contract. Its rounding, exceptional behavior, and side effects are unknown.

There is no visible independent iteration limit. Discarded fractional digits are never reconsidered during scaling.

### Result assembly

After scaling, the integer accumulator is shifted left by 16 bits to form the integer contribution to the unsigned result.

If the fractional numerator is zero, no fractional-conversion call occurs.

Otherwise, F-73d099a86adb receives the scaled numerator and denominator. Its return is combined with the integer contribution using bitwise OR.

There is no visible mask restricting that dependency’s result to the low 16 bits. Its upper bits can therefore affect the result’s upper half. Composition is not addition and supplies no arithmetic carry between components.

If the negative flag is set, the complete combined unsigned result is then negated modulo \(2^{32}\).

## Acceptance examples

These are static derivations, not executed tests. Inputs are hexadecimal bytes, with the end address immediately after the listed bytes. Unless stated otherwise, memory is valid and stable, and the arithmetic involved is representable.

1. **Integer with termination — `1E 12 F0`**

   The integer becomes twelve. `F` terminates collection before the low nibble is processed. Default scaling produces 12,000, and the return is `0x2EE00000`. No fractional-conversion call occurs.

2. **Negative marker after a digit — `1E 1E F0`**

   The integer becomes one, then `E` sets the flag. The return is `0xFC180000`, the unsigned negation of `0x03E80000`.

3. **Repeated negative markers — `1E EE 1F`**

   Both `E` markers set the same sticky flag. The result is again `0xFC180000`; the markers do not cancel.

4. **Terminator without digits — `1E F0`**

   The return is zero. The low nibble is not processed, and no fractional conversion occurs.

5. **Exhaustion — `1E 12` or `1E`**

   Both return zero. The former lacks a terminating non-digit; the latter lacks any payload byte.

6. **Accepted fractional digit — `1E 1A 5F`**

   If the shared-object comparison evaluates true when the denominator is one, digit five is accepted. After scaling, F-73d099a86adb receives 5,000 and ten. If its return is \(R\), the function returns `0x03E80000` bitwise-OR \(R\).

   A stable shared numeric value greater than one is sufficient only under the additional assumption that its declaration and comparison conversions implement ordinary ordering for those values.

7. **Ignored fractional digit — `1E 1A 5F`**

   If that comparison evaluates false, five is consumed but ignored. The numerator remains zero, no fractional conversion occurs, and the result is `0x03E80000`.

   A stable shared numeric value at or below one implies this outcome only under the same ordinary-ordering assumption. The missing declaration prevents an unconditional threshold-based assertion.

8. **Zero digit can grow the denominator — `1E A0 F0`**

   If the comparison evaluates true, the numerator remains zero while the denominator becomes ten. No fractional-conversion call occurs because its condition depends on the numerator, not on whether a digit was accepted. The result is zero.

9. **Negative scale — `1E 1C 4F`**

   The scale becomes minus one. F-870c4fcf7295 is called once with one and ten. If it returns zero, the function returns zero. An assumed division result must not replace the actual dependency result.

10. **Fractional negative marker — `1E 1A EF`**

    `E` terminates fractional processing without setting the flag. The return is positive `0x03E80000`.

11. **Exponent terminator — `1E 1B 0E`**

    The exponent is zero. `E` is consumed as its terminator rather than interpreted as a negative marker. The return is `0x03E80000`.

12. **Non-marked conversion**

    If F-f089df22028c returns −1, its multiplication by 65,536 is representable, and the indirect dependency receives the 32-bit representation of −1,000. The final return is that dependency’s result.

    Under an explicitly assumed 32-bit bit-vector interpretation of the initial multiplication, a dependency result of `0x00010000` instead yields zero without an indirect call. Its signed multiplication overflow prevents treating this as an unconditional portable-language example.
