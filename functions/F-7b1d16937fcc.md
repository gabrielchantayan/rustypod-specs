# F-7b1d16937fcc

## Purpose

F-7b1d16937fcc coordinates a preparation operation, stages metadata when preparation succeeds, and invokes a second operation using the prepared workspace.

The established branch contract is:

- A nonzero preparation result skips metadata staging and the second operation. After conditional cleanup, the function returns the 32-bit value 7.
- A zero preparation result selects one of two metadata layouts, stages that layout, and invokes the second operation.
- After the second operation, the function conditionally invokes cleanup, clears bit 7 of the input object's current flag byte, and returns the second operation's 32-bit result.
- Cleanup eligibility depends on bit 0 of a local 16-bit field, not directly on the preparation result.

“Preparation,” “workspace,” “transfer,” and “cleanup” identify structural roles. Their application-level meanings and the internal behavior of the dependencies are not established.

### Preparation

### Nonzero preparation result

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each assumes valid accesses and normal return from invoked dependencies.

1. **Single retained-address adjustment.**  
   If the entry-time value at input +0x08 is 0x1000, the retained address is 0x1208. Preparation receives 0x1208 as argument 1. If the second operation is reached, it also receives 0x1208 as argument 1. Neither receives 0x1410.

2. **Nonzero preparation.**  
   Any nonzero preparation result leads to return value 7 after the cleanup check. Metadata staging, the second operation, and the direct flag-byte update do not occur.

3. **First layout.**  
   If preparation returns zero and the selection read finds bit 1 clear, staging uses workspace offsets +88, +92, +100, and transfer destination +104.

4. **Second layout.**  
   If the selection read instead finds bit 1 set, staging uses +168, +172, +180, and transfer destination +184.

5. **Unguarded subtraction.**  
   If F-8810f53aaa0b returns zero, preparation is still called with a fourth argument representing −1.

6. **Output slot remains zero.**  
   If the output slot remains zero through its argument read, F-0436ad55a07c receives zero as argument 4.

7. **Output slot changes later.**  
   If preparation leaves the slot zero but a later dependency changes it through an available alias to 0x12345678 before sampling, the second operation receives 0x12345678.

8. **Related-object selection changes.**  
   If input +0x08 changes after entry but before derived-metadata evaluation, the +0x3c4 read uses the newly read related-object address. Both major operations still receive the original retained address.

9. **Repeated dependency returns differ.**  
   If the two F-44362605ab79 calls return different values, preparation receives the first and the second operation receives the second.

10. **Second-operation result does not suppress finalization.**  
    Any 32-bit result from F-0436ad55a07c is propagated unchanged on normal completion. Cleanup checking and bit-7 clearing still occur.

11. **Final flag sampling.**  
    A final flag read of 0xff produces a write of 0x7f. A final read of 0x02 produces 0x02, regardless of the earlier layout-selection value.

12. **Current cleanup pointer.**  
    If cleanup bit 0 is set, cleanup receives the pointer-field value current at the call, not necessarily the initial inline-storage address. If the bit is clear, no cleanup call occurs.
