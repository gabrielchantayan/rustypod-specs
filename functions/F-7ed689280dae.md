# F-7ed689280dae

## Purpose

F-7ed689280dae performs an unconditionally repeated sequence of indirect calls, byte accesses, and 32-bit memory accesses. Call results and hidden entry state determine addresses, stored values, subsequent call arguments, and loop-carried state.

The supplied static evidence establishes no application-level purpose. It does not support classifying the routine as initialization, serialization, allocation, device control, or object management.

This contract describes the represented access order and dataflow. Reaching any later event requires earlier calls to return and earlier memory accesses to complete. Neither condition is established for an actual execution.

## Interface

### Explicit inputs and output

The represented interface has four 32-bit inputs and no declared return value.

- **First input:** supplied to the first indirect call of the initial iteration. Each iteration’s final call supplies its replacement for the next iteration.
- **Second and third inputs:** have no visible explicit use. This does not establish their irrelevance under an incompletely recovered calling convention.
- **Fourth input:** its low eight bits supply the first two byte stores. It is set to zero late in the first iteration and remains zero in the represented subsequent iterations.

No normal return, completion status, or exit condition is represented. Absence of a declared return value is not evidence of successful completion.

### Hidden inputs and loop-carried state

Execution additionally depends on:

- An incoming continuation/code-location value used to derive the **initial iteration’s first indirect-call target**.
- An initial byte-access base.
- An initial 32-bit value used in a left shift by 28 bits.
- An initial unsigned 32-bit value used in a logical right shift by 22 bits to form a read address.
- A global 32-bit value read during each iteration.
- An unresolved secondary result-channel value used as a later call argument.
- Results and effects of unresolved indirect calls.

The continuation/code-location value is mutable loop-carried state, not an immutable entry parameter. Near the end of every completed iteration, **between the final two indirect calls**, it is replaced with a fixed embedded code location. Thus only the initial iteration’s first target depends on the incoming continuation. Subsequent iterations derive that target from the replacement location.

The next first input is obtained separately, from the final call’s result. Updating the continuation and obtaining that input are distinct events.

### Widths and arithmetic

Selector reads are unsigned eight-bit reads. Byte stores retain only the low eight bits. Word reads and stores are 32 bits. Ordinary represented arguments and results are 32 bits; several results are 64 bits and are separated into low and high 32-bit halves.

Address expressions below describe numeric address formation, not validated object layouts. A selector-derived address is absolute unless explicitly described as base-relative.

For conditional numerical examples, 32-bit bit-vector arithmetic is assumed: multiplication and left shifts retain the low 32 bits, and explicitly unsigned right shifts are logical. Some represented operations use signed operands. Their overflow and signed-left-shift behavior are not established as portable guarantees. Pointer width, address wraparound, alignment requirements, and endianness remain unresolved.

## Behavior

### Execution boundaries

The body executes at least once and repeats without a represented condition.

Every indirect call is an observable boundary, including calls with unused results. No call is established as pure, successful, memory-preserving, or global-preserving. “No explicit arguments” below describes the supplied representation, not a proven machine-level zero-argument interface.

The following stages preserve the order of represented calls and memory accesses. Descriptive terms such as “factor,” “expanded base,” and “replicated word” identify dataflow roles only.

### Ordered iteration

1. **Obtain the first result and write the input byte.**  
   The first call receives the current first input. Its target is the current continuation/code-location value plus 4094 bytes. Four more calls follow; the last supplies a 32-bit result. The low byte of the current fourth input is stored first at the current byte-access base plus 17, then at that base plus 1.

2. **Store shifted hidden state.**  
   A call receives the preceding result shifted left by two bits. Four further calls produce an address factor. A 32-bit store writes the current hidden shift value shifted left by 28 bits at 16 times that factor plus 20. Four times the factor is retained for later use.

3. **Read the source word.**  
   Immediately after that store, a 32-bit unsigned word is read at the current hidden unsigned address value logically shifted right by 22 bits, plus 20. The byte-access base is not added.

4. **Retain a payload and clear a word.**  
   A call receives the four-times factor retained in stage 2. The next call supplies a payload retained for later uses. A further call receives the source word logically shifted right by 22 bits and then left by 28 bits. Four more calls produce another factor. A 32-bit zero is stored at four times that factor plus 20.

5. **Write through a freshly read selector.**  
   A call receives four times the preceding factor. Four further calls produce an unsigned 32-bit result. An unsigned byte is read at the current base plus 1. The low byte of the new result shifted left by two bits is stored at the selector’s numeric value plus 17, without adding the base.

6. **Extract a byte and retain its selector.**  
   A call receives the unsigned result shifted left by two bits. The following call supplies a value passed to another call together with that unsigned result shifted left by 30 bits. Four further calls produce another result. The selector at the current base plus 1 is reread and retained. At selector plus 17, the routine stores the low byte of the earlier unsigned result masked to 30 bits and logically shifted right by 20 bits.

7. **Store a word using the retained selector.**  
   A call receives the latest result shifted left by two bits; four further calls follow. The payload retained in stage 4, shifted left by two bits, is stored as a 32-bit word at the retained selector plus 20. There is no new selector read for this store.

8. **Snapshot the global and obtain the first wide result.**  
   The global 32-bit value is read and retained. A call receives the four-times factor from stage 2. Four further calls follow; the last supplies a 64-bit result. Its low half shifted left by two bits becomes the **first expanded base**. The selector at the current base plus 1 is reread. The low byte of the global snapshot logically shifted right by 22 bits is stored at selector plus 17.

9. **Use the high half and clear a byte.**  
   A call receives the high half of the first wide result. The next call supplies a value passed onward together with the first expanded base shifted left by 28 bits. Four further calls produce another result. The selector at the current base plus 1 is reread, and zero is stored at selector plus 17.

10. **Create the first replicated word.**  
    A call receives the latest result shifted left by two bits. Four further calls produce a result passed twice, each time shifted left by two bits, to the next call. Four more calls produce a value whose left shift by two bits becomes the **first replicated word**. This word is stored at 4096 times the first expanded base plus 20.

11. **Replicate the first word.**  
    A call receives the first expanded base shifted left by 14 bits. Four further calls produce an address factor. The first replicated word is stored at four times that factor plus 20.

12. **Obtain a second wide result and use a scaled selector source.**  
    A call receives four times the preceding factor. Four further calls produce a 64-bit result. Its low half shifted left by two bits becomes the **second expanded base**. A selector is read at 16384 times the first expanded base plus 1. At selector plus 17, the routine stores the low byte of the first replicated word masked to 30 bits and logically shifted right by 20 bits.

13. **Forward wide-result halves and clear a selected byte.**  
    A call receives the high half of the second wide result. The following call supplies a value passed as the next call’s single explicit argument. Another call produces a further 64-bit result. Its low and high halves are passed, in that order, to the next call. After two more calls, a selector is read at 268435456 times the second expanded base plus 1, and zero is stored at selector plus 17.

The next call receives, in order, the second replicated word shifted left by 28 bits and the unresolved secondary result-channel value. Four further calls produce an address factor. The second replicated word is stored at four times that factor plus 20.

    A call receives the final replicated word as three explicit arguments. Four further calls produce an address factor. The final replicated word is stored at four times that factor plus 20.

    A call receives four times the preceding address factor. Four further calls produce another result. The next unsigned address value is set to that result shifted left by two bits. The next hidden shift value is set to the preceding address factor shifted left by three bits.

No allocation, release, reference counting, ownership transfer, or lifetime extension is established. Address-like values passed to dependencies are not thereby owned pointers.

## Acceptance examples

These are conditional static deductions, not executed tests.

1. **Initial truncation and order.**  
   With fourth input 0x123456AB, reaching the first stores writes 0xAB at current base plus 17 before writing 0xAB at current base plus 1.

2. **Absolute selector destination.**  
   A selector value of 200 selects byte address 217, not current base plus 217.

3. **Extraction still truncates.**  
   If the unsigned result in stage 6 is 0x3FF00000, masking and shifting yields 0x3FF; the byte store writes 0xFF.

4. **Saved selector is not reread.**  
   If stage 6 retains selector 7 and a later call changes its source byte to 9, stage 7 still writes at address 27, assuming the access completes.

5. **Wide halves have different roles.**  
   If the first wide result has low half 3 and high half 9, the first expanded base is 12, while the subsequent high-half argument is 9.

6. **A shifted argument can collapse to zero.**  
   Under 32-bit bit-vector arithmetic, the second replicated word has 14 low zero bits. Its stage-17 left shift by 28 bits therefore yields zero. The call remains part of the sequence.

7. **Restricted next-base values.**  
   Under that arithmetic model, the next base is one of 0, 0x40000000, 0x80000000, or 0xC0000000. This establishes no access validity.

8. **Continuation replacement is independent of the next input.**  
   If execution reaches the final two calls, the penultimate call returns before the continuation is replaced. Replacement precedes the final call. Whatever 32-bit value the final call supplies becomes the next first input, not the next continuation.

9. **Incoming continuation affects only the initial target.**  
   Two otherwise comparable entries with different incoming continuations can have different initial first-call targets. If both complete an iteration, their next first-call targets derive from the same embedded replacement location, regardless of their next first-input values.

10. **No one-iteration success return.**  
    If every call and access completes, execution begins another iteration rather than returning a success result.
