## Behavior

### Execution and dependency ordering

The visible path contains no explicit conditional branch or loop. It proceeds through ordered call groups and memory accesses until a dependency fails to return, an access cannot complete, or the terminal boundary is reached.

A recurring call group comprises an initial indirect call followed by four further indirect calls. The initial call may receive explicit operands; the following calls show no explicit arguments. Often the final result becomes an address index for the next memory operation.

The calls are observable boundaries. This contract does not treat them as inert separators, merge them, or assume that calls showing no arguments are pure. Dependencies may modify memory between two otherwise similar reads.

### Opening argument and byte-derived state

The opening five-call group begins by passing the second argument to a dependency. Its final 32-bit result selects a word destination at `scaled4(result) + 0x14`. The fourth argument, logically shifted right by three, is stored there.

The next five-call group begins with the scaled opening result. Its final result supplies an opening work value. Four times that value supplies an opening scaled value.

Execution then:

- Reads one unsigned byte at the implicit entry address plus 1.
- Writes `low8(opening scaled value)` to address `0x11 + that byte`.
- Starts another five-call group with three operands: that byte shifted right by three, the opening scaled value, and the implicit entry address shifted left by two.

After this group, the byte at the implicit entry address plus 1 is read again. This second byte is retained as a saved selector. It need not equal the first byte.

At address `saved selector + 0x11`, execution stores `highByte(opening work value)`. A subsequent five-call group receives four times the preceding group’s final result. After that group, the opening scaled value is written as a 32-bit word at `scaled4(saved selector) + 0x14`.

### Propagated scaled values

A further five-call group starts with four operands: the saved selector repeated three times, then the saved selector shifted right by one. Its final result selects another word destination at offset `0x14`, scaled by four. The opening scaled value is stored there.

The following groups establish a repeated pattern:

- A result supplies a scaled-by-four value.
- That value is stored at an address formed by scaling the same result by sixteen and adding `0x14`.
- A later dependency result selects a scaled-by-four destination at offset `0x14` for the previously retained value.

This pattern occurs before and after a special call boundary. At the first such boundary, a scaled result is passed to a distinct indirect dependency, another call produces a 32-bit token, and that token is passed into the next five-call group.

After that token-driven group, the stored word is `maskedHalf` of the retained scaled result, rather than the unmasked result.

A later group again stores a result scaled by four at its own scaled-by-sixteen address plus `0x14`. Before the following call group begins, execution reads a 32-bit word at the retained scaled value plus `0x14`. That word, logically shifted right by three, is the first argument to the next group.

The word just read is not necessarily the word just written: scaling the original result by four and by sixteen produces different addresses except in special cases. Aliasing must be established from actual values, not inferred from the shared offset.

A final five-call group begins with four times the latest group result. The invalid-instruction boundary follows its last call.

## Acceptance examples

These examples are conditional static expectations, not executed tests. They assume relevant dependencies return, required accesses succeed, and the stated arithmetic is representable.

1. **Fourth-argument truncation.** Fourth arguments 0 through 7 produce an opening stored word of zero. Argument 8 produces 1. Argument `0xFFFFFFFF` produces `0x1FFFFFFF`. The opening dependency result still determines the destination.

2. **Low-byte reduction.** If the opening work value is `0x41`, its scaled value is `0x104`; the first selected byte write stores `0x04`, not the full scaled value.

3. **High-byte extraction.** For a work value of `0x3AB00000`, `highByte` is `0xAB`. The intermediate masked-and-shifted quantity is wider than eight bits; truncation is part of the store.

4. **Selector reread.** If an initial selector is 5 and an intervening dependency changes its source byte to 9, the first byte write targets `0x16`, while the subsequent reread-selected byte write targets `0x1A`.

5. **Saved selector.** If the saved selector is 9, the selector-derived large-offset word write begins at `0x80024`. Later changes to the original selector byte do not change that already-retained value.

6. **Distinct word locations.** For a result of 3, a self-derived scaled-by-sixteen write begins at `0x44`, while the later scaled-by-four read begins at `0x20`. The read must not automatically reuse the stored value.

7. **Mask boundaries.** A central half of `0x00400001` produces masked products `0x80` and `0x10`, respectively. Bits above the lowest 22 do not contribute to those products.

8. **Intervening mutation.** If a dependency writes a nonzero word to absolute address `0x24` between explicit clears, the later clear remains a required separate effect. The contract does not promise that the location stays zero between clears.
