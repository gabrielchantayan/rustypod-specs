# F-a5146f308c64

## Purpose

F-a5146f308c64 conditionally creates a result associated with a supplied object, transfers four words of metadata, and invokes setup and registration dependencies.

The function first obtains an opaque context value and invokes a preparation dependency. A subsequent lookup determines whether it returns zero immediately or continues. On the continuing path, it captures a two-word value, adjusts its first word, submits the adjusted data, creates a result, copies metadata, requests a 36-byte allocation, and performs further calls.

This is an orchestration contract. “Context,” “object,” “creation,” “allocation,” and “registration” describe apparent roles at this call site, not verified domain semantics or ownership rules.

Two creation and registration arguments come from global-value reads. Their timing is part of the contract: they are not established to be constants, and their values must not be replaced by the addresses of their storage.

## Interface

The function accepts five integer-like arguments, designated A through E, and returns an integer-like value. The supplied representation uses 32-bit integers and four-byte word accesses. Some integer-like values are used as addresses or opaque handles; this does not establish a portable pointer ABI.

| Argument | Established use |
|---|---|
| A | Passed to creation and setup dependencies; also used to form an address at byte offset `0x58`. |
| B | Passed to preparation, lookup, and a later initialization dependency; directly read at offsets `0x80`, `0x84`, `0x88`, and `0x8C`. |
| C | Negated to obtain the displacement when D is nonzero. |
| D | Zero/nonzero selector for the displacement rule. All nonzero values select the same branch. |
| E | Used as the displacement when D is zero; not used as the displacement when D is nonzero. |

The return value is:

- Zero when the first F-ffe0d92c57b7 lookup returns zero.
- Otherwise, the value returned by F-2698159acdb1, if execution reaches the final return.

There is no established success-code convention. A zero creation result is not treated as a checked failure: the function later attempts an address-based read relative to that result.

## Behavior

### Entry and the early-return path

The function first calls F-7a89f2f7fd9a without arguments and saves its result as an opaque context value.

It next calls F-1151dcd9bead with B followed by three zero arguments. This call precedes the branch-controlling lookup and therefore occurs even on the early-return path.

The function then calls F-ffe0d92c57b7 with B:

- A zero result causes an immediate zero return.
- A nonzero result permits the remaining operations.

Only this first lookup result controls the branch. It is not reused as the source or destination of later field accesses.

There is one lookup on the early-return path and six on a normally completing continuing path. Each lookup receives B. Their results need not be equal, and later lookup results are not explicitly checked for zero.

### Capture and displacement

The second lookup supplies the source of two reads, in this order:

1. The four-byte word at offset `0x30`, designated the original first word.
2. The four-byte word at offset `0x34`, designated the original second word.

The displacement is E when D is zero. When D is nonzero, the displacement is the negation of C, irrespective of E.

The adjusted first word is the original first word plus that displacement. The second word is preserved without arithmetic.

After initialization, the supplied local layout exposes the following four consecutive words relative to the address later passed to F-a19ace379809:

| Relative offset | Initialized content |
|---:|---|
| `0x00` | Adjusted first word |
| `0x04` | Original second word |
| `0x08` | Original first word |
| `0x0C` | Original second word |

The later “original-pair address” points at relative offset `0x08`. Thus, its second word occupies the final word of this four-word region.

The original first word is captured before the original second word. The adjusted first word and the final copy of the second word are initialized before the third lookup.

For signed 32-bit values whose negation and addition remain representable, the arithmetic rule is unambiguous. The supplied representation does not establish a portable overflow policy for negating the minimum signed value or producing an out-of-range sum. Wrapping, saturation, rejection, and trapping must not be assumed for those cases.

### Submit the adjusted data

The function performs a third lookup with B. It then calls F-a19ace379809 with:

1. The third lookup result.
2. The address of the adjusted first word.

Its return value is unused.

The four-word layout specifies initialized storage available at call entry, not a verified access extent for the dependency. The dependency may read or write through the supplied pointer; its actual extent and pointer-retention behavior are unknown.

In particular, the original-pair storage is adjacent to the adjusted pair. If the dependency writes into that adjacent storage, the later setup call can observe changed contents. The function does not restore the original pair after this call.

### Read S1 and create the result

The function performs a fourth lookup with B. After that lookup returns, it reads the global value S1 while preparing the call to F-2698159acdb1.

The creation call receives six arguments, in order:

1. A.
2. Zero.
3. The fourth lookup result.
4. The value read from S1’s global storage.
5. Zero.
6. One.

S1 is a value operand, not an instruction to pass the address of its storage. Its value is not established to be immutable. The fourth lookup and earlier dependencies may change that global before this read. Reading it before the fourth lookup, or caching an earlier value across that lookup, is not an equivalent contract.

The creation result is saved for later operations and eventual return. It is not checked for zero or other invalid values.

### Copy four words

The function performs a fifth lookup with B. Its result becomes the destination base for the following direct accesses:

1. Read B at offset `0x84`.
2. Read B at offset `0x88`.
3. Read B at offset `0x8C`.
4. Read B at offset `0x80`.
5. Write the captured `0x80` value to destination offset `0xC4`.
6. Write the captured `0x84` value to destination offset `0xC8`.
7. Write the captured `0x88` value to destination offset `0xCC`.
8. Write the captured `0x8C` value to destination offset `0xD0`.

All accesses are four bytes wide. All four source reads precede the first destination write, with no intervening dependency call.

Consequently, overlap between source and destination does not cause a destination write to alter a source value that this sequence has yet to capture. This ordering does not establish atomicity, synchronization, or safety against concurrent mutation.

### Capture the associated value and perform setup

After the four writes, the function reads the four-byte value at offset `0x04` from the creation result. This captured associated value is retained for later calls.

The function then performs a sixth lookup with B and calls F-a8c06eac92c0 with:

1. A.
2. The creation result.
3. The sixth lookup result.
4. The original-pair address.
5. Zero.

The original-pair storage was initialized from the second lookup’s fields. It is not refreshed from that object before setup. Its contents at this point remain subject to any earlier dependency writes through the adjusted-data pointer.

The associated value is captured before both the sixth lookup and setup. It is not reread from the creation result afterward.

### Allocation and final calls

The remaining operations occur in this order:

1. F-8157a180d901 receives `0x24`, or 36 decimal.
2. F-df542ee3655d receives that call’s result, the captured associated value, B, and six.
3. F-4b539170a43a receives the saved context value and the creation result.
4. After F-4b539170a43a returns, the function reads global value S2 while preparing the next call.
5. F-aa408aa1a280 receives the saved context value, the captured associated value, and the value read from S2’s global storage.
6. The function initializes a local four-byte slot with the captured associated value.
7. F-7e55b35f8edc receives A plus byte offset `0x58` and the address of that local slot.

S2, like S1, is a global-value read rather than a storage-address argument or an established constant. F-4b539170a43a and earlier dependencies may change its storage. An earlier cached value cannot replace the read performed after F-4b539170a43a returns.

If all operations complete normally, the function returns the creation result. The return values of the submission, setup, initialization, registration, and final attachment calls do not select an alternative return path.

## Side effects

Established direct effects include:

- Four four-byte writes into the fifth lookup result.
- Ordered reads from the second lookup result, B, the creation result, and the two globals.
- Initialization of local storage passed by address to three dependencies.
- A call requesting 36 bytes from F-8157a180d901.
- The ordered dependency invocations described above.

Returning zero after the first lookup does not imply a side-effect-free invocation: both the context-producing call and preparation call have already occurred.

There is no explicit release of the creation result or the result of the 36-byte request. This establishes neither a leak nor an ownership transfer. Ownership, reference counting, and hidden cleanup remain dependency-specific unknowns.

The function retains numeric context and associated values across calls. It does not establish that intervening dependencies preserve globals, keep referenced objects alive, or preserve the meanings of those values.

Local addresses passed to F-a19ace379809, F-a8c06eac92c0, and F-7e55b35f8edc have no established lifetime beyond this invocation. Whether the dependencies copy, mutate, retain, or otherwise use those addresses is unknown.

There is no explicit rollback, retry, error translation, allocation-failure branch, or status aggregation. A dependency that does not return normally prevents later operations. An unusable returned address has no local guard before its subsequent dereference.

## Acceptance examples

These are conditional static predictions, not executed tests.

1. **Initial lookup returns zero.**  
   If the entry and preparation calls return normally and the first lookup returns zero, the function returns zero. There is no second lookup, S1 read, creation call, metadata copy, allocation request, or S2 read.

2. **Explicit displacement.**  
   With original words 100 and 40, D equal to zero, and E equal to 7, the initialized adjusted pair is 107 and 40. The adjacent original pair is 100 and 40. C does not affect this calculation.

3. **Negated displacement.**  
   With the same original words, C equal to 7, and any nonzero D, the adjusted first word is 93 regardless of E. With C equal to −7 instead, it is 107.

4. **Distinct lookup results.**  
   Given six distinct usable results, the second supplies the original words, the third is submitted with adjusted data, the fourth goes to creation, the fifth receives the metadata writes, and the sixth goes to setup. Reusing the first result throughout would not satisfy the contract.

5. **S1 changes during the fourth lookup.**  
   Suppose S1’s storage contains value X before the fourth lookup and that lookup changes it to Y before returning. With no further change before the global read, creation receives Y, not X and not the address of S1’s storage.

6. **Four-word transfer.**  
   If B’s fields at offsets `0x80`, `0x84`, `0x88`, and `0x8C` supply 11, 22, 33, and 44 at their respective reads, destination offsets `0xC4`, `0xC8`, `0xCC`, and `0xD0` receive those values respectively. All source reads occur first.

7. **Captured associated value.**  
   If the creation result’s `0x04` field supplies H when read, later calls use H even if that field subsequently changes. This does not guarantee continued validity of any object represented by H.

8. **S2 changes during registration.**  
   Suppose S2’s storage contains P before F-4b539170a43a and that dependency changes it to Q before returning. With no further change before the global read, F-aa408aa1a280 receives Q. An earlier S2 read would not satisfy the required ordering.

9. **Zero creation result.**  
   If creation returns zero, execution still proceeds through the fifth lookup and four-word transfer before attempting the associated-value read relative to zero. A clean zero return is not guaranteed.

10. **Unrepresentable arithmetic.**  
    Negating the minimum signed 32-bit C, or adding a displacement outside the signed range, has no specified portable outcome here. Acceptance must not require a guessed wrapping or saturation rule.
