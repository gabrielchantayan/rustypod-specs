# F-14d8c4229cc7

## Purpose

F-14d8c4229cc7 updates four consecutive integer fields in caller-supplied storage. It independently limits two signed inputs to the inclusive interval **0 through 65,536**, stores the limited values, and then stores two derived values:

- The integer average of the limited values.
- Half of the second limited value minus the first, truncated toward zero, followed by subtraction of one.

The established behavior is a bounded numeric state update. The meanings of the values and the containing object are not established. In particular, the evidence does not identify them as coordinates, gains, limits, or any other application-specific quantity.

The four writes are ordered, but they do not constitute an established atomic transaction.

## Behavior

### Independent input limiting

Each numeric input is independently limited to the inclusive interval **[0, 65,536]**:

- A negative input becomes zero.
- An input greater than 65,536 becomes 65,536.
- An input equal to either boundary remains unchanged.
- Any input strictly between the boundaries remains unchanged.

The two inputs are not compared against one another. The function does not sort them or require the first to be less than or equal to the second.

For the following descriptions, **A** denotes the bounded first value and **B** denotes the bounded second value. These are descriptive quantities, not additional storage locations exposed by the interface.

### Derived values

The third field receives:

**truncation toward zero of (A + B) / 2**

Because both operands are nonnegative, this is also the mathematical floor of their average. An odd sum loses its fractional half; the result is not rounded to the nearest integer.

The fourth field receives:

**truncation toward zero of (B − A) / 2, then minus 1**

The order matters. Subtraction of one occurs after the division. The behavior is not equivalent for every input to subtracting a quantity from the numerator before division.

For a negative odd difference, truncation toward zero is distinct from rounding downward. For example, a difference of −3 contributes −1 before the final subtraction, yielding −2.

### Observable access order

The established update sequence is:

1. Limit the first input.
2. Determine whether the second input is negative and, if so, replace it with zero.
3. Write A to the field at offset `0x8D0`.
4. If the original second input was nonnegative and exceeds 65,536, limit it to 65,536.
5. Write B to the field at offset `0x8D4`.
6. Write the integer average to the field at offset `0x8D8`.
7. Write the adjusted half-difference to the field at offset `0x8DC`.

Thus, the first destination write precedes the upper-bound adjustment of a nonnegative second input. No dependency or other externally visible operation intervenes in that adjustment, but the four destination writes remain separately ordered effects.

The function does not explicitly read the previous contents of any destination field. The derived values come from the argument values after limiting, not from rereading the first two stored fields.

Once limiting is complete:

| Quantity | Inclusive range |
|---|---|
| A | 0 to 65,536 |
| B | 0 to 65,536 |
| A + B | 0 to 131,072 |
| B − A | −65,536 to 65,536 |

All numeric intermediates fit within a signed 32-bit integer. Extremely negative or positive numeric inputs are limited before entering the sum or difference. They therefore do not cause numeric overflow in these derived calculations under the stated width interpretation.

This numeric safety does not establish the safety of address arithmetic involving the destination base.

## Side effects

For ordinary writable memory, successful completion leaves the four fields with the specified values. No other destination field is explicitly modified. There is no allocation, deallocation, ownership transfer, callback, logging operation, or explicit global-state access.
