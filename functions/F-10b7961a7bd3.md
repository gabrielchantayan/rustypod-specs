# F-10b7961a7bd3

## Purpose

F-10b7961a7bd3 examines byte-addressable storage, skips an initial run of nonzero bytes satisfying a forward classification predicate, and then performs a backward scan that may cause one zero-byte write. It returns either an address within the supplied storage or null.

In-place trimming is **inferred intent**, not an unconditional description of its behavior. Two distinctions are essential:

- The forward predicate directly tests bit 0 of a classification byte.
- The backward predicate tests bit 0 only **after** the classification byte has been converted to an unsigned integer, converted to a byte pointer, and converted back to an unsigned integer. Whether that round trip preserves the classification byte’s low bit is not established.

The backward scan also stops upon reaching the retained-start address without classifying that position. Reaching this boundary suppresses the zero-byte write.

Consequently, conventional trimming behavior is not guaranteed even when the backward conversion preserves bit 0. For example, under otherwise ordinary length and stable-storage assumptions, one retained byte followed entirely by backward-continuing bytes keeps its suffix.

## Interface

### Input and return value

The function accepts one pointer to byte-addressable storage. There is no explicit length, capacity, classification-table parameter, or error-output parameter.

It returns:

- Null immediately if the forward scan reads a zero byte.
- Otherwise, the retained-start address if a final read at that address is nonzero.
- Null if that final read observes zero.

A nonnull result aliases the supplied storage. It may equal the input pointer or point farther into the same storage. No separate result allocation or copying is explicit.

A null input is not handled as an empty sequence: the function first attempts to read through it.

### Representation, widths, and layout

The supplied representation establishes byte-sized input and classification accesses, with byte values interpreted as unsigned values from 0 through 255.

F-2a4c402ba617 supplies a result used as a pointer to a signed-integer table-base field. Each classification lookup reads that field and combines its value with an input byte converted to an unsigned integer. The accessed field contains an integer address component, not an established byte-array pointer.

For both scan directions:

1. The signed table-base value participates in addition with an unsigned-integer byte value.
2. The addition therefore occurs in the unsigned-integer domain.
3. The resulting integer is converted to a byte pointer.
4. One classification byte is read through that pointer.

If the unsigned-integer width is \(w\), the base is converted into that domain and the addition is reduced modulo \(2^w\). This is not established as portable pointer indexing.

The two directions then differ:

- **Forward:** bit 0 of the classification byte is tested directly.
- **Backward:** the classification byte is converted to an unsigned integer, then to a byte pointer, then back to an unsigned integer. Bit 0 of this final integer controls continuation.

The backward integer-to-pointer-to-integer round trip must not be treated as an identity without additional target guarantees. In particular, preservation of the original classification byte’s low bit is unresolved.

F-1cb585febd84 supplies a signed-integer result used as a byte-pointer displacement. Exact signed-integer, unsigned-integer, and pointer widths are not independently established. Width-specific conclusions remain conditional.

### Access, lifetime, and ownership preconditions

The function performs no explicit validation. Successful execution requires:

- Readable storage at every input address actually examined.
- A valid table-base-field pointer for every field read.
- Readable classification storage at each computed classification address.
- Valid pointer arithmetic for the displacement and every backward step.
- Writable storage at the termination address if a write occurs.
- Continued validity of the retained-start address and saved table-base-field pointer through their uses.

The backward conversion of a classification value to a pointer is not itself followed by a dereference of that pointer. Its conversion back to an integer nevertheless requires target semantics sufficient to determine the continuation predicate.

A reachable zero is necessary if forward scanning continues indefinitely through forward-selected bytes; the function need not reach a zero when an earlier byte stops that scan.

No ownership transfer is explicit. Dependency effects on ownership and lifetime are unknown.

## Behavior

### Forward scan

At each forward position, the function first reads one input byte.

If that byte is zero, the function immediately returns null. It does not call either dependency for that position and performs no explicit write.

For a nonzero byte, the function calls F-2a4c402ba617. After the call, it reads the signed-integer table-base field through the returned pointer and obtains the classification byte using the address calculation described above.

The input value used for this lookup is the value read **before** the dependency call. Mutation of that input location during the call does not cause a replacement input read for the same lookup.

The forward decision directly tests the classification byte:

- Bit 0 set: advance the input position by one byte and repeat.
- Bit 0 clear: stop advancing and designate the current address as the **retained start**.

Thus F-2a4c402ba617 is called once for each nonzero byte examined forward, including the byte that stops the scan. Its result is not cached across the entire forward phase. Different calls may return different field pointers or expose different table contents.

The pointer returned by the final forward call is saved for later table-base-field reads. The retained start preserves an address, not the earlier value stored there.

### Displacement acquisition

After establishing the retained start, the function calls F-1cb585febd84 once with that address.

The signed-integer result is used as a byte displacement from the retained start to form the initial backward-scan address.

The function does not check whether the result:

- Is positive.
- Measures the distance to a zero terminator.
- Lies within the available storage.
- Remains consistent with storage after the dependency call.

A byte-string length interpretation is **inferred**, not established by the supplied dependency information.

The saved table-base-field pointer survives across this call as a stored value. The function does not reacquire it or validate its lifetime afterward.

### Backward scan

The backward scan takes at least one step, regardless of the displacement.

Each iteration saves the current scan address as the **previous address**, then moves the candidate address backward by one byte.

If the candidate equals the retained start, the scan stops immediately:

- No candidate-byte read occurs for backward classification at that boundary.
- No table-base-field read occurs for that iteration’s classification.
- No classification byte is read.
- The converted-result continuation predicate is not evaluated.

Otherwise, a backward classification is performed. It requires both:

- A byte read at the candidate address.
- A signed-integer table-base-field read through the pointer saved during forward scanning.

The supplied expression does **not** establish the relative evaluation order of these two reads. Both contribute to the classification-address calculation before the classification byte is read.

The candidate byte is converted to an unsigned integer, added to the loaded base in the unsigned domain, and the result is converted to a byte pointer. One classification byte is then read.

For the continuation decision, that classification byte undergoes the following conversions:

- Byte value to unsigned integer.
- Unsigned integer to byte pointer.
- Byte pointer back to unsigned integer.

The scan continues backward if bit 0 of the **final converted integer** is set. It stops if that bit is clear.

This is the established backward decision rule. A rule expressed directly as “continue when the classification byte’s bit 0 is set” is valid only under the additional assumption that the conversion round trip preserves that bit.

There are no backward calls to F-2a4c402ba617. Nevertheless, the signed-integer table-base field is read anew for each backward classification. Saving its address does not freeze its value.

A zero-valued candidate away from the retained-start boundary is not an automatic stop. It is classified using byte value zero and the same conversion-dependent continuation rule.

If the displacement accurately measures the distance to a terminating zero, and the relevant storage remains stable, the first backward candidate is the byte immediately before that terminator. Without those assumptions, no logical-end starting position is established.

### Conditional write

After the backward scan stops, the function compares the final candidate address with the retained start.

- Equal: no write.
- Unequal: write one zero byte at the previous address saved during the final iteration.

For valid pointer arithmetic, that write address is one byte after the final candidate.

The write decision depends on the boundary comparison, not directly on the original classification byte. Away from the boundary, it follows a stop caused by a clear low bit in the converted backward result.

The function performs at most one explicit byte write. It does not clear any remaining suffix.

Under accurate length and stable-storage assumptions, the write may replace the first byte after the final backward-stopping candidate or rewrite the existing terminator. If the scan instead reaches the retained-start boundary, the write is suppressed.

### Final read and return

After the optional write, the function rereads the byte at the retained start.

- Zero: return null.
- Nonzero: return the retained-start address.

This is a fresh read, not reuse of the original forward value. A dependency may have changed the retained-start byte.

A null return therefore does not establish that the original input was empty or entirely forward-selected. It can also follow mutation of the retained start. An earlier termination write is not undone.

## Acceptance examples

These are **conditional acceptance examples**, not executed tests.

Unless stated otherwise, assume valid readable and writable storage, stable dependency-visible state, a terminating zero, a displacement equal to the number of bytes from the retained start to that zero, and classification-address conversions reaching the intended entries.

For examples involving ordinary backward classification, additionally assume that the classification-byte-to-integer-to-pointer-to-integer conversion preserves bit 0. Assume spaces have classification bit 0 set and letters have it clear. These assumptions do not establish a named character class.

### Empty input

For an initial zero byte:

- Return null.
- Call neither dependency.
- Perform no explicit write.

No backward conversion assumption is needed.

### Entirely forward-selected input

For three spaces followed by zero:

- Call F-2a4c402ba617 three times.
- Reach zero in the forward scan and return null.
- Do not call F-1cb585febd84.
- Perform no explicit write.

This example depends only on the direct forward classification predicate, not on backward conversion semantics.

### Skipped prefix without copying

For two spaces followed by `ab` and zero:

- Retain the address of `a`.
- Call F-2a4c402ba617 three times.
- Classify `b` backward.
- With low-bit preservation, stop at `b`.
- Rewrite the existing zero after `b`.
- Return the address of `a`, leaving both prefix spaces unchanged.

Without the low-bit-preservation assumption, the backward stop at `b` is not established merely by its classification byte.

### Trailing run removed

For two spaces followed by `ab`, two spaces, and zero:

- Retain the address of `a`.
- With low-bit preservation, continue backward through both trailing spaces.
- Stop at `b`.
- Write zero over the first space after `b`.
- Return the address of `a`.
- Leave the later space and original terminator untouched by direct writes.

### Single retained byte with a trailing run

For `a`, two spaces, and zero:

- Retain the address of `a`.
- With low-bit preservation, continue backward through both spaces.
- Reach the retained-start boundary without classifying `a` backward.
- Perform no write.
- Return the address of `a`, leaving both spaces before the original terminator.

More generally, the same no-write result follows whenever every backward candidate after the retained start produces a converted result with bit 0 set, regardless of the original classification bytes’ low bits.

### Single-byte sequence

For `a` followed by zero:

- Retain `a` when its forward classification bit is clear.
- The first backward step reaches the retained start.
- Perform no backward classification and no write.
- Return the address of `a`.

No backward conversion-preservation assumption is needed.

### Distinct classification predicates

For a forward lookup:

- Classification value 2 stops forward scanning.
- Classification value 3 advances it.

For a backward lookup away from the boundary:

- A final converted integer with bit 0 clear stops scanning.
- A final converted integer with bit 0 set continues scanning.

Classification values 2 and 3 imply those respective backward decisions **only if** their conversion round trips preserve bit 0. Without that guarantee, the classification bytes alone do not determine the documented backward outcome.

### Dependency mutation

Suppose F-1cb585febd84 changes the retained-start byte to zero while leaving storage valid and returning a displacement that permits the subsequent traversal.

The final reread produces null. Any termination write selected by the backward scan occurs first and remains in effect. This example does not require a particular backward path; that path remains governed by the converted-result predicate.

### Unsigned address wraparound

Conditionally assume 32-bit unsigned-integer arithmetic and suitable integer-to-pointer address mapping.

If the table-base value converts to `0xfffffff0` and the input byte is `0x20`, the classification-address sum is `0x00000010`. It is not an unbounded address above `0xffffffff`.

This example concerns address formation only. It establishes neither readable storage at that address nor preservation of a backward classification result’s low bit.

### Backward operand ordering
