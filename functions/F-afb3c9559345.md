# F-afb3c9559345

## Purpose

F-afb3c9559345 conditionally rebuilds portions of a mutable state object using a selected 16-byte record associated with an owner object. On its full completion path, it initializes state, transfers descriptor data, selects one of two scalar channels, optionally transforms paired values and both channels, and writes four arithmetic outputs.

A geometry-related interpretation is plausible but inferred. The established behavior is the access sequence, dependency interaction, state changes, and result selection described below.

There are three principal outcomes:

- Eligibility declines processing: return zero without entering the rebuild sequence.
- Processing is selected and option bit `0x4000` is set: return six without entering the rebuild sequence.
- Processing is selected and `0x4000` is clear: begin rebuilding and return the initialization dependency’s status. Continue beyond initialization only when that status is zero.

A zero result does not distinguish an eligibility rejection from a completed rebuild.

## Interface

### Arguments and result

The supplied representation exposes four 32-bit arguments and a signed 32-bit result.

| Argument | Meaning |
|---|---|
| State address | Address of the mutable state object. |
| Auxiliary address | Passed to eligibility; also dereferenced directly on specified paths. |
| Selector | Unsigned 32-bit record selector. |
| Options | Unsigned 32-bit option mask. |

The selector is normalized before the bounds check: zero remains zero; every nonzero value is reduced by one. Selectors zero and one therefore both select normalized index zero.

Only these option bits control visible branches:

| Bit | Effect |
|---|---|
| `0x0001` | Bypass eligibility and suppress the later transformation stage. |
| `0x0008` | Bypass eligibility without suppressing transformation. |
| `0x4000` | Return six if processing has been selected. |

Other option bits receive no local validation and have no established direct effect.

## Behavior

### 1. Capture the owner and check the selector

The function first reads the owner address from state `+0x04`. Later owner accesses use this captured address, not a fresh read of state `+0x04`.

After selector normalization, it reads the owner’s unsigned record count at `+0x198`. If the normalized index is greater than or equal to that count, it invokes F-540af0155702 with:

- A diagnostic string reference.
- The value 300.
- The value obtained from the separate diagnostic-context global for this invocation.

There is no explicit local error return after this call. If the dependency returns normally, execution proceeds with the same normalized index. The check therefore does not itself guarantee that later record access is in bounds.

Whether the diagnostic dependency returns, terminates, or transfers control elsewhere is unresolved.

### 2. Select processing

If either bypass bit, `0x0001` or `0x0008`, is present, processing is selected without calling eligibility.

Otherwise, F-99aeb8eabebe receives the state address, auxiliary address, and normalized index. A zero result causes an immediate zero return. Any nonzero result selects processing.

After processing is selected, the function checks `0x4000`. If set, it returns six.

This ordering matters: with no bypass bit, eligibility rejection takes precedence over the six result. The initial bounds check also precedes both eligibility and the `0x4000` decision.

Neither early-return path performs direct state writes shown in this function. Dependencies already invoked may nevertheless have changed memory or other state.

### 3. Begin rebuilding

For selected processing with `0x4000` clear, the function reads the record-table address from the captured owner and forms the selected record address using a 16-byte stride. That selected address is retained for later record accesses.

The ensuing direct accesses occur in this order:

1. Read the rebuild-value global and store its 32-bit value at state `+0x48`.
2. Clear the 16-bit field at state `+0x6e`.
3. Clear the 16-bit field at state `+0x6c`.
4. Capture owner `+0xbc`.
5. Capture owner `+0x68`.
6. Capture record `+0x0c`.
7. Capture record `+0x08`.
8. Read state `+0xc4` and pass its value to F-1cc54a4c66f8.
9. After that call returns, clear state `+0xb8`.

F-1cc54a4c66f8 has no checked result. Its name and argument do not establish reset, release, or ownership semantics.

The function maintains four adjacent 32-bit scratch words. Before initialization, their address-order contents are:

| Scratch position | Initial value |
|---|---|
| First | Captured record `+0x08` |
| Second | Captured owner `+0x68` |
| Third | Captured record `+0x0c` |
| Fourth | Captured record `+0x08` |

The first scratch word is assigned after preparation returns; the other three values were captured before preparation.

F-55bbc91c5390 then receives, in argument order:

- State address plus `0xa0`.
- Captured owner `+0x68`.
- Captured owner `+0xbc`.
- Captured record `+0x0c`.

Its signed 32-bit status becomes the function’s return status. If nonzero, rebuilding stops here. Earlier writes and dependency effects are not rolled back.

### 4. Transfer descriptor data and adjust flags

On initialization success, the transfer dependency receives:

- Destination: state address plus `0x6c`.
- Source: the newly read value at state `+0xc4`, plus `0x14`.
- Third argument: 20.

The source base is reread after initialization. It need not equal the value previously passed to preparation.

The call shape suggests a 20-byte memory transfer, but that interpretation is inferred. Exact transfer semantics, write extent, overlap handling, and failure behavior are unavailable.

After the dependency returns, the function reads state `+0x7c`. It clears bit zero, sets bit two, and stores the result.

If the auxiliary address is nonzero, it next reads the unsigned 16-bit value at auxiliary `+0x0e`. If that value is less than 24, it performs a second flags store using the originally saved flags with bit zero cleared and bits two and eight set.

Consequences:

- A nonzero auxiliary address causes the `+0x0e` read regardless of option bit `0x0001`.
- The threshold comparison is unsigned.
- A value of 24 does not satisfy the threshold.
- A false threshold condition does not clear an existing bit eight.
- The second flags store does not reread the flags word.

### 5. Select and snapshot scalar channels

The function clears state `+0x28`, then `+0x34`.

It then reads record `+0x04` through the retained selected-record address. Unlike the record’s `+0x08` and `+0x0c` values, this scalar is read after preparation, initialization, and descriptor transfer.

The owner fields at `+0x130` and `+0x12c` are compared. If unequal, F-8f41f510c86c is called with no visible arguments, and its 32-bit result replaces the record scalar.

The function next reads owner `+0x144`:

- Bit zero clear: store the chosen scalar at state `+0x28`.
- Bit zero set: store it at state `+0x34`.

It then performs these operations in order:

1. Copy state `+0x28` to `+0x38`.
2. Copy state `+0x34` to `+0x3c`.
3. Clear state `+0x2c`.
4. Clear state `+0x30`.

The snapshots precede transformation. This function does not refresh them afterward.

### 6. Optionally transform pairs and channels

This stage executes exactly when option bit `0x0001` is clear. Option bit `0x0008` does not suppress it.

The function reads auxiliary `+0x10`, then auxiliary `+0x14`, and captures the pair-array address from state `+0x70`. These auxiliary reads have no null-address guard.

Pairs consist of two consecutive 32-bit words, with an eight-byte stride. Starting at index zero, the function compares its index against the current signed 16-bit count at state `+0x6e`.

For each admitted pair:

- Its first word and the captured auxiliary `+0x10` value are passed to F-74efb2674226; the result is immediately stored into the first word.
- Its second word is then read and passed with the captured auxiliary `+0x14` value to the same dependency; that result is immediately stored into the second word.

The retained array address advances by eight bytes per completed pair. State `+0x70` is not reread.

The count is reread at each loop condition, not captured once. Changes caused by dependencies or aliasing can therefore change the number of subsequent iterations. A count change during a pair does not skip that pair’s second transformation.

A zero or negative initial signed count admits no pairs. Regardless of pair count, the function then transforms state `+0x28` using the captured first auxiliary value, stores the result, transforms state `+0x34` using the captured second auxiliary value, and stores that result.

No arithmetic meaning for F-74efb2674226 is established.

## Side effects

The operation is not transactional. Initialization failure preserves earlier direct writes; abnormal dependency exits or inaccessible memory can interrupt later processing after partial changes.

No direct allocation or deallocation is shown. Ownership of the state, owner, records, auxiliary storage, descriptor storage, and pair array is not transferred by any established local rule. Dependency ownership and lifetime effects remain unknown.

Required accessible storage depends on the executed path:

- The initial state and owner reads occur before eligibility.
- A selected rebuild requires the selected record and the accessed state fields.
- Initialization success reaches the transfer dependency and its storage requirements.
- A nonzero auxiliary address causes the guarded `+0x0e` read after successful initialization.
- With `0x0001` clear, successful initialization also reaches unconditional auxiliary reads at `+0x10` and `+0x14`.
- Admitted pair iterations require accessible pair storage.

Thus `0x0001` suppresses transformation-stage auxiliary reads, not all direct auxiliary reads. A null auxiliary address skips the threshold read but is not locally safe for the transformation stage.

No local aliasing restrictions or pointer validation are shown. Overlapping state, owner, record, auxiliary, global, or pair storage can make earlier writes affect later reads. Unknown dependencies must not be assumed to preserve globals, record contents, state fields, unrelated memory, or ownership.

## Acceptance examples

These are conditional requirements derived from static evidence, not executed tests.

1. **Selector normalization.** With sufficient records, selectors zero and one select record zero; selector two selects record one.

2. **Failed bounds check.** With count zero and selector zero, F-540af0155702 receives the diagnostic reference, 300, and the diagnostic-context global value obtained for that call. If it returns, eligibility and rebuilding remain reachable.

3. **Eligibility precedence.** With options `0x4000`, no bypass bits, and eligibility returning zero, the result is zero rather than six.

4. **Blocked bypass.** With options `0x4008`, eligibility is not called and the result is six after the bounds check. The rebuild-value global is not read by the rebuild sequence.

5. **Mutable global input.** If eligibility changes the rebuild-value global and then selects processing, a subsequent rebuild stores the later global value at state `+0x48`, absent another intervening change. An entry-time value must not be substituted.

6. **Initialization failure.** If initialization returns a nonzero status, that exact status is returned. Transfer, channel selection, transformation, and final output stores are skipped; earlier effects remain.

7. **Transformation bypass with auxiliary access.** With `0x0001` set and initialization successful, there are no transformation calls or transformation-stage reads at auxiliary `+0x10` and `+0x14`. If the auxiliary address is nonzero, the earlier unsigned 16-bit read at `+0x0e` still occurs and may cause the additional flags write.

8. **Threshold boundary.** With stable, nonaliasing storage, threshold 23 forces flag bit eight on; 24 does not. Neither case independently clears an existing bit eight. Bit zero is cleared and bit two set.

9. **Negative count.** With `0x0001` clear and count `-1`, no pair is transformed, but the auxiliary transformation arguments are read and both scalar channels are transformed.

10. **Changing count.** If the first admitted pair’s first transformation causes the count to become zero, that pair’s second transformation still occurs. The next loop condition admits no further pair.

11. **Snapshot timing.** A scalar selected into `+0x34` is copied to `+0x3c` before transformation. A subsequent direct transformation store to `+0x34` does not refresh `+0x3c`.

12. **Final arithmetic.** If finalization leaves \(a=3,b=5,c=11,d=17\), the final four stores are 8, 12, 3, and 5.
