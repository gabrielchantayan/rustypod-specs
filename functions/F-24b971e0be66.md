# F-24b971e0be66

## Purpose

The established behavior is an ordered sequence of indirect calls, calculated memory accesses, shared-storage updates, and a final attempted call to address zero. The supplied static representation does not establish an application-level purpose.

Recurring operations include writing 32-bit values at scaled addresses, using unsigned selector bytes to choose byte destinations, and copying the low eight bits of a 32-bit read into a byte destination. These patterns do not establish an object model, serialization format, device protocol, or ownership convention.

This contract describes visible operations and retained values. Unknown dependencies remain potentially state-changing and nonreturning; calls without displayed arguments are not behaviorally irrelevant.

### Ambient inputs and storage

Execution additionally depends on:

- An incoming control-address value used to derive the first call target.
- An incoming 32-bit register value used by the first word write.
- Ordinary and auxiliary dependency results, including an auxiliary pointer.
- Shared storage designated **G-A**, **G-B**, and **G-C**.

G-A is read as a 32-bit word. G-B receives 32-bit writes. G-C is the byte at absolute address 1. A final expression reads a three-byte quantity associated with address 9.

These designations do not imply disjoint storage. Shared symbols, calculated accesses, and dependency-visible memory may overlap.

### Widths and addressing conventions

A **byte** is eight bits, a **word** is 32 bits, and the final zero write is 16 bits. A **pair result** is a displayed 64-bit result separated into low and high 32-bit words.

The **scaled slot** of a value is the address obtained by multiplying that value by four and adding 20. A **selector update** reads an unsigned byte from its specified selector address, then writes one byte at the selector’s numeric value plus 17.

“Low byte” means the least significant eight bits of a value, not necessarily the byte at its lowest memory address.

Unsigned right shifts operate on 32-bit values. Signed-looking multiplication and left shifts occur in the representation; overflow and signed-character interpretation require machine-level confirmation. Address expressions below preserve the displayed operations rather than imposing unlimited-precision arithmetic or a portable signed-overflow rule.

No alignment, allocation extent, byte order, or memory validity guarantee is supplied.

2. The intact fourth input.

### 2. Derived addresses and a retained base

A subsequent returned word is forwarded to another dependency. The following call returns a value retained as the **base**.

Before the next call, zero is written as a byte at the earlier shifted result multiplied by 8192, plus 9. The next dependency receives the base, the intervening returned word shifted right by 22, and that intervening word intact.
