# F-395b09db5506

## Purpose

F-395b09db5506 constructs a selector-dependent byte response using mutable state.

Three behaviors are established by the supplied static representation:

- Selector `0xC0` prepares backing state and constructs a selector list.
- An eligible data selector computes a candidate data range, then either constructs a response or delegates to F-78effd4e3255.
- Every other selector receives a five-byte default response.

For locally completed responses, an unsigned caller-supplied limit caps the returned length, **not the number of output writes**. Delegated results are returned without an additional cap.

Discovery followed by chunk retrieval is inferred intent, not an independently established protocol.

Arithmetic qualifications matter: both preparation-result adjustment and candidate-length calculation contain signed 32-bit addition. The supplied representation does not establish behavior when either addition overflows.

## Behavior

### Preparation and selector-list response

Selector `0xC0` first reads the status byte at state offset `0x450`. If zero, F-afc40ad0719e is invoked with the state address. Its return value does not control continuation.

Two provider calls follow, in order:

1. F-U01, selected through dispatch-table byte offset `0x18`.
2. F-U02, selected through dispatch-table byte offset `0x14`.

Each receives the provider address. The provider’s dispatch-table address is accessed separately for each call; the second target is not guaranteed to come from the first call’s table.

F-47dfbb96db37 then receives these arguments, in order:

1. The embedded-region address at state offset `0x68`.
2. F-U02’s result.
3. A value read through a global-held address.
4. F-U01’s result.
5. A fresh status-byte read from state offset `0x450`.

The global-derived value and fresh status are obtained after both provider calls. Their relative evaluation order is not established. Dependencies may have changed either value.

F-47dfbb96db37’s 32-bit result is stored at state offset `0x64`. The function then invokes F-d7be9cfb4000 with that result plus 247 and a second argument of 248.

The addition uses signed 32-bit arithmetic. If the result exceeds `INT32_MAX − 247` before adjustment, the addition overflows; the supplied representation alone does not establish subsequent behavior. F-d7be9cfb4000’s operation is unknown even when the addition is representable. Ceiling division is only a possible interpretation.

On a defined continuation, the low byte of F-d7be9cfb4000’s result is saved and written to state offset `0x60`.

The response header is then written in this order:

1. Read the state byte at `0x18` and write it to output offset `0`.
2. Write `0xC0` to offset `1`.
3. Write zero to offset `2`.
4. Read the count byte at `0x60` and write it to offset `3`.

List construction starts at position zero. Before every list-byte write, the position is compared against a fresh unsigned-byte count read. An admitted position produces the low byte of `0xC2 + position` at output offset `4 + position`.

**At most 255 list bytes can be written.** Every count read is at most 255, so only positions zero through 254 can enter the body. Position 255 cannot pass the comparison. Although the update reduces the counter to eight bits, no wrapping update is reachable.

Consequences:

- The highest list-write offset is `258`.
- Maximum local output footprint is 259 bytes.
- Count mutation can change list length but cannot enlarge that bound.
- With stable, non-overlapping storage, list length equals the stored count.
- With aliasing, earlier output writes can change later count reads, so the header count and actual list length can disagree.

The return calculation uses the saved dependency-result byte, not the final list position or a fresh count. Four is added and the result reduced modulo 256 before applying the caller’s limit.

### Data-selector eligibility

For selectors other than `0xC0`, data eligibility requires a numeric selector:

- Greater than `0xC1`; and
- Strictly less than `0xC2 + count`.

The count is read only when the first condition holds. The upper endpoint is formed once for this decision; duplicated comparisons in the supplied representation do not imply repeated count reads.

Count zero admits no data selectors. Count 255 admits numeric selectors `0xC2` through `0x1C0`, inclusive. Eligibility is not restricted to one-byte selector values.

No preparation or provider calls occur on this path.

### Offset and candidate length

For an eligible selector, the chunk index is the low eight bits of the selector-minus-`0xC2` difference. Eligibility restricts it to zero through 254.

The starting offset is the index multiplied by 248, ranging from zero through 62,992. Both that positive product and the corresponding negative signed product are representable in 32 bits.

Candidate-length calculation has two distinct stages:

1. Read the field at state offset `0x64` as signed 32-bit and add the signed negative offset term.
2. Convert the signed result to unsigned 32-bit, then compare it with 247.

This is **not an unconditionally defined unsigned subtraction**.

Let the signed field value be \(S\) and the nonnegative offset be \(O\). The signed intermediate is representable only when \(S-O\) is at least `INT32_MIN`; its upper bound cannot overflow because the added term is nonpositive. For index zero, the addition is always representable. For larger indices, sufficiently negative field values cause signed underflow.

When the signed addition is representable:

- Its conversion to unsigned 32-bit is well-defined.
- An unsigned result greater than 247 selects candidate length 248.
- Otherwise, that unsigned result is the candidate length.

Thus, the candidate length is between zero and 248 on this defined path. A representable negative intermediate converts to a large unsigned value and selects 248. In particular, a nonnegative field smaller than the offset produces a representable negative intermediate, not signed overflow.

For field bits `0x80000000` and index one, the signed calculation would fall below `INT32_MIN`. The source representation does not establish a wrapped candidate value, subsequent dependency calls, response, or return for that case.

### Backing-data checks

After candidate-length calculation, F-41867b969e65 receives the embedded-region address. Its result is used as a backing-data address.

The function then rereads the total field, this time as unsigned 32-bit:

- If the offset is not strictly below that fresh value, local success fails and F-1cb585febd84 is skipped.
- Otherwise, F-1cb585febd84 receives the backing-data address. Local success additionally requires the offset to be strictly below its unsigned result.

For defined candidate arithmetic, F-41867b969e65 is called even when the subsequent total-field check fails.

These checks constrain only the starting offset. They do not validate the entire requested range or establish that offset plus candidate length fits either bound. Candidate length remains based on the earlier signed field read, even if a dependency changes the field.

### Successful data response

On local success, direct byte writes occur in this order:

1. State byte from `0x18` to output offset `0`.
2. Selector’s low byte to offset `1`.
3. Zero to offset `2`.
4. Candidate length’s low byte to offset `3`.
5. Zero to offset `4`.

F-U03 is then invoked with:

- Destination: output address plus four.
- Source: backing-data address plus the calculated offset.
- Length: candidate length’s low byte.

The explicit zero at offset `4` precedes the invocation. An ordinary nonzero-length copy would overwrite it, but F-U03’s exact transfer semantics are unknown. Length zero still causes an invocation after the direct zero write.

The reported length is candidate length plus four, with an explicit byte reduction in the supplied representation. Since candidate length is at most 248 on the defined path, the result is four through 252 and that reduction does not wrap. The caller’s limit caps the return.

### Failed backing-data checks

If either starting-offset check fails, F-78effd4e3255 receives:

1. State address.
2. Original selector.
3. Output address.
4. Original reported-length limit.
5. The same original limit again.

Its result is returned without further capping.

No local response bytes have been written before this delegation. Earlier dependencies may nevertheless have modified output, state, globals, dispatch tables, or storage lifetime.

### Default response

Selectors outside the list and eligible-data cases receive five ordered byte writes:

1. State byte from `0x18`.
2. Selector’s low byte.
3. Zero.
4. One.
5. Zero.

All five writes occur even when the limit is zero. The return is the smaller of five and the limit.

## Side effects

The preparation path directly replaces:

- The 32-bit field at `0x64` with F-47dfbb96db37’s result.
- The byte at `0x60` with F-d7be9cfb4000’s low result byte.

Local output writes occur independently of the reported-length limit. A zero limit is not a side-effect-free size query.

Dependencies may introduce additional effects. No preservation guarantee is established for state, globals, provider tables, allocations, or backing storage.

Overlapping state and output makes access order observable. Header writes can alter later state reads; list writes can alter continuation counts. This does not enlarge the established selector-list bound.

No explicit rollback, synchronization, dependency-error handling, or partial-write recovery is visible. Signed-overflow cases and invalid-storage behavior have no established continuation contract.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless explicitly varied, assume valid, stable, non-overlapping storage, normally returning dependencies, and representable signed arithmetic.

1. **Three advertised selectors.** A saved count byte of three produces the state byte, `0xC0`, zero, three, then `0xC2`, `0xC3`, `0xC4`. A limit of at least seven yields seven.

2. **Maximum list.** A stable count of 255 produces list bytes at offsets `4` through `258`. The last byte is `0xC0`. The footprint is 259 bytes; the wrapped reported length is three.

3. **Changing count.** Even if every continuation read observes 255, only positions zero through 254 execute. Mutation cannot admit position 255.

4. **Reported-length wrap.** A saved count byte of 252 yields reported length zero. With the stored count remaining 252, construction still writes 256 bytes.

5. **Aliasing.** If output overlaps the count field, header or list writes may change continuation reads. Header count and list length need not agree; the 259-byte bound still applies.

6. **Small limit.** A default-path selector with limit two receives all five direct writes and returns two.

7. **Eligibility endpoints.** Count zero excludes `0xC2`. Count two admits `0xC2` and `0xC3` but excludes `0xC4`.

8. **Full first chunk.** Count at least one, total 500, selector `0xC2`, and a positive F-1cb585febd84 result produce candidate length 248. Local success requests that transfer length and returns the smaller of 252 and the limit.

9. **No full-range validation.** Count at least two, total 300, selector `0xC3`, and F-1cb585febd84 result 249 produce offset 248 and candidate length 52. Both starting-offset checks pass despite not establishing a complete 52-byte range.

10. **Equal starting offset and fresh total.** Offset 248 and post-accessor total 248 fail the first check. F-1cb585febd84 is skipped, and delegation receives the original limit twice.

11. **Selector-byte reduction.** Count 63 admits numeric selector `0x100`. Its index is 62, but its response selector byte is zero.

12. **Zero-length success after mutation.** If the initial signed total equals the offset, candidate length is zero. If F-41867b969e65 increases the total and the second bound exceeds the offset, success performs five direct writes, invokes F-U03 with length zero, and reports four before capping.

13. **Defined negative intermediate.** With count at least two, initial total 100, and selector `0xC3`, the signed intermediate is −148, which is representable. Unsigned conversion selects candidate length 248. If the total remains 100, the later offset check fails and delegation follows.

14. **Signed underflow remains unresolved.** With count at least two, total-field bits `0x80000000`, and selector `0xC3`, adding −248 to the signed field underflows. No wrapped candidate length or later outcome is established.
