# F-355248ba09a4

## Purpose

F-355248ba09a4 performs a fixed, ordered sequence of indirect calls, memory reads, and memory writes. It propagates its explicit input into two word destinations, propagates captured values into further destinations, performs byte-selected writes, updates shared storage, and finally attempts a call through address zero.

No application-level purpose is established. Allocation, subsystem initialization, serialization, and dispatch are not established interpretations.

This contract distinguishes:

- **Established static evidence:** represented access widths, arithmetic types, value dependencies, argument positions, and ordering.
- **Inferred intent:** possible application meaning, not relied upon here.
- **`documented_only`:** behavior not resolved by the supplied representation, including dependency effects, pointer interpretation, and signed-overflow outcomes.

Every later operation is conditional on execution reaching it. A call that does not return, or an access that prevents continuation, can stop the sequence.

## Interface

### Explicit input and result

The routine accepts one **32-bit input word**. Its signedness, valid range, pointer meaning, and ownership meaning are not established.

There is **no explicit return value**. A return is represented after the address-zero call, but is reachable only if that call returns.

### Implicit inputs

The routine also depends on:

- An incoming control-link value used to calculate the first call target.
- An ambient base used as both an address component and byte-store data.

- A shared 32-bit input, called **shared word A**.
- Shared 32-bit storage, called **shared word B**.
- A byte at numerical address **1**.
- A three-byte shared input at numerical address **9**.

The address of shared word B, and any relationship between it and address 9, are unresolved.

### Widths and arithmetic

Bytes, halfwords, words, and pair results have widths of **8, 16, 32, and 64 bits**, respectively. Pair halves are the low and high 32 bits of the result.

Unsigned 32-bit arithmetic is reduced modulo \(2^{32}\). This applies to unsigned multiplication, addition, and left shifts: discarded high bits do not survive into a subsequent pointer conversion. Unsigned right shifts insert zeros.

For an **unsigned index**, a four-byte-stride destination is therefore:

\[
D_u(i)=\bigl(4i+20\bigr)\bmod 2^{32}.
\]

For a **signed index**, the similarly shaped expression uses signed 32-bit intermediates. Its behavior when multiplication or addition overflows remains `documented_only`. The unsigned rule must not be substituted for that uncertainty.

The behavior sections identify which four-byte-stride destinations use unsigned arithmetic. Other such destinations use signed arithmetic. Likewise, a sixteen-byte-stride store described below uses signed arithmetic.

Unsigned additions outside these destination formulas also wrap. In particular, adding 20 to an unrestricted unsigned lookup word or shared-A sample is not unbounded mathematical addition.

A value assigned to unsigned storage does not retroactively make its producing expression unsigned. Some retained unsigned values originate from signed left shifts; the result of those producing shifts remains unresolved when signed-shift rules do not establish it.

A **byte-selected write** reads an unsigned byte at a selector address, then writes at that byte’s value plus 17. Its destination is consequently **17–272**, inclusive. A word’s **low byte** means its least significant eight bits, not necessarily the byte at its lowest memory address.

Integer-to-pointer interpretation, address-space validity, and endianness remain `documented_only`, independently of the established unsigned arithmetic.

## Behavior

### Ordering and retained observations

The represented path has no conditional branch or loop. Explicit calls and memory effects occur in their represented order.

Dependencies may modify shared or reachable storage. A later explicit read is therefore a fresh observation. A retained value, however, is not implicitly refreshed after intervening calls.

Calculated addresses may alias. Separate stores remain separate effects even when their addresses coincide. No rollback is represented.

### 1. Entry calls and ambient-base access

The first indirect call receives the input word. Its target is calculated from the incoming control-link value plus **4,082**, using a signed intermediate.

A word-producing call follows, and its result is forwarded to another dependency. Further calls produce a pair result.

The routine then:

1. Writes the ambient base’s low byte at ambient base plus 9.
2. Reads a word at ambient base plus 52.
3. Calls a dependency with the pair’s low half shifted left by two, its high half, and the word just read.

The ambient-base address additions and the low-half left shift use signed intermediates. Further calls precede the first input-word store.

### 2. Input propagation and two lookup observations

An auxiliary **signed index** selects a four-byte-stride destination where the input word is stored.

The routine then reads an unsigned word at the **unscaled first index plus 20**. This is the **first lookup word**; it is not necessarily read from the destination just written.

A dependency receives the unscaled first index. Further calls include a producer whose result is forwarded, then calls yielding a second signed index. The input word is stored at that index’s four-byte-stride destination.

Only after that store, a second unsigned lookup word is read at:

\[
(\text{first lookup word}\gg22)+20.
\]

This unsigned expression is bounded and does not overflow. A dependency subsequently receives four times the second signed index.

### 3. Scaled-result propagation and high-field source

Further calls produce a signed word result. Its signed left shift by two forms the **scaled result**.

The second lookup word shifted right by one supplies an **unsigned index**. The scaled result is stored at \(D_u\) of that index. Multiplication and addition in this destination wrap modulo \(2^{32}\), even though the stored value was produced by a signed shift.

The routine next reads an unsigned word at:

\[
(\text{second lookup word}+20)\bmod2^{32}.
\]

This separately retained observation is the **high-field source word**.

A dependency receives the halved second lookup word. After further calls, the scaled result is stored again at a newly returned **signed index’s** four-byte-stride destination.

The routine then captures the **first shared-A sample**, followed by a call receiving four times that newly returned signed index.

### 4. High fields and guaranteed-zero values

After further calls, the routine calculates:

- **High field:** high-field source word shifted right by 22.
- **Small shared field:** first shared-A sample shifted right by 23.

The high field does not come from shared word A.

An auxiliary signed index selects a four-byte-stride destination where the high field is stored. The next dependency receives, in order:

1. That index.
2. The same index.
3. The small shared field.
4. The high field.

After a producer call, the small shared field is shifted right by 23 again. This is zero: the first shift already reduced it to at most 511.

Following further calls, the high field is stored at another signed index’s four-byte-stride destination. A dependency receives four times that index.

A later auxiliary **unsigned index** selects a destination that is explicitly zeroed using \(D_u\). That unsigned index is then passed to a dependency. Its address calculation can wrap even when the resulting numerical address is small.

After another call sequence, a returned signed index selects a four-byte-stride destination where the twice-shifted small shared field is stored. This is another zero word store.

The routine then reads an unsigned word at:

\[
((\text{unsigned zeroing index}\mathbin{\&}(2^{29}-1))\gg19)+20.
\]

This address is between **20 and 1,043**. A dependency subsequently receives four times the most recent signed index.

### 5. Low-address byte selection

After further calls, the preceding word observation is shifted right by 22, producing a **ten-bit field**.

The twice-shifted shared field is zero. Consequently, the next byte-selected write reads its selector at **address 1**, then stores the ten-bit field’s low byte at the selected destination.

A dependency receives the same auxiliary word in its first three argument positions and zero in the fourth. Subsequent calls include a call receiving zero.

A later call result is retained while the routine:

1. Reads a selector byte at four times the ten-bit field plus 1.
2. Writes zero at the selected destination.
3. Passes the retained result, signed-shifted left by two, to a dependency.

The selector address in step 1 is **1–4,093**; its unsigned calculation cannot overflow.

Another sequence produces a result passed, signed-shifted left by two, in two argument positions. A following producer’s unsigned word is forwarded to another dependency.

After another call, the routine freshly reads the byte at address 1 and writes zero at the selected destination.

An auxiliary signed word is retained for later shifts. A dependency receives that word in three explicit argument positions.

### 6. Retained small base and first publication

A producer result and the earlier forwarded unsigned word shifted right by 23 are passed to a dependency. Further calls yield another result.

The routine freshly reads the byte at address 1, zero-extends it, and retains it as the **small base**. It writes zero at small base plus 17.

Further calls receive a signed-shifted result, followed later by another signed-shifted result repeated in two positions.

A producer then supplies the **published word**. The routine writes it to shared word B and passes the captured value to a dependency. Another call occurs before the next explicit read.

The routine reads a word at small base plus 116 and writes its low byte at small base plus 1. These use the retained small base, not a new read of address 1. Their unsigned additions cannot overflow because the small base is at most 255.

A dependency receives the retained auxiliary signed word shifted left by 11.

### 7. Word-to-byte mirroring

A pair-producing call is followed by a dependency receiving the pair’s low half, its high half, and the retained published word shifted right by 23. The third argument is not a fresh read of shared word B.

Further calls yield a signed index. Four times that index becomes the **mirror base**, using signed multiplication. The routine reads a word at mirror base plus 116, writes its low byte at mirror base plus 1, and passes the mirror base to a dependency.

After more calls, a signed result shifted left by two is retained as an unsigned **scaled selector**. Its producing shift remains subject to the signed-arithmetic qualification.

The routine freshly reads the word at mirror base plus 116 and again writes its low byte at mirror base plus 1. The earlier observation is not reused.

The next value-bearing call receives:

1. The retained auxiliary signed word shifted left by 12.
2. The scaled selector.
3. The scaled selector again.
4. The signed result underlying that selector shifted left by 18.

Producer/consumer calls follow. Another signed index supplies a new four-times-index base. The routine reads an unsigned **mirrored word** at that base plus 116 and writes its low byte at that base plus 1.

After passing that base to a dependency and making further calls, the full mirrored word is stored at **16 times a returned signed index plus 20**. This is a signed-arithmetic, sixteen-byte-stride destination, not an ordinary four-byte-stride destination.

### 8. Full-word propagation and linking

A dependency receives the unsigned expression:

\[
((\text{scaled selector}\gg2)\ll16)\bmod2^{32}.
\]

The left shift discards high bits. This expression does not recover bits lost while forming the scaled selector.

Following further calls, the mirrored word is stored at a signed index’s four-byte-stride destination. Four times that signed index is passed to a dependency.

Another sequence produces a signed result whose left shift by two forms the **first link word**. It is stored at:

\[
((\text{scaled selector}\mathbin{\&}\text{0xFFFFFFFC})+20)\bmod2^{32}.
\]

This destination addition is unsigned and wraps. A dependency receives the first link word twice.

Another call chain leads to a zero word store at a returned signed index’s four-byte-stride destination, then a call receiving four times that index.

A later pair supplies the **second link word**, formed by signed-shifting its low half left by two. Its high half is interpreted as a signed destination index. The second link word is stored at that index’s four-byte-stride destination.

Shared word A is freshly read as the **second shared-A sample**. A dependency receives the second link word, the pair’s high-half index, the second link word, and the second link word.

After further calls, the second link word is stored at another signed index’s four-byte-stride destination. The routine then reads the **final lookup word** at:

\[
(\text{second shared-A sample}+20)\bmod2^{32}.
\]

### 9. Final writes and termination

Further calls produce a retained final pair.

Before the next call, the routine reads a selector byte at mirrored word shifted right by 23, plus 1. It writes the final lookup word’s low byte at the selected destination.

A dependency receives the final pair’s high half three times, followed by its **unsigned low half shifted left by two modulo \(2^{32}\)**.

After additional calls, another byte-selected write reads its selector at:

\[
((\text{final pair low half}\mathbin{\&}(2^{30}-1))\gg21)+1.
\]

It stores the low byte of final lookup word shifted right by 22. This selector address is **1–512**.

Further calls consume signed-shifted results, including a result repeated in two positions. A later word result is forwarded to a dependency, followed by a byte-producing call.

The final explicit sequence is:

1. Write a zero byte through an auxiliary pointer supplied by a call.
2. Read the three-byte shared input at address 9.
3. Write shared word B with the byte-producing result in bits 0–7 and the observed three-byte value in bits 8–31.
4. Write a zero halfword at the final pair’s low half masked to 30 bits and shifted right by seven.
5. Attempt a call through address zero with three zero arguments.
6. Return only if that call returns.

The auxiliary-pointer store precedes the three-byte read. If they alias, composition uses the post-store observation.

3. **Unsigned lookup addition:** If the second shared-A sample is 4,294,967,295, the final lookup’s unsigned addition produces numerical address **19** before pointer conversion. This does not establish that address 19 is readable.

4. **Independent field sources:** A high-field source of 8,388,608 and first shared-A sample of 4,294,967,295 produce high field 2 and small shared field 511. Both high-field stores use 2. The associated four-argument call receives the auxiliary index twice, then 511, then 2. The twice-shifted shared field is zero.

5. **Byte selection and truncation:** A ten-bit field of 1,023 and selector byte 40 at address 1 cause a byte store of 255 at address 57.

6. **Fresh mirroring:** If intervening dependencies change the word at mirror base plus 116, the second mirroring write uses the new observation’s low byte.

7. **Sixteen-byte stride:** A relevant signed index of 3 selects address 68 for the full mirrored-word store, not ordinary destination 32.

8. **Unsigned final argument:** A final-pair low half of 1,073,741,825 produces argument **4** when unsigned-shifted left by two. This rule does not resolve earlier signed left shifts.

9. **Final composition:** A byte result of 170 and observed three-byte value of 1,193,046 produce shared word B value **305,419,946**. No adjacency between the shared locations follows.

10. **Aliasing and termination:** An auxiliary pointer into the three-byte input modifies that input before composition. If the subsequent halfword store prevents continuation, the address-zero call is not reached. If that call does not return, normal return is not established.
