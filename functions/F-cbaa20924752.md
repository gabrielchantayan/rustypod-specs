# F-cbaa20924752

## Purpose

F-cbaa20924752 selects one of two record banks and writes a 32-bit configuration word into an indexed record. It can use a caller-supplied selection or derive an initial selection by intersecting two one-byte table entries and consulting dependencies.

The function returns either zero or decimal 19 through its explicit return paths. Zero means that the record-write path was reached; it does not establish that dependencies succeeded, that the configuration is valid, or that any broader operation completed.

The supplied static representation establishes memory accesses and control flow. It does not establish the application meaning of the banks, table entries, configuration bits, or dependency calls.

### Return value

The explicit return value is a 32-bit quantity:

- **0:** the function reaches and performs its configuration-word store.
- **19:** automatic selection produces an initial zero intersection, or the selector is not accepted as bank 1 or bank 2 when bank selection occurs.

Dependency return values are not directly returned. In particular, the selection dependency’s result controls only whether its call is repeated.

### Referenced storage and layout

Records have a **32-byte stride**. This function writes only the first 32-bit word of the selected record. It does not explicitly initialize or clear the other 28 bytes.

## Behavior

### 1. Entry dependency

Before inspecting either pointer argument or selecting a bank, the function calls **F-3b7c5b30bd55** with the integer value **20**.

Its return value is ignored. The function does not branch on it.

This call precedes the function’s first selector read. Therefore, “initial selector” below means the value observed after this dependency returns, not necessarily the value present when the caller invoked F-cbaa20924752. No preservation guarantee for caller storage or global state is established for the dependency.

### 2. Choosing direct or automatic selection

The function reads the selector byte.

- If the byte is nonzero, it proceeds directly to bank selection.
- If the byte is zero, it performs automatic selection.

The direct path does not read the compatibility table and does not invoke either selection-related dependency.

### 3. Automatic selection

The function reads two bytes from the compatibility table, using the first and fourth arguments as byte offsets. It computes their bitwise intersection and writes the resulting byte through the selector pointer.

The initial branch is based on that computed intersection:

- **Zero intersection:** set the return status to 19 and proceed to the exit dependency. Neither selection-related dependency is called.
- **Nonzero intersection:** invoke **F-49ef92ddd2b2**, passing the selector pointer and record-index pointer.

The relative order of the two compatibility-table reads is not established. Both are required to compute the intersection before the selector write.

The selection dependency is called at least once for a nonzero intersection. It is called again whenever its return value is **21**. The same pointer arguments are supplied on every iteration; values written through them are not reset to the original intersection or original record index.

There is no visible retry limit. If every invocation returns 21, this function does not reach notification, bank selection, the exit dependency, or its return statement.

On the first dependency result other than 21, the loop stops. The function does not otherwise classify that result as success or failure.

It then calls **F-7fc5c24aeec1**, supplying:

1. The current selector byte, promoted to an integer.
2. The current record-index character, converted to an integer.

The relative evaluation order of these two argument reads is not established. The dependency’s return value is ignored.

Notification occurs before validating whether the selector is 1 or 2. Consequently, a selection dependency result other than 21 can lead to notification followed by a return status of 19.

The function rereads the selector for subsequent bank selection. It does not rely on a selector value cached before notification. If notification changes the selector or record-index storage, those changes can affect the subsequent bank choice or record address.

### 4. Selecting a bank

The bank-selection logic accepts:

- Selector **1:** first bank.
- Selector **2:** second bank.
- Any other selector: return status **19**, with no explicit bank-state or record write.

The test for 1 and the later test for 2 are separate selector reads on the path that does not match 1. No dependency call occurs between these tests, but the supplied representation does not establish atomicity or synchronization against external mutation.

For the chosen bank, the function reads the record-index character and computes a record address at:

**bank base + 32 × converted record index**

It also obtains the selected bank base for use in locating the state word. The representation contains separate base references for record-address formation and state-address formation; it does not establish a protected snapshot of mutable global bases.

No record-count limit or index validation is present.

### 5. Updating bank state and the record

The function first writes the 32-bit value **1** to the state location 220 bytes before the selected bank base.

It then obtains four 32-bit configuration-table entries using the argument-to-table mapping in the Interface section. Their bitwise union, together with the fixed bit mask **0x80000000**, becomes the value written to the selected record’s first word.

The resulting record word therefore has bit 31 set, regardless of the table contents. All other bits are the bitwise union of the corresponding bits from the four table entries.

The record write replaces the entire first 32-bit word. The function does not read that word to preserve its previous bits.

The explicit order is:

1. Form the selected record destination.
2. Write the selected bank’s state word to 1.
3. Read the configuration-table entries and compute the combined word.
4. Store the combined word at the record destination.

The relative order of the four configuration-table reads is not established.

This ordering matters if storage overlaps. For example, if the state location aliases a configuration-table entry, the state write occurs before that entry is read. The record destination has already been formed before the state write.

### 6. Exit dependency and return

Every explicit returning path calls **F-5a0e2e961d01** with the integer value **20**, then returns the selected status.

The exit dependency’s return value is ignored. There is no visible mechanism by which its return value changes zero into 19 or vice versa.

This call is not an unconditional cleanup guarantee: endless selection retries, non-returning dependencies, or faults can prevent it from being reached.

## Side effects

### Explicit memory effects

Depending on the path, the function can perform these writes:

- Automatic selection writes the compatibility-byte intersection through the selector pointer, including when that intersection is zero.
- A valid bank selection writes a 32-bit 1 to that bank’s state location.
- A valid bank selection writes one 32-bit configuration word at the start of the selected record.

The function does not explicitly write through the record-index pointer. F-49ef92ddd2b2 receives that pointer and may modify its target; the dependency’s behavior is unknown.

Invalid selection does not undo the earlier selector write or dependency effects. There is no visible rollback if execution fails after the bank-state write but before the record write.

### Dependency effects

The entry and exit dependencies are invoked even on ordinary status-19 paths. Their effects are not established.

F-49ef92ddd2b2 receives both caller pointers. F-7fc5c24aeec1 receives values, not those pointers, but may still affect globally reachable storage. None of these dependencies can be assumed to preserve globals, preserve caller memory, or retain or release memory in a particular way.

### Width and arithmetic constraints

- Selector values and compatibility entries are 8-bit quantities.
- Configuration entries, the bank-state store, and the record store are 32-bit quantities.
- Configuration-table addressing uses a scale of 4.
- Record addressing uses a scale of 32.
- The state location uses a displacement of −220 bytes.
- The configuration mask is a 32-bit value with only bit 31 set.

For arbitrary 32-bit integer indices, scaled address calculations can exceed the representable address range. The supplied evidence does not resolve overflow semantics, address wrapping, fault behavior, or valid table extents. Such cases are not specified as returning 19.

No byte-order conversion is visible. The numeric word written is established; its byte layout depends on target endianness.
