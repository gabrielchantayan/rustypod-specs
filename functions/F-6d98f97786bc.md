# F-6d98f97786bc

## Purpose

F-6d98f97786bc dispatches operations against a caller-supplied state object. Its established behavior includes selecting an identifier, obtaining an associated handle, processing queued event categories, invoking category-specific handlers, resetting four byte counters, and conditionally clearing a timed-state flag.

The operation selector determines which behavior occurs. Most paths return the 32-bit value zero. The queue-processing path instead returns the result of the most recently dispatched recognized event, or zero if no recognized event was dispatched.

Descriptions such as “identifier,” “handle,” “counter,” and “timed-state flag” are behavioral labels inferred from use. Their application-level meanings are not established.

## Interface

The function accepts three machine-word arguments:

| Argument | Interpretation |
|---|---|

| Operation selector | A 32-bit integer compared against 4, 8, 32, and 64. |

For identifier comparisons, the auxiliary value and stored identifier are compared as 32-bit values. The admission comparison against 3 is signed. The status comparison against −1 refers to the all-ones 32-bit representation.

## Behavior

### Common entry behavior

The context-address word and seed word are read before operation dispatch. A result accumulator begins at zero.

Unsupported operation selectors return zero without explicit writes to the supplied object. The entry-time global reads still occur.

### Operation 4: select an identifier and establish an associated handle

The stored identifier is first examined using a signed comparison against 3.

- If the stored identifier is less than 3 and differs from the auxiliary value, the function immediately returns zero.
- Otherwise, the auxiliary value is written to the stored identifier field.

Consequently, a negative stored identifier restricts replacement in the same way as identifiers 0, 1, and 2. A stored identifier of 3 or greater admits a different auxiliary value, including a negative one.

After writing the identifier:

1. The function calls the context-provider dependency identified here as F-unknown-01.
2. Four bytes are added to the returned address.
3. The stored identifier is read again.
4. F-b37968c9f644 is called with the adjusted address and that current identifier.
5. Its 32-bit result is written to the associated-handle field.

The reread matters: the identifier passed to F-b37968c9f644 is not necessarily the original auxiliary value if the provider changes accessible state.

If the stored handle result is zero, F-a817d8d58c10 is called. The supplied evidence marks this dependency as non-returning; normal execution does not continue through that call.

For a nonzero result, the function calls F-d205b6619363 on the object, then F-e35b2bccb75d with the object and the fixed arguments 0 and 1. It returns zero, ignoring both dependency results.

### Operation 8: conditional deactivation sequence

The stored identifier is compared with the auxiliary value.

- A mismatch returns zero without invoking the operation-specific dependencies.
- A match calls F-e35b2bccb75d with the object, 1, and 1, followed by F-d205b6619363 on the object.

The function then returns zero.

This call order differs from the common completion sequence used by operation 4 and some operation-64 paths.

### Operation 32: poll and dispatch events

This operation repeatedly polls until F-e08f888de5db returns a nonzero value.

Before every poll:

1. The current stored identifier is copied into a 32-bit scratch word.
2. A separate 32-bit scratch value is set to zero.
3. The first word of a two-word descriptor is set to the address of that zeroed value. The second descriptor word has no explicit initialization in the supplied evidence.
4. Two other 32-bit scratch words are each reset to the entry-time seed word.

F-e08f888de5db receives the object and addresses of the identifier scratch word and the two seeded words. It can modify those scratch words. Their values are reinitialized on the next iteration rather than carried forward.

A nonzero poll result ends the loop immediately. No category dispatch is performed for that poll.

For a zero poll result, the low 16 bits of the last seeded scratch word determine the event category. Its upper 16 bits do not affect dispatch.

| Category | Explicit action before handler | Handler |
|---:|---|---|
| 1 | Increment byte at `0x2E0` | F-a7dad23e028e with the object |
| 3 | Increment byte at `0x2E1` | F-0dce558036fd with the object and the byte at captured context address + 2 |
| 4 | Increment byte at `0x2E2` | F-ebf9a68d2fc9 with the object |
| 6 | Increment byte at `0x2E3` | F-daf78a556d2c with the object and the byte at captured context address + 3 |

Each increment is stored back as an 8-bit value; the byte wraps from 255 to 0. The counter update precedes the handler invocation.

For categories 3 and 6, the configuration byte is read for that dispatch, after the counter update. The configuration byte is not an entry-time snapshot.

Each recognized handler replaces the result accumulator with its 32-bit return value. Other categories leave the accumulator unchanged and cause another poll. There is no explicit iteration limit. If the polling dependency never returns nonzero, this function does not reach its post-loop behavior.

### Operation 32: post-loop timed-state processing

After polling stops, the byte at `0x2DC` is read.

If it is zero, the function immediately returns the accumulated handler result.

If it is nonzero, the following sequence occurs:

1. F-7a117b899bf6 is called with a two-word scratch area.
2. The first word of that area is treated as an address from which a callable address is read at byte offset 12.
3. That callable, identified here as F-unknown-02, is invoked with the scratch-area address and the descriptor established during the final polling iteration.
4. F-bf18a6a8124b is called with the descriptor address and produces a 64-bit result.
5. A 32-bit object address is read from captured context address + 4.
6. A 32-bit baseline is read at offset `0x2D8` from that referenced object.

The baseline need not belong to the supplied object. Equality between the referenced object and the supplied object is not established.

Let the low and high 32-bit halves of the conversion result be the low word and high word. The expiry decision uses only the low word:

- Compute low word minus baseline using unsigned 32-bit arithmetic.
- If that wrapped difference is greater than 499, write zero to the supplied object’s flag at `0x2DC`, then write zero to its word at `0x2D8`.
- Otherwise, neither field is explicitly cleared by this expiry branch.

Thus, a difference of 499 does not clear the fields; a difference of 500 does. A low word numerically below the baseline can produce a large wrapped difference and trigger clearing.

Finally, F-ec22bd8215d3 is called with the two-word scratch area and a second argument formed from the high word minus an unsigned borrow indicator. The indicator is 1 exactly when the low word is less than the baseline. This subtraction supplies a 32-bit argument; the high word does not participate in the expiry threshold comparison.

The function returns the accumulated handler result. Results from the timing-related dependencies do not replace that accumulator.

### Operation 64: react to lookup and status

The associated-handle field is first read. If zero, the function returns zero.

Otherwise, F-unknown-01 is called. F-9c4f3d705d74 is then called with its unadjusted result and the stored identifier, read after the provider returns.

If the lookup result is nonzero:

- An auxiliary value other than 4 returns zero.
- For auxiliary value 4, the four counter bytes are cleared in ascending offset order: `0x2E0`, `0x2E1`, `0x2E2`, `0x2E3`.
- F-d205b6619363 is then called, followed by F-ebf9a68d2fc9.
- The function returns zero.

If the lookup result is zero:

- Auxiliary value −1 calls F-d205b6619363, then F-e35b2bccb75d with 0 and 1, then F-c6c589453fa8 with the four fixed arguments 8, 0, 11, and 4.
- Auxiliary value 0 calls F-d205b6619363, then F-e35b2bccb75d with 0 and 1.
- Every other auxiliary value returns zero without those calls.

All operation-64 paths that return normally return zero.

## Side effects

Explicit object writes are limited to identifier replacement, associated-handle replacement, individual byte-counter increments, four-counter clearing, and timed-state clearing on the paths described above.

Dependencies can introduce additional side effects. No preservation guarantee is established for object fields, global state, indirect memory, or external resources across any dependency call. Reads that occur after a dependency must therefore be interpreted against the then-current memory, except for the two global words explicitly captured on entry.

There is no rollback:

- Identifier replacement precedes handle acquisition.
- A zero handle is stored before the non-returning dependency is called.
- Counters are incremented before their handlers run.
- Timed-state clearing precedes the final timing dependency.

No recoverable error result is established for polling termination, unsupported selectors, identifier mismatches, lookup outcomes, or ignored statuses. These paths generally return zero, so zero alone cannot distinguish them.

## Acceptance examples

The following are conditional static acceptance examples, not executed tests. Unless specified otherwise, dependencies are assumed not to mutate fields relevant to the example.

1. **Restricted identifier replacement.** With stored identifier 2, operation 4, and auxiliary value 5, the function returns zero without replacing the identifier or invoking the provider.

2. **Signed admission boundary.** With stored identifier −1 and auxiliary value 0, operation 4 is rejected. With stored identifier 3 and auxiliary value −1, identifier replacement is admitted.

3. **Successful handle establishment.** If operation 4 is admitted and F-b37968c9f644 returns a nonzero word, that word is stored at `0x2D4`; F-d205b6619363 precedes F-e35b2bccb75d with 0 and 1; the result is zero.

4. **Failed handle establishment.** If that dependency instead returns zero, zero is stored at `0x2D4` before F-a817d8d58c10 is invoked. No normal return is established.

5. **Operation-8 ordering.** With matching identifiers, F-e35b2bccb75d receives 1 and 1 before F-d205b6619363 runs. A mismatch invokes neither.

6. **Category masking and wrapping.** A successful poll yielding category word `0xABCD0001` selects category 1. A counter byte of 255 is written as 0 before F-a7dad23e028e runs.

7. **Last recognized result.** If successful polls yield categories 1, 9, and 4, followed by a terminating poll, the returned accumulator is the result from F-ebf9a68d2fc9. Category 9 does not reset it.

8. **Immediate polling termination.** If the first poll returns nonzero, no event handler runs. With a zero timed-state flag, the function returns zero.

9. **Expiry boundary.** With a nonzero timed-state flag and wrapped low-word-minus-baseline difference of 499, the expiry branch does not clear the fields. At 500, it clears `0x2DC` before `0x2D8`.

10. **Borrow behavior.** With low word 10 and baseline 11, the unsigned difference is `0xFFFFFFFF`, so expiry clearing occurs. The final timing dependency receives high word minus 1 as its second argument.

11. **Lookup-present reset.** With a nonzero associated handle, nonzero lookup result, and auxiliary value 4, all four counters are cleared before F-d205b6619363 and F-ebf9a68d2fc9 run.

12. **Lookup-absent notification.** With a nonzero associated handle, zero lookup result, and auxiliary value −1, the two object operations precede F-c6c589453fa8 with 8, 0, 11, and 4. The result is zero.
