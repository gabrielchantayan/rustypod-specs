# F-b2366138325f

## Purpose

F-b2366138325f reports whether bit 6 of an unsigned word stored at a fixed offset from a supplied base address is set.

For a valid, stable input location, the result is exactly one of two unsigned values:

- **0** when the selected bit is clear.
- **1** when the selected bit is set.

This is a bit-state query, not a validation operation. The supplied evidence does not identify what the bit means, what kind of object contains it, or whether it represents a status, permission, capability, or other property.

## Interface

### Input

The function accepts one integer-valued argument used as a base address. The word to inspect begins **72 bytes after that base**, at offset **0x48**.

The argument is used directly for address formation. The function does not first read a pointer from the base location.

The supplied representation declares the argument as a signed integer rather than a pointer. Its exact ABI width and the rules by which its value becomes an address are not established independently. Consequently, this contract does not promise support for arbitrary host pointer widths, negative address representations, or addresses requiring truncation or sign extension.

### Output

The function returns an unsigned scalar whose value is always **0 or 1**, provided execution reaches the return normally.

The return representation is an unsigned integer type. Its exact ABI width is not independently established by the supplied material; the two possible numerical results do not depend on that width.

### Accessed word and layout

The accessed field has the following established properties:

| Property | Contract |
|---|---|
| Location | Base address plus 72 bytes |
| Access form | One unsigned-word dereference |
| Selected bit | Bit 6, numbering the least significant bit as bit 0 |
| Selection mask | 0x40, or decimal 64 |
| Normalization | The selected bit is shifted right by six positions |
| Modification | None expressed by this function |

The supplied unsigned-word notation conventionally denotes a 32-bit type. However, no type definition or independent machine-width evidence accompanies it. **A 32-bit field width is therefore documented_only**, rather than an independently established ABI guarantee. The bit extraction itself requires only that the unsigned word can represent bit 6.

The offset is a byte offset: it is added to the integer address before the address is treated as an unsigned-word location. It is not an offset of 72 words.

### Preconditions

For defined, successful operation:

- The resulting location must permit the unsigned-word read.

## Behavior

### Established operation

The function forms the field address, reads the unsigned word at that address, and reduces the observed word to the selected bit’s Boolean value.

The returned value depends only on whether the observed word contains the 0x40 bit. All other bits are discarded by the mask. No count, enumeration, error status, or original field value is returned.

For example, an observed word of 0x40 produces 1, not 64. An observed word of 0x80 produces 0 even though that word is nonzero.

### Observable read order

The supplied body contains one explicit memory read: the unsigned-word dereference at base plus 72.

There are no preceding object reads, no pointer-chasing steps, and no subsequent field reads. Address formation precedes the field access; bit selection and result normalization use the value obtained from that access.

This establishes the source-level access sequence. It does **not** establish:

- A particular machine load instruction or bus transaction count.
- Atomicity of the load.
- Memory barriers or acquire semantics.
- A volatile-access guarantee.
- A stable result across calls while another actor changes the field.

Because the source-level operation reads the unsigned word, this contract does not reduce its accessibility requirement to the single byte that might contain bit 6 on a particular target.

### Arithmetic boundaries

The address displacement is the positive constant 72. No scaling by the field width is expressed.

The supplied representation performs this addition in an integer-address expression. It does not establish that overflow wraps, that the address is widened first, or that invalid values are rejected. Callers must therefore not rely on overflow behavior at the argument type’s limits.

Once an unsigned word has been obtained, extracting bit 6 introduces no arithmetic ambiguity: masking leaves either zero or 64, and shifting right by six yields zero or one.

### Errors and invalid inputs

There is no explicit error branch and no reserved error return.

An unreadable, unmapped, misaligned, stale, or otherwise invalid field address is not converted into a zero result. Such an access may fault or have other environment-dependent consequences. The supplied evidence does not specify an exception type, signal, recovery mechanism, or successful return in these cases.

A numerically zero base receives no special handling. It would direct the access to numerical address 72, subject to the environment’s address rules. Whether that location is readable is outside the established contract.

## Acceptance examples

These are conditional acceptance cases derived from the static evidence. **They have not been executed.**

For each successful case, assume that address formation is valid and that the complete unsigned word at base plus 72 is readable and stable during the access.

| Observed unsigned word | Expected return | Reason |
|---|---:|---|

| 0xC0 | 1 | Bit 6 remains selected when bit 7 is also set. |

Additional conditional criteria:

- **Unselected-bit independence:** Two valid observed words differing only outside bit 6 must produce the same return value.
- **Selected-bit sensitivity:** Two valid observed words differing only in bit 6 must produce opposite results, zero and one.
- **Offset selection:** Changing storage at the base address must not affect the result unless that change also affects the word read at base plus 72.
- **No field update:** For ordinary memory without external writers or read side effects, calling the function must leave the accessed word unchanged.
- **Fresh invocation:** If a properly synchronized writer changes bit 6 between two calls, each call’s result must correspond to the word observed by that call.
- **Invalid access:** An inaccessible field address has no specified successful return. Returning zero is not an established error-handling requirement.
