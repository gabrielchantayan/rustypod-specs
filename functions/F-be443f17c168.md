# F-be443f17c168

## Purpose

The established behavior is a sequence of calls, reads, and writes—not proof of a particular object type or initialization policy. In particular, the external dependency’s implementation is unavailable. Its calls must not be described as clearing, allocating, constructing, or releasing memory.

A plausible intent is to initialize a primary region and two related descriptors that refer to it. This interpretation is **inferred intent**, not an additional behavioral guarantee.

## Behavior

### Notation and scope

The sole external callee is assigned the document-local opaque function ID **F-000000000001**. This label identifies the repeated dependency in this contract; it does not assert a known public identity or implementation.

The ordering below is the ordering expressed by the supplied representation. It is not a claim about processor-level memory ordering, synchronization, or atomicity.

### Entry capture and first region

Before invoking any dependency, the function reads the 32-bit value at base offset `0x08` and retains that value for later use.

It then invokes F-000000000001 with:

- First argument: base address plus `0x14`.
- Second argument: `0x58`, or 88.

After that call returns, the visible operations occur in this order:

1. Read G-A and retain its 32-bit value.
2. Write the entry-captured value to offset `0x14`.
3. Write the retained G-A value to offset `0x6C`.
4. Read G-B and write its value to offset `0x70`.
5. Read G-C and write its value to offset `0x74`.

The initial read at `0x08` therefore precedes the first dependency call. A change to that source location during the call does not change the value later written to `0x14`.

The three slots at `0x6C`, `0x70`, and `0x74` lie immediately after, not inside, the first dependency’s nominal 88-byte region. That region ends at `0x6B`.

### Second region

The function next invokes F-000000000001 with:

- First argument: base address plus `0x78`.
- Second argument: `0x1C`, or 28.

After that call returns, the visible operations occur in this order:

1. Read G-E and retain its value.
2. Read G-D and write its value to offset `0x7C`.
3. Write the retained G-E value to offset `0x80`.
4. Read G-I and retain its value.
5. Read G-F and write its value to offset `0x84`.
6. Read G-G and write its value to offset `0x88`.

The nonalphabetical read order matters. G-E is captured before G-D is read; G-I is captured before G-F, G-G, and G-H are read.
