## Behavior

### Sequencing conventions

Two recurring call sequences are described compactly:

- A **five-call chain** makes one call with the specified explicit arguments, followed by four calls without explicit arguments. Its final result is retained where stated.
- A **nine-call token chain** makes a leading call with the specified arguments, obtains an opaque 32-bit token from a no-explicit-argument call, passes that token to another call, obtains a second token from another no-explicit-argument call, passes it onward, and makes four further no-explicit-argument calls. A token-consuming call sometimes receives an additional argument, identified below.

These descriptions specify visible argument positions and ordering, not complete calling conventions. Different occurrences need not share targets. No intervening dependency is assumed to preserve memory or globals.

“First snapshot” and “second snapshot” below mean the captured 32-bit word values, not later contents of their source addresses.

### Initial payload stores and byte writes

The first explicit effect is a 32-bit store of the incoming payload at the incoming base plus `0x14`.

A five-call chain follows. Its leading call receives the first argument and uses a target derived from incoming machine state. Four times the chain’s final result, plus `0x14`, becomes the destination of a second store of the incoming payload.

Another five-call chain begins with that fourfold-scaled result and supplies a new unsigned 32-bit result. A pointer byte is then read at the first argument logically shifted right by eight, plus one. The byte value plus `0x11` selects the destination of a byte store containing the low eight bits of the new result shifted left by two.

A five-call chain receives that shifted result. The initial pointer-byte address is then read again. At the newly selected destination, the function stores the low eight bits of the earlier unsigned result masked by `0x3FFFFFFF` and shifted right by 20. The stored byte therefore selects bits 20 through 27, not the full ten-bit intermediate quantity.

A further five-call chain begins with the preceding chain’s final result shifted left by two.

The two pointer reads are distinct operations separated by calls. Their byte values and selected destinations need not match.

### Captured global-derived stores

The third argument, logically shifted right by seven and multiplied by four, supplies a store base. The captured value is written at that base plus `0x14`.

A five-call chain receives the captured value. The same captured value is then stored again at the same calculated address; there is no intervening explicit reread of the datum.

Another five-call chain receives the preceding chain’s final result shifted left by two. Its final result initiates the snapshot stages.

The indexed pointer byte is reread and another selected-destination zero write occurs.

2. The current unsigned loop-control quantity shifted right by eight.

- On the first iteration, it uses the target expression established immediately before loop entry, documented as F-UNRESOLVED-03.

A second five-call chain receives the first chain’s final result shifted left by two. Its final result supplies both next-iteration values: the ordinary argument after left shift by two, and the unsigned loop-control quantity after left shift by 26.

- **Initial indirection:** With first argument `0x00001200`, the pointer-byte read address is `0x13`. A byte value of `0xA0` selects destination `0xB1`.

- **Captured global value:** With third argument `0x100`, both global-derived stores address `0x1C`. If the captured converted value is `0x89ABCDEF`, both explicit stores use it even if a dependency changes the underlying datum between stores.

- **Snapshot aliasing:** A snapshot-producing result of zero makes the preceding store and snapshot read both address `0x14`. Under ordinary coherent-memory behavior without intervening modification, the snapshot is zero.

- **Positional arguments:** If the latest fourfold-scaled result is `0x40` and the first snapshot is `0x00001200`, the relevant two-argument leading call receives `0x40` first and `0x90` second.

- **Snapshot extraction:** For first snapshot `0xFEDCBA98`, logical shifts by 16, 24, 23, and 31 yield `0xFEDC`, `0xFE`, `0x1FD`, and `1`. The direct byte destination is therefore `0x1D`.

- **Pointer rereading:** Pointer-byte values changing from `0x20` to `0x30` select destinations `0x31` and `0x41`. Caching the first pointer value would not match the explicit read sequence.

- **Loop target transition:** If execution reaches two iterations, the first leading call uses F-UNRESOLVED-03’s target expression; the second uses F-UNRESOLVED-04’s expression. Neither target’s internal behavior is specified.
