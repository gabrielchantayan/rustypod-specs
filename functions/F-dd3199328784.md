# F-dd3199328784

## Purpose

F-dd3199328784 performs an ordered chain of unresolved indirect invocations, derives address-bearing values from their results and implicit execution state, mutates memory through mixed-width accesses, and ends with an unresolved four-argument indirect transfer.

An application-level purpose is not established. Repeated offsets do not prove a record layout, and character-like numeric constants do not prove text processing.

This contract distinguishes:

- **Established static evidence:** operations, widths and ordering represented in the supplied material.
- **[INFERENCE]:** interpretations conditional on additional assumptions, including 32-bit truncating machine arithmetic.
- **documented_only:** unresolved behavior that cannot be made an executable requirement from the supplied evidence.

No runtime tests have been performed.

## Acceptance examples

These examples are conditional static criteria, not executed tests.

- **Third argument:** Under 32-bit truncating shifts, 0x00000123 contributes 0x23000000 to its early transformed argument position. This does not establish whole-function equivalence with 0x00000023 because implicit state remains observable.

- **Compact boundary:** Under the same interpretation, the compact base is a multiple of eight between 0 and 1,016. Treating it as an unrestricted pointer fails to preserve the represented calculation.

- **Low-address publication:** If the compact field is 0x1FC, the compact base is 0x3F8. Its byte publications at absolute addresses 1 and 0x15 contain 0xF8 at their respective positions. The intervening absolute-address-0x54 assignment contains the link value shifted left by one, not the compact base.

- **Unknown-width global:** An implementation cannot be accepted merely because it reads one byte at absolute address 5 and zero-extends it. That load width requires declaration or machine-level evidence.

- **Intervening final write:** If absolute address 0x3A overlaps a later word-read range, acceptance requires that read to observe the state after the 0x3A store. Moving it before the store is not generally equivalent.

- **Mutable 0x67:** If an intervening relative store changes 0x67, the next publication-base + 9 assignment uses the newly evaluated global value. Reusing the original low byte from 0xA9 is not generally equivalent.

- **Global-base retention:** If assigning 0x20 at absolute address 0x60 changes storage overlapping the global-base source, the publication pattern still uses the base retained before that assignment.

- **Failure and retention:** No recovery code is promised for an inaccessible destination. If the earlier final-argument location changes after its read, the final transfer still receives the retained value.
