# F-40a12cc001fe

## Purpose

F-40a12cc001fe performs a two-pass operation over a collection of records. It first checks a required field and selects a reference record. For a nonempty valid collection, it rounds the reference dimensions down to multiples of eight, requests three temporary buffers, and invokes a producer dependency. If that producer succeeds, it traverses the collection again, prepares three temporary buffers per record, invokes a transformation dependency, and conditionally dispatches a format-specific operation.

The established contract is the sequence of record accesses, dependency calls, mutations, cleanup calls, and return values described below. Image-plane terminology would be a plausible interpretation of the three buffers and quarter-sized secondary allocations, but that interpretation is not established by the supplied evidence.

## Behavior

### Entry and first traversal

A zero A6 causes an immediate `0xfffffffa` return. No dependency is called on that path.

For nonzero A6, the function initializes a local traversal context through F-538044b67754, passing A6 and the 32-bit sentinel `0xfffffffe`. It then repeatedly calls F-6e4651b532dc with that context and an output location for a record reference.

A nonzero traversal result means the function processes the yielded record. A zero result ends the pass.

For each yielded record, the function first reads the 32-bit field at `0x2c`:

- If it is zero, the function calls F-944b595e25e9 on the traversal context and returns `0xfffffffa`.
- Otherwise, the record participates in reference selection.

The first valid record becomes the reference. A later record replaces it only if **both** of its dimensions are strictly greater than the current reference’s dimensions, using signed 32-bit comparisons:

- D8 is compared first.
- D4 is compared only if the candidate’s D8 is strictly greater.
- Replacement requires D4 also to be strictly greater.

Consequently, this is not independent maximization of both dimensions, a largest-area choice, or a lexicographic ordering. Equality in either dimension prevents replacement. Traversal order can affect the selected record.

If the pass ends without yielding any record, the function calls F-944b595e25e9 and returns zero. No buffers are requested and no producer is invoked.

### Reference normalization and buffer requests

For a nonempty valid first pass, the selected reference is mutated:

1. D8 is read, masked with `0xfffffff8`, and written back.
2. D4 is read, masked with `0xfffffff8`, and written back.

These operations clear the low three bits. For nonnegative dimensions, they round down to multiples of eight; values from zero through seven become zero. Negative inputs are not rejected.

Three calls to F-638beded7699 follow, each with a second argument of zero:

1. A primary size obtained from the product of the two masked dimension values retained from the normalization step.
2. A secondary size obtained by rereading D4 and D8, multiplying them, and applying a signed right shift by two.
3. Another secondary size obtained by another reread, multiplication, and signed right shift by two.

The first request uses unsigned 32-bit operands in the supplied representation. The latter two use signed 32-bit operands and signed-shift semantics in that representation. There is no widening to a 64-bit size and no explicit overflow check.

For ordinary nonnegative dimensions whose product fits in signed 32 bits, the secondary requests are one quarter of the corresponding product. Since normalized dimensions are multiples of eight, that division has no remainder in this range.

The two secondary request sizes must not be assumed equal unconditionally: dimensions are reread after intervening dependency calls. The function contains no protection against those dependencies changing reachable state.

None of the three returned buffer values is checked for failure.

### Producer invocation

4. A5.
5. Primary reference buffer value.
6. First secondary reference buffer value.
7. Second secondary reference buffer value.

The final two arguments are loaded from the record for this call rather than guaranteed to equal earlier allocation operands.

A nonzero producer result sets the function’s return value to `0xfffffffa` and skips the second traversal. The reference dimensions remain modified. The three reference buffer values are still passed to the release dependency, and the traversal context is finalized.

A zero producer result enters the second traversal.

### Second traversal and per-record preparation

The function calls F-d21c4d658cde on the traversal context with `0xfffffffe`, then repeatedly obtains records through F-6e4651b532dc until it returns zero.

There is no second-pass check of the field at `0x2c`. The code also does not establish that this pass yields precisely the first pass’s records or order.

For each yielded record, the function requests three buffers through F-638beded7699, always with second argument zero:

1. The current D8 × D4 product.
2. A freshly evaluated D8 × D4 product, signed-right-shifted by two.
3. Another freshly evaluated product, signed-right-shifted by two.

These requests occur **before** this record’s dimensions are normalized for this iteration. Each request rereads the fields after preceding dependency calls.

The function then:

1. Reads D8, clears its low three bits, and writes it back.
2. Reads D4, clears its low three bits, and writes it back.

## Side effects

### Record mutation

Reference dimensions are normalized before reference buffer requests and producer invocation. Every second-pass record is normalized after its per-record requests.

These writes are not transactional:

- Producer failure does not restore the reference dimensions.
- An unsupported discriminator does not prevent normalization or transformation.
- No rollback is shown for later failures.
- A record may be normalized more than once if traversal yields it repeatedly.

No direct write to `0x20`, `0x2c`, or `0x30` is shown.

### Memory and lifetime

The function requests three reference buffers and, for each second-pass iteration, three more buffers. It explicitly calls the release dependency on the applicable three values after their final visible use.

This establishes call behavior, not a complete ownership model. It does not prove:

- That F-638beded7699 always allocates fresh memory.
- That F-5e3309c9d083 accepts null values.
- That other dependencies do not release or retain buffers.
- That returned values cannot alias one another.
- That transformation leaves release-target slots unchanged.

The traversal context and transformation descriptor are local temporary storage. Their addresses are passed to dependencies; valid retention beyond the enclosing operation is not established.

### Arithmetic and aliasing risks

All dimensions and products shown are 32-bit quantities. Large inputs can exceed representable product ranges. The supplied evidence does not justify treating mathematical products as unbounded integers or silently converting negative dimensions to valid sizes.

Records, buffers, and dependency-accessible state are not shown to be disjoint. Observable behavior therefore includes repeated reads after calls, rather than an assumption that initial values remain stable.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Except where stated otherwise, they assume stable record fields, ordinary successful buffer requests, no descriptor modification, and dependencies that return normally.

1. **Zero collection argument.** With A6 equal to zero, expect `0xfffffffa` and no dependency calls.

2. **Empty traversal.** With nonzero A6 and immediate first-pass exhaustion, expect initialization, one traversal attempt, finalization, and a zero return. Expect no buffer requests.

3. **Required-field rejection.** If a first-pass record has zero at `0x2c`, expect finalization and `0xfffffffa`. No dimension normalization or buffer requests have yet occurred in this invocation.

4. **Strict two-dimension selection.** For valid records encountered with `(D8, D4)` values `(16, 16)`, `(24, 16)`, `(16, 24)`, and `(24, 24)`, only the last replaces the first. Improving one dimension while tying the other is insufficient.

5. **Order-sensitive selection.** With only `(24, 16)` and `(16, 24)`, whichever appears first remains the reference. Neither dominates the other in both dimensions.

6. **Reference rounding.** A selected reference with `(D8, D4) = (19, 27)` becomes `(16, 24)`. Under stable fields, its reference requests are 384, 96, and 96, and the producer receives dimensions 16 and 24.

7. **Per-record allocation precedes rounding.** A second-pass record still holding `(19, 27)` requests sizes 513, 128, and 128 before being changed to `(16, 24)`. Its descriptor uses the normalized dimensions.

8. **Producer rejection.** A nonzero producer result yields `0xfffffffa`, skips traversal reset and all per-record transformations, and still causes the three reference release calls followed by traversal finalization. Reference dimension writes remain.

9. **Unsupported format.** A second-pass record with any discriminator other than `0x0565` or `0x1888` still receives buffer preparation, normalization, transformation, and three release calls. It receives no format-specific call.

10. **Dimensions below eight.** A selected reference with nonnegative dimensions below eight is normalized to zero dimensions. Under stable fields, zero-size requests follow; there is no explicit rejection before the producer call.
