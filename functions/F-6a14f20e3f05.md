## Behavior

### Ordered operations

The established order within the visible body is:

1. Invoke F-e194f3fbdfaa once, without explicit arguments.
2. Use its returned address as the destination origin.
3. Read the referenced four-byte global value and write that value to destination bytes 0–3.
4. Write zero to destination byte 16.
5. Write a four-byte zero to destination bytes 20–23.
6. Return without an explicit result.

The global read occurs after the dependency returns. Consequently, the value used for the first write is not necessarily the value that existed before entry. F-e194f3fbdfaa may change the global before returning.

The body shows no second global read for the clearing operations. Those writes use zero independently of the copied value.

This is the order expressed by the supplied static representation. It does not establish individual machine instructions, hardware transaction boundaries, or cross-thread visibility order.

### Widths and address calculations

The destination is addressed using four-byte elements for the wider accesses. The byte-clearing location is four such elements after the origin, giving offset 16. The final wider write is five such elements after the origin, giving offset 20.

The offset calculations are therefore 4 × 4 = 16 bytes and 5 × 4 = 20 bytes. The final four-byte access covers offsets 20 through 23. These constant calculations do not establish that adding them to an arbitrary returned address is valid.
