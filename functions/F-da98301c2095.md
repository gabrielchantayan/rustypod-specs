# F-da98301c2095

## Purpose

Three selector values receive dedicated results:

- 107 selects slot A.
- 108 selects slot B.
- 109 selects slot C.

Every other selector returns the value obtained from slot D.

This selection behavior is established by the supplied static representation. The semantic meaning of the selectors and stored values is unknown. In particular, the evidence does not establish that the results are addresses, status codes, handles, or enumeration members.

The read sequence is also significant: the represented path for selector 109 reads slot D before reading slot C, even though the value obtained from slot D is not returned.

## Behavior

### Selection and represented read order

The function first distinguishes selector 107. If that comparison succeeds, it reads slot A and returns the value obtained from that read. The represented path does not read slots B, C, or D.

If the selector is not 107, the function distinguishes selector 108. If that comparison succeeds, it reads slot B and returns the value obtained from that read. The represented path does not read slots A, C, or D.

For every selector other than 107 and 108, the function reads slot D before resolving the remaining special case.

- If the selector is 109, it subsequently reads slot C and returns the value obtained from slot C. The earlier value obtained from slot D is discarded.
- If the selector is not 109, it returns the value already obtained from slot D.

Accordingly, the represented paths are:

| Selector | Ordered slot reads | Returned value |
|---|---|---|
| 107 | A | Value read from A |
| 108 | B | Value read from B |
| 109 | D, then C | Value read from C |
| Any other value | D | Value read from D |

Each listed slot is read once in the supplied representation. No retry, loop, second lookup, or cache is shown.

This table describes the ordering supported by the supplied representation. Whether each represented read corresponds to a distinct externally observable machine access is unknown. The evidence does not establish volatile access, memory-mapped I/O, compiler transformation constraints, or the fidelity of the representation to the executable.

### Fallback behavior
