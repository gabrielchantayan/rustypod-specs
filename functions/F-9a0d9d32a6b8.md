## Behavior

Before testing whether initialization data is null, the function reads:

1. A 32-bit global default value.
2. A global fallback-data pointer.

With non-null initialization data, it retains the caller-supplied address and skips both fallback-specific destination writes. The early global reads still occur.

With null initialization data, it performs these operations before any dependency call:

1. Reads a 32-bit word through the global fallback-pointer expression and writes that word at destination offset 0.
2. Writes the previously captured default value at destination offset 0x8F8.
3. Selects the previously captured fallback pointer as the initialization-data address for subsequent operations.

The offset 0x8F8 is derived from word index 0x23E multiplied by four bytes. These are two separate writes, not initialization of the intervening region.

The fallback source expression uses the global pointer again, whereas the later initialization-data address comes from its earlier capture. Under stable global state they refer to the same storage. The supplied body does not establish an atomic snapshot or synchronized access. If the destination aliases global storage, the first write can also affect state used elsewhere; the captured default and captured fallback pointer remain the values selected earlier.

### 3. Install initialization metadata

The function reads the first initialization word as D, then writes D at H.

Next, it reads a 32-bit displacement at D − 12 and writes the second initialization word at H + Δ.

- The write at H can change the second initialization word before that word is consumed.
- It can change the displacement-storage contents before the displacement is consumed.

The relative evaluation order of the displacement read and second-word read within the displaced-write operation is not established by the supplied expression. No additional ordering between those two reads is required by this contract.
