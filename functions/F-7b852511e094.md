# F-7b852511e094

## Purpose

F-7b852511e094 transfers a requested number of bytes from a source address to a destination address, advancing both addresses toward higher addresses. It returns both resulting end addresses packed into a 64-bit value.

The established behavior is a forward, block-structured transfer with specific read-before-write groupings. It is not an overlap-safe transfer in general. Its observable access order matters when the ranges overlap, when accesses have device side effects, or when an access faults.

The apparent intent is an optimized byte-copy operation. That intent does not establish compatibility with any standard library interface: in particular, the return value contains two advanced addresses rather than simply the original destination address.

## Interface

The supplied representation exposes four inputs:

| Input | Width and interpretation | Role |
|---|---|---|
| Destination | Address of byte-addressable memory; represented as a 32-bit address in the packed result | Start of the destination range |
| Source | Address of byte-addressable memory; represented as a 32-bit address in the packed result | Start of the source range |
| Count | Unsigned 32-bit integer | Number of bytes to transfer |
| Auxiliary value | 32-bit value | Incoming value does not affect the established transfer or result |

The result is 64 bits:

- Bits 31–0 contain the final destination address.
- Bits 63–32 contain the final source address.

On normal completion, assuming address advancement is valid and does not wrap, those addresses are the original destination plus the count and the original source plus the count, respectively. This remains the result for overlapping ranges; overlap can change the transferred data, not the amount of advancement.

For a zero count, the result contains the original addresses, and neither range is accessed.

### Preconditions for an ordinary successful transfer

For nonzero counts:

- Every selected source access must be readable.
- Every selected destination access must be writable.
- Address advancement must be valid in the execution environment.
- The environment must permit the selected 32-bit memory accesses, including their alignment.
- If the required outcome is a copy of the source bytes as they existed on entry, the ranges must not overlap in a way that lets earlier writes affect later reads.

There is no explicit validation of these conditions. Null addresses, alignment failures, protection violations, and address-space exhaustion are not converted into a returned error.

The transfer selects 32-bit accesses even though its endpoints are byte-addressed. No alignment-adjustment phase is established. Byte-only operation occurs when the total count is at most three; larger requests include 32-bit accesses.

## Behavior

### Transfer extent and arithmetic

Let the count be divided into a whole number of 32-byte blocks and a remainder from 0 through 31.

The operation transfers:

1. Every complete 32-byte block, in increasing address order.
2. A 16-byte group if selected by the remainder.
3. An 8-byte group if selected by the remainder.
4. A 4-byte group if selected by the remainder.
5. A final group of zero through three individual bytes.

The selected groups consume exactly the requested count on a normal execution. There is no explicit read or write beyond that extent.

The count calculations are 32-bit unsigned calculations. In particular, the operation subtracts 32 before deciding whether to enter the full-block path and subtracts 32 after each full block. This subtraction wraps rather than becoming a negative unsigned count.

After all full blocks, the internal arithmetic value is the remainder minus 32, reduced modulo \(2^{32}\). Its low five bits still equal the remainder. The tail selection uses those low bits:

- Bit 4 selects 16 bytes.
- Bit 3 selects 8 bytes.
- Bit 2 selects 4 bytes.
- Bits 1 and 0 select the last zero through three bytes.

Consequently, the initial subtraction does not cause a short request to become a huge transfer. For example, a count of zero performs no memory accesses despite the subtraction wrapping.

The signed comparisons appearing in tail selection are sign-bit tests of shifted 32-bit values. They do not interpret the original count as a signed length. Counts with the high bit set remain large unsigned requests.

### Complete 32-byte blocks

Each complete block uses two consecutive 16-byte portions. Within a block, offsets below are relative to the current source and destination addresses.

For the first portion, the represented access order is:

1. Read 32 bits at source offset 4.
2. Read 32 bits at source offset 8.
3. Read 32 bits at source offset 12.
4. Read 32 bits at source offset 0.
5. Write the value from source offset 0 to destination offset 0.
6. Write the previously read values to destination offsets 4, 8, and 12, in that order.

For the second portion:

1. Read 32 bits at source offsets 16, 20, 24, and 28, in that order.
2. Write those values to destination offsets 16, 20, 24, and 28, in that order.

Both current addresses then advance by 32 for the next block or tail.

All four source words in the first portion are read before any destination write in that portion. All four source words in the second portion are likewise read before its writes. However, the first portion’s writes occur before the second portion’s reads. A 32-byte block is therefore not captured as one complete snapshot before writing.

### The 16-byte tail group

If selected, this group reads four 32-bit values at current source offsets 0, 4, 8, and 12, in that order. Only after all four reads does it write the corresponding values to destination offsets 0, 4, 8, and 12, in that order.

Both current addresses advance by 16.

Unlike the first half of a complete block, this group reads offset 0 before offsets 4, 8, and 12.

### The 8-byte tail group

If selected, this group reads 32-bit values at current source offsets 0 and 4, then writes them to destination offsets 0 and 4.

Both current addresses advance by 8.

### The 4-byte tail group

If selected, this group reads one 32-bit value from the current source and writes that value to the current destination.

Both current addresses advance by 4.

### The final byte group

The remaining byte count is between zero and three:

| Remaining bytes | Access behavior |
|---|---|
| 0 | No byte accesses |
| 1 | Read one source byte, then write it to the destination |
| 2 | Read two consecutive source bytes, then write both destination bytes in increasing address order |
| 3 | Read three consecutive source bytes, then write all three destination bytes in increasing address order |

All source bytes in this final group are read before any of its destination bytes are written. Both addresses advance by the number of bytes in the group.

For a three-byte tail, the first byte is handled separately from the following pair, but this does not change the established order: three increasing-address reads precede three increasing-address writes.

### Overlapping ranges

The routine does not compare the endpoints or choose a backward direction.

For disjoint ordinary memory ranges, a successful transfer reproduces the source bytes at the destination. For overlapping ranges, values depend on whether an earlier destination write changes a later source location before that location is read.

Read-before-write grouping provides limited overlap tolerance within a group. It does not provide a general overlap guarantee across groups.

When source and destination are identical, the routine still performs its selected reads and writes. It does not skip the transfer. This distinction matters for memory with access side effects.

## Side effects

The directly established external effects are reads from the source range and writes to the destination range.

For ordinary, fault-free memory:

- Each requested source byte participates in exactly one selected read.
- Each requested destination byte participates in exactly one selected write.
- No selected access extends outside the requested ranges.
- No other memory location is explicitly accessed.

A 32-bit load and store transfers a word value without explicit byte swapping. When both addresses use the same ordinary memory interpretation, the corresponding four bytes are preserved.

The operation does not allocate memory, release memory, transfer ownership, or retain an address for later use. The caller remains responsible for the lifetime and accessibility of both ranges.

No explicit global-state access, synchronization, memory barrier, callback, or external function invocation is present. This does not establish that accesses are atomic or that concurrent observers see a coherent snapshot. Concurrent modification of the ranges is outside the established deterministic contract.

The incoming auxiliary value is overwritten on some paths and otherwise has no externally visible use. It is not an error code, transfer limit, or ownership flag in the established behavior.

### Failures and partial completion

No explicit error return exists. A normal result does not separately report success or the number of bytes copied.

If a selected access fails, the execution environment determines the resulting exception or fault behavior. Earlier writes may already have occurred. There is no rollback.

The read-before-write groups constrain partial effects. For example, a failure during one of the four source reads in a 16-byte tail group occurs before any destination write for that group. Conversely, a failure during a later group does not undo completed earlier groups.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Unless stated otherwise, assume stable ordinary memory, permitted alignment, valid ranges, no address wrap, and successful accesses.

### Zero count

Given any source and destination address values and a count of zero:

- No source or destination memory is accessed.
- The low result half contains the original destination.
- The high result half contains the original source.
- Changing the auxiliary input does not change this behavior.

This does not require the addresses to identify readable or writable memory, because the operation performs no dereference.

### Three bytes

Given source bytes `21`, `43`, and `65`, expressed in hexadecimal, and a disjoint writable destination:

- The three source bytes are read in increasing address order.
- All three reads occur before the first write.
- The destination receives `21`, `43`, and `65`.
- Both returned addresses are advanced by three.

### Thirty-one bytes

For a count of 31, the operation selects groups of 16, 8, 4, and 3 bytes, in that order.

There is no complete 32-byte block and no access to a thirty-second byte. The final addresses are each advanced by 31.

### Thirty-two bytes

For a count of 32, exactly one complete block is transferred, with no tail.

The first source word accessed is the word at offset 4, not the word at offset 0. The first destination word written is at offset 0. Both returned addresses are advanced by 32.

### Safe small overlap within one group

Given a count of three and a destination starting one byte above the source, the operation reads all three original source bytes before writing any destination byte.

The destination therefore receives the original three-byte sequence, assuming ordinary memory. This example does not imply general overlap safety.

### Overlap across groups

Given a count of 32 and a destination starting 16 bytes above the source:

- The first 16-byte portion reads the original source offsets 0 through 15.
- Its writes replace source offsets 16 through 31.
- The second portion subsequently reads those replaced bytes.
- The destination’s second 16-byte portion consequently repeats the original first 16-byte portion.

This is not the result of snapshotting all 32 original source bytes before writing.

### Fault during a grouped read

Given a count of 16 and a fault on the source read at offset 8:

- Reads at offsets 0 and 4 precede the fault.
- No destination write for that group has yet occurred.
- No normal packed result is established.

The actual fault delivery mechanism remains environment-dependent.
