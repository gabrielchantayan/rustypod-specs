# F-d1618a742f22

## Purpose

F-d1618a742f22 resolves an indexed item into a caller-supplied, two-field result. Its observable behavior depends on whether an associated context contains a nonzero lookup-table pointer:

- With no lookup table, it delegates resolution to F-5ef10d079522, then writes a selector derived from the original object address.
- With a lookup table, it selects a table entry and copies the low 16 bits of that entry’s value into the result.

The function returns a 32-bit status independently of the result fields. The explicit rejection status is `0xffffffce`, equivalent to −50 when interpreted as a signed 32-bit integer. A completed table lookup returns zero. The delegated path returns the status supplied by F-5ef10d079522, even if that status indicates failure.

These are established behaviors of the supplied static representation. The meanings of the indexed items, table values, selector, and status convention are not established.

## Behavior

### Entry and initial validation

The observable order begins as follows:

1. Write zero to the first 16-bit output field.
2. Call F-8ff48652068d with the original object address.
3. Check the output address for null.
4. Interpret the index as signed 32-bit and reject it if negative.
5. If the preceding checks allow execution, call F-1813c89b0386 with the address at object offset `0xe64`.
6. Reject the index if that call returns a count less than or equal to the index, using an unsigned comparison.
7. Read the lookup-table field at offset `0xe50` in the context returned by the first context-resolution call.

The null and signed-index checks short-circuit the initial count call. They do not prevent the preceding output write or context-resolution call.

For ordinary, non-aliasing storage and dependencies that do not modify the output, an initial validation rejection leaves the first field zero and does not locally write the second field. Dependency effects are not constrained by the supplied evidence.

### Delegated path

A zero value in the first context’s lookup-table field selects this path.

The function:

1. Writes zero to the first output field again.
2. Calls F-8ff48652068d again with the original object address.
3. Repeats the output-address and signed-index checks.
4. Calls F-1813c89b0386 again.
5. Requires the index to be strictly less than the second returned count.
6. Obtains the indexed record’s first 32-bit word.
7. Calls F-5ef10d079522.
8. After that call returns, overwrites the first output field with the object-derived selector.
9. Returns the dependency’s 32-bit status unchanged.

The second context-resolution result, not the first, supplies the pointer at context offset `0xf60`. The implementation does not visibly recheck whether that second context has acquired a lookup table.

The second invocation of F-1813c89b0386 is shown without explicit arguments in the supplied representation. Its intended relationship to the first invocation is plausible but not established. The contract can establish the repeated call and use of its result, not its actual argument list.

- Records are addressed at a stride of 20 bytes.
- Only the first 32-bit word of the selected record is visibly read here.

After F-5ef10d079522 returns, the first output field is written regardless of the returned status. Under the apparent 32-bit machine-shift interpretation, this field contains bits 1 through 16 of the original object-address bit pattern:

This extraction is not a signed division of the object address. Its derivation assumes the displayed shifts represent 32-bit machine operations; the static representation does not establish a portable high-level signed-shift contract.

### Lookup-table path

A nonzero lookup-table field observed after initial validation selects this path.

The function writes `1` to the first output field, then rereads the context’s lookup-table pointer. It rejects with `0xffffffce` if that reread pointer is null. It also contains a check that the address of the second output field is nonnull.

The second-field check occurs after writes through the output pointer and is not a general buffer-validity check.

The pointer reread matters: the function does not preserve the first nonzero table-pointer observation as its working pointer. For example, output/context aliasing could make the intervening marker write relevant. No synchronization or atomic-snapshot guarantee is visible.

#### Table layout

The table is accessed as 32-bit words:

| Word position | Interpretation |
|---|---|
| `0` | Signed search count |
| `2j + 1` | Value associated with entry `j` |
| `2j + 2` | Unsigned threshold associated with entry `j` |

For example, the first entry’s value is at byte offset 4 and its threshold at byte offset 8.

The search can additionally read:

- The threshold following the candidate entry.
- The preceding threshold.
- Word zero as though it were the preceding threshold when the candidate is entry zero.

Consequently, storage containing only the advertised number of ordinary entries may be insufficient. A following threshold or sentinel can be required.

#### Selection rules

The search uses signed 32-bit lower and upper entry bounds. Initially, the lower bound is zero and the upper bound is the table’s signed count minus one.

For a candidate entry:

- If the index equals the candidate threshold, select that candidate.
- If the index exceeds the candidate threshold but is below the following threshold, select that candidate.
- If the index exceeds the candidate threshold and equals the following threshold, select the next entry.
- If the index exceeds both relevant thresholds, continue in the higher range.
- If the index is below the candidate threshold but is at least the preceding threshold, select the preceding entry.
- Otherwise, continue in the lower range.

All threshold comparisons use unsigned 32-bit values.

When the bounds cross, the function selects the most recently computed candidate. Before any candidate has been computed, that retained candidate is entry zero.

Selection completes by writing the low 16 bits of the selected entry’s 32-bit value to the second output field and returning zero. The upper 16 bits are discarded, without range checking or saturation.

For suitably ordered thresholds and adequate sentinel storage, these operations resemble selection of a threshold interval. Sortedness, sentinel conventions, and interval coverage are not validated locally.

### Arithmetic and malformed tables

The search count and bounds are signed 32-bit quantities. The visible midpoint uses the sum of the bounds followed by a right shift. No overflow guard is visible for either count-minus-one or the bound sum.

A zero count does not produce an empty-table error: the initial bounds are already crossed, so entry zero’s value is read and returned. Negative counts other than the minimum signed value likewise lead directly to that read under the displayed arithmetic. The minimum signed count makes the subtraction overflow under ordinary signed arithmetic; its outcome is not established here.

The delegated record displacement uses a 32-bit unsigned index multiplied by 20. Large validated indices can exceed a nonwrapping 32-bit byte displacement. The initial count check alone does not prove a valid record address.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Unless stated otherwise, assume valid, non-aliasing storage, normally returning dependencies, and no dependency mutation of relevant storage.

1. **Index with its high bit set.**  
   For index `0x80000000`, the function first writes zero to the first field and calls F-8ff48652068d. It then returns `0xffffffce` without the initial count call.

2. **Index equal to the initial count.**  
   If the count call returns 7 and the index is 7, the function returns `0xffffffce`. It does not inspect the context’s table field after that rejection.

3. **Successful delegation.**  
   Suppose both counts admit index 2, the first context has no table, and F-5ef10d079522 returns `0x12345678`. The returned status is exactly `0x12345678`. After the call, the first field receives the selector derived from the original object address.

4. **Delegated error still updates the selector.**  
   If F-5ef10d079522 returns `0xffffffce`, the caller still receives that status and the function still performs its final selector write.

5. **Second count becomes smaller.**  
   If the first count admits index 4 but the repeated count is 4, delegated resolution is not called. The local return is `0xffffffce`.

6. **Threshold interval.**  
   For a valid one-entry search table with current threshold 10, following sentinel threshold 20, value `0x12345678`, and index 15 admitted by initial validation, the table path writes first field `1`, second field `0x5678`, and returns zero.

7. **Exact following threshold.**  
   If the search examines an entry with threshold 10 and following threshold 20, index 20 selects the following entry, provided the relevant storage exists.

8. **Zero table count.**  
   If initial validation admits the index but the table count is zero, the function nevertheless copies the low 16 bits of the word at table byte offset 4 and returns zero. It does not report an empty-table error.

9. **Null output.**  
   No clean rejection is promised. The entry write precedes the null check, so a memory fault or other platform-dependent consequence can occur first.
