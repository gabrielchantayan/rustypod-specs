# F-96dc131ff7b6

## Purpose

F-96dc131ff7b6 conditionally writes a one-byte marker into a caller-supplied object and returns the 32-bit value 1 on every normally completed path.

The marker write depends on two decisions:

1. Whether a dependency returns a nonzero result for a constructed value and a previously captured global value.
2. If that result is nonzero, whether another dependency’s result differs from a 32-bit field in the supplied object.

The function does not directly clear the marker when either condition fails. Its return value does not indicate whether the marker was written.

**Inferred intent:** The marker may indicate that an eligible object differs from some current external state. The meanings of eligibility, the compared state, and the marker are not established by the supplied evidence.

## Interface

### Input

The function accepts one argument, treated as the base address of an object. The visible operations use two locations relative to that base:

| Offset from base | Width | Visible role |
|---|---:|---|
| 0xD5, decimal 213 | 1 byte | Conditionally receives the value 1 |
| 0xD8, decimal 216 | 4 bytes | Read for comparison with a dependency result |

These locations do not overlap. The function contains no direct access to the bytes between them.

The supplied representation expresses the argument as an integer and subsequently uses it as an address. The behavioral requirement is therefore an address usable for the conditional accesses above, rather than an ordinary numeric identifier.

No object type, allocation size, ownership descriptor, or explicit length is supplied.

### Output

The visible return is a four-byte value equal to 1. This return occurs after all applicable dependency calls and after any marker write.

The return is constant across normally completed paths, including paths that:

- Skip the object-field comparison.
- Find equal comparison values.
- Write the marker.

It is not a success/failure distinction for those outcomes.

### Preconditions and validity

There is no visible null check, bounds check, address-overflow check, or alignment check.

For an execution that reaches the field comparison, the four bytes beginning at base + 0xD8 must be readable. For an execution that reaches the marker write, the byte at base + 0xD5 must be writable.

These are path-dependent access requirements. If the earlier decision result is zero, this function performs neither direct object access. That fact does not establish that an invalid base is supported by the surrounding interface.

The evidence does not define the outcome of inaccessible memory, invalid address arithmetic, unsupported alignment, or a dependency that does not return normally.

## Behavior

3. Call F-938c950e5046 with no visible arguments and retain its four-byte result.
4. Read a value from a second global storage location and call F-9e50c66a96dd with two arguments:
   - The result from F-938c950e5046.

5. Call F-682adfd5a561 with two arguments:
   - The result from F-9e50c66a96dd.

The first four dependency calls are unconditional within the visible body, subject to earlier calls returning normally.

The timing of the two global reads matters. The first occurs after F-44874cacba18 returns but before F-938c950e5046 runs. The second occurs after F-938c950e5046 returns and before F-9e50c66a96dd is invoked.

Consequently, a dependency’s modification of global storage can affect these inputs according to when the modification occurs. In particular:

- A change made by F-44874cacba18 can affect either later global read.
- A change made by F-938c950e5046 can affect the second global read.
- Changing the first global location after its value has been captured does not, by itself, replace the retained value used as the second argument to F-682adfd5a561.

No assumption is made that any dependency preserves either global location.

### Decision and conditional comparison

The result from F-682adfd5a561 is tested against zero.

If it is zero:

- F-eadf6abacb1d is not called.
- The field at base + 0xD8 is not directly read.
- The marker at base + 0xD5 is not directly written.
- The function proceeds to return 1.

If it is nonzero:

- F-eadf6abacb1d is called with no visible arguments.
- After that call returns, the four-byte field at base + 0xD8 is read.
- The dependency result is compared with that field.

The field read follows the dependency call. A modification to that field during F-eadf6abacb1d can therefore affect the comparison. This contract does not substitute a field value captured before that call.

The visible comparison is inequality. It is not a range, ordering, or magnitude test. Positive and negative nonzero decision results both select the comparison path.

### Conditional marker write

If the result from F-eadf6abacb1d differs from the four-byte object field, the function stores the one-byte value 1 at base + 0xD5.

If the values are equal, the function makes no direct marker write.

The marker’s previous value is not read before the store. Therefore:

- A previous value of 0 becomes 1 on the write path.
- A previous value of 1 is still subject to the store of 1.
- Any other previous byte value becomes 1 on the write path.
- On a path without the store, the function does not directly normalize, clear, or otherwise update that byte.

“No direct write” does not mean the byte is guaranteed unchanged across the whole invocation. Dependencies may have effects not established by this function’s body.

## Acceptance examples

The following are conditional acceptance cases, not observed runtime results. Each assumes normal dependency returns and valid memory for all reached accesses.

### Zero decision result

Suppose F-682adfd5a561 returns 0.

Expected behavior:

- The four unconditional dependency calls occur in the stated order.
- F-eadf6abacb1d is not called.
- Neither object location is directly accessed.
- The function returns 1.

This holds regardless of what comparison value F-eadf6abacb1d might otherwise have produced.

### Nonzero decision and equal values

Suppose F-682adfd5a561 returns −1, F-eadf6abacb1d returns 37, and the field read after that call contains 37.

Expected behavior:

- The nonzero result selects the comparison path.
- The field is read after F-eadf6abacb1d returns.
- No direct marker store occurs.
- The function returns 1.

The decision result need not equal 1.

### Nonzero decision and unequal values

Suppose the decision result is 2, the later dependency returns 37, and the field contains 38 when read.

Expected behavior:

- One byte with value 1 is stored at base + 0xD5.
- This function makes no direct write to the field at base + 0xD8.
- The function returns 1.

### Marker already set

Suppose the comparison values differ and the marker already contains 1.

Expected behavior: the store of 1 still occurs. There is no marker-value guard that eliminates it.

### Field changed during the final dependency

Suppose the field contains 10 before F-eadf6abacb1d, that dependency changes it to 20, and the dependency returns 20.

Expected behavior: the later read obtains 20, so this function does not directly write the marker. This case is conditional on the stated dependency effect; that effect is not independently established.

### First global changed after capture

Suppose the first global contains 7 when captured, and F-938c950e5046 subsequently changes that global to 9.

Expected behavior: F-682adfd5a561 receives the retained value 7 as its second argument. The later global contents do not replace the captured value.
