# F-3643422b0298

## Purpose

F-3643422b0298 delegates an initial operation, inspects selector bits in a caller-supplied object, and conditionally invokes a second dependency against an interior region of that object. It returns a 32-bit status and, on selected paths, updates either a classification field or a fallback field.

The established behavior is a decision process with three possible successful classifications in one selector branch and one possible successful classification in another. An unsuccessful initial operation returns immediately. A completed initial operation with neither selector bit set produces a separate immediate result. Exhausting the applicable classification attempts stores a previously captured global value and returns a fallback result.

“Selector,” “classification,” and “fallback” describe the roles visible in this function. Their application-level meanings are inferred intent, not established semantics. In particular, the dependency used for classification is not established to be a string comparison, lookup, validator, or parser.

### Output

The return value is a 32-bit quantity. The directly established return values are:

- **3:** F-12fc53a42084 did not return exactly 11.
- **10:** The initial operation returned 11, but both relevant selector checks were clear.
- **5:** The first classification attempt in the 0x10 branch returned nonzero.
- **6:** The second classification attempt in that branch returned nonzero.
- **7:** The third classification attempt in that branch returned nonzero.
- **9:** The classification attempt in the 0x20 branch returned nonzero.
- **13:** All classification attempts in the selected branch returned zero; the fallback field was written.

These descriptions specify return-path conditions, not application-level success or failure meanings.

## Behavior

### Initial dependency and global capture

The first action is a call to F-12fc53a42084 with these arguments, in this order:

1. The supplied object address.
2. The address at object offset +0x1C.
3. The supplied auxiliary 32-bit value.

After that dependency returns, the function reads a 32-bit global value and retains it for possible use in the fallback write. This contract calls that global the **fallback source**.

The fallback-source read occurs after the initial dependency returns and before the initial result is rejected or selector bits are examined. Consequently:

- Changes the initial dependency makes to the fallback source can affect the captured value.
- The fallback source is read even when the initial result is not 11.
- Changes made to that source by later classification calls do not replace the already captured value.

If the initial dependency’s result is anything other than exactly 11, the function returns 3. It performs no direct object-field write on this path. Any effects already produced by the dependency remain outside that statement.

### Branch selection

If the initial result is 11, the function reads the 32-bit field at +0x28 and tests bit 0x10.

- If bit 0x10 is set, it selects the three-attempt branch.
- If bit 0x10 is clear, it reads the field again and tests bit 0x20.
  - If bit 0x20 is clear, it returns 10.
  - If bit 0x20 is set, it selects the single-attempt branch.

The second selector test is reached only when the first test is clear. It is a separate field access in the supplied representation; this contract does not replace the two accesses with a guaranteed single snapshot.

When both selector bits are set in a stable field value, the 0x10 branch takes precedence. The function does not attempt the 0x20 classification after entering the 0x10 branch, even if all three attempts fail.

Once a branch has been selected, the function does not reconsider that selection after a dependency call. A dependency’s changes to the selector bits can affect a later field update, but do not redirect the remaining classification sequence.

### Three-attempt branch

This branch invokes F-efdae002d289 up to three times. Each call receives:

1. A value read from a distinct global argument source.
2. The address at object offset +0x1C.

For this contract, those global sources are **candidate A**, **candidate B**, and **candidate C**, in attempt order. Their types, contents, and meanings beyond their use as call arguments are unknown.

The attempts are ordered and short-circuiting:

| Attempt | Global argument source | If dependency returns nonzero |
|---|---|---|
| First | Candidate A | Update +0x28 with classification bit 0x40; return 5. |
| Second | Candidate B | Update +0x28 with classification bit 0x80; return 6. |
| Third | Candidate C | Update +0x28 with classification bit 0x100; return 7. |

A later attempt occurs only if every earlier attempt returned zero. Any nonzero result qualifies, regardless of sign or magnitude.

Each candidate argument is obtained for its own reached call. The function does not establish a snapshot of all candidate sources before the first classification call. Earlier dependencies therefore cannot be assumed to leave later argument sources unchanged.

If all three calls return zero, execution proceeds to the fallback write.

### Single-attempt branch

This branch calls F-efdae002d289 once with:

1. A value read from a fourth global argument source, called **candidate D**.
2. The address at object offset +0x1C.

A nonzero result causes a classification-field update using bit 0x400 and a return value of 9. A zero result proceeds to the fallback write.

### Classification-field update

Every successful classification directly reads the current 32-bit field at +0x28, applies the 32-bit mask 0xFFFF000F, inserts the selected classification bit, and writes the resulting 32-bit value back to the same field.

The update has these exact bit effects:

- Bits 0–3 are preserved.
- Bits 4–15 are cleared, except for the selected classification bit.
- Bits 16–31 are preserved.

The selected bit is one of 0x40, 0x80, 0x100, or 0x400, according to the successful attempt.

Both selector bits, 0x10 and 0x20, are cleared by every successful classification update. Any previous classification bits within bits 4–15 are also cleared before the selected bit is inserted.

The preservation applies to the field value read **after the successful dependency returns**, not necessarily to the value used during branch selection. A dependency may have changed the field in between.

### Fallback write

If the selected branch exhausts its classification calls with zero results, the function writes the previously captured 32-bit fallback-source value to object offset +0x38 and returns 13.

This path does not directly update +0x28. It does not restore any field or global state changed by dependencies.

The fallback write is not reached when the initial result is rejected, when neither selector is present, or when a classification succeeds.

## Side effects

The function’s direct object writes are limited to:

- One 32-bit write at +0x28 on a successful classification path; or
- One 32-bit write at +0x38 on a fallback path.

Those direct writes are mutually exclusive in a normally completed invocation. Some paths perform neither.

The function directly reads the fallback source after the initial call, reads selector fields as required, reads candidate argument sources only for reached attempts, and rereads +0x28 when applying a classification update.

These are source-level sequencing observations, not guarantees about atomicity, physical memory transactions, compiler treatment of nonvolatile storage, or concurrent access safety.

No direct allocation, release, ownership transfer, logging, or external I/O is visible. This does not establish that the dependencies lack those effects. In particular:

- Dependencies receive object-related addresses and may mutate accessible state.
- No dependency is established to preserve global values.
- No dependency is established to preserve the object’s storage or lifetime.
- Ownership and release behavior are documented_only unknowns.

If a dependency invalidates storage required by a later access, the visible function provides no recovery mechanism.
