# F-1f8f230512ab

## Purpose

F-1f8f230512ab repeatedly invokes unresolved indirect targets, transforms their results, reads selected memory locations, and performs ordered byte and 32-bit writes. The represented body has no normal return and no explicit error result.

The established behavior is state mutation and dependency invocation. No application-level purpose is established. Interpreting the accesses as initialization, serialization, allocation, or device configuration would require evidence not supplied here.

This contract distinguishes the represented operations from conclusions that depend on a 32-bit arithmetic interpretation. It does not establish that the recovered interface completely describes the executable calling convention.

## Interface

### Explicit inputs and output

The represented interface has four 32-bit arguments:

| Argument position | Visible role |
|---|---|
| First | No visible use. |
| Second | Supplied to the first indirect invocation. Its working value is replaced near the iteration boundary by a dependency result shifted left by two. |
| Third | No visible use. |
| Fourth | Its low eight bits are captured at iteration entry for two subsequent byte writes. Its working value is set to zero late in the first iteration. |

No returned value or successful termination path is represented. The unused arguments remain part of the represented interface; their lack of visible use does not establish that callers may omit them.

### Widths, addressing, and preconditions

Byte reads produce unsigned eight-bit values. Byte writes retain the low eight bits of their supplied values. Explicit word accesses are 32 bits wide. Several results are represented as 64-bit quantities whose low and high 32-bit halves are used separately.

Unsigned right shifts are logical. Arithmetic descriptions below use 32-bit bit-vector interpretation for left shifts, multiplication, and computed addresses: only the low 32 bits survive. This is an interpretation of the represented width-sensitive dataflow, not independent verification of target overflow or pointer semantics.

Consequences include:

- A left shift by 28 retains only the original low four bits.
- A left shift by 30 retains only the original low two bits.
- Masking to 30 bits, shifting right by 20, and storing a byte selects original bits 20–27.
- Shifting right by 22 and storing a byte selects original bits 22–29.
- Adding 17 to an unsigned selector byte produces an absolute address from 17 through 272, not a displacement from the iteration’s memory base.
- Adding 20 to a saved selector produces a word address from 20 through 275, potentially unaligned.

Successful progress requires each encountered target to be callable and return, and each encountered access to complete. These conditions are not checked by the represented body. Alignment requirements, endianness, memory mappings, and fault handling remain unresolved.

## Behavior

### Execution and ordering

The body repeats unconditionally. If all calls return and all accesses complete, another iteration begins instead of a return.

The ordering below is observable ordering in the supplied representation. Calls omitted from a phase description as “intervening calls” still occur; that phrase does not authorize their removal or reordering. Calls with no displayed arguments also remain semantically unknown.

Selectors are read afresh whenever specified. A dependency may change a selector, a global, or another later-read location. A saved selector or saved result instead denotes the value already captured in the represented dataflow. This distinction does not establish any general dependency preservation guarantee.

### Initial calls and base-relative byte writes

At iteration entry, the low byte of the fourth working argument is captured before any call.

The first indirect invocation receives the second working argument and uses a target derived from the entry control-address state. The next call produces a result that is forwarded to a subsequent invocation. Further calls produce the result used for the next argument transformation.

The captured byte is then written, in order:

1. At entry base plus 17.
2. At entry base plus 1.

The preceding dependency result, shifted left by two, is passed to the next invocation. Intervening dependencies therefore run before these stores, not after an assumed initialization barrier.

### First indexed word, address-derived read, and zero word

Further calls produce the **first word index**. A 32-bit store writes the entry shift source shifted left by 28 at:

**16 × first word index + 20.**

Immediately afterward, a 32-bit word is read at:

**(entry address source logically shifted right by 22) + 20.**

This read address is between 20 and 1043 inclusive and need not be aligned.

A dependency receives four times the first word index. A later result is retained as the **saved word value**. The previously read word is shifted right by 22 and then left by 28 for another dependency argument. Only original bits 22–25 can survive that transformation under the stated width interpretation.

Further calls produce a **zero-word index**. Zero is written as a 32-bit word at four times that index plus 20. The next invocation receives four times that index.

### Packed-byte writes and a saved-selector word write

A later result becomes the **packed value**. The byte at entry base plus 1 is read as a selector. At selector plus 17, the function writes the low byte of the packed value shifted left by two.

A dependency then receives the packed value shifted left by two. Another result is forwarded together with the packed value shifted left by 30 to a two-argument invocation.

After further calls:

- Entry base plus 1 is read again, and this selector is saved.
- At saved selector plus 17, a byte is written from the packed value masked to 30 bits and shifted right by 20.
- A newly obtained result shifted left by two is passed to a dependency.
- After intervening calls, the saved word value shifted left by two is written as a 32-bit word at saved selector plus 20.

The latter byte and word writes use the same saved selector. An intervening change to entry base plus 1 does not, by itself, retarget the word write.

The global word is then read once and saved. A dependency receives four times the first word index before the next paired result is obtained. The global snapshot therefore precedes that call sequence.

### First paired result and first replicated word

A represented 64-bit result supplies the **first scaled result**: its low 32 bits shifted left by two.

The function rereads the selector at entry base plus 1 and writes, at selector plus 17, the low byte of the saved global word shifted right by 22. It then passes the paired result’s high 32 bits to a dependency.

A later result is forwarded together with the first scaled result shifted left by 28. After further calls, entry base plus 1 is reread and zero is written at the selected address plus 17.

Subsequent calls include:

- An invocation receiving a newly obtained result shifted left by two.
- Later, a two-argument invocation receiving two copies of another result shifted left by two.

Neither invocation establishes the value eventually replicated. A still later result shifted left by two becomes the **first replicated word**.

That word is stored at:

1. First scaled result multiplied by 4096, plus 20.
2. Four times a later dependency result, plus 20.

Between the stores, a dependency receives the first scaled result shifted left by 14, followed by further calls. After the second store, an invocation receives four times its destination index.

The two stores have equal supplied values but independently computed destinations. No common object or ownership relationship is established.

### Second paired result and selector clearing

A later represented 64-bit result supplies the **second scaled result**, again its low 32 bits shifted left by two.

Before its high half is passed onward, the function reads a selector at:

**first scaled result × 16384 + 1.**

At selector plus 17, it writes the low byte of the first replicated word masked to 30 bits and shifted right by 20.

The high half of the paired result is then passed to a dependency. A subsequent result is forwarded to another invocation. A further represented 64-bit result has its low and high halves forwarded as two arguments, in that order.

After additional calls, a selector is read at:

**second scaled result × \(2^{28}\) + 1.**

Zero is written at selector plus 17.

Following an invocation supplied with another result shifted left by two and further calls, a result is retained as the **second replication source**. The function reads a selector at four times the second scaled result plus 1 and writes zero at selector plus 17.

A dependency receives the second scaled result shifted left by ten. A later invocation receives a forwarded result followed by the saved word value shifted left by 28.

After more calls, the selector at four times the second scaled result plus 1 is read again, and zero is again written through it. These are distinct reads and writes separated by dependencies; they cannot be collapsed on the available evidence.

### Second replicated word and final packed-byte update

The **second replicated word** is the second replication source shifted left by 14. It is stored at:

1. The second replication source shifted left by two, multiplied by 4096, plus 20.
2. Four times a later dependency result, plus 20.

Between the stores, one invocation receives the second replication source shifted left by 16. After another call, a two-argument invocation receives:

- The second replicated word shifted left by 28.
- An additional 32-bit value from an unresolved result channel.

Under 32-bit bit-vector arithmetic, the first argument is zero because the second replicated word already has its low 14 bits cleared. This does not determine the second argument.

After the second word store, a dependency receives four times that store’s destination index. Further calls produce the **third word index**.

The selector at four times the second scaled result plus 1 is reread. At selector plus 17, the function writes the low byte of the second replicated word masked to 30 bits and shifted right by 20.

A dependency then receives the second replication source shifted left by 26. Another result is forwarded together with the third word index shifted left by 30. A later represented 64-bit result is forwarded as low-half and high-half arguments.

Following further calls, the same selector location is read afresh, and zero is written at the newly selected address plus 17.

### Third propagated word and four-argument invocation

A subsequent result shifted left by two becomes the **third propagated word**. It is stored at:

**third word index × 16384 + 20.**

The following four-argument invocation receives, in order:

1. Third word index shifted left by 12.
2. Third word index shifted left by 12.
3. Third word index shifted left by 14.
4. Third propagated word.

The third argument is not a third copy of either preceding argument.

After intervening calls produce another destination index, the third propagated word is stored at four times that index plus 20. The next invocation receives four times that index.

### Final propagation stages and iteration boundary

Two further stages each obtain a result and form a propagated word equal to four times that result. Each stage:

- Writes that word at 16 times the same result plus 20.
- Invokes a dependency with three copies of the propagated word.
- Obtains another destination index through further calls.
- Writes the propagated word at four times that destination index plus 20.
- Invokes a dependency with four times that destination index.

During the first stage, the fourth working argument is set to zero after its first word write and before its three-argument invocation.

During the second stage, after its first word write, the new entry base becomes that stage’s self-indexing result multiplied by \(2^{30}\). Under 32-bit bit-vector arithmetic, this base has only four possible values: zero, \(2^{30}\), \(2^{31}\), or \(3\times2^{30}\).

Further calls produce the final result for the iteration. The next iteration’s state is formed as follows:

- Second working argument: final result shifted left by two.
- Entry shift source: the destination index used for the last word store, shifted left by three.
- Entry address source: the new second working argument.
- Entry control-address state: a fixed represented control location.
- Fourth working argument: zero.

Before repeating, zero is written at the new entry base plus 17 and then at the new entry base plus 1. The next iteration still executes its initial calls before performing its own two base-relative byte writes.

## Side effects

Directly represented effects include byte writes, 32-bit writes, selector-byte reads, an address-derived word read, one global-word snapshot per iteration, indirect invocations, and updates to loop-carried working state.

Dependencies occur between many writes. These operations are not an atomic transaction, and intermediate state may be observed or changed by dependencies.

No explicit rollback, allocation, release, reference-count operation, ownership transfer, synchronization, or cleanup is identifiable in this body. No corresponding absence is established for dependencies.

If execution stops partway through, earlier completed operations occurred. Their resulting memory state need not persist: an intervening dependency or external handler may overwrite or reverse earlier effects. The represented body itself supplies no explicit rollback path.

Aliasing is not excluded among computed destinations, selector locations, the global word, and dependency-managed memory. An earlier write may therefore affect a later read where the actual addresses overlap.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Address and shift calculations use the stated 32-bit interpretation.

1. **Initial truncation and ordering.** With fourth argument `0x123456AB`, successful initial calls are followed by a byte write of `0xAB` at entry base plus 17, then another at entry base plus 1.

2. **Absolute selector destination.** A selector value of `0xFE` selects address 271 for a byte write. The entry base is not added again.

3. **Saved selector.** A saved selector of 7 selects address 24 for its packed-byte write and address 27 for the later saved-word write. Merely changing the selector memory between those operations does not retarget the saved-word write.

4. **Fresh selector reads.** If two separate selector reads return 3 and 9, their respective byte writes target addresses 20 and 26. Intervening dependencies prevent assuming the second read repeats the first value.

5. **High-nibble isolation.** An entry shift source of `0x1234567A` supplies `0xA0000000` to the first indexed word store.

6. **Packed-byte extraction.** A packed value of `0x3AB00000`, masked to 30 bits and shifted right by 20, produces `0x3AB`; the byte write retains `0xAB`.

7. **Distinct third argument.** If the third word index is 1 and the third propagated word is `0x24`, the four-argument invocation receives `0x1000`, `0x1000`, `0x4000`, and `0x24`, in that order.

8. **Zero does not resolve its companion.** The second replicated word shifted left by 28 supplies zero to its two-argument invocation. No value is thereby established for the unresolved second argument.

9. **Loop-carried zero.** Completion of the first iteration’s tail includes zero writes at the new base offsets 17 and 1. The next iteration also captures zero from the fourth working argument.

10. **Interrupted progress without persistence guarantees.** If a dependency overwrites an earlier word destination and then does not return, the earlier word store still occurred. Its original value need not remain, and subsequent operations are not guaranteed.
