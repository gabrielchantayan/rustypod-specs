## Behavior

### 1. Initial calls and first captured address

At the start of each iteration, a byte-valued temporary is set to zero.

1. Invoke `F-U01` with two explicit zero arguments. Its target is the current link/control value plus `0xFFE`.
2. Invoke `F-U02`.
3. Invoke `F-U03`.
4. Read the 32-bit contents of global slot A. Retain that value as **address A**.
5. Invoke `F-U04`.
6. Invoke `F-U05`, obtaining a paired result. Call its low word **first low word** and its high word **first high word**.
7. Invoke `F-U06` with:
   - first argument: first low word;
   - second argument: first high word plus first low word, with an explicitly zero byte also included in the displayed sum.
8. Write an 8-bit secondary output associated with `F-U06` to address A plus `0x11`.
9. Invoke `F-U07`.
10. Write an 8-bit zero to address A plus `0x15`.

The load of global slot A occurs before `F-U04`; both byte stores use the captured address. They do not visibly reload the global slot after intervening calls.

### 2. Halfword result and second paired result

1. Invoke `F-U08`.
2. Write its 16-bit result to an address supplied through a secondary output, plus `0x0C`.
3. Invoke `F-U09`, obtaining another paired result:
   - **second low word**;
   - **second high word**.
4. Write a 16-bit zero to second high word plus `0x2C`.
5. Write second low word shifted right logically by 26 bits to frame base plus `0x26C`, using a 32-bit store.

The shifted value is in the range 0 through 63. The high word of the pair is used as an address base; no validity check precedes the halfword store.

### 3. Saved pointer and fixed-location halfword

2. Read a 32-bit pointer from frame base plus `0x320`; retain it as **address B**.
3. Invoke `F-U11`.
4. Invoke `F-U12`.
5. Write second low word shifted left by two bits to address B plus `0x54`, using a 32-bit store.
6. Invoke `F-U13`.
7. Invoke `F-U14`.
8. Invoke `F-U15`.
9. Invoke `F-U16`.
10. Invoke `F-U17`.
11. Read an unsigned 16-bit value from fixed address `0x21C48994`; call it **first index**.
12. Invoke `F-U18`.
13. Read a 32-bit value from frame base plus `0x280` and pass it as the explicit argument to `F-U19`.

The shifted store uses the previously captured second low word, not a newly obtained result. Only its low 32 bits are written.

The fixed-address halfword read occurs after `F-U17` and before `F-U18`. The frame-relative argument read occurs after `F-U18`.

### 4. Breakpoint and continuation-dependent work

Immediately after `F-U19` returns, execute software breakpoint immediate `0x92`.

No ordinary recovery path is visible. All following behavior is conditional on execution continuing after this operation.

If continuation occurs:

1. Scale the 32-bit result of `F-U19` by four through a left shift; retain this as the **scaled result**.
2. Derive the constant `0x21C4` by logically shifting `0x21C48960` right by 18 bits and multiplying by four. Call it the **fixed scaled base**.
3. Read a 32-bit address from first index plus `0x44`; retain it as **record address**.
4. Invoke `F-U20`.
5. Invoke `F-U21`, retaining its 32-bit result.
6. Read a 32-bit value from first index plus `0x04`.
7. Invoke `F-U22` with the result of `F-U21` followed by that freshly read value.
8. Read the 32-bit contents of global slot B; retain it as **address C**.
9. Invoke `F-U23`.
10. Write the low halfword of address C to address C plus scaled result.
11. Invoke `F-U24`.
12. Read a 32-bit address from fixed scaled base plus `0x54`, equivalently fixed address `0x2218`; retain it as **address D**.
13. Invoke `F-U25`, obtaining an address-bearing 32-bit result.
14. Write the 16-bit value `0x21C4` to that result plus `0x04`.
15. Invoke `F-U26`.
16. Invoke `F-U27`.

The write through address C is a 16-bit store of part of the captured address itself. It is not a copy of the contents at that address.

### 5. Final paired result and frame-base transition

After `F-U27`:

1. Read an unsigned 16-bit value from address D plus `0x34`; call it **second index**.
2. Invoke `F-U28`, obtaining:
   - **final low word**;
   - **final high word**.
3. Write final low word to frame base plus `0x258`, using a 32-bit store.
4. Read an unsigned 16-bit value from final high word plus `0x14`; call it **field value**.
5. Derive:
   - **wide offset**: final low word shifted left by six bits;
   - **scaled address**: final high word multiplied by four;
   - **index offset**: second index multiplied by four.
6. Subtract `0xF4` from the frame base.
7. Write final low word to index offset plus `0x74`, using a 32-bit store.

The store at frame base plus `0x258` uses the base before subtraction. The supplied representation does not restore the frame base before looping.

Both second index and field value originate as unsigned 16-bit reads. Thus index offset is between 0 and `0x3FFFC`, and field value is between 0 and `0xFFFF`.

### 6. Final stores and iteration transition

Continue in this order:

1. Invoke `F-U29`.
2. Write field value to record address plus `0x54`, using a 32-bit store.
3. Invoke `F-U30`.
4. Write field value to record address plus `0x64`, using a 32-bit store.
5. Invoke `F-U31`.
6. Write the low halfword of record address to wide offset plus a secondary address-bearing output associated with `F-U31`.
7. Invoke `F-U32`.
8. Invoke `F-U33`.
9. Read one byte from second index plus index offset, equivalently five times second index.
10. Invoke `F-U34`.
11. Write that captured byte to field value plus external offset plus `0x19`.
12. Invoke `F-U35`.
13. Write scaled address to record address plus `0x44`, using a 32-bit store.
14. Invoke `F-U36`.
15. Set the link/control value used by the next iteration to the fixed continuation value shown in the representation.
16. Read a 32-bit value from scaled address plus `0x44`.
17. Invoke `F-U37` with that value as its explicit argument.
18. Begin another iteration.

The two 32-bit stores of field value use the same captured, zero-extended halfword despite the intervening call.

The byte read is also captured before `F-U34`; the subsequent byte store does not visibly reread its source.

The final argument load uses scaled address, not record address. It occurs after the store to record address plus `0x44` and after `F-U36`. Aliasing or dependency side effects can therefore affect what the final load observes.
