# F-08b79cd509bb

## Purpose

F-08b79cd509bb conditionally records a supplied 32-bit value in a caller-provided state region or delegates processing to F-15120226cfd2.

The selection depends on a comparison against one state field and a nonzero test of another. On the recording path, the function stores the supplied value without calling the dependency. On the delegated path, it may first clear the comparison field for the distinguished value `0x52800008`; it then calls the dependency and, if that call returns normally, clears a separate state field.

These are established operations. Descriptions such as “pending value,” “active object,” “release,” or “notification” would assign meanings not established by the supplied evidence.

## Behavior

### Initial decision and recording path

The first direct state operation is a 32-bit read at offset `0x34`. That value is compared with the comparison argument.

Only if they are equal does the function read the 32-bit field at offset `0x4C`. Any nonzero value in that field satisfies the second condition; the test is not restricted to the value one.

If both conditions succeed:

- The function writes the supplied value to the 32-bit field at offset `0x84`.
- It returns without calling F-15120226cfd2.
- It performs no direct write to offsets `0x34` or `0x4C`.

This path takes precedence over the distinguished-value behavior. If the supplied value is `0x52800008`, that value is stored at offset `0x84` just like any other supplied value; the function does not clear offset `0x34`.

A zero supplied value is also stored normally on this path. Thus, a final zero at offset `0x84` alone does not identify which path was taken.

### Delegated path

The delegated path is selected when either:

- The initial value read at offset `0x34` differs from the comparison argument; or
- That initial value matches, but the subsequent read at offset `0x4C` yields zero.

If the initial comparison fails, offset `0x4C` is not read by this function.

Before invoking the dependency, the function handles the supplied value as follows:

- If it is not `0x52800008`, the function performs no further direct access to offset `0x34`.
- If it is `0x52800008`, the function performs a fresh 32-bit read at offset `0x34`.
- If that fresh value equals the comparison argument, the function writes a 32-bit zero at offset `0x34`.
- Otherwise, it leaves that field untouched.

The fresh read is distinct from the initial read. The clearing decision therefore depends on the value observed by the later access, not necessarily the value observed at entry. The function provides no synchronization that would make those observations a single snapshot.

The function then calls F-15120226cfd2 exactly once, with:

1. The comparison argument.
2. The original supplied value.

The dependency does not receive a substituted zero or the value read from offset `0x34`. The state address is not explicitly passed to it.

If the dependency returns normally, the function writes a 32-bit zero at offset `0x84` and returns. This write is unconditional within the normally returning delegated path. It does not depend on any dependency result.

### Ordering guarantees and limits

The established direct ordering is:

- Initial read at `0x34` before the conditional read at `0x4C`.
- Both initial decision reads before any direct write.
- Any distinguished-value read and conditional clear at `0x34` before the dependency call.
- The dependency call before the final clear at `0x84`.

There is no direct write at `0x84` before the dependency call on the delegated path.

These are source-level access-order facts, not guarantees of atomicity, inter-thread visibility, hardware barriers, or a supported concurrent-use model.

## Side effects

### Direct state changes

On the recording path, the sole direct mutation is a four-byte store of the supplied value at offset `0x84`.

On the delegated path, direct mutations are:

- A conditional four-byte zero store at offset `0x34`, limited to the distinguished-value case with a matching fresh read.
- A four-byte zero store at offset `0x84`, after normal return from the dependency.

The function never directly writes offset `0x4C` or any other state location.

If the conditional clear at offset `0x34` occurs, the subsequent dependency call happens after that clear. There is no rollback operation in the visible function.
