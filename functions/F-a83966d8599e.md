# F-a83966d8599e

## Purpose

F-a83966d8599e combines two 32-bit words whose sign, exponent, and fraction fields match the binary32 floating-point representation.

**Inferred intent:** software floating-point addition, using nearest-even rounding for ordinary finite results and discarding subnormal inputs and underflowed results.

**Established limitation:** the supplied static representation does not establish an unconditional IEEE 754 addition contract. It includes explicit subnormal-discard behavior, an unresolved indirect transfer for NaN operands, target-dependent shift expressions, and an unresolved overflow construction. For opposite-sign infinities, it returns the value of a named data object converted to the return type; the object’s declaration and underlying access width are unavailable.

The requirements below distinguish established behavior, inferred arithmetic intent, and behavior that remains **documented_only**.

## Interface

### Inputs

The function accepts two unsigned 32-bit words by value.

| Bits | Width | Interpretation |
|---|---:|---|
| 31 | 1 | Sign |
| 30–23 | 8 | Encoded exponent |
| 22–0 | 23 | Stored fraction |

These fields define the following classifications:

- Exponent zero: zero or subnormal encoding.
- Exponent 1 through 254: normal finite encoding.
- Exponent 255, fraction zero: infinity.
- Exponent 255, fraction nonzero: NaN.

The arguments are not pointers. No input-buffer size, alignment, allocation, or memory-ownership requirement is visible.

The interface supplies no explicit rounding mode, exception-state object, or output pointer.

### Output

A normal return supplies one unsigned 32-bit word. Depending on the selected path, that word is:

- An input word returned unchanged.
- Positive or negative zero.
- A packed finite arithmetic result.
- The value of a named data object converted to the unsigned 32-bit return type.
- A word produced by the unresolved overflow construction.
- The returned word of an unresolved indirect dependency.

The return width does **not** establish the width of the data-object access. Its declared type, signedness, storage width, access width, and any extension associated with obtaining the returned value remain unknown.

There is no separate success indicator or error code. The indirect dependency is not established to return normally.

### Arithmetic widths and preconditions

The visible unsigned working values are 32 bits. Unsigned addition, subtraction, multiplication, and left-shift results are interpreted within that width, subject to the unresolved shift-count semantics described below. Signed tests interpret the high bit as a sign bit. Carry detection applies to addition of two unsigned 32-bit values.

The implementation uses:

- Logical right shifts.
- An explicitly signed right shift.
- A leading-zero count on a 32-bit value.
- Shift-and-combine operations resembling rotation.
- Shift counts restricted to eight bits in some expressions and five bits in another.

No visible input validation rejects any 32-bit argument pattern. This does not establish that every selected dependency or unresolved target operation completes successfully.

## Behavior

### 1. Classification precedes arithmetic

The initial classification separates pairs of normal finite operands from pairs containing an exponent-zero or exponent-255 encoding.

This decision uses the argument values directly. No input-memory dereference is visible.

Special-input handling precedes sign-directed addition or subtraction. Consequently, the ordinary finite arithmetic paths do not determine the handling of zeros, subnormals, infinities, or NaNs.

### 2. Zero and subnormal operands without infinity or NaN

When at least one operand has exponent zero and neither has exponent 255:

1. If the first operand has a nonzero exponent, return the first operand unchanged.
2. Otherwise, if the second operand has a nonzero exponent, return the second operand unchanged.
3. Otherwise, return negative zero only when both complete input words are exactly `0x80000000`.
4. Return positive zero in every other case.

This establishes the following behavior:

- A normal operand paired with a zero or subnormal is returned unchanged.
- The discarded operand’s sign and fraction do not affect that normal result.
- Two subnormal operands produce positive zero, even if their exact mathematical sum would be normal.
- A negative subnormal is not treated identically to exact negative zero for the two-operand zero-sign rule.
- Mixed-sign exact zeros produce positive zero.
- Two exact negative zeros produce negative zero.

“Flush subnormals to zero” is an incomplete description unless accompanied by the exact negative-zero rule.

### 3. NaNs and infinities

When the special-input path includes an exponent-255 operand, classification values with the sign removed are compared against the infinity boundary.

#### At least one NaN

If either operand is a NaN encoding, control transfers indirectly through F-unresolved-01. If that dependency returns a word, the function returns that word.

The representation does not establish:

- Which operand, if either, supplies the result payload.
- Whether a signaling NaN is quieted.
- Whether signs or payloads are preserved.
- Whether a canonical NaN is produced.
- Whether the transfer returns normally.
- Whether exception state or other global state changes.

Those properties remain **documented_only**.

#### No NaN

If neither operand is NaN:

- Exactly one infinity causes that infinity operand to be returned unchanged.
- Two infinities with the same sign cause the first operand to be returned unchanged.
- Two infinities with opposite signs cause the named data object’s value to be returned after conversion to the unsigned 32-bit return type.

For opposite-sign infinities, neither the object’s value nor its declaration is supplied. The representation therefore does not establish a particular returned bit pattern, a 32-bit memory read, or a particular zero-extension or sign-extension operation. A canonical invalid-operation NaN is plausible intent, not an established result.

Infinity handling takes precedence over zero/subnormal handling. An infinity paired with a subnormal returns the infinity unchanged.

### 4. Normal finite operands with equal signs

For two normal finite operands with equal signs, the implementation orders the words by unsigned encoding so the larger encoded magnitude is processed first.

Each significand is reconstructed in a 32-bit working representation:

- The implicit leading one occupies bit 31.
- The 23 stored fraction bits occupy bits 30–8.
- Bits 7–0 provide alignment and rounding space.

The smaller significand is shifted right by the difference between the working exponent fields. Those fields include the sign contribution, but the common sign cancels in their difference.

The aligned significands are added with explicit 32-bit carry detection:

- A carry selects a one-bit renormalization path.
- Without carry, the combined significand remains at the original working scale.

Packing combines the retained significand with the encoded exponent and sign. Rounding decisions inspect a guard bit, lower residual bits, and, on relevant boundary paths, bits discarded while aligning the smaller operand.

The visible exact-boundary correction clears the least significant retained result bit. This supports **inferred nearest-even intent**; it does not resolve target-dependent shifts or the overflow construction.

For ordinary nonexceptional results, the common input sign is retained through encoded arithmetic. No rounding-mode input or rounding-mode read is visible.

The path includes checks against the exponent-255 magnitude boundary. A result reaching that boundary on the checked path enters the dedicated overflow construction.

### 5. Normal finite operands with opposite signs

For opposite-sign normal operands, the operation becomes a magnitude subtraction. The implementation changes one working sign representation and, when necessary, rearranges the operands so the larger magnitude is processed first.

The significands use the same 32-bit layout described above. The aligned smaller significand is subtracted from the larger.

The subsequent behavior depends on the resulting leading bits:

- A result already in the appropriate high-bit range is packed and rounded.
- A result requiring a limited normalization step is shifted and packed using a signed right shift.
- A result requiring further left normalization uses a leading-zero count to adjust the exponent and construct the packed word.
- Exact cancellation and results rejected by the low-exponent checks return positive zero.

The further-normalization path checks that the adjusted exponent remains in the required encoded range. It does not construct a gradual-underflow subnormal result.

For a nonzero ordinary result, the working sign corresponds to the larger-magnitude operand. Exact cancellation returns positive zero regardless of the first operand’s sign.

Subtraction rounding also accounts for discarded alignment bits. At a relevant boundary, zero discarded bits cause the least significant retained bit to be cleared; nonzero discarded bits instead cause a provisional packed result to be decremented. This cannot be replaced by an unconditional increment whenever the guard bit is set.

### 6. Shift-count boundaries

Some alignment and discarded-bit checks use the low eight bits of a shift count. This is not equivalent to reducing all counts modulo 32.

In particular:

- A count of 32 cannot automatically be treated as zero.
- A count greater than 32 cannot automatically be assigned portable expression-language behavior.
- A zero exponent difference can produce a complementary discarded-bit shift count of 32.
- A normalization expression can also contain a complementary shift of 32 when its five-bit count is zero.

For effective counts from 1 through 31, the visible operations support the ordinary alignment description. Exact behavior for zero, 32, and larger effective counts requires target instruction semantics not established by the supplied representation.

These boundaries remain **documented_only**. They are not permission to choose an arbitrary shift policy.

### 7. Overflow construction

The equal-sign path contains a dedicated overflow return expression after relevant combination, packing, and rounding decisions.

That expression combines a provisional packed result with an address-like operand before extracting and rebuilding high fields.

**Established:** an overflow-specific encoded-word construction exists.

**Inferred intent:** produce an infinity with the appropriate sign.

**Unknown:** the arithmetic meaning of the address-like operand, including any scaling implied by its unresolved type. An exact universal overflow result cannot be established from the supplied material.

No visible caller-selected directed rounding mode or explicit saturation-to-largest-finite policy is provided.
