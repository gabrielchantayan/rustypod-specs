# F-ff4685fc5c14

## Purpose

F-ff4685fc5c14 specifies a state-dependent sequence of memory accesses, computed-target calls, nested processing, a backward cycle, a software breakpoint, and an endpoint marked as invalid instruction data. No application-level service, successful outcome, or normal return is established.

The contract distinguishes:

- **Established static evidence:** explicit access widths, address expressions, ordering, initialized state, branch dependencies, and target-selection updates.
- **Inferred intent:** none assigned. Address labels do not establish hardware behavior, initialization services, allocation, or ownership.
- **Unknown / documented_only:** incomplete entry state, undeclared global types, problematic arithmetic semantics, dependency effects, and runtime termination.

Every operation is conditional on execution reaching it and preceding operations permitting continuation. No runtime tests have been performed.

## Interface

### Inputs and result

The represented interface has four explicit inputs:

| Input | Represented form | Uses |
|---|---|---|

| Third | 32-bit integer/address | Indirection, offset-two halfword destination, and stored values. |

Additional entry requirements include:

- Another incoming address-valued register.
- An eight-byte destination.
- A comparison pointer.
- An accumulator increment.
- Unresolved stack contents used as an address.
- A stack-supplied halfword and output pointer.

Some dependencies also produce extra register results beyond their principal result.

No result value or reachable normal return is established.

### Widths and address conventions

Byte, halfword, word, and wide mean 8, 16, 32, and 64 bits. Explicitly typed indirect accesses establish those widths. Retained pointer-like values are represented in 32 bits. All offsets below are byte offsets.

Named globals lack independent declarations. Their access widths remain unresolved unless explicitly established. Converting a value to 16 bits before assigning it to a global does not establish a halfword destination. Capturing a global into 32-bit state establishes the retained width, not necessarily the underlying access width.

The **original destination** is the incoming eight-byte destination. The **advanced destination** is eight bytes beyond it.

There are no represented entry checks for nullness, alignment, extent, or accessibility. Signed overflow, address wrapping, out-of-object pointer arithmetic, byte order, and excessive shifts remain documented_only. Examples using modular arithmetic explicitly assume 32-bit wrapping.

## Behavior

### Entry and dispatch

The represented order is:

1. Store the fourth input’s low byte at the first input plus the incoming unsigned value.
2. Read a word at the third input plus 16. Store the incoming unsigned value as a word at the loaded address plus 16.
3. Multiply the second input by −2,147,483,648. Store a zero byte at the product plus eight, then the incoming address-valued register’s low byte at the product plus two.
4. Invoke D-01 with zero, then D-02 without represented explicit arguments.
5. Treat D-02’s low word as an address and store the fourth input’s low byte there.
6. Capture the global at 0x0897ef80 into a 32-bit working base.
7. Store D-02’s full wide result through the original destination.
8. Establish the advanced destination and store the low halfword of D-02’s high word at the third input plus two.

The global capture precedes the wide store. An overlapping store may change the global’s memory without replacing the retained base.

Under modular multiplication, the second-input product is zero for even inputs and 0x80000000 for odd inputs. Neither address is established as accessible.

If D-02’s signed low word is nonnegative, enter the shared trailing region. Otherwise, choose between the two negative-result alternatives using whether the advanced destination’s low 30 bits are zero.

#### Outer processing and retained call-target state

Distinguish these state components:

- **Current state:** initially the earlier halfword-derived or replacement global value.
- **History state:** initially zero.
- **Separate working value:** initially zero.
- **Cursor:** initially a represented stack-word address.
- **Retained call-target state:** initially 0x0897f0c3; updated by D-04 and D-05 selection as described below.

At each outer iteration:

1. Store current state as a word at the cursor minus four. Retain that preceding address as the candidate cursor for another outer iteration.
2. Compute eight times history state. Store that computed value as a word **at the address equal to eight times history state**. This is a self-address store, not a store through the preceding cursor address.
3. Clear a word at the address formed by shifting history state left by 17, interpreting the result as signed, arithmetic-right-shifting by 32, and adding 16.
4. Store halfword 0xc470 at an address equal to:
   - current state logically shifted right by four;
   - minus sixteen times the separate working value;
   - minus one if bit three of current state is zero;
   - plus 38.
5. Assign 0x8000 to the global at 0xfe238028.
6. Replace history state with 0x0897f228.
7. Assign address 0x225fc470 to the global at that address.
8. Establish an intermediate offset state of zero.
9. Assign 0x225f to the global at 0x0000229f.
10. Read the global at 0x00000022, shift its value right by 16, and store the converted result as a word at the current cursor plus 84.

The last global’s read width and shift signedness are unresolved; this is not necessarily an upper-halfword extraction from a word.

2. Replace retained call-target state with 0x0897f193.

#### Inner processing

Each inner iteration:

1. Store the working offset as a word at the wide working value’s low-word address plus 12.
2. Arithmetic-right-shift the signed low word by its low byte.
3. Retain the represented signed-subtraction-overflow condition for subtracting one from that shifted value.
4. Read a word through twice the shifted value.
5. Replace current state with 0x0897f1ec.
6. Assign the loaded word’s 16-bit-converted value to the location associated with F-422afe36d401.
7. Store word 0x0897f1f8 at the loaded word’s address plus four.
8. Select the previously retained preceding stack-word address as the cursor.

If the overflow condition is true, return to outer processing. The retained call-target state is not reset on that transition.

Otherwise:

1. Store byte 0xd8 through the wide working value’s high word.
2. Replace current state with eight.
3. Establish a zero comparison value.
4. Select D-05’s target as the **prior retained call-target state plus 0xe56**.
5. Replace retained call-target state with 0x0897f1d7.
6. Invoke the selected target with zero, replacing the wide working value with its result.

- Treat that halfword as an address and store the accumulator there as a word.

## Side effects

Writes reach input-derived memory, stack-derived addresses, globals, fixed addresses, dependency-associated locations, and addresses obtained from narrow values or call results.

Earlier writes can remain observable after a later fault, breakpoint, invalid-instruction event, or nonreturning call. No rollback, structured error result, synchronization, atomicity, or reentrancy guarantee is established.

Aliasing makes ordering significant. In particular, the outer current-state store and history-derived self-address store have distinct address expressions, even when particular inputs make them overlap.

Calls are not assumed to preserve globals or reachable memory. Pointer publication establishes neither allocation nor ownership transfer, retention, release, or lifetime.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Distinct outer destinations:** With history zero and cursor 0x1000, the first outer store writes current state at 0x0ffc. The following history-derived self-address store writes word zero at address zero. It does not inherently write at 0x0ffc.

2. **Taken first D-04:** Starting with selector 0x0897f0c3, a differing comparison pointer selects target 0x0897f0f1. The selector becomes 0x0897f193 before that call. If D-05 is subsequently reached without another selector update, it selects 0x0897ffe9 and changes the selector to 0x0897f1d7 before invocation.

3. **Skipped first D-04:** With the same initial selector, equality skips D-04 without changing selector state. If D-05 is reached, it selects 0x0897ff19—not 0x0897ffe9—and then establishes selector 0x0897f1d7.

4. **Retained outer selector:** If D-04 has established selector 0x0897f193 and an overflow transition returns to outer processing without D-05, a subsequently taken D-04 selects 0x0897f1c1. Outer entry does not restore the initial selector.

5. **Parenthesized arithmetic:** Assuming 32-bit wrapping and original destination 0x1000, the setup base is 0x0d000000. The subsequent word clear is at 0x1597f15c.

6. **Initial inner store:** On first inner entry, the wide low word is zero and working offset is 0x0897f22d. Reaching the store writes that word at address 12.

7. **Separate subtraction:** Holding other operands fixed, increasing the separate working value by one decreases the outer halfword-store address by 16, subject to the arithmetic semantics.

8. **Breakpoint ordering:** If breakpoint 4 does not resume, argument and target-base selection have already occurred. The post-breakpoint working-quantity replacement and D-17 have not occurred.

9. **History lag:** With setup bypassed, current state 0x11223344 and retained cursor word 0xaabbccdd produce history 0x11223344, next argument 0x1557799b, and current state 0xaabbccdd. The next saved history byte is 0x44.

10. **Post-call global read:** If D-09 changes the global at 0x00000060 and returns, subsequent halfword addressing uses the post-call read.

11. **No protective comparison:** Under 32-bit modular multiplication, a D-14-derived scaled value below 20 can only be zero. Its word self-address store still precedes the comparison.
