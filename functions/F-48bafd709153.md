# F-48bafd709153

## Purpose

F-48bafd709153 performs an in-place, offset-driven transformation of a buffer, using a second buffer obtained through object metadata. It processes a table of two-byte offsets, obtains a size-like result for each referenced item, updates a descending 32-bit position, invokes an external operation for each item, and replaces each table entry with the low 16 bits of the resulting position. It then updates several header bytes and invokes a final external operation over the calculated gap.

The established behavior is the sequence of reads, dependency calls, arithmetic, and writes described below. The apparent intent is to repack variable-sized items toward the end of a buffer, preserve an existing suffix in working storage, and process the unused gap. That interpretation is not an established contract for the external dependencies: their implementations and runtime effects are unavailable.

The explicit return value does not report the resulting position or a dependency status. It is a 64-bit value whose upper 32 bits reproduce the second argument and whose lower 32 bits are zero.

## Behavior

### 1. Capture initial metadata

The function first reads the native 16-bit table displacement from object + 0x0E.

It then follows the pointer at object + 0x40, follows the pointer at the beginning of that metadata structure, and reads the working-buffer address at second structure + 0xE4.

Next it reads:

1. The primary-buffer address from object + 0x44.
2. The native 16-bit entry count from object + 0x14.
3. The unsigned header displacement from object + 0x08.
4. The native 16-bit initial extent at metadata + 0x1E, reached through another access to the pointer field at object + 0x40.
5. The two header bytes at +0x05 and +0x06 that encode the initial suffix offset.

The two accesses through object + 0x40 are not a promise that the underlying field cannot change. No dependency has yet been called, but concurrent mutation is not addressed by the supplied material.

The resulting primary-buffer address, working-buffer address, header address, entry count, table displacement, and initial extent are retained for subsequent work. They are not explicitly refreshed after dependency calls.

The source establishes which bytes participate in the initial two-byte offset. It does not establish a necessary evaluation order between the two reads within that combined expression.

### 2. Invoke the initial three-argument dependency

Let:

- The initial extent be the zero-extended 16-bit value from metadata.
- The suffix offset be the unsigned value decoded from header bytes +0x05 and +0x06.

The function invokes F-22000020 with these ordered arguments:

1. Working-buffer address plus suffix offset.
2. Primary-buffer address plus suffix offset.
3. Initial extent minus suffix offset, computed at 32-bit width.

This call happens even when the entry count is zero. There is no local check that the suffix offset is at most the initial extent. If it is greater, the third argument wraps to a large unsigned 32-bit value.

The function does not use this dependency’s return value.

Interpreting this invocation as a copy from the primary buffer into the working buffer is inferred intent, not established dependency behavior.

### 3. Process table entries in ascending table order

The function performs exactly the captured entry count’s number of iterations, unless an access or dependency prevents normal continuation.

For entry index zero through entry count minus one:

1. Compute the entry address as primary-buffer address plus table displacement plus twice the index.
2. Read the entry’s second byte.
3. Read the entry’s first byte.
4. Decode the two saved bytes as an unsigned, high-byte-first 16-bit offset.
5. Invoke F-38c1baaad724 with:
   - The original object address.
   - The working-buffer address plus the decoded offset.
6. Subtract the dependency’s 32-bit result from the current 32-bit position, retaining the low 32 bits.
7. Invoke F-22000020 with:
   - Primary-buffer address plus the new position.
   - Working-buffer address plus the same saved offset.
   - The unmodified 32-bit result from F-38c1baaad724.
8. Write the high byte of the new position’s low 16 bits to the entry’s first byte.
9. Write the low byte of the new position to the entry’s second byte.

The current position initially equals the captured initial extent. It is updated cumulatively, not recomputed independently for each item.

The current entry’s original offset bytes are saved before either dependency call. A dependency’s modification of that entry does not cause its offset to be re-read during the same iteration. Conversely, later entries are read only when their iterations begin; changes to them by earlier dependency calls can affect later processing.

The function does not sort entries, check for duplicate offsets, validate item extents, or detect overlap.

A zero result from F-38c1baaad724 leaves the position unchanged but still causes the three-argument call and both entry-byte writes.

A negative signed result is not rejected. For example, a result with signed value −1 increases the position by one modulo 2³², while the next dependency receives the result’s all-one 32-bit representation.

### 4. Update the header

After every table entry has been processed, the function performs these byte writes in order:

1. Header +0x05 receives the high byte of the final position’s low 16 bits.
2. Header +0x06 receives the low byte of the final position.
3. Header +0x01 receives zero.
4. Header +0x02 receives zero.
5. Header +0x07 receives zero.

There is no intervening dependency call between these explicit writes.

The function does not explicitly update the native 16-bit initial extent in metadata, the entry count, the table displacement, or either stored buffer pointer.

### 5. Invoke the final dependency and return

The function computes the table-end displacement as:

**table displacement + 2 × entry count**

Both inputs are zero-extended 16-bit values. This expression is at most 196,605, so the expression itself does not overflow 32 bits. It can nevertheless exceed a 16-bit offset range or the actual buffer allocation.

F-220002d4 is then invoked with:

1. Primary-buffer address plus the table-end displacement.
2. Final position minus the table-end displacement, at 32-bit width.

No check ensures that the final position is at or beyond the table end. If it is earlier, the second argument wraps.

The return value of F-220002d4 is ignored. If that call returns normally, F-48bafd709153 returns the second input argument in the upper 32 bits and zero in the lower 32 bits.

## Side effects

### Direct writes

The function directly writes:

- Two bytes per processed table entry.
- Five header bytes.

These are ordered writes, not an atomic update. If execution stops partway through, earlier writes and dependency effects are not rolled back.

Addresses may alias. If header bytes overlap table entries, or either buffer overlaps object metadata, direct and dependency writes can interact. The supplied material neither forbids such layouts nor establishes useful results for them. The sequence above remains the basis for analyzing an aliasing case.
