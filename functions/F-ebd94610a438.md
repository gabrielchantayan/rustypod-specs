# F-ebd94610a438

## Purpose

F-ebd94610a438 updates a mutable state record, calls two dependencies in a fixed order, and conditionally invokes an operation through a receiver’s function table.

Dispatch occurs exactly when the second dependency returns nonzero and the subsequently read signed 32-bit selection is **nonnegative and strictly less than the receiver’s signed 32-bit bound**. Selection zero is admitted whenever the bound is positive.

A dispatched operation’s 32-bit result becomes the function’s result. Every normal path that skips dispatch returns a 32-bit zero.

These statements describe behavior established by the supplied static representation. Interpreting the selection as an index, the bound as a count, or the preliminary calls as preparation and readiness checks is inferred intent, not an established semantic contract.

## Behavior

### 1. Initial state update

The function reads the 32-bit word at state-record offset +4 and writes the same bit pattern to offset +8.

This write precedes both dependency calls. It occurs even when a later gate or bound check rejects dispatch.

There is no explicit validation of the state-record address before this access. Defined execution requires the source word to be readable and the destination word writable at the time of the copy. Signed interpretation does not affect the copied bit pattern.

### 2. Preliminary dependency calls

After the copy, the function calls F-e409dfa213c9 with the state-record address. Its return value, if any, is not used.

If that dependency returns normally, the function next calls F-392d97f6cbd4 with no explicit arguments in the supplied representation.

The second dependency’s result is tested for zero:

- Zero causes an immediate normal result of zero, without the function’s later receiver-address, selection, bound, or function-table accesses.
- Any nonzero value permits the subsequent state-record reads. The result need not equal one or be positive.

Both calls occur before the receiver address and dispatch selection are captured. Neither dependency is assumed to preserve the record, globals, receiver storage, or function table. The absence of an explicit argument to F-392d97f6cbd4 does not imply absence of state effects.

### 3. Post-dependency reads

Following a nonzero gate result, the represented access order is:

1. Read the receiver-address word from state-record offset +0.
2. Read the signed 32-bit selection from state-record offset +8.
3. If the selection is nonnegative, read the signed 32-bit bound from receiver offset +4.

Loading the receiver-address word is distinct from dereferencing that receiver:

- A negative selection still causes the receiver-address word in the state record to be read.
- A negative selection avoids the receiver-bound read.
- Selection zero causes the receiver-bound read and may subsequently dispatch.

Thus, zero is not a sentinel that avoids receiver dereferences. A negative selection avoids this function’s receiver-bound and function-table accesses, but does not prevent either preliminary dependency from accessing receiver-related state.

### 4. Dispatch decision

Dispatch requires both of the following signed comparisons to hold:

- Selection is greater than or equal to zero.
- Selection is strictly less than the bound.

The representation initially forms a zero-equality condition for the selection. For nonnegative selections, that condition is replaced by equality between the bound and selection. The subsequent dispatch condition excludes equality and requires the selection to be at most the bound. Together, those conditions establish a strict upper bound, **not** exclusion of selection zero.

Consequences for signed 32-bit values are:

- Every negative selection is rejected without reading the receiver’s bound.
- Zero is admitted exactly when the bound is positive.
- Equality with the bound is rejected, including selection zero with bound zero.
- A selection greater than the bound is rejected.
- A bound of zero or less admits no selection.
- A bound of one admits only selection zero.
- A bound of two admits selections zero and one.

The decision does not subtract one from either value, multiply the selection, compute a selection-indexed address, or use unsigned comparison. There is no selection arithmetic whose overflow could alter these boundaries.

### 5. Indirect operation

For an admitted selection, the function obtains the function-table address from receiver offset +0 and selects the operation at table byte offset +60.

The supplied representation shows eight argument positions:

| Position | Represented value |
|---|---|
| 1 | Receiver address |
| 2 | Selected signed 32-bit value |
| 3 | Original opaque 32-bit payload |
| 4 | Function address obtained from the same table slot used to select the target |
| 5–8 | Four 32-bit values originating from machine context not defined by the exposed interface |

These positions describe the represented call, not a verified portable callback signature. In particular, the intended role and actual consumption of the fourth through eighth positions are unknown.

The call target and fourth argument are expressed through separate lookups of the same table slot. Their relative evaluation order and exact physical read count are not established. With stable ordinary memory, both designate the same function address. Concurrent mutation or unusual memory semantics cannot be resolved from this representation.

If the indirect operation returns normally, its 32-bit result is returned without an explicit conversion, range restriction, or semantic interpretation. No explicit memory write or restoration follows the call.

The function does not explicitly restore that word. If a dependency changes it, the function uses the later value when reading the selection and does not subsequently reinstate the copied value.

There is no explicit allocation, deallocation, resource acquisition, or ownership transfer in this function.

## Acceptance examples

These are **conditional static acceptance examples**, not executed tests. Unless stated otherwise, they assume valid accessible storage, stable ordinary memory during the relevant accesses, normal returns, and the specified dependency effects.

1. **Gate rejection still follows the initial write.**  
   The source word at state-record offset +4 contains 17. The function copies 17 to offset +8, calls F-e409dfa213c9, and then receives zero from F-392d97f6cbd4. It returns zero without its later receiver-address or selection reads. Dependency-side accesses or mutations are not excluded.

2. **A dependency changes the selection.**  
   The initial copy places 3 at offset +8, but a preliminary dependency changes that word to 4. With a nonzero gate result and receiver bound 5, dispatch uses selection 4. It does not use the earlier copied value 3.

3. **Negative selection avoids the bound read.**  
   After the preliminary calls, the selection is −1 and the gate result is nonzero. The function reads the receiver-address word and selection, but does not read the receiver’s bound or function table. It returns zero without dispatch.

4. **Zero selection depends on the bound.**  
   After a nonzero gate result, selection zero causes the bound to be read. A positive bound admits dispatch. A zero or negative bound rejects dispatch and produces a normal zero result. An inaccessible bound does not become safe merely because the selection is zero.

5. **Selection zero with bound one propagates the operation’s result.**  
   The gate returns nonzero, the selection is zero, and the bound is one. The indirect operation is called with selection zero and the original opaque payload among its represented arguments. If it returns the 32-bit pattern 0x89abcdef, F-ebd94610a438 returns that same pattern.

6. **A bound of two admits two selections.**  
   With gate success and bound two, selection zero dispatches and selection one dispatches. Selection two is rejected because equality with the bound is excluded.

7. **Positive interior selection dispatches.**  
   With selection two, bound five, and a nonzero gate result, the indirect operation is called. Its normal 32-bit return becomes the function’s result.

8. **Nonpositive bounds admit nothing.**  
   With a nonzero gate result, selection zero is rejected for bound zero or any negative bound. Selection one is also rejected for those bounds. These nonnegative selections still cause the bound read.

9. **Signed extremes do not wrap.**  
   Selection −2147483648 is rejected without a receiver-bound read. Selection 2147483647 cannot be strictly below any signed 32-bit bound and is rejected after the bound read. Selection 2147483646 is admitted when the bound is 2147483647.

10. **The incoming third argument does not provide a bound.**  
    Two invocations differing only in that incoming integer have the same represented dispatch behavior and result when all other state, dependency behavior, and relevant machine context are identical.

11. **A zero result does not identify the path taken.**  
    With selection zero and bound one, dispatch occurs. If the indirect operation returns zero, the final result is zero despite the call having occurred.
