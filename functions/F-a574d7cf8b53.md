# F-a574d7cf8b53

## Purpose

F-a574d7cf8b53 selects one of two lookup paths from a 32-bit discriminator in a caller-supplied object and returns a pair of 32-bit fields from the selected result. When an applicable lookup produces a null result, the function returns 64 zero bits.

The first path applies to discriminator values below two and is enabled only when the second input is nonnegative as a signed 32-bit integer. The second path applies when a subsequent discriminator read equals two. It obtains a key through an indirectly selected callable, then performs a two-argument lookup.

Other discriminator values lead to F-a817d8d58c10. The supplied static evidence presents that path as non-returning, but does not establish the dependency’s actual behavior.

These are structural descriptions, not application-level semantics. The evidence does not identify what the object, lookup key, or returned fields represent.

## Interface

The function accepts two inputs:

- **Object reference:** A 32-bit address-like value identifying readable memory. Although represented as a 32-bit integer in the supplied material, it is used as a base address.
- **Signed selector:** A signed 32-bit integer. Its sign controls whether the below-two path performs a lookup. Its magnitude is not otherwise used, and it is not explicitly passed to a dependency.

No input validation is established. A null, invalid, undersized, or inaccessible object reference can cause a memory-access failure before any useful result is produced.

### Object layout used by this function

Offsets are byte offsets from the object reference. Each listed access is four bytes wide.

| Offset | Interpretation established by use |
|---|---|
| +0x08 | Unsigned 32-bit discriminator |
| +0x0C | Address of an object whose first four-byte word addresses a callable table |
| +0x10 | Address of another object containing a field at offset +0x40 |

- A four-byte table pointer at offset zero of the object referenced from +0x0C.

### Output

On a normal return, the result is a 64-bit bit pattern:

- Bits 31–0 contain the field read at result offset +0x10.
- Bits 63–32 contain the field read at result offset +0x14.

Equivalently, the result is the high field shifted left by 32 bits, combined with the low field. Both fields are treated as raw 32-bit values; no sign extension is established.

There is no separate success flag. A successful lookup whose two fields are both zero is indistinguishable in the returned value from a skipped or null lookup.

## Behavior

### Initial selection

The function first reads the four-byte discriminator at object offset +0x08 and compares it with two using an **unsigned** comparison.

Values zero and one take the below-two path. All other 32-bit values proceed to a second discriminator check. Consequently, a bit pattern such as 0xFFFFFFFF does not qualify as below two.

### Below-two path

For this path, the signed selector is compared with zero.

If the selector is negative:

- No lookup dependency is invoked.
- The object field at +0x14 is not read.
- The function returns 64 zero bits.

If the selector is zero or positive:

1. The function reads the four-byte value at object offset +0x14.
2. It passes that value as the sole explicit argument to F-fbead5c2c287.
3. It checks the returned 32-bit value for zero.

If the dependency returns zero, the function returns 64 zero bits.

If the dependency returns a nonzero address, the function reads four bytes at that address plus +0x10, then four bytes at that address plus +0x14. These become the low and high halves of the returned value, respectively.

The selector is only a sign gate. For a stable object and identical dependency behavior, selectors zero, one, and the largest positive signed 32-bit value select the same operations. No indexing, scaling, or selector-dependent argument formation is present.

There is no second discriminator read on this path.

### Equals-two path

When the first discriminator read is not below two, the function reads the discriminator at object offset +0x08 again. If this second value is two, the following sequence applies.

First, the function resolves an indirect callable:

1. Read the address at object offset +0x0C.
2. Read the table address from offset zero of the referenced object.
3. Read the callable address from table offset +0x144.
4. Invoke that callable and retain its 32-bit result.

The supplied material shows no explicit arguments for this invocation. It does not establish an implicit receiver convention or justify describing this as a method call with a particular receiver argument.

After the indirect call returns, the function prepares the lookup:

1. Read the address at object offset +0x10.
2. Read the four-byte value at offset +0x40 of that referenced object.
3. Invoke F-3a548392a5a0 with two explicit 32-bit arguments:
   - The value just read from offset +0x40.
   - The result of the indirect call.

The timing is significant: the +0x10 pointer and its referenced +0x40 field are read **after** the indirect invocation returns. The contract must not replace these reads with values captured before that invocation. The unknown callable may affect memory, and no preservation guarantee is supplied.

If F-3a548392a5a0 returns zero, the function returns 64 zero bits.

If it returns a nonzero address, the function reads the four-byte field at result offset +0x10, followed by the four-byte field at result offset +0x14, and returns them as the low and high halves of the 64-bit result.

The signed selector does not gate this path. A negative selector does not suppress either the indirect invocation or F-3a548392a5a0.
