# F-29b7066c265c

## Purpose

F-29b7066c265c combines two 32-bit operand encodings after consulting an external dependency. Its ordinary arithmetic paths distinguish equal-sign from opposite-sign operands, align significands by exponent distance, and produce a rounded 32-bit result. Separate paths handle encodings resembling zeros, subnormal numbers, infinities, and NaNs.

**Inferred intent:** the masks, hidden significand bit, exponent spacing, and rounding operations strongly suggest a binary32 addition routine with special handling supplied partly by a dependency. This does **not** establish full IEEE 754 conformance. In particular, the visible handling of subnormal encodings, cancellation, exceptional transfers, and overflow must not be replaced by a generic floating-point addition specification.

**Established scope:** the contract below describes the supplied static representation. It does not establish the implementation of the dependency, the contents of referenced data, target-specific shift behavior, or behavior omitted from that representation.

## Behavior

### 1. Dependency consultation precedes classification

The third and fourth explicit arguments initialize the working operands. The function then invokes F-8bd6630341c0 with:

1. The first explicit argument.
2. The first opaque referenced value.
3. The second opaque referenced value.
4. The address of the first working operand.
5. The address of the second working operand.

The second explicit argument is not forwarded.

The dependency can modify both working operands through these addresses. Every subsequent operand-dependent decision uses the working values after that call.

A nonzero dependency result causes an immediate return of the first working operand. No operand classification, arithmetic, or exceptional-value selection described below occurs on that path.

A zero dependency result permits processing to continue. It does not imply that either working operand is unchanged.

### 2. Encoding interpretation and classification

The visible masks assign the following roles to operand bits:

- Bit 31: sign.
- Bits 30 through 23: eight-bit exponent field.
- Bits 22 through 0: fraction field.

This layout matches binary32, but inputs remain raw words for purposes of this contract.

The initial special-value gate examines each operand by XORing it with its own one-bit left shift and masking with `0x7f000000`. For this layout, a zero masked result identifies an exponent field of either zero or all ones. If either operand satisfies that condition, execution takes the special-value path.

Otherwise, both operands have exponent fields from 1 through 254 and enter the ordinary arithmetic paths.

Left shifts, additions, subtractions, and doubling in this contract retain only the low 32 bits unless a separate carry or signed interpretation is explicitly identified.

### 3. Special values without an all-ones exponent

If neither working operand has an all-ones exponent, the special-value path applies the following ordered selection:

1. If the first working operand has a nonzero exponent field, return it unchanged.
2. Otherwise, if the second working operand has a nonzero exponent field, return it unchanged.
3. Otherwise, return `0x80000000` only when both complete operand words equal `0x80000000`.
4. In every other case, return `0x00000000`.

Consequences established by this ordering:

- A normal operand is returned unchanged when paired with a zero-exponent operand.
- Two zero-exponent encodings do not undergo visible significand addition.
- Nonzero subnormal fractions do not change the result of the final zero-selection rule.
- Two negative-zero words produce negative zero.
- Negative zero combined with a nonzero negative subnormal produces positive zero, not negative zero.

These rules are more specific than a general claim that the routine “adds floating-point numbers.”

### 4. All-ones exponent cases

When at least one working operand has an all-ones exponent, classification uses the operands doubled modulo \(2^{32}\). This removes the sign bit from the comparison while positioning the exponent and fraction information for unsigned comparison.

If either doubled word is greater than `0xff000000`, the function performs an indirect call. Under the inferred binary32 interpretation, this condition identifies a NaN encoding.

The indirect target is the saved incoming return-context value with its lowest two bits cleared. The function returns the 32-bit result attributed to that call. The supplied representation does not establish its argument contract, side effects, or eventual control flow. It is not safe to replace this path with a specified quiet-NaN result.

If neither doubled word exceeds `0xff000000`:

- If the doubled words differ, return the first working operand when its doubled word equals `0xff000000`; otherwise return the second working operand.
- If the doubled words are equal and the signs agree, return the first working operand.
- If the doubled words are equal and the signs differ, return the opaque referenced result word.

Under the binary32 interpretation, these rules select an infinity when paired with a finite operand, preserve equal-sign infinities, and delegate the opposite-infinity result to external data. The bits of that last result are unknown.

### 5. Ordinary arithmetic: common representation

The ordinary paths use an extended significand consisting of the fraction shifted left by eight bits with bit 31 forced on. This supplies the implicit leading bit and eight low-order positions used during alignment and rounding.

An exponent-bearing quantity is obtained by shifting a complete operand word right by 23 bits. For a negative operand this quantity includes the original sign bit in bit 8; it is not merely the eight-bit exponent field. Subsequent result assembly relies on 32-bit arithmetic involving that quantity.

Alignment shifts use the low eight bits of an exponent difference. Some later expressions shift by a count derived from 32 minus that difference. Exact behavior at counts of 32 or greater requires the target shift semantics; it must not be guessed from a host language.

### 6. Opposite-sign ordinary operands

The second working operand’s sign is toggled before comparison. The operands are then conditionally exchanged so that the first working operand carries the larger magnitude and the eventual result sign. This is a working-state transformation, not a write to caller-owned operand storage.

The smaller extended significand is shifted right by the exponent distance and subtracted from the larger extended significand.

The resulting difference has three broad outcomes:

- **Leading bit remains set:** the function assembles a result without further left normalization. Bit 7 of the extended difference controls the initial rounding increment. Nonzero bits below that position establish a non-tie and permit immediate return.
- **A one-bit normalization is sufficient:** the difference is doubled, and a signed right shift contributes to result assembly. The rounding decision uses bit 7 of the doubled difference and the low six bits of the original difference.
- **Further normalization or underflow handling is needed:** the function may return positive zero or derive a normalization distance using a 32-bit leading-zero count.

The further-normalization path computes a candidate exponent-bearing value and accepts it only when its high-bit relationship to the original exponent-bearing value passes an explicit comparison. Failure returns positive zero. The visible accepted expression uses a rotate-like combination with a shift count reduced to five bits, then adds the exponent contribution.

For the two rounding paths that reach tie correction:

- If the shifted-out portion of the smaller significand is zero, clear the candidate result’s least significant bit.
- Otherwise, decrement the candidate result by one.

This is a concrete subtraction-rounding rule. It is not equivalent to simply adding a sticky bit and applying an unspecified rounding mode.

Exact ordinary cancellation reaches a positive-zero return in the visible representation. No ordinary cancellation path explicitly constructs negative zero.

### 7. Same-sign ordinary operands

The operands are conditionally exchanged by unsigned word comparison. Because their signs agree, this orders their magnitudes for alignment.

The smaller extended significand is shifted right by the exponent distance and added to the larger extended significand. A separate carry-out test determines whether the sum needs a one-bit right normalization.

With carry-out:

- The wrapped sum is shifted right one bit and its top bit is restored.
- Bit 7 of that normalized value controls a rounding increment.
- Additional low-bit information determines whether the result can return directly or must undergo tie and overflow handling.

Without carry-out:

- The unnormalized sum supplies the fraction contribution.
- Bit 7 controls the rounding increment.
- A zero rounding bit returns the assembled result immediately.
- When rounding is active, lower bits and the doubled candidate result determine whether later tie or overflow handling is required.

For applicable tie handling, an exactly zero shifted-out portion of the smaller significand causes the candidate’s least significant bit to be cleared.

A doubled candidate is compared unsigned against `0xff000000` on paths reaching the overflow decision. Candidates below that threshold return normally. Other candidates enter the terminal overflow expression.

That terminal expression forces the exponent-position contribution to all ones and incorporates a shifted value derived from the candidate plus an address-derived quantity. It appears intended to produce a signed infinity encoding. Its exact result remains conditional on the meaning of that address expression; this contract does not silently replace it with `0x7f800000` or `0xff800000`.
