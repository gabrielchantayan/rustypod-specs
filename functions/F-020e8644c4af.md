# F-020e8644c4af

## Purpose

F-020e8644c4af searches an indexed collection in ascending index order. A candidate qualifies only if it passes three ordered conditions:

1. Its pointer is non-null and its first byte equals the first byte of the supplied query.
2. F-1cb585febd84, called with the candidate pointer, returns the supplied comparison value.
3. F-fca51b715561, called with the candidate pointer, query pointer, and comparison value, returns zero.

The function returns the index of the first qualifying candidate. It also returns zero when the collection is exhausted. Consequently, a return value of zero does not distinguish a successful match at index zero from an unsuccessful search.

Interpreting this operation as a string lookup, the comparison value as a string length, or the final dependency as a byte-comparison routine is plausible intent, not established behavior. The contract below describes the visible filtering and dependency calls without assuming those meanings.

## Behavior

### Traversal and termination

The search starts at index zero.

Before accessing an entry, the function reads the descriptor’s count field and compares it with the current index using signed ordering. If the count is less than or equal to that index, the function returns zero immediately.

Thus, an initially zero or negative count causes immediate return. On that path, neither the entry-array field nor the query’s first byte needs to be read.

When the count permits another entry:

1. The entry-array address is read from the descriptor.
2. The candidate pointer is fetched from the slot at the current index, using a four-byte slot stride.
3. The candidate is evaluated as described below.
4. If it fails to qualify, the index advances by one and the count check is repeated.

The count and entry-array address are not visibly snapshotted for the entire search. A later iteration reads them again. Changes made through dependency calls can therefore affect later traversal, provided those changes leave subsequent accesses valid.

### Candidate evaluation

A null candidate pointer is skipped. It does not cause a query-byte read or either dependency call.

For a non-null candidate, the function compares the first candidate byte with the first query byte. A mismatch skips the candidate without calling either dependency.

Both bytes must be readable when this comparison is reached. The visible expression establishes the comparison’s position before the dependency calls, but does not establish an observable ordering between the candidate-byte read and query-byte read.

If the bytes are equal, F-1cb585febd84 is called with the candidate pointer. Its result is compared with the supplied comparison value:

- If unequal, the candidate is skipped.
- If equal, F-fca51b715561 is called.

F-fca51b715561 receives, in order:

1. The candidate pointer already fetched for this entry.
2. The query pointer.
3. The original supplied comparison value.

A zero result qualifies the candidate, and the function immediately returns its current index. Any nonzero result rejects it and allows traversal to continue.

Neither dependency is called merely because an entry is present. Their invocation is controlled by the preceding conditions.

### Stability across dependency calls

The candidate pointer selected for the current entry is retained for the two dependency calls. There is no visible reload of that entry slot between them.

Accordingly, if F-1cb585febd84 changes the array slot but returns the required comparison value, F-fca51b715561 still receives the previously selected candidate pointer. Whether that pointer remains valid is a dependency and caller responsibility not resolved by the supplied evidence.

There is also no second first-byte check after F-1cb585febd84 returns. If that dependency changes candidate or query contents, the final dependency observes whatever contents remain accessible when it executes.

After a qualifying result from F-fca51b715561, the function returns without checking the count again. A dependency-induced count reduction does not visibly cancel a match already accepted by that call.

### Integer and address boundaries

The index starts at zero and increases only after rejection. With a stable count representable as a signed 32-bit integer, accepted indices range from zero through one less than that count. An index equal to the largest positive signed count cannot pass the next count check.

The entry-address calculation uses a four-byte stride. It must not be assumed safe merely because the index is below the count. Large indices can make the scaled offset or resulting address unrepresentable under the actual execution model, and the array may be smaller than the advertised count.

The visible function supplies no bounds validation beyond the count comparison. It does not validate:

- The descriptor address plus either field offset.
- The array address plus the scaled index.
- The size or accessibility of a selected candidate.
- The accessibility of the query.
- Any dependency-specific range implied by the comparison value.

No safe wraparound behavior is established for invalid or overflowing address calculations.

## Acceptance examples

These examples are conditional on valid address calculations, readable required storage, and dependencies that return normally. Dependency results are stipulated, not inferred from character contents.

- The function returns zero.
- No entry slot is read.
- Neither dependency is called.
- The query pointer need not be dereferenced.

- Index one reaches the first-byte comparison.
- Neither dependency is called for either entry.
- The function returns zero after reaching the count boundary.

- F-fca51b715561 is not called for it.

- Both dependencies are called in that order.
- The candidate is rejected regardless of the nonzero result’s sign.

- The numeric return alone cannot distinguish this match from exhaustion.

- No later entry is inspected.

- The function returns zero without reading another entry slot.

- This example requires the retained pointer to remain valid under the final dependency’s contract.
