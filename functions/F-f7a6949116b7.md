# F-f7a6949116b7

## Purpose

F-f7a6949116b7 selects one of four dependencies using a byte reached indirectly through its first argument. For selector values 4, 5, 6, and 7, it invokes exactly one corresponding dependency. For every other selector value, it returns without invoking any of those dependencies.

The significant argument-routing exception is selector 5: the dependency receives the original fourth argument in both its fourth and seventh argument positions. The original seventh argument is not forwarded on that branch.

This is a source-facing contract. The dispatch decisions, argument routing, and direct memory-access sequence are established by the supplied static evidence. The meanings of the selector, the pointed-to structures, and the six additional argument words are unknown. No runtime tests have been performed.

## Behavior

### Lookup sequence

Before choosing a dependency, the function reads the address-bearing field at offset 8 from the outer object. It then reads the selector byte at offset 178 from the object identified by that field.

The second access depends on the value obtained by the first. The selector is therefore obtained through one level of stored indirection.

The supplied body contains one selector load. Dispatch uses that loaded value; no selector reload is shown before a dependency call or before return.

This describes the source-level access sequence, not an independently verified machine-instruction trace. Compiler treatment, atomicity, and volatile-access guarantees are not established.

## Acceptance examples

None of the other three dependencies is invoked by this function. If the selected dependency returns normally, the dispatcher returns.
