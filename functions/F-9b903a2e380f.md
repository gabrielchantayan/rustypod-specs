# F-9b903a2e380f

## Purpose

F-9b903a2e380f conditionally updates a 32-bit field in a secondary object and, when that field changes, invokes two dependencies in a fixed sequence.

The update is gated by an indirect operation on the primary object. Only the low 32 bits of that operation’s returned value determine whether the secondary object is inspected. If those bits are nonzero and the existing field differs from the requested value, the function stores the requested value before invoking either subsequent dependency.

An inferred intent is to change a property of an eligible object and then notify related machinery. The property’s meaning and the dependencies’ notification semantics are not established.

## Interface

**Inputs**

- **Primary object reference.** A pointer to an object containing, in the supplied representation:
  - At byte offset 0: a pointer to an indirect-operation table.
  - At byte offset 8: a pointer to a secondary object.
- **Requested value.** A 32-bit integer used for an equality comparison and, conditionally, a 32-bit store. No range restriction, normalization, or validation is visible.

**Output**

The function has no explicit return value. Its observable results are the indirect invocation, conditional memory access and modification, and conditional calls to the two named dependencies.

If an update occurs, that field must also be writable, and later pointer reads and dependency invocations must be valid.

These are access requirements, not validations performed by the function. There are no visible null checks, bounds checks, or checks that a pointer still identifies the same object after an external call.

## Behavior

### 1. Invoke the primary object’s indirect operation

The function reads the operation-table pointer from the beginning of the primary object, selects the entry at byte offset 8, and invokes that entry with the primary object reference as its sole explicit argument.

This invocation occurs on every visible execution path, including paths that perform no update.

The returned quantity is represented as 64 bits. Its low 32 bits are tested for zero. Its upper 32 bits do not affect the subsequent decision:

- If the low 32 bits are zero, the function returns without directly reading the secondary-object pointer or its field.
- If the low 32 bits are nonzero, processing continues.

Although the supplied representation extracts the upper half of the result, that extracted value is replaced before it could affect the enabled path. A nonzero upper half does not compensate for a zero lower half.

The indirect operation may have side effects. Nothing supplied establishes that it preserves the primary object, its secondary pointer, other memory, or global state. The next phase uses the primary object’s state as read after this invocation, rather than a secondary pointer saved beforehand.

### 2. Read and compare the secondary field

On an enabled path, the function reads the secondary-object pointer from primary offset 8 and then reads the 32-bit field at secondary offset 104.

It compares that field with the requested value:

- If equal, it returns without a direct field write and without calling either named dependency.
- If unequal, it proceeds to the update.

Equality is an exact comparison of 32-bit integer values. There is no ordering comparison, truth-value conversion of the requested value, masking, or special handling for negative values.

Thus zero, positive values, and negative values all follow the same comparison-and-store rule. This is a description of visible behavior, not evidence that all such values are semantically valid for the wider application.

### 3. Store the requested value

When the comparison finds a difference, the function writes the requested 32-bit value to offset 104 of the secondary object selected during the comparison phase.

The write precedes both named dependency calls. There is no visible rollback or restoration of the previous value.

The selected pointer is retained for this comparison and write. Later calls, however, obtain their arguments through fresh reads of the primary object’s secondary-pointer field. The function therefore does not establish that every phase operates on the same secondary object.

### 4. Invoke F-fd61d89535ad

After the store, the function reads the secondary pointer again from primary offset 8. It reads the 32-bit value at offset 0 of that secondary object and invokes F-fd61d89535ad with:

1. That value.
2. The integer constant 1.

The first argument is not the newly stored field value. It is obtained from the beginning of the secondary object selected by this later read.

No result from this dependency is inspected. If it returns normally, execution proceeds to the final call. Its effects on the primary object, secondary objects, globals, or memory ownership are unknown.

### 5. Invoke F-ebd0ee53699f

After F-fd61d89535ad returns normally, the function invokes F-ebd0ee53699f with five arguments:

1. An address-like value read from offset 0 of a secondary object obtained through primary offset 8, increased by 84 bytes.
2. A value represented by a global operand whose contents and meaning are not supplied.
3. A secondary-object pointer obtained through primary offset 8.
4. Zero.
5. Zero.

The primary object’s secondary-pointer field is consulted again after the preceding dependency. Consequently, this call must not be specified as necessarily targeting the object whose field was changed.

The first and third arguments both involve reads of that pointer field. The supplied representation does not establish the evaluation order of those argument expressions or an atomic snapshot across them. In an ordinary execution where the relevant memory remains stable while the arguments are prepared, they refer to the same secondary object. A stronger consistency guarantee is not established.

The addition of 84 constructs an argument; it does not itself access memory at the resulting address. No explicit overflow check is shown. The behavior of an invalid or overflowing address calculation is not established as a supported case.

After the final dependency returns normally, this function returns without examining a result.

## Side effects

The function has one explicit conditional memory modification: a 32-bit store at secondary offset 104.

Its directly visible external-call sequence is:

1. The indirect operation, always.
2. F-fd61d89535ad, only after an enabled, unequal comparison and the field store.
3. F-ebd0ee53699f, after the preceding dependency returns normally.

On a disabled or equal-value path, the absence of a direct store does not imply absence of side effects: the initial indirect operation has already run.

No allocation, deallocation, ownership transfer, reference-count operation, locking, logging, or explicit error reporting is visible in this function. Those properties cannot be inferred for its dependencies.

The input references are used for access and argument construction. The supplied evidence does not establish that callees borrow them, retain them, release them, or preserve their lifetime. Normal continuation requires the later accesses to remain valid.

There is no visible transactional protection. If a dependency does not return normally, the function supplies no recovery path. In particular, the direct field store has already occurred before either named dependency begins.

## Acceptance examples

These are conditional consequences of the static evidence, not executed tests. Unless stated otherwise, assume valid accesses, stable memory between external calls, and normally returning dependencies.

1. **Disabled gate.** The indirect result has zero in its low 32 bits. The function performs no direct secondary-field read or write and invokes neither named dependency. This remains true if the upper 32 bits are nonzero.

2. **Enabled gate, unchanged value.** The low result bits are nonzero, the secondary field contains 17, and the requested value is 17. The field is read but not written; neither named dependency is invoked.

3. **Enabled gate, changed value.** The field contains 17 and the requested value is 23. The function writes 23, calls F-fd61d89535ad, then calls F-ebd0ee53699f. Both calls begin after the store.

4. **Negative requested value.** The field contains zero and the requested value is −1. With a nonzero gate, the function stores the 32-bit representation of −1 and follows the same dependency sequence. No visible validation rejects it.

5. **Initial operation redirects the secondary pointer.** The indirect operation changes primary offset 8 before returning a nonzero low result. The comparison uses the pointer read after that change, not the pointer that existed on entry.

6. **First named dependency redirects the secondary pointer.** The function updates one secondary object; F-fd61d89535ad then changes primary offset 8 to another valid object. The final call’s arguments are constructed from the later state. It is not required to receive the updated object.

7. **Dependency interrupts completion.** F-fd61d89535ad does not return normally. The field store has already occurred, but normal execution does not reach the final dependency. No rollback is visible.
