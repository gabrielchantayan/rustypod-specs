# F-9a00e0444c98

## Purpose

F-9a00e0444c98 performs an ordered, forward search over entries exposed by an opaque collection interface. It prepares a search operand, obtains a collection token from a caller-provided location, and examines entries strictly after a supplied position. It returns the position of the first examined entry for which an opaque comparison dependency returns zero.

Three result classes are established:

- A nonnegative position identifies a matching entry.
- −1 indicates that no match was returned, including when the caller supplies no collection location.
- −2 indicates that preparation of the search operand returned zero.

“Search operand,” “collection,” and “match” describe the apparent roles of the values. The supplied static evidence does not establish a concrete container type, string encoding, equality relation, or application-level purpose.

This contract describes the routine’s own operations and their ordering. It does not assume that its dependencies preserve global state, keep collection contents stable, or leave memory ownership unchanged.

## Interface

### Inputs

The routine receives three arguments:

1. **Collection-location pointer.** A pointer to a location containing a 32-bit opaque collection token. The pointer may be null. If nonnull and execution reaches collection processing, the routine reads exactly one 32-bit word from that location and retains that value for subsequent collection operations.

   The pointed-to location is not established to contain the collection itself. Its first word supplies the token passed to the collection dependencies. No larger object layout is established.

2. **Search input.** A 32-bit opaque value passed unchanged to F-83fcd2d25cd8. Its interpretation is unknown. It could represent a handle, address, or another encoded value; no particular interpretation is required by this contract.

3. **Starting position.** A signed integer position. Every negative value is treated as −1 for search progression. A nonnegative value is used as the position preceding the first candidate.

The search is therefore **exclusive** of a nonnegative starting position. A starting position of zero begins consideration at position one, not position zero. Any negative starting position begins consideration at position zero.

## Behavior

### Preparation precedes collection handling

The routine first calls F-83fcd2d25cd8 with the search input.

If the result is zero, the routine returns −2 immediately. On this path, the routine itself does not read the collection-location pointer, obtain a collection bound, look up an entry, or invoke the comparison dependency.

This preparation occurs even when the collection-location pointer is null. Consequently, a null collection-location pointer does not by itself determine whether the result is −1 or −2.

If preparation returns a nonzero value, that value is retained as the prepared search operand for all later comparisons. The routine does not repeat preparation.

### Collection-location handling

After successful preparation, a null collection-location pointer causes the routine to return −1.

For a nonnull pointer, the routine reads its 32-bit word once and retains the resulting collection token. It does not reread the caller’s location during the search.

The routine then treats any negative starting position as −1 and calls F-10b760faca36 with the retained token. The returned signed integer becomes the search bound.

No validation is performed on either the collection token or the bound. In particular:

- A nonnull collection-location pointer containing a zero token is not treated as a null collection-location pointer.
- A negative bound is not reported through a distinct error result.
- The bound is obtained once rather than refreshed between candidates.

### Candidate order and stopping conditions

Before considering each candidate, the routine increments the current position by one. It examines that candidate only if the resulting signed position is strictly less than the retained bound.

For each candidate that satisfies the bound comparison, the observable order is:

1. Call F-6bbddce1b930 with the retained collection token and candidate position.
2. Read one 32-bit word from the returned location.
3. Call F-9878699bd825 with that entry word as the first argument and the prepared search operand as the second.
4. If the comparison result is zero, return the candidate position immediately.

A nonzero comparison result causes the routine to continue to the next position. Its sign and magnitude do not affect search progression.

If an incremented position fails the strict bound comparison, the routine returns −1. There is no entry lookup or comparison for that out-of-range position.

Under ordinary, nonoverflowing signed arithmetic, candidates are examined in increasing order without skipping positions. The first observed zero comparison result wins. No later position is inspected after a match.

### Boundary behavior

For a negative starting position, normalization makes position zero the first candidate. Thus, a bound of zero or a negative bound results in no entry lookups, although preparation, the collection-token read, and the bound query still occur for a nonnull collection-location pointer.

For a nonnegative starting position, the first possible candidate is its successor. If that successor is at least the bound, the routine returns −1 without looking up an entry.

The increment takes place **before** the bound comparison. A large bound or an already out-of-range starting position does not eliminate the increment.

With signed 32-bit positions, a starting position of 2,147,483,647 requires an increment outside the representable range. The supplied evidence does not establish a wrapping rule or another defined outcome for that case. This contract therefore does not promise −1, a wrapped search, or termination for it.

For a well-defined traversal with a signed 32-bit bound, the largest position that can satisfy the strict comparison against the maximum bound is 2,147,483,646.

Its direct memory reads are limited to:

- One 32-bit collection-token read, when preparation succeeds and the collection-location pointer is nonnull.

## Acceptance examples

The following are conditional contract examples derived from static evidence. They are not reports of executed tests. Except where stated otherwise, assume valid readable locations, normal dependency returns, and defined signed arithmetic.

### Preparation failure takes precedence

Given any collection-location pointer and any starting position, if F-83fcd2d25cd8 returns zero, the result is −2.

No collection-bound query, entry lookup, or comparison is performed by this routine. This remains true when the collection-location pointer is null.

### Null collection after successful preparation

Given a null collection-location pointer and a nonzero preparation result, the result is −1.

Preparation still occurs. No collection token is read and no collection dependency is called.

### Negative positions begin at zero

Given a nonnull collection-location pointer, a bound of three, and a starting position of −8, candidates are considered in the order zero, one, two.

If the comparison at zero is nonzero and the comparison at one is zero, the result is one. Position two is not looked up.

The same candidate sequence results from any other negative starting position.

### A nonnegative starting position is excluded

Given a bound of four and a starting position of one, the first candidate is two.

If position one would compare equal but positions two and three return nonzero comparison results, the result is −1. Position one is never inspected.

### No candidate below the bound

Given a bound of three and a starting position of two, the position is incremented to three and fails the strict bound comparison. The result is −1 with no entry lookup.

Given a negative starting position and a bound of zero, the same no-lookup result occurs after the first candidate becomes zero.

### Only zero means match

Given candidate positions zero and one, a comparison result of −1 at zero does not terminate the search. If the comparison at one returns zero, the result is one.

A positive nonzero comparison result has the same continuation effect.

### Earlier observed match wins

Given a bound of five and a negative starting position, if comparisons at positions zero and one are nonzero and the comparison at two is zero, the result is two.

No lookup at three or four occurs, regardless of what those entries would return.

### Zero token is forwarded

Given a valid, nonnull collection-location pointer whose stored token is zero and a successful preparation result, F-10b760faca36 receives zero.

The subsequent outcome depends on that dependency. The routine does not convert the zero token into the null-location behavior.

### Signed maximum is outside the guaranteed progression

Given a signed 32-bit starting position of 2,147,483,647, this contract does not assign an ordinary result to the attempted increment.

Acceptance must not require wraparound, successful termination, or a particular entry-access sequence without additional arithmetic evidence.
