## Side effects

### Memory layout and access ordering

The visible accesses establish offsets, not an object schema:

- Offset 1: an 8-bit selector in several address families, and a directly cleared byte near the iteration’s end.
- Offset 17: either a direct byte destination or an offset from a byte-valued selector.
- Offset 20: a 32-bit read or write after various scaling and extraction operations.

A selector-derived destination is an absolute address between 17 and 272 under the represented arithmetic. It is not a pointer loaded from memory: only one byte is loaded.

Selectors are repeatedly reread. Intervening calls may change their contents, so apparently repeated stores can reach different destinations.

No aliasing exclusions are established. Byte stores, word stores, the global read, and dependency accesses may overlap. The visible order must therefore be preserved.

## Acceptance examples

These are conditional trace expectations, not executed tests.

1. **Unsigned selector interpretation.** If an initial selector read returns 255 and the incoming auxiliary value has low byte 171, the next explicit byte write is 171 at address 272. The selector is not sign-extended.

2. **Captured selector survives intervening calls.** If the initial selector is 7, argument 3 is 3, and the intervening transfer run returns normally, the corresponding word write is 12 at address 27. Changing the selector during that run does not change this destination.

3. **Later selector reads are fresh.** If dependencies change the selector before a later clear, that clear uses the changed byte. It need not target the address used by an earlier selector store.

4. **Extracted bytes are truncated.** If first payload is `0x3ff00000`, its packed-byte expression yields `0x3ff` before byte truncation, so the stored byte is `0xff`.

5. **Shifted arguments discard high bits.** If argument 3 is `0x10000001`, its left shift by 28 contributes `0x10000000`, not an unbounded-integer value.

6. **Direct-clear order is observable.** Each direct-clear pair writes offset 17 before offset 1. Reversing them is not equivalent when accesses have side effects.

7. **A zeroed selector is not guaranteed to remain zero.** Although `next base + 1` is directly cleared, intervening calls precede the final selector read. A dependency mutation must be reflected in that read.

8. **Second payload’s later shift is zero.** Under the stated 32-bit arithmetic, the explicit `second payload << 28` argument is zero for every middle result.

9. **No normal completion.** If all calls return and all accesses succeed indefinitely, the function begins another iteration rather than returning a success value.
