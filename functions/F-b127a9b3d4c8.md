# F-b127a9b3d4c8

## Purpose

F-b127a9b3d4c8 coordinates a two-input matching operation with an optional escape expression. It obtains converted representations of the first two input values, checks the first input against a configured complexity limit, optionally validates and decodes an escape value, and delegates matching to F-bf8a91b6216b.

The visible interface returns no value directly. Successful matching publishes a signed result through a caller-provided context. Certain rejection paths invoke diagnostic dependencies; other paths return without explicitly publishing a result.

**Inferred intent:** the diagnostic identifiers associate this function with LIKE- or GLOB-style pattern matching. The actual matching rules, wildcard syntax, case handling, and interpretation of the result are not established by this body.

4. An 8-bit value of 1 at context +38.

The first two words form a sign-extended 64-bit representation in low-word/high-word order. Their numeric interpretation as one stored 64-bit object depends on the target layout. The meanings of the values 4 and 1 are not established independently; they are observable metadata writes.

## Behavior

### Initial conversion and limit check

The function first reads the configuration-state address from context +24 and retains that address.

It then performs these dependency calls in order:

1. F-95b79f0a129e on the first argument-vector entry.
2. F-95b79f0a129e on the second entry.
3. F-8e8cd22930fb on the first entry.

The first two returned values are retained as converted representations. A zero result later prevents the matching call. The third return value is used as a signed 32-bit quantity for the complexity comparison.

The first argument-vector entry is accessed separately for the first and third calls. The body does not establish that dependencies leave the argument vector unchanged, so those calls cannot be assumed to receive the same handle if intervening side effects alter it.

After the third call, the function reads the signed limit at configuration-state offset +112. The address used for this read is the address captured before any dependency call, not a fresh read of context +24.

If the limit is strictly less than the quantity returned by F-8e8cd22930fb:

1. The function writes the 32-bit value 1 at context +52.
2. It calls F-518be8877b82 with the address context +8 and a diagnostic-string reference associated with excessive pattern complexity.
3. It returns.

Equality is permitted. This is a signed comparison; no absolute value, unsigned reinterpretation, or arithmetic scaling is visible.

This rejection precedes escape processing and the zero checks on the converted first two inputs. It can therefore occur even when one of those conversions returned zero.

### Branch without an escape argument

When the argument count is anything other than 3, the function uses a 32-bit escape parameter of zero and proceeds to the common matching gate.

There is no separate rejection for counts below 2 or above 3. A count of 0 or 1 does not prevent the unconditional accesses to the first two argument-vector entries. Such calls require those entries to remain accessible despite the supplied count.

### Branch with an escape argument

When the count equals 3, the function reads the third argument-vector entry and passes it to F-95b79f0a129e.

If that conversion returns zero, the function returns immediately. It does not explicitly write result fields or invoke the escape diagnostic dependency on this path.

For a nonzero converted escape representation, the function calls F-b4209d504f85 with:

- The converted representation.
- A 32-bit all-ones value, represented as −1 in the supplied expression.

The function continues only if this dependency returns exactly 1.

If the return value is anything else, the function calls F-d8267ca9780b with:

- The original context address.
- A diagnostic-string reference associated with the requirement for a single escape character.
- The 32-bit all-ones value.

It then returns without calling the matcher.

If the return value equals 1, the function calls F-429a3f34f0b2 with:

- The converted escape representation.
- Zero.
- The address of temporary 4-byte storage that currently contains that same converted representation.

The return value becomes the escape parameter supplied to the matcher. Any value written through the temporary-storage address is not subsequently read by this body.

**Inferred intent:** F-b4209d504f85 appears to measure an escape representation, and F-429a3f34f0b2 appears to decode its single character. The unit of measurement and the encoding are not established. “One” must not be strengthened into “one byte,” “one Unicode scalar,” or another particular character model without a dependency contract.

### Common matching gate and result publication

The function calls the matcher only if both retained first-input and second-input conversion results are nonzero.

If either is zero, it returns without directly publishing a result. With a count of 3, escape processing has already occurred before this gate; an invalid escape can therefore produce a diagnostic even when a primary conversion returned zero.

For the matching call, the function obtains a 4-byte parameter through the object address currently stored at context +0, at that object’s offset +8. Unlike the configuration-state address, this object address is not captured before the earlier dependency calls.

F-bf8a91b6216b receives, in order:

1. The retained first converted representation.
2. The retained second converted representation.
3. The indirectly read 4-byte matching parameter.
4. Zero for the non-escape branch, or the return value of F-429a3f34f0b2 for a valid escape branch.

After the matcher returns, the function retains its signed 32-bit return value and invokes F-74b5a05d0094 with no explicit arguments.

Only after that call returns does it perform the four result and metadata writes listed in the interface, in that order. No range check or Boolean normalization is applied to the matcher result.

- The complexity flag write precedes the complexity diagnostic call.
- Escape conversion, validation, and decoding precede the primary-conversion zero gate.
- The matcher precedes F-74b5a05d0094.

## Acceptance examples

These examples are conditional static expectations, not results of executed tests. They assume dependencies return normally and all accessed memory remains valid.

1. **Ordinary two-input completion.**  
   The count is 2, both primary conversions are nonzero, and the measured quantity is within the signed limit. The matcher receives escape parameter zero. If it returns 7, the function calls F-74b5a05d0094, then writes result words 7 and 0, followed by metadata values 4 and 1 at their respective widths.

2. **Negative result preservation.**  
   Under the same completion conditions, a matcher return of −2 produces a low word with bit pattern `0xFFFFFFFE` and a high word with bit pattern `0xFFFFFFFF`. It is not converted into a true/false value.

3. **Limit boundary.**  
   A measured quantity equal to the signed limit does not trigger complexity rejection. A greater quantity does: context +52 is set to 1, the complexity diagnostic dependency is invoked, and neither escape conversion nor matching occurs.

4. **Signed comparison.**  
   A limit of −1 and measured quantity of 0 trigger complexity rejection. This follows from signed ordering, not from an unsigned maximum interpretation.

5. **Missing primary representation.**  
   With count 2, an allowed complexity value, and either primary conversion returning zero, the function makes no matcher call and performs no direct result-publication writes. Earlier dependency effects remain possible.

6. **Valid optional escape.**  
   With count 3, a nonzero escape conversion, and a validation return of exactly 1, the decode dependency is invoked. If both primary conversions are nonzero, its return value—not its temporary-storage output—is passed as the matcher’s fourth argument.

7. **Invalid escape despite missing primary representation.**  
   With count 3 and an allowed complexity value, a zero primary conversion does not bypass escape validation. If the escape conversion is nonzero and validation returns 2, the escape diagnostic dependency is called and matching does not occur.

8. **Zero escape conversion.**  
   With count 3 and an allowed complexity value, a zero third conversion causes immediate return without escape validation, decoding, or matching.

9. **Count other than 3.**  
   A count of 4 follows the same branch as a count of 2. The third entry is not accessed by this body. A count of 1 also selects that branch, but does not make the unconditional second-entry access safe.
