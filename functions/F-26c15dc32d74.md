# F-26c15dc32d74

## Purpose

F-26c15dc32d74 selects one four-bit field from a byte obtained through an indirect address. A selector byte in the input record determines which field is returned:

- Selector equal to zero: return the upper four bits.
- Selector unequal to zero: return the lower four bits.

The result is an unsigned eight-bit value whose numeric range is 0 through 15. The selected field is right-aligned; the upper four bits of the result are always zero.

The established behavior is extraction only. The function does not advance an address, toggle the selector, consume the input, or modify the referenced byte. Interpreting the record as a cursor for processing successive four-bit values is possible intent, not an established contract.

## Interface

### Input record

The function receives one address identifying a record with the following accessed layout:

| Byte offset | Accessed width | Meaning |
|---|---:|---|
| 0–3 | 32 bits | Stored address used to locate the source byte |
| 4 | 8 bits | Selector: zero chooses the upper field; any nonzero value chooses the lower field |

These are the only record fields accessed in the supplied representation. No record size, trailing fields, allocation metadata, or padding beyond the accessed bytes is established.

The 32-bit address field is interpreted as an address, rather than as the byte to be processed. After reading that field, the function reads one byte from the location it designates.

The record therefore has two distinct readability requirements:

1. Its selector byte and address field must be readable.
2. The address obtained from its first four bytes must designate a readable byte.

The supplied representation establishes a four-byte address field. It does not establish a portable representation for environments with wider addresses. Byte order for decoding that field follows the target execution environment; it is not independently specified as a serialized wire format.

### Output

The return value is eight bits wide and unsigned. It contains exactly one selected four-bit value, numerically normalized to the range 0–15.

There is no separate status result. Zero is a valid extracted value, not an error indicator.

### Preconditions

For defined normal operation:

- The input must designate storage suitable for the record accesses described above.
- Reading the 32-bit address field must be valid under the target’s alignment and memory-access rules.
- The stored address must designate a readable source byte.
- The accesses must not be invalidated while the operation is in progress.

No null check, bounds check, address-range check, or alignment check is visible. The function does not establish the validity of either address before using it.

No ownership transfer is expressed by the interface. The function borrows access to the record and the source byte for the duration of the operation.

## Behavior

### Selection rule

The selector is tested for equality with zero. Its meaning is not restricted to the values zero and one.

Every nonzero byte selects the lower four bits, including values whose most significant bit is set. Although the selector access is represented through a character-sized type, the zero-versus-nonzero decision is unaffected by whether that character type is signed.

The selected byte is treated as unsigned:

- For a zero selector, the upper four bits are shifted down by four positions. The original lower four bits do not affect the result.
- For a nonzero selector, only the lower four bits are retained. The original upper four bits do not affect the result.

In particular, extracting the upper field from a byte with its most significant bit set still produces a value between 8 and 15, not a negative value or a sign-extended result.

### Access order

At the level established by the supplied static representation, the operation proceeds in this order:

1. Read the selector byte at record offset 4 and decide which field to select.
2. Read the 32-bit address stored at record offset 0.
3. Read one byte through that address.
4. Return the selected four-bit value as an unsigned byte.

Only the selected branch is evaluated. The representation does not show an initial source-byte read followed by a selector read, nor does it show one source-byte read for each possible selection.

This ordering is a description of the supplied function representation. It is not a guarantee about processor bus transactions, speculative execution, or ordering between threads. No volatile qualification, atomic operation, synchronization mechanism, or memory barrier is established.

### Widths and arithmetic

The source datum is eight bits wide, and each selectable field is four bits wide. The selector is also read as a single byte.

The upper-field operation is a right shift by four positions on an unsigned byte value. The lower-field operation retains the bits selected by the four-bit mask whose numeric value is 15. Both operations produce a result already representable in eight bits; returning it does not discard any significant result bits.

No addition, subtraction, multiplication, address increment, or selector update is performed. The function cannot overflow a cursor or wrap a position counter because no such state transition is present.

The selector’s record offset is four bytes because it follows one 32-bit field. It is not offset by the native pointer size of an arbitrary host environment.

### Boundary and aliasing cases

All 256 source-byte values have a defined extraction result when the memory preconditions hold.

The function does not reject an address merely because the source byte overlaps the input record. With ordinary stable readable memory, such overlap simply makes the result depend on the byte at the designated location. The supplied representation contains no non-overlap check and no write that would itself disturb an overlapping source byte.

No coherent-snapshot behavior is established if another actor modifies the selector, address field, or source byte during the operation. The accesses are separate; callers must not infer that the function reads an immutable record snapshot or provides synchronization.
