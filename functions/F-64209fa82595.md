# F-64209fa82595

## Purpose

F-64209fa82595 has an established **ordered-effects behavior**: it invokes unresolved dependencies, writes four-byte values to computed addresses, performs byte-selected writes, and enters an unconditional repeating call/write sequence.

The supplied static representation does not establish a higher-level purpose. Repeated scaling and address offsets do not establish an allocator, object model, serializer, device protocol, or ownership convention.

This contract describes the represented execution, conditional on valid entry state, valid accesses, and dependencies returning where subsequent behavior is specified. Warnings about invalid instruction data and removed unreachable regions limit confidence that the representation completely captures the original executable.

No normal return is visible.

## Behavior

### Call notation and ordering

A **five-call group** means five distinct, ordered call sites:

1. The first site receives the explicit arguments listed for that group.
2. Four subsequent sites show no explicit arguments.
3. The primary result of the fifth invocation is captured when specified.

Distinct call sites do **not** establish distinct target functions. The first invocation’s target depends on incoming control-flow state, and nothing supplied proves that it differs from a subsequent target. Repeated invocation of the same dependency is therefore permitted wherever target inequality is unproved.

A **bridge** means four ordered call sites:

- A call receiving the listed arguments.
- A call with no explicit arguments whose primary result is captured.
- A call receiving that captured result.
- A call with no explicit arguments whose primary result is forwarded as specified.

“No explicit arguments” describes the representation only. It does not exclude meaningful implicit arguments or residual register and stack state.

The group and bridge notation preserves invocation order; it does not assign semantics, purity, termination, or target equality to their dependencies.

### Byte-access phase

Define:

\[
Q=(U\mathbin{\&}\text{0x7fffffff})\mathbin{\mathrm{>>}}7.
\]

A **selected write using \(Q\)** consists of a fresh one-byte read at \(Q+1\), followed by a one-byte write at the zero-extended selector value plus 17. The selector read precedes its associated write.

The ordered behavior is:

1. Perform a selected write using \(Q\), storing the low byte of \(r_{16}\mathbin{\mathrm{<<}}2\).

2. Invoke a dependency with three identical explicit arguments, each equal to the 32-bit shifted value \(r_{16}\mathbin{\mathrm{<<}}2\). Invoke another dependency without explicit arguments and capture its primary result. Supply that result to a five-call group, capturing \(r_{17}\).

3. Perform another selected write using \(Q\), storing the low byte of:
   \[
   (r_{16}\mathbin{\&}\text{0x3fffffff})\mathbin{\mathrm{>>}}20.
   \]
   This uses the earlier unsigned result \(r_{16}\), not \(r_{17}\).

4. Execute a five-call group beginning with \(4r_{17}\), capturing unsigned \(r_{18}\). Retain the 32-bit shifted value:
   \[
   X=r_{18}\mathbin{\mathrm{<<}}2.
   \]
   Its later use through a signed holder is subject to the arithmetic and conversion qualifications.

5. Write the low byte of \(X\) directly at:
   \[
   (H\mathbin{\mathrm{>>}}7)+28.
   \]

6. Perform a selected write using \(Q\), storing zero.

7. Invoke a dependency with \(H\mathbin{\mathrm{>>}}7\), then another without explicit arguments. No primary result from these two calls is explicitly forwarded. Execute a five-call group beginning with:
   \[
   (r_{18}\mathbin{\&}\text{0x3fffffff})\mathbin{\mathrm{>>}}6,
   \]
   capturing \(r_{19}\).

8. Perform a selected write using \(Q\), storing zero.

9. Execute a five-call group beginning with \(4r_{19}\), capturing unsigned \(r_{20}\). Initialize:
   \[
   C=(r_{20}\mathbin{\&}\text{0x3fffffff})\mathbin{\mathrm{>>}}25.
   \]
   Consequently, \(0\leq C\leq31\).

10. Read one byte at \(1024X+1\). Zero-extend it, add 17, and write one zero byte at the resulting destination.

11. Invoke a dependency with \(2C\). Invoke another without explicit arguments and retain its primary result as the initial loop-carried value.

The four selector reads at \(Q+1\) are distinct observable reads. Dependencies, earlier explicit writes, or external state may change their results.

Step 5’s direct byte write precedes step 6’s selector read and zero write. Aliasing can therefore affect not only the final stored byte but also the selector used by step 6.

### Unconditional repeating phase

Each iteration has this order:

1. Execute a five-call group whose first invocation receives the current loop-carried value and \(C\mathbin{\mathrm{>>}}8\). Capture its final primary result.
2. Read a fresh byte at \(1024X+1\). Write zero at the zero-extended selector plus 17.
3. Execute another five-call group beginning with four times the result captured in step 1.
4. Replace the loop-carried value with four times the final primary result of step 3.
5. Replace \(C\) with that same final result shifted left by 26 bits and held as an unsigned 32-bit value, subject to the signed-shift qualification.
6. Repeat without an exit test.

The retained \(X\) is not explicitly replaced in the loop.

For the first iteration, \(C\mathbin{\mathrm{>>}}8\) is necessarily zero because initial \(C\) is at most 31. Later iterations replace \(C\); that initial bound does not persist.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume valid accesses and returning dependencies wherever needed.

1. **Initial ordering.** The four-byte write at \(B+20\) occurs before F-U001 is invoked. A dependency observing that storage is reached only after the write.

2. **Coincident dependency targets.** If incoming control-flow state makes F-U001 resolve to the same target as the next call site, the first group still performs five ordered invocations. The contract must not reject that execution merely because two targets coincide.

3. **Third-input boundary.** If \(P=\text{0x00004000}\), word-phase step 9 receives 1 as its fourth explicit argument. If \(P=\text{0x00003fff}\), that argument is 0.

4. **State shifts.** If \(S=\text{0x12345678}\), then \(L=\text{0x00123456}\), \(H=\text{0x00001234}\), and word-phase step 17 receives \(\text{0x00002468}\) as its third explicit argument.

5. **Unsigned state multiplication.** If \(S=\text{0x20000000}\), its unsigned multiplication by eight yields \(M=0\). This does not make other accesses valid or resolve unrelated signed arithmetic.

6. **Repeated word effect.** For a valid small \(r_3=2\), word-phase steps 4 and 5 each write the four-byte value 8 at numerical address 52. The intervening calls remain observable.

7. **Selector reread.** If successive reads at \(Q+1\) yield 4 and 9, their associated writes target 21 and 26. Reusing the first selector would violate the contract.

8. **Byte truncation.** If \(r_{16}=\text{0x00000123}\), the first selected byte write stores \(\text{0x8c}\).

9. **Masked value truncation.** If \(r_{16}=\text{0x3ab00000}\), the later masked-and-shifted expression is \(\text{0x3ab}\), but its byte store writes \(\text{0xab}\).

10. **Selector self-modification.** If \(Q+1=18\) and the selector initially contains 1, a selected write targets address 18 itself. If that write stores zero and nothing intervenes changes it, the next selector read obtains zero and selects address 17.

11. **First loop argument.** For every possible unsigned \(r_{20}\), the first iteration receives zero as its second explicit argument. No equivalent zero guarantee follows for subsequent iterations.

12. **No normal completion.** If every reached dependency returns and every access succeeds indefinitely, execution remains in the repeating phase rather than returning normally.
