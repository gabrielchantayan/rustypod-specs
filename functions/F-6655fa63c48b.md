# F-6655fa63c48b

## Purpose

F-6655fa63c48b performs a long ordered sequence of indirect invocations, transforms their outputs, mutates memory through calculated addresses and absolute globals, and finishes with an unresolved indirect control transfer.

No application-level purpose is established. Character-like constants do not establish text formatting, an encoding, a string interface, or a decoding operation.

This is a **partial, documented_only behavioral contract**. It specifies selected invocation relationships, direct-memory transitions, and important read/write ordering. It does not enumerate the complete invocation protocol, every intermediate memory event, or the exact repeated-store count. Those are documentation coverage limitations, distinct from missing dependency identities or missing global declarations.

“Established” means explicitly supported by the supplied static representation, conditional on its fidelity and reachability. It does not mean runtime-confirmed.

## Behavior

### Invocation protocol

The first indirect destination depends on incoming control-flow state plus 0xFFE. Its displayed argument is the incoming word shifted left by 22 bits. Many later destinations are calculated from embedded control-location values using the same displacement.

The opening protocol includes these relationships:

- A word output supplies arguments formed by left shifts of 8 and 11 bits.
- A paired output supplies four arguments: its low portion shifted left by 8, its unchanged high portion, zero, and zero.
- Another paired output supplies zero, its high portion, its low portion shifted left by 8, and its low portion shifted left by 11.

Invocations with no displayed arguments occur between these relationships. An unused displayed result does not establish that the invocation is dispensable, pure, or unable to affect later memory.

Later argument formation includes saved-output reuse across intervening invocations, duplicate arguments, explicit zeros, field masks, logical right shifts, and paired-output extraction. Unsigned shifts of a 64-bit container by 34, 36, and 44 bits yield its high 32-bit portion shifted right by 2, 4, and 12 bits respectively.

Masks select fields of several widths, including 11 through 17 bits and 19 through 24 bits. Their presence does not establish a serialization format.

Unsigned 32-bit operations retain 32-bit results. A shift followed by a right shift does not generally recover bits discarded by the first operation. Some represented operands are signed; signed overflow and certain shift semantics remain unresolved. Arithmetic relationships below that require wrapping are explicitly conditional on a 32-bit bit-vector interpretation.

The complete ordered invocation list and most later argument relationships are not specified here. These transformation families alone are not an acceptance oracle for the complete protocol.

### Opening direct-memory phase

The following descriptive names identify saved values, not verified objects:

- **Final pair:** paired output immediately before the direct stores.
- **Derived base:** an earlier output shifted left by 25 bits.
- **Shifted base:** another output multiplied by 2²⁵.
- **Saved shifted word:** a preceding output shifted left by 8 bits.
- **Small index:** an output shifted left by 8, masked with 0x7FFF, then logically shifted right by 6.
- **Doubled index:** twice the small index.

Under 32-bit bit-vector interpretation, the small index ranges from 0 through 508 in multiples of four. The doubled index ranges from 0 through 1016 in multiples of eight. These bounds do not establish address validity.

The first word store places the derived base at the final pair’s high portion plus 0x14. A byte store then places the low byte of that high portion at derived base plus 9. Before that byte is overwritten with the low byte of the derived base, a word containing the shifted base is stored at the final pair’s low portion multiplied by 256, plus 0x54.

Next, shifted base plus 0x14 receives a zero word. A byte is read at shifted base plus 5 and saved. Doubled index plus 0x14 receives a zero word, followed by a word store of the zero-extended saved byte at shifted base plus 0x34.

The word at shifted base plus 0x14 is then read afresh. After another zero-word store at doubled index plus 0x14, the low byte of that saved word is written twice consecutively at doubled index plus 0x15.

Overwritten and duplicate stores remain separate represented events. Aliasing or device-facing memory can make their intermediate effects observable.

### Absolute 0x05 observation and retained value

After those duplicate offset-0x15 stores, the named global associated with absolute **0x05** is read and converted to an unsigned 32-bit value. Call the conversion result the **absolute-derived base**.

Its declaration is absent. Therefore:

- The load width is unresolved.
- Its declared signedness is unresolved.
- Zero-extension from an 8-bit load is not established.
- The result is not established to lie within 0–255.
- Stored bits 0x80 do not, by themselves, establish a result of 128.

The read occurs before the following assignment to the named global at **0x01**. Earlier dynamic stores may overlap the storage read at 0x05, so an entry-time snapshot is not equivalent.

The assignment at 0x01 uses an explicitly 8-bit-converted doubled index. Its destination access width remains unresolved because the global declaration is unavailable. In contrast, the following dynamic store at absolute-derived base plus 0x15 is explicitly a byte store containing the low byte of the small index.

Further dynamic writes use the saved shifted word and the word previously read at shifted base plus 0x14. A 32-bit word is then loaded from absolute-derived base plus 0x54, before that location receives the previously saved word. Call the original loaded value the **retained word**. Its later uses refer to that pre-overwrite read, not a reload.

Subsequent events include an address-derived word store at doubled index plus 0x14, followed by an assignment at named absolute **0x54** whose right-hand value is the retained word shifted left by one. The expression is word-sized; the global destination width is unresolved. Doubled index plus 0x14 is then overwritten twice with the retained word.

Two explicit byte stores at doubled index plus 0x15 contain the low byte of four times the retained word. Afterwards, named absolute **0x15** receives an explicitly 8-bit-converted doubled index. That conversion does not establish the global’s destination width.

### Intermediate mutation and literal stores

The intermediate phase follows loaded words and explicitly zero-extended byte reads as address bases. It includes repeated writes, overlapping byte and word regions, and fresh reads at offsets 0x64 and 0x74. An explicit byte read at offset 5 can supply the base for a word read at offset 0x74.

Not every event in this phase is enumerated here. In particular, this document does not reconstruct every alias-dependent saved value.

For the later groups:

- **Adjusted base** is four times the retained word minus decimal 150.
- **Scaled base** is four times the adjusted base.
- **Late loaded word** is a word read at offset 0x74 from an explicitly zero-extended byte base during the intermediate phase.
- **Doubled late base** is twice the late loaded word.
- **Quadrupled late base** is four times that word.

Under wrapping 32-bit arithmetic, the adjusted base is congruent to 2 modulo 4. It cannot equal 3.

Explicit literal stores place byte 0x3A at four times the late loaded word, halfword 0x3A at eight times that word, and word 0x3A at quadrupled late base plus 0x20.

At scaled base plus 0x20, successive word stores contain 0x20 and 0x2F. An explicit byte is then freshly read at scaled base plus 4, zero-extended, and stored as a word at the same offset-0x20 destination. Another word store of 0x20 follows.

Only afterwards is the separate **global base slot** read into a saved 32-bit signed value. Call that result the **saved global base**. Its receiving value is word-sized; without the slot declaration, a physical 32-bit read is an inference rather than an established access width.

This read precedes the assignment of 0x20 to named absolute **0x60**, whose destination width is also unresolved. Earlier aliasing stores may affect the global-base observation. Moving the read to entry or after the 0x60 assignment is not equivalent.

### Repeated store region

After the 0x60 assignment, an initial group performs, in order:

1. A word store of the quadrupled late base at eight times the retained word plus 0x54.
2. A byte store of the scaled base’s low byte at saved global base plus 0x19.
3. A byte store of the saved global base’s low byte at scaled base plus 0x11.
4. A word store of eight times the retained word at saved global base plus 0x34.

The subsequent repeated groups use eight times the adjusted base for the first destination calculation and final stored word. Their word, byte, byte, word ordering remains significant.

The saved global base is not reloaded for each group. A store that aliases its backing global storage does not replace the already saved value.

The exact repetition count is not specified by this document. This is a coverage limitation, not a claim that the count is unknowable from the supplied representation. Collapsing the region into one update is not authorized.

### Late absolute-global observations

After the repeated region, the named global associated with absolute **0xA9** is read into a saved 32-bit value, the **absolute saved word**. The receiving width is established; the underlying global’s read width and signedness remain unresolved.

This observation precedes both the explicit word load at quadrupled late base plus 0x74 and the assignment to named absolute **0x3A**. Call that offset-0x74 result the **saved late field**.

The 0x3A assignment uses a character-converted adjusted base multiplied by eight, then increased by 0x30. Under the stated 32-bit and low-eight-bit interpretation, its low eight bits equal those of eight times the adjusted base plus 0x30. The character conversion does not establish an 8-bit destination access. Character signedness and any destination conversion remain qualified by missing type evidence.

Words are next saved from doubled late base plus 0x14 and scaled base plus 4. Dynamic stores then include:

- A byte at doubled late base plus 0x0D derived from the scaled base.
- Byte 0x6C at scaled base plus 8.
- Bytes derived from the saved global base at scaled base plus 0x0D and plus 9.
- A word containing doubled late base at doubled late base plus 0x54.

Only afterwards does named absolute **0x67** receive the explicitly 8-bit-converted absolute saved word. The conversion selects the low eight bits before assignment. **The destination’s access width is unresolved.**

Three later observations of 0x67 are distinct fresh reads:

- After a word load at doubled late base plus 0x44, its value supplies the assignment to named absolute **0x21**, before the dynamic byte store at scaled base plus 0x10.
- After additional dynamic writes, including a word store at saved global base plus 0x44, a fresh read supplies an explicit byte store at scaled base plus 9.
- After a byte store at doubled late base plus 9, a word store of the absolute saved word at scaled base plus 0x44, and a word read at scaled base plus 0x54, another fresh read supplies another byte store at scaled base plus 9.

Neither the 0x67 read widths nor the 0x21 destination width are established. The explicit dynamic byte destinations do establish 8-bit stores, but not the widths of the source-global reads.

Intervening dynamic stores may overlap 0x67. Consequently, neither the initially assigned value nor an earlier read can replace a later read without additional memory and type evidence.

Other late events include a byte store using a signed right shift, a word read at scaled base plus 0x40, and stores using previously saved fields. The signed shift count comes from the low byte of the scaled base. Excessive-count behavior is **documented_only**.

### Final mutation and transfer

A word loaded at doubled late base plus 4 becomes the **terminal base**. A halfword containing 0x65 is stored at twice that base. Afterwards, a word is read at terminal base plus 0x64 and saved as the **terminal field**.

Further stores include a byte derived from a saved scaled-base-plus-0x14 word and a word containing decimal 100 at offset 0x54 of another loaded destination.

A word is read at terminal base plus 0x74. A subsequent word load at doubled late base plus 0x64 supplies another destination. Final stores include the terminal base’s low byte at doubled late base plus 9, the terminal field at the loaded destination plus 0x54, and that loaded destination at twice the terminal field.

The terminal indirect transfer receives four displayed words:

- 0x72.
- The saved terminal field.
- The earlier saved word from doubled late base plus 0x14.
- The word read from terminal base plus 0x74.

These arguments use saved observations, not an assumed final-memory snapshot. A return without an explicit value is represented afterwards; whether the transfer returns is unresolved.

## Acceptance examples

These are conditional static examples, not executed tests.

- **Paired output:** If an early pair has low portion 1 and high portion 2, and the represented shifts are defined, the corresponding four arguments are 256, 2, 0, and 0.
- **Small index:** If the small index is 12, the doubled index is 24. The explicit 8-bit conversions used for assignments at 0x01 and 0x15 produce 0x18. Their global destination access widths remain unresolved.
- **Absolute-derived base:** If the 0x05 read and unsigned 32-bit conversion produce 128, the following offset-0x15 byte destination is address 0x95. Bits 0x80 in storage alone do not establish that premise.
- **Retained value:** If the retained word is 7 and the shift is defined, the right-hand value assigned at named absolute 0x54 is 14. This does not establish a 32-bit destination access.
- **Global-base timing:** If earlier overlapping stores change the global base slot, its later read must use the value observed at that point, subject to the environment’s memory semantics.
- **Reachable adjusted-base arithmetic:** Retained word 38 gives adjusted base 2 and scaled base 8. The expression assigned at 0x3A evaluates to 0x40 before any destination conversion. This is compatible with the adjusted base’s required congruence modulo 4.
- **Fresh 0x67 observation:** If an intervening aliasing store changes the declared global value observed at 0x67 from 0xAB to 0xCD, a later explicit byte store sourced from that fresh read receives 0xCD. This premise concerns observed values, not an assumed byte-wide global layout.
- **Partial execution:** If a reached access faults, later stores and the terminal transfer are not required to occur. Restoration of earlier memory is not promised.

These examples do not fill the omitted event sequences or repetition count.
