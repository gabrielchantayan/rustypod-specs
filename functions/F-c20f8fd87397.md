# F-c20f8fd87397

## Purpose

F-c20f8fd87397 is a stateful operation that returns either null or an interior address in record storage associated with a caller-supplied context. Its established operations include requesting storage with the numeric argument 512, examining and updating fixed-stride record headers, invoking a dependency with a record payload address, and reading and updating context fields.

**Inferred intent:** managing context-associated records, including payload construction or reuse and metadata-based selection.

**Established limitation:** the global values controlling dispatch, arithmetic, and transitions are unavailable. The evidence establishes individual actions and their local ordering constraints, but not a complete execution path or selection policy for particular arguments. Neither dependency is assumed to preserve globals.

## Behavior

### Initialization and dispatch

The operation explicitly initializes its retained working state to zero, including retained context, storage, and result pointers. It obtains its initial dispatch state from global storage. This initialization does not establish that every transient arithmetic value is defined on every possible path.

Three global words have particularly important roles:

- **Scale word:** used in scaling and branch arithmetic.
- **Coefficient word:** used in multiplication, sign extraction, and branch arithmetic.
- **Dispatch-base word:** used to relate the retained state to numbered actions.

These labels describe uses, not constant values.

Each dispatch attempt first evaluates the following observations in order:

1. Read and retain the scale word for that dispatch.
2. Read and retain the coefficient word for that dispatch.
3. Read the dispatch-base word for the range check.

The range check interprets the state-minus-base difference as unsigned and accepts differences from 0 through 28, subject to the arithmetic qualifications below. A larger unsigned difference enters the fallback path.

For an in-range attempt, further observations follow:

1. Reread the coefficient word and extract its signed 32-bit sign by arithmetic right shift through 31 positions.
2. Read the dispatch-base word into the default transition-target working value.
3. Reread the dispatch-base word to select a numbered action.

The retained sign is zero or negative one. It need not describe the coefficient sampled earlier in the dispatch.

The range check, default target, and action selection therefore use three distinct dispatch-base observations. With a stable base, the accepted range corresponds to 29 numbered actions. If the base changes, passing the range check does not guarantee that the later selection matches a numbered action.

An unmatched selection reaches shared continuation arithmetic rather than an explicit rejection. A defined result for every such situation is **documented_only**, including whether all transient values consumed there have been assigned.

These are source-level observation distinctions. They do not establish volatile access semantics, atomicity, or a hardware-level observation protocol.

### Fallback and storage-pointer publication

The out-of-range fallback writes the retained storage pointer to context offset 0x2C. It then clears two arithmetic working values, obtains a subsequent state from global storage, and resumes dispatch. A numbered action can enter this same publication path directly.

This path is not a no-side-effect error return. If reached before context capture, it attempts the write relative to the initially zero context address. It does not first establish that the retained context is usable.

### Payload dependency

The payload action calls F-00f738d948cf with six positional arguments:

1. A fresh coefficient observation multiplied by the retained value used for header offset 0x08.
2. A separate coefficient observation multiplied by the retained value used for header offset 0x04.
3. A previously prepared coefficient-scaled value derived from the captured second-input product.
4. The retained fourth input.
5. The selected record’s payload address, at record offset 0x10.
6. The retained context address.

The first two products are prepared in separate, ordered statements before the call. Their coefficient observations need not equal each other or the dispatch-sampled coefficient.

The dependency returns a 32-bit integer. No success convention is established.

Post-call processing uses two distinct scale-word observations:

- The first supplies a saved product involving the dispatch-sampled coefficient and the returned value.
- The second supplies a term in the subsequent selector calculation.

For precision, let:

- \(C\) be the dispatch-sampled coefficient.
- \(H\) be the sign value extracted from the later pre-call coefficient observation.
- \(R\) be the dependency result’s 32-bit pattern.
- \(A\) and \(B\) be the first and second post-call scale observations.

The saved product is:

\[
P = C R A \pmod{2^{32}}.
\]

The selector is bit 31 of the 32-bit complement of:

\[
P \mathbin{\mathrm{OR}}
\left((H-C) R B \pmod{2^{32}}\right).
\]

This specifies a discriminator, not a success test. The dependency may change globals before these observations. Even if \(A=B\), the retained sign \(H\) need not correspond to \(C\).

Further global transition data determine how the selector affects execution. After the call, the action retains the selected record’s base and index for subsequent actions.

### Header publication and result retention

A publication action updates a selected record and the context. Its established ordering is a **partial order**, not a total ordering of every read.

First, it performs these stores in sequence:

1. Retained header value to record offset 0x04.
2. Retained header value to record offset 0x08.
3. Captured second-input product to record offset 0x0C.

It then reads context offset 0x30, multiplies that first metadata observation by the scale retained at the start of this dispatch, and stores the result at record offset 0x00.

Only after those header stores does it evaluate the context-update expression. That expression uses:

- A second read of context offset 0x30.
- A fresh coefficient-word read.
- The same retained dispatch scale.

**The second context-metadata read and the fresh coefficient read are not sequenced relative to each other.** They occur in opposite operands of one multiplication expression. The evidence therefore does not require either observation to occur first.

Both observations supply the update calculation, and the context-metadata store follows that calculation.

Writing \(S\) for the retained dispatch scale, \(M_1\) and \(M_2\) for the two metadata observations, and \(K\) for the fresh coefficient observation, the arithmetic structure is:

\[
\text{record header at 0x00} = S M_1,
\]

\[
\text{new context metadata} = K(S M_2 + S).
\]

These formulas remain subject to the signed-arithmetic limitations below. They do not justify replacing the context update with an ordinary increment.

After storing the context update, the action retains the selected record’s offset-0x10 address as its result.

A separate action retains an existing selected record’s payload address without performing these publication stores.

## Acceptance examples

These examples are conditional obligations for the named actions, not proven complete paths from entry.

1. **Changing dispatch base.** If the range check and later action selection observe different bases, action selection uses its own later observation. The intermediate default-target observation remains distinct. Passing the earlier check does not guarantee a numbered action.

2. **Different coefficient samples.** If the dispatch coefficient is 2 but the later sign-extraction observation has its top bit set, the retained sign is negative one. Post-call processing uses that sign and the dispatch coefficient in their separate roles.

3. **Separate post-call scale observations.** Suppose \(C=1\), \(H=0\), \(R=1\), \(A=0\), and \(B=1\). The saved product is zero. The other term is all ones, so the selector is zero. Reusing \(A\) instead of observing \(B\) would produce selector one and is not equivalent.

4. **Header clearing.** With valid record storage, the clearing action writes zero at offsets 0x04, 0x08, 0x0C, then 0x00. No payload clearing is required by this action.

5. **Payload displacement.** For record index 2 and valid, non-overflowing addressing, the record starts 64 bytes after its storage base; the payload starts 80 bytes after that base.

6. **Storage request.** Reaching the request action passes exactly 512 to F-d33f6d597e5d. A null response affects transition selection but does not alone establish the function’s final return value.

7. **Null context lookup.** Reaching the lookup action with a zero context attempts the offset-0x2C read before testing the context for nonzero. Safe rejection is not guaranteed.

8. **Distinct publication metadata.** Suppose the retained scale is 2, the first metadata observation is 3, the second is 5, and the fresh coefficient observation is 7. With these small, non-overflowing values, the record’s first header word receives 6 and the context metadata receives 84. Combining the two metadata observations would be incorrect.

9. **Unordered update operands.** During that publication, observing the fresh coefficient before the second metadata read is not excluded; neither is the reverse order. Both belong to the update calculation after the header stores and before the context-metadata store. Acceptance must not require a particular ordering between those two reads.

10. **Null after effects.** An execution eventually returning null may already have requested storage, cleared headers, published a storage pointer, or invoked the payload dependency. Null does not establish absence of side effects.

## Uncertainties

The following remain **documented_only**:

- Global contents, stability, initial dispatch choice, and transition targets.
- Complete paths, concrete reachability, and termination.
- Semantic argument meanings, record count, valid index range, and selection policy.
- Defined outcomes for unmatched action selection or use of unassigned transient state.
- Dependency success conventions, effects, ownership, and release obligations.
- Context-metadata meaning and returned-pointer lifetime.
- Recovery from invalid accesses or invalid address formation.
- Byte order, alignment guarantees, concurrency, and reentrancy.

Arithmetic widths matter. Unsigned 32-bit operations wrap modulo \(2^{32}\). Arithmetic sign extraction and unsigned extraction of bit 31 are different operations.

Not every expression is wholly unsigned. Some products, sums, differences, and state arithmetic involve signed 32-bit intermediates. A later unsigned conversion does not establish that an earlier signed overflow is defined. In particular, the unsigned range-check interpretation does not independently define overflowing signed state subtraction.

Record addressing includes 32-bit word-index arithmetic before pointer formation. The nominal 32-byte stride describes valid, non-overflowing addresses; it does not establish safe arbitrary wrapping or bounds.

Separate source observations do not establish safe concurrent mutation. Likewise, the absence of sequencing between the two publication-update operands does not supply synchronization or guarantee race-free behavior.
