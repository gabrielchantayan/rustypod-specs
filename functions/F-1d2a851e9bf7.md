# F-1d2a851e9bf7

## Purpose

F-1d2a851e9bf7 conditionally updates state obtained from a dependency. It has two paths:

- For selector **0xB66**, it obtains four input words, passes each through the same dependency, converts the four returned values into bytes, and stores those bytes at four consecutive state offsets.
- For every other selector, it delegates an update using the state address, the selector, and the first input word.

If the initial state lookup returns zero, the function returns without reading the input buffer or invoking either update dependency.

These are established structural behaviors. The meanings of the selector, the four components, and the destination fields are not established. In particular, interpreting the four bytes as color channels or interpreting the transformation dependency as a clamp would require evidence not supplied here.

## Behavior

If its result is zero:

- The function returns immediately.
- The selector does not cause either update path to execute.
- No input word is read by this function.
- No direct destination-byte store occurs.
- Neither F-b480b7309435 nor F-94dda7bf4a98 is called.

The initial dependency itself may have side effects. Thus, this early return means “no subsequent work by this function,” not necessarily “no observable effects.”

If the result is nonzero, that result is retained as the state base for the remainder of the call. The function does not acquire a replacement state base after later dependency calls.

### Selector 0xB66: input capture

For selector 0xB66, the function reads the input words in a specific order:

1. Second word, at byte offset 4.
2. Third word, at byte offset 8.
3. Fourth word, at byte offset 12.
4. First word, at byte offset 0.

The first three reads occur before the first transformation call. The first word is read to supply that call’s first argument. Consequently, all four input values have been captured before any transformation dependency executes.

This order is relevant to aliasing and externally changing memory. The function does not obtain an atomic four-word snapshot. However, once the four reads have completed, subsequent changes to the input buffer by transformation dependencies do not change the values already captured for this invocation.

The initial state lookup precedes every input read. Any effect that lookup has on the input storage can therefore affect the values captured.

### Selector 0xB66: transformation calls

The function calls **F-b480b7309435** four times, in component order: first, second, third, fourth.

Each call receives three arguments:

- The corresponding captured input word.
- Zero.
- **0x10000**, or **65,536**.

The four results are retained independently. All four calls complete before the function performs its first direct destination-byte store.

The constant arguments suggest a range-related operation, but that interpretation is inferred intent only. The dependency’s actual behavior, input interpretation, result range, and side effects are unknown. This contract does not assume it clamps values to the interval from zero through 65,536.

### Selector 0xB66: byte conversion and stores

Each transformation result undergoes the same conversion:

- Multiplication by **0x1FF**, or **511**.
- Right shift by **0x11**, or **17 bits**.
- Narrowing to one byte.

The resulting bytes are stored in component order:

| Component | Destination offset from retained state base |
|---|---:|
| First | 0x95D |
| Second | 0x95E |
| Third | 0x95F |
| Fourth | 0x960 |

Each direct store is one byte. The function does not directly replace a four-byte field at these offsets or directly modify neighboring bytes.

For a nonnegative transformation result whose multiplication is representable in signed 32-bit arithmetic, the conversion is the low eight bits of:

**floor(result × 511 / 131,072)**

If a transformation result is within **0 through 65,536**, inclusive, then:

- The product lies between zero and **33,488,896**.
- Signed 32-bit multiplication does not overflow.
- The shifted value lies between zero and **255**.
- Narrowing to a byte does not discard any nonzero high bits.

Within that conditional range, the conversion is monotone. It does not round to nearest; it discards the fractional portion after scaling.

Behavior outside that range is not fully established. Negative signed right shifts and signed multiplication overflow require machine-level or language-level semantics not supplied here. No saturation or explicit arithmetic error check is visible.

The four stores occur sequentially, not as a single atomic update. An observer capable of observing intermediate writes may see a partially updated four-byte group.

### Other selectors: delegated update

- The retained nonzero state base.
- The original selector.
- The first input word.

The second, third, and fourth input words are not directly read on this path.

No transformation calls or direct destination-byte stores occur on this path. The delegated dependency may perform its own reads, writes, validation, or other work; those behaviors are not established here.

There is no special handling of any other selector value. In particular, zero and negative selectors follow the same delegated path.

## Side effects

On the 0xB66 path, the function directly performs:

- Four four-byte input reads, in the order described above.
- Four one-byte writes at state offsets 0x95D through 0x960.

On the delegated path, it directly reads only the first four-byte input word.

On the zero-state path, it performs neither input reads nor direct stores after the lookup.

### Dependency effects

The input and destination storage may alias; no explicit non-aliasing check exists. Because every required input word is read before the first direct store on the 0xB66 path, those stores do not alter the captured values used by the current invocation. Dependency effects remain a separate concern.

### Errors and interrupted execution
