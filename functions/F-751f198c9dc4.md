# F-751f198c9dc4

## Purpose

F-751f198c9dc4 transforms seven 16-bit input elements into temporary values, calls dependency F-9a770d6f49ee with the address of one temporary, and calculates a 32-bit result using the dependency’s return value, two global values, and three bytes of the temporary.

When both arguments are non-null, the function explicitly writes the destination twice: first with a scaled difference, then with that difference plus a byte-derived additive term. The second write is the final explicit destination update on normal completion.

The constants and byte fields suggest a time-related calculation: the additive term has the form “hours × 3600 + minutes × 60 + seconds.” That interpretation is inferred intent, not an established semantic guarantee. The dependency’s interpretation of its argument, the global values’ meanings, and the result’s unit are unknown.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and return

The function accepts:

- **Input address:** a nullable pointer used to read seven consecutive 16-bit elements, numbered 0 through 6.
- **Destination address:** a nullable pointer used to write one 32-bit integer.

It has no explicit return value and exposes no status code.

If either argument is null, the function performs no explicit input-element reads, dependency call, global-value reads, or destination writes.

For the non-null path, the caller must provide readable storage for all seven input elements and writable storage for the 32-bit destination. Non-nullness alone does not establish validity. The routine contains no explicit bounds, alignment, accessibility, or overlap checks.

The source-level types imply storage suitably aligned for 16-bit reads and 32-bit writes. Behavior for misaligned addresses is not established independently of the target execution environment.

### Input fields

Let \(U_0,\ldots,U_6\) denote the seven input elements interpreted as unsigned 16-bit bit patterns. Define:

\[
B_i = U_i \bmod 256.
\]

The high byte of each of elements 2 through 6 does not contribute to the explicitly constructed values. Both bytes of element 0 contribute. Only the low byte of element 1 contributes.

The function constructs three 32-bit temporary quantities:

| Quantity | Bit-level value |
|---|---|
| Primary word \(P\) | \(B_2 \times 2^{24} + B_3 \times 2^{16} + B_4 \times 2^8 + B_5\) |
| Secondary word \(Q\) | \(((U_0 \times 2^{16}) + U_1)\mathbin{\&}\texttt{0xFFFF00FF}\) |
| Adjusted word \(R\) | \((B_6 - 1) \bmod 256\), zero-extended to 32 bits |

Equivalently, the secondary word is:

\[
Q = U_0 \times 2^{16} + B_1.
\]

Its bits 8 through 15 are zero. The adjusted word is in the range 0 through 255; its upper 24 bits are zero.

These definitions describe numeric bit positions, not a portable byte order in memory. The memory byte order visible to the dependency depends on the target representation.

### Global inputs

After the dependency returns, the function uses:

The arithmetic is represented as 32-bit integer arithmetic. The supplied evidence does not independently establish the globals’ declared types, synchronization requirements, or application-level meanings.

For ordinary completion, the global pointer must designate readable storage when dereferenced. No explicit check enforces that requirement.

## Behavior

### 1. Null guard

The non-null path is entered only when both arguments are non-null.

A null input suppresses all explicit work even if the destination is valid. A null destination likewise suppresses all explicit work even if the input is valid. Neither case initializes a destination or reports an error.

### 2. Input sampling and temporary construction

The primary word is constructed first, using the low bytes of input elements 2, 3, 4, and 5.

The secondary word is constructed next, using all 16 bits of element 0 and the low eight bits of element 1.

The adjusted word is constructed last, using an eight-bit decrement of the low byte of element 6.

All these constructions precede the dependency call. The supplied expression structure does not establish a left-to-right order for individual input reads within a construction. In particular, it does not justify claiming that elements 2 through 5 are read in ascending index order.

Each input access is expressed as a 16-bit element read, even where only eight bits contribute. A contract requiring only isolated readable bytes would therefore be insufficient.

The adjusted word wraps at eight bits. A low byte of zero produces 255, not a negative 32-bit value. A low byte of one produces zero.

### 3. Dependency call

The function calls F-9a770d6f49ee once, passing the address of the primary word.

The secondary and adjusted words have already been assigned, but their addresses are not explicitly passed. Their placement relative to the primary word is not established by ordinary declaration order. Treating the argument as the start of a larger multiword record requires additional layout evidence.

The primary word is address-exposed and may be modified during the call. Consequently, the final calculation must use its value after the dependency returns, not automatically its initially constructed value.

The dependency supplies an integer return value \(D\). No return value is checked for failure. If the dependency returns normally, its returned integer participates directly in the subsequent calculation.

### 4. Global-dependent calculation and first write

After the call returns, the function reads the multiplier and the baseline reached through the global pointer. It calculates:

\[
T = M \times (D - G),
\]

where \(M\) is the observed multiplier and \(G\) is the observed baseline.

The global accesses occur after the dependency call. The dependency must not be assumed to preserve either the multiplier, the global pointer, or the storage reached through that pointer.

The expression does not establish a relative evaluation order between reading the multiplier and obtaining the baseline. Both supply values to the calculation before the first explicit destination write.

The function then writes \(T\) to the destination as a 32-bit integer.

### 5. Byte-derived calculation and second write

Let \(P'\) be the primary word’s bit pattern after the dependency returns. Define:

\[
H = (P' \mathbin{\gg} 16) \mathbin{\&} 255,
\]

\[
N = (P' \mathbin{\gg} 8) \mathbin{\&} 255,
\]

\[
S = P' \mathbin{\&} 255.
\]

The additive term is:

\[
A = 3600H + 60N + S.
\]

The extraction of \(H\) passes through a 16-bit conversion, but its value remains in the range 0 through 255. Values 128 through 255 are therefore not negative hour coefficients.

The function writes:

\[
T + A
\]

to the destination, replacing the earlier explicit value.

The top byte of \(P'\), bits 24 through 31, does not participate directly in this additive term. It may still influence the dependency’s return value or other dependency behavior.

No range validation limits \(H\) to 23 or \(N\) and \(S\) to 59. Each may be any byte value. The additive term therefore ranges from zero through:

\[
255 \times 3600 + 255 \times 60 + 255 = 933555.
\]

### Arithmetic boundaries

The input packing and adjusted-byte decrement have explicit bounded bit-pattern interpretations.

The scaled difference and final addition are more restricted. Their source representation uses 32-bit integer operations, but the supplied evidence does not resolve overflow semantics well enough to promise portable signed wraparound.

Acceptance expectations involving ordinary integer values require that the subtraction, multiplication, and final addition remain representable in their operative types. Overflowing cases are documented-only until execution-level semantics are established.

## Side effects

2. Call F-9a770d6f49ee.
3. Read the global-dependent operands and calculate the scaled difference.
4. Write the scaled difference to the destination.
5. Use the primary word’s post-call value to calculate the additive term.

The two destination assignments are explicit in the supplied representation. Whether both become separately observable machine stores requires execution-level evidence. They are not specified as atomic, volatile, or synchronized operations.

### Errors

These examples are conditional static expectations, not results of executed tests. Unless stated otherwise, assume valid storage, normal dependency return, stable relevant state after that return, and representable arithmetic.

### Ordinary additive calculation

Suppose the primary word’s selected bytes after the dependency returns are \(H=1\), \(N=2\), and \(S=3\). Suppose also that \(D=12\), \(G=10\), and \(M=100\).

Then:

- The first explicit destination value is \(200\).
- The additive term is \(3723\).
- The second explicit destination value is \(3923\).

### Dependency modification is respected

Suppose the primary word initially has nonzero selected bytes, but the dependency replaces it with zero before returning. With \(D=12\), \(G=10\), and \(M=100\), both explicit destination assignments have value \(200\).

Using the pre-call bytes instead would violate the established post-call calculation.

### Byte values are not range-validated

If \(H=N=S=255\), the additive term is \(933555\). The function does not reject these bytes as invalid time components.

### Global mutation during the call

Suppose the dependency changes the multiplier to 7 and the baseline to 20, then returns 23. With a zero additive term, the scaled difference and completed result are both 21. Pre-call global values do not define the caller’s calculation.
