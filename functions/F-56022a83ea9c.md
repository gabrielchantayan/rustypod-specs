# F-56022a83ea9c

## Purpose

F-56022a83ea9c transforms and combines 32-bit words from a source object and a destination object, writes results into destination storage, publishes a destination count, and conditionally invokes dependencies.

The processing resembles unsigned multiword addition with carry. That interpretation requires assumptions about global factors, operand stability, valid storage, and count representation. The visible operations alone do not establish a conventional integer representation.

The explicit normal-return statuses are:

- **1:** an initial source-count or destination-count check rejects processing.
- **0:** processing reaches normal completion, including paths that invoke either dependency.

A return of 0 does not establish sufficient capacity, normalized output, successful dependency execution, or preservation of destination ownership.

## Interface

### Arguments and representation

The function accepts three addresses, in this order:

| Argument | Role established by visible use |
|---|---|
| Source descriptor | Supplies a count and a word-storage address. |
| Capacity descriptor | Supplies a count for the final carry decision; its address is passed to dependencies. |
| Destination descriptor | Supplies a count and a word-storage address; receives word and count writes. |

The source and destination descriptors expose:

| Byte offset | Field |
|---|---|
| 0 | 32-bit count |
| 4 | 32-bit word-storage address |

The capacity descriptor must expose a readable 32-bit count at offset 0. Its other fields, if any, are unknown.

Storage words are 32 bits wide and occupy consecutive four-byte positions. The supplied representation uses 32-bit addresses. Byte order is not established.

All three initial counts and both storage addresses are read before either rejection returns. Consequently, rejection does not make unreadable descriptor addresses safe. Storage contents are not read on those rejection paths.

### Global factors

Four global factors participate:

| Factor | Visible uses |
|---|---|
| Count scale | Scales each initial count separately; read again on the final-carry path. |
| Input factor | Transforms participating words; also supplies an address-shaped auxiliary argument on one branch. |
| Output factor | Transforms stored result words; supplies the appended carry word directly. |
| Count encoding factor | Read twice after word processing, with distinct uses described below. |

No factor is established to be 1, nonzero, stable, or the inverse of another.

The **two post-processing count-encoding reads are distinct**:

1. The first reading is captured for the third argument to F-61e238108dfa and for the count written after an appended carry word.
2. The second reading calculates the initially published destination count.

The initial count publication does not use the first captured reading. Equality of these readings requires an explicit stability assumption.

### Arithmetic and validity requirements

Word multiplication, addition results, and stored values are represented at 32-bit width. Unsigned carry checks detect overflow of addition; they do not recover the high half of multiplication.

The source uses signed comparisons for count validation and loop bounds. For ordinary fixed-width interpretation, products retain their low 32 bits and those count results are interpreted as signed 32-bit values. The supplied representation does not independently resolve language-level signed overflow or every machine boundary case.

In particular, negation of the most-negative signed 32-bit count is unresolved. The ordinary accepted-range statements below exclude that case.

The caller must provide readable descriptors and enough valid storage for the actual accesses. No local allocation or pre-write capacity check protects the processing loops or optional append.

## Behavior

### Initial reads and rejection

The initial descriptor observations occur in this order:

1. Destination count, multiplied by a reading of the count scale.
2. Source count, multiplied by another reading of the count scale.
3. Capacity count, multiplied by another reading of the count scale.
4. Source storage address.
5. Destination storage address.

The source-count magnitude calculation occurs before the destination storage-address read, but the rejection itself occurs afterward.

Let the scaled source count be **A**, the scaled destination count be **D**, and the captured scaled capacity be **K**. These are descriptive quantities, not claims about the objects’ domain representation.

The function first rejects when the computed magnitude of A exceeds 28. Otherwise, it rejects unless the computed magnitude of D is less than 29.

For counts whose signed negation is representable, both checks accept the inclusive range −28 through 28. Negative accepted values remain negative loop bounds; the function does not replace them with their magnitudes.

K is not range-checked.

A rejection returns 1 without visible writes or dependency calls. All initial descriptor reads listed above have nevertheless occurred.

### Forward word processing

Carry starts at 0. Destination positions are processed in ascending address order. Source positions, when consumed, also advance in ascending address order.

Under stable operand and factor readings, a paired position has this arithmetic meaning:

- Transform its source word and existing destination word by the input factor.
- Add the transformed words at 32-bit width.
- Add incoming carry.
- Set outgoing carry to 1 if either addition overflows unsigned 32-bit range, otherwise 0.
- Multiply the low 32-bit sum by the output factor and store it.

The two carry indications are combined as a Boolean result, not a carry value of 2.

A source-only or destination-only position uses one transformed word plus incoming carry. Multiplication overflow alone does not set carry. Overflow of the output transformation does not affect carry.

This arithmetic description requires stable readings where the displayed operations read an operand more than once. The visible sum calculation and carry calculation are not universally based on one captured copy of every factor and word.

In particular:

- Paired processing reads the destination word for both sum formation and carry determination.
- When A < D, paired processing also reads the source word again for carry determination.
- When A ≥ D, each consumed source word is captured before its arithmetic uses.
- Input-factor readings recur within arithmetic and carry calculations.
- A destination-only position separately reads the input factor for its auxiliary address-shaped value.

All arithmetic and carry work for a position precedes its destination store. Exact ordering among separate operands within one expression is not established.

### When A < D

The paired portion processes A positions if A is positive, otherwise none.

The destination-only portion then processes exactly D − A positions. Its storage access starts at the next destination position after the paired portion, even if A is negative.

For nonnegative counts, this is A paired positions followed by D − A destination-only positions.

For example, A = −1 and D = 1 causes no paired processing and two destination-only positions. The negative source count does not cause backward addressing or conversion to a positive source length.

This branch always executes at least one destination-only iteration.

### When A ≥ D

The paired portion processes D positions if D is positive, otherwise none.

The source-only portion then processes exactly A − D positions. These positions consume successive source words and write successive destination words without reading those destination positions first.

For nonnegative counts, exactly A destination positions are processed. A negative D can cause more positions to be processed than A suggests as a conventional length.

If A and D are equal and negative, neither portion processes words.

### Count publication: two separate encoding reads

Let **M** be the larger of the original signed counts A and D.

After word processing completes:

1. The count encoding factor is read and captured. Call this reading **E**.
2. The count encoding factor is read again. Call this reading **P**.
3. The destination count is written with the 32-bit product P × M.

E is retained for a possible dependency argument or appended-count update. P determines the first published count.

There is no visible word write between these two encoding reads. That does not establish that they return equal values. Any claim that E = P must state a stability assumption.

Count publication occurs even when no words were processed. It is not normalization: the function does not inspect leading result words to determine the count.

### Completion without final carry

When final carry is 0, F-61e238108dfa is called with:

1. Destination descriptor address.
2. Capacity descriptor address.
3. E, the **first** count-encoding reading.
4. A branch-dependent auxiliary value.

The destination count has already been written using P, the **second** reading. Therefore, the third dependency argument need not be the factor that produced the visible count.

If F-61e238108dfa returns anything other than exactly 1, this function returns 0 immediately.

If it returns exactly 1, F-9c6cf2acef37 is called with the destination and capacity descriptor addresses, after which this function returns 0.

Neither dependency’s result is propagated as the return status.

### Completion with final carry

When final carry is 1, F-61e238108dfa is skipped.

The function reads the count scale again and compares the 32-bit product of that reading and the already calculated initial count value P × M against K. The visible comparison tests whether their 32-bit difference is zero.

This is an equality test, not a less-than comparison or capacity sufficiency check. It uses the calculated publication value, not a fresh read of the destination count field.

If the values differ:

1. The current output factor is written at the next destination word position.
2. The destination count is replaced with the 32-bit product E × (M + 1).
3. The function returns 0 without invoking either dependency.

Thus the comparison uses a count derived from P, while the appended count uses E. The appended word is the output factor, not necessarily the integer 1.

If the compared values are equal, F-9c6cf2acef37 is called with the destination and capacity descriptors. The function then returns 0 without locally appending a word.

A count greater than the capacity can select the append path: inequality alone is sufficient.

## Side effects

### Local writes and their order

The visible write sequence is:

1. Zero or more ascending destination-word writes.
2. Initial destination-count publication using P × M.
3. On the unequal final-carry path only, one additional word write followed by a replacement count using E × (M + 1).

A dependency, when called, runs after the initial count publication. Its subsequent effects are unknown.

The two count-encoding reads occur after the main word writes and before the first count write. Accordingly, earlier destination writes that alias the count-encoding global could affect both readings. The supplied body does not establish a mechanism that makes the two adjacent readings differ; neither does it establish their unconditional equality.

### Aliasing

No non-aliasing guarantee is visible among:

- Descriptor objects.
- Source and destination storage.
- Descriptor fields and storage words.
- Those objects and global factors.

Initial scaled counts and storage addresses are captured before processing and are not refreshed after overlapping writes. Later global readings remain sensitive to the state observed at those reads.

The source is not explicitly written through its source storage address. It can nevertheless change when destination writes overlap it. A write in one iteration precedes the next iteration’s reads, so forward overlap can expose previously written results as subsequent input.

Aliasing a descriptor count with a processed word can affect memory during processing, but it does not change the captured loop counts. Aliasing a factor with the initial destination-count publication can affect a later factor read on the carry path.

A conventional multiword-addition interpretation therefore needs an appropriate overlap contract in addition to stable arithmetic factors.

### Ownership and failures

The visible body performs no allocation, release, or explicit ownership transfer.

Dependency calls do not establish whether memory is retained, resized, replaced, allocated, or released. This function makes no subsequent local storage access after a dependency call; that does not imply the dependency preserves any storage or globals.

There is no local recovery for invalid addresses, insufficient storage, dependency non-return, or abnormal arithmetic behavior. Such failures are not converted into status 1 or another structured error.

## Dependencies

### F-61e238108dfa

Called only when final carry is 0, after count publication.

Its third argument is E, the first count-encoding reading. The published count instead uses P, the second reading.

Its fourth argument is branch-dependent:

- **A ≥ D:** the source storage address advanced by four bytes for each source word consumed.
- **A < D:** the auxiliary value from the last destination-only iteration.

In the second case, that iteration initially assigns a separate reading of the input factor as a raw address-shaped value. It replaces the value with all 32 bits set if the iteration produces carry. Because this dependency is called only when final carry is 0, the carry-triggered replacement does not reach the call. The passed value is therefore that iteration’s auxiliary input-factor reading, which could itself have any 32-bit pattern.

This fourth argument is not universally an end pointer and is not established to designate valid storage.

Only the distinction between return value 1 and all other return values is established. Purpose, memory requirements, ownership effects, and global mutations remain **documented_only**.

### F-9c6cf2acef37

Called with destination and capacity descriptor addresses when either:

- Final carry is 0 and F-61e238108dfa returns exactly 1.
- Final carry is 1 and the scaled initial publication value equals K.

Its result is ignored. Its purpose, mutations, ownership behavior, and global effects remain **documented_only**.

## Acceptance examples

These are conditional static expectations, not runtime observations. Unless stated otherwise, assume all four global factors remain 1, operands remain stable, descriptors and storage are valid and non-overlapping, and storage is sufficient.

### Initial rejection

With A = 29, the function returns 1 after the initial descriptor reads, without destination writes or dependency calls.

With A = 2 and D = −29, it also returns 1. D = −28 passes the ordinary destination-count check.

### Paired addition without carry

Source count 1 with word 5 and destination count 1 with word 7 produce destination word 12.

E and P are both 1 under the stability assumption. Count 1 is published. F-61e238108dfa receives third argument 1 and a fourth argument one word beyond the source start.

A dependency return of 0, 2, or any other value except 1 leads directly to return 0. A return of 1 causes F-9c6cf2acef37 to be called first.

### Carry through a longer destination

Source count 1 with word 1 and destination count 2 with words 4,294,967,295 and 8 produce words 0 and 9.

Final carry is 0 and count 2 is published. F-61e238108dfa receives the auxiliary input-factor value 1 as its fourth argument, not a source end address.

### Final carry: unequal versus equal capacity

Source and destination counts of 1, with source word 1 and destination word 4,294,967,295, produce a first result word of 0 and final carry 1.

With capacity count 2, count 1 is initially published; inequality selects an appended word of 1 and replacement count 2. Neither dependency is called.

Capacity count 0 selects the same append path. The function does not reject that apparent capacity shortage.

With capacity count 1, equality instead selects F-9c6cf2acef37. No carry word is locally appended.

### Distinct count-encoding readings

Conditionally suppose the two encoding reads yield E = 3 and P = 5. This example does not assert that such variation occurs in an ordinary isolated execution.

With M = 1 and final carry 0:

- The destination count is published as 5.
- F-61e238108dfa receives third argument 3.

With M = 1, final carry 1, count scale 1, and K = 2:

- Count 5 is initially published.
- The comparison uses 5, not 3.
- Inequality selects the append.
- The replacement count is 3 × 2 = 6.

With K = 5 instead, equality selects F-9c6cf2acef37 without a local append. These outcomes distinguish both encoding reads and their downstream uses.

### Accepted negative count

With A = −1, D = 1, and destination words 7 and 9, no paired positions are processed. Two destination-only positions leave those words unchanged under unit factors.

The published count is 1 despite two processed positions. F-61e238108dfa is called with the auxiliary factor value. Negative accepted counts are therefore not ordinary lengths.
