# F-e0470d196d34

## Purpose

1. Invokes an indirect callback selected through the object.
2. Passes a 32-bit input value and an interior address of that object to F-b9acea4b06ad.
3. Writes three byte-sized values into consecutive positions in the storage identified by that dependency’s result.

The first written byte is derived from a 32-bit field. The next two are read individually from adjacent byte positions in the source object.

The established behavior is this call-and-write sequence. The meanings of the object, its fields, the callback, and the returned storage are not established. ### Dependency invocation

### Third destination write

### Ordering and aliasing

The established local sequence is:

1. Indirect callback.
2. F-b9acea4b06ad.
3. Read the 32-bit source field, then write destination offset 8.
4. Read source offset 29, then write destination offset 9.
5. Read source offset 30, then write destination offset 10.

## Acceptance examples

These are conditional contract examples, not reported test results.

### Ordinary non-overlapping storage

Assume both callees return normally, source and destination do not overlap, all accesses are valid, and no intervening mutation occurs.

If the post-call 32-bit source field is `0x123456AB`, destination offset 8 must receive `0xAB`. Destination offsets 9 and 10 must receive the bytes separately present at object offsets 29 and 30 when those accesses occur.

### Endianness-sensitive source layout

Under a little-endian 32-bit interpretation, source bytes `AB 56 34 12` at offsets 28–31 represent `0x123456AB`. With no mutation or overlap, the three destination bytes become `AB 56 34`.

Under a big-endian interpretation, source bytes `12 34 56 AB` represent the same integer. Under otherwise identical conditions, the three destination bytes become `AB 34 56`.

These outcomes distinguish numeric truncation for the first output from address-based byte reads for the remaining outputs. The target endianness is not established by the supplied body alone.

### Mutation by a callee

If the callback or F-b9acea4b06ad changes the source fields and leaves them valid, the subsequent reads use the changed state. Using values cached before either call would violate the visible sequence.

### Overlapping source and destination

Assume the destination base is 21 bytes beyond the object address. Destination offsets 8, 9, and 10 then coincide with object offsets 29, 30, and 31.

If the first derived output byte is `0x7E`, the first store places `0x7E` at object offset 29. The second read obtains that newly written byte and stores it at object offset 30. The third read then obtains `0x7E` there and stores it at object offset 31.

Under these conditions, all three destination bytes become `0x7E`. This follows from sequential reads and writes, not from an assumed bulk-copy operation.
