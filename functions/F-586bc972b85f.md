# F-586bc972b85f

## Purpose

F-586bc972b85f coordinates preparation calls, target-state selection, indirect callbacks, status-dependent record processing, and a conditional state-table update.

Its established contract is an ordered sequence of reads, calls, and writes. “Manager,” “resource,” “state,” and “record” identify storage roles, not proven domain semantics. Interpreting the operation as notification, completion, or synchronization is inferred intent.

The two explicit inputs do not constitute a complete callable interface. Additional incoming execution state, contextual values, storage addresses, and indirect-call targets are required.

## Behavior

### Initial processing

If the incoming zero-condition state is set, the working mask becomes its bitwise intersection with the first explicit input. Otherwise, it remains unchanged.

F-da3be2b0546d receives, in order:

1. The shared context word.
2. The second explicit input.
3. The resulting working mask.

For index/category 1, flag bit `0x04` is set without clearing other bits.

For index/category 1 and mode 4, D-01 is called. F-f82bb660a2ac then receives its returned address advanced by four bytes and the integer 3. Its result is compared as unsigned 32-bit data: values 0 and 1 set flag bit `0x08`; all other values leave that bit unchanged.

Two further, separate D-01 calls occur. The first returned address, advanced by four bytes, goes to F-1cd96d01ddae. The second, independently returned address, advanced by four bytes, goes to F-9ef7726bf517. No equality between these addresses is established.

For index/category 1, F-2708b7c79728 is then called, followed by D-04 with argument `0x23`.

### Initial manager capture and target selection

After those calls, the manager global is read **unconditionally**, before mode selection. Its value is retained as the **selection manager**. This read occurs even when the selected mode never uses that manager.

| Mode | Target |
|---|---|
| 0 or 2 | 2 |
| 1 or 3 | 4 |
| 4 | 4, with the resource sequence below |
| 5 | 4, with the conditional buffer read below |
| Any other signed value | Incoming unsigned 32-bit target retained |

For mode 4, the observable sequence is:

1. Read the manager global again, independently of the selection-manager capture.
2. Read the resource word at offset `0x5c` from this newly obtained manager.
3. Call D-02 with that word.
4. If the index/category is 2 or 4, call F-a708118dcc50 without reading the status field for this predicate.
5. Otherwise, read the signed 32-bit status at offset `0x34` from the retained **selection manager**. Call F-a708118dcc50 only if this value is not −1 and is less than 16.
6. Read the resource word at offset `0x5c` from the retained selection manager and call D-03 with it.

Thus the entry argument can come from a different manager than the status test and exit argument. Even for one manager, entry and exit resource values need not match: the field is read at different times.

The status predicate admits negative values other than −1. It is not a check for the inclusive range 0–15.

For mode 5, the conditional length is compared unsigned with 4. A value below 4 suppresses the buffer access. Otherwise, byte offset 3 is read and its low bit is tested. Either outcome leaves the target at 4; the read is nevertheless part of the visible behavior.

### Preparation and outstanding-object dispatch

Another D-01 call occurs. Its returned address advanced by four bytes is passed to F-56ee0cebf586.

The outstanding-object operation distinguishes three reads of the outstanding-slot global:

1. Read and retain a slot address for a possible later zero write.
2. Read the global again, then read that slot’s object value for the null check.
3. If the checked value is nonzero, read the global again and read its slot contents anew to obtain the object used for dispatch. Read that object’s dispatch-table pointer and invoke D-05 at table offset `0x1c`.

After D-05 returns normally, write zero to the slot address retained in step 1. If the null check finds zero, neither dispatch nor clearing occurs.

The check does not validate a previously retained object. If the later lookup obtains a different object, that different object supplies the dispatch target. If it obtains zero or an invalid address, no additional guard is visible.

The zero write can clear a different slot from the one used for dispatch. It also occurs after the callback, so it can overwrite a replacement installed in the retained slot during the callback.

Next, D-06 is invoked unconditionally through the incoming callback object’s dispatch entry at offset `0x0c`. No explicit callback argument list or ownership operation is established.

### Primary manager capture and status processing

The manager global is read and retained as the **processing manager**. The function then separately reloads the manager global, reads that newly obtained manager’s resource word at `0x5c`, and calls D-02.

After D-02 returns, the 32-bit status field is read from the retained processing manager. It is converted through a one-byte character value and promoted to a signed integer. This is the **captured status**.

Character signedness is unresolved. Values 0–127, including 100, are unambiguous; interpretations of narrowed values `0x80`–`0xff` remain **documented_only**.

F-88707f7d96dd receives the shared context word after capture. Later explicit status branches use the captured status, not another manager-status read.

If the captured status is 100:

1. Write the marker byte to the processing manager at offset `0x20 + index`.
2. Set the transient record’s 32-bit field at offset 4 to 100.
3. Call F-43ce968102ca with the shared context word.

After this optional sequence, read and retain the persistent-record global as the **captured record base**. This read occurs on both status paths and occurs **before** clearing the transient record’s byte at offset 0.

Then set that transient byte to zero.

For captured status 100, perform these writes in order:

| Destination | Width | Value |
|---|---:|---|
| Record at a **freshly reloaded persistent-record global**, index stride 20, offset 0 | 1 byte | 0 |
| Record at the **captured record base**, index stride 20, offset 4 | 4 bytes | 100 |
| Same captured-base record, offset 8 | 4 bytes | Signed index/category |
| Same captured-base record, offset 12 | 4 bytes | 0 |
| Same captured-base record, offset 16 | 4 bytes | Updated flags |

Finally, set the transient record’s word at offset 4 to the captured status again.

The byte write and four word writes reach one logical record only under an explicit base-stability assumption. Bytes 1–3 are not explicitly written by these operations.

For captured status other than 100, the captured record base is not subsequently dereferenced by this path. Set the transient record’s word at offset 4 to the captured status, then call F-c6c589453fa8 with two zero arguments, the transient record address, and size `0x14`.

Only transient bytes 0 and 4–7 have explicit assignments on this non-100 path. Other bytes are not established.

### State transition

The admission check and write each obtain their own state-table base:

1. Reload the state-table global and read the unsigned byte at the index. Compare it with the full unsigned 32-bit target.
2. If that byte is no greater than the target, or the target equals 2, reload the state-table global and read the indexed byte again. Require this second byte to be less than 4.
3. If admitted, reload the state-table global a third time and write the target converted to one byte at the index.

The first byte read occurs even for target 2. Failure of the first clause suppresses the second read. Failure of either admission clause suppresses the write and all transition-block actions.

With stable bases and bytes, admission means that the old state is below 4 and either does not exceed the target or the target is 2. Without stability, the two predicate bytes and destination byte need not belong to the same table or hold the same prior value.

Following an admitted write, comparisons continue to use the full unsigned target:

- For target 2, call F-43ce968102ca with the shared context.
- For target below 4 but not 2, take no further action in this block.
- For target at least 4:
  1. If target equals 4, read marker-table A’s global base and write the marker at the index.
  2. If the captured status is greater than 15, read marker-table B’s global base and write the marker at the index.
  3. Set transient byte 0 to `0x0e`.
  4. Set transient word 4 to 100.
  5. Call F-c6c589453fa8 with two zeros, the transient address, and size `0x14`.

Targets above 255 therefore can produce a truncated stored byte while still taking the full-width “at least 4” path.

### Finalization

Read the resource word at offset `0x5c` from the retained processing manager and call D-03. This does not reload the manager global.

Finally, return the contextual 32-bit return word.

## Side effects

No allocation, explicit deallocation, ownership transfer, bounds-error result, rollback, retry, or exceptional cleanup is visible. Clearing an object slot is not proof of object destruction.

F-c6c589453fa8 receives stack-resident storage. Whether it copies, mutates, retains, or interprets that storage is unknown; this function establishes no safe retention lifetime.

D-02 and D-03 bracket regions in the normal-return sequence. Their placement does not prove locking, mutual exclusion, matching resource identities, or exception-safe release. If a dependency fails to return normally, subsequent calls and writes are not guaranteed.

Index arithmetic includes a 20-byte record stride and byte offsets added to addresses. No checks reject negative indices, excessive indices, or overflow. Valid ranges, overflow semantics, and behavior for invalid addresses remain **documented_only**, rather than a promised wraparound policy.

## Acceptance examples

These are conditional static examples, not executed tests. Unless specified otherwise, relevant storage remains stable and dependencies return normally without changing it.

1. **Mask and flags.** Mask `0xf0` and first input `0x3c` yield forwarded mask `0x30` when the incoming zero condition is set, otherwise `0xf0`. For index 1 and mode 4, flags gain `0x04`; a F-f82bb660a2ac result of 1 additionally enables `0x08`, while 2 and `0xffffffff` do not.

2. **Distinct selection managers.** If the unconditional manager capture obtains address A but the mode-4 entry reload obtains B, D-02 receives B’s resource word. For index 3, the status predicate reads A; D-03 also receives A’s resource word. A status of −2 qualifies, while −1 and 16 do not. For index 2, the predicate does not read A’s status.

3. **Mode-5 boundary.** Length 3 suppresses the offset-3 buffer read. Length 4 requires it. Either selects target 4.

4. **Distinct outstanding slots.** If the clearing capture obtains slot S, the null-check reload obtains a nonzero object from T, and the dispatch reload obtains object Q from U, dispatch uses Q. After normal return, S is zeroed, not necessarily T or U. A replacement installed in S during dispatch is overwritten.

5. **Split persistent destinations.** With captured status 100, suppose the record-base capture obtains A and the subsequent byte-write reload obtains B. The indexed byte at B is cleared; words at offsets 4, 8, 12, and 16 are written through A. The optional F-43ce968102ca call precedes both base reads.

6. **Non-100 base capture.** With captured status 7, the persistent-record global is still read before transient byte 0 is cleared. No persistent-record dereference follows on this primary path; F-c6c589453fa8 receives tag 0 and status 7.

7. **Permitted decrease and rejection.** Mode 0 selects target 2. Stable old state 3 admits a write of 2 and a transition F-43ce968102ca call. Stable old state 4 rejects the transition for every target; earlier primary processing remains unaffected.

8. **Separate state bases.** For target 4, if the first predicate read through base A yields 0 and the second through B yields 3, admission succeeds. If the write reload obtains C, the byte is written through C. No write to A or B follows merely because they supplied predicate bytes.

9. **Two submissions.** Mode 3, captured status 16, and stable old state 0 produce a primary transient submission with tag 0/status 16, followed by state 4, both marker writes, and a submission with tag `0x0e`/status 100.

10. **Full-width target versus stored byte.** An unlisted mode retaining target 256, with stable old state 0, admits a stored byte of 0. The transition still takes the at-least-4 submission path and does not write marker table A.
