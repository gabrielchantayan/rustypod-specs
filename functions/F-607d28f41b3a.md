# F-607d28f41b3a

## Purpose

F-607d28f41b3a traverses a linked structure, optionally adjusts and checks a candidate cursor, and publishes a 32-bit result followed by an 8-bit status.

Three normal completion paths are established:

- A zero final comparison selects publication of the candidate cursor’s value at publication time, with status 0.
- A nonzero boundary-check result selects a shortcut call to F-d49b96a8539f, followed by publication of its associated result scratch word with status 1.
- The common fallback calls F-d49b96a8539f and publishes a different result scratch word with status 1.

The cursor supplied to candidate extraction and the cursor subsequently published with status 0 are distinct observations. Dependencies can potentially change the cursor between those observations through an address exposed during boundary handling.

An ordered-container insertion operation is **inferred intent**, not an established guarantee. Ordering, duplicate handling, allocation, balancing, and the meaning of status 1 beyond identifying a fallback path remain unspecified.

## Behavior

### Search and saved anchor

The search-comparison state starts at 1.

The function first reads the structure’s header address and reads that header’s offset-0x04 field to obtain the initial node. It separately reads the structure’s header address again to initialize a saved anchor. These are separate source-level observations; a coherent snapshot is not established.

For each nonnull node:

- Both fallback result scratch words are initialized to zero.
- F-0eea27201602 receives the comparison-context address, the original operand, and the current node’s payload address at offset 0x10, in that order.
- The current node becomes the saved anchor.
- A zero comparison result selects the node’s offset-0x0c link.
- Any nonzero comparison result selects its offset-0x08 link.

The selected link is read after the comparison dependency returns. No preservation of node fields by that dependency is established.

Traversal ends when the selected node address is null. There is no cycle detection or iteration limit.

After a nonempty search, the saved anchor is the last visited node and the comparison state is the last search result. After an empty search, the anchor is the separately read header address, the comparison state remains 1, and neither fallback result scratch word has been initialized by the search.

Comparison results are classified only as zero or nonzero. No signed ordering interpretation is established.

### Control-byte decision

After search completion, the function reads the structure’s byte at offset 0x18.

A nonzero value selects the common fallback without initializing or processing a candidate cursor.

A zero value initializes candidate cursor storage with the saved anchor. If the final search comparison was zero, boundary handling and adjustment are skipped. Otherwise, boundary handling follows.

### Boundary handling

The function rereads the structure’s header address and loads the header’s offset-0x08 word into the common-fallback result scratch.

F-9ed8931accde receives:

1. The address of candidate cursor storage.
2. The address of the common-fallback result scratch containing the boundary word.

Both arguments expose writable local storage. The supplied body neither establishes read-only use nor prevents retention of these addresses.

A nonzero result selects the shortcut:

- F-d49b96a8539f receives the other result scratch’s address, the original structure address, a zero-valued argument, the saved anchor, and the original operand.
- The result scratch’s contents after that call are published.
- Status 1 is written, and the function returns.

This call uses the saved search anchor, not the potentially changed candidate cursor.

A zero boundary result selects adjustment using the cursor contents left by F-9ed8931accde.

### Candidate adjustment

The function first reads the candidate’s byte at offset 0x00. Only if that byte is zero does it follow the candidate’s offset-0x04 link and read offset 0x04 through that linked object.

If the byte was zero and the resulting pointer equals the candidate, the cursor is replaced by the candidate’s offset-0x0c link. No explicit null check follows this replacement before extraction.

Otherwise, ordinary navigation applies.

#### Ordinary navigation

There are two separate source-level reads of the candidate’s offset-0x08 link:

- The first supplies a saved navigation value.
- The second determines whether to climb or descend.

If the second read is null, the function ignores the first value for descent and obtains a prospective ancestor through offset 0x04.

For each prospective ancestor, it compares that ancestor’s offset-0x08 link with the previous candidate, then replaces the cursor with the prospective ancestor regardless of the comparison result. Equality continues the climb through offset 0x04. Inequality ends it. The first tested ancestor whose link differs therefore becomes the final cursor.

There is no explicit null protection for these ancestor accesses.

If the second offset-0x08 read is nonnull, descent begins using the value from the **first** read. At each step:

- The cursor becomes the saved navigation value.
- One offset-0x0c read supplies the next saved navigation value.
- A separate offset-0x0c read determines whether descent continues.

A null continuation-test value ends descent at the current cursor. A nonnull value continues using the first read’s value.

The function does not reconcile disagreement between either pair of reads. For example, a null saved navigation value followed by a nonnull continuation-test value is not made safe by an additional check. These distinctions describe source-level evaluation, not guaranteed physical load counts or supported concurrent mutation.

### Extraction, final comparison, and cursor publication

After selection or adjustment, a separate local 32-bit scratch location is cleared. This does not initialize either fallback result scratch.

The subsequent sequence is:

1. Read the candidate cursor and pass that value to F-4987dca85981.
2. Obtain that dependency’s 32-bit return value.
3. Call F-0eea27201602 with the comparison-context address, the extracted value, and the original operand.
4. Test the final comparison result.

Search supplied the original operand before a node payload address. The final comparison instead supplies the extracted value before the original operand.

If the final comparison is zero, the function **reads candidate cursor storage again**, publishes that newly read value, then publishes status 0. It does not publish the extraction dependency’s return value.

In particular, when boundary handling exposed the cursor address, F-9ed8931accde may have retained it. F-4987dca85981 or the final F-0eea27201602 call may modify the cursor through that retained address or shared state. The value passed to extraction, the value present during final comparison, and the value published afterward need not be identical.

The final comparison uses the returned extraction value even if cursor storage changes. No re-extraction or consistency check follows such a change.

A nonzero final comparison selects the common fallback.

### Common fallback

F-d49b96a8539f receives:

1. The address of the common-fallback result scratch.
2. The original structure address.
3. A zero-valued argument.
4. The saved search anchor.
5. The original operand.

After the call returns, the function reads the result scratch, publishes it, and writes status 1.

Candidate adjustment and later cursor mutation do not replace the saved anchor passed to fallback.

If boundary handling exposed the result scratch’s address, its contents may have changed during extraction or final comparison through a retained address. Common fallback therefore uses and publishes the contents left by the complete dependency sequence, including its own call—not necessarily the originally loaded boundary word.

## Acceptance examples

These are conditional static criteria, not runtime test results. Each assumes valid accesses, normal dependency returns, terminating traversal, and the preservation conditions explicitly stated.

### Empty search with candidate processing disabled

Given a null initial node and nonzero control byte:

- No search comparison, boundary call, or extraction occurs.
- Common fallback receives the separately read header as anchor.
- If fallback writes a defined result word, that word is published with status 1.
- If it leaves the scratch untouched, a defined result is not established.

### Initialized common fallback left unchanged

Given a nonempty search, nonzero control byte, and preservation of the common scratch through fallback, the final search iteration’s zero initialization is published as result 0 with status 1. This does not independently establish success or failure.

### Candidate return with a stable cursor

Given a final zero search comparison and enabled candidate processing:

- Boundary handling and adjustment are skipped.
- Extraction receives the saved anchor.
- If the final comparison is zero and cursor storage remains unchanged throughout extraction and final comparison, the saved anchor is published with status 0.

The preservation assumption is necessary to identify the published word with the extraction input.

### Candidate mutation through a retained address

Suppose boundary handling returns zero and retains the cursor address. Adjustment finishes with cursor value A, which is passed to extraction.

If extraction changes the cursor to B through that address, the final comparison returns zero, and the cursor remains B through publication, the result is B with status 0. Extraction was performed on A, not B.

Alternatively, if the final comparison changes the cursor to C before returning zero, and it remains C until publication, C is published. Neither case causes re-extraction.

### Boundary shortcut with a changed cursor

Given a nonzero boundary result:

- Adjustment and extraction do not occur.
- Shortcut fallback receives the saved anchor even if the boundary dependency changed the cursor.
- After a nonempty search, preservation of the shortcut scratch through fallback permits publication of its initialized zero with status 1.
- After an empty search, that initialization is not established.

### Boundary word preserved through common fallback

Suppose an empty search enables candidate processing, boundary handling loads a defined word W and returns zero, adjustment is valid, and the final comparison is nonzero.

W is published with status 1 **only if the common scratch remains W throughout boundary handling, extraction, final comparison, and common fallback**.

Initial nonmutation by F-9ed8931accde is insufficient: it may retain the scratch address, allowing an intervening dependency to change the word later. Without full preservation, publication reflects the scratch contents remaining after common fallback.

### Stable descent and fallback anchor

Suppose ordinary adjustment applies, both offset-0x08 reads agree on a nonnull link, and each descent read pair agrees. Descent ends at the first reached node whose offset-0x0c pair is null.

If the final comparison is nonzero, fallback still receives the saved search anchor, not the adjusted cursor. The read-pair agreement is an assumption, not a merger of the specified reads.
