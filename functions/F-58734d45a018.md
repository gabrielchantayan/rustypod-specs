# F-58734d45a018

## Purpose

F-58734d45a018 transforms caller-owned storage in place. Under the representation conditions below, it reverses the bytes of three consecutive 32-bit words, then stores a byte-reversed 16-bit value at the beginning of the fourth word.

The final value comes from the fourth word’s **low numerical 16 bits**, not necessarily its first two addressed bytes. The destination is always the fourth word’s starting address. This distinction changes the result on big-endian storage.

The transformation does not reorder words, reverse the entire region, or perform a full-width reversal of the fourth word.

An intended use as byte-order conversion for three full-width fields and one shorter field is plausible but unestablished. No application-level field meanings are available.

## Behavior

### Three full-width fields

The first three words are transformed independently. Within each word, the four address-ordered bytes are reversed. Each word stays at its original position, and bit order within individual bytes is unchanged.

For example, a numerical word value of **0x12345678** becomes **0x78563412** under either supported byte order.

The first twelve bytes are therefore three separate reversal regions, not one combined region. No byte moves between these words. With stable input, changing one word’s initial value does not affect either of the other two results.

### Final half-width destination

The fourth word supplies its low numerical 16 bits. The required stored value is the two-byte reversal of that selected halfword.

| Selected low numerical half | Stored halfword value |
|---|---|
| 0x1234 | 0x3412 |
| 0xABCD | 0xCDAB |
| 0x0000 | 0x0000 |
| 0xFFFF | 0xFFFF |

The halfword is stored at offsets **12–13**, regardless of byte order. Offsets **14–15** are not written.

This produces different whole-word behavior:

| Property | Little-endian storage | Big-endian storage |
|---|---|---|
| Location of selected input bytes | Offsets 12–13 | Offsets 14–15 |
| Destination | Offsets 12–13 | Offsets 12–13 |
| Result at the destination | Original first two bytes exchanged | Original last two bytes copied in reverse order |
| Original high numerical half | Preserved | Replaced |
| Last two addressed bytes | Preserved | Preserved |

For an initial fourth-word numerical value of **0x11223344**:

- Little-endian result: **0x11224433**.
- Big-endian result: **0x44333344**.

The calculated halfword is independent of the fourth word’s original high numerical half. The complete resulting word is not necessarily independent of it: little-endian storage preserves that high half.

### Arithmetic widths and narrowing

The full-word transformations have the stated byte-reversal result under unsigned 32-bit arithmetic.

For the final destination, each contributing fourth-word value is narrowed to an unsigned 16-bit value before the subsequent arithmetic. Under the stated promotion model, that arithmetic uses signed 32-bit integers rather than a 16-bit arithmetic domain.

The wider intermediate can contain nonzero bits above the destination width. Its maximum value is **0x00FFFFFF**, or **16,777,215**, which is representable as a signed 32-bit integer. Conversion to the unsigned 16-bit destination retains the low 16 bits and yields the required byte reversal.

Thus, a selected halfword of **0xFFFF** produces a stored halfword of **0xFFFF** despite the wider intermediate. Equivalent behavior is not established for narrower promoted integers, different word widths, or padded representations.

### Access order

The abstract access sequence establishes these ordering constraints:

- The first word’s replacement precedes acquisition of the second word’s input.
- The second word’s replacement precedes acquisition of the third word’s input.
- The third word’s replacement precedes the fourth-word calculation and final halfword write.

Each of the first three replacements uses one full-word input-value evaluation. The final calculation contains two full-word value evaluations at the fourth position. Their relative evaluation order is not established.

With stable ordinary memory, both fourth-word evaluations obtain the same value, so their unspecified relative order does not affect the result.

These are source-level value-access and sequencing properties, not machine-transaction guarantees. They do not establish physical load counts, instruction widths, atomic writes, or independently observable fourth-word reads. The concrete contract does not cover changing input or reads with external side effects.

### Repeated application

On little-endian storage, two normally completed applications restore the entire original sixteen-byte region.

On big-endian storage:

- Two applications restore the first three words.
- The first application generally destroys the fourth word’s original high numerical half.
- The fourth-word transformation is idempotent: once applied, further applications leave that word unchanged unless it is independently modified.

Consequently, repeated application is not generally an inverse for the entire region on big-endian storage.
