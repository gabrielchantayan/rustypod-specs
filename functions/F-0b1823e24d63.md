# F-0b1823e24d63

## Purpose

F-0b1823e24d63 conditionally changes a 64-bit position, a related 64-bit accounting value, and a table of 32-bit run pairs. A dependency selects between a direct position update, run processing, and return without either operation.

Failures can follow observable progress. Position normalization, table changes, accounting updates, and dependency effects are not visibly rolled back. Every ordinary return writes a two-word position difference, then optionally invokes a final dependency.

“Run,” “accounting,” and “publication” describe structural roles. Their interpretation as allocation or extent management is inferred intent, not an established domain contract.

## Behavior

### 1. Entry admission

The function first reads a status from static storage.

The entry gate interprets the incoming increment’s high word as signed and incorporates the incoming carry bit. The supplied signed-overflow expressions establish that the gate opens when the mathematical signed high-word value plus the carry bit is negative:

- Carry clear: the high word is negative.
- Carry set: the high word is less than −1.

A closed gate goes directly to the common return tail with the entry-time static status.

An open gate reads the primary position and adds the incoming increment without storing the sum. Admission rejects exactly those resulting bit patterns whose high word is `0xFFFFFFFF` and whose low word is at least `0x80000000`. Equivalently, the unsigned result lies in `0xFFFFFFFF80000000` through `0xFFFFFFFFFFFFFFFF`.

Rejection goes to the common tail with the entry-time status. This is a specific rejection interval, not a general signed-overflow rule.

### 2. Candidate increment and count limit

F-3594f32e3fe8 is called, and its 32-bit result becomes the retained count. Multiplying that count by the unsigned unit size produces the candidate increment. The local status becomes zero.

If the unit size is less than the primary object’s unsigned threshold at +40, F-3594f32e3fe8 is called again with the candidate product’s low and high words as visible arguments. Its second result is not explicitly used.

The function subsequently reads the context field at +2. If it equals `0x4244`, it adds the candidate increment to the then-current primary position and applies the same rejection interval as above.

A rejected product-plus-position check causes a **second read of static status storage**, after the count-producing call and any optional second call. The function reloads that status before examining mode:

- Nonzero mode goes directly to the common tail with this newly read status.
- Zero mode continues after decrementing the count modulo \(2^{32}\) and subtracting one unit size from the candidate increment modulo \(2^{64}\).

The zero-mode adjustment also produces a local decrement-underflow marker: zero when the original count was nonzero, and all ones when it was zero. That marker does not participate in a reachable nonzero-mode limit decision.

Whenever nonzero mode reaches the context-limit comparison, the local high-word marker is zero. The condition is therefore exactly:

**unsigned retained count ≤ unsigned context limit at +360.**

Failure selects −34 and enters the common tail. Zero mode bypasses this comparison entirely, including after count underflow.

### 3. Dispatch

The function snapshots the primary position before calling F-0c688a5353e6 with the context pointer.

**Result zero:**

1. Store the saved position plus the candidate increment into the primary position.
2. Read the related-object pointer and accounting value, then add the candidate increment to accounting.
3. Read the primary flag byte and set bit 7 while preserving other bits.

The status is zero. A position change performed by F-0c688a5353e6 is overwritten because the position calculation uses the pre-call snapshot. Accounting is read after the call and after the position write.

**Result other than zero or 16:** retain that result and enter the common tail without a branch-local position increment.

**Result 16:** enter run processing.

### 4. Normalize before processing runs

The normalization target is the unsigned 64-bit product of unit size and accumulated unit count. The function reads the current primary position after dispatch and computes the modulo-\(2^{64}\) adjustment from that position to the target.

The adjustment’s low word is written to scratch storage even when the adjustment is zero. This storage is also the word immediately following the later publication descriptor’s known prefix.

For a nonzero adjustment, the function then:

1. Writes the target to the primary position.
2. Adds the adjustment to related accounting, explicitly writing its low word before its high word with carry.
3. Sets primary flag bit 7.
4. Subtracts the adjustment from the remaining candidate increment.

These effects precede the first run attempt. Later failure does not visibly undo them.

### 5. Attempt and commit runs

Each iteration reads the current table entry’s start and length and forms their wrapping 32-bit sum. F-b775eff8d313 receives:

#### Status −34

Otherwise:

- On the first −34, set status to zero, disable the retry allowance, and evaluate the loop continuation condition without committing a run or directly advancing position.
- On a later −34, proceed to run commit only if the **proposed run length** is nonzero.

The allowance is not reset by successful progress. The first −34 does not guarantee another call: if the remaining increment is zero, the loop terminates with status zero.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless specified, dependencies return normally without changing the illustrated state.

1. **Closed entry gate.** High word zero with carry clear skips processing dependencies and returns the entry-time static status. Output is still written; an already-enabled finalization flag still causes finalization.

2. **Admission boundary.** An admitted sum of `0xFFFFFFFF80000000` is rejected. `0xFFFFFFFF7FFFFFFF` is outside the rejection interval.

3. **Observable status reload.** Let entry-time static status be 5. Suppose the count dependency changes that storage to 9, the context field is `0x4244`, and the product-plus-position check rejects. Nonzero mode returns 9, not 5, after the common tail.

4. **Unsigned count limit.** In nonzero mode, an admitted retained count of 7 passes limit 7 and fails limit 6 with −34. A decrement-underflow marker cannot affect this comparison.

5. **Zero-mode decrement underflow.** If count zero produces a rejected product-plus-position check in zero mode, the adjusted count becomes `0xFFFFFFFF`, and the candidate increment loses one unit modulo \(2^{64}\). The context-limit comparison is bypassed.

6. **Direct progress.** With admission and limits satisfied, unit size 4096, retained count 2, and dispatch result zero, position and accounting each increase by 8192 modulo \(2^{64}\); flag bit 7 is set.

7. **Normalization survives failure.** Unit size 4096, accumulated count 3, and current position 8192 produce a normalization adjustment of 4096. A subsequent ordinary error from the first run attempt leaves position at 12288 and accounting increased by 4096.

8. **Later −34 uses proposed length.** After the retry allowance is consumed, a −34 result with proposed length zero stops even when the current table length is 5. A nonzero proposed length instead permits the commit path.

9. **Zero-remainder first −34.** In unrestricted processing with zero remainder, the first −34 becomes zero, and the loop ends without a second attempt or direct run commit.

10. **Publication storage and failure.** At a first replacement, descriptor-relative +12 contains the normalization adjustment’s low word, absent intervening mutation. Only the 12-byte prefix is established as descriptor construction. A publication failure leaves the rewritten table visible.

11. **Restricted partial progress.** A committed run leaving a nonzero remainder returns −34 after table, position, accounting, and flag updates.

12. **Finalization follows output.** If finalization changes position, the output remains the difference computed before that call.
