# F-d806c27da772

## Purpose

F-d806c27da772 conditionally updates records within a mutable context. An initial mode read selects ascending or descending traversal. Selected records undergo opaque identifier operations, incremental bookkeeping, and, in descending traversal, optional numerical processing and indirect callbacks.

The result is not an aggregate success status:

- Normal ascending completion returns 0 even if record operations failed.
- Normal descending completion returns 0 if any state-eligible record had unequal secondary and target identifiers; otherwise it returns 3.
- A nonzero entry-operation result immediately returns 3.

Ordered-structure maintenance and position-like callback coordination are inferred intent, not established domain semantics.

## Interface

### Input, result, and storage requirements

The input is a context address represented by 32 bits. The result is a 32-bit value, with explicit return values 0 and 3.

No null check, storage-size check, count validation, address-overflow check, or callback validation is visible. Every executed access requires accessible storage. Dependencies must supply any output subsequently consumed for behavior to be defined.

Offsets below are byte offsets. No maximum record count or guarantee that records are disjoint from fixed context fields is established.

### Workspace and callback

A contiguous temporary workspace contains three 32-bit words:

1. Candidate identifier, not initialized at invocation entry.
2. Local failure status, initialized to 0 before the initial context-helper call.
3. Entry/exit argument, initialized after that helper returns to context plus `0x13a8`.

Candidate-producing calls receive the first word’s address. Their write extent is unknown; preservation of adjacent words is not established. Each entry or exit call loads its argument from the third word as it then exists.

The callback is obtained through the object referenced at context `0x107c`: the object’s first word identifies a dispatch structure whose entry at byte offset `0x10` is invoked. Arguments are an object address and a 32-bit arithmetic value. The representation also loads the object field to supply the object argument; it does not establish one cached object load shared by dispatch resolution and argument preparation.

No direct allocation, release, or ownership transfer is visible. Dependency ownership behavior and retention of temporary addresses remain unknown.

## Behavior

### Entry, traversal selection, and completion

F-efbfec7ec1c8 receives the context before mode selection. Its return is ignored. The workspace’s third word is then initialized.

The subsequent mode read selects one traversal family:

- Mode 2 selects descending traversal.
- Any other value selects ascending traversal.

Later mode changes do not switch families. Ascending processing may nevertheless reread mode for other decisions.

Every attempted record operation begins with F-f0216cff9365, using the current entry handle and workspace third word. Nonzero return immediately returns 3, omitting both the matching exit operation and final context helper.

After successful entry, record failure normally proceeds to F-2bb3dbfa7286. This exit call reloads its handle and workspace argument. Nonzero exit return writes 3 to local status without terminating traversal.

Normal traversal completion invokes F-efbfec7ec1c8 again. “Entry” and “exit” describe placement only; locking or resource-management semantics are unproven.

### Ascending traversal

The index begins at zero. Each iteration condition rereads the signed count. Dependency mutations may therefore change the remaining extent.

One state byte is read using the state-address global for that access. The captured byte is compared with both 2 and 3. Either value excludes the record.

Otherwise, eligibility requires current different from target and target different from `0xffffffff`. The entry operation follows.

After successful entry:

- Saved different from boundary records failure and proceeds to exit.
- Equality causes current to be copied into saved before candidate production. Later failure does not undo this write.

#### Candidate production and midpoint selection

The optional flag is read first. Mode is read for this decision only when the flag is nonzero. F-ce5add3994af then receives the operation handle, current, target, and workspace address. Nonzero return abandons remaining record work.

If the inspected flag was zero or the inspected mode was zero, processing uses the produced candidate directly.

Otherwise, F-0b688265fbea is called for current and, only on success, for candidate. Each receives context and two output addresses. Either failure records record failure.

The candidate pair is added together, then added to the first current output; this signed 32-bit expression is divided by two. For representable arithmetic, division truncates toward zero.

A positive result resets the workspace candidate to the then-current identifier and initializes a search from the current lookup pair. Mode is reread. Only zero permits searching, despite the earlier nonzero-mode requirement; intervening dependency mutation can make this reachable.

While the search start is below the midpoint:

- If start plus extent reaches the midpoint, the search identifier becomes the workspace candidate.
- Otherwise, F-8fce2b40d724 advances the search identifier, followed on success by F-0b688265fbea to obtain a new pair.

Advance or lookup failure ends searching without taking the general record-failure branch. The retained workspace candidate is still used. No progress bound or cycle detection is visible. A nonpositive midpoint leaves the originally produced candidate unchanged.

#### Rearrangement and writes

The optional flag is reread. If nonzero, F-8fce2b40d724 obtains a further identifier from the candidate into separate temporary storage. Failure abandons remaining work.

F-e3a1bffa31a1 then receives candidate and boundary. Only success permits a second call with secondary and current. Either failure abandons remaining work.

After both succeed, the optional flag is read again:

- Zero selects the then-current target as new current.
- Nonzero selects the further-identifier temporary.

Current is written first. For the nonzero case, saved is then copied into `+0x20`. Secondary is finally written from the workspace candidate.

A zero-to-nonzero flag change between optional identifier production and final selection can select a temporary not initialized on that path. Because the temporary is not reset per record, it may instead contain an earlier value. No defined fresh-output guarantee exists.

Normal ascending completion returns 0, irrespective of local failure status.

### Descending traversal

The signed count is read once. The index is decremented before each nonnegative-index test, starting with count minus one.

State filtering performs conditional accesses:

1. Read a byte using the state-address global; value 2 excludes the record.
2. Otherwise, read a byte using the global again; value 3 excludes the record.

These are not comparisons against one captured byte or necessarily one address. No order beyond the conditional first-then-second access is established for external changes to the global or addressed storage.

Three local controls begin as: no work encountered, prior processing not established, and signed running maximum zero.

For a record passing state filtering, equal secondary and target cause a direct `0xffffffff` write to `+0x40`, without entry or exit.

Unequal identifiers establish “work encountered” before attempting entry. Later failure does not clear it.

#### Initial callback

After successful entry, an initial callback is attempted only when the optional flag is zero and prior processing has not been established.

Its argument is twice record `+0x28`, minus record `+0x2c`, minus context `0x138c`. A negative result is replaced by zero.

Nonzero callback return records failure and skips common work. Zero establishes prior processing before common work; later failure does not roll this back.

## Side effects

Updates are incremental, not transactional. Saved identifiers, markers, rearrangements, sentinel writes, and dependency effects can survive later failure. No explicit marker clearing is visible.

Handles and many context or record inputs are reloaded at use sites. No general snapshot guarantee exists across dependencies. Unspecified argument evaluation order must not be converted into a stronger read-order contract.

The state-address global is used at every executed state access. Numerical globals A and B are consumed at their argument evaluations after conversion returns. No dependency is assumed to preserve any of these globals.

Workspace output writes may affect adjacent status and entry/exit argument words. The status word does not determine normal return, but changed neighboring words can alter subsequent calls.

No dependency is assumed to preserve globals, avoid ownership changes, or discard addresses passed to it.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless varied explicitly, assume accessible storage, representable arithmetic, stable relevant inputs, successful dependencies, valid outputs, and preservation of adjacent workspace words.

1. **Empty traversal:** Count zero reaches both context-helper calls. Ascending returns 0; descending returns 3.

2. **State access counts:** Ascending performs one state-byte read per visited record. Descending performs one when its first value is 2, otherwise two.

3. **Changing state address:** In descending traversal, suppose the first displacement observation addresses a byte containing 3 and the second addresses a different byte containing 2. Both tests pass. A first byte equal to 2 suppresses the second state access entirely.

4. **Ascending guard failure:** Saved unequal to boundary produces entry and exit calls, but no candidate production. Normal completion still returns 0.

5. **Ascending success:** With optional processing stably zero, saved receives old current before candidate production. After both rearrangements succeed, current becomes target and secondary becomes candidate.

6. **Entry failure:** Nonzero entry return immediately produces 3, without matching exit or final context helper.

7. **Workspace mutation:** If candidate production changes the third workspace word, a subsequent exit loads that changed value. A later entry also uses it unless intervening behavior changes it.

8. **Descending matched identifiers:** Equal secondary and target cause only the direct sentinel write on that record. If no record requires work, normal return is 3.

9. **Descending failure persistence:** Initial callback failure still leads to exit and normal return 0 because work was encountered. Candidate failure after marking retains all four preliminary writes.

10. **Adjustment failure:** Nonzero F-d31de91d1e1b return suppresses F-502c68bf367d but does not suppress rearrangement.

11. **Cached callback input:** With prior processing established, a cached `+0x28` value of 30000 and updated maximum 1000 produce callback argument 9000. A later mutation of the field to 90000 by F-d7be9cfb4000 does not change that argument.

12. **Denominator observations:** Two observations of −9 produce −1. Main observation −9 and correction observation +9 produce −2 under the represented signed-shift arithmetic. Neither case establishes read order.

13. **Mutable numerical globals:** If F-0ec3a2a1b51e changes numerical globals A and B, and they remain stable afterward, F-c4b34006a13c receives the changed values. Entry-time values are not substituted. Changes during argument preparation require reasoning about each observation independently; no A-before-B order is promised.
