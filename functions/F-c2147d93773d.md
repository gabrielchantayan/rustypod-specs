# F-c2147d93773d

## Purpose

F-c2147d93773d clears the least-significant bit of one selected 32-bit storage location through a read-modify-write operation.

The input selects a location at a 32-byte stride. Inputs below four use a fixed address region; all other inputs use a base value obtained from a global data location. The function accesses the 32-bit word four bytes into the selected stride.

This is an address-based behavioral contract. The available evidence does not establish whether the selected word is ordinary memory, a device register, or another mapped resource. Descriptions such as “disable a channel,” “acknowledge an event,” or “release an object” would therefore be inferred intent, not established behavior.

## Interface

**Input:** One unsigned 32-bit integer, interpreted as a selector.

**Output:** No return value.

**Explicit memory effect:** A 32-bit value is read from the selected address, its bit zero is cleared, and the resulting 32-bit value is written to that same address.

The supplied representation supports a 32-bit unsigned arithmetic model. Under that model, selector multiplication and address addition retain their low 32 bits. Address calculations below use this model; their suitability for a particular executable environment remains a precondition rather than a safety guarantee.

The interface exposes no length, allocation size, permission information, error-result parameter, or ownership token. It performs no visible validation that the computed address belongs to a valid object or mapped register.

For a normal completion, the following environmental conditions are required:

- The selected target supports the indicated 32-bit read and write.
- For selectors of four or greater, the global base-value location is readable.
- The calculated address is meaningful in the execution environment.
- Any alignment, access-width, or device-specific requirements are satisfied.

These are caller or environment obligations. The function does not check them.

## Behavior

### Address selection

Let \(n\) be the unsigned 32-bit input. Let \(A\) denote the address of the word to modify.

For \(n < 4\):

\[
A = \texttt{0x3C700004} + 32n
\]

The four selected addresses are:

| Input | Target word address |
|---:|---:|
| 0 | `0x3C700004` |
| 1 | `0x3C700024` |
| 2 | `0x3C700044` |
| 3 | `0x3C700064` |

This branch does not evaluate the global base value.

For \(n \geq 4\), let \(B\) be the base value obtained from the global data location:

\[
A = (B + 32n + 4) \bmod 2^{32}
\]

The selector is not rebased at the branch boundary. In particular, selector four contributes an offset of 128 bytes before the additional four-byte word offset. It does not select \(B+4\).

There is no visible upper-bound check. Every unsigned input of four or greater follows the global-base branch, including inputs whose multiplication wraps in the 32-bit arithmetic model.

The fixed-base branch produces four-byte-aligned addresses. For the global-base branch, the target has the same alignment modulo four as \(B\), because both the stride contribution and the final offset are divisible by four. No alignment correction occurs.

### Read-modify-write transformation

After selecting the address, the function reads one 32-bit value from that address. Let this read value be \(R\). The value supplied to the subsequent write is:

\[
W = R \mathbin{\&} \texttt{0xFFFFFFFE}
\]

Consequently:

- Bit zero of \(W\) is zero.
- Bits one through thirty-one of \(W\) equal the corresponding bits of \(R\).
- If \(R\) is odd, \(W\) is one less than \(R\).
- If \(R\) is even, \(W\) equals \(R\).

The write occurs even when bit zero was already clear. There is no conditional skip for an unchanged value.

For ordinary, stable, writable memory without concurrent interference, the resulting stored value is \(W\). For device-backed or otherwise side-effecting storage, this equation describes the value submitted to the write; it does not establish the device’s resulting internal state or the value of a later read.

### Access ordering

1. For selectors of four or greater, obtain the global base value needed for address selection.
2. Read the selected 32-bit target word.
3. Write the masked 32-bit value to the same selected address.
4. Return without a value.

For selectors below four, the first access is unnecessary and is absent from the supplied behavior.

The visible operation includes one target-word read and one target-word write. It does not include a second target read for verification, a retry loop, or a separate success check.

This logical ordering does not establish volatile semantics, processor barriers, bus transaction details, or ordering relative to unrelated accesses. Those properties require information not supplied here.

## Side effects

### Target storage

The explicit modification is confined to the selected 32-bit word. The value written preserves the upper 31 bits of the value actually read and clears its lowest bit.

This is not an atomic bit-clear operation. Another actor can modify the word between the read and write. A later write from this function can therefore overwrite concurrent changes to bits other than bit zero, even though its own mask preserves those bits from its earlier read.

For example, if another actor sets bit two after this function reads the word, the function’s subsequent write may restore bit two to its previously read value. No locking, compare-and-exchange, or retry mechanism is visible.

### Global base storage

The global base value is consulted only for selectors of four or greater. No separate write to that global location is visible.

That does not prove that the global location is unchanged in every environment. The computed target could alias it, and mapped storage could have indirect side effects. The available evidence provides no non-aliasing guarantee or memory-map definition.

### Ownership and resources

No allocation, deallocation, ownership transfer, or reference-count operation is visible. The input is a numeric selector, not an explicit owned resource handle.

The function neither returns the selected address nor exposes the value read before modification. It provides no restoration mechanism for the cleared bit.

### Repeat invocation

For stable ordinary memory, applying the function repeatedly to the same selected location is value-idempotent: after the first successful call, later calls write the same value unless another actor changes the word.

Repeated calls are not necessarily side-effect-idempotent. Each call still performs a read and a write, and either access may matter for mapped devices or access-observing environments.

## Acceptance examples

These are conditional contract examples, not results of executed tests.

### Fixed-region selection

Given input zero and ordinary writable storage at `0x3C700004`, if the target read produces `0xA5A5A5A5`, the function must submit a 32-bit write of `0xA5A5A5A4` to that address.

Given input three, the target must be `0x3C700064`. The global base value must not be needed for this branch.

### Boundary between address regions

Given input four and a global base value of `0x20000000`, the target must be `0x20000084`.

Selecting `0x20000004` would violate the contract: the input is not reduced by four before the stride calculation.

### Already-cleared bit

Given any valid selected location whose read value is `0x12345678`, the function must still submit a write of `0x12345678`.

An implementation that omits this write would not preserve the observable access behavior.

### Mask boundaries

Under ordinary-memory assumptions:

| Target read value | Required write value |
|---:|---:|
| `0x00000000` | `0x00000000` |
| `0x00000001` | `0x00000000` |
| `0x80000001` | `0x80000000` |
| `0xFFFFFFFF` | `0xFFFFFFFE` |

The high bit is preserved; the mask does not impose signed-value semantics.

### Arithmetic wraparound

Under the stated 32-bit arithmetic model, input `0x08000000` has a stride contribution of zero modulo \(2^{32}\). It therefore selects \(B+4\), also reduced modulo \(2^{32}\).

Input `0xFFFFFFFF` has a stride contribution of `0xFFFFFFE0`; its final target is \(B-28\), modulo \(2^{32}\).

These examples establish calculated addresses only. They do not establish that those addresses are safe or valid to access.

### Concurrent modification

If the target read produces zero and another actor writes four before this function writes, this function may subsequently write zero. Preserving the concurrent actor’s update is not a guaranteed behavior.
