# F-4bda01947d15

## Purpose

F-4bda01947d15 routes a supplied record through a context-associated subsystem. Depending on an enable mask and a classification result, it:

- Dispatches the original record to a type-selected handler.
- Makes conditional calls that may transform or process the record.
- Produces a preliminary record-like value, dispatches it to handler 0, and then dispatches the original record.
- Performs an additional classification-specific operation.
- Invokes a nonreturning dependency on selected rejection or failure paths.

Established behavior includes shared-mask initialization, field capture, parameter selection, dependency calls, indirect dispatch, and return-value selection. The body does **not** establish that the supplied record is mutated: it passes the record to dependencies whose effects are unknown.

“Classification,” “transformation parameter,” and “preliminary value” describe observable roles, not established domain meanings.

## Interface

### Arguments and accessed layouts

The supplied representation uses 32-bit addresses, integer-sized arguments, and return values.

The first argument is a **context address**. A 32-bit field at byte offset +0x150 supplies the subsystem value. The function rereads this field for separate operations rather than retaining one subsystem snapshot.

The second argument is a **record address**. The body accesses:

| Record offset | Width | Use |
|---|---:|---|
| +0 | 32 bits | Captured on nonzero-classification paths and passed to later dependencies. |
| +0x0E | 8 bits | Type byte, used both for conversion and mask-bit selection. |
| +0x10 | 16 bits, unsigned | Attribute, widened to 32 bits. |

These accesses do not establish the record’s complete layout or allocation size.

The type byte is converted through a plain-character representation to a 32-bit integer. Values 0–12 have unambiguous routing behavior. High-bit bytes require additional signedness and execution-model information; they are not assigned ordinary supported behavior here.

The attribute is zero-extended. Subsequent decisions use this captured value, not a refreshed record-field read.

### Result

The normal result is an uninterpreted 32-bit value, initially 9. It can be replaced by:

- The indirect operation used for ordinary dispatch.
- F-256e8a77aa59.
- F-b816af9a7d2b.

The function does not normalize those results. No status meaning is established for 9 or any dependency result.

Selected paths invoke dependencies identified as nonreturning and have no normal return under that designation.

### Preconditions

Ordinary defined execution requires:

- A record acceptable to F-5f5f14cedda3 and readable at the accessed offsets.
- A readable context subsystem field whenever evaluated.
- Valid shared pointers and readable shared words; writable mask storage when initialization occurs.
- Valid handler objects, operation tables, and callable entries on dispatch paths.
- Valid subsystem-relative addressing at byte offset +4.
- A defined mask-shift operation.
- Satisfaction of each dependency’s argument requirements.

There is no initial null-record validation. A later null comparison occurs only after the initial dependency call and record-field reads; it does not make null input supported.

## Behavior

### 1. Capture initial state and conditionally initialize the mask

The initial sequence is:

1. Establish the default result, 9.
2. Call F-5f5f14cedda3 with the record and retain its 32-bit result as the **key**.
3. Capture the shared mask-storage address and read the initial 32-bit mask contents.
4. Read the type byte and perform its character-to-integer conversion.
5. **Only if the initial mask word was zero, read and capture the fallback-storage pointer.**
6. Read and zero-extend the record’s 16-bit attribute.
7. **Only if the initial mask word was zero, dereference the captured fallback pointer and copy that 32-bit word into mask storage.**

The fallback pointer is therefore obtained **after type conversion but before attribute capture**. The fallback word is obtained **after attribute capture**. The fallback address is not established as constant, and pointer capture must not be conflated with dereferencing it.

The initialization destination is expressed through the shared mask-storage pointer again. The later enable-bit check explicitly uses the address captured earlier. With stable shared pointer storage, both designate the same word; no synchronization or concurrent pointer-change guarantee is established.

The decision to initialize depends on the **initial** mask word. A zero fallback word is still written; there is no retry loop. Initialization precedes type rejection and subsystem preparation.

F-5f5f14cedda3 executes before these captures. Its unknown effects may therefore influence the subsequently read record fields or shared state.

### 2. Enforce the type’s upper bound

If the converted type is greater than 12, invoke nonreturning F-a817d8d58c10.

This check has no explicit lower bound. It is not complete validation of every possible byte value.

On this rejection path, mask initialization may already have occurred. F-7c170ecfc86e has not been called, and the body shows no explicit record-release operation.

### 3. Prepare the subsystem and check enablement

For a type that passes the upper-bound check:

1. Read the context field at +0x150.
2. Call F-7c170ecfc86e with that subsystem value and the captured key.
3. Reread the mask word through the initially captured mask-storage address.
4. Test the bit selected by the **original unsigned type byte**.

For types 0–12, the selected bit is the corresponding bit of the 32-bit word.

Preparation precedes this mask read. If F-7c170ecfc86e changes that word, the subsequent check can observe the changed contents; the initial mask snapshot is not reused.

If the selected bit is clear:

- A null record takes an explicit return branch yielding 9, subject to all earlier accesses having been valid.
- A nonnull record is passed to F-09ba55c206ac, followed by nonreturning F-feee9156a257.

The body does not establish that F-09ba55c206ac destroys, releases, or mutates the record.

### 4. Classify the enabled record

Read the context subsystem field again and call F-3340ee3ffdc5 with:

1. The current subsystem value.
2. The captured key.
3. The converted type.
4. The captured unsigned attribute.

Retain its 32-bit result as the **classification**.

If classification is zero, perform ordinary direct dispatch immediately. This path does not read the shared transformation default, capture the record’s first word, or perform the preliminary-value probe.

### 5. Ordinary direct dispatch

Ordinary dispatch consists of:

1. Read the current context subsystem field and form its byte-offset +4 address.
2. Call F-9266831caef7 with that address and the captured type.
3. Read the returned object’s leading 32-bit operation-table address.
4. Obtain the callable entry at table byte offset +8.
5. Invoke it with the returned object as receiver and the original record as the second argument.
6. Return its 32-bit result.

No explicit null check protects the returned object or its operation table on this path.

This dispatch is used both for classification zero and after successful preliminary-value dispatch.

### 6. Select the transformation parameter

For every nonzero classification, first read the shared 32-bit default parameter. Apply these overrides:

| Captured type | Effective parameter |
|---|---|
| 0 | 2 |
| 2 or 4 | 1 |
| 3 or 11 | 0 |
| 9, attribute 128–138 inclusive | 128 |
| 12, attribute below 19 | 0 |
| Otherwise | Shared default |

The shared default is read even when an override replaces it.

The type-9 interval follows from **unsigned 32-bit subtraction**: subtracting 128 from the captured attribute must produce a value below 11. Attributes below 128 wrap and fail this comparison. With a 16-bit unsigned input attribute, precisely 128–138 satisfy it.

The exact 32-bit value **0x0000FFFF**, or 65535, suppresses the later transformation-and-processing pair. The 32-bit value 0xFFFFFFFF does not satisfy this sentinel comparison.

### 7. Capture the first word and probe for the special case

Read the record’s first 32-bit word. Then read the current subsystem field and call F-9d8c91d0e283 with its byte-offset +4 address and the captured key.

This probe occurs on **every nonzero-classification path**, including types and keys that cannot satisfy the special case. It also occurs when the effective transformation parameter is 65535.

The special case requires all three conditions:

- Captured type equals 2.
- Probe result equals zero.
- Captured key equals 1.

When selected:

1. Initialize a local 32-bit auxiliary value to 2.
2. Call F-cd7e1905512f with the captured first record word, scalar arguments 0, 0, and 1, the auxiliary value’s address, and a final scalar argument 1.
3. If the returned 32-bit value is zero, invoke nonreturning F-a817d8d58c10.
4. Otherwise, read the current subsystem field and look up handler 0 through F-9266831caef7 using the subsystem-relative +4 address.
5. Invoke that object’s operation at table byte offset +8 with the object as receiver and the preliminary value as the second argument.
6. Discard that operation’s result.
7. Perform ordinary direct dispatch for the original captured type and original record.

Only the latter dispatch result is returned.

There is no explicit null check for either handler object on this path. It bypasses F-09b5d9827724, F-256e8a77aa59, and the classification-3 follow-on stage, even when the classification is 3.

### 8. Outside the special case, optionally call the processing pair

Select a 32-bit processing-mode argument:

- 7 for classification 3 or 4.
- 4 for every other nonzero classification.

If the effective parameter is not 65535:

1. Call F-09b5d9827724 with, in order:
   - Original record address.
   - Captured first record word.
   - 0.
   - Captured converted type.
   - Effective transformation parameter.
   - Selected processing mode.
   - Captured unsigned attribute.
   - 0.
2. Disregard that call’s return value.
3. Call F-256e8a77aa59 with the original record and 0.
4. Use its 32-bit result as the eventual result.

These calls may mutate or process the record, but their actual effects are not established by this body.

If the effective parameter is 65535, skip both calls. The result remains 9 unless the next stage replaces it.

### 9. Apply the classification-3 follow-on stage

Only for classification exactly 3:

1. Read the current subsystem field.
2. Call F-bc2b33235f5b with its byte-offset +4 address and the captured key.
3. Interpret the returned bits as an unsigned 32-bit value.
4. Continue only if its low two bits equal binary 01.
5. Read the current subsystem field again and call F-9266831caef7 for handler 0.
6. If that result is zero, invoke nonreturning F-a817d8d58c10.
7. Otherwise, call F-b816af9a7d2b with that returned object and the captured key.
8. Replace the eventual result with this call’s result.

This stage can run after the processing pair or after its suppression by the sentinel. Classification 4 selects mode 7 but does not enter this stage.

## Side effects

The visible body reads record fields, context fields, shared pointer storage, mask words, the shared parameter default, handler objects, and operation tables.

Its explicit externally visible data write is conditional mask initialization. It does not explicitly write a record field. Dependency calls and indirect operations may have additional effects, but those effects are not established here.

Capture timing matters:

- The key is obtained before the type and attribute.
- The fallback pointer, when needed, is captured between type conversion and attribute capture.
- The fallback word is read afterward.
- The record’s first word is captured only after nonzero classification and parameter selection.
- Context subsystem values are read separately for successive operations.

Later dependency effects do not refresh already captured values. They may affect fields or globals that have not yet been read. No dependency is assumed to preserve globals.

The body establishes neither allocation nor direct deallocation. The preliminary value’s ownership, the record’s ownership, and whether any callee retains supplied addresses are unknown.

There is no visible rollback, cleanup guarantee, locking, or atomic initialization protocol.

## Acceptance examples

These are conditional consequences of static control flow, not executed tests. Unless otherwise stated, assume accessible storage, defined arithmetic, stable shared pointers, and normally returning dependencies except those designated nonreturning.

1. **Fallback capture order.** With an initially zero mask, the type is read and converted before the fallback pointer is captured. The attribute is then read before the captured fallback address is dereferenced and its word copied to mask storage.

2. **No initialization needed.** With a nonzero initial mask, the fallback-pointer read and fallback-word read are skipped. The later enablement decision still rereads the mask after F-7c170ecfc86e.

3. **Initialization before rejection.** With an initially zero mask and type 13, fallback initialization occurs before F-a817d8d58c10. Subsystem preparation does not occur.

4. **Preparation changes enablement.** For type 4, if F-7c170ecfc86e clears bit 4 in the captured mask storage, the following check takes the disabled-bit path.

5. **Disabled nonnull record.** F-09ba55c206ac receives the record before F-feee9156a257 is invoked. No release or mutation effect is implied by this sequence.

6. **Classification zero.** For enabled type 4 and classification zero, handler 4 receives the original record and its result is returned. The shared parameter default, first-word capture, and preliminary probe are bypassed.

7. **Type-9 boundaries.** For nonzero classification, attributes 128 and 138 select parameter 128; attributes 127 and 139 retain the shared default.

8. **Type-12 boundary.** Attribute 18 selects parameter 0; attribute 19 retains the shared default.

9. **Exact sentinel.** For type 1 and classification 2, default 0x0000FFFF suppresses both processing calls and leaves result 9. Default 0xFFFFFFFF does not suppress them. The probe occurs in either case.

10. **Special preliminary dispatch.** For type 2, key 1, nonzero classification, and zero probe result, a nonzero preliminary value is dispatched to handler 0 before the original record is dispatched to handler 2. Only the latter result is returned.

11. **Preliminary failure.** Under those special-case conditions, a zero preliminary result invokes F-a817d8d58c10 before either handler dispatch.

12. **Special case overrides follow-on eligibility.** If the special case is selected with classification 3, no flags query or F-b816af9a7d2b call occurs.

13. **Follow-on result replacement.** Outside the special case, classification 3, flags value 5, and a nonzero handler-0 result cause F-b816af9a7d2b to replace any prior processing result. Flags value 3 does not trigger this operation.

14. **Sentinel does not suppress follow-on.** For classification 3 and parameter 65535, eligible low flags bits still lead to the handler-0 lookup and follow-on call. A zero lookup result invokes F-a817d8d58c10.

15. **Classification 4.** Mode 7 is selected, but no classification-3 flags query occurs.

- **documented_only — dependency effects:** Mutation, memory retention, allocation, release, global changes, and internal failures remain unknown.
- **documented_only — return meanings:** Neither 9 nor any forwarded result has an established domain interpretation.
- **documented_only — layouts:** Only accessed offsets and widths are established; complete record, context, subsystem, and handler layouts are unknown.
- **documented_only — shared-state changes:** No synchronization establishes behavior for concurrent pointer or word updates.
- **documented_only — nonreturning mechanisms:** The evidence identifies nonreturning paths but does not establish whether they terminate execution, transfer control, or use another mechanism.
- **Inferred intent:** Type-aware routing and preparatory processing are plausible descriptions, not independent semantic guarantees.
