# F-31a843df4922

## Purpose

F-31a843df4922 is a non-returning, repeatedly executed sequence of indirect calls, memory reads, memory writes, and a software breakpoint.

The established behavior is the ordering and arithmetic of these operations. The supplied representation does not establish a higher-level purpose such as initialization, decoding, device control, or record processing. In particular, an infinite loop does not establish that successive iterations are safe: the represented execution-context base decreases on every completed iteration.

This contract describes the visible operations conditional on execution reaching them. An indirect call, invalid memory access, or breakpoint may prevent subsequent operations.

## Interface

**Explicit arguments:** None.

**Normal return:** None. The visible control flow has an unconditional back edge and no return statement. This does not establish that execution always reaches that back edge.

**Implicit inputs:**

- An incoming link-register value used to determine the first indirect-call target.
- An execution-context base used for several relative accesses and subsequently reduced by 244 bytes.
- An incoming register value used as part of a late byte-store address.
- Two global pointer slots, at `0x087120b4` and `0x08712120`.
- Memory reached through fixed addresses, loaded pointers, dependency results, and arithmetic-derived addresses.
- Dependency results conveyed as 16-bit, 32-bit, or paired 32-bit quantities.
- Additional register results whose calling convention and provenance are not established.

There is no visible input validation.

### Width and arithmetic conventions

The visible operations use:

- 8-bit byte reads and writes.
- 16-bit halfword reads and writes.
- 32-bit word reads and writes.
- 64-bit dependency results split into low and high 32-bit halves.

Unsigned 16-bit loads are zero-extended when subsequently used in 32-bit arithmetic. Halfword stores retain only the low 16 bits of their source. The explicitly unsigned right shift by 26 is logical and produces a value from 0 through 63.

For address calculation and shifted 32-bit bit patterns, this contract uses 32-bit arithmetic, retaining the low 32 bits. This is a description of the represented machine operations, not a claim that equivalent signed arithmetic would be portable in a high-level language. Exact processor overflow, alignment, and fault behavior remains unknown.

Endianness is not established. Widths and addresses are established independently of byte order.

### Names used below

The following are explanatory labels, not source identifiers:

- **Context base:** the implicit execution-context address, before its decrement within the current iteration.
- **First record:** the pointer captured from the first global pointer slot.
- **Table base:** the pointer later captured from the second global pointer slot.
- **Fixed index:** the zero-extended halfword read at `0x21c48994`.
- **Destination record:** the word loaded from fixed-index-relative offset `0x44`.
- **Secondary record:** the word loaded from address `0x2218`.
- **Selected index:** a later zero-extended halfword read from the secondary record.

Dependency labels F-D01 through F-D37 identify call occurrences for this contract. They are opaque cross-references, not authoritative recovered function identities. Some occurrences have the same computed target, as described under Dependencies.

- Context-relative reads and writes.
- A persistent 244-byte reduction of the represented context base per iteration reaching that point.
- A software breakpoint on every iteration that reaches it.

Aliasing is unrestricted by the evidence. A direct store can affect a later read if their addresses overlap. A dependency can change memory, globals, or execution state unless its independent contract establishes otherwise.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. They assume required calls return, addressed memory is accessible, and intervening effects do not invalidate the stated observations.

1. **Initial addition wraps at 32 bits.**  
   If F-D05 yields low word `0xffffffff` and high word `2`, F-D06 receives `0xffffffff` as its first argument and `1` as its second.

2. **Top-six-bit extraction differs from the shifted store.**  
   If F-D09 yields low word `0xfc000001`, the context-relative write at offset `0x26c` stores `63`. The later write at captured-pointer offset `0x54` stores `0xf0000004`.

3. **Captured pointer survives a pointer-slot change as an address value.**  
   If the first global slot contains address A when read, and F-D04 subsequently changes that slot to B, the direct stores at offsets `0x11` and `0x15` still use captured address A. Accessibility of A remains a separate precondition.

4. **Breakpoint termination prevents later operations.**  
   If the breakpoint transfers control without resumption, the table write, context decrement, final record updates, and next iteration do not occur along that execution.

5. **Table write truncates the pointer value.**  
   If the captured table base is `0x12345678` and F-D19 returns `3`, the halfword store targets `0x12345684` and writes `0x5678`.

6. **Selected value is zero-extended.**  
   If the halfword at final-pair high-word address plus `0x14` contains `0xffff`, the direct word writes at destination-record offsets `0x54` and `0x64` each write `0x0000ffff`.

7. **Byte read has no implicit record base.**  
   If the selected index is `7`, the late byte read addresses `35`, before F-D34. A replacement that instead reads record-base-plus-35 would not match the visible behavior.

8. **Context movement persists across iterations.**  
   If one iteration starts with context base S and reaches its decrement, the next iteration uses S minus 244 as its context base, provided execution continues normally and no dependency changes that state.
