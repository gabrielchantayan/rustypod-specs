# F-8475047b9e1d

## Purpose

F-8475047b9e1d coordinates mode-dependent operations on an object referenced through a caller-supplied context. It then performs a common sequence of checking, publication or registration, and conditional finalization.

The established behavior is a dispatcher with observable ordering requirements. Some modes invoke one dependency; two modes invoke three dependencies while protecting a single 32-bit object field from the third dependency’s changes. Unsupported modes write a fixed value to that field.

An apparent intent is to transition an object to a state represented by byte value 100 before finalization. That interpretation is inferred, not established: the meanings of the state byte, the protected field, the diagnostic arguments, and the finalization operation are not supplied.

The function has no explicit result value. Its observable results are dependency calls, memory writes, and whatever additional effects those dependencies produce.

If execution continues, the function reads the state byte again for dispatch. The dispatch value is therefore not necessarily the value observed by the entry check. In particular:

- F-bfade2068003 may have changed the byte.
- The function does not refresh its cached initial-object reference after that call.

If the initial byte is 100, the entry dependency is skipped, but the dispatch byte is still a separate read.

### 3. Protected-field operation for modes 6 and 7

1. Reads the 32-bit field at initial-object offset 40.
2. Calls F-85b845ed0ee9 with the original first argument and the context pointer.
3. Writes the saved 32-bit value back to initial-object offset 40.

The saved value is the value after the first two calls, not the value at function entry.

## Acceptance examples

These are conditional behavioral criteria derived from static evidence, not executed tests. Each assumes valid required storage and normal returns unless stated otherwise.

- Neither state-mismatch dependency is called.
- No mode-specific dependency is called.
- No direct write to offset 40 occurs.
- F-62673223987f runs before F-a29f2b98c4bc.

### Entry handling changes the selector

- Entry handling occurs first.
- Dispatch selects F-7a942ad521b9, regardless of the byte observed before entry handling.
- Later state decisions depend on their own reads.

### Mode 6 preserves the intermediate field value

- F-59029331d3eb runs before F-46cee3909c7d.
- If offset 40 contains 75 after those calls, 75 is saved.
- If F-85b845ed0ee9 changes that field to 90 and returns, the function writes 75 back.
- A different value present at function entry is not restored merely because it preceded the mode operations.

### Unsupported selector

Given dispatch value 255:

- No mode-specific dependency is selected.
- The function writes 32-bit value 33 at initial-object offset 40.
- It proceeds to the post-dispatch state check and common publication sequence.

### Context replacement does not replace the cached object

- Later state checks still read offset 16 of the initial object.
- Direct field writes still target offset 40 of the initial object.
- F-a29f2b98c4bc receives the context object reference read after F-62673223987f returns.

### Publication changes the finalization decision

- F-85722f62e20a is called.
- If subsequent dependencies make that same byte 100 before the final read, finalization runs.
- If it remains non-100, finalization is skipped.

### Exact finalization-result boundary

Given finalization runs:

- A result of −1 triggers the offset-4 read and indirect call.
- Results 0, 1, or −2 do not trigger that read or call.
- The branch is exact equality with −1, not a general negative-result test.
