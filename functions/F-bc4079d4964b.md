# F-bc4079d4964b

## Purpose

The first argument does not affect the result.

An inferred use is recognizing line-feed and carriage-return character values. That interpretation is not required by the established behavior: the function receives an integer, not a string or a character stream, and performs no decoding or normalization.

## Behavior

The function evaluates whether the second argument belongs to the two-element set containing 10 and 13.

The established comparison order is:

1. Test equality with decimal 10.
2. If that test is false, test equality with decimal 13.
3. Return the resulting Boolean.

The logical operation short-circuits: a match against 10 makes the second equality unnecessary at the expression level. This does not establish a particular machine-instruction sequence or branch structure.

The complete result relation is:

| Second argument | Result |
|---|---|
| 10 | True |
| 13 | True |
| Any other representable integer | False |

Both accepted values are exact matches. There is no interval check, masking, low-byte extraction, or tolerance for nearby values. For example, the values between and adjacent to the accepted values—9, 11, 12, and 14—are all rejected.

The first argument does not participate in either comparison. For a fixed second argument, changing the first argument cannot change the result established by the supplied body.
