# F-31b345a85bd2

## Purpose

F-31b345a85bd2 computes and stores two 32-bit quantities from a descriptor associated with an input object:

- A maximum adjusted size.
- An aggregate adjusted size.

The descriptor selects between two modes. A nonzero leading value supplies one size shared by all items. A zero leading value selects a table containing individual sizes. In either mode, the adjustment subtracts eight.

**Inferred intent:** the subtraction may remove a fixed per-item overhead. Neither the meaning of the sizes nor the units of measurement is established. The contract therefore uses “size” only as a descriptive label, not as a guarantee that values are nonnegative or measured in bytes.

The function has no explicit validation or error-reporting path. Its two output stores occur after the selected calculation finishes.

## Behavior

### Common entry sequence

The function first reads the descriptor pointer from object offset `0x1C`. It then reads the descriptor’s leading signed value.

That leading value selects the mode:

- Exactly zero selects individual-size table mode.
- Any nonzero value, including a negative value, selects shared-size mode.

The leading value is read once. The function does not re-read it to reconsider the selected mode.

Before processing sizes, the maximum and aggregate calculations start at zero.

### Individual-size table mode

The item count is tested using a signed comparison against an index that begins at zero.

If the count is zero or negative at the first test, no table entry is read. Both computed outputs remain zero.

For a positive count, entries are visited in ascending index order, beginning with entry zero. For each visited entry:

1. The entry’s signed value is reduced by eight.
2. The adjusted result is interpreted as unsigned for the maximum comparison and aggregate addition.
3. The maximum retains the greater of its current unsigned value and the adjusted unsigned value.
4. The aggregate incorporates the adjusted unsigned value.

The maximum comparison is strictly unsigned. There is no lower-bound clamp. In particular, an entry below eight can contribute a very large unsigned value rather than zero.

For subtraction results representable as signed 32-bit integers, conversion to unsigned follows the ordinary modulo-\(2^{32}\) interpretation. Thus an entry of four produces an adjusted unsigned value of \(4,294,967,292\), not zero.

The aggregate addition in this mode has an unsigned operand and therefore proceeds in the unsigned arithmetic domain in the supplied representation. Its 32-bit unsigned result is then assigned back to signed storage. If that result exceeds the signed range, the exact signed interpretation depends on the target’s unsigned-to-signed conversion behavior. A conventional bit-preserving interpretation is plausible, but the supplied material does not independently establish that implementation rule.

### Repeated reads in table mode

The count is read again for each loop-condition evaluation, including the final evaluation that ends traversal.

The table base is read for each visited entry. Consequently, the visible structure is not equivalent to taking one immutable snapshot of the count and table pointer before traversal.

### Shared-size mode

When the leading descriptor value is nonzero:

- The maximum is the shared size minus eight, converted to unsigned.
- The aggregate is the signed item count multiplied by the shared size minus eight.

The table-address field and table contents are not read in this mode.

The maximum does not depend on the count. A count of zero therefore does not force the maximum to zero. A negative count is also used directly; it is not rejected or treated as an empty collection.

Unlike table mode, the multiplication shown here is signed. If either the subtraction or multiplication exceeds the signed 32-bit range, the supplied representation does not establish a portable result.

### Final publication

After either mode completes, the function performs two writes in this order:

1. The unsigned maximum to object offset `0x180`.
2. The aggregate to object offset `0x184`.

There is no earlier output-field write.

The writes are separate. The function provides no transaction, rollback, or atomic publication guarantee for the pair. If execution fails during the second store, the first store may already have changed the object.

### Arithmetic boundaries

The following distinctions are material:

- **Negative counts:** table mode performs no iterations for an initially negative count; shared-size mode uses the negative count in multiplication.
- **Sizes below eight:** negative adjusted values are not clamped. Their conversion to unsigned affects the maximum and table-mode accumulation.
- **Subtraction underflow:** a signed size below \(-2,147,483,640\) cannot have eight subtracted within signed 32-bit range.
- **Shared-size product overflow:** a mathematically valid product is not sufficient; the signed intermediate must also fit the target’s signed 32-bit range for an unambiguous source-level result.
- **Table indexing overflow:** the displayed entry-offset calculation uses signed index multiplication by four. Indices above \(536,870,911\) exceed signed 32-bit range in that multiplication, independently of whether backing memory exists.
- **Table aggregate range:** unsigned addition can wrap modulo \(2^{32}\), but conversion of a high unsigned result back to the signed accumulator remains target-dependent.

No saturation, overflow diagnostic, or range validation is shown.
