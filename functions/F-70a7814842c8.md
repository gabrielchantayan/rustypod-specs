# F-70a7814842c8

## Purpose

F-70a7814842c8 reads and captures a 32-bit integer, optionally invokes an output-related dependency, and returns a value derived from two separate queries of the captured integer.

A captured value of zero produces an immediate return of −1. For a nonzero captured value:

- The first query determines a saved predicate indicating whether its lowest three bits are clear.
- A nonnull destination enables an intervening dependency call, optionally preceded by a direct zero-byte write.
- The second query supplies the input to the return arithmetic.
- The saved predicate and the arithmetic component are combined using unsigned 32-bit addition, followed by conversion to the signed return type.

Output preparation and size calculation are plausible **inferred intent**. The evidence does not establish the destination’s format, the meaning of the captured integer, or that the return value counts bytes written.

This contract separates established access and call ordering from arithmetic interpretations that require execution-model assumptions.

## Interface

### Required integer-location argument

The first argument identifies storage from which the function reads one 32-bit signed integer.

The function performs this read before testing the captured value or inspecting the destination. There is no explicit check for a null pointer, inaccessible storage, unsuitable alignment, or expired lifetime.

The captured integer is subsequently passed by value. Its semantic role is unknown; it is not established to be an address, resource handle, length, or ownership token.

The function does not reread the original integer location.

### Optional destination argument

The second argument is either null or a pointer to byte-addressable storage.

A null destination suppresses both:

- The function’s direct byte write.
- The call to F-29c531f09e4a.

It does not suppress the two calls to F-ae3bc1bfd2a8 on the normally completing nonzero-input path.

For a nonnull destination, the function passes either that address or an address advanced by exactly one byte to F-29c531f09e4a. It may first write one zero byte at the original address.

There is no capacity argument or local bounds check. The required storage extent cannot be determined without the dependency’s contract.

### Return value and widths

The return type is a signed 32-bit integer in the supplied representation. The relevant arithmetic uses both signed and unsigned 32-bit values; the direct destination write occupies one byte.

The zero-input branch returns signed −1 directly.

On the nonzero-input branch, the final return expression is an **unsigned 32-bit value**, because the saved predicate is unsigned. Conversion of that expression to the signed return type is a separate operation. Values exceeding the signed maximum require an execution-model rule; they must not be described unconditionally as a portable negative return.

Pointer width, calling convention, and byte order are not established.

## Behavior

### Capture and zero-input branch

The function first reads and retains the required integer.

If the captured value is zero:

- It returns −1.
- Neither dependency is invoked.
- No destination byte is written.
- The destination is not dereferenced.

The required integer read still occurs. An invalid required pointer is not handled by the zero-value branch.

### First query and saved predicate

For a nonzero captured integer, the function invokes F-ae3bc1bfd2a8 with that integer.

The first query result is represented as an unsigned 32-bit value for the predicate calculation. The saved predicate is:

- **1** when the lowest three bits are all zero.
- **0** otherwise.

The predicate itself is unsigned 32-bit.

A first query result of zero therefore produces predicate 1. Negative results are not rejected as errors; their converted unsigned representation supplies the tested bits. Under the stated 32-bit interpretation, conversion of a signed negative value to unsigned uses reduction modulo \(2^{32}\).

Only the predicate is retained for subsequent decisions. The first query result is not substituted for the second query result.

### Optional destination processing

If the destination is null, the function makes no destination-related call or direct write.

If the destination is nonnull and the saved predicate is 1:

1. The function writes one zero byte at the original destination.
2. It invokes F-29c531f09e4a with the captured integer and the destination advanced by one byte.

If the destination is nonnull and the predicate is 0:

- There is no direct destination write.
- F-29c531f09e4a receives the captured integer and the original destination.

The direct zero-byte write, when present, occurs before the dependency invocation. This does not guarantee that the byte remains zero afterward: the dependency’s complete memory effects are unknown.

No result from F-29c531f09e4a is inspected or explicitly propagated.

### Second query

After destination processing, the function invokes F-ae3bc1bfd2a8 again with the same captured integer.

This second query occurs whether the destination is null or nonnull. It also occurs regardless of the first query’s numeric value or saved predicate.

The second result is held as a signed 32-bit integer and supplies the return arithmetic. The function does not compare the two query results or require them to agree.

All later behavior is conditional on earlier dependency calls returning normally. A dependency that traps, transfers control elsewhere, or does not return prevents subsequent operations from being reached.

### Return arithmetic: established structure

Let \(p\) denote the unsigned predicate, either 0 or 1, and let \(n\) denote the second query result as a signed 32-bit integer.

The arithmetic has three materially distinct boundaries:

**Signed addition and sign-dependent adjustment.** The computation uses signed \(n+7\). A signed right shift by 31 positions supplies a value that is converted to unsigned 32-bit and logically shifted by 29 positions. Under arithmetic signed right shifts, that adjustment is 7 when \(n+7\) is negative and 0 otherwise.

**Unsigned intermediate and signed arithmetic component.** Adding the adjustment involves unsigned 32-bit arithmetic. The resulting unsigned value is converted to signed 32-bit, then right-shifted by three positions to obtain the arithmetic component, denoted \(q\). A conversion outside the signed range and a right shift of a negative signed value each require an execution-model rule.

**Unsigned final addition and signed return conversion.** Because \(p\) is unsigned, combining \(p\) with \(q\) converts \(q\) to unsigned 32-bit and performs addition modulo \(2^{32}\). The resulting unsigned value is then converted to the signed return type.

Thus, even when \(n+7\) is representable, the complete negative-result behavior is not established by a portable signed-arithmetic interpretation alone.

### Conditional arithmetic interpretation

Under an execution model with:

- Arithmetic right shifts for negative signed 32-bit values; and
- Unsigned-to-signed conversions that preserve the 32-bit pattern, interpreting values above \(2^{31}-1\) as negative;

and provided \(n+7\) is representable as signed 32-bit, the arithmetic component is:

\[
q=\operatorname{trunc}_{0}\left(\frac{n+7}{8}\right)
\]

Here \(\operatorname{trunc}_{0}\) means truncation toward zero.

The final unsigned expression is:

\[
U=\bigl(p+(q\bmod 2^{32})\bigr)\bmod 2^{32}
\]

Under the same bit-preserving signed conversion rule, the signed return equals the mathematical sum \(p+q\). This is a **conditional interpretation**, not an unconditional replacement for the actual unsigned final addition.

For:

\[

the signed addition is representable, the relevant signed shifts operate on nonnegative values, and the unsigned-to-signed conversions remain within the signed range. In this interval, the truncation formula and nonnegative return do not depend on rules for negative signed shifts or out-of-range unsigned-to-signed conversion.

For smaller \(n\), those rules matter. For example, when \(n=-16\), the conditional arithmetic component is −1. With \(p=0\), the final unsigned expression is `0xffffffff`; obtaining signed −1 from it requires the stated return-conversion rule.

## Side effects

This is an access-order property, not permission for every overlapping arrangement. Validity under the applicable memory model and dependency contracts remains unresolved.

### Ownership and errors

The explicit local rejection is a captured integer of zero. There is no visible classification of query results as success or failure, and no local recovery from invalid storage, insufficient capacity, or dependency failure.

A return of −1 is not established as uniquely identifying the zero-input branch. Under the conditional arithmetic model, a nonzero-input invocation can also return −1.
