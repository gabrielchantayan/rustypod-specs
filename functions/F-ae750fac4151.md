# F-ae750fac4151

## Purpose

F-ae750fac4151 selects between an operation supplied by a receiver and an operation reached through an external lookup. Selection depends on whether a receiver-provided 32-bit value equals a caller-supplied 32-bit selector.

The two routes produce their results differently:

- The receiver route supplies a writable, initially zero result slot to an indirect operation. The final contents of that slot become the function result.
- The lookup route calls F-283eda65a14c. A zero lookup result produces a zero function result without further work. A nonzero lookup result is passed to F-5710a8628cba, whose result becomes the function result.

This establishes routing and result propagation, not a domain-specific meaning. Interpreting the selector as a type identifier, the lookup result as an object, or the returned word as a success indicator would be inferred intent rather than established behavior.

## Interface

The function accepts four arguments and returns one 32-bit word.

| Position | Contract role | Established representation |
|---|---|---|
| First | Receiver used for indirect dispatch | Pointer to storage whose first machine word supplies a dispatch-table base |
| Second | Opaque forwarded payload | 32-bit word |
| Third | Selector compared with the receiver query result and otherwise submitted to lookup | 32-bit integer |
| Fourth | Opaque forwarded payload | 32-bit word |
| Return | Selected operation result, or the retained zero result | 32-bit word |

The second and fourth arguments have no established numerical, pointer, ownership, or status interpretation. Their bit patterns are forwarded, but their order changes relative to the public argument list: the fourth argument precedes the second in both result-producing calls.

The receiver dispatch layout contains two relevant entries:

| Byte offset from dispatch-table base | Role | Supplied arguments |
|---|---|---|
| 228, equivalently 0xE4 | Query operation | Receiver |
| 100, equivalently 0x64 | Receiver result-producing operation | Receiver, fourth argument, second argument, address of result slot |

The query operation produces a 32-bit integer used in the equality comparison. The result-producing operation receives a pointer to a writable 32-bit slot. Its ordinary return value does not contribute to this function’s result.

The supplied representation is consistent with a 32-bit dispatch environment. It establishes the byte offsets and four-byte data widths above. It does not independently establish a complete ABI, byte order, calling convention, object model, or dispatch-table extent.

### Preconditions

Normal completion requires all memory accesses and selected calls to be valid:

- The receiver must support the initial dispatch-base read.
- The dispatch base must support reading and invoking the query entry at byte offset 228.
- On the equality route, the receiver and its dispatch state must support another dispatch-base read and invocation of the entry at byte offset 100.
- Each invoked dependency must accept the supplied arguments and return normally for this function to return normally.
- If the receiver operation uses the supplied result pointer, it must access the writable four-byte slot within its valid lifetime.

No explicit receiver-null check, dispatch-entry validation, selector validation, or payload validation is present. These are caller or dependency preconditions, not conditions checked and reported by F-ae750fac4151.

## Behavior

### Initial state and query

A private four-byte result slot is initialized to zero before the receiver query is invoked.

The receiver’s dispatch-table base is obtained from the first word of receiver storage. The entry at byte offset 228 is then selected and invoked with the receiver as its sole explicit argument.

The query result is compared for exact equality with the third argument. This is a 32-bit equality decision, not a range test, ordering comparison, or truth-value test. No selector arithmetic, masking, narrowing, or normalization is visible.

The query occurs on every route that proceeds normally beyond the initial dispatch. There is no route that skips it based solely on the selector or opaque payload values.

### Equal-selector route

When the query result equals the third argument, the function invokes the receiver entry at byte offset 100.

That invocation receives, in order:

1. The receiver.
2. The fourth argument’s 32-bit value.
3. The second argument’s 32-bit value.
4. The address of the private four-byte result slot.

The slot is still zero when its address is first supplied to this operation. The initial query did not receive that address as an explicit argument.

The receiver’s dispatch base is obtained again for this second indirect invocation. The visible behavior therefore does not require the dispatch base used for the query to remain the dispatch base used for the result-producing call. In particular, a query-side mutation of receiver dispatch state can affect the second call. There is no visible check that the two dispatch bases are equal.

The receiver operation’s own return value is ignored. On normal return from that operation, the current contents of the result slot become the result of F-ae750fac4151.

Consequences include:

- If the receiver operation leaves the slot unchanged, the result is zero.
- If it writes a complete 32-bit value, that value is returned.
- The visible function does not check whether the operation wrote the slot.
- It performs no validation, translation, or success interpretation of the slot contents.
- Neither F-283eda65a14c nor F-5710a8628cba is called on this route.

The contract does not require that the receiver operation perform exactly one write. If it makes multiple valid writes, the value remaining in the slot when control returns is the value subsequently returned.

### Unequal-selector route

When the query result differs from the third argument, the function calls F-283eda65a14c with the third argument as its sole explicit argument.

If F-283eda65a14c returns zero:

- F-5710a8628cba is not called.
- The receiver entry at byte offset 100 is not called.
- The initialized result remains zero.
- F-ae750fac4151 returns zero.

If F-283eda65a14c returns a nonzero 32-bit value, F-5710a8628cba is called with:

1. The nonzero lookup result.
2. The fourth argument.
3. The second argument.

The 32-bit return value from F-5710a8628cba becomes the function result without further visible interpretation or transformation.

The condition is nonzero, not positive. A lookup result with its high bit set therefore selects F-5710a8628cba just as any other nonzero value does. Whether such a value is valid for that dependency is not established.

The receiver entry at byte offset 100 is not invoked anywhere on the unequal-selector route.

### Result and error distinctions

A zero result is not a unique diagnostic. It can arise from at least three visibly distinct normal paths:

- An unequal query result followed by a zero result from F-283eda65a14c.
- An unequal query result, a nonzero lookup result, and a zero result from F-5710a8628cba.
- An equal query result followed by a receiver operation that leaves or sets the result slot to zero.

The function provides no separate status output identifying which case occurred.

There is no visible retry, exception handler, error-code conversion, or recovery path. An invalid access, invalid indirect target, dependency failure that prevents normal return, or nonreturning dependency has no established conversion into a normal zero result.

## Side effects

### Direct memory activity

The visible function:

- Initializes a private four-byte result slot.
- Reads the dispatch-table base from receiver storage.
- Reads the query dispatch entry at byte offset 228.
- On the equal-selector route, reads the receiver dispatch base again and reads the operation entry at byte offset 100.
- Supplies a writable pointer to the private result slot only on the equal-selector route.
- Obtains the final 32-bit result from the selected result-producing path.

The ordering above describes source-visible access and call dependencies. It is not a claim about instruction scheduling, atomicity, volatile access semantics, or hardware memory ordering.

No direct write to receiver storage, caller payload storage, or global storage is shown. This does not imply those locations remain unchanged: invoked dependencies may have side effects.

### Ownership and lifetime

No allocation, deallocation, reference-count adjustment, or explicit ownership transfer is visible in F-ae750fac4151.

The receiver and opaque argument values are passed onward without a visible copy of any referenced object or buffer. The source does not establish whether any forwarded value denotes owned memory, borrowed memory, a handle, or ordinary numeric data.

The result-slot address refers to temporary storage associated with this invocation. It is available to the receiver operation during that call. No supported use after F-ae750fac4151 returns is established.

A nonzero value returned by F-283eda65a14c is forwarded to F-5710a8628cba without any visible intervening acquisition or subsequent release. This alone does not establish that the value is a pointer or that either dependency owns or releases an associated resource.

### Dependency effects

The function provides no visible isolation from dependency effects. In particular, the contract does not assume that the query operation, either named dependency, or the receiver result-producing operation preserves globals, receiver state, external resources, or memory reachable through its arguments.

The query operation runs before branch selection. Any side effects it performs therefore occur before either route’s subsequent dependency calls.

## Dependencies

Invoked only when the receiver query result differs from the third argument.

- Input: the original third argument, a 32-bit selector.
- Output used here: a 32-bit value tested for equality with zero.

Its lookup policy, side effects, failure modes, and ownership semantics are not established by the supplied body.

### F-5710a8628cba

Invoked only after an unequal receiver query result and a nonzero result from F-283eda65a14c.

- Inputs, in order: lookup result, fourth argument, second argument.
- Output: the 32-bit word returned by F-ae750fac4151 on this route.

Its internal interpretation of those arguments and its side effects are unknown.

### Receiver-selected indirect dependencies

Two additional dependencies are identified structurally by receiver dispatch offsets, not by fixed opaque function IDs. Their actual targets are not supplied.

- Offset 100 selects the receiver result-producing operation.

A fixed target identity must not be inferred from either offset. The target can depend on receiver state, including state changed during the query.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not reports of executed tests.

### Matching selector with an explicit result write

Given a third argument of 17 and a query result of 17, the receiver operation at offset 100 must be selected. If the second argument is the word 0x11223344 and the fourth is 0x55667788, the operation receives the fourth word before the second word, followed by the writable result-slot address.

If that operation writes 0xA1B2C3D4 to the slot and returns normally, F-ae750fac4151 returns 0xA1B2C3D4. Neither named dependency is called.

### Matching selector with no slot modification

Given equality between the query result and selector, suppose the receiver operation returns a nonzero ordinary return value but does not modify the supplied result slot.

F-ae750fac4151 returns zero. The receiver operation’s ordinary return value is not a substitute for the output slot.

### Unequal selector with lookup miss

Given a query result of 8 and a selector of 9, F-283eda65a14c receives 9.

If it returns zero, F-ae750fac4151 returns zero without calling F-5710a8628cba or the receiver operation at offset 100.

### Unequal selector with nonzero lookup result

Given unequal query and selector values, suppose F-283eda65a14c returns a valid nonzero value accepted by F-5710a8628cba.

F-5710a8628cba receives that value, then the original fourth argument, then the original second argument. If it returns 0xDEADBEEF, F-ae750fac4151 returns the same 32-bit word.

### Boundary values in comparisons

If the query result and selector both have the bit pattern 0xFFFFFFFF, the equal-selector route is taken. Their interpretation as negative signed integers does not alter equality.

On the unequal-selector route, a lookup result of 0x80000000 satisfies the nonzero condition. The call to F-5710a8628cba is therefore selected, conditional on that value being valid for the dependency.

### Query changes the dispatch base

Suppose the query returns a value equal to the selector and validly replaces the receiver’s dispatch base before returning.

The subsequent operation is selected through the receiver’s dispatch state read after the query, rather than necessarily through the earlier base. This acceptance case depends on the replacement providing a valid entry at offset 100.
