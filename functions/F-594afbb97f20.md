# F-594afbb97f20

## Purpose

F-594afbb97f20 conditionally dispatches operations according to byte-valued tags in a caller-supplied memory region and a signed selector.

Two dispatch paths are established:

- A tag-3 path selects a four-byte payload from one of four positions and passes it, together with two signed integer arguments and one unsigned integer argument, to F-d8f0965cd047.
- A tag-4 path applies only to selector zero and the first tag position. It calls F-dbc24f77c9d2, then an external dependency whose opaque function ID is not supplied.

The tag-4 check occurs after the tag-3 dispatch decision and any resulting call. It is a separate check, not an alternative decided from a single initial snapshot of the memory region.

The broader purpose of these operations is unknown. The tags, payloads, integers, and external operations must not be assigned application-specific meanings without additional evidence.

## Behavior

### 1. Ordered tag-3 selection

The function examines positions in ascending order: first, second, third, fourth.

At each position, it reads the tag byte and checks whether it equals 3. Only if that tag comparison succeeds does it check whether Selector equals the position’s required value.

This ordering has an important consequence: Selector does not limit the function to reading only the corresponding tag.

- The first tag is read initially on every ordinary execution.
- The second tag is read if the first position does not satisfy both conditions.
- The third tag is read if neither earlier position satisfies both conditions.
- The fourth tag is read if none of the first three positions satisfies both conditions.

A matching tag without the matching selector does not stop this search.

If a position satisfies both conditions, the function reads exactly four bytes from that position’s payload offset. It then calls F-d8f0965cd047 with seven arguments, in this order:

1. The selected four-byte payload.
2. Integer A.
3. Integer B.
4. Quantity.
5. Integer A again.
6. Integer B again.
7. Quantity again.

The duplicated argument groups are established behavior. No different interpretation of the two groups is justified by the available evidence.

The payload is an opaque four-byte value. It is not established to be an address, handle, signed number, or owned object. Its numeric interpretation, including byte order, is not independently specified.

At most one call to F-d8f0965cd047 occurs during an invocation. A successful selection prevents examination of later positions during this initial search.

If no position satisfies both conditions, no payload is loaded and F-d8f0965cd047 is not called.

### 2. Separate tag-4 check

After the tag-3 selection and any resulting call return normally, the function reads the first tag byte again.

It checks whether that byte equals 4. Only if it does does the function check whether Selector equals zero.

If either condition fails, the function returns without performing the tag-4 operations.

This is a fresh read of the first tag, not reuse of its earlier value. In particular, F-d8f0965cd047 may have effects that change what the later check observes. The supplied evidence does not establish that this dependency preserves Region or other reachable state.

Consequently, the two dispatch paths are not necessarily mutually exclusive. Both can execute if the tag-3 dependency returns and the subsequent first-tag read observes 4 while Selector remains zero.

### 3. Tag-4 dispatch and quantity split

When the tag-4 condition succeeds, Quantity is separated into:

- **Aligned portion:** Quantity with its low four bits cleared.
- **Remainder:** Quantity’s low four bits.

The aligned portion is an unsigned 32-bit multiple of 16, ranging from 0 through 4,294,967,280. The remainder ranges from 0 through 15. Their ordinary nonnegative sum equals the original Quantity.

The function first calls F-dbc24f77c9d2 with seven arguments:

1. Zero.
2. Zero.
3. The address eight bytes after Region.
4. Integer B.
5. Integer A.
6. The aligned portion.
7. The address 24 bytes after Region.

The dependency receives addresses into Region, not copies of the data at those addresses.

After that call returns normally, the function calls the unmapped external dependency with three arguments:

1. Integer B plus the aligned portion.
2. Integer A plus the aligned portion.
3. The remainder.

The ordering of Integer B before Integer A is established for both tag-4 calls.

The additions combine a signed 32-bit integer with an unsigned 32-bit value. Under the represented arithmetic rules, the signed input is converted to unsigned 32-bit form and the sum is computed modulo \(2^{32}\). These are not checked additions, saturating additions, or established pointer arithmetic.

For example, an input integer of −1 combined with an aligned portion of 16 produces the 32-bit value 15. The external dependency’s interpretation of those argument bits is unknown.

Both tag-4 calls occur even when their corresponding quantity portion is zero. There is no local zero-length suppression.

### 4. Return and failure boundaries

The function returns after the tag-4 decision or after the external dependency returns.

No dependency result is inspected. No explicit error status, recovery action, or rollback appears.

If a memory access fails, a dependency does not return, or a dependency terminates execution, the remaining operations are not established to occur. The function provides no visible local mechanism for handling such outcomes.

- F-d8f0965cd047 receives that payload followed by Integer A, Integer B, Quantity, then the same three values again.
- Later tags are not read during the initial search.
- The first tag is read again afterward.

- The second tag is examined and rejected.
- The third tag selects the payload at offset 84.
- The fourth tag is not read during the initial search.
- F-d8f0965cd047 is called once.
- The later tag-4 path is not taken because Selector is not zero.

### Selector outside the supported range

Given Selector −1 or 4:

- All four tags are read during the initial search.
- No payload is selected.
- F-d8f0965cd047 is not called.
- The first tag is read again.
- The tag-4 calls do not occur, even if that tag is 4.

Thus, an unsupported selector is not a safe no-access request.
