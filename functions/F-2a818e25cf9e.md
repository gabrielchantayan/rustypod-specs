# F-2a818e25cf9e

## Purpose

F-2a818e25cf9e conditionally updates a shared 32-bit value, then returns a read from the shared target captured at entry.

An initial comparison with the exact value 4 controls the update. If the comparison succeeds, the function initializes two local 32-bit objects from its third and fourth inputs, supplies their addresses to F-8af40cc8e379 in two ordered calls, and combines their contents after both calls return. The combination is a bitwise OR of the unsigned object with the signed object shifted left by one bit, subject to the signed-shift limitations described below.

The meaning of the shared value, the significance of 4, and the meanings of the dependency selectors are not established. Interpreting this as initialization, caching, or configuration discovery is inferred intent, not part of the established contract.

## Behavior

The function first captures the global pointer’s value. It then reads the comparison target through the global pointer and tests the full recovered 32-bit value for equality with 4.

The captured pointer is retained for the later conditional store and final read. The comparison is expressed through the global pointer rather than explicitly through the captured copy.

In stable sequential execution, both pointers identify the same target. If an external mechanism can change the global pointer between capture and comparison, the supplied representation does not establish that the comparison target and captured target remain identical. The comparison is an exact equality test. It is not a test of an individual bit, a masked field, or a range.

### Comparison value equal to 4

When the comparison value equals 4, the function performs the following ordered operations:

1. Initializes a signed 32-bit local object with the third input.
2. Initializes a separate unsigned 32-bit local object with the fourth input.
3. Calls F-8af40cc8e379 with selector 0x34 and the address of the unsigned object.
4. After that call returns, calls F-8af40cc8e379 with selector 0x35 and the address of the signed object.
5. After both calls return, combines the then-current local contents.
6. Stores the combination through the pointer captured at entry.
7. Reads through that captured pointer to obtain the result.

### Which local values determine the store

The combination uses the local contents after both dependency calls have returned, not a snapshot taken immediately after each object’s corresponding call.

In particular, the unsigned object’s value immediately after the first call is insufficient to determine the store. The first call could retain its address, and the second call could modify that object as well as the signed object. The dependency implementation is unavailable, so preservation across the second call cannot be assumed.

Likewise, no visible rule confines a dependency’s writes to the object passed in that particular call. Such confinement would require an additional dependency contract.

The relative order of the two local reads within the final combination is not established as a separate externally observable guarantee. Both follow completion of the second call in the supplied representation.

### Combination and integer limits

For operands within the established, safely representable signed-shift range, the stored unsigned value is the bitwise OR of:

- The final unsigned local value.
- Twice the final signed local value, obtained by shifting it left by one bit.

The operation is bitwise OR, not addition. Overlapping set bits do not create carries. Neither operand is masked to a single bit or a narrow field.

For a signed 32-bit local value from 0 through 1,073,741,823 inclusive, shifting left by one bit remains within the nonnegative signed 32-bit range. Numeric examples within that range do not require an assumption about negative or overflowing signed shifts.

A 32-bit bit-vector interpretation extends the combination as follows: shift the signed object’s bit pattern left one position, retain the low 32 bits, and OR that pattern with the unsigned object. Under that interpretation:

- Result bit 0 comes only from the unsigned object’s bit 0.
- Each result bit from 1 through 31 combines the corresponding unsigned-object bit with the preceding signed-object bit.
- The signed object’s original bit 31 is discarded.

That bit-vector interpretation is conditional for negative signed operands or operands whose mathematical doubled value exceeds the signed 32-bit maximum. The supplied representation alone does not establish machine-level shift semantics for those cases. Unconditional numeric results for them remain documented_only.
