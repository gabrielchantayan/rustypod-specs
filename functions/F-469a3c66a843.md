## Behavior

### Established dispatch sequence

For an invocation that reaches normal completion, the visible operations occur in this order:

1. Read the initial integer from the input-referenced storage.
2. Add the constant 348 to that integer.
3. Interpret the resulting value as the address of storage containing a callable address.
4. Read the callable address from that storage.
5. Invoke the selected target once, with no explicit argument expressions.
6. After the target returns normally, return from the wrapper.

The callable-address read therefore depends on the earlier integer read. The selected target is not invoked until its address has been obtained.

No explicit wrapper-owned write appears before or after the invocation. No additional read, dispatch attempt, or retry appears after the selected target returns.

- The wrapper reads the base before reading the slot.
- It invokes the target selected by that slot once.
- If the target returns normally, the wrapper returns with no explicit result.
- The wrapper performs no explicit write of its own.

### Two possible targets

Given a base with multiple callable slots, only the slot at displacement 348 is used by the visible wrapper. A callable stored at another displacement is not selected merely because it is nearby.

This case assumes the replacement is otherwise valid; it does not establish concurrent-update safety.
