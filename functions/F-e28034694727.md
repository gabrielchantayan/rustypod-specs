# F-e28034694727

## Purpose

F-e28034694727 examines a record reached indirectly through a caller-supplied mutable state block. Depending on the record’s discriminator bytes, it either:

- Replaces two 32-bit state fields and one 8-bit state field, returning a category-specific result.
- Consults dependency F-b7a6dfd8bf97 and conditionally replaces only the first 32-bit state field.
- Returns zero without performing any direct state writes.

The established behavior is a discriminator-driven state transition. The semantic meanings of the records, discriminator values, state fields, and return codes are not supplied. Descriptions such as “record,” “category,” and “mode” below identify structural roles, not established application-level types.

## Behavior

### Initial lookup and dispatch

The function first reads the initial object address from state offset `0x00`, then reads the candidate address from that object’s offset `0x18`.

If the candidate address is zero, it returns `0`. No candidate fields are read, no dependency is called, and no direct writes occur.

For a nonzero candidate, it reads the primary discriminator byte at candidate offset `0x08`. The recognized primary values are `0x02`, `0x06`, and `0x0F`.

Any other primary value produces result `0` without further record-field reads or direct state writes.

The candidate address is captured by this initial lookup. Later writes to state offset `0x00` do not cause the function to repeat the lookup or select a different candidate.

### Primary discriminator `0x02`

The function reads the secondary discriminator at candidate offset `0x09`.

Three secondary values are recognized:

| Secondary discriminator | Mode byte written |
|---:|---:|
| `0x03` | `2` |
| `0x06` | `0` |
| `0x07` | `1` |

For any other secondary value, the function returns `0` without reading the payload fields at offsets `0x14` and `0x18`, and without performing direct writes.

For a recognized secondary value, the direct operation sequence is:

1. Read the 32-bit payload at candidate offset `0x14`.
2. Write that value to state offset `0x00`.
3. Write the selected single-byte mode to state offset `0x08`.
4. Read the 32-bit payload at candidate offset `0x18`.
5. Write that value to state offset `0x04`.
6. Return `3`.

Only one byte is written at state offset `0x08`; this is not a 32-bit assignment to the surrounding storage.

### Primary discriminator `0x0F`

The secondary discriminator handling, mode mapping, payload accesses, and write sequence are identical to those for primary `0x02`.

The sole established difference is the successful return value: this branch returns `2`, not `3`.

An unrecognized secondary discriminator returns `0` without direct writes or dependency calls.

### Primary discriminator `0x06`

The function reads the 32-bit value at candidate offset `0x10` and passes that value as the sole visible argument to F-b7a6dfd8bf97.

If the dependency returns zero, F-e28034694727 returns `0` without performing a direct state write.

If the dependency returns any nonzero 32-bit result, the function:

1. Reads candidate offset `0x10` again.
2. Writes this newly read 32-bit value to state offset `0x00`.
3. Returns `1`.

The second read is behaviorally significant. The value installed in the state is not necessarily the value originally passed to the dependency. If the dependency changes the candidate’s field at offset `0x10`, the later value is the one selected for the state write.

This branch does not directly write state offsets `0x04` or `0x08`. It also does not directly read the secondary discriminator or payload fields at offsets `0x14` and `0x18`.

### Ordering and overlapping storage

The accesses above are not specified as an atomic transaction.

For the two-field transitions, the payload at candidate offset `0x18` is read only after the first state-field write and the mode-byte write. If either destination overlaps that payload, the later read observes the storage after those writes, subject to the execution environment’s memory semantics. The function does not first take a complete payload snapshot.

Likewise, overlapping destination fields and candidate fields must be interpreted using the stated access order, rather than assuming independent objects.

This contract records the ordering visible in the supplied representation. It does not establish synchronization, atomicity, or guarantees for concurrently modified memory.
