# F-e9635d699624

## Purpose

F-e9635d699624 conditionally performs an ordered series of operations on an object: an initial dependency call, linked-structure updates, record processing, associated-resource calls, replacement of an object field, aggregate accounting, and conditional metadata-dependent accounting.

“Teardown,” “resource cleanup,” and “allocation accounting” are inferred intent. The established contract is the sequence of accesses, calls, and branches described below. Dependency names do not establish memory release, ownership transfer, synchronization, global preservation, or successful return.

A null object address returns immediately without dependency calls or object/global accesses.

## Interface

### Input and result

The function accepts one object address and has no explicit return value.

The supplied representation uses 32-bit integers and address-bearing words. All offsets below are byte offsets. Record tags are one byte; metadata selectors are unsigned 16-bit values.

A non-null object must remain accessible for every reached access, including accesses after dependency calls. The function does not validate object lifetime, allocation extent, list membership, selector bounds, or dependency-supplied indices.

### Other addressed state

Two context acquisitions serve different stages:

- An **aggregate-context global** directly supplies context addresses for the two-word accounting update. Its repeated reads are significant.
- A later **allocation-context pointer** is obtained by dereferencing a separate global pointer location after F-2fd8826557a4.

These contexts need not be identical.

The metadata reference supports a 32-bit accounting quantity at −0x08, a 32-bit header at −0x10, and unsigned 16-bit selectors at −0x0C and −0x0A.

All reached addresses must permit the specified access. Ordinary arithmetic descriptions below assume valid address calculations. Overflow behavior of signed address expressions is not independently established by this representation.

## Behavior

### 1. Initial call

For a nonzero object address, call F-00cf49e09ab2 with the object address and integer 1.

All subsequent object reads occur after this call. No assumption is made that it preserves object contents or global state.

### 2. Linked-structure updates

Inspect the predecessor field at object +0x04.

- If zero, write the successor value to owner +0x8C.
- Otherwise, write the successor value to predecessor +0x08.

After that write, inspect the object’s successor field again. If nonzero, write the object’s predecessor value to successor +0x04.

The owner-head or predecessor-forward write precedes the successor-backward write. The object’s own link fields are not explicitly cleared.

The representation repeats field accesses rather than establishing one immutable snapshot of all links. In particular, the predecessor used in the nonzero branch and the successor used in the backward-link update are obtained through expressions reached after their branch conditions. Aliasing can therefore affect later accesses. Relative evaluation order within a single assignment expression is not established.

### 3. Record processing

Read object +0x14. If zero, skip both record iteration and the immediately following F-94cb53877c15 call.

Otherwise, retain that address as the initial cursor and start a signed 32-bit index at zero. Before each iteration, compare the index with the current signed value at object +0x0C.

For each entered iteration:

- Obtain the byte at cursor +0x01 and convert it to an integer.
- Obtain the 32-bit value at cursor +0x10.
- Call F-9ef145997789 with those values, in that argument order.
- Advance the cursor by 0x14 bytes and the index by one.

The relative evaluation order of the two argument reads is not established. Plain-character signedness is also unresolved: bytes with their top bit set do not have a proven sign-extension or zero-extension contract.

The loop bound is reread on each comparison. The cursor is not reloaded from object +0x14. A dependency can consequently change the number of iterations without changing the cursor’s progression.

After iteration ends, reread object +0x14 and pass its current value to F-94cb53877c15. This call is selected by the original nonzero-array branch, even if the field has since become zero.

A zero or negative initial bound skips all record calls but does not skip that final call when the initial array address was nonzero.

### 4. Associated-resource calls

Perform these operations in order:

1. Call F-c171d4869dd0 with the current fields at +0x38 and +0x34, followed by integer 1.
2. Call F-94cb53877c15 with the current field at +0x20.
3. Test the field at +0x4C. If nonzero, reread it and call F-94cb53877c15 with that value plus 0x28.
4. Call F-c171d4869dd0 with the current field at +0x28, the field at +0xEC shifted left one bit, and integer 1.
5. Reread +0x28 and call F-94cb53877c15 with its current value.
6. Call F-94cb53877c15 with the current field at +0x148.

Only the +0x4C call has a local nonzero guard. The guard and argument are separate accesses; they are not a guaranteed snapshot.

The optional argument is an interior address, 0x28 bytes beyond the argument-producing read. Nothing establishes ownership of the enclosing storage.

The shift uses a represented 32-bit signed integer expression. For nonnegative representable results, its mathematical effect is multiplication by two. Negative operands and signed overflow remain documented_only; this contract does not substitute checked arithmetic or assert wrapping behavior for those cases.

### 5. Field replacement and aggregate accounting

First, read an opaque global 32-bit value and write it to object +0x44.

The aggregate-context access sequence is then:

1. Read the aggregate-context global and retain this **original context**.
2. Read the displacement at object −0x04 and subtract it from the object address to derive the **metadata reference**.
3. Read the unsigned 32-bit **accounting quantity** at metadata reference −0x08.
4. Reread the aggregate-context global, then read the **old low word** at that context +0x38.
5. Reread the aggregate-context global again and form a **retained high-source address** at that context +0x3C. The high word is not yet read.
6. Reread the aggregate-context global again to select the **low-word destination** at that context +0x38. Write the old low word minus the accounting quantity there.
7. After the low-word write, read the high word through the retained high-source address. Subtract the correction described below and write the result to **original context +0x3C**.

Thus, there are four aggregate-context global reads: the original capture and three later reads. The original capture occurs before the displacement and accounting-quantity reads. The high-word source address is constructed before the low-word write, but the high-word contents are read after that write. The high-word destination uses the original context, not another global reread.

The correction subtracted from the high-source value is the sum of:

- The accounting quantity interpreted as signed 32-bit and arithmetically shifted right by 31, producing zero or −1.
- An unsigned borrow indicator: 1 when the old low word is less than the accounting quantity, otherwise 0.

The unsigned accounting operations produce 32-bit modular results.

When the aggregate-context global remains stable and the relevant storage does not alias in a way that interferes with these accesses, the pair of writes subtracts the sign-extended 32-bit accounting quantity from a two-word value, modulo 64 bits. That interpretation does not replace the explicit access sequence.

If context values differ between reads, the old low word, low destination, high source, and high destination can refer to different contexts. If the low write overlaps the retained high-source storage, the subsequent high read observes that write. If the low write changes the aggregate-context global itself, the already retained high-source address and original high destination do not change.

After the high-word write, call F-2fd8826557a4 without explicit arguments.

### 6. Conditional metadata processing

After F-2fd8826557a4 returns, dereference the separate global pointer location to capture the allocation-context pointer.

Only then compare the metadata reference with numeric address 8. If equal, return without header validation or detailed context updates. Earlier aggregate accesses still occurred; in particular, this reference makes the accounting-quantity address numerically zero, which must satisfy the reached-access precondition.

Otherwise, form the header address at metadata reference −0x10 and validate it:

- Read the header and test whether it is zero.
- Only if that read was nonzero, read the header again and test its least significant bit.
- A zero first read or an odd second read selects F-a817d8d58c10, annotated as non-returning.

These checks need not observe the same header value. No rollback precedes the non-returning call.

For an accepted header:

1. Call F-c0fc6d033caa with the captured allocation context.
2. Read the unsigned 16-bit selector at metadata reference −0x0C and form the context-relative address using four times that selector.
3. Reread the header and mask it with 0x3FFFFFFC, producing a retained **masked quantity**.
4. Subtract that quantity from the 32-bit word at context +0x224 plus four times the first selector.
5. Subtract the same quantity from context +0x30C.
6. Read the unsigned 16-bit selector at metadata reference −0x0A.
7. Subtract the same quantity from context +0x0E0 plus four times the second selector.
8. Subtract the same quantity from context +0x220.
9. Call F-09dcb55e8e0a without explicit arguments.
10. Use its returned integer to select context +0x310 plus four times that integer, and decrement the selected 32-bit word.
11. Decrement the 32-bit word at context +0x390.
12. Reread the header, mask it with 0x3FFFFFFC, and subtract this newly obtained quantity from context +0x08.
13. Call F-cc6c9b4a0f68 with the captured context and header address.
14. Call F-e586bff64fb7 with the captured context, then return.

The context argument remains the captured pointer despite intervening calls. Validation is not repeated after F-c0fc6d033caa. The first four quantity subtractions reuse one masked value; the subtraction at +0x08 uses a later header read.

Selectors are zero-extended 16-bit values before scaling. Neither they nor the returned index receive local bounds checks. The quantity subtractions use 32-bit unsigned arithmetic without underflow checks. The two count decrements are represented as signed integer additions of −1; signed overflow at the minimum value remains documented_only.

## Side effects

Direct writes can affect:

- An owner-head field or predecessor-forward link.
- A successor-backward link.
- Object +0x44.
- The separately selected aggregate low and high destinations.
- Conditional allocation-context quantities and counts.

All dependency calls occur in the stated sequence. Their additional effects are unknown.

No ownership guarantee follows from passing an address to a dependency. The function does not itself establish that any allocation is released, that the object is inaccessible afterward, or that a second invocation is safe.

The operation is not transactional. Invalid memory, dependency failure, or non-returning header rejection can occur after earlier mutations. No restoration path is shown. Synchronization and reentrancy guarantees are unresolved.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless a case says otherwise, assume valid non-aliasing storage, stable context globals, representable address arithmetic, and dependencies that return without changing relevant state.

1. **Null object.** A zero input produces no dependency calls and no object or global accesses.

2. **Head removal.** With predecessor zero and successor nonzero, owner +0x8C receives the successor before successor +0x04 receives zero.

3. **Interior removal.** With both neighboring addresses nonzero, predecessor +0x08 receives the successor before successor +0x04 receives the predecessor.

4. **Allocated array with no iterations.** A nonzero initial array address and count zero or negative cause no F-9ef145997789 calls. F-94cb53877c15 still receives the subsequently reread array field.

5. **Changed bound and array field.** If the initial count is two and the first record dependency changes it to one, only one record is processed. If that call also replaces the array field, the final array-related call receives the replacement, while iteration used the original cursor.

6. **Optional interior argument.** A stable zero +0x4C field omits its call. A stable nonzero value produces an argument 0x28 bytes beyond it.

7. **Aggregate borrow.** With quantity 3, old low word 2, and high word 7, the resulting words are 0xFFFFFFFF and 6.

8. **Signed aggregate correction.** With quantity 0x80000000, low word 0x90000000, and high word 5, the resulting words are 0x10000000 and 6. Unsigned 64-bit subtraction of the quantity would not give that high word.

9. **Low write changes the aggregate global.** Suppose the aggregate-context global is stored at its initial context’s +0x38, and the low write changes that global’s value. The following high read still uses the address retained before the low write, and the high write still targets the originally captured context +0x3C. It does not follow the newly stored global value. This example explicitly permits aliasing.

10. **Metadata reference 8.** Assuming the earlier quantity read at numeric address zero is valid, aggregate updates and F-2fd8826557a4 occur. The allocation-context pointer is then read, and detailed metadata processing is skipped.

11. **Invalid stable header.** A zero header selects F-a817d8d58c10 on the first validation read. A nonzero odd header selects it after the second read. Neither reaches F-c0fc6d033caa.

12. **Accepted zero masked quantity.** A stable header of 0x40000000 passes validation and masks to zero. Quantity-subtraction writes preserve their numeric values, but the selected count and context +0x390 are still decremented.
