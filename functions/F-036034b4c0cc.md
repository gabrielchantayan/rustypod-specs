# F-036034b4c0cc

## Purpose

F-036034b4c0cc replaces the first 32-bit word of a caller-supplied record with a value obtained from a global location. It then examines the record’s second 32-bit word as a pointer.

If that pointer is null, the function returns the original record address. If it is non-null, the function reads the first 32-bit word of the referenced object, passes that value to F-a1d9ef1cc8fe, and, if that call returns, passes the previously captured object pointer to F-feee9156a257.

The supplied static representation marks F-feee9156a257 as non-returning. Consequently, a normal return is established for the null-pointer branch, but not for the non-null branch.

This pattern is consistent with an object-state transition followed by processing of an associated resource. Describing it as construction, destruction, deallocation, or ownership release would require evidence not supplied here.

## Interface

**Input:** one address identifying a writable record.

**Result:** the original input address on the established normal-return path.

The visible record layout is:

| Byte offset | Width | Interpretation in this function |
|---|---:|---|
| 0 | 32 bits | Replaced with a value read from a global location |
| 4 | 32 bits | Read and interpreted as a pointer to an associated object |

For a non-null associated-object pointer, the referenced object has this additional visible requirement:

| Byte offset | Width | Interpretation in this function |
|---|---:|---|
| 0 | 32 bits | Read as the argument to F-a1d9ef1cc8fe |

No other record fields or associated-object fields are directly accessed in the supplied body.

The recovered representation uses four-byte record elements and interprets the second element as a pointer. This supports a 32-bit pointer-bearing layout for this contract. It does not establish a portable layout for a platform with wider pointers, nor does it establish the signedness of the words.

The global source contributes one 32-bit value. Its meaning, permitted values, initialization requirements, and relationship to the record type are unknown.

**Preconditions for the visible accesses:**

- The input must identify storage that supports the first 32-bit write and the subsequent read at byte offset 4.
- The global source must be readable when the initial assignment is evaluated.
- If the second word is nonzero, it must yield an address supporting a 32-bit read at offset 0.
- Any additional requirements imposed by F-a1d9ef1cc8fe or F-feee9156a257 must hold. Those requirements are not available here.

The function performs no explicit input-pointer validation. A null input is not a supported empty-record case.

## Behavior

### Initial state replacement

The function obtains the global 32-bit value and writes it into the first word of the input record. The previous first-word value is not read or preserved by this function.

This replacement precedes the read of the second record word and precedes either dependency call. Thus, dependency execution occurs only after the initial replacement has taken place.

The global read is associated with this initial assignment. There is no visible refresh of that value later in the function.

The first write is unconditional: a null associated-object pointer does not prevent it. Conversely, an inaccessible second record word does not prevent the earlier write from being attempted first. There is no rollback operation in the visible body.

### Associated-object selection

After replacing the first word, the function reads the second 32-bit word of the record and retains its pointer interpretation.

If that value is zero, the function:

- Does not dereference an associated object.
- Does not invoke either dependency.
- Returns the original record address.

There is no direct write to the second record word on this branch.

If the value is nonzero, the function reads the first 32-bit word at the captured associated-object address. That word becomes the sole visible argument to F-a1d9ef1cc8fe.

### Dependency sequencing

F-a1d9ef1cc8fe is invoked before F-feee9156a257. The latter is reached only if the former returns normally.

No return value from F-a1d9ef1cc8fe is visibly inspected or used. In particular, there is no visible success/failure branch controlling the second call.

When control returns from F-a1d9ef1cc8fe, F-feee9156a257 receives the associated-object pointer captured before the first call. The function does not reread the record’s second word to select this argument.

This distinction matters if F-a1d9ef1cc8fe changes the record, globals, or associated object. Such changes cannot be excluded. They do not cause this function to select a replacement pointer for the second call.

Likewise, the first associated-object word is not visibly reread after F-a1d9ef1cc8fe. The second dependency receives the object address, not another read of its leading word.

### Return behavior

The null-associated-object branch has an explicit normal return of the input address.

The non-null branch reaches a call marked non-returning in the supplied static representation. That annotation supports treating normal return from this branch as unavailable in the established contract. It does not identify whether the dependency exits, transfers control elsewhere, raises an exception, loops, or has some other non-returning behavior.

A common return appears after the conditional in the supplied representation. If F-feee9156a257 unexpectedly returned despite its annotation, that representation would lead to returning the original input address. This is a conditional observation, not a guarantee that the executable supports violating the non-returning assumption.

### Arithmetic and bounds

The visible operations use fixed field offsets and a zero comparison. There is no visible size calculation, iteration, numeric increment, or arithmetic transformation of either stored word.

The only directly accessed record offsets are 0 and 4. The only directly accessed associated-object offset is 0. No lengths or bounds are supplied or checked.

## Side effects

The sole direct memory write established by the function body is the 32-bit replacement at record offset 0.

The function does not directly:

- Clear the associated-object pointer.
- Restore the original first word.
- Allocate storage.
- Copy the associated object.
- Record a dependency result.
- Release either the input record or the associated object through an independently identified memory-management operation.

These are limits on the visible body, not guarantees about the dependencies. Either dependency may have additional effects that are undocumented here.

The pointer is passed to F-feee9156a257, but passing an address alone does not establish ownership transfer or deallocation. Likewise, the leading word passed to F-a1d9ef1cc8fe might represent a handle, address, identifier, or ordinary value; its role is unknown.

No preservation guarantee is established for globals, the record, or the associated object across either dependency call. No exception handling, failure cleanup, transaction boundary, or compensating write is visible.

No synchronization or atomicity guarantee is established. The access order described here is the order represented by the supplied body, not a concurrency or hardware memory-ordering contract.

## Acceptance examples

These examples are conditional consequences of the static evidence, not executed tests. Each assumes valid storage and any applicable dependency preconditions unless stated otherwise.

### Null associated object

Given a record whose second word is zero:

- Its first word is replaced with the global source value.
- Neither dependency is invoked.
- The function returns the same address it received.
- The function performs no direct write to the second word.

The prior first-word value does not affect branch selection.

### Non-null associated object

Given a record whose second word identifies a readable associated object:

- The record’s first word is replaced before either dependency call.
- The associated object’s first word is read and passed to F-a1d9ef1cc8fe.
- If that dependency returns, F-feee9156a257 receives the captured object pointer.
- No normal function result is promised after the annotated non-returning call.

### Zero leading word in a non-null object

Given a non-null associated-object pointer whose first word is zero, F-a1d9ef1cc8fe receives zero.

The null check concerns the object pointer, not the object’s leading word. A zero leading word does not skip either call if the first dependency returns.

### Pointer mutation during the first dependency

Suppose the record initially references object A, and F-a1d9ef1cc8fe changes the record’s second word to reference object B.

If that call returns, F-feee9156a257 still receives A’s captured address. This function does not reload the field or validate whether A remains usable.

### Invalid associated-object address

Suppose the input record is accessible, but its second word is nonzero and does not identify readable storage.

The first-word replacement precedes the attempted associated-object read. No explicit error result, recovery action, or restoration is provided. The actual fault behavior is outside the available evidence.

### First dependency does not return

If F-a1d9ef1cc8fe does not return normally, the visible sequence does not reach F-feee9156a257 or the function’s return. No cleanup behavior is established for that case.
