# F-58026c517ee7

## Purpose

F-58026c517ee7 repeatedly performs an ordered sequence of indirect calls, memory accesses, a software breakpoint, and register-state changes. The supplied static representation contains no normal return or exit condition.

No application-level purpose is established. In particular, the evidence does not establish allocation, initialization, object construction, device control, or memory ownership. The contract describes the represented operations, conditional on calls returning, memory accesses succeeding, and execution continuing through the breakpoint.

Values used as addresses are not thereby established to be valid pointers. Several addresses are formed directly from narrow integer values or arithmetic results.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit return value. It nevertheless consumes implicit machine state:

- A link-like value used to derive the first indirect-call target on every iteration.
- A frame-base register used for memory accesses and decreased during each completed iteration.
- An incoming auxiliary register value used in a late byte-store address.
- Two global 32-bit address-base values, read at distinct points.
- Memory at fixed, frame-relative, returned, and arithmetic-derived addresses.
- Primary results and secondary-register outputs from indirect calls.

These are observable machine-state dependencies, not a recovered ordinary parameter list.

There is no represented success result, error result, or normal completion. Observable outputs consist of memory writes, calls and their arguments, the breakpoint, and changes to implicit state.

### Widths and arithmetic

The contract distinguishes 8-bit bytes, 16-bit halfwords, 32-bit words, and paired 64-bit values. A paired value is consumed as low and high 32-bit halves; this does not establish the dependency’s actual calling convention.

Unsigned halfword reads are zero-extended when used as wider values. Byte and halfword stores retain only the low eight or sixteen bits, respectively. Word stores retain 32 bits.

Address arithmetic, additions, multiplications, and left shifts are described as 32-bit machine-width operations, discarding bits above bit 31. No overflow checks are represented. This is a machine-width interpretation, not a claim that equivalent signed-language expressions are portable or defined.

Byte order, required alignment, address-space mapping, and access-fault behavior are unresolved.

### Preconditions

An uninterrupted iteration requires executable call targets, returning dependencies, accessible memory of each specified width, and breakpoint handling that permits continuation. Secondary-register outputs must be usable where consumed.

The function performs no explicit validation of these conditions. A failed call or access has no represented local recovery path.

## Behavior

### Conventions and ordering

F-D01 through F-D37 identify indirect call sites in execution order. They do not necessarily identify distinct implementations. Known target equalities are listed under **Dependencies**.

A **captured** value is read or produced at the stated point and reused without an explicit reread of its original memory location. This describes the supplied local dataflow; it does not establish a general register-preservation or memory-preservation guarantee for unknown dependencies.

The ordering below concerns explicit local operations. Dependency-internal operations may introduce additional reads, writes, failures, or state changes.

### 1. Iteration entry and initial stores

At the start of **every iteration**, F-D01 derives its target by adding `0xFFE` to the link-like state, at 32-bit address width. On the first iteration, that state is incoming state; on later iterations, it is the state that reaches the loop entry after the preceding F-D37.

A zero byte is prepared before F-D01, which receives two explicit zero arguments. After it returns, a separate byte-valued addition component is set to zero.

F-D02 and F-D03 run next. The first global 32-bit address base is then read and captured. F-D04 follows, then F-D05, which supplies a paired value. F-D06 receives:

- The low 32-bit half.
- The 32-bit sum of the high half, low half, and zero-valued addition component.

F-D05 and F-D06 have the same statically computed target.

After F-D06, its consumed secondary byte output is stored at the captured first global base plus `0x11`. F-D07 then runs, followed by a zero-byte store at that same captured base plus `0x15`. Neither store rereads the global base.

F-D08 supplies a 16-bit primary result and a secondary address output. The primary result is stored as a halfword at that secondary address plus `0x0C`.

### 2. First paired-value processing

F-D09 supplies another paired value. Before the next call, the function writes:

- A zero halfword at its high half plus `0x2C`.
- A word at the current frame base plus `0x26C`, containing its low half logically shifted right by 26 bits.

The latter value is between 0 and 63 inclusive.

A working value is then established as `0x21C48960`. F-D10 runs, after which a 32-bit pointer is read from the frame base plus `0x320`. F-D11 and F-D12 run before a word is stored through that captured pointer, at offset `0x54`. The stored value is the low half from F-D09 shifted left by two bits.

Consequently, changing the pointer’s source slot during F-D11 or F-D12 does not itself redirect this local store: no reread of that slot is represented.

### 3. Narrow-base reads and breakpoint

F-D13, F-D14, F-D15, F-D16, and F-D17 run in order. F-D13 shares its target with F-D09, but its primary result is not consumed locally.

An unsigned halfword is read from `0x21C48994`, the working value plus `0x34`. Its zero-extended value becomes the **narrow base**. No upper address bits are recovered or supplied.

F-D18 runs. A word is then read from the frame base plus `0x280` and passed to F-D19, whose 32-bit primary result is consumed. The function next executes a software breakpoint with immediate `0x92`.

If execution does not continue through the breakpoint, none of the following local operations in that iteration occurs.

After continuation, the function shifts the F-D19 result left by two bits and derives `0x21C4` from the working value by a logical right shift of 18 followed by multiplication by four. It then reads a word from the narrow base plus `0x44`. That word is captured as the **principal destination pointer**.

### 4. Second-global indexed store

F-D20 runs, followed by F-D21, which supplies a 32-bit result. A word is then read from the narrow base plus `0x04`. F-D22 receives the F-D21 result as its first explicit argument and this newly read word as its second.

The second global 32-bit address base is read and captured after F-D22. F-D23 runs before a halfword store at:

- The captured second global base, plus
- The F-D19 result shifted left by two bits.

The stored halfword contains the low 16 bits of the captured second global base itself. A change to the global’s storage during F-D23 does not trigger a local reread.

### 5. Constant-derived lookup and late index

F-D24 runs before a word is read from `0x2218`, equal to `0x21C4 + 0x54`. This word is captured as another pointer.

F-D25 supplies an address result. The function stores halfword `0x21C4` at that address plus `0x04`.

F-D26 and F-D27 then run. An unsigned halfword is read from the pointer captured at `0x2218`, plus `0x34`. Its zero-extended value is the **late index**. The pointer is not reread from `0x2218` after the intervening calls.

F-D28 follows and supplies a paired value.

### 6. Frame change and directly indexed store

The low half from F-D28 is first stored as a word at the current frame base plus `0x258`. An unsigned halfword is then read from the high half plus `0x14`; its zero-extended value is retained as the **expanded halfword**.

The function derives the low half shifted left by six bits and four times the high half. It then decreases the frame-base register by `0xF4`, or 244 bytes.

After that state change, it computes four times the late index and stores the low half from F-D28 as a word at that value plus `0x74`. This destination is directly index-derived, not frame-relative.

The earlier frame-relative store uses the frame state before the decrease. No balancing restoration appears before repetition. Later frame-relative operations therefore depend on the decreased state, subject to unresolved dependency effects.

### 7. Final stores, link-like assignment, and repetition

F-D29 runs before the expanded halfword is stored as a word at the principal destination pointer plus `0x54`. F-D30 runs before the same value is stored as a word at that pointer plus `0x64`.

After F-D31, a halfword is stored at the sum of the F-D28 low half shifted left by six bits and a secondary address component associated with F-D31. The stored value is the low 16 bits of the principal destination pointer.

F-D32 and F-D33 run next. A byte is read from five times the late index: the late index plus its previously computed fourfold value. Since the index is unsigned 16-bit, this address ranges from zero through `0x4FFFB` without multiplication overflow.

F-D34 runs before that captured byte is written at the expanded halfword plus the incoming auxiliary register value plus `0x19`.

F-D35 runs before four times the F-D28 high half is stored as a word at the principal destination pointer plus `0x44`. F-D36 then runs.

In the final preparation for F-D37, the represented link-like state is explicitly assigned **`0x08712031`**. After that assignment, a word is read from four times the F-D28 high half plus `0x44`; F-D37 receives that word as its explicit argument.

The loop then repeats without an exit test. F-D01 again derives its target from the link-like state plus `0xFFE`. **If the assignment of `0x08712031` survives F-D37, the next F-D01 target is `0x0871302F`.** Preservation by F-D37 is not established. The explicit assignment is known; the state actually reaching the next iteration remains conditional on the unknown dependency.

## Acceptance examples

These are conditional consequences of the static representation, not runtime observations. Each assumes execution reaches the relevant operations and required accesses succeed.

1. **Paired addition wraps.** If F-D05 supplies low half `0xFFFFFFFF` and high half `2`, F-D06 receives `0xFFFFFFFF` and `1` under 32-bit arithmetic.

2. **High-bit extraction differs from left shift.** If the F-D09 low half is `0xFC000000`, the frame-relative store at offset `0x26C` writes `63`; the later store through the captured pointer writes `0xF0000000`.

3. **Pointer capture precedes calls.** If the frame-relative pointer read after F-D10 produces address A, and F-D11 changes that source slot to B, the represented later store still targets A plus `0x54`, not B plus `0x54`, provided the captured state remains available.

4. **Narrow base has no implicit upper region.** If the fixed-address halfword read yields `0xFFFF`, the principal-pointer read occurs at `0x10043`.

5. **Indexed address and stored truncation differ.** With captured second global base `0x12345678` and F-D19 result `3`, the indexed halfword store targets `0x12345684` and writes `0x5678`.

6. **Zero extension survives word stores.** If the halfword read through the F-D28 high half yields `0xFFFF`, the principal-destination stores at offsets `0x54` and `0x64` write `0x0000FFFF`.

7. **Breakpoint can stop later effects.** If execution stops at the breakpoint, the principal-pointer read and subsequent local stores do not occur. Earlier effects are not undone.

8. **Frame decreases accumulate conditionally.** Two reached adjustments decrease the frame base by 488 bytes in total if no dependency or external action otherwise changes it, interpreted at machine width.

9. **Next target depends on surviving state.** If F-D37 returns with the assigned link-like value `0x08712031` unchanged, the next F-D01 target is `0x0871302F`. If F-D37 changes that state to another value L, the next target is L plus `0xFFE`, at 32-bit width. No preservation is assumed.

10. **Store inventory excludes dependency effects.** A completed iteration performs exactly fifteen explicit local stores. Writes inside dependencies do not belong to that count.
