# F-65bc357068fa

## Purpose

The established behavior is an ordered sequence of calls, reads, and writes. Allocation, construction, registration, and activation are possible interpretations, not established semantics.

The publication destination is not proven separate from the referenced object. If it overlaps that object, publication is itself an additional direct write to object storage, potentially including bytes outside the five explicitly addressed fields.

## Side effects

The function directly performs:

- Five object-relative field stores: a word at offset 0, a byte at offset 24, and words at offsets 28, 36, and 32.
- One four-byte pointer store through a destination derived from the publication-base global.
- Three dependency calls with unknown additional effects.

The five field stores directly cover object bytes 0–3, 24, and 28–39. **That list does not bound all object bytes directly written by the function.** If the publication slot overlaps the object, the publication store directly writes the overlapping object bytes as well.

Accordingly, an assertion that other object bytes remain untouched requires both:

- No overlap between those bytes and the publication slot.
- No dependency or external modification of those bytes.

Aliasing among the object, global sources, and publication destination is not excluded. Consequences include:

- An early object write can change a global source that is read later.
- Publication can overwrite an initial field value.
- Publication can write object bytes outside the explicitly addressed fields.
- A final field store can overwrite the publication slot.
- Direct stores can alter global storage when their destinations overlap it.

The publication base is read at its specified point in the sequence. If prior writes or dependencies have changed that source, the resulting value determines the destination.

No explicit cleanup path retracts publication if a later field write fails. There is also no guarantee that the initial field values or the published pointer representation remain intact at return unless relevant dependency effects and overlaps are excluded.
