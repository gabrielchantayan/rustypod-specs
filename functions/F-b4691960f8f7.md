# F-b4691960f8f7

## Purpose

F-b4691960f8f7 adapts the result of F-5a8b0ee5bea0 into a two-value status interface and, on success, publishes an adjusted integer through a caller-supplied pointer.

The established behavior is narrow:

- Forward two opaque values to F-5a8b0ee5bea0.
- Supply that dependency with the address of an invocation-local integer initialized from a fourth argument.
- Treat a dependency result of exactly zero as success.
- On success, subtract one from the integer left in the local storage and write the result to the caller’s output location.
- Return zero after that write.
- For every nonzero dependency result, return three without performing the wrapper’s output write.

An inferred intent is to convert a dependency-produced count or position to a value one lower. Neither a count interpretation nor an indexing convention is established. The contract therefore describes an integer adjustment, not a particular application-level meaning.

## Behavior

### Initialization and dependency call

The initial integer is copied into local storage before the dependency is invoked. This is a by-value snapshot: later changes to any caller storage from which the argument originated do not, merely by that relationship, change the local copy.

F-5a8b0ee5bea0 is then called once, receiving:

1. The first opaque value.
2. The second opaque value.
3. A pointer to the initialized local integer.

The dependency can access that integer through the pointer. If it returns normally without changing the integer, the initial value remains available for the subsequent adjustment. If it replaces the value, the replacement is the value relevant to the success path.

There is no explicit retry, additional dependency call, or preliminary validation in the supplied wrapper.

### Zero dependency result

A dependency result of exactly zero selects the success path.

After the dependency returns, the wrapper obtains the integer then present in local storage, subtracts one, and writes the adjusted value through the output pointer. It then returns zero.

The output write occurs after the dependency call. It does not publish an intermediate dependency value before that call finishes. The output location’s previous contents are not explicitly read by the wrapper.

Returning zero follows the output write. Thus, zero is the established normal return value only when execution reaches the end of that path. If arithmetic or the output access prevents normal completion, the evidence supplies no alternative returned status.

### Nonzero dependency result

Any dependency result other than zero selects the failure path. Positive and negative nonzero results receive the same treatment.

The wrapper returns three. It does not:

- Perform the subtraction.
- Read the final local integer for the output adjustment.
- Write through the output pointer.
- Return the dependency’s original nonzero value.

Dependency error distinctions are therefore collapsed into a single wrapper status.

“Does not write through the output pointer” is a statement about this wrapper’s explicit operations. It is not a guarantee that the pointed-to storage remains unchanged throughout the invocation. The dependency’s effects on shared or reachable memory are unknown.

### Arithmetic boundaries

The adjustment is integer subtraction by one. There is no explicit saturation, lower-bound test, sentinel exception, or range validation.

- A local value of zero produces negative one.
- The maximum signed value produces one less than that maximum.
- The minimum signed value requires special treatment in the specification because its mathematical predecessor is not representable.

The supplied evidence does not establish whether the last case wraps, traps, or is governed by another execution rule. A portable, normally completing success-path acceptance condition must exclude that boundary unless the applicable arithmetic semantics are independently established. Wraparound must not be assumed.
