# F-f6366b6b2161

## Purpose

F-f6366b6b2161 maps two 32-bit input words to a 32-bit result. Most inputs produce a result directly through bit extraction, shifting, zero return, or sign-dependent saturation. A narrowly defined set of inputs instead selects a configuration-dependent indirect transfer.

**Inferred intent:** The input layout and arithmetic are consistent with conversion of a binary64 floating-point representation to an unsigned 32-bit integer, with special handling for exceptional representations. This interpretation explains the sign, exponent, and fraction boundaries, but it is not an independently established interface declaration.

**Established limitation:** The supplied static representation does not fully resolve the indirect transfers or the semantics of large variable shifts. This contract therefore specifies the direct arithmetic and visible dispatch behavior while marking unresolved behavior as **documented_only**. It does not claim a complete floating-point conversion standard, exception mechanism, or callback ABI.

## Interface

### Inputs

The visible interface has two arguments:

| Argument | Width | Visible interpretation |
|---|---:|---|
| Low word | 32 bits | Unsigned word contributing the lower portion of the encoded value. |
| High word | 32 bits | Signed word for arithmetic comparisons and right shifts; its bit pattern also participates in unsigned arithmetic and bit assembly. |

The order is low word first, high word second. These are scalar arguments, not pointers. No buffer, length, alignment requirement, or caller-provided output region is visible.

When the inputs are interpreted as binary64 bits:

- Bit 31 of the high word is the sign.
- Bits 30–20 of the high word are the 11-bit exponent field.
- Bits 19–0 of the high word and all 32 bits of the low word form the fraction.

That interpretation is useful explanatory context, not proof that callers supply an actual floating-point object or use any particular memory byte order.

### Output

The visible return type is an unsigned 32-bit word.

Direct paths return one of:

- Zero.
- A shifted, assembled 32-bit magnitude.
- `0xFFFFFFFF` for a nonnegative high word on the saturation path.
- Zero for a negative high word on the saturation path.

The exceptional dispatch path returns the result attributed to an unresolved indirect dependency. Its behavior, including whether it returns normally, is not established.

### Arithmetic model and preconditions

The following distinctions are required:

- Unsigned 32-bit addition, multiplication, left shift, complement, and bitwise combination operate on 32-bit patterns; overflowing unsigned results retain their low 32 bits.
- Signed right shifts of the high word are represented as sign-extending shifts. The negative-input conclusions below rely on that interpretation.
- The signed addition used in the early negative-input comparison cannot overflow a signed 32-bit value: its input is negative, and adding `0x40000000` yields a value between `−0x40000000` and `0x3FFFFFFF`.
- Variable right shifts can request counts from 0 through 255. Counts of 32 or greater are **documented_only** because the supplied representation does not establish their target-level result. They must not silently be treated as modulo-32 shifts or as ordinary portable-language shifts.

No additional input validity restriction is visible. Every pair of 32-bit input words enters the selection logic.

## Behavior

### 1. Initial magnitude construction

Before selecting the principal path, the function forms a 32-bit candidate from:

- The high word shifted left by 11 bits, retaining only the low 32 bits.
- The low word shifted logically right by 21 bits.
- Bitwise OR of those two results.

It also obtains the high word shifted arithmetically right by 20 bits. If that signed slice is nonzero, the function sets bit 31 of the candidate.

Consequently, only the top 11 bits of the low word affect this candidate. Its lower 21 bits do not affect ordinary shifted results. They can still affect the later exceptional-versus-saturation classification through the separate test of whether the entire low word is zero.

The candidate construction does not itself return a result.

### 2. Negative high-word handling

If the signed high-word slice is negative, the function compares the signed high word plus `0x40000000` with `−0x00100000`.

- If the sum is strictly smaller, the result is zero.
- Otherwise, execution proceeds to the saturation-or-exception classification.

Equivalently, under the stated signed interpretation:

- High-word bit patterns `0x80000000` through `0xBFEFFFFF`, inclusive, return zero immediately, regardless of the low word.
- High-word bit patterns `0xBFF00000` through `0xFFFFFFFF`, inclusive, proceed to later classification.

The boundary `0xBFF00000` is not part of the early-return range. Its eventual result is still zero, but through the later direct saturation path.

No configuration or payload read is visible on the early-zero path.

### 3. Nonnegative high-word handling

For a nonnegative high word, its upper slice is in the range 0 through `0x7FF`.

The function computes a shift distance equal to:

**1054 minus the upper slice.**

It takes the candidate-return path when the upper slice is at most 1054 (`0x41E`).

That path has three relevant ranges:

| Upper slice | Shift distance | Result |
|---:|---:|---|
| 0–798 | 1054–256 | Zero; the candidate is explicitly discarded. |
| 799–1022 | 255–32 | A logical right shift is requested, but the result is **documented_only** because the count is at least 32. |
| 1023–1054 | 31–0 | The candidate shifted logically right by the stated distance. |

The low-eight-bit mask on the shift count does not resolve the middle range: each distance there is already between 32 and 255.

For upper slices 1055 through 2047, the function bypasses the candidate-return path and proceeds to saturation-or-exception classification.

For ordinary positive binary64 values whose exponent slice is 1023–1054, the defined candidate-shift path is consistent with discarding fractional bits rather than rounding to nearest.

### 4. Saturation-versus-exception classification

This stage forms a 32-bit classification word:

- Double the high-word bit pattern modulo \(2^{32}\).
- Add one if the low word is nonzero; otherwise add zero.
- Retain the low 32 bits.

If the classification word is less than `0xFFE00001`, the function returns the bitwise complement of the high word shifted arithmetically right by 31 bits:

- Nonnegative high word: `0xFFFFFFFF`.
- Negative high word: `0x00000000`.

The visible representation contains an additional threshold check inside this range, but both outcomes return exactly the same value. No behavioral distinction is established for those two subranges.

If the classification word is at least `0xFFE00001`, the function enters configuration-dependent dispatch.

Under the binary64 interpretation, the dispatch condition selects representations with an all-ones exponent and a nonzero fraction: NaN encodings. Positive and negative infinity instead take direct saturation, returning `0xFFFFFFFF` and zero respectively.

These direct saturation returns do not read the visible configuration or payload storage.

### 5. Configuration-dependent dispatch

The function reads a shared 32-bit configuration word and selects a mode from its low four bits.

Subsequent configuration tests appear as separate reads. A single stable snapshot must not be assumed. If the storage can change between reads, mode selection and later flag decisions can reflect different observed values.

The following names distinguish visible storage roles without asserting their addresses, ownership, or meaning:

- **Configuration word:** controls mode and flag selection.
- **Shared payload word:** supplies an argument in several dispatch branches.
- **Paired payload word:** initially supplies the first argument in one branch.
- **Alternate payload word:** replaces the second argument in that branch when a flag is set.

#### Mode 9

The function reads the configuration word and tests bit 20, mask `0x00100000`.

- **Bit 20 clear:** read the shared payload word and transfer indirectly with two explicit arguments: zero, then that payload.
- **Bit 20 set:** read the configuration word again and transfer indirectly with two explicit arguments:
  1. The value 8.
  2. The 32-bit result of complementing the configuration word shifted left by 15 bits, then shifting that complemented result left by one bit.

The second argument in the set-bit branch can equivalently be described as the 32-bit complement of the latest configuration word shifted left by 16 bits, with bit 0 cleared. This transformation uses the later configuration read, not necessarily the value used for the flag decision.

#### Mode 8

The function reads the configuration word and tests bit 6, mask `0x40`.

- **Bit 6 set:** transfer indirectly with two explicit zero arguments. No payload read is visible in this branch.
- **Bit 6 clear:** perform these visible reads in order:
  1. Read the paired payload word.
  2. Read the shared payload word.
  3. Read the configuration word and test bit 4, mask `0x10`.

  If bit 4 is clear, transfer indirectly with the paired payload as the first explicit argument and the shared payload as the second.

  If bit 4 is set, replace the first argument with zero, read the alternate payload word, and transfer indirectly with zero followed by that alternate payload.

The paired and shared payload reads occur even when bit 4 causes both loaded values to be discarded.

#### Mode 10

The function reads the configuration word and tests bit 6.

- Bit 6 clear: transfer indirectly with one explicit argument, zero.
- Bit 6 set: transfer indirectly with one explicit argument, `0x80000000`.

No payload read is visible in this mode.

#### All other modes

The function performs an indirect transfer with no explicit arguments shown.

This does not establish that the actual target has a zero-argument interface. Register contents, hidden arguments, and transfer conventions are unresolved.
