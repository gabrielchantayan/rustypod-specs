# F-70f204417fd6

## Purpose

F-70f204417fd6 specifies an ordered sequence of indirect dependency interactions and memory effects. Directly represented effects include computed-address byte stores, two halfword reads, an assignment of a retained 8-bit payload to a global object, and a word store through a retained pointer-like output. The represented endpoint performs an exceptional operation followed by an indirect control transfer, with no ordinary return shown.

No application-level purpose is established. The evidence does not justify describing this as initialization, reset, decoding, or device control. A global object’s symbolic name does not establish its role.

This contract distinguishes established static relationships from unresolved executable semantics. In particular, the global assignment’s 8-bit source does **not** establish the destination object’s type or the assignment’s memory-access width.

## Behavior

### Ordering and dependency boundaries

The represented body is straight-line, with no explicit data-dependent branch or loop. This establishes relative ordering in the supplied representation, not unconditional progress through the entire sequence.

Every dependency interaction remains an observable boundary, including those whose primary results are discarded. Unknown dependencies may modify memory or execution state, fault, terminate, or fail to return. Similar argument shapes do not make interactions interchangeable.

A frequent relationship passes four times a primary result to another dependency. At some boundaries, that receiver’s result is forwarded unchanged to a further dependency; elsewhere it is discarded. Other interactions forward an unscaled returned word. One later single-argument interaction uses twice a primary result rather than four times it. These relationships must remain distinct.

The phases below describe payload provenance, exceptional argument relationships, and direct-access order. They do not authorize omission or coalescing of intervening opaque interactions.

### Incoming-payload phase

Early computed-address byte stores use the incoming 8-bit payload. No local assignment first replaces it with zero.

The ordinary relationship is:

- Byte destination: eight times the producing result.
- Following interaction: two equal explicit arguments, each 16,384 times that same result.

The equal arguments are not established to be lengths, bounds, or region endpoints.

Exceptions include:

- A destination at twice a result, followed by equal arguments scaled by 4,096. The address-producing result comes from F-70f204417fd6-D03, which receives four times an earlier result. That earlier result is not the store’s address source.
- A four-argument interaction after an ordinary eightfold store. Arguments one, two, and four contain the same 16,384-scaled value; argument three contains the incoming word scaled by 1,024.
- The immediately following interaction receives eight times a secondary output of that four-argument interaction.
- Several boundaries forward four times the result of the equal-argument interaction to another dependency.
- A boundary keeps the eightfold byte destination but uses two equal fourfold arguments instead of 16,384-scaled arguments.

Two 64-bit-result interactions occur during this phase. At each, the next relevant interaction receives the low 32-bit portion first, the high 32-bit portion second, and the same high portion again third. Argument-position duplication is established; domain meaning is not.

These stores are explicit byte writes, without a represented destination readback or read-modify-write.

### Zero stores and payload transitions

After the incoming-payload phase, six explicit computed-address byte stores write zero. Each has a separately obtained producing result, an eightfold destination, and a following interaction with equal 16,384-scaled arguments.

These are six ordered writes, not a region-clear guarantee. Destinations may alias, and dependencies between writes may change memory.

The next payload transition stores the low byte of the store’s own computed destination. The destination is eight times its producing result. The following interaction receives two equal 16,384-scaled arguments and a third argument containing the eightfold address value, not merely its low byte.

A subsequent unsigned 32-bit result establishes a longer-lived payload: the low byte of eight times that result. Its initial destination is sixteen times the result, and the following equal arguments use a scale of 32,768.

Later stores reuse this retained payload. Fresh address-producing results do not themselves establish replacement payloads.

### Retained history and large-scale destinations

- Following equal arguments at a further scale of 134,217,728.

Such simplification is conditional where signed operations are involved; unbounded arithmetic or assumed signed wrapping is insufficient.

### First halfword read

A later boundary writes the longer-lived payload to a byte destination equal to 8,192 times a fresh result. It then reads 16 bits at 4,096 times the same result plus byte offset 56.

The following interaction receives the 4,096-scaled base first and the loaded halfword contents second. The loaded contents are not the read address.

Observable order is:

2. Halfword read.

### Extracted payloads

A later computed-address byte store uses original bits 19 through 26 of the unsigned result that established the longer-lived payload. The extraction excludes bits above bit 28 before byte truncation; truncation additionally excludes bits 27 and 28. The resulting stored byte can range from zero through 255. It is not inherently three-bit.

A different payload derives from the upper numerical byte of the retained product. Dividing this unsigned byte by 32 produces a value from zero through seven. This three-bit payload is stored repeatedly afterward.
