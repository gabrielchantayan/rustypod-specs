# F-164f955d6593

## Purpose

F-164f955d6593 makes one or two ordered requests through runtime-selected operations. It derives each request value from its first 32-bit argument. The first operation receives a value retaining the argument’s highest eight bits and lowest twelve bits. If that operation returns zero, a second operation receives a value retaining only the lowest twelve bits.

A nonzero operation result is treated as an address. The function returns the 32-bit word at byte offset 4 from that address. If both operations return zero, the function returns zero without performing that result-relative read.

“Request,” “lookup,” and “fallback” describe the observed control flow, not an established application-level meaning. The evidence does not identify what the masked fields represent or what the extracted word means.

Two separate reads of the global dispatch reference are significant. The function saves the reference from the first read for possible fallback dispatch. After writing the first request value, it reads the global reference again to select the first operation. The first operation and fallback can therefore use different objects even if neither operation changes the global reference.

## Interface

| Position | Established treatment |

The local request word is addressable, writable storage. Each lookup receives its address, not merely its value. The same address is supplied on both attempts.

The representation also places the fourth-argument copy adjacent to the request word. This does not establish that the lookup accepts a two-word public request structure or reads the neighboring word.

### Implicit inputs

The function accesses a global dispatch reference after calling F-5ca868b1d325. It reads that global reference twice before the first lookup:

1. Once to retain a reference for possible fallback.
2. Again, after writing the first masked request value, to select the first lookup’s dispatch object.

The function also depends on dispatch data reachable through the selected objects and on memory reachable through any nonzero lookup result.

### Output

Normal completion returns an opaque 32-bit word:

- Two zero lookup results produce zero.
- Otherwise, the output is the 32-bit word at byte offset 4 from the first nonzero lookup result.

A zero output does not uniquely indicate lookup failure. A successful lookup can select a payload word whose value is zero.

All accesses and calls on the executed path must be valid:

- Both reads of the global dispatch-reference storage must be possible.

The saved object need not be dereferenceable on a path where the first lookup succeeds: the function saves its reference but does not use it for dispatch on that path.

## Behavior

### Preparation and ordered global reads

The function first copies argument 3 into the local request word and argument 4 into a separate local word.

It then calls F-5ca868b1d325 with no explicit arguments. No return value from that dependency is consumed. The local copies precede this call; neither is explicitly passed to it.

After that dependency returns, the following order is established:

1. Read the global dispatch reference and save the resulting object reference for possible fallback.
2. Overwrite the request word with argument 1 masked by `0xFF000FFF`.
3. Read the global dispatch reference again to obtain the object used for the first lookup.
4. Read that object’s initial dispatch-table reference.
5. Select and invoke the callable entry at byte offset 8 of that table.

The two global reads must not be described as a single cached read. The saved reference supplies fallback dispatch, while the later read supplies first-attempt dispatch.

Changes made by F-5ca868b1d325 can affect both reads because both occur after it returns. The body does not establish that the dependency initializes the global, preserves other globals, or has no other effects.

### First request value and invocation

The first request value is argument 1 bitwise-masked with `0xFF000FFF`. For a 32-bit argument, the mask:

- Retains bits 31 through 24.
- Clears bits 23 through 12.
- Retains bits 11 through 0.

This is a bit-selection operation, with no arithmetic overflow or signed comparison involved.

The first selected operation receives one explicit argument: the address of the local request word. The supplied representation does not show a separate receiver argument. It does not establish a complete calling convention or exclude implicit execution context.

The operation returns a 32-bit result. The function tests only whether that result is zero:

- Zero triggers fallback.
- Any nonzero bit pattern selects payload extraction.

A high-bit-set result is not rejected as negative. There is no alignment check, address-range check, or classification of nonzero values as error codes.

The operation may write through the supplied request address. Such writes do not determine success: the function branches on the returned result, not on the post-call contents of the request word.

### Fallback request and invocation

Fallback occurs exactly when the first lookup returns zero.

Before invoking fallback, the function overwrites the same request word with argument 1 masked by `0x00000FFF`. This retains bits 11 through 0 and clears bits 31 through 12. Any value written into the request word by the first lookup is replaced.

Fallback dispatch uses the object reference saved by the **first** global read. It does not read the global reference again and does not necessarily use the object selected for the first lookup.

At fallback time, the function reads the saved object’s initial dispatch-table reference and selects the callable entry at byte offset 8. These dispatch contents are read for the fallback; the first lookup’s callable target is not cached for reuse.

The resulting distinctions are observable:

- A change to the global reference between its two initial reads can make fallback use a different object from the first lookup.
- A change to the global reference during the first lookup does not replace the already-saved fallback reference.
- A change to the saved object’s dispatch-table reference or relevant table entry can affect fallback.
- If the first lookup used a different object, changes confined to that different object do not by themselves change dispatch through the saved object.

These statements describe which references are used. They do not establish synchronization or safe concurrent mutation.

The fallback receives the same local address as the first lookup. If both masks produce identical values, the second call still occurs after a zero first result. There is no equality check or duplicate-request suppression.

If fallback also returns zero, the function returns zero. It does not read a payload relative to either zero result.

### Payload extraction

On either lookup’s nonzero result, the function reads one 32-bit word at byte offset 4 from that result and returns the word unchanged.

First-attempt success prevents fallback, regardless of the extracted payload’s value. In particular, a payload of zero does not trigger another lookup.

The body does not explicitly read a field at result offset 0, validate an object header, inspect the extracted word, or release the lookup result.

The offset is a four-byte address displacement. The evidence provides no allocation-bound check or explicit address-overflow handling. Normal completion therefore requires the resulting access to be valid; the contract does not assign portable behavior to an invalid or wrapping address calculation.

## Acceptance examples

These examples are conditional consequences of the static evidence, not executed tests. Unless a case states otherwise, assume valid memory and call targets, normal dependency returns, and no unspecified interference.

### First lookup succeeds

For argument 1 equal to `0xAB123456`, the first request word is `0xAB000456`.

If the first lookup returns a nonzero address whose word at byte offset 4 is `0x13579BDF`, the function returns `0x13579BDF`. Fallback does not occur.

### Fallback succeeds

For argument 1 equal to `0xAB123456`:

- The first lookup receives `0xAB000456`.
- A zero result causes the request word to become `0x00000456`.
- Fallback dispatches through the object saved by the first global read.
- If fallback returns a nonzero address with payload `0x2468ACE0` at byte offset 4, the function returns `0x2468ACE0`.

### Both lookups return zero

Exactly two lookup calls occur after F-5ca868b1d325. The function returns zero without a result-relative payload read.

### Successful result has a zero payload

If the first lookup returns nonzero and its payload word is zero, the function returns zero without fallback. The output alone cannot distinguish this case from two zero lookup results.

### Equal request values still produce two calls

For argument 1 equal to `0x00123456`, both masks produce `0x00000456`.

If the first lookup returns zero, fallback still occurs. The equal request values do not imply equal results, equal targets, or absent side effects.

### Global changes between its two reads

Suppose the first global read yields object A. After that read, but before the second global read, the reference changes to object B.

The first lookup dispatches through B. If it returns zero, fallback dispatches through saved object A. This distinction does not require either lookup to modify the global reference.

This example is conditional on those read values being observed and all required accesses remaining valid; it is not a guarantee of safe concurrent mutation.

### Global changes during the first lookup

Suppose both initial reads yield object A, and the first lookup then replaces the global reference with object B before returning zero.

Fallback still dispatches through A. If that lookup also changed A’s dispatch data, fallback uses the dispatch data read from A at fallback time.

### Request storage is modified

If the first lookup changes the request word and returns zero, fallback receives the low twelve bits of the original first argument, not the modified word.

If the first lookup returns nonzero, request-word changes do not replace the payload extraction from the returned address.
