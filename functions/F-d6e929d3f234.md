# F-d6e929d3f234

## Purpose

F-d6e929d3f234 interprets an encoded numeric value beginning at a supplied byte address and returns a 32-bit unsigned result. The leading byte selects either a directly decoded integer representation or a delegated conversion.

The function is a reader, not an advancing cursor operation: its directly visible implementation does not update the supplied addresses. For one leading-byte value, it calls F-18cef3824d73; any effects of that dependency are outside the established local behavior.

For integer representations that require additional bytes, a failed length check produces zero. That result is indistinguishable from a successfully decoded zero. There is no corresponding local check that the leading byte itself lies within the supplied bounds.

The encoded format’s name, intended domain, and validity rules are not established. In particular, the implementation accepts leading-byte values that an external format specification might reserve or reject.

### Result

The delegated branch starts from a signed integer result, shifts it right by 16, and converts the shifted result to the unsigned return type. The signed-shift qualification is discussed under **Uncertainties**.

## Behavior

### Initial selection and observable read sequence

The directly expressed sequence is:

1. Read the start address from the descriptor.
2. Read the limit address from the descriptor.
3. Read the byte at the start address and compare it with hexadecimal 1E.
4. If that comparison matches, use the delegated path.
5. Otherwise, read the byte at the start address again and use that value to select an integer representation.

Thus, the supplied representation expresses two leading-byte reads on the nondelegated path, rather than a single saved leading byte. The decoding rules below assume the input remains stable during the call.

The source alone does not prove the exact number of physical loads after compilation. Concurrent modification, memory-mapped input, and other externally changing storage are not assigned reliable semantics by this contract.

### Delegated representation: leading byte 1E

If the initial leading-byte comparison matches hexadecimal 1E, the function calls F-18cef3824d73 with:

- The original start address, still pointing at the leading byte.
- The original limit address.
- A third argument equal to zero.

The leading byte is not skipped before this call. No additional local length check precedes delegation.

The dependency’s signed integer result is shifted right by 16 positions. The shifted value is then returned as a 32-bit unsigned quantity.

Under arithmetic signed-right-shift semantics, this retains the signed upper 16-bit portion of the dependency result and sign-extends it before unsigned conversion. It is not an unsigned extraction that necessarily returns a value between 0 and 65,535. For negative inputs, arithmetic right shift also differs from signed division that truncates toward zero.

The caller performs no subsequent descriptor or payload reads in the visible delegated path.

### Three-byte representation: leading byte 1C

This representation consists of the leading byte followed by two payload bytes.

The function checks whether the start address plus three is less than or equal to the limit address.

- If the check fails, return zero without reading the payload.
- If the check succeeds, combine the two payload bytes in big-endian order and return the resulting unsigned 16-bit value, zero-extended to 32 bits.

The first payload byte supplies bits 15 through 8; the second supplies bits 7 through 0. There is no sign extension. Payload bytes FF FF therefore produce 65,535.

The limit may equal the address immediately after the second payload byte.

### Five-byte representation: leading byte 1D

This representation consists of the leading byte followed by four payload bytes.

The function checks whether the start address plus five is less than or equal to the limit address.

- If the check fails, return zero without reading the payload.
- If the check succeeds, combine the four payload bytes in big-endian order into the 32-bit unsigned result.

The first payload byte supplies bits 31 through 24, followed by the remaining bytes in descending significance.

Every 32-bit bit pattern is representable by this branch. A payload with its top bit set is still returned through the unsigned interface; no signed-range validation occurs.
