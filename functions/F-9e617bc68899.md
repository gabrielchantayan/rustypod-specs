# F-9e617bc68899

## Purpose

F-9e617bc68899 scans an indexed collection exposed through an object field and returns one greater than the largest positive score among entries whose classification matches a supplied selector.

The classification is binary: an entry is classified according to whether a dependency’s 64-bit result is zero or nonzero. The selector is compared against that normalized classification, not against the original 64-bit value.

The running maximum starts at zero. Consequently, matching entries with zero or negative scores do not lower the result. Subject to representable final arithmetic and normal completion of all dependencies, the result is at least one.

This description establishes the wrapper’s behavior. The meanings of the collection, classification, and score are not established.

The object address must support every collection-field read that execution reaches. The source provides no explicit null check, object-size check, alignment check, or lifetime check.

### Output

The represented return type is a signed 32-bit integer.

For executions with valid memory accesses, normally returning dependencies, and representable final addition, the return value is:

- One, if no entry both matches the selector and has a positive score.
- Otherwise, one greater than the greatest positive score returned for a matching entry.

A matching score equal to the largest signed 32-bit integer creates an arithmetic boundary: adding one is not representable as a signed 32-bit result. The supplied representation does not establish a portable result for that case.

## Behavior

### Initial count acquisition

The wrapper first reads the collection field and passes its four-byte value to F-03ceb16af2f5.

The returned signed count is retained as the scan bound. The wrapper does not obtain another count later, even if a dependency changes the object, the collection field, or collection contents.

Only after this dependency returns does the wrapper begin its scan with a running maximum of zero.

If the count is zero or negative, there are no indexed dependency calls. The wrapper proceeds directly to the final addition and returns one.

### Scan range and ordering

For a positive count, the wrapper visits indices in increasing order, beginning at zero and ending at the count minus one.

Each visited index has the following externally relevant order:

1. Read the collection field.
2. Call F-40de2fa7f2df with that newly read field value and the current index.
3. After that call returns, read the collection field again.
4. Call F-ed5c859d049c with this second field value and the same index.
5. After both results are available, consider whether the score should replace the running maximum.
6. Advance to the next index.

The two collection-field reads are distinct. The wrapper does not retain the field value used for count acquisition or reuse the classification call’s field value for the score call.

Consequently, the count, classification, and score calls may receive different collection-field values if the field changes between reads. In particular, if F-40de2fa7f2df changes that field before returning, the subsequent F-ed5c859d049c call receives the changed value.

No assumption is made that a dependency preserves globals, object fields, collection contents, or memory ownership.

### Classification matching

The classification result is normalized as follows:

- A 64-bit result of zero produces classification zero.
- Any nonzero 64-bit result produces classification one.

Negative nonzero results and values whose only nonzero bits lie above the low 32 bits both belong to classification one. The comparison concerns the full represented 64-bit result.

The unsigned selector must equal this normalized zero-or-one classification.

Therefore:

- Selector zero admits only entries whose classification result is exactly zero.
- Selector one admits every entry whose classification result is nonzero.
- Any selector greater than one admits no entries.

The selector is not normalized to a Boolean. For example, selector two does not mean “nonzero.”

An out-of-range selector does not bypass the scan. For a positive count, both indexed dependencies are still called for every index.

### Score selection

The score dependency is called unconditionally for each visited index, including when the classification cannot match the selector.

After both calls return, the wrapper replaces its running maximum only when both conditions hold:

- The normalized classification equals the selector.
- The signed score is strictly greater than the current running maximum.

Because the initial maximum is zero:

- Negative scores never replace it.
- Zero scores never replace it.
- Positive scores can replace it only for matching entries.
- A score equal to the current maximum leaves that maximum unchanged.

Equal-score behavior does not imply selection of a particular entry: the function returns only a number and retains no externally exposed entry identity.

### Final result and arithmetic limits

After the scan, the wrapper adds one to the running maximum and returns the result.

For a maximum between zero and `2,147,483,646`, inclusive, the result is representable and lies between one and `2,147,483,647`, inclusive.

If a matching score of `2,147,483,647` becomes the maximum, the final addition exceeds the signed 32-bit range. This contract does not assign a wrapped, saturated, or error result to that execution.

The scan index itself does not require signed overflow for any positive signed 32-bit count. At the largest possible count, the final visited index is `2,147,483,646`; the subsequent increment reaches the count, and the scan ends.

## Acceptance examples

These examples are conditional static expectations, not reports of executed tests. Unless stated otherwise, assume valid field reads, normally returning dependencies, and stable dependency responses.

### Nonpositive count

If F-03ceb16af2f5 returns zero or a negative number:

- Neither indexed dependency is called.
- The selector has no effect on the result.
- The function returns one.

### Filtering and maximum selection

Suppose the count is four, and the indexed classification-result/score pairs are:

| Index | Classification result | Score |
|---:|---:|---:|
| 0 | 0 | 7 |
| 1 | 5 | 12 |
| 2 | 0 | 3 |
| 3 | -2 | 9 |

With selector zero, the qualifying positive scores are seven and three, so the result is eight.

With selector one, the qualifying positive scores are twelve and nine, so the result is thirteen.

Both cases still call both indexed dependencies at all four indices.

### Selector outside the binary domain

The scan still performs all eight indexed dependency calls. No classification can match selector two after normalization.

### Matching nonpositive scores

If every matching entry has a score of zero or less, the result is one, even if nonmatching entries have large positive scores.

### Full-width classification

Suppose an entry’s 64-bit classification result is `4,294,967,296` and its score is six.

That entry matches selector one, not selector zero. If no matching entry has a higher score, the result is seven.

### Field mutation between calls

Suppose the collection field initially contains value A, and the count call returns two. At index zero, suppose the classification call receives A and changes the field to B before returning.

The score call for index zero must use a fresh field read and therefore receives B, provided no intervening effect changes it again. The retained scan count remains two.

### Maximum representable score
