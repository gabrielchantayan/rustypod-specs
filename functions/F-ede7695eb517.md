# F-ede7695eb517

## Purpose

F-ede7695eb517 modifies object-like storage, invokes two dependencies, acquires an accounting context through a global pointer, checks preceding metadata, updates accounting words, and delegates further processing of the metadata.

The established contract is the ordering of these accesses and calls. Destruction followed by allocation release is **inferred intent**, not an established ownership contract. The available source does not establish the object type, the meanings of the accounting categories, or whether either final dependency releases storage.

A null object address produces an immediate no-op. For a non-null address, the initial overwrite and two dependency calls precede metadata validation. Rejection therefore does not imply that the input or external state remains unchanged.

## Behavior

### 1. Null handling

If P is null on entry, the function returns immediately. It does not read either global data source, write object storage, examine metadata, acquire a context, or call a dependency.

Additional null comparisons appear later, but the locally held P is not reassigned. They do not provide additional metadata or context validation on an execution that began with non-null P.

### 2. Initial overwrite and object-side calls

For non-null P, the function:

1. Reads the global overwrite datum.
2. Stores the obtained 32-bit value at P.
3. Calls F-1bf9985dc121 with P + 92.
4. Calls F-2fd8826557a4 without an explicit argument.
5. Acquires C through the global context-pointer datum and its referent.

The overwrite is **global-sourced**, not established as a fixed constant. Different invocations may read different values if that global datum changes. A dependency that later changes the datum does not cause this function to repeat the initial store. Conversely, the function provides no guarantee that dependencies preserve the word already written at P.

Context acquisition occurs after both calls. A change by either call to the global pointer, or to the context value stored at its referent, can affect which C is acquired. Subsequent operations use captured C rather than re-reading that pointer chain.

Dependencies may also modify metadata or other relevant memory. Later reads observe the state present when they execute, not necessarily entry state.

### 3. Header validation

After acquiring C, the function checks the 32-bit header at P − 8.

The failure condition is:

- The header is zero; or
- A subsequent header read has bit 0 set.

The zero test is evaluated first. When it finds zero, the bit test is skipped. Otherwise, the source expresses another header read for the bit test; it does not establish one shared captured value for both tests.

On failure, the function calls F-a817d8d58c10 without an explicit argument. The supplied representation marks this dependency as non-returning. Its implementation and actual failure mechanism are unavailable. The local source contains no explicit rejection return after that call if it were unexpectedly to return.

On the normal continuation, the function calls F-c0fc6d033caa with C before reading the selectors and capturing the accounting amount.

The check neither validates selector bounds nor requires a nonzero masked amount. A nonzero header with bit 0 clear can pass even when its accounting amount is zero. Header changes after this check are not revalidated.

### 4. Four amount updates

After F-c0fc6d033caa returns, the function reads the unsigned 16-bit selector at P − 4 and forms the first selected accounting address.

It then reads the header at P − 8 and captures the result of masking it with **0x3FFFFFFC**. This amount retains bits 2 through 29, clears bits 0, 1, 30, and 31, and lies between zero and 0x3FFFFFFC inclusive in multiples of four.

Using that one captured amount, the function performs these updates in order:

1. Subtract from the word at C + 0x224 + four times the first selector.
2. Subtract from the word at C + 0x30C.
3. Read the unsigned 16-bit selector at P − 2, then subtract from the word at C + 0x0E0 + four times that selector.
4. Subtract from the word at C + 0x220.

The second selector is read after the first two updates. The amount is not re-read for the third or fourth update.

Each selector ranges from 0 through 65,535. Multiplication by four yields a displacement from zero through 262,140. This multiplication does not overflow 32 bits, but it does not establish that adding the displacement and base offset to C produces an intended or valid address.

Each update reads the selected word’s then-current value and writes the subtraction result. If locations alias, a later operation can observe an earlier write.

### 5. Count updates and final amount update

The function next calls F-09dcb55e8e0a without an explicit argument. Its result is represented as a signed 32-bit integer.

The function then:

1. Decrements the 32-bit word selected by C + 0x310 + four times that result.
2. Decrements the 32-bit word at C + 0x390.
3. Updates the word at C + 8 by subtracting a newly read header value masked with 0x3FFFFFFC.

No local check constrains the index-producing result to nonnegative values or a valid table range. Large or negative results must not be silently treated as validated indices.

The final masked amount is independent of the earlier captured amount. Header changes caused by accounting aliases or F-09dcb55e8e0a can therefore affect it. There is no second validity check before this subtraction.

The source establishes the order of these updates, but not a total ordering of independent operand reads within an individual arithmetic expression. In particular, this contract does not require a particular order between reading an accounting destination and reading the header where both participate in one update.

Validation passes and the masked amount is 256. The amount destinations at C + 0x230, C + 0x30C, C + 0x0F4, C + 0x220, and C + 8 become 744. The count destinations at C + 0x318 and C + 0x390 become 9.

### Changed final header

### Aliased count destinations

### Underflow
