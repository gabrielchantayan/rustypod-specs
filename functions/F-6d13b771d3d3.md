## Behavior

### Ordered memory operations

For an execution that reaches each successive operation without a fault or external interruption, the visible local sequence is:

1. Store the incoming r4-derived 32-bit value at the destination-region pointer.
2. Store the incoming r6-derived 32-bit value four bytes after that pointer.
3. Read an unsigned 16-bit value eight bytes after that pointer.
4. Zero-extend the read value and interpret the result as an absolute address.
5. Store the incoming r4-derived 32-bit value at that absolute address.
6. Calculate the indirect-transfer arguments and target, then perform the transfer.

These operations are ordered in the supplied representation. It does not establish physical bus transaction widths, compiler memory barriers, atomicity, or visibility order to other processors or devices.

### First transfer argument

The first supplied argument is derived from the already-read 16-bit address value.

The visible calculation advances a pointer measured in four-byte units by four elements, converts the result to an integer, and multiplies it by 16,777,216. The advance therefore represents **16 bytes**, not four bytes.

With ordinary non-wrapping address arithmetic, the integer before multiplication ranges from 16 through 65,551. The multiplication raises an important width issue:

- With 32-bit modular multiplication, only the low eight bits of that integer affect the result.
- Under that interpretation, the argument is the low byte of the read address plus 16, modulo 256, placed in bits 24–31; bits 0–23 are zero.
- For example, address value zero produces argument bits `0x10000000`, and address value `0x00F0` produces zero.

However, the supplied representation expresses the operation using a signed integer multiplication. Under signed 32-bit source-language rules, many possible inputs exceed the representable positive range. The evidence does not justify treating the displayed expression as a portable signed-arithmetic specification.

Accordingly, the 16-byte advance and multiplication factor are established static evidence. The low-32-bit result is a conditional machine-arithmetic interpretation, not an unqualified cross-platform guarantee.
