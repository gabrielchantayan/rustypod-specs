# F-9d78ef8dc721

## Purpose

F-9d78ef8dc721 populates caller-supplied result storage through one of four paths:

- A fallback path when a signed index-like value fails validation.
- A flag-dependent transformation for selector `0x6D1E`.
- A composite, address-like construction for selector `0x6D1F`.
- A delimiter-selection path for every other selector.

These roles describe the supplied static representation, not established application semantics. The relationship between the index and the selected record is unresolved. The generic path’s initial text, fallback content, and composite formatting rules are also unresolved.

This contract distinguishes established operations from inferred intent. Dependencies are identified only by opaque IDs. Their allocation, ownership, failure, and shared-state behavior are not supplied.

## Behavior

### Validation and fallback

The index-like value is interpreted as signed 32-bit.

A negative value takes fallback without reading the context’s upper-bound word. For a nonnegative value, the function reads the bound at context offset `0x58` and rejects the index when it equals or exceeds that bound under signed comparison.

Thus zero is accepted only when the bound is positive. A negative bound rejects every nonnegative index. The check is not an unsigned comparison.

On fallback, the observable data-access sequence is:

1. Capture the shared fallback-object pointer from its global storage.
2. Read the fallback header global and write that 32-bit value to the destination’s first word.
3. Compare the destination address with the captured fallback-object pointer.
4. If they differ, clear the destination’s second word.
5. In that unequal-address case, read the captured object’s second word and pass the destination and that payload to F-151ab4bfe553.
6. Return the destination.

The header is read from a global; it is not an established constant. The pointer comparison and payload access use the captured fallback-object pointer, not a specified reread of its global storage.

When the addresses match, the header write still occurs, but the second-word clearing, payload read, and F-151ab4bfe553 call are skipped.

The order matters under aliasing: the fallback payload is read after both destination writes applicable to the unequal-address case. No general protection against partial overlap is visible.

F-e7b12f377f06 is not called on fallback.

### Common operation after successful validation

Every accepted index causes a call to F-e7b12f377f06 with the address at context offset `0x54`, before selector-specific processing.

The index is not an explicit argument of that call. Consequently, the evidence does not establish that the returned base represents the indexed record.

Both special selectors use the returned base. Generic selectors still perform the call, although they do not subsequently use that base in the displayed operations.

### Selector `0x6D1E`

The numeric configuration and flag are accessed in this order:

1. Read a signed 32-bit numeric global.
2. Read the byte at returned-base offset `0x39`.
3. If that byte is zero, retain the first numeric read.
4. If that byte is nonzero, read the same numeric global again and subtract five from this second read using signed 32-bit arithmetic.

All nonzero flag bytes select the reread-and-subtract path. The two numeric reads are not guaranteed to produce equal values. The first read still occurs when its value is replaced.

If subtraction from the second read exceeds the signed 32-bit range, behavior is **documented_only**. No overflow handling is established.

After selecting the numeric value, the function:

- Invokes F-9d0ecc5f6adf.
- Passes its result and the selected numeric value to F-c0b020cd3882.
- Reads a separate result-header global and writes its 32-bit value to the destination’s first word.
- Clears the destination’s second word.
- Passes the destination and F-c0b020cd3882’s result to F-151ab4bfe553.
- Returns the destination.

The header-global read occurs after both transformation calls. Its value is not established as immutable, and neither preceding dependency is assumed to preserve it. This path has no visible fallback-style self-alias exception.

### Generic selectors

Any selector other than `0x6D1E` and `0x6D1F` enters this path.

A signed ordinal is formed by subtracting `0x6D21` from the selector’s signed 32-bit interpretation. The ordinal is written into the initial word of a local temporary area, which is then passed to F-246821290652.

Nearby setup also stores the index-like value and other machine-state values. Their relationship to the temporary’s logical content is unresolved. In particular, the evidence does not establish an ordinary initialized text-object layout.

Subject to meaningful signed arithmetic, delimiter selection behaves as follows:

- The initial start position is zero.
- The function requests one preceding-boundary search for each ordinal step.
- Each search calls F-a4621b603aad with the temporary, delimiter value `10`, and the current position.
- A search result of exactly `-1` takes the fixed-data result path.
- Any other result becomes the next position after adding one.

A negative ordinal performs no preceding-boundary searches. It is not explicitly rejected.

After the preceding-boundary phase, a start position of `-1` also selects the fixed-data path. This post-phase check matters if unusual dependency results or arithmetic produce that value.

The fixed-data path calls F-398e0e9a318a with the result destination and a fixed data object. Its contents are not supplied.

Otherwise, one further F-a4621b603aad call searches from the selected start:

- If it returns a value other than `-1`, that value is the endpoint.
- If it returns `-1`, F-d8cbf9aa79a9 supplies the endpoint through a call with no displayed explicit arguments.
- F-ed33cfb647fe receives the result destination, temporary, start position, and endpoint minus start as the requested length.

Finally, F-289ec4311c64 receives the temporary, and its return value becomes this function’s return value, on both result-construction branches.

Delimiter `10` is established. Treating it as line feed and interpreting the operation as line selection are inferred intent. Position units, endpoint validity, and the argument-free endpoint dependency’s relationship to the temporary remain unknown.

Ordinal subtraction, position increment, loop counting, and endpoint-minus-start use signed integer operations in the representation. No overflow repair or validation of negative results other than the specified `-1` checks is visible.

### Selector `0x6D1F`

#### Initialization and configuration reads

The function first invokes F-a2527c9526b8, then invokes F-5b24edfb22c0 with the destination. The latter’s return value becomes the target supplied to subsequent F-34e302dc2e9a calls.

Next, default 32-bit configuration values are read in this exact role order:

1. Country.
2. Postal code.
3. State.
4. City.
5. Street.

Only after all five default reads does the function read the byte at returned-base offset `0x3A`.

If that byte is nonzero, alternate configuration globals are read in the same order: country, postal code, state, city, street. These replace the selected defaults. All five default reads occur even when all five values are subsequently replaced.

The initialization calls precede these reads and the flag access. They are not assumed to preserve globals or the returned-base object. Configuration contents and meanings beyond their call-site roles are unknown.

#### Leading components and street

#### City/state decision

A city-role temporary is constructed using offset `0x18`, its role-specific marker, and the selected city configuration. Its second 32-bit word is passed to F-d8cbf9aa79a9.

Only if that inspection returns nonzero does the function construct and inspect a state-role temporary using offset `0x20` and the selected state configuration.

The combined branch is selected exactly when both inspection results are nonzero. Negative inspection results also satisfy these tests.

If a state temporary was created, it is passed to F-289ec4311c64 first. The city temporary is then passed to F-289ec4311c64 in every case. These calls occur before either construction branch proceeds.

#### Combined branch

When both inspections are nonzero:

1. F-398e0e9a318a constructs a format-holder temporary from fixed format data.
2. F-5b24edfb22c0 initializes a separate output temporary.
3. Fresh postal-code, state, and city temporaries are constructed, in that order.

Interpreting the postal-code stack write as preparation of a fifth formatting argument is an ABI inference, not an established explicit argument. Its actual consumption by F-1f62160dfd52 is **documented_only**.

The inspected city and state temporaries are not reused. Fresh transformations can produce different values if dependencies observe changing state or have side effects.

Exact punctuation, spacing, encoding, and formatting behavior are not established.

#### Separate-components branch

If either required inspection is zero, fresh city, state, and postal-code temporaries are constructed and submitted individually, in that order.

Each temporary is passed to F-289ec4311c64 after submission and before the next field transformation.

This branch still transforms and submits state when the initial city inspection was zero and therefore skipped the initial state inspection.

#### Country and return

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Negative index:** Index `-1` takes fallback without a context-bound read or F-e7b12f377f06 call.

2. **Signed exclusive bound:** Bound `3` accepts index `0` and rejects index `3`. Bound bit pattern `0xFFFFFFFF`, interpreted as `-1`, rejects index `0`.

3. **Fallback self-alias:** If the destination equals the captured fallback-object pointer, the header global is still read and written to the first word; no explicit second-word clearing, payload read, or F-151ab4bfe553 call follows.

4. **Fallback header variability:** If the fallback header global contains a different value on another invocation, the destination receives that invocation’s read value, not an assumed constant.

5. **Zero special flag:** For selector `0x6D1E`, a zero flag retains the numeric global’s first read and causes no second numeric read.

6. **Nonzero special flag:** If the first numeric read yields `100`, the flag is nonzero, and the second read yields `80`, the selected value is `75`. The first read is not reused.

7. **Subtraction boundary:** If the second numeric read is the minimum signed 32-bit value, subtracting five exceeds the representable range. No particular result is specified.

8. **Configuration replacement:** With a nonzero `0x3A` flag, all five default reads precede the flag read; all five alternate reads follow it in country, postal-code, state, city, street order.

9. **Generic first segment:** Selector `0x6D21` performs no preceding-boundary searches. Under conventional text-search semantics, its final search bounds the first segment.

10. **Missing preceding delimiter:** For selector `0x6D22`, an initial search result of `-1` selects fixed-data construction instead of substring construction.

11. **Negative ordinal:** Selector `0x6D20` is not rejected for its ordinal of `-1`; it performs no preceding-boundary searches.

12. **Combined construction:** Two nonzero inspection results select combined formatting with fresh field temporaries. The postal-code extraction is written to stack storage; only four explicit formatting arguments are established.

13. **Skipped state inspection:** A zero city inspection skips initial state inspection, but the separate branch still transforms and submits city, state, and postal code.

14. **Return distinction:** If final F-289ec4311c64 returns a value different from the destination, that value is returned on generic and composite paths.
