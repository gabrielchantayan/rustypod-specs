# F-21ed86641ead

## Purpose

F-21ed86641ead performs an ordered series of indirect dependency invocations, transforms dependency results, mutates memory through derived and fixed addresses, and finishes with an unresolved indirect transfer.

The supplied static representation does not establish an application-level purpose. Character-like constants do not establish formatting or text processing; self-relative stores do not establish a particular collection or object model.

This contract distinguishes:

- **Established static evidence:** represented interfaces, widths, data relationships, and access ordering.
- **Inferred intent:** possible interpretations, not acceptance requirements.
- **documented_only:** behavior not resolved by the supplied evidence.

This is a static behavioral contract, not a claim of successful execution or a complete reconstruction of the underlying executable.

### Implicit inputs

### Outputs and completion

No explicit return value is represented.

The final indirect transfer receives four represented arguments:

1. 0x72.
2. A 32-bit value recently read from an offset-0x64 field.
3. A previously captured 32-bit offset-0x14 value.
4. A recently read 32-bit offset-0x74 value.

The third argument is a retained capture, not a fresh read at transfer time. The representation shows a call followed by return; the actual control-flow meaning and whether the target returns are **documented_only**.

### Preconditions and errors

Conditional completion requires all reached targets to be executable and all reached memory accesses to be valid at their represented widths. This includes low fixed addresses, potentially unaligned accesses, and addresses obtained from bytes, shifted values, multiplication, and loaded pointer-like contents.

No null, bounds, alignment, capacity, overflow, or target-validity checks are represented. There is no represented status code, exception translation, rollback, or cleanup path. Input validity alone cannot guarantee completion.

## Behavior

### Dependency invocation region

The initial dependency receives the unchanged first argument, unchanged second argument, and second argument shifted left by six positions. Two further indirect invocations precede an invocation receiving a returned 32-bit value shifted left by eight positions.

A long straight-line invocation region follows. Its established properties are:

- Distinct calls retain their represented order, including calls with no explicit arguments and calls whose results are ignored.
- Explicit zeros, duplicated arguments, and separately transformed versions of one result are significant.
- Captured results sometimes remain in use across many intervening calls.
- There are no explicit loops or conditional branches in this region.
- Progress remains conditional on dependency return.

A call with no explicit arguments does not establish that argument registers are cleared or that the true interface has no inputs.

Transformations include left shifts, logical right shifts of unsigned quantities, masks, and separation of wide results into two 32-bit portions. Visible low-field mask widths include 1, 11–22, and 24 bits. One recurring extraction retains the low 20 bits and shifts right by ten, selecting bits 10–19.

Unsigned 64-bit shifts by 34, 36, and 44 positions operate on the wide container before narrowing. They are not oversized shifts of a 32-bit operand.

### Width and arithmetic rules

Represented memory widths are 8, 16, and 32 bits; intermediate result containers also include 64 bits. Most arithmetic and address formation are represented at 32 bits. Byte stores retain eight bits. Byte reads used in explicitly unsigned promotions produce values from 0 through 255.

Under confirmed 32-bit machine-bit semantics, left shifts discard bits outside the result width. Successive shifts whose total reaches 32 can discard every original bit. Widening those calculations to unbounded arithmetic would change the contract.

Many expressions are represented as signed shifts or signed multiplication. Portable signed-overflow behavior is not established. Modulo-2³² interpretations are therefore conditional, not unconditional requirements.

A late byte store uses a signed right shift whose count comes from the low eight bits of an address-derived value. Counts of at least 32 are expressible. Count handling and signed right-shift semantics remain **documented_only**.

### Direct-effects terminology

The following descriptive roles identify captured values without asserting structure types:

| Role | Derivation |
|---|---|
| Shifted base | A dependency result’s lower 32 bits shifted left by 25 positions. |
| Scaled base | A separate 32-bit dependency result multiplied by 2²⁵. |
| Index | Bits 6–14 extracted from another result after its eight-position left shift. |
| Doubled index | Twice the index. |

All ordering below is ordering in the supplied representation. A load is evaluated against memory at that point, not automatically against entry-state memory. Derived addresses may alias one another or fixed-address storage.

### Opening mutations and first fixed-address accesses

The direct region first stores the shifted base as 32 bits at final-upper-portion plus 0x14. It then writes the upper portion’s low byte at shifted-base plus 0x09 and stores the scaled base at final-lower-portion multiplied by 256, plus 0x54. The same shifted-base byte destination is then written again, now with the shifted base’s low byte.

The scaled-base field at 0x14 is cleared before an unsigned byte is read at scaled-base plus 0x05. The doubled-index field at 0x14 is cleared next. The captured byte is zero-extended into the scaled-base field at 0x34, after which the scaled-base field at 0x14 is read as 32 bits.

That captured word is followed by another clear at doubled-index plus 0x14 and two distinct byte writes of its low byte at doubled-index plus 0x15.

**The fixed-address byte read at 0x05 occurs next.** Its zero-extended value becomes another base. Immediately afterward, address 0x01 receives the doubled index’s low byte. Subsequent operations write:

- The index’s low byte at the fixed-byte-derived base plus 0x15.
- The forwarded word’s low byte at scaled-base plus 0x11.
- The forwarded word as 32 bits at the earlier captured word plus 0x54.
- Zero at scaled-base plus 0x11.

Only then is a 32-bit association read from fixed-byte-derived base plus 0x54. That association is captured before the field is replaced by the earlier offset-0x14 capture. Consequently, neither the fixed 0x05 read nor this association read is an entry-state read.

### Traversal, overlapping fields, and remaining early fixed writes

The next region combines loaded addresses with stores at offsets 0x09, 0x14, 0x15, 0x24, 0x34, 0x44, 0x54, 0x64, and 0x74.

A 32-bit read at scaled-base plus 0x74 supplies a destination base. Separately, the doubled-index offset-0x74 field appears twice in one store expression: one read determines the destination and another determines the stored value. Their relative evaluation order is unresolved; they are not established as one captured read.

The captured association is written twice to its own offset-0x24 field, interleaved with byte writes through another loaded base. The doubled-index offset-0x14 field is first given a shifted dependency-derived value.

**At that point, fixed address 0x54 receives the captured association shifted left by one, as a 32-bit store.** Two 32-bit writes of the association to doubled-index plus 0x14 follow. Two byte stores at doubled-index plus 0x15 then use the low byte of four times that association. **Fixed address 0x15 next receives the doubled index’s low byte.**

Further traversal uses:

- Four times the captured association as a common derived base.
- A doubled value loaded through the doubled-index offset-0x74 field.
- A byte read at a derived base plus 0x05, used as the base of a 32-bit offset-0x74 read.
- An offset-0x64 load supplying another self-relative destination.
- A 32-bit offset-0x04 load supplying a later byte-read base.

The later byte at offset 0x05 is read twice, with intervening stores. These reads are not automatically interchangeable. The second traversal produces a leaf value and its doubled form, used in the final region below.

Offset 100 decimal means 0x64. These accesses do not establish a complete record layout. Byte stores at 0x15 can overlap word fields beginning at 0x14; aliasing and byte order determine the resulting bytes.

### Constants and repeated association updates

The leaf value supplies three ordered destinations for 0x3a: an 8-bit store at four times the leaf, a 16-bit store at eight times the leaf, and a 32-bit store at four-times-leaf plus 0x20.

The earlier fourfold association is reduced by 150. Four times this adjusted value is called the **mutation base** below. Its offset-0x20 field receives, in order, 32-bit values 0x20, 0x2f, the zero-extended byte then read at mutation-base plus 0x04, and 0x20 again.

A 32-bit global is then read and captured as the **global-derived base**. **After that read, fixed address 0x60 receives a 32-bit 0x20.**

An initial association group uses eight times the original association. Subsequent explicit groups use eight times the adjusted value. Each group orders four writes:

- A 32-bit four-times-leaf value at the applicable eightfold base plus 0x54.
- The mutation base’s low byte at global-derived base plus 0x19.
- The global-derived base’s low byte at mutation-base plus 0x11.
- The applicable eightfold value at global-derived base plus 0x34.

These are repeated explicit occurrences, not a data-dependent loop. Their exact multiplicity is not enumerated in this contract and remains **documented_only** here; replacing the region with one occurrence is not justified. The global-derived base is captured once, not reloaded between groups.

### Final captures and fixed-byte propagation

For this region, the **doubled-leaf base** is twice the leaf value; the **fourfold-leaf base** is four times that leaf.

After the repeated groups, the function reads a 32-bit word at fixed address **0xa9**, then reads the fourfold-leaf offset-0x74 field. It next writes fixed address **0x3a** with the low-byte result of eight times the adjusted value plus 0x30.

The doubled-leaf offset-0x14 field and mutation-base offset-0x04 field are then captured as 32-bit words. The former is retained for the final transfer.

Before updating fixed address 0x67, the function writes:

- The mutation base’s low byte at doubled-leaf plus 0x0d.
- 0x6c at mutation-base plus 0x08.
- The global-derived base’s low byte at mutation-base plus 0x0d and then plus 0x09.
- The doubled-leaf base as 32 bits at its own offset 0x54.

**Fixed address 0x67 then receives the low byte of the captured 32-bit word from 0xa9.** The doubled-leaf offset-0x44 field is read next. **A fresh byte read at 0x67 supplies the write to fixed address 0x21.**

That fixed-byte read follows the offset-0x44 read. The contract does not substitute the original 0xa9 capture for the read of 0x67.

### Offset-0x10 replacement and later reads of 0x67

The captured offset-0x44 value supplies a byte write at **mutation-base plus 0x10**, followed by a word write at global-derived base plus 0x54. The shift-derived byte store at doubled-leaf plus 0x01 follows. The global-derived offset-0x54 field is then replaced with the mutation base.

A word is next read at mutation-base plus 0x40. The earlier offset-0x04 capture is stored at global-derived base plus 0x74, and the newly read word is stored at **mutation-base plus 0x10**.

Thus, the explicit byte write at offset 0x10 **precedes** the 32-bit copy and is overwritten by it. Later byte writes at offset 0x11 use other derived bases. Their overlap with this copied field is conditional on aliasing, not established by a shared base.

After a word store at global-derived base plus 0x44, **0x67 is read again as a byte**, supplying a store at mutation-base plus 0x09. A byte store at doubled-leaf plus 0x09 and a word store of the captured 0xa9 word at mutation-base plus 0x44 intervene before a word is read at mutation-base plus 0x54.

**A third byte read at 0x67 then supplies another store at mutation-base plus 0x09.** These are three distinct reads of 0x67 overall: one for fixed 0x21 and two for the derived offset-0x09 destination. Intervening derived writes may alias 0x67. The read values are therefore not guaranteed identical.

### Completion mutations and final transfer

The recently loaded mutation-base offset-0x54 value becomes another destination base. Its offset 0x0d receives the low byte of the earlier fourfold-leaf offset-0x74 capture. The doubled-leaf offset-0x54 field receives the retained offset-0x14 capture.

A word is then read at mutation-base plus 0x14. Subsequent writes place:

- The earlier offset-0x74 capture’s low byte at doubled-leaf plus 0x11.
- The recently loaded destination base’s low byte at mutation-base plus 0x09.
- That destination base as a word at mutation-base plus 0x44.

A word read at doubled-leaf plus 0x04 supplies a loaded base. A 16-bit 0x65 is stored at twice that loaded base, before its offset-0x64 field is read for the second final argument.

The recent mutation-base offset-0x14 capture supplies a byte store at the other destination base plus 0x11, followed by a 32-bit decimal 100 at that base plus 0x54.

The loaded base’s offset-0x74 field is read for the fourth final argument. A separate read at doubled-leaf plus 0x64 supplies another base. Before transfer, the function writes the loaded base’s low byte at doubled-leaf plus 0x09, stores the second final argument at that other base plus 0x54, and stores that other base at twice the second final argument.

The transfer then receives 0x72 and the three captures specified in the interface.

## Side effects

The direct region performs byte, halfword, and word writes, including fixed-address byte writes at 0x01, 0x15, 0x21, 0x3a, and 0x67, and word writes at 0x54 and 0x60. Meaningful fixed reads include the byte at 0x05, the word at 0xa9, and the three separately ordered byte reads at 0x67.

Accesses are interleaved and nontransactional. Earlier effects may remain if a later access faults or a dependency does not return. No restoration is represented.

Endianness, alignment support, memory-mapped-device behavior, synchronization, atomicity, and concurrent modification are **documented_only**. Repeated represented accesses must not be collapsed merely because their destinations or values appear equal.

No explicit allocation or release is identifiable in the direct region. Dependencies may allocate, retain, mutate, or release memory; no ownership or lifetime guarantees are established.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Input forwarding:** A second input of 3 supplies unchanged 3 and shifted 192 to the initial dependency.

2. **Width boundary:** Under confirmed 32-bit machine-bit semantics, shifting 0x04000000 left by six produces zero, not a widened 0x100000000.

3. **Unsigned promotion:** An early scaled-base offset-0x05 byte of 0xff supplies a word value of 255 at offset 0x34.

4. **Fixed 0x05 timing:** If an earlier derived write changes address 0x05, the later fixed-byte read uses the changed byte, not an entry-state capture.

5. **Offset-0x10 replacement:** If the byte store writes 0xab and the subsequent word copy writes 0x12345678, the earlier byte does not survive independently. Byte layout depends on endianness. Later offset-0x11 stores affect that word only if their actual addresses overlap it.

6. **Separate 0x67 reads:** Suppose the captured 0xa9 word has low byte 0x12. Without intervening changes, 0x21 receives 0x12. If a later derived write aliases 0x67 and changes it to 0x34 before the first derived copy, that copy receives 0x34. If another intervening write changes it to 0x56, the second copy receives 0x56.

7. **Repeated updates:** An access-trace model retains the explicit association groups and their four-store order; final contents alone do not specify the represented behavior.

8. **Retained final argument:** A later aliasing store that changes the doubled-leaf offset-0x14 field does not refresh the capture already retained for the third final argument.

9. **Partial failure:** A successful early store is not restored by any represented path if a later pointer-derived access faults.
