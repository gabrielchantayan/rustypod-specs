## Behavior

### Widths and notation

The notation below describes observable relationships, not an implementation algorithm:

- \(R_8(x)\): read one byte at address \(x\), interpreted as an unsigned value from 0 through 255.
- \(W_8(x,y)\): write one byte at address \(x\), using the low eight bits of \(y\).
- \(W_{32}(x,y)\): write 32 bits at address \(x\).
- \(\operatorname{low8}(y)\): the low eight bits of \(y\).

Computed addresses are absolute expressions. No enclosing allocation or object base is visible.

Unsigned quantities are 32 bits unless stated otherwise. Their right shifts are logical. Signed multiplication and signed left shifting must not automatically be replaced by modular unsigned arithmetic.

For signed results, expressions displayed as \(4x\) summarize a fourfold scale. Where the representation uses a signed left shift rather than multiplication, that distinction is identified below; validity for negative or overflowing operands is unresolved.

Two particular scales are established unsigned operations:

\[
M_u=(4m)\bmod 2^{32},\qquad
R_u=(4r)\bmod 2^{32}.
\]

These are unsigned 32-bit left shifts by two: bits beyond bit 31 are discarded **before** conversion to a signed 32-bit intermediate.

Let \(M_s\) and \(V\) denote the respective signed conversions of \(M_u\) and \(R_u\). When the unsigned value is at most \(2^{31}-1\), the conversion preserves its numeric value. Conversion of a larger value is **documented_only**; a particular signed interpretation is not assumed.

The byte stores associated with these intermediates retain their low eight bits. Subsequent signed arithmetic using \(V\) has separate validity constraints.

### Unconditional loop and changing call target

1. Five-call chain **F-X18-1 … F-X18-5** begins with \(L\) and \(U\gg8\), producing signed 32-bit result \(v\).
2. A fresh selector read at \(B\) precedes \(W_8(R_8(B)+17,0)\).
3. Five-call chain **F-X19-1 … F-X19-5** begins with the signed-left-shift-by-two result of \(v\), producing signed 32-bit result \(w\).

**F-X18-1 changes its target expression after the first iteration.** Its first execution uses a code-associated anchor retained during the setup of **F-X17-2**, plus 4094 bytes. \[

## Side effects

### Explicit memory effects

Before the loop, the visible prefix contains exactly:

- **Eight 32-bit writes.**
- **Six byte writes.**
- **Five selector-byte reads.**

The six byte writes consist of two nonzero-capable selector-based writes, one direct third-input-derived write, two selector-based zero writes using \(A+1\), and one selector-based zero write using \(B\).

The direct third-input-derived write does not read a selector.

Each completed loop iteration adds one selector-byte read, one byte write, and ten indirect calls.

### Ordering and aliasing

## Acceptance examples

These examples are conditional static deductions, not executed tests. They assume valid addresses, defined relevant arithmetic, and returning dependencies unless otherwise stated.

### Initial ordering

For \(P=3\), the first explicit effect writes the 32-bit value 3 at absolute address 32. A trace placing any dependency call before that write conflicts with the visible ordering.

### Distinct shifts of the third input

For \(Q=\mathtt{0x00018000}\):

- The word stored after **F-X07-5** is 384.
- The third argument to **F-X09-1** is 768.
- The direct byte-write destination is address 31.
- **F-X14-1** receives 3.

### Retained overwrite destination

If \(k=2\), the first write at \(T+20\) writes 8 at address 52. After **F-X09** returns, the explicit overwrite writes 32 at address 52, regardless of \(l\). Intervening dependency effects remain possible.

### Unsigned scaling discards high bits first

If \(m=\mathtt{0x40000000}\), then \(M_u=0\) and \(M_s=0\). The first selector-based byte write stores zero, and all three explicit arguments to **F-X11-1** are zero.

If \(r=\mathtt{0x40000000}\), then \(R_u=0\), \(V=0\), and \(B=1\). The direct third-input-derived byte write stores zero. This case does not depend on an out-of-range unsigned-to-signed conversion.

### Fresh selector and byte truncation

If the first selector is 5, the first selector-based destination is 22. If a dependency changes that selector to 9, the next destination is 26.

For \(m=\mathtt{0x3ab00000}\), the masked shift by 20 produces \(\mathtt{0x3ab}\), but the associated byte write stores \(\mathtt{0xab}\).

### Loop transition

The first **F-X18-1** execution receives zero as its second argument and uses the entry-established target expression.

After a completed iteration, the next execution uses the target expression retained from **F-X19-5** setup, not the entry expression. Repeating the entry target expression would contradict the represented control-target transition.

A completed iteration proceeds into another iteration; no visible success return intervenes.
