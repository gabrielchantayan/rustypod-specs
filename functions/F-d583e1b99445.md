# F-d583e1b99445

## Purpose

F-d583e1b99445 describes a machine-state-dependent routine that conditionally copies one 16-bit value, may perform an additional indirect 16-bit update under exceptional arithmetic conditions, and then enters an unconditional dispatch-and-interrupt loop.

No application-level purpose is established. In particular, the supplied representation does not establish a buffer-processing API, a normal return path, or a recoverable error protocol.

A material distinction exists between the apparent size of the conditional sequence and its reachable effects. Under the 32-bit address arithmetic represented in the supplied material, the later conditional memory-transfer blocks cannot be reached from the stated entry conditions. They must not be promoted into unconditional or ordinary behavior.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Initial selection and optional halfword copy

If the primary address is nonzero:

- The initial copy is skipped.
- The conditional sequence preceding the dispatch loop performs no represented memory access.
- The dispatch base remains the incoming link address.

If the primary address is zero, the routine first computes a gate value from:

- the incoming link address;
- the incoming carry, interpreted as zero or one;
- the stack address logically shifted right by one bit.

Under the represented 32-bit arithmetic model, this sum is reduced to 32 bits.

It also computes a destination address by adding the displacement to the source address, in bytes. It then performs the following observable memory operations in order:

1. Read one unsigned 16-bit value from the incoming source address.
2. Write that value to the computed destination address.

The destination need not be disjoint from the source. Exact aliasing is permitted by the represented operation order: the read precedes the write.

The internal source-address state becomes the computed destination minus the adjustment. This calculation does not itself access memory. The carry state used by the subsequent gates is cleared.

No null, alignment, range, or writability check precedes the copy. In particular, a zero primary address does not imply that the source address is valid.

### 2. Conditions for reaching the exceptional update

After the initial copy, additional work is guarded by a succession of zero-result conditions.

For the exceptional update to be reached, all of the following must hold under the represented 32-bit model:

- The primary address was zero.
- The incoming link address is zero.
- The previously computed gate value is zero.
- The displacement equals the comparison word.
- The adjusted source-address state equals the adjustment.
- The auxiliary word is zero.
- Adding twice the displacement to the stack address produces zero modulo \(2^{32}\).

These are cumulative conditions, not alternative entry points.

The guarded shift operations do not require an arbitrary-shift policy on this reachable path: their shift counts are taken from results already required to be zero. Consequently, their effective shift counts are zero.

The arithmetic imposes an unusually strong restriction. Because the link address must be zero, the earlier gate value requires the incoming carry to be zero and the stack address to be either zero or one. The later addition requires an even stack address. Together, these imply:

- stack address zero;
- incoming carry zero;
- displacement either zero or \(2^{31}\).

This is a static consequence of the represented 32-bit arithmetic, not evidence that an actual execution environment permits such a stack address.

### 3. Exceptional indirect halfword update

If every preceding gate succeeds, the routine performs an exceptional state update.

The represented ordering is:

1. Update a special machine-state location using the stack address multiplied by 64.
2. Replace the link-derived address with the incoming link address plus the stack address multiplied by 64.
3. Read a 16-bit value from the original link address.
4. Use that 16-bit value, zero-extended, as a destination address.
5. Store a 16-bit value equal to the loaded value plus 15, truncated to 16 bits.
6. Advance an internal primary-address cursor by two bytes.
7. Clear the carried flag state.

The expression for the indirect update contains two references to the same 16-bit source location. The representation establishes the value dependency and the destination write, but not a reliable hardware-level ordering or count of those source reads if the location is volatile or externally changing.

Under the cumulative conditions above, both the incoming link address and stack address are zero. Thus, if this path can execute at all, it attempts to obtain the indirect-update value from address zero. Whether that address is readable is an environmental prerequisite, not a guarantee.

### 4. Later conditional blocks are not reachable

The exceptional update advances the internal primary-address cursor from zero to two.

If the following gates proceed far enough to compare that advanced cursor against the earlier zero gate value, their exclusive-or result is two, not zero. The remaining conditional chain therefore stops.

If the exceptional update is not reached, the later chain is already disabled.

Accordingly, under the stated model, the later represented blocks do not:

- advance an output pointer by 36 bytes;
- read through a sign-extended byte-derived address;
- emit a pair of 32-bit address-valued stores;
- perform the final signed-halfword-derived pair of stores.

Those operations appear in the supplied representation but are not established reachable behavior. They are not acceptance requirements for an implementation of this entry path.

### 5. Dispatch-and-interrupt loop

After the conditional region, the routine enters an unconditional loop.

On its first iteration, the dispatch base is the link-derived address retained by the preceding region. Under the reachable arithmetic cases described above, it equals the incoming link address: the only path that modifies it requires a zero stack address and a zero incoming link address.

Each iteration has this observable ordering:

1. Invoke the first indirect target at the dispatch base plus **3,766 bytes**.
2. Supply three represented 32-bit arguments: zero, zero, and `0xFFFFFFA5`.
3. After that call returns, invoke a second target at the represented fixed address `0x0857A94B`, with no explicit arguments shown.
4. After that call returns, issue software interrupt number `0x5B`.
5. If execution resumes after the interrupt, set the dispatch base to `0x083D4CC2`.
6. Repeat.

The third argument to the first dependency has the bit pattern `0xFFFFFFA5`. Interpreted as signed 32-bit two’s-complement, it is −91; its intended signedness is unknown.

After an interrupt returns and the base assignment executes, the next first-call target is `0x083D5B78`.

Neither an address calculation nor the supplied call notation establishes that the target is executable or that its encoded low bits satisfy the platform’s calling convention.

## Acceptance examples

These examples are conditional static obligations, not recorded executions.

### Nonzero primary address

Given a nonzero primary address and a usable incoming link address:

- No initial halfword copy occurs.
- No exceptional indirect update occurs.
- The first dependency target is the incoming link address plus 3,766 bytes.
- The calls and interrupt follow the stated order if each preceding operation returns.

### Zero primary address with a nonzero link address

Given readable source memory and writable destination memory:

- Exactly the represented initial halfword transfer occurs before dispatch.
- A nonzero link address prevents the exceptional path.
- The first dispatch still uses the incoming link address.

### Aliasing copy

Given zero primary address and zero displacement:

- The initial read and write address the same halfword.
- The loaded value is written back unchanged.
- No ownership change or allocation is implied.

### Faulting copy source

Given zero primary address and an unreadable source:

- The routine attempts the source read before the destination write.
- No successful copy or later call is promised.
- No routine-defined error result is available.

### Exceptional-path arithmetic

Assume the represented 32-bit model, readable address zero, and all exceptional gate equalities satisfied.

Then:

- The incoming carry and stack address must be zero.
- The indirect halfword update uses a value read from address zero.
- The later pair-store blocks remain unreachable.
- Successful arithmetic gating alone does not establish valid memory access.

### Interrupt continuation

If both calls return and the interrupt resumes execution:

- The dispatch base becomes `0x083D4CC2`.
- The next first-call target is `0x083D5B78`.

If the interrupt does not resume, no subsequent assignment or iteration is promised.
