# F-55b77747959b

## Purpose

F-55b77747959b processes a 32-bit input mask using two configured selectors and three table positions.

For each selector whose bit is present in the input mask, the function visits the table positions in ascending order. At a position whose membership word lacks that selector bit, it ORs the **entire input mask** into the corresponding accumulation word. At a matching position, it instead invokes a dependency sequence using selector-specific descriptor data and addresses of temporary storage.

The final dependency result controls continuation: zero allows another position to be processed; nonzero prevents all remaining table-position work in the invocation.

“Membership,” “accumulation,” and “payload” are descriptive names for observed data flow. Notification, delivery, and success/failure semantics are not established.

## Behavior

### Entry and configuration snapshot

The function captures the table-base value before reading the configuration word. It initializes its continuation state to zero, reads the 32-bit configuration word at offset 4 from configuration storage, and writes that word into local snapshot storage.

The selectors are the first two bytes of that snapshot in increasing memory-address order. The other two bytes are not used as selectors.

Consequences:

- Selector extraction is from one word snapshot, not repeated reads of configuration storage.
- Numeric interpretation of the configuration word’s first two bytes depends on target byte order.
- Later changes to configuration storage do not change the snapshot.
- Later changes to the global table-base value do not redirect this invocation’s table accesses.

The last two statements assume dependencies do not corrupt the function’s local storage.

### Selector processing

Exactly two selector positions are considered, in order. Each selector is read as an unsigned byte from the snapshot.

The function forms a shifted single-bit expression and intersects it with the input mask. If the intersection is zero, it does not traverse the table for that selector.

Selectors 0 through 30 have the straightforward interpretation of testing the corresponding bit in a 32-bit word. Selector 31 and selectors greater than 31 require target-specific shift evidence; the body provides no range check. A mathematical single-bit interpretation must not be imposed on those cases without establishing the target behavior.

The selector-position counter advances through 0 and 1 and then terminates the function. Its explicit byte-width reduction does not create additional selector iterations on this path.

### Position ordering and continuation

For an enabled selector, positions 0, 1, and 2 are considered in order.

Before reading each position’s membership word, the function checks its continuation state:

- Zero permits the position’s processing.
- Nonzero ends the current table traversal without reading that position’s membership word.

The continuation state is not reset between selectors. Even after a nonzero result, the second selector is still read from the snapshot and its eligibility expression is evaluated. It cannot cause further table-position work.

Thus, stopping table work does not eliminate every remaining local read or shift evaluation.

### Nonmatching position

A nonmatching position is one whose membership word lacks the selected bit.

The observable table-access sequence is:

1. Read the position’s 32-bit membership word.
2. Read its 32-bit accumulation word.
3. Write back that accumulation word ORed with the complete 32-bit input mask.

The update includes input bits unrelated to either configured selector. It is not restricted to the selected bit.

There is no dependency call on this path. The body does not skip the write when the resulting value equals the previous value. These are ordinary read-modify-write accesses; atomicity is not established.

### Matching position

A matching position is one whose membership word contains the selected bit. The function performs no direct accumulation-word update for that position.

It instead performs this sequence:

1. Obtain the current descriptor-base value and derive the selector’s record address using a 12-byte stride. The selector is converted through a character type for this calculation.
2. Write the selector byte into the local header.
3. Read the record’s 32-bit field at offset 4 and its one-byte field at offset 8.
4. Call D-01 with the 22-byte region’s address, the 32-bit field, and the one-byte field.
5. After D-01 returns, reread the byte at offset 8 from the same derived record address, this time through a character type.
6. Call D-02 with no arguments.
7. Add 4 to D-02’s result and pass the adjusted value and current position index to F-b37968c9f644.
8. Call F-cd7e1905512f with six arguments, in this order:
   - F-b37968c9f644’s result;
   - 0;
   - 3;
   - 9;
   - the selector-header address;
   - the promoted character captured after D-01, plus 1.
9. Call F-256e8a77aa59 with F-cd7e1905512f’s result and 0.
10. Replace the continuation state with F-256e8a77aa59’s result.

The relative evaluation order of the two descriptor-field reads preparing D-01’s arguments is not established. Both precede the call.

D-01’s return value is unused. No direct payload initialization, validation, or clearing occurs before that call.

The post-D-01 byte read can observe a value different from the byte supplied to D-01. It uses the previously derived record address; changing the global descriptor-base value during D-01 does not redirect that particular reread. A later matching position obtains the descriptor base again and can therefore use a different record location.

The character value used in the final argument is captured before D-02. Later dependency changes to descriptor storage do not cause another read for that argument.

### Completion

If F-256e8a77aa59 returns zero, the function proceeds to the next position, if any. Multiple matching positions can invoke the dependency sequence.

If it returns nonzero, all later position work is suppressed, including work for the other selector.

After considering both selectors, the function returns without an explicit result. There is no local rollback or explicit cleanup call. Earlier accumulation writes remain in effect unless another actor changes them.

## Side effects

### Direct writes

The body directly writes:

- The four-byte local configuration snapshot.
- The one-byte local selector header on each matching path.
- Reached accumulation words on nonmatching paths.
- Local traversal and intermediate-result state.

At most three distinct accumulation words are directly updated, but each can receive a separate write for each enabled selector.

**The body does not directly write the 22-byte destination region.** Passing its address to D-01 establishes neither initialization nor modification of its contents.

Repeated OR operations are value-idempotent when intervening state is unchanged. They nevertheless remain separate reads and writes, and dependencies can change table contents between visits.

### Dependency-visible effects

F-cd7e1905512f receives the header address. Its access direction, accessed extent, and treatment of the following region are unknown.

The function does not establish that any dependency preserves globals, descriptors, table contents, or other shared state. Only the table base and configuration word are captured for invocation-wide reuse.

If D-01 leaves destination bytes untouched, the enclosing function has not initialized them. Whether subsequent dependencies read those bytes, and whether such reads are valid, depends on unavailable dependency contracts.

The exposed temporary addresses are local to the invocation. Dependencies must not be assumed to copy the data, finish using it synchronously, retain it safely, or release associated resources. Those behaviors remain unknown.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, they assume valid storage, defined arithmetic and shifts, normal dependency returns, and no intervening mutation.

### Neither selector is enabled

Given selectors 2 and 5 and an input mask containing neither bit:

- The table base is captured.
- The configuration word is read and stored locally.
- Both selector eligibility tests occur.
- No table word is accessed and no dependency is called.

### Full-mask accumulation

Given selectors 1 and 4, an input mask containing bits 1 and 7, and membership words all lacking bit 1:

- Selector 1 visits all three positions.
- Every accumulation word receives an OR write containing both bits 1 and 7.
- Selector 4 causes no traversal because input bit 4 is absent.
- No dependency is called.

An implementation that accumulates only bit 1 would not match this behavior.

### A nonzero result stops later work

Given an enabled selector with position 0 nonmatching and position 1 matching:

- Position 0’s accumulation write occurs first.
- Position 1 invokes the dependency sequence without a direct accumulation update.
- If F-256e8a77aa59 returns nonzero, position 2’s membership word is not read.
- The second selector is still examined, but it performs no table-position work.
- The earlier accumulation update is not rolled back.

### Zero permits another matching position

Given matching positions 0 and 1:

- Position 0 invokes the sequence with index 0.
- A zero final result permits position 1 to invoke it with index 1.
- Another zero permits position 2 to be considered.

A membership match alone is not a stopping condition.

### Duplicate selectors are processed twice

- Both selector positions cause traversals.
- Unchanged nonmatching positions receive repeated full-mask OR writes.
- Matching positions can invoke the dependency sequence again.

There is no deduplication.

## Uncertainties

The following remain **documented_only**:

- **Shift semantics:** selector 31 and out-of-range selectors require target-specific evidence. No range check is present.
- **Character signedness:** descriptor indexing converts the selector through a character type. Under signed eight-bit interpretation, selector bytes 128–255 produce negative indices; under unsigned interpretation, they remain positive. This does not resolve whether the preceding shift is defined.
- **Promoted length-like arithmetic:** the post-D-01 character is promoted before adding 1. Under unsigned eight-bit character interpretation, the result ranges from 1 through 256; under signed eight-bit interpretation, from −127 through 128. This is not an established wrapping byte increment.

- **Destination bounds and initialization:** the region contains 22 bytes, but D-01’s access extent and initialization behavior are unknown. If it copies exactly a byte-count argument, counts above 22 would exceed the region; that copying interpretation is conditional.

- **Ownership and dependency effects:** no preservation, copying, retention, allocation, or release guarantees are established.
- **Concurrency and faults:** no synchronization or local fault recovery is shown. Platform behavior remains outside the supplied evidence.
