# F-4a4de352a54c

## Purpose

F-4a4de352a54c compares two zero-terminated byte sequences lexicographically, using unsigned byte ordering. For stable, readable inputs, it reports whether the first sequence sorts before, equals, or sorts after the second.

The comparison ends at the first unequal byte pair or at a zero byte. It does not compare sequence lengths in advance, interpret text encodings, apply locale rules, or normalize characters.

The result is a three-way ordering indicator, not the numerical difference between the bytes that determine the ordering.

This contract distinguishes behavior established by the supplied static representation from assumptions needed to describe ordinary, stable-memory use. No runtime tests have been performed.

## Interface

**Inputs**

- A first pointer to byte-addressable memory.
- A second pointer to byte-addressable memory.

Each compared element is an unsigned 8-bit byte, with values from 0 through 255. The interface supplies no length, capacity, encoding, ownership flag, or error-output location.

For the ordinary zero-terminated-sequence interpretation, each input must identify readable memory through and including its terminating zero byte. A narrower condition suffices for an individual invocation: every location actually examined before comparison ends must be readable. For example, an immediate mismatch can end the operation without either sequence’s later terminator being accessed.

**Output**

The result is a 32-bit value with one of these bit patterns:

| Relationship under stable-input conditions | Returned 32-bit value |
| --- | --- |
| First sequence sorts before the second | `0xFFFFFFFF` |
| Sequences compare equal | `0x00000000` |
| First sequence sorts after the second | `0x00000001` |

Interpreting `0xFFFFFFFF` as a signed 32-bit two’s-complement integer gives −1. The supplied return declaration establishes a four-byte result, but does not establish a signed API type. Consumers should distinguish the raw return representation from its signed interpretation.

There is no explicit error result. All three documented return values are comparison outcomes, not validation statuses.

## Behavior

### Comparison model

Comparison starts at offset zero in both inputs. Corresponding bytes are considered together.

If the current bytes are equal and nonzero, both positions advance by exactly one byte. The next comparison therefore concerns the next byte in each sequence. The function does not skip bytes or advance one input independently.

A pair stops the traversal when either:

- The two bytes differ; or
- A zero byte is encountered during the stopping checks.

With stable inputs, equal nonzero pairs are the only pairs that permit advancement. Consequently, the decisive position is the first mismatch, or the common zero terminator when all preceding bytes match.

### Ordering

At the decisive position, unsigned byte ordering determines the result:

- A smaller byte in the first input produces `0xFFFFFFFF`.
- Equal bytes produce zero.
- A larger byte in the first input produces one.

This gives the conventional prefix relationship. If one sequence ends where the other still has a nonzero byte, the terminating zero sorts before that nonzero byte. An empty sequence therefore sorts before every nonempty sequence.

Bytes with their high bit set remain positive unsigned values. For example, `0x80` sorts after `0x7F`, and `0xFF` sorts after `0x01`. There is no signed-character ordering.

Only the sign-like category is returned. A difference of one byte value and a difference of 255 byte values can produce the same result.

### Read structure and ordering limits

The supplied representation establishes repeated source-level accesses to the current bytes, rather than a single retained snapshot of each pair.

Within each traversal iteration:

1. The current bytes are compared for inequality.
2. Only if that comparison reports equality is the first input’s current byte checked for zero.
3. Only if that zero check reports nonzero is the second input’s current byte checked for zero.
4. Advancement occurs only if none of those checks stops traversal.

These checks are short-circuited. An unequal pair bypasses both zero checks. A successful first-input zero check bypasses the second-input zero check.

After traversal stops, the current bytes are read again for the return decision. The first ordering test distinguishes “first byte greater” from “first byte less than or equal.” The less-than-or-equal case performs a further strict-less-than test to distinguish the negative result from zero.

The relative evaluation order of the two operand reads within an individual binary comparison is not established by the supplied representation. It must not be specified as “first input is always read before second input.”

These are source-level evaluation facts, not a guarantee of a particular number or ordering of machine loads. The supplied material does not establish volatile accesses, compiler output, or an instruction-level memory-access trace.

### Boundary and termination behavior

Zero is a terminator, not an ordinary sequence element that can be traversed. If both inputs contain the same zero at the decisive position, bytes after that position do not affect the ordinary comparison result.

No maximum length or traversal bound is supplied. Equal nonzero bytes keep the comparison advancing until a stopping condition is reached.

The representation does not perform an integer length subtraction or accumulate a byte count. Its byte comparisons do not require signed arithmetic on byte values. Pointer width, address-space limits, and behavior upon advancing beyond a valid accessible object are not established.

### Inputs that change during evaluation

The stable-input condition matters because stopping checks and final ordering checks access the bytes again.

If input memory changes between those accesses, the values that caused traversal to stop need not be the values used to select the return value. The function provides no snapshot, lock, retry, or consistency check.

The visible return alternatives remain the same three constants, but a coherent lexicographic interpretation of changing data is not established. Whether concurrent modification is permitted at all depends on the surrounding execution and memory model, which is not supplied.
