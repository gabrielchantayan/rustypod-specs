## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Input forwarding.** If the explicit input is `0x89ABCDEF` and execution reaches F-I001, its displayed argument is exactly `0x89ABCDEF`. No visible preprocessing occurs.

2. **High-half shift truncation.** If H₈ is `0x00000200`, the third argument to F-I010 and the argument to F-I011 are both zero: shifting left by 23 discards the set bit. An unbounded arithmetic result would not conform.

3. **Guaranteed zero despite a nonzero result.** For every possible W₂₅, F-I038 receives zero as its first argument. Its unresolved second argument is not thereby constrained to zero.

4. **Sign-extending reconstruction.** If W₅₄ is `0x04000000`, the second argument to F-I062 is `0xFC000000`, under the displayed arithmetic-right-shift interpretation. This expression does not generally reconstruct W₅₄.

5. **Discarded masked field.** For every W₆₇, the second argument to F-I083 is zero. LSL₂₇(W₆₇) has no set bits within its lowest 23 bits.

6. **Minimum final address.** If F-I095 returns a pair whose uppermost 12 bits are zero, the final store targets numeric address zero. A nonzero lower 52-bit portion does not change that address.

7. **Unaligned final address.** If those uppermost 12 bits equal one, the final store targets address one. The static contract predicts the attempted address, not successful completion of an unaligned access.

8. **Maximum final address.** If those uppermost 12 bits equal 4095, the store targets address 5118 and supplies the 16-bit value `0x00CD`.

9. **Ordering.** If execution reaches the final store, F-I096, F-I097, F-I098, and F-I099 have already been invoked in that order. The represented invalid-instruction boundary follows the store, not vice versa.
