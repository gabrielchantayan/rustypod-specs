# F-c214e4c55164

## Purpose

F-c214e4c55164 conditionally stores a caller-supplied four-byte value at an address calculated from fields in a caller-supplied object.

A four-byte field at object offset 12 controls whether the store occurs. If its initial value is zero, the function returns without performing the destination store. Otherwise, a base address from object offset 20 and a second reading of the offset-12 field determine the destination.

A plausible interpretation is replacement of the final four-byte field in the last occupied entry of a 16-byte-entry array. That interpretation requires additional assumptions about the field’s meaning, positive values, stable memory, and storage bounds. The supplied representation establishes the address calculation, not those assumptions.

## Interface

### Inputs

- **Object address:** An address-like argument represented as a 32-bit integer in the supplied representation. The function uses it to locate fields at byte offsets 12 and 20. No complete object type or allocation size is established.
- **Replacement value:** An opaque four-byte argument. On the taken path, the function assigns the full four-byte value to the destination. No explicit masking, narrowing, validation, or interpretation of its contents appears.

The replacement value may represent ordinary data, an address, a handle, or something else under external conventions. Its semantic type and ownership significance are not established.

### Destination relationship

Let **B** denote the base-address value read at offset 20, and **N** denote the value from the second reading at offset 12. Subject to the execution environment’s arithmetic and address rules, the destination relationship is:

**B + 16 × N − 4**

The assignment covers four bytes beginning at that destination.

For a stable positive N, this is byte offset 12 within zero-based entry N − 1 of a hypothetical 16-byte-entry array. The entry interpretation is inferred; the displacement and access width are established.

## Behavior

### Initial decision

The function first evaluates the four-byte integer field at object offset 12 against zero.

If that read yields zero, the function returns without evaluating the destination expression and without performing an explicit memory write. In particular, this path does not require reading the field at offset 20.

The condition distinguishes zero from nonzero. It is not a positivity check. A negative integer value therefore takes the same branch as a positive nonzero value.

### Destination selection

When the initial reading is nonzero, the destination expression contains:

- A four-byte read at object offset 20.
- Another four-byte read at object offset 12.
- Scaling of the second offset-12 value by 16.
- Addition of the base-address value and a displacement of negative four bytes.

The second offset-12 reading supplies the value used for destination selection. The representation does not visibly retain the initial decision value for that calculation.

The initial decision precedes evaluation of the taken branch. Within the destination expression, however, the supplied representation does not establish a relative evaluation order between the base-field read and the second offset-12 read. Neither ordering is an unconditional part of this contract.

For stable ordinary memory, both readings at offset 12 produce the same value. If the memory changes between evaluations, the decision value and destination-selection value can differ in the represented behavior. This observation does not establish safe concurrent access, volatile semantics, or a guarantee of two physical loads in generated instructions.

### Assignment and return

After the destination is calculated, the function performs one explicit four-byte assignment using the replacement argument and then returns.

There is no explicit destination-value read, comparison with the old value, or conditional suppression of an equal-value assignment. There is also no separate increment, decrement, clearing, or restoration of either object field.

The assignment establishes a four-byte replacement operation in the supplied representation. It does not establish hardware atomicity, a particular instruction sequence, memory-ordering guarantees, or partial-store behavior on failure.

On the normally completing nonzero path, the only explicit mutation is the four-byte destination assignment. The destination is not checked for overlap with the object. It can therefore replace the offset-12 field, the offset-20 field, or other object bytes if the address calculation selects those locations.

## Acceptance examples

These examples are conditional consequences of static inspection. No runtime tests have been performed.

### Initially zero field

Given a valid initial read at object offset 12 that yields zero:

- No destination assignment is performed.
- The offset-20 field is not read by the represented path.
- The replacement value is not stored by this function.

An unreadable offset-20 location or unusable base value does not itself affect this path, provided the initial read and return otherwise complete normally.

### Stable value of one

Given stable readable fields, an offset-12 value of 1, a base value B, valid arithmetic, and writable four-byte storage at B + 12:

- The replacement value is assigned to the four bytes beginning at B + 12.
- No separate object-field update occurs.
- No other explicit memory store appears.

If those destination bytes alias the object, the corresponding object bytes are changed by this same assignment.

### Stable value of two

Under the same validity conditions, an offset-12 value of 2 selects B + 28.

It does not select B + 32. The final negative-four-byte displacement remains part of the address relationship.

### Stable negative value

Given a stable offset-12 value of −1 and valid arithmetic and storage, the destination is B − 20.

The function does not reject the value because it is negative. This example does not establish that storage before B is normally valid or intended.

### Different values across the two readings

Suppose the represented evaluations remain distinct, the initial offset-12 read yields 1, and the second yields zero. With a valid base B and writable storage at B − 4:

- The initial nonzero value causes entry into the write path.
- The second value selects B − 4.
- The replacement value is assigned there.

This is a conditional evaluation example, not a guarantee about compiled load counts or safe concurrent mutation.
