# F-98085658bfd4

## Purpose

F-98085658bfd4 conditionally changes the byte representation of a buffer associated with a state object. It either leaves the object unchanged, swaps adjacent bytes in the existing buffer, or allocates and populates a replacement buffer.

The representation tags have these operational meanings:

- **1:** a variable-width byte representation, decoded through F-429a3f34f0b2 and produced locally using UTF-8-style encoding.
- **2:** little-endian 16-bit units.
- **Any other byte value:** big-endian 16-bit units when interpreted by the conversion branches.

These meanings describe branch behavior, not validation of supported tag values. The function does not restrict requested tags to a defined enumeration.

The apparent intent is conversion between UTF-8 and the two byte orders of UTF-16. That interpretation is supported by the arithmetic, but the contract is narrower: malformed input handling, dependency behavior, and ownership rules are not established.

## Interface

### Arguments and result

The function receives four arguments:

1. **State address:** a 32-bit address identifying the mutable object described below.
2. **Requested representation:** an unsigned 32-bit value. Its full width participates in the initial equality check; only its low eight bits select later branches and are eventually stored.
3. **Opaque 32-bit argument:** not used by the visible implementation.
4. **Byte-buffer address:** copied into temporary storage on one path, but overwritten before any visible use. No buffer read or write through this argument is established.

The result is a 32-bit status:

- **0:** an initial no-op, an in-place byte swap, or completion of the replacement-buffer path.
- **7:** F-69bd2f35c00e returned nonzero, or F-83e6016208ce returned a null address.

A result of zero does not establish that the input was well-formed text. A result of seven does not establish that dependencies left the object unchanged.

### State layout

Offsets are measured in bytes from the state address.

| Offset | Width | Visible role |
|---|---:|---|
| `0x10` | 32 bits | Opaque value passed as the first argument to F-83e6016208ce |
| `0x14` | 32-bit address | Current data-buffer address |

The data length excludes the terminating bytes written by allocated conversions.

The visible implementation uses 32-bit integer and address arithmetic, 16-bit flag accesses, and 8-bit byte accesses. Native byte order for multi-byte state fields is not independently established. Buffer byte order is explicit in the conversion operations.

### Preconditions

For defined, memory-safe execution, callers must supply accessible state and buffer storage for the path taken. In particular:

- Adjacent-byte swapping requires complete, readable and writable byte pairs.
- Conversion from 16-bit units requires complete units and, whenever a unit lies in `0xd800`–`0xdfff`, another complete unit.
- F-429a3f34f0b2 must advance its supplied cursor sufficiently for the decoding loop to terminate.
- Allocation-size arithmetic, source-end calculation, output-length calculation, and output writes must remain valid for the target address model.
- Successful allocation must provide storage sufficient for all generated bytes and terminators.

These conditions are not checked locally. Negative lengths, arithmetic overflow, truncated input, inaccessible addresses, and output-capacity exhaustion have no defined error result in the supplied evidence.

## Behavior

### 1. Initial gate and representation comparison

The function reads the 16-bit flags field to determine whether bit `0x0002` is set. The supplied representation contains two initial reads of this field; no synchronization between them is established.

If the enable bit is clear, the function returns zero without calling a dependency or explicitly writing the state or data.

If the enable bit is set, the current 8-bit representation tag is compared with the **entire unsigned 32-bit requested value**. Equality returns zero immediately.

Only after this full-width comparison does the function reduce the requested value to its low eight bits for branch selection.

Consequently, requesting `0x00000101` while the stored tag is `1` is not an initial no-op, although later selection treats the requested representation as `1`.

### 2. Selection of in-place or allocated processing

Subject to subsequent state changes by dependencies:

- Current tag `1`, requested low byte other than `1`: allocate for conversion from the variable-width representation into 16-bit units.
- Current tag other than `1`, requested low byte other than `1`: use the in-place pair-swapping path.
- All remaining cases: allocate using the capacity formula associated with conversion to the variable-width representation.

For allocation, the requested byte count is:

- Twice the previously read input length, plus **2**, when selection observed current tag `1` and requested low byte other than `1`.
- Twice the previously read input length, plus **1**, otherwise.

No overflow check is visible. The supplied signed-length arithmetic does not establish a portable outcome for overflowing values.

### 3. In-place adjacent-byte swapping

The function first calls F-69bd2f35c00e with the state address.

If its result is nonzero, the function returns seven. It performs no subsequent explicit writes, but dependency side effects remain possible.

If its result is zero, the function reads the current data address and length **after the call**. It then visits the buffer in two-byte steps. For each pair, it:

1. Reads the first byte.
2. Reads the second byte and writes that value into the first position.
3. Writes the saved first byte into the second position.

The loop condition checks only whether the pair’s first address precedes the calculated end. An odd positive length therefore causes access to one byte beyond the nominal length. There is no odd-length rejection.

After the loop, the stored representation tag becomes the low eight bits of the original requested value, and the function returns zero.

This path does not explicitly change the length, flags, or field at `0x24`, and does not append a terminator. It swaps pairs even when the old and requested low-byte tags are equal but the initial full-width comparison failed.

### 4. Allocation and post-allocation dispatch

For an allocated conversion, the function captures the source address and source end before calling F-83e6016208ce. The capacity calculation uses a length read separately from the read used to calculate that end.

F-83e6016208ce receives the value from state offset `0x10` and the calculated capacity.

After the allocation call, the function reads an external 32-bit global value, including when the returned allocation address is null. A null result then causes return seven.

For a non-null result, the function rereads the current representation tag to select the actual converter:

- Tag `1`: decode variable-width input.
- Tag `2`: read little-endian 16-bit units.
- Any other tag: read big-endian 16-bit units.

Thus, the source address and end are captured before allocation, while converter selection occurs afterward. The evidence does not establish that F-83e6016208ce preserves the state or globals. If it changes the tag or source storage, capacity selection and actual conversion can diverge.

### 5. Variable-width input to 16-bit output

While the source cursor precedes the captured end, the function calls F-429a3f34f0b2 with:

- The current source address.
- The captured source-end address.
- An address through which the dependency updates the source cursor.

The returned unsigned 32-bit value determines the output. There is no separate decoder-error check.

A value below `0x10000` produces one 16-bit unit, including values in the surrogate range. A value at or above `0x10000` produces four bytes through surrogate-style arithmetic.

Requested low byte `2` selects little-endian output; every other requested low byte selects big-endian output on this branch.

For exact treatment of arbitrary decoder results, let:

- \(x\) be the unsigned 32-bit result.
- \(h=\lfloor x/256\rfloor\bmod256\).
- \(d=(x-65536)\bmod2^{32}\).

For \(x\ge65536\), the four component bytes are:

- High-unit low byte: \(\bigl((\lfloor d/1024\rfloor\mathbin{\&}192)+\lfloor h/4\rfloor\bigr)\bmod256\).
- High-unit high byte: \(\bigl(((d\times4096)\bmod2^{32})\mathbin{\gg}30-40\bigr)\bmod256\).
- Low-unit low byte: \(x\bmod256\).
- Low-unit high byte: \(((h\mathbin{\&}3)-36)\bmod256\).

Little-endian output writes each unit’s low byte first; big-endian output writes each unit’s high byte first. For valid supplementary Unicode scalar values, these formulas produce the ordinary surrogate pair. Values above `0x10ffff` are not rejected locally.

After decoding completes, the function stores the number of generated data bytes in the length field, then writes two consecutive zero bytes after the data. Neither zero byte is included in the stored length.

### 6. 16-bit input to variable-width output

Each iteration reads a 16-bit unit in the byte order selected by the post-allocation tag.

A unit outside `0xd800`–`0xdfff` becomes the value to encode, and consumes two input bytes.

A unit anywhere within `0xd800`–`0xdfff` causes the function to consume another 16-bit unit. It does not require the first unit to be a high surrogate or the second to be a low surrogate. The combined value is:

\[
65536+((\text{first unit}\mathbin{\&}1023)\times1024)
       +(\text{second unit}\mathbin{\&}1023).
\]

Because both units are assembled from two bytes, the displayed mask on the second unit reduces to its low ten bits. The result always lies between `0x10000` and `0x10ffff`.

The selected value is encoded using these size boundaries:

| Value | Output size |
|---|---:|
| `0x00`–`0x7f` | 1 byte |
| `0x80`–`0x7ff` | 2 bytes |
| `0x800`–`0xffff` | 3 bytes |
| At least `0x10000` | 4 bytes |

For values reachable from complete 16-bit input, the byte construction is standard UTF-8 encoding. Embedded zero units produce zero data bytes; they do not terminate processing.

After conversion, the function stores the generated data-byte count and writes one zero byte immediately after the data.

The implementation contains an alternate encoding route using the captured external global if a combined surrogate value has a zero upper 16-bit half. Under the displayed unit widths and arithmetic, that condition is unreachable. Its intended purpose is unknown.

### 7. Replacement-buffer publication

After storing the output length and writing terminators, the function calls F-74b5a05d0094 with the state address.

Only after that call returns does it explicitly:

1. Store the requested value’s low byte as the representation tag.
2. Read the then-current 16-bit flags and replace them with  
   \((\text{flags}\mathbin{\&}\texttt{0xfe3f})\mathbin{|}\texttt{0x0060}\).
3. Store the replacement-buffer address at offset `0x14`.
4. Store the same address at offset `0x24`.
5. Return zero.

The flag operation forces bits `0x0020` and `0x0040` on and bits `0x0080` and `0x0100` off; other bits are preserved from the post-call flags value.

F-74b5a05d0094 sees the newly stored length, but the function has not yet explicitly published the new data address or tag. There is no subsequent length write. Any length modification by that dependency therefore survives.

## Side effects

The direct observable effects are path-dependent:

- **Initial no-op:** state reads only.
- **In-place path:** one dependency call, pairwise buffer writes, then one tag write.
- **Allocation failure:** allocation-related dependency effects and a global read, but no explicit publication of a replacement.
- **Allocated success:** source reads, output writes, length update, terminator writes, a dependency call, then tag, flags, and two address-field writes.

Ownership is not established. The naming and call placement suggest allocation followed by handling of the old storage, but the evidence does not prove that any dependency allocates owned memory, frees old memory, detaches shared storage, or preserves unrelated fields.

The replacement address is retained locally across F-74b5a05d0094 and published afterward. No local check establishes that it remains valid after that call.

No atomicity, locking, rollback, or concurrency guarantee is visible.

## Acceptance examples

These are static, conditional expectations, not executed tests.

1. **Disabled processing.** With flag bit `0x0002` clear, return zero without dependency calls or explicit buffer/state writes, regardless of the requested tag.

2. **Exact tag match.** With processing enabled, stored tag `2`, and requested value exactly `2`, return zero without swapping.

3. **Full-width mismatch.** With stored tag `2` and requested value `0x00000102`, call F-69bd2f35c00e. If it returns zero and leaves a four-byte buffer `11 22 33 44`, produce `22 11 44 33`, retain stored tag `2`, and return zero.

4. **Dependency refusal.** On an in-place path, a nonzero result from F-69bd2f35c00e produces status seven. No pair swap or final tag write follows; dependency mutations are not excluded.

5. **Null allocation.** For one input byte on the path selected as tag `1` to requested tag `2`, the allocation request is four bytes. A null result produces status seven after the external-global read.

6. **Basic conversion to little-endian units.** If the decoder consumes the complete input and returns `0x0041`, tag-`1` input requested as tag `2` produces data `41 00`, stored length two, and two trailing zero bytes.

7. **Supplementary conversion.** If the decoder returns `0x1f600`, requested tag `2` produces `3d d8 00 de`; requested tag `3` produces `d8 3d de 00`. Each has stored length four and two trailing zero bytes.

8. **Little-endian units to bytes.** With tag `2`, input `41 00 ac 20`, and requested tag `1`, the output data is `41 e2 82 ac`, followed by one zero byte, with stored length four.

9. **Unvalidated surrogate pairing.** With tag `2`, input `00 dc 41 00`, and requested tag `1`, the first unit is accepted as a pair starter. The combined value is `0x10041`, producing `f0 90 81 81`, not a local malformed-input error.

10. **Embedded zero.** With tag `2`, input `00 00 41 00`, and requested tag `1`, output data is `00 41`, followed by a terminator. Stored length is two.

11. **Odd pair-swap length.** A nominal length of three causes access to positions two and three for the final swap. Safe rejection is not an acceptance requirement; this input violates the complete-pair precondition.

All allocated-success examples additionally require suitable allocation, terminating decoder behavior where applicable, and dependencies that leave the relevant buffers and final length valid.
