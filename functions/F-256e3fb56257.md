# F-256e3fb56257

## Purpose

F-256e3fb56257 continuously repeats an ordered sequence of indirect calls, byte accesses, and 32-bit memory accesses. Selected call results are scaled, truncated, split into words, or retained for later address calculations and call arguments.

The visible body has an unconditional loop and no normal-return path. Its first iteration depends on incoming state beyond the four declared arguments. Each completed iteration supplies replacement values for several inputs to the next iteration.

No application-level purpose is established. The accessed memory is not established to represent objects, device registers, allocation records, or serialized data.

The producer and validity of the secondary-register value are not established. It is consumed after intervening calls; it must not be assumed to equal a particular earlier argument or result.

The four declared arguments are therefore insufficient to determine execution.

### Widths, addresses, and preconditions

Byte accesses transfer 8 bits. Word accesses transfer 32 bits. Four call sites have results represented as 64-bit quantities: F-D026, F-D105, F-D132, and F-D136. Their low and high words are each 32 bits.

The arithmetic descriptions and examples below use a conditional 32-bit bit-vector interpretation: products, additions, and left shifts retain only their low 32 bits. Right shifts of the unsigned values described below are logical. This interpretation does not establish portable behavior for overflowing signed expressions in the supplied representation.

A **selector-derived write** comprises:

1. An unsigned 8-bit read from the specified selector address.
2. An 8-bit write to the numerical address equal to that byte plus `0x11`.

The destination is consequently between `0x11` and `0x110`, inclusive. The selector is an address component, not a pointer-sized object fetched from memory.

Progress through any described interval requires its calls to return and its accesses to succeed. Accessible memory, executable call targets, acceptable alignment, and sufficient execution resources are environmental preconditions, not locally checked guarantees.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Selector interpretation.** If a selector read returns `0x80`, its associated byte-write destination is `0x91`, irrespective of the selector’s source address.

2. **Initial word placement.** If the entry value component is `1` and the fourth argument is `2`, the first word write stores `0x00001000` at `0x00002014`, provided execution reaches it and the access succeeds.

3. **Shift composition.** Under 32-bit arithmetic, F-D013’s first argument is zero for every entry value component. Preserving nonzero bits beyond 32 bits would not match this interpretation.

4. **Byte truncation.** A selector payload of `0x12345678` produces byte `0xe0` in the selector-derived write immediately after F-D088.

5. **Fresh versus retained selector.** If the read after F-D095 yields `0x20`, the word write after F-D100 targets `0x34`. A dependency changing the selector location during F-D096–F-D100 does not change that retained address.

6. **Direct clearing.** If reset base is `0x40000000`, each clearing pair writes zero at `0x40000011` and then `0x40000001`, without a selector read. Those four direct writes remain separate from the ten selector-derived writes.

7. **Global snapshot.** If a dependency changes the global after its explicit read, the selector write after F-D105 still uses the retained snapshot.

8. **Complete iteration.** If all calls return and all accesses succeed, one iteration includes ten selector reads and fourteen byte writes. Completion of F-D146 proceeds into another iteration rather than returning normally.
