# F-5fe1270f6b01

## Purpose

F-5fe1270f6b01 scans and destructively modifies a sequence of fifteen 32-bit words. It interprets each word from its most significant bit toward its least significant bit, groups selected set bits into coordinate records, scales those coordinates, and submits each record through an indirect operation on a supplied receiver.

The interpretation of the words as rows, and of the records as rectangles, is **inferred intent**. The established behavior is a particular scan-and-clear procedure. It is not established as a lossless bitmap-to-rectangle conversion: some input patterns cause bits to be cleared without their coordinates being covered by an emitted record.

The routine has no explicit result value or recoverable error result. Its observable outputs are mutations of the input words, allocations, and receiver calls.

## Interface

The routine takes four arguments:

| Argument | Behavioral role |
|---|---|
| Input storage address | Beginning of fifteen consecutively addressed 32-bit words, occupying 60 bytes. The routine reads and writes this storage. |
| Receiver address | Address of an object whose first field identifies a dispatch table. An operation is obtained from byte offset 28 in that table. |
| First scale | A value represented as a 32-bit integer, applied to word-index coordinates. |
| Second scale | A value represented as a 32-bit integer, applied to bit-position coordinates. |

The supplied representation uses 32-bit words and a dispatch arrangement consistent with 32-bit pointers. Compatibility with another pointer width, object layout, or calling convention is not established.

Each emitted allocation contains four consecutive 32-bit fields, in this order:

1. Scaled starting word index.
2. Scaled starting bit position.
3. Scaled exclusive ending word index.
4. Scaled exclusive ending bit position.

For descriptive purposes, a set-bit position is identified by a pair consisting of a word index from 0 through 14 and a bit position from 0 through 31. Bit position 0 denotes the most significant bit, with mask `0x80000000`; position 31 denotes the least significant bit.

## Behavior

### Working state

The routine begins at word index 0 and bit position 0, with a scan limit of 32. It maintains:

- A current word index and current bit position.
- A bit position at which scanning starts on the next word.
- An exclusive horizontal scan limit.
- Four pending coordinate fields.

The pending fields are initialized through F-8ff0260f6859, using a destination spanning sixteen bytes, a size argument of sixteen, and a fill argument of 255. Under the expected fill behavior, all four fields become `0xffffffff`.

The starting-bit field is the active-record indicator: a value other than `0xffffffff` means a candidate is active. The ending-bit field initially remains unset. The ending-word field remains unset until emission preparation.

The sentinel value is not a valid ordinary coordinate. Normal word indices are below 15, and normal bit positions and exclusive limits are at most 32.

### Bit inspection and clearing

Within a word, positions are visited in increasing bit-position order. The routine forms the mask for the current position and reads the corresponding input word.

If the inspected bit is set:

- With no active candidate, the routine records the current word index and bit position as the candidate start. It also records that bit position as the next word’s scan start.
- With an active candidate, the candidate’s start remains unchanged.
- The routine clears the inspected bit in input storage.

Clearing is performed as a read-modify-write. The word used for this write is read again rather than necessarily reusing the value from the initial bit inspection.

If the inspected bit is zero and no candidate is active, no input write occurs.

### Establishing the horizontal extent

After a candidate starts, the routine continues through consecutive set bits in that first word.

If it encounters a zero before reaching position 32:

- That zero’s bit position becomes the candidate’s exclusive ending-bit coordinate.
- The scan limit becomes that same position.
- The routine nevertheless performs a clearing read-modify-write at the zero position.
- Advancing the bit position then leads into word-transition handling.

Thus, even an already-zero bit can receive a write. This matters for storage with write-observable behavior or concurrent access; neither such use is established as supported.

If the first run reaches the end of the word, word-transition handling sets the exclusive ending-bit coordinate to 32 and retains a scan limit of 32.

Once this horizontal extent is known, subsequent words are scanned only from the candidate’s starting bit position up to, but not including, its ending-bit position.

### Extending to later words

At a word transition, scanning resumes at the saved starting bit position in the next word. With an active candidate, the same horizontal interval is examined.

A later word containing set bits throughout that interval is consumed: those bits are cleared, and the routine proceeds to the next word.

The routine does not inspect positions to the left of the saved start or at or beyond the current exclusive limit while extending this candidate. Such positions may be encountered during a later rescan.

### Emission after a zero in a later word

If a candidate already has a known ending-bit coordinate and the routine encounters a zero inside that interval, it emits a record.

The unscaled coordinates are:

- Starting word: the word where the candidate began.
- Starting bit: the bit where the candidate began.
- Exclusive ending word: the word containing the newly encountered zero.
- Exclusive ending bit: the previously established horizontal limit.

The current word is therefore excluded from the emitted record.

However, any set bits already visited earlier in that current word have already been cleared. There is no rollback, restoration, or separate record for that consumed prefix.

After submission and sentinel reset:

- The word index is restored to the candidate’s original starting word.
- Scanning resumes one bit position after the candidate’s ending-bit coordinate.
- The next-word starting bit position becomes 0.
- The scan limit becomes 32.

This is not simply a forward-only traversal. Emission can cause earlier words to be scanned again.

### Emission at the final word boundary

When an active candidate reaches the transition beyond word index 14, the routine emits it with exclusive ending-word coordinate 15.

If the horizontal end was not previously established, it is first set to 32.

After this emission, the scan restarts at bit position 0 of the candidate’s original starting word. The implementation obtains that word index through an unsigned decrement followed by an increment. For a candidate beginning at word 0, the intermediate decrement wraps to `0xffffffff`, then the increment restores 0.

This final-boundary restart differs from the later-word-zero case: it restarts at position 0, rather than one position beyond the former horizontal end.

When word-transition handling advances beyond word 14 without another candidate requiring emission, the routine returns.

### Scaling and record submission

Before allocating a record, the routine replaces its pending coordinate values with scaled values:

- Both word coordinates use the first scale.
- Both bit coordinates use the second scale.

There is no clipping, saturation, coordinate-order validation, or rejection of zero or negative scales.

It then:

1. Requests sixteen bytes from F-8157a180d901.
2. Stores the four scaled 32-bit values into the returned storage in coordinate order.
3. Obtains the receiver operation from dispatch-table byte offset 28.
4. Calls that operation with the receiver and the address of the local record-pointer slot.
5. Calls F-8ff0260f6859 again to reset the sixteen-byte pending-coordinate area.

The receiver receives an address containing the allocation pointer, not merely the allocation pointer as a direct argument. The operation can therefore modify that pointer slot. No subsequent read, explicit release, or other use of its resulting value is shown.

### Integer behavior

Coordinates, masks, scan counters, and sentinel fields use 32-bit unsigned representations in the supplied material. Ordinary bit inspection occurs at positions 0 through 31, so the mask shift is within that range on the expected path.

Most scaling expressions combine a signed scale argument with an unsigned coordinate, yielding low-32-bit arithmetic in the represented model. Negative scales therefore need not produce meaningful geometric coordinates.

The terminal exclusive-word calculation uses a scale multiplied by the literal 15 in a signed-looking expression. No wider intermediate or overflow check is shown. A low-32-bit machine result is a plausible interpretation, but language-level behavior on signed overflow is not established by the supplied material. Acceptance examples below avoid overflow.

## Side effects

### Input mutation

Selected set bits are cleared as they are encountered, before the corresponding record is allocated or submitted. Some zero positions are also written during horizontal-bound discovery.

If allocation or submission fails after these writes, the routine contains no rollback path.

The input is not snapshotted. Later scans read current storage contents, including changes made by earlier clearing operations or by dependencies. The routine does not establish synchronization or concurrent-mutation safety.

### Allocation and ownership

Every emission requests a fresh sixteen-byte allocation. The routine performs no explicit deallocation.

Allocation failure is unchecked: the returned address is used immediately for four stores. The resulting failure mode depends on the allocator and execution environment.

Ownership transfer is **documented_only**. Passing an address of the allocation-pointer slot suggests that the receiver operation may adopt or replace the pointer, but the supplied material does not establish whether it releases, retains, copies, or transfers the allocation.

### Receiver and other state

The receiver’s dispatch operation is looked up separately for each emission. Caching or stability of the dispatch table is not established.

There are no direct accesses to named global state in the supplied body. This does not establish freedom from global side effects: all three dependency roles may affect externally visible state. No preservation of globals by those dependencies is assumed.

## Acceptance examples

These examples are static expectations, not executed tests. They assume successful allocation, expected sentinel initialization, and a receiver operation that records submissions without changing input storage or disrupting execution. Unless stated otherwise, both scales are 1 and all unmentioned bits are zero.

### Empty input

All fifteen words are zero.

Expected behavior:

- No record allocation or receiver submission.
- No input writes.
- Return after scanning through word index 14.

### One isolated bit

Only word 2, bit position 5 is set.

Expected submitted record: **(2, 5, 3, 6)**.

The set bit is cleared. The zero at position 6 in word 2 receives the horizontal-bound discovery write. The zero at position 5 in word 3 triggers emission and is not itself cleared by that emission branch.

### A complete rectangular run

Words 2 and 3 contain exactly bit positions 5, 6, and 7.

Expected submitted record: **(2, 5, 4, 8)**.

All six set bits are cleared. The zero at word 4, position 5 terminates vertical extension. No second record is expected.

### Two separated runs in one word

Word 2 contains positions 1 and 2, and positions 5 and 6.

Expected submission order:

1. **(2, 1, 3, 3)**
2. **(2, 5, 3, 7)**

The first emission returns scanning to word 2 beyond the first run’s ending position, allowing the second run to be discovered.

### Candidate reaching the last word

Only word 14, positions 30 and 31 are set. The first scale is 2 and the second scale is 3.

Expected submitted record: **(28, 90, 30, 96)**.

The exclusive unscaled bounds are word 15 and bit position 32. Both set bits are cleared before submission.

### Cleared prefix omitted from the record

Word 0 contains positions 4, 5, and 6. Word 1 contains only position 4.

Expected submitted record: **(0, 4, 1, 7)**.

The routine clears word 1, position 4 while attempting to extend the candidate. It then encounters the zero at position 5 and emits a record excluding word 1. Consequently, that cleared bit is not covered by the emitted record, and no separate record for it is expected.

Any requirement for lossless coverage of original set bits would reject this behavior. The supplied body nevertheless establishes it.

### Zero scaling

For an input producing one record, setting both scales to zero produces four zero-valued record fields. Discovery and clearing still depend on the original bits; zero scales do not suppress emission.
