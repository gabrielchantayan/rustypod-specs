# F-8a9589a9b71f

## Purpose

F-8a9589a9b71f coordinates operations on two pointer-addressed objects. It selects a sequence of dependency calls using two scaled header values, their signs, and, on some paths, a signed comparison result.

The established behavior is a dispatcher with strict result checking:

- A scaled value derived from the second object controls an initial range rejection and an immediate successful return for zero.
- A zero scaled value for the first object selects a special binary operation.
- Otherwise, the signs of the two scaled values select further operations.
- Every dependency result used as a status must be exactly zero for execution to continue successfully.
- The comparison dependency is different: its result is interpreted as a signed 32-bit value and divided into negative and nonnegative cases.

The function returns a 32-bit value of either **0** or **1**. Here, “success” means return value 0 and “failure” means return value 1; those labels describe this function’s return convention, not an independently established application-level meaning.

The mathematical or domain-specific meaning of the objects and dependency operations is unknown. Their names, representation, allocation rules, and intended arithmetic interpretation cannot be established from the supplied evidence.

## Interface

### Inputs

The function receives two pointers, referred to here as **A** and **B**, in that order.

Each pointer is initially used to read a 32-bit header at offset zero. Depending on the selected path, the pointers are then passed to dependencies that may access more of the objects.

The following notation describes the initial decision values:

- **Hₐ**: the initial 32-bit header read through A.
- **Hᵦ**: the initial 32-bit header read through B.
- **G**: a shared scaling value read by the initial multiplication expressions.
- **X**: the low 32 bits of the product used for A.
- **Y**: the low 32 bits of the product used for B.

The calculation for B precedes the calculation for A. The source contains a separate reference to the shared scaling value in each calculation; it does not establish a single shared snapshot. If the scaling value can change between those evaluations, X and Y need not use the same value of G.

Multiplication is treated as 32-bit wrapping arithmetic in the supplied representation. Neither a mathematical product wider than 32 bits nor overflow rejection is shown.

### Outputs

The return value is always:

| Value | Meaning within this contract |
|---|---|
| 0 | The selected path completed with every required status result equal to zero, or the early-zero condition applied. |
| 1 | The initial range check rejected Y, or a required dependency returned a nonzero status. |

There is no distinct return value for the failing dependency, comparison outcome, range violation, or unsupported object state.

### Preconditions and object layout

For defined execution of the visible initial accesses:

- A and B must each permit a 32-bit header read at offset zero.
- The shared scaling storage must be readable.
- Object alignment and memory-access requirements must satisfy the target platform.
- Any invoked dependency’s additional preconditions must hold.

No null-pointer checks, length checks, object-tag checks, or explicit validation of accessible storage are shown.

Only the first 32-bit header is directly accessed through each object by this function. The remainder of each object’s layout is documented_only.

Aliasing is not explicitly prohibited. A and B may designate the same storage at the dispatcher level, but whether a particular dependency supports identical or overlapping objects is documented_only.

## Behavior

### 1. Capture the initial decision values

The function first calculates Y using B’s header, then calculates X using A’s header.

Both calculations occur before any early return, including the immediate return for Y equal to zero. Consequently, an unreadable A is not bypassed merely because B would produce a zero result.

Subsequent dispatch decisions use these saved products. The function does not visibly reload either header or recompute either product after a dependency call.

### 2. Apply the range condition to Y

The function constructs a 32-bit magnitude-like value from Y:

- If Y is nonnegative under signed 32-bit interpretation, it uses Y unchanged.
- If Y is negative under signed 32-bit interpretation, it uses its wrapping 32-bit negation.

It then interprets that result as signed and rejects values greater than 28.

This check is performed twice on the saved Y value before any dependency call. No object read or dependency call intervenes. In the supplied representation, the second check does not add another condition.

The signed minimum value is an important exception to an ordinary absolute-value interpretation:

- Y representing −2,147,483,648 negates to the same 32-bit pattern.
- That pattern remains negative when tested as signed.
- It therefore does **not** satisfy “greater than 28” and passes this check.

Thus, the admitted signed values of Y are −28 through 28, plus −2,147,483,648.

There is no corresponding range check on X. The two visible range checks both concern Y.

### 3. Return immediately if Y is zero

After passing the range check, Y equal to zero causes an immediate return of 0.

No dependency is invoked on this path. X has already been calculated, but its value does not affect the return.

The arithmetic status-test form in the supplied representation distinguishes exactly zero from every nonzero 32-bit pattern. In particular, Y equal to 1 does not take this early return.

### 4. Handle X equal to zero

If Y is nonzero and X is zero:

1. Invoke F-a743bb08af07 with arguments **(B, A)**.
2. If its status is nonzero, return 1.
3. Invoke F-268334470dda with argument **A**.
4. Return 0 if that result is zero; otherwise return 1.

The sign of Y does not further divide this path.

### 5. Handle nonzero products with matching signs

When X and Y are both nonzero and have matching signed sign bits, the function distinguishes the positive and negative cases.

#### Both positive

1. Invoke F-61e238108dfa with arguments **(A, B)**.
2. Interpret its result as signed 32-bit:
   - **Nonnegative:** invoke F-9c6cf2acef37 with **(A, B)** and return according to that result alone: zero becomes 0; nonzero becomes 1.
   - **Negative:** invoke F-d0b1d84c27e6 with **(B, A)**. If its status is nonzero, return 1. Otherwise invoke F-268334470dda with **A** and return according to that status.

The nonnegative-comparison route has no subsequent call to F-268334470dda.

#### Both negative

1. Invoke F-268334470dda with **B**. Return 1 if its status is nonzero.
2. Invoke F-268334470dda with **A**. Return 1 if its status is nonzero.
3. Invoke F-61e238108dfa with **(A, B)**.
4. Interpret its result as signed 32-bit:
   - **Negative:** invoke F-d0b1d84c27e6 with **(B, A)**. Return 1 if its status is nonzero. Otherwise invoke F-268334470dda with **B** and return according to that status.
   - **Nonnegative:** invoke F-9c6cf2acef37 with **(A, B)**. Return 1 if its status is nonzero. Otherwise invoke F-268334470dda with **B**. Return 1 if that status is nonzero. Finally invoke F-268334470dda with **A** and return according to that final status.

Repeated calls to the same dependency with the same pointer are distinct operations. The evidence does not establish that they are redundant, idempotent, or safe to combine.

### 6. Handle nonzero products with opposite signs

#### X negative, Y positive

1. Invoke F-268334470dda with **A**. Return 1 if its status is nonzero.
2. Invoke F-762df453eb50 with **(B, A)**. Return 1 if its status is nonzero.
3. Invoke F-268334470dda with **A** again.
4. Return 0 only if the final status is zero.

#### X positive, Y negative

1. Invoke F-268334470dda with **B**. Return 1 if its status is nonzero.
2. Invoke F-762df453eb50 with **(B, A)**. Return 1 if its status is nonzero.
3. Invoke F-268334470dda with **B** again.
4. Return 0 only if the final status is zero.

The binary operation has the same argument order in both opposite-sign cases. Only the object supplied to the preceding and following unary calls changes.

### 7. Short-circuiting and state-sensitive execution

Every status check is immediate. Once a checked status is nonzero:

- The function returns 1.
- No later dependency in the selected sequence is invoked.
- No rollback or compensating operation is visible.

The comparator’s sign test is not a status check. Both negative and nonnegative comparator results select further work; neither alone causes failure.

Because dependencies may change object or shared state, the call sequences must be preserved exactly. The saved X and Y still select the route even if earlier dependency calls change the headers from which those products were originally calculated.

## Acceptance examples

These are conditional acceptance criteria derived from static control flow, not records of executed tests. Unless a case says otherwise, pointers and dependency preconditions are assumed valid.

1. **Zero second product:** If Y is zero, return 0 with no dependency calls. The header calculations for both B and A still precede the return.

2. **Ordinary range rejection:** If Y is signed 29 or signed −29, return 1 without invoking a dependency. X does not affect this result.

3. **Boundary admission:** If Y is 28 or −28, the range check does not reject it. The remaining route depends on X and, where applicable, dependency results.

4. **Signed-minimum exception:** If Y has the 32-bit pattern representing −2,147,483,648, do not reject it through the range condition alone. Treat it as negative for subsequent sign-based dispatch.

5. **No first-product range limit:** If Y is 1 and X is a large positive signed value, do not reject solely because X exceeds 28. Select the both-positive route.

6. **Zero first product:** With X equal to zero and Y equal to 1, invoke F-a743bb08af07(B, A), followed by F-268334470dda(A) only if the first result is zero. Two zero statuses produce return 0.

7. **Positive products, nonnegative comparison:** With positive X and Y, if F-61e238108dfa(A, B) returns zero, invoke F-9c6cf2acef37(A, B). A zero status returns 0 directly, without a unary call.

8. **Positive products, negative comparison:** With positive X and Y and a negative comparison result, invoke F-d0b1d84c27e6(B, A), then F-268334470dda(A) if permitted. Do not substitute B for that final argument.

9. **Negative products, nonnegative comparison:** If all statuses are zero, the dependency sequence is F-268334470dda(B), F-268334470dda(A), F-61e238108dfa(A, B), F-9c6cf2acef37(A, B), F-268334470dda(B), then F-268334470dda(A). Return 0.

10. **Negative products, negative comparison:** Following the two initial successful unary calls and a negative comparison result, invoke F-d0b1d84c27e6(B, A), then the unary dependency on B. Do not append a unary call on A.

11. **Opposite signs:** For negative X and positive Y, the unary argument is A both before and after F-762df453eb50(B, A). For positive X and negative Y, that argument is B both times.

12. **Nonzero status short-circuit:** If any status-producing dependency returns 1, 2, or the 32-bit all-ones pattern, return 1 immediately. None of these patterns counts as success.

13. **Mutation does not redispatch:** If an early unary call changes an object header, retain the route selected from the original X and Y. Later dependencies may observe changed object storage, but this function does not recompute its sign decisions.
