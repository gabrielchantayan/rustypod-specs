# F-0aa633a1fe00

## Purpose

F-0aa633a1fe00 validates six inputs through an ordered sequence of dependency calls and local checks. It returns a 32-bit status at the first rejecting stage.

The established contract concerns input representations, call arguments, call order, branching, and returned statuses. Application-level meanings of the references, template contents, and dependency operations are not established.

The routine resembles a validator using length-like and comparison-like operations. That interpretation is inferred intent, not a substitute for the dependency-outcome contract. In particular, repeated calls remain distinct, and some successful paths omit a length-like check.

## Behavior

### Initialization and precedence

Before checking any input, the routine initializes local storage in this order:

1. The four-byte scratch object.
2. A, in four-byte units at offsets 0, 4, 8, and 12.
3. B, in four-byte units at offsets 0, 4, 8, and 12.
4. S, in four-byte units at offsets 0, 4, and 8.

The supplied representation shows these values being obtained from static storage. All initialization precedes the first dependency call and the primary-reference zero check.

Consequently, “no dependency calls” on an early rejection does not mean “no preceding storage reads or writes.” The local initialization still occurs.

No template or scratch reinitialization is visible after this initial sequence.

### Primary validation

The primary reference is checked before the name, mode, selection, secondary reference, or override flag affects a decision.

- A zero primary reference returns **6**, without calling a dependency.
- Otherwise, F-1cb585febd84 receives the primary reference. A zero result returns **6**.
- If that result is nonzero, F-3ec7d07fef90 receives the primary reference and the scratch-object address. A nonzero result returns **6**.
- Only a nonzero first result followed by a zero second result permits name validation.

The first dependency result is tested only for zero versus nonzero at this stage. No maximum or minimum positive magnitude is imposed.

### Name validation

A zero name reference returns **7**.

For a nonzero name reference, the first call to F-7f14f1ab6851 receives the name reference, A’s address, and count **12**.

#### Preliminary decision

If the first A call returns nonzero, the preliminary decision ends immediately. No preliminary B call or name-length-like call occurs.

If the first A call returns zero:

- F-7f14f1ab6851 receives the name reference, B’s address, and count **13**.
- F-1cb585febd84 then receives the name reference, regardless of whether the B result was zero.
- The latter result is interpreted as an unsigned 32-bit value.
- If the B result was zero, a value greater than **13** returns **7**.
- If the B result was nonzero, a value greater than **12** returns **7**.

Equality with the applicable bound permits continuation. A result whose 32-bit pattern would represent a negative signed integer is instead a large unsigned value here and exceeds either bound.

#### Final decision

Unless the preliminary decision returned **7**, another F-7f14f1ab6851 call receives the name reference, A’s address, and count **12**.

- A zero result completes name validation successfully.
- A nonzero result causes another call using the name reference, B’s address, and count **13**.
- A nonzero result from that final B call returns **7**.
- A zero final B result completes name validation successfully.

The two A calls are separate invocations. The preliminary and final B calls, when both occur, are also separate invocations. Earlier results cannot be substituted for later results.

The same local region addresses are reused without caller-side restoration. Their contents need not remain equal to their initial values if a dependency modifies them.

A successful name path can omit F-1cb585febd84 entirely: a nonzero first A result bypasses the preliminary threshold check, and a later zero A or B result permits acceptance. The caller therefore does not enforce a universal name-length bound.

### Mode and selection validation

Only after successful name validation does the routine use mode to choose a selection range.

| Unsigned mode | Accepted selection |
|---|---|
| 0 or 1 | 1 through 10, inclusive |
| 3 or 4 | 1 through 14, inclusive |
| Any other value | No selection is accepted; return **5** |

For a supported mode, an out-of-range selection returns **8**.

The range operation subtracts one from the selection in unsigned 32-bit arithmetic, then compares the result unsigned against 10 or 14. Subtraction wraps modulo \(2^{32}\).

This accepts exactly the stated positive ranges:

- Zero wraps to 4,294,967,295 after subtraction and is rejected.
- Negative signed selections are rejected.
- Each upper endpoint is accepted.
- The immediately following value is rejected.

Mode is itself unsigned. For example, mode 4,294,967,295 is unsupported; it does not qualify as a value below two.

Unsupported-mode rejection precedes secondary-reference validation. For a supported mode, selection rejection also precedes secondary-reference validation.

### Secondary preliminary validation

After a supported mode and an accepted selection:

- A zero secondary reference returns **9**.
- Otherwise, F-1cb585febd84 receives the secondary reference. A zero result returns **9**.
- If that result is nonzero, F-3ec7d07fef90 receives the secondary reference and the same scratch-object address used during primary validation.
- A nonzero result returns **9**.

The caller does not reinitialize the scratch object between the two validation stages. Secondary validation receives its then-current contents, not a guaranteed copy of the original initializer or of any particular earlier value.

After these checks succeed, a nonzero override flag returns **0** immediately. This includes negative flag values. A nonzero flag suppresses only the S-specific checks; it does not bypass secondary preliminary validation.

### Additional restriction when override is zero

With override zero, F-7f14f1ab6851 receives the secondary reference, S’s address, and count **8**.

If this first S result is zero:

- F-1cb585febd84 receives the secondary reference again.
- Its result is interpreted as unsigned 32-bit.
- A value greater than **8** returns **11** immediately, without a second S call.

If the first S result is nonzero, that length-like call is skipped.

Unless the greater-than-eight rejection already returned, a second F-7f14f1ab6851 call receives the secondary reference, the same S address, and count **8**:

- A nonzero second result returns **11**.
- A zero second result returns **0**.

Thus, a zero first S result is not sufficient for success. Conversely, a nonzero first S result does not itself reject: a zero second result still permits success.

The second call occurs without caller-side restoration of S. Neither equal results nor unchanged template contents are guaranteed.

## Side effects

### Directly represented effects

The routine reads static initializer data and writes its local scratch and template storage before validation.

It contains no visible direct write through any caller-supplied reference, explicit heap allocation or release, or direct assignment to application global state. Its explicit normal output is the status result.

These observations apply to the caller itself, not to its dependencies.

### Dependency-mediated effects

Dependencies receive caller-supplied references and, for two dependencies, addresses of local storage. Their implementations are absent. They may have effects not exposed by their returned values.

The caller does not establish that dependencies:

- Preserve globals or caller-referenced data.
- Preserve scratch or template contents.
- Interpret count arguments in bytes.
- Restrict accesses to the supplied count or initialized local extent.
- Avoid allocation, release, pointer retention, or other external effects.
- Return deterministically when called again with the same argument values.

Call order, short-circuiting, and repeated invocation are therefore part of the contract. Treating a repeated call as redundant could change observable behavior.

The local addresses are valid local-storage addresses during this invocation. The caller shows neither an explicit ownership-transfer operation nor cleanup of dependency-managed resources. Whether a dependency retains a pointer, assumes ownership, or releases other memory remains unknown; safe use after this invocation is not established.

## Acceptance examples

These are conditional expectations derived from static control flow, not runtime observations. Unless an example specifies otherwise, preceding stages permit continuation and dependencies return normally.

1. **Primary zero takes precedence.**  
   Primary zero returns **6**, even with name zero and unsupported mode. Local initialization occurs, but no dependency is invoked.

2. **Primary’s first dependency can stop validation.**  
   A nonzero primary reference followed by a zero F-1cb585febd84 result returns **6**. F-3ec7d07fef90 is not called.

3. **Name zero precedes mode rejection.**  
   After successful primary validation, name zero returns **7**, even for mode 2.

4. **The preliminary name bound can be 12.**  
   First A result zero and preliminary B result nonzero select bound 12. An unsigned name result of 12 permits the final comparison decision; 13 returns **7** before that decision.

5. **The alternative name bound is 13.**  
   First A and preliminary B results both zero select bound 13. A result of 13 permits continuation; 14 returns **7**.

6. **Name acceptance need not involve a length-like call.**  
   First A nonzero, final A nonzero, and final B zero complete name validation without calling F-1cb585febd84 on the name reference. First A nonzero followed by final A zero also completes name validation without that call.

7. **A preliminary pass does not guarantee name acceptance.**  
   First A zero, preliminary B nonzero, and unsigned result 12 pass the bound. If final A and final B are both nonzero, the result is still **7**.

8. **Unsupported mode precedes secondary failure.**  
   Mode 2 returns **5**, even when the secondary reference is zero.

9. **Selection endpoints are inclusive.**  
   For mode 1, selection 10 proceeds and 11 returns **8**. For mode 3, selection 14 proceeds and 15 returns **8**. Selection zero or −1 returns **8** for every supported mode.

10. **Unsigned mode interpretation matters.**  
    Mode 4,294,967,295 returns **5** after successful name validation.

11. **Override does not bypass preliminary checks.**  
    Override −1 with secondary zero returns **9**. With successful secondary preliminary validation, the same override returns **0** without an S call.

12. **The S threshold rejection short-circuits.**  
    Override zero, first S result zero, and subsequent unsigned result 9 return **11** without a second S call.

13. **Passing the S threshold still requires another call.**  
    First S result zero and subsequent unsigned result 8 require a second S call. Its zero result returns **0**; its nonzero result returns **11**.

14. **A first S mismatch can still succeed.**  
    First S result nonzero skips the threshold call. A zero second S result returns **0**.

15. **Local state is reused, not restored.**  
    If a dependency changes scratch during primary validation, the caller does not restore it before secondary validation. If a template is changed during a call, later calls receive the same region address without restoration. Their results remain dependency-defined.

16. **Count arguments are observable; access limits are not established.**  
    A calls receive count 12, B calls count 13, and S calls count 8. These expectations do not require byte-count semantics, read-only template access, or accesses confined to those numeric extents.
