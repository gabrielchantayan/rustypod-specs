# F-208b38999878

## Purpose

F-208b38999878 performs an ordered sequence of memory reads and writes using implicit incoming machine state, then invokes an unresolved indirect destination with four arguments.

The established behavior is a memory-state transformation followed by control transfer. No application-level purpose, data-structure identity, or device protocol is established. Repeated stores, low-address accesses, and values used both as addresses and arithmetic operands prevent a safe interpretation as an ordinary object initializer or collection operation.

This contract describes the supplied static representation. It does not establish that every represented operation is reachable in an executable, that the recovered interface matches a callable entry point, or that the final indirect destination returns.

## Interface

### Inputs

No explicit parameters are shown. The body nevertheless depends on three incoming machine values:

- **Primary base:** a value treated as an unsigned 32-bit quantity, a memory base, and an arithmetic operand.
- **Secondary base:** a value treated as a signed 32-bit quantity, a memory base, and an arithmetic operand.
- **Initial selector:** a value treated as a signed 32-bit quantity and used to derive an early store address.

These are descriptive contract terms, not established parameter names or calling-convention assignments.

A separate **shared base** is obtained from a fixed memory cell after the initial three stores. Its value is retained for subsequent accesses; the visible body does not reload that cell.

Other inputs include the contents of all locations read through these bases, derived addresses, and fixed addresses.

### Outputs

There is no established scalar return value. Observable outputs consist of:

- Ordered byte, halfword, and word memory writes.
- Reads that may themselves be observable on special memory.
- A final indirect invocation with four arguments.
- Any effects of that unresolved invocation.

A normal return appears after the invocation in the supplied representation. Whether execution actually reaches that return is unknown.

### Widths and layout

The representation distinguishes:

| Access class | Width |
|---|---:|
| Byte | 8 bits |
| Halfword | 16 bits |
| Word | 32 bits |

All offsets below are byte offsets. A word access at offset `0x10`, for example, covers offsets `0x10` through `0x13`; it can overwrite earlier byte stores within that range.

Byte extraction means retaining the low eight bits. An unsigned byte promoted for a word store has a value from 0 through 255. Memory byte order is not supplied, so this contract does not assign individual byte values to multibyte stores except where independent byte writes establish them.

### Preconditions

Completion of the visible sequence requires every accessed address to support the indicated access width and operation. This includes fixed low addresses, addresses derived by doubling incoming values, and addresses loaded from memory.

There are no visible checks for null addresses, bounds, alignment, arithmetic overflow, permissions, or valid indirect destinations. The contract does not invent such checks. Successful execution also requires an executable final destination and whatever calling-convention conditions that destination requires.

## Behavior

### Initial publication and shared-state acquisition

The primary-base word at offset `0x20` receives three successive values:

1. The value `0x2f`.
2. The zero-extended byte read from primary-base offset `0x04`.
3. The value `0x20`.

The byte read occurs after the first word store and before the second. These are distinct accesses, not merely a final assignment of `0x20`.

The shared base is then read from its fixed backing cell. A word store of `0x20` follows at absolute address `0x60`.

The secondary base is doubled to obtain a retained arithmetic value. That doubled value is stored as a word at the address formed by doubling the initial selector and adding `0x54`.

### Repeated cross-linked writes

The next region publishes relationships among the incoming values and the shared base.

Its first publication has three ordered writes:

- A byte at shared-base offset `0x19` receives the primary base’s low byte.
- A byte at primary-base offset `0x11` receives the shared base’s low byte.
- A word at shared-base offset `0x34` receives twice the initial selector.

The remaining repeated publications use twice the primary base instead of twice the initial selector. Each is preceded by a word store of twice the secondary base at the address formed by twice the primary base plus `0x54`. Within each publication, the two byte writes precede the shared-base word write, in the order described above.

These publications repeatedly address the same derived locations. They do not visibly advance a pointer or traverse a range. Equal stored values do not make the operations interchangeable with a single publication when aliases, externally observed writes, or special memory are relevant.

The exact numerical repetition count is **documented_only** here. The supplied representation establishes a finite repeated sequence and its ordering, but this contract does not certify an independently verified count. A count-sensitive implementation requires that remaining evidence to be resolved rather than choosing an arbitrary loop bound.

### Captured values and secondary-state updates

After the repeated region, the function reads and retains:

- A word at absolute address `0xa9`.
- A word at twice the secondary base plus `0x74`.

A byte at absolute address `0x3a` then receives twice the primary base’s low byte plus `0x30`, reduced to eight bits.

Next, a word is captured from secondary-base offset `0x14`, followed by a word captured from primary-base offset `0x04`. The latter is a fresh word read, distinct from the initial byte read at that offset.

The following updates occur in order:

- Secondary-base offset `0x0d` receives the primary base’s low byte.
- Primary-base offset `0x08` receives byte `0x6c`.
- Primary-base offsets `0x0d` and `0x09`, in that order, receive the shared base’s low byte.
- Secondary-base offset `0x54` receives the secondary base as a word.
- Absolute address `0x67` receives the low byte of the word captured from address `0xa9`.

The function then reads a signed word from secondary-base offset `0x44`. It copies the byte at absolute address `0x67` to absolute address `0x21`.

The signed word just read supplies three subsequent effects:

- Its low byte is written to primary-base offset `0x10`.
- Its full word is written to shared-base offset `0x54`.
- A right-shifted form supplies a byte written to secondary-base offset `0x01`. The shift count is the primary base’s low byte.

The word at shared-base offset `0x54` is then overwritten with the primary base.

The exact semantics of the signed right shift, especially for counts of 32 or greater, are not established by this representation. They must not be replaced with an assumed masking or saturation rule.

### Overlapping primary-state updates

A word is read from primary-base offset `0x40`.

The earlier captured word from primary-base offset `0x04` is written to shared-base offset `0x74`. The newly read word from offset `0x40` is written to primary-base offset `0x10`. This word write overlaps and supersedes the earlier byte write at offset `0x10`, and also covers offset `0x11`.

The secondary base is written as a word to shared-base offset `0x44`.

Subsequent updates are:

- Primary-base offset `0x09` receives a fresh read of the byte at absolute address `0x67`.
- Secondary-base offset `0x09` receives the primary base’s low byte.
- Primary-base offset `0x44` receives the word captured earlier from absolute address `0xa9`.

A word read from primary-base offset `0x54` now establishes a **linked base**. It is read at this point, not captured on entry.

Primary-base offset `0x09` again receives the byte read from absolute address `0x67`. The linked base’s byte at offset `0x0d` then receives the low byte of the word captured from twice the secondary base plus `0x74`.

The earlier word captured from secondary-base offset `0x14` is written back to secondary-base offset `0x54`, replacing the intervening self-base value.

### Final linked-state updates and invocation

A word is captured from primary-base offset `0x14`.

Secondary-base offset `0x11` receives the same low byte previously written to linked-base offset `0x0d`. Primary-base offset `0x09` then receives the linked base’s low byte, and primary-base offset `0x44` receives the linked base as a word.

A fresh signed word read from secondary-base offset `0x04` establishes a **record base**. The function writes halfword `0x0065` at twice that record base, then reads a word from record-base offset `0x64`.

The linked base receives two further writes:

- Its byte at offset `0x11` receives the low byte of the word captured from primary-base offset `0x14`.
- Its word at offset `0x54` receives decimal 100.

The function next captures a word from record-base offset `0x74`, then reads a word from secondary-base offset `0x64`.

Its final visible writes are:

- Secondary-base offset `0x09` receives the record base’s low byte.
- The address obtained from secondary-base offset `0x64`, plus `0x54`, receives the word previously read from record-base offset `0x64`.
- Twice the value read from record-base offset `0x64` receives the word read from secondary-base offset `0x64`.

The unresolved destination is then invoked with these four arguments, in order:

1. Decimal 114, equivalently `0x72`.
2. The word read from record-base offset `0x64`.
3. The earlier captured word from secondary-base offset `0x14`.
4. The word read from record-base offset `0x74`.

No visible operation resolves the indirect destination or checks it before invocation.

### Arithmetic and aliasing rules

Unsigned primary-base arithmetic is represented at 32-bit width. Doubling, adding offsets, and byte narrowing must not silently become unbounded arithmetic.

Doubling the signed secondary base, initial selector, or record base can exceed signed 32-bit range. The supplied representation does not establish a portable overflow rule. Inputs avoiding such overflow permit the ordinary mathematical interpretation; other inputs are **documented_only** pending machine-level evidence.

No disjointness between memory regions is established. Later reads observe memory after earlier writes. Values explicitly captured earlier remain captured values even if their backing locations subsequently change. Final-state simplifications therefore require explicit nonaliasing and ordinary-memory assumptions.

## Acceptance examples

These examples are conditional specifications, not executed tests.

### Initial access trace

A result that writes only the last value does not preserve the represented access trace.

### Byte narrowing

Given a primary base whose low byte is `0xf0`, the write to absolute address `0x3a` carries byte `0x10`: twice `0xf0` plus `0x30`, narrowed to eight bits.

This example assumes preceding accesses complete. It does not imply that every address derived from such a primary base is valid.

### Temporary self-reference

Given ordinary, nonaliasing storage and uninterrupted execution, secondary-base offset `0x54` first receives the secondary base, then later receives the word captured from secondary-base offset `0x14`.

The original content of offset `0x54` is not restored unless it happens to equal that captured word.

### Overlapping stores

Given nonaliasing shared and primary regions, the byte initially written at primary-base offset `0x11` does not necessarily survive. The later word store at primary-base offset `0x10` covers it.

The final byte at offset `0x11` depends on that word’s representation and any still-later aliasing writes.

### Final invocation arguments

Given nonaliasing ordinary memory, suppose the captured secondary-offset-`0x14` word is `0x11223344`, the record-offset-`0x64` word is `0x00000200`, and the record-offset-`0x74` word is `0xaabbccdd`.
