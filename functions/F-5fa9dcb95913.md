# F-5fa9dcb95913

## Purpose

F-5fa9dcb95913 transfers bytes into caller-provided storage using a mutable, stream-like state object. It consumes available buffered bytes, invokes a refill dependency when necessary, and may subsequently use a direct-transfer dependency.

The apparent intent is an element-oriented read: element size multiplied by requested element count determines the byte target. Normal completion returns the requested count. Early termination delegates return-value calculation to F-d7be9cfb4000.

The element-read interpretation is inferred. In particular, F-d7be9cfb4000 is not supplied, so short returns are not established to equal the number of complete elements transferred.

## Behavior

### Entry and initial availability

The function first reads and saves the global configuration mask.

If element size is zero, it returns zero immediately. The entry global read still occurs, but no state or destination access and no dependency call is visible on this path.

For nonzero element size, it reads the state flags:

- If `0x01000000` is clear, initial availability is the signed 32-bit value at offset 0. There is no second global-mask read on this path.
- If `0x01000000` is set, it reads the global mask again. Initial alternate availability is calculated only if the initially captured flags, masked by this second value, equal `0x00400001`. Otherwise initial availability is zero.

The saved entry value does not control this initial comparison.

### Alternate availability calculation

Address comparisons and subtractions in this calculation use unsigned 32-bit values. The resulting bit pattern is subsequently used as a signed 32-bit available-byte count.

For stable address fields, the calculation yields:

- Zero if the boundary address is at or below the current address.
- Current address minus boundary address, modulo \(2^{32}\), if the boundary is above the current address.

This is not the usual forward distance from current address to boundary. For example, current address `0x1000` and boundary `0x1010` produce `0xfffffff0`, interpreted as −16. A sufficiently large unsigned gap can instead wrap to a positive signed result.

The field-read sequence matters:

- With `0x00001000` set, the function first reads the current address, compares it with a boundary-field read, and conditionally rereads the boundary as a candidate. If that candidate is at or below the saved current address, it uses candidate minus current and bypasses the later calculation. With stable fields, this shortcut produces zero.
- Otherwise, the function reads the current address and boundary for the later calculation, then reads the boundary again for its comparison. Depending on that comparison, subtraction uses either the saved boundary or the saved current address.

Thus the stable-field formula does not describe every possible result under interleaved field changes. No synchronization is visible.

Post-refill alternate availability uses the same address-calculation behavior, but a different mask source and explicit exclusion of `0x00800000`, as described below.

### Byte target and completion

After establishing initial availability, the function initializes its transferred-byte count to zero and marks direct transfer ineligible. It then forms the byte target from element size multiplied by requested element count.

The operands and subsequent target comparisons are signed 32-bit quantities. Overflow behavior for this signed product is not conclusively established by the supplied representation.

At each main-loop completion check, if transferred bytes are at least the target:

1. The function rereads the current flags.
2. If `0x01000000` is clear, it writes local availability to offset 0.
3. It returns the requested element count unchanged.

A nonpositive target can therefore complete without transferring bytes. Except when element size itself is zero, initial state processing has already occurred. Requested count zero does not bypass availability initialization.

### Buffered transfer

When local availability is positive and the target has not been reached, the function selects the smaller of availability and remaining target bytes.

It calls the unmapped byte-copy dependency with the destination, the current address read from offset 4, and the selected byte count. The caller does not use a copy return value.

After that call, it:

1. Decreases local availability by the selected count.
2. Advances its local destination pointer.
3. Increases its transferred-byte count.
4. Rereads offset 4 and writes that value increased by the selected count.

The source address supplied to the copy and the address subsequently advanced are separate reads on opposite sides of the dependency call. They must not be assumed equal if the dependency changes state.

### Choosing refill or direct transfer

When availability is less than one, the function examines the current threshold at offset 28.

Direct transfer occurs only when both conditions hold:

- The original total byte target is greater than the threshold in signed comparison.
- An earlier nonterminating negative refill result has made direct transfer eligible.

The threshold comparison uses the original target, not the remaining byte count. Its read occurs even when direct transfer is still ineligible.

Otherwise the function refills. The refill preparation performs a separate threshold read; equality with the earlier threshold read is not guaranteed under interleaved changes.

### Refill

If the threshold is less than the original target, the function sets `0x00800000` in the flags. It then calls F-d1a8963fd3c6 with the state pointer and a second argument of zero.

After the call, it captures the flags and writes them back with `0x00800000` cleared. This clearing occurs for every refill result. It does not restore the bit’s previous state and also removes the bit if the dependency set it.

The refill result controls subsequent behavior:

- **−1:** terminate through the short-return path, without recomputing availability.
- **−2:** preserve local availability, emit no byte, make direct transfer eligible, and resume.
- **Any other value:** recompute availability from the post-call state.

For recomputation:

- Ordinary mode reads availability from offset 0.
- Alternate mode compares the captured post-call flags, with `0x00800000` excluded, against the saved entry-time global mask. The comparison must equal `0x00400001`; otherwise availability becomes zero.
- No new global-mask read is made for this calculation.

After recomputation, a nonnegative refill result increases the transferred count by one, writes the result’s low eight bits to the destination, advances the destination, and resumes the completion check. This byte is counted separately from any buffered availability established by the refill. A nonnegative result does not itself make direct transfer eligible.

A negative result other than −1 or −2 emits no byte but does make direct transfer eligible after recomputing availability.

Once eligibility becomes true, no visible operation resets it.

### Direct transfer

Before calling F-b4ea9751e416, the function captures an accounting baseline:

- With `0x00000020` clear: current address plus offset-24 accounting value minus backing-buffer address.
- With that flag set: the value at offset 40.

It calls F-b4ea9751e416 with destination, remaining byte count, and state.

For a positive result, it performs these updates in order:

1. Advances the local destination by the reported count.
2. Writes baseline plus reported count minus one to offset 24.
3. Increases the transferred count by the reported count.
4. Sets local availability to zero.
5. Reads the final byte of the destination range just reported as transferred and writes it to the backing-buffer address obtained from post-call state.
6. Writes backing-buffer address plus one to offset 44.
7. Writes backing-buffer address plus one to offset 4.
8. Sets `0x00020000` in the current flags.

The backing-buffer field is read separately for the byte write and subsequent address updates. These are not guaranteed to use a single captured address. Evaluation order between the source-byte read and destination-address evaluation within the byte assignment is not established.

After positive-result updates, or immediately for a nonpositive result, the function takes the short-return path if the result is −1 or zero. For other results it tests the current `0x00000040` flag and terminates if set.

Consequences include:

- A positive result with the stop flag set terminates only after all positive-result updates.
- That termination takes precedence over the next normal-completion check, even if the target has been reached.
- Other negative results with the stop flag clear do not directly terminate or advance the transfer. Repeated attempts without progress are possible.
- There is no visible validation that a positive result is at most the requested remaining count.

### Short return

The short-return path rereads current flags. If `0x01000000` is clear, it stores local availability at offset 0.

It then calls F-d7be9cfb4000 with transferred bytes and element size and returns that dependency’s result unchanged.

Previously delivered bytes and state changes remain in place. No rollback is shown.

## Side effects

Visible effects include destination writes, current-address advancement, conditional availability writeback, accounting and boundary updates, and flag changes.

A positive direct transfer additionally writes its final delivered byte into the backing buffer.

The global configuration mask is directly read but not directly written. The saved entry value remains the mask used by post-refill calculations even if a dependency changes the global. Initial alternate-mode processing instead uses the separate initialization-time read. Equality between these observations, atomicity, and consistency requirements are unknown.

No allocation or deallocation is directly visible. This does not establish whether dependencies allocate, retain pointers, transfer ownership, or release resources.

The function does not visibly retain the destination pointer in state or global storage. Dependency retention behavior is unknown.

There is no separately established error code, error-object contract, or mandatory error-flag update. Errors exposed by callees are handled only through the branches described above and any state changes those callees perform.

## Acceptance examples

These are conditional static acceptance cases, not observed executions. They assume valid memory, relevant arithmetic without unresolved signed overflow, and the stated dependency behavior.

1. **Zero element size.** Element size zero returns zero after the entry global-mask read. State and destination are not accessed; there is no second global-mask read.

2. **Ordinary buffered completion.** Size two, count three, and ordinary availability eight require six copied bytes. If the copy dependency copies those bytes and preserves relevant state, the current address advances by six, availability is written back as two, and the result is three. No refill or direct transfer occurs.

3. **Zero requested count.** Nonzero size and count zero still establish initial availability. Initially selected alternate mode therefore causes the second global-mask read even though no bytes are requested. Normal completion returns zero.

4. **Different global-mask observations.** Suppose the entry mask is zero, the second mask is `0x00400001`, and initial flags are `0x01400001`. The initial mask comparison succeeds using the second read. If a later refill leaves those flags unchanged and requires availability recomputation, its mask comparison fails using the saved zero entry mask. The function does not reread the global to reconcile the difference.

5. **One byte returned by refill.** For a one-byte target with no initial availability, a refill result of `0x123` causes availability recomputation, followed by delivery of byte `0x23`. The function then returns the requested count through normal completion. The temporary refill bit has been cleared.

6. **Refill failure after progress.** If three bytes have been transferred when refill returns −1, no availability recomputation occurs. Ordinary-mode exit writes local availability back. The returned value is exactly F-d7be9cfb4000’s result for three and the supplied element size.

7. **Positive direct result with stop flag.** An eligible direct call returning four with `0x00000040` set performs all positive-result updates, including preserving the final delivered byte in the backing buffer. It then uses F-d7be9cfb4000, even if four bytes completed the target.

8. **Nonterminal negative direct result.** A direct result of −3, with stop flag clear and no relevant state change, does not terminate or advance the transfer. Further direct attempts can occur without a retry limit.

9. **Alternate availability sign.** With stable fields, a successful alternate mask comparison, current address `0x1000`, and boundary `0x1010`, availability is −16. That value alone cannot enter the positive-availability copy path.
