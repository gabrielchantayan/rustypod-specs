# F-1393b2e3d099

## Purpose

F-1393b2e3d099 computes a signed-integer result from three signed-integer inputs. The result combines:

- The second input’s numeric value.
- A fixed contribution of two.
- A contribution determined by the third input, enabled only when that input exceeds 30.
- An additional contribution of two when the first input equals 2 and the second input equals zero.
- A contribution determined by the second input, enabled only when that input exceeds 127.

**Established static behavior:** the function performs arithmetic, comparisons, and right shifts. It makes no visible calls and accesses no visible memory through pointers.

In particular, the second input contributes its entire numeric value, not merely its encoded width. This contract therefore specifies the arithmetic result without assigning protocol or format semantics.

## Behavior

### Result definition

For inputs whose evaluation does not overflow, the result is:

**second input + 2 + third-input contribution + special contribution + second-input contribution**

The contributions are defined below. This mathematical expression describes the result; it does not replace the evaluation order specified afterward.

### Third-input contribution

When the third input is at most 30, its contribution is zero. This includes all representable negative values, zero, and positive values through 30.

When the third input exceeds 30, its contribution is the number of successive seven-bit right shifts required to reduce that positive value to zero. Each positive value encountered before a shift contributes one.

Equivalently, for a positive third input above the threshold, the contribution is its number of base-128 digits:

| Third-input range | Contribution |
|---|---:|
| At most 30 | 0 |
| 31 through 127 | 1 |
| 128 through 16,383 | 2 |
| 16,384 through 2,097,151 | 3 |
| 2,097,152 through 268,435,455 | 4 |
| 268,435,456 through 34,359,738,367 | 5 |

Each range applies only to values representable by the actual input type.

The threshold is specifically 30, not 127. Thus a third input of 30 contributes nothing, while 31 contributes one even though both fit within seven bits.

Every value shifted on this path is positive. Consequently, the behavior does not depend on how an implementation right-shifts negative signed integers.

### Special contribution

The special contribution is two exactly when both conditions hold:

- The second input equals zero.
- The first input equals 2.

Otherwise, this contribution is zero.

The first input has no other established effect. For a fixed nonzero second input and fixed third input, changing the first input does not change a defined result.

### Second-input contribution

When the second input is at most 127, this contribution is zero. Negative values are not rejected, converted to unsigned values, or measured by magnitude.

When the second input exceeds 127, the contribution is the number of successive eight-bit right shifts required to reduce that positive value to zero.

| Second-input range | Contribution |
|---|---:|
| At most 127 | 0 |
| 128 through 255 | 1 |
| 256 through 65,535 | 2 |
| 65,536 through 16,777,215 | 3 |
| 16,777,216 through 4,294,967,295 | 4 |

Again, ranges are limited by the actual signed input type.

The threshold matters independently of the shift width: a second input of 127 contributes zero here, while 128 contributes one. Values from 128 through 255 require only one shift to reach zero.

### Evaluation order

The established evaluation order is:

1. Form the initial accumulated value by adding one to the second input.
2. Evaluate and add the third-input contribution, one increment at a time.
3. Apply the special contribution of two if its conditions hold.
4. Add one unconditionally.
5. Evaluate and add the second-input contribution, one increment at a time.
6. Return the accumulated value.

During the third-input calculation, each increment precedes the corresponding seven-bit shift. During the second-input calculation, each eight-bit shift precedes its corresponding increment.

These operations affect only local integer state in the supplied body. There is no visible memory-write sequence or dependency call between them. Nevertheless, the order is relevant to the arithmetic contract: an initial addition can overflow before subsequent conditions are considered.

### Arithmetic boundaries and errors

All added contributions are nonnegative. Once the initial accumulated value is formed, the calculation only increases it.

A negative second input is permitted by the visible control flow. It bypasses the second-input shift contribution and the special contribution. Its defined result is therefore the second input plus two plus the third-input contribution.
