# F-17cd15d6fe29

## Purpose

F-17cd15d6fe29 performs a stateful update on a caller-supplied object using a 32-bit value, two control arguments, and an 8-bit attribute.

Two paths are established:

- If the byte at object offset `0xE8` is nonzero, the function stores the supplied value at offset `0xE0` and returns without calling any dependency.
- Otherwise, it records the attribute, resolves an associated handle, performs several dependent operations, constructs a temporary context, and conditionally invokes a processing dependency. It then stores the supplied value and passes the temporary context to a final dependency.

The apparent intent is to update an object's current selection or associated item, with optional processing controlled by a mode and caller flags. That interpretation is inferred; the semantic identities of the object, value, handle, and temporary context are not established.

This contract distinguishes direct effects of F-17cd15d6fe29 from effects that may occur inside its dependencies.

## Behavior

### 1. Select the short or full path

The first direct object access is an 8-bit read at offset `0xE8`.

If that byte is nonzero:

1. Store the supplied 32-bit value at object offset `0xE0`.
2. Return.

On this path, the function does not directly store the attribute, resolve a handle, obtain a context, construct the temporary context, read the 16-bit field, or call any dependency.

The byte is tested only once. Later changes to that location do not cause this invocation to reconsider its selected path.

### 2. Record the attribute and resolve a handle

When the initial byte is zero:

1. Store the 8-bit attribute at object offset `0xE4`.
2. Call F-1f46730b1ced with the address at object offset `0xB0` and the supplied 32-bit value.
3. Treat the result as a 32-bit handle-like value.
4. If that result is zero, call F-a817d8d58c10.

The attribute store precedes handle resolution and the zero-result branch. There is no visible rollback of that store.

The non-returning annotation on F-a817d8d58c10 establishes the expected control-flow boundary, but not its termination mechanism. Whether it aborts, transfers control elsewhere, or performs some other non-returning operation is unknown.

### 3. Process the resolved handle

For a nonzero handle, the function makes these calls in order:

1. F-d2f99870cc43 with the handle.
2. F-bf557f07179f with the original object address and the 32-bit result of F-d2f99870cc43.
3. F-fa8898fa75ae with the same handle value.

The result passed to F-bf557f07179f is not inspected or transformed here.

The stored handle value is used again later if processing is enabled. The intervening call to F-fa8898fa75ae does not, by itself, establish that the handle has been released or remains valid. Those semantics belong to that dependency's unknown contract.

### 4. Construct the temporary context

The function obtains two context addresses through two separate calls to F-fdd8589eca2d:

1. Call F-fdd8589eca2d.
2. Read one byte at offset `0x2C` from its result.
3. Call F-fdd8589eca2d again.
4. Read a 32-bit value at offset `0x28` from this second result.
5. Call F-2c5a9f9c1eb3 with a local temporary-storage address, the 32-bit value, and the previously read byte.

The local storage is represented as a 92-byte region. Its internal layout and the meaningful extent of its contents are unknown.

The two context results need not be identical. The byte and 32-bit value are acquired at different times, with a dependency call between their reads. This function therefore does not establish that they form a consistent snapshot of one context object.

No explicit initialization of the temporary storage precedes F-2c5a9f9c1eb3. The visible contract is that the dependency receives the storage and the two acquired values, not that the storage is zero-filled.

### 5. Decide whether to invoke processing

After temporary-context construction, call F-5c5958cfd5fe and compare its 32-bit result with `8`.

If the result equals `8`, skip processing and proceed to the final value store and temporary-context finalization.

For every other result:

1. Call F-fdd8589eca2d a third time.
2. Determine a 16-bit argument:
   - Read the 16-bit field at object offset `0xE6` only when the suppression argument is zero and the processing argument is nonzero.
   - Otherwise use zero without reading that field.
3. Call F-818c773e8c8a with, in order:
   - The third context result.
   - The temporary-storage address.
   - The resolved handle.
   - The original processing argument.
   - The selected 16-bit value.

The third context call occurs before the conditional field read. If that call modifies offset `0xE6`, the subsequent read observes the field after the call, subject to the execution environment's memory semantics.

A zero processing argument does not suppress F-818c773e8c8a. Only the mode result of `8` suppresses that call. The two caller controls select its final argument.

### 6. Store the supplied value and finalize

After either skipping processing or returning from F-818c773e8c8a:

1. Store the supplied 32-bit value at object offset `0xE0`.
2. Call F-920630e53283 with the temporary-storage address.
3. Return if that dependency returns.

The value store occurs before the final dependency call. This function does not restore the field afterward if that dependency changes it.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Later steps require earlier dependencies to return normally unless specified otherwise.

### Nonzero initial selector

Given a valid object whose byte at `0xE8` is nonzero:

- The supplied value is stored as 32 bits at `0xE0`.
- No dependency is called.
- No attribute store or `0xE6` read occurs.

This applies to every nonzero byte value, not just `1`.

### Resolver failure

- The attribute store at `0xE4` precedes resolution.
- F-a817d8d58c10 is called.
- No normal continuation, final value store, or temporary-context finalization is established.

### Mode equal to eight

Given successful resolution and a mode result of `8`:

- Handle processing and temporary construction occur.
- There are two calls to F-fdd8589eca2d, not three.
- F-818c773e8c8a is not called.
- Offset `0xE6` is not read.
- The supplied value is stored before F-920630e53283 is called.

### Field-derived processing value

- A third context call occurs.
- The function then reads the 16-bit field at `0xE6`.
- That value is supplied to F-818c773e8c8a with the unchanged processing argument.

A processing argument of `-1`, under the recovered signed interpretation, satisfies the nonzero condition.

### Forced-zero processing value

- F-818c773e8c8a is still called.
- Its final argument is zero.
- Offset `0xE6` is not read.

### Distinct context results
