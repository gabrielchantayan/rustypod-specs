# F-4838a890d12c

## Purpose

F-4838a890d12c computes a candidate byte extent from a two-byte input field and context-dependent format information. It reports success only when an initial derived offset is below a context limit and the selected additional extent is nonzero and less than 520 bytes.

On success, it writes the sum of the initial offset and the additional extent to a caller-supplied 32-bit output location. On ordinary rejection, it returns a failure bit pattern without directly writing that location.

The apparent intent is to identify an extent within a structured input record. That interpretation is inferred, not established: the available evidence does not define the record format, the conversion performed by F-0ec8efa9c769, or the meaning of the context’s mode fields.

## Interface

The function accepts three arguments:

1. **Context address.** An address represented by a 32-bit value. It identifies an object containing further addresses and format-selection fields.
2. **Input address.** An address from which the function reads two-byte fields. No explicit input-buffer length is passed.
3. **Output address.** An address at which the function can store one 32-bit result.

The return value is a 32-bit quantity:

| Outcome | Return bit pattern | Direct output write |
|---|---:|---|
| Accepted extent | 0x00000000 | One 32-bit store |
| Ordinary rejection | 0xFFFFFFCE | None |

The rejection pattern represents −50 when interpreted as a signed 32-bit integer. No symbolic error name or broader error convention is established.

## Behavior

### 1. Derive the initial offset

The function first reads the two-byte field at input offset 0 and passes its value to F-0ec8efa9c769.

The dependency’s result is used at full 32-bit width. The function adds 2 and, if that result is odd, instead uses the original result plus 3. For ordinary nonnegative values without overflow, this produces the least even integer greater than or equal to the dependency result plus 2.

The derived offset is then treated as an unsigned 32-bit quantity.

The function next reads the descriptor address through context offset 8 and reads the unsigned 16-bit limit at descriptor offset 30. Processing continues only if the derived offset is **strictly less than** that limit.

Equality rejects. No format-selection reads or further dependency calls occur on this rejection path.

Under the 32-bit interpretation, an offset that passes this comparison is necessarily even and at most 65,534. The comparison does not establish that the caller’s input allocation is that large.

### 2. Select an additional extent

After the initial-offset comparison passes, the candidate additional extent starts at zero.

The function reads the address at context offset 4, then the flag byte at offset 8 of that object.

- **Flag equals zero:** select an additional extent of 4 bytes. The nested mode path is not read.
- **Flag is nonzero:** inspect the nested mode path described below.

For the nonzero-flag path, the function reads the descriptor address through context offset 8 again. It follows the address at descriptor offset 4, then the address at intermediate-object offset 8, and finally reads the mode byte at offset 236 of the mode-bearing object.

The mode determines the next action:

| Mode | Action |
|---:|---|
| 3 | Select 64 bytes |
| 4 | Decode an input-relative selector |
| Any other value | Leave the additional extent at zero |

The second descriptor-address read is distinct from the earlier read used to obtain the limit. The evidence does not require those reads to produce the same address if the context changes during execution.

### 3. Decode the mode-4 selector

In mode 4, the function reads a two-byte field at the input address plus the derived offset and calls F-0ec8efa9c769 with that field.

Only the low 16 bits of this dependency result participate in selector interpretation. They are interpreted as a signed 16-bit value:

| Selector | Additional extent |
|---:|---|
| 1 | 88 bytes |
| 2 | 248 bytes |
| 3 or 4 | Computed from another input field |
| Any other value | Zero |

For selector 3 or 4, the function reads the two-byte field at input offset **derived offset + 8** and calls F-0ec8efa9c769 again. It uses this third result at full 32-bit width, multiplies it by 2, and adds 10 to obtain the additional extent.

There are no visible reads of the intervening six bytes between the selector field and this further field. Their contents have no direct effect in the supplied behavior.

### 4. Validate the additional extent and return

The function accepts the selected additional extent only when both conditions hold:

- It is less than 520 under an unsigned 32-bit comparison.
- It is not zero.

If either condition fails, the function returns 0xFFFFFFCE without directly storing to the output address.

If both conditions hold, the function adds the derived offset and the additional extent, stores the resulting 32-bit value at the output address, and returns zero.

The descriptor limit is **not** checked against:

- The final sum.
- The selector’s complete two-byte span.
- The further field at derived offset + 8.
- The purported extent’s availability in the input allocation.

A final result greater than the descriptor limit is therefore not, by itself, grounds for rejection.
