# F-a44e748fd472

## Purpose

The established behavior is an ordered sequence of mixed-width memory accesses, address traversals, field replacements, computed-address writes, and a final unresolved indirect invocation.

No application-level purpose is established. Repeated constants, self-address stores, and pointer-like fields do not establish a particular data structure or algorithm.

This contract describes the supplied static representation. Its correspondence to an executable’s true function boundary, calling convention, and control flow remains unresolved.

## Interface

### Incoming state

There are no explicit parameters or returned data in the supplied representation. The operation nevertheless consumes incoming register state:

| Contract name | Incoming state | Uses |
|---|---|---|
| A | Address carried in r4 | Memory base and stored address value |
| B | 32-bit value carried in r5 | Memory base and truncated byte value |
| C | Address carried in r6 | Memory base and stored address value |
| D | 32-bit value carried in r7 | Stored word and truncated byte |
| E | 32-bit value carried in r3 | Stored word |

These are entry-state names, not an established conventional argument list.

Three fixed storage dependencies are designated **G1**, **G2**, and **G3**. Their addresses, meanings, initial contents, ownership, and mutability are not established.

The final indirect dependency is designated **F-unresolved-1**, a contract-local opaque identifier. It does not establish the target’s identity or validity.

### Widths, layout, and notation

The representation distinguishes 8-bit bytes, 16-bit halfwords, and 32-bit words. Address-bearing fields are represented as words. This contract uses that 32-bit model; the executable’s actual address model is not independently verified.

All offsets are hexadecimal byte offsets. Offset `0x64` is decimal 100.

In the behavior below:

- An unqualified field read or write is a 32-bit word access.
- Explicit byte and halfword accesses use 8 and 16 bits respectively.
- A narrow store retains the corresponding low bits.
- Names introduced for captured values remain fixed despite later memory changes.
- Names do not imply distinct allocations or nonaliasing.

No complete object layout, extent, alignment, or field type is established. A word write can overlap several byte fields. Endianness determines the byte representation of a word.

### Preconditions and results

Completion requires every reached address to permit the specified access. This includes pointer-derived locations, address sums, doubled values, and addresses derived from a byte interpreted as a character.

No null checks, bounds checks, allocation checks, or explicit error-return convention are represented.

Observable results are memory accesses, mutations, possible faults, and the indirect invocation. If that invocation returns, the representation then returns without an explicit result value. Its behavior must not be reduced to a pure memory transformation.

## Behavior

### Ordering and interpretation

The following intervals describe one represented straight-line path. Reads observe memory at their position in that path, including earlier overlapping writes. A fresh read cannot generally be replaced by a previously captured value.

Repeated writes and unchanged-value writebacks remain accesses. Their removal would change access-sensitive behavior and possible fault ordering.

Except where explicitly qualified below, arithmetic overflow and address validity are environmental uncertainties, not a promise of wrapping arithmetic.

### Computed-address tail and invocation

Read G1 as **AR**, then Q+`0x74` as **AS**. Store low AS as a halfword at address AS+Q. Next store low AR as a halfword at address twice AQ.

Read one byte at AO+Q using the representation’s character interpretation, then convert it to unsigned 32-bit value **AT**. If that character interpretation is signed, negative byte values become their corresponding unsigned 32-bit values after sign extension. Plain-character signedness is not independently established.

Continue in this order:

1. Store low AS as a halfword at AR+AS.
2. Store low AS again as a halfword at AS+Q.
3. Store word `0x45` at AT+`0x45`.
4. Read G2 as **AU**, G3 as **AV**, and Q+`0x44` as **AW**, in that order.
5. Store byte `0x44` at AT+`0x44`.
6. Store AV as a word at address twice AU.
7. Store low AU as a halfword at AF+AU.

Invoke **F-unresolved-1** with these three represented arguments, in order:

1. AT bitwise-OR `0x44`.
2. AU.
3. AW.

The first argument uses bitwise OR, not addition.

In the represented 32-bit unsigned model, AT+`0x44` and AT+`0x45` use unsigned arithmetic modulo \(2^{32}\). That does not establish the validity of the resulting memory addresses. Other sums, subtractions, and doubling operations involve signed or pointer-like quantities; a blanket unsigned-wrap interpretation is not justified.

## Side effects

The operation mutates incoming-state-reachable memory and potentially unrelated addresses derived from stored values. Reads of fixed storage occur late enough that preceding overlapping writes could affect their results.

No allocation or release is explicitly represented before the indirect invocation. No ownership transfer is established. Replacing an address-bearing field does not prove destruction or release of its previous referent.

Writes are not transactional. If an access terminates execution, preceding accesses may already have changed memory; no rollback or recovery path is represented.

No synchronization, atomicity, volatile qualification, or concurrency guarantee is established. The ordering above is the ordering of the supplied representation, not independently verified hardware transactions.

The indirect dependency may change memory, globals, resources, or control flow. Its absence does not justify assuming preservation, ownership retention, successful return, or freedom from errors.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each assumes execution reaches the described interval.

1. **Captured first-interval destination.** Suppose S+`0x04` initially contains address X₁. The Q+`0x54` word write then changes S+`0x04` to X₂ through aliasing. The subsequent word `0x64` store still targets X₁+`0x60`, not X₂+`0x60` and not Q+`0x60`.

2. **Read follows the intervening byte write.** Suppose S+`0x11` and S+`0x14` designate overlapping physical storage. The O-destination capture occurs first. The S+`0x11` byte write then occurs before the S+`0x14` word read. The byte written at O-destination+`0x15` comes from that later read, subject to the environment’s representation and alias rules.

3. **Narrowing versus full-word preservation.** If W is `0x123456ab`, W-derived byte stores write `0xab`; the store at B+`0x34` writes the complete word. Later overlapping accesses may change either destination.

4. **Repeated and unchanged writes.** A+`0x1c` receives byte `0x79` before byte `0x68`. Separately, the Q+`0x64` read/writeback requires both read and write access even when its ordinary-memory contents remain unchanged.

5. **Mixed-width overlap.** The word `0x74` at U+`0x10` affects four bytes. The later U-payload-derived byte store changes only its addressed byte. Determining the resulting word requires endianness and intervening alias behavior.

6. **Conditional signed-character expansion.** Under signed 8-bit character interpretation, byte `0x80` produces AT=`0xffffff80` and first invocation argument `0xffffffc4`. Under unsigned character interpretation it produces AT=`0x00000080` and argument `0x000000c4`. The supplied material does not independently select between those character models.

7. **Unsigned tail addition differs from OR.** Under signed-character interpretation, byte `0xff` produces AT=`0xffffffff`. In the 32-bit unsigned arithmetic model, the word destination AT+`0x45` is `0x00000044`, the byte destination AT+`0x44` is `0x00000043`, and the first invocation argument remains `0xffffffff`.

8. **Partial completion.** If the halfword store at twice AQ faults and execution terminates, the preceding halfword store at AS+Q has already been reached. The character read and indirect invocation have not been reached on that path.
