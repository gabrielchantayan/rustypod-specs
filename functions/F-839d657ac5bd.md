# F-839d657ac5bd

## Purpose

F-839d657ac5bd selects between two state-transition sequences according to whether a 32-bit selector is zero.

The nonzero sequence conditionally initializes context fields, writes fields in an associated object, updates shared configuration, and selects a final control-word update using configuration and status observations. The zero sequence invokes two dependencies and transforms two separately observed control values: one for the return value and one for the control-word store.

These are structural descriptions established by the supplied static representation. Application-level interpretations such as enabling hardware, allocating storage, or releasing a resource are not established.

## Behavior

### Nonzero sequence: preparation and object stores

The following order is established:

1. Read and retain the context value at `0xB4`.
2. Read context offset `0xA0`.
3. If that observation is zero, write zero to context offset `0x98`, then write the retained `0xB4` value to offset `0x9C`.
4. Read and retain the control word as the initial control snapshot.
5. Read and retain the associated-object address from context offset `0x34`.
6. Invoke F-8f180221fee0 without explicit arguments.
7. Store its 32-bit result at associated-object offset `0x80`.
8. Write `0x20080000` to the setup word.
9. Obtain the indexed-address displacement, form the indexed destination address, and store the retained context value with bit 31 cleared.
10. Invoke F-d7be9cfb4000 with arguments zero and `0x40`.
11. Store a rounded value derived from an additional 32-bit output of that call at associated-object offset `0x38`.

A nonzero observation at context offset `0xA0` skips the two conditional context stores. It does not skip the remaining preparation.

The captured context value is not reread for either the `0x9C` store or the indexed configuration store. Likewise, changes to context offset `0x34` after its capture do not redirect either associated-object store.

In contrast, the indexed-address displacement is obtained after the setup-word store, rather than being captured at entry. If those storage roles alias, or if the displacement changes before address evaluation, the destination follows that later observation.

The rounding operation adds three modulo \(2^{32}\), then clears bits 0 and 1. For an input no greater than `0xFFFFFFFC`, this produces the least multiple of four greater than or equal to the input. Inputs `0xFFFFFFFD`, `0xFFFFFFFE`, and `0xFFFFFFFF` produce zero through wraparound. There is no saturation or visible overflow error.

The additional output associated with F-d7be9cfb4000 is visible, but its formal ABI meaning is unresolved. It is not established to be an address, size, allocation result, or ordinary declared return value.

### Nonzero sequence: branch selection

After the associated-object store at `0x38`, the function obtains the configuration base and reads the byte at base offset `0x04`.

The special path requires both:

- The observed configuration byte is zero.
- The initial control snapshot masked with `0x03CC0000` equals `0x000C0000`.

A nonzero configuration byte selects the ordinary path regardless of the initial control bits. The control condition uses the earlier snapshot, not a fresh control observation.

### Special path

The function performs these stores in order:

1. Obtain the configuration base again and write `0x80` at that base plus `0x18`.
2. Write `0x39` to the auxiliary word.
3. Write the initial control snapshot with bit 26 set to the control word.

The base used for the first store need not equal the base previously used for the configuration-byte read. The representation does not authorize retaining the earlier base in place of the later observation.

The final control value is the initial control snapshot OR `0x04000000`. There is no fresh control read for this construction. Intervening changes to the control location can therefore be overwritten.

The result has the control location’s 32-bit address in its upper half and zero in its lower half.

### Ordinary path: optional dependency

If bits 18 and 19 of the initial control snapshot are both one, invoke F-9c06a5856a0f with:

- The four-bit value in initial-control bits 22 through 25.
- Zero as the second argument.

Otherwise, omit that call. Both the call condition and the extracted argument use the initial snapshot. No result from this dependency is visibly consumed.

### Ordinary path: ordered status and control observations

A status extraction means bits 29 and 30 of a 32-bit status observation, yielding zero through three. Bit 31 is excluded.

After the optional dependency, the access sequence is:

1. Read status and extract the first two-bit value.
2. Read control unconditionally.
3. If the first extraction is not three, use that control observation unchanged for the final store.
4. If the first extraction is three:
   - Read status again and extract its two-bit value.
   - Read control again, after this second status read.
   - Construct a candidate by setting bits 31 and 26 in this latest control observation, using `0x84000000`.
   - If the second extraction is not three, read control yet again and replace the candidate with this final observation OR `0x8C000000`.

The final candidate is then written to control. Thus:

| Status observations | Control value written |
|---|---|
| First extraction is zero, one, or two | The unconditional control observation immediately after the first status read |
| First and second extractions are both three | The control observation after the second status read, OR `0x84000000` |
| First extraction is three; second is zero, one, or two | The final additional control observation, OR `0x8C000000` |

In the last case, the preceding control read and the intermediate `0x84000000` construction still occur. That intermediate construction is replaced; it is not separately written to control.

The result’s lower half is zero. Its upper half is:

- The first extracted status value when that value is zero, one, or two.
- Three when both extractions are three.
- The final control observation OR `0x8C000000` when the first extraction is three and the second is not three.

Neither the unconditional control read nor later reads may be collapsed into a single snapshot. In particular, a change between the second and third ordinary-path control observations affects the changing-status case’s store and result.

### Zero sequence

The zero sequence performs:

1. Read context offset `0x34`.
2. Invoke F-8b341d935c06 with that value, zero, and one.
3. Read context offset `0x34` again.
4. Invoke F-ddf4a1f94e38 with the newly observed value and `0x80`.
5. Read control and retain this first post-call observation for the result.
6. Read control again and transform this second observation for the control-word store.
7. Write the transformed second observation to control.

The transformation clears bits 26 through 31 and bit 17, forces bit 21 to one, and preserves all other bits. Equivalently, it applies mask `0x03FDFFFF`, then sets `0x00200000`.

The returned upper half contains the control location’s address. The returned lower half applies this same transformation to the **first** post-call control observation.

Consequently, the returned lower half and stored control value are equal only when the transformations of the two observations agree. Equality of the observations is sufficient but not necessary: differences solely in cleared or forced bits do not affect the transformed result.

The second context read is also distinct. If the first dependency changes offset `0x34`, the second dependency receives the replacement value.

No context accesses at `0x98`, `0x9C`, `0xA0`, or `0xB4` are explicitly performed by this sequence.

## Side effects

Direct effects comprise the context, associated-object, configuration, auxiliary, setup, and control stores specified above. Dependencies may have additional effects not established here.

Every normally completing path writes control. On the ordinary path with an initial status extraction below three, this includes writing back an unchanged observed value. Such an equal-value store remains an observable operation where the storage interface exposes writes.

There is no visible rollback, fault recovery, or dependency-error translation. If a call does not return normally or an access faults, later operations are not established to occur, and earlier effects are not visibly undone.

Ordinary completion requires each accessed address to remain valid for the corresponding access. In particular, the retained associated-object address must remain usable across dependency calls. No visible lifetime protection, ownership acquisition, allocation, release, reference counting, or synchronization is established.

The storage-role names do not establish non-aliasing. A store to one role may affect a later read through another role if they share physical storage. Statements about omitted field accesses do not guarantee that those bytes remain unchanged through aliases or dependency effects.

## Acceptance examples

These are conditional static examples, not execution reports. They require valid accesses, normally returning dependencies, and the stated observations.

1. **Conditional context initialization.** With a nonzero selector, context `0xA0` observed as zero, and initial `0xB4` equal to `0xFEDCBA98`, the conditional stores are zero at `0x98`, then `0xFEDCBA98` at `0x9C`. The indexed store carries `0x7EDCBA98`.

2. **Initialization skipped.** If context `0xA0` is observed as nonzero, neither conditional context store occurs. Aliasing and dependency effects remain unconstrained.

3. **Rounding boundaries.** Additional call outputs five and eight each produce eight at associated-object offset `0x38`. Each of `0xFFFFFFFD`, `0xFFFFFFFE`, and `0xFFFFFFFF` produces zero.

4. **Special stale snapshot.** If initial control is `0x000C0000` and the configuration byte is zero, the final control store is `0x040C0000`, regardless of intervening control changes. The return has the control address in its upper half and zero below.

5. **Address-source timing.** If the indexed displacement is observed as `0x20` after the setup store, the indexed destination is the shared anchor plus `0x20`; an earlier displacement value does not determine it. If the configuration-byte access uses one base and the special-path store later observes another, the byte is read at the first base plus `0x04`, and `0x80` is stored at the second base plus `0x18`.

6. **Ordinary path without a second status read.** If the first status extraction is two and the following control read is `0x12345678`, that value is written unchanged. No second status read occurs. The result is `0x0000000200000000`.

7. **Stable status trigger with changing control.** If both status extractions are three, the unconditional control read after the first status is `0x00000010`, and the control read after the second status is `0x00000020`, the final store is `0x84000020`. The result is `0x0000000300000000`.

8. **Changing status trigger with three control observations.** Suppose the status extractions are three and zero. If the successive ordinary-path control observations are `0x00000010`, `0x00000020`, and `0x00000040`, the intermediate candidate is `0x84000020`, but it is replaced. The final store is `0x8C000040`, and the result is `0x8C00004000000000`. Second extractions of one or two follow the same rule.

9. **Fresh zero-sequence argument.** If F-8b341d935c06 changes context offset `0x34`, F-ddf4a1f94e38 receives the newly read value.

10. **Different zero-sequence control observations.** If the first post-call control observation is `0xFFFFFFFF` and the second is zero, the returned lower half is `0x03FDFFFF`, while the stored value is `0x00200000`. If both observations are `0xFFFFFFFF`, both transformed values are `0x03FDFFFF`.
