# F-ad81696f6186

## Purpose

F-ad81696f6186 conditionally initiates an operation for a resolved target, with an alternate path that dispatches the action label `GotoNowPlaying` when the target matches the current item and additional state predicates allow that path.

The supplied static evidence establishes the branch conditions, dependency calls, object-relative offsets, argument values, and normal-path cleanup sequence. It does not establish the application-level meanings of most objects or predicates. “Current item,” “target,” and “operation” are descriptive roles, not verified type names.

Every visible normal return has the 32-bit value `1`. That value does not distinguish a disabled invocation, the alternate action, or the main operation path. The routine exposes no explicit failure result.

## Behavior

### 1. Gate and early return

The first operation is a call to F-2d774464b525.

If its result is zero, the routine returns `1` immediately. On that path, there is no visible access to either input argument, no construction of the local objects, and no subsequent dependency call.

If its result is nonzero, the routine continues. All subsequent behavior described below is conditional on dependencies returning normally.

### 2. Resolve the target and access the context-associated object

The routine calls F-6da76fc58c80, then passes its result and the original selector value to F-ec8e3558572e. The latter’s 32-bit result is retained as the resolved target value.

Next, F-eb24201e389b initializes the four-byte wrapper using the context region at offset `0xB4`.

The routine then:

1. Calls F-e38e6836b640 with that wrapper.
2. Invokes virtual entry `0x38` through the returned object.
3. Calls F-e38e6836b640 with the wrapper again.
4. Invokes virtual entry `0xF0` through this second returned object.

The second lookup is observable and must not be replaced, at the contract level, with an assumption that the first object remains the lookup result. The intervening virtual call or lookup may change state.

The supplied representation does not show explicit receiver arguments for these two virtual calls. It establishes their dispatch targets and order, but not a complete machine-level calling convention.

### 3. Prepare comparison objects and the operation descriptor

F-87be4aa684d1 supplies an object retained for subsequent provider-related virtual calls.

The routine initializes the first 24-byte comparison object through F-ba5a4c1e0746 with two zero-valued arguments. It then invokes provider virtual entry `0x15C`, explicitly passing the provider reference and the address of that comparison object.

It initializes the second 24-byte comparison object in the same way. It obtains a fresh result from F-6da76fc58c80 and calls F-3676a46d9aec with:

- That fresh service result.
- The resolved target value.
- The address of the second comparison object.

The routine obtains another fresh result from F-6da76fc58c80. Through that result, it invokes virtual entry `0xA4`; the returned 32-bit value and a zero-valued argument are passed to F-1c06d0a5910b to initialize the 20-byte operation descriptor.

All three calls to F-6da76fc58c80 are distinct. The evidence does not establish that they return the same object or observe unchanged global state.

Descriptor construction occurs before the path decision. Consequently, it occurs even when the routine ultimately takes the alternate action and never passes the descriptor to F-69a62b9a6385.

### 4. Select the alternate-action path

The first branch predicate is provider virtual entry `0x1A4`.

If its result is nonzero, the routine skips the comparison and takes the main path.

If its result is zero:

1. F-05cc4e9ef0f4 is called on the first comparison object.
2. F-05cc4e9ef0f4 is called on the second comparison object.
3. Their 64-bit results are compared for exact equality.

These are full 64-bit comparisons, not comparisons of only the lower 32 bits. Signedness does not affect equality.

If the values differ, the routine takes the main path. If they match, it invokes provider virtual entry `0x13C`. A zero result takes the main path; a nonzero result selects the alternate-action path.

Only on the alternate-action path, provider virtual entry `0x194` is queried. If that result is nonzero, provider virtual entry `0xF0` is invoked before action construction. A zero result merely skips that invocation; it does not cancel the alternate action.

The routine then calls F-9b9c1c7483f4 with:

- The address of the branch-specific slot.
- The action label `GotoNowPlaying`.
- The address of the branch-specific scratch word.

There is no visible initialization of that scratch word before this call on this path. The evidence does not establish whether the dependency reads it, writes it, or treats it solely as output.

The returned 32-bit value is passed to the context’s virtual entry `0x11C`, together with the context reference. After that call returns, F-8a5aadac202f is called with the address of the branch-specific slot.

This path does not call F-1a78504cbf6c, F-69a62b9a6385, or F-047e5b66fb7c.

### 5. Execute the main path

The main path is selected whenever the alternate-action conditions are not all satisfied.

F-1a78504cbf6c is called with the numeric arguments `0` and `2`. Its result is stored as the auxiliary object reference. There is no visible null check.

The routine then performs, in order:

1. Auxiliary-object virtual entry `0x38`.
2. Auxiliary-object virtual entry `0x5C`, explicitly passing the auxiliary reference, `1`, and `0`.
3. Auxiliary-object virtual entry `0xF0`.
4. A write of zero to the branch-specific scratch word.
5. A call to F-69a62b9a6385.
6. Auxiliary-object virtual entry `0x1A8`.
7. A call to F-047e5b66fb7c with the address of the auxiliary-reference slot.

F-69a62b9a6385 receives, in order:

- The context reference.
- The resolved target value.
- The numeric value `3`.
- The address of the operation descriptor.
- The auxiliary object reference.
- The 32-bit bit pattern `0xFFFFFFFF`.

The final argument’s semantic interpretation is unknown. It may represent signed `−1`, an unsigned maximum, or an application-defined sentinel; the established contract is its bit pattern.

The scratch-word zero write is visible in the supplied representation, but that word is not explicitly passed to F-69a62b9a6385. No additional argument or application-level purpose should be inferred from the write.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime observations. Unless otherwise stated, all reached dependencies return normally.

1. **Disabled gate.**  
   Given F-2d774464b525 returns zero, the result is `1`. No context access, selector resolution, object initialization, or cleanup follows.

2. **Provider excludes the alternate action.**  
   Given provider entry `0x1A4` returns nonzero, neither comparison conversion nor provider entry `0x13C` is invoked. The main path runs, followed by common completion.

   Given entry `0x1A4` returns zero and the comparison results are `0x0000000100000007` and `0x0000000200000007`, the main path runs. Equal low halves do not satisfy the comparison. Entry `0x13C` is not reached.
