# F-204085e51d24

## Purpose

The supplied static representation describes a state-mutating routine that interleaves numerous indirect calls with explicit word, byte, and halfword memory accesses. It forwards its explicit input to the first call, derives addresses and values from incoming machine state and call results, updates a global word, and ultimately attempts a call through address zero.

No application-level purpose is established. In particular, the evidence does not establish that this routine initializes an object, decodes a format, implements a supervisor service, or manages an allocation. Names attached to global storage are not sufficient evidence for those interpretations.

This contract describes the observable operations represented by the supplied material. Its applicability is conditional on that representation accurately describing the executable. Several aspects—especially implicit register results, computed call targets, and low-address accesses—remain **documented_only**, not independently validated.

## Interface

**Explicit input:** one opaque 32-bit value. The routine passes this value as the sole displayed argument to its first indirect call. No direct interpretation, validation, dereference, or later reuse of the explicit input is shown.

**Output:** no explicit return value. A normal return is represented after the final indirect call, but that return is reachable only if every preceding operation, including the call through address zero, completes and returns.

**Additional effective inputs:**

- An incoming return-link value used to calculate the first call target.
- An incoming opaque 32-bit register value used in the first explicit word store.
- Another incoming unsigned 32-bit register value whose upper ten bits are extracted.
- A global 32-bit storage location, read at two separate points.
- A byte stored at absolute address `0x00000001`.
- Three bytes associated with the final global-word construction.
- Ordinary call results, paired 32-bit results represented together as 64 bits, and several implicit secondary-register results.
- Every memory location read directly or accessed by a dependency.

These additional inputs are part of the represented execution, not a complete conventional function signature.

**Notation used below:**

- A **word** is 32 bits, a **byte** is 8 bits, and a **halfword** is 16 bits.
- `slot(index)` means the address obtained by multiplying an index by four and adding `0x14`.
- “Low byte” means bits 7–0 of a value, regardless of the signedness of an intermediate character conversion.
- “Shift right” means logical right shift when the operand is identified as unsigned.
- Descriptive names such as “initial global snapshot” identify values for this contract; they do not establish object types or ownership.

The supplied representation mixes signed integer arithmetic with unsigned arithmetic. Unsigned calculations have 32-bit truncation semantics. Signed multiplication and left shifts must not be silently treated as portable, defined wrapping arithmetic: their exact executable behavior requires confirmation outside this evidence.

**Execution preconditions:** all reached call targets must be executable under the actual calling convention; all reached memory accesses must be permitted with the necessary widths and alignment; and dependencies must return if execution is to proceed. None of these conditions is checked locally.

## Behavior

### Entry and initial field stores

The first indirect call target is formed by adding `0xFFE` to the incoming return-link value. The explicit 32-bit input is forwarded to this call.

A sequence of further indirect calls follows. A returned index then selects a word destination through `slot(index)`. The routine writes the incoming opaque register word there.

Only after that store, it reads the global 32-bit storage location and retains an **initial global snapshot**. A following call receives the index multiplied by four, rather than the address including `0x14`.

After more calls, the routine derives:

- An **upper-ten-bit value** by shifting the other incoming unsigned register value right by 22. Its range is 0 through 1023.
- An **upper-nine-bit value** by shifting the initial global snapshot right by 23. Its range is 0 through 511.

The upper-ten-bit value is written as a full word to `slot(index)`, where this index comes from an implicit secondary-register result. A subsequent call receives that same index twice, followed by the upper-nine-bit and upper-ten-bit values.

A later call returns an opaque word, which is forwarded to another call.

### Repeated word writes and the first indirect-byte update

The next call sequence produces another index. The routine writes the upper-ten-bit value to its word slot, then calls a dependency with the index multiplied by four.

Another implicit secondary-register result supplies an unsigned index. The routine writes zero to its word slot, invokes a dependency with that index, and forwards a later returned word to another dependency.

The routine then writes the upper-nine-bit value shifted right by another 23 bits into a newly selected word slot. Because the upper-nine-bit value is at most 511, this stored word is necessarily zero under the displayed 32-bit unsigned semantics.

It next reads a word from:

`0x14 + ((saved unsigned index AND 0x1FFFFFFF) shifted right by 19)`.

The computed address ranges from `0x14` through `0x413`. Four-byte alignment is not guaranteed by this expression.

After intervening calls, the loaded word is shifted right by 22. Call the result the **extracted ten-bit field**.

The routine then:

1. Reads a byte from address `0x00000001`.
2. Adds `0x11` to that byte’s unsigned value.
3. Writes the low byte of the extracted ten-bit field to the resulting address.

The read address is exactly one because the earlier upper-nine-bit value shifted right by another 23 bits is zero. The destination therefore lies between `0x11` and `0x110`.

A following dependency receives one implicit 32-bit result three times, followed by zero. Further calls include an explicit zero argument.

### Byte clears and global-word publication

The next explicit byte update reads a byte at:

`1 + 4 × extracted ten-bit field`.

This selector address ranges from `1` through `4093`. The routine adds `0x11` to the byte read there and writes zero to that destination.

Subsequent call groups pass selected indices shifted left by two, sometimes duplicated as two arguments. An opaque word result is forwarded to another call.

The routine next reads the byte at absolute address one and writes zero at that byte’s value plus `0x11`. It retains an implicit signed secondary-register result as a **saved shift input**, then passes that value three times to a dependency.

After another returned word is obtained, a call receives that word and a previously returned unsigned word shifted right by 23.

The byte at absolute address one is read again. This new byte value is retained as a **saved byte base**, and zero is written to `saved byte base + 0x11`.

These reads must remain distinct. Calls between them may change the byte at address one.

Following additional calls and duplicated shifted-index arguments, a dependency returns an unsigned word. The routine:

1. Writes that word to a global 32-bit destination.
2. Passes the word to another dependency.
3. Makes a further call.
4. Reads a word at `saved byte base + 0x74`.
5. Writes its low byte to `saved byte base + 1`.

The saved byte base is not reloaded from address one for this read/write pair.

### Word-to-byte transfers and scaled destinations

A dependency receives the saved shift input shifted left by 11.

A subsequent call produces a represented 64-bit result. Its lower and upper 32-bit halves are passed, in that order, to another dependency, followed by the recently published word shifted right by 23. This use does not establish whether the dependency actually returns a language-level 64-bit integer or two register values.

A later index is multiplied by four to form a **retained scaled base**. The routine reads a word at that base plus `0x74` and writes its low byte at that base plus one.

After intervening calls, a new index produces a **retained aligned value** by shifting left by two. The routine repeats the word read and byte write at the earlier retained scaled base. This is a second read, not reuse of the earlier word; intervening dependencies may have changed the source.

A following dependency receives, in order:

- The saved shift input shifted left by 12.
- The retained aligned value.
- The same retained aligned value again.
- The new index shifted left by 18.

Returned opaque words are then forwarded through additional calls.

Another selected index is multiplied by four. The routine reads a word at that scaled base plus `0x74`, retains the full word as the **retained payload**, and writes its low byte at the scaled base plus one.

A later selected index controls a different layout: the retained payload is written at `16 × index + 0x14`. This sixteen-byte scaling must not be replaced by the four-byte scaling used elsewhere.

A dependency next receives the retained aligned value shifted right by two and then left by 16. The two operations remain significant: the evidence does not justify reconstructing any high bits lost when the aligned value was originally formed.

### Payload propagation and second global snapshot

After further forwarding calls, the retained payload is written to another four-byte-scaled word slot.

A newly returned index is shifted left by two. That shifted value is written as a word at:

`(retained aligned value AND 0xFFFFFFFC) + 0x14`.

The shifted value is then passed twice to a dependency.

Following more calls, zero is written to another selected word slot.

Another represented 64-bit result supplies two 32-bit halves. The lower half is shifted left by two and written to the word slot selected by the upper half.

The routine then reads the global storage location again, producing a **second global snapshot**. This is not interchangeable with the initial snapshot: intervening calls may have modified the storage.

A following call receives the shifted lower half, the upper half, and two more copies of the shifted lower half.

After additional calls, the shifted lower half is written to another selected word slot. The routine then reads a word at `second global snapshot + 0x14`, retaining it as the **final source word**.

### Final byte distribution and terminal operations

Another represented 64-bit result supplies a **final lower half** and **final upper half**.

The routine reads a selector byte at:

`(retained payload shifted right by 23) + 1`.

This selector address lies between `1` and `512`. It writes the low byte of the final source word to `selector byte + 0x11`.

A following call receives three copies of the final upper half, followed by the final lower half shifted left by two.

After additional calls, the routine reads another selector byte at:

`((final lower half AND 0x3FFFFFFF) shifted right by 21) + 1`.

This selector address also lies between `1` and `512`. It writes the low byte of the final source word shifted right by 22 to `selector byte + 0x11`.

Further calls pass shifted indices, including one call receiving the same shifted index twice. A later opaque word result is forwarded to another dependency. The next call supplies a byte result.

The final explicit operations are ordered as follows:

1. Write zero through an implicit byte-pointer result.
2. Construct a 32-bit word whose low byte is the last byte result and whose upper 24 bits come from a three-byte global value.
3. Write that word to the same global destination used for the earlier publication.
4. Write a zero halfword at `(final lower half AND 0x3FFFFFFF) shifted right by 7`.
5. Attempt a call through address zero with three displayed zero arguments.
6. Return, only if that call returns.

The halfword destination ranges from zero through `0x007FFFFF` and need not be aligned.

## Side effects

The routine performs explicit writes of 32, 16, and 8 bits, including writes to global storage and dynamically selected addresses. A byte store does not imply clearing adjacent bytes. The final halfword store clears two bytes, not a full word.

All direct accesses and dependency calls occur in the represented order. Dependencies may introduce additional reads, writes, exceptions, nontermination, or control transfers. The routine contains no displayed branch, retry loop, rollback, validation failure path, or explicit error result.

Aliasing is unrestricted by the evidence. A byte destination may overlap global state, a later selector, another destination, or a source word. Consequently:

- Repeated reads must not be collapsed.
- Repeated writes must not be removed merely because their values match.
- Global values must not be treated as constant across calls.
- A dependency’s apparently unused result does not make its call disposable.

No explicit allocation, deallocation, reference-count adjustment, or ownership transfer is established. Passing an address-like value does not prove that a dependency borrows, retains, consumes, or releases it.

Fault behavior is **documented_only**. No local recovery is shown for invalid memory, misalignment, inaccessible low addresses, invalid call targets, or a non-returning dependency.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Initial bit extraction.** If the incoming unsigned register word is `0xFFC00000` and the initial global snapshot is `0xFF800000`, the extracted values are 1023 and 511. The later word store of the upper-nine-bit value shifted right by 23 stores zero.

2. **Byte truncation.** If the extracted ten-bit field is `0x3AB`, its first indirect byte write stores `0xAB`. Its subsequent selector read uses address `1 + 4 × 0x3AB`, not an address derived from `0xAB`.

3. **Fresh selector reads.** If address one contains 7 at one read and a dependency changes it to 9 before the next read, the corresponding destinations are `0x18` and `0x1A`. Reusing the first selector would violate the represented behavior.

4. **Word-read width.** If a word read at a scaled base plus `0x74` produces `0x123456AB`, the associated byte store writes `0xAB`. Where that word becomes the retained payload, later word stores preserve `0x123456AB`.

5. **Distinct scaling.** For an index of 3, a four-byte-scaled word slot is at `0x20`; the sixteen-byte-scaled destination is at `0x44`.

6. **Final construction.** If the final byte result is `0xAB` and the three-byte global value is numerically `0x123456`, the constructed global word is `0x123456AB`. Its physical byte order depends on target endianness.

7. **Failure prefix.** If a dependency does not return, no later explicit operation is required to occur. No rollback of earlier stores is shown.

8. **Address-zero call.** Successful execution through the final halfword write is not sufficient to establish normal return. The address-zero call must also complete and return.
