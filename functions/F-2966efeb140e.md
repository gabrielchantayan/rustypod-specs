# F-2966efeb140e

## Purpose

F-2966efeb140e repeatedly obtains a 32-bit classification value from F-d8deec1d50bf, applies a set of signed comparisons and arithmetic tests, and conditionally calls F-7b683909c5ac. A subsequent call to F-8801c242b41b requires both a nonzero record address from F-7b683909c5ac and a nonzero 32-bit field at byte offset 20 in that record.

Every iteration performs a signed 32-bit subtraction of the captured baseline from the classification **before testing baseline equality or reading any classification-control values**. This operation also occurs on below-baseline paths that later discard its result. Its overflow behavior is unresolved and can affect whether those paths reach their otherwise applicable acceptance tests.

The supplied representation has no normal return path, iteration limit, explicit delay, or error exit. After each completed iteration, execution resumes with another call to F-d8deec1d50bf.

These are static control-flow findings. Describing the function as an event loop, filter, or notification dispatcher is inferred intent rather than established application semantics.

## Behavior

### Per-iteration acquisition and unconditional arithmetic

Each iteration begins with a four-byte read at offset 4 from the captured context address. F-d8deec1d50bf is then called with three arguments, in these roles:

1. The just-read context field.
2. The address of the 28-byte local region.
3. The address of the separate four-byte local region.

No return value from this dependency is inspected.

Immediately after the dependency returns, the function reads the classification and computes the signed 32-bit difference:

**classification minus captured baseline**.

This computation precedes:

- The baseline-equality comparison.
- The decision between below-baseline and above-baseline processing.
- Every pivot, adjustment, decrement, match-value, or upper-limit read.

The computation is unconditional within a returning iteration. The equal and below-baseline paths do not use its result for their acceptance conditions, but that does not make the operation absent or exempt from overflow concerns. The above-baseline path uses this already-computed difference rather than introducing a subtraction only after selecting that path.

All arithmetic described below is represented as signed 32-bit arithmetic. Acceptance outcomes involving an out-of-range result remain conditional on the unresolved overflow semantics.

### Baseline equality

After the initial subtraction, a classification equal to the captured baseline is accepted.

No classification-control input is read on this path. The initial difference is zero and therefore does not overflow.

Throughout this contract, **accepted** means that F-7b683909c5ac is called. Acceptance does not itself guarantee a call to F-8801c242b41b.

### Below-baseline processing

For a classification signed-less-than the captured baseline:

1. Read the pivot and test equality.
2. Accept immediately if equal.
3. Otherwise, read the pivot again and test whether the classification is signed-less-than this second value.

The initial classification-minus-baseline result is no longer used on these paths. Nevertheless, its computation has already occurred.

#### Below the pivot

If the second pivot comparison places the classification below the pivot:

- Read the lower adjustment and add it to the classification.
- Accept if the result is zero.
- Otherwise, read the lower decrement and subtract it from that result.
- Accept if the new result is zero.
- Otherwise, read the lower match value and compare it with the twice-adjusted result.
- Accept on equality; reject on inequality.

The tests short-circuit. A zero after addition avoids the decrement and match-value reads. A zero after subtraction avoids the match-value read.

#### Not below the pivot

If pivot equality failed and the subsequent less-than comparison also failed:

- Read the pivot again and subtract it from the classification.
- Compare that difference with hexadecimal `0x3c24`, decimal 15,396.
- Accept if equal.
- Otherwise, perform another classification-minus-pivot subtraction using another fresh pivot read.
- Compare that difference with hexadecimal `0x5126`, decimal 20,774.
- Accept if equal; reject otherwise.

The second offset computation and comparison do not occur if the first comparison succeeds.

With stable pivot storage, this branch is reached only for a classification strictly above the pivot. With changing storage, the equality test, ordering test, and offset calculations need not use the same pivot value.

### Above-baseline processing

After baseline equality has failed, classifications not below the baseline take the above-baseline path. This path uses the difference computed immediately after F-d8deec1d50bf returned.

The acceptance tests are gated by two ordered conditions:

1. The difference must be unequal to a first upper-limit read.
2. If unequal, the difference must be signed-less-than a second upper-limit read.

Equality in the first comparison rejects the classification without the second read. Failure of the second comparison also rejects it.

For unchanged upper-limit storage, the gate requires the difference to be strictly less than the limit. The separate-read behavior remains part of the contract.

If the gate succeeds:

- Accept if the difference equals hexadecimal `0x10000`, decimal 65,536.
- Otherwise, read the upper adjustment and add it to the difference.
- Accept if the adjusted result is zero.
- Otherwise, accept if the adjusted result equals hexadecimal `0xffb4`, decimal 65,460.
- Reject any other result.

The literal match at 65,536 avoids reading the upper adjustment. A zero adjusted result avoids the final literal comparison.

The signed comparison of the original classification with the baseline does not establish that the 32-bit difference is representable. An above-baseline mathematical difference can exceed the maximum signed 32-bit value.

### Accepted-value processing

For each accepted classification, the function calls F-7b683909c5ac with no explicit arguments.

Its result is represented as 64 bits and separated into two 32-bit portions:

- The low portion is treated as a record address.
- The high portion initially supplies another integer value.

If the low portion is nonzero, the function reads the four-byte integer field at byte offset 20 from that address. This field replaces the high portion for the subsequent nonzero decision.

F-8801c242b41b is called only if:

- The low portion is nonzero; and
- The record field at offset 20 is nonzero.

Thus, a zero low portion suppresses both the record read and the final dependency call, regardless of the high portion. For a nonzero low portion, the record field—not the original high portion—determines whether the call proceeds. Any nonzero 32-bit field pattern passes; positivity is not required.

When the call proceeds, the function rereads the four-byte field at offset 4 from the captured context address and passes that freshly read value to F-8801c242b41b. It does not reuse the argument previously passed to F-d8deec1d50bf.

### Continuation and errors

Rejection returns control to the next iteration. Accepted-value processing also returns control to the next iteration after its applicable calls complete.

No classification is shown to terminate the function. No dependency return status is handled as an explicit error, and no retry limit or recovery branch is shown. Faults, non-returning dependencies, exceptions, and other transfers of control have no established handling in this function.

## Acceptance examples

These are conditional static examples, not executed tests. Unless a qualification says otherwise, dependencies return, accessed memory is valid, control values remain stable during the example, and **every executed arithmetic operation—including the unconditional initial subtraction—has a representable signed 32-bit result**.

1. **Baseline equality.** A classification equal to the captured baseline first produces an initial difference of zero, then is accepted. No pivot or other classification-control value is read.

2. **Pivot equality.** With baseline 100, classification 20, and pivot 20, the initial difference is −80. The below-baseline pivot equality accepts without lower adjustments or pivot-offset calculations.

3. **First lower zero.** With baseline 100, pivot 0, classification −20, and lower adjustment 20, the initial difference is −120. The lower addition produces zero and accepts without reading the lower decrement or lower match value.

4. **Second lower zero.** Under the same boundaries and classification, a lower adjustment of 25 gives 5. A lower decrement of 5 then gives zero and accepts without reading the lower match value.

5. **Lower final match.** With baseline 100, pivot 0, classification −20, lower adjustment 25, and lower decrement 2, the final lower result is 3. A lower match value of 3 accepts; 4 rejects.

6. **Pivot-relative offsets.** With baseline 30,000 and pivot 0, classifications 15,396 and 20,774 each accept through their respective offset comparisons. For 15,396, the second offset subtraction is skipped. The initial baseline differences are −14,604 and −9,226 respectively.

7. **Upper-limit equality rejects.** With baseline 0, classification 65,536, and upper limit 65,536, the initial difference equals the first limit read. The classification is rejected before the upper literal acceptance test or upper-adjustment read.

8. **Upper literal accepts.** With baseline 0, classification 65,536, and upper limit 70,000, the gate passes and the literal comparison accepts. The upper adjustment is not read.

9. **Upper adjusted acceptance.** With baseline 0, classification 100, and upper limit 200, an upper adjustment of −100 accepts through zero. An adjustment of 65,360 accepts through 65,460. An adjustment of zero rejects.

10. **Discarded difference still exposes overflow.** With baseline 2,147,483,647, classification −20, pivot 0, and lower adjustment 20, the mathematical initial difference is −2,147,483,667, outside signed 32-bit range. The later lower addition would yield zero without overflowing, but acceptance is **not established**: execution first encounters the unresolved initial subtraction. If the applicable arithmetic semantics allow execution to continue normally through that operation, the subsequent lower-path tests accept.

11. **Zero address suppresses dispatch.** After acceptance, a result from F-7b683909c5ac with a zero low portion causes no record read and no F-8801c242b41b call, even with a nonzero high portion.

12. **Record field gates dispatch.** After acceptance and a nonzero record address, an offset-20 field of zero suppresses F-8801c242b41b. Any nonzero 32-bit value permits the call.

13. **Fresh context-field argument.** If F-7b683909c5ac changes the captured context’s offset-4 field and its returned record permits dispatch, F-8801c242b41b receives the changed field value rather than the earlier acquisition argument.

The evidence does not establish whether overflow wraps, traps, invalidates execution assumptions, or is excluded by environmental invariants. No wider-arithmetic or modular-arithmetic interpretation is substituted. Overflow-sensitive examples therefore remain conditional.

Signedness matters independently of overflow. Replacing signed classification, pivot, difference, or limit comparisons with unsigned comparisons would define different behavior.
