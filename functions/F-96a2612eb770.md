## Behavior

It then writes the low eight bits of X to the address numerically equal to A plus `0x11`.

The visible addressing is significant:

- A is used as a numerical address component, not as an offset from the entry base.
- The store destination is in the inclusive range `0x11` through `0x110`.
- Only one byte is written.
- Higher bits of X do not affect this stored byte.

The lookup completes before the store. If the store aliases the lookup location, the selected A is still the byte read before the overwrite.

### 4. Second lookup and second store

After F-U07 returns, the routine computes a byte-lookup address from twice X plus one and reads one byte there. Denote this newly read unsigned byte by **B**.

Under the represented unsigned 32-bit arithmetic, this lookup address is:

**(2 × X + 1) modulo 2³².**

Consequences of that arithmetic include:

- The lookup address is always odd.
- Inputs that differ only in bit 31 produce the same lookup address.
- Large inputs wrap in the represented 32-bit arithmetic; no overflow check is shown.

Whether the actual instruction stream implements precisely that address arithmetic remains subject to the representation’s decoding uncertainty.

The routine writes a single byte to the address numerically equal to B plus `0x11`. The stored byte consists of bits 22 through 29 of X:

**floor(X / 2²²) modulo 256.**

Bits 30 and 31 do not survive conversion to the stored byte. Bits 0 through 21 do not contribute to this second stored value.

This second lookup occurs after the first seven calls. Its value must therefore be taken from memory at that point in the sequence. It must not be assumed to match an entry-time snapshot: the first store or any preceding dependency might have changed that location.

### Store-address boundaries
