# F-ec136ae63250

## Purpose

This contract characterizes the externally relevant behavior represented for F-ec136ae63250: condition-selected interrupt requests and coprocessor operations, followed by an invalid-instruction recovery boundary.

The evidence supports a contract for **selected operations and their relative order**, not a complete specification of machine execution. Instruction recovery encountered invalid data and stopped at the terminal boundary. Consequently, operation selection is distinguishable from successful delivery, completion, or continuation.

No application-level purpose is established. The sequence does not, by itself, establish exception recovery, deliberate termination, hardware initialization, or useful data processing.

The acceptance criteria below are conditional static expectations. They have not been exercised at runtime.

## Behavior

### Condition classes

Two independent questions determine the represented operation trace:

1. Is the zero condition true?
2. Are the negative and overflow conditions equal?

Interrupt activity is selected whenever the zero condition is true or the other two conditions differ. The load is selected whenever the negative and overflow conditions are equal.

These selections can overlap. A true zero condition does not suppress the load when the other two conditions are equal.

The source representation refers to the same incoming condition values throughout and contains no explicit updates to them. This establishes the represented selection rules. It does **not** establish that an interrupt handler or coprocessor operation preserves physical flags, registers, globals, or any other machine state.

## Side effects

### Observable ordering

The trace table establishes ordering between represented interactions, not completion ordering for all consequences of those interactions.

For example, where a load is selected between the interrupt groups, its represented invocation follows the sixth first-group request and precedes the first second-group request. This does not prove that asynchronous work initiated by an interrupt has completed before the load begins.

Within either interrupt group, each request follows the preceding request’s continuation. There is no represented batching, concurrency, retry, or local recovery.

### Reads and writes

The represented computation uses the condition inputs to select operations and uses the address base only for the selected load operand. It exposes no payload fields or ordinary memory-access sequence.

The first and last interrupt selections allow a true zero condition to determine the result without needing a comparison of the other two condition values. This is a property of the represented condition evaluation, not proof of a hardware status-register read sequence.

No explicit ordinary memory store, global assignment, allocation, release, or ownership transfer is shown. That observation does not establish memory or global-state preservation. F-D01 through F-D04 may have effects that are absent from the supplied representation.

For any load-related memory access, the evidence establishes neither the first actual address read nor the extent or order of subsequent accesses.

### Ownership and lifetime

None of the inputs is established as an owned allocation. Passing an opaque token does not establish transfer, borrowing, retention, or release.

If F-D03 accesses memory through its address operand, the necessary validity period, permissions, and accessible extent depend on semantics not supplied here. The caller’s exact memory obligations therefore remain documented only.

## Acceptance examples

All examples below are derived static expectations, not runtime results. Full traces assume continuation from every preceding selected interaction and an accurate recovered representation.

1. **Alternate path with load.** With a false zero condition and equal negative and overflow conditions, F-D02 is selected once with its five ordered operands. F-D03 follows once. Neither interrupt group is selected. Continued execution reaches F-D04.

2. **Interrupt path without load.** With a false zero condition and unequal negative and overflow conditions, six requests carry `0x1DDF1D`, followed by four carrying `0x1CDF1C`. F-D02 and F-D03 are absent from the selected trace.

3. **Overlapping interrupt and load selection.** With a true zero condition and equal negative and overflow conditions, the load occurs between the two interrupt groups. An interpretation that makes interrupt selection exclude the load is inconsistent with the represented behavior.

4. **True zero condition with unequal comparison inputs.** Both interrupt groups are selected, but the load is not. The zero condition does not independently enable F-D03.

5. **Ordinary address calculation.** With the load selected and a base of `0x1000`, the third F-D03 operand is `0x125C`, provided the arithmetic is representable. This expectation does not establish that the address is readable or aligned.

6. **Unselected invalid address.** If the negative and overflow conditions differ, the representation requires no F-D03 access, even when the base would be unsuitable for a load. Other dependency effects remain unconstrained.

7. **Early loss of continuation.** If the first interrupt request never resumes the represented sequence, none of the remaining nine requests, any intervening load, or F-D04 is required to occur.

8. **Multiplicity preservation.** Combining the six identical first-group requests into one request changes the specified interaction trace. Identical operands do not make repeated requests interchangeable with a single request.

9. **Arithmetic boundary.** If adding 604 exceeds the applicable integer range, neither a wrapped operand nor an overflow error is an established acceptance result. Resolving that case requires the missing arithmetic model.

10. **Noncanonical condition scalars.** The static comparison distinguishes equal from unequal negative and overflow values. It supplies no additional interpretation for noncanonical flag encodings and does not prove that such inputs are reachable.
