# F-c3d28e48088c

## Purpose

F-c3d28e48088c conditionally copies an eight-byte payload, represented as two adjacent four-byte units, from a source region to a destination region.

The destination address controls whether any payload access occurs. When the destination is null, the operation returns without reading the source. When the destination is non-null, the operation reads both source units and writes both destination units.

The first argument is unused in the supplied body. There is no result value, status report, validation, allocation, or cleanup operation.

This contract distinguishes behavior established by the supplied static representation from execution details that representation does not establish. No runtime tests have been performed.

| Second | Destination address | May be null. Otherwise identifies the beginning of two adjacent writable four-byte units. |

The operation returns no value. A caller cannot obtain success or failure through a return status.

For a non-null destination, normal completion requires:

## Behavior

### Null destination

If the destination is null, the operation performs no payload reads or writes and returns.

In particular:

- It does not inspect either source unit.
- It does not check whether the source is null.
- It does not use the first argument.
- It does not invoke a dependency or emit a diagnostic.

A null destination is therefore an established no-copy case, not a reported error.

### Non-null destination

For a non-null destination, the supplied representation establishes this memory-access sequence:

1. Read the source’s second four-byte unit, at offset 4, and retain its value.
2. Read the source’s first four-byte unit, at offset 0.
3. Write the first source value to the destination’s first unit, at offset 0.
4. Write the retained second source value to the destination’s second unit, at offset 4.
5. Return without a result value.

The source’s second unit is read before its first unit. Both source reads precede the first destination write.

On normal completion, the destination’s first unit contains the value obtained by the first-unit source read, and its second unit contains the value obtained by the earlier second-unit source read. With stable ordinary memory, these are the source’s two initial unit values.

There is no content-dependent branch. Zero values, all-bits-set values, and other four-byte patterns follow the same path.

### Overlap and aliasing

The body does not check for overlap and does not reject equal source and destination addresses.

For valid overlapping regions, under memory semantics that permit the accesses, both source values are read before either destination write. Consequently, the first destination write does not change the value used by the second destination write: that second value has already been retained.

If source and destination are identical, the operation still performs the represented reads and writes. It does not take a separate no-op branch. For stable ordinary memory, the final contents equal the initial contents.

If the regions overlap without being identical, the destination writes can also change bytes within the source region. There is no promise that the source remains unchanged. The relevant guarantee is the read-before-write ordering, subject to the validity and memory-model qualifications above.

### Addressing and arithmetic

The only nonzero payload offset is four bytes. The operation uses fixed-size accesses; it accepts no length, performs no loop, and does not calculate a caller-controlled transfer size.

There is no payload arithmetic, saturation, truncation, or numeric conversion. There is also no explicit address-overflow check. Supplying a non-null address does not establish that the following eight-byte region exists or can be accessed.

## Side effects

The explicit external side effects are the two destination writes on the non-null path.

For valid, disjoint, ordinary-memory regions, the body writes only the destination’s first and second four-byte units. It contains no explicit write before the destination or beyond its eight-byte payload.

The destination can alias other caller-visible state. For example, an address into shared or global storage causes that storage to be modified. The absence of an explicit global reference does not make such aliased storage immune to change.

### Ownership and lifetime

The body neither allocates nor releases memory. It contains no ownership-transfer operation and does not explicitly retain either address after returning.

The caller remains responsible for providing storage with a suitable lifetime and access permissions. The operation does not extend a storage lifetime, resize a region, or clear the source after copying.

### Errors and partial effects

There is no explicit error-return path, exception handler, rollback mechanism, or cleanup action.

A non-null destination combined with a null or otherwise invalid source is not a guarded no-copy case. The body attempts the second source-unit read first. The resulting machine fault, language-level consequence, or environmental response is not specified by the supplied material.

Likewise, destination writes are not validated in advance. The body provides no transactional guarantee. If an environment permits the first destination write to complete and then interrupts or rejects the second, the supplied representation contains no mechanism to restore the first unit.

The two-unit transfer is not established as atomic.

## Acceptance examples

These examples are conditional behavioral expectations derived from static evidence. They are not reports of executed tests.

### Null destination with an unusable source

Given a null destination, the source argument may be null or may fail to identify readable storage. The expected body behavior is to return without a source read and without a destination write.

This establishes source non-access for that branch; it does not establish how a calling environment handles constructing or passing unusual address values.

### Distinct, valid regions

Given a readable source containing first-unit value A and second-unit value B, and a disjoint writable destination, normal completion leaves the destination containing A followed by B.

The access sequence reads B before A, then writes A before B. The source is not explicitly written.

### Identical source and destination

Given one valid region used for both addresses, with stable values A and B, normal completion leaves those values unchanged.

Acceptance requires the represented reads and writes, not merely unchanged final bytes. Equal addresses do not select the null-destination branch.

### Destination one unit after the source

Suppose three consecutive valid units initially contain A, B, and C. The source begins at the first unit, and the destination begins at the second.

The operation reads B, then A, before writing anything. It then writes A to the second unit and B to the third. The resulting units are A, A, and B.

This distinguishes the represented behavior from a copy that reads the second source unit only after overwriting it.

### Destination one unit before the source

Suppose three consecutive valid units initially contain A, B, and C. The source begins at the second unit, and the destination begins at the first.

The operation reads C, then B, and writes B followed by C. The resulting units are B, C, and C.
