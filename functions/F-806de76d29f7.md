# F-806de76d29f7

## Purpose

F-806de76d29f7 performs seven extraction-and-conversion rounds using state initialized from a caller-supplied object. Each round produces a candidate and submits one four-byte portion of that candidate to a predicate dependency. A nonzero predicate result causes the candidate to be assigned into a temporary sequence.

After all seven rounds, retained candidates are assigned from that sequence to caller-object locations in reverse retention order. The destination order is exactly:

**+0x44, +0x3C, +0x34, +0x2C, +0x1C, +0x24, +0x14.**

Only as many destinations are visited as there are retained candidates. The nonmonotonic ordering of the fifth and sixth destinations is established behavior.

The function then invokes a dependency on the full temporary sequence and returns without an explicit result.

The apparent intent is to populate object fields from the most recent acceptable extracted values. “Extraction,” “conversion,” “assignment,” and “cleanup” describe call-site roles; they do not establish data formats, copying semantics, or resource ownership.

### Temporary-sequence initialization

1. The 56-byte sequence-region address.
2. The value just read from the initialization global.
3. 8.
4. 7.

Consequently, if state setup modifies the initialization global, this call receives its value after that modification, not its value at function entry.

Subsequent accesses use seven slots at an eight-byte stride. This is consistent with initialization of seven elements, but the dependency’s actual writes, ownership effects, and interpretation of its arguments remain unknown.

The retained count and round count are then set to zero.

### Seven extraction rounds

On the normal path, exactly seven rounds occur. Predicate rejection does not stop extraction, and no separate end-of-input condition is tested.

Each round has the following order:

1. **Extract:** F-f970f3b0ebd4 receives the eight-byte extraction-result region and the 24-byte state region.
2. **Convert:** F-8f8de12d7136 receives the candidate-area start and the extraction-result region.
3. **Read and test:** The function reads the four-byte scalar at candidate displacement +4 and passes its value to F-d8cbf9aa79a9.
4. **Conditionally retain:** If the predicate result is nonzero, F-46f0b3cb316e receives the next unused sequence-slot address as destination and the candidate-area start as source. The retained count increases after that call returns.
5. **Candidate cleanup:** F-289ec4311c64 receives the candidate-area start, regardless of whether retention occurred.
6. The round count increases.

Only zero versus nonzero matters. A negative nonzero predicate result takes the same branch as a positive result.

Retained candidates occupy consecutive slots in encounter order. Rejected rounds consume no slot. On normal completion, the retained count is between zero and seven inclusive, and retention destinations have byte offsets drawn from 0, 8, 16, 24, 32, 40, and 48.

The seven rounds finish before the function makes any explicit destination-assignment call into the caller’s object. This ordering does not exclude earlier object mutations through dependency side effects.

### Caller-object assignment

After extraction, retained sequence slots are selected in reverse order. The function performs the first applicable rows below, in table order:

| Retained count required | Destination | Source selection |
|---|---|---|
| At least 1 | Object +0x44 | Last retained slot |
| At least 2 | Object +0x3C | Second-last retained slot |
| At least 3 | Object +0x34 | Third-last retained slot |
| At least 4 | Object +0x2C | Fourth-last retained slot |
| At least 5 | Object +0x1C | Fifth-last retained slot |
| At least 6 | Object +0x24 | Sixth-last retained slot |
| Exactly 7 | Object +0x14 | Seventh-last retained slot |

Every row invokes F-46f0b3cb316e with destination first and source second.

Threshold checks and assignment calls are interleaved. After an assignment returns, the next threshold is checked before the next assignment. The function does not wait for seven retained candidates before making any assignments.

With no retained candidates, this phase makes no assignment calls. With fewer than seven, destinations beyond the applicable prefix receive no assignment call from this phase. That does not guarantee their entry values remain unchanged: dependencies may have other effects.

For a retained count between zero and seven, all selected slot indices are between zero and six. Threshold checks prevent selection of a negative slot index. Slot-offset multiplication produces values no greater than 48, so this bounded arithmetic does not require overflow or wraparound. Object-address additions still require valid address arithmetic; invalid addresses are not handled locally.

### Final sequence cleanup

After the extraction rounds and all applicable destination assignments, the function reads the cleanup global immediately before calling F-251368e8a842. Its arguments are:

1. The temporary-sequence address.
2. 7.
3. 8.
4. The value just read from the cleanup global.

This is a read of a different global from the initialization global. It is not a reuse of the earlier argument.

Any earlier dependency may have modified the cleanup global. The final argument therefore reflects that global’s value at this late read point, including changes made during initialization, extraction, candidate cleanup, or destination assignment.

Cleanup is requested for the full seven-slot sequence, even when fewer than seven candidates were retained. No subsequent explicit cleanup call is shown for the state or extraction-result regions.

## Side effects

### Observable ordering

On normal completion, the ordering is:

1. State setup.
2. Initialization-global read.
3. Temporary-sequence initialization.
4. Seven ordered extraction, conversion, predicate, optional retention, and candidate-cleanup rounds.
5. Zero through seven caller-object assignment calls.
6. Cleanup-global read.
7. Full-sequence cleanup.

Each candidate-cleanup call follows that round’s optional retention and precedes the next extraction. Final sequence cleanup follows every destination assignment.

The two global reads occur at different execution points. They must not be modeled as values captured together at entry. This timing matters even in a single-threaded environment because dependencies may modify either global.

### Mutation and ownership

Dependencies receive addresses of mutable local regions and, for destination assignment, caller-object locations. The function itself visibly updates its counters; the supplied body does not expose the memory operations performed inside dependencies.

F-46f0b3cb316e is used both for candidate retention and for caller-object assignment. Its behavior could involve copying, moving, reference management, or other mutation; none is established by this call site alone.

Candidate cleanup follows retention, and full-sequence cleanup follows caller-object assignment. Correct resource lifetimes would require compatible dependency semantics, but the call pattern does not prove those semantics.

Likewise, the values loaded from the two globals do not establish ownership transfer, callback invocation, descriptor interpretation, or release responsibility. Dependencies are not assumed to preserve either global. Distinct global storage locations also do not prove that their stored values differ or refer to separate resources.

### Errors and abnormal exits

There is no visible input validation, explicit error return, rollback, or recovery branch. A zero predicate result is ordinary filtering.

Only the predicate return value controls a branch. Other dependency return values are not used to decide whether processing continues.

If a dependency does not return normally, later calls and reads are not guaranteed. For example, failure during destination assignment can prevent the cleanup-global read and final cleanup. Earlier completed assignments are not rolled back.

The sequence of object updates is not transactional.
