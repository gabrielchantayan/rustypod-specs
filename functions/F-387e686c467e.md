# F-387e686c467e

## Purpose

F-387e686c467e accepts two operands represented by pairs of 32-bit words and produces a 64-bit result bit pattern.

**Inferred intent:** software floating-point subtraction, with operand order B minus A. The sign manipulation, high-word field boundaries, alignment, normalization, and rounding resemble arithmetic on binary64 encodings.

**Established limitation:** the supplied static representation does not establish the values of the external masks and result words. It also contains unresolved indirect transfers. This contract therefore does not promise IEEE 754 subtraction for all inputs, gradual underflow, standard exceptional-value propagation, or a particular floating-point exception model.

The word-level behavior and conditional read ordering below take precedence over the inferred floating-point interpretation.

## Behavior

### Initial classification

For each operand, classification adds `0x00100000` to its high word, doubles the result at 32-bit width, and tests intersection with G1.

The A test occurs first. If its intersection is zero, exceptional handling begins without evaluating the B test. Otherwise, B is tested using a separate G1 reference. The main arithmetic path is reached only if both tested intersections are nonzero.

This is not unconditionally equivalent to “both inputs are normal finite numbers.” That interpretation requires an external mask value not supplied here.

### Exceptional and boundary results

Exceptional handling obtains a further G1 value and sets bit `0x00200000` in it. Call that resulting mask K. K is a working value for the following decisions; it need not equal a mask reconstructed from an earlier G1 observation.

First consider the doubled original high word of each operand, at 32-bit width. The first subcase applies when K contains at least one bit absent from B’s doubled high word and at least one bit absent from A’s doubled high word.

Result precedence within this subcase is:

1. If K intersects B’s doubled high word, return B unchanged.
2. Otherwise, if K intersects A’s doubled high word, return A with bit 63 inverted.
3. Otherwise, return negative zero only when B is exactly `0x8000000000000000` and A is not that exact pattern. Return positive zero in every other case.

Thus B selection takes precedence even when both operands satisfy their respective intersection tests.

If the first subcase does not apply, form a summary for each operand: double its original high word and add one if its low word is nonzero, all at 32-bit width.

If both summaries are unsigned-less-than-or-equal to K:

- Equal summaries and opposite original sign bits return B-high above a zero low word.
- Equal summaries and matching original sign bits return G3 above low word `0x00000001`.
- Unequal summaries return B-high above zero when B’s summary equals `0xFFE00000`.
- Other unequal-summary cases return A-high with its top bit inverted, above zero.

Summary equality is not operand equality: the low word contributes only a zero-versus-nonzero distinction.

If either summary exceeds K, execution enters indirect exceptional handling.

| 8 | Bit `0x40` clear; bit `0x10` set | `0`, G7 |

The transformed mode-9 word is obtained from a fresh G2 reference by shifting left 15, complementing the 32-bit result, and shifting left once more. The status-bearing word is `0x30000000` with the incoming status bit placed at bit 27.

**Mode-8 reads precede final argument selection.** When bit `0x40` is clear, G6 is read first and G4 second. Only then is bit `0x10` tested through G2. If that bit is set, the saved G6 and G4 values are discarded, the first argument becomes zero, and a G7 read supplies the second argument. Selecting `(0, G7)` therefore does not eliminate the preceding G6 and G4 reads.

The destination is derived from the incoming return link by clearing its bottom two bits. The visible argument lists do not establish a complete calling convention, exclude additional live inputs, or establish that the destination is a conventional function.

### Main arithmetic selection and alignment

The main path inverts A’s sign bit. Matching original signs select a magnitude-difference path; differing original signs select a magnitude-sum path. This is the principal evidence for B minus A.

Both paths may exchange their working operand representations. The selection uses unsigned word comparisons, low-word subtraction, and explicit carry or borrow relationships. It must not be replaced without justification by signed comparison of packed operands.

Working high words are separated at bit 20. Alignment operates across the two 32-bit words and retains additional discarded-bit information for rounding.

The two arithmetic paths have distinct G1 uses:

- **Matching original signs:** G1 is referenced again in constructing the aligned negative contribution. Signed arithmetic right shift by two supplies both an arithmetic term and, through complementation of another such reference, a mask applied to the smaller working high word. The representation contains separate references within this construction; their relative machine-load ordering is not established.
- **Differing original signs:** a separate G1 reference is interpreted as signed and shifted right by one. Its complement masks the smaller working high word before bit `0x00100000` is inserted as an implicit significand bit.

These are arithmetic dependencies on G1, not merely repeated classification checks.

### Magnitude-difference path

This path combines a dominant working operand with an aligned negative contribution.

For exponent-like gaps through 32, the contribution is assembled across both words, including carry propagation. Larger gaps use a separate alignment and discarded-information representation. In that larger-gap path, an original gap of 62 or more returns the reconstructed dominant operand directly.

A negative combined high intermediate enters cancellation handling. That handling can:

- Shift the combined value left by one and use an additional discarded bit.
- Round a reconstructed result, including tie handling.
- Shift back right in a boundary case.
- Normalize using leading-zero counts across the high and low words.
- Return a result containing only a low word.
- Return positive zero.

For leading-zero normalization, a zero high word causes the low word to determine the remaining count. The exponent-like adjustment accounts for both the normalization distance and a masked exponent-like field. If the resulting signed adjustment is negative, the result is positive zero.

Another boundary path returns a nonzero reconstructed pair only when twice its candidate high word is unsigned-greater-than `0x001FFFFF`; otherwise that nonzero candidate is replaced by positive zero.

These explicit zero exits prevent a general promise of gradual underflow or preservation of every mathematically nonzero tiny difference.

When cancellation handling is unnecessary, discarded information determines whether the retained pair is returned unchanged or rounded.

### Magnitude-sum path

This path adds aligned magnitudes. A carry beyond the retained high fraction region triggers one-bit right normalization and exponent-like reconstruction.

For gaps through 32, alignment contributes to both words with explicit carries. Larger gaps use a separate construction that preserves a nonzero summary of the smaller low word. At sufficiently large gaps, the direct high-word addition is omitted, but the remaining discarded-information processing must not be assumed irrelevant.

The bit removed by right normalization participates in rounding. Additional information from the smaller operand distinguishes a tie from a value beyond the tie.

At the visible overflow-result exits, twice the candidate high word is compared, at 32-bit width, with `0xFFE00000`:

- Below the threshold, return the candidate high and low words.
- Otherwise, construct a result whose low word is zero and whose upper word comes from G5.

For each such overflow construction, G5 is read **before** the sign test. If the sign-setting branch is taken, G5 is referenced **again**, and bit `0x80000000` is set in that later value. The first value is then discarded. The two references are not established to observe the same value.

The sign test is a signed test of an address-like expression involving the candidate high word and a fixed base. Its meaning is unresolved. The result must not be simplified unconditionally to signed infinity.

### Rounding

Several branches establish the following retained-word behavior:

- Discarded information can leave the retained pair unchanged.
- An increment affects the retained low word first.
- Low-word wraparound carries into the high word.
- A detected exact tie clears the retained least-significant bit after the increment, selecting an even result.

This supports round-to-nearest, ties-to-even on those branches. It does not establish one universal rounding mode across all exceptional, underflow, overflow, and shift-boundary cases.

## Acceptance examples

These are conditional static acceptance criteria. No runtime tests have been performed.

### Exceptional selection precedence

If exceptional handling reaches the first subcase and K intersects both doubled high words, the result is B unchanged. Returning sign-inverted A violates the selection order.

### Narrow negative-zero result

If that subcase reaches its final zero selection:

- B equal to negative zero and A unequal to negative zero produces negative zero.
- Both operands equal to negative zero produce positive zero.
- Any other B produces positive zero.

These are branch-conditional criteria, not classifications of arbitrary inputs.

### Summary equality

If the first subcase is bypassed, both summaries are at most K, and the summaries are equal:

- Matching original signs select G3 above `0x00000001`.
- Opposite original signs select B-high above zero.

Different nonzero low words do not defeat summary equality.

### Mode-8 discarded reads

Suppose mode 8 is selected, the later bit-`0x40` test is clear, and the bit-`0x10` test is set.

The required source-level sequence includes reading G6, reading G4, testing bit `0x10`, and then reading G7. The visible arguments are `(0, G7)`. A description that omits the G6 and G4 reads is incorrect even though their values are not passed.

If bit `0x10` is instead clear, the arguments use the previously obtained G6 and G4 values.

### Overflow reread

Suppose an overflow-result exit reads value X from G5 and then takes the sign-setting branch. If the subsequent G5 reference supplies Y, the result’s upper word is Y with its sign bit set, not necessarily X with its sign bit set. The lower word is zero.

If the sign-setting branch is not taken, the initial G5 value supplies the upper word.

### Rounding carry and cancellation

On a rounding branch that increments retained low word `0xFFFFFFFF`, wraparound must propagate into the retained high word.

If cancellation normalization reaches its negative adjusted-exponent branch, the result is positive zero. Requiring a nonzero subnormal result on that branch contradicts the visible behavior.
