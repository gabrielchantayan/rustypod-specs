# F-99e0d644698f

## Purpose

F-99e0d644698f processes selected object fields in ascending field-number order, using acquired working storage. Each selected field produces dependency calls and, in some cases, direct stores. A construction dependency receives the resulting record description; its nonzero result is passed to a submission dependency. Indexed fields and chunked content can produce multiple construction/submission attempts.

“Record,” “snapshot,” “byte sequence,” and “chunk” describe inferred roles. Established behavior consists of visible accesses, call arguments, ordering, arithmetic, branches, and status handling. Dependency bodies are unavailable; apparent roles do not establish copying, clearing, serialization, delivery, or ownership effects.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

F-b37968c9f644 receives the environment result plus four and the externally read word. F-1a836ac93559 then receives the preparation result and 4; its result supplies the working capacity.

F-fab3799b3190 is called next. Zero returns status 3 immediately. A nonzero result supplies the working address. The object’s method at table offset 12 is then called once to obtain a 64-bit value, called the **snapshot**.

Preparation therefore occurs even for an admitted empty mask and before acquisition failure is known.

## Acceptance examples

These are conditional static expectations, not executed tests. Returning examples require valid accessed storage and returning callees.

1. **Empty selection:** Selector 65, zero mask, nonzero admission, and nonzero acquisition produce one snapshot query and 28 field-temporary initialization/cleanup pairs, no construction calls, and status zero.

2. **Admission rejection:** Zero mask and zero admission invoke F-a817d8d58c10 before preparation.

3. **Selected unsupported selector:** Selector 64 with a selected field reaches field-temporary initialization and the clear-role call before selector failure. Field-specific querying and ordinary field cleanup are not reached.

4. **Field-zero argument order:** Selector 67 passes context, 66, and object to F-594bf962780e in that order. Selector 65 substitutes 68.

5. **Field 6 layout:** Selector 65 places the field byte at offset 4 and calls the payload writer at offset 5. Ordinary construction receives length nine if the cursor check passes.

6. **Narrowing versus rejection:** Query result 65,537 becomes writer argument 1 for field 8 but invokes failure for field 22.

7. **Repeated final query:** Field 9 with count one queries index zero twice. Distinct results become successive writer arguments.

8. **Limited append:** Narrowed length eight and available space five produce copy-role and post-copy calls with count five, then a five-byte cursor advance.

9. **Oversized chunk source:** A matching field-11 path with length greater than available space calls F-d7be9cfb4000, then F-44362605ab79 on the additional temporary, before any loop header writes. Intermediate copies use that source and its count-based advances.

10. **Chunk bound zero:** If the oversized branch receives bound zero, source acquisition still occurs. The sole iteration calls F-151ab4bfe553 with the unadvanced source; no intermediate copy or submission occurs.

11. **Unchecked service:** A null service result is dereferenced, not treated as optional absence. A null candidate instead bypasses matching-content processing.

12. **Maximum bound and cleanup:** A maximum unsigned chunk bound with returning callees causes repeated counter wraps. Neither temporary cleanup nor normal return is reached.

13. **Ordinary submission failure:** Outside the continuing chunk loop, nonzero submission records status 2, cleans up the current field temporary, skips later fields, and reaches final working-address handoff.
