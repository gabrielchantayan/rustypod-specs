## Behavior

The working result and numerous arithmetic and state slots are initialized to zero. Additional global reads initialize four saved state words, followed by the initial dispatch state. Their visible read order is:

1. The entry-only state-seed capture.
2. The first saved state seed.
3. The second saved state seed.
4. The third saved state seed.
5. The fourth saved state seed.
6. The initial dispatch state.

Every dispatch-loop condition then performs these captures, in order:

1. Current A.
2. Current B.
3. Current M.
4. A read of T for the unsigned state-difference test.

An unsigned difference greater than 9 selects the out-of-range action. Otherwise, the routine reads D and logically halves it **before selecting the in-range action**. This preparation occurs even when the selected action returns immediately.

The in-range selection expression reads T again. Consequently, the condition test and subsequent selection are separate base reads. The representation supplies no default action for an out-of-range selection produced by that second read; the actual consequences of inconsistent base reads require machine-level resolution.

With stable T across these two reads, differences 0 through 9 select their correspondingly numbered actions. Return occurs only through action 2. There is no visible iteration bound.

## Acceptance examples

These are conditional static compatibility examples, not executed tests.

1. **Immediate return.** If initialization and stable dispatch-base reads select action 2, the result is zero. No dependency executes, but dispatch captures and the D-halving read still occur.

2. **Normalized action 0 selection.** If the signed shifted expression yields negative one, negation yields one and selects the state alternative weighted by that bit. A zero shifted result selects the other alternative. Treating negative one itself as the selector changes behavior.

3. **Input reduction.** If action 6’s second-input product has low 16 bits equal to one—for example, product 65,537 where the arithmetic interpretation permits it—the working result becomes one. The separately reduced first input is not substituted.

4. **Persistent entry capture.** If a dependency changes the global backing the entry seed before a later action 6 execution, action 6 still uses the entry-captured value.

5. **Pre-call versus post-call multipliers.** If action 9’s dependency changes M, P, and Q, result arithmetic uses the dispatch-captured M but the subsequently read P and Q.

6. **Action 4 factor retention.** If its dependency changes D, the secondary-result multiplier remains the half value captured before the call.

7. **Out-of-range capture retention.** If its numeric dependency changes A and B, subsequent arithmetic still uses their dispatch captures. The later call-offset read remains post-call.

8. **Inter-call mutation.** If action 6’s first dependency changes globals supplying its intervening state loads, those loads use the later reads. Its final exclusive-or operand is read after the second call.

9. **Unmasked return.** If action 5 loads Q above 65,535 and action 2 follows without replacing the result, the full loaded word is returned.

10. **Dispatch boundaries.** With a stable base, unsigned differences 9, 10, and \(2^{32}-1\) select action 9, the out-of-range action, and the out-of-range action respectively.

11. **No guaranteed progress.** Constants and secondary results that continually select non-returning actions need not produce a return; no watchdog is visible.
