# F-10ec51e16937

## Purpose

The supplied static representation describes a nonterminating sequence of indirect calls, byte accesses, and 32-bit word accesses. It repeatedly transforms values returned by unresolved dependencies into addresses, stored values, and subsequent call arguments.

A higher-level purpose—such as initialization, allocation, interpretation, or device control—is not established. The repeated offsets and shifts do not by themselves establish an object format or ownership protocol.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional interpretation:** the resulting behavior under a 32-bit, wrapping machine-arithmetic interpretation.
- **Unknown behavior:** dependency effects, execution validity, and details not recoverable from the supplied material.

The representation has no normal exit. Completing an iteration returns execution to the beginning of the sequence, with selected state replaced by values computed near the end of that iteration.

## Interface

### Explicit inputs and output

The represented interface has four 32-bit input slots:

| Input | Represented use |
|---|---|
| First | No explicit use in the displayed body. |
| Second | No explicit use in the displayed body. |
| Third | Supplies shifted word values and call arguments until replaced near the end of an iteration. |
| Fourth | Passed to an early dependency, then replaced near the end of an iteration. |

The first two slots are not proven irrelevant to the actual executable: unresolved calls and an incompletely recovered calling convention prevent that stronger conclusion.

The represented return type is void, but no return is reachable in the displayed control flow. There is no established result value, success flag, or error code.

### Additional execution state

The body also depends on:

- An incoming address base, called **the base** below.
- An incoming payload, of which initially only its low byte is stored.
- Incoming control-link state used to derive the first indirect-call target.
- A readable global word, sampled once early in every iteration.
- An additional register result consumed later as a dependency argument without an explicit producer assignment in the representation.

These are material preconditions, not additional fully recovered public parameters.

### Width and notation

For the conditional 32-bit interpretation:

- \(W(x)\) means retain the low 32 bits.
- \(L(x,n)=W(x\,2^n)\).
- \(\operatorname{byte}(x)\) means retain the low 8 bits.
- \(\operatorname{low}(x)\) and \(\operatorname{high}(x)\) select the two 32-bit halves of a represented 64-bit result.
- Address arithmetic is reduced to 32 bits.
- A word access transfers 32 bits; a byte access transfers 8 bits.

The notation describes bit-vector behavior, not signed-language overflow rules. Some displayed expressions use signed integer types, so executable confirmation is required before treating wrapping arithmetic as an unconditional platform guarantee.

A **selector write at base \(b\)** means:

1. Read one unsigned byte at \(W(b+1)\).
2. Zero-extend that byte to obtain an address component.
3. Write one byte at that component plus 17.

Consequently, the destination of a selector write lies between addresses 17 and 272. This is an absolute address calculation in the representation, not a pointer-sized load or an offset from \(b\).

## Side effects

The explicit effects comprise:

- Ordered indirect dependency invocations.
- Byte reads used as absolute-address selectors.
- Byte and word stores described above.
- One early global-word read per iteration.
- One late indexed word read per iteration.
- Replacement of loop-carried execution state.

The representation contains no bounds checks, null checks, alignment checks, rollback, exception handling, or explicit error branch. No particular reaction to an invalid access or invalid call target is established.

Repeated stores must not be collapsed merely because their values match. Dependencies intervene, destinations may change, and addresses may denote observable memory.

No allocation, release, reference-count operation, or ownership transfer is explicitly identifiable. A dependency may perform any of these, but the supplied material does not establish that behavior.

## Dependencies

All F-D01.1 through F-D27.4 identifiers used above are opaque labels for unresolved call sites. Group lengths are defined by the behavior section; identifiers beyond a group’s stated length do not exist in this contract.

Their established interface information is limited to:

- Invocation order.
- Explicitly represented arguments.
- Selected 32-bit results.
- Selected results represented as two 32-bit halves.
- The additional incompletely recovered register result used in phase 5.

The targets are computed indirectly. Their identities, signatures, termination, memory effects, and preservation guarantees are unknown. Different call-site IDs may resolve to the same function.

A dependency that does not return prevents later operations from occurring. A dependency that changes memory can affect subsequent fresh reads, including selector reads, the global snapshot in a later iteration, and the indexed word read.

## Acceptance examples

These examples are conditional static checks, not executed tests.

1. **Retained selector versus fresh selector.** If the initial selector byte is 7, the first payload byte is written at address 24. Even if F-D02 changes that selector byte, the following input-derived word store remains at address 27, because it uses the retained value 7.

2. **Shifted third input.** If the current third input is 3, its early word contribution is 12. Its phase-5 argument is \(3\,2^{28}\), under the 32-bit interpretation.

3. **Global snapshot.** If the sampled global word is \(2^{22}\), phase 2 writes byte value 1. A dependency changing the global after the snapshot does not alter this explicitly retained contribution.

4. **Masked extraction followed by byte truncation.** If a phase-4 stored value is \(2^{29}\), masked extraction produces 512, but the selector write stores byte value zero.

5. **Wide result ordering.** When a dependency supplies distinct low and high halves, a subsequent two-half forwarding call receives low first and high second. Calls explicitly receiving only the high half must not substitute the low half.

6. **Restricted replacement base.** If \(u\) is 5, \(B=2^{30}\) under wrapping arithmetic. The direct clears target \(2^{30}+17\), then \(2^{30}+1\). They do not use selector indirection.

7. **Late sign-bit store.** An even retained \(w\) produces zero; an odd retained \(w\) produces \(2^{31}\), independently of its other bits.

8. **Fresh read after clearing.** If a dependency changes the byte at \(B+1\) to 9 after the direct clears, the final selector write targets address 26, not address 17.

9. **No normal completion.** If every dependency returns and every access succeeds, finishing phase 10 starts another iteration rather than returning to the caller.

## Uncertainties

The following remain **documented_only**:

- Actual executable reachability and correctness of the recovered control flow.
- The removed unreachable region mentioned in the supplied material.
- Exact calling convention, hidden-input initialization, and register preservation.
- Actual identities and behavior of every indirect dependency.
- Whether represented 64-bit results are semantic 64-bit values or paired register outputs.
- The producer and meaning of the extra register-derived argument.
- Address-space validity, byte order, alignment requirements, and access-fault behavior.
- Volatile, device-memory, concurrency, or atomicity semantics.
- Global storage aliasing; the supplied material warns that global symbols overlap.
- Ownership, lifetime, allocation, and release responsibilities.
- A platform-level guarantee of 32-bit wrapping for every displayed signed expression.

The low selector-derived addresses and repeated control transfers are observations, not proof of a particular runtime design.
