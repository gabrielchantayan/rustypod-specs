# F-5e31366444c1

## Purpose

F-5e31366444c1 conditionally dispatches an operation through an object-associated function, optionally surrounding that dispatch with calls to a captured interceptor.

The established behavior has three principal outcomes:

- Reject an initially absent object, descriptor, or operation target by reporting a diagnostic and returning −2.
- Allow an interceptor to stop the operation by returning a signed value less than 1.
- If the object’s dispatch gate is nonzero, invoke the operation target and optionally let the interceptor replace its result.

A zero dispatch gate produces a different diagnostic and returns −2. When an interceptor exists, this gate is checked only after the interceptor has accepted the operation.

“Object,” “descriptor,” “interceptor,” and “dispatch gate” are descriptive labels for observed storage and call roles. They do not establish application-level semantics.

## Interface

### Inputs

The function receives four arguments:

| Position | Contract |
|---|---|
| 1 | A nullable pointer to an object containing the fields described below. |
| 2 | An opaque 32-bit value forwarded to indirect calls. |
| 3 | An opaque 32-bit value forwarded to indirect calls and, on the no-interceptor path, duplicated into another argument position. |
| 4 | An opaque 32-bit value forwarded to the operation target only when no interceptor is present. With an interceptor, that target argument is replaced by the 32-bit value 1. |

The observed representation is a 32-bit address and word model. Null and zero checks test whether all bits are zero. No signed interpretation of arguments 2–4 is established.

### Object layout

The following byte offsets are relevant:

| Offset | Width | Observed use |
|---|---:|---|
| +0 | 32 bits | Descriptor address. |
| +4 | 32 bits | Nullable interceptor function address. |
| +12 | 32 bits | Dispatch gate; zero prevents dispatch, any nonzero value permits it. |

The descriptor contains an operation function address at byte offset +20, also occupying 32 bits.

No meaning is established for intervening fields. In particular, this function does not directly access the object field at offset +8.

### Return value

The return value is a signed 32-bit integer:

- −2 after either locally selected diagnostic path, provided the diagnostic dependency returns normally.
- The interceptor’s result if its preliminary call returns less than 1.
- The operation target’s result when there is no interceptor.
- The interceptor’s final result when the target runs with an interceptor present.

Results from indirect calls are not normalized, clamped, or mapped into a documented status enumeration. A returned −2 does not by itself prove that this function emitted a diagnostic: an indirect callee can also return −2.

### Preconditions

A null first argument is explicitly handled. Other pointer failures are not.

Every nonzero data address actually dereferenced must designate readable storage of the required width. Every indirect function address actually invoked must designate a callable function compatible with the observed call shape.

The initial checks do not establish that pointers are valid, aligned, live, or stable. They also do not protect against an interceptor changing the object or descriptor before dispatch.

## Behavior

### 1. Initial eligibility checks

The function first tests whether the object pointer is null.

If it is nonnull, the function reads the descriptor address at object offset +0. If that address is nonzero, it reads the operation address at descriptor offset +20.

Initial eligibility requires all three of the following:

1. A nonnull object pointer.
2. A nonzero descriptor address read from the object.
3. A nonzero operation address read from that descriptor.

These reads are conditional:

- A null object pointer causes no object-field read.
- A zero descriptor address causes no descriptor-field read.
- Failure of any initial eligibility condition prevents both interceptor invocation and gate inspection.

On initial ineligibility, the function invokes F-4fc89ec41a6d with five 32-bit arguments, in order:

| Position | Value |
|---|---:|
| 1 | 32 |
| 2 | 104 |
| 3 | 121 |
| 4 | 0 |
| 5 | 0 |

If that call returns normally, F-5e31366444c1 returns −2. The dependency’s return value, if any, is not used.

### 2. Interceptor capture and preliminary call

After initial eligibility succeeds, the function reads the interceptor address from object offset +4 and retains that address for the rest of this invocation.

If the captured address is zero, no interceptor call occurs.

If it is nonzero, the function invokes that address with six arguments:

| Position | Value |
|---|---|
| 1 | Original object pointer |
| 2 | 5 |
| 3 | Original argument 2 |
| 4 | Original argument 3 |
| 5 | 0 |
| 6 | 1 |

The returned value is tested as a signed 32-bit integer.

- A result less than 1 is returned immediately.
- A result of 1 or greater permits processing to continue.

The comparison is not a zero-only rejection: negative values also stop processing. On this early-return path, the function does not inspect the dispatch gate, call the operation target, issue its own diagnostic, or make a final interceptor call.

For an invocation with a nonzero captured interceptor, the eventual operation target’s fifth argument is 0 and its sixth argument is 1. Those values do not depend on the interceptor’s positive result or on original argument 4.

The interceptor address is not recaptured after the preliminary call. If that call modifies the object’s interceptor field, a later final interceptor call still uses the originally captured address.

### 3. Dispatch-gate check

After the preliminary interceptor call has returned a positive result—or immediately after capturing a zero interceptor address—the function reads the 32-bit gate at object offset +12.

If the gate is zero, the function invokes F-4fc89ec41a6d with:

| Position | Value |
|---|---:|
| 1 | 32 |
| 2 | 104 |
| 3 | 120 |
| 4 | 0 |
| 5 | 0 |

If that dependency returns normally, the function returns −2.

No final interceptor call occurs on this path, even if the preliminary interceptor call succeeded.

Any nonzero gate permits dispatch, including a bit pattern that would be negative if interpreted as a signed integer. If an interceptor ran, this check observes the gate after that call, not a value saved before it.

### 4. Operation dispatch

When the gate is nonzero, the function resolves the operation address again through the object’s current descriptor.

This is not guaranteed to be the same descriptor or operation address that passed the initial eligibility check. In particular, a preliminary interceptor can change the object before this resolution. There is no second null check for the descriptor or operation address.

The operation call receives six arguments:

| Position | Without interceptor | With interceptor |
|---|---|---|
| 1 | Original object pointer | Original object pointer |
| 2 | Original argument 2 | Original argument 2 |
| 3 | Original argument 3 | Original argument 3 |
| 4 | Operation address obtained through the current descriptor | Operation address obtained through the current descriptor |
| 5 | Original argument 3 | 0 |
| 6 | Original argument 4 | 1 |

The fourth argument is a function-address value, not a descriptor address or the interceptor address.

The supplied representation separately expresses the operation address used as the call target and the operation address supplied as argument 4. It does not establish an exact read order or guarantee a single shared load. Under stable storage, both denote the operation address at the current descriptor’s offset +20. Behavior under concurrent mutation is not established.

### 5. Result handling

Without an interceptor, the function returns the operation result unchanged.

With an interceptor, the function calls the previously captured interceptor address again, using:

| Position | Value |
|---|---|
| 1 | Original object pointer |
| 2 | 133 |
| 3 | Original argument 2 |
| 4 | Original argument 3 |
| 5 | 0 |
| 6 | Operation result |

The function returns this final interceptor result unchanged.

There is no sign check on the operation result before the final interceptor call and no sign check on the final interceptor result before returning it. A negative or zero operation result still reaches the final interceptor if the target returned normally.

## Side effects

### Direct effects

The function directly performs conditional reads from the object and descriptor and invokes external functions. The supplied evidence contains no direct stores to object fields, descriptor fields, or other caller-visible memory.

Its local argument substitutions do not modify the caller’s argument storage.

### Effects through dependencies

The interceptor and operation target receive the object pointer. Their effects on that object, other memory, global state, resources, and control flow are unknown.

F-4fc89ec41a6d may have diagnostic or other effects, but only its argument tuples and invocation conditions are established here.

The function does not directly allocate or release memory. This does not establish that its callees avoid allocation or release. Nor does it establish that the object remains live after an indirect call.

### Observable ordering

For normal returns and valid accesses, the established high-level order is:

1. Initial object, descriptor, and operation eligibility checks.
2. Interceptor-address capture.
3. Optional preliminary interceptor call.
4. Gate read, unless the preliminary call stopped processing.
5. Either diagnostic reporting or operation dispatch.
6. Optional final interceptor call, only after operation dispatch returns.
7. Return.

No additional ordering among expression-internal operation-address reads is established.

## Acceptance examples

These examples are conditional on valid storage, compatible callees, and normal returns from all calls reached.

1. **Null object.** With a null first argument, the only dependency call is F-4fc89ec41a6d with `(32, 104, 121, 0, 0)`. The function returns −2.

2. **Absent descriptor or initial operation.** A nonnull object with a zero descriptor, or a readable descriptor with a zero operation address, takes the same diagnostic path. Neither the interceptor field nor the gate is inspected.

3. **Preliminary interceptor returns zero.** Given initial eligibility and a nonzero interceptor address, a preliminary result of zero is returned immediately. A zero gate does not cause a diagnostic because the gate is never reached.

4. **Preliminary interceptor returns a negative value.** A preliminary result of −7 produces a return value of −7, with no operation or final interceptor call.

5. **Accepted interception followed by a zero gate.** If the preliminary interceptor returns 2 and the subsequently read gate is zero, the diagnostic arguments are `(32, 104, 120, 0, 0)`. The function returns −2 without a final interceptor call.

6. **Dispatch without interception.** Suppose the gate is nonzero and the interceptor address is zero. The target receives original argument 3 in both positions 3 and 5, and original argument 4 in position 6. If it returns −9, the function returns −9.

7. **Dispatch with interception.** If the preliminary interceptor accepts, the target receives 0 and 1 in positions 5 and 6. If the target returns −9 and the final interceptor returns 12, the function returns 12.

8. **Interceptor replacement during the preliminary call.** If the preliminary interceptor changes the stored interceptor address, the final interceptor call nevertheless uses the address captured before that change.

9. **Gate mutation during the preliminary call.** If the interceptor changes a valid object’s gate from zero to nonzero and returns positively, dispatch proceeds. If it changes the gate to zero, the zero-gate diagnostic path is selected.

10. **Descriptor replacement during the preliminary call.** If the interceptor installs a different valid descriptor and operation address, dispatch resolves through that current descriptor. The initially checked operation is not a frozen dispatch choice.
