## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Zero third input.** Arguments derived solely by shifting a zero third input are zero. Dependency invocations are still required; later memory contents remain dependent on implicit inputs.

2. **Small-index boundary.** Under 32-bit bit-vector shifts, an index-producing result with low seven bits `0x7F` produces small index `0x1FC` and small base `0x3F8`.

3. **Truncation and extension.** A byte store receiving `0x12345678` stores `0x78`. An offset-`5` byte read yielding `0xFE` selects base `0xFE` for the following lookup, not a sign-extended negative base.

4. **External-base capture order.** Any alias-sensitive model must place the external-base global read after the last adjusted-base offset-`0x20` store and before the fixed-word `0x60` store. Reversing either boundary is not generally equivalent.

5. **Capture after fixed-byte mutation.** If fixed byte `0x3A` overlaps the later peer-base offset-`0x14` or adjusted-base offset-`4` word access, that capture includes the intervening byte mutation according to the memory model. A pre-write snapshot is unacceptable.

6. **Fresh fixed-byte consumers.** If an intervening computed write changes byte `0x67`, the next adjusted-base offset-`9` assignment consumes that changed byte. Reusing the captured fixed word’s original low byte is unacceptable. Without intervening changes and under ordinary-memory assumptions, the fresh reads may yield equal values.

7. **Cross-offset assignment.** If the captured peer-base offset-`0x14` word differs from the original offset-`0x54` word, the later offset-`0x54` assignment writes the former. It does not restore the latter.

8. **Overlapping fields and repeated stores.** A word clear followed by an overlapping byte write is not an unchanged cleared word. Likewise, the four adjusted-base offset-`0x20` stores remain distinct represented events despite their final `0x20` value.

9. **Late failure and terminal arguments.** A final-store fault does not promise restoration of earlier effects. If the terminal invocation is reached, its first argument is `0x72`, and its third argument remains the earlier peer-base offset-`0x14` capture rather than a fresh read.
