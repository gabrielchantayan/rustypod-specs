## Behavior

The first direct object access reads the enable byte at offset 16.

If that byte is zero, the function returns immediately. It does not read the bound and does not invoke any dependency.

If the byte is nonzero, the function reads the signed 32-bit bound at offset 4. That value is retained for the scan. Neither the enable byte nor the stored bound is directly read again.

Consequently, a later change to either field does not itself change the outer function’s enabled decision or retained range. Such a change may still affect a dependency that reads the object.

### Range and probe order

The scan starts with index zero. Before each probe, the current index is compared with the retained bound using signed ordering.

If the index is greater than or equal to the bound, the function returns normally without making that probe. Thus:

- A zero or negative bound produces no probes.
- A positive bound makes indices zero through one less than the bound eligible.
- Eligibility alone does not guarantee that an index is reached: an earlier nonzero result or a dependency that does not return normally prevents further scanning.

For each reached eligible index, F-0d1bcade3bad receives two arguments in order:

1. The original input argument.
2. The current signed 32-bit index.

Its result is represented as a 32-bit integer. Only the distinction between zero and nonzero is used.

After a zero result, the index advances by one and the range comparison is repeated. After a nonzero result, scanning stops immediately. No subsequent index is probed, even if it remains within the retained range.

If every eligible probe returns zero normally, the function returns after exhausting the range. Neither post-match dependency is called on that path.
