# F-15c8eb7116f2

## Purpose

The established behavior is an ordered sequence of unresolved dependency invocations, integer transformations, memory reads, and memory writes. It clears and later reads shared state, publishes dependency-derived values, clears a final halfword, and invokes address zero with three zero arguments.

No application-level purpose is established. Allocation, initialization, serialization, service dispatch, and ownership management are not supported interpretations.

This contract distinguishes:

- **Established static evidence:** represented accesses, widths, arguments, transformations, and ordering.
- **Inferred intent:** descriptive terms such as “field,” “table-like,” and “publication”; these do not establish an object model or protocol.
- **documented_only:** behavior not resolved by the supplied representation.

Every effect is conditional on execution reaching it. Dependencies may modify memory, fault, transfer control, or never return. No runtime tests have been performed.

## Interface

The represented interface accepts three 32-bit arguments.

### Additional execution context

The explicit inputs do not fully determine execution. Incoming machine context also supplies the first invocation’s target base, an unsigned quantity used by the first byte store, an address used for its selector read, and a quantity shifted left by two for the first invocation’s fourth argument.

### Outputs and preconditions

No explicit return value is represented. Outputs consist of dependency invocations, direct memory effects, and writes to two shared 32-bit locations, called the **reset-state word** and **published-state word** here.

Successful traversal requires each reached target and memory access to support the represented operation. No validation establishes those conditions. Normal return additionally requires the final invocation at address zero to return.

Unsigned 32-bit calculations retain 32-bit results, including wraparound where applicable. Unsigned right shifts are logical. Some scaling, additions, and left shifts instead operate on represented signed 32-bit quantities. ## Behavior

### Ordering and selector-directed stores

The represented body has one explicit path, without loops or conditional branches. Dependency bodies may contain arbitrary control flow.

A recurring **selector-directed store** first reads an unsigned byte from a specified selector address, then writes one byte at the selector’s numeric value plus `0x11`. Its destination is therefore between `0x11` and `0x110`, inclusive—not relative to the selector’s containing object.

Repeated selector expressions represent fresh observations where they occur. Calls between them may change their values. Repeated stores are distinct effects, not permission to collapse them into one final update.

### Entry and initial forwarding

F-D01 targets incoming control context plus `0xFFE`. Its arguments are, in order:

1. The second explicit input.
2. The same input again.
3. The third explicit input.
4. An incoming context quantity shifted left by two.

Four more invocations precede the first direct store. The last supplies an **early result**. The store reads its selector at incoming address context plus one and writes the low byte of the incoming unsigned quantity logically shifted right by 22.

The next invocation receives the early result shifted left by two.

A later group supplies a **separate later result**. Its following invocation receives that later result shifted left by two twice, then zero. Equality with the early result is not established. These result shifts use represented signed arithmetic.

Another invocation receives the word at absolute address `0x30` in four argument positions. Whether this represents one physical read or several is unresolved.

Two subsequent selector-directed zero stores read selectors at the second explicit input logically shifted right by nine, plus one. Calls intervene; the second selector must not be reused from the first.

### Early word propagation and extractions

The next region contains these ordered effects, separated by dependencies:

### Typed reads and paired results

The middle region interleaves calls and selector-directed stores with these data-read forms, in this order:

2. A word at another paired low word plus a contribution of zero or `0x80000000`. The contribution comes from logically shifting that low word right by 19 and then left by 31.

No explicit validity check precedes these accesses. The byte and halfword forms without established signedness must not acquire an assumed ABI extension rule.

The halfword-forwarding sequence produces a paired result. Its high word selects a four-times-scaled destination receiving the retained right-by-19 quantity. A later result selects another destination receiving the same quantity.

### Reset state and constant deductions

### Published state and repeated field copying

A dependency result is written to the published-state word before further calls.

Later groups read words at selected bases plus `0x74` and write their low bytes at those bases plus one. One base is a retained unsigned-byte value; others derive from scaled dependency results.

Two occurrences use the same retained scaled base, with calls between them. Each reads the word again, so the resulting byte writes need not agree.

### Final reset-state capture and propagation

Near the end, a scaled word destination is cleared. The following interleaving is significant:

1. A paired result supplies a low word and a high word.
2. The low word is interpreted as signed 32-bit and shifted left by two.
3. That shifted value is written at four times the high word plus `0x14`.
4. **Only after this first store, the reset-state word is read and retained as a captured base.**
5. Dependencies are invoked. The first receives the shifted value, the high word, and the shifted value twice more.
6. A later dependency result selects another four-times-scaled destination plus `0x14`; the same retained shifted value is written there.
7. **Only after that second store, a word is read at the captured reset-state base plus `0x14`.**

The first store may alias reset state and therefore affect the captured base. Conversely, dependencies or the second store may change reset state after capture without changing the retained base. They may still change the contents subsequently read at captured base plus `0x14`.

Further calls produce a final paired result whose low word is retained through termination. A selector-directed store writes the low byte of the captured-base word; its selector comes from another retained word shifted right by 23, plus one. A later selector-directed store writes the captured-base word shifted right by 22, truncated to a byte; its selector address uses the final paired low word masked to 30 bits, shifted right by 21, plus one.

### Final publication and termination

Further forwarding calls include one at a differently offset unresolved target. After the last dependency returns an eight-bit result, the final effects are:

1. Clear one byte through a secondary-result pointer.
2. Read the shared 24-bit quantity represented at absolute address `0x09`.
3. Write the published-state word with that quantity in its upper 24 bits and the returned byte in its lower eight bits.
4. Clear a halfword at the final paired low word masked to 30 bits and logically shifted right by seven.
5. Invoke F-D03 at address zero with three zero arguments.
6. Return only if F-D03 returns.

The shared 24-bit observation follows the pointer-based byte clear. Aliasing can therefore affect the published value. These effects are not one atomic operation.

1. **Independent results:** Early result three and separate later result five yield a single forwarded argument of 12, then later arguments 20, 20, and zero.

3. **Fresh selector:** If an intervening dependency changes a selector, a later selector-directed store may choose a different destination.

4. **Truncation:** A byte-store value of `0x1234` writes `0x34`.

5. **Different table formulas:** An unsigned result of one gives the two `0x44`-based read addresses `0x48` and `0x44`.

9. **Fresh reset observation:** A dependency changing reset state after its clear may affect a later fresh read. Two unsigned right shifts by 23 of one retained observation still yield zero.

10. **Capture after first store:** Suppose reset state initially contains `0x1000`, and the first high-word-selected store aliases it and writes `0x2000`. The subsequent capture is `0x2000`.

13. **Final publication:** Returned byte `0xAB` and the subsequently observed shared 24-bit value `0x123456` produce published word `0x123456AB`.

14. **Final-call failure:** If address zero is not callable, normal return is not promised; preceding effects are not rolled back.
