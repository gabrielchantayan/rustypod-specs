# F-697f02051d96

## Purpose

F-697f02051d96 transfers two consecutive bytes from a source region to a destination region through two ordered, one-byte assignments.

The second source byte is read after the first destination byte has been written. Consequently, overlapping regions can produce a different result from a two-byte transfer that first captures both original source bytes. The contract must preserve this ordering rather than merely require that the destination match the source’s initial contents.

The established behavior is limited to these two byte transfers. There is no explicit allocation, deallocation, length check, error reporting, or dependency call.

## Behavior

### Ordered transfer

Normal execution has the following memory-access sequence:

1. Read the byte at source offset 0.
2. Write that byte to destination offset 0.
3. Read the byte at source offset 1.
4. Write that byte to destination offset 1.
5. Return without an explicit value.

These are two distinct one-byte assignments, not an established single two-byte transaction. In particular, the first write precedes the second read.

With disjoint, stable, valid memory, the result is straightforward: destination offset 0 receives the original byte at source offset 0, and destination offset 1 receives the original byte at source offset 1.

With overlapping memory, the first write may change the storage subsequently read as source offset 1. The second assignment uses the value present at that location when its read occurs, not necessarily the value that was there at entry.

### Overlap behavior

When both arguments designate the same starting address, each assignment reads and then writes the same byte location. For ordinary stable memory, the final contents are unchanged. This does not mean the function skips the reads or writes.

When the destination starts one byte after the source, the first destination byte is also the second source byte. The first assignment therefore overwrites the value that the second assignment subsequently reads. For stable ordinary memory, the original first source byte is propagated to both destination positions.

When the destination starts one byte before the source, the first write does not overwrite the second source byte. Under the same conditions, the two destination bytes receive the two original source bytes.

These outcomes follow from the specified access order. They do not establish a general snapshot-copy or overlap-safe move guarantee.
