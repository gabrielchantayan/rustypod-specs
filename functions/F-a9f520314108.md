# F-a9f520314108

## Purpose

F-a9f520314108 performs an in-place byte-order transformation on selected fields of a caller-supplied memory region. It reverses the bytes of several individual 32-bit words, reverses the byte sequence across three adjacent pairs of 32-bit words, and performs one 16-bit transformation through a narrower store. Other bytes remain unchanged.

The established behavior is a fixed memory transformation, not a general buffer conversion: there is no length argument, field selection, format detection, or conditional processing.

**Inferred intent:** the field selection and mixed widths suggest conversion of a structured record between byte-order conventions. Neither the record’s identity nor any field’s semantic meaning is established. In particular, the adjacent word pairs need not represent arithmetic 64-bit integers; their established behavior is reversal of an eight-byte sequence.

## Behavior

### Transformation definitions

A **32-bit byte reversal** exchanges the most significant and least significant bytes and exchanges the two middle bytes. For example, the numeric word `0x12345678` becomes `0x78563412`.

This operation preserves every input bit exactly once. It performs no signed conversion, carry propagation, saturation, or arithmetic addition. Under 32-bit unsigned evaluation, bits shifted beyond the word width are discarded; the masks and shifts place the four input bytes into distinct output positions.

A **paired reversal** reads two adjacent words before changing either destination. The lower-indexed destination receives the byte-reversed original higher-indexed word. The higher-indexed destination receives the byte-reversed original lower-indexed word.

For example, adjacent words containing `0x11223344` and `0x55667788` become `0x88776655` and `0x44332211`. Under a consistent ordinary little-endian or big-endian word layout, this reverses the eight bytes of that pair.

A **halfword reversal** exchanges the two bytes of a 16-bit value. Here, that value is obtained by narrowing a word value to its low 16 numeric bits. The result is stored through a two-byte destination at byte offset 28.

### Ordered accesses and updates

The following is the access order expressed by the supplied representation. It is not a guarantee about individual machine instructions, bus transactions, or compiler treatment of ordinary nonvolatile memory.

1. **Words 0 through 5, in increasing index order.**  
   Each word is read, byte-reversed, and written back before processing the next word.

2. **Words 15 and 16.**  
   Word 15 is read first, then word 16. Both original values are obtained before either destination is written. Word 15 receives the reversed original word 16; word 16 then receives the reversed original word 15.

3. **The halfword destination at byte offset 28.**  
   The source expression references word 7 twice, narrowing each referenced value to 16 bits before forming the exchanged-byte result. The expression does not establish a relative evaluation order between those references. A halfword is then written at byte offset 28.

   With stable ordinary memory, both references supply the same value. The function must not be treated as defining a coherent snapshot if that word changes during evaluation.

4. **Words 9, 10, and 17, in that order.**  
   Each is read, reversed, and written back before the next listed word is processed.

5. **Words 11 and 12.**  
   Word 11 is read, followed by word 12. Word 11 is then written with the reversed original word 12, followed by word 12 with the reversed original word 11.

6. **Words 13 and 14.**  
   Word 13 is read, followed by word 14. Word 13 is then written with the reversed original word 14, followed by word 14 with the reversed original word 13.

The function then returns without an explicit result.

The order is not a simple ascending traversal. In particular, the pair at offsets 60–67 is updated before the halfword at offset 28, while the pairs at offsets 44–59 are updated near the end.

### Halfword memory-order qualification

The halfword operation narrows the **numeric value** of word 7; it does not directly select the first two address-ordered bytes.

On a little-endian target, the low 16 numeric bits occupy offsets 28 and 29. The operation therefore exchanges those two bytes and leaves offsets 30 and 31 unchanged.

On a big-endian target, the low 16 numeric bits occupy offsets 30 and 31, but the halfword destination remains at offsets 28 and 29. Consequently, the operation copies those low-order bytes into the first half of the word in reversed order, leaving offsets 30 and 31 unchanged. This is not merely an exchange of the first two bytes.

A target-independent contract must retain this distinction rather than silently assuming the intended byte-order convention.

## Side effects

### Atomicity and intermediate states

The transformation is not expressed as an atomic record update. Earlier destinations are written before later sources are read.

Each paired reversal saves both input words before its first write, preventing that first write from destroying the input needed for the second destination. This local property does not make the pair update atomic or provide concurrency synchronization.

There is no rollback path. If execution fails after some stores have completed, the representation provides no restoration mechanism. Which completed stores are externally observable in a faulting or otherwise invalid execution is target-dependent.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid storage, the stated integer widths, stable memory, and successful completion.

### Independent word reversal

If word 0 initially contains `0x12345678`, it must contain `0x78563412` afterward.

The same numeric mapping applies independently to words 1–5, 9, 10, and 17. A transformed word does not take its input from an adjacent word.

### Pair exchange with reversal

If word 15 initially contains `0x01020304` and word 16 contains `0xA1B2C3D4`, their final values must be:

| Word | Final value |
|---|---|
| 15 | `0xD4C3B2A1` |
| 16 | `0x04030201` |

Both outputs depend on original inputs. The first output must not become the source for calculating the second.

The same paired relationship applies independently to words 11–12 and 13–14.

### Little-endian halfword behavior

If word 7 initially has numeric value `0xA1B2C3D4` on a little-endian target, it must finish as `0xA1B2D4C3`.

Only the low numeric halfword changes. The address-ordered bytes at offsets 30 and 31 remain unchanged.

### Big-endian halfword behavior

With the same initial numeric value `0xA1B2C3D4` on a big-endian target, the written halfword is `0xD4C3`, placed at offset 28. Word 7 therefore finishes as `0xD4C3C3D4`.

This example distinguishes the established mixed-width operation from an assumed portable in-place two-byte exchange.

### Unchanged locations

Whatever initial values occupy words 6 and 8 must remain unchanged by this function. Bytes 30 and 31 must also remain unchanged, despite their inclusion in a source-word access.

Bytes outside the 72-byte span have no visible accesses in the supplied body.

### Repeated application

On a little-endian target with the stated widths and valid stable storage, applying the function twice restores the original contents of the entire 72-byte span. Each independent reversal and paired reversal is self-inverse, as is the halfword byte exchange in that memory layout.

This restoration property is not established for a big-endian target. The halfword operation there can overwrite bytes that it does not subsequently recover.

### Boundary bit patterns

For any independently reversed word, all-zero and all-one values remain unchanged. Within a paired reversal, such values still move between the two word positions when the pair differs.

These cases do not bypass processing or alter the access sequence.
