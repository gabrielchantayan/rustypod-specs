# F-b387fb72ee11

## Purpose

F-b387fb72ee11 dispatches a 32-bit operation selector against a caller-supplied state object. Its directly established behavior includes conditional notification, storing and resolving a selection value, dependency-controlled processing loops, submission of packed scratch data, and conditional clearing of timing-related fields.

An event-processing or lifecycle role is inferred, not established. The application meanings of the selectors, selected values, submitted data, and timing units remain unknown.

Every normal return shown produces the 32-bit value zero. Two paths can iterate indefinitely if their controlling dependencies continue returning zero. A selector-4 failure path invokes a dependency identified by the supplied representation as nonreturning.

## Behavior

### Common entry

Before selector-specific processing, the function performs these operations in order:

1. Calls an unmapped context accessor.
2. Calls F-f82bb660a2ac with the returned context address advanced by four bytes and the constant 6.
3. Retains the lookup’s 32-bit result.
4. Reads and retains the shared 32-bit seed.

This sequence occurs even for unsupported selectors and selector-1 arguments that fail the later gate. Such calls therefore are not established as side-effect-free.

Later context-access calls are separate calls. Neither their returned addresses nor their effects are assumed identical to those of the initial call.

### Selector 1: gated notification

The selector-specific path proceeds only when the operation argument equals 5 and the retained lookup result is nonzero.

When both conditions hold, the function obtains a context again, advances that address by four bytes, and calls F-be95475fc79f with that address and the retained lookup result.

If F-be95475fc79f returns nonzero, F-42ba21aff2f5 receives the state object and zero. A zero result skips that call.

Normal completion returns zero. This path contains no direct writes to the listed object fields; dependency writes remain possible.

### Selector 4: store, resolve, or take the nonreturning path

The function first writes the operation argument as a 32-bit value at `0x2D4`. It then compares the original argument, interpreted as signed, against 3.

For an argument less than 3:

- The context accessor is called again.
- The current 32-bit value at `0x2D4` is read after that call.
- F-b37968c9f644 receives the context address advanced by four bytes and the newly read field value.
- Its 32-bit result is written to `0x2D0`.
- A nonzero result leads to a normal return of zero.

The initial argument write does not guarantee that the resolver receives the same value: the intervening context call is not known to preserve the object.

F-a817d8d58c10 is invoked when the signed argument is at least 3, or when the argument is less than 3 and resolution returns zero. In the latter case, zero has already been stored at `0x2D0`.

The supplied representation marks F-a817d8d58c10 as nonreturning. Whether it terminates execution, raises an exception, or transfers control by another mechanism is unknown.

Negative arguments enter the resolution path. There is no explicit lower-bound check.

### Selector 8: repeat until a dependency returns nonzero

If the retained lookup result is nonzero, the function first obtains a context again and calls F-4944ce526800 with:

- The context address advanced by four bytes.
- The retained lookup result.
- The constant 6.
- Zero.

No return value from this call is used.

The processing loop then runs at least once, including when the lookup result is zero. Before each call to F-704f99fd5e22, the visible scratch assignments occur in this order: an address-bearing word receives the address of a separate scratch word; the first explicit scratch argument receives the captured seed; the addressed scratch word receives zero; and the second explicit scratch argument receives the captured seed.

F-704f99fd5e22 receives the state object, the retained lookup result, and addresses of the two seed-initialized words. The additional address-bearing scratch word is not an explicit argument in the supplied call expression. Its possible implicit role is unknown.

A zero return repeats the loop and reinitializes the scratch state. A nonzero return ends the loop, after which the function returns zero. No visible iteration limit, timeout, or cancellation condition exists.

### Selector 32: process and submit

Each iteration starts with these visible scratch operations, in order:

- Read `0x2D4` into the selection scratch word.
- Initialize a second explicit scratch word from the captured seed.
- Store the address of a further scratch word into the address-bearing scratch word.
- Set that addressed word to zero.
- Initialize the third explicit scratch word from the captured seed.

F-e08f888de5db receives the state object and the addresses of the selection word and the two seed-initialized words.

A nonzero return ends the loop immediately. That iteration performs neither the special-action check nor submission. A zero return proceeds through both stages below.

#### Conditional action

The function first examines the low 16 bits of the third explicit scratch word supplied to F-e08f888de5db, called the result word here.

Only when those bits equal 3 does it read the byte at `0x2FC`. Only an exact byte value of 1 triggers the action:

1. Obtain a context again.
2. Read the current 32-bit selection field at `0x2D4`.
3. Call F-4944ce526800 with the context address advanced by four bytes, that field value, 6, and zero.
4. After the call returns, clear the byte at `0x2FC`.

The selection read follows the context call; it is not the earlier iteration snapshot. A flag value such as 2 does not trigger the action. When the result’s low 16 bits are not 3, this function does not perform the flag read at this point.

#### Packed submission

Every zero-return iteration constructs a packed 32-bit word after the conditional action:

| Bits | Contents |
|---|---|
| 31–24 | Zero |
| 23–16 | `0x0F` |
| 15–8 | Low eight bits of the result word at packing time |
| 7–0 | Zero |

The numeric value is `0x000F0000` plus the low result byte shifted left by eight bits. Other result bits do not affect this word.

The packing read occurs after any conditional-action dependencies. Their preservation of scratch or shared state is not established. The packed word overwrites the address-bearing scratch word used earlier in the iteration.

At this point, the packed word is followed contiguously by the word initially set to zero and then by the result word. “Initially zero” does not establish its contents after dependency calls.

The function then:

1. Calls an unmapped operation with the object address advanced by `0x2D8`.
2. Calls F-c6c589453fa8 with 6, zero, the packed-word address, and 3.
3. Calls a second unmapped operation with the same object-region address.
4. Starts the next iteration.

Packing precedes the first bracketing operation; the submission dependency receives the scratch address afterward. The effects of the bracketing operation are unknown.

The constant 3 is not established as a byte count, word count, or record count. Synchronization is a possible intent for the bracketing calls, not a proven property.

### Selector-32 timing path

After loop completion, the function reads the byte at `0x2F8`. A zero value skips this timing path. Any nonzero value enables it.

The enabled path has this order:

1. F-7a117b899bf6 receives the address of a scratch word.
2. A callable address is loaded from offset `0x0C` relative to the address-bearing value then held in that word.
3. The callable receives the address of that same word and the address of another scratch word.
4. F-bf18a6a8124b receives the second word’s address and returns a 64-bit value.
5. The current 32-bit timing reference is read from `0x2F4`.
6. The reference is subtracted from the returned value’s low half using modulo-\(2^{32}\) arithmetic.

If the unsigned difference exceeds 499, this function directly clears the byte at `0x2F8` first, then writes a 32-bit zero at `0x2F4`.

A difference of 499 or less skips those two direct clearing writes. It does **not** establish preservation of the fields through completion: F-ec22bd8215d3 still executes and its effects are unknown.

F-ec22bd8215d3 receives the first timing scratch word’s address and a 32-bit adjusted high half. That value is the returned 64-bit value’s high half, reduced by one when its low half is unsigned-less-than the captured reference. The decrement is a 32-bit operation. This calculation uses the captured reference even if `0x2F4` has just been cleared.

The expiration decision uses only the modular low-half difference, not a full 64-bit elapsed-time comparison.

## Side effects

### Direct state changes

The function directly writes:

- `0x2D4` on every selector-4 invocation.
- `0x2D0` after selector-4 resolution returns.
- `0x2FC` after the selector-32 conditional action returns.
- `0x2F8`, then `0x2F4`, when the timing threshold is exceeded.
- Invocation-local scratch storage along the processing and timing paths.

These are statements about direct writes, not complete postconditions for object contents. Dependencies may also modify the object or reachable state.

No rollback is visible when a dependency fails to return or transfers control elsewhere. Calls following a failure to return are not reached.

### Ownership and lifetime

No explicit allocation or release of the state object is shown. This does not establish that dependencies neither allocate nor release memory.

Dependencies receive addresses of invocation-local scratch storage. Whether they retain these addresses is unknown; any safe retention would require a lifetime arrangement not established here.

The final timing call is not established as a destructor or release operation. Resource ownership represented by the timing scratch words remains unknown.

### Errors and progress

There is no distinct normal-return error code. Normal completion returns zero.

Both processing loops rely entirely on their controlling dependency eventually returning nonzero. Continuous zero returns permit unbounded iteration. Selector 32 performs a submission sequence for every zero-return iteration that reaches those calls.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes dependencies return where required and storage remains valid.

1. **Unsupported selector.** Selector 2 still performs the context access, lookup, and shared-seed read. It then returns zero without selector-specific processing.

2. **Selector-1 gates.** Argument 4 skips the selector-specific calls even with a nonzero lookup. Argument 5, a nonzero lookup, and a nonzero F-be95475fc79f result lead to F-42ba21aff2f5 receiving the object and zero.

3. **Selector-4 success.** Argument 2 is stored before the additional context call. If resolution returns a nonzero value, that value is written to `0x2D0` and normal completion returns zero. Equality between the stored argument and resolver input additionally requires that the intervening dependency not change `0x2D4`.

4. **Selector-4 boundaries.** Argument 3 is stored, then reaches the nonreturning endpoint without resolution. Argument −1 enters resolution because the comparison is signed. A zero resolution result is stored before the nonreturning endpoint is invoked.

5. **Selector-8 progress.** Controller returns of zero, zero, and nonzero produce three calls, with scratch reinitialized each time. A zero initial lookup skips the preliminary F-4944ce526800 call but not the loop.

6. **Selector-32 special action.** A zero controller result, result low half equal to 3, and flag byte equal to 1 cause the action call, then direct flag clearing, then packing and submission. A flag value of 2 does not trigger the action.

7. **Packing.** A result word of `0x1234ABCD` at packing time produces the packed numeric value `0x000FCD00`.

8. **Loop completion.** A nonzero F-e08f888de5db return skips submission for that iteration and proceeds to the timing-flag check.

9. **Timing threshold.** With the timing path enabled, a modular difference of 499 causes no direct clearing writes. A difference of 500 causes the byte flag clear followed by the reference clear. F-ec22bd8215d3 executes in both cases. Final field preservation at 499 requires an explicit nonmutation condition for the intervening dependencies, including that final call.

10. **Timing wraparound and borrow.** Low half 20 and reference `0xFFFFFF00` yield a modular difference of 276: no direct clearing writes occur, and the final call receives the high half reduced by one. Low half 900 and reference 1000 yield `0xFFFFFF9C`, which exceeds 499 and triggers direct clearing. Neither case establishes final field contents after unknown dependency effects.
