# F-43691a26a7a2

## Purpose

F-43691a26a7a2 transfers a 16-byte input block into a local working state, invokes an ordered sequence of opaque dependencies, transfers the resulting state to a 16-byte output block, and returns a 64-bit value assembled from two working-state words.

The established structure consists of:

- A transposed input transfer.
- One unconditional initial dependency call.
- Intermediate stages controlled by a signed stage-count parameter.
- One unconditional final stage.
- A transposed output transfer.
- Return construction after the output transfer.

A round-based block transformation is **inferred intent**. The evidence does not establish an algorithm identity, the transformations performed by the dependencies, or any cryptographic properties.

These are descriptions of accesses through argument roles, not assertions that the corresponding storage regions are distinct. If input and output overlap, reads through the input base also read overlapping output storage, and writes through the output base also modify overlapping input storage.

## Behavior

### Working-state preparation

Before reading the input block, the wrapper writes arguments 1, 2, 3, and 4 into working-state words 0, 1, 2, and 3, respectively.

It then overwrites all 16 state bytes during the input transfer. With input storage separate from the working state, the initial word values do not survive that transfer as state contents.

Those initial stores cannot be ignored under every possible alias arrangement. If the input addresses overlap the working state, the stores may change bytes before the input transfer reads them. Such an arrangement is not established as a supported calling pattern, but the ordering remains relevant.

### Input transfer

Consider input byte positions as four rows of four bytes. Let **r** identify a row and **c** a column, each from 0 through 3.

The byte at input offset **4r + c** is transferred to working-state offset **r + 4c**.

Input reads occur in ascending offset order. Each byte is read before its corresponding state-byte write, and that pair completes before the next byte transfer.

| Input offsets, in read order | Corresponding state offsets |
|---|---|
| 0, 1, 2, 3 | 0, 4, 8, 12 |
| 4, 5, 6, 7 | 1, 5, 9, 13 |
| 8, 9, 10, 11 | 2, 6, 10, 14 |
| 12, 13, 14, 15 | 3, 7, 11, 15 |

This is a byte-layout transposition, not a numeric conversion. It does not depend on word endianness.

The complete input transfer precedes the first dependency call. No output-role write occurs during this phase.

### Initial dependency call

F-d522aca80568 is invoked with:

1. The working-state address.
2. The unadjusted offset-data base address.

This call occurs for every N, including zero and negative values.

The wrapper does not inspect a returned status. Subsequent processing uses the state and other conditions left by the dependency; preservation of unrelated storage or global state is not established.

### Intermediate stages

Intermediate stage indices begin at 1 and continue while strictly less than N. Each stage invokes, in order:

1. F-6fed294631b9 with the working-state address.
2. F-81533b18b43b with the working-state address.
3. F-f55e646646c2 with arguments 1 and 2, followed by the working-state address.
4. F-d522aca80568 with the working-state address and the offset-data base advanced by 16 times that stage’s index.

The state is not reset, restored, or copied between these calls. Each call completes before the next begins, assuming normal returns.

For N greater than 1, there are N − 1 intermediate stages. For N less than or equal to 1, there are none.

Arguments 1 and 2 supplied to F-f55e646646c2 are the function’s argument values, not the initial copies placed in the working state. Overwriting those state copies during input transfer therefore does not determine the context values passed to this dependency.

### Final stage

After all intermediate stages, the wrapper unconditionally invokes:

1. F-6fed294631b9 with the working-state address.
2. F-81533b18b43b with the working-state address.
3. F-d522aca80568 with the working-state address and the offset-data base advanced by **16 × N** bytes.

F-f55e646646c2 is not invoked in this final stage.

Consequences include:

- N = 1 selects offset 16 for the final F-d522aca80568 call.
- N = 0 selects offset 0 again; it does not suppress the final stage.
- Negative N skips intermediate stages and supplies a negative final displacement, subject to arithmetic and address validity.

There is no visible rejection or normalization of these values.

### Output transfer

After the final dependency returns, the wrapper transfers state bytes to output bytes using the inverse layout mapping:

- State offset **r + 4c** supplies output offset **4r + c**.
- Output writes occur in ascending offsets 0 through 15.
- State reads occur at offsets 0, 4, 8, 12, then 1, 5, 9, 13, then 2, 6, 10, 14, then 3, 7, 11, 15.
- Each state-byte read precedes its corresponding output-byte write.

No separate snapshot of the final state is established before this transfer. If output storage overlaps the working state, an earlier output write can affect a later state read. The sequential transfer order, rather than an abstract simultaneous permutation, determines that case.

If output storage overlaps input storage, these writes directly modify the overlapping input bytes. All input-role reads have already completed, so the wrapper does not thereby overwrite an input byte that it still needs to read.

### Return construction

After all 16 output writes complete, the wrapper obtains the first two 32-bit state words and combines them into the 64-bit result.

The evidence establishes that both words are used after output transfer; it does not require a particular relative read order between those two words.

The numeric interpretation of each word depends on target endianness. If output writes have modified the working state through overlap, the return reflects the resulting state, not a guaranteed pre-output snapshot.

### Aliasing

Input-role reads and output-role writes must be distinguished from claims about whole storage regions:

- With disjoint input and output, output-role writes do not modify input storage.
- With overlapping input and output, output-role writes directly modify the overlap.
- With overlapping input and output, input-role reads directly read storage that also belongs to the output region.
- Other aliases can allow dependency accesses or working-state accesses to affect those regions as well.

Exact in-place use and partial input/output overlap introduce no unread-input overwrite by the wrapper’s output phase: all input-role reads precede all output-role writes. This ordering alone does not prove compatibility with dependencies that access aliases, retain pointers, or modify related storage.

Whether dependencies retain pointers, release resources, or require particular ownership arrangements remains unknown. Continued use of the working-state address after its lifetime is not justified by this evidence.

### Errors and interruption
