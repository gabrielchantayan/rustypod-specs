# F-405260ef6eb9

## Purpose

F-405260ef6eb9 conditionally transfers a four-word region from a source address to a destination address.

The established behavior has two paths:

- When the 32-bit field at context offset `0x2C` is zero, the function directly transfers four 32-bit words.
- When that field is nonzero, the function invokes F-3a43adaaeff9 twice: first with the original source and destination addresses, then with both addresses advanced by eight bytes.

The context field is read again for each dependency invocation. Its initial nonzero value selects the delegated path, but does not establish the values subsequently passed to the dependency.

The likely intent is to support an unchanged transfer in one mode and processing of two adjacent portions in another. That interpretation is inferred, not an established description of the dependency’s behavior. In particular, the supplied evidence does not establish that the delegated path copies, transforms, or fully initializes the destination.

### Data widths and layout

The relevant context field occupies four bytes beginning at context offset `0x2C`. The branch distinguishes only a zero 32-bit value from a nonzero 32-bit value. There is no positive-versus-negative comparison.

The direct path accesses four consecutive 32-bit words:

| Word position | Byte offset from its region’s base |
|---|---:|
| First | `0x00` |
| Second | `0x04` |
| Third | `0x08` |
| Fourth | `0x0C` |

Each source and destination region therefore spans 16 bytes on the direct path.

The dependency’s second invocation receives source and destination addresses advanced by two words, or eight bytes. This is address adjustment, not a demonstrated bound on the dependency’s memory accesses.

No field within a transferred word is decoded. The direct path preserves the word values without an established arithmetic conversion. Byte order is not specified by the evidence; it follows the execution environment’s 32-bit loads and stores.

## Behavior

### Path selection

The first observable operation established by the supplied body is a 32-bit read from context offset `0x2C`.

- If the observed value is zero, execution follows the direct path.
- If the observed value is nonzero, execution follows the delegated path.

Once selected, the path is not reconsidered. A later change to the context field does not cause the function to switch to the other path.

### Direct path

The direct path performs the following ordered memory operations:

1. Read the second source word.
2. Read the third source word.
3. Read the fourth source word.
4. Read the first source word.
5. Write the captured first word to the first destination word.
6. Write the captured second word to the second destination word.
7. Write the captured third word to the third destination word.
8. Write the captured fourth word to the fourth destination word.

Thus, all four source words are read before the first destination write. The read order differs from ascending word order; the write order is ascending word order.

The values captured from the second, third, and fourth source words remain the values used for their corresponding destination writes. Destination writes do not cause those source words to be read again.

For valid ordinary memory with no concurrent modification, the final destination region contains the four source-word values captured by those reads. This includes overlapping source and destination regions: the direct path captures every source word before modifying the destination.

This overlap property is local to the direct path. It does not establish any overlap guarantee for the dependency.

If source and destination addresses are equal, the supplied body still contains all four reads and all four writes. It has no explicit equality shortcut.

The direct path does not invoke F-3a43adaaeff9. It does not explicitly write the context field. However, a destination region that overlaps the context may change that field as a consequence of the destination writes.

### Delegated path

After the initial nonzero branch decision, the function reads the context field again. It then invokes F-3a43adaaeff9 with five arguments, in this order:

1. The original context address.
2. The value from that second context-field read.
3. The original source address.
4. The original destination address.
5. The integer value one.

If that invocation returns normally, the function reads the context field a third time. It then invokes F-3a43adaaeff9 with:

1. The original context address.
2. The value from that third context-field read.
3. The source address advanced by eight bytes.
4. The destination address advanced by eight bytes.
5. The integer value one.

The first invocation completes before the field read supplying the second invocation.

The initial branch read is not reused as either invocation’s field argument. The field value used for the first invocation is also not reused for the second. Consequently:

- The first invocation may receive a field value different from the value that selected the path.
- The second invocation may receive a field value different from the first invocation’s value.
- Either invocation may receive zero, even though entry into this path required an earlier nonzero observation.

There is no explicit dependency-result check between calls. The supplied body does not use a return value from either invocation.

If the first invocation does not return normally, the evidence does not establish execution of the third field read or the second invocation. If the second invocation returns normally, the wrapper returns without an explicit result.

### Arithmetic boundaries

The established offsets are fixed:

- Second dependency source offset: eight bytes.
- Second dependency destination offset: eight bytes.

There is no variable-length calculation, multiplication by a caller-supplied count, saturation, or explicit overflow handling.

The evidence does not define behavior when these address adjustments exceed the valid address range. It does not support treating address wraparound as an accepted feature.

## Side effects

### Directly established effects

On the direct path, the function performs one context-field read, four source-word reads, and four destination-word writes.

On a delegated path whose first invocation returns normally, it performs three context-field reads in total and two ordered dependency invocations. The wrapper contains no explicit source-word loads or destination-word stores on that path; such accesses, if any, occur inside the dependency.

### Aliasing and mutable state

No non-aliasing restriction is established by the supplied body.

The source, destination, and context may overlap in address, subject to access validity and any dependency requirements. Such overlap can make an apparent destination write also be a context modification.

The dependency must not be assumed to preserve the context field, source data, destination data, or global state. In particular, the second invocation observes the context field after the first invocation has returned.

The repeated field reads do not establish synchronization, atomicity, or thread safety. Behavior under concurrent mutation is not specified by this evidence.

### Errors and partial completion

## Acceptance examples

These examples are conditional contract cases, not executed tests.

### Zero field with distinct regions

Given a readable zero context field, four readable source words with values `0x11223344`, `0x55667788`, `0x99AABBCC`, and `0xDDEEFF00`, and a valid separate destination region:

- The destination receives those four word values in that order.
- Destination writes occur at offsets zero, four, eight, and twelve bytes.
- F-3a43adaaeff9 is not invoked.
- The function supplies no explicit return value.

### Zero field with overlapping regions

Given valid ordinary memory, no concurrent modification, and a destination beginning four bytes after the source:

- The four source words are captured before any destination write.
- The destination receives the captured source sequence, rather than a sequence contaminated by earlier writes.
- Memory outside the destination range is not explicitly written by this path.

The same reasoning applies to a destination beginning before the source, provided every access is valid.

### Zero field with identical regions

Given identical valid source and destination addresses and a zero context field:

- The direct path reads all four words and then writes their captured values back.
- An unchanged final memory image does not imply an absence of writes.

### Nonzero field with stable observations

Given a context field observed as the same nonzero value on all three reads, and a first dependency invocation that returns normally:

- The dependency is invoked twice with that field value.
- The first invocation receives the original source and destination addresses.
- The second receives addresses eight bytes later.
- Both receive one as the fifth argument.

No final destination contents are prescribed without a dependency contract.

### First invocation changes the context field

Given an initial nonzero observation, a first invocation supplied with a nonzero field value, and a first invocation that changes the field to zero before returning:

- The second invocation still occurs.
- Its second argument is zero, assuming that is what the subsequent field read observes.
- The wrapper does not substitute a direct copy or skip the second invocation.

### First invocation does not return

Given entry into the delegated path and a first invocation that never returns:

- The wrapper does not proceed to its second invocation.
- No completed-function result is established.
