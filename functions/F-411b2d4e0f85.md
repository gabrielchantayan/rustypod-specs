| Incoming fifth argument | Forwarded fifth argument |

The external values are forwarded as complete 32-bit values. No masking, range restriction, signed conversion, bit combination, or further interpretation is visible after a selected external value is read.

In particular, an external value is not passed through selection again. If external word A contains 16 and the incoming fifth argument is 0, the dependency receives 16; that does not cause a subsequent read of external word B.

### External-read behavior

The resulting argument alone does not fully describe the function. The supplied representation establishes this external-read schedule:

| Incoming fifth argument | External reads, in order |
|---|---|
| 0 | A |
| 1, 2, 4, or 8 | None |
| Any other value less than 5 | None |
| 16 | B |
| 32 | B, then A |
| Any other value greater than or equal to 5 | B |

Thus, an incoming value of 32 causes a read of B whose value is discarded, followed by the read of A whose value is forwarded. An incoming value such as 5, 9, or 17 causes a read of B, but the dependency receives zero regardless of the value read.

The comparisons involving ordering use the signed interpretation of the fifth argument. All negative signed 32-bit inputs therefore select zero without reading either external word. The signed minimum, −2,147,483,648, follows this same rule. The signed maximum, 2,147,483,647, reads B and then selects zero.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed test results. Each dependency-call example assumes that all required reads complete and that invocation is possible.

1. **Literal forwarding:** With fifth argument 4, the dependency receives 4 in position 5. Neither A nor B is read. The remaining six arguments retain their incoming bit patterns.

2. **Zero uses A:** With fifth argument 0 and A returning `0xA5A5A5A5`, the dependency receives `0xA5A5A5A5` in position 5. B is not read.

3. **Sixteen uses B:** With fifth argument 16 and B returning `0x80000000`, the dependency receives that complete 32-bit pattern. No sign-based normalization or secondary selection occurs.

4. **Thirty-two has two reads:** With fifth argument 32, B returning 7, and A subsequently returning 11, the read order is B followed by A, and the dependency receives 11. B’s value is not forwarded.

5. **Unsupported positive input still reads:** With fifth argument 5, B is read and the dependency receives zero, whatever 32-bit value B supplies.

6. **Unsupported low input does not read:** With fifth argument 3, neither external word is read and the dependency receives zero.

7. **Negative input:** With fifth argument −1, neither external word is read and the dependency receives zero.

8. **Signed boundaries:** The signed minimum selects zero without external reads. The signed maximum reads B and then selects zero.

9. **External values are terminal:** With fifth argument 0 and A returning 32, the dependency receives 32 after only the A read. The selected value does not trigger the two-read behavior associated with an incoming selector of 32.

10. **Dependency effects remain unconstrained:** If the dependency modifies A or B and returns normally, this function performs no subsequent restoration or reread.
