# F-e3b26f245f4c

## Purpose

F-e3b26f245f4c performs a word-oriented subtraction into a caller-supplied destination descriptor, then removes leading zero words from the destination’s logical length.

The established arithmetic behavior is subtraction of two sequences of unsigned 32-bit words, with borrow propagated from lower-index words toward higher-index words. This supports the inferred interpretation of little-endian, base-$2^{32}$ unsigned integers.

The routine rejects an operand-length ordering in which the first operand has fewer words than the second. It does **not** independently reject a numerically smaller first operand when their word counts permit subtraction. A borrow remaining beyond the first operand’s declared length is discarded.

Success is reported by the 32-bit value `1`; the explicit failure paths return `0`. Success does not establish that subtraction was nonnegative in an unbounded integer interpretation.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments

The routine accepts four arguments:

1. **Destination descriptor**: a pointer to a writable descriptor containing at least four consecutive 32-bit fields.
2. **First operand descriptor**: a pointer to a descriptor whose first two 32-bit fields are readable.
3. **Second operand descriptor**: a pointer to a descriptor whose first two 32-bit fields are readable.
4. **Opaque auxiliary value**: one 32-bit value forwarded to a dependency if destination capacity expansion is requested.

The visible descriptor layout is:

| Byte offset | Destination interpretation | Operand interpretation |
|---|---|---|
| 0 | Address of writable 32-bit word storage | Address of readable 32-bit word storage |
| 4 | Signed 32-bit logical word count | Signed 32-bit logical word count |
| 8 | Signed 32-bit capacity used by the expansion check | Not inspected directly |
| 12 | Metadata field set to zero after arithmetic | Not inspected directly |

Addresses stored in descriptor fields are represented by 32-bit values in the supplied representation. Native byte endianness is not established. Word significance is established by traversal: index zero is processed first and supplies borrow to index one.

The destination’s offset-12 field may represent a sign or another status property, but that interpretation is not established. The contractual observation is its assignment to zero.

### Result

The routine returns a 32-bit result:

- `1`: the arithmetic and destination-normalization path completed.
- `0`: either the operand-length ordering was rejected or the capacity dependency returned a null result.

These are the only explicit normal return values visible in the supplied body. Dependency failure, nonreturn, and invalid memory access are not converted into additional result codes here.

### Preconditions for the ordinary arithmetic contract

The useful, bounded subtraction behavior requires:

- Valid descriptor storage with the access permissions listed above.
- Nonnegative operand word counts.
- Readable first-operand storage for its declared word count.
- Readable second-operand storage for its declared word count.
- Writable destination storage for the first operand’s word count, whether already available or established by the capacity dependency.
- Proper alignment and representable address calculations for all accessed words.
- No overlapping storage arrangement that overwrites a word or descriptor field before its required read.

The routine does not check these conditions comprehensively. In particular, it does not validate pointers, reject negative lengths, verify source capacities, or independently validate destination storage after the capacity dependency returns.

## Behavior

### 1. Capture operand lengths and check their ordering

The routine first reads the signed 32-bit word count from the first operand descriptor, then reads the signed 32-bit word count from the second operand descriptor.

If the first count is less than the second count under signed comparison, it calls F-4fc89ec41a6d with the five argument values:

`3`, `115`, `100`, `0`, `0`.

If that dependency returns normally, the routine returns `0`. It does not enter destination expansion, arithmetic, or normalization.

This is a length-order check, not a full magnitude comparison. Equal-length operands proceed regardless of their word values.

### 2. Ensure destination capacity through a conditional dependency

When the length ordering is accepted, the routine reads the destination’s signed 32-bit capacity field.

If capacity is less than the captured first-operand count under signed comparison, it calls F-08bc2fc94856 with:

1. The original destination descriptor pointer.
2. The captured first-operand count.
3. The second operand descriptor pointer.
4. The opaque auxiliary value.
5. The same opaque auxiliary value again.

A null dependency result causes return value `0`, with no subsequent arithmetic or normalization by this routine.

A non-null dependency result permits execution to continue. Importantly, that returned pointer is only used as a success gate. The routine does **not** adopt it as a replacement destination descriptor. Subsequent accesses still use the originally supplied destination descriptor.

Consequently, successful expansion must leave usable destination storage reachable through the original descriptor if arithmetic is to be valid. Whether the dependency actually allocates, relocates, releases, or otherwise modifies memory is not established here.

The operand counts remain the previously captured values. They are not refreshed after this call.

### 3. Acquire storage pointers

After capacity handling succeeds, the routine reads storage addresses in this order:

1. First operand storage.
2. Destination storage.
3. Second operand storage.

These address reads occur after the possible capacity call. Thus, any descriptor changes made by that dependency can affect the selected storage, even though the iteration counts remain the earlier captured counts.

The initial borrow is clear.

### 4. Subtract the second operand’s words

For each index covered by the second operand’s captured word count, in ascending order:

- Read the first operand word.
- Read the second operand word.
- Compute the destination word using unsigned 32-bit subtraction and the incoming borrow.
- Write the destination word.
- Advance all three word positions.

For input words $a_i$ and $b_i$, and incoming borrow $c_i$ equal to zero or one, the stored result is:

\[
r_i=(a_i-b_i-c_i)\bmod 2^{32}.
\]

The outgoing borrow is:

- With no incoming borrow: one exactly when $a_i<b_i$.
- With an incoming borrow: one exactly when $a_i\le b_i$.

The latter comparison is important at the boundary where both input words are equal: subtracting the additional one still requires a borrow.

Each pair of source words is read before that index’s destination write. No later source word is prefetched by this subtraction phase.

### 5. Propagate borrow through the remaining first-operand words

If a borrow remains after the second operand’s words have been consumed, the routine processes successive first-operand words, stopping at the first operand’s captured length.

For each such word:

- Read the word.
- Store the word minus one, modulo $2^{32}$.
- Continue propagating borrow if the original word was zero.
- Otherwise stop propagating borrow.

Thus, an original zero becomes `0xffffffff` and retains the borrow; an original nonzero word is decremented and clears the borrow.

If the borrow reaches the end of the first operand, it is discarded. There is no separate underflow return, error call, or additional high word.

### 6. Copy any untouched remainder

After borrow propagation, any unprocessed first-operand words are retained in the destination.

If the current source and destination addresses are equal, the routine skips this copy. Otherwise, it copies the remaining words in ascending address order. The visible copy is grouped into up to four sequential word transfers per iteration, but its relevant ordinary behavior is a forward copy, not an overlap-safe move.

Each transferred word is read and then written before the next word’s transfer. Arbitrary overlapping storage is therefore not supported by this body.

### 7. Commit metadata and normalize

After arithmetic and any remaining copy, the routine:

1. Writes the captured first-operand count to the destination logical-length field.
2. Writes zero to the destination field at byte offset 12.
3. If that count is positive, reads the destination storage address again.
4. Scans backward from the last word in the initial result range.

For each trailing zero word, it decrements the destination’s logical-length field. Scanning stops upon encountering a nonzero word or reducing the logical length to zero.

For ordinary non-overlapping descriptors and storage, the final logical length is therefore:

- Zero if every result word is zero.
- Otherwise, one greater than the highest index containing a nonzero result word.

Normalization does not clear discarded words or reduce capacity. It changes only the logical length; zero words above the new logical end remain physically present.

The routine then returns `1`.

## Side effects

### Destination writes

On the successful arithmetic path, the routine may write:

- Up to the captured first-operand count of destination words.
- The destination logical-length field, initially to the captured count and subsequently once per removed leading zero word.
- Zero to the destination field at byte offset 12.

An unchanged tail may receive no writes when its source and destination addresses are identical. Nevertheless, the metadata assignments still occur.

The routine does not explicitly write the destination capacity or storage-address fields. Any changes to those fields during expansion belong to the dependency’s behavior.

### Source mutation through aliasing

There are no direct writes through operand descriptor pointers in the visible arithmetic body. Operand memory can still change when it aliases destination storage or when a dependency modifies it.

Exact in-place destination storage matching the first operand is compatible with the forward arithmetic order under ordinary descriptor separation. Exact matching with the second operand also allows each subtraction word to be read before its same-index write, provided the destination has sufficient writable storage for the full first-operand length.

These observations do not imply support for arbitrary partial overlaps. A destination starting inside a later portion of a source can overwrite a word before that word is read.

Descriptor-storage overlap is especially hazardous: arithmetic writes can affect descriptor fields later used for metadata updates or normalization. No general result is promised for such arrangements.

### Ownership and allocation

This routine contains no explicit allocation or release operation outside its dependency call. It does not establish ownership transfer for either operand, destination storage, or the auxiliary value.

A null expansion result does not establish rollback. The dependency may already have changed memory or external state before returning null.

### Error-related effects

The rejected-length path invokes F-4fc89ec41a6d. Its effects are unknown. The explicit `0` return applies only if it returns control normally.

No destination-zeroing, rollback, or general error cleanup is visible.
