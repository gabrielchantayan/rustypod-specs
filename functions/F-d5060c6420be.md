# F-d5060c6420be

## Purpose

F-d5060c6420be conditionally adds flag bits to records connected by two directional links.

Its ordinary execution has two phases:

1. Examine selected linked rings using a signed 32-bit comparison field and add bit `0x40` to certain contiguous spans.
2. Examine records in contiguous storage using another signed 32-bit comparison field and, for records already carrying `0x40`, potentially add `0x80` or `0x100`.

The function does not clear any flag bits.

An important control-flow exception connects the two phases: if a qualifying first-phase search returns to its starting record without finding a different comparison value, execution abandons the remaining first-phase descriptors and enters the second phase at the descriptor index plus one. It does not restart the second phase at record zero.

The evidence establishes link traversal, comparisons, and flag updates. Interpreting these operations as geometric classification, extremum detection, or another domain-specific operation is inferred intent, not an established contract.

## Interface

The function accepts one address identifying a control structure. It returns no value.

There is no explicit success indicator, error code, diagnostic, or recovery mechanism. Normal completion consists of returning after the second-phase index reaches its unsigned bound.

## Behavior

### 1. First-phase descriptor processing

The first-phase index starts at unsigned zero. Before each descriptor is processed, it is compared against the descriptor count.

For each visited descriptor:

1. Fetch its starting-record address.
2. Read its enable value.
3. If the enable value is zero, perform no linked-record traversal for that descriptor and advance to the next descriptor.
4. Otherwise, search forward for a record whose first comparison field differs from the starting record’s first comparison field.

The forward search advances at least once before examining a comparison field. After each link advance, it first tests whether the new address equals the starting address.

If the search returns to the starting address, execution takes the cross-phase transition described below. The comparison field of that returned-to record is not needed to establish this transition.

Otherwise, the search continues while the reached record’s first comparison field equals the starting record’s first comparison field.

### 2. First-phase backward boundary scan

When the forward search finds a different first comparison value:

- That differing record becomes the initial reference record.
- Its backward-linked record becomes a fixed traversal origin.
- The traversal origin is also the initial candidate record.

The function then advances backward before each boundary test. Reaching the fixed traversal origin ends this descriptor’s scan immediately. No boundary comparison is performed for that returning step.

At each other visited record:

- If its first comparison field equals the current candidate’s first comparison field, continue backward without changing the candidate or reference.
- If those values differ, evaluate a marking decision.

For the marking decision, define:

- **C**: the candidate’s signed first comparison value.
- **R**: the reference record’s signed first comparison value.
- **L**: the newly reached record’s signed first comparison value.

A span is marked exactly when either:

- **R < C** and **L < C**, or
- **R ≥ C** and **C < L**.

The second case deliberately includes equality between the reference and candidate values. It must not be replaced by a rule requiring both neighboring values to be strictly greater.

When marking is selected, traversal starts at the candidate and follows backward links until it reaches the newly reached record. Each visited record before that endpoint receives a read-modify-write that adds `0x40`. The endpoint itself is excluded.

After every differing-value boundary, whether or not marking occurred:

1. Fetch the newly reached record’s forward link and use that address as the new reference record.
2. Use the newly reached record as the new candidate.

On ordinary completion of the backward scan, processing advances to the next descriptor.

### 3. Transition to the second phase

There are two entry paths:

**Ordinary entry:** After all descriptors have been processed, the second-phase index is explicitly set to zero.

**Early entry:** If an enabled descriptor’s initial forward search returns to its starting record, the remaining descriptors are abandoned. The shared index is incremented once and execution continues in the second phase.

Thus, if descriptor index **d** triggers early entry, the first second-phase index is **d + 1**. The record bound, not the descriptor bound, then determines whether any record is processed.

This behavior also applies to a one-record ring: following its forward link immediately returns to the start.

### 4. Second-phase record processing

At the top of each second-phase iteration, the current unsigned index is compared against the current record count. If the index is greater than or equal to that count, the function returns.

Otherwise, the indexed record is located at the record-storage address plus 48 times the index. Its flag word is read and retained for any later update in that iteration.

Both comparison endpoints initially refer to the indexed record itself.

#### Record without `0x40`

If the saved flag word lacks `0x40`, no link search occurs. Both endpoints remain the indexed record.

The subsequent strict comparison conditions cannot succeed for a stable comparison field, because they would require a value to be strictly less than itself. Consequently, under stable, nonaliased inputs, no flag write occurs for this record.

#### Record with `0x40`

If the saved flag word includes `0x40`, two searches occur in order.

First, search forward:

- Advance through the forward link.
- If the reached address is the indexed record, skip the remainder of this iteration.
- Otherwise, continue while the reached record’s second comparison field equals the indexed record’s second comparison field.

Only after finding a forward record with a different value does the backward search begin:

- Advance through the backward link from the indexed record.
- If the reached address is the indexed record, skip the remainder of this iteration.
- Otherwise, continue while the reached record’s second comparison field equals the indexed record’s second comparison field.

The forward search therefore completes before any backward-search link traversal. A forward search returning to the start prevents the backward search entirely.

### 5. Second-phase flag classification

After any required searches complete, define:

- **V**: the indexed record’s signed second comparison value.
- **F**: the forward endpoint’s signed second comparison value.
- **B**: the backward endpoint’s signed second comparison value.

The function applies these conditions in order:

1. If **F < V < B**, store the saved flag word with `0x80` added.
2. Otherwise, if **B < V < F**, store the saved flag word with `0x100` added.
3. Otherwise, perform no flag write.

All inequalities are strict. Equal endpoint or center values do not satisfy the corresponding condition.

The stored value is formed from the flag word saved near the start of that iteration. There is no second flag-word read immediately before this store.

After classification or a search-return skip, increment the index and repeat the second-phase bound check.

## Side effects

The only explicit writes are to record flag words at byte offset `+16`.

- First-phase writes add `0x40`.
- Second-phase writes add either `0x80` or `0x100`.
- No existing bit is explicitly cleared.
- Neither link field nor either comparison field is explicitly rewritten.
- There are no explicit writes to the control structure or descriptors.

A first-phase write occurs once per visited member of each selected span. Overlapping spans or descriptors can cause repeated writes to the same flag word, including writes whose numeric value is unchanged because `0x40` was already present.

The second phase can preserve both `0x80` and `0x100` in the same flag word if one was already set and the current classification adds the other. It does not enforce exclusivity.

There is no transactional behavior. Earlier flag writes remain if a later traversal fails to terminate or encounters invalid memory.

No external calls, I/O, allocation, deallocation, locking, or explicit synchronization are present. Concurrent mutation is not covered by a consistency guarantee.

## Acceptance examples

These are conditional contract examples derived from static evidence. They have not been executed.

### Disabled descriptor with no records

Given one readable descriptor with enable value zero, and a record count of zero:

- Its starting-record address is fetched.
- No record is dereferenced through that address.
- Ordinary second-phase entry starts at zero and returns immediately.
- No flag word is written.

### Uniform first-field ring causes early phase entry

Given descriptor index 2 is enabled, and its valid circular ring has identical first comparison values throughout:

- Its initial forward search eventually returns to its start.
- Descriptors after index 2 are not processed.
- Second-phase processing begins at record index 3.
- Records 0 through 2 are not visited by the second phase.

If the record count is at most 3, the function returns without any second-phase record access.

### Ordinary descriptor completion does not skip record zero

Given every enabled descriptor finds a differing first comparison value and completes its backward scan:

- The second-phase index is reset to zero after descriptor processing.
- Record zero is considered if the record count is nonzero.

### First-phase upper-valued candidate

At a reached differing-value boundary, suppose **R = 2**, **C = 7**, and **L = 3**.

Both surrounding values are below the candidate value. The candidate-inclusive, endpoint-exclusive backward span receives `0x40`.

### First-phase reference equality is significant

At a reached differing-value boundary, suppose **R = 4**, **C = 4**, and **L = 9**.

The span is marked because **R ≥ C** and **C < L**. Requiring **R > C** would produce a different result and would not match the supplied comparisons.

### First-phase nonselected boundary

Suppose **R = 8**, **C = 5**, and **L = 1**.

Neither marking condition holds. No span write occurs at this boundary, but the reference and candidate are still updated before scanning continues.

### Second-phase increasing endpoint order

Given a record with `0x40`, successfully found endpoints, and second comparison values **F = −4**, **V = 0**, **B = 6**:

- `0x80` is added to the saved flag word.
- Existing bits remain set.
- `0x100` is neither added nor cleared by this classification.

The negative value participates in a signed comparison.

### Second-phase decreasing endpoint order

Given **F = 12**, **V = 7**, and **B = 1**, with the required searches completed:

- `0x100` is added.
- If `0x80` was already set, both bits remain set afterward.

### Equal second-field ring

Given a record carrying `0x40` whose forward ring has the same second comparison value everywhere:

- The forward search returns to the indexed record.
- No backward search occurs.
- No second-phase flag write occurs for that iteration.

### Existing classification without `0x40`

Given a stable record whose flag word contains `0x80` but not `0x40`:

- No link search occurs.
- Its classification bits remain unchanged.
- The function does not clear or recompute its existing `0x80`.
