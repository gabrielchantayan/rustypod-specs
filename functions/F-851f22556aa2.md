# F-851f22556aa2

## Purpose

F-851f22556aa2 conditionally copies one of six four-word records from a dependency-supplied context into caller-supplied storage.

The function first obtains a context through F-7fba0909c452. A null result causes an immediate return. With a non-null context, selectors from `0x3000` through `0x3005`, inclusive, select records numbered zero through five. Other selectors cause no record copy; instead, the function sets the context’s first word to `0x500` if that word is zero.

This is a description of the supplied static evidence. The interpretation of the first context word as a status or error field, and of the copied words as a particular kind of record, is inferred intent rather than an established semantic meaning.

## Interface

### Inputs

The function has two explicit inputs:

- **Selector:** an integer value used to choose a record or enter the out-of-range path.
- **Destination:** a pointer to integer storage. On a selected-record path, four consecutive words are written starting at this address.

There is no explicit context input. The context pointer comes from F-7fba0909c452.

### Width and arithmetic model

The supplied representation uses integer words and unsigned arithmetic consistent with a 32-bit model. Under that model:

- One word occupies four bytes.
- The selector has a 32-bit integer representation.
- Record values and the context’s first word are 32-bit words.
- The range check subtracts `0x3000` using unsigned 32-bit arithmetic and compares the result with five.

The exact original ABI and type declarations are not independently available. Byte offsets below are conditional on this 32-bit, four-byte-word model. Word indices and access ordering follow directly from the supplied representation.

The selector test is not merely an upper-bound check. Unsigned subtraction excludes values below `0x3000` as well as values above `0x3005`. Negative signed selector values also fail the range check.

## Behavior

### 1. Obtain the context

F-851f22556aa2 calls F-7fba0909c452 once, without explicit arguments, before validating the selector or accessing the destination.

The returned value is treated as a pointer to integer words.

If it is null, the function returns immediately. It does not inspect the selector for the purpose of choosing a subsequent path, read the first context word, or access the destination.

Any effects of the dependency precede this return and remain outside the established direct behavior of F-851f22556aa2.

### 2. Classify the selector

For a non-null context, exactly these selectors enter the record-copy path:

`0x3000`, `0x3001`, `0x3002`, `0x3003`, `0x3004`, and `0x3005`.

All other 32-bit selector values enter the out-of-range path.

The unsigned comparison is important at the boundaries. A selector of `0x2FFF` does not select an earlier record: subtracting `0x3000` produces an unsigned value greater than five. Similarly, `0x3006` does not select a seventh record.

Only accepted selectors are subsequently normalized to a record number by subtracting `0x3000`. The resulting record number is zero through five, so the shown record-index arithmetic does not overflow in that path.

### 3. Handle an out-of-range selector

The function reads word zero of the returned context.

- If the read value is zero, it writes `0x500` to that same word.
- If the read value is nonzero, it leaves the word unchanged.

It then returns without directly accessing the destination or the record table.

This path does not replace an existing nonzero value, regardless of whether that value is `0x500` or some other bit pattern. The supplied representation shows an ordinary conditional read and write, not an atomic compare-and-set operation.

### 4. Copy a selected record

For an accepted selector, the record number identifies one of six adjacent records. Each record consists of four consecutive words, and successive records begin four words apart.

The context-relative layout is:

| Selector | Record number | First word index | First byte offset | Four-word byte span |
|---|---:|---:|---:|---|
| `0x3000` | 0 | 165 | `0x294` | `0x294`–`0x2A3` |
| `0x3001` | 1 | 169 | `0x2A4` | `0x2A4`–`0x2B3` |
| `0x3002` | 2 | 173 | `0x2B4` | `0x2B4`–`0x2C3` |
| `0x3003` | 3 | 177 | `0x2C4` | `0x2C4`–`0x2D3` |
| `0x3004` | 4 | 181 | `0x2D4` | `0x2D4`–`0x2E3` |
| `0x3005` | 5 | 185 | `0x2E4` | `0x2E4`–`0x2F3` |

The table establishes accessed locations, not a requirement that all intervening context storage be read. For the last record, the final word begins at byte offset `0x2F0`; the four-word span ends at the exclusive offset `0x2F4`.

The copy occurs in four ordered steps:

1. Read the selected record’s first word, then write destination word zero.
2. Read its second word, then write destination word one.
3. Read its third word, then write destination word two.
4. Read its fourth word, then write destination word three.

There is no demonstrated snapshot of all four source words before writing begins. The function performs no range-path check or clearing of the first context word.

### 5. Account for overlapping storage

No non-overlap requirement or overlap check appears in the supplied representation.

With separate source and destination storage, the result is the selected four-word record. If the destination overlaps the context, an earlier destination write can modify a source word before a later read.

Consequently, this is not an overlap-safe snapshot-copy contract. Its established behavior is the ordered sequence of individual word reads and writes.

A destination that aliases the first context word can also change that word during an otherwise valid record copy. Thus, “the valid path does not update the first context word” is only true of its dedicated status-handling logic, not an unconditional promise about aliased memory.
