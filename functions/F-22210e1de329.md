# F-22210e1de329

## Purpose

F-22210e1de329 conditionally records a pair of 32-bit coordinate values and a one-byte classification in storage selected by a signed 16-bit index. When recording is enabled, it also refreshes two coordinate fields in the supplied object from the selected coordinate record.

Regardless of whether recording is enabled, the function increments the descriptor’s 16-bit index field. Consequently, a disabled call still advances the index; it is not a no-op.

The interpretation of the coordinate pair as a point, the classification as a path command, and the index as an append position are inferred intent rather than established semantics. The established behavior is the set of memory reads, writes, transformations, and ordering described below.

## Interface

### Inputs

The function accepts four arguments:

| Argument | Width and interpretation |
|---|---|
| Object address | A 32-bit address-valued argument identifying an object with the fields below. |
| First coordinate | A 32-bit signed integer value, written either unchanged or after a signed right shift by 16 bits. |
| Second coordinate | A 32-bit signed integer value, subject to the same transformation. |
| Classification selector | A 32-bit integer. Zero selects stored byte value 2; every nonzero value selects stored byte value 1. |

The supplied representation uses 32-bit integers and address-bearing fields, 16-bit short fields, and one-byte flags. It does not establish a portable ABI beyond that representation.

### Object layout

Offsets are byte offsets relative to the object address.

| Offset | Size | Role |
|---|---:|---|
| `0x14` | 4 bytes | Address of a descriptor. Read on every call. |
| `0x18` | 4 bytes | Cached first coordinate. Written only when recording is enabled. |
| `0x1c` | 4 bytes | Cached second coordinate. Written only when recording is enabled. |
| `0x51` | 1 byte | Recording-enable flag. Zero disables recording; any nonzero byte enables it. |
| `0x53` | 1 byte | Coordinate-transformation flag. Read only when recording is enabled. Any nonzero byte enables the right shift. |

### Descriptor layout

Offsets are relative to the descriptor address obtained from the object.

| Offset | Size | Role |
|---|---:|---|
| `0x02` | 2 bytes | Index field. Interpreted as signed when selecting a record; incremented on every call. |
| `0x04` | 4 bytes | Base address of coordinate records. Read only when recording is enabled. |
| `0x08` | 4 bytes | Base address of classification bytes. Read only when recording is enabled. |

Each coordinate record occupies eight bytes:

- The first coordinate occupies bytes 0–3.
- The second coordinate occupies bytes 4–7.

Classification storage uses one byte per index.

### Outputs and preconditions

There is no defined return value. Results are communicated through memory writes.

Every call requires readable access to the object’s descriptor-address field and enable flag, plus readable and writable access to the descriptor’s index field.

An enabled call additionally requires:

- Readable access to the transformation flag and both storage-base fields.
- Writable access to the selected eight-byte coordinate record.
- Writable access to the selected classification byte.
- Readable access to the coordinate record after the writes.
- Writable access to both cached-coordinate fields in the object.

The function performs no visible checks for null addresses, buffer bounds, capacity, alignment, index validity, or overlapping storage. Those are caller obligations if normal completion is required.

## Behavior

### Descriptor selection and enable decision

The function first reads the descriptor address from object offset `0x14`. It then reads the byte at object offset `0x51`.

The descriptor address is therefore read even when recording is disabled. The function retains the descriptor address selected at entry; it does not reread the object’s descriptor-address field before incrementing the index.

If the enable byte is zero, the function skips all coordinate and classification processing and proceeds directly to index advancement.

### Enabled record selection

When recording is enabled, the function reads the descriptor’s two-byte index and interprets it as a signed 16-bit value. Denote that captured value by \(k\).

It then reads:

1. The classification-storage base address from descriptor offset `0x08`.
2. The coordinate-storage base address from descriptor offset `0x04`.

The selected coordinate record begins at:

\[
\text{coordinate base} + 8k
\]

The selected classification byte is at:

\[
\text{classification base} + k
\]

A negative index selects addresses before the respective bases. There is no conversion to an unsigned index and no rejection of negative values.

Because \(k\) is signed 16-bit, the mathematical displacement \(8k\) ranges from −262,144 through 262,136. That multiplication fits within a signed 32-bit integer. Adding the displacement to an address can nevertheless exceed an address-space boundary or select invalid storage; the function does not guard against either condition.

### Coordinate transformation

After selecting the record and reading the storage bases, the function reads the byte at object offset `0x53`.

- If the byte is zero, both coordinate arguments remain unchanged.
- If the byte is nonzero, each signed 32-bit coordinate undergoes a right shift by 16 bits before being stored.

The supplied representation expresses a signed shift. Under arithmetic, sign-extending shift semantics, the transformation is:

\[
q = \left\lfloor \frac{v}{65536} \right\rfloor
\]

for signed coordinate value \(v\).

For negative values, this differs from division rounded toward zero. For example, −1 becomes −1 under arithmetic shifting, not zero. The exact target instruction implementing the signed shift is not supplied, so this negative-value interpretation remains conditional on arithmetic-shift semantics.

Both coordinates are controlled by the same flag observation.

### Record and classification writes

The function performs the following writes in order:

1. The transformed or unchanged first coordinate to the selected record’s first four bytes.
2. The transformed or unchanged second coordinate to the selected record’s next four bytes.
3. One classification byte to the selected classification address.

The classification byte is determined solely by whether the fourth argument is zero:

| Selector | Stored byte |
|---|---:|
| Zero | 2 |
| Any nonzero 32-bit value | 1 |

The selector is not truncated and stored directly. Negative nonzero values select byte value 1 just as positive nonzero values do.

### Cache refresh

After writing the classification byte, the function reads the second coordinate back from the selected coordinate record. It then reads the first coordinate from that record and writes it to object offset `0x18`. Finally, it writes the previously read second coordinate to object offset `0x1c`.

The cache is therefore refreshed from memory, not directly from the coordinate arguments.

For disjoint storage with no external mutation, the cached values equal the coordinate values just stored. With overlapping storage, the readback distinction matters. For example, a classification-byte write that overlaps a coordinate can change the value subsequently copied into the object.

The second coordinate is captured before the cached first-coordinate write. If the cached first-coordinate destination overlaps the record’s second coordinate, that write does not change the already captured value later written to object offset `0x1c`.

### Unconditional index advancement

After the enabled branch, or immediately after skipping it, the function reads the descriptor’s two-byte index field again, adds one, and writes a two-byte result to the same field.

This is a fresh read. The increment is not necessarily based on the index captured for record selection. If enabled-path writes overlap the index field, the final increment uses the field’s value after those writes.

The addition is performed at an integer width sufficient to represent every signed 16-bit input plus one. The boundary issue is the subsequent two-byte storage, not overflow of that addition.

Under ordinary low-16-bit storage semantics, the field advances modulo 65,536:

- −1 advances to 0.
- 0 advances to 1.
- 32,767 stores the bit pattern `0x8000`, interpreted as −32,768 on the next signed read.
- −32,768 advances to −32,767.

The supplied representation does not independently establish the target’s narrowing-conversion semantics at the 32,767 boundary.

## Side effects

For valid, disjoint storage and no concurrent mutation:

| Condition | Directly written storage |
|---|---|
| Recording disabled | Descriptor index only |
| Recording enabled | Selected coordinate pair, selected classification byte, both cached coordinates, descriptor index |

No allocation, deallocation, ownership transfer, external call, or explicit synchronization is visible. The function mutates caller-provided storage; it does not visibly acquire or release that storage.

The listed effects are not transactional. Coordinate writes precede the classification write, cache writes follow the classification write, and index advancement occurs last. If a later access fails, earlier writes may already have occurred.

The source-level access order is established by the supplied representation. It is not a guarantee of hardware atomicity, inter-thread synchronization, memory-mapped-device ordering, or an exact bus-access trace.

Invalid addresses and insufficient buffers have no defined recovery behavior here. There is no error return or rollback path. Platform fault handling, if any, is outside this function’s visible contract.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. No runtime tests have been performed. Unless stated otherwise, storage is valid, disjoint, and unchanged by other execution.

### Disabled recording still advances

Given a zero enable byte and index 7:

- The final index is 8.
- Coordinate records, classification bytes, and cached coordinates are unchanged.
- The transformation flag and storage-base fields are not read by this path.
- A valid descriptor index remains necessary even though recording is disabled.

### Enabled recording without transformation

Given a nonzero enable byte, zero transformation byte, index 3, coordinates 123 and −456, and selector zero:

- Coordinate record 3 receives 123 and −456.
- Classification byte 3 receives 2.
- The cached coordinates become 123 and −456.
- The final index is 4.

### Nonzero selector classification

Given an enabled call with selector −9:

- The selected classification byte receives 1.
- The magnitude and sign of the selector do not otherwise affect the result.

### Signed coordinate transformation

Given enabled recording, a nonzero transformation byte, and arithmetic signed-shift semantics:

- 98,304 becomes 1.
- −98,304 becomes −2.
- −1 becomes −1.
- The maximum signed 32-bit value becomes 32,767.
- The minimum signed 32-bit value becomes −32,768.

These transformed values are stored as 32-bit coordinates and subsequently read back into the cached fields.

### Negative index

Given index −1 and enabled recording:

- The coordinate destination begins eight bytes before the coordinate base.
- The classification destination is one byte before the classification base.
- If those addresses are valid, processing proceeds without an index error.
- With no overlap affecting the index, its final value is zero.

### Signed index boundary

Given index 32,767 and ordinary low-16-bit storage semantics:

- An enabled call selects coordinate displacement 262,136 and classification displacement 32,767.
- The final index bit pattern is `0x8000`.
- A later call interprets that pattern as −32,768.

The function provides no capacity check or special full-buffer behavior at this boundary.

### Classification overlapping the index

Suppose the selected classification byte aliases part of the descriptor’s index field, while the coordinate and cache writes do not affect that field:

- Record selection uses the original signed index.
- The classification write changes the index’s stored representation.
- The final increment reads that changed representation and adds one.

The exact numeric result depends on which byte is overlapped and on target byte order. It must not be specified as simply “original index plus one.”
