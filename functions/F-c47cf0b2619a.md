This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### 1. Admission

Processing begins only if both conditions hold:

1. The third argument is nonnull.
2. The second argument, interpreted as a signed 32-bit integer, is nonnegative.

Under the represented 32-bit interpretation, the second condition admits bit patterns from `0x00000000` through `0x7fffffff` and rejects patterns from `0x80000000` through `0xffffffff`.

A zero second argument is therefore admitted. The second argument is not required to be nonnull by this function.

If either condition fails, the function returns without calling any listed dependency and without directly reading pointed-to memory.

### 2. Local pointer storage and lookup

For an admitted invocation, the function initializes three local pointer slots with the second, third, and fourth arguments respectively. These are local assignments; no caller-owned pointer slot is directly updated.

It then invokes F-798b2f89ac14 with:

1. The first argument.
2. The second argument.

The result is treated as 64 bits. Its low 32 bits are converted into a byte address and placed in the local slot initially containing the third argument.

If that address is null, processing ends. The upper 32 bits of the lookup result cannot cause further processing when the low-word address is null.

If that address is nonnull, the function reads exactly one byte from it and zero-extends that byte for a zero test. An initially extracted upper result word does not affect this decision: on the nonnull path, the byte read replaces it.

If the byte is zero, processing ends. The function does not directly inspect a second byte, determine a length, or scan for a terminator.

### 3. Preparation

When the lookup-derived address is nonnull and its first byte is nonzero, the function saves that address into the local slot initially containing the fourth argument. The original fourth-argument value is thereby discarded.

It then invokes F-d3922c7fe0ec with the address of the local slot holding the lookup-derived pointer.

This dependency can change that slot. Its return value is not used. The caller does not subsequently use the slot’s updated value to select a branch or as the saved pointer passed to the final dependency.

The separately saved pointer value is the lookup-derived address as it existed before F-d3922c7fe0ec was called. This preserves the pointer value, not the contents or validity of the addressed memory. The dependency’s effects on that memory and on shared state are unknown.
