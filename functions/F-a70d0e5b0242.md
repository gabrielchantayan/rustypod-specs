# F-a70d0e5b0242

## Purpose

The supportable contract is an **ordered, conditional description of memory effects**, not a validated executable specification. The representation reports invalid instruction data, includes right shifts by the represented operand width, and terminates at invalid-instruction markers. These limitations affect arithmetic interpretation and reachability.

No allocation, release, ordinary dependency invocation, or successful return is visible. Initialization, dispatch, and state installation are possible interpretations, not established requirements.

## Behavior

### Derived quantities and ordering

The following descriptive terms identify values, not additional interface fields:

- **Selector:** the unsigned 32-bit representation of the first input after arithmetic right shift by 23.
- **Adjusted selector:** selector minus 0x38.
- **Reduced selector:** selector minus 0xE0, followed by clearing bit 31.
- **Half-index:** reduced selector shifted right by one.
- **Halfword-region base:** **twice the quantity selector minus 0xE0**, calculated as unsigned 32-bit arithmetic:
  \[
  2 \times (\text{selector}-0xE0)\pmod{2^{32}}.
  \]

The halfword-region base is not twice the selector followed by subtraction of 0xE0. It also does not use the reduced selector.

Under conventional arithmetic right-shift semantics, a nonnegative first input gives a selector from 0 through 255. A negative input gives an unsigned selector from 0xFFFFFF00 through 0xFFFFFFFF.

The sequences below preserve the displayed order of separate memory-effect expressions. They do not impose an unsupported evaluation order among operands within one expression. Previously captured values remain captured values unless an explicit later read is identified.

## Acceptance examples

These are conditional static review cases, not executed tests.

1. **Initial truncation.** A second input of 0x00012345 produces an initial halfword value of 0x2345. The destination still uses the full second input as its displacement.

2. **Signed selector.** A first input of −1 produces selector 0xFFFFFFFF under conventional arithmetic right shift, not 0x1FF.

3. **OR displacement.** Selectors zero and 0x88 both yield lookup displacement 0x88.

4. **Correct halfword-region arithmetic.** With selector 0xE0, the halfword-region base is zero. With selector zero, unsigned 32-bit subtraction and multiplication give 0xFFFFFE40. Subtracting 0xE0 after multiplication would give a different, incorrect result.

5. **Uninitialized first halfword.** Absent aliasing, halfword-region offsets 4, 6, and 2 receive 0xFFFF in that order; offset 0 retains its prior contents until read.

6. **Early termination.** If the first dependency address has its sign bit set and execution reaches the test, the derived-base offset-4 write has already occurred. The subsequent offset-0x12 writes do not occur on that branch.

7. **Signed halfword collapse.** On the continuing branch, captured halfword 0x8000 yields 0xFFFFFFFF at derived-base offset 8; 0x7FFF yields zero.

8. **Repeated publication reads.** Suppose the self-store targets the published-address global and changes its value. The half-index store uses the subsequent global read plus four, not necessarily the originally published pointer-derived address. No fixed ordering between the self-store’s destination and value reads is required.

9. **Late reset read.** Suppose step 6 publishes upper halfword 0x1234, but an intervening aliasing write changes that view to 0xABCD. The final combined reset value is 0xABCDEA70, not 0x1234EA70.

10. **Unresolved shifts.** A model must not silently interpret a 32-bit right shift by 32 as zero, an unchanged operand, or a widened shift. Selecting one requires additional evidence.
