# F-e80871fb2c8c

## Purpose

F-e80871fb2c8c scans values from an indexed input object and forwards selected values to an opaque output destination. It stops either when it encounters an unpaired delimiter or when its captured input bound is reached.

The distinguished values are:

| Value | Conventional character interpretation | Role |
|---|---|---|
| `0x23` | `#` | Introduces a possible two-value pair |
| `0x5C` | Backslash | Delimiter unless consumed as the second value of a recognized pair |
| `0x2F` | `/` | Delimiter unless consumed as the second value of a recognized pair |
| `0x3A` | `:` | Delimiter |

A recognized pair consists of `0x23` followed by `0x5C`, `0x2F`, or `0x23`. Both values are forwarded unchanged. In particular, the leading `0x23` is retained; this function does not remove an escape marker.

The distinction between stopping conditions is externally visible:

- On a delimiter, the function writes the position immediately after that delimiter to the caller’s cursor storage.
- On exhaustion, the function writes `1` to the caller’s status byte and does not directly commit its local scanning position to the cursor storage.

Calling this a segment scanner is an interpretation of its structure, not an established application-level purpose.

## Interface

The function has four arguments and no explicit return value.

| Argument | Established role and representation |
|---|---|
| First argument | An opaque 32-bit value. The function does not directly inspect, forward, or otherwise use it. |
| Input object | A machine address represented as a 32-bit value in the supplied representation. A four-byte field at byte offset `4` is read during initialization. The same object address is subsequently passed to the indexed-access dependency. |
| Cursor storage | Address of a readable unsigned 32-bit position. The function reads it once after initialization and may later overwrite it with a delimiter-successor position. |
| Status storage | Address of a writable one-byte value. The function initially writes `0`; on exhaustion it writes `1`. |

The cursor is an unsigned 32-bit quantity. The captured input bound is also unsigned 32-bit. Their comparison is unsigned. Position increments, including the lookahead position and committed successor position, use 32-bit unsigned arithmetic.

Values returned by indexed access are represented as signed 32-bit integers. Comparisons against the distinguished values are exact integer comparisons. Ordinary values are forwarded to the output dependency without a visible narrowing conversion. The function therefore does not itself establish that all accessed or emitted values are bytes, Unicode scalar values, or characters in any particular encoding.

## Behavior

### Initialization and observable ordering

Before scanning, the function performs these actions in order:

1. Calls F-5b24edfb22c0 with no arguments and captures its 32-bit result as the output handle.
2. Reads the four-byte field at input-object offset `4`.
3. Passes that field value to F-d8cbf9aa79a9 and captures its unsigned 32-bit result as the input bound.
4. Writes `0` to the status byte.
5. Reads the unsigned 32-bit initial cursor into a local scanning position.

These calls occur even if the initial cursor will already be at or beyond the captured bound.

This order matters when arguments alias or dependencies have side effects. For example, the status-byte write precedes the cursor read. If those storage regions overlap, that write can alter the position subsequently read. Similarly, the field at input-object offset `4` is read only after F-5b24edfb22c0 returns.

The bound and output handle are captured once. The function does not refresh them during scanning. The caller’s cursor storage is not reread after initialization.

### Bound handling

At the beginning of each scan iteration, the function compares the local position with the captured bound.

If the position is greater than or equal to the bound:

- It writes `1` to the status byte.
- It returns immediately.
- It makes no indexed-access call for that iteration.
- It does not directly write the local position to cursor storage.

Thus an initial cursor beyond the bound is treated the same as one exactly at the bound. There is no separate invalid-position error.

If the position is below the bound, the function obtains the current value by calling F-08e2860e8e52 with the input object and local position.

### Ordinary values

A current value other than `0x23`, `0x5C`, `0x2F`, or `0x3A` is forwarded by one call to F-f6ff441ad60a, using the captured output handle and that value.

The local position then advances by one, and scanning continues.

No return value from the output dependency is inspected.

### Delimiters

When the current value is `0x5C`, `0x2F`, or `0x3A`, and it has not already been consumed as the second value of a recognized pair:

- The delimiter is not forwarded.
- The function writes the local position plus one to the 32-bit cursor storage.
- It returns immediately.

The function does not read the following input value on this path.

Its only direct status-byte write on a delimiter path is the earlier initialization to `0`. A final status value of `0` therefore depends on the absence of overlapping writes and intervening dependency effects.

### Pair recognition

When the current value is `0x23`, the function always performs a lookahead access through F-08e2860e8e52 at the local position plus one.

There is no separate bound check before this lookahead.

If the lookahead value is `0x5C`, `0x2F`, or `0x23`:

- The function calls F-f6ff441ad60a with the captured output handle and `0x23`.
- After that call returns, it calls F-f6ff441ad60a with the same captured handle and the captured lookahead value.
- The local position advances by two in total.
- Scanning resumes with the next bound comparison.

The second value is consumed as part of the pair. A paired backslash or slash does not terminate scanning. A paired `0x23` is not reconsidered as the start of another pair.

The second output argument remains the already captured lookahead value even if the first output call changes the input object. The function does not reread that value between output calls.

If the lookahead is anything else, including `0x3A`:

- Only the current `0x23` is forwarded.
- The local position advances by one.
- Scanning continues normally.

The lookahead value is not retained for the next iteration in this case. If scanning reaches that position, the value is requested again. Consequently, a dependency that returns different results on repeated accesses can affect the later decision.

### Arithmetic and progress

All position additions are modulo \(2^{32}\). No overflow check or saturation is present.

The function advances its local position by one for an ordinary emitted value, by two for a recognized pair, and by one in the cursor value it commits after a delimiter.

The beginning-of-iteration bound comparison does not validate the lookahead index. In particular, a `0x23` at the final in-bound position causes an access at the bound. If that access returns a recognized pair value, the function emits both values even though the second access was outside the range admitted for a primary iteration.

Modulo arithmetic can also make a recognized pair wrap the local position to zero near the maximum 32-bit position. Universal termination therefore cannot be inferred solely from the presence of the bound comparison.

## Side effects

The function’s direct memory effects are limited to:

- Reading the input object’s four-byte field at offset `4`.
- Reading the initial four-byte cursor.
- Writing `0` to the status byte.
- Writing `1` to that byte on exhaustion.
- Writing a four-byte successor cursor on delimiter termination.

It does not directly write input contents or explicitly allocate or release memory.

Output is performed incrementally through F-f6ff441ad60a. There is no visible buffering, rollback, transaction boundary, or cleanup path. Earlier output calls have already occurred when a later delimiter is found or the bound is reached.

The function ignores the results of output calls and contains no visible failure-status handling for any dependency. If a dependency does not return normally, subsequent actions described here are not guaranteed to occur.

These direct effects do not constrain dependency effects. In particular, the supplied evidence does not prove that dependencies preserve globals, cursor storage, status storage, the input object, or the resource associated with the output handle.

Aliasing can make otherwise separate interface effects interact. For example, overlapping status and cursor storage may cause the delimiter cursor write to overwrite the initialized status byte. No non-aliasing check is present.

## Acceptance examples

These examples are conditional: assume stable indexed values, valid argument storage, no relevant aliasing, dependencies that return normally, and no dependency mutation of cursor or status storage. “Emitted” means the ordered values supplied to F-f6ff441ad60a, not verified bytes in an external buffer.

1. **Initial position equals the bound.**  
   The initial status write is `0`, followed by a write of `1`. No indexed access or output call occurs. The cursor is not directly updated. Both initialization dependencies still run.

2. **Initial position exceeds the bound.**  
   Behavior is the same as exhaustion at equality. The function does not clamp the position or report a distinct error.

3. **An ordinary value followed by a slash.**  
   Starting at position zero with indexed values `A`, `/` and a bound admitting both positions, the emitted sequence is `A`. The cursor becomes `2`, and the status remains `0`. The slash is not emitted.

4. **A delimiter at the initial position.**  
   If the initial position is `7`, that position is in bounds, and its value is `:`, the cursor becomes `8`. Nothing is emitted.

5. **A paired slash followed by a colon.**  
   With values `#`, `/`, `:` from position zero, the emitted sequence is `#`, `/`. The colon terminates scanning and commits cursor `3`.

6. **A hash followed by a colon.**  
   With values `#`, `:` from position zero, the colon is first accessed as lookahead and does not form a recognized pair. The hash is emitted. The colon is then accessed again as the current value, terminates scanning, and commits cursor `2`.

7. **A paired hash followed by a slash.**  
   With values `#`, `#`, `/`, the emitted sequence is `#`, `#`. The second hash is consumed by the pair, so it does not pair with the slash. The slash terminates scanning and commits cursor `3`.

8. **Exhaustion after ordinary output.**  
   With two ordinary values and bound `2`, starting at zero, both values are emitted and status becomes `1`. The caller’s cursor remains at its original value, rather than becoming `2`.

9. **A final in-bound hash.**  
   With bound `1` and a hash at position zero, indexed access at position `1` still occurs. If that access returns a slash, the emitted sequence is hash then slash; the next bound comparison produces exhaustion. If it returns an unrecognized value, only the hash is emitted before exhaustion. Whether the access itself is valid is dependency-defined.
