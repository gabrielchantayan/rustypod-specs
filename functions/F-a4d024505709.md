# F-a4d024505709

## Purpose

F-a4d024505709 computes a candidate position from a requested displacement, conditionally updates an origin field, performs associated movement and refresh processing, and returns whether the candidate differs from the initially observed position.

**Established behavior:** integer arithmetic, conditional object-field writes, dependency calls, virtual dispatch, and a Boolean position comparison.

**Inferred intent:** windowed navigation or scrolling, with aligned origin changes and movement propagation. These interpretations do not establish application-level units or dependency semantics.

The return value does not indicate whether the origin changed, whether notification occurred, or whether a dependency succeeded.

## Interface

The function receives four arguments:

1. **Object reference:** a pointer to mutable storage with the layout below.
2. **Requested displacement:** a signed 32-bit integer.
3. **Unused argument:** an opaque 32-bit value, neither read nor forwarded by the visible body.
4. **Mode:** a signed 32-bit integer. Only exact values `1` and `2` have special handling.

It returns a Boolean equal to **initial position ≠ candidate**.

## Behavior

### Arithmetic conventions

**Initial position** is the first result from F-30ee4f4bfdfc. **Entry origin** is the origin saved immediately afterward. **Effective displacement** initially equals the requested displacement. **Candidate** is the later range-selected position.

For F-870c4fcf7295:

- **Q(a, b)** denotes its ordinary return.
- **R(a, b)** denotes the additional register result consumed by mode-1 processing.

Quotient and remainder are plausible interpretations, not established semantics.

### Initial observation and normalization

First, call F-30ee4f4bfdfc with no explicit argument shown. Then read and save the entry origin.

If entry origin is negative, write zero to the origin field. The saved entry origin remains negative and is used later for movement calculations, refresh decisions, and final origin-change detection.

### Mode-1 displacement adjustment

Only mode `1` performs this stage.

Save the current origin after normalization. This saved value is retained across both comparisons and any intervening helper calls.

If initial position plus effective displacement is strictly below the saved origin:

- Read stride and retain it.
- Call F-870c4fcf7295 with initial position and that stride.
- Replace effective displacement with R minus the retained stride.

Next, independently of whether that adjustment occurred:

- Read stride again.
- Read window count for the comparison.
- Compare saved origin with initial position plus current effective displacement minus stride times window count.
- If saved origin is less than or equal to that expression, call F-870c4fcf7295 with initial position and this newly captured stride.
- Replace effective displacement with twice the captured stride, minus R, minus one.

Both adjustments can occur. The second uses the displacement produced by the first. A helper may change fields, but it does not replace the saved origin or captured stride used in the corresponding calculation.

### Candidate calculation

Call F-30ee4f4bfdfc again, now explicitly passing the object. Add effective displacement to its result.

Compute the upper bound as end position minus base position. Candidate selection is:

- If the displaced position exceeds the upper bound, choose the upper bound.
- Otherwise, choose the displaced position, replacing it with zero if negative.

This is not an unconditional clamp to a nonnegative interval. A negative upper bound is selected when the displaced position exceeds it.

The two position observations need not agree. The body does not establish purity or equivalent calling contracts for the two calls.

### Movement-branch selection

Compare candidate with current origin plus stride times window count.

- If candidate is strictly below that boundary, skip selector `2`.
- Otherwise, invoke object dispatch `0x0CC` with the object and selector `2`.
- A nonzero result selects the forward-origin branch.
- A zero result continues to the backward-origin check.

The backward check compares candidate with the then-current origin. Only if candidate is strictly smaller does it invoke object dispatch `0x0CC` with selector `1`. A nonzero result selects the backward-origin branch.

Selector `2` can therefore precede selector `1`. The backward comparison reloads origin after any selector-2 callback; it is not constrained to use the earlier boundary’s origin.

### Forward-origin branch

For mode `2`:

1. Capture current origin and write captured origin plus effective displacement.
2. Capture stride, then window count.
3. Compare end position minus base position with captured window count times captured stride plus captured origin plus effective displacement.
4. If the range is strictly smaller, call F-870c4fcf7295 with candidate and captured stride.
5. Replace origin with  
   **(1 − captured window count) × captured stride + captured stride × Q**.

Both stride and window count are captured **before** this corrective helper call and retained across it. Mutations to those fields by the helper do not alter that replacement expression. If correction is unnecessary, this alignment helper is not called and the initially written origin is not replaced by this expression.

For every other mode, including mode `1`:

1. Capture stride.
2. Call F-870c4fcf7295 with candidate and captured stride.
3. Read window count **after the helper returns**.
4. Write  
   **(1 − newly read window count) × captured stride + captured stride × Q**  
   to origin.

Thus a helper mutation to window count affects non-mode-2 alignment, but not mode-2 overflow correction. A helper mutation to stride affects neither expression’s captured stride.

After either path, read origin and replace it with zero if negative. This post-helper check observes the current field.

Then read the associated-object pointer. If nonnull:

- Retain that pointer as the movement receiver.
- Call F-870c4fcf7295 with current origin minus saved entry origin, and current stride.
- After the helper returns, read movement scale and multiply it by Q to obtain the movement amount.
- Subtract the amount from the current movement accumulator and store the result.
- Invoke the retained associated object’s dispatch `0x144` with receiver arguments `(0, −amount, 1, 0)`.
- Call F-d156b0b83eb3 with the embedded-state address and `(0, amount)`.

The amount is retained across the associated-object callback. That callback does not cause it to be recomputed for embedded-state processing.

### Backward-origin branch

For mode `2`, capture current origin, write origin plus effective displacement, and replace that sum with zero if negative.

For every other mode, capture stride, call F-870c4fcf7295 with candidate and captured stride, and write captured stride times Q to origin. There is no separate negative-origin clamp on this path.

Then read the associated-object pointer. If nonnull:

- Retain that pointer.
- Call F-870c4fcf7295 with saved entry origin minus current origin, and current stride.
- Read movement scale after the helper returns and multiply it by Q.
- Add the resulting amount to the current movement accumulator and store it.
- Invoke retained associated-object dispatch `0x144` with `(0, amount, 1, 0)`.
- Call F-d156b0b83eb3 with the embedded-state address and `(0, −amount)`.

In both movement branches, a null associated-object pointer suppresses the movement-amount helper call, accumulator update, associated-object dispatch, and embedded-state call. With a nonnull pointer, these operations are not suppressed merely because the amount is zero.

### Refresh processing

After either origin-movement branch, call F-3fac671648b8 with the object. If its result is nonzero, call F-0d27caf8e50d and then F-92bea7c30bd6, each with the object.

If neither movement branch was selected:

1. Call F-3fac671648b8.
2. If its result is nonzero and initial position differs from candidate, call F-3ba0d8b4ad23 with the object and initial position, then with the object and candidate.
3. Call F-3fac671648b8 again, regardless of the first result.
4. Call F-0d27caf8e50d followed by F-92bea7c30bd6 only if the second result is nonzero and saved entry origin is negative.

The two predicate calls are independent observations, including when no position-processing calls intervene.

Only if they differ, load the notification target. Only if that target is nonzero, call F-ca0f66276073 with these five arguments:

| 2 | Value read from the first referenced global 32-bit word |

Return initial position ≠ candidate. Later field mutations do not replace these retained comparison values.

## Side effects

Observable sequencing includes:

- Initial position call before entry-origin capture.
- Negative-origin normalization before mode processing.

- Movement accumulator update before associated-object dispatch.
- Associated-object dispatch before embedded-state processing.
- Refresh processing before final origin observation.

## Acceptance examples

These are conditional static deductions, not executed tests. Unless explicitly overridden, dependencies return normally, preserve relevant fields and globals, storage is valid, and all arithmetic is representable.

### Position change without origin movement

Given initial and second positions `12`, displacement `3`, mode `0`, origin `10`, stride `5`, window count `4`, and range `100`:

- Candidate is `15`, below forward boundary `30`.
- Neither selector is called.
- If both refresh-predicate results are zero, neither refresh pair nor two-position processing occurs.
- Origin remains `10`.
- Final position dispatch receives base position plus `15` and `1`.
- Return is true.

### Forward alignment with associated movement

Given initial and second positions `12`, displacement `23`, mode `0`, origin `10`, stride `5`, window count `4`, range `100`, selector `2` returning nonzero, and Q(35, 5) = `7`:

- Candidate is `35`.
- Origin becomes `20`.

**Additionally, if the associated-object pointer is nonnull**, movement scale is `8`, and Q(10, 5) = `2`:

- Accumulator decreases by `16`.
- Associated-object movement is `−16`.
- Embedded-state movement is `16`.

With a null pointer, all three effects are absent. If final origin remains `20` and target is nonzero, notification reports `20` using the then-read global-word values. Return is true.

### Backward alignment with complete branch conditions

Given initial and second positions `25`, displacement `−13`, mode `0`, origin `20`, stride `5`, window count `4`, range at least `12`, selector `1` returning nonzero, and Q(12, 5) = `2`:

- Candidate is `12`.
- Candidate is below forward boundary `40`, so selector `2` is skipped.
- Candidate is below origin, enabling selector `1`.
- Origin becomes `10`.

**If the associated-object pointer is nonnull**, movement scale is `8`, and Q(10, 5) = `2`, accumulator increases by `16`, associated movement is `16`, and embedded-state movement is `−16`. None of those effects occurs with a null pointer.

### Forward helper changes window count

Suppose forward alignment uses stride `5`, candidate `35`, Q(35, 5) = `7`, and the alignment helper changes window count from `4` to `6`, preserving other relevant state.

- In a non-mode-2 forward branch, count is read afterward: origin becomes `(1 − 6) × 5 + 35 = 10`.
- In mode `2`, if overflow correction was selected after capturing count `4`, origin becomes `(1 − 4) × 5 + 35 = 20`.

These expectations require the respective branch and correction conditions to hold. They distinguish retained and reloaded fields.

### Normalization without position change

Given entry origin `−3`, both positions `0`, displacement `0`, positive stride and count, positive range, and both refresh-predicate results zero:

- Origin becomes zero.
- Candidate equals initial position.
- A nonzero target triggers notification with origin zero.
- Final position dispatch is omitted.
- Return is false.

### Negative range and independent predicates

If displaced position is `0` and range is `−4`, candidate is `−4`, not zero. Subsequent branch selection remains conditional.

Separately, on a no-movement path with negative entry origin, a zero first refresh-predicate result omits position processing, while a nonzero second result still triggers the refresh pair.
