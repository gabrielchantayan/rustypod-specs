# F-81c906bf6e3a

## Purpose

F-81c906bf6e3a performs either a direct delegated operation or a bounded group operation associated with a request and its context.

In the group path, it derives a candidate range, processes selected members until a nonzero status occurs, and observes a one-byte member marker. If any examined member has that marker set, it subsequently sets the marker on every discoverable member in the selected range, including members not reached before an error. It then clears a context activity byte.

Both normally returning paths decrement a 32-bit context field and return a status.

These are established structural behaviors. Interpreting the group as a storage allocation unit, the marker as a particular application state, or the decrement as reference-count release would require additional evidence.

### Output

The return value is a 32-bit status:

- On the direct path, it is the result of F-78d1342ad960.
- On the group path, it starts at zero.
- It becomes the result of a selected-member acquisition or, after successful acquisition, the result of F-78d1342ad960.
- A nonzero status prevents further iterations of the first pass.
- Marker propagation and final context updates do not replace the status.

Zero therefore acts as “continue” within this function. No specific meaning is established for individual nonzero values.

### Preconditions

The function performs no explicit argument validation.

For a normal defined execution, the request and captured context must support the accesses above. Any member address dereferenced after successful acquisition must also be valid. Lookup-produced addresses are checked for zero before marker access; acquisition-produced addresses are not.

Arithmetic and range assumptions are discussed under **Uncertainties**. In particular, the function does not validate that the initial grouping value is a power of two, that the requested member number is positive, or that signed arithmetic remains representable.

## Behavior

### Entry and path selection

The function first captures the context address from the request. It initializes the return status to zero and the local member slot from the fourth argument.

It then:

1. Reads the context words at `0xc0` and `0x40` and passes them, in that argument order, to F-870c4fcf7295.
2. Retains that helper’s 32-bit result as the initial grouping value.
3. Calls F-b93e3fe564f6 with the captured context address.
4. Reads the context byte at `0x14`.

The direct path is selected if the byte is nonzero or the retained grouping value, interpreted unsigned, is less than two.

The order of evaluation of the two context-word reads used as arguments to the initial helper is not established by the supplied representation. Both supply that call; the preparation call follows it.

The path-selection byte is read after F-b93e3fe564f6. Consequently, changes that helper makes to the byte can affect path selection. Changes it makes to the request’s context word do not redirect this function’s own subsequent context accesses: the original context address has already been captured.

### Direct path

The function calls F-78d1342ad960 with the request address and retains its result.

It does not directly write the context activity byte at `0x16` on this path. In particular, it does not clear a pre-existing nonzero value there.

It then performs the common final decrement and returns the delegated status.

### Group setup

The group path writes one to the context activity byte at `0x16`.

It reads the request’s member number and derives a group start using a 32-bit mask operation:

- Subtract one from the member-number bit pattern.
- Clear every bit selected by the grouping value minus one.
- Add one.

For a positive member number and a power-of-two grouping value, this produces a one-based aligned group start. That interpretation is conditional; the observed operation is the mask operation, not division or general-purpose rounding.

The function initializes a local “marker observed” condition to false, then calls F-f3192f39e4f6 with the captured context.

The returned value and the request’s member number are compared as unsigned 32-bit quantities. The candidate count is chosen as follows, with the first condition taking precedence:

- If the returned value is below the request’s member number, the count becomes the inclusive distance from the computed group start through the request’s member number.
- Otherwise, if the returned value is below the computed end of the original group, the count becomes the inclusive distance from the group start through that returned value.
- Otherwise, the original grouping value remains the count.

Thus a returned bound below the requested member does **not** directly truncate the range to that bound. In that case, the selected range ends at the requested member.

The group start is computed before F-f3192f39e4f6, while the request member used for the subsequent comparisons is read after it. No preservation of request state by the helper is established.

### First pass: conditional processing and marker observation

The function traverses consecutive candidate numbers beginning at the computed group start. The loop continues only while:

- The signed loop index is less than the count interpreted as a signed 32-bit integer; and
- The retained status is zero.

For each candidate, it compares that candidate with the request’s member number as read at that point.

If they are equal, it selects the processing branch without calling F-811a25bdbe21.

Otherwise, it reads the context word at `0x54` and calls F-811a25bdbe21 with that word and the candidate number:

- A zero result selects the processing branch.
- A nonzero result selects the lookup-only branch.

The request member field is not captured once for the whole first pass. Its value can therefore affect different iterations differently if intervening calls modify it.

#### Processing branch

The function calls F-870c4fcf7295 with the constant `0x40000000` and the current context word at `0x40`.

If that result plus one equals the candidate number, the function skips acquisition and delegated processing for that candidate. It does not inspect a member marker through this branch.

Otherwise:

1. It calls F-133a6620fb39 with the captured context, candidate number, address of the writable local member slot, and a final zero argument.
2. It retains that helper’s status.
3. If the status is nonzero, it does not call the member-processing helper, inspect the member marker, or call F-44d249c54e70 for this candidate.
4. If the status is zero, it calls F-78d1342ad960 with the value currently held in the local member slot.
5. It retains that result as the function status.
6. It reads the byte at offset `0x1e` from the address currently held in the local member slot.
7. If the byte is nonzero, it records that a marker has been observed.
8. It calls F-44d249c54e70 with no explicit arguments.

The marker read and the no-argument helper call occur even when F-78d1342ad960 returns a nonzero status. That error affects continuation of the first pass, not these remaining actions for the current candidate.

No zero-address check protects the marker read after successful acquisition. The local slot begins with the fourth argument and is reused across iterations; this function does not reset it before each acquisition.

#### Lookup-only branch

The function calls F-c1f06f89d6d7 with the captured context and candidate number, replacing the local member slot with its result.

A zero result produces no marker read. A nonzero result is inspected at offset `0x1e`; a nonzero byte records that a marker has been observed.

This branch does not update the retained status, call F-78d1342ad960, or call F-44d249c54e70.

### Second pass: marker propagation

If no marker was observed, the second pass is omitted.

If a marker was observed, the function traverses the entire selected candidate range again. This pass is not conditioned on the retained status.

For each candidate, it calls F-c1f06f89d6d7 with the captured context and candidate number. If the returned address is nonzero, it writes one to that member’s byte at `0x1e`. Zero results are skipped.

Consequences:

- A first-pass error does not prevent propagation.
- Candidates not reached before that error may still be looked up and marked.
- Candidates skipped by the special-number comparison may still be marked.
- The second pass performs fresh lookups; it does not reuse first-pass member addresses.
- The exact value of a previously nonzero marker is normalized to one on every member returned by the second-pass lookups.

### Exit

After the group passes, the function writes zero to the captured context’s activity byte at `0x16`, including when the retained status is nonzero.

Both paths then read the 32-bit context field at `0xe0`, subtract one, write the result back, and return the retained status.

This final read occurs after the preceding helper calls. The decrement therefore applies to the field’s then-current value, not an entry snapshot.

## Side effects

Directly established writes are:

- Group entry: context byte `0x16` becomes one.
- Conditional propagation: member byte `0x1e` becomes one.
- Group exit: context byte `0x16` becomes zero.
- Every normal return: context word `0xe0` is decremented.

The function makes no explicit allocation or deallocation operation identifiable from this body. F-133a6620fb39 can write through the supplied local-slot address. Other ownership, lifetime, resource, and global-state effects belong to unknown dependency contracts.

The no-argument F-44d249c54e70 call follows each successful acquisition and delegated member-processing call. Its placement alone does not establish that it unlocks, releases, commits, or frees anything.

The activity byte is not managed as a saved-and-restored value. The group path overwrites any entry value with one and later zero. No atomicity, locking guarantee, reentrancy protection, or synchronization semantics are established.

Cleanup behavior is established only for normally returning dependencies. Nonlocal exits, faults, or termination inside a dependency are not covered.

## Acceptance examples

The following are conditional static acceptance examples, not executed tests. Unless otherwise stated, addresses are valid, arithmetic stays representable, and dependencies do not modify values relevant to the example.

### Direct delegation

If the post-preparation byte at `0x14` is nonzero, the function delegates using the request address, regardless of the grouping value.

Expected effects: the initial grouping and preparation calls still occur; no direct activity-byte write occurs; the current context counter is decremented; the delegated status is returned.

A grouping value of zero or one also selects this path when the mode byte is zero.

### Full aligned group

With grouping value eight, requested member ten, and a bound of at least sixteen, the selected range is nine through sixteen.

If no processing call returns an error, all eight candidates are considered in order. Candidate ten bypasses F-811a25bdbe21.

### Bound within the group

With grouping value eight, requested member ten, and bound twelve, the range is nine through twelve.

With the same grouping and requested member but bound seven, the range is nine through ten, not an empty range and not a range ending at seven.

### Error followed by propagation

Suppose an early candidate reveals a nonzero marker and a later acquisition returns a nonzero status.

Expected behavior: first-pass processing stops after the failing candidate; no processing, marker read, or F-44d249c54e70 call follows that failed acquisition. The second pass still looks up every candidate in the selected range and marks every nonzero result. The activity byte is cleared, the counter is decremented, and the acquisition status is returned.

### Processing error with marker observation

If acquisition succeeds but F-78d1342ad960 returns nonzero, the current member marker is still read and F-44d249c54e70 is still called. A marker discovered by that read can trigger full-range propagation despite the error.

### Special candidate

If the per-candidate F-870c4fcf7295 result plus one equals the candidate, acquisition and delegated processing are skipped for it. If another candidate establishes marker propagation, that skipped candidate is nevertheless included in the second-pass lookup range.

### Count with its high bit set

If the final count has its top bit set, its signed interpretation is negative. Starting from index zero, neither pass enters its loop. On the group path, the activity byte is still set and then cleared, the counter is decremented, and the status remains zero.

## Uncertainties

The following are **documented_only**:

- The application meanings of the context, member numbers, activity byte, marker, and decrement field.
- Whether callers guarantee power-of-two grouping values or positive member numbers.
- The complete contracts and side effects of every dependency.
- Whether successful acquisition always replaces the local slot with a valid address.
- Whether any dependency owns, retains, releases, or invalidates request, context, or member storage.
- Concurrency, aliasing restrictions, and nonlocal error behavior.
- Exact target behavior where signed addition, subtraction, loop increments, or the final decrement exceed signed 32-bit range.

Unsigned comparisons and mask arithmetic are significant. They must not be silently replaced by signed comparisons or arbitrary-width mathematics. Conversely, the supplied representation does not justify promising portable signed-overflow behavior.

The mask calculation resembles one-based power-of-two grouping. Marker propagation resembles synchronization of a group-wide state. Both are inferred intent, not additional contractual guarantees.
