## Behavior

The numbered stages preserve the order of directly represented memory effects. Calls occur between many of these effects. Dependencies must not be treated as pure: they may change memory, device state, or other state observable by later accesses.

For compactness:

- **Selector clear at a base** means: read one byte at base plus `1`, zero-extend it, then store zero at selector plus `0x11`.
- **Selector write at a base** means the same read followed by a specified byte store.
- **Narrow word copy at a base** means: read a 32-bit word at base plus `0x74`, then write its low byte at base plus `1`.

These describe access patterns, not established object layouts. Repeated selector reads are new reads; they must not be replaced with cached values unless explicitly stated.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Maximum selector.** If a selector read returns `0xFF`, its offset-`0x11` store targets `0x110`. A wider table index must not be inferred.

2. **Payload truncation.** If the payload seed is `0xFFC00000`, shifting right by 22 gives `0x3FF`; the initial byte store writes `0xFF`.

3. **Numeric word truncation.** If a narrow word copy reads `0x12345678`, its byte store writes `0x78`. This does not establish memory endianness.

4. **Address wraparound.** Under the apparent 32-bit model, multiplying `0x40000000` by four yields zero. Subsequent offsets are applied to that wrapped result; no overflow rejection is represented.

5. **Fresh selector reads.** If an intervening dependency changes a selector from `2` to `9`, subsequent selector writes target `0x1A`, not the earlier `0x13`.

6. **Repeated word overwrite.** If no intervening effect changes the eightfold base, its offset-`0x34` word is first assigned the scaled result and later the high word of a paired result. Both stores are observable.

7. **Direct low-address writes.** On a path reaching stage 10, address `0x0D` is explicitly assigned `0xC0`. This is not merely a write to an object-relative offset.

8. **Failure after partial progress.** If a dependency does not return after an early store, later stages are not required to occur. No restoration of the early store is established.
