# F-2ea7a451b5e1

No reliable application-level purpose is established. Character-like constants do not establish formatting or text output; pointer-like accesses do not establish allocation, serialization, or a container operation.

This contract distinguishes three evidence levels:

- **[INFERENCE]:** interpretation requiring assumptions beyond that material.

All execution descriptions are conditional on reaching the relevant operation. Dependency bodies, actual instruction semantics, and the memory environment are unavailable.

## Side effects

### Fixed-storage ordering and snapshot semantics

Fixed storage and calculated destinations are not established as disjoint. The meaningful fixed-storage trace includes these ordering constraints:

| Region | Established ordering and interpretation |
|---|---|
| Early fixed accesses | The value at 0x05 is read and converted to unsigned 32-bit before a byte is assigned at 0x01. Its converted value is retained as a base; its load width remains unresolved. |
| Intermediate fixed writes | A word assignment at 0x54 supplies twice the earlier loaded word. Later derived writes precede the byte assignment at 0x15. These are ordered effects, not independent initialization declarations. |
| Repeated-region entry | The separate fixed-location word supplying the fixed-loaded base is captured **before** the word assignment of 0x20 at 0x60. The base must not be reconstructed by reloading after that assignment. |
| Repeated-region exit | The word at 0xA9 is captured **before** the derived offset-0x74 load from the quadrupled branch base. That load precedes the byte assignment at 0x3A. The latter supplies the low eight bits of eight times the adjusted quantity plus 0x30. |
| Terminal fixed-byte propagation | The low byte of the saved 0xA9 word is assigned to 0x67. A derived offset-0x44 word load from the doubled branch base follows. Only afterward is the **current** byte at 0x67 read for assignment to 0x21. |

The 0xA9 snapshot remains a saved 32-bit value despite later memory changes. In contrast, the reads from 0x67 are reloads:

- Following the assignment to 0x21, several derived writes and a derived word load occur. A later byte store at adjusted-base offset 9 reads 0x67 again.
- A derived byte write, a word store of the saved 0xA9 snapshot at adjusted-base offset 0x44, and a word load from adjusted-base offset 0x54 intervene before another byte store at adjusted-base offset 9 reads 0x67 again.

Neither later store unconditionally reuses the earlier saved low byte. An intervening derived write may alias 0x67. The assignment to 0x21 similarly uses the represented current read, not a contractual substitution of the 0xA9 snapshot.

This specifies the meaningful fixed-storage ordering without claiming that all possible global effects of dependencies are known.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Third-input boundaries.** Third inputs 0 and 0x3FF contribute zero at the field-derived invocation. Input 0x400 contributes 0x800; input 0xFFFFF contributes 0x1FF800.

2. **Excluded bits.** Inputs 0x00000400 and 0xFFF00400 contribute equal field-derived arguments. Whole-function equivalence is not required.

3. **Narrowing and widening.** An explicit byte store supplied with 0x12345678 supplies 0x78. An explicit unsigned byte read of 0xE2 widened to a word supplies 0x000000E2.

4. **Unresolved fixed-load width.** A model of the read at 0x05 cannot be accepted as necessarily eight-bit merely because the result is converted to unsigned 32-bit. Additional type or instruction evidence is required.

5. **Equal repeated-region payloads.** If the earlier loaded word is 50, both the first and subsequent offset-0x34 payload derivations produce 400. A requirement that they differ numerically is incorrect.

6. **Base capture before 0x60.** If the 0x60 assignment overlaps the storage supplying the fixed-loaded base, subsequent repeated writes still use the base captured before that assignment.

7. **0xA9 snapshot.** If the derived offset-0x74 read or later accesses change storage overlapping 0xA9, later uses of the saved snapshot retain the previously captured word.

8. **0x67 reloads.** If a derived write changes 0x67 before either later adjusted-base offset-9 store, that store uses the value obtained by its own current read. Equal payloads require supporting memory conditions, not unconditional snapshot reuse.

9. **Intermediate observability.** An observer distinguishing individual accesses must retain the sequence 0x20, 0x2F, the read-derived word, and 0x20 at the repeated constant destination.

10. **Terminal capture and failure.** Terminal arguments use the specified saved values even if their source locations change. If execution stops earlier, restoration of prior memory contents is not required.
