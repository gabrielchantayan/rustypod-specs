# F-010217156c1c

## Purpose

F-010217156c1c modifies a caller-supplied, header-prefixed array of 32-bit words using a second such array, an unsigned 32-bit multiplier, and a signed 32-bit starting position.

The established behavior consists of source-driven multiply-add operations, propagation of any remaining carry, and a conditional replacement of the destination header. Four global factors participate in header interpretation and digit conversion.

**Inferred intent:** shifted multiply-add over a multiword integer representation.

That interpretation is conditional. The supplied evidence does not establish the factors’ declarations, values, inverse relationships, or supported representations. In particular, decoding differs between the source-processing stage and the remaining-carry stage, and several signed conversions prevent an unconditional mathematical-limb interpretation.

## Interface

### Arguments and result

| Input | Established role |
|---|---|
| Source pointer | Addresses signed 32-bit words: a header followed by source digits. |
| Destination pointer | Addresses writable signed 32-bit words: a header followed by destination digits. Selected existing words are read before replacement. |
| Multiplier | Unsigned 32-bit value used in each source-digit product. |
| Starting position | Signed 32-bit destination position. Position zero selects the first digit; position minus one selects the header. |

The function returns no value. It reports neither capacity exhaustion nor arithmetic failure.

### Layout and factors

Each array element occupies four bytes. The header is element zero. Digit position \(p\) selects element \(p+1\).

Four global data dependencies have distinct roles:

- **Header-decoding factor:** used for initial counts and the final header comparison.
- **Header-encoding factor:** used when replacing the destination header.
- **Digit-decoding factor:** used when interpreting stored words.
- **Digit-encoding factor:** used when storing arithmetic results.

Their declarations, widths, signedness, values, and initialization are unavailable. No inverse relationship is established.

Conversion timing matters:

- Initial header products are assigned to signed 32-bit counts before sign testing.
- Main-loop decoding expressions use the digit-decoding factor in its unknown arithmetic type.
- During carry propagation, the factor is first converted to unsigned 32 bits, then multiplied by the captured destination word.
- The final header product is compared directly with the signed position, without first being assigned to a signed 32-bit count.

### Preconditions and ownership

There are no visible null, alignment, capacity, overlap, or position checks.

A normal execution requires readable headers, readable source words reached by the captured source count, readable destination words selected for existing-digit contributions, and writable destination words for every result. The header must also be writable if replacement occurs.

Index arithmetic, pointer arithmetic, and accessed storage must remain valid. The captured destination count controls existing-word reads; it does not impose a write limit.

No allocation, release, or ownership transfer is visible. The arrays remain caller-supplied storage.

## Behavior

### Initial count capture

The source header is multiplied by the header-decoding factor, and the product is assigned to a signed 32-bit count. A negative assigned count is then negated.

The destination count is derived in the same manner, after the source count.

For representable products other than the minimum signed 32-bit value, this obtains the magnitude of the assigned product. It does not necessarily obtain the magnitude of the original multiplication expression: assignment occurs first.

An out-of-range assignment to the signed count is an unresolved conversion boundary. Negating the minimum signed 32-bit value is also outside the portable arithmetic behavior established here.

Both counts are captured before digit processing. Later changes to either header do not refresh them.

The source index and unsigned 32-bit carry start at zero. The destination position starts at the supplied position.

### Source-driven processing

The source stage processes successive source digits while the signed source index is below the captured signed source count. Each iteration writes one destination word.

#### Existing destination contribution

If the current signed position is less than the captured signed destination count, the selected destination word is read and multiplied by the digit-decoding factor. That expression is assigned to an unsigned 32-bit contribution.

The multiplication occurs in the arithmetic type determined by the stored word and the factor’s unavailable declaration. Assignment to unsigned 32 bits happens afterward; it does not make the multiplication itself an unsigned 32-bit operation.

Otherwise, the contribution is zero and the selected destination word is not read. In this branch, the explicit zeroing occurs after formation of the source product.

The position test has no lower-bound check. Position minus one selects the header. Lower positions can select preceding storage, subject to valid object bounds and arithmetic.

#### Source product

The current source digit is multiplied by the digit-decoding factor. The resulting expression is explicitly converted to unsigned 64 bits, then multiplied by the multiplier widened to unsigned 64 bits.

The multiplication therefore produces an unsigned 64-bit result, including reduction modulo \(2^{64}\) where applicable.

Decoding precedes the unsigned 64-bit conversion. A negative signed decoded value converts modulo \(2^{64}\), rather than being zero-extended from its low 32 bits. Overflow during the decoding expression is not repaired by the later conversion.

The unsigned product is assigned to a signed 64-bit holder. An out-of-range assignment is another unresolved conversion boundary. The body subsequently extracts the holder’s low 32 bits and converts the holder back to unsigned 64 bits to obtain its high 32 bits.

Consequently, identifying these extracted words with the original unsigned product requires appropriate behavior at that signed 64-bit assignment boundary.

#### Result and outgoing carry

Let \(B=2^{32}\). The destination contribution, extracted low product word, and incoming carry are unsigned 32-bit quantities.

The contribution and low product word are added first. Their low 32 bits form an intermediate word, and their unsigned carry-out is recorded. The incoming carry is then added to that intermediate word, with a second unsigned carry-out.

The low result is therefore the sum of those three contributions modulo \(B\). That result is assigned to a signed 32-bit temporary before encoding.

The high-product path has a separate conversion boundary: the extracted high 32-bit word is explicitly converted to signed 32-bit form **before** the outgoing-carry additions.

Let:

- \(H\) be the extracted unsigned high word;
- \(S\) be the result of converting \(H\) to signed 32 bits;
- \(c_1\) and \(c_2\) be the two carry indicators, each zero or one.

If that signed conversion produces a value and execution continues, the outgoing unsigned 32-bit carry is

\[
\bigl(\operatorname{unsigned32}(S)+c_1+c_2\bigr)\bmod B.
\]

The familiar formula \((H+c_1+c_2)\bmod B\) is justified when converting \(S\) back to unsigned 32 bits recovers \(H\). This holds without an out-of-range conversion when \(H\leq 2^{31}-1\). For larger high words, the supplied evidence does not establish the necessary signed-conversion behavior.

The signed low-result temporary is multiplied by the digit-encoding factor and assigned to the selected signed 32-bit destination word. The factor’s type controls that multiplication. Out-of-range result conversion and signed encoding overflow remain unresolved boundaries.

Each iteration advances the source index once and advances the destination position once after the destination write.

Neither a zero multiplier nor a zero source digit skips the iteration.

### Remaining-carry propagation

After source processing, propagation continues while the unsigned 32-bit carry is nonzero.

For a position below the captured destination count, the decoding sequence is specifically:

1. Read the selected destination word into a signed 32-bit temporary.
2. Read the digit-decoding factor and convert it to an unsigned 32-bit temporary.
3. Multiply those captured values to obtain the contribution.

The factor is fetched and narrowed **after** the destination-word capture, before the multiplication. The multiplication uses unsigned 32-bit arithmetic: the signed word is converted to unsigned 32 bits when combined with the unsigned factor temporary. The contribution is their product modulo \(B\).

This is not the main loop’s decoding operation. A signed multiplication that could overflow in the main loop is replaced here by defined unsigned 32-bit multiplication, once the factor conversion itself has completed.

At or beyond the captured destination count, the contribution is zero. Neither the selected destination word nor the digit-decoding factor is read for that contribution.

The incoming carry and contribution are added in unsigned 32-bit arithmetic. Their low-word sum is multiplied by the digit-encoding factor and assigned to the destination word. Unlike the main stage, this encoding expression receives an unsigned 32-bit sum, not a sum first assigned to a signed 32-bit temporary. The unavailable factor declaration therefore affects the two encoding expressions differently.

The destination position advances after the write. The next carry is solely the unsigned carry-out from adding the incoming carry and contribution; it is not derived from the encoded stored word.

After one propagation iteration, carry is either zero or one. A propagation iteration at or beyond the captured destination count adds zero to the carry, so its carry-out is zero and propagation stops, subject to valid arithmetic and storage operations.

If carry is already zero, no propagation iteration occurs. Untouched trailing digits are not inspected or normalized.

### Final header decision

After both stages, the destination header is read again. Its product with the header-decoding factor is compared directly with the final signed destination position.

If the product compares less than the position, the header is replaced with the position multiplied by the header-encoding factor. Otherwise, it remains unchanged.

This comparison:

- Uses the current header, not the captured destination count.
- Does not take an absolute value.
- Does not first assign the product to signed 32 bits.
- Has arithmetic width and comparison signedness dependent on the unknown factor declaration.

It is therefore not unconditionally a signed comparison or a length-extension-only operation.

### Arithmetic boundaries

No universal wraparound rule is established for:

- Signed multiplication involving global factors.
- Out-of-range conversion to signed 32-bit counts or result temporaries.
- Negation of the minimum signed 32-bit count.
- Assignment of an out-of-range unsigned product to the signed 64-bit holder.
- Conversion of an extracted high word above \(2^{31}-1\) to signed 32 bits.
- Position or index increments beyond their signed ranges.
- Position-plus-one arithmetic or pointer arithmetic outside valid bounds.

These boundaries must remain distinct from the explicitly unsigned arithmetic.

## Side effects

### Access order

At the granularity established by the supplied body:

1. The source header is read and its count derived.
2. The destination header is read and its count derived.
3. Each source iteration conditionally reads and decodes an existing destination word, reads and decodes a source word, and writes the destination result.
4. Carry propagation performs successive destination writes, with the conditional read-and-factor-capture sequence described above.
5. The destination header is read again and conditionally replaced.

Within individual multiplication expressions, the relative evaluation order of a word read and a factor read is not established. Carry propagation is different: its separate captures establish destination-word read before digit-factor read and conversion.

Factors are referenced at their use sites. No complete entry snapshot, synchronization mechanism, or stability guarantee is visible.

### Overlap

There is no overlap check and no source copy. A destination write can alter a source digit that a later iteration reads.

Captured counts remain unchanged even if overlapping writes alter headers. The final header comparison nevertheless uses a fresh destination-header read.

A write at position minus one can overwrite the destination header during either arithmetic stage. The final comparison then observes that changed header.

No immutable-source or overlap-safe mathematical result is promised.

### Errors

Invalid storage, invalid arithmetic, and unsupported representations have no specified function-level error outcome.

## Acceptance examples

These are conditional static consequences, not executed tests.

### Direct multiply-add

Assume all factors are signed 32-bit values equal to one, arithmetic is representable, storage is sufficient, and arrays do not overlap.

For source header **2**, source digits **[3, 4]**, destination header **3**, destination digits **[10, 20, 30]**, multiplier **5**, and starting position **1**:

- Destination digits become **[10, 35, 50]**.
- No carry-propagation digit is written.
- The final position is **3**.
- The header remains **3**.

### Appended carry digit

Under the same assumptions, use source header **1**, source digit **2,147,483,647**, destination header **0**, multiplier **3**, and starting position **0**.

The product is **6,442,450,941**. Its low word is **2,147,483,645**, and its high word is **1**, which converts to signed 32 bits without an out-of-range boundary.

The first destination digit becomes **2,147,483,645**. Propagation writes **1** to the next digit without reading its old contents. The header becomes **2**.

### Propagation uses unsigned decoding

Assume:

- Both header factors are signed 32-bit one.
- The digit-decoding factor is signed 32-bit **2**.
- The digit-encoding factor is signed 64-bit one.
- Assigning **4,294,967,295** to a signed destination word produces **−1**.
- Storage and all other arithmetic are valid.

Use source header **1**, source digit **1,073,741,823**, multiplier **3**, destination header **2**, destination digits **[0, 2,147,483,647]**, and starting position **0**.

The source decoding is **2,147,483,646**, and the product is **6,442,450,938**. The first result digit is **2,147,483,642**, with carry **1**.

Propagation captures the next destination word, then converts the factor **2** to unsigned 32 bits. Their unsigned product is **4,294,967,294**, without signed multiplication overflow. Adding carry produces **4,294,967,295** and no carry-out.

The second stored digit is **−1** under the stated assignment assumption. The header remains **2**.

### High-word conversion boundary

Assume unit header factors with signed 32-bit types and unit digit factors with unsigned 32-bit types. Also assume the relevant out-of-range signed conversions preserve the low-width bit patterns.

For source header **1**, stored source digit **−1**, destination header **0**, multiplier **4,294,967,295**, and starting position **0**:

- Decoding yields unsigned **4,294,967,295**.
- The product has low word **1** and high word **4,294,967,294**.
- The signed 64-bit holder preserves that product’s bit pattern under the stated assumption.
- The high word converts to signed **−2**; its unsigned conversion during carry addition recovers **4,294,967,294**.
- Destination digits become **[1, −2]**, and the header becomes **2**.

This outcome is conditional on the signed-conversion assumptions. The high-word-plus-carries formula alone does not establish it.

### Zero multiplier still writes

With signed unit factors, source header **2**, destination header **0**, multiplier **0**, and starting position **0**, both source digits are read and both selected destination digits are written as zero, provided their decoding expressions are valid. The header becomes **2**.

### Empty source can change metadata without digit writes

With signed unit factors, source header **0**, destination header **2**, and starting position **5**, neither arithmetic stage runs. No digits are read or written. The final comparison succeeds, and the header becomes **5**. The intervening storage is not initialized.

### Final comparison depends on factor type

For source header **0**, destination header **−3**, and starting position **0**:

- With signed 32-bit unit header factors, the captured destination count is **3**, but the final comparison uses **−3**. The header becomes **0**.
- With an unsigned 32-bit unit header-decoding factor, assume initial count assignment yields **−3**, subsequently normalized to **3**. The final comparison instead compares unsigned **4,294,967,293** with zero. It fails, leaving the header **−3**.

No digit processing occurs in either case.
