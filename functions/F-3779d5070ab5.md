# F-3779d5070ab5

## Purpose

F-3779d5070ab5 conditionally obtains or creates a result associated with a source object and a destination context. Its visible behavior depends on a source flag, a comparison of context fields, destination flags, and opaque dependency results.

Two principal paths are established:

- With the initially observed source mode bit clear, select an associated object, optionally attempt a shortcut, and otherwise create and initialize an object.
- With that bit set, either create an object and potentially process a linked sequence, or process the sequence without creating an object.

A zero return does not imply absence of side effects. Admission and selection dependencies may already have run, and the traversal-only path returns zero after processing its sequence. A nonzero return is either an unchanged shortcut result or a retained created-object address.

“Source,” “destination,” “associated object,” “creation,” and “notification” describe inferred roles. They do not establish domain semantics, ownership, allocation, or dependency behavior.

## Interface

### Arguments and representation

The function accepts four arguments:

1. **Source address:** an address of an object containing 32-bit fields and a byte flag. Null is explicitly handled.
2. **Destination address:** a 32-bit address-valued argument. Zero is explicitly handled.
3. **Optional descriptor address:** passed unchanged to dependencies; on one traversal path, interpreted as two consecutive 32-bit words. Null selects a fallback.
4. **Traversal argument:** a 32-bit value passed unchanged as the fourth argument of every sequence-processing call. Its semantic type is unknown.

The supplied representation uses 32-bit words, 32-bit address values, and individual byte accesses. All offsets below are byte offsets. No length argument, bounds check, address-overflow check, or explicit alignment check is present.

### Result

The result is a 32-bit value:

- Zero on explicit rejection, selected dependency failures, or completion without a created object.
- The exact nonzero result from F-3931e02c2857 on shortcut success.
- Otherwise, the address obtained from F-704d91f94e04.

Nonzero shortcut results are not independently validated as addresses. No distinct error code or processed-entry count is returned.

## Behavior

### Admission and retained context

If the source address is nonnull, the function first reads its word at `0x00`. It returns zero without calling a dependency if:

- The source address is null.
- That initial word is zero.
- The destination address is zero.

The source-word read precedes rejection of a zero destination. A zero destination therefore does not protect an invalid nonnull source from being read.

If these prerequisites hold, call F-1115c37ad1b6 with the original destination and descriptor arguments. A zero result returns zero immediately.

After a nonzero admission result, reload source word `0x00` and retain it as the source-context address. The reloaded address is not checked for zero. Changes made during admission can therefore alter the context used later.

The retained created-object address and selected associated-object value initially equal zero.

### Initial mode-clear selection

Read source byte `0x1d`. If bit `0x01` is clear, compare the 32-bit words at destination offset `0x0c` and retained source-context offset `0x0c`.

Both reads participate in the comparison. Their relative evaluation order is not established by the supplied expression.

- If equal, read source word `0x20` and use it directly as the selected associated-object address.
- If unequal, read source word `0x20`, pass it to F-53a23d4b077c, and use the result. A zero result returns zero immediately.

The equal case has no corresponding zero check. It proceeds to read selected-object offset `0x24`, even if the selected value is zero.

Read selected-object word `0x24`. If it is zero, do not read destination byte `0x18d`; proceed to creation.

If that word is nonzero, read destination byte `0x18d`. If bit `0x10` is clear, proceed to creation. If set, read destination word `0x40` and call F-3931e02c2857 with that value and the selected associated-object address.

A nonzero shortcut result is returned unchanged, with no creation or final notification. A zero result falls through to creation.

### Initial mode-set decision

If the initial source mode bit is set, read destination byte `0x18c`.

- Bit `0x10` set: proceed to creation.
- Bit `0x10` clear: skip creation and enter traversal setup.

This path does not compare context fields, invoke F-53a23d4b077c, or establish a nonzero selected associated-object value.

### Creation and initialization

Call F-704d91f94e04 with the destination address. A zero result returns zero immediately. Creation failure does not fall back to traversal.

Retain a nonzero result as the created-object address. Read source word `0x10` and write it to created-object word `0x18`.

Then reread source byte `0x1d`. This observation, rather than the initial mode observation, determines initialization.

**If bit `0x01` is clear:**

1. Read created-object word `0x10` and write it to created-object word `0x24`.
2. Write the retained selected associated-object value to created-object word `0x20`.
3. Read selected-object word `0x24` and write it to created-object word `0x28`.
4. Write the created-object address to selected-object word `0x24`.

The final write publishes the new head only after these created-object fields have been assigned. This ordering does not establish synchronization or thread safety.

If this branch is reached from an initially mode-set path, the selected associated-object value is still zero. The visible behavior then includes writing zero to created-object offset `0x20` and attempting the subsequent selected-object-field read through that zero base. No safe mode-transition handling is present.

**If bit `0x01` is set:**

1. Read created-object byte `0x1d`, set bit `0x01`, and write the byte back while preserving its other bits.
2. Call F-12d234fad301 with:
   - Retained source-context address plus `0xcc`.
   - Source word `0x28`.
   - Destination address plus `0xcc`.
   - Address of created-object word `0x28`.

The dependency’s result is ignored. The body does not establish a relative evaluation order among the argument expressions.

After either initialization branch, call F-493743038bd6 with the created-object address, the original descriptor address, and the literal value `1`. Ignore its result.

Reread the source mode bit:

- Clear: skip traversal and proceed to final notification.
- Set: enter traversal setup.

Thus, dependency-induced source-flag changes can affect both initialization and traversal selection.

### Traversal setup

If no object was created:

- With a null descriptor, read destination word `0x40` into the local cursor, then read cursor-object word `0x24` into a companion local.
- With a nonnull descriptor, first read descriptor word `0x04` into the companion local, then read descriptor word `0x00` into the cursor.

The null-descriptor fallback does not validate the cursor before dereferencing it.

If an object was created:

- Read created-object word `0x24` into the companion local.
- Set the cursor to the created-object address.

In this case, traversal setup does not directly read the descriptor, although earlier dependencies received it.

The cursor is a 32-bit addressable local slot. The companion is another 32-bit local. The supplied body does not establish a supported aggregate layout encompassing them.

### Sequence processing

After setup, read source word `0x20` as the first sequence-entry address.

For every nonzero current entry:

1. Call F-a2dffecdec45 with the current entry, original destination, address of the cursor slot, and original fourth argument.
2. Store its return value into the companion local.
3. Read the current entry’s successor at offset `0x08`.

Use that successor as the next entry. The successor read occurs after the dependency call, so a change to the current entry’s successor during that call affects traversal.

The original fourth argument is used on every call. Neither the companion’s initial value nor a prior return value replaces it.

A zero dependency result does not terminate traversal. An initially zero sequence head produces no processing calls. No cycle detection or iteration limit is visible.

### Final notification and return

If a created object exists after traversal is skipped or completed:

1. Write zero to the local cursor slot.
2. Read the global datum referenced at the final call site for use as the notification’s second argument.
3. Call F-ebd0ee53699f with destination address plus `0x48`, that global-derived value, and the retained created-object address.

Ignore the notification’s result.

The global read occurs after the cursor has been cleared. The supplied material does not define the datum’s value or establish that it is immutable. Earlier dependencies may or may not affect it; no preservation guarantee is available.

Return the retained created-object address. If no object was created, omit notification and return zero.

## Side effects

Direct writes to caller-accessible objects are:

- Created-object offset `0x18`.
- In mode-clear initialization, created-object offsets `0x24`, `0x20`, and `0x28`, followed by selected-object offset `0x24`.
- In mode-set initialization, created-object byte `0x1d`, preserving bits other than `0x01`.

Additional writes occur to local cursor and companion storage. F-a2dffecdec45 receives the cursor slot’s address and can modify it through that argument.

Every dependency may have further effects not specified here. In particular, no dependency is established to preserve globals, source fields, destination fields, object lifetimes, or previously obtained addresses. The final global argument must not be treated as a constant across those calls.

No explicit release, reference-count operation, rollback, or recovery mechanism is visible. Clearing the local cursor is not evidence of releasing or unlinking anything.

Successful continuation requires every accessed address to remain valid at the time of access. This includes sequence entries after their processing calls. The body supplies no protection against invalidating callbacks, concurrent mutation, or cycles.

## Acceptance examples

These are conditional static scenarios, not executed tests. Unless a change is expressly described, they assume dependencies return normally and all subsequently accessed memory remains valid.

1. **Null source:** Return zero without invoking dependencies or reading destination fields.

2. **Zero destination:** With a readable nonnull source whose first word is nonzero, read that word, then return zero without calling F-1115c37ad1b6.

3. **Admission rejection:** If F-1115c37ad1b6 returns zero, return zero without reloading the source context, selecting an object, creating, or traversing.

4. **Context comparison:** In initial mode-clear operation, compare the destination and retained-context words at `0x0c`. Acceptance must not require either comparison operand to be read first.

5. **Shortcut success:** With a valid selected object, nonzero selected word `0x24`, destination shortcut bit set, and a nonzero F-3931e02c2857 result, return that exact result. Do not create or notify.

6. **Shortcut fallback:** If the shortcut returns zero and creation succeeds with mode remaining clear, perform the ordered link initialization, call F-493743038bd6, skip traversal, and notify. Return the created address.

7. **Traversal only:** With initial mode set and destination creation bit clear, initialize traversal from the descriptor or fallback object. Process reachable entries and return zero, including when calls modify the cursor.

8. **Creation failure:** If creation was selected but F-704d91f94e04 returns zero, return immediately without traversal fallback.

9. **Mutable successor:** If a processing dependency changes the current successor to zero, traversal ends after that call. If it changes the successor to another valid entry, that replacement is visited next.

10. **Stable fourth argument:** Different processing results do not alter the fourth argument supplied to later calls.

11. **Mode changed before traversal:** If mode-set initialization occurs but F-493743038bd6 clears the source mode bit, skip traversal and proceed to notification.

12. **Global changed before notification:** If an earlier dependency changes the final-call global datum, and nothing changes it again before its read, notification receives the changed value. The read follows cursor clearing; the contract does not require an entry-time value.

13. **Incompatible initialization transition:** If an initially mode-set creation path reaches mode-clear initialization, the selected value remains zero. Safe linking is not an acceptance guarantee for this transition.
