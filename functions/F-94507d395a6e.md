# F-94507d395a6e

## Purpose

F-94507d395a6e describes a fragment that derives a small unsigned value from one incoming register value, reads a byte through a global address reference, and writes one 32-bit word through an incoming or conditionally replaced base register. It then either remains in an empty loop or reaches a location marked as invalid instruction data.

The established behavior is narrower than a complete executable-function contract. The supplied representation explicitly reports damaged or undecodable control flow. It establishes arithmetic, a byte read, a conditional base change, a word write, and the represented paths after that write. It does not establish the actual processor behavior at the invalid-instruction locations.

No successful return, recovery path, or useful application-level result is shown. The apparent purpose of the surrounding program, the destination field, and the global byte is unknown.

## Behavior

### Derived value and overflow predicate

Let the first and second incoming values be unsigned integers in the range 0 through 4,294,967,295.

The initial derived value is the first input divided by 4 with its remainder discarded, then increased by 7. Its range is:

- Minimum: 7.
- Maximum: 1,073,741,830.

This addition cannot overflow a 32-bit unsigned integer.

Separately, the second input is divided by 2 with its remainder discarded. The fragment checks whether adding 198 to that result would overflow a signed 32-bit integer.

Although the second input is unsigned, its logical right shift by one produces a value no greater than 2,147,483,647. Consequently, the relevant signed overflow is positive overflow, not negative overflow. The predicate is true exactly when the shifted value is at least 2,147,483,450.

Equivalently, in terms of the original second input:

- Predicate false: 0 through 4,294,966,899, inclusive.
- Predicate true: 4,294,966,900 through 4,294,967,295, inclusive.

In hexadecimal, the true range begins at `0xFFFFFE74`.

The overflow result is used as a Boolean condition. The sum used by that check is not itself stored or returned.

### Global-relative byte read

After the initial derived value and overflow predicate are computed, the fragment reads one byte at offset 24 from the globally referenced address.

This read precedes the branch on the overflow predicate. It therefore occurs even when the predicate is true and the byte’s value will subsequently be discarded.

A consumer must not treat that read as optional merely because the overflow path does not use its result. If the address is invalid, protected, volatile, or mapped to a device, the attempted read may be significant. The fragment does not define fault handling or device semantics.

### Selection of destination and stored value

If the overflow predicate is false:

- The initial derived value is retained.
- The incoming address-base register is retained.
- The byte read from the global-relative location is retained for a later zero/nonzero check.

If the overflow predicate is true:

- The derived value is replaced with zero.
- The destination base is replaced with the address represented as stack-relative offset 16.
- The retained byte value is replaced with zero.

The byte replacement is a change to a temporary value, not a write back to the global-relative byte.

The fragment then writes a 32-bit word at offset 384 from the selected destination base. The word is the selected derived value shifted right logically by 23 bits.

On the overflow path, the stored word is always zero. The represented destination is 384 bytes beyond the stack-relative address at offset 16. If both offsets share an ordinary byte-addressed stack origin, this corresponds to offset 400 from that origin. The source does not establish a valid writable stack object at that address.

On the non-overflow path, the stored word is the integer quotient of the initial derived value divided by 8,388,608. Its possible values are 0 through 128, inclusive.

### Behavior after the write

The destination write occurs before the fragment selects between its loop and invalid-instruction paths.

If the stored word is zero, the fragment enters an empty loop whose continuation condition is the negation of the previously computed overflow predicate:

- With the predicate false, the represented loop repeats indefinitely.
- With the predicate true, the loop body is passed through once, its continuation condition is false, and execution reaches an invalid-instruction marker.

No memory read, memory write, predicate recomputation, or externally observed state check is shown inside the loop. A later change to the input registers or global byte is not represented as a way to release it.

If the stored word is nonzero, execution checks the retained byte:

- A nonzero byte selects one invalid-instruction marker.
- A zero byte selects another invalid-instruction marker.

Both represented outcomes are invalid-instruction boundaries. The supplied material does not establish whether their actual runtime effects are identical.

The overflow predicate being true always forces the stored word to zero. Therefore, the nonzero-word path is reachable only when the predicate is false.

### First-input boundary for the empty loop

When the overflow predicate is false, the stored word is zero exactly when the first input is at most 33,554,403, or `0x01FFFFE3`.

At the next value, 33,554,404, or `0x01FFFFE4`, the stored word becomes one.

Thus the represented path partition is:

| Overflow predicate | First input | Stored word | Subsequent represented behavior |
|---|---|---:|---|
| False | 0 through `0x01FFFFE3` | 0 | Indefinite empty loop |
| False | `0x01FFFFE4` through `0xFFFFFFFF` | 1 through 128 | Byte-dependent selection of invalid-instruction boundary |
| True | Any 32-bit value | 0 | Single loop-body pass, then invalid-instruction boundary |

These outcomes presume the preceding memory accesses complete.
