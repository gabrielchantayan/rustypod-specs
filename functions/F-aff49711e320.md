# F-aff49711e320

## Purpose

**Established static evidence:** F-aff49711e320 interleaves indirect calls with byte, halfword, and word memory accesses. It extracts upper-bit fields, forms addresses from call results and retained values, copies low bytes from words, stores full words, and clears selected locations.

The representation contains **two explicit 32-bit assignments to the same global storage location, G1**. It also reads a second global, G2, and reads a three-byte global region, G3. It does not explicitly assign G2 or G3. Computed writes or dependency activity could affect global storage through aliasing, but those effects are not established.

**Inferred intent:** The access patterns resemble indexed storage and packed-field manipulation. No application-level meaning, object model, allocator role, or device protocol is established.

The final visible call targets address zero with three zero arguments. A return follows in the representation, but normal completion depends on that call returning.

### Widths and layout

A byte is 8 bits, a halfword is 16 bits, and a word is 32 bits. Word-to-byte stores retain only bits 0–7. Pair results are represented as 64 bits, split into low and high 32-bit halves; this does not prove a conventional 64-bit return ABI.

G1 is assigned as a word. G2 is read as a word and used as an address base. G3 contributes a 24-bit value to the final composition of G1. No surrounding object layout is established.

Unsigned right shifts are logical. Sign selection uses a signed 32-bit interpretation and an arithmetic right shift by 31.

Address expressions use 32-bit operands in the supplied representation. Some multiplications and left shifts have signed intermediate types. Their executable overflow semantics are unresolved. References below to **32-bit wraparound semantics** mean that arithmetic results are truncated modulo \(2^{32}\); they are conditional interpretations, not a resolution of that uncertainty.

## Behavior

The phases below preserve the order of direct accesses and significant call arguments. “Retained” identifies a value reused by this routine, not a promise that dependencies preserve the memory from which it originated.

### 1. Initial field stores and reduced-word capture

Two indirect calls occur before the first direct memory access. F-dep-001 uses a target derived from incoming link-like state plus 0xffe. The next call belongs to F-dep-002 and has a location-derived target.

The routine then stores a word at four times a secondary-result value, plus 0x14. The stored value is the incoming register-like word logically shifted right by 22, producing at most 10 significant bits.

An F-dep-002 call receives that secondary-result value. A subsequent call result is forwarded to another call. Further calls produce an index, and the routine stores the third explicit argument logically shifted right by 23 at four times that index, plus 0x14.

Next, it reads a word from the address formed by:

- Masking a secondary-result value with 0x1fffffff.
- Shifting the masked value right by 19.
- Adding 0x14.

There is **no multiplication by four** in this read address. Its represented range is 0x14 through 0x413.

The scaled index from the preceding store is passed to F-dep-002. Additional calls occur before the loaded word is logically shifted right by 22. The resulting 10-bit value is retained for the next phase.

### 2. Byte-selected writes and initial sign-based clearing

The routine reads a byte at the incoming register-like word plus one. It adds 0x11 to that unsigned byte and writes the low byte of the retained reduced value to the resulting address.

A call receives another secondary-result value. After another call, the next call receives zero, expressed as an explicitly zero-valued word logically shifted right by 23.

Further calls produce an index. Before passing that index onward shifted left by two, the routine:

- Reads a byte at four times the reduced value, plus one.
- Adds 0x11 to that byte.
- Writes a zero byte at the selected destination.

Since the reduced value is at most 0x3ff, this selector-read address ranges from 1 through 0xffd.

More calls produce another index, whose left-shift-by-two result is supplied twice to one call. A later primary result is retained and forwarded to another call. After another call, sign-based clearing occurs.

The signed interpretation of the incoming register-like word selects a byte-read address:

- Address 1 for a nonnegative value.
- Address 2 for a negative value.

The routine reads the byte at that address and clears the byte at the selected unsigned value plus 0x11.

### 3. Repeated sign selection and first assignment to G1

A secondary-result word is retained and supplied three times to one call. A subsequent primary result is forwarded with the previously retained primary result from phase 2 logically shifted right by 23.

After further calls produce an index, the routine rereads the sign-selected byte at address 1 or 2. It retains this second selector value and clears the byte at that value plus 0x11.

This is a new read. Dependencies between the two sign-selector reads may change the selected memory.

The produced index is passed onward shifted left by two. Another call sequence produces an index whose left-shift-by-two result is supplied twice to a call.

A following call returns a word. The routine:

1. Assigns that word to G1.
2. Passes the same retained word to another call.
3. Makes a further call.
4. Reads a word at the retained second selector value plus 0x74.
5. Writes that word’s low byte at the retained selector value plus one.

The last copy uses the retained selector value, not a fresh sign-selector read.

### 4. Pair forwarding and repeated word-to-byte copying

The retained secondary-result word from phase 3 is shifted left by 11 and passed to F-dep-002.

F-dep-003 then supplies a pair result. Its low half, high half, and the word previously assigned to G1 logically shifted right by 23 are passed as three arguments to another dependency. The third argument uses the retained word; it does not reread G1.

Further calls produce an index. The routine multiplies it by four, reads a word at that scaled address plus 0x74, and writes the word’s low byte at the scaled address plus one.

That scaled address is passed onward. Additional calls produce a newer index. The routine then repeats the word read and byte write using the **earlier scaled address**, not the newer index.

The repeated copy performs a fresh read. A dependency-mediated change to its source word can therefore change the second byte written.

A four-argument call receives, in order:

- The retained secondary-result word shifted left by 12.
- The newer index shifted left by two.
- The same shifted index again.
- The newer index shifted left by 18.

The newer index shifted left by two is retained for later addressing and arguments.

### 5. Saved-word replication and scaled-value stores

Following result-producing and forwarding calls, another index is multiplied by four. The routine reads a word at that scaled address plus 0x74, retains the full word, and writes its low byte at the scaled address plus one.

It passes the scaled address onward. Further calls produce an index, and the retained full word is stored at 16 times that index, plus 0x14.

The next significant argument is formed from the retained left-shift-by-two value from phase 4: first logically shift it right by two, then shift the result left by 16.

The recovered operation order matters to the static description. However, **under 32-bit wraparound semantics, the final argument equals the original phase-4 index shifted left by 16 and truncated to 32 bits**. The initial left shift discards the original upper two bits, but those bits cannot affect the final 32-bit result after the left shift by 16. This equivalence does not settle the separate uncertainty about signed-expression semantics.

After further calls, the retained full word is stored at four times another index, plus 0x14. That scaled index is passed onward.

A subsequent call sequence produces another index. Its left-shift-by-two result is stored at:

- The phase-4 retained shifted value masked with 0xfffffffc.
- Plus 0x14.

The newly stored value is then supplied twice to a call.

After additional calls, the routine writes a zero word at four times a new index, plus 0x14, and passes that scaled index onward.

All full-word replication in this phase uses the word captured near the beginning of the phase. The original source is not reread for those stores.

### 6. Pair-derived stores and captured G2 base

F-dep-004 returns a pair result. The routine shifts its low half left by two and stores that result at four times the high half, plus 0x14.

It then reads G2 once and retains its word value as an address base.

A four-argument call receives:

1. The shifted low half.
2. The high half.
3. The shifted low half again.
4. The shifted low half again.

Further calls produce an index. The same retained shifted low-half value is stored at four times that index, plus 0x14.

The routine next reads a word at the captured G2-derived base plus 0x14. It does not reread G2 after the intervening calls. Thus, a dependency may change the word ultimately read through that base, but changing G2 itself does not replace the captured base.

The latest scaled store index is then passed onward.

### 7. Final byte projections

After additional calls, F-dep-005 returns another pair result. Its low half is retained through the terminal halfword clear.

Before forwarding the pair-derived arguments, the routine:

- Logically shifts the saved full word from phase 5 right by 23.
- Reads a selector byte at that result plus one.
- Writes the low byte of the word loaded through the captured G2 base at the selector value plus 0x11.

The selector-read address ranges from 1 through 0x200.

A four-argument call then receives three copies of the pair’s high half, followed by the pair’s low half shifted left by two.

More calls occur, including forwarding a primary result. A later call produces an index. Before that index is passed onward, the routine performs another byte-selected write:

- Mask the retained pair low half with 0x3fffffff.
- Logically shift right by 21.
- Read a byte at that result plus one.
- Write the low byte of the G2-derived word logically shifted right by 22 at the selector value plus 0x11.

This selector-read address also ranges from 1 through 0x200. The value written is bits 22–29 of the retained G2-derived word; its top two bits do not survive byte truncation.

The newly produced index is passed onward shifted left by two. Further calls produce another index whose left-shift-by-two result is supplied twice to a call.

### 8. Terminal pointer clearing, second assignment to G1, and zero-address call

After another call, F-dep-006 is called without explicit arguments. Its result is forwarded to F-dep-002. F-dep-007 then returns a byte-sized value and exposes a pointer-like secondary result.

The terminal direct operations occur in this order:

1. Write a zero byte through the secondary pointer-like result.
2. Read G3 as a represented 24-bit value.
3. Assign G1 a word whose low eight bits are the returned byte and whose upper 24 bits are the G3 value.
4. Write a zero halfword at the address formed by masking the phase-7 pair low half with 0x3fffffff, then logically shifting right by seven.
5. Call F-dep-008 at address zero with three zero arguments.

The halfword address ranges from zero through 0x007fffff. No rounding or alignment adjustment is applied.

No dependency call intervenes between these terminal direct accesses. Nevertheless, aliasing matters: the pointer-based byte clear may affect G3 before its read, and the later halfword clear may overlap G1 or other storage.

The represented composition of G1 establishes bit placement, not memory byte order or the number of physical reads used for G3.

## Side effects

The established direct effects are computed byte, halfword, and word writes, plus **two word assignments to G1**. G2 and G3 are explicitly read, not explicitly assigned.

Every destination selected by an unsigned byte plus 0x11 lies between 0x11 and 0x110. These are literal low-address accesses in the representation, not validated offsets within an established object.

Dependencies may modify globals, selectors, source words, destinations, or external state. Consequently:

- Repeated reads must remain distinct.
- A stored value need not remain present after a later call.
- Retained words can differ from their original source’s current contents.
- Equal destinations allow later writes to replace earlier writes.
- Computed accesses may alias globals or each other.

The supplied warning establishes possible overlap between global symbols. Independent storage for G1, G2, and G3 must not be assumed.

There is no visible rollback, cleanup path, status check, or explicit error reporting. Fault behavior and dependency errors remain unresolved.

## Acceptance examples

These are conditional deductions from static evidence, not observed executions. Each assumes execution reaches the relevant operation.

1. **Third-argument extraction.** A third argument of 0xffffffff produces a stored word of 0x000001ff.

2. **Byte truncation.** A phase-1 loaded word of 0xffffffff reduces to 0x3ff. The first byte-selected store writes 0xff.

3. **Sign selection.** Incoming register-like values 0x7fffffff and 0x80000000 select byte reads at addresses 1 and 2 respectively. The destination depends on the byte actually read.

4. **Distinct selector reads.** If the first sign-selected byte is 5 and an intervening dependency changes it to 9, the clears target 0x16 and 0x1a. Reusing the first selector would change behavior.

5. **Saved full word.** A phase-5 source word of 0x123456ab causes an immediate byte write of 0xab and later full-word replication of 0x123456ab, even if the original source subsequently changes.

6. **Repeated source read.** If the phase-4 source word changes from 0x11223344 to 0x55667788 between its reads, the corresponding byte writes are 0x44 and 0x88.

7. **Intermediate truncation without final divergence.** Under 32-bit wraparound semantics, a phase-4 index of 0x40000001 becomes 4 after shifting left by two. Shifting that retained value right by two and then left by 16 gives 0x00010000. Directly shifting the original index left by 16 and truncating also gives 0x00010000. This demonstrates intermediate information loss, not a different final argument.

8. **Captured global base.** If G2 is captured as 0x1000 and a dependency later changes G2 to 0x2000, the phase-6 word read still uses address 0x1014, assuming the represented arithmetic and access complete.

9. **Unaligned terminal address.** A phase-7 pair low half of 0x00000080 produces halfword destination address 1. Whether that write succeeds is platform-dependent.

10. **Final composition.** If G3 yields 0x123456 after the pointer-based clear and F-dep-007 returns 0xab, the second explicit assignment to G1 writes 0x123456ab. A subsequent overlapping halfword clear could alter that storage again.
