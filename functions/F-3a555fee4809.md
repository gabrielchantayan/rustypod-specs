# F-3a555fee4809

## Purpose

F-3a555fee4809 checks a memory-resident structure containing a fixed bitmap and a sequence of inclusive ranges. It performs boundary checks, validates range ordering, and optionally checks range-associated indices and bitmap membership.

Established behavior is validation by calls to F-7b0b9523800e, using diagnostic values 8 and 16. The function returns a 32-bit zero if execution reaches its normal return. It does not return a distinct validation-failure value.

The likely intent is to reject malformed range data before use by another component. Rejection is not independently established: the behavior of F-7b0b9523800e is unavailable. If that dependency returns, this function continues rather than explicitly terminating the failed validation path.

## Behavior

### 1. Fixed-region boundary check

The function first reads the context’s end boundary and compares it against the structure address plus 8208 bytes.

If the boundary is lower than that computed address, it calls F-7b0b9523800e with diagnostic value 8. Equality passes this comparison.

This is the first visible validation action, preceding reads of the declared size and range count. The corresponding call visibly includes the context, diagnostic value 8, the third argument, and two copies of the fourth argument.

There is no explicit return after this call. If the dependency returns, the function proceeds to read the declared size even though the fixed-region check failed.

### 2. Declared-size checks

The function reads the four bytes at offsets 4–7 and assembles an unsigned 32-bit declared size.

It reports diagnostic value 8 if either condition holds:

- The context end boundary is lower than the structure address plus the declared size.
- The declared size is less than 8208 bytes.

The minimum-size condition is expressed through two unsigned comparisons: a check below 8192, followed by a check that the difference from 8192 is below 16. Together, they reject every declared size below 8208.

The declared size is not used as a traversal limit. In particular, no visible check requires the range records to fit within the declared size. The later record-array check uses the context end boundary instead.

If the diagnostic dependency returns, processing continues.

### 3. Range-count and record-array boundary check

The function reads a big-endian unsigned 32-bit range count at offsets 8204–8207.

It then compares the context end boundary against the computed end of the record array:

- Record data begins 8208 bytes after the structure address.
- Each record occupies 12 bytes.
- The computed array end is the record-data address plus 12 times the range count.

A lower context boundary triggers diagnostic value 8. Equality passes.

The supplied representation does not show overflow detection for the multiplication or address addition. Consequently, this check must not be treated as proof that all record bytes are accessible for arbitrary 32-bit counts.

The count is retained for traversal; it is not visibly reread after diagnostic calls.

### 4. Per-record decoding and ordering checks

Records are visited in increasing storage order.

For each record, the function reads the start, end, and base-index bytes before making that record’s first diagnostic call. These record values are not visibly reloaded after a diagnostic call.

Two checks apply regardless of the mode byte:

1. The inclusive end must not be less than the start. A descending range triggers diagnostic value 8.
2. Except for the first record, the start must be strictly greater than the preceding record’s stored end. A start less than or equal to that end triggers diagnostic value 8.

Thus, under ordinary unsigned range interpretation, consecutive records may be adjacent but must not overlap. For example, a record ending at 10 may be followed by one starting at 11, but not one starting at 10.

The previous-end state is updated to the current record’s decoded end after that record’s checks. This update uses the decoded end, not the subsequently advanced start used during bitmap traversal.

There is no sorting, merging, normalization, or correction of records.

### 5. Mode-dependent index-limit check

After the ordering checks for each record, the function reads the context byte at offset 8.

If that byte is zero, the record receives no index-limit or bitmap checks. Traversal continues with the next record.

If the byte is nonzero, the function reads the 32-bit context limit at offset 400. It computes a candidate last index equivalent, in unsigned 32-bit arithmetic, to:

**base index + end − start, reduced modulo 2³².**

If the context limit is less than or equal to that candidate, it calls F-7b0b9523800e with diagnostic value 16.

Accordingly, passing this comparison requires the candidate to be strictly below the limit. The arithmetic is not checked for overflow. A wrapped candidate may pass even where an unbounded mathematical calculation would exceed the limit.

This check occurs before any bitmap validation for the record.

### 6. Mode-dependent bitmap checks

The bitmap uses most-significant-bit-first ordering within each byte:

- Bit index 0 selects mask 128 in bitmap byte 0.
- Bit index 7 selects mask 1 in bitmap byte 0.
- Bit index 8 selects mask 128 in bitmap byte 1.

For normal, non-wrapping ranges, the function visits each value from start through end inclusively.

The choice of bitmap rule is made once per record, from the original start’s upper 16 bits.

#### Start has zero upper 16 bits

If the start is below 65,536:

1. The end must also have zero upper 16 bits. Otherwise, diagnostic value 8 is reported.
2. For each visited value, the bitmap bit indexed by its lower 16 bits must be clear.
3. A set bit triggers diagnostic value 8.

If the upper-end check reports an error and the dependency returns, traversal still proceeds under this clear-bit rule. It does not switch to the other bitmap rule when a visited value crosses 65,535.

#### Start has nonzero upper 16 bits

If the start is at least 65,536, each visited value receives two checks, in this order:

1. The bitmap bit indexed by the value’s upper 16 bits must be set.
2. The bitmap bit indexed by the value’s lower 16 bits must be set.

A missing bit triggers diagnostic value 8. If the first diagnostic call returns, the second bitmap check still follows.

Both checks use the same 8192-byte bitmap. They do not address separate tables.

### 7. Completion

After all records are processed, the function returns a 32-bit zero.

A zero range count skips all record validation and all mode-dependent checks. It does not skip the preceding fixed-region, declared-size, count-read, or record-array boundary operations.
