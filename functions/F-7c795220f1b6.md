# F-7c795220f1b6

## Purpose

The established behavior is an ordered sequence of memory accesses and dependency calls. It is not sufficient to describe this operation as a generic ring-buffer update: the count is incremented before the first dependency runs, the mode is examined afterward, and later decisions use state that dependencies may have changed.

A likely intent is to populate and process a rotating set of fixed-stride records, with an initial transition through modes 1 and 2. That interpretation is inferred, not established. The record contents, the significance of each mode, and the work performed by either dependency are unknown.

## Behavior

### 1. Advance the count before calling the first dependency

The function reads the four-byte count at offset `0xAB4`. It saves that original value for destination selection and writes the original value plus one back to the same field.

It then calls F-148f046b5d07 with three supplied arguments, in this order:

1. The state base.
2. The opaque four-byte input.
3. The destination derived from the **original**, pre-increment count.

Consequently, the count has already been updated when this dependency is entered. The destination does not use the incremented count.

For example, with an initial count of 1, the direct count write stores 2, while the destination supplied to F-148f046b5d07 is the state base plus `0xBE8`.

No subsequent decision is made until this dependency returns normally. Its behavior is unknown; in particular, it must not be assumed to preserve the mode, count, record contents, globals, or other reachable state.

### 2. Examine the mode after the first dependency

After F-148f046b5d07 returns, the function establishes the state base plus `0xBE8` as its default secondary address and reads the mode at offset `0xAB0`.

There are three branches.

#### First mode read equals 2

The function reads the count again and examines its least significant bit.

- If that bit is set, the selected secondary address remains the state base plus `0xBE8`.
- If that bit is clear, the selected secondary address becomes the state base plus `0xC7C`.

It then invokes F-de71f85df2e6 with two supplied arguments:

1. The state base.
2. The selected secondary address.

This branch does not directly write the mode field.

The parity decision uses the count observed **after** F-148f046b5d07 returns. It is not necessarily the original count plus one. The dependency may have changed it.

#### First mode read does not equal 2, and a second mode read equals 1

If the comparison with 2 fails, the supplied representation reads the mode field again to compare it with 1.

When that second read equals 1, the function invokes F-de71f85df2e6 with three supplied arguments:

1. The state base.
2. The state base plus `0xB54`.
3. The state base plus `0xBE8`.

After this call returns normally, the function directly writes 2 to the mode field.

That write is unconditional within this branch. If F-de71f85df2e6 changed the mode, this subsequent write replaces that change with 2.

The evidence shows different supplied argument counts for the same dependency in the two branches. It does not establish a single verified prototype that resolves this difference.

#### Neither comparison selects a dependency call

If the first mode read is not 2 and the second mode read is not 1, the function directly writes 1 to the mode field. It does not invoke F-de71f85df2e6 in this branch.

For stable ordinary memory, this covers every mode value other than 1 and 2. It is not an error branch and does not reject unexpected mode values.

### 3. Normalize only an exact count value of 3

After the selected mode branch completes, the function reads the count field again.

- If the current value equals 3, it writes 1 to that field.
- Otherwise, it leaves that field unchanged at this stage.

This comparison occurs after any F-de71f85df2e6 call and, in the mode-1 branch, after the direct mode write of 2. It therefore observes any count changes made by either dependency.

This is an equality-based replacement, not general modular reduction, saturation, or range enforcement. Values greater than 3 are not reduced merely because they exceed 3. Negative values are not repaired.

The function then returns without a value.
