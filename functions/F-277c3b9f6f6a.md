# F-277c3b9f6f6a

## Purpose

F-277c3b9f6f6a sets one selected bit in byte-addressed storage associated with an object. When the requested position is not below the object’s recorded capacity, it first calls F-6a2a5ddf37ed with a requested capacity equal to the position plus one.

Bit numbering within each byte is most-significant-bit first: position zero selects the highest-order bit of the first byte, and position seven selects its lowest-order bit.

The established behavior includes these distinctions:

- A position with a negative signed 32-bit interpretation is ignored and returns zero without accessing the object.
- An accepted position below the recorded capacity proceeds directly to the bit update.
- An accepted position equal to or above capacity causes a dependency call.
- A nonzero dependency result is returned unchanged, with no subsequent direct object or bitmap access.
- A zero dependency result is followed by a capacity assignment and then the bit update.
- The target byte’s numeric address is calculated using unsigned 32-bit addition. Overflow wraps modulo 4,294,967,296 before conversion to a byte pointer.

“Bitmap,” “capacity,” and “capacity management” describe inferred intent. The branch conditions, accesses, arithmetic, writes, and return handling are established by the supplied static representation.

## Interface

### Inputs and object layout

The function receives an object pointer and a 32-bit unsigned position.

Under the represented 32-bit word model, the object has these relevant fields:

| Byte offset | Width | Observed role |
|---|---:|---|
| 0 | 32 bits | Unsigned capacity or position limit |
| 4 | 32 bits | Not directly accessed by this function |
| 8 | 32 bits | Unsigned numeric backing address |

The field at offset eight contains an address value, not inline bitmap data. The meaning of the intervening field is unknown; its absence from this function’s direct accesses does not constrain the dependency’s use of it.

The capacity comparison is unsigned. A recorded capacity with its highest bit set is therefore a large positive capacity value for that comparison, not a negative value.

### Position and integer widths

The position is initially examined through a signed 32-bit interpretation:

- Values from zero through 2,147,483,647 are accepted.
- Values from 2,147,483,648 through 4,294,967,295 return zero immediately.

For an accepted position:

- The requested capacity is position plus one, calculated as an unsigned 32-bit value.
- That capacity lies between one and 2,147,483,648 inclusive; the addition does not wrap.
- The byte displacement is the position divided by eight, rounded down.
- The displacement lies between zero and 268,435,455 inclusive.
- The bit mask is 128 shifted right by the position’s remainder modulo eight.

The displacement calculation uses a signed right shift, but only after the negative-position branch has been excluded. Its operand is therefore nonnegative, and the result is ordinary division by eight rounded down.

### Backing-address arithmetic

The stored backing address is unsigned and 32 bits wide. The nonnegative byte displacement is converted to unsigned for addition to that address.

The resulting numeric byte address is:

**(stored backing address + byte displacement) modulo 4,294,967,296.**

This is established unsigned wraparound, not an unspecified arithmetic error. The wrapped 32-bit integer result is then converted to a byte pointer, and that pointer is used for the byte read and write.

Whether that conversion produces a usable pointer, and whether the resulting address is readable and writable, are separate questions not established by the supplied evidence. A wrapping sum is not itself rejected. A nonwrapping sum is not itself evidence of valid storage.

### Output

The function returns a represented 32-bit integer status:

- Zero when the position is rejected by the signed check.
- Zero after the bit-setting path completes.
- The exact nonzero result from F-6a2a5ddf37ed when that dependency returns nonzero.

Zero does not distinguish an ignored request from a completed bit update.

### Preconditions for normal completion

An accepted position requires an object pointer that supports the applicable field accesses.

When execution reaches the bit update, conversion of the computed 32-bit numeric address must yield a pointer supporting a readable and writable byte. This requirement applies to the address after modular addition, including when that addition wraps.

Following a zero dependency result, the object must remain accessible for the capacity write and the subsequent backing-address read. The dependency must also leave conditions permitting the later byte access if normal completion is expected.

No explicit null check, allocation-length check, address-wrap check, pointer-validity check, or synchronization mechanism is present.

For a rejected position, this function performs no object access, so object validity is not required for its own operations on that branch.

## Behavior

### Position rejection

The first decision tests whether the position’s signed 32-bit interpretation is negative.

If so, the function returns zero immediately. It does not read capacity, call the dependency, read the backing address, or access bitmap storage.

Consequently, a position of 2,147,483,648 is ignored rather than processed as a large unsigned bit index.

### Capacity decision

For an accepted position, the function reads the capacity field at offset zero.

If capacity is strictly greater than the position, the dependency is not called. Execution proceeds to the backing-address read and bit update.

If capacity is less than or equal to the position, the function calls F-6a2a5ddf37ed with:

1. The original object pointer.
2. The unsigned 32-bit requested capacity equal to position plus one.

Equality triggers this call. For example, capacity eight covers positions zero through seven under the observed comparison; position eight requests capacity nine.

### Dependency result handling

The dependency’s result determines whether any further direct accesses occur.

For a nonzero result, the function immediately returns that exact result. It performs no subsequent capacity assignment, backing-address read, or target-byte access.

This does not imply failure atomicity. Any effects performed by the dependency are not undone by this function.

For a zero result, the function writes position plus one into the capacity field. It does not reread capacity to preserve a different value that the dependency may have installed. A larger capacity written by the dependency is overwritten with the exact requested value.

The capacity assignment precedes the backing-address read. Thus, subsequent processing uses the backing-address field as it exists after both the dependency call and the caller’s capacity write.

### Target-byte selection

On either the no-dependency path or the zero-result dependency path, the function reads the unsigned backing address at offset eight.

It adds the unsigned byte displacement using 32-bit modular arithmetic, then converts that resulting integer address to a byte pointer. No backing address is cached before the dependency call.

The distinction between address calculation and memory validity is material:

- Overflow of the unsigned address sum has a defined numeric result under the represented model.
- The source does not establish that the resulting pointer is valid.
- There is no special error return for an address sum that wraps.
- Inaccessible storage or an unusable pointer conversion has no specified recovery behavior here.

### Bit modification

The selected byte is read, combined with the mask using bitwise OR, and written back.

| Position modulo eight | Mask value |
|---:|---:|
| 0 | 128 |
| 1 | 64 |
| 2 | 32 |
| 3 | 16 |
| 4 | 8 |
| 5 | 4 |
| 6 | 2 |
| 7 | 1 |

All other bits in that byte are preserved relative to the value read by this operation.

If the selected bit is already set, the resulting byte value is unchanged, but the represented operation still includes a read and a write. No direct initialization of other bytes is shown.

After the byte write, the function returns zero.

The function directly writes at most one capacity field and one selected byte. Its dependency may have additional effects that cannot be bounded from this source alone.
