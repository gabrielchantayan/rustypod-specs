# F-258f535b0738

## Purpose

The established contract is the sequence of accesses, calls, and branch conditions below. A teardown or lifecycle-transition purpose is plausible, given the leading-word replacements and paired calls for linked entries, but remains inferred intent. The source does not establish the semantic meaning of the object, shared field, polling state, or linked-entry contents.

The function has no explicit result value. It provides no visible timeout, error return, or recovery path.

## Behavior

It then calls F-dc842e45211e with the original input address.

After that call returns, the function:

1. Reads a shared address from static storage.
2. Writes zero to the 32-bit field four bytes after that address.
3. Reads a second opaque 32-bit value from another static location.
4. Writes that value to the input object’s leading word.

These operations are ordered. F-dc842e45211e is invoked after the first leading-word write and before the shared-field clear. The second leading-word write occurs after that clear.

The static locations are sources of values, not a guarantee that those values are immutable. In particular, the shared address and second leading-word value are obtained after F-dc842e45211e has executed.

1. The address of original handle storage.
2. The context value read for this call.
3. The local pointer-array address.

| Byte offset from polling-state address | Initial contents |
|---|---|

### 3. Poll until the dependency returns exactly one

The function calls F-a1ecaae6738a with:

1. The polling-state address.
2. The address of separate polling-result storage.

The signed 32-bit return value controls the loop. If it equals `1`, polling stops. For every other value, the function calls F-dcbd5e1e578f with the polling-state address and then calls F-a1ecaae6738a again.

Consequently:

- `0`, negative values, and positive values other than `1` all continue polling.
- Exactly one F-dcbd5e1e578f call follows each non-`1` return.
- No F-dcbd5e1e578f call follows the completing return of `1`.
- The caller does not reinitialize polling state between attempts.
- No retry limit, timeout, cancellation branch, or distinct error branch is visible.

The polling dependency’s return value is separate from the polling-result storage supplied by address. A return of `1` does not establish that the result storage contains `1`, or that it was initialized at all.

## Acceptance examples

These examples are conditional static-contract examples, not executed tests. They assume valid accesses and returning dependencies unless stated otherwise.

1. **Immediate completion and null root.** If the first polling return is `1` and the initial root test reads zero, no F-dcbd5e1e578f call occurs. F-7fa3e55b7211 still runs. Both preparatory cleanup calls and all per-entry calls are skipped. Finalization receives anchor minus `0x94`.

2. **Non-completing polling values.** For polling returns `0`, `−1`, `2`, then `1`, there are three interleaved F-dcbd5e1e578f calls. Later processing begins only after the fourth polling return.

3. **Context changed during polling.** If the first context read yields A, a polling dependency changes that location to B, and it remains B until the later read, F-f35532238f81 receives A and F-7fa3e55b7211 receives B. Their values are not required to match.

4. **Return value differs from output storage.** If the completing polling call returns `1` while leaving result storage containing `9`, the caller copies `9` into the result-copy slot. It does not replace that value with the loop’s return value.

5. **Nonzero root, empty traversal.** If the initial root test is nonzero and preparatory processing leaves a zero head, both preparatory calls occur but neither per-entry call form occurs.

6. **Stable two-entry chain.** If preparatory processing leaves entry A followed by B followed by zero, and dependencies preserve the remaining chain, the head becomes B before A’s two calls and zero before B’s two calls.

7. **Root changed by preparation.** If F-d0acc006efef changes the root field to zero, F-88d9235286f8 receives zero. No new nonzero guard intervenes.

8. **Null root with non-null head.** A zero initial root test skips traversal even if the cleanup head is nonzero. The head alone does not activate cleanup.
