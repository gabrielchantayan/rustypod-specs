# F-e8e4e1462829

## Purpose

F-e8e4e1462829 conditionally replaces a rectangle in a mutable state object, processes and copies that rectangle, and invokes dependencies according to the resulting state.

Established behavior includes:

- Returning immediately when an enable byte is zero.
- Rejecting reversed coordinates using signed 32-bit ordering.
- Leaving the rectangle unchanged when its dimensions match the stored dimensions and a designated state slot is nonzero.
- Otherwise replacing the primary rectangle, processing it, and copying its current contents to a secondary region.
- Conditionally invoking dependencies for nonzero state slots.
- Entering a further call sequence only when a rectangle predicate returns zero and a designated slot is zero.
- Transferring to a nonreturning failure dependency when coordinate ordering or later result checks fail.

The apparent purpose is size-sensitive management of rectangle-associated resources. This is **inferred intent**, not an established interpretation of the dependencies. In particular, the body does not establish that F-8157a180d901 allocates memory, that its argument denotes a byte count, or that F-f027f0bfb38b initializes an allocation.

## Behavior

### 1. Enable gate

The first direct access is an unsigned byte read at state +0x60.

A zero value causes immediate normal return. The function does not then read the input rectangle, write state, or invoke a dependency.

### 2. Validate coordinate order

With the gate enabled, the function reads the first vertical coordinate and then the second vertical coordinate.

If the first is greater than the second under signed 32-bit ordering, execution reaches F-a817d8d58c10. Horizontal coordinates are not read on this path.

Otherwise, the function reads the first horizontal coordinate and then the second horizontal coordinate. A signed first-horizontal value greater than the second also leads to F-a817d8d58c10.

The comparison accounts for signed subtraction overflow. Merely testing the sign bit of a wrapping difference would not reproduce the behavior.

Equal endpoints pass validation. Zero width, zero height, and a rectangle with both dimensions zero are therefore permitted at this stage. No direct state write precedes either ordering failure.

### 3. Compare dimensions and possibly return

The requested height is the second vertical coordinate minus the first, using the values already read. It is compared with the primary rectangle’s second vertical word minus its first vertical word.

Only if those 32-bit differences match does the function compare widths. The requested width uses the horizontal values already read; the stored width comes from the primary rectangle.

If both differences match and the current +0x54 slot is nonzero, the function returns normally without replacing either rectangle or calling a dependency.

This is a size comparison, not coordinate equality. A translated rectangle can be ignored even though all four coordinates differ.

The +0x54 read for this early return occurs only after both dimension comparisons succeed. A zero slot prevents this return even when both dimensions match.

The arithmetic is modulo \(2^{32}\). Valid signed endpoints can produce a difference greater than the largest signed 32-bit integer without being rejected.

### 4. Replace, process, and copy

If processing continues, the function rereads the input rectangle rather than simply reusing all validation values.

The exposed sequence is:

- Read the first vertical word, second horizontal word, and second vertical word.
- Read the first horizontal word and write it to state +0x20.
- Write the three previously fetched words to +0x24, +0x28, and +0x2c, respectively.

This is not an atomic 16-byte copy. Because all four source words are fetched before the first destination write, overlap must be interpreted using that access sequence. Concurrent input changes can also make the copied rectangle differ from the rectangle that passed validation.

Next, F-c6d95d05936a receives the primary rectangle address.

After it returns, the function copies the current primary words into the secondary rectangle in coordinate order: +0x20 to +0xb4, +0x24 to +0xb8, +0x28 to +0xbc, and +0x2c to +0xc0. Each source read is followed by its corresponding destination write.
