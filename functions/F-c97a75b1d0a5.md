# F-c97a75b1d0a5

## Purpose

F-c97a75b1d0a5 is a global-controlled state machine with conditional memory-writing behavior. Depending on its dispatch path, it can bind its arguments, clear a descriptor word, derive arithmetic state, call F-a6985b136b4f, write a computed 32-bit value to a computed address, or return zero.

The supplied evidence does not establish a fixed sequence of these operations. Global contents determine the initial state, subsequent states, arithmetic parameters, and destination calculations. Neither a fixed number of writes nor eventual termination is established.

Generating and storing a sequence is a plausible **inferred intent**, not an interface guarantee. In particular, the integer argument is not established as a length, and the dependency result is not established as randomness.

This contract distinguishes:

- **Established static evidence:** operations and ordering represented by the supplied function.
- **Inferred intent:** possible high-level interpretations, not requirements.
- **documented_only:** unresolved behavior requiring global contents, dependency semantics, or execution-environment information.

No runtime tests have been performed.

## Behavior

### Entry and dispatch

Entry initializes the following working state to zero:

- Active descriptor reference and saved integer argument.
- Sequence position and saved destination index.
- Two persistent arithmetic accumulators, called **primary** and **secondary** below.
- Derived store value.
- Auxiliary arithmetic value.

The initial selector is read from a global word.

Every dispatch first reads a shared arithmetic global into an **entry-captured arithmetic value**. It then dispatches using the current selector plus a global dispatch offset. Explicit dispatch values are 0 through 8. Value 5 and every unmatched value execute clearing.

The entry capture occurs even for states that return immediately or do not subsequently use that captured value.

The numbers below identify dispatch cases, not a required execution order.

| Dispatch | Operation |
|---|---|
| 0 | Derive a store value and auxiliary value; choose a successor using a compound arithmetic sign test. |
| 1 | Bind the original arguments. |
| 2 | Return 32-bit zero. |
| 3 | Replace arithmetic state using a fresh global read and a dependency result. |
| 4 | Reset the sequence position. |
| 5 or unmatched | Clear the first active descriptor word. |
| 6 | Reset both persistent arithmetic accumulators. |
| 7 | Write one computed destination word and advance the position. |
| 8 | Derive a destination index and choose a successor using another compound sign test. |

Every nonreturning state selects another dispatch. No visible iteration limit exists.

### Binding, clearing, and resets

**Binding, state 1:** The function reads this state’s successor selector first, then binds the descriptor address and integer argument into their active working slots. Binding does not dereference the descriptor.

**Clearing, state 5 or unmatched:** The function stores a 32-bit zero through the active descriptor reference, then reads the clearing successor selector. It does not reset the position, index, accumulators, auxiliary value, or derived store value.

An unmatched dispatch is therefore a memory-writing fallback, not a harmless default or an error return.

**Position reset, state 4:** The sequence position becomes zero, then the state’s successor selector is read.

**Accumulator reset, state 6:** The secondary and primary accumulators become zero, then a successor selector is read. This successor source is also used by state 3. The reset does not clear the derived store value or auxiliary value.

### Accumulator-derived processing, state 0

This state derives a factor using a global factor word, a signed arithmetic right shift by 30, and XOR. The expression contains separate reads of that global; their equality requires stability not supplied by the evidence.

The state then:

- Replaces the derived store value with a 32-bit product of the derived factor and the secondary accumulator.
- Computes a compound sign predicate using the primary accumulator and global parameters.
- Replaces the auxiliary value with the primary accumulator minus a global subtraction parameter.

The predicate includes multiplication, addition, subtraction, complement, OR, and XOR, with literal values including 1, 2, 3, and the 32-bit pattern `0xfffffffb`. Its meaning is not established as an ordinary equality, bounds, or overflow check.

After these calculations, successor candidates are obtained in this order:

1. Read the state-0 successor global and form the **negative candidate** by adding four.
2. Read that same global again to obtain the **nonnegative candidate** directly.
3. Select between the captured candidates using the predicate’s sign.

Both reads occur regardless of which candidate is selected. A negative predicate chooses the first read plus four; a nonnegative predicate chooses the second read.

Only under an additional stability assumption can these candidates be described as a single selector and that selector plus four.

### External-result update, state 3

This state distinguishes two reads of the same arithmetic global:

- The **entry-captured arithmetic value**, obtained before dispatch.
- A **fresh arithmetic read**, obtained within state 3 before the dependency call.

The primary accumulator is first replaced with the 32-bit product of:

**fresh arithmetic read × current derived store value × 256**

This multiplication does **not** use the entry-captured value.

The function then calls F-a6985b136b4f with no explicit arguments. Its result is consumed as a 32-bit integer.

After the call, calculations use:

- The dependency result.
- The entry-captured arithmetic value.
- The primary accumulator already replaced before the call.
- The saved auxiliary value.
- Additional reads of global arithmetic parameters.

The post-call processing derives an XOR-based quantity involving the entry-captured value and a global arithmetic right shift by 30. A further correction uses a signed right shift by 31 and another global read. Products, a bitwise OR of decremented products, additions, and subtraction then determine the replacement secondary accumulator. Finally, the primary accumulator is replaced by a product involving the entry-captured value, that correction, and the auxiliary value.

The successor selector is read after those replacements.

Three distinctions must remain intact:

1. The pre-call multiplication uses the fresh read.
2. Post-call arithmetic uses the earlier entry capture.
3. Other globals are read after the call and are not established as pre-call snapshots.

The two arithmetic reads need not agree. Nor may the dependency be assumed to preserve globals, memory, or control flow.

### Index derivation and sign selection, state 8

This state replaces the saved destination index using the current sequence position and global arithmetic parameters. It also calculates a separate argument-derived quantity and a compound sign predicate.

The argument contribution includes:

**low 16 bits of the saved integer argument multiplied by a global factor**

The multiplication is not inherently a 16-bit operation; the mask retains 16 bits from its result.

The position-derived and argument-derived calculations include:

- 32-bit multiplication and addition.
- Complement operations.
- OR with `0xffff`.
- An arithmetic right shift by 30.
- A logical right shift by two of an unsigned product.
- Further multiplication, subtraction, OR, XOR, and complement operations.
- A combined right-by-one and left-by-31 bit expression.

These operations do not establish an ordinary comparison between position and length. The saved destination index is not visibly masked to 16 bits and is not proven nonnegative or in bounds.

After deriving the index and predicate, the successor candidates are obtained in this order:

1. Read the state-8 successor global and form the **negative candidate** by subtracting one.
2. Read that same global again to obtain the **nonnegative candidate** directly.
3. Select the first candidate for a negative predicate, or the second for a nonnegative predicate.

Both reads precede selection. Without stability, the candidates need not differ by one.

The saved destination index persists until another state-8 execution replaces it. State 7 uses that saved value rather than recalculating it.

### Destination write and position advance, state 7

This state performs one 32-bit store.

The destination is formed from the 32-bit address-bearing word currently read at descriptor offset 4, with displacement:

**four × global destination scale × saved destination index**

The stored bit pattern is:

**global output factor × derived store value**

There is no explicit bounds check, alignment check, or validation of either the address-bearing word or the derived displacement.

After the store, the sequence position is replaced by:

**low 16 bits of global recurrence factor × global argument factor × (previous position + `0x9c49`)**

The argument factor is the same global source used in state 8’s argument-derived product. The recurrence factor is also used in state 8’s mask-related arithmetic. These shared roles do not establish constant values.

After a successful update, the position is between 0 and 65,535 inclusive. No particular period, uniqueness of positions, or progress toward termination follows.

The state’s successor selector is read last. Its global source is also used after the position-reset state.

## Side effects

### Observable ordering

The visible control structure establishes:

- Initial selector acquisition precedes the dispatch loop.
- Each dispatch captures the arithmetic global before reading the dispatch offset for case selection.
- Binding reads its successor before saving the arguments.
- Clearing stores zero before reading its successor.
- State 3 performs its fresh-read multiplication before calling F-a6985b136b4f.
- State 3’s result-dependent arithmetic follows the call.
- States 0 and 8 each perform two ordered successor-global reads before selecting a candidate.
- State 7 reads the descriptor’s address-bearing word to form its destination.
- The destination store precedes the position update.
- The position update precedes state 7’s successor read.

Separate operand reads within one compound expression are not assigned a total order by this contract. No atomicity, synchronization, or concurrent-access safety is established.

### Aliasing and retained state

No non-aliasing restriction is checked.

A destination store may overwrite either descriptor word, a controlling global, or storage used by a later operation. In particular:

- Overwriting descriptor offset 4 can change a later destination base.
- Overwriting a global can change later arithmetic or dispatch.
- Multiple stores can target the same location.
- Clearing can affect storage serving another role.

State 7 rereads the address-bearing word each time. It does not retain an immutable original destination base.

Resetting one part of the working state does not reset unrelated parts. For example, resetting the position leaves a previously derived destination index available for a subsequent write.

### Errors and termination

No explicit error reporting, recovery, null check, bounds check, or termination guard is visible.

An invalid access may fault or have other target-dependent consequences. A dependency may not return. Dispatch cycles may continue indefinitely.
