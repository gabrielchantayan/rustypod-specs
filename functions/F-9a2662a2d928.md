# F-9a2662a2d928

## Purpose

F-9a2662a2d928 writes selected portions of an existing destination object using a source object, an externally supplied selector byte, and two implicit 32-bit values. It performs two field validations, selects a base value, calls a dependency for a nested source region, conditionally populates additional fields, increments a shared counter, and invokes a final dependency.

“State” and “configuration” are inferred descriptions of the destination and source objects. They do not establish domain semantics.

The operation is not transactional. Writes precede every explicit rejection, and there is no visible rollback. Some destination fields retain earlier contents on particular paths. Neither dependency is known to preserve state, configuration, or shared memory. Accordingly, an assignment establishes a value at that assignment’s observation checkpoint, not necessarily at function return.

## Interface

### Explicit arguments and result

| Item | Established contract |
|---|---|
| First explicit argument | A 32-bit value with no visible use. |
| Second explicit argument | A pointer from which one 8-bit external selector is read, without a preceding validity check. |
| Return value | A 32-bit bit pattern: `0xFFFFFFFF` on an explicit rejection, or `0x00000000` after the final dependency returns normally. |

Interpreting `0xFFFFFFFF` as signed −1 is conventional; the established result is the bit pattern.

### Implicit inputs

The visible interface also relies on:

- A writable state-object base.
- A readable configuration-object base.
- An implicit 32-bit value, called **A** here.
- Another implicit 32-bit value, called **B** here.

Their invocation mechanism is unresolved. Neither value is established as a constant.

Throughout this contract:

- **a** is the low eight bits of A.
- **b** is the low eight bits of B.
- **External selector** is the byte read through the second explicit argument.
- **Configuration selector** is the byte read at configuration offset `0x00`.

The selectors are independent. No equality check connects them.

### Memory and execution preconditions

Visible state accesses extend through byte offset `0x8D`, requiring an accessible span of at least `0x8E` bytes when those accesses execute. Direct configuration accesses can extend through offset `0x53`. F-6d8c85350b66 receives configuration base plus `0x40`; its additional access requirements are unknown.

Objects must support the listed byte and 32-bit accesses. Pointer validity, alignment, byte order, object size, non-overlap, and exclusive access are not checked here. The offset descriptions are not a portable serialization format.

Dependencies must return normally for execution to reach later stages. There is no established error translation for faults, exceptions, or non-returning calls.

The next branch uses the captured external selector, not a new read from state `0x58`.

### External-selector-specific writes

| External selector | Ordered additional writes |
|---|---|
| `0` or `7` | Write a to state `0x42`, then `0x43`; individually copy configuration bytes `0x30`–`0x33` to state `0x5D`–`0x60`, in increasing-offset order. |
| `1`, `2`, or `5` | Write a to state `0x42`, then `0x43`. |
| `3` | Write a to state `0x42`, then `0x43`; individually copy configuration bytes `0x2C`–`0x2F` to state `0x59`–`0x5C`, in increasing-offset order. |
| `4` | Copy configuration byte `0x10` to state `0x42`, then configuration byte `0x11` to state `0x43`. |
| `6` or any other byte | No additional writes at this stage. |

An unrecognized external selector does not itself reject the operation. Omitted fields are not initialized by this stage.

### Unsigned range validation

First, read configuration `0x08` as an unsigned 32-bit value. Then write a to state byte `0x40`.

If that captured value is at most 8, continue without assigning state word `0x3C`.

If it exceeds 8, read configuration `0x08` again:

- A second unsigned value greater than 16 causes immediate return of `0xFFFFFFFF`.
- Otherwise, write full-width B to state `0x3C` and continue.

For stable configuration memory:

| Configuration `0x08` | Outcome |
|---|---|
| 0–8 | Continue without initializing state `0x3C`. |
| 9–16 | Assign B to state `0x3C`, then continue. |
| 17–`0xFFFFFFFF` | Reject. |

The first read determines whether the second read happens; the second determines rejection. With mutable or overlapping memory, a first value above 8 followed by a second value at most 8 still takes the B-assignment path.

### Discriminator validation

Read configuration word `0x0C` and compare it with 1.

- If equal, write b to state byte `0x41`.
- Otherwise, write a to state byte `0x41`, then read configuration `0x0C` again.
  - If the second value is not 2, return `0xFFFFFFFF`.
  - If it is 2, increment the existing signed 32-bit state value at `0x3C` by one and store the result.

When the range stage did not initialize `0x3C`, the increment operates on its preexisting contents. Signed-overflow behavior is not established.

After validation, perform these writes in order:

| State offset | Width | Value |
|---|---:|---|
| `0x14` | 32 bits | A fresh read of configuration `0x0C` |
| `0x08` | 32 bits | A |
| `0x0C` | 32 bits | A |
| `0x05` | 8 bits | a |
| `0x04` | 8 bits | a |
| `0x4C` | 32 bits | A |
| `0x45` | 8 bits | b |
| `0x46` | 8 bits | a |

The configuration value copied to state `0x14` need not equal the value accepted by validation if the source changes between reads.

### Configuration-selector dispatch

Read configuration byte `0x00`:

| Configuration selector | Action |
|---|---|
| `0`, `3`, or `5` | Write A to state word `0x78`. |
| `1` | Write an opaque static 32-bit value, **K₁**, to state `0x78`. |
| `7` | Write an opaque static 32-bit value, **K₇**, to state `0x78`. |
| `2`, `4`, `6`, or any other byte | Return `0xFFFFFFFF`. |

K₁ and K₇ come from distinct static references. Their numeric values, and whether their contents differ, are unknown.

Every accepted selector writes `0x78` before calling F-6d8c85350b66. That call may subsequently change `0x78`; the earlier assignment is not a preservation guarantee.

### Nested-region processing

Call F-6d8c85350b66 once with configuration base plus `0x40`. Its visible result is a 32-bit integer, tested only for zero versus nonzero.

#### Zero result

After the dependency returns zero:

1. Write a to state byte `0x28`.
2. Write A to state words `0x2C`, `0x30`, `0x34`, `0x38`, `0x7C`, and `0x80`, in that order.

These are assignments of A, not necessarily zeroing operations.

There is no assignment to state `0x78` in this branch. Its value after the dependency remains unconstrained by the earlier selector assignment unless dependency preservation is separately assumed.

#### Nonzero result

After the dependency returns nonzero:

1. Write b to state byte `0x28`.
2. Copy configuration word `0x40` to state `0x2C`.
3. Read configuration word `0x44`, retain that value, and write it to state `0x30`.
4. Read configuration word `0x48`, retain that value, and write it to state `0x34`.
5. Read configuration word `0x50`, retain that value, and write it to state `0x38`.

These configuration reads occur after the dependency, so they observe any changes it made. Configuration `0x4C` is not directly copied.

Next, read state byte `0x58`. If it equals 7, overwrite state `0x30`, `0x34`, and `0x38`, in that order, with the respective retained configuration values shifted left by one bit. The shift inputs are those retained values, not fresh reads of the destination words.

The selector check uses the state byte at this later point, not the originally captured external selector. The dependency may have changed it.

The shifts operate on signed 32-bit values in the supplied representation. Nonnegative inputs through `0x3FFFFFFF` have unambiguous doubled results. Behavior for negative inputs or results outside the signed representable range remains documented_only.

Then:

1. Read state `0x78` as an unsigned 32-bit base.
2. Read state `0x30`, add it to that base using unsigned 32-bit arithmetic, and write the low 32 bits to state `0x7C`.
3. Compare the captured unsigned base with a read of state `0x34`, interpreted as unsigned.
4. If the base is smaller, read state `0x34` again and subtract the base using unsigned 32-bit arithmetic. Otherwise, select zero.
5. Store the selected result through a signed 32-bit value into state `0x80`.

With stable state, the final calculation is a difference clamped to zero when the base is greater than or equal to state `0x34`. With mutable state, comparison and subtraction can observe different values, so that description is conditional.

Unsigned addition and subtraction are modulo `2³²`. For a selected difference above `0x7FFFFFFF`, its passage through the signed intermediate leaves the exact out-of-range conversion behavior unresolved by the supplied representation.

### Success tail

After either nested-result branch:

1. Obtain the referenced shared-counter location.
2. Write a to state byte `0x8C`.
3. Read the signed 32-bit counter, add one, and write it back.
4. Call F-266a29fc8dc5 with an opaque static first argument and a second argument of zero.
5. Return `0x00000000` if that call returns normally.

The counter update is not shown as atomic. Signed overflow and external synchronization are unresolved.

The final dependency’s result is ignored. Its normal return does not imply preservation of any state field or of the counter.

## Side effects

- State mutation begins before validation; explicit rejection does not undo it.
- Explicit rejection paths reach neither dependency and do not perform the visible counter increment.
- The visible successful path performs one counter read–increment–write before the final dependency.
- No direct allocation, release, ownership transfer, whole-object clearing, or rollback is shown.
- Neither dependency’s allocation, release, ownership, or memory-preservation behavior is established.
- Dependency mutations can affect later reads, including the nested configuration fields, state `0x58`, state `0x78`, and the counter reference.
- Overlapping objects can make earlier writes alter later reads. Retention statements require the absence of such interference.
- No thread-safety, reentrancy, volatile-access, or memory-ordering guarantees are established.

The ordering above describes the supplied static operations, not independently verified hardware transaction order.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, assume valid, non-overlapping objects, stable memory apart from the described operations, and arithmetic within established ranges. Each state assertion identifies its observation checkpoint; it is not automatically a post-return assertion.

1. **Early range rejection retains preceding writes.**  
   With stable configuration `0x08 = 17`, return `0xFFFFFFFF`. At that return, the initial writes, applicable external-selector writes, and state `0x40` assignment have occurred. Discriminator processing, both dependencies, and the counter update have not occurred.

2. **The small-range path increments existing state.**  
   With configuration `0x08 = 8`, configuration `0x0C = 2`, and initial state `0x3C = 20`, state `0x3C` is 21 immediately after the discriminator increment, before either dependency. It was not first replaced with B. Its value at function return is not established without additional preservation assumptions.

3. **The upper accepted range initializes before incrementing.**  
   With configuration `0x08 = 16`, configuration `0x0C = 2`, and B = 5, state `0x3C` is 6 immediately after the discriminator increment, before either dependency. A post-return value of 6 additionally requires preservation by both dependencies and absence of other interference.

4. **Late selector rejection remains partially mutating.**  
   With accepted range and discriminator fields but configuration selector 4, return `0xFFFFFFFF` after the common post-discriminator writes. Neither dependency is called.

5. **A zero nested result guarantees six subsequent word assignments, not seven.**  
   With accepted validation, configuration selector 0, and A = 9, state `0x78` receives 9 immediately before F-6d8c85350b66. Suppose that dependency changes `0x78` to zero and returns zero. Immediately after the last zero-branch assignment, before the success tail, the six words at `0x2C`, `0x30`, `0x34`, `0x38`, `0x7C`, and `0x80` are 9; state `0x78` remains zero under these assumptions. Thus nonzero A does not establish that all seven words are nonzero together. The six-word checkpoint does not assert preservation across F-266a29fc8dc5.

6. **A later selector value of 7 doubles retained inputs.**  
   Let A = 4, external selector = 7, configuration selector = 0, and nested configuration words `0x44`, `0x48`, and `0x50` be 3, 10, and 2. Suppose F-6d8c85350b66 returns nonzero and preserves those source values, state `0x58`, and state `0x78`. Immediately after the nonzero branch writes state `0x80`, before the success tail, state `0x30`, `0x34`, and `0x38` are 6, 20, and 4; state `0x7C` is 10; state `0x80` is 16. No preservation by the final dependency is implied.

7. **Unsigned addition wraps while the stable-state difference clamps.**  
   At entry to the nonzero branch, let state `0x78 = 0xFFFFFFFE`, state `0x58` differ from 7, configuration `0x44 = 5`, and configuration `0x48 = 10`. Immediately after the branch writes state `0x80`, state `0x7C` is 3 and state `0x80` is zero. This checkpoint precedes F-266a29fc8dc5; it is not a claim about post-return contents.

8. **The external selector alone does not reject.**  
   External selector `0xFF` causes no selector-specific writes. With accepted configuration fields, supported configuration selector, established arithmetic, and normally returning dependencies, the visible result is zero. Untouched selector-specific fields retain their prior values only until another operation or dependency changes them.
