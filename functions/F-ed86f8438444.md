# F-ed86f8438444

## Purpose

F-ed86f8438444 conditionally dispatches an operation associated with a caller-supplied object. A gate input selects either immediate rejection or dispatch. Dispatch initializes a mutable four-word record, derives an object-relative address, and selects a sequence of dependencies using a selector and observations of a comparison global.

The comparison global is referenced first for equality and, only if equality fails, again for ordering. The supplied representation does **not** establish a single captured comparison value. Nor does it establish the signedness of the ordering comparison: the global’s declaration is absent, so the selector’s declared signed type alone is insufficient.

Immediate rejection returns a fixed status and conditionally initializes the object’s first word. Dispatch returns the first two words of the mutable record as they stand after the selected dependencies return normally.

This contract distinguishes:

- **Established static evidence:** operations, arguments, sequencing, and result construction shown by the supplied representation.
- **Inferred intent:** descriptive interpretations such as “dispatch,” “preparation,” and “status.”
- **documented_only:** unresolved types, dependency behavior, runtime properties, and validity requirements.

No runtime tests have been performed.

## Behavior

### Immediate rejection

The gate comparison precedes any direct object read.

When the gate differs from `0x408`, the function:

1. Reads the 32-bit word at object offset zero.
2. Writes `0x00000500` to that location if the observed word is zero.
3. Returns the original object-address word in the low half and `0x00000500` in the high half.

A nonzero first word is not overwritten. Its value does not determine the returned high half.

No dependency is called, and the comparison global is not referenced on this path. The selector and auxiliary value have no effect on the represented rejection behavior.

Normal completion requires readable storage for the first word and, when the read yields zero, writable storage there. No explicit null, alignment, accessibility, or size check is shown.

### Dispatch setup

When the gate equals `0x408`, the function performs the following represented operations before routing:

1. Calculates the object-relative address at offset `0x838`.
2. Initializes the record’s first, second, third, and fourth words, in that order.
3. Evaluates the selector’s equality comparison against the global.

The derived address is based on the original object input. A dependency’s later change to the record’s first word does not cause that address to be recalculated.

The represented record initialization and global-reference order are established. Compiler transformations, actual machine-load counts, atomicity, and synchronization properties are not independently established.

### Comparison observations

For the routing description:

- **E** denotes the comparison-global value observed for the first, equality comparison.
- **O** denotes the value observed for the second, ordering comparison, if that comparison is reached.
- **Equality succeeds** means the selector equals E under the comparison’s applicable type conversions.
- **Lower comparison succeeds** means the selector is less than O under the ordering comparison’s applicable type conversions.

The sequence is significant:

1. Observe the global for equality.
2. If equality succeeds, select the equality route without a second comparison.
3. Otherwise, observe the global again for the less-than comparison.
4. Select the lower branch if less-than succeeds; select the upper branch if it fails.

E and O are not established to be equal. No explicit intervening write or dependency call appears in this function, but that does not establish a stable global snapshot.

The upper branch is the **failure of less-than**, not an established greater-than condition. If equality against E fails but the selector compares equal to O, less-than fails and the upper branch is selected.
