# F-068ffcf20684

## Purpose

F-068ffcf20684 performs an ordered sequence of memory reads and writes through incoming addresses, pointer-bearing fields, and calculated destinations, followed by an unresolved indirect transfer carrying three arguments.

The established behavior is memory mutation and dispatch. The supplied representation does not establish an object model, protocol, ownership operation, or higher-level purpose. Self-links, repeated stores, and small constants do not by themselves establish initialization, serialization, or reference counting.

This contract describes static evidence only. It does not establish executable fidelity, runtime reachability, or successful execution on any target.

## Interface

### Incoming state

No explicit parameters are declared. Three incoming machine-state values are nevertheless consumed:

| Contract name | Established use |
|---|---|
| **A** | Address for an initial byte write and a pointer-field read. |
| **B** | Principal address, stored address value, and source of truncated address bytes. |
| **C** | Word written into B’s storage, also truncated for a byte write. |

These are contract names, not recovered parameter names. Their calling-convention locations and entry-state requirements are **documented_only**.

Three external storage cells supply additional inputs:

- **G1:** a word used in an address sum and truncated for a halfword write.
- **G2:** a word used in address calculations, truncated for a halfword write, and supplied to the indirect target.
- **G3:** a word written to a destination calculated from G2.

Each cell is read at its specified point, not necessarily at entry. Earlier writes may affect these cells if addresses alias.

### Outputs

No return value is declared. Observable outputs are the represented memory accesses and the three arguments supplied to the indirect target.

A return appears after the transfer in the supplied representation. Whether the underlying transfer actually returns is unresolved.

### Widths and notation

- A **byte** is 8 bits, a **halfword** 16 bits, and a **word** 32 bits.
- A low byte or halfword means the least significant 8 or 16 bits of a captured value.
- All offsets and unprefixed constants below are decimal.
- Reading or writing a word at an address accesses four bytes beginning there; a halfword accesses two.
- Named values and addresses remain captured values unless a fresh read is explicitly stated.

The representation uses 32-bit integer-like address values and pointer fields. Native address interpretation, byte order, and alignment requirements are unresolved.

The dispatch byte is converted to a 32-bit unsigned value. Arithmetic on that unsigned value, including addition of 68 or 69, is modulo \(2^{32}\) in the displayed integer model. This does not establish that the resulting address is valid. Other calculated addresses involve signed integer-like sums or doubling; safe wraparound must not be assumed for those expressions.

## Behavior

### Ordering, aliasing, and validity

The following phases describe the represented access order, not merely desired final memory contents.

No separation is established among A, B, traversed nodes, external cells, or calculated destinations. Earlier writes can alter later pointer reads, payload reads, and external-cell reads. Overlapping writes can alter only part of a later word, with the resulting value dependent on byte order.

A value captured before a write is not retroactively changed by that write. Conversely, a fresh read must not be replaced by a previously captured value without an additional no-alias assumption.

For ordinary-memory execution, every reached access requires readable or writable storage of its stated width. Pointer-bearing fields must contain usable addresses when consumed. The body does not visibly check these conditions.

### Initial capture and traversal

The first word read is at **B + 100**. Call it **Initial payload**, and retain its low byte. That byte is written at **A + 9** before the word at **A + 116** is read as **First node**.

The low byte of B, called **Base byte**, is then written at **First node + 13**. Next, the word at **First node + 84** is read and the captured word is written back to that same address. The value involved is the word present when this read occurs, not necessarily its entry-time value. Byte value 116 is subsequently written at **First node + 9**.

The next writes place C as a word at **B + 68**, then B as a word at **First node + 52**. The word at **First node + 4** is read as **Second node**. Initial payload is written as a word at **Second node + 36**, followed by C’s low byte at **B + 25**.

Two words are then captured from Second node, in order:

- **Linked value** from **Second node + 116**.
- **Replacement payload** from **Second node + 4**.

The word at **B + 116** is read as **Root node**. A word read from **Root node + 20** supplies a destination base; Linked value is written as a word at that base plus 84. Only afterward is **Root node + 4** read as **Branch node**.

Initial payload’s low byte is written at **B + 13** twice consecutively. Replacement payload is then written as a word at **B + 100**, followed by word value 116 at **Branch node + 48**.

The traversal next rereads **Root node + 4**. The word at the newly obtained address plus 116 becomes **Middle node**. This reread can differ from Branch node because intervening writes may alias the field.

A fresh word read at **B + 100** supplies **Current payload byte**, its low byte. That byte is written at **B + 29**. Finally, a word read at **B + 68** supplies another address, whose word at offset 20 becomes **Selected node**. This path does not necessarily follow C: the earlier C store may have been overwritten through aliasing.

### Linking and payload propagation

Linked value is first written as a word at **Middle node + 52**, followed by Selected node as a word at **B + 20**. The word at **B + 84** is captured as **Previous base field**. Base byte is then written at **Selected node + 9**.

A word read at **Middle node + 4** supplies an address whose word at offset 116 becomes **Leaf node**. Linked value’s low byte is written at **Leaf node + 21**. The next writes, in order, are:

- B as a word at **B + 84**.
- Middle node’s low byte at **B + 17**.
- Previous base field’s low byte at **Leaf node + 17**.

The word at **Leaf node + 100** is then captured as **Leaf payload**. Current payload byte is written at **B + 9** before **Middle node + 4** is read again, this time as **Peer node**. Peer node need not equal the address obtained from the earlier read of that field.

Base byte is written at **Peer node + 9**. The word at **Peer node + 80** is captured as **Peer payload**. The following writes occur in order: Leaf payload’s low byte at **Peer node + 17**, Base byte again at **Peer node + 9**, Leaf payload as a word at **B + 20**, Peer node’s low byte at **B + 13**, and Peer payload’s low byte at **Peer node + 0**.

Two further words are captured from Middle node: **Indexed offset** from offset 116, then **Container node** from offset 20. Peer node is written as a word at **Peer node + 84**, establishing a stored self-address but no ownership meaning.

The word at **Container node + 4** is read as **Terminal node**. Byte value 100 is written at **Terminal node + 16**; word value 100 is then written at **B + 84**, followed by word value 100 at **Terminal node + 64**.

This phase ends with four writes, in order:

- Leaf payload’s low byte at **B + 13**.
- Terminal node’s low byte at **Container node + 9**.
- Leaf payload as a word at **B + 36**.
- Base byte at **Container node + 17**.

These are temporal obligations. For example, B + 84 receives B and later 100, but aliasing can produce additional overlapping changes. Neither value is an unconditional final-state guarantee.

### Calculated destinations and dispatch

G1 is read as **First external word**. A fresh word read at **B + 116** becomes **Final root value**; its low halfword becomes **Root halfword**. This fresh read is independent of the earlier Root node capture.

Root halfword is written at address **Final root value + B**. First external word’s low halfword is then written at address **2 × Terminal node**.

Next, one byte is read at address **Indexed offset + B**. The displayed plain-character interpretation is converted to a 32-bit unsigned value, called **Dispatch value**. Plain-character signedness is unresolved:

- For bytes below 128, Dispatch value equals the byte.
- With unsigned plain character, bytes 128–255 retain those values.
- With signed 8-bit plain character, a high-bit byte can become a negative intermediate and then a large unsigned value.

Root halfword is next written at **First external word + Final root value**, then written again at **Final root value + B**. The latter repeats the earlier halfword store using the captured values.

Word value 69 is written at **Dispatch value + 69**. G2 is then read as **Second external word**, G3 as **External payload**, and **B + 68** as **Dispatch payload**, in that order.

The final three direct writes are:

- Byte value 68 at **Dispatch value + 68**.
- External payload as a word at **2 × Second external word**.
- Second external word’s low halfword at **Linked value + Second external word**.

The indirect target receives, in order:

1. **Dispatch value bitwise-OR 68**.
2. **Second external word**.
3. **Dispatch payload**.

The first argument uses bitwise OR, not addition, and is not generally either dispatch-related store address.

The byte store and word store based on Dispatch value occupy five consecutive byte positions in the 32-bit address calculation, potentially crossing its wrap boundary. The word store occurs first and is not necessarily naturally aligned.

## Acceptance examples

These examples are conditional static obligations, not executed tests.

### Captured word and byte truncation

Assume Initial payload is 0x123456AB and execution reaches the stated accesses.

The initial write at A + 9 carries byte 0xAB. The later word write at Second node + 36 carries the complete captured value 0x123456AB. The two first-phase writes at B + 13 each carry 0xAB.

These obligations concern values written at those moments. They do not require those values to survive subsequent overlapping writes.

### Self-read uses the value present at read time

Assume **First node + 84 contains 0x11223344 when the self-read occurs**. The represented operation reads that word and writes the captured 0x11223344 back to the same address.

An entry-time value alone is insufficient. For example, if **A + 9 equals First node + 84**, the earlier initial byte store can alter part of that word before the self-read. Its byte-order-dependent effect must be accounted for rather than assuming the original word is read.

A final-memory observation alone may not distinguish the self-read-and-write from no operation. Access-sensitive storage may distinguish them.

### Address truncation is not dereferencing

Assume B is 0x12345678. Base byte is 0x78. Each store specified as using Base byte carries 0x78, regardless of the byte stored at address B.

### Fresh reads can change traversal

Assume an earlier write changes B + 116 before the final phase. The final phase uses the word read there at that later point, not the earlier Root node capture.

Likewise, the second read of Root node + 4 and the later reread of Middle node + 4 use their then-current contents. Equality with earlier captures requires additional conditions.

### External reads are not entry snapshots

Assume an earlier calculated write overlaps G2. The Second external word is obtained from G2 after the word store at Dispatch value + 69, at its specified read point. No requirement preserves G2’s entry-time contents.

### Bitwise-OR dispatch argument

Assume Dispatch value is 5 and all reached accesses are valid.

The word store of 69 begins at address 74. The later byte store of 68 targets address 73. The first indirect argument is 69, because 5 bitwise-OR 68 equals 69; it is neither store address.

### High-bit indexed byte

Assume the indexed byte is 0x80.

With unsigned plain character, Dispatch value is 128. With signed 8-bit plain character and the displayed conversion, it is 0xFFFFFF80. The evidence does not choose between these cases or establish validity of their resulting addresses.

### Invalid intermediate destination

If a reached pointer supplies an unusable destination, successful completion or dispatch is not required. No visible guard protects that access, and the direct body provides no rollback of earlier writes.
