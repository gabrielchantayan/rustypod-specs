# F-d3c85b6f029d

## Purpose

F-d3c85b6f029d performs a fixed prefix of indirect calls and byte writes, then repeatedly performs ten indirect calls and one byte write. The supplied representation contains no normal exit from the repeating phase.

Established behavior includes argument transformations, fresh selector reads, retained state, call ordering, and a dispatch-target change after the first iteration. No application-level purpose is established. Interpreting the function as allocation, serialization, protocol handling, or device control would be inferred intent.

This contract distinguishes:

- **Established static evidence:** operations and data relationships visible in the supplied representation.

## Behavior

### Integer widths and conversion boundaries

Identified unsigned arguments and unsigned results are represented as 32-bit quantities. Their right shifts introduce zeros. Their left shifts retain the low 32 bits.

Several dependency results are represented as signed 32-bit quantities. Left shifting a negative signed value, or obtaining a result outside the signed range, has no established portable outcome here. Signed multiplication and addition likewise require qualification when their mathematical results are not representable.

Three prefix stores convert a value to **plain character** before writing it. The representation does not establish plain-character signedness or the implementation’s handling of out-of-range conversion to a signed character type.

This affects all three stores:

- **Write 1:** conversion of the complete unsigned first argument.
- **Write 2:** conversion of the unsigned first argument shifted right by 22.
- **Write 3:** conversion of a retained signed intermediate derived from F-12.

For these stores, describing the resulting memory pattern as the source value’s low eight bits requires a **low-eight-bit-preserving narrowing assumption**. That assumption is not established by the supplied representation. In particular, a positive source value above 127 can exceed an eight-bit signed plain-character range even when it fits in an unsigned character.

Where the converted value is representable, its numerical value is preserved. Examples below use small nonnegative values when giving unconditional numerical character-conversion results.

F-12 adds a separate, earlier conversion boundary:

1. Its unsigned 32-bit result is shifted left by two with unsigned arithmetic.
2. That result is assigned to a signed 32-bit intermediate.
3. The intermediate is converted to plain character for write 3 and later used in selector-address arithmetic.

When the shifted unsigned value is at most `0x7fffffff`, the signed intermediate has that numerical value. Otherwise, the conversion result and whether execution continues normally are not established.

Resolving this unsigned-to-signed conversion does **not** resolve the later plain-character conversion. For example, an intermediate of 128 is representable as signed 32 bits but may be outside the plain-character range.

A **32-bit wrapping interpretation**, where explicitly invoked below, additionally assumes that relevant arithmetic retains low 32-bit patterns and that those patterns have the stated address interpretation. It is not a claim of portable signed-arithmetic behavior.

### Address selection

**Incoming-selector writes.** Four prefix writes each read the unsigned byte at the incoming selector base plus one. Each freshly read value selects that write’s destination by addition of `0x11`. Computing the selector-read address depends on the incoming base and applicable arithmetic semantics.

**Fourth-argument write.** Write 3 uses the fourth argument shifted right by seven, plus `0x1c`. This unsigned calculation ranges from `0x1c` through `0x0200001b` and does not overflow 32 bits.

**Result-derived selector writes.** The signed intermediate derived from F-12 is multiplied by `0x400`, then increased by one, to produce a selector-read address. The unsigned byte read at that address selects the final write destination by addition of `0x11`.

Under bit-preserving unsigned-to-signed conversion and a 32-bit wrapping/address interpretation, this selector-read address is the low 32 bits of F-12’s original result shifted left by 12, plus one. That formula identifies the selector’s address, not the final destination.

The representation retains the address-producing intermediate throughout the loop and rereads the selector for every associated write. Actual ABI preservation is not independently established.

## Acceptance examples

These are conditional static observations, not executed tests. Each assumes execution reaches the stated operation, accessible addresses, returning preceding dependencies, and no intervening effects that contradict the scenario.

1. **Full-width input versus conditional byte patterns.** With first argument `0xffffffff`, F-01 receives three complete `0xffffffff` arguments. Writes 1 and 2 have pattern `0xff` only under low-eight-bit-preserving plain-character narrowing. Their patterns are otherwise unresolved.

2. **Representable character values.** With first argument 1, write 1 stores numerical value 1 and write 2 stores zero. Neither character conversion requires an out-of-range result.

3. **Fourth-argument boundaries.** Fourth argument zero selects address `0x1c` and passes zero to F-13. Fourth argument `0xffffffff` selects `0x0200001b` and passes `0x01ffffff`.

4. **Fresh selector observation.** An incoming selector of `0x20` selects destination `0x31`. If that selector becomes `0x40` before the next incoming-selector write, the next destination is `0x51`, not the previous selection.

5. **Two conversion boundaries.** If F-12 returns `0xffffffff`, its unsigned shift produces `0xfffffffc`, while F-15 receives `0x00ffffff`. Write 3 has pattern `0xfc` only under bit-preserving intermediate conversion and low-eight-bit-preserving character narrowing. With the additional wrapping/address interpretation, the selector-read address is `0xfffff001`.

6. **Representable intermediate, unresolved character conversion.** If F-12 returns 32, the signed intermediate is 128 and the selector-read address is `0x20001`; the address arithmetic is representable. Write 3 is still conversion-sensitive: 128 may be outside the plain-character range. Under low-eight-bit-preserving narrowing its pattern is `0x80`.

7. **Fully representable small intermediate.** If F-12 returns 1, the intermediate is 4, write 3 stores numerical value 4, and the selector-read address is `0x1001`. The final destination depends on the byte read there.

8. **Excluded upper bits.** If F-24 returns `0x3e000000`, the auxiliary value is 31 and F-25 receives 62. Setting either highest result bit does not change those values. The first F-27 second argument is zero.

9. **Carried-state transition.** F-26’s result reaches the first F-27 without a shift. If F-36 later returns 1, the next F-27 receives 4 and `0x00040000`; both signed shifts are representable for that input.

10. **Dispatch transition and interruption.** The first F-27 target calculation produces `0x08833787`; later calculations produce `0x088337c5`. Separately, if F-02 does not return, write 1 and F-01 have already occurred, but F-03 and later operations are not reached.

11. **Continuing execution.** If all accesses, conversions, arithmetic, and dependencies continue normally, every iteration invokes F-27 through F-36 in order and performs one zero-byte store. No normal return follows.
