The **doubling carry** is true if doubling overflows or adding that comparison bit to the doubled low result overflows. This is not saturation.

Another global has distinct evaluations:

1. Its first value plus doubling carry supplies the saved **byte-address contribution**.
2. Its second value is compared unsigned against 0xffffffa6.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Threshold:** 0x4e contributes zero to derived address value; 0x4f contributes one. Signed doubling still requires applicable target semantics.
- **Early alias:** if the ambient-byte store changes threshold’s global storage, the subsequent threshold evaluation uses that changed storage; the previously saved replacement word remains saved.
- **Saved word:** the doubled-secondary byte store precedes the fourth-argument halfword store. The shift uses the preceding full-word load, not a reload.
- **Carry evaluations:** a second carry-global evaluation of 0xffffffa7 skips the third evaluation. A value of 0xffffffa6 requires it; the third value may differ from the first two.
- **Initial traversal ordering:** if the root store aliases the carrier-load location, carrier is loaded from the changed storage. The initial-child load follows carrier’s load, and both precede carrier’s first 0x54 store.
- **Replacement timing:** the linked replacement global is read after both consecutive unsigned-link-0x09 stores, but before the root-child load and nested unsigned-link update.
- **Shift provenance:** unsigned link ending in 0x03 supplies shift count three and the doubled-link character address. The result reaches second carrier link’s 0x08 before carrier’s 0x74 update and carrier’s 0x11 result store.
- **Corrected overlapping stores:** if working record plus 0x0c equals hub plus 0x15, and the saved hub-0x64 low byte is 0xa5, these stores write 0x73 followed by 0xa5. Their order cannot be reversed.
- **Full-width read:** a readable byte at hub plus 0x64 is insufficient by itself for the later fresh word load. All four bytes must support the represented read even though only its low byte is used.

- **Terminal OR:** final character value 0x40 produces first argument 0x44, not 0x84.
