# F-bc773b12848b

## Purpose

F-bc773b12848b adjusts two fields in a memory-backed state object, derives a bounded transfer count, invokes a dependency for one or two contiguous spans, and advances the state’s cursor by the derived count.

The layout and arithmetic suggest consumption from an eight-byte circular storage area. That interpretation is **inferred intent**, not an independently established storage or ownership contract. In particular, the supplied evidence does not establish the dependency’s transfer direction, return behavior, memory effects, or complete interface.

The established behavior is therefore a state-normalization and dependency-dispatch contract. Successful copying of the returned number of bytes is conditional on the behavior of F-357fdad13bb5.

## Behavior

### 1. Normalize the state fields

The function first reads the 32-bit cursor field at offset 12 and logically shifts it right by three. This produces the number of complete eight-byte units contained in that unsigned value.

If that quotient is zero, neither state field is written during normalization.

If the quotient is nonzero, the function:

1. Reads the cursor field again and writes it after subtracting eight times the previously calculated quotient.
2. Reads the field at offset 8 and writes it after subtracting the same amount.

The cursor write precedes the offset-8 field write.

For stable ordinary memory, the normalized cursor is the initial unsigned cursor modulo eight. The subtraction from both fields preserves their 32-bit modular difference. The source does not check whether subtracting that amount from the offset-8 field represents a valid application-level position.

The repeated cursor read matters if the storage can change between accesses. The evidence does not establish volatile semantics, synchronization, atomicity, or support for concurrent mutation. The simple remainder interpretation assumes the cursor remains unchanged between its initial read and normalization write.

### 2. Derive availability and select the count

After normalization, the function reads the two state fields and forms a 32-bit difference:

- Availability bit pattern: field at offset 8 minus field at offset 12.

The supplied expression does not establish which of those two reads occurs first.

The function then compares the availability bit pattern and the requested count as signed 32-bit integers. If signed availability is less than the signed requested count, the selected count becomes the availability bit pattern. Otherwise, the requested count is retained.

For values in the range 0 through \(2^{31}-1\), with a nonnegative availability in that same range, this behaves like an ordinary minimum.

That interpretation does not extend to arbitrary 32-bit inputs:

- An availability bit pattern with its top bit set is negative in the signed comparison.
- A requested count with its top bit set is also negative in that comparison.
- There is no explicit rejection of either condition.
- There is no conversion of a negative-looking availability to zero.

The selected count is subsequently used as an unsigned quantity.

### 3. Select the first span

The function reads the cursor field again and uses its low three bits as a byte offset from the state address. This offset is between zero and seven.

The bytes remaining until the end of the inferred eight-byte storage area are eight minus that offset. The first-span count is the unsigned minimum of:

- The selected count.
- The bytes remaining to that boundary.

The first-span count is therefore always between zero and eight, inclusive.

For stable memory following normalization, the cursor itself is already between zero and seven. The mask nevertheless remains part of the observed behavior.

### 4. Invoke the dependency

The function always makes a first invocation of F-357fdad13bb5, including when the selected count is zero.

That invocation supplies three visible arguments, in this order:

1. The output address.
2. The state address plus the masked cursor offset.
3. The first-span count.

No dependency result is inspected.

If the selected count differs from the first-span count, the function makes a second invocation of F-357fdad13bb5. The supplied representation exposes only two arguments for this invocation:

1. The output address plus the first-span count.
2. The unadjusted state address.

No explicit third argument is shown for the second invocation. In particular, the evidence does **not** establish that this invocation receives the selected count minus the first-span count. Supplying that difference would add behavior not established by the provided representation.

The second invocation occurs after the first returns. Its occurrence and address calculations use counts selected before the first invocation; they are not recomputed from any state modifications made by the dependency.

### 5. Advance the cursor and return

After all required dependency invocations return, the function reads the cursor field at offset 12 again. It adds the selected count and writes the result back to that field using 32-bit arithmetic.

Consequently, the final write is based on the cursor value present **after** the dependency calls, not necessarily the normalized cursor used to select the first span.

If the dependency does not modify that field, the final cursor is the normalized cursor plus the selected count, modulo \(2^{32}\). If the dependency modifies it, the selected count is added to that modified value instead.

The function then returns the selected count.

The function does not re-normalize the cursor after this addition. A cursor of eight or greater can therefore remain stored on return.

## Side effects

### Direct state writes

The function can directly perform:

- A normalization write at offset 12.
- A normalization write at offset 8, after the cursor normalization write.
- A final advancement write at offset 12, after the dependency calls.

Even a zero-count request can normalize the fields and invoke the dependency. On normal completion it also executes the final cursor read and write, although the added count may be zero.

No direct write to the inferred eight-byte storage area or output region is visible.

### Dependency-mediated effects

F-357fdad13bb5 may have effects not described in the supplied evidence. This contract does not assume that it:

- Copies bytes in a particular direction.
- Preserves the state fields or global state.
- Accepts overlapping regions.

The wrapper itself contains no explicit allocation or release operation. That observation is not an ownership guarantee for dependency calls.

### Ordering, aliasing, and failure

Normalization occurs before dependency dispatch. Cursor advancement occurs only after the dispatched calls return.

No rollback is visible. If a dependency does not return normally, normalization and any already completed dependency effects may remain observable without the final cursor advancement.

The function performs no visible null, bounds, overlap, or ownership checks. If the output region aliases the state object, dependency effects may change fields subsequently read by the final update. Whether such aliasing is supported is unknown.
