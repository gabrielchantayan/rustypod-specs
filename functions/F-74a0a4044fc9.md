# F-74a0a4044fc9

## Purpose

Updates two 32-bit state words using independent caller-supplied bit masks and a shared set-or-clear selector. The updates occur between calls to two dependencies whose contracts are unavailable.

**Status: DOCUMENTED ONLY.** The local bitwise behavior is established by static evidence, but the state storage, dependency behavior, and execution environment are not sufficiently specified for a complete interoperable implementation.

## Interface

The function accepts three scalar inputs:

| Input | Representation | Meaning |
|---|---|---|
| First mask | Unsigned 32-bit value | Selects bits to modify in the first state word. |
| Second mask | Unsigned 32-bit value | Selects bits to modify in the second state word. |
| Mode selector | Signed 32-bit integer | Zero selects setting bits; every nonzero value selects clearing bits. |

The function returns a 32-bit value of zero if execution reaches its return. There is no local error result or count of changed bits.

Neither mask is a pointer. No caller-owned buffer is read or written through the arguments, and no ownership transfer is visible.

The state words reside in storage reached through a global base reference:

- First word: byte offset `0x48` from the base.
- Second word: byte offset `0x4C` from the base.
- Each access has a width of 32 bits.

The absolute base value, storage type, alignment guarantees, access permissions, and byte order are not supplied. The offsets and widths establish locations relative to the base, not a complete serialized representation or a hardware register contract.

## Behavior

### Operation selection

The selector is tested for equality with zero, not interpreted as a two-value enumeration:

- **Zero:** set the bits selected by each mask.
- **Any nonzero value:** clear the bits selected by each mask.

Negative selector values therefore select clearing, just as positive nonzero values do.

### State transformation

For the first word, the first mask controls the update. For the second word, the second mask controls the update.

In set mode:

- Every bit whose mask bit is one becomes one.
- Every bit whose mask bit is zero retains its previously read value.

In clear mode:

- Every bit whose mask bit is one becomes zero.
- Every bit whose mask bit is zero retains its previously read value.

The mask complement used in clear mode is confined to the 32-bit word width.

The two masks do not directly influence one another. There is no combining of the two words into a wider value, and no carry or arithmetic interaction between them.

### Ordering

The visible sequence is:

1. Call F-f120802e6343 with no explicit arguments.
2. Obtain the global base reference used for the later second-word access.
3. Read and update the first state word.
4. Store the first word’s result.
5. Read and update the second state word using the captured base reference.
6. Store the second word’s result.
7. Call F-82729ee22091 with no explicit arguments.
8. Return zero.

The first word is stored before the second word is read. This ordering matters if the storage is device-backed, shared, or otherwise has read/write side effects.

The first-word accesses resolve their location through the global base reference, whereas the second-word accesses use the previously captured base value. With a stable base these refer to the expected adjacent words. The supplied evidence does not establish what happens if an external agent changes that reference during execution.

### Edge cases

- A zero mask preserves the corresponding value read from storage, but the function still performs its read and write.
- A mask containing all 32 bits sets the corresponding word to all ones in set mode and clears it to zero in clear mode.
- Selecting bits already in the requested state does not suppress the write.
- Both zero masks still result in both dependency calls and both word updates.
- The function performs no visible validation of the masks, selector, base reference, or target storage.

For ordinary writable memory, repeating the same transformation is value-idempotent. That does not establish idempotence of dependency effects or of device-backed reads and writes.

## Side effects

The function visibly:

- Calls F-f120802e6343 before its state accesses.
- Reads and writes a 32-bit value at offset `0x48`.
- Reads and writes a 32-bit value at offset `0x4C`.
- Calls F-82729ee22091 after both writes.

No allocation, deallocation, explicit ownership change, or additional local state mutation is visible.

The paired dependency calls do **not** establish locking, interrupt exclusion, transaction boundaries, or memory barriers. Those are possible interpretations, not known behavior.

The two updates are separate read-modify-write operations. The available evidence does not guarantee atomicity for either operation or for the pair. If concurrent modification is permitted without additional protection, a write can overwrite changes made after its preceding read.

There is no visible rollback path. If execution fails after the first write but before completion, the evidence provides no mechanism for restoring that word. Failure handling, faults, and nonlocal exits depend on the environment and unknown dependency contracts.

## Uncertainties

### Missing environmental contract

The evidence does not establish:

- The global base value or how it is initialized.
- Whether the words are ordinary memory, memory-mapped registers, or another storage mechanism.
- Byte order, required alignment, or supported access widths of the underlying storage.
- Whether reads or writes have hardware-specific side effects.
- Whether all 32 bits are writable or have special semantics.
- Whether the base reference or state words can change asynchronously.
- Any synchronization or ordering guarantees beyond the visible access sequence.
- Fault behavior for invalid or inaccessible storage.
- Whether either dependency returns, changes the base, or changes the state words.

If these locations are registers with write-one-to-clear, read-to-clear, reserved-bit, or similar semantics, the values actually retained by the device cannot be inferred from ordinary-memory bitwise rules alone.

### Inferred intent

The structure suggests coordinated setting or clearing of two bitfields, with the dependency pair potentially bracketing a protected operation. Neither the meaning of the bits nor a protection mechanism is established.

Those interpretations must not be promoted into requirements without additional evidence.
