# F-9ff35ee00410

## Purpose

F-9ff35ee00410 selects one of two control sequences according to whether a 32-bit mode input is zero.

- **Nonzero mode:** invoke five dependencies in a fixed order, clear one byte in a globally selected object, and return zero.
- **Zero mode:** clear a different object byte, prepare control state, and attempt three ordered acknowledgment stages. Return zero only if every stage passes its final status check; otherwise return the 32-bit pattern `0xFFFFFFFF`.

The sequence suggests staged request/acknowledgment coordination. That is **inferred intent**, not an established subsystem identity. Neither branch is established to mean start, stop, enable, disable, or reset.

A central distinction is between **retained control addresses**, used for polling, and **control-global references appearing separately in masked assignments**. The supplied representation does not establish that those separate references select the same address.

## Interface

### Inputs and result

| Item | Width | Established behavior |
|---|---:|---|
| Context token | 32 bits | Forwarded unchanged to designated dependencies; not directly interpreted or dereferenced by this function |
| Mode | 32 bits | Compared with zero; every nonzero bit pattern selects the same branch |
| Result | 32 bits | Either `0x00000000` or `0xFFFFFFFF` on a normal return |

Zero means either that the nonzero-mode sequence reached its return or that all three zero-mode final acknowledgment checks passed. It does not independently establish success according to unknown dependency contracts.

`0xFFFFFFFF` identifies a failed zero-mode final status check. There is no distinct result for each failing stage. Interpreting this pattern as signed −1 is caller-dependent.

The function does not inspect dependency return values. A dependency that does not return normally can prevent any subsequent operation or normal result.

### Referenced state

The following labels describe roles, not source identifiers.

| State reference | Accesses required when reached |
|---|---|
| Nonzero-mode object global | Selects an object with a writable byte at byte offset 5 |
| Zero-mode object global | Selects an object with a writable byte at byte offset 5 |
| First control global | Supplies the retained first-stage address; also appears separately in the source-value and destination expressions of an offset-60 masked assignment |
| Second control global | Supplies retained second-stage addresses during first-stage iterations; also appears separately in the source-value and destination expressions of second-stage preparation |
| Third control global | Supplies retained third-stage addresses during second-stage iterations; also appears separately in the source-value and destination expressions of third-stage preparation |

Control accesses are 32-bit word accesses. Offset 60 corresponds to word index 15. Offset 0 is the first word.

The retained first-stage address requires readable/writable storage at offset 0. An address selected for the offset-60 source requires readable storage there; an address selected for its destination requires writable storage there. These need not be the retained first-stage address, or each other, unless reference stability is assumed.

The same distinction applies to second- and third-stage preparation: the source word, destination word, and retained polling word can belong to different selected addresses. Later polling requires the retained addresses to remain readable.

No null, alignment, bounds, lifetime, or permission checks are visible. Accessible storage, or a supported register interface, is a precondition for each reached access. Pointer width, byte order, allocation size, alignment guarantees, address-space properties, and aliasing relationships are not established.

## Behavior

### Nonzero mode

For any nonzero mode, the function performs the following sequence:

1. Invoke F-000000000001 with numeric arguments 1 and 64.
2. Invoke F-000000000002 without explicit arguments.
3. Invoke F-443218df8c75 with the context token.
4. Invoke F-c0e2b31c8333 with the context token.
5. Invoke F-92725e201739 with the context token.
6. Resolve the nonzero-mode object global and write zero to the selected object’s byte at offset 5.
7. Return `0x00000000`.

The object selection occurs after all five dependency calls. Their preservation of the object global or the object itself is not assumed.

This branch contains no direct control-word polling and makes no calls to F-000000000003.

### Zero-mode preparation

For mode zero, the function first:

1. Resolves the zero-mode object global and writes zero to the selected object’s byte at offset 5.
2. Invokes F-cfa8842f7f6c without explicit arguments.
3. Captures the first control global’s address for the offset-0 update and first-stage polling.
4. Performs the offset-60 masked assignment described below.
5. Reads the 32-bit word at offset 0 of the retained first-stage address, clears bit 0 using mask `0xFFFFFFFE`, and writes the result back to that same retained address.

The offset-60 assignment uses the first control global separately for its source-value expression and its write-destination expression. It reads a 32-bit word at offset 60, clears bits 0 through 3 using mask `0xFFFFFFF0`, and stores the resulting 32-bit value at offset 60 of the destination selected by the other reference expression.

It does **not** explicitly use the retained first-stage address for that assignment. Equality among the retained address, the source address, and the destination address requires a stability assumption.

The supplied representation does not establish the evaluation order of the assignment’s two pointer expressions. The value read supplies the masked value written, but this data dependency does not establish which pointer expression is evaluated first. Nor does it establish an exact count of physical global-pointer loads.

The offset-60 assignment precedes the offset-0 update through the retained address.

### Common acknowledgment rules

Each reached stage makes between one and ten calls to F-000000000003. Every call receives the numeric argument 10.

The dependency call occurs before that iteration’s acknowledgment check. Therefore, a bit already set before entry into a stage does not eliminate the first call.

Each iteration checks bit 1 of its retained polling word, using mask `0x00000002`:

- A set bit ends iteration immediately.
- A clear bit increments the unsuccessful-check count.
- Ten unsuccessful iteration checks end iteration without an eleventh call.

After iteration ends, the function performs a **separate status read and bit-1 test**. This final test alone decides whether the stage passes.

An acknowledgment observed during iteration is not remembered independently of memory:

- A bit that ends iteration can clear before the final read, causing failure.
- A bit can be clear at all ten iteration checks and set at the final read, allowing progress.
- Failure at the final read does not restart the stage, even if fewer than ten calls were made.

The argument 10 establishes neither a duration nor a unit. The visible bound is a call count, not a wall-clock timeout.

### First acknowledgment stage

Every first-stage iteration performs these operations in order:

1. Invoke F-000000000003 with argument 10.
2. Capture the current second control global’s address, replacing any second-stage address captured by an earlier iteration.
3. Read and test bit 1 at offset 0 of the retained first-stage address.

The second control address is captured even when that iteration’s first-stage check is unsuccessful.

After iteration ends, the function reads and tests bit 1 of the retained first-stage word again:

- Clear: return `0xFFFFFFFF`.
- Set: proceed to second-stage preparation.

No second-stage preparation occurs on the failure path. The second-stage polling address, if used, is the address captured during the last first-stage iteration.

### Second-stage preparation and acknowledgment

Preparation performs a masked assignment whose source-value expression and destination expression each reference the second control global separately.

The source is a 32-bit word at offset 0. Its value is masked with `0xFFFFFFFE`, clearing bit 0, and the result is written to offset 0 of the separately selected destination.

There is no explicit capture of one fresh address for both accesses. Neither selected address is guaranteed to equal the address retained during the first stage. The relative evaluation order of the two pointer expressions is not established.

Second-stage polling nevertheless uses the **retained address from the last first-stage iteration**, not a newly selected preparation address.

Every second-stage iteration:

1. Invokes F-000000000003 with argument 10.
2. Captures the current third control global’s address, replacing any third-stage address captured earlier.
3. Reads and tests bit 1 of the retained second-stage word.

After iteration ends, a separate read tests bit 1 of that retained word:

- Clear: return `0xFFFFFFFF`.
- Set: proceed to third-stage preparation.

The third-stage polling address is the address captured during the last second-stage iteration.

### Third-stage preparation and acknowledgment

Preparation references the third control global separately in the source-value and destination expressions of another masked assignment.

It reads a 32-bit word at offset 0, masks that value with `0xFFFFFFFE`, and writes the result to offset 0 of the separately selected destination. A single fresh address shared by both accesses is not established. Neither address must equal the retained third-stage polling address, and the pointer-expression evaluation order is unspecified by the supplied representation.

Each third-stage iteration:

1. Invokes F-000000000003 with argument 10.
2. Reads and tests bit 1 of the retained third-stage word.

There is no further control-address capture within this stage.

After iteration ends, a separate read tests bit 1 of the same retained word:

- Clear: return `0xFFFFFFFF`.
- Set: execute the completion sequence.

### Zero-mode completion

After all three final checks pass:

1. Invoke F-691c38e4e705 with the context token.
2. Invoke F-000000000001 with numeric arguments 0 and 64.
3. Invoke F-000000000002 without explicit arguments.
4. Return `0x00000000`.

These completion calls are absent from every visible zero-mode failure path.

## Side effects

### Direct writes

| Condition | Direct write |
|---|---|
| Nonzero mode | Zero to byte offset 5 of the object selected after the dependency sequence |
| Zero mode | Zero to byte offset 5 of the initially selected zero-mode object |
| After zero-mode preparation dependency returns | At offset 60 of a destination selected through the first control global, write the source word selected through a separate reference to that global, masked with `0xFFFFFFF0` |
| After the offset-60 assignment | At offset 0 of the retained first-stage address, write its read value masked with `0xFFFFFFFE` |
| First stage passes | At offset 0 of a destination selected through the second control global, write the source word selected through a separate reference to that global, masked with `0xFFFFFFFE` |
| Second stage passes | At offset 0 of a destination selected through the third control global, write the source word selected through a separate reference to that global, masked with `0xFFFFFFFE` |

For each masked assignment, bits outside the mask’s cleared positions come from the **source value read**. Preservation of the destination’s other bits requires that source and destination designate the same word, together with suitable memory semantics and absence of interfering writes.

In particular, the offset-60 mask clears source bit 1 as well as bits 0, 2, and 3. The offset-0 masks do not clear source bit 1, but a different source word can supply a bit-1 value different from the destination’s prior value. Aliasing can also connect these writes to other described locations.

There is no visible rollback. Failure leaves prior direct writes and dependency effects in place.

## Acceptance examples

These are conditional consequences of static behavior, not executed tests. Unless stated otherwise, dependencies return normally, accesses are valid, globals remain stable, and memory has ordinary non-interfering read/write semantics.

1. **Nonzero mode selects one sequence.**  
   Modes 1 and `0xFFFFFFFF` both invoke the five dependencies in the specified order, then clear the selected object byte and return zero. Neither invokes the polling dependency.

2. **Immediate acknowledgments still require calls.**  
   If every stage observes bit 1 set at its first iteration check and final check, exactly three polling calls occur, one per stage. Completion runs and the result is zero.

3. **First-stage failure stops progression.**  
   If bit 1 is clear at all ten first-stage iteration checks and its final check, the result is `0xFFFFFFFF`. Initial zero-mode writes have occurred. Neither second-stage preparation nor completion occurs.

4. **Second-stage failure retains prior effects.**  
   If the first stage passes but the second stage’s final check fails, second-stage preparation has occurred. Third-stage preparation and completion have not.

5. **Acknowledgment disappearance causes failure.**  
   If an iteration sees bit 1 set and the immediately following final status read sees it clear, that stage fails without another polling call.

6. **Late acknowledgment can pass.**  
   If ten iteration checks see bit 1 clear but the separate final read sees it set, the stage passes without an eleventh call.

7. **First preparation need not target the retained block.**  
   Suppose the first control address is retained, then its global changes before the offset-60 assignment and remains stable throughout that assignment. The offset-60 update affects the newly selected block. The subsequent offset-0 update and first-stage polling still use the original retained block.

8. **A separate-reference assignment can copy between blocks.**  
   Conditional on the second-stage preparation’s source expression selecting one block and its destination expression selecting another, a source value of `0x00000003` produces a destination write of `0x00000002`. The destination’s previous unrelated bits need not survive. This case prescribes no evaluation order for those expressions. The same distinction applies to offset-60 preparation and third-stage preparation.

9. **Preparation and polling can diverge even with a stable assignment.**  
   If the second control global changes after its last first-stage capture and then stays stable during preparation, preparation reads and writes the new block, while second-stage polling reads the previously retained block. The corresponding case applies to the third control global.

10. **Mask preservation is conditional.**  
    With stable references and ordinary non-interfering memory, an offset-60 value of `0x1234567F` becomes `0x12345670`; an offset-0 value of `0x00000003` becomes `0x00000002`. These examples do not establish destination-bit preservation when the source and destination differ.

11. **Polling is call-bounded.**  
    Zero mode makes at most 30 polling calls, ten per reached stage. Any successful zero-mode path makes at least three. No elapsed-time bound follows.
