# F-5fd7b5f528b4

## Purpose

F-5fd7b5f528b4 resolves an absolute or relative destination, adjusts an auxiliary cursor, and records the resulting position in a mutable object. It returns either the effective destination or a distinguished failure value, with a status notification before every normal return.

Established behavior includes:

- An initially zero extent bypasses request validation and returns zero.
- Three origin selectors support absolute, current-relative, and initial-extent-relative requests.
- A negative resolved upper word causes failure.
- Destinations at or beyond a freshly observed extent are clamped.
- Cursor handling distinguishes repositioning from reuse of an existing cursor.
- Successful processing writes a saved cursor, a refreshed context-derived value, a position, and an endpoint-related flag.

A seek-like operation over block-organized data is inferred intent, not an established dependency contract. The arithmetic, field accesses, calls, and writes below define the observable behavior without requiring that interpretation.

## Behavior

### Entry and empty-extent handling

The function captures the context address through the position object’s associated record, then reads the extent through that record’s metadata address.

If this initial extent is zero, it selects the zero result, notifies F-038b46411c0c with zero, and returns.

This shortcut occurs before origin validation, upper-word validation, the global-base read, cursor processing, and success-state writes. Consequently, unsupported origins and negative requested upper words do not cause explicit failure on this path.

The function itself makes no position-object writes on this shortcut. That does not constrain the notifier’s effects.

### Origin resolution

For a nonzero initial extent:

- **Origin 0:** retain the requested lower and upper words.
- **Origin 1:** read the recorded position as an unsigned 32-bit base and add it to the requested lower word.
- **Origin 2:** use the initially observed extent as that base.
- **Any other origin:** fail explicitly.

In either relative mode, the lower result is the unsigned 32-bit sum. The upper-word adjustment uses the unsigned carry from that addition.

Specifically, the signed upper operand is converted to unsigned for addition to the unsigned carry. The addition therefore wraps modulo \(2^{32}\), without a signed-addition overflow boundary. The resulting unsigned value is assigned back to signed 32-bit storage. If it is not representable there, the target’s conversion interpretation remains relevant.

The resulting signed upper word is then tested. A negative value causes explicit failure before cursor calls or direct success-state writes.

### Fresh extent comparison and clamping

After the sign check, the function traverses the position object’s current associated-record and metadata fields to read the extent again.

It forms a zero-or-one value indicating whether the candidate lower destination is below that fresh extent. Clamping occurs when this value is less than or equal to the nonnegative signed upper word.

With stable extent storage:

- Upper word zero and lower destination below the extent: no clamp.
- Upper word zero and lower destination equal to or above the extent: clamp.
- Positive upper word: clamp regardless of the lower destination.

Clamping sets the upper word to zero and replaces the lower destination with another extent read through the object’s pointer chain. The comparison and replacement are distinct accesses; they need not observe the same extent.

On every path that proceeds beyond clamping, the effective upper word is zero: an unclamped request necessarily had upper word zero, and a clamped request explicitly receives zero.

The clamp decision is retained independently of the effective numeric destination. Later behavior depends on whether clamping occurred, not merely on whether the destination equals an extent.

### Global-based unit-field read

After clamp processing and before cursor-path selection, the function reads the global-supplied address/base value, combines it with the captured context address, and reads an unsigned 16-bit field from the resulting address.

Adding nine produces a quantity in the established range **9 through 65544**. This addition does not overflow its represented intermediate range.

The full quantity is passed to F-703fd5651586 on the repositioning path. On the existing-cursor path, only its low eight bits select the right-shift count. Thus the supplied shift count can range from 0 through 255 despite the full quantity’s minimum of nine.

No validation limits that count to 0 through 31. The representation alone does not establish execution semantics for larger counts.

### Cursor-path selection

The function compares the effective signed upper word with a zero-or-one value indicating whether the effective lower destination is below the recorded position, interpreted as unsigned.

Because the effective upper word is zero, this selects the repositioning path exactly when the effective destination is below the position read for this comparison.

The existing-cursor path performs another recorded-position read for its later unit-index calculation. The function does not require those reads to agree.

### Repositioning path

F-40e4fc419124 receives six arguments, in this order:

1. Captured context address.
2. Metadata address freshly read through the position object’s associated record.
3. Original requested lower word.
4. Zero.
5. Auxiliary input.
6. Original requested lower word again.

The two lower-word arguments are the original input, not the resolved relative destination or the clamped destination.

Its 32-bit result becomes the working cursor. No value from this dependency is explicitly classified as an error by this caller.

Next, F-703fd5651586 receives the effective lower destination, effective upper word, and full halfword-plus-nine quantity. Its result is used as the **signed 32-bit advancement accumulator**. Its internal calculation and units are unknown.

### Existing-cursor path

The saved cursor at object offset 12 becomes the working cursor.

The destination-side index uses:

- The effective lower destination if unclamped.
- The effective lower destination minus one, modulo \(2^{32}\), if clamped.

This value is shifted right as unsigned 32-bit data using the low-eight-bit shift count. A newly read recorded position is independently shifted using the same count.

If the recorded-position index exceeds the destination-side index, no advancement occurs. Otherwise, their difference is calculated as an **unsigned 32-bit subtraction** and assigned to the **signed 32-bit advancement accumulator**. A zero difference skips advancement.

For an unsigned difference above `0x7FFFFFFF`, its interpretation after assignment to signed storage is target-dependent. It must not be assumed to remain a nonnegative signed count.

The clamped subtraction by one is observable. For example, it can select the unit containing the byte immediately before the extent. If a replacement extent read yields zero, that subtraction instead produces `0xFFFFFFFF`.

### Advancement

While the signed advancement accumulator is nonzero, F-5a8a1a11a291 receives:

1. Position-object address.
2. Captured context address.
3. Current working cursor.
4. Address of the working-cursor storage.
5. Current signed advancement accumulator.

Its returned progress is signed 32-bit.

A zero return causes immediate explicit failure. Otherwise, the function subtracts that signed progress from the signed accumulator and repeats until the accumulator is zero.

There is no explicit rejection of:

- A negative accumulator.
- Negative progress.
- Progress larger than the remainder.
- A subtraction outside the signed 32-bit range.
- A dependency sequence that never reaches zero.

The subtraction is signed arithmetic; wrapping is not established. Termination and defined execution therefore require suitable dependency behavior and arithmetic conditions. Working-cursor changes through the supplied address are used by subsequent calls.

### Success writes and endpoint flag

After cursor processing completes, the function performs these operations in order:

1. Write the working cursor at object offset 12.
2. Call F-08426f0ea83d with the captured context address.
3. Store its 32-bit result at object offset 16.
4. Store the effective lower destination at object offset 8.
5. Calculate and write the flag at object offset 28.
6. Notify F-038b46411c0c with zero.
7. Return the effective destination with upper result word zero.

If the retained clamp decision is false, the flag is written as zero without evaluating the extent-and-mask expression.

If clamped, the function reads a fresh extent through the object’s then-current pointer chain and reads the context mask twice. The flag is one exactly when the resulting unsigned expression is no greater than the effective destination.

For stable mask storage, the expression is:

\[
((\text{fresh extent}+\text{mask})\mathbin{\&}\mathord{\sim}\text{mask}).
\]

Addition, complement, and conjunction are 32-bit; addition wraps modulo \(2^{32}\). More precisely, one mask read supplies the addition operand and a separate read supplies the complemented operand. Their agreement is not guaranteed, and the ordering of independent operand reads is not established.

F-08426f0ea83d may alter reachable storage before this expression. The captured context is retained, but the metadata chain is traversed afresh. No callee is assumed to preserve previously written fields.

### Explicit failure

Unsupported origins on nonempty data, negative resolved upper words, and zero advancement returns converge on the same outcome: notification 22 followed by the all-ones 64-bit result.

The success-stage writes are skipped. There is no rollback of dependency effects, including any working-cursor changes or reachable-state mutations already performed.

## Side effects

The function’s direct object writes are the four success writes at offsets 12, 16, 8, and 28, in that order, with the context-refresh call between the first two.

Reads include repeated pointer-chain traversals, a global-supplied base read, the context-relative halfword, and conditional mask reads. No coherent metadata snapshot or synchronization operation is established.

No explicit allocation, release, or ownership transfer appears in this function. This does not establish that dependencies refrain from allocating, releasing, retaining pointers, or mutating globals.

The working-cursor address supplied to F-5a8a1a11a291 refers to storage available during the call. Retention behavior is unknown; no longer lifetime is promised by this function.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests. Except where stated otherwise, storage is stable, accessed addresses are valid, shifts are defined, and dependencies return normally.

1. **Empty extent overrides invalid request details.**  
   Initial extent zero, an unsupported origin, and a negative requested upper word produce result zero and notification zero. There is no global-base read, cursor call, context-refresh call, or direct object write.

2. **Unsupported nonempty origin fails.**  
   Initial extent nonzero and origin 3 produce the all-ones result and notification 22, without success-stage writes.

3. **Carry can remove a negative input upper word.**  
   Recorded position `0xFFFFFFF0` plus requested lower word `0x20` produces lower word `0x10` and carry one. Requested upper word −1 converts to `0xFFFFFFFF`; unsigned addition of one produces zero. The assigned signed upper word is zero, so the sign check does not reject it.

4. **Positive upper word clamps.**  
   Extent 1000, resolved upper word one, and lower word five produce effective destination 1000 with upper word zero.

5. **Exact extent changes the index calculation.**  
   Extent 1024, absolute destination 1024, recorded position zero, and halfword zero produce a shift quantity of nine. Clamping makes the destination-side index derive from 1023, yielding one rather than two. An advancement call is therefore required with signed remainder one.

6. **Clamping does not guarantee flag one.**  
   Stable extent 1000 and mask 511 yield expression 1024, greater than destination 1000, so the flag is zero. Extent 1024 with the same mask yields expression 1024 and flag one.

7. **Repositioning receives the original lower word.**  
   A current-relative request with recorded position 1000, lower word `0xFFFFFF9C`, and upper word −1 resolves to 900. On a nonclamping path, repositioning occurs, but F-40e4fc419124 receives `0xFFFFFF9C` in both designated lower-word argument positions.

8. **The full quantity and shift count differ.**  
   A halfword of 65535 produces full quantity 65544 and low-eight-bit shift count eight. Repositioning forwards 65544 to F-703fd5651586; existing-cursor calculations use eight.

9. **Out-of-range signed conversion stays conditional.**  
   A valid shift count of zero can permit an unsigned index difference of `0x80000000`. Its assignment to the signed accumulator is target-dependent. The contract does not assert a portable positive remainder or modular loop subtraction.

10. **Zero progress fails without rollback.**  
    If an advancement call changes reachable state or the working cursor and then returns zero, notification is 22 and the result is all ones. Those dependency effects are not undone.

- The global-supplied base value, its ownership, stability, and semantic role.
- Address-arithmetic behavior outside valid address ranges.
- Target-specific unsigned-to-signed conversion for values above `0x7FFFFFFF`.
- Signed-subtraction overflow behavior in the advancement loop.
- Shift semantics for selected counts of 32 through 255.
- Dependency units, valid progress ranges, termination guarantees, memory ownership, and state preservation.
- Full layouts and semantic names of accessed records and fields.
- Behavior under concurrent or dependency-induced mutation.
- Ordering among independent reads inside the final expression.
- Whether notification value 22 corresponds to a public error category.

There is no signed-overflow uncertainty in the relative upper-word addition itself: that addition is unsigned. Uncertainty concerns the subsequent signed assignment where its result is not representable.
