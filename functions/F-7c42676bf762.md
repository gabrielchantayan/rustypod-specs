# F-7c42676bf762

## Purpose

F-7c42676bf762 performs an ordered search over contiguous, fixed-stride records. It returns the address of the first record accepted by its filters, or null when its traversal count reaches zero.

Acceptance has two stages:

- Basic qualification using two signed selectors, two exclusion masks, and an inclusion mask.
- Conditional contextual qualification using metadata, descriptor selection, a context-list search, and three dependencies.

A basically qualified record can bypass contextual processing. Returning a record therefore does not establish that any dependency ran.

“Record,” “context,” “root,” and “descriptor” identify structural roles only. Their application-domain meanings are unknown.

### Collection layout

| Byte offset | Access width | Interpretation |
|---:|---:|---|
| 0 | 32 bits | Contextual root address |
| 8 | Signed 32 bits | Initial traversal count |
| 16 | 32 bits | Initial record address |

The count is read before the initial record address. Both reads occur even when the count is zero. These two values are retained for traversal rather than reloaded from the collection on each iteration.

The root address is read only when a record reaches contextual processing. It is captured separately for each such candidate.

### Record layout and selector conversion

Records have a 40-byte stride.

| Byte offset | Access width | Interpretation |
|---:|---:|---|
| 0 | 32 bits | Object address or handle used by contextual processing |
| 6 | Signed 16 bits | Primary identifier |
| 8 | Signed 32 bits | Word converted to signed 16 bits for the secondary comparison |
| 10 | Unsigned 16 bits | Inclusion flags and exact-value bypass field |
| 24 | 32 bits | First exclusion flags |
| 28 | 32 bits | Second exclusion flags |

The secondary comparison is **not a 16-bit memory read at offset 8**. It reads the entire 32-bit word beginning at offset 8, converts that value to signed 16 bits, and compares the resulting value, promoted to signed 32 bits, with the secondary selector.

Consequently, a secondary-selector comparison requires the entire four-byte region at offsets 8–11 to be readable. It overlaps the separately accessed flags region at offsets 10–11.

Under a little-endian layout and conventional low-16-bit narrowing, the converted secondary identifier corresponds to the physical halfword at offset 8, while the flags occupy the other halfword. That interpretation is conditional: byte order is not independently established by the supplied representation. On a different byte order, the relationship between the loaded word’s numerical bits and those physical halfwords changes.

Both selector comparisons use signed 16-bit results promoted to signed 32 bits. A selector outside −32768 through 32767 cannot equal such a result. The portability limits of the secondary narrowing are recorded under Uncertainties.

### Output and ownership

The result is either:

- The address of an accepted record in the traversed sequence; or
- Null when the retained traversal count reaches zero.

The result is not a copy, an object handle, or a descriptor address. No allocation, retention, ownership transfer, or lifetime extension is visible. The caller must ensure that returned record storage remains usable.

## Behavior

### Traversal

Before reading any fields of the current record, the function tests whether the retained remaining count equals zero. If it does, the function returns null.

After rejecting a record, the function decreases that count by one and advances the record address by 40 bytes. Earlier records are not revisited.

The termination condition is equality with zero, not a nonpositive test. A negative initial count is therefore not an empty collection. It can cause traversal beyond valid storage and eventually encounter arithmetic or address failures; no safe outcome is established for that input.

The first accepted record is returned immediately. Later records are not examined.

### Basic qualification and read order

For each visited record:

1. The signed 16-bit primary identifier at offset 6 is read and compared with the primary selector.
2. Only if it matches, the 32-bit exclusion word at offset 28 is read and tested against the second exclusion mask.
3. The 32-bit exclusion word at offset 24 is then read and tested against the first exclusion mask, even if the preceding exclusion test failed.
4. Only if both mask intersections are zero, the 32-bit word at offset 8 is read, converted to signed 16 bits, and compared with the secondary selector.
5. Only if that comparison succeeds, the unsigned 16-bit flags at offset 10 are read and intersected with the inclusion mask.

Basic qualification requires both identifier comparisons to succeed, both exclusion intersections to be zero, and the inclusion intersection to be nonzero.

A zero inclusion mask prevents all records from qualifying. A zero exclusion mask imposes no exclusion, but does not remove the corresponding visible record-word access.

A primary mismatch prevents all remaining basic-filter accesses for that record. An exclusion failure prevents the secondary-word and inclusion-flag accesses. A secondary mismatch prevents the separate inclusion-flag access, although the preceding 32-bit secondary-word load already covered the flags’ bytes.

### Immediate acceptance

After basic qualification, the current record is returned without dependencies when any of these ordered conditions applies:

- The primary selector is negative.
- Otherwise, the context value is zero.
- Otherwise, a fresh unsigned 16-bit read at record offset 10 equals exactly 0x0080.

The first condition avoids contextual memory access and the exact-value flags reread. The zero-context condition also avoids that reread.

The exact-value condition is not a bit-presence test. A reread value of 0x0081 does not satisfy it.

These bypasses do not replace basic qualification. In stable storage, flags equal to 0x0080 still require an inclusion mask containing bit 0x0080. The inclusion check and exact-value check are separate reads; the supplied body does not establish that concurrently mutable storage must yield the same value for both.

### Contextual capture and metadata

For a basically qualified record that takes no bypass, the function reads, in order:

- The root address at collection offset 0.
- The object address or handle at record offset 0.
- An unsigned metadata byte obtained through the context.

The metadata access follows an address at context offset 16, then an address at offset 8 in that referenced object. From the resulting table base, the selected byte is at displacement:

**20 × secondary selector + 18 bytes.**

The selector is signed. A matching negative selector is not clamped or converted into a validated nonnegative table index. No table bounds check is visible.

The metadata byte is captured before F-725887638d3e is called with the captured object value. It is not visibly reread afterward.

### Category gate

The result of F-725887638d3e selects the following gate:

| Result | Metadata requirement |
|---|---|
| 0x61 | Exactly 0x61 |
| 0x62 | No value restriction |
| Any other value | At least 0x63 |

The metadata is an unsigned byte, so the final condition covers values 0x63–0xFF.

Failure rejects the record and resumes traversal without calling either remaining dependency.

Result 0x62 does not eliminate the metadata access: that access already occurred before the call. Its address must be valid even when the returned category imposes no metadata-value restriction.

### Descriptor selection

After the category gate passes, the function reads 32-bit fields at offsets 8 and 12 from the captured object address and supplies them, together with the captured root address, to F-2dc561e1332f.

Both object-field reads occur after F-725887638d3e returns. Their relative evaluation order is not established. Effects of the earlier dependency may therefore change either observed field.

A nonnull result from F-2dc561e1332f becomes the descriptor address.

A null result selects a fallback instead:

- Read the first 32-bit word at the captured root as an address.
- Read the 32-bit address at offset 44 in that referenced object.
- Use that address as the descriptor.

The null lookup result is not itself rejection or exhaustion. No visible null check protects the fallback dereferences or the selected descriptor.

### Context-list search

After descriptor selection, the function searches for the secondary selector using a signed 32-bit index initially equal to zero.

Every loop-condition evaluation has this access order:

1. Read the signed 32-bit count at context offset 4.
2. Compare the current index with that freshly read count.
3. Only if the index is less than the count, read the list address at context offset 8 and then the signed 32-bit list entry at displacement four times the index.
4. Stop if that entry equals the secondary selector. Otherwise increment the index and evaluate the condition again.

The count and list address are repeated condition accesses, not established snapshots. An initially zero or negative count causes neither a list-address read nor a list-entry read.

For a stable positive count, the first equal entry determines the resulting index. If no entry matches, the resulting index equals that count. For a stable zero or negative count, the resulting index is zero.

If the count or list address changes between condition evaluations, the search follows the values read at each evaluation. A no-match result must not generally be described as equal to one fixed count.

### Companion selection and final decision

Whatever stopped the list search, the resulting index selects a 32-bit companion value from a separate array whose address is read at context offset 44. This access occurs even when no list entry was examined or matched.

The function then calls F-e6db2171781a with:

- The first 32-bit word at the selected descriptor.
- The selected 32-bit companion value.

The relative evaluation order of these argument-memory reads is not established.

A zero result accepts the current record. Any nonzero result rejects it and resumes traversal.

For a stable positive list count with no match, the companion array must support an access at index equal to that count—one beyond the last searched list index. For a zero or negative count, companion index zero is used instead.

## Acceptance examples

These are conditional static criteria, not runtime observations. Unless stated otherwise, required storage is valid, adequately sized, and stable throughout the example.

1. **Empty collection.** With count zero, read the collection count and initial record address, then return null without reading record fields or calling dependencies.

2. **Ordered search.** If the first record fails an exclusion test and the second passes basic qualification with context zero, return the second record’s address. Do not inspect a third record.

3. **Both exclusion reads.** After a matching primary identifier, a nonzero intersection at offset 28 rejects the record, but the exclusion word at offset 24 is still read. The secondary word is not read.

4. **Signed primary matching.** A primary field representing −1 matches selector −1, not 65535. If the other basic conditions pass, the negative selector accepts immediately without contextual access.

5. **Secondary access width.** A candidate reaching the secondary comparison performs a four-byte read beginning at offset 8, followed by signed-16-bit conversion. A readable two-byte region at offset 8 alone does not satisfy the access requirement.

6. **Zero inclusion.** With inclusion mask zero, no record qualifies, regardless of context or dependency behavior.

7. **Exact bypass.** With a nonnegative matching primary selector, nonzero context, stable flags 0x0080, and inclusion mask 0x0080, a basically qualified record is accepted without dependencies. Stable flags 0x0081 do not obtain this bypass.

8. **Category gate.** Result 0x61 with metadata 0x61 permits descriptor selection; the same result with metadata 0x62 rejects. Result 0x62 permits any captured metadata byte, but does not excuse an invalid preceding metadata access.

9. **Other categories.** For a category result other than 0x61 or 0x62, metadata 0x62 rejects and metadata 0x63 permits further processing.

10. **Descriptor fallback.** A null result from F-2dc561e1332f selects the root-derived descriptor. If the remaining accesses succeed and F-e6db2171781a returns zero, accept the current record.

11. **Nonpositive list count.** With a stable count of zero or −2, do not read the list address or any list entry. Read companion index zero and let the final dependency determine acceptance.

12. **Missing list key.** With stable count three and no equal list entry, examine indices zero through two, then reread the count with index three. Do not read another list entry. Select companion index three.

13. **Repeated count observation.** If the first condition observes count two, entry zero is unequal, and the next condition observes count zero, stop at index one without a second list-address read. Select companion index one.

14. **Final rejection.** A nonzero final dependency result continues traversal at the next 40-byte record. A later candidate may still be accepted.

## Uncertainties

### Established limits

Safe operation requires accessible storage for every reached read, valid lifetimes, and arithmetic that remains valid in the represented execution model. Contextual paths require valid metadata addressing, object fields, descriptor storage, list entries actually examined, and the selected companion entry.

The function supplies no visible bounds, provenance, alignment, or lifetime validation.

### Arithmetic and representation: documented_only

Visible arithmetic includes a 40-byte record stride, metadata displacement of 20 times a signed selector plus 18, four-byte list and companion displacements, count decrement, and index increment.

No overflow checks are present. Portable behavior at signed overflow, address wraparound, or out-of-object addressing is not established.

Byte order is unknown. The secondary comparison must remain specified as a 32-bit read followed by signed-16-bit conversion, not unconditionally as a physical halfword read. Conventional low-bit narrowing explains the usual target interpretation; conversion of an out-of-range signed 32-bit value to signed 16 bits is not a universally portable arithmetic rule established by this representation alone.

Negative record counts are not empty collections. Negative list counts do skip list reads, but still select companion index zero.

### Inferred intent

The function appears to select a context-compatible record through category screening and descriptor-dependent comparison. Those meanings are inferred, not required behavior.

The companion entry beyond a fully searched positive-length list may serve as fallback storage. Its existence and domain meaning remain unknown; the access itself is established.
