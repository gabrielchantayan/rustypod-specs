# F-4fb4db0607d2

## Purpose

F-4fb4db0607d2 computes sixteen coefficient results from two memory-resident arrays, stores them incrementally in a destination, and then stores a Boolean derived from the inputs’ metadata bytes.

The indexing and scaling are consistent with multiplication of two four-by-four matrices stored in column-major order, with signed coefficients having sixteen fractional bits. That interpretation is inferred intent. The established static evidence is the operand addressing, signed multiplication and accumulation, rounding adjustment, result reconstruction, and ordered memory accesses described below.

The result reconstruction contains signed 32-bit arithmetic. Consequently, representable signed 64-bit accumulation is not, by itself, sufficient to establish a particular output word. Some numerical results require reconstruction semantics that remain unresolved.

### Rounding adjustment and reconstruction

The accumulated signed 64-bit value is adjusted by adding **32,768**, or **0x8000**. The adjustment can itself exceed the signed 64-bit range.

The reconstruction combines two components derived from that adjusted quantity:

- A low component obtained by retaining the low unsigned 32-bit word and shifting it right by sixteen bits.
- A high component obtained by selecting the upper 32-bit word, converting it to signed 32-bit form, and multiplying that signed value by **65,536**.

The components are combined by bitwise inclusive OR and stored as an unsigned 32-bit word.

This establishes a reconstruction operation, not an unconditional guarantee that every input produces a well-defined extraction of bits 16–47. Two distinct arithmetic questions matter:

1. How an upper unsigned word outside the positive signed 32-bit range converts to signed 32-bit form.
2. What happens if the resulting signed multiplication by 65,536 is outside the signed 32-bit range.

If the converted signed upper word is \(H\), that multiplication is representable precisely when:

\[
-32{,}768 \le H \le 32{,}767.
\]

A positive upper word of **32,768** already falls outside this range, even though it is itself a representable signed 32-bit value.

Where accumulation, adjustment, conversion, and reconstruction have the required defined behavior, the reconstructed word corresponds to bits **16 through 47** of the adjusted quantity. Under a wrapping or equivalent bit-pattern reconstruction model, that characterization also describes the intended output when the signed reconstruction multiplication exceeds its range. Such a model is not established universally by the supplied representation.

Within the supported arithmetic domain, the numerical characterization is the low 32 bits of:

\[
\left\lfloor\frac{S+32{,}768}{65{,}536}\right\rfloor.
\]

The floor matters for negative quantities; this is not division truncated toward zero.

Under the inferred fixed-point interpretation, the adjustment rounds to the nearest retained unit, with exact halfway cases directed toward positive infinity. No saturation or explicit overflow report is visible. Absence of saturation does not, however, establish wrapping behavior for otherwise unresolved signed operations.

### Metadata processing

Metadata processing occurs only after all sixteen coefficient stores.

The function first reads the left metadata byte at offset 64. If that byte is zero, it does not read the right metadata byte. Otherwise, it reads the right metadata byte at offset 64.

It then stores a Boolean at destination offset 64:

- false if the left metadata byte was zero;
- false if the left byte was nonzero and the right byte was zero;
- true if both tested bytes were nonzero.

This is a short-circuit access rule, not merely a truth table. A zero left metadata byte suppresses the right metadata read but suppresses no coefficient work.

Noncanonical nonzero input bytes, such as 2 or 255, count as true. Their original byte values are not propagated.
