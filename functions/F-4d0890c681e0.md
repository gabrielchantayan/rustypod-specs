# F-4d0890c681e0

## Purpose

F-4d0890c681e0 performs a two-stage operation through F-e416cbaf2fc4, then selects between normal return, an indirect callback, and a call to F-a817d8d58c10.

The first stage submits one of two fixed data references. Its choice depends only on whether the second input is zero. A zero result stops processing.

The second stage derives a data reference and a count from state reachable through the first input. Its result controls the final action:

- A zero low-order result word causes normal return.
- A nonzero low-order result word normally causes an indirect callback.
- When that word shares at least one set bit with the second input, a nonzero state field instead selects F-a817d8d58c10.

This is the established control structure. The semantic purpose of the fixed data, derived data, callback, and final dependency is not established. In particular, the evidence does not establish that the two stages write text, delimit records, report errors, or terminate the process.

### 3. Derive the second-stage data reference

### 4. Submit the derived data

2. The value returned by F-44362605ab79.
3. The result from F-8810f53aaa0b, reduced by one.

Important boundaries:

- A count-producing result of 1 yields a submitted count of 0.
- A result of 0 yields the 32-bit representation of −1, ordinarily 0xFFFFFFFF.
- Whether the callee interprets that representation as signed, unsigned, or another quantity is unknown.

### 5. Evaluate the mask condition

The function computes whether the bitwise intersection of:

- The unsigned 32-bit selection value, and
- The low 32 bits of the second-stage result

This is an any-common-bit test, not equality and not a requirement that all selection bits be present.

If the intersection is nonzero, the function reads the 32-bit field at context + 0x14. If the intersection is zero, it does not read that field.

The field is interpreted only as zero versus nonzero. No individual bit, sign, or magnitude has additional established significance.

Although the upper 32 bits of the second-stage result appear in an intermediate representation, they have no established influence on the final branch:

- With no mask intersection, the path is selected independently of that upper word.
- With a mask intersection, the context field replaces it before the relevant zero comparison.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid memory and returning dependencies except where stated otherwise.

1. **Zero selection and immediate stop.**

2. **Nonzero selection does not change the initial count by magnitude.**

   If the first stage continues and F-8810f53aaa0b returns 0, the second-stage count has the 32-bit representation 0xFFFFFFFF. No explicit guard prevents the call.

4. **Fresh reference after a dependency mutation.**  
   Suppose context + 0x10 initially references object A. If F-8810f53aaa0b changes that field to reference object B, the next dependency receives B. The earlier count-producing argument was obtained through A.

5. **A zero low word overrides a nonzero upper word.**  
   If the second-stage result has low word 0 and upper word 0x12345678, the function returns without the conditional state read or either final call.

6. **Nonmatching result bits select the callback.**  
   With selection 0x04 and low result word 0x02, the function does not read context + 0x14. It invokes the indirect callback.

7. **Partial overlap is sufficient.**  
   With selection 0x0C and low result word 0x08, the mask condition is true. A zero state field selects the callback; any nonzero state field selects F-a817d8d58c10.

8. **Zero selection excludes the final direct dependency.**  
   With selection 0 and a nonzero low result word, the function selects the callback regardless of the value stored at context + 0x14, which it does not read.
