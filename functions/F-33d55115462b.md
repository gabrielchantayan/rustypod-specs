# F-33d55115462b

## Purpose

F-33d55115462b selects one of three addresses and returns the 32-bit word stored at the selected address.

Selection depends on the ordering of the addresses, not on the values stored at those addresses. The first address is the candidate; the second and third addresses participate in conditional comparisons that determine whether the candidate or another address is selected.

When the second address does not exceed the third address, the selection is consistent with constraining the candidate address to that inclusive address interval. This is an inferred interpretation, not an established requirement on the input. The function contains no explicit validation that the two addresses form an ordered interval.

The general contract is the branch-dependent selection described below. It remains applicable to unordered inputs wherever the underlying address comparisons and memory accesses are valid.

## Interface

### Input

The function accepts one address identifying a descriptor containing three consecutive 32-bit slots.

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | Candidate address |
| 4 | 32 bits | Second address |
| 8 | 32 bits | Third address |

Each slot is interpreted as an address of a 32-bit word. The slots are not themselves the candidate return values.

These widths follow from the supplied representation: descriptor elements and the return value are four-byte quantities, and descriptor elements are converted to pointers. The exact target address model, including whether any pointer bits have special significance, is not independently established.

### Output

The function returns the 32-bit word read from the selected address. The word is returned without an explicit arithmetic transformation, signed conversion, or interpretation as a status code.

There is no separate success indicator. Every possible 32-bit pattern can be an ordinary result if that pattern is readable at the selected address.

### Preconditions

For ordinary completion:

- The descriptor address must support the descriptor reads reached by the selected execution path.
- The addresses involved in each reached comparison must admit the address-ordering behavior represented by the supplied material.
- The selected address must support a 32-bit read.
- Any alignment constraints imposed by the actual target must be satisfied.
- The descriptor and selected storage must remain usable for the duration of the corresponding accesses.

The function does not explicitly enforce these conditions.

Not every execution path needs the third descriptor slot or the storage referenced by every slot. An invalid unselected pointee is not explicitly dereferenced. This does not, by itself, establish that arbitrary invalid address representations are safe to compare.

## Behavior

### Address selection

The function first obtains the candidate address from descriptor offset 0.

It then compares the second address with the candidate:

- If the second address is greater than the candidate, the second address is selected. The third address does not participate in this path.
- If the second address is less than or equal to the candidate, the third address is compared with the candidate:
  - If the third address is strictly less than the candidate, the third address is selected.
  - Otherwise, the candidate is selected.

A 32-bit word is then read from the selected address and returned.

The following table summarizes selection for stable descriptor contents:

| Relationship | Selected address |
|---|---|
| Second address greater than candidate | Second address |
| Second address at most candidate, and third address less than candidate | Third address |
| Second address at most candidate, and third address at least candidate | Candidate |

The stored words at the three addresses do not influence this choice. For example, a numerically small word at a higher address does not cause that address to be treated as a lower bound.

### Equality

The two comparisons treat equality differently:

- Equality between the second address and the candidate enters the path that examines the third address.
- Equality between the third address and the candidate selects the candidate.

Consequently, equality between the second address and the candidate does not by itself finish selection. A third address below that shared address is still selected.

If all three addresses are equal, the function selects the candidate and returns the word at the common address.

### Unordered second and third addresses

There is no general sorting operation and no unconditional median selection.

If the second address exceeds the third address:

- A candidate below the second address causes selection of the second address, without consulting the third address.
- A candidate at or above the second address causes selection of the third address, because that third address must then be below the candidate under an ordinary total address ordering.

Thus, interpreting the operation as interval clamping requires an additional ordering precondition. That interpretation must not replace the established branch behavior for other inputs.

### Reads and their ordering

The supplied representation establishes the following source-level access sequence:

1. Read the candidate address from descriptor offset 0.
2. Read the second address from descriptor offset 4 for the first comparison.
3. If that comparison selects the second-address path, obtain the address from offset 4 again and read the 32-bit word there.
4. Otherwise, read the third address from descriptor offset 8 for the second comparison.
5. If the third-address path is selected, obtain the address from offset 8 again and read the 32-bit word there.
6. Otherwise, read the 32-bit word at the previously obtained candidate address.

There is no depicted second read of the candidate descriptor slot.

The repeated appearances of the second and third descriptor slots matter when describing the supplied representation. They do not independently establish a machine-level requirement for distinct memory transactions. The material supplies neither volatile-access guarantees nor a concurrency model. An implementation-level guarantee about repeated physical loads is therefore documented_only.

For stable ordinary memory, this distinction does not affect the selected result. If descriptor contents can change between accesses, the address used for the final read may differ from the address previously compared on the second- or third-address path. No coherent-snapshot guarantee is established.

## Acceptance examples

The examples below are conditional specifications, not runtime observations. They assume stable descriptor contents, valid aligned memory where required, and an environment in which the displayed addresses have the indicated ordering.

### Candidate inside an ordered interval

Given a candidate address of `0x2000`, a second address of `0x1000`, and a third address of `0x3000`, the candidate is selected.

If the word at `0x2000` is `0x89ABCDEF`, the result must be that exact 32-bit pattern. Values at the other two addresses do not affect the result.

### Candidate below the second address

Given a candidate address of `0x1000` and a second address of `0x2000`, the second address is selected.

The third descriptor slot is not read on this path in the supplied representation. Its contents do not influence the result.

### Candidate above the third address

Given a candidate address of `0x3000`, a second address of `0x1000`, and a third address of `0x2000`, the third address is selected. The returned word comes from `0x2000`, not from the candidate.

### Equality still permits third-address selection

Given a candidate and second address both equal to `0x2000`, with a third address of `0x1000`, the third address is selected.

An implementation that always returns from the shared candidate/second address upon equality would not satisfy the represented behavior.

### Unordered endpoints are not normalized

Given a candidate address of `0x2000`, a second address of `0x3000`, and a third address of `0x1000`, the second address is selected.

The function does not swap the second and third addresses or choose the median address.

### Pointee values do not determine selection

Given a candidate between ordered second and third addresses, the candidate remains selected even if its stored word is numerically greater than both other stored words.

This distinguishes address selection from clamping the returned word’s numeric value.
