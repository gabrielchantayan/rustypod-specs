# F-0017f3d33dd8

## Purpose

F-0017f3d33dd8 coordinates processing of a caller-supplied memory region, updates progress fields in a state object, and writes a four-word trailer into the region. Subordinate calls determine whether processing succeeds. Ordinary processing failures still lead to terminal measurement and trailer output.

Batch processing and progress measurement are inferred intent. The established contract is the observable access, call, update, and return behavior below.

Two unresolved aspects prevent a fully deterministic contract:

- The flag-controlled skip path uses an initial-measurement value that it never visibly initializes.
- The residual operand used around the final processing call has unresolved provenance and preservation.

Neither uncertainty may be replaced with an assumed zero, conventional remainder, or dependency-preservation guarantee.

## Interface

### Arguments and return

| Argument | Representation | Established role |
|---|---|---|
| State | 32-bit address | Mutable object containing position, dispatch, unit-width, cursor, and checkpoint fields. |
| Region | 32-bit address | Base address for processing and trailer output. Zero is explicitly rejected. |
| Size | Signed 32-bit integer | Input to capacity calculations and trailer placement. |
| Mode | 32-bit integer | Only zero permits entry. |
| Flag address | Address of a one-byte value | Read after entry validation and the initial cursor write. Exactly byte value 1 selects the skip path. |

The 32-bit return value is selected as follows:

| Value | Condition on ordinary completion |
|---|---|
| 0 | Normal processing reaches a successful final subordinate call. |
| 1 | The indirect operation or an attempted subordinate processing call returns nonzero. |
| 2 | The flag byte equals 1. Processing is skipped, but terminal measurement and trailer output occur. |
| 3 | Mode is nonzero, or mode is zero and the region address is zero. |

These are control-flow results, not guarantees concerning invalid accesses, arithmetic faults, nonreturning dependencies, or dependency-defined exceptional behavior.

### State layout

Each observed field occupies four bytes.

| Offset | Use |
|---|---|
| `+0x04` | Address of the indirect-dispatch object. |
| `+0x0c` | Baseline subtracted from a position during measurement. |
| `+0x14` | Input to a measurement conversion. |

| `+0x24` | Unit width used in capacity, address, and length calculations. |
| `+0x2c` | Mutable region cursor. |

The dispatch object begins with a table address. The callable address is obtained from table offset `+0x14`.

No complete state layout, lifetime protocol, alignment requirement, or synchronization contract is established.

- **S**: signed supplied size.
- **U**: unit width captured for capacity setup.

- **H**: batch step supplied through F-870c4fcf7295.

Address expressions, state fields, counts, and the displayed integer arithmetic are 32-bit. The source does not establish widening before products. Formulas describe ordinary representable arithmetic; exact overflow, address-wrap, invalid-access, and alignment behavior remains documented_only.

Two distinct global locations provide additional 32-bit arguments to F-c4b34006a13c. They are mutable inputs, not established constants. Their relative read order within a call’s argument evaluation is not established.

## Behavior

### 1. Entry checks

Mode is checked first. A nonzero mode returns 3.

With mode zero, a zero region address returns 3.

Neither rejection path explicitly dereferences state or flag, invokes a dependency, or writes the trailer. There is no corresponding explicit validation of state, flag address, size, unit width, dispatch storage, or output capacity.

### 2. Initial cursor and flag

For an accepted entry, the first explicit state write is:

**cursor = B + 4 × trunc((S − 28) / 4)**

The flag byte is read afterward. Consequently, overlap between the cursor field and flag storage can affect the flag value observed.

If the flag byte is exactly 1:

- Select return value 2.
- Keep C at zero.
- Skip initial measurement, capacity setup, indirect dispatch, and subordinate processing.
- Continue to terminal measurement and trailer generation.

M₀ is not visibly initialized on this path, although trailer generation uses it. Its value and the resulting measurement-related trailer contents are unresolved.

Every other flag-byte value selects normal processing.

### 3. Initial measurement

Normal processing establishes M₀ through this sequence:

1. Read state `+0x14` and convert it through F-1c7710595b35.
2. After that call returns, read and retain the current position from `+0x20`.
3. Read the baseline from `+0x0c` and convert retained-position-minus-baseline through F-1c7710595b35.
4. Call F-450415463608 with converted difference first and converted `+0x14` value second.
5. Call F-0ec3a2a1b51e, obtaining a 64-bit result.
6. After F-0ec3a2a1b51e returns, read the two global inputs and call F-c4b34006a13c with the result’s low and high 32-bit words, followed by those global values.
7. Pass the resulting low and high words to F-9f634613286e with a third argument of 3.
8. Call F-baa332e06e32 and retain its 32-bit result as M₀.

No relative order between the two global reads is established. Earlier dependencies may change either global before these reads.

The explicit return values of F-450415463608 and, in this sequence, F-9f634613286e are not consumed. Their effects must not be treated as absent.

The retained position from step 2 is also used later by the indirect operation. Subsequent changes to state `+0x20` do not replace that retained argument.

### 4. Capacity and step setup

Read U from state `+0x24`.

Call F-870c4fcf7295 with S − 16 and U; use its ordinary return as the initial Q. Then apply the signed comparison:

**If S − (12 × Q + 16) ≤ Q × U, decrement Q by one.**

Call F-870c4fcf7295 with 65536 and the same captured U; retain its return as H.

Call F-870c4fcf7295 again with Q and H. Its ordinary return is not explicitly consumed.

The arithmetic meaning of this dependency is unknown. Q and H are not unconditionally quotients, and the final residual operand is not established as Q modulo H. Changes to state `+0x24` during these calls do not replace the captured U used in this setup.

### 5. Indirect operation

Load the dispatch target through the object referenced by state `+0x04`, using table entry `+0x14`.

The visible arguments are:

1. The dispatch-object address, read again from state `+0x04`.
2. The loaded callable address itself.
3. The position retained during initial measurement.
4. That retained position arithmetically shifted right by 31 bits.
5. Zero.

The fourth argument is zero for a nonnegative retained position and all-one bits for a negative position. No semantic interpretation of this argument sequence is established.

A nonzero return selects result 1 and proceeds to terminal measurement.

A zero return causes M₀ to be written to state `+0x30`, followed by batch processing.

### 6. Full batches and their measurements

The signed loop index starts at H. A full batch is attempted while the index is less than Q.

For each attempt:

- Read state `+0x24` and compute byte count H × current unit width.
- Read `+0x24` again and compute input address B + current unit width × (index − H).
- Call F-06ca3003b5b9 with state, input address, byte count, and H.

A nonzero result selects return value 1 and exits processing. This function does not perform the failed batch’s success-side count, position, or checkpoint updates. Dependency effects are not rolled back.

After a zero result:

1. Add H to C.
2. Read the then-current position, add the precomputed byte count, store the resulting position to `+0x20`, and retain that computed value locally.
3. Convert state `+0x14` through F-1c7710595b35.
4. Read a fresh baseline from `+0x0c`; convert retained-updated-position-minus-baseline through F-1c7710595b35.
5. Call F-450415463608 with converted difference first.
6. Call F-0ec3a2a1b51e.
7. After that call returns, read the two global inputs and call F-c4b34006a13c with the returned low/high words and those inputs.
8. Call F-9f634613286e with the resulting low/high words and 3.
9. Call F-baa332e06e32 and write its result to state `+0x30`.
10. Add H to the loop index.

This measurement does **not** repeat the initial position-read sequence. It does not reread `+0x20` after the first conversion. If that conversion changes the stored position, the measurement still uses the retained computed position. Its baseline, however, is read after that conversion and can reflect dependency changes.

The global reads occur after the current F-0ec3a2a1b51e call, without an established order between the two reads. Their values need not match those used for M₀ or another checkpoint.

Unit width is reread for each batch’s length and address calculations. No validation guarantees termination for arbitrary Q, H, or overflow behavior.

### 7. Final processing call

After normal loop completion, one final F-06ca3003b5b9 call is attempted, including when no full batches ran.

The visible calculations use the unresolved residual operand:

- Byte count: residual × a fresh read of state `+0x24`.
- Address: B + another read of state `+0x24` × (Q − residual).
- Arguments: state, calculated address, calculated byte count, residual.

There is no explicit zero-residual bypass.

A nonzero return selects result 1 without the final success-side increments.

A zero return causes:

- An addition of the residual operand to C.
- An addition of the precomputed final byte count to the then-current position.
- Return selection to remain 0.

The residual’s origin, lifetime, and preservation across intervening calls are unresolved. In particular, equality between its pre-call uses and its post-call count contribution is not independently established. Descriptions using one R for all these uses are conditional on that stability.

A successful final call does not directly write a checkpoint to `+0x30`.

### 8. Terminal measurement

Every accepted-entry path that reaches this stage performs terminal measurement, including skip and ordinary failure paths.

First:

- Convert state `+0x14`.
- After that conversion returns, read position and baseline and convert their difference.
- Call F-450415463608 with converted difference first.
- Call F-0ec3a2a1b51e.

The position and baseline reads both follow the first conversion; their relative evaluation order is not established.

The remaining sequence differs from initial and full-batch measurement:

1. Pass the returned low/high words to F-9f634613286e with 3.
2. After F-9f634613286e returns, read the two global inputs and pass its returned low/high words and those inputs to F-c4b34006a13c.
3. Call F-baa332e06e32 to obtain M₁.

Thus terminal global reads occur after F-9f634613286e, not merely after F-0ec3a2a1b51e. Either dependency may change the values eventually read. No order between the two global reads is established.

The terminal F-c4b34006a13c return is not explicitly consumed. No equivalence between the different measurement orderings is established.

### 9. Trailer output

Compute E = B + 4 × trunc(S / 4). The explicit write and cursor-read sequence is:

1. Write E − 8 to state `+0x2c`.
2. Write a four-byte zero at E − 4.
3. Read the cursor; write a cursor value four bytes lower; write C through the previously read address.
4. Read the cursor again; write a cursor value four bytes lower; write M₀ through the previously read address.
5. Read the current cursor and write the 32-bit difference M₁ − M₀ through it.

With nonoverlapping storage, the result is:

| Address | Value |
|---|---|
| E − 16 | M₁ − M₀ |
| E − 12 | M₀ |
| E − 8 | C |
| E − 4 | Zero |

The final cursor is E − 16.

Aliasing can change this outcome. A trailer store may overwrite the cursor field before a later cursor read, so the ordinary layout is not unconditional.

## Side effects

Explicit writes target state `+0x20`, `+0x2c`, and `+0x30`, plus the trailer stores. The function also reads the two global inputs at every executed F-c4b34006a13c call site. No explicit writes to those globals are shown; dependency writes remain possible.

There is no explicit allocation, release, or ownership transfer. Dependencies receiving addresses are not established to preserve, retain, own, or release the addressed storage.

Processing failure is nontransactional. Earlier successful increments persist unless dependencies alter them. A failing call may already have changed memory. Terminal dependencies may further change state before trailer output.

For nonnegative S, E excludes the final S modulo 4 bytes from explicit trailer targets. Small or negative sizes are not rejected and can produce addresses before B. Valid ordinary execution requires sufficient accessible storage for every executed access, not merely a nonzero region address.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations.

1. **Rejected entry.** Nonzero mode returns 3 without explicit state or flag access. With mode zero, a zero region address also returns 3 without trailer output.

2. **Skip.** With flag byte 1, valid nonoverlapping storage, and returning terminal dependencies, result is 2. No processing call occurs; trailer count and last word are zero. M₀ and both measurement-related trailer values remain unresolved.

3. **Indirect failure.** If the indirect operation returns nonzero, result is 1, no subordinate processing occurs, and C remains zero. M₀ has been established; terminal measurement and trailer output still occur.

4. **Failure after one batch.** Let H = 4, Q = 10, and unit width remain 8. If the first full batch succeeds and the second fails, with no independent position mutations, C is 4 and position advances by 32. The failed batch contributes no success-side increment.

5. **Retained batch position.** Suppose a successful batch computes and stores position 132. If the following first conversion changes `+0x20` to 900 and leaves the baseline at 20, the second conversion receives 112, not 880. Initial and terminal measurement instead read position after their first conversion.

6. **Mutable measurement globals.** If F-0ec3a2a1b51e changes the globals before an initial or checkpoint call to F-c4b34006a13c, that call uses the subsequently read values. If terminal F-9f634613286e changes them again, terminal F-c4b34006a13c uses those later values. No identical-input guarantee applies.

7. **No full batches.** If H is at least Q under signed comparison, the loop is skipped, but the final processing call is still attempted. If its residual remains R throughout and the call succeeds, C increases by R and position by the precomputed byte count. No direct final checkpoint write occurs.

8. **Unaligned size.** For S = 103 and nonoverlapping valid storage, E = B + 100. Trailer words occupy offsets 84, 88, 92, and 96. The final cursor is B + 84; offsets 100–102 are not explicit trailer targets.
