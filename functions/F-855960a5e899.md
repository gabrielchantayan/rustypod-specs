# F-855960a5e899

## Purpose

F-855960a5e899 performs a sequence of dependency calls interleaved with byte, halfword, and word memory accesses. The supplied static representation does not establish an application-level purpose such as allocation, serialization, rendering, or destruction.

The supported contract is a **conditional memory-and-call trace**. Explicit arguments alone do not determine its effects: ambient execution state, dependency results, secondary outputs, and separately sampled shared memory contribute to later calls and accesses.

The represented path ends at an invalid-instruction boundary rather than an explicit normal return. Successful completion and a returned status are therefore not established.

This document distinguishes:

- **Established static evidence:** represented accesses, widths, value relationships, and ordering between separate operations.
- **Inferred intent:** possible interpretations that are not behavioral requirements.
- **documented_only:** behavior unresolved by the supplied material.

Every described operation is conditional on execution reaching it and on preceding calls and accesses permitting continuation.

## Behavior

### Entry effects and selector rereading

The initial operation reads a byte at the ambient address-like value plus 1. The resulting unsigned selector determines the destination at selector plus 17. The ambient payload byte is written there before the first dependency receives the second explicit argument.

Early calls also forward the ambient address-like value logically shifted right by 11 and dependency results shifted left by 2.

After several calls, the selector byte at the original ambient base plus 1 is read again. Its newly sampled value determines another destination. The payload comes from the ambient extraction input masked to 31 bits, logically shifted right by 21, and narrowed to a byte.

The reread is independent of the initial read. Intervening dependencies may change shared memory. The second destination must not be reconstructed using the first selector.

The masked extraction can contain ten bits before storage. Byte narrowing retains original input bits 21 through 28 and discards the higher extracted bits.

### Recurring selector-directed interactions

The path repeatedly alternates calls with selector reads and byte writes. At each occurrence, a byte is read from that occurrence’s computed selector address; its unsigned value selects the destination at selector plus 17.

This recurring pattern does not establish a loop or authorize merging, caching, or reordering occurrences. Even equal selector addresses need not yield equal values across intervening calls.

Selector addresses use distinct transformations, including scaling by 4, 8, 16, 64, 1,024, or 4,096; logical right shifts by 9, 11, 12, or 21; masks followed by further scaling or shifting; and larger shift-derived scales.

Payloads include:

- Zero.
- A dependency result multiplied by four and narrowed to a byte.
- A 32-bit value shifted right by 22 and narrowed.
- A value masked to 30 bits and shifted right by 20.
- A value masked to 22 bits and shifted right by 12.
- The low byte of a saved word read.
- Selected high bits from a represented 64-bit result.

These expressions need not be byte-wide before storage. For example, an unsigned 32-bit value shifted right by 22 can contain ten bits; byte storage retains original bits 22 through 29.

Some later calls receive a saved selector together with transformed dependency results. Argument positions matter: the selector does not consistently occupy the same position.
