### Transition into the final loop

The last run’s result has its top two bits cleared and is shifted right by 25, producing a **five-bit loop seed** in the range 0 through 31.

A different byte lookup address is formed from four times the second byte-source result, multiplied by 1024, plus one. An unsigned byte is read there; zero is stored at that byte value plus 17.

A dispatch receives twice the five-bit loop seed. A subsequent no-explicit-argument dispatch supplies the first iteration’s carried argument.

Each loop iteration then:

1. Invokes F-unknown-004 with the carried argument and the current loop word shifted right by eight.
2. Performs four more ordered dispatches, retaining the last result.
3. Rereads the second lookup byte and stores zero at that byte value plus 17.
4. Performs a dispatch run whose first call receives the retained result shifted left by two.
5. Replaces the carried argument with the final result shifted left by two.
6. Replaces the loop word with that same final result shifted left by 26.
7. Repeats without a visible exit test.

The initial loop word is the five-bit loop seed, so the first iteration’s second explicit argument is zero. Subsequent loop words need not remain five-bit values.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes execution reaches the operation, relevant addresses are valid, and earlier dependencies return.

1. **Distinct initial destinations.**  
   With first argument 8, the first store writes the 32-bit value 8 at address 52. After the initial dispatch run, the second store writes 8 at address 28.

2. **Third-argument truncation.**  
   An original third argument of 16,383 produces zero in the fourth argument of the four-argument dispatch run. A value of 16,384 produces one. The maximum unsigned 32-bit input produces 262,143.

3. **Fresh destination selection.**  
   If the lookup byte is 7 for one access, that access writes at address 24. If intervening behavior changes the lookup byte to 9, the next selected store writes at address 26. Reusing the earlier selection would violate the represented behavior.

4. **Byte truncation.**  
   A first byte-source result of 65 produces a first byte value of 4, because four times 65 is 260 and only the low eight bits are stored.

5. **Different extraction from the same result.**  
   A first byte-source result of hexadecimal 3FF00000 produces 255 for the later store derived by clearing the top two bits, shifting right by 20, and retaining the low byte.

6. **Auxiliary-result overflow.**  
   Under the 32-bit machine interpretation, an auxiliary result of 64 produces destination address 20 and stored value hexadecimal 40000000. The address product loses all bits, while the value product does not.

7. **Loop-entry boundary.**  
   Any valid five-bit loop seed produces zero as the first iteration’s second argument. A seed of 31 is passed as 62 to the dispatch preceding loop entry.

8. **No promised return.**  
   If all accesses and dependencies continue normally, completing one loop iteration must lead to another. A normal return after a fixed iteration count is unsupported by the represented control flow.
