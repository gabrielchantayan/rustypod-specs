# F-46a01d013a61

## Purpose

F-46a01d013a61 partially initializes and conditionally updates a destination object using a source descriptor, two explicit 32-bit arguments, and additional incoming state. Its visible return values are `0x00000000` on normal completion and `0xFFFFFFFF` on rejection.

Initialization precedes validation. Rejection preserves preceding writes; there is no rollback. Accepted execution selects an adjustment, calls F-6d8c85350b66, performs result-dependent updates, increments an externally addressed counter, and calls F-266a29fc8dc5.

**Established static evidence:** access widths, offsets, ordering, branch conditions, arithmetic representations, calls, and return constants described below.

**Inferred intent:** configuration or state initialization. This does not establish complete initialization, application-level validity, or ownership transfer. “Baseline,” “marker,” “category,” “mode,” and “adjustment” are descriptive labels rather than established domain meanings.

## Behavior

### Initial destination updates

Before validation, the function writes the primary value to destination `0x50`. It then copies source words in this order: `0x18` to destination `0x64`, `0x14` to `0x54`, and `0x28` to `0x74`.

Each copy reads its source and then writes its destination before the next copy. Earlier destination writes can therefore affect later source reads through overlap.

The function next writes the full baseline to destination `0x88`, then `0x84`, and the marker’s low byte to `0x8D`.

### Selector-dependent updates

| Selector | Ordered effects |
|---|---|
| `0` or `7` | Write baseline low byte to destination `0x42`, then `0x43`; copy source bytes `0x30`–`0x33` individually, in increasing order, to destination `0x5D`–`0x60`. |
| `1`, `2`, or `5` | Write baseline low byte to destination `0x42`, then `0x43`. |
| `3` | Write baseline low byte to destination `0x42`, then `0x43`; copy source bytes `0x2C`–`0x2F` individually, in increasing order, to destination `0x59`–`0x5C`. |
| `4` | Read source byte `0x10` and write destination `0x42`; then read source byte `0x11` and write destination `0x43`. |
| `6` or any other value | No accesses in this phase. |

Each byte copy completes before the next source read. Omitted fields are not initialized by this dispatch. In particular, selector `7` does not directly write destination `0x58`.

### Range validation

The function reads source word `0x08` as unsigned, then writes the baseline low byte to destination `0x40`.

If the captured value is at most `8`, validation continues without assigning destination word `0x3C`. Otherwise, source word `0x08` is read again. A second value greater than `16` causes immediate rejection. A second value at most `16` causes the full marker to be written to destination `0x3C`.

For stable source memory:

- `0`–`8`: leave destination `0x3C` unassigned by this phase.
- `9`–`16`: assign the marker to destination `0x3C`.
- `17`–`0xFFFFFFFF`: reject.

The second read is distinct. An overlapping destination `0x40` write or other mutation can change its value; it need not remain greater than `8`.

### Mode validation

The first source word read at `0x0C` is compared with `1`. Equality writes the marker low byte to destination `0x41` and accepts the mode.

Otherwise, the function writes the baseline low byte to destination `0x41`, then reads source word `0x0C` again. Unless that second value equals `2`, execution rejects. If it equals `2`, destination word `0x3C` is read, incremented by one using a signed 32-bit representation, and written back.

With stable source memory, modes `1` and `2` pass; all others reject. Mode `2` increments either the marker assigned during range validation or the existing destination word when that phase did not assign it. Signed-overflow behavior is **documented_only**.

### Common accepted-mode updates

Following mode acceptance, source word `0x0C` is read afresh and copied to destination `0x14`. The copied value is not necessarily the value that passed validation.

### Inspection-dependent updates

For an accepted category, F-6d8c85350b66 is called once with the address of source offset `0x40`. Its result is captured in a signed 32-bit representation and tested only for zero versus nonzero. The dependency’s full prototype and internal behavior are unknown.

#### Zero captured result

The function writes the baseline low byte to destination `0x28`, followed by full baseline words to `0x2C`, `0x30`, `0x34`, `0x38`, `0x7C`, and `0x80`, in that order.

These are baseline assignments, not necessarily zeroing operations. This branch does not read destination `0x78`.

#### Nonzero captured result

The function writes the marker low byte to destination `0x28`, then copies source word `0x40` to destination `0x2C`.

It next reads and captures source words `0x44`, `0x48`, and `0x50`, respectively writing them to destination `0x30`, `0x34`, and `0x38`. Each read/write pair completes before the next.

Destination byte `0x58` is then read. If it equals `7`, the three captured source values are shifted left by one and written to destination `0x30`, `0x34`, and `0x38`, in that order. These operations use captured values, not fresh destination reads. The shifts have signed 32-bit representations; negative inputs and nonrepresentable results remain **documented_only**.

Next, destination word `0x78` is captured as an unsigned adjustment. Destination word `0x30` is read, added to that adjustment using 32-bit unsigned arithmetic, and the low 32 bits are written to destination `0x7C`.

Destination word `0x34` is read and compared as unsigned against the adjustment. If it is strictly greater, destination `0x34` is read again and the adjustment is subtracted using unsigned 32-bit arithmetic. Otherwise, numerical zero is selected. The selected result is written to destination `0x80` through a signed 32-bit intermediate.

For stable memory and representable intermediate results, destination `0x80` is the positive unsigned excess of destination `0x34` over the adjustment, or zero. Conversion of a subtraction result exceeding the signed 32-bit range is **documented_only**; this contract does not impose an unestablished conversion rule.

All these accesses follow the inspection call. The dependency is not assumed to preserve source, destination, or external state.

### Completion

Only after that byte write does it read the signed 32-bit counter through the captured pointer, add one, and write the result through the same pointer. Signed overflow is unresolved. This read/add/write sequence provides no atomicity guarantee.

The external expression supplying the first argument to F-266a29fc8dc5 is evaluated **after the counter write**. F-266a29fc8dc5 is then called with that expression as its first argument and numerical zero as its second argument.

The first expression’s declared type, whether evaluation entails a storage read, any such read’s width, and argument conversion are not established. The supplied prototype also does not establish the second argument’s receiving type.

If the call returns normally, the function returns zero without inspecting its result.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, assume valid, non-overlapping storage, stable memory, normally returning dependencies, and no dependency mutation of discussed fields.

1. **Early rejection preserves initialization.** With source range word `17`, return `0xFFFFFFFF` after initial and selector updates and the destination `0x40` byte write. No mode-phase write or dependency call occurs.

2. **Range boundaries preserve different state.** Range `8` leaves destination `0x3C` unassigned by range validation. Range `16` assigns the marker. Later mode and category checks still apply.

3. **Mode two can use incoming state.** With range `8`, mode `2`, and incoming destination `0x3C = 12`, that word becomes `13`, rather than first being reset.

4. **Invalid mode still writes a byte.** With a passing range and mode `3`, destination `0x41` receives the baseline low byte before rejection. Common accepted-mode updates do not occur.

5. **Selector and category are independent.** Selector `2` performs its early writes, while category `2` later rejects after the common updates. A selector outside `0`–`7` can complete when all later conditions pass.

6. **Zero inspection completes normally.** Accepted range, mode, and category with a zero captured inspection result cause baseline assignments, counter increment, late final-argument evaluation, and the final call.

7. **Unshifted derivation.** With category `0`, baseline `10`, nonzero inspection, destination `0x58 ≠ 7`, and source words `0x44 = 4`, `0x48 = 25`, `0x50 = 6`, destination words `0x30`, `0x34`, `0x38`, `0x7C`, and `0x80` become `4`, `25`, `6`, `14`, and `15`, before later dependency effects.

8. **Destination state controls shifting.** Under the preceding conditions but with destination `0x58 = 7`, those words become `8`, `50`, `12`, `18`, and `40`. Selector `7` alone is insufficient.

9. **Unsigned addition wraps.** With captured adjustment `0xFFFFFFFF` and destination `0x30 = 2`, destination `0x7C` receives `1`. If destination `0x34` equals the adjustment, destination `0x80` receives zero.

10. **Counter alias affects a compatible final argument.** Additionally assume the final expression denotes compatible 32-bit storage interpreted by the call as the numerical value stored there. If the counter target is exactly that storage, initially `41`, and destination `0x8C` does not overlap it, completion writes `42` before evaluating the expression. Under these additional assumptions, the first argument denotes `42`, not `41`. Without the missing declaration and prototype, only evaluation ordering—not this width or numerical interpretation—is established.
