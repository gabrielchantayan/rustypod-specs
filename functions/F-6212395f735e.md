# F-6212395f735e

## Purpose

F-6212395f735e performs a gated, reverse-order processing operation over an object containing control fields, a record region, and dependency handles. It may instead perform one fallback operation when the record count is nonpositive.

The established behavior has three distinguishing features:

- A nonzero byte at object offset `0x123D` suppresses all dependency calls at entry.
- Records whose discriminator is `2` or `3` are skipped. Other records are processed from the highest selected index downward, stopping at the first nonzero processing result.
- The return value is a 64-bit composite. Its low 32 bits are either `0` or `3`; its high 32 bits are either the original second argument or a value subsequently read from object offset `0x1394`.

The terms “completed,” “status,” “record,” and “handle” below are descriptive labels. Their application-level meanings are not established. In particular, a low return word of `0` does not necessarily mean that the function performed work: the entry suppression path also returns that value.

## Behavior

### Entry suppression

The function first reads the byte at `0x123D`.

If that byte is nonzero:

- No dependency is called.
- No direct object write occurs.
- The low return word is `0`.
- The high return word is the original second argument.

This path does not initialize the local working word.

If the byte is zero, the function initializes its local working word from the fourth argument and proceeds to the gates.

### Preliminary gates

The function calls F-6b71c72d5449 with the object address.

A nonzero result terminates the operation with low return word `3` and the original second argument as the high word. No later dependency is called.

A zero result permits a call to F-f0216cff9365 using the 32-bit value then read at `0x1380`. Only one argument is explicit at this call site.

If this call returns nonzero, the function returns low word `3` and the original high word. It does not perform the final dependency call.

If both gate results are zero, the function reads `0x123D` again. This is a fresh read: dependencies may have changed the object.

If the second suppression read is nonzero, record and fallback processing are bypassed. The function proceeds directly to the final dependency call, retaining low word `0` and the original high word unless that final call changes the low-word decision.

### Count selection

If the second suppression read is zero, the signed 32-bit count at `0x1080` is sampled.

- Counts less than `1`, including negative counts, select fallback processing.
- Positive counts select reverse record processing.

The count is not visibly reloaded during iteration. Changes to the stored count by dependencies therefore do not alter the already selected iteration bound.

### Fallback processing

For a nonpositive count, the function reads `0x1394` into the upper return word.

It then calls F-9420a5e9ee08 with six explicitly represented arguments, in this order:

1. The 32-bit value at `0x1060`.
2. The 32-bit value at `0x1064`.
3. The 32-bit bit-pattern `0xFFFFFFFF`.
4. The address of the local working word.
5. The sampled upper return word.
6. The third input argument.

The constant `0xFFFFFFFF` is established as a 32-bit all-ones argument; its semantic interpretation as a signed value or sentinel is unknown.

If the processing result is zero, the function writes:

1. `1` to byte `0x123D`.
2. `3` to byte `0x1390`.

It then proceeds to the final dependency call with low return word `0`.

If the processing result is nonzero, the function sets the low return word to `3`, writes `3` to byte `0x1390`, and proceeds to the final dependency call. It does not itself set `0x123D` on this failure path.

### Reverse record processing

For a positive count, the first considered record index is one less than the sampled count. Subsequent indices decrease by one.

For each considered index:

- A discriminator of `2` skips that record.
- A discriminator of `3` also skips that record.
- Any other discriminator selects the record for processing.

The visible discriminator condition may read the same byte twice: once for comparison with `2`, then, if that comparison is false, again for comparison with `3`. A contract requiring exactly one discriminator read per record is not supported.

For a selected record, the following dependency calls occur in order:

1. F-f0216cff9365, with the current value at `0x1380` and the record-associated address.
2. F-2bb3dbfa7286, with a newly read value at `0x1380` and the same record-associated address.
3. F-9420a5e9ee08, after reading `0x1394` into the upper return word.

The first two results are ignored. They do not directly prevent the processing call.

The record processing call has four explicitly represented arguments:

1. The value at `0x1060`.
2. The record-specific value at `0x1240 + index × 0x50`.
3. The record-specific value at `0x1244 + index × 0x50`.
4. The address of the local working word.

A zero processing result continues the reverse traversal. A nonzero result stops traversal immediately; no lower-index record is considered by this invocation afterward. On that stop path, the function sets the low word to `3` and writes `3` to `0x1390`.

If traversal exhausts all indices, including when every record was skipped, the function writes `1` to `0x123D`, then `3` to `0x1390`, and retains low word `0`.

The upper return word is replaced before each selected record’s processing call. Thus it reflects the most recent such sample of `0x1394`. If every record is skipped, it remains the original second argument.

The local working word is initialized only once. Any mutation made through its address by one processing call is available to later processing calls; there is no visible reset between records.

### Final dependency call

After either processing path, or after bypass due to the second suppression check, the function calls F-2bb3dbfa7286 with:

1. The current 32-bit value at `0x1380`.
2. The address at object offset `0x13A8`.

A zero result causes a write of `3` to `0x1390` and leaves the low return word unchanged.

A nonzero result sets the low return word to `3`. There is no additional direct state-byte write on that branch, although processing may already have written it.

Consequently:

- A zero final result cannot clear an earlier low-word failure.
- A nonzero final result changes an otherwise zero low word to `3`.
- Successful processing may set `0x123D` before the final call subsequently produces low word `3`.

## Side effects

The only direct object writes established for this function are byte writes to `0x123D` and `0x1390`. It does not directly clear either byte.

The function does not visibly roll back earlier writes when the final dependency returns nonzero. Nor does it visibly undo successful processing of higher-index records when a lower-index record fails.

Dependency effects remain part of the execution environment. No dependency is proven to preserve the object, handle, record contents, global state, or pointed-to storage. In particular:

- Reads of `0x1380` for separate calls are not interchangeable snapshots.
- Record processing arguments are read after the two record-associated dependency calls.
- A dependency may change a discriminator for a record not yet considered.

Accordingly, a direct write described above does not by itself establish the field’s final value after subsequent dependency calls.

## Acceptance examples

These examples are conditional on dependency calls returning normally, required memory being valid, and dependencies making no changes beyond those expressly stated.

1. **Suppressed at entry.** With `0x123D` nonzero, the function makes no dependency calls and returns low word `0`, high word equal to input two.

2. **First gate rejects.** With entry suppression clear and F-6b71c72d5449 returning nonzero, no other dependency is called. The return is low word `3`, original high word, with no direct object write.

3. **Second suppression check becomes active.** Suppose both gates return zero, but a gate sets `0x123D` nonzero. Processing is bypassed. If the final call returns zero, the function writes `3` to `0x1390` and returns low word `0` with the original high word.

4. **Negative count uses fallback.** A sampled count of `−1` does not initiate reverse traversal. It selects the same fallback operation as zero. If processing and the final call both return zero, the direct writes are `0x123D = 1`, `0x1390 = 3`, then `0x1390 = 3` again. The high word is the sampled value from `0x1394`.

5. **All records skipped.** For count `3` with discriminators at indices `2`, `1`, and `0` each stably equal to `2` or `3`, no record-associated dependency calls occur. Completion writes still occur. With a zero final result, the return has low word `0` and the original high word.

6. **Stop at a record failure.** For count `3`, let index `2` process with result zero and index `1` process with a nonzero result. Index `0` is not considered. The high word comes from the sample before processing index `1`; the low word is `3` regardless of the final call’s result.

7. **Completion followed by final failure.** If traversal completes, then the final dependency returns nonzero, the low word is `3` even though this function already wrote `1` to `0x123D`.
