# F-323804bcc494

## Purpose

F-323804bcc494 coordinates an operation on a caller-supplied object, optionally invokes a follow-up dependency, and conditionally copies a 16-bit field from that object into a field of an object obtained from another dependency.

The function returns the 32-bit result of its principal operation. That result is captured before the optional follow-up and conditional field update. Neither later step explicitly replaces the captured result.

**Established behavior:** the sequence of dependency calls, the conditions governing additional calls, the two field offsets, and the conditional 16-bit write are visible in the supplied static evidence.

**Inferred intent:** the final conditional write resembles initialization of an unset field from a nonzero source field. This interpretation is not a stronger guarantee: the destination is obtained again before writing, and the source is read again. Intervening dependency effects can therefore change both the object being written and the value copied.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, dependencies return normally and all reached accesses are valid.

1. **Zero control value, readable source.**  
   The initial lookup, setup, and principal operation occur. The follow-up is omitted. The source field is still read, regardless of its value. There are no later lookups and no direct write. The principal result is returned unchanged.

2. **Nonzero control value, source observed as zero.**  
   The follow-up occurs before the source read. If that read observes zero, no candidate destination is obtained and no direct write occurs.

3. **Nonzero source and occupied candidate destination.**  
   With a nonzero control value, a nonzero source observation triggers a second lookup. If the field at that returned address plus `0x80` is nonzero, there is no third lookup and no direct write.

4. **Stable destination and source.**  
   Suppose the control value is nonzero, the source remains `0x1234`, both later lookups return the same destination, and its checked field is zero. The function writes `0x1234` to that destination field and returns the principal result.

5. **Destination changes between lookups.**  
   Suppose the checked destination field is zero, but the last lookup returns a different object whose destination field is nonzero. The function writes to the last object without checking its field. A contract that preserves every nonzero destination field would reject behavior the evidence permits.

6. **Source changes after the initial source test.**  
   Suppose the source test observes `0x1234`, the candidate destination field is zero, and the final lookup changes the source to zero. The final copy writes zero. The earlier nonzero observation does not constrain the later copied value.

7. **Negative control value.**  
   A representable negative control value is nonzero and enables the same local branches as other nonzero values. It is also passed unchanged to F-5b8747ba252d.

8. **Principal result resembles failure.**  
   Even if the principal result has a value conventionally interpreted as failure elsewhere, this function does not inspect it. Reached follow-up operations still occur, and that same 32-bit result is returned.
