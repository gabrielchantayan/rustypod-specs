# F-641b3712cfc7

## Purpose

- consults service objects, potentially requests action value 4, and may transfer control to a dependency marked as non-returning.

## Behavior

### Preliminary operations

The first observable call is to F-6799eeb2fd42, with no explicit arguments. Its return value, if any, is not used.

After that call, the function reads the 32-bit value at input offset 0xC8.

- If it is zero, the following callback and notification are skipped.
- If it is nonzero, the function invokes the input object’s dispatch-table entry at offset 0x13C, passing the input object as an explicit argument.
- If that callback returns zero, F-c206e6f8e0d5 is skipped.
- If the callback returns nonzero, the function reads offset 0xC8 again and passes that newly read value to F-c206e6f8e0d5.

The second read matters. The initial nonzero check does not guarantee that the value eventually passed to F-c206e6f8e0d5 is nonzero or unchanged. The intervening callback may affect the object.

Next, the function reads the byte at input offset 0xC1. If that byte is nonzero, it calls F-8ac0302a48ef with the input object. Otherwise, that call is skipped.

These operations precede the main branch. They are not bypassed by the later early return.

### Main branch selection

Only whether the result equals zero is significant:

- A nonzero result selects the object-specific branch.
- A zero result selects the service-object branch.

There is no established distinction among different nonzero results.

### Object-specific branch

When F-06244c3a54b1 returns nonzero:

1. F-44874cacba18 is called with the input object.
2. The value at input offset 0xB0 is read again.
3. F-d1589ea82582 is called with that newly read value.
4. The function returns 1.

The second value at offset 0xB0 need not equal the value previously passed to F-06244c3a54b1. F-44874cacba18 and other intervening effects must not be assumed to preserve it.

No service-object lookup occurs on this branch.

### Service-object branch: initial gate

It invokes that object’s dispatch-table entry at offset 0xC4 with two explicit arguments:

If the result is nonzero, the function immediately returns 1. On that path there is no second service lookup, no secondary-object query, no action-value-4 call, and no call to F-feee9156a257.

A zero result allows processing to continue.

### Service-object branch: secondary lookup

The supplied representation shows no explicit arguments for this indirect invocation. In particular, it does not establish that the second lookup result is passed as an explicit receiver argument.

The two calls to F-b7af80e829ec must not be treated as interchangeable. They may return different objects. Subsequent operations at offsets 0xF8 and 0xC4 use the retained primary service object from the first call, not the result of the second lookup.

### Non-null secondary object: threshold comparison

If the secondary object is non-null, the function performs two indirect queries in this order:

1. Invoke primary-service dispatch-table offset 0xF8, passing the primary service object.
2. Invoke secondary-object dispatch-table offset 0x94, passing the secondary object.

The first query result is treated as an unsigned 32-bit quantity.

For the comparison, the second query result participates in unsigned 32-bit arithmetic. The threshold is its 32-bit bit pattern plus decimal 3000, reduced modulo \(2^{32}\). The function tests whether the first query result is less than or equal to that threshold, using unsigned comparison.

This is not established as a signed, saturating, or wrap-aware time comparison. Negative-looking bit patterns and addition overflow retain their unsigned modular consequences.

If the comparison succeeds:

1. F-ce4ff32f927a is called with the input object and the 32-bit value 4.

There is no further secondary-object null check between F-ce4ff32f927a and F-feee9156a257. The saved address is used even if the intervening call changes other state. Whether that address remains valid is a dependency and lifetime requirement, not a guarantee established here.

### Fallback operation

- the secondary object is null; or
- the secondary object is non-null and the unsigned threshold comparison fails.

The function invokes primary-service dispatch-table offset 0xC4 with:

- the retained primary service object;
- the 32-bit value 3.

Unlike the earlier invocation with value 2, this invocation’s result is ignored.

- If it is non-null, the function calls F-feee9156a257 with that address.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests. Each assumes that preceding calls return normally and all reached memory accesses are valid.

1. **Normal object-specific path.** If the main branch query returns any nonzero value, F-44874cacba18 runs before F-d1589ea82582. The latter receives the post-call value at offset 0xB0. The result is 1, and no service lookup occurs.

2. **Callback changes the notification value.** If offset 0xC8 initially contains a nonzero value, the offset-0x13C callback changes it to zero, and that callback returns nonzero, F-c206e6f8e0d5 receives zero. Reusing the initial value would violate the observed reread.

3. **Service gate stops processing.** If the main query returns zero and the primary service’s operation with value 2 returns nonzero, the function returns 1 without performing the second lookup.

4. **Null secondary object.** If the initial service gate returns zero and the secondary lookup returns null, neither quantity query runs. The primary-service operation with value 3 runs, its result is ignored, and the function returns 1.

5. **Inclusive threshold.** If the secondary quantity is 1000 and the primary quantity is 4000, the comparison succeeds. F-ce4ff32f927a receives value 4, followed by F-feee9156a257 receiving the secondary object. The operation with value 3 is skipped.

6. **Above threshold.** With secondary quantity 1000 and primary quantity 4001, the comparison fails. The primary-service operation with value 3 precedes F-feee9156a257. F-ce4ff32f927a is not called.

7. **Unsigned wraparound.** If the secondary quantity’s bit pattern is 0xFFFFFFFF, adding 3000 produces 2999 modulo \(2^{32}\). A primary quantity of 2999 satisfies the comparison; 3000 does not. No saturation is applied.

8. **Distinct service lookup results.** If the two service lookups return different addresses, offset 0xE8 is selected through the second object, but the quantity query at offset 0xF8 and any fallback operation at offset 0xC4 still use the first object.
