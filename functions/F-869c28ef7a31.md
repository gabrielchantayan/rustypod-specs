# F-869c28ef7a31

## Purpose

F-869c28ef7a31 updates a two-word destination descriptor from a two-word source descriptor, with an optional dependency call concerning the destination’s existing value.

The destination metadata’s low bit controls the initial call to F-94cb53877c15. After that call, if any, the source’s first word selects one of two paths:

- **Zero source value:** write zero to the destination value without directly changing destination metadata.
- **Nonzero source value:** merge source and destination metadata, invoke F-7129d6a8d912, store its result, and force the destination metadata’s low bit to one.

The established contract is the ordering of descriptor accesses and dependency calls. Describing the dependencies as cleanup and value production is convenient shorthand. Actual deallocation, allocation, copying, and ownership semantics are not established.

## Interface

The function accepts three arguments and has no explicit return value.

| Argument | Representation | Established role |
|---|---|---|
| Context | Opaque 32-bit value | Forwarded unchanged to F-7129d6a8d912 on the nonzero-source path. |
| Destination descriptor | Address of two adjacent 32-bit words | Supplies the initial call gate and existing value; receives direct writes. |
| Source descriptor | Address of two adjacent 32-bit words | Supplies the branch selector and, conditionally, metadata and dependency arguments. |

Descriptor layout:

| Byte offset | Width | Destination role | Source role |
|---|---:|---|---|
| 0 | 32 bits | Existing or replacement value | Zero/nonzero selector and subsequent dependency argument |
| 4 | 32 bits | Metadata; bit 0 gates F-94cb53877c15 | Encoded metadata; bits 31 through 1 supply a decoded quantity |

These widths do not establish that the first words are pointers. They may represent addresses, handles, or another 32-bit encoding. Descriptor-address width and byte order are not established.

The supplied source presents source words through a signed 32-bit view. The branch distinguishes zero from every other bit pattern, including patterns with bit 31 set. For quantity decoding, the source metadata is explicitly interpreted as unsigned 32-bit data before shifting right by one.

### Preconditions

Ordinary, defined execution requires:

- Valid destination storage for the accesses on the selected path.
- A readable source first word at the post-cleanup branch decision.
- Readable source metadata and a readable source first word again on the nonzero-source path.
- Appropriate alignment and storage lifetime for the execution environment.
- Satisfaction of the dependencies’ own requirements, which are not supplied.
- Continued validity of all later accesses if either dependency changes descriptor storage, related storage, or accessibility.

The function contains no explicit checks for null descriptor addresses, overlap, encoded-quantity validity, or dependency-result validity.

The zero-source path does not directly read source metadata. The layout describes that field, but this path does not establish a requirement to access it.

## Behavior

The following describes the direct operations established by the supplied body. Dependency-internal activity remains unspecified.

### Initial destination inspection

The function first reads destination metadata and examines bit 0.

If the bit is clear, it skips F-94cb53877c15.

If the bit is set, it reads the destination value and calls F-94cb53877c15 with that 32-bit value. The function does not use a return value from this dependency.

This call precedes the source branch decision. The gate does not depend on whether:

- The destination value is zero.
- The source value is zero.
- The source and destination values are equal.
- The descriptor addresses coincide or overlap.

A set destination low bit therefore causes the call even when the destination value is zero.

Before this call, F-869c28ef7a31 does not directly clear either destination word. Any changes occurring during the call are dependency effects, not guaranteed behavior of this function.

### Source branch decision

After F-94cb53877c15 returns normally, or immediately if it was skipped, the function reads the source’s first word.

A zero value selects the zero-source path. Every nonzero 32-bit pattern selects the nonzero-source path; there is no positivity test.

The source is not captured before the initial dependency call. If that dependency changes source-visible storage, the branch uses the contents subsequently read, not necessarily the contents present at function entry.

### Zero-source path

The function writes a 32-bit zero to the destination’s first word and returns.

On this path, it does not directly:

- Read the source’s second word.
- Invoke F-7129d6a8d912.
- Write destination metadata.
- Force destination metadata bit 0 either on or off.

Destination metadata therefore retains the value present at this point. If F-94cb53877c15 ran, that value need not equal its entry value.

In particular, this path can leave a zero destination value together with a set destination low bit. There is no normalization of that combination.

### Nonzero-source path: metadata merge

Before invoking F-7129d6a8d912, the function writes destination metadata combining:

- Bit 0 from destination metadata read for this update.
- Bits 31 through 1 from source metadata read for this update.

The source metadata’s low bit is discarded. The destination metadata’s old upper 31 bits are discarded.

Both operands must be obtained before the merged word is written. The supplied evidence does not establish which operand is read first.

The destination low bit used here is a fresh read for the merge, not necessarily the value observed by the initial call gate. For example, an initial dependency effect can change that bit between the gate and the merge.

This metadata write occurs before the value-producing call. At this stage, the function has not directly replaced the destination’s first word.

### Nonzero-source path: value-producing call

The function next calls F-7129d6a8d912 with:

1. The original opaque 32-bit context.
2. A newly read source first word.
3. A newly read source metadata word, interpreted as unsigned 32-bit data and logically shifted right by one.

The third argument ranges from zero through 2,147,483,647 inclusive. No multiplication, addition, or quantity scaling is shown.

The source-derived arguments are read after the destination metadata merge. They are not guaranteed to match the earlier branch selector or the metadata used in that merge. In particular, overlap can make the preceding destination write alter a subsequent source read.

The relative evaluation order of the two source-derived arguments is not established. Both are obtained before the dependency is invoked.

A zero decoded quantity does not suppress the call. Once the nonzero-source branch is selected, the function does not recheck whether the subsequently read source value is nonzero.

### Nonzero-source path: result and final metadata update

If F-7129d6a8d912 returns normally, its 32-bit result is written to the destination’s first word.

The function then reads destination metadata again and writes it back with bit 0 forced to one. The other 31 bits come from this post-call read, not from a saved copy of the earlier merge.

Consequently, changes made to destination metadata by F-7129d6a8d912 can survive the final update, except that bit 0 is forced on.

There is no result validation. A zero result is stored and followed by the same final metadata update as any nonzero result.

## Side effects

### Direct write order

The zero-source path performs one direct write: zero to the destination value.

The nonzero-source path performs three direct writes, in order:

1. Merged destination metadata.
2. The returned destination value.
3. Destination metadata with bit 0 set.

This is not an atomic replacement of the two-word descriptor. F-7129d6a8d912 is invoked after the first write but before the remaining two.

The function contains no direct write through the source argument. This does not imply that source-visible storage remains unchanged: destination writes can affect it through overlap, and dependency effects are unknown.

### Exact descriptor coincidence

When source and destination addresses are identical, the outcome must still be divided by the source branch decision.

**Nonzero-source case:** Assume the shared first word is nonzero at the post-cleanup branch decision, dependencies leave descriptor storage unchanged, and all accesses and dependency arguments remain valid.

Under these assumptions:

- The initial metadata merge reproduces the shared metadata word: its low bit and upper bits come from that same word.
- F-7129d6a8d912 receives the shared first word and the shared metadata logically shifted right by one.
- Its result replaces the shared first word.
- The shared metadata ends with bit 0 set.

These observations do not establish lifetime safety. If F-94cb53877c15 ran, it did so before F-7129d6a8d912 received the source value. Unchanged descriptor bits do not prove that a resource represented by those bits remains valid.

**Zero-source case:** If the shared first word is zero at the post-cleanup branch decision, there is no metadata merge and no call to F-7129d6a8d912. The function writes zero to the shared first word and does not directly change shared metadata.

Thus, with both shared words initially zero and no dependency effects, both remain zero. The low bit is not forced on.

If shared metadata initially has bit 0 set, F-94cb53877c15 is called first, even when the shared first word is zero. Subsequent branch selection and final metadata depend on any effects of that call.

### Partial overlap

No overlap check or snapshot protects later source reads.

For example, if the destination metadata word occupies the same storage as the source’s first word, the nonzero-source metadata merge can change the source value later supplied to F-7129d6a8d912. The earlier nonzero branch decision does not constrain that later value to remain nonzero.

No general overlap-safe copying guarantee is established. Whether such overlapping descriptors are valid inputs under the surrounding environment is documented_only.

### Ownership and external state

The destination low bit controls one dependency call and is forced on after a normal return from the nonzero-source path. This suggests a cleanup or ownership convention, but does not establish one.

Specifically, the evidence does not prove that:

- F-94cb53877c15 releases a resource or safely accepts zero.
- F-7129d6a8d912 allocates, duplicates, retains, or transfers a resource.
- The returned value is independent of the source value.
- Either dependency preserves globals, descriptor storage, or referenced resources.

No broader ownership or lifetime guarantee follows from the metadata operations alone.

### Errors and interrupted execution

There is no explicit error result, recovery path, rollback, or dependency-result check.

If F-94cb53877c15 does not return normally, the shown flow does not reach source inspection or any direct descriptor write.

If F-7129d6a8d912 does not return normally, the metadata merge has already occurred, but the result store and final low-bit update are not reached.

Invalid-access behavior and dependency-specific failure mechanisms are not established.

## Acceptance examples

Given destination metadata `0x2468ACE0` and source first word zero:

- Neither dependency is called.
- Destination first word becomes zero.
- Destination metadata remains `0x2468ACE0`.
- Source metadata is not directly read.

### Zero source, set destination low bit

- After its normal return, destination first word becomes zero.
- Destination metadata remains `0x00000009`.
- F-7129d6a8d912 is not called.

- F-94cb53877c15 is skipped.

- F-7129d6a8d912 receives the original context, `0x12345678`, and quantity 5.

The source’s clear low bit does not clear the destination’s low bit.

### High-bit values and zero quantity

A source first word of `0x80000000` selects the nonzero-source path.

With source metadata `0xFFFFFFFF`, the decoded quantity is `0x7FFFFFFF`, or 2,147,483,647. It is not a negative or sign-extended result.

With source metadata `0x00000001`, the decoded quantity is zero, but F-7129d6a8d912 is still called. If it returns zero, the destination value becomes zero and destination metadata bit 0 is still set.

### Exactly coincident zero descriptors

Given identical source and destination addresses with both shared words zero:

- The initial dependency is skipped.
- The source branch selects the zero-source path.
- The first shared word is written as zero.
- The shared metadata remains zero.
- F-7129d6a8d912 is not called.

There is no metadata merge or final low-bit-setting operation.

### Exactly coincident nonzero descriptor

- The metadata merge leaves `0x0000000A`.
- F-7129d6a8d912 receives the context, `0x12345678`, and quantity 5.

This expectation assumes valid dependency inputs and no dependency modification of descriptor storage.

### Dependency mutation of metadata

The function does not restore the metadata previously derived from the source.
