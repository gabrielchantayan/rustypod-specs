## Behavior

The returned integer is classified only as **zero** or **nonzero**. Its magnitude and sign do not otherwise affect the decision. Negative values and positive values both select the nonzero branch.

This dispatch occurs before either named dependency is called. The visible body does not re-read the dispatch entry or repeat the initial call.

### Zero-result branch

When the initial dispatch returns zero, the function calls F-6a21f4f07f67 with the original object-reference value.

The returned unsigned value is used as a record address. The function first reads the byte at offset 0x25 and compares it with zero.

- If that byte is **nonzero**, the function reduces the input integer by one and returns the result. It does **not** read the byte at offset 0x26.
- If that byte is **zero**, the function reads the byte at offset 0x26.
  - A zero second byte causes the input integer to be returned unchanged.
  - A nonzero second byte causes the input integer to be reduced by one.

The second byte is interpreted as an unsigned byte when promoted for comparison. Its possible numeric values are therefore 0 through 255 under the apparent eight-bit-byte model. The first byte is used only for zero testing, so its signedness does not affect branch selection.

The decrement is applied **at most once**. A nonzero first byte is sufficient to select it; the second field is neither needed nor inspected in that case.

F-eaea3d854c70 is not called on this branch.

It then adds two to the returned signed integer and returns that sum.

On this branch:
