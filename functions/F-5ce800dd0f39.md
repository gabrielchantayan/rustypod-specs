# F-5ce800dd0f39

## Purpose

Those values come from seven global storage locations, with two values retained locally for reuse across later dispatches.

The established behavior is the dispatch sequence and its data dependencies. The meaning of the dispatched operation and the global values is unknown. In particular, the available evidence does not establish that the operations register entries, set properties, acquire resources, or perform any other domain-specific action.

The final dispatch has a control-flow recovery limitation. The supplied representation treats it as a call followed by return, while its annotation reports an indirect jump. This contract distinguishes the represented dispatch sequence from uncertainty about the final transfer’s return mechanics.

### Retained values versus fresh reads

The retained G-A value is obtained before dispatch 1. Dispatch 1’s second argument is shown as a separate read of G-A rather than a use of that retained value. Dispatch 3 uses the retained value.

Similarly, the retained G-B value is obtained only after dispatch 1 returns and before dispatch 2. Dispatch 2’s second argument is shown as a separate read of G-B. Dispatches 4 and 5 use the retained value.

This distinction matters if global storage can change between reads. With stable ordinary storage, the retained value and its corresponding immediately following argument read agree. The evidence does not establish synchronization, volatile access semantics, atomicity, or the legality of concurrent mutation, so it does not justify a general concurrency guarantee.

The capture timing also matters without concurrency:

- Dispatch 1 may change G-B before the function retains it.
- Dispatch 1 may change G-A, but that does not replace the value already retained for dispatch 3.
- Dispatch 2 may change G-B, but that does not replace the value already retained for dispatches 4 and 5.

This describes the function’s explicit dataflow. It does not assume that an unknown target has any particular preservation behavior beyond what is necessary for normal execution under the calling convention.

### Per-dispatch observation points

G-1 through G-5 are each read for their corresponding dispatch. They are not all captured at function entry. A preceding target can therefore affect a later dispatch by changing one of these locations before it is read.

The receiver’s dispatch-table base and the target at offset 0x58 are likewise resolved for each dispatch. A normally returning target may change the receiver’s initial field or the contents of its dispatch table. If it does, a later dispatch can select a different target.

The receiver pointer value passed to each dispatch remains the function’s input pointer. A change to the receiver’s contents is distinct from replacing that pointer.

The supplied representation does not establish a strict evaluation order among the target lookup and the separate argument reads within one dispatch expression. The contract therefore establishes stage ordering across calls, but does not require a particular within-stage ordering of those reads. It also does not guarantee an exact machine-load count.
