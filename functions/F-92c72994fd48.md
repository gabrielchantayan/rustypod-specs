# F-92c72994fd48

## Purpose

F-92c72994fd48 performs up to three conditional preliminary actions for a supplied record, then conditionally updates accounting state and processes allocation metadata.

The established sequence is:

1. Perform preliminary dependency calls selected by record fields.
2. Check whether further processing is disabled or the allocation reference is null.
3. Adjust the allocation address, read an accounting amount, update two accounting words, and invoke F-2fd8826557a4.
4. Unless the adjusted address is the distinguished value `8`, validate a header, update allocator-related counters, and invoke further dependencies.

“Cleanup,” “allocation,” and “allocator” describe inferred roles. The visible accesses, arithmetic, calls, and branches establish behavior; they do not independently establish ownership transfer, memory release, or synchronization semantics.

## Behavior

### Preliminary actions

A null record returns before any other visible access or dependency call.

For a nonnull record, the function performs these actions in order:

1. Read the 32-bit field at record offset `0x00`; invoke F-2106ab1fda38 if nonzero.
2. Read the 32-bit field at record offset `0x30`; invoke F-7446dea3e07b if nonzero.
3. Read the 32-bit field at record offset `0x60`. If nonzero:
   - Read the table address from record offset `0x64`.
   - Write byte value `1` at context offset `0x101`.
   - Read the call target from table offset `0x1C` and invoke it.
   - If it returns normally, write byte value `0` at context offset `0x101`.

The table address is captured before the marker write. The target entry is read afterward, so aliasing or other changes affecting the table entry can matter.

The marker is replaced, not saved and restored. Normal completion of the indirect call is followed by a zero write regardless of the marker’s original value or changes made by that call. No marker restoration is shown for a nonlocal exit or a call that never returns.

The three selector reads occur sequentially. Earlier dependencies may change fields tested later. None of these calls has explicit arguments in the supplied representation; that does not establish the absence of implicit calling-convention inputs.

### Release gating and metadata discovery

After preliminary actions finish, read the accounting-state global and retain its value as the **initial accounting-state address**. This capture occurs even when a later gate causes an immediate return.

Next, read the byte at record offset `0x1F`:

- Nonzero: return.
- Zero: continue.

This flag does not suppress preliminary actions or the initial accounting-state capture.

Read the 32-bit allocation reference at record offset `0x38`:

- Zero: return.
- Nonzero: continue.

Call the nonzero reference **P**. Read a 32-bit adjustment at **P − 4**, and obtain **B**, the adjusted allocation address, by subtracting that adjustment from P.

Read the 32-bit accounting amount **S** at **B − 8**.

These address calculations have 32-bit width. No checked subtraction or rejection of wrapped addresses is shown. The accounting amount is read before any header-validity check.

### Accounting access order and arithmetic

The accounting update is not a single captured-state operation. It uses four separate evaluations of the accounting-state global: the initial capture described above, followed by three evaluations after S is read.

The complete established order is:

1. Retain the initial accounting-state address captured before the record-flag check. Its offset `0x3C` will be the high-word destination.
2. After reading S, evaluate the accounting-state global again and read the 32-bit word at that address plus `0x38`. Call this captured value **L**.
3. Evaluate the accounting-state global again and capture the address at that value plus `0x3C`. This is the **high-word source address**. Do not read its word yet.
4. Evaluate the accounting-state global again to select the low-word destination at that value plus `0x38`.
5. Write **L − S**, retaining the low 32 bits, to that low-word destination.
6. Only after that write, read the 32-bit word at the previously captured high-word source address. Call the value read at this time **U**.
7. Write the high-word result to the initial accounting-state address plus `0x3C`.

There is no further evaluation of the accounting-state global to obtain U. The high-word source address was captured before the low-word store, but its contents are read afterward. Consequently, U is not an entry-time or pre-store snapshot.

The high-word result is:

**U − (sign contribution + borrow), modulo 2³²**, where:

- **borrow** is `1` if unsigned L is less than unsigned S, otherwise `0`;
- **sign contribution** is `0` when S has bit 31 clear and `−1` when S has bit 31 set.

With a stable accounting-state address and noninterfering storage, the two words behave as subtraction of a sign-extended 32-bit S from a two-word quantity. They do not implement unsigned 64-bit subtraction of S for every possible S.

The source and destination addresses need not coincide if the global changes between evaluations. Aliasing also matters: if the low-word destination overlaps the captured high-word source, the subsequent read of U observes storage after the low-word write. The borrow still uses captured L and S; it is not recomputed from destination contents.

After both accounting writes, invoke F-2fd8826557a4. Header validation has not yet occurred.

### Allocator-state capture and distinguished address

After F-2fd8826557a4 returns, read an allocator-state address through a separate global reference. Call the captured address **A**.

If B equals `8`, return without header validation, allocator-counter updates, or further allocator dependency calls.

This exception applies to B, not P. It occurs after:

- Reading the adjustment at P − 4.
- Reading S at B − 8.
- Updating the accounting words.
- Calling F-2fd8826557a4.
- Capturing A.

Thus, B equal to `8` does not bypass the earlier read at address zero implied by B − 8.

### Header validation

For B other than `8`, define the header address **H = B − 0x10**.

First read the 32-bit word at H:

- If zero, invoke nonreturning F-a817d8d58c10.
- Otherwise, read the header word again and test bit 0. If that bit is set, invoke F-a817d8d58c10.

The nonzero check and bit test use separate reads. Under changes between reads, they need not inspect the same value. No subsequent requirement that the header remain unchanged is established.

On this function’s validation-failure path, no direct allocator-counter update described below has occurred. Preliminary calls, accounting writes, and F-2fd8826557a4 have already occurred, however, and are not rolled back.

After successful validation, invoke F-c0fc6d033caa with A.

### Allocator bookkeeping

If F-c0fc6d033caa returns, perform the following sequence. A remains the captured allocator-state address; changes to its originating global do not redirect these accesses.

1. Read an unsigned 16-bit first index at B − `0x0C`.
2. Read the 32-bit header at H and mask it with `0x3FFFFFFC`. Call the captured result **Q**.
3. Read and update the 32-bit counter at **A + `0x224` + 4 × first index**, subtracting Q.
4. Read and update the 32-bit counter at **A + `0x30C`**, subtracting Q.
5. Read an unsigned 16-bit second index at B − `0x0A`.
6. Read and update the 32-bit counter at **A + `0x0E0` + 4 × second index**, subtracting Q.
7. Read and update the 32-bit counter at **A + `0x220`**, subtracting Q.
8. Invoke F-09dcb55e8e0a and use its 32-bit result as a third index.
9. Read and decrement the 32-bit counter at **A + `0x310` + 4 × third index**.
10. Read and decrement the 32-bit counter at **A + `0x390`**.
11. Read the header at H again, mask this fresh value with `0x3FFFFFFC`, and subtract that quantity from the 32-bit counter at **A + `0x08`**.
12. Invoke F-cc6c9b4a0f68 with A and H.
13. If it returns, invoke F-e586bff64fb7 with A.

Each update uses the counter contents at that operation, not a snapshot of all counters before bookkeeping. Overlapping counter locations can therefore accumulate multiple updates.

All counter results retain 32 bits. No saturation or underflow rejection is shown. Address calculations likewise have no visible overflow checks.

The first two indices are zero-extended from 16 bits; their fourfold offsets range from zero through `0x3FFFC`. The third index has no visible range or sign check.

The mask retains bits 2 through 29. Q is a multiple of four from zero through `0x3FFFFFFC`. A header can pass the visible validation and still produce Q equal to zero.

The first four quantity deductions share captured Q. The deduction at A + `0x08` uses a later header read, after F-09dcb55e8e0a and both count decrements. Neither that dependency nor earlier writes are assumed to preserve the header.

## Acceptance examples

These are conditional criteria from static evidence, not executed tests.

1. **Null record.** A null record returns without preliminary calls, context-marker accesses, or accounting-global reads.

2. **Blocked processing.** If all preliminary selectors are nonzero when read and the calls return, the two direct preliminary calls and indirect call occur in order. A subsequently nonzero byte at record offset `0x1F` causes return after the initial accounting-state capture, without reading the allocation reference.

3. **Null allocation reference.** With a zero blocking flag and zero reference at offset `0x38`, the initial accounting-state capture occurs, but adjustment metadata and S are not read and no accounting store occurs.

4. **Marker replacement.** If the marker starts at `7` and the selected indirect call returns, the function writes `1` before invocation and `0` afterward, not `7`.

5. **Stable-state borrow.** With stable accounting-state addressing, noninterfering storage, L equal to `3`, S equal to `5`, and U read as `10`, the low result is `0xFFFFFFFE` and the high result is `9`.

6. **High-bit amount.** Under the same stability conditions, L equal to `0xFFFFFFFF`, S equal to `0x80000000`, and U read as `10` produce low `0x7FFFFFFF` and high `11`.

7. **Post-store high-word read.** Suppose L is `3`, S is `5`, and the selected low-word destination is exactly the captured high-word source location. With no intervening modification, the low store writes `0xFFFFFFFE`; U is then read as `0xFFFFFFFE`, regardless of that location’s earlier contents. The high result written through the initial state address is `0xFFFFFFFD`.

8. **Changed accounting-state global.** If the four global evaluations yield different state addresses, the initial address selects only the high destination; the next selects L’s source; the next selects the captured high source; and the last selects the low destination. Changing the global after the low store does not redirect the pending U read.

9. **Distinguished address.** If suitable earlier accesses produce B equal to `8`, accounting and F-2fd8826557a4 still occur, followed by allocator-state capture. Header checks and remaining allocator operations do not occur.

10. **Validation failure.** A zero first header read, or a nonzero first read followed by an odd second read, invokes F-a817d8d58c10 after accounting. No rollback is provided.

11. **Zero quantity.** If the relevant header reads yield `2` and dependencies preserve relevant metadata, validation succeeds and quantity deductions subtract zero. Both count decrements and final dependency calls still occur.

12. **Changed final quantity.** If F-09dcb55e8e0a changes the header, the final deduction uses its later masked value. The four preceding deductions retain captured Q.
