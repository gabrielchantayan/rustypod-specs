# F-e6a26463de68

## Purpose

F-e6a26463de68 selects one byte from each complete four-byte group of an input region, accumulates the selected bytes into blocks of at most 64 bytes, and submits those blocks to F-c20ae87ac99e.

Selection is controlled by an evolving 32-bit state. Successful completion commits a further transformation of that state to caller-supplied storage. A nonzero result from a full-block submission terminates processing without that final state write. A result from a partial-block submission is discarded.

The apparent intent is state-driven byte selection with buffered delivery. The available evidence does not establish that the state is random, that the dependency writes to a particular destination, or that delivery is transactional.

## Interface

The function has four inputs and an integer return value:

| Input | Representation | Role |
|---|---|---|
| State storage | Pointer to an integer word | Read once at entry; written once on normal completion |
| Remaining input extent | Unsigned 32-bit integer | Number of input bytes available for processing |
| Auxiliary value | Signed integer, apparently 32 bits | Assigned internally but has no established effect on observable behavior |
| Input address | Integer-form address, apparently 32 bits | Base address of the first four-byte group |

The observed representation uses 32-bit arithmetic and addresses. The exact original language-level types and signed-overflow rules are not established. Arithmetic described below as modulo \(2^{32}\) specifies the apparent target-level word behavior, not a guarantee about portable signed-language evaluation.

### Required storage

The state pointer must identify readable storage for the entry read. On any path that reaches normal completion, that same address must also support the final word write.

The input must support each selected byte read. For an extent \(L\), the function considers

\[
N=\left\lfloor L/4\right\rfloor
\]

four-byte groups. It reads exactly one byte from each group that it reaches, unless processing terminates earlier following a full-block submission.

The implementation does not visibly validate pointers, address ranges, alignment, or overlap. Callers must provide storage compatible with the target platform’s access requirements.

### Return value

Under ordinary returning execution:

- Normal completion returns zero.
- A nonzero result from a 64-byte submission is returned unchanged.
- A result from a submission shorter than 64 bytes is ignored, including a nonzero result.

No explicit error code is produced for an invalid address, inaccessible memory, arithmetic fault, or dependency failure that does not return normally.

## Behavior

### State parameters and arithmetic

Five global scalar values participate in the state transformations. Their numeric values are not supplied. For this contract, they are identified by role:

- **Entry multiplier**
- **Entry addend**
- **Selection multiplier**
- **Commit multiplier**
- **Commit addend**

These names describe operands, not additional interface arguments.

Let the entry state word be \(S\). Before checking whether any complete input group exists, the function establishes a working state:

\[
W=(\text{Entry multiplier}\times S+\text{Entry addend})\bmod 2^{32}.
\]

For each selected input byte, it first updates the working state:

\[
W=(W\times\text{Selection multiplier}+40263)\bmod 2^{32}.
\]

The fixed addend is hexadecimal 9D47, or decimal 40263.

The byte position within the current four-byte group is then:

\[
J=(W\mathbin{\&}127)\mathbin{\gg}5.
\]

Consequently, \(J\) is always 0, 1, 2, or 3. Bits 5 and 6 of the updated state determine the selected position; the lower five bits do not affect that position.

On normal completion, the state word is replaced by:

\[
S_{\text{new}}=(W\times\text{Commit multiplier}+\text{Commit addend})\bmod 2^{32}.
\]

The final transformation also occurs when the input extent is less than four bytes. In that case, no per-byte state update occurs, but both the entry transformation and the final transformation still occur.

### Entry and empty-input behavior

The state word and the entry transformation operands are read before the function checks the input extent. Thus an extent of zero does not make the state pointer optional.

The selected-byte buffer initially contains zero valid bytes. If fewer than four input bytes remain:

1. No input byte is read.
2. If the buffer contains pending selected bytes, those bytes are submitted.
3. The final state transformation is written to caller storage.
4. The function returns zero.

For an initial extent of zero through three, the buffer is empty, so the dependency is not called.

The relative evaluation order of the independent operands used in a single arithmetic expression is not established. In particular, the evidence does not justify an exact order among the initial state-word read and the two entry-operand reads.

### Processing each complete group

For every reached group having at least four remaining bytes, the observable sequence is:

1. Update the working state using the selection multiplier.
2. Derive a byte position from the updated state.
3. Read one byte at the current input address plus that position.
4. Store that byte at the next position in the local selected-byte buffer.
5. If this fills the buffer to 64 bytes, submit the buffer.
6. Decrease the remaining extent by four and advance the input address by four.
7. Continue, or terminate if that full-block submission returned nonzero.

There is no visible four-byte load. The other three bytes in a group need not be read by this function.

The remaining-extent subtraction is performed only after the extent has been found to be at least four, so it does not underflow. The local buffer index remains within 0 through 63 on ordinary control flow.

The input-address advancement also occurs for the group that triggers a nonzero full-block result, before the function returns. This changes only a local address value, not a caller-owned pointer. Address overflow behavior is not separately validated.

### Full-buffer submissions

Each full submission calls F-c20ae87ac99e with:

- A count of 64.
- A pointer to the local buffer containing the 64 selected bytes in input-group order.

If the result is zero, the buffer’s logical count becomes zero and processing continues.

If the result is nonzero:

- That result becomes the function’s return value.
- No later input group is read.
- No partial-buffer submission follows.
- The function does not perform its final write to the state word.

The absence of the final state write does not undo any changes already made by the dependency.

### Final partial submission

Once fewer than four input bytes remain, any pending buffer prefix is submitted with its actual count, from 1 through 63.

The return value of this submission is discarded. The function proceeds to the final state transformation and returns zero even if this dependency call returns a nonzero value.

Only the indicated prefix is logically supplied as output. There is no established terminator, padding convention, or guarantee concerning bytes beyond that count.

If the number of processed groups is an exact multiple of 64, no additional zero-length submission occurs.

### Global changes during dependency calls

The global operands are not all captured as one entry-time snapshot.

- The entry transformation is completed before any dependency call.
- The selection multiplier is used afresh for each selected byte.
- The commit operands are used when normal completion reaches the final transformation.

Therefore, if F-c20ae87ac99e changes the selection multiplier, later selected bytes can be affected. If it changes the commit operands, the final state value can be affected.

The working state is not reloaded from caller storage after a dependency call. A dependency mutation of the stored state does not replace the working state. On normal completion, the final write can overwrite such a mutation.

## Side effects

The function itself has the following established memory effects:

- One entry read of the caller-supplied state word.
- Reads of the global transformation operands at their respective use sites.
- One selected input-byte read per processed group.
- Writes into a local 64-byte buffer.
- Dependency calls for complete blocks and, when present, the final partial block.
- One final state-word write on normal completion.
- No final state-word write after a nonzero full-block result.

There is no visible allocation, deallocation, or direct write to the input region.

The buffer is local to the invocation. Its address is exposed to F-c20ae87ac99e during calls and reused across submissions. This function does not establish any ownership transfer or permission to retain that address after return. Whether the dependency copies, modifies, retains, or otherwise acts on the buffer is unknown.

The state word is not checkpointed after each successful full submission. Consequently, an invocation may submit one or more blocks and then return a later full-block error without recording its final working state. Previously submitted effects are not rolled back.

Overlap is not explicitly rejected. If the state word overlaps input storage, the function’s own final state write occurs after its input reads have finished on normal completion. Dependency writes to overlapping storage, or changes by external actors, can affect subsequent reads and cannot be assumed absent.

## Acceptance examples

These examples are conditional on valid memory, ordinary dependency returns, and the stated arithmetic model. Exact selected byte values require the actual global operands and initial state.

### Extent below one group

For an extent of 0, 1, 2, or 3:

- No input byte is read.
- No dependency call occurs.
- The entry transformation is followed by the commit transformation.
- The transformed state is written.
- The result is zero.

An invalid state pointer is not made safe by this extent.

### One group and ignored partial error

For an extent of 4 through 7:

- Exactly one byte is selected from positions 0 through 3.
- The dependency is called once with count 1.
- If that call returns a nonzero value, the function nevertheless commits the state and returns zero.

The last zero through three input bytes are not processed.

### Exactly one full block

For an extent of 256 bytes:

- Exactly 64 bytes are selected, one from each consecutive four-byte group.
- The dependency is called once with count 64.
- On a zero result, the state is committed and the function returns zero.
- On a nonzero result, that result is returned and this function does not write the state word.
- No trailing zero-length call occurs in either case.

### Full block followed by a partial block

For an extent of 260 bytes, if the first dependency call returns zero:

- The first call contains 64 selected bytes.
- One further byte is selected from the group beginning at input offset 256.
- A second call has count 1.
- The second call’s result is ignored.
- The state is committed and the function returns zero.

If the first call returns nonzero, the group beginning at offset 256 is not read and the second call does not occur.

### Global mutation between blocks

For an input requiring more than 64 selections, suppose the first full-block call returns zero and changes the selection multiplier. The next selection uses the changed multiplier with the already accumulated working state. The function does not restart from the caller’s stored state.

### Auxiliary-value independence

For two otherwise identical invocations, changing only the auxiliary integer does not alter the established byte selections, submission counts, state transformation, or return handling. Internal assignments involving that input do not affect the controlling decisions.
