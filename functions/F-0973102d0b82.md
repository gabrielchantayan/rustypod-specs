# F-0973102d0b82

## Purpose

F-0973102d0b82 conditionally stores a 32-bit integer in the first zero-valued slot within a descriptor’s scanned range. It first rejects any value already present in that range. If two descriptor fields compare equal, it invokes F-b1555bc29718 before searching for a zero slot.

The behavior is not a conventional append operation:

- Duplicate detection returns −1 without directly modifying the descriptor or its backing storage.
- Finding a zero slot causes a descriptor field to be incremented and the candidate to be written into that slot.
- Finding no zero slot returns −1 without directly storing the candidate.
- The field controlling the scanned range is not directly incremented.
- The dependency can run even when the function ultimately returns −1.

The interpretation of zero as an available slot is inferred from the search and replacement behavior. Names such as “capacity,” “length,” or “growth” are not established by the available evidence.

## Interface

### Inputs

The function receives two arguments:

1. **Descriptor address.** An address permitting access to at least three consecutive 32-bit integer fields.
2. **Candidate.** A 32-bit integer compared with slot contents and, on a successful slot search, stored unchanged.

The descriptor layout is:

| Byte offset | Field | Observed role |
|---|---|---|
| 0 | Backing-address field | Supplies the address used to access slots. |
| 4 | Scan-bound field | Controls the duplicate scan and, after a possible dependency call, determines the extent of the zero-slot scan. |
| 8 | Equality/counter field | Compared with the scan-bound field to decide whether to invoke the dependency; incremented when a zero slot is selected. |

Slots are four bytes apart and are accessed as 32-bit integers. Slot zero begins at the address supplied by the backing-address field.

The supplied representation uses a 32-bit integer as an address-bearing field. Native pointer size, address-space mapping, alignment requirements, and the validity of converting that field to an address are target-dependent and are not independently established.

### Output

The result is a signed integer:

- **−1:** Either the candidate was found during duplicate detection, or no zero slot was found during the subsequent search.
- **A nonnegative index:** The zero-based index selected by the zero-slot search and used for the candidate store.

The same failure result therefore covers two materially different paths, one of which can invoke the dependency.

### Preconditions for defined ordinary operation

The following conditions are necessary for the straightforward behavior described below:

- The descriptor is readable wherever its fields are examined.
- Any directly modified descriptor field is writable.
- Every slot actually read is accessible as a 32-bit integer.
- A selected slot is writable.
- Address calculations and signed integer arithmetic remain valid in the execution environment.
- The descriptor and storage are not concurrently modified in ways that invalidate the reads or accesses.

The function does not validate these conditions. No bounds error, invalid-pointer result, or arithmetic-error result is established.

A negative scan-bound field is not explicitly rejected. Its observable control-flow consequences are described below; it is not thereby established as a supported descriptor state.

## Behavior

### 1. Duplicate detection

The function scans from index zero upward while the index is less than the descriptor’s scan-bound field.

For each examined index, it obtains the slot address from the backing-address field and reads the corresponding 32-bit slot. It compares the slot with the candidate.

On the first equality, the function immediately returns −1. It does not proceed to the descriptor-field equality check, invoke F-b1555bc29718, or perform its own descriptor or slot writes.

The scan-bound field is consulted as the loop proceeds; it is not initially captured as a single fixed bound. The backing-address field is also used during individual slot accesses. Consequently, a fixed scan range and fixed backing array require stable descriptor contents during this phase.

If the scan-bound field is zero or negative when the initial loop condition is evaluated, no slot is read by this phase.

### 2. Conditional dependency invocation

After duplicate detection finishes without a match, the function compares the equality/counter field with the scan-bound field.

If they are equal, it calls F-b1555bc29718 with the descriptor address. If they are unequal, it does not call that dependency.

There is no explicit check of a dependency return value. If the dependency returns normally, execution continues using descriptor contents available afterward. In particular, the function does not establish that the backing address, scan bound, or equality/counter field retains its earlier value.

Duplicate detection is not repeated after the dependency returns. Thus, if the dependency introduces the candidate into the scanned storage, this function does not independently reject that newly introduced duplicate before storing into a zero slot.

### 3. Zero-slot search

After the optional dependency call, the function reads the scan-bound field and captures it for the second scan.

It examines slots in increasing index order, starting at zero and stopping before that captured bound. Each examined slot is read as a 32-bit integer through the descriptor’s backing-address field.

The search selects the first slot equal to zero. If no such slot is encountered, its search result is −1.

For a captured bound of zero or less, this search performs no slot reads and produces −1.

The second scan does not search for the candidate. Its only slot-content criterion is equality to zero.

### 4. State update for a selected slot

For an ordinarily completed search that selected a slot, its index is nonnegative and strictly less than the captured scan bound. Under those conditions, the function:

1. Reads the descriptor’s current equality/counter field.
2. Adds one and writes the result back to that field.
3. Reads the descriptor’s backing-address field.
4. Stores the candidate at the selected four-byte slot offset.
5. Returns the selected index.

The equality/counter update precedes the candidate store. The backing-address read used for the store occurs after that field update.

The function does not directly change the scan-bound field. It also does not shift existing slots, compact the range, or directly initialize other slots.

If the search result is −1, these direct updates are skipped and the function returns −1.

The supplied control flow also excludes updates for a selected index equal to the captured bound. An ordinary successful search cannot produce that index because the search stops before the bound.

### Zero candidate

Zero has a special interaction with the two scans:

- If the initial duplicate scan encounters any zero slot, a zero candidate is rejected immediately with −1.
- With stable storage and no dependency-induced change, a zero candidate cannot both pass duplicate detection and subsequently find a zero slot.
- If the dependency introduces a zero slot after duplicate detection, the second scan can select it. The function then increments the equality/counter field, writes zero into the already-zero slot, and returns its index.

No explicit nonzero-candidate precondition or rejection rule exists.

## Side effects

### Direct effects

On a successful zero-slot search, the function directly performs:

- One incrementing write to the equality/counter field.
- One candidate write to the selected slot.

On duplicate rejection, it performs neither write and does not invoke the dependency.

On a no-zero result, it performs neither direct write, but dependency effects may already have occurred.

### Ordering and partial effects

The equality/counter write precedes the selected-slot write. The operation is not shown as transactional.

If an access fault or other execution failure occurs after the counter write but before the candidate store completes, there is no established rollback. This is an ordering consequence, not a documented error-handling mechanism.

The description establishes phase order and the explicit write-before-store relationship. It does not establish a total machine-level ordering for every pair of field reads occurring within one expression.

### Ownership and aliasing

The function itself contains no explicit allocation, release, or ownership-transfer operation. It does not establish who owns the descriptor or backing storage.

F-b1555bc29718 may have ownership or allocation effects; those are unknown.

No non-aliasing checks are shown. If backing storage overlaps the descriptor, a slot write can also modify descriptor fields. Likewise, because the backing-address field is read after the equality/counter update, overlapping or externally changing storage can affect the eventual store address. The ordinary collection-like interpretation therefore depends on a suitable storage layout; it is not a guarantee for arbitrary aliasing arrangements.

## Acceptance examples

These examples assume accessible storage, valid arithmetic, no concurrent mutation, and no descriptor/storage overlap. Dependency behavior is stated explicitly where relevant.

| Initial state and condition | Required observable result |
|---|---|
| Scan bound 3; slots `[7, 0, 9]`; candidate 9 | Return −1 during duplicate detection. Do not invoke the dependency or perform direct writes. |
| Scan bound 3; equality/counter 5; slots `[7, 0, 9]`; candidate 4 | Skip the dependency. Increment equality/counter to 6, write 4 at index 1, and return 1. Scan bound remains 3. |
| Scan bound 4; equality/counter 8; slots `[0, 6, 0, 8]`; candidate 3 | Select index 0, not index 2. Increment equality/counter to 9, write 3 at index 0, and return 0. |
| Scan bound 3; equality/counter 5; slots `[7, 8, 9]`; candidate 4 | Return −1 after searching all three slots. Perform no direct writes. |
| Scan bound 3; equality/counter 5; slots `[7, 0, 9]`; candidate 0 | Return −1 on the initial scan’s zero match. Leave the counter and slots unchanged. |
| Scan bound 0; equality/counter 2 | Read no slots, skip the dependency, and return −1. |
| Scan bound −2; equality/counter 0 | Read no slots, skip the dependency, and return −1. |

Additional conditional cases:

- **Dependency changes the search range:** Start with scan bound and equality/counter both 2, slots `[7, 8]`, and candidate 4. If the dependency returns with scan bound 3, equality/counter 2, and slots `[7, 8, 0]`, the function selects index 2, increments the equality/counter field to 3, stores 4 there, and returns 2.
- **Dependency leaves no available slot:** Under the same initial equality condition, if the dependency returns with no zero in the resulting scanned range, the function returns −1 without its own field or slot writes. Dependency side effects remain possible.
- **Dependency introduces a duplicate:** If the initial scan finds no candidate, but the dependency returns with slots `[4, 0]`, scan bound 2, and equality/counter 6, candidate 4 is written at index 1 and the counter becomes 7. The function does not repeat duplicate detection.
- **Dependency enables a zero candidate:** If an initially zero-length descriptor invokes the dependency and it returns with scan bound 1, equality/counter 0, and slot `[0]`, candidate zero produces counter 1, slot `[0]`, and result 0.
