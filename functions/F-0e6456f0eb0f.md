# F-0e6456f0eb0f

## Purpose

F-0e6456f0eb0f scans a caller-provided byte region and writes packed output into the beginning of that same region. Each eligible iteration obtains an unsigned value from F-c181a51d2f48. Values from 0 through 63 participate in packing; larger values do not. Four accepted values produce three output bytes. A partial group of two or three accepted values produces one or two bytes, respectively.

Scanning stops at either the effective scan bound or a byte equal to `0x3D` (“=”). The stopping “=” byte is not consumed by this function.

The packing and stopping rule resemble a Base64 decoder. That interpretation is **inferred intent**, not an established alphabet or validation contract. The supplied evidence does not establish how F-c181a51d2f48 obtains its value, nor whether that value corresponds to the byte currently being scanned.

## Interface

### Inputs

The function accepts:

- **Buffer address:** the start of the scanned region and the destination for packed output.
- **Requested scan bound:** an unsigned integer. A nonzero value is used directly. Zero requests an effective bound from F-1cb585febd84.

The bound limits scan iterations, not output bytes, accepted values, or complete groups.

There is no separate output buffer, capacity argument, error destination, or explicit decoding-policy argument.

### Integer and address model

The visible representation uses byte-sized storage, unsigned integer classification values and bounds, and signed integer address conversions for distance calculations.

The behavioral arithmetic below uses 8-bit bytes and the apparent 32-bit integer model:

- Bounds and classification results range from 0 through 4,294,967,295.
- Packing retains the low eight bits of each output-byte expression.
- The return value has a signed 32-bit representation.
- Scan distance is compared with the bound after conversion to unsigned.

The underlying type definitions and address-conversion rules are not supplied. The 32-bit model is supported by the visible address-to-integer operations but is not independently established by platform declarations. Behavior involving address truncation, address wraparound, or nonrepresentable signed address differences is **documented_only**.

### Return value

The function returns the distance between the final output position and the original buffer address, calculated through integer-converted addresses. In the ordinary, representable case, this is the number of bytes written.

The return value does not report:

- How many input positions were scanned.
- How many classification results were rejected.
- Whether termination occurred at the bound or at “=”.
- Whether an incomplete group remains.
- Whether the scanned data follows any particular alphabet.

A zero return can therefore represent several distinct outcomes, including no iterations, an immediate “=”, no accepted values, or exactly one accepted value.

## Behavior

### Effective bound

The function begins with the input position and output position both at the supplied buffer address. Its packing state is empty, and no output has been produced.

If the requested bound is nonzero, F-1cb585febd84 is not called.

If the requested bound is zero, F-1cb585febd84 is called once, before any scan-byte read. Its result becomes the unsigned effective bound. This function does not visibly pass the buffer address to that dependency.

Consequently, zero does not necessarily mean “scan nothing.” It means “obtain the bound from the dependency.” If the resulting effective bound is zero, no scan byte is read and F-c181a51d2f48 is not called.

### Scan and stop order

Before each possible iteration, the function first compares the unsigned scan distance with the effective bound.

If the distance is not below the bound, processing stops without reading the next byte.

If the distance is below the bound, the function reads the current scan byte:

- If it is `0x3D`, processing stops. The position is not advanced, no classification call is made for that byte, and no padding-specific validation occurs.
- Otherwise, the scan position advances by one byte, and F-c181a51d2f48 is called once.

This order is observable. The classification dependency runs only after the current byte has passed the “=” check and the scan position has advanced.

No explicit argument carries that byte or either buffer position to F-c181a51d2f48. Its input mechanism is unknown.

### Classification results

The result of F-c181a51d2f48 is interpreted as unsigned:

- Values **0 through 63** are accepted.
- Values **64 and above** are ignored for packing.

An ignored value still consumes one scan iteration. It causes no direct output write and does not reset or advance the packing state. Accepted values separated by ignored values therefore remain part of the same group.

The function does not itself check whether the scanned byte is a letter, digit, whitespace, a NUL byte, or another character. Apart from `0x3D`, scanned byte values do not directly select a visible branch. Any further classification policy belongs to the dependency and is unknown here.

### Packing accepted values

Packing proceeds over accepted values, independently of how many scan positions were required to obtain them.

For four consecutive accepted values denoted \(a,b,c,d\), each in the range 0–63, the output bytes are:

\[
\begin{aligned}
\text{first byte} &= (a \times 4)\ \mathbin{\mathrm{OR}}\ \left\lfloor b/16 \right\rfloor,\\
\text{second byte} &= ((b \times 16) \bmod 256)\ \mathbin{\mathrm{OR}}\ \left\lfloor c/4 \right\rfloor,\\
\text{third byte} &= ((c \times 64) \bmod 256)\ \mathbin{\mathrm{OR}}\ d.
\end{aligned}
\]

These are byte results. The truncation in the second and third expressions is significant: bits above bit 7 are discarded.

Writes occur incrementally:

1. The first accepted value is retained; it produces no output.
2. The second accepted value produces the first byte.
3. The third accepted value produces the second byte.
4. The fourth accepted value produces the third byte and completes the group.

The next accepted value begins a new group.

Each output byte is written after the classification call that supplies the value needed to finish that byte. The output position advances only after that write.

### Partial groups and termination

Termination does not flush, reject, or otherwise process incomplete groups:

| Accepted values in the final group | Bytes already written for that group | Termination behavior |
|---|---:|---|
| 0 | 0 | No additional action |
| 1 | 0 | Retained value is abandoned |
| 2 | 1 | Existing byte is retained |
| 3 | 2 | Existing bytes are retained |

There is no check that unused low-order bits are zero. There is also no requirement for a second “=” byte or any particular amount of padding.

Ignoring address-representation issues, if \(n\) classification results are accepted before termination, the returned output count is:

\[
\left\lfloor \frac{3n}{4} \right\rfloor.
\]

No NUL terminator or other suffix is appended.

## Side effects

### Direct buffer effects

Output starts at the first byte of the supplied buffer and occupies a contiguous prefix.

The function’s own output writes cannot overtake its scan position: every write requires at least two accepted results, and every classification call requires a scan advance. Under ordinary address arithmetic, these writes therefore affect previously scanned positions rather than future positions.

This supports in-place packing, but does not establish safety against dependency side effects. A dependency may alter unread bytes, previously written output, or unrelated state.

Outside the produced prefix, the function performs no clearing or normalization. Remaining bytes retain their prior contents except for any dependency effects. A consumer must use the returned count rather than assume a terminated output string.

### Read, call, and write ordering

The established ordering is:

- Optional bound dependency call.
- Bound check.
- Current-byte read, only if the bound permits it.
- Stop on “=”, otherwise advance the scan position.
- Classification dependency call.
- Optional single-byte output write.
- Next bound check.

A dependency’s changes to buffer contents can affect later scan-byte reads. There is no visible snapshot of the input.

### State and errors

Packing state is local to the invocation. No persistent state update is directly visible.

There is no explicit error return or malformed-input status. Out-of-range classification results are skipped, incomplete groups are tolerated, and “=” terminates immediately.

Memory faults, dependency failures, nontermination, and nonrepresentable address arithmetic have no visible recovery path. Their platform-specific consequences are **documented_only**, not ordinary error behavior promised by this contract.

## Acceptance examples

The examples below assume representable address arithmetic and dependencies that return normally without invalidating the buffer or altering the relevant bytes unexpectedly. Classification sequences describe dependency results, not input-character mappings.

### Explicit bound and a complete group

Given:

- A requested bound of four.
- Four readable scan bytes, none equal to `0x3D`.
- Classification results of 19, 22, 5, and 46.

Expected behavior:

- F-1cb585febd84 is not called.
- F-c181a51d2f48 is called four times.
- The output prefix becomes `0x4D 0x61 0x6E`.
- The return value is 3.
- No terminating byte is appended.
- No fifth scan byte is read.

The result does not establish which input characters, if any, yield those classification values.

### Ignored result within a group

Given five eligible scan bytes and classification results of 19, 64, 22, 5, and 46:

- All five scan positions are consumed.
- The result 64 produces no write and leaves packing progress unchanged.
- The output is again `0x4D 0x61 0x6E`.
- The return value is 3.

The same skip behavior applies to any unsigned result above 63, including the maximum 32-bit unsigned value under the apparent integer model.

### Immediate “=”

Given a positive effective bound and a first byte of `0x3D`:

- The first byte is examined.
- No classification call occurs.
- No output byte is written.
- The return value is 0.

No subsequent byte is read to validate padding.

### “=” after two accepted values

Given an effective bound permitting at least three positions, two initial non-“=” bytes, a third byte of “=”, and classification results 19 and 22:

- Two classification calls occur.
- `0x4D` is written at the beginning of the buffer.
- The third byte stops scanning without a classification call.
- The return value is 1.

No additional output is produced on termination.

### Bound exhaustion during a partial group

With all scanned bytes different from “=”:

- One accepted result produces zero bytes.
- Two accepted results produce one byte.
- Three accepted results produce two bytes.
- Four accepted results produce three bytes.

These outcomes do not become errors merely because the bound ends the scan.

### Zero requested bound

- F-1cb585febd84 is called once.
- No buffer byte is read by this function.
- F-c181a51d2f48 is not called.

### NUL byte within the scan

- That byte does not directly terminate this function.
- The scan advances and a classification call occurs.
- Packing depends on the returned classification value.

Any string-length interpretation belongs to an unknown dependency, not to this visible stopping rule.
