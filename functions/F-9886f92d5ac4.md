# F-9886f92d5ac4

## Purpose

F-9886f92d5ac4 conditionally transfers 32-bit words from a selected record into caller-provided storage. A status field in that record controls whether another word may be transferred. The caller supplies a maximum transfer count, and the function reports the actual count through a separate output location.

The return value reports whether the low four status bits are zero at a final status observation. It does **not** directly report whether the requested number of words was transferred.

The supplied static representation establishes the accesses and decisions described below. Interpreting the record as a device, queue, or FIFO is plausible but unproven.

## Interface

The function has four inputs and one direct return value:

| Item | Contract |
|---|---|
| Record selector | Signed 16-bit integer used to select an entry through a global lookup root. |
| Destination | Address at which successive opaque 32-bit words are written. |
| Transfer limit | Unsigned 32-bit maximum number of words to transfer. |
| Count output | Address receiving the actual transfer count as an unsigned 32-bit value. |
| Return value | A 32-bit bit pattern: either `0x00000000` or `0xFFFFFF01`. |

`0xFFFFFF01`, if interpreted as a signed 32-bit two’s-complement integer, is −255. No symbolic error name or broader status-code convention is established.

### Lookup and record layout

The observed selection mechanism uses:

- A global lookup-root value.
- A selector stride of `0x18C` bytes, or 396 bytes.
- A 32-bit record-address value read from the beginning of the selected entry.

The selected entry is therefore located by applying the signed selector, scaled by 396 bytes, to the lookup root. The selector is not visibly converted into an unsigned index before this calculation.

The selected record exposes these fields:

| Offset from selected record | Width | Observed role |
|---|---:|---|
| `0x15C` | 32 bits | Source word read for each transfer. |
| `0x160` | 32 bits | Status word; only its low four bits affect control flow. |

These offsets identify accessed fields, not the complete record layout. The supplied representation uses 32-bit address-bearing values; it does not independently establish the full platform ABI, byte order, or memory-region type.

### Preconditions

For defined operation in an ordinary memory model:

- The global lookup root and the selected entry must be readable.
- The selected entry must identify a record whose status field is readable.
- The source-word field must be readable whenever a transfer occurs.
- The count-output location must permit a 32-bit write.
- The destination must permit every 32-bit write actually performed.

A destination sized for the full transfer limit is sufficient for destination capacity, though an invocation that stops early uses fewer words. For a zero limit, the function does not access destination storage.

No bounds, null-pointer, alignment, capacity, or accessibility checks are visible. Negative selectors are not rejected. Their scaled displacement is negative; whether the resulting entry exists is an external precondition.

## Behavior

### Record selection

The function resolves the selected record once, before examining its status or transferring any word.

The selector’s signed 16-bit range, multiplied by 396, fits within signed 32-bit arithmetic. This does not establish that the resulting address is valid or that adding the displacement to the lookup root cannot cross the usable address range.

Later transfers continue to use the selected record address. There is no visible repetition of the lookup or re-selection of the record.

### Transfer gating and ordering

The actual transfer count begins at zero.

Before each potential transfer, the function reads the selected record’s 32-bit status field and examines its low nibble. A zero low nibble prevents that transfer.

If the low nibble is nonzero, the function then checks whether the actual count is below the caller’s transfer limit. Thus, the status read precedes the limit check. Reaching the transfer limit does not eliminate the status observation made when checking whether to continue.

For each permitted transfer:

- A fresh 32-bit value is read from the record’s source-word field.
- That value is written to the current destination word.
- The next destination position is four bytes later.
- The actual transfer count advances by one.

Every source-word read uses the same record-relative address, `0x15C`. The source address does not advance. Only the destination advances.

The function does not visibly decrement a field in the record, clear status bits, or acknowledge a transfer through an explicit record write. If reading the source field consumes data or changes status, that behavior belongs to the underlying memory region and is not established by this function alone.

### Stopping conditions

Transfers stop when either:

- A loop-condition status read has a zero low nibble; or
- The actual count has reached the transfer limit.

Only the low four status bits participate. A nonzero status word with a zero low nibble stops transfer just as an all-zero status word does.

For an unsigned 32-bit limit, the count cannot wrap through its increment in this function. A transfer requires the count to be strictly below the limit. Even at the maximum limit, `0xFFFFFFFF`, the final possible increment reaches that value without exceeding it. This arithmetic property does not establish that the corresponding destination range is usable.

### Final status decision

After transfer stops, the function performs another status-field read. This read is separate from the status read that checked whether the loop should continue.

The final observation determines the return value:

| Final status low nibble | Return value |
|---|---|
| Zero | `0xFFFFFF01` |
| Nonzero | `0x00000000` |

The final read is authoritative for the return value even if it differs from an earlier observation.

Consequently:

- A transfer stopped by a zero status observation can return `0x00000000` if the final observation becomes nonzero.
- A transfer that reaches its limit can return `0xFFFFFF01` if the final observation is zero.
- Neither return value alone identifies whether the requested count was reached.

After choosing the return value, the function writes the actual count to the count-output location, then returns.

### Zero-limit behavior

A zero limit suppresses all source-word reads and destination writes, but does not bypass record selection or status access.

In the supplied representation, a zero-limit invocation makes:

1. The status read used to evaluate the loop condition.
2. The separate final status read.

It then writes zero to the count-output location. The final status observation still determines the return value.

## Side effects

### Caller storage

Transferred words occupy consecutive four-byte destination positions. On normal completion, the count output is written once, including when no words were transferred.

There is no rollback. If an invalid access or external fault interrupts execution, the supplied representation establishes no recovery path and no guarantee that the count output has been updated. Earlier destination writes may already have occurred.

### Aliasing

No non-overlap check is visible.

If the count-output location overlaps transferred destination data, the final count write can overwrite that data.

If destination storage overlaps the selected record, a transfer write can change a field subsequently read by the function. In particular:

- Overwriting the source-word field can affect later source values.
- Overwriting the status field can affect subsequent transfer decisions or the final return-value decision.

The return value is selected before the count-output write. An overlapping count write that changes the status field therefore does not retroactively change the selected return value.

These observations describe access order; they do not establish that such overlap is supported by the original language, ABI, alignment rules, or memory region.

### Ownership and synchronization

No allocation, release, ownership transfer, locking, or explicit synchronization is visible. Destination and count-output storage remain caller-provided.

The function contains no visible direct write to the lookup root or selected record, except where caller-supplied output addresses alias those locations. Reads may nevertheless have external effects if the record is backed by side-effecting memory.

## Acceptance examples

These are conditional examples derived from static evidence, not executed tests. They assume valid accesses and no output aliasing unless stated otherwise.

### Zero limit with a nonzero final low nibble

Given a transfer limit of zero:

- No source word is read.
- No destination word is written.
- The count output receives zero.
- If the final status observation has any low-nibble bit set, the return value is `0x00000000`.

### Upper status bits do not permit transfer

Given a positive limit and a first status observation of `0x00000100`:

- Its low nibble is zero, so no word is transferred.
- The count output receives zero.
- If the final observation also has a zero low nibble, the return value is `0xFFFFFF01`.

### Limit reached while status remains nonzero

Given a limit of three, nonzero low nibbles at all status observations, and successive source reads yielding three specified 32-bit values:

- Those values are written in order to destination byte offsets 0, 4, and 8.
- No fourth source word is read.
- The count output receives three.
- The return value is `0x00000000`.

There are five status reads in the represented control flow: three preceding successful transfers, one checking continuation after the third transfer, and one final read.

### Status becomes zero before the limit

Given a limit of five, two successful transfers, and then a loop-condition status observation with a zero low nibble:

- Exactly two destination words are written.
- The count output receives two.
- A zero low nibble at the final read produces `0xFFFFFF01`.

### Status changes between stopping and return

Given that a zero low nibble stops transfer, followed by a nonzero low nibble at the final read:

- No transfer is added between those two observations.
- The count remains the number already transferred.
- The return value is `0x00000000`.

Conversely, after the limit is reached, a zero final low nibble produces `0xFFFFFF01` even though the full requested count was transferred.
