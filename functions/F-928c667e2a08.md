# F-928c667e2a08

## Purpose

F-928c667e2a08 conditionally invokes a lookup-like dependency and, when that dependency returns a nonzero result, computes a 32-bit result from a context field and a field in the returned record.

The operation has three distinct stages:

1. Check a context, a pointer-valued context field, and the first byte of a supplied byte sequence.
2. Invoke F-a19afa5473aa with the supplied sequence pointer and a separate 32-bit context field.
3. Combine a context value with sixteen times a 32-bit value read from the dependency’s result.

A zero return is used for multiple rejected or unsuccessful cases. It is not an unambiguous failure indicator: the final arithmetic may also produce zero.

The apparent intent is to turn a lookup result into an address or offset within a fixed-stride collection. That interpretation is inferred, not established. The visible behavior establishes arithmetic and memory accesses, but does not establish that the result addresses a valid object.

## Behavior

### 1. Context gating

If the context is zero, the function returns zero.

On this path:

- No context field is read.
- The sequence is not dereferenced.
- F-a19afa5473aa is not called.

If the context is nonzero, the function reads the pointer-valued field at context offset 0x48. This read occurs even when the sequence pointer is null.

A nonzero context therefore must support that field read merely to reach a normal rejection result. Supplying an invalid nonzero context is not equivalent to supplying a zero context.

If the field at offset 0x48 is null, the function returns zero without dereferencing the sequence or calling the dependency.

### 2. Sequence gating

After the context and its field at offset 0x48 have passed their checks, a null sequence pointer causes a zero return.

For a nonnull sequence pointer, the function reads exactly the first byte for its own eligibility check. That byte is treated as unsigned, with values from 0 through 255.

- A first byte of zero causes a zero return without a dependency call.
- Every nonzero byte value, including values from 128 through 255, passes this check.

No further byte is examined by the wrapper. It does not search for a terminator, validate a length, compare content, or establish that the sequence is a valid string.

The first-byte value is used only as a zero/nonzero gate. It does not replace or advance the sequence pointer passed to the dependency.

### 3. Dependency invocation

Once all preceding gates pass, the function reads the 32-bit context field at offset 0x80 and calls F-a19afa5473aa exactly once.

The dependency receives:

1. The original sequence pointer.
2. The value read from context offset 0x80.

The pointer-valued field at offset 0x48 is not an argument. Its observed role is solely to permit or prevent the call.

If the dependency returns zero, F-928c667e2a08 returns zero. In that case, it does not read the context field at offset 0x50 or the record field at offset 4.

No post-call eligibility check is visible. In particular, the wrapper does not re-read the gate at offset 0x48 or the first sequence byte after the dependency returns.

### 4. Result computation

If F-a19afa5473aa returns a nonzero value, that value is used as a record address.

After the call, the wrapper reads:

- The signed 32-bit field at context offset 0x50.
- The signed 32-bit field at offset 4 from the returned record address.

The returned result is the former value plus sixteen times the latter.

Both field reads occur after the dependency returns. The supplied expression does not establish their relative order. A contract that requires the context-field read to precede the record-field read, or vice versa, would go beyond the evidence.

The context field at offset 0x50 is not captured before the call. If the dependency changes it while leaving the context valid, the subsequent read observes the post-call value. Likewise, the record value is read from memory after the dependency returns; no independent copy or validation is visible.
