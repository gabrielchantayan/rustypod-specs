## Behavior

### Width and layout rules

Every direct memory access shown in the body is one byte wide.

The first destination is at byte offset `0x11` from an ambient base. The later destinations are formed differently: the body reads an unsigned byte, treats its numeric value as an address contribution, adds `0x11`, and writes one byte at that resulting address.

A selector byte therefore chooses a destination in the inclusive numeric range `0x11` through `0x110`, assuming ordinary byte-addressed arithmetic. The visible expression does not add a separate object or table base to this range. Interpreting these destinations as ordinary fields of a larger object would require evidence not supplied here.

The ambient payload is unsigned and 32 bits wide:

- Its first stored byte consists of bits 0 through 7.
- Its second stored byte consists of bits 22 through 29.
- Bits 30 and 31 do not contribute to that second byte.
- The right shift used for the second byte is logical because its operand is unsigned.

The selector-derived read address is the selector multiplied by `0x400`, followed by addition of one. That address is used twice, at separate points in the sequence. It is not a visibly cached read.

## Acceptance examples

These are conditional acceptance criteria, not test results. They assume the relevant path is reachable, preceding calls return, memory accesses are valid, and the represented operands remain available as described.

### Payload-byte selection

Given an ambient payload of `0xFFC000AB`:

- The first direct store writes `0xAB`.
- The later payload store writes `0xFF`.

Given an ambient payload of `0xC0000000`, the later payload store writes zero. This distinguishes bits 22–29 from the top eight bits.

### Zero selector byte

If the ambient-selector read returns zero, the second direct write targets numeric address `0x11`.

If it returns `0xFF`, that write targets numeric address `0x110`.

Neither result is implicitly rebased onto the ambient destination base.

### Repeated read observes changed state

Suppose the first selector-derived read returns `0x20`. Its following clear writes zero at `0x31`.

If intervening dependency effects change the selector byte to `0x40`, the second clear writes zero at `0x51`. Reusing the first selector byte would not match the visible sequence.

### Explicit call arguments

With selector 3 and an F-U08 result of 7, F-U09 receives explicit argument values 24, 24, 3, and 28, in that order.

With an F-U03 result of 5, F-U04 receives 20. With an F-U13 result of 9, F-U14 receives 36.

These examples stay within the nonnegative, nonoverflowing arithmetic ranges.

### Alias-sensitive behavior

If a preceding byte write overlaps a later selector-read address, and no intervening effect changes that byte, the later read observes the written byte. A contract that snapshots all selector bytes at entry would not match the visible ordering.

### Interrupted execution

If F-U09 does not return, the second selector-derived read and clear are not reached through the represented sequence. Earlier writes are not visibly undone.
