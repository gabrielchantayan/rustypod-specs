# F-cf42aa14242d

## Purpose

F-cf42aa14242d performs fourteen dependent memory-selection stages, prepares a sparse stack-relative region, and transfers control to external operations. Its contract includes intermediate publications, repeated reads, narrow writes, and changes in address selection—not merely final memory contents.

**Established static evidence:** the supplied representation contains 32-bit word accesses, signed 16-bit reads, 8-bit accesses, fourteen global-selection stages, two ordinary external invocations, and a terminal operation annotated as non-returning.

**Inferred intent:** the memory publications may connect records and prepare data for an external consumer. No record schema, resource protocol, or successful-completion guarantee follows from that interpretation.

All later obligations are conditional on execution reaching them. Invalid addresses, arithmetic behavior, prematurely consumed byte values, or external behavior may prevent subsequent effects.

## Behavior

The following requirements describe observable access relationships in the supplied representation. They do not establish volatile semantics, atomicity, synchronization, or hardware execution order. Operand evaluation order within a compound expression is not independently established.

2. The entry-relative 0x44 word, establishing the initial entry link.

The initial publication group consists of:

| Destination | Payload source |
|---|---|

### Selection and propagation obligations

Each stage uses a distinct global selection source. One observation selects the **replacement base**; a separate observation supplies the complete word published at the stage’s destination plus 0x44. The contract does not collapse these observations into one guaranteed value.

The destination-relative 0x44 publication precedes publication of the **incoming propagated word** at replacement base plus 0x14.

| Stage | Destination selected for the global-derived word |
|---|---|
| 1 | Initial entry link |
| 2 | Entry link captured during stage 1 |
| 3–5 | Replacement-relative 0x14 word captured in the preceding stage |
| 6 | Entry link captured during stage 5, before obtaining the working base |
| 7 | Working link captured during stage 6 |
| 8–10 | Plain byte observed in the preceding stage, widened under unresolved byte rules |
| 11–14 | Working link captured in the preceding stage |

Stages 1–13 obtain outgoing propagation by reading the then-current replacement base plus 0x44 after their stage-specific halfword publication. That read precedes the between-stage self-publication at offset 0x54. The self-published value is the entry base through stage 4 and the working base thereafter.

Stage 14 has no corresponding outgoing propagation read or required final self-publication.

### Entry-base stages: 1–4

These stages retain the entry base as their principal base. Their stage-specific requirements are:

|---|---|
| 1 | The initial explicit-relative 0x64 word supplies an entry-relative 0x11 byte before a fresh entry-link capture and signed-halfword observation. That word becomes a temporary complete-word payload, while replacement plus 0x74 supplies the **early reciprocal value**. The temporary payload is published at entry plus 0x54. Stage 4’s outgoing propagation read occurs before restoration of the entry base at entry plus 0x54. The temporary publication and both stage-3 duplicate byte writes remain distinct effects.

### Working-base transition: 5–6

Stage 5’s initial entry-relative 0x11 byte derives from the temporary complete-word payload. It independently observes anchor plus 0x64, then captures the entry link and signed halfword. The early reciprocal value is published at anchor plus 0x54.

Replacement plus 0x14 supplies the new **working base**. Its 0x0D byte derives from replacement. The halfword still uses the previously captured entry link as payload. Outgoing propagation precedes the working base’s self-publication.

Stage 6 must use that stage-5 entry-link capture as its global-publication destination; a link associated with the new working base is not a substitute.

Stage 6 begins its local work with a working-relative 0x11 byte derived from stage 5’s anchor-relative observation. Its working link and signed halfword are captured before either base refreshes. The early reciprocal value is again published at anchor plus 0x54.

Two refreshes then have different sources and timing:

- Working base refreshes from replacement plus 0x14. Its 0x0D byte uses the replacement value from before replacement refresh.
- Replacement refreshes from incoming propagated word plus 0x14.

Anchor is published at early reciprocal value plus 0x54 before the halfword publication. The halfword combines the earlier signed halfword with refreshed replacement and uses the earlier working link as payload.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Signed addressing:** halfword representation 0xFFFE contributes −2 where widened, provided the resulting arithmetic and address are valid.

2. **Selection independence:** if the two observations of a stage’s global differ, replacement comes from the first and the destination-relative 0x44 payload from the second.

3. **Stage-4 ordering:** the shifted-entry byte follows common replacement-relative publication. The fresh-0x64-derived byte follows replacement-relative 0x14 capture and precedes anchor-relative 0x04 observation.

4. **Transition destination:** if stage 5 captures entry link 0x1000, stage 6’s global-derived word targets 0x1044. A different link associated with the new working base does not redirect that write.

5. **Intermediate effects:** preserving only the final entry-relative 0x54 value omits stage 4’s temporary publication. Combining stage 3’s duplicate bytes likewise omits an effect.

6. **Byte interpretation:** plain-byte representation 0xFE does not establish either −2 or 254 as an address contribution.

7. **Overlap:** stage 9’s outgoing word equals retained payload only if intervening effects leave the published bytes unchanged.

8. **Sum-selected publication:** replacement 0x1000 and incoming propagated word 0x80 select address 0x1080 for the retained-payload write, assuming valid arithmetic.

9. **Product observations:** an overlapping intervening publication may change the second product-state-relative 0x44 observation. Reusing the first observation is unsupported.

10. **Stage boundary:** stage 14 requires its product-related reads, but not an outgoing replacement-relative 0x44 propagation read.

11. **Premature consumption:** substituting zero or a later byte definition for either prematurely consumed value is unsupported.

12. **Preparation and freshness:** anchor 0x20 nominally yields shifted values 0x200 and 0x2000 under valid shifts and no interference. If F-opaque-01 changes the argument global and returns, the later call uses its fresh post-publication observation.
