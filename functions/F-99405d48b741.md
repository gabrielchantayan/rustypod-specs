## Acceptance examples

These are conditional requirements, not execution results. They assume full-width accessibility, supported arithmetic and conversions, and valid realizable overlaps where specified.

1. **Early mutation and retained selection.** If an initial relationship write changes selector + 0x14 before target selection, target reflects the changed signed word. Changing root + 0x44 at that point does not reselect anchor.

2. **Source width despite byte output.** Providing only one readable byte at support + 0x44 does not satisfy the four-byte source requirement for the annotation at associate + 0x0d.

3. **Negative index.** With index −3 and stride 8, the first replacement-chain source is decimal address 44: the product −24 plus offset 68. No negative-index rejection intervenes; accessibility remains a separate condition.

4. **Separate routing observations.** If supported routing observations yield 0x500 and then 0x700, context is 0x500 while anchor + 0x44 receives 0x700. This condition does not establish a mechanism by which the routing source changes.

5. **Replacement-dependent weight.** If replacement base and displaced contents both equal 0x800, target is 7, and index is 3, the replacement assigns 14 at 0x814. If the fresh multiplier observation sees that assignment, weight is 42.

6. **Payload source versus region.** With weight 0x200 and index 3, payload initialization reads at 0x274 and region is 0x600. Substituting a read at 0x674 would violate the contract.

7. **Publication-time payload.** If D’s leading word assignment changes the payload slot, D’s byte annotation uses the changed payload. E independently obeys the same ordering rule. A and B remain separate occurrences even when they produce identical contents.

8. **Retained versus fresh distribution input.** If the payload assignment at context + 0x64 changes region + 0x44, the annotation at context + 0x09 still derives from retained region contents. The later annotation at region + 0x11 derives from the fresh four-byte observation.

9. **Closing destination and base retention.** If the current payload is 0xb00 when the first closing address is formed, its destination is 0xb01. Even if that assignment changes first argument + 0x14, the remaining closing annotations use the previously retained closing base.

10. **Preparation layout and order.** For first argument 3 and supported shifts, offsets 0x10 and 0x34 receive 0x30 and 0x300. All four preparation clears occur before any of the six copies.

11. **Non-return boundary.** If F-opaque-01 does not return, the seventh-argument clear and subsequent dependency transitions are not reached. Earlier direct effects are not thereby undone.

12. **Late continuation consumption.** If F-opaque-01 changes the continuation source and returns, the later invocation consumes that source after the intervening assignments, rather than substituting an assumed incoming value.
