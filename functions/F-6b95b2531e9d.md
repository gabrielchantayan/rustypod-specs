# F-6b95b2531e9d

## Purpose

F-6b95b2531e9d performs a nested search and conditionally writes two 32-bit output words.

The outer search examines records obtained from a caller-supplied collection. Each outer record whose word at byte offset 4 equals a caller-supplied match value triggers a separate inner search. The inner search obtains its collection and iteration count from dependencies. Each inner record whose word at byte offset 4 equals a shared comparison word triggers an extraction call, followed by two caller-visible output writes.

The function does not stop after a match. Multiple inner matches, including matches reached through different outer records, can overwrite the outputs repeatedly.

**Established behavior:** nested traversal, comparisons, dependency-call order, output-write order, and a finalization call after each normally completed inner traversal.

**Inferred intent:** extracting a pair of values from matching nested records.

**Not established:** the meaning of those values, whether the extraction dependency initializes both temporary words, and whether the finalization dependency releases a resource.

## Behavior

### Outer traversal

The outer iteration position begins at zero and is maintained as an unsigned 32-bit value. The supplied outer count remains the loop bound; this function does not obtain a replacement outer count from a dependency.

For each position strictly less than that count:

1. The position is narrowed to a signed 16-bit value and then widened to the integer argument passed to F-0ff4e60503e7.
2. F-0ff4e60503e7 receives the caller’s outer collection argument and that converted index.
3. The function reads the returned record’s 32-bit word at byte offset 4.
4. If that word equals the outer match value, the function performs the complete inner-search sequence described below.
5. Otherwise, it advances to the next outer position without acquiring an inner collection.

A matching outer record does not end the outer traversal.

### Index conversion and iteration limits

The loop positions and the lookup indices have different widths.

Under the signed 16-bit interpretation represented by the supplied listing:

- Positions 0 through 32,767 produce indices 0 through 32,767.
- Position 32,768 produces index −32,768.
- Position 65,535 produces index −1.
- Position 65,536 produces index 0 again.

This conversion applies independently to both traversals. Large counts do not produce a monotonically increasing sequence of nonnegative lookup indices. Instead, the 16-bit index pattern repeats.

The iteration count itself is not narrowed to 16 bits. A count greater than 65,536 therefore requests repeated index patterns rather than only one traversal of that pattern.

An unsigned 32-bit count of zero causes no iterations. For the maximum count, the last processed position is 4,294,967,294; the subsequent position equals the bound and fails the loop condition. The displayed loop does not require an unsigned wraparound to terminate.

### Inner collection acquisition

For every matching outer record, the function:

1. Calls F-9d7a092439f5 without explicit arguments and saves its 32-bit result in a local collection slot.
2. Calls F-d0b90560f1fd without explicit arguments and saves its unsigned 32-bit result as the inner iteration count.
3. Begins a new inner traversal at position zero.

The order is significant: collection acquisition precedes count acquisition.

A new collection acquisition and a new count acquisition occur for each matching outer record. The function does not cache either result across outer matches.

The inner count is captured once per inner traversal. Later dependency calls do not cause this function to query that count again.

### Inner traversal and matching

For each inner position strictly less than the captured inner count:

1. The position undergoes the same signed 16-bit narrowing and integer widening used by the outer traversal.
2. F-0ff4e60503e7 receives the saved inner collection value and the converted index.
3. The function reads the returned record’s 32-bit word at byte offset 4.
4. It compares that word with a shared 32-bit comparison word.
5. An equal comparison triggers extraction and output writes.

The shared comparison word is referenced for each inner comparison; it is not explicitly saved once at function entry or once at inner-search acquisition. Dependencies may affect shared state. Consequently, the evidence does not establish that all inner records are compared against one invariant value.

The comparison is equality, not an ordering or range test.

### Extraction and output writes

For each matching inner record, the following order is explicit:

1. Read the pointer-like field at record byte offset 8.
2. Read a 32-bit word through that pointer.
3. Call F-ccabec065f5e with that word and the address of a first local 32-bit temporary.
4. After the dependency returns, read the first temporary and store it through the first output destination.
5. Read a second local 32-bit temporary and store it through the second output destination.

The extraction dependency is not passed either caller output destination directly.

There is no explicit assignment to the second temporary in the supplied function. There is also no explicit initialization of the first temporary before its address is passed to the dependency. A two-word extraction result is plausible intent, but it is not an established dependency contract.

In particular, the evidence does not independently prove that the second temporary occupies a writable output region covered by the dependency’s second argument. The second output word must therefore be treated as **documented_only** unless the dependency contract and temporary layout establish how that word becomes initialized.

Both output stores occur after the extraction dependency returns. No returned status is checked before either store.

### Inner-search finalization

After a normally completed inner traversal, the function calls F-5d38327d98c6 with the address of the local collection slot.

This call occurs even when the captured inner count is zero or no inner record matched. It occurs once per matching outer record, after that record’s inner traversal.

Passing the slot’s address permits the dependency to modify the stored collection value. The listing does not establish whether the dependency releases memory, changes reference counts, clears the slot, or performs another operation.

No corresponding finalization call is made for an outer record that fails its comparison.

### Completion and exceptional interruption

After all outer positions have been processed, the function returns without an explicit value.

There are no explicit branches for dependency failure, invalid records, invalid payload pointers, or output-store failure. There is no shown recovery or guaranteed finalization if a dependency or memory access prevents normal continuation.

## Side effects

### Caller-visible output mutation

The function writes the output destinations only after an inner match and a normally returning extraction call.

If no such match occurs, this function performs no explicit store through either output pointer. This does not guarantee that the underlying memory remains unchanged: an unknown dependency could affect it through other aliases.

With multiple inner matches, there are two output stores per match, in traversal order. The function does not accumulate results.

If the destinations are distinct, valid, and unaffected by later dependency activity, their final contents are the words stored for the last matching inner record reached.

If both destinations identify the same 32-bit location, the first store occurs and is then overwritten by the second store. Under normal execution without another intervening modification, the second temporary supplies that location’s final value.

No non-aliasing requirement is checked. If an output destination aliases collection data or shared state, an output store may change later comparisons or lookup behavior. Whether such aliasing is valid depends on contracts not supplied here.

### Ownership and resource state

The function itself contains no explicit allocation or release operation. It acquires an opaque inner collection value and later passes its slot to F-5d38327d98c6.

That pairing is consistent with acquisition and release, but ownership transfer and resource disposal remain unknown. No ownership transfer for the caller’s outer collection, output destinations, returned records, or indirectly accessed payload is established.

## Acceptance examples

These are conditional static acceptance criteria, not observed runtime results.

### Zero outer count

Given an outer count of zero:

- No record lookup occurs.
- No inner collection or inner count is acquired.
- No extraction or finalization dependency is called.
- Neither output destination is explicitly written by this function.

### No matching outer records

Given valid outer lookups and no equality between an outer record’s offset-4 word and the supplied outer match value:

- There is one lookup per outer position.
- No inner-search dependency sequence begins.
- Neither output destination is explicitly written.

### Matching outer record with an empty inner traversal

Given one matching outer record and an acquired inner count of zero:

- Collection acquisition precedes count acquisition.
- No inner lookup or extraction occurs.
- F-5d38327d98c6 is called with the collection slot’s address.
- Neither output destination is explicitly written.

### A single inner match

Given one matching inner record, readable payload indirection, and an extraction contract that establishes two valid temporary words:

- The payload word is read before extraction.
- Extraction completes before either output store.
- The first output receives the first temporary.
- The second output receives the second temporary afterward.
- The traversal continues; the match does not cause an early return.

Without that extraction contract, the second output’s expected value remains **documented_only**.

### Repeated matches

Given two matching inner records and valid extraction results:

- Both records trigger extraction and both output stores.
- The first match does not suppress the second.
- Subject to valid distinct destinations and no later aliased modification, the second match determines the final output contents.

### Signed-index boundary

- The next position is looked up using index −32,768.

A nonnegative index of 32,768 is not the represented lookup argument.

### Shared comparison changes
