## Behavior

### 1. Initial selector read and byte store

Before any indirect call, the function reads one byte at the entry-state base plus one.

It interprets that byte as an unsigned selector, adds 17, and writes the entry-state byte to the resulting address.

The ordering is significant:

1. Read the selector.
2. Compute the selector-derived address.
3. Store the entry-state byte.
4. Begin the indirect-call sequence.

The visible code performs no validity check before the read or write. If the first read cannot complete, no later direct operation is established. If the first write cannot complete, the first indirect call has not yet occurred.

### 2. First five indirect calls

The first indirect call receives the explicit input shifted left by two bits. Its target depends on the entry-state control address.

Four more indirect calls follow. They have no explicit arguments in the recovered representation. The first four calls’ return values are not visibly used. The fifth call supplies an unsigned 32-bit result that remains relevant later in the function.

“No explicit arguments” describes the visible representation only. It does not establish that a callee ignores incoming registers, global state, or other calling-context data.

### 3. Second selector read, byte store, and sixth call

After the fifth call returns, the function rereads the byte at the entry-state base plus one. This second read occurs after all effects of the first five calls.

The freshly read selector determines the destination of a second byte store: selector plus 17.

Under the apparent byte-storage model, the stored value is the low byte of four times the fifth call’s result. Equivalently, it is four times the low byte of that result, reduced modulo 256. The recovered expression performs a character conversion before multiplication, so exact language-level conversion rules remain a platform uncertainty; the low-eight-bit interpretation is the evident machine-level effect.

After this store, the sixth indirect call receives the freshly read selector, zero-extended to an unsigned 32-bit value.

The sixth call uses the captured selector. It does not perform another visible read of the selector location. In particular, if the second store aliases that location, the argument still comes from the read preceding the store.

### 4. Seventh through twelfth indirect calls

The seventh indirect call has no explicit argument and produces a four-byte result.

The eighth indirect call receives that result directly. There is no visible arithmetic transformation between the returned quantity and the argument.

The ninth, tenth, eleventh, and twelfth indirect calls follow, each with no explicit argument in the recovered representation. The twelfth call’s result is captured as a signed integer.

The fifth call’s earlier unsigned result is still used after these calls. The function does not visibly recompute it or obtain a replacement value from memory.

### 5. Third byte read and byte store

After the twelfth call returns, the function uses the fifth call’s result to derive a new read address.

Under 32-bit unsigned arithmetic, that read address is eight times the fifth call’s result plus one, reduced modulo 2³². The function reads one byte from that address.

That newly read byte is another unsigned selector. The third write destination is this selector plus 17.

The value written is derived from the fifth call’s result:

- Keep its low thirty bits.
- Shift that quantity right by twenty bits.
- Convert the result to a byte for storage.

Before byte conversion, the shifted quantity can range from 0 through 1023. Under the apparent low-byte storage interpretation, the final byte is original result bits 20 through 27. Original bits 28 and 29 do not survive the byte store; original bits 30 and 31 have already been masked out.

The read occurs after calls six through twelve. Those calls can therefore affect the selector read at the computed address, even though the address calculation uses the previously captured fifth-call result.

### 6. Thirteenth through seventeenth indirect calls

The thirteenth indirect call receives the twelfth call’s signed result shifted left by two bits.

The same signed-shift limitation applies as for the explicit input: the recovered expression does not establish wraparound behavior for negative values or values whose fourfold result is not representable.

Four more indirect calls follow, with no explicit arguments in the recovered representation. Their return values are not visibly consumed.

### 7. Recovered endpoint

This establishes no normal return, cleanup sequence, or recovery behavior. It also does not prove that a deployed execution necessarily reaches a hardware invalid-instruction fault: the boundary may reflect incomplete or incorrect instruction recovery.
