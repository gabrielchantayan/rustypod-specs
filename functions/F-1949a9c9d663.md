If selection completes with an eligible status, it optionally processes the selected pair, then processes other records and conditionally invokes a destination-copy dependency.

This contract describes statically established inputs, arithmetic, memory observations, dependency calls, state transitions, and return selection. The domain meanings of the records and status values are unknown.

## Behavior

### Entry, allocation, and loading

The current status and descriptor position start at zero. An initial return candidate is read from global storage before checking required inputs.

If the descriptor base is zero or the primary key is null, the function returns that candidate without allocation.

Otherwise, F-d33f6d597e5d receives the 32-bit product of the record count and a global size factor. The factor is not established to equal 0x588. After the call, another global is read as the return candidate. A zero allocation result returns that candidate without loading or release.

A nonzero allocation result becomes the temporary base. Descriptors are then loaded in ascending index order. Each F-6b5ae5017b36 call receives:

1. The descriptor’s first word multiplied by the global loading factor, represented in 32 bits.
2. The temporary base plus the descriptor index multiplied by 0x588.
3. The constant 0xAB.
4. The descriptor’s second word.

The representation establishes these inputs, but not a complete ordering among the memory reads evaluating different arguments.

Each loader result replaces the current status; the descriptor index then advances by one. Loading continues only while that status is zero and the unsigned index is below the count. A nonzero loader result prevents selection, becomes the returned result, and still leads to ordinary release.

With zero records and successful allocation, no loader is called; selection completion is reached with both selections unset.

Global factors are not established as constant across dependency calls.

### Marker comparisons

After successful loading, both selected positions are initialized to 0xFFFFFFFF. The scan position starts at zero.

Whenever its unsigned value is below the count, two marker comparisons occur at the current record’s offset 0x56C. The first marker comparison precedes the second; the second still occurs when the first succeeds.

Each comparison examines up to twenty byte pairs:

- The record byte is multiplied by −75, increased by 36, and reduced to eight bits.
- The corresponding marker-table byte is multiplied by 17 and reduced to eight bits.
- The transformed values are compared.

Within each pair, the record-byte read precedes the marker-table-byte read. A mismatch ends that comparison immediately. Twenty equal pairs establish a match. Zero bytes do not terminate marker comparison.

Marker matching therefore does not mean direct equality between stored record bytes and marker-table bytes. The two comparisons independently read record bytes; they are not established to share a saved marker snapshot.

  - **Second marker matches:** another F-870c4fcf7295 call receives an explicitly represented zero argument. Its secondary byte output contributes the signed-byte interpretation of −41 times that byte, reduced modulo 256. The resulting position becomes the first selection.
  - **Neither marker matches:** another F-870c4fcf7295 call has an unrecovered argument list. Its secondary 32-bit output contributes the signed-byte interpretation of the low eight bits of −19 times that output. Key comparison begins at the resulting position.

Displacements on a route are cumulative. The record used for key comparison need not be the record whose markers were examined.

A completed scan step increments its resulting position by one before the next boundary check.

### Encoded string comparisons

A comparison starts at record offset 0xEC or 0x20. Each iteration reads a record byte, then a key byte. The key byte is multiplied by 17 modulo 256.

A mismatch immediately ends comparison, with a 32-bit difference equal to the record byte minus the transformed key byte. Equal bytes terminate comparison only when the record byte is zero; otherwise both addresses advance.

Consequently:

- Equality requires matching transformed bytes through a common zero terminator.
- A key zero transforms to zero.
- There is no visible maximum comparison length.
- The record offsets identify starting addresses, not enforced field boundaries.
- Ordinary untransformed text equality is insufficient to establish equality here.
