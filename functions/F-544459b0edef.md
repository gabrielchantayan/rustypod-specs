# F-544459b0edef

## Purpose

F-544459b0edef coordinates comparisons, cursor advancement, and an operation on a container-like object. It selects between:

- A conditional bulk path that invokes a dependency, resets several fields, and publishes a header address.
- An iterative path that captures a cursor word before advancement, passes that value to an update dependency, and publishes a dependency-controlled result.

The function has two distinct output channels: a 32-bit word written through its first argument and a packed 64-bit return value. These channels can contain different values, including after a successful iterative operation.

A range-removal or container-clearing interpretation is plausible but not established. “Container,” “header,” “cursor,” “bulk,” and “update” describe access roles, not recovered data types or ownership guarantees.

The established contract is the visible sequence of accesses, dependency calls, direct writes, and return construction. Dependencies may have additional effects. In particular, writable temporary slots passed to dependencies can remain reachable through retained pointers during later calls.

## Behavior

### Initial publication and temporary initialization

Before any dependency call, the function:

1. Reads container +16.
2. Writes that header address to the output word.
3. Reloads container +16 and reads the selected header’s +8 word into a comparison temporary.
4. Initializes the captured-item slot with the original output-word address.
5. Initializes the result slot with the original container address.

The output write precedes the second header load. If the output address overlaps container storage, the initial write can therefore affect which header is used for the +8 read.

The original cursor address is also stored in a separate temporary. That temporary is replaced before its only visible dependency use, so this initialization does not provide a later cursor snapshot.

### Preliminary comparisons and bulk eligibility

The first call to F-2f569f4b2914 receives:

- The original cursor address.
- The address of the temporary containing the initial header +8 word.

A zero return skips the remaining bulk-eligibility checks and enters the iterative path.

For a nonzero return, the function reloads container +16 into another temporary and calls F-2f569f4b2914 with:

- The original fourth argument.
- The address of that header-address temporary.

Only if this second result is nonzero does the function read container +20. The bulk path is selected only when that field is also nonzero.

Consequently:

- A zero first comparison skips both the second preliminary comparison and the state-field read.
- A zero second comparison skips the state-field read.
- Any nonzero 32-bit comparison result passes a preliminary comparison; exact equality to one is unnecessary.
- A zero state field prevents bulk selection.
- Failure to select the bulk path always leads to a separate loop comparison.

Dependencies may change container storage between these reads. Eligibility is determined from the values actually observed at the specified points, not from an entry-state snapshot.

### Bulk operation and reset

On the bulk path, the function reloads the header address, reads that header’s +4 word, and calls F-256b766d474e with:

- The original container address.
- The freshly read header +4 word.

Its direct return value is ignored.

After the dependency returns, the function performs these direct writes in order:

1. Writes a current header address to the +8 field of a header selected through container +16.
2. Writes zero to the +4 field of a header selected through container +16.
3. Writes a current header address to the +12 field of a header selected through container +16.
4. Writes zero to container +20.
5. Reloads container +16 and publishes that value to the output word.

The header address is reloaded for the reset operations. A header address cached before the dependency call does not determine their destinations.

If container +16 remains a stable address H and the relevant storage does not overlap, the direct resulting state is:

- Header H +4: zero.
- Header H +8: H.
- Header H +12: H.
- Container +20: zero.
- Output word: H.

The function returns immediately after publication. The upper return word is the same loaded value used for that final output write; the lower word is the original output-word address.

The supplied evidence establishes ordering between these writes. It does not independently establish the order of the destination-address and value reads within a write that reloads container +16 for both purposes. Overlapping layouts must not be analyzed as though all header loads were one stable snapshot.

### Iterative comparison and termination

On entering the iterative path, the function calls F-2f569f4b2914 with:

- The original cursor address.
- The original fourth argument.

The loop terminates only when the comparison result is **exactly one**.

A result of zero, two, or any other 32-bit value causes an iteration. This predicate differs from the nonzero predicates used by the preliminary comparisons.

Each completed iteration is followed by another comparison with the same original arguments.

### Iteration body

For each nonterminating loop comparison, the function:

1. Reads the first 32-bit word at the original cursor address.
2. Retains that value across a call to F-2d9569c0b133 with the original cursor address.
3. Assigns the retained pre-advancement value to the captured-item slot.
4. Calls F-f59beec76d5b with the result-slot address, original container address, and captured-item-slot address, in that order.
5. Reads the result slot and writes its current value to the output word.
6. Performs the next loop comparison.

The item supplied to the update dependency is therefore the cursor word read **before** advancement. It is not a reread of the cursor after advancement.

The captured-item assignment occurs **after** advancement returns. If an earlier update exposed that slot’s address and the advancement dependency modifies it through a retained pointer, this explicit assignment replaces that modification before the next update call.

The result slot is initialized only once. The function itself does not reset it between iterations. Nevertheless, a value written by one update is available to a later update only if intervening dependency activity leaves it unchanged. Comparisons and advancement calls may modify the slot through retained pointers.

F-f59beec76d5b may modify both slots. Its direct return value is ignored. The following output write uses the result-slot value observed after that call returns.

### Iterative exit and escaped slots

When a loop comparison returns exactly one, the function performs no further advancement, update call, or explicit output write.

With no iterations, neither return-contributing slot has been passed to F-f59beec76d5b during this invocation. Under ordinary valid access to the supplied operands, their initialized values produce an upper word equal to the original container address and a lower word equal to the original output-word address. The output retains its initial header publication unless a dependency changed it.

After one or more iterations, both slot addresses have escaped to F-f59beec76d5b. A subsequent F-2f569f4b2914 call may access them through retained pointers, including during the comparison that returns exactly one.

The return therefore uses:

- The result slot’s value after that final comparison.
- The captured-item slot’s value after that final comparison.

Neither word is guaranteed to equal its value immediately after the last update call. The final explicit output write also need not match the upper return word: it precedes the terminating comparison.

For example, an update may leave result R and captured item S, causing an output write of R. If the terminating comparison changes the slots to U and V, the return contains upper word U and lower word V. Without an additional write to the output location, that location still contains R.
