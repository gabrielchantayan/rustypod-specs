# F-f1d8765d6c06

## Purpose

F-f1d8765d6c06 conditionally invokes a transfer into storage associated with a context object. Before transferring, it asks a dependency to accommodate a requested endpoint. It reports the requested count when that dependency returns exactly the requested endpoint; otherwise, it reports −1.

Two conditions produce an explicit diagnostic call: a zero source-address argument, and a designated context flag being set. Failure of the endpoint request does not produce that diagnostic call.

The apparent intent is an append-like operation. That interpretation is **inferred**, not established: the supplied body does not directly update the stored position, and the behavior of the endpoint dependency is unavailable.

## Behavior

### Initial read and rejection precedence

The first operation visible in the body is a load of the descriptor address from context offset +0x20. That address is retained for subsequent use.

The source-address argument is then compared with zero.

If the source-address argument is zero:

1. The flags word is not inspected.
2. F-4fc89ec41a6d is invoked with five arguments: 0x20, 0x75, 0x73, zero, and zero, in that order.
3. The function returns −1 if the diagnostic dependency returns normally.

Thus, a zero source takes precedence over the flag-based rejection. It is not accepted merely because the requested count is zero. It also does not make an invalid context safe, because the descriptor-address field is read first.

For a nonzero source, bit 0x200 of the flags word is tested. If that bit is set:

1. No flags write, stored-position read, endpoint request, or transfer is visible in this function.
2. F-4fc89ec41a6d is invoked with 0x20, 0x75, 0x7e, zero, and zero.
3. The function returns −1 if that dependency returns normally.

The numerical diagnostic values are established; their external meanings are unknown.

### Flags update

If the source is nonzero and the tested 0x200 bit is clear, the flags word is read again. That second value is masked with 0xfffffff0 and written back to context offset +0x14.

This clears bits 0 through 3 and preserves bits 4 through 31 from the value used for the update.

The flags test and flags update are separate reads in the supplied representation. They must not be described as necessarily using one captured value. No atomicity or concurrency guarantee is established.

The write occurs before reading the stored position and before invoking F-9a8ea7637eda. It is not undone when the endpoint request fails.

### Endpoint request

After the flags update, the function reads the stored position from descriptor offset +0.

It forms a requested endpoint by adding the requested count to that captured position. It then invokes F-9a8ea7637eda with:

1. The captured descriptor address.
2. The calculated endpoint.
3. The original requested count.
4. The auxiliary value.
5. The same auxiliary value again.

The dependency's result is compared for exact equality with the calculated endpoint. The caller does not interpret it as a Boolean or merely check whether it is nonnegative.

If the result differs:

- The function returns −1.
- No transfer dependency is invoked.
- No diagnostic dependency is invoked by this function.
- The earlier flags write remains an observable action.
- Any effects of F-9a8ea7637eda remain subject to that dependency's unknown behavior; no rollback is visible.

### Transfer path

If F-9a8ea7637eda returns exactly the calculated endpoint, the function reads the storage-base value from offset +4 of the **captured descriptor**.

It forms a destination using that freshly read storage base plus the **previously captured stored position**, then invokes the transfer dependency with:

1. That destination.
2. The original source-address value.
3. The original requested count.

The timing matters:

- A storage-base change made by F-9a8ea7637eda can affect the destination.
- A stored-position change made by that dependency does not replace the position already captured by this caller.
- A change to the context's descriptor-address field does not redirect this caller to a different descriptor; the caller continues using the address loaded at entry.

These observations do not imply that the dependency is permitted to invalidate the captured descriptor. Such invalidation could make the subsequent read unsafe.

The transfer dependency's result, if any, is ignored. After it returns normally, F-f1d8765d6c06 returns the original requested count. There is no visible transfer-result check and no explicit stored-position write after the transfer.

### Counts and arithmetic boundaries

For a zero count with a nonzero source and an accepted flag state, the function still clears the low flag bits, requests an endpoint, and invokes the transfer dependency if the endpoint result matches. Whether a zero-count transfer accesses memory is unknown.

For a negative count, the same control flow remains applicable. Its safety and meaning depend on arithmetic behavior and dependency contracts that are unavailable.

The endpoint addition and destination formation have no visible overflow checks. This contract does not prescribe wrapping, trapping, or safe behavior for out-of-range arithmetic.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes valid accesses, defined arithmetic, and normal dependency returns.

1. **Zero source overrides flag rejection.**  
   With a zero source and any requested count, the descriptor-address field is read first. The function then calls F-4fc89ec41a6d with third argument 0x73 and returns −1. It does not read the flags word.

2. **Flag rejection leaves flags untouched by this body.**  
   With a nonzero source and flags 0x0000020f, the function calls F-4fc89ec41a6d with third argument 0x7e and returns −1. It does not clear the low four bits or request an endpoint.

3. **Endpoint mismatch retains the flags update.**  
   Suppose both flags reads produce 0x000001af, the stored position is 10, and the requested count is 3. The function writes flags 0x000001a0 and requests endpoint 13. If F-9a8ea7637eda returns 12, the function returns −1 without invoking either the transfer dependency or the diagnostic dependency afterward.

4. **Endpoint match enables transfer.**  
   With stored position 10 and requested count 3, a dependency result of 13 enables the transfer. If the subsequently read storage base is 0x1000, the destination is 0x100a. The source and count 3 are forwarded, and normal transfer return is followed by return value 3.

5. **A changed base is used, but a changed position is not reread.**  
   Suppose the captured position is 10. If F-9a8ea7637eda changes the descriptor's position to 99 and its base to 0x2000, then returns the required endpoint, the destination uses 0x2000 plus 10, not plus 99.

6. **Zero count does not bypass dependencies.**  
   With a nonzero source, accepted flags, and stored position 10, count zero requests endpoint 10. A matching result causes a transfer invocation with count zero, followed by return value zero.

7. **A negative return need not identify the rejection path.**  
   With count −1 and a representable endpoint calculation, a matching endpoint result causes a transfer invocation with count −1. If that call returns normally, the function returns −1 without having taken either explicit rejection path.
