# F-814d4ee17e01

## Purpose

F-814d4ee17e01 rebuilds a destination collection of 32-bit item indices using four classification groups. Its explicit emission order is:

1. Indices carried by special records.
2. Ordinary group A: the low 32 bits of a classification result are nonzero.
3. Ordinary group B: that low half is zero and a subsequent classification returns nonzero.
4. Ordinary group C: that low half is zero and the subsequent classification returns zero.

This order is established by the supplied static representation. A complete, duplicate-free partition of the provider’s indices is only a conditional result. In particular, ordinary-group insertion receives the address of the live traversal counter. Its effects can therefore change subsequent traversal unless the dependency preserves that counter.

The function explicitly writes a one-byte marker after its emission loops terminate and before temporary cleanup. An observed marker value of `1` does **not** establish progress by the current invocation: the function does not clear it on entry, and dependency effects are unknown.

Grouped or prioritized rebuilding is inferred intent. The domain meanings of the classifications and the ordering policy for special records are unresolved.

## Behavior

### Preparation and traversal

The destination address is first supplied to F-7a304fc4cb8d. Whether this clears contents, preserves allocation, or performs another operation is dependency-defined.

The special descriptor’s three fields are then explicitly zeroed. Ordinary collections are initialized through F-7eb73ab0bcd6 in the order **B, A, C**. Each call receives a distinct additional four-byte temporary address. The meanings and required initial contents of those additional arguments are not established.

F-e38e6836b640 obtains the provider used to query the traversal bound. That unsigned 32-bit bound is captured once; it is not explicitly refreshed during traversal.

The traversal counter starts at zero. Iteration admission uses an unsigned comparison with the captured bound, and each normally completed iteration ends with an unsigned increment.

If dependencies preserve the counter, a zero bound admits no iterations, and any positive bound visits indices from zero through bound minus one. For a bound of `0xffffffff`, the final increment reaches `0xffffffff` and the next comparison fails; this ordinary progression does not wrap.

Without counter preservation, the visited indices and termination behavior are not guaranteed.

### Item acquisition and classification

Every entered iteration obtains a provider again through F-e38e6836b640. The item-access dispatch entry receives the fetched-item output area, that provider, and the counter’s current value. Repeated lookup does not establish that these providers are identical to, or consistent with, the provider that supplied the bound.

F-f814eaa01b27 receives the 20-byte item-representation area, the fetched-item area, and zero. Classification then follows this precedence:

- A nonzero result from F-3f2e817b9ef7 selects the special path. Neither later classification dependency is called for that iteration.
- Otherwise, F-1862b8feb88c supplies a 64-bit result. A nonzero low 32-bit half selects group A.
- If the low half is zero, F-ee40771ccb18 receives the item representation and the high 32-bit half. Its nonzero result selects B; its zero result selects C.

The high half is passed as a 32-bit argument. Its sign bit is not independently tested, and its domain interpretation is unknown.

Ordinary insertion calls F-84652ce813be with the selected collection and the **address of the actual traversal counter**. It does not pass a detached index copy. Consequently, synchronous copying alone is insufficient to establish traversal order: the dependency could copy the value and also modify the counter. Retaining that address could also affect later loops that reuse the same counter storage.

After either classification path completes normally, F-c1466ea05103 receives the constructed item representation before the counter increment. No separate explicit cleanup call targets the fetched-item area.

### Special-record accumulation

The special path builds a temporary record comprising an 8-byte leading value and a following 32-bit index.

F-5b24edfb22c0 first receives the leading-value storage. The current traversal counter is then copied into the index field. After that copy, F-ba5a4c1e0746 receives the separate 24-byte temporary and two zero arguments.

F-5fb92c16ae07 receives a second 8-byte temporary and the item representation. F-46f0b3cb316e then receives both 8-byte temporaries, followed by F-289ec4311c64 on the second temporary. These calls precede insertion of the 12-byte record.

Insertion depends on the special descriptor:

- Equal current end and allocation end cause a call to F-c2c664eac19b with the descriptor address, current end, and temporary-record address.
- Otherwise, current end is advanced by 12 bytes **before** any construction call. F-4bbba16cfe23 receives the old end and temporary record only when that old end is nonzero.

Thus, a malformed descriptor with zero current end unequal to allocation end advances current end without calling F-4bbba16cfe23. The body does not repair that inconsistency.

Following insertion, F-4e292a3dd745 receives the 24-byte temporary, then F-289ec4311c64 receives the first 8-byte temporary. These operations do not independently establish copying, transfer, reference management, or release semantics.

### Destination emission

Every explicit index-emission call uses F-84652ce813be with the destination address and an address identifying a 32-bit source index.

**Special phase.** Each source index is at offset `8` within a 12-byte record. The iterator advances by 12 bytes after each insertion call. Every termination check rereads the special current-end field.

Accordingly, special emission uses a live end, not a captured bound. The iterator is not reloaded from start on each iteration. A dependency-induced end change affects later comparisons; relocation or incompatible descriptor changes can invalidate the iterator.

**Ordinary phases.** Groups A, B, and C follow in that order. Each phase resets the shared unsigned counter to zero and uses that group’s previously captured emission bound.

For each source address, the group’s base field is reread and combined with four times the current counter. The base is not captured once for the entire phase. The bound is not recomputed after special processing or after earlier emissions.

Thus, later source addresses can use a changed base while retaining an older bound. Counter mutation through an earlier retained address can also affect these loops.

Under stable storage, preserved counters, preserved inserted values, and noninterfering dependency effects, ordinary groups preserve traversal order. Those conditions, together with appropriate provider and special-processing behavior, support the intended grouped sequence; the body alone does not establish them.

### Marker write and cleanup

Only after all four emission loops terminate does the function explicitly write byte value `1` at offset `0x84c`. Ordinary cleanup calls then occur in the order **C, A, B**, each through F-43e46bf31086.

Special cleanup uses different descriptor timing from special emission:

- Current end is read once, **after ordinary cleanup**, and retained as the cleanup termination bound.
- Start is read separately to initialize the cleanup iterator.
- At every termination check, start is read again and saved, including the check that terminates the loop.
- Termination compares the iterator with the saved end, not with the freshly read start.
- Each entered iteration calls F-289ec4311c64 on the iterator address, then advances the iterator by 12 bytes.

The repeated start reads neither reset the iterator nor refresh the saved end. The start value obtained during the final termination check becomes the address later supplied to F-ff1bdc376dcd.

After the loop, allocation end minus start is evaluated using later descriptor reads. The supplied representation does not establish the relative order of those two operand reads. Their difference and `12` are passed to F-870c4fcf7295.

Finally, F-ff1bdc376dcd receives the previously saved start address, the result from F-870c4fcf7295, and zero. The address is **not refreshed after that helper returns**. It need not equal the start value used in the capacity difference.

This final helper sequence occurs even if the special cleanup loop has no iterations.

## Acceptance examples

These are conditional consequences of static evidence, not execution results.

### Empty traversal

With captured traversal bound zero, no item-fetch or classification iteration occurs. Ordinary bounds are still queried. If the special descriptor remains empty, conditional special processing is skipped.

If all emission bounds are zero and calls return normally, the explicit marker write occurs, followed by cleanup. An empty destination additionally requires appropriate preparation and empty-collection semantics from the dependencies.

### Ordinary grouping

Suppose indices `0` and `3` select C, index `1` selects B, and index `2` selects A. With preserved counters, insertion order and values, stable storage, and no interference, destination emission is:

**2, 1, 0, 3**

If the first ordinary insertion copies index `0` but then changes the live counter to `2`, the following increment makes it `3`. With bound four and no further changes, indices `1` and `2` are skipped.

### Classification precedence and width

A nonzero F-3f2e817b9ef7 result suppresses both later classification calls.

With a zero first result, any nonzero low half from F-1862b8feb88c selects A regardless of the high half. A zero low half instead passes the high-half bit pattern onward, including patterns with its top bit set.

### Changing descriptors

If a special destination insertion changes current end, the next special termination check reads that changed end.

If an ordinary destination insertion changes its source collection’s base, the next source address uses the new base but the old captured bound. Safe continuation requires valid storage at the resulting address.

### Cleanup snapshots

If special cleanup changes current end, its termination bound remains the earlier snapshot. If it changes start, the final termination check captures the then-current start for the final address argument.

A later start change made by F-870c4fcf7295 does not refresh that saved argument.

### Marker observations

If the marker is already `1` on entry and a dependency prevents progress before emission, the observed byte can still be `1` without the explicit write being reached.

If control reaches the explicit write, every emission loop has terminated and cleanup follows in the established order. Neither fact makes an isolated observation of `1` proof of that path or of successful cleanup.
