# F-b39e71597039

## Purpose

F-b39e71597039 selects one of two byte-oriented command streams and interprets commands until its cursor reaches the selected stream’s nominal length. One selector causes a preliminary dependency call. A second input controls the branch taken by a resource-related command, except where the selector forces that input’s effective value to zero.

Established behavior consists of stream selection, operand reads, cursor progression, and ordered dependency calls. Descriptions such as “resource operation” identify roles; they do not establish what the dependencies do.

Unsupported selectors return without interpreting a stream. Unsupported command bytes enter a nonterminating loop rather than producing an error result.

### Return and termination

No return value is exposed.

Normal return occurs when:

- The selector is not 1, 2, 3, or 4.
- The command cursor reaches or exceeds the selected nominal length.

There is no explicit error result, dependency-status check, or visible exception handling. An unsupported command enters an endless loop. Inaccessible memory or a nonreturning dependency can also prevent normal completion; their platform consequences are not established.

## Behavior

### Entry selection

| Selector | Preliminary action | Stream | Nominal length | Effective resource argument |

| Any other value | Return | None | — | Unused |

Selectors 2 and 3 force the effective resource argument to zero. Their command-1 behavior therefore does not depend on the original second input.

For selector 4, the preliminary call completes before the long-stream binding is obtained. No preservation of global bindings or stream contents by F-a99a8ca02c77 is established. If it changes state subsequently read by this function, those later reads observe the resulting state.

After selection, interpretation starts at cursor zero. The selected stream base and nominal length are retained for that invocation; command contents are not copied into an immutable snapshot.

### Traversal and bounds

Before each command-byte read, the unsigned cursor is compared with the nominal length. A cursor at or beyond that length causes return.

This check validates only the command’s starting position. Once a command starts:

- Operand reads are not checked against the nominal length.
- Payload reads are not checked against the nominal length.
- Dependency calls complete before the next command-start check, assuming they return.
- Advancing past the nominal length causes return at the next check, not during the current command.

The cursor advances by one, two, five, or three plus an unsigned byte length, depending on the command. Every completed supported command advances it strictly forward.

Although the represented cursor is 32 bits, its own progression cannot approach wraparound under these nominal lengths: a command starts below 185 and advances by at most 258, giving a maximum next cursor of 442. This does not establish address safety for adding offsets to an arbitrary stream base.

The record layout is:

| Relative byte offset | Meaning |
|---:|---|
| 0 | Command byte 0 |
| 1 | Selector operand |
| 2 | Unsigned payload length |
| 3 onward | Payload bytes |

For a length \(n\) actually read from offset 2, the next command starts at the current position plus \(3+n\).

The observable order is:

1. Call F-8163ddbc7a0d and retain its opaque 32-bit result.
2. Read the selector operand at relative offset 1.
3. Call F-aa7d2a3b136c with that byte.

6. Call F-514bf918f958 with the retained result.

The length has range 0–255. A length of zero **at its actual read time** produces no payload-byte calls and advances by three bytes. It still performs the acquisition, selector, and finalization calls.

Initial stream contents alone do not determine this outcome. Both F-8163ddbc7a0d and F-aa7d2a3b136c execute before the length read and may alter that byte. The selector operand is likewise read only after F-8163ddbc7a0d returns.

The internal payload countdown underflows after its terminating zero check in the represented unsigned arithmetic. That temporary value is not used as the next command cursor and does not make a zero-length payload execute.

For a stable first field with value \(w\), the second argument is \(2w\) and the third is \(w\). Since \(w\) is unsigned 16-bit, doubling ranges from 0 through 131070. It is not a 16-bit multiplication that discards the upper bit.

The first field occurs in two argument expressions. The representation does not establish a single shared load, an atomic snapshot, or a complete evaluation order among descriptor-field reads. Relationships between those arguments therefore require stable field contents across the relevant reads.

The seventh argument is character-sized, retaining the low eight bits of the corresponding field under the represented target interpretation. Signedness and subsequent argument extension are unresolved; a value with bit 7 set must not be promised to arrive as a particular positive or negative integer.

## Acceptance examples

These are conditional static criteria, not executed tests. Referenced storage must be accessible, and dependencies must return unless the example states otherwise. Byte preservation is assumed only where explicitly stated.

1. **Unsupported selector.** Selector zero returns without a command-stream read or any listed dependency call. The second input has no effect.

2. **Forced default branch.** With selector 2 or 3, a command byte read as 1 invokes F-7499e6caeab2 with the default-resource binding and 52, even when the original second input is nonzero. That command does not read the descriptor.

3. **Maximum doubled field.** With selector 1, a nonzero second input, and a command byte read as 1, assume the descriptor’s first field remains 65535 across both relevant reads. F-639865e28f2b receives 131070 and 65535 as its second and third arguments.

4. **Empty payload at read time.** After command byte 0 is recognized, assume the length byte is zero when read after F-8163ddbc7a0d and F-aa7d2a3b136c return. There are no F-47d954b1c7a5 calls, and the next cursor is three bytes after the command start. A length byte initially zero does not suffice if either earlier dependency changes it.

5. **Ordered payload.** Suppose command 0’s selector is 7 when read, its length is 2 when read, and its two payload bytes are 18 and 52 at their respective reads. The selector call receives 7, and the payload calls receive 18 then 52. The next cursor is five bytes after the command start.

6. **Packed operands at read time.** After command 3’s acquisition call returns, suppose offsets 4 and 3 yield 205 and 171, respectively, and offsets 1 and 2 yield 18 and 52 when read. F-d22a851ad449 receives 4660, followed by F-524e254fe930 receiving 43981. Changes by the acquisition call before these reads may change either result; changes by the first value’s receiving dependency cannot change the already captured second value.

7. **Cross-boundary operand.** If command 2 is recognized at short-stream offset 7, its operand is read at offset 8 despite the nominal length being 8. If the read and dependency call complete, the next cursor is 9 and the function returns at the next boundary check.

8. **Unsupported command.** If a command-byte read yields 4, the function enters the visible endless loop. It neither advances to another command nor returns normally.

9. **Preliminary mutation.** With selector 4, F-a99a8ca02c77 runs before the long-stream binding is obtained. If it changes that binding and returns, selection uses the subsequently obtained binding. If it does not return, interpretation never starts.
