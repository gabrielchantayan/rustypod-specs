# F-10361f7952ce

## Purpose

F-10361f7952ce describes an indefinitely repeated sequence of indirect calls, selector-directed byte writes, and 32-bit memory transfers. Call results determine subsequent addresses, payloads, arguments, and state carried into the next iteration.

No application-level purpose is established. The evidence does not identify the accessed storage as ordinary objects, device registers, allocation metadata, or an instruction stream. “Selector,” “payload,” and “propagation” below describe observable relationships, not storage types or intended semantics.

This is a conditional behavioral contract for the supplied static representation. Unresolved entry state and indirect dependencies prevent treating it as a fully specified, conventionally callable API. If every dependency returns and every access completes, execution continues indefinitely.

### Widths and arithmetic

The representation distinguishes unsigned 8-bit reads, 8-bit writes, 32-bit reads and writes, and results represented as 64-bit quantities. A byte write retains the low eight bits. A represented wide result is separated into low and high 32-bit components; this does not establish its actual machine-level return convention.

For conditional numerical descriptions:

- Scaling and left shifts retain the low 32 bits.
- Address arithmetic uses the resulting 32-bit bit pattern.
- **Field extraction** clears the top two bits of a 32-bit value, then shifts it unsigned right by 20. Its range is 0–1023.
- **High-fragment extraction** shifts a 32-bit value unsigned right by 22.
- An **indexed byte write** first reads an unsigned selector byte, then writes at absolute address selector + 17. Its destination range is 17–272.

These are explicit bit-vector conventions, not a claim that every signed-looking expression has portable language semantics. Exact instruction behavior, address width, and overflow interpretation remain documented uncertainties.

## Behavior

### Ordering and dependency notation

All visible calls are indirect and are designated through opaque dependency ID **F-DEP-001**. That ID denotes unresolved call occurrences, not one established common target.

A **result group** below consists of three consecutive calls with no explicitly represented arguments, followed by a fourth call whose result is used. Calls described as having no explicit arguments may still consume machine state; they are not established zero-input functions.

The phases preserve the order of direct memory operations and the call/result relationships between them. Calls are observable boundaries. No dependency is assumed to preserve globals, selector storage, or other accessible memory.

### 1. Entry write and initial word pair

An iteration begins by reading the byte at current selector base + 1. The current entry byte is written at that selector’s indexed byte destination. Both inputs are unresolved initially; subsequent iterations use the carried base and entry byte zero.

A call receives the current first argument. A result group follows. Four times its result becomes the **initial propagated word**, which is stored at current fourth argument × 4096 + 20.

The next call has four explicit arguments, in order:

1. Current fourth argument × 1024.
2. The same value.
3. Current carried quantity shifted left by 12.
4. Initial propagated word.

A result group supplies a destination selector for a second word store. The same initial propagated word is written at that result × 4 + 20, after which a call receives that result × 4.

### 2. Two further word pairs

A result group supplies a new seed. Four times the seed is stored at seed × 16 + 20. A call receives this propagated word in all three explicit argument positions.

Another result group supplies the second destination. The same word is stored at result × 4 + 20, followed by a call receiving result × 4.

This sequence repeats with a distinct seed and payload:

- A result group supplies the seed.
- Seed × 4 is stored at seed × 16 + 20.
- A call receives that payload three times.
- Another result group supplies a second destination.
- The payload is stored at result × 4 + 20.
- A call receives result × 4.

Two values from this second sequence remain significant:

- **Quarter-space base:** its first seed × \(2^{30}\).
- **Single-bit seed:** its later, second-destination result.

Under the stated 32-bit convention, the quarter-space base depends only on its seed’s low two bits. The single-bit seed later supplies a word containing either zero or only the top bit.

### 3. Repeated clears, single-bit store, and lookup

A result group supplies the **lookup selector**. The function writes zero first at quarter-space base + 17, then at quarter-space base + 1.

A call receives lookup selector × 4. A following call produces an opaque value, which is passed to another call. A result group follows.

The same two direct byte clears occur again, in the same order. They remain separately observable because calls intervene. A call receives the latest result × 4, followed by another result group.

The result of this last group is the **single-bit destination seed**. Its scaled value, **retained single-bit destination argument**, is four times that seed. Both relationships matter independently of later results.

The function then performs, in order:

1. A 32-bit store of single-bit seed shifted left by 31 at single-bit destination seed × 16 + 20.
2. A 32-bit read at field extraction of lookup selector + 20.

The lookup address ranges from 20 through 1043 and need not be word-aligned.

A call receives the retained single-bit destination argument. The next call produces the **later word payload**. A subsequent call receives the lookup word’s high fragment shifted left by 28.

A result group then supplies a distinct **zero-word destination seed**. Zero is stored as a 32-bit word at that seed × 4 + 20, and a call receives that seed × 4.

The zero-word destination seed does not replace the retained single-bit destination argument. The latter remains the value reused at the start of phase 5.

### 4. Selector-directed updates and saved-selector store

A result group supplies the **byte-update value**.

The function reads the selector at quarter-space base + 1 and writes the low byte of byte-update value × 4 at its indexed destination. A call receives byte-update value × 4. Another call produces an opaque value; the following call receives that value and byte-update value shifted left by 30.

After a result group, the selector at quarter-space base + 1 is read again and saved. The low byte of the field extraction of the byte-update value is written at saved selector + 17.

A call receives the latest group result × 4. Four calls with no explicitly represented arguments follow. The function then stores later word payload × 4 as a 32-bit word at saved selector + 20.

This word-store address uses the saved byte, not a fresh selector read. Intervening modifications to the selector’s source address therefore do not, by themselves, change this destination.

The globally addressed 32-bit value is sampled next, after that word store and before phase 5’s first call.

### 5. Retained argument, global-derived byte, and first wide result

The first call receives the **retained single-bit destination argument from phase 3**: four times the earlier result that selected the single-bit word-store destination immediately before the lookup read. It does not receive four times the later zero-word destination seed.

A result group supplies a result represented as 64 bits. Its low 32-bit component × 4 becomes the **first wide-derived word**.

The function reads the selector at quarter-space base + 1 and writes the low byte of the previously sampled global value’s high fragment at its indexed destination.

A call receives the wide result’s high 32-bit component. Another call produces an opaque value. The next call receives that value and first wide-derived word shifted left by 28.

After a result group, the selector at quarter-space base + 1 is freshly read, and zero is written at its indexed destination. A call receives the latest result × 4.

Another result group follows. A call receives that group’s result × 4 in both explicit argument positions.

### 6. Second propagated word and further wide results

A result group supplies a seed whose value × 4 becomes the **second propagated word**. That word is stored at first wide-derived word × 4096 + 20. A call receives first wide-derived word shifted left by 14.

A result group supplies a second destination. The same second propagated word is stored at result × 4 + 20, followed by a call receiving result × 4.

Another result group supplies a result represented as 64 bits. Its low component × 4 becomes the **second wide-derived word**.

The function reads an unsigned selector byte at first wide-derived word × 16384 + 1. It writes the low byte of the field extraction of the second propagated word at that selector’s indexed destination.

A call receives the second wide result’s high component. Another call produces an opaque value, passed to a following call.

The next call produces another represented 64-bit result. Its low and high components are passed, in that order, to a two-argument call. One call with no explicit arguments follows, then a result-producing call.

### 7. Final clears and word propagation

The selector at second wide-derived word × \(2^{28}\) + 1 is read, and zero is written at its indexed destination. A call receives the latest result × 4.

A result group supplies the **final propagation seed**.

The **next selector base** is second wide-derived word × 4. Its byte at offset 1 is read, and zero is written at the corresponding indexed destination.

A call receives second wide-derived word shifted left by 10. Another call produces an opaque value. The following call receives that value and the later word payload from phase 3 shifted left by 28.

A result group follows. The selector at next selector base + 1 is read again, and zero is written at its indexed destination. A call receives the latest result × 4. Four calls with no explicit arguments follow.

The **final propagated word** is final propagation seed shifted left by 14. It is stored at (final propagation seed × 4) × 4096 + 20.

A call receives (final propagation seed × 4) shifted left by 14. One call with no explicit arguments follows. A two-argument call then receives:

- Final propagated word shifted left by 28.
- An unresolved register-derived 32-bit value.

Under the stated bit-vector convention, the first argument is zero: the combined left shifts discard every original bit. No value is established for the second argument.

A result group supplies the second destination for the final propagated word. That word is stored at result × 4 + 20, followed by a call receiving result × 4.

### 8. Transition to the next iteration

A result group supplies a seed whose value × 4 becomes the **next carried quantity**.

The function freshly reads the selector at next selector base + 1. It writes the low byte of the field extraction of the final propagated word at the indexed destination.

The fourth argument is replaced by the next carried quantity. A call receives final propagation seed shifted left by 26. Another call produces an opaque value. The next call receives that value and the new fourth argument shifted left by 28.

The following call produces a represented 64-bit result. The next iteration’s entry byte is set to zero. The result’s low and high components are passed, in order, to another call.

One call with no explicit arguments follows. A final result-producing call supplies the next first argument after scaling by four.

Execution repeats with the next selector base and carried quantity. The first-call target basis on this repeated path is established at the preceding iteration’s end, rather than taken from the unresolved initial control value.

## Acceptance examples

These are conditional static expectations, not executed tests. Numerical examples use the stated 32-bit convention and assume execution reaches the indicated operations.

1. **Entry selector.** If the initial selector read returns 7, the destination is address 24. The written byte is the unresolved entry byte, not necessarily zero.

2. **Initial propagation.** If phase 1’s first result-group result is 3 and the fourth argument is 2, the first word is 12 and its destination is 8212. The next call receives 2048, 2048, carried quantity shifted left by 12, and 12.

3. **Retained argument distinguished from later result.** Suppose phase 3’s single-bit destination seed is 5 and its later zero-word destination seed is 9. The single-bit store targets address 100; the zero-word store targets address 56. The call immediately after the lookup receives 20, and phase 5’s first call also receives 20—not 36.

4. **Unaligned lookup.** If the lookup selector is \(2^{20}\), field extraction yields 1 and the word read begins at address 21. Rounding it to 20 or 24 changes the represented access.

5. **Saved selector.** If phase 4 saves selector 9, its later word store targets address 29 even if an intervening dependency changes the selector’s source byte to 12.

6. **Fresh selector.** If two specified reads return 9 and then 12, the corresponding indexed byte destinations are 26 and 29. Reusing the first selector for both writes changes behavior.

7. **Byte truncation.** A byte-update value of 255 produces scaled value 1020, but its first indexed byte write stores 252.

8. **Single-bit payload.** An odd single-bit seed produces word \(2^{31}\); an even seed produces zero.

9. **Global sample timing.** If the global value is sampled as \(2^{22}\), the phase-5 global-derived byte is 1. A later dependency change to global storage does not replace that already sampled value in the represented expression.

10. **No zero-result exit.** Zero dependency results do not select a visible termination branch. Continued successful accesses and returning calls lead to another iteration.

11. **Partial effects.** If a dependency does not return after a completed store, the remaining sequence is not reached and no visible rollback restores the prior memory value.
