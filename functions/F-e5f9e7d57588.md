# F-e5f9e7d57588

## Purpose

F-e5f9e7d57588 scans length-prefixed records in a caller-designated buffer region. It recognizes selected record classes, accumulates presence bits in caller-owned state, and stores selected scalars, payload locations, and lengths in caller-owned output storage.

Validation failures select an entry-sampled record status. **They stop scanning only when that status is nonzero.** A common-length failure leaves the cursor unchanged; a class-specific size failure occurs after the cursor has advanced. If the sampled status is zero, either failure permits continued scanning, with different consequences for progress.

When another eight-byte header is unavailable, successful completion requires exact exhaustion of the declared region and a mode-dependent set of presence bits.

The evidence establishes parsing operations, not a named format or the semantic meaning of its fields.

## Behavior

### Record layout and arithmetic

The local scan cursor starts at zero and is not written back to state.

Each record begins with:

| Record-relative bytes | Meaning |
|---|---|
| 0–3 | Unsigned 32-bit total length, big-endian |
| 4–7 | 32-bit tag, big-endian |

Total length includes the eight-byte header. Payload length, where used, is total length minus eight.

The observed arithmetic uses 32-bit results. Cursor, record-end, location, and recognition calculations are described here as bit-pattern operations modulo \(2^{32}\). Length comparisons are unsigned. The explicit tag-ordering comparison uses signed 32-bit interpretations.

This describes the supplied representation; it is not a claim that arbitrary signed-overflow expressions have portable language-level semantics.

### Entry and header availability

The record status is sampled before either explicit argument rejection. If the state pointer or buffer base is zero, the function returns the argument status without dereferencing state or accessing output.

Before each header, the function checks whether cursor plus eight wraps and whether the resulting unsigned value exceeds the current declared region length. A wrapping addition prevents a header read. Otherwise, the region-length comparison uses state word 7 at that point.

When a complete header is unavailable, the function applies the completion rule below.

For an available header:

- State word 8 supplies the region origin.
- The record location is the 32-bit sum of that origin and the current cursor.
- Header byte 3 is read first and retained.
- The total length is decoded using that retained byte and bytes 0–2.
- The tag is then decoded from bytes 4–7.

The evidence does not establish an evaluation order among the other byte reads within each decoding expression. The decoded length, decoded tag, retained byte 3, and computed record location are used afterward; extraction does not resample the entire header.

### Common validation and cursor advancement

A record passes common validation only if:

1. Its unsigned total length exceeds seven.
2. Its computed unsigned record end is no greater than the current state word 7.

The record end is cursor plus total length. Unlike the header-availability check, this addition has no separate overflow rejection. A wrapped end can pass.

Common-validation failure selects the entry-sampled record status without advancing the cursor or performing class processing.

Common-validation success advances the cursor to the computed end **before** recognition, class-specific size checks, or output extraction. Subsequent class rejection does not undo this advancement.

### Recognition reads and retained calculations

Seven global recognition locations are designated \(A,B,D,E,F,G,H\). These are labels for storage locations, not fixed numeric values or function identifiers. Reads of one location at different stages need not return the same value.

Recognition has the following read and reuse structure:

- \(A\) is read for the initial tag-equality test.
- Only if equality fails, \(A\) is read again for the signed-order comparison.
- Only if that comparison selects the greater-than branch, \(A\) is read a third time for its initial recognition calculation.
- In the remaining-tag branch, \(B\) is read for an equality test. Only if that test fails is \(B\) read again for the subsequent difference calculation.

The greater-than branch initially computes and retains:

\[
\text{tag} - \text{newly read }A - \text{read }F.
\]

If this retained difference is nonzero, the function reads \(G\), adds it to that retained value, and retains the updated result. Only if the updated result is also nonzero does it read \(H\) and test the sum with that updated result.

Thus later recognition tests reuse arithmetic already performed. They do not reread \(A\) or \(F\), and the test involving \(H\) does not reread \(G\).

In the remaining-tag branch, after the \(B\)-equality test fails, the function computes and retains:

\[
\text{tag} - \text{newly read }B + \text{read }D.
\]

Only if this retained result is nonzero does it read \(E\) and test the sum of \(E\) and that result. This final test does not reread \(B\) or \(D\).

These dependencies establish which calculations are reused, but do not establish an evaluation order between global operand reads within the same arithmetic expression. In particular, no order is asserted between the third \(A\) read and the \(F\) read, or between the second \(B\) read and the \(D\) read.

### Initial equality class: bounded byte string

If the decoded tag equals the value from the first \(A\) read, this class takes priority and no later recognition branch is evaluated.

Its effects are:

1. OR `0x200` into state word 0.
2. Store the payload location in output word 5.
3. Scan payload bytes for zero, using output word 6 as the exposed count.

For stable, non-overlapping memory, the final count is the first zero byte’s payload-relative index, or the payload length if no zero occurs. A terminator is not required.

Each iteration writes the current count to output word 6, reads that word back, and checks whether total length is no greater than count plus eight. A payload byte is read only if that bound check permits it. If the byte is nonzero, the next iteration uses an incremented count.

Consequently:

- An empty payload produces count zero without a payload-byte read.
- A zero byte is not included in the count.
- The scan does not read beyond the payload under stable, non-overlapping conditions.
- The function neither copies the bytes nor inserts a terminator.

If output aliases other relevant storage or is externally modified, the count readback matters; the simple minimum-of-length-and-terminator description is not an unconditional snapshot guarantee.

### Signed-greater branch

After initial equality fails, this branch is selected only when the signed tag exceeds the signed value from the **second** \(A\) read.

Let the initial retained difference be the result involving the **third** \(A\) read and \(F\), as described above.

| Recognition outcome | Required total length | Effects |
|---|---|---|
| Initial retained difference is zero | Any length passing common validation | OR `0x800` into flags; write payload length to output word 8, then payload location to word 7 |
| Difference becomes zero after adding \(G\) | Divisible by eight | OR `0x100` into flags; write payload length to output word 4, then payload location to word 3 |
| Updated difference plus \(H\) is zero | Exactly 12 | OR `0x20` into flags; decode four payload bytes as a big-endian scalar into output word 0 |

The divisibility test uses the low three bits of the retained header byte 3. With an ordinary stable header read, this is equivalent to total length being divisible by eight. Later changes to that header byte do not change the retained test input.

A recognized aligned-length or scalar class with an invalid size selects the sampled record status and performs none of that class’s flag or output writes.

If none of the recognition tests succeeds, the record is skipped without a class-specific error.

### Remaining-tag branch

This branch is reached when initial equality fails and the signed-greater comparison does not select the preceding branch. Its meaning depends on the actual values returned by the first two \(A\) reads, not on a single assumed snapshot.

| Recognition outcome | Required total length | Effects |
|---|---|---|
| Tag equals the first \(B\) read | Any length passing common validation | OR `0x400` into flags; no output write |
| Retained difference involving the second \(B\) read and \(D\) is zero | Exactly 24 | OR `0x80` into flags; write payload location to output word 2 |
| That retained difference plus \(E\) is zero | Exactly 12 | OR `0x40` into flags; decode four payload bytes as a big-endian scalar into output word 1 |

Wrong sizes for either fixed-size class select the sampled record status without that class’s flag or output writes. Unrecognized tags are skipped.

### Continuation and completion

The pending status starts at zero. Accepted and unrecognized records preserve it. Validation failures replace it with the entry-sampled record status.

A nonzero pending status returns immediately, without another header read or completion check. A zero pending status permits scanning to continue:

- After a class-size failure, the cursor already points to the computed record end.
- After a common-length failure, the cursor remains unchanged. A stable invalid header can therefore be inspected indefinitely.

When another complete header is unavailable, completion requires both:

1. The cursor equals the current declared region length exactly.
2. Current state flags contain every required bit.

The required mask is `0x3e0` for mode zero and `0x320` for any nonzero mode. Extra bits are permitted. The flag check is reached only if cursor equality succeeds.

Successful completion returns zero in the lower result half. Otherwise, the completion status is read and returned. A zero completion status can therefore make a failed completion condition indistinguishable from success in the returned bits.

## Side effects

State and output updates are incremental, with no rollback on later failure.

Flags are not cleared on entry. Output words for absent classes are untouched. Under non-overlapping use, repeated classes overwrite their corresponding outputs while accumulating flags.

Observable ordering includes:

- Entry sampling of record status precedes argument rejection.
- Cursor advancement precedes class-specific size validation.
- Each recognized class updates its flag before its output operations.
- Each payload-length/location pair stores length before location.
- Scalar classes update their flags before payload reads and the scalar store.
- The bounded-string class stores its location before beginning count writes, readbacks, and byte checks.

Flag updates are read-modify-write operations; atomicity is not established. A flag write can affect a later payload read when storage overlaps. Likewise, output writes can affect later state, buffer, or global reads through aliasing. Already decoded header values and retained recognition intermediates are not retroactively changed by such writes.

No allocation, release, ownership transfer, explicit buffer write, or payload copy is visible. Stored offsets do not extend buffer lifetime. Consumers must keep the referenced storage available while using them.

Synchronization and concurrent-modification guarantees are not established.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless specified otherwise, memory is accessible, stable, non-overlapping, and address calculations do not wrap.

1. **Argument rejection.** A zero state pointer or buffer base returns argument status in the lower half and mode in the upper half. Record status has already been sampled; no output is accessed.

2. **Empty successful region.** Region length zero, mode zero, and preexisting flags containing `0x3e0` produce a zero lower half without a header read. No records need appear in this call.

3. **Nonzero-mode success.** An empty region with mode 1 and flags containing `0x320` returns upper half 1 and lower half zero.

4. **Trailing fragment.** If accepted records leave four bytes before the declared end, completion selects completion status even when all required flags are present.

5. **Unrecognized record.** An eight-byte record whose tag matches no applicable recognition test advances the cursor by eight without changing flags or output.

6. **Scalar extraction.** A correctly selected 12-byte scalar record containing payload bytes `01 23 45 67` stores `0x01234567` in its designated scalar word. A later failure does not undo it.

7. **Bounded string.** A tag matching the first \(A\) read, total length eleven, and payload `41 00 42` produces count one. Replacing the zero with a nonzero byte produces count three without requiring a fourth payload byte.

8. **Class-size failure with nonzero record status.** A selected 24-byte class presented with total length sixteen advances the cursor, then returns record status without setting `0x80` or writing output word 2.

9. **Class-size failure with zero record status.** With that same record, sampled record status zero, declared length sixteen, and sufficient preexisting completion flags, scanning reaches exact exhaustion and returns a zero lower half despite the rejected class.

10. **Common-length failure with zero record status.** A stable header with total length below eight leaves the cursor unchanged. If sampled record status is zero, the function can repeat the same failed inspection indefinitely.

11. **Wrapped record end.** At cursor eight, total length `0xffffffff` computes end seven. With declared length sixteen, common validation accepts that end. Safe subsequent memory access is not implied.

12. **Separate \(A\) reads.** If permitted environmental changes yield \(A\) values 0, 50, and 80 for the equality, ordering, and difference reads, respectively, tag 100 fails equality and enters the signed-greater branch. An \(F\) value of 20 makes the retained initial difference zero, selecting the unrestricted-length class.

13. **Separate \(B\) reads.** Suppose tag 10 reaches the remaining branch. A first \(B\) read of 11 fails equality; a second \(B\) read of 15 and \(D=5\) produce a zero retained difference. With total length 24, the fixed-size payload-location class is selected.

14. **Retained arithmetic.** In the signed-greater branch, an initial retained difference of 10, followed by \(G=20\), yields retained value 30. An \(H\) read of `0xffffffe2` makes the final sum zero. With total length 12, the scalar class is selected. Changes to \(A\), \(F\), or \(G\) after their relevant reads do not cause those operands to be reread for this final test.
