# F-fe7764814f8f

## Behavior

### Ordered initialization before the dependency call

The visible sequence is:

1. Write a 32-bit zero at destination offset 0.
2. Write a 32-bit zero at destination offset 16.
3. Write a 32-bit zero at destination offset 20.
4. Write an 8-bit zero at destination offset 24.
5. Read one byte through the source-byte address and write that byte at destination offset 25.
6. Write a 32-bit zero at destination offset 12.
7. Write a 32-bit zero at destination offset 8.
8. Write a 32-bit zero at destination offset 4.

The byte is read at step 5, not captured at entry. This distinction matters if the source-byte address aliases the destination.

If the operations complete without interference, the dependency receives a destination whose six 32-bit fields at offsets 0 through 20 are zero, whose byte at offset 24 is zero, and whose byte at offset 25 contains the value observed by step 5.

This describes the state immediately before the dependency call. It is not a guarantee that these values survive the dependency.

### Dependency invocation

F-ffe3c25e7ae8 is called once with the destination address as its sole visible argument.

The caller does not visibly pass the source-byte address separately. The copied byte is available through the destination, but whether the dependency reads it is unknown.

No visible condition skips this call after successful completion of the preceding operations.

### Ordered processing after the dependency returns

After the dependency returns:

1. Its 32-bit result is stored at destination offset 16.
2. A 32-bit zero is written at offset 4 from the address represented by that result.
3. A 32-bit write is performed at offset 8 from an address read from destination offset 16. The value written is also obtained from destination offset 16.
4. A corresponding 32-bit write is performed at offset 12, again using the field at destination offset 16.
5. The original destination address is returned.

The first associated-region write uses the captured dependency result. The later writes reference the stored field at destination offset 16 rather than relying solely on that captured result.

This distinction matters when writes overlap the destination. In particular, the write at offset 4 from the returned address could change destination offset 16 before the subsequent operations read it.

For the writes at offsets 8 and 12, the supplied evidence does not establish a separate observable ordering between obtaining the destination address and obtaining the value from the same field. No dependency call occurs between those accesses.

### Ordinary non-overlapping outcome

If the dependency returns normally, its result denotes suitable storage, the relevant regions do not overlap, and no external agent changes the relevant memory:

- Destination offset 16 contains the dependency result.
- The associated region contains zero at offset 4.
- Its fields at offsets 8 and 12 each contain the dependency result.
- The returned address equals the destination address.

Other destination fields retain their pre-call initialization values only if the dependency leaves them unchanged. This function does not restore those fields after the call.

### Source aliasing

The source-byte address may point into the destination; no explicit prohibition or protective copy is visible.

Consequences depend on the preceding writes:

- If it points to destination offset 24, the byte read is zero because that location has already been cleared.
- If it points into the 32-bit fields at offsets 0, 16, or 20, it observes a byte from a field already cleared to zero, under the ordinary zero representation.
- If it points into the fields at offsets 4, 8, or 12, it is read before those fields are cleared. The copied value can therefore reflect their entry state.
- If it points to destination offset 25, that byte is read and written back before the later initialization writes.

These are consequences of the access order, not special-case branches.
