# F-ed4541f0c348

## Purpose

F-ed4541f0c348 performs a two-stage check using a caller-supplied context and an indirectly referenced object. Either stage can assign a 32-bit value to a context field and invoke a callback stored in that context.

The established result convention is:

- Return **0** when an invoked callback returns exactly zero.
- Return **1** when a callback returns nonzero, subject to the first-stage continuation rules, or when execution reaches the end without a zero callback result.

The first stage can invoke the callback and then continue into the second stage. The second stage invokes the callback at most once and returns immediately afterward.

The values written to the context appear to identify the condition being reported. Their application-level meanings, and whether the overall result represents success, failure, acceptance, or rejection, are not established.

## Interface

### Arguments

The function receives four machine-word arguments:

| Argument | Established use |
|---|---|
| Context address | Base address for a flags word, a callback address, and a writable 32-bit field. Also passed to the callback. |
| Indirect-object address | Address of a slot containing an object address. Fields of that object supply handles to dependencies. |
| Conversion input | A 32-bit value passed to F-3be1fe46711f. Its returned word becomes an addressable lookup input. |
| Auxiliary word | A 32-bit value saved in local storage, with no explicit later use by the function itself. |

The supplied representation uses 32-bit words and address values. No portable interface for wider pointers is established.

### Result

The normal return value is a 32-bit word whose value is always **0** or **1**.

The function does not directly return a dependency result, callback result, collection size, or element address.

### Referenced layouts

The context is accessed at these byte offsets:

| Offset | Width | Access and interpretation |
|---|---:|---|
| `0x1C` | 32 bits | Flags word; mask `0x10` controls whether the second-stage scan is skipped. |
| `0x28` | 32-bit address | Callback entry point, loaded when a callback is about to be invoked. |
| `0x5C` | 32 bits | Writable field assigned `0x17` or `0x24` before the corresponding callback. |

The indirect-object argument points to a 32-bit address slot. The object reached through that slot is accessed at:

| Offset | Width | Use |
|---|---:|---|
| `0x14` | 32 bits | First argument to F-8fbbf5288d61. |
| `0x18` | 32 bits | Collection handle used by the second stage. |

Each element address returned by F-6bbddce1b930 is used to read a **signed 32-bit integer** at byte offset `0x04`.

No other object fields are explicitly accessed.

### Preconditions

For execution to complete normally, every address actually accessed must be valid for the indicated operation. In particular:

- The context must support the reads and writes reached on the selected path.
- The indirect-object slot and the object fields reached through it must be readable.
- Every invoked callback address must identify a callable target compatible with the observed invocation.
- Every element examined by the second stage must support a 32-bit read at offset `0x04`.
- Dependencies and callbacks must return normally if normal completion is required.

There are no explicit null checks, bounds checks on object storage, callback-validity checks, or exception-recovery operations in this function.

## Behavior

### 1. Prepare the first-stage input

The function saves the supplied argument values into local storage. It then calls F-3be1fe46711f with the conversion input.

The returned 32-bit word replaces the first word of the local scratch storage. The address of that word is subsequently passed to F-8fbbf5288d61.

The conversion call occurs **before** the function reads the object address through the indirect-object argument. Consequently, mutations performed by F-3be1fe46711f can affect that later read. The function does not establish that the conversion dependency is pure.

The explicit first-stage input is an addressable 32-bit word. Although additional saved arguments appear alongside it in the supplied representation, a larger aggregate interface is not established; see **Uncertainties**.

### 2. Perform the first-stage lookup

After the conversion returns, the function:

1. Reads the object address from the indirect-object slot.
2. Reads the 32-bit field at object offset `0x14`.
3. Calls F-8fbbf5288d61 with that field value and the address of the scratch word.

Its result is interpreted as a **signed 32-bit integer**.

If the result is negative, the first-stage callback is skipped and execution proceeds to the second-stage gate.

If the result is zero or positive, the function:

1. Writes the 32-bit value `0x17` to context offset `0x5C`.
2. Loads the callback address from context offset `0x28`.
3. Invokes that callback with two arguments: the word value **0**, followed by the context address.
4. Interprets the callback result as zero versus nonzero.

A zero callback result causes an immediate return of **0**. No flags read or second-stage scan follows on that path.

A nonzero callback result does **not** immediately determine the final result. Execution continues to the second-stage gate.

The callback address is loaded after the `0x17` write. There is no cached callback address established before that write.

### 3. Apply the second-stage gate

The function reads the 32-bit flags word at context offset `0x1C` and tests mask `0x10`.

- If the masked bit is set, the function skips the collection scan and returns **1**.
- If the masked bit is clear, the function begins the collection scan.

This flags read occurs after any first-stage callback has returned. A change to the flags word made by that callback can therefore affect whether scanning occurs.

No other flag bits participate in this decision.

### 4. Acquire the collection handle

When scanning is enabled, the function reads the object address through the indirect-object slot again, then reads the 32-bit field at that object’s offset `0x18`.

This is a fresh read of the indirect-object slot, not reuse of the object address read for the first stage. A dependency or callback that changes that slot can therefore cause the two stages to use different objects.

The collection handle obtained at this point is retained for the scan. The function does not explicitly reload object offset `0x18` on each iteration.

### 5. Scan using a freshly queried bound

The scan index begins at signed value **0**.

Before each possible element access, the function calls F-10b760faca36 with the retained collection handle. Its return is interpreted as a signed 32-bit bound.

An element is examined only when the current signed index is strictly less than that newly returned bound.

Consequences include:

- A bound of zero or any negative value prevents an element access when the index is zero.
- The bound is queried repeatedly rather than captured once.
- Changes in the bound can terminate or extend the scan.
- A final bound query occurs when evaluating the condition that ends an ordinary scan.

When the current index is below the bound, the function calls F-6bbddce1b930 with the collection handle and index. It then reads the signed 32-bit value at offset `0x04` of the returned element address.

- A zero or negative element value does not trigger the callback. The index advances by one, and the bound is queried again.
- A strictly positive element value triggers the second-stage callback.

The function provides no independent consistency check between the bound query and element retrieval. Any guarantees needed to make retrieval valid must come from the dependencies and their surrounding execution environment.

### 6. Report the first qualifying element

For the first examined element whose signed field is greater than zero, the function:

1. Writes the 32-bit value `0x24` to context offset `0x5C`.
2. Loads the callback address from context offset `0x28`.
3. Invokes it with the word value **0** and the context address.
4. Returns **0** if that callback returned zero, otherwise **1**.

No later element is examined.

The callback address is loaded afresh for this invocation. It need not be the same address used for the first-stage callback if intervening execution changed the context.

### 7. Complete without a qualifying element

If a bound query ends the scan before a positive element field is found, the function returns **1**.

It does not write a “no match” value to context offset `0x5C`. That field retains whatever value is then present, which may include changes made by dependencies or callbacks.

## Side effects

### Direct writes

The explicit nonlocal writes performed by this function are:

- `0x17` at context offset `0x5C`, when the first-stage lookup result is nonnegative.
- `0x24` at the same offset, when a scanned element has a strictly positive signed field.

Both writes are 32 bits wide. If both stages invoke callbacks, the function’s direct writes occur in that order.

Neither value is restored before return. However, the function does not guarantee that its last written value remains present: a callback can modify the field afterward.

The function also initializes local scratch storage and supplies an address into that storage to F-8fbbf5288d61. That dependency’s possible writes through the address are not established here.

### Callback and dependency effects

The function can invoke the context callback zero, one, or two times during a normally completing invocation.

It does not save and restore the context, referenced object, collection, callback field, or global state around dependency calls. Their mutation behavior must not be assumed away.

Observable sequencing matters:

- Conversion precedes the first indirect-object read.
- The first-stage callback, if invoked and nonzero, precedes the flags read.
- The flags read precedes acquisition of the scan handle.
- Each bound query precedes its corresponding element retrieval.
- Each context-field write precedes the associated callback-address load.

### Ownership and lifetime

No explicit allocation, deallocation, reference-count update, or ownership transfer is performed by this function.

Passing a handle or pointer to a dependency does not establish that the dependency borrows, retains, releases, or takes ownership of it. In particular, the lifetime rules for the local scratch address passed to F-8fbbf5288d61 are unknown beyond its availability during that call.

### Errors

Negative first-stage results do not produce a dedicated error return; they merely bypass the first-stage callback.

Nonpositive collection bounds end or prevent scanning according to the signed comparison. Negative element fields are treated like zero for qualification purposes.

There is no explicit handling for invalid memory, an invalid callback target, abnormal dependency termination, or inconsistent collection state.

## Acceptance examples

These are conditional behavioral examples, not executed tests. All assume valid reached memory accesses and normally returning dependencies.

1. **First-stage zero is an immediate exit.**  
   F-8fbbf5288d61 returns zero. The function writes `0x17` and invokes the callback. If the callback returns zero, the function returns **0** without reading the flags word or querying the collection.

2. **A negative lookup can still lead to a successful scan trigger.**  
   The first-stage result is negative and mask `0x10` is clear. Bound queries permit indices 0, 1, and 2; their element fields are respectively `0`, `-4`, and `7`. Only index 2 triggers a callback. The function writes `0x24` and returns according to that callback’s zero/nonzero result.

3. **The flag suppresses scanning, not the first stage.**  
   Mask `0x10` is set when the gate is reached. The function returns **1** without acquiring a collection handle. A first-stage callback may already have occurred.

4. **A nonzero first callback does not force return 1.**  
   The first-stage callback returns nonzero. Scanning remains enabled and finds a qualifying element. If the second callback returns zero, the final result is **0**.

5. **An empty or negative bound does not retrieve an element.**  
   Scanning is enabled, but the initial bound is zero or negative. F-6bbddce1b930 is not called, no `0x24` write occurs, and the function returns **1**.

6. **The bound is not a snapshot.**  
   The initial bound permits index 0, whose element field is nonpositive. The next bound query returns 1. At index 1 the strict comparison fails, so no element at index 1 is retrieved.

7. **Only the first positive element is reported.**  
   Index 0 has a positive field. Regardless of later elements, the function writes `0x24`, invokes the callback once for the scan, and returns without another bound query.

8. **Signedness changes qualification.**  
   An element field with bit pattern `0x80000000` is negative as a signed 32-bit integer and does not qualify. The same pattern as a bound prevents the initial scan iteration. As a first-stage result, it bypasses the first-stage callback.

9. **Callback mutation can change the next stage.**  
   The first callback returns nonzero after setting mask `0x10` in the context. The subsequent gate observes that set bit and returns **1** without scanning.

## Uncertainties

The following are **documented_only**:

- Application meanings of `0x17`, `0x24`, the tested flag, and the final Boolean-like result.
- Exact calling conventions and declared types beyond the observed 32-bit representation.
- The full memory contract of the scratch pointer supplied to F-8fbbf5288d61. The supplied representation shows four saved argument words, with the first replaced by the conversion result, but does not establish an authoritative aggregate layout or the dependency’s access extent.
- Dependency and callback ownership rules, global-state effects, reentrancy, and synchronization.
- Collection behavior if state changes between bound evaluation and element retrieval.
- Behavior if index advancement exceeds the signed 32-bit range. No overflow guard or defined wraparound policy is established.
- Behavior under aliasing that causes a context-field write to affect another subsequently read location. The access order is established, but disjointness of caller-provided storage is not.
- Abnormal completion and invalid-address behavior.
