# F-730119a90fb4

## Purpose

F-730119a90fb4 conditionally constructs a descriptor and publishes it at the head of a list belonging to a captured table-like object. The descriptor associates local column indices with optional referenced-column name storage, a referenced-object name region, and three action bytes.

The foreign-key interpretation is **inferred intent**, supported by diagnostic categories and data relationships. Established behavior consists of eligibility checks, count validation, allocation, name-comparison and byte-transfer calls, explicit memory writes, publication, and cleanup.

The function returns no value. Construction may be skipped, rejected by a diagnostic, abandoned after allocation failure, or completed by publication. Cleanup occurs on all normally continuing paths, including skipped construction. Cleanup can invoke a non-returning integrity-failure dependency after publication has already occurred.

Actual byte-copy semantics are not established: the body invokes an unidentified external primitive with destination, source, and length arguments. References below to successful name copying are conditional on that primitive providing the presumed transfer behavior.

## Interface

### Arguments and widths

The visible interface uses five arguments in a 32-bit pointer and word model:

| Argument | Required visible structure |
|---|---|
| Context | Pointer to context storage described below |
| Local-column list | Nullable pointer to a count-and-array structure |
| Referenced-name descriptor | Pointer containing a source pointer and encoded length |
| Referenced-column list | Nullable pointer to a count-and-array structure with compatible allocator metadata |
| Action word | 32-bit value; only bits 0–23 are extracted |

The context has these accessed fields:

| Offset | Width | Use |
|---|---:|---|
| `+0x00` | 32 bits | Allocation-context argument |
| `+0x40` | 32 bits | Construction inhibitor |
| `+0x180` | Pointer | Current table |
| `+0x198` | 8 bits | Additional construction inhibitor |

Both list structures expose a 32-bit count at `+0x00` and an array pointer at `+0x0C`. Entries occupy 12 bytes. Their word at `+0x04` supplies a name pointer. During referenced-list cleanup, the first word is also passed to a dependency; the third word is not directly consumed.

The referenced-name descriptor contains a source pointer at `+0x00` and a 32-bit encoded length at `+0x04`. Every length observation uses the unsigned encoded value shifted right by one. The low bit is excluded.

The captured table exposes:

| Offset | Width | Use |
|---|---:|---|
| `+0x04` | 32 bits | Column count, compared as signed in traversal |
| `+0x08` | Pointer | Array of 20-byte column records |
| `+0x24` | Pointer | Descriptor-list head |

Each column record’s first word supplies its name pointer.

### Descriptor layout

For captured mapping count \(n\), construction initially assigns the following layout:

| Offset | Width | Assigned value |
|---|---:|---|
| `+0x00` | Pointer | Captured table |
| `+0x04` | Pointer | Table’s list head observed after allocation |
| `+0x08` | Pointer | Referenced-object name region |
| `+0x0C` | 32 bits | Zero |
| `+0x10` | 32 bits | \(n\) |
| `+0x14` | Pointer | Mapping array, initially descriptor `+0x1C` |
| `+0x18` | 8 bits | Zero |
| `+0x19` | 8 bits | Action bits 8–15 |
| `+0x1A` | 8 bits | Action bits 0–7 |
| `+0x1B` | 8 bits | Action bits 16–23 |

Each mapping occupies eight bytes: a local index followed by an optional referenced-name pointer. The referenced-object name region initially begins at descriptor offset \(28+8n\).

Without a referenced-column list, mapping second words receive no explicit initialization here. No zero value is guaranteed. Dependencies may also mutate already initialized storage; the table describes direct assignments, not unconditional final-state guarantees.

### Preconditions

Defined successful use requires valid storage for every reached access, consistent array extents, suitable allocator metadata, and representable size and address arithmetic. Non-null names passed to length or comparison dependencies must satisfy those dependencies’ contracts.

There are no general pointer, bounds, positive-count, or overflow checks. A non-null referenced list must meet the explicit allocator-release requirements, even when construction is ineligible.

Dependency return and preservation properties are not assumed. Conditional examples below expressly state stronger stability assumptions where needed.

## Behavior

### Eligibility and count selection

The function first reads and captures the context’s table pointer. A null pointer skips construction.

Otherwise it reads the context word at `+0x40`. Only if that word is zero does it read the byte at `+0x198`. Either nonzero inhibitor skips construction. Skipped paths issue no direct construction diagnostic and proceed to cleanup.

The captured table pointer is not refreshed after calls.

Without a local-column list:

- The table count is read and reduced by one.
- A negative signed result skips construction without a direct diagnostic.
- If a referenced list exists, its count must equal the 32-bit value one.
- A mismatch invokes F-2022b0f73f3b with context, the last column’s currently obtained name, and the referenced-name descriptor, then proceeds to cleanup.
- Otherwise the mapping count is one.

With a local-column list, the two list counts are compared for equality when the referenced list exists. A mismatch invokes F-2022b0f73f3b and proceeds to cleanup. The local count is subsequently read to capture \(n\). Zero is not rejected. Negative signed counts are not expressly rejected either.

Count comparisons establish equality only at their observation points. They do not guarantee that later dependency calls leave counts unchanged.

### Sizing and allocation

Let \(L_{\mathrm{size}}\) be the first decoded referenced-name length observation. The initial allocation-size expression is:

\[
29+8n+L_{\mathrm{size}}.
\]

For a non-null referenced list, sizing then traverses entries in order while the signed index is less than a freshly read signed list count. Each iteration rereads the list’s array pointer, obtains that entry’s name, calls F-1cb585febd84, and adds its returned length plus one.

The function calls F-f053f140662a with the context’s first word and the resulting size. A null result proceeds directly to cleanup without a direct allocation-failure diagnostic.

All relevant words and addresses are 32-bit. The body establishes no overflow rejection or safe interpretation of excessive or negative size expressions. In particular, a high-bit-set count can suppress signed traversal while still affecting allocation arithmetic. Such inputs are not established as safe.

### Initial assignments and independent length observations

After a non-null allocation, the function:

1. Stores the captured table pointer.
2. Reads the table’s current list head and stores it as the predecessor.
3. Computes the referenced-object destination from the allocation and captured \(n\).
4. Stores the mapping-array pointer and referenced-object destination pointer.
5. Invokes the unidentified transfer primitive.
6. Writes a terminating zero byte.
7. Establishes a subsequent string cursor.
8. Stores zero at `+0x0C` and the captured mapping count at `+0x10`.

Four distinct encoded-length observations matter:

| Observation | When obtained | Use |
|---|---|---|
| \(L_{\mathrm{size}}\) | Before sizing dependencies and allocation | Initial allocation size |
| \(L_{\mathrm{call}}\) | For the transfer invocation | Length argument |
| \(L_{\mathrm{term}}\) | After that invocation returns | Address of the explicit terminating zero |
| \(L_{\mathrm{cursor}}\) | After the zero write | Initial cursor for subsequent names |

The transfer invocation receives the computed destination, the source pointer obtained from the referenced-name descriptor, and \(L_{\mathrm{call}}\).

The zero byte is written at destination plus \(L_{\mathrm{term}}\). The cursor is separately set to destination plus \(L_{\mathrm{cursor}}\). The body does not enforce equality among these four lengths. In particular, the external primitive is not known to preserve the referenced-name descriptor.

Thus neither allocation coverage nor agreement between the presumed transferred extent, terminator position, and subsequent cursor is unconditional.

### Local-column resolution

For an explicit local list, the outer traversal uses captured \(n\), interpreted through signed comparison. Each requested position scans table columns upward from index zero.

Every inner-loop condition rereads the table count. For each comparison call, the function rereads the table-array pointer and the requested-list array pointer, then obtains their corresponding name pointers. F-e6db2171781a receives the table name followed by the requested name.

A zero result causes the selected index to be written through the descriptor’s then-current mapping-array pointer, followed by exit from the inner loop.

**A matching comparison is not sufficient for acceptance.** After either a match or loop exhaustion, the function rereads the table count. If that signed count is less than or equal to the selected or exhausted index, it invokes F-2022b0f73f3b and abandons publication. The diagnostic’s requested-name argument comes from another read of the local list’s array and name.

Consequently, a dependency that reduces the table count can cause rejection after a matching index has already been written. With stable table contents, counts, requested names, and comparison semantics, resolution selects the earliest matching column. Without that stability, no snapshot-based earliest-match guarantee is established.

Without an explicit local list, the function rereads the table count after allocation and initial name processing, subtracts one, and writes that result as the first mapping index. It does not repeat the earlier nonnegative check.

### Referenced-name entries and publication

With a referenced list, the name-storage loop uses captured \(n\), not the list’s current count.

The string cursor is incremented before each loop-condition evaluation, including the final unsuccessful evaluation. For each accepted iteration:

1. Read the referenced array and entry name, then obtain a length from F-1cb585febd84.
2. Store the current destination through a fresh read of the descriptor’s mapping-array pointer.
3. Reread the referenced array and entry name for the transfer invocation.
4. Invoke the unidentified primitive with destination, that source, and the saved length.
5. Write zero at destination plus the saved length.
6. Advance the cursor by that length.

The source supplied to the transfer need not be the source measured before the length call. Sizing lengths and per-entry transfer lengths are also independent observations.

After required processing, action bytes are written in this order: `+0x18`, `+0x1A`, `+0x19`, `+0x1B`. The function then stores the allocation pointer into the captured table’s head field. This is publication.

The pending-allocation cleanup pointer is cleared immediately afterward. No explicit rollback follows if cleanup later fails.

## Side effects

### Common cleanup and ownership boundary

All normally continuing paths execute:

1. F-94cb53877c15 with the pending unlinked allocation, or null.
2. F-e5380ae57ea1 with the local-list argument, including null.
3. Return if the referenced list is null; otherwise continue its cleanup.

The body treats publication as transfer of the descriptor out of pending cleanup. Actual allocation ownership and release semantics of dependencies remain unestablished. Callers cannot infer that either input list remains usable.

For referenced entries, the array pointer is captured once for traversal. Each signed loop condition rereads the list count. Each entry’s first word is passed to F-841dc33ee157; afterward its second word is read and passed to F-94cb53877c15. The traversal advances by 12 bytes.

Afterward, a fresh read of the list’s array pointer is passed to F-94cb53877c15. Mutation can therefore make this differ from the traversed array.

### Global accounting adjustment

After array cleanup:

- The global accounting-base pointer is read and captured.
- The recovery distance is read from four bytes before the referenced-list pointer.
- Subtracting that distance from the list pointer yields a recovered address \(R\).
- A 32-bit quantity \(Q\) is read at \(R-8\).

The body additionally rereads the global accounting-base pointer to obtain the low-word location at `+0x38` and the high-word operand location at `+0x3C`. No dependency call intervenes in these accounting operations. The high-word destination uses the initially captured base.

Let \(A\) be the observed low word, \(H\) the high-word operand, and \(b\) be one if unsigned \(A<Q\), otherwise zero. The writes are, in order:

\[
\text{low}\leftarrow A-Q
\]

\[
\text{high}\leftarrow H-(s+b),
\]

where \(s=0\) when \(Q\)’s high bit is clear and \(s=-1\) when it is set. These word results have 32-bit width. This is not ordinary subtraction of an unsigned 32-bit \(Q\) from an unsigned 64-bit counter for every possible \(Q\).

F-2fd8826557a4 is then called. Only after it returns is the global allocator-context pointer read and captured as \(C\).

### Explicit allocator-state mutations

If \(R=8\), the function returns without the following block-header operations.

Otherwise the header is at \(R-0x10\). Its word must be nonzero and have its low bit clear. The body performs these validation observations before calling F-c0fc6d033caa. Invalid metadata invokes non-returning F-a817d8d58c10.

On the valid path, F-c0fc6d033caa receives captured \(C\). After it returns:

- An unsigned 16-bit selector \(a\) is read at \(R-0x0C\).
- The header is reread and masked with `0x3FFFFFFC`, producing size \(S\).
- An unsigned 16-bit selector \(d\) is read at \(R-0x0A\), after the first two counter subtractions.

The ordered 32-bit state updates are:

| Order | Location | Change |
|---:|---|---|

| 2 | \(C+0x30C\) | Subtract saved \(S\) |

## Acceptance examples

These are conditional static expectations, not executed tests. Unless explicitly varied, assume valid storage, representable arithmetic, stable inputs and globals across dependencies, normal returns, and a transfer primitive that copies exactly the requested bytes.

1. **Ineligible context.** A null table causes no descriptor allocation or construction diagnostic. Common cleanup still runs, including referenced-list allocator operations when applicable.

2. **Implicit mapping.** A three-column table with no local list and one referenced entry produces mapping count one and local index two after successful construction.

3. **Empty implicit table.** Table count zero causes construction to be skipped before allocation. A nonempty table with two referenced entries instead produces a count diagnostic.

4. **Explicit mismatch.** Local count two and referenced count one produce a diagnostic before allocation.

5. **Stable duplicate names.** Table names “key”, “value”, “key” resolve a matching request to index zero. Duplicate requests are not rejected.

6. **Match invalidated by mutation.** A comparison at index two returns zero but reduces the table count to two. Index two is written; the post-search check then diagnoses failure. The allocation is not published.

7. **Independent object lengths.** Suppose the sizing length is three, the transfer argument length is three, the primitive changes the encoded length to ten, and it remains ten afterward. The explicit zero and initial subsequent cursor use destination plus ten, not plus three. Safety requires independently adequate storage.

8. **Changed referenced source.** A length call measures one source and changes the entry name pointer. The subsequent transfer receives the newly read source with the previously returned length.

9. **Action placement.** `0xA1B2C3D4` assigns `0xC3`, `0xD4`, and `0xB2` at `+0x19`, `+0x1A`, and `+0x1B`. The high byte is ignored.

10. **Empty or unnamed mappings.** Matching explicit zero counts can publish a zero-mapping descriptor. With no referenced list, mapping second words have no established initialization value.

11. **Allocator mutation boundaries.** If F-c0fc6d033caa changes metadata, the subsequent selectors and size reflect the later reads without revalidation. If F-09dcb55e8e0a then changes the header size, only the final size subtraction uses that fresh value.

12. **Failure after publication.** A referenced-list header integrity failure occurs after successful head insertion. No direct rollback precedes the non-returning failure call.
