### Initial updates and read-back

The initial memory effects establish several order-sensitive relationships.

First, the high-shift token is stored as a word at final-high-word offset 0x14. Its offset-9 byte receives the final high word’s low byte. The scaled base is then stored at offset 0x54 from 256 times the final low word, after which the high-shift token’s offset-9 byte receives the token’s own low byte.

Next, scaled-base offset 0x14 is cleared as a word before an unsigned byte is read from scaled-base offset 5. Selector-base offset 0x14 is cleared, then that byte is widened and stored as a word at scaled-base offset 0x34.

The word at scaled-base offset 0x14 is subsequently read back. Another selector-base word clear follows. Two separate byte stores then copy the read-back word’s low byte to selector-base offset 0x15.

These stores remain distinct even when values repeat. The read-back is not an unconditional zero: intervening aliasing, mapped-memory behavior, or external mutation may affect it.

### Fixed-address milestones within computed-address processing

Fixed and computed addresses are not presumed independent. The following milestones preserve the fixed operations’ positions relative to surrounding computed accesses.

**Fixed address 5 and fixed address 1.** After the two selector-base offset-0x15 byte stores, the function reads an unsigned byte from fixed address 5. Call its widened value the **low-address base**. Only afterward does it write the selector base’s low byte to fixed address 1.

That fixed-address write precedes the following computed effects, in order:

- Low-address-base offset 0x15 receives the selector’s low byte.
- Scaled-base offset 0x11 receives the byte-aligned token’s low byte.
- Offset 0x54 from the earlier read-back word receives the byte-aligned token as a word.
- Scaled-base offset 0x11 is overwritten with zero.

A word is then loaded from low-address-base offset 0x54. Call this saved word the **relationship word**. The same location is overwritten with the earlier read-back word; selector-base offset 0x34 receives the selector as a word.

**Fixed address 0x54.** Before this fixed store, the function loads a word from scaled-base offset 0x74 and uses it as a base. Its offset 0x54 first receives the scale input shifted left by 26. An offset-0x74 relationship through the selector base also supplies bases and values for a word store.

The relationship word is twice stored at its own offset 0x24; the scaled-base-derived destination’s offset-9 byte twice receives its low byte. Between those repetitions, that destination’s offset 0x54 receives the byte-aligned token. Selector-base offset 0x14 then receives the scale input shifted left by 26.

Only then does fixed address 0x54 receive a **word equal to the relationship word shifted left once**. This is not a constant store.

**Fixed address 0x15.** After the fixed-address-0x54 store, selector-base offset 0x14 receives the relationship word twice. Two separate byte stores at selector-base offset 0x15 then receive the low byte of four times the relationship word. Fixed address 0x15 subsequently receives the **selector base’s low byte**, before the next computed offset-0x54 word store.

The calculation of four times the relationship word and its two-bit-left-shifted form both occur in this region; their unconditional equivalence is not assumed for signed expressions.

## Acceptance examples

These are conditional examples, not runtime results.

### Multiplication is not signed left shift

For scale input −1, ordinary signed 32-bit multiplication by 0x2000000 yields −33554432 without multiplication overflow. This does not justify replacing it with signed left shift of a negative operand.

For input 64, the signed product exceeds the positive 32-bit range. A wrapped result requires an explicit bit-vector assumption.

### Selector and overwrite

Under truncating 32-bit arithmetic, selector input 0x12345678 produces selector 0x1e0 and selector base 0x3c0.

Under the same interpretation, high-shift-token offset 9 receives the final high word’s low byte first and zero later. Checking only the final byte misses required ordering.

### Fixed-address interaction

If fixed address 5 returns 0xfe, the low-address base is 254, not a negative value. That read precedes fixed address 1’s write. Even if computed accesses overlap either address, this ordering is not reversed.

### Loaded-word fixed store

Given relationship word 3 and defined arithmetic, fixed address 0x54 receives word 6 at its specified milestone. The fixed-address-0x15 byte later receives the selector base’s low byte, not the relationship word’s low byte.

### Global-read timing

If the fixed-address-0x60 store overlaps global storage, the repeated-publication base still comes from the preceding global read. It is not obtained by rereading the modified storage.

### Finalization aliasing

If fixed address 0x3a overlaps the later final-relationship-base offset-0x14 read, that saved word may include the byte write’s effect. The earlier constant-base offset-0x74 read does not include that intervening effect.

### Intermediate writes and failure

A write-sensitive observer sees publication-base offset 0x20 receive 0x20, 0x2f, the widened offset-4 byte, and 0x20 separately.
