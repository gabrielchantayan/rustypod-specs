# F-0ce6e03f9d03

## Purpose

F-0ce6e03f9d03 conditionally invokes a registered callback after resolving a source index and selecting a resource descriptor. It supplies six callback arguments assembled from caller state, the selected descriptor, and indexed data.

The callback’s 32-bit result determines the function’s subsequent direct action:

| Result | Direct action |
|---|---|
| 0 | Return without writing the status or operation marker. |
| 1 | Invoke F-2022b0f73f3b with a selected diagnostic template, then write status 23. |
| 2 | Write operation-marker byte 0x5C. |
| Any other value | Invoke F-2022b0f73f3b with an unresolved global operand and the callback result, then write status 1. |

An authorization-related purpose is inferred from diagnostic labels and the callback structure. The established contract is the observable selection, invocation, and result handling below; the callback’s actual policy is unknown.

## Behavior

### Entry gates

The function first reads and retains the owner address from context offset 0. Later owner accesses use that captured address, not a fresh read of context offset 0.

It reads the callback field at captured-owner offset 224:

- Zero causes immediate return.
- Nonzero permits reading the operation marker.

The marker must equal signed byte value −107, corresponding to bit pattern 0x95 in the represented signed-byte interpretation. Any other marker causes immediate return.

Neither early-return path directly writes context or operation memory.

### Source-index resolution

After both gates pass, F-49f750c2c596 is invoked with six positional arguments:

1. Captured owner address.
2. Opaque input.
3. Constant 149, or 0x95.
4. Lookup-data pointer.
5. Opaque input again.
6. Lookup-data pointer again.

The dependency returns a 64-bit quantity. Its low 32 bits are interpreted as a signed source index.

A negative source index causes immediate return. A nonnegative source index permits descriptor selection and may later index the source-descriptor array.

The upper 32 bits do not affect subsequent observable behavior. Although the representation extracts them, subsequent relevant uses replace that temporary value.

No preservation guarantee is established for F-49f750c2c596. Its effects remain observable even if a negative result ends processing. In particular, later accesses must not be described as using pre-resolution snapshots of the operation, lookup data, callback registration, or context fields.

### Lookup search and final classification

The entry index starts at zero.

At each search-bound check:

1. A null lookup-data pointer admits no entry and ends the search.
2. Otherwise, the signed 16-bit count is read.
3. If the count is less than or equal to the current entry index, the search ends without reading that entry’s key.
4. Otherwise, the operation key at offset 36 is read, followed by the candidate entry’s 32-bit key.
5. Equal keys end the search; unequal keys advance the index by one.

Thus, with stable memory, a nonpositive count admits no entries, and a positive count admits indices zero through count minus one. Entries are considered in ascending order, and the first equal key ends the search.

The operation key is read for each comparison rather than captured before the loop. The count is also reread during bound checks.

After the search ends, the function checks whether the final index is admitted by the lookup count. For nonnull lookup data, this check reads the signed 16-bit count again. If the final index is nonnegative and strictly below that newly read count, the descriptor pointer at \(20 + 48j\) is selected.

With stable memory, that final condition identifies the first matching entry. With changing memory, it is a separate classification: a count change can invalidate a previously matched index or admit an index whose key was not compared. The final check does not repeat the key comparison.

The signed 16-bit count limits search progression to at most index 32,767. The entry-index multiplication and fixed-offset calculations therefore remain within signed 32-bit range before addition to the lookup-data base. Validity of the resulting address is still a caller-side requirement.

### Fallback selection

Fallback is attempted only if the final lookup classification does not select an entry.

The function performs these accesses in order:

1. Read context offset 392 and test that observed word for nonzero.
2. If it was nonzero, read context offset 392 again.
3. Use the second observed word as an address and read the 32-bit descriptor pointer stored there.

The first observed address is not retained as a guaranteed snapshot for the dereference. Using that same address is only a stable-memory simplification. If the two reads differ, the second value determines the dereference; no second null check is established.

If the first read is zero, no fallback-pointer slot is dereferenced and the selected descriptor remains null.

If lookup classification selects an entry, fallback is bypassed even when that entry’s descriptor pointer is null.

After selection, a null descriptor causes return without invoking the callback.

### Selector-derived argument

For a nonnull descriptor, the function reads the signed 32-bit requested selector from operation offset 40.

- A nonnegative requested selector is used directly.
- A negative requested selector is replaced by the descriptor’s signed 32-bit default at offset 12.

If the effective selector is nonnegative, the function reads the selector-array base from descriptor offset 8, then reads the first 32-bit word at:

\[
\text{selector-array base} + 20 \times \text{effective selector}
\]

That word becomes the fourth callback argument.

If the requested selector and default selector are both negative, a fixed static address becomes the fourth callback argument instead. The selector-array base and element are not read on that path. A source label suggests row-identifier text at this address, but its underlying bytes are not supplied.

No upper-bound or multiplication-overflow check is present for selector indexing.

### Callback-result handling

The callback result is handled as a 32-bit integer.

**Result 0:** Return immediately, without a direct status or marker write.

**Result 2:** Write byte 0x5C to operation offset 0, then return. This function does not directly change other operation bytes or context status on this path.

**Result 1:** Select one of two static diagnostic-template addresses using two distinct reads of captured-owner offset 4:

1. The first signed 32-bit reading establishes an initial choice according to whether it equals 2.
2. The second signed 32-bit reading is compared with 3.
3. If the second reading is less than 3, the choice is replaced according to whether the resolved source index equals zero.

The first template is selected when the resulting condition is true; otherwise the second is selected.

With stable owner memory, the first template is selected exactly when the owner field is below 3 and the source index is zero. With differing readings, the full two-read rule applies; for example, a first reading of 2 followed by a reading of 3 retains the first-template choice.

F-2022b0f73f3b is then invoked with the context and selected template. After it returns normally, the function writes 23 to context offset 4.

**Any other result:** After the callback returns, the function evaluates an unresolved named global operand and supplies it as the second argument to F-2022b0f73f3b. The first argument is the context; the third is the callback result.

The global’s declaration and underlying data are absent. It is not established whether this expression supplies a loaded scalar or an address, nor whether its value is immutable. It must not be characterized as a fixed diagnostic value or as a value captured before the callback.

After F-2022b0f73f3b returns normally, the function writes 1 to context offset 4.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, they assume valid memory, stable fields, suitable address arithmetic, and dependencies that return normally.

1. **Disabled callback:** A zero initial callback field causes return before the operation marker is read or any dependency is called.

2. **Different marker:** A nonzero callback field with a marker other than the represented 0x95 value causes return without calling a dependency.

3. **Negative resolution:** A resolver result whose low word represents −1 causes return before lookup selection. Resolver effects are not undone.

4. **First duplicate wins:** Two admitted entries have the operation key. The lower-index entry supplies the descriptor.

5. **Matched null:** The first matching entry contains a null descriptor pointer. No fallback-field read or callback follows.

6. **Stable fallback:** A zero or negative count leads to fallback. Both reads of context offset 392 yield the same nonzero slot address; the pointer stored in that slot becomes the descriptor.

7. **Changing fallback field:** The first fallback-field read yields one nonzero slot address, while the second yields another. The descriptor pointer is read from the second address. If the second value is null, safe execution is not established.

8. **Null lookup data:** If the resolver accepts null lookup data and returns a nonnegative source index, lookup entries are skipped and fallback is attempted.

9. **Count changes before final classification:** The search stops because index zero is not admitted. If the final count read now admits index zero, its descriptor pointer is selected without a key comparison on that search pass.

10. **Nonnegative default:** A negative requested selector and default selector 4 select the word at selector-array byte offset 80.

11. **Both selectors negative:** The fixed static address is used without reading the selector array.

12. **Result 2:** The marker becomes 0x5C. No direct status write occurs.

13. **Result 1:** Stable owner value 1 and source index zero select the first template. Status becomes 23 only after the diagnostic call returns.

14. **Unexpected negative result:** Callback result −7 takes the generic diagnostic path. Its second argument comes from the unresolved global operand evaluated after the callback; −7 is the third argument. Status becomes 1 after diagnostic completion.
