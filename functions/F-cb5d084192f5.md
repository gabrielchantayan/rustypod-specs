# F-cb5d084192f5

## Purpose

F-cb5d084192f5 conditionally connects a queried 32-bit value to two operations selected through the caller-supplied object.

The established behavior is:

- Obtain an object reference from F-938c950e5046.
- Invoke an operation selected through that object’s dispatch table.
- Stop if that operation returns the 32-bit value −1.
- Otherwise, pass the returned value to an operation selected through the supplied object.
- Pass the resulting four-byte value to a second operation selected through the supplied object.

The function exposes no explicit return value.

An interpretation such as “query a selection, resolve it, then apply it” is plausible intent, not an established contract. The available evidence does not identify what the queried value represents, what the intermediate result contains, or what the final operation does.

## Behavior

### Dependency and query stage

The first operation is a call to F-938c950e5046 with no explicit arguments in the supplied representation.

After it returns, F-cb5d084192f5 uses the returned address to read an object header containing a dispatch-table address. It then obtains a callable target from byte offset +0x168 of that table and invokes it.

The query invocation has no explicit arguments in the supplied representation. In particular, the evidence does not show the returned object reference being passed as an explicit receiver. An implementation or specification must not silently add such an argument based solely on an assumed object-oriented convention.

The query produces the 32-bit value used for the branch decision.

### Sentinel branch

If the query result equals −1, F-cb5d084192f5 returns without performing either of its two dispatches through the supplied argument.

This comparison is exact. It does not reject every negative value, zero, or any broader range. For example, a query result of −2 follows the non-sentinel path.

The branch does not undo any effects of F-938c950e5046 or the query operation. Both have already executed.

### Non-sentinel branch

If the query result differs from −1, the function performs the following operations in order:

1. Read the dispatch-table address from the supplied object.
2. Resolve the callable target at byte offset +0x130.
3. Invoke that target with two explicit arguments: the supplied object reference and the query result.
4. Retain the four-byte result of that invocation.
5. Read the dispatch-table address from the supplied object again.
6. Resolve the callable target at byte offset +0x13c using this later table address.
7. Invoke that target with two explicit arguments: the supplied object reference and the retained four-byte result.

The second object-header read occurs after the first supplied-object operation returns. Consequently, the last target is selected from the object’s then-current dispatch-table address, not necessarily the table used for the preceding operation.

This distinction is observable if the first operation changes the supplied object’s dispatch-table address. The evidence does not permit assuming that either the object header or the table contents remain unchanged across dependency calls.

The query result is passed to the first supplied-object operation without any visible range adjustment, clamping, or arithmetic transformation. The resulting four-byte value is passed to the final operation without any visible interpretation or validation.
