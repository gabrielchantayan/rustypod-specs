# F-262044357f22

## Purpose

F-262044357f22 performs a bounded scan of fixed-stride records, accumulating one 32-bit value from each record until one of three conditions occurs:

- The newly accumulated value is strictly greater than an unsigned threshold.
- A record supplies a zero value.
- The scan reaches a bound selected by a 16-bit field in a separate object.

It reports a 32-bit accumulated value, a 32-bit record index, a one-byte termination indicator, and a 32-bit return value.

The established behavior is a bounded accumulation and comparison operation. Interpreting the record values as lengths, the threshold as a capacity, or the return values as named status codes would be inferred intent, not an established contract.

## Interface

The function has seven inputs, three of which designate writable output locations.

| Position | Contract name | Representation and role |
|---|---|---|
| 1 | Selector object | Address of an object whose 16-bit field at byte offset 2 selects the scan bound. |
| 2 | Threshold | Unsigned 32-bit value used for strict comparison with each newly computed accumulated value. |
| 3 | Record area | Address of records separated by an 8-byte stride. The function reads a 32-bit value at byte offset 4 within each visited record. |
| 4 | Initial total | Unsigned 32-bit starting value written to the accumulated-value output before scanning. |
| 5 | Index output | Address of a writable 32-bit output. |
| 6 | Total output | Address of a readable and writable 32-bit output. This location also supplies the accumulator value at every processed record. |
| 7 | Indicator output | Address of a writable one-byte output. |

The return value is 32 bits. The only explicitly produced return values are:

- **0:** a newly computed total was strictly greater than the threshold.
- **16:** the scan ended without taking that greater-than return path.

These values are described numerically because no symbolic status meanings are established.

### Memory layout

The selector object must provide a readable 16-bit field beginning at byte offset 2. A field value equal to **0x482B** selects a bound of eight records; every other value selects a bound of three records.

For record index \(k\), the accessed field starts at byte offset \(8k + 4\) from the record-area address and occupies four bytes. The function does not explicitly read the first four bytes of a record.

Consequently:

- A three-record scan can access fields beginning at offsets 4, 12, and 20.
- An eight-record scan can additionally access fields beginning at offsets 28, 36, 44, 52, and 60.

The last possible field occupies bytes 60 through 63 relative to the record-area address. Earlier termination can avoid later accesses.

The numeric selector comparison does not establish a portable byte sequence. Byte order and the target’s alignment requirements are not specified by the supplied material.

For defined execution, each memory access actually reached must be valid for its width and operation. In particular:

- The selector field must be readable after those writes.
- Each visited record field must be readable.
- The total output must remain readable and writable during accumulation.

No null-pointer checks, range checks on the supplied addresses, allocation checks, or explicit memory-failure handling are present.

## Behavior

### Initialization and bound selection

The first explicit memory effect is a four-byte write of the initial total to the total output.

The next explicit memory effect is a one-byte write of zero to the indicator output.

Only after those writes does the function read the selector’s 16-bit field. It selects a scan bound of eight for 0x482B and three otherwise. The selected bound is then retained for the scan; the selector is not read again.

This ordering matters if an output overlaps the selector. In that situation, bound selection observes the selector field after the initialization writes, not necessarily its value on entry.

The scan begins at record index zero.

### Record processing

Before each record-field read, the function checks whether the current index is below the selected bound. Once the bound is reached, no additional record field is read.

For an in-range record:

1. Its four-byte field at offset 4 within the record is read.
2. If the field is zero, scanning ends immediately without adding it.
3. If the field is nonzero, the current four-byte value in the total output is read.
4. The record value is added using unsigned 32-bit arithmetic.
5. The resulting 32-bit value is written to the total output.
6. That computed value is compared with the threshold using an unsigned, strict greater-than comparison.

The total output is therefore working state, not merely a final destination. In particular, the first accumulation reads the location after both initialization writes, including any effect of overlap with the indicator output.

A total equal to the threshold does not cause the return value zero.

### Arithmetic

The record field is represented as a signed 32-bit quantity when read, but addition to the unsigned 32-bit total converts it to its corresponding unsigned value. The resulting addition is modulo \(2^{32}\).

For a current total \(T\) and a record field with 32-bit unsigned interpretation \(V\), the stored result is:

\[
(T + V) \bmod 2^{32}
\]

The comparison uses this wrapped result. There is no separate overflow check, saturation, wider mathematical sum, or requirement that totals increase.

A field with its high bit set is still nonzero and participates in accumulation. For example, the bit pattern 0xFFFFFFFF contributes 4,294,967,295 modulo \(2^{32}\), which is equivalent to subtracting one modulo \(2^{32}\).

The initial total is not independently compared with the threshold.

### Greater-than termination

If a newly computed total is greater than the threshold:

- The total output has already received that computed value.
- The current zero-based record index is written to the index output.
- The function returns 0 immediately.
- No subsequent record is read.
- No explicit indicator write occurs after its initialization.

Thus the index identifies the record whose contribution produced the greater-than result. It is not the count of successfully processed records and does not identify the preceding record.

For non-overlapping outputs, the indicator remains zero on this path.

### Zero-field or bound termination

If scanning ends without a greater-than result, the function writes the index output as follows:

- If no nonzero record was processed, it writes zero.
- Otherwise, it writes the index of the last nonzero record processed.

It then distinguishes the termination condition:

- If the current scan index is still below the selected bound, a zero field caused termination. The indicator output is written with one.
- If the selected bound was reached, no further indicator write occurs.

The function then returns 16.

For non-overlapping outputs:

| Termination condition | Return | Index output | Indicator output |
|---|---:|---:|---:|
| First field is zero | 16 | 0 | 1 |
| Zero after one or more processed records | 16 | Last processed index | 1 |
| All permitted records processed | 16 | Bound minus one | 0 |
| Newly computed total exceeds threshold | 0 | Triggering record index | 0 |

The index alone cannot distinguish an immediate zero field from processing record zero and then stopping. The indicator also does not, by itself, distinguish bound exhaustion from greater-than termination; the return value is needed.

## Side effects

### Explicit memory effects

The supplied body establishes these access-order constraints:

- Initial total write precedes indicator initialization.
- Indicator initialization precedes selector-field reading.
- Each visited record-field read precedes the corresponding accumulator read and write.
- A new total is stored before its greater-than comparison determines termination.
- The index output is written only on a termination path.
- On zero-field termination, the index write precedes the final indicator write of one.

No rollback occurs when the function returns zero. The triggering addition remains stored, subject to any overlap with the subsequent index write.

No explicit writes target the selector or record area as such. However, output writes can modify either if their storage overlaps.

### Overlapping storage

The function contains no separation checks. Therefore, with overlapping storage, the usual meanings of the three final outputs are not guaranteed to coexist.

Examples of ordering consequences include:

- If the indicator overlaps the total, indicator initialization can change a byte of the initial total before the first accumulation.
- If an output overlaps a future record field, a write can change a later field before it is read.
- If the index output overlaps the total, the terminating index write can replace some or all of the accumulated value.
- On zero-field termination, the final one-byte indicator write can alter an overlapping index or total after the index has been written.

The threshold comparison uses the computed 32-bit result associated with the accumulator write; it is not specified as a fresh read of the total output after that write.

These consequences describe the supplied access sequence. Whether particular overlapping or misaligned objects satisfy the target language and platform’s memory-access rules remains unknown.

## Acceptance examples

The following examples are conditional static expectations, not executed tests. Unless otherwise stated, all required storage is valid, outputs are separate from all inputs and one another, and record values refer to the four-byte field at offset 4 within each record.

### 1. Immediate zero field

Given an initial total of 7, threshold 100, and first record value zero:

- No addition occurs.
- Total output is 7.
- Index output is 0.
- Indicator output is 1.
- Return value is 16.
- The second record is not read.

The result is the same for either selected bound.

### 2. Equality does not trigger early return

Given initial total 4, threshold 10, and record values 6 followed by zero:

- The first addition produces 10.
- Equality with the threshold does not cause return 0.
- The second field is read and terminates the scan.
- Final outputs are total 10, index 0, and indicator 1.
- Return value is 16.

### 3. Greater-than result on a later record

Given initial total 1, threshold 10, and record values 4 and 6:

- The first total is 5.
- The second total is 11.
- Total output is 11.
- Index output is 1.
- Indicator output is 0.
- Return value is 0.
- No third record is read.

### 4. Three-record bound

Given a selector field other than 0x482B, initial total 0, threshold 100, and record values 1, 2, and 3:

- All three records are processed.
- Total output is 6.
- Index output is 2.
- Indicator output is 0.
- Return value is 16.
- A fourth field is not read, even if present and zero.

### 5. Eight-record bound

Given selector field 0x482B, initial total 0, threshold 100, and eight record values of 1:

- Total output is 8.
- Index output is 7.
- Indicator output is 0.
- Return value is 16.
- A ninth field is not read.

### 6. Initial total already exceeds the threshold

Given initial total 20, threshold 10, and first record value zero:

- Total output remains 20.
- Index output is 0.
- Indicator output is 1.
- Return value is 16.

This establishes that the initial total alone does not cause return 0.

### 7. Unsigned wraparound

Given initial total 0xFFFFFFFE, threshold 10, and record values 3 followed by zero:

- The first addition wraps to 1.
- The greater-than check does not succeed.
- Final outputs are total 1, index 0, and indicator 1.
- Return value is 16.

The mathematical sum exceeding the 32-bit range does not itself cause an error result.

### 8. High-bit-set record value

Given initial total 5, threshold 10, and record values 0xFFFFFFFF followed by zero:

- The first addition produces 4 modulo \(2^{32}\).
- Final outputs are total 4, index 0, and indicator 1.
- Return value is 16.

No rejection of a negative signed interpretation is performed.

### 9. No unsigned total can exceed the maximum threshold

Given threshold 0xFFFFFFFF and valid accesses:

- No computed unsigned 32-bit total can satisfy the greater-than condition.
- Termination therefore occurs through a zero field or bound exhaustion.
- The return value is 16.

This does not prevent accumulator wraparound.
