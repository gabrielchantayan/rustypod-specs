# F-f7c21c23a4e8

## Purpose

F-f7c21c23a4e8 classifies an ordered pair of 32-bit input words using a key derived from the second word. It selects one of four behaviors:

- Evaluate the original input pair with two stored auxiliary words.
- Reduce the original input into a four-word workspace, then evaluate that workspace.
- Invoke an exceptional handler.
- Issue a notification, then read and return a stored result.

The established contract covers classification, dependency arguments, represented read ordering, workspace consumption, and result forwarding. It does not establish the mathematical meaning of the input pair or result.

**Inferred intent:** Clearing a possible sign bit and selecting a continuation from two low bits suggest numerical range reduction with quadrant-like dispatch. This interpretation is not an acceptance requirement.

## Interface

### Inputs and return value

The routine accepts:

| Input | Width and represented type | Established local use |
|---|---|---|
| First input word | Signed 32-bit integer | Tested for equality with zero on one boundary path; otherwise forwarded |
| Second input word | Unsigned 32-bit integer | Supplies the classification key; otherwise forwarded unchanged |

The result is one 32-bit word of unspecified semantic type.

Dependencies receiving the original input pair receive the first word before the second. Masking the second word for classification does not change the original second word supplied to those dependencies.

The input pair’s encoding, word significance, and byte order are not established. In particular, the evidence does not establish a floating-point or larger-integer interface.

### Referenced stored words

The routine references five 32-bit stored words:

| Contract name | Established use |
|---|---|
| Primary threshold | Initial signed comparison; separately read as a reduction argument |
| Secondary boundary | Equality comparison; separately read for signed ordering if equality fails |
| Special result | Read and returned after notification |
| Auxiliary first word | Third argument of direct evaluation |
| Auxiliary second word | Fourth argument of direct evaluation |

These names describe call-site roles. Their values, initialization, ownership, and intended numerical meanings are unknown.

Repeated uses described as separate reads are distinct accesses in the supplied representation. The primary threshold is not captured once for both classification and reduction. The secondary boundary is not captured once for both equality and ordering.

This distinction does not establish volatility, atomicity, concurrent visibility, or a one-to-one correspondence with machine-level loads.

### Reduction workspace

The reduction path supplies a writable address into invocation-local storage to F-3ebdb2596b90. Subsequent evaluation consumes four 32-bit words with this layout:

## Behavior

### Classification key and initial decision

The classification key is the second input word with bit 31 cleared. Its range is zero through 2,147,483,647 inclusive. It is therefore nonnegative when interpreted as a signed 32-bit integer.

The routine reads the primary threshold and compares it with the key using signed ordering:

- If the key is less than or equal to the threshold, direct evaluation is selected.
- If the key is greater than the threshold, secondary-boundary classification follows.

Equality belongs to direct evaluation. A negative initial threshold sends every possible key to secondary-boundary classification.

The established local arithmetic consists of bit masking and comparisons. No mathematical conversion of the input pair is established, and no overflow-producing addition, subtraction, or multiplication is involved in these decisions.

### Direct evaluation

The direct path performs these represented operations in order:

1. Reads the auxiliary first word into local storage.
2. Reads the auxiliary second word into local storage.
3. Calls F-eaf1de973a81 with the original first input word, original second input word, captured auxiliary first word, captured auxiliary second word, and a fifth 32-bit argument equal to zero.
4. Returns the dependency’s result without an explicit transformation.

The original second word retains its top bit.

This path does not read the secondary boundary, call the reducer, notify, or invoke the exceptional handler. Although the two auxiliary values occupy positions also used by reduced evaluation, direct evaluation does not consume reducer output.

### Secondary-boundary classification

This stage is reached only when the key exceeds the initial primary-threshold value.

The routine first reads the secondary boundary and compares its complete 32-bit representation with the key. The boundary is not masked.

If equality succeeds:

- A zero first input word selects notification followed by a stored-result read.
- A nonzero first input word selects exceptional handling.
- No second boundary read for ordering occurs.

If equality fails, the routine reads the secondary boundary again. It compares the key with this newly read value using signed ordering:

- A key strictly less than the ordering-read value selects reduction.
- A key greater than or equal to the ordering-read value selects exceptional handling.

The equality and ordering reads need not observe the same value. Classification must not be described as comparing against a single cached boundary.

Consequences include:

- A negative boundary value at the equality read cannot equal the nonnegative key.
- A negative equality-read value alone does not force exceptional handling. The ordering read may subsequently observe a value greater than the key.
- A negative ordering-read value selects exceptional handling because the key cannot be strictly less than it.
- If the ordering read equals the key after the equality read differed, exceptional handling is selected. Equality is not retried.
- A boundary that remains negative across both reads selects exceptional handling whenever this stage is reached.

### Notification and stored result

When the key equals the equality-read boundary and the first input word is zero, the routine:

1. Calls F-77dd9f40f9b6 with one 32-bit argument equal to one.
2. After that call returns, reads the special result.
3. Returns the word just read.

The notification dependency’s return value is unused. It receives neither original input word.

The special result is not captured before notification. If notification changes it before returning, the later read can observe that changed value, subject to the storage-access semantics not established here.

No reducer, evaluator, or exceptional handler is called on this path.

### Exceptional handling

F-9f634613286e receives the original first input word, original second input word, and a third 32-bit argument equal to one. Its result is returned unchanged.

This path is selected after entry into secondary-boundary classification when either:

- The equality-read boundary matches the key and the first input word is nonzero; or
- The equality-read boundary differs from the key and the key is not strictly below the signed ordering-read boundary.

There is no explicit result normalization, error-status interpretation, retry, or recovery.

### Reduction and evaluator selection

Reduction requires all three conditions:

- The key exceeds the initial primary-threshold value.
- The key differs from the equality-read boundary.
- The key is strictly below the signed ordering-read boundary.

The routine then reads the primary threshold again and calls F-3ebdb2596b90 with these arguments, in positional order:

1. Original first input word.
2. Original second input word.
3. Writable workspace address.
4. Newly read primary threshold.

The threshold supplied to reduction need not match the threshold used for initial classification. No reclassification follows this later read.

After reduction returns, only the low two bits of its returned word are retained. The resulting selector is in the range zero through three:

| Selector | Evaluator | Arguments |
|---:|---|---|
| 0 | F-eaf1de973a81 | Workspace words at offsets 0, 4, 8, and 12; fifth argument one |
| 1 | F-834cd4b2002a | Workspace words at offsets 0, 4, 8, and 12 |
| 2 | F-eaf1de973a81 | Workspace words at offsets 0, 4, 8, and 12; fifth argument one |
| 3 | F-834cd4b2002a | Workspace words at offsets 0, 4, 8, and 12 |

All higher return bits are ignored for dispatch. A reducer return pattern that another interface might interpret as a negative status or error still selects an evaluator according to these two low bits. No local error-status branch is visible.

The selected evaluator’s result is returned without an explicit transformation. No caller-side negation or other result adjustment distinguishes selectors zero and two, or selectors one and three.

### Selector-specific workspace read ordering

Selector zero has an established partial ordering that the other selectors do not.

For selector zero:

1. The word at workspace offset 0 is read and captured as the first evaluator input.
2. The word at offset 4 is then read and captured as the second evaluator input.
3. Only after those captures are the evaluator’s call arguments evaluated, using the two captured values and the workspace words at offsets 8 and 12.

Thus, the offset-0 read precedes the offset-4 read, and both precede the reads supplying offsets 8 and 12. The relative evaluation order of offsets 8 and 12 is not established.

For selectors one, two, and three, all four workspace words occur directly as evaluator call arguments. Their argument positions establish value placement, not read order. No relative evaluation order among those four reads is established by the supplied representation.

Selectors zero and two therefore share an evaluator and positional argument contract, but not the same established read-order contract. With stable workspace contents, they supply the same four words and fifth argument. If contents can change during argument acquisition, equal acquired values cannot be assumed.

These statements concern the represented accesses; they do not assert exact instruction scheduling or synchronization semantics.

## Side effects

### Established effects and sequencing

The routine reads selected stored words, supplies writable local storage to the reducer, invokes dependencies, and returns a word. It contains no explicit write to the five referenced stored words and no explicit heap allocation or deallocation.

Established sequencing includes:

- Initial threshold classification precedes every dependency call.
- The boundary equality read occurs only after the initial above-threshold decision.
- The boundary ordering read occurs only after equality fails.
- The reduction-argument threshold read occurs after reduction is selected and before the reducer call.
- Direct evaluation captures the auxiliary first word before the auxiliary second word.
- Reduction returns before any workspace values are consumed by an evaluator.
- Selector zero captures workspace offset 0 before offset 4, then acquires offsets 8 and 12 for the evaluator call without an established order between those last two reads.
- Selectors one, two, and three have no established relative ordering among their four workspace argument reads.
- Notification returns before the special result is read.
- An evaluator or exceptional-handler result is forwarded without a subsequent explicit read of the referenced stored words.

No reducer write order is established.

### Dependency effects and ownership

## Acceptance examples

These examples are conditional consequences of static evidence, not observed executions. Unless stated otherwise, assume valid storage, complete workspace initialization on reduction paths, and normal dependency returns.

1. **Initial equality selects direct evaluation.**  
   If the initial threshold equals the key, F-eaf1de973a81 receives the original pair, the two captured auxiliary words, and zero. No boundary read or reduction occurs.

2. **The input’s top bit is preserved outside classification.**  
   Two second input words differing only in bit 31 produce the same key. With matching stored-state observations, their classification decisions match. Dependencies receiving the original pair nevertheless receive different second words. Different reducer outputs can produce different continuations.

3. **Stable interior boundary selects reduction.**  
   With initial threshold 100, key 200, and both boundary reads equal to 300, reduction occurs. A reducer result of zero selects F-eaf1de973a81 with workspace arguments and one.

4. **Boundary reads cannot be collapsed.**  
   With initial threshold 100, key 200, a negative equality-read boundary, and ordering-read boundary 300, reduction occurs. The negative first observation does not determine the ordering decision.

5. **Second-read equality is exceptional.**  
   With initial threshold 100, key 200, and boundary observations 300 then 200, exceptional handling occurs even if the first input word is zero.

6. **Equality success suppresses the ordering read.**  
   If the key exceeds the initial threshold and equals the first boundary observation, zero in the first input selects notification. No ordering-read boundary value is acquired.

7. **Notification precedes result acquisition.**  
   If notification changes the special result before returning and that change is visible to the later read, the changed word is returned. A pre-notification snapshot would not satisfy this ordering contract.

8. **Nonzero first input at boundary equality is exceptional.**  
   When the key exceeds the threshold, matches the equality-read boundary, and the first input is nonzero, F-9f634613286e receives the original pair and one.

9. **A later threshold value is passed to reduction.**  
   If classification reads threshold 100 and the reduction-argument read obtains 150, classification uses 100 and the reducer receives 150. Classification is not repeated.

10. **Selector zero has ordered captures.**  
    After reduction selects zero, offset 0 is captured before offset 4. Both captures precede acquisition of offsets 8 and 12. Either relative order for the latter two reads is consistent with the supplied representation.

11. **Selector two does not inherit selector zero’s ordering.**  
    A reducer result of two selects the same evaluator and fifth argument as zero. It does not establish offset-0-before-offset-4 acquisition: all four workspace words are direct call arguments on that path.

12. **Low-bit equivalence is limited.**  
    Reducer results one and five both select F-834cd4b2002a. Equal final results additionally require matching acquired workspace arguments and compatible dependency behavior. Selectors zero and two likewise share dispatch, but retain their different established read-order contracts.

13. **Incomplete reduction output remains unresolved.**  
    If any consumed workspace word is unestablished, the evidence supplies neither a defined expected argument for that position nor a deterministic final result.
