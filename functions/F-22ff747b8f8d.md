# F-22ff747b8f8d

## Purpose

F-22ff747b8f8d conditionally invokes a downstream operation. It obtains an initial 32-bit value, requests temporary numeric data, applies an input-controlled override, and evaluates a carry-sensitive eligibility condition. If eligible, it adjusts the initial value, passes that adjusted value through another dependency, and invokes the final dependency.

Established outcomes:

- An initial value of zero stops processing and produces a zero return.
- Failed numeric eligibility also produces a zero return.
- Successful eligibility produces exactly the 32-bit result of the final dependency, including zero if that dependency returns zero.

A position, extent, or limit calculation is a possible interpretation of the numeric fields, but that is **inferred intent**, not established application semantics. This contract assigns descriptive numeric names without attributing a domain meaning.

## Behavior

### Initial gate

F-0f1843fcf6e2 is called first, without explicit arguments.

If its 32-bit result is zero, F-22ff747b8f8d returns zero immediately. It does not call the other dependencies or directly read the documented input fields.

For a nonzero result, that same result is retained for subsequent use. It is not reacquired later.

### Population and override

F-200380a3070f is called with these arguments, in positional order:

1. The original input value.
2. The nonzero initial result.
3. The address of the temporary region.

The caller does not inspect a return value from this dependency.

After the call returns, the input byte at `+0x03` is read. A nonzero byte causes explicit zero writes to the temporary low and high components. This is a zero-versus-nonzero test, not a test specifically for one.

The override leaves the increment, threshold, and adjustment unchanged.

The override byte is read after population. Consequently, a mutation of that byte by F-200380a3070f affects this invocation’s decision.

### Eligibility arithmetic

Eligibility uses 32-bit addition, an unsigned carry, a 16-bit unsigned threshold, and signed interpretation of the updated high component.

First, the low component and increment are added as unsigned 32-bit values. Two consequences of this addition matter:

- The low sum is the result reduced modulo \(2^{32}\).
- The carry is one if the mathematical sum exceeds `0xFFFFFFFF`, and zero otherwise.

The carry is added to the high component, retaining the resulting 32-bit pattern. That updated high pattern is then interpreted as a signed 32-bit integer for eligibility.

The operation is eligible exactly when:

- The updated signed high component is greater than zero; or
- The updated high component is zero and the wrapped low sum is strictly greater than the zero-extended threshold.

A negative updated high component is ineligible, regardless of the low sum. When the updated high component is zero, equality between the low sum and threshold is ineligible.

The supplied subtraction-sign and signed-overflow conditions jointly establish this predicate. A sign-only interpretation of wrapped negation would not preserve the behavior at signed boundaries.

An equivalent arithmetic interpretation treats the updated high component and wrapped low sum as a signed 64-bit pair and compares that pair with the nonnegative threshold. The increment is added to the original pair with carry, retaining the 64-bit result. This equivalence does not establish a declared 64-bit field or a domain meaning.

The caller explicitly writes the carry-adjusted high component back to temporary storage. It does not visibly write the wrapped low sum back to the low component.

The threshold comparison is formed before the final eligibility branch. Its evaluation is not conditionally omitted merely because the updated high component alone determines the outcome.

### Effect of a nonzero override

When the override byte is nonzero, both components are zero before eligibility arithmetic.

Adding any unsigned 32-bit increment to a zero low component produces no carry. The updated high component therefore remains zero. Eligibility reduces to:

**The unsigned 32-bit increment must be strictly greater than the unsigned 16-bit threshold.**

The dependency-produced component values no longer influence the decision. This restriction is essential when applying examples involving negative high components, carry cancellation, or the high sign boundary: those examples require a zero override byte.

### Eligible path

If eligibility fails, the function returns zero without calling F-d1e995cfb2d3 or F-97f36d1a1364.

If eligibility succeeds, the 16-bit adjustment is zero-extended and added to the retained initial result. The addition is unsigned 32-bit arithmetic and wraps modulo \(2^{32}\).

F-d1e995cfb2d3 receives that adjusted value as its sole explicit argument. The caller does not reject a wrapped result of zero and does not check this dependency’s result for a failure-like value.

After F-d1e995cfb2d3 returns, F-97f36d1a1364 is called with:

1. The 32-bit input field at `+0x40`.
2. The result from F-d1e995cfb2d3.
3. The constant `3`.
4. The 32-bit input field at `+0x4C`.

The two input-field reads occur as part of preparing the final call, after F-d1e995cfb2d3 completes. Their relative order is not established.

The final dependency’s complete 32-bit result is returned unchanged.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless otherwise stated, assume dependencies return normally, all required memory is valid and initialized, and the values described remain unchanged until consumed.

1. **Initial zero.** If F-0f1843fcf6e2 returns zero, the function returns zero. No remaining dependency is called, and this function performs no direct input-field read.

2. **Override at equality.** With a nonzero override byte, increment `100`, and threshold `100`, eligibility fails. The function returns zero without either eligible-path call. The original low and high components do not affect this result.

3. **Override above threshold.** With a nonzero override byte, increment `101`, and threshold `100`, eligibility succeeds. Both eligible-path dependencies are called.

4. **Strict comparison without override.** With a zero override byte, high component zero, low component `100`, increment zero, and threshold `100`, eligibility fails.

5. **Carry participates.** With a zero override byte, high component zero, low component `0xFFFFFFFF`, increment one, and threshold `65535`, the low sum wraps to zero and the updated high component becomes one. Eligibility succeeds.

6. **Negative high dominates.** With a zero override byte, high component `0xFFFFFFFF`, low component zero, increment zero, and threshold zero, eligibility fails. Interpreting the high component as a large unsigned value would give the wrong result.

7. **Carry cancels a negative high.** With a **zero override byte**, high component `0xFFFFFFFF`, low component `0xFFFFFFFF`, and increment two, the updated high component is zero and the wrapped low sum is one. Eligibility succeeds for threshold zero and fails for threshold one. With a nonzero override byte instead, both components are cleared, and increment two is eligible for either of those thresholds.

8. **Carry crosses the high sign boundary.** With a **zero override byte**, high component `0x7FFFFFFF`, low component `0xFFFFFFFF`, increment one, and threshold zero, the updated high component is `0x80000000`. Eligibility fails. With a nonzero override byte instead, the components are cleared and increment one exceeds threshold zero, so eligibility succeeds.

9. **Adjustment wraps.** If eligibility succeeds, the initial result is `0xFFFFFFF0`, and adjustment is `0x0020`, F-d1e995cfb2d3 receives `0x00000010`.

10. **Zero adjusted value is forwarded.** If eligibility succeeds, the initial result is `0xFFFFFFFF`, and adjustment is one, F-d1e995cfb2d3 receives zero. No local zero-value rejection intervenes.

11. **Final result passes through.** If the final dependency returns `0x80000005`, the function returns that exact pattern. If it returns zero, the function returns zero despite having executed the eligible path.

12. **Late object-field consumption.** If F-d1e995cfb2d3 changes the input’s `+0x40` field and returns normally, the final call consumes the field’s value when read afterward, not a value captured before transformation. This example assumes the mutation leaves the field valid and no further mutation intervenes.
