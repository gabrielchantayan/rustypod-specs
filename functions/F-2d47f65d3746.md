# F-2d47f65d3746

## Purpose

F-2d47f65d3746 performs a preliminary indirect call through an object-associated dispatch table. The result determines whether it invokes F-d4804f3331f5.

The established contract is a two-outcome wrapper:

- A zero result from the preliminary call permits the subsequent dependency call and produces a 32-bit return value of zero.
- Any nonzero result from the preliminary call prevents the subsequent dependency call and produces a 32-bit return value of one.

The return value therefore reports the preliminary branch outcome, not the result of F-d4804f3331f5. The wrapper does not inspect that dependency’s return value.

The preliminary call may be intended as a readiness check, and the paired signed inputs may describe bounds. Those interpretations are not established. The contract uses positional inputs and exact value transformations instead.

## Behavior

### Preliminary dispatch

Every ordinarily entered execution first reaches the indirect call associated with Input 2. There is no earlier branch based on the integer inputs.

Resolving the call requires an object-storage read followed by a table-entry read. The dispatch expression appears both as the invocation target and as the source of the second argument. The supplied representation does not establish whether machine execution shares those reads or repeats them, nor the ordering between those two resolutions.

Accordingly, a precise machine-read trace is not established. With stable object and table storage, both uses resolve from the same byte-offset-20 entry.

The preliminary target’s result is interpreted as a 32-bit integer for comparison with zero. No other result bits or values receive special treatment.

### Nonzero preliminary result

When the preliminary target returns any nonzero value:

- F-d4804f3331f5 is not called.
- The temporary shared storage used by the other branch is not explicitly initialized.
- The paired sentinel transformation is not applied.
- The wrapper returns the 32-bit value one.

The original nonzero result is not propagated. Positive and negative nonzero results collapse to the same outward value.

Any effects already caused by the preliminary target remain outside the wrapper’s control. There is no visible rollback.

### Zero preliminary result

When the preliminary target returns zero, the wrapper establishes a four-byte temporary cell and explicitly writes zero to it.

It then tests Inputs 7 and 8 for the joint sentinel condition: both must equal signed 32-bit minus one.

- If both are minus one, the effective seventh input remains minus one and the effective eighth input becomes 2,147,483,647.
- Otherwise, both effective values equal their respective input values.

This is a paired transformation. Input 8 equal to minus one is not sufficient by itself. Input 7 equal to minus one is also not sufficient by itself.

The relevant 32-bit representations are:

- Minus one: all 32 bits set.
- Replacement maximum: 0x7FFFFFFF, the largest signed 32-bit integer.

The transformation substitutes a constant. It does not increment, add, subtract, clamp a calculated result, or perform range arithmetic. No arithmetic overflow arises from the transformation itself.

### Subsequent dependency call

After initializing the temporary cell and selecting the effective integer values, the wrapper invokes F-d4804f3331f5 with eleven arguments:

| Position | Value |
|---|---|
| 1 | Input 1 |
| 2 | Input 2 |
| 3 | Input 5 |
| 4 | Address of the initialized four-byte temporary cell |
| 5 | Effective Input 7 |
| 6 | Effective Input 8 |

| 8 | Input 4 |
| 9 | Input 3 again |
| 10 | Input 4 again |

The fourth and eleventh arguments alias exactly. They identify one storage location, not two independently initialized locations. If the dependency writes through either argument, the other argument refers to that same modified storage.

The seventh and ninth arguments duplicate Input 3’s value; the eighth and tenth duplicate Input 4’s value. This establishes value repetition, not a copy of any memory those values might identify.

After F-d4804f3331f5 returns normally, the wrapper returns zero. It does not inspect the dependency’s return value or read the temporary cell back to decide its own result.

If either callee does not return normally, the supplied body establishes no subsequent normal return from this wrapper.

## Side effects

The wrapper’s explicit memory activity is limited to dispatch-related reads and initialization of the temporary cell on the zero-result branch.

There is no explicit wrapper operation that:

- Writes to the object identified by Input 2.
- Changes the dispatch-table entry.
- Allocates heap storage.
- Releases caller-owned memory.
- Reads Input 6.
- Reads the temporary cell after F-d4804f3331f5 returns.

These observations do not imply that the callees are side-effect-free. Either callee may modify reachable objects, globals, external resources, or other state. Their effects are not specified by this body.

The temporary cell is local to this invocation. The wrapper provides its address during the subsequent dependency call and makes no visible ownership transfer. Retaining that address for use after the wrapper returns is not supported by the observed storage lifetime. Whether the dependency actually retains it is unknown.

For all other argument values, ownership, borrowing, retention, mutation, and release behavior remain unspecified. Passing a value onward does not establish any of those properties.

These are conditional acceptance criteria derived from static evidence. No runtime tests have been performed.

1. **Preliminary rejection with a positive value.**  
   Given valid, stable dispatch storage and a preliminary result of 6, the wrapper must return one and must not invoke F-d4804f3331f5.

2. **Preliminary rejection with a negative value.**  
   Given a preliminary result of minus one, the wrapper must return one. It must not propagate minus one as its outward result.

   Given a preliminary result of zero and Inputs 7 and 8 equal to minus two and minus three, respectively, those values must be forwarded unchanged. The wrapper does not reject them or reorder them.

7. **Temporary-storage aliasing.**  
   At entry to F-d4804f3331f5, arguments 4 and 11 must identify the same four-byte cell, initially containing zero. If the dependency changes that cell, the wrapper’s return remains zero provided the dependency returns normally.

8. **Unused sixth input.**

These criteria do not prescribe behavior for invalid dispatch storage or violations of unknown callee preconditions.
