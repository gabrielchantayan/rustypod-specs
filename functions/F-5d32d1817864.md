# F-5d32d1817864

## Purpose

The established behavior is the sequence of accesses, calls, decisions, and returns described below. Terms such as “header,” “record,” “position,” “advance,” and “progress” describe inferred roles; they do not establish a particular file format or application protocol.

## Side effects

The explicit destination mutations are five 32-bit stores and, conditionally, one 16-bit counter read-modify-write. They occur before record advance and delegated processing.

There is no explicit assignment targeting the context or associated-state structure by role. This does not guarantee their preservation: destination storage may alias them, and dependencies may modify them.

Failure ordering is observable:

- Stop rejection follows the progress-related calls and precedes that record’s header read.
- Record-advance failure follows the current record’s direct destination writes.
- Delegated-processing failure follows both those writes and a successful record advance.
- Later-record failures occur after earlier-record processing has run.

The function performs no local rollback or compensating call on these paths. It does **not** guarantee that earlier writes remain intact: intervening dependencies, including a failing advance or operations on later records, may alter or undo them.

No explicit allocation or release occurs here. Destination lookup may find, create, borrow, or otherwise supply an object; ownership is unknown. The absence of a caller-side release does not establish that dependencies preserve or release the object.

Temporary storage addresses are exposed to dependencies. Retention, asynchronous use, and validity beyond this invocation are not established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example concerns mutation, its stated inputs remain stable for the relevant accesses.

1. **Empty sequence.** If enclosing read, comparison, and advance succeed and the first count comparison sees zero, return zero. No per-record calls occur, and neither position-output word needs an initialized value for this caller.

2. **Progress bypass with successful destination mutation.** If the secondary result is nonzero, this caller does not read the second output word. It does read the first word when storing destination offset 24. With all remaining checks successful and subsequent loop exit, return zero.

3. **Progress bypass followed by read failure.** If the secondary result is nonzero and the record read returns a nonzero status, return that status. Neither position-output word has been consumed by this caller.

4. **Progress combination.** If the secondary result is zero, the first output word is 1,024, and the second is 1, the derived quantity is 4,194,305. Both words must be defined for this calculation.

5. **Initial read failure or enclosing mismatch.** A nonzero initial-read status is returned without conversion or comparison. A discriminator mismatch after a successful read and optional conversion instead returns −208 without enclosing advance.

6. **Conditional stop.** If the progress branch is selected and the stop check returns nonzero, the progress-related calls occur first, then −208 is returned without that record’s header read.

7. **Record mismatch or missing destination.** A record mismatch returns −208 before lookup. A matching record whose lookup returns zero returns −108 before direct destination writes.

8. **Counter boundary.** If byte 14 is zero at the decision and the destination counter contains 65,535, the function stores zero before record advance. Later dependency behavior may change it again.

9. **Failure after writes.** If record advance returns a nonzero status, return that exact status. The destination stores and any counter update occurred before the call, and no local rollback follows. Final destination contents remain dependent on the failing dependency’s effects.

10. **Changed mode byte.** If byte 14 is zero at the increment decision but becomes nonzero during advance, the counter update occurs, while delegated processing receives the later nonzero byte.

11. **Length boundaries.** Enclosing length 92 and record length 152 produce zero advance arguments. Smaller values still reach the advance dependency as 32-bit differences; their acceptance there is unknown.

12. **Later failure.** If an earlier record completes and a later record fails, this function does not compensate for the earlier record. This does not require the earlier destination contents to survive intervening calls.
