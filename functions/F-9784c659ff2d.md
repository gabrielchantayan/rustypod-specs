# F-9784c659ff2d

## Purpose

F-9784c659ff2d advances a primary object’s 32-bit selection through an indexed collection, conditionally reports a change, performs three virtual operations, calculates a derived integer, and updates an optional associated object.

The established selection policy is:

- Select the first entry, in collection order, whose value is greater than the current selection under unsigned 32-bit comparison.
- If no entry qualifies and the captured collection count is positive, select the entry returned by a further access to index zero.
- If the captured count is nonpositive, return after the initial dependency call.

This is an ordered search, not a search for the smallest qualifying value. Sortedness, entry validation, and collection repair are not established.

“Selection,” “notification,” and “candidate” are functional labels. Their application-level meanings are unknown. A cycling-selection interpretation is inferred intent, not an additional requirement.

## Behavior

### Initial call and count capture

The first visible operation calls F-29eca01f3b88 with no explicit arguments shown.

After it returns, the function reads the signed 32-bit count at primary offset `0x34` and retains it. The initial call can therefore affect the captured count and subsequent object reads.

The retained count controls the entire search. Later changes to the count field do not change that loop bound.

### Ordered search and fallback

For successive indices beginning at zero and less than the captured count, the function calls F-3bc04b368704 with the address of primary embedded storage at `0x30` and the index.

After each accessor returns, the function compares the current primary selection with the returned entry’s value at `0x04`, both interpreted as unsigned 32-bit integers. The first strictly greater entry value ends the search.

The selection is read for each comparison, not captured before the loop. Accessor effects on the selection can therefore affect the comparison immediately following that access. The source does not establish a relative evaluation order between the selection read and the entry-value read within the comparison.

Equal values do not qualify.

If no entry qualifies:

- A captured count of zero or less causes return.
- A positive captured count causes another accessor call for index zero; that result becomes the selected entry.

The fallback is a separate access even though an unsuccessful positive-count search already accessed index zero. Its result is not required by this function to equal the earlier result.

A negative count performs no collection accesses. For a positive signed 32-bit count, the index increases only as far as that count; the visible loop increment does not require signed overflow.

### Selection assignment and notification

The selected entry’s value is read again and compared with the current primary selection.

If equal, the selection write and both change notifications are skipped.

If unequal:

1. The selected entry’s value is read for assignment and written to primary offset `0x20`.
2. F-438680ffebfe receives the embedded-storage address at primary offset `0x8C` and fixed address A-01.
3. Virtual slot `0x40` of the target referenced by primary offset `0x88` is invoked with that target and the then-current selection.

The comparison read and assignment read of the entry value are separate. Stable entry storage is necessary to conclude they produce the same value.

The notification target is not checked for null. Its dispatch information and the selection argument are obtained after F-438680ffebfe returns. That helper’s effects can therefore affect the later notification. No relative evaluation order among the notification call’s argument and dispatch expressions is established.

### Three primary virtual calls and global-read schedule

Every selected-entry path next performs three primary virtual calls through slot `0x58`, regardless of whether the selection changed.

The following statement-level ordering is established:

1. **First invocation.** Its explicit argument positions are:
   - Primary-object address.
   - Loaded value from G-01.
   - Loaded value from G-02.
   - A function-pointer value obtained through the primary object’s slot `0x58`.
   - Two further values whose origins are not established.

   The invocation target is also obtained through primary slot `0x58`. The target expression and the function-pointer argument are separate expressions referring to the same slot; a single cached dispatch lookup is not established.

2. **Retained read.** Only after the first invocation returns, G-03 is read and its value retained for the third invocation.

3. **Second invocation.** Its explicit arguments are:
   - Primary-object address.
   - A fresh, independent read of G-03.
   - A read of G-04.

   The G-03 argument is not supplied from the earlier retained value. The retained read and this argument read refer to the same global location but are distinct reads.

4. **Third invocation.** Its explicit arguments are:
   - Primary-object address.
   - The value retained from G-03 before the second invocation.

   This invocation does not reread G-03 for that argument.

The first invocation completes before the retained read. The retained read precedes preparation and execution of the second invocation. The second invocation completes before the third.

Within a call expression, the source does **not** establish an evaluation order among global-value arguments, dispatch-table reads, or other argument expressions. In particular, it does not establish whether G-01 is read before G-02, or whether the second invocation’s fresh G-03 read precedes its G-04 read.

### Optional associated-object updates

After calculating the derived integer, the function reads primary offset `0x94`. If null, it returns. The arithmetic dependency therefore still runs when no associated object exists.

A nonnull associated-object address is retained for the remaining processing.

A matching candidate field is a 32-bit value that becomes exactly `0x80000002` when bit `0x20` is cleared. Exactly `0x80000002` and `0x80000022` satisfy that condition.

The first candidate is tested first:

- Read and test offset `0x54`.
- Only if that matches, read and test offset `0x60`.
- If both match, write the derived integer to `0x64`, then read `0x80` and copy it to `0x58`.
- Do not test the second candidate.

Otherwise, test the second candidate:

- Read and test offset `0x6C`.
- Only if that matches, read and test offset `0x78`.
- If both match, write the derived integer to `0x7C`, then read `0x80` and copy it to `0x70`.

If neither candidate matches, neither destination pair is directly assigned.

Regardless of matching outcome:

1. Set bit `0x20` in associated flags at `0x48`, preserving other bits.
2. Call F-6d16652f2d03 with the associated-object address and the interior address at `0x80`.
3. Check the callback pointer at `0x34`.
4. Only if nonnull, inspect the low eight bits of the field at `0xA0`.
5. If those bits are zero, invoke the callback target’s slot `0x128`. No explicit arguments are shown.
6. Invoke associated-object slot `0x5C` with the associated-object address.

## Side effects

- A conditional primary selection assignment.
- At most one associated candidate’s two destination assignments.
- Setting associated-object flag `0x20`.
- Setting returned-object flag `0x40`.

## Acceptance examples

These are conditional consequences of static evidence, not runtime results. Dependencies return normally and preserve relevant storage unless stated otherwise.

1. **Nonpositive count.** A captured count of `0` or `−1` causes return after the initial dependency, with no collection access or subsequent processing.

2. **Collection order wins.** Selection `10` with entry values `7`, `30`, `20` selects `30`. The third entry is not accessed during that search.

3. **Unsigned comparison.** Selection `0x7FFFFFFF` and first entry `0x80000000` select that entry.

4. **Fallback and unchanged selection.** A single stable entry equal to the selection is accessed during search and again for fallback. Notifications are skipped, but all three primary virtual calls and the arithmetic calculation occur.

5. **Global identities and argument positions.** If the first call’s G-01 and G-02 reads yield `11` and `22`, those values occupy its second and third explicit argument positions. This does not specify which read occurs first.

6. **Repeated G-03 read and retention.** Suppose the first primary call returns with G-03 holding `100`, both subsequent reads of G-03 yield `100`, and the second primary call changes G-03 to `200`. The second call receives its independently read `100`; the third receives the retained `100`, not `200`. The read trace includes two G-03 reads before the second call, not one.

7. **Fixed address versus contents.** On a changed-selection path, F-438680ffebfe receives A-01 itself as its second argument. The contract does not substitute data stored at A-01 or any G-labeled word.

8. **Arithmetic and null association.** With mode `3`, selection `76,000`, and dependency result `0` for arguments `0` and `1,000`, the derived value is `18`. A null associated pointer then causes return; it does not skip that dependency.

9. **Candidate precedence.** If both candidate pairs match and the derived value is `42`, only the first candidate receives `42` and the copied source value. The second candidate is not tested.

10. **No match still processes association.** If neither pair matches, candidate destinations receive no direct assignments, but flag updates, dependency processing, callback gating, and the final virtual call still occur.

11. **Low-byte gate.** A nonnull callback with gate value `0x00000100` is invoked; gate value `1` suppresses it.
