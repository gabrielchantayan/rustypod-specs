# F-772bde8329ba

## Purpose

F-772bde8329ba conditionally dispatches an operation using an opaque 32-bit input.

The established behavior has two stages:

1. Obtain a pointer through F-b7af80e829ec, derive an earlier address from it when non-null, and invoke an indirect target selected through that address.
2. Only when the first indirect target returns exactly the 32-bit integer value 1, pass the original input to F-87be4aa684d1 and invoke another indirect target selected through its returned pointer.

The interpretation of the first result as a permission, readiness, or eligibility check is **inferred intent**, not an established semantic meaning. The input’s meaning and the second dispatch’s purpose are unknown.

This contract describes the supplied static evidence. No runtime tests have been performed.

## Interface

One opaque 32-bit value is accepted.

- No validation, masking, conversion, or direct dereference of this value is established.
- If the first indirect result equals 1, the value is supplied unchanged as the explicit argument to F-87be4aa684d1.
- Otherwise, F-87be4aa684d1 is not invoked by this function.

The value may represent an identifier, address, handle, flags, or another kind of payload. None of these interpretations is established. In particular, treating zero as an invalid input would add a restriction absent from the supplied evidence.

### Output

The ordinary paths shown either return after the first indirect result fails the equality check or reach the end after the second indirect invocation. Values returned by F-87be4aa684d1 and the first indirect target are used internally. No result from the second indirect target is used.

The final indirect transfer has a recovery limitation described under **Uncertainties**. Consequently, an unconditional guarantee of normal return to the caller is not established.

## Behavior

### 1. Obtain the first pointer

F-b7af80e829ec is invoked before either indirect dispatch.

The recovered call shows no explicit arguments. This does not establish that all machine-level argument locations are irrelevant or that the dependency has no implicit execution context.

Its result is interpreted as a pointer to storage whose elements occupy four bytes in the recovered layout.

If the returned pointer is non-null, the address used for the next memory access is 20 bytes earlier. This is an address adjustment of five four-byte elements; it is not a read of five elements.

If the result is null, the adjustment is skipped, but execution still proceeds to the next dereference. There is no established null-result return path.

### 2. Resolve and invoke the first indirect target

The adjusted address supplies the first table base. The target address is then obtained from the entry at byte offset 448, or hexadecimal 0x1C0, from that table base.

The established observable order is:

1. F-b7af80e829ec completes.
2. The result is conditionally adjusted.
3. The table base is read through the resulting address.
4. The first target address is read through that table base.
5. The first indirect target is invoked.
6. Its result is tested.

The supplied representation does not establish the complete machine-level argument list for the indirect invocation. In particular, it does not justify claiming either that an object receiver is passed or that no receiver is passed.

A table associated with an object-like structure is a plausible interpretation, but the established contract is the concrete pointer-and-table access pattern.

### 3. Apply the exact-result gate

The first indirect result is treated as a 32-bit integer and compared with exactly 1.

- A result equal to 1 permits the second stage.
- Every other 32-bit result causes an ordinary return before F-87be4aa684d1 is invoked.

This is not a general nonzero test. Results such as 2 and negative integer values do not pass.

No retry, fallback dispatch, error translation, or alternate processing is shown on the nonmatching path. Returning at this point does not undo any effects already produced by F-b7af80e829ec or the first indirect target.

### 4. Obtain the second pointer

After the exact-result gate passes, F-87be4aa684d1 is invoked with the original 32-bit input as its explicit argument.

The input has not been transformed by this function. No extra validity condition is applied before forwarding it.

The result is used directly as an address. Unlike the first dependency’s result, it is not shifted backward by 20 bytes. No null check is established for this result.

This call occurs after the first indirect target returns. Any changes that earlier dependencies make to global or shared state may therefore be visible to F-87be4aa684d1. Preservation of that state is not guaranteed.

### 5. Resolve and invoke the second indirect target

The address returned by F-87be4aa684d1 supplies another table base. The second target address is read from byte offset 252, or hexadecimal 0xFC, from that base.

The established order is:

1. F-87be4aa684d1 completes.
2. A table base is read through its result.
3. The second target address is read from the table entry at offset 252.
4. Control is transferred to that target.

### Ownership and lifetime

No explicit error result, exception handler, or recovery mechanism is shown.
