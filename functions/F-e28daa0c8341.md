# F-e28daa0c8341

## Purpose

F-e28daa0c8341 conditionally examines one 32-bit entry in a caller-supplied table. If the selected entry is nonzero, it invokes F-4e292a3dd745 and, if that invocation returns normally, invokes F-feee9156a257. The supplied static representation marks the latter invocation as nonreturning.

The selection argument has a pointer-shaped interface but is used as a signed integer selector, not dereferenced as a pointer. Negative selectors are ignored. Nonnegative selectors are checked against a signed bound read from the descriptor. The entry is examined only when the selector is strictly less than that bound.

**Inferred intent:** this resembles a guard that triggers a terminal response when an indexed slot is occupied or otherwise nonzero. Neither the meaning of a slot nor the purpose of the terminal response is established. These interpretations are not additional behavioral requirements.

## Interface

### Inputs

Two pointer-shaped arguments are supplied:

| Input | Established use |
|---|---|
| Descriptor | Identifies storage containing a table base in the first 32-bit word and a signed bound in the second 32-bit word. |
| Selector | Its numeric representation is interpreted as a signed integer. It is never dereferenced. |

The source representation uses 32-bit integer words and four-byte table spacing. The contract below describes that represented machine model. Exact pointer-to-integer conversion and address-overflow semantics are documented uncertainties, not a promise of portability to a different-width environment.

### Descriptor layout

The function accesses the following fields, conditionally:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 32 bits | Numeric table base used to form an entry address. |
| 4 | 32 bits | Signed selection bound. |

An examined table entry is a 32-bit word at the table base plus four times the nonnegative selector.

The bound is an **exclusive upper bound** on examination. A selector equal to the bound does not cause an entry read.

No other descriptor fields, entry fields, allocation metadata, or lengths are inspected.

### Output and normal return

There is no returned value.

A normal return occurs without invoking either dependency when:

- The selector is negative.
- The selector is nonnegative but not strictly less than the signed bound.
- The selector is in range and the examined 32-bit entry is zero.

For an in-range nonzero entry, normal return is not established: the function calls F-4e292a3dd745 and then, if control returns, calls F-feee9156a257 at a site marked nonreturning.

### Preconditions

Memory requirements depend on the selected path:

- For a negative selector, this body performs no descriptor or table read. It therefore imposes no descriptor-read requirement on that path.
- For any nonnegative selector, the descriptor’s word at byte offset 4 must be readable.
- For an in-range selector, the descriptor’s word at byte offset 0 must also be readable, and the computed table-entry address must permit a 32-bit read.
- The calling environment must supply pointers, alignment, and numeric address representations suitable for the represented execution model.

There is no explicit null check on the descriptor, no table-base validation, and no recovery path for an invalid memory access.

## Behavior

### 1. Interpret the selector

The selector’s numeric representation is tested as a signed integer.

If it is negative, the function returns without reading through either input and without invoking a dependency. This includes any pointer-shaped value whose signed interpretation is negative; the selector is not required to identify an object.

A null selector has numeric value zero and follows the nonnegative path. It is **not** an unconditional no-op.

### 2. Read and compare the bound

For every nonnegative selector, the function reads the descriptor’s second 32-bit word, at byte offset 4. It interprets that word as a signed bound.

The function examines a table entry only when the selector is strictly less than this bound. The supplied representation establishes that result through an equality exclusion together with a signed less-than-or-equal comparison.

Consequences:

- A selector equal to the bound causes no table-entry read.
- A selector greater than the bound causes no table-entry read.
- A zero or negative bound admits no nonnegative selector.
- A negative selector remains ignored regardless of the bound because the descriptor is not read on that path.
- A zero selector is eligible when the bound is positive.

The function does not normalize a negative bound, reinterpret it as unsigned, or report it as malformed.

### 3. Read the selected entry

For an eligible selector, the function reads the descriptor’s first 32-bit word as the table base. It then reads one 32-bit entry at a displacement of four bytes times the selector.

The observable data-read order established by the body is:

1. Descriptor bound.
2. Descriptor table base, only if the selector passes the bound check.
3. Selected table entry, only after the base is obtained.

No loop, neighboring-entry scan, or second table-entry read is present. The entry is tested only for zero versus nonzero; its sign and individual bit fields do not otherwise affect this function.

If the entry is zero, the function returns normally.

### 4. Handle a nonzero entry

If the entry is nonzero:

1. F-4e292a3dd745 is invoked with no explicit arguments.
2. If it returns normally, F-feee9156a257 is invoked with no explicit arguments.

The second invocation is marked nonreturning in the supplied static representation. The body contains no established normal-return continuation for this path.

The function does not reread the descriptor or selected entry between these calls. Any change made by the first dependency therefore does not cause the triggering condition to be reevaluated before the second call.

If the first dependency terminates execution, transfers control elsewhere, or fails to return for another reason, the second call is not reached. Its actual control-flow behavior is unknown.

### Arithmetic boundaries

The address displacement uses multiplication by four in the represented integer/address computation. The body contains no explicit check for multiplication overflow, address-addition overflow, wraparound, or an address outside the underlying allocation.

A positive signed bound does not itself prove that every admitted selector has a representable four-byte displacement. Under a 32-bit signed arithmetic interpretation, selectors above 536,870,911 exceed the positive signed range when multiplied by four. Even a representable displacement can exceed the table allocation or overflow when combined with the base.

The contract therefore requires a valid computed entry address for the entry-reading path. It does not choose an unestablished overflow rule.

Additional boundary criteria:

- A negative selector with an unreadable descriptor must not cause a descriptor read by this body.

- An admitted selector with an invalid computed entry address has no defined recovery behavior in this contract.
- Large selectors whose address arithmetic overflows are not assigned a guessed entry location.
