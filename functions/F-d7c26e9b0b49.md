# F-d7c26e9b0b49

Its established behavior is the ordering of calls, conditional memory accesses, status selection, paired-word arithmetic, and direct context writes. Terms such as “extent,” “position,” “planner,” and “refresh” describe observed roles; they do not establish application semantics.

## Interface

### Inputs and result

The function receives:

- A context pointer, accessed through 32-bit fields.
- A 32-bit control input, tested against zero only during a conditional work-count adjustment.

It returns a 32-bit status:

- Zero is the ordinary success result.
- Ordinary nonzero dependency statuses are returned unchanged.

- A negative callback low word selects a separately loaded error-status value, not the callback result itself.

### Local storage and initialization requirements

- An unsigned 32-bit work-count local, whose address is supplied to F-9838ae3a5083.

**Each word must be initialized before a reached read.** A successful query does not, by itself, establish that both extent words are read:

## Behavior

### 1. Initial query and extent decision

Before querying, the function retains the associated-object pointer from context offset `0x00` and initializes the auxiliary local to zero.

It calls F-da5096269123 with the resource at `0x70` and the address of the extent low word.

- A nonzero status is returned after F-00bce032c44a.
- On success, the extent high word is read first.
- If that high word is nonzero, the initial refresh path is taken without testing the low word.
- If the high word is zero, the low word is read and tested.
- If both tested values are zero, execution proceeds directly to finalization.

There is no second query. Later extent reads are not guaranteed to reproduce the values observed here.

### 2. Initial refresh and callback decision

For the nonzero-extent branch, the function captures the buffer pointer from `0xE4` and calls F-973bb4e26f5d with:

1. The resource from `0x70`.
2. The captured buffer pointer.
3. The 32-bit value at offset `0x08` of the object currently referenced by context offset `0x00`, plus one.

The low 32 bits of the result are the status.

A nonzero status causes immediate exit through F-00bce032c44a. There is no subsequent buffer-byte read, callback, or finalization on this path.

On success, the first byte of the captured buffer is read:

- If zero, the callback is skipped. The selected low result word is zero, while the refresh result’s upper word is retained.
- If nonzero, the function invokes the callback target at offset `0x20` of the object retained **before the query**. Its arguments are that retained object, the captured buffer, and zero.

The object used to derive the refresh argument may therefore differ from the object used for the callback.

If the callback low word is zero, execution proceeds directly to finalization. This path does not read the separate error-status location or directly clear the position.

An empty initial buffer or a nonzero callback low word instead causes a 32-bit read from the separate error-status location. **The read precedes the signed test of the selected low word.**

- A negative selected low word causes the loaded error-status value to be returned after exit processing.
- A nonnegative selected low word enters repeated processing.

Thus the error-status location is also read on the empty-buffer and positive-callback paths, although its value is not selected for return at that point.

On entry to repeated processing, the function writes zero to `0x98`, then zero to `0x9C`. The first planner companion is the refresh result’s upper word for an empty initial buffer, or the callback result’s upper word for a positive callback low word.

### 3. Planning

Each iteration calls F-9838ae3a5083 with:

- The context.
- The current 32-bit companion.
- The then-current extent low and high words.
- Addresses of the work-count and auxiliary locals.

| Planner status | Effect |
|---|---|
| Zero | Continue with count adjustment and processing. |

The auxiliary local is not reinitialized between planner calls. No preservation guarantee is established for either address-exposed local.

### 4. Count adjustment

Arithmetic is expressed as low/high 32-bit words. Carry and borrow connect the words; arithmetic right shifts produce sign-extension words.

If the work count is `0xFFFFFFFF`, the function replaces it with the 32-bit result of F-7071f254f784. Its paired operands are:

1. The then-current extent minus the sign-extended displacement at `0xC0`.
2. The value at `0x40` plus eight as the low word, with that addition result’s arithmetic sign-extension word as the high word.

For the first operand, the high-word subtraction includes both the displacement’s sign-extension word and the unsigned borrow from the low-word subtraction.

The replacement result is not checked again against the sentinel.

A second adjustment is considered afterward. It requires:

- The then-current count to be zero.
- The control input to be zero.
- The other position at `0xA0`/`0xA4`, plus the sign-extended displacement, to equal the current position at `0x98`/`0x9C`.

The equality includes low-word carry. Its high-word equality must succeed before the low-word equality is tested.

When these conditions hold, F-7071f254f784 replaces the count using:

1. The then-current extent minus the current position, including low-word borrow.
2. The value at `0x40` plus eight and its arithmetic sign-extension word.

The second adjustment observes storage after any first arithmetic call. It does not rely on that call preserving context fields or the address-exposed extent storage.

F-7071f254f784’s exact numerical operation is unavailable. A division-like interpretation is inferred, not established.

### 5. Companion reset and preparation

After adjustment, the function replaces the companion with the arithmetic sign-extension word of the displacement currently read from `0xC0`:

- `0x00000000` for a clear sign bit.
- `0xFFFFFFFF` for a set sign bit.

It then compares the current position with the sign-extended displacement. The high-word equality is tested first; the low-word equality is tested only if the high words match.

If equal, F-11effff0926d receives the context and current auxiliary value:

- Its upper result word replaces the companion.
- A nonzero low-word status is returned after exit processing.
- Zero permits continued processing.

Preparation is independent of whether the count is zero. It can also change address-exposed storage if it has access through retained pointers; no preservation contract excludes this.

### 6. Per-unit processing

The function starts an unsigned 32-bit counter at zero. **Every loop-condition comparison rereads the work-count local** and compares the counter with that current value. The adjusted count is not captured as a fixed loop bound.

Consequently, changes through an address retained by a dependency can shorten or extend the number of unit calls. With an unchanged count, the loop makes that many calls unless a nonzero status interrupts it.

Each unit call to F-5569dd87c920 receives:

- The context.
- The resource then read from `0x70`.
- The current-position words then read from `0x98` and `0x9C`.
- A final argument of one.

Its upper result word replaces the companion. Its low-word status determines the transition:

- Zero: increment the unsigned counter and evaluate the condition again, rereading the count.
- Nonzero other than `0x65`: return that status after exit processing.
- `0x65`: perform the extent-based position replacement below and leave the unit loop without another count comparison.

For per-unit `0x65`, the function:

1. Reads the then-current extent low word and writes it to `0x98`.
2. Reads the then-current extent high word and writes it to `0x9C`.
3. Uses the extent high word as the next planner companion.
4. Skips the remaining units and calls the planner again.

This is not a restoration of a guaranteed original extent. A dependency may have changed the extent storage before these reads.

The function does not directly advance position after successful unit calls. Any advancement comes from dependency effects.

After ordinary loop completion, the next companion is the last unit result’s upper word, if any unit ran; otherwise the preparation result’s upper word, if preparation ran; otherwise the displacement sign-extension word.

There is no independent progress check, cancellation check, or outer-iteration limit.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Query failure:** A nonzero query status is returned after F-00bce032c44a. Neither extent word is tested.

2. **High-word short circuit:** If the query succeeds and the extent high word is nonzero, the initial decision does not read the low word. If the following refresh fails, no extent-low read is required on that path.

3. **Zero callback without extent-low read:** With a nonzero extent high word, successful refresh, nonempty buffer, and zero callback low word, execution reaches finalization without the function reading the extent low word.

4. **Zero extent:** A zero high word causes a low-word read. If that is also zero, initial refresh, callback, position clearing, and planning are bypassed; finalization still runs.

5. **Negative callback:** The error-status location is read before the signed decision. Its value is returned after exit processing, even if that value is zero.

6. **Empty initial buffer:** The callback is skipped, the error-status location is read, position is cleared low word first, and the first planner receives the initial refresh’s upper word.

7. **Extent changed after query:** Suppose the query initially supplies a nonzero high word, and a later dependency changes the address-exposed extent storage before planning. The planner receives the later contents, subject to their validity at the reads—not the initially observed pair.

8. **Extent changed during a unit call:** If a unit operation changes retained extent storage and returns `0x65`, the position replacement uses the changed contents. The planner is then called again; finalization is not immediate.

9. **Shrinking work count:** Suppose adjustment leaves a count of three, and the first successful unit call changes the address-exposed count to one. After incrementing the counter to one, the next comparison reads one and terminates that unit loop.

10. **Growing work count:** Suppose the count is one, and the first successful unit call changes it to three. If subsequent calls preserve three and return zero, two additional unit calls occur.

11. **Preparation changes count:** A zero adjusted count does not guarantee no unit calls. If preparation runs successfully and changes the address-exposed count to two, the first loop comparison observes two.

12. **Zero work without preparation:** If the count remains zero and preparation is skipped, the next planner receives the displacement’s sign-extension word.

13. **Planner `0x65`:** Finalization runs, and its dependencies determine the eventual status rather than returning `0x65` directly.

14. **Changed final buffer:** If F-23e80d20fbf0 empties the captured buffer, the conditional final operation is skipped. If it makes that buffer nonempty, the operation runs even when the earlier Boolean was false.

15. **Negative displacement:** Under the visible paired-word arithmetic, subtracting sign-extended `0xFFFFFFFF` from a zero extent produces low word one and high word zero.
