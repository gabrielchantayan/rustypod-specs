# F-4d705591e79c

## Purpose

F-4d705591e79c coordinates an initialized traversal-like state, repeated acquisition of a 32-bit candidate, and a candidate-dependent decision. It stops when acquisition reports zero or when the decision reports nonzero, finalizes the state, and returns a 32-bit result.

The established behavior is dependency-driven. The function itself does not inspect candidate contents, compare candidates, interpret the second input, or distinguish different nonzero status values.

**Inferred intent:** find a candidate accepted by a predicate, returning zero when traversal ends without acceptance. This interpretation is not a complete established contract: the dependencies’ semantics are unavailable, zero is not excluded as a valid candidate, and the candidate output storage is read again after the decision call.

## Behavior

### Acquisition and decision sequence

At least one acquisition is attempted after initialization returns normally.

Each acquisition invokes F-6e4651b532dc with the state-region address followed by the candidate-region address. Its result is treated as a 32-bit integer and compared with zero.

If the acquisition result is zero:

- No decision call is made for that acquisition.
- The candidate region is not read by this function on that branch.
- The selected function result is zero.
- Execution proceeds to finalization.

A zero acquisition result ends the loop even if the dependency wrote a candidate value before returning. That written value does not affect the result on this branch.

If the acquisition result is nonzero:

- The function reads the four-byte candidate region.
- It invokes F-efdae002d289 with that read value as its first argument and the second function input as its second argument.
- After F-efdae002d289 returns normally, it reads the candidate region again and selects this later value as the current result.
- It compares the decision result with zero.

If the decision result is zero, acquisition repeats. If the decision result is nonzero, the loop ends and execution proceeds to finalization.

All nonzero acquisition results take the same branch. All nonzero decision results also take the same branch. No positive-versus-negative distinction, status decoding, retry limit, or special error category is visible.

### Distinct candidate reads

The candidate value supplied to F-efdae002d289 and the value selected after that call come from separate reads.

Under ordinary execution with no intervening modification, those reads produce the same value. Equality is not guaranteed by the available evidence. For example, F-6e4651b532dc receives the candidate region’s address and could retain it in state accessible to another dependency. Whether such retention or subsequent modification occurs is unknown.

Consequently, the established return rule is not simply “return the value passed to the successful decision call.” It is “select the candidate-region value read after that decision call.”

When a decision returns zero, the selected value does not become a persistent fallback. A later zero acquisition selects zero and ends the function, regardless of candidates encountered earlier.

### Finalization and return
