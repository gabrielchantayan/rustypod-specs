# F-1a6022da054c

## Purpose

F-1a6022da054c conditionally derives two 32-bit output words from byte data located through a caller-supplied descriptor. It delegates selection of a byte offset to F-e81ed1edd673, independently transforms two four-byte groups, and applies a separate multiply-and-add transformation to each group.

The established behavior is a sequence of descriptor checks, one dependency call, optional output writes, and a 32-bit return value. The source does not establish what the descriptor represents, what the outputs mean, or whether the nonzero return paths represent particular application-level errors.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

The function accepts four arguments:

| Argument | Observed representation | Role |
|---|---|---|
| First output destination | Nullable pointer to a 32-bit word | Receives the result derived from relative byte offsets 8–11. |
| Descriptor | Nullable pointer to a 32-bit word | Its first word is tested before delegation and later used as a byte-address base. The descriptor pointer itself is passed to the dependency. |
| Second output destination | Nullable pointer to a 32-bit word | Receives the result derived from relative byte offsets 4–7. It is processed before the first output destination. |
| Auxiliary argument | Opaque 32-bit value | Passed unchanged to F-e81ed1edd673. |

The return value is a 32-bit word:

- An unavailable numeric value, designated **descriptor-rejection status**, is returned when the descriptor pointer is null or its first word is zero at entry.
- Another unavailable numeric value, designated **offset-rejection status**, is returned when the dependency returns zero.
- Zero is returned after the optional output processing completes.

The two rejection statuses are read from distinct referenced data locations. Their numeric values, equality or inequality, and relationship to zero are not supplied. Consequently, a caller cannot use this evidence alone to assign numeric error codes or assume that every rejection returns nonzero.

Four additional referenced 32-bit data values control output calculation:

- **Second-output multiplier**
- **Second-output addend**
- **First-output multiplier**
- **First-output addend**

These names describe their use, not an established guarantee of constancy, immutability, or semantic meaning.

### Validity requirements

For an execution without invalid memory accesses:

- A nonnull descriptor must initially permit a 32-bit read.
- Any nonnull output destination must permit the corresponding 32-bit write.
- Each enabled output calculation must have four readable bytes at the addresses determined when that calculation is reached.
- The dependency must be callable with the supplied descriptor and auxiliary argument.

No buffer length, alignment requirement, allocation size, or descriptor layout beyond the directly observed first word is established. Additional requirements imposed by F-e81ed1edd673 remain unknown.

Null output destinations are explicitly supported. A null descriptor is explicitly handled before any dereference or dependency call.

## Behavior

### Entry rejection

The function first checks whether the descriptor pointer is null.

If it is null, the function returns the descriptor-rejection status. It does not invoke F-e81ed1edd673 or directly write either output destination.

If the descriptor pointer is nonnull, the function reads its first 32-bit word. If that word is zero, the same rejection path is taken.

This initial check is not a lasting guarantee about the descriptor contents. In particular, the dependency may subsequently change them.

### Offset selection

For a descriptor that passes the entry check, the function calls F-e81ed1edd673 exactly once, passing:

1. The original descriptor pointer.
2. The auxiliary argument unchanged.

The dependency result is interpreted as an unsigned 32-bit value, called the **selected offset** in this contract.

A selected offset of zero causes immediate return of the offset-rejection status. No direct output write follows that return.

Every nonzero unsigned 32-bit selected offset passes this check, including 1 and values with the high bit set. The visible condition does not enforce an upper bound, a minimum greater than 1, or a relationship to an available buffer length.

The source contains arithmetic around this check, but its observable branch condition is exactly whether the unsigned result is zero. It is not a signed-negative test.

### Optional second-output calculation

If the second output destination is null, this calculation and its direct memory accesses are skipped.

Otherwise, the function rereads the first word of the descriptor and uses that newly read value as a byte-address base. This read occurs after the dependency returns. The function does not reuse the entry-check value or recheck the newly read base for zero.

It obtains four bytes at the following relative offsets from that base:

- Selected offset plus 4
- Selected offset plus 5
- Selected offset plus 6
- Selected offset plus 7

Each byte is unsigned. Each is multiplied by decimal 23, and only the low eight bits of that product contribute to the assembled word.

The transformed bytes are assembled in positional order:

- The byte at relative offset 4 supplies bits 31–24.
- The byte at relative offset 5 supplies bits 23–16.
- The byte at relative offset 6 supplies bits 15–8.
- The byte at relative offset 7 supplies bits 7–0.

Thus, for an input byte \(b\), the contributing byte is

\[
t(b) = (23b) \bmod 256.
\]

For four bytes \(b_0,b_1,b_2,b_3\) in increasing address order, the assembled 32-bit word is

\[
P =
t(b_0)2^{24}
+ t(b_1)2^{16}
+ t(b_2)2^8
+ t(b_3).
\]

The second output receives the 32-bit result of multiplying \(P\) by the second-output multiplier and adding the second-output addend.

The destination write occurs before processing the first output destination.

### Optional first-output calculation

If the first output destination is null, this calculation and its direct memory accesses are skipped.

Otherwise, the function again reads the first word of the descriptor. This is a separate read, occurring after any second-output write. The resulting value is used as this calculation’s byte-address base.

The four byte positions are now selected offset plus 8, 9, 10, and 11. The byte transformation and positional assembly are identical to those described above.

The first output receives the 32-bit result of multiplying this assembled word by the first-output multiplier and adding the first-output addend.

The function then returns zero.

### Arithmetic and representation

The selected offset and packed words are 32-bit quantities. Input bytes range from 0 through 255; their multiplication by 23 therefore ranges from 0 through 5865 before reduction to eight bits.

The top byte’s multiplication is expressed differently from the other three in the supplied representation, but its contribution to a 32-bit packed word is still the low eight bits of the byte-times-23 product placed in bits 31–24.

Output arithmetic produces a stored 32-bit word. The intended fixed-width interpretation is

\[
\text{result} = (M P + A) \bmod 2^{32}.
\]

The supplied representation does not establish a portable source-language signed-overflow contract. It should not be used to claim that an implementation with narrower intermediates, checked arithmetic, saturation, or wider untruncated output is equivalent.

The byte assembly is explicit and independent of host endianness. The byte order of the final 32-bit destination store is not separately specified by the supplied evidence.

Address expressions combine a descriptor-derived 32-bit base, the unsigned selected offset, and small positive offsets. No overflow or bounds checks are visible. The target’s effective-address behavior, including any 32-bit wrapping, is not established sufficiently to make wrapped or invalid addresses a supported input class.

## Side effects

### Established direct effects

On the successful path, the function performs:

- One initial descriptor-word read.
- One dependency call.
- For each nonnull output destination, a fresh descriptor-word read, four byte reads, accesses to the applicable multiplier and addend, and one 32-bit output write.
- A zero return after all enabled calculations complete.

On an entry-rejection path, it reads the applicable rejection-status data value but makes no dependency call and no direct output write.

On an offset-rejection path, it reads the applicable rejection-status data value after the dependency call and makes no subsequent direct output write.

### Ordering and aliasing

The established high-level order is:

1. Entry validation.
2. Dependency call.
3. Selected-offset validation.
4. Second-output processing, if enabled.
5. First-output processing, if enabled.
6. Zero return.

The supplied expression does not establish the exact order of the four byte reads within either calculation, or the order of those reads relative to multiplier and addend reads. Such ordering must not be inferred from their textual arrangement.

No distinctness check is made between pointers.

If both output destinations identify the same valid word, the second-output value is written first and the first-output value later overwrites it, provided both calculations complete.

If the second output destination overlaps the descriptor’s first word, that write changes the base read by the later first-output calculation. This is materially different from taking one descriptor snapshot for both outputs.

Other overlaps may affect later reads, including overlaps with source bytes or referenced data values. The function does not visibly prevent them. Whether such aliases are valid under the original execution environment is not established.

### Ownership and failure

No direct allocation, deallocation, ownership transfer, or persistent pointer retention is visible. The function’s direct memory use consists of reads and optional destination writes.

This says nothing about the dependency’s ownership behavior. It must not be assumed to preserve, retain, release, or avoid changing any memory solely because those actions are absent from the caller’s body.

No rollback is visible. If the second-output write completes and later first-output processing cannot complete, the source provides no mechanism to undo the earlier write.

There is no explicit error return for an invalid nonnull pointer, insufficient data, address overflow, or inaccessible output. The outcome of such an access is outside the established normal-return contract.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Null descriptor.** With a null descriptor pointer, return the descriptor-rejection status without calling F-e81ed1edd673 or directly writing either output. Nonnull output pointers do not change this branch.

2. **Zero initial descriptor word.** With a readable descriptor whose first word is zero, take the same rejection path. No source-byte access for either output occurs.

3. **Dependency returns zero.** With a nonzero initial descriptor word and a dependency result of zero, return the offset-rejection status. Any effects already performed by the dependency remain outside the caller’s rollback behavior.

4. **Both outputs disabled.** With a descriptor that passes entry validation, a normally returning dependency that selects a nonzero offset, and both output destinations null, return zero without reading either four-byte group or rereading the descriptor for output processing.

5. **Only the second output enabled.** If the selected offset is 1, read the group at base-relative offsets 5–8. Do not process the first-output group.

6. **Byte reduction and packing.** For an enabled group containing bytes 1, 2, 3, and 4 in increasing address order, the packed intermediate is hexadecimal 0x172E455C. With an applicable multiplier of 1 and addend of 0, store that word.

7. **Reduction above one byte.** For a group containing 255, 0, 0, and 1, the transformed bytes are 233, 0, 0, and 23. The packed intermediate is 0xE9000017, not a saturating or unreduced product.

8. **Output wraparound.** For a packed intermediate of 1, multiplier 0xFFFFFFFF, and addend 2, the fixed-width output is 1. A checked-overflow error or a wider stored result would not match the 32-bit transformation.

9. **Identical output destinations.** If both destinations identify the same valid word and both source groups remain readable, the final word contains the first-output result because that write occurs last.

10. **Descriptor replacement by the dependency.** If the dependency changes the descriptor’s first word from one valid base to another before returning a nonzero offset, output processing uses the replacement base, not the entry-check base.

11. **Descriptor overwritten by the earlier output.** If the second destination is the descriptor word, and its computed result is a valid replacement base, an enabled first-output calculation uses that replacement base. Combining the two descriptor reads into one would change this behavior.
