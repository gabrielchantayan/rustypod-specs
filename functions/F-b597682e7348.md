## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Entry fault boundary:** if either initial read fails, the explicit-byte store has not occurred. Failure of the subsequent dependent read occurs after that store.
2. **Changing input storage:** three differing input-offset-`0x64` observations can produce differing bytes. C uses B’s retained observation, not a fresh fourth read.
3. **Signed displacement:** with halfword pattern `0xFFFF`, displacement-based addressing uses −1 where arithmetic is otherwise valid.
4. **Exceptional F destination:** if working base is 12, selection is 100, and loaded displacement is 7, F’s halfword destination is 124, not 107.
5. **Replacement addressing:** H, L, and M use their replacement active selections for the specified halfword destinations and outgoing word observations.
6. **Character boundary:** character pattern `0x80` does not establish a unique portable recipient address without resolving character signedness.
7. **Product distinction:** if operand is 2, the first later product is 20, and the word observed at offset `0x74` is 7, the second later product is 40, not 14, provided the relevant arithmetic and accesses are valid.
8. **Retained object field:** replacing the object’s offset `0x14` does not redirect the observation based on its captured old value.
9. **Reread distinction:** aliasing mutations can cause the two second-later-product-offset-`0x44` observations to differ.
10. **Undefined-source boundary:** neither early-use byte is required to equal zero or its later assigned value.
11. **Call visibility:** post-first-call stack assignments are not prepared inputs to that call. A nonreturning first dependency prevents those assignments and the second call.
12. **Terminal continuation:** return from F-cdec09f5d432 does not imply return to the original caller.
