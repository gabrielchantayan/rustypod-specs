# F-8c28795990ad

## Purpose

F-8c28795990ad performs state-selected processing on a caller-supplied object. It acquires an initial synchronization-like resource, optionally prepares a reference-counted-looking value, and repeatedly dispatches according to a one-byte object field until a branch produces a nonzero result or an unsupported selector is observed.

The synchronization and reference-counting interpretations are inferred intent, not established dependency contracts. The established behavior is the sequence of calls, memory accesses, and return-value decisions described below.

A selector value of zero does not itself produce a terminating result. Progress from that branch requires an observable change affecting a later selector read, or some nonlocal behavior inside a dependency. There is no explicit iteration limit, timeout, or cancellation check.

## Behavior

It then calls F-4a19e3742733 with the saved value. The function does not inspect a return value from this call.

### 2. Optional preparation for an initially zero selector

If this read is nonzero, all preparation described in this subsection is skipped. In particular, the primary argument’s local copy is not passed to the local-slot cleanup dependency on that path.

If the selector is zero, the following operations occur in order:

1. Read the current 32-bit resource field at object offset `0x78`.
2. Call F-fd58bea73663 with that freshly read value.
3. Read the 32-bit field at object offset `0x70`.
4. Call F-5be25e516952 with the address of the local slot initialized from the primary argument and the value read from offset `0x70`.
5. Perform the guarded assignment-like sequence described below.
6. Call F-e1c941072f1b with the address of the primary argument’s local slot.
7. Read the resource field at object offset `0x78` again.
8. Call F-4a19e3742733 with that freshly read value.

F-5be25e516952 receives a writable local-slot address. The value used afterward is the slot’s post-call contents, not necessarily the original primary argument.

#### Assignment-like sequence

The supplied representation guards this sequence with a comparison between the addresses of two distinct local slots. Those addresses are represented as unequal, so the sequence is taken in the displayed function.

First, F-e1c941072f1b is called on the address of the destination slot, which was explicitly set to zero earlier.

Next, the current source-slot value is captured and copied into the destination slot.

If the source-slot value is nonzero:

- Its 32-bit field at offset `+8` is read.
- If that field is nonzero, F-338d16f9ce72 is called without explicit arguments.
- The 32-bit field at offset `+4` of the captured value is read, incremented by one, and written back.
- The 32-bit field at offset `+8` of the captured value is read again.
- If this second read is nonzero, F-1333331b2da1 is called without explicit arguments.

The second metadata check is a fresh read. It must not be treated as equivalent to the first check: the intervening call and increment may affect observable state.

The increment has no explicit range check or overflow handling in this body. The operation targets a 32-bit integer field. Boundary behavior at the largest signed value is not established by the supplied high-level representation alone.

After this sequence, the source slot is passed to F-e1c941072f1b as described above. The destination slot remains available to the dispatch loop.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid memory and normal dependency returns unless stated otherwise.

1. **Unsupported selector throughout entry.**  
   If the preparation check and first loop read both observe selector 2, preparation is skipped, no branch-specific processing occurs, the destination slot is passed to cleanup, the original resource is passed to final resource cleanup, and the function returns 1.

2. **Selector 1 completes immediately.**  
   If preparation is skipped, the first loop read observes 1, and F-6f55f69d947d returns 7, the function performs selector-1 processing once, performs final cleanup, and returns 7 unchanged.

3. **A negative result is terminal.**  
   If selector 3 is observed and F-e11dcb817d43 returns −1, dispatch terminates. The function does not normalize that value to 1 or retry because it is negative.

4. **Zero requests another dispatch read.**  
   If selector-4 completion returns zero and the next selector read observes 1, the next iteration uses selector-1 processing. The function does not remain bound to selector 4.

5. **Persistent selector zero does not terminate normally.**  
   If preparation and every loop read observe zero, every called dependency returns normally, and nothing changes the selector, selector-0 processing repeats indefinitely. Final cleanup is not reached.

6. **Preparation does not fix the first dispatch choice.**  
   If the initial selector is zero but preparation leaves the selector at 4, the first loop iteration follows selector 4 after completing all preparation calls.

7. **A later zero selector does not trigger preparation.**  
   If the initial selector is 1, selector-1 completion returns zero, and the next selector is zero, the selector-0 branch runs without the preparation sequence having occurred.

8. **Null prepared value avoids metadata accesses.**  
   If the source slot is zero after F-5be25e516952 and remains zero through the subsequent destination cleanup call, zero is copied to the destination. No direct `+4` or `+8` metadata access occurs in the assignment-like sequence.

9. **Metadata conditions are independent observations.**  
   For a valid nonzero prepared value, a nonzero first `+8` read causes F-338d16f9ce72 to be called. A zero second `+8` read skips F-1333331b2da1. The first call does not force the second.

10. **Final cleanup preserves the captured resource identity.**
