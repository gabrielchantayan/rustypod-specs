# F-6b21ab331f98

## Purpose

F-6b21ab331f98 processes records occupying 32 bytes each, using F-af8be05ab6e8 to handle thirteen two-byte fields per record. Records are visited in descending address order, starting at the supplied output address.

Processing stops before another record begins when either the remaining count equals zero or an internal termination state has been set. Termination detected during a record does not abandon that record: later fields are padded, a final source-byte check is performed, and metadata is written.

A terminal record is fully processed before normal return. Complete initialization of its storage is not established. In particular, the dependency may leave a component unwritten, and the field that triggers termination is not subsequently padded.

The field meanings, source encoding, and semantic interpretation of the metadata are not established beyond the mechanical behavior below.

## Behavior

### Record admission and initial state

The internal termination state begins false. A local source-cursor cell is initialized from the source-address input.

Before each record, the function returns if the remaining count equals zero or the termination state is true.

Consequences:

- A zero initial count causes no dependency calls, direct source-byte reads, or output writes.
- A nonzero count admits the first record without a preliminary source-byte check.
- A negative count is not rejected at admission.
- An initially set flag bit 6 does not set the internal termination state and does not itself stop processing.

The flag byte and the internal termination state are separate pieces of state.

### Field processing order

Each admitted record processes thirteen fields in increasing address order:

1. Five fields beginning at offsets 1, 3, 5, 7, and 9.
2. Six fields beginning at offsets 14, 16, 18, 20, 22, and 24.
3. Two fields beginning at offsets 28 and 30.

While termination remains false, each field causes a call to F-af8be05ab6e8 with these arguments, in order:

1. The address of the local source-cursor cell.
2. The address of the field’s first component.
3. The address of the field’s second component.

The dependency can update the cursor through the supplied cell. Subsequent dependency calls and the final source-byte check use the resulting cursor value.

After each normal dependency return, the caller reads the first component from output memory. If that byte equals zero, it sets the internal termination state.

The second component is not tested. No separate dependency return value is inspected. The caller does not initialize either component before the call and does not establish that the dependency writes either or both components.

Accordingly, the termination decision is based on the byte actually present after the call, not necessarily on a newly produced byte.

### Padding after field termination

Once a first component is observed as zero, the termination state remains true for the rest of the invocation. No further dependency calls occur.

Every later field in the current record is padded with two bytes of value 255. Within each padded field, the second component is written first, followed by the first component.

Padding continues across field-group boundaries. For example, termination in the first group causes padding of its remaining fields and all fields in the second and third groups.

The triggering field is not padded or otherwise repaired by the caller. If the dependency writes zero to its first component but leaves its second component untouched, that second component retains its earlier contents unless another permitted effect changes it. A zero first component therefore does not establish that both bytes of the terminating field were initialized.

### Final source-byte check

After all thirteen fields have been handled, the function reads one byte through the current source cursor.

This read is unconditional for a record that reaches this stage. An already-true termination state does not bypass it.

If the byte is zero, termination is set. A nonzero byte does not clear termination previously established by a field.

There are therefore two independent ways to establish termination:

- A zero first component observed immediately after a dependency call.
- A zero source byte observed after all fields have been processed.

The caller performs no direct source-byte read between individual fields. Source reads performed inside F-af8be05ab6e8 remain part of that dependency’s unknown behavior.

### Flag and metadata writes

After the final source-byte check, the function sets bit 6 of the current flag if termination is true. This operation preserves the flag’s other bits.

It then performs the following byte writes, in this order:

1. Offset 0 receives the current flag.
2. Offset 11 receives 15.
3. Offset 12 receives 0.
4. Offset 13 receives the metadata input’s low eight bits.
5. Offset 26 receives 0.
6. Offset 27 receives 0.

These writes occur after all field operations and after the final source-byte read. Consequently, metadata written by the current record cannot affect that record’s earlier source check, although overlapping storage may affect later activity.

### Progression and return

After the metadata writes:

1. The flag is incremented and retained as an eight-bit value.
2. The output address is decreased by 32 bytes.
3. The remaining count is decreased by one.
4. Record admission is checked again.

Flag increment is modulo 256: 255 advances to 0. Carries are not suppressed at bit 6 or any other bit.

A terminal record is fully processed before normal return, but is not guaranteed to be fully initialized. Count exhaustion alone does not insert bit 6. Conversely, an already-set bit 6 can appear in a nonterminal record because it is part of the supplied or incremented flag value.

For negative counts, repeated decrement may eventually exceed the signed representation’s range. No portable wraparound or eventual zero-count termination is established for that case.

## Acceptance examples

These are conditional behavioral requirements derived from static evidence, not executed tests. Unless an example states otherwise, assume valid memory, normal dependency returns, and no additional aliasing or external effects.

### Zero capacity

With count zero, there are no dependency calls, direct source-byte reads, or output writes. This path does not require dereferenceable source or output storage.

### One nonterminal record

With count one, suppose all thirteen dependency calls leave nonzero first components and the final cursor byte is nonzero.

Exactly thirteen calls occur. Metadata is written, and processing ends through count exhaustion. Offset 0 equals the initial flag; no terminal bit is added merely because capacity is exhausted.

### First-field termination with an untouched second component

Suppose offset 2 initially contains 82. The first dependency call writes zero at offset 1, leaves offset 2 unchanged, and leaves a readable source cursor.

Only one dependency call occurs. Offset 2 remains 82; the caller does not initialize or pad it. Every later field receives two bytes of value 255, written second component first.

The final cursor byte is still read. All metadata bytes are written, with bit 6 set in the flag, and no next record begins.

This outcome is a fully processed terminal record without a guarantee that every field component was initialized during the invocation.

### Zero second component only

Suppose a dependency call leaves a nonzero first component and a zero second component.

That field does not establish termination. The next field receives a dependency call unless termination is subsequently established elsewhere.

### Termination at a field-group boundary

Suppose the fifth call leaves a zero first component.

Exactly five calls occur. The triggering field is not padded. All six fields in the second group and both fields in the third group are padded. The final source read and metadata writes still occur.

### Final-cursor termination

Suppose all thirteen first-component observations are nonzero, but the final cursor points to a zero byte.

All thirteen dependency calls occur. No fields are padded because of this final check. Bit 6 is set in the record flag, and no next record begins.

### Two records with flag wraparound

With count two and initial flag 255, suppose neither record encounters either termination condition.

The first record is processed at the supplied address with flag 255. The second is processed 32 bytes earlier with flag 0. The initially set bit 6 does not prevent processing the second record.

### Metadata truncation

For metadata value hexadecimal 123456AB, offset 13 receives hexadecimal AB in each normally completed record. The upper 24 bits have no direct output use in this function.
