### Global-source transfer

After the dependency returns, the function reads the 32-bit global source and writes that value into the four-byte destination range at offsets 0–3.

The value used is the one obtained after the dependency invocation. The dependency’s effects on global state are unknown. Consequently, a value observed before that invocation is not sufficient to predict the copied value.

The global-source read precedes the destination write that consumes it. There is no shown separate read through the returned destination pointer before this write.

That distinction does not imply that destination contents are unread. The global source may overlap destination storage:

- If the global source coincides exactly with destination offsets 0–3, the read obtains that field’s value at the time of the read, and the first write stores the same 32-bit value back.
- If the source partially overlaps destination storage, the read obtains its value before the first destination write changes any overlapping bytes.
- If the global source overlaps a later destination field, a subsequent fixed-value write may modify the source storage.

The function does not reread the global source after the initial transfer. Its value after return is therefore not generally guaranteed to equal the value copied at the start of the write sequence.

### Fixed-value writes

2. Four bytes containing 0 at offsets 20–23.

After the final write, the function returns without an explicit value.

No separate reads through the returned destination pointer are shown. However, the global-source read may access overlapping destination storage, including a field that is subsequently written.
