# F-298bfb7f5074

## Purpose

F-298bfb7f5074 produces two Boolean outputs from an effective integer value. Ordinarily, the effective value is the supplied selector. Selector value 3 instead requests resolution through dependency F-72b51d9ef411, using a 32-bit value read from an input object.

The first output reports whether the effective value is nonzero. The second reports whether that same value equals exactly 2. The function writes the first output before the second.

This contract describes behavior established by the supplied static source representation. It does not establish the application-level meaning of the selector, the input object, or either output.

## Behavior

### Direct-selector path

When the selector is anything other than 3, it is used directly as the effective value.

The function first writes the result of the nonzero comparison to the first output. It then writes the result of the equality-to-2 comparison to the second output and returns.

This path contains no explicit object-field read and no call to F-72b51d9ef411.

Consequently:

- Selector 0 produces false, then false.
- Selector 2 produces true, then true.
- Every other selector except 3 produces true, then false.

There is no range restriction or validation limiting selectors to a small enumeration. Negative values, for example, are nonzero and do not equal 2.

### Dependency-resolved path

When the selector is exactly 3, the function performs these observable actions in order:

1. Reads the 32-bit value at offset 0x9A8 from the input-object address.
2. Calls F-72b51d9ef411 with that value as its sole argument.
3. Uses the dependency’s returned integer as the effective value.
4. Writes whether that value is nonzero to the first output.
5. Writes whether that value equals 2 to the second output.
6. Returns without a data result.

The comparison results depend on the dependency’s return value, not on the original selector value of 3.

A returned value of 3 does not cause another dependency call. The function performs only one resolution step. Likewise, any other returned value is classified directly without further lookup or normalization.

The object field is read once by this function on this path. There is no explicit reread following the dependency call. If the dependency changes that field, the function does not use the changed field to resolve the effective value again.

### Integer interpretation

The selector and effective value are interpreted in the supplied representation as 32-bit integers. Classification uses only comparison with zero and comparison with 2. There is no arithmetic transformation of the effective value, no narrowing to a Boolean before the equality-to-2 comparison, and no bitmask test.

The equality-to-2 output therefore does not mean “the second bit is set.” For example, effective values 6 and −2 yield false for that output despite being nonzero.

Address formation adds the fixed byte offset 0x9A8 to the first argument. The supplied material does not establish behavior for address overflow or for an invalid resulting address. No wraparound-access guarantee is part of this contract.

### Output aliasing and write order

The function does not check whether its output addresses overlap.

If both arguments identify the same Boolean storage location and both writes complete, the second write determines the final stored value. With an effective value of 1, for example, the function first writes true and then overwrites it with false. With effective value 2, both writes store true.

If an output overlaps the object field used on the dependency-resolved path, this function’s field read precedes both output writes. Such an overlap may change the object’s storage through an output write, but it does not cause this function to reread the field.

These ordering claims describe the function’s access sequence. They do not establish atomicity, synchronization, or safe concurrent access.

Only the Boolean-sized destination regions are explicitly written. The function does not initialize a larger output structure, clear adjacent bytes, or write a status code elsewhere.

For selector 3, the function additionally reads one 32-bit object field and invokes F-72b51d9ef411 before either output write. Any side effects of that dependency occur according to the dependency’s own behavior.

No explicit allocation, deallocation, ownership transfer, reference-count operation, global-variable access, logging, or cleanup appears in this function. This does not imply that F-72b51d9ef411 lacks such effects.
