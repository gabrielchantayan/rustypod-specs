# F-0dce558036fd

Eligibility depends on two fields in a caller-supplied context, the low 32 bits of a dependency’s result, and a comparison between the low byte of the second argument and a shared limit.

## Behavior

### 1. Context eligibility

The function first reads the 32-bit field at context offset `0x2D4`.

If that field is zero, it returns `11`. It does not read the byte at `0x2E1`, call any dependency, or explicitly write shared state on this path.

If the field is nonzero, it reads the unsigned byte at offset `0x2E1`. A value of four or greater causes a return of `11`, again without dependency calls or explicit shared writes.

The successful initial condition is therefore a nonzero 32-bit field followed by an unsigned byte in the inclusive range zero through three. The ordering and short-circuiting of these reads are established.

### 2. Dependency-based eligibility

After both context checks pass, the function initializes a local 32-bit slot with the complete selector word.

It then calls an unmapped dependency, designated here as **F-000000000001**. This identifier is a document-local opaque label, not a supplied provenance mapping. The displayed call has no explicit arguments. Its result supplies the first argument to F-9c4f3d705d74.

After that call returns, the function reads the 32-bit context field at `0x2D0` and calls F-9c4f3d705d74 with:

1. The result of F-000000000001.
2. The newly read field at `0x2D0`.

F-9c4f3d705d74 produces a displayed 64-bit result. The low 32 bits determine whether execution can proceed: zero rejects the operation, and any other bit pattern accepts this stage. This is a nonzero test, not a positive signed-value test.

If the low 32 bits are zero, the function returns `11`. The upper 32 bits do not enable the request path and do not select another externally visible result.

The context field at `0x2D0` is read after F-000000000001 returns. Consequently, changes that dependency makes to the field can affect the following call. No preservation guarantee is assumed for either dependency.

### 3. Selector comparison

When the low result word is nonzero, the function extracts the selector’s low eight bits and represents them as an unsigned 32-bit value. The other 24 selector bits do not participate in the comparison.

It reads the leading element of a shared region as the limit, selects `9` as the result for comparison failure, and retains that region’s address for a possible later write.

The displayed use of the region as a byte pointer supports a one-byte, zero-extended limit. The shared object’s declaration is absent, so independent confirmation of that load width remains documented-only.

The request path requires the extracted selector byte to be **strictly less than** the limit. Equality is rejected.

Under the byte-limit interpretation:

- A limit of zero rejects every selector.
- A limit of one accepts only selector byte zero.
- A limit of 255 accepts selector bytes zero through 254.
- Selector byte 255 is never accepted.

A comparison failure returns `9`, without calling F-cd7e1905512f or F-46e5cb3247c2 and without the function’s explicit shared-byte write.

### 4. Request call

If the comparison succeeds, the function calls F-cd7e1905512f with seven arguments, in this positional order:

| Position | Argument |
|---|---|
| 1 | A fresh 32-bit read of context offset `0x2D4`. |
| 2 | Zero. |
| 3 | Eight. |
| 4 | Three. |
| 5 | Address of the local 32-bit selector slot. |
| 6 | One. |
| 7 | The original context address. |

The first argument is not necessarily the value that passed the initial guard. The intervening dependencies may have changed the field; this function does not repeat the nonzero guard on the newly read value.

The complete selector word remains available through the fifth argument, despite eligibility using only its low byte. Thus, selector words with identical low bytes can pass the same comparison while still being distinguishable to F-cd7e1905512f.

The supplied address permits that dependency to modify the local slot. Subsequent behavior uses the slot’s post-call contents.

The request result is treated as a 32-bit value and tested for zero. A high-bit-set nonzero result follows the nonzero branch; it is not rejected as negative.

### 5. Post-request read and completion

After F-cd7e1905512f returns, the function loads a separate shared 32-bit value. This read occurs before selecting between the zero-result and nonzero-result branches, so it is reached even when the request result is zero.

If the request result is zero, the function returns `28`. It does not perform its explicit shared-byte update or call F-46e5cb3247c2.

If the result is nonzero, the function:

1. Writes the low eight bits of the current local selector slot to byte offset two of the previously retained shared region.
2. Calls F-46e5cb3247c2 with the nonzero request result, zero, and the shared 32-bit value loaded after the request call.
3. Returns that dependency’s 32-bit result unchanged.

The shared-byte write precedes final delegation. There is no visible rollback if final delegation reports failure or otherwise returns an error-like value.

The written byte can differ from the byte that passed the comparison if F-cd7e1905512f modified the local slot. No second comparison validates the replacement value.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, required memory is accessible and dependencies return normally.

1. **Inactive context.** If the field at `0x2D4` is zero, the result is `11`. The byte at `0x2E1` is not read, and no dependency is called.

2. **Context-byte boundary.** With a nonzero field at `0x2D4`, a byte value of four at `0x2E1` returns `11`. A value of three passes only the initial guard; later checks still apply.

3. **Low-word rejection.** If F-9c4f3d705d74 returns a zero low word and a nonzero upper word, the result remains `11`. The shared selector limit is not read.

4. **Strict comparison.** Assuming a byte limit of five, selector byte four reaches F-cd7e1905512f, while selector byte five returns `9` without that call.

5. **High selector bits remain available.** With a limit above two, selector words `0x00000002` and `0xABCD0002` both satisfy the same selector comparison. Each complete word is nevertheless supplied through the local slot, so identical downstream results are not required.

6. **Request failure still reads shared data.** If all eligibility checks pass but F-cd7e1905512f returns zero, the separate shared 32-bit value is still read. The result is `28`; no explicit shared-byte update or final delegation follows.

7. **Modified selector is committed without rechecking.** Suppose selector byte two passes against limit five, and F-cd7e1905512f changes the local word to a value ending in `FE` before returning nonzero. The function writes `0xFE` at shared-region offset two and then calls F-46e5cb3247c2.

8. **Fresh context-field observation.** Suppose the initial field at `0x2D4` is nonzero, but an intervening dependency changes it to zero. If later eligibility checks pass, F-cd7e1905512f receives zero as its first argument; this function does not reject that updated value first.

9. **Delegated result and persistent write.** If the request result is nonzero and F-46e5cb3247c2 returns `0xFFFFFFFF`, the enclosing result is `0xFFFFFFFF`. The preceding shared-byte write is not undone by this function.
