# F-158207dce1c0

## Purpose

F-158207dce1c0 conditionally updates three 32-bit fields in a caller-supplied object: a stored base quantity and two derived quantities.

An update is triggered when the requested quantity differs from the stored base, or when a separate force argument is nonzero. A triggered update accepts the requested quantity as the new base only when its unsigned value is below 32,768. Whether or not that replacement occurs, the function recomputes both derived quantities from the base then stored in the object.

Each derived quantity uses its own signed control field. A control below a shared signed threshold enables multiplication followed by a 15-bit logical right shift. Otherwise, the corresponding derived quantity receives the base unchanged.

The apparent intent is a fixed-point scaling operation with independently controlled outputs. That interpretation is inferred; the supplied evidence does not establish units, names, expected control ranges, or the meaning of the shared threshold.

## Behavior

### 1. Determine whether to update

The function reads the unsigned stored base at offset `0x6C` and compares it with the full unsigned requested quantity.

An update occurs if either:

- The stored base and requested quantity differ.
- The force argument is nonzero.

If the values are equal and force is zero, the function returns without writing any object field. The threshold and controls are not read on that path.

The base read is part of the decision even when force is nonzero. Force does not bypass the comparison in the supplied expression.

### 2. Conditionally replace the base

On an update, the function checks whether the requested quantity is strictly less than 32,768 using an unsigned comparison.

- Values from 0 through 32,767 are written to offset `0x6C`.
- Values from 32,768 through 4,294,967,295 are not written there.

A request outside the accepted range does **not** cancel the update, clamp the value, clear the base, or produce an error result. Instead, recomputation continues using the base read from the object afterward.

Consequently:

- An out-of-range request differing from the stored base still triggers recomputation.
- An out-of-range request equal to the stored base does not trigger recomputation unless force is nonzero.
- A forced update with an accepted request performs the base write even when the stored value already equals that request.

### 3. Capture the shared threshold and obtain the effective base

After the optional base write, the function reads the shared signed threshold and retains that value for the second output’s control comparison.

It then reads the unsigned base at offset `0x6C` again. This later read supplies the effective base for both derived quantities.

This is a genuine reread in the supplied body, not merely reuse of the value observed during the initial decision. Under exclusive access, it yields the newly written request when replacement occurred, or the retained base otherwise. No concurrency guarantee is established.

### 4. Compute and write the first derived quantity

The first signed control, at offset `0x7C`, is compared with a reference to the shared signed threshold.

If the control is strictly below that threshold, the first output is calculated as follows:

1. Interpret the signed control’s bit pattern as an unsigned 32-bit multiplication operand.
2. Multiply it by the effective unsigned base.
3. Retain the low 32 bits of the product.
4. Logically shift that 32-bit result right by 15 bits.

Otherwise, the first output is the effective base unchanged.

The result is written to offset `0x70`.

The comparison is signed, but the multiplication is unsigned because the other operand is unsigned. Negative controls are therefore not treated as negative fixed-point products, nor are they clamped to zero.

The multiplication wraps before the right shift. It is not equivalent in general to computing a full 64-bit product and then shifting it.

### 5. Compute and write the second derived quantity

After the first output write, the function reads the second signed control at offset `0x80` and compares it with the threshold value captured before the effective-base read.

If the second control is strictly below that captured threshold, the second output uses the same wrapped unsigned multiplication and 15-bit logical shift described above.

Otherwise, the second output is the effective base unchanged.

The result is written to offset `0x74`, after which the function returns.

The second result does not use the first result as its base. Both output calculations independently start with the effective base read from offset `0x6C`.

### Threshold-read distinction

The supplied body both captures the shared threshold and references that shared threshold again in the first-control comparison. The second-control comparison explicitly uses the captured value.

With a stable threshold, both comparisons use the same numerical threshold. The evidence does not justify replacing this distinction with a promise that both comparisons always observe one atomic snapshot, or that both always observe the latest shared value.

### Arithmetic boundaries

For a scaled branch, let:

- \(B\) be the effective unsigned 32-bit base.
- \(G\) be the signed control.
- \(U(G)\) be that control converted to unsigned 32-bit form.

Then the output is:

\[
\left\lfloor
\frac{(B \times U(G)) \bmod 2^{32}}{2^{15}}
\right\rfloor
\]

The result of this branch is always between 0 and 131,071 inclusive. The bypass branch can copy any unsigned 32-bit base value.

No rounding offset, saturation, or wider-product preservation is visible. Equality between a control and its applicable threshold selects bypass, not scaling.
