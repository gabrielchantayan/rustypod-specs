# F-ec0e8e32247a

## Purpose

The established behavior is not a general addition, maximum, or saturation operation:

- When both values are zero, the result is 98.
- When exactly one value is zero, the result is the low eight bits of the nonzero value.
- When both values are nonzero and either exceeds 98, the result is 99.
- When both values are nonzero and neither exceeds 98, the result is 98.

The first argument has no direct effect in the supplied function body.

The meaning of the numeric results is unknown. In particular, there is no evidence that 98 and 99 represent percentages, success and failure, limits, or named status codes.

### Both values zero

If both values are zero, the function returns 98.

This is distinct from the exactly-one-zero case. The function does not return the low eight bits of their sum in the both-zero case; that would produce zero and would contradict the visible behavior.

### Exactly one value zero

If one value is zero and the other is nonzero, the function returns the low eight bits of their unsigned sum. Because one operand is zero, this is also the low eight bits of the nonzero operand.

The result is the remainder after dividing the nonzero value by 256. Thus:

- Nonzero values from 1 through 255 are returned unchanged.
- A nonzero multiple of 256 produces zero.
- Values larger than 255 can produce any result from 0 through 255.

No threshold limit is applied in this case. A nonzero value of 100 produces 100 when paired with zero, not 99.

The addition does not create an unsigned-overflow edge case under the stated 32-bit interpretation: the branch requires one operand to be zero, so the sum equals the other representable operand. The subsequent mask discards all but the lowest eight bits.

### Both values nonzero

When both values are nonzero, the function compares each against 98 using unsigned ordering.

- If either value is strictly greater than 98, the function returns 99.
- Otherwise, it returns 98.

The threshold is strict. A value of exactly 98 does not trigger the result of 99.

There is no low-eight-bit reduction before these comparisons. For example, 256 remains greater than 98 in this case; it is not treated as zero.
