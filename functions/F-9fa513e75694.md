# F-9fa513e75694

## Purpose

F-9fa513e75694 conditionally submits an operation involving a primary object, a 32-bit selector, and a related-object reference. It uses a temporary 20-byte workspace, checks an unsigned capacity limit of 1000, invokes a preparation dependency, and optionally invokes a manager callback.

The selector value −1 selects a distinct path: the capacity increment can depend on the related object, and callback arguments are recomputed after the manager’s gate method. Every other selector uses an increment of one and a related-object flag to choose an operation attribute.

These role descriptions are inferred intent. The established behavior is the access and call sequence below. The meanings of the objects, capacity, attributes, and notification byte are not established.

## Interface

### Inputs

The supplied representation exposes three 32-bit inputs:

| Input | Interpretation established by use |
|---|---|
| Primary object | Address used for field reads and passed to dependencies. |
| Selector | A 32-bit value compared with −1, whose bit pattern is `0xffffffff`. Other values follow the ordinary-selector path. |
| Related object | A 32-bit address-like value passed to dependencies and, on some paths, dereferenced. Zero is specially handled only in one sentinel-path capacity calculation. |

The primary object must support the following accesses whenever the corresponding path reaches them:

| Byte offset | Access |
|---|---|
| `0xe3c` | One-byte read; converted to Boolean by comparison with zero. |
| `0xef4` | Unsigned 32-bit read on one sentinel-selector path. |

The related object has these path-dependent layout requirements:

| Byte offset | Access |
|---|---|
| `0x40` | 32-bit pointer read when the selector is −1, the current-related-object comparison differs, and the related object is nonzero. |
| `0x18c` | One-byte read on every ordinary-selector path that passes the capacity check; only bit 0 is inspected. |

The pointer obtained from related-object offset `0x40` must support an unsigned 16-bit read at offset `0x2e`.

These offsets describe observable layout requirements, not independently identified structure types.

### Output

The result is a 32-bit value:

- `0x00000000`: the normal completion path was reached.
- `0xffffffd7`: an initial eligibility check returned zero, or a capacity comparison rejected the operation.

Under signed 32-bit interpretation, `0xffffffd7` is −41. No named error category is established.

A zero result does not establish that the optional manager callback ran. A zero gate result skips that callback without changing the normal return value.

### Preconditions and unsupported conditions

There are no explicit null checks for the primary object, the context object, the manager, its method table, or the final notification target. The ordinary-selector path does not check whether the related object is zero before dereferencing it.

All accessed storage and indirect-call targets must be valid when used. Invalid pointers, dependency failures that do not return normally, and invalid method targets have no defined recovery behavior in the supplied evidence.

## Behavior

### Initial context and eligibility

1. Call F-8ff48652068d and retain its returned context address.
2. Read a 32-bit value at context offset `0xf40`.
3. Pass that value to F-3b037d560480.
4. If the result is zero, return `0xffffffd7` immediately.

This rejection path does not obtain the manager, initialize the temporary workspace, perform capacity checks, write the notification byte, or call the workspace finalizer.

If eligibility is nonzero:

1. Call F-87be4aa684d1 and retain the returned manager address.
2. Read context offset `0xf40` again.
3. Call F-1c06d0a5910b with the temporary workspace address, the newly read value, and zero.
4. Call F-d5511c118375 with the workspace address and retain its 32-bit result as the capacity base.

The two reads at context offset `0xf40` are separate. The second occurs after both the eligibility dependency and manager acquisition; the implementation does not require it to equal the first.

The temporary workspace occupies 20 bytes of local storage. Its internal format and initialization coverage are unknown.

### Capacity arithmetic

Both capacity comparisons use unsigned 32-bit arithmetic. The capacity base’s bit pattern is interpreted as unsigned for addition, and addition wraps modulo \(2^{32}\).

Rejection occurs only when the resulting unsigned sum is strictly greater than 1000. Equality with 1000 is accepted.

This is not a mathematical nonoverflowing capacity check. For example, a base bit pattern of `0xffffffff` plus one wraps to zero and passes the comparison.

### Sentinel selector: −1

Call F-267f68fe54d6 with the primary object. Compare its returned 32-bit value with the related-object input.

Determine the unsigned 32-bit capacity increment as follows:

- If the values are equal:
  - Call F-30529d2a9890 with the primary object.
  - After that call returns, read the unsigned 32-bit field at primary-object offset `0xef4`.
  - Use that field as the increment.
- If the values differ and the related object is zero:
  - Use an increment of zero.
- If the values differ and the related object is nonzero:
  - Read the pointer at related-object offset `0x40`.
  - Read the unsigned 16-bit field at offset `0x2e` through that pointer.
  - Zero-extend the field to 32 bits and use it as the increment.

The equality branch takes precedence over the zero-related-object case. If both compared values are zero, F-30529d2a9890 still runs and the primary-object field supplies the increment.

Add the increment to the capacity base using the arithmetic described above. If the unsigned sum exceeds 1000:

1. Call F-c1466ea05103 with the workspace.
2. Return `0xffffffd7`.

This rejection may already have called F-267f68fe54d6 and F-30529d2a9890. It does not undo their effects.

If the capacity comparison passes:

1. Read the byte at primary-object offset `0xe3c` and normalize it to 0 or 1.
2. Call F-be0967308708 with the primary object.
3. Call F-d3be6a307196 with these ordered arguments:
   - workspace address;
   - primary object;
   - selector bit pattern `0xffffffff`;
   - related object;
   - the result from F-be0967308708;
   - the previously captured Boolean.
4. Invoke the manager’s gate method at method-table byte offset `0x1b8`, passing the manager as receiver.

If the gate result is zero, skip the optional callback.

If the gate result is nonzero:

1. Read and normalize the primary-object byte at `0xe3c` again.
2. Call F-be0967308708 again.
3. Resolve the manager method at method-table byte offset `0x128`.
4. Invoke it with the manager as receiver, followed by:
   - selector −1;
   - related object;
   - the newly obtained dependency result;
   - the newly captured Boolean;
   - zero.

The callback’s attribute and Boolean may therefore differ from those passed to F-d3be6a307196. The second Boolean read precedes the second call to F-be0967308708.

### Ordinary selector: every value other than −1

Add one to the capacity base using unsigned 32-bit arithmetic.

If the result exceeds 1000, finalize the workspace with F-c1466ea05103 and return `0xffffffd7`. The related object’s flag byte is not read on this rejection path.

Otherwise:

1. Read the byte at related-object offset `0x18c`.
2. If bit 0 is clear, call F-be0967308708 with the primary object and use its result as the operation attribute.
3. If bit 0 is set, use the 32-bit value 2 instead; do not call F-be0967308708 on this path.
4. Call F-d3be6a307196 with:
   - workspace address;
   - primary object;
   - the original selector;
   - related object;
   - the selected attribute;
   - the Boolean value of the primary-object byte at `0xe3c`.
5. Invoke the manager’s gate method at method-table offset `0x1b8`.

The Boolean supplied to F-d3be6a307196 is read after any attribute-producing call to F-be0967308708. No relative ordering is asserted among argument reads internal to the preparation call’s evaluation.

If the gate result is nonzero:

1. Read and normalize the primary-object byte at `0xe3c` again.
2. Resolve the manager method at method-table offset `0x128`.
3. Invoke it with the manager as receiver, followed by the original selector, related object, previously selected attribute, newly captured Boolean, and zero.

Unlike the sentinel-selector path, this path does not recompute the attribute after preparation or gating. The callback receives the earlier attribute even if intervening calls changed relevant state.

### Normal completion

After preparation and any optional callback:

1. Read the pointer at retained-context offset `0xf00`.
2. Write the single byte value 1 at offset `0xb92` through that pointer.
3. Call F-c1466ea05103 with the workspace.
4. Return zero.

The notification pointer is read at this late stage, rather than cached before the intervening calls. The notification write occurs before workspace finalization.

## Side effects

### Direct effects

The only explicit nonlocal write shown is the one-byte assignment of 1 to the notification target at normal completion. It occurs whether the gate returns zero or nonzero.

No explicit restoration or rollback follows a capacity rejection. Initial eligibility rejection performs no workspace finalization because workspace initialization has not occurred.

### Indirect effects

Every dependency and indirect method may have effects not described by the supplied body. In particular:

- Do not assume dependencies preserve object fields, global state, manager method tables, or context fields.

- The sentinel path explicitly refreshes its attribute after gating; the ordinary path retains its earlier attribute.
- The manager method table is resolved at the respective call sites. There is no established guarantee that both calls observe an unchanged table.

### Ownership and lifetime

The workspace belongs to this invocation and is passed by address to dependencies. F-c1466ea05103 is called once on every normally returning path after workspace initialization: either at capacity rejection or at normal completion.

Its role as a finalizer is inferred from call placement. It is not established that it frees memory, releases references, or reverses preparation.

No ownership transfer of the primary object, related object, manager, context, or nested pointers is established. Whether callees retain any supplied address is unknown. No explicit allocation or release operation is visible in this function body.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, dependencies return normally and all required addresses are valid.

1. **Eligibility rejection.** If F-3b037d560480 returns zero, the result is `0xffffffd7`. No manager acquisition, workspace initialization, finalization, or notification write occurs.

2. **Ordinary-selector boundary.** With selector 4 and capacity base 999, the sum is 1000 and processing continues. With base 1000, the sum is 1001: workspace finalization occurs, the result is `0xffffffd7`, and no preparation or notification write occurs.

3. **Unsigned wraparound.** With an ordinary selector and capacity-base bit pattern `0xffffffff`, the sum wraps to zero and passes. Interpreting that base as a negative signed number must not replace the established unsigned calculation.

4. **Zero related object on the sentinel path.** If the selector is −1, the related object is zero, and F-267f68fe54d6 returns a nonzero value, the increment is zero. No related-object field is read to obtain it. Later dependencies still receive the zero related-object value.

5. **Equal comparison with zero.** If both the related object and F-267f68fe54d6 result are zero, F-30529d2a9890 runs and the increment comes from primary-object offset `0xef4`, not from the zero fallback.

6. **Unsigned 16-bit increment.** If the sentinel comparison differs and the nested field contains `0xffff`, its increment is 65535, not −1. With base zero, the operation is rejected after workspace finalization.

7. **Ordinary attribute override.** If the ordinary path passes capacity and related-object flag bit 0 is set, preparation receives attribute 2. F-be0967308708 is not called. A nonzero gate causes the optional callback to receive the same attribute 2.

8. **Gate declines callback.** If preparation completes and the gate returns zero, the optional callback is skipped, but the notification byte is still written to 1, the workspace is finalized, and zero is returned.

9. **Sentinel attribute refresh.** If the sentinel path passes capacity, the gate is nonzero, and the two calls to F-be0967308708 return different values, preparation receives the first value and the callback receives the second.

10. **Ordinary attribute retention.** If the ordinary path obtains an attribute from F-be0967308708 and the gate later changes state that would affect a fresh lookup, no fresh lookup occurs. The callback receives the retained attribute, with a freshly read Boolean.
