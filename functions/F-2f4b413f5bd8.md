# F-2f4b413f5bd8

## Purpose

F-2f4b413f5bd8 applies an integer-valued update to storage selected through an implicit context. A category and property determine the destination and whether the supplied value is stored directly, converted to a boolean, or encoded into one byte.

Requests that do not reach an accepted update invoke F-375c8199e7c2. Its effects and termination behavior are unknown; calling it does not establish that an error is reported or that state remains unchanged.

The apparent intent is a state-setting interface. Domain-specific meanings for the selectors, encodings, and fields are not established.

## Interface

### Inputs and output

| Contract name | Role | Evidenced representation |
|---|---|---|
| Value | Value to store or encode | Explicit 32-bit signed integer |
| Context | Base address of mutable storage | Implicit input carried in an integer-valued machine register |
| Category | Major dispatch selector | Implicit integer input |
| Property | Field and encoding selector | Implicit integer input |

The explicit Value alone is insufficient to invoke the operation correctly. The calling convention for the implicit inputs is not established.

Ordering comparisons are signed. Value comparisons occur before byte encoding; they do not compare only the low byte.

There is no explicit return value. An accepted update returns after its destination write. A fallback invocation returns only if F-375c8199e7c2 returns.

## Behavior

### Evaluation model and global stability

The source-visible read sequence below is authoritative for interpreting changing globals. It describes representation-level evaluation, not guaranteed physical load scheduling, atomicity, or volatile semantics.

The later compact dispatch and encoding tables assume that every relevant global remains stable during the invocation and that their arithmetic is representable. Without that assumption, separate read results govern separate decisions. In particular, failure of an equality test does not establish inequality against a later read of the same location.

### Major dispatch

The function first forms the address-valued base Context plus `0x944`; this calculation does not read the selected storage.

Category dispatch then behaves as follows:

| Condition | Result |
|---|---|
| Category `0x8861` and Property `0x8862` | Store one byte at S offset `0x42`: zero if Value is zero, otherwise one |
| Category other than `0x2300`, excluding that pair | Invoke F-375c8199e7c2 |
| Category `0x2300` | Continue with property dispatch |

The boolean route accepts every Value. It does not consult A through F.

### Property dispatch with individual read results

For Category `0x2300`, the following describes the actual decision sequence, including repeated reads.

1. Read A and compare Property with that result plus `0x11`. Equality selects family X at offset `Property − 0x855D`. No second property-threshold read occurs on this route.
2. If equality failed, read A again. Property below this second result plus `0x11` selects the lower region. Otherwise, select the upper region. The upper region therefore includes equality with the second threshold when the first equality failed.

In the lower region:

- Read B for equality with Property. A match stores Value as a 32-bit integer at offset `0x34`.
- If that equality fails, read B again and test whether this second result is below Property.
- If so, only Properties `0x8580`, `0x8581`, and `0x8582` select family X, at offset `Property − 0x8558`. Other properties fall back.
- Otherwise, continue to the lower literal routes. This continuation includes equality between Property and the second B read.
- Property `0x0D1C` stores Value as a 32-bit integer at offset `0x38`.
- Otherwise, Property `0x2200` selects family M at offset `0x25`.
- If neither literal matched, read D and compute U before checking whether Property selects family R or Q.
- Property `0x8571` selects family R at offset `0x26`; Property `0x8572` selects family Q at offset `0x27`. Any other property falls back after that D read and U computation.

In the upper region:

- Read F for equality with Property. Equality selects family Y at offset `Property − 0x8562`.
- If equality fails, read F again and test whether this second result is less than or equal to Property.
- If so, only Properties `0x8598`, `0x8599`, and `0x859A` select family Z, at offset `Property − 0x8567`. Other properties fall back.
- Otherwise, Properties `0x8589` and `0x858A` select family X at offset `Property − 0x855D`; Properties `0x8590` and `0x8591` select family Y at offset `Property − 0x8562`. Other properties fall back.

Thus, changed reads can route Property equal to the second F result into the family-Z property check rather than family Y.

### Encoding families and their reads

Every accepted encoding writes exactly one byte. Within each family, matches are evaluated in the stated order. An unmatched Value invokes F-375c8199e7c2 without a preceding destination write or index read.

#### Family X

1. Value `0x1702` encodes as 0, without an encoding-related A read.
2. Otherwise, read A and compare Value with that result minus one; a match encodes as 1.
3. Otherwise, read A again and compare Value directly with this new result; a match encodes as 2.
4. Otherwise, Value `0x8578` encodes as 3.
5. Otherwise, fall back.

These A reads are additional to any A reads used for property dispatch. A property-threshold result is not reused for encoding.

#### Family M

| Ordered condition | Byte |
|---|---:|
| Value = `0x2100` | 4 |
| Otherwise, Value < `0x2101` and Value = `0x0104` | 3 |
| Otherwise, Value < `0x2101` and Value = `0x0BE2` | 2 |
| Otherwise, Value < `0x2101` and Value matches a read of C | 1 |
| Otherwise, Value = `0x2101` | 0 |
| Otherwise, Value > `0x2101` and Value = `0x8570` | 5 |

C is read only after entering the below-`0x2101` region and failing its two literal matches. All other values fall back.

#### Family R

U has already been computed from one earlier D read. All comparisons against U use that retained result.

| Region and ordered match | Byte |
|---|---:|
| Value = U | 3 |
| Value > U, Value = `0x8575` | 4 |
| Value > U, Value = `0x86AE` | 6 |
| Value > U, Value = `0x86AF` | 7 |
| Value < U, Value = `0x0104` | 2 |
| Value < U, Value matches a read of C | 0 |
| Value < U, Value = `0x2100` | 1 |
| Value < U, Value matches a fresh read of D | 5 |

In the below-U region, C is read only after the `0x0104` mismatch. The later D read occurs only after the C and `0x2100` mismatches. It need not equal the D value from which U was computed.

#### Family Q

U has already been computed, even though the initial family-Q comparison is against D rather than U.

- Read D and compare it with Value. Equality encodes as 5.
- If equality fails, read D again and test whether this new result is below Value.
- When that test succeeds, Value equal to cached U encodes as 3; otherwise, Value `0x8575` encodes as 4.
- When that test fails, Value `0x0104` encodes as 2; otherwise, compare with a read of C for encoding 0; otherwise, Value `0x2100` encodes as 1.
- All unmatched cases fall back.

The last branch means Value is less than **or equal to** the second D result. It becomes strictly below D only under stable D, because the earlier equality has then excluded equality.

Under stable D, the compact regions are therefore: equality with D → 5; above D → cached U or `0x8575`; below D → `0x0104`, C, or `0x2100`, in that order.

There are no separate literal cases for `0x86AE` or `0x86AF` in Q.

#### Families Y and Z

Family Y first accepts Value `0x0300` as 0, then `0x0301` as 1, without reading E for either accepted literal.

After those mismatches, Y reads E and compares Value with that result minus one, encoding a match as 2. If that fails, it reads E again and compares Value directly with the new result, encoding a match as 3.

Family Z performs only these latter two E comparisons, with the same separate-read behavior and encodings. It has no independent `0x0300` or `0x0301` acceptance.

## Side effects

### Direct updates

An accepted path completes the necessary selector and value comparisons, then reads the index at Context offset `0x24C` once and writes one destination:

- One byte for boolean or encoded updates.
- Four bytes for either direct integer update, preserving the complete Value.

No previous destination value is read. No read-modify-write operation is visible. No further global read is visible between the index read and destination write.

The index is not captured at entry. Its value when the accepted path reads it determines the selected address. Global locations and context storage are not established to be disjoint.

### Fallback paths

Fallback paths perform no visible index read or destination write before invoking F-375c8199e7c2. They can nevertheless have performed global reads, including:

- Repeated A, B, or F reads during dispatch.
- D and U computation before rejecting an unsupported lower-region property.
- Encoding-related reads before rejecting Value.

These distinctions matter even when no direct update occurs. A fallback does not imply an absence of preceding memory accesses.

### Ownership and concurrency

No direct allocation, release, ownership transfer, or pointer retention is visible. Context-associated storage is mutated in place.

No lock, atomicity guarantee, snapshot of globals, or memory-ordering guarantee is established. Nothing establishes that F-375c8199e7c2 preserves globals or context, or that it refrains from acquiring or releasing memory.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. All assume valid accessed storage and representable arithmetic. Examples using fixed A through F assume relevant globals remain stable unless individual read results are specified.

1. **Boolean conversion:** Category `0x8861`, Property `0x8862`, and Value `0x100` write byte 1 at offset `0x42`, despite Value’s zero low byte. Value zero writes byte 0. Neither case reads A through F.

2. **Category rejection:** Category `0x8861` with another Property invokes F-375c8199e7c2 without a visible global-symbol or index read.

3. **Raw integer preservation:** With Category `0x2300` and Property `B < T`, Value −1 is stored as a complete 32-bit value at offset `0x34`. A is read twice for property dispatch; B is read once because equality succeeds.

4. **Adjacent encoded fields:** If `B < 0x8581 < T`, Property `0x8581` and Value `0x1702` write byte 0 at offset `0x29`. This route reads A twice and B twice during dispatch but performs no encoding-related A read.

5. **First threshold equality wins:** If T equals `0x2200`, that Property selects X rather than M. The destination is `Property − 0x855D`; the property equality uses one A read.

6. **Repeated A reads are not a snapshot:** Suppose the first A-derived threshold differs from Property, but the second equals Property. The operation enters the upper region, not X through the initial equality route. Further behavior depends on the F reads and upper literal checks.

7. **Second B equality can reach a literal route:** Suppose the first B read differs from Property `0x0D1C`, while the second equals it, after lower-region entry. The ordering test fails and the operation stores the raw Value at offset `0x38`, rather than selecting the B-equality destination.

8. **Second F equality can reach Z:** Suppose upper-region entry occurs for Property `0x8598`, the first F read differs from Property, and the second equals it. The less-than-or-equal test selects Z’s property group, not Y.

9. **Unsupported property still reads D:** Under stable globals, let Property `0x2201` be below T and below B. After the literal property mismatches, D is read and U computed. The operation then falls back without reading the index.

10. **Q retains U independently:** Suppose the preselection D read is `0x2000`, producing U `0x208D`. On a Q route with Value `0x208D`, let the equality and ordering reads of D both be `0x2001`. Equality fails, the ordering test succeeds, and cached U matches: byte 3 is written. U is not recomputed from `0x2001`.

11. **Q’s changed boundary permits equality in its lower branch:** On a Q route with Value `0x0104`, suppose the equality read of D differs from Value, but the ordering read equals Value. The ordering test fails and the literal case writes byte 2.

12. **R’s range gate matters:** On an R route, Value `0x86AE` writes byte 6 when above cached U, but byte 3 when equal to U. Below U, acceptance depends on that region’s matches instead.

13. **Encoding rereads remain distinct:** On X with Value `0x8578`, suppose its first encoding A read is `0x8578`, making the minus-one comparison fail, and its second encoding A read is also `0x8578`. Byte 2 is written before the literal byte-3 case can apply.
