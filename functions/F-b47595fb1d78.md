# F-b47595fb1d78

## Purpose

F-b47595fb1d78 selects among three direct word-write operations, a special save-and-restore sequence, and a return without target-memory access.

The special sequence saves five words, writes a version of one saved word with bit 4 cleared, writes one to another destination, performs a word read followed by a write of the value read, and writes the five saved values to restoration destinations.

The established behavior concerns address evaluations and memory accesses. The evidence does not establish that the addressed locations are device registers, identify their meanings, or prove that any write completes a hardware operation.

A significant distinction is that some accesses use base values captured at entry, while others evaluate the corresponding global again. The contract preserves those distinctions even when stable global values would make the resulting addresses identical.

## Interface

### Arguments and result

The function has two integer arguments:

- **Selector:** determines the operation.
- **Value:** supplies the direct-write value or, when the selector is zero, selects the special sequence if it equals one.

The represented integer model is 32 bits. Selector comparisons distinguish exactly zero, one, and two. The special value comparison distinguishes exactly one. There is no range validation or normalization.

The function returns no value, status, previous word, or completion indication.

Word accesses in the supplied representation are four bytes. Direct writes carry the value argument’s 32-bit representation. The special sequence treats saved words as four-byte values; its bit-clearing operation is a 32-bit mask.

Exact calling convention, endianness, and physical machine access widths remain documented_only unknowns.

### Global address inputs

Two global values supply addresses:

- **Control-base global:** supplies the base for a destination at byte offset `+0x0C`.
- **Register-base global:** supplies the base for several positive- and negative-offset word accesses.

These are descriptive roles, not established hardware meanings.

At entry, before selector-dependent behavior, the representation evaluates:

1. The control-base global, retaining an **entry-cached control base**.
2. The register-base global, retaining an **entry-cached register base**.

Later evaluations of either global are distinct from using these retained values. A later evaluation is not specified to return the same address.

“Evaluation” here describes the supplied representation. It does not establish a separate physical load instruction for every occurrence.

### Address layout

All offsets are bytes. Every listed target access is a four-byte word access.

| Base role | Offset | Use |
|---|---:|---|
| Control | `+0x0C` | Direct control write or special-sequence control write |
| Register | `−0x4FFF4` | Selector-two direct write |
| Register | `−0x4FFF0` | First snapshot, masked write, final restoration |
| Register | `−0x4FFE8` | Fifth snapshot and first restoration |
| Register | `+0x00` | Special-sequence read followed by write |
| Register | `+0x0C` | Selector-one direct write |
| Register | `+0x10` | Fourth snapshot and second restoration |
| Register | `+0x20` | Third snapshot and third restoration |
| Register | `+0x24` | Second snapshot and fourth restoration |

The applicable base evaluation is specified below. This table alone does not imply that accesses sharing an offset use the same base value.

The register-relative offsets result from scaling the represented word offsets by four. The control offset is an address increment of twelve bytes. Address overflow, pointer validity, and machine-level address arithmetic are not established by these offset conversions.

### Preconditions

For completing execution, global storage must support the represented evaluations. Every target address reached by the selected branch must support the applicable read or write.

The function does not validate null addresses, alignment, mapping, permissions, address overflow, region overlap, or concurrent modifications. A valid entry-cached base does not make a later global-derived address valid.

For an unrecognized selector, target-memory validity is unnecessary to the represented path because no target address is accessed. The two entry global evaluations still occur.

## Behavior

### Entry behavior

Every selector follows the same entry evaluation order: control-base global first, register-base global second.

These evaluations precede branch selection in the supplied representation. They occur even when their retained values are not subsequently used and even when the selected branch performs no target-memory access.

### Selector zero, value other than one

After the two entry evaluations:

1. Evaluate the control-base global again.
2. Write the value argument to the word at that newly evaluated base plus `0x0C`.
3. Return.

The destination does **not** use the entry-cached control base. The entry-cached register base is also unused by this path.

Zero is a direct-write value, not a no-operation request. Every value other than one follows this branch when the selector is zero.

### Selector one

After the two entry evaluations:

1. Evaluate the register-base global again.
2. Write the value argument to the word at that newly evaluated base plus `0x0C`.
3. Return.

Neither entry-cached base determines this write’s destination. The control destination is not independently accessed by this branch, although aliasing can make the same physical location reachable through different address expressions.

### Selector two

After the two entry evaluations:

1. Evaluate the register-base global again.
2. Write the value argument to the word at that newly evaluated base minus `0x4FFF4`.
3. Return.

This destination differs from both negative-offset locations used by the special sequence.

### Other selectors

Any selector other than zero, one, or two returns after the entry evaluations without a target-word read or write.

Under the represented signed 32-bit interpretation, this includes negative values and positive values greater than two. No invalid-selector status is produced.

### Selector zero, value one

This branch uses both entry-cached bases and repeated evaluations of the register-base global. The following order is established at the representation level.

#### Snapshot phase

Each snapshot separately evaluates the register-base global, then reads its corresponding word:

| Order | Base selection | Read offset | Saved value’s later use |
|---:|---|---:|---|
| 1 | First post-entry evaluation of register-base global | `−0x4FFF0` | Masked write and final restoration |
| 2 | Second post-entry evaluation of register-base global | `+0x24` | Fourth restoration |
| 3 | Third post-entry evaluation of register-base global | `+0x20` | Third restoration |
| 4 | Fourth post-entry evaluation of register-base global | `+0x10` | Second restoration |
| 5 | Fifth post-entry evaluation of register-base global | `−0x4FFE8` | First restoration |

These reads are not specified as relative to the entry-cached register base. Nor does the representation establish that the five evaluations produce one common base.

#### Modification and restoration phase

After all five snapshots:

1. **Evaluate the register-base global again**, for the sixth post-entry evaluation. At that base minus `0x4FFF0`, write the first saved word masked with `0xFFFFFFEF`. This clears bit 4, whose value is `0x10`, and retains the other 31 bits.
2. At the **entry-cached control base plus `0x0C`**, write the four-byte value one. This step does not reevaluate the control-base global.
3. At the **entry-cached register base plus `0x00`**, read a word and then write that same value back to that address.
4. At the **entry-cached register base minus `0x4FFE8`**, write the fifth saved word.
5. At the **entry-cached register base plus `0x10`**, write the fourth saved word.
6. At the **entry-cached register base plus `0x20`**, write the third saved word.
7. At the **entry-cached register base plus `0x24`**, write the second saved word.
8. At the **entry-cached register base minus `0x4FFF0`**, write the first saved word.
9. Return.

The read-and-write at offset zero uses a value read at that point, after the control write. It does not use a snapshot from the earlier phase.

The final write uses the original first snapshot without rereading its source or destination. The branch does not inspect saved values to decide whether to omit any access. In particular, an already-clear bit 4 does not remove the masked write.

### Base changes, aliasing, and final-state limits

If the register-base global changes, snapshots can come from different regions. The masked write can use yet another region. All restoration destinations nevertheless remain relative to the entry-cached register base.

Consequently, “restoration” describes the ordering and use of saved values, not an unconditional promise to restore each snapshot’s source location. With changing bases, the sequence can copy words from later-selected regions into the entry-selected region.

Changes to the control-base global after entry do not redirect the special control write. Conversely, the direct control-write branch uses its later evaluation, not the entry-cached value.

If bases remain stable, all targets are distinct ordinary-memory words, and no external modification occurs, the special sequence leaves the five saved locations with their initial values, writes one to the control destination, and leaves the offset-zero word with the value read there.

Without those conditions, final values must be derived from the ordered accesses. Aliasing can make a later restoration overwrite the control write. Target locations may also overlap global storage; there is no established non-aliasing guarantee.

## Side effects

At the representation level:

- Every path evaluates the two base globals at entry.
- Each direct-write path performs one additional global evaluation and one target-word write.
- An unrecognized selector performs no further represented memory access.
- The special path performs six additional register-base-global evaluations, six target-word reads, and eight target-word writes.

These counts distinguish global evaluations from target-word accesses. They are not counts of guaranteed physical memory transactions.

The offset-zero read-and-write is not an unconditional no-op. Reads and writes may have independent observable effects on device-backed or otherwise side-effectful storage, even when the written bit pattern equals the value read.

There is no visible allocation, deallocation, ownership transfer, resource acquisition, or explicit assignment replacing either global base. This does not exclude modification of global storage through an aliased target address.

No lock, barrier, interrupt-state change, retry, delay, polling operation, or completion check is represented. The function therefore establishes no atomicity, exclusion, device-completion guarantee, or machine-level ordering stronger than the supplied evidence supports.

There is no error-handling path or visible rollback mechanism. If an access fails, earlier accesses may already have occurred; fault behavior and subsequent execution are documented_only.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. References to changed base values specify what an evaluation observes; they do not assert a particular physical load implementation or synchronization mechanism.

### Direct control destination uses the later evaluation

Suppose selector zero and value seven are supplied. The entry control evaluation yields one region, while the later control evaluation yields a different region.

The write of seven must be described relative to the later-evaluated region at `+0x0C`, not relative to the entry-cached region. The entry register evaluation still precedes that later control evaluation.

The same rule applies to value zero and every other value except one.

### Direct register destinations use later evaluations

For selector one and value pattern `0x89ABCDEF`, the write is at `+0x0C` relative to the post-entry register-base evaluation.

For selector two with the same value, the write is at `−0x4FFF4` relative to that branch’s post-entry register-base evaluation.

If the entry register evaluation and the destination evaluation differ, the latter determines the destination in both cases.

### Unrecognized selector

For selector three, the represented behavior is:

- Evaluate the control-base global.
- Evaluate the register-base global.
- Return without target-word access or status.

Negative one follows the same path under the stated signed 32-bit interpretation.

### Stable-base temporary bit clearing

Assume stable bases, valid distinct targets, ordinary memory, and no concurrent modification. If the first saved word is `0x12345678`, the special branch writes `0x12345668` during the masked step and later writes `0x12345678` during final restoration.

If the first saved word is `0x00000001`, both writes carry `0x00000001`. Neither represented write is omitted.

### Distinct snapshot and restoration regions

Suppose the entry-cached register base identifies region A, but the second snapshot’s register-base evaluation identifies region B.

The second saved word comes from region B at `+0x24`. The fourth restoration writes that saved value to region A at `+0x24`. The contract must not describe this as restoring region B.

The same source-versus-destination distinction applies independently to each snapshot.

### Masked-write destination changes

Suppose the first snapshot reads value `0x12345678` through one register-base evaluation, but the masked-store evaluation yields another base.

The intermediate value `0x12345668` is written at `−0x4FFF0` relative to the masked-store evaluation. Final restoration writes `0x12345678` at `−0x4FFF0` relative to the entry-cached register base.

Those addresses need not equal the first snapshot’s address.

### Special control write and self-assignment remain entry-relative

If the control-base global changes after entry, the special control write still uses the entry-cached control base.

The subsequent offset-zero read and write, and all five restorations, still use the entry-cached register base regardless of later register-base-global values.

The offset-zero read occurs after the control write and before the first restoration. Its write uses the value from that read.

### Overlapping destinations

If the special control destination aliases a restoration destination, a later restoration can replace the value one. Acceptance must follow the ordered writes rather than require the final control-destination value to be one.

## Uncertainties

### Established static evidence

- Selector partition and special value comparison.
- Four-byte represented word accesses and the listed offsets.
- Entry evaluation order.
- Additional global evaluations on each direct-write path.
- Separate register-base evaluations for all five snapshots and the masked store.
- Entry-cached bases for the special control write, offset-zero access, and restorations.
- The 32-bit mask and represented access order.
- Absence of visible calls, status reporting, and error handling.

### Inferred intent

The special sequence appears intended to temporarily clear a bit while issuing another control operation and then restore selected state.

The hardware role of the bit, meaning of the control write, and purpose of the offset-zero read-and-write are not established.

### Documented_only unknowns

- Actual addresses, mappings, permissions, and alias relationships.
- Exact machine argument widths and calling convention beyond the represented 32-bit model.
- Endianness and physical load/store widths.
- Whether repeated global evaluations become separate machine loads.
- Compiler and processor ordering guarantees.
- Address-overflow and invalid-pointer behavior.
- Whether storage is ordinary memory, volatile, device-backed, or otherwise side-effectful.
- Permitted concurrent or asynchronous modifications.
- Fault behavior, partial completion, and device acceptance of writes.

These unknowns are not resolved by assuming stable bases or ordinary-memory semantics.

## Evidence

This contract is based solely on the supplied static function representation. The represented four-byte element size supports the register-relative byte-offset conversions. The control destination uses the separately represented twelve-byte address increment.

The distinction between retained entry values and later global evaluations follows the address expressions used for each access. It does not prove corresponding physical load counts or hardware transaction order.
