# F-56d00438c177

## Purpose

The available static evidence describes a long, call-interleaved sequence of byte and 32-bit memory updates. It does not establish a domain-level purpose such as initialization, serialization, resource release, or device control.

The visible operations repeatedly:

- Obtain values from indirect calls.
- Scale those values into addresses or call arguments.
- Copy or extract low-order portions of words into bytes.
- Write scaled values into locations with offsets of 0x14 or 0x24.
- Clear byte locations and word locations, including the absolute word at address 0x24.
- Forward opaque call results to later calls.

The supplied representation ends at an explicit bad-instruction termination marker, not a normal return. Its warnings also identify unreliable control-flow recovery and overlapping global storage. Consequently, this contract distinguishes the behavior represented in the supplied material from behavior established for an executable. No runtime behavior has been verified.

## Interface

**Declared inputs.** Three inputs are represented, each 32 bits wide. Only the third has an explicit data-flow use: an early indirect call receives it twice as its second and third arguments. The first two have no explicit uses in the visible body. Their absence from explicit expressions does not establish that they are irrelevant to the actual calling convention or indirectly invoked code.

**Additional entry state.** The represented body also depends on:

- An incoming link-like value used to form the first indirect call target.
- An incoming address-bearing value, from which a byte at offset 1 is read.
- An incoming byte written through that byte-derived address.
- Two secondary-register results attributed to earlier calls but not expressed as ordinary return values.

These are not established as ordinary API parameters. Their provenance and ABI significance are documented_only.

**Output.** The declared interface has no return value. There is no visible normal return. Memory changes and dependency invocations are the principal represented outputs.

**Access requirements.** Conditional execution of the represented trace requires every encountered call target to be executable and every encountered memory access to be valid. No bounds checks, alignment checks, null checks, or access-failure recovery are visible.

**Notation.** The following names describe contract values, not source identifiers:

- A byte is an unsigned 8-bit quantity.
- A word is a 32-bit quantity.
- `low8(value)` denotes truncation to the low eight bits.
- `wrap32(value)` denotes retention of the low 32 bits.
- “Byte-selected write through base” means: read an unsigned byte at base plus 1, then write a byte at that byte’s numeric value plus 0x11.

The last operation selects an address between 0x11 and 0x110. It is not a pointer-sized load from the base.

Address calculations below use the represented 32-bit machine interpretation. Signed-looking multiplications and shifts do not justify imposing source-language signed-overflow behavior on the original executable. Actual overflow semantics remain qualified by the recovery limitations.

## Behavior

### Ordering and dependency boundaries

The visible trace is linear: there are no represented loops, conditional branches, or early error returns.

Many direct memory operations are separated by indirect calls, often by runs of several calls with no explicit arguments. Those calls are observable boundaries, not removable decoration. They may change memory subsequently read by this function. A repeated load must therefore not be replaced by an earlier value merely because its address is unchanged.

Likewise, a value saved from an earlier call remains distinct from a later call’s result. Similar-looking address expressions do not establish a shared object or a shared dependency.

### Entry and initial word-to-byte copies

The represented sequence begins with two indirect calls. The second produces a word-sized result.

Next, the incoming byte is written through a byte selector read at offset 1 from the incoming address-bearing state. A following call receives four times the second call’s result.

After further calls, another call result is scaled by four. Call this scaled word the **initial scaled value**.

At that address:

1. Read a word at offset 0x74.
2. Write its low byte at offset 1.
3. Read the word at offset 0x74 again.
4. Invoke a dependency with that newly read word, followed by the third declared input twice.

The two word reads are separate observations. Aliasing, unusual memory behavior, or an external agent can make their values differ.

An opaque result is subsequently forwarded to another dependency. After further calls, a new result is scaled by four; its word at offset 0x74 is copied, by low-byte truncation, into offset 1. A subsequent dependency receives that scaled address.

### High-bit-derived writes

Define the **high slice** as the initial scaled value logically shifted right by 25. Define the **high placement** as the high slice shifted left by 23, and the **early quotient** as the high placement logically shifted right by 3.

The following represented operations occur in order, with dependency calls between groups:

1. Write the high slice shifted left by 19 to the word at four times the first secondary-register result plus 0x14.
2. Invoke a dependency with that secondary-register result.
3. Obtain a represented 64-bit call result.
4. Invoke another dependency with its low word, high word, and low word, in that order.
5. Obtain a new result; at four times that result plus 0x14, write the first secondary-register result shifted left by 3.
6. Pass four times the new result to a dependency.
7. Write early quotient times 0x80000 at early quotient times 0x200000 plus 0x14.
8. Invoke a dependency with early quotient times 0x80000 repeated three times.
9. Obtain another result; write the early quotient at four times that result plus 0x14, then pass four times the result onward.

Under 32-bit wraparound arithmetic, the early quotient is a multiple of 0x100000. Both products in step 7 therefore wrap to zero. That operation becomes a zero-word write at absolute address 0x14, and the next three explicit arguments are zero. This consequence is conditional on the represented width and wraparound interpretation.

### Byte selectors and linked scaled values

A later dependency supplies a word called the **first payload**.

The function reads the byte at early quotient plus 1 and writes `low8(first payload × 4)` at the selected address plus 0x11. A dependency then receives:

- The selected byte logically shifted right by 3.
- The first payload shifted left by 2.
- The early quotient shifted left by 2.

After more calls, the selector byte at early quotient plus 1 is read again. Call this second byte the **retained selector**. The selected destination receives the low byte of the first payload masked with 0x3FFFFFFF and logically shifted right by 20.

A newly obtained result, shifted left by 2, is passed onward. After intervening calls:

- First payload times four is written at retained selector times four plus 0x14.
- A dependency receives the retained selector three times, followed by the retained selector logically shifted right by 1.
- Another result supplies a destination at four times that result plus 0x14, where the same scaled first payload is written.

Two subsequent groups each obtain a fresh result, multiply it by four, and write that scaled value at sixteen times the unscaled result plus 0x14. Each scaled value is passed onward; the first is also copied into a later destination at four times a separately obtained result plus 0x14.

For the second group:

- An opaque intermediate return is forwarded.
- A later word destination receives the scaled value masked with 0x3FFFFFFF and logically shifted right by 1.

Another fresh result is scaled by four and written at sixteen times that result plus 0x14. The function then reads a word at the scaled value plus 0x14, logically shifts it right by 3, and passes it to a dependency. This read is not necessarily from the location just written: the write uses sixteen times the result, whereas the read uses four times the result.

A later destination receives that saved scaled value.

### Payload record fields

A new dependency result becomes the **record payload**. Its sixteenfold product is the **record base**. The record payload masked with 0x3FFFFFFF and logically shifted right by 1 is the **late quotient**.

Before establishing the subsequent record fields, the retained selector is written to the word at:

- `(retained selector logically shifted right by 3) × 0x80000 + 0x24`.

A dependency receives the record base and four times the record payload. After intervening calls:

1. Write the retained selector at record base plus 0x24.
2. Read the word at record base plus 0x74 and pass it onward.
3. Obtain a fresh result, retained here as the **shift source**.
4. Through record base, perform a byte-selected write of the low byte of the masked record payload logically shifted right by 20.
5. Pass four times the shift source to a dependency.
6. Forward an opaque return through another dependency.
7. Obtain a fresh result.
8. Reload the selector through record base and write zero through it.
9. Pass four times the fresh result onward.

The two selector loads through record base are distinct, with intervening calls.

Next:

- Write zero to the byte at late quotient plus 0x0F.
- Define the **clear base** as late quotient times 0x400.
- Perform a zero byte-selected write through clear base.
- Invoke a dependency with the shift source shifted left by 23 repeated three times, followed by the shift source shifted left by 25.

### Repeated clearing and absolute storage

After a result-forwarding sequence and further calls, the selector at clear base plus 1 is read again. Zero is written at that selector plus 0x11. A separately obtained result, shifted left by 2, is passed onward.

The saved selector then determines a word-clear destination:

1. Write zero at selector plus 0x44.
2. Write zero to the absolute word at address 0x24.
3. Invoke a dependency with arguments 0, 0x98, clear base, and 0x98.

The selector-plus-0x44 destination need not be word-aligned.

After further result forwarding and calls:

- A freshly returned result selects a zero-word write at four times the result plus 0x44.
- The absolute word at 0x24 is again cleared.
- Four times that result is passed onward.

A later represented 64-bit return is split. A dependency receives its low word shifted left by 2. After that call, zero is written at twice the saved high word plus 0x44, followed by another zero write at absolute 0x24.

Another dependency receives zero, the second secondary-register result, and that secondary result shifted left by 2.

After another call, a dependency receives the late quotient masked with 0x3FFFFF and shifted left by 7. Further calls lead to another zero-word write at four times a fresh result plus 0x44, another absolute 0x24 clear, and forwarding of the scaled destination.

These are four explicit absolute-word clears at 0x24. Their repetition matters: intervening dependencies may modify that storage.

### Final links and byte updates

A dependency consumes four times a newly obtained result and returns another result. Zero is written at four times this returned value plus 0x14. The next dependency receives that value three times and the masked late quotient shifted left by 7.

After further calls, a fresh result selects another zero-word write at four times the result plus 0x14.

The function then performs two more linking groups:

- A result’s fourfold value is written at its sixteenfold address plus 0x14 and later copied to four times a different result plus 0x14.
- Another result’s fourfold value is written at its sixteenfold address plus 0x14, followed by a dependency receiving the fourfold and sixteenfold values.

An opaque return is forwarded together with the masked late quotient shifted left by 4. Later, the masked late quotient times 0x80 is written at four times a newly obtained result plus 0x14.

Define the **final selector base** as late quotient times 0x4000000. Subsequent operations are:

1. Obtain a payload; through final selector base, write its fourfold low byte.
2. Pass four times that payload onward, then forward an opaque result.
3. Reload the selector through final selector base and write the low byte of the same payload masked with 0x3FFFFFFF and shifted right by 20.
4. Pass four times a separately obtained result onward.
5. Obtain a new payload, reload the selector through final selector base, and write its fourfold low byte.
6. Pass the loaded selector, zero-extended, to a dependency.
7. Forward another opaque result.
8. Through eight times the new payload, perform a byte-selected write of the low byte of that payload masked with 0x3FFFFFFF and shifted right by 20.
9. Pass four times a separately obtained result onward.
10. Execute the remaining represented indirect calls and reach the bad-instruction termination marker.

The last byte-selected write uses a different base from the preceding final-selector-base operations.

## Side effects

The direct visible effects are byte stores, word stores, and indirect dependency invocations. No explicit allocation, deallocation, ownership transfer, lock operation, or I/O API is identifiable.

No ownership guarantee follows from passing a numeric value to a dependency. Dependencies may retain values, release resources, mutate shared memory, or fail; their contracts are unavailable.

The function itself performs no visible rollback. If execution faults or a dependency does not return, earlier writes may already have occurred. A zero store is still an observable write; identical values do not make repeated stores or calls redundant.

The absolute location 0x24 and byte-selected low addresses may denote ordinary memory, mapped hardware, special runtime storage, or invalid addresses. Their meaning is not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Duplicated third input.** If the second read of the initial word field returns 0x11223344 and the third declared input is 0xAABBCCDD, the corresponding call receives 0x11223344, 0xAABBCCDD, and 0xAABBCCDD.

2. **Low-byte copy.** If a word read for an initial offset-1 update yields 0x123456AB, the byte written is 0xAB. The later word read for the call remains independent.

3. **Unsigned selector.** If a selector load returns 0xFE, its selected byte destination is address 0x10F. It is not a negative displacement or a loaded pointer.

4. **Masked extraction.** For payload 0x3AB00000, masking with 0x3FFFFFFF and shifting right by 20 produces 0x3AB. A byte destination receives 0xAB, not a ten-bit value.

5. **Wrapped high-derived operation.** Under 32-bit wraparound, the early quotient’s alignment forces the described large-product store to write zero at address 0x14. Nonzero high bits do not prevent this wraparound.

6. **Reload after mutation.** If a dependency changes a selector byte between two represented loads, the second write follows the new selector. Reusing the first selector would violate the represented read order.

7. **Distinct link and read locations.** For a linking-group result of 3, the sixteenfold destination plus 0x14 is 0x44, while the fourfold read location plus 0x14 is 0x20. The subsequent call consumes the word read at 0x20 shifted right by 3.

8. **Repeated absolute clear.** If a dependency changes address 0x24 after one clear, the next explicit clear writes zero again. The contract does not guarantee that address 0x24 remains zero after later calls.

9. **Interrupted execution.** If a dependency fails to return, later direct writes are not required to occur. Previously performed writes are not represented as undone.
