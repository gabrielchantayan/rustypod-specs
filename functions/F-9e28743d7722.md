# F-9e28743d7722

## Purpose

F-9e28743d7722 scans consecutive bytes from a caller-supplied address and accumulates a base-ten-weighted integer result.

Its behavior is **not equivalent to ordinary decimal-string conversion**. The continuation test establishes only an upper bound on the current byte. Under the unsigned eight-bit interpretation of the supplied byte type, every value from 0 through 57 is accepted, including zero, whitespace, punctuation, and decimal digits. Values from 58 through 255 terminate the scan.

For accepted decimal digits, the accumulator behaves as a decimal parser while arithmetic remains representable. For accepted bytes below the digit range, the byte contributes a negative offset relative to the value 48.

The apparent intent is decimal conversion. That intent is inferred, not an additional restriction on accepted input.

**Input:** one pointer to byte-addressed memory.

**Output:** one integer result, returned directly. There is no separate status result, consumed-length result, or end-pointer output.

The supplied representation uses a byte type, a signed integer type for the result and accumulator, and an unsigned integer cast within the accumulation expression. Their definitions and target ABI are not provided.

The following width distinctions matter:

- The signed and unsigned integer types are corresponding integer types. A 32-bit interpretation is plausible for this representation but is not independently established by a type definition or ABI description.
- Numerical boundary examples explicitly identified as 32-bit are conditional on 32-bit signed and unsigned integers.

**Memory preconditions:**

No writable input storage is required. The function does not take ownership of the input and does not return ownership of any storage.

## Behavior

### Initial state and termination

The accumulator begins at zero. Before accepting any byte, the function reads the byte at the current cursor and evaluates whether subtracting 48 produces a value less than 10.

With unsigned eight-bit input promoted to a signed integer wide enough for the subtraction, that condition is true exactly for byte values 0 through 57. In particular, a negative subtraction result satisfies the comparison.

Consequently:

- Bytes 48 through 57 are accepted as ordinary decimal digits.
- Bytes 0 through 47 are also accepted.
- Bytes 58 through 255 end the scan.
- A terminating byte is inspected but does not contribute to the result.
- If the first byte terminates the scan, the result is zero.

Termination depends only on the byte comparison. There is no explicit termination on zero, end of allocation, a character count, arithmetic magnitude, or an error condition.

### Input-read and cursor order

The supplied expression structure establishes this source-level order for each accepted position:

1. Read the current byte for the continuation decision.
2. If accepted, read the current byte again for accumulation.
3. Update the accumulator.
4. Advance the local cursor by one byte.
5. Evaluate the continuation decision at the new position.

At a terminating position, only the continuation read is required by that structure. There is no subsequent accumulation read or cursor advance for that position.

The two reads at an accepted position are separate source-level evaluations. The input is not declared volatile or atomic, however. This contract therefore does not promise two distinct machine load instructions. It also does not define behavior for unsynchronized concurrent modification or memory-mapped input.

For stable, ordinary memory, both evaluations observe the same byte. All examples below assume that condition.

The cursor is a local copy of the supplied pointer. Advancing it does not write a new pointer value into caller-owned storage.

### Accumulation

For stable input and arithmetic that supports the mathematical result, each accepted byte updates the accumulator according to:

\[
A_{\text{next}} = 10A_{\text{current}} + b - 48
\]

Here, \(b\) is the accepted byte value.

For a decimal digit, \(b-48\) is between zero and nine. For any accepted byte below 48, the contribution is negative. Such a byte is processed at its encountered position; it is neither skipped nor interpreted as a formatting directive.

In particular:

- Whitespace is not skipped.
- A plus sign is not treated as a positive-sign marker.
- A minus sign is not treated as a negative-sign marker.
- A zero byte is not treated as an end marker.
- Leading decimal zeroes are accepted and still cause reads and cursor advances.
- There is no special handling of a numeric prefix or a radix indicator.

Once a terminating byte is encountered, the current accumulator is returned without a separate normalization or validation step.

### Arithmetic limits and conversions

The mathematical recurrence describes ordinary, representable cases. It is not sufficient to establish behavior for every long input.

The multiplication by ten is formed from signed integer operands. The byte used for accumulation is explicitly converted to the unsigned integer type. The subsequent additions therefore involve unsigned arithmetic under the usual corresponding-type interpretation. The resulting expression is then assigned back to the signed accumulator.

These stages create distinct boundary conditions:

- Signed multiplication can overflow before the unsigned additions take place.
- The unsigned additions use arithmetic modulo the unsigned type’s range.
- Assigning an unsigned result outside the signed type’s representable range back to the signed accumulator depends on the applicable language and implementation rules.

The supplied representation does not justify a universal guarantee of wrapping, saturation, trapping, rejection, or correct arbitrary-length conversion.

For a conventional 32-bit interpretation, signed multiplication must remain within \(-2^{31}\) through \(2^{31}-1\). Even if that multiplication is representable, the final unsigned expression can lie outside the signed range. These are separate cases and must not be conflated.

## Acceptance examples

These examples assume stable memory, unsigned eight-bit bytes, and ordinary representable arithmetic unless stated otherwise. Character names refer to their conventional ASCII byte values. A colon has value 58 and provides a terminating byte.

| Input beginning at the supplied address | Expected behavior |
|---|---|

| Lowercase `a` | Returns zero because byte value 97 terminates immediately. |
| `123` followed by colon | Returns 123. The colon is inspected but not accumulated. |

The negative-result examples are conditional because the accumulation expression passes through unsigned arithmetic before assignment to the signed accumulator. They are not evidence that the unspecified implementation must choose a particular out-of-range unsigned-to-signed conversion.

- **32-bit signed boundary:** For digits representing 2147483648 followed by a colon, the last multiplication can remain signed-representable while the final unsigned expression exceeds the signed maximum. The returned signed value is not established here.

- **Unreadable initial address:** No defined error code or safe failure behavior is established.
