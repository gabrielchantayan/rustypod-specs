# F-0c4833245f7e

## Purpose

The supplied static representation describes a sequence of indirect calls interleaved with byte and 32-bit memory accesses. Call results, explicit inputs, entry-state values, and loaded data determine subsequent call arguments, addresses, and stored values.

No higher-level purpose is established. The accesses do not establish an object model, allocation protocol, device interface, or serialized format.

The representation reports invalid instruction data and ends at a truncated control-flow boundary. This contract describes the visible execution prefix, conditional on preceding calls returning and memory operations completing. It does not establish normal termination.

Additional required state includes:

The four explicit inputs therefore do not determine the execution.

### Outputs and completion

The visible interface has no ordinary return value. Observable outputs consist of memory accesses and dependency interactions.

One dependency supplies a represented 64-bit result, subsequently split into two 32-bit halves. Other consumed call results are 32-bit quantities.

The final call is followed by the reported invalid-instruction boundary, not an established normal return. Whether execution actually traps or continues through instructions absent from the representation remains documented_only.

### Widths and arithmetic

A byte read yields an unsigned value from 0 through 255. A byte store retains the low 8 bits. A word access transfers 32 bits. Logical right shifts insert zeros.

Explicit unsigned 32-bit products, additions, and left shifts operate modulo \(2^{32}\). This rule does **not** automatically apply to signed expressions merely because their result is later assigned to unsigned storage.

Signed-represented arithmetic occurs in input-relative addresses, scaled call results, publication addresses, and several left shifts. Overflow, negative signed left shifts, and out-of-range unsigned-to-signed conversions require interpretation beyond the supplied representation. This contract does not resolve them by assuming wrapping machine arithmetic.

Memory validity, alignment, executable call targets, and returning dependencies are preconditions for reaching later stages. No visible checks establish those conditions.

## Behavior

### Call notation

Opaque IDs **F-U01** through **F-U24** identify ordered call-site groups, not proven distinct functions. A suffix, such as **F-U01.1**, identifies a call within a group.

Unless otherwise specified, a **five-call chain** has:

- A first call receiving the listed explicit arguments.
- Four subsequent calls with no explicit arguments shown.
- A consumed result from the fifth call.

“No explicit arguments shown” does not mean that the destination cannot observe register or stack inputs. Results from earlier calls are not automatically forwarded as explicit arguments.

All five-call chain results consumed below are represented as signed 32-bit values except the unsigned results of F-U01 and F-U21. F-U09 has no subsequently consumed result.

The following stages are ordered. Within a stage, the stated memory operations occur in the stated order, except for the explicitly unresolved ordering of two argument reads.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes preceding execution reaches the relevant operation and required accesses are valid.

1. **Initial ordering.** With an entry-state word of `0x12345678` and a representable first-input-plus-20 address, that word is stored before F-U01.1.

2. **Byte truncation.** If the first result is 65 and the entry-relative byte is 3, the first byte store writes 4 at address 20: four times 65 is 260.

3. **Unsigned address wrap.** If the first result is `0x04000000`, its unsigned multiplication by 64 yields zero. The second byte read therefore addresses 1.

4. **Masked byte value.** If the first result is `0x3ff00000`, the masked right shift produces 1023; the byte store writes 255.

5. **Zero-store indirection.** If the zero-update read at address 1 yields 255, zero is stored at address 272, not address 1.

6. **Distinct publication and read addresses.** A publication result of 2 stores word 8 at address 52. A subsequent read at its scaled value plus 20 addresses 28.

7. **Extraction evaluation order.** If F-U18 returns 3, the signed product is 12, its unsigned conversion remains 12, and the extraction store addresses 32. If F-U18 instead returns `0x20000000` as a positive signed value, multiplication by 4 exceeds the signed 32-bit range. This contract does not require extraction base `0x80000000`.

8. **Fresh final read.** If F-U18 returns zero, both final byte-read expressions address 1 without signed overflow. If their observed bytes are respectively 2 and 9, the final stores address 19 and 26. Reusing the earlier byte would not match the represented behavior.

9. **Partial execution.** If a dependency does not return, later direct stores are not required. Previously completed effects have no visible rollback.
