# F-2ba4f513a37c

## Purpose

The established behavior is an ordered sequence of four byte stores interleaved with 24 indirect calls. The function takes one explicit 32-bit unsigned input and also depends on incoming machine context that is not represented in its declared interface.

The stores use byte-valued address selectors. Each selector is read from memory, zero-extended, and increased by 17 to obtain the destination address. Consequently, each explicitly visible store targets one byte at an address between 17 and 272 inclusive. Whether those addresses represent ordinary memory, mapped devices, or an invalid address range is not established.

The available representation ends at an explicitly marked bad-instruction boundary. It does not establish a normal return, a successful completion status, or the actual machine behavior beyond that boundary.

No higher-level purpose is established. In particular, interpreting the operation as serialization, device programming, or a protocol exchange would require evidence not present here.

## Interface

### Explicit input

The function accepts one unsigned 32-bit value, called the **input word** in this contract.

Its visible uses are:

- The low eight bits supply the first stored byte.
- The complete word is passed to the first indirect dependency.
- Bits 22 through 29 supply the second stored byte.

Bits not selected for the stores still reach the first dependency through the complete argument.

### Implicit inputs

Two incoming machine-context values affect execution:

- A register-derived signed integer supplies the initial selector-table location after multiplication by 524,288.

Neither value is initialized within the visible function. Their validity, source, and relationship to the caller are undocumented.

Memory at the selector locations is also input. The function reads those locations at the points specified below; it does not take a single selector snapshot at entry.

### Output and completion

## Behavior

It reads one unsigned byte at the address one byte beyond that base. Call this first selector value **S1**.

It then stores the low eight bits of the input word at address S1 + 17.

The selector is an address component, not an index scaled by an element size. Because it is an unsigned byte, the destination is within the inclusive address range 17–272.

### 5. Perform the third store and forward its selector

The function reads the selector byte at the initial base plus one again. Call this value **S3**.

It stores the low eight bits of four times the low byte of the derived word at address S3 + 17. At the byte level, the stored value is:

- Derived-word bits 0–5 moved into stored bits 2–7.
- Stored bits 0 and 1 cleared.
- All higher derived-word bits discarded.

Equivalently, the stored byte is four times the derived word, reduced modulo 256.

The function then calls F-900000000013 with S3 zero-extended to a 32-bit unsigned argument. The argument is the selector byte, not the store destination address and not the stored value.

There is no additional selector read between this store and that call. Thus the call receives the selector used for this particular store even if the selector location subsequently changes.

### 7. Perform the fourth store

The function computes a new selector-read address from the derived word:

- Multiply the derived word by eight using unsigned 32-bit arithmetic.
- Add one using unsigned 32-bit arithmetic.
- Interpret that resulting value as an address.

Both unsigned operations reduce modulo 2³². This location is independent of the initial base except where the resulting numeric addresses happen to coincide.

The function reads one unsigned byte from this new location. Call it **S4**.

It then stores a byte at address S4 + 17. The stored value is obtained by masking the derived word to its low 30 bits, shifting right by 20, and retaining the low eight bits.

The resulting stored byte contains derived-word bits 20–27. Bits 28 and 29 survive the intermediate mask and shift but are discarded by the final byte narrowing. Bits 30 and 31 are removed by the mask.

| Stage | Selector read location | Store destination | Stored byte |

These operations are not shown as a transaction. There is no visible rollback, locking, or restoration of earlier bytes after a later failure.

### Selector rereads

Suppose the first three selector reads return 3, 9, and 255 respectively. The first three store destinations are addresses 20, 26, and 272.

F-900000000013 receives 255. It does not receive 272.

This behavior is acceptable even though the three selector reads use the same location: intervening calls may change its contents.

### Derived-word truncation

- The third stored byte is `0xE0`.
- The final selector-read address is `0x91A2B3C1`.
- The fourth stored byte is `0x23`.

The actual fourth store destination still depends on the byte read at that computed address.

### Unsigned address wraparound

If the derived word is `0x20000000`, multiplication by eight wraps to zero in unsigned 32-bit arithmetic. The final selector is therefore read at address 1.

The third and fourth stored bytes are both zero. This example does not establish that address 1 is valid to read.

### Safe signed-shift arguments

If F-900000000007 returns 7, F-900000000008 receives 28.

If F-900000000019 returns 9, F-900000000020 receives 36.

These examples do not specify behavior for negative results or signed results whose left shift exceeds the signed range.

### Repeated destination

If all four selector reads return 5 and no other operation modifies address 22, all four explicit stores target address 22. After the fourth store, that byte contains derived-word bits 20–27.

Earlier values are still written in order; they are not omitted merely because the final destination is the same.
