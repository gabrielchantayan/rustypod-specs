# F-a1885c38e61e

## Purpose

F-a1885c38e61e returns the low 24 bits of an input word, optionally reduced by a value obtained from F-b4f2a03d18ae.

The decision to obtain that adjustment depends on selected high bits of the input word. The adjustment, when requested, is obtained by passing an address three input-word elements beyond the supplied address. The result is an unsigned subtraction result, not necessarily a value confined to 24 bits.

Established behavior is limited to this extraction, conditional dependency invocation, and subtraction. Interpreting the input as a particular record type, or interpreting the result as a length, count, or offset, would be inferred intent rather than established behavior.

## Behavior

### Initial extraction

The function first obtains the first unsigned input word and retains only its low 24 bits using the mask `0x00FFFFFF`.

For a 32-bit input word, this produces a value between 0 and 16,777,215 inclusive. Bits 24 through 31 do not contribute to this initial value.

This extracted value is saved before the conditional dependency call can occur. The function does not explicitly recompute it after that call.

### Adjustment decision

The function evaluates the first input word again in the condition. It selects bits using `0x70000000`, shifts the selected value right by 26 bit positions, and compares the result with 4 using a strict greater-than comparison.

The shift count is significant. Although the selected bits are at positions 28 through 30, the shift is by 26, not by 28. Consequently, the comparison operand can take the values 0, 4, 8, 12, 16, 20, 24, or 28.

For a stable 32-bit input word, the decision is:

| Value of bits 30–28, interpreted as a three-bit field | Value after masking and shifting | Adjustment requested |
|---|---:|---|
| 0 | 0 | No |
| 1 | 4 | No |
| 2 | 8 | Yes |
| 3 | 12 | Yes |
| 4 | 16 | Yes |
| 5 | 20 | Yes |
| 6 | 24 | Yes |
| 7 | 28 | Yes |

Equivalently, for this width model, the adjustment path is taken when bit 29 or bit 30 is set. Bit 28 alone does not trigger it.

Bit 31 is excluded by the decision mask. Bits 24 through 27 are also excluded. These bits affect neither the initial extraction nor the decision.

### Path without adjustment

When the comparison is false, F-b4f2a03d18ae is not invoked. The saved low-24-bit value is returned unchanged.

In this path, no address three elements beyond the input is explicitly formed or passed to another function. There is no adjustment-related access requirement imposed by the visible body on that path.

### Path with adjustment

When the comparison is true:

1. The function forms an address three unsigned-integer elements beyond the supplied pointer.
2. It invokes F-b4f2a03d18ae once with that address.
3. If the dependency returns normally, its result is received into a signed-integer temporary.
4. That value is subtracted from the previously saved unsigned extraction.
5. The unsigned subtraction result is returned.

There is no explicit second dependency call, retry, result validation, saturation, or post-subtraction mask.

Under the 32-bit model, subtracting the signed adjustment from the unsigned saved value converts the adjustment to the unsigned arithmetic domain. The result is the mathematical difference reduced modulo 4,294,967,296.

Consequences include:

- A positive adjustment larger than the extracted value wraps to a large unsigned result.
- A negative adjustment acts as an increase, subject to the same modulo reduction.
- The final result may have nonzero bits above bit 23.
- An adjustment of zero preserves the extracted value.
- An adjustment equal to the extracted value produces zero.

This behavior does not establish that every signed adjustment value can actually be returned by F-b4f2a03d18ae. It establishes the arithmetic applied if such a value is received.
