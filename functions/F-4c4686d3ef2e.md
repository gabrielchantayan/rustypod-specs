# F-4c4686d3ef2e

## Purpose

F-4c4686d3ef2e selects an integer value from two locations associated with a supplied memory base. The location at displacement 32 has priority. Its value is returned when nonzero; otherwise, the value at displacement 28 is returned.

Selection depends on equality with zero, not sign or magnitude. A negative value at the priority location takes precedence over any fallback value. The fallback is accepted without further qualification and may itself be zero.

“Priority” and “fallback” describe selection roles only. An application-level interpretation such as override and default is inferred intent, not an established field meaning.

The function receives one signed-integer argument used as a memory-address base. No length, object descriptor, status destination, or separate validity indicator is supplied.

The relevant locations are identified by fixed numeric displacements:

| Displacement from base | Role | Access requirement |
|---|---|---|
| 32 | Priority integer | Read on every normally completing call |
| 28 | Fallback integer | Read only when the priority observation is zero |

Under a byte-addressed target interpretation, these are byte displacements, not integer-array indices. The evidence does not identify the containing object, its total extent, or its allocation origin.

The integer-form argument is not evidence of a portable pointer interface. A caller must use a representation that the actual environment can interpret as the intended base. The contract does not authorize truncating a wider address to fit the argument.

### Result

Normal completion returns one signed integer. There is no separate success indicator.

A nonzero priority observation is returned unchanged. A zero priority observation instead causes the fallback observation to be returned unchanged. Zero is therefore a valid data result, not an identified error code.

The function does not report which location supplied the result.

## Behavior

### Selection and access ordering

The priority location controls both result selection and the need to access fallback storage.

When its observation is nonzero, that observation determines the return value. The fallback’s value does not participate in the decision, and the established path has no fallback read.

When the priority observation is zero, the fallback location supplies the result. The fallback observation occurs after the priority observation. There is no further test requiring the fallback to be positive, nonzero, or otherwise acceptable.

This establishes conditional access, not merely a preference between two values already obtained. Reading fallback storage unconditionally could introduce an access that the nonzero-priority path does not require.

There is no explicit second observation of the priority location, retry, comparison between the two values, or third result source.

### Preservation of selected values

The selected integer is returned without numerical modification. In particular:

- Nonzero values are not normalized to one.
- Negative values are not treated as absent.
- Negative values are not negated.
- A fallback value of zero is not replaced with another value.
- The larger of the two field values is not necessarily selected.

The smallest representable negative value is eligible for selection. Returning it does not require an intermediate absolute-value calculation or other arithmetic on the field value.

These guarantees concern valid integer representations. The evidence does not define behavior for storage that cannot validly be read as the required integer type.

### Address calculations

Both locations are derived from the supplied base using fixed positive displacements. Neither field’s contents affect either address.

The supplied representation performs signed-integer address arithmetic before interpreting the resulting value as a memory address. It supplies no overflow check, saturation rule, or explicit wraparound mechanism.

Accordingly, valid address formation is a precondition. A caller cannot rely on an overflowing addition to wrap to some other readable location. A numerically representable sum alone is also insufficient: its interpretation must designate storage that can legally be read in the target environment.

The exact relationship between integer values and usable memory addresses remains **documented_only**. In particular, the function establishes no portable rule for address provenance, negative integer-form addresses, address-space boundaries, or conversion to a wider pointer representation.

### Changes during execution

The function does not establish a combined snapshot of the two fields.

If the execution environment permits intervening changes, a zero priority observation is followed by a later fallback observation. The returned fallback value need not match the fallback’s value at the earlier observation time.

Likewise, an observed nonzero priority value remains the selected value even if that location changes afterward. No explicit reread updates the result before return.

These are conditional descriptions of the access structure, not guarantees of thread safety. The evidence contains no explicit synchronization or atomic-access qualification. It also does not establish that every source-level observation corresponds to one indivisible hardware transaction.

### Priority is not a magnitude comparison

If the priority observation is 1 while fallback storage contains 500, the result must be 1. Selecting 500 because it is larger would violate the selection rule.

If the priority observation is −1 while fallback storage contains 500, the result must be −1. Treating a negative priority value as unavailable would also violate the rule.

### Conditional fallback accessibility

If the priority observation is nonzero, the established path does not require a fallback read. This does not independently prove that an arbitrary surrounding layout is valid, nor does it constrain speculative hardware behavior.

If the priority observation is zero and fallback storage is inaccessible, no normal result is specified. Returning a manufactured default instead of performing the required access would not satisfy the established behavior.

### Representation boundaries

On a target with 32-bit two’s-complement signed integers, priority observations of −2,147,483,648 and 2,147,483,647 must each be returned unchanged.

With a zero priority observation, either boundary value observed in fallback storage must likewise be returned unchanged. These criteria concern value preservation, not arithmetic on the selected value.

### Intervening changes

In an environment where the observations are legal, suppose the priority observation is zero and the later fallback observation is 12. The result must be 12, even if fallback storage contained 7 earlier.

If the priority observation is 6 and that location later changes to zero, the selected result remains 6. The contract does not require another priority observation.
