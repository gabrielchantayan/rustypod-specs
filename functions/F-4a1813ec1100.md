# F-4a1813ec1100

## Purpose

F-4a1813ec1100 dispatches an event through a sequence of conditional handlers and object-associated callbacks.

Its established behavior is:

1. Optionally invoke a preliminary dependency for a particular nested event code.
2. Recognize one nested code as an unconditional handled result after invoking a dependency.
3. Give another nested code an additional opportunity to produce a nonzero result.
4. Select and invoke one of two object-associated callbacks.
5. If that callback returns zero, conditionally invoke a final object-associated callback.
6. Return the first applicable nonzero result, except for the unconditional handled case, which returns exactly one.

The meanings of the event codes and callbacks are not established. Terms such as “event,” “object,” and “handled” describe the apparent dispatch structure, not a verified application-level protocol.

## Interface

The function receives two address-bearing arguments:

| Argument | Role |

The result is represented as a 32-bit integer in the supplied representation.

Zero means that none of the reached result-producing handlers returned a nonzero value. Nonzero values are generally propagated unchanged. One branch instead returns the fixed value one, independently of its dependency’s result.

## Behavior

### 1. Preliminary notification

The function first reads the event discriminator at +0x04.

If that value is 0x16, it reads the nested-record address from event +0x08 and then the nested code from nested record +0x04.

Only nested code 0x2503 triggers the preliminary call:

- Read the 32-bit object field at +0x11C.
- Convert that value to a character-sized argument.
- Invoke F-7a0a59ba417f with the object address and converted argument.

The dependency’s result, if any, does not determine this function’s result and is not used to stop dispatch.

Nested code 0x2502 does not trigger the call. Other nested codes also do not trigger it.

The source establishes a conversion to a character type, but not that type’s signedness or the complete calling convention. The argument must not be described as an unmodified 32-bit object field.

### 2. Fixed-result special case

After the preliminary stage, the function reads the event discriminator again. This is a fresh read, including when F-7a0a59ba417f was invoked.

If this discriminator is 0x16, the function reads the nested-record address and nested code again.

If this nested code is 0x7901:

1. Read object +0xB0.
2. Invoke F-da4129f79d61 with that field’s value.
3. Return exactly one.

No later handler is reached on normal return from that dependency. Its result does not replace the fixed result one.

### 3. Additional special-case handler

If the fixed-result branch was not taken, the function uses the discriminator value already obtained for that branch’s eligibility check. It does not reread the discriminator between these two special-case checks.

If that retained discriminator is 0x16, it reads the nested-record address and nested code again.

The additional handler is reached when the nested-code arithmetic identifies 0x7902:

1. Invoke F-776e6a3d3e9b with the original object address and event address.
2. If its result is nonzero, return that result unchanged.
3. If its result is zero, continue.

Under the represented 32-bit arithmetic, the observed subtraction followed by comparison with two selects nested code 0x7902. It is not a range test and does not identify every code greater than 0x7900.

### 4. Primary callback selection and invocation

If no preceding branch returned, the function reads the event discriminator again.

If it is 0x16, the function reads the nested-record address and nested code again. It selects the callback-table entry at +0x10C only when this newly observed nested code equals 0x2A.

In every other case, it selects the entry at +0x110.

After selecting the entry offset, the function reads the table address from object +0x00 and obtains the callable target at the selected offset. It then invokes that target with the original object address and event address.

If the primary callback returns nonzero, that exact integer is returned. The final conditional callback is not considered.

If the primary callback returns zero, processing continues.

Selection is therefore based on state observed at this stage, not necessarily on the event state present at function entry. Earlier dependencies may have changed the event or object state; their preservation behavior is unknown.

### 5. Final conditional callback

Following a zero result from the primary callback, the function reads the event discriminator again.

If it is not 0x0F, the function returns zero.

If it is 0x0F:

1. Read the 32-bit payload value at event +0x08.
2. Read the 32-bit object field at +0x50.
3. Compare the values for equality.

If they differ, return zero.

If they match, read the current table address from object +0x00, obtain its callable entry at +0xE0, and invoke that target with the original object address and event address.

A nonzero result from this final callback is returned unchanged. A zero result leads to the function returning zero.

The comparison does not dereference the event payload. At this stage, the payload is used as a 32-bit comparison value, unlike its use as a nested-record address for discriminator 0x16.

### Final callback eligibility

Given discriminator 0x0F:

- The primary callback at +0x110 runs first.
- A nonzero primary result ends dispatch, even when the payload matches object +0x50.
- Following a zero primary result, matching payload and object field values cause +0xE0 to be invoked.
- A mismatch causes zero to be returned without that final invocation.

### Mutation changes subsequent dispatch

Given an initial discriminator of 0x16 and nested code 0x2503, suppose F-7a0a59ba417f changes the event to discriminator 0x16 with nested code 0x7901.

The subsequent fresh reads observe that state, so F-da4129f79d61 is invoked and the function returns one. The preliminary code does not permanently determine the dispatch path.

Likewise, if a primary callback returns zero after changing the event to discriminator 0x0F and making its payload equal object +0x50, the final callback becomes eligible. That eligibility is not fixed at entry.
