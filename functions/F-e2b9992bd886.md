### Initial mutation boundary

The **terminal result** is the last combined dependency result before explicit stores. Other retained dependency-derived quantities supply:

- A **shifted base**, formed by a left shift of 25 bits.
- A **scaled-value base**, formed by multiplication by 0x02000000.
- An **early word**, formed by a left shift of eight bits.
- A **compact extraction**, formed by shifting a dependency result left eight bits, masking to 0x7FFF, and logically shifting right six.
- A **compact base**, twice the compact extraction.

[INFERENCE] Under truncating 32-bit shifts, the compact extraction ranges from 0 through 508 in multiples of four; the compact base ranges from 0 through 1016 in multiples of eight. These bounds establish no memory validity.

The opening publications write the retained shifted value as a word at terminal-high offset 0x14, write the terminal high portion’s low byte at shifted-base offset 9, publish the scaled-value base at offset 0x54 from 256 times the terminal low portion, and overwrite shifted-base offset 9 with the retained shifted value’s low byte.

The next access group clears the scaled-value base’s word at offset 0x14, reads its unsigned byte at offset 5, clears the compact base’s word at offset 0x14, publishes the loaded byte as a zero-extended word at scaled-value-base offset 0x34, and reloads scaled-value-base offset 0x14.

**Under ordinary byte-addressed memory semantics, successful accesses, and no external mutation, this reload yields zero.** The intervening compact-base store writes only zeros, so any overlap preserves zero bytes in the cleared word. The other intervening word store is at offset 0x34 of the same scaled-value base, disjoint from its word at offset 0x14. No dependency invocation intervenes.

Device-memory behavior or concurrent mutation could invalidate that ordinary-memory conclusion, but such behavior remains **documented_only**. The represented intervening stores do not themselves justify a nonzero reload.

The function clears compact-base offset 0x14 a second time, then performs two byte stores at compact-base offset 0x15 using the reloaded word’s low byte. Under the ordinary-memory conditions above, both byte stores publish zero.

### Fixed-location read at 0x05 and zero-derived uses

After those two compact-base byte publications, the function reads the fixed-location state associated with 0x05 and converts it to an unsigned 32-bit **fixed-state-derived base**.

This read precedes the byte publication at fixed address 0x01, which contains the compact base’s low byte. Address 0x01 does not supply the fixed-state-derived base.

Subsequent accesses include:

- A byte publication at fixed-state-derived-base offset 0x15 containing the compact extraction’s low byte.
- An early-word byte publication at scaled-value-base offset 0x11, followed later by an explicit zero byte at that same address.
- A word publication at offset 0x54 from the retained reload value.
- A word load at fixed-state-derived-base offset 0x54, retained as the **saved link**, followed by replacement of that word with the retained reload value.

Under the ordinary-memory zero conclusion, the reload-derived destination is fixed address 0x54, and that early word publication contains the early word. The later replacement at fixed-state-derived-base offset 0x54 contains zero.

Calculated writes intervene between the 0x05 read and the saved-link load. They may overlap the selected word, so the saved link reflects memory at the load’s position, not necessarily its contents when 0x05 was read. In particular, it must not be assumed independent of the earlier publication at 0x54.

The retained converted base and retained reload value are not refreshed when their originating memory changes.

## Acceptance examples

These examples are conditional static obligations, not executed tests.

### Initial reload with overlapping zero storage

Assume ordinary byte-addressed memory, successful accesses, and no external mutation. Let the scaled-value base be 0x10000000.

Its word at 0x10000014 is cleared. The byte loaded from 0x10000005 may be nonzero; for example, 0xA7 is subsequently published as word value 0x000000A7 at 0x10000034. That destination does not overlap 0x10000014.

Whether the intervening compact-base zero store is disjoint, partially overlapping, or fully overlapping, it cannot introduce a nonzero byte into the cleared word. The reload must yield zero. Both following compact-base offset-0x15 byte publications consequently contain zero.

A nonzero reload would require behavior outside these ordinary-memory assumptions, not merely aliasing by the represented stores.

### Zero-derived destination and replacement

Under the same assumptions, the retained reload value is zero. The early-word publication through that value’s offset 0x54 therefore targets fixed address 0x54.

The later fixed-state-derived offset-0x54 replacement publishes zero. The saved-link load occurs before that replacement and is not thereby required to return zero.

### Converted fixed-state base

If the 0x05 read converts to unsigned value 0x1000, subsequent selected accesses include byte address 0x1015 and word address 0x1054.

Acceptance requires the 0x05 read before the publication at 0x01. This establishes neither the original read width nor the saved link’s value.

### Ordered saved-link publications

For a saved link of 0x120 under compatible arithmetic, the later fixed word publication at 0x54 contains 0x240 and precedes the fixed byte publication at 0x15. Intervening calculated stores remain observable and may overlap fixed storage.

### Fresh 0x67 observations

If the retained 0xA9 word is 0x123456AB, its byte publication at 0x67 contains 0xAB.

If 0x67 still contains 0xAB when read for 0x21, that destination receives 0xAB. If intervening overlapping writes subsequently change 0x67 to 0x5C and then 0xE2 before the respective later reads, the two publication-base offset-9 stores receive 0x5C and 0xE2. Reusing 0xAB for all consumers does not satisfy this conditional behavior.

### Width and completion boundaries

Masking unsigned 0xFFFFFFFF to 24 bits and shifting left six yields 0x3FFFFFC0. Shifting the full word first is not equivalent.
