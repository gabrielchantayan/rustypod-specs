# F-7e1af31826c7

## Purpose

F-7e1af31826c7 looks up a record using state associated with a first object and lookup fields supplied by a second object. It returns a record pointer or null.

The visible lookup modes are:

- A zero 32-bit identifier delegates lookup to F-90be72a33f67.
- A nonzero identifier selects either linked traversal or indexed search, subject to two prerequisite dependency results.
- Indexed lookup may construct and prepare a cached collection. Certain initialization failures fall back to linked traversal; an indexed search miss does not.

The application-level meanings of the objects, records, identifiers, and surrounding protocol calls are unknown. A null return does not identify which rejection, failure, or absence condition occurred.

## Behavior

The first visible memory access reads the associated-state pointer from first-object offset `0xF9C`.

If it is zero, the function returns null without dependency calls or second-object reads.

Otherwise, that state address is retained and F-724e1e872fe7 is called with the second-object address. A zero result returns null without reading the identifier. A nonzero result permits the 32-bit identifier read at second-object offset `0xF0`.

The first object's state field is not refreshed after the dependency call. If that call changes the field, subsequent operations still use the captured state address.

### Delegated lookup for identifier zero

1. The captured state address.
2. Zero.
3. The second-object word at offset `0x110`.
4. The second-object word at offset `0x114`.

Its result is returned unchanged.

This branch does not visibly call F-cd52fcefba54, inspect the traversal-selection byte, or enter the indexed-path protocol.

### Nonzero-identifier gate

For a nonzero identifier, F-cd52fcefba54 is called without explicit arguments.

A zero result causes immediate null return. Otherwise, the function reads the state byte at offset `0x06`. Nonzero selects linked traversal; zero selects indexed lookup.

The captured identifier remains the lookup key. Later dependency effects on the second object's identifier do not refresh it.

### Linked traversal

Linked traversal starts by reading the head pointer at state offset `0x0C`.

For each nonnull record, its identifier at offset `0x0C` is compared with the captured key. Equality returns that record pointer. Inequality causes its next-record pointer at offset `0x00` to be read. Reaching null returns null.

The first matching record in link order is selected. No sorted-order requirement, cycle detection, or traversal limit is visible. A reachable cycle without a match can prevent termination.

When linked traversal is reached through indexed initialization fallback, its head read occurs after F-1333331b2da1 returns. No previously captured head is used.

### Indexed-path entry and cache initialization

The function reads and saves the 32-bit value at state offset `0x9D0`, then calls F-338d16f9ce72 with that value. Only afterward does it inspect the cached pointer at offset `0x9D4`.

A nonzero cache skips construction and preparation.

A zero cache causes F-f16e3e6dbf6b to be called with the captured state address. Its result is explicitly written to the cache field, even if null.

If the construction result is null, preparation is skipped. F-1333331b2da1 receives the saved protocol value, and linked traversal follows.

If construction returns nonnull, F-b4b5aa4c2f83 receives:

- The construction-result address plus four bytes, identifying the entry area.
- The first 32-bit word of that allocation.
- A value read from a static/global slot.

The static/global slot is read while forming the preparation call's arguments, after construction has returned and its result has been installed in the cache. It is not established to be an immutable value, a fixed address argument, or a constant. Earlier dependencies may change the slot before this read. Its declaration, precise type, contents, and semantic role are unavailable. The relative evaluation order of this slot read and the allocation-header read is not established.

The preparation return value does not control execution. After preparation, the cache field is read again:

- Nonzero permits indexed search.

Construction or preparation is not assumed to preserve other state. In particular, preparation may replace the cache pointer. The pointer subsequently loaded for search need not equal the construction result.

### Indexed search and access identity

Before searching, the function loads the collection pointer from the cache field. This loaded base is used throughout the search; the state cache field is not refreshed for each position.

The lower position starts at zero. The upper position is the signed interpretation of the collection count minus one.

While the signed difference between the bounds exceeds one, the function examines the midpoint formed by signed addition of the bounds followed by division by two.

The accesses at a midpoint are materially distinct:

- **Equality check:** the midpoint's record-pointer slot is loaded, then that record's identifier is read and compared with the key.
- **Equality hit:** the same indexed pointer slot is loaded again to obtain the selected return pointer. The pointer used for the equality check is not retained as the result.
- **Equality miss:** the same indexed pointer slot is loaded again, then the identifier reached through this second pointer is read for unsigned ordering. The pointer used for the equality check is not retained for this comparison.

Consequently, without pointer-slot stability, the ordering comparison may concern a different record from the equality comparison. On an equality hit, the selected pointer may likewise differ from the record whose identifier matched. The reloaded result pointer receives no identifier check.

After an equality miss, a key smaller than the identifier observed for ordering moves the upper bound to the midpoint. Otherwise, the lower bound moves to the midpoint. The midpoint itself remains a boundary.

Once the interval width is at most one, the function scans the remaining inclusive positions in ascending order. It first checks whether a position remains. For each position, it loads the record pointer, retains that pointer as the candidate, and compares its identifier with the key. Equality selects that retained pointer; otherwise scanning advances.

Unlike the midpoint-hit path, this final scan does not reload the pointer slot to select the matched result.

If no position remains, the selected result is null. Before returning any indexed result, including null, F-1333331b2da1 is called with the saved state word. The selected result is retained across that call and returned without subsequent validation.

An indexed miss never triggers linked fallback.

### Ordering, duplicates, and arithmetic

The interval reduction is consistent with an index sorted by ascending unsigned identifiers. No order validation is visible. An unsorted collection can cause an existing record to be missed.

For stable pointer slots and identifiers, a midpoint match returns immediately. Duplicate identifiers therefore have no general first-position guarantee. If selection occurs in the final scan, the lower remaining matching position wins.

For ordinary nonnegative counts with representable intermediate arithmetic:

- Zero entries produce no indexed pointer-slot access and return null after the balancing call.
- One entry examines position zero.
- Two entries examine positions zero and then one, stopping at a match.

The representation uses signed arithmetic for count-minus-one, bound subtraction, midpoint addition, and position changes. Correct behavior is not established where these operations overflow. Pointer-offset overflow, negative or malformed counts, and insufficient allocation extents are also outside the established well-formed-input behavior.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests.

1. **Missing state.** With a zero state pointer, expect null and no dependency call or second-object read.

2. **Eligibility rejection.** With nonzero state and a zero eligibility result, expect null without reading the identifier.

3. **Delegated lookup.** With successful eligibility and identifier zero, expect the four-argument F-90be72a33f67 call and its result returned unchanged. Expect no nonzero-identifier gate or indexed protocol.

4. **Gate rejection.** With a nonzero identifier and a zero F-cd52fcefba54 result, expect null without reading the selection byte.

5. **Linked duplicates.** With direct traversal selected and stable readable links containing multiple matches, expect the first matching record in link order.

6. **Construction returns null.** Expect null to be written to the cache, no preparation call, then F-1333331b2da1 followed by a fresh list-head read.

7. **Preparation argument changes before use.** If an earlier dependency changes the static/global slot and it remains stable through argument formation, expect preparation to receive that changed value—not a presumed original constant. Construction's cache write precedes the slot read.

8. **Preparation replaces or clears the cache.** A valid replacement collection is used by the subsequent search. A cleared cache instead causes the balancing call and linked fallback.

9. **Midpoint equality hit with a changed slot.** If the equality-check load reaches a matching record but the subsequent result-selection load returns a different pointer, expect that second pointer to be selected without an identifier check. Any lifetime effects of the balancing call remain separate unknowns.

10. **Midpoint equality miss with a changed slot.** If the equality-check load reaches one nonmatching record and the ordering load reaches another, expect bound selection to use the latter record's identifier, provided all accesses remain valid.

11. **Final-scan match.** For a match reached in the final scan, expect selection of the pointer loaded for that comparison, rather than an additional slot reload.

12. **Indexed miss despite list match.** With a valid stable index lacking the key, expect null after the balancing call even if the linked sequence contains a match.

13. **Unsigned boundary and empty index.** A stable sorted index containing `1` and `0x80000000` treats the latter as the larger identifier. A valid zero-count index performs no indexed record-pointer reads and returns null after balancing.
