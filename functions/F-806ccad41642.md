# F-806ccad41642

## Purpose

F-806ccad41642 dispatches a 32-bit event selector against shared state. Recognized selectors are 4, 8, 32, and 64. Their visible effects include storing a selection, obtaining a resource-like value, delivering a temporary notification record, incrementing a byte counter, invoking a common action, and assigning a byte flag.

This contract establishes caller-side control flow, memory-access widths and ordering, dependency arguments, and result construction. “Resource,” “notification,” and “common action” describe inferred roles; their application meanings are not established.

The matching selector-8 path has a significant output dependency: the notification recipient receives writable access to a temporary record, and the caller subsequently reads that record’s first word to construct its return value. The prepared value of that word is not a guaranteed returned value.

## Behavior

### Entry and unrecognized selectors

At entry, the function retains the shared-state base, initializes the lower result word to zero, and initializes the three-word temporary record from the inputs.

A selector other than 4, 8, 32, or 64 causes no visible dependency call or persistent state write. Normal completion returns the original selector as the upper half and zero as the lower half.

The entry-time read of the shared-state reference still occurs. No state-field dereference is visible on an unrecognized-selector path.

### Selector 4: selection and resource setup

The caller performs these effects in order:

1. Writes the event value to offset 4 through the shared-state reference used at that access.
2. Compares the event value, interpreted as signed 32-bit, with 2.
3. If it exceeds 2, calls F-a817d8d58c10.
4. Otherwise, calls the unmapped provider dependency.
5. Adds four to the provider’s result in the supplied 32-bit intermediate representation.
6. Reads the selected value from offset 4 of the retained entry-time base.
7. Calls F-b37968c9f644 with the adjusted provider result and that selected value.
8. Stores F-b37968c9f644’s 32-bit result at offset 8 of the retained base.
9. If that result is zero, calls F-a817d8d58c10.
10. Otherwise, clears the 32-bit field at offset 16 of the retained base, then writes 1 to its flag byte at offset 0.

Successful normal completion returns upper half 4 and lower half zero.

The selection write precedes rejection. Rejected inputs therefore leave that explicit write in place before the nonreturning call; there is no caller-side rollback.

The signed check accepts more than 0, 1, and 2. Bit patterns `0x80000000` through `0xFFFFFFFF` represent negative signed values and do not satisfy “greater than 2.” Values 3 through `0x7FFFFFFF` do satisfy it.

The selected value passed to F-b37968c9f644 is read after the provider call, from the retained state block. It must not be replaced by the original event value: the provider may have modified that block.

The resource result is stored before its zero check. If it is zero, neither the subsequent clearing of offset 16 nor the assignment of flag 1 occurs in the visible caller.

### Selector 8: conditional notification and record-derived return

The event value is checked as unsigned 32-bit:

- Values greater than 2 reach F-a817d8d58c10.
- Values 0, 1, and 2 continue.

For an accepted value, the caller reads offset 4 through the current shared-state reference and compares it with the event value.

On a mismatch, there is no visible dependency call or persistent state write. The returned halves are 8 and zero.

On a match, the caller:

1. Calls F-c53d8fb06b23 with the original context.
2. Replaces the low byte of the temporary record’s first word with 2.
3. Writes zero to each of the record’s second and third 32-bit words.
4. Calls F-c6c589453fa8 with arguments 10, 0, the record’s address, and a byte length of 12.
5. Reads the record’s first 32-bit word after the call and uses it as the upper result half. The lower half remains zero.

The first word initially contains selector 8, whose other three bytes are zero. The byte replacement therefore prepares the complete first word as 2. Immediately before delivery, the three word values are 2, 0, and 0.

That prepared state does not establish the returned upper half. F-c6c589453fa8 receives access to the record, and its mutation behavior is unknown. Its direct return value is ignored, but changes it makes to the first record word are reflected in the caller’s normal return.

The original event value and auxiliary value are not delivered as the second and third record words; both are explicitly overwritten with zero.

### Selector 32: key precedence and counter gating

The event value is first compared with the 32-bit primary key at offset 44 through the shared-state reference.

If the primary key does not match:

- The secondary key at offset 48 is read through the shared-state reference.
- A secondary-key match causes F-27382f30f1a2 to be called with the original context and 1.
- Either way, the returned halves are 32 and zero.

If the primary key matches, the secondary key is not examined. Primary-key processing therefore takes precedence when both keys equal the event value.

On a primary-key match, the caller reads the counter byte at offset 1 through the shared-state reference, increments its value, and writes the truncated byte back through that reference. The stored increment is modulo 256.

The decision uses that byte-width increment:

- If it is greater than 3, the caller writes zero to offset 1 of the retained entry-time base and returns with lower half zero.
- If it is 0, 1, 2, or 3, the caller invokes F-60063d22d02e with the original context and uses its 32-bit result as the lower half.

The upper half remains 32.

An initial counter of 3 is written as 4 and then reset to zero, without invoking the common action. An initial counter of 255 is written as zero and does invoke the common action.

The increment store uses the shared-state reference, while the reset uses the retained base. No synchronization guarantee makes those two reference forms interchangeable.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Successful setup:** For selector 4 and event value 2, if the provider and setup dependency return normally and F-b37968c9f644 returns nonzero, that result is stored at retained-state offset 8. Offset 16 is then cleared and the flag set to 1. Returned halves: 4 and zero.

3. **Signedness distinction:** Selector 4 with event value `0xFFFFFFFF` passes its signed range check. Selector 8 with the same value reaches F-a817d8d58c10 through its unsigned check.

6. **Selection mismatch:** For selector 8 and accepted event value 1, if the selected field is 2, neither notification-path dependency is called. Returned halves: 8 and zero.

8. **Counter wraparound:** With a primary-key match and initial counter 255, the increment store writes zero and F-60063d22d02e is called. Its result supplies the lower half.

12. **Common-action result:** For selector 64, nonzero resource, nonzero predicate result, event value 4, and F-60063d22d02e result `0x12345678`, returned halves are 64 and `0x12345678`.
