# F-389be44b388f

## Purpose

F-389be44b388f conditionally issues a notification in response to a discriminator contained in an input record. It always returns the 32-bit value `1` when execution reaches its normal return.

The notification has two arguments: a value captured from global storage at entry and a 32-bit decision value. The decision is determined as follows:

- Discriminator `0x00010002` causes a notification with decision `1`, without consulting the record’s payload or flags.
- Discriminators `0x00010001`, `0x00010003`, and `0x00010006` enter a shared decision path.
- On that shared path, a clear flag bit `0x00000008` produces decision `1`.
- A set flag bit `0x00000008` requires an object lookup and a status query. Status exactly `3` produces decision `1`; every other status produces decision `0`.
- Other discriminators return `1` without issuing the notification.

These are established control-flow properties. Interpreting the record as an event, the decision as permission or enablement, or the notification as a particular subsystem operation would be inferred intent, not established behavior.

### Output

That return value does **not** distinguish:

- A discriminator that caused no notification.
- A notification carrying decision `1`.
- A notification carrying decision `0`.

The function exposes its distinction primarily through dependency calls rather than through its return value.

### Preconditions for normal completion

The record must support the reads selected by its discriminator:

- Every path requires a readable 32-bit discriminator at offset `+8`.
- The three shared-path discriminators additionally require a readable 32-bit payload at offset `+12` and flags at offset `+16`.
- Discriminator `0x00010002` and unrecognized discriminators do not require payload or flag reads in the supplied body.

A flag-set shared path additionally requires usable results and dispatch structures from its dependencies, as described below. There is no explicit input-pointer validation, alignment check, bounds check, or recovery for invalid memory.

No ownership transfer or caller-side release obligation can be derived from this body alone.

## Behavior

### 1. Entry snapshot and discriminator read

Before reading the record’s discriminator, the function reads one 32-bit value from global storage. This captured value becomes the first notification argument if a notification is reached.

The global read occurs even when the discriminator is later ignored and no notification occurs.

The function next reads the discriminator at record offset `+8`.

This ordering matters if the record aliases global storage or if external mechanisms make individual reads observable. The body supplies no synchronization or atomicity guarantee.

### 2. Immediate-notification discriminator

For discriminator `0x00010002`, the function selects decision `1` and proceeds directly to notification.

On this path:

- The payload at offset `+12` is not read.
- The flags at offset `+16` are not read.
- F-120cb3bb1627 is not called.
- Neither indirect dispatch operation is performed.
- F-a817d8d58c10 is not called.

After a normally returning notification, the function returns `1`.

### 3. Shared-path discriminator selection

Discriminators `0x00010001` and `0x00010003` enter the shared path directly.

The remaining discriminator selection uses a 32-bit integer subtraction by `0x00010000` and comparison of the result with `6`. The plainly established additional accepted value is therefore `0x00010006`.

An ordinary nonmatching discriminator returns `1` immediately, after the entry global read and discriminator read. It performs no notification and no lookup.

For extreme discriminator values where the displayed signed subtraction would overflow, the supplied representation does not independently establish the intended arithmetic semantics. This is a documented limitation rather than a reason to assume additional accepted values.

### 4. Shared-path field reads and default decision

For each of the three shared-path discriminators, the function:

1. Reads the 32-bit payload at offset `+12`.
2. Establishes decision `1`.
3. Reads the 32-bit flags at offset `+16`.
4. Tests only bit `0x00000008`.

The payload read precedes the flag read. In particular, the payload is read even when the tested flag is clear and no lookup will use that payload.

If the tested flag is clear, the function proceeds to notification with decision `1`. The other 31 flag bits do not affect this branch.

### 5. Flag-set lookup and status evaluation

If bit `0x00000008` is set, the function changes the decision to `0` and performs the following dependency sequence:

1. Calls F-120cb3bb1627 with no explicit arguments.
2. Uses the returned value as an object address and reads its dispatch-table pointer from object offset `0`.
3. Obtains an indirect callable from byte offset `0x24` in that table.
4. Calls that operation with two explicit arguments: the returned object address and the previously captured payload.
5. Treats the operation’s result as a second object address.
6. Checks whether that second address is zero.
7. For a nonzero result, reads the second object’s dispatch-table pointer at offset `0` and invokes the callable at table byte offset `8`.
8. Compares that operation’s 32-bit result with `3`.

The status invocation shows no explicit arguments in the supplied call expression. A receiver argument or other ABI-specific input must not be invented from an assumed object model.

If the status equals `3`, the decision becomes `1`. Otherwise the decision remains `0`. There is no further status classification, range validation, or retry.

The first object returned by F-120cb3bb1627 is not checked for zero before dereference. A nonzero first object is also insufficient by itself: its dispatch pointer and the selected callable must be usable.

### 6. Null lookup result

If the first indirect operation returns zero, the function calls F-a817d8d58c10 with no explicit arguments.

The supplied representation annotates this call as non-returning. That annotation is not proof of the dependency’s implementation. The important local property is that there is no recovery branch, alternate decision, or explicit return following a returning invocation of that dependency. If it did return, the displayed continuation would attempt dispatch through the zero result.

Accordingly:

- A non-returning failure handler is consistent with the displayed intended failure path.
- The body does not establish whether that handler terminates execution, raises an exception, transfers control elsewhere, or uses another mechanism.
- Successful notification after a null lookup is not supported as normal behavior.

### 7. Notification and normal return

Every notification receives:

1. The global value captured before the discriminator read.
2. The selected 32-bit decision, either `0` or `1`.

The function does not reread that global value before notification. Changes made to the original global storage by intervening dependencies do not replace the captured argument.

The notification’s return value, if any, is ignored. If the notification returns normally, F-389be44b388f returns `1`.

## Side effects

The body contains no explicit stores to the record, global storage, or returned objects. It performs no explicit allocation, release, or reference-count adjustment.

Its directly established observable effects are:

- One entry-time global read.
- Selected record-field reads.
- Conditional object and dispatch-table reads.
- Conditional calls to dependencies.
- A normal return of `1`.

This is not a purity guarantee. Any dependency may mutate memory or globals, allocate or release resources, retain arguments, fail, or transfer control. The supplied body does not establish those contracts.

For a flag-set shared path with a nonzero lookup result, the local order is:

1. Capture global value.
2. Read discriminator.
3. Read payload.
4. Read flags.
5. Call F-120cb3bb1627.
6. Read the first object’s dispatch pointer and selected callable.
7. Invoke the lookup operation.
8. Read the second object’s dispatch pointer and selected callable.
9. Invoke the status operation.
10. Invoke the notification.
11. Return `1`, if all preceding calls return normally.

Dependencies may add effects between these steps. No assumption that they preserve globals or leave previously accessed objects unchanged is justified.
