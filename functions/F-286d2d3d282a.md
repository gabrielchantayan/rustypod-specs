## Behavior

The function first reads the signed 32-bit increment at offset `0x220` and caches it.

It then calls F-d7be9cfb4000 exactly once, supplying:

2. The integer value **1000**.

After the dependency returns, the function reads the unsigned comparison value at offset `0x228`. That value becomes the initial **candidate**.

This ordering is significant:

- A dependency change to the comparison field can affect the current invocation because the comparison read follows the call.
- A dependency change to the increment field does not replace the cached increment used for the call or subsequent accumulation.
- Accumulator and tracked-value reads, when required, also occur after the dependency returns.

The function does not establish that the dependency preserves the object or any global state.

### Ordered path selection

All comparisons in this selection process are unsigned.

**1. Measurement below 31**

The candidate becomes **33**, and the function takes the reset path.

The comparison field has already been read, even though its value does not affect this branch.

**2. Measurement equal to 31 or 32**

The function takes the accumulation path. The candidate initially remains the comparison value.

These two measurement values reach accumulation before any comparison-minus-two test.

**3. Measurement at least 33 and below comparison minus 2**

The subtraction uses unsigned 32-bit arithmetic. Consequently:

- Comparison **0** produces threshold **4,294,967,294**.
- Comparison **1** produces threshold **4,294,967,295**.

If the measurement is below that threshold, the candidate becomes:

\[
\left((\text{comparison}+\text{measurement}+1)\bmod 2^{32}\right)
\mathbin{\text{shift-right}}1.
\]

The right shift is unsigned. This produces the floor of half the **wrapped sum**, not necessarily the rounded average of the two unbounded mathematical values.

The function then takes the reset path.

**4. Remaining measurements**

If either of the following holds, the function takes the accumulation path:

- The measurement is below the comparison value.
- The measurement is below **102**.

Otherwise, it takes the reset path without changing the candidate from the comparison value.

These decisions are ordered. For example, a measurement below 102 can still take the earlier averaging-and-reset branch if it is at least 33 and below comparison minus 2.

### Accumulation path

The function reads the accumulator at offset `0x21c` as a signed 32-bit integer and adds the cached signed increment.

If the mathematical sum lies within **−2,147,483,648 through 2,147,483,647**, the resulting value is established. It is converted to unsigned 32-bit form and written to the accumulator field.

The addition itself has two signed operands. Behavior when their mathematical sum exceeds the signed 32-bit range is **documented_only**. Assignment to an unsigned destination does not, by itself, establish wrapping behavior for that preceding signed addition.

After writing the accumulator, the function reads the unsigned tracked value at offset `0x224`. It compares that value with:

\[
(\text{measurement}+2)\bmod 2^{32}.
\]

- If the tracked value is less than or equal to this computed value, the computed value is written to the tracked-value field.
- If the tracked value is greater, this update performs no write.
- Equality causes a write even though the stored numerical value does not change.

The updated unsigned accumulator then determines the next action:

- **Below 250,000:** retain the current candidate and proceed directly to final normalization. Neither field is cleared. The tracked-value field remains untouched if its conditional update was not taken.
- **At least 250,000:** reread the tracked-value field, replace the candidate with that read value, and take the reset path.

The threshold follows from the two represented unsigned tests. Accumulator values below **249,856** continue without reset. Values from **249,856 through 249,999** also continue because their difference from 249,856 is below **144**. The first threshold-reaching value is therefore **250,000**.

A negative but representable signed sum is not rejected. Conversion gives a large unsigned accumulator value, so it reaches the reset threshold.

### Reset path

The function performs these direct writes in order:

1. Write a 32-bit zero to the accumulator at offset `0x21c`.
2. Write a 32-bit zero to the tracked value at offset `0x224`.

On an accumulation path that reaches the threshold, these writes occur after the accumulator update, the tracked-value comparison and any resulting update, and the tracked-value reread used to select the candidate.

Thus, final zero values do not erase the fact that intermediate reads and writes occur in the represented sequence.

Reset paths selected without accumulation do not directly read the accumulator or tracked value before clearing them.

### Final normalization

The candidate is checked through unsigned subtraction from **33**:

- Candidates **33 through 102**, inclusive, are returned unchanged.
- Every other candidate is replaced with **33**.

Values below 33 fail because the subtraction wraps to a large unsigned value. Values above 102 also fail. In particular, **103 becomes 33**, not 102.

Normalization does not store the result into the object. The comparison field is not directly updated.
