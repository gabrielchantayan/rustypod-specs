# F-f38d4334b42b

## Purpose

F-f38d4334b42b combines two behaviors selected by its second argument:

- With a zero selector, it either preserves a supplied 64-bit value or subtracts the unsigned seventh argument and a further eight from that value.
- With a nonzero selector, it either preserves that supplied value or returns a 64-bit comparison result of zero or four.

The first byte at the supplied address determines which behavior applies within the selected mode. In the nonzero-selector mode, two global values participate in selecting the comparison target.

These are established structural behaviors. The application-level meanings of the byte, selector, global values, and eight-unit adjustment are unknown. No interpretation as a string parser, allocator, validator, or particular object operation is established.

## Interface

The function accepts seven arguments and returns a 64-bit unsigned result.

| Argument | Contract |
|---|---|
| First | Address from which one character-sized byte is read unconditionally. Only that first byte is used. |
| Second | 32-bit integer selector. Zero selects arithmetic mode; every nonzero value selects comparison mode. |
| Third | 32-bit integer compared with a selected global value on applicable comparison-mode paths. |
| Fourth | 32-bit argument with no established use in the supplied body. |
| Fifth | Unsigned 32-bit low word of the supplied 64-bit value. |
| Sixth | 32-bit high word of the supplied 64-bit value. Its declared signedness does not change the bit pattern placed in the returned high word. |
| Seventh | Unsigned 32-bit amount subtracted in one arithmetic-mode case. |

For this contract:

- **B** is the first byte read from the first argument.
- **L** is the unsigned value of the fifth argument.
- **H** is the 32-bit bit pattern of the sixth argument, interpreted unsigned when composing a result.
- **T** is the unsigned value of the seventh argument.
- **V** is the supplied 64-bit value, equal to H × 2³² + L.
- **Global A** and **Global B** identify the two distinct global values referenced by the body. These labels do not imply application-level meanings.

The first argument must support a readable byte access when the function is entered. There is no null check, length argument, or path that avoids this initial read. The byte need not be followed by a terminator or any additional readable data.

Global A must be readable on every nonzero-selector path. Global B must additionally be readable when the selector is nonzero and B is not zero. Each global is used as a 32-bit integer comparison value.

No alignment requirement beyond that necessary for the actual byte access is established for the first argument. The source does not establish a concrete calling convention, machine-register assignment, or external binary layout for the arguments.

## Behavior

### Entry and byte classification

The function first reads B from the address supplied as its first argument.

The distinctions relevant to subsequent behavior are:

- B equals zero.
- B equals one.
- B is any other byte value.

Whether the source language treats plain character values as signed or unsigned does not change these classifications. Every byte other than zero or one belongs to the third class.

Only one byte read through the first argument is established. The function does not scan subsequent bytes or determine a string length.

### Zero-selector arithmetic mode

When the second argument is zero, neither Global A nor Global B is read.

If B is nonzero, the return value is V without adjustment. This applies equally to B equal to one and to every other nonzero byte.

If B is zero, the return value is:

**(V − T − 8) modulo 2⁶⁴**

T is treated as an unsigned 32-bit quantity extended to the width of the calculation. The total subtraction is not defined by first computing T + 8 in 32 bits. In particular, T near its maximum can produce a total decrement exceeding 2³².

The established word-level arithmetic is:

- First form D = (L − T) modulo 2³².
- The returned low word is (D − 8) modulo 2³².
- The returned high word is H minus one if L < T, minus another one if D < 8, with the final high word interpreted modulo 2³².

The two borrow conditions are independent. Both can apply during one invocation. Thus the high word may decrease by two even though the seventh argument itself is only 32 bits wide.

The original expression represents the second borrow through a decrement followed by a conditional increment when D > 7. The formulation above describes the resulting arithmetic without depending on that expression’s shape.

The third and fourth arguments do not affect the result in this mode.

### Nonzero-selector comparison mode

Every nonzero value of the second argument selects the same mode. Its sign and magnitude do not otherwise affect behavior.

After the initial byte read, the function reads Global A.

If B is zero:

- Global A is the selected comparison value.
- Global B is not read.
- The function returns four if the third argument equals the value read from Global A.
- Otherwise, it returns zero.

If B is nonzero, the function next reads Global B. This read occurs before the decision to return V for an unsupported byte value.

If B is one:

- The value read from Global B is the selected comparison value.
- The function returns four if the third argument equals that value.
- Otherwise, it returns zero.
- The earlier read of Global A still occurs, even though its value is not used in the final comparison.

If B is neither zero nor one:

- Both global reads have occurred, in the order Global A then Global B.
- The function returns V.
- No comparison with the third argument determines that result.

Comparison results are full 64-bit values of zero or four. Their high 32 bits are zero; they are not composed with H.

The seventh argument has no effect in this mode. The fourth argument remains unused.

### Result classification

The complete result selection is:

| Second argument | B | Result |
|---|---|---|
| Zero | Zero | (V − T − 8) modulo 2⁶⁴ |
| Zero | Any nonzero byte | V |
| Nonzero | Zero | Four if the third argument equals Global A’s read value; otherwise zero |
| Nonzero | One | Four if the third argument equals Global B’s read value; otherwise zero |
| Nonzero | Any other byte | V |

A returned zero is therefore not an independently identifiable error indicator. It can result from an unequal comparison, an unchanged input value of zero, or arithmetic wrapping to zero. Likewise, four can arise either from equality or from another path whose numeric result happens to be four.

## Side effects

### Read ordering

The source-level access order is:

1. Read the byte through the first argument.
2. If the selector is zero, perform no global reads.
3. Otherwise, read Global A.
4. If B is nonzero, read Global B.

This ordering matters particularly for nonzero-selector calls with B outside zero and one: returning V does not bypass either global read.

These are accesses established by the supplied body. They do not, by themselves, establish hardware access ordering, atomicity, volatile semantics, or synchronization guarantees.

### Writes and ownership

No explicit memory writes occur in the supplied body. In particular, the function does not write through the first argument or update either global.

No allocation, release, ownership transfer, or retention of the supplied address is shown. The function does not return an address derived from that argument.

No calls to other functions are present. Consequently, there are no unknown callee side effects to account for within this body. This does not establish that the globals are immutable or that the surrounding execution environment cannot change them.

### Errors and invalid inputs

There is no explicit error-reporting path and no explicit validation of the first argument or global storage.

An unreadable first argument can prevent completion on every branch because the byte read is unconditional. An unreadable global can prevent completion on a branch requiring that access, including a branch that would otherwise return V unchanged.

The exact manifestation of an invalid access—such as a process fault or platform-specific exception—is outside the established contract. No recovery behavior is shown.

## Acceptance examples

These examples are conditional consequences of the supplied static evidence, not observed runtime results. Hexadecimal results are written as full 64-bit values.

### Preserved value in arithmetic mode

Given:

- Second argument is zero.
- B is one.
- H is 0x12345678.
- L is 0x9ABCDEF0.

The result is **0x123456789ABCDEF0**, regardless of T or the third argument. Neither global is read.

The same result applies for any other nonzero B.

### Arithmetic without a borrow

Given:

- Second argument is zero.
- B is zero.
- H is two.
- L is 100.
- T is 20.

The result is **0x0000000200000048**: the low word becomes 72, with no change to the high word.

### Borrow caused by the final eight

Given:

- Second argument is zero.
- B is zero.
- H is two.
- L is ten.
- T is five.

The intermediate low-word difference is five. Subtracting eight borrows from the high word, producing **0x00000001FFFFFFFD**.

### Borrow caused by subtracting T

Given:

- Second argument is zero.
- B is zero.
- H is two.
- L is three.
- T is five.

Subtracting T first borrows once. The subsequent eight-unit subtraction needs no additional borrow. The result is **0x00000001FFFFFFF6**.

### Two borrows and a decrement exceeding one word

Given:

- Second argument is zero.
- B is zero.
- H is five.
- L is zero.
- T is 0xFFFFFFFF.

The intermediate low-word difference is one, so both borrow conditions apply. The result is **0x00000003FFFFFFF9**.

An implementation that truncates T + 8 to 32 bits before subtracting would not satisfy this example.

### Full-width underflow

Given zero selector, zero B, H = 0, L = 0, and T = 0, the result is **0xFFFFFFFFFFFFFFF8**. Arithmetic wraps rather than reporting underflow.

### Selection of Global A

Given a nonzero selector and B equal to zero, if the third argument equals the value read from Global A, the result is **0x0000000000000004**. If it differs, the result is zero. Global B is not read.

### Selection of Global B

Given a nonzero selector and B equal to one, Global A is read first and Global B second. Equality with Global B’s read value produces four; inequality produces zero. Global A’s value does not determine the result.

### Unsupported byte in comparison mode

Given a nonzero selector, B equal to two, and V equal to **0xABCDEF0123456789**, the result is **0xABCDEF0123456789**. Both globals are read first, regardless of their values or the third argument.
