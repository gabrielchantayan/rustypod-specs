## Behavior

### Evidence boundary and operation ordering

The representation contains no explicit conditional branch or loop in the function body. Its repeated call patterns are a fixed sequence, not evidence of a runtime iteration count controlled by the input.

Dependency behavior can nevertheless prevent progress, alter memory, or change external state. Thus, “later” below always means “if control reaches that operation.”

Four direct byte writes divide the sequence into four phases. Each write occurs before the associated phase’s first dependency invocation. Dependency calls between writes can observe or modify memory, including the same locations.

For precise reference, this document assigns opaque, local dependency IDs **F-D001** through **F-D220** in invocation order. These are occurrence identifiers, not externally supplied identities, and do not assert that every occurrence denotes a distinct function.

### First phase: input-derived write and initial forwarding

Before any dependency invocation, the function writes one byte to the address obtained by doubling the input value. The written byte is the low eight bits of the ambient word.

F-D001 then receives two equal arguments, both equal to the original input value. Its target is the entry-state-derived target described under Interface.

The remainder of the phase contains:

- Three calls with no explicit arguments, followed by a call whose four-byte result is retained.
- One call receiving that retained result unchanged.
- Nine ordered result-scaling groups.
- A final group that produces the value used by the second direct byte write and its following call.

A **result-scaling group** has the following behavioral boundary: three dependencies run with no explicit arguments; a fourth dependency, also with no explicit arguments, supplies an apparent 32-bit integer result; a fifth dependency receives that result shifted left by two bit positions. The result used by the fifth call is specifically the fourth call’s result, not an earlier result or a cached common value.

The nine groups are successive and independently obtain their results. No equality between their results is established.

After those groups, three further no-explicit-argument calls precede a fourth such call whose result becomes the **first boundary value**. The next phase’s byte write occurs before the consumer of this boundary value.

### Second phase: ambient-word-derived write

The second direct write has:

- Destination: the first boundary value shifted left by three bit positions and interpreted as an address.
- Width: one byte.
- Value: the low eight bits remaining after the unsigned ambient word is shifted right by 22 positions.

Consequently, the selected source bits are positions 22 through 29 of the ambient word, with bit zero being the least significant bit. Bits 30 and 31 do not contribute to this byte.

The dependency immediately following this write receives two arguments derived from the same first boundary value:

1. The value multiplied by four.
2. The value shifted left by ten bit positions.

The multiplication is visibly represented as multiplication, whereas the repeated scaling groups use a left shift. They agree for suitable nonnegative values without overflow; the evidence does not justify treating them as universally interchangeable arithmetic operations.

The remainder of the phase contains eight calls with no explicit arguments, followed by a result-producing call and a consumer receiving that result shifted left by two positions. Eight ordinary result-scaling groups follow. Thus, this phase has nine left-by-two consumers in total, but its first such consumer has a longer preceding call sequence than the ordinary groups.

Finally, three no-explicit-argument calls precede a fourth that produces the **second boundary value**.

### Third phase: first zero write

The third direct write stores a zero byte at the address obtained by shifting the second boundary value left by three positions.

The immediately following dependency receives two equal arguments. Both are the second boundary value shifted left by 14 positions.

Three no-explicit-argument calls then precede a call whose four-byte result is passed unchanged to one consumer. This is a separate result from the second boundary value.

Nine ordinary result-scaling groups follow.

Three further no-explicit-argument calls precede a fourth that produces the **third boundary value**.

### Fourth phase: second zero write and endpoint

The fourth direct write stores a zero byte at the address obtained by shifting the third boundary value left by three positions.

The immediately following dependency receives two equal arguments, each equal to the third boundary value shifted left by 14 positions.

Three no-explicit-argument calls then precede a call whose four-byte result is retained. The next dependency receives that same result twice, unchanged.

Nine ordinary result-scaling groups follow. Four final dependency calls have no explicit arguments and no visibly consumed results.

The representation then reaches the invalid-instruction termination marker. It does not show successful completion, a status code, or recovery.

### Initial write precedes the first dependency

No assumption about F-D001 preserving that byte is implied.

### Ordinary result scaling

If a later group also returns 7, that does not authorize merging the calls or reusing an earlier result.

- The second direct write stores `0xFF` at address 24.

The byte does not incorporate the ambient word’s top two bits.

The same relationship applies independently to the third boundary value, the fourth store, and F-D166.
