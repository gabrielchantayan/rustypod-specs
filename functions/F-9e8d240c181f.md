## Behavior

### Selection and read order

The default cell is read before the selector-dependent alternative is chosen.

For a zero selector:

- The value read from the default cell is the selected value.
- The alternative cell is not read by the visible function body.

For a nonzero selector:

- The default cell is still read.
- The alternative cell is then read.
- The value obtained from the alternative cell replaces the default-cell value for the subsequent dependency call.

This distinction matters when reads can fail, are externally observable, or occur against concurrently changing storage. The visible behavior is not merely “read whichever cell is selected”: the default-cell read occurs on both paths.

The supplied representation establishes this access sequence at the source-facing level. It does not independently establish volatile semantics, synchronization, memory barriers, or the exact machine-level transactions used to implement those reads.

### Dependency invocation

After selection, F-438680ffebfe is invoked once with two arguments, in this order:

1. The original 32-bit payload.
2. The selected 32-bit stored value.

Both arguments are passed as values. The visible body does not pass the address of either global cell, nor does it directly dereference the payload.

The selected value is obtained before the call. The visible body performs no later global read to refresh that argument. If F-438680ffebfe changes either cell during execution, that mutation does not retroactively change the argument already supplied to that invocation.

No meaning can be assigned to either argument solely from its position. In particular, value passing does not establish whether an argument is an integer, an encoded reference, or an address that the dependency may interpret.

### Return behavior

After F-438680ffebfe returns normally, this function returns the original payload. It does not substitute the dependency’s return value or the selected stored value.

There is no visible conditional branch based on the dependency’s outcome, no retry, and no explicit failure translation. The function does not inspect any dependency-produced status in the supplied body.
