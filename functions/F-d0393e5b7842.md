# F-d0393e5b7842

## Purpose

F-d0393e5b7842 conditionally transfers two consecutive 32-bit words from a source region to a destination region.

A null destination disables the transfer entirely, including source reads. With a non-null destination, the function reads the second source word first, then reads and writes the first word, and finally writes the previously obtained second word.

The operation preserves the words’ bit patterns; it does not interpret them as signed integers, floating-point values, addresses, or ownership-bearing handles. The first argument does not affect the shown behavior.

This contract describes established static behavior. No runtime tests have been performed.

## Interface

The function accepts three arguments, in this order:

| Position | Role | Width or layout | Meaning |
|---|---|---|---|
| First | Unused value | 32 bits | Accepted but not read or otherwise used by the shown body. |
| Second | Destination address | Pointer width unspecified | Either null, which suppresses all work, or the address of two consecutive writable 32-bit words. |
| Third | Source address | Pointer width unspecified | When the destination is non-null, the address of two consecutive readable 32-bit words. |

There is no return value and no returned success or failure indicator.

For each non-null memory region, the first word occupies offsets 0 through 3 bytes and the second occupies offsets 4 through 7 bytes. The supported element width is 32 bits, or four bytes; the complete transferred region is eight bytes. Pointer width is not established by the word width.

The two words are independent, uninterpreted values. In particular, the contract does not establish that they form a numeric 64-bit quantity or assign significance to either word.

### Preconditions

If the destination is null, no source-memory validity requirement follows from this body: it does not dereference the source.

If the destination is non-null, defined ordinary-memory operation requires:

- Both source words to be readable.
- Both destination words to be writable.

## Behavior

### Null destination

The function checks the destination before accessing either memory region.

When the destination is null:

- Neither source word is read.
- No destination word is written.
- The first argument remains behaviorally irrelevant.
- The function returns without a result.

Consequently, a null source does not itself cause a dereference in this branch. This is a statement about the function body, not about evaluation of arguments by its caller.

### Non-null destination

For a non-null destination, the memory effects have this semantic order:

1. The second source word, at byte offset 4, is read and retained.
2. The first source word, at byte offset 0, is read.
3. That first-word value is written to destination offset 0.
4. The retained second-word value is written to destination offset 4.

The second destination write uses the value obtained before the first destination write. It does not reread the second source word.

For stable, valid ordinary memory, the destination therefore receives the source’s two original word values. Any bits already present in the destination are replaced; there is no merging, masking, conversion, comparison, or arithmetic on those values.

The first argument does not select a branch, influence an address, change the transferred values, or supply an error result.

### Overlapping regions

The shown body contains no overlap check and does not require disjoint source and destination regions.

Both source-word values are obtained before either destination write. Thus, for valid ordinary memory, an overlapping first destination write cannot change the value subsequently used for the second destination word.

Important cases include:

- **Identical addresses:** The function reads both source words and writes the same values back to the same locations. The final contents are unchanged, but the reads and writes still occur.
- **Destination one word after source:** The original first source word replaces the original second source word, and the original second source word is written into the following word.
- **Destination one word before source:** The original first source word is written into the preceding word, and the original second source word replaces the original first source word.

These are conclusions about the explicit word accesses on valid memory. They do not establish support for arbitrary unaligned addresses, special memory mappings, or every possible language-level aliasing arrangement.

### Invalid memory and interrupted execution

There is no explicit error-handling path.

A non-null destination combined with a null or otherwise unreadable source does not produce a defined error return. Likewise, a destination that is non-null but unwritable is not rejected before the source reads.

The semantic order matters if execution is interrupted by a memory-access failure:

- The second source read precedes the first source read.
- Both source reads precede the first destination write.
- The first destination write precedes the second destination write.

The body supplies no rollback. If the first destination write completes and a later access fails, there is no restoration of the earlier contents.

The exact fault mechanism, whether a failed access can partially complete, and the visibility of writes at a hardware boundary are not established here.

## Acceptance examples

These examples are conditional specifications, not executed tests. Unless stated otherwise, they assume valid, stable, suitably aligned ordinary memory.

### Disabled transfer

Given a null destination and any source-pointer value, including null, the function returns without reading source memory or writing destination memory.

Changing the first argument must not change that behavior.

### Separate source and destination

Given source words `0x11223344` and `0xAABBCCDD`, with a distinct writable destination, the destination ends with those same values in that order.

The second source word is read before the first source word. The first destination word is written before the second.

No byte-order interpretation is required: each value is transferred as a 32-bit word.

### Identical source and destination

Given a region containing words `0x13579BDF` and `0x2468ACE0`, and both pointer arguments identifying its beginning, the final values remain unchanged.

Acceptance still requires the described accesses. This case is not a null-destination no-op.

### Forward overlap by one word

Given three consecutive words containing `0x11111111`, `0x22222222`, and `0x33333333`, let the source begin at the first word and the destination at the second.

The final three words are:

| Position | Final value |
|---|---|
| First | `0x11111111` |
| Second | `0x11111111` |
| Third | `0x22222222` |

The third word receives the original second source value, not the value that replaced it.

### Backward overlap by one word

Given three consecutive words containing `0x11111111`, `0x22222222`, and `0x33333333`, let the source begin at the second word and the destination at the first.

The final three words are `0x22222222`, `0x33333333`, and `0x33333333`.

### Invalid active source
