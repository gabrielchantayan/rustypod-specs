# F-1e84f2939196

## Purpose

F-1e84f2939196 selects a fixed displacement from a numeric selector and adds that displacement to a supplied base value. It returns the resulting integer; it does not retrieve the contents of the resulting address.

The established behavior is a finite selector-to-displacement mapping with a default displacement. Some selectors intentionally produce the same result. The mapping is not a uniform progression.

An address or field-location calculation is a plausible interpretation of this operation, but the supplied evidence does not establish that the base is a pointer, that it identifies an allocated object, or that any returned value may safely be dereferenced. The behavioral contract therefore treats both the base and the result as integers.

## Interface

**Inputs**

| Input | Representation supported by the evidence | Meaning |
|---|---|---|
| Base | Integer declared as `int` in the supplied representation | Starting value to which the selected displacement is added |
| Selector | Four-byte value, giving a 32-bit selector domain | Chooses a displacement through equality with the listed selector values |

**Output**

One integer, declared with the same integer type as the base, containing the selected sum.

**Width qualification**

The selector’s four-byte width is explicit in the supplied representation. The representation does not independently establish the bit width of the base or result, because their type is expressed as `int` rather than an explicitly sized integer. A 32-bit base and result are a plausible target interpretation, but remain an inference rather than a separately verified interface fact.

The selector cases use values from 0 through 16. Their interpretation is unaffected by signedness. Selector bit patterns that do not represent one of those listed values select the default displacement; no signed ordering comparison is required.

**Preconditions**

For an exact arithmetic guarantee independent of unverified overflow behavior, the selected sum must be representable in the base/result integer type.

There is no evidenced requirement that the base be positive, aligned, nonzero, allocated, or a valid address. No input buffer, output buffer, length, object handle, or ownership transfer is part of the visible interface.

The exact calling convention, argument placement, and return-value placement are **documented_only** unknowns.

The mapping must not be replaced by a monotonic selector-to-offset formula. In particular, selector 10 chooses 48, while selector 15 chooses 32. The selector is a lookup key, not an index multiplied by a constant stride.

### Arithmetic and boundaries

All selected displacements are positive. The smallest is 8 and the largest is 48. When the selected sum is representable, the returned integer is greater than the base by exactly the selected amount.

No scaling by an element size is evidenced. The observable operation adds the listed integer directly. Interpreting these integers as byte offsets is reasonable only under an additional address-layout interpretation not established here.

The evidence supplies no explicit overflow check, saturation, range-error result, or alternate arithmetic path. It also does not establish a portable rule for a sum exceeding the base/result type’s maximum value. Consequently, wraparound must not be treated as a guaranteed result.

If the base/result type is confirmed to be a signed 32-bit integer, the largest base permitted for a representable sum is 2,147,483,647 minus the selected displacement. A base of at most 2,147,483,599 is therefore sufficient for every selector. Under that same interpretation, adding these positive displacements cannot underflow a representable base.

### Selection and completion

Each selector selects one displacement and one result. No retry, iteration, allocation attempt, callback, or secondary lookup appears in the supplied evidence.

An unlisted selector does not produce a distinct error or failure result. It produces the ordinary base-plus-12 result. Callers cannot use that result alone to distinguish an unlisted selector from one of the explicitly listed selectors that also choose 12.
