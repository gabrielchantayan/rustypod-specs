# F-9bf13f8f02d7

## Purpose

F-9bf13f8f02d7 prepares selected fields of a caller-supplied object using a descriptor and, conditionally, an object obtained from a dependency. It invokes preparation helpers, selects a source for a 16-byte transfer-shaped operation, conditionally obtains a replacement word, configures descriptor-dependent state, initializes several storage regions, and writes a saved identity marker as its final explicit object write.

The inferred intent is object initialization with optional reuse of state from a compatible existing object. This intent is not sufficient to establish that the function constructs a complete object, acquires ownership, or leaves every field initialized.

The established return value on normal completion is the 32-bit value zero. There is no explicit failure return or rollback path.

- **Destination object:** a pointer used for 32-bit field accesses, interior pointers passed to dependencies, and one byte-sized write.
- **Descriptor:** a 32-bit address used as the base of several reads and as a possible source address passed to an external dependency.

Neither argument is checked for null before use. Both must satisfy the access requirements of the executed path. The destination must provide writable storage through at least byte offset `0x230`, inclusive. Dependencies may require additional storage or stronger alignment; their requirements are not established here.

The following descriptor locations participate:

## Behavior

### 1. Invoke preparation dependencies

The first observable dependency calls occur in this order:

2. F-cf0ff6894387 receives the destination address plus `0x228`.

### 2. Classify the supplied object and save a marker

After the provider returns, the function reads a global 32-bit marker and saves its value for the final destination write.

The provider result is classified as compatible only when:

- it is nonzero; and
- the 32-bit word at its base equals the global marker used by the comparison.

A zero provider result is rejected without dereferencing it. Any nonzero result is dereferenced for classification; there is no independent validity check.

The saved marker read and the comparison’s global-marker reference are distinct expressions in the supplied representation. No dependency call occurs between them. In an ordinary stable-memory execution they agree. Concurrent or externally changing marker storage is not assigned synchronization semantics by this contract.

The compatibility decision is retained for subsequent decisions. The function does not repeat the compatibility check after later dependency calls.

### 3. Read the early selector and choose a source

The function next reads the 32-bit descriptor word at `0x1C` and retains that value for the early branches.

The source argument for the transfer-shaped dependency is:

- the compatible supplied object’s address plus `0x214`, if compatibility succeeded and the retained selector equals exactly `1`;
- otherwise, the descriptor address plus `0x18`.

Thus, a compatible object is not sufficient by itself to select the supplied-object source. The selector must also equal `1`.

The function then calls F-opaque-01 with:

- destination address plus `0x214`;
- the selected source address;
- the integer length argument `16`.

The call shape suggests a 16-byte transfer. Its actual byte-copy behavior, overlap handling, fault behavior, and additional effects are not established without that dependency’s contract.

Under conventional transfer semantics, this operation updates destination bytes `0x214`–`0x223`, including the word at `0x220`.

### 4. Conditionally replace the trailing word

If compatibility failed and the retained early selector equals `1`, the function performs these operations in order:

1. Calls F-opaque-02 with the single argument zero.
2. Calls F-cce4c42e04c6 without an explicit argument.
3. Stores the latter call’s 32-bit result at destination offset `0x220`.

This branch is controlled by the earlier compatibility decision and retained selector. It does not reread the descriptor selector or supplied object’s marker after the transfer-shaped call.

The explicit store at `0x220` follows the transfer-shaped call and therefore supersedes any value that call placed in that word. A subsequent dependency still has an opportunity to modify it.

The role of F-opaque-02 is unknown. It must not be described as resetting a clock, seeding a generator, or clearing an error without additional evidence.

### 5. Invoke the post-transfer dependency

F-209ea8b8b7fe is always called on a normal execution that reaches this point. It receives:

- the address of destination offset `0x220`.

The first argument is read after the transfer-shaped call and any conditional replacement store. The second argument permits direct modification of the word at `0x220`, but does not establish that the callee modifies only that word.

### 6. Configure state from the descriptor’s later selector

Only after F-209ea8b8b7fe returns does the function read the descriptor word at `0x08`.

If that word equals exactly `2`:

- destination offset `0x188` receives the 32-bit value `1`;
- destination offset `0x224` receives the destination’s own 32-bit address.

For every other 32-bit value:

- destination offset `0x188` receives the 32-bit value `2`;
- destination offset `0x224` receives zero.

These two stores occur in the order listed. The descriptor value is read once for this decision.

The self-address field records the destination pointer itself, not an interior pointer and not the supplied object’s pointer.

### 7. Perform later initialization writes

The remaining explicit operations occur in this order:

1. Write one zero byte at destination offset `0x230`.
2. Read the descriptor’s 32-bit word at `0x04` and write that value at destination offset `0x200`.
3. Write a 32-bit zero at destination offset `0x004`.
4. Call F-opaque-03 with destination address plus `0x1D4` and integer size argument `0x24`.
5. Write destination address plus `0x1D4` into the 32-bit field at `0x194`.
6. Write fifteen 32-bit zeros, in ascending address order, at offsets `0x198`, `0x19C`, continuing through `0x1D0`.

8. Return the 32-bit value zero.

The fifteen explicit stores cover exactly 60 bytes, `0x198`–`0x1D3`. They do not include the pointer field at `0x194` or the region beginning at `0x1D4`.

The external call’s size argument is hexadecimal `0x24`, or 36 bytes. Under conventional clearing semantics, its affected region would be `0x1D4`–`0x1F7`, inclusive. Clearing is inferred from the call shape, not established from the unavailable body.

## Side effects

The function exposes destination interior addresses to multiple dependencies. Their effects may extend beyond the explicitly passed fields; no confinement or global-preservation guarantee is available.

The explicit destination writes are ordered as described above. This is not an atomic initialization operation. A fault or non-returning dependency can leave a partially modified destination. The final marker write is last among this function’s explicit writes, but that alone does not establish a publication protocol, memory barrier, or thread-safety guarantee.

Descriptor reads are staggered:

- offset `0x1C` is read before the transfer-shaped call;
- offset `0x08` is read after the post-transfer dependency;
- offset `0x04` is read during the later initialization sequence.

Consequently, the function does not operate on a single descriptor snapshot. Earlier calls or overlapping destination writes can affect later reads.

No non-aliasing check is present. If the descriptor, destination, supplied object, or marker storage overlap, behavior must be evaluated using the stated access order and the actual dependency contracts. Successful operation with overlapping transfer source and destination is not established.

Only equality with `1` and `2` affects the described branches. There is no range check, sign-dependent branch, or arithmetic normalization of descriptor values.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. “Compatible” means classification succeeds at the time of the check.

### Compatible object and early selector `1`

Given a compatible supplied object and descriptor word `0x1C = 1`:

- F-opaque-01 receives the supplied object’s address plus `0x214` as its source.
- F-opaque-02 and F-cce4c42e04c6 are not called.
- F-209ea8b8b7fe is called afterward with the then-current destination word at `0x214` and address `0x220`.

Under conventional transfer semantics and absent other intervening mutations, the four destination words at `0x214`–`0x220` initially match the supplied object’s corresponding words. The final word remains subject to F-209ea8b8b7fe.

### Missing object and early selector `1`

Given a zero provider result and descriptor word `0x1C = 1`:

- no provider-result dereference occurs;
- the transfer source is descriptor plus `0x18`;
- F-opaque-02 receives zero;
- F-cce4c42e04c6 is called, and its result is stored at `0x220` before F-209ea8b8b7fe.

A nonzero supplied object with a mismatching marker follows the same branch, after its first word has been read.

### Compatible object but early selector not `1`

Given a compatible object and descriptor word `0x1C = 0`, or any other value unequal to `1`:

- the source is descriptor plus `0x18`, not the supplied object;
- neither conditional dependency is called.

The same source and conditional-call outcome applies to an incompatible object when the selector is not `1`.

### Later selector exactly `2`

If the descriptor word at `0x08` reads as `2` after F-209ea8b8b7fe returns, destination offset `0x188` is written with `1`, followed by a self-address write at `0x224`.

If it reads as any other value, those writes are `2` and zero respectively.

These outcomes depend on the later read, not on the descriptor’s contents at entry.

### Saved marker differs from a later marker

If a dependency changes the global marker after it was saved, and execution completes normally, the explicit final write at destination offset zero still uses the saved value. There is no final compatibility recheck.

### Final initialization boundaries

On normal completion, the function has explicitly written zero to all fifteen words from `0x198` through `0x1D0`, written the interior address at `0x194`, and zeroed the byte at `0x230`.

These facts alone do not imply that every byte between those fields is zero or that F-opaque-03 cleared its region.
