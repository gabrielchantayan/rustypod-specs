# F-248f88de3ff6

## Purpose

This procedure performs caller-memory writes, fixed-address accesses, computed calls, and stack-state changes. Its represented paths lead either to a repeating continuation or to an invalid-instruction endpoint. No application-level purpose, normal return, or successful completion condition is established.

This contract distinguishes:

- **Established static evidence:** explicit access widths, represented operation ordering, target calculations, and scalar-state transitions.
- **Inferred intent:** insufficient evidence to identify an application service.
- **Unknown behavior:** executable validity, missing declarations, dependency contracts, and operations whose arithmetic semantics are unsettled.

A represented call target is documented even when the callee’s identity and behavior are unknown. A target calculation does not establish that executable code exists there.

### Outputs and preconditions

Every reached access requires accessible storage of its actual width. No argument, bounds, alignment, permission, or null validation precedes the accesses. Valid explicit arguments alone do not establish a valid invocation.

### Width and arithmetic conventions

Explicit pointer accesses establish access width. Undeclared global accesses do not acquire a width from their address, name, assignment expression, or receiving scalar.

In particular, conversion of a global value to 32 bits does not establish a four-byte read; assignment of a two-byte expression does not establish a two-byte destination write.

Unsigned 32-bit operations retain that width. Signed overflow, invalid signed left shifts, right shifts by 32 on 32-bit operands, and out-of-range conversions are not silently replaced by wrapping or processor-specific semantics. All offsets below are bytes.

1. Store D’s low address byte through A.
2. Read the global at `0x0897ef80` into retained signed 32-bit state; its source width is unknown.
3. Store A’s address as four bytes through W.
4. Store B as four bytes at W plus four.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Entry truncation:** B equal to `0x12345678` causes a four-byte store at W plus four and two-byte `0x5678` at C plus two, assuming valid accesses.

2. **Selection:** negative A with T equal to `0x40000000` selects the zero-mask region despite nonzero T.

3. **Outer address:** N zero and V `0x10` select address `0x26` for `0xc470`; V `0x18` selects `0x27`.

4. **Initial effects:** J zero produces a four-byte zero store at address zero. Initial carried low half zero produces a four-byte `0x0897f22d` store at address `0x0c`, if reached.

5. **Dispatch capture:** initial F `0x0897f0c3` and an unequal outer comparison select target `0x0897f0f1`, while replacing F with `0x0897f193`. The following inner zero-argument call therefore targets `0x089800e9`, then replaces F with `0x0897f1d7`. Equality at the outer comparison leaves the initial F unchanged.

6. **Distinct continuation calls:** G below `0x14` selects `0x0897f80f`. An upper-branch zero condition selects `0x0897f83b`. A nonzero condition selects `0x08791770` only if execution resumes after the breakpoint.

7. **Signed multiplication:** L interpreted as −1 produces G `0xffffffe0`, selecting the upper branch. L `0x04000000` overflows signed multiplication; a wrapped G is not established.

8. **Read width and timing:** converting `0x0897effa` to unsigned 32-bit does not establish its read width. The shared-tail read at `0x00000060` occurs after the first shared-tail call, so pre-call contents cannot be substituted without a preservation guarantee.
