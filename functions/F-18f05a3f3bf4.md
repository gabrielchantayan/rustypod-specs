# F-18f05a3f3bf4

## Purpose

F-18f05a3f3bf4 performs an indefinitely repeated sequence of memory accesses and dependency calls. Its visible behavior includes initialization writes, overlapping writes of different widths, calls through control-flow-dependent targets, interpretation of dependency results as addresses, and a conditional software breakpoint.

No normal return, validation protocol, ownership transfer, or recoverable error result is established. A higher-level purpose—such as allocation, initialization, or device control—is not established.

This contract describes static evidence in the supplied representation. It does not resolve questionable recovered arithmetic or establish that every represented operation has executable semantics on a particular platform. All examples are conditional; no runtime tests have been performed.

### Width and address interpretation

The representation contains 8-, 16-, 32-, and 64-bit accesses. Pointer conversions and the use of separate 32-bit halves of dependency results suggest a 32-bit address model. That model is an inference, not a complete platform specification.

Unsigned 32-bit arithmetic is modular. This applies, in particular, to accumulator addition, working-value multiplication by 64, unsigned working-value offsets, unsigned scaled-address offsets, transfer-value formation from the working value, and payload multiplication.

It does **not** automatically apply to calculations explicitly represented as signed:

- Initial pointer conversion, addition of input 5 and eight, and subsequent doubling.
- Conversion of the high half of F-D01’s result to signed 32 bits before adding `0x50`.
- Conversion of F-D05’s low half to signed 32 bits before multiplication by 32.
- Doubling the signed interpretation of F-D07’s low-half destination.
- Left-shifting the signed interpretation of the candidate record address by two.
- Left-shifting the signed interpretation of the current pointer by eight.
- The signed shifts used in the final branch condition.

Overflow, negative signed left shifts, out-of-range conversions, pointer arithmetic, byte order, and alignment require platform interpretation. Their uncertain cases remain documented_only; they are not silently replaced with unsigned wrapping.

### Output and preconditions

The only explicit output parameter receives the unmodified seed as 32 bits. The function also modifies numerous other addresses and invokes dependencies.

No normal return value or terminating success condition is visible. Continued progress requires each preceding access, arithmetic operation, and call to permit continuation. No checks establish that any supplied or derived address is mapped, aligned, writable, or readable.

## Behavior

### Initialization

The first two visible memory effects are 32-bit stores:

1. `0x00000040` at absolute address `0x28`.
2. Zero at absolute address `0x2C`.

The representation identifies overlapping global storage at these locations. They must not be assumed to be independent logical objects.

Next, an intermediate signed address value is formed from the incoming current pointer, input 5, and an additional eight bytes. The function stores that intermediate as 32 bits at twice its numeric value. Both the additions and doubling are represented as signed calculations; overflowing cases have no established modular result.

Initialization then stores the original seed through input 2 and stores the low byte of the initial working value at the initial data address plus 20 bytes. That offset follows from advancing five 32-bit elements.

These accesses are ordered. Aliasing can cause a later initialization write to overwrite an earlier one. A fault or other interruption at an earlier access can prevent all subsequent effects.

### Outer write sequence

Each outer entry issues these accesses in order:

| Order | Access |
|---|---|
| 1 | Store an 8-bit zero at the data address. |
| 2 | Store the low 16 bits of the working value at the data address. |
| 3 | Store the 32-bit payload at the data address. |
| 4 | Add the transfer value to the accumulator, modulo \(2^{32}\), then store the resulting 32-bit accumulator at the companion address. |

On initial entry, the data and companion addresses coincide. They need not coincide on subsequent entries.

The narrower writes remain part of the access contract even if a later write replaces their contents. Final memory contents alone do not establish this sequence, especially for overlapping or device-backed storage.

After the outer sequence, the function enters the inner processing sequence with F-D01’s argument set to zero.

### Inner entry and F-D01 effects

At the beginning of every inner iteration, the function saves the low byte of the current transfer value. Later byte writes in that iteration use this saved byte, not the subsequently replaced transfer value.

F-D01 is called with the current 32-bit iteration argument. Its target depends on the target state specified under Dependencies. Its represented 64-bit result supplies:

- A low 32-bit destination address.
- A high 32-bit base used for a pointer load.

The following accesses are ordered:

1. Store the result’s low 16 bits at the low-half destination.
2. Compute the unsigned 32-bit working value multiplied by 64; store that 32-bit result at the address represented by the same result.
3. Read 32 bits through the current pointer and replace the transfer value with that read value.
4. At the unsigned working value plus four bytes, store the low 16 bits of the old current pointer plus four.
5. Read a 32-bit pointer from the F-D01 high-half base plus `0x50`, then replace the current pointer with it.

The fourth access does not dereference the old pointer. Its stored halfword is derived numerically from that pointer. The fifth access performs the high-half conversion and offset as a signed calculation; a high-half value near a signed boundary cannot be assumed to wrap safely.

Because the pointer read follows preceding stores, aliasing may affect both the transfer-value read and the replacement-pointer read.

### Intermediate calls and scaled destination

After those accesses, the function calls:

1. F-D02, with no explicit arguments shown.
2. F-D03, with no explicit arguments shown.
3. F-D04, with the transfer value read through the old current pointer.
4. F-D05, with that transfer value shifted right by three bits as unsigned 32-bit data.

F-D05’s represented 64-bit result supplies a **candidate record address** from its high half. Its low half is converted to signed 32 bits and multiplied by 32; the result is then assigned to an unsigned 32-bit **scaled address**.

The function stores the scaled address as 32 bits at that same address **before** comparing it with decimal 20. The comparison is unsigned.

Signed multiplication is material here. For example, a positive low half above `0x03FFFFFF` overflows signed 32-bit multiplication by 32. The unsigned destination type does not establish wrapping for the preceding signed multiplication.

### Small-scaled-address transition

If the scaled address is below 20, the function leaves the inner loop and repeats its enclosing repetition:

- The outer write sequence is not executed.
- F-D01’s next argument is reset to zero.
- F-D01 uses the small-result target state on its next call.
- The working value remains unchanged.
- The transfer value remains the value read through the old current pointer.

For defined signed multiplication, zero is the only possible scaled result below 20. The branch therefore follows an attempted 32-bit zero store at address zero. The comparison does not guard that store.

The constant `0x0897EDDF` is used in forming an intervening dependency target. It is not the next F-D01 argument.

### Continuing transition

If the scaled address is at least 20, the function performs the following effects in order:

1. Store the working value as 32 bits at the scaled address plus `0x58`.
2. Store the low 16 bits of the replacement current pointer at the working value plus `0x0E`.
3. Replace the transfer value with the unsigned working value shifted left by two bits.
4. Store the previously saved byte at a named global byte location.
5. Call F-D06 with the unsigned current-pointer value shifted right by two bits.
6. Call F-D07 without explicit arguments.

The named byte location’s address, semantic role, and relationship to other storage are not established. Its source-level naming does not establish reset behavior.

F-D07 returns a represented 64-bit value. Its low half becomes a destination address; its high half becomes the companion address. The function then issues:

| Order | Access |
|---|---|
| 1 | Store the saved byte at twice the signed interpretation of the low-half destination. |
| 2 | Store the low byte of the high half at the low-half destination plus eight bytes. |
| 3 | Store the candidate record address as 32 bits at twice the unsigned accumulator. |
| 4 | Store the complete 64-bit F-D07 result at the low-half destination. |

The first destination involves signed multiplication and has no established result when that multiplication overflows. The third uses unsigned 32-bit multiplication. The second follows an eight-byte pointer advance; validity of the resulting pointer is a separate platform and memory-layout requirement.

These accesses may overlap. The final 64-bit store can overwrite earlier bytes, but it does not remove their observable access history.

### Record writes and next-state construction

After the F-D07 stores:

- The accumulator becomes the signed interpretation of the candidate record address shifted left by two, assigned to unsigned 32-bit state.
- The working value becomes the signed interpretation of the current pointer shifted left by eight, assigned to unsigned 32-bit state.

Neither signed left shift is unconditionally modular. Negative inputs and results outside the signed representable range require additional execution semantics.

The function then writes three consecutive 32-bit fields at the candidate record address:

| Byte offset | Stored value |
|---|---|
| `0x00` | Transfer value computed before F-D06 |
| `0x04` | Newly computed working value |
| `0x08` | Current-pointer value |

This establishes a 12-byte write footprint, not allocation, ownership, or a complete object format.

The payload becomes the transfer value multiplied by 256 using unsigned 32-bit arithmetic. The data address becomes zero.

### Outer restart or breakpoint continuation

The branch selector is formed by:

- Interpreting the current pointer as signed.
- Left-shifting by 31.
- Right-shifting the signed result by 32.
- Converting to unsigned and shifting right by 20.

The shift by 32 is outside the ordinary valid range for a 32-bit operand. The preceding signed left shift also has restrictions. No general mapping from pointer values to branch outcomes is established.

Conditional on a zero selector:

- Execution restarts the outer write sequence.
- The data address is zero.
- The companion address is F-D07’s high half.
- The accumulator addition uses the transfer value computed before F-D06.
- F-D01 subsequently receives argument zero and uses the outer-restart target state.

Conditional on a nonzero selector:

1. Store the selector as 32 bits at the unsigned payload plus `0x20`.
2. Set the next F-D01 argument to the signed interpretation of the payload shifted right by 29.
3. Select the breakpoint-continuation target state.
4. Invoke a software breakpoint with immediate value four.
5. If execution resumes, replace the working value with the signed interpretation of the companion address shifted right by 18, assigned to unsigned state.
6. Continue the inner loop without repeating the outer writes or resetting the argument.

Signed-right-shift semantics for negative values remain documented_only. The breakpoint is neither a normal return nor an established terminal error.

## Acceptance examples

All examples assume preceding accesses and calls complete and explicitly required arithmetic has defined or supplied platform semantics.

### Initialization with seed one

The working value is six, the initial data address is `0x01000000`, and input 2’s destination receives the 32-bit value one. The initialization byte at address `0x01000014` is `0x06`.

### Unsigned seed underflow

With seed zero, the working value is `0xFFFFFFFE`. The initialization byte at address `0x14` is `0xFE`. This does not establish that the preceding absolute and signed-derived accesses are valid.

### Ordered initial outer writes

When the data and companion addresses coincide, acceptance requires the byte-zero, working-halfword, payload-word, and updated-accumulator-word writes in that order. A matching final word is insufficient evidence.

### Small result resets the argument

If F-D05’s low half is zero, the function attempts a 32-bit zero store at address zero. If it completes, the next F-D01 call uses base `0x0897EDF1` plus `0xA1E` and receives zero, without intervening outer writes.

### Signed multiplication boundary

A low half of one produces scaled address `0x20`: the function stores `0x20` there, then stores the working value at `0x78`.

A low half of `0x08000000` overflows signed multiplication by 32. A zero scaled result is **not** established. Only with an additional signed-wrapping interpretation would this case produce zero and take the small-result transition.

### Saved byte survives local replacement

If the transfer value’s low byte is `0xAB` at inner entry, the continuing path uses `0xAB` for the named-global store and doubled-destination byte store. Replacing the transfer value locally does not change that saved byte. Dependency or aliasing effects may later overwrite either destination.

### Distinct restart arguments

A zero selector leads through outer writes at data address zero and then F-D01 with argument zero and the outer-restart target.

A nonzero selector followed by breakpoint resumption leads directly to F-D01 with the signed-shift-derived argument and breakpoint-continuation target. It does not substitute `0x0897EDDF` or reset the argument to zero.
