# F-71ca831fb02d

## Purpose

F-71ca831fb02d conditionally initializes two shared metrics, prepares template-derived descriptors, and invokes a mode-dependent sequence of allocation and construction dependencies.

Established behavior consists of field accesses, retained values, descriptor modifications, and dependency calls. The semantic object types, presentation effects, and meaning of the metrics are not established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

The function accepts four arguments and has no explicit return value.

| Argument | Observed width and interpretation | Use |
|---|---|---|
| Input record | 32-bit address-like value | Supplies a flag byte and signed measurement; forwarded to lookup dependencies. |
| Mode | Signed 32-bit value | Zero versus nonzero selects construction flow; equality with one separately selects descriptor values. |
| Context A | Opaque 32-bit value | Forwarded unchanged to every construction dependency. |
| Context B | Opaque 32-bit value | Forwarded unchanged to every construction dependency. |

Observed input-record layout:

| Byte offset | Access | Interpretation |
|---|---|---|
| 4 | One byte | Only bit 0 is tested. |
| 8 | Signed 32-bit read | Measurement used to customize descriptor C. |

A global address value identifies shared metric storage:

| Byte offset | Access | Interpretation |
|---|---|---|
| 8 | Signed 32-bit read/write | First metric; also the initialization sentinel. |
| 12 | Signed 32-bit read/write | Second metric; not independently checked for initialization. |

The function captures one shared-state address at entry. That captured address supplies both metric-write destinations and the later metric reads. The sentinel check separately reads the global address and accesses offset 8 through that separately obtained address. Equality of the captured address and the sentinel-check address is not independently enforced.

All accessed addresses must support the stated reads and writes. Dependency results must satisfy the dereference requirements below. There is no visible argument validation, allocation-result check, bounds check, or error return.

Descriptors A through E designate five 104-byte local descriptor regions. Descriptor K designates a 92-byte region. These labels describe this contract, not public symbols. An extended descriptor used in the nonzero branch has fields through byte offset 123.

## Behavior

### Shared-metric initialization

After capturing the shared-state address, the function checks the signed 32-bit field at offset 8 through a separate read of the global address.

A nonzero sentinel skips initialization completely, regardless of the second metric. A zero sentinel initiates this sequence:

1. Invoke F-9d0ecc5f6adf without arguments and retain its 32-bit result for both resolutions.
2. Obtain the first lookup-key value from its global location and invoke F-ed4b1fd8953e with the input-record address and that key.
3. After the lookup returns, read and retain the global resource-selector value.
4. Read a 32-bit descriptor address from offset 8 of the lookup result.
5. Invoke F-5710a8628cba with the retained result from F-9d0ecc5f6adf, a separate read of the global resource-selector value, and the first 32-bit word at the descriptor address.
6. Invoke F-59c1430f85c2 with a temporary-storage address, the resolution result, the low 16 bits of the descriptor’s word at offset 4, and the byte at descriptor offset 12.
7. Subsequently read the first 32-bit word of that temporary storage, clear bit 0, and use the resulting address for signed 16-bit reads at offsets 82 and 84. Sign-extend and add those values; write the signed 32-bit sum to offset 8 of the captured shared-state address.
8. Obtain the second lookup-key value and invoke F-ed4b1fd8953e again with the input-record address.
9. Read the descriptor address at offset 8 of this second lookup result.
10. Invoke F-5710a8628cba with the retained result from F-9d0ecc5f6adf, the resource-selector snapshot saved after the first lookup, and the second descriptor’s first word.
11. Invoke F-59c1430f85c2 with the same temporary-storage region and the corresponding resolution result and descriptor fields. Subsequently interpret its first word as above, add the two signed 16-bit fields, and write the result to shared-state offset 12 through the captured address.

The second resolution does **not** reload the resource selector. Changes to that global during the first resolution, either temporary-storage call, or the second lookup do not change the saved selector supplied to the second resolution. The first resolution uses its own read rather than the saved value.

For each descriptor, the first word is supplied to the resolution call before the offset-4 word and offset-12 byte are supplied to F-59c1430f85c2. Those latter fields are accessed after the resolution returns; their values are not established as pre-resolution snapshots.

Passing temporary storage to F-59c1430f85c2 does not establish that the dependency writes it. Defined subsequent processing requires its first word to contain a valid address-like result at the time it is read. Whether the dependency guarantees that condition is unknown. The second call uses the same storage; a fresh result cannot be assumed merely because a call occurred.

Clearing bit 0 preserves every other address bit. No additional tag or alignment validation is visible.

Each metric sum lies between −65,536 and 65,534 and therefore fits signed 32-bit storage. The first write precedes the second lookup. The update is not atomic, and no rollback is visible. A first metric calculated as zero leaves the sentinel eligible to trigger initialization on a later invocation.

### Common descriptor preparation and snapshots

An unidentified external dependency receives destination, source, and byte count for each transfer. Its implementation is unavailable. Layout statements about transferred contents are conditional on byte-copy semantics.

The preparation order is A, B, C, D, then E. All five transfers precede the first allocation.

**Descriptor A:**

- Transfer 104 bytes from its globally supplied template source.
- After that transfer returns, capture the global base used for the A/B selection table.
- Read input flag bit 0.
- Replace the 32-bit field at offset 72 with table entry 1 only if that bit is set and mode equals one; otherwise use entry 0.

The table access for A separately reads the global table base. It is not expressed using the captured base. With no intervening dependency, those reads ordinarily identify the same table, but equality under asynchronous mutation is not established.

**Descriptor B:**

- Separately read the global base associated with the A/B table and use that read plus **1012 bytes** as B’s template source.
- Transfer 104 bytes from that source.
- Read input flag bit 0 again and apply the same “set bit and mode equals one” selection rule.
- Replace B’s 32-bit field at offset 72 using the table base captured after A’s transfer.

B’s source and B’s replacement table therefore have different snapshot boundaries. A change to the global base during B’s transfer does not redirect B’s replacement table. The table contents themselves are not snapshotted: the selected entry is read after that transfer.

After B’s replacement, the function reads and retains, in order:

1. The first metric at offset 8 of the entry-captured shared-state address.
2. The second metric at offset 12 of that same address.
3. The input measurement at input offset 8.
4. The default global value used for the mode-dependent descriptor field.

If mode equals one, it then reads the separate mode-one global value and substitutes it for the default. The default read still occurs in mode one.

Those metric, measurement, and selected-value snapshots remain the operands for subsequent descriptor modifications across the following transfer calls. Mutating their original storage during those calls does not cause a reload for these modifications.

**Descriptor C:** Transfer 104 bytes from its globally supplied template source. Replace:

| Byte offset | Replacement |
|---|---|
| 60 | Signed 32-bit arithmetic result described below. |
| 64 | Retained mode-selected 32-bit value. |

The arithmetic grouping is:

1. Add the two retained metrics.
2. Subtract that sum from the retained input measurement.
3. Subtract two.
4. Divide by two, truncating toward zero.
5. Add the retained first metric.

Signed 32-bit overflow behavior is documented_only. The mathematical description applies when the metric sum, subtraction of that sum, subtraction of two, and final addition are each representable as signed 32-bit values. Reassociating the subtractions would change these intermediate-overflow conditions and is not part of this contract.

**Descriptor D:** Transfer 104 bytes from its separately supplied global template source, then replace the 32-bit field at offset 64 with the same retained mode-selected value.

**Descriptor E:** Transfer 104 bytes from its separately supplied global template source. Its conditional offset-100 replacement occurs in the common tail.

The separate source reads occur at their respective transfers; the function does not capture all template addresses at entry.

### Common tail

After either branch:

1. Request 544 bytes from F-8157a180d901.
2. Invoke F-7f6becd152e6 with that result, literal zero, both contexts, and descriptor D.
3. Read input flag bit 0 again.

If this final read is set, read the globally supplied tail-table base and then its 32-bit entry at byte offset 8. Write that value to descriptor E at offset 100. Request 560 bytes and invoke F-60fe53f7ab39 with descriptor E and the usual arguments.

If the final flag read is clear, there is no E construction. The function returns without an explicit result.

## Side effects

Direct effects include conditional writes to the two shared metric fields, local descriptor writes, reads from input and global storage, and calls to dependencies with addresses of temporary storage.

The function makes no explicit input-record write and performs no visible deallocation. It neither establishes allocation ownership transfer nor proves a leak. Constructor results, if any, are not used by the visible caller.

Descriptor storage is temporary. Retention of its address by a dependency would require a lifetime arrangement not established here.

Dependencies may alter reachable memory or global values; no preservation contract is supplied. Specific retained addresses and values nevertheless remain snapshots as described above. A retained table address does not imply retained table contents.

Assuming normal returns, mode zero produces four allocation/construction pairs, and nonzero mode produces three. A set final flag adds one pair. Initialization calls are additional and independent of these counts.

No local failure branch, exception handling, cleanup sequence, synchronization, or rollback is visible. Failure or nonreturn in a dependency may prevent all subsequent operations.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, they assume valid storage, normal returns, byte-copy transfers, stable relevant memory, and representable arithmetic.

1. **Nonzero sentinel, mode zero, clear flag.** Initialization is skipped even if the second metric is zero. Construction order is A, C, K, D, using their respective dependencies. E is omitted.

2. **Mode one, set flag.** A and B receive entry 1 at offset 72. The default mode-dependent global value is read, then the mode-one value is read and retained for C and D. Construction uses B, the extended descriptor, D, and E.

3. **Mode two, set flag.** The nonzero branch applies. A and B receive entry 0 because mode is not one. The extended descriptor receives entry 1 from its separate flag-only table.

4. **Resource selector changes during the first resolution.** Suppose the selector snapshot saved after the first lookup is X and the first resolution changes the global selector to Y. The second resolution still receives X, assuming no unrelated invalidation prevents progress.

5. **Selection-table base changes during B’s transfer.** Suppose the base captured after A’s transfer is P. If B’s transfer changes the global base to Q, B’s offset-72 replacement still reads its selected entry through P. B’s template source was determined separately before that transfer.

6. **Metrics change during C’s transfer.** With retained metrics 10 and 7 and retained measurement 16, the metric sum is 17, the next intermediates are −1 and −3, division gives −1, and the final result is 9. Changes to the original metric storage during the transfer do not alter those operands.

7. **Overflow boundary.** If retained metrics are 2,147,483,647 and 1, their first required addition is outside signed 32-bit range. This contract does not assign a result, even if an algebraically rearranged expression would avoid that intermediate.

8. **Computed zero sentinel.** A resolved pair of −12 and 12 stores zero as the first metric. The second initialization still proceeds. A later invocation observing zero attempts initialization again.

9. **Flag changes before the tail.** Earlier clear reads do not prevent E construction if the final read is set. Earlier descriptor replacements are not retroactively changed.

10. **Allocation returns zero.** Zero is forwarded to the selected construction dependency. Its response is unknown.

11. **Temporary-storage call supplies no valid word.** The caller still attempts its subsequent read and address-based accesses. No local recovery is established; successful metric production cannot be assumed.
