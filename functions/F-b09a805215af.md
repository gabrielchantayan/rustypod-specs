## Behavior

### Numeric mapping

For an input in the inclusive interval `0x61` through `0x7A`, the result is the input reduced by `0x20`. The resulting interval is `0x41` through `0x5A`.

For every input outside that interval, the result equals the original input.

Consequently:

- The two endpoints, `0x61` and `0x7A`, are converted.
- The adjacent values `0x60` and `0x7B` are unchanged.
- Values already corresponding to uppercase ASCII letters are unchanged.
- Zero, control-character values, punctuation, and digits are unchanged.
- Values above `0xFF` are unchanged when representable by the input type.

The last property is important: this is not an unconditional conversion to an eight-bit character. A larger integer whose low byte happens to represent a lowercase ASCII letter does not qualify merely because of that low byte. For example, `0x161` remains `0x161`; it does not become `0x41` or `0x141`.

### Range evaluation and arithmetic

The selection criterion uses an unsigned difference from `0x61`, compared strictly against `0x1A`. For the ordinary unsigned domain described above, this selects exactly the 26 values from `0x61` through `0x7A`.

For inputs below `0x61`, unsigned subtraction wraps within the arithmetic domain. The resulting difference is outside the accepted range; those inputs are not converted. Such wraparound is part of the unsigned range-selection behavior, not an error condition.

The strict comparison matters at the upper boundary. The difference for `0x7A` is `0x19`, which qualifies. The difference for `0x7B` is `0x1A`, which does not.

On the selected path, the conversion result is also restricted to its low eight bits. Because every selected input already produces a result between `0x41` and `0x5A`, that restriction does not change any selected result. It does not apply to the unchanged-input path and must not be interpreted as a promise that every returned value fits in eight bits.

- An output differs from its input exactly when the input lies between `0x61` and `0x7A`, inclusive.
- Every changed output lies between `0x41` and `0x5A`, inclusive.

- Applying the function again to an already returned value leaves that value unchanged.
- Distinct inputs can produce the same result. For example, `0x41` and `0x61` both produce `0x41`.

The function does not report whether conversion occurred through any separate channel. A caller needing that distinction must compare the returned value with the supplied value.
