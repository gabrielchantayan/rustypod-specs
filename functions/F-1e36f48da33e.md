# F-1e36f48da33e

## Purpose

F-1e36f48da33e stores two initialization results in a caller-supplied object. If an asymmetric entry gate passes, it repeatedly acquires a seven-word record, optionally dispatches callbacks through a context-associated registry, conditionally invokes a no-argument operation, and evaluates a late termination comparison.

A nonzero callback result stops dispatch for the current record. It does not directly terminate the acquisition loop. Normal loop termination requires equality between the record’s then-current first word and a shared marker, under the comparison’s actual type-conversion rules.

“Initialization,” “record,” “registry,” and “dispatch” describe apparent roles. Their application-level meanings are inferred. The contract distinguishes established access and control-flow behavior from unresolved dependency semantics.

## Behavior

- It rereads the field at `0x34`.
- If that field is nonzero, it tests the retained result from F-26c9446e65b4.
- Processing begins only when both tested values are nonzero.

A failed gate returns without context acquisition, record acquisition, or restoration of the object fields. Dependency effects outside these explicit writes remain unconstrained.

### Lookup and callback dispatch

- The captured registry reference.
- The first record word as read for this lookup.
- The callback-address slot’s address.
- The callback-argument slot’s address.

### Late termination comparison

- Inequality begins another acquisition iteration.

## Acceptance examples

These are conditional consequences of static control flow, not runtime observations. Calls are assumed to return normally and supply usable values where consumed. In termination examples, “equal” and “unequal” mean the outcome under the actual comparison conversions; they do not assume a 32-bit marker.

1. **First gate field remains zero.** If the first initializer returns zero and `0x34` remains zero through the gate, both initializers and both writes still occur. No context is acquired.

2. **Second result is zero.** A nonzero first gate field is insufficient when the retained second result is zero. The gate does not substitute a later value read from `0x58`.

3. **First field changes during initialization.** A nonzero first result does not ensure entry if `0x34` becomes zero before its gate read. A zero first result does not prevent entry if that field becomes nonzero and the retained second result is also nonzero.

4. **Registry absent.** A zero registry reference skips lookup and callbacks, but not the flag test or final comparison.

5. **Initial lookup exhausted.** A zero initial lookup result causes no callback and no continuation lookup. Its other effects, if any, remain relevant to later reads.

6. **Callback stops dispatch.** A nonzero callback result causes no continuation lookup after that callback. If the final comparison reports inequality, acquisition repeats.

7. **Continuation exhausted.** A zero callback result triggers continuation lookup. If that lookup returns zero, execution advances to the flag test without another callback.

8. **Record key changes.** If a callback changes the first record word and returns zero, continuation lookup receives the word present when its argument is read, not a saved acquisition-time key.

9. **Flag changes during dispatch.** If acquisition supplies a nonzero flag but the flag is zero at its post-dispatch read, F-41d0ae4663e8 is skipped. The reverse transition causes the call when the nonzero value remains present at that read.

10. **Initially matching record.** Initial equality does not suppress dispatch. Return requires equality at the final comparison after all intervening effects.

11. **Callback affects termination.** With a stable marker and no later relevant modifications, changing the record word so the final comparison reports inequality causes another iteration; changing it so the comparison reports equality causes return. Marker stability alone is insufficient if later operations change the record.

12. **Marker changes late.** A change to the marker before its final read can affect termination even if the record remains unchanged. Whether a particular numeric or bit-pattern change alters equality is unresolved without the marker’s type and comparison conversions.

13. **Context fields change.** A later change at `0x1c` does not replace the retained acquisition argument. A change at `0x20` can affect a subsequent iteration’s captured registry, but does not replace the current iteration’s capture.
