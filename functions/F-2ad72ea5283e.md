# F-2ad72ea5283e

## Purpose

F-2ad72ea5283e traverses a sequence of linked objects, invoking an indirectly selected operation on each visited object. Traversal stops when an operation returns a nonzero status or when the current object becomes null.

The function returns a separate 32-bit output value, not the operation’s status. That output begins at zero and is shared across successive operation calls. A call that reports zero status can still affect the eventual result by modifying this output.

The established behavior is a traversal with status-controlled termination and a shared output slot. Interpreting it as a search, lookup, or request-resolution operation is inferred intent only; the supplied evidence does not establish the meaning of the objects, the two additional arguments, or the returned bits.

## Behavior

### Initialization and observation order

The observable sequence begins with a call to F-9d0ecc5f6adf. No explicit arguments are supplied.

After that call returns:

1. The global value designated Argument A is read.
2. The global value designated Argument B is read.
3. The first word of the local output storage is initialized to zero.
4. The initial object reference is tested for null.

Consequently, changes made by F-9d0ecc5f6adf to either global can affect the arguments subsequently passed to operations. The global reads also occur when the initial object reference is null.

The values captured from the globals are reused for the entire traversal. This function does not explicitly reread either global between operation calls. A later operation may change the globals, but such a change does not refresh the captured argument values in this invocation.

The reads are separate and ordered. The evidence does not establish an atomic two-value snapshot or any synchronization with concurrent writers.

### Processing a nonnull object

For each nonnull current object, the function obtains the dispatch base from the object’s first word. It selects the callable address stored 100 bytes beyond that base, then invokes that address with the four arguments described above.

No validation of the object, dispatch base, or callable address is shown.

The output storage is shared across all these calls. It is not reinitialized when traversal advances. An operation can therefore observe the first word left by an earlier operation.

Dispatch is resolved from the current object for each invocation. The evidence does not support caching one operation address for the entire traversal.

### Status-controlled continuation

When an operation returns:

- **Nonzero status:** traversal stops immediately. The function returns the first output word.
- **Zero status:** the function reads the next-object reference from the current object’s word at index 5 and makes that reference current.

The next-object field is read only after a zero status. It is not read in advance of the operation call.

This timing makes dependency-driven mutation significant. If an operation changes the current object’s next-object field and then returns zero, the subsequent traversal follows the field value observed after the operation returns.

If the newly obtained reference is null, no further operation is invoked. The function returns the current first output word.

### Output and status are independent

There is no branch that translates an operation status into a return value.

In particular:

- Zero status does not imply that the output remains zero.
- Nonzero status does not imply that the output is nonzero.
- A value written by an operation returning zero can become the final return if traversal later reaches null without another write.
- An operation returning nonzero without changing the output causes the previously retained output value to be returned.

All 32 bits of the output word are returned as represented. No sign check, range check, normalization, or arithmetic transformation is shown.

### Termination and failure boundaries

The visible normal termination conditions are:

- A visited operation returns nonzero.
- After a zero-status operation, traversal reaches a null next-object reference.

No iteration limit or cycle detection is present. A cycle whose operations continually return zero can prevent termination.

No explicit recovery or error-result path is shown for invalid references, invalid dispatch targets, dependency failures, or nonlocal exits.
