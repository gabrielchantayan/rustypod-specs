# F-0222d85d114f

## Purpose

F-0222d85d114f performs a gated byte-pattern check using an input object and values obtained from dependencies. Every normal return is a 32-bit zero or one.

The accepted pattern is asymmetric:

- The unsigned measured quantity must exceed four.
- The two bytes immediately before the calculated end position must be `4p` or `4P`.
- A lowercase `m` immediately before those bytes is sufficient, regardless of the preceding byte.
- An uppercase `M` in that position additionally requires a preceding period.

Consequently, this is not an ordinary case-insensitive check for a `.m4p` suffix. Filename-extension recognition is plausible intent, not an established interface contract. The source does not establish that the candidate is a string, that the measured quantity is its length, or that either value describes a filename.

The initial gate takes precedence over all candidate content: if it returns zero, this function returns zero without obtaining or examining a candidate.

## Behavior

### Initialization and gate

Before the first indirect call, the four local words are initialized from the four arguments.

The function reads the dispatch-table address through the original object, obtains the entry at byte offset 8, and calls it with the original object address as its sole visible argument.

Its result is tested for equality with zero:

- A zero result causes immediate return of zero.
- Any nonzero 32-bit result permits processing to continue, including a bit pattern that would represent a negative signed value.

On the zero-gate path, there is no second indirect call, no call to any of the four identified dependencies, no candidate-byte read, and no visible finalization call. The gate operation itself may still have side effects.

### Processing after a nonzero gate

The function rereads the dispatch-table address through the original object. It calls the entry at byte offset 16 with these visible arguments, in order:

1. The address of the local word initialized from the third argument.
2. The original object address.

The source establishes the call and argument order, but not the operation’s semantic result. An output-producing or in-place operation is a possible interpretation, not a guaranteed contract.

After that operation returns, the following dependency calls occur in order:

1. **F-b9acea4b06ad** receives the address of the first local word and the address of the third local word.
2. **F-289ec4311c64** receives the address of the third local word.
3. **F-44362605ab79** receives the address of the first local word. Its 32-bit result is retained as an address-like candidate value.
4. **F-d8cbf9aa79a9** receives the current contents of the second local word. Its result is interpreted as an unsigned 32-bit quantity.

F-d8cbf9aa79a9 is called even when the candidate value returned by F-44362605ab79 is zero. Candidate eligibility is tested only after both calls return.

The candidate value is retained across the call to F-d8cbf9aa79a9; it is not obtained again afterward. This retention does not establish that the storage it designates remains valid or unchanged.

### Eligibility and address calculation

Candidate bytes are examined only when:

- The retained candidate value is nonzero; and
- The unsigned measured quantity is greater than four.

Quantities zero through four therefore cause rejection without a candidate-byte read. Values with the high bit set satisfy the threshold; there is no visible upper-bound check.

For nonwrapping arithmetic, define the end position as the candidate base plus the measured quantity. All candidate-byte positions below are relative to that calculated end, not to a searched terminator.

The calculation uses 32-bit values. It must not be interpreted as an unbounded mathematical addition or as proof of valid pointer arithmetic. The contract does not establish safe behavior where address addition or subsequent backward offsets cross the representable address range.

### Byte acceptance condition

For valid, stable storage and nonwrapping addressing, acceptance requires all of the following:

- The byte at end minus one is `p` or `P`.
- The byte at end minus two is `4`.
- Either:
  - The byte at end minus three is lowercase `m`; or
  - The byte at end minus three is uppercase `M`, and the byte at end minus four is a period.

The lowercase branch does not inspect the byte at end minus four. A preceding period is therefore not required for lowercase `m`.

No earlier bytes are compared. There is no visible scan for a terminator, search for an earlier matching sequence, allocation-size check, or independent validation that the measured quantity belongs to the retained candidate.

### Candidate-read order

The supplied representation establishes this short-circuit evaluation order:

1. Read end minus one and compare with lowercase `p`.
2. If that comparison fails, read end minus one again and compare with uppercase `P`.
3. If either comparison succeeds, read end minus two and compare with `4`.
4. If that succeeds, read end minus three and compare with lowercase `m`.
5. If the lowercase comparison fails, read end minus three again and compare with uppercase `M`.
6. Only if the uppercase comparison succeeds, read end minus four and compare with a period.

A failed prerequisite prevents the later reads. In particular, the period position is not read on the successful lowercase-`m` branch.

The repeated reads describe the supplied expression-level behavior; they do not establish distinct physical memory transactions in an executable. No snapshot or synchronization mechanism is shown. Interpreting the result as a predicate over one fixed byte sequence requires storage that remains stable during evaluation.

### Finalization and return order

Every normally completing path after a nonzero gate calls F-289ec4311c64 with the address of the first local word.

- When the byte condition succeeds, that call occurs before returning one.
- When eligibility or any byte comparison fails, that call occurs before returning zero.

This final call occurs even when the candidate value is zero or the measured quantity is at most four. It is separate from the earlier call to F-289ec4311c64 with the third local word’s address.

Thus, a normally completing active path contains two calls to F-289ec4311c64, with different local addresses. A zero-gate path contains neither. No unwind or recovery path is shown for an interrupted execution.
