# F-853525b73c75

The established behavior is a memory-access protocol, not a recognizable application-level operation. The supplied representation does not establish a record type, device protocol, ownership scheme, or meaningful return value. ## Behavior

### Repeated write prefix

The prefix repeatedly accesses four destinations:

| Destination | Width | Value |
|---|---:|---|
| Base A plus `0x11` | Byte | Low byte of base B |
| Base B plus `0x34` | Word | Secondary input in the first group; doubled base A in subsequent groups |
| Twice base A plus `0x54` | Word | Primary input |
| Base B plus `0x19` | Byte | Low byte of base A |

Within each complete group, accesses occur in the table’s order. The prefix ends with an additional first-destination byte write followed by a second-destination word write containing doubled base A; the later behavior starts immediately afterward.

The repetitions are fixed in the supplied representation, not controlled by a visible input-dependent loop. The exact repetition count is **documented_only** in this contract.

The first write of the secondary input remains part of the observable access history even though subsequent groups write another value at that address. Similarly, each repeated write remains significant for aliasing, fault timing, or memory-mapped storage.

No memory reads are shown in this prefix. Its stored values come from incoming values and arithmetic.

### Initial snapshots and low-address updates

After the prefix, the function obtains a word from absolute address `0xA9`, then a word from primary input plus `0x74`. Both values are retained for later use.

It next writes one byte at absolute address `0x3A`. The byte is the low eight bits of twice the low byte of base A plus `0x30`. This is a byte arithmetic transformation; it is not established to produce a decimal character.

The next snapshots are a word from base C plus `0x14`, followed by a word from base A plus `0x04`.

The function then performs an ordered cluster of writes:

- Base C plus `0x0D` receives the low byte of base A.
- Base A plus `0x08` receives `0x6C`.
- Base A plus `0x0D`, followed by base A plus `0x09`, receives the low byte of base B.
- Base C plus `0x54` receives base C as a word.
- Absolute address `0x67` receives the low byte of the word previously read at `0xA9`.

The snapshots retain the values read at their respective read times. They are not implicitly refreshed if an intervening write overlaps their original locations.

### Shift-derived byte and overlapping fields

A word is read from base C plus `0x44`. Next, a byte is read from absolute address `0x67` and written to absolute address `0x21`.

Using the word just obtained from base C plus `0x44`, the function:

- Writes its low byte to base A plus `0x10`.
- Writes the full word to base B plus `0x54`.
- Writes a shift-derived byte to base C plus `0x01`.

The shift-derived byte comes from a signed right-shift expression whose count is the low eight bits of base A. For counts from 0 through 31 and nonnegative operands, the visible expression has an unambiguous ordinary interpretation. Negative operands and counts of 32 or greater require target-machine semantics; this contract does not assume count masking, saturation, or a portable signed-shift rule.

Base B plus `0x54` is then overwritten with base A as a word. This overwrite occurs after the shift-derived byte write.

A word is subsequently read from base A plus `0x40`. The earlier snapshot from base A plus `0x04` is written to base B plus `0x74`, and the newly read word is written to base A plus `0x10`.

This last write covers four bytes, offsets `0x10` through `0x13` relative to base A. It therefore overlaps the earlier byte write at offset `0x10` and the prefix byte destination at offset `0x11`.

Base B plus `0x44` then receives base C as a word. A fresh byte read from absolute address `0x67` supplies a write to base A plus `0x09`. Base C plus `0x09` receives the low byte of base A. Finally, base A plus `0x44` receives the original word snapshot from absolute address `0xA9`.

### First loaded destination

The function reads a word from base A plus `0x54` and uses it as a new address base, called **destination D** here.

Before using D, it again reads the byte at absolute address `0x67` and writes that byte to base A plus `0x09`. The two recent reads of `0x67` are separate accesses; they must not be assumed to return the same value when overlapping storage or external mutation is possible.

The low byte of the earlier word read from primary input plus `0x74` is written to destination D plus `0x0D`.

The earlier snapshot from base C plus `0x14` is then written as a word to base C plus `0x54`. This replaces the earlier self-address write at that location, subject to any intervening aliasing.

Next, the function reads a word from base A plus `0x14`. After that read:

- Base C plus `0x11` receives the same low byte previously written to D plus `0x0D`.
- Base A plus `0x09` receives the low byte of D.
- Base A plus `0x44` receives D as a word.

The word read from base A plus `0x14` remains available for a later byte write.

### Final loaded destinations and indirect invocation

The function reads a word from base C plus `0x04` and uses it as **destination E**.

It writes the halfword value `0x0065` at twice E. It then reads a word from E plus `0x64`; call this value **value V**.

The next writes are:

- The low byte of the snapshot from base A plus `0x14` to D plus `0x11`.
- The word value `100`, equivalent to `0x64`, to D plus `0x54`.

A word is then read from E plus `0x74`. This becomes the fourth argument of the indirect invocation.

Afterward, the function reads a word from base C plus `0x64` and uses it as **destination G**. Base C plus `0x09` receives the low byte of E. Destination G plus `0x54` receives V as a word. Finally, twice V receives G as a word.

Only after those writes does the unresolved indirect dependency receive these four arguments, in order:

| Position | Value |
|---|---|
| First | `0x72` |
| Second | V, as read from E plus `0x64` |
| Third | The earlier word snapshot from base C plus `0x14` |
| Fourth | The word read from E plus `0x74` |

## Acceptance examples

If that low byte is `0xF0`, the written byte is `0x10`, because only the low eight bits of twice `0xF0` plus `0x30` are retained. Neither case establishes a text-encoding purpose.

### Distinguishing the first prefix write

Assume all relevant destinations are disjoint and writable. Let the secondary input be `0x11223344`, and let doubled base A be `0x00002000`.

The shift-derived byte written at base C plus `0x01` is `0x1F`. This example does not resolve negative operands or large shift counts.

### Full-word overlap

The later word write to base A plus `0x10` replaces all four bytes in that range, including earlier byte stores at offsets `0x10` and `0x11`. Which byte occupies each address depends on endianness.

### Final argument capture
