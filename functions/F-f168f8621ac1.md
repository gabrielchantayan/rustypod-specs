# F-f168f8621ac1

The representation ends at an explicit bad-instruction boundary and contains a warning about invalid instruction data. Consequently, this contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred intent:** possible interpretations that are not required behavior.
- **documented_only unknowns:** matters that cannot be resolved from this material.

The strongest supported characterization is an ordered, externally dependent state transformation. There is no established basis for describing it as initialization, serialization, allocation, object construction, or a conventional collection operation.

All behavior below is conditional on execution reaching the relevant operation. No runtime tests have been performed.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial byte selection.** If the first selector read yields 7 and the inherited write-source value is `0x01400000`, the visible byte write targets numeric address 24 and stores 5. This assumes execution reaches the write with those values.

2. **Third-argument truncation.** Under 32-bit shift semantics, a third argument of 1 contributes `0x04000000` to its shifted call argument. A value of 64 contributes zero. The transformation therefore does not preserve all input bits.

3. **Masked byte extraction.** For a first bit source of `0x3AB00000`, masking to 30 bits and shifting right by 20 produces `0x3AB`; the byte write stores `0xAB`, not a wider field.

4. **Literal zero-selector path.** If the represented zero intermediate remains valid and memory at numeric address 1 contains 9, the zero-byte update writes at address 26. It does not write to address 1 itself.

5. **Split-result ordering.** For a represented 64-bit result with upper half 3 and lower half 5, the immediate zero-word store targets address 32. The later large-scale store targets `0x50000014` and stores `0x14000000`, under 32-bit unsigned arithmetic.

6. **Distinct scaled addresses.** If a returned value is 2, its scaled handle is 8. The corresponding 16-times destination is 52, while handle plus 20 is 28. A later read at 28 cannot be replaced with the value stored at 52.

7. **Fresh final selector.** If the first final selector read yields 4 and the second yields 8, the two byte writes target addresses 21 and 25. Reusing the earlier selector would violate the visible access sequence.

8. **Late failure.** If execution fails after an earlier word write, no restoration of that word is established. Acceptance must not require transactional behavior.
