# F-86e59aee734e

## Purpose

F-86e59aee734e performs an ordered, short-circuiting search over entries associated with a caller-supplied object. It constructs a temporary search operand from a caller-supplied 32-bit value, obtains entries in ascending index order, and passes each entry to a predicate-like dependency. It returns a 32-bit Boolean result: 1 on the first nonzero predicate result, or 0 when the captured iteration bound is exhausted.

This is a description of the supplied static evidence, not a claim about the application-level meaning of the search. The entry type, search-operand representation, and predicate semantics are unknown.

## Behavior

### 1. Prepare a local boundary value

The function first reads the signed 32-bit integer at the value address. It forms a local 32-bit value by adding one to that input.

This is a local value, not a write back to the caller’s integer. The visible body does not directly modify the caller’s integer.

The addition is an important width boundary. For input values from −2,147,483,648 through 2,147,483,646, the mathematical result fits in a signed 32-bit integer. For input 2,147,483,647, the mathematical result does not fit. The supplied representation does not establish whether that case wraps, traps, or has another language- or target-specific consequence. A behavioral contract must not silently choose one.

### 2. Initialize the search operand

The function provides a 16-byte local storage region to F-7167855775c3, together with:

1. The original value address.
2. The address of the local incremented value.

No initialization of that 16-byte storage is visible before the call. F-7167855775c3’s return value, if any, is not consumed.

The incremented value is computed before this call, but the original input is passed by address rather than as a copied scalar. Consequently, the dependency receives both a previously computed local value and access to the caller’s current storage. It is not established that these form a range, that either address is read-only, or that the dependency preserves other reachable state.

Search-operand initialization happens even when the object’s eventual iteration bound is zero or negative.

### 3. Capture the iteration bound

After F-7167855775c3 returns, the function reads a signed 32-bit value at object byte offset 12. It retains that value as the bound for the entire search.

This ordering is observable: initialization precedes the bound read. If initialization changes the object’s bound through aliasing or another side effect, the subsequent read observes the resulting value, subject to the target’s execution rules.

The function does not reread the bound during iteration. Changes made to the object’s bound by later dependencies therefore do not change the number of indices allowed by this captured bound.

### 4. Visit eligible indices in ascending order

Iteration starts at signed 32-bit index zero.

Before each possible visit, the function compares the current index with the captured bound using signed ordering. If the bound is less than or equal to the index, it immediately returns 0.

Consequences:

- A bound of zero causes no entry visits.
- A negative bound also causes no entry visits.
- A positive bound permits indices from zero through one less than the bound, unless an earlier predicate call succeeds.
- The bound is a stopping criterion, not evidence that the underlying entry storage actually contains that many valid entries.

For each eligible index, the following call order is established:

1. **Entry acquisition:** Call F-8966abe1b944 with the address at object offset 8 and the current index. Retain its 32-bit return value as an opaque entry token.
2. **Per-visit preparation:** Call F-86442406562f with a second 16-byte local storage region.
3. **Predicate evaluation:** Call F-50b504e2c17e with the entry token, the search-operand storage from the initial call, and the per-visit storage.

No direct initialization of the per-visit storage is visible before its first use by F-86442406562f. The same storage region is passed again on later visits. No intervening clearing or cleanup is visible.

F-86442406562f’s return value, if any, is not consumed. The entry token is passed onward without a visible null, range, or validity check.

### 5. Stop on nonzero; otherwise advance

If F-50b504e2c17e returns a nonzero signed 32-bit result, the function returns 1 immediately. There are no later entry acquisitions or per-visit preparation calls on that execution path.

If the predicate result is zero, the index increases by one and the bound check repeats.

The loop’s index increment does not itself require signed overflow under the visible control flow. For the largest positive signed 32-bit bound, the last eligible index is 2,147,483,646. Advancing after a zero result produces 2,147,483,647, at which point the next bound check terminates the loop. ## Acceptance examples

These examples are conditional contracts, not reported executions. They assume valid memory, defined arithmetic, and normally returning dependencies.

### Zero bound

- F-7167855775c3 has already been called.
- No entry acquisition, per-visit preparation, or predicate evaluation occurs.
- The result is 0.

### Negative bound

Given a captured bound of −1, the signed bound check terminates at initial index zero. Initialization still precedes that check. The result is 0.

### Immediate success

Given a positive captured bound and a nonzero predicate result for index zero:

- Exactly one entry acquisition occurs, for index zero.
- One per-visit preparation follows it.
- One predicate evaluation follows preparation.
- The result is 1, regardless of whether the predicate returned 1, −1, or another nonzero value.

- Index three is not acquired.
- The result is 1.
