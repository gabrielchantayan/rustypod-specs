# F-5629f8ce6df1

## Purpose

F-5629f8ce6df1 maps input bytes to an unsigned 32-bit result through one of two paths selected by an external classification table:

- An arithmetic path accumulates input bytes using a decimal-like recurrence.
- A lookup path examines at most seven candidates and returns one selected unsigned byte.

The arithmetic path is not conventional decimal parsing. Its continuation condition accepts every byte from `0x00` through `0x39`, inclusive. A leading minus byte selects a negative multiplier but is also accumulated. A zero byte does not terminate accumulation.

The lookup path returns `1` after seven rejected candidates. This is not a distinct error value: an accepted result byte or the arithmetic path can also produce `1`.

This contract distinguishes established static behavior, conditional arithmetic interpretations, inferred intent, and unresolved dependency behavior. No runtime tests have been performed.

## Interface

### Input

The function accepts one pointer to unsigned 8-bit input elements. It receives no length, output buffer, or caller-owned traversal pointer.

There is no explicit null-pointer check or bounds check. Required readable storage depends on the selected path:

- Classification reads the first input byte and an external classification-table entry.
- Arithmetic accumulation reads each examined byte, including the stopping byte. An accepted position is read separately for its continuation condition and its update.
- Lookup passes the original input pointer to F-abcb7c332db0. That dependency’s access requirements are unknown.

A zero-terminated input is not sufficient to guarantee arithmetic termination. Zero satisfies the continuation condition, so execution may continue beyond it.

### Output

The return value is unsigned 32-bit.

| Outcome | Return |
|---|---|
| Arithmetic termination | The final signed multiplication result converted to unsigned 32-bit, subject to the arithmetic qualifications below |
| Lookup acceptance | One selected unsigned byte, zero-extended to 32 bits |
| Seven rejected candidates | `1` |

There is no consumed-length result, returned end pointer, separate status channel, or error object.

### Widths and external storage

The supplied representation uses:

- Unsigned 8-bit input, filter, descriptor-offset, and result bytes.
- Signed 32-bit arithmetic accumulator, multiplier, cached lookup bases, and comparison result.
- Unsigned 32-bit lookup token and candidate index.
- A signed 32-bit cell containing the classification-table address representation.

External globals supply the candidate-table, descriptor-region, and result-table bases. Their declarations, allocation bounds, initialization, ownership, and lifetimes are absent.

Several address calculations have established unsigned 32-bit arithmetic because their operands include both a cached signed 32-bit value and an unsigned 32-bit value. These are:

- Classification-table indexing.
- Candidate-filter indexing.
- Descriptor-offset indexing.
- Descriptor-address construction.

Those integer additions operate modulo \(2^{32}\), before any integer-to-pointer conversion.

Two other calculations require separate qualification:

- The candidate-base-minus-seven calculation operates directly on an external global before its result is stored in a signed 32-bit cache. The omitted global declaration prevents establishing its arithmetic type and conversion behavior.
- Successful result selection adds the unsigned index directly to the result-base global, without first caching that global in a signed 32-bit value. The index alone does not establish unsigned 32-bit addition. A wider integer global could widen the operation; a pointer global could introduce pointer arithmetic and element scaling.

### Preconditions

Defined, non-faulting execution requires valid storage for every actual access and valid arguments for every dependency call.

Signed arithmetic must remain representable. Any implementation-dependent conversions encountered must permit continued execution. Integer-to-pointer conversions, pointer arithmetic where applicable, and the validity of resulting addresses depend on the target environment.

A defined modulo integer calculation does not itself make the resulting pointer valid. No storage lifetime or ownership guarantee follows merely from passing a pointer to a dependency.

## Behavior

### Classification and path selection

F-2a4c402ba617 is called once, without explicit arguments, before classification-related reads.

Its result is interpreted as a pointer to a signed 32-bit address-bearing cell. Classification reads that cell and the first unsigned input byte. The supplied representation does not establish an evaluation order between these two reads.

For the classification address, the signed cell value is converted to unsigned 32-bit and added to the input byte. The addition wraps modulo \(2^{32}\). The resulting integer is converted to a pointer, and one character-sized table entry is read.

An entry equal to `0x20` selects arithmetic accumulation. Every other entry selects lookup. This compares the classification-table entry with `0x20`; it does not directly test whether the input is a space.

For example, a cell representing `0xFFFFFFF0` and an input byte of `0x30` produce classification address integer `0x00000020`. Whether that integer maps to readable storage remains unresolved.

### Arithmetic initialization and continuation

The accumulator begins at zero. A fresh read of the first input byte selects the multiplier:

- `−1` if that read is `0x2D`.
- `+1` otherwise.

Sign selection does not advance the input position.

Each continuation condition subtracts 48 from the current unsigned byte after promotion to signed 32-bit and tests whether the result is less than ten. The subtraction is representable for every possible input byte.

Consequently, the accepted range is `0x00` through `0x39`, inclusive.

| Byte | Accepted? | Mathematical contribution before accumulation |
|---|---:|---:|
| Zero, `0x00` | Yes | `−48` |
| Space, `0x20` | Yes | `−16` |
| Plus, `0x2B` | Yes | `−5` |
| Minus, `0x2D` | Yes | `−3` |
| Digits, `0x30`–`0x39` | Yes | `0`–`9` |
| Colon, `0x3A` | No | Not accumulated |
| Any higher byte | No | Not accumulated |

There is no whitespace skipping, conventional sign consumption, or special handling of zero.

The continuation condition and accumulator update read the current byte separately. If the input changes between those reads under otherwise valid execution conditions, the update byte need not satisfy the condition that admitted the iteration.

After each completed update, the local input position advances by one byte. The first failing byte is inspected but not accumulated or advanced past. The caller receives no updated pointer.

### Arithmetic update and return

Each accumulator update combines distinct arithmetic stages:

1. Multiplication of the signed accumulator by ten uses signed 32-bit arithmetic.
2. The update byte is explicitly converted to unsigned 32-bit. Adding it to the multiplication result therefore converts that result to unsigned 32-bit.
3. Subtraction of 48 is unsigned 32-bit arithmetic.
4. The unsigned result is converted back to the signed 32-bit accumulator.

Provided the signed multiplication is representable, the unsigned intermediate is

\[
U=\bigl((10a\bmod 2^{32})+b-48\bigr)\bmod 2^{32},
\]

where \(a\) is the previous signed accumulator and \(b\) is the separately read unsigned update byte.

This formula describes the unsigned stage. It does not authorize wrapping the preceding signed multiplication.

If \(U\) is at most `2147483647`, assignment to the accumulator is exact. For larger values, the unsigned-to-signed conversion is implementation-defined under the represented arithmetic semantics; an implementation-defined signal is also possible.

A mathematically negative update is therefore not established merely because its magnitude fits signed 32-bit. For example, the first update for a minus byte produces unsigned intermediate `4294967293`. Obtaining signed `−3` requires a particular conversion rule.

On termination, the signed accumulator is multiplied by the selected signed multiplier. This multiplication must also be representable. In particular, multiplying `−2147483648` by `−1` overflows. A representable signed result is then converted to unsigned 32-bit modulo \(2^{32}\).

No saturation, explicit overflow rejection, arbitrary-precision calculation, or conversion fallback is visible.

### Lookup preparation

If classification selects lookup, F-1cb585febd84 is called once without explicit arguments. Its return is retained as an unsigned 32-bit token. The token’s meaning is unknown.

External bases are then sampled in this order:

1. Descriptor-region base, retained in a signed 32-bit cache.
2. Candidate-table base, retained in a signed 32-bit cache for filter access.
3. Candidate-table base again, used to form a separate signed 32-bit cache for descriptor-offset access by subtracting seven before storage.

The two candidate-base reads are distinct. With stable compatible state, they may describe a candidate region and a preceding seven-byte offset region. Stability is not enforced.

The omitted declaration of the candidate-base global prevents establishing the arithmetic used for subtraction by seven. Depending on that declaration, integer width, signed overflow, conversion into the cache, or pointer arithmetic may matter. Later unsigned indexing does not resolve this earlier calculation.

The candidate index begins at zero.

### Candidate examination

Candidates are considered in ascending order, zero through six.

For each candidate, one unsigned filter byte is read first. Its address integer is the cached candidate base converted to unsigned 32-bit, plus the unsigned index, modulo \(2^{32}\).

The filter byte is compared with the full unsigned 32-bit token. The token is not truncated to eight bits.

If they differ, the candidate is rejected immediately. Its descriptor-offset byte is not read, and F-abcb7c332db0 is not called for that candidate.

If they are equal:

- One unsigned descriptor-offset byte is read using the separately cached offset-region base plus the index, modulo \(2^{32}\).
- That offset, ranging from zero through 255, is added to the cached descriptor-region base using unsigned 32-bit arithmetic.
- F-abcb7c332db0 is called with the resulting 32-bit descriptor address value, the original input pointer, and the unchanged token.

For example, a cached descriptor base representing `0xFFFFFFF0` and an offset of `0x30` produce descriptor address value `0x00000020`.

A zero dependency return accepts the candidate. Any nonzero return rejects it. Rejection advances the index. After rejection of candidate six, the function returns `1` without examining an eighth candidate.

If the token exceeds 255, no filter byte can equal it. Subject to valid preparation and accesses, all seven filter bytes are read, no descriptor-offset bytes are read, no comparison calls occur, and the return is `1`.

### Successful lookup return

The first accepted candidate wins. No later candidate is inspected.

Only after acceptance does the function read the result-base global and combine it with the selected unsigned index. The resulting address is used to read one unsigned byte, which is returned zero-extended to 32 bits.

The arithmetic and address mapping of this combination are **documented_only** because the result-base global’s declaration is absent:

- A compatible 32-bit integer declaration can yield modulo-\(2^{32}\) addition.
- A wider integer declaration can produce a wider addition.
- A pointer declaration can produce pointer arithmetic with scaling determined by its pointed-to type.

The supplied representation therefore does not establish that result entry \(n\) is always located exactly \(n\) bytes after a numeric base, or that the result address always wraps at \(2^{32}\).

The late global read is established independently of this uncertainty. A comparison dependency can change the result-base global before it is read. Candidate and descriptor bases remain cached, but the contents reached through those caches are not snapshotted.

## Side effects

### Direct effects and ordering

No direct stores to input, global memory, or caller-supplied output storage are visible. Local state changes include accumulation, multiplier selection, local pointer traversal, cached bases, and candidate advancement.

Established sequencing includes:

- F-2a4c402ba617 before classification reads.
- Classification before either selected path.
- Sign selection before the first arithmetic continuation check.
- Each accepted continuation check before its separate update-byte read.
- F-1cb585febd84 before lookup-base sampling.
- Candidate filtering before that candidate’s descriptor-offset read and comparison call.
- Successful comparison before the result-base global and result byte are read.

No synchronization is supplied. Concurrent mutation is not guaranteed to have defined or repeatable behavior. Dependency-mediated changes between sequenced operations can affect subsequent reads.

### Dependency effects and ownership

Dependency implementations are unavailable. None is assumed pure, preserving of globals, or non-owning.

The token and cached candidate and descriptor bases are not refreshed after comparison calls. A dependency may nevertheless modify memory reached through those cached values, affecting later candidate processing.

No allocation or release operation is directly visible. This does not establish that dependencies allocate nothing, release nothing, retain no pointers, or preserve the validity of referenced storage.

### Errors

There is no explicit handling for invalid pointers, inaccessible storage, arithmetic overflow, conversion signals, or dependency failures.

A nonzero comparison return is treated solely as candidate rejection. It is not propagated as a separate error. The fallback `1` is indistinguishable from a successful result of `1`.

## Acceptance examples

These are conditional static examples, not executed tests. Unless further qualified, memory is stable, required accesses and pointer conversions are valid, dependencies return normally, and lookup preparation completes without arithmetic or conversion failure.

1. **Ordinary digits.** If classification selects arithmetic for `123:`, the accumulator becomes `1`, `12`, and `123`. Colon terminates accumulation. The return is `123`.

2. **Immediate termination.** If classification selects arithmetic for input beginning with `A`, no accumulator update occurs. The return is `0`.

3. **Accumulated minus.** Assume every out-of-range unsigned-to-signed accumulator conversion maps \(U\) to \(U-2^{32}\), without signaling. Arithmetic input `-12:` produces accumulators `−3`, `−29`, and `−288`. The multiplier is `−1`, so the return is `288`.

4. **Accumulated plus.** Under the same conversion assumption, arithmetic input `+1:` produces `−5`, then `−49`. The multiplier remains `+1`; the unsigned return is `4294967247`.

5. **Zero is accepted.** Under that conversion assumption, arithmetic bytes `1`, zero, then colon produce accumulators `1` and `−38`, returning `4294967258`. Independently of the conversion rule, zero passes the continuation condition.

6. **Small negative result still requires a conversion rule.** For arithmetic input consisting of minus followed by colon, the first unsigned intermediate is `4294967293`. The representation alone does not establish assignment of signed `−3` or an exact final return.

7. **Filter short-circuit.** If candidate zero’s filter differs from the token, its descriptor-offset byte is not read and no comparison call occurs for it.

8. **First acceptance.** If candidates zero and one reject and candidate two’s comparison returns zero, the selected byte for index two is returned. Candidates three through six are not examined. Its exact address depends on the result-base declaration and value.

9. **Wide token.** For token `256`, all seven filter comparisons fail. No descriptor-offset reads or comparison calls occur. The return is `1`.

10. **Conditional result-address wrapping.** Assume explicitly that the result-base global is an unsigned 32-bit integer and that its addition with the index uses unsigned 32-bit arithmetic. If candidate two accepts and the late-read global value is `0xFFFFFFFF`, the resulting address integer is `0x00000001`. The return is the unsigned byte at its valid pointer mapping. Without that type and arithmetic assumption, this exact address is unresolved.

11. **Late result-base observation.** If an accepting comparison changes the result-base global before returning, the subsequent result selection reads the changed global, not a pre-comparison cached value. Address formation still depends on its omitted declaration.

12. **Ambiguous fallback.** Seven rejected candidates return `1`. An accepted result byte of `1` returns the same value.
