# F-2b86bf938ef5

## Purpose

F-2b86bf938ef5 initializes a destination’s leading 17 bytes using one 32-bit value from fixed storage and selected fields from a source region.

The destination receives:

- A 32-bit value obtained from fixed storage at call time.
- Three 32-bit values read from source offsets 4, 8, and 12.
- One byte read from source offset 16.

The source’s first four bytes are not explicitly read. The operation is a sequence of field transfers, not an established whole-object copy or snapshot. Overlapping storage can therefore change which values later transfers observe.

**Established behavior:** the field widths, offsets, and transfer order described below.

**Inferred intent:** initialization of a compact record with a fixed-storage header and a copied payload.

**Not established:** the record’s type, the header’s meaning, or whether the byte at offset 16 represents a flag, count, character, or other value.

## Behavior

### Ordered transfers

The established sequence consists of five transfers:

1. Read the four-byte value from fixed storage and write it to destination offsets 0–3.
2. Read four bytes at source offset 4 and write the resulting 32-bit value to destination offsets 4–7.
3. Read four bytes at source offset 8 and write the resulting 32-bit value to destination offsets 8–11.
4. Read four bytes at source offset 12 and write the resulting 32-bit value to destination offsets 12–15.
5. Read one byte at source offset 16 and write it to destination offset 16.

Each transfer uses the value read for that transfer. The source fields are not all captured before destination modification begins. Earlier writes therefore matter when they overlap locations read later.

This is the order established by the supplied representation. It does not independently establish hardware transaction boundaries, atomicity, or observations available to concurrent threads or devices.

The source’s leading four bytes do not contribute to the result.

### Overlapping storage

The operation must not be specified as though it first snapshots the source or guarantees overlap-safe copying.

If an earlier destination write changes a location used by a later source read, that later transfer observes the changed value under ordinary sequential memory semantics. Consequently, the resulting payload can differ from the source payload as it existed at entry.

When destination and source have the same base address, the first transfer replaces their shared leading four bytes. The remaining transfers read and write corresponding locations at offsets 4, 8, 12, and 16. For ordinary stable memory and valid accesses, these later transfers leave their respective values unchanged. They remain explicit accesses rather than a demonstrated no-op optimization.

The fixed-storage location may also matter to aliasing. Its value is read for the first transfer; there is no later explicit reread. If a destination write aliases that location, it can modify the fixed storage and thereby affect a subsequent call. Whether such aliasing is possible is not established.
