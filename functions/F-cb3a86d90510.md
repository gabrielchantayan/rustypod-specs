# F-cb3a86d90510

## Purpose

F-cb3a86d90510 performs a bounded, two-stage lookup.

It first searches an ordered primary table for a record whose unsigned 16-bit identifier equals the supplied unsigned argument. For the first matching primary record, it searches an ordered secondary table for a signed 16-bit key equal to that primary record’s signed 16-bit association value. A successful lookup returns the secondary entry’s signed 16-bit result, widened to the function’s signed return type.

The function returns the distinguished value **2,147,483,647** if either search fails. Once a primary record matches, failure in the secondary search ends the operation; later primary records are not considered.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

### Input

The function accepts one unsigned integer argument, treated by the supplied representation as **32 bits**.

The argument is compared directly against unsigned 16-bit identifiers read from the primary table. There is no visible truncation of the argument to 16 bits. Consequently:

- Arguments from 0 through 65,535 can match a primary identifier.
- Arguments from 65,536 through 4,294,967,295 cannot match any primary identifier.
- An out-of-range argument still causes the bounded primary search; there is no visible range-check shortcut.

### Return value

The return type is a signed integer, treated here as **32 bits**.

The possible normal results are:

| Outcome | Result |
|---|---:|
| Both stages find a match | Signed 16-bit secondary result, widened without changing its mathematical value |
| No primary identifier matches | 2,147,483,647 |
| A primary identifier matches, but no secondary key matches its association value | 2,147,483,647 |

Successful results lie between **−32,768 and 32,767**, inclusive. The failure sentinel is therefore distinguishable from every successful result.

There is no separate status output, output buffer, or explicit error-detail channel.

## Behavior

### Primary search

The function examines primary records in ascending order, starting with the first record and stopping after at most 205 records.

For each visited record, it reads the unsigned 16-bit identifier at offset 10 and compares it against the full unsigned argument. This comparison does not reinterpret the identifier as signed: an identifier with the high bit set remains a value between 32,768 and 65,535.

A nonmatching identifier advances the search to the next record. The first matching identifier selects that record and immediately begins the secondary search.

If all 205 primary identifiers fail to match, the function returns the failure sentinel. In this case, it performs no visible secondary-table reads and does not read any primary association field.

### Secondary search

After selecting a primary record, the function examines secondary entries in ascending order, starting with the first entry and stopping after at most 32 entries.

For each candidate secondary entry, it compares:

- The signed 16-bit key at offset 2 of that secondary entry.
- The signed 16-bit association value at offset 16 of the selected primary record.

The supplied representation places both reads within the repeated comparison. It does **not** show the primary association value being captured once before the secondary search. Thus, the represented operation obtains the selected primary association value for each attempted secondary comparison.

The two operands of a single comparison have no established relative evaluation order in the supplied representation. This contract therefore does not promise that the secondary key is read before the primary association value, or vice versa.

If a comparison succeeds, the function reads the signed 16-bit result at offset 0 of that same secondary entry and returns its widened value immediately. It does not inspect subsequent secondary entries or resume the primary search.

If all 32 comparisons fail, the function returns the failure sentinel immediately.

### Duplicate handling

The lookup is ordered rather than set-based.

- If multiple primary records have the requested identifier, only the **first** matching record participates.
- If multiple secondary entries match the selected primary association value, the **first** matching entry supplies the result.
- A failed secondary search for the first matching primary record is final, even if a later primary record with the same identifier would have produced a successful result.

These precedence rules are part of the observable behavior.

## Acceptance examples

The following are conditional acceptance examples, not executed test results. They assume the stated widths, valid addresses, and stable table contents.

### Direct success

Suppose the argument is 42. The first primary record with identifier 42 has association value −7. The earliest secondary entry with key −7 has result 123.

The function returns **123**. Earlier secondary entries are compared; later entries are not visited.

### Signed result preservation

Suppose the selected association value matches a secondary entry whose result is −32,768.

The return value is **−32,768**, not 32,768 and not the failure sentinel.

Likewise, a result of −1 returns **−1**, while a result of 32,767 returns **32,767**.

### Unsigned primary identifier

Suppose the argument is 65,535 and a primary identifier contains the unsigned 16-bit value 65,535.

That identifier can match. Its bit pattern must not be treated as a primary identifier of −1.

By contrast, an argument of 4,294,967,295 does not match it. The argument is not narrowed to its low 16 bits.

### No primary match

Suppose none of the 205 primary identifiers equals the argument.

The function returns **2,147,483,647** after examining all primary identifiers. No secondary key, secondary result, or primary association field is read by the represented search.

### First primary match prevents fallback

Suppose two primary records have identifier 9. The earlier record’s association value has no secondary match. The later record’s association value would match a secondary entry.

The function returns **2,147,483,647**. It does not try the later primary record.

### First secondary match wins

Suppose the selected association value is 5. Two secondary entries have key 5; the earlier one has result −10 and the later one has result 20.

The function returns **−10**. The later matching entry cannot override it.

### Final entries remain eligible

Suppose only the last primary record matches, and only the last secondary entry matches its association value.

The function returns that last secondary entry’s signed result. Both bounds are inclusive of their final valid entry.

### Zero is not a terminator

Suppose an early primary identifier is zero, but the requested identifier occurs later.

The zero identifier does not terminate the search. Similarly, a secondary key of zero is an ordinary comparison value, not an end marker.
