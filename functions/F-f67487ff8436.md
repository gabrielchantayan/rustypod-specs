# F-f67487ff8436

## Purpose

F-f67487ff8436 selects a pointer by processing an initial object and, if necessary, a secondary object. Before selection, it conditionally performs three clearing stores and invokes two dependencies associated with shared state.

The established selection rule is:

- Process the initial object through F-79fb23590966.
- If the resulting candidate differs from the initial object’s sentinel, return the candidate address plus 20 bytes.
- Otherwise, resolve and process a secondary object.
- If the secondary candidate differs from that object’s sentinel, return the candidate address plus 20 bytes.
- If both comparisons match, return the shared fallback pointer loaded at the terminal branch.

“Object,” “candidate,” “sentinel,” “initialization,” and “fallback” describe observed roles, not established application types. The evidence does not establish that an object is a container or that the returned pointer identifies a particular data structure.

## Behavior

### Temporary initialization

Before any dependency call, the function initializes the first temporary word from the initial candidate and the second temporary word from the auxiliary initial value.

The auxiliary initial value is not supplied as a separate dependency argument. Its possible visibility through adjacent storage is unresolved. After the first processing call, the second word is overwritten with the first word’s then-current value.

### Conditional shared-state work

The function reads the global pointer identifying the flag-bearing object, then reads the 32-bit flag at offset 12.

If bit 0 is set, the entire conditional initialization sequence is skipped. There is no call to F-b255b26284e6 and no fallback-pointer capture for this sequence.

If bit 0 is clear, the following ordering is established:

1. Read the global context value and call F-b255b26284e6 with it.
2. After that call returns, read the shared fallback pointer and capture its value.
3. Use the probe’s zero/nonzero result to determine whether clearing and initialization proceed.

The fallback-pointer capture occurs even when the probe returns zero. In that case, the conditional sequence performs no clearing stores and calls neither F-804adc29bbfb nor F-d08d3ca17b81. The pointer capture itself does not dereference the captured region.

For a nonzero probe result, the sequence continues:

1. Read the shared fallback pointer again, separately from the earlier capture, and write a 32-bit zero at offset 0 through this newly read pointer.
2. Write a 32-bit zero at offset 4 through the captured pointer.
3. Write a 32-bit zero at offset 8 through the captured pointer.
4. Call F-804adc29bbfb with the captured pointer, a first global initialization value, and a second global initialization value, in that argument order.
5. Read the global context value again and call F-d08d3ca17b81 with that value.

Thus, the first clearing store is not explicitly addressed through the captured pointer. Only the stores at offsets 4 and 8, and the first argument to F-804adc29bbfb, explicitly use that capture.

If the relevant fallback-pointer reads produce the same address, the stores clear three consecutive words in one region. The contract does not assume that equality: if the reads differ, the first store targets a different base from the remaining two stores. No synchronization, atomicity, or global-stability guarantee follows from this access pattern.

The three stores occur in the stated order, before F-804adc29bbfb, which precedes F-d08d3ca17b81. The relative evaluation order of the two global initialization-value reads is not independently established.

The later context read is distinct from the read used for F-b255b26284e6. Dependencies are not assumed to preserve the context or any other global value.

A nonzero probe result selects the branch; it does not establish successful initialization. No result from the following two calls is tested.

### Initial-object processing

After the optional shared-state sequence, the function calls F-79fb23590966 with:

- The first temporary word’s address;
- The initial object address plus 120 bytes;
- The unchanged lookup argument.

Its return value is not used for selection. Instead, the function uses the first temporary word after the call.

It copies that candidate into the second temporary word, then compares the candidate against the 32-bit sentinel read at initial-object offset 136. This sentinel read occurs after the processing call and after any conditional clearing or initialization.

If the values differ, the function returns the candidate plus 20 bytes. It does not obtain a provider object or resolve a secondary object.

### Secondary-object resolution

If the first candidate equals the initial object’s post-call sentinel:

1. Call F-17fe47085641.
2. Read the dispatch-table address through its returned object.
3. Read the callable target at dispatch-table offset 204.
4. Invoke that target.
5. Pass its represented 32-bit result and a literal zero to F-682adfd5a561.

The indirect call has no explicit argument list in the supplied representation. Its full signature, calling convention, and any implicit receiver handling remain unknown.

If F-682adfd5a561 returns zero, call F-a817d8d58c10. The supplied representation identifies that dependency as non-returning. No normal result is established for this path.

### Secondary-object processing

If secondary resolution returns a nonzero object address, call F-79fb23590966 with:

- The same first temporary word’s address;
- The secondary object address plus 120 bytes;
- The unchanged lookup argument.

There is no explicit reset of the first temporary between processing calls. The first call left it equal to the initial sentinel at the time of comparison. Any intervening dependency mutation through accessible storage remains subject to unknown dependency contracts.

After the second processing call, read the secondary object’s 32-bit sentinel at offset 136 and compare it with the candidate:

- If they differ, return the candidate plus 20 bytes.
- If they match, read and return the shared fallback pointer without adjustment.

This terminal fallback read is separate from both fallback-pointer reads associated with initialization. It need not produce the region used by either clearing destination.

### Arithmetic and boundary behavior

The offsets 120, 136, 204, and 20 are byte displacements. The clearing stores are 32 bits wide; their offsets are 0, 4, and 8.

No candidate validation precedes the final 20-byte adjustment. A zero candidate that differs from the applicable sentinel selects address 20 rather than an explicit error.

The supplied representation uses 32-bit integer and word values and address-related quantities consistent with that representation. It does not independently establish portable signed-overflow behavior or the complete machine addressing model. Callers must not infer usable wrapped addresses from unchecked additions.

## Side effects

### Direct accesses

The function directly initializes and updates temporary words, reads global values and object fields, conditionally performs three 32-bit zero stores, and invokes dependencies.

No explicit allocation or release operation is shown.

There are no direct stores whose addresses are formed from the initial-object or secondary-object arguments. This is an addressing-based observation, not an object-preservation guarantee. The clearing destinations are not established to be disjoint from either object, global storage, or other relevant memory. A clearing store could therefore affect an object field or later access if those locations alias.

Even on the nonzero initialization branch, the three stores are not necessarily writes to three consecutive words of a single region. That description requires the captured fallback pointer and the separate first-store pointer read to agree.

## Acceptance examples

These are conditional static expectations, not executed tests. Assume valid accessed storage and normally returning dependencies except where stated. Unspecified mutations must not be assumed absent unless an example explicitly fixes the relevant values.

1. **Flag bypass.**  
   If flag bit 0 is set, the probe, initialization-related fallback capture, clearing stores, and both initialization calls are skipped. Initial-object processing still occurs.

2. **Zero probe still captures the pointer.**  
   If flag bit 0 is clear and F-b255b26284e6 returns zero, the function subsequently reads and captures the fallback pointer. It performs no clearing stores and calls neither F-804adc29bbfb nor F-d08d3ca17b81. It does not dereference the captured region merely because of this capture.

3. **Equal clearing bases.**  
   If the probe is nonzero and both relevant fallback-pointer reads yield the same region, its words at offsets 0, 4, and 8 receive zero in that order. The initialization call receives that region. Later contents depend on subsequent effects.

4. **Different clearing bases.**

F-804adc29bbfb receives A. This example preserves the distinct accesses without asserting that such a change occurs in a particular runtime.

5. **Initial candidate selected.**  
   If the first processing call leaves candidate 4096 and the subsequent initial sentinel read differs, return address 4116. No secondary-provider calls occur.

6. **Secondary candidate selected.**  
   If the first comparison matches, secondary resolution returns a valid nonzero object, and the second processing call leaves candidate 8192 unequal to the subsequent secondary sentinel, return address 8212.

8. **Secondary resolution fails.**

9. **Zero candidate is not rejected.**
