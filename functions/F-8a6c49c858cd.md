# F-8a6c49c858cd

## Behavior

### Status preparation and gating

When the reset selector is nonzero, the function reads the primary status byte, clears bit `0x04`, and writes the resulting byte back. All other bits are preserved. This write occurs even when `0x04` was already clear.

The function then reads the status byte used for gating and for a later dependency argument.

Processing proceeds only when both `0x04` and `0x08` are clear in that captured byte. If either bit is set, the function returns 0 without calling any visible dependency.

Consequences:

- Reset can remove a block caused solely by `0x04`.
- Reset does not remove a block caused by `0x08`.
- Other status bits do not independently block entry.
- The reset write, when requested, occurs before a possible gate rejection.

The primary-object nonnull check occurs after the status access. It does not make an ordinary null input safe.

### Eligibility

After the status gate passes, a nonzero primary-object reference causes the function to read the reference at offset `0x40`, then the unsigned 16-bit field at offset `0x2E` in that associated object.

A zero eligibility field causes return 0. A nonzero field permits the attempt-state updates.

The request input is not this eligibility field. In particular, a request value of zero does not independently reject an otherwise eligible nonnull object.

The representation includes a path that retains the request value when the primary reference is zero, but the subsequent nonnull requirement still prevents the attempt. That structure does not establish a safe null-input case because the earlier status access remains.

### Attempt-state updates

1. Writes the captured status byte with `0x04` set.
2. Reads the 32-bit field at `0x188`, adds one, and writes the result to that field.

The status write uses the previously captured byte, rather than a fresh status-byte read.

No overflow check, saturation, or special error result accompanies the increment. The accessed field is 32 bits, but the source representation expresses signed addition. ### Positional traversal

A nonzero dependency result is treated as an object reference. Traversal begins at unsigned 32-bit position zero.

At each condition check, the function reads the returned object’s unsigned 32-bit count at `0x0C`. If the current position is below that count, it reads the 32-bit entry reference from the corresponding four-byte table slot beginning at `0x10`.

- A zero entry reference causes no entry write.
- A nonzero entry reference receives the current position as a 32-bit write at offset `0x24`.

The position advances after each processed slot, including null slots. Null entries therefore leave gaps in the values assigned to other entries; the table is not compacted.

The count is not visibly captured once for the entire traversal. A write that aliases the count or a future table slot can affect subsequent traversal. No non-aliasing guarantee is supplied.

Duplicate entry references are not filtered. With a stable table and no other interference, repeated references to one index field receive successive writes, and the last encountered position remains.

For an ordinary stable, accessible table, traversal stops when the position reaches the count. There is no explicit maximum-count rejection, storage-bound check, or address-overflow check.
