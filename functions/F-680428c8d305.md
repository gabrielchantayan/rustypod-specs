# F-680428c8d305

## Purpose

F-680428c8d305 obtains a 16-bit discriminator from an opaque dependency and, for either of two discriminator values, obtains an additional 32-bit value from a second dependency. It reports a 32-bit status separately from the discriminator and additional value.

The established behavior is a two-stage operation:

- Initialize both caller-provided output locations to zero.
- Invoke F-8f49ed59b67e to obtain a discriminator and update a working status.
- If that status is zero, optionally invoke F-c5640ca5b487 for discriminators `0x8001` and `0x8002`, then publish the discriminator.
- Return the working status.

Interpreting these values as a tag and associated payload is useful descriptive terminology, not an established domain meaning. The supplied evidence does not identify the underlying format, resource, protocol, or object type.

## Interface

### Inputs and outputs

The function has four arguments and a status return:

| Position | Role | Width and interpretation |
|---|---|---|
| First | Opaque input passed to dependencies | One 32-bit value. Its representation and meaning are unknown. |
| Second | Discriminator output location | Address of writable storage for one unsigned 16-bit value. |
| Third | Additional-value output location | Address of writable storage for one opaque 32-bit value. |
| Fourth | Initial working status | One 32-bit integer value, copied into function-local status storage. |
| Return | Final working status | One 32-bit integer value. Zero controls continuation; every nonzero value prevents the corresponding success path. |

These widths follow the supplied source model: the discriminator is an unsigned 16-bit quantity, opaque four-byte values are 32 bits, and integer status and arithmetic use the source model’s 32-bit integer representation. The evidence does not independently establish an external ABI.

The initial status is not merely a default return value. It is supplied through writable status storage to the first dependency. Consequently, the caller’s fourth argument can influence that dependency, and the dependency can replace it.

### Storage requirements

The second and third arguments must designate storage suitable for their respective writes. There is no visible null check, bounds check, alignment repair, or pointer validation.

For a well-defined ordinary call:

- The discriminator output must permit a 16-bit write.
- The additional-value output must permit a 32-bit write.
- Both locations must remain valid for the duration of the function.
- Any additional access requirements imposed by the dependencies must also hold.

The function uses the supplied addresses directly. It does not allocate replacement output storage, return an output address, or visibly release caller storage.

The two outputs are separate arguments, not fields of an established aggregate layout. No padding, relative offset, byte order, or shared allocation is specified.

### Output interpretation

With distinct, valid output storage and dependencies that do not independently alter those locations:

- A failure reported by the first dependency leaves both outputs zero.
- A successful first stage publishes its discriminator, even if the optional second stage reports failure.
- The additional value is published only when the discriminator is one of the two selected values and the second dependency leaves status zero.

These are conditional output guarantees. The dependencies’ broader memory effects are unknown.

## Behavior

### 1. Initialize caller-visible outputs

The function first writes unsigned 16-bit zero to the discriminator output.

It then writes 32-bit zero to the additional-value output.

These are separate writes in that order. They occur before either dependency is invoked and before any decision based on status or discriminator.

The function next establishes private working-status storage containing the fourth argument’s value. It passes the address of this storage to dependencies; it does not pass the address of the caller’s original argument storage.

### 2. Obtain and classify the discriminator

F-8f49ed59b67e is invoked once with:

1. The first argument’s 32-bit value.
2. The address of the working status.

The function captures the dependency result as an unsigned 16-bit discriminator. It then reads the working status.

If the status is nonzero:

- F-c5640ca5b487 is not invoked.
- The captured discriminator is not written to the discriminator output.
- No later wrapper-level write is made to either output.
- The current working status is returned.

The dependency result alone does not establish success. A nonzero status suppresses discriminator publication even when the returned discriminator is `0x8001` or `0x8002`.

If the status is zero, processing continues using the captured discriminator.

### 3. Select the optional second stage

Exactly two discriminator values select F-c5640ca5b487:

- `0x8001`
- `0x8002`

Every other unsigned 16-bit discriminator skips that dependency.

The source expresses part of this selection through subtraction from `0x8000`. Its externally relevant effect is an exact match for `0x8002`, not a range check and not a signed comparison. In particular:

- `0x8000` does not select the second stage.
- `0x8003` does not select the second stage.
- Values below `0x8000` do not select it.
- `0xFFFF` does not select it.

The discriminator is zero-extended for the comparison logic. A discriminator with its top bit set is not treated as a negative 16-bit value.

Under the supplied 32-bit model, subtraction below `0x8000` can wrap in unsigned arithmetic. Those results do not create another accepted discriminator: only `0x8002` produces the tested difference of two. No arithmetic result is exposed as an output or return value.

### 4. Obtain the additional value when selected

For either selected discriminator, F-c5640ca5b487 is invoked once with:

1. The same first-argument value supplied to the first dependency.
2. The same working-status address.

The first-stage status check must have observed zero before this call. The function does not explicitly reinitialize the working status between the two dependency calls.

The second dependency’s result is captured as an opaque 32-bit value. The function then reads the working status again.

- If status is zero, it writes the captured 32-bit result to the additional-value output.
- If status is nonzero, it does not publish that result.

A zero-valued additional result is valid for publication. The function does not distinguish a zero result from a nonzero result when status is zero.

There is no retry, alternate dependency, or rollback on second-stage failure.

### 5. Publish the discriminator and return status

Whenever the first-stage status check observed zero, the function writes the captured 16-bit discriminator to the discriminator output.

This write occurs:

- After any selected second dependency has returned.
- After any successful additional-value publication.
- Even if the second dependency changed status to nonzero.

The function then returns the current working status.

This creates an important distinction between the two failure points:

- First-stage failure suppresses discriminator publication.
- Second-stage failure does not suppress discriminator publication.

The function returns status, not the discriminator, additional value, or a Boolean conversion of status. Nonzero status values are not normalized.

## Side effects

### Ordered writes performed by this function

The wrapper-level write sequence is:

| Condition | Ordered output writes |
|---|---|
| All calls reaching initialization | 16-bit discriminator zero, then 32-bit additional-value zero |
| First-stage status nonzero | No further wrapper output writes |
| First-stage status zero, unselected discriminator | Final 16-bit discriminator write |
| Selected discriminator, second-stage status nonzero | Final 16-bit discriminator write |
| Selected discriminator, second-stage status zero | 32-bit additional-value write, then final 16-bit discriminator write |

Dependency calls occur between initialization and final publication. A dependency able to access the output locations indirectly could observe or change them during those intervals. The wrapper does not restore the additional-value output to zero after a failed dependency.

The ordering above describes the accesses established by the supplied source. It does not establish atomicity, inter-thread synchronization, or a hardware memory-ordering guarantee.

### Aliasing and overlap

The function performs no visible overlap detection.

If the output storage overlaps, the listed writes apply to the same underlying bytes in their stated order. Consequences include:

- The initial 32-bit zero write can overwrite bytes written by the initial 16-bit zero write.
- A published additional value can be partially overwritten by the final discriminator write.
- The final logical outputs need not be independently representable in overlapping storage.

Exact byte patterns depend on the overlap, alignment, byte order, and validity rules of the execution environment. This contract does not invent a byte order or guarantee that every overlap is valid.

The first argument is passed by value, so its bit pattern is not reloaded from caller memory. If it represents a handle, address, or other reference to mutable state, output writes or dependency activity may still affect the state reached through that value.

### Ownership and other state

The visible wrapper contains no allocation, deallocation, explicit resource acquisition, or explicit resource release. It does not visibly retain either caller output address.

That does not establish equivalent restrictions for the dependencies. Their allocation, ownership, global-state mutation, input consumption, and pointer-retention behavior are unknown. In particular, the additional 32-bit result must not be assumed to be a pointer, an owned allocation, or a borrowed reference.

## Acceptance examples

The following are conditional acceptance scenarios derived from static evidence, not executed tests.

Unless stated otherwise, assume valid, distinct output storage; normal dependency return; and no dependency writes to either output except through the wrapper’s subsequent publication.

### First-stage failure

Given any initial output contents, suppose F-8f49ed59b67e returns discriminator `0x8001` and leaves working status equal to `7`.

Expected:

- Both outputs are initialized to zero.
- F-c5640ca5b487 is not called.
- The discriminator output remains zero.
- The additional-value output remains zero.
- The return value is `7`.

The selected discriminator does not override first-stage failure.

### Successful unselected discriminator

Suppose the first dependency returns `0x8000` and leaves status zero.

Expected:

- No second dependency call occurs.
- The discriminator output becomes `0x8000`.
- The additional-value output remains zero.
- The return value is zero.

The same branch selection applies to `0x0000`, `0x7FFF`, `0x8003`, and `0xFFFF`, with each value published unchanged as the discriminator.

### Successful selected discriminator

Suppose the first dependency returns `0x8002` with status zero. The second dependency returns `0x12345678` and leaves status zero.

Expected:

- Both dependencies are called once, in the stated order.
- The additional-value output receives `0x12345678`.
- The discriminator output subsequently receives `0x8002`.
- The return value is zero.

A first-stage discriminator of `0x8001` selects the same second-stage behavior.

### Second-stage failure

Suppose the first dependency returns `0x8001` with status zero. The second dependency returns `0x12345678` but leaves status equal to `9`.

Expected:

- The second result is not published.
- The discriminator output becomes `0x8001`.
- The additional-value output remains zero under the stated no-indirect-writes assumption.
- The return value is `9`.

The discriminator publication is not rolled back or suppressed.

### Initial status remains significant

Suppose the fourth argument is `5`, and the first dependency returns `0x8002` without changing status.

Expected:

- The first-stage status check observes `5`.
- No second call occurs.
- Neither captured result is published.
- The return value is `5`.

Conversely, a nonzero initial status does not prevent continuation if the first dependency changes it to zero.

### Zero additional value

Suppose the first dependency returns `0x8001` with status zero, and the second returns zero with status zero.

Expected:

- The wrapper performs the successful 32-bit additional-value write even though its value is zero.
- It then publishes discriminator `0x8001`.
- It returns zero.

Final output contents alone cannot distinguish that successful zero publication from an untouched initialized additional-value output.
