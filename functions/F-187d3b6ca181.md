# F-187d3b6ca181

## Purpose

F-187d3b6ca181 processes a descriptor using a context and shared state. It applies coarse eligibility checks, consults an external gate, handles four descriptor kinds, updates byte-sized counters and indexed state, and invokes continuation or completion dependencies.

A staged transfer is an inferred purpose, not an established protocol contract. The established behavior consists of the accesses, conditions, calls, and state changes below.

For a non-null descriptor, every visible exit calls F-09ba55c206ac and then F-feee9156a257, which is marked non-returning. The apparent 32-bit result is therefore an internal status on those paths, not an established caller-visible return value.

## Interface

### Arguments and storage

The supplied representation has two 32-bit pointer-like arguments:

1. **Context:** storage containing a gate argument and four progress counters.
2. **Descriptor:** metadata containing a payload pointer, declared length, and kind.

Neither argument is checked before the initial descriptor accesses.

Descriptor layout:

| Offset | Width | Use |
|---|---:|---|
| +0x08 | 32 bits | Payload pointer |
| +0x0C | Unsigned 16 bits | Declared payload length |
| +0x10 | Unsigned 16 bits | Descriptor kind |

Context layout:

| Offset | Width | Use |
|---|---:|---|
| +0x2D0 | 32 bits | Second argument to F-9c4f3d705d74 |
| +0x2E0 | 8 bits | Selector-1 counter |
| +0x2E1 | 8 bits | Selector-3 counter |
| +0x2E2 | 8 bits | Selector-4 counter |
| +0x2E3 | 8 bits | Selector-6 counter |

“Selector” identifies a numeric dispatch value, not a known protocol meaning.

A shared-state global contains a pointer to storage with this layout:

| Offset | Width | Use |
|---|---:|---|
| +0x00 | Unsigned 8 bits | Count |
| +0x01 | 8 bits | Selected value |
| +0x02 | 8 bits | Alternate selected value |
| +0x03 | Unsigned 8 bits | Current index |
| +0x04 | 32 bits | Enable word |
| +0x08 | 32 bits | Pointer-like value for a table of 32-bit entries |

A separate synchronization global supplies arguments to F-U02 and F-U03. Each invocation has its own load of that global; paired invocations are not established to receive equal arguments.

### Parser interface

F-704f99fd5e22 receives five arguments, in this exact positional order:

| Position | Argument |
|---|---|
| 1 | Context |
| 2 | Earlier result from F-5f5f14cedda3 |
| 3 | Address of a 32-bit working value initialized to all ones |
| 4 | Address of a 32-bit selector |
| 5 | Address of a 32-bit working value initialized to zero |

The selector is initially 8, then replaced before each actual parser call: by payload byte 1 for kind 0, by 1 for kind 2, by 4 for kind 5, or by 6 for kind 7. The parser can write these addressed values. No subsequent decision in this routine uses their post-call contents. Its 32-bit result becomes the internal status.

### Preconditions and termination

Defined operation requires accessible metadata, context, shared state, and all payload and table locations actually accessed. Dependency-specific requirements are unknown.

Declared length alone does not establish payload safety: kind 0 reads byte 1 even when the declared length is one. No visible check establishes table capacity for every later index.

The initial status is 62. At the common exit:

- A zero descriptor argument returns the current status.
- Otherwise, the descriptor is passed to F-09ba55c206ac, followed by F-feee9156a257.

The zero-descriptor branch does not establish null-input support: descriptor fields have already been read.

## Behavior

### Entry, retained values, and gate

The initial sequence is:

1. Read the descriptor kind.
2. Read the payload pointer.
3. Read and unsigned-widen the declared length.
4. Establish status 62 and call F-5f5f14cedda3 with the descriptor.
5. Load and retain the shared-state pointer from its global.
6. Load the shared-state global again and inspect the enable word through that separately obtained pointer.

Thus the enable check does not explicitly use the retained pointer. The representation establishes two global loads; it does not establish that their results must agree.

The rejection checks are short-circuited in this order: zero enable word, kind greater than 7, null captured payload pointer, zero captured length. Any rejection reaches the common exit with status 62.

Otherwise, F-U01 is called. Its result becomes the first argument to F-9c4f3d705d74; the context word at +0x2D0 is read for the second argument after F-U01 returns. A zero gate result exits with status 62.

After gate success, the three parser working values are initialized. Kinds 1, 3, 4, and 6 then exit with status 62 without calling the parser.

The captured kind, length, payload pointer, descriptor-derived value, and retained shared-state pointer remain the values used across calls. Later shared-state accesses use the retained pointer, not a fresh load of the shared-state global. Payload bytes and shared-state fields are nevertheless reread at the points described below.

### Synchronization-like call ordering

F-U02 and F-U03 are names for observed paired calls, not established locking operations.

Every F-U02 invocation loads its argument from the synchronization global at that invocation. Every F-U03 invocation obtains a separate global value.

Four update sequences capture the F-U03 argument **after the shared-state write but before resetting the context counter**:

- Kind-0 special selection update.
- Kind-2 accepted selection.
- Kind-5 accepted count response.
- Kind-7 accepted item store.

In these sequences, the order is: F-U02; branch-specific work and shared-state store; synchronization-global load; context-counter reset; F-U03 with the captured argument.

For the kind-5 table-related pair and the kind-7 index-increment pair, the F-U03 argument is instead loaded after the intervening work. These distinctions remain observable if storage aliases or dependencies change the synchronization global.

### Kind 0: payload-selected handling

The selector is set from unsigned payload byte 1 before calling F-704f99fd5e22.

After the parser returns, a special case applies when the captured length is exactly two and a newly read payload byte 0 is zero. In that case:

- Payload byte 1 is read and compared with 3.
- If it equals 3 and parser status is zero, invoke F-U02, copy shared byte +0x02 to +0x01, capture the F-U03 argument, reset context byte +0x2E1, and invoke F-U03.
- Exit for every outcome of this special case, retaining parser status.

Outside that case, nonzero parser status exits. With zero status, payload byte 1 is read again and selects:

| Value | Mutation before call | Call replacing status |
|---:|---|---|
| 1 | Increment context +0x2E0 | F-a7dad23e028e(context) |
| 3 | Increment context +0x2E1 | F-0dce558036fd(context, current shared byte +0x02) |
| 4 | Increment context +0x2E2 | F-ebf9a68d2fc9(context) |
| 6 | Increment context +0x2E3 | F-daf78a556d2c(context, current shared index) |
| Other | None | None; exit with zero status |

The pre-parser selector and post-parser dispatch byte may differ if a dependency changes payload storage.

### Kind 2: selection response or selector-1 continuation

The parser is called with selector 1.

For captured length one, payload byte 0 is compared with the current shared count. This comparison occurs before testing parser status.

If the byte is below the count and parser status is zero:

1. Invoke F-U02.
2. Reread payload byte 0 and store it in shared byte +0x01.
3. Capture the F-U03 argument.
4. Reset context byte +0x2E0.
5. Invoke F-U03.
6. Reread the shared count; exit if zero.
7. Otherwise read the shared index and call F-daf78a556d2c with context and that index, replacing status.

If that accepted path is not taken, the payload-versus-count comparison is performed again. A below-count result at this second comparison exits.

All remaining cases exit on nonzero parser status. With zero status, increment context byte +0x2E0 and call F-a7dad23e028e, replacing status.

Consequently, an equal or above-count one-byte value is not independently rejected. With zero parser status, it reaches selector-1 continuation. The value stored after F-U02 is also not required by this routine to equal the value previously compared.

### Kind 5: count response or selector-4 continuation

The parser is called with selector 4.

If captured length is not one, nonzero parser status exits. Zero status increments context byte +0x2E2 and invokes F-ebf9a68d2fc9, replacing status.

For length one, nonzero parser status exits. With zero status:

1. Invoke F-U02.
2. Read payload byte 0 and store it as the shared count.
3. Capture the F-U03 argument.
4. Reset context byte +0x2E2.
5. Invoke F-U03.
6. Reread the shared count.

If that count is zero, call F-e35b2bccb75d with context, 0, 0; then call F-c6c589453fa8 with 8, 0, 13, 4. Neither result replaces status.

If the count is nonzero:

1. Invoke F-U02 using a fresh synchronization-global load.
2. Read the unsigned count, multiply by four, and call F-fab3799b3190 with that size.
3. Store its 32-bit result in the shared table-pointer field.
4. Reread the count and call F-U04 with the returned value and four times this newly read count.
5. Load the synchronization global and invoke F-U03.
6. Call F-a7dad23e028e with context, replacing status.

F-U04’s effects are unknown. The call does not establish initialization, clearing, allocation, or any other storage operation.

There is no visible failure check on the F-fab3799b3190 result and no visible release of the previous table value. The two size arguments can differ if the count changes across the allocation-like call.

### Kind 7: indexed item or selector-6 retry

The parser is called with selector 6.

If captured length is below 130, read and retain the current shared index for validation. The accepted item path requires, in short-circuit order:

1. That index is below the current shared count.
2. Payload byte 0 equals that captured index.
3. Parser status is zero.

On acceptance:

1. Invoke F-U02.
2. Call F-8157a180d901 with 8.
3. Call F-001d181710cd with that result, the captured payload pointer advanced by one byte, and captured length minus one.
4. Read the current table pointer and current shared index and store the returned 32-bit value at the corresponding four-byte-stride entry.
5. Capture the F-U03 argument.
6. Reset context byte +0x2E3.
7. Invoke F-U03.
8. Reread the table pointer and shared index and inspect that entry.

The store index need not equal the validation index. The inspected entry need not be the entry just stored. No intervening revalidation is visible.

If the inspected entry is zero, exit with parser status. Otherwise:

1. Invoke F-U02.
2. Increment the current shared index, storing eight bits.
3. Load the synchronization global and invoke F-U03.
4. Reread and capture the shared index.
5. Compare it with the current count.

If the captured index is at least the count, call F-c6c589453fa8 with 8, 0, 13, 4 and exit. Otherwise, call F-daf78a556d2c with context and that captured index, replacing status.

When the accepted path fails for a length below 130, payload byte 0 is compared again with the previously captured validation index. Equality exits immediately, including when the index was not below count.

Every remaining kind-7 case reaches retry handling. Nonzero parser status exits. Zero status increments context byte +0x2E3 and calls F-daf78a556d2c with context and the current shared index. **This retry call’s result is ignored.**

Lengths of 130 or more bypass item validation and storage. Length one can enter the accepted path, passing zero data length and the pointer immediately after payload byte 0.

## Side effects

All explicit counter and index increments store eight bits, wrapping modulo 256. Byte counts and indices are unsigned when widened. Count multiplied by four ranges from 0 through 1020; this multiplication itself does not overflow 32 bits. Accepted kind-7 data lengths range from 0 through 128.

Table access uses a four-byte stride and a 32-bit pointer-like base. Valid address formation, capacity, and alignment are preconditions; no visible bounds guarantee covers changes across dependency calls.

Synchronization-like pairs do not cover every read. Their placement establishes neither atomicity nor exclusion, memory ordering, or concurrency safety.

The routine visibly passes non-null descriptors to F-09ba55c206ac. Whether that releases descriptor storage, payload storage, both, or neither is unknown. Allocation-result ownership, table lifetime, and item-result ownership are also unknown. No explicit release of overwritten table entries is visible. F-001d181710cd may copy or retain payload storage; neither is established.

Dependencies are not assumed to preserve globals, context, payload, or table contents. A retained pointer does not imply retained field values or continued object lifetime.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume accessible storage and no dependency mutation of relevant state.

1. **Disabled input:** A zero enable word skips the gate and parser, but not the earlier descriptor-derived call. A non-null descriptor still reaches cleanup and the non-returning call.

2. **Parser positions:** For kind 2, the parser’s third argument addresses all ones, its fourth addresses selector 1, and its fifth addresses zero. These are distinct 32-bit working values.

3. **Kind-0 special response:** Length two, payload bytes 0 and 3, and zero parser status copy the alternate selected value into the selected value and reset the selector-3 counter. F-0dce558036fd is not called.

4. **Short kind-0 payload:** Declared length one still requires byte 1 to be readable. The routine does not reject the short declaration before that read.

5. **Accepted kind-2 selection:** Length one, payload 2, count 5, and zero parser status store selected value 2, reset the selector-1 counter, and request the current index.

6. **Kind-2 equality:** Payload equal to count with zero parser status increments the selector-1 counter and invokes F-a7dad23e028e rather than accepting a selection.

7. **Zero kind-5 count:** A one-byte zero response with zero parser status stores count zero, resets the selector-4 counter, calls F-e35b2bccb75d, then issues the fixed completion tuple. No table-producing call occurs.

8. **Changed kind-5 count:** If count is 3 when F-fab3799b3190 is called and becomes 5 before it returns, its size argument is 12 while F-U04’s size argument is 20. No effect of F-U04 is implied.

9. **Synchronization argument capture:** If F-U02 changes the synchronization global, the paired F-U03 can receive a different value. In an accepted response update, F-U03 uses the value captured before the counter reset, even if that reset aliases the synchronization global.

10. **Kind-7 boundary and completion:** With stable count 3, index 2, matching payload, length 129, and a nonzero inspected entry, index becomes 3 and completion is invoked. Length 130 instead reaches retry handling; with zero parser status its retry result is ignored.

11. **Wrap:** Incrementing a counter containing 255 stores zero without a visible overflow error.
