# F-87a40c3922d5

## Purpose

F-87a40c3922d5 performs two ordered control operations and then polls a 32-bit status slot. Polling ends when a status operation reports failure, a timeout predicate reports expiration, or bit 7 of the status slot is clear after the iteration’s intervening calls.

Diagnostic references support interpreting this sequence as a device soft-reset operation. The supplied representation establishes the call sequence and branching behavior, but not the hardware meaning of the control values or a guarantee of device readiness.

The explicit normal return values are:

| Value | Established condition |
|---|---|
| 0 | A status operation returned nonzero, the following timeout predicate returned zero, the per-iteration pacing call returned, and bit 7 of the status slot was then clear. |
| 89, hexadecimal 0x59 | A status operation returned zero. |
| 90, hexadecimal 0x5A | Either control operation returned zero, or a timeout predicate returned nonzero; the corresponding diagnostic call subsequently returned normally. |

These are the caller’s decisions. They do not establish a common error convention across dependencies, completion of a hardware reset, or restoration of device state on failure.

## Interface

### Inputs

The supplied representation declares no explicit parameters. It nevertheless uses two incoming values:

- A 32-bit quantity read from storage at byte offset 16 from a global-associated base.
- The incoming 32-bit contents of processor register r3, used to initialize a local status slot.

The global-associated value is captured before any dependency call and passed to every timeout-predicate invocation. Its interpretation as timeout configuration is inferred from that use. Its units, valid range, and dependency-side signedness are unknown.

The incoming register value supplies an initial bit pattern. The evidence does not establish whether it is an intentional interface input or incidental calling-context state.

### Output and widths

The function returns a 32-bit value. Its explicit returns are limited to 0, 89, and 90.

The status slot, captured global-associated value, and token returned by F-U02 are each represented as 32-bit quantities. Dependency results used for branching are represented as 32-bit integer results and are tested only for zero or nonzero.

No pointer width, byte order, allocation result, or returned ownership transfer is established by the supplied representation.

### Storage layout and lifetime

The referenced configuration field occupies a 32-bit quantity at byte offset 16 from its base. No surrounding layout is established.

The local status slot is 32 bits wide. Its address is passed to F-03fd77b56fa0. The caller examines only bit 7, using the mask 0x80, decimal 128. Other bits do not directly affect the caller’s branches.

The local slot exists for this invocation. No visible allocation extends its lifetime beyond the function’s return. Passing its address does not establish whether the receiving dependency retains or exposes that address.

## Behavior

### Entry capture

The function first reads the 32-bit value at byte offset 16 from the referenced base and saves it. It then initializes the local status slot from incoming r3.

Both actions precede the first dependency call.

The configuration source is not explicitly reread during this invocation. Later timeout calls receive the captured value rather than a fresh read from that source. This does not imply that dependencies preserve globals or refrain from consulting other state.

### First control operation

The function calls F-2ac0bc8c9f68 with arguments 6 and 4, in that order.

A zero result selects the diagnostic associated with inability to initiate the soft-reset operation. The function then calls F-1b7fa166ef25 with that diagnostic reference and returns 90 if the diagnostic call returns normally.

Every nonzero result permits continuation. No distinction is made between positive and negative nonzero results under a signed interpretation.

On the zero-result path, there is no inter-control call, second control operation, polling setup, status operation, or timeout evaluation.

### Inter-control call and second control operation

After a nonzero first control result, the function calls F-U01 with argument 1000. No result from this call is used.

After F-U01 returns, the function calls F-2ac0bc8c9f68 with arguments 6 and 0.

A zero result selects the diagnostic associated with inability to clear soft reset. F-1b7fa166ef25 receives that reference, and the function returns 90 if the diagnostic call returns normally.

A nonzero result permits polling setup.

The placement of F-U01 is consistent with a delay between control operations, but neither its actual effect nor the units of 1000 are established. No compensating control operation or rollback is visible on either control-failure path.

### Polling setup

After both control results are nonzero, the function performs these calls in order:

1. F-233fe84cf225 with argument 100.
2. F-U02 with no explicit arguments.

The result of the first call is not used. The 32-bit result from F-U02 is saved as an opaque token.

The token is obtained once and supplied unchanged to every timeout-predicate call. It is not refreshed on loop repetition.

If F-U02 supplies a time reference, both control operations and the calls carrying 1000 and 100 occur before that reference is obtained. The evidence does not establish whether those earlier operations count toward any dependency-defined timeout.

### Polling iteration

Each iteration begins by calling F-03fd77b56fa0 with arguments 15 and the address of the local 32-bit status slot.

If this status operation returns zero, the function returns 89 immediately. That iteration performs no timeout evaluation, no call carrying 50, no status-bit inspection, and no diagnostic call.

If the status operation returns nonzero, the function calls F-U03 with:

- The token captured from F-U02.
- The configuration value captured at entry.

A nonzero F-U03 result selects timeout handling. The function calls F-1b7fa166ef25 with the timeout-related diagnostic reference and returns 90 if that call returns normally.

A zero F-U03 result permits a call to F-233fe84cf225 with argument 50. After that call returns, the function reads the status slot and tests bit 7:

- Clear bit 7 produces return 0.
- Set bit 7 starts another iteration with a new F-03fd77b56fa0 call.

The function does not reinitialize the status slot between iterations.

### Status observation and intervening mutation

The decisive status read occurs after both F-U03 and F-233fe84cf225, not immediately after F-03fd77b56fa0.

F-03fd77b56fa0 receives the slot’s address. The supplied evidence does not prohibit that dependency from retaining or exposing the address. Consequently, it does not establish that the intervening dependencies cannot modify the slot through shared or retained access.

The bit test therefore uses the slot’s contents after the intervening calls. It is not necessarily a test of the exact value present when the status operation returned.

Similarly, a nonzero status-operation result without an output write does not by itself establish that the slot remains equal to incoming r3 or to a previous iteration’s value. Those conclusions require the additional condition that no intervening modification occurred.

### Decision precedence

The visible sequence establishes these priorities:

1. A zero status-operation result causes return 89 without evaluating timeout or status bits.
2. After a nonzero status-operation result, a nonzero timeout result causes diagnostic handling and return 90 without pacing or bit inspection.
3. Only a nonzero status result followed by a zero timeout result reaches the call carrying 50 and the subsequent bit test.

Thus, a clear status bit does not override a timeout result. It also does not bypass the per-iteration call carrying 50.

### Termination and arithmetic

There is no explicit iteration counter or local retry limit.

Polling can continue indefinitely if status operations return nonzero, timeout predicates return zero, and bit 7 remains set whenever inspected. A dependency can also block indefinitely; no local recovery is visible.

The function performs no visible deadline addition, elapsed-time subtraction, duration conversion, or counter arithmetic. Overflow and clock-wrap behavior, if relevant, belong to dependency behavior and remain unknown.

The explicit scalar arguments—6, 4, 0, 1000, 100, 15, and 50—and the mask 128 fit within 32 bits. The representation does not justify narrower argument widths or a specific signed interpretation inside the dependencies.

## Acceptance examples

These are conditional consequences of the supplied representation, not executed tests. Each normal-return outcome assumes that the required accesses and calls complete normally.

### First control failure

If the first F-2ac0bc8c9f68 call returns zero:

- Its arguments are 6 and 4.
- The first-control-failure diagnostic is passed to F-1b7fa166ef25.
- The function returns 90.
- No later operational dependency is called.

### Second control failure

If the first control result is nonzero and the second is zero:

- F-U01 receives 1000 between the control calls.
- The second control call receives 6 and 0.
- The clear-reset-failure diagnostic is issued.
- The function returns 90 without polling setup.

### Status failure takes precedence

After completed polling setup, if a status operation returns zero:

- The function returns 89.
- No timeout predicate or per-iteration pacing call follows.
- No status-bit test or diagnostic occurs.

The slot’s contents do not affect that return.

### Clear status after eligible pacing

If a status operation returns nonzero, F-U03 returns zero, and bit 7 is clear after F-233fe84cf225 receives 50 and returns:

- The function returns 0.
- No diagnostic is issued.

A clear bit immediately after the status operation is insufficient by itself; the relevant value is the value read after the intervening calls.

### Clear status with timeout

If the status operation returns nonzero and F-U03 returns nonzero, the function issues the timeout diagnostic and returns 90 even if the slot contains a clear bit 7.

There is no call carrying 50 and no bit test on that path.

### Busy status followed by completion

If one eligible bit test observes bit 7 set and the next eligible bit test observes it clear:

- A new status operation begins the second iteration.
- Each nonzero status result is followed by a timeout check.
- Each zero timeout result is followed by a call carrying 50.
- The second bit test produces return 0.

### Nonzero status result without an output write

Suppose F-03fd77b56fa0 returns nonzero without modifying the slot, F-U03 returns zero, and the pacing call returns.

The bit test reads the slot’s contents after those intervening calls. If the status dependency retained or exposed the address and an intervening call changed the slot, that changed value controls the decision.

Only if no modification occurred since initialization does the first bit test use the incoming register value. On later iterations, using a previously stored value likewise depends on no subsequent modification.

Whether nonzero-without-write behavior or indirect mutation is permitted by the dependency implementations remains unknown.

### Continued polling

If every status result is nonzero, every timeout result is zero, and every eligible bit test observes bit 7 set, the function keeps polling without a locally imposed limit.
