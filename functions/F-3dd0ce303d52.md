## Behavior

### Invocation prefix and dependency boundaries

The prefix is not shown as a loop or as data-dependent branching. Provided each dependency returns, execution proceeds to the next visible invocation without checking a success indicator.

The argument exchanges have several established characteristics:

- Many consumers receive a preceding primary result shifted left by 8 bits.

These dependencies cannot safely be consolidated into a single pure calculation. Their invocation order, multiplicity, secondary result channels, and possible memory effects are part of the unresolved behavior.

### Arithmetic and bit-field constraints

The representation performs word-sized shifts, masks, scaling, and subtraction. It does not show saturation, overflow detection, or range rejection.

A faithful machine-level interpretation must retain intermediate widths. Under a 32-bit wrapping interpretation, left shifts discard bits beyond bit 31. Successive shifts therefore cannot be treated as unbounded multiplication followed by a later right shift.

Important visible transformations include:

- Selection of the low 24 bits before shifting or extracting subfields.
- Selection of 22-bit, 20-bit, 19-bit, 18-bit, 17-bit, 14-bit, 13-bit, 12-bit, 11-bit, and single-bit regions.
- Extraction of bits 10–19 by masking to 20 bits and then shifting right by 10.
- Extraction of upper-result subfields by shifting a 64-bit container right by 34, 36, or 44 bits. These correspond to the high 32-bit half shifted right by 2, 4, or 12 bits.
- Scaling values by 2, 4, and 8 when forming subsequent addresses.
- Subtracting 0x96 from an intermediate before further scaling.
- Multiplication by 0x02000000 when forming an early base in the mutation region.

Several intermediate values become zero under 32-bit wrapping even when their original inputs are nonzero. For example, a value already shifted left by 28 bits and then shifted left by another 28 bits cannot retain any original bit. Such arithmetic facts do not authorize deleting intervening dependency invocations.

The representation contains signed left shifts and signed multiplication. Consequently, wrapping arithmetic is a conditional target-machine interpretation, not an established portable language guarantee.

### Transition to explicit memory mutation

The final paired result from the invocation prefix supplies two inputs to the first direct writes. Other retained results determine a heavily shifted base, a shifted word, and a small indexed base.

The small index is derived by shifting a 32-bit result left by 8, masking to 15 bits, and shifting right by 6. Under word-sized bit-vector semantics, the index is a multiple of four between 0 and 508 inclusive. Its doubled base is therefore a multiple of eight between 0 and 1016.

The opening mutation sequence establishes these ordering constraints:

1. A 32-bit write through the final high-result half at offset 0x14 precedes a byte write through a retained shifted base at offset 9.
2. A 32-bit write through a base formed by scaling the final low-result half precedes a second byte write to that same offset-9 location.
3. A 32-bit zero write at offset 0x14 of the heavily shifted base precedes an 8-bit read at its offset 5.
4. A zero write through the doubled small-index base precedes storage of the zero-extended byte at offset 0x34 of the heavily shifted base.
5. The offset-0x14 word is subsequently read back. The representation does not replace that read with the earlier constant.
6. Further zero writes and repeated byte writes occur through the small-index-derived base.

Aliasing can affect these observations. In particular, an earlier store may change a later read when computed ranges overlap. The read-back word cannot unconditionally be asserted to be zero.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Paired-result separation.** If a producer supplies low half 0x00123456 and high half 0x89ABCDEF at a forwarding site that shifts only the low half by eight, the consumer receives 0x12345600 and 0x89ABCDEF in the corresponding positions.

2. **Truncation before extraction.** Under 32-bit wrapping, shifting 0x12345678 left by eight and subsequently right by eight yields 0x00345678, not the original word.

3. **Small-index boundary.** If the relevant retained result is 0x7F, the small index is 508 and its doubled base is 1016. A value of 0x80 instead produces index zero at this extraction site.

4. **Byte widening.** If a reached offset-5 byte read returns 0xFE, the subsequent word store of that widened value contains numeric value 254, not a sign-extended negative value.

5. **Repeated byte destination.** If both opening offset-9 writes complete, observers may see the first byte followed by its replacement. A final-memory-only comparison does not establish preservation of this behavior.

6. **Store-width distinction.** A reached halfword store of 0x3A writes a 16-bit numeric value. It is not interchangeable with an 8-bit store, irrespective of whether the addressed region is later interpreted as text.

7. **Dependency failure.** If a prefix dependency does not return, no later direct store is guaranteed. Earlier dependency effects are not rolled back by any visible mechanism.

8. **Final transfer.** If all preceding operations complete, F-D003 receives first argument 0x72. Successful return from that target remains an additional condition for the represented return to be reached.
