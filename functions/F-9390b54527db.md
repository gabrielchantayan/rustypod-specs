# F-9390b54527db

The established behavior is an ordered sequence of memory accesses and dependency calls. The source does not establish application-level meanings for the flags, comparison values, or counter. In particular, the counter must not be described as a reference count, and the operation must not be described as destruction, cancellation, or completion without additional evidence.

A nonzero byte in the referenced object disables the entire processing path: the function returns without calling either dependency, marking the wrapper, or decrementing the counter.

## Behavior

### 1. Capture the object and inspect the entry gate

The function first reads the 32-bit address stored at W offset `0x00`, capturing T. It then reads the byte at T offset `0x14`.

If that byte is nonzero, the function returns immediately. On this path:

- Neither dependency is called.
- The marker at W offset `0x1F` is not written.
- The counter at T offset `0xE0` is not accessed.
- The remaining condition and comparison fields are not accessed by this function.

All nonzero byte values have the same gating effect. The function does not require the gate to equal 1.

If the byte is zero, execution continues. This gate is not rechecked later, including after dependency calls.

### 2. Invoke the first dependency

The function calls **F-b93e3fe564f6**, passing the captured T.

This call occurs before the wrapper marker is written and before any optional-call conditions are evaluated. Consequently, mutations performed by this dependency can affect the later condition values, comparison values, and counter.

The caller does not visibly inspect a return value. Continuing behavior assumes the dependency returns normally.

Even if this dependency changes the address stored at W offset `0x00`, the current invocation continues to use the original captured T.

### 3. Mark the wrapper

After the first dependency returns, the function writes the byte value 1 at W offset `0x1F`.

This is a byte-sized write. It is not an increment, toggle, or whole-word assignment.

The write happens regardless of whether the optional second dependency will be called. It also happens before the wrapper condition at offset `0x1D` is read.

### 4. Evaluate the optional-call conditions

The function reads the byte at W offset `0x1D`.

If that byte is zero, it skips the remaining optional-call conditions and proceeds to the counter update. In particular, it does not read T offset `0x09` or either comparison field on this path.

If the wrapper byte is nonzero, the function reads the byte at T offset `0x09`.

If that object byte is nonzero, it skips the integer comparisons and proceeds to the counter update.

Only when the wrapper byte is nonzero and the object byte is zero does the function evaluate the integer conditions:

- First, it compares the 32-bit value at T offset `0x24` with the 32-bit value at W offset `0x04`.
- If those values differ, the optional call is selected without evaluating the signed-order condition.
- If those values are equal, it evaluates whether the signed 32-bit value at T offset `0x24` is less than or equal to the signed 32-bit value at T offset `0x28`.
- If that signed comparison is true, the optional call is selected.
- Otherwise, the optional call is skipped.

The supplied expression contains a second read of T offset `0x24` for the signed-order condition. It must not be treated as an explicitly saved value from the preceding equality comparison. The source does not establish an atomic snapshot of the fields or a relative evaluation order between the two operands within an individual comparison.

For stable memory, the selection rule is: a nonzero wrapper condition, a zero object condition, and either unequal comparison values or a signed lower-or-equal relation.

If selected, the function calls **F-d0d75bd453b2**, passing W, not T. The call occurs after the marker write and before the counter update. No return value is visibly used.

### 5. Decrement the counter

After the optional call returns—or after that call is skipped—the function reads the 32-bit counter at the captured T offset `0xE0`, subtracts one, and writes the result back to the same location.

The counter is read at this late point. It is not saved before either dependency call. A dependency’s change to that counter therefore affects the value this function subsequently decrements, provided the memory remains valid.

The operation is an ordinary read-modify-write sequence. No lock, atomic instruction, saturation rule, lower-bound check, or error return is established.

For signed values above −2,147,483,648, subtracting one has an ordinary representable signed 32-bit result. The supplied source does not establish a portable result for decrementing −2,147,483,648. Wrapping to 2,147,483,647 is not a guaranteed acceptance condition.

The function then returns without an explicit result.

## Side effects

1. A one-byte store of 1 to W offset `0x1F`.
2. A 32-bit store of the decremented counter to T offset `0xE0`.
