# F-0a5e6011a383

## Purpose

F-0a5e6011a383 conditionally clears one 32-bit field in a caller-supplied memory region, invokes F-15120226cfd2 with two unchanged arguments, and then clears a second 32-bit field.

The first clear occurs only when the third argument equals the discriminator `0x52800008` and the first field equals the second argument. The second clear occurs after the dependency returns normally, regardless of whether the first clear occurred.

This is an ordering-sensitive operation. The dependency is invoked after any conditional first-field clear and before the unconditional second-field clear. The evidence does not establish the application-level meaning of either field or either forwarded argument.

The comparison is equality, not a range check, bit-mask test, or comparison against only part of the field. Under the apparent 32-bit model, the entire 32-bit value participates.

### Conditional first-field clear

## Side effects

The established direct access order is:

1. Optional 32-bit read at offset `0x34`.
2. Optional 32-bit zero store at offset `0x34`, following a matching read.
3. Invocation of F-15120226cfd2.
4. 32-bit zero store at offset `0x84`, following normal dependency return.

This ordering has several consequences:

- A dependency that can observe the first field may observe its conditional clear before the final field is cleared.
- The dependency runs before this function performs its final write at offset `0x84`.
- If the dependency changes offset `0x84` and returns with that location still valid and writable, the final store overwrites that change with zero.
- If the dependency changes offset `0x34`, this function does not subsequently restore or clear that field again.
