# F-dd05c5fa8922

## Purpose

F-dd05c5fa8922 specifies an operation that interleaves indirect dependency calls with byte, 16-bit, and 32-bit memory accesses. Its application-level purpose is not established.

The observable contract consists of ordered calls, argument transformations, memory reads, and stores. It includes byte-selected absolute destinations, repeated global snapshots, word-to-byte copies, and a terminal call to address zero. There are no visible conditional branches, loops, status checks, or recovery paths.

All behavior below is established from the supplied static representation unless explicitly marked as inference or unknown. Successful execution is not established. No runtime tests have been performed.

## Interface

**Explicit input:** one opaque 32-bit value, passed unchanged to the first dependency. No direct validation or dereference of this argument is visible.

**Additional incoming state:**

- A control-address value used to form the first indirect target by adding `0xffe`.
- An incoming byte used by the first byte store.
- An incoming address-like value used for the first selector read.
- Existing memory and global contents.

Several later calls also provide secondary machine outputs, separate from their ordinary represented return values. These outputs become indices, repeated arguments, a retained control value, and a byte-store pointer. Their actual calling convention is unknown.

**Output:** no explicit returned data. A return is represented after the final zero-address call; reaching it requires every preceding access and call to complete, including that final call.

**Widths and notation:**

- A byte is 8 bits; a halfword is 16 bits; a word is 32 bits.
- A split result is 64 bits, divided into low and high 32-bit halves.
- `low8` denotes the least significant eight bits.
- All right shifts described below are logical shifts of unsigned 32-bit values.
- **G-A** is a 32-bit global read twice.
- **G-B** is a 32-bit global written twice.
- **G-C** is a three-byte component associated with address `0x9`, used in the terminal combination.

These labels describe accesses, not validated objects or disjoint storage.

Address formulas retain the widths and qualifications of the representation. In particular, signed left shifts and signed multiplication are not assumed to wrap. Pure unsigned 32-bit arithmetic has its usual finite-width interpretation, but that does not establish pointer validity or platform address-conversion behavior.

A call described as having “no explicit arguments” is not asserted to receive zeroed registers or no implicit machine state.

## Behavior

### Call-sequence conventions

To make exact call counts explicit:

- A **forwarding pair** contains exactly two calls: a producer returning a 32-bit value, followed by a consumer receiving that value.
- A **four-call tail** contains exactly four calls, with no represented explicit arguments. A named result or secondary output comes from the fourth call.
- Two forwarding pairs followed by a four-call tail therefore mean eight calls, not nine or ten.

Each occurrence denotes distinct ordered call sites. These descriptions do not imply identical targets, interchangeable behavior, or absence of side effects.

### 1. Entry and anchor creation

The first dependency receives the explicit input. Four calls follow; the fourth supplies a result.

Next, a byte is read at the incoming address-like value plus 1. Its unsigned value selects the absolute destination at that value plus `0x11`. The incoming byte is stored there. The selected destination is between `0x11` and `0x110`, independent of the original selector-read base.

A dependency receives the preceding result shifted left by two. A four-call tail supplies another result; its left-shift-by-two value is retained as **scaled-first**.

The following calls occur in order:

- A consumer of scaled-first.
- A producer of **first-word**.
- A consumer of first-word.
- A producer of **anchor**.

A zero byte is stored at `8192 × scaled-first + 9`. A dependency then receives anchor, `first-word >> 22`, and first-word.

### 2. Anchor-derived stores and initial links

A forwarding pair and a four-call tail produce a split 64-bit result.

Before the next call, `low8(anchor)` is stored at `anchor + 9`. A 32-bit word is then read from `anchor + 0x34` for that call. The dependency receives:

- The split result’s low half shifted left by two.
- Its high half.
- The loaded anchor-derived word.

**Exactly four calls follow this consumer.** The fourth supplies secondary output **first-index**. There is no fifth intervening call.

The function stores anchor as a word at `4 × first-index + 0x14`, then reads **saved-first** as a word from `first-index + 0x14`. These are distinct address formulas. A dependency receives first-index.

A forwarding pair and four-call tail produce **second-index**. Anchor is stored at `4 × second-index + 0x14`. A word, **linked-word**, is read from `(saved-first >> 22) + 0x14`. The next dependency receives `4 × second-index`.

A four-call tail produces **payload-source**. Define **half-index** as `linked-word >> 1`. The function:

- Stores payload-source shifted left by two at `4 × half-index + 0x14`.
- Reads **next-word** from `linked-word + 0x14`.
- Calls a dependency with half-index.

The read uses linked-word itself, not half-index.

### 3. Shifted fields and zero-derived accesses

A forwarding pair and four-call tail produce **third-index**. The shifted payload-source is stored at `4 × third-index + 0x14`.

G-A is read into **snapshot-one** before a dependency receives `4 × third-index`. A four-call tail supplies secondary output **fourth-index**.

Define:

- **upper-next** as `next-word >> 22`.
- **upper-global** as `snapshot-one >> 23`.

Upper-next is stored at `4 × fourth-index + 0x14`. A dependency receives fourth-index twice, upper-global, and upper-next.

A forwarding pair follows. Between its producer and consumer, the representation computes **double-shift**, equal to `upper-global >> 23`. Because snapshot-one is unsigned 32-bit, upper-global is at most `0x1ff`; double-shift is therefore zero.

A four-call tail produces an index. Upper-next is stored at that index’s `4 × index + 0x14` location, and a dependency receives the scaled index.

Another four-call tail supplies secondary output **masked-source**. A zero word is stored at `4 × masked-source + 0x14`, followed by a dependency receiving masked-source.

Next come one forwarding pair and **exactly four further calls**. The final result selects a word destination. The function stores double-shift, therefore zero, at `4 × index + 0x14`, then reads **extracted-word** from:

\[
((\text{masked-source}\ \&\ \texttt{0x1fffffff}) >> 19) + \texttt{0x14}.
\]

A dependency receives the scaled index. Four calls follow before extracted-word is shifted right by 22, producing **shifted-extracted**.

A selector byte is then read at `double-shift + 1`, necessarily address 1 under the established width interpretation. The function stores `low8(shifted-extracted)` at the selector plus `0x11`.

### 4. Byte clearing and first G-B assignment

A dependency receives one secondary machine output in its first three positions and zero in its fourth. One no-explicit-argument call follows, then a dependency receives zero.

A four-call tail produces a result. Before passing that result shifted left by two onward, the function reads a selector byte at `4 × shifted-extracted + 1` and stores zero at the selector plus `0x11`.

A four-call tail produces another result. A dependency receives its left-shift-by-two value twice. A producer supplies **middle-word**, a consumer receives middle-word, and one further call executes.

The function reads the byte at address 1 and clears the selected byte at selector plus `0x11`.

A secondary output is retained as **retained-control** and passed three times to a dependency. A producer then supplies a result to a consumer together with `middle-word >> 23`.

A four-call tail produces another result. The function reads address 1 into **small-base** and clears the byte at `small-base + 0x11`. A dependency receives the produced result shifted left by two.

Another four-call tail produces a result whose shifted value is passed twice to a dependency. The next producer supplies **control-word**.

Control-word is written to G-B **before** a dependency receives it. One additional call follows.

The function then reads a full word at `small-base + 0x74` and stores its low byte at `small-base + 1`. Small-base is the retained selector value; address 1 is not reread for this copy.

### 5. Repeated copies and payload propagation

A dependency receives retained-control shifted left by 11. A split-result producer follows. Its low half, high half, and `control-word >> 23` are passed to a consumer.

A four-call tail produces **copy-index**. Define **copy-base** as `4 × copy-index`. The function reads a word at `copy-base + 0x74`, stores its low byte at `copy-base + 1`, and calls a dependency with copy-base.

A four-call tail produces **argument-source**. Define **argument-base** as argument-source shifted left by two.

The word read at `copy-base + 0x74` and low-byte store at `copy-base + 1` are repeated before the next call. This is a fresh word read, not reuse of the previous loaded value.

A dependency receives retained-control shifted left by 12, argument-base twice, and argument-source shifted left by 18.

Two forwarding pairs followed by a four-call tail produce an index. At its four-times-scaled base, the function reads **payload-word** from offset `0x74`, stores its low byte at offset 1, and passes the scaled base to a dependency.

A four-call tail produces another index. Payload-word is stored at `16 × index + 0x14`.

The next dependency receives:

\[
(\text{argument-base} >> 2) << 16.
\]

The unsigned right shift operates on argument-base after its earlier formation; this contract does not replace it with an unconstrained-width expression involving argument-source.

Two forwarding pairs follow. **Exactly four calls occur after the second forwarding consumer**, with the fourth producing the index for a payload-word store at `4 × index + 0x14`.

### 6. Final links and selector writes

A dependency receives the scaled index from the preceding store. A four-call tail produces a result whose left-shift-by-two value is **link-value**.

Link-value is stored at:

\[
(\text{argument-base}\ \&\ \texttt{0xfffffffc}) + \texttt{0x14}.
\]

A dependency receives link-value twice.

Next come **two producer/consumer forwarding pairs followed by exactly four calls**. The fourth call supplies an index. A zero word is stored at `4 × index + 0x14`, and a dependency receives the scaled index.

A four-call tail produces a split result. Its low half shifted left by two becomes **final-link**; its high half becomes **final-index**.

Final-link is stored at `4 × final-index + 0x14`. G-A is read again into **snapshot-two**. A dependency receives final-link, final-index, final-link, and final-link.

A four-call tail supplies another index. Final-link is stored at `4 × index + 0x14`. **Final-word** is then read from `snapshot-two + 0x14`.

A dependency receives the scaled index. A four-call tail produces a split result retained as **final-low** and **final-high**.

The function reads a selector byte at `(payload-word >> 23) + 1`, then stores `low8(final-word)` at selector plus `0x11`.

A dependency receives final-high three times and final-low shifted left by two. A forwarding pair and four-call tail follow.

The function reads another selector byte at:

\[
((\text{final-low}\ \&\ \texttt{0x3fffffff}) >> 21) + 1
\]

and stores `low8(final-word >> 22)` at selector plus `0x11`.

A dependency receives the latest result shifted left by two. A four-call tail produces another result, whose shifted value is passed twice to a dependency.

### 7. Terminal effects

After that two-argument consumer, one call executes, followed by a forwarding pair. The next dependency supplies an 8-bit result and a secondary pointer output.

The remaining operations are ordered as follows:

1. Store a zero byte through the secondary pointer.
2. Read G-C’s three-byte component.
3. Form a 32-bit value with G-C in the upper 24 bits and the dependency’s byte result in the low eight bits.
4. Store that value to G-B.
5. Store a zero halfword at `(final-low & 0x3fffffff) >> 7`.
6. Call address zero with three zero arguments.
7. Return only if that call returns.

The halfword’s starting address ranges from zero through `0x007fffff`. No alignment adjustment or validation is visible. The component combination establishes bit placement, not an independently established byte order for the resulting memory store.

## Side effects

Dependencies may change memory or globals between accesses. Consequently:

- The two G-A reads are distinct snapshots.
- Repeated address-1 reads may select different destinations.
- The two reads at `copy-base + 0x74` must remain distinct.
- The first G-B assignment need not survive until the terminal assignment.

## Acceptance examples

These are conditional requirements, not executed tests.

- **Initial selector:** if the first selector read yields `0x20` and the incoming byte is `0xab`, the first explicit store writes `0xab` to `0x31`, provided preceding calls and accesses complete.

- **Different address scales:** with first-index equal to 3, the anchor store targets `0x20`, while saved-first is read from `0x17`. Reading back from `0x20` instead would violate the specified sequence.

- **Exact first-index boundary:** after the consumer of the split result and anchor-derived word returns, exactly four calls precede the anchor store indexed by the secondary output. An extra fifth call is not equivalent, even if its ordinary return value is ignored.

- **Other exact call boundaries:** the masked-source consumer is followed by one forwarding pair and four calls before the zero-word store. The transformed argument-base consumer is followed by two forwarding pairs and four calls before the payload-word store. The repeated link-value consumer has the same two-pair/four-call structure before its zero-word store.

- **Zero-derived selector:** for any unsigned 32-bit snapshot-one, shifting right by 23 twice yields zero. The corresponding selector read therefore occurs at address 1.

- **Fresh copy source:** if an intervening dependency changes the word at `copy-base + 0x74`, the second copy uses the changed word’s low byte.

- **Narrowed final values:** if final-word is `0xffc000ab`, the first final selector store writes `0xab`. The later shifted store writes `0xff`, because the shifted value is `0x3ff` before byte narrowing.

- **Terminal composition:** if the G-C component read is `0x123456` and the terminal byte result is `0xab`, the second G-B assignment is the 32-bit value `0x123456ab`.

- **Terminal ordering and failure:** the pointer-byte clear precedes the G-C read and second G-B write; the halfword clear follows that write; the zero-address call follows the halfword clear. A fault at any stage does not imply reversal of earlier effects.
