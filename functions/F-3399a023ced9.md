# F-3399a023ced9

## Purpose

F-3399a023ced9 conditionally submits a requested number of four-byte units to an address-based circular region. An accepted request invokes F-7b852511e094 for either one contiguous span or two spans crossing the region end, updates page-associated metadata, advances the producer position, increments a byte counter, and publishes a producer-position mirror.

This circular-storage interpretation is inferred intent. The supplied static representation establishes calls, arithmetic, memory accesses, and return construction; it does not establish that the dependency actually transfers data.

Admission requires the wrapped requested byte length to be **strictly less than** the calculated available quantity. Equality is rejected.

Before any dependency call on an accepted request, the function reads an address-bearing global datum and writes a Boolean **through the resulting pointer**. The evidence does not establish a directly addressed Boolean global, a constant destination address, or separation between that destination and other storage.

### Arithmetic and storage assumptions

The contract describes the represented 32-bit arithmetic: address, length, addition, and subtraction results wrap modulo \(2^{32}\). Derived address and length comparisons are unsigned. This describes the supplied representation, not a portable-language guarantee about arbitrary signed arithmetic.

Let \(L\) be four times argument 4, reduced to 32 bits. Although the count is represented as signed in the supplied material, there is no negative-count check. A negative count or overflowing conversion therefore receives no special rejection.

Page indices are obtained by logically shifting a wrapped 32-bit byte offset right by 12: pages are 4,096 bytes for these calculations.

Ordinary circular-storage use requires valid accessible storage, consistent region positions, suitable alignment, sufficient metadata, and appropriate external synchronization. Those conditions are not enforced here. The accepted path additionally requires the address-bearing global datum to be readable and its resulting pointer to designate storage suitable for the Boolean store.

## Behavior

### Admission

The function first reads these descriptor words in order:

1. Consumer position.
2. Producer position.
3. Capacity-like quantity.

Denote those initial observations by \(C\), \(P\), and \(S\). The calculated available quantity is:

\[
A =
\begin{cases}
S-(P-C) \pmod {2^{32}}, & P>C,\\
C-P, & P<C,\\
S, & P=C.
\end{cases}
\]

The capacity-like word is read even when the \(P<C\) case subsequently replaces its contribution.

The request is accepted exactly when \(L<A\). Otherwise, the function returns rejection without a dependency call or explicit memory write. In particular, rejection does not reach the global address-datum read or the indirect Boolean store.

This calculation is not a general consistency check. Underflow in the \(P>C\) case can produce a large available quantity rather than an error.

### Accepted-path indirect store and protected page

After acceptance, the function performs the following ordered accesses:

1. Reads the address-bearing global datum.
2. Writes a Boolean through the pointer obtained from that read.
3. Reads the descriptor’s region base.

The Boolean value is true when argument 7 contains mask `0x00000002`, and false otherwise.

The global datum supplies the destination address; it is not itself established as the Boolean destination. The destination’s identity, address stability across invocations, and aliasing relationships are unresolved. The function does not visibly restore the Boolean destination or the address-bearing datum.

Using the initially observed consumer position and the base read **after** the Boolean store, the function retains a protected page index:

\[
R=((C-\text{base})\bmod 2^{32}) \mathbin{\text{logical shift right}} 12.
\]

Consequently, if the Boolean destination aliases the descriptor base, this calculation can observe the changed base. The initial consumer and producer observations remain the values used earlier; they are not refreshed at this point.

The function next reads the region end and compares it with the wrapped sum \(P+L\):

- End strictly below \(P+L\): split path.
- Otherwise: contiguous path.

Equality uses the contiguous path. Overflow of \(P+L\) is not separately detected.

### Page-value selection

For a computed inclusive page interval from \(a\) through \(b\), page-value assignments follow this rule:

- If \(R<a\) or \(b<R\), assign argument 6 to entries \(a\) through \(b\).
- Otherwise, if \(R\ne0\), assign argument 6 to entries \(a\) through \(R-1\).
- Otherwise, perform no assignments for that interval.

Each assignment sequence proceeds in increasing page-index order. A sequence whose initial index exceeds its final index performs no assignments.

When \(R\) lies inside the interval, the rule excludes both the protected page and every later page in that interval. It is not equivalent to updating every page except the consumer page.

### Contiguous path

The function invokes F-7b852511e094 once with these represented argument positions:

1. Initial producer position \(P\).
2. Argument 3.
3. Requested byte length \(L\).
4. Original argument 4.
5. Argument 2.
6. Argument 3 again.

The true dependency signature and significance of the trailing arguments are not established.

After the call returns, descriptor producer and base fields are read to calculate:

- Start page: producer-relative-to-base offset, logically shifted right by 12.
- Inclusive end page: producer-relative-to-base offset plus \(L-1\), wrapped to 32 bits before the shift.

The representation contains separate producer/base expressions for these calculations. A single atomic or coherent snapshot is not established.

The function then:

1. Applies the page-value selection rule.
2. Reads the start page’s flags word.
3. ORs that word with all bits of argument 7.
4. Writes the result to that flags word.

It subsequently reads descriptor fields to choose the new producer:

- If current producer plus \(L\), wrapped to 32 bits, equals current end, the new producer is the base read for that branch.
- Otherwise, the new producer is the producer read for the addition plus four times the original count, wrapped to 32 bits.

The new producer is written to descriptor offset 12.

These metadata and advancement operations occur after the dependency call. The dependency is not known to preserve the descriptor, the global address datum, or the Boolean destination. Nor are later descriptor reads guaranteed to match earlier reads if aliasing or concurrent mutation occurs.

### Split path

The function reads the region end again and computes:

- Tail length \(T\): that end minus initial producer \(P\), modulo \(2^{32}\).
- Head length \(H\): \(L-T\), modulo \(2^{32}\).

It retains the head length rounded downward to a multiple of four for eventual producer advancement.

F-7b852511e094 is invoked twice, in order:

| Call | Destination-like value | Source-like value | Byte length |
|---|---|---|---|
| First | Initial producer \(P\) | Argument 3 | \(T\) |
| Second | Descriptor base read after the first call | Argument 3 plus \(T\) rounded downward to a multiple of four | \(H\) |

Source-address addition wraps to 32 bits. Advancing by the rounded-down tail length is not necessarily the same as advancing by the exact tail length.

After both calls return, the function reads producer and base fields to derive:

- Tail start page from the producer-relative-to-base offset.
- Tail inclusive end page from that offset plus \(T-1\), wrapped before the page shift.

These calculations likewise do not establish an atomic descriptor snapshot.

The split-path metadata order is:

1. Read the tail start page’s flags word.
2. Write that word OR argument 7.
3. Apply the page-value selection rule to the tail interval.
4. Perform eligible head page-value assignments.

Head page-value handling is separate:

- If \(H\le4095\), no head page-value assignment occurs.
- Otherwise, let the head end page be \((H-1)\) logically shifted right by 12.
- If that end page is below \(R\), assign argument 6 to entries zero through that end page.
- Otherwise, if \(R\ne0\), assign argument 6 to entries zero through \(R-1\).
- If \(R=0\), assign no head page values.

Assignments proceed in increasing index order. Once the 4,096-byte threshold is reached, the head interval can include a partially covered final page. There is no separate head-page flags update.

Finally, the function reads the current base, adds \(H\) rounded downward to a multiple of four with 32-bit wrapping, and writes the result as the producer position.

### Common completion

After either accepted path:

1. Read the current counter at offset 24.
2. Add \(L\) modulo \(2^{32}\) and write the counter.
3. Read the current producer at offset 12.
4. Write that value to the mirror at offset 16.
5. Return acceptance.

Dependency results are ignored. No explicit dependency-failure status or rollback path is present. Acceptance describes the normal-return path through this function, not proof of successful data transfer.

## Side effects

The explicit accepted-path ordering is:

| Stage | Contiguous path | Split path |
|---|---|---|
| Indirect Boolean operation | Read global address datum, then store through obtained pointer | Same |
| Subsequent descriptor observation | Read base for protected page, then end for path selection | Same |
| Dependency activity | One call | Tail call, then head call |
| Metadata | Page values, then start-page flags | Tail start-page flags, then tail values, then eligible head values |
| Producer update | Write producer | Write producer |
| Accounting | Read and write counter | Read and write counter |
| Publication | Read producer, write mirror | Same |

The indirect Boolean store can affect later behavior if its destination aliases subsequently read storage. It can also overlap the address-bearing datum itself; no disjointness guarantee is supplied. Such overlap does not retroactively change the pointer already obtained for that store, but may affect later observations of the datum.

Metadata overlap makes path-dependent ordering observable. A split-path page-value assignment can overwrite an earlier flags update; a contiguous-path flags update can modify a word previously assigned as a page value.

No explicit allocation, release, or ownership transfer is visible in this function. This does not establish the dependency’s ownership behavior. No synchronization primitive or memory barrier is visible, and the stated ordering is not a concurrent publication guarantee.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless overridden, assume valid storage, stable non-aliasing descriptor fields, no arithmetic overflow, a Boolean destination disjoint from relevant storage, and a dependency that returns without modifying that state.

1. **Exact availability is rejected.**  
   With 16 bytes available and a count of four units, the lower return word is `0xffffffff`. No dependency call, global address-datum read, or explicit write occurs.

2. **Equal positions use capacity.**  
   With equal producer and consumer positions, capacity-like value 64, and count three, \(L=12\) is accepted. Equal positions are not independently classified as full or empty.

3. **Boolean destination is selected indirectly.**  
   If the global datum contains address \(X\), an accepted request with flags `0x02` stores true through \(X\), then reads the descriptor base. If a later invocation observes address \(Y\), its store targets \(Y\); this function imposes no constant-address requirement.

4. **Boolean aliasing can affect the protected page.**  
   If the indirect store changes the descriptor base through overlap, the protected-page calculation uses the base observed after that store. The already captured consumer and producer values are not refreshed. The precise changed base depends on Boolean representation and overlap, which remain documented_only.

5. **Exact-end contiguous request wraps the producer.**  
   With producer 16 bytes below end and an admitted four-unit request, there is one 16-byte dependency call. With descriptor fields preserved, producer and final mirror become base.

6. **Protected-page selection truncates updates.**  
   For page interval 2 through 5 and \(R=3\), only page-value entry 2 is assigned. Entries 3 through 5 are excluded from that interval’s assignments.

7. **Short split head omits head metadata.**  
   With a 16-byte tail and admitted 32-byte request, calls have lengths 16 and 16. The second source advances by 16; no head page value is assigned; producer becomes base plus 16.

8. **Unaligned split lengths expose rounding.**  
   With a six-byte tail and ten-byte head, the second source advances by four, its length is ten, and producer becomes base plus eight. This describes arithmetic, not supported alignment.

9. **Flags use all supplied bits.**  
   An observed flags word `0x10` combined with argument 7 equal to `0x06` yields `0x16` at that update. The earlier indirect Boolean store writes true. Later overlapping assignments may replace the flags word.

10. **Zero length is not a no-op guarantee.**  
    If availability is positive, zero length is admitted and reaches a dependency call. At relative producer offset zero, subtracting one produces end-page index `0xfffff`. The protected-page rule still controls assignments; the large index alone does not guarantee a large write sequence.
