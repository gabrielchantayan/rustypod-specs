# F-6c7ac9769d41

## Purpose

F-6c7ac9769d41 performs an accounting-and-dependency sequence for a nonzero address-like input. It normalizes that input using preceding metadata, updates an initial pair of accounting words, selects a later accounting context, validates metadata, and conditionally updates further counters before invoking two final dependencies.

**Established static behavior:** zero input returns immediately; nonzero input triggers an initial dependency and accounting operations; a normalized address of 8 bypasses the later stage; certain metadata values invoke a dependency represented as non-returning.

**Inferred intent:** the metadata layout, masks, and counter changes are consistent with releasing an allocation and updating allocator statistics. They do not establish that memory is reclaimed, that ownership changes, or that any dependency provides synchronization.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

### Input and return

The function accepts one address-like value represented by a 32-bit integer and returns no value.

For nonzero input, the caller or execution environment must provide accessible storage for every address reached on the selected path. The function does not generally validate mapping, alignment, allocation provenance, selector bounds, or accounting-context validity.

The representation distinguishes:

- 32-bit address-like integers and full-width metadata.
- Unsigned 32-bit amounts and many accounting operations.
- Unsigned 16-bit category selectors.
- Signed 32-bit intermediate values, including the returned index and the two later count decrements.

Unsigned arithmetic wraps modulo \(2^{32}\). This does not independently establish the behavior of every signed address calculation, signed multiplication, or signed decrement at its overflow boundary. Those boundaries remain documented_only.

### Metadata layout

Let **P** denote the original nonzero input. After the initial dependency returns, a 32-bit displacement is read at P − 4 and subtracted from P to obtain the normalized address **B**.

| Address | Width | Role |
|---|---:|---|
| P − 4 | 32 bits | Displacement used to obtain B |
| B − 16 | 32 bits | Validation flags and masked accounting amount |
| B − 12 | Unsigned 16 bits | First category selector |
| B − 10 | Unsigned 16 bits | Second category selector |
| B − 8 | Unsigned 32 bits | Amount for the initial accounting update |

The displacement access need not be disjoint from the normalized metadata. No non-overlap constraint is established.

Two separate global roots are used:

- An initial accounting-context root, evaluated several times around the first accounting update.
- A separate global indirection, dereferenced after an intermediate dependency to obtain the later context **C**.

Neither root is established as immutable, and the two contexts are not established as disjoint.

## Behavior

### Zero input and initial dependency

Zero input returns without invoking dependencies or explicitly accessing metadata or accounting storage.

For nonzero input, the function first invokes **F-8d9399c13232**, passing P. Metadata and global-root observations described below occur after that dependency returns and therefore can reflect its effects.

The function then captures the current value of the initial accounting-context root. A second check of the input follows. No represented assignment changes the input before that check, so under ordinary call semantics an initially nonzero input cannot take this second return. It is not a validity check on the pointed-to storage.

The function reads the displacement at P − 4, obtains B, and reads the unsigned 32-bit amount **S** at B − 8. There is no explicit check that B is nonzero, lies within an allocation, or has any particular relationship to P beyond the displacement calculation.

### Initial accounting update: address capture and access order

The first accounting update must not be reduced to an unconditional two-word operation on one stable context. Its destination and source addresses use separately captured root values.

The observable sequence is:

1. Capture the initial accounting-context root, after F-8d9399c13232 and before normalization. This captured value determines the eventual **high-word write destination**, at offset +0x3c.
2. After normalization and the read of S, evaluate the root again and read the unsigned low word at that value plus 0x38. Call the value read **L**.
3. Evaluate the root again and capture the **high-word read address**, at that value plus 0x3c. The high word itself is not yet read.
4. Evaluate the root again to obtain the **low-word write address**, at that value plus 0x38.
5. Store \((L-S)\bmod 2^{32}\) at the low-word write address.
6. Read the high word through the previously captured high-word read address.
7. Store the computed high-word result through the high-word write destination determined by the initial root capture.

Thus the high-word read occurs **after** the low-word store, but its address was captured **before** that store. The high-word write destination uses the initial root value, not a fresh evaluation after the low-word store.

Let **H** be the 32-bit bit pattern read at step 6. Let **b** be 1 if L is less than S under unsigned comparison, otherwise 0. Define \(\sigma(S)\) as 0 when bit 31 of S is clear and −1 when that bit is set, reflecting the represented signed arithmetic right shift. The high-word result is:

\[
(H-\sigma(S)-b)\bmod 2^{32}.
\]

For stable, disjoint storage, both words belong to the same context. In that case:

- If S has bit 31 clear, the high word decreases only on a low-word borrow.
- If S has bit 31 set, the high word increases by one, then decreases by the borrow.

This is not ordinary subtraction of a zero-extended unsigned 32-bit quantity from a 64-bit counter.

Aliasing can affect more than root identity. If the low-word destination overlaps the captured high-word source, the high-word calculation uses the value present **after** the low-word store. If the low-word store changes root storage, neither the captured high-word source address nor the initially captured high-word destination is recomputed.

### Intermediate dependency and late bypass

After the initial accounting stores, the function invokes **F-2fd8826557a4** without explicit arguments.

Only after that call returns does it read the separate global indirection to obtain C. This selection must reflect the post-call state; the dependency is not assumed to preserve global roots.

The function then compares B with the numeric address value 8.

If B equals 8, it returns without performing the later validation, later-stage counter-update statements, or final dependency calls. The following have already occurred:

- The initial dependency.
- Normalization and the read of S.
- Both initial accounting stores.
- F-2fd8826557a4.
- Selection of C through the separate indirection.

For B equal to 8, the earlier S read at B − 8 accesses numeric address zero. Reachability of a normal return therefore depends on that access being permitted by the execution environment.

### Metadata validation

For B other than 8, the function reads the 32-bit word at B − 16 and tests it for zero. If that read is nonzero, it reads the word again and tests bit 0.

**F-a817d8d58c10** is invoked if:

- The first validation read is zero; or
- The first read is nonzero and bit 0 of the second validation read is set.

The dependency is represented as non-returning. No normal continuation from this failure branch is represented.

The two checks are not an atomic metadata snapshot. If the first read is nonzero but the second is zero, the bit test does not itself reject that second value.

Failure occurs after the initial accounting update and F-2fd8826557a4, with no rollback. No later-stage counter-update statement has executed at that point. This does **not** mean that later-context counters are unchanged: earlier stores may overlap them, and preceding dependencies may modify them.

### Later accounting stage

After validation passes, the function invokes **F-c0fc6d033caa** with C.

C remains the captured context value for subsequent explicit context-relative accesses and final calls. A dependency changing the global indirection does not by itself replace this captured value. The dependency may nevertheless change memory reachable through C or B.

The function next:

1. Reads the first unsigned 16-bit selector at B − 12 and forms its category address.
2. Reads the metadata word at B − 16 again.
3. Masks that word with 0x3ffffffc to obtain the accounting amount **M**.

M is a multiple of four between 0 and 0x3ffffffc inclusive. The mask removes bits 0, 1, 30, and 31. Validation does not require M to be nonzero, and the post-dependency read supplying M is not revalidated.

The following updates occur in order:

| Order | Address | Update |
|---:|---|---|
| 1 | C + 0x224 + four times the first selector | Subtract M |
| 2 | C + 0x30c | Subtract M |
| 3 | C + 0xe0 + four times the second selector | Subtract M |
| 4 | C + 0x220 | Subtract M |

The second unsigned 16-bit selector is read at B − 10 **after** update 2 and before update 3. Consequently, earlier stores that overlap that selector can affect the selected address.

Each update reads the destination’s current 32-bit value and writes the unsigned subtraction result modulo \(2^{32}\). M is reused for all four updates, even if those stores alter the metadata word.

Neither selector is range-checked. Each can represent 0 through 65535, giving a scaled offset up to 0x3fffc before addition of the fixed category offset. Valid storage for the selected addresses is an external precondition.

The function then invokes **F-09dcb55e8e0a** without explicit arguments. Its returned integer supplies an index for the remaining operations:

1. Decrement the signed 32-bit word at C + 0x310 + four times the returned index.
2. Decrement the signed 32-bit word at C + 0x390.
3. Read the metadata word at B − 16 again, mask it with 0x3ffffffc, and subtract that newly obtained unsigned amount from the 32-bit word at C + 8.

The returned index is not checked. Its valid range, signed address-arithmetic boundaries, and signed-decrement overflow behavior are not independently established.

For the final amount subtraction, both the current counter value and the newly read masked metadata contribute to the result. Their relative read order within that expression is not independently established; both precede the store. The metadata read occurs after the preceding count-decrement statements.

The final amount need not equal M. F-09dcb55e8e0a or an overlapping counter store may have changed the metadata. No renewed validity check occurs.

### Final dependency sequence

After the explicit accounting updates, the function invokes:

1. **F-cc6c9b4a0f68**, with C and B − 16.
2. **F-e586bff64fb7**, with C.

The second call occurs only if the first returns. Normal return from the function follows only if the second also returns.

There is no represented status result, retry, or rollback.

## Side effects

The function directly performs two initial accounting stores and, on the validated non-bypass path, seven later accounting stores. These are seven update operations, not necessarily seven distinct locations.

Computed addresses can overlap. For example:

- First selector 58 targets C + 0x30c, also updated immediately afterward.
- Second selector 80 targets C + 0x220, also updated immediately afterward.
- Returned index 32 targets C + 0x390, also decremented immediately afterward.

Overlapping updates observe preceding stores rather than using one common original value. The two accounting contexts, their global roots, and metadata are not established as mutually disjoint.

No explicit atomic operation or concurrency protocol is established. Dependency placement may suggest synchronization, but that interpretation requires dependency contracts not supplied here.

Ownership remains unknown. Passing B − 16 to F-cc6c9b4a0f68 does not establish deallocation, ownership transfer, retention, or permission to reuse storage. No explicit metadata write follows that call.

Invalid accesses have no represented recovery path. Unsigned accounting subtraction does not report underflow.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume accessible, suitably aligned storage; stable roots; disjoint locations; returning non-failure dependencies; and no dependency-induced metadata changes.

1. **Zero input.** Input zero returns without dependency calls or explicit accounting accesses.

2. **Low-word borrow.** With S = 5, L = 3, and H = 9, the initial update writes low word 0xfffffffe and high word 8.

3. **High-bit amount.** With S = 0x80000000, L = 0x90000000, and H = 9, the initial update writes low word 0x10000000 and high word 10. Treating S as zero-extended and leaving H at 9 would not match.

4. **Root storage overwritten by the low store.** Suppose the initial root contains address A and is itself stored at A + 0x38. All root evaluations before the low store observe A. If that store changes the root, the subsequent high-word read and write still use A + 0x3c; neither address is selected again from the changed root.

5. **Late bypass.** If B = 8 and the earlier address-zero read is permitted, the initial update, F-2fd8826557a4, and selection of C occur before return. Later validation and final dependencies do not occur.

6. **Invalid metadata.** A stable metadata value of zero invokes F-a817d8d58c10. Stable values 0x101 and 0x103 also invoke it because bit 0 is set. Earlier effects remain; these values do not reach the M-based updates.

7. **Valid ordinary amount.** Stable metadata 0x102 passes validation and masks to 0x100. Each of the first four later amount updates subtracts 256. If the metadata remains unchanged, the final C + 8 subtraction also uses 256.

8. **Zero masked amount.** Stable metadata 2 passes validation and produces M = 0. The amount-update statements still execute, and the two count decrements still occur. The path is not a no-op.

9. **Changed final amount.** If M = 0x100 and F-09dcb55e8e0a changes the metadata to 0x202, the first four amount updates use 0x100 while the final subtraction uses 0x200, without renewed validation.

10. **Overlapping category counter.** First selector 58 causes two consecutive subtractions of M from C + 0x30c. With no other change, its net reduction is twice M modulo \(2^{32}\).

11. **Failure with overlapping contexts.** If an initial accounting destination coincides with a later-context counter, that counter may already have changed when metadata validation fails. Failure prevents later-stage update statements, not all changes to those locations.
