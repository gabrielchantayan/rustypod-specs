1. Read four bytes at selected-base byte offset `0x7FFF4`.
2. Write that value to the first output address.
3. Read four bytes at selected-base byte offset `0x7FFF0`.

The offsets follow from four-byte element indexing:

- Element index `0x1FFFC` corresponds to byte offset `0x7FFF0`.

The source addresses are therefore adjacent four-byte locations, but they are accessed in descending address order: the higher-addressed value is copied first.

The second write targets the original second output address, not the selected base merely because the pointer slot may have been replaced. Replacing that slot changes the extraction source; it does not redirect either output destination.

### Ordering and aliasing

The order of the successful-path accesses is behaviorally significant. The function does not visibly snapshot both source values before writing either output.

If the first output address overlaps the second source location, the first write can change the value subsequently read for the second output. The second output then receives the value present after that first write, not necessarily the value that existed when the dependency returned.

If both output addresses are identical, both writes still occur in order. Assuming both accesses complete, the final contents are those produced by the second write. This is not necessarily an initial source value when source/destination overlap also exists.

If the second output write overlaps either source location, it occurs only after both source reads. That overlap cannot retroactively change the already-read values, although it can change the source storage’s final contents.

There is no overlap rejection or explicit alias-handling branch.
