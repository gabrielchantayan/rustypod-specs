# F-72b51d9ef411

## Purpose

F-72b51d9ef411 classifies an object into one of three numeric states by examining up to two bytes in an indirectly referenced record.

The established result mapping is:

- **0:** the first examined byte is zero.
- **1:** the first examined byte is nonzero and the second examined byte is zero.
- **2:** both examined bytes are nonzero.

The first byte gates access to the second byte. When the first byte is zero, the second byte is not examined.

Interpreting these bytes as flags is reasonable inferred intent, but their application-level meanings are unknown. The available evidence does not establish names such as “enabled,” “ready,” or “error” for any state.

The supplied representation uses a 32-bit integer argument for address calculations and a 32-bit load for an indirect address. This contract therefore describes the represented 32-bit address model. It does not establish compatibility with a different pointer width or a native pointer-based interface.

|---|---:|---|

## Behavior

### Classification and access order

The established behavior has a short-circuit structure.

First, the function reads the 32-bit address slot at offset `0xF00` from the input base. It uses that address to read the first classification byte at offset `0x1C`.

If the first byte equals zero, the function returns 0. It does not proceed to the second classification byte.

If the first byte is nonzero, the supplied representation reads the address slot at input base plus `0xF00` again. It then reads the second classification byte at offset `0x8E` from the address obtained by that second read.

A zero second byte produces result 1. Any nonzero second byte produces result 2.

Consequently, the represented logical read sequences are:

| Condition | Ordered reads | Result |
|---|---|---:|
| First byte is zero | Address slot; first byte | 0 |
| First byte is nonzero, second byte is zero | Address slot; first byte; address slot again; second byte | 1 |
| Both bytes are nonzero | Address slot; first byte; address slot again; second byte | 2 |

There are no represented writes between these reads.

### Byte interpretation

Each classification byte is tested only for equality with zero.

No individual bit is singled out, and no nonzero magnitude has a distinct meaning. For example, byte values `0x01`, `0x80`, and `0xFF` all take the nonzero branch.

Whether a character-sized value is interpreted as signed or unsigned does not change these decisions. A high-bit-set byte remains unequal to zero under either interpretation.

### Address stability

The repeated address-slot read matters to the behavioral description. The supplied representation does not retain the first address explicitly for use in the second-byte access.

With stable ordinary memory, both reads yield the same record address. If the slot changes between reads, the represented accesses can inspect the first byte in one record and the second byte in another.

This observation does not establish that concurrent mutation is supported. There is no evidence of synchronization, atomic operations, volatile qualification, or a defined concurrent-memory contract. Nor does the supplied representation establish the exact number of physical bus transactions in executable code.

### Arithmetic boundaries

The offsets select addresses; they do not compute the classification result. No byte value is added, multiplied, truncated into another state, or used as an array index.

The evidence does not establish safe behavior when adding an offset exceeds the valid address range or leaves accessible storage. Such cases are outside the normal-completion preconditions. They must not be assigned an invented result based on presumed address wrapping.

## Acceptance examples

These examples are conditional contract examples derived from static evidence. They are not reports of executed tests.

### First byte clear

Given a readable address slot and a referenced record whose byte at offset `0x1C` is `0x00`, the expected result is 0.

The byte at offset `0x8E` is irrelevant to this execution. It need not be read, and this branch does not require its address to be accessible.

### First byte set, second byte clear

Given a stable address slot, a first byte of `0x01`, and a second byte of `0x00`, the expected result is 1.

Changing the first byte to `0x80` or `0xFF` does not change that result while the second byte remains zero.

### Both bytes set

Given a stable address slot, a first byte of `0x02`, and a second byte of `0x80`, the expected result is 2.

The result remains 2 for any replacement values that leave both bytes nonzero. There is no requirement that a “set” byte equal exactly 1.

### Conditional address replacement

If the first slot read yields record A and its first byte is nonzero, while the second slot read yields record B, the represented decision uses record B’s second byte.

If that byte is zero, the result is 1; otherwise, it is 2. This example describes the represented read sequence, not a guarantee for unsynchronized concurrent updates.
