# F-45c4da8c8b13

## Purpose

F-45c4da8c8b13 performs unconditional preparation followed by a control-bit-gated selection operation. Preparation includes clearing one byte in each of five fixed-stride records. When enabled, the function requests a selection, optionally processes the selected record, and assigns the retained selection result through a globally supplied result-location reference.

For a selection other than −1, a comparison-like dependency determines the function’s return byte and whether an additional external operation occurs. A zero result suppresses that operation and produces return value 1. A nonzero result causes three destination bytes to be saved, an external call to be made, and the saved bytes to be restored; the function then returns 0.

The additional external call receives a destination reference, a selected-record address, and integer argument 12. Its implementation and authoritative mapping are not supplied. **Neither copying nor any particular memory access by that dependency is established.**

These are control-flow and access requirements, not application semantics. Interpreting the function as updating a current record while retaining destination-specific metadata is inferred intent only.

## Interface

### Inputs and return value

The function has no explicit arguments. Its inputs come from global references, referenced memory, and dependency results.

Its declared return is a byte, treated as an unsigned 8-bit value in the supplied representation:

| Path | Return |
|---|---|
| Control bit clear | The full control byte obtained by a second read |
| Control bit set; selection is −1 | 0 |
| Control bit set; selection is not −1; comparison result is zero | 1 |
| Control bit set; selection is not −1; comparison result is nonzero | 0 |

The disabled-path return is not a Boolean conversion. The control byte and its reference are evaluated again after the enable test. With stable state, a disabled return has bit 0 clear; without stability, the second read need not equal the tested byte.

### Referenced state

The following names describe roles, not source identifiers:

| Role | Use |
|---|---|
| Reset-table reference | Supplies the base retained for five byte-clearing stores |
| Control-object reference | Supplies the address whose byte at offset 11 is tested and, on the disabled path, read again |
| Selection-table reference | Supplies the base used in selected-record address calculation |
| Destination-object reference | Supplies the comparison argument, preservation-read addresses, external-operation argument, and retained restoration address |
| Result-location reference | Supplies the location assigned the retained selection result on enabled completion |

These roles are not proven to identify separate allocations. In particular, the reset and selection tables are not established to be the same table, despite both using a 20-byte stride.

### Widths, offsets, and arithmetic

The directly accessed control, reset, preservation, and restoration fields are one byte wide.

The reset stores target base-relative offsets **14, 34, 54, 74, and 94**. Only these five byte locations are directly accessed by the reset loop. The evidence does not require every byte in the surrounding 100-byte span to be accessible.

The selected-record address is calculated using a stride of 20 bytes. This establishes neither a 20-byte record allocation size nor a table capacity. The preservation and restoration offsets are 7, 6, and 11.

Selection and comparison results are retained in signed integer locals. The supplied representation is consistent with a 32-bit integer model, but runtime ABI confirmation is absent. Multiplication by 20 and addition to the selection-table base have no visible overflow checks. Behavior outside valid arithmetic and address ranges is **documented_only**.

The external operation receives integer argument 12. That value is not independently established to be a byte count, a record size, or an accessible-memory requirement.

The result-location pointer’s pointee type is not supplied. Consequently:

- The function assigns the retained integer selection result through that pointer.
- The destination store’s width, signedness, representation, and conversion behavior are unknown.
- A signed integer local does **not** establish a signed 32-bit destination write.
- Exact result-storage bytes cannot be specified without the missing destination type.

### Preconditions for normal completion

All directly accessed byte locations must be valid for their respective reads or writes. Selected-record address arithmetic must produce an address usable by the dependencies that receive it. The result-location reference must identify a valid assignment target under its actual, unspecified type.

Dependencies must return normally and leave subsequently used addresses valid for execution to reach normal completion. This is a condition on safe execution, not an established guarantee about those dependencies.

## Behavior

### Unconditional preparation

Every invocation begins with the same dependency sequence:

- F-a8e1b074c923 receives integer arguments 3 and 1.
- F-a8e1b074c923 then receives 4 and 1.
- F-b91c8a6c3b55 is called without arguments.
- F-781bd4260eaf receives 3.
- F-9843a1e76b20 receives 4.

Only after those calls does the function capture the reset-table base. Using that retained base, it clears the five reset bytes in ascending offset order: 14, 34, 54, 74, then 94. The base is not reloaded between those stores.

F-781bd4260eaf then receives 4. The enable check follows this call, so all preparation occurs even when selection is disabled.

No result from these preparation dependencies is used to select an error branch. Their possible effects on globals or referenced memory are not specified.

### Control-bit gate

The function obtains the control-object reference and tests bit 0 of its byte at offset 11.

If that bit is clear, the function evaluates the control reference and byte access again, returning the entire byte from that second access. It does not request a selection, perform selected-record processing, or assign a selection result.

The separate accesses matter when references or memory can change. A behavioral substitute must not replace the disabled return with constant zero or simply return the previously tested byte.

If bit 0 is set, the function proceeds to selection. The control byte is not used as the enabled-path return value.

### Selection and sentinel handling

F-222833e3624b receives integer argument 0. Its returned integer is retained as the selection result.

Exactly −1 means that selected-record processing is skipped. On that path, the function proceeds directly to the enabled-path result assignment and returns 0.

Every other value enters selected-record processing. No visible check rejects:

- Negative selections other than −1.
- Indices above 4.
- Indices beyond an allocation’s capacity.
- Values that make stride arithmetic overflow or produce an invalid address.

The five reset records therefore do not establish a valid selection range of 0 through 4.

### Selected-record processing

For a selection other than −1, F-9843a1e76b20 first receives 3. The function then reads the selection-table base and calculates the selected-record address using the retained selection and the 20-byte stride.

F-3c3879b3cad3 receives integer argument 1 and that address. Its result is not used.

F-d1a3481e68e2 next receives the same retained selected-record address and a destination address obtained from the destination-object reference. The selected-record address is not recalculated after either dependency returns.

After F-d1a3481e68e2 returns, the function reads and retains the then-current destination-object reference. This retained address is used for any restoration stores. The function also records whether the comparison result was zero.

The destination supplied to comparison can differ from the retained post-comparison destination. No contract establishes that comparison preserves the global destination reference.

### Nonzero-result external operation

A zero comparison result skips all three preservation reads, the external operation, and all three restoration stores.

For a nonzero result, the function reads destination bytes in this order:

1. Offset 7.
2. Offset 6.
3. Offset 11.

Each access obtains its address through the destination-object reference rather than through the retained restoration address.

The function then calls F-627c0a9d4e15 with:

- The current destination-object reference.
- The retained selected-record address.
- Integer argument 12.

The established behavior is the invocation and its arguments. The evidence does not establish that this dependency copies data, reads 12 bytes, writes 12 bytes, writes the destination at all, or leaves other memory untouched.

If the dependency returns normally, the function restores the saved bytes at offsets 7, 6, and 11, in that order, using the destination address retained immediately after comparison. These stores occur regardless of what the external operation actually did.

Thus, preservation reads, the external-operation destination argument, and restoration stores need not refer to the same object if the global reference changes. The familiar interpretation “replace twelve bytes except three fields” is valid only under additional, explicit assumptions about dependency semantics and address stability.

### Completion and result assignment

Every selected-record path that completes normally calls F-2d55a2d7c401 without arguments, followed by F-781bd4260eaf with argument 3. Both calls occur whether comparison returned zero or nonzero.

After these calls, the function obtains the current result-location reference and assigns the original selection result through it. The same assignment stage is reached directly when selection was −1, without the selected-record completion calls.

The assignment’s source is the selection result, not the comparison result and not the return byte. Its destination representation remains unspecified because the pointee type is missing.

The enabled return is 1 only for a non-sentinel selection whose comparison result was zero. Otherwise it is 0. Later dependency activity does not cause the comparison to be repeated.

## Side effects

### Established direct accesses and writes

Direct writes established by the representation are:

- Five one-byte zero stores during preparation.
- Three one-byte restoration stores on a nonzero comparison result, after F-627c0a9d4e15 returns.
- An assignment through the current result-location reference on every enabled path reaching completion, with unknown destination width and conversion.

The function directly reads the control byte and, conditionally, the three preservation bytes. Passing selected-record or destination addresses to a dependency does not establish that dependency’s internal access pattern.

All dependency side effects remain separate from these direct effects.

### Ordering and aliasing

Preparation precedes the control test. Preservation reads precede F-627c0a9d4e15; restoration stores follow it. Selected-record completion calls precede the final result assignment.

The operation is not shown to be transactional. There is no rollback branch or explicit recovery path.

Aliasing is not excluded. Reset writes may affect a control byte or another referenced object if their storage overlaps. Likewise, the final result assignment may affect previously restored bytes if its target overlaps them. Exact consequences of that assignment require its missing destination type.

The described ordering is the access sequence exposed by the supplied representation. Hardware-level visibility, atomicity, and synchronization are not established.

### Ownership and lifetime

The function contains no explicit allocation or deallocation operation. This does not establish that its dependencies allocate nothing, release nothing, or preserve object lifetimes.

Neither passing an address nor retaining it establishes ownership transfer. Dependencies must not invalidate addresses needed later if execution is to complete safely, but their actual lifetime guarantees are unknown.

A dependency that does not return normally prevents later operations from being established to occur. No dependency-specific error, exception, or termination semantics are supplied.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Normal dependency return and valid accessed storage are prerequisites unless stated otherwise.

### Disabled, stable control

With a stable control byte of 0x80:

- All preparation calls and reset stores occur.
- Selection is not requested.
- The return byte is 0x80.
- No final selection-result assignment occurs.

A stable control byte of 0x00 similarly returns 0x00. If the byte changes after the gate test, the disabled return follows the second read instead.

### Enabled, sentinel selection

If the gate is enabled and selection returns −1:

- No selected-record address is passed to processing or comparison.
- No preservation, F-627c0a9d4e15 invocation, restoration, or selected-record completion calls occur.
- The final assignment uses −1 as its source value and the then-current result-location reference as its target.
- The return byte is 0.

This does not specify that four bytes containing signed −1 appear in memory. That expectation requires an authoritative result-location type.

### Selected record, zero comparison

For selection 2, valid arithmetic, and comparison result zero:

- The selected-record address is the selection-table base plus 40 bytes.
- Processing precedes comparison.
- No preservation reads, F-627c0a9d4e15 call, or restoration stores occur.
- The two selected-record completion calls occur.
- The final assignment uses selection value 2, subject to the unknown destination conversion.
- The return byte is 1.

### Selected record, nonzero comparison

With a stable destination reference and nonzero comparison result:

- Bytes at offsets 7, 6, and 11 are saved in that order.
- F-627c0a9d4e15 receives the destination, retained selected-record address, and integer 12.
- After normal return, the saved bytes are written back at offsets 7, 6, and 11 in that order.
- Completion calls and the selection-result assignment follow.
- The return byte is 0.

No expectation about the other destination bytes follows from the supplied evidence.

**Conditional copy interpretation:** If a separate authoritative contract establishes that F-627c0a9d4e15 successfully copies exactly 12 bytes from its second address to its first, then stable, valid, nonoverlapping addresses imply that, immediately after restoration, offsets 0–5 and 8–10 contain copied values while offsets 6, 7, and 11 contain their saved values. Final-state expectations additionally require that subsequent dependencies and the result assignment do not alter those bytes.

### Changed reference and negative selection

If comparison changes the destination reference, restoration uses the post-comparison address, not necessarily the address supplied to comparison. Later reference changes do not redirect the retained restoration address.

If selection returns −2, the function enters selected-record processing rather than taking the sentinel path. With valid signed arithmetic, the calculated address is 40 bytes below the selection-table base. Safe execution still depends on accessible storage and dependency requirements.
