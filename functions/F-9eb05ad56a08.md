# F-9eb05ad56a08

## Purpose

The supplied static representation describes an operation that interleaves numerous indirect dependency calls with computed-address memory writes, then enters a loop with no represented exit.

No application-level purpose is established. The arithmetic resembles scaled addressing and extraction of packed fields, but interpreting the operation as serialization, allocation, initialization, rendering, or device control would exceed the evidence.

This contract describes the visible sequence conditionally: execution must reach each operation, dependencies must return where required, and preceding memory accesses must succeed. It does not establish that the supplied representation is a complete or faithful account of executable behavior.

## Behavior

### Execution and ordering rules

Many calls show no explicit arguments. This means only that no arguments are represented at that call site; it does not prove that the dependency consumes no machine state.

The descriptions below identify significant results by their roles and order. Different results are not assumed equal merely because they undergo the same arithmetic.

### Initial call sequence and inherited-state write

Execution begins with an indirect call whose target depends on inherited control state. It then performs two result-producing calls, each followed by a call receiving the corresponding opaque 32-bit result. Additional calls follow.

After a later call produces an integer result, the function:

1. Writes the inherited 32-bit payload to the inherited base plus 20 bytes.
2. Calls another dependency with four times that result.
3. Performs further intervening calls.

There is no visible validation of the inherited base before the write.

### Early scaled word operations

A subsequent integer-producing call supplies the first scaled-address value. The function:

1. Forms four times that value.
2. Logically shifts Input 3 right by seven bits.
3. Writes the four-times value to the address formed by sixteen times the original result plus 20.
4. Reads a 32-bit word from the four-times value plus 20.
5. Calls a dependency with the four-times value in both represented argument positions.

A further call sequence includes opaque result forwarding. After another integer-producing call, the function writes the previously read word, logically shifted right by eight, back to the same four-times-plus-20 address.

The read value is therefore a snapshot taken before the intervening calls. The later write does not reload that word. Changes made to the destination by those dependencies can be overwritten.

After another scaled-result call and intervening calls, the function writes a new four-times result to its corresponding sixteen-times-plus-20 address.

It next calls a dependency with \(H\), performs more calls, and writes that preceding four-times result to its own four-times-plus-20 address. This is distinct from the earlier sixteen-times-based destination.

\[

This is a fresh byte read whenever evaluated. It is not a pointer-sized load or a read of a complete pointer object.

A subsequent unsigned 32-bit call result, called the **first byte-stage result**, determines a value shifted left by two. The function:

1. Reads the selector byte at \(Q+1\).
2. Writes the low byte of the shifted value to \(D(Q)\).
3. Calls a dependency with that shifted value in three represented argument positions.
4. Performs additional calls.
5. Reads the selector byte at \(Q+1\) again.
6. Writes the low byte of  
   \((\text{first byte-stage result}\mathbin{\&}\texttt{0x3fffffff})\mathbin{\mathrm{>>}}20\)

Because of final byte truncation, this second byte write retains bits 20 through 27 of the first byte-stage result. It does not retain all ten bits remaining after the mask and shift.

After another call sequence, a **second byte-stage result** is shifted left by two. The function then:

1. Writes the low byte of that shifted value to \((J\mathbin{\mathrm{>>}}7)+28\).
2. Reloads the selector at \(Q+1\) and writes zero to \(D(Q)\).
3. Calls a dependency with \(J\mathbin{\mathrm{>>}}7\).
4. Makes another call, then calls a dependency with  
   \((\text{second byte-stage result}\mathbin{\&}\texttt{0x3fffffff})\mathbin{\mathrm{>>}}6\).
5. Performs more calls.
6. Reloads the selector at \(Q+1\) and writes zero to \(D(Q)\) again.

Since \(J\) is at most 255, \(J\mathbin{\mathrm{>>}}7\) is either zero or one. Consequently, the separate byte destination is numerically either 28 or 29, subject to the represented address interpretation.

The repeated selector reads must not be collapsed into one read: intervening calls or aliasing writes may change the selected destination.

### Loop preparation and nonterminating tail

Before entering the loop, the function:

- Writes zero to a byte-selected destination whose selector address is the second byte-stage shifted value multiplied by 1024, plus one.
- Calls a dependency with twice the initial loop-carried word.
- Calls another dependency and retains its result.

Each represented loop iteration then:

1. Calls a dependency with the retained result and the loop-carried word logically shifted right by eight.
2. Performs several intervening calls and retains a fresh result.
3. Reloads the selector at the same computed selector address and writes zero to the selected byte address.
4. Calls a dependency with the fresh result shifted left by two.
5. Performs more calls and obtains another result.
6. Uses that result shifted left by two as the retained result for the next iteration.

The first iteration’s second represented argument is zero, because its initial loop-carried value is at most 31. Under 32-bit modular shift semantics, subsequent iterations derive that argument from the low six bits of the preceding iteration’s final result; it need not remain zero.

These are conditional acceptance criteria derived from the representation, not executed tests.

1. **Input 3 extraction:** If execution reaches the four-argument call, Input 3 of `0xffffffff` contributes `0x000007ff` as its fourth represented argument. Input 3 of `0x001fffff` contributes zero.

2. **Snapshot writeback:** If the early word read yields `0x12345678`, the subsequent writeback uses `0x00123456`. This remains the written value even if an intervening dependency changes the destination, assuming control returns normally.

3. **Fresh selector reads:** If the first selector read at \(Q+1\) yields 3, its byte destination is 20. If a later selector read yields 9, that later destination is 26. Reusing destination 20 would not preserve the represented behavior.

4. **Low-byte truncation:** If the first byte-stage result is `0x12345678`, its first byte write stores `0xe0`; its later masked-and-shifted byte write stores `0x23`.

5. **Narrow separate destination:** For \(W=\texttt{0x7fffffff}\), the separate byte destination is 28. For \(W=\texttt{0x80000000}\), it is 29.

6. **Initial loop argument:** For every initial loop-carried value permitted by its mask and shift, the first iteration passes zero as the second represented argument.

7. **Later loop argument:** Under 32-bit modular shifts, if an iteration’s final dependency result is 1, the next loop-carried word is `0x04000000`, and the following iteration’s second represented argument is `0x00040000`.

8. **Invalid memory:** If a required computed address is inaccessible, no explicit validation or recovery path is represented. The actual fault mechanism remains documented_only.
