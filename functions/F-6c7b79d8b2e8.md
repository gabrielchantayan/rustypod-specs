# F-6c7b79d8b2e8

## Purpose

The sequence depends on four explicit inputs, additional incoming machine state, dependency results, and memory contents. Numerical values returned by dependencies are used to form addresses; they are not established object pointers.

Three evidence categories apply throughout:

- **Established:** operations, widths, data dependencies, and sequencing explicitly present in the supplied representation.
- **Conditional interpretation:** consequences requiring additional assumptions, particularly 32-bit wrapping arithmetic and low-eight-bit byte conversion.
- **`documented_only`:** unresolved behavior, including dependency semantics and execution beyond the terminal boundary.

The representation contains invalid-instruction warnings and a truncated endpoint. This contract describes its visible path, not a verified executable trace.

### First selector read and byte write

Using the retained F-D040 result, the function calculates the selector address and reads an unsigned byte there. It adds 17 to the **loaded byte value** to obtain the byte-write destination.

Consequently, the destination is numerically between 17 and 272 inclusive. It is not the selector address plus 17.

The written byte is obtained by converting the F-D055 result shifted left by 2. Under low-eight-bit byte conversion, its stored bit pattern is:

\[
(4 \times \text{F-D055 result}) \bmod 256.
\]

F-D056 follows, receiving the F-D055 result shifted left by 2 twice, then that result shifted left by 4. The twice-used shifted value is represented through a signed 32-bit intermediate; exact conversion semantics require the machine interpretation.

F-D056’s target calculation uses an offset of 4,076 bytes. The other visible call-target calculations use 4,094 bytes. This distinction is part of the represented behavior.

F-D059 through F-D062 then execute in order. F-D062 supplies a result used later.

The function performs no direct memory write between F-D057 and F-D062. This does not restrict dependency memory effects.

### Second selector read and final calls

The function reads the selector address again, using the retained F-D040 result. This is a new read after intervening calls; neither equality with the first byte nor unchanged selector memory is guaranteed.

The newly loaded unsigned byte plus 17 determines the second byte-write destination. The written byte is the conversion of:

\[
(\text{F-D055 result} \mathbin{\&} 1{,}073{,}741{,}823) \gg 20.
\]

Before byte conversion, this expression ranges from 0 through 1,023. Under low-eight-bit conversion, only bits 20 through 27 of the retained F-D055 result reach memory. Bits 28 and 29 do not survive the byte narrowing.

F-D063 receives the retained F-D062 result shifted left by 2.

1. The F-D067 result shifted left by 2.
2. The unsigned byte captured by the second selector read.

The second argument is the captured selector byte, not a fresh read and not the byte written to the destination.

F-D069 is then invoked without explicitly represented arguments. The supplied representation ends immediately afterward at the invalid-instruction boundary.

These are conditional static examples, not executed tests. Unless stated otherwise, they require valid accesses, valid targets, returning dependencies, and arithmetic that represents the listed values.

5. **Scaled bits feed F-D046.**  
   If F-D040 returns 5, its scaled value is 20 and F-D046’s first argument is 327,680. Under 32-bit wrapping shifts, its third argument is 1,073,741,824.
