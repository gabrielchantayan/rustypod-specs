# F-e22a24a092b7

## Purpose

F-e22a24a092b7 conditionally refreshes three 32-bit fields in a caller-supplied context. It compares a value derived from an input record with one of two reference values selected by the record’s mode byte.

Three return values are established:

- **0:** the comparison matched, dependency F-1a1e9d85ae73 returned, and the three context-field assignments completed.
- **7:** the mode byte was neither 0 nor 1.
- **23:** the mode was supported, but the comparison did not match.

An optional call to F-870c4fcf7295 transforms the input value before mode validation. Consequently, return value 7 does not imply that no dependency ran or that no state changed.

The apparent intent is to validate a quantity in units of 64 and then refresh cached quantities from a metadata record. That interpretation is inferred from the arithmetic and field relationships; the source does not establish the application-level meaning of those quantities.

## Interface

### Arguments and result

The function receives four explicit arguments:

1. **Context pointer:** points to a writable sequence of 32-bit words. Its first word supplies an address used to locate two other records.
2. **Input-record pointer:** points to a record containing a mode byte and two 32-bit integer fields.
3. **Forwarded word:** a 32-bit value passed to F-1a1e9d85ae73 without direct interpretation by this function.
4. **Forwarded word:** another 32-bit value passed in the same manner.

The return value is one 32-bit word containing 0, 7, or 23 on the established normal-return paths.

The supplied representation uses 32-bit integer and address-bearing fields, 16-bit unsigned metadata fields, and an 8-bit mode. Byte order and alignment requirements are not established independently of that representation.

## Behavior

### Initial reads

Before validating the mode, the function obtains:

1. A metadata-record address through root offset 0x84.
2. A state-record address through root offset 0x20.
3. The 32-bit input quantity at input offset 0x08.
4. The 32-bit field at input offset 0x10.

Both referenced-record addresses are fetched regardless of which mode will eventually be selected. Their pointed-to contents are not both necessarily read.

The root address is obtained through the context for the two initial pointer loads. No external call occurs between those loads in the visible body. Concurrent modification and memory-mapped access behavior are not specified.

### Optional transformation

If the field at input offset 0x10 is zero, the initial input quantity remains the comparison quantity.

If it is nonzero, the function calls F-870c4fcf7295 with:

- First argument: the product of the field at input offset 0x10 and the previously read input quantity, increased by 36.
- Second argument: 72.

The dependency’s returned 32-bit value becomes the comparison quantity, interpreted as a signed integer by the subsequent arithmetic shown in the source.

The arithmetic supplied as the first argument is represented as signed 32-bit arithmetic. Signed overflow behavior is not established by the supplied evidence. Cases requiring overflow must not be assigned a portable mathematical or wraparound result.

F-870c4fcf7295 is not established to be pure. It may affect memory later read by this function, including the mode or pointed-to reference fields. The mode is read only after this optional call returns.

### Mode selection

The mode byte is first compared with zero.

- **Mode 0:** the reference value comes from the state record captured during the initial reads. The signed 32-bit field at offset 0x0C is increased by 32 and then right-shifted by six bits.
- **Nonzero mode:** the mode byte is read again and compared with 1. If it is 1, the reference is the unsigned 16-bit metadata field at offset 0x64, widened to 32 bits.
- **Any other mode:** the function returns 7 immediately.

For ordinary stable memory, this is a choice between modes 0 and 1 with all other byte values rejected. Because a nonzero mode is read a second time, the source does not establish one atomic mode snapshot.

The initial metadata and state addresses remain the ones used for mode selection even if F-870c4fcf7295 changes the corresponding root fields. Their contents, however, are read after that call.

### Comparison

The comparison quantity is increased by 32 and right-shifted by six bits. The resulting value is compared with the selected reference.

For nonnegative values whose addition does not overflow, this operation is:

\[
Q(x)=\left\lfloor\frac{x+32}{64}\right\rfloor
\]

Thus it groups values into 64-unit bins with the boundary shifted by 32. It is not a general checked rounding operation.

The right shifts are applied to signed expressions in the supplied representation. Negative signed right-shift behavior is not independently established. The selected reference is held as an unsigned 32-bit value, so the comparison uses the corresponding unsigned conversion of the shifted comparison quantity.

If the values differ, the function returns 23. No direct context-field assignments occur on that path.

### Successful refresh

If the values match, the function performs a refresh in this order:

1. Reads the root address from the context again and captures the metadata-record address at root offset 0x84.
2. Calls F-1a1e9d85ae73.
3. After that dependency returns, assigns context offset 0x18.
4. Assigns context offset 0x1C.
5. Assigns context offset 0x24.
6. Returns 0.

The metadata address is captured before the call, but its 16-bit contents are read after the call. Changes that the dependency makes to that captured record can therefore affect the outputs. Replacing the root’s metadata pointer during the call does not redirect these reads.

The output values are:

- **Context 0x18:** metadata 0x54, zero-extended and multiplied by 64.
- **Context 0x1C:** metadata 0x64 minus metadata 0x54, negated and multiplied by 64, using unsigned 32-bit arithmetic.
- **Context 0x24:** metadata 0x6A, zero-extended and multiplied by 64.

The first and third outputs lie between 0 and 4,194,240 inclusive.

For the middle output, an equivalent 32-bit bit-pattern description is:

\[
64 \times
(\text{metadata}_{0x54}-\text{metadata}_{0x64})
\pmod {2^{32}}
\]

If metadata 0x64 exceeds metadata 0x54, the stored word represents a negative multiple of 64 under a signed two’s-complement interpretation. The function does not reject that relationship.

Metadata 0x54 is read separately for the first and second assignments. The source does not establish the relative evaluation order of the two metadata reads within the second assignment. No combined metadata snapshot is taken.
