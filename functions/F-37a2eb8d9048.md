# F-37a2eb8d9048

## Purpose

F-37a2eb8d9048 selects a byte-range length, subtracts that length from one object field, invokes a preparatory dependency, dispatches an indirect callback with the selected range, adds the same length to another object field, and invokes a final dependency.

The selection rule is unusual: the third argument is **not an upper bound**. Before the running index reaches that argument, source bytes are not examined. At and after that index, a zero byte terminates selection. An object flag can impose a separate upper bound.

These are established static behaviors. Interpreting the fields as formatting width, output count, or string precision would be inferred intent, not an established contract. In particular, conventional bounded-string semantics must not replace the observed selection rule.

## Interface

### Arguments and return

The function accepts three machine-level arguments:

1. **Object address.** Identifies storage containing the fields listed below.
2. **Source address.** Identifies the origin used for byte inspection and for the callback’s range arguments.
3. **Threshold.** A signed integer controlling when zero-byte inspection begins.

The supplied representation uses 32-bit integer and address-bearing quantities. Object-field offsets are byte offsets. Source inspection uses one-byte character loads; only equality with zero matters, so character signedness does not affect the termination test.

There is no explicit return value, success indicator, or error code.

### Object layout used directly

| Byte offset | Width | Direct use |
|---|---:|---|
| `0x18` | 32 bits | Flag word; bit `0x20` selects bounded scanning |
| `0x20` | 32 bits | Encoded indirect-call target; its two least significant bits are cleared before invocation |
| `0x34` | 32 bits | Arithmetic field reduced by the selected length before the preparatory dependency |
| `0x38` | 32 bits | Signed scan limit, read only in bounded mode |
| `0x3c` | 32 bits | Arithmetic field increased by the selected length after the callback |

The arithmetic fields are represented as signed integers. The flag word and encoded target are represented as unsigned 32-bit values.

No other object fields are directly accessed in the supplied body. Dependencies may access additional state.

### Preconditions for a fully defined, normally returning execution

The caller and dependencies must collectively provide:

- Readable storage for each object field actually accessed.
- Writable storage for the two arithmetic fields when their updates occur.
- Readable source bytes at every address the selection rule examines.
- A usable indirect-call target after clearing the encoded target’s two low bits.
- Calling conventions compatible with all three calls.
- Object storage that remains usable for the accesses made after each dependency returns.
- Representable arithmetic and valid address formation under the applicable execution model.

An empty selected range does not bypass either dependency or the callback. It also does not bypass the initial flag read.

The function does not itself allocate storage, acquire ownership, or release memory. That observation does not establish ownership behavior for any dependency.

## Behavior

### 1. Choose the scanning mode

The selected length begins at zero.

The function reads the flag word at offset `0x18` and tests bit `0x20`:

- **Bit clear:** selection has no object-provided upper bound.
- **Bit set:** selection is bounded by the signed field at offset `0x38`.

This mode decision occurs before the calls. It is not repeated after a dependency changes the object.

### 2. Select the length

Selection proceeds using a nonnegative running index, subject to the arithmetic limitations described under Uncertainties.

At an examined index:

- If the index is less than the threshold, the function advances without reading the corresponding source byte.
- If the index is greater than or equal to the threshold, the function reads that source byte.
  - A zero byte stops selection at the current index.
  - A nonzero byte permits the index to advance.

Consequently, reaching the threshold does **not** stop selection by itself. At equality, the source-byte test determines whether selection stops.

A zero byte located before a positive threshold has no effect on selection because that byte is not inspected by this function.

#### Unbounded mode

There is no explicit limit check. Selection ends only upon observing a zero byte at an index greater than or equal to the threshold.

For a positive threshold, all earlier positions are counted without source reads. For a zero or negative threshold, zero-byte inspection starts at index zero.

If no qualifying zero byte is reachable before invalid access or arithmetic failure, the function has no explicit alternative termination or error path.

#### Bounded mode

Before applying the threshold and byte rules at each index, the function reads the signed limit at offset `0x38` and checks whether the index is strictly less than that limit.

If not, selection stops immediately. There is no source-byte read at that index.

For a stable limit:

- A zero or negative limit selects length zero.
- A positive limit permits inspection or advancement only for indices below the limit.
- Selection may end at the limit without having observed any zero byte.
- If the threshold is at least the positive limit, the selected length equals the limit and this function performs no source-byte reads.

The limit is read repeatedly, rather than visibly cached once for the entire scan. The supplied body has no calls inside the scan and makes no direct writes during it. Effects of concurrent or asynchronous changes to that field are not defined here.

### 3. Reduce the first arithmetic field

After selection, the function reads the field at offset `0x34`, subtracts the selected length, and stores the result back to that field.

This update precedes every call.

The field is still read and written when the selected length is zero. No saturation, range check, or explicit overflow handling is present.

### 4. Invoke the preparatory dependency

The function calls F-be81034a42a8 with the object address as its sole visible argument.

The range length has already been selected, and the subtraction has already occurred. No return value from this dependency is used.

The dependency’s effects are unknown. In particular, it may modify the encoded callback target or either arithmetic field. The supplied body provides no basis for assuming preservation of object fields, global state, source contents, or ownership.

### 5. Resolve and invoke the callback

After F-be81034a42a8 returns, the function reads the encoded target at object offset `0x20`. It clears its two least significant bits with the 32-bit mask `0xfffffffc`, then calls the resulting address.

The callback receives three visible arguments, in this order:

1. The original object address.
2. The original source address.
3. The source address advanced by the selected length.

The callback target is therefore obtained **after** the preparatory dependency, not before it.

The two source-derived arguments describe a conventional half-open range from the source origin to the computed end. This describes the argument relationship only. There is no evidence that the callback must read that range, emit it, treat it as a string, or refrain from modifying it.

The end address is not a pointer to a guaranteed terminator:

- Selection may have stopped at a bound.
- Earlier embedded zero bytes may have been skipped by selection.
- A dependency may have changed source contents after selection.

The callback is invoked even when both range arguments are equal. Its return value is not used.

### 6. Increase the second arithmetic field

After the callback returns, the function reads the field at offset `0x3c`, adds the previously selected length, and stores the result back.

The read occurs after the callback. If either earlier call changed this field, the addition uses the value then present, not a value captured before those calls.

The same selected length is used for the subtraction, range end, and addition. No rescan occurs after either dependency.

### 7. Invoke the final dependency

The function calls F-ea83ae94b50b with the object address as its sole visible argument, then returns normally if that dependency returns normally.

The addition at offset `0x3c` has already occurred when this dependency is entered.

## Side effects

The directly established access and call order is:

1. Read the mode flag.
2. Perform selection, including repeated limit reads in bounded mode and conditional source-byte reads.
3. Read and write the field at offset `0x34`.
4. Call F-be81034a42a8.
5. Read and mask the encoded callback target.
6. Invoke the resolved callback.
7. Read and write the field at offset `0x3c`.
8. Call F-ea83ae94b50b.

This is the ordering exposed by the supplied representation, not a claim about processor-level memory barriers, atomicity, or compiler treatment of ordinary memory accesses.

There are no direct source writes, allocations, deallocations, retries, validation failures, or explicit exception handlers in this body.

Dependencies can introduce additional effects. In particular:

- The callback need not observe the original source contents.
- The final dependency need not observe either arithmetic field unchanged from an earlier stage.
- No ownership transfer or retention guarantee can be established.
- There is no transactional rollback.

If a dependency fails to return normally, later stages are not reached through this function’s normal control flow. For example, a callback failure occurs after the first field update and preparatory call, but before the second field update and final call. No explicit recovery restores earlier state.

Aliasing between the object and source is not prohibited by a visible check. Any consequences depend on actual memory overlap and dependency behavior; independent object and source storage must not be assumed without an external precondition.

## Acceptance examples

These examples are conditional static acceptance cases, not executed tests. Unless otherwise stated, assume stable object fields during selection, valid storage and addresses, representable arithmetic, normally returning dependencies, and dependencies that do not alter the arithmetic fields.

### Positive threshold does not cap selection

In unbounded mode, let the threshold be 3. Suppose the source bytes at indices 3 and 4 are nonzero, and index 5 is zero.

The selected length is 5. This function does not read source indices 0 through 2 during selection. The callback receives the source origin and the address five bytes beyond it.

If the initial arithmetic fields are 20 and 7, the first becomes 15 before the preparatory call, and the second becomes 12 after the callback.

### A zero at the threshold terminates selection

In unbounded mode, let the threshold be 3 and the byte at index 3 be zero.

The selected length is 3, regardless of the contents at indices 0 through 2. The byte at index 3 is read; it is not included in the selected length.

### Earlier zero bytes are ignored by selection

In unbounded mode, let the threshold be 4. Suppose index 1 is zero, index 4 is nonzero, and index 5 is zero.

The selected length is 5. Selection does not detect the zero at index 1. The range passed to the callback includes that earlier zero byte.

This case rejects an implementation that substitutes an ordinary scan from the source origin.

### Negative threshold starts inspection immediately

In unbounded mode, let the threshold be −2. Suppose indices 0 and 1 are nonzero and index 2 is zero.

The selected length is 2. A negative threshold does not make the range negative or suppress byte inspection.

### Bound reached before inspection begins

In bounded mode, let the limit be 3 and the threshold be 8.

The selected length is 3, with no source-byte reads by this function. The callback still receives the source address and its three-byte-advanced end address. This does not waive any validity requirements imposed by the callback.

### No read at the bound

In bounded mode, let the limit be 4 and the threshold be 1. Suppose source indices 1 through 3 are nonzero.

The selected length is 4. This function does not inspect source index 4, even if that byte would be zero.

### Nonpositive bound still dispatches

In bounded mode, let the limit be zero or negative.

The selected length is zero and no source bytes are read. Both arithmetic fields undergo their respective read/write operations, both dependencies are called, and the callback receives equal start and end addresses.

### Preparatory changes affect dispatch

Suppose F-be81034a42a8 replaces the encoded target field with a usable value whose two low bits are set.

Dispatch uses the replacement value with those bits cleared. It does not use the field’s value from function entry.

### Callback changes affect the later addition

Suppose the selected length is 3 and the callback leaves the field at offset `0x3c` equal to 100.

The function stores 103 into that field before invoking F-ea83ae94b50b, regardless of its value before the callback.
