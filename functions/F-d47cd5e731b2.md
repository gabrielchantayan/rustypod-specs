# F-d47cd5e731b2

## Purpose

F-d47cd5e731b2 constructs or initializes a 52-byte object and, except for one early-return case, populates two byte-mapping tables.

**Established behavior:** The function has two construction families:

- Selector values 0 and 1 directly initialize a newly allocated object, allocate two mapping buffers, and populate them.
- Every other selector delegates object initialization, conditionally returns the resulting object immediately, or populates mapping buffers already referenced by that object.

Both mappings use byte-classification queries. One can convert values in the ASCII lowercase interval to corresponding uppercase values; the other can perform the reverse conversion. Conversion requires positive classification results for both members of the pair.

**Inferred intent:** The object appears to represent character-classification and case-conversion state. The meanings of the classification masks and object header values are not independently established. This contract therefore identifies masks numerically and does not require a particular locale or character-set interpretation.

## Interface

The selector is represented as a signed integer in the supplied material, but only equality tests against 0 and 1 affect branching. Negative values therefore select the delegated family just as other nonzero, non-one values do.

- In the direct family, this is the address returned by the 52-byte object-allocation call.

## Behavior

### Direct construction: selectors 0 and 1

The function requests 52 bytes from F-8157a180d901. It performs no explicit failure check before using the returned address.

The explicit initialization order is:

1. Write 32 at offset 4.
2. Write 0 at offset 8.
3. Write the selector, either 0 or 1, at offset 12.
4. Read the first direct-family global header value.
5. Write 0 at offset 20.
6. Read the second direct-family global value.
7. Write the previously read header value at offset 0.
8. Write byte 0 at offset 24.
9. Write the previously read second global value at offset 20.
10. Write byte 0 at offset 24 again.

The two writes at offset 24 and the temporary zero at offset 20 are part of the supplied operation order. The body does not justify replacing the first write at offset 20 with a claim that the field is zero on return.

The function then constructs the first mapping completely before discovering the second mapping’s bounds.

For each mapping, it stores the bounds, requests exactly enough bytes from F-fab3799b3190 for the inclusive interval, stores the returned buffer pointer in the object, and fills the buffer in increasing input-value order. Neither mapping is null-terminated.

After filling the second mapping, it returns the object without an explicit finalization call.

### Delegated construction: every other selector

The function first requests a 52-byte allocation from F-8157a180d901.

It places the first and second auxiliary arguments, in that order, into a temporary record containing two consecutive 32-bit words. It then:

1. Calls F-b396014b2502 with the context argument.
2. Calls F-98c73c666ec8 with the allocation address, that dependency’s result, literal 0, and the first auxiliary argument.
3. Uses the object address returned by F-98c73c666ec8 for subsequent object operations.
4. Overwrites offset 0 from the delegated-family global header value.
5. Compares the word at offset 20 with a global sentinel.

If the comparison is equal, the function immediately returns the object. This branch does not explicitly set offset 24, construct either mapping, call F-23df8d149813, or call F-7c87d6325a96.

If the comparison is unequal, the function:

1. Writes byte 1 at offset 24.
2. Calls F-23df8d149813 with the temporary record’s address, the context argument, and literal 2.
3. Constructs both mappings using the same classification and conversion rules as the direct family.
4. Calls F-7c87d6325a96 with the temporary record’s address after the second mapping is complete.
5. Returns the object.

This family does not explicitly allocate mapping buffers. After storing each mapping’s bounds, it reads the corresponding pointer from offset 44 or 48 and writes through that pointer. Buffer validity and capacity are therefore requirements on the delegated initialization and any intervening dependency effects.

The finalization call receives the record in its state at that time; the body does not restore its original two words after F-23df8d149813.

### Bound discovery

The first mapping uses classification mask 16. The second uses mask 8. All classification calls go through F-3e0e547bb25a and receive the object address, the mask, and a byte-valued candidate.

For each mapping:

- The provisional lower bound starts at 0.
- Candidates 0 through 254 are queried in ascending order until a nonzero classification result occurs.
- If one occurs, its candidate becomes the lower bound.
- The upper bound starts at 255.
- After an ascending match, candidates are queried in descending order from 255 while the candidate remains strictly above the lower bound. The first nonzero result stops this descent.
- If descent reaches the lower bound, that bound is retained without a second classification query at that point.

A significant edge case is that the ascending search **does not query 255**. If every query from 0 through 254 returns zero, both bounds become 255. There is no descending search in that case.

Consequently, an entirely unclassified domain does not produce an empty mapping. It produces the singleton interval [255, 255], containing the identity byte 255.

With ordinary dependency returns, the generated intervals always satisfy:

- 0 ≤ lower bound ≤ upper bound ≤ 255.
- Inclusive length is upper bound minus lower bound plus one.
- Length is between 1 and 256 bytes.

These arithmetic operations use 32-bit unsigned working values. Given the established bound construction, the length calculation does not overflow or underflow.

### First mapping: mask 16, lowercase-range conversion

The function stores this mapping’s bounds at offsets 28 and 32.

For each input value in the inclusive interval, it writes exactly one byte. Input value equal to the lower bound occupies buffer offset 0.

The output is normally the input byte unchanged. Conversion occurs only when all of the following hold:

- The input is between 97 and 122 inclusive.
- A fresh mask-16 query for that input returns nonzero.
- A subsequent mask-8 query for the input minus 32 returns nonzero.

When all conditions hold, the output is the input minus 32.

The second query is conditional on the first query succeeding. Inputs outside 97–122 cause no per-entry classification queries. Within that interval, a zero mask-16 result prevents the mask-8 query.

The range test is an unsigned 32-bit subtraction comparison. For the established 0–255 input domain, it selects exactly 97–122.

### Second mapping: mask 8, uppercase-range conversion

The function stores this mapping’s bounds at offsets 36 and 40.

For each input value in the inclusive interval, it writes one byte, indexed relative to the lower bound.

Conversion occurs only when:

- The input is between 65 and 90 inclusive.
- A fresh mask-8 query for that input returns nonzero.
- A subsequent mask-16 query for the input plus 32 returns nonzero.

When all conditions hold, the output is the input plus 32. Otherwise, the input byte is written unchanged.

The second query is again short-circuited. Inputs outside 65–90 cause no per-entry classification queries.

All bytes in an interval are written, including interior values whose classification result is zero. Bounds describe a contiguous table span, not a packed list of classified values.

### Ordering and dependency interference

The first table is fully written before the second bound search begins. Each entry’s required classification calls finish before its byte is written.

Classification is repeated during table construction even when bound discovery previously queried the same input. Earlier results are not cached as membership decisions.

Dependencies may have unknown side effects. Accordingly:

- The bounds reflect the sequence of classification results actually observed during discovery, not necessarily a stable classification set.
- Stored bounds are written before a direct-family buffer allocation or a delegated-family buffer-pointer read.
- Once a buffer pointer has been obtained for filling, writes advance from that captured pointer; later classification calls do not cause the pointer field to be reread for every entry.
- A dependency’s modifications to object fields or globals are not implicitly undone.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume successful storage provision, stable classification responses, and no dependency mutation that interferes with construction.

1. **Direct selector 1.** The object-allocation request is 52 bytes; offset 12 is written as 1. Both mapping buffers are requested and filled. Neither temporary-record dependency is called.

2. **No matches for either mask.** For each mask, candidates 0–254 are queried and return zero. Both recorded intervals are [255, 255]; both buffers contain one byte, 255. No classification query for candidate 255 is needed on this path.

3. **Classification exists only at 255.** With all 0–254 responses zero, behavior remains the same as the preceding example. The function does not discover that membership through its ascending search.

4. **A single first-mask match at 97 with no matching counterpart.** If mask 16 is nonzero only at 97 and mask 8 at 65 is zero, the first mapping has bounds [97, 97] and contains byte 97, not 65.

5. **A qualifying pair.** If mask 16 is nonzero at 97 and mask 8 is nonzero at 65, the first mapping entry for 97 becomes 65, and the second mapping entry for 65 becomes 97.

6. **An interior unclassified value.** If first-mask matches establish bounds 97 and 99, but 98 is unclassified under mask 16, the first mapping still contains an entry for 98. That entry is 98.

7. **Bounds spanning the full byte domain.** If discovery observes matching endpoints 0 and 255, the direct family requests 256 bytes for that mapping. Inputs outside the relevant ASCII conversion interval remain identity entries even if classified.

8. **Delegated early return.** If the initialized object’s offset-20 word equals the sentinel, offset 0 is still overwritten before return. No table construction or temporary-record setup/finalization call follows that comparison.

9. **Changing classification responses.** If a value qualifies during bound discovery but fails its later per-entry classification query, its mapping entry remains unchanged. Discovery membership is not reused to force conversion.
