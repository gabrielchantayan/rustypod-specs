# F-026d9bfbb983

## Purpose

F-026d9bfbb983 populates a private workspace from caller-supplied input and table storage, combines workspace values in place, and extracts bytes into caller-supplied output storage.

There are two ordered phases:

- **Population:** selected input bytes determine table reads whose adjusted values are written into the workspace.
- **Combination and extraction:** selected workspace entries are updated, then selected bytes are written to output.

External configuration controls admission to each stage, addressing, and arithmetic. The supplied evidence does not establish fixed dimensions, a fixed output length, or a standard transform.

This contract describes statically established behavior. It does not assume that configuration remains constant, that every workspace entry is initialized, or that the operation terminates.

## Behavior

### Admission and arithmetic

Population rows, population candidates, extraction passes, reduction columns, reduction lanes, and output lanes have separate admission decisions. Each decision tests whether a 32-bit arithmetic-and-bitwise result is negative when interpreted as signed.

The masks and constants appearing in those decisions do not establish ordinary rectangular bounds. In particular, they do not justify a fixed row count, pass count, or output size.

Arithmetic mixes signed and unsigned 32-bit interpretations. Byte conversion is explicit at the input adjustment and final output store; it does not imply that all intervening signed operations wrap safely.

Some calculations occur even when their associated probe rejects further work. Arithmetic validity is therefore required for probes as well as admitted data operations.

### Population

The second argument is adjusted once by subtracting the entry-time input adjustment. Later population accesses use that retained displacement.

The initial row comes from the row/pass seed. Each row probe obtains:

- A population-bias value for workspace positioning.
- A separate population-bias value, increased by one, for a stride-like quantity.
- A fresh row/pass-seed value that can become the second phase’s starting pass.

The row auxiliary used in table grouping and the row guard share the same captured stride. They do not independently reread the population bias for that dependency. Some row-guard preparation precedes the fresh seed capture; the capture still occurs on the probe that ends population.

For an admitted row, the candidate counter starts from the row/reduction bound with its least significant bit set. Each candidate obtains a fresh population-bias value to determine its effective column. The counter advances before candidate admission is resolved.

A rejected candidate performs no input read, table read, or workspace write. An admitted candidate:

- Reads one unsigned byte.
- Adds 204 modulo 256.
- Uses the adjusted byte to select a 32-bit table entry.
- Subtracts a separately obtained population-bias value.
- Writes the result into one workspace entry.

The next row is the preceding row plus one. Preparation of that next-row value occurs during candidate probing, including the terminating candidate probe.

#### Population layout

The input address is the input base plus the current row, the retained input displacement, and twice a fresh population-bias value. It contains no candidate-column contribution.

Consequently, under stable relevant configuration and unchanged input storage, multiple admitted candidates in one row read the same byte address. They remain distinct read operations; their table addresses can differ.

The workspace destination is twice the sum of the row and its captured position bias, plus the effective column. Effective column means the candidate value before advancement plus its separately obtained population bias. A workspace entry may be overwritten more than once.

Table addressing has three byte-scaled contributions:

| Contribution | Byte scale |
|---|---:|
| Group selection | 2,048 |
| Effective column | 1,024 |
| Byte-dependent selection | 4 |

These scales describe address construction, not allocation dimensions or validated boundaries.

A useful mathematical normalization of the group is eight, minus the table-group control, plus the group-selection population bias, minus the low three bits of the negated sum of row and captured stride. The original unsigned 32-bit address arithmetic remains relevant.

For precision, the byte-dependent selection can also be described without assigning a conventional table meaning. Let **adjusted byte** be the input byte increased by 204 modulo 256. Let **low byte** mean the nonnegative residue modulo 256.

- For adjusted bytes from 204 through 255, the selection is the adjusted byte plus the byte additive bias, minus the byte XOR bias, minus three.
- For adjusted bytes from 0 through 203, the selection is the adjusted byte plus both byte biases, minus twice the byte-selection population bias, plus 765, minus twice the sum of two low-byte residues. Those residues are taken from:
  - the byte XOR bias minus 204 times the adjusted byte;
  - 204 times the adjusted byte minus the byte-selection population bias.

These are normal forms of the unsigned 32-bit selector arithmetic. They do not authorize replacing target address semantics with unbounded mathematical addressing.

The population-bias occurrences used for input addressing, group selection, byte selection, and stored-value adjustment are separate. The table-group control is also used again after candidate admission.

### Transition between phases

The row probe that terminates population supplies the second phase with:

- Its fresh row/pass-seed capture as the first pass.
- Its captured stride as the shared stride for the entire second phase.

Neither value necessarily equals the corresponding value used by an earlier admitted row. The shared stride is not refreshed during the second phase.

Population completes before any explicit output store.

### Combination and extraction passes

Each pass first undergoes admission using the candidate/pass control, pass mixer, and retained stride. A rejected pass performs no reduction or output work.

An admitted pass obtains another candidate/pass-control value with its least significant bit cleared. This captured seed determines the starting reduction column and two addressing contributions that remain fixed throughout the pass.

For each column probe, a lane origin is captured as seven minus a lane-bound occurrence. The lane starts at the negation of that origin. Both actions occur even when the column is rejected.

Column admission uses additional lane-bound occurrences and the column mixer. An admitted column processes reduction lanes. A rejected column ends reduction for that pass and leaves its freshly initialized lane and origin available to output extraction.

Reduction-lane admission uses the retained stride together with live row/reduction-bound, row/pass-seed, candidate/pass-control, and reduction-mixer occurrences. The seed used here is not the captured pass-start value.

An admitted reduction replaces one workspace entry and advances the lane. A rejected reduction advances the column and begins another column probe.

### Workspace replacement

The following normalized layouts describe entry indices for defined executions. They use the current lane before its advancement.

| Selection | Workspace entry index |
|---|---|
| Destination | Sixteen times the pass, plus the lane, plus three times the captured origin, minus twice the destination displacement. |
| Source | Sixteen times the pass, plus the lane, plus three times the captured origin, plus twice the sum of the column and source/output displacement. |

The pass-address contribution is formed from two cached values. Their mathematical sum is eight times the pass; this normalization does not remove the original intermediate arithmetic or its validity requirements.

The replacement adds four contributions:

1. The destination’s previous value.
2. A selected source value.
3. A bitwise-OR correction.
4. The retained stride.

Each operand of the OR correction is formed by multiplying a workspace value by negative two and adding a reduction adjustment. One uses the destination’s previous value; the other uses a source value.

Two distinctions affect the result:

- The reduction adjustment has two separate occurrences. Equal workspace values do not imply equal correction operands.
- Source/output displacement has separate occurrences for the additive source and the correction source. They can select different entries unless stability is established.

The destination index is retained for the replacement. There is no intermediate destination store between the reads that contribute to that replacement.

### Output extraction

Output starts only after the pass’s column loop terminates. It begins with the lane and origin established by that terminating column probe.

Output admission uses the lane bound, output mixer, output bound, and retained stride. Rejection performs no output store.

For each admitted output lane:

- The destination byte address is the output base plus eight times the pass, the current lane, the captured origin, and a fresh source/output displacement.
- A workspace entry is selected.
- The captured origin is added to that entry’s value.
- The result is converted to unsigned 32-bit and logically shifted right.
- The low byte is adjusted and stored.
- The lane advances.

For a normalized description of selection, consider the 32-bit bit pattern of the negated sum of the current lane and retained stride. Its bit numbered two contributes either zero or one to workspace selection. The selected entry is:

- Sixteen times the pass;
- minus twice the extraction-selector value used for selection;
- plus three times the captured origin;
- minus the retained stride;
- plus two;
- minus that bit’s value.

The extraction selector is referenced again for shift calculation. That occurrence need not match the selection occurrence.

For shift calculation, a lane factor is four minus the retained stride minus the low two bits of the same negated lane-and-stride sum. The shift count is the low byte of the shift origin, plus the shift-calculation extraction selector, minus the lane factor multiplied by the sum of captured origin and shift multiplier.

Only the low eight bits of the count are retained. Counts from 32 through 255 are therefore possible; they are not established as valid shifts of a 32-bit value.

For a defined shift, the stored byte is the shifted result plus the retained stride, minus the captured origin, minus one, reduced modulo 256. No adjacent output bytes are implicitly cleared.

After output admission rejects further lanes, the next pass is the preceding pass plus one, not a reread of the row/pass seed.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Immediate rejection.** If the first population-row probe rejects and the resulting first pass probe also rejects, there are no input-byte reads, table reads, workspace data operations, or output-byte writes. Entry and probe captures still occur, and their arithmetic must remain valid.

2. **Later pass-start capture.** If the row/pass seed differs between entry and the population-ending probe, the second phase starts from the terminating probe’s captured value.

3. **Independent population biases.** Different values at the row-position and stride captures affect their respective uses independently. The terminating row probe’s stride remains the second-phase stride despite later configuration changes.

4. **Repeated row input.** With stable input-address configuration, two admitted candidates in one row read the same input address. Their effective columns can select different table entries.

5. **Input-byte wrap.** Input byte 52 becomes adjusted byte 0. Input byte 51 becomes adjusted byte 255. This adjustment wraps rather than saturates.

6. **Conditional high-byte selector.** For adjusted byte 204 and stable zero byte biases, the normalized byte-dependent table selection is 201. This alone does not determine the table address: group and column contributions still apply.

7. **Equal-slot replacement.** If all workspace references select the same initialized value and both reduction-adjustment occurrences agree, the two correction operands agree. Their OR equals either operand. Different adjustment occurrences invalidate that simplification.

8. **Changing source selection.** If source/output displacement differs between its two reduction occurrences, the additive source and correction source are selected independently. The replacement must not assume one cached source.

9. **Terminating column origin.** If the terminating column probe captures lane bound 10, its origin is negative three and output starts at lane three, subject to valid arithmetic and subsequent output admission.

10. **Final-byte reduction.** If a valid shifted value is 250, retained stride is 10, and origin is 3, the stored byte is 0.

11. **Rejected output.** A rejected output probe writes nothing and leaves any prospective destination byte untouched.

12. **Invalid extraction prerequisites.** An uninitialized selected workspace entry or a shift count of 32 does not establish portable deterministic output. No zero initialization, modulo-32 shift rule, or fallback byte is supplied.
