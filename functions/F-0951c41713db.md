# F-0951c41713db

## Purpose

F-0951c41713db performs two readiness-gated writes to a caller-supplied destination:

1. Capture an address-like value from a global base cell.
2. Wait for bit 1 of a 32-bit status value selected through the global base.
3. Read the caller’s input byte and write its zero-extended value to the destination.
4. Wait for bit 0 of a 32-bit status value selected through the captured base.
5. Read one byte at offset `0x7c` from the captured base and write its zero-extended value to the same destination.
6. Return zero.

The first wait references the global base, whereas the second wait and final byte read use the earlier capture. This distinction is material if the global base changes.

A readiness-gated device exchange is plausible intent, not an established protocol. The destination may be ordinary storage or an externally significant location. The visible operation specifies accesses and transferred values; it does not establish the destination’s response to writes.

Completion requires both readiness bits to be observed set at their respective stages. An external action need not establish second-stage readiness: when the destination aliases the captured status location, the first destination write can itself set bit 0.

## Interface

### Arguments

| Argument | Referenced extent | Established use |
|---|---:|---|
| Input address | One 8-bit byte | Read after the first wait succeeds |
| Destination address | One 32-bit unsigned object or corresponding writable location | Written after each wait succeeds |

There is no explicit length, base address, timeout, cancellation control, or callback argument.

The input byte is not captured at entry. Its value is obtained after the successful first-stage status test. A change before that read can therefore affect the first written value if the execution environment permits and exposes the change.

No destination read is expressed.

### Return value

Every visible normal return produces a 32-bit zero value.

The final destination operation is a 32-bit write of the zero-extended byte read from the captured base plus `0x7c`. This establishes the value supplied to that write, not persistent readable contents for every permitted destination.

For ordinary writable storage, assuming the write has ordinary storage semantics and no intervening modification, the destination contains that final value on return. For a device register, write-only location, or other externally significant destination, subsequent readable contents and write effects remain unspecified.

The return value does not encode either byte, a readiness delay, or an observed error condition. Whether callers interpret zero as success is not established.

### Global state and addressed layout

The function reads a global cell containing an address-like base value. The captured form is represented as a 32-bit signed integer.

| Offset from selected base | Access width | Use |
|---|---:|---|
| `0x78` | 32 bits | Status read |
| `0x7c` | 8 bits | Final data-byte read |

The status values are treated as unsigned 32-bit quantities. The first readiness mask is `0x00000002`; the second is `0x00000001`.

The source does not establish the global cell’s declared type, pointer width, or complete address-conversion rules. In particular, retaining the base in a 32-bit integer does not establish a portable pointer representation.

### Preconditions

An execution that completes without an access failure requires:

- A readable global base cell.
- Valid 32-bit status reads at offset `0x78` for every base selected during the first wait.
- A valid 32-bit status read at captured-base offset `0x78`.
- A valid 8-bit read at captured-base offset `0x7c`.
- A valid input-byte read when the first wait completes.
- A destination accepting both expressed 32-bit writes.
- Address calculations, conversions, alignment, and mappings valid for the target.

Completion also requires each readiness test eventually to observe its required bit set. This is an observation requirement, not an unconditional requirement for an external producer. Earlier accesses, including an aliased first destination write, may affect the later status.

The visible body imposes no explicit disjointness requirement between the input, destination, global cell, and addressed region. The consequences of overlap depend on valid aliasing, representation, and access semantics in the target environment.

## Behavior

### Base capture

Before either readiness loop, the function reads the global base and retains its value in the represented 32-bit integer form.

Later changes to the global cell do not directly replace this capture. The second wait and final byte read continue to derive their addresses from the captured value.

This is a capture of the base value, not a snapshot of the addressed region. Status and data at that region are read later.

### First readiness wait

The first wait evaluates the unsigned 32-bit status at offset `0x78` from the base referenced through the global cell.

The condition succeeds when bit 1 is set. Other bits do not affect the condition. Thus `0x00000002`, `0x00000003`, and `0x80000002` satisfy this test; `0x00000001` does not.

The first test occurs at least once. If it fails, the function repeats the condition without an expressed timeout, delay, yield, or cancellation branch.

The global base appears in this repeated condition rather than being replaced by the captured value. At the supplied representation’s level, a later evaluation can consequently select a different region.

This does not establish machine-level reload frequency, volatile access, atomicity, or visibility of concurrent modifications. Those depend on target and compilation properties absent from the source material.

No input read or destination write is expressed before this wait succeeds.

### First destination write

After the first readiness condition succeeds, the function reads one unsigned byte from the input address.

It converts that byte to an unsigned 32-bit value and writes that value to the destination. The numeric value is between `0` and `255`; its upper 24 bits are zero.

This is an expressed 32-bit write, not an 8-bit write. It is not a write to captured-base offset `0x7c` unless the caller’s destination happens to designate that location.

The first write is behaviorally significant even though another write to the same destination follows on a completing execution. It can affect ordinary storage, a mapped device, or any later location with which it aliases.

In particular, if the destination designates the captured status object, an input byte with bit 0 set supplies a status value that can satisfy the next wait. For ordinary writable status storage and an input byte of `1`, the first write supplies `0x00000001`, establishing bit 0 before the second-stage test.

### Second readiness wait

After the first destination write, the function evaluates the unsigned 32-bit status at captured-base offset `0x78`.

The condition succeeds when bit 0 is set. Other bits do not affect this test. A status value of `0x00000002` alone is insufficient; `0x00000001` and `0x00000003` suffice.

This stage includes its own status evaluation after the first write. Even if the first-stage status had both bits set, that earlier observation is not reused as the second-stage result.

If bit 0 is not observed set, the condition repeats without an expressed timeout, delay, yield, cancellation path, or recovery action.

The function may reach this stage after having changed the status through aliasing. Accordingly, second-stage readiness can arise from the first destination write, pre-existing state, external activity, or other access effects permitted by the environment. The source establishes no single required producer.

### Final byte read, destination write, and return

After the second readiness condition succeeds, the function reads one unsigned byte from captured-base offset `0x7c`.

It zero-extends that byte to 32 bits and writes the result to the destination. The supplied write value is between `0` and `255`, with its upper 24 bits zero.

The function then returns zero.

The source does not establish that readiness remains asserted during the data read, that the data is stable, or that reading it consumes or acknowledges anything. It also does not establish that the final destination write preserves a readable copy of the supplied value.

## Side effects

### Expressed access order

For a completing execution, the represented order is:

1. Read and capture the global base.
2. Evaluate the first-stage condition, referencing the global base and reading its selected 32-bit status, until bit 1 is observed set.
3. Read the input byte.
4. Write its zero-extended value to the destination.
5. Read the captured region’s 32-bit status until bit 0 is observed set.
6. Read the captured region’s byte at offset `0x7c`.
7. Write that byte’s zero-extended value to the destination.
8. Return zero.

This is the source-level access sequence. It is not evidence of a particular number of bus transactions, hardware memory barriers, atomic operations, or inter-thread ordering guarantees.

### Aliasing and intermediate state

The first destination write precedes every second-stage status read. It can therefore affect second-stage readiness when the locations overlap.

If the destination aliases the global base cell, the first write can alter that cell. Such a change does not directly alter the already captured base used by the second stage.

If the destination overlaps the final data-byte location, the first write can affect the byte subsequently read. The exact affected bytes depend on overlap, target byte order, and the location’s write semantics.

If the input overlaps the destination, the input read precedes the first write. The supplied first write value therefore derives from the byte read before that write, subject to the target permitting those accesses.

For ordinary destination storage, the first write can create an intermediate stored value before the final write replaces it. External observation of that intermediate state requires an appropriate observation and synchronization model. No such model is established here.

For externally significant destinations, either write may have effects unrelated to retaining the written value. Both supplied values and their order remain part of the represented behavior.

### Ownership, failures, and nontermination

The visible body makes no calls, allocates no memory, releases no memory, and contains no operation retaining either argument beyond the invocation.

There is no explicit pointer validation or error-reporting branch. Access faults, unsupported alignment, invalid address calculations, and exceptional mapped-location behavior have no visible recovery path. They are not converted into a documented nonzero return.

If the first wait never succeeds, the input read and both destination writes are not reached. If the second wait never succeeds, the first destination write has occurred, but the final data read, final write, and normal return are not reached.

## Acceptance examples

These are conditional consequences of the supplied static sequence, not executed tests.

### Immediate completion with ordinary storage

Assume a stable valid base, both readiness bits set at their respective evaluations, an input byte of `0xa6`, and a final data byte of `0x39`.

The destination receives a first 32-bit write of `0x000000a6`. A separate second-stage status read follows. The final 32-bit write supplies `0x00000039`, and the function returns zero.

If the destination is ordinary storage without intervening modification, its contents on return are `0x00000039`.

### Unsigned byte conversion

Assume the input byte is `0xff`, the final data byte is `0x80`, and both waits complete.

The supplied destination values are `0x000000ff` and then `0x00000080`. Neither byte is sign-extended.

### First stage remains unready

Assume every first-stage status evaluation has bit 1 clear.

Execution remains in the first wait. No input-byte read or destination write is reached. A set bit 0 does not change that outcome.

### First write establishes second-stage readiness

Assume:

- The base is stable.
- Its status location is ordinary writable 32-bit storage.
- The destination designates that status location.
- The initial status is `0x00000002`.
- The input byte is `0x01`.
- The final data byte is `0x5a`.
- No intervening modification occurs, and the target permits the accesses.

The first wait succeeds on bit 1. The first destination write stores `0x00000001` into the status location. The subsequent second-stage read observes bit 0 set, without any additional external readiness action.

The final read obtains `0x5a`; the final destination write supplies `0x0000005a` to that same status location. The function returns zero even though this final value has bit 0 clear: no readiness test follows the final write.

### Second stage remains unready

Assume the first wait succeeds, but every subsequent second-stage status evaluation has bit 0 clear, including after any effect of the first destination write.

The input byte is read and its zero-extended value is written. Execution then remains in the second wait. The final data read, final write, and normal return are not reached.

### Global base changes

Assume region A’s base is captured, then the global cell changes to region B’s base.

If a later first-stage evaluation observes that change, region B can satisfy the first wait. The second-stage status and final data read still use region A’s captured base.

Visibility of the global change is an additional target-dependent condition, not established by the source alone.

### Externally significant destination

Assume both waits complete and the destination accepts writes as commands rather than retaining readable storage contents.

The function still supplies two ordered 32-bit write values and returns zero. Acceptance does not require a destination readback to equal the final supplied byte.
