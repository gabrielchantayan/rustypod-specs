# F-4b79b63abc57

## Purpose

F-4b79b63abc57 searches a bit-addressed resource for a range satisfying an initial clear-bit requirement, publishes a starting position and length, and then attempts to extend that length forward toward a separate target.

The inferred intent is to find a contiguous available range within a caller-supplied interval. The established behavior is narrower and sometimes surprising: unsigned arithmetic can wrap, reverse scanning can count positions below its current boundary, resource access can precede boundary checks, and one endpoint-acquisition failure returns zero. These behaviors must not be replaced with an idealized interval-search contract.

The function does not directly modify resource bits or reserve the reported range. Acquisition, conversion, and release dependencies have unknown effects and ownership semantics.

## Interface

The function accepts seven positional arguments:

| Argument | Representation and role |
|---|---|
| Resource context | Opaque 32-bit value supplied to F-1f96b6eaec84. |
| Lower position | Unsigned 32-bit initial search boundary. |
| Upper limit | Unsigned 32-bit exclusive limit used during candidate advancement and extension. |
| Required length | Unsigned 32-bit initial clear-count requirement. |
| Extension target | Unsigned 32-bit target for subsequent growth. It does not reduce an already-published required length. |
| Start output | Address of a writable 32-bit integer object receiving a position bit pattern. |
| Length output | Address of a writable unsigned 32-bit object, also read during extension. |

The return value is a 32-bit integer status:

- Zero on ordinary success and on the exceptional endpoint-acquisition failure described below.
- −34 on initial size rejection or ordinary search exhaustion.
- A dependency-provided nonzero status on other acquisition and transition-release failures.

Zero does not establish that every acquisition succeeded. A nonzero return does not establish that outputs were cleared or left untouched.

### Arithmetic and access preconditions

Position arithmetic, the initial interval-size calculation, and extension-length increments use unsigned 32-bit arithmetic, wrapping modulo \(2^{32}\). There is no preliminary check that the upper limit is at least the lower position. A reversed interval can therefore pass the initial size test.

Reverse clear counts use signed 32-bit arithmetic. Their increments and combined sums can overflow; the supplied representation does not establish a dependable result after such overflow. Predictable examples below exclude it.

Output addresses must be valid for every reached read or write. There are no null checks. A successful acquisition must, as an external precondition, make the subsequent resource accesses valid; a zero status alone does not prove pointer validity.

Ordinary result interpretation additionally requires suitable nonaliasing. The output objects may otherwise overlap each other, resource storage, or dependency-accessible state. Such overlap is not checked.

Successful dependency returns do not establish preservation of outputs or other exposed state. Claims about values observable after return require explicit noninterference assumptions.

## Behavior

### Resource layout

A position selects:

- A block using the position shifted right by 12: 4,096 positions per block.
- A word using position bits 5 through 11: 128 consecutive 32-bit words per block.
- A bit using \(0x80000000 \gg (\text{position} \bmod 32)\).

Increasing positions therefore traverse each converted word from its most significant bit toward its least significant bit.

Every selected resource word is loaded and passed to F-b5c826d2ab04. Bit tests and whole-word zero tests use its returned 32-bit value. This establishes logical bit selection after conversion, not the byte order of stored resource data.

A clear bit contributes to the search. A set bit obstructs the current candidate.

### Initial rejection and acquisition

The function initializes its current block-pointer slot to null, then compares the required length with the unsigned difference between upper limit and lower position.

If that difference is smaller than the required length, it returns −34 immediately. It makes no dependency calls and performs no output-object accesses.

Otherwise, the initial probe is lower position plus required length minus one, modulo \(2^{32}\). A zero required length is accepted and places the probe one position before the lower position.

F-1f96b6eaec84 receives the context, initial probe, and address of the block-pointer slot.

A nonzero acquisition status skips searching and proceeds to shared cleanup. The returned status is the acquisition status; cleanup’s return value is ignored. Cleanup still depends on the slot’s then-current value, including any value supplied on acquisition failure.

After a zero acquisition status, the selected resource word is loaded and converted before the reverse-loop boundary is tested.

### Reverse search

The reverse search maintains a current lower scan boundary, a backward probe, a current clear count, and a retained clear count. Initially, the boundary is the caller’s lower position and both counts are zero.

The outer scan continues while the current boundary is no greater than the probe, using an unsigned comparison.

For a clear bit:

- The current clear count increases by one.
- The probe decreases by one with unsigned wraparound.
- The mask shifts toward more significant bits.

There is no general success check after each individual clear bit.

When the mask leaves the word, traversal moves to the preceding word and converts it. A converted word equal to zero is consumed as 32 clear positions at once. After each such consumption, the combined current and retained count is compared with the requirement.

This whole-word path does not first limit consumption to the distance remaining above the current lower boundary. It can count positions below that boundary. Word loading and block transitions can also occur before the outer boundary condition is checked again.

At a backward block crossing, the function:

1. Calls F-1e9d170e476a with the current slot value and a zero second argument.
2. On a nonzero result, proceeds directly to shared cleanup with that status.
3. On zero, explicitly clears the pointer slot.
4. Calls F-1f96b6eaec84 for the decremented probe.
5. On zero acquisition status, selects the last word of the acquired block and continues.

The backward-crossing acquisition is represented without the explicit output-pointer argument shown at the other acquisition sites. Its effective interface is unresolved. Successful continuation through that site cannot be assumed to establish a usable pointer.

For a set bit, the function first evaluates the combined clear count. If sufficient, reverse scanning stops. Otherwise:

- The new lower scan boundary is the obstructing position plus the current clear count plus one, modulo \(2^{32}\).
- The probe advances from the obstructing position by the full required length, modulo \(2^{32}\).
- If the advanced probe is at or beyond the upper limit, scanning stops.
- Otherwise, any necessary block transition is performed, and the advanced probe’s word is loaded and converted.
- The previous current count becomes the retained count; the current count resets to zero.

The retained count is replaced, not cumulatively increased by the previous combined count. It contributes both to later success decisions and to the reported start. The search is therefore not equivalent to restarting an independent required-length scan after every obstruction.

An advance within the recorded block reuses the block access but still loads and converts the selected word. An advance to another block releases, clears the slot after successful release, and reacquires with an explicit output-pointer argument. Transition errors bypass ordinary result publication.

### Search failure and initial publication

When reverse searching ends normally, the combined count is compared with the required length as an unsigned 32-bit quantity.

If insufficient, the function directly performs these actions in order:

1. Writes zero to the start output.
2. Establishes return status −34.
3. Writes zero to the length output.
4. Enters shared cleanup.

If sufficient, it directly writes the required length to the length output, then writes the calculated start to the start output. The calculated start is the current lower scan boundary minus the retained count, modulo \(2^{32}\).

The forward endpoint is derived from that calculated start plus the required length, modulo \(2^{32}\). It is not obtained by rereading the start output.

These stores publish an initial result before endpoint preparation or extension completes. Later failures do not trigger rollback. Dependency effects can nevertheless change what remains observable in either output.

An extension target smaller than the required length does not cause a direct reduction of the published length.

### Endpoint preparation

The function prepares access to the endpoint before deciding whether extension is needed.

If the endpoint’s block differs from the recorded block, it calls F-1e9d170e476a. A nonzero release result exits through shared cleanup with that status. After successful release, the function clears the slot and calls F-1f96b6eaec84 for the endpoint.

This acquisition site has exceptional status handling: a nonzero acquisition result is discarded, and shared cleanup is entered with return status zero. The initial output stores have already occurred. Their final values still depend on dependency noninterference.

After successful endpoint acquisition, or when no switch is required, the endpoint word is loaded and converted. This access occurs even if:

- The published length already meets or exceeds the extension target.
- The endpoint equals or exceeds the upper limit.

Only afterward does the function read the length output to decide whether growth is needed.

### Forward extension

Extension begins only when the observed length output is below the extension target. Each attempted increment checks these conditions in order:

1. If the endpoint is at or beyond the upper limit, stop.
2. If the selected converted bit is set, stop.
3. Otherwise, read the current length output and write that value plus one, modulo \(2^{32}\).
4. If the incremented value equals the extension target, stop immediately.

On reaching the target, the function does not advance the endpoint or mask for that final accepted position.

Otherwise, the endpoint increases by one and the mask shifts toward less significant bits. Crossing a word boundary selects and converts the next word. Crossing a block boundary first releases the current block, clears the pointer slot after successful release, and acquires the next block.

There is no intervening upper-limit check before those next-word accesses or acquisitions. The limit is checked at the next per-position attempt.

The initial extension decision uses a less-than comparison, but subsequent termination tests compare the incremented length for equality with the target. If dependencies or aliasing alter the length output between accesses, ordinary monotonic-growth reasoning need not hold.

Extension acquisition and transition-release failures return their nonzero status through shared cleanup. Already-performed length increments are not undone.

### Shared cleanup

On every path reaching shared cleanup, the function tests the current value of its block-pointer slot. If nonnull, that value is passed to F-1e9d170e476a with a zero second argument. The cleanup return value is ignored.

After a failed transition release, the function does not itself clear the slot. However, the slot’s address previously escaped through acquisition’s output-pointer argument. The dependency contracts do not exclude retained access to it.

Consequently, cleanup is not unconditionally a retry with the identical pointer. It uses the slot’s then-current value. A second release with the same pointer follows only if intervening dependency effects leave that slot unchanged and nonnull. A changed nonnull value is passed instead; a null value suppresses the cleanup call.

## Side effects

Established direct effects are:

- Selected 32-bit resource-word reads.
- Ordered writes to the two caller output objects.
- Repeated reads and increments of the length output.
- Calls to acquisition, conversion, and release dependencies.
- Updates to the internal block-pointer slot, whose address is exposed to acquisition.

The function contains no direct resource-word writes and no identified allocation or deallocation operation. It does not directly reserve the reported range.

Important observable ordering includes:

- Immediate rejection: no dependency calls or output accesses.
- Ordinary failure: start-zero store before length-zero store.
- Initial success: length store before start store.
- Endpoint conversion before the extension-length comparison.
- Incremental length publication before later extension work.
- Final cleanup after result publication or most errors.

“Acquisition” and “release” describe apparent roles only. Ownership transfer, resource lifetime, synchronization, mutation, and memory-release behavior are not established.

A successful dependency may still modify output objects. Final cleanup may do so after the last direct output store. Therefore, direct stores and values observable after return are separate contract claims.

## Acceptance examples

These are conditional static consequences, not executed tests.

Unless explicitly stated otherwise, examples assume valid, distinct output objects; stable converted resource contents; valid resource access on the described path; no signed counter overflow; no concurrent interference; and successful dependency operations except the stated failure. Dependencies—including conversion and final cleanup—must additionally leave both output objects unchanged except for this function’s direct stores and must not independently alter the exposed pointer slot. These assumptions are not implied by successful statuses.

1. **Immediate rejection.**  
   Lower 100, upper 105, required length 6: return −34 without dependency calls or output accesses. This example does not require dependency-preservation assumptions because no dependency executes.

2. **Initial success followed by extension.**  
   Lower 100, upper 110, required length 3, target 5, with positions 100–104 clear: return zero with start 100 and length 5. Position 105 need not be inspected. The final accepted increment terminates growth immediately.

3. **Immediate obstruction to growth.**  
   With required length 3 and positions 100–102 clear, a set bit at 103 prevents extension. The final outputs are start 100 and length 3 under the noninterference assumptions.

4. **Target below the requirement.**  
   A successful required-length-3 search with target 2 directly publishes length 3 and does not reduce it. Endpoint preparation and conversion still occur before extension is skipped.

5. **Access at the exclusive upper limit.**  
   Lower 100, upper 103, required length 3, target 4, and positions 100–102 clear: the endpoint word for position 103 is loaded and converted. The subsequent boundary check prevents growth, leaving length 3.

6. **Ordinary search exhaustion.**  
   Lower 100, upper 103, required length 3, with position 102 set: advancing the probe reaches or exceeds the upper limit with an insufficient count. The function writes start zero, then length zero, and returns −34.

7. **Endpoint acquisition failure reported as zero.**  
   Lower 4093, upper 5000, required length 3, with positions 4093–4095 clear: the function publishes start 4093 and length 3. If the endpoint-block release succeeds but acquisition for position 4096 fails, it returns zero. Cleanup uses whatever value that failed acquisition leaves in the pointer slot. The stated final outputs require output preservation even on failure and during cleanup.

8. **Zero requirement without initial wraparound.**  
   Lower 100, upper 200, required length zero, target zero: acquisition initially targets 99, and its word is converted before the empty reverse interval is recognized. The function publishes start 100 and length zero, then prepares and converts the endpoint at 100. This does not generalize to lower zero, where the initial probe wraps to the maximum unsigned position.

9. **Failed transition release and conditional retry.**  
   If a transition release returns a nonzero status, that status is returned. If dependencies leave the pointer slot unchanged and nonnull, shared cleanup calls release again with the same pointer. Without that assumption, cleanup tests and uses the then-current slot value; identical-pointer retry is not guaranteed.

## Uncertainties

**documented_only — Backward acquisition interface.** The backward-block call lacks the explicit output-pointer argument present elsewhere. Its effective signature and successful continuation behavior remain unresolved.

**documented_only — Escaped pointer-slot lifetime and mutation.** Acquisition receives the slot’s address. Retention, later modification, and lifetime obligations are unspecified. Cleanup pointer identity cannot be asserted independently of a slot-preservation assumption.

**documented_only — Dependency noninterference.** Output preservation, global preservation, resource stability, ownership, release effects, and concurrency guarantees are unavailable. Status success supplies none of these guarantees.

**documented_only — Signed overflow.** Large reverse counts or combined counts can exceed signed 32-bit range. The resulting behavior is not established.

**documented_only — Aliasing and changing observations.** Converted words are cached across bit checks, while the length output is reread. Aliasing or external mutation can invalidate a stable-bitmap interpretation and change final outputs.

**Inferred intent.** Clear bits likely represent availability, and block operations likely manage access to bitmap storage. Neither inference establishes reservation, synchronization, or ownership transfer.
