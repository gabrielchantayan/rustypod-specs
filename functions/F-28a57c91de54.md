# F-28a57c91de54

## Purpose

F-28a57c91de54 performs a read–modify–write operation on a 32-bit word reached through an indirect reference. Its second argument selects a bit position, and its third argument determines whether that bit is cleared or set.

The established behavior is a bit update, not a toggle: a zero third argument requests clearing; every nonzero third argument requests setting. The function has no explicit return value and no explicit error-reporting mechanism.

The apparent intent is to update a flag within an externally owned word. That interpretation does not establish the surrounding object’s identity, the permitted flag positions, or any synchronization requirements.

## Interface

The function accepts three arguments:

| Argument | Recovered representation | Role |
|---|---|---|
| Indirect reference | Address of a 4-byte slot whose contents are interpreted as a target address | Locates the word to update |
| Bit selector | Unsigned 32-bit value | Supplies the shift count after reduction to its low eight bits |
| Update control | Signed 32-bit value | Selects clearing when zero and setting otherwise |

There is no explicit return value.

### Indirect layout

Two levels of accessible storage are involved:

1. The first argument identifies a readable 4-byte address-bearing slot.
2. The address represented by that slot identifies a readable and writable 32-bit word.

The supplied representation supports a 32-bit address-bearing slot. It does not establish a portable interface for a platform with wider native pointers.

No byte offsets beyond the beginning of either object appear in the supplied body. The function does not access an array element, advance either address, or inspect surrounding object metadata.

The bit numbering is numeric: bit zero is the least significant bit of the loaded 32-bit value. The source does not establish a byte order for the word’s representation in memory.

### Preconditions

For an ordinary, successful update:

- The first argument must identify storage from which a 4-byte address value can be read.
- The address obtained through that slot must identify a readable 32-bit word.
- The address used for the final store must identify a writable 32-bit word.
- Both levels of access must satisfy the execution platform’s address-validity and alignment requirements.
- A well-defined interpretation of the shift must exist for the effective bit position.

The function does not check these conditions.

The ordinary postconditions below additionally assume that the address-bearing slot and target word remain stable against external interference during the operation. This stability is a caller or environment obligation, not a property enforced by the function.

## Behavior

### Input interpretation

The update control is tested only for equality with zero. Its magnitude and sign otherwise have no significance. For example, positive one and negative one both request setting.

The effective bit position is the low eight bits of the bit selector. Numerically, it lies between 0 and 255. Consequently, selectors differing only above bit seven select the same effective shift count.

This reduction is **not** evidence of reduction modulo 32. In particular, selectors whose low eight bits are 32 through 255 do not have an established portable interpretation.

### Observable access sequence

At the level of the supplied recovered body, the operation proceeds in this order:

1. Read the address-bearing slot identified by the first argument.
2. Read a 32-bit word through the address obtained from that slot.
3. Form a one-bit mask using the effective bit position.
4. Select the cleared or set result according to whether the update control is zero.
5. Evaluate the indirect destination and write the resulting 32-bit word.

The final destination expression again refers through the first argument. The body therefore does not provide a reliable contract that the target address is captured once and reused independently of subsequent changes to the slot.

Under stable, ordinary memory, the initial read and final write address the same target word. If another participant changes the address-bearing slot during the call, the supplied source alone is insufficient to establish the actual machine-level access sequence or concurrency outcome.

The original word is read before the requested update is stored. There is no branch that skips the original-word read because the caller requests setting or clearing.

### Clearing

When the update control is zero, the selected bit is cleared. All other bits of the loaded word are retained.

For an effective bit position with an established single-bit mask:

- A selected bit that was one becomes zero.
- A selected bit that was already zero remains zero.
- No other bit is intentionally changed.

The resulting full 32-bit word is stored. There is no explicit suppression of the store when clearing leaves the value unchanged.

### Setting

When the update control is nonzero, the selected bit is set. All other bits of the loaded word are retained.

For an effective bit position with an established single-bit mask:

- A selected bit that was zero becomes one.
- A selected bit that was already one remains one.
- No other bit is intentionally changed.

The resulting full 32-bit word is stored. There is no explicit suppression of the store when setting leaves the value unchanged.

### Width and shift boundaries

The supplied text alone does not establish whether the actual executable implements the expected top-bit mask or whether a strict source-language interpretation is applicable. For effective positions 32 through 255, the source does not establish a valid 32-bit shift result. The contract must not silently substitute a wrapped position, a zero mask, a rejected request, or a particular processor’s shift-count behavior.

## Side effects

The explicit mutation is a full-width, 32-bit store through the indirect destination.

Under stable, nonoverlapping storage, the address-bearing slot is read but not intentionally modified. The target word is both read and written.

The operation is not established as atomic. There is no visible lock, atomic read–modify–write primitive, memory barrier, or retry mechanism. Concurrent updates to the same word can therefore not be assumed to compose safely; an intervening update may be overwritten by a result calculated from an earlier read.

A same-value update still reaches an explicit store in the recovered body. Whether a particular compiler or memory environment preserves every displayed access is not established. In particular, the source does not identify either storage location as volatile or as memory-mapped I/O.

The body contains no allocation, release, ownership transfer, or lifetime extension. It uses the supplied storage in place. It does not establish who owns either object or who must eventually release it.

No explicit global object is accessed. That observation does not establish that the supplied addresses cannot point into global storage.

If the target word overlaps the address-bearing slot, the final write can overwrite the reference itself. No overlap check prevents this. Such an arrangement does not satisfy the ordinary assumption that the reference remains usable after the call; subsequent use requires interpreting the newly written address value.
