# F-de3024fb195b

## Purpose

The function reports:

- A return status: zero for either normal exhaustion or a zero-valued terminator; otherwise the first nonzero dependency result.

## Behavior

### Initialization and record-limit selection

Both outputs are initialized on entry:

- Accumulated quantity becomes zero.
- Terminator indicator becomes zero.

The context’s 16-bit field then selects the record limit:

| Selector value | Maximum records examined |
|---|---:|
| 0x482B | 8 |
| Any other value | 3 |

The limit is selected once. Subsequent changes to the selector do not cause it to be selected again.

### Ordered processing

Records are considered in sequence order, beginning with the first record.

For each record within the selected limit:

- Its signed quantity is read.
- If the quantity is zero:
  - No dependency call is made for that record.
  - The terminator indicator becomes one.
  - Processing ends with return status zero.
  - The accumulated quantity retains the total from preceding successful calls.
- If the quantity is nonzero:
  - F-78d86e98287a receives the context reference, that record’s opaque four-byte value, and that record’s signed quantity.
  - A nonzero dependency result immediately ends processing and is returned unchanged.
  - A zero dependency result causes the quantity to be added to the accumulated output, after which processing advances to the next record.

If the selected limit is reached without a zero quantity or nonzero dependency result, the function returns zero with the terminator indicator still zero.

### Accumulation and stopping rules

- The accumulated output includes only quantities whose dependency calls returned zero.
- The quantity belonging to a failing dependency call is not added.
- Records following a terminator or failed dependency call are not processed.
- A zero quantity outside the selected limit is not examined and does not set the terminator indicator.
- A negative quantity is passed to the dependency. If that call succeeds, the negative quantity decreases the accumulated result, subject to the unresolved arithmetic model.
- No absolute value, clamping, or reinterpretation as an unsigned quantity is shown.
- No explicit rollback, retry, or cleanup is performed after a dependency failure.
- A failure result does not establish that the dependency produced no external effects.

For nonoverlapping storage and a dependency that leaves these outputs alone, the terminator indicator has only two final values: zero or one.

### Aliasing and mutation

Outputs are initialized before the selector and records are read. If output storage overlaps input storage, initialization can change the selector or record contents before processing.

Each record’s quantity is obtained before its dependency call and that obtained quantity is used for subsequent accumulation. Later records are read only when reached. Dependency mutation of those later records can therefore affect subsequent processing.

The accumulated output is updated after each successful call rather than merely written once at completion. Dependency access to that same storage could affect the result.

No comprehensive aliasing or dependency-mutation contract can be established from the available context.

### Inferred intent
