# F-71ee711958bb

## Purpose

F-71ee711958bb constructs a byte-oriented response containing a prefix, optional metadata, and operation-selected payload content. For supported operations, it requests delivery of the smaller of the accumulated construction count and the caller’s unsigned limit.

Eight operations select individual payload dependencies. A ninth operation invokes six of those dependencies in a fixed sequence. Unsupported operations produce an error notification without requesting output. An output result unequal to the requested count produces a different error notification.

This contract describes established static behavior. The external protocol, meaning of the operation values, and semantics of dependency-generated payloads are not established.

## Interface

The function accepts five inputs and has no explicit return value.

| Input | Observed representation | Role |
|---|---|---|
| Context | Opaque 32-bit value | Passed to F-603a53835f04 to obtain the context used for subsequent error notifications. |
| Payload-source reference | Pointer to a 32-bit object reference | Used to obtain metadata and passed unchanged as a pointer value to every selected payload dependency. |
| Output interface | Pointer to an object whose first word identifies an indirect-call table | Supplies a classification pointer and receives the eventual output request. |
| Operation | Signed 32-bit integer | Selects payload construction or the unsupported-operation path. |
| Limit | Unsigned 32-bit integer | Determines initial prefix values, payload allowances, and the maximum requested output count. |

The supplied representation uses 32-bit pointers and four-byte table entries. Table displacements describe this observed layout, not a portable object model.

There are **four distinct indirect-call sites**:

| Object | Table displacement | Observed use |
|---|---:|---|
| Output interface | `0x08` | Called with the output-interface object; returns the classification-byte pointer. |
| Payload object | `0x28` | Returns the first 32-bit metadata quantity. |
| Payload object | `0x24` | Returns the second 32-bit metadata quantity. |
| Output interface | `0x10` | Called with the output-interface object, an unsigned 32-bit requested count, and a temporary descriptor address; returns a count compared with the requested count. |

For each metadata query, the payload object is obtained through the payload-source reference. The displayed calls do not establish their complete calling convention or an explicit receiver argument.

### Storage and validity preconditions

Normal execution requires valid objects, indirect-call tables, classification pointers, and storage for every described access. The classification pointer must remain valid for each read, including after dependencies have had opportunities to replace or affect it.

The construction buffer must accommodate prefix writes and any writes performed by payload dependencies. The limit is **not** an enforced construction-buffer bound. Prefix construction occurs even when the limit is zero or smaller than the prefix.

The supplied body does not explicitly establish how the construction-buffer pointer or its companion descriptor word becomes initialized. A complete memory-safety contract therefore requires information outside this body.

Payload returns must permit valid subsequent pointer arithmetic and buffer access. No local validation enforces that requirement.

## Behavior

### Preparation and observation order

Before dispatching on the operation, the function performs these actions in order:

1. Calls F-603a53835f04 with the original context and three zero arguments. Its result becomes the error-reporting context.
2. Calls F-9b3ee6b2bfa6 with a local management-object address and the additional arguments `255` and `3`.
3. Invokes the output-interface operation at displacement `0x08`, saving its returned classification pointer.
4. Invokes the payload-object operation at displacement `0x28`, saving its result.
5. Invokes the payload-object operation at displacement `0x24`, saving its result.
6. Calls an unidentified external dependency with the construction-buffer pointer and `255`.
7. Reads the classification byte and writes the initial prefix.
8. Calls F-c9c29fb7e6f0 with the address of the classification-pointer storage and the additional arguments `1` and `3`.
9. Completes the prefix according to that dependency’s zero or nonzero result.

The two metadata queries occur even when the eventual prefix omits their values, and even for unsupported operations.

The unidentified external dependency cannot be specified as clearing, allocating, or validating the buffer from its arguments alone.

F-c9c29fb7e6f0 receives writable access to the classification-pointer storage. The later classification read consequently uses the then-current pointer, which need not equal the pointer initially returned by the output interface.

No dependency is assumed to preserve globals, referenced objects, indirect-call tables, or aliased memory. The ordering above identifies when observations occur; it does not freeze the observed objects between calls.

### Initial prefix

Let **L** be the unsigned 32-bit limit. Let **low8** denote retention of the low eight bits.

If the initial classification byte is `0x1A`, the function writes:

| Buffer offset | Value |
|---:|---|
| 0 | low8(L − 1) |
| 1 | Zero |
| 2 | Zero |

The next prefix position is 3.

For every other initial classification byte, it writes:

| Buffer offset | Value |
|---:|---|
| 0 | Zero |
| 1 | low8(L − 1) |
| 2–6 | Zero |

The next prefix position is 7.

Writes occur in increasing offset order. These initial writes precede operation validation. Neither a small limit nor an unsupported operation prevents them.

### Prefix completion and metadata

A **nonzero** result from F-c9c29fb7e6f0 selects the short form:

- One zero byte is written at the next prefix position.
- The first payload position is 4 after an initial `0x1A` classification, or 8 otherwise.
- The saved metadata query results do not contribute to this prefix.

A **zero** result selects the metadata-bearing form. Nine bytes are written at the next prefix position:

| Relative offset | Value |
|---:|---|
| 0 | L − 4 if that unsigned 32-bit subtraction is at most 8; otherwise 8 |
| 1–4 | First metadata result plus one, encoded most-significant byte first |
| 5 | Zero |
| 6–8 | Low 24 bits of the second metadata result, encoded most-significant byte first |

The metadata-length byte is therefore:

- 8 when L is below 4, because unsigned subtraction wraps to a value greater than 8.
- L − 4 when L is between 4 and 12 inclusive.
- 8 when L exceeds 12.

All nine bytes are written regardless of that byte’s value. A metadata-length byte of zero does not suppress the remaining eight writes.

The first payload position becomes 12 after an initial `0x1A` classification, or 16 otherwise. The first metadata quantity is represented as signed 32-bit for its increment; overflow semantics at the signed boundary remain unresolved. Encoding uses the incremented quantity’s 32-bit representation. The second quantity contributes only bits 23 through 0.

### Payload selection and accumulation

Each selected payload dependency receives:

1. The original payload-source reference pointer.
2. A destination at the current construction position.
3. An allowance equal to low8(L − current position).

The allowance calculation uses unsigned 32-bit subtraction followed by retention of the low eight bits. Its value is always between 0 and 255. It is not a saturating “remaining capacity” calculation: a position beyond L can produce a large nonzero allowance.

Each return is added to the construction position. For `0x3F`, that updated position determines the next destination and the next independently calculated allowance. The aggregate does not invoke F-119b4a266f19 or F-d168cbb1f129.

The supplied representation treats payload returns and intermediate additions as signed 32-bit quantities. The completed accumulated count is subsequently treated as unsigned 32-bit. Signed overflow behavior is not established merely by that final unsigned use.

No return is locally interpreted as an error sentinel. Negative or excessive returns are not rejected, clamped, or reported as payload errors. Their consequences depend on the resulting arithmetic and pointer validity.

### Unsupported operations

Every operation absent from the dispatch table is unsupported, including negative values.

For an unsupported operation:

- Preparation, both metadata queries, and prefix construction have already occurred.
- No payload dependency is selected.
- No final classification read or final length-byte rewrite occurs.
- No output request is made.
- F-7f008c1060db receives the derived context and additional arguments `2`, `5`, and `0x2400`.
- Finalization follows if that notification returns normally.

The function does not return an explicit status.

### Final prefix update and output

For a supported operation, let **N** be the completed accumulated count as an unsigned 32-bit value, subject to the arithmetic uncertainties above.

The function rereads the classification byte through the current classification pointer.

| Final classification | N ≤ L | N > L |
|---|---|---|
| `0x1A` | Offset 0 receives low8(N − 1) | Offset 0 receives low8(L) |
| Anything else | Offset 1 receives low8(N − 2) | Offset 1 receives low8(L) |

This decision is independent of the initial classification. A changed pointer or changed byte can select a different prefix offset for the final rewrite. The rest of the prefix is not rebuilt.

The function then copies the construction-buffer pointer and its companion 32-bit word, in that order, into a temporary descriptor. The observed descriptor consists of two consecutive 32-bit words: the buffer pointer first, the companion word second. The companion word’s meaning is unknown.

The output-interface operation at displacement `0x10` receives:

- The output-interface object.
- The unsigned 32-bit count min(N, L).
- The temporary descriptor’s address.

Clamping affects the requested output count only. It does not undo earlier writes or constrain what payload dependencies already wrote.

The returned count is compared with the requested count as an unsigned 32-bit quantity:

- Exact equality causes no output-mismatch notification.
- Any inequality causes F-7f008c1060db to receive the derived context and additional arguments `2`, `11`, and `0`.

A larger-than-requested result is a mismatch just as a short result is. There is no visible retry.

A zero requested count does not suppress the call. Only a zero returned count satisfies a zero-byte request.

### Finalization

On normal control flow, F-ffa7163332aa is called with the local management-object address after successful output, after a returning mismatch notification, or after a returning unsupported-operation notification.

The body does not establish cleanup behavior when a dependency fails to return normally.

## Side effects

Established effects include ordered dependency calls, indirect-table lookups, classification reads, prefix and metadata writes, payload calls, a possible output request, error notifications, and normal-path finalization.

The original payload-source reference pointer is reused for every payload call. If a dependency replaces the referenced object, later dependencies may observe that replacement. The two earlier metadata-query results are saved values; they are not queried again during payload construction.

The output interface is consulted before construction and again for delivery. Its later indirect-call target is not established as immutable across intervening dependencies.

No explicit ownership transfer of caller-provided objects is visible. Passing the temporary descriptor does not establish that output is synchronous, that bytes are copied, or that the recipient may safely retain either the descriptor or its buffer pointer.

Likewise, the local management object’s initialization and finalization do not establish which storage it owns, whether the construction buffer belongs to it, or what the finalizer releases.

Dependencies may have additional effects not specified by this function’s body.

## Acceptance examples

These are conditional static derivations, not executed tests. Unless stated otherwise, they assume valid storage, normally returning dependencies, representable signed arithmetic, and no dependency mutation that changes the listed observations or constructed bytes.

1. **Short prefix, single payload.**  
   Initial and final classification are `0x1A`; L = 32; the selector returns nonzero; operation is `0x01`; F-b518e364ef68 returns 5.
   - Initial prefix bytes are `1F 00 00 00`.
   - The payload destination is offset 4 and its allowance is 28.
   - N = 9; offset 0 becomes `08`.
   - The output request is 9 bytes. A return of 9 produces no mismatch notification.

2. **Metadata extends beyond the output limit.**  
   Classification remains different from `0x1A`; L = 10; the selector returns zero; metadata results are `0x01020304` and `0xA1B2C3D4`; a supported single payload returns zero.
   - Metadata starts at offset 7 and is `06 01 02 03 05 00 B2 C3 D4`.
   - The payload destination is offset 16 and the allowance is 250.
   - N = 16; offset 1 becomes `0A`.
   - Only 10 bytes are requested, despite prefix writes through offset 15.

3. **Aggregate ordering and recomputed allowances.**  
   The short `0x1A` form is used; L = 100; operation is `0x3F`; the six returns are 1, 2, 3, 4, 5, and 6.
   - Destinations are offsets 4, 5, 7, 10, 14, and 19.
   - Allowances are 96, 95, 93, 90, 86, and 81.
   - N = 25; offset 0 becomes `18`; 25 bytes are requested.

4. **Unsupported operation still prepares the buffer.**  
   Operation `0x02` performs preparation and prefix completion, then reports `(2, 5, 0x2400)`. It makes no output request and finalizes if reporting returns normally.

5. **Both short and excessive output results fail equality.**  
   For a requested count of 9, either a return of 8 or a return of 10 produces notification `(2, 11, 0)`. Neither causes a visible retry.

6. **Classification changes without prefix conversion.**  
   Initial classification is `0x1A`; final classification is not; L = 32; the short prefix is selected; a single payload returns 5.
   - Construction begins with the four-byte short form and produces N = 9.
   - Finalization rewrites offset 1 to `07`, not offset 0.
   - The prefix is not converted to the form normally selected by the final classification.

7. **Zero limit still permits construction and an output call.**  
   Classification remains `0x1A`; L = 0; the selector returns nonzero; a supported single payload returns zero.
   - The initial prefix is `FF 00 00 00`.
   - The payload is called at offset 4 with allowance 252.
   - N = 4; offset 0 becomes zero because N > L.
   - Output is called with count zero. A zero return passes the equality check; any nonzero return produces the mismatch notification.

## Uncertainties

The following remain **documented_only**:

- Initialization and validity of the construction-buffer pointer and companion descriptor word.
- Actual buffer capacity and the unidentified external operation’s effects.
- Complete calling conventions and internal behavior of the four indirect operations.
- Meanings of classification `0x1A`, operation values, metadata fields, and error arguments.
- Whether payload returns measure physically written bytes, logical required size, or something else.
- Signed overflow semantics for metadata increment and accumulated payload additions.
- Consequences of invalid pointers, invalid destinations, or insufficient storage.
- Dependency mutation of globals, referenced objects, tables, aliased storage, or classification-pointer storage.
- Output retention, descriptor mutation, copying, and synchronization behavior.
- Whether error reporting returns normally.
- Resource ownership and release performed by initialization or finalization.

An **inferred intent** is that payload dependencies append serialized sections and return their lengths, and that the local management object supports temporary storage. Neither inference establishes a dependency contract, allocation size, or bounds safety.
