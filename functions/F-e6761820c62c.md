# F-e6761820c62c

## Purpose

F-e6761820c62c rewires a linked structure around a supplied node and the object referenced at that node’s offset `0x0C`.

The established behavior is a fixed sequence of 32-bit field reads and writes, including an update to either a distinguished reference slot or a neighboring object’s child-reference slot. No external function is called.

**Inferred intent:** under a conventional binary-tree layout, this operation is a left rotation. The supplied node moves below its former right child; the promoted child’s former left subtree becomes the supplied node’s right subtree; and the incoming reference to the supplied node is redirected to the promoted child. This interpretation requires structural and aliasing assumptions that the function does not check.

The contract below distinguishes the directly visible accesses from that tree interpretation.

## Behavior

### Ordered observable accesses

The following order is established by the supplied representation. Field values are read when described; they are not all captured at entry.

1. **Select the promoted object.**  
   Read the 32-bit field at target offset `0x0C`. Retain that address as the promoted-object address for the remainder of the operation.

2. **Replace the target’s outgoing reference.**  
   Read promoted-object offset `0x08` and write that 32-bit value to target offset `0x0C`.

3. **Conditionally repair the transfer object’s incoming reference.**  
   Read promoted-object offset `0x08` again and compare it with zero. If nonzero, read that field again to obtain the destination object address, then write the target address to that object’s offset `0x04`.

   If the tested value is zero, no transfer-object write occurs. This zero test does not validate any other reference.

4. **Give the promoted object the target’s incoming reference.**  
   Read target offset `0x04` and write the value to promoted-object offset `0x04`.

5. **Locate and inspect the distinguished slot.**  
   Read container offset `0x10`. Using that address, locate offset `0x04`, then read the resulting distinguished slot and compare it with the target address.

6. **Redirect the incoming reference.**
   - If the distinguished slot equals the target address, write the promoted-object address to that slot.
   - Otherwise, read target offset `0x04` to obtain the parent-object address. Read parent-object offset `0x08`.
     - If it equals the target address, write the promoted-object address to parent-object offset `0x08`.
     - Otherwise, write the promoted-object address to parent-object offset `0x0C`.

   The last branch does **not** check that parent offset `0x0C` previously referred to the target.

7. **Place the target beneath the promoted object.**  
   Write the target address to promoted-object offset `0x08`.

8. **Finish the target’s incoming reference.**  
   Write the promoted-object address to target offset `0x04`.

The distinguished-slot address is located only after the earlier mutations. Its holder is not captured at function entry. Similarly, on the non-distinguished path, the parent address is read after promoted-object offset `0x04` has been written.

### Result under ordinary tree assumptions

With distinct, stable objects and consistent tree links, let the target initially have a right child designated as the promoted object, and let that promoted object initially have a left subtree.

After normal completion:

- The promoted object replaces the target in the incoming parent link or distinguished slot.
- The promoted object inherits the target’s former parent reference.
- The target becomes the promoted object’s left child.
- The promoted object becomes the target’s parent.
- The promoted object’s former left subtree becomes the target’s right subtree.
- If that subtree exists, its parent reference becomes the target.
- The target’s left subtree and promoted object’s right subtree remain unchanged, assuming they do not alias other written locations.

This is the inferred left-rotation result. It is not a guarantee for malformed or overlapping structures.

1. Target offset `0x0C`.
2. Promoted-object offset `0x04`.
3. One incoming-reference slot.
4. Promoted-object offset `0x08`.
