# F-0c42192b67a5

## Purpose

F-0c42192b67a5 selects between two object-associated operations using a signed 32-bit selector. A successful selected operation supplies three 32-bit results, stores the third result in a path-specific object field, and conditionally sets flag bits.

A request equal to an externally stored comparison value bypasses all object access, output writes, and coordination calls. Otherwise, the function invokes an entry dependency, initializes flags, performs selection and any selected operation, and invokes an exit dependency before normal return.

**Established static behavior:**

- A selected operation returning zero is treated as successful.
- A selected operation returning nonzero causes the first two result outputs to be cleared; its status is returned.
- No matching identifier produces status one and clears the first two result outputs.
- The first identifier has priority when both identifiers match.
- The second identifier comparison evaluates a 32-bit object element, converts that value to signed 16 bits, and promotes the result for comparison. Its semantic identifier width is therefore 16 bits, but its source-level evaluation width is 32 bits.

**Inferred intent:** the paths retrieve related result records. The first path has one-time preparation; the second consumes a pending notification. These descriptions do not establish domain semantics or dependency behavior.

## Behavior

### Bypass and entry

The function first reads the externally referenced 32-bit comparison value and compares it with the request.

If equal, it returns one immediately:

- No object access.
- No result or flags write.
- No entry or exit dependency call.

If unequal, the function retains local copies of the object address, request, selector, and opaque fourth input, then calls an unresolved entry dependency with an externally referenced coordination target. No subsequent use of the copied opaque input is visible.

After the entry call returns, the function writes zero to the flags destination. This precedes both identifier comparisons.

The external comparison value’s meaning and synchronization are unknown. The entry call’s semantics and effects are also unknown.

### Identifier selection

The first comparison accesses the signed 16-bit identifier at `0x1CA`, promotes it to signed 32 bits, and compares it with the full selector.

If it matches, the first path is selected. The second comparison is not evaluated.

Only if the first comparison fails does the function evaluate the **32-bit object element at `0x1C8`**. It converts that value to signed 16 bits, then promotes the converted value for comparison with the full signed 32-bit selector. Under the represented width semantics, the low 16 bits determine that signed identifier; the remaining bits do not determine equality after conversion.

Consequently:

- A negative 16-bit identifier can match a negative selector.
- Matching low 16 bits alone is insufficient if the full selector differs from the sign-extended identifier.
- A selector outside the signed 16-bit range cannot match either comparison.
- The second comparison’s semantic narrowing does not justify treating its source access as only 16 bits.

Because flags are cleared before selection, aliasing between the flags destination and object storage can affect either comparison.

### First path: preparation and operation

The function calls F-2b447e614ee2 with a local working-storage address. It then reads the preparation-state byte at `0x1D1`.

If that byte is zero, the function:

- Obtains the current dispatch-table address from the object.
- Calls the entry at table offset `0x2C`, supplying the object, saved request, working-storage address, and a 32-bit zero.
