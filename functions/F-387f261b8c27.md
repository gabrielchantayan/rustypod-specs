# F-387f261b8c27

## Behavior

### Reading conventions

The following names describe observations, not source-level identifiers:

- **word slot at X** means a 32-bit access at address \(X + 20\).
- **indirect byte destination from X** means: read one unsigned byte at address \(X + 1\), then use that byte’s numeric value plus 17 as the destination address.
- Distinct named results come from distinct dependency-return occurrences. Equal values must not be assumed.
- A saved result remains a saved value across intervening calls. A fresh memory read does not reuse an earlier byte unless explicitly stated.

There are unresolved calls between many accesses listed below. The lists establish direct-access order; they do not imply that dependencies preserve memory between those accesses.

### 1. Initial state propagation

At iteration entry, the first dependency is invoked with the current second input twice, followed by the current third input. Four subsequent calls have no explicit arguments in the supplied representation. The final call supplies a word called the **first index**.

The operation then:

1. Stores the current second input in the word slot at four times the first index.
2. Passes four times the first index to another dependency.
3. Makes four further no-explicit-argument calls; the last supplies the **base index**.
4. Saves four times the base index as the **base payload**.
5. Stores the base payload in the word slot at sixteen times the base index.
6. Derives the **byte base** as the base index multiplied by \(2^{30}\).

Only the low two bits of the base index contribute to the byte base under 32-bit arithmetic.

A further dependency receives the base payload three times. After four more no-explicit-argument calls, the last supplies the **secondary index**. The base payload is stored in the word slot at four times that index.

Another call receives four times the secondary index. Four following calls produce the **selector word**.

### 2. Repeated input-byte writes and a computed word read

The operation writes the current fourth input:

1. At byte base plus 17.
2. At byte base plus 1.

A dependency receives the selector word shifted left by two. A following returned word is passed to another dependency; four more calls produce the **flag index**.

The same two byte writes occur again, in the same order. They are not redundant by contract: intervening dependencies may have changed either location.

A dependency receives four times the flag index. Four more calls produce the **record index**. The operation then:

1. Stores the secondary index shifted left by 31 in the word slot at sixteen times the record index.
2. Reads a 32-bit word from address  
   \(20 + ((\text{selector word} \mathbin{\&} \text{0x3fffffff}) \gg 20)\).

The stored shifted value is either zero or `0x80000000`, depending on the secondary index’s low bit.

The computed read address ranges from 20 through 1043 inclusive. It is not necessarily aligned to four bytes. The read remains a 32-bit read, including when its starting address is unaligned.

A dependency receives four times the record index. A subsequent call supplies a **retained index**. Another dependency receives the loaded word shifted right by 22 and then left by 28, with 32-bit truncation.

### 3. Initial indirect-byte updates

A dependency receives four times the clear index. Four following calls supply the **packed word**.

The operation then:

2. Writes the low byte of four times the packed word to the resulting indirect byte destination.

A dependency receives four times the packed word. A subsequent returned word is passed to another dependency together with the packed word shifted left by 30. Four following calls provide another index.

Next:

2. The low byte of  
   \((\text{packed word} \mathbin{\&} \text{0x3fffffff}) \gg 20\)

3. A dependency receives four times the newly returned index, followed by four no-explicit-argument calls.
4. Four times the retained index is written as a 32-bit word at saved byte plus 20.

## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **First word propagation.** If the first index is 3 and the current second input is `0x12345678`, the first direct store writes that word at address 32. This requires the preceding calls to return and the address to be writable.

2. **Input-byte truncation is not repeated.** If the fourth input is `0xAB`, both initial byte stores write exactly `0xAB`. Later iterations use zero because the iteration transition replaces this input.

3. **Byte-base reduction.** If the base index is 4, the byte base is zero under 32-bit arithmetic. The repeated input-byte stores therefore target addresses 17 and 1.

4. **Computed read boundary.** A selector word of `0x3fffffff` selects a 32-bit read beginning at address 1043. The representation provides no alignment repair or range rejection.

5. **Single-bit flag.** An even secondary index produces a zero flag word. An odd secondary index produces `0x80000000`, assuming 32-bit shift behavior.

6. **Saved selector versus reread.** If the saved selector byte is 7, the retained-index word is written at address 27 even if an intervening dependency changes the selector’s original location to 9.

7. **Indirect byte range.** A fresh selector byte of 255 directs the associated byte write to address 272; it is not treated as negative.

8. **Forced-zero argument.** Regardless of the shift source, shifting its 14-bit-left-shifted propagated value left by another 28 yields zero under 32-bit arithmetic.

9. **Iteration handoff.** If the next iteration index is 5, the next iteration starts with second and third inputs equal to 20 and fourth input equal to zero. Before that restart, 20 is stored at address 100.

10. **Interrupted progress.** If a dependency does not return after a direct store, that earlier store has occurred, but subsequent direct stores and the iteration transition have not been reached. No compensating action is shown.
