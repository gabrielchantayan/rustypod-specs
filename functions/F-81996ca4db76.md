# F-81996ca4db76

## Purpose

F-81996ca4db76 builds a 256-slot mapping from unsigned byte codes to 16-bit values and 16-bit indices into a supplied value table.

Selectors 0 and 1 use an external operation with different source arguments. Other selectors initiate stream-backed loading, supporting either an explicit code list or consecutive-code ranges. Either stream format can be followed by value overrides.

Updates are not transactional. Clearing, metadata assignments, completed mappings, and completed overrides remain in place if a later operation fails.

The interpretation of the values as character or glyph identifiers is inferred intent. The established behavior is a mapping operation over integer values and indices.

## Interface

The function accepts six arguments and returns a 32-bit integer status.

| Argument | Established role |
|---|---|
| Destination | Pointer to writable mapping state with the layout below. |
| Table descriptor | Pointer to an object containing a 32-bit table pointer at byte offset 8. |
| Table count | Unsigned 32-bit bound for table searches and indexed copies. |
| Input context | 32-bit context argument passed to dependencies. In the explicit-list path, its field at byte offset 32 is read directly as a byte-buffer pointer. |
| Base position | 32-bit quantity used to compute stream-backed position metadata. |
| Selector | Unsigned 32-bit quantity. Values 0 and 1 select externally supplied mappings; all greater values select stream-backed processing. |

### Destination layout

All offsets are measured in bytes from the destination address.

| Offset | Size | Meaning established by access |
|---|---:|---|
| 0 | 4 bytes | Format/flags word. The initial stream header assignment stores a zero-extended byte. |
| 4 | 4 bytes | Position metadata. |
| 8 | 4 bytes | Extent metadata, calculated differently by each mapping path. |
| 12 | 512 bytes | 256 consecutive 16-bit value slots. |
| 524 | 512 bytes | 256 consecutive 16-bit index slots. |

The destination must support accesses through byte offset 1035 inclusive.

A zero index does not uniquely identify an unmapped code. It can also represent a match at table index zero or an unchanged index after an unmatched override.

### Representation and preconditions

The table contains consecutive 16-bit entries. Comparisons use equality of their 16-bit representations; signed interpretation does not change the equality result.

Defined execution requires valid storage, compatible alignment and representation, and valid addresses for every reached access. The function does not validate destination size, descriptor size, table capacity, buffer capacity, or overlap.

Address arithmetic is expressed in a 32-bit environment. In particular, large table counts do not establish that twice an index is a nonwrapping address offset. Callers must ensure that all reached address calculations identify valid storage.

No ownership transfer is established for any argument. Validity requirements imposed by dependencies remain additional prerequisites.

## Behavior

### Entry gate and initial clearing

The first relevant access is a read of the table pointer from descriptor offset 8.

If that pointer is null, the function returns 3. It performs no destination writes and calls no dependency on that path.

Otherwise, it visits codes 0 through 255 in increasing order. For each code, it writes:

1. Zero to the 16-bit value slot.
2. Zero to the corresponding 16-bit index slot.

This clearing does not directly write any of the three leading metadata words.

The entry pointer check is not a lasting table-pointer snapshot. Later table accesses load the pointer again from the descriptor.

### Selectors 0 and 1: externally supplied mapping

After clearing, both selectors first read a default source-argument global as a 32-bit value.

- Selector 0 uses that loaded value.
- Selector 1 subsequently reads an alternative source-argument global and uses the second value instead.

Thus, selector 1 reads both globals, in default-then-alternative order. The globals themselves are not established to be mapping objects. Their loaded values become arguments to an unknown external operation.

That operation receives:

- The address of the destination value array.
- The selected 32-bit source argument.
- A length argument of 512 bytes.

Its implementation and source data are unavailable. A copy-like purpose is inferred from the invocation, but its exact effects are not established. The remaining behavior operates on destination memory as it exists after the call.

The function next writes zero to the extent field and processes all 256 value slots in increasing code order.

For each code:

- It reads the 16-bit value.
- If the value is zero, it performs no further processing for that code.
- Otherwise, it searches the table beginning at index 1.

The search compares entries while its index is less than the table count. It stops at the first equal entry or when that bound prevents another comparison.

If the terminal search index equals the table count, the function clears the **index slot first**, then clears the **value slot**.

Otherwise, it stores the low 16 bits of the terminal index in the index slot. It then raises the extent to the current code plus one if the existing unsigned extent is smaller.

Under stable table contents and ordinary nonaliasing storage, a successful search chooses the earliest matching table entry starting at index 1. Table index zero is not considered.

Two count boundaries are significant:

- **Count 1:** Every nonzero value is rejected, because the initial search index already equals the count.
- **Count 0:** No table comparison occurs. The initial index is 1, which does not equal zero, so every nonzero value is retained and receives index 1.

The count-zero behavior follows the branch conditions; it does not establish that callers are intended to pass zero.

This path returns zero. It does not directly assign the format/flags or position fields. Effects of the unknown external operation on those fields are not established.

### Stream-backed initialization

For selectors of at least 2, the function first assigns:

\[
\text{position}=(\text{base position}+\text{selector})\bmod 2^{32}.
\]

It calls F-e40a3ceddab2 with the input context. A nonzero result is returned immediately.

It then calls F-6fa39a8df0d4 with the context and a pointer to a local 32-bit status:

1. The low eight bits of the result are stored, zero-extended, in the format/flags word.
2. Only afterward is the status checked.
3. A nonzero status is returned immediately.

A second call to F-6fa39a8df0d4 supplies a count from its result’s low eight bits. Its status is checked before format processing.

Format decisions read the destination flags rather than relying solely on the original header result:

- Low seven bits equal to 0 select an explicit code list.
- Otherwise, another flags read tests for low seven bits equal to 1, selecting ranges.
- If neither test selects a format, the unsupported-format path is taken.

After either supported format, a further flags read tests bit 7 for an override section. Higher bits, if introduced by other writes, do not participate in these masks.

### Format 0: explicit code list

The count byte is a list length from 0 through 255.

The function writes extent equal to length plus one, then calls F-d036abe1e536 with the context and length. A nonzero result is returned immediately, leaving that extent assignment in place.

On success, it reads the byte-buffer pointer from context offset 32 once. It directly reads the declared number of code bytes from consecutive addresses beginning at that pointer.

List positions correspond to table indices starting at 1. At each position:

- The code byte is read even if its corresponding table index is outside the table bound.
- If the index is strictly below the table count, the index slot is written first.
- The table pointer is then loaded from the descriptor, the corresponding 16-bit entry is read, and the value slot is written.
- An out-of-bound index produces neither mapping write.

The buffer cursor advances locally. No direct store of the advanced cursor back into the context is visible.

Duplicate codes are permitted. Later eligible positions overwrite earlier mappings for the same code. A later ineligible position does not erase an earlier mapping.

After the loop, including when the list length is zero, the function calls F-9787e15c337d with the context. Its return value is not captured. Processing then reaches the override decision.

Absent other memory effects, extent remains the declared length plus one, not the number of populated codes or the highest code.

### Format 1: consecutive-code ranges

The count byte specifies zero through 255 ranges.

The function sets extent to zero and begins assigning table positions at index 1. For each range, it calls F-6fa39a8df0d4 twice:

1. To obtain a starting code from the low eight result bits.
2. To obtain a length-minus-one byte from the low eight result bits.

Status is checked after each call. Neither mapping writes nor the range’s extent update occur until both reads succeed.

The length is the second byte plus one, so it lies between 1 and 256. The function raises extent to that length if the existing unsigned extent is smaller.

Each range position advances both the table index and the code. A mapping is written only when:

- The table index is strictly below the table count; and
- The code is below 256.

Eligible positions write the index slot first, then reload the descriptor’s table pointer, read the table value, and write the value slot.

Code progression does not wrap at 255. Positions beyond code 255 are skipped but still consume table positions. The following range begins after the entire declared length of the preceding range. Overlapping ranges can overwrite earlier mappings.

After all ranges, the function reads extent and caps it at 256 if it is larger. Without external or alias-induced changes, extent is the maximum individual range length, or zero for no ranges. It is not the total length or highest mapped code.

The function’s range arithmetic consumes at most \(255\times256=65{,}280\) table positions. The next unused index is therefore at most 65,281; this arithmetic does not approach 32-bit overflow.

### Optional overrides

After either supported base format, the function rereads the flags word.

If bit 7 is clear, it returns the current status. Otherwise, F-6fa39a8df0d4 supplies an override count from its low eight result bits. A nonzero status terminates processing before any override entry is read.

Each override requires:

1. A code read through F-6fa39a8df0d4, using its low eight result bits.
2. A 16-bit value read through F-8f49ed59b67e.

The status is checked after each call. A failing read prevents that override’s direct mapping writes, although dependency side effects are not excluded.

After both reads succeed, the function writes the value slot immediately. It then searches the table from index zero, considering entries strictly below the table count.

- The first equal entry causes its index, narrowed to 16 bits, to be written to the index slot.
- If no entry matches, the index slot is not changed.

Consequently, an unmatched override can leave a new value paired with an index from a base mapping or earlier override. A match at table index zero writes zero without clearing the value.

Overrides do not directly update extent. Repeated overrides for the same code are processed in input order.

### Unsupported format and failure

An unsupported format calls F-4457a9a44a68 with a fixed invalid-table diagnostic. If that dependency returns normally, the function returns 3. Both header reads have already completed before this path is reached.

Other detected errors return the nonzero status supplied by the relevant dependency, without translation or rollback.

Depending on the failure point, the destination can retain cleared arrays, partial mappings, new position metadata, a newly stored flags byte, and either old or updated extent metadata.

## Side effects

Direct effects are destination writes, reads of descriptor and table storage, ordered reads of source-argument globals on selectors 0 and 1, and direct buffer reads in format 0.

The function contains no explicit allocation or deallocation. Dependencies may allocate, release, retain, or otherwise affect memory; their implementations are not supplied.

Only format 0 calls F-9787e15c337d, after successful buffer preparation and completion of the direct byte loop. No corresponding call is visible after buffer-preparation failure or on other paths.

The function does not assume a stable table-pointer snapshot: each reached table comparison or copy reloads the descriptor field. An eligible list or range entry writes its destination index before reading that pointer and table value. Overlap can therefore affect the subsequently copied value.

Destination flags are also reread at decisions. Dependency changes to flags can affect format selection or whether overrides are attempted.

Descriptions of ordinary resulting mappings assume stable inputs and noninterfering storage. They do not establish that dependencies preserve globals, destination fields, descriptor contents, or ownership.

## Acceptance examples

These are conditional static cases, not executed tests. Unless stated otherwise, dependencies succeed, storage does not interfere, and relevant inputs remain stable.

1. **Null entry pointer.** A null table pointer at descriptor offset 8 produces status 3 without destination writes or dependency calls.

2. **Source-argument read order.** Selector 0 reads the default global and passes that loaded value to the external operation. Selector 1 first reads the default global, then reads the alternative global and passes the alternative value.

3. **Earliest predefined match.** A post-operation value of 42, table count 6, table index 1 unequal to 42, and indices 2 and 5 equal to 42 produce stored index 2. If index 1 also equals 42, the stored index is instead 1.

4. **Predefined rejection ordering.** With count 1 and a nonzero value slot, the index slot is cleared before the value slot.

5. **Predefined zero count.** With count zero and a nonzero post-operation value at code 200, the value is retained, index 1 is stored, and extent reaches at least 201. That search reads no table entry.

6. **Repeated explicit code.** A format-0 list of codes 7, 7, and 9 with table count 4 leaves code 7 mapped from table index 2 and code 9 from index 3. Extent is 4.

7. **List beyond the bound.** List length 3 and table count 2 cause all three bytes to be read, but only the first position is eligible for mapping. Extent is 4.

8. **Range crossing 255.** A range starting at code 254 with length 4 can map only codes 254 and 255. All four table positions are consumed before the next range. Its extent contribution is 4.

9. **Range extent.** Two ranges of lengths 3 and 5 produce extent 5, not 8.

10. **Unmatched override.** If a code initially has index 6 and its override value is absent from the table, the new value is stored while index 6 remains.

11. **Match at zero.** An override whose first match is table index zero stores index zero and retains the supplied value.

12. **Header failure ordering.** If the first header call returns low byte 129 and a nonzero status, flags become 129 before that status is returned. No second header call follows.

13. **Unsupported format.** Stable flags with low seven bits equal to 2 reach the diagnostic after both successful header reads. Normal diagnostic return is followed by status 3.
