# F-3020fe0d05d6

## Purpose

F-3020fe0d05d6 conditionally performs a preliminary notification, then conditionally constructs and processes a work object against shared state.

A work object containing a nonzero associated pointer undergoes discriminator-based state handling, queue-like insertion, notification-like calls, and secondary construction and submission. A work object containing a zero associated pointer instead takes a virtual cleanup-like path. Both main paths finish with a conditionally executed indirect call.

The contract below distinguishes explicit operations from inferred roles. “Event,” “construction,” “queue,” “notification,” and “cleanup” describe apparent intent; they do not establish dependency semantics, ownership, or synchronization guarantees.

## Interface

### Input and representation

The function accepts one record pointer. The supplied representation uses 32-bit integers, 32-bit pointer-bearing storage, and byte-addressed offsets.

| Input location | Observed access | Purpose |
|---|---|---|
| +0 | Signed 32-bit read, conditional | Preliminary threshold comparison |
| +4 | 32-bit word read followed by character conversion | Initial nonzero flag |
| +5 | Explicit character-sized read | Main-path gate |

The initial flag is obtained by converting the word at +4 to a character, not by an independently expressed byte load at +4. Its exact correspondence to stored bytes depends on target byte order and conversion conventions. Character signedness does not affect the subsequent zero/nonzero comparison.

The original input pointer is also passed unchanged to the first invocation of F-afb630a7107c.

### Output

There is no explicit return value or returned status code. Observable results are dependency calls, direct memory writes, object handling, and a possible final indirect call.

### Access preconditions

Ordinary completion requires valid storage and callable targets for all accesses selected by the path:

- The input must support the word read at +4 and the later byte read at +5.
- A nonzero initial flag additionally requires a readable signed 32-bit value at input +0.
- The first constructed work object must support a pointer read at +8. No null check precedes that read.
- The shared-state pointer must support the fields and subobject addresses described below.
- A nonzero associated event pointer must support a signed 32-bit read at +4.
- The payload-copy case requires a readable pointer at event +12 and a readable 32-bit value at its target.
- Virtual dispatch requires readable dispatch pointers, readable dispatch entries, and callable targets.
- Queue-like storage must support a pointer write at +4.
- A nonzero pointer read during the final gate must support a 32-bit read at its target.
- The opaque data locations used for comparisons, construction descriptors, and the final callable must be readable when reached.

These are requirements implied by accesses, not validations performed by this function. Alignment requirements and invalid-access behavior are not established.

## Behavior

### 1. Preliminary notification and delayed main gate

The function first reads the input word at +4 and tests whether its character conversion is nonzero.

Only when this test succeeds does it read the signed 32-bit integer at input +0. If that integer is strictly greater than 20, it calls, in order:

1. F-6622e2509ce3, retaining its 32-bit result.
2. F-4ffd7bc0e22a, retaining its 32-bit result.
3. F-b8522592e971, passing the second result as the first argument and the first result as the second argument.

Exactly 20, smaller positive values, zero, and negative values do not trigger this sequence. When the initial flag is zero, input +0 is not read by this function.

The explicit byte read at input +5 occurs after the optional notification sequence. If that byte is zero, the function returns. Otherwise, main processing begins.

These conditions are not an entry-time snapshot. Preliminary dependencies may affect the byte subsequently read at +5; their effects are not assumed absent.

### 2. First construction and shared-state acquisition

Main processing proceeds in this order:

1. Call F-a66a9be680df.
2. Pass its result and the value 12 to F-c5a232e4455b.
3. After F-c5a232e4455b returns, read the first construction descriptor from an opaque 32-bit data location.
4. Call F-afb630a7107c with the preceding result, that descriptor value, and the original input pointer.
5. Retain the returned work-object pointer.
6. Call F-c0c0b8633623 and retain the shared-state pointer.
7. Call F-338d16f9ce72 with the address at shared-state +268, or +0x10C.
8. Read the event pointer from work-object +8.

The first descriptor is a data read at this stage, not an established immutable constant. In particular, its value is obtained after F-c5a232e4455b returns.

The value 12 is visibly passed to construction-related dependencies. Its meaning as an allocation size or object size is not established.

### 3. Zero event pointer

If the event pointer is zero, the function checks whether the work-object pointer is nonzero. If so, it invokes the work object’s virtual entry at dispatch-table byte offset +4, explicitly supplying the work-object pointer.

This null check does not make a null construction result safe: work-object +8 has already been read.

Execution then reaches the common final gate. No discriminator handling, queue-like insertion, secondary notification, or secondary construction occurs on this path.

The virtual entry may release or destroy the object, but neither behavior is established.

### 4. Nonzero event pointer and comparison-data reads

For a nonzero event pointer, the function reads the signed 32-bit discriminator at event +4.

It then dispatches using an opaque comparison-data location with this ordering:

1. Read the comparison operand and test discriminator equality.
2. If equal, write the 32-bit value 1 to shared-state +320.
3. If unequal, read the comparison operand again and perform a signed less-than test.
4. A successful less-than test selects the lower group below.
5. A failed less-than test selects the remaining group below.

The discriminator is retained from its event read. The comparison operand is referenced separately for the equality and less-than tests; its immutability is not established.

Only under the additional assumption that both comparison reads return the same value may this be described as a single-pivot dispatch: equality, then strictly smaller values, then strictly greater values. Without that assumption, the remaining group means “unequal to the first observed operand and not less than the second observed operand.” It can include equality with the second operand.

### 5. State fields and lower-group cases

The relevant shared-state fields are:

| Offset | Width | Observed use |
|---|---|---|
| +320 / +0x140 | 32 bits | Mode-like state; signed comparisons include −1, 1, and 2 |
| +324 / +0x144 | 32 bits | Count-like state; −1 selects initialization |
| +328 / +0x148 | 32 bits | Raw payload value |

When the signed less-than test selects the lower group:

| Discriminator | Direct behavior |
|---|---|
| 0x6600000D | Write 0 to +324, then 0 to +320 |
| 0x66000014 | Optional sentinel initialization, then increment +324 |
| 0x66000015 | Optional sentinel initialization, then conditional decrement |
| 0x66000017 | Write 0 to +324, then 0 to +320 |
| Any other value | No direct state-field write in this dispatch stage |

For either count-related case, the function first reads +324 and compares it with −1. If equal, it:

1. Calls F-87be4aa684d1.
2. Reads the returned object’s dispatch table and invokes the entry at byte offset +364, or +0x16C.
3. Writes the returned 32-bit value to shared-state +324.

No explicit argument list is shown for that virtual invocation. Its implicit receiver and full calling convention remain unknown.

For discriminator 0x66000014, the function then reads +324, adds 1, and writes the result to +324. This arithmetic read occurs after optional initialization; it is not the sentinel-test read.

For discriminator 0x66000015, the subsequent sequence is different:

1. Read +324 and test whether the signed value is greater than zero.
2. If the test fails, perform no decrement write.
3. If the test succeeds, read +324 again, subtract 1 from this second value, and write the result to +324.

The subtraction operand is therefore not necessarily the value that passed the positivity test. No established exclusion or stability guarantee permits merging these reads.

Arithmetic is represented as signed 32-bit arithmetic without a visible overflow guard. Incrementing the maximum signed value is unresolved without target arithmetic evidence. For decrement, stability would make subtraction safe after a positive test; without stability, the second read could instead observe the minimum signed value, making overflow behavior unresolved there as well. Neither operation is specified as unbounded mathematical arithmetic, saturation, or guaranteed wraparound.

### 6. Remaining-group cases

If equality failed and the subsequent signed less-than test also fails:

| Discriminator | Direct behavior |
|---|---|
| 0x6600001A | Write 0 to +320 |
| 0x6600001B | Perform the mode transition below |
| 0x66000024 | Copy a pointed-to 32-bit payload value into +328 |
| Any other value | No direct state-field write in this dispatch stage |

For 0x6600001B, the function reads +320 as the transition candidate. If it equals −1, it calls F-87be4aa684d1 and invokes the returned object’s virtual entry at dispatch-table byte offset +396, or +0x18C. The result becomes the candidate; it is not first stored at +320.

A candidate of 1 causes a write of 2 to +320. A candidate of 2 causes a write of 1. Any other candidate produces no direct mode write. No second read of +320 supplies this decision.

For 0x66000024, the function reads the pointer at event +12, reads the 32-bit value it addresses, and writes that value to shared-state +328. The copied bits are uninterpreted. No null check, payload validation, or payload ownership transfer is visible.

2. Call F-8157a180d901 with 8.

There is no null check before writing at returned-storage +4. Only that pointer-bearing field is explicitly initialized here; the remaining bytes of the storage requested with 8 are unspecified by this function.

The calls on shared-state +300 and +308 resemble synchronization and notification, but do not establish locking, exclusion, or wakeup semantics.

### 8. Common final gate

Both main paths reach this stage.

The function reads a pointer from shared-state +268. If it is zero, it returns without reading through it. Otherwise, it reads the first 32-bit word of the pointed-to object. A zero word also causes return.

If both pointer and word are nonzero, the function invokes the callable obtained from a separate opaque global data location, with no explicit arguments shown.

This is not visibly a virtual call through the object inspected by the gate. That object supplies only the gating pointer and word. The separate callable’s identity, stability, calling convention, and effects remain unknown.

## Side effects

Direct writes are limited to:

- The discriminator-selected writes at shared-state +320, +324, and +328.
- The work-object pointer write at offset +4 of newly obtained storage.

Dependencies, virtual calls, and the final indirect call may have additional effects. They must not be assumed to preserve input bytes, shared-state fields, opaque data locations, globals, object contents, or object lifetimes.

The nonzero-event path passes storage containing the work-object pointer to F-37efbe955e3e and does not subsequently invoke the work object’s cleanup-like entry. This suggests an ownership handoff, but retention and release obligations are unknown.

On the zero-event path, the virtual entry may release the work object. The lifetime of the secondary object after F-9a5c97dc580d is likewise unknown. No visible operation establishes ownership or release of the event payload.

There are no explicit error-result checks or local rollback steps. Failures may occur after state writes or dependency effects have happened. Allocation-failure conventions, exceptions, abnormal control transfers, and dependency-provided cleanup are not established.

## Acceptance examples

These are conditional static examples, not executed tests. Access validity, ordinary dependency returns, and any stated stability assumptions are prerequisites.

1. **Disabled paths.** If the initial converted flag is zero and the later byte at +5 is zero, input +0 is not read, no dependency is called, and the function returns.

2. **Strict preliminary threshold.** A nonzero initial flag and input value 21 cause the three preliminary calls in the specified order. Input value 20 does not. If the later byte at +5 is zero, neither case enters main processing.

3. **Delayed gate.** If a preliminary dependency changes input +5 from zero to nonzero, the later gate can observe the changed byte and enable main processing.

4. **Descriptor read timing.** If F-c5a232e4455b changes the first descriptor location before returning, the first construction uses the subsequently read value. The corresponding rule applies to F-0a77364c41cc and the second descriptor.

5. **Zero event.** A valid work object with a zero pointer at +8 takes its virtual +4 entry before the common final gate. Queue-like insertion and secondary construction do not occur.

6. **Stable comparison and ordered reset.** If both comparison reads return the same value greater than 0x6600000D, that discriminator writes zero to +324 before writing zero to +320, then takes the full nonzero-event continuation.

7. **Separate comparison observations.** Suppose the discriminator is 0x66000024, the equality operand is 0x66000025, and the later less-than operand is 0x66000024. If those distinct observations are possible, equality fails and less-than also fails. The payload-copy case is selected, not the equality write of 1 to +320.

8. **Initialized increment.** With the lower group selected for 0x66000014, an initial count of −1 and query result 7 cause writes of 7 and then 8, assuming the subsequent arithmetic read observes 7.

9. **Separate decrement reads.** With the lower group selected for 0x66000015, a positive-test read of 3 followed by a subtraction read of 0 produces a write of −1, if such differing observations are possible. A positivity-test read of zero suppresses the subtraction read and decrement write.

10. **Queried mode.** With the remaining group selected for 0x6600001B, an initial mode of −1 and query result 2 cause a write of 1. A query result of 0 causes no direct mode write.

11. **Equality precedence.** If the first comparison read equals the discriminator, the function writes 1 to +320 and does not perform the second comparison read or any numeric-case dispatch.

12. **Final gate.** A null pointer at shared-state +268 suppresses the pointed-to word read and final call. A nonnull pointer with a zero first word suppresses the final call. A nonzero pointer and nonzero word enable the separate indirect call.
