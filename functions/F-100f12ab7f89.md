# F-100f12ab7f89

## Purpose

F-100f12ab7f89 selects between a bulk-processing/reset path and an iterative cursor-processing path. It writes a caller-supplied 32-bit output word and returns a separate 64-bit value assembled from two 32-bit words.

**Established behavior:** the function initializes the output from a context field, performs comparison-dependent eligibility checks, and takes the bulk path only if two comparison results and a context state field are all nonzero. Otherwise, it repeatedly compares a cursor with a boundary, advances the cursor, and processes the value captured before advancement. Iteration terminates only when the comparison returns exactly 1.

**Inferred intent:** the accessed structure may be a sentinel-based container. The bulk path resembles clearing the container, while the iterative path resembles processing or erasing a range. These interpretations do not establish a container type, ownership model, or deletion policy.

The contract below distinguishes direct operations of this function from effects of its dependencies. Dependency names describe observed roles, not guaranteed semantics.

### Private state

The function uses four relevant private words:

- A snapshot initialized from structure +8 and passed by address to the first comparison.
- A temporary word initially holding the cursor reference; if the first comparison is nonzero, it is replaced with a freshly loaded structure reference and passed by address to the second comparison.
- A context/result word initialized to the original context reference.
- A candidate word initialized to the original output address.

The context/result and candidate words are passed by address to per-candidate processing. Their update rules differ: the context/result word is not directly reinitialized between passes, whereas the candidate word is directly overwritten on every pass.

### Outputs and return representation

The output word receives a direct write at entry. The bulk path writes it again after resetting state. Each completed iterative processing pass also writes it.

The direct return is a 64-bit concatenation:

- The upper 32 bits contain one selected word.
- The lower 32 bits contain another selected word.
- Each word contributes its 32-bit bit pattern, without sign extension into the other half.

On the bulk path, the upper word is the structure reference loaded immediately before the final output write. The lower word is the original output address.

On the iterative path, the upper word is the current context/result word and the lower word is the current candidate word when the return is constructed.

No success, error, ownership, or pointer interpretation of the complete return value is established.

## Behavior

### Entry initialization

The function first reads context +16 and writes that 32-bit value to the output word.

It then reloads context +16 and reads structure +8 through the reloaded reference. This second value becomes the private comparison snapshot.

The ordering is observable under aliasing. For example, if the output overlaps context +16, the snapshot read uses the state present after the output write. The function does not guarantee that the initial output and the snapshot originate from an unchanged object.

Before calling any dependency, the candidate word contains the output address, the context/result word contains the context reference, and the temporary word contains the cursor reference.

The first call to F-1c076abb7b7f receives:

1. The cursor reference.
2. The address of the private structure +8 snapshot.

The function tests this result for zero versus nonzero.

### Bulk-path eligibility

If the first comparison returns zero, the second preliminary comparison is skipped, and context +20 is not directly read for eligibility. Execution proceeds to the iterative path.

If the first comparison returns nonzero:

1. Context +16 is reloaded into the private temporary word.
2. F-1c076abb7b7f receives the boundary value and the address of that temporary word.
3. If this second result is nonzero, context +20 is read.
4. The bulk path is selected only if both the second result and the value read from context +20 are nonzero.

These eligibility decisions accept every nonzero 32-bit result, not only 1. A result with all bits set qualifies just as a result of 1 does.

The second comparison receives the address of a private copy of the structure reference, not the address of context +16. Changing that private copy alone does not directly change context +16. Other dependency effects remain unknown.

A nonzero first comparison followed by either a zero second comparison or a zero context +20 value leads to the iterative path.

### Bulk processing and reset

The bulk path calls F-988a0b75f36b with:

- The original context reference.
- The 32-bit value at structure +4, reached through a fresh read of context +16.

The direct return value of this dependency is ignored.

After it returns normally, the function performs these direct stores in order:

1. Store a value read from context +16 into structure +8, with the destination also obtained through context +16.
2. Store zero into structure +4.
3. Store a value read from context +16 into structure +12, with the destination also obtained through context +16.
4. Store zero into context +20.
5. Reload context +16 and store that value into the output word.

The structure reference is not held fixed across the dependency call or across the reset sequence. Repeated context reads select the relevant destinations and self-reference values. The representation does not establish a finer ordering between operand reads within an individual self-reference assignment.

With stable, disjoint storage, these operations make +8 and +12 point to the same structure, clear +4, and clear context +20. If the dependency changes context +16, subsequent reset operations follow the changed reference. Aliasing between destinations and the context can also affect later operations.

The function then returns the final output-assigned structure reference in the upper word and the original output address in the lower word. It does not perform an iterative comparison or cursor advancement on this path.

### Iterative processing

When bulk processing is not selected, F-1c076abb7b7f is called with the cursor reference and the boundary value.

The loop terminates only when the result is **exactly 1**. Zero and every nonzero value other than 1 cause an iterative pass.

Each pass has the following observable sequence:

1. Read and preserve the cursor’s first 32-bit word.
2. Call F-e4e03c421405 with the cursor reference.
3. Overwrite the candidate word with the value captured before that call.
4. Call F-03c5c9b9557d with the address of the context/result word, the original context reference, and the address of the candidate word.
5. Read the current context/result word and write it to the output word.
6. Perform the next iterative comparison.

Thus, per-candidate processing receives the captured pre-advancement value, even if advancement has changed the cursor’s first word. The dependency’s direct return is ignored.

The two writable scratch words have distinct persistence rules:

- **Context/result word:** initialized once to the context reference. This function does not reset it between passes. A dependency-written value can remain available to later processing.
- **Candidate word:** initialized to the output address, then overwritten during every pass with that pass’s captured cursor word. A candidate value written by per-candidate processing does not carry unchanged through another pass: the next pass replaces it after advancement and before processing.

A dependency-written candidate value reaches the packed return only if no subsequent operation changes it before return. In particular, a later pass necessarily overwrites it. Effects through previously exposed scratch addresses are not specified by the dependency interfaces.

When a comparison finally returns exactly 1, there is no additional direct output write. The current context/result and candidate words form the upper and lower return words, respectively.

### Zero-pass iterative path

If the first iterative comparison returns exactly 1:

- No cursor-first-word capture occurs.
- Neither advancement nor per-candidate processing occurs.
- This function performs no direct output write after its entry write.
- The context/result word remains initialized to the original context reference.
- The candidate word remains initialized to the original output address.

Consequently, the packed return contains the original context reference above the original output address.

The final output value is not unconditionally established by the entry write. At least the first preliminary comparison and the terminating iterative comparison have executed; a second preliminary comparison may also have executed. Their effects are unknown. They may change the output through an aliased argument or other reachable state.

Only under an explicit assumption that these dependencies preserve the output word does it retain its entry value.

## Acceptance examples

### Short-circuited eligibility and no passes

Given a first preliminary result of zero and a first iterative result of 1:

- The second preliminary comparison is skipped.
- Context +20 is not directly read for eligibility.
- No bulk processing, advancement, or per-candidate processing occurs.
- No direct output write follows the entry write.
- The return contains the original context reference above the original output address.

If both executed comparisons preserve the output, its final value equals the entry value. Without that preservation assumption, its final contents are unspecified by this function’s direct writes alone.

### Comparison changes output on a zero-pass path

Suppose an executed comparison changes the output through reachable state and the first iterative comparison returns 1.

The function does not restore the entry value before returning. Under the assumption that no later dependency changes that word, the comparison-written value remains in the output.

### Second preliminary comparison rejects bulk processing

Given a nonzero first result and a zero second result, context +20 is not directly read for eligibility. The next decision is an iterative comparison, regardless of context +20’s contents.

### Nonterminating nonzero comparison result

Given iterative results of 2 followed by 1, exactly one pass occurs. The candidate supplied to processing is the cursor word captured before advancement. The result 2 does not terminate iteration.

### Candidate replacement across two passes

Suppose the first pass captures value P, and processing changes its candidate word to X. Suppose the next iterative comparison permits another pass, whose cursor capture is Q.

The second processing call receives Q, not X, in the candidate word. If it leaves that word as Y and the next comparison returns 1 without changing scratch storage, the return’s lower word is Y.

If processing left the context/result word as A on the first pass, the function does not reinitialize it before the second processing call.

### Final scratch values and output

Suppose the final processing call leaves the context/result word as A and the candidate word as B.

The function directly writes A to the output immediately after that call. If the terminating comparison preserves those scratch words, the return contains A above B. If that comparison also preserves the output, the final output is A.

### Bulk dependency redirects the structure

Suppose bulk processing changes context +16 to another valid structure reference.

With otherwise stable, disjoint storage, the later reset writes target the newly referenced structure. The final output and upper return word use the reference loaded after the reset, not an entry-time reference.
