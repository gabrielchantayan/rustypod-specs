# F-2571cdad928d

## Purpose

F-2571cdad928d conditionally populates selected fields of an existing, fixed-stride output record array using metadata associated with a signed 16-bit selector.

The established behavior has two phases:

1. Generate a value and a position for each emitted record, using grouped source positions and either a common value or a per-record value.
2. Generate timing-related fields from run-length metadata through an opaque conversion dependency.

Successful completion returns the 32-bit value **0**. The explicitly unsuccessful paths return **3**. One unsuccessful path also invokes an indirect callback on the input object.

The interpretation of the generated fields as sizes, positions, and timing is inferred from their arithmetic and placement. Their application-level units and meaning are not established.

## Interface

One pointer to an object with a 32-bit layout. The function accesses:

| Object-relative byte offset | Established use |
|---|---|
| `0x00` | Pointer to a table containing an indirect callback |
| `0x1B0` | 32-bit association value supplied to F-a2a686313150 |

There is no initial null-pointer check for the object itself. A readable object through offset `0x1B0` is therefore a precondition for defined execution.

### Return value

The return is 32 bits:

- **0:** both output-population phases completed.
- **3:** the association value was zero, the selector provider returned zero, metadata lookup returned zero, or the preparation dependency returned zero and the callback subsequently returned normally.

These values do not establish the absence of side effects inside dependencies. No other explicit return value appears.

## Behavior

### 1. Eligibility, selection, and preparation

The function first reads the association value at object offset `0x1B0`.

- If zero, it returns 3 without invoking any named dependency.
- Otherwise, it calls F-8b2d02fa1959.
- If that result is zero, it returns 3.

For a nonzero selector-provider result, the function reads the signed 16-bit selector at offset `0x1A`. It then calls F-a2a686313150 with the association value and sign-extended selector.

The association value is read for this call after F-8b2d02fa1959 has returned. It is not guaranteed to equal the value that passed the initial nonzero check if that dependency changes the object.

If metadata lookup returns zero, the function returns 3. Otherwise, it calls F-870f7f736b83 with the selector-provider result and the same captured selector.

If preparation returns zero:

1. The function obtains the callback through the input object's table.
2. It invokes that callback with the original object pointer.
3. If the callback returns normally, the function returns 3.

This is the only explicit callback path. No cleanup or release behavior may be attributed to the callback without its separate contract.

If preparation returns nonzero, F-02d6ae513643 is called with the selector-provider result. Its return becomes the output base. This result is not checked for zero.

### 2. Value and position generation

After obtaining the output base, the function captures:

- The output count.
- The common value.
- The total source-position count.

The captured output count controls entry into the outer generation loop. It does **not** bound every record write inside that loop.

Generation starts with output index zero, consumed source-position count zero, and group index zero. While the output index is less than the captured output count, the current group's source-position span is determined as follows:

- If the group index is at or beyond the grouping descriptor's last-group threshold, the span is the captured total source-position count minus the consumed count.
- Otherwise, the span is the next grouping entry's boundary minus the current grouping entry's boundary.

The comparison reads the grouping descriptor's count at that time. The boundary subtraction uses entries separated by the 12-byte stride.

For every source position in the computed span:

1. Read the source-position value at the current consumed position plus the position's index within this span.
2. Reset a per-position accumulator to zero.
3. Repeat according to the current grouping entry's repetition count.
4. For each repetition:
   - Select the captured common value if nonzero.
   - Otherwise, read the per-record value indexed by the current output index.
   - Write the source position plus the current accumulator to output field `0x08`.
   - Write the selected value to output field `0x00`.
   - Add the selected value to the accumulator.
   - Advance the output index.

Thus, each source position begins a new local accumulation. Values emitted from a previous source position do not contribute to the next source position's offsets.

The position field is written **before** the value field for each record. When per-record mode is active, the value is read before either write.

After the group's source-position loop finishes, the consumed count advances by the computed span and the group index advances by one.

Important boundary behavior:

- There is no inner check that stops record writes at the output count.
- A group may emit more records than the remaining count.
- Zero or negative spans skip the source-position loop, but still alter the consumed count and advance the group index.
- Zero or negative repetition counts emit no records for that source position.
- Invalid or non-progressing metadata is not rejected. It can lead to later out-of-bounds accesses, arithmetic problems, or failure to terminate.

### 3. Timing-field generation

After the first phase finishes, the function unconditionally writes zero to output record zero at offset `0x14`. This occurs even when the captured output count is zero or negative.

It then calls F-870c4fcf7295 with:

1. The 32-bit metadata field at offset `0x5C`.
2. The value 100.

The 32-bit result is retained as the second argument for subsequent conversion calls. This contract does not assume that the dependency implements multiplication, division, scaling, or any particular rounding behavior.

Timing processing begins with:

- A cumulative increment of zero.
- A target index of one.

For each timing run:

1. Read and retain that run's increment.
2. For each repetition allowed by its repetition count:
   - Add the increment to the cumulative increment.
   - If the target index minus one is less than the captured output count, convert the individual increment and write the result to field `0x18` of record “target index minus one.”
   - If the target index is less than the captured output count, convert the cumulative increment, advance the target index, and write the result to field `0x14` of the record selected before that advance.

When both conditions hold, the individual-increment conversion and write occur before the cumulative-increment conversion and write. The target index advances after the second conversion returns but before its result is stored.

Timing input is processed beyond the point at which all cumulative fields have been assigned. For a positive output count, the target index stops advancing when it reaches that count. Subsequent timing repetitions continue to:

- Increase the cumulative increment.
- Convert the individual increment.
- Overwrite field `0x18` of the last output record.

They do not write additional cumulative fields.

For zero or negative output counts, ordinary non-overflowing comparisons suppress these per-repetition writes and conversions. The unconditional record-zero initialization and initial conversion call still occur.

After all timing runs complete, the function returns 0.

## Side effects

### Direct memory effects

The function directly writes selected fields of the output array. It does not explicitly write the input object or metadata descriptors.

Output initialization is partial:

- Records not reached by generation retain their previous value and position fields.
- Timing fields without a qualifying timing repetition retain previous contents, except for record zero's unconditional `0x14` initialization.
- Other output bytes remain untouched by this function's explicit stores.

There is no rollback. If execution stops during a dependency call or invalid access, earlier stores may already be visible.

### Reads and dependency-visible ordering

The function mixes captured values with repeated reads:

- The selector is captured before metadata lookup and preparation.
- The output count, common value, and total source-position count are captured after output-base acquisition.
- Group counts, grouping pointers, repetition counts, source-position pointers, and per-record value pointers are read during generation.
- Timing-run counts and repetition conditions are read during timing processing rather than all being snapshotted at entry.
- Each run's increment is captured before its repetition loop.

Unknown callees are not assumed to preserve shared memory or globals. In particular, conversion calls can precede later metadata reads. If a dependency changes reachable metadata, later reads can observe those changes while captured values remain unchanged.

### Ownership

No explicit allocation or release operation is visible in this function. Output acquisition and preparation may have ownership effects, but those effects are unknown here.

The function does not establish that the caller gains ownership of the output base, that metadata is borrowed, or that the callback frees anything.

### Generation can exceed the count

Given output count 1 and a first group that emits two records:

- Both records are written before the outer count condition is checked again.
- The count is not a safe bound on actual writes.

Acceptance requires storage for the actual emissions, not merely the declared count.

### Timing saturation

Given output count 2 and three timing repetitions with increments 5, 7, and 9:

- Record zero's `0x14` field is initialized to zero.
- The first repetition writes the converted value of 5 to record zero's `0x18`.
- It also writes the converted cumulative value 5 to record one's `0x14`.
- The second repetition writes the converted value of 7 to record one's `0x18`.
- The third overwrites that same field with the converted value of 9.
- No cumulative field is written for the second or third repetition.

All conversions use the parameter returned by the initial conversion call.

### Zero output count

With output count zero and otherwise valid storage and metadata:

- The first generation phase is skipped.
- Record zero's `0x14` is still written with zero.
- The initial conversion call still occurs.
- Timing repetitions do not produce conditional output writes.
- Normal completion returns 0.
