# F-33030d813f2f

## Purpose

F-33030d813f2f conditionally copies two 32-bit values from fixed offsets within a caller-designated object into independently optional output locations.

The established behavior is a pair of ordered, conditional transfers—not necessarily a simultaneous snapshot. The first output write, when performed, precedes the second source read. Aliasing can therefore change the value delivered to the second output.

A zero object locator produces a fixed failure result without accessing either output. A nonzero object locator produces a success result if the requested memory operations complete. No object-type, extent, alignment, or access-permission validation is visible.

Interpreting the transferred values as a particular pair of properties is **inferred intent**, not established behavior. Their meanings are unknown.

## Interface

The function has three inputs and returns one 32-bit result:

| Input or result | Contract |
|---|---|
| Object locator | An integer-valued locator used as the base address for source accesses. Zero selects the failure path. |
| First output location | An optional destination for one 32-bit value. A null location disables the first transfer. |
| Second output location | An optional destination for one 32-bit value. A null location disables the second transfer. |
| Return value | The 32-bit pattern `0x00000000` on the nonzero-object path, or `0xFFFFFF40` when the object locator is zero. |

The failure pattern corresponds to −192 when interpreted as a signed 32-bit two’s-complement integer. The established result is the bit pattern; its interpretation as a named error code is not supplied.

## Behavior

### Zero object locator

If the object locator is zero:

- The function returns `0xFFFFFF40`.
- It does not read either object field.
- It does not write either output.
- Non-null output arguments do not change this result.

In particular, the function does not clear or initialize outputs on this path. Existing output contents remain unchanged by this function.

### Nonzero object locator

If the object locator is nonzero, the function processes the outputs in this order:

1. If the first output is non-null, it reads the 32-bit value at object offset `0x18` and writes that value to the first output.
2. After that transfer, or immediately if it was disabled, it considers the second output. If the second output is non-null, it reads the 32-bit value at object offset `0x1C` and writes that value to the second output.
3. After all requested transfers complete, it returns `0x00000000`.

Each output is independently optional. A null first output does not prevent the second transfer. A null second output does not prevent the first transfer.

With a nonzero object locator and both outputs null, the function performs no object-field reads and no output writes, then returns success. Consequently, success alone does not establish that the object points to accessible storage.

There is no visible error return for an inaccessible source, an unwritable destination, insufficient object extent, or misalignment. Such conditions violate the normal-completion preconditions; their consequences depend on the execution environment.

### Ordering and aliasing

The first transfer completes before the second source value is read. The function does not first capture both source values.

This order matters when destinations alias each other or overlap source storage:

- If both outputs designate the same ordinary destination, and that destination does not overlap either source field, the second transfer overwrites the first transfer’s result.
- If the first output designates the field at offset `0x1C`, the first transfer changes the value subsequently read for the second transfer.
- If the second output overlaps the first source field, that write occurs only after the first source read and any first output write have completed.

These conclusions assume valid ordinary memory accesses. Partially overlapping regions, device memory, or concurrently modified storage require additional platform rules that are not supplied.

No atomic pairwise update, rollback, or synchronization is established. If execution cannot complete a later access, the earlier output write may already have occurred.

## Side effects

The function ordinarily leaves source storage unchanged when outputs are disjoint from it. If an output aliases source storage, that storage can be modified as described above.
