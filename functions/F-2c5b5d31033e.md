# F-2c5b5d31033e

## Purpose

The supplied static representation describes a straight-line sequence of indirect calls, byte stores, 32-bit stores, and a small number of memory reads. It does not establish a higher-level purpose such as initialization, serialization, allocation, or device control.

The observable contract is therefore an ordered sequence of effects, conditional on the representation accurately describing executable instructions and on each intervening call returning normally. The representation explicitly reports invalid instruction data and terminates at an invalid-instruction boundary. It does not establish a normal return path.

This document separates:

- **Established static evidence:** operations explicitly present in the supplied representation.
- **Inferred intent:** possible interpretations not strong enough to impose requirements.
- **Unknowns — documented_only:** behavior that cannot be resolved from the supplied material.

No runtime tests have been performed.

These identifiers distinguish occurrences for specification purposes. They do not prove that different occurrences target different functions.

A “no-explicit-argument call” means that the supplied representation shows no arguments. It does not prove that the actual machine interface has no register, stack, or global inputs.

Except where a stage explicitly interleaves effects, listed calls occur consecutively in the stated order.

## Side effects

### Memory and aliasing

The body directly performs byte and 32-bit accesses. It includes writes to absolute addresses `0x0D` and `0x11`, and writes selected by unsigned byte values plus `0x11`. Such selected destinations range from `0x11` through `0x110`.

No address validation, null rejection, bounds check, alignment check, or access-failure handling is shown.

Derived regions may overlap one another or fixed addresses. Consequently:

- Earlier writes may affect later reads.
- Different symbolic destinations may designate the same storage.
- A later write can replace an earlier value.
- Intervening calls prevent assuming that a written value remains unchanged.

The contract does not make these operations transactional. A fault or nonreturning dependency can leave a partial sequence of effects.

## Acceptance examples

These are conditional static acceptance examples, not observed runtime results.

1. **Initial argument preservation and replacement.** If the first two stores are valid, the second argument is written in full at doubled entry plus `0x34`. If execution reaches stage 2, a high-word result is later written to that same address. Acceptance must preserve both writes and their order, rather than collapse them into one final assignment.

2. **Byte truncation.** With incoming register 4 equal to 130, doubled entry is 260 and its low byte is 4. The first byte store therefore writes 4. This example requires no signed overflow.

3. **Unsigned-byte selector.** If a stage-8 read yields `0xFF`, the zero store targets `0x110`, and selector base is 510. The selector is not sign-extended to −1.

4. **Fresh reads across calls.** If the two reads from loaded base plus 1 in stage 15 yield 2 and 9, the destinations are `0x13` and `0x1A`. Reusing the first selector would violate the represented access sequence.

5. **Fixed-address overwrite.** If stage 9 stores saved selector at `0x0D` and execution reaches stage 10, the body later stores `0xC0` there. Acceptance must retain the intermediate store even when only the later value survives.

6. **Reduced-address boundary.** A scaling result whose masked low 27 bits are all ones produces reduced address `0x3FF`. The stage-7 fourth-argument byte store therefore targets `0x406`.

7. **Nonreturning dependency.** If **F-D01-01** does not return, no later body operation is required to occur. The two preceding stores have already been attempted.

8. **Terminal behavior.** An execution reaching the final represented boundary is not evidence of an ordinary void return. Acceptance must leave the actual invalid-instruction response unresolved unless independently established.
