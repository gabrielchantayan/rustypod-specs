# F-81963d81bb92

## Purpose

F-81963d81bb92 conditionally performs an item-creation and registration sequence, or invokes alternate handling for an already-marked category.

Processing requires both an input-object discriminator equal to 2 and a nonzero lookup result. For category selectors 0, 1, and 2, a corresponding context byte selects between the two paths:

- Zero selects the creation sequence.
- Any nonzero value selects alternate handling.

Every other selector selects creation without a category-marker read or write.

“Creation,” “item,” and “registration” describe inferred roles. The established contract consists of the conditional memory accesses, dependency calls, argument values, and ordering below. In particular, the call receiving 36 does **not** establish allocation or a byte-sized storage request.

### Preconditions

- Successful lookup with a recognized selector requires the corresponding context-marker byte to be readable.

The context is not checked for zero. It need not be directly accessed on discriminator failure or zero lookup, but dependencies may impose independent requirements.

No bounds, alignment, address-overflow, or mapped-memory checks are visible. Valid-address preconditions are required; the contract does not assign safe behavior to invalid or overflowing address calculations.

## Behavior

### Eligibility and category selection

The local 32-bit temporary is initially assigned the fourth argument. Its initial contents do not control a branch or supply a dependency argument.

The input-object address is then checked against zero. If zero, F-a817d8d58c10 is called without arguments. No ordinary continuation after that call is established.

For a nonzero address, the discriminator byte at input-object offset `0x11E` is read once. A value other than 2 causes return without lookup, marker access, or creation calls. Byte signedness does not change equality with 2.

A discriminator of 2 causes F-ffe0d92c57b7 to be called with the input-object address. Its 32-bit result is retained as the lookup value. Zero causes return. A nonzero value permits further processing.

The discriminator is not reread after lookup, so a change to it during lookup does not cause a new eligibility decision.

For selectors 0, 1, and 2, exactly the corresponding marker byte is then read. This read occurs after lookup returns:

- Selector 0 uses offset `0x9C`.
- Selector 1 uses offset `0x9D`.
- Selector 2 uses offset `0x9E`.

Zero selects creation; any nonzero byte selects alternate handling. A lookup dependency that changes the marker can therefore affect the selected path.

For any other selector, creation is selected without reading any category marker.

### Alternate handling

A recognized selector whose marker is nonzero causes F-befffbb40ab7 to receive, in order:

1. Context address.
2. Input-object address.

The function returns after this dependency returns. Neither the selector nor the lookup value is passed to it.

This path performs no direct marker write and does not enter the creation sequence. It does not establish that the alternate dependency preserves markers, other memory, or global state.

Neither operand is established as immutable, entry-captured, or preserved across dependency calls. Each call receives the value evaluated for its own argument, rather than an established live reference to that global/data location.

The integer 36 has no established unit. F-8157a180d901 may be allocation-related, but neither a storage request nor a 36-byte allocation follows from the caller alone. The established behavior is the argument value and forwarding of the returned auxiliary value.

The final marker write uses the original selector. It does not reread the marker or depend on its current contents. Thus, a dependency may change the marker during creation, but normal completion still writes 1 for a recognized selector. Unrecognized selectors receive no direct marker write.

### Failure and partial completion

Only the lookup value is tested for zero.

The handle, descriptor, item, and auxiliary values are forwarded without visible validity checks. In particular, an auxiliary value of zero is passed unchanged to F-3a954974c1bb, and an item value of zero is still used by subsequent calls and placed in the registration slot.

No local failure branch, release sequence, or rollback is shown. If a dependency does not return normally, later operations are not reached. Earlier effects are not visibly undone.
