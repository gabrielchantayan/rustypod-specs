## Behavior

- the incoming zero-condition state is true; or
- the incoming negative-condition value differs from the incoming overflow-condition value.

The **load condition** is true when the incoming negative-condition value equals the incoming overflow-condition value.

These definitions describe the visible representation. They are not a guarantee about how physical condition flags evolve during execution.

1. **First conditional group**

   - Each uses selector **0x1DDF1D**.
   - If the interrupt condition is false, one coprocessor move operation occurs instead.

2. **Conditional load**

   - Its address-like operand is the incoming address base plus **0x25C**.
   - If the load condition is false, this operation is absent.

3. **Second conditional interrupt group**
   - If the interrupt condition is true, four software-interrupt operations occur in succession.
   - Each uses selector **0x1CDF1C**.
   - If the interrupt condition is false, this group is absent.

4. **Unresolved terminal boundary**
   - The representation ends at an operation marking bad instruction data and truncated control flow.
   - No ordinary return, result production, or subsequent instruction sequence is established.

Within each interrupt group, the repeated operations are separate ordered occurrences. They must not be described as one interrupt with a repetition count unless an external observer is explicitly abstracting away the individual occurrences.

### First conditional group

When the interrupt condition is true, the seven occurrences of selector **0x1DDF1D** precede any conditional load and any occurrence of selector **0x1CDF1C**.

When the interrupt condition is false, the alternative coprocessor move has the visible operand sequence:

- hexadecimal **0xF**;
- decimal **5**;
- decimal **0**;

### Conditional load

When the negative-condition and overflow-condition values are equal, the load operation follows the entire first conditional group.

Its visible operands are:

- decimal **5**;
- the first incoming coprocessor-related value;
- the address-like value obtained by adding **0x25C** to the incoming base.

The operation is characterized as a long coprocessor load. That characterization does not establish the number of bytes transferred, the number of memory accesses, byte order, destination register span, or address writeback behavior.

The visible representation supplies no explicit base update. This is not sufficient evidence that the underlying operation leaves the corresponding physical register or other machine state unchanged.

### Second conditional interrupt group

When the interrupt condition is true, four occurrences of selector **0x1CDF1C** follow the conditional-load decision.

The same incoming condition values appear in both interrupt-condition checks. Thus, at the level of the supplied representation, both interrupt groups are selected together. It would be unsupported to independently choose the two groups based on newly sampled condition values.

Conversely, this representation does not prove that an actual interrupt handler preserves processor condition flags or that the underlying machine instructions test immutable snapshots.

### Continuation and failure

A software interrupt may transfer control to a handler, fault, terminate execution, or return to a continuation. A coprocessor operation may complete, trap, or fail. Those outcomes are not specified here. For example, selecting the seven-interrupt branch does not establish that all seven interrupts are actually delivered if the first never returns.

The terminal marker does not establish a particular processor exception, operating-system signal, diagnostic message, or exit status. It establishes only that the supplied representation provides no resolved continuation.
