# F-b56e4e513a0a

## Purpose

F-b56e4e513a0a locates a logical starting position in an ordered extent table, partitions a requested count across subsequent entries, and dispatches each selected portion to one of two dependencies. After a dependency returns zero, the function updates its remaining-count state, advances an address-like value by 512 per selected unit, and adds that portion to a caller-provided counter.

Extent traversal, dispatch selection, accounting, and status propagation are established by static evidence. Storage transfer is inferred intent; the actual operation, transfer direction, and meaning of an extent unit are not established.

The operation is not transactional. This function does not undo earlier accounting when a later dependency fails or the table is exhausted. This does not guarantee preservation of earlier counter contents: dependencies may modify the counter or other memory, including before returning an error.

### Results

- **Zero:** successful-call accounting reduces remaining units to zero, or a processing-phase count check finds the index outside the current table count while no units remain.
- **Five:** initial selection finds no containing entry, or processing reaches the current extent count while units remain.
- **Any nonzero dependency result:** returned unchanged.

Five is not an exclusive identifier for range failure; a dependency may independently return five.

A zero result describes this function’s control flow and accounting. It does not independently establish an external transfer or guarantee that the counter equals the original request if a dependency or overlapping storage changes it.

## Behavior

### Initial write and selection

The first externally visible memory access established by the body is a zero store to the completed counter. This precedes the context and table reads used for selection.

Selection starts at entry index zero. At each entry:

- The current unsigned extent count is read and compared with the index.
- If the index is not below that count, the function returns five.
- Otherwise, the table address and entry length are read.
- The entry is selected only if the remaining logical offset is strictly below its length.
- Otherwise, that length is subtracted from the logical offset and the index advances.

Selection locates the start; it does not validate the entire requested range.

For stable metadata:

- A start exactly at an extent’s end proceeds to a later extent.
- Zero-length extents are skipped without dispatch during selection.
- An empty table rejects every start.
- A start at or beyond the aggregate extent length is rejected.
- A zero-unit request undergoes the same selection.

If selection fails, no dependency is invoked. The function has nevertheless already zeroed the counter.

### Processing and portion selection

After selecting an entry, the function checks the current extent count again. If the selected index is now outside that count, it returns five when units remain and zero otherwise.

When the index passes the check, the function rereads the table address and entry length. Available units are the unsigned 32-bit difference between this length and the within-entry offset. The portion is the smaller unsigned value of available units and remaining requested units.

The selected entry’s length is therefore read separately during selection and processing. No immutable metadata snapshot is established. If its length decreases below the selected offset between these reads, available-unit subtraction wraps in unsigned arithmetic rather than reporting an invalid offset.

### Dispatch

For selector zero, F-3028a6a8124a receives these five arguments:

1. The 32-bit context field at offset `0x04`.
2. The entry’s base value plus the current within-entry offset.
3. The selected portion’s unit count.
4. The current transfer address.
5. The auxiliary value.

The table address is read again to obtain the base. Consequently, the selected length and dispatch base need not come from the same table instance if metadata changes.

Portion selection precedes dispatch. The supplied representation does not establish the exact relative order of the separate context-field, table-address, and base reads used to assemble the call arguments.

For any nonzero selector, F-a572fbc92576 is invoked instead. No explicit arguments are visible for that invocation. The five arguments above must not be presumed to reach it through an unspecified calling convention.

Both dependency results enter the same status decision.

### Zero dependency result

After a zero dependency result, the function performs these updates in order:

1. Resets the within-entry offset to zero.
2. Subtracts the selected portion from remaining units.
3. Advances the local transfer address by 512 times the portion.
4. Reads the current completed counter, adds the portion, and stores the result.
5. Returns zero if remaining units are zero.
6. Otherwise advances the index and resumes processing at the next entry.

The counter update is a read-modify-write, not a store from an independent cumulative total. A dependency’s counter modification before returning zero becomes the input to this addition.

Completion depends on remaining units, not counter contents. A changed counter does not itself change the locally tracked remaining request.

### Nonzero dependency result

A nonzero dependency result is returned immediately. The function does not perform that call’s successful-result updates: it does not subtract the portion, advance the transfer address, or add the portion to the counter.

It also performs no restoration:

- Earlier accounting additions are not rolled back.
- Earlier counter contents are not guaranteed to survive dependency effects.
- Counter changes made by the failing dependency are not undone.
- Failure without a counter addition does not establish absence of external work or partial effects.

There is no retry or compensating call.

### Zero requests and zero portions

A zero request is not an unconditional no-op.

If its start cannot be placed inside an extent, the function returns five without dispatch. If the start is selected and the subsequent processing count check permits that index, the portion is zero and the chosen dependency is called.

A zero dependency result then causes a counter read-modify-write adding zero before successful return. This preserves the value read at that point; it does not restore the initial zero if the dependency changed the counter. A nonzero dependency result is propagated without the addition.

A zero-length entry reached after processing begins likewise produces a zero-unit dispatch if its index passes the count check. Following success, remaining units and the transfer address are unchanged. If units remain, the index advances. Thus initial selection skips empty entries, whereas processing can dispatch them.

### Arithmetic widths and traversal bounds

Logical offsets, remaining units, portions, traversal lengths, and index comparisons are unsigned 32-bit quantities.

Unchecked unsigned 32-bit calculations include:

- Index multiplication by the eight-byte entry stride.
- Available-unit subtraction.
- Entry base plus the unsigned within-entry offset.
- Portion multiplication by 512 and addition to the transfer-address value.
- Addition of a portion to the counter value.

The unsigned transfer-address calculation retains the low 32 bits before storage back into its represented type. It is not an established checked, wider address calculation. The base-value addition can similarly wrap.

The counter is represented as a signed 32-bit integer, but addition with the unsigned portion uses unsigned arithmetic. There is no saturation or range check. Consumers cannot assume the resulting stored value is a nonnegative signed count; out-of-range unsigned-to-signed conversion remains representation-dependent.

**The entry index does not wrap through the shown control flow.** Every increment follows a check establishing that the index is below the current unsigned 32-bit extent count. Since that count cannot exceed 4,294,967,295, an index eligible for increment is at most 4,294,967,294. Incrementing can therefore produce at most 4,294,967,295, not zero.

At that maximum index, the next count check must reject it, regardless of subsequent count changes. Changing metadata cannot make any unsigned 32-bit count exceed that index. The transition from selection to processing retains the same index and introduces no backward movement.

Consequently, traversal is finite even with arbitrarily changing metadata, provided accesses complete validly and invoked dependencies return. There are at most 4,294,967,295 index increments across both phases. Zero lengths and zero portions do not defeat this bound because continued traversal advances the index.

This bounded control flow is distinct from guaranteed normal completion. An invalid access may prevent completion, and a dependency may never return. Some address expressions also contain signed operands; the evidence does not establish safe wrapping semantics for every address calculation or safe access after address arithmetic overflow.

## Side effects

Directly established effects are:

- Initial counter zeroing.
- Later counter read-modify-write operations after zero dependency results.
- Reads of the specified context and extent fields.
- Calls to the selected dependency.

The body shows no direct allocation, release, context-field assignment, extent-table assignment, or transfer-memory dereference. Counter writes can nevertheless affect metadata when storage overlaps.

These direct-operation limits do not constrain dependency effects. Neither dependency is established to preserve the counter, context, table, transfer memory, or globals, whether it returns zero or nonzero.

The count and table address are reread rather than snapshotted. Dependency-induced metadata changes can affect later traversal. The function shows no locking, synchronization, rollback, or restoration.

No direct ownership transfer is established. Passing an address-like value does not determine whether a dependency borrows, retains, modifies, or releases referenced storage.
