# F-ae87df3c1506

## Purpose

F-ae87df3c1506 selects between an out-of-range reporting operation and an indexed extraction-and-forwarding operation.

The selection depends first on the sign bit of a 32-bit index and, only for indices whose sign bit is clear, on a value returned by an indirect object-associated call. On the extraction path, the function supplies a temporary record to one dependency and then forwards the record’s payload address and leading 16-bit field to another dependency.

The wrapper establishes the call order and temporary storage layout. It does not establish the meaning of the extracted bytes, the format of the out-of-range report, or the ownership behavior of its dependencies.

## Interface

The function accepts three arguments:

| Argument | Established representation | Role |
|---|---|---|
| Object reference | Address interpreted through 32-bit integer-sized fields in the supplied representation | Supplies an indirect-call table address and a separate field used for extraction. |
| Index | 32-bit unsigned value | Tested through a signed 32-bit interpretation, then compared as unsigned against the indirect call’s result. |
| Output context | Opaque 32-bit value | Passed unchanged to either the out-of-range dependency or the payload-forwarding dependency. |

There is no explicit return value. Normal completion returns control to the caller without a status result. Exceptions, nonlocal exits, faults, or termination inside dependencies are not characterized by the supplied evidence.

### Object layout requirements

For a nonnegative index, the object reference must permit the following accesses when they occur:

- A 32-bit field at object byte offset 0, used as an indirect-call table address.
- A callable entry obtained from byte offset `0x124` within that table.
- On the extraction path only, a 32-bit field at object byte offset `0x40`.

The callable entry is invoked with the object reference as its explicit argument. Its result is treated as an unsigned 32-bit value for the range comparison.

These are access requirements, not proof of a complete object type, allocation size, or table schema. The supplied evidence does not identify a constructor, ownership rule, or lifetime protocol for the object.

### Temporary record layout

The extraction path uses adjacent local storage with this layout:

| Relative byte offset | Size | Use |
|---|---:|---|
| 0 | 2 bytes | Leading field subsequently supplied to F-b287fa5e8a41. |
| 2 | 510 bytes | Payload region whose address is supplied to F-b287fa5e8a41. |

F-438984c93ed5 receives the address of the leading field. F-b287fa5e8a41 receives the address two bytes later.

The wrapper performs no explicit initialization of either region before extraction. The dependency contract must therefore supply any initialization needed for defined subsequent use.

## Behavior

### Index screening

The first decision interprets the index as a signed 32-bit integer.

Indices from `0x80000000` through `0xffffffff` take the out-of-range path immediately. For those inputs, the wrapper does not read the object’s table address and does not invoke the indirect callable.

Indices from `0x00000000` through `0x7fffffff` proceed to the object-associated indirect call.

This check is not a conversion to an absolute value, a clamp, or a signed comparison against the eventual bound. The original 32-bit index is retained for the later unsigned comparison and for extraction.

### Bound acquisition and comparison

For an index whose sign bit is clear, the wrapper:

1. Reads the table address from the object’s first 32-bit field.
2. Obtains the callable entry at table byte offset `0x124`.
3. Invokes that callable with the object reference.
4. Treats the returned value as unsigned 32-bit.
5. Takes the out-of-range path if that value is less than or equal to the index.

The extraction path is selected only when the returned value is strictly greater than the index.

A returned value of zero rejects every index that reaches this comparison. Equality also rejects: an index equal to the returned value is not accepted.

The range decision does not establish that the object or its associated data remains unchanged afterward. In particular, the indirect callable may modify object fields or other state. The wrapper does not preserve a previously read copy of the extraction field across that call.

### Out-of-range path

Both rejection conditions use the same reporting operation:

- An index with its sign bit set.
- A sign-bit-clear index greater than or equal to the indirect result.

The wrapper invokes F-438680ffebfe with:

- The original output-context value.
- The address of one fixed data object embedded with the program.

The fixed object’s bytes, encoding, extent, and interpretation are unavailable. It must not be specified as a particular message, empty result, exception descriptor, or sentinel without additional evidence.

On this path, the wrapper does not invoke F-438984c93ed5 or F-b287fa5e8a41. If F-438680ffebfe returns normally, the wrapper then returns normally. The wrapper itself does not implement a throw or termination operation.

### Extraction and forwarding path

When the index is strictly below the unsigned indirect result, the wrapper reads the object’s 32-bit field at byte offset `0x40`. This read occurs after the indirect callable has returned.

It then invokes F-438984c93ed5 with:

- The value read from object byte offset `0x40`.
- The original 32-bit index.
- The address of the temporary record’s leading 16-bit field.

If that call returns, the wrapper reads the leading 16-bit field and invokes F-b287fa5e8a41 with:

- The original output-context value.
- The address of the 510-byte payload region.
- The value read from the leading 16-bit field.

The payload pointer therefore differs from the record pointer supplied to F-438984c93ed5 by exactly two bytes.

The wrapper does not inspect a return status from F-438984c93ed5. It also performs no explicit validation that the leading field describes data within the payload region. In particular, no visible comparison limits that field to 510.

The leading field plausibly represents a payload length, but that meaning is inferred rather than established by the wrapper. Its stored width is 16 bits. The supplied evidence does not establish its semantic signedness or the receiving dependency’s formal parameter type.

After F-b287fa5e8a41 returns normally, the wrapper returns without an explicit cleanup call.

## Side effects

### Direct effects

The wrapper directly performs object and dispatch-table reads, prepares arguments, and uses temporary local storage. No direct write to the caller’s object or output context is visible.

The wrapper does not explicitly allocate or free heap memory. That observation does not extend to any dependency.

### Dependency-mediated effects

All persistent output changes, error reporting, extraction writes, allocation, release, and global-state changes are dependency-defined.

No dependency may be assumed to:

- Preserve globals.
- Leave the object unchanged.
- Copy rather than retain a pointer.
- Acquire or release ownership.
- Return normally.
- Restrict its writes to the temporary record.

The wrapper passes its local record to F-438984c93ed5 and its local payload address to F-b287fa5e8a41. Those addresses refer to temporary storage whose wrapper-provided lifetime ends when the invocation ends. The visible code supplies no lifetime extension for retained pointers.

### Observable ordering constraints

On an accepted index, the order is:

1. Object-associated indirect call.
2. Read of the extraction field at object byte offset `0x40`.
3. F-438984c93ed5.
4. Read of the temporary leading field.
5. F-b287fa5e8a41.

This ordering matters if a dependency changes the object or temporary record.

On a rejected nonnegative index, the indirect call precedes F-438680ffebfe. On a sign-bit-set index, F-438680ffebfe occurs without that indirect call.

No extraction call, payload-forwarding call, or retry follows an out-of-range report.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Normal return from each reached dependency is assumed unless stated otherwise.

### Sign-bit-set index

Given index `0xffffffff`:

- The signed screening condition rejects it.
- No object-table read or indirect call is required by this wrapper path.
- F-438680ffebfe receives the original output context and fixed-data address.
- Neither extraction nor payload forwarding occurs.

This does not establish that an arbitrary output context is safe for the reporting dependency.

### Empty bound

Given index zero and an indirect result of zero:

- The indirect callable runs.
- Equality causes rejection.
- F-438680ffebfe runs.
- The object field at byte offset `0x40` is not read by the wrapper.

### Last accepted index below a bound

Given index four and an indirect result of five:

- Extraction is selected.
- The field at object byte offset `0x40` is read after the indirect call.
- F-438984c93ed5 receives index four.
- If extraction initializes the leading field to seven and returns, F-b287fa5e8a41 receives that field value and the payload-region address.

This case does not establish that seven is a byte count.

### Index equal to the bound

Given index five and an indirect result of five, the wrapper reports out of range. It does not extract entry five.

### Unsigned comparison boundary

Given index `0x7fffffff` and indirect result `0x80000000`, the range comparison accepts the index. The returned value is not treated as negative for that comparison.

By contrast, index `0x80000000` is rejected before any indirect call, regardless of what result that call might otherwise produce.

### Object mutation during the indirect call

If the indirect callable changes the field at object byte offset `0x40`, returns a bound greater than the index, and leaves that field readable, extraction receives the changed field value.

### Leading field larger than the payload region

If extraction returns with leading field 511, the wrapper performs no visible 510-byte-capacity check before forwarding. Whether that value causes an overread or has another meaning depends on F-b287fa5e8a41 and is not established here.
