### 2. Three dependency-reference evaluations and the first termination boundary

2. A separate evaluation is interpreted as signed 32 bits and shifted right by 32. Its result supplies an address base.

The second evaluation’s shift makes the resulting base unresolved under ordinary 32-bit rules. Under an arithmetic-right-shift interpretation, the third evaluation produces a 16-bit value of either `0x0000` or `0xffff`.

The function next writes that derived 16-bit value at the unresolved base plus four.

Only afterward does it interpret the **first** saved dependency value as signed 32 bits and test whether it is negative. If negative, execution reaches the first invalid-instruction termination marker. No later operations are represented on that path, and preceding writes are not undone.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume the relevant preceding accesses complete and any disputed arithmetic has a specified interpretation.

1. **Element-write order.** The third argument receives `0xffff` at byte offsets four, six, and two, in that order. Offset zero is not directly targeted by those three writes.

2. **16-bit address formation.** If offset zero contains `0x1234` when read, the masked 32-bit write targets `0x00001234`, regardless of the third argument’s base address.

3. **Independent reference evaluations.** If the first F-e47d7b2e9c88 evaluation has its sign bit clear but the third has its sign bit set, arithmetic-right-shift semantics yield a derived 16-bit value of `0xffff` while permitting the nonnegative continuation. One cached reference value would not model these premises.

4. **Negative branch.** If the first saved dependency value is negative as signed 32 bits, the write at the unresolved base plus four precedes termination. The later write at base plus `0x12` is not represented on that path.

5. **Bit-dependent addresses.** A clear bit two selects `0x58`, with subsequent low destinations `0x5c` and `0x170`. A set bit two selects `0x5c`, with destinations `0x60` and `0x180`.

6. **Signed read snapshot.** A saved 16-bit read of `0xffff` produces `0xffffffff` after sign extension and arithmetic right shift by 16. A saved read of `0x7fff` produces zero.

7. **Distinct late dependency values.** If the first F-8afdaab91693 evaluation is `0x2000` and the second is `0x3000`, the multiply-by-eight clearing destination is `0x10000`, while the left-shift-by-two stored value is `0xc000`.

8. **Publication reread.** If all publication reads yield the same value, the following offset-four write is four bytes after the first destination. If the intervening store changes what publication storage yields, the later destination follows the new read instead.

9. **Current reset content.** If reset-upper-half storage still contains `0x1234` at final construction, the constructed reset value is `0x1234ea70`. If intervening writes changed it to `0xabcd`, the result is `0xabcdea70`.

10. **No successful-exit promise.** Even if every access completes on the nonnegative path, the representation ends at the second termination marker, not a normal return.
