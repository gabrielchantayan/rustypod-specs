# F-817e3c69adf5

## Purpose

F-817e3c69adf5 obtains a 32-bit value from a dependency and selects between a zero-result path and a nonzero-result path.

On the zero-result path, it writes zero to a caller-supplied object, calls F-f2b8332efb8a with argument 3, and returns zero if that call completes normally. The supplied body does not establish whether this represents success, failure, notification, recovery, or another operation.

On the nonzero-result path, it prepares temporary data, derives a 32-bit threshold by adding 60 to a conversion result, stores the original acquired value in the object, and obtains another conversion result. An unsigned comparison selects either F-910df819391b or an indirect callable obtained through the object. The selected operation’s result is returned without visible interpretation.

The contract below describes statically established behavior. A time-related interpretation of the conversions and threshold is plausible but unconfirmed. No runtime tests have been performed.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume dependencies complete normally and preserve the validity of subsequent accesses.

### Zero acquisition without semantic classification

Given an initial result of zero, the routine writes zero at object offset 196, calls F-f2b8332efb8a with 3, and then returns zero. An ordinary nonzero return from that dependency does not change the routine’s return value.

This example does not classify the outcome as success or failure, or the call as a notification.

### Strictly below the threshold

Given a nonzero acquisition result, base value 1,000, and later conversion result 1,059:

- The threshold is 1,060.
- The original acquisition result is stored before the later conversion.
- F-910df819391b receives 1 and the local 4-byte area.
- Its 32-bit result is returned unchanged.
- No indirect dispatch occurs.

### Equality boundary

Given base value 1,000 and later result 1,060, the routine selects indirect dispatch. The selected entry receives the object pointer and 2. Equality does not select F-910df819391b.

### Unsigned upper range

Given base value zero and later result 4,294,967,295, the threshold is 60 and indirect dispatch is selected. Treating the later result as signed negative would produce the wrong branch.

### Wrapped threshold and zero boundary

Given base value 4,294,967,280, the threshold is 44. A later result of 43 selects F-910df819391b; 44 selects indirect dispatch.

Given base value 4,294,967,236, the threshold wraps to zero. No unsigned 32-bit later result is below zero, so indirect dispatch is selected for every normally returned later result.

### Direct write versus final contents

On the zero-result path, if F-f2b8332efb8a can reach and change the object field, the final field need not remain zero. Acceptance requires this routine’s zero write before the call, not preservation by the dependency.

Likewise, on the nonzero path, the direct write must use the original acquired value even when every conversion result differs from it.
