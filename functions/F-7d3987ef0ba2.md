# F-7d3987ef0ba2

## Purpose

F-7d3987ef0ba2 performs an ordered sequence of computed dependency calls, 32-bit memory writes, byte reads, and byte writes, followed by an unconditional repeating tail.

The supplied static representation does not establish an application-level purpose. Scaling, bit extraction, repeated calls, and small numerical write addresses do not establish serialization, initialization, device control, or any particular data format.

No normal return is represented. If every dependency returns and every memory access completes, execution reaches a loop with no represented exit.

This contract describes the visible static behavior, subject to warnings about invalid instruction data and removed control flow. It does not establish that the representation is a complete or accurate account of executable behavior.

### Width and arithmetic interpretation

Word writes store four bytes. Byte reads produce unsigned values from 0 through 255; byte writes retain the low eight bits of their supplied value. Right shifts of explicitly unsigned values are logical.

For conditional numerical examples, arithmetic uses 32-bit machine bit patterns, retaining the low 32 bits after multiplication, addition, or left shift. Write \(M(z)\) for reduction modulo \(2^{32}\), and define:

\[
W(z)=M(4z), \qquad S(z)=M(16z).
\]

This convention is not a resolution of the recovered signed expressions. Some products and shifts have signed operands in the representation. Actual overflow behavior, signed-shift semantics, pointer formation, alignment, and endianness remain documented-only unknowns.

In particular, the loop’s two result updates are separate 32-bit calculations from the same unscaled result: one shifts it left by two bits, and the other shifts it left by 26 bits.

## Behavior

### Dependency notation and ordering

Every unresolved dependency is designated **F-00000000**, qualified by its occurrence in the sequence. This is an opaque unresolved-identity marker, not an assertion that all occurrences invoke the same function.

A **four-call run** means four consecutive F-00000000 calls with no explicit arguments in the representation. Unless stated otherwise, the primary result of the fourth call supplies the subsequent value.

A **producer/consumer pair** means a call with no explicit arguments followed by a call receiving that producer’s primary result. Any additional consumer argument is stated explicitly.

“No explicit arguments” does not establish an absence of implicit register inputs. Dependencies may have additional effects between the local events described below. No memory-preservation, global-preservation, or ownership contract is assumed for them.

### Entry and first word-write phase

The first local memory effect is a word write of \(X\) at address \(W(X)+20\).

The initial dependency target is derived from the incoming link-register context. Its four explicit arguments, in order, are:

1. \(W(X)\);
2. \(X\);
3. the original \(P\);
4. \(H\) shifted left by three bits.

Two producer/consumer pairs follow. The first consumer receives only its producer’s result. The second receives its producer’s result and \(H\gg8\).

A four-call run follows. Afterward, the function writes \(X\) again at \(W(X)+20\), then invokes a dependency with four times that run’s final result.

Another four-call run supplies \(A\). The function retains \(W(A)\), shifts the working third input right by seven bits, and writes \(W(A)\) at address \(S(A)+20\). It then invokes a dependency with \(W(A)\) and \(M(8H)\).

The repeated write of \(X\) is independently observable: intervening dependencies may observe or change the location.

- Only the corresponding producer’s result.
- The corresponding producer’s result followed by \(H\gg8\).

### Unconditional repeating tail

At each iteration, a dependency receives two explicit arguments: the current loop-carried value \(L\), followed by \(N\gg8\).

A four-call run then produces a primary result. The function freshly reads the byte at \(B_{\mathrm{read}}\), writes zero at that byte’s value plus 17, and calls a dependency with the run’s result shifted left by two bits.

A second four-call run supplies a primary result \(R\). Two distinct updates determine the next iteration:

- The next first explicit argument is \(L_{\mathrm{next}}=M(R\ll2)\).
- The next shift-state value is \(N_{\mathrm{next}}=M(R\ll26)\).

Both updates use the **unscaled \(R\)**. The 26-bit shift does not use \(L_{\mathrm{next}}\), and the next iteration does not pass \(R\) unchanged.

Initialization differs from recurrence: the first iteration receives the unscaled pre-loop result \(L_0\). Its second explicit argument is necessarily zero because \(N_0\le31\). Later iterations receive the scaled result from the preceding iteration and \(M(R\ll26)\gg8\); their second arguments need not be zero.

The byte-read source address remains based on the earlier \(V\). It is not recomputed from \(R\), \(L\), or \(N\).

No termination condition, iteration bound, or normal return is represented.

## Side effects

All explicit data reads are byte reads used to form subsequent byte-write addresses. Each read is a separate event. Earlier writes or intervening dependencies may change the value returned by a later read.

Adding 17 to an unsigned byte produces a numerical address from 17 through 272 inclusive. The context-derived byte-write address \((H\gg23)+28\) ranges from 28 through 539.

These ranges do not establish valid mappings. The offsets 20, 17, and 28 do not identify fields, enclosing structures, array bounds, or allocation extents.

### Aliasing, partial effects, and errors

A byte write may change a byte that is subsequently reread. Replacing later reads with cached values would therefore alter represented behavior in some memory states.

No local bounds checks, input rejection, explicit error return, rollback, or transactional boundary appear. If a dependency fails to return or an access faults, preceding completed effects have no represented undo operation. Actual fault and exception handling remain unknown.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. Numerical results use the 32-bit machine-arithmetic interpretation defined above.

1. **Entry write precedes the first call.**  
   With \(X=3\) and a valid destination, the first local effect writes the word 3 at address 32. The initial dependency executes afterward.

2. **The repeated entry write is preserved.**  
   If an intervening dependency changes that destination, the second explicit write restores \(X\) before the following scaled-result call. Removing the second write changes observable behavior.

3. **The third input is shifted fourteen bits overall.**  
   With \(P=\texttt{0x00004000}\), the later four-argument context call receives 1 as its fourth argument. The initial dependency receives the original \(P\).

4. **The index mask matters.**  
   If retained \(W(G)=\texttt{0x80000080}\), then \(I=1\), and the relevant byte source is address 2.

5. **Byte reads are fresh.**  
   If the byte at \(I+1\) first equals 5, the corresponding byte-derived write targets address 22. If a dependency changes that byte to 9 before the next read, the next such write targets address 26.

6. **Byte stores truncate.**  
   With \(U=\texttt{0x12345678}\), the first byte-derived write stores `0xe0`. The later extracted-byte write stores `0x23`, provided both accesses are reached.

7. **Loop initialization is unscaled.**  
   If the pre-loop call returns 3, the first loop-head dependency receives 3, not 12, as its first explicit argument. Its second explicit argument is zero for every possible \(N_0\).

8. **The recurrent loop arguments use separate shifts.**  
   If an iteration’s final four-call run returns \(R=\texttt{0x40000001}\), the next loop-carried argument is `0x00000004`. Independently, the next \(N\) is `0x04000000`, so the next loop-head call receives `0x00040000` as its second argument. Passing \(R\) unchanged or deriving \(N\) from the already scaled argument fails this condition.

9. **Successful iteration completion repeats.**  
   If all calls return and accesses complete, finishing an iteration leads to another iteration. No represented condition converts completion into a normal return.
