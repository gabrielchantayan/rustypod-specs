# F-8c02c3768008

## Purpose

The supplied static representation does not establish a higher-level purpose. In particular, it does not justify describing the operation as initialization, cleanup, allocation, device control, or ordinary application processing. It also marks instruction-decoding failures and ends without a recovered normal return.

This contract therefore describes the observable prefix supported by that representation. Its requirements are conditional on execution reaching each operation, the intervening calls returning, and the relevant memory accesses being valid. Behavior beyond the recovered prefix is **documented_only**.

3. F-U03, whose integer result is retained for a later call.

No explicit arguments are shown for these three calls. This does not establish that the callees have zero inputs or cannot observe machine state.

After F-U03 returns, the visible memory operations are:

- Read one unsigned byte from the address one byte beyond the hidden address-like input.
- Add decimal 17 to that byte’s numeric value to obtain a destination address.

The stored byte is obtained by logically shifting the hidden unsigned word right by 22 bits and retaining the low eight bits. For a 32-bit source word, this selects original bits 22 through 29; bits 30 and 31 are discarded by the byte conversion.

The destination is formed directly from the byte value. It is not a pointer-sized value loaded from memory, and it is not an offset from the address that supplied the byte. Its numeric range is decimal 17 through 272 inclusive. Whether that low address range is mapped or writable is unknown.

F-U04 is then called with one visible argument: the retained result of F-U03 shifted left by two bit positions. The representation does not settle overflow behavior for this signed-looking expression.

### First selector-dependent store and four-argument call

Next, the function:

- Reads one unsigned byte from that address.
- Adds decimal 17 to the byte’s numeric value.
- Stores a zero byte at the resulting destination.

This destination has the same decimal 17–272 range as the first store.

2. The selector shifted left by three bit positions again.

## Acceptance examples

These are conditional acceptance examples derived from static evidence, not executed tests. They assume valid accesses, returning dependencies, and no unspecified interference relevant to the example.

### First store selects only eight bits

If the hidden unsigned word is hexadecimal `0xFFC00000`, and the hidden-state byte read yields decimal 9, the first visible store writes decimal 255 to address 26.

This follows because the right shift produces a value whose low byte is 255, and the destination is 9 plus 17.

If the hidden word is instead hexadecimal `0xC0000000`, the stored byte is zero: its only set bits lie above the eight-bit window retained after the shift.

### Selector-derived addressing and arguments

For selector 3:

- Each selector-derived byte-read address is decimal 3073.
- The first two visible arguments to F-U09 are each decimal 24.
- Its third visible argument is decimal 3.

If F-U08 returns 5, its fourth visible argument is decimal 20. These values do not require overflow assumptions.

If the first read at address 3073 yields 7, the corresponding zero store targets address 24.

### Repeated reads can select different destinations

Suppose the first selector-derived read yields 7 and the later read yields 8 because an intervening dependency changes memory.

The two zero stores target addresses 24 and 25 respectively. An implementation that caches the first byte and uses it for both stores would not match the recovered behavior.

### Destination boundaries

A source byte of zero selects destination address 17. A source byte of 255 selects destination address 272. Neither case selects an address relative to the source-byte location.

### Interrupted execution

If F-U03 does not return, no subsequent direct byte store is established to occur.

If the first store succeeds but F-U04 does not return, the first store remains an observed effect; neither later zero store is established to occur. No rollback is visible.

The repeated zero stores may suggest clearing state. That is only inferred intent and supplies no additional acceptance requirement.
