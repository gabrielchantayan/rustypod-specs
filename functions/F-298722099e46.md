# F-298722099e46

## Purpose

F-298722099e46 conditionally invokes object callbacks, notifies a related object, and performs a gated state update on a primary object.

The established behavior is an ordered sequence of indirect calls, dependency calls, field reads, and two possible flag updates. A 32-bit mode value affects the initial callbacks and the value passed to one dependency. Later processing is enabled by bit `0x10` in either the primary object or a previously captured related object.

Names such as “primary object,” “related object,” and “flags” describe access relationships, not established application-level types. A lifecycle, visibility, activation, or notification purpose is plausible but not established.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Mode-dependent initial callbacks

For a nonzero mode, the function reads the primary flag word at offset `0x48` and tests bit `0x10`.

If that bit is set:

1. The primary dispatch-table entry at offset `0x120` is invoked with the primary object as its explicit argument.
2. After that call returns, the primary dispatch-table entry at offset `0x118` is invoked with the primary object as its explicit argument.

The second dispatch is resolved after the first call. The function does not establish that both calls use the same dispatch-table pointer or that the first callback preserves object state.

If the mode is nonzero and bit `0x10` is clear, both calls are skipped.

For mode zero, this initial flag-gated pair is skipped without using the initial flag test.

### 2. Zero-mode query and follow-on calls

Only for mode zero, F-a1a48bd3fbde is called with the primary object.

If its 32-bit result is nonzero:

1. The primary dispatch-table entry at offset `0x1C` is invoked with the primary object.
2. F-20460d1f31d3 is called with no explicit arguments shown.

If the query returns zero, those two calls are skipped.

There is no visible interpretation of the query result beyond zero versus nonzero. No conclusion is established about the operation performed by F-20460d1f31d3 or whether it consumes implicit machine or global state.

### 3. Capture relationship pointers and optionally notify

After the initial mode-dependent processing, the function reads:

1. The notification-target pointer from primary offset `0x3C`.
2. The related-object pointer from primary offset `0x34`.

The related-object pointer captured here is used for the later fallback flag test.

If the notification target is non-null, the function reads its pointer field at offset `0x78`. Only if that pointer equals the primary-object pointer does it call F-df6da5bd408b.

That dependency receives:

- The captured notification-target pointer.
- A 32-bit selector equal to `1` when mode is zero and `0` for every nonzero mode.

In particular, mode values greater than one produce selector zero. They do not expose a negative or wrapped subtraction result to this dependency.

The notification occurs before the later update gate. Its effects can therefore influence the primary object’s flag word subsequently read by the function. However, changing primary offset `0x34` during this dependency does not replace the already captured related-object pointer used by that gate.

### 4. Decide whether to perform the update

After the optional notification, the primary flag word at offset `0x48` is read and bit `0x10` is tested.

- If the primary bit is set, the update proceeds without reading the captured related object’s flag word.
- If the primary bit is clear and the captured related-object pointer is null, the function returns.
- If the primary bit is clear and that pointer is non-null, its flag word at offset `0x48` is read. The update proceeds only if its bit `0x10` is set.
- Otherwise, the function returns.

An early return here skips the explicit bit-`0x20` update, F-6d16652f2d03, the late related-object callback, and the final primary callback and bit-`0x40` update. It does not undo earlier calls or their effects.

### 5. Mark the primary object and call the update dependency

On the enabled path, the function sets bit `0x20` in the primary flag word at offset `0x48` using a 32-bit read-modify-write OR.

Other bits in the value read for this update are preserved by this operation. The operation is not established as atomic.

The function then calls F-6d16652f2d03 with the following visible operands, in order:

1. The primary-object pointer.
2. The address at primary-object offset `0x80`.
3. Opaque argument A.
4. Opaque argument B.
5. An unresolved machine-context value.
6. Another unresolved machine-context value.

The interior address is passed directly; there is no visible copy of the region. Its contents, extent, mutability, and ownership treatment by the dependency remain unknown.

The flag write precedes this call. The dependency may subsequently change the flag word, so the source does not guarantee that bit `0x20` remains set when F-298722099e46 returns.

### 6. Conditionally invoke the current related object

After F-6d16652f2d03 returns, primary offset `0x34` is read again.

If that pointer is null, the late related-object callback is skipped, and the field at offset `0xA0` is not needed for this decision.

If the pointer is non-null, the function reads the 32-bit field at primary offset `0xA0` and tests its conversion to an 8-bit character value for zero. Under the represented truncation semantics, this tests whether the low eight numeric bits are zero, not whether the entire 32-bit field is zero.

If that character value is zero, the function invokes the related object’s dispatch-table entry at offset `0x128`. The indirect call shows no explicit arguments. A receiver argument or calling convention must not be invented.

The related pointer used here is not necessarily the pointer captured before F-df6da5bd408b. The current pointer is used to resolve the dispatch; the source does not establish a single immutable snapshot across the condition and call.

### 7. Obtain a destination and mark it

After the optional related-object callback, the primary dispatch-table entry at offset `0x5C` is invoked with the primary object.

Its result is interpreted as an object address. The function reads the 32-bit word at result offset `0x48`, sets bit `0x40`, and writes the result back.

There is no null check, status check, or alternate path for this result. Other bits from the value read are preserved by the OR operation. No explicit operation follows this write.

## Side effects

The function’s two explicit memory writes are:

- Setting primary flag bit `0x20` on the enabled update path, before F-6d16652f2d03.
- Setting bit `0x40` at offset `0x48` of the final callback’s returned object, after the late callback opportunity.

Those object addresses may alias. For example, the final callback may return the primary object. The supplied body neither requires nor excludes such aliasing.

All dependency and callback effects remain possible unless separately specified. In particular, this function does not establish that callees preserve globals, object fields, dispatch tables, related pointers, or memory ownership.

There is no explicit synchronization, rollback, error reporting, allocation, or deallocation. Invalid memory accesses, invalid dispatch targets, or callees that do not return normally prevent the remaining sequence from being guaranteed. Their failure mechanism is not specified here.

5. **Captured related object enables processing.**

Even if notification replaces primary offset `0x34`, the captured object enables the update. The later callback decision uses the post-update related pointer instead.
