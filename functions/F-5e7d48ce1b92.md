# F-5e7d48ce1b92

## Purpose

F-5e7d48ce1b92 performs guarded initialization of four category regions in a caller-supplied object.

When an initial attached-source query returns nonzero, the function obtains category descriptors, swaps their 32-bit entries in place, selects retained counts, writes category bookkeeping, invokes dependencies at 12-byte-spaced destination addresses, and calculates allocation-related fields. It subsequently marks the object initialized.

**Established static behavior:** initialization rejects a nonzero initialization flag, an invalid sentinel, or a category state that fails either of two initial checks. The source-present path includes three calls involving the attached-source region and temporary storage. Those calls do not establish that the source is replaced, cleared, released, or transferred.

**Inferred intent:** the labels suggest audio, video, podcast, and photo showcase categories. The swaps and allocation calculations suggest ordering and budget distribution. These interpretations do not establish statistical properties, resource ownership, or budget units.

## Behavior

### Entry guards

The function calls F-338d16f9ce72 without explicit arguments before reading either guard.

It reads the initialization flag as an unsigned byte. A nonzero value causes rejection without reading the sentinel. Otherwise it reads the sentinel as a signed byte and requires −1, whose byte representation is 0xff.

Next, in category order, it reads each +0x88 word. A nonzero word causes rejection without calling that category’s query dependency. A zero word permits F-e5a6af26f645 to be called on that region; a nonzero result also causes rejection.

No local recovery or rollback is supplied.

### Source decision and setup

After successful guards, F-044962b7cef6 is called on +0xf4.

A zero result skips category processing, the subsequent three-call source-related sequence, and allocation. The function still reaches normal completion.

For a nonzero result, the function passes a temporary word’s address to F-4085480a3d85, then reads that word and passes its value to F-a88ea44c0865. The visible body does not initialize that word before the first call. It establishes neither that the first dependency writes it nor what the second dependency does.

The function then processes four categories in order. The initial nonzero source result is only a branch condition, not a cached source argument.

### Category descriptor and swaps

For each category, F-044962b7cef6 is called again on +0xf4. Its result and the category number are passed to F-09f1b01179c4. The category number is converted through a signed byte; values 0 through 3 are unchanged. The returned address is used as the descriptor without a local validity check.

The swap loop starts at index zero. Every loop condition calls F-8cb33c040d4d and compares the index with its result as unsigned 32-bit values. Each entered iteration:

- Calls F-8cb33c040d4d again.
- Calls F-eec8106f4698.
- Calls F-d7be9cfb4000 with the F-eec8106f4698 result first and the additional count result second.
- Uses a secondary result associated with F-d7be9cfb4000 as the selected entry index.

The selected-index ABI, range, and mathematical interpretation are **documented_only**.

After these calls, the function reads the descriptor start and saves the current entry. It reads the selected entry, writes that value to the current entry, then writes the saved value to the selected entry. The current-entry address is retained for its write; the descriptor start is read again for the selected-entry accesses.

No bounds check or uniform-randomness guarantee is present. A self-swap still performs the visible entry accesses and writes. Count queries are repeated even when they would be redundant for a stable descriptor.

### Retained count and descriptor adjustment

After the swap loop, the category byte at +0x38 is cleared.

A further count result determines a retained-count snapshot:

- If its signed 32-bit interpretation is less than 501, preserve that word.
- Otherwise select 500.

That snapshot is written to +0x28. This is a 500-entry cap only for ordinary nonnegative counts. High-bit-set words take the signed-less-than branch.

A zero-valued temporary word is prepared, and another count query is compared with the retained snapshot as unsigned.

**Reported count below the retained snapshot:** the descriptor end word is read and saved **before** another count query. The function then calls F-bf2d94ca473b with:

1. The descriptor address.
2. The saved end address.
3. The retained snapshot minus the additional count result, as a 32-bit difference.
4. The zero-valued temporary’s address.

The saved address need not equal the descriptor’s end after the intervening query. This call does not itself establish insertion, expansion, or any other storage postcondition.

**Otherwise:** another count query is made. If the retained snapshot is unsigned-smaller than that result, the function considers direct shortening.

It captures the end address and calculates the retained endpoint from the descriptor start plus four times the retained snapshot. If the descriptor start equals the captured end, it performs no direct end update. Otherwise, the visible copy traversal starts at its own stopping endpoint and copies no entries. A subsequent traversal advances in four-byte steps from the retained endpoint until it equals the descriptor end, without accessing entry contents. The end word is then reduced by the captured end-to-retained-endpoint byte difference with its low two bits cleared.

For stable, valid, aligned addresses with the retained endpoint inside the sequence, this sets the logical end to the retained endpoint. No backing-storage release is explicit. Invalid alignment, ordering, or address arithmetic can prevent traversal termination.

The retained snapshot used for these comparisons and calculations is distinct from later reads of +0x28. Dependencies may have changed that field.

### Category bookkeeping and destination calls

The function reads +0x28 and writes that value to active count +0x24.

If this value is signed-less-than one, it writes 0xffffffff to +0x2c, +0x30, and +0x34, in that order. This branch does not directly write a label, make destination calls, increment the local populated-category counter, or add to the object total.

For a positive value, it writes:

1. Last position: the captured count minus one.
2. First position: zero.
3. Current position: zero.
4. The category’s selected static label address.

The labels correspond, in category order, to audio, video, podcast, and photo showcase text. Their addresses, not ownership of their storage, are written.

Next, F-584cb3d03b47 receives the address of a 12-byte temporary region that the body has not explicitly initialized. Its return value is supplied as the third argument to F-080c7de5084b. The first argument is the category’s +0x8c region; the second is a fresh retained-count read made after F-584cb3d03b47 returns.

These calls do not establish allocation, construction, initialization, or adequate destination capacity.

The following loop checks its index against a fresh **signed** retained-count read on every condition. Each iteration:

- Reads the source entry using the descriptor’s then-current start address and four-byte spacing.
- Writes that entry into the first word of a two-word temporary region.
- Clears the low byte of a separate temporary word, preserving its upper 24 bits.
- Calls F-390a12124e19 with the destination-storage address read from +0x8c plus 12 times the index, and the two-word temporary’s address.

Only the temporary’s first word is explicitly assigned here. The separate byte-cleared word is not that argument region. Destination spacing does not establish record contents or a successful record-construction postcondition.

It does not reset the total beforehand. This count can differ from the value used to enter the positive branch.

### Allocation inputs and first pass

Allocation begins after those three calls return.

The function first reads an external base value and caches it as the threshold-table base. It then reads the object budget at +0x84. Afterward, it reads the external base value again and caches that result minus 16 bytes as the factor-table base.

Thus the bases need not describe adjacent tables if the two external reads differ. Both captured bases remain cached across allocation dependencies; individual 32-bit table entries are read when used, not copied into a table snapshot.

In category order, the first pass compares the active count with the corresponding threshold using signed comparison. Only a count at most the threshold permits F-e5a6af26f645 to be called.

If that query returns nonzero, the function **rereads the active count after the call**, reads the factor from the cached factor base, and calls F-870c4fcf7295 with one explicit argument: active count plus factor minus one. The active count need not equal the value used in the threshold comparison.

It then subtracts the returned 32-bit value from the remaining budget, decrements the local populated-category counter, and writes the returned value to +0x98.

There is no explicit requirement that this category previously incremented the counter. No allocation field is universally cleared before this pass.

### Second allocation pass

This pass runs only if both the remaining populated-category counter and remaining budget are signed-positive.

F-870c4fcf7295 is called with **remaining budget first, remaining populated-category count second**. Its 64-bit result supplies a lower 32-bit base allocation and an upper 32-bit value used in signed comparisons. Quotient-and-remainder semantics are inferred, not established.

Categories are visited in order. A category is considered only when its allocation field reads as zero. F-e5a6af26f645 is then called; a nonzero result admits the category. The allocation field is not rechecked after that call.

Each admitted category increments a one-based local ordinal and receives:

- Base allocation plus one if the ordinal is at most the signed upper result.
- Base allocation otherwise.

After writing the allocation, the function reads the category factor through the cached factor base and multiplies it by the **base allocation**, not the incremented assignment. It compares that 32-bit product with the retained count as signed values and selects the signed minimum. When the retained field is selected, it is read again for the selected value.

The selected word is written to active count, followed by selected word minus one written to last position. This pass does not directly adjust first position, current position, destination contents, retained count, or object total.

## Acceptance examples

These are conditional deductions, not executed tests.

1. **Initialized guard:** If the flag read after F-338d16f9ce72 is nonzero, rejection precedes sentinel access, category checks, and source queries.

2. **Direct category rejection:** With passing earlier guards, a nonzero +0x88 word rejects without calling that category’s F-e5a6af26f645.

3. **No source:** If the initial source query returns zero and reached calls return normally, category processing and allocation are skipped. The direct flag write precedes the completion call.

4. **Stable empty category:** With zero count results, valid accesses, normal dependency returns, and preservation of the relevant fields, retained and active counts are written as zero and all three position fields as 0xffffffff. The destination-call loop is not entered.

5. **Stable 700-entry category:** Assume valid aligned source and destination storage, in-range selected indices, normal returns, stable descriptor/count reporting except for the direct shortening, and no dependency or concurrent changes to retained count or other relevant fields. The swap loop covers indices 0 through 699, retention selects 500, the descriptor end becomes the 500-entry endpoint, and F-390a12124e19 is called 500 times. This establishes call count, not successful construction of 500 records.

6. **Stable three-entry category:** Under valid-access, normal-return, and relevant-state-preservation assumptions, the positive branch directly writes active count three, first position zero, last position two, and current position zero. If retained count and object total remain unchanged by intervening calls, accumulation increases the previously existing total by exactly three.

7. **Captured end:** If the insertion-like branch captures an end address and the following count query changes the descriptor end, F-bf2d94ca473b still receives the captured address.

8. **Reloaded allocation count:** If a category passes its threshold comparison and its eligibility call changes active count before returning nonzero, the one-argument arithmetic call uses the changed count and the factor read afterward.

9. **Remainder distinction:** If the two-argument arithmetic call returns lower word two and upper word one, the first admitted category receives allocation three; its active-count candidate nevertheless uses two times the subsequently read factor, capped through the signed retained-count comparison.
