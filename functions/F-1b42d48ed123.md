# F-1b42d48ed123

## Purpose

F-1b42d48ed123 maps an index to an output consisting of two adjacent 16-bit fields. A pointer-valued field in derived state selects one of two mechanisms:

- **Direct resolution:** obtain a 32-bit item word from a collection with a 24-byte entry stride and pass it to F-5ef10d079522.
- **Table selection:** search a table of 32-bit values and boundaries, then store the low 16 bits of the selected value.

The function writes the first output field before validating its arguments. It also calls a dependency before validation. Consequently, rejection is not side-effect-free, and the initial clearing operation does not by itself guarantee the output’s contents at return.

The likely intent is to provide a compact item identifier using either individual resolution or boundary-based selection. The semantic meaning of the output fields is not established.

## Interface

### Arguments

| Argument | Established representation | Use |
|---|---|---|
| Context | 32-bit address-bearing value | Supplies fields and is passed to dependencies. |
| Index | Unsigned 32-bit integer | Selects a collection entry or table range. Its signed 32-bit interpretation must also be nonnegative. |
| Output | Address of 16-bit storage | Identifies the first of two adjacent output fields. |

The locally accessed output layout is:

| Byte offset | Width | Local behavior |
|---|---:|---|
| 0 | 16 bits | Cleared on entry; subsequently written according to the selected mode. |
| 2 | 16 bits | Passed to the direct resolver or written with a truncated table value. |

These are individual memory accesses, not an established serialization format. Byte order is not specified by the supplied evidence.

### Return value

The return representation is 32 bits:

- Explicit local rejection returns **0xFFFFFFCE**, or **−50** under signed 32-bit interpretation.
- Table-selection completion returns **0**.
- Direct-resolution completion returns the exact 32-bit result of F-5ef10d079522.

No symbolic error name or interpretation of the resolver’s status values is established.

### Preconditions for ordinary execution

The output address must support the initial 16-bit write. Reaching a path that uses the second field additionally requires valid storage through byte offset 3.

The context, derived-state addresses, collection, table, and resolver state must support every access actually reached. In particular:

- A null output pointer is not safely rejected: it is dereferenced before the null check.
- The context reaches F-8ff48652068d before local validation.
- Neither collection nor table accessibility is fully established by the local bounds checks.
- Address calculations must be valid in the execution model.

No non-aliasing contract is established. Output writes may affect later reads if the output overlaps context, derived state, or table storage.

Non-overlap alone does **not** establish dependency non-mutation. A dependency could reach the output through an independently retained reference. Any guarantee about final output contents across dependency calls therefore requires an additional assumption about those dependencies’ effects.

## Behavior

### Entry and outer validation

The first local operation writes zero to the first 16-bit output field. There is no local initialization of the second field.

The function then calls F-8ff48652068d with the context and retains the returned address as derived state.

After that call returns, the function rejects the request if any of the following applies, in this short-circuit order:

1. The output pointer is null.
2. The index, interpreted as signed 32-bit, is negative.
3. The unsigned 32-bit count at context offset **0xE88** is less than or equal to the index.

Thus, an index with bit 31 set is rejected without requiring the outer count read. The dependency call has nevertheless already occurred.

On an outer-validation failure:

- The return value is 0xFFFFFFCE.
- The last **local** write to the first field was zero.
- No local write has initialized the second field.
- F-8ff48652068d may have changed either field or other state.

Only under an explicit assumption that the dependency does not modify the output, together with valid storage and absence of interfering writes, does this failure leave the first field zero and the second field unchanged.

After successful outer validation, the function reads the 32-bit pointer-valued field at derived-state offset **0xE80**. Zero selects direct resolution; nonzero selects table selection.

### Direct resolution

The function locally clears the first output field a second time. It then calls F-8ff48652068d again with the context.

The second returned address is used for resolver-state construction. It need not equal the first returned address, and the first call’s derived-state contents are not assumed stable.

The function repeats the output-nonnull and signed-index checks. If those checks permit further work, it calls F-beaa3d5aacef with the **address of the context field at offset 0xEB0**. The returned count is treated as unsigned 32-bit. The index must be strictly less than this count.

Direct resolution therefore depends on two separate bounds:

1. The context count at offset 0xE88, checked before mode selection.
2. The count returned by F-beaa3d5aacef, checked after the second derived-state call.

The outer count is not rechecked after either later dependency call.

If direct-mode validation fails, the function returns 0xFFFFFFCE without calling the resolver. The last local write to the first field was zero, and no local write initialized the second field. Actual final contents remain subject to effects of the second F-8ff48652068d call and, when reached, F-beaa3d5aacef. Valid, non-overlapping output storage does not remove this uncertainty.

On successful validation, F-5ef10d079522 receives:

| Argument | Construction |
|---|---|
| Resolver state | Read the 32-bit address at offset **0xF60** from the second derived-state result, then add **0x1C8**. |
| Item word | Read the collection base from context offset **0xEB0**, advance by **24 × index** bytes, and load the entry’s first 32-bit word. |
| Output destination | Address of the second 16-bit output field. |
| Scratch destination | Address of local scratch storage. |

The collection-field address given to F-beaa3d5aacef is distinct from the collection base subsequently loaded from that field. The count dependency may change that field; the later load is not specified to reuse an earlier collection base.

After the resolver returns normally, the function locally overwrites the first output field with:

**floor(index / 2) modulo 65,536.**

The width matters: this follows from a 32-bit unsigned left shift by 15 followed by a logical right shift by 16. Bits discarded by the left shift do not reappear.

This write occurs regardless of the resolver’s returned status. The function then returns that status unchanged.

The resolver receives the second-field address, but its contract is unavailable. This function does not guarantee that the resolver writes the second field, including when it returns a success-like or failure-like status.

### Table selection

The function writes **1** to the first output field, then reloads the table pointer from derived-state offset **0xE80**. This is a separate read after the output write, not reuse of the mode-selection value.

It returns 0xFFFFFFCE if:

- The reloaded table pointer is null; or
- The computed address of the second output field is null.

The second condition is not a buffer-size or accessibility check. On this rejection path, the last local first-field write was one and there is no local second-field write.

The table uses 32-bit words:

| Byte offset | Interpretation |
|---|---|
| 0 | Signed 32-bit entry count |
| 4 + 8 × entry number | Associated 32-bit value |
| 8 + 8 × entry number | Unsigned 32-bit boundary |

The search starts with lower position zero, upper position equal to count minus one, and selected position zero.

For conventional positive counts and non-overflowing search arithmetic, each iteration examines the midpoint of the current lower and upper positions. Boundaries are compared as **unsigned 32-bit values** against the unsigned index.

The selection and narrowing rules are:

- If the index equals the examined boundary, select the examined entry without reading the next boundary.
- If the index exceeds the examined boundary, read the next boundary:
  - An index below that next boundary selects the examined entry.
  - Equality with the next boundary selects the next entry.
  - An index above the next boundary advances the lower search position.
- If the index is below the examined boundary, read the preceding boundary:
  - An index at least as large as the preceding boundary selects the preceding entry.
  - Otherwise, reduce the upper search position.

If the search positions cross, the function uses the retained selected position. After an iteration that narrows the search, this is the most recently examined midpoint. If no iteration occurs, it remains zero.

Two edge accesses are significant:

- At examined entry zero, the “preceding boundary” access reads the table’s **count word**, interpreted unsigned. If this comparison succeeds, the selected position becomes **−1**, and the associated-value access is at byte offset **−4** relative to the table pointer.
- At the nominal last entry, the next-boundary read reaches beyond the value/boundary pairs implied by the count. An extra readable boundary is not established.

On completion, the function writes the low 16 bits of the selected 32-bit value to the second output field and returns zero. Truncation does not produce a separate error.

The function does not validate boundary ordering, table extent, consistency with the outer count, or the semantic range of table values.

## Side effects

### Local writes and dependency effects

The established local write order is:

1. Clear the first field before the first dependency call.
2. After outer validation:
   - Direct mode clears the first field again before its second derived-state call.
   - Table mode writes one before reloading the table pointer.
3. Direct mode writes the index-derived first field after the resolver returns.
4. Table completion writes the selected value’s low 16 bits to the second field.

The function never generally clears the second field on failure.

Local-write history and final memory contents are distinct guarantees. A dependency may modify either output field through references not visible in this function. In particular, both outer rejection and direct-mode count rejection occur after dependency calls that follow a local clear. Their unconditional guarantee is the identity of the last local write, not a final zero value.

### Read ordering

The following ordering relationships are established:

- Initial clearing precedes the first F-8ff48652068d call.
- That call precedes outer validation.
- Successful outer-count validation precedes the mode-field read.
- Direct mode calls F-8ff48652068d again before querying the collection count.
- The collection-count call precedes construction of the resolver arguments.
- The resolver returns before the final direct-mode first-field write.
- Table mode writes one before reloading its table pointer.

Exact ordering among independent expressions constructing a single dependency call is not established. No volatile, synchronization, or atomicity contract is supplied.

### Ownership and lifetime

There is no explicit local allocation, release, or ownership-transfer operation.

This does not establish that dependencies avoid allocation, release, pointer retention, or global mutation. The local scratch address supplied to the resolver has local lifetime; safe retention beyond the call would require a contract not provided here. Its required writable extent is also unknown.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, they assume valid, non-overlapping storage, valid arithmetic, no concurrent interference, and dependencies that return normally **without modifying output storage or disturbing the state described in the example**, except for explicitly stated resolver writes.

### Outer-bound rejection

Given outer count 8 and index 8:

- The first field is locally cleared.
- F-8ff48652068d is called once.
- The return is 0xFFFFFFCE.
- Neither the collection-count dependency nor the resolver is reached.
- Under the stated non-mutation assumption, the first field is zero and the second remains unchanged.

Index 0x80000000 is rejected by the signed-index check without reading the outer count.

### Rejection with dependency output mutation

Suppose F-8ff48652068d can independently access the output and writes 0x1357 and 0x2468 to its two fields. If the subsequent outer count rejects the index, with no other writes:

- The return is 0xFFFFFFCE.
- The last local first-field write was zero.
- The actual fields are 0x1357 and 0x2468.

Output overlap with the context or table is unnecessary for this outcome.

Similarly, if direct-mode F-beaa3d5aacef writes the first field and then returns a count that rejects the index, there is no subsequent local clear to undo its write.

### Direct resolution and propagated status

Given direct mode, index 6, and both bounds greater than 6:

- F-8ff48652068d is called twice.
- F-beaa3d5aacef receives the collection-field address.
- The resolver receives the first 32-bit word of collection entry 6.
- After the resolver returns, the first field is written as 3.
- The function returns exactly the resolver’s status.

If the resolver writes 0x2468 to the second field and returns an error status, the final fields are 3 and 0x2468 under the stated assumptions. The error status does not suppress the first-field write.

For index 131,072, with sufficiently large bounds and collection storage, the final first field is zero because 65,536 truncates to 16 bits.

### Direct-mode second-bound rejection

If the outer count admits the index but the collection-count result does not:

- The resolver is not called.
- The return is 0xFFFFFFCE.
- The last local first-field write was zero.
- No local write initializes the second field.
- Under dependency non-mutation, the first field remains zero and the second remains unchanged.

### Table equality and truncation

Given two entries with boundaries 10 and 20, values 0x12345678 and 0x0000ABCD, and an outer count admitting the index:

- Index 10 produces fields 1 and 0x5678.
- Index 15 produces fields 1 and 0x5678.
- Index 20 produces fields 1 and 0xABCD.

Each returns zero. These paths do not require a boundary beyond the two stated boundaries.

### Zero count and preceding-entry access

With table count zero, the search performs no iteration. If the value word at byte offset 4 is readable, its low 16 bits are written to the second field and the function returns zero. Zero count is not locally treated as an empty-table error.

Separately, with table count 2, first boundary 10, and index 5, the first midpoint is entry zero. The preceding-boundary comparison uses the count word, so 2 is compared against 5. That comparison selects entry −1. If storage at table offset −4 is readable and contains 0x12345678, the result is fields 1 and 0x5678 with return zero. Without such readable storage, a defined completion is not established.

## Uncertainties

The following remain **documented_only**:

- Semantic meanings of the output fields, item words, and table values.
- Boundary ordering and intended range coverage.
- Any terminal sentinel or readable storage before the table.
- Legitimacy of zero or negative table counts.
- Dependency mutation, ownership, lifetime, and output-initialization contracts.
- Concurrency, reentrancy, and global-state preservation.
- Exact behavior for invalid addresses, address wraparound, or overflowing signed arithmetic.

Forming count minus one can overflow for the minimum signed 32-bit count. Midpoint addition and table-position calculations can also overflow for extreme values. Negative counts otherwise ordinarily bypass the search and retain selected position zero. No portable result is promised where the arithmetic itself is invalid.

The supplied representation reports omitted unreachable regions. Their contents and any information lost in reconstruction are unavailable.
