# F-a71330230cfd

## Purpose

F-a71330230cfd conditionally updates a mutable state object using a selected 24-byte table entry and the result of an external 64-bit transformation.

When the state address is nonzero and its signed selection index is less than the table’s signed count, the function:

- Copies an eight-byte value from the selected entry into the state.
- Forms a 64-bit product from a state-held 32-bit factor and an entry-held 64-bit operand.
- Publishes that product into the state before calling dependency F-1e0edc6e0bc9.
- Replaces the published product with the dependency’s result.
- Stores the sum of that result and the previously captured entry value into another state field.

When the index is not less than the count, the function instead installs the maximum signed 64-bit value in two state fields and zero in a third.

A zero state address causes an immediate return without accessing either object.

These are established static behaviors. Interpreting the fields as times, positions, durations, or any other domain-specific quantities is not supported by the supplied evidence.

## Behavior

### Zero state address

The function tests the state address before reading the descriptor, index, context, or any entry.

If the state address is zero:

- It performs no direct memory reads or writes through either argument.
- It does not call F-1e0edc6e0bc9.
- It returns without a result.

The context address need not identify readable storage in this case.

### Selection decision

For a nonzero state address, the function reads the descriptor address from state offset `0x1c`, then the signed index from offset `0xa4`, and obtains the signed count from the descriptor.

Entry processing occurs exactly when:

**signed index < signed count**

This is not an unsigned bounds check and is not equivalent to checking that the index lies in the interval from zero through count minus one.

If the comparison is false, execution takes the sentinel branch.

### Selected-entry branch

The entry address is derived from the descriptor’s entry-array address plus 24 times the signed index. The arithmetic is represented through 32-bit address-related values. No overflow or bounds check is present.

The function first captures the entry value at offset `0x08`:

1. It reads the four-byte word at entry offset `0x0c`.
2. It reads the eight-byte value beginning at entry offset `0x08`, retaining that value for the eventual sum.
3. It reads the low four-byte word at entry offset `0x08` for copying.
4. It writes that low word to state offset `0xa8`.
5. It writes the previously read word from entry offset `0x0c` to state offset `0xac`.

With stable, non-overlapping storage, this copies the entry’s complete eight-byte value. The separate accesses matter if memory changes between reads or if the destination aliases the source. The copied field and the retained addend are not established to be a single atomic snapshot.

Next, the function reads the factor at state offset `0x7c`. It obtains the entry-array address from the descriptor again and uses the previously captured index to locate the product operand.

This repeated base-address read matters: the addend and product operand are not guaranteed to come from the same array address if that descriptor field changes between reads.

The product calculation uses:

- The factor interpreted as a signed 32-bit integer.
- An eight-byte entry operand represented by a low and a high 32-bit word.
- A retained result width of 64 bits.

Let the unsigned factor bit pattern be \(u\), the operand’s low word be \(L\), and its high word be \(H\). The low result word is the low 32 bits of \(uL\). The high result word combines:

- The high 32 bits of the unsigned product \(uL\).
- The low 32 bits of \(uH\).
- A sign correction of \(-L\) when the factor’s top bit is set.

Thus, at the bit-pattern level, the computation is multiplication of the sign-extended 32-bit factor by the entry’s 64-bit operand, retaining the low 64 bits. It does not preserve a wider mathematical product and does not detect overflow.

The resulting product is published in this order:

1. High word to state offset `0xbc`.
2. Low word to state offset `0xb8`.

This order differs from the earlier copied-value writes.

The function then reads four bytes from context offset `0x64` and calls F-1e0edc6e0bc9 with four 32-bit arguments:

1. Product low word.
2. Product high word.
3. The context value.
4. Zero.

The dependency returns a 64-bit value. The caller writes that return value to the eight-byte field beginning at state offset `0xb8`, replacing the intermediate product.

Finally, it adds the retained entry addend to the returned 64-bit value and writes the resulting eight-byte value to state offset `0xb0`.

The retained addend is not reread after the dependency call. Conversely, the function does not reread the copied field to compute the sum. Changes to that field by the dependency therefore do not redefine the addend used by this invocation.

The evidence shows no overflow check or saturation for the final addition. Exact overflow semantics beyond the represented 64-bit operation remain documented_only.

### Sentinel branch

If the signed index is greater than or equal to the signed count, the function performs these direct writes in order:

1. `0xffffffff` to state offset `0xa8`.
2. `0x7fffffff` to state offset `0xac`.
3. Zero to state offset `0xb8`.
4. Zero to state offset `0xbc`.
5. `0x7fffffffffffffff` to the eight-byte field at state offset `0xb0`.

The resulting values are:

| State field | Value |
|---|---|
| `0xa8` | Maximum signed 64-bit value: 9,223,372,036,854,775,807. |
| `0xb8` | Zero. |
| `0xb0` | Maximum signed 64-bit value: 9,223,372,036,854,775,807. |

This branch does not read the factor, entry-array address, entry contents, or context field. It does not call the dependency.

These statements describe direct accesses, not an isolation guarantee:

- Arguments, descriptors, entries, and state may alias unless callers prevent it.
- A state write can affect a later read if their underlying storage overlaps.
- F-1e0edc6e0bc9 may have additional effects that are not established here.
- No locking, synchronization, rollback, or atomic publication protocol is shown.

No allocation, release, ownership transfer, or retention operation is directly shown. That does not establish that the dependency performs none.

The eight-byte accesses shown as single operations are not evidence of hardware atomicity or a particular sequence of underlying bus accesses.
