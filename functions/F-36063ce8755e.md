# F-36063ce8755e

## Purpose

F-36063ce8755e selects a formatting path for a 32-bit quantity decomposed using factors of 3,600 and 60. It invokes an output dependency with a destination-like input, a format-like value, and formatting operands.

**Inferred intent:** render a duration, choosing between an hours-inclusive form, a shorter form, and a special seconds-only form. The division factors, branch structure, and format-associated labels support this interpretation. Exact text, punctuation, localization behavior, and output ownership are not established.

The function also returns a 64-bit value assembled from two local 32-bit words. That return must not be assumed to be the rendered text, its length, or a success indicator.

## Interface

### Inputs

The interface has four ordered inputs:

| Input | Width | Established use |
|---|---:|---|
| Quantity | 32 bits | Passed through two arithmetic dependency calls and remainder-like calculations. |
| Prefix selector | 32 bits | Compared with zero to choose one of two static addresses. Also initializes the upper return word. |
| Output argument | 32 bits | Passed unchanged as the first argument to the final output dependency. Also initializes temporary storage. |
| Special-mode selector | 32 bits | Compared with exactly 1 to enable the special path when both arithmetic results are zero. Also initializes temporary storage. |

The quantity and the two selectors are represented as signed 32-bit integers in the supplied listing. The output argument is an uninterpreted 32-bit value at this boundary. Its downstream interpretation may be a pointer, handle, or another representation; that contract is unavailable.

There is no visible input validation.

### Output

The result is a 64-bit concatenation:

- Bits 31–0 come from the first local 32-bit word.
- Bits 63–32 come from the second local 32-bit word.

Equivalently, this is an unsigned bitwise assembly of the two words, not sign extension of the lower word.

The final output dependency’s return value is not used to form this result.

### Local storage exposed to dependencies

Four consecutive 32-bit local words are initialized, in order, from the four inputs. For this contract:

- **Pair A** consists of the first and second words.
- **Pair B** consists of the third and fourth words.

The special path passes the address of Pair A or Pair B to several dependencies. The visible source establishes the word placement and addresses passed; it does not establish the dependencies’ object layouts or their permitted write extents.

The storage is local to the invocation. Any dependency retaining these addresses after return would need an external lifetime contract not present in the evidence.

## Behavior

### 1. Initialize the local words

Before the dependency calls, the four local words receive the quantity, prefix selector, output argument, and special-mode selector respectively.

These initial values matter on the special path because dependencies receive addresses into this storage. They also explain why the ordinary short-form return retains the original prefix selector in its upper half.

### 2. Compute two quotient-like values and a residual

The function invokes F-d7be9cfb4000 twice:

1. With the original quantity and 3,600.
2. With an intermediate quantity and 60.

Let:

- **H** be the first dependency result.
- **R₁** be the original quantity minus 3,600 times H.
- **M** be the second dependency result, obtained using R₁ and 60.
- **R** be R₁ minus 60 times M.

The source expresses each subtraction as addition of a product with a negative constant.

The calls occur in this order. The second call uses the intermediate result, not the original quantity.

**Inferred intent:** H is hours, M is minutes within the remainder, and R is seconds within the next remainder. This interpretation depends on F-d7be9cfb4000 behaving as the expected division operation. Its behavior, including rounding for negative inputs, is not independently established.

All participating values are 32-bit. The source does not establish widened intermediate arithmetic or overflow checks. If the dependency supplies results that make these products or sums overflow signed 32-bit arithmetic, the exact outcome is `documented_only`; this contract does not invent saturation, trapping, or a source-language wraparound guarantee.

### 3. Choose a prefix-associated address

After the second arithmetic dependency call, the function selects:

- **P₀** if the original prefix selector equals zero.
- **P₁** otherwise.

P₀ and P₁ are distinct static addresses. Their bytes and meanings are not supplied.

The selection is based on the original input’s zero/nonzero status. There is no separate negative-selector case, and a selector of 2 is treated like a selector of 1.

The residual R is then calculated.

### 4. Select the formatting path

There are three paths:

| Condition | Path |
|---|---|
| H is nonzero | Hours-inclusive ordinary path |
| H is zero, and either M is nonzero or the special-mode selector is not exactly 1 | Short ordinary path |
| H is zero, M is zero, and the special-mode selector is exactly 1 | Special path |

R is not part of the special-path eligibility check. Under conventional division, a nonzero seconds remainder can therefore take that path.

### 5. Ordinary paths

#### Hours-inclusive ordinary path

When H is nonzero:

1. The function selects a static format-associated address, **T₃**.
2. The first local word is replaced with M.
3. The second local word is replaced with R.
4. F-ce41e65501f5 is invoked with these explicitly shown arguments, in order:
   - The original output argument.
   - T₃.
   - The selected prefix address.
   - H.
5. The function returns the concatenation of the second and first local words.

The visible local assignments stage M and R immediately before the output call. Their role as additional formatting arguments is plausible from the apparent stack layout, but not proven solely by the explicit argument list.

Subject to the shown call not modifying that local storage through behavior absent from the evidence, the return has:

- Lower 32 bits: M.
- Upper 32 bits: R.

#### Short ordinary path

When H is zero and the special path is not selected:

1. The function selects a different static format-associated address, **T₂**.
2. The numeric operand for the explicit output call becomes M.
3. The first local word is replaced with R.
4. The second local word remains the original prefix selector.
5. F-ce41e65501f5 is invoked with:
   - The original output argument.
   - T₂.
   - The selected prefix address.
   - M.
6. The function returns the concatenation of the second and first local words.

Subject to the same local-storage qualification, the return has:

- Lower 32 bits: R.
- Upper 32 bits: the original prefix selector.

The ordinary short and hours-inclusive paths therefore give different meanings to the upper return word.

### 6. Special path

1. Invoke F-9d0ecc5f6adf with no explicit arguments.
2. Read a static 32-bit lookup-associated value, **K**.
3. Invoke F-c0b020cd3882 with the result of step 1 and K.
4. Invoke F-7afe554bcf62 with the address of Pair B and the result of step 3.
5. Invoke F-5b24edfb22c0 with the address of Pair A.
6. Invoke F-44362605ab79 with the address of Pair B, obtaining a 32-bit value.
7. Invoke F-1f62160dfd52 with:
   - The address of Pair A.
   - The address of separate static format-associated storage, **Tₛ**.
   - The previously selected prefix address.
   - The value obtained in step 6.
8. Invoke F-44362605ab79 with the address of Pair A, obtaining another 32-bit value.
9. Invoke F-ce41e65501f5 with:
   - The original output argument.
   - The value obtained in step 8.
   - R.
10. Invoke F-289ec4311c64 with the address of Pair A.
11. Invoke F-289ec4311c64 with the address of Pair B.
12. Return the concatenation of the second and first local words as they exist after both final dependency calls.

The output call still receives the original third input. It does not substitute the potentially modified third local word.

The return is assembled **after** the two F-289ec4311c64 calls. No contract may replace it with Pair A’s earlier contents without evidence that those dependencies preserve the words.

**Inferred intent:** this sequence obtains a context-dependent string-like value, constructs temporary formatting objects, produces a dynamic format, emits the residual quantity, and cleans up temporaries. Construction, conversion, formatting, and destruction semantics remain unproven dependency interpretations.
