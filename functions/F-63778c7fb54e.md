# F-63778c7fb54e

## Purpose

F-63778c7fb54e conditionally returns a 32-bit value selected from an indexed region of a caller-supplied object. It either:

- Writes the selected value to the caller’s output location and returns **0**.
- Returns **3** without directly writing the output location.

The function has two polling policies, selected by an object byte. Both can invoke F-c8120265b43a repeatedly. The policies differ in their readiness conditions, dependency arguments, stopping conditions, and treatment of an object status value of 4.

**Established behavior:** the function compares object fields, polls through an opaque dependency, and conditionally copies one 32-bit field to the output.

**Inferred intent:** the fields appear to describe indexed work or buffered data, and the dependency may provide a wait or progress operation. Neither that interpretation nor any time unit for its numeric arguments is established.

## Behavior

### Entry gate

The function first reads the current index and index limit and compares them as signed 32-bit integers.

If the current index is not less than the limit, the function returns 3. It does not proceed to the policy selector, indexed fields, dependency calls, or output store.

Otherwise, it reads the policy selector:

- A value of 2 selects the **alternate policy**.
- Every other byte value selects the **ordinary policy**.

The policy selector is not read again during this invocation. Changes to it made later do not switch the active policy.

The index limit is also not checked again. Later indexed accesses use newly read current indices without repeating the entry bounds comparison.

### Ordinary policy

The function first reads the current index and uses it to read the selected value and ordinary comparison value.

If those values differ, it proceeds directly to the successful output operation. It does not consult status, the stop indicator, or the selected-value sentinel before doing so.

If they are equal, it reads status:

- Status 4 causes an immediate return of 3.
- Any other status starts the polling loop with a local counter of zero.

Each polling evaluation uses a newly read current index. It reads the selected value and ordinary comparison value for that index.

The loop’s readiness and status checks occur in this order:

1. If the two indexed values differ, polling ends successfully without reading status for that evaluation.
2. If they are equal, status is read.
3. If that status is 4, polling ends successfully.
4. Otherwise, the function evaluates failure conditions before any dependency call.

This creates an important distinction: status 4 at the initial equal-value check returns 3, whereas status 4 observed at a later loop check leads to a successful output store.

For an equal-value loop evaluation with status other than 4, the failure conditions are:

- Status is 3.
- Status is not 3 and the stop indicator is 3.
- Neither byte condition above applies, and the local counter is at least 1000.

Status 3 prevents the stop-indicator read. The counter threshold is considered only when neither byte equals 3.

If a failure condition holds, the function returns 3 without directly storing to the output.

Otherwise, it increments the local counter and tests the selected value already read during that loop evaluation. If that value is the 32-bit all-ones pattern, interpreted as signed −1, it returns 3 without calling the dependency.

If that sentinel test does not fail, the function:

1. Reads the 32-bit dependency argument at offset 0x1380.
2. Calls F-c8120265b43a with that value and the numeric second argument **10**.
3. Discards the dependency’s return value, if any.
4. Repeats the polling evaluation.

On a path that remains equal and has no earlier stopping condition, calls occur with counter values initially corresponding to 0 through 999. After **1000 dependency calls**, a further equal-value evaluation returns 3 at the counter threshold. No 1001st call occurs.

Readiness or status 4 can still end polling successfully at that next evaluation because those checks precede the counter threshold.

### Alternate policy

The alternate policy starts with a local counter of zero. It does not use the ordinary comparison field.

Each iteration reads a fresh current index, then the selected value and alternate comparison value for that index.

The readiness checks are ordered as follows:

1. If the selected value differs from the alternate comparison value, proceed to successful output. Do not read the auxiliary value or status for that iteration.
2. If those values are equal, read the auxiliary value.
3. If the auxiliary value is nonzero, proceed to successful output without reading status.
4. If the auxiliary value is zero, read status.
5. If status is 4, proceed to successful output.

If none of those conditions allows success, the function:

1. Reads the dependency argument.
2. Calls F-c8120265b43a with that value and the numeric second argument **100**.
3. Reads the stop indicator.
4. Returns 3 if the stop indicator is 3.
5. Otherwise, returns 3 if the local counter is at least 200.
6. Otherwise, increments the counter and begins another iteration.

The stop-indicator and counter checks occur **after** the dependency call. Thus, a preexisting stop indicator of 3 does not prevent the first call when the readiness checks require polling.

On a continuously non-ready path with a stop indicator other than 3, the function makes **201 dependency calls** before returning 3: the iteration entered with counter 200 still performs its call before failing the threshold check.

Status 3 has no special stopping meaning in this policy. The selected value’s all-ones pattern also has no special sentinel meaning here.

A dependency call that makes data ready can still be followed by failure. The function checks the stop indicator and counter before re-reading readiness. In particular, the final threshold iteration returns 3 without another readiness evaluation.

### Successful output operation

All successful paths converge on the same final operation:

1. Re-read the current index.
2. Read the selected value using that newly read index.
3. Store that 32-bit value to the output address.
4. Return 0.

The stored value is not necessarily the value that satisfied an earlier readiness comparison. There is no explicit snapshot or synchronization spanning those reads.

A successful path does not repeat the entry comparison against the index limit.

## Side effects

### Direct effects

The only explicit write to caller-provided memory is the successful 32-bit output store. The function does not explicitly modify any object field.

All explicit return-3 paths omit that output store. This means “no direct output write,” not necessarily “the output memory is unchanged”: a dependency could modify it indirectly, and aliasing or external writers may also matter.

The polling counter is local and is not persisted to the object.

### Dependency effects and read visibility

Dependency calls are observable effects. Their first argument is re-read from offset 0x1380 before every call; the second argument is fixed by the selected policy.

No preservation guarantee for F-c8120265b43a is established. In particular, it must not be assumed to preserve:

- Object contents or the current index.
- The dependency argument used by subsequent calls.
- Memory reachable through other state.
- Ownership or lifetime of allocations.

The function continues using its object address after calls. Validity of that memory is therefore a prerequisite, not an enforced guarantee.

Polling re-reads several fields and can observe dependency-induced changes. This does not establish volatile access, atomicity, memory ordering, thread safety, or freedom from data races.

### Ownership and errors

No allocation, release, or ownership transfer is explicit in this function. Passing a 32-bit value to the dependency does not establish whether it is a handle, pointer, or ownership-bearing reference.

Invalid addresses are not translated into return value 3. Dependency failures have no explicit return-value handling. Nonreturning behavior, faults, callbacks, and external effects of the dependency remain undocumented.

## Acceptance examples

These examples are conditional expectations from static evidence, not runtime test results. Unless stated otherwise, accessed memory is valid, relevant fields remain stable, dependency calls return, and the dependency does not modify the output.

1. **Entry rejection.** Current index 5 and limit 5 produce return 3, with no dependency call or direct output write.

2. **Signed entry comparison.** Current index −1 and limit 1 pass the entry gate. This does not establish that subsequent memory accesses are valid; those accesses use a negative index displacement.

3. **Ordinary immediate readiness.** A selector other than 2, with unequal selected and ordinary comparison values, produces return 0 and copies the selected value. Status and stop indicator do not block this path.

4. **Ordinary initial status 4.** Equal ordinary values and status 4 at the initial status check produce return 3 without a dependency call.

5. **Ordinary later status 4.** If the initial equal-value status check is not 4, but a loop status read observes 4 while the values remain equal, the function stores the selected value and returns 0.

6. **Ordinary status 3.** With equal values, status 3 at the loop check causes return 3 before a dependency call and without reading the stop indicator at that check.

7. **Ordinary sentinel.** Equal values of all ones, with status neither 3 nor 4 and stop indicator not 3, cause return 3 before the first dependency call. Unequal values do not apply this sentinel rule.

8. **Ordinary threshold.** Persistently equal nonsentinel values, status neither 3 nor 4, and stop indicator not 3 produce exactly 1000 calls with second argument 10, followed by return 3.

9. **Alternate immediate readiness.** With selector 2 and unequal selected and alternate comparison values, the function succeeds without a dependency call, auxiliary-value read, or status read.

10. **Alternate auxiliary readiness.** Equal alternate values and a nonzero auxiliary value produce success without a status read or dependency call.

11. **Alternate preexisting stop.** Equal alternate values, zero auxiliary value, status other than 4, and stop indicator 3 produce one call with second argument 100, then return 3.

12. **Alternate threshold.** Persistently equal alternate values, zero auxiliary value, status other than 4, and stop indicator not 3 produce exactly 201 calls, then return 3.

13. **Alternate readiness after a call.** If a call changes the object to a ready state, success occurs on the next evaluation only if the post-call stop-indicator and counter checks permit another iteration.

14. **Final index re-read.** If the current index changes before the successful output operation, the copied value comes from the index read at that operation, not necessarily the index that established readiness.
