# F-cf8121d269c4

## Purpose

F-cf8121d269c4 walks a linked object structure and selectively replaces objects whose one-byte discriminator is `0x95` and whose 32-bit selector matches the requested selector.

A matching object is handled in place:

- A negative signed replacement index changes its discriminator to `0x5c`.
- A nonnegative replacement index selects a source object from a separate table. Selected fields are transferred directly or through dependencies, in a specific order.

An object that does not match is not directly replaced. Instead, the function visits two linked objects, delegates processing of another field, and then visits objects referenced by an optional collection.

This is a static behavioral contract derived from the supplied function body. “Object,” “selector,” and “replacement” are descriptive terms, not established application-level type names. Deep-copy semantics, ownership transfer, and the meaning of the discriminators are not established.

## Interface

The function has four apparent logical inputs and no explicit return value:

| Input | Representation | Role |
|---|---|---|
| Operation context | Opaque 32-bit value | Passed to recursive invocations and dependencies. Its interpretation is unknown. |
| Current object | Pointer, represented as 32 bits in the supplied model | Object to inspect or modify. A null pointer is accepted. |
| Requested selector | Unsigned 32-bit value | Compared for exact equality with a matching-kind object’s selector field. |
| Replacement descriptor | Pointer-like 32-bit value | Supplies a replacement-table base when a matching object has a nonnegative index. |

The replacement descriptor is not directly dereferenced by a null-object call, a nonmatching call, or a matching call with a negative index. Dependencies receive it only where shown below.

### Collection layout

A non-null collection reference identifies a structure with:

- A signed 32-bit count at `+0x00`.
- A 32-bit entry-table reference at `+0x0c`.
- Entries spaced 12 bytes apart.
- A 32-bit object reference in the first four bytes of each entry.

This function does not directly access the remaining eight bytes of each entry.

### Replacement descriptor layout

At descriptor offset `+0x0c`, the function reads a 32-bit replacement-table reference. Replacement entries are spaced 12 bytes apart. The first four bytes of the selected entry contain the source-object reference.

### Preconditions

Except for the expressly supported null current object, every address actually accessed must be valid for the corresponding read or write. In particular:

- A replacement source must be non-null and readable at all fields used.
- A replacement destination must be writable at all fields directly updated.
- Collection and replacement-table indexing must resolve to valid entries.
- All dependency-specific input and lifetime requirements must hold.

The function supplies no explicit bounds checks, cycle detection, allocation-failure handling, or pointer-validity checks.

## Behavior

### 1. Null-object handling and match selection

If the current object is null, the function returns immediately. It performs no object reads and makes no dependency calls.

Otherwise, it reads the one-byte discriminator.

- If the discriminator is not `0x95`, the function takes the traversal path without directly reading the selector at `+0x24`.
- If the discriminator is `0x95`, it reads the 32-bit selector at `+0x24` and compares it with the requested selector.
- Exact equality selects the replacement path. Inequality selects traversal.

The comparison is over all 32 bits. It does not use the signed interpretation of either selector.

### 2. Traversal of a nonmatching object

Traversal occurs in this order:

1. Read the reference at current-object offset `+0x08` and recursively invoke F-cf8121d269c4 with that reference.
2. After that invocation returns, read the reference at `+0x0c` and recursively invoke F-cf8121d269c4.
3. After the second invocation returns, read the value at `+0x38` and call F-dfb0bd02dea5 with the operation context, that value, the requested selector, and the replacement descriptor.
4. After F-dfb0bd02dea5 returns, read the collection reference at `+0x10`.
5. If the collection reference is null, return.
6. Otherwise, visit its indexed object references in ascending index order, beginning at zero.

Each recursive invocation receives the same operation context, requested selector, and replacement descriptor.

For the collection, the loop condition uses a signed comparison against the count stored in the collection. A zero or negative count causes no entry visits. For each visited entry, the function reads the entry-table reference, reads the object reference at the corresponding 12-byte stride, and recursively processes that object.

These reads are not a snapshot of the initial graph:

- The second linked-object reference is read after the first recursive invocation.
- The `+0x38` field is read after both linked-object invocations.
- The collection reference is read after F-dfb0bd02dea5.
- The collection count is read again for each loop condition.
- The collection entry-table reference is read for each visited entry.

Consequently, mutations made by earlier calls can affect later traversal. The collection structure selected after F-dfb0bd02dea5 is retained for the loop; the parent object’s collection field is not explicitly reread for each entry.

A null referenced object is harmless to the recursive F-cf8121d269c4 call. No equivalent null-handling guarantee is established for F-dfb0bd02dea5.

### 3. Matching object with a negative index

For a matching object, the function reads the 32-bit field at `+0x28` as a signed integer.

If it is negative, the function writes the single byte `0x5c` to offset `+0x00` and returns.

In this branch:

- No replacement-table lookup occurs.
- No dependency is called.
- No child or collection is traversed.
- No other destination field is directly written.

Every value with its high bit set is negative under the supplied signed 32-bit interpretation, including `0xffffffff` and `0x80000000`.

### 4. Matching object with a nonnegative index

For a nonnegative index, the function reads the replacement-table reference from descriptor offset `+0x0c`. It then selects the entry at a 12-byte stride and reads the source-object reference from that entry’s first four bytes.

There is no explicit upper-bound check. The source-object reference is selected once; later dependency calls do not cause the function to select a new source object.

Replacement then proceeds in the following order:

| Order | Action |
|---:|---|
| 1 | Read the source discriminator and write it to destination `+0x00`. |
| 2 | Read source `+0x08`, call F-1a5398bcc6b3 with the operation context and that value, then write its 32-bit result to destination `+0x08`. |
| 3 | Read source `+0x0c`, call F-1a5398bcc6b3, then write its 32-bit result to destination `+0x0c`. |
| 4 | Read source `+0x10`, call F-1698e90c5d31, then write its 32-bit result to destination `+0x10`. |
| 5 | Copy four bytes from source `+0x24` to destination `+0x24`. |
| 6 | Copy four bytes from source `+0x3c` to destination `+0x3c`. |
| 7 | Copy four bytes from source `+0x28` to destination `+0x28`. |
| 8 | Copy four bytes from source `+0x30` to destination `+0x30`. |
| 9 | Call F-869c28ef7a31 with the operation context, destination address `+0x14`, and source address `+0x14`. |
| 10 | Call F-869c28ef7a31 with the operation context, destination address `+0x1c`, and source address `+0x1c`. |
| 11 | Read source `+0x38`, call F-5f042ee1ac4e, then write its 32-bit result to destination `+0x38`. |
| 12 | Copy two bytes from source `+0x02` to destination `+0x02`, then return. |

Each direct copy reads its source field at that stage, not at function entry. Each dependency result is stored only after the corresponding dependency returns.

The function does not subsequently traverse the replaced destination’s links or collection. It does not check whether the copied discriminator and selector would themselves match. A second substitution requires another invocation or behavior inside a dependency.

### 5. Arithmetic and aliasing

Both table forms use 12-byte entry spacing. Collection indices start at zero and increase by one; replacement indices are accepted only when nonnegative as signed 32-bit values.

The supplied representation uses 32-bit quantities for pointers and indexed arithmetic. It does not justify a portable promise about overflow behavior. Valid-input acceptance therefore requires that all calculated entry addresses identify valid memory in the execution environment; a nonnegative index alone is insufficient.

No source/destination disjointness check is present. If the source aliases the destination, or dependencies modify the source, later reads observe the memory then present. Replacement is ordered field processing, not a whole-object snapshot copy. Whether dependencies support such aliasing is unknown.

## Side effects

The function directly mutates only matching destinations. Its direct writes are those listed above, or the single discriminator write for a negative index.

For a nonmatching object, it performs no direct writes to that object. Recursive calls and dependencies can nevertheless mutate that object, reachable objects, shared structures, or other state. Their effects are not constrained by this body.

Replacement is not visibly transactional:

- The discriminator is changed before the first replacement dependency runs.
- Earlier writes remain in place while later calls execute.
- No rollback or cleanup path is shown.
- No dependency result is checked before storage.

The function does not directly allocate, release, or retain memory through an identified primitive. Overwriting old references is not evidence that their prior targets are released. Likewise, a dependency-produced reference is not evidence of fresh allocation, unique ownership, or ownership transfer.

Recursive traversal has no visited set or depth limit. Shared references may be processed repeatedly. Cycles can cause unbounded recursion unless intervening mutations or external behavior break them.

There is no explicit error return or diagnostic. Faults, nonreturning dependencies, and dependency-specific failures have no visible recovery mechanism here.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests.

1. **Null current object.** With a null current-object reference, the call returns without dereferencing the replacement descriptor or invoking a dependency.

2. **Different discriminator.** With discriminator `0x94`, the object’s selector does not affect branch selection. The function traverses in the specified order rather than performing a direct replacement.

3. **Different selector.** With discriminator `0x95` and unequal 32-bit selectors, the function traverses. A negative value at `+0x28` does not cause a discriminator change on this path.

4. **Negative replacement index.** With discriminator `0x95`, equal selectors, and index `0xffffffff`, only the discriminator is directly changed to `0x5c`. An otherwise unusable replacement descriptor is not directly accessed on this branch.

5. **First replacement entry.** With a matching object and index zero, a valid descriptor selects the first 12-byte entry. Assuming all dependencies return normally and memory remains valid, direct writes and dependency calls occur in the replacement order specified above.

6. **Empty collection.** For a nonmatching object with a non-null collection and count zero or negative, the two linked-object calls and F-dfb0bd02dea5 still precede the collection check. No collection entry is processed.

7. **Mutation affects later traversal.** If processing the first linked object changes the parent’s `+0x0c` field, the second recursive invocation uses the changed field, provided the parent remains readable.

8. **Count changes during iteration.** If processing a collection entry reduces the count to the next index or below, the next loop condition stops traversal. If it increases the count, additional entries can become eligible, subject to valid memory and termination.

9. **Replacement does not recurse immediately.** If a replacement installs non-null child references, this invocation does not traverse them afterward. This criterion makes no claim about processing performed internally by replacement dependencies.

10. **Dependency mutation is visible.** If the first replacement dependency changes source `+0x0c`, the second dependency receives the subsequently read value, not a value captured before replacement began.
