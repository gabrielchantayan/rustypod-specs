# F-7d59cb76c2e6

## Purpose

F-7d59cb76c2e6 performs an ordered sequence of memory mutations using two explicit inputs and three additional entry-state values. It then transfers control through an unresolved indirect dependency.

The supplied static evidence supports a memory-effect contract, not a domain-level interpretation. It does not establish that the routine initializes an object, links records, formats a message, or implements any particular protocol. Repeated stores, mixed-width accesses, overlapping locations, and address-derived byte values are part of the visible behavior and must not be replaced by a cleaner inferred operation.

This contract distinguishes:

- **Established static evidence:** access widths, address relationships, value dependencies, and ordering represented in the supplied material.
- **Inferred intent:** none required for the contract.
- **documented_only:** unresolved calling-convention details, platform-dependent arithmetic, indirect-target behavior, and other facts not established by the evidence.

No runtime tests have been performed.

## Behavior

### Initial publication and repeated stores

The first visible effect is a four-byte store of P at Q plus `0x54`.

The routine then stores x-byte at Y plus `0x19`, stores y-byte at X plus `0x11`, and stores the complete Q value at Y plus `0x34`, in that order.

A long, finite run of repeated stores follows. Each repeated group has the same ordered effects:

| Position within a group | Effect |
|---|---|
| First | Store P as four bytes at D plus `0x54`. |
| Second | Store x-byte at Y plus `0x19`. |
| Third | Store y-byte at X plus `0x11`. |
| Fourth | Store D as four bytes at Y plus `0x34`. |

The repetitions use unchanged input values; they do not traverse an array or advance a pointer.

These repeated writes cannot automatically be collapsed into one group. Repetition can be observable through mapped devices, external observers, or overlapping destinations. Even for ordinary memory, aliasing between a word destination and either byte destination can make group ordering significant.

**documented_only:** this contract does not certify the exact numerical count of repeated groups. It establishes their contents, ordering, fixed destinations, and placement before the remaining accesses. Exact write-count conformance requires an independently verified count.

### Captured values and initial global updates

After the repeated region, the routine captures, in order:

1. A four-byte value from fixed address `0x000000A9`.
2. A four-byte value from P plus `0x74`.

It next writes one byte at fixed address `0x0000003A`. The resulting byte is the low eight bits of twice x-byte plus `0x30`. This is a wrapping byte transformation, not established decimal formatting.

It then captures a four-byte value from Z plus `0x14`, followed by a four-byte value from X plus `0x04`.

All four captures occur after the repeated stores. If the earlier destinations overlap these sources, the captured values reflect those earlier mutations.

For subsequent descriptions, these captured values are called:

- **global snapshot:** the word read from `0x000000A9`.
- **payload snapshot:** the word read from P plus `0x74`.
- **saved Z word:** the word read from Z plus `0x14`.
- **saved X word:** the word read from X plus `0x04`.

These are saved values, not promises that the source locations remain unchanged.

### Cross-location updates

The next group writes x-byte at Z plus `0x0D`, writes byte `0x6C` at X plus `0x08`, and writes y-byte at X plus `0x0D` and X plus `0x09`. It then stores Z as a four-byte value at Z plus `0x54`.

The routine writes the low byte of the global snapshot to fixed address `0x00000067`. It subsequently reads a four-byte signed value from Z plus `0x44`; call this the **shift source**.

Only after that read does it read the byte at `0x00000067` and copy that byte to `0x00000021`. The copy is a read of the location at that point in execution, not an unconditional reuse of the previously written byte.

The shift source then contributes to three ordered effects:

- Its low byte is stored at X plus `0x10`.
- Its full four-byte representation is stored at Y plus `0x54`.
- A byte derived by right-shifting the signed shift source is stored at Z plus `0x01`.

The shift count is the low eight bits of X. The result byte is the low eight bits of the shifted result.

**documented_only:** negative-value right-shift behavior and counts of 32 or greater require target semantics not supplied here. The contract does not assume hardware count masking or define these cases by analogy with another platform.

After the shift-derived byte store, Y plus `0x54` receives X as a four-byte value. Thus the earlier store of the shift source there is transient if execution continues successfully and no later alias changes the location.

### Word transfers and derived destinations

The routine next reads a four-byte value from X plus `0x40`. It then:

- Stores the saved X word at Y plus `0x74`.
- Stores the newly read word at X plus `0x10`.
- Stores Z at Y plus `0x44`.

The word store at X plus `0x10` covers offsets `0x10` through `0x13`, including the earlier byte destination at `0x11`.

Next, the routine reads the byte currently at `0x00000067` and writes it to X plus `0x09`. It writes x-byte at Z plus `0x09`, and stores the global snapshot as four bytes at X plus `0x44`.

It then reads a four-byte address-bearing value from X plus `0x54`; call this **link A**. After that read, it again reads `0x00000067` and writes the resulting byte to X plus `0x09`.

The two copies from `0x00000067` are separate observations. Intervening stores may change that fixed-address byte through aliasing.

The next effects use link A and the saved captures:

- Store the low byte of the payload snapshot at link A plus `0x0D`.
- Restore the saved Z word into Z plus `0x54`.
- Read a four-byte word from X plus `0x14`; call this the **secondary snapshot**.
- Store the low byte of the payload snapshot at Z plus `0x11`.
- Store the low byte of link A at X plus `0x09`.
- Store link A as four bytes at X plus `0x44`.

The secondary snapshot is captured before the following access through Z plus `0x04`.

### Final derived-address effects

A four-byte address-bearing value is read from Z plus `0x04`; call this **link B**.

The routine stores the two-byte value `0x0065` at the address obtained by doubling link B. This is a halfword store, not a byte store of `0x65`. The representation of its two bytes depends on target byte order.

It then reads a four-byte signed value from link B plus `0x64`; call this **link C**.

Next, it stores the low byte of the secondary snapshot at link A plus `0x11`, and stores the four-byte integer value 100 at link A plus `0x54`.

A further four-byte value is read from link B plus `0x74`; this becomes the final outgoing argument. Only afterward does the routine read a four-byte address-bearing value from Z plus `0x64`; call this **link D**.

The final local stores are ordered as follows:

- The low byte of link B goes to Z plus `0x09`.
- Link C goes as four bytes to link D plus `0x54`.
- Link D goes as four bytes to the address obtained by doubling link C.

The doubling of link B and link C is represented using signed 32-bit values. Overflow behavior is not established. Unlike D, these address calculations must not be assigned unsigned wraparound semantics without further evidence.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Disjoint ordinary-memory destinations

Assume all reached accesses are valid, relevant regions do not overlap, arithmetic is supported, and execution reaches the indirect target.

At the end of the repeated region:

- Q plus `0x54` contains P.
- D plus `0x54` contains P.
- Y plus `0x19` contains x-byte.
- X plus `0x11` contains y-byte.
- Y plus `0x34` contains D, replacing the earlier Q value.

This describes that boundary, not the final state after later stores or the dependency.

### Byte truncation

If X has low byte `0xE7`, each repeated write at Y plus `0x19` writes `0xE7`, regardless of the higher bits of X.

The byte transformation at `0x0000003A` produces `0xFE`, because twice `0xE7` plus `0x30` is `0x1FE`, whose low byte is `0xFE`. This does not imply a valid character encoding.

### Unsigned doubling

If X is `0x80000010`, D is `0x00000020`. The repeated word destination is consequently `0x00000074`, subject to target address semantics and access validity.

This example does not resolve signed doubling of link B or link C.

### Overlapping word and byte destinations

Assume little-endian storage, no other relevant aliasing, and that the word read from X plus `0x40` is `0x11223344`.

The subsequent word store at X plus `0x10` places bytes `0x44`, `0x33`, `0x22`, and `0x11` at offsets `0x10` through `0x13`. In particular, it replaces the earlier y-byte at offset `0x11`.

A contract preserving that earlier byte independently would be incorrect.

### Saved value versus later memory

If the saved Z word is `0x55667788`, that captured value is later written to Z plus `0x54` and supplied as outgoing argument 3. These uses do not reread Z plus `0x14`.

Later mutations of the capture’s original location do not change the saved value.

### Invalid first destination

If the initial store at Q plus `0x54` cannot complete, the evidence provides no normal error return and no basis for requiring later stores or the indirect transfer. The precise fault mechanism is platform-dependent.
