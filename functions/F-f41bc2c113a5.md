# F-f41bc2c113a5

## Purpose

F-f41bc2c113a5 coordinates seven indirect operations on a supplied receiver, with a direct call to F-d7185491b9c5 between the fourth and fifth operations.

The established behavior is an ordered sequence of dispatches and argument selections. Several arguments come from external 32-bit data items. Two values are retained across calls, while other values are obtained at later points. This distinction matters if a dependency changes the external data or the receiver’s dispatch state.

The semantic purpose of the operations is unknown. The evidence does not establish that they configure properties, draw elements, register resources, or perform any other particular application-level task.

## Interface

Each indirect operation receives three arguments:

1. The original receiver pointer.

“Primary” and “secondary” describe argument position only. They do not imply application semantics.

F-d7185491b9c5 receives the same receiver pointer as its sole visible argument.

## Behavior

### Ordered operation sequence

The following table describes the arguments to the seven indirect operations. A **retained** value is the value obtained at the earlier capture point, not a later reread.

| Operation | Primary argument | Secondary argument |
|---|---|---|
| 1 | Separate read of the shared-primary item | Read of the initial-secondary item |
| 2 | Retained shared-primary value | Read of the second-secondary item |
| 3 | Retained shared-primary value | Separate read of the pivot item |
| 4 | Read of the fourth-primary item | Retained pivot value |

There is no visible condition that selects or omits an operation. On a normally returning path, all seven indirect operations and the direct dependency call occur.

### Initial capture and first two operations

Before operation 1, the function obtains and retains the shared-primary item’s 32-bit value.

Operation 1 nevertheless uses a separate occurrence of a read from that item for its primary argument. The retained value and operation 1’s argument therefore have distinct read points in the supplied representation. They must not be treated as necessarily identical if the underlying item can change between those reads.

Operation 1 also obtains its secondary argument from the initial-secondary item and resolves the receiver’s current dispatch entry.

After operation 1 returns, operation 2 is dispatched. Its primary argument is the retained shared-primary value. Its secondary argument comes from the second-secondary item at this later stage.

Consequently, changes made by operation 1 can affect operation 2’s secondary argument or dispatch target. They do not, by themselves, replace the retained shared-primary value.

### Pivot capture and operations 3 and 4

After operation 2 returns and before operation 3, the function obtains and retains the pivot item’s value.

Operation 3 uses a separate read of the pivot item as its secondary argument. As with the shared-primary item, the capture and the argument read are distinct in the supplied representation.

Operation 3’s primary argument remains the retained shared-primary value.

After operation 3 returns, operation 4 obtains its primary argument from the fourth-primary item. Its secondary argument is the retained pivot value, not a fresh read of the pivot item.

Thus, a pivot-item change performed by operation 3 may affect external state but does not change operation 4’s secondary argument.

### Direct dependency and final three operations

After operation 4 returns, F-d7185491b9c5 is invoked with the receiver.

After that dependency returns:

- Operation 5 obtains its primary argument from the fifth-primary item and derives its secondary argument from the retained pivot value by subtracting 3.
- Operation 6 uses the retained shared-primary value and obtains its secondary argument from the sixth-secondary item.
- Operation 7 uses the retained shared-primary value and obtains its secondary argument from the final-secondary item.

The late data reads must not be replaced with entry-time snapshots. Earlier dependencies may change the values that these later operations observe.

After operation 7 completes normally, the function returns without producing an explicit result.
