# F-015b24a070ee

## Purpose

F-015b24a070ee performs a bounded, ordered search through records obtained from F-0ff4e60503e7. It selects the first record whose outer discriminator matches a value captured from shared state and whose referenced inner record contains a caller-supplied key. On a match, it copies one 32-bit value from that inner record to a caller-supplied destination.

If no match is found, the function performs no direct write to the destination. It returns no status distinguishing a successful match from exhaustion.

This contract describes the behavior established by the supplied static representation. Record meanings, dependency internals, and application-level intent are not established.

## Behavior

### Shared-state snapshot

Before checking whether any candidates are requested, the function reads the shared discriminator once and retains the resulting 32-bit value for its comparisons.

The function does not directly reload that shared value during the search. If a dependency changes the shared location, later candidates are still compared against the initially captured value.

This is not an atomic snapshot of the surrounding record collection. The function reads candidate fields only as it reaches them.

### Candidate order and lookup arguments

The logical candidate counter begins at unsigned 32-bit zero. Before each lookup, the function compares that counter with the unsigned search bound. If the counter is greater than or equal to the bound, it returns immediately.

Otherwise, it calls F-0ff4e60503e7 with:

1. Argument 2, passed unchanged.
2. The logical counter narrowed to a signed 16-bit value and then widened to a signed 32-bit integer.

The lookup index therefore does not remain a nonnegative 32-bit counter throughout the search:

- Logical counters 0 through 32,767 produce indices 0 through 32,767.
- Logical counters 32,768 through 65,535 produce indices −32,768 through −1.
- Logical counter 65,536 produces index 0 again.
- The index pattern repeats every 65,536 logical candidates.

The supplied representation establishes the narrowing operation and signed extension. The sequence above uses the represented 16-bit truncation interpretation; it should not be treated as a portability guarantee for arbitrary source-language conversion rules.

### Candidate inspection and match selection

After a lookup returns, the function directly reads the outer record’s discriminator at offset 4.

If that discriminator differs from the captured shared value, the candidate is rejected. The function does not directly read the outer record’s inner-address field or any inner-record field for that candidate.

If the discriminator matches, the function:

- Reads the inner-record address from outer offset 8.
- Reads the inner key from inner offset 0.
- Compares that key with argument 4.

A different inner key rejects the candidate. An equal inner key selects it.

For a rejected candidate, the logical counter increases by one and the next bound check occurs. For a selected candidate, the function reads the inner value at offset 4, writes that 32-bit value to the result destination, and returns without another lookup.

Thus the selected result belongs to the first matching candidate in logical lookup order, not necessarily the first occurrence of a distinct lookup index. Repeated indices may yield different records or values if the dependency or surrounding state changes.

### Boundaries and arithmetic

A zero search bound causes no dependency calls and no direct result write. The initial shared-discriminator read still occurs.

If all lookups return normally and no candidate matches, a bound of \(N\) produces exactly \(N\) dependency calls. The logical counters used are 0 through \(N-1\).

The unsigned counter does not wrap during such an exhausted search, even at the maximum bound of 4,294,967,295. The last inspected counter is 4,294,967,294. Its increment reaches 4,294,967,295, and the next bound check returns before another increment.

Equality comparisons test 32-bit values. They do not perform a signed ordering comparison or a range match.

## Side effects

### Direct reads and writes

The function’s direct access order is:

1. Read the shared discriminator.
2. For each reached candidate, call F-0ff4e60503e7.
3. Read that candidate’s outer discriminator.
4. Only on discriminator equality, read the inner-record address and then the inner key.
5. Only on key equality, read the inner value and write it to the result destination.

There is at most one direct destination write. No result initialization, clearing, or failure sentinel is written.

Consequently, “no match leaves the destination unchanged” is valid only when no dependency or external actor changes that storage. The narrower unconditional guarantee is that this function itself performs no destination write on exhaustion.

### Aliasing

The visible body imposes no non-aliasing check on the result destination. If it aliases valid source storage, the selected inner value is read before the destination write. If it aliases the shared discriminator, a successful result write can overwrite that shared location after the search has already captured its comparison value.

Such aliasing does not cause this function to restart the search or inspect another candidate after the write. Whether particular aliases are valid under the underlying memory and type rules is not established.

### Ownership and resource lifetime

The function contains no visible allocation, release, retain, or ownership-transfer operation. It uses dependency-returned addresses and an address obtained from an outer record without an explicit lifetime-management call.

That observation does not establish that F-0ff4e60503e7 allocates nothing, releases nothing, or preserves any object’s lifetime. The records must remain valid for the reads that follow the call.

### Errors and abnormal completion

The function has no explicit error result or recovery path. Invalid addresses, inaccessible memory, misaligned accesses, dependency failures, and concurrent invalidation have no defined handling in the supplied representation.

A dependency that does not return prevents the function from reaching later candidates or its ordinary return. No guarantee of termination is made beyond the finite loop bound when all reached operations complete normally.

## Acceptance examples

These examples are conditional acceptance criteria, not reports of executed tests. Unless stated otherwise, all reached memory accesses are valid, all dependency calls return normally, and no dependency or external actor modifies the illustrated storage.

1. **Empty search.**  
   Given a bound of zero, the function reads the shared discriminator, makes no lookup calls, performs no direct destination write, and returns.

2. **Outer mismatch skips inner storage.**  
   Given a bound of one and a returned outer discriminator different from the captured value, the function makes one lookup with index 0 and returns without directly reading the inner-address field. An unusable address stored in that unvisited field is not itself accessed.

3. **Inner mismatch preserves the destination.**  
   Given a matching outer discriminator but an inner key different from the requested key, the function reads the inner address and key, does not read the inner value for copying, and performs no direct destination write.

4. **First match wins.**  
   Given a bound of three, a rejected first candidate, and a matching second candidate whose inner value is 73, the function calls the dependency with indices 0 and 1, writes 73, and returns. It does not request index 2.

5. **Negative boundary index.**  
   Given a bound of 32,769 and no earlier match, the last lookup receives index −32,768, corresponding to logical counter 32,768. It does not receive positive index 32,768.

6. **Repeated lookup index.**  
   Given a bound of 65,537 and no match, the function makes 65,537 calls. Both the first and last calls receive index 0. No deduplication occurs.

7. **Shared-state change during lookup.**  
   Suppose the captured discriminator is 5 and the dependency changes its shared source location to 9. A returned outer discriminator of 5 still passes the current invocation’s discriminator test; a discriminator of 9 does not pass merely because it is now stored globally.

8. **Unsuccessful search with dependency effects.**  
   Suppose a dependency call writes to storage also used as the result destination, but no candidate matches. The function performs no direct result write. The destination nevertheless reflects the dependency’s change; preserving its entry value is not an unconditional postcondition.
