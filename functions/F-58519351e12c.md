# F-58519351e12c

## Purpose

F-58519351e12c performs a two-stage integer conversion using a caller-supplied mutable state record.

It first delegates conversion to F-d2e82eeae580 with the numeric argument 10. If the resulting cursor identifies a `#` byte before a retained boundary, the delegated result becomes a candidate radix for a second conversion. This second conversion supports radices 2 through 36, an optional leading sign, and digit values obtained through a global-selected lookup table.

The principal observable distinction is:

- Without a qualifying `#`, the function returns the delegated result.
- With a qualifying `#`, the function consumes the marker and returns the suffix conversion’s value or zero.
- Marker consumption occurs even when the candidate radix is invalid or the suffix cannot produce a value.

The apparent intent is a radix-prefixed integer reader. That interpretation is inferred; the first conversion’s exact syntax and error conventions are not established.

### Global data input

Suffix digit lookup depends on a global value that supplies the digit-table base address. For an admitted input byte, the lookup address is formed from that global value plus the byte’s low-seven-bit index. The selected entry is read as a signed 8-bit quantity.

The global value and the memory it selects are separate dependencies:

- Changing the global value can select different table storage.
- Changing table contents can change digit classification without changing the global value.

The supplied body does not establish the global’s declaration width, initialization, lifetime, mutability, or preservation by dependencies.

### Return value

The return value is a signed 32-bit integer:

- The result of F-d2e82eeae580 when no qualifying marker is found.
- The signed suffix value when suffix conversion completes.
- Zero for invalid radix, empty suffix, sign-only suffix, or a scan accepting no digits.

There is no separate local status result. Zero does not distinguish successful conversion of zero from the other zero-return paths.

## Behavior

### Dependency calls and retained boundary

The function first reads the boundary field and calls F-1fe3b1afff2c with the state pointer and that boundary value. No return value from this call is used visibly.

After the call returns, the function reads the boundary field again and retains the resulting address. The reread matters: preservation of the boundary by the first dependency is not assumed.

The function then calls F-d2e82eeae580 with:

1. The state pointer.
2. The retained boundary.
3. The integer 10.

Its signed 32-bit result is retained as both the initial return candidate and the possible suffix radix.

Only after the second dependency returns does the function read the cursor field. Either dependency can therefore affect the cursor used for marker recognition.

The retained boundary is not refreshed after the second call. A later change to the record’s boundary field does not replace this retained value.

No digit-table-base snapshot before either dependency call is visible. The lookup expression obtains its base from the global value on the admitted-byte lookup path, after both calls.

### Marker recognition and commitment

If the cursor is at or beyond the retained boundary, the function returns the initial result without reading a marker byte.

Otherwise, it reads the cursor byte:

- A byte other than `#`, value `0x23`, causes the initial result to be returned.
- A `#` causes the address immediately after the marker to be written to the cursor field.

The marker write occurs before radix validation or suffix inspection. There is no local rollback.

After this write, the function rereads the cursor field to obtain the suffix starting address.

### Suffix eligibility

Suffix processing requires both:

- The post-marker cursor differs from the retained boundary.
- The initial result is strictly greater than 1 and strictly less than 37.

The supported radix interval is therefore exactly 2 through 36.

If either condition fails, the function returns zero. The marker remains consumed, and no final scan-position write occurs.

An invalid radix does not lead to local sign inspection, digit admission, or table lookup.

### Optional sign

At an eligible suffix start, the first byte is examined for `-`, value `0x2D`. If it is not minus, it is examined for `+`, value `0x2B`.

A minus selects negative conversion. A plus selects nonnegative conversion. Any other byte remains the first candidate digit.

A recognized sign advances only the local scanning address. This advance is not immediately written to the record.

If the sign advance reaches the retained boundary, the function returns zero without committing the advance. The stored cursor remains immediately after `#`, pointing at the sign.

If another byte follows the sign, the ordinary scanning path is entered. Its final cursor write commits the sign’s consumption even if that following byte is rejected and no digit is accepted.

### Byte admission and global-based lookup

Candidate bytes are examined in increasing address order, stopping before the retained boundary.

The following byte values are rejected before lookup:

- NUL: `0x00`.
- Horizontal tab: `0x09`.
- Line feed: `0x0A`.
- Form feed: `0x0C`.
- Carriage return: `0x0D`.
- Space: `0x20`.
- Every byte from `0x80` through `0xFF`.

Other byte values from `0x01` through `0x7F` reach the lookup path. In particular, vertical tab, `0x0B`, and DEL, `0x7F`, are not independently rejected by admission.

For an admitted byte:

1. Its low seven bits supply an index from 0 through 127.
2. The lookup expression obtains the table base from the digit-table-base global.
3. The signed byte at that base plus the index is read and extended to an integer.
4. The resulting digit value must be nonnegative and strictly less than the radix.

A negative entry or a digit value equal to or greater than the radix stops conversion. The rejecting byte is not consumed.

Because high-bit input is rejected before lookup, masking does not make such input an alias for an ASCII byte.

The function does not establish the table’s character mapping. Decimal and alphabetic digit conventions must not be assumed. Nor is a fixed table base established independently of the global: dependency changes to that global can affect subsequent lookup selection.

### Accumulation, termination, and final write

The accumulator starts at zero. For each accepted digit, the mathematical update is

\[
A_{\text{next}} = rA + d,
\]

where \(r\) is the candidate radix and \(d\) is the signed-byte-derived, nonnegative digit value.

After an accepted digit, scanning advances one byte. Scanning stops at the retained boundary or at the first rejected byte.

No minimum digit count is required. Rejecting the first candidate leaves the accumulator at zero.

After scanning, a negative sign causes negation of the accumulator. The current scanning address is then written to the cursor field, and the value is returned.

Thus, the final cursor identifies either the first unconsumed byte or the retained boundary. This final write occurs even when no digits were accepted, provided execution reached the ordinary scanning path.

### Integer limits

The initial result, radix, accumulator, extended digit value, and return value use the recovered signed 32-bit integer representation.

There is no visible overflow check, saturation, range-error return, or overflow status. The recurrence and sign application establish results when all intermediate operations are representable.

If multiplication, addition, or final negation exceeds the signed 32-bit range, a portable result is not established by the supplied source. In particular, 32-bit representation alone does not justify promising wraparound. Such behavior remains documented_only.

## Side effects

### Direct writes

The visible body writes the cursor field:

1. Immediately after recognizing `#`, to commit marker consumption.
2. After an ordinary suffix scan, to commit the final scanning position.

The second write does not occur for invalid radix, empty suffix, or sign-only early returns.

No separate direct writes to the boundary field, input bytes, digit-table-base global, or table entries are visible. This statement describes access targets; it does not establish non-aliasing between supplied storage regions.

### Significant read and call order

The established local order is:

1. Read the boundary for the first dependency call.
2. Call F-1fe3b1afff2c.
3. Reread and retain the boundary.
4. Call F-d2e82eeae580.
5. Read the cursor.
6. If the cursor precedes the retained boundary, read the possible marker.
7. On `#`, write the advanced cursor and reread it.
8. If suffix processing is eligible, inspect the first suffix byte for a sign.
9. During scanning, read each candidate byte.
10. For an admitted byte, use the digit-table-base global to form the selected entry address, then read that signed-byte entry.
11. After scanning and sign application, write the final cursor.

The global-base access belongs to the admitted-byte lookup path, not to initialization before the dependencies. A locally rejected byte does not cause a lookup through this expression.

Sign inspection can read the first suffix byte more than once. An unsigned first digit can also be read again during scanning. The body does not establish reliable semantics for concurrent mutation or volatile storage, nor an exact machine-level load count.

## Acceptance examples

These are conditional acceptance criteria from static inspection, not executed tests. Unless stated otherwise, they describe state after both dependency calls, use a valid retained boundary, and avoid arithmetic overflow.

1. **No remaining bytes.** If the cursor equals the retained boundary and the initial result is 17, return 17 without reading a marker or locally writing the cursor.

2. **No marker.** If the cursor points to `;` before the retained boundary and the initial result is 12, return 12 without a local cursor write.

3. **Invalid radix.** With initial result 1 and remaining bytes `#10`, return zero and leave the cursor immediately after `#`. No local suffix or table lookup occurs. Results 37 and negative values are also invalid radices.

4. **Empty suffix.** With initial result 16 and a final `#`, consume the marker, return zero, and leave the cursor at the boundary.

5. **Sign-only suffix.** With initial result 16 and remaining bytes `#-`, return zero and leave the cursor at `-`. A final plus behaves analogously.

6. **Conditional successful conversion.** Suppose the base selected during lookup identifies readable entries mapping `1` to 1 and `A` to 10. With initial result 16 and remaining bytes `#1A`, return 26 and place the cursor at the boundary.

7. **Negative conversion.** Under the same lookup assumptions, `#-1A` with initial result 16 returns −26 and ends at the boundary.

8. **Digit equal to radix.** If the selected entry maps `2` to 2, initial result 2 with `#2` returns zero and leaves the cursor at `2`.

9. **Rejecting byte after sign.** With initial result 10 and `#- `, return zero and leave the cursor at the space. The sign advance is committed, unlike the sign-only case.

10. **Whitespace termination.** If `1` maps to 1, initial result 10 with `#1 2` returns 1 and stops at the space. The later `2` is not examined by the suffix scan.

11. **High-bit rejection.** A first candidate byte of `0xB1` stops conversion without a local lookup for index `0x31`. Dependency accesses remain outside this assertion.

12. **Vertical tab classification.** If the selected entry for `0x0B` is −1, it stops conversion. If it is 3 and the radix is 8, that byte is accepted as digit value 3.

13. **Dependency changes the table base.** Suppose the global initially selects a table mapping `A` to 1, but a dependency changes it before returning to select a table mapping `A` to 10. If that latter base remains in effect during lookup, initial result 16 with `#A` returns 10, not 1. No pre-call base snapshot is visible.

14. **Lookup storage not needed on a local early path.** If the initial result is returned because no marker is present, the local body does not access the digit-table-base global or an entry. This does not establish that the dependencies avoided those accesses.
