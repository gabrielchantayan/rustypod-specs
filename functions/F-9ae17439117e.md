# F-9ae17439117e

## Purpose

F-9ae17439117e conditionally updates a state object obtained from dependency F-7fba0909c452. A 32-bit selector chooses either a single-word assignment or a three-word assignment accompanied by a derived boolean flag.

An unrecognized selector does not update those selected fields. Instead, it records value `0x500` in the state object's first word, but only if that word is currently zero.

The state lookup occurs before any input-data access. If it returns a null pointer, this function returns immediately.

These behaviors are established by the supplied static representation. The meanings of the selectors, stored words, flag, and error value are not established. Treating them as particular application settings or naming `0x500` as a particular standardized error would require additional evidence.

## Behavior

### 1. Obtain the state object

The function first calls F-7fba0909c452.

If its result is null, the function returns without reading the selector's input data and without making any of the state accesses listed above. This does not imply that the dependency itself has no side effects.

If its result is non-null, the function reads the first 32-bit input element before selecting a branch.

### 2. Single-word selectors

For the following selectors, the initially read input word is written to the corresponding state location:

| Selector | Destination byte offset |
|---|---|
| `0x8126` | `0x8E4` |
| `0x8127` | `0x8E8` |
| `0x8128` | `0x8EC` |

The function then returns. It does not explicitly inspect the status word, write the derived boolean, or read additional input elements on these branches.

The input value is copied without range checks, conversion, clamping, scaling, or normalization. Negative values and other 32-bit patterns receive no special treatment.

### 3. Three-word selector

For selector `0x8129`, the supplied representation establishes this access order:

1. Write the first input word, already read before dispatch, to state offset `0x8F0`.
2. Read the second input word and write it to state offset `0x8F4`.
3. Read the third input word and write it to state offset `0x8F8`.
4. Read the first input word again.
5. If that reread equals `0x10000`, read the second input word again.
6. If the reread first word equals `0x10000` and the reread second word equals zero, read the third input word again.
7. Write the derived boolean at state offset `0x8FC`, then return.

The boolean is **false** exactly when the values observed during this second, conditional inspection are:

- first word: `0x10000`;
- second word: zero;
- third word: zero.

It is **true** otherwise.

The inspection short-circuits:

- If the reread first word differs from `0x10000`, the boolean inspection does not reread either remaining word.
- If the reread first word is `0x10000` but the reread second word is nonzero, it does not reread the third word.

These conditional rereads are separate from the reads needed to copy all three words. Every successful execution of this branch reads all three input elements for copying.

Only one byte at `0x8FC` is explicitly assigned as a boolean. The supplied representation does not specify a wider-word replacement at that location.

### 4. Unrecognized selectors

For every other selector, the first input element has already been read.

The function then reads the 32-bit state word at offset `0x000`:

- If it is zero, the function writes `0x500` there.
- If it is nonzero, the function leaves it unchanged.

The function then returns. There are no explicit writes to the selected value fields or derived boolean on this branch.

This behavior preserves an existing nonzero status rather than overwriting it. It does not establish that the status word is an error queue, that `0x500` has any particular external name, or that some other operation later clears it.

### Aliasing and changing input

The function does not snapshot the three input words before updating state. Reads and writes are interleaved.

If input storage overlaps the state object, earlier state writes can affect later input reads. In particular, the boolean is based on the later input reads, not on rereading the three destination fields and not necessarily on the values initially copied.

Consequently, the simple description “copy a triple and flag whether that triple differs from `(0x10000, 0, 0)`” is valid only when the relevant input values remain stable throughout the operation.

No explicit non-aliasing check or restriction appears in the supplied representation. Whether a particular overlapping layout is valid under the original language's object and aliasing rules remains unspecified.

These examples are conditional expectations derived from static evidence, not observed test results. Unless otherwise stated, they assume valid, stable, non-overlapping input and state storage and a non-null state result.

### Single-word assignment

### Unrecognized selector with clear status
