# F-402eef64af83

## Purpose

F-402eef64af83 is a predicate over a signed threshold and a signed integer held in indirectly addressed storage.

For a normally completing invocation, the return value is **one if the threshold is nonnegative and the stored integer is strictly greater than the threshold; otherwise, it is zero**.

The first argument supplies an address-bearing integer, not the value to compare. The relevant storage begins at the address obtained by adding the numeric displacement four to that argument.

A negative threshold disables the storage access. A zero threshold enables it.

**Established static evidence:** the signed eligibility and comparison rules, displaced storage access, and zero-or-one result.

**Inferred intent:** the function may test whether an object-associated quantity exceeds a limit. The evidence does not identify an object type, quantity, unit, or application-level meaning.

## Behavior

### Predicate semantics

Negative thresholds are unconditional rejection cases and do not consult the stored value. This includes the minimum representable signed threshold; no magnitude conversion or negation is needed.

For every nonnegative threshold, the function obtains the integer at the displaced location and applies signed, strict ordering:

- A smaller stored value is rejected.
- An equal stored value is rejected.
- A larger stored value is accepted.

A negative stored value therefore cannot be accepted against an eligible threshold. Treating its representation as a large unsigned number would violate the contract.

Zero is an ordinary eligible threshold. A stored value of zero is rejected; a positive stored value is accepted.

The maximum representable threshold is also eligible. No same-type signed integer can exceed it, so its normal result is always zero. Nevertheless, it does not suppress the represented storage read.

### Storage selection

The comparison value comes from the location displaced by four from the address carrier.

The contract does not require the undisplaced address to be read, nor does it require intervening storage to be examined. Readability of the undisplaced location alone does not establish that the required displaced read is valid.

The evidence identifies no enclosing record layout beyond this one access. It does not establish:

- Whether the carrier denotes an allocation base or an interior address.
- The identity or size of any preceding field.
- The extent of an enclosing allocation.
- The meaning of the retrieved integer.
- Whether the storage is ordinary memory or a special mapping.

For valid invocations, the carrier’s numeric value has no independent role in the predicate result. Two carriers with the same signed value at their respective displaced locations produce the same result for the same threshold.
