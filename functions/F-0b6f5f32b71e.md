# F-0b6f5f32b71e

## Purpose

F-0b6f5f32b71e conditionally finalizes a mutable context, serializes selected context words into a caller-provided destination, and overwrites the first 96 context bytes with a deterministic pattern.

The block size, length trailer, and word serialization suggest a digest-finalization role. That interpretation is inferred intent, not an established algorithm identity. The supplied evidence does not establish a particular digest algorithm, the meaning of the encoded bytes, or the contracts of the dependencies.

Two paths bypass ordinary finalization:

- A zero destination value returns a global 32-bit value without accessing the context.
- Under a particular context mode and flag, F-d8a13f219e81 can return a nonzero value that is immediately returned to the caller.

On the ordinary path, the function returns zero. This is not an independently established success guarantee: unsupported modes also reach that return value.

## Interface

Two global 32-bit values are relevant:

- **Zero-destination result:** read only when the destination argument is zero.

### Storage and ownership preconditions

For ordinary operation, the context must support the reads and writes described below. For supported output modes, the destination must support every four-byte output group actually reached.

No allocation or explicit release occurs directly in this function. No ownership transfer is established. Dependency ownership, retention, allocation, and release behavior remain unknown.

Destination/context overlap is not checked. Non-overlap is the safe precondition for interpreting output as a stable serialization of context state. With overlap, output writes can change future reads, and the final overwrite can destroy emitted bytes.

## Behavior

### 1. Zero-destination path

The function first determines whether the destination value is zero.

If zero, it reads the zero-destination result global and returns that 32-bit value immediately. It does not directly read or write the context, call either dependency, serialize output, or perform the final overwrite.

Consequently, an otherwise invalid context value is not dereferenced on this path.

### 2. Conditional preliminary operation

For a nonzero destination, the function examines the context control word.

F-d8a13f219e81 is called only if both conditions hold:

1. The low byte of the control word is `2`.
2. Bit `0x100` is set.

The low-byte comparison precedes the flag test. The supplied representation shows separate control-word reads for these tests; it does not establish an atomic snapshot.

The call receives the context and a zero second argument.

- A nonzero return value is returned immediately and unchanged.
- A zero return value allows ordinary processing to continue.

If this call returns nonzero, no subsequent block padding, output serialization, or deterministic context overwrite is performed directly by this function. Effects already produced by the dependency are not undone.

If the call returns zero, subsequent context reads observe whatever state exists after that call. No preservation of fields or globals by the dependency may be assumed.

### 3. Block marker and padding

The function reads the 32-bit field at offset 68 and masks it with `0x3f`. The resulting block position is therefore between 0 and 63.

It writes byte `0x6c` at that position, then considers the following position.

- If that following position is greater than 56, remaining bytes through offset 63 are filled with `0xec`. F-fc23781a6360 is then called with the context address as both arguments. Processing resumes with a fill position of zero.
- Otherwise, no preliminary block-processing call occurs.

The function next fills from the current fill position through offset 55, inclusive, with `0xec`.

Boundary behavior follows directly:

- An initial position of 55 places the marker at 55 and leaves no further bytes to fill before the trailer.
- An initial position of 56 requires an additional block-processing call.
- An initial position of 63 places the marker at 63, performs no trailing fill in that block, and still requires the additional call.

The initial block position is captured before the optional block-processing call. Trailer values and mode, however, are read afterward. The dependency therefore can affect trailer construction.

### 4. Eight-byte trailer

After padding, the function reads the control word again and selects its low byte.

Define the byte transform

\[
E(x)=(157x+236)\bmod 256.
\]

This is the low-byte result of multiplying a byte by −99 and subtracting 20. It produces \(E(0)=\texttt{0xec}\).

For describing the trailer, let \(H\) and \(L\) denote the 32-bit fields at offsets 64 and 68. If these fields remain stable throughout the trailer writes, define

\[
T=((H\cdot 2^{32}+L)\cdot 8)\bmod 2^{64}.
\]

The trailer is placed at offsets 56–63:

- **Mode 1:** apply \(E\) separately to the eight bytes of \(T\), ordered least significant byte first.
- **Mode 2:** apply \(E\) separately to the eight bytes of \(T\), ordered most significant byte first.
- **Other modes:** do not write a trailer.

The stable-field description is not a promise that the function takes a single counter snapshot. The evidence shows fresh counter reads for successive trailer-byte calculations. Bytes are written in ascending destination-offset order. Within the cross-word byte calculation, the relative ordering of the two field reads is not established.

The multiplication by eight is a 64-bit bit-length construction with truncation: the highest three bits of the combined counter do not appear in the trailer. This description does not establish what units the counter originally represents.

For unsupported modes, offsets 56–63 retain whatever contents result from the marker, padding, prior context contents, and any preceding dependency call. They are not replaced with a validated or default trailer.

### 5. Final block processing

F-fc23781a6360 is called unconditionally after the trailer-selection stage, again with the context address supplied as both arguments.

Thus the ordinary path makes:

- One call to F-fc23781a6360 when the initial block position is 0–55.
- Two calls when the initial block position is 56–63.

Any return value from this dependency is ignored. No direct error branch follows it.

The output multiplier global is read after this final call. The control word is then read again to select output mode. These values are not assumed to match values that existed before the call.

### 6. Output serialization

Only post-call modes 1 and 2 produce output.

The output offset starts at zero. Before each four-byte group, the function rereads the unsigned 32-bit bound at context offset 96. If the current offset is less than that bound, it:

1. Reads one 32-bit word from context offset \(72+\text{output offset}\).
2. Multiplies that word by the retained output multiplier.
3. Emits four transformed bytes of the resulting 32-bit word.
4. Advances the output offset by four.

For each group, all four destination bytes are written, in ascending destination-address order.

- **Mode 1:** bytes of the product are emitted least significant first, each transformed by \(E\).
- **Mode 2:** bytes are emitted most significant first, each transformed by \(E\).
- **Other modes:** the serialization loops are skipped.

The product is consumed as a 32-bit bit pattern. For inputs whose signed multiplication overflows, the supplied representation does not by itself settle the original language’s overflow semantics. Treating the product modulo \(2^{32}\) describes the apparent fixed-width operation, but overflow cases require target-level confirmation.

The mode is selected before entering its loop; it is not reread for each group. In contrast, the bound is reread for every loop condition. A source word is read and multiplied once per group, before any of that group’s four writes.

For a stable bound \(n\), with ordinary nonwrapping addressing:

- \(n=0\) writes no output.
- Positive \(n\leq\texttt{0xfffffffc}\) writes \(4\lceil n/4\rceil\) bytes.
- A bound not divisible by four does not produce a partial final word.
- A stable bound above `0xfffffffc` never becomes less than or equal to the offset: the unsigned offset eventually wraps to zero. Successful termination is therefore not established, even if earlier memory accesses were somehow valid.

No bound validation restricts serialization to a particular number of state words.

### 7. Final deterministic overwrite

After serialization, or immediately after skipping serialization for an unsupported mode, the function overwrites context offsets 95 down to 0.

For overwrite step \(j\), where \(j\) ranges from 0 through 95:

\[
b=(200+j)\bmod256,
\]

and the byte written at offset \(95-j\) is

\[
((b\mathbin{\mathrm{xor}}\texttt{0xba})\cdot((b+17)\bmod256))\bmod256.
\]

The first write is `0xa2` at offset 95. The last is `0x58` at offset 0.

This overwrites the block area, both counter fields, and the six 32-bit words at offsets 72–95. It does not directly overwrite the bound at 96 or the control word at 100.

The function then returns zero.

## Side effects

The observable direct mutation order on the ordinary path is:

1. Optional effects of F-d8a13f219e81.
2. Marker byte.
3. Any fill through the end of the first block.
4. Optional first call to F-fc23781a6360.
5. Fill through offset 55.
6. Mode-dependent trailer writes.
7. Final call to F-fc23781a6360.
8. Destination writes, if the resulting mode is supported.
9. Descending overwrite of context bytes 95–0.

There is no rollback or transactional behavior.

The overwrite is deterministic, not random and not a zero-fill. Calling it secure erasure would require evidence beyond the supplied material.

Overlapping destination and context can alter source words, the repeatedly read output bound, or retained context fields. The final overwrite can also erase output that aliases offsets 0–95. No alias-safe copy is present.

Invalid addresses, insufficient storage, alignment failures, dependency failures other than the explicit nonzero preliminary return, and external interruption have no specified recovery behavior.

## Acceptance examples

These are conditional acceptance criteria, not runtime observations.

1. **Zero destination:** Given a zero destination and a zero-destination global value of `0x12345678`, the result is `0x12345678`. The context is not directly accessed.

2. **Delegated early return:** Given initial mode 2 with bit `0x100` set, if F-d8a13f219e81 returns `7`, the function returns `7`. No later direct padding, serialization, or overwrite occurs.

3. **Padding boundary at 55:** If the lower counter’s low six bits are 55 when read, the marker is written at offset 55. No preliminary block call occurs; the final block call still occurs.

4. **Padding boundary at 56:** If those bits are 56, the marker is written at 56, offsets 57–63 receive `0xec`, and the preliminary block call occurs. Offsets 0–55 are then filled with `0xec` before trailer processing.

5. **Trailer byte order:** With stable counters \(H=0\), \(L=1\), mode 1 yields trailer bytes `d4 ec ec ec ec ec ec ec`. Mode 2 yields `ec ec ec ec ec ec ec d4`. These are bytes presented to the final dependency, not necessarily bytes remaining after return.

6. **Output word order:** If the final dependency leaves a source word `0x01020304` and the captured multiplier is 1, mode 1 emits `60 c3 26 89`; mode 2 emits `89 26 c3 60`.

7. **Nonmultiple bound:** With stable bound 5, sufficient nonoverlapping storage, and supported mode, two complete words are emitted: eight bytes, not five.

8. **Unsupported mode:** If the mode remains unsupported at both later mode reads, no trailer or output bytes are written by those stages. The final block call and descending context overwrite still occur, followed by return zero.

9. **Overwrite endpoints:** On a normally completed ordinary path, direct overwrite writes offset 95 before offset 0, leaving those bytes as `0xa2` and `0x58`, respectively.
