# F-4fd3a319e04e

## Purpose

The supplied static representation describes a routine that interleaves unresolved calls with computed-address word stores and byte accesses, then enters a loop with no represented exit.

No application-level purpose is established. The evidence does not identify a serializer, allocator, device operation, decoder, or collection interface. This contract therefore describes represented dataflow, access widths, ordering, argument propagation, and state transitions without assigning a domain-specific meaning.

The representation includes warnings about invalid instruction data and omitted unreachable regions. Statements below describe its represented behavior, not verified executable behavior. No runtime tests have been performed.

Some displayed intermediate arithmetic uses signed types. Modular formulas here express the intended bit-level interpretation of the represented operations; they do not establish defined signed-overflow or signed-left-shift behavior in a reconstructed high-level language.

## Behavior

### Ordering and terminology

Stages below occur in order, provided preceding accesses and calls complete.

A **four-call run** consists of four consecutive calls displayed without explicit arguments. Unless stated otherwise, its **result** means the fourth call’s primary result. The first three calls still occur and may have effects.

“No explicit arguments” does not establish a zero-argument ABI. Unused primary results do not imply effect-free calls.

Each dependency may modify accessible memory. Direct accesses separated by calls remain distinct observable operations. Values described as retained follow the representation’s dataflow; this does not independently prove that the executable calling convention preserves the corresponding physical state.

### Initial word publication

The routine first stores the payload at:

**low32(4 × index + 0x14).**

This 32-bit store precedes every represented call.

The first dependency receives four arguments, in order:

1. low32(4 × index);
2. the original index;
3. the original control word;
4. low32(8 × ambient word).

Its target is formed using the incoming link-register value.

The next operations are:

1. A no-explicit-argument call supplies a result, which another dependency receives as its single displayed argument.
2. Another such call supplies a result, which another dependency receives together with the ambient word logically shifted right by eight bits.
3. A four-call run occurs.
4. The original payload is stored again at the original computed address.
5. A dependency receives low32(four times that run’s result).

The second payload store is observable even when it writes the same bits. Intervening dependencies may have observed or modified the destination.

### Ambient-word and scaled-result publications

A new four-call run produces a result. Retain **scaled value A**, equal to low32(four times that result).

The routine stores scaled value A at low32(sixteen times the result + 0x14). A dependency then receives scaled value A and low32(eight times the ambient word).

Two exchanges follow:

- A no-explicit-argument result is forwarded as one displayed argument.
- Another result is forwarded together with the ambient word shifted right by eight bits.

A further four-call run occurs. The routine stores scaled value A at:

**low32(8 × ambient word + 0x14),**

then forwards low32(four times the latest run’s result).

Another four-call run supplies a result whose fourfold value is stored at its sixteenfold address plus 0x14, with both calculations reduced to 32 bits.

The next dependency receives:

1. low32(8 × ambient word);
2. that same value again;
3. ambient word shifted right by eight bits;
4. original control word shifted right by fourteen bits.

The fourth argument follows two successive logical shifts by seven bits. It is not the original control word shifted by seven or twenty-one bits.

After another four-call run, the routine stores low32(eight times the ambient word) at that value plus 0x14. It then forwards low32(four times the run’s result).

### Secondary-register-derived publication

Another four-call run occurs. Its final call is followed by consumption of the unresolved secondary-register result, called **secondary value** below. The surrounding representation does not use that final call’s primary result for this publication.

The routine computes and retains:

**secondary publication = low32(secondary value × 0x01000000).**

It stores that value at:

**low32(secondary value × 0x04000000 + 0x14),**

then passes the stored value to a dependency.

After another four-call run, the same retained secondary publication is stored at low32(four times the new result + 0x14). A dependency then receives low32(four times that result).

No bounds check or address validation is represented.

### Further word publications and retained address seed

A new four-call run supplies a result. Retain **scaled value B**, its fourfold value reduced to 32 bits. Store scaled value B at the result’s sixteenfold address plus 0x14, then pass scaled value B to a dependency.

Two exchanges follow, each obtaining a no-explicit-argument result and forwarding it as one displayed argument.

After another four-call run:

- Store scaled value B at low32(four times the latest result + 0x14).
- Forward low32(four times that result).

A subsequent four-call run produces a result whose fourfold value becomes the **address seed**. The routine stores this seed at the result’s sixteenfold address plus 0x14, then passes the seed to a dependency.

Two more one-argument result-forwarding exchanges follow.

After another four-call run, the routine stores the ambient word shifted right by sixteen bits at low32(four times the latest result + 0x14). It then forwards low32(four times that result).

A further four-call run supplies a result from which the routine retains:

**retained base = low32(sixteen times the result).**

It stores the result’s fourfold value at low32(retained base + 0x14). The next dependency receives:

1. retained base;
2. retained base again;
3. ambient word shifted right by fifteen bits.

After another four-call run, retained base itself is stored at low32(retained base + 0x14). This is the same directly calculated destination as the preceding store, although intervening calls may have modified it. The routine then forwards low32(four times the latest result).

### First byte-publication phase

Define the **early lookup address** as:

**((address seed AND 0x7fffffff) shifted right by seven bits) + 1.**

A further four-call run produces the **first byte source**.

The routine reads an unsigned byte at the early lookup address, then stores low8(four times the first byte source) at:

**the byte just read + 0x11.**

The destination therefore lies between 0x11 and 0x110 inclusive. This is a destination selected by an 8-bit value, not a pointer-sized pointer read.

A dependency receives three identical arguments, each low32(four times the first byte source). A no-explicit-argument result is then obtained and forwarded to another dependency.

After a four-call run, the routine rereads the byte at the early lookup address. At the destination selected by this new read, it stores:

**low8((first byte source AND 0x3fffffff) shifted right by twenty bits).**

The retained first byte source supplies this byte. The intervening run supplies a separate result, whose fourfold value is forwarded afterward.

### Second byte-publication phase

Another four-call run produces the **second byte source**.

The routine performs these accesses in order:

1. Store low8(four times the second byte source) at **(ambient word shifted right by twenty-three bits) + 0x1c**.
2. Read the unsigned byte at the early lookup address.
3. Store zero at the byte just read + 0x11.

The direct destination in step 1 lies between 0x1c and 0x21b inclusive.

A dependency receives the ambient word shifted right by twenty-three bits. A no-explicit-argument call follows; its primary result is not forwarded by the displayed surrounding operations. Another dependency receives:

**(second byte source AND 0x3fffffff) shifted right by six bits.**

After a four-call run, the routine rereads the early lookup byte and stores zero at its currently selected destination. It then forwards low32(four times that run’s result).

The early lookup reads cannot be merged into one cached read. Dependencies or earlier direct stores may change the lookup byte, including through address overlap.

### Establishing the final lookup and loop state

Another four-call run supplies a result. From it, retain the **loop shift state**:

**(result AND 0x3fffffff) shifted right by twenty-five bits.**

Its initial range is 0 through 31.

Independently, retain the **final lookup address**:

**low32(low32(second byte source × 4) × 0x400 + 1).**

This address derives from the second byte source, not from the loop’s carried value. The represented loop never updates its address-forming value.

The routine reads an unsigned byte at the final lookup address and stores zero at the byte just read + 0x11.

A dependency receives twice the initial loop shift state. A following no-explicit-argument call supplies the initial **carried value**. That dependency result is separate from both the second byte source and the result used to initialize the loop shift state.

### Repeated loop behavior

Each iteration performs the following ordered operations:

1. Call a dependency with the current carried value and the current loop shift state logically shifted right by eight bits.
2. Perform a four-call run.
3. Read an unsigned byte at the retained final lookup address.
4. Store zero at the byte just read + 0x11.
5. Forward low32(four times the preceding run’s result).
6. Perform another four-call run.
7. Replace the carried value with low32(four times the final run’s result).
8. Replace the loop shift state with low32(that same result shifted left by twenty-six bits).
9. Repeat without an exit test.

**The final lookup address remains unchanged by these carried-value and shift-state updates.** Every iteration nevertheless performs a fresh byte read there. Dependencies or direct stores may change the byte, so successive zero stores may select different destinations despite using the same lookup address.

The first iteration’s second opening-call argument is necessarily zero because the initial loop shift state is at most 31. On later iterations it equals the preceding final result’s low six bits shifted left by eighteen bits. Its possible values are therefore multiples of 0x00040000, up to 0x00fc0000.

The represented target-forming state for the opening call differs between initial entry and subsequent iterations. Identical dependency identity across those cases is not established.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume the relevant calls and accesses complete under the stated 32-bit interpretation.

1. **Initial publication precedes calls.** With index 3, the first direct store writes the 32-bit payload at 0x20. The later payload publication writes there again.

2. **Control shifting uses fourteen bits.** With control word 0x80000000, the later four-argument dependency receives 0x00020000 as its fourth argument.

3. **Ambient shifts retain unsigned semantics.** With ambient word 0x12345678, its right shifts by eight, fifteen, sixteen, and twenty-three bits are respectively 0x00123456, 0x00002468, 0x00001234, and 0x00000024.

4. **Byte selection is not pointer loading.** A lookup byte of 0x7f selects destination 0x90. A subsequent lookup byte of 0x02 selects 0x13.

5. **Byte truncation applies.** A first byte source of 0x00000041 produces 0x04 for its first byte publication.

6. **Final lookup address survives carried-value changes.** With second byte source 1, the final lookup address is 0x1001. If the initial carried value is 7 and an iteration’s final result is 3, the next carried value is 12. Both iterations still read their lookup byte at 0x1001.

7. **A retained address does not imply a retained byte.** If successive reads at that same final lookup address yield 0x7f and 0x02, the corresponding loop stores clear 0x90 and 0x13. The changed selection does not imply an address update.

8. **Lookup arithmetic wraps at 32 bits.** With second byte source 0x00100000, its fourfold value is 0x00400000. Multiplication by 0x400 wraps to zero, making the final lookup address 1.

9. **Loop argument state changes independently.** The first iteration’s second opening-call argument is zero. If an iteration’s final result is 1, the next shift state is 0x04000000 and the following second argument is 0x00040000. Neither update changes the final lookup address.

10. **No finite normal completion is represented.** Once the loop is reached, returning calls and completing accesses do not produce a normal return after any finite iteration count.
