## Behavior

### Interpretation and descriptive quantities

The following names describe relationships, not source identifiers or additional state:

- **Selector:** the unsigned 32-bit representation of the first argument after its represented signed right shift by 23.
- **Lookup displacement:** selector bitwise-OR `0x88`.
- **Adjusted selector:** selector minus `0x38`, modulo \(2^{32}\).
- **Masked displacement:** selector minus `0xE0`, modulo \(2^{32}\), then bitwise-AND `0x7FFFFFFF`.
- **Half displacement:** masked displacement logically shifted right by one.
- **Halfword-region address:** twice the result of selector minus `0xE0`, with both operations using unsigned 32-bit arithmetic.
- **Unresolved word address:** the signed field read from fourth argument plus `0x28`, shifted left by two and then right by 32.
- **Dependency-derived base:** the F-e47d7b2e9c88-associated value, interpreted as signed 32 bits and shifted right by 32.

The last two quantities are unresolved. A right shift by 32 of a 32-bit value does not supply a portable result. The signed left shift used in the unresolved word address introduces a further arithmetic limitation.

Under the represented arithmetic-right-shift interpretation, nonnegative first arguments produce selectors from `0` through `255`; negative arguments produce `0xFFFFFF00` through `0xFFFFFFFF`. The selector is not an unsigned eight-bit index.

Masked displacement is at most `0x7FFFFFFF`; half displacement is at most `0x3FFFFFFF`.

## Acceptance examples

These are conditional static expectations, not runtime observations. Unmentioned accesses must succeed and avoid unintended interference.

1. **Argument truncation.** If the second argument’s low 16 bits are `0xABCD`, the first represented write stores those 16 bits. Its address uses the full second argument, not its truncated halfword.

2. **OR-based displacement.** Selector `0x08` produces lookup displacement `0x88`, not `0x90`.

3. **Unreferenced argument.** Changing only the third argument introduces no explicit data-flow change in the representation. This does not establish the machine-level calling convention.

4. **Intervening aliasing.** With selector `0x80`, context base `0x64`, and fourth argument `0xB8`, fourth argument plus `8`, selector plus `0x40`, and context base plus `0x5C` all equal `0xC0`. With otherwise noninterfering accesses, the linked-value store there is overwritten by `0xB8`; the later context-field read obtains `0xB8`. Expecting the linked value requires absence of **all intervening overlapping writes**, not merely absence of faults or external modification.

5. **Early terminal branch.** A negative F-e47d7b2e9c88-associated value reaches the first invalid-instruction boundary only after the marker store at dependency-derived base plus `4`, assuming preceding effects succeed.

6. **Signed halfword conversion.** On the continuing branch, a halfword read of `0x8000` yields a word payload of `0xFFFFFFFF` at dependency-derived base plus `8`; `0x7FFF` yields zero.

7. **Small-offset selection.** Associated-value bit `2` clear selects `0x58` and destination `0x170`; bit `2` set selects `0x5C` and destination `0x180` for the corresponding half-displacement word store.

8. **Scaled-pointer reread.** If the read used to form the destination following the self-addressed store returns `0x240`, the half-displacement write targets `0x244`, regardless of the scaled pointer originally assigned to the global.

9. **Reset reread.** If reset-halfword storage returns `0x1234` when read for the final composite, the constructed value is `0x1234EA70`, even if an earlier assignment supplied a different upper halfword.

10. **Final ordering and termination.** The assignment carrying `0x5C` follows the self-address assignment and reset composite assignment. Successful completion of all represented accesses still leads to the second invalid-instruction boundary, not a normal return.
