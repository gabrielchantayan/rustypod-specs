# F-7343695e1968

## Purpose

F-7343695e1968 performs an ordered sequence of low-level memory reads and writes, then invokes an unresolved indirect target. The supplied static representation establishes memory effects but does not establish an application-level purpose.

The behavior includes overlapping byte and word writes, addresses derived by multiplying input values, repeated writes to the same locations, reads from low absolute addresses, and a final transfer with four arguments. It must not be described as a conventional object initializer, formatter, container operation, or ownership operation without additional evidence.

This contract distinguishes:

- **Established static evidence:** accesses, widths, values, and ordering visible in the supplied representation.
- **Inferred intent:** none required to describe the observed sequence.
- **documented_only:** facts that cannot be resolved from that representation, including the true calling convention, target-machine arithmetic in exceptional cases, and the indirect target’s behavior.

No runtime tests have been performed.

## Behavior

### Initial publication and index selection

The initial operations are ordered and alias-sensitive.

First, a word containing the fourth input is written at Context C `+0x44`. A byte is then read at Context A `+0x05`. After that read, the low byte of Context C is written at first input `+0x09`, and the previously read byte is zero-extended and written as a word at Context B `+0x44`.

The third-input region then receives the fourth input at `+0x14`. Context C receives the low byte of Context A at `+0x15`, followed by the full third input at `+0x44`.

Only after these writes is Context A `+0x05` read again. The two byte reads are distinct observations; intervening writes can affect the second through aliasing.

The low byte of the fourth input is then written at third input `+0x15`. The second Context A byte selects a word read at absolute address:

**zero-extended byte + `0x74`**

This is a byte-derived address, not evidence of an object-relative field or a word-indexed table. Its possible starting addresses range from `0x74` through `0x173`.

That word becomes the indexed word. The subsequent initial publications are, in order:

- Low byte of Context A at third input `+0x15`.
- Context D as a word at third input `+0x54`.
- Low byte of the double index at first input `+0x09`.
- Fourth input as a word at third input `+0x14`.

The last word write overlaps the earlier byte writes at third input `+0x15`. The final byte pattern depends on target endianness.

### Constant writes and derived-address setup

The function next writes:

| Destination | Width | Value |
|---|---:|---:|
| Quadruple index | 8 bits | `0x3A` |
| Eight times indexed word | 16 bits | `0x003A` |
| Quadruple index `+0x20` | 32 bits | `0x0000003A` |

The adjusted input and scaled base determine the next destination. At scaled base `+0x20`, four word writes occur in this order:

1. `0x00000020`.
2. `0x0000002F`.
3. The zero-extended byte read from scaled base `+0x04`, with that read occurring after the first two writes.
4. `0x00000020`.

The shared base is loaded after this sequence. A word containing `0x00000020` is then written at absolute address `0x60`.

These accesses cannot be reduced to their final values when aliases, faults, or externally observable memory are relevant.

## Acceptance examples

These are conditional contract examples, not executed tests.

### Distinct initial byte observations

Given valid storage and aliasing that lets an intervening initial write change Context A `+0x05`:

- Context B `+0x44` receives the zero-extended first observation.
- The indexed-word address uses the second observation.

Using one cached byte for both purposes does not satisfy the visible ordering.

### Intermediate constant writes remain observable

Given a monitor capable of observing successful writes at scaled base `+0x20`, it observes `0x20`, then `0x2F`, then the zero-extended byte obtained from scaled base `+0x04`, then `0x20`, all as 32-bit stores.

A single final store of `0x20` is insufficient.

### Full-width overwrite supersedes byte publication

Given little-endian storage, a fourth input of `0x11223344`, and no other relevant aliases, the last initial word write at third input `+0x14` leaves bytes `44 33 22 11` there. The byte at `+0x15` is consequently `0x33`, despite earlier writes to that byte.

For a different byte order, this expected layout must change.

### Saved values survive later storage changes

Given valid accesses and no interruption, the third indirect argument is the saved field captured from double index `+0x14`. Later changes to that location do not implicitly refresh the captured value.

### Shift with an unambiguous operand

Given a nonnegative loaded link of `0x12345678` and a shift count of four, the byte written at double index `+0x01` is `0x67`.

This example does not specify negative-operand shifts or counts of 32 or greater.

### Final dispatch arguments

Given traversal value `0x2000`, saved field `0x34567890`, final payload `0xABCDEF01`, and successful preceding accesses, the visible indirect arguments are `0x72`, `0x2000`, `0x34567890`, and `0xABCDEF01`, in that order.
