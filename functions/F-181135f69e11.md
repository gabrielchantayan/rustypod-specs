# F-181135f69e11

## Purpose

F-181135f69e11 updates a 32-bit value in a mutable object, conditionally invokes two dynamically dispatched operations, and conditionally computes a signed 32-bit result stored elsewhere in the object.

Its return value is **not generally the result it computes and stores**. Depending on the path, it returns either a complete flags word, zero, or a previously read object word.

The apparent intent is to coordinate a position-like update with optional dependent-state maintenance and a bounded calculation. Those meanings are inferred, not established. The contract below therefore identifies object fields by byte offset rather than assigning domain-specific names.

## Interface

### Inputs

The function receives:

1. A reference to a mutable object whose accessed fields are represented as 32-bit words.
2. A signed 32-bit input value.

The object reference must support the direct reads and writes described below. Its first word supplies a dispatch-table reference used on conditional paths.

### Return value

The function returns a 32-bit unsigned value. There are three return cases:

| Condition at the final processing gate | Returned value |
|---|---|
| Bit `0x00000001` of the word at offset `0x124` is clear | The entire word read from offset `0x124` |
| That bit is set, but the subsequently read word at offset `0xEC` is zero | Zero |
| That bit is set and the subsequently read word at offset `0xEC` is nonzero | The word read from offset `0xD0`, before either direct dependency call |

The word at offset `0x120` is an output through object mutation on the third path. It is not the function’s return value.

### Object layout used directly

All offsets are byte offsets from the supplied object reference.

| Offset | Width | Established use |
|---|---:|---|
| `0x000` | 32 bits | Dispatch-table reference |
| `0x048` | 32 bits | Flags; bit `0x00000010` controls an optional dispatch |
| `0x0D0` | 32 bits | Arithmetic operand and return-value snapshot |
| `0x0D8` | 32 bits | Arithmetic operand |
| `0x0EC` | 32 bits | Zero/nonzero gate and later address-like operand |
| `0x0FC` | 32 bits | Signed comparison operand |

| `0x104` | 32 bits | Signed arithmetic operand |
| `0x120` | 32 bits | Computed-result destination |
| `0x124` | 32 bits | Flags and, on one early-return path, the returned word |

The dispatch table is accessed at byte offsets `0x164` and `0x84`. These are table-entry locations, not offsets of additional object fields.

### Preconditions

For a defined successful execution:

- The object must be writable at offset `0x100`.
- Every field reached along the selected path must be readable or writable as required.
- Each reached dispatch entry must identify a callable operation compatible with receiving the object reference.
- Direct dependencies must accept the arguments actually supplied.
- The object, dispatch information, and required memory must remain usable after any callback that precedes a later access.
- Signed arithmetic used for the final bound must have a defined interpretation in the execution environment.

No null checks, object-size checks, dispatch validation, or explicit arithmetic-error handling are visible.

## Behavior

### 1. Store the input before any conditional operation

The function first writes the supplied signed 32-bit input to object offset `0x100`.

It then reads the signed 32-bit word at offset `0x0FC` and compares it with the supplied input. If the object word is strictly less than the input, the function:

1. Obtains the dispatch-table reference from the object.
2. Obtains the operation at table offset `0x164`.
3. Invokes that operation with the object reference.

Equality does not trigger this operation.

The comparison uses the supplied input, not a subsequent reread of offset `0x100`. The initial store therefore occurs before the callback, but a callback’s changes to the object are not subsequently undone by another unconditional store of the input.

### 2. Optionally invoke the second dispatched operation

After the first conditional operation has completed, if invoked, the function reads the word at offset `0x048`.

If bit `0x00000010` is clear, this stage performs no read of offset `0x0EC` and invokes no operation.

If that bit is set, the function reads offset `0x0EC`. When that word is nonzero, it obtains the object’s dispatch-table reference and invokes the operation at table offset `0x84`, passing the object reference.

Consequently:

- The first operation may affect whether the second operation is invoked.
- The dispatch-table reference used for the second invocation is obtained at that invocation, rather than necessarily reusing the reference used for the first.
- A nonzero word at offset `0x0EC` alone is insufficient; the flag bit must also be set.
- Return values from both dispatched operations are ignored.

No assumption is made that either operation preserves object fields, global state, memory ownership, or the dispatch-table reference.

### 3. Evaluate the final processing gate

After both optional dispatch stages, the function reads the full 32-bit word at offset `0x124`.

If bit `0x00000001` is clear, it returns that full word immediately. It does not clear other bits or normalize the return value to a Boolean.

If that bit is set, the function reads offset `0x0EC` again. If the value is zero, it returns zero immediately.

These are fresh accesses after the callbacks. A value observed at offset `0x0EC` during the earlier dispatch gate does not determine this later gate.

Neither early-return path directly writes offset `0x120`. Earlier callbacks may nevertheless have changed it.

### 4. Capture operands and invoke the direct dependencies

When the final gate permits processing, the function reads and retains the following object words in this order:

1. Offset `0x0D0`, as a 32-bit unsigned word.
2. Offset `0x0D8`, as a signed 32-bit value.
3. Offset `0x104`, as a signed 32-bit value.
4. Offset `0x100`, as a signed 32-bit value.

It next reads offset `0x0EC` for the argument to F-b01436b9ce2b. Thus, the nonzero gate read and this argument-producing read are separate source-level accesses.

F-b01436b9ce2b receives the value derived by adding `0x80` to the word read from offset `0x0EC`. This is an address-like calculation; the supplied evidence does not establish the dependency’s semantic argument type or the validity of the resulting address.

The function then calls F-870c4fcf7295 with two arguments:

- The 32-bit difference between the captured word at `0x0D8` and the captured unsigned word at `0x0D0`.
- The 32-bit result returned by F-b01436b9ce2b.

For the first argument, the unsigned operand makes the subtraction a 32-bit unsigned computation under the represented type model. The resulting bit pattern is the subtraction modulo \(2^{32}\). The dependency’s own interpretation of that argument is not established.

The result of F-870c4fcf7295 is used as a signed 32-bit candidate result.

The captured operands are not reread after the direct dependency calls. In particular, changes those dependencies make to offsets `0x0D0`, `0x0D8`, `0x100`, or `0x104` do not replace the already captured values used by this invocation.

### 5. Store the candidate, then conditionally replace it

After F-870c4fcf7295 returns, the function writes its candidate result to offset `0x120`.

It computes a signed bound from the captured value at offset `0x104` minus the captured value at offset `0x100`. If that bound is strictly less than the signed candidate, the function writes the bound to offset `0x120`.

For inputs where that signed subtraction is defined, the final directly stored value is therefore the signed minimum of:

- The result from F-870c4fcf7295.
- The captured value at `0x104` minus the captured value at `0x100`.

The source expresses a candidate write followed by a conditional replacement. This is not merely a specification to perform one write of the final minimum. Whether both stores remain separately observable in a particular compiled execution depends on the memory model and generated implementation, which are not supplied.

There is no explicit lower clamp. A negative bound can replace a positive candidate, and a negative candidate can remain unchanged.

Finally, the function returns the captured unsigned word from offset `0x0D0`.

## Side effects

### Direct object writes

The function itself expresses only these object writes:

- An unconditional write of the input to offset `0x100`.
- A write of the candidate to offset `0x120` when the final gate permits processing.
- A second write to offset `0x120` when the signed bound is strictly smaller than the candidate.

It does not directly modify the flags at offsets `0x048` or `0x124`, the gate word at `0x0EC`, or the arithmetic source fields.

1. Dispatch-table operation at offset `0x164`.
2. Dispatch-table operation at offset `0x84`.

The first two calls are independently conditional. The last two occur together only after the final gate succeeds.

Effects of all four callees are unknown. The supplied body does not establish that they are pure, preserve globals, preserve object contents, retain references, allocate memory, or release memory.

## Acceptance examples

These examples are conditional deductions from the supplied static evidence, not runtime observations. Except where explicitly stated, assume callees return normally, do not change relevant fields, and arithmetic remains defined.

### Initial signed comparison

With offset `0x0FC` containing `10`:

- Input `11` is first written to `0x100`, then the operation at dispatch offset `0x164` is invoked.
- Input `10` is written, but that operation is not invoked.
- Input `-1` is written, but that operation is not invoked.

The comparison is signed, not an unsigned comparison of the same bit patterns.

### Independent second-dispatch gate

If bit `0x10` at offset `0x048` is clear, a nonzero value at offset `0x0EC` does not cause the operation at dispatch offset `0x84` to run.

If the bit is set and offset `0x0EC` is nonzero, that operation runs before offset `0x124` is examined.

### Full-word early return

If the final read at offset `0x124` yields `0x000000A4`, the function returns `0x000000A4`, not zero. Bit zero is clear.

Neither direct dependency is called, and the function itself does not write offset `0x120` on this path.

### Zero gate return

If offset `0x124` yields `0x000000A5` and the subsequent read at offset `0x0EC` yields zero, the return value is zero. It is not `0x000000A5`.

### Candidate retained

Suppose the final gate succeeds, the captured words are:

- Offset `0x0D0`: `20`.
- Offset `0x0D8`: `50`.
- Offset `0x104`: `100`.
- Offset `0x100`: `70`.

F-870c4fcf7295 receives a first argument of `30`. If it returns a candidate of `12`, offset `0x120` receives `12` and is not replaced, because the bound is `30`. The function returns `20`.

### Candidate replaced by a negative bound

With captured values `5` at offset `0x104` and `9` at offset `0x100`, the bound is `-4`.

If the candidate is `12`, the function first writes `12` to offset `0x120`, then writes `-4`. There is no clamp to zero.

### Unsigned subtraction boundary

If the captured word at offset `0x0D8` is `3` and the captured unsigned word at offset `0x0D0` is `5`, the first dependency argument has the 32-bit bit pattern `0xFFFFFFFE`.

Its semantic interpretation inside F-870c4fcf7295 remains unknown.

### Callback mutation affects later decisions

If the first dispatched operation changes offset `0x124` from an odd word to an even word, the later final gate uses the changed word.

If the second dispatched operation changes offset `0x100`, the later bound uses that changed value, not necessarily the original input.
