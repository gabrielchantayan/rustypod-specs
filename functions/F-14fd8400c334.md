# F-14fd8400c334

## Purpose

F-14fd8400c334 coordinates operations over three opaque boundary values, two signed quantities, an opaque workspace value, a signed threshold, and an opaque context value. It selects a terminal dependency sequence or partitions the work, performs a rearrangement sequence, and invokes itself on two subproblems in order.

**Established static evidence:** the function uses signed comparisons, halves one quantity, obtains another split quantity from a dependency, selects among three rearrangement sequences, and performs sequential recursive processing. It has no explicit return value.

**Inferred intent:** the boundary, split, and workspace relationships resemble a buffered divide-and-conquer merge or range-rearrangement operation. This interpretation does not establish sorting, stability, element movement, allocation, or destruction.

The contract below specifies observable argument relationships, local-storage relationships, and call order. It does not assign unverified semantics to dependencies.

### Local storage and validity

The function uses 32-bit local slots for the current boundaries, two cuts, and a working boundary. Certain dependencies receive addresses of these slots. These are addresses of local storage containing opaque values, not necessarily addresses of the objects represented by those values.

A critical storage identity applies on the partitioning path: the working-boundary slot passed by address to **F-12575309c9f1** in rearrangement Alternative B is subsequently reused to hold the context value before each recursive invocation. The shared recursive boundary is captured separately before that reuse.

No explicit validation rejects negative quantities, invalid opaque values, inconsistent boundaries, overlapping objects, insufficient workspace, or out-of-range dependency results. Validity requirements beyond the observed operations remain **documented_only**. Termination is not guaranteed merely by supplying values of the stated widths.

## Behavior

### Initial selection

All quantity comparisons are signed.

The first terminal sequence is selected exactly when:

- The left quantity is less than or equal to the right quantity; and
- The threshold is greater than or equal to the left quantity.

Otherwise, the second terminal sequence is selected when the threshold is greater than or equal to the right quantity.

Partitioning occurs only when both terminal conditions fail. There is no earlier empty-range or zero-quantity return.

### First terminal sequence

The dependency order is:

1. **F-fae1bf9a30ba** receives the incoming start boundary, incoming middle boundary, and workspace value.
2. Its 32-bit result is retained.
3. **F-1f5b9bde2df1** receives, in order, the workspace value, retained result, current middle boundary, end boundary, current start boundary, and context value.

The function returns if these calls return normally. No partitioning or recursion occurs.

### Second terminal sequence

The dependency order is:

1. **F-fae1bf9a30ba** receives the incoming middle boundary, incoming end boundary, and workspace value.
2. Its 32-bit result is retained.
3. **F-e6daf0443eb7** receives the current start boundary, current middle boundary, workspace value, retained result, end boundary, and context value.

The function then returns if the dependencies return normally.

Neither terminal sequence contains explicit rollback, cleanup, or error handling.

### Partition construction

The left cut initially contains the incoming start boundary. The right cut initially contains the incoming middle boundary.

#### Left-selected split

When the right quantity is strictly less than the left quantity:

1. The left split quantity is the left quantity divided by two.
2. **F-12575309c9f1** receives the address of the left-cut slot and the left split quantity. Its return value is ignored.
3. **F-7aa404df27a8** receives the current middle boundary, end boundary, post-call left cut, and context value. Its 32-bit result is stored in the right-cut slot.
4. **F-fac420ffd791** receives the addresses of the middle-boundary slot and right-cut slot. Its signed 32-bit result becomes the right split quantity.

The final call may modify both addressed slots. Their post-call values govern subsequent operations.

#### Right-selected split

When the left quantity is less than or equal to the right quantity:

1. The right split quantity is the right quantity divided by two.
2. **F-12575309c9f1** receives the address of the right-cut slot and the right split quantity. Its return value is ignored.
3. **F-4a68531d8f4f** receives the current start boundary, middle boundary, post-call right cut, and context value. Its 32-bit result is stored in the left-cut slot.
4. **F-fac420ffd791** receives the addresses of the start-boundary slot and left-cut slot. Its signed 32-bit result becomes the left split quantity.

Again, both addressed slots must be treated as potentially modified.

An address passed to an earlier dependency is not established to have been discarded. Later dependencies may therefore encounter state affected through retained addresses, subject to their unknown contracts.

### Rearrangement preparation

After the selected split sequence returns, the function:

- Captures value snapshots of the current middle boundary and right cut.
- Computes the remaining left quantity as the incoming left quantity minus the left split quantity.
- Initializes the working-boundary slot from the current left cut.

A snapshot preserves the captured 32-bit value; it does not preserve the contents or lifetime of any object denoted by that value.

The following alternatives are ordered. Alternative A takes precedence over the other two.

### Alternative A: right split is smaller and fits

This alternative applies when the right split quantity is strictly less than the remaining left quantity and is less than or equal to the threshold.

The dependency sequence is:

1. **F-fae1bf9a30ba** receives the current middle boundary, current right cut, and workspace value. Its result is retained.
2. **F-2355fc619e7e** receives the working-boundary value, saved middle boundary, and saved right cut. Its result is ignored.
3. **F-fae1bf9a30ba** receives the workspace value, retained result from step 1, and working-boundary value.

The result of step 3 becomes the shared recursive boundary.

### Alternative B: remaining left quantity exceeds the threshold

This alternative applies only if Alternative A was not selected and the threshold is strictly less than the remaining left quantity.

The dependency sequence is:

1. **F-95da9a244c7f** receives the current left cut, current middle boundary, and current right cut.
2. **F-12575309c9f1** receives the address of the working-boundary slot and the right split quantity.

Both return values are ignored. After step 2 returns, the function reads the working-boundary slot and captures its value separately as the shared recursive boundary.

This capture precedes the context overwrite described below. The slot and the captured boundary are not interchangeable: subsequent writes to the slot do not, by themselves, change the captured boundary value.

### Alternative C: remaining left quantity fits

This is the remaining case: Alternative A was not selected, and the remaining left quantity is less than or equal to the threshold.

The dependency sequence is:

1. **F-fae1bf9a30ba** receives the current left cut, current middle boundary, and workspace value. Its result is retained.
2. **F-fae1bf9a30ba** receives the saved middle boundary, saved right cut, and working-boundary value. Its result is ignored.
3. **F-2355fc619e7e** receives the workspace value, retained result from step 1, and saved right cut.

The result of step 3 becomes the shared recursive boundary. In particular, step 3 uses the saved right cut, not the ignored result of step 2.

### Recursive processing and slot reuse

After any rearrangement alternative, the shared recursive boundary has been captured separately from the working-boundary slot.

Immediately before the first recursive invocation, the function writes the incoming context value into that working-boundary slot. In Alternative B, this is the same 32-bit slot whose address was supplied to **F-12575309c9f1**. No intervening release, address invalidation, or requirement to discard that address is established.

The first recursive call visibly supplies:

1. Current start boundary.
2. Current left cut.
3. Captured shared recursive boundary.
4. Left split quantity.
5. Right split quantity.
6. Workspace value.
7. Threshold.
8. Zero.

Only if the first invocation returns does processing continue.

Immediately before the second recursive invocation, the function writes the incoming context value into the same working-boundary slot again. This is a second write, not merely continued reliance on the value written before the first call. If the slot was changed during the first recursive invocation through a retained address, this second write replaces that intervening value.

The second recursive call visibly supplies:

1. Captured shared recursive boundary.
2. Current right cut.
3. End boundary.
4. Remaining left quantity.
5. Incoming right quantity minus the right split quantity.
6. Workspace value.
7. Threshold.
8. Zero.

A dependency that retains the working-slot address and accesses it during its valid lifetime may observe the context overwrite before the first recursion, access or modify the slot during recursive execution, and observe the repeated overwrite before the second recursion. This is a storage relationship, not a guarantee that any dependency actually retains or accesses the address.

Other escaped local slots are likewise not assumed immutable across later calls. In particular, the second recursive invocation uses the right-cut slot’s value when that invocation is prepared; it is not specified to use a snapshot taken before the first invocation.

The supplied interface has nine inputs, but the recursive call expressions expose eight. The writes of context into the working-boundary slot immediately before those calls are established; whether they implement delivery of a ninth recursive argument is **documented_only**. Slot identity alone does not resolve the calling convention.

### Integer behavior

Quantity comparisons and dependency-produced split quantities are signed 32-bit.

Division by positive two truncates toward zero. A negative odd quantity is therefore not rounded toward negative infinity.

Both remaining-quantity calculations use subtraction. There is no visible checked arithmetic, saturation, or explicit overflow response. Acceptance examples below use representable results. Behavior for unrepresentable signed subtraction remains **documented_only**.

There is no explicit check that split quantities lie within their corresponding input quantities, that recursive quantities decrease, or that recursion depth is bounded.

External-object effects are dependency-mediated. Nothing in this function establishes that dependencies preserve globals, preserve objects designated by opaque arguments, or refrain from allocation, release, retention, or ownership transfer.

Address-taking creates additional observable relationships:

- **F-12575309c9f1** can access a cut slot during partitioning and the working-boundary slot in Alternative B.

These observations do not grant permission to access expired local storage or establish the dependencies’ retention policy. They also do not establish concurrency safety or atomic access.

No explicit allocation, deallocation, ownership transfer, cleanup, rollback, or error reporting appears in this function. Dependencies may nevertheless perform such actions. If a dependency or recursive invocation does not return normally, later operations in the stated sequence are not guaranteed to occur.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Dependency results, mutations, and normal returns are stipulated where necessary.

1. **First terminal selection.** Left quantity 4, right quantity 9, and threshold 4 select the first terminal sequence. The first dependency’s result becomes the second argument of **F-1f5b9bde2df1**. No recursive call occurs.

2. **Second terminal selection.** Left quantity 9, right quantity 4, and threshold 4 select the second terminal sequence. **F-fae1bf9a30ba** receives the middle/end pair before **F-e6daf0443eb7** runs.

3. **Alternative A.** Left quantity 10, right quantity 6, and threshold 2 select a left split quantity of 5. If **F-fac420ffd791** returns a right split of 2, the remaining left quantity is 5 and Alternative A applies. The visible recursive quantity pairs are (5, 2) followed by (5, 4), subject to normal returns.

4. **Alternative B and shared-slot identity.** With the same inputs but a returned right split of 3, Alternative B applies. Suppose its **F-12575309c9f1** call leaves boundary value B in the addressed working slot. The function captures B as the shared recursive boundary, then writes context value C into that same slot before the first recursive call. A valid retained address refers to the slot now containing C; the captured recursive boundary remains B.

5. **Repeated context overwrite.** Continue the preceding example. Suppose a dependency retains the working-slot address and, during the first recursive invocation, changes that slot to value D. If the invocation returns normally, the parent writes C into that slot again before the second invocation. The second invocation still receives captured boundary B as its first visible argument. This example is conditional on the retained access being valid and the recursive calling contract being resolved.

6. **Alternative C.** Left quantity 6, right quantity 10, and threshold 3 produce a right split quantity of 5. If the returned left split is 4, the remaining left quantity is 2 and Alternative C applies. Its third operation uses the saved right cut, regardless of the ignored result from its second operation.

7. **Threshold equality.** With left quantity 6, right quantity 10, threshold 3, and returned left split 3, the remaining left quantity equals the threshold. Alternative A fails because the right split is 5; Alternative B’s strict comparison also fails. Alternative C applies.

8. **Zero quantities.** Both quantities and threshold equal to zero select the first terminal sequence. Zero-looking input does not bypass dependencies.

Recursive examples do not resolve the missing ninth-argument delivery contract or establish termination.
