# F-1f4e8621665d

## Purpose

F-1f4e8621665d scans 17 callback descriptors in ascending index order. Except for a conditional gate at index 9, each descriptor selects a callback that can enable further processing of a corresponding state record. Eligible records undergo a status check, preparation, and conditional external submission. Each completed submission sets the corresponding bit in a local 32-bit activity mask.

The mask starts with a value loaded from a selection table, not necessarily zero. After the scan, a nonzero mask causes a post-scan dependency call. An unresolved final transfer receives either that dependency’s result or zero.

This contract describes statically established behavior. Application meanings, dependency internals, and unresolved transfer semantics are not established.

## Interface

### Inputs and result

The function has no explicit parameters and no explicit result value.

Its effective inputs include:

- A global state-base value, read separately at three initialization points.
- A global selection-table base.
- A global callback-descriptor-table base, read again for each iteration.
- A hidden incoming context base used for object adjustment and the index-9 gate.
- Dependency targets, including descriptor-selected callbacks and an unresolved final transfer.

The three initialization reads of the global state base serve different purposes:

1. Saving a base for the later index-9 state-byte access.
2. Obtaining a base for the selector access within the initial-mask expression.
3. Establishing a saved record-array base after the initial mask has been loaded.

The representation does not establish that these reads necessarily produce identical values.

### Widths and accessed layouts

The representation uses 8-bit bytes and 32-bit words, addresses, and integer values. The gate dependency returns a 64-bit quantity.

## Behavior

### Initialization and distinct state-base reads

Before scanning, the function saves the current global state base for the later gate-byte access and initializes the final-transfer argument to zero.

It then evaluates the initial-mask access. That expression:

- Reads the global selection-table base.
- Separately reads the global state base to obtain the signed 32-bit selector at offset 4.
- Loads the unsigned 32-bit mask at selection-table displacement 12 plus four times that selector.

The representation does not establish an evaluation order between the selection-table-base read and the state-base read inside this expression. Both contribute to the eventual mask access; neither must be described as occurring first.

After the initial mask has been loaded, the scan index is initialized to zero. The global state base is read again, and offset 28 is added to establish the saved record-array base.

Consequently, the gate byte, selector, and records need not belong to the same state region if the separate global reads yield different bases. Later replacement of the global state base does not explicitly refresh the saved gate base or saved record-array base.

The mask is loaded only once. Later changes to the selector or selection table do not reload it.

### Iteration order and descriptor loading

The function visits indices 0 through 16, inclusive.

At each iteration, it reads the current global callback-descriptor-table base and selects the 8-byte descriptor at eight times the current index. It reads the descriptor’s first word and then its second word.

Thus, the table base is not captured once for the whole scan. An earlier dependency can replace that global base, causing a later iteration to obtain its descriptor from another table.

After loading the descriptor words, the function writes the current index into the neighboring index byte, then initializes the status byte to 1. The 22-byte scratch region is not visibly initialized. Its storage is reused across iterations.

The callback receives the status-byte address, not a separate explicit index argument. Adjacency alone does not establish permission for the callback to access the index byte or scratch region.

### Index-9 gate

Only index 9 applies the additional gate. Its descriptor words have already been loaded, and its local index and status bytes have already been initialized.

The function reads the 32-bit field at hidden-context offset 720 and calls F-d7be9cfb4000 with that value and 300. It examines the returned 64-bit quantity as upper and lower 32-bit halves.

| Upper half | Byte at offset 3 from the initially saved gate base | Result |
|---|---|---|
| Zero | Not read | Continue processing index 9 |
| Nonzero | Zero | Continue processing index 9 |
| Nonzero | Nonzero | Skip index 9 |

When required, the state byte is read after F-d7be9cfb4000 returns. Mutation of that byte by the dependency can therefore affect the decision.

The lower half does not determine whether processing continues. A zero upper half permits processing regardless of the lower half. A nonzero upper half makes the subsequently read state byte decisive.

Replacing the global state base during the gate does not redirect this byte access: it uses the base saved during initialization. Mutating the memory at that saved base can affect the access.

Similarly, replacing the global descriptor-table base or modifying index 9’s descriptor during the gate does not replace the two descriptor words already loaded for index 9. Later iterations re-read the global table base.

Skipping index 9 omits its callback, record comparison, preparation, submission, and mask update. Scanning continues at index 10.

### Callback resolution and invocation

The descriptor’s second 32-bit word encodes both an object adjustment and a dispatch-mode bit.

The adjusted object address is the hidden context base plus the signed interpretation of the second word shifted arithmetically right by one bit. This is a sign-preserving shift, not unsigned division by two.

The second word’s least significant bit selects the target-resolution mode:

- **Bit clear:** use the descriptor’s first word directly as the callback target.
- **Bit set:** read the adjusted object’s first 32-bit word. Add that value to the descriptor’s first word with its lowest two bits cleared, then read a 32-bit callback target from the resulting address.

The indirect-mode object-word and target reads occur when callback resolution is reached, after the index-9 gate if applicable. Those memory contents are not part of the earlier descriptor snapshot.

The callback receives the adjusted object address and the status-byte address. Its result is interpreted as a signed 32-bit integer for a zero/nonzero decision.

A nonzero result ends processing of the current entry without record comparison, preparation, submission, or addition of its mask bit. A zero result enables record processing.

### Status consistency check

After a zero callback result, the function selects the record at the saved record-array base plus twelve times the current index. It reads the byte at record offset 8 and compares it with the status byte minus one.

The subtraction is not reduced back to eight bits. The byte is promoted before subtraction, and the comparison uses the resulting unsigned 32-bit value.

Consequences include:

- Status 1 matches record byte 0.
- Status 2 matches record byte 1.
- Status 255 matches record byte 254.
- Status 0 produces comparison value 4,294,967,295 and matches no record byte.
- Record byte 255 matches no possible status-byte value.

A mismatch calls F-a817d8d58c10 without explicit arguments.

That dependency is annotated as non-returning, but its implementation is unavailable. No specific exception, termination action, diagnostic, or recovery mechanism is established. If it unexpectedly returns, the visible continuation proceeds to preparation; the caller contains no separate recovery branch at this point.

### Preparation and submission

After the comparison, or after an unexpected return from the mismatch dependency, the function reads the record’s 32-bit field at offset 4. It calls F-7f14f1ab6851 with that value and the scratch-region address.

A zero preparation result causes no submission and adds no mask bit.

A nonzero preparation result causes the function to:

1. Read the same record field again.
2. Call F-unknown-02 with the newly read value and the same scratch-region address.
3. Add the current entry’s bit to the local activity mask by bitwise OR.

The two record-field reads are distinct. Preparation can change that field, so preparation and submission can receive different first arguments.

The submission result is not inspected. If submission returns normally, the mask bit is set regardless of any result it may supply. If it does not return, the bit update and subsequent scan steps are not reached.

Only bits 0 through 16 can be newly set by the scan. Existing bits, including bits 17 through 31, are preserved.

### Completion and final transfer

After index 16, the function examines the accumulated 32-bit mask.

- If zero, the final-transfer argument remains zero.
- If nonzero, F-c9ee018573ab is called without explicit arguments, and its 32-bit result replaces the final-transfer argument.

F-unknown-03 is then invoked with that single 32-bit argument.

The mask is not explicitly passed to either dependency and is not visibly written back to the selection table.

If the final transfer returns, the function returns without an explicit result. Whether the unresolved operation represents an ordinary call, continuation, or tail transfer remains unknown.

## Side effects

### Direct effects

Visible direct writes affect local working storage: the index byte, status byte, accumulated mask, and final-transfer argument. The caller does not visibly write the global state records, selection table, or descriptor table.

Externally visible behavior primarily consists of ordered reads and dependency calls. Processing is sequential; a dependency that does not return prevents later operations from being reached.

### Mutable shared inputs

Dependencies are not assumed to preserve globals or pointed-to data.

Important distinctions are:

- The initialization uses three separate state-base reads, with different purposes.
- The saved gate base and saved record-array base are not explicitly refreshed afterward.
- The global descriptor-table base is re-read on every iteration.
- Each iteration retains its already loaded descriptor words.
- Index 9 retains those words across its gate call.
- The gate byte is conditionally read after the gate dependency.
- The record status byte is read after the callback.
- The submission argument is re-read after preparation.
- The initial mask is retained locally rather than reloaded.

These distinctions determine which mutations can affect later operations. They do not establish synchronization, atomicity, or validity under concurrent mutation.

### Ownership and storage lifetime

No allocation, deallocation, reference-count update, or ownership transfer is directly visible in the caller. Their absence inside dependencies is not established.

The status and scratch addresses refer to invocation-local storage. The scratch region is reused between entries. Retention or asynchronous use of either address requires an external lifetime contract that is unavailable.

The supplied representation does not establish how many scratch bytes preparation writes or submission reads. A nonzero preparation result does not prove initialization of all 22 bytes.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Except where stated otherwise, they assume valid memory, compatible interfaces, and normal dependency returns.

1. **Distinct initialization bases.**  
   If the initial saved state base is A, the state-base read for selection yields B, and the later record-base read yields C, the gate byte is read from A plus 3, the selector from B plus 4, and records begin at C plus 28. This does not prescribe an order between the selection-table-base read and the selector’s state-base read inside the mask expression.

2. **Descriptor-table replacement between iterations.**  
   If an index-2 dependency replaces the global descriptor-table base, index 3 obtains its descriptor using the replacement base. The already loaded index-2 descriptor is not reloaded.

3. **Descriptor replacement during the index-9 gate.**  
   If the gate replaces the global descriptor-table base or edits the current descriptor, permitted index-9 processing still resolves its callback using the descriptor words loaded before the gate. Index 10 reads the then-current global table base.

4. **Zero mask with bypassed callbacks.**  
   With an initial mask of zero, if every reached callback returns nonzero and no entry submits, F-c9ee018573ab is not called. F-unknown-03 receives zero.

5. **Preexisting activity without submissions.**  
   An initial mask containing only bit 31 still causes the post-scan call even if no entry adds a bit. Its result, including zero, is forwarded.

6. **One completed submission.**  
   With an initial mask of zero, index 4 returning zero, leaving status 1, matching record byte 0, and obtaining nonzero preparation causes submission. After submission returns, bit 4 is set, making the final mask nonzero.

7. **Matching status without submission.**  
   Status 2 and record byte 1 pass the check. A zero preparation result then causes no submission or new mask bit.

8. **Zero status cannot match.**  
   After a zero callback result, status 0 invokes the mismatch dependency for every record byte, including 255.

9. **Index-9 skip and lower-half irrelevance.**  
   A nonzero gate upper half followed by a nonzero saved-base byte skips index 9. A zero upper half permits processing without reading that byte, regardless of the lower half.

10. **Preparation changes the submission argument.**  
    If preparation receives value A, changes the record field to B, and returns nonzero, submission receives B.

11. **Highest scanned entry.**  
    A returning submission at index 16 sets bit 16. Index 17 is never visited.
