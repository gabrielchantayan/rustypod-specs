# F-f72185e94bd5

## Purpose

F-f72185e94bd5 copies the current contents of a global 32-bit storage location into the first word of a supplied object, obtains an associated address through a dependency, and conditionally processes a linked structure. It then calls a final dependency and returns a 64-bit value assembled from an address-derived low word and a private saved high word.

The established contract is an ordered sequence of memory accesses and dependency calls. Destruction, cleanup, dispatch-table installation, and ownership release are possible interpretations, not established semantics. In particular, the initial global value is not established to be constant, and the node-processing dependencies are not established to free memory.

All behavior below is derived from static evidence. No runtime tests have been performed.

### Result

On normal completion, the result is a 64-bit concatenation:

- Bits 31 through 0 contain the 32-bit representation of the result address.
- Bits 63 through 32 contain the final contents of the saved word initialized from the second argument, read after F-8a5aadac202f returns.

This is word concatenation, not signed addition. A high word whose top bit is set contributes that exact 32-bit pattern.

On the nonzero branch, F-d0acc006efef receives the address of the saved high word. It may modify that word directly or make its address available to later dependencies during the same invocation. Therefore, the returned high word is not necessarily its value immediately after F-d0acc006efef returns.

The result does not establish a success code, an ownership token, or a valid live pointer.

## Behavior

### Initial global read and object write

The function reads the current 32-bit value from a global storage location and writes that value into the first word of the supplied object.

The global read precedes the object write. Both precede initialization of the three private saved words and the first dependency call.

The source establishes a read from storage, not installation of an invariant literal. Different invocations may copy different values if that storage changes. The value’s identity and semantic meaning are unknown.

There is no visible rollback of the object write if later processing faults or fails to return.

### Saved words and address acquisition

After the initial object write, the function initializes private 32-bit saved words from the second, third, and fourth arguments, in that order.

It calls F-1b9e6fff9bc9 once, passing the first argument’s address plus 40 bytes. This displacement corresponds to ten 32-bit elements.

The returned anchor determines the list header, branch field, finalization address, and result address. There is no visible null or validity check before the branch-field access.

The anchor is retained as a value. Later changes to memory used by F-1b9e6fff9bc9 do not cause the caller to acquire another anchor.

### Branch decision and preparation

The function reads the 32-bit branch field and tests whether it is zero.

If zero, it skips both conditional processing dependencies and the entire draining loop, proceeding to finalization. A nonempty header alone does not cause draining on this path.

If nonzero, the function performs these preparation operations in order:

1. Reads the branch field again as an address, reads the word eight bytes beyond that address, and stores the payload word into the private slot initialized from the third argument.
2. Reads the branch field again and stores that word into the private slot initialized from the second argument.

Thus, on this path, the visible caller replaces the saved copies of both the second and third arguments before exposing their addresses to a dependency. It does not similarly replace the saved fourth argument.

These branch-field reads are distinct source-visible accesses. The function provides no synchronization or snapshot mechanism making their values identical. If the field changes between accesses, the payload word and saved address word may correspond to different targets.

The initial nonzero test does not validate subsequent branch-field values. For example, a later zero value used for the payload lookup would still lead to an attempted read eight bytes beyond that address representation.

### First conditional dependency

The function calls F-d0acc006efef with these arguments, by position:

1. Address of the private word initialized from the fourth argument.
2. List-header address.
3. Address of the private word now containing the payload word.
4. Address of the private word now containing the saved branch-field value and ultimately supplying the return high word.

The dependency can access and modify the supplied private words. Its return value is not consumed.

The supplied addresses remain addresses of private storage belonging to the active invocation. The visible caller does not establish that the dependency discards them when its call returns. It may retain them for use by later dependencies before this function completes.

No validity after the private storage’s lifetime, ownership transfer, or permitted asynchronous access is established.

### Second conditional dependency

After F-d0acc006efef returns, the function reads the branch field again and calls F-88d9235286f8 with:

1. List-header address.
2. The newly read branch-field word.
3. A zero word.

There is no second branch test. If F-d0acc006efef clears the branch field, F-88d9235286f8 is still called with zero as its second argument.

The second argument is not taken from the saved high word. Changes to that saved word and changes to the branch field are distinct unless some unavailable dependency behavior connects them.

The return value of F-88d9235286f8 is not consumed.

### Header-driven draining

After F-88d9235286f8 returns, the function reads the first word of the list header.

A zero value ends draining. A nonzero value selects the current node. For each selected node:

1. The function reads the node’s offset-zero word as the successor.
2. It writes that successor into the first word of the list header.
3. It calls F-ff1bdc376dcd with the node’s offset-eight word, its offset-four word, and zero, in that argument-position order.
4. It calls F-ff1bdc376dcd again with the retained current-node address, one, and zero.

The header update precedes both calls, and the node-field call precedes the node-address call. Both field values for the first call are obtained before that call begins; their relative read order is not established.

The second call uses the retained node address. No additional dereference of that node is visible between the two calls. Whether either call releases or invalidates memory is unknown.

After the second call returns, the function reads the header again. It does not continue solely from a previously saved successor. Dependency changes to the header can therefore redirect, terminate, or extend draining.

There is no cycle detection, iteration bound, or node validation. Termination requires that a header read eventually observe zero. A cyclic or continually replenished structure may prevent finalization and return.

### Finalization and return

Both branches converge on F-8a5aadac202f, called with the anchor minus 32 bytes.

On the zero branch, this follows the branch decision without conditional processing or draining. On the nonzero branch, it follows loop termination.

Its return value is not consumed. After it returns, the function obtains the saved high word and constructs the 64-bit result.

On the nonzero branch, that high word includes any changes made through its exposed address during the invocation, including changes made by later dependencies through retained state. A value written by F-d0acc006efef survives into the result only if no subsequent modification replaces it.

If any dependency does not return normally, the visible function provides no alternate completion or recovery path.

## Side effects

### Direct writes

The visible function directly performs:

- One 32-bit write to the supplied object, using the preceding global read.
- Initialization and conditional replacement of private saved words.
- One 32-bit header write for each selected node.

It does not directly clear the branch field, clear node payload fields, or mark detached nodes.

The initial global access is a read. The function contains no visible direct write to that global location, although dependencies are not established to preserve it.

### Dependency-mediated effects and ownership

Dependencies may modify shared or reachable state. Ignoring their return values does not imply that they are read-only.

The two per-node calls have a release-like shape, but no allocation family, size interpretation, reference-count operation, or ownership transfer is established.

The private saved words are invocation-local storage. Passing their addresses permits mutation and does not establish either non-retention or a longer storage lifetime. In particular, later dependencies may access a retained address while the invocation remains active.

### Partial effects and errors

No explicit error result, error branch, exception handler, or rollback appears.

A fault or nonreturning dependency can leave the object update and any completed header advances in effect. The contract does not guarantee that finalization runs after interrupted processing.

## Acceptance examples

These are conditional acceptance criteria, not execution reports. They assume valid accessed storage, valid address calculations, and normal dependency returns unless stated otherwise.

### Current global value and zero branch

Suppose global storage contains a particular 32-bit pattern when the initial read occurs, and the branch decision observes zero.

- The object’s first word receives that pattern before private-word initialization and F-1b9e6fff9bc9.
- The conditional dependencies and per-node calls do not occur, even if the header is nonzero.
- F-8a5aadac202f receives anchor minus 32 bytes.
- The high word remains the original second-argument pattern; this path exposes no address of that private word.
- The low word represents anchor minus 40 bytes.

If the global contains a different pattern on another invocation, that invocation copies the newly read pattern rather than a value fixed by this contract.

### Nonzero branch with an empty processed header

Suppose the branch decision observes nonzero and the payload read is valid. If the two conditional dependencies leave the header zero:

- They run in the specified order.
- No per-node call occurs.
- Finalization follows.
- The return high word is the saved word’s contents after finalization returns.

### Changed branch field and retained saved-word address

Suppose F-d0acc006efef clears the branch field and writes a chosen pattern through its fourth argument.

F-88d9235286f8 is still called, with zero as its second argument. Draining depends on the header subsequently observed, not on another branch-field test.

If no later operation modifies the saved high word, the chosen pattern becomes the return high word. If a later dependency, including F-8a5aadac202f, changes that word through retained state, the final contents after finalization supply the high word instead.

### One-node list

Suppose draining observes one valid node with a zero successor, and dependencies do not change the header afterward.

The function writes zero to the header before either per-node call. It calls first with the two node fields, then with the retained node address. The next header read ends draining, and finalization follows.

### Interrupted or nonterminating processing

If header reads never observe zero, normal return is not guaranteed. If an access is invalid or a dependency does not return, no fallback result or rollback is established.
