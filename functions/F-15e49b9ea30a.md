# F-15e49b9ea30a

## Purpose

F-15e49b9ea30a performs an ordered selection among dependency-call routes. It obtains an initial 32-bit value, exposes a working slot to probes, and either returns without explicit publication or publishes a selected value before returning.

The established meanings of its return codes are structural:

| Return | Established meaning on normal completion |
|---|---|
| **0** | A required later probe returned zero. No explicit publication call occurred. |
| **1** | The fallback probe and fallback processing call completed, followed by publication of the working-slot value. |
| **2** | One of two routes published either the working-slot value or a freshly obtained value. |
| **3** | One of two other routes published either the working-slot value or a freshly obtained value. |

“Probe,” “processing,” and “publication” describe roles in this function, not established domain semantics. A nonzero probe result selects a branch; it does not independently establish validity or application-level success.

### Working storage

The function maintains an addressable **32-bit working slot**. Probes and fallback processing receive its address. Their mutations can affect later calls and, on applicable routes, the published value.

The working slot belongs to this invocation. Passing its address does not establish ownership transfer, permission to retain it after return, or any allocation or release obligation.

### Shared table reference and entry layout

A shared reference supplies an address-like table base. The function reads that reference **twice**, in a specified order after the initial value-producing call:

1. A first read supplies a saved base for later probes.
2. A separate second read supplies the base for the initial probe’s entry at offset `0x10`.

The two reads are distinct. Their returned values are not required to agree by the supplied evidence.

Each selected table entry is a 32-bit quantity at a fixed **byte offset**:

| Offset | Base used |
|---|---|
| `0x10` | The second read of the shared reference |
| `0x14`, `0x18`, `0x30`, `0x34`, `0x48`, `0x0C` | The saved value from the first read |

Each entry read covers four bytes beginning at its selected offset. The evidence does not establish table length, entry semantics, byte order, alignment requirements, or a requirement to access unselected entries.

Defined ordinary execution requires the particular addresses accessed to be readable and dependency-specific preconditions to hold. Those dependency preconditions are not supplied.

## Behavior

### Initialization and table-base selection

The working slot is first assigned the fourth argument. The function then calls **F-44362605ab79** with the second argument and replaces the working slot with that call’s 32-bit result.

There is no intervening probe or other dependency call that receives the working-slot address. The fourth argument is therefore not an alternative initial probe value. In particular, a zero result from F-44362605ab79 replaces it with zero.

After the initial value-producing call returns, the function:

1. Reads the shared table-base reference and saves that value.
2. Reads the shared table-base reference again.
3. Reads the 32-bit entry at offset `0x10` from the base obtained by the second read.
4. Invokes the initial probe with that entry.

A change made by the initial value-producing call can affect both reference reads because both occur afterward.

The representation establishes no dependency call between the two reference reads. It nevertheless provides no stability or concurrency contract that permits treating them as necessarily equal. The initial probe can therefore obtain its entry through a different base from the one used by every later probe.

After these reads, no further explicit read of the shared table-base reference is established. Replacing that shared reference later does not redirect subsequent entry accesses. Later accesses continue to use the saved base, provided that base remains valid.

Saving a base does not snapshot its table contents. Each selected entry is read when needed, after preceding dependency calls have returned.

### Common probe contract

Every probe invokes **F-01ebd883f9b0** with:

1. The first argument.
2. The address of the 32-bit working slot.
3. A 32-bit table entry.

The initial probe uses offset `0x10` through the separately reread base. All later probes use their selected offsets through the saved base.

For branching probes, the returned integer is tested only for equality or inequality with zero. Every nonzero result follows the nonzero branch; no positive-only test or magnitude check is established. The fallback probe at `0x0C` has no return-value-dependent branch.

The working slot is not restored between probes. A probe may leave a changed value even when it returns zero, and subsequent calls receive the same slot.

### Route selected by a nonzero `0x10` result

The function next probes offset `0x14` using the saved base.

After that probe returns, the function reads the working slot into a selected-value temporary before testing the probe result.

- If the result is nonzero, it publishes that selected value and returns **2**.
- If the result is zero, it proceeds to the probe at `0x18`. The earlier selected-value read does not cause publication.

After the `0x18` probe returns, the function again reads the working slot into the selected-value temporary before testing the result.

- If the result is zero, it returns **0**, with no explicit publication.
- If the result is nonzero, it publishes the selected value and returns **3**.

Thus, the working slot is read after `0x18` even on the route that returns zero. This is distinct from publication: the value is selected locally but not passed to the publication dependency.

Neither branch calls F-44362605ab79 a second time. Values published on these routes come from the working slot after the applicable probe.

### Route selected by a zero `0x10` result

The function next probes offset `0x30` using the saved base.

If the `0x30` result is nonzero, it probes offset `0x48`:

- A zero `0x48` result causes return **0**, without another value-producing call or explicit publication.
- A nonzero `0x48` result causes a second call to F-44362605ab79 with the second argument. The function publishes that call’s 32-bit result and returns **2**.

The second value-producing call is a fresh invocation. Its result need not equal the initial result or the working-slot contents.

On the successful `0x48` route, the explicit publication argument is the fresh return value, not a reread of the working slot.

### Route selected by zero results at `0x10` and `0x30`

The function probes offset `0x34` using the saved base.

If that probe returns nonzero, it probes offset `0x48`, also using the saved base:

- A zero `0x48` result causes return **0**, without another value-producing call or explicit publication.
- A nonzero `0x48` result causes a second call to F-44362605ab79 with the second argument, publication of its returned value, and return **3**.

The routes selected by nonzero results at `0x30` and `0x34` therefore share the same final probe offset and fresh-value mechanism, but return different codes.

### Fallback route

If the probes at `0x10`, `0x30`, and `0x34` all return zero, the function probes offset `0x0C` using the saved base.

That probe’s return value is ignored. Its mutations and other effects are not undone.

The function then invokes **F-2cda0b9de44d** with:

1. The first argument.
2. The working-slot address.
3. The fourth argument.
4. The fifth argument.

After normal return from fallback processing, the function reads the working slot, publishes that value, and returns **1**.

There is no conditional check of the fallback processing result. This function establishes no failure branch between normal return from processing and publication.

## Acceptance examples

These are **conditional static acceptance criteria**, not executed tests. They assume valid accessed storage and normal dependency returns.

1. **Distinct table-reference reads.**  
   If the first shared-reference read yields base A and the second yields base B, the initial probe receives the entry at B plus `0x10`. If that probe returns nonzero, the next probe receives the entry at A plus `0x14`. The function does not substitute B for the saved base.

2. **Return 2 through the working slot.**  
   The `0x10` probe returns nonzero. The `0x14` probe leaves value X in the working slot and returns nonzero. The function reads and publishes X, then returns **2**. No other offset is probed.

3. **Mutation survives a zero probe result.**  
   The `0x10` result is nonzero. The `0x14` probe writes X and returns zero. The `0x18` probe receives the slot containing X. If it writes Y and returns nonzero, Y is published and the result is **3**.

4. **Read without publication.**  
   Results at `0x10`, `0x14`, and `0x18` are nonzero, zero, and zero. The working slot is read after both later probes, but no publication call occurs. The function returns **0**.

5. **Fresh value on the `0x30` route.**  
   Results at `0x10`, `0x30`, and `0x48` are zero, nonzero, and nonzero. If the final probe leaves X in the slot and the second value-producing call returns Y, publication receives Y. The result is **2**.

6. **Fresh value on the `0x34` route.**  
   Results at `0x10`, `0x30`, `0x34`, and `0x48` are zero, zero, nonzero, and nonzero. The second value-producing result is published, and the function returns **3**.

7. **Required final probe returns zero.**  
   Either route reaches `0x48`, which returns zero. The function returns **0**, without a second value-producing call or explicit publication.

8. **Fallback ignores the last probe result.**  
   The `0x10`, `0x30`, and `0x34` results are zero. Whether `0x0C` returns zero or nonzero, fallback processing follows. If processing leaves X in the slot, X is published and the result is **1**.

9. **Saved base, live entry contents.**  
   After the saved base has been captured, an earlier dependency changes its `0x34` entry to X. If execution later reaches that entry, the probe receives X. Changing only the shared reference does not redirect that later read.

10. **Zero and nonzero boundary values.**  
    An initial value-producing result of zero replaces the fourth argument in the slot. A selected publication value of zero is still published. A probe result with only its highest bit set follows the nonzero branch, not a positive-only branch.
