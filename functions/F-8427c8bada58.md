# F-8427c8bada58

## Purpose

F-8427c8bada58 traverses a linked node structure using an opaque comparison dependency. It then either returns a selected candidate directly or delegates to F-f17b5e0d319d. It reports the selected result through caller-provided storage containing a 32-bit word followed by a one-byte discriminator.

**Established behavior:** discriminator zero identifies the direct-candidate path. Discriminator one identifies a path that called F-f17b5e0d319d. Neither the result word nor the discriminator independently establishes that an insertion succeeded.

**Inferred intent:** the search, predecessor-like adjustment, and final comparison resemble ordered-tree insertion with optional duplicate suppression. This interpretation does not establish ordering rules, uniqueness, allocation, balancing, or ownership.

An important part of the contract is temporary-storage reuse. The word forwarded after delegation is not necessarily newly produced by F-f17b5e0d319d: depending on the path, its output storage can already contain zero, a copied header word, or a value modified through an earlier dependency call. Some empty-search paths leave the selected output temporary uninitialized before delegation.

### Temporary storage relevant to observable behavior

Two distinct 32-bit temporary words can serve as F-f17b5e0d319d output storage:

- **General-delegation word:** used by the common delegation path, including nonzero mode and a nonzero final candidate comparison.
- **Immediate-delegation word:** used only when F-f689f7569c43 returns nonzero.

These are descriptive roles, not additional interface arguments.

Before **each** initial-search comparison, the routine writes zero first to the immediate-delegation word and then to the general-delegation word. If the initial search visits no nodes, neither initialization occurs.

The general-delegation word also stores the copied header word passed by address to F-f689f7569c43. The immediate-delegation word’s low byte is subsequently reused to hold the outgoing discriminator.

### Output stores

On normal completion, this routine directly performs:

1. One 32-bit store at result offset `0x00`.
2. One byte store at result offset `0x04`.

It does not directly write offsets `0x05` through `0x07`. The two result stores are separate, not an atomic aggregate update.

The definedness of a delegated result depends on both the selected temporary’s prior state and F-f17b5e0d319d’s actions. Requiring that dependency to initialize its output word on every path would be stronger than the supplied evidence supports.

## Behavior

### Initial search

The routine reads the header pointer through structure offset `0x10`, then reads the initial node pointer at that header’s offset `0x04`. It reads structure offset `0x10` again to initialize the retained search position.

Those are separate header-pointer reads. They are not a promised snapshot.

Before traversal:

- The retained position is the header obtained by the second read.
- The retained comparison outcome is nonzero.
- Neither delegation-output temporary has yet been initialized by this routine.

For every non-null search node, the routine first zeroes both delegation-output words in the order described above. It then calls F-bcefa5957e76 with:

1. The address at structure offset `0x19`.
2. The original opaque argument.
3. The current node’s payload address at offset `0x10`.

After the call, the current node becomes the retained position. A zero comparison result selects the child at offset `0x0c`; any nonzero result selects the child at offset `0x08`.

The child field is read after the comparison returns. Changes made by that dependency can therefore affect the next search step. Only zero versus nonzero is tested; no signed less-than or greater-than interpretation is established.

Traversal ends when the selected search pointer is null. The retained position is the last visited node, or the separately loaded header if no node was visited. The retained outcome is the last comparison result, or the initial nonzero value for an empty search.

The mode byte at structure offset `0x18` is read only after traversal.

### Nonzero mode

A nonzero mode byte bypasses candidate selection, cursor comparison, and predecessor adjustment. It does not bypass the initial search.

The routine invokes F-f17b5e0d319d with:

1. The address of the general-delegation word.
2. The structure address.
3. Literal zero.
4. The retained search position.
5. The original opaque argument.

After the dependency returns, the routine copies the general-delegation word to the caller’s result and writes discriminator one.

If at least one node was visited, the general-delegation word was explicitly zeroed before the last initial comparison. If no node was visited, this routine has not initialized that word before this call. There is no unconditional initialization immediately before delegation.

### Zero mode: selecting a candidate

For zero mode, a writable temporary candidate cursor is initialized to the retained search position.

If the retained comparison outcome is zero, the routine proceeds directly to candidate extraction. It does not call F-f689f7569c43 or perform predecessor adjustment.

If the retained outcome is nonzero, the routine:

- Reads the current header pointer again through structure offset `0x10`.
- Copies the 32-bit word at that header’s offset `0x08` into the general-delegation word, replacing any earlier zero.
- Calls F-f689f7569c43 with the address of the candidate cursor and the address of that same general-delegation word.

Both arguments designate writable temporary storage. The routine does not restore either value after the call.

If F-f689f7569c43 returns nonzero, the routine immediately invokes F-f17b5e0d319d using the **immediate-delegation word**, not the header-copy word. The position argument remains the retained search position, regardless of any candidate-cursor modification.

After this immediate delegation, the immediate-delegation word is copied to the caller’s result and discriminator one is written. Candidate extraction and final candidate comparison are skipped.

If F-f689f7569c43 returns zero, adjustment uses the candidate cursor as it exists after that call.

### Predecessor-like adjustment

The routine first reads the candidate’s metadata byte at offset `0x00`.

If that byte is zero, it reads the candidate’s parent-like pointer and then that record’s offset `0x04` pointer. If this second pointer equals the candidate, the candidate is replaced with its offset `0x0c` pointer. No ordinary subtree or ancestor adjustment occurs in that special case.

Otherwise, adjustment examines the candidate’s offset `0x08` child:

- When that child is non-null, adjustment enters that subtree and follows offset `0x0c` links to a node whose corresponding link is null. That terminal node becomes the candidate.
- When that child is null, adjustment ascends through offset `0x04` parent-like pointers. At each level, it tests whether the previous candidate equals the parent’s offset `0x08` child and makes the parent the new candidate. Ascent continues while the test is equal. The first parent for which it is unequal remains the candidate.

Thus, ancestor adjustment includes the stopping parent; it does not leave the cursor at the child below that parent.

The representation includes repeated reads of child fields. In particular, the offset `0x08` pointer is loaded before a separate read tests it for null, and descent loads an offset `0x0c` pointer separately from the read controlling continuation. A conventional deterministic traversal interpretation requires stable relevant links during those reads.

There are no explicit null checks for the parent-like records dereferenced by adjustment, and no cycle detection. Valid, terminating topology is a precondition.

### Candidate comparison and final choice

The selected candidate is passed to F-39ff2f52ab1b. Its 32-bit result is then passed to F-bcefa5957e76 with:

1. The comparison-context address at structure offset `0x19`.
2. The value returned by F-39ff2f52ab1b.
3. The original opaque argument.

This differs from initial search argument ordering: the extracted candidate value is second, and the original argument is third.

If the final comparison returns zero, the routine writes the candidate cursor to result offset `0x00` and discriminator zero to offset `0x04`. No F-f17b5e0d319d call occurs.

If the final comparison returns nonzero, the routine invokes F-f17b5e0d319d using the general-delegation word and the retained search position. It then forwards that word and writes discriminator one.

A zero final comparison is not independently proven to mean equality. Its meaning depends on F-bcefa5957e76.

## Side effects

The routine directly writes temporary storage and the two caller-result fields. It does not directly update structure fields or node links.

No direct allocation, deallocation, reference-count operation, or payload copy is established. Passing a payload address does not itself transfer ownership.

Dependencies may modify memory, global state, ownership, or topology. This caller establishes no general preservation guarantee.

Temporary-storage exposure matters:

- F-f689f7569c43 receives the candidate cursor and the general-delegation word by address.
- A changed candidate cursor controls subsequent adjustment and extraction.
- A changed general-delegation word remains available for forwarding after later delegation; it is not reset after the cursor call.
- Subsequent dependencies are not proven to preserve memory reachable through previously exposed addresses.
- F-f17b5e0d319d receives one of two distinct output-word addresses, depending on the branch.
- After forwarding the result word, this routine writes the discriminator into the low byte of the immediate-delegation word before copying that byte to caller storage. On the immediate-delegation path, that modifies part of the temporary just supplied as dependency output.

Whether a dependency retains an address, and whether later use would be valid, remain unspecified. No lifetime beyond the invocation is granted for temporary storage.

There is no explicit alias validation. Result storage overlapping structure or node memory can overwrite that memory during the final stores; such overlap is not established as supported. Dependency writes can also affect caller storage independently of this routine’s direct writes.

No explicit error return, allocation-failure check, null-argument check, exception handling, or nonlocal-exit handling is visible. Invalid storage can fail on the relevant access; cyclic topology can prevent termination. Discriminator one is not a success guarantee.

## Acceptance examples

These are conditional static scenarios, not executed tests. They assume accessible storage, terminating topology, normal dependency returns, and any preservation conditions stated.

### Search direction and repeated initialization

Given two visited nodes, the routine zeroes both delegation-output words before each initial comparison, not merely once before traversal.

A zero comparison selects offset `0x0c`; any nonzero result selects offset `0x08`. A negative interpretation of a nonzero result does not change that choice.

### Nonempty search with unchanged general output

Given at least one visited node, nonzero mode, and dependencies that leave the general-delegation word unchanged after its last explicit zeroing, F-f17b5e0d319d can return without writing its output.

The caller then receives word zero and discriminator one. A newly written insertion result is not required for this conditional outcome.

### Empty search with nonzero mode

Given a null initial search pointer and nonzero mode, no initial comparison or temporary zeroing occurs. Delegation uses the general-delegation word and the retained header position.

If F-f17b5e0d319d writes `0x12345678`, that word is forwarded with discriminator one. If it leaves the word unchanged, this routine establishes no defined result word.

### Header copy reused after cursor modification

Given zero mode and a nonzero retained outcome, suppose the copied header word is `0x11223344`. F-f689f7569c43 changes that addressed word to `0x55667788` and returns zero.

If adjustment terminates, final comparison is nonzero, later dependencies preserve that word, and F-f17b5e0d319d leaves it unchanged, the caller receives `0x55667788` with discriminator one. This holds even if the initial search was empty.

### Immediate delegation uses the other word

Given an empty search, zero mode, and a nonzero result from F-f689f7569c43, the initialized header-copy word is not the selected insertion output.

F-f17b5e0d319d receives the immediate-delegation word, which this routine has not initialized. Copying or modifying the header word therefore does not establish a defined result if insertion output is left unchanged.

For a nonempty search, that immediate-delegation word was instead zeroed before the last initial comparison.

### Direct candidate result

Given zero mode and a zero retained search outcome, cursor comparison and predecessor adjustment are skipped.

If extraction followed by final comparison returns zero, the result is the retained candidate cursor with discriminator zero. Neither temporary output word is forwarded.

### Ancestor stopping point

Given ordinary ancestor adjustment, suppose ascent passes parents whose offset `0x08` children equal the prior candidate, then reaches a parent where that equality is false.

That first unequal parent becomes the candidate supplied to extraction.

### Result-byte boundaries

Given non-overlapping result storage and dependencies that do not modify it, the routine writes the result word before the discriminator byte and leaves result offsets `0x05` through `0x07` unchanged.
