Consequences:

- Reachability, operation order, iteration counts, and call counts are unresolved.
- A loop-like operation must not be interpreted as a conventional bounded fill merely because it updates a counter.
- The explicit return operation need not be reached.

The represented arithmetic distinguishes several widths:

Sign-bit expressions must not be replaced by ordinary mathematical comparisons without proving equivalence under that model and the external values.

### Mutable unsigned state and computed-byte operation

One operation replaces the mutable unsigned state with:

\[
(31 \times \text{previous state}) \bmod 256.
\]

Because the state is unsigned 32-bit, multiplication may first wrap at 32 bits; the final mask still gives the expression above. This reduction is not proven to occur before every other use of the third input’s activated value.

A separate computed-byte operation:

- Calculates an address offset from counter state and external arithmetic values.
- Calculates a byte value through additional external factors and a signed 16-bit conversion followed by multiplication by `0x9d`.

- Updates the temporary counter and address-related working state.
- Replaces the mutable unsigned state with the low eight bits of the generated value.

The address-related state can be initialized using an integer conversion of an invocation-local counter’s address. Thus the calculation cannot be specified as a recurrence from the third argument alone.

## Acceptance examples

These are conditional static criteria, not runtime observations.

1. **Grouped word clearing.** If the grouped-clear operation executes with valid writable object storage, it writes four-byte zeros at `0x018`, `0x01c`, and `0x0e8`, in that order. It does not thereby require clearing intervening bytes.

2. **Scalar retained from activation.** If activation establishes scalar value \(s\), and no scalar overwrite occurs before the temporary-record call, that call’s fourth argument is the external scaling factor multiplied by \(s\), under the represented 32-bit arithmetic.

3. **Scalar overwritten after activation.** If the counter-scaling operation overwrites the scalar after activation, and the call follows without another scalar change, its fourth argument scales that overwritten value—not the original first input.

4. **Computed store before call.** If the temporary-record call operation executes, its computed four-byte store at object offset `0x1dc` precedes F-7fb2c125d7bd with fifth argument `0x1a`.

5. **Unsigned-state reduction.** Immediately before the multiply-by-31 reduction, state `0x100` produces `0x00`; state `0xff` produces `0xe1`. These examples do not establish a complete invocation path.

6. **Object-relative computed-byte destination.** If the current write base denotes object offset `0x3e8` and the calculated offset is zero, the computed-byte operation writes at that object location. Describing this as a temporary-record write would be incorrect.

7. **Conditional temporary destination.** If the current write base denotes valid temporary storage and the calculated offset selects an accessible byte there, the computed-byte operation writes that byte. Merely selecting a base through the mutable temporary-related pointer is insufficient to establish either condition.

8. **Dependency-mutated temporary arguments.** If a dependency call changes temporary words later consumed by an object-region call, those later arguments reflect the changed contents. Initial clearing does not justify substituting zero.

9. **Conditional zero return.** If the return operation executes without an update to the result slot, it returns zero. Zero is not thereby established as success.

10. **Null inputs.** A null second or fourth input alone does not establish safe rejection, a particular return, or freedom from memory access. Those outcomes require reachable-transition and dependency evidence.
