# F-9e5e664c8ae7

## Purpose

F-9e5e664c8ae7 accepts one integer argument and produces an eight-byte result.

**Inferred intent:** construct the IEEE 754 binary64 representation of the unsigned magnitude encoded by a 32-bit input pattern. Under the execution conditions below, the conversion is exact for every magnitude from 0 through 4,294,967,295.

This is not a signed conversion and does not take an absolute value. Under conventional two’s-complement interpretation, the input pattern associated with signed −1 represents unsigned magnitude 4,294,967,295 for this purpose.

**Established static boundary:** the supplied material establishes an eight-byte return value, not a floating-point return type or a caller’s interpretation of that value. Binary64 is a mathematical interpretation of the constructed bits.

## Behavior

The branch decision concerns that aligned pattern. It is not an early test of the original argument.

Consequently:

- The initial leading-zero evaluation is reached even for zero input.

\[
2^k \le U < 2^{k+1}, \qquad 0 \le k \le 31.
\]

Under the exact-conversion conditions, the returned binary64 fields satisfy:

\[

The represented value is exactly \(U\). Every nonzero result in this interpretation is positive, finite, and normal. No nonzero input produces a subnormal, infinity, NaN, or negative value. Powers of two have a zero fraction.

No rounding is necessary: a 32-bit unsigned magnitude requires at most 32 significant binary digits, while binary64 provides 53. The numeric result therefore does not depend on a floating-point rounding mode under these conditions.

### Precision and layout properties

Under conventional nonzero leading-zero counting, alignment places the highest input bit at bit 31 without discarding lower significant input bits.

In the resulting representation:

- All significant input bits are retained.
- The low eleven bits of the aligned pattern occupy result bits 31–21.
- Result bits 20–0 are zero.
- The remaining fraction information and the exponent occupy the high result portion.

The four-byte boundary is not a rounding boundary.

The least positive result is `0x3FF0000000000000`, representing 1. The greatest is `0x41EFFFFFFFE00000`, representing 4,294,967,295.

For conventional nonzero counts, the exponent-related signed arithmetic remains within 32-bit signed range. This does not resolve the separate validity of signed left shifts.

### Dependence on right-shift semantics

Arithmetic right shift is necessary for the exact-conversion interpretation.

Every conventionally aligned nonzero pattern has bit 31 set. Sign extension therefore matters. If the relevant right shift instead zero-fills, while all other fixed-width assumptions remain unchanged:

- The fraction field remains unchanged.
- The encoded exponent increases by two.
- The represented value becomes four times \(U\).

For example, input magnitude 1 would produce the encoding of 4.0 rather than 1.0.

This is a conditional consequence of alternative integer semantics, not an observed execution mode.

### Zero and incomplete evaluation

A successful all-zero return is established when the initial evaluation completes and its aligned result is zero.

For zero input, a conventional leading-zero operation may return 32. Shifting a 32-bit word by its full width is not universally valid. The evidence therefore does not establish an unconditional successful conversion of zero under every execution model.

There is no visible recovery path for an exceptional leading-zero evaluation, an invalid shift, or another incomplete evaluation. The presence of an all-zero branch does not make it an exception handler.
