# F-bb77071485ff

## Purpose

F-bb77071485ff selects a region using an indexed table of unsigned 32-bit boundary values. A nonzero starting boundary and the first subsequent nonzero boundary form a usable pair only when the latter is strictly greater than the former. Intermediate zero entries are skipped; a nonzero but nonincreasing candidate terminates the search unsuccessfully.

For a usable pair, the function publishes the boundary difference as the length. It then either publishes a calculated address directly or invokes two dependencies in sequence.

The function distinguishes three behaviors:

- Initial validation rejection: independently generate status 6 without assigning either output or calling a dependency.
- Accepted index but no usable boundary pair: clear both outputs and return 0.
- Usable boundary pair: publish the length, then complete the direct or dependency-backed path.

Return values do not uniquely identify these behaviors. In particular, either dependency can return 6, which this function propagates unchanged. A returned 6 therefore does **not** establish that outputs were untouched or that no dependency ran. Similarly, a returned 0 does not establish that a nonempty region was delivered.

The interpretation of the table as region boundaries is inferred intent. The accesses, comparisons, calculations, assignments, and calls below are established by the supplied static representation.

### Return value

The represented return type is a signed 32-bit status.

- **Independently generated 6:** the descriptor is null, or the requested unsigned index is greater than or equal to the cached bound.
- **Independently generated 0:** no usable boundary pair exists, or the direct-storage path completes.

## Behavior

### Initial validation

For a nonnull descriptor, the function reads the unsigned 32-bit bound at offset 4 and retains it for subsequent comparisons.

It rejects a null descriptor or an index greater than or equal to that bound. Initial rejection returns 6, performs no output assignment, and calls neither dependency. A null descriptor is rejected without reading descriptor storage. A nonnull descriptor with bound zero rejects every requested index.

A later status 6 from a dependency is a different execution path and does not inherit these no-write and no-call properties.

### Starting boundary

After accepting the index, the function reads the table-address field at offset 16 and then the 32-bit table entry selected by four-byte indexing.

A zero starting boundary immediately produces the empty-result behavior:

1. Write zero to the address output.
2. Write zero to the length output.
3. Return 0.

No forward search or dependency call occurs in this case. Later nonzero entries cannot replace a zero starting boundary.

### Candidate search

For a nonzero starting boundary, the function advances the index once and reads the corresponding table entry before checking whether another scan iteration is permitted.

Consequently, the scan can read and use the entry at the cached bound:

- A nonzero entry at that index is evaluated as a candidate.
- A zero entry at that index ends the search.
- The scan does not advance beyond that index.

A zero candidate is skipped only while its index remains below the cached bound. Each continued lookup uses the descriptor’s table-address field again; the supplied representation does not establish one retained table base for the whole scan.

The first nonzero candidate terminates the search. It is usable only if it is strictly greater than the retained starting boundary.

If that candidate equals or is smaller than the start, later entries are not considered. If no usable candidate is found, the function writes zero to the address output, then zero to the length output, and returns 0 without calling either dependency.

The bound is retained from initial validation rather than reread during the search. The starting boundary is likewise retained.

### Length publication

For a usable pair, the length is the unsigned boundary difference:

\[
\text{length}=\text{ending boundary}-\text{starting boundary}.
\]

The function writes this value to the length output **before** reading the direct-storage selector at descriptor offset 20.

This ordering is observable when the length output aliases descriptor storage. For example, a length write to offset 20 changes the value subsequently used to select the delivery path.

### Direct-storage delivery

After publishing the length, the function reads descriptor offset 20.

If the value is nonzero, the function reads that field again for the address calculation and writes:

\[
\text{address}=\text{direct-storage base}+\text{starting boundary}-1.
\]

It returns 0 without calling either dependency.

The calculation uses the starting boundary, not the requested index. The adjustment and zero-entry handling suggest one-based offsets with zero reserved for absence; that interpretation is inferred rather than independently established.

No check verifies that the calculated address refers to accessible storage of the published length.

### Dependency-backed delivery

If the direct-storage selector is zero after length publication, the function reads and retains the opaque 32-bit field at descriptor offset 0. It then obtains the base at offset 12 and calculates:

\[
\text{position argument}=\text{base}+\text{starting boundary}-1.
\]

It calls F-e40a3ceddab2 with the retained opaque value and the calculated position argument.

If that dependency returns nonzero, the function immediately returns that status. This includes a returned status of 6. F-977b73bb902a is not called.

If F-e40a3ceddab2 returns zero, the function calls F-977b73bb902a with:

- The same retained opaque value.
- The retained boundary difference.
- The original address-output pointer.

It returns the second dependency’s status unchanged, including 0 or 6.

There is no subsequent clearing, restoration, or republication of either output. The length was written before either call, but its final contents are not guaranteed if a dependency changes accessible memory. The opaque argument is reused from the retained value, not recovered from the descriptor after the first call.

### Widths and arithmetic

The index, bound, boundaries, and boundary comparisons are unsigned 32-bit quantities.

For a usable pair, the start is at least 1 and the end is strictly greater. Therefore:

\[
1\leq\text{length}\leq 2^{32}-2.
\]

The difference fits in unsigned 32-bit storage. It need not fit as a positive signed 32-bit value. The function performs no signed-range rejection before writing it to the represented signed output location or passing it to the final dependency. A high-bit-set output pattern does not indicate a negative boundary difference.

The scan index cannot wrap under the displayed control flow: the accepted index is below a 32-bit bound, advancement can reach that bound, and no further advancement occurs once it is reached.

Table-address calculations and base-plus-boundary calculations have no overflow checks. Their represented 32-bit unsigned arithmetic can wrap. This arithmetic behavior does not establish that a resulting address is valid. External pointer representation, conversion rules, alignment requirements, and byte order remain unspecified.

## Side effects

### Direct output writes

| Execution path | Writes performed directly by this function |
|---|---|
| Initial rejection | None |
| Zero start or unusable candidate search | Address output = 0, then length output = 0 |
| Direct-storage completion | Length first, then calculated address |
| Dependency-backed attempt | Length before either dependency; no direct address-output assignment |

This table is path-based, not status-based. In particular, status 6 can correspond either to the first row or to a dependency-backed attempt.

If both output pointers identify the same 32-bit location:

- Clearing leaves zero.
- Direct delivery leaves the calculated address because that write occurs last.
- Dependency-backed delivery first writes the length; subsequent contents depend on dependency behavior.

Output overlap with the descriptor can affect later reads, including delivery selection, the opaque argument, and the position base. Overlap is neither detected nor prevented.

### External state and ownership

The dependency-backed path can change external state through either dependency. The supplied material does not establish whether that state concerns position, storage, allocation, caches, or another resource.

No explicit allocation, deallocation, locking, ownership transfer, or release operation is performed directly by this function. That observation does not constrain dependency effects.

The calculated direct address does not establish ownership, lifetime, mutability, or a release obligation. The same properties are unknown for any address produced by F-977b73bb902a.

Neither dependency is assumed to preserve globals, descriptor contents, outputs, or other reachable memory, nor to own or release any resource.

### Errors and partial publication

Initial validation is the only place this function independently generates status 6. Either dependency can also return 6 and have it propagated after length publication.

Invalid accesses are not handled by an explicit recovery path in the supplied representation. They must not be treated as documented status-6 outcomes.

A dependency failure can occur after output publication or external-state changes. The function provides no transactional rollback.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, memory supports all required accesses, outputs do not overlap inputs or each other, and calculated addresses are valid.

1. **Null descriptor.** A null descriptor returns independently generated status 6. Outputs remain unchanged, and neither dependency runs.

2. **Index at the bound.** With bound 4 and requested index 4, initial validation returns 6 without reading a table entry or assigning outputs.

3. **Zero start.** For an accepted index whose starting entry is zero, both outputs become zero in address-then-length order. The function returns 0 without examining later entries.

4. **Skipped zeros.** With bound 4, requested index 0, and entries 5, 0, 0, 13, the selected length is 8. With direct-storage base 4096, the address output becomes 4100 and the function returns 0.

5. **Usable entry at the bound.** With bound 3, requested index 2, entry 2 equal to 9, and readable entry 3 equal to 14, the selected length is 5. An initial request for index 3 would nevertheless be rejected.

6. **Zero at the bound.** With the same bound and start, but entry 3 equal to zero, both outputs are cleared. No entry beyond 3 is read.

7. **Nonincreasing candidate.** With starting boundary 9 and the next nonzero boundary equal to 8 or 9, both outputs are cleared. A later boundary of 20 is not considered.

8. **First dependency returns 6.** A usable pair defines length 8 and the direct-storage selector is zero. The function writes 8 to the length output, calls F-e40a3ceddab2, and returns 6 if that dependency returns 6. The second dependency is not called. This function does not assign the address output, but dependency effects remain possible.

9. **Second dependency returns 6.** Under the same pair and selector, F-e40a3ceddab2 returns zero and F-977b73bb902a returns 6. Both calls occur, the returned status is 6, and no output restoration follows. Thus status 6 alone cannot distinguish this execution from initial rejection.

10. **Other propagated failure.** If the first dependency returns 17, the function returns 17 immediately after length publication. If the first returns zero and the second returns 17, the latter status is returned without clearing outputs.

11. **Large unsigned length.** Starting boundary 1 and ending boundary \(2^{32}-1\) produce the 32-bit length pattern `0xFFFFFFFE`. It is not rejected because its signed interpretation is negative.

12. **Length aliases the selector.** If the length output identifies descriptor offset 20, a usable pair writes its positive length there before delivery selection. The subsequent selector read therefore observes that written value, absent other mutation, and selects direct delivery rather than the previously stored zero selector.
