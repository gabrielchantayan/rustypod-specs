# F-7bab64075080

## Purpose

F-7bab64075080 is represented as a flag-dependent indirect control-transfer operation. On the recovered path selected by a set incoming zero flag, it derives an aligned destination from two incoming register values and the incoming carry flag, then transfers control to that destination.

The supplied representation does not establish a higher-level purpose, such as dispatching an application operation, processing an object, or reporting an error. It also does not reliably establish whether the indirect transfer is an ordinary call, a tail transfer, or part of a larger instruction sequence.

**Evidence boundary:** the available representation reports invalid instruction data and substantial control-flow recovery failures. This contract therefore distinguishes the visible arithmetic and branch selection from unresolved execution behavior. It is not a claim that the original executable has been fully recovered.

### Destination calculation

For the set-zero-flag path, define:

- \(W\): the incoming 32-bit value from register 12.
- \(L\): the incoming 32-bit link-register value.
- \(s\): the low five bits of \(L\), giving a selector from 0 through 31.
- \(C\): the incoming carry flag.
- \(B = \mathtt{0x0897BF40}\).

For a nonzero selector, the visible expression combines a logical right shift of \(W\) by \(s\) with a left shift by \(32-s\). Within a 32-bit word, this corresponds to rotating \(W\) right by \(s\) bits. Call that result \(R\).

The subtraction amount is:

- \(B\) when the carry flag is set.
- \(B+1 = \mathtt{0x0897BF41}\) when the carry flag is clear.

The destination is then represented by the following relationship:

\[
T = \bigl((R-B-\delta)\bmod 2^{32}\bigr)
    \mathbin{\&} \mathtt{0xFFFFFFFC},
\]

where \(\delta=0\) for set carry and \(\delta=1\) for clear carry.

This relationship describes fixed-width unsigned arithmetic, not unbounded integer arithmetic. In particular:

- Subtraction underflow wraps modulo \(2^{32}\).
- There is no visible overflow or underflow error.
- Clearing the final two bits occurs **after** subtraction.
- The resulting destination is divisible by four.
- Alignment discards information; different intermediate results can produce the same destination.

The carry-dependent difference is one before alignment. After alignment, toggling carry can either leave the destination unchanged or move it by four bytes modulo \(2^{32}\). It must not be described as always changing the destination by one byte.

### Zero rotation selector

A selector of zero requires a separate evidence qualification.

The displayed expression then contains a left shift by 32. Literal evaluation under conventional 32-bit C shift rules would not define that operation. A machine rotate operation would commonly leave the word unchanged for a zero rotation, but the supplied material does not establish that machine behavior independently.

Consequently:

- The low-five-bit selector calculation is established by the visible expression.
- The rotate interpretation is well-supported for selectors 1 through 31.
- Treating selector zero as an identity rotation is inferred intent, not an unconditional guarantee.
- Selector-zero behavior remains **documented_only** pending authoritative instruction semantics or execution evidence.

Selectors separated by multiples of 32 have the same visible low-five-bit value. Whether zero-selector cases therefore share ordinary identity-rotation behavior remains subject to this qualification.
