# F-58252715e9e7

## Purpose

F-58252715e9e7 coordinates dependency calls, scans an object-selected array of 24-byte records, clears one byte in each qualifying record, and conditionally invokes an object-held callback.

Callback dispatch depends on three observations:

- Whether the callback-target field is nonzero at the final target check.
- Whether any probe performed during this invocation returned nonzero.
- If no probe returned nonzero, whether an object-held suppression byte is zero.

The probe condition is invocation-local and sticky: once a probe returns nonzero, subsequent zero results do not undo it.

These are structural behaviors. The supplied evidence does not establish that the function releases resources, completes an operation, resets an object, or sends a notification.

## Behavior

### Initial dependency call

The function starts with its remembered probe condition false and calls F-7107f219f55e with numeric argument zero.

This call precedes the first record-count read. Any changes it makes to the count, array base, or other subsequently accessed state can affect the invocation.

### Mutable record scan

The logical record index is a signed 32-bit value initialized to zero.

Before each iteration, the function reads the current signed 32-bit count at object offset +0x04. An iteration is admitted only when the current index is less than that newly read count.

For an unchanged count:

- A zero or negative count admits no iterations.
- A positive count admits indices from zero through count minus one, subject to valid address calculations and accesses.

The count is not retained as an entry-time snapshot. Changes made by dependencies can shorten or extend the remaining scan.

**Count mutation alone cannot make the scan unbounded.** Assuming valid, defined execution and normally returning dependencies, there are at most 2,147,483,647 iterations. The largest signed 32-bit count is 2,147,483,647, so the largest index any count can admit is 2,147,483,646. Incrementing that index produces 2,147,483,647 without overflow; no signed 32-bit count can admit another iteration.

This is an index-control upper bound, not a guarantee that an array of that size can be traversed. Record-offset multiplication and address formation have separate range and validity requirements. A dependency may also fail to return before the bound becomes relevant.

For each admitted index:

1. The function reads the current array base from object offset +0x08.
2. It locates the indexed record using the 24-byte stride.
3. It reads the record’s 32-bit value at offset +0x04.

If that value is zero, the function skips all per-record calls and the explicit byte clear for this iteration. It increments the index and checks the current count again.

If that value is nonzero, the following observable sequence occurs:

1. F-4ca91beb8adc is called without explicit arguments.
2. Its 32-bit integer result is tested for nonzero. A nonzero result sets the remembered probe condition to true; a zero result leaves that condition unchanged.
3. The array-base field is read again.
4. The 32-bit value at the same logical index’s record offset +0x04 is read from that current array.
5. F-94e2e30e208d is called with this newly read value.
6. After that call returns, the array-base field is read again.
7. Zero is written to the single byte at the same logical index’s record offset +0x08 in that current array.
8. The index is incremented, and the current count is checked again.

Eligibility is not retested after the probe. A probe that changes the argument slot to zero does not cancel the dependency call or byte clear.

The array base is likewise not retained across these calls. Consequently, the eligibility read, argument read, and byte write can refer to different arrays while retaining the same logical index. Each reached access must independently remain valid.

The direct byte write does not clear the 32-bit eligibility/argument slot or any adjacent bytes.

### Unconditional post-scan calls

After the scan terminates, the function calls:

1. F-e89c8f50a7df with the original object address and numeric argument 0x44, or 68 decimal.
2. F-ffdded7ca165 with numeric argument zero.

These calls occur even when no iterations were admitted or every visited record had a zero eligibility value, provided preceding execution remains valid and all preceding calls return normally.

The application-level meaning of 68 is unknown.

### Flag-controlled calls

After both post-scan calls return, the function reads the 32-bit flags field at object offset +0x0C and tests mask 0x10.

If the masked bit is clear, neither flag-controlled call occurs.

If the bit is set, the function calls:

1. F-ad6543e399ad with the original object address.
2. F-aacdb1821b51 with the original object address and numeric argument zero.

There is one flag test for the pair. Clearing the bit during the first call does not cancel the second call.

Changes to the flags made by earlier dependencies can affect this phase because the flags are read only after those earlier calls.

### Callback decision and dispatch

The function next reads the callback-target field at object offset +0xB0.

If it is zero, the function returns. The suppression byte is not read for callback gating on this path.

For a nonzero target:

- If the remembered probe condition is true, callback dispatch proceeds without reading the suppression byte for this gate.
- Otherwise, the function reads the byte at object offset +0x1C. A nonzero value causes return; zero permits dispatch.

On the dispatch path, the function invokes the callback target stored at object offset +0xB0 and supplies the 32-bit value stored at object offset +0xAC as its sole explicit argument. It does not use a callback result.

The target is referenced again for invocation rather than being retained solely from the earlier zero check. The supplied representation does not establish the relative machine-level order of the final target and argument loads. It also supplies no synchronization contract for changes between the check and invocation.

If the callback returns normally, the function performs no further explicit work before returning.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Unless a case specifies mutation, assume stable fields, valid storage and arithmetic, normally returning calls, and no concurrent modification.

### Empty or negative count

With a count of zero or a negative count:

- The initial call occurs.
- No records are accessed by the scan.
- Both unconditional post-scan calls occur.
- The flags and callback gates are still evaluated.

If the callback target is nonzero and the suppression byte is zero, the callback can run without any record having been processed.

### Zero eligibility value

With count one and a zero record value at +0x04:

- No probe or F-94e2e30e208d call occurs for the record.
- Its +0x08 byte is not explicitly cleared.
- Callback eligibility is determined by the final target and suppression byte, since no probe set the remembered condition.

### Qualifying record and zero probe result

With one nonzero eligibility value and a zero probe result:

- The argument slot is reloaded and passed to F-94e2e30e208d.
- The +0x08 byte is cleared afterward.
- The remembered condition remains false.
- A nonzero suppression byte blocks callback dispatch.

### Sticky probe condition

With two qualifying records whose probes return nonzero and then zero:

- Both records receive their per-record call and byte clear.
- The remembered condition remains true.
- A nonzero callback target permits dispatch even when the suppression byte is nonzero; that byte is not read for the gate.

### Probe changes the argument value

If a record initially qualifies and the probe changes its +0x04 slot to zero without changing the array base:

- The record remains admitted.
- F-94e2e30e208d receives zero.
- The byte clear still follows.

### Array replacement before the write

If F-94e2e30e208d replaces the array base with another valid array:

- The byte clear uses the replacement base and current logical index.
- The clear is not guaranteed to affect the array used for eligibility or argument loading.

### Count changes during processing

If processing index zero changes the count from three to one, index zero finishes and the next comparison ends the scan.

If processing index zero instead changes the count from one to three, indices one and two become eligible for subsequent iterations, assuming the count then remains three.

Repeated count increases cannot admit index 2,147,483,647. The finite scan bound remains applicable, although it does not guarantee representable record addresses or completion of dependencies.

### Flag changes

If a post-scan dependency sets bit 0x10 before the flags read, both flag-controlled calls occur.

If F-ad6543e399ad clears that bit, F-aacdb1821b51 still occurs because no second flag test intervenes.

### Zero callback target

If the target is zero at the final target check:

- No callback is invoked.
- The suppression byte is not read for callback gating.
- Previously completed calls and writes are not undone.
