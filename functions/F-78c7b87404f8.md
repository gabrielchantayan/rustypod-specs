### Ordered observable requests

The following stages occur in the listed order, subject to earlier operations continuing.

1. **Initial primary-condition branch**
   - If the primary condition holds, issue five consecutive software-interrupt requests, each with immediate **0x1DDF1D**.
   - Otherwise, issue one coprocessor-move request with leading selector fields **0xF, 5, 0**, followed by coprocessor operands **12 and 13**, in that order.

   These alternatives are mutually exclusive in the visible representation.

2. **Earlier conditional load**
   - If the negative and overflow conditions compare equal, issue a coprocessor long-load request.
   - Its selector is **5**.
   - Its coprocessor-associated operand is **10**.
   - Its represented address expression is the first address-base value plus **0x260**, or 608 decimal.
   - If the conditions compare unequal, this stage issues no request.

3. **Second primary-condition interrupt group**
   - If the primary condition holds, issue four consecutive software-interrupt requests with immediate **0x1DDF1D**.
   - Otherwise, this stage issues no request.

4. **Independent nonzero-condition interrupt**
   - If the incoming zero condition is false, issue one software-interrupt request with immediate **0x1EDF1D**.
   - If it is true, this stage issues no request.

   This condition is independent of whether the negative and overflow conditions match.

5. **Main primary-condition branch**
   - If the primary condition holds, issue this ordered sequence:
     1. Seven software-interrupt requests with immediate **0x1CDF1C**.
     2. One coprocessor-move request with leading selector fields **0xF, 7, 0**, followed by operand **12 in both operand positions**.
     3. One software-interrupt request with immediate **0x1CDEFC**.
     4. One software-interrupt request with immediate **0x1DCEBB**.
     5. Ten software-interrupt requests with immediate **0x1DDF1D**.
   - Otherwise, issue one coprocessor-move request with leading selector fields **0xF, 5, 0**, followed by operands **11 and 13**, in that order.

   The duplicated use of operand 12 in the primary branch is significant. The evidence does not establish whether that operation reads, writes, or otherwise interprets either operand position.

6. **Later conditional load**
   - If the negative and overflow conditions compare equal, issue a second coprocessor long-load request.
   - Its selector is **5**.
   - Its coprocessor-associated operand is **10**.
   - Its represented address expression is the second address-base value plus **0x25C**, or 604 decimal.
   - Otherwise, this stage issues no request.

7. **Final primary-condition interrupt group**
   - If the primary condition holds, issue four consecutive software-interrupt requests with immediate **0x1CDF1C**.
   - Otherwise, this stage issues no request.

8. **Terminal marker**
   - Reach the represented invalid-instruction termination.
   - No ordinary return or continuation beyond this marker is supplied.
