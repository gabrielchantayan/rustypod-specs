# F-17411ec88deb

## Purpose

F-17411ec88deb performs an ordered sequence of memory mutations using two explicit inputs, three additional incoming machine-state values, several pointer-like values loaded from memory, and a fixed-address data region. It ends with an indirect control transfer carrying four arguments.

**Established static evidence:** the supplied representation contains repeated stores, mixed-width accesses, pointer-derived addressing, overlapping fields, and an unresolved indirect destination. It provides no validation, explicit error result, allocation, or release operation.

**[INFERENCE]** The operation may belong to a larger stateful execution context rather than being independently callable through its displayed two-input interface. Its application-level purpose cannot be established.

This contract describes the visible access sequence, not a conventional object model. Field names below identify access locations only; they do not establish structure types, ownership, or independent storage.

## Behavior

### Repeated-write phase

The opening phase repeatedly touches four destinations in a fixed order:

1. A byte at base A plus 0x11.
2. A word at base B plus 0x34.
3. A word at twice base A plus 0x54.
4. A byte at base B plus 0x19.

The first byte receives the low eight bits of base B. The fourth receives the low eight bits of base A. The third receives the primary input’s 32-bit pattern.

The first write to base B plus 0x34 receives the secondary input. Every subsequent write there receives twice base A as a 32-bit unsigned result.

The repeated groups are unconditional in the supplied representation. The final group is partial: it contains the first two writes, then proceeds to the next phase without another write to the third or fourth destination.

Repeated writes must not be treated as a single final-state assignment when describing the visible sequence. They can matter for overlapping memory, externally observed accesses, or faults. Whether the underlying execution preserves every displayed repetition is not independently established.

The exact repetition count is **documented_only** in this contract; no numerical count is asserted.

### Initial snapshots and fixed-address updates

After the last repeated word write, the operation reads a word from fixed address 0xA9, then reads a word from the primary-input base plus 0x74.

It next writes one byte at fixed address 0x3A. The value is the low eight bits of twice the low byte of base A plus 0x30. Thus this is a wrapping byte transformation, not a validated decimal-character conversion.

The next word reads obtain:

- A value from base C plus 0x14.
- A value from base A plus 4.

These values are retained for later use. Their later destinations receive these earlier snapshots, not necessarily the contents then present at their original locations.

The operation then writes:

- The low byte of base A at base C plus 0x0D.
- Byte 0x6C at base A plus 8.
- The low byte of base B at base A plus 0x0D and then plus 9.
- Base C’s 32-bit value at base C plus 0x54.
- The low byte of the fixed-address word snapshot at fixed address 0x67.

The order above is material if destinations overlap one another or locations read later.

### Linked-field updates

A word is now read from base C plus 0x44. Call its captured value the **link value**.

The byte at fixed address 0x67 is copied to fixed address 0x21. The operation then places the low byte of the link value at base A plus 0x10 and the complete link value at base B plus 0x54.

A shifted form of the link value supplies a byte written at base C plus 1. The displayed shift is a signed right shift, with a count derived from the low eight bits of base A. The result is then narrowed to one byte.

For nonnegative link values and counts below 32, the ordinary right-shift interpretation is sufficient. Negative operands and counts of 32 or greater require target-specific clarification; they must not silently be assigned a portable result.

The word at base B plus 0x54 is then overwritten with base A’s 32-bit value.

Next, the operation reads a word at base A plus 0x40. After that read:

- The earlier snapshot from base A plus 4 is written at base B plus 0x74.
- The newly read word is written at base A plus 0x10.
- Base C’s value is written at base B plus 0x44.
- The current byte at fixed address 0x67 is written at base A plus 9.
- The low byte of base A is written at base C plus 9.
- The earlier fixed-address word snapshot is written at base A plus 0x44.

The word write at base A plus 0x10 overlaps the earlier byte write at that same offset and the repeated-prefix byte location at plus 0x11. This overlap is established independently of any aliasing between bases.

### First loaded destination

The next word read is from base A plus 0x54. Call the captured value the **first destination**. It is not necessarily the address written during the repeated phase: that earlier address was twice base A plus 0x54.

After this read, the current byte at fixed address 0x67 is again written at base A plus 9.

The low byte of the earlier word read from the primary-input base plus 0x74 is then written at the first destination plus 0x0D. The earlier snapshot from base C plus 0x14 is written back at base C plus 0x54, replacing the prior self-reference there.

A word is then read at base A plus 0x14. Its low byte will later be used at the first destination plus 0x11.

Before that later use, the operation:

- Writes the low byte of the primary-input snapshot at base C plus 0x11.
- Writes the low byte of the first destination at base A plus 9.
- Writes the full first-destination value at base A plus 0x44.

Consequently, the fixed-address snapshot previously written at base A plus 0x44 is not that field’s last direct write.

### Final linked accesses and indirect transfer

The operation reads a word at base C plus 4. Call this captured value the **second address value**.

A halfword with numeric value 0x0065 is written at twice the second address value. A word is then read at the second address value plus 0x64; call that captured word the **transfer value**.

The next mutations place:

- The low byte of the snapshot from base A plus 0x14 at the first destination plus 0x11.
- The 32-bit numeric value 100 at the first destination plus 0x54.

A word is then read at the second address value plus 0x74. This read occurs after both writes to the first-destination region, so aliasing can affect its result.

The operation next reads a word at base C plus 0x64. Call it the **final destination**. It then writes the low byte of the second address value at base C plus 9, writes the transfer value at the final destination plus 0x54, and writes the final-destination value as a word at twice the transfer value.

Finally, an unresolved indirect destination receives four arguments in this order:

| Position | Argument |
|---|---|
| 1 | Numeric constant 0x72 |
| 2 | Transfer value |
| 3 | Earlier snapshot from base C plus 0x14 |
| 4 | Word read from the second address value plus 0x74 |

The visible mutations precede this transfer. No argument is an explicit ownership-transfer indicator.

- Word stores can overwrite adjacent byte fields.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Initial overwrite remains observable

Given valid, independent destinations and a secondary input different from twice base A, an access trace must distinguish the first word write at base B plus 0x34 from subsequent writes there. A final-memory comparison alone cannot establish this behavior.

### Byte arithmetic wraps

If base A’s low byte is 0xF0 and execution reaches the fixed-address byte update, the numeric byte written at address 0x3A is 0x10: twice 0xF0 plus 0x30, reduced to eight bits. No range rejection or decimal-digit normalization is visible.

### Earlier snapshots survive later source changes

If the word at base C plus 0x14 initially contains 0x12345678, and no earlier operation changes it before its read, that captured value is later written at base C plus 0x54 and passed as the third indirect argument. A subsequent change to its original location does not by itself change the captured value.

### Overlapping field replacement

If no other alias affects the region, the word written at base A plus 0x10 replaces the earlier byte at plus 0x10 and covers the byte at plus 0x11. Expected individual bytes depend on the target’s byte order.

### Distinct calculated addresses

A checker must distinguish base A plus 0x54 from twice base A plus 0x54. The first-destination read uses the former; repeated primary-input stores use the latter.

### Final transfer arguments

If execution reaches the indirect transfer, its first argument is 0x72, its second is the captured transfer value, its third is the earlier base-C-plus-0x14 snapshot, and its fourth is the later second-address-plus-0x74 snapshot. Changes made by intervening stores matter only where they precede the respective capture.

### Unsupported shift case
