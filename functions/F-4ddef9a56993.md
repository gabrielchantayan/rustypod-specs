# F-4ddef9a56993

## Purpose

F-4ddef9a56993 conditionally decodes fields from an opaque input into a caller-supplied mutable record. Its control flow depends on a discriminator already present in that record, values returned by dependencies, and two optional marker values.

The established behavior is a sequence of dependency calls, record updates, discriminator-based dispatch, and early returns. The routine does not construct a complete record from scratch, clear unused fields, or roll back changes on failure.

**Inferred intent:** the input is a bit-oriented encoded configuration, with indexed or explicit numeric values and optional extension information. Field names below describe their observable roles, not an established external format.

The value `3` is a distinguished early-return and rejection result. The meaning of other returned values is not established.

## Interface

### Inputs and return value

| Input | Established representation and use |
|---|---|
| Input handle | An opaque 32-bit value forwarded to dependencies without local interpretation. |
| Input length | A 32-bit integer used only in two remaining-bit calculations. It is multiplied by eight, suggesting a byte count. |
| Output record | A mutable pointer addressed at fixed byte offsets. The routine both reads existing contents and writes decoded fields. |

The return value is a 32-bit integer. It is either:

- `3`, from an explicit rejection or propagation of a dependency result equal to `3`; or
- the most recently retained result from a status-producing dependency.

Bit-field reader results do not replace the retained status.

A local 32-bit cursor starts at zero. Its address is passed to every dependency call. Cursor interpretation, advancement, and validity checking belong to those dependencies and are not established here.

## Behavior

### 1. Initial status operation

The cursor is initialized to zero. F-9d95bb1f8e3e is called with the input handle and cursor address, without an explicit record argument.

If its result is `3`, the routine returns `3` immediately. No direct record writes have occurred at this point, although dependency side effects remain possible.

Any other result becomes the retained status. It does not prevent subsequent decoding.

### 2. Primary numeric value and common initialization

The routine requests four bits from F-567b1e4ae69d and narrows the result to an unsigned byte.

After that call returns, it reads and captures a global lookup-table base. The captured base is reused for later indexed numeric values, even if subsequent dependency calls change the global base.

Observable operations then occur in this order:

1. Store the selector byte at `0x18`.
2. Resolve the primary numeric value:
   - Selector `15`: request 24 bits from F-567b1e4ae69d.
   - Any other selector: load four bytes from the captured table at four times the selector.
3. Store that four-byte value at `0x14`.
4. Request four bits and store the low byte at `0x01`.
5. Write `0xFF` separately to offsets `0x1C`, `0x1D`, `0x1E`, and `0x1F`, in ascending order.
6. Write `0xFF` separately to offsets `0x10`, `0x11`, `0x12`, and `0x13`, in ascending order.
7. Read the discriminator at `0x00`.

The selector is not explicitly masked to four bits. A conventional bit reader would return a value from zero through fifteen, but that range is a dependency assumption. The actual local narrowing permits selector values through 255.

### 3. Special handling for initial discriminator 5 or 29

If the discriminator read after common initialization is `5` or `29`:

1. Copy that discriminator to `0x04`.
2. Write bytes `01 00 00 00` at `0x1C` through `0x1F`, in ascending order.
3. For discriminator `29` only, write bytes `01 00 00 00` at `0x10` through `0x13`, in ascending order.
4. Request four bits and store the unsigned low byte at `0x0C`.
5. Resolve the secondary numeric value using the same selector rule as the primary value: selector `15` requests 24 bits; otherwise load from the captured table.
6. Store the resulting four-byte value at `0x08`.
7. Call F-9d95bb1f8e3e with the input handle, cursor address, and record pointer.

If this call returns `3`, return `3`. Otherwise replace the retained status with its result and continue.

For any other initial discriminator, write zero to `0x04`; do not directly initialize `0x08` or `0x0C`.

The discriminator is reread for the next dispatch. It is not assumed to remain equal to the value that selected this special handling.

### 4. Main discriminator dispatch

The next discriminator read selects one of three behaviors.

| Discriminator | Behavior |
|---|---|
| `1–7`, `17`, `19–23` | Call F-3eee64f47633 with the input handle, cursor address, and record pointer. |
| `8`, `9`, `12–16`, `24–28`, `32–35`, `37`, `38` | Return `3` immediately. |
| `36` | Request five bits, store the low byte at `0x0D`, then return `3`. |
| All other values | Proceed directly to the secondary dispatch. |

For F-3eee64f47633, result `3` causes an immediate return of `3`. Any other result replaces the retained status, after which execution proceeds to the secondary dispatch.

Consequently, `0x0D` can be updated even though the routine rejects the operation.

### 5. Secondary discriminator dispatch

The discriminator is read again. If it is `17` or any value from `19` through `27`:

1. Request two bits.
2. Store the low byte at `0x03`.
3. If that stored byte is `2` or `3`, return `3`.
4. Otherwise continue to optional-extension handling.

All other discriminator values proceed to optional-extension handling without directly writing `0x03`.

Values `24–27` cannot reach this step unchanged through their own main-dispatch cases, because those cases return `3`. They can nevertheless be selected here if F-3eee64f47633 changes the discriminator after an admitted main-dispatch value.

### 6. First optional marker

Optional-extension handling first reads `0x04`. If that byte is `5`, return the retained status without attempting a marker read.

Otherwise, calculate a remaining-bit quantity from the 32-bit input length multiplied by eight, minus the current 32-bit cursor, and compare the result as unsigned with `16`.

If the unsigned result is less than `16`, return the retained status.

If it is at least `16`:

1. Request eleven bits.
2. Store the returned 32-bit value at `0x20`.
3. If the value is not `0x2B7`, return the retained status.
4. Call F-9d95bb1f8e3e with the input handle, cursor address, and record pointer.
5. If its result is `3`, return `3`.
6. Otherwise replace the retained status with that result.
7. Read the discriminator and copy it to `0x04`.
8. Read the discriminator again; unless this read yields `5`, return the retained status.

A marker mismatch is consumed and recorded. There is no visible rewind or restoration.

### 7. Extension flag and secondary numeric value

After a matching first marker and a subsequent discriminator of `5`:

1. Request one bit.
2. Store the returned 32-bit value at `0x1C`.
3. If that returned value is exactly `1`:
   - Request four bits.
   - Store the unsigned low byte at `0x0C`.
   - Resolve and store the secondary numeric value at `0x08`, using the captured table or a 24-bit read for selector `15`.

For any returned flag value other than exactly `1`, the routine leaves `0x08` and `0x0C` unchanged at this stage. It does not clear them when the flag is zero.

### 8. Second optional marker

Recalculate the unsigned remaining-bit quantity using the current cursor.

If it is less than `12`, return the retained status.

Otherwise:

1. Request eleven bits.
2. Overwrite `0x20` with that returned 32-bit value.
3. If it differs from `0x548`, return the retained status.
4. Request one bit.
5. Store its returned four-byte value at `0x10`.
6. Return the retained status.

Thus a second marker, whether matching or not, replaces the first marker in the record.

## Side effects

### Partial mutation

All writes are immediate. Returning `3` does not undo primary decoding, sentinel initialization, extension updates, marker storage, or dependency mutations.

Fields not reached retain their previous contents, except where dependencies modify them. In particular:

- `0x03` is not universally initialized.
- `0x0D` is written only on the discriminator-36 rejection path.
- `0x20` is untouched unless a marker read occurs.
- `0x08` and `0x0C` can retain stale values.
- The two flag regions begin as all-ones bytes but may later be overwritten.

### Arithmetic and bounds

The remaining-bit checks use an unsigned 32-bit interpretation of the displayed multiply/subtract result. They are not equivalent to a validated nonnegative remaining length.

Under target 32-bit wrapping arithmetic, a cursor beyond the nominal end can produce a large unsigned remainder and therefore permit another read. Negative lengths and multiplication overflow are not explicitly rejected. Portable signed-overflow semantics are not established by the supplied representation.

The initial fields, special-discriminator fields, two-bit field, and five-bit rejection field have no visible local length checks. Dependency behavior determines whether insufficient input is rejected, tolerated, or accessed unsafely.

### Shared state and aliasing

The global table pointer is captured once, but table contents are loaded when each indexed value is needed. No table contents are snapshotted.

Dependencies may modify the cursor, record, globals, or table contents. The visible routine provides no isolation or preservation guarantee. Aliasing between the record, input storage, and table is not ruled out; such aliasing can make write/read order observable.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume dependencies return values within their requested widths and do not unexpectedly mutate unrelated state.

1. **Initial distinguished result.** If the first F-9d95bb1f8e3e call returns `3`, the routine returns `3` before any direct record write or field-reader call.

2. **Indexed primary value.** If the first four-bit result is `2`, the record receives selector `2` at `0x18` and the four-byte value at captured-table offset eight at `0x14`. No 24-bit request occurs for this primary value.

3. **Explicit primary value.** If the first selector is `15`, a 24-bit request supplies `0x14`; no primary table-entry load occurs.

4. **Initial discriminator 29.** Both flag regions receive bytes `01 00 00 00`, offset `0x04` receives `29`, and a secondary numeric value is decoded before the additional F-9d95bb1f8e3e call.

5. **Rejecting two-bit value.** If main dispatch admits discriminator `17`, F-3eee64f47633 returns a non-`3` result without changing it, and the two-bit reader returns `2`, offset `0x03` becomes `2` and the routine returns `3`. No optional marker is read.

6. **Mutation changes secondary dispatch.** If main dispatch admits discriminator `1` but F-3eee64f47633 changes it to `24`, secondary dispatch requests two bits. The earlier rejection case for discriminator `24` is not revisited.

7. **Rejection with additional output.** With main-dispatch discriminator `36`, a five-bit result is stored at `0x0D`, then the routine returns `3`.

8. **Optional-marker suppression.** If optional-extension handling observes `5` at `0x04`, it returns the retained status without reading a marker, regardless of nominal remaining length.

9. **First-marker mismatch.** With at least sixteen unsigned remaining bits and a returned eleven-bit value other than `0x2B7`, that value is stored at `0x20` and the retained status is returned. No post-marker status call occurs.

10. **Second-marker boundary.** After the extension flag and any associated numeric value, an unsigned remainder of eleven prevents a second marker read; twelve permits it. If the marker is `0x548`, a one-bit request supplies the four-byte value at `0x10`.
