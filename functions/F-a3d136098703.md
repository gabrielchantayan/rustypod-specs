# F-a3d136098703

## Purpose

F-a3d136098703 queries whether a nonnegative bit position is set in a packed array of 32-bit words. It returns a 32-bit value equal to either zero or one.

The operation first rejects negative positions, then checks the position’s word index against a signed word-count field, and only then examines the selected word. A zero result therefore does not distinguish an unset bit from a rejected position.

The apparent intent is a bounded bit-membership query. That interpretation is inferred from the indexing and masking behavior; the supplied evidence does not establish the surrounding data type, its construction rules, or its application-level meaning.

## Interface

The function has two inputs:

- **Descriptor reference:** A reference to a two-field descriptor. The first field contains the address of the packed word storage. The second field supplies a signed 32-bit word count.
- **Bit position:** A signed 32-bit integer identifying the queried bit.

The result is a four-byte scalar. All established normal return paths produce exactly **0** or **1**. The evidence does not establish a richer result type or a separate error channel.

The descriptor and backing-storage layout exposed by the supplied representation is:

| Location | Meaning | Interpretation |
|---|---|---|
| Descriptor offset 0 | Backing-storage address | Address represented in the first 32-bit field |
| Descriptor offset 4 | Word count | Signed 32-bit integer |
| Storage offset 4 × word index | Selected packed word | Unsigned 32-bit value |

The descriptor layout reflects the 32-bit representation in the supplied evidence. It is not evidence for a portable native-pointer structure on a different-width platform.

Within each packed word, position zero denotes the least-significant bit and position 31 denotes the most-significant bit. Successive words account for successive groups of 32 positions. This establishes numerical bit ordering, not byte endianness.

Memory validity requirements depend on the path taken:

- A negative position does not require a descriptor or storage read.
- A nonnegative position requires a readable descriptor count field.
- A position whose word index passes the count comparison additionally requires a readable address field and a readable selected 32-bit storage word.

The count field is not itself proof that the corresponding storage exists. Valid address representation, sufficient backing storage, and any alignment requirements remain caller obligations for paths that access storage.

## Behavior

### Position rejection

Every negative signed position returns zero before the descriptor is inspected.

This includes the minimum signed 32-bit value. There is no established negative-index wrapping, absolute-value conversion, or interpretation relative to the end of the storage.

For nonnegative positions, the function determines:

- The **word index**, equal to the position divided by 32, rounded down.
- The **bit index**, equal to the remainder after division by 32.

The word index consequently ranges from 0 through 67,108,863. The bit index ranges from 0 through 31.

Although the supplied representation contains arithmetic that could accommodate signed division, its negative-position guard makes those adjustments irrelevant to every path that continues. The externally relevant calculation is ordinary division and remainder on a nonnegative signed 32-bit value.

### Word-count comparison

The descriptor’s word count is read and compared with the calculated word index using a strict signed comparison.

If the word index is not less than the count, the result is zero. In particular:

- A zero count rejects every nonnegative position.
- A negative count also rejects every nonnegative position.
- Equality is rejected: a count of one admits word index zero, not word index one.

There is no established separate validation or error report for a negative count. Such a count simply causes the comparison to fail.

The bound is measured in **32-bit words**, not bits or bytes. A positive count of one admits positions 0 through 31; a count of two admits positions 0 through 63.

The function does not calculate a total bit capacity by multiplying the count by 32. Its bound decision uses the word index directly. Consequently, the behavior should not be replaced with a capacity calculation that could introduce a different overflow boundary.

### Selected-word query

If the word index passes the comparison, the function obtains the backing-storage address from the descriptor and reads the 32-bit word at a byte displacement equal to four times the word index.

It tests the bit at the calculated bit index:

- If that bit is set, the result is one.
- Otherwise, the result is zero.

Other bits in the selected word do not affect the result. Other storage words are not needed by the source-level operation.

A bit index of 31 is within the operation’s established selection range and denotes the high bit of the selected 32-bit word. The contract describes that observed bit-selection behavior without prescribing a source-language signed-shift expression for a replacement implementation.
