# F-fc6b91b5a714

## Purpose

F-fc6b91b5a714 conditionally retrieves a 32-bit word through two address-based records.

The second argument selects an initial record. A flag in that record must have its least significant bit set, and its associated address must be nonzero. A flag at the resulting address must then have its least significant bit clear. Only when all three conditions hold does the function read and return the associated word from that second record. Otherwise, it returns zero.

This describes established static behavior. Interpreting the records as tagged objects, wrappers, or links is inferred intent, not an established data-model contract. The function does not establish that the final word is itself an address.

| Second | 32 bits, represented as signed | Tested against zero. When nonzero, used as the base address of the initial record. |

The second argument’s signed representation does not introduce a positivity requirement. The function checks only whether it is zero. A negative represented value is not explicitly rejected; whether it denotes an accessible address depends on the execution environment.

The first argument is behaviorally irrelevant for both cases of the second argument:

- When the second argument is zero, the function returns zero without dereferencing either argument.
- When the second argument is nonzero, the initial flag read replaces the first argument’s working value before that value can affect the result.

**Return value**

The result is a 32-bit word:

- Zero when any gating condition fails.
- The exact 32-bit word read from the second record’s word field when all gating conditions pass.

A successful final read can itself produce zero. Consequently, the return value alone does not distinguish a failed gate from a completed lookup whose stored result is zero.

## Behavior

### Initial-record selection

A zero second argument ends processing immediately with a zero return. There are no record reads on this path. In particular, the first argument is not used as an alternative record address.

For a nonzero second argument, the first observable record access is an 8-bit read at offset 0x1D from that address. The function tests bit 0 of the byte it reads.

If that bit is clear, the function returns zero. It does not read the initial record’s field at offset 0x20.

If that bit is set, processing continues to the address field.

### Address-field selection

After observing bit 0 set in the initial flag byte, the function reads the 32-bit field at offset 0x20 from the initial record. This word supplies the address of the second record.

If the word is zero, the function returns zero. It does not attempt to read a flag relative to address zero.

If the word is nonzero, processing continues at that address. No additional numerical restrictions on the address are visible.

### Second-record selection

The next record access is an 8-bit read at offset 0x1D from the second-record address.

This flag has the opposite acceptance condition from the initial flag:

- Bit 0 set: return zero without reading the second record’s word field.
- Bit 0 clear: read the 32-bit word at offset 0x20 from the second record and return it.

The remaining seven bits of each flag byte do not affect these decisions. Thus any odd initial flag byte passes the first flag gate, while any even second flag byte passes the second flag gate.

### Read ordering and limits

The source-established sequence of conditional record reads is:

1. Initial flag byte.
2. Initial 32-bit address field, only if the initial flag permits it.
3. Second flag byte, only if the address field is nonzero.
4. Second 32-bit result field, only if the second flag permits it.

Each listed field is read once when its stage is reached. The function does not search, iterate, recursively follow records, or perform another lookup using the final returned word.

These are source-level access and dependency claims. They do not establish a processor’s speculative bus transactions or guarantees for device memory.

The function therefore provides no evidence of taking ownership of either record or transferring ownership of anything represented by the returned word. Additional boundary cases:

- Changing only the first argument must not change the result or record-read path.
- An unreadable initial address field is irrelevant when the initial flag rejects traversal.
- An unreadable second result field is irrelevant when the second flag rejects traversal.
- If both record addresses are identical and the shared flag remains stable, the lookup cannot pass both flag gates: the first requires bit 0 set, while the second requires it clear. This conclusion depends on stability between the two flag reads.
- An invalid nonzero address is not a supported zero-result case. Its outcome is outside the established normal-return contract.
