# F-01ab8755db0c

## Purpose

F-01ab8755db0c is represented as a non-returning sequence of indirect calls, byte-level control writes, and 32-bit memory transfers. After four initialization calls, it repeatedly executes a fixed-order cycle. Results from indirect calls supply both stored data and subsequent memory addresses.

The evidence establishes the ordering and arithmetic of this cycle, but not its application-level purpose. In particular, it does not establish that the memory locations are ordinary RAM, device registers, descriptors, or valid mapped addresses. Terms such as “control byte” and “payload word” below describe access patterns, not a confirmed hardware or data-model interpretation.

This contract is source-facing and conditional on the supplied representation being accurate. No runtime tests have been performed.

## Behavior

### Initialization and recurrence

Four indirect calls occur before the repeating cycle. The fourth produces the initial cycle index. Earlier initialization calls have no explicit arguments in the supplied representation; their side effects and implicit inputs remain unknown.

Each cycle obtains a new index from its final call. That result becomes the index for the next cycle. Other state carried into the next cycle includes the current selector-lookup base and two related shifted values.

The first indirect call inside the cycle uses a target derived from a different carried control-flow value on the initial entry than on later entries. It must not be assumed to identify one stable dependency on all iterations.

### 1. Opening selector update and first payload transfer

At cycle entry:

1. The incoming control-field value supplies a middle-field byte.
2. A selector is read at the current lookup base plus 1.
3. That byte is written at selector plus 17.
4. An indirect-call sequence begins with a call receiving the incoming shifted-state value shifted left by 12.
5. A subsequent call returns a 32-bit quantity. That result is forwarded with the cycle index shifted left by 30.
6. A later call returns a represented 64-bit quantity. Its lower and upper 32-bit halves are forwarded, in that order, to another call.
7. After further calls, a result is obtained, and a newly read selector at the same lookup address is used to clear a control byte.
8. The result shifted left by 2 is passed onward.

The second selector lookup is a distinct read. Calls between the two lookups may change the selector or other relevant state.

A subsequent result supplies a payload equal to that result shifted left by 2. The operation writes this payload to the address formed from the cycle index multiplied by 16,384, plus 20.

The following call receives four explicit arguments:

- The cycle index multiplied by 4,096.
- The same scaled index again.
- The cycle index shifted left by 14.
- The newly stored payload.

After intervening calls, another result selects a slot at four times that result plus 20. The same payload is written there, then four times the selecting result is passed onward.

### 2. Two repeated scale-and-copy groups

Two successive groups each derive a new payload from a call result:

- The payload is four times the result.
- The first write is to sixteen times that result plus 20.
- A call receives three copies of the payload.
- After intervening calls, another result selects a second slot at four times that result plus 20.
- The same payload is written to that second slot.
- Four times the second selector result is passed onward.

The second group also establishes a control base equal to its first result multiplied by 1,073,741,824, interpreted at the represented arithmetic width.

This base is used directly for later byte writes. It is not a pointer read from the payload slots.

### 3. Paired clears and field-dependent lookup

After another call sequence returns a value:

1. Zero is written to control base plus 17.
2. Zero is written to control base plus 1.
3. The returned value shifted left by 2 is passed to a call.
4. A following result is forwarded unchanged to another call.
5. More calls produce another value.
6. Zero is again written to control base plus 17.
7. Zero is again written to control base plus 1.
8. The second value shifted left by 2 is passed onward.

These are two distinct ordered pairs of writes. They are not redundant in the observable contract because dependency calls intervene.

A later result selects a slot at sixteen times that result plus 20. The stored word is the second group’s copy-slot selector shifted left by 31. Under 32-bit bit-vector arithmetic, this preserves only that selector’s least significant bit.

Next, the operation reads a 32-bit word from a numerical address formed by adding 20 to bits 20 through 29 of the earlier returned value. There is no additional base and no multiplication by four.

That address may be unaligned. The source contains no alignment correction or rejection.

After a call receiving four times the new slot-selector result, another result is retained for a later selector-based payload write. The word just read contributes an argument formed by shifting it right by 22 and then left by 28.

After more calls, a newly selected four-times-result-plus-20 slot is explicitly cleared with a 32-bit zero write.

### 4. Selector-mediated payload installation

Another call sequence returns a value used in two distinct byte updates:

- First, its value shifted left by 2 is truncated to eight bits and written through a selector read from control base plus 1.
- Calls then receive the full 32-bit shifted value and, later, a pair consisting of an intermediate result and the original value shifted left by 30.
- After further calls, the selector at control base plus 1 is read again and captured.
- Through that captured selector, the operation writes the original value’s middle-field byte.

Subsequent calls occur before a four-byte payload write at captured selector plus 20. The payload is the retained result from the preceding phase shifted left by 2.

The captured selector is reused for this payload address. A later dependency changing the byte at control base plus 1 does not, in the represented local dataflow, redirect this particular write.

Only after that payload write does the operation read the global 32-bit value.

### 5. Global-derived control update and another payload pair

A call receives the scaled slot selector retained from the earlier field-dependent phase. Further calls return a represented 64-bit quantity.

The operation then:

- Retains its lower half shifted left by 2 as a new payload index.
- Reads a selector at control base plus 1.
- Writes the low eight bits of the global snapshot shifted right by 22 through that selector.
- Passes the upper half of the paired result to a call.
- Forwards a later 32-bit result together with the retained payload index shifted left by 28.
- After further calls, reads the selector again and clears its control byte.

The global read is a snapshot at its stated position. Later calls are not assumed to preserve the global, and the subsequent byte calculation does not reread it.

Following additional calls, one result is shifted left by 2 and supplied twice to a dependency. Further calls produce a new payload, also shifted left by 2.

That payload is written to:

1. The retained payload index multiplied by 4,096, plus 20.
2. After intervening calls, four times a newly returned selector result, plus 20.

A call between those writes receives the retained payload index shifted left by 14. A call after the second write receives four times its selecting result.

### 6. Late selector clears and next-cycle state construction

Another represented 64-bit result supplies:

- A new address seed: its lower half shifted left by 2.
- An upper half passed to a dependency.

Before that upper-half call, the operation performs a selector-based control write using a lookup address equal to the previous payload index multiplied by 16,384, plus 1. The byte written is the middle-field byte of the recently stored payload.

The new address seed then establishes another base by multiplication by 268,435,456.

After a 32-bit result is forwarded and a later paired result has both halves forwarded:

- A selector read at this new base plus 1 directs a zero-byte write.
- A subsequent result shifted left by 2 is passed onward.
- Further calls produce a value retained for next-cycle state.

The next cycle’s selector-lookup base becomes four times the new address seed. A selector read at that base plus 1 directs another zero-byte write.

The following call receives the address seed shifted left by 10. A later call receives an intermediate result and the earlier retained selector-based payload source shifted left by 28.

After further calls, the selector at the next-cycle lookup base plus 1 is read again and its control byte is cleared again.

The operation then constructs a shifted-state value from the retained next-cycle value shifted left by 14 and writes it to a slot at that retained value multiplied by 16,384, plus 20.

A later dependency receives four times the retained value, shifted left by 14. Another receives:

- The new shifted-state value shifted left by 28.
- An additional machine-register value whose provenance is unresolved.

More calls produce a slot selector. The shifted-state value is copied to four times that selector plus 20, followed by a call receiving four times the selector.

The last call sequence returns the next cycle index. Execution repeats without a local termination condition.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

### Selector addressing

If an opening selector lookup returns 7 and the field input is 0x00500000, the direct control write is one byte of value 5 at numerical address 24.

If the selector later changes to 9 during an intervening call, the subsequent selector-based clear targets address 26. It does not necessarily clear address 24.

### Payload scaling

If the cycle index is 3 and the first payload-producing result is 5, the first payload is 20 and is written at numerical address 49,172.

The following four-argument call receives 12,288, 12,288, 49,152, and 20.

These expectations assume the relevant calls return and the address is writable.

### Unscaled field lookup

If the value used for the field-indexed read is 0x00300000, the 32-bit read starts at numerical address 23. Replacing that with an aligned table lookup would change the behavior.

Whether the actual environment permits that access is undocumented.

### Captured versus fresh selector

If the captured selector in the selector-mediated payload phase is 12, the later payload write targets address 32. A dependency changing the selector memory to 20 before that write does not alter the captured address.

Elsewhere, a selector explicitly reread after a call must reflect the value available at that later read.

### Global snapshot

If the global snapshot is 0x00C00000, the later global-derived control byte is 3. A dependency changing the global after the snapshot does not change this calculation.

### Partial execution

If the first initialization dependency never returns, no subsequent local accesses occur. If a payload write faults, the representation supplies no rollback of earlier writes and no guaranteed next iteration.
