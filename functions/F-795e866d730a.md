# F-795e866d730a

## Purpose

F-795e866d730a transforms two 32-bit input words into one 64-bit packed result. The transformation separates a sign bit, an 11-bit classification field, and a 52-bit payload distributed across the inputs. It constructs a 32-bit leading-significand word and a separate sign-and-exponent-like word.

The established contract is the bit transformation described below. Interpreting the inputs as the high and low words of an IEEE 754 binary64 encoding explains the field boundaries, zero handling, and normalization. That interpretation is inferred intent, not an independently established interface guarantee.

The result is not an ordinary IEEE 754 binary64 encoding. Its most significant 32 bits contain the constructed significand; its least significant 32 bits contain the sign, an adjusted field, and, for one input class, an additional marker.

No runtime tests have been performed.

## Interface

### Inputs

Two unsigned 32-bit words, described here as:

- **Upper input:** contains the sign in bit 31, the classification field in bits 30–20, and the upper 20 payload bits in bits 19–0.
- **Lower input:** contains the remaining 32 payload bits.

Bit 0 is the least significant bit of a word.

The following descriptive quantities define the contract:

| Quantity | Definition |
|---|---|
| Sign | Upper input bit 31, retained at bit 31 of the result’s least significant word |
| Class field | Upper input bits 30–20, interpreted as an unsigned integer from 0 through 2047 |
| Payload | The 52-bit concatenation of upper input bits 19–0 and all 32 lower-input bits |
| Magnitude present | True when either the class field or the payload is nonzero |
| Upper payload portion | The most significant 31 bits of the 52-bit payload |
| Lower payload portion | The least significant 21 bits of the payload |

Magnitude presence explicitly excludes the sign. Consequently, the two sign encodings of zero take the same magnitude-dependent branches.

### Output

The return value is a 64-bit bit container with two components:

- **Most significant word:** a 32-bit constructed significand.
- **Least significant word:** a 32-bit control word containing the preserved sign and an adjusted field, with a class-specific marker when applicable.

The mathematical packing is:

**Return value = constructed significand × 2³² + control word.**

This establishes word significance, not byte order in memory or the platform’s register-return convention.

### Preconditions and ownership

Every pair of 32-bit input words has a defined result under the supplied operations. There are no pointer parameters, buffer sizes, alignment requirements, or caller-provided storage.

The function does not acquire or transfer memory ownership. The supplied body contains no allocation, release, external calls, or explicit memory access through an address.

## Behavior

### Arithmetic model

The transformation uses 32-bit word operations. Left shifts discard bits beyond bit 31. Unsigned right shifts introduce zeros.

A signed right-shift classification appears in the supplied body. Its observed role is to distinguish a zero class field, an all-ones class field, and every other class field. The contract below expresses those three cases directly rather than depending on a language-specific signed-shift rule.

All effective variable shift counts used to construct results are within 1 through 31. No result requires a shift by 32.

### Initial field construction

For either sign of zero, the initial control word contains only the sign bit.

For every nonzero magnitude, the initial control word contains:

- The original sign in bit 31.
- The class field plus hexadecimal `3C00` in the low field.

The addition is exact for the full class-field range. Its largest value is hexadecimal `43FF`; it does not reach the sign bit.

An initial significand is formed from:

- The upper 31 payload bits in bits 30–0.
- Bit 31 set whenever magnitude is present.

Thus, nonzero inputs initially receive an explicit leading one, even when the class field is zero. The subsequent zero-class handling either replaces that provisional form with a normalized payload or returns zero.

The lower 21 payload bits are also retained temporarily, aligned into bits 31–11 of a 32-bit word. They contribute to the returned significand only on the zero-class normalization paths.

### Nonzero class fields other than all ones

When the class field is from 1 through 2046 inclusive:

- Return the initial significand without further normalization.
- Return the initial control word without an additional marker.
- Discard the lower 21 payload bits from the result.

For this class, the constructed significand is exactly an explicit leading one followed by the upper 31 payload bits. There is no rounding based on the discarded bits. In particular, discarded bits cannot increment the retained significand or adjusted field.

Inputs that differ only in the lower 21 payload bits produce identical results in this class.

### All-ones class field

When the class field is 2047:

- Keep the same significand construction used for other nonzero classes.
- Set bit 30 of the control word.
- Preserve the original sign in control-word bit 31.
- Retain hexadecimal `43FF` in the adjusted low field.

The resulting control word is therefore:

- Hexadecimal `400043FF` for a clear sign.
- Hexadecimal `C00043FF` for a set sign.

This path does not inspect the payload to choose different handling for zero versus nonzero payload. It does not distinguish signaling from quiet encodings, set a payload-specific status, or report an error in the supplied body.

The lower 21 payload bits remain discarded. As a result, a nonzero payload confined to those bits can produce the same return value as a zero payload with the same sign and class field. If the inputs are interpreted as binary64, this means some NaN encodings and the corresponding infinity encoding collide in the returned representation. Whether an enclosing system considers those results equivalent is unknown.

### Zero class field and zero payload

When both the class field and payload are zero:

- The returned significand is zero.
- The returned control word contains only the original sign.

The function therefore preserves the distinction between positive and negative zero at the bit-container level.

### Zero class field and nonzero payload

For a zero class field with nonzero payload, the function normalizes the payload. The retained significand begins with the payload’s highest set bit at bit 31.

Let **highest payload position** be the position of the highest set bit in the 52-bit payload, numbering payload bits from 0 through 51.

For every such input:

- The constructed significand is the highest 32 significant payload bits, left-aligned at bit 31.
- If fewer than 32 significant bits exist, the remaining low significand bits are zero.
- Any payload bits below the retained 32-bit window are discarded without rounding.
- The control word preserves the sign and has low-field value hexadecimal `3BCD` plus the highest payload position.

The highest payload position ranges from 0 through 51, so the adjusted low field ranges from hexadecimal `3BCD` through hexadecimal `3C00`. No subtraction underflow occurs on a reachable normalization path.

There are two established normalization cases.

#### Payload reaches the upper 31-bit portion

If any of the upper 31 payload bits is set, the function determines how many leading zero bits precede that portion’s highest set bit. This count ranges from 1 through 31 because the portion occupies only bits 30–0.

The returned significand combines:

- That upper portion shifted left by the count.
- The corresponding high bits from the temporarily aligned lower portion.

The adjusted low field is hexadecimal `3C00`, minus the count, plus one.

The temporarily inserted leading one is not part of the normalized payload. It is removed or shifted out before the final significand is returned.

#### Payload is confined to its lowest 21 bits

If the upper 31 payload bits are zero, the nonzero payload is wholly within the lower input’s lowest 21 bits.

The function left-aligns that payload so its highest set bit reaches bit 31. A preliminary 16-bit adjustment is used for payloads confined to their lowest five bits; further adjustments resolve the remaining leading zeros.

The net result is the same highest-set-bit normalization specified above. In this case every nonzero payload bit fits within the 32-bit result significand, so no payload information is discarded by normalization.
