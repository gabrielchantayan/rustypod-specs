# F-0c6874b13942

## Purpose

F-0c6874b13942 is an externally directed state machine that can modify bytes in place. It accepts one 32-bit argument, which a particular state installs as the base address for subsequent destination accesses. External data controls dispatch, reference addressing, arithmetic transformations, and continuation decisions.

The supplied static evidence establishes individual byte accesses and state transitions. It does not establish a conventional buffer interface, a fixed processing length, a guaranteed initialization sequence, or termination.

Reaching the returning state produces zero. This is not a general success indication: the function may return without accessing the supplied argument, transform bytes before returning, repeat accesses, or continue indefinitely.

## Behavior

### Entry and dispatch

The working destination base, two signed-halfword counters, position, lane, saved position components, and arithmetic scratch state begin at zero. The initial selector is read from external configuration.

Every dispatch compares the current selector with the externally read dispatch origin by subtraction. Recognized differences are 0 through 11. Dispatch does not first validate the selector or configuration.

The following table defines the state effects. A selector loaded by one state is interpreted against the dispatch origin at the next dispatch; it is not inherently a state number.

| Selector minus origin | Effect |
|---:|---|
| 0 | Execute one byte transformation, then choose a continuation. |
| 1 | Clear the secondary halfword counter and load its configured continuation selector. |
| 2 | Set the primary halfword counter to −123 and load its configured continuation selector. |
| 3 | Load a configured continuation selector and install the argument as the working destination base. |
| 4 | Execute the shared tail using the secondary halfword counter. |
| 5 | Return 32-bit zero. |
| 6 | Execute progression using the saved arithmetic state. |
| 7 | Load a configured continuation selector without directly accessing destination or reference bytes. |
| 8 | Clear the primary halfword counter and load the same selector used by difference 2. |
| 9 | Set position to 123, clear the lane, and select the dispatch origin. |
| 10 | Execute the shared tail using the primary halfword counter. |
| 11 | Set the secondary halfword counter to −123 and load the same selector used by difference 1. |

An unrecognized difference executes the shared tail using the primary counter. It does not produce an invalid-state error.

There is no enforced ordering among setup states. In particular, the argument-installation state need not precede a byte transformation.

### Shared tail

The shared tail converts its selected signed-halfword counter into arithmetic scratch state through multiplication by 77, signed-halfword narrowing, multiplication by −123 with byte extraction, and sign extension.

Under the fixed-width interpretation, the saved result is simply \(\operatorname{s8}(C)\), where \(C\) is the selected counter. The narrowing and extraction operations remain relevant when determining whether a target execution supports this reduction.

The tail then loads its configured continuation selector. It does not modify either counter.

### Transformation addresses

For a transformation, let \(P\) be the current 32-bit position. Define:

\[
A=\operatorname{s8}(P-123)
\]

and

\[
D=\operatorname{s8}(77A).
\]

The destination address is the working destination base plus \(D\). The reference address is the configured reference base plus the same \(D\).

The displacement is therefore between −128 and 127 inclusive. Negative displacements refer to storage before the corresponding base, not to unsigned forward offsets.

No evidence establishes that all possible displacements are visited. Storage requirements depend on the reached state sequence, not on an implicit fixed buffer length.

### Transformation read and write order

Across separate expressions, the supplied body establishes this order:

1. Read the old destination byte.
2. Read the transformation scalar and retain its low 16 bits as a signed halfword.
3. Read a reference byte for an intermediate mask.
4. Compute additional arithmetic, including saved position information.
5. Read a reference byte again within the expression producing the new destination value.
6. Write one destination byte.
7. Compute the lane-dependent continuation and any applicable arithmetic predicate.

Each reference access derives its address from the reference-base configuration. Both accesses use the same displacement. They address the same location only if the relevant base remains stable.

The representation contains two reference accesses rather than one saved reference value reused twice. Whether both remain distinct in executable instructions is not established.

Under the fixed-width reduction, the first reference byte’s contribution cancels from the final stored byte. That arithmetic cancellation does not establish that its access is absent, cannot fault, or has no externally observable effect.

### Stored-byte relation

- \(B\) be the old destination byte, in the range 0 through 255.
- \(R\) be the byte obtained by the second reference access.
- \(K\) be the signed-halfword interpretation of the retained scalar.
- \(L\) be the signed-halfword interpretation of the current lane.

Define the unsigned 16-bit quantity:

\[
V=\operatorname{low16}
\left(
-77L+117+\bigl((154L+256)\operatorname{OR}22\bigr)
\right).
\]

The stored byte is:

\[

\left(

This is a modular reduction of the byte-producing arithmetic, not a replacement for the entire state machine. In particular, it does not determine subsequent selectors.

The store occurs even when the resulting byte equals the old byte.

Although only the low byte ultimately contributes to the store, \(V\) as defined above is a 16-bit quantity. For lane zero it is 395, not 139.

### Lane-dependent continuation

The transformation derives a discriminator:

\[
Q=\operatorname{s8}(77L).
\]

It also replaces arithmetic scratch state with another extracted signed byte. Under the fixed-width interpretation, that saved scratch value is \(\operatorname{s8}(L)\).

Continuation has three cases:

- If \(Q=0\), evaluate the zero-discriminator predicate.
- If \(Q=1\), evaluate the one-discriminator predicate.
- Otherwise, execute progression directly.

Both predicates depend on the old destination byte and the byte just stored, using separately calculated affine byte mappings. They also use externally read coefficients and masks. They are not established as equality checks or simple comparisons of old and new data.

The predicate result is interpreted as signed 32-bit:

| Predicate | Nonnegative result | Negative result |
|---|---|---|
| Zero-discriminator | Its configured branch selector | That selector plus 10 |
| One-discriminator | Its configured branch selector | That selector minus 6 |

The selected values still undergo ordinary dispatch against the origin.

The predicate calculations use saved byte values, not new destination or reference reads. Configuration reads, including further scalar reads, occur after the store. Those later scalar uses operate on the external 32-bit value; they are not limited to the signed-halfword value retained for the stored-byte calculation.

### Progression

Progression can be entered through dispatch difference 6 or directly from a transformation with discriminator other than zero or one.

It consumes saved state. It does not establish that a transformation occurred immediately beforehand.

After a transformation, the saved position components include \(A\), the full product \(77A\), and the low byte of \(133\cdot77A\). Progression forms the 32-bit arithmetic quantity:

\[
U=235-77A+\bigl((154A+256)\operatorname{OR}42\bigr).
\]

It combines \(\operatorname{low8}(U)\), \(U\operatorname{AND}149\), external coefficients, and an offset. A subsequent arithmetic-and-bitwise calculation supplies a signed continuation result.

Progression then performs these state changes:

- Position becomes the signed interpretation of the saved low byte of \(133\cdot77A\).
- Lane is updated from the current arithmetic scratch state through two narrowing-and-multiplication stages.
- A nonnegative continuation result selects the dispatch origin.
- A negative continuation result selects the dispatch origin plus 7.

Because \(133\cdot77\equiv1\pmod{256}\), progression immediately following a transformation sets position to \(A\). The next transformation’s position component is therefore a signed-byte modular decrement by 123, not an ordinary increment.

The lane update similarly reduces to the signed low byte of the scratch input under the fixed-width interpretation. When progression immediately follows a transformation without intervening scratch changes, this retains the signed low byte of the previous lane. A route through the shared tail can provide a different scratch input.

If progression is reached before any transformation, it consumes the saved values then present, including their entry-time zeros. The formulas involving saved \(A\) and \(77A\) describe their transformation-produced relationship, not an invariant for every possible direct entry.

## Acceptance examples

These are conditional criteria derived from static evidence. None has been executed.

### Immediate return

If the initial selector minus the dispatch origin is 5, the function returns 32-bit zero without installing the argument as the destination base or accessing destination or reference bytes.

An invalid argument does not itself prevent this path, because the argument is not dereferenced.

### Position initialization followed by transformation

If difference 9 executes and a stable dispatch origin then leads to difference 0, position is 123 and lane is zero.

Thus \(A=0\) and \(D=0\). The transformation accesses the working destination base and reference base.

The working destination base equals the argument only if the installation state previously executed. Otherwise, it retains its earlier value, initially zero.

### Concrete stored byte

Assume a transformation has:

- Old destination byte \(B=0\).
- Second reference byte \(R=0\).
- Lane \(L=0\).
- Retained scalar \(K=0\).
- Valid memory and the fixed-width arithmetic interpretation.

Then:

\[
V=\operatorname{low16}(117+(256\operatorname{OR}22))
=117+278
=395.

The stored byte is:

\[
\operatorname{low8}
\left(99(179\cdot180+395-117)+236\right)
=130.

Equivalently, the inner quantity reduces to 242 modulo 256, and \(99\cdot242+236\) reduces to 130.

This criterion specifies the write only. It does not determine the subsequent predicate result or termination.

### Negative displacement

If \(A=-1\), then \(D=-77\).

Both accesses are 77 bytes before their respective bases. Treating the displacement as a forward offset of 179 would not match the signed addressing behavior.

### Unrecognized dispatch difference

If the dispatch difference is outside 0 through 11, the function executes the shared tail with the primary counter and loads the shared-tail selector.

Returning an invalid-state status instead would not match the supplied behavior.

### Store precedes continuation

A transformation’s byte store occurs before its subsequent predicate calculations. A later transition, fault, or failure to terminate does not imply rollback of that store.
