## Behavior

### 1. Initial selection and early exits

The function first retains a value of the selection multiplier for possible later use.

It then tests the product of a read of the selection multiplier and the source header. If that product is zero, the function returns immediately:

- No dependency is called.
- No destination magnitude word is read or written by the visible function.
- No destination header write occurs.
- The destination header is not needed for this path.

This is a product-zero test, not necessarily a raw-header-zero test. A zero multiplier, or a product that becomes zero under wrapping arithmetic, can produce this exit even for a nonzero source header.

If the source test does not return, the function tests the product of the selection multiplier and the destination header.

When that product is zero:

1. F-bcd78fb452c3 is called with the destination pointer only.
2. After the call, the destination header is read.
3. The destination header is replaced with the zero-result multiplier times the negation of the product of the initially retained selection value and that post-call header.
4. The function returns.

The zero-result multiplier is obtained for this post-call calculation. The source is not passed to the dependency, and no source magnitude word is explicitly read by this branch.

Consequently, the visible branch alone does not establish that a zero destination becomes the negative of the source. Such behavior would require additional information about the dependency, shared state, or a higher-level calling convention.

### 2. Selection between magnitude addition and subtraction

When neither initial product-zero test returns, a signed product involving both headers and the selection multiplier determines the next branch.

A negative product selects the magnitude-addition path. Every other result selects the magnitude-subtraction path.

Calling these “opposite-sign” and “same-sign” paths is justified only if the multiplier and intermediate arithmetic preserve the intended sign relationship. The visible expression uses multiplication rather than a direct comparison of header sign bits. Overflow can therefore matter.

### 3. Magnitude-addition path

Before calling a dependency, the function derives a destination count and a source count by multiplying each header by the addition length multiplier and taking a signed absolute value.

It then calls F-a6b5d842289c with the destination pointer. Its 32-bit return value is retained for the final header calculation. The function subsequently obtains the addition encode multiplier and retains it for the magnitude writes.

The previously derived counts are not recomputed after the dependency call.

Processing starts at the first magnitude word, with carry zero:

- Across the overlapping portion of the two counts, the function reads and decodes a destination word and a source word, adds them with the incoming carry, and writes the encoded low 32 bits to the destination.
- If the destination count is larger, remaining destination words are decoded, incremented by the carry, and rewritten.
- If the source count is larger, remaining source words are decoded, incremented by the carry, and written into the corresponding destination positions.
- If a carry remains after the larger count is exhausted, an additional encoded carry word is written and the result count increases by one.

Each overlap step accounts for both overflow from adding the two decoded words and overflow from adding the incoming carry. The carry is a numeric value, not an address that is dereferenced.

The final destination header is the product of the addition header multiplier, the resulting word count, and the dependency return value. The header multiplier is read at the final update; it is not established to be unchanged since entry.

This path does not scan away leading zero words. Even if the stored high word decodes to zero, the count reflects the processed length and optional appended carry.

### 4. Magnitude-subtraction path

Before its dependency call, this path derives both counts by multiplying the respective headers by the subtraction length multiplier and taking signed absolute values.

F-a6b5d842289c is then called with the destination pointer. Its return value is retained as a header factor. As on the addition path, the derived counts survive the call and are not recomputed.

The function processes words from least significant to most significant. Its propagated state begins at one and represents a no-borrow condition under the ordinary unsigned interpretation.

Across the overlap, each destination word is decoded, reduced by one and by the decoded source word, and combined with the propagated state. The encoded low 32 bits are written to the destination. Comparisons and carry detection determine the next propagated state.

For words beyond the source count but within the destination count, the same propagation continues without a source contribution. For words beyond the destination count but within the source count, it continues as subtraction from an implicit zero destination word.

Under conventional 32-bit unsigned arithmetic and suitable encode/decode multipliers, this computes destination magnitude minus source magnitude modulo a width of the larger count.

After this pass:

- If the final propagated state is nonzero, the stored words are retained.
- If it is zero, every processed destination word undergoes a second low-to-high pass implementing multiword two’s-complement negation under the conventional decoding interpretation. The retained dependency return value is also negated.

The function then scans downward from the highest processed word. Each candidate word is decoded with the subtraction decode multiplier. Decoded-zero high words are excluded from the final count; scanning stops at the first decoded-nonzero word or at count zero.

The final header is the product of the subtraction header multiplier, the possibly negated dependency return value, and the normalized word count.

High words excluded by normalization are not cleared. If the final count is zero and header arithmetic is defined, the final header product is zero.
