# F-16e9f0520650

## Purpose

F-16e9f0520650 initializes a caller-designated memory region as sixteen contiguous tables, each containing 256 four-byte entries. Eight tables contain zero words. The other eight contain the entry index positioned in one of four byte lanes of a 32-bit word, with each byte-lane table appearing twice.

The destination occupies exactly 0x4000 bytes, or 16,384 bytes. Its two 0x2000-byte halves contain the same collection of table types, but **not the same arrangement or identical contents at corresponding relative offsets**. The first half begins with a high-byte table; the second half begins with a zero table.

**Established static behavior:** fixed-size initialization using an index-major sequence of sixteen stores per index.

**Inferred intent:** the nonzero tables may support byte-position lookup or word composition. No particular consumer, encoding, pixel format, or application-level purpose is established.

## Behavior

### Destination layout and expressed store order

There are sixteen adjacent tables, each occupying 0x400 bytes. Every table contains 256 entries of four bytes each.

For entry index **n**, ranging from 0 through 255 inclusive, the displacement within a table is 4 × n. Each destination address is B plus its table-base offset plus that displacement.

The following table defines both the final word values and the order of stores within each iteration. Values are numeric 32-bit words; their byte representation depends on the target’s endianness.

The iteration order is index-major: all sixteen stores for one index precede the stores for the next index. The function does not finish one table before beginning another.

The expressed store order is not strictly increasing by address. For each index, the zero store in the table at offset 0x1400 precedes the byte-lane store in the table at offset 0x1000.

### Iteration boundaries and completion

The first iteration uses index zero. The last uses index 255. There is no iteration for index 256.

The loop advances its index before the final two stores of each iteration. Those two stores still belong to the current entry: their address and low-byte value have already been determined for that entry. Thus the final iteration includes both the zero store at B + 0x3BFC and the word 0x000000FF at B + 0x3FFC before termination.

Normal completion performs:

- 256 iterations.
- Sixteen four-byte stores per iteration.
- 4,096 stores overall.
- One store to every four-byte entry in the 0x4000-byte region.

The first store writes zero at B. The final store writes 0x000000FF at B + 0x3FFC, covering bytes through B + 0x3FFF.

For index zero, all sixteen values are zero. For every later index, the eight byte-lane entries are nonzero and the other eight entries remain zero-valued.

There is no visible conditional early-return path.

### Widths and arithmetic

Every destination write is four bytes. The generated values are 32-bit word patterns.

During executed iterations, the index ranges from 0 to 255. Restricting that index to its low eight bits therefore does not change its value. The shifted-value ranges are:

| Byte lane | Minimum word | Maximum word |
|---|---:|---:|
| Bits 24–31 | 0x00000000 | 0xFF000000 |
| Bits 16–23 | 0x00000000 | 0x00FF0000 |
| Bits 8–15 | 0x00000000 | 0x0000FF00 |
| Bits 0–7 | 0x00000000 | 0x000000FF |

These describe bit patterns, not signed numeric payloads. A high-byte result such as 0xFF000000 is required even though the same bits would represent a negative number under signed 32-bit interpretation.

The incremented loop index reaches 256 at termination. Neither its executed range nor the value 256 requires arithmetic wraparound.

The largest within-table displacement is 255 × 4 = 0x3FC. The largest store-start displacement is 0x3C00 + 0x3FC = 0x3FFC. Adding the four-byte store width establishes the 0x4000-byte extent.

These bounded index and displacement calculations do not establish behavior for overflowing or otherwise invalid destination-address calculations. Such cases remain outside the normal-completion preconditions.

## Side effects

### Memory mutation

The function overwrites every byte of the 0x4000-byte destination region through four-byte stores. It overwrites the zero tables as well as the byte-lane tables; preexisting zero-table contents are not preserved or skipped.

Under valid address calculations, distinct entries do not overlap, and no explicit destination store lies outside the region.

The two halves are **not identical**. Each contains four zero tables and one table for each byte lane, but those tables occupy different relative positions. Equality holds between the matching individual tables listed above, not between the two complete halves.

There is no visible copy operation from one half to the other. Every entry is populated by its own store.

### Ownership and lifetime

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence, not reports of executed tests.

### Complete overwrite

Given valid writable storage for the entire region, normal completion must produce every word specified by the layout table, independently of the initial contents.

If all destination bytes initially contain a nonzero sentinel, the eight zero tables must nevertheless become entirely zero. Initializing only the byte-lane tables would not satisfy the contract.

### Representative index

For index 0x7F, the within-table displacement is 0x1FC. After normal completion:

| Address | Required word |
|---|---:|
| B + 0x01FC | 0x7F000000 |
| B + 0x09FC | 0x007F0000 |

| B + 0x35FC | 0x00007F00 |
| B + 0x3DFC | 0x0000007F |

The entry at displacement 0x1FC in every zero table must contain zero.

### Distinguishing the halves

For index one:

- B + 0x0004 must contain 0x01000000.
- B + 0x2004 must contain zero.
- B + 0x0404 must contain zero.
- B + 0x2404 must contain 0x01000000.

An implementation that duplicates the first 0x2000 bytes directly into the second half would fail these requirements.

At index zero, corresponding entries in all tables are zero. That limited equality must not be generalized to the remaining indices or the complete halves.

### Upper boundary

For index 255:

- B + 0x03FC must contain 0xFF000000.
- B + 0x27FC must contain 0xFF000000.
- B + 0x3BFC must contain zero.
- B + 0x3FFC must contain 0x000000FF.

No index-256 stores occur. Under the valid-address preconditions, the explicit destination writes end at byte offset 0x3FFF.

### Ordered observation

If an observation mechanism faithfully exposes the expressed store sequence, it must show all sixteen stores for index zero before the first store for index one.

Within an index, it must show the store at table offset 0x1400 before the store at table offset 0x1000.

A table-major initializer could produce the same final ordinary-memory contents, but it would not preserve this expressed access sequence.

### Byte representation

If the environment is little-endian, the word 0x7F000000 appears as bytes 00, 00, 00, 7F in increasing address order. If the environment is big-endian, it appears as 7F, 00, 00, 00.

Acceptance using byte dumps must apply the actual environment’s byte order. No universal byte order is established here.
