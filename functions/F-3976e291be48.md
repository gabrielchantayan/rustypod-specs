# F-3976e291be48

## Purpose

F-3976e291be48 selects one of five dependency-interaction profiles using a selector and an external discriminator. A recognized profile obtains opaque 32-bit values, supplies them to operation dependencies in prescribed relationships, and returns one designated value. An unsupported selection returns zero.

The established contract concerns dispatch, argument relationships, observation order, and return selection. It does not establish what the dependencies compute. In particular, selector values and operation numbers do not independently establish a data format, conversion rule, or numerical meaning.

Discriminator equality has priority over all literal-selector profiles. Literal recognition additionally depends on a relational comparison with the discriminator.

## Interface

### Arguments and result

The supplied representation exposes five argument positions:

| Position | Representation | Contractual use |
|---|---|---|
| First | Opaque 32-bit value | Unused by the visible behavior. |
| Second | 32-bit integer representing a context address | Used to locate a context field and supplied unchanged to operation dependencies. |
| Third | Opaque 32-bit source operand | Forwarded unchanged once in every recognized profile. |
| Fourth | Signed 32-bit count | Forwarded unchanged or subjected to a one-bit or two-bit left shift. |
| Fifth | Signed 32-bit selector | Compared with the external discriminator and recognized literals. |

These widths describe the supplied static representation. Original declarations and calling-convention guarantees are not independently established.

The result is 32 bits. On normal completion of a recognized profile, it is a designated value previously returned by F-b35e541ebc78—not a return value from an operation dependency.

Zero is therefore ambiguous: it can mean unsupported selection or successful completion with a designated value of zero.

### Context layout and validity

The function directly reads a four-byte field beginning at byte offset 4 from the context address. This is the only directly accessed context layout established by the supplied representation.

The first field read occurs before dispatch. Consequently, an unsupported selector does not bypass the context access. Ordinary completion requires the field to be readable even when the eventual result is zero without dependency calls.

No local null, alignment, extent, or address-validity check is visible. The concrete address model, address-addition overflow behavior, and consequences of invalid or misaligned access remain **documented_only**.

The source operand is not directly dereferenced. Any storage, alignment, representation, or lifetime requirements associated with it arise from dependencies and remain unresolved.

### Terminology

A **token** is an opaque 32-bit result of F-b35e541ebc78. Token-role names describe how values participate in later interactions; they do not imply allocation, uniqueness, validity, or ownership.

The **entry observation** is the initial context-field value. A **fresh observation** is a later read of that field.

A **destination role** denotes an operation argument position. It does not establish that the argument is an address or that the operation writes memory.

## Behavior

### Dispatch contract

The entry observation precedes all dispatch decisions.

| Condition | Selected behavior |
|---|---|
| Selector equals discriminator | Equality profile |
| Equality fails, discriminator-less-than-or-equal-to-selector comparison is true, selector is 0x1406 | Profile 0x1406 |
| Same relational outcome, selector is 0x140c | Profile 0x140c |
| Equality fails, relational comparison is false, selector is 0x1400 | Profile 0x1400 |
| Same relational outcome, selector is 0x1401 | Profile 0x1401 |
| Any other reached case | Unsupported selection |

Unsupported selection returns zero without invoking any dependency.

A literal match alone is insufficient. Equality can override a literal profile, and the relational outcome can place a literal in an arm that rejects it.

The discriminator participates in the equality comparison and, only after equality fails, the relational comparison. No dependency call intervenes. Its declaration is unavailable, so storage width, comparison signedness, volatility, and stability between observations remain **documented_only**. The conditions above specify comparison outcomes without assuming a stable discriminator value or a particular signedness.

### Dependency argument conventions

Every token request supplies F-b35e541ebc78 with two arguments: a context-field observation followed by zero.

Every operation dependency receives the unchanged context address first. Its other arguments have these ordered roles:

| Dependency | Arguments following the context |
|---|---|
| F-fbf0cbff8cb3 | Operation number; destination token; literal or count operand |
| F-915779408ccb | Operation number; destination token; first input; second input |
| F-cb523cc6fa7d | Operation number; destination token; input token |
| F-489dcd301bad | Operation number; destination token; input token |

Operand delivery through F-fbf0cbff8cb3 always uses operation 0x28. This establishes delivery of an argument, not assignment or evaluation semantics.

Every recognized profile contains exactly one operation that directly forwards the external source operand. It uses F-915779408ccb, operation 1, with the source-linked token as destination and ordered inputs consisting of the source operand followed by the count token. All literal and count deliveries for that profile precede this interaction.

### Token acquisition and observation boundaries

Token requests have distinct roles even if their returned values are equal:

| Profile | Token roles in acquisition order | Returned role |
|---|---|---|
| Equality | Count, source-linked, transformed, result, literal-16 | Fourth token |
| 0x1406 | Count, source-linked, transformed, result | Fourth token |
| 0x140c | Count, source-linked, result | Third token |
| 0x1400 | Count, source-linked, first intermediate, second intermediate, result, literal-24, literal-8 | Fifth token |
| 0x1401 | Count, source-linked, first intermediate, second intermediate, third intermediate, fourth intermediate, result, literal-8, literal-7 | Seventh token |

The observation rules are role-dependent:

- Count and literal-token requests receive the saved entry observation.
- Source-linked, intermediate, transformed, and result-token requests receive fresh observations.
- Each fresh observation occurs after the preceding token request returns and before the request consuming that observation.

These boundaries matter when dependencies mutate the context. A later fresh observation can see such a mutation; a saved-entry request still receives the original value.

Equality, 0x1406, and 0x140c acquire all tokens before any operation dependency is invoked.

The other profiles have an observable acquisition boundary within operand preparation:

- In 0x1400, six tokens are obtained before operations begin. Delivery of literal 24 completes before acquisition of the literal-8 token.
- In 0x1401, eight tokens are obtained before operations begin. Delivery of literal 8 completes before acquisition of the literal-7 token.

Those delayed requests still use the saved entry observation. They do not reread the context field after the preceding operation.

### Profile-specific relationships

The following requirements define operation ordering and argument relationships without assigning mathematical meaning to the operation numbers.

**Equality profile.** Operand preparation delivers 16 to the literal-16 token before delivering the one-bit-shifted count to the count token. After the source-linked interaction, F-cb523cc6fa7d relates the transformed destination to the source-linked input under operation 0x27. The terminal operation is F-915779408ccb operation 6: result destination, transformed first input, literal-16 second input.

**Profile 0x1406.** Operand preparation delivers the two-bit-shifted count. The source-linked interaction precedes an F-cb523cc6fa7d operation 0x29 whose destination is the transformed token and whose input is the source-linked token. The terminal operation is F-489dcd301bad operation 0x1e, with result destination and transformed input.

**Profile 0x140c.** Operand preparation and the source-linked interaction match the corresponding roles in 0x1406. Its terminal operation is instead F-cb523cc6fa7d operation 0x29, directly relating the result destination to the source-linked input. There is no separate transformed token and no F-489dcd301bad call.

**Profile 0x1400.** Operand preparation delivers 24, then 8, then the unchanged count to their respective roles, respecting the delayed acquisition described above. After the source-linked interaction, the remaining relationships are:

| Relationship | Dependency and operation | Destination | Ordered inputs |
|---|---|---|---|
| First intermediate | F-cb523cc6fa7d, 0x26 | First intermediate | Source-linked |
| Second intermediate | F-915779408ccb, 6 | Second intermediate | First intermediate; literal-24 |
| Terminal | F-915779408ccb, 3 | Result | Second intermediate; literal-8 |

These relationships occur in table order.

**Profile 0x1401.** Operand preparation delivers 8, then 7, then the unchanged count, again respecting the delayed acquisition boundary. After the source-linked interaction, the remaining relationships are:

| Relationship | Dependency and operation | Destination | Ordered inputs |
|---|---|---|---|
| First intermediate | F-cb523cc6fa7d, 0x26 | First intermediate | Source-linked |
| Second intermediate | F-915779408ccb, 6 | Second intermediate | First intermediate; literal-8 |
| Third intermediate | F-915779408ccb, 7 | Third intermediate | First intermediate; literal-7 |
| Fourth intermediate | F-915779408ccb, 0x0c | Fourth intermediate | First intermediate; second intermediate |
| Terminal | F-915779408ccb, 1 | Result | Fourth intermediate; third intermediate |

These relationships occur in table order. Although the terminal operation number is also 1, that interaction does not directly forward the external source operand.

For every profile, a required interaction must return normally before its successor begins. The designated result token is returned only after the terminal operation completes normally.

Negative unshifted counts receive no local rejection. Their meaning to dependencies is unknown. A zero count does not remove token requests, literal deliveries, or any other operation.

Dependencies are not assumed to preserve the context, source-associated storage, discriminator, or other globals. Context mutations can affect later fresh observations. They cannot retroactively replace the saved entry observation used for count and literal-token requests.

Zero and duplicate tokens receive no local rejection. Equal token values do not merge roles or eliminate calls.

Operation return values are ignored. There is no visible status-dependent branch, retry, rollback, or cleanup. A normally returned dependency value does not interrupt the profile even if that value would indicate failure under the dependency’s own contract. If a dependency exits abnormally or does not return, later interactions and the ordinary return are not guaranteed.

No direct allocation, release, or ownership transfer is established. Neither token acquisition nor a destination argument proves resource ownership or a memory write. Dependency-specific lifetime and release obligations remain unresolved.

## Acceptance examples

The following are conditional acceptance criteria, not executed tests. Ordinary-completion examples assume readable required storage and normally returning dependencies.

1. **Rejected dispatch still accesses context.** When the reached arm rejects the selector, the entry field read occurs, no dependency is called, and the result is zero. An invalid context is not made safe by rejection.

2. **Equality overrides a recognized literal.** If equality succeeds for selector 0x1406, the equality profile applies. There are five token requests, the count receives a one-bit shift, and F-489dcd301bad is not called.

3. **Relational admission matters.** If equality fails and the relational comparison is true for selector 0x1400, the selection is unsupported despite the recognized literal.

4. **Count three distinguishes the profiles.** Equality delivers count operand 6. Admitted 0x1406 and 0x140c profiles deliver 12. Profile 0x1406 returns token four after its F-489dcd301bad interaction; 0x140c returns token three without that interaction.

5. **Saved and fresh observations can diverge.** If the first token request changes the context field, the second request uses a fresh read. Later literal-token requests still use the entry observation, including requests delayed until after an operation.

6. **Delayed acquisition is observable.** In 0x1400, the literal-24 delivery completes before token request seven. In 0x1401, the literal-8 delivery completes before token request nine. Equal token values do not permit moving either request earlier.

7. **Terminal inputs are role-sensitive.** Equality’s final inputs are the transformed token and literal-16 token, not the transformed token and count token. Profile 0x1401 ends with fourth-intermediate and third-intermediate inputs, not another direct forwarding of the source operand.

8. **Zero does not short-circuit.** With zero count and zero returned by every token request, the entire selected profile still occurs. Literal operands retain their specified values, and normal completion returns zero.

9. **Shift boundaries remain explicit.** In a two-bit-shifted profile, count 536,870,911 delivers 2,147,483,644. Count 536,870,912 is outside the established signed-representable range; its concrete shifted operand is unresolved. Equality count 1,073,741,823 delivers 2,147,483,646.

10. **Negative unshifted counts are forwarded.** An admitted 0x1400 or 0x1401 profile with count −1 supplies −1 unchanged and retains every required interaction. Dependency acceptance is unresolved.

11. **Operation results do not replace the selected token.** If a terminal operation returns normally with a value different from the designated result token, normal completion still returns the designated token.
