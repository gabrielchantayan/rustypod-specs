# F-3e632da2b304

## Purpose

F-3e632da2b304 performs an ordered series of indirect dependency invocations, transforms explicit and implicit machine-state values, mutates fixed and dynamically addressed storage, and finishes with a four-argument indirect transfer.

**Established static evidence:** the interface exposes two 32-bit inputs and no explicit return value. Behavior also depends on entry control state, implicit result state, dependency results, and memory observed during execution. The represented body contains no validation branch, recovery path, or rollback.

**Inferred intent:** recurring masks and shifts suggest packed-field processing. Interconnected offset-based accesses suggest state updates. Neither observation establishes an application purpose, object model, record format, or ownership policy.

This contract describes behavior supported by the supplied static representation. **documented_only** identifies unresolved matters rather than supplying assumed semantics. No runtime tests have been performed.

## Behavior

### Dependency-driven transformations

### Widths, conversions, and arithmetic

Explicitly typed dynamic memory operations distinguish 8-, 16-, and 32-bit transfers. Byte stores retain eight source bits; halfword stores retain sixteen; word stores transfer thirty-two. Explicit unsigned byte loads expand to values from 0 through 255.

High-word extraction selects bits 32–63 of a 64-bit container. Unsigned right shifts introduce zeros.

Under truncating 32-bit machine arithmetic, each intermediate retains its low thirty-two bits. Two successive left shifts by twenty-eight consequently produce zero, not a retained 56-position field. Signed expressions do not independently establish portable signed-overflow behavior.

Under that same bit-vector interpretation, the selector ranges from 0 through 508 in multiples of four. The doubled selector ranges from 0 through 1016 in multiples of eight. These bounds follow from the preceding left shift and mask, not from the fixed-location 0x05 input.

Address calculations include scaling by two, four, eight, and 0x02000000, fixed offsets, and subtraction of 0x96. None establishes that the resulting address is valid.

Near completion, a signed word is right-shifted by a count derived from the low byte of the recurring byte base. The expression itself does not constrain the count to 0–31. Oversized-count behavior and right shifting of negative operands remain **documented_only**.

Named fixed-location declarations are unavailable. An explicit eight-bit conversion establishes a truncated operand, not necessarily an eight-bit physical assignment. This distinction applies to fixed locations 0x01 and 0x15, as well as other undeclared fixed storage.

### Fixed 0x54 assignment

A later change to the traversal word’s original storage does not replace the retained operand.

### Fixed 0x3a conversion order

Given a retained traversal word of 0x66, the adjusted quantity is 0x102.

If character conversion retains the low eight bits, the converted value is 2; multiplication by eight followed by addition of 0x30 produces 0x40. Using the full adjusted word would instead produce 0x840 and would not preserve the represented conversion order.

The fixed assignment follows the 0xa9 and dynamic +0x74 captures and precedes the dynamic +0x14 and +0x04 captures. Its physical width remains unresolved.

### Global sampling and fresh 0x67 reads

If the sample is 0x12345678, captured-global-byte operands are 0x78. Later changes to the original global do not redirect retained-base operations.
