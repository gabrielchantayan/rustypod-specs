# F-d8d87e133b12

## Purpose

This function constructs a 64-byte record in selected storage, updates a descriptor, links that descriptor through a head field, and conditionally invokes one dependency before invoking a final dependency. If execution reaches the normal return, the result is a 32-bit zero.

“Record,” “descriptor,” and “head” are organizational labels for the observed memory accesses. Their application-specific meanings are not established.

The descriptor-address derivation is unresolved: the supplied representation applies a signed right shift of 32 to a 32-bit value. That expression does not establish a valid, portable result. The remaining contract is therefore conditional on a target-specific interpretation supplying a meaningful descriptor address. It is not a guarantee that ordinary inputs permit safe execution.

## Behavior

### 1. Derive the descriptor address

The seed is interpreted as signed, shifted right by 32, and converted to the descriptor pointer.

Because the operand is 32 bits wide, the shift count equals its width. The supplied representation does not define a portable result for this expression. In particular, this contract does not replace it with a zero result, sign extension, or a masked shift count.

All following descriptor-relative operations are conditional on resolving that target-specific behavior.

### 2. Perform the optional indirect store

The function tests whether the low ten bits of the descriptor address are zero.

If so, it reads the destination address from descriptor offset 4 and the word value from descriptor offset 0, then stores that word through the destination address.

The predicate concerns the descriptor address, not descriptor contents. Address zero satisfies this bit test; there is no separate null exclusion.

The relative evaluation order of the two source reads is not established by the supplied expression. The indirect store completes before record selection begins, assuming execution continues normally. It can therefore affect subsequent selection reads if its destination aliases them.

### 3. Select and publish the record address

Record selection uses unsigned 32-bit values and operations:

- The word at descriptor offset 24 is reduced by 64 modulo \(2^{32}\), then logically shifted right by three to form a mask.
- The unsigned selector is bitwise-ANDed with that mask to form an index.
- The index is multiplied by eight.
- That offset is added to the unsigned base word read at descriptor offset 20.

The base, mask, index, multiplication, and addition are all unsigned 32-bit expressions. In particular, the base-plus-offset sum wraps modulo \(2^{32}\) **before** conversion to a pointer.

The right shift limits the mask to `0x1FFFFFFF`; consequently, the masked index cannot exceed `0x1FFFFFFF`. Multiplication by eight therefore produces at most `0xFFFFFFF8` and does not itself overflow 32 bits. The addition to the base can overflow and wraps.

For example, a base of `0xFFFFFFF8`, an offset-24 word of 72, and selector 1 produce an offset of eight and a final address value of zero—not `0x100000000`.

Other consequences:

- Values below 64 at descriptor offset 24 wrap during subtraction.
- Masking is not general modulus reduction.
- Candidate starts are spaced in multiples of eight bytes, while each initialized record spans 64 bytes.
- Distinct selected starts can produce overlapping records.
- No capacity, bounds, or alignment check is visible.

The relative order of the base and mask-source reads is not established. After the address calculation, the selected address is written to descriptor offset 16 before any record word is initialized.

The unsigned calculation establishes the 32-bit address value. Its conversion to an accessible pointer remains subject to the target’s address-space rules.

### 4. Construct the record

After publishing the selected address, the function reads descriptor offset 12 once for this stage. That captured word supplies both the saved word and tag choice:

- Record offset 60 receives the complete captured word.
- Record offset 0 receives `0x13` if bit 0 is clear, or `0x33` if bit 0 is set.

The first external displacement is then read. The second explicit input is written at record offset 4, followed by its sum with that captured displacement at offset 8.

The remaining displacement-derived words are written at offsets 12, 16, 20, 24, 28, 32, 36, 40, 52, and 56, in that order. Each uses the next corresponding external displacement. Finally, the seed is written at offsets 44 and 48, in that order.

Thus the record’s write order is:

1. Offset 60.
2. Offset 0.
3. Offset 4.
4. Offsets 8 through 40 in four-byte increments.
5. Offsets 52 and 56.
6. Offsets 44 and 48.

The displacement reads occur during this sequence. Earlier writes can affect later displacement values if storage aliases; concurrent modification is likewise not excluded.

The first displacement is explicitly captured as a signed 32-bit value before addition to the signed second input. Overflow of that signed addition has no established wrapping result. The supplied material does not establish enough type and machine-level information to impose one uniform overflow rule on all eleven displacement additions. Conditional examples therefore use representable sums.

### 5. Update descriptor fields and insert the descriptor

After record construction, the function writes:

1. The low eight seed bits to descriptor offset 40.
2. The low eight seed bits to descriptor offset 41.
3. The full seed to descriptor offset 28.

Each byte store affects only its addressed byte.

It then reads the head word at list-anchor offset 8, copies that value to descriptor offset 0, and writes the descriptor address into the head field.

The head field is explicitly read again after that write. Subsequent branching uses this reloaded value, not an assumed copy of the value just stored.

No atomic operation, lock, memory barrier, or compare-and-swap is visible. The body does not establish concurrent-list safety or safe publication to another observer.

### 6. Make the conditional dependency call

This contract assigns two document-local opaque dependency IDs:

- **F-000000000001:** conditional dependency.
- **F-000000000002:** final dependency.

The conditional-call decision is:

| Condition | Action |
|---|---|
| Reloaded head is nonzero | Call F-000000000001 with that 32-bit head value. |
| Reloaded head is zero and comparison words differ | Call F-000000000001 with the word read at comparison-anchor offset 8. |
| Reloaded head is zero, comparison words are equal, and condition byte is nonzero | Call F-000000000001 with that byte zero-extended to 32 bits. |
| Reloaded head is zero, comparison words are equal, and condition byte is zero | Suppress the conditional call. |

When the reloaded head is zero, the comparison-anchor word at offset 8 is read before the word at offset 12.

The condition byte at list-anchor offset 1 is read only when the reloaded head is zero and those two captured comparison words are equal. Neither comparison word is read on the nonzero-head path.

### 7. Invoke the final dependency and return

F-000000000002 is called after the conditional stage. No explicit arguments are shown for it.

If F-000000000001 was called, the final dependency is reached only if that call returns normally. Both dependency return values are unused.

After F-000000000002 returns normally, the function returns 32-bit zero.

## Acceptance examples

These examples are conditional contract checks, not executed tests. Unless stated otherwise, assume meaningful descriptor derivation, valid accessible storage, no overlapping regions, stable external storage, representable displacement sums, and normally returning dependencies.

### Tag selection preserves the complete source word

If descriptor offset 12 contains `0xA4`, record offset 60 receives `0xA4` and offset 0 receives `0x13`.

If it contains `0xA5`, offset 60 receives `0xA5` and offset 0 receives `0x33`.

Only bit 0 chooses the tag; the complete word is saved.

### Masking is not ordinary indexing

With descriptor offset 24 equal to 128, the mask is eight.

Selector 15 produces index eight and an offset of 64 bytes. Selector 7 produces index zero and an offset of zero. Selecting index seven in the latter case would not match the observed arithmetic.

### Record-address addition wraps

With base `0xFFFFFFF8`, offset-24 word 72, and selector 1:

- The subtraction produces eight.
- The shift produces mask one.
- The masked index is one.
- Multiplication produces eight.
- Unsigned addition produces address value zero.

This establishes address selection only. Successful construction additionally requires the resulting pointer and every subsequently accessed record location to be valid. Without that condition, normal completion is not promised.

### Seed copies retain different widths

For seed `0x123456AB`, record offsets 44 and 48 and descriptor offset 28 receive `0x123456AB`. Descriptor offsets 40 and 41 each receive byte `0xAB`.

This example remains conditional on meaningful descriptor derivation for that seed.

### Stable nonzero head insertion

For a nonzero descriptor address and stable, nonoverlapping head storage, the old head is copied into descriptor offset 0. The descriptor address becomes the new head and is obtained by the explicit reload.

F-000000000001 receives that address. F-000000000002 follows if the conditional dependency returns normally.

### Zero-head decisions

Conditioned on a valid execution whose head reload is zero:

- Comparison words 7 and 9 cause the conditional dependency to receive 7.
- Equal comparison words and condition byte 2 cause it to receive 2.
- Equal comparison words and condition byte zero suppress the conditional call.

The final dependency is reached in each case if preceding execution continues normally.

### No dependency-preservation guarantee

If the conditional dependency changes global state or releases storage, this function performs no visible restoration before the final call. Acceptance must not require undocumented preservation.
