# F-d46271555c7b

## Purpose

F-d46271555c7b rebuilds an object-associated collection or selection context, attempts to locate a previously recorded 32-bit value in the rebuilt traversal, and activates the corresponding resolved value. If a signed status/index field is negative after traversal cleanup, it instead resolves and activates position zero.

The preservation-and-reselection interpretation is **inferred intent**. The established behavior consists of the ordered reads, writes, comparisons, and dependency calls described below. In particular, the routine does not establish that the rebuilt collection is nonempty, that a resolved value is nonzero, or that dependencies leave the object unchanged.

The routine has no explicit return value. Its observable results are object-memory changes and dependency effects.

## Acceptance examples

### Matching a nonnegative position

Expected behavior: the old-value state-zero sequence occurs before rebuilding; 3 is written to `0xFC`; resolution receives 3; its result is written to `0xF8` and activated; traversal cleanup occurs; no fallback resolution occurs.

Expected behavior: no matched-result extraction or resolution occurs. Cleanup precedes the signed test. The retained `0xFFFFFFFF` triggers a write of zero to `0xFC`, resolution at zero, and activation.

### A zero prior value matches

Assume the captured prior value is zero and traversal successfully yields a first output word of zero.

Expected behavior: the initial state-zero sequence is skipped, but the item matches and follows the normal matched-result path.

### Matching still leads to fallback

Expected behavior: the matched value is resolved and activated first. After cleanup, the signed-negative field triggers an additional resolution and activation at zero. No intervening deactivation is required by the visible routine.

### Cleanup changes the decision

Assume no match occurs, but cleanup changes `0xFC` from the sentinel to 5.

Expected behavior: fallback is skipped because the post-cleanup signed value is nonnegative. Conversely, cleanup changing an otherwise nonnegative field to a negative value triggers fallback.

### Dispatch uses a fresh field read
