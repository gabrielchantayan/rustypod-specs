# F-361bb888720f

## Purpose

F-361bb888720f prepares an instruction stream for an update-like operation. It resolves a target, maps assignments to column positions, reserves cursor and register identifiers, invokes policy and planning dependencies, and emits or patches instructions. A target byte selects an alternate delegated path.

**Established static evidence:** the body changes preparation state and calls instruction-generation dependencies. It does not itself iterate over stored rows or directly write stored records.

**Inferred intent:** the target is table-like, linked descriptors are index-like, the distinguished column is identifier-like, and two-phase preparation is trigger-related. These interpretations do not establish dependency or instruction semantics.

**Unknown:** the generated program’s runtime behavior. This contract describes preparation-time operations, conditional on dependencies returning normally and reached accesses and arithmetic being valid.

### Widths and preconditions

Words, addresses, mapping entries, and identifiers are 32-bit. Mapping entries are tested as signed. Byte fields are accessed at byte width.

Mapping allocation size is formed by shifting the target’s column-count word left by two. Descriptor-array allocation similarly uses a four-byte-per-entry size. No local overflow, index-range, chain-cycle, or identifier-exhaustion checks are established. Signed counter arithmetic and signed allocation-size arithmetic require suitable ranges; portable wraparound is not established.

Safe execution requires valid reached storage and terminating chains. Counts used for allocation, initialization, scanning, and later traversal are distinct observations. Dependencies are not assumed to preserve fields, arrays, or memory ownership.

No status is returned. Errors are observable through dependency calls, context changes, and potentially partial generated output.

## Behavior

### Entry and mapping allocation

The database address is saved from the context before the entry gate. Context field `0x40` is tested first. Only if it is zero is the saved database object’s byte at `0x1e` read. Either nonzero value bypasses preparation and reaches cleanup.

F-255803dd327e resolves the target using the context and target description. Null reaches cleanup. Otherwise:

1. F-49f750c2c596 receives the context’s **current** database address and target field `0x4c`; its result is saved as the database identifier.
2. F-795062e1d753 receives the context, target, operation `100`, and assignments. Its nonzero result enables two-phase preparation.
3. Presence of target field `0x18` is cached as a Boolean.
4. F-956f9fcb5326 receives the context, target, and phase-enabling result.
5. A zero result permits F-382bffe8f3c1.
6. Another zero result permits F-83e6016208ce with the saved database address and mapping allocation size.

A failed gate or null allocation reaches cleanup.

After allocation, ascending mapping entries receive `0xffffffff` while the index is less than the target’s **live signed count**. The allocation-size count is not retained as the initialization bound. An allocator-induced count change can therefore make initialization cover a different extent.

### Cursors and assignments

#### Retained positions and bounds

The post-scan test uses the live count, not a saved match flag. A comparison dependency can reduce the count while returning a match, so the post-scan name-recognition branch can run even after a mapping write.

An accepted unmatched name uses the retained termination position. Neither F-56e7529314e4 nor later policy argument formation recomputes that position. The column-array address is read afterward without bounds revalidation. Policy result `2` likewise writes the retained mapping position without checking the allocation extent.

With stable nonnegative count \(N\), an unsuccessful scan retains \(N\). Acceptance then selects a column outside the declared \(N\)-column range; result `2` writes outside the requested \(N\)-entry mapping extent. When counts change, either access may instead be within its corresponding extent. No spare entry is established.

### Descriptor and data registers

- Identifier-changing state selects every descriptor without inspecting its column-index array.
- Otherwise, participation requires at least one referenced mapping entry to be nonnegative.
- Participating descriptors receive a newly incremented context register counter; others receive zero.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Entry gate:** nonzero context field `0x40` prevents the database-byte read and resolution. Common cleanup still occurs.

2. **Duplicate assignments:** assume stable valid counts, names, assignment records, and relevant storage. Two accepted assignments matching one ordinary column cause ordered local writes of their respective positions to that mapping entry, each before its policy call. A policy result `2` causes a subsequent local sentinel write. A surviving final mapping value is established only if intervening dependencies preserve that mapping.

3. **Stable-count unmatched name:** if count \(N\) remains unchanged from allocation sizing through policy handling and no comparison matches, successful name recognition retains position \(N\). Policy argument formation accesses beyond the declared column range; result `2` writes beyond the requested mapping extent. Safe completion is not established.

4. **Changed-count unmatched name:** suppose four mapping entries were requested, scanning terminates at position two with count two, and name recognition increases the count to three while accepting. With valid three-column storage and four-entry mapping storage, the position-two column read and result-`2` mapping write are within their respective extents. The retained position remains two.

5. **Distinct phase snapshots:** suppose the two setup reads of program field `0x0c` yield `40` and `70`, while later reads differ. On reaching both transitions, their `0x5b` operands use `40` and `70` respectively. Patch calls use their own later reads, not those saved values.

6. **Mask precedence and boundary:** the distinguished column avoids both mapping and shift evaluation. An ordinary column reads its mapping first. At low-byte shift count `30`, the signed shift avoids the identified sign-bit hazard; at `31`, portable behavior is unestablished, including with an all-ones mask. Counts `32` through `255` have the separate width violation.

7. **Independent counting:** if initialization is skipped but dependencies make the later counting predicate true, `0x29` receives register zero, `1`, and `0`, before phase-closing emissions.

8. **Delegation and late failure:** normal alternate-path return makes target-description and selection cleanup arguments zero. Separately, a late phase error reaches cleanup without subsequent explicit temporary releases or closing emissions.
