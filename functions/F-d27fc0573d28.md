## Purpose

Its observable behavior depends on ambient machine state and dependency-produced values, not just its two declared inputs. The available evidence does not establish a conventional object operation, output-buffer transformation, or usable return value.

The supplied static representation ends at an invalid-instruction termination marker rather than an ordinary return. Normal completion and a stable final-state invariant are therefore not established.

This contract distinguishes:

- **Established static evidence:** operations and relationships explicitly represented in the supplied material, conditional on that representation being accurate.

## Behavior

### Entry effects and ordering

The first represented memory interaction reads an unsigned byte at the incoming address-like value plus one. Its value selects an absolute numeric destination by adding 0x11. The incoming 8-bit value is written there.

The destination lies between 0x11 and 0x110 inclusive. It is not represented as an offset into the region containing the selector.

Only after that store does the first indirect dependency call receive the second declared input. A later call receives the incoming unsigned address-like value shifted right by 11.

After further calls, the selector at the incoming address plus one is evaluated again. The new selector determines another destination in the same low-address range. The stored byte is derived from the other incoming unsigned 32-bit quantity: clearing its highest bit, shifting right by 21, then retaining eight bits selects original bits 21–28.

The two selector evaluations are distinct. No equality is guaranteed across intervening calls. The second selector is also retained for later argument forwarding; subsequent forwarding does not itself require another selector evaluation.

### Recurring selector-mediated stores

A recurring interaction consists of a selector-byte read followed by a byte write at numeric address 0x11 plus that selector. Dependency calls separate many such interactions.

Selector locations are derived from incoming state, primary results, secondary outputs, retained values, and apparent result components. Their derivations include scaling, masking, right shifts, and an offset of one. Several selector locations are explicitly numeric address 0x1 or reduce to it through established zero-valued unsigned calculations.

Represented byte values include:

Without that assumption, this document supplies no expected product or selector address for overflow-affected cases.

### Zero-address accesses are not no-ops
