# F-467cb0c60ff3

## Purpose

F-467cb0c60ff3 conditionally extracts a 32-bit value from an input record. It selects between two interpretations of the record’s field at byte offset 0x14:

- A value returned directly when an initial dependency result equals 0x15.
- An address of a tagged object, inspected only when a second dependency result satisfies an address-based eligibility test.

In the indirect case, the object must have a first 32-bit word equal to 4. The function then returns its second 32-bit word. Ordinary paths that do not select a value return zero.

This is a description of the supplied static evidence, not a claim about the application-level meaning of the values. The record’s type, the dependency’s purpose, and the meanings of 0x15 and 4 are not established.

## Behavior

### Initial classification

The first observable operation shown is a four-byte read from the input record at offset 0x10. That value is passed to F-2eb743f270d1.

If the dependency returns exactly 0x15, the function reads the record’s 32-bit field at offset 0x14 and returns it immediately.

On this path:

- F-2eb743f270d1 is called exactly once.
- The field at offset 0x14 is interpreted as the result itself, not as an address.
- No object tag is checked.
- No indirect object read occurs.
- The field is read after the dependency returns. Any change the dependency makes to that field can therefore affect the returned value.

The supplied logic does not snapshot offset 0x14 before invoking the dependency.

### Repeated classification

If the first dependency result is anything other than 0x15, the function reads offset 0x10 again and calls F-2eb743f270d1 again.

This is a second call with a newly loaded argument. It is not a reuse of the first result or the first argument.

Consequently:

- The second argument may differ if the first call changed the record.
- The second result may differ even when the argument remains unchanged.
- The second call occurs for every first result other than 0x15.
- There is no third dependency call.

If the second result is 0x15, the function does not return to the initial direct-value behavior. That result is instead processed by the eligibility test described next.

### Eligibility test

The second dependency result is adjusted by subtracting 0x15. The adjusted quantity is then interpreted as an address and compared against address 0x00000006.

The indirect-object path is eligible when that adjusted address is greater than or equal to address 0x00000006.

This operation has two important properties:

- The subtraction occurs before the address interpretation. It is not subtraction of 0x15 integer elements from an existing pointer.
- The comparison is expressed as an address comparison, not as an explicit signed comparison of the dependency result.

Under a 32-bit modular-address interpretation with unsigned address ordering, the condition is equivalent to subtracting 21 modulo 2³² and checking whether the result is at least 6. On that interpretation:

| Second result, expressed as a 32-bit pattern | Indirect-object eligibility |
|---|---|
| 0x00000000 through 0x00000014 | Eligible, because subtraction wraps to a high address value |
| 0x00000015 through 0x0000001A | Ineligible |
| 0x0000001B through 0xFFFFFFFF | Eligible |

Thus, under that interpretation, eligibility excludes exactly the six patterns from 21 through 26. It is not equivalent to a signed test that accepts only results of 27 or greater.

The exact machine-level arithmetic and comparison require confirmation beyond the supplied representation. This distinction is documented rather than assumed away.

If the eligibility test fails, the function returns zero without reading offset 0x14.

### Indirect-object selection

If the eligibility test succeeds, the function reads the record’s field at offset 0x14 as an object address.

It then applies these conditions in order:

1. If the address is null, return zero.
2. Otherwise, read the first 32-bit word at that address.
3. If that word is not exactly 4, return zero.
4. If it is exactly 4, read and return the next 32-bit word, at object byte offset 4.

The relevant object layout is:

| Object byte offset | Width | Observed use |
|---|---:|---|
| 0 | 4 bytes | Required tag value: 4 |
| 4 | 4 bytes | Returned value when the tag matches |

The object’s second word is not read when the tag differs from 4. The first word is not read when the selected address is null.

The object address is loaded after the second dependency call. The function does not use the earlier dependency argument as the object address.
