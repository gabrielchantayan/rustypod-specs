# F-29b3b2844d6d

## Purpose

F-29b3b2844d6d conditionally links a record into a context-maintained chain, then drains another chain through two calls per removed node. Its 64-bit result combines the original context address with a 32-bit status-like value.

The operation has two distinct paths:

- If the context’s record field is zero on entry, it performs no dependency calls or context writes and returns the second argument in the upper half of the result.
- If that field is nonzero, it invokes a preparation dependency, links the record selected by the context after that call, and drains the context’s pending-node chain. The upper half of the result then comes from a mutable working value supplied to the preparation dependency.

These are established control-flow effects. Interpreting the linked record as “active,” the pending nodes as “retired,” or the dependency calls as deallocation is inferred intent, not an established ownership contract.

## Interface

### Arguments

The function accepts four arguments:

1. **Context address.** An address used to access 32-bit fields. Relevant fields begin at byte offsets 0, 4, and 16.
2. **Fallback result word.** A 32-bit value used as the upper result word only when the initial context field at offset 16 is zero. Although represented as a signed integer in the supplied material, no signed comparison or arithmetic is performed on it; its bit pattern is what matters.
3. **Unused word.** A 32-bit argument with no established read or forwarding operation in this function.
4. **Preparation word.** A 32-bit value copied into temporary storage and exposed by address to F-30f3d8fd1907 on the nonzero-record path. It has no direct effect on the zero-record path.

### Result

The function returns a 64-bit packed value:

| Result bits | Meaning |
|---|---|
| 31–0 | The original context address, represented as a 32-bit word |
| 63–32 | The fallback result word on the zero-record path; otherwise, the final working word described below |

Packing does not sign-extend the upper word into a larger result. For example, an upper word of `0xFFFFFFFF` occupies exactly bits 63–32.

The source representation uses 32-bit fields as addresses and packs the context address into a 32-bit result component. This contract therefore describes that represented address model. A portable wider-pointer calling convention is not established.

### Required memory layouts

The context exposes these fields:

| Byte offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Pending-chain head; read and updated during draining |
| 4 | 32 bits | Existing linked-chain head; read and replaced during linking |
| 16 | 32 bits | Record selector; tested initially, read again before preparation, and read again afterward |

A record selected through context offset 16 exposes:

| Byte offset | Width | Established use |
|---|---:|---|
| 8 | 32 bits | Read to initialize a preparation working word |
| 12 | 32 bits | Written with the previous linked-chain head |

Each pending node exposes:

| Byte offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Successor address |
| 4 | 32 bits | Second argument to the first per-node dependency call |
| 8 | 32 bits | First argument to that call |

The minimum valid extent of each object follows from the fields actually accessed. The material does not establish complete object sizes, allocation boundaries, alignment rules, or additional fields.

## Behavior

### 1. Initial branch selection

The function first reads the context’s 32-bit field at offset 16 into a working word.

If that word is zero:

- No pending-chain field is read.
- No linked-chain field is read or written.
- Neither dependency is invoked.
- The upper result word is the second argument.
- The lower result word is the original context address.

An existing pending chain is therefore not drained when the initial record selector is zero.

### 2. Preparation on the nonzero-record path

If the initial record selector is nonzero, the function reads context offset 16 again and uses that newly read address to obtain the 32-bit field at record offset 8.

That second selector read matters: the address used for this field access is not contractually guaranteed to equal the selector captured for the initial branch decision. No synchronization or stability mechanism is shown.

The function prepares three address-exposed temporary words:

- A **working selector word**, initially containing the selector captured by the first read.
- A **record-derived word**, initialized from offset 8 of the record selected by the second read.
- A **preparation word**, initialized from the fourth argument.

It then calls F-30f3d8fd1907 with four arguments, in this order:

1. Address of the preparation word.
2. Original context address.
3. Address of the record-derived word.
4. Address of the working selector word.

The dependency can directly modify all three temporary words and the context through the supplied addresses. Its return value is not used.

Only the working selector word is explicitly consumed later by this function. Changes to the other two temporary words have no direct subsequent use here, although the dependency may also cause independent side effects.

The temporary addresses are supplied during this invocation. No permission to retain them beyond their valid lifetime is established.

### 3. Linking the post-preparation record

After F-30f3d8fd1907 returns, the function reads context offset 16 again. This post-call value selects the record that will be linked.

The function then:

- Reads the current linked-chain head from context offset 4.
- Writes that value to offset 12 of the selected record.
- Writes the selected record address to context offset 4.

The record’s link field is written before the context’s linked-chain head is replaced.

The selected record is not taken from the working selector word, even though the preparation dependency can modify that word. Consequently:

- The record initially tested may differ from the record eventually linked.
- The record whose offset-8 field was read may differ from the record eventually linked.
- The upper result word may differ from every record address involved.

There is no nonzero check on the post-preparation selector. A preparation dependency that leaves context offset 16 zero or otherwise invalid does not trigger a defined error branch; the function proceeds to the record-offset-12 write.

### 4. Draining the pending chain

Once linking is complete, the function repeatedly reads the pending-chain head at context offset 0.

A zero head terminates draining. A nonzero head selects one pending node for the current iteration.

For each selected node, the function performs these effects in order:

1. Reads the selected node’s successor at offset 0.
2. Writes that successor into the context’s pending-chain head.
3. Reads the selected node’s words at offsets 8 and 4 for dependency arguments.
4. Calls F-ff1bdc376dcd with the offset-8 word, the offset-4 word, and a zero third argument.
5. Calls F-ff1bdc376dcd again with the selected node’s address, the value one, and a zero third argument.
6. Rechecks the context’s pending-chain head for the next iteration.

The relative evaluation order of the offset-8 and offset-4 argument reads is not established. Both supply the first per-node call.

The node is removed from the context chain before either dependency invocation. Thus a dependency that observes the context through another route sees the updated head, subject to any additional mutations it performs.

The second dependency invocation always uses the node selected at the beginning of that iteration. It does not substitute a newly read context head.

The next iteration reads the context head afresh. Dependencies that mutate the head can therefore change which nodes are subsequently processed, add work, terminate traversal, or prevent termination. The function does not retain an independent traversal cursor that overrides those mutations.

### 5. Result selection

On the nonzero-record path, the upper result word ultimately comes from the working selector word exposed to F-30f3d8fd1907. The loop’s terminating head check refreshes the return candidate from that word.

If preparation leaves the working selector word unchanged, and no other permitted side effect changes that storage, the returned upper word is the selector captured by the initial read—not necessarily the record linked after preparation.

The lower result word remains the original context address. Mutating the context’s contents does not replace that address in the result.

## Side effects

### Direct effects

On the nonzero-record path, the function directly:

- Writes the previous linked-chain head into the selected record at offset 12.
- Replaces context offset 4 with that record’s address.
- Replaces context offset 0 once for every pending node selected for processing.

If draining terminates normally, its final head check observed zero at context offset 0.

The function does not directly clear context offset 16. It also does not directly overwrite the selected pending node’s successor or payload fields.

### Ownership and lifetime

The two per-node calls are consistent with releasing node-associated storage and then releasing the node, but that interpretation is not established by this function alone.

In particular, the contract does not assume that F-ff1bdc376dcd:

- Frees either address.
- Owns any argument.
- Preserves global state.
- Preserves the context or other pending nodes.
- Cannot fail, reenter, or terminate execution.

The first per-node call must return in a state that permits the second call to receive the selected node’s address. Whether passing an address after its storage has been released is valid depends on the dependency contract; this function does not settle that question.

### Preconditions and errors

There is no explicit argument validation, error return, rollback, or recovery branch.

For normal completion, all executed memory accesses must be valid, dependencies must return normally, and the pending traversal must reach a zero head. Relevant safety requirements include:

- A readable context selector even on the zero-record path.
- A readable offset-8 field for the record used before preparation.
- Writable selected-record offset 12 and context offset 4 after preparation.
- Readable pending-node fields and writable context offset 0 during draining.

Malformed addresses, insufficient object extents, destructive aliasing, or dependency effects that invalidate later accesses are not converted into a documented status. Their consequences are outside the established normal behavior.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

### Zero selector with a nonempty pending chain

Given a valid context whose offset-16 field is zero, and a second argument of `0x89ABCDEF`:

- No dependency is called.
- The pending chain remains untouched by this function.
- The upper result word is `0x89ABCDEF`.
- The lower result word is the context address.

### Preparation without selector changes

Suppose the initial selector identifies record A, preparation leaves both the context selector and working selector unchanged, and the pending head is zero.

Expected effects:

- A’s offset-12 field receives the previous context offset-4 value.
- Context offset 4 becomes A’s address.
- No per-node calls occur.
- The upper result word is A’s address.

### Preparation selects a different record

Suppose the initial selector identifies A, preparation changes context offset 16 to B, and preparation sets the working selector word to `0x13572468`.

Expected effects:

- The pre-preparation offset-8 read is from the record selected at that earlier read.
- B receives the old linked-chain head at offset 12.
- Context offset 4 becomes B’s address.
- Assuming normal completion without later changes to the working word, the upper result word is `0x13572468`, not A or B.

### Two stable pending nodes

Suppose the pending chain is N followed by M followed by zero, and dependencies preserve that chain state apart from this function’s writes.

Expected dependency order:

1. N’s offset-8 word, N’s offset-4 word, zero.
2. N’s address, one, zero.
3. M’s offset-8 word, M’s offset-4 word, zero.
4. M’s address, one, zero.

Before the first pair, context offset 0 becomes M. Before the second pair, it becomes zero.

### Dependency changes the pending head

If a dependency changes context offset 0 to Q during processing of N, the next iteration processes Q rather than blindly following N’s previously read successor, provided Q is nonzero and valid.

### Invalid post-preparation selector

If preparation changes context offset 16 to zero, no guarded failure or fallback result is established. The function attempts the selected-record link write using that value.
