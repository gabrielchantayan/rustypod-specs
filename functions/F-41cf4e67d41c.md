# F-41cf4e67d41c

## Purpose

F-41cf4e67d41c advances an indexed record cursor and prepares a mode-dependent sequence of output values. It can skip records, report exhaustion, divert to an error-reporting path, or return a completed output sequence.

The established behavior is structural: it selects a record from a table with 20-byte entries, writes tagged value slots, and invokes dependencies to obtain or transform two string-like values. Names such as “record,” “slot,” and “string-like” describe the visible layout, not a verified external data model.

The function is not transactional. Cursor advancement, output-pointer publication, dependency effects, and partial output writes can remain visible on unsuccessful returns.

## Behavior

### 1. Entry capture and discriminator check

The function reads the external expected discriminator, the state’s owner address, and the state’s output-object address. It computes the output-object address plus `0x28` and writes that address to state offset `0xF8`.

This publication occurs before validating the discriminator.

If the state word at offset `0x44` differs from the captured expected value, the function immediately returns `0x15`. It does not directly advance the cursor or explicitly write the status field on this path.

If the discriminator matches, it calls F-c171d4869dd0 with:

1. The initial slot address, output object plus `0x28`.
2. The state word at offset `0x48`.
3. The value `1`.
4. The fourth argument.
5. The fourth argument again.

The return value is not used. Initialization, clearing, allocation, and ownership effects of this call are unknown.

### 2. Cursor advancement and selection

Each selection attempt reads the cursor at state offset `0x70`, then immediately stores that value plus one back to the same field. The pre-increment value is the candidate index.

The signed record-count comparison occurs after this increment. If the candidate is at or beyond the count, selection stops without a record-marker read for that candidate.

Otherwise:

- If the current mode conversion is not `2`, selection stops at the candidate.
- If the mode conversion is `2`, the candidate record’s first byte is read.
- A first byte equal to `0x6E`, the byte value for `n`, causes another selection attempt.
- Any other first byte selects that candidate.

Thus mode 2 skips consecutive `0x6E` records. Each skipped record consumes one cursor increment. The attempt that discovers exhaustion also increments the cursor.

After selection, the count is read again for a signed comparison against the candidate. If the candidate is at or beyond that count, the function writes zero to state offset `0x74` and returns `0x65`.

The function does not explicitly reject negative indices, negative counts, cursor overflow, or address-arithmetic overflow.

### 3. Owner-controlled diversion

After successful selection, the function reads the 32-bit field at offset `0xD8` of the owner captured at entry.

If nonzero, it:

1. Writes `9` to state offset `0x74`.
2. Calls F-d5aed6d90713 without explicit arguments.
3. Passes that result to F-2cb24bca4183, together with the address at state offset `0xF4` and a final zero argument.
4. Returns `1`.

The record has already been consumed by cursor advancement. The normal output-value construction below is bypassed.

### 4. Mode-1 prefix

The selected record address is formed using the state’s record-table address and the selected index, with a stride of 20 bytes.

If the mode conversion is `1`, the function writes two prefix slots before the common record values.

The first prefix slot begins at output-object offset `0x28`. Its writes occur in this order:

1. A 16-bit tag of `4` at slot offset `0x1C`.
2. An attribute byte of `1` at slot offset `0x1E`.
3. The selected 32-bit index at slot offset `0x00`.
4. Its sign-extension word at slot offset `0x04`.

The second prefix slot begins at output-object offset `0x50`:

1. A 16-bit tag of `0xA2` is written at slot offset `0x1C`.
2. The record’s first byte is interpreted as unsigned and multiplied by four to select a 32-bit external lookup entry.
3. That entry is written at slot offset `0x14`.
4. F-1cb585febd84 is called with no explicit argument in the supplied representation.
5. Its result is written at slot offset `0x18`.
6. Bytes `3` and `1` are written at offsets `0x1E` and `0x1F`, respectively.

The common numeric-slot cursor then starts at output-object offset `0x78`. Without this prefix, it starts at offset `0x28`.

### 5. Numeric record fields

Two numeric slots are always constructed after selection and the owner check:

- The first receives the signed 32-bit record field at offset `0x04`.
- The second receives the signed 32-bit record field at offset `0x08`.

For each slot, the function writes the 16-bit tag `4`, reads the record field, writes its low 32-bit payload, writes a 32-bit sign-extension word, then writes attribute byte `1` at slot offset `0x1E`.

The sign-extension word is zero for nonnegative values and all ones for negative values. These writes form a two-word representation of the original signed 32-bit value; they do not widen its range.

The mode is then checked again. If it converts to `1`, a third numeric slot is populated from record offset `0x0C`, using the same tag, payload, sign-extension, and attribute pattern.

2. F-a5347e97e77b is called with the selected record address, the current slot field at offset `0x14`, and `0x20`.

### 8. Completion and failure

## Side effects

Direct effects include:

- Publishing the initial slot address even on discriminator mismatch.
- Advancing the cursor before exhaustion, owner diversion, or output-allocation failure is reported.
- Writing partial output before later failures.
- Updating status and completion fields only on the specified paths.
- Marking the currently referenced owner on return `7`.

There is no explicit rollback, memory release, or ownership transfer in the supplied body. Dependencies may allocate, release, retain, or modify memory, but none of those behaviors is established here.

Addresses and selected indices retained locally can survive dependency calls even if those calls modify the corresponding state fields. Conversely, mode checks, selected state reads, and pointer-field reads occur again at specified later points. A single entry-time mode snapshot is not an accurate model.

For stable mode 1, slot starts are output offsets `0x28`, `0x50`, `0x78`, `0xA0`, `0xC8`, `0xF0`, `0x118`, and `0x140`. For stable non-mode-1 operation, the two numeric slots and first string-like slot start at `0x28`, `0x50`, and `0x78`.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid memory, ordinary non-overlapping layouts, and dependency behavior consistent with each example.

1. **Discriminator mismatch:** The published initial-slot pointer is updated, and the result is `0x15`. No direct cursor increment occurs.

2. **Immediate exhaustion:** With cursor and count both `5`, the cursor becomes `6`, status becomes zero, and the result is `0x65`. No candidate marker read is required.

3. **Mode-2 skipping:** With cursor `0`, count `3`, stable mode `2`, and marker bytes `0x6E`, `0x6E`, then `0x41`, index `2` is selected and the cursor becomes `3`.

4. **Skipped final record:** With cursor `0`, count `1`, stable mode `2`, and marker `0x6E`, the cursor becomes `2`: once for the skipped record and once for the exhaustion attempt. The result is `0x65`.

5. **Owner diversion:** A valid selected index plus a nonzero captured-owner field at `0xD8` produces status `9`, the two reporting-related calls, and result `1`.

6. **Signed payload:** A record numeric field of `−1` produces low and high payload words both equal to `0xFFFFFFFF`, tag `4`, and attribute `1`.

7. **Stable mode-1 completion:** If both slot-preparation calls return zero, construction includes the index prefix, lookup prefix, three numeric values, two string-like values, and terminator fields. Completion stores `8` at state offset `0xEC` and returns `100`.

8. **Stable mode-2 completion:** With successful dependencies, no mode-1 prefix or additional string-like slot is constructed directly. Completion stores `3` at state offset `0xEC`.

9. **Second preparation failure:** In mode 1, a successful first preparation followed by a nonzero second preparation leaves earlier output writes intact, marks the reread owner, and returns `7`.
