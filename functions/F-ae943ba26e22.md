# F-ae943ba26e22

## Purpose

F-ae943ba26e22 searches forward through consecutive character elements for a value equal to a supplied target.

For a positive count and valid storage, it returns the address of the earliest matching element among the specified number of elements, or null if none matches. The count, not a terminator, limits the search. A zero-valued element has no special role unless it equals the target.

A zero count returns null without reading the supplied storage or performing search-related pointer arithmetic.

A negative count enters the search rather than being rejected. It does not reverse traversal. Its count-derived boundary is behind the start, where that displacement is valid, while candidate selection proceeds forward. Such a count therefore does not provide the bounded-miss behavior available for a positive count.

The interpretation as a bounded search is inferred intent. The conditions governing candidate selection, comparison, and return are established by the supplied definition.

## Behavior

### Empty search

A zero count returns null, regardless of the target or any potential match at the start.

This path does not inspect a candidate, form the count-derived boundary, or advance a candidate position. It therefore does not require the start to designate readable storage.

### Positive-count results

For a positive count, valid pointer operations, and stable storage, the eligible range consists of exactly the requested number of consecutive elements beginning at the start.

The result is governed by these rules:

- The earliest eligible element equal to the target supplies the returned address.
- If every eligible element differs from the target, the result is null.
- No element after the first match is inspected.
- The element immediately beyond the eligible range is not read.
- A zero-valued element does not terminate the search for another value.

A count of one permits only two results: the start address if its element matches, or null otherwise. The following position is still required for boundary handling, but its element is not inspected.

### Evaluation and access constraints

The definition distinguishes candidate traversal from the final decision to return a candidate address.

For every candidate considered, its following position is formed before character equality can determine the result. The continuation boundary compares that following position with the position displaced from the start by the count. An immediate match does not bypass these pointer operations.

The boundary decision precedes any character comparison used to decide whether traversal continues. Consequently, the last eligible candidate of a positive-count search is handled differently from an interior candidate:

| Candidate situation | Required character-value evaluations |
|---|---|
| Interior candidate that differs from the target | One equality evaluation for continuation. |
| Interior candidate whose continuation comparison matches | A continuation equality evaluation, followed by a separate final equality evaluation. |
| Last eligible candidate of a positive-count range | A final equality evaluation, without a continuation equality evaluation. |
| Element immediately beyond a positive-count range | No candidate read. |

The separate final equality controls whether a candidate address or null is returned. With stable storage, a matching interior candidate satisfies both evaluations.

If an execution environment permitted those two evaluations to observe different values, a failed final comparison would produce null; the search would not resume at the next candidate. The supplied evidence does not establish a supported mechanism for such mutation. Unsynchronized concurrent writes are not valid acceptance conditions.

These constraints describe source-level value evaluations. They do not promise a particular number, timing, or order of physical memory transactions after compilation. The storage interface is neither volatile nor atomic. Ordinary-read optimization may change the physical realization without changing defined behavior.

Similarly, the contract does not require a compiled implementation to retain, recompute, or materialize the count-derived boundary in any particular manner.

### Negative counts

Negative counts are not empty searches, validation failures, or requests to search backward.

Where validly formed, the count-derived boundary lies earlier in the same array than the start. Forward advancement within that array cannot reach that earlier boundary. The boundary therefore supplies no valid exhaustion point for this path.

A forward match can nevertheless produce a defined result. For example, an interior start may have both a valid earlier boundary and a valid following position. If its element matches and remains stable across the required evaluations, the function returns the start. A later forward match can also be returned if every intervening operation is valid.

Without a match, forward traversal through a finite array eventually requires an invalid operation. The definition supplies no graceful miss result, wraparound behavior, or termination guarantee beyond that point.

Negativity alone does not make the initial displacement invalid: validity depends on the start’s location in its actual array. Conversely, representability of the signed count does not establish that the corresponding pointer displacement is valid.

Boundary and advancement requirements apply even to searches that would match immediately. An invalid count-derived position is not made harmless by readable matching storage.
