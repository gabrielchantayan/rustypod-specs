# F-ea2187d1da59

## Purpose

The supplied static representation describes an initial byte write, two setup calls, and an unconditional repeating sequence of ten indirect calls with an intervening byte write. Results from the final call in each group determine two arguments in the next group.

The first call position within the repeating sequence changes target after the first group. The first group uses a target-selection value established during setup. Every subsequent group uses a different target-selection value established near the end of the preceding group. These targets must not be treated as the same dependency or assumed to have equivalent behavior.

No application-level purpose is established. The writes are not established as device operations, and the call sequence is not established as a protocol.

This contract describes the supplied static representation, subject to its instruction-recovery and control-flow warnings. It is not a runtime-validated description of an executable. No runtime tests have been performed.

## Interface

### Explicit input

There is one explicit unsigned scalar input.

Under the recovered 32-bit word model, its original value supplies:

- The argument to the first setup call, after a left shift by one bit.
- The second argument to the first call of the first repeating group, after a logical right shift by eight bits.

The original input is replaced by feedback at the end of the first group. It does not directly supply arguments in subsequent groups.

The supplied representation identifies this input as an unsigned integer but does not include an independently verified ABI or integer-width declaration. Numerical examples below are conditional on 32-bit words.

### Implicit incoming state

Three incoming values are used without appearing as explicit formal parameters:

| State item | Use |
|---|---|
| Incoming data word | Supplies the initial stored byte and the first group’s shifted-byte value. |
| Incoming address base | Locates the selector byte at offset one. |
| Incoming linkage value | Selects the first setup-call target after addition of `0xF74`. |

The data word has an unsigned interpretation in the supplied representation. The address base and linkage value participate in address calculations. Their provenance, validity, and calling convention are unknown.

### Output and termination

No explicit return value or normal return path is shown.

If all dependencies return normally and all accesses succeed, the represented control flow repeats indefinitely. This does not establish that actual execution cannot fault, trap, transfer control elsewhere, or remain inside a dependency.

### Memory layout

The directly visible memory operations use only these locations:

| Location | Access width | Meaning |
|---|---:|---|
| Incoming address base plus one | 8 bits | Unsigned destination selector |
| Numeric address `0x11` plus the selector | 8 bits | Destination of a byte write |

The selector is an unsigned byte, not a stored pointer. The selected destination therefore ranges from `0x11` through `0x110`, inclusive.

No larger object layout, allocation extent, alignment contract, or ownership relationship is established. Because all explicit accesses are one byte wide, their interpretation does not depend on multi-byte byte order.

## Behavior

### Arithmetic model

For the unsigned 32-bit interpretation used by the conditional examples:

- Left shifts retain the low 32 bits.
- Right shifts introduce zero bits.
- A one-byte store retains the low eight bits of its value.

Consumed dependency results are represented as signed integers. Their subsequent left shifts require separate treatment: ordinary 32-bit machine-shift results can be described, but defined signed-language behavior is not established for negative values or results outside the signed range.

In particular, converting a shifted result to the unsigned current-input state does not, by itself, establish that the preceding signed shift was defined.

Address overflow, integer-to-address interpretation, and fault behavior remain undocumented.

### Dependency identity

The dependency IDs in this contract label distinct visible call-target expressions. They are not independently verified function identities.

Two IDs distinguish the changing first call position:

- **F-dep-03**: the target selected for the first group.
- **F-dep-13**: the different target selected for every subsequent group.

The source establishes different target-selection constants for these calls. It does not establish whether either target aliases another entry point or whether their implementations behave similarly.

### Initial byte write

Before any dependency call:

1. Read an unsigned byte from the incoming address base plus one.
2. Select destination address `0x11` plus that byte.
3. Write the low eight bits of the incoming data word to that destination.

The destination’s previous value is not visibly read. There is no visible null, bounds, permissions, or validity check.

### Setup

Following the initial write:

1. A fixed target-selection value for F-dep-02 is established.
2. **F-dep-01** is called with the original input shifted left by one bit. Its target depends on the incoming linkage value plus `0xF74`. Its return value is not visibly consumed.
3. The first-group target-selection value for F-dep-03 is established.
4. **F-dep-02** is called with no explicit arguments. Its returned word becomes the initial carried value.

The first repeating group therefore begins with:

- The original explicit input as its current input word.
- The result of F-dep-02 as its carried value.
- The incoming data word as its current data word.
- The first-group target selection for its first call.

“No explicit arguments” does not imply that a dependency observes no registers, memory, globals, or other machine state.

### Repeating group

Each completed group contains ten calls. The byte write occurs after the fifth call and before the sixth.

| Call position | Operation |
|---:|---|
| 1 | Call F-dep-03 in the first group, or F-dep-13 in every later group, with the carried value and the current input word logically shifted right by eight bits. |
| 2 | Call **F-dep-04** with no explicit arguments. |
| 3 | Call **F-dep-05** with no explicit arguments. |
| 4 | Call **F-dep-06** with no explicit arguments. |
| 5 | Call **F-dep-07** with no explicit arguments and retain its result. |
| — | Re-read the selector and perform the group’s byte write. |
| 6 | Call **F-dep-08** with the result of F-dep-07 shifted left by two bits. |
| 7 | Call **F-dep-09** with no explicit arguments. |
| 8 | Call **F-dep-10** with no explicit arguments. |
| 9 | Call **F-dep-11** with no explicit arguments. |
| 10 | Call **F-dep-12** with no explicit arguments and retain its result. |

Returns from the first four calls, and from calls six through nine, are not visibly consumed. This does not constrain their side effects or establish that they return normally.

The target-selection state used at the first call position is reused for selecting several intervening calls. It is not a permanently fixed first-call target. Immediately before F-dep-12 is invoked, that state is assigned the constant selecting F-dep-13. F-dep-12 itself uses a separately established target.

Consequently, after F-dep-12 returns and execution follows the back edge, the first call is to F-dep-13, not F-dep-03. The first-group selection is not restored on that path.

### Byte write within each group

After F-dep-07 returns and before F-dep-08 is called:

1. Read the selector byte again from the incoming address base plus one.
2. Select destination address `0x11` plus that byte.
3. Store the low eight bits of the current data word logically shifted right by 22 bits.

In the first group, the stored value consists of original data bits 22 through 29. It is not the conventional most-significant byte, and it is not the entire shifted word.

The selector is re-read for every write. A dependency or an earlier aliasing write can therefore change the destination of a later store.

### Feedback and subsequent groups

After F-dep-12 returns:

- Its result shifted left by two bits becomes the next carried value.
- Its result shifted left by 26 bits becomes the next current input word.
- The current data word becomes zero.
- Execution begins the next group using the already-established F-dep-13 target selection.

There is no visible condition, counter, delay, or termination test.

Under ordinary 32-bit bit-vector shift semantics, for a final result \(t\):

- The next first argument to F-dep-13 is \((t \times 4) \bmod 2^{32}\).
- Its second argument is \((t \mathbin{\&} 0x3F) \ll 18\).
- The next group’s byte write stores zero.

Only the low six bits of \(t\) affect the next second argument. Both shifted arguments are subject to the signed-shift qualification above.

The first group is the only group using F-dep-03. Every later group uses F-dep-13 at that position. Every group after the first also uses a zero current data word.

## Side effects

### Direct memory effects

The represented function performs:

- One initial selector-byte read and one initial byte write.
- One further selector-byte read and byte write per reached group-write position.

Repeated writes remain distinct operations even when their address and value are unchanged.

The selected destination may alias the selector location; no evidence excludes that possibility. Such a write can change the selector read by a subsequent operation.

The memory may be ordinary storage, mapped hardware, protected storage, or invalid addresses. Its classification and any externally significant consequences are unknown.

### State changes

The visible carried state consists of:

- The carried argument value.
- The current input word.
- The current data word.
- The changing call-target selection.

All four matter to subsequent behavior. Describing only scalar argument feedback would omit the transition from F-dep-03 to F-dep-13.

These local state relationships do not imply any global-state preservation guarantee.

### Dependency effects and ownership

No explicit allocation, release, resource acquisition, or ownership transfer is visible.

The incoming address base is used as an address; ownership of the referenced storage is not established. Numeric arguments passed to dependencies are not established as pointers.

No dependency is assumed to preserve global state, leave the selector unchanged, avoid re-entry, or refrain from allocating, retaining, transferring, or releasing resources. Such behavior requires dependency evidence that is not supplied.

### Errors

There is no visible error return, status check, rollback, or recovery branch.

Consumed results are used in shifts without a visible error-value check. A dependency’s failure-like return value is not recognized as an error by the shown control flow.

## Acceptance examples

These examples are conditional consequences of the supplied representation, not observed test results. Unless otherwise stated, they assume valid accesses, normally returning dependencies, and the 32-bit arithmetic model.

### Initial write and shifted extraction

For an incoming data word of `0xA5C39E72` and an unchanged selector of `0x20`:

- The initial write stores `0x72` at address `0x31`.
- The first group’s write stores `0x97` at address `0x31`.
- Later groups’ writes store `0x00`.

The value `0x97` comes from bits 22 through 29.

### First-group input and target

For an explicit input of `0x80000180`:

- F-dep-01 receives `0x00000300`.
- The first group calls F-dep-03 at its first call position.
- That call’s first argument is the result of F-dep-02.
- Its second argument is `0x00800001`.

Calling F-dep-13 at this first-group position would not match the represented target selection.

### Feedback changes arguments and target

If F-dep-12 returns `3` at the end of the first group:

- The second group begins by calling F-dep-13, not F-dep-03.
- Its first argument is `12`.
- Its second argument is `0x000C0000`.
- Its group write stores zero.

These particular shifts remain within the positive signed 32-bit range. They do not require an overflowing signed-shift interpretation.

If F-dep-12 again returns `3`, the third group also calls F-dep-13 with those arguments. There is no alternating return to F-dep-03.

### Re-reading the selector

If the initial selector is `0x20` and a dependency changes it to `0x40` before the first group write:

- The initial write targets `0x31`.
- The first group write targets `0x51`.

Caching the initial selector across these operations would violate the visible access sequence.

### Selector boundaries

A selector of zero selects address `0x11`. A selector of `0xFF` selects address `0x110`.

Neither value is visibly rejected. Successful memory access remains a precondition.

### Interrupted progress

If F-dep-07 does not return, that group’s byte write and later calls are not reached.

If F-dep-12 does not return, no next group is reached, even though the target-selection state for F-dep-13 has already been established. Assigning that selection does not itself invoke F-dep-13.

It also establishes the target transition: setup selects F-dep-03 for the first group; a different constant replaces that selection before F-dep-12; the back edge reaches the next first-call position without restoring the setup selection.
