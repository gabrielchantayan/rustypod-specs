# F-04713ea74d07

## Purpose

F-04713ea74d07 returns a signed 32-bit quantity derived from fields of a caller-supplied object. Two predicate results select between:

- A difference between two object fields, optionally limited by a value read from an associated object.
- A difference using an alternative endpoint, without that limit.

An entry dependency and an exit dependency are called with the address of an embedded region in the primary object. Their placement suggests synchronization, but their actual effects are not established.

The established behavior is the selection, calculation, conditional associated-object access, and return sequence described below. Interpreting the result as available capacity, readable length, or another particular domain quantity would be inferred intent, not a demonstrated contract.

## Behavior

### 1. Entry operation

The function first calls an entry dependency, identified here as **D-01**, with the primary-object address plus `0x24`.

D-01 and D-02 below are opaque document-local dependency identifiers. Their externally assigned function IDs are not provided.

No predicate call or primary-object data-field read used in the result calculation precedes D-01 in the established sequence.

D-01’s effects are unknown. In particular, the specification does not assume that fields retain their pre-call values, that a lock has actually been acquired, or that the dependency preserves global state.

### 2. Predicate selection

After D-01 returns, the function calls F-900e57cefc4b with:

- The primary-object address.
- The 32-bit value `0x00040000`.

If this call returns zero, the function selects the **common calculation path** immediately. It does not perform the second predicate call.

If this call returns nonzero, the function calls F-900e57cefc4b again, with:

- The same primary-object address.
- The 32-bit value `0x00010000`.

A nonzero second result selects the common calculation path. A zero second result selects the **alternative calculation path**.

Only zero versus nonzero matters. The function does not require a nonzero result to equal one, and negative predicate results count as nonzero.

The values passed to F-900e57cefc4b resemble flag masks, but the dependency’s implementation is not available. The contract therefore describes them as arguments to a predicate, not as proof that any particular stored flag is tested.

### 3. Common calculation path

The function reads the signed 32-bit values at primary-object offsets `+0x1c` and `+0x18`, and calculates:

**common difference = value at `+0x1c` − value at `+0x18`.**

Both reads occur after all predicate calls required for this path. Their relative order within the subtraction is not established by the supplied representation.

#### Negative common difference

If the common difference is negative:

- It becomes the selected result.
- The function does not read the associated-object address at `+0x04`.
- Neither associated-object dependency is called.
- The associated-object field at `+0x14` is not read.

The result is not clamped to zero.

#### Nonnegative common difference

If the common difference is zero or positive, the function:

1. Reads the 32-bit associated-object address from primary-object offset `+0x04`.
2. Calls F-1baafa35e5fb with that captured address.
3. Reads the signed 32-bit field at offset `+0x14` from that captured associated-object address.
4. Calls F-885b1df95043 with the same captured address.
5. Selects the smaller signed value between the previously calculated common difference and the captured associated-object field.

The associated-object address is not reread after F-1baafa35e5fb. If that dependency changes the primary object’s `+0x04` field, the later field access and F-885b1df95043 call still use the address already captured.

The common difference is also not recomputed after either associated-object dependency. Changes those dependencies make to primary-object endpoint fields do not update that captured difference.

The associated-object field is read after F-1baafa35e5fb returns and before F-885b1df95043 is called. The selected value uses that captured field value, not a new read after F-885b1df95043.

The signed comparison has several consequences:

- An associated value larger than the difference leaves the difference unchanged.
- An associated value smaller than the difference replaces it.
- Equality yields that shared value.
- A negative associated value replaces any nonnegative common difference, producing a negative result.

There is no visible validation that the associated value is nonnegative.

### 4. Alternative calculation path

This path is reached only when the first predicate result is nonzero and the second predicate result is zero.

The function reads the signed 32-bit values at primary-object offsets `+0x50` and `+0x18`, and calculates:

**alternative difference = value at `+0x50` − value at `+0x18`.**

This difference becomes the selected result without comparison against the associated-object field.

On this path:

- The common endpoint at `+0x1c` is not read by the visible calculation.
- The associated-object address at `+0x04` is not read.
- F-1baafa35e5fb and F-885b1df95043 are not called.
- Negative differences are not clamped or otherwise adjusted.

As with the common-path subtraction, the relative order of its two operand reads is not established.

### 5. Exit operation and return

After selecting the result, the function captures it for return and calls **D-02** with the primary-object address plus `0x24`.

If D-02 returns normally, the function returns the previously selected signed 32-bit value. There is no visible recalculation or object-field reread after D-02.

Consequently, ordinary changes D-02 makes to the primary object or associated object do not change the already selected result. No stronger claim is made about abnormal control flow, invalid memory effects, or other behavior outside the supplied representation.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, assume valid addresses, normally returning dependencies, representable signed arithmetic, and no dependency mutations affecting the values described.

1. **First predicate is zero.**  
   The `0x00040000` call returns zero. With `+0x1c = 80`, `+0x18 = 20`, and associated `+0x14 = 45`, the return is **45**. The `0x00010000` predicate call must be absent.

2. **Second predicate selects the common path.**  
   The first predicate returns a nonzero value and the second returns a nonzero value. With a common difference of 60 and associated value 90, the return is **60**. Both associated-object dependencies occur around the associated field read.

3. **Alternative endpoint is selected.**  
   The first predicate returns nonzero and the second returns zero. With `+0x50 = 95` and `+0x18 = 20`, the return is **75**. No associated-object access or associated-object dependency call occurs, regardless of the value at `+0x1c`.

4. **Negative common difference bypasses the associated object.**  
   A common-path selection with `+0x1c = 10` and `+0x18 = 25` returns **−15**. An unusable address in `+0x04` is not itself dereferenced by this function on that path. This does not waive any independent requirements imposed by the reached dependencies.

5. **Zero still reaches the associated object.**  
   A common difference of zero and associated value 7 returns **0**, but the associated-object address read, both associated-object calls, and the intervening field read still occur.

6. **Negative associated value is retained.**  
   A common difference of 12 and associated value −4 returns **−4**. No nonnegative-result guarantee applies.

7. **Alternative negative result is unchanged.**  
   On the alternative path, `+0x50 = 5` and `+0x18 = 9` produce **−4**, without associated-object limiting.

8. **Captured associated address remains in use.**  
   If F-1baafa35e5fb changes the primary object’s associated-address field, the subsequent `+0x14` read and F-885b1df95043 call still use the address captured before that change, provided it remains valid.

9. **Exit-time field mutation does not recalculate the result.**  
   If the selected result is 18 before D-02, changing an endpoint field during D-02 does not cause a new subtraction. Normal return yields **18**.

10. **Unused argument variation.**
