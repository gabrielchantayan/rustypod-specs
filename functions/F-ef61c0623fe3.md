# F-ef61c0623fe3

## Purpose

F-ef61c0623fe3 conditionally selects a 32-bit value from an associated object, applies that value through an input-object callback, and emits a notification. One successful path also records two values in the input object and invokes F-069a1d444a2d.

**Established behavior:** selection depends on two entry checks, the presence and readiness of an associated object, two observations obtained from the input object, and an unsigned comparison involving a 3,000-unit adjustment. The function returns either 0 or 1.

**Inferred intent:** the observations and selected values may represent positions or times, and the unsigned comparison may detect a sufficiently old candidate. Their units and semantic meaning are not established. This contract therefore uses “observation,” “candidate,” and “selection” without assigning domain meaning.

## Interface

### Input and result

The function receives one pointer to a mutable object. The visible layout uses 32-bit words and 32-bit pointer representations.

The result is a 32-bit value:

- **1:** a selection callback and a notification callback have returned, followed by the exit operation.
- **0:** processing was rejected by an entry check, or the entered region completed without selecting a value.

These results describe control flow, not independently verified success of the invoked operations. Several dependency results are ignored.

There is no established null-input behavior. The input must support all memory accesses reached on the executed path. Invalid pointers, inaccessible fields, invalid dispatch tables, and nonreturning dependencies have no recovery behavior in the visible function.

## Behavior

### Entry checks

The function first calls **F-b7abcf60c990**, passing the address at input offset `0x060`.

- A zero result causes an immediate return of 0.
- A nonzero result permits the next check.

It then invokes **F-000000000001**, resolved through the input object’s dispatch table at slot offset `0x1A4`, with the input object as receiver.

- A nonzero result causes an immediate return of 0.
- A zero result permits entry into the processing region.

The second check is not called when the first check returns zero. Neither the entry nor exit operation is called on either early-return path.

These checks are not established as pure. Their writes and any changes they cause to later-observed state remain possible.

### Entering and inspecting the associated interface

After both checks pass, the function calls **F-000000000002** with the address at input offset `0xA4C`. Its result does not control subsequent processing.

Only after this call returns does the function read the associated-object pointer at offset `0x054`.

If that pointer is zero, the function calls **F-000000000003** with the same embedded-region address and returns 0.

For a nonzero pointer, it forms the associated-interface address by adding four bytes. It then invokes **F-000000000004**, using dispatch-table slot `0x138` of that interface.

If this callback returns zero, the function calls F-000000000003 and returns 0. Otherwise, processing continues.

The associated-interface address is retained for the remaining associated-interface calls. The function does not visibly reload the containing object’s pointer field to replace that address if an intervening dependency changes the field.

### Obtaining the selection inputs

For a ready associated interface, the function performs these calls in order:

1. **F-000000000005** on the input object, through slot `0x17C`, producing the first 32-bit observation.
2. **F-000000000006** on the associated interface, through slot `0x144`, passing the first observation and obtaining a 32-bit index-like value.
3. **F-000000000007** on the associated interface, through slot `0x13C`, passing that index-like value and obtaining the original candidate.
4. **F-000000000005** again on the input object, producing the second observation.

The two observation calls are distinct. The function does not assume equal results or reuse the first result for the comparison.

After the second observation returns, the function reads and retains the global 32-bit token. This read occurs before branch selection, including when neither successful path will be taken.

### Unsigned threshold selection

The first selection condition is:

**the original candidate plus 3,000, reduced modulo 2³², is strictly less than the second observation when both are compared as unsigned 32-bit values.**

Consequences:

- Equality does not satisfy the condition.
- The adjustment can wrap.
- A candidate whose signed interpretation is negative is not rejected.
- This is not a signed comparison and is not an unbounded-integer addition.

When the condition holds, the function:

1. Invokes **F-000000000008** on the input object, through slot `0x100`, passing the original candidate.
2. Performs the notification described below.
3. Calls F-000000000003 with the embedded-region address at `0xA4C`.
4. Returns 1.

The visible body does not directly write either selection-storage field on this path and does not call F-069a1d444a2d. Dependencies may nevertheless modify those fields or other state.

This path takes precedence over the index-like value’s zero/nonzero status. In particular, an index-like value of zero does not prevent success when the unsigned threshold condition holds.

### Predecessor selection

If the unsigned threshold condition is false, the function examines the index-like value.

A zero value results in an exit-operation call and return of 0. No selection or notification callback is made on this path.

For a nonzero value, the function:

1. Invokes F-000000000007 again, passing the index-like value minus one.
2. Invokes F-000000000008 on the input object, passing this second lookup result.
3. Writes that second lookup result to the 32-bit field at offset `0x998`.
4. Writes the original candidate to the 32-bit field at offset `0x994`.
5. Calls **F-069a1d444a2d**, passing the input object and the retained global token.
6. Performs the notification.
7. Calls F-000000000003 with the embedded-region address at `0xA4C`.
8. Returns 1.

The order of the two direct field writes is significant: offset `0x998` is written before offset `0x994`. Both writes occur after the selection callback returns and before F-069a1d444a2d is called.

The function does not visibly recompute the original candidate, first lookup result, second observation, or captured token after intervening callbacks.

### Notification

Both successful paths invoke **F-000000000009** through dispatch-table slot `0x14` of the embedded object at input offset `0x014`.

The notification receives:

- The embedded object’s address as receiver.
- The retained global 32-bit token.
- A literal zero argument.

The notification precedes the exit operation. Its return value does not determine the function’s result.

The predecessor-selection path passes the same retained token to F-069a1d444a2d and to the notification. The token is not visibly reread between those calls, even if a dependency changes the global storage.

## Side effects

### Directly established effects

The function’s explicit data writes are limited to the two 32-bit fields on the predecessor-selection path:

1. Offset `0x998`: predecessor-derived selection.
2. Offset `0x994`: original candidate.

All other visible effects occur through dependencies.

For every normal-return path that reaches F-000000000002, F-000000000003 is subsequently called once. On successful paths, selection, optional field writes and helper invocation, and notification occur before that exit call.

No exception handling, failure unwinding, or alternate exit mechanism is established. If a dependency does not return normally, the visible function does not establish that the exit operation will run.

### Ownership and state stability

The visible body does not directly allocate, free, retain, or release memory. This does **not** establish that its dependencies avoid those actions.

The paired operations may represent synchronization, but that interpretation is inferred rather than established. The contract does not promise locking, exclusion, recursion support, or lifetime protection.

Dependencies are not assumed to preserve:

- The input object’s dispatch table.
- The associated interface’s dispatch table.
- The associated-object pointer field.
- Either selection-storage field.
- The global token’s storage.
- The lifetime of any referenced object.

Dispatch-table accesses remain associated with their respective calls; there is no established invariant that a table observed for one call remains unchanged for later calls. Callers and dependency implementations must provide sufficient lifetime and memory validity for the actual execution.

## Acceptance examples

These are conditional static examples, not runtime results. They assume valid accessible objects, valid dispatch targets, and normally returning dependencies.

### First check rejects

- Result: 0.
- No later dependency is called.
- Neither direct selection-storage write occurs.

### Second check rejects

- Neither paired operation is called.
- The associated-object pointer is not read by the visible body.

### Missing or unready associated object

If both entry checks permit processing, but the associated-object pointer is zero:

- Entry operation, pointer read, and exit operation occur in that order.
- Result: 0.

If the pointer is nonzero but F-000000000004 returns zero:

- The associated readiness callback occurs between entry and exit.
- Neither observation callback is reached.
- Result: 0.

### Threshold path, including zero index

Suppose the original candidate is 1,000 and the second observation is 4,001.

The adjusted candidate is 4,000, so the strict unsigned comparison succeeds. The function selects 1,000, notifies, exits, and returns 1. This remains true if the index-like value is zero.

### Equality boundary

Suppose the original candidate is 1,000 and the second observation is 4,000.

The threshold condition is false because equality is insufficient.

- With index-like value zero: exit and return 0.
- With index-like value two: perform the additional lookup with argument one, select its result, write the two fields in the specified order, call F-069a1d444a2d, notify, exit, and return 1.

### Unsigned wraparound

Suppose the candidate’s unsigned value is 4,294,966,296 and the second observation is 2,001.

Adding 3,000 modulo 2³² produces 2,000. The threshold condition succeeds. The selected value remains the original candidate bit pattern, not the adjusted value.

### Captured-token stability

Suppose the token read after the second observation yields value T. A later selection callback or F-069a1d444a2d changes the global token storage to U.

The notification still receives T. On the predecessor path, F-069a1d444a2d also receives T.
