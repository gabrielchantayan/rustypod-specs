# F-bd0a5082b3f8

## Purpose

F-bd0a5082b3f8 dispatches descriptor-directed operations on a caller-supplied 32-bit value slot. Depending on the descriptor, it traverses subordinate records, invokes indirect handlers, processes collection elements, delegates a value operation, or clears the slot.

The established contract is dispatch and sequencing, not a universal destruction guarantee. Several paths call dependencies whose implementations are unavailable. Their names, argument shapes, and subsequent slot clearing do not establish that they release memory, preserve global state, or leave the slot unchanged.

## Interface

The function has four arguments and no explicit return value:

| Argument | Established representation and use |
|---|---|
| Value-slot address | Address of a writable 32-bit word. Some paths interpret its contents as an address or handle. |
| Descriptor address | Address of a byte-addressed descriptor. Its first byte selects the operation. |
| Third argument | A 32-bit value with no explicit use in the supplied body. |
| Fourth argument | A 32-bit value used to initialize temporary storage on one path and forwarded to one dependency on another. |

The visible representation uses 32-bit words, addresses, and indirect-call targets. The operation selector is one unsigned byte. Counts, indices, operation modes, and several dependency results are compared as signed 32-bit quantities.

### Preconditions and invalid inputs

The function reads the descriptor’s handler-table field **before checking whether the value-slot address is null**. A null slot therefore does not make an invalid descriptor safe.

For nonzero selectors, the function returns if the slot contains zero. Selector 0 is exempt and may continue with zero slot contents.

All addresses actually dereferenced, including handler tables, metadata, record tables, and values interpreted as pointers, must support the corresponding accesses. No bounds, alignment, address-validity, or arithmetic-overflow checks are visible. Fault handling is not defined by this body.

A descriptor-null branch exists inside the fallback block, but normal entry reads the descriptor first. It must not be advertised as supported null-descriptor entry behavior.

## Behavior

### Entry and repeated dispatch

An internal preservation state starts at zero.

At each dispatch iteration, the function:

1. Reads the 32-bit handler-table address at descriptor offset +16.
2. Returns if the slot address is null.
3. Reads the selector byte.
4. For any nonzero selector, reads the slot and returns if its contents are zero.
5. If the previously read handler-table address is nonzero, reads its target at offset +16. Otherwise, the phase handler is absent.
6. Dispatches on the selector.

Most paths return. Only a nonterminal selector-0 wrapper replaces the descriptor and repeats this sequence.

Selectors outside 0 through 5 return without an explicit slot write or dependency call, after the entry reads above.

### Selector 0: wrapper or collection processing

The function reads the metadata address from descriptor offset +8.

**Null metadata:** execution enters the fallback operation described below. The descriptor remains the current, nonnull descriptor.

**Metadata flags containing either bit in mask `0x00000006`:**

- The current slot contents are captured as the collection handle.
- A writable 32-bit temporary is initialized from the fourth argument.
- A signed element index starts at zero.
- Before each prospective iteration, F-10b760faca36 is called with the captured collection handle. Its result is compared with the current index.
- If the index is less than that result, F-6bbddce1b930 is called with the captured handle and index. Its result replaces the temporary.
- F-50507157c742 receives the temporary’s address, the current word at metadata offset +16, and zero.
- Iteration continues with the next index.
- After termination, F-9aef742d6dcd is called with the captured handle.
- The caller’s slot is set to zero, and the function returns.

The count is queried repeatedly, including the terminating check; it is not captured once. The collection handle is captured once and is not refreshed if dependencies change the slot. The metadata word at +16 is read separately for each element-processing call.

F-50507157c742 receives writable temporary storage, not the caller’s slot. Changes it makes to that temporary are not copied into the slot.

**Neither flag bit set:**

- The flags word is read again.
- The preservation state is replaced by the flags masked with `0x00000400`.
- The descriptor address is replaced by the metadata word at +16.
- Dispatch repeats.

Nested wrappers replace the preservation state rather than accumulate it. Thus the last traversed nonterminal wrapper determines this state. There is no visible cycle detection or traversal limit.

### Selector 1: reverse record traversal

F-fa1cf018d20d receives the slot address, the 32-bit all-ones value, and the descriptor address. If its signed result is positive, the function returns immediately.

Otherwise:

1. If a phase handler was captured, it is called with phase value 2, the slot address, and the descriptor address. A result equal to 2 causes immediate return.
2. F-4da75e9c77cb receives the slot and descriptor addresses.
3. The record-table base and signed count are read. An initial record position is calculated as base plus count multiplied by 20.
4. Before every loop-condition check, that position is decreased by 20.
5. Starting with iteration index zero, the loop continues while the index is less than the descriptor’s currently read signed count.
6. F-23eebec8340f receives the slot address, current record address, and zero.
7. If its result is nonzero, F-50a87c4da87c receives the slot address and that result. F-a8ecb9fc98cf then receives the returned value and the same nonzero result.
8. After traversal, the shared completion sequence runs.

For a stable positive count, records are visited from the last entry to the first. The loop bound is reread after dependency calls; the initial position is not recomputed when the count changes. The position is also decremented before the final failed loop check.

### Selector 2: selected-record processing

If a phase handler exists, it first receives phase value 2, the slot address, and the descriptor address. A result equal to 2 causes immediate return.

F-7eb30049adbd then receives the slot and descriptor addresses. Its signed result is the candidate record index.

If a phase handler exists, it is called a second time with phase value 2 and the slot address, without an explicit descriptor argument. This second call occurs even for a negative candidate index. Its result does not change the visible record-selection outcome.

For a nonnegative candidate, the function subsequently reads the signed count at descriptor offset +12. A record is processed exactly when:

- the candidate is nonnegative; and
- the candidate is strictly less than that count.

The record address is calculated from the descriptor’s then-current base at +8 plus candidate multiplied by 20. F-50a87c4da87c receives the slot address and record address. F-a8ecb9fc98cf receives its result and that record address.

Negative indices, an index equal to the count, and indices greater than the count skip record processing. They still proceed to shared completion.

### Shared completion for selectors 1 and 2

If a phase handler was captured, it receives phase value 3 and the slot address. Its return value is ignored.

If the preservation state is zero:

1. The slot’s current contents are read and passed to F-5990a26eaaa3.
2. The slot is explicitly set to zero.

If the preservation state is nonzero, neither action occurs.

The slot is reread after preceding dependency calls. There is no zero-value check immediately before F-5990a26eaaa3. A dependency or phase handler can therefore change which value is passed.

Preservation suppresses these two explicit completion actions only. It does not establish that the slot or its referent remains unchanged by other calls.

### Selectors 3 and 4: direct indirect-handler dispatch

Selector 3 reads handler-table offset +4, if a table is present. If the target is nonzero, it receives the slot’s current contents. The function then returns.

Selector 4 similarly uses handler-table offset +8. Its target receives the slot and descriptor addresses.

Missing tables or zero targets cause return. Neither selector performs an explicit slot write or runs shared completion.

### Selector 5 and selector-0 null-metadata fallback

For a nonnull descriptor, the fallback block rereads descriptor offset +16. If that table has a nonzero target at +12, the target receives the slot address and the function returns immediately.

Without that override:

- Selector 5 chooses mode −1 regardless of descriptor offset +4.
- Selector 0 with null metadata reads its signed mode from descriptor offset +4.
- Mode 1 bypasses the fallback’s additional zero-slot check.
- Other modes read the slot and return if it is zero.

## Side effects

Explicit writes are limited to:

- assigning zero to the caller’s slot on the paths identified above;
- assigning the descriptor’s replacement word in fallback mode 1;
- initializing and updating a temporary word used during collection processing.

Dependencies and indirect handlers may have additional effects. They receive writable addresses on several paths. Their effects on slot contents, descriptors, record tables, collections, global state, and memory ownership are unknown.

The phase target is captured before dispatch and reused during that operation. Mutating the table later does not visibly cause it to be refreshed. In contrast, the fallback override table is reread when entering that block.

No rollback, error object, status return, or exception recovery is visible. Early-return signals are specific control results: a positive F-fa1cf018d20d result or exactly 2 from the first phase-2 invocation. They are not established as errors.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Null slot with readable descriptor.** Given a readable descriptor and a null slot address, the handler-table field is read, then the function returns. There is no selector read or dependency call.

2. **Zero slot and selector 1.** Given a nonnull slot containing zero and selector 1, dispatch returns before the selector-1 gate or any phase call.

3. **Wrapper preservation.** Given a nonterminal selector-0 wrapper with bit `0x400` set, leading directly to selector 1, ordinary completion invokes phase 3 if available but omits F-5990a26eaaa3 and the explicit final zero assignment. This does not constrain mutations by dependencies.

4. **Nested wrapper replacement.** If that wrapper leads through another nonterminal wrapper whose `0x400` bit is clear, ordinary selector-1 or selector-2 completion performs the value call and final clear.

5. **Stable reverse traversal.** With selector 1, a stable count of three, and no early exit, F-23eebec8340f receives record addresses at base +40, base +20, and base, in that order.

6. **Selector-2 boundaries.** With a stable count of three, candidates 0 and 2 process the corresponding records. Candidates −1, 3, and 4 do not. All proceed to shared completion unless the initial phase handler already returned 2.

7. **Phase-call distinction.** For selector 2 with a phase handler and no initial veto, the visible sequence includes phase 2 with slot and descriptor, the candidate-index dependency, phase 2 with slot only, optional record processing, then phase 3 with slot only.

8. **Empty collection.** If the first collection-bound query returns zero, no element callback occurs. The collection-finalization dependency still runs, and the slot is cleared.

9. **Replacement of zero.** Selector 0 with null metadata, no fallback override, mode 1, and a zero slot assigns the descriptor’s replacement word. Its zero input does not prevent assignment.

10. **Fallback override.** A nonzero fallback target at handler-table offset +12 receives the slot address and ends local processing. No local mode-based clear follows.
