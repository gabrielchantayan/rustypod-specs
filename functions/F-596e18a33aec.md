## Behavior

### Initial routing

The function first tests whether every set bit in the classification mask is also set in A-high shifted right by four. Only if that test fails does it perform the corresponding test for B-high.

If either test succeeds, execution enters the **special-classification route**. If neither succeeds, execution enters the **arithmetic-or-other-exception route**.

These are exact mask tests. They must not be replaced with conventional floating-point classification without separately establishing the mask’s value.

### Special-classification route: continuation decision

For a stable classification-mask value, define a 32-bit threshold as that mask multiplied by `0x20`, with wraparound. Each high word is separately doubled with wraparound.

An operand exceeds this threshold when:

- Its doubled high word is greater than the threshold; or
- Its doubled high word equals the threshold and its low word is nonzero.

If either operand exceeds the threshold, the function selects a control-dependent continuation transfer.

The visible comparison sequence considers A first. The B threshold comparison is needed only when A does not exceed the threshold. Multiplication and comparison are word operations: this is not an unbounded comparison of the original 64-bit pairs.

### Control-dependent continuation transfers

The mode is the control word’s low nibble. Every transfer target is obtained by clearing the low two bits of the incoming link-like value.

The visible return from each transfer is forwarded as this function’s result. No post-transfer adjustment is shown.

| Mode 9, that bit set, and all bits in `0x00070000` clear | `0x30000000`, primary payload, and `0x30000000` with incoming status bit 0 placed at bit 27 |

### Special-classification route: direct results

If no continuation transfer is selected, the function first compares A-high, with its sign bit cleared, against `0x7FF00000`.

If unequal:

1. A-high is adjusted by setting bit `0x00080000` when A-low is nonzero or any of A-high’s lowest 12 bits is set.
2. The prospective result high word starts as B-high’s sign bit alone.
3. That sign bit is conditionally toggled using the adjusted A-high.
4. The result low word is zero.

The sign-toggle rule uses a signed-subtraction-overflow condition, not a plain unsigned comparison. For a tested word \(x\), define:

- \(N(x)\): whether \(x\) XOR `0x80000000` is negative as a signed 32-bit value.
- \(V(x)\): whether signed 32-bit subtraction of `0x00100000` from \(x\) overflows.

One toggle occurs when \(N(x)=V(x)\). A separate toggle occurs when \(x\) equals `0x80000000`. Both conditions are evaluated, so two toggles cancel.

If the first masked comparison equals `0x7FF00000`, the function instead makes the same masked comparison for B-high.

If B’s comparison is unequal:

- B-high has bit `0x00080000` set when B-low is nonzero or any of B-high’s lowest 12 bits is set.
- The same two-toggle rule, using adjusted B-high, is applied to A-high’s sign bit.
- A-low is returned unchanged.
- The result high word is A-high with only those possible sign toggles.

The adjusted B-high is used for the sign decision; it is not returned.

If both masked high-word comparisons equal `0x7FF00000`, execution reaches the common fallback.

### Arithmetic-or-other-exception route

This route first intersects the classification mask with B-high shifted right by four.

The delegated arithmetic path is selected only when:

- That intersection is nonzero; and
- A-high intersects the classification mask shifted left by four.

Otherwise, the function considers two direct exceptional-result paths, in A-first order.

#### Delegated arithmetic and result construction

The function prepares three explicit 32-bit arguments for F-333a3bc98e99:

1. A-low shifted left 11.
2. A-high shifted left 11, combined with A-low shifted right 21 and bit `0x80000000`.
3. B-low shifted left 11.

The function also computes a B-derived word from B-high shifted left 11 combined with B-low shifted right 21. This word participates in later arithmetic. The evidence does not establish it as an additional argument to the dependency.

Before the call, a signed exponent-like word is formed by taking the classification-mask intersection with A-high shifted right four, combining it with the sign difference between A-high and B-high, and subtracting the corresponding B intersection. A second word adds `0x03FC0000`.

Let the dependency’s 64-bit result be \(R\). The provisional result has:

- Low word: bits 11–42 of \(R\).
- High word before sign combination: bits 43–63 of \(R\), plus an exponent-like contribution multiplied by `0x00100000`, with word wraparound.
- A sign contribution equal to the exponent-like word multiplied by `0x80000000`, modulo \(2^{32}\), XORed into that high word.

The exponent-like contribution combines the previously prepared B-derived word with the signed right shift by 16 of the word containing the `0x03FC0000` bias.

Rounding is controlled by bit 10 of \(R\):

- If bit 10 is clear, no rounding adjustment occurs.
- If bit 10 is set, the provisional low word is incremented.
- If bits 0–9 are all zero, the incremented low word is additionally forced even by clearing bit 0.
- A carry is added to the provisional high word only if the original provisional low word was `0xFFFFFFFF`.

This is consistent with a ties-to-even step over the discarded 11 bits, but that observation alone does not establish the dependency’s numerical meaning.

The rounded pair is returned only if all three conditions hold:

1. Removing the calculated sign contribution from the final high word leaves a nonnegative signed word.
2. The pre-rounding, pre-sign high word intersects the result mask.
3. At least one result-mask bit is absent from the final high word.

The result mask is consulted after F-333a3bc98e99 returns. Its value must not be assumed to equal its pre-call value.

If the pair is rejected:

- A signed biased word below `0x04000001` produces an all-zero 64-bit result.
- Otherwise, `0xA0000000` is added to the provisional high-word address-like value using the visible word-address interpretation. The returned low word is zero, and the returned high word is formed by ORing the adjusted word with `0x7FFFFFFF`, then XORing with `0x000FFFFF`.

Thus the latter result high word is either `0x7FF00000` or `0xFFF00000`, depending on the adjusted sign bit.

The address-like representation is used for arithmetic and conversion, not for an explicit memory load or store. Its exact machine interpretation remains subject to the uncertainty below.

#### Direct exceptional-result paths

If delegated arithmetic is not selected, the function tests the A intersection with the shifted classification mask first.

If it is nonzero, both operands undergo this preparation:

- Set high-word bit `0x00080000` if the operand’s low word is nonzero or any of its high word’s lowest 20 bits is set.
- Compare the resulting high word shifted right 19 with the sign-comparison word.
- Toggle its sign bit if equal.

The result low word is zero. The result high word is the XOR of the prepared high words, ORed with `0x7FFFFFFF`, then XORed with `0x000FFFFF`. This produces `0x7FF00000` or `0xFFF00000`.

If the A test fails but the corresponding B intersection is nonzero, the same preparation is performed. The result low word is zero, and the result high word contains only the XOR of the prepared sign bits: `0x00000000` or `0x80000000`.

The 20-bit preparation masks here differ deliberately from the 12-bit masks in the earlier special-classification route.
