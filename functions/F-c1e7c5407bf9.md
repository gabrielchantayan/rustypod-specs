# F-c1e7c5407bf9

## Purpose

F-c1e7c5407bf9 has no explicit parameters and returns no value. It reads three shared scalar cells and either returns normally or continues evaluating a loop. The supplied representation contains no calls and no explicit writes to shared storage.

The routine retains a working value between condition evaluations. Each evaluation combines that value with two occurrences of a control-cell read. A zero result ends execution. A nonzero result causes a first-candidate read; unless the result is exactly one, a second-candidate read follows and supersedes the first candidate as the retained value.

A polling or synchronization purpose is **inferred intent**, not established behavior. Repeated references to shared storage do not establish atomicity, visibility of concurrent updates, or a valid synchronization protocol.

## Behavior

### Acquisition and condition evaluation

Before evaluating the loop condition, the routine acquires the control-cell value into its retained signed local value. Neither candidate is acquired before the first condition evaluation.

Each condition evaluation then uses the retained value and two control-cell read occurrences. One control operand is negated. The other is shifted right by 31 positions. An adjustment is formed by subtracting the shifted operand from the negated operand; that adjustment is then added to the retained value. The result is assigned to the condition-result local before the exit and selection decisions use it.

This grouping matters. A final mathematical result that fits in the local type does not make an overflowing negation or intermediate subtraction valid.

The two control references within one evaluation are not sequenced relative to each other by the supplied expression. The contract therefore does not promise:

- Which of those control reads occurs first.
- That they observe the same value.
- That either observes the initial control value.
- That the arithmetic can be reduced using one common control value when observations differ.

The stored condition result is distinct from the retained working value. Computing a condition does not replace the retained value with that result.

### Exit and candidate selection

The condition result determines the following access behavior:

| Stored condition result | Candidate acquisitions | Retained value afterward | Outcome |
|---|---|---|---|
| Zero | None | Unchanged | Return normally. |
| Exactly one | First candidate only | First candidate’s assigned value | Evaluate another condition. |
| Any other nonzero value | First candidate, then second candidate | Second candidate’s assigned value | Evaluate another condition. |

The first-candidate acquisition is present on every entered body path. On the two-candidate path, its assigned value is subsequently superseded, but the supplied representation still contains that first acquisition before the second.

Candidate selection uses the condition result already computed. It does not acquire the control cell again to decide whether the second candidate is needed.

A candidate value does not itself trigger an immediate return. It becomes the retained value for the next condition evaluation, which includes further control references and arithmetic.

### Consequences for fixed control values

Under the conditional 32-bit model:

- A fixed nonnegative control value produces a zero first condition result. The routine returns without acquiring a candidate.
- A fixed negative control value produces a first condition result of one, provided all intermediates are representable. The first body therefore acquires only the first candidate.

For a fixed, arithmetically valid negative control value, subsequent behavior depends on the retained value:

| Retained value relative to control | Condition result | Consequence |
|---|---:|---|
| One less than control | Zero | Return without candidate acquisition. |
| Equal to control | One | Acquire only the first candidate. |
| Any other value | Neither zero nor one | Acquire first candidate, then second candidate. |

These reductions permit termination after candidate acquisition, repeated first-only selection, repeated two-candidate selection, or alternation between the two selection paths. They do not apply when the two control operands differ or when the assumed integer model does not hold.
