# F-00c4b3d6190c

## Purpose

F-00c4b3d6190c replaces a byte-sized field in a caller-supplied object, conditionally invokes one of two change handlers, invokes a final dependency, and returns whether a separate byte-sized gate was zero when inspected.

The change classification uses the entire 32-bit requested value, although the stored field receives only its low eight bits. Consequently, the handler selection is not necessarily a classification of the change visible in the stored byte.

The returned Boolean reports the sampled gate condition. It does not report whether the field changed, whether a handler ran, or whether a dependency succeeded.

These are established properties of the supplied static representation. Describing the field as a set of flags and the gate as a suppression mechanism is inferred intent, not an independently established semantic role.

- **Requested value:** an unsigned 32-bit value. All 32 bits participate in change classification; only bits 0–7 are written to the object’s replacement field.

On normal return, the function produces a Boolean:

- **True:** the gate byte was zero at its single visible sampling point.
- **False:** the gate byte was nonzero at that sampling point.

The physical return-register representation of this Boolean is not established by the supplied material.

## Behavior

### Entry and field replacement

The first observable operation established by the supplied representation is a call to F-b7cd573c0b4c with no explicit arguments.

Only after that call returns does F-00c4b3d6190c read the previous byte at offset `0x2F1`. Therefore, the previous value used for classification is the value present after the entry dependency, not necessarily the value that existed when F-00c4b3d6190c was invoked.

Next, the function writes the low eight bits of the requested value to offset `0x2F1`. The previous value is retained for subsequent classification. The field is written even if:

- Its low-byte value is unchanged.
- The gate will suppress handler invocation.
- The requested value contains nonzero bits above bit 7.

There is no visible conditional avoidance of this write.

### Gate sampling

After the replacement-field write, the function reads the byte at offset `0x2BC` and records whether it equals zero.

A nonzero gate prevents both change handlers from being called by this function. It does not prevent the preceding replacement-field write or the later final dependency call.

A zero gate permits change classification. The recorded zero/nonzero result also determines the Boolean returned on normal completion.

The gate is not visibly reread. Later dependency activity may change it without changing the already recorded return value.

### Change classification

For classification, the previous byte is treated as an unsigned value and zero-extended to 32 bits. Thus, its possible values are 0 through 255, with all upper 24 bits clear.

An **addition condition** exists when the requested 32-bit value contains at least one set bit that was clear in this zero-extended previous value.

A **removal condition** exists when the previous value contains at least one set bit that is clear in the requested 32-bit value.

When the sampled gate is zero:

1. If the addition condition exists, the function selects the addition handler.
2. Otherwise, if the removal condition exists, it selects the removal handler.
3. Otherwise, it calls neither change handler.

Addition takes precedence over removal. If one invocation both introduces and removes bits, only the addition handler is called.

The full-width comparison has an important consequence: any requested value with a nonzero bit in positions 8–31 satisfies the addition condition. The previous byte cannot contain any of those bits. This remains true even when the low byte written to the object is unchanged or has only lost bits.

The only zero-gate case with neither handler selected is a requested 32-bit value exactly equal to the zero-extended previous byte.

### Addition-handler path

On the addition-handler path, F-3878194a6aa9 is called with:

1. The object address.
2. The four-byte value read from offset `0x2CC`.
3. The four-byte value read from offset `0x2DC`.

These auxiliary reads belong to this selected path; they are not visibly required when the gate is nonzero, when only removal is detected, or when no change is detected.

Both auxiliary values are obtained before the handler call. The supplied representation does not establish which auxiliary field is read first.

The replacement-field write precedes these reads and the handler call. The handler therefore runs after the requested low byte has been installed, subject to any intervening external mutation.

### Removal-handler path

If the addition condition is absent and the removal condition exists, F-f798119e6339 is called with the object address.

The two auxiliary fields are not visibly read on this path.

### Finalization and return

After the gate-controlled section, F-d49b39475920 is called with the object address. This happens on every path that reaches this point normally, including paths with a nonzero gate and paths without any detected change.

The function then returns the previously recorded gate comparison.

No dependency return value is visibly inspected or used to determine that Boolean. If a dependency does not return normally, the supplied representation establishes neither a subsequent final call nor a Boolean result.
