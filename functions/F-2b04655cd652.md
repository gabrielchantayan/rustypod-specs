# F-2b04655cd652

## Purpose

F-2b04655cd652 conditionally passes a trailing byte range to a transfer dependency after validating a length, a numeric pointer token, a leading marker, a bounded zero-terminated region, a trailing-byte condition, and a destination-capacity limit.

On a successful path, it invokes the transfer dependency and returns the calculated trailing-range length. On a rejected path, it invokes diagnostic dependency F-4fc89ec41a6d and returns −1 if that dependency returns normally.

The established behavior does **not** support interpreting the trailing-byte condition as “require eight bytes of value 3.” Under stable-memory assumptions, the function instead rejects a scanned region whose final **seven** nonzero bytes all equal 3. Other sufficiently long scanned regions can pass this condition.

These are static behavioral findings. No runtime tests have been performed.

## Interface

The function has five positional inputs and an integer result.

| Position | Contract role | Representation and use |
|---|---|---|
| 1 | Destination or context word | A 32-bit opaque value. Forwarded unchanged as the transfer dependency’s first argument. This function does not directly dereference it. |
| 2 | Capacity limit | A signed 32-bit integer compared against the calculated trailing-range length. |
| 3 | Input base | A byte pointer. Conditionally used to read the leading marker, scan a byte region, inspect trailing bytes, and derive the transfer source. |
| 4 | Declared length, denoted \(L\) | A signed 32-bit integer. Controls validation, scan bounds, trailing-range length, and one forwarded argument. |
| 5 | Numeric pointer token | A pointer-valued input compared against the pointer representation of \(L+1\). Its incoming pointee is never read by this function. |

The result is represented as a signed 32-bit integer:

- **−1:** local validation rejected the request, provided the diagnostic dependency returns normally.
- **A nonnegative byte count:** local validation accepted the request and the transfer dependency returned normally.

The transfer dependency’s return value is not examined. Consequently, the nonnegative result establishes that the call returned, not that an unknown downstream operation succeeded.

### Input layout on the accepted path

Relative to the input base, the relevant layout is:

| Byte offset | Meaning |
|---|---|
| 0 | Leading marker, required to equal 2 |
| 1 through \(n\) | \(n\) consecutive nonzero bytes |
| \(n+1\) | First zero byte encountered by the bounded scan |
| \(n+2\) onward | Trailing range passed to the transfer dependency |

Here, \(n\) is the count of nonzero bytes before the terminating zero. An accepted request requires:

\[
8 \le n \le L-2
\]

The trailing-range length is:

\[
m=L-n-2
\]

Its starting address is the input base plus \(n+2\). The terminating zero is excluded from that range.

For a defined, returning execution:

- The integer operations must be representable, particularly \(L+1\).
- Dependencies must satisfy any additional, presently unknown requirements for their arguments.

## Behavior

### 1. Reject a short declared length

If \(L<10\), the function selects diagnostic reason **0x6F**.

This includes all negative lengths. The function performs no input-byte reads and does not inspect the capacity limit or compare the numeric pointer token on this path.

It then invokes F-4fc89ec41a6d as described under Dependencies and returns −1 if that call returns normally.

### 2. Validate the numeric pointer token and leading marker

For \(L\ge10\), the function computes the numeric value \(L+1\), converts that value to a pointer representation, and compares it for equality with the fifth input.

This is a numeric-token check, not a check against the end address of the input buffer. The input base does not participate in the calculation.

If the token does not match:

- Diagnostic reason **0x6B** is selected.
- No input byte is read.
- The incoming fifth input is not dereferenced.

If the token matches:

- The function reads the byte at input offset 0.
- It derives the scan starting address at input offset 1.
- The marker must equal **2**.

A marker other than 2 also selects diagnostic reason **0x6B**. No scan bytes are read after a marker rejection.

Thus, the token and marker failures share a diagnostic reason but have different memory-read behavior.

### 3. Scan for a bounded terminating zero

After a matching token and marker, the function scans bytes beginning at input offset 1. It counts nonzero bytes and stops at either:

- The first zero byte; or
- A count of \(L-1\) nonzero bytes.

The function reads scan bytes in increasing address order. It does not perform a scan read once the count has reached \(L-1\).

When a zero byte is found, the maintained scan address is advanced past that zero. This detail determines both the later trailing-byte inspection and the transfer source.

The scan is rejected with diagnostic reason **0x71** if either:

- No zero was found within the \(L-1\) permitted scan bytes; or
- Fewer than eight nonzero bytes preceded the zero.

A zero at offset \(L-1\) is permitted. In that case, \(n=L-2\), and the prospective trailing range has length zero.

The scan does not read trailing-range bytes after the first zero.

### 4. Inspect bytes immediately preceding the post-zero address

For a scan that found a zero after at least eight nonzero bytes, let \(P\) be the address immediately after that zero.

The function begins inspecting at \(P-8\), advancing toward \(P-1\) while inspected bytes equal 3. It stops at the first byte not equal to 3, or after the final inspection position.

The zero found by the scan is at \(P-1\). Under stable-memory assumptions, that byte cannot equal 3. Consequently:

- \(P-8\) through \(P-2\) are the final seven nonzero bytes of the scanned region.
- If all seven equal 3, the inspection reaches the terminating zero at \(P-1\).
- Reaching that position selects diagnostic reason **0x73**.
- If any of those seven bytes differs from 3, the function proceeds.

Equivalently, for stable input, the trailing-byte check rejects precisely when the final seven scanned nonzero bytes are all 3.

On a passing path, the signed inspection offset forwarded to the transfer dependency is one of:

\[
-8,-7,-6,-5,-4,-3,-2
\]

It identifies the first position in that ordered inspection whose byte differs from 3. The byte at \(P-9\) is not part of this inspection.

No interpretation such as padding validity, cryptographic correctness, or format compliance is established by the supplied evidence.

### 5. Calculate and check the trailing-range length

After the trailing-byte check passes, the function calculates:

\[
m=(L-1)-(n+1)=L-n-2
\]

The established scan constraints make \(m\) nonnegative. Its possible range is:

\[
0 \le m \le L-10
\]

The function compares \(m\) with the capacity limit using a signed comparison.

- If \(m\) exceeds capacity, it selects diagnostic reason **0x6D**.
- Otherwise, it invokes the transfer dependency.

A negative capacity rejects every otherwise acceptable request, including one with \(m=0\). Capacity equal to \(m\) is accepted.

The function does not perform additional checks on the destination/context word, alignment, overlap, trailing-range contents, or zero-length transfer handling.

### 6. Invoke the transfer dependency and return

On the accepted path, the transfer dependency receives five arguments in this order:

1. The original 32-bit destination/context word.
2. The address \(P\), immediately after the scanned zero.
3. The calculated trailing-range length \(m\).
4. The signed inspection offset described above.
5. The original declared length \(L\).

If the dependency returns normally, F-2b04655cd652 returns \(m\).

The function invokes the dependency even when \(m=0\). In that case, \(P\) is the address immediately after the declared input region. Whether the dependency accepts such an address with a zero count is not established.

## Side effects

### Direct memory behavior

The function directly reads input memory but performs no explicit writes through either supplied pointer.

For accepted or late-rejected requests, its own read order is:

1. Leading marker at offset 0.
2. Scan bytes in ascending order, through the first zero or scan limit.
3. Trailing-check bytes in ascending order starting eight bytes before the post-zero address.

The trailing check rereads bytes already encountered by the scan. It also rereads the terminating zero if all seven preceding inspection bytes equal 3.

There is no explicit allocation, release, ownership transfer, or persistent-state update in the visible body.

### Dependency effects

A locally rejected request invokes only the diagnostic dependency. A locally accepted request invokes only the transfer dependency.

Either dependency may have effects not visible here. This contract does not assume that either dependency:

- Preserves globals;
- Preserves input or destination memory;
- Allocates or releases memory;
- Merely logs or merely copies;
- Returns normally.

The function contains no visible recovery path for a fault during a read, a dependency exception, or a nonreturning dependency. The −1 result is specifically the local validation-failure result after a returning diagnostic call, not a universal error guarantee.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, assume valid readable memory, stable input, representable arithmetic, a matching numeric pointer token, marker 2, and dependencies that return normally.

1. **Short length takes precedence over all input contents.**  
   With \(L=9\), expect diagnostic reason 0x6F and result −1. No input memory is read, regardless of the token, capacity, or input-base value.

2. **A mismatched token prevents the marker read.**  
   With \(L=12\), the required token is the pointer representation of numeric value 13. A different token selects reason 0x6B without reading the input.

3. **A matching token does not validate the marker.**  
   With \(L=12\), a matching token, and marker 1, expect reason 0x6B after the marker read. No scan occurs.

4. **Eight nonzero bytes permit a zero-length transfer.**  
   With \(L=10\), place eight nonzero bytes at offsets 1–8 and zero at offset 9. Let the byte at offset 2 differ from 3. With capacity 0, expect a transfer call with source at offset 10, length 0, inspection offset −8, and original length 10. The function then returns 0.

5. **Seven nonzero bytes are insufficient.**  
   If the first zero follows only seven nonzero scan bytes, expect reason 0x71. The trailing inspection and transfer call do not occur.

6. **Missing zero exhausts the scan.**  
   With \(L=12\) and all bytes at offsets 1–11 nonzero, expect exactly those eleven scan positions to be read, then reason 0x71. Offset 12 is not read by the scan.

7. **Seven trailing bytes of value 3 cause rejection.**  
   With \(L=12\), \(n=8\), and zero at offset 9, set offsets 2–8 to 3. The trailing inspection reaches the zero at offset 9, selects reason 0x73, and does not invoke the transfer dependency. Offset 1 can be any nonzero value.

8. **A differing byte permits further validation.**  
   Under the preceding layout, change offset 5 to 4 while offsets 2–4 remain 3. The inspection stops at offset 5, producing inspection offset −5. The calculated trailing length is 2.

9. **Capacity equality is accepted.**  
   For the preceding passing layout, capacity 2 permits a transfer from offset 10 with length 2, followed by result 2.

10. **Insufficient or negative capacity rejects after inspection.**  
    For that same length-2 range, capacity 1 selects reason 0x6D. Capacity −1 also rejects an otherwise acceptable zero-length range.
