# F-328d7ef52173

## Purpose

F-328d7ef52173 decrements a 16-bit field and performs an in-place transformation of a descending sequence of 16-bit values. The transformation uses the difference between two values captured before the decrement.

The number of transformed values is determined by 16-bit modular arithmetic. It is not checked against an allocation size or constrained to a nonnegative mathematical count. In particular, decrementing an initially zero field can produce a large operation rather than an empty one.

**Established static behavior:** address calculation, two value captures, a field decrement, and a descending read/write sequence.

**Inferred intent:** the operation resembles removal or adjustment of an entry in a compact table of offsets. The supplied material does not establish that interpretation, and it is not part of the required contract.

## Interface

The function has three inputs and no explicit return value:

| Input | Interpretation used by this contract |
|---|---|
| **Descriptor address** | Address from which an unsigned 16-bit displacement is read at byte offset 28. |
| **Region address** | Address of a mutable region. An unsigned 16-bit field is read and replaced at byte offset 10. The same address is the base for locating the transformed sequence. |
| **Adjustment** | An apparently signed 32-bit integer used both in address calculation and in determining the iteration count. |

The supplied representation uses 32-bit integer-like inputs for both addresses and the adjustment. It does not provide a separately verified calling convention, pointer model, or platform ABI.

The relevant layout is:

| Location | Width | Use |
|---|---:|---|
| Descriptor address + 28 | 16 bits | Unsigned displacement, read once. |
| Region address + 10 | 16 bits | Unsigned field, read once and overwritten with its decrement modulo 65,536. |
| Computed sequence locations | 16 bits each | Two initial signed value reads, followed by signed reads and truncated writes. |

Define:

- **R**: the unsigned displacement read from the descriptor, in the range 0 through 65,535.
- **N**: the adjustment.
- **B**: the region address.
- **E**: the computed reference address, mathematically \(B + R - 2N\).
- **P**: the signed 16-bit value initially read at \(E-4\).
- **Q**: the signed 16-bit value initially read at \(E-2\).
- **C**: the unsigned 16-bit field initially read at \(B+10\).
- **K**: the least nonnegative residue of \(C-1-N\) modulo 65,536.

These definitions describe the access pattern without asserting that every possible input produces valid addresses. Valid storage, alignment, and address-arithmetic requirements are caller preconditions.

### Storage and ownership preconditions

For a successful complete operation:

- The descriptor field must be readable.

- Both initial sequence locations must be readable, including when **K** is zero.
- Every sequence source location must be readable.
- Every sequence destination location must be writable.
- Addresses must satisfy the execution environment’s alignment and memory-access requirements.

No non-aliasing requirement is enforced by the function. Aliasing can change results and must be accounted for by the caller.

## Behavior

### Initial observations

The function first reads the unsigned 16-bit displacement at descriptor offset 28 and uses it with the region address and adjustment to locate **E**.

It then captures, in order:

1. **P**, the signed 16-bit value at \(E-4\).
2. **Q**, the signed 16-bit value at \(E-2\).

Both captures precede the read and write of the region field. Subsequent writes do not refresh either captured value.

The signed difference used throughout the transformation is:

\[
D=P-Q
\]

Because both captured values are signed 16-bit values, **D** ranges from −65,535 through 65,535. This subtraction fits within a signed 32-bit integer.

### Field update

After capturing both values, the function reads **C** from region offset 10 as an unsigned 16-bit value.

It computes \(C-1\) in a wider integer and writes its low 16 bits back to the same location. Consequently:

- An initial field of 1 becomes 0.
- An initial field of 0 becomes 65,535.
- Every other initial value decreases by one.

The wider decremented value is in the range −1 through 65,534. The iteration count is derived from that value and **N**; it is not obtained by rereading the stored field.

This write happens even when no sequence transformation follows.

### Iteration count

The exact number of completed iterations, assuming all accesses succeed, is:

\[
K=(C-1-N)\bmod 65{,}536
\]

where the result is selected from 0 through 65,535.

This is a low-16-bit countdown, not a signed “while positive” condition. Negative mathematical results do not suppress processing.

Examples of the count rule include:

- \(C=3,\ N=2\): **K** is 0.
- \(C=0,\ N=0\): **K** is 65,535.
- \(C=3,\ N=-1\): **K** is 3.

The source representation uses an unsigned intermediate and masks the countdown to 16 bits at each condition check. Thus its low 16 bits govern termination even when the initial subtraction wraps in a 32-bit unsigned representation.

### Sequence transformation

For each iteration numbered \(j\), starting at 1 and ending at **K**:

- The source is the 16-bit value at \(E-4-2j\).
- The destination is the 16-bit location at \(E-2-2j\).
- The source is read before that iteration’s destination is written.
- The destination receives the low 16 bits of the signed source value minus **D**.

Equivalently, the stored bit pattern is the source bit pattern minus **P** plus **Q**, reduced modulo 65,536.

The first iteration reads at \(E-6\) and writes at \(E-4\). Each subsequent iteration moves both locations two bytes toward lower addresses.

For **K** greater than zero, the complete sequence footprint is:

| Access | Locations, in traversal order |
|---|---|
| Sequence sources | \(E-6,\ E-8,\ \ldots,\ E-4-2K\) |
| Sequence destinations | \(E-4,\ E-6,\ \ldots,\ E-2-2K\) |

The two initially captured locations are additional reads. Their reads occur even if **K** is zero.

### Integer values and truncation

A signed 16-bit source value ranges from −32,768 through 32,767. Subtracting **D** gives a mathematical result between −98,303 and 98,302, which fits within signed 32-bit arithmetic.

A result need not fit in signed 16 bits. The represented operation stores a 16-bit result; this contract describes that result by its low 16 bits. For example, a mathematical result of 32,768 is stored as the bit pattern `0x8000`, conventionally interpreted as −32,768 on a two’s-complement target.

The supplied material does not establish portable source-language semantics for every out-of-range signed narrowing conversion. The low-bit description is the intended target-level interpretation of the displayed 16-bit store, subject to the evidence limits below.

### Overlap and captured state

Adjacent iterations intentionally operate on overlapping source and destination ranges: one iteration writes an address read by the preceding iteration. Because traversal proceeds toward lower addresses, those ordinary sequence writes do not replace a later iteration’s source.

That property does not establish general alias safety:

- The field update at \(B+10\) occurs before all iterative source reads. If a source overlaps that field, the source read observes the updated bytes, absent other interference.
- If the field overlaps either captured location, **P** and **Q** still reflect the values read before the field update.
- An iterative destination may overlap the region field and replace the decremented value.
- A destination may overlap descriptor storage if the underlying memory is writable. The displacement has already been captured and is not reread.
- A source overlapping descriptor storage observes memory at the time of that source read, not a saved copy of the descriptor.

For ordinary nonwrapping addresses, the function does not issue a sequence destination write at \(E-2\). Nevertheless, that location can change through an overlapping region-field write.

## Acceptance examples

These are conditional acceptance examples derived from static evidence. They are not reports of executed tests.

### Zero iterations still decrement the field and read both captured values

Given **C** = 3 and **N** = 2, with valid descriptor and captured-value locations:

- The region field becomes 2.
- **K** is zero.
- Both initial sequence values are read.
- No iterative sequence reads or writes occur.

This case must not be treated as an early return before the initial reads or field write.

### Two descending transformations

Assume distinct, valid metadata and sequence storage:

- **R** = 64.
- **N** = 1.
- **C** = 4.
- The signed values at region offsets 58 and 60 are 100 and 110.
- The signed values at offsets 56 and 54 are 200 and −20.

Then:

- **E** is region offset 62.
- **P** is 100, **Q** is 110, and **D** is −10.
- The region field becomes 3.
- **K** is 2.
- The first sequence write stores 210 at offset 58.
- The second sequence write stores −10 at offset 56.
- The value at offset 60 remains 110, provided no metadata alias affects it.

### A result crossing the signed 16-bit boundary

Assume **K** is 1, **P** is 0, **Q** is 1, and the first source is 32,767.

The mathematical result is 32,768. The destination receives `0x8000`, not a saturated value of 32,767.

### Zero initial field does not imply no work

Given **C** = 0 and **N** = 0:

- The field write stores 65,535.
- **K** is 65,535.
- Subject to valid storage, the function performs that many descending sequence transformations.

An implementation that rejects the underflow, clamps it to zero, or skips the loop would differ from the supplied behavior.

### A source overlapping the region field observes the decrement

Assume an address layout in which the first iterative source is \(B+10\), the captured values occupy separate locations, and **K** is positive.

The first iterative source read occurs after the field write. It therefore uses the updated 16-bit field value, interpreted as signed, rather than the original unsigned **C**.

### Captured values survive later overwrites

If the first sequence destination overwrites the original location of **P**, all subsequent iterations still use the originally captured **P** and **Q**. The difference is not recalculated from memory.
