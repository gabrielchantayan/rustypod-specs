# F-675089d24864

## Purpose

F-675089d24864 performs state-dependent memory mutation and indirect control transfer. Its domain-level purpose is not established. The available evidence does not justify describing it as an allocator, parser, constructor, or serializer.

The represented outcomes are:

- Returning a dependency’s 64-bit result.
- Returning a locally assembled 64-bit result.
- Reaching a boundary identified as invalid instruction data.
- Continuing through a loop with no established iteration bound.
- Issuing software interrupt 74 and, if execution continues, reaching an unresolved indirect transfer.

This is a conditional, source-facing contract. Access widths, arithmetic predicates, and represented sequencing are established static evidence. Successful execution, memory safety, and faithful recovery of all control-flow edges are not established.

### Widths and memory model

The represented accesses have widths of 8, 16, or 32 bits. Results transported as 64 bits can be separated into low and high 32-bit halves.

Arithmetic below uses 32-bit bit patterns, with truncation to that width and signed interpretation where required by an arithmetic right shift, a negativity test, or signed subtraction overflow. Narrow stores retain the low 8 or 16 bits. Bytes used in arithmetic are zero-extended; the finalization destination is explicitly obtained by zero-extending a 16-bit read.

Signed subtraction overflow is distinct from unsigned carry and ordinary ordering. Address calculations, products, and left shifts must retain their width-sensitive behavior.

The contract does not establish byte order, alignment rules, address-space permissions, memory concurrency, or fault handling. Validity of every accessed address and the actual entry convention are execution preconditions, not checks performed by this operation.

## Behavior

### Entry gate and dispatch

The second argument is reduced by 12 before the first represented memory access. That access reads a halfword at the adjusted argument plus 256 times the index input.

A nonzero halfword selects a terminal side route. The index product is arithmetically shifted right by 29. A destination base is loaded from that shifted value minus 57, before either dependency call. The first call receives the shifted value minus 62, a word read at twice the shifted value plus the auxiliary base plus 138, a local stack address, and 67. The next call receives the first result’s two 32-bit halves and the fixed marker `0x08572BC4`. An auxiliary result from the second call is stored as a word at the captured destination base plus 4. The representation then ends at an invalid-instruction boundary.

A zero halfword enters dispatch. Two quantities govern it:

- The adjusted argument, arithmetically shifted right by 25 and then reduced by 62.
- Twice the scale input, truncated to 32 bits and compared unsigned against 113.

The first quantity is necessarily between −126 and 1. Subtracting 116 therefore cannot overflow a signed 32-bit result. Consequently, the represented below-threshold overflow shortcut is unreachable under this arithmetic model.

The reachable dispatch is:

| Doubled scale value | Selected behavior |
|---|---|
| Unsigned below 113 | Ordinary arithmetic route, using address contribution 104. |
| Unsigned at least 113, with signed overflow on subtracting 113 | Ordinary arithmetic route, using the doubled value arithmetically shifted right by 29 as its address contribution. |
| Unsigned at least 113, without that overflow | Extended mutation route. |

The doubled value is always even. Thus 113 is not a reachable dispatch value. The smallest reachable value selecting the extended route is 114. The overflow-controlled ordinary range above the threshold consists of even values from `0x80000000` through `0x80000070`.

The unreachable shortcut remains present in the representation. It selects finalization using the fixed address-like value `0x08572B78` and saves a route marker in stack state. For a zero doubled value, it additionally calls a dependency using a record byte addressed by 32 times the adjusted argument plus a fixed-location-derived base plus 4, that base, a fixed-location word, and 32 times the adjusted argument plus 153. This is documented structure, not reachable acceptance behavior.

### Ordinary arithmetic route

A byte is read at the doubled scale value plus the selected address contribution minus 70. A dependency then supplies a 64-bit result. Its high half is saved in stack state; its low half is multiplied by the doubled scale value plus `0x08572BD3`.

After another call, an auxiliary result supplies a word address by being doubled. The word is read and doubled to determine both a destination contribution and a later branch predicate. The destination is that doubled word arithmetically shifted right by 21, plus the earlier byte plus 53.

A second word read at the same source address supplies the value written to that destination, shifted left by one. The destination therefore depends on the first read, while the stored value depends on the second. They are not interchangeable observations.

If bit 20 of the first doubled word is set, two further calls consume, respectively, a halfword at the secondary base plus 4 and a byte at the earlier product minus 60. After those calls, a word loaded at the earlier byte plus 89 supplies a base. The low 16 bits of the latest auxiliary result are stored at that base plus the full auxiliary result. Execution then reaches an invalid-instruction boundary.

Otherwise, execution enters common finalization. The product minus 61 becomes its route-selected address. The earlier byte plus 53 is saved in stack state; it is **not** the value ultimately written at finalization destination offset 4.

### Extended mutation route

Several calls surround the object-like accesses. Two initial calls precede loading an object base from an auxiliary result plus the dispatch-derived signed quantity. A further call precedes writing that quantity’s low byte at object offset 11.

Another call precedes reading the selector byte at offset 15. The next call supplies an auxiliary byte written at offset 19. A subsequent call returns a base from which a word is read at the selector-byte offset. Two further calls follow; the latter returns the 32-bit value used by the subsequent branch.

The next decision tests signed subtraction overflow of the loaded word minus the object base.

#### Overflow case

The latest call result is doubled and retained. The selector is widened and increased by 18, producing a value from 18 through 273. A dependency receives the latest result and its arithmetic right shift by 25; its low 32-bit result becomes a new base.

The loaded word minus the object base is stored at new-base offset 100. A word is then read at new-base offset `0x07000000`. Carry is tested across addition of that word, the widened selector, and a carry-in of one exactly when the unsigned new base exceeds `0xF8FFFFFF`.

Without carry, the sum’s low byte, including carry-in, is written at a fixed-location base plus 17. Execution reaches an invalid-instruction boundary.

With carry, the observable sequence includes intervening calls between these accesses:

- A byte read at new base plus `0x07000008` plus the widened selector.
- A word store of the retained doubled result at new-base offset `0x07000054`.
- A word store of the zero-extended byte at new-base offset `0x07000044`.
- A byte store at the zero-extended byte plus the widened selector, containing the low byte of new base plus `0x07000008`.

Further calls include one receiving a preceding result minus 166. Software interrupt 74 follows. If execution continues through the represented edge, an unresolved indirect transfer receives a fixed-location value, a byte read at that value plus 9, another fixed-location value, and a local stack address. Its 64-bit result is returned if that transfer returns as represented.

#### Non-overflow case

Before the next call, the latest result is arithmetically shifted right by 9 and compared unsigned against `0xFFFFFFBE`. The comparison is captured before the call. It is true precisely when the signed shifted value lies between −65 and −1.

The call receives the latest result, its shifted value plus 65, and the loaded word minus 60 arithmetically shifted right by 20.

A false captured comparison enters the shared processing tail directly. A true comparison first stores the object base’s low 16 bits at the returned low half plus 42. Execution then enters the shared tail if object-base negativity equals signed subtraction overflow of the returned high half minus 47. Otherwise, it enters the loop body.

On that first direct loop entry, the state value is the returned high half, the first call’s index-like argument is the returned low half logically shifted right by 25, and the pending word-store payload is the auxiliary base minus the object base.

The pending payload is written as a word at current-state offset 62. The state plus 10 is then multiplied by 65,536 at 32-bit width. A negative result selects the local return immediately, using the latest returned low half as its low-half source.

Otherwise, the latest returned low half is stored as a halfword at its high half plus 60. Two calls follow, after which the halfword constant 38 is written at the latest returned base plus 2.

The remaining body derives a value by multiplying state-plus-10 by `0x10000000` and arithmetically shifting right by 9. Its sum with state-plus-10 is combined by exclusive OR with a fixed-location word captured before an intervening call. That call receives twice the latest base and state-plus-10 times 65,536 minus 81.

The exclusive-OR result is saved in stack state. A further call receives marker `0x085734E8`, a byte read at that result plus 1, the derived value plus 47, and an auxiliary result. The derived value plus 47 is then written at the exclusive-OR result plus 36. After another call, the shared tail receives a result pair consisting of the exclusive-OR result as its low half and an auxiliary result plus 48 as its high half.

The shared tail computes twice the pair’s low half and four times the square of its high half, all at 32-bit width. Three calls follow: the first receives the low half plus the secondary base, the second receives a fixed-location word, and the third has no displayed explicit arguments. The fixed-location continuation condition is read after these calls.

If that condition is zero, the local return uses the latest auxiliary result arithmetically shifted right by 9 as its low-half source. If nonzero, the square is stored at twice the pair’s high half plus 52, and another loop iteration begins.

- The latest auxiliary result becomes the next state.
- Twice the tail pair’s low half becomes the next index-like argument.

Thus the payload written at state offset 62 is not permanently the auxiliary-base-minus-object-base difference. A direct tail entry also establishes the square payload before any subsequent loop body.

## Acceptance examples

These are conditional static criteria, not executed tests. They assume the indicated accesses and dependency returns occur as represented.

1. **Initial nonzero gate:** A nonzero first halfword selects the two-call side route and destination-plus-4 word store. Threshold dispatch is not entered.

2. **Wrapping scale:** Scale input `0x80000000` doubles to zero. With a zero initial halfword, it selects the ordinary below-threshold route, not the unreachable finalization shortcut.

3. **Threshold reachability:** A doubled value of 112 selects the ordinary route. A doubled value of 114 selects the extended route. No 32-bit scale input produces doubled value 113.

4. **Signed-overflow dispatch:** Doubled value `0x80000070` selects the ordinary route; `0x80000072` selects the extended route. Both are above 113 unsigned.

5. **Separate source observations:** If the ordinary route’s source word changes between its two reads, destination calculation uses the first observation and stored data uses the second.

6. **Narrow destination:** A finalization halfword of `0xFFFE` denotes initial destination address 65,534, without sign extension.

7. **Captured finalization base:** If a dependency changes the fixed-location base after capture, the offset-4 store still contains the captured value.

8. **Loop payload transition:** After a nonzero shared-tail condition, the square store occurs before repetition. The next state-offset-62 store contains that square, not necessarily the original base difference.

9. **Carry-byte width:** A carry-path byte of `0xFF` becomes word value 255 for the word store and address arithmetic. The later byte store still truncates its own value to eight bits.
