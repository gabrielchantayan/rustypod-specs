# F-30f7f2100f80

## Purpose

F-30f7f2100f80 performs an ordered sequence of indirect calls, transforms primary and secondary call results, mutates memory through calculated addresses, and finally invokes an unresolved indirect destination.

**Established static evidence:** the supplied representation identifies argument uses, arithmetic widths, many memory-access widths and offsets, fixed-address state changes, and ordering constraints. It does not establish a domain-level operation such as formatting, serialization, rendering, or object initialization.

**Inferred intent:** repeated masks, scaling, and field-like offsets suggest manipulation of packed values and interconnected state. This does not establish object types, field meanings, or ownership.

This contract describes the supplied representation’s visible behavior. Unresolved execution semantics are identified as **documented_only**, not replaced with conventional pointer or object behavior.

## Behavior

### Call sequencing and result transformations

The first invocation targets the incoming return link plus 0xFFE and receives the first argument. A long straight-line sequence of indirect calls follows. Subsequent destinations are calculated from embedded code-position values plus 0xFFE.

No explicit conditional branch or loop selects an alternative path through this phase. Calls without displayed arguments remain ordered events; they are not established as pure operations or as taking no actual inputs.

Common transformations supplied to later calls include:

- A 32-bit result shifted left by eight.
- A represented 64-bit result separated into low and high 32-bit halves.
- The low half shifted left by eight while the high half is supplied separately.
- Additional arguments containing zero, shifted result halves, masked fields, or retained earlier results.
- Secondary result-register values whose complete return signatures are unresolved.

The third argument’s five-position left shift appears twice: first beside a shifted 32-bit result, then beside transformed halves of a paired result. No preceding range check is visible.

Unknown dependencies may change globals, memory, ownership, or external state. Neither global preservation nor memory lifetime preservation is assumed.

### Arithmetic and width rules

Most arithmetic and address construction use represented 32-bit quantities. Represented 64-bit values principally support paired results and extraction, including unsigned shifts by 32, 34, 36, and 44 positions.

Visible transformations include low-bit masks of widths 11 through 24 at various sites, fixed left shifts up to 31 positions, logical right shifts of unsigned quantities, multiplication by two, four, eight, 256, and 33,554,432, and subtraction of 150.

These are width-sensitive operations, not unbounded integer arithmetic. Under a 32-bit bit-vector model, left shifts discard high bits. A later right shift cannot recover them, and successive left shifts totaling at least 32 positions can eliminate every original bit.

Some retained quantities are explicitly zero before subsequent shifts and forwarding. Those arguments remain zero in the displayed dataflow, without making intervening calls removable.

Signed overflow, signed left-shift semantics, and out-of-range variable shifts remain **documented_only**. Arithmetic examples below are conditional on a stated execution model.

### Initial direct-memory effects

For this region, descriptive names identify value origins rather than recovered object types:

| Name | Origin |
|---|---|
| Packed base | A retained call-result low half shifted left by 25. |
| Scaled base | Another retained call result multiplied by 33,554,432. |
| Retained shifted result | A separate call result shifted left by eight. |
| Small index | A call result shifted left by eight, masked to 15 low bits, then logically shifted right by six. |
| Doubled index address | Twice the small index. |
| Final pair | The last represented paired result before direct mutation. |

The opening memory effects have an established order. A 32-bit packed-base value is written at the final pair’s high half plus 0x14. The byte at packed base plus 9 receives the low byte of that high half. A 32-bit scaled-base value is then written at 256 times the final pair’s low half plus 0x54, before packed base plus 9 is overwritten with the low byte of the packed base.

Next, scaled base plus 0x14 is cleared as a 32-bit word. A byte is read from scaled base plus 5. The word at doubled index address plus 0x14 is cleared before the loaded byte is zero-extended and written to scaled base plus 0x34.

The word at scaled base plus 0x14 is subsequently read. Another clear of doubled index address plus 0x14 precedes two consecutive byte stores of that read word’s low byte at doubled index address plus 0x15.

The post-clear read is an actual represented read, not an unconditional constant-zero result. Aliasing or observable-memory semantics may distinguish it.

### Linked-address mutation and early fixed storage

A byte is read at fixed address 0x05 and zero-extended for use as an address base. Fixed byte address 0x01 receives the low byte of the doubled index address.

Derived byte writes and word transfers then interleave. In particular, a word is read from the byte-selected base plus 0x54 before that location is overwritten. Call this retained word the **anchor**.

The anchor feeds later twofold, fourfold, and eightfold scaling. Its doubled value is written as a 32-bit word at fixed address 0x54.

The routine also writes the low byte of the doubled index address to **fixed address 0x15**. This occurs after the repeated byte writes of the anchor’s four-scaled value at doubled index address plus 0x15, and before the subsequent word store at four times the anchor plus 0x54 and the word store at doubled index address plus 0x34. It is a separate fixed-address mutation, not merely another field-offset description.

The surrounding region includes:

- Repeated word stores at doubled index address plus 0x14.
- Repeated byte stores at offsets 9 and 0x15.
- Self-valued word stores at offsets 0x14 and 0x24.
- Word transfers through offsets 4, 0x44, 0x54, 0x64, and 0x74.
- Byte writes at offset 0x0D.
- A byte loaded at offset 5 and widened into an address base for a word read at offset 0x74.

The last behavior uses an eight-bit address source, not an established full-width pointer. Repeated reads and writes remain distinct represented accesses; no structure identity or list invariant is established.

### Literal writes and repeated-store boundary

The following names describe later retained values:

- **Selected word:** the word reached through a late byte-selected base plus 0x74.
- **Transfer base:** four times the selected word.
- **Late base:** twice the selected word.
- **Adjusted value:** four times the anchor minus 150.
- **Adjusted base:** four times the adjusted value.
- **Shared base:** the value of the global 32-bit word loaded immediately before the fixed word write at 0x60.

The numeric value 0x3A is written as a byte at four times the selected word, as a 16-bit quantity at eight times that word, and as a 32-bit quantity at transfer base plus 0x20.

Adjusted base plus 0x20 subsequently receives four 32-bit writes, in this order: 0x20, 0x2F, a zero-extended byte read from adjusted base plus 4, and 0x20 again.

**After those derived accesses, the global word is read to obtain the shared base. Only afterward is 0x20 written as a 32-bit word at fixed address 0x60.**

Thus preceding derived accesses can affect the sampled global through aliasing. The read must not be moved after the fixed-address store. Conversely, later mutations of the global storage do not automatically replace the already retained shared-base value.

The repeated-store region follows. Each group orders four writes:

| Order within group | Width | Destination and value |
|---|---:|---|
| First | 32 bits | A scaled destination plus 0x54 receives the transfer base. |
| Second | 8 bits | Shared base plus 0x19 receives the low byte of the adjusted base. |
| Third | 8 bits | Adjusted base plus 0x11 receives the low byte of the shared base. |
| Fourth | 32 bits | Shared base plus 0x34 receives an eight-scaled value. |

The first group’s scaled destination and final value use eight times the anchor. Subsequent groups use eight times the adjusted value. The shared and adjusted bases are retained values, not freshly loaded global values on every repetition.

These are repeated accesses to the described destinations, not evidence of traversal over distinct elements. Exact multiplicity is not independently enumerated in this contract and is **documented_only**; no replacement count or permission to collapse repetitions is asserted.

### Publication and three distinct reads at 0x67

The low byte of the retained word read at 0xA9 is written to fixed byte address **0x67**. Three later reads of 0x67 are explicitly represented.

**First read: copy to 0x21.** A word read at late base plus 0x44 occurs after publication and before reading 0x67 for the byte write at fixed address 0x21. The copy uses the byte read at that point.

Between this copy and the second read of 0x67, derived mutations include:

- A byte write at adjusted base plus 0x10.
- Two word writes at shared base plus 0x54, first the loaded offset-0x44 word and later the adjusted base.
- A byte write at late base plus 1, derived from a signed right shift.
- A word read at adjusted base plus 0x40.
- Word writes at shared base plus 0x74, adjusted base plus 0x10, and shared base plus 0x44.

The shift count is the low eight bits of the adjusted base. Counts beyond the defined operand range remain **documented_only**; no masking to five bits is assumed.

**Second read: first derived publication.** The routine freshly reads 0x67 and writes that byte at adjusted base plus 9.

A byte write at late base plus 9 follows. A 32-bit write of the retained 0xA9 word at adjusted base plus 0x44 follows that, then a word is read at adjusted base plus 0x54.

**Third read: second derived publication.** The routine reads 0x67 again and writes that newly read byte at adjusted base plus 9.

Intervening derived writes may alias address 0x67. Consequently, neither derived byte store is specified as unconditional reuse of the originally published byte, nor is the third read interchangeable with the second.

### Final transfers and terminal invocation

Subsequent effects use the word loaded from adjusted base plus 0x54 as another derived base. They include byte stores at offsets 0x0D and 0x11, restoration of the retained late-base offset-0x14 word at late base plus 0x54, and a word read at adjusted base plus 0x14.

## Acceptance examples

These are conditional static review examples, not executed tests.

### Width-sensitive inputs

Under 32-bit bit-vector shifts, a third argument of 3 supplies 96 at each five-position-shift use. Bit pattern 0x08000000 supplies zero after the same transformation.

A paired result with low half 0x12345678 and high half 0x9ABCDEF0 supplies 0x34567800 and 0x9ABCDEF0 at a low-shift/high-pass call site.

### Small-index boundary

Under that same model, the small index is a multiple of four between 0 and 508 inclusive. Its doubled address is a multiple of eight between 0 and 1016 inclusive. These bounds do not establish mapped or writable memory.

### Global sampling order

If preceding derived writes change the global word, the shared base reflects its value when read after those writes and before the fixed word write of 0x20 at 0x60. Sampling it afterward is not an established equivalent.

### Fixed byte writes

If the doubled index address is 0x1F8, its fixed-address publication at 0x15 stores 0xF8.

If the adjusted value is 0x23, the write at fixed address 0x3A stores 0x48: eightfold scaling plus 0x30 yields 0x148, narrowed to eight bits. That write follows the 0xA9 and transfer-base-offset-0x74 reads and precedes the next offset-0x14 and offset-4 reads.

### Fresh reads of published storage

Suppose publication writes 0x7B to 0x67. With stable ordinary memory and no aliasing writes, the copy to 0x21 and both later derived publications receive 0x7B.

If an intervening derived store changes 0x67 to 0x22 before the second read, that read observes the applicable new value. If another intervening store changes it again before the third read, the third publication must use its own read, not the second read’s retained value.

### Partial effects and completion

An early fault does not require rollback or terminal invocation. If all preceding operations complete, the terminal destination receives the specified tuple; no numeric success return or zero-input shortcut is established.
