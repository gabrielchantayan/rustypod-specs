# F-b3a211f667d5

## Purpose

F-b3a211f667d5 dispatches one of three behaviors according to a 32-bit selector:

- Selector `0x61`: conditionally invoke a dependency, then clear two bits in a record’s 16-bit flags field.
- Selector `0x62`: return without reading or writing the record and without invoking dependencies.
- Every other selector: invoke a preparation dependency, inspect a flag, and conditionally replace an eight-byte record field and invoke two further dependencies.

These are established structural behaviors. The meanings of the selectors, flags, record fields, and dependency operations are unknown. Terms such as “preparation” describe call position, not a proven application-level purpose.

The function provides no explicit return value or status result.

## Behavior

### Selector `0x61`: conditional call followed by flag clearing

The function first reads the 16-bit flags field at offset `0x1C` and tests mask `0x0002`.

If that bit is set, F-e6e9e68a0990 is not invoked. The function proceeds to the final flag update.

If that bit is clear, the function performs another read of the flags field and tests mask `0x000C`. If either bit selected by this mask is set, it invokes F-e6e9e68a0990 with:

1. The record reference.
2. The original 32-bit auxiliary value.

If neither selected bit is set, the dependency is skipped.

The two condition reads are distinct in the supplied evidence. In particular, the second read is conditional on the result of the first. A combined single-read predicate describes the result only when the flags remain stable across those reads.

After the optional dependency returns, or immediately if it was skipped, the function reads the flags field again, applies the 16-bit mask `0xFFF3`, and writes the result back to that field. This clears masks `0x0004` and `0x0008` and preserves the other bits from this final read.

The update is based on a fresh read, not a flags value saved before the dependency call. If F-e6e9e68a0990 changes the flags and returns normally with the record still accessible, those changes participate in the final update.

The final flag write occurs even if both bits being cleared are already zero. No other direct record write occurs on this path.

After that write, the function returns.

### Selector `0x62`: no action

The function returns immediately.

There are:

- No dependency calls.
- No direct reads from the record.
- No direct writes to the record.
- No direct use of the auxiliary value.

This is a distinct no-action case, not the default path.

### Every other selector: preparation and conditional replacement

The function first invokes F-4c8fe82549db with the record reference.

Only after that dependency returns does the function directly read the flags field and inspect mask `0x0008`. Consequently, any flag changes made by that dependency affect the branch decision.

If mask `0x0008` is clear, the function returns immediately. It does not directly read the two 32-bit argument fields, replace the first eight bytes of the record, or invoke the remaining dependencies.

If mask `0x0008` is set, the following sequence occurs:

1. Read the 32-bit fields at offsets `0x08` and `0x0C` and pass their values, in that argument order, to F-bd6cb6825d26.
2. After that dependency returns, write its full 64-bit result to offsets `0x00`–`0x07`.
3. Invoke F-8d7acd353fe6 with no explicit arguments.
4. Split its 64-bit result into its low and high 32-bit portions.
5. Read the 32-bit fields at offsets `0x08` and `0x0C` again.
6. Invoke F-a2d1320ee317 with four arguments: the low 32-bit portion, the high 32-bit portion, the newly read field at `0x08`, and the newly read field at `0x0C`.
7. Return.

The relative evaluation order of the two field reads used for a single dependency call is not established. Their argument positions are established.

The second pair of field reads is not required to equal the first pair. F-bd6cb6825d26 and F-8d7acd353fe6 may have effects not described by their explicit argument lists. In particular, the evidence does not establish that either dependency preserves the record through aliases or preserves global state.

The 64-bit record write completes before F-8d7acd353fe6 is invoked. The second pair of field reads occurs after F-8d7acd353fe6 returns.

The split of the latter dependency’s result preserves its low and high 32-bit patterns in that order. The high portion comes from bits 32 through 63 of the 64-bit result. No addition, multiplication, or pointer offset arithmetic is performed on that result. Whether a downstream consumer interprets either 32-bit portion as signed is unknown.

### No reachable default-path flag write

The supplied body includes a later conditional flag update controlled by the same saved decision that already caused an immediate return when true.

Reaching the later point requires that decision to be false. Therefore, under ordinary control flow, the later flag-setting operation is unreachable.

The default path consequently performs no direct write to the flags field. This conclusion does not imply that its dependencies leave flags unchanged.

## Side effects

### Direct effects

The function’s direct memory effects are limited to:

- Reading the flags field on the `0x61` and default paths.
- Clearing masks `0x0004` and `0x0008` in the flags field on the `0x61` path.
- Reading the two 32-bit argument fields on the active default path, once for each of two dependency calls.
- Replacing the first eight bytes of the record on the active default path.

No direct allocation, deallocation, input/output operation, global-variable access, or resource release is established.

### Dependency effects and ownership

The record reference is passed to F-e6e9e68a0990 and F-4c8fe82549db on their respective paths. The supplied body does not establish whether either dependency retains the reference, changes other record fields, accesses global state, or manages resources.

Likewise, the 32-bit fields passed by value are not established to be handles, addresses, lengths, or ordinary numbers. No ownership transfer can be inferred from their widths alone.

The function overwrites the previous 64-bit contents at offset `0x00` without directly reading or releasing them first. Whether preparation or another dependency manages any associated resource is unknown. The replacement must not be described as leak-free, destructive, or ownership-transferring without additional evidence.

### Error and partial-progress behavior

There is no explicit error-result check for any dependency.

In particular, every 64-bit result returned normally by F-bd6cb6825d26 is stored, including zero or a value that another component might interpret as an error indicator. Every result returned normally by F-8d7acd353fe6 is split and forwarded.

There is no rollback. If a later operation fails, earlier dependency effects or the completed 64-bit record write may already be visible.

No synchronization or atomic read-modify-write guarantee is established for the flags update. Claims about concurrent access require a separate memory and synchronization contract.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume accessible memory, normal dependency returns, no concurrent mutation, and dependencies that leave fields unchanged except where explicitly specified.

### No-action selector

Given selector `0x62`, the function must return without accessing the record or invoking any dependency. The auxiliary value must have no direct effect.

### Conditional call and clearing

Given selector `0x61` and stable flags `0x000C`:

- F-e6e9e68a0990 must receive the record reference and the supplied auxiliary value.
- After its normal return, both selected bits must be cleared.
- If the dependency leaves the flags unchanged, the final flags must be `0x0000`.

Given selector `0x61` and stable flags `0x000E`:

- Mask `0x0002` suppresses the dependency call.
- The final flags must be `0x0002`.

Given selector `0x61` and stable flags `0xA001`:

- The dependency must not be called.
- The final flags must remain `0xA001`.
- A flags write still occurs.

### Dependency changes preserved by the final read

Given selector `0x61`, initial flags `0x0008`, and F-e6e9e68a0990 changing the flags to `0x804E` before returning:

- The final mask must operate on `0x804E`.
- The final flags must be `0x8042`, not a masked version of the initial value.

### Preparation controls the default branch

Given an unrecognized selector, if F-4c8fe82549db returns with mask `0x0008` clear:

- No later dependency must be invoked.
- This function must not directly overwrite the first eight record bytes.

This requirement applies even if the bit was set before preparation. Conversely, preparation setting the bit activates the remaining path even if it was initially clear.

### Replacement and result splitting

Given an active default path, suppose F-bd6cb6825d26 returns `0xFEDCBA9876543210` and F-8d7acd353fe6 returns `0x1122334455667788`.

The first eight-byte field must receive the numeric value `0xFEDCBA9876543210` before F-8d7acd353fe6 is called. F-a2d1320ee317 must receive `0x55667788` as its first argument and `0x11223344` as its second.

If the two 32-bit record fields change between the first and second dependency calls, the final call must use the freshly read values, not cached earlier values.

### Default path does not set mask `0x0004`

Given an active default path whose dependencies leave flags at `0x0008`, the function must not directly change them to `0x000C`. The later conditional flag-setting operation is unreachable under ordinary execution.
