# F-60c7a5266fe6

## Purpose

F-60c7a5266fe6 performs two unsigned 16-bit memory reads, selects a state-update path according to whether its second argument is zero, performs a final 32-bit memory store, and returns its fifth argument unchanged.

For a nonzero second argument, the final store writes the zero-extended value from the second read to a context-relative destination.

For a zero second argument, the function assigns five global destinations, writes the captured second-read value to a different context-relative destination, calculates a shifted context base, and ultimately writes 141 to a destination relative to that shifted base.

The zero comparison occurs after both reads. Consequently, the zero-selected path is not an established mechanism for safely handling an inaccessible zero-based address.

Application-level purpose is unknown. Interpretations such as initialization, recovery, or exception-state setup are inferred intent, not contractual behavior.

## Behavior

### Common prefix

The represented sequence begins with:

1. Read an unsigned 16-bit value from the argument source.
2. Read an unsigned 16-bit value from the context source and zero-extend it to 32 bits.
3. Establish the original context as the base for the eventual final store.
4. Compare the second argument with zero.

The argument-source value is captured for possible use by the zero-selected path. The context-source value is captured as a 32-bit numerical value in the range 0 through 65,535.

Both reads precede the branch decision. In particular:

- A zero second argument still requires the initial read based on address 4.
- A nonzero second argument is not validated before its offset-4 read.
- The argument-source read remains part of the nonzero path even though its value does not determine that path’s store or result.
- Neither source is explicitly reloaded later.

This is the order expressed by the static representation. It does not independently establish physical instruction scheduling, memory-transaction decomposition, or fault-delivery timing.

### Nonzero second argument

The function skips the conditional state updates and writes the captured, zero-extended context-source value to the ordinary destination using a 32-bit store.

It then returns the fifth argument unchanged.

No assignments to G1–G5, branch-destination store, or context-left-shift calculation appear on this path. The final-store base remains the original context.

### Zero second argument

This path is selected only after the common-prefix reads have been reached and execution has continued to the comparison.

Its represented sequence is:

1. Supply the context minus 5 to the assignment to G1.
2. Use G1’s post-assignment value in a multiplication by 256, supplying that expression’s result to the assignment to G2.
3. Store the captured, zero-extended context-source value at the branch destination using a 32-bit store.
4. Replace the retained final-store payload with the 32-bit value 141.
5. Calculate the context shifted left by 8 bits and retain that result as the final-store base.
6. Convert the captured argument-source value to unsigned 32 bits and supply it to the assignment to G3.
7. Supply the original context value to the assignment to G4.
8. Supply the auxiliary value to the assignment to G5.
9. Add 48 bytes to the retained shifted base and perform the final 32-bit store of 141.
10. Return the fifth argument unchanged.

The left-shift calculation is therefore positioned **after the branch-destination store and before the assignments to G3, G4, and G5**. It is not deferred until the final store.

The branch-destination address uses the original context, not the shifted base. Its payload is the captured context-source value, not 141.

No separate store to the ordinary destination appears on this path. Its bytes may nevertheless be affected if they overlap another destination that is written.
