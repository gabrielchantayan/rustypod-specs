# F-be3477f421e5

## Purpose

On its active path, it invokes initialization-related dependencies, obtains and submits values for the requested index and eligible adjacent indices, performs conditional actions on three associated handles, and resets several state fields.

The distinction between a “current” index and its “next” and “previous” neighbors follows directly from the arithmetic and destination fields. Interpreting the operation as selection, navigation, animation, or display initialization is **inferred intent**, not an established interface guarantee.

The contract below describes the supplied static representation. Dependency implementations are unavailable. Their names, return-value meanings, memory ownership, and effects on shared state are not established.

## Behavior

### 1. Entry guard

The function reads the 32-bit word at `0xE8` and tests its low-order byte.

- If that byte is nonzero, it returns immediately.
- If that byte is zero, it enters the active path.

On the immediate-return path, there are no explicit object writes or dependency calls.

Other bits in the guard word do not independently prevent entry.

### 2. Initial calls and requested-index setup

The active path begins in this order:

2. Call F-44341bd71b97 with the object and integer argument 1.
3. Call F-44341bd71b97 with the object and integer argument 2.
4. Call F-44341bd71b97 with the object and integer argument 3.
5. Read the callback address at `0xAC` and invoke it with the requested index.

The callback produces an opaque 32-bit value. After that callback returns, the function explicitly writes:

1. Byte `0xA4` ← 2.
2. Word `0x50` ← −40.
3. Word `0x54` ← 160.
4. Word `0x58` ← 360.
5. Word `0x64` ← 122.
6. Word `0x68` ← 122.
7. Word `0x6C` ← 122.
8. Word `0x7C` ← requested index.

It then calls F-9e6f3623406e with the object and the callback result.

Consequently, the initial callback runs before these explicit writes. F-9e6f3623406e runs after them, but may itself change the object. No particular post-call value is guaranteed for fields a dependency can modify.

### 3. Next-index processing

The next candidate is the requested index plus one, subject to the arithmetic limitations discussed under Uncertainties.

The function reads the wrap-mode byte at `0xE7` after the requested-index submission.

**When wrap mode is zero:**

- Read the signed boundary value at `0xA0`.
- If the candidate is strictly less than that boundary, process the candidate.
- Otherwise, call F-44341bd71b97 with the object and 3. No next-index callback, explicit `0x80` write, or next-value submission occurs on this branch.

**When wrap mode is nonzero:**

- Read the signed boundary value at `0xA0`.
- If that boundary is less than or equal to the candidate, choose index zero.
- Otherwise, choose the candidate.
- Process the chosen index regardless of whether it is otherwise a valid application index.

Processing a next index means, in order:

1. Read the callback address at `0xAC` and invoke it with the chosen index.
2. Write the chosen index to `0x80`.
3. Call F-9e6f3623406e with the object and callback result.

The index write therefore occurs after the callback and before submission.

### 4. Previous-index processing

Previous-index processing follows all next-index activity. Its initial candidate is the original requested index minus one.

The function reads `0xE7` again. It does not reuse the next-index phase’s mode value.

**When wrap mode is zero:**

- If the previous candidate is negative, call F-44341bd71b97 with the object and 1. No previous-index callback, explicit `0x78` write, or previous-value submission occurs.
- Otherwise, invoke the callback currently stored at `0xAC` with the previous candidate, then write that candidate to `0x78`.

This branch does not compare a nonnegative previous candidate against `0xA0`.

**When wrap mode is nonzero:**

- If the previous candidate is negative, read the current boundary value at `0xA0` and choose that value minus one.
- Otherwise, choose the previous candidate without reading the boundary for this decision.
- Invoke the callback currently stored at `0xAC` with the chosen index.
- Write the chosen index to `0x78`.

Whenever a previous-index callback is performed, the function next calls F-9e6f3623406e with the object and its result.

The function does not clamp an arbitrary out-of-range requested index into the boundary range. Neighbor wrapping consists only of the specific substitutions above.

- Callback addresses are read separately for the requested, next, and previous lookups.
- Mode and boundary values are not captured once for the entire operation.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless otherwise stated, assume valid accesses, normally returning dependencies, no relevant dependency mutations, and representable signed arithmetic.

1. **Guarded no-op.**  
   If the guard word’s low-order byte is nonzero, the function returns without any dependency call or explicit write.

2. **Interior index without wrapping.**  
   For requested index 2, boundary 5, and zero wrap mode, index-callback arguments occur in order 2, 3, 1. The corresponding explicit index writes are `0x7C` ← 2, `0x80` ← 3, and `0x78` ← 1. Each callback result is submitted before the next neighbor phase.

4. **Last index without wrapping.**  
   For requested index 4 and boundary 5, next processing calls F-44341bd71b97 with argument 3. Callback arguments are 4 and then 3. There is no explicit next-index write.

5. **Wrapping at either boundary.**  
   With boundary 5 and nonzero wrap mode:
   - Requested index 4 produces callback arguments 4, 0, 3.
   - Requested index 0 produces callback arguments 0, 1, 4.

6. **Single-element boundary with wrapping.**  
   For requested index 0 and boundary 1, all three callback arguments are zero. Duplicate indices do not suppress callbacks or submissions.

7. **Zero boundary is not rejected.**  
   For requested index 0, boundary 0, and nonzero wrap mode, callback arguments are 0, 0, −1. The supplied representation does not establish that the callback accepts these arguments.

8. **Query result does not gate the action.**

9. **Dependency mutation affects later decisions.**
