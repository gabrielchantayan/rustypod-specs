### Address derivation

The third write uses the ambient word as an unsigned 32-bit value.

Its destination address is obtained by retaining the highest ten bits of that word, interpreting them as a number from 0 through 1,023, and multiplying that number by 256.

Consequences of this calculation:

- The possible destination addresses range from `0x00000000` through `0x0003FF00`, inclusive.
- Every destination is a multiple of 256 bytes.
- There are 1,024 possible destination addresses.
- The lower 22 bits do not affect the destination address.
- The multiplication cannot overflow a 32-bit unsigned quantity: its largest result is `0x0003FF00`.
- Address zero is possible and is not rejected by the fragment.

The represented access uses the derived number directly as an address. No allocation base, table base, object pointer, or additional displacement is visible.

These facts describe the recovered address calculation, not the platform’s memory map. A low numerical address might designate ordinary memory, a device, protected memory, or an unmapped region. The evidence does not decide among those cases.

### Stored value and layout

The third write is represented as a 16-bit store derived from the ambient word’s low 16 bits.

The address selection and stored payload therefore use different portions of the same word:

- Highest ten bits: destination selection.
- Lowest sixteen bits: stored bit pattern.
- Bits 16 through 21: no effect on either the represented destination or the represented payload.

A change confined to those intervening six bits leaves the represented third write unchanged.

The recovered representation narrows the word through a signed 16-bit type. For a bit-level description, the represented payload is the low 16-bit pattern. The signed numerical interpretation of a pattern with its high bit set must not be mistaken for an additional store or a wider sign-extended write.

The evidence does not establish byte order. For example, a payload of `0x1234` establishes a 16-bit pattern, but not whether the lower-addressed byte is `0x12` or `0x34`.

No larger record, array element structure, or adjacent-field layout is demonstrated.
