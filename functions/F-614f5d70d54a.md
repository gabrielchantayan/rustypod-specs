# F-614f5d70d54a

## Purpose

F-614f5d70d54a performs ordered dispatch on an event-like input and an object-like receiver. It first attempts a specialized callback selected by an event category and, for some categories, a value obtained from F-468ee00d626a. If no specialized callback is selected, or the selected callback returns zero, it enters a common fallback phase.

The fallback phase first queries a receiver callback. A zero query result suppresses further handling and produces a zero result. A nonzero query result permits either conversion followed by category-specific handling or direct generic handling.

These are structural descriptions, not established application semantics. The evidence does not establish that the input is a keyboard event, that the discriminator values name particular commands, or that nonzero necessarily means “handled.”

## Behavior

### 1. Ordered specialized selection

Selection proceeds through the following alternatives in order. The first successful alternative selects one callback. Later alternatives are not evaluated after a match.

Each reference to reading the category below denotes a fresh read of the event field at offset 4. Each call to F-468ee00d626a receives the original event address.

1. Read the category. If it equals 0x0D, call F-468ee00d626a. A result equal to 0x59 selects F-CB180.
2. If no selection has occurred, read the category again. If it equals 0x0D, call F-468ee00d626a again. A result equal to 0x5A selects F-CB17C.
3. If still unmatched, read the category again. If it equals 0x0D, call F-468ee00d626a again. A result equal to 0x6F selects F-CB184.
4. If still unmatched, read the category again. A category equal to 0x15 selects F-CB188 without calling F-468ee00d626a for this alternative.
5. If still unmatched, evaluate the 0x57 alternative:
   - Read the category. If it equals 0x0D, call F-468ee00d626a and compare the result with 0x57.
   - Only if that combined test fails, read the category again. If this new read equals 0x07, call F-468ee00d626a and compare the result with 0x57.
   - Either successful comparison selects F-CB174.
6. If still unmatched, evaluate the 0x58 alternative with the same two-part structure:
   - A fresh category read equal to 0x0D permits one call to F-468ee00d626a.
   - If that combined test fails, another category read equal to 0x07 permits another call.
   - A result equal to 0x58 in either permitted call selects F-CB178.
7. If still unmatched, read the category again. A category equal to 0x13 selects F-CB170.
8. If the final category check does not match, enter fallback without invoking a specialized callback.

This sequence is not equivalent, in general, to decoding the event once and consulting a lookup table. Category reads and discriminator calls are repeated. The supplied evidence does not establish that F-468ee00d626a is pure, deterministic, or unable to modify the event, receiver, dispatch table, or other state.

For example, an early discriminator call can fail its current comparison while altering the category so that a later alternative succeeds. A result equal to 0x58 during the first discriminator call does not itself select F-CB178; only the comparisons at the designated 0x58 alternative can do that.

Under the additional assumption that the category remains stable:

- Category 0x0D can cause up to five discriminator calls.
- Category 0x07 can cause up to two discriminator calls.
- Other categories cause no discriminator calls.

Those bounds are conditional on stability. If discriminator calls change the category, both parts of a two-part alternative can become eligible, allowing up to seven discriminator calls across the whole selection phase.

### 2. Selected specialized callback

After selection, the function reads the receiver’s dispatch-table address and loads the selected callback address from its associated slot.

The callback receives, in order:

1. The original receiver address.
2. The original event address.

If its result is nonzero, that exact result is returned immediately. The fallback query, conversion dependency, and fallback handlers are not called.

If its result is zero, execution enters fallback. No further specialized alternative is tried. In particular, a zero result from an earlier-priority callback does not cause selection of a later specialized callback.

No null-target check is performed before the indirect call.

### 3. Common fallback query

Fallback is entered either because no specialized callback matched or because the selected callback returned zero.

The function then reads the receiver’s dispatch-table address and loads F-CB160 from offset 0x160. This is a new table lookup, not reuse of the table address used for a prior specialized callback.

F-CB160 receives only the receiver address.

- If it returns zero, the function returns zero.
- If it returns nonzero, the function reads the event category and chooses a fallback path.

The query result is used solely as a zero/nonzero condition. It is not itself returned.

Because the table lookup occurs after the specialized callback, a dispatch-table replacement performed by that callback can affect which query implementation runs. Because the fallback category is read after the query returns, event changes made by either callback can affect fallback routing.

### 4. Fallback routing

The category obtained after a successful query is retained for this routing decision.

| Category read after query | Action |
|---|---|
| 0x07 or 0x0D | Call F-682adfd5a561 with the event and 0x0A00; pass its four-byte result to F-9a45315b9740 with the receiver |
| 0x15 | Call F-682adfd5a561 with the event and 0x3500; pass its four-byte result to F-e9270c70c772 with the receiver |
| Any other value | Call F-UNRESOLVED-01 with the receiver and event |

F-UNRESOLVED-01 is a local documentary identifier for the direct fallback dependency whose opaque published identity is not supplied.

For both conversion paths, argument order is:

- Converter: event address, then the indicated constant.
- Handler: receiver address, then the converter’s four-byte result.

There is no check for conversion failure, nullness, sign, or any other property of the conversion result. Its value is forwarded to the chosen handler.

The handler’s result becomes the function’s result without normalization or additional dispatch. A zero handler result ends processing just as a nonzero result does.

Once the fallback category has been read, later changes to the event category by the converter do not change the chosen fallback branch.

## Side effects

### Direct effects

The visible function body performs:

- Reads of the event category.
- Reads of the receiver’s dispatch-table field.
- Reads of selected callback entries.
- Calls to dependencies.
- Integer comparisons and result selection.

It contains no explicit write to receiver storage, event storage, the dispatch table, or a named global. It performs no visible allocation, release, copying, or ownership bookkeeping.

That absence is limited to the visible body. It does not imply that the function is side-effect-free: dependencies may mutate memory or external state.

### Observable ordering

For ordinary readable memory, the significant ordering is:

1. Ordered category checks and their conditionally invoked discriminator calls.
2. Selected specialized callback lookup and invocation, if any.
3. Immediate return on a nonzero specialized result.
4. Otherwise, a fresh dispatch-table lookup and fallback query.
5. A category read only if the query returns nonzero.
6. Conversion followed by its selected handler, or a direct generic fallback call.
7. Return of the resulting handler value.

The function does not visibly snapshot the event or receiver before calling dependencies. A dependency’s changes can therefore influence later reads.

This describes the supplied control flow, not a synchronization contract. Atomicity, volatile semantics, cross-thread visibility, and memory barriers are not established.

### Ownership and lifetime

The original input addresses are forwarded rather than copied into new objects. The converter’s result is forwarded as a four-byte value.

No ownership transfer is explicitly represented. It is unknown whether any dependency retains an input address, consumes the converted value, releases storage, or modifies globals. Callers must satisfy the actual lifetime requirements of those dependencies; those requirements cannot be inferred from this function alone.

## Acceptance examples

These are conditional acceptance cases derived from static control flow, not executed tests.

### Stable category 0x0D, first discriminator match

Assume the category remains 0x0D, the first discriminator result is 0x59, and F-CB180 returns −3.

Expected behavior:

- One discriminator call.
- F-CB180 invoked with receiver and event.
- Result −3 returned unchanged.
- No fallback query or fallback handler invoked.

### Stable category 0x0D, later discriminator match

Assume the category remains 0x0D and successive discriminator results are 0x00, 0x00, and 0x6F.

Expected behavior:

- Three discriminator calls.
- F-CB184 selected.
- No evaluation of later specialized alternatives.
- Its nonzero result returns immediately; its zero result enters fallback.

### Stable category 0x07, second eligible match

Assume the category remains 0x07, and the two discriminator results are 0x58 and 0x58.

Expected behavior:

- The first result fails the 0x57 alternative.
- The second result satisfies the 0x58 alternative.
- F-CB178 is selected.
- The first 0x58 result alone does not select that callback.

### Specialized callback declines

Assume category 0x15 selects F-CB188 and that callback returns zero.

Expected behavior:

- No later specialized callback is considered.
- The dispatch table is read again to obtain F-CB160.
- If F-CB160 returns zero, the final result is zero and no conversion occurs.
- If it returns nonzero and the subsequently read category is still 0x15, conversion uses 0x3500 and handling proceeds through F-e9270c70c772.

### State changes affect fallback

Assume category 0x13 selects F-CB170. That callback changes the event category to 0x07, replaces the receiver’s dispatch table, and returns zero. Assume the new table’s F-CB160 returns nonzero without changing the category.

Expected behavior:

- The query comes from the replacement table.
- Fallback observes category 0x07.
- Conversion uses 0x0A00.
- F-9a45315b9740 receives the conversion result.

### Unmatched category

Assume category 0x22 remains stable.

Expected behavior:

- No discriminator or specialized callback runs.
- F-CB160 runs.
- A zero query result yields zero.
- A nonzero query result leads to F-UNRESOLVED-01, whose result is returned unchanged.

### Opaque conversion result

Expected behavior:

- There is no local conversion-error branch.
