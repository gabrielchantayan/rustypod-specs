# F-55bbc91c5390

## Purpose

F-55bbc91c5390 processes a selected byte range into a mutable destination context. It supports two paths:

- A direct path delegates interpretation of a byte range to F-7dbf55efb6cc.
- A composite path delegates expansion to F-ee03dc7f5730, recursively processes newly added component descriptors, and adjusts coordinate pairs produced by each successful recursive call.

The composite path applies independent horizontal and vertical scaling followed by translation. A special case bypasses the scaling dependency when both scale words equal 65,536.

These descriptions summarize the supplied static representation. Names such as “component,” “coordinate,” and “scale” express inferred roles, not independently verified format definitions.

## Interface

The function accepts five arguments represented as 32-bit values:

| Input context | Address-like 32-bit value passed to input-management dependencies. A pointer is subsequently read at byte offset 32. |

## Behavior

### 1. Prepare the input position and extent

The function first calls F-e40a3ceddab2 with the input context and the sum of the base and relative offsets.

- A nonzero result is returned immediately.
- F-d036abe1e536 is not called on this failure.
- No local input-finalization call occurs on this failure.

If the first call returns zero, the function calls F-d036abe1e536 with the input context and extent.

- A nonzero result is returned immediately.
- No local input-finalization call occurs on this failure either.

Only after both calls return zero does the function read the byte pointer at input-context offset 32.

The position sum uses signed 32-bit operands. Overflow handling is not established; mathematical addition without range limits must not be assumed.

### 2. Select direct or composite processing

For a zero extent, the function selects direct processing without reading a byte from the prepared range.

For a nonzero extent, it reads the first byte and tests bit 7:

- Bit 7 clear: direct processing.
- Bit 7 set: composite processing.

This is a first-byte classification, not a scan or validation of the full range. The local code does not reject a negative extent. A negative extent is nonzero and therefore reaches the first-byte read if preparation succeeds.

### 3. Direct processing

The function calls F-7dbf55efb6cc with:

1. The destination context.
2. The prepared byte pointer.
3. An end pointer formed by adding the extent to that byte pointer.

It then calls F-9787e15c337d with the input context, irrespective of whether F-7dbf55efb6cc returned zero or nonzero.

The result returned by F-7dbf55efb6cc is the function’s result. No result from F-9787e15c337d is inspected.

For zero extent, the two range pointers are equal. The direct dependency is still called. This function itself does not dereference the range in that case; the dependency’s behavior for an empty range remains a separate contract.

### 4. Expand a composite input

Before calling the expansion dependency, the function captures, in order:

1. The pointer at destination-context offset 36.
2. The signed descriptor count at destination-context offset 24.

It then calls F-ee03dc7f5730 with only the destination context. The input context and selected range are not explicit arguments to this dependency.

Immediately after that call, it invokes F-9787e15c337d on the input context.

If expansion returned nonzero, that status is returned. Component processing does not begin.

If expansion returned zero, the function reads the descriptor count again, after the finalization call. The earlier count and this later count define the descriptor indices to process: starting at the earlier count and stopping before the later count.

The later count is captured once for this loop. Subsequent count changes do not directly extend its iteration range. If the later count is no greater than the earlier count, no component is processed and the function returns zero, assuming the signed arithmetic involved is valid.

### 5. Process each selected component recursively

Components are visited in increasing descriptor-index order.

For each component, the function:

- Reads the current descriptor-array pointer from destination-context offset 32 and locates the descriptor using the 24-byte stride.
- Reads and sign-extends the signed 16-bit count at offset 22 of the previously captured object.
- Recursively invokes F-55bbc91c5390 with the same destination context, same input context, unchanged base offset, and the descriptor’s relative offset and extent.

The supplied representation does not establish the relative evaluation order of the two descriptor-word argument reads.

A nonzero recursive result is returned immediately. The current component’s coordinate adjustment is skipped, and later components are not processed.

After recursive success, the function rereads the descriptor-array pointer and reacquires the current descriptor. Thus, descriptor-array relocation during recursion can be accommodated at this boundary, provided the current descriptor index remains valid.

The function then rereads the signed 16-bit count from the previously captured object. The difference between the new and old signed values determines how many coordinate pairs it will adjust.

This is a count-difference calculation, not a separately validated append operation. A zero or negative difference causes no coordinate writes.

### 6. Adjust the resulting coordinate range

The coordinate range begins at the coordinate-array base plus eight times the count saved before recursion. The coordinate-array pointer is read after recursive success, from the previously captured object.

The descriptor’s first scale word is tested against 65,536. Only if it matches is the second scale word read for the corresponding equality test.

**Both scale words equal 65,536**

For each selected pair:

- Add the descriptor’s first translation word to the first coordinate and write the result.
- Add the descriptor’s second translation word to the second coordinate and write the result.

F-74efb2674226 is not called on this path.

**Either scale word differs from 65,536**

For each selected pair:

- Pass the first coordinate and first scale word to F-74efb2674226.
- Add the first translation word to its result and write the first coordinate.
- Pass the second coordinate and second scale word to F-74efb2674226.
- Add the second translation word to its result and write the second coordinate.

The first coordinate is written before the second scaling call. Pairs are processed in ascending address order.

The descriptor and coordinate-range pointers are retained during a component’s adjustment loop. The code performs descriptor-field reads within processing rather than taking one immutable copy of all four transform words. In particular, each translation is read after its corresponding scaling call on the nonidentity path. Unknown dependency side effects or aliasing can therefore affect the values subsequently observed.

No full two-dimensional matrix operation is present: there are no cross-coordinate terms in the visible adjustment.

After all selected components complete successfully, the function returns zero.

## Side effects

### State and memory

The function directly writes coordinate words on the composite path. Other changes to destination state, input state, descriptor storage, or counts are delegated to dependencies or recursive calls.

Processing is incremental, not transactional:

- Earlier components remain processed when a later component fails.
- A failing recursive call may already have changed state.
- No rollback restores input position, counts, descriptors, or coordinates.
- A failure during coordinate access or arithmetic has no visible local recovery mechanism.

### Input finalization

F-9787e15c337d is called once after either direct interpretation or composite expansion at the current invocation level. It is not called locally when either preparation dependency fails.

For composite processing, this call precedes every child invocation. There is no additional parent-level finalization call after the child loop. Recursive invocations perform their own preparation and finalization according to the same rules.

The name “finalization” describes its position in the sequence, not proven ownership behavior. It is not established that this dependency frees memory, restores a cursor, or leaves unrelated state unchanged.

### Ownership and lifetime

No direct allocation or deallocation appears in the supplied representation. Ownership transfer is not established.

Safe execution requires every pointer actually dereferenced to remain valid for that access. In particular:

- The object pointer captured before composite expansion must remain usable afterward and across recursive calls.
- Descriptor-array relocation is reread at the documented boundaries, but descriptor indices must remain meaningful.
- Coordinate storage must cover the range selected by the signed counts.
- Pointers retained across scaling calls must remain valid.

The function does not enforce these requirements.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Initial preparation failure.** If F-e40a3ceddab2 returns a nonzero status, the function returns that same status. No later dependency is called by this invocation.

2. **Extent preparation failure.** If the first preparation succeeds and F-d036abe1e536 returns nonzero, that status is returned without reading the prepared byte pointer or calling F-9787e15c337d locally.

3. **Empty direct input.** With successful preparation and extent zero, no first-byte classification read occurs. F-7dbf55efb6cc receives equal begin and end pointers, followed by F-9787e15c337d.

4. **Direct interpretation error.** With a nonzero extent and first-byte bit 7 clear, a nonzero result from F-7dbf55efb6cc does not suppress finalization. Its status is returned afterward.

5. **Composite expansion error.** With first-byte bit 7 set, a nonzero expansion result is followed by finalization and then returned. No child is processed.

6. **No selected components.** If expansion succeeds and the descriptor count observed after finalization equals the saved count, the invocation returns zero without recursion.

7. **Identity scaling with translation.** Suppose one successful child changes the signed count from 2 to 4, its two scale words remain 65,536, translations remain 3 and −2, and the selected pairs are (10, 20) and (−5, 7). With valid storage and no interfering mutations, the resulting pairs are (13, 18) and (−2, 5). No scaling dependency is called.

8. **Nonidentity call order.** For one selected pair on the nonidentity path, the first scaling call and first-coordinate write occur before the second scaling call. Expected numeric results require F-74efb2674226’s contract.

9. **Child failure.** If a selected child returns nonzero, its descriptor’s coordinate adjustment and all later components are skipped. Previously completed changes are not undone.

10. **Decreased signed count.** If a successful child changes the signed count from 4 to 2, the negative difference produces no coordinate writes. The function does not report an error merely for that decrease.
