## Behavior

### Common preparation

Each invocation begins with a fresh four-byte temporary result initialized to zero. The wrapper does not initialize that temporary from either object field.

The control value is then compared with zero. The distinction is zero versus nonzero, not positive versus nonpositive. No range restriction is visible.

### Zero-control path

When the control value is zero:

1. The wrapper writes four bytes of zero to the field at offset `0x40`.
2. The temporary result is set to zero again.
3. The wrapper writes that zero result to the field at offset `0x44`.
4. The function returns without an explicit result.

F-d6f1e679078e is not invoked on this path. Neither auxiliary value is forwarded or otherwise visibly used.

The direct destination-write order is `0x40` before `0x44`. The prior contents of those fields do not determine the values written. No direct read of either field is shown.

This branch does not establish release or cleanup of any resource that the previous field contents might have represented. It establishes replacement of the stored values only.

### Nonzero-control path

When the control value is nonzero, the wrapper invokes F-d6f1e679078e with five arguments in this positional order:

| Dependency position | Value supplied |
|---|---|
| First | Object base plus byte offset `0x18` |
| Second | The supplied control value |
| Third | Address of the four-byte temporary result, initially zero |
| Fourth | Auxiliary value B |
| Fifth | Auxiliary value A |

The auxiliary values therefore reach the dependency in the reverse order from their positions in this function’s interface.

The dependency is called before either destination field is directly written by the wrapper. If it returns normally and execution continues:

1. The wrapper writes the supplied control value to the four-byte field at offset `0x40`.
2. The wrapper obtains the temporary result’s then-current four-byte value and writes it to the field at offset `0x44`.
3. The function returns without an explicit result.

The call’s return value, if any, is not used. The third dependency argument is the visible mechanism by which the dependency can provide the value later stored at offset `0x44`.

The wrapper does not check whether the dependency changed the temporary result. If the dependency leaves it unchanged, the stored result is zero. If the dependency writes another four-byte value there, that value is stored without visible validation or transformation.

The dependency receives the control value unchanged. A negative control value, under a signed interpretation of the 32-bit representation, still follows the nonzero path; there is no visible rejection or normalization.
