# F-f987e285db03

## Purpose

F-f987e285db03 searches a forward-linked sequence for the first reachable entry whose 32-bit key equals a requested value. A null link or an entry whose key is the all-ones 32-bit value terminates the search unsuccessfully.

When a matching entry is found, the function invokes dependency F-4a46423b0bb4 with the original container address and the matching entry address. If that invocation returns normally, this function writes an address 20 bytes beyond the matching entry’s base into caller-supplied output storage, then returns the 32-bit value zero.

An unsuccessful search returns the 32-bit pattern `0xFFFFFF85`, interpreted as −123 when treated as a signed 32-bit integer. It does not write the output storage.

These are source-supported behaviors. Descriptions such as “lookup,” “payload,” “detach,” or “remove” require care: searching and returning an interior address are established; removal, ownership transfer, and the meaning of the interior region are not.

## Interface

### Inputs

The function has three arguments:

| Argument | Source-facing interpretation |
|---|---|
| Requested key | A 32-bit value compared for equality against entry keys. The all-ones value, conventionally signed −1, is reserved by the traversal as a terminator. |
| Container address | An address from which a 32-bit head-link value is read at byte offset 12. The original address is also passed to F-4a46423b0bb4 on a match. |
| Output-storage address | An address at which one 32-bit address value is written after a matching entry has been processed by the dependency. |

The supplied representation uses four-byte integer and link fields. The address calculations below describe that apparent 32-bit address model. Portability to a different pointer width or address model is not established.

### Return value

There are two explicit normal return values:

- `0x00000000`: a matching entry was found, F-4a46423b0bb4 returned normally, and the output write completed.
- `0xFFFFFF85`: traversal reached a null link or a sentinel entry without selecting a match.

The latter is −123 under signed 32-bit interpretation. No particular error-name mapping is established.

The dependency’s return value, if any, is not used. A dependency failure that returns normally is therefore not distinguishable through this function’s explicit return value unless it prevents subsequent execution or changes the accessibility of the output storage.

### Relevant memory layout

Only the following fields are read directly by this function:

| Object | Byte offset | Width | Meaning used here |
|---|---:|---:|---|
| Container | 12 | 4 bytes | Initial entry address |
| Entry | 0 | 4 bytes | Next-entry address |
| Entry | 12 | 4 bytes | Key or terminator value |

The returned address is the selected entry’s base plus 20 bytes. The function does not read the region at that address, establish its size, or validate its contents.

These accesses do not establish a complete container or entry layout. In particular, the function does not inspect the entry bytes at offsets 4 through 11 or 16 through 19.

### Preconditions for defined, normally completing use

The container field at offset 12 must be readable. Every non-null entry actually examined must have a readable four-byte key at offset 12. Each nonmatching, nonsentinel entry must also have a readable four-byte link at offset 0.

On a successful path, the output-storage address must permit a four-byte write after the dependency returns. F-4a46423b0bb4 may impose additional requirements on the container and selected entry; those requirements are not available here.

A null output-storage address is not rejected in advance. It is not accessed on an ordinary unsuccessful search, but it cannot support the successful-path write in an ordinary memory environment.

## Behavior

### Search start and termination

The function first reads the initial entry address from the container at byte offset 12. It does not first validate the container address.

If the initial entry address is null, the function returns `0xFFFFFF85`. It does not read an entry key, invoke the dependency, or write the output storage.

For each non-null current entry, the function reads the four-byte key at entry offset 12. It checks for the sentinel value before considering a match.

Consequently, an entry whose key is `0xFFFFFFFF` terminates traversal regardless of the requested key. Such an entry is never selected, including when the requested key is also `0xFFFFFFFF`. The sentinel entry’s next link is not read.

### Matching and advancement

For a nonsentinel entry, equality with the requested key selects that entry immediately. Selection stops the traversal; later entries are not searched.

If the key is neither the sentinel nor the requested value, the function reads the next-entry address from offset 0 of the current entry. That address becomes the next entry examined. A null value ends the search unsuccessfully.

The search therefore selects the first matching entry in actual link-following order. It does not sort keys, inspect later duplicates, or perform a second pass.

The key read precedes any next-link read for that entry. The next link is not read directly by this function for a selected entry or a sentinel entry. This distinction affects which memory locations must be readable on each path.

### Successful-path ordering

Once an entry is selected, the observable sequence is:

1. Invoke F-4a46423b0bb4 with the original container address and the selected entry address.
2. If that invocation returns normally, write the selected entry’s base address plus 20 bytes to the caller’s output storage.
3. If the write completes, return zero.

The address used for the output is derived from the selected entry address retained by this invocation. The function does not re-read the container head, selected key, or selected next link after calling the dependency.

The output displacement is five four-byte units, totaling 20 bytes. It is not five bytes. The output write stores an address value; it does not copy 20 bytes, copy entry contents, or dereference the returned interior address.

The source supplies no address-overflow guard. Normal use requires that the relevant field accesses and the 20-byte address displacement be meaningful in the execution environment. Behavior at invalid or overflowing addresses is not established.

### Failure and abnormal execution

An ordinary unsuccessful traversal returns `0xFFFFFF85` without a direct write to the container, entries, or output storage, and without invoking F-4a46423b0bb4.

Invalid reads, an invalid output write, a dependency that does not return, and a nonterminating link cycle are not converted into this failure return. The function contains no explicit recovery for those conditions.

There is no cycle detection or traversal bound. A stable cycle containing neither a sentinel nor a matching key does not reach a normal return. A reachable match or sentinel can still terminate traversal before repetition.

## Side effects

### Direct reads and writes

The function directly:

- Reads the initial link from container offset 12 once.
- Reads one key from each non-null entry it examines.
- Reads a next link only from entries that are neither sentinels nor matches.
- Writes one four-byte address value through the output argument only after a match and a normal dependency return.

There is no direct allocation, release, entry-content copy, or global-state access visible in this function.

### Dependency-mediated effects

F-4a46423b0bb4 runs before the output write and receives both the original container and selected entry addresses. Its writes, global-state changes, resource operations, and ownership effects are unknown.

The caller must not infer that the dependency merely unlinks an entry, preserves globals, preserves entry storage, or leaves the container unchanged.

If the dependency invalidates the selected entry’s storage, this function has no visible mechanism to detect that fact. It can still attempt to publish the address computed from the retained entry base. That does not establish that the resulting address denotes live or usable storage.

### Aliasing and ownership

No visible check prohibits the output storage from overlapping the container, an entry field, or another accessible object. If such overlap is valid in the execution environment, the final four-byte write can alter that object after the dependency returns.

In particular, the output store is not performed early to protect it from dependency effects. A dependency write to the same storage may be overwritten by the later output write; a dependency action that makes the storage unwritable can instead prevent normal completion.

Ownership of the container, selected entry, and returned interior region is not specified. Returning an interior address does not by itself establish ownership transfer, a release obligation, or a lifetime guarantee.

## Acceptance examples

These examples are conditional acceptance criteria, not reports of executed tests. Successful cases assume that the dependency returns normally and that the output write is valid.

1. **Empty sequence.**  
   The container’s head link is null. The result is `0xFFFFFF85`; the dependency is not called, and the output storage is unchanged by this function.

2. **Immediate ordinary match.**  
   The first entry has a nonsentinel key equal to the requested key. The dependency receives the original container address and that entry’s base. The output becomes that base plus 20 bytes, and the result is zero. This function does not read the entry’s next link.

3. **Match after skipped entries.**  
   Two entries have nonsentinel, nonmatching keys, and their links lead to a third entry with the requested key. Reads proceed through each skipped entry’s key and then its link. The third entry is selected; later entries are not examined.

4. **Duplicate matching keys.**  
   Two reachable entries have the same requested nonsentinel key. The earlier entry in link-following order is selected. Only that entry is passed to the dependency by this invocation.

5. **Sentinel before a possible match.**  
   A reachable entry has key `0xFFFFFFFF`, and its next-link field would lead to an otherwise matching entry. The result is `0xFFFFFF85`. The sentinel’s next link is not read, and the later entry is not considered.

6. **Requested key is the sentinel value.**  
   The requested key is `0xFFFFFFFF`. Reaching an entry with that value produces an unsuccessful return, not a match, because sentinel recognition takes precedence over equality selection.

7. **No match before a null link.**  
   All examined entries have nonsentinel, nonmatching keys, and the last next link is null. The result is `0xFFFFFF85`, with no dependency call and no output write.

8. **Dependency changes the selected entry’s contents.**  
   A match is found, and the dependency modifies the entry while leaving the output storage writable. The stored result is still the retained entry base plus 20 bytes; this function does not recompute selection from modified fields. The validity of the returned region remains dependent on the dependency’s effects.

9. **Stable cycle without a match or sentinel.**  
   Link traversal repeats indefinitely under otherwise valid, unchanged memory. No bounded-time failure return is promised.
