# F-9f56f351b49c

## Purpose

F-9f56f351b49c performs a polling operation with status inspection, optional error reporting, and a timeout decision. Its established behavior is to return a 32-bit success value only when a status-mask condition is satisfied after the timeout check and a delay call. It returns a 32-bit failure value when a status operation fails, an error-detail operation fails, or the timeout dependency reports a nonzero result.

The diagnostic labels suggest an ATA-related status wait, including error reporting and a busy-related timeout. That interpretation is inferred intent, not a complete hardware contract. The supplied evidence does not establish device selection, register semantics, timeout units, or the meaning of every status bit.

A reported device-error bit is not itself a terminal failure. When error-detail retrieval succeeds, the function reports the detail and continues through the timeout and completion checks.

- **1:** the completion-mask branch was taken.

These are the only explicit return values in the supplied body. The result does not distinguish status-access failure, error-detail-access failure, and timeout.

A result of 1 does not establish that no device error was observed. One or more error-detail reports may precede success.

## Behavior

### Initialization and observation order

The function first initializes the local error-detail word from the third argument and the local status word from the fourth argument.

It then invokes an external dependency that returns a 32-bit token. This document calls that dependency **F-unmapped-01**. The identifier is a document-local opaque label, not a supplied cross-reference.

Only after F-unmapped-01 returns does the function read and retain the global base value. Consequently, changes that F-unmapped-01 makes to that global can affect the captured base.

The token and captured base are reused throughout the loop. The wrapper does not explicitly reacquire the token or reread the global base on later iterations. It does, however, perform a fresh read at offset 24 from the retained base on every iteration that reaches the timeout check.

### Status acquisition

Each iteration begins by calling F-03fd77b56fa0 with:

- Selector 15.
- The address of the local 32-bit status word.

The dependency’s result is tested for zero versus nonzero.

If the result is zero, the function immediately returns 0. On this branch, it performs no wrapper-level diagnostic call, timeout check, delay call, or completion-mask test for that iteration.

If the result is nonzero, processing continues using the status word’s then-current contents. The wrapper does not verify that the dependency wrote a fresh value or all 32 bits.

### Error-bit processing

The function tests bit 0 of the status word using mask 0x00000001.

If that bit is clear, error-detail retrieval and error reporting are skipped.

If that bit is set, the function calls F-03fd77b56fa0 with:

- Selector 9.
- The address of the local 32-bit error-detail word.

If this call returns zero, the function invokes F-1b7fa166ef25 with a diagnostic-message reference associated with failure to obtain error information. It then returns 0.

If this call returns nonzero, the function invokes F-1b7fa166ef25 with:

- An error-detail diagnostic-message reference.
- The error-detail word masked with 0x000000FF.

The masked diagnostic argument is numerically in the range 0 through 255. The mask does not modify the stored error-detail word. Bits 8 through 31 do not contribute to this diagnostic argument.

After this diagnostic call, the function continues; it does not return failure merely because status bit 0 was set. There is no explicit wrapper-level acknowledgement, reset, or clearing of that bit.

The complete diagnostic strings and rendering behavior are not available. Their labels support the distinction between error-detail reporting, error-detail retrieval failure, and timeout reporting, but not exact output wording.

### Timeout decision

After status acquisition and any error-bit processing, the function reads the 32-bit value at byte offset 24 from the retained base.

It calls a second external dependency, labeled here **F-unmapped-02**, with:

- The token returned by F-unmapped-01.
- The freshly read 32-bit value.

The result is tested for zero versus nonzero.

If nonzero, the function calls F-1b7fa166ef25 with the timeout diagnostic-message reference and then returns 0.

If zero, the function proceeds to the delay call.

This ordering gives the timeout result precedence over the completion-mask condition. Even a status word with both completion-mask bits clear cannot produce success if F-unmapped-02 returns nonzero on that iteration.

The evidence does not establish whether F-unmapped-02 measures elapsed time, compares counters, or interprets a duration. Only its placement, arguments, and result-dependent branch are established.

### Delay and completion decision

When F-unmapped-02 returns zero, the function calls F-233fe84cf225 with the numeric argument 50.

The unit and exact effect of 50 are unknown. The wrapper does not inspect that call’s result.

After the call returns, the function tests the local status word using mask 0x00000088, selecting bits 7 and 3:

- If both selected bits are clear, it returns 1.
- If either selected bit is set, it starts another iteration.

The wrapper performs no explicit fresh status acquisition between the delay call and this test. Normally, the tested word would therefore be the one obtained earlier in the iteration. That relationship is conditional on intervening dependencies not changing the exposed local storage through retained aliases or other applicable side effects.

The delay call occurs even on an iteration that ultimately returns 1. Completion is not checked before that call.

### Repetition and termination

Each repeated iteration begins with another selector-15 call.

The function has no explicit iteration limit. Termination depends on a dependency reporting failure, the timeout dependency returning nonzero, or the completion-mask condition becoming satisfied.

If status acquisition continues succeeding, the timeout dependency continues returning zero, and either bit 7 or bit 3 remains set at every completion test, the function continues indefinitely.

## Side effects

The function can expose the following observable activity:

1. A call to F-unmapped-01.
2. A read of the global base value.
3. Repeated selector-15 calls that receive writable local storage.
4. Conditional selector-9 calls that receive separate writable local storage.
5. Conditional diagnostic calls.
6. Repeated 32-bit reads at offset 24 from the captured base.
7. Timeout-decision calls using those read values.
8. Calls to F-233fe84cf225 with argument 50.

The wrapper contains no explicit global-memory write, allocation, release, or device-register write. This does not imply that its dependencies lack those effects.

No ownership transfer is established for the token, captured base, diagnostic-message references, or local destination addresses. The function makes no explicit cleanup call on any exit path. Whether the external token represents a resource requiring cleanup cannot be determined from the supplied evidence.

The captured base fixes the address used for subsequent offset-24 reads; it does not freeze the contents at that address. Dependency-induced changes to that field can affect later timeout decisions. Changes to the original global base do not, by themselves, change the already captured base.

No locking, atomicity, volatile-access semantics, or reentrancy guarantee is established.

## Acceptance examples

These are conditional acceptance cases derived from static control flow, not executed tests. Unless a case says otherwise, assume dependencies return normally and do not unexpectedly alter exposed local storage.

### Immediate status-operation failure

If the first selector-15 call returns zero, the expected result is 0.

F-unmapped-01 and the global-base read have already occurred. No wrapper-level diagnostic, offset-24 read, timeout call, or delay call follows that failed status operation.

### Immediate completion

Suppose selector 15 succeeds and leaves a status word of 0, and F-unmapped-02 returns zero.

The function calls F-233fe84cf225 with 50 and then returns 1. It does not retrieve error detail or emit a wrapper-level diagnostic.

### Reported error followed by success

Suppose selector 15 succeeds with status 0x00000001, selector 9 succeeds with error detail 0x123456AB, and F-unmapped-02 returns zero.

The function reports error detail 0xAB, calls F-233fe84cf225 with 50, and returns 1. Bit 0 does not participate in the final mask.

### Error-detail retrieval failure

Suppose selector 15 succeeds with bit 0 set, but selector 9 returns zero.

The function emits the error-detail retrieval failure diagnostic and returns 0. It does not perform that iteration’s offset-24 read, timeout call, or delay call.

### Timeout takes precedence over completion

Suppose selector 15 succeeds with status 0 and F-unmapped-02 returns nonzero.

The function emits the timeout diagnostic and returns 0 without calling F-233fe84cf225. The clear completion mask does not override timeout.

### Two diagnostics in one iteration

Suppose status bit 0 is set, error-detail retrieval succeeds, and the timeout dependency then returns nonzero.

The error-detail diagnostic occurs first, followed by the timeout diagnostic. The result is 0, and no delay call occurs.

### Either selected bit causes repetition

With successful status acquisition and a zero timeout result, status 0x00000008 or 0x00000080 causes a delay call followed by another iteration.

A status value such as 0x80000000 does not itself prevent success: its bit is outside mask 0x00000088.

### Success without destination replacement

If selector 15 returns nonzero without writing its destination, the existing status value remains relevant. On the first iteration, that is the fourth argument.

Similarly, if selector 9 reports success without writing its destination, the low eight bits of the existing error-detail word are reported. Initially, those bits come from the third argument.
