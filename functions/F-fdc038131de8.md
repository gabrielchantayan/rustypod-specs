# F-fdc038131de8

## Purpose

F-fdc038131de8 performs a synchronous, two-stage transfer controlled by status bits. It waits for one status condition, copies a 16-bit value from the first argument to the second argument, waits for another status condition, and replaces that destination value with a 16-bit value read from a base-relative location. Normal completion returns a 32-bit zero.

The status and data offsets suggest a device-register transaction. That interpretation is **inferred intent**, not established hardware semantics. The established behavior is the sequence of status reads, one argument-based data read, and two destination writes.

An important distinction is that the function captures a base value before waiting, but the first wait obtains its base from the shared base slot on each represented evaluation. The second wait and final data read use the captured value. These need not refer to the same region if the shared base slot changes.

## Interface

### Arguments

The function takes two pointer arguments:

- **Source pointer:** identifies a location from which one 16-bit value is read after the first wait succeeds.
- **Destination pointer:** identifies a location written twice, with a wait between the writes. Each write is 16 bits.

The source pointer does not supply an address for the final read. That read uses the captured base and a fixed offset.

No length, timeout, cancellation token, or error-reporting pointer is supplied. No null-pointer, alignment, accessibility, or overlap checks are shown.

### Result

The represented return type is 32 bits. Every normal return supplies zero.

Zero does not independently establish that a device operation succeeded. It establishes only that control passed both polling conditions and reached the return after the final write. There is no separate failure return in the supplied representation.

### Shared state and layout

The function reads a shared slot containing a base value. The relevant base-relative layout is:

| Offset from a base | Access width | Use |
|---|---:|---|
| 0x78, or 120 bytes | 32 bits | Status polling |
| 0x7c, or 124 bytes | 16 bits | Final data read |

The two tested status masks are:

- First wait: mask 0x00000002, selecting bit 1.
- Second wait: mask 0x00000001, selecting bit 0.

A wait succeeds when its selected bit is nonzero. Other bits do not affect that wait's decision.

The representation uses a 32-bit integer carrier for the captured base. It does not establish a portable pointer model or define behavior for every possible bit pattern in the shared base slot.

### Preconditions for normal completion

Normal completion requires all accesses actually reached to be valid in the execution environment:

- The shared base slot must be readable.
- The first wait's selected status addresses must permit 32-bit reads.
- The captured base's status address must permit 32-bit reads.
- The captured base's data address must permit a 16-bit read.
- The source must permit a 16-bit read.

Any required alignment and device-access rules must also be satisfied. They are not checked here.

Both waits must eventually observe their selected bit set. Without that condition, normal completion is not guaranteed.

## Behavior

### 1. Capture the base

Before the first wait, the function reads the shared base slot and retains that value for later use.

This captured value determines:

- The status address used by the second wait.
- The data address used by the final 16-bit read.

Subsequent changes to the shared base slot do not replace this captured value within the represented operation.

### 2. Wait for status bit 1

The first wait repeatedly evaluates the following condition: the 32-bit status value at offset 0x78 from the base currently obtained from the shared base slot must have bit 1 set.

The supplied representation contains a fresh reference to the shared base slot in this polling expression rather than a reference to the captured base. Accordingly, the represented behavior permits successive evaluations to address different status locations if that slot changes.

This distinction concerns the supplied access expressions. Whether an actual compiled execution reloads shared memory on every iteration depends on access qualifiers, compilation, and the platform memory model, none of which are supplied.

The wait:

- Performs at least one status evaluation.
- Continues while bit 1 is clear.
- Ignores every other status bit when deciding whether to continue.
- Has no shown delay, retry limit, timeout, cancellation check, or error branch.

The source value has not yet been read and no explicit destination write has yet occurred.

### 3. Copy the source value to the destination

Once the first wait succeeds, the function reads 16 bits through the source pointer and writes that value through the destination pointer.

The source value is sampled at this stage, not when the function begins. Changes to source storage during the first wait can therefore affect the value copied.

No arithmetic, byte swapping, masking, sign extension into a larger stored object, or other transformation of this 16-bit value is shown.

This is an actual intermediate write in the represented behavior. It must not be treated as absent merely because a later write targets the same destination. A device, concurrent observer, or aliased status location may react to it.

### 4. Wait for status bit 0 using the captured base

After the first destination write, the function repeatedly reads the 32-bit status location at offset 0x78 from the captured base.

This wait ends when bit 0 is set. Bit 1 is not tested here, and the function does not require both status bits to be set simultaneously.

Like the first wait, this wait performs at least one status evaluation and has no shown timeout, delay, cancellation, or explicit failure path.

If this wait does not finish, the first destination write has already occurred, but the final data read and second destination write have not.

### 5. Read captured-base data and overwrite the destination

After the second wait succeeds, the function reads 16 bits at offset 0x7c from the captured base and writes those bits through the destination pointer.

The final read is distinct from the status read. A value observed in the status location does not supply the final data value.

For an ordinary stable destination with no competing writes, its value after this step is the value obtained from the captured-base data location. The earlier source-derived destination value has been overwritten.

### 6. Return

The function returns a 32-bit zero after the second destination write.

There is no shown cleanup, restoration, validation of the final value, or comparison between the two values written.

## Acceptance examples

These examples are conditional contracts, not reported executions.

### Both status conditions are immediately satisfied

Given valid accesses, a stable base, bit 1 set on the first first-stage status evaluation, and bit 0 set on the first second-stage evaluation:

- The function performs the source read and first destination write.
- It then performs the captured-base data read and second destination write.
- It returns zero.

For ordinary memory without competing writers, the final destination contains the captured-base data value, not necessarily the source value.

### First condition remains false

If every first-stage status evaluation observes bit 1 clear:

- The function remains in the first wait.
- It does not explicitly read the source.
- It performs neither destination write.
- It does not return.

This does not imply that polling reads have no external effects.

### Second condition remains false

If the first wait succeeds but every second-stage evaluation observes bit 0 clear:

- The source-derived destination write occurs.
- The function remains in the second wait.
- It does not perform the final data read or final destination write.
- It does not return.

### Shared base changes between stages

Suppose the initial capture obtains base A, but a later first-stage evaluation obtains base B from the shared slot.

If the first wait succeeds using B, the subsequent second wait and final data read still use A. Acceptance must not require both stages to use B or require the first stage to remain on A.

### Source changes during the first wait

If the source initially contains one value and changes before the first wait finishes, the copied value is the value actually read after that wait. The interface does not promise a source snapshot at entry.

### Unrelated status bits are set

A status value with bit 0 set but bit 1 clear does not satisfy the first wait. A status value with bit 1 set but bit 0 clear does not satisfy the second wait.

### Intermediate write affects readiness

If the destination is a device endpoint whose first write causes bit 0 at the captured status location to become set, the sequence permits that interaction: the first destination write precedes all second-stage polling evaluations. The device-specific causal behavior remains external to this contract.
