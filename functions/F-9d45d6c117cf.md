# F-9d45d6c117cf

## Purpose

F-9d45d6c117cf coordinates a three-dependency lookup operation and publishes a two-word result: a selected table-entry address and a 32-bit value.

The operation first obtains an intermediate result from F-58cc241cfb6b, then invokes F-d7be9cfb4000. A secondary machine-level result associated with that second call determines an initial table-entry address. F-347fcc605342 evaluates that address and supplies a candidate value. A nonzero candidate is accepted directly. A zero candidate triggers a fallback that selects another table entry and reads its value.

The selected address and value are both written to caller-supplied output storage and packed into the function’s 64-bit return value.

This describes the established static behavior. The application-level meanings of the object, entries, candidate values, and fallback selector are not established.

## Interface

### Inputs

The function has four inputs:

| Input | Established representation | Required accessible storage |
|---|---|---|
| Output destination | Pointer to 32-bit words | At least two writable words for the final result |
| Context address | 32-bit address-bearing value | Readable fields at byte offsets 4, 20, and 24, when their respective reads occur |
| Input-pair address | Pointer to 32-bit words | At least two readable words before the first dependency call |
| Auxiliary value | Opaque 32-bit value | No local dereference |

The output destination, context address, input-pair address, and auxiliary value are also forwarded to dependencies as described below. Those dependencies may impose additional requirements not established here.

### Context layout

Only these context fields have visible local uses:

| Byte offset | Width | Local use |
|---|---:|---|
| 4 | 32 bits | Displacement added to the context address to form the first argument to F-58cc241cfb6b |
| 20 | 32 bits | Base address used to construct a table-entry address |
| 24 | 32 bits | Argument to F-d7be9cfb4000; separately reread as the fallback selector when fallback occurs |

The two uses of the field at offset 24 are distinct reads at different times. They need not observe the same value if an intervening dependency modifies the context.

The displacement at offset 4 is used to form an address. This function does not itself dereference that formed address.

### Outputs

The destination receives:

| Byte offset | Width | Result |
|---|---:|---|
| 0 | 32 bits | Selected table-entry address |
| 4 | 32 bits | Selected value |

The return value is 64 bits:

- Bits 31–0 contain the selected address’s 32-bit representation.
- Bits 63–32 contain the selected value’s 32-bit representation.

This is a bitwise packing contract. A selected value with its top bit set remains that same 32-bit pattern in the upper half; the return is not a sign-extended version of the value alone.

No byte order for the in-memory representation of the 64-bit return is established by this packing description.

## Behavior

### Initial dependency invocation

Before invoking F-58cc241cfb6b, the function obtains:

- The 32-bit displacement at context byte offset 4.
- The first 32-bit word of the input pair.
- The second 32-bit word of the input pair.

The relative order of those reads is not established by the supplied call expression. All supply values to the first call.

F-58cc241cfb6b receives eight positional arguments:

1. The context address plus its displacement field.
2. The context address.
3. The captured first input-pair word.
4. The captured second input-pair word.
5. The output destination address.
6. The context address again.
7. The input-pair address.
8. The auxiliary value.

The repeated context argument and the simultaneous forwarding of input-pair contents and its address are part of the visible interface. The contract does not collapse them into a single logical argument.

The first dependency produces a 32-bit result used by the next dependency. Its internal effects are unknown. In particular, the forwarded pointers mean that later context reads cannot safely be treated as having the same values as earlier reads.

### Secondary result and initial entry selection

After F-58cc241cfb6b returns, the function reads the context field at byte offset 24 and invokes F-d7be9cfb4000 with:

1. The 32-bit result from F-58cc241cfb6b.
2. The newly read context field.

The ordinary result of F-d7be9cfb4000 is not visibly used. Instead, the supplied representation exposes a secondary result-register value after that call. That value is multiplied by four and added to the table-base field read at context byte offset 20.

The resulting address is the initial selected entry address.

The factor of four establishes a four-byte entry stride. It does not establish that the secondary result is nonnegative, within a valid table range, or an application-level index. Those properties depend on an unavailable dependency and calling-convention contract.

This function does not directly read the initial entry’s contents before the next call. It passes the entry address to F-347fcc605342.

### Candidate evaluation

F-347fcc605342 receives three positional arguments:

1. The context address.
2. The initial selected entry address.
3. The input-pair address.

Its 32-bit result controls selection:

- If the result is nonzero, the initial entry address remains selected, and that result becomes the selected value.
- If the result is zero, fallback selection occurs.

Every nonzero 32-bit pattern takes the direct path. The test does not require a positive signed value. For example, a result whose bits are all ones takes the direct path.

The dependencies’ names and surrounding structure do not establish whether F-347fcc605342 validates, searches, converts, or mutates an entry. Only its arguments and the zero-versus-nonzero decision are established.

### Fallback selection

When the candidate is zero, the function rereads:

- The context’s table-base field at byte offset 20.
- The context’s selector field at byte offset 24.

The fallback address is the newly observed table base plus four times the newly observed selector. The relative order of these two reads is not established.

The function then directly reads one 32-bit value from the fallback address. That address and that value become the selected result.

Consequences:

- The fallback can use a different table base from the initial selection if F-347fcc605342 changed the context.
- The fallback selector can differ from the value passed earlier to F-d7be9cfb4000.
- The fallback value is accepted without another zero check.
- A zero fallback value is therefore a normal locally produced result, not a request for another fallback.
- The fallback entry is not passed through F-347fcc605342.

If F-347fcc605342 returns nonzero, the function does not perform these fallback field reads or the direct fallback-entry read.

### Publication

Once the selected address and value have been determined, publication occurs in this order:

1. Write the selected address to the first output word.
2. Write the selected value to the second output word.
3. Return their 64-bit packed representation.

The selected value has already been obtained before either final output write. If the output storage aliases the selected table entry, the final stores can overwrite table storage, but they do not cause a new read of the selected value.

The final stores are not an atomic two-word publication. No synchronization or concurrent-reader guarantee is established.

## Side effects

### Directly established effects

The function directly:

- Reads the two input-pair words before the first dependency call.
- Reads context fields at the stages described above.
- Reads one table word only on the fallback path.
- Writes two consecutive 32-bit output words on normal completion.
- Calls the three dependencies in the order listed in the Dependencies section.

There is no visible local allocation, release, reference-count operation, or ownership transfer. This absence does not establish that the dependencies perform none.

### Dependency-mediated effects

The first dependency receives the output destination, context address, and input-pair address. The third receives the context address, selected entry address, and input-pair address.

Their effects on reachable memory, globals, resources, and external state are unknown. No preservation guarantee is established. Even F-d7be9cfb4000, which receives no explicit pointer from this function other than whatever its argument bits may represent, cannot be assumed to preserve globals.

There is no rollback around dependency calls or final writes. If execution fails after a dependency has changed state, this function provides no visible mechanism to restore it.

### Preconditions and errors

There are no visible null checks, bounds checks, alignment checks, or arithmetic-overflow checks.

Successful execution requires valid memory for each access when that access occurs, including any fallback entry read. Dependencies may require more.

A zero candidate is a branch condition, not an established error code. No separate local error result is produced. Invalid addresses, inaccessible storage, unsuitable alignment, dependency failure, and abnormal control transfer have no locally defined recovery behavior.

Aliasing is not explicitly rejected. However, aliasing output, context, input-pair, or table storage can expose dependency writes and final output stores through multiple views. The contract provides ordering, not an assurance that such aliasing is harmless.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid accessible memory and the stated dependency behavior.

### Nonzero candidate

Suppose the table base observed after F-d7be9cfb4000 is address `0x00001000`, and its secondary result corresponds to index 3. The initial entry address is `0x0000100C`.

If F-347fcc605342 returns 7:

- The selected address is `0x0000100C`.
- The selected value is 7.
- No fallback entry is directly read by this function.
- The output words are `0x0000100C` and `0x00000007`.
- The packed return is `0x000000070000100C`.

### Zero candidate with nonzero fallback

Suppose F-347fcc605342 returns zero. At fallback time, the context contains table base `0x00002000` and selector 5, and the word at `0x00002014` is 42.

The selected address is `0x00002014`, the selected value is 42, and the packed return is `0x0000002A00002014`.

The earlier table base and earlier selector do not determine this fallback result.

### Zero fallback value

Under the same fallback conditions, if the word at `0x00002014` is zero, the function publishes that address with value zero and returns `0x0000000000002014`. No additional selection is attempted.

### Top-bit-set candidate

If F-347fcc605342 returns the 32-bit pattern `0xFFFFFFFF`, the direct path is taken. That pattern occupies the upper 32 bits of the packed return. It is not treated as zero or replaced by a fallback value.

### Context mutation during evaluation

If F-347fcc605342 changes the table-base and selector fields and then returns zero, fallback uses the changed fields. If it makes the same changes but returns nonzero, the selected address remains the initial address computed before that call.
