# F-26bbe9362b4d

## Purpose

F-26bbe9362b4d conditionally records a supplied 32-bit value in an object. When an initial object byte is zero, it also records an input byte, obtains a handle, performs dependency calls, initializes temporary storage, and conditionally invokes another dependency before recording the 32-bit value.

Two paths are established:

- **Nonzero initial gate:** write the supplied 32-bit value at object offset `0x104` and return without dependency calls.
- **Zero initial gate:** write the supplied byte at offset `0x108`, perform the dependency sequence described below, conditionally dispatch, write the supplied 32-bit value at offset `0x104`, and pass temporary storage to a final dependency.

The business meanings of the fields, handle, mode, and dependency operations are not established. “Lookup,” “construction,” “dispatch,” and “finalization” below describe apparent roles, not verified callee semantics.

## Behavior

### Initial gate

The first direct memory access reads one byte at object offset `0x10C`.

If that byte is nonzero, the function writes the recorded value as 32 bits at object offset `0x104` and returns immediately. It performs no dependency calls and does not write offset `0x108`, inspect context fields, sample the displacement global, or perform the conditional 16-bit read.

The gate is not visibly reread. Its initial observation selects the path for this invocation.

### Ordinary-path setup and handle processing

If the initial gate is zero, the function writes the recorded byte at object offset `0x108` before calling any dependency.

It then invokes F-1f46730b1ced with the address of the object’s embedded region at offset `0xD4` and the recorded 32-bit value. The returned 32-bit handle is retained and compared with zero.

A zero result causes a call to F-a817d8d58c10 with no visible arguments. The supplied listing marks this dependency as non-returning. Under that annotation, execution does not reach temporary construction, optional dispatch, the later write at offset `0x104`, or finalization. The earlier write at offset `0x108` has already occurred.

For a nonzero handle, the following dependency sequence occurs:

1. F-d2f99870cc43 receives the retained handle and supplies a 32-bit result.
2. F-bf557f07179f receives the original object address and that result.
3. F-fa8898fa75ae receives the retained handle.

The handle’s retained bits are subsequently passed to dispatch if dispatch occurs. This establishes only reuse of the same value. It does **not** establish that F-fa8898fa75ae preserves the referenced resource, leaves ownership unchanged, or permits safe subsequent use. Invalidation, release, ownership transfer, or another change to the resource remain possible; later dispatch may receive a stale value.

### Context sampling and temporary construction

After F-fa8898fa75ae returns, the function obtains construction inputs through two distinct calls to F-fdd8589eca2d:

- The first call returns an address. The function reads one byte at that address plus `0x2C` and retains the byte.
- The second call returns an address. The function reads 32 bits at that address plus `0x28`.

The second call occurs after the first byte has been read. The two returned addresses need not be equal. A change to the first context during the second call does not cause the previously sampled byte to be reread.

F-2c5a9f9c1eb3 then receives, in order:

- The address of the 92-byte local storage region.
- The 32-bit field sampled through the second context result.
- The byte sampled through the first context result.

No explicit clearing or initialization of the local storage precedes this call. The dependency’s writes, initialized extent, internal representation, and resource effects are unknown.

### Mode and optional dispatch

After construction returns, F-5c5958cfd5fe is called. Its result is compared with the exact value `8`.

If the result equals `8`, execution skips dispatch preparation and dispatch itself. In particular, there is no third F-fdd8589eca2d call, no displacement-global read, and no conditional 16-bit object read.

For every other result, the suppression selector determines preparation:

- **Nonzero suppression selector:** call F-fdd8589eca2d a third time and select a 16-bit zero auxiliary value. Do not read the displacement global or the displaced object location.
- **Zero suppression selector:** call F-fdd8589eca2d a third time, then test the dispatch argument.
  - If the dispatch argument is zero, select a 16-bit zero auxiliary value without reading the displacement global or the displaced object location.
  - If the dispatch argument is nonzero, read the referenced displacement global **after the third context call returns**. Combine that sampled displacement with the original object address, then read 16 bits from the resulting address. Those 16 bits become the auxiliary value.

Thus, on the eligible sampling path, the established order is: third context call, global displacement read, displaced 16-bit read, dispatch call.

An entry-time displacement or a value cached before the third context call is not an equivalent observation when intervening dependencies can change the global. The object data is likewise sampled after that call, not at function entry. No dependency is assumed to preserve either storage location.

F-818c773e8c8a receives, in order:

1. The third context result.
2. The local temporary-storage address.
3. The retained nonzero handle bits.
4. The original 32-bit dispatch argument.
5. The selected 16-bit auxiliary value.

A nonzero suppression selector suppresses the global and 16-bit reads, not dispatch. A zero dispatch argument also does not suppress dispatch when mode differs from `8`.

No result from F-818c773e8c8a is visibly consumed.

### Completion

After dispatch returns, or immediately after the mode-`8` skip, the function writes the original recorded value as 32 bits at object offset `0x104`.

Only then does it call F-920630e53283 with the local temporary-storage address. The function returns when that dependency returns.

This is an ordering guarantee, not an unconditional final-state guarantee:

- Dispatch runs before this function’s ordinary-path write at offset `0x104`.
- Finalization runs after that write.
- If finalization can modify the object, offset `0x104` need not still contain the recorded value when the function returns.

There is no visible rollback, retry, or alternate cleanup path. Cleanup following an exception, nonlocal exit, termination, or other failure to return is not established.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless specified otherwise, they assume valid accessed storage and normally returning dependencies.

### Nonzero gate

Given a nonzero byte at object offset `0x10C`, the function must write the recorded value at offset `0x104` and return without dependency calls. It must not directly write offset `0x108` or read the displacement global.

### Zero handle

Given a zero initial gate and a zero result from F-1f46730b1ced, the byte write at offset `0x108` must precede F-a817d8d58c10. Under its non-returning annotation, no later phase is reached. The function has not performed its ordinary-path write at offset `0x104`.

### Mode exactly `8`

Given a nonzero handle and mode `8`, construction must occur, followed by the recorded-value write and finalization. The third context call, displacement sampling, displaced 16-bit read, and dispatch must all be omitted.

### Dispatch with zero auxiliary data

Given mode other than `8` and a nonzero suppression selector, the third context call and dispatch must occur. Dispatch receives a zero auxiliary value; neither the displacement global nor the displaced 16-bit location is read.

The same omitted reads and zero auxiliary value apply when the suppression selector and dispatch argument are both zero. Dispatch still receives the original dispatch argument.

### Displacement changed by the third context call

Given mode other than `8`, a zero suppression selector, and a nonzero dispatch argument, suppose the third context call changes the displacement global to a different usable value.

The subsequent 16-bit read must use the displacement sampled after that call. Using an earlier displacement would not match the established ordering. Dispatch receives the 16-bit value read at the newly selected address.

### Object data changed before sampling

Under the same eligible conditions, suppose the third context call changes the 16-bit data at the address selected by the subsequently sampled displacement. The function must read that data after the context call and global read, rather than reuse an entry-time sample.

### Distinct construction contexts

If the first two context calls return different addresses, construction must receive the byte from the first result’s offset `0x2C` and the 32-bit value from the second result’s offset `0x28`.

### Handle invalidation remains possible

If F-fa8898fa75ae invalidates the referenced resource but returns normally, the established call sequence still passes the retained handle bits to dispatch when mode permits. This example specifies value reuse, not safe resource use or successful dispatch.

### Commit ordering

If dispatch inspects offset `0x104`, this function has not yet performed its ordinary-path recorded-value write there. If finalization inspects that offset, the write has already occurred. Dependency mutations can affect either observation.
