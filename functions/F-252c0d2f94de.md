# F-252c0d2f94de

## Purpose

F-252c0d2f94de classifies an input record and conditionally dispatches operations on a mutable receiver. It returns a 32-bit status whose observed values are 0 and 1.

The established behavior has three categories:

- Two record kinds are accepted unconditionally and may trigger one of three operations when a receiver flag is set.
- Two other record kinds are accepted without invoking an operation.
- One record kind is accepted only when receiver fields and record fields satisfy one of two matching rules. Each successful rule invokes a different indirect operation.

All other kinds are rejected, subject to the repeated kind read described below.

“Accepted” means that the function returns 1. It does not necessarily mean that it invokes a dependency or modifies the receiver. Interpreting this function as an event handler, and its result as an event-consumption indicator, is inferred intent rather than an established interface guarantee.

## Interface

### Arguments and result

The function takes two arguments:

1. **Receiver:** a pointer to mutable, word-addressed state.
2. **Record address:** a 32-bit address-valued argument used to access a record.

The visible representation uses 32-bit integer words and byte-addressed offsets. No argument is validated for nullness, address validity, object type, alignment, or available storage.

The result is a 32-bit value:

- **1:** an acceptance path completed normally.
- **0:** no acceptance path matched.

No other normal result is visible. A dependency fault, invalid indirect call, or inaccessible memory is not converted into a return value.

### Record layout used by this function

Offsets are in bytes from the record address.

| Offset | Width | Role |
|---|---:|---|
| 0x04 | 32 bits | Kind discriminator |
| 0x08 | 32 bits | First matching field |
| 0x0C | 32 bits | Second matching field |

The first word of the record is not visibly accessed. The matching fields are accessed only on the branch whose later kind read equals 0x13.

### External state

Two distinct external 32-bit values participate in matching:

- **Primary alternative:** an alternate accepted value for the record’s first matching field.
- **Secondary comparison value:** the value required for that field on the secondary path.

These labels distinguish observable roles, not ownership or mutability guarantees. Neither value is written directly by this function.

## Behavior

### 1. Initial kind read

The function first reads the 32-bit kind at record offset 0x04.

If that value is 6 or 7, it follows the command-dispatch path below and returns 1 after any invoked dependency returns normally. It does not inspect either matching field.

If the value is 0x0D or 0x15, it returns 1 without inspecting receiver state or invoking a dependency.

For any other initial value, the function reads the kind at offset 0x04 again. If this second read is not 0x13, it returns 0. Otherwise, it performs the matching procedure.

Thus, the supplied evidence contains two kind reads on this latter path. They must not be described as one cached read. For stable record storage, both yield the same value. If the storage can change between reads, the later read controls entry into matching; no synchronization or supported concurrent-access protocol is established.

### 2. Command dispatch for initial kinds 6 and 7

The function reads the 32-bit receiver word at offset 0x118 and tests its low eight bits for zero.

If those bits are zero, it returns 1 without calling the command selector.

If they are nonzero:

1. It invokes F-11c1b7e655b3 with no visible arguments.
2. It compares the returned 32-bit value against three constants:
   - **0x57:** invoke F-5edeb7e9c4e0 with the receiver.
   - **0x58:** invoke F-b5a7190f43fd with the receiver.
   - **0x6F:** write zero to the single byte at receiver offset 0x118, then invoke F-f75928eeb9bc with the receiver.
3. It returns 1 after the selected dependency returns normally, or immediately if none of the three values matched.

Only one selected operation can be invoked during this dispatch. A selector result other than the three listed values still produces a return of 1.

The gate is tested before F-11c1b7e655b3 runs and is not visibly checked again afterward. Changes made by that dependency do not cause the function to repeat the gate decision.

The zero store precedes F-f75928eeb9bc. It is a one-byte store, not a full-word assignment. No guarantee is made that the byte remains zero after the dependency returns.

### 3. Matching for a later kind read of 0x13

#### Primary match

The function reads the record’s second matching field at offset 0x0C and retains that value.

It then reads the receiver’s primary expected second field at offset 0x44. If the two values differ, it skips the remaining primary checks.

If they are equal, it:

1. Reads the record’s first matching field at offset 0x08.
2. Reads the receiver’s primary expected first field at offset 0x40.
3. Accepts the first field if it equals that receiver value.
4. If it does not equal the receiver value, reads the external primary alternative and accepts the field if it equals that alternative.

A successful primary match loads the receiver’s dispatch-table address and invokes the operation at table offset 0xD4, passing the receiver. After normal return from that operation, this function returns 1.

The primary alternative is not visibly read when the first field already matches the receiver’s primary expected value. It is also not read when the second field fails its primary comparison.

A successful primary match terminates processing. The secondary enable field and secondary comparison value are not then consulted.

#### Secondary match

If the primary match does not succeed, the function reads the receiver word at offset 0x9C.

If that word is zero, it returns 0.

If it is nonzero, the function compares the previously retained record second field against the receiver word at offset 0x98.

If those values differ, it returns 0 without reading the secondary comparison value or rereading the record’s first field.

If they are equal, it:

1. Reads the record’s first matching field at offset 0x08.
2. Reads the external secondary comparison value.
3. Compares those two 32-bit values.

If they differ, it returns 0.

If they match, it:

1. Invokes F-5710a8628cba with no visible arguments.
2. Retains a one-byte result from that invocation.
3. Loads the receiver’s dispatch-table address and the operation at table offset 0xA0.
4. Invokes that operation with the receiver and the retained byte.
5. Returns 1 after normal return from the indirect operation.

The dispatch-table lookup occurs after F-5710a8628cba. Its target must not be assumed to be the target that would have been found before that dependency ran.

### 4. Width and arithmetic constraints

The visible comparisons use complete 32-bit values except for the command gate and the one-byte dependency result.

There is no range comparison, scaling calculation, counter update, or explicit numeric overflow operation. Address formation uses fixed byte offsets. Validity of those address calculations is a caller or environment precondition, not something checked by the function.

Testing whether the low eight bits are zero does not depend on whether an eight-bit character is signed. However, the relationship between those low bits and the byte stored at receiver offset 0x118 depends on target byte order. The source establishes the low-bit test and byte-addressed store separately; it does not establish byte order.

## Side effects

The only direct memory write visible in this function is the one-byte zero store at receiver offset 0x118 for selector result 0x6F.

Additional effects may occur through:

- F-11c1b7e655b3;
- F-5edeb7e9c4e0;
- F-b5a7190f43fd;
- F-f75928eeb9bc;
- F-5710a8628cba;
- either indirect receiver operation.

Their effects are not bounded by this function’s body. They must not be assumed to preserve receiver storage, external state, dispatch tables, record storage, or memory ownership.

No direct allocation, release, reference-count adjustment, or record write is visible. This absence does not establish that dependencies neither allocate nor release memory.

The function contains no visible rollback. If the byte is cleared and the following dependency fails to return normally, the visible sequence contains no restoration of that byte.

Callers must ensure that every region accessed on the selected path is valid for the required access. If a dependency invalidates storage subsequently accessed by this function, the supplied evidence provides no recovery behavior.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, memory is stable and valid, and all invoked dependencies return normally.

1. **Kind 6 with a disabled command gate**  
   The low eight bits of the receiver word at offset 0x118 are zero. The result is 1. F-11c1b7e655b3 is not invoked.

2. **Kind 7 selecting 0x57**  
   The gate is nonzero and F-11c1b7e655b3 returns 0x57. F-5edeb7e9c4e0 receives the receiver once, and the result is 1.

3. **Clear-before-operation command**  
   Kind is 6, the gate is nonzero, and the selector returns 0x6F. The byte at receiver offset 0x118 is set to zero before F-f75928eeb9bc is invoked. The result is 1; the final byte value depends on that dependency’s effects.

4. **Unrecognized selector result**  
   Kind is 7 and the enabled selector returns a value other than 0x57, 0x58, or 0x6F. None of the three command operations is invoked. The result remains 1.

5. **Unconditional acceptance**  
   Initial kind is 0x0D or 0x15. The result is 1 without a receiver-state read.

6. **Unrecognized stable kind**  
   Both kind reads yield 0x12. The result is 0, and neither matching field is inspected.

7. **Primary direct match**  
   Kind is 0x13. Both record matching fields equal their corresponding primary receiver fields. The operation at table offset 0xD4 is invoked, the result is 1, and neither external comparison value is required.

8. **Primary alternative match**  
   The second field matches the primary expected second field. The first differs from the receiver’s primary expected first field but equals the external primary alternative. The primary indirect operation runs, and the result is 1.

9. **Secondary match after primary failure**  
   The primary match fails. The secondary enable word is nonzero, the retained second field matches receiver offset 0x98, and the first field matches the external secondary comparison value. F-5710a8628cba runs before the table-offset-0xA0 operation; its retained byte is passed to that operation. The result is 1.

10. **Disabled secondary matching**  
    The primary match fails and receiver offset 0x9C contains zero. The result is 0, even if the record would otherwise satisfy the secondary comparisons.

11. **Primary precedence**  
    Both match rules would succeed under stable state. Only the primary operation runs. F-5710a8628cba and the secondary operation are not invoked.
