### Loop initialization and transitions

F-D48’s unsigned result, restricted to its low 30 bits and logically shifted right 25, establishes the initial unsigned loop state. Its range is 0–31.

F-D49 receives twice that state. F-D50 supplies the first argument for the initial F-D51 call without a left shift. F-D51’s second argument is the current unsigned loop state logically shifted right eight, so it is zero on initial entry.

Each loop iteration has three observable interaction regions:

- F-D51 through F-D55 precede the iteration’s selector pair.
- The selector pair freshly reads the loop selector address and writes zero at the selected absolute destination.
- F-D56 through F-D60 follow that pair.

F-D56 receives F-D55’s integer result shifted left two.

F-D60 supplies two distinct updates for the next iteration:

- Its result shifted left two becomes the next F-D51 first argument.
- Its result separately shifted left 26 is assigned to the unsigned loop state.

The second update is not a shift of the already shifted first argument. Assignment to unsigned state does not establish that the preceding integer left shift was defined.

Under a conditional 32-bit bit-vector interpretation of those operations, F-D60’s low six bits determine the next unsigned state. After the subsequent logical right shift by eight, those bits occupy positions 18–23 of F-D51’s second argument. This bit interpretation is not an unconditional requirement for an unspecified integer model.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes the relevant operations are reached and their accesses, calls, arithmetic, and conversions permit continuation.

1. **Unsigned address wrapping.** A first input of 2,147,483,648 gives initial word-store address 20 and stored value 2,147,483,648. The prefix selector address is one.

2. **Absolute selection.** A selector byte of 200 directs its paired write to absolute address 217, regardless of the selector-read address.

3. **Fresh selection and ordering.** If the first selector read yields three and a dependency changes that selector to nine before the next read, the pairs target addresses 20 and 26 respectively. Reusing the first destination would violate the contract.

4. **Reused word destination.** F-D14 result three gives destination 68. The direct stores there supply 12 and later 48, with the second store occurring after F-D19. Intervening dependency writes are permitted.

5. **Conditional character conversion.** F-D24 result 64 produces unsigned shifted value 256. With bit-preserving integer conversion and low-eight-bit-preserving character storage, the first selector write stores zero. F-D24 result 1,048,576 produces second-selector pre-conversion value one.

6. **Conditional direct byte.** F-D36 result 65 produces unsigned shifted value 260. Under the required conversions, the direct character store writes four at the fourth-input index plus 28, before the following selector read.

7. **Initial loop arguments.** An all-one F-D48 result produces initial state 31 and F-D49 argument 62. Initial F-D51 receives F-D50’s result unchanged as its first argument and zero as its second.

8. **Conditional later-loop arguments.** F-D60 result three, under a defined 32-bit interpretation of both left shifts, makes the next F-D51 arguments 12 and 786,432. This example does not authorize arbitrary signed shifts.

9. **Target transition.** Initial F-D51 uses represented target 0x08833787; the next entry uses 0x088337C5. After one completed iteration, six selector pairs have occurred. A backedge is represented, but normal dependency returns and valid memory alone do not establish further defined execution.
