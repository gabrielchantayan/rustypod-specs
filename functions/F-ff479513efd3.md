# F-ff479513efd3

## Purpose

F-ff479513efd3 performs an in-place, wordwise multiply-and-add over a caller-supplied destination range. Each source word is multiplied by one common unsigned multiplier, added to the corresponding existing destination word, and combined with the carry from the preceding position. The function overwrites the destination with the low words and returns the final carry.

The established arithmetic interpretation is a sequence of unsigned 32-bit limbs, processed from lower index to higher index. Interpreting those limbs as a little-endian multiword integer is useful but is an inferred representation convention, not a separately established requirement of the caller.

The apparent pointer-shaped return value carries an arithmetic result. It does not identify an allocated object or necessarily identify any accessible address.

This contract describes the supplied static representation. No runtime tests have been performed. In particular, the arithmetic interpretation assumes the intended 32-bit machine model; portability to other pointer widths or literal execution under strict language-level pointer and signed-overflow rules is not established.

## Interface

The function has four inputs, in this order:

| Input | Role | Width and interpretation |
|---|---|---|
| Destination base | Start of the words to update | Address of writable unsigned 32-bit words |
| Source base | Start of the multiplicands | Address of readable unsigned 32-bit words |
| Count | Number of positions to process | Signed integer, interpreted as 32 bits under the target model |
| Multiplier | Common multiplier for every position | Unsigned 32-bit integer |

The supplied declaration presents the return type as a pointer to an unsigned word. Its operational meaning is the final unsigned 32-bit carry encoded in the return value’s bits.

For a positive count:

- Both ranges must support the accesses described below for every processed position.
- Destination words must be readable as well as writable: their previous values participate in the calculation.
- Source words need only be readable unless their storage also belongs to the destination range.
- Each indexed position occupies four bytes under the 32-bit word interpretation.
- Address calculation must remain valid for the complete accessed ranges.
- The function does not receive lengths other than the count and does not verify range capacity.

For a zero or negative count, neither base is accessed. Null bases are therefore compatible with this no-work path.

There is no input carry. Carry begins at zero for every invocation.

The function returns no separate success indicator. A zero result can mean either that no words were processed or that the final arithmetic carry was zero.

## Behavior

### No-work path

When the signed count is less than one, the function returns the null-valued result.

This path performs no source-word reads, no destination-word reads, and no destination writes. The multiplier has no effect on the result.

A negative count is not converted to an unsigned length and does not initiate a large traversal.

### Arithmetic definition

Let:

- \(B = 2^{32}\);
- \(n\) be the positive count;
- \(m\) be the multiplier, in the range \(0\) through \(B-1\);
- \(s_i\) be the source word observed for position \(i\);
- \(d_i\) be the destination word observed before the write for that position;
- \(c_i\) be the carry entering that position.

The initial carry is \(c_0 = 0\). For each position, in increasing index order:

\[
t_i = s_i m + d_i + c_i
\]

The replacement destination word and next carry are:

\[
r_i = t_i \bmod B,
\qquad
c_{i+1} = \left\lfloor \frac{t_i}{B} \right\rfloor.
\]

The function stores \(r_i\) at destination position \(i\). After the last position, it returns the bit pattern of \(c_n\).

These equations describe the intended machine-width result without requiring a particular multiplication implementation. They apply when the repeated reads of a given word agree and the 32-bit arithmetic interpretation holds.

The carry is not merely an overflow flag. It may contain any of many 32-bit values. For this recurrence, \(0 \leq c_i \leq m\). The complete per-position total fits in an unsigned 64-bit value: it is at most \(B^2-1\).

The final carry is not stored at destination position \(n\). A caller needing that extra limb must handle the returned value separately.

### Width and carry construction

The static representation divides both the multiplier and each source word into unsigned low and high 16-bit halves.

The product calculation combines those halves while explicitly compensating for:

- Overflow when adding the two cross products.
- Overflow when adding the low-half product to the shifted cross-product contribution.
- Overflow when adding the incoming carry to the low product word.
- Overflow when adding the existing destination word to that result.

Each overflow contributes to the high product word at the appropriate significance. Consequently, replacing this behavior with a computation that discards the high half of the multiplication would not satisfy the contract.

Some intermediates appear signed or pointer-shaped in the supplied representation. Their role in the arithmetic is nevertheless as 32-bit bit patterns. That observation supports the recurrence above, but does not establish that the representation is portable source code.

### Traversal and access order

Positions are completed in increasing order. The write for one position occurs before source reads for the next position.

For each position, the supplied representation shows:

1. A source-word read used to obtain the low 16 bits.
2. Another source-word read used to obtain the high 16 bits.
3. Arithmetic combining those parts with the multiplier and incoming carry.
4. A destination-word read used in the addition.
5. Another destination-word read used in the carry comparison.
6. A write replacing that destination word.

These are static expression-level access observations, not a verified processor-level load trace. A compiler may combine ordinary nonvolatile reads. The contract does not promise a particular number of physical bus transactions.

If memory can change between the repeated reads, the low and high halves need not originate from the same source value, and the destination value used for addition need not match the value used for the overflow comparison. The simple arithmetic recurrence is therefore conditional on stable observations within each position. Volatile-memory, concurrent-access, and memory-mapped-I/O semantics are not established.

Processing is arranged in groups of up to four positions. Completion checks after the first, second, and third positions prevent access beyond a short final group. After a fourth position, the remaining count is reduced by four; traversal either finishes or continues at the next group.

This grouping does not change the logical order or restart the carry. Counts crossing a four-position boundary retain the carry from the preceding position.

### Aliasing and overlap

The function does not copy the source range before writing the destination.

Exact aliasing is compatible with the sequential arithmetic model. At each position, the word serves as both the source multiplicand and the old destination value before being replaced.

Partial overlap is order-sensitive:

- If an earlier destination write changes a later source position, that later calculation uses the changed source value.
- If a destination write affects only source positions already consumed, it does not retroactively alter their results.
- No snapshot semantics are provided.

For disjoint ranges, or where overlap does not alter future source observations, define the initial multiword values as:

\[
S = \sum_{i=0}^{n-1} s_i B^i,
\qquad
D = \sum_{i=0}^{n-1} d_i B^i.
\]

Then the updated destination represents \((D+mS)\bmod B^n\), and the returned carry is \(\lfloor(D+mS)/B^n\rfloor\).

This whole-range identity must not be applied to initial source contents when earlier writes modify source words that have not yet been read.

## Side effects

For a positive count, the function writes exactly one result word at each destination position from zero through count minus one, in that order. It performs the writes even when a result equals the previous contents.

There is no explicit write beyond the requested destination range. The source is not explicitly written through its own base, although overlapping destination storage can change source contents.

The supplied body contains no allocation, deallocation, external call, I/O operation, or explicit access to global state. It does not retain either base for later use. The caller remains responsible for the storage lifetime and for interpreting the returned carry.

There is no validation for null addresses, insufficient capacity, alignment, inaccessible storage, or address-range overflow when the count is positive. Such conditions are outside the valid-memory preconditions. No checked failure result or recovery behavior is established.

Updates are incremental rather than transactional. The body contains no rollback mechanism. If execution is interrupted after some writes, those writes have already occurred; precise fault behavior is not specified by this evidence.
