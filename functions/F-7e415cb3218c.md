# F-7e415cb3218c

## Purpose

F-7e415cb3218c accepts an unsigned selector of 0 or 1, writes selector-dependent shared state, and calls a final dependency with the original context and an indication of whether selector 1 was chosen. Selector 1 additionally invokes three transformation dependencies and stores their results.

The established contract is an ordered sequence of reads, writes, and calls. The domain meaning of the state and transformations is unknown. “Mode selection” and “notification” describe inferred intent, not independently established semantics.

The function reads the shared state-base slot once before validating the selector and **again on an accepted path to address the selector-byte write**. Other direct state-field accesses use the initially captured base. The evidence does not establish that these two reads produce the same address.

On normal completion, the function returns the 32-bit value zero for either accepted selector and `0xFFFFFFFF` for every rejected selector. Zero does not certify dependency success: the function performs no dependency-result checks.

## Behavior

### Validation and rejection

The function first reads the shared base slot and captures its value as the initial base. It then compares the full unsigned selector with 2.

For selector values of 2 or greater:

- The shared base slot is not read a second time by the visible function.
- No listed state field is directly read or written.
- No dependency is called.
- The return value is `0xFFFFFFFF`.

Thus, rejection avoids state-field accesses, but not the initial shared-slot read.

### Common accepted-selector preparation

For selector 0 or 1, the function performs these operations in order:

1. It reads the shared base slot again to obtain the selector-store base.
2. It writes the selector as one byte at selector-store base `+0x01`.
3. It writes the 32-bit pattern `0x3F400000` at initial base `+0x28`.

The selector-byte conversion loses no information because only 0 and 1 reach it.

The second shared-slot read does not replace the initially captured base for subsequent field accesses. Even when the selector byte targets a different object or region, the constant write and all later direct field accesses remain relative to the initial base.

The constant is established as a raw 32-bit store. Under an IEEE 754 binary32 interpretation it represents 0.75; the evidence does not establish that consumers interpret this field as floating-point data.

### Selector 0

After common preparation, the function calls F-6537324b2b8c with:

- The original 32-bit context.
- A false-valued argument, numerically 0, resulting from the selector-equals-1 comparison.

The call’s return value is ignored. If it returns normally, the function returns zero.

There are no direct accesses at initial base `+0x18` or `+0x24` on this path. That absence does not guarantee those fields remain unchanged: the final dependency’s effects are unknown.

### Selector 1

After common preparation, the function performs the following operations in order.

**First transformation.** It reads 32 bits at initial base `+0x18` and calls F-f2b8ff34d9f0 with that value and the numeric argument 2.

After that call returns, its 32-bit result is supplied as the first argument to F-450415463608. The second argument is the shared transformation value read for this later call. It is not established as a value captured before F-f2b8ff34d9f0.

The 32-bit result from F-450415463608 is written at initial base `+0x18`. No direct write to that field occurs between the two transformation calls. Either dependency may nevertheless have independent shared-state effects.

**Second transformation.** After that result is stored, the function reads the 32-bit field at initial base `+0x24`. The representation treats this input as a signed 32-bit integer and forms a left-shift-by-two expression. That expression is passed to F-d7be9cfb4000 together with the numeric argument 3.

The 32-bit result of F-d7be9cfb4000 is written at initial base `+0x24`.

For a nonnegative input no greater than `0x1FFFFFFF`, the shifted value is representable as a signed 32-bit integer and equals four times the input. Exact behavior for negative inputs or larger positive inputs is unresolved: the supplied evidence does not establish a portable signed-shift rule or a target-level wraparound rule.

The `+0x24` input is read after both earlier transformation calls and the direct `+0x18` result store. It need not equal the value present at function entry.

**Replacement store.** After storing the second transformation result, the function reads the shared replacement value and writes its 32 bits at initial base `+0x28`.

This is the second direct write to that field on selector 1. The initial constant write remains part of the behavior; it is not omitted merely because replacement follows.

The replacement is obtained after F-d7be9cfb4000 returns. Changes to the shared replacement value before that read can affect the stored value.

**Final call.** After all direct field writes, the function calls F-6537324b2b8c with the unchanged context and a true-valued argument, numerically 1. Its return value is ignored. If the call returns normally, the function returns zero.
