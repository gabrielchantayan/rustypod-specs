# F-80c0c1b5ab22

## Purpose

F-80c0c1b5ab22 conditionally performs an object-associated operation using a looked-up handle and a temporary, 92-byte workspace. It records a supplied 32-bit value in the object on both normal completion and a short-circuit path.

An object byte selects between two substantially different behaviors:

- **Nonzero:** record the supplied value immediately and return, without calling dependencies.
- **Zero:** record a supplied byte, resolve a handle, invoke several dependencies, initialize a temporary workspace, conditionally invoke an additional operation, record the supplied value, and finalize the workspace.

The functional meanings of the object fields, supplied value, handle, and workspace are not established. Interpretations such as “deferred update,” “resource selection,” or “notification” are inferred intent only, not requirements of this contract.

## Behavior

### 1. Initial branch and short-circuit completion

The first direct memory operation is an eight-bit read at object offset `0xEC`.

If this byte is nonzero:

1. The supplied 32-bit value is written at object offset `0xE4`.
2. The function returns.

This path does not directly write the supplied byte at `0xE8`, read `0xEA`, initialize a workspace, or call any dependency. All nonzero byte patterns select this path; there is no distinction among them.

If the initial byte is zero, execution follows the full-operation path. The function does not directly reread this branch byte later. A subsequent change to the byte does not cause the function itself to reconsider the initial branch decision.

### 2. Supplied-byte write and handle lookup

On the full-operation path, the supplied byte is first written at object offset `0xE8`.

F-1f46730b1ced is then called with:

- The object address advanced by `0xB4` bytes.
- The supplied 32-bit value, unchanged.

Its 32-bit result is retained as the handle for subsequent calls.

If the result is zero, F-a817d8d58c10 is invoked. The supplied static representation marks this dependency as non-returning. Consequently, under that annotation, this invocation has no normal return and does not proceed to later steps.

The supplied-byte write occurs before this failure point. No direct write to `0xE4` has yet occurred on this path. Dependency-induced changes are not constrained by this observation.

No special rejection is visible for a nonzero handle with its high bit set or for any other nonzero bit pattern.

### 3. Handle-associated dependency sequence

1. F-d2f99870cc43 receives the handle and produces a 32-bit result.
2. F-bf557f07179f receives the original object address and that result.
3. F-fa8898fa75ae receives the handle.

The evidence does not establish whether that dependency releases anything, modifies reference counts, changes the handle’s underlying state, or has another purpose. There are no visible result checks between these calls and the next stage.

### 4. Workspace initialization from two separately obtained addresses

Workspace initialization uses two separate calls to F-fdd8589eca2d:

1. Call F-fdd8589eca2d.
2. Read one byte at offset `0x2C` from that call’s returned address.

The one-byte value is captured before the second call and then retained as a value. The four-byte value is obtained afterward. There is no basis for treating these reads as a single atomic snapshot or assuming that the second call preserves the state observed through the first address.

The workspace’s internal layout, initialized extent, and validity rules are delegated to F-2c5a9f9c1eb3 and its consumers.

### 5. Mode query and conditional operation

If the result equals `8`, the function skips the conditional operation completely. In particular, it does not make the additional F-fdd8589eca2d call described below and does not directly read the object’s field at `0xEA`.

For every result other than `8`, the function:

1. Calls F-fdd8589eca2d a third time.
2. Selects a 16-bit argument:
   - If Control B is zero **and** Control A is nonzero, read two bytes at object offset `0xEA`.
   - Otherwise, use the 16-bit value zero without reading that field.
3. Calls F-818c773e8c8a with these five arguments, in order:
   - The result of the third F-fdd8589eca2d call.
   - The workspace address.
   - The retained handle.
   - Control A, unchanged.
   - The selected 16-bit value.

The third address-producing call precedes the optional read at `0xEA`. If that call changes the object field, the subsequent direct read observes the field after the call, not a value captured earlier.

Control A is not normalized to a Boolean before forwarding. For example, a value of `2` is passed as `2`, not as `1`. Control B only selects between a field read and a zero argument; it is not itself forwarded.

### 6. Final direct write and workspace finalization

2. Call F-920630e53283 with the workspace address.

## Acceptance examples

These are conditional static acceptance scenarios, not reports of executed tests.

1. **Short-circuit byte is nonzero.**  
   Given a readable initial byte of `0x80` at `0xEC`, the function writes the supplied value at `0xE4` and returns without dependency calls. The supplied byte is not directly written to `0xE8`.

2. **Lookup yields zero.**  
   Given an initial zero byte at `0xEC`, the supplied byte is written to `0xE8` before lookup. If lookup returns zero, F-a817d8d58c10 is invoked. Under its non-return annotation, workspace initialization, conditional operation, final direct value write, and workspace finalization do not occur.

3. **Mode result is exactly `8`.**  
   Given successful preceding calls, the workspace is still initialized from two separately obtained addresses. The third F-fdd8589eca2d call and F-818c773e8c8a are skipped. The final direct value write precedes workspace finalization.

4. **Object-sourced 16-bit argument.**

5. **Forced-zero 16-bit argument.**  
   With a mode result other than `8`, either nonzero Control B or zero Control A causes a zero final argument. The function makes no direct read at `0xEA`. The third address-producing call and conditional operation still occur.

6. **Changing context results.**  
   If the first two F-fdd8589eca2d calls return different valid addresses, workspace initialization receives the byte from the first address’s `0x2C` field and the four-byte value from the second address’s `0x28` field. They are not required to originate from one context.
