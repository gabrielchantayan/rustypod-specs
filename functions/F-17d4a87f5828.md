# F-17d4a87f5828

## Purpose

F-17d4a87f5828 classifies an opaque input against three ordered reference tokens and, for a recognized token, conditionally invokes one of three object-associated callbacks.

The three reference tokens are associated with wheel, upward-arrow, and downward-arrow handling. These descriptions identify their apparent roles; they do not establish the full byte contents of the referenced data or the semantics of the classification dependency.

The function returns a 32-bit recognition result:

- **1:** a token was recognized. Its callback was either invoked or suppressed by an equality check.
- **0:** none of the three token comparisons returned zero.

A result of 1 does not establish that a callback changed state, succeeded, or was invoked at all. Callback return values are ignored.

This contract distinguishes behavior established by the supplied static representation from inferred intent and unresolved implementation details. No runtime tests have been performed.

## Behavior

### Classification order

The function uses one classification dependency with two arguments: the classification value and a category-specific reference token. Its 32-bit result is interpreted only as zero or nonzero.

The categories are considered in this order:

1. Wheel.
2. Upward arrow, only if the wheel comparison returned nonzero.
3. Downward arrow, only if both preceding comparisons returned nonzero.

A zero result selects that category immediately. Later comparisons are not performed.

This is an ordered classification, not three independent checks. If the dependency could return zero for more than one reference token, the earliest category takes precedence.

A nonzero classification result is not visibly treated as an error. Its sign and magnitude do not affect the branch.

### Global comparison timing

The placement of global reads is significant.

After the wheel classification call returns, the function reads a global 32-bit value and retains that value as a snapshot. This read occurs whether the wheel classification result was zero or nonzero.

The following behavior then depends on the selected category:

- **Wheel:** the function reads the global value again and compares the event value with this second read. The earlier snapshot does not control the wheel suppression decision.
- **Upward arrow:** the function compares the event value with the snapshot taken immediately after the wheel classification call.
- **Downward arrow:** the function compares the event value with that same snapshot.
- **Unrecognized input:** the function returns 0 after all three classifications return nonzero. The initial global read has nevertheless already occurred.

Thus, the upward-arrow and downward-arrow paths do not obtain a fresh global value after their own classification calls.

The global is not read before the first classification call. Consequently, changes made by that call can affect the snapshot.

These statements describe the read placement in the supplied static representation. They do not establish volatile access semantics, atomicity, or guarantees about concurrent observation.

### Suppression and callback selection

For a recognized category, equality between the event value and the applicable global value suppresses dispatch.

A suppressed event returns 1 without reading the object’s callback table or invoking a callback.

If the values differ, the function:

- Reads the table address from the object’s first field.
- Reads the callback address at the category’s table offset.
- Invokes that callback with the original object reference and event value.
- Returns 1 if the callback returns normally.

No additional classification or global comparison occurs after the callback returns.

The suppression rule uses exact 32-bit equality. There is no range check, sign-based branch, masking operation, or arithmetic transformation of the event value.

### Arithmetic and boundary behavior

No arithmetic is performed on the event value or classification value.

The only visible address arithmetic adds one of three fixed byte offsets to the table address. The function does not visibly check address overflow, table bounds, null addresses, or callback validity.

All 32-bit event-value bit patterns are eligible for equality comparison and callback forwarding. Negative values, zero, and values with the high bit set receive no special treatment.

## Acceptance examples

These examples are conditional static acceptance criteria, not recorded executions. Callback-invoking examples assume valid table accesses and a normally returning callback.

### Wheel match with suppression

Given:

- The first F-D01 call returns zero.
- The event value equals the second global read.

Required behavior:

- No upward-arrow or downward-arrow comparison.
- No object-table read.
- No callback.
- Return 1.

Both global reads occur in the represented order, although the first value does not determine suppression.

### Wheel match without suppression

Given:

- The first F-D01 call returns zero.
- The event value differs from the second global read.

Required behavior:

- Resolve the callback at table offset 292.
- Invoke it with the original object reference and event value.
- Ignore its return value.
- Return 1.

### Upward-arrow match using the earlier snapshot

Given:

- The wheel comparison returns nonzero.
- The subsequent global snapshot is 7.
- The upward-arrow comparison returns zero.
- That comparison changes the global to 9.
- The event value is 7.

Required behavior:

- Suppress the callback and return 1.
- Do not reread the global for the suppression decision.
- Do not perform the downward-arrow comparison.

With an event value of 9 instead, the same conditions require dispatch through table offset 296, because the relevant snapshot remains 7.

### Downward-arrow dispatch

Given:

- The first two comparisons return nonzero.
- The third comparison returns zero.
- The event value differs from the snapshot taken after the first comparison.

Required behavior:

- Resolve and invoke the callback at table offset 300.
- Pass the original event value without transformation.
- Return 1 after the callback returns.

Changes to the global during the second or third comparison do not replace the retained snapshot.

### No recognized category

Given that all three F-D01 calls return nonzero:

- Perform the comparisons in the specified order.
- Read the global once, after the first comparison.
- Do not access the object’s table.
- Return 0.

### Multiple possible matches

If F-D01 would return zero for both wheel and upward-arrow tokens, but the wheel comparison is reached first, only the wheel result matters. The upward-arrow comparison must not occur.

### Callback result is not propagated

If an unsuppressed selected callback returns zero or another value, F-17d4a87f5828 still returns 1. A callback that does not return normally falls outside that normal-return criterion.
