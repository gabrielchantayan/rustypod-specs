# F-34a9309ff3cc

## Purpose

F-34a9309ff3cc conditionally dispatches an event against a mutable receiver. Its established behavior consists of three paths:

- Event kinds 7 and 13 decode a value and may invoke a receiver method with −1 or +1.
- Event kind 21 obtains a payload, conditionally sets up an opaque receiver-associated value, and computes a signed value for possible receiver dispatch.
- Event kind 19 compares identifiers and may invoke one of two other receiver methods.

The Boolean result reports whether the selected path is considered handled. It does not uniformly report whether a receiver method ran, whether that method returned nonzero, or whether side effects occurred.

**Inferred intent:** the first two paths may handle directional input and accumulated movement; the identifier path may dispatch notifications. These interpretations are not requirements. Likewise, the conditional setup sequence resembles allocation and initialization, but the supplied evidence establishes only calls, arguments, an opaque returned value, and a receiver-field write.

## Behavior

### Event classification

The function first reads the 32-bit event kind at `0x04`.

- Values 7 and 13 select direction decoding.
- Value 21 selects payload processing.
- Any other initial value leads to a second read of the kind field. Identifier matching proceeds only if this second read equals 19; otherwise the result is false.

The second read is explicit in the supplied representation. It is not specified as reuse of the initial value. No dependency call intervenes between these two reads on that path. Synchronization or concurrent modification guarantees are not established.

### Direction decoding: kinds 7 and 13

F-682adfd5a561 is called with the event address and selector `0x0A00`. Its returned 32-bit value is passed to F-11c1b7e655b3.

The latter result determines dispatch:

| Decoded value | Action |
|---|---|
| `0x57` | Invoke receiver method `0x15C` with −1 |
| `0x58` | Invoke receiver method `0x15C` with +1 |
| Any other value | Return false without that receiver-method invocation |

The −1 argument has the 32-bit representation `0xFFFFFFFF`.

For either accepted value, method resolution occurs after both dependencies return: the function reads the receiver’s method-table address and the entry at `0x15C`, then invokes that entry. Its return value is ignored. Normal return from the method is followed by a true result.

This path performs no explicit flags check or access to receiver offset `0x108`. Dependency side effects may nevertheless affect the receiver before method resolution.

### Payload processing: kind 21

#### Extraction and gate

F-682adfd5a561 is called first, with the event address and selector `0x3500`. Its returned value is retained as the payload address.

Only afterward does the function read receiver flags at `0x48`. If bit `0x01000000` is set, the function returns false without the subsequent setup and processing calls.

Consequently, this false result does not imply that no dependency ran or that no side effects occurred. Changes to the flags made during extraction affect the gate.

#### Conditional setup of the opaque receiver value

When the gate permits processing, the function reads receiver offset `0x108`. If that value is nonzero, it skips the setup sequence.

If the value is zero, the sequence is:

1. Call F-8157a180d901 with the numeric argument `0x34`, equal to decimal 52.
2. After that call returns, read a global datum.
3. Call F-1058afc38c04 with four arguments: the returned value from F-8157a180d901, `4`, `1`, and the just-read global datum.
4. Write the 32-bit result of F-1058afc38c04 to receiver offset `0x108`.
5. Call F-991ae23131ae with that returned value and `0x20`.

The fourth argument is the **value read from a global**, not an established fixed address-bearing constant. F-8157a180d901 may change that global. Its value therefore must not be captured before that call or treated as immutable.

The source does not provide the global’s declaration or establish its semantic type. Its contents are not supplied.

The argument `0x34` is established numerically. Its interpretation as a byte count, and F-8157a180d901’s interpretation as an allocator, are not established. Similarly, F-1058afc38c04’s result is an opaque 32-bit value, not a proven initialized-state address.

The primary match succeeds when the event identifier at `0x08` equals either:

- The receiver identifier at `0x40`; or
- A primary global identifier.

## Acceptance examples

These are conditional examples, **not executed tests**. They assume valid reached accesses, normal call returns, and no unspecified side effects contradicting the stated conditions.

1. **Negative direction:** kind 7 with decoding result `0x57` invokes `0x15C` with −1 and returns true regardless of that method’s result.

2. **Rejected decoding:** kind 13 with decoding result `0x59` returns false without receiver dispatch.

3. **Gate observes extraction effects:** for kind 21, if extraction sets the disabling flag, the later flags read causes false. Extraction has already occurred.

6. **Zero setup result:** if the returned value is zero, F-991ae23131ae is still called with zero and `0x20`, and payload processing continues. No false return is introduced merely because the stored value is zero.

7. **Fresh receiver-field read:** if F-aa672b15efb7 changes `0x108`, F-be0ad8f71bac receives the changed value, subject to any other intervening effects.

8. **Zero candidate:** a zero candidate still permits the F-be0ad8f71bac call, then produces true without `0x15C` dispatch.

12. **Secondary ordering:** after a secondary match, F-5710a8628cba runs before method-table resolution for `0xA0`.

13. **Unsupported kind:** if the initial kind selects neither direction nor payload processing and the second kind read is not 19, the result is false.
