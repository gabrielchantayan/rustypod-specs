# F-556ba9968cb6

## Purpose

F-556ba9968cb6 exposes a sequence of indirect calls interleaved with computed-address memory reads and writes. Its visible effects include publishing the second and third input words, storing scaled results obtained from dependencies, clearing several words and bytes, and updating byte-addressed destinations selected by other bytes in memory.

A conventional application-level purpose is not established. In particular, the evidence does not justify describing this function as an allocator, initializer, serializer, device driver, or destructor. Repeated stores and small absolute addresses may be meaningful in the original execution environment, or may reflect an unreliable recovery of the instruction stream.

The available representation explicitly reports invalid instruction data and ends at an invalid-instruction boundary. This specification therefore separates:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional interpretation:** consequences if those operations faithfully represent executable instructions and their indirect calls return.
- **Unknown behavior:** dependency effects, actual address validity, calling convention details, and behavior beyond the damaged boundary.

There is no established normal-completion contract.

### Initial publication and scaled-word stores

The next direct memory effect is a 32-bit store of the second input at:

\[
4 \times \text{initial index} + 0x14.
\]

A call receives four times that index. Four subsequent calls produce a **scale index**. The function retains four times the scale index as a **scaled word**, and stores that scaled word at:

\[
16 \times \text{scale index} + 0x14.
\]

The scaled word is passed to another indirect call. A following result is forwarded to a further dependency, after which four additional calls produce a new index. At its four-times-index address plus `0x14`, the function stores:

\[
(\text{scaled word} \mathbin{\&} 0x3fffffff) \gg 1.

This is a mask followed by a logical right shift; it is not unrestricted division of the original value by two.

Another call sequence produces a **link index**. Four times this index becomes the **link word**. The function stores the link word at sixteen times the link index plus `0x14`.

It then reads a 32-bit unsigned word at the link word plus `0x14`, shifts that loaded value right by three, and passes the shifted value to a dependency. This read is not necessarily from the location just written: the write used sixteen times the index, whereas the read uses four times the index.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Second-input publication.** If the initial index is `3`, the first direct word store writes the second input at `0x20`. This follows from \(4\times3+0x14\), independently of dependency-internal effects.

2. **Different scaling means different locations.** If the link index is `2`, the link word is `8`. Its initial store is at `0x34`, while the subsequent unsigned word read is at `0x1c`. An implementation must not replace the read with the retained value merely because a nearby store preceded it.

3. **Masking precedes shifting.** If the principal word is `0x80000002`, the reduced word is `1`, not `0x40000001`. The top two bits are removed before the right shift.

4. **Byte selectors are fresh where reread.** If the selector at the principal base plus one changes from `5` to `9` during intervening calls, the first selected write targets `0x16`; the later zero-byte write targets `0x1a`.

5. **Captured selectors remain captured.** If the clearing sequence captures selector `7`, its later zero-word store targets `0x4b`, even if a dependency subsequently changes the selector’s source byte.

6. **Byte truncation.** If the first tail word is `0x41`, the low-byte four-times-value store writes `0x04`. The corresponding shifted call argument is `0x104`; it is not truncated to a byte.

7. **Masked high-field byte.** If a tail word is `0x3ff00000`, its masked right-shift-by-twenty value is `0x3ff`; the byte store retains `0xff`.

8. **Repeated absolute clears.** Even if absolute address `0x24` already contains zero, the four represented zero-word stores remain separate ordered effects. Intervening dependencies may observe or modify that address.

9. **Aliasing remains effective.** If an earlier store overlaps a later selector byte, that later read uses the resulting memory content, subject also to intervening dependency effects. There is no snapshot of all selectors at entry.
