# F-9499bcad13a6

## Purpose

F-9499bcad13a6 evaluates an opaque input against up to three ordered candidates through dependency F-a1e68ae27737. It stops at the first nonzero result and writes the byte value 1 to the corresponding position in a caller-supplied destination.

The candidate-to-destination mapping is:

| Candidate position | Destination byte offset |
|---|---:|
| First | 0x1D, decimal 29 |
| Second | 0x1E, decimal 30 |
| Third | 0x1C, decimal 28 |

If all three dependency results are zero, this function performs no destination write of its own.

The established behavior is ordered evaluation and conditional byte marking. Interpreting the candidates as names, strings, types, or categories would require evidence not supplied here. Likewise, a nonzero dependency result is a branch condition, not an established indication of equality, success, or validity.

## Behavior

### Ordered evaluation

The function retains a reference to the candidate storage before the first dependency invocation. It obtains the first four-byte candidate through the global candidate reference and invokes F-a1e68ae27737 with:

- The opaque input value as the first argument.
- The first candidate value as the second argument.

If the result is nonzero, the function writes the one-byte value 1 at destination offset 0x1D and returns. It does not read the second or third candidate for another invocation.

If the first result is zero, the function reads the second candidate from the retained candidate-storage reference, at byte offset 4. It invokes F-a1e68ae27737 again with the same opaque input value and this newly read candidate value.

If the second result is nonzero, the function writes the one-byte value 1 at destination offset 0x1E and returns. It does not read the third candidate for another invocation.

Only if both earlier results are zero does the function read the third candidate from the retained reference, at byte offset 8. It invokes F-a1e68ae27737 with the same opaque input value and this third candidate value.

If the third result is nonzero, the function writes the one-byte value 1 at destination offset 0x1C. If that result is zero, it performs no destination write of its own. Either outcome ends the function.

### Priority and call count

The first nonzero result determines the destination offset. There is no aggregation of results and no evaluation of lower-priority candidates after a nonzero result.

On a normally returning path, the dependency is invoked:

- Once if the first result is nonzero.
- Twice if the first result is zero and the second is nonzero.
- Three times if the first two results are zero.

The third result controls whether the three-call path includes a destination write, but it does not change the number of calls.

### Candidate-read timing

The second and third candidate values are not established to be snapshots taken at entry. Their reads occur only after earlier dependency invocations return zero:

1. The first candidate is read before the first invocation.
2. The second candidate is read after the first invocation returns zero.
3. The third candidate is read after the second invocation returns zero.

Consequently, an earlier invocation can affect a later candidate value if it modifies the retained candidate storage. This function contains no visible copy of all three entries before calling the dependency.

Later candidate accesses use the retained reference. A dependency’s reassignment of the global candidate reference does not, by itself, redirect those later accesses. This does not guarantee that the retained storage remains allocated, readable, or unchanged.

The initial reference retention and the first candidate access are expressed through the global reference. No intervening dependency invocation separates them. The evidence does not establish an atomic snapshot or behavior under asynchronous modification during those initial accesses.

### Destination update semantics

A selected update is a one-byte store of the value 1. It is not a multi-byte integer write, an increment, or a read-modify-write operation.

The function does not read the existing destination byte before overwriting it. It does not clear either of the other two destination bytes.

Thus, this function alone does not enforce mutual exclusivity among the three positions. If other positions already contain nonzero values, a selected update leaves them untouched by this function’s own stores.

## Acceptance examples

These examples are conditional specifications, not runtime test results. Unless an example states otherwise, assume readable candidate storage, valid selected destination addresses, normally returning dependency calls, and no dependency-induced memory changes.

| Dependency results, in invocation order | Calls | Direct destination effect |
|---|---:|---|
| Nonzero | 1 | Store byte 1 at offset 0x1D |
| Zero, nonzero | 2 | Store byte 1 at offset 0x1E |
| Zero, zero, nonzero | 3 | Store byte 1 at offset 0x1C |
| Zero, zero, zero | 3 | No direct destination write |

**First-result priority.** If the first invocation returns nonzero, only offset 0x1D is selected. Possible results for the second and third candidates are irrelevant because those invocations do not occur.

**No clearing.** Suppose destination bytes at offsets 0x1C, 0x1D, and 0x1E initially contain 7, 0, and 9. If the first invocation returns nonzero and the dependency leaves destination memory unchanged, the resulting bytes are 7, 1, and 9.

**All-zero preservation is conditional.** If all three invocations return zero and none modifies destination memory, the destination remains unchanged. If a dependency invocation modifies it, the function does not restore the previous contents.

**Deferred candidate loading.** If the first invocation changes the retained storage’s second entry and returns zero, the second invocation receives the value read after that change, provided the storage remains valid.

**Global-reference replacement.** If the first invocation replaces the global candidate reference, returns zero, and leaves the originally retained storage valid, the second candidate is still read from the retained storage rather than automatically following the replacement.

**Unreached locations.** If the first invocation returns nonzero, this function does not need to read the second or third candidate. This is not a claim about any memory accesses performed internally by the dependency.
