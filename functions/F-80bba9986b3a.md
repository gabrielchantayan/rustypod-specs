# F-80bba9986b3a

## Purpose

F-80bba9986b3a conditionally obtains a handle, prepares associated state, obtains a data address and a pointer-shaped quantity, and invokes a processing dependency. It returns a signed 32-bit status. After successful handle acquisition, it also writes an optional one-byte indicator: zero when processing returns zero, and one otherwise.

The directly established outcomes are:

- **−50:** the initial dependency returns zero, the second argument is zero, or handle acquisition returns zero.
- **−43:** acquisition succeeds, but the conditions for processing are not met.
- **Processing status:** when processing occurs, its result is returned unchanged.

“Acquisition,” “preparation,” “processing,” and “finalization” describe the observable call sequence. They do not establish application semantics, resource ownership, or the internal behavior of dependencies.

This contract describes static evidence. No runtime tests have been performed.

## Behavior

### Entry gates and acquisition

F-78d2ee17e68f is called without arguments. This occurs even if the second argument is zero.

If its result is zero, the function returns −50 immediately. If its result is nonzero but the second argument is zero, the function also returns −50.

Neither path calls F-3080127849ac, accesses the record fields, or performs this function’s indicator write. Dependencies may have their own effects; “no indicator write” refers only to the explicit store in F-80bba9986b3a.

When both entry gates pass, F-3080127849ac is called with the first argument. A zero result produces an immediate return of −50. A nonzero result is retained as the handle for subsequent calls.

### State after successful acquisition

The function establishes a failure indicator of one and a provisional return status of −43.

It reads the first record’s 32-bit field at offset 4, uses that value as a nested-record address, and captures the nested record’s 32-bit field at offset 8.

It then calls F-efaaaab570a3 with the acquired handle. That dependency’s result is not used. The captured nested value is not reread afterward.

Consequently, changes made by F-efaaaab570a3 can affect subsequent reads of the first record, but do not replace the already captured nested value.

### Two-read gate and data acquisition

After F-efaaaab570a3 returns, the function reads the first record’s offset-32 field to test whether it is nonzero.

If this **gate read** yields zero:

- No second offset-32 read is reached.
- F-c45cb3f8e7fd is skipped.
- Processing is skipped.
- The provisional status remains −43, and the indicator remains one.

If the gate read yields nonzero, the function reads the same field again while forming the arguments to F-c45cb3f8e7fd. This **argument read**, not the gate-read value, supplies the second argument.

F-c45cb3f8e7fd receives, in order:

1. The acquired handle.
2. The value obtained by the second offset-32 read.
3. The address of the mutable data-address slot, initially containing the fourth argument.
4. The address of the mutable quantity slot, initially containing the third argument’s pointer bits.

No dependency call intervenes between the two offset-32 reads. Nevertheless, the contract does not collapse them into a single read or assert that their results necessarily match. Equality requires an appropriate stability assumption. In particular, passing the nonzero gate does not independently guarantee that the second argument delivered to F-c45cb3f8e7fd is nonzero.

After F-c45cb3f8e7fd returns, processing is eligible only when:

- Its returned value is exactly zero; and
- The resulting quantity slot contains a nonzero pointer-shaped value.

A nonzero dependency result is not propagated. It leaves the retained status at −43. A zero quantity likewise prevents processing.

There is no requirement that this dependency replace either slot. An unchanged slot retains its argument-derived initial value.

### Quantity conversion and data inspection

On an eligible path, the quantity’s 32-bit bit pattern is interpreted as unsigned and shifted right by one bit. The resulting bits replace the quantity slot.

This is a logical shift, equivalent to unsigned division by two with the remainder discarded:

- A quantity of one passes the nonzero eligibility check but converts to zero.
- An odd quantity is rounded down.
- The converted range is zero through 2,147,483,647.
- No dereference of the quantity as an address is performed.

The function then reads the first 16-bit element at the resulting data address. There is no additional null check and no positive-quantity check before that read.

The value selected for processing’s first argument depends on an exact comparison with hexadecimal 003A:

- If the element equals hexadecimal 003A, the selected value is the previously captured nested value plus hexadecimal 07C4, or 1,988 decimal.
- Otherwise, the selected value is zero.

A character or delimiter interpretation is inferred intent only. The visible operation is a 16-bit equality comparison.

The addition is represented as signed 32-bit arithmetic. The supplied material does not establish the target’s behavior when the mathematical sum is outside the signed 32-bit range. Such cases remain documented_only; this contract does not assume wrapping or saturation.

### Processing and completion

1. The selected value.
2. The resulting data address.
3. The converted quantity.

Its signed result replaces the provisional −43 status.
