# F-d7c53106f5f1

## Purpose

F-d7c53106f5f1 conditionally runs an ordered sequence of dependency calls using a 112-byte local work area.

It compares an opaque input token against up to two reference values. A nonzero result from the first comparison selects mode 1. Otherwise, a nonzero result from the second comparison selects mode 0. If both results are zero, it returns without invoking any downstream dependency.

The reference addresses do **not** necessarily share the same base. The function first reads and saves a shared base value, then reads that shared location again to obtain the base used for the first reference. If a second comparison is needed, its reference uses the initially saved base.

On a selected path, the function supplies two object fields and the selected mode to a dependency, invokes another dependency on the same work area, optionally invokes a third dependency using a later-read object field and an unresolved ambient value, and finally invokes a fourth dependency on the work area.

These are established call and access relationships. Descriptions such as construction, processing, notification, and destruction would be inferred intent, not established semantics.

## Behavior

### Shared-base reads and reference selection

The access sequence begins as follows:

1. The function reads the shared base location and saves that value for possible use by the second reference lookup.
2. It reads the same shared base location again.
3. Using the base obtained by this second read, it reads the 32-bit first reference at byte offset +152.
4. It invokes F-a1e68ae27737 with the comparison token followed by that reference value.

No dependency call intervenes between the two shared-base reads. Nevertheless, their equality is not established: no stability, synchronization, or memory-access contract for that shared location is supplied.

If the first comparison result is nonzero, the function selects the 32-bit mode value 1. It does not read the second reference and does not invoke the comparison dependency again. The first comparison therefore has strict precedence.

If the first result is zero, the function reads the 32-bit second reference at byte offset +156 from the base saved by the **first** shared-base read. It does not reload the shared base location for this lookup. It then invokes F-a1e68ae27737 with the same comparison token and this second reference.

If the second result is nonzero, the function selects the 32-bit mode value 0. If the second result is zero, the function returns immediately.

Thus, the first reference uses the later base observation, while the second reference, if needed, uses the earlier saved observation. The two references need not come from the same underlying region.

The second reference is fetched only after the first comparison returns. A valid modification of the second-reference memory during that call can therefore affect its value. Changing only the shared base location during the call does not redirect the second lookup, because that lookup uses the already saved base.

On the double-zero path, no caller-object field read and no downstream dependency invocation is shown. The evidence does not require an object dereference on that path.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Each example assumes valid accesses and normal returns except where stated otherwise.

1. **First comparison selects mode 1.** The shared base location is read twice before the first comparison. If that comparison returns any nonzero 32-bit value, F-5f924a41e165 receives mode 1. The second reference is not read, and no second comparison occurs.

2. **Second comparison selects mode 0.** If the first comparison returns zero and the second returns nonzero, F-5f924a41e165 receives mode 0. Both comparisons receive the same explicit token. The second reference comes from offset +156 relative to the initially saved base.

3. **Different base observations.** If the first shared-base read yields region A and the second yields region B, the first comparison receives the reference from B at +152. If it returns zero, the second comparison receives the reference from A at +156. An implementation that assumes both references use B would not preserve the established sequence.

4. **No base reload after the first comparison.** If the first comparison changes the shared base location to region C and returns zero, that change alone does not make the second reference come from C. The second lookup still uses the initially saved base.

5. **Reference mutation during comparison.** If the first comparison validly changes the 32-bit value at +156 relative to the initially saved base and then returns zero, the second comparison receives the subsequently read value.

6. **Neither comparison selects.** If both comparison results are zero, none of the four downstream dependencies is invoked. No caller-object field is visibly read.

7. **Optional field is zero at inspection.** On a selected path, if the field at +120 is zero when inspected after F-0cd2f3764592, F-9f3817fb74e8 is skipped. F-cffc4cb91a3c is still invoked.

8. **Earlier calls alter the optional decision.** If an earlier dependency validly changes the field at +120, the late test uses the value available after F-0cd2f3764592, not a captured entry value.

9. **Optional field tests nonzero.** The first argument to F-9f3817fb74e8 is obtained by a separate field read. Its second argument remains unresolved; it must not be specified as zero or equated with an explicit input without additional evidence.

10. **A dependency does not return normally.** Later calls, including the final work-area call, are not guaranteed after a fault, nonlocal exit, or nontermination.
