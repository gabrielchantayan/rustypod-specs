# F-cbd722b0647b

## Purpose

F-cbd722b0647b conditionally invokes an auxiliary dependency and dispatches an input record through callbacks associated with a receiver. It returns the first nonzero callback result encountered in its prescribed dispatch order, or zero if no invoked callback returns nonzero.

The established behavior is a sequence of conditional calls, not a single lookup against an immutable event classification. The function rereads input fields between dispatch stages. Earlier dependencies may therefore affect later decisions by modifying the receiver, input record, referenced payload, or dispatch table.

An event-processing interpretation is plausible but inferred. The meanings of the numeric selectors and the receiver’s fields are not established.

## Interface

### Inputs

Two inputs are present:

- **Receiver:** an address interpreted as the base of an object containing 32-bit fields and a dispatch-table reference.
- **Input record:** an address interpreted as the base of a record containing a 32-bit selector and, for some selector values, another 32-bit field that is interpreted as an address or compared as a value.

Although the supplied representation expresses the input-record address through an integer parameter, its observable use is address-based.

### Output

The result is a 32-bit integer:

- A nonzero result from an invoked indirect callback is returned unchanged, without normalization.
- Zero is returned if every invoked indirect callback returns zero.
- The result, if any, of F-4fd087f2325e is not inspected and is not directly propagated.

Nonzero does not establish success or failure. It is a short-circuit result whose application meaning is unknown.

### Preconditions

The caller must provide memory valid for every read reached on the actual execution path. In particular:

- The input record must support the selector read.
- Every reached `0x16` classification must provide a valid referenced payload for the secondary-selector read.
- Every reached indirect call requires a valid receiver, dispatch-table reference, and callable entry at the selected offset.
- Dependencies must return normally for subsequent stages to be reached.

There are no explicit checks for null addresses, record sizes, payload validity, table bounds, or callable targets.

## Behavior

### 1. Optional auxiliary call

The function first reads the input record’s 32-bit selector at offset `0x04`.

If it is not `0x16`, this stage performs no payload read and no auxiliary call.

If it is `0x16`, the function reads the payload address from input-record offset `0x08`, then reads the payload’s 32-bit secondary selector at offset `0x04`. It tests whether subtracting `0x2500` produces `2`. Under ordinary 32-bit machine-integer interpretation, this selects the secondary value `0x2502`.

When that condition holds:

1. The function reads the receiver’s 32-bit word at offset `0x10C`.
2. It narrows that word to the character type represented in the supplied evidence.
3. It invokes F-4fd087f2325e with the receiver and the narrowed value.

The auxiliary call does not itself terminate dispatch based on a return value. On normal return, processing continues.

The narrowing is significant. The full 32-bit receiver word is not passed as the second argument. For values outside the character type’s representable range, the exact resulting numeric argument depends on character width and conversion rules not established here. In particular, a negative-versus-positive interpretation of high-bit character values must not be assumed.

### 2. Conditional early callback

The function reads the input selector again. It does not reuse the selector or secondary selector from the auxiliary-call decision.

If the newly read selector is `0x16`, it freshly reads the payload address and the secondary selector. If that secondary selector is zero, it resolves the receiver’s current dispatch-table reference and invokes the entry at offset `0x124`.

This callback receives the original receiver address and original input-record address.

- If its 32-bit return value is nonzero, the function returns that exact value immediately.
- If it returns zero, processing continues.
- If the selector is not `0x16`, or its secondary selector is not zero, this callback is skipped.

An auxiliary dependency that changes the record from secondary selector `0x2502` to zero can therefore make this callback eligible. Conversely, changing the outer selector away from `0x16` prevents this stage from reading the payload.

### 3. Main callback selection

The function again reads the input selector.

If this read yields `0x16`, it reads the payload address and the payload’s secondary selector. It selects:

- The dispatch-table entry at offset `0x10C` when that secondary selector is `0x2A`.
- The dispatch-table entry at offset `0x110` otherwise.

If the outer selector is anything other than `0x16`, it selects offset `0x110` without reading a payload.

The function resolves the current dispatch-table reference, loads the selected callback, and invokes it with the receiver and input-record addresses.

This stage is reached whenever the earlier stages have returned normally without a nonzero indirect-callback result. It is not skipped merely because an earlier callback already ran and returned zero.

- A nonzero result is returned immediately and unchanged.
- A zero result permits the final conditional stage.

### 4. Final conditional callback

After the main callback returns zero, the function reads the input selector again.

If it is `0x0F`, the function reads:

1. The 32-bit field at input-record offset `0x08`.
2. The receiver’s 32-bit field at offset `0x50`.

If those values are equal, the function resolves the current dispatch-table reference and invokes the entry at offset `0x0E0`, again passing the receiver and input-record addresses.

- A nonzero result is returned unchanged.
- A zero result leads to the function’s final zero return.

If the selector is not `0x0F`, neither comparison field is read by this stage. If the selector is `0x0F` but the values differ, the callback is skipped.

### 5. Default completion

When no invoked indirect callback has returned nonzero, the function returns zero.

There is no additional fallback call after the final conditional stage.

## Side effects

### Direct effects

The supplied body contains reads and dependency calls but no explicit stores to receiver fields, input-record fields, payload fields, or global state.

That does not establish that an invocation is side-effect-free. Each dependency can have effects not visible in this body.

### Observable read and call order

The established sequencing is:

1. Initial selector and conditional payload reads.
2. Conditional receiver-field read and auxiliary call.
3. Fresh selector and conditional payload reads.
4. Conditional callback at table offset `0x124`.
5. Fresh selector and conditional payload reads.
6. Main callback at table offset `0x10C` or `0x110`.
7. Fresh selector and conditional comparison reads.
8. Conditional callback at table offset `0x0E0`.

Within an indirect dispatch, the dispatch-table address is obtained from the receiver before the selected entry is called.

Dependencies may modify data subsequently reread. The contract therefore does not permit treating the initial selector, initial payload address, initial secondary selector, or initial dispatch-table reference as an invocation-wide snapshot.

This describes the logical accesses visible in the supplied representation. It does not establish volatile semantics, atomicity, memory barriers, or a machine-instruction trace for concurrently changing memory.

- F-unresolved-a is skipped if the secondary selector remains `0x2502`.
- F-unresolved-c is then invoked.

- If it returns `-7`, the function returns `-7`.
- Neither main callback nor the final conditional callback is invoked.

- A zero result from that callback produces a final zero return because the outer selector remains `0x16`.

Thus, zero from the early callback means “continue,” not “finish with zero.”

### Special main dispatch

Given outer selector `0x16` and secondary selector `0x2A`:

- F-unresolved-a is skipped.
- F-unresolved-b is invoked instead of F-unresolved-c.
- Its result determines immediate return or continuation.

A secondary selector of `0x2A` does not select F-unresolved-b when the outer selector is not `0x16`.

### Final matching dispatch

Given outer selector `0x0F`, an input field equal to the receiver field at `0x50`, and a zero result from F-unresolved-c:

- F-unresolved-d is invoked.
- Its result is returned if nonzero.
- If it returns zero, the overall result is zero.

If F-unresolved-c returns nonzero, the comparison and F-unresolved-d call are not reached.

### Dependency mutation changes later classification

Given initial outer selector `0x16` and secondary selector `0x2502`, suppose F-4fd087f2325e changes the secondary selector to zero:

- The next stage observes zero and invokes F-unresolved-a.
- Its subsequent behavior depends on its result and any further mutations.

Likewise, if a main callback returns zero after changing the outer selector to `0x0F` and arranging equal comparison fields, the final callback becomes eligible even though the initial selector was different.
