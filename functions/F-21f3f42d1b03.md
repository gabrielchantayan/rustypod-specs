# F-21f3f42d1b03

## Purpose

F-21f3f42d1b03 conditionally processes a caller-supplied object, dispatches to dependencies according to object flags and an input option word, and returns either zero or a 32-bit value read from that object.

The established behavior is a gated state transition followed by an exact selector comparison. It is not established that the return value represents success, an error, a pointer, or a count. Zero can result from several distinct paths, including a successful final comparison when the selected object value is itself zero.

Descriptions such as “flags,” “selector,” and “value” below are behavioral labels for observed fields, not established application-level meanings.

## Interface

### Inputs

The function receives two arguments:

- **Object address:** an address represented by a 32-bit integer in the supplied interface. Zero is explicitly accepted and causes an immediate zero result. Nonzero addresses are used to access object storage without validation.
- **Option word:** an unsigned 32-bit quantity. Bit 3, with mask `0x00000008`, controls an additional branch. A derived option word is obtained by clearing only that bit, using mask `0xFFFFFFF7`.

No other option bits are cleared, truncated, or validated by this function.

### Object storage

The following offsets are relative to the supplied object address:

| Offset | Access width | Established use |
|---|---:|---|
| `0x14` | 32 bits | Conditionally inspected for bit 0; also read as the final returned value |
| `0x1C` | 16 bits | Flags used for entry gating, a direct update, and dispatch |
| `0x1F` | 8 bits | Selector compared with the derived option word |

The selector is interpreted as unsigned and extended to 32 bits for comparison. Its comparison is therefore against the full derived option word, not merely that word’s low byte.

The accesses imply a storage requirement through offset `0x1F` on paths reaching the selector comparison. Other paths may require fewer direct accesses, while dependencies may require additional storage. Alignment, address validity, byte order, and the complete object layout are not established by the supplied material.

### Output

The output is a 32-bit quantity:

- Zero for a null object address.
- Zero when the initially read flags have bit 0 set.
- Zero on the conditional early-return path described below.
- Zero when the final selector comparison fails.
- Otherwise, the 32-bit contents at offset `0x14`, read after the comparison succeeds.

There is no distinct error result established by this interface.

## Behavior

### Entry gate and direct flag update

For a zero object address, the function returns zero without accessing object storage or invoking a dependency.

For a nonzero address, it first reads the 16-bit flags at offset `0x1C`. This initial snapshot controls two decisions:

1. Whether processing is permitted at all.
2. Whether F-be57f04e6ec4 is invoked after the flag update.

If bit 0 of the initial flags is set, the function returns zero. It performs no direct flag write and invokes no dependency on this path.

Otherwise, it writes a 16-bit replacement to offset `0x1C`. The replacement preserves every bit from the initial snapshot and additionally sets bit 1 if bit 4 was set in that snapshot.

Consequences of this update:

- Bit 1 is never cleared by the direct write.
- Bit 4 remains unchanged.
- Every other flag bit is preserved.
- A write occurs even when the replacement equals the original value.
- The replacement is derived from the initial snapshot, not a second flags read.

If bit 11, mask `0x0800`, was set in the initial snapshot, the function next invokes F-be57f04e6ec4 with the object address. This decision is based on the initial flags, even though the direct flag write has already occurred.

The function then reads the 16-bit flags again. This fresh read determines the main dispatch using bit 1. Consequently, effects of F-be57f04e6ec4 on the flags can affect dispatch. The initial bit-0 gate is not repeated, even if a dependency has since set that bit.

### Dispatch when the freshly read bit 1 is clear

When bit 1 of the fresh flags read is clear, the function invokes F-e6e9e68a0990 with:

- The original object address.
- The complete, unchanged 32-bit option word.

Any return value from this dependency is ignored. If the dependency returns normally, execution proceeds to the final selector comparison.

The target function does not directly read the 32-bit field at offset `0x14` before this call on this branch.

### Dispatch when the freshly read bit 1 is set

When bit 1 of the fresh flags read is set, the function first invokes F-98085658bfd4 with:

- The original object address.
- The derived option word, with bit 3 cleared and all other bits retained.

A 32-bit result is received, but it does not determine any subsequent observable decision in this function:

- If input bit 3 is clear, no branch uses that result.
- If input bit 3 is set, the result is replaced by a fresh 32-bit read from object offset `0x14` before the relevant bit test.

The call itself remains part of the required behavior; its effects cannot be discarded merely because its returned value is not consequential here.

If input bit 3 is clear, the function invokes F-94f17d1d24a0 with the object address and then proceeds to the final selector comparison.

If input bit 3 is set, the function reads the 32-bit field at offset `0x14` after F-98085658bfd4 returns:

- If bit 0 of that field is clear, it invokes F-94f17d1d24a0 and proceeds to the final comparison.
- If bit 0 is set, it first invokes F-69bd2f35c00e with the object address.
  - A nonzero result causes an immediate zero return.
  - A zero result allows F-94f17d1d24a0 to be invoked, followed by the final comparison.

The nonzero-result early return bypasses both F-94f17d1d24a0 and the final selector read.

The observed result of F-69bd2f35c00e is a 32-bit signed integer tested only for zero versus nonzero. Negative and positive nonzero results take the same early-return path.

### Final selector comparison and return

Every normally returning dispatch path that has not taken the early return reaches the same comparison:

- Read the unsigned byte at offset `0x1F`.
- Compare its zero-extended value with the full 32-bit derived option word.
- If unequal, return zero.
- If equal, read the 32-bit field at offset `0x14` and return that value.

The returned field value is not a cached value from an earlier access. Dependencies may have changed it, including after the optional bit-0 inspection.

Since the selector is only eight bits wide, equality requires the derived option word to be at most `0xFF`. Clearing bit 3 does not remove any higher bits. Therefore, any input option word with a set bit at position 8 or above necessarily fails the final comparison, although earlier processing and dependency calls still occur.

The derived option word always has bit 3 clear. A selector whose bit 3 is set therefore cannot match it.

Input option words differing only in bit 3 have the same comparison target and the same argument to F-98085658bfd4. They need not have the same overall behavior: bit 3 enables the additional field inspection and possible F-69bd2f35c00e call, and F-e6e9e68a0990 receives the unmodified option word.
