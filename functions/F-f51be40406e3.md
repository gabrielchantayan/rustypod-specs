# F-f51be40406e3

## Purpose

F-f51be40406e3 performs an ordered sequence of indirect dependency invocations, derives scalar and address-like values from their results, mutates memory using several access widths, and finishes with an indirect transfer carrying four represented arguments.

No application-level purpose is established. Character-like constants do not establish formatting behavior; repeated offsets do not establish a particular record, container, or linkage scheme.

This contract distinguishes:

- **Established static evidence:** access widths, computations, value provenance, and ordering represented in the supplied source.
- **Inferred intent:** interpretations not established by those operations.
- **documented_only:** unresolved behavior or a stated limit of this contract.

The contract describes represented behavior, not a validated machine-level execution model. It does not assume that unresolved dependencies preserve globals, return normally, or retain or release memory.

### Arithmetic boundaries

The represented constant left-shift counts reach 31. Masks select fields of several widths, including 24, 22, 21, 20, 19, 18, 17, 16, 14, 13, 12, 11, and one bit.

Unsigned 32-bit operations have 32-bit boundaries. Unsigned left shifts discard bits beyond that width; unsigned right shifts introduce zero high bits. Masking a value constrains selected bits, not memory validity.

Some right shifts operate on a 64-bit combined result before conversion to 32 bits:

- Shifting right by 34 selects the upper portion shifted right by two.
- Shifting right by 36 selects the upper portion shifted right by four.
- Shifting right by 44 selects the upper portion shifted right by twelve.

These must not be treated as 32-bit shifts by those counts.

Many other shifts, multiplications, additions, and subtractions use signed-looking 32-bit quantities. Their overflow and conversion behavior is **documented_only**. Low-32-bit machine arithmetic is a conditional interpretation, not an unconditional guarantee.

Near the end, a signed-looking word is right-shifted by a count obtained from the low eight bits of an address-derived value. That count can exceed 31; neither its machine handling nor the result for negative operands is established.

### Opening direct-memory effects

The direct-access phase uses several retained values:

- A lower dependency-result portion shifted left by 25.
- Another dependency result multiplied by 0x02000000.
- An index obtained by shifting a result left by eight, masking with 0x7FFF, then shifting right by six.
- Twice that index.
- The lower and upper portions of the last combined dependency result.

The opening order is significant. A word at offset 0x14 from the last upper portion receives the retained shift-derived value. A byte at offset 9 from the shift-derived base receives the low byte of that upper portion. A word at offset 0x54 from the last lower portion multiplied by 256 receives the separately scaled base. The earlier offset-9 byte is then overwritten with the low byte of the retained shift-derived value.

Next, a word at offset 0x14 from the separately scaled base is cleared before a byte is read at offset 5 from that base. A word at offset 0x14 from twice the index is cleared before the byte is stored, zero-extended, as a word at offset 0x34 from the scaled base.

The function subsequently reads the scaled-base offset-0x14 word, clears the index-derived offset-0x14 word again, and performs two byte stores of the retained read value at the index-derived offset 0x15.

The word read after the clear must remain a read. Intervening accesses may alias its location; its value is not unconditionally zero.

### Constant stores and repeated publication

A separate base is derived by subtracting 0x96 from an earlier fourfold quantity and multiplying the result by four. This contract calls it the **adjusted base**.

Its offset-0x20 destination receives four ordered word writes: 0x20, 0x2F, a zero-extended byte freshly read from adjusted-base offset 4, and 0x20 again.

**The global word used for later publication is loaded next, before the word store of 0x20 to absolute address 0x60.** Its loaded value is retained as the **publication base**. The later absolute-address store does not cause a reload or replacement of that retained value.

### Final mutation: fresh absolute-0x67 reads

The absolute-0x21 store therefore does not necessarily receive a cached byte from the original absolute-0xA9 word.

- The first occurs after the offset-0x10 word write and a word store at publication-base offset 0x44.
- Before the second read, the function writes a byte at working-base offset 9, writes the retained full absolute-0xA9 word at adjusted-base offset 0x44, and reads a word at adjusted-base offset 0x54.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Masked index

Under defined low-32-bit shift semantics, the masked index lies between 0 and 508 inclusive and is divisible by four. Twice the index lies between 0 and 1016 inclusive and is divisible by eight. Neither bound establishes accessible memory.

### Ordered overwrite and zero-extension

If both opening offset-9 writes are reached, both belong in the trace, in order. If the later byte-to-word conversion reads 0xFE, its word value is 0x000000FE, not a sign-extended value.

### Retained publication base

If the global load yields a publication base and the subsequent absolute-0x60 store changes the global’s backing storage through overlap, subsequent publication addresses still use the already loaded value. Reloading after the store is not equivalent.

### Absolute-0x3A overlap

If the later working-base offset-0x14 read covers absolute address 0x3A, it occurs after the byte store there. Under ordinary-memory semantics, its result must account for that write according to byte order, rather than use a pre-store snapshot.

### Fresh absolute-0x67 observations

If the write to 0x67 supplies 0xA5 but its subsequent fresh read yields 0x5A, the store to 0x21 uses 0x5A. If the two later reads yield 0x11 and 0x22, their respective adjusted-base offset-9 stores use those separate values.

### Repeated writes and interruption

Observable offset-0x20 writes retain the order 0x20, 0x2F, byte-derived word, 0x20. A final-memory comparison is insufficient.

If a dependency does not return, later accesses are not required to occur. If the terminal transfer is reached, its first argument is 0x72 and the other arguments retain their distinct provenance.
