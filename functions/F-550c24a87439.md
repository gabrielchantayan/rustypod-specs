# F-550c24a87439

## Purpose

F-550c24a87439 performs an ordered sequence of four dependency calls, followed by two writes to a destination selected before those calls.

The third dependency receives a fixed address, a value obtained from global storage, and the difference between the results of the first two dependencies. The fourth dependency receives no explicit arguments. After it returns, this function clears the second 32-bit destination field and then assigns a globally supplied value to the first 32-bit destination field.

The available static representation establishes this sequence, but not its application-level purpose. It does not establish that the third call copies memory, that the fourth call performs cleanup, or that the final writes publish a particular named state. Those interpretations must not be treated as requirements.

## Behavior

### Entry and destination capture

The first established operation is a read of the global pointer source. Its value is retained as the destination for both final stores.

This capture occurs before any dependency call. Consequently, a dependency that changes the global pointer source does not, merely by changing that source, redirect the final writes. The final writes use the previously captured destination.

This does not guarantee that the destination remains valid. A dependency could alter, unmap, release, or otherwise invalidate the referenced storage. The supplied representation establishes no protection against such behavior and no ownership rule that would prohibit it.

### Collection of the two arithmetic inputs

F-0b41fd16baac is called first, with no explicit arguments. Its result is retained.

F-461527f65e9e is called second, also with no explicit arguments. Its result is retained separately.

The second call therefore occurs after the first call returns. State changes made by the first dependency may be visible to the second. The contract does not assume that either dependency preserves global state.

The arithmetic input to the third dependency is the first result minus the second result. The operands are not reversed, normalized, clamped, or compared before use.

Following the fourth call, the function performs these updates in order:

1. It stores the 32-bit value zero at byte offset 4 from the captured destination.
2. It obtains the value from the global assignment source and stores that value as a 32-bit unit at byte offset 0 from the captured destination.

- The fourth dependency is called after the third returns.

The third argument is −60. The visible function does not clamp it to zero or skip either later call because it is negative. Whether the third dependency accepts that value is unknown.

### Pointer source changed during a dependency

Assume the entry capture selects destination A. A dependency then changes the global pointer source to destination B, while A remains valid.

The final two stores still target A. They do not reload the pointer source to select B.

### Global argument changed before the third call

Assume either of the first two dependencies changes the global argument source.

The third call uses the value read after those dependencies return, not a value implicitly captured at entry. If both dependencies modify it, the relevant value is the one present at the actual read.

### Assignment source changed by the fourth dependency

Assume the fourth dependency updates the global assignment source and returns normally.

The final offset-0 store uses the value read after that update and after the offset-4 zero store. It does not use an earlier snapshot.

### Overlapping assignment source

Assume the global assignment source denotes the same four bytes as destination offset 4, with ordinary compatible memory semantics.

The zero store precedes the assignment-source read. Consequently, the value subsequently stored at destination offset 0 is zero. This example is conditional on the overlap; the representation does not establish that such overlap occurs.

If the fourth dependency does not return normally, the final stores are likewise not reached through normal continuation.

No recovery behavior is specified.
