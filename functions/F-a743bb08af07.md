# F-a743bb08af07

## Purpose

F-a743bb08af07 conditionally copies a descriptor’s leading 32-bit value and a bounded sequence of 32-bit payload words to another descriptor.

An initial calculation combines the source descriptor’s leading value with a shared multiplier. The magnitude of that product controls both admission and the number of payload words copied. A magnitude greater than 28 produces return value 1 without destination writes. An admitted operation returns 0.

When the source and destination descriptor addresses are identical, the function performs the admission calculation but does not copy descriptor or payload storage.

The interpretation of the leading value and shared multiplier is not established. They may encode a logical length and a conversion factor, but that is inferred intent, not part of the established contract.

## Interface

### Inputs

The function receives two descriptor addresses:

- **Source descriptor:** identifies the leading value used in the admission calculation and, when copying occurs, the payload address.
- **Destination descriptor:** identifies storage for the copied leading value and supplies the destination payload address.

The accessed descriptor layout is:

| Byte offset | Width | Observed role |
|---|---:|---|
| 0 | 32 bits | Signed value used in the source-side multiplication; copied to the destination on an admitted, distinct-descriptor operation. |
| 4 | 32 bits | Address-bearing field identifying payload storage. Read for payload accesses; not explicitly copied. |

No larger descriptor layout is established. Additional fields, if present, are not directly accessed.

Payload elements are opaque 32-bit words. Their arithmetic interpretation is irrelevant to the copy.

A shared scalar multiplier is an implicit input. Its storage location, initialization, valid range, and mutability are not specified by the supplied evidence. It participates in the displayed signed-integer multiplication.

### Output

The function returns a 32-bit result:

| Value | Meaning |
|---|---|
| 0 | The admission check passed. Copying occurred if the descriptors were distinct, subject to the zero-length case. |
| 1 | The calculated magnitude exceeded 28. No destination writes were initiated. |

No other ordinary return value appears in the supplied representation. Faults and arithmetic behavior outside established representable cases do not have a specified return value.

### Preconditions

For an ordinary, defined execution:

- The source leading field must be readable.
- The shared multiplier must be readable.
- The multiplication and any required negation must have defined behavior in the execution model.
- For an admitted operation with distinct descriptors, the destination leading field must be writable.
- If the calculated payload length is nonzero, both address-bearing fields must be readable, and every accessed payload word must be readable or writable as appropriate.
- Payload address calculations must designate valid memory under the target’s address representation.

There is no explicit null-pointer, alignment, allocation-size, or payload-capacity check.

A destination need not be dereferenceable on the rejection path or on an admitted identical-descriptor path, because neither path accesses destination storage separately. That does not relax the source leading-field requirement: admission is calculated before descriptor identity is considered.

## Behavior

### Admission calculation

The function reads the source leading value and the shared multiplier and forms their product. The displayed representation uses signed 32-bit integer arithmetic.

For products whose multiplication and magnitude calculation are representable, define the **calculated length** as the nonnegative magnitude of that product.

- A calculated length greater than 28 is rejected immediately with return value 1.
- A calculated length from 0 through 28, inclusive, is admitted.

The function does not independently validate either multiplication operand. A large source value can therefore be admitted when the multiplier is zero. Negative source values or negative multipliers can also be admitted when the resulting magnitude is within the bound.

The relative order of the source-field read and the shared-multiplier read within the multiplication expression is not established. Both contribute to admission before any explicit destination write.

### Descriptor identity

After admission, the function compares the two descriptor addresses.

If they are identical, it returns 0 without copying the leading field or accessing payload fields. Identity does not bypass admission: identical descriptors still produce return value 1 when the calculated length exceeds 28.

Only descriptor-address identity is checked. The function does not compare payload addresses or detect overlapping payload regions.

### Leading-field copy

For admitted, distinct descriptors, the function reads the source leading field again and writes that value to the destination leading field.

Consequently, the value copied into the destination is not necessarily the same read that supplied the admission calculation. If the source changes between those reads, the calculated length and the copied leading value can reflect different source states. No synchronization or consistency mechanism is shown.

Only the leading field is explicitly copied. The destination retains its existing payload-address field unless a payload write later aliases and changes it.

### Payload copy

After the leading-field write, the function copies exactly the calculated number of 32-bit words, assuming all accesses complete normally.

The copy proceeds in descending index order:

- For length 28, the first transferred word is index 27.
- For any positive length, the final transferred word is index 0.
- For length 0, no payload word or payload-address field is accessed.

Each payload index denotes a byte displacement of four times that index from the corresponding payload address. Thus an admitted positive-length copy explicitly transfers at most 112 payload bytes.

For each iteration, the source word supplies the value written to the destination word. The payload-address fields are referenced by the loop’s access expressions rather than being explicitly cached before the loop. The contract therefore does not assume that the payload bases remain fixed if earlier writes change those fields through aliasing.

The precise evaluation order of the source and destination address expressions within an iteration is not established by the supplied representation. Successful transfer of a word requires reading its source value before completing the corresponding destination write, but that does not establish a total ordering of all address-field reads.

After the final word transfer, the function returns 0.

### Arithmetic boundaries

The admission bound limits ordinary payload index arithmetic: admitted indices range from 0 through 27, and their byte displacements range from 0 through 108. These index displacements fit in a signed 32-bit integer.

That bound does not prove that the initial multiplication is safe. A product outside the signed 32-bit range requires an execution-model rule not supplied here.

The magnitude calculation also has a special boundary: the minimum signed 32-bit value, −2,147,483,648, has no positive counterpart representable in signed 32 bits. Its negation must not be assumed to behave like a mathematical absolute value. Overflow and minimum-value cases are **documented_only** rather than assigned guessed return values or copy lengths.

## Side effects

On a representable-product rejection, the function performs the admission-related reads and returns 1. It does not explicitly write either descriptor or payload storage and does not access the payload-address fields.

On an admitted identical-descriptor operation, it returns 0 without explicit memory writes or payload accesses.

On an admitted distinct-descriptor operation, the explicit write order is:

1. Write the source’s reread leading value into the destination leading field.
2. Write payload words in descending index order.

No rollback is shown. If an access fails after the leading-field write or after some payload writes, earlier writes may already be visible. There is no established exception-handling or recovery contract.

The function contains no explicit allocation, deallocation, ownership transfer, or reference-count operation. Successful copying does not establish independent ownership of the payload. The descriptors’ address-bearing fields are not intentionally replaced.

For conventional non-overlapping storage, source descriptor fields and source payload words are only read. With aliasing, destination writes may affect memory that also serves as source data, descriptor metadata, or shared state. The initial calculated length remains based on the admission calculation; subsequent metadata changes do not trigger a new admission check.

No explicit shared-multiplier write is shown. A destination payload address could nevertheless designate its storage. Non-aliasing must be a caller precondition if such modification must be excluded.

## Acceptance examples

These are conditional expectations derived from static evidence, not runtime test results. Except where stated otherwise, they assume representable arithmetic, stable inputs, valid addresses, and descriptor metadata disjoint from payload writes.

### Positive product within the limit

Given a source leading value of 3 and a multiplier of 2, the calculated length is 6.

For distinct descriptors, the function returns 0, copies the leading value 3, and transfers payload indices 5 through 0 in that order. The destination payload-address field is unchanged.

### Negative product within the limit

Given a source leading value of −4 and a multiplier of 2, the calculated length is 8.

The function copies the leading value −4, not 8. It transfers payload indices 7 through 0 and returns 0. The copied metadata value and payload length have different roles.

### Exact admission boundary

A representable product of either 28 or −28 is admitted. Distinct descriptors cause 28 word transfers, descending from index 27 to index 0.

A representable product of 29 or −29 is rejected with return value 1 and no destination writes.

### Zero-length operation

Given a source leading value of 9 and a multiplier of 0, distinct descriptors produce return value 0 and a destination leading value of 9.

No payload-address field or payload word is accessed. An unusable payload address alone therefore does not prevent this path from completing, provided the required leading-field accesses are valid.

### Identical descriptors

If both arguments designate the same descriptor and the calculated length is 12, the function returns 0 without payload access.

If both designate the same descriptor and the calculated length is 30, the function returns 1. Identity does not override rejection.

### Direction-sensitive overlap

Suppose four source words occupy consecutive positions containing A, B, C, D, and the destination payload begins one word above the source payload. With a calculated length of 4, descending transfers preserve those four original values at the destination.

If instead the destination begins one word below the source, descending copying is not generally safe. Under that layout, each write can overwrite the source word needed by the next iteration. With the stated initial values, all four destination positions can become D. The function does not promise general overlap-safe copying.

### Failure after metadata update

For distinct descriptors with a positive admitted length, an invalid payload address may fail only after the destination leading field has been written. The contract does not promise that a failed operation leaves the destination unchanged.
