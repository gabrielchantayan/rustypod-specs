# F-40a2c7f59981

## Purpose

F-40a2c7f59981 initializes a caller-supplied descriptor, conditionally rescales its count to a unit size of 512, updates shared state, invokes a preparation dependency, checks two numeric conditions, and invokes a final dependency if those checks pass.

The established contract consists of memory accesses, arithmetic, dependency calls, and status returns. Interpreting count multiplied by unit size as a byte capacity is plausible intent, not established domain semantics.

Failure is not transactional. Descriptor initialization precedes every locally generated error. Preparation failures and numeric-check failures occur after a shared-state write. No direct rollback or cleanup is visible.

### Return value

The result is a 32-bit status.

| Status | Meaning established by this function |
|---|---|
| 0 | The final dependency was called and returned control. |
| 0x50, decimal 80 | The original unit size was neither 512 nor an exact multiple of 512. |

## Behavior

### Initial writes and derived scalar

The function first writes the descriptor in this order:

1. Original unit size at offset 0.
2. Original initial-count bit pattern at offset 16.
3. The initial count’s sign-extension word at offset 20.

The high count word is zero when the initial count is below 2³¹ and 0xFFFFFFFF otherwise.

It then calls F-d7be9cfb4000 with the 32-bit arguments 131,072 and the original unit size. After that call returns, its 32-bit result is stored at offset 8.

This call occurs even for a unit size that will subsequently be rejected. Its result is treated as a scalar, not a status; no returned bit pattern causes an immediate error.

The first dependency may have other effects. In particular, preservation of descriptor fields, globals, or other reachable storage is not established.

### Unit-size eligibility and normalization

The eligibility decision uses the original unit-size argument, not a reread of descriptor offset 0.

If the original unit size is 512, the function skips normalization. It does not restore the count or unit-size fields if the first dependency changed them through another access path.

Otherwise, the original unit size must have its low nine bits clear. If any of those bits are set, the function returns 80 immediately. The initial descriptor writes and derived-scalar store have already occurred; the reset-field write and later dependencies have not.

For an eligible unit size other than 512, define the unsigned scale as the original unit size divided by 512. This division is implemented by an unsigned nine-bit right shift. The maximum possible scale is 0x7FFFFF.

Normalization performs these writes in order:

1. Replacement low count word at offset 16.
2. Replacement high count word at offset 20.
3. Replacement derived scalar at offset 8.
4. Unit size 512 at offset 0.

The normalized count equals the initial count interpreted as a signed 32-bit integer, multiplied by the unsigned scale, represented in two 32-bit words. This multiplication fits within signed 64-bit range for all eligible inputs.

Equivalently, let \(A\) be the unsigned initial-count bit pattern, \(S\) the scale, and \(E\) the initial sign-extension word. The low count word is the low 32 bits of \(A S\). The high count word is:

\[
\bigl(\lfloor AS / 2^{32}\rfloor + SE\bigr) \bmod 2^{32}.
\]

Normalization uses the original initial count and the saved first-dependency result, rather than values reread from those descriptor fields. The replacement derived scalar is the first-dependency result multiplied by the scale, modulo 2³². Overflow is not rejected.

Zero satisfies the local multiple-of-512 condition. For an original unit size of zero, if the first dependency returns normally, normalization writes zero into both count words and the derived scalar, then writes 512 into the unit-size field.

### Reset and shared-state update

After either skipping normalization for an original unit size of 512 or completing normalization, the function clears descriptor offset 4.

It then calls F-48a3dae42ee4 with the single 32-bit argument 1.

**After that dependency returns, the function reads the global reference supplying the shared-state base.** It writes the dependency’s 32-bit result at byte offset 0x4C from that current base.

The observable sequence is therefore:

1. Clear descriptor offset 4.
2. Call F-48a3dae42ee4.
3. Read the global reference supplying the shared-state base.
4. Store the returned value at the current base plus 0x4C.
5. Read descriptor arguments for the preparation call.

A base captured before F-48a3dae42ee4 is not equivalent. If that dependency changes the global reference, the subsequently read base determines the destination.

The returned value is not validated locally. Zero does not cause immediate failure. Its interpretation as a resource, pointer, handle, index, or ordinary scalar is unknown.

The source does not establish that the destination is disjoint from the descriptor. If the shared-state write overlaps descriptor fields, this function’s own write can change values consumed by later calls and checks, even when no dependency directly changes the descriptor.

### Preparation call and failure precedence

F-103c378ce6b9 receives four 32-bit arguments:

1. Current low count word.
2. Current high count word.
3. Current unit-size field.
4. Preparation context.

The descriptor values are read after the shared-state write. They are not guaranteed to equal the initialization or normalization results.

If preparation returns a nonzero status, that status is returned unchanged. The product check, divisibility check, and final dependency are not reached.

If preparation returns zero, the numeric checks read descriptor fields after that call. The descriptor is not explicitly passed to preparation, but access through aliases or shared state remains possible. No preservation guarantee is established.

### Product threshold

For descriptor fields that remain stable during this calculation, let:

- \(L\) be the unsigned low count word;
- \(H\) be the unsigned high count word;
- \(U\) be the unsigned unit-size field.

The checked product is:

\[
P = \bigl((H \cdot 2^{32} + L)U\bigr) \bmod 2^{64}.
\]

Its low word is the low 32 bits of \(LU\). Its high word is:

\[
\bigl(HU + \lfloor LU / 2^{32}\rfloor\bigr) \bmod 2^{32}.
\]

The function returns 81 exactly when the product’s high word is zero and its low word is less than 0x80000, decimal 524,288. Equality passes.

This is a truncated 64-bit arithmetic comparison, not a comparison of an unbounded mathematical product. There is no separate overflow rejection. A count with a signed-negative interpretation is not rejected merely for that reason: a nonzero product high word passes this threshold check.

### Count divisibility

After the product check passes, the function returns 82 exactly when both conditions hold:

- The current high count word is nonzero, or the current unsigned low count word is greater than 0x3FFFFFFF.
- At least one of the current low count word’s bottom three bits is set.

Thus, a count whose high word is zero and whose low word is at most 1,073,741,823 is exempt from the divisibility requirement. The boundary itself is included.

Other count representations must have their low word divisible by eight. A nonzero high word alone is not grounds for rejection.

### Final call and success

After both numeric checks pass, F-988f729c43e0 receives:

1. Current low count word.
2. Current high count word.
3. Current unit-size field.
4. Final context.

The function does not inspect a result from this dependency. If it returns control normally, F-40a2c7f59981 returns zero.

Success therefore means completion of the visible sequence, not independently established success inside the final dependency.

The descriptor is read separately across stages. The source does not establish an atomic snapshot or a total order among all reads within an individual argument list or compound expression. The arithmetic descriptions above assume stable fields during the relevant calculation.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests.

Unless an example explicitly overrides an assumption:

- All dependencies return normally.
- Dependencies do not alter descriptor fields, directly or indirectly.
- Preparation returns zero.
- The shared-state store does not change descriptor values used by subsequent calls or checks.
- No concurrent interference changes relevant fields or references.
- All required memory accesses are valid.

The shared-state-store assumption is independent of dependency preservation. A dependency can leave the descriptor untouched while its returned value is subsequently written into overlapping descriptor storage by this function.

1. **Invalid unit size.** Initial count 1,024 and unit size 513 produce status 80. The first dependency has already run and its result has been stored at offset 8. This function does not clear offset 4 or invoke any later dependency.

2. **Below threshold.** Initial count 1,023 and unit size 512 produce a checked product of 523,776. The reset, shared-state update, and preparation call occur before status 81. The final dependency is not called.

3. **Exact threshold.** Initial count 1,024 and unit size 512 produce 524,288. Both checks pass, the final dependency is called, and the function returns zero.

4. **Normalization.** Initial count 512 and unit size 1,024 produce normalized count 1,024 and unit size 512. If the first dependency returns \(R\), the derived scalar becomes \(2R \bmod 2^{32}\). The product meets the threshold exactly.

5. **Zero unit size.** If the first dependency returns normally for zero, normalization produces zero count words, a zero derived scalar, and unit size 512. Under the remaining assumptions, preparation succeeds and status 81 follows. The first dependency’s behavior for zero is unknown.

6. **Divisibility boundary.** With unit size 512, initial count 0x3FFFFFFF passes despite not being divisible by eight. Initial count 0x40000001 returns 82. Initial count 0x40000000 passes.

7. **Sign-extended count.** Initial count bit pattern 0xFFFFFFF8 and unit size 512 produce high count word 0xFFFFFFFF. The product high word is nonzero, and the low count word is divisible by eight. Both checks pass.

8. **Preparation failure precedence.** With initial count 1 and unit size 512, a preparation status of 37 overrides the default zero-status assumption and is returned as 37. The otherwise applicable product failure is not evaluated.

9. **Changed shared-state base.** If F-48a3dae42ee4 changes the global base reference from one valid base to another, the returned value is stored at the new base plus 0x4C. The old base does not determine this store’s destination.

10. **Shared-state overlap changes the outcome.** Override only the noninterference assumption for the shared-state store. Let initial count be 1,023 and initial unit size be 512. Suppose the current shared-state destination aliases descriptor offset 0, and F-48a3dae42ee4 returns 1,024. The store changes the descriptor unit size to 1,024 before preparation. With preparation returning zero without mutation, the product is 1,047,552, both checks pass, and the final dependency receives unit size 1,024. Status 81 from example 2 no longer follows.
