# F-224873eea2ed

## Purpose

F-224873eea2ed selects one of two dependencies using a discriminator stored inside an input object. It passes the selected dependency the object’s base address and an eight-bit selector extracted from a 16-bit field. If that dependency returns a non-null object, F-224873eea2ed invokes an indirect operation associated with the returned object and returns that operation’s result unchanged.

An unsupported discriminator or a null dependency result produces a zero result without an indirect invocation.

The established behavior is dispatch and result forwarding. The domain meaning of the discriminator values, selector, returned object, and final result is unknown.

## Interface

### Input

The function accepts one argument, represented in the supplied source as a 32-bit integer used as a memory address. This contract calls it the **input base**.

Relevant locations are:

| Location relative to input base | Access | Meaning established by the source |
|---|---|---|
| `0x90` | Signed eight-bit read | Dispatch discriminator |
| `0x94` | Unsigned 16-bit read | Selector source; only its low eight numeric bits are passed onward |
| `0x90` | Address passed to the indirect operation | Interior address within the original input object |

The discriminator comparisons correspond to these byte patterns under the represented eight-bit signed interpretation:

- `0xA2`, interpreted as −94, selects F-74af3c64851d.
- `0xA1`, interpreted as −95, selects F-7c98cdf9320e.

The input is not established to be a string, array, or object of a known public type. No overall object size is supplied. On a path that reads the selector, the complete 16-bit storage unit at offset `0x94` must be accessible, even though the subsequent mask discards half its numeric value.

### Output

The result is an opaque 32-bit value.

- Unsupported discriminator: zero.
- Selected dependency returns null: zero.
- Selected dependency returns non-null: the indirect operation’s 32-bit result, unchanged.

Zero is therefore ambiguous. It can indicate either an early exit or a zero result from an indirect operation that was actually invoked. The wrapper supplies no separate status distinguishing those cases.

These conditions are not checked by F-224873eea2ed. A null input base is not explicitly rejected.

## Behavior

### Discriminator selection

The function first reads the signed byte at input offset `0x90` and compares it with −94.

If it matches, F-74af3c64851d is selected. The alternative-discriminator check is skipped.

If it does not match, the source expresses another read of the same byte and compares that value with −95:

- A match selects F-7c98cdf9320e.
- A mismatch returns zero immediately.

For a stable input byte, this accepts exactly the byte patterns `0xA2` and `0xA1`.

The two discriminator expressions must not be silently replaced in the contract with one cached observation. If the underlying byte can change between them, the source-level selection depends on the value observed by each expression. Whether two distinct physical loads occur, and whether asynchronous mutation has defined semantics, is not established by the supplied material.

### Selector extraction and dependency call

After selecting a dependency, the function reads an unsigned 16-bit value at input offset `0x94` and retains only its low eight numeric bits. The resulting selector is in the inclusive range 0–255.

The selected dependency receives two arguments, in this order:

1. The original input base.
2. The selector.

The selection does not alter either value before passing it onward, apart from the selector mask.

The extraction is numeric, not an established instruction to read the byte at offset `0x94`. Which addressed byte contributes the low eight bits depends on the target’s byte order. The complete 16-bit read remains part of the represented behavior.

Only one of the two dependencies is called during an invocation. There is no fallback from one dependency to the other if the selected dependency returns null.

### Null-result handling

The selected dependency’s result is treated as an object address and compared with null.

If it is null, F-224873eea2ed returns zero. It does not attempt to read an operation table or invoke an indirect operation on that path.

The null check does not establish that any non-null result is valid. No type, extent, alignment, or operation-table validation is shown.

### Indirect invocation

For a non-null dependency result, the function performs the following dependent accesses:

1. It reads the first 32-bit word of the returned object.
2. It uses that value as the base address for an operation entry at byte offset `0x20`.
3. It reads the callable address stored at that entry.
4. It invokes that callable with two arguments:
   - The dependency-returned object address.
   - The address equal to the original input base plus `0x90`.

The second argument is an address, not a copy of the discriminator or selector. It identifies the same interior location used for the discriminator reads. The extent and interpretation of memory available through that argument are unknown.

The table entry is obtained after the selected dependency has returned. Its value is not established to come from any state that existed before that dependency call.

The indirect operation’s result becomes the function’s result without masking, normalization, or a separate success check.

### Completion and exceptional paths

The shown wrapper has no explicit retry, recovery, error translation, or cleanup path. If a dependency or the indirect operation does not return normally, normal completion of F-224873eea2ed is not established.

There is no explicit handling for unreadable memory, malformed returned objects, invalid operation-table addresses, or invalid callable entries.
