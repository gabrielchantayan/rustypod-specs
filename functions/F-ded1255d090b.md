# F-ded1255d090b

## Purpose

F-ded1255d090b performs an ordered sequence of indirect calls interleaved with three explicit memory writes. Results from selected calls determine a scaled-address word write, two byte writes, and arguments to later calls.

The available static evidence does not establish an application-level purpose. In particular, it does not identify the affected memory as a device register, buffer, object, table, or allocator-managed region. Such interpretations are **documented_only**, not behavioral guarantees.

The visible sequence ends at a reported bad-instruction boundary rather than an ordinary return. Its completeness and reachability are therefore uncertain. This contract describes the visible prefix, conditional on execution following the represented control flow and each preceding operation completing.

## Behavior

### Dependency naming

The opaque dependency IDs below identify call occurrences in execution order. They do not establish that the underlying callees are distinct functions. Each ID is a local contract label for an unresolved target.

### 1. Initial calls and word write

1. Invoke **F-100000000001**. Its target is calculated from the incoming link-context value with an added displacement of `0xFFE`. No explicit arguments or consumed return value are shown.
2. Invoke **F-100000000002** and retain its returned four-byte value as the **initial index result**.
3. Scale that result by four and add `0x14` to obtain the first explicit write address.
4. Write the incoming word to that address as a 32-bit value.
5. Invoke **F-100000000003**, passing the initial index result scaled by four.

No explicit memory read supplies the incoming word immediately before this write; it is an incoming machine-state value in the representation.

The address calculation is based on the returned result itself, not on the incoming context base. No bounds check is visible. The representation does not establish how signed multiplication overflow, address overflow, misalignment, or an invalid address behaves.

### 2. Acquisition of the retained unsigned result

Invoke these dependencies in order:

1. **F-100000000004**
2. **F-100000000005**
3. **F-100000000006**
4. **F-100000000007**

No explicit arguments are shown for these calls. Retain the 32-bit unsigned return value of **F-100000000007** as the **retained result**.

Earlier unused call results do not imply absence of side effects.

### 3. First byte write and three-argument call

Calculate the retained result shifted left by two bits. For the unsigned 32-bit operation, bits shifted beyond the 32-bit width are discarded.

Then, in the visible order:

1. Read an unsigned byte from the incoming context base plus one.
2. Add `0x11` to that byte’s numeric value.
3. Write the low eight bits of the retained result shifted left by two to the resulting address.
4. Invoke **F-100000000008** with three explicit arguments:
   - The retained result shifted left by two.
   - The same shifted value again.
   - The retained result shifted left by four.

Thus, the byte written is the retained result multiplied by four modulo 256. Its low two bits are always zero.

The read byte is used directly as a numeric address component. The destination is not shown as the incoming context base plus another displacement. Since the byte ranges from 0 through 255, the resulting destination address ranges from `0x11` through `0x110`, inclusive.

The first two call arguments have the same 32-bit bit pattern. The third is independently formed from the retained result; it is not calculated from a narrower stored byte.

### 5. Second byte read and write

After **F-100000000014** returns:

1. Read an unsigned byte again from the incoming context base plus one.
2. Retain this second byte for a later call.
3. Add `0x11` to the second byte’s numeric value.
4. Write a byte to that address, derived from the retained result as follows:
   - Keep its low 30 bits.
   - Shift that masked value right by 20 bits.
   - Store only the low eight bits of the result.

The intermediate shifted value can range from 0 through 1023. Narrowing it to a byte means the stored value consists of bits 20 through 27 of the retained result. Bits 28 and 29 can affect the intermediate value but are discarded by the byte write; bits 30 and 31 are removed by the mask.

The retained result comes from **F-100000000007**. The second stored byte does not derive from the middle index result.

The second context-byte read is independent of the first. There are seven dependency calls between the two reads, and those dependencies have unknown effects. The two destination addresses therefore need not match.

### 6. Final calls

2. Invoke **F-100000000016**.
3. Invoke **F-100000000017**.
4. Invoke **F-100000000018**.
5. Invoke **F-100000000019** and retain its returned value as the **final index result**.
6. Invoke **F-100000000020** with:
   - The final index result shifted left by two.

No explicit arguments are shown for **F-100000000016** through **F-100000000019**, or for **F-100000000021**.

The byte supplied to **F-100000000020** is the saved second read. No third context-byte read is shown before that call. Consequently, intervening memory changes do not, by themselves, change that saved argument.

## Side effects

| First | 32 bits | Four times the initial index result, plus `0x14` | Incoming word |
| Second | 8 bits | First context byte plus `0x11` | Low eight bits of the retained result shifted left by two |
| Third | 8 bits | Second context byte plus `0x11` | Bits 20–27 of the retained result |

These operations may alias. For example, a byte-write destination may overlap the context-byte address or the earlier word-write region. The visible sequence has no alias detection or special handling. The word write’s byte order is not established. Its width is established as four bytes, but the supplied evidence does not define the processor’s endianness or unaligned-access behavior.

No explicit allocation, release, reference-count change, or ownership transfer is visible. This does not prove that dependencies perform none. In particular:

- The four-byte value passed between **F-100000000009** and **F-100000000010** is not proven to be a pointer.
- If it is a pointer, ownership and lifetime rules remain unknown.
- No dependency may be assumed to preserve globals, memory, or unspecified machine state.

No rollback or explicit error recovery is visible. If execution stops during a later operation, earlier completed writes and dependency effects are not shown being undone.

### Scaled word destination

This example avoids signed-overflow and address-wrap ambiguities.

### Byte extraction and call arguments

- The first byte destination is `0x31`.
- The stored byte is `0x9C`.
- **F-100000000008** receives bit patterns `0x048D159C`, `0x048D159C`, and `0x12345670`.

If the second context-byte read also returns `0x20`, the second byte write goes to `0x31` and stores `0x12`. It replaces the earlier byte at that address, assuming no intervening effect changes the relevant memory semantics.

### Changed destination selector

If the first context-byte read returns `0x02` and the second returns `0x07`, the two byte-write destinations are `0x13` and `0x18`.

**F-100000000020** receives 7 as its second explicit argument, even if a dependency changes the context byte again after the second read.

### Intermediate-width truncation

If the retained result is `0x3FF00000`, masking and shifting for the second write produces 1023, but the stored byte is `0xFF`, not a multi-byte representation of 1023.

If the retained result is `0xC0000000`, both explicit byte values are zero: the first shift has zero low eight bits, and the second calculation masks away the two set high bits.

### Interrupted execution

If **F-100000000010** does not return, the later dependencies and second byte write are not reached through the visible sequence. The earlier word write and first byte write have already occurred; no visible recovery reverses them.
