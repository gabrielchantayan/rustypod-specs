# F-78b81dd22688

## Purpose

F-78b81dd22688 performs an ordered sequence of indirect calls, derives values from their results and implicit execution state, mutates memory through computed addresses and fixed-location symbols, and ends with an unresolved indirect transfer.

No domain-level purpose is established. Constants that resemble characters do not establish text generation, formatting, serialization, or an encoding. Repeated offsets do not establish object boundaries or a recovered data structure.

This contract distinguishes:

- **Established static evidence:** exchanges, dependencies, conversions, and access ordering explicitly represented in the supplied body.
- **Inferred intent:** possible interpretation, not an acceptance requirement.
- **documented_only:** behavior that the supplied material does not resolve, or that this contract does not fully enumerate.

“Publication” below names a repeated group of stores. It implies neither synchronization nor a domain-specific protocol.

## Behavior

The opening phase is a long, straight-line sequence of indirect calls. No explicit input-dependent branch, loop, or early return is represented.

The first call receives the first input. Two calls with no represented explicit arguments follow. The next call receives the incoming execution-state word shifted left by 3 and the fourth input shifted left by 25.

Later boundaries exchange 32-bit results, lower and upper 32-bit portions of 64-bit results, and additional call-associated state. Arguments include shifted or masked values, duplicate arguments, and explicit zeros. Calls with no represented arguments remain interspersed throughout.

### Numeric widths and storage widths

Explicit computed dereferences establish accesses of 8, 16, or 32 bits at their respective sites. Represented result manipulation also uses 64-bit quantities.

**A fixed-location symbol’s declaration is not supplied.** Consequently, a conversion applied to its value, or to an expression assigned to it, does not establish the underlying object’s access width. This distinction applies consistently to every fixed-location symbol discussed below, including the publication-base source.

Established numeric properties include:

- Selecting the lower or upper half of a 64-bit result produces a 32-bit portion; this does not establish memory byte order.
- An explicit unsigned 8-bit read widened to 32 bits yields 0–255.
- Explicit 8-bit computed destinations retain eight bits; explicit 16-bit destinations retain sixteen bits.
- A low-20-bit field logically shifted right by 10 is in 0–1023.
- Low-24-, low-22-, and low-19-bit fields have maxima 16,777,215, 4,194,303, and 524,287 before subsequent transformations.

Under 32-bit bit-vector semantics, sequential shifts retain intermediate truncation. Left by 8 followed by logical right by 8 retains only the original low 24 bits. Some cumulative left-shift sequences would yield zero under that interpretation.

These are conditional arithmetic properties, not unconditional guarantees for represented signed operations. Signed shifts, multiplication, addition, and address scaling may overflow; target overflow and address-wrap behavior are **documented_only**.

A late explicit 8-bit destination receives a truncated signed right-shift result. The shift count is the low eight bits of a computed word, potentially 0–255. Behavior for negative operands and counts at least 32 is unresolved.

### Opening mutations and linked accesses

Direct memory mutation begins after the call phase, without a represented validation boundary.

The opening mutations include a 32-bit store through an address derived from an upper result half plus 0x14, an 8-bit store at another base plus 9, a scaled 32-bit store at offset 0x54, and a second 8-bit store overwriting the offset-9 destination.

An early computed base is zeroed at offset 0x14. An explicit unsigned 8-bit read at that base plus 5 is saved. A separate computed 32-bit destination is then zeroed before the saved byte is widened and stored at the first base plus 0x34. The first base’s offset-0x14 word is subsequently read.

That read need not return zero: intervening computed stores may overlap the zeroed storage. The separate zero destination is written again after the read. Repeated explicit 8-bit stores at another computed offset-0x15 destination are distinct represented events.

The value associated with fixed location 0x05 is converted to unsigned 32 bits and used as a numeric base. Its original read width, signedness, and conversion details are **documented_only**. It is not established to be an unsigned-byte load.

After that capture, the symbol associated with 0x01 receives an explicitly eight-bit-converted value derived from a doubled computed value. Later, the symbol associated with 0x15 receives another explicitly eight-bit-converted value. Neither assignment establishes an 8-bit store to the symbol.

The converted 0x05 value participates in an explicit 8-bit computed store at offset 0x15 and a 32-bit computed read at offset 0x54. The read value is saved before that same computed offset-0x54 destination is overwritten.

The linked phase reuses loaded words as numeric addresses, writes self-derived values, doubles or quadruples loaded values, and interleaves 8-bit and 32-bit computed stores. The symbol associated with 0x54 receives a doubled saved value; the expression’s represented width does not establish the symbol’s store width.

An explicit unsigned-byte read at a computed offset 5 supplies the numeric base for a 32-bit read at offset 0x74. No additional lookup or validation is represented.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Input forwarding.** If the first boundary is reached, its represented argument preserves the first input’s 32-bit pattern.

2. **Proven unsigned-byte widening.** If an explicit computed offset-5 byte read returns 0xfe, its widened value is 254, not −2. This does not establish the read width of the separate symbol associated with 0x05.

3. **Computed-destination truncation.** An explicit computed 8-bit destination receiving 0x123456ab stores pattern 0xab. This rule does not establish an 8-bit destination for a fixed symbol assigned an eight-bit-converted expression.

4. **Sequential shifts.** Under 32-bit bit-vector semantics, left by 8 followed by logical right by 8 maps 0xab123456 to 0x00123456.

5. **Publication-base capture.** If the publication-base capture yields address 0x1000, the run uses that captured value. A later overlapping store does not establish a recapture. The source symbol’s original read width remains unresolved.

6. **Post-publication capture.** If publication changes storage contributing to the 0xa9 symbol’s value, the saved 32-bit value is obtained from the subsequent symbol read and conversion. It is not necessarily a four-byte read beginning at 0xa9. Capture precedes the next computed offset-0x74 read and the 0x3a assignment.

7. **Conditional byte interpretation of 0x67.** If the missing declaration establishes an unsigned 8-bit object at 0x67, the saved value is 0x123456ab, and nothing changes that object after initialization, later symbol reads yield 0xab. Copying this value to 0x21 still does not establish that destination’s width.

8. **Conditional aliasing at 0x67.** Under that same unsigned-byte declaration, if an intervening computed store changes the object to 0xcd before a later read, that read supplies 0xcd. An explicit computed 8-bit destination receiving it stores 0xcd. The saved 32-bit value remains 0x123456ab.

9. **Unknown fixed-store extent.** Assigning numeric 0x20 to the symbol associated with 0x60 does not, without its declaration, establish which four bytes are overwritten. The assignment’s position after publication-base capture remains required.

10. **Observable overwrites.** The explicit shared computed word destination receives 0x20, then 0x2f, then a widened loaded byte, then 0x20. Final-state equality alone is insufficient for trace equivalence.

11. **Termination.** Reaching the final destination establishes that preceding represented direct accesses were reached in order, not that the destination returns successfully.
