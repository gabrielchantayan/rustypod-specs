# F-d8c26e64838f

## Purpose

F-d8c26e64838f constructs an object from an input record, presents that object to an optional collection of handlers, and, if no collection handler returns a nonzero result, traverses a fallback structure. It returns the first nonzero handler result, or zero when dispatch terminates without one.

“Construction,” “handler,” “classification,” and “fallback” describe inferred roles. The established behavior consists of field reads, dependency calls, ordered indirect calls, conditional traversal, and propagation of a 32-bit result. The application-level meanings of the record, object, and result are not supplied.

On every visible normal-return path, a nonnull constructed object receives a final indirect call. That call is consistent with release or destruction, but its ownership effects are unknown.

## Interface

### Input record

The function takes one pointer to a record accessed in 32-bit words.

| Byte offset | Access | Established use |
|---|---|---|
| 0 | Read 32 bits | Compare against an externally supplied discriminator. |
| 12 | Form an address within the record | Pass that address to F-4d7c82c9282a. |
| 20 | Read 32 bits | Pass the value to F-4d7c82c9282a after F-483a717208e6 returns. |

The input pointer is not checked for null before the first read. Direct field accesses reach through byte 23. That span alone does not establish all storage requirements: F-4d7c82c9282a receives an address within the record, and its access extent is unknown.

The record is not copied as a whole. The discriminator comparison occurs before F-483a717208e6; the offset-20 read occurs afterward. Changes to accessible record storage during that dependency call can therefore affect the later read without changing the already selected discriminator branch.

Construction receives selector **8** when the first input word equals the external discriminator, and selector **9** otherwise. The discriminator’s value and the selectors’ application meanings are unknown.

### Return value

The return value is a 32-bit integer:

- Zero when dispatch terminates without a nonzero handler result.
- Otherwise, the exact 32-bit result from the handler that stops dispatch.

Results are not normalized to one. A result with its sign bit set is nonzero and stops dispatch.

No explicit error result is generated for a null construction result, an absent collection, an absent fallback root, or collection exhaustion. Faults and dependency failures have no visible recovery contract.

## Behavior

### Construction

The function compares the input’s first 32-bit word with the external discriminator.

Whichever comparison branch is selected, it calls F-483a717208e6 once with **20**. It then reads the input’s 32-bit value at byte offset 20.

F-4d7c82c9282a receives these arguments, in order:

1. The 32-bit result from F-483a717208e6.
2. Selector 8 or 9, determined by the earlier comparison.
3. The address of input storage at byte offset 12.
4. The subsequently read 32-bit value from input offset 20.

There is no intervening validity or null check on the first dependency’s result. F-4d7c82c9282a returns the constructed-object pointer used throughout dispatch.

The dispatch result is initialized to zero. A null constructed-object pointer does not itself stop dispatch.

The argument 20 and the use of the first dependency’s result suggest allocation followed by initialization. That interpretation does not establish allocation success, ownership transfer, or failure cleanup.

### Collection selection: two distinct field reads

The function calls F-3fdd14ecd250 and obtains a context pointer. It then reads the context’s 32-bit field at offset 44 to decide whether to enter collection processing.

- If this **first read** is zero, collection initialization and enumeration are skipped.
- If this **first read** is nonzero, the function reads offset 44 of the **same context again** and passes the value from this **second read** to F-538044b67754.

The tested value and the initialization argument are not a single captured handle. No dependency call occurs between these two reads, but the supplied evidence does not establish that the field remains stable. Consequently, the second value is not guaranteed to equal the first or even to be nonzero.

The second read does not trigger another presence test. If the first value is nonzero and the second is zero, F-538044b67754 is still called with zero.

### Collection traversal

When the first collection-field read is nonzero, F-538044b67754 receives:

1. The local 20-byte traversal-state area.
2. The value obtained by the second context-offset-44 read.
3. The 32-bit bit pattern **0xFFFFFFFE**, representing −2 under signed interpretation.

After initialization returns, the function repeatedly calls F-6e4651b532dc with the local state and the two-pointer output area.

A zero enumeration result ends collection traversal. The function does not consume an element pointer from the output area for that result.

A nonzero enumeration result causes the first output pointer to be treated as a collection element. The function calls that element’s indirect method at table offset **52**, passing the element and the constructed-object pointer.

- A zero handler result requests another enumeration call.
- A nonzero handler result stops collection dispatch.

There is no visible null check for an enumerated element or its method table.

F-944b595e25e9 is called once after each visibly normally terminating initialized traversal, whether enumeration ends or a handler returns nonzero. There is no corresponding finalization call when collection processing was skipped.

If a collection handler returns nonzero, fallback is skipped entirely. The function does not obtain the fallback root or call the constructed object’s classification method. It proceeds to the final object call and returns the selected handler result.

If initialization receives a changed or zero collection value, these same subsequent calls remain the visible control flow if the dependencies return normally. Whether those dependencies accept that argument is unknown.

### Fallback setup

Fallback is reached when the initial collection-field test is zero or initialized collection traversal ends without a nonzero handler result.

The function calls F-3fdd14ecd250 again and reads the fallback-root pointer at offset 40 of the newly returned context. It does not reuse the earlier context pointer. The two context calls need not return the same pointer or expose the same state.

The root pointer is captured before object classification:

- If the constructed-object pointer is null, no classification call occurs and filtering is disabled.
- Otherwise, the constructed object’s indirect method at table offset **20** is called with the object as its argument.

The supplied representation treats the classification result as 64 bits. Its low 32 bits determine filtering: zero disables filtering; nonzero enables it. The high 32 bits do not determine filtering and do not replace the root pointer.

Classification is performed for a nonnull constructed object even when the captured root is null. Root absence is tested afterward, at traversal entry.

### Fallback filtering and handler invocation

A null current node ends fallback traversal.

For a nonnull node, filtering determines whether its handler is invoked:

| Filtering state | Nested filter-control value | Behavior |
|---|---|---|
| Disabled | Not read | Invoke the node handler. |
| Enabled | Zero | Invoke the node handler without calling F-35b8bd5fa9e0. |
| Enabled | Nonzero | Call F-35b8bd5fa9e0 with the constructed object; invoke the handler only if that dependency returns nonzero. |

When filtering is enabled, obtaining the nested control value requires first reading the pointer at node offset 12, then reading 32 bits at offset 12 of the referenced object.

This nested read precedes the continuation check described below. A null node-offset-12 field is therefore not safely recognized as a terminal condition in the filtering branch: the function attempts a read at an address derived from that null pointer plus 12. Whether that access faults is environment-dependent; successful completion is not established.

The node handler is the indirect method at table offset **48**. It receives the current node and the constructed-object pointer.

A nonzero handler result stops dispatch immediately. No continuation-field read or successor call follows for that node.

### Fallback continuation

If the handler returns zero, or filtering suppresses the handler, the dispatch result remains zero. The function then reads the current node’s field at offset 12 for continuation eligibility.

This is a later read, distinct from the pointer read used for filtering. It occurs after any filtering dependency and after any zero-result handler call. Those calls may change the field or other reachable state; no preservation guarantee is supplied.

- A zero continuation field ends traversal.
- A nonzero continuation field causes a call to the current node’s indirect method at table offset **28**, with the node as its argument.

The successor method’s result is represented as 64 bits. Its low 32 bits become the next node pointer. The continuation field itself does not become the next node.

The high 32 bits are carried in temporary state but have no demonstrated effect on handler selection, continuation, or the return value. When filtering is enabled, the nested-control read replaces the relevant temporary before its test; when filtering is disabled, that test is bypassed. The initial upper-half constant used on the null-object path likewise has no demonstrated dispatch effect.

There is no visible cycle detection or iteration limit. A traversal may fail to terminate if handlers keep returning zero and continuation keeps producing nodes.

### Final object call

Before any visible normal return, a nonnull constructed-object pointer receives its indirect method at table offset **4**, with the object as its argument.

This call occurs after collection finalization, if collection traversal was initialized, and after any fallback work. It also occurs when fallback has no root or all encountered nodes are filtered out.

A null constructed-object pointer receives no final object call.

The final call’s result is ignored. The previously selected 32-bit dispatch result is returned. No visible exception or fault recovery guarantees this call after an earlier abnormal exit.

## Side effects

### Direct effects and observable ordering

The function directly updates local dispatch, iterator, filtering, and traversal state. It does not visibly assign to the input record or to the context’s root and collection fields.

It passes writable-address-shaped storage references to dependencies, including the input subrecord address and local iterator buffers. Their actual read/write contracts remain unknown.

Observable ordering includes:

- Discriminator comparison before F-483a717208e6.
- Input offset-20 read after that dependency returns.
- Construction before context lookup and dispatch.
- First collection-field read before the conditional second read.
- Second collection-field read before F-538044b67754, with no intervening dependency call.
- Collection finalization before fallback context lookup.
- Root capture before classification.
- Nested filtering reads before any applicable gating dependency or node handler.
- Zero-result node handling before the continuation-field read.
- Final object call after dispatch on normal-return paths.

Capturing a pointer does not freeze its target storage. Unknown dependencies may change globals or reachable memory, and no synchronization or callback-mutation restrictions are established.

### Ownership

The constructed object is passed synchronously to handlers but is not directly returned or visibly stored in an identified global location by this function.

The following remain unknown:

- Whether F-483a717208e6 allocates storage.
- Whether construction consumes, retains, or releases its first argument.
- Whether handlers retain the constructed object.
- Whether the final offset-4 method releases memory.
- Whether collection finalization releases resources.

No separate release of the first dependency’s result is visible when construction returns null. This observation does not establish a leak without the dependencies’ ownership contracts.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests. They assume valid reached accesses and normally returning dependencies unless stated otherwise.

1. **Selector and read timing.** A matching discriminator selects 8; a nonmatching discriminator selects 9. If F-483a717208e6 changes input offset 20 through another reference, construction receives the later value, while the selector remains based on the earlier comparison.

2. **Collection absent at first read.** If the first context-offset-44 read is zero, no second collection-field read or collection initialization occurs. Fallback obtains a fresh context.

3. **Collection value changes.** If the first offset-44 read yields nonzero value A and the second yields different value B, initialization receives B, not A. If B is zero, initialization still occurs with zero. Its handling of zero is **documented_only**.

4. **Collection acceptance.** If collection handlers return zero and then −7, enumeration stops at −7. Collection finalization occurs, fallback is skipped, a nonnull constructed object receives its final call, and the function returns −7.

5. **Empty enumeration.** If the first enumeration result is zero, no collection-element method is called. Finalization precedes fresh fallback context acquisition.

6. **Null constructed object.** Collection and fallback handlers may receive null. Classification and final object calls are omitted, and filtering is disabled.

7. **Null fallback root.** With a nonnull constructed object, classification still occurs after capturing the null root. No fallback-node handler is invoked.

8. **Classification low half is zero.** Filtering is disabled regardless of the classification result’s high half. A nonnull node’s handler is invoked without the nested filter read.

9. **Nested control is zero.** With filtering enabled, a readable nested control value of zero permits the node handler without calling F-35b8bd5fa9e0.

10. **Filtering rejects a node.** With filtering enabled and nonzero nested control, a zero result from F-35b8bd5fa9e0 suppresses the handler. The continuation-field read still occurs.

11. **Handler changes continuation.** If a handler returns zero after clearing its node’s offset-12 field, the later read stops traversal without calling the successor method.

12. **Terminal field with filtering disabled.** A zero offset-12 field does not suppress the node handler. If that handler returns zero, the subsequent continuation check stops traversal.

13. **Null nested pointer with filtering enabled.** The nested read is attempted before terminal-field handling. A clean zero return is not guaranteed.

14. **Successor width.** If a successor result has a zero low half and a nonzero high half, the next node is null and traversal ends. The high half does not supply a node address.
