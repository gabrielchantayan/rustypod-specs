# F-44fc76230b37

## Purpose

F-44fc76230b37 selects between a global fallback transfer and an object-dispatched transfer into a caller-supplied destination.

The selection depends on whether a nested 32-bit state field equals −1. The fallback transfers data from a global source. The other path invokes an indirect callback using a mutable four-word argument frame, transfers data from that frame, and invokes a final dependency on the frame.

**Status: DOCUMENTED ONLY.** The transfer dependency, finalization dependency, indirect callback, and global data contract are unresolved. Their behavior is necessary to determine the complete output and ownership semantics.

## Interface

### Inputs

The function accepts four machine-level arguments:

| Position | Evidenced representation | Role supported by the available evidence |
|---|---|---|
| First | Object address in a 32-bit word | Supplies the nested state reference and indirect dispatch table. Also initializes the first word of the mutable argument frame. |
| Second | Destination address in a 32-bit word | Supplies the destination for the transfer and the explicit trailing-word store. Also initializes the second frame word. |
| Third | Opaque 32-bit value | Initializes the third frame word. No direct interpretation is visible. |
| Fourth | Opaque 32-bit value | Initializes the fourth frame word, which supplies the explicit trailing-word store on the dispatched path. |

Addresses are carried in 32-bit words in the supplied representation. Whether either address-valued argument has a higher-level type, alignment constraint, or ownership annotation is not established.

### Referenced layouts

The following byte offsets are established relative to the first input’s object address:

- Offset 0 contains a dispatch-table address.
- Offset 64 contains an address of a nested object.
- Offset 36 within that nested object contains the 32-bit state used for branch selection.
- Offset 336 within the dispatch table contains the indirect callback address.

The destination is accessed as follows:

- Destination offset 4 is passed to F-46f0b3cb316e.
- Destination offset 12 receives an explicit 32-bit store.
- There is no explicit store to destination offset 0 by F-44fc76230b37 itself.

The transfer dependency’s access extent is unknown. These offsets do not establish the complete destination size or prove that bytes outside the explicit store remain unchanged.

### Mutable argument frame

The function establishes an addressable frame of four consecutive 32-bit words, initialized in input order. The indirect callback receives:

1. The address of the first frame word.
2. The original first-input object address.

Subsequent operations can use frame contents after the callback has run. The frame is therefore not merely a record of immutable input values.

### Result

The result is a 64-bit bit pattern composed of two frame words:

- Bits 0–31 contain the first frame word.
- Bits 32–63 contain the second frame word.

This describes bit significance, not memory byte order. No byte-order conversion is visible, and the target’s memory endianness is not established.

The result is not evidenced to be a status code or a single pointer. On the dispatched path, its words can reflect changes made through the frame.

## Behavior

### Selection

The function reads the nested-object address from object offset 64 and then reads the 32-bit state at nested-object offset 36.

- The all-ones 32-bit value, interpreted as −1, selects the fallback path.
- Every other 32-bit value selects the dispatched path.

There is no visible distinction among non−1 state values.

### Fallback path

The function invokes F-46f0b3cb316e with:

- First argument: destination address plus 4.
- Second argument: global-source address plus 4.

After that dependency returns, the function reads the 32-bit word at offset 12 from the global-source base retained before the transfer call, and writes that word to destination offset 12.

The trailing global word is therefore read **after** F-46f0b3cb316e returns. A dependency that changes that word can affect the explicit store.

The indirect callback and F-ee5919ca4be6 are not invoked on this path. The third and fourth inputs are staged but have no direct role in the fallback transfer or trailing-word store.

The function then returns the packed first and second frame words. No operation in this path is explicitly given the frame address. In the absence of indirect or aliased modification by a dependency, those words remain the original first and second inputs.

### Dispatched path

The function resolves the callback through the original object’s dispatch table and invokes it with the frame address and original object address.

After the callback returns:

- F-46f0b3cb316e receives the **original destination address plus 4** as its first argument.
- Its second argument is the address of the frame’s second word.
- After that dependency returns, the current fourth frame word is stored as a 32-bit value at **original destination offset 12**.
- F-ee5919ca4be6 is then invoked with the address of the first frame word.
- Finally, the current first and second frame words are packed into the 64-bit result.

Important consequences:

- Changing the frame’s second word does not redirect the explicit destination accesses. Those use the original second input.
- The transfer dependency receives an address into the frame, not the address value contained in the second word.
- The trailing-word store uses the fourth frame word after both the callback and F-46f0b3cb316e have returned.
- The result uses the first two frame words after F-ee5919ca4be6 has returned.
- Changes made by F-ee5919ca4be6 cannot change the value already used for the trailing-word store, though that dependency might independently access other state under its unknown contract.

### Preconditions and failure behavior

For a normal return, the operations actually performed must be valid:

- The first input must permit reading the nested reference and state field.
- The selected path’s source and destination accesses must be valid.
- On the dispatched path, the dispatch-table reference and callback entry must be readable and callable.
- Each dependency’s additional preconditions must hold.

No null checks, buffer-length checks, callback checks, explicit error result, or local recovery behavior are visible. Invalid references or dependency failures have no defined handling in the available evidence.

The function does not independently normalize, validate, or interpret the third or fourth inputs.

## Side effects

Directly evidenced effects are:

- Invocation of F-46f0b3cb316e once on either path.
- One explicit 32-bit write at original destination offset 12, after that invocation returns.
- Invocation of the indirect callback only on the dispatched path.
- Invocation of F-ee5919ca4be6 only on the dispatched path, after the explicit trailing-word store.
- Creation and use of a mutable four-word frame for the duration of the call.

Further effects are dependency-controlled and unresolved. These may include changes to the destination, source, frame, object, or global state, but no particular additional effect is established.

No allocation, deallocation, reference-count operation, or ownership transfer is directly established. In particular:

- Passing an address to F-46f0b3cb316e does not establish whether it copies, moves, constructs, assigns, or retains data.
- Passing the frame to F-ee5919ca4be6 does not establish that it destroys or releases anything.
- The supplied evidence establishes frame availability during the call, not permission to retain its address afterward.

No synchronization behavior is visible.

## Acceptance examples

These are static acceptance scenarios derived from the supplied evidence. They are **not executed tests**. Dependency behavior is stated as an explicit condition wherever needed.

### Sentinel selects the fallback

Given valid references and a nested state word of hexadecimal FFFFFFFF:

- F-46f0b3cb316e is invoked with destination plus 4 and global source plus 4.
- The indirect callback is not invoked.
- F-ee5919ca4be6 is not invoked.
- Destination offset 12 receives the global trailing word read after the transfer dependency returns.

If the first two frame words remain unchanged, the result packs the original object address in the low 32 bits and the original destination address in the high 32 bits.

### Zero selects dispatch

Given a nested state word of zero:

- The indirect callback is invoked.
- F-46f0b3cb316e subsequently receives destination plus 4 and the address of the frame’s second word.
- The trailing-word store precedes F-ee5919ca4be6.

The global fallback transfer is not selected.

### Other negative values also select dispatch

A state word representing −2 selects the same path as zero. The sentinel comparison is specifically against −1, not against all negative values.

### Callback changes do not redirect the destination

Suppose the callback changes the first frame word to hexadecimal 11111111, the second to hexadecimal 22222222, and the fourth to hexadecimal AABBCCDD. Suppose neither subsequent dependency changes those words.

Then:

- The transfer target remains the original destination plus 4.
- Destination offset 12 receives hexadecimal AABBCCDD.
- The returned 64-bit pattern is hexadecimal 2222222211111111.

### Transfer-time frame mutation affects the trailing store

Suppose the callback leaves the fourth frame word unchanged, but F-46f0b3cb316e changes that word through an access permitted by its eventual contract.

The explicit destination-offset-12 store uses the changed value, because it occurs after the dependency returns. Whether such an access is permitted is unresolved.

### Final dependency changes affect the result

Suppose the trailing-word store has completed and F-ee5919ca4be6 then changes the first two frame words to hexadecimal 33333333 and hexadecimal 44444444.

The returned pattern is hexadecimal 4444444433333333. Those later frame changes do not retroactively change the value used by the already-completed trailing-word store.

### Global trailing value is sampled after transfer

On the fallback path, suppose F-46f0b3cb316e changes the trailing word at offset 12 of the retained global-source base.

The subsequent explicit destination store uses that updated word, rather than a value sampled before the dependency call.

## Uncertainties

### Inferred intent

The two paths are consistent with selecting a default value or obtaining an object-specific value, then transferring a payload and associated trailing word. The final frame dependency could serve a lifetime-management role.

These interpretations are not established contracts. They must not be used to infer copying depth, reference counting, destruction, error semantics, or the meaning of the trailing word.

The following remain unresolved:

Consequently, the visible offsets and call ordering are sufficient for a partial behavioral contract, but not for an interoperable independent implementation without additional dependency and platform evidence.
