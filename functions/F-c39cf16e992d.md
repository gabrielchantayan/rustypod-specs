# F-c39cf16e992d

## Purpose

F-c39cf16e992d performs a bounded sequence of delegated transitions from an initial 32-bit state toward a supplied target state. It exposes a writable 32-bit progress field and returns one of two 32-bit status values:

- **0:** the current state equals the target when the function checks for completion.
- **2:** a delegated transition reports a nonzero result, or a successful transition is followed by a progress-field increment whose signed result is at least 129.

The function checks state equality **before** each delegated transition. It does not immediately check equality after a transition. Consequently, a transition that reaches the target can still lead to status 2 if the progress limit prevents the next equality check.

The progress field is initialized to zero. Under the additional condition that the dependency does not modify that field indirectly, it counts successful delegated transitions, up to and including the transition that raises it to 129. The source does not establish that noninterference condition, so the field is not unconditionally a reliable transition count.

## Behavior

### Initialization and first completion check

The first established externally visible action is a 32-bit write of zero to the progress destination.

The private current state is initialized from the initial-state input. The function then compares that current state with the target.

If they are equal, the function returns 0 without invoking F-8fce2b40d724. The progress destination has nevertheless already been written.

The target is a by-value input. No later read from caller-owned target storage is visible.

### Delegated transition

When the current state differs from the target, the function invokes F-8fce2b40d724 with:

1. The original opaque context.
2. The current state value.
3. The address of the function’s private current-state storage.

The second argument is the state value at invocation. The third argument allows the dependency to replace the state that a later iteration will inspect.

The same private state storage is used across transitions. The caller’s progress destination is not passed as a direct argument to the dependency.

The supplied evidence does not establish that the dependency writes the state on every call, writes it only on success, or leaves other reachable memory unchanged.

### Nonzero dependency result

If the dependency returns a nonzero result:

- The function does not perform its post-success read of the progress destination.
- The function does not perform its post-success increment.
- The function does not check the updated current state against the target.
- The function returns 2.

Any side effects already performed by the dependency remain outside the caller’s visible rollback logic. In particular, a nonzero result does not imply that the dependency left the state or progress destination unchanged.

### Zero dependency result

If the dependency returns zero, the function performs these actions in order:

1. Reads the 32-bit value currently stored at the progress destination.
2. Adds one to that value.
3. Writes the incremented value to the progress destination.
4. Uses the incremented value in a signed comparison with 129.

If the incremented value is less than 129, execution returns to the state-equality check.

If the incremented value is 129 or greater, the function returns 2 without another state-equality check.

The increment uses the value read **after** the dependency returns. It is not an increment of a protected private counter, and it is not necessarily based on the value written by the preceding iteration.

### Ordinary bounded execution

If the dependency does not modify the progress destination, and no other actor modifies it, the progress values written after successful transitions are 1 through 129.

Under those conditions:

- The function performs at most 129 dependency invocations.
- A failing invocation is included in that invocation bound but does not increase the progress value.
- Target equality is checked initially and after each of the first 128 successful transitions.
- A 129th successful transition raises the progress field to 129 and returns 2.
- The state produced by that 129th successful transition is not checked for equality.

A successful return therefore permits at most 128 successful transitions under these noninterference conditions.

If the dependency can indirectly modify the progress destination, the numeric threshold does not establish an unconditional 129-invocation bound. Repeatedly lowering the field can permit additional transitions.

### Integer behavior

The threshold is the integer value 129, not 128. The continuation condition is strictly “less than 129.”

The visible comparison is signed. A negative incremented value therefore satisfies the continuation condition.

Ordinary noninterfering execution increments only values from zero through 128, so its additions do not approach the signed 32-bit boundary.

If the value read from the progress destination is the maximum signed 32-bit integer, adding one exceeds that range. The supplied representation does not establish whether the original executable wraps, traps, or has another relevant behavior. No overflow policy is inferred.

These examples are conditional consequences of the supplied static behavior, not executed tests. Unless stated otherwise, assume valid storage, normally returning dependency calls, no concurrent mutation, no indirect modification of the progress destination, and representable arithmetic.

### Initial state already matches

Given an initial state equal to the target:

- The progress destination is written with zero.
- The dependency is not invoked.
- The function returns 0.

Any previous value in the progress destination is discarded.

### One successful transition reaches the target

Given distinct initial and target states, suppose the first dependency invocation returns zero and writes the target into the supplied state storage.

The function writes 1 to the progress destination, passes the threshold comparison, observes target equality on the next iteration, and returns 0.

### First transition reports failure

The function returns 2 without incrementing the progress field. Under the stated noninterference assumptions, the field remains zero.

This result is unchanged if that failing invocation also writes the target into the private state storage: no completion check follows the failure.

### Target reached on successful transition 128

Suppose the first 127 successful transitions leave the state different from the target, and transition 128 writes the target.

The function writes 128 to the progress destination. Because 128 is less than 129, it performs another equality check and returns 0.

### Target reached on successful transition 129

Suppose the first 128 successful transitions leave the state different from the target, and transition 129 writes the target.

The function writes 129 to the progress destination and returns 2. It does not inspect the newly produced state for equality.

### Successful transitions leave the state unchanged

Given distinct initial and target states, suppose every dependency invocation returns zero but leaves the current state unchanged.

The function invokes the dependency 129 times, writes 129 to the progress destination, and returns 2.

### Dependency changes the progress destination

Suppose a dependency invocation returns zero after indirectly writing 127 to the progress destination.

The function reads 127, writes 128, and continues to another equality check. Its progress value need not equal the number of successful invocations.

If the dependency instead writes 128 before returning zero, the function writes 129 and returns 2 without another equality check.

### Dependency changes progress and then reports failure

The function returns 2 without its own increment. The dependency-written value remains, absent some other intervening effect.
