# F-362f01c69b03

## Purpose

F-362f01c69b03 dispatches according to a 32-bit selector read from a caller-supplied memory region. It has two explicitly recognized selector values and a third recognition condition involving an unresolved data value.

The two explicit selectors invoke different dependencies and produce a return value of 1. The third condition additionally examines a value reached through an indirect pointer: a zero value produces 0 without invoking its dependency; a nonzero value causes the dependency’s result to become this function’s result. Selectors satisfying none of these conditions produce 0.

These are established control-flow behaviors in the supplied static representation. Interpreting the result as “handled,” “success,” or any other domain-specific status would be inferred intent, not an established contract.

## Behavior

### Selector acquisition and precedence

The function first reads the selector from byte offset 4 relative to the second argument. Subsequent dispatch decisions use that acquired value; the visible body does not reread the selector.

1. Selector 0x0000EAB0 selects F-4adbd4757be7.
2. Otherwise, selector 0x0000EAB1 selects F-3e171b998782.
3. Only for other selectors does the function evaluate the remaining recognition condition.

Consequently, even if an explicit selector would also satisfy the unresolved-value condition, the explicit branch still wins. The pointer field and indirect integer are not read by this function on either explicit branch.

### Remaining recognition condition

For every selector other than the two explicit values, the function tests whether adding an unresolved data value to the acquired selector produces zero.

The supplied evidence does not provide that data value’s contents or independent declaration. It therefore does not identify the third recognized selector numerically.

The operation is presented in a 32-bit integer context. Under 32-bit modular addition, the condition is satisfied when the two operands’ bit patterns sum to zero modulo 2³². This makes the accepted selector the additive inverse of the unresolved value under that arithmetic model. The exact wraparound semantics are not independently established by instruction-level evidence, so this interpretation must not be mistaken for proof of source-language signed-overflow behavior.

If the condition is false, the function returns 0. It does not read the pointer field, dereference that pointer, or invoke any dependency on this path.

If the condition is true, the function performs the indirect gate described next.

### Indirect gate and delegated result

After the third recognition condition succeeds, the function:

- Reads the pointer at byte offset 12 from the supplied base.
- Reads a 32-bit integer through that pointer.
- Distinguishes zero from every nonzero value.

A zero integer produces a result of 0 without invoking F-1c750cea830f.

A nonzero integer causes one invocation of F-1c750cea830f. No explicit argument expressions are shown at that call site. Its result supplies this function’s unsigned 32-bit result.

The gate is strictly a zero/nonzero distinction. Negative represented integers are not excluded: if the read is valid and its value is nonzero, they take the delegated path.

The indirect integer is read before the dependency is called. No second gate read is visible after the call, and no post-call validation of the dependency’s result is shown.
