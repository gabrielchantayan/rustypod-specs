# F-14e18f37a85b

## Purpose

F-14e18f37a85b processes 17 callback descriptors in ascending index order, conditionally compares callback-produced data against associated records, and accumulates a 32-bit mask. If the resulting mask is nonzero, it calls F-c9ee018573ab with the original input and that mask. It then reaches an unresolved indirect dispatch with either that dependency’s result or zero.

Change detection and propagation are inferred intent. The established behavior consists of the reads, callback resolution, validation, dependency calls, and mask operations specified below. The application meaning of the records, tags, payload, and mask is unknown.

The function distinguishes **captured addresses** from **contents read through those addresses**. It captures separate state-block bases during startup and reloads the callback-table base on each iteration. Replacing a global base later does not redirect accesses through an already captured address; modifying storage at that address can affect subsequent reads.

## Behavior

### Startup reads and capture lifetimes

Startup proceeds in the following established order:

1. Read the state-block global and retain that address for entry 9’s possible gate-byte read.
2. Initialize the eventual final-dispatch argument to zero.
3. Evaluate the initial-mask lookup. This reads the initial-mask-table global and separately reads the state-block global to obtain the selector at offset 4, then loads the selected 32-bit mask.
4. Initialize the traversal index to zero.
5. Read the state-block global again and retain that address plus 28 as the record-array base.

The expression does not independently establish the relative evaluation order of the initial-mask-table-base read and the state-block-base read used for the selector. Both belong to startup mask initialization, before the record-base capture.

There are therefore three distinct state-block-base reads:

- The first supplies the retained gate base.
- The second supplies the address for the selector read.
- The third supplies the retained record base.

Their values must not be assumed identical. No dependency call intervenes between these startup reads, but the representation does not establish that repeated global reads necessarily return the same value.

The gate base and record base remain captured for the invocation. Dependencies replacing the state-block global do not redirect either one. The selector and initial mask are also not reread. The initial-mask-table base is a startup read, not a per-entry lookup.

### Per-entry ordering

The function visits indices 0 through 16, inclusive, once each, in ascending order.

At the start of each iteration, it:

1. Reads the current callback-table global.
2. Locates that iteration’s 8-byte descriptor.
3. Reads and captures the descriptor’s first 32-bit word.
4. Reads and captures its second 32-bit word.
5. Writes the current index into scratch offset 1.
6. Writes 1 into scratch offset 0.

Thus, a previous entry’s dependencies can affect later entries by replacing the callback-table global or changing descriptor storage.

For the current entry, however, both descriptor words have already been captured before either the callback or entry 9’s eligibility dependency runs. Subsequent replacement of the callback-table global, or mutation of that descriptor’s storage, does not change the current entry’s captured descriptor words.

These reads and scratch writes also occur when entry 9 will be skipped.

### Entry-9 eligibility

Only for entry 9, the function reads the input object’s 32-bit field at offset 720 and calls F-d7be9cfb4000 with that field and the integer 300.

The dependency supplies a 64-bit result. Eligibility depends on its upper 32 bits:

- If the upper half is zero, proceed to callback resolution without reading the gate byte.
- If the upper half is nonzero, read the byte at offset 3 from the **first captured state-block base**.
  - A zero byte permits callback resolution.
  - A nonzero byte skips the callback and all later processing for entry 9.

The lower 32 bits of the result do not affect this decision.

The gate byte is read after F-d7be9cfb4000 returns. That dependency can therefore affect the decision by changing the byte in the captured storage. Replacing the state-block global alone does not redirect the gate-byte read.

Skipping entry 9 does not clear an existing mask bit.

### Callback resolution and invocation

Interpret the captured second descriptor word as a signed 32-bit quantity and arithmetic-shift it right by one bit. Add that signed adjustment to the original object address to obtain the receiver address. Negative adjustments are possible.

Bit 0 of the second descriptor word controls dispatch:

- **Clear:** use the first descriptor word directly as the callback target.
- **Set:** read a 32-bit value at the adjusted receiver address; clear the low two bits of the first descriptor word; add that masked value to the receiver-loaded value; read the callback target from the resulting address.

The indirect form masks the first descriptor word, not the second.

The callback receives the adjusted receiver address and the scratch-region address. No validation is shown for any receiver, lookup address, or callback target.

For entry 9, receiver-memory reads used by indirect resolution occur after the eligibility dependency returns. Although the descriptor words are already captured, that dependency may still affect indirect resolution by changing the receiver’s contents or the lookup storage.

### Callback result and tag validation

A nonzero callback result ends processing for that entry. The function performs no expected-tag read, comparison call, external update, or new mask-bit addition for it.

A zero callback result selects the record at the **captured record-array base** plus 12 times the current index. The function then validates the scratch tag against the record’s expected byte at offset 8.

The scratch byte is promoted before subtraction. Validation compares its value minus one against the expected byte as a 32-bit unsigned comparison; subtraction is not reduced to eight bits.

Consequences include:

- Scratch tag 1 matches expected tag 0.
- Scratch tag 255 matches expected tag 254.
- Scratch tag 0 produces comparison value 4,294,967,295 and matches no expected byte.
- Expected tag 255 cannot match any scratch byte.

The expected tag is read after the callback returns. The relative evaluation order of the scratch-tag read and expected-tag read within the comparison is not independently established.

A mismatch calls F-a817d8d58c10 with no explicit arguments. That dependency is marked nonreturning in the supplied representation. No normal continuation from the mismatch path is established.

### Comparison, update, and bit addition

After successful tag validation:

1. Read the 32-bit record argument at offset 4.
2. Call F-7f14f1ab6851 with that argument and the scratch payload address.
3. If its result is zero, finish the entry without external update or a newly added bit.
4. If its result is nonzero, reread the same record field and pass the freshly read value, together with the payload address, to an unresolved external update operation.
5. After that operation returns, OR the current entry’s bit into the local mask.

The record address remains derived from the captured record base. Replacing the state-block global during a dependency does not redirect these reads.

The second record-field read is significant. F-7f14f1ab6851 may modify the field, so comparison and update need not receive equal values. Likewise, both operations receive the same payload address, but no guarantee establishes unchanged payload contents between calls.

The external update’s result, if any, is ignored. If it does not return, the bit addition and later traversal are not reached.

### Mask completion and terminal dispatch

The mask begins with the selected table value, not necessarily zero. The function only adds bits by OR; it never clears them.

The bit position is the entry index masked to eight bits. Reachable indices are 0–16, so this masking does not change any reachable position. Only bits 0–16 can be newly added; all initial bits, including bits 17–31, remain set.

After entry 16:

- If the mask is zero, bypass F-c9ee018573ab and retain zero as the terminal argument.
- Otherwise, call F-c9ee018573ab once with the original object argument and full 32-bit mask, and use its result as the terminal argument.

The unresolved indirect dispatch follows.

## Acceptance examples

These examples are conditional static-contract cases, not runtime observations. Unless stated otherwise, storage is accessible, dependencies return, and there are no additional mutations.

1. **Zero completed mask.**  
   The initial mask is zero and every invoked callback returns nonzero. No tag validation, comparison, or external update occurs. F-c9ee018573ab is bypassed; terminal dispatch receives zero.

2. **Preserved high bit.**  
   The initial mask contains only bit 24 and no entry adds a bit. F-c9ee018573ab receives that unchanged mask.

3. **One changed entry.**  
   Entry 4 returns zero with scratch tag 3; its expected tag is 2. Comparison returns nonzero and external update returns. With no other bits, completion receives mask 16.

4. **No eight-bit tag wraparound.**  
   A zero-result callback supplies tag 0 while the expected byte is 255. Validation invokes F-a817d8d58c10 rather than accepting the pair.

5. **Separate startup state captures.**  
   If the three state-block-global reads yield distinct addresses, the first supplies the gate byte, the second supplies the selector, and the third supplies the record-array base. The function does not unify them into one snapshot.

6. **Global replacement versus gate-storage mutation.**  
   Entry 9’s eligibility dependency replaces the state-block global but leaves the originally captured gate storage accessible. With a nonzero upper result half, the function still reads the original storage’s byte at offset 3. If the dependency also changes that byte, the changed byte controls eligibility.

7. **Gate-byte read suppressed.**

8. **Current descriptor captured, next table fresh.**

9. **Captured record address, fresh record value.**
