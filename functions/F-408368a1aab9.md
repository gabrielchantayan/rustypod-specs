### Initial propagation and lookup

The first memory access stores the link seed as a word at second-base offset `0x34`. The scale seed is then doubled. Only afterward is the word at second-base offset `0x74` read and doubled.

The first base receives the doubled scale seed at offset `0x54`. The fourfold seed is then formed, and its low byte is stored at original-third-base offset `0x15`. Auxiliary-base offset `0x44` receives the doubled second-base field.

A byte is read at doubled-seed-region offset `0x05`. Its zero-extended value selects a word read at that value plus `0x74`, producing the initial lookup region. The starting address of this lookup lies between `0x74` and `0x173`, inclusive; no separate table base is visible.

The next mutations and read have this order:

1. Initial-lookup-region offset `0x44` receives the doubled second-base field as a word.
2. Original-third-base offset `0x15` receives the doubled scale seed’s low byte.
3. Doubled-seed-region offset `0x0D` receives the initial lookup address’s low byte, followed by a word store of the doubled-seed region’s own address at offset `0x14`.
4. Original-third-base offset `0x54` receives the link seed as a word.
5. Doubled-seed-region offset `0x64` is read to obtain the further region.
6. Further-region offset `0x0D` receives the same captured byte marker, followed by its own address as a word at offset `0x14`.

Thus, the overwrite at third-base offset `0x15` precedes both doubled-seed-region stores. The third-base offset-`0x54` store occurs after those stores but before the further-region address read. Either distinction can affect subsequent behavior under aliasing.

### Cross-region updates and refreshed lookup

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Initial ordering under aliasing.** If third-base offset `0x15` overlaps a doubled-seed destination, its doubled-seed-byte overwrite occurs before the marker and self-address stores. If third-base offset `0x54` overlaps the further-region pointer field, that word store occurs before the pointer is read.

2. **Arithmetic boundary between stores.** If the first `0x3A` byte store succeeds but the subsequent third-base subtraction cannot complete under the target’s arithmetic rules, the contract does not promise either later `0x3A` store. The first store precedes the unresolved arithmetic boundary.

3. **Fresh lookup capture.** If intervening writes change linked-region offset `0x05` before its second read, the late lookup uses the changed byte. If the subsequent third-base byte store changes that location again, it does not replace the already captured lookup byte.

4. **Overwritten constant field.** With valid ordinary memory and no relevant overlap, scaled-third-region offset `0x20` contains word `0x20` immediately after its four-store sequence. The earlier stores and intervening byte read remain part of the access trace.

5. **Temporary self-address.** Without relevant overlap, double-lookup-region offset `0x54` temporarily contains its own address and later receives the captured offset-`0x14` word. A final observation alone does not show the temporary store was absent.

6. **Final-chain distinction.** If the chain base is a representable address, the halfword destination is twice that address, while the following word read is at the original chain base plus `0x64`. Treating both accesses as relative to the doubled address violates the contract.

7. **Failure and invocation boundary.** An inaccessible derived location does not promise a clean error return or rollback. If execution reaches the indirect target, its effects must be considered separately; preservation of globals, memory, and ownership cannot be assumed.
