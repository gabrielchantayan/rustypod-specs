## Behavior

### 1. Initial branch and memory transfer

The function first forms the low 32 bits of Control multiplied by 4096.

If that result is nonzero, the initial memory transfer is skipped. The conditional chains described below do not enable any further explicit memory operation before the recurring call sequence.

If the result is zero, the function:

1. Computes a destination address by adding Offset to Source in bytes.
2. Reads one 16-bit value at Source.
3. Replaces its working source address with the destination address minus Adjustment.
4. Writes the previously read 16-bit value at the destination.
5. Uses the incoming Link value as the next condition-bearing address.

The read precedes the write. Overlap does not turn this into a multi-element copy: exactly one halfword is loaded and then stored.

The branch condition is not equivalent to Control being zero. Under 32-bit arithmetic, it holds whenever the low 20 bits of Control are zero. Thus nonzero values such as hexadecimal `00100000` also enter the transfer path.

For every such Control value, its tested bit at hexadecimal `00040000` is clear. Consequently, the carry-like contribution used in the early exceptional-path conditions is zero.

The working-source replacement does not itself establish an externally visible register-preservation contract. It matters because later conditions inspect that updated value.

### 2. Conditions for the exceptional store

The first conditional chain proceeds only while each relevant intermediate result is zero. Every reached shift in this chain has a zero shift count: entry to each stage requires the value supplying that count to be zero.

Under the stated 32-bit interpretation, entry to the exceptional store requires all of the following:

- Control has its low 20 bits clear.
- Link is zero.
- Slot shifted right by one is zero.
- Peer equals Offset.
- The updated working source equals Adjustment.
- Accumulator is zero.
- Slot plus twice Offset is zero modulo \(2^{32}\).

The updated-source equality is equivalent to:

\[
\text{Source}+\text{Offset}-\text{Adjustment}
\equiv \text{Adjustment}\pmod{2^{32}}.
\]

The Slot condition restricts Slot to the numeric addresses zero or one. This is an arithmetic result, not evidence that either address is a valid argument-storage location.

The final addition can produce a carry, but the exceptional block resets the carry-like state before the next chain. That carry does not rescue later conditional memory operations.

### 3. Exceptional store and associated state

If all exceptional-store conditions hold, the representation performs these effects:

- Assigns Slot multiplied by 64 to an additional machine-state location.
- Replaces the working Link address with Link plus Slot multiplied by 64.
- Performs a 16-bit store whose destination address is obtained by zero-extending a 16-bit value read at the old Link address.
- Forms the stored value by adding 15 to another 16-bit read at that same old Link address, retaining the low 16 bits.
- Advances another working address by one 16-bit element, which is two bytes.

The destination calculation and stored-value calculation contain separate displayed reads of the old Link location. The evidence does not establish their relative evaluation order. They must not be contracted into one read for memory-mapped or externally changing memory.

Because exceptional entry requires Link to be zero, both reads address location zero. This path therefore requires an execution environment in which those accesses, the resulting destination store, and the unusual argument-storage address are meaningful. Otherwise execution may fault before the recurring call sequence.

If Slot is zero, the replacement Link remains zero. If Slot is one, it becomes decimal 64.

### 4. Why later displayed memory operations are unreachable

The later conditional chain can begin only after the exceptional block and only if its replacement Link is zero.

Given the established exceptional-entry conditions:

- Slot can only be zero or one.
- A zero replacement Link therefore requires Slot to be zero.
- The earlier Slot-derived comparison address is zero.
- The address advanced by one 16-bit element is numeric two.

The next two zero-gated comparisons consequently produce zero and then two. The second comparison fails the required zero condition. All subsequent conditional stages remain disabled.

Accordingly, within this arithmetic model, the displayed later pointer loads, paired 32-bit stores, signed-halfword operations, and further address adjustments have no reachable execution. They are not additional supported behaviors or acceptance requirements.

## Acceptance examples

These are conditional static acceptance examples. No runtime tests have been performed.

1. **Transfer bypass.** With Control equal to one, the initial product is hexadecimal `00001000`, which is nonzero. No explicit data-memory transfer occurs before the first dependency invocation. Its target is incoming Link plus hexadecimal `0EB6`, modulo \(2^{32}\).

2. **Nonzero Control entering the transfer path.** With Control equal to hexadecimal `00100000`, the product by 4096 wraps to zero. If Source is readable and Source plus Offset is writable, the observed 16-bit source value is stored at that destination.

3. **Overlapping transfer.** With a qualifying Control value and Offset equal to zero, the source halfword is read and that captured value is written back to the same address. This does not establish a wider copy or any ownership change.

4. **Early exceptional-path rejection.** If the transfer occurs but Link is nonzero, the exceptional store is not reached. The function proceeds to its recurring sequence using the incoming Link for the first target calculation.

5. **Conditional exceptional execution.** If every exceptional-entry condition holds, Slot is zero, and address-zero accesses are valid, the exceptional store occurs and the first recurring target is hexadecimal `00000EB6`. The later displayed conditional memory operations remain unreachable.

6. **Store truncation.** If an exceptional stored-value read yields hexadecimal `FFFA`, adding 15 produces a stored halfword of hexadecimal `0009`. The destination depends on its separate address-forming read.

7. **Loop continuation.** If both calls return and the interrupt resumes, the next iteration’s first target is hexadecimal `083D5B78`, regardless of the initial Link. This guarantees only the local target assignment, not preservation of external state.

8. **Interrupted progression.** If the first dependency never returns, neither the second dependency nor the interrupt is reached in that iteration.
