# F-11ed8242c40c

## Purpose

F-11ed8242c40c is a four-word, 32-bit routine with three distinct observable outcomes:

- Return the first input word unchanged.
- Return a word containing comparison-related bits and selected incoming status bits.
- Dispatch through an address derived from incoming machine state, returning the dispatched operation’s result.

The input layout and exceptional-value classification are consistent with two binary64-like values, each supplied as a low word followed by a high word. That interpretation is inferred intent, not a complete floating-point comparison contract. In particular, ordinary finite inputs take the unchanged-first-word path rather than producing comparison flags.

Exceptional dispatch depends on externally supplied control data. Its target, ultimate behavior, and error handling are unresolved.

## Behavior

### 1. Initial high-word classification

The routine first examines B and D through their bitwise OR and associated sign and arithmetic tests. The resulting early-exit condition can be expressed as follows:

A high word is **special-class** when it lies in either unsigned interval:

- `0x7ff00000` through `0x7fffffff`;
- `0xfff00000` through `0xffffffff`.

If neither B nor D is special-class, the routine returns A unchanged.

This includes ordinary finite binary64 encodings, zeros, and subnormal encodings under the inferred layout. The low words do not affect this early-exit decision.

Some branches perform equality checks before returning A, but both outcomes of those checks return A. They do not introduce a different result or an externally visible write.

If at least one high word is special-class, processing continues to full-operand classification.

### 2. Full-operand exceptional classification

For this contract, an operand with high word H and low word L is **non-NaN-class** when either:

- The truncated 32-bit value `2 × H` is less than `0xffe00000`; or
- That value equals `0xffe00000` and L is zero.

Under the inferred binary64 interpretation, this accepts finite values and infinities, but excludes NaN encodings.

The first operand is classified before classification of the second operand is needed. If the first fails, the second operand’s numerical classification does not change the decision to enter exceptional dispatch.

Processing now splits:

- If both operands are non-NaN-class, construct and return a comparison-related word.
- Otherwise, enter the control-driven indirect-dispatch behavior described below.

Consequently, comparison-word construction is reached only when at least one operand is infinity-class and neither operand is NaN-class. It is not the general path for comparing two finite operands.

### 3. Comparison-word construction

The sign bit of `B | D` selects one of two constructions.

#### At least one high word has its sign bit set

Define:

- **E:** Both high words and both low words are equal.
- **L:** The unsigned pair `(B, A)` is lexicographically less than or equal to `(D, C)`, with the high word compared first.

The result contains:

| Result bit | Condition setting it |
|---:|---|
| 31 | L is false |
| 30 | E is true, or Q bit 3 is set |
| 29 | L is true, or Q bit 2 is set |
| 28 | Never set by this construction |
| 27 | Q bit 0 |
| 26–0 | Zero |

Other bits of Q do not survive this branch’s mask and final shift.

The comparison of high words is unsigned even when one or both high words have their sign bit set. A numeric-order interpretation therefore depends on the operand encodings and the surrounding convention; it is not an independent signed-integer comparison.

#### Neither high word has its sign bit set

The routine compares B against D first. If the high words are equal, it instead compares A against C.

For the selected comparison:

- **Cflag** is true when the first selected word is unsigned greater than or equal to the second.
- **Nraw** is the sign of the truncated 32-bit subtraction of the second selected word from the first.
- **V** is signed subtraction overflow.
- **E** remains full equality of both operand words.

When V is false, the result is formed by OR-combining:

- Nraw into bit 31;
- E into bit 30;
- Cflag into bit 29;
- The low five bits of Q into bits 27 through 31.

When V is true, the explicit comparison contribution instead sets bit 31 to the inverse of Cflag, clears its equality contribution, and sets bit 29 to Cflag. The same Q contribution is OR-combined.

In either case, bits 26 through 0 are zero. Q can therefore set a flag-position bit even when the comparison’s own contribution is clear.

Given the preceding classification gates, the selected subtraction on this branch cannot actually overflow: an accepted special operand with a nonnegative high word is positive infinity, and equal accepted special high words require zero low words. The overflow-handling construction is present in the supplied evidence but does not expand the reachable accepted input set.

If Q has only bit 0 available, these results resemble an N/Z/C/status encoding with no overflow bit set. Treating Q as restricted in that way is an additional precondition, not an established property of this routine.

### 4. Exceptional control dispatch

This section applies when at least one operand fails the full non-NaN-class test.

All dispatched calls use the destination derived from R by clearing its low two bits. The supplied evidence shows different argument lists at that destination; it does not establish a single reliable callable signature.

First, G is tested with mask `0x000d0000`.

#### When that masked value is zero

The low nibble of a subsequent G read selects a mode.

| Mode | Observed behavior |
|---:|---|
| 10 | Dispatch with two arguments: a first word initially zero, changed to `0x80000000` if G bit `0x40` is set; and K0 |
| 8, with G bit `0x40` set | Dispatch with arguments zero and zero |
| 8, with G bit `0x40` clear | Read K1 and K0 as the initial argument pair; if a subsequent G read has bit `0x10` set, replace the pair with zero and K2; dispatch with the resulting pair |
| 9 | Replace the effective first input word with 8 and the effective second input word with K0, then continue below |
| Any other mode | Dispatch with no explicit arguments represented in the supplied evidence |

For mode 8 with bit `0x40` clear, the initial reads of K1 and K0 occur even when the later bit-`0x10` decision replaces those values.

#### Continuing control dispatch

This stage is reached either directly when the initial mask test is nonzero, or after mode 9.

1. If a G read has bit `0x00100000` clear, dispatch with one explicit argument: zero.
2. Otherwise, if a subsequent G read has all bits in `0x00070000` clear, dispatch with three explicit arguments:
   - `0x30000000`;
   - The effective second input word;
   - `0x30000000` OR Q bit 0 shifted into bit 27.
3. Otherwise, dispatch with two explicit arguments:
   - The effective first input word;
   - The 32-bit value obtained by shifting G left by 15, complementing that truncated value, and shifting left once more.

For the final case, the second argument is equivalently:

`0xfffffffe XOR ((G & 0x0000ffff) << 16)`.

Thus its low 16 bits are always `0xfffe`; only G’s low 16 bits influence its upper half.

Unless mode 9 replaced them, the effective first and second input words remain A and B.

Each dispatch path returns the 32-bit result represented as coming back from the indirect destination. There is no visible post-dispatch transformation of that result.
