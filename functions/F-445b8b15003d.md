## Behavior

### 1. Store the input before calling dependencies

The function first stores the input value at state offset `0x748`.

This store precedes both associated-object queries and all later calls. There is no visible rollback if a subsequent access or dependency fails.

### 2. Query the associated object twice

The function resolves and invokes the associated object's dispatch entry at byte offset `0x88`. It stores the four-byte result at state offset `0x738`.

It then resolves and invokes the associated object's dispatch entry at byte offset `0x5C`. It stores that result first at state offset `0x734`, then at state offset `0x73C`.

These are separate dispatch resolutions. The associated-object address and its dispatch-table pointer are read again for the second call. The first call is not established to preserve either of them.

The value stored at `0x73C` is the same captured result stored at `0x734`; it is not obtained by rereading `0x734`.

The first two indirect calls have no explicit arguments in the supplied representation. A receiver argument or other calling-convention state must not be invented from the object-based dispatch pattern alone.

### 3. Make two state-object indirect calls

Three global four-byte storage locations supply values to these calls. For clarity, they are designated here as **Gα**, **Gβ**, and **Gγ**. These designations describe distinct storage locations, not known semantic constants.

The visible sequence is:

1. Read Gα and retain that value.
2. Resolve the state object's dispatch entry at byte offset `0x58` and invoke it with three explicit arguments: the state-object address, a read of Gα, and a read of Gβ.
3. Resolve the state object's dispatch entry at byte offset `0x58` again and invoke it with the state-object address, the retained Gα value, and a read of Gγ.

The first invocation's Gα argument is expressed as a separate read from the value retained before that call. The evidence does not establish that the two reads must be coalesced or that Gα cannot change between them.

The second call uses the retained Gα value, not a fresh read after the first invocation. Conversely, Gγ is supplied through the second call's argument expression; it is not shown as captured before the first invocation.

The state object's dispatch-table pointer is resolved separately for each invocation. The first invocation may therefore affect the target selected for the second invocation.

The precise evaluation order among dispatch lookup and argument expressions within a single call is not established. The sequence between the two calls is established. Their return values are not used by this function.

### 4. Invoke F-c20bd8e1d6d9 and capture later state

The function reads state offset `0x73C` and passes that current value to F-c20bd8e1d6d9 together with the state-object address.

This read occurs after both state-object indirect calls. Consequently, it can observe a value different from the second query result if a preceding dependency changed the field.

After F-c20bd8e1d6d9 returns, the function reads state offset `0x738` and retains that value for the conditional path. This is a fresh field read, not reuse of the first query's captured result.

The retained value is captured before the optional call to F-5d926e3607be. Changes that F-5d926e3607be makes to `0x738` do not replace this retained argument.

### 5. Decide whether to enter the conditional path

The function reads state offset `0x74C`.

- If it is nonzero, the function proceeds directly to the conditional path without calling F-5d926e3607be.
- If it is zero, the function calls F-5d926e3607be with the state-object address and then reads `0x74C` again.
- If that second read is zero, the function returns without calling F-1dfbe787cb93, the unresolved external payload-preparation dependency, or F-ed03cb1b6aa9.
- If the second read is nonzero, the conditional path executes.

The return value of F-5d926e3607be does not control the branch. The branch depends on the subsequent field read.

A nonzero gate read is not a promise that later dependencies preserve that field.
