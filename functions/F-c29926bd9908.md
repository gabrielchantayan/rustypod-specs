# F-c29926bd9908

## Purpose

F-c29926bd9908 performs an ordered, entry-indexed state transition. It conditionally resets state when the full transition argument equals 8, invokes several entry-related dependencies, submits a 20-byte temporary record, polls until a dependency returns nonzero, and then performs further state updates.

A global table-base read occurs before the special-case comparison, including when the reset is skipped. On the reset path, some writes use different snapshots of the same global base. Their targets must not be collapsed into one contiguous region without an additional stability assumption.

“Reset,” “submission,” and “cleanup” describe observable operations, not established application-level meanings. No dependency implementation or runtime evidence is available.

## Behavior

### Entry read and special-reset selection

Before testing the transition value, the function reads a global holding the base of a four-byte-stride table. Call this captured value the **early table base**.

It then compares the entire 32-bit transition value with 8. A value such as `0x108` does not select the reset, despite having the same low byte.

If the comparison fails, all special-reset operations below are skipped. The initial global read has nevertheless already occurred.

### Special reset

When the transition value equals 8, the function reads the same table-base global again. Call this second value the **reset-time table base**.

The four zero-byte writes occur in this order:

| Order | Target address | Width |
|---:|---|---:|
| 1 | Reset-time table base + 4 × entry index | 8 bits |
| 2 | Early table base + 4 × entry index + 1 | 8 bits |
| 3 | Early table base + 4 × entry index + 2 | 8 bits |
| 4 | Early table base + 4 × entry index + 3 | 8 bits |

Thus, the first write uses the second global read; the remaining three use the value captured before the branch. These are four individually represented byte writes. They target four consecutive bytes only if the two base snapshots agree. No synchronization or stability guarantee establishes that agreement.

Next:

1. F-15643c36365d returns an object.
2. The function reads that object’s dispatch-table address and invokes the operation selected at dispatch-table byte offset `0x48`. The representation shows no explicit arguments to this operation.
3. If the result is nonzero, F-15643c36365d is called again. Through the newly returned object’s dispatch table, the function invokes the operation at offset `0x44`, passing that object and zero.
4. F-646d64bbe501 is called with the context, entry index, and zero.

The two object-accessor calls are separate. Object identity and lifetime across them are not established.

The function then performs three ordered global reads:

1. Read the byte-oriented base; designate this snapshot **B₁**.
2. Read the word-oriented base; designate this snapshot **W**.
3. Read the byte-oriented base again; designate this snapshot **B₂**.

All three reads precede the following clearing writes. The exact write order is:

| Order | Target address | Width | Value |
|---:|---|---:|---:|
| 1 | B₂ − 2 | 8 bits | 0 |
| 2 | B₁ + 1 | 8 bits | 0 |
| 3 | W + 4 | 32 bits | 0 |
| 4 | B₂ − 1 | 8 bits | 0 |
| 5 | B₁ + 2 | 8 bits | 0 |
| 6 | W + 8 | 32 bits | 0 |

These offsets do not depend on the entry index. B₁ and B₂ are separate snapshots, not one established stable base. The representation performs two iterations containing three writes each; it does not establish any larger reset.

Finally, the unmapped shared-object accessor is called, and F-ebd9fed2fee8 receives its result and the entry index. Unlike most later shared-object calls, this call uses the returned address without adding four.

### Conditional entry operation

On the common path, the function calls the unmapped shared-object accessor and then calls F-c1e400b68436 with the returned address plus four bytes and the entry index.

Only if the result equals `0x13` does it call F-a2715f79cdcc with the entry index.

That dependency’s result is compared with 2 as an unsigned 32-bit value:

- Results 0 and 1 cause F-352a899fb784 to receive the context and that result.
- Every other 32-bit pattern suppresses F-352a899fb784.
- In particular, patterns representing negative signed values do not satisfy this unsigned comparison.

F-88707f7d96dd is then called with the context and entry index, regardless of whether either conditional call occurred.

### Polling

After submission returns, the function reads a separate 32-bit global value once. This captured value seeds all polling iterations; the global is not re-read by the loop.

Each iteration:

1. Writes the captured seed into the first 32-bit temporary slot.
2. Writes the same seed into the second, distinct 32-bit temporary slot.
3. Calls F-704f99fd5e22 with the context, entry index, the first slot’s address, the second slot’s address, and zero.
4. Repeats if the result is zero.

There is at least one call. Values written through either slot address are replaced with the captured seed before the next call.

Any nonzero result ends polling. There is no visible timeout, delay, retry limit, cancellation check, or distinct treatment of negative nonzero results. If every result is zero, all subsequent operations remain unreached.

### Matching-context update

After polling terminates, the function reads the 32-bit context field at offset `0x2D0` and compares it with the entry index.

If they differ, it neither writes that field nor calls F-fa1e7c5a0d15 at this stage.

If they match:

1. It writes zero to the context field.
2. It evaluates whether the record’s 32-bit field at offset 4 differs from `0x0B`.
3. If different, it calls F-fa1e7c5a0d15 with 1.

The context write precedes the record-field comparison and is not conditional on that comparison’s result. Entry index zero receives no special exemption.

The function directly initialized the record field to `0x10` and shows no later direct assignment to it. Its containing record was exposed to F-c6c589453fa8, however. Whether any dependency can validly alter it before this comparison is unresolved; the comparison must not simply be discarded as always true.

### Status-byte update

The represented signed-byte comparison distinguishes bit pattern `0xFE`:

| Observed byte | Flag passed to F-ca1c4e2f14bb | Selected replacement |
|---|---|---|
| `0xFE` | False | `0xFE` |

F-ca1c4e2f14bb receives the context, entry index, and selected flag. After it returns, the function writes the selected replacement byte.

The address, flag, and replacement are determined before the call. The function does not re-read the table base or status byte afterward. A helper mutation of the original byte can therefore be overwritten; a helper change to the global base does not redirect this captured-address write.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless a case states otherwise, dependencies return normally and do not change state relevant to that case.

1. **Skipped reset still reads the global.** With transition `0x108`, the initial table-base read occurs, but the reset-time re-read and all special-reset writes are skipped. The submitted transition byte is nevertheless `0x08`.

2. **Different initial-table snapshots.** If the initial read yields address A and the reset-time read yields address C, transition 8 causes zero-byte writes to C + 4 × entry index, then A + 4 × entry index + 1, +2, and +3. Acceptance must not require all four writes to target one consecutive region. If A equals C, the four targets are consecutive.

3. **Different fixed-clear snapshots.** If the ordered global reads yield B₁, W, and B₂, acceptance requires writes to B₂−2, B₁+1, W+4, B₂−1, B₁+2, and W+8, in that order and at the specified widths. Equality of B₁ and B₂ is not required.

4. **Unsigned filtering.** With F-c1e400b68436 returning `0x13`, a subsequent result of 1 reaches F-352a899fb784 with 1. Results 2 and `0xFFFFFFFF` suppress it. If the first result is not `0x13`, neither conditional dependency is called.

5. **Polling resets both slots.** If the captured seed is S and polling results are zero, zero, then nonzero, there are three calls. Both slots contain S immediately before each call, even if earlier calls modified them or the seed global.

6. **Persistent polling.** If polling always returns zero, the context update, status-byte operation, and final four operations are not reached.

7. **Matching zero index.** If the entry index and context field are both zero and the record field remains `0x10`, the function writes zero to the context field and then calls F-fa1e7c5a0d15 with 1.

8. **Conditional record mutation.** If a valid dependency interaction leaves the record field equal to `0x0B` before its later comparison, a matching context field is still cleared, but F-fa1e7c5a0d15 is suppressed. The availability of such an interaction is not established.

9. **Captured status decision.** Status `0xFE` produces a false flag and replacement `0xFE`; every other byte produces a true flag and replacement zero. A helper change to that byte is overwritten at the captured address.

10. **Unspecified record bytes.** Acceptance must not require zeros or any other fixed pattern at record offsets 1–3.
