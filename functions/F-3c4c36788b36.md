# F-3c4c36788b36

## Purpose

F-3c4c36788b36 operates on a descriptor for contiguous 16-byte records and a supplied source record. Its visible behavior selects among three paths:

- Use an available record slot and initialize its embedded sequence.
- Modify existing storage when the descriptor initially has no available slot but dependency results select a reuse path.
- Allocate replacement outer storage, transfer ranges, construct a record, dispose of old storage, and publish a replacement descriptor.

The apparent intent is insertion or append of a record containing a sequence of 4-byte elements. That interpretation is **inferred**, not a substitute for the visible behavior. In particular, the reuse path contains a backward traversal with a potentially enormous iteration count, and the replacement-storage path returns the outer capacity boundary rather than the newly inserted record’s embedded sequence.

This contract describes the supplied static representation. It does not establish that every represented path is reachable, safe, or faithfully recovered.

## Interface

### Inputs

**Outer descriptor.** A pointer to at least three consecutive 32-bit fields:

| Byte offset | Visible role |
|---|---|
| 0 | Outer storage base |
| 4 | Current outer boundary |
| 8 | Outer storage limit |

The function treats record spacing as 16 bytes. Field names describe their observed use; the source does not independently establish their invariants.

**Source record address.** A 32-bit address-like input. The function passes the whole address to record-level dependencies and accesses an embedded descriptor beginning 4 bytes into the source:

| Source byte offset | Visible role |
|---|---|
| 0 | Record-level data handled by dependencies |
| 4 | Embedded sequence base |
| 8 | Embedded sequence end |
| 12 | Embedded sequence capacity boundary, where relevant to dependencies |

Sequence elements occupy 4 bytes in the visible address arithmetic. Their value type and lifecycle are unknown.

### Output

The result is a pointer-shaped 32-bit value whose meaning depends on the path:

- Available-slot path: the selected record’s address plus 4, except for an explicit null return described below.
- Reuse path, if it completes: the initially cached outer boundary plus 4.
- Replacement-storage path: the new outer capacity boundary.

These return values are not normalized to a single semantic role.

### Preconditions and arithmetic model

Successful ordinary execution requires readable and writable descriptors, valid dependency-specific arguments, and storage adequate for all accesses and transfers actually performed. The function does not visibly validate those requirements.

The representation uses 32-bit fields, 32-bit unsigned query results, and 32-bit address arithmetic. Unsigned comparisons and logical right shifts are visible in growth calculations. Signed-looking additions, shifts, and pointer conversions also appear; their precise overflow semantics are not established by this representation.

Any modular-arithmetic examples below are explicitly conditional on 32-bit wrapping target behavior. They are not claims that overflowing signed expressions have portable language-level semantics.

## Behavior

### 1. Initial selection and available-slot reservation

The function first reads the outer boundary and compares it with the outer limit.

If they differ, it chooses the available-slot path. It does not require the boundary to be less than the limit.

Before constructing anything, it writes the cached boundary plus 16 into the descriptor’s boundary field. If the cached boundary was zero, it immediately returns null. Consequently, this null return follows a descriptor mutation; it is not a no-effect failure.

For a nonzero cached boundary:

1. F-f4fd698ba468 receives that boundary and the source record address.
2. The dependency’s return value becomes the record address used for subsequent initialization. Equality with the reserved boundary is not established.
3. The function writes zero to that returned record’s offsets 4, 8, and 12, in that order.
4. F-e02ac27bd77d queries the source embedded descriptor.
5. A comparison of that unsigned result against 31 selects one of two stack-resident values used as the allocation count.

The supplied representation does not show those two values being initialized. Therefore the count, including any intended minimum-capacity policy, is **documented_only**.

F-871e64ddc6de is then called with the selected count multiplied by 4 and a second argument of zero. Its result is immediately stored as the destination sequence base.

F-c816a9b43103 receives the then-read source base, source end, allocated address, and destination embedded descriptor. After it returns, the function queries source length again through F-e02ac27bd77d and writes:

- Destination end: current destination base plus four times that returned length.
- Destination capacity boundary: current destination base plus four times the previously selected allocation count.

The destination embedded descriptor address is returned.

No allocation-result check, rollback, or explicit cleanup on failure is visible.

### 2. Initially equal boundary and limit: reuse decision

When the initial boundary equals the limit, the function calls F-8abe585ac5ab with no explicit argument, then F-5dbde81efa3b with the outer descriptor. If the latter’s unsigned result is smaller than the former’s, it selects the reuse path.

Those results resemble an outer size/capacity comparison, but that interpretation remains inferred. The first call’s missing argument must not be silently repaired.

#### Reservation and backward traversal

The function rereads the outer boundary, writes that reread value plus 16 back to the descriptor, and invokes F-62bbe2f0b7a7 with the outer descriptor and the reread boundary.

It then traverses backward in 16-byte steps. The stopping boundary is the **initially cached** boundary, not the reread boundary and not the descriptor’s current value.

At each step, it first subtracts 16 from the traversal address. If that address equals the cached stopping boundary, traversal ends without a disposal call at that address. Otherwise, F-ac1e579267a1 receives the corresponding decremented record address.

This is not safely interpretable as an ordinary empty-range loop. If the reread and cached boundaries are equal, the first comparison is against one record before that address.

Under a 32-bit wrapping model, with both boundaries unchanged and all calls returning, this entails 268,435,455 calls to F-ac1e579267a1 before the traversal address wraps back to the stopping boundary. Invalid memory access or dependency failure may occur much earlier. Without established wrapping semantics, termination is unknown.

If the two addresses are not congruent modulo 16, repeated wrapping subtraction by 16 cannot reach the stopping address.

#### Record update and alias check

After traversal completes, F-4fcc06b56813 receives the cached stopping boundary and the source record address.

The destination embedded descriptor is then taken as the cached boundary plus 4. If this equals the source embedded descriptor address, the function skips all remaining sequence-level work and returns it. Earlier reservation, traversal, and record-level operations have already occurred.

Otherwise, the function queries source length through F-e02ac27bd77d, then destination capacity through F-2aa59d7a08b5.

### 3. Reuse path: insufficient embedded capacity

If destination capacity is less than the queried source length, the function queries source length again and destination length separately.

For destination length \(n\), it computes two unsigned 32-bit candidates:

- \(n + 32\)
- \(n + (n \mathbin{\mathrm{shiftRight}} 1) + (n \mathbin{\mathrm{shiftRight}} 3)\)

It selects the larger candidate using unsigned comparison after the represented arithmetic. Overflow can therefore change the result from an unbounded mathematical growth formula.

It then compares that candidate with the newly queried source length. This comparison selects between two stack-resident values used as the actual allocation count. Their initial contents are not supplied. The actual capacity is therefore **documented_only**, rather than established as the maximum of source length and the growth candidate.

The visible operation order is:

1. Allocate four times the selected count through F-871e64ddc6de, with second argument zero.
2. Invoke F-c816a9b43103 on the current source range and the new allocation, passing the destination embedded descriptor.
3. Invoke F-f19cd7a3a483 with the destination descriptor and its then-current base/end.
4. Read the destination base, query destination capacity, and pass that saved base and queried capacity to F-ff1bdc376dcd, with third argument zero.
5. Publish the new allocation as destination base.
6. Query source length again and publish the destination end.
7. Publish the destination capacity boundary using the selected allocation count.

The old allocation is not visibly released before the transfer dependency is called. Conversely, this sequence does not establish what that dependency itself may release or mutate.

### 4. Reuse path: sufficient embedded capacity

If capacity is sufficient, the function compares separately queried destination and source lengths.

**Destination shorter than source:**

- Query destination length again.
- Invoke F-322ef06b78d8 for a source prefix of that many 4-byte elements, targeting the destination base.
- Query source length again and update destination end.
- Invoke F-c816a9b43103 for the remaining source suffix, targeting the destination position after the prefix.
- Return immediately.

This path does not explicitly rewrite the destination capacity boundary. The end update occurs before the suffix operation.

**Destination at least as long as source:**

- Invoke F-322ef06b78d8 for the entire then-read source range.
- Pass its return value and the destination’s then-read end to F-f19cd7a3a483, together with the destination descriptor.
- Query source length again.
- Set destination end to current destination base plus four times that length.
- Set destination capacity boundary to the same address.

Thus this path explicitly makes end and capacity boundary equal, even if capacity was previously larger. It must not be specified as preserving capacity.

### 5. Replacement outer storage

If the reuse comparison fails, the function queries F-5dbde81efa3b again. Let this result be \(n\). It computes an outer allocation count using the same unsigned growth candidates described above and chooses the larger candidate.

F-871e64ddc6de receives that count multiplied by 16 and a second argument of zero.

The following operations occur before the replacement descriptor is published:

1. F-92597cedeebc receives the current outer base, cached initial boundary, new allocation, and outer descriptor.
2. An insertion address is calculated as the new allocation plus the low-four-bits-cleared difference between the cached boundary and the **then-read** outer base.
3. F-62bbe2f0b7a7 receives the outer descriptor, that insertion address, and the source record.
4. F-92597cedeebc receives the cached boundary, then-current outer boundary, and a destination calculated again from the then-read outer base, plus 16.
5. F-5dbde81efa3b is queried again; this result is saved for the final boundary calculation.
6. F-4d471b016ddf receives the outer descriptor and its then-read base and boundary.
7. The outer base is saved, F-8abe585ac5ab is called with the outer descriptor, and F-ff1bdc376dcd receives the saved base, query result, and zero.
8. The new base, new boundary, and new limit are written, in that order.

The new boundary is the allocation base plus 16 times the saved later size result, plus another 16. The new limit is the allocation base plus 16 times the earlier allocation count.

The function returns that new limit. It does not return the insertion address.

## Side effects

Established direct effects include:

- Early outer-boundary advancement, before construction or sequence allocation.
- Writes to destination sequence base, end, and capacity fields.
- Replacement of the complete outer descriptor on the replacement-storage path.
- Allocation calls and release-shaped calls.
- Dependency-mediated transfer, record update, and range-disposal operations.

The function has no visible transactional guarantee. No explicit restoration follows a failed allocation, failing dependency, or incomplete transfer.

Ownership is only partially evidenced. Returned addresses refer to internal record metadata or an allocation boundary; the return alone does not establish independent ownership. The storage dependencies’ allocation, destruction, release, and exception behavior are unknown.

Dependencies may mutate passed descriptors, referenced storage, or globals. Repeated queries and field reads therefore cannot be collapsed into one stable snapshot without additional evidence.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Non-equal boundary and limit with zero boundary.** The boundary becomes 16 and the result is null. No record-operation dependency is called on this path.

2. **Available nonzero slot.** If F-f4fd698ba468 returns a valid record address, its three embedded descriptor fields are cleared before the source-length query. The returned pointer is that address plus 4, not necessarily the originally reserved address plus 4.

3. **Unchanged equal boundaries entering reuse.** If the decision dependencies leave the outer boundary unchanged, the backward traversal must not be described as immediately empty. Under wrapping arithmetic it traverses the address cycle before reaching the cached boundary again, subject to earlier faults.

4. **Embedded descriptor identity.** If traversal completes and source and destination embedded descriptor addresses are identical, sequence allocation and sequence-copy branches are skipped. Earlier side effects remain observable.

5. **Sufficient capacity, shorter destination.** Conditional on stable queries and conventional transfer behavior, the existing prefix is transferred first, destination end is updated second, and the remaining suffix is processed last. The function makes no explicit capacity-boundary write.

6. **Sufficient capacity, destination not shorter.** After transfer and trailing-range handling, both destination end and capacity boundary are explicitly set to the address computed from the latest source-length query.

7. **Outer replacement with stable size 10.** Assuming unchanged queries, no overflow, and successful dependencies, the growth count is 42: the candidates are 42 and 16. The allocation request is 672 bytes, the final boundary is new base plus 176, and the result and final limit are new base plus 672.

## Uncertainties

The following remain **documented_only**:

- Initial contents of stack-selected inner allocation counts.
- Exact dependency signatures, notably inconsistent argument counts.
- Whether query-like dependencies are pure or preserve globals and descriptors.
- Allocation failure signaling, alignment, zero-size handling, and ownership.
- Element construction, assignment, destruction, and overlap semantics.
- Signed overflow behavior and validity of wrapped addresses.
- Correctness and practical reachability of the backward traversal.
- Aliasing beyond the explicit embedded-descriptor equality check.
- Exception unwinding, hidden cleanup, and omitted control-flow effects.
- Whether the unusual return value and capacity updates are intentional.
