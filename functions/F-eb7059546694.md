# F-eb7059546694

## Purpose

F-eb7059546694 performs an in-place, format-selected traversal of records addressed through a trailing table of 16-bit offsets. For each visited record, it invokes dependencies at selected byte addresses. Format 4 additionally selects a payload-processing sequence using a 16-bit discriminator.

**Established behavior:** address selection, dependency-call order, conditional discriminator handling, and a normal return value of zero.

**Inferred intent:** the dependency calls and discriminator values are consistent with representation conversion of structured binary data. Neither the conversion operation nor its direction is established by the supplied evidence. In particular, the dependencies must not be specified as byte-swapping functions without independent evidence.

The function does not itself validate the structure, report malformed records, or establish ownership of the referenced storage.

## Interface

### Inputs

The function accepts three arguments:

| Argument | Role |
|---|---|
| Context | Address of an object accessed as an array of 32-bit integer slots. Slot 0 supplies a data-region address; slot 3 supplies an extent used to locate an offset table. |
| Format selector | A 32-bit integer. Exactly 3 and 4 select processing paths. Other values select neither path. |
| Discriminator-order selector | A 32-bit integer used only in the nonzero-header-flag path of format 4. Zero requests a discriminator dependency call before dispatch; any nonzero value requests that call after dispatch. |

The source-facing model uses 32-bit integers and address-bearing values, 16-bit short integers, and 8-bit bytes. No portable behavior for a different pointer or integer model is established.

### Output

Every path that reaches the function’s return produces the 32-bit value zero.

Zero is not a validation result. The same value is returned after processing records, processing no records, or selecting an unsupported format. A dependency fault or nonreturning dependency prevents this normal return.

### Referenced layout

Let **B** denote the address obtained from context slot 0 at function entry.

| Location | Interpretation by this function |
|---|---|
| B + 8 | One-byte flag, tested for zero versus nonzero |
| B + 10 | Unsigned 16-bit record count |
| Context slot 3 | Extent used in the initial table-address calculation |
| Trailing offset table | Consecutive unsigned 16-bit record offsets |
| Record byte 0 | Unsigned byte used to calculate the payload position |
| Payload byte 0, format 4 with nonzero flag | Signed 16-bit discriminator |

The initial table address is:

**B + initial extent − 2 × initial record count**

Each table element supplies an unsigned 16-bit displacement from the data-region address read from context slot 0 for that iteration. The displacement is not relative to the table or to the current record.

The initial data-region address and table address are retained. Later changes to context slot 0, the extent, or the count do not recompute that table address.

### Preconditions

For a defined, normally completing invocation:

- The context must permit the initial accesses to slots 0 and 3.
- B + 10 must permit a 16-bit read, including for unsupported format selectors.
- For supported formats, every evaluated count, table, record, flag, and discriminator access must be valid.
- The address calculations must identify valid storage under the applicable execution model.
- All dependency-specific access, alignment, mutability, and lifetime requirements must hold.
- Dependencies must return normally if a normal return from this function is required.

No explicit null check, bounds check, alignment repair, extent check, record-length check, or discriminator validation is present.

The extent’s legal range and signed-overflow behavior are not established. The table calculation must not be treated as a checked subtraction: an extent smaller than twice the count does not produce a reported error.

## Behavior

### Initialization and traversal

Before selecting a format path, the function obtains the initial data-region address and computes the trailing-table address using the initial count and extent. Thus, an unsupported format does **not** avoid all memory accesses.

For format 3 or 4, traversal starts with unsigned 32-bit index zero. Before each iteration, the index is compared with the unsigned 16-bit count reread at **B + 10**. The count is not captured once for the entire traversal.

For every admitted iteration:

1. The function obtains a record address from the current context-slot-0 address and that iteration’s table element.
2. It performs the format-specific dependency calls.
3. It increments the index and reevaluates the count condition.

The table element address uses the previously computed table address plus twice the index. The dependency evidence does not establish an ordering between the context-slot-0 read and the table-element read within record-address formation.

The changing count and changing context-slot-0 value can therefore affect later iterations. In contrast, the header locations remain relative to B, and the table address remains the initially calculated address.

There is no deduplication or sorting. Repeated offsets cause repeated visits, and out-of-order offsets are processed in table order.

### Payload position

For both supported formats, payload position is calculated only after the initial record dependency calls described below.

The function then reads the record’s current first byte and adds the following even displacement to the record address:

**2 × floor((first byte + 2) / 2)**

The byte is promoted before adding 2; the addition does not wrap at eight bits. The displacement ranges from 2 through 256.

This is an even displacement relative to the record. It does not guarantee that the resulting address is absolutely aligned if the record address is unaligned.

Because the first-byte read occurs after dependency calls, its value can reflect dependency side effects. It is not necessarily the byte value present at entry to the iteration.

### Format 3

For each record, the function invokes:

| Order | Dependency | Address |
|---:|---|---|
| 1 | F-bb2eb79124b3 | Record + 2 |
| 2 | F-df70a2b0a7d8 | Record + 6 |

It then calculates the payload position and reads the flag at **B + 8**.

If the flag is zero, it invokes **F-bb2eb79124b3** once at the payload address.

If the flag is nonzero, it invokes **F-df70a2b0a7d8** six times, in this exact payload-relative order:

**0, 2, 4, 6, 8, 10**

The third argument has no effect on format 3.

### Format 4: common prefix

For each record, the function first invokes **F-bb2eb79124b3** at record + 2. It then calculates the payload position and reads the flag at **B + 8**.

If the flag is zero, it invokes **F-bb2eb79124b3** once at the payload address. It performs no discriminator read and no discriminator dependency call on that path. The third argument has no effect there.

If the flag is nonzero, processing continues with discriminator handling.

### Format 4: discriminator ordering

With a nonzero header flag:

- If the third argument is zero, the function invokes **F-df70a2b0a7d8** at the payload address **before** reading the discriminator.
- It then reads a signed 16-bit discriminator at the payload address and selects a body sequence.
- If the third argument is nonzero, it invokes **F-df70a2b0a7d8** at the payload address **after** the body sequence.

Exactly one of these before-or-after calls is selected on any normally completed nonzero-flag format-4 iteration. The discriminator value used for dispatch is consequently read after the initial discriminator call in the zero-selector case, but before that call in the nonzero-selector case.

The recognized values are **0x0100, 0x0200, 0x0300, and 0x0400**. These are positive values in the signed 16-bit domain. They are native 16-bit read results, not specified byte sequences.

### Format 4: discriminators 0x0300 and 0x0400

Either value selects exactly one body call:

**F-bb2eb79124b3 at payload + 10.**

The two values have identical behavior within this function.

### Format 4: other discriminator values

No body dependency calls occur for any other discriminator value.

The selected before-or-after call at the payload address still occurs. An unknown discriminator is neither rejected nor reported through the return value.

### Unsupported formats

For a format selector other than 3 or 4:

- Initial address and table calculations still occur.
- No record traversal or dependency calls occur.
- The normal result is zero.

## Side effects

The function contains no explicit data-store operation of its own. Observable mutations may arise through its dependency calls.

Dependencies receive interior addresses into the referenced data. Their write footprints, global effects, allocation behavior, ownership effects, and error behavior are unknown. Passing an interior address does not establish transfer of ownership or permission to release storage.

The function does not explicitly allocate or release memory. This does not establish that its dependencies avoid either operation.

Aliasing is not excluded. A dependency could affect a later record byte, header flag, count, table element, context slot, or discriminator if its behavior and the storage arrangement permit that effect. The contract must therefore preserve the following distinctions:

- The initial base and table address are retained.
- The count is reread at each loop condition.
- Context slot 0 is reread for each record address.
- The payload-length byte is read after the common-prefix calls.
- The header flag is read after payload-position calculation.
- The discriminator is read at the third-argument-selected point.

A body dependency changing the discriminator does not cause redispatch within that iteration.

No rollback, transactional boundary, or recovery behavior is present. If execution stops during a dependency call, earlier effects are not explicitly undone.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid storage and normally returning dependencies.

1. **Unsupported format:** With selector 5, initial metadata is accessed, no dependency is called, and the function returns zero. Invalid initial metadata remains capable of preventing completion.

2. **Zero records:** With selector 3 or 4 and an initial count of zero, no record is visited and the result is zero. Table-address calculation still occurs.

3. **Payload displacement boundary:** If the first byte when read is 254 or 255, the payload displacement is 256 in both cases. It is not zero.

4. **Format 3, zero flag:** For one stable record, the call order is F-bb2eb79124b3 at record + 2, F-df70a2b0a7d8 at record + 6, then F-bb2eb79124b3 at the calculated payload. Changing the third argument does not alter this sequence.

5. **Format 3, nonzero flag:** After the common prefix, the six F-df70a2b0a7d8 payload calls occur in ascending offsets 0 through 10 at two-byte spacing. Any nonzero flag byte selects this path.

6. **Format 4, early discriminator processing:** With a nonzero flag and third argument zero, F-df70a2b0a7d8 receives the payload address before the discriminator read. If the subsequently read value is 0x0100, the six-call 0x0100 body follows. There is no second discriminator-address call afterward.

7. **Format 4, late discriminator processing:** With a nonzero flag, a nonzero third argument, and a discriminator read as 0x0400, the body calls F-bb2eb79124b3 at payload + 10, followed by F-df70a2b0a7d8 at the payload address.

8. **Unknown discriminator:** With a nonzero flag and an unrecognized discriminator, only the selected before-or-after discriminator call occurs after the common prefix. The normal result remains zero.

9. **Mutable count:** If the first record’s dependencies change the count at B + 10 from two to one, the next loop condition ends traversal. The initially calculated table address is not recomputed.

10. **Mutable context base:** If a dependency changes context slot 0, the next admitted iteration uses the new value as the record-offset base, while retaining the original table address and original-base header locations.

11. **Repeated offsets:** If two admitted table entries resolve to the same record and dependencies preserve traversal metadata, both entries are processed. The function does not suppress the second visit.
