# F-45b3522e4a7d

## Purpose

F-45b3522e4a7d conditionally copies one 16-bit memory value, may perform an additional low-address 16-bit update under exceptionally restrictive entry-state conditions, and then enters a non-returning sequence of computed control transfers and software interrupts.

No application-level purpose is established. The supplied representation does not support describing this function as a conventional parser, allocator, serializer, or other named service.

A substantial set of conditional operations appears between the initial copy and the terminal control-transfer loop. Under the ordinary 32-bit arithmetic interpretation described below, most of those operations are unreachable. They are not additional required effects merely because they appear in the supplied representation.

This contract distinguishes:

- **Established static behavior:** operations and control dependencies visible in the supplied material.
- **Conditional deductions:** reachability conclusions using 32-bit modular arithmetic and the displayed pointer scaling.
- **Documented-only unknowns:** target execution semantics, external control-transfer behavior, and hidden entry-state validity.

## Behavior

### Arithmetic interpretation

The following behavioral deductions use a 32-bit address and unsigned-word model:

- Address addition and subtraction retain the low 32 bits.
- A 16-bit pointer increment advances the numeric address by two bytes.
- Unsigned right shifts insert zero bits.
- Carry means carry out of a 32-bit addition.
- A 16-bit store retains the low 16 bits of its value.

This is the useful machine-level interpretation of the supplied representation, not a claim that all displayed pointer operations constitute portable language-level operations.

### Initial branch and memory copy

If the explicit argument is not divisible by four, the function does not execute the initial copy. The subsequent conditional gates also remain unselected, and execution reaches the terminal loop with the original link address as its first control-transfer base.

If the argument is divisible by four, the function:

1. Derives a destination address by adding the offset word to the source address.
2. Reads one unsigned 16-bit value from the source address.
3. Derives an adjusted source-address value by subtracting the deduction word from the destination address.
4. Writes the previously read 16-bit value to the destination address.

The read precedes the write. There is no visible address-range, overlap, null, or alignment check.

The adjusted source-address value is used in later comparisons; deriving it does not itself access memory.

If the destination equals the source, the visible behavior is still a read followed by a write of the same 16-bit value. The contract does not eliminate that write as redundant, particularly where memory accesses may have device effects.

### Gate leading to the exceptional update

After the initial copy, additional work is selected only through a sequence of zero-result gates. Each gate depends on the preceding gate succeeding.

Under the stated 32-bit model, reaching the exceptional update requires all of the following:

- The explicit argument is divisible by four.
- The link address is zero.
- The unsigned stack address shifted right by one is zero.
- The comparison word equals the offset word.
- The deduction word equals the adjusted source-address value.
- The sum word is zero.
- Adding twice the offset word to the stack address yields zero modulo \(2^{32}\).

These conditions can be reduced further:

- The stack address must be zero.
- The offset word must be either `0x00000000` or `0x80000000`.
- The comparison word must equal that offset word.
- The source address and deduction word must satisfy  
  \(2 \times \text{deduction word} \equiv \text{source address} + \text{offset word} \pmod {2^{32}}\).
- The sum word and link address must both be zero.

The reason the stack address cannot be one is arithmetic, not a presumed valid-stack rule: twice any 32-bit word is even, so adding it to one cannot produce zero modulo \(2^{32}\).

Consequently, an environment that requires a nonzero valid entry-stack address cannot reach this update under this model. Such a requirement is not established by the supplied material itself.

### Exceptional low-address update

When the exceptional gate succeeds, the visible operations include:

- Updating a machine-state quantity to the low 32 bits of the stack address multiplied by 64.
- Deriving a new link address by adding 64 times the stack address to the previous link address.
- Reading an unsigned 16-bit value through the previous link address.
- Using the zero-extended read value as a destination address.
- Writing that value plus 15, truncated to 16 bits, to that destination.

The displayed memory expression contains two uses of the 16-bit read through the link address. It does not establish a reliable relative evaluation order for those uses or a hardware transaction count. For stable ordinary memory, both uses yield the same value. Volatile, device-backed, or concurrently changing memory requires a target-specific interpretation.

On the reachable exceptional path, the prior link address and stack address are both zero. Therefore:

- The 16-bit read is from address zero.
- The new link address remains zero.
- The derived machine-state quantity becomes zero.
- For a stable halfword value \(h\) at address zero, the destination address is \(h\), and the stored halfword is \((h + 15) \bmod 2^{16}\).

The initial copy precedes this update. If the initial copy changes address zero, the exceptional update observes the memory state after that copy.

### Reachability of the remaining conditional region

The later conditional region includes apparent address loads, wider writes, signed-halfword handling, and further state adjustments. Those operations are not reachable under the stated arithmetic interpretation.

The relevant invariant is:

- Entering the exceptional update requires the earlier auxiliary address value to be zero.
- That update advances a separate initially zero 16-bit pointer value by one element, making its numeric value two.
- The next gate can retain a zero result, but the following comparison combines that value two with the required zero auxiliary value, producing a nonzero result.
- All later conditional blocks require an uninterrupted chain of zero results and therefore remain unselected.

If the exceptional update is not entered, its first successor gate is already disabled.

Thus the later region establishes no additional reachable memory-layout contract under this model. In particular, this function must not be specified as reliably constructing a record or performing the apparent later 32-bit stores.

### Terminal control-transfer loop

The function eventually enters an unconditional repeating sequence, unless an earlier access faults or execution otherwise fails to reach it.

On the first iteration, the control-transfer base is the current link address:

- Normally, this is the entry link address.
- On the exceptional path, it is zero.

Each iteration performs, in order:

1. A call to the code address at the current base plus `0xEB6`, with explicit argument words `0`, `0`, and `0xFFFFFFA5`.
2. If that call returns, a call to code address `0x0857A94B`, with no explicit arguments shown.
3. If that call returns, a software interrupt with immediate `0x5B`.
4. If execution resumes after the interrupt, replacement of the control-transfer base with `0x083D4CC2`.
5. Repetition.

The third explicit argument to the first call has unsigned value `4294967205` and signed 32-bit interpretation −91. No signedness contract for the recipient is established.

These are computed code addresses, not reads of function pointers from those addresses. From the second iteration onward, the first target is `0x083D5B78`.

The supplied body provides no exit condition. It does not guarantee that either call returns or that the interrupt resumes at the following operation.

### Exceptional update with stable memory

Assume the execution environment permits the unusual entry state and low-address accesses:

- Argument zero.
- Link address, stack address, offset word, comparison word, and sum word all zero.

- Deduction word `0x1000`.
