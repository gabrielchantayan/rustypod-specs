# F-6ed206137014

## Purpose

F-6ed206137014 conditionally appends a nonzero object reference to an externally referenced linked structure, between two dependency calls. Its normal return value comes from the first dependency, not from the insertion decision or the final dependency.

The established behavior is narrower than “insert if absent.” Eligibility depends on two object fields being zero and the object differing from the observed head. The function does not search the structure, validate its links, or establish that an eligible object is absent from another structure.

The function snapshots the external control-area pointer immediately after the first dependency returns. Subsequent head accesses and the previous-tail read are expressed through the external pointer storage, whereas the final tail assignment uses the saved pointer. These references must not be treated as interchangeable when storage overlaps or external state changes.

“Head,” “tail,” “backward link,” and “forward link” describe inferred structural roles. The field offsets, access relationships, conditions, and write order are established by the supplied static representation.

- A nonzero first argument produces the result of F-ff91b5d6bcbb, provided all subsequent operations and the final dependency return normally.

### External pointer and control area

A separate external storage location holds the control-area pointer. Reading that pointer is distinct from reading either entry of the control area.

| Offset within control area | Size | Established use | Inferred role |
|---|---|---|---|
| `0` | 4 bytes | Compared with the object and zero; assigned the object on empty insertion. | Head |

The external pointer is captured once before object-field inspection. The final tail assignment targets offset 4 of that saved address.

Other control-area operations are expressed through the external pointer storage rather than through the saved address. This is a source-level relationship, not a claim about exact machine-level load counts.

## Behavior

### Zero object

A zero first argument returns zero immediately.

Neither dependency executes. The function does not read the external pointer storage, either object field, or any control-area entry.

### Initial dependency and pointer snapshot

For a nonzero object, the function first calls F-ff91b5d6bcbb with:

1. The object value.
2. The 32-bit value `1`.
3. The original third argument.
4. The original fourth argument.
5. The original fourth argument again.

The returned 32-bit value is retained for the eventual normal return.

Immediately after that call returns, the function reads the external control-area pointer and saves its value. This read occurs before the object’s field at `0x150` is read. It also occurs when subsequent eligibility checks reject insertion.

The first dependency is not known to preserve the object, the external pointer, the control area, or any other global state. Accordingly, both the saved pointer and the eligibility observations reflect state after that dependency returns.

Capturing a pointer value does not itself dereference its control area. If the first object field rejects insertion, the function does not subsequently access the head or tail entries directly. The external pointer storage must nevertheless have been readable for the snapshot.

### Eligibility

After capturing the control pointer, the function reads the object’s field at `0x150`.

- If this field is nonzero, insertion is skipped. The field at `0x154` is not read.
- If it is zero, the function reads the field at `0x154`.
- If the second field is nonzero, insertion is skipped.
- Only if both fields are zero does the function compare the object with the head entry addressed through the external pointer.
- If that head equals the object, insertion is skipped.

Thus, insertion requires two observed zero object fields and a head unequal to the object.

The saved control pointer is not used for this head comparison. The comparison is expressed through the external pointer storage. No separate tail-membership check, traversal, or consistency check occurs.

### Empty insertion

For an eligible object, the function next checks whether the head addressed through the external pointer is zero.

If zero, it performs these writes in order:

1. Assigns the object to the head addressed through the external pointer.
2. Assigns the object to the tail at offset 4 of the saved control pointer.

The head-zero check and head assignment are both expressed through the external pointer, not through the saved pointer. The final tail assignment uses the saved pointer even if an earlier write has affected the external pointer storage.

Neither object link is explicitly written on this branch. Under nonoverlapping storage and no interference, both remain at their observed zero values.

The existing tail value is not read. A stale tail is replaced without dereferencing the object it names, assuming the saved and externally referenced control areas remain the same.

### Nonempty insertion

If the eligible object encounters a nonzero head at the head-zero check, the function reads the previous tail at offset 4 through the external pointer.

It then performs these writes in order:

1. Assigns that previous-tail value to the new object’s field at `0x150`.
2. Assigns the new object to the previous tail’s field at `0x154`.
3. Assigns the new object to offset 4 of the saved control pointer.

The previous-tail value used for the first two writes has already been obtained before either write occurs. The final destination is determined by the earlier pointer snapshot, not by consulting the external pointer after those writes.

No direct head assignment occurs on this branch. The new object’s forward field is not explicitly cleared. Under nonoverlapping storage and no interference, it remains zero.

The previous tail is not checked for zero, validity, reachability from the head, or a zero forward field. Its forward field is overwritten without first being read.

### Final dependency and return

After insertion completes or is skipped, the function calls F-b56a17d0278a with:

1. The object value.
2. The 32-bit pattern `0xFFFFFFFF`.
3. Zero.
4. Zero.
5. Zero.

This call occurs on every nonzero-object path that reaches it, regardless of the first dependency’s result or the insertion decision.

The meaning of `0xFFFFFFFF` is unknown. Its established property is that all 32 bits are set; no command, mask, or signed-sentinel interpretation is established.

If the final dependency returns normally, the function returns the saved result of F-ff91b5d6bcbb. It does not use the final dependency’s result or reread the structure to compute its result.

## Side effects

### Direct access order

The established source-level order on the nonzero path is:

1. Initial dependency call.
2. Read and save the external control-area pointer.
3. Read the first object field.
4. Conditionally read the second object field.
5. Conditionally compare the head through the external pointer.
6. Conditionally check that head against zero.
7. Perform the selected insertion operations, ending with a tail write through the saved pointer.
8. Final dependency call.
9. Return the saved initial result.

This order does not establish volatile semantics, machine-level load counts, atomicity, or a concurrency protocol.

### Snapshot and aliasing consequences

Ordinary nonoverlapping execution with an unchanged external pointer makes the saved and externally referenced control areas identical. That is a conditional simplification, not an unconditional property.

An insertion write can overwrite the external pointer storage if those locations overlap. Such an overwrite does not retarget the final tail assignment: that assignment still addresses offset 4 of the saved pointer.

For example, the previous tail’s forward field may overlap the external pointer storage. The second nonempty-insertion write then changes that external pointer to the new object. The subsequent tail write nevertheless targets the originally saved control area.

Other aliases can make a write affect storage serving multiple roles. Therefore, statements such as “the head remains unchanged” or “the new forward link remains zero” require nonoverlap and absence of interference. The contract establishes direct destinations and ordering, not blanket preservation of every other logical field.

### Ownership and dependency effects

No direct allocation or release operation is visible. Neither dependency’s allocation, release, or ownership behavior is established.

Insertion does not by itself establish ownership transfer or a lifetime guarantee. Normal continuation requires the relevant object and control storage to remain valid after the first dependency.

The final dependency may observe and modify the post-insertion state, including releasing or otherwise invalidating storage if its unknown contract permits that. Consequently, direct insertion effects are not unconditional post-return memory guarantees.

### Errors, arithmetic, and interruption

The visible operations use 32-bit values, equality comparisons, fixed address offsets, and four-byte assignments. No signed ordering comparison or counter arithmetic is present.

Address formation uses offsets 336, 340, and 4. No bounds, alignment, or address-overflow checks are visible. The representation does not establish a portable wrapping-address rule for invalid inputs.

There is no explicit recovery, rollback, or distinct error result for invalid storage or inconsistent links. During nonempty insertion, the new object’s backward field is written before the previous tail’s forward field is accessed. An invalid previous tail can therefore interrupt execution after an earlier mutation.

Specific fault delivery, abnormal dependency outcomes, and whether later operations execute after a fault remain unresolved.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless specified otherwise, assume valid nonoverlapping storage, no concurrent interference, normal dependency returns, and no dependency mutation of the illustrated state.

### Zero object

Given a zero first argument:

- The result is zero.
- Neither dependency executes.
- No external pointer snapshot or structure access occurs.

### Nonzero first link

Given a nonzero object whose first link is nonzero after F-ff91b5d6bcbb returns:

- The external control pointer is read and saved before the first-link read.
- The second link is not read.
- No control-area entry is directly accessed.
- No insertion write occurs.
- The final dependency still executes, and the initial dependency’s result is returned.

### Nonzero second link

Given a zero first link and nonzero second link:

- The pointer snapshot precedes both link reads.
- No head comparison or insertion write occurs.
- The final dependency still executes.

### Object already at the head

Given both object fields zero and the externally referenced head equal to the object:

- The pointer snapshot and both link reads occur before the head comparison.
- Insertion is skipped.
- The tail is neither inspected for consistency nor repaired.
- The final dependency still executes.

### Empty head with a stale tail

Given both fields zero and a stable external pointer to a control area with zero head:

- The head is assigned through the external pointer.
- The tail is then assigned through the saved pointer.
- The stale tail value is not read or dereferenced.
- Neither object link is directly rewritten.

### Ordinary nonempty append

Given both fields zero, a distinct nonzero head, and a valid previous tail:

- The previous tail is read through the external pointer.
- The object’s backward field receives that tail.
- The previous tail’s forward field receives the object.
- The saved control area’s tail receives the object.
- Under the stated assumptions, the head is unchanged and the object’s forward field remains zero.

### Insertion overwrites the external pointer storage

Assume the control area is A, the new object is B, and the previous tail is C. The external pointer initially contains A. Both B links are zero, A’s head is nonzero and distinct from B, and A’s tail contains C.

Additionally, C’s forward field overlaps the external pointer storage; other relevant destinations do not overlap.

Then:

- The saved control pointer is A.
- B’s backward field receives C.
- Writing B to C’s forward field changes the external pointer storage from A to B.
- The final tail assignment still writes B at offset 4 of A.
- That final assignment is not redirected to offset 4 of B.

This example requires no assumption that the preexisting links form a valid list.

### Initial result is zero

Given a nonzero object and a zero result from the first dependency:

- The pointer snapshot and eligibility processing still occur.
- Eligible insertion is still attempted.
- The final dependency still executes.
- Normal return produces zero.

### Nonzero head with zero tail

Given an eligible object, a nonzero head, and zero tail:

- The nonempty branch is selected.
- Zero is assigned to the object’s backward field.
- A write of the object is attempted at offset `0x154` from the zero tail value.
- Successful completion, a particular fault, recovery, and an error return are not established.
