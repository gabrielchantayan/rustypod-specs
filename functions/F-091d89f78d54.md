# F-091d89f78d54

## Purpose

F-091d89f78d54 examines a dependency-provided collection, records category presence in four state bytes, performs category-dependent calls, and conditionally prepares a descriptor and initializes associated state.

Established behavior consists of memory accesses, value conversions, branch conditions, and dependency calls. Application-level meanings of the categories, descriptor fields, and final action are not established.

There are three visible outcomes:

- Return the 32-bit value zero.
- Execute a common failure sequence and return `0xffffffff`.
- Transfer control to a dependency represented as non-returning.

A zero return does not independently guarantee descriptor initialization: the final decision can be reached without descriptor preparation. Likewise, completing descriptor initialization does not guarantee a return, because the current category-1 flag can direct execution to the terminal dependency.

## Behavior

### Entry and shared state

The function clears state bytes `0x00`, `0x01`, `0x02`, and `0x03`, in that order. The remembered indices for categories 0, 2, and 3 initially equal zero.

It writes the context value as a 32-bit quantity at offset `0x04` of a shared object designated **G-A**.

A separate shared pointer holder, **G-B**, contains an address through which a 32-bit argument is read. The distinction between the holder, its pointer value, and the pointed-to word is observable:

1. Call F-U01 to obtain an interface object.
2. Read G-B and retain its current pointer value for later collection acquisition.
3. Separately read G-B again and read the 32-bit word through that pointer.
4. Invoke interface dispatch-table offset `0x08`, passing the interface object and that word.

The retained pointer from step 2 is not the specified source of the step-3 dereference. If the holder changes between the reads, the addresses can differ. No intervening dependency call is shown between those two holder reads.

A nonzero dispatch result selects the common failure path.

On a zero result:

1. Call F-U01 again; its returned object need not be the same object.
2. Read the 32-bit word through the **previously retained pointer**, without reloading G-B for this argument.
3. Invoke dispatch-table offset `0x14`, supplying the interface object, that word, and the address of a local collection-pointer slot.

The second dispatch’s direct return value is ignored. No initialization of the collection-pointer slot before this call, and no validation of its resulting value, is visible.

Consequently, dependency changes to G-B do not redirect this collection-acquisition dereference. Changes to the word at the retained address can still change the argument.

### Collection scan

The collection’s signed 32-bit count is read at offset zero for each loop-condition evaluation. The index starts at zero and advances by one after each iteration. A zero or negative initial count causes no iterations.

For an index *i*, the item base is collection base plus *i* times `0x60`. The category comparisons access the **32-bit word at item offset `0x08`**.

Each iteration contains four separate word reads and character conversions, in this order:

1. Read the word, convert it to char, and compare with 1. A match writes 1 to state byte `0x00`.
2. Read the word again, convert it to char, and compare with 0. A match writes 1 to state byte `0x01` and records this index for category 0.
3. Read the word again, convert it to char, and compare with 2. A match writes 1 to state byte `0x02` and records this index for category 2.
4. Read the word again, convert it to char, and compare with 3. A match writes 1 to state byte `0x03` and records this index for category 3.

The state writes are interleaved with later collection reads. This is not one category read followed by four comparisons, nor a mutually exclusive selection based on a saved value.

With stable, nonoverlapping storage, the four conversions observe the same word; flags record presence, and repeated categories leave the last matching index selected. With overlap or external mutation, a flag write can affect a later comparison or a subsequent count read. The four comparisons must therefore remain distinct in the behavioral model.

The source operation is word-to-character conversion. Unknown byte order prevents replacing it with “read the byte at item offset `0x08`.” Character signedness and conversion behavior for values outside the character range are not independently established.

### Gate and category actions

After scanning, the function reads state byte `0x01`. If it is zero, it also reads state byte `0x00`. It fails if both are zero. Categories 2 and 3 alone do not pass this gate.

After the gate passes:

- If the current state byte `0x02` is nonzero, call F-U02, then call F-U03 with its result, the collection pointer, category value 2, and the remembered category-2 index.
- Next, if the current state byte `0x03` is nonzero, perform the corresponding calls for category 3.
- Next, if the current state byte `0x00` is nonzero, perform the category-1 sequence.

The category-1 sequence calls, in order:

1. F-3609a8b2bc1a.
2. F-22e1c0b9e1bb.
3. F-3609a8b2bc1a again.
4. F-U04.
5. F-U05.

For F-U05, the second argument is the 32-bit value 1 if the then-current state byte `0x01` is zero, otherwise 2. Its first argument is formed by reading the 32-bit field at state `+0x1c` and adding `0x84`.

These checks use live state, not saved scan results. No dependency is assumed to preserve flags. A dependency-induced flag change can enable a later action even if the corresponding category was not found; an unchanged remembered index would then still be zero.

After these actions, a zero state byte `0x01` skips descriptor preparation and proceeds to the final state decision.

### Descriptor preparation and initialization

When state byte `0x01` is nonzero, the remembered category-0 index selects the item. The function performs the descriptor transfers in the table, including the conditional write to `0x58`.

The comparison with 5 uses the retained value from the initial explicit byte read at selected item `+0x09`. It does not reread the source or descriptor byte after the intervening transfers.

Next:

1. Call F-U02.
2. Call F-U03 with its result, the collection pointer, category value 0, and the remembered category-0 index.
3. Call F-U06 with state `+0x08`, the descriptor address, and the original result address.

A nonzero F-U06 result selects the common failure path.

On a zero result:

1. Call F-U01.
2. Reload the pointer from G-B and read the 32-bit word through that current pointer.
3. Invoke dispatch-table offset `0x18` with the interface object, that word, and the 32-bit descriptor field at `0x20`.
4. Call F-2a679a2c64f2 with state `+0x10` and the descriptor address.

The later dispatch does **not** use the retained acquisition pointer. Changes to G-B by any preceding dependency, including the immediately preceding F-U01, can make this dispatch use a different location. Descriptor `+0x20` is not directly populated by the listed transfers.

The dispatch’s return value is ignored. A nonzero F-2a679a2c64f2 result selects failure. A zero result is followed by F-30801baebbd2, then F-c54f538d90e7, then the final state decision.

### Final state decision

The function reads state byte `0x00`. If zero, it returns zero.

Otherwise, it compares state byte `0x20` with 2. On equality, it calls F-5f059abe9606 with the state address and the current character value at `0x21`.

It then reads state byte `0x20` again and supplies that value to F-U07. The supplied value need not equal the earlier comparison value, particularly after F-5f059abe9606.

F-U07 is represented as non-returning. Behavior if it returns is unresolved.

### Common failure sequence

Every visible failure branch performs these operations in order:

1. Write `0xffffffff` through the original result address.
2. Call F-8fc1650ac01f with 3.
3. Call F-U08 with the then-read shared argument **G-C** and zero.
4. Return `0xffffffff`.

The result write precedes both calls. Those dependencies may subsequently change the result word or other memory. There is no visible rollback.

## Acceptance examples

These are conditional static cases, not executed tests. Unless varied explicitly, assume valid disjoint storage, stable collection contents, and dependencies that preserve relevant memory.

1. **Initial dispatch failure.** A nonzero result at dispatch `0x08` prevents collection acquisition. Flags and context have already been written. The common failure sequence follows.

2. **Empty, negative, or insufficient categories.** A nonpositive count produces no iterations and fails the gate. A collection containing only converted categories 2 and 3 also fails, before their F-U03 calls.

3. **Repeated category 0.** If two items’ category words convert to 0, the later index supplies the selected-item transfers. Fixed collection transfers still use absolute offsets. With zero initialization statuses and category 1 remaining absent, the function returns zero after both post-initialization calls.

4. **Word narrowing differs from an addressed byte.** Suppose the target is big-endian and its word-to-character conversion keeps the low eight bits. A category word numerically equal to 1 matches category 1 even if its lowest-addressed byte is zero. Under the same assumptions, a source word `0x01020304` supplies character value 4 to descriptor `0x10`, `0x2c`, or `0x30`, rather than the lowest-addressed byte value 1.

5. **Interleaved scan mutation.** Suppose state byte `0x00` aliases the category word’s lowest-addressed byte, the target is big-endian, and the initial word is 1. The category-1 match writes that byte before the category-0 comparison rereads the word. That later comparison must use the modified word, not a saved original category.

6. **Shared pointer replacement.** Suppose the first retained G-B pointer addresses location A. The second F-U01 changes G-B to point to B without invalidating A. Acquisition dispatch `0x14` still receives the word at A. If G-B points to B after the later F-U01, dispatch `0x18` receives the word at B.

7. **Subtype 5.** If the retained explicit byte from selected item `+0x09` equals 5, descriptor `0x58` is cleared after the other transfers and before category-0 F-U03. Otherwise there is no direct write to that field.

8. **Category 1 without category 0.** The category-1 sequence supplies 1 to F-U05. Descriptor preparation is skipped. If the category-1 flag remains set, the terminal path follows.

9. **All four categories.** Category-2 processing precedes category-3 processing, followed by the category-1 sequence and category-0 preparation. F-U05 receives 2 if category-0 presence remains set.

10. **Late failure or action mutation.** A nonzero F-U06 status fails after descriptor writes, without restoration. Separately, if action comparison observes 2 and F-5f059abe9606 changes the action byte, F-U07 receives the reread value.
