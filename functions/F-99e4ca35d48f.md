# F-99e4ca35d48f

## Purpose

F-99e4ca35d48f conditionally converts a payload carried by an input object into a compact request, submits that request through F-704f99fd5e22, and, when submission returns zero, invokes an additional operation with an eight-byte record.

Processing is gated by a comparison against global state and by a subsequent authorization-like dependency result. Only three combinations of input discriminator and signed length are accepted. A rejected gate or unsupported combination leaves the working status at decimal 62.

The apparent intent is to translate selected input values into another representation and notify a state-associated subsystem after successful submission. That interpretation is inferred; the meanings of the discriminators, status codes, global object, and notification operation are not established.

The function also has an input-object cleanup path. The supplied representation marks a dependency on that path as non-returning, so a conventional caller-visible status return is not established for ordinary non-null inputs.

## Interface

### Inputs

The function has two arguments:

- **Context token:** a 32-bit value forwarded unchanged as the first argument to F-704f99fd5e22. This function does not otherwise interpret it.
- **Input-object address:** a value used as an address in a 32-bit address model.

The input object is accessed using the following byte offsets:

| Offset | Access width | Interpretation |
|---|---:|---|
| +8 | 32 bits | Payload address |
| +12 | 16 bits | Signed length or format-size field |
| +16 | 16 bits | Unsigned discriminator |

These fields are read unconditionally before input eligibility is established. Consequently, a null input-object address is not a supported optional-input case, despite a later null check before cleanup.

The established initial access order is:

1. Read the unsigned discriminator at +16.
2. Read the payload address at +8.
3. Read the signed 16-bit field at +12.
4. Call F-5f5f14cedda3 with the input-object address.

The three captured fields are not subsequently refreshed. A dependency that mutates the input object does not change these already captured values.

### Output and return status

The represented return type is a signed 32-bit integer.

A working status starts at hexadecimal 0x3E, or decimal 62. If submission occurs, the return value of F-704f99fd5e22 replaces that status. Otherwise, it remains 62.

This describes the status selected by the function, not a guarantee that it reaches the caller. For a non-null input object, the final path calls F-09ba55c206ac and then F-feee9156a257. The supplied representation marks the latter as non-returning.

### Preconditions

For execution without invalid accesses:

- The input-object address must permit the initial field reads.
- Global-state accesses must remain valid at each point where they occur.
- On a payload-processing path, the payload address must be non-null and must support the accesses described below.
- Dependencies that receive addresses of local storage must use those addresses within a valid lifetime.

No alignment validation, bounds validation, or defensive handling of stale global pointers is visible.

## Behavior

### 1. Capture input and obtain an identifier

After capturing the discriminator, payload address, and signed length, the function calls F-5f5f14cedda3 with the input-object address. Its 32-bit result becomes the input-associated identifier used for the eligibility comparison and, if reached, submission.

The function then captures a reference to a global cell containing an object address. It initializes the following local values before evaluating the gates:

- Working status: 62.
- Auxiliary word: zero.
- Mutable selector word: the unsigned 16-bit discriminator, zero-extended to 32 bits.
- Adjacent mutable word: 0xFFFFFFFF.
- Two-word record: both words zero.

The unsigned extension matters: discriminator values from 0x8000 through 0xFFFF remain positive 32-bit values.

### 2. Check global eligibility

Processing continues only when both of these conditions hold:

1. The object address currently stored in the global cell is nonzero.
2. The 32-bit field at offset +0x2D0 in that object equals the identifier returned by F-5f5f14cedda3.

If either condition fails, the function skips payload processing and submission. The selected status remains 62, and execution proceeds to the final cleanup path.

A successful comparison does not freeze the global object or its identifier field. Later accesses resolve the object address again through the global cell.

### 3. Apply the second gate

When the global comparison succeeds:

1. An unmapped zero-argument dependency is called to obtain a 32-bit value.
2. The object address is read again through the captured global-cell reference.
3. The 32-bit field at offset +0x2D0 of that object is read.
4. F-9c4f3d705d74 receives the value from the zero-argument dependency and the newly read field value.

Only a nonzero result from F-9c4f3d705d74 permits payload processing.

The identifier supplied to this second gate can differ from the identifier observed in the earlier comparison if a dependency changes global state. No second equality comparison with the original input-associated identifier is performed.

A zero gate result leaves the selected status at 62.

### 4. Check the captured payload address

After both gates pass, a null captured payload address causes a call to F-a817d8d58c10. That call is marked non-returning in the supplied representation.

This check precedes validation of the discriminator/length combination. Therefore, even an unsupported combination reaches F-a817d8d58c10 if both gates pass and its captured payload address is null.

No status-returning recovery from that call is established.

### 5. Convert an accepted payload

Exactly three discriminator/length pairs reach submission:

| Unsigned discriminator | Signed length | Selector supplied to submission | Initial second record word |
|---:|---:|---:|---|
| 4 | 2 | Payload byte at offset 1, zero-extended | Low 16 bits contain the two payload bytes in reversed byte positions; high 16 bits are zero |
| 8 | 4 | 7 | Byte-reversed 32-bit payload word |
| 10 | 2 | 9 | Low 16 bits of the loaded payload word; high 16 bits are zero |

All other pairs skip submission and retain status 62. Negative signed lengths cannot match either accepted positive length.

#### Discriminator 4, length 2

The selector becomes the unsigned byte at payload offset 1.

The second record word is assembled so that:

- Bits 7–0 contain the byte at payload offset 1.
- Bits 15–8 contain the low byte of a 32-bit load at the payload address.
- Bits 31–16 remain zero.

The supplied representation expresses multiple payload reads, including a 32-bit dereference, despite the accepted length being two. It does not justify a contract in which exactly two bytes of readable storage are sufficient.

For ordinary stable memory on the apparent little-endian target, payload bytes 0x12 and 0x34 produce selector 0x34 and second record word 0x00001234.

#### Discriminator 8, length 4

The selector becomes 7.

A 32-bit payload word is loaded and its four bytes are reversed. The shifts and masks operate within 32 bits; no wider arithmetic is required.

#### Discriminator 10, length 2

The selector becomes 9.

The low 16 bits of a 32-bit payload load are copied into the low half of the second record word. The upper half remains zero. As with discriminator 4, the represented access is wider than the accepted length field.

#### First record word

For every accepted pair, the original unsigned discriminator is placed in the low 16 bits of the first record word. Its high 16 bits remain zero before submission.

Thus, immediately before submission, the eight-byte record consists of:

| Byte offset | Width | Contents |
|---|---:|---|
| 0 | 32 bits | Original discriminator, zero-extended |
| 4 | 32 bits | Converted payload value |

These are pre-submission values. Whether the record remains unchanged across dependencies is not established.

### 6. Submit the request

F-704f99fd5e22 is called with five arguments, in this order:

1. The context token.
2. The identifier originally returned by F-5f5f14cedda3.
3. Address of the mutable word initialized to 0xFFFFFFFF.
4. Address of the mutable selector word.
5. Address of the auxiliary word initialized to zero.

The selector word and the word initialized to 0xFFFFFFFF occupy adjacent 32-bit positions, with the selector first.

The submission return value replaces the selected status. No result values written into the three explicitly addressed local words are inspected afterward by this function.

A nonzero submission result skips the subsequent record operation. A zero result triggers it.

### 7. Perform the zero-status record operation

When submission returns zero:

1. Read the current object address through the captured global-cell reference.
2. Form an address at object offset +0x2D8.
3. Call an unmapped dependency with that address.
4. Call F-c6c589453fa8 with the arguments: integer 1, integer 0, address of the eight-byte record, integer 8.
5. Call another unmapped dependency with the same previously formed address.

The first and last calls have the shape of paired synchronization operations, but their actual semantics are unknown.

The +0x2D8 address is computed after submission. It can therefore refer to a different object from the one used by either eligibility gate. There is no visible null recheck at this stage.

The last call uses the same saved address as the first, even if the middle operation changes the global cell.

### 8. Follow the final cleanup path

All ordinary gate failures, unsupported pairs, and completed submission paths converge on a final input-object check.

For a non-null input-object address:

1. Call F-09ba55c206ac with that address.
2. Call F-feee9156a257 with no explicit arguments.

F-feee9156a257 is marked non-returning. If that annotation is accurate, the selected status is not returned on these paths.

If the input-object address is zero, the cleanup calls are skipped and the selected status is returned in the represented control flow. However, reaching this point with zero would already have required unconditional accesses near address zero and a call to F-5f5f14cedda3 with zero. It is not evidence of safe null handling.

## Side effects

Established direct behavior includes:

- Reading input-object fields before validation.
- Reading global object pointers and fields at several distinct times.
- Reading payload storage only after both gates pass and the payload-null check is satisfied.
- Initializing and modifying local request storage.
- Invoking dependencies with the arguments and ordering described above.
- Passing the input object to a final dependency on ordinary non-null paths.

No direct write to the input object, payload, or global object is visible. Dependencies may mutate any state available to them; their names and calling patterns do not establish preservation guarantees.

Ownership is unresolved:

- F-09ba55c206ac receives the input object, but whether it releases, resets, or retains it is unknown.
- The original payload address is not directly passed to a release operation.
- The function passes addresses of local storage to dependencies. Retention beyond the function’s active lifetime is not established as safe.
- The record operation’s eight-byte size does not establish whether F-c6c589453fa8 copies the bytes synchronously.

There is no visible rollback. Once submission or another dependency has executed, later failure or non-return does not undo its effects.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Payload examples assume stable ordinary memory and the apparent little-endian target representation.

1. **No eligible global object.**  
   If the global cell contains zero at the first gate, neither the second gate nor payload conversion nor submission occurs. The selected status remains 62. A non-null input still reaches the final dependency sequence.

2. **Identifier mismatch.**  
   If the input-associated identifier differs from the global-object field, submission is skipped, even when the payload and format would otherwise be acceptable.

3. **Second gate returns zero.**  
   If the first gate passes but F-9c4f3d705d74 returns zero, a null payload does not trigger F-a817d8d58c10. Payload-null handling lies after this gate.

4. **Unsupported format with null payload.**  
   If both gates pass, the captured payload is null, and the discriminator is unsupported, F-a817d8d58c10 is nevertheless called before format rejection.

5. **Accepted two-byte reversal.**  
   With discriminator 4, signed length 2, and payload bytes beginning 0x12, 0x34, 0x56, 0x78, submission receives selector 0x34. The pre-submission record words are 0x00000004 and 0x00001234.

6. **Accepted four-byte reversal.**  
   With discriminator 8, signed length 4, and payload bytes 0x12, 0x34, 0x56, 0x78, submission receives selector 7. The pre-submission record words are 0x00000008 and 0x12345678.

7. **Accepted low-half extraction.**  
   With discriminator 10, signed length 2, and payload bytes beginning 0x12, 0x34, 0x56, 0x78, submission receives selector 9. The pre-submission record words are 0x0000000A and 0x00003412.

8. **Wrong signed length.**  
   Discriminator 8 with length 2, or discriminator 4 with length −1, does not submit. The selected status remains 62.

9. **Submission failure.**  
   If submission returns a nonzero value, that value becomes the selected status and F-c6c589453fa8 is not called.

10. **Global replacement during submission.**  
    If submission returns zero after replacing the object address in the captured global cell, the +0x2D8 operation address is derived from the replacement object. Earlier eligibility does not pin the original object.
