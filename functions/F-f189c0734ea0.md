# F-f189c0734ea0

## Purpose

F-f189c0734ea0 conditionally validates a referenced data object, resolves two entries from it, and records selected results in a caller-supplied context.

The operation is gated twice: first by F-842c847230dc, then by a context state word. If either gate suppresses processing, the function returns 1 without directly modifying the context. Otherwise, it may invoke a preparation dependency, check two identifying values, and perform two lookups.

The return value is not a complete summary of context state. In particular, an absent second lookup result causes an early return without a direct update to the context state word. A nonzero return can therefore accompany an incomplete set of output fields.

Names such as “descriptor,” “signature,” and “lookup” below describe inferred roles. The established behavior is the access, call, comparison, and write sequence specified here.

## Behavior

### 1. Initial gate

The function initializes its prospective return status to 1 and calls F-842c847230dc with no explicit arguments.

If that dependency returns nonzero, the function immediately finishes with return value 1. It performs no direct context access on this path.

If the dependency returns zero, the function reads the context state word at offset +8:

- A nonzero state word suppresses further processing and produces return value 1.
- A zero state word permits processing to continue.

Changes made by F-842c847230dc are not undone. In particular, the tested state word is read after that call returns.

### 2. Preparation decision

On the processing path, the function reads the descriptor address from context offset +4 and reads the descriptor state at descriptor offset +4.

This access occurs **before** the later explicit descriptor-null check. A null descriptor at this point is therefore not a safely handled rejection case.

If the descriptor state is not −1, preparation is skipped and the prospective return status remains 1.

If the descriptor state is −1:

1. The function reads the auxiliary address from context offset +0.
2. It reads a 32-bit argument from auxiliary offset +4.
3. It passes that argument to F-14a05337bb55.
4. The low 32 bits of the returned 64-bit value replace the prospective return status.

The upper 32 bits of that result do not determine a later stored field or the final return value on any normally completing path shown here.

The function does not directly replace the context’s descriptor address with any portion of the preparation result. Any descriptor replacement or descriptor-state update associated with preparation must be performed through side effects of the dependency or external state.

### 3. Post-preparation validation

After the preparation decision, the function re-reads the descriptor address from context offset +4. This permits a preparation dependency to have changed that address.

If this newly read descriptor address is nonzero, its descriptor state at offset +4 is read. That read occurs before the prospective return status is tested for zero.

Validation then rejects the operation on the first applicable condition:

1. The re-read descriptor address is null.
2. Its descriptor state is −1.
3. The prospective return status is zero.
4. The first decoded signature differs from its expected global value.
5. The second decoded signature differs from its expected global value.

The signature steps execute only if all preceding conditions permit them:

- For the first signature, the function reads the data address at offset +0 of the captured, re-read descriptor and passes it to F-76bf07f4ac67.
- For the second signature, it re-reads the descriptor address from the context, reads that descriptor’s data address, adds 8, and passes the resulting address to F-76bf07f4ac67.

The first comparison uses one global expected value; the second uses a distinct global expected value.

The second signature does not necessarily use the same descriptor or data address as the first. F-76bf07f4ac67 is not established to preserve the context or globals. Moreover, the second signature path does not repeat the earlier descriptor-null or descriptor-state checks after re-reading the descriptor address.

If validation rejects:

- The prospective return status becomes 0.
- The context state word at offset +8 is written with −1.
- The function returns 0.

No direct write to context offsets +12 or +16 occurs on this rejection path. Dependency side effects remain possible.

### 4. First lookup and output write

After both signature checks pass, the function calls F-b5bee446b938 with three arguments:

1. The context address.
2. The data address obtained through the context’s then-current descriptor address.
3. A first global selector value.

After that call returns, its 32-bit result is written to context offset +16.

A zero first result is not treated as a rejection. The second lookup still occurs. The function does not directly validate the first result or use it to select the return status.

### 5. Second lookup and early return

The function calls F-b5bee446b938 again, using:

1. The context address.
2. A freshly obtained data address through the context’s descriptor address.
3. A second global selector value.

The first lookup and its output write precede this call. Consequently, the second lookup can observe the updated context field at offset +16. It can also observe any side effects from the first lookup.

If the second lookup returns zero, the function immediately returns the prospective return status.

On this early-return path:

- There is no direct write to context offset +12.
- There is no direct write to context offset +8.
- The direct write to context offset +16 has already occurred.
- Any dependency-originated modifications are retained.

In particular, the initially observed zero state word is not explicitly changed to a completed or failed state on this path.

### 6. Nonzero second lookup result

1. The function adds 4 to that saved result.
2. It calls F-c223c8c1cf8e with the resulting address-like value.
3. After the call returns, it writes the conversion result to context offset +12.
4. It adds 8 to the saved second lookup result.
5. It writes that value to context offset +8.
6. It returns the prospective return status.

The final state value is derived from the saved second lookup result, not from the conversion result.

A zero conversion result is stored normally. It does not cause rejection or change the function’s return status.

## Acceptance examples

These examples are conditional contracts, not observed executions. Unless stated otherwise, assume valid addresses, normally returning dependencies, representable address additions, and no dependency side effects beyond those described.

1. **Gate suppresses all processing.**  
   If F-842c847230dc returns nonzero, the result is 1 and there are no direct context reads or writes. This does not imply that the dependency itself leaves memory unchanged.

2. **Existing state suppresses processing.**  
   If the gate returns zero and context offset +8 contains −1, or any other nonzero word, the result is 1. Preparation, signature decoding, and lookups do not occur.

3. **Preparation remains unsuccessful.**  
   Suppose the initial descriptor state is −1, preparation returns a low word of zero, and the post-preparation descriptor is nonnull. Its state word is read, then validation rejects. Neither signature decoder is called. Context offset +8 becomes −1 and the result is 0.

4. **Preparation replaces the descriptor.**  
   Suppose preparation changes context offset +4 to a different valid descriptor whose state is not −1, and returns a nonzero low word. Validation uses the replacement descriptor rather than requiring continued use of the original one.

5. **First signature mismatch short-circuits.**  
   With otherwise acceptable state, a first signature mismatch prevents the second signature call and both lookups. The state becomes −1 and the result is 0.

6. **Zero first lookup is retained.**  
   If both signatures match and the first lookup returns zero, zero is written at context offset +16. The second lookup still runs.

7. **Absent second lookup leaves completion state unwritten.**  
   If the second lookup returns zero, the function returns its prospective status without directly writing offsets +8 or +12. The first lookup result remains stored at +16.

8. **Full result path preserves non-Boolean status.**  
   Suppose preparation supplies low word 7, both signatures pass, and the second lookup returns an address A. If conversion of A + 4 returns zero, the function stores zero at +12, stores A + 8 at +8, and returns 7.

9. **A later null descriptor is rejected; an initial null is not safely checked.**  
   If preparation changes a previously accessible descriptor address to null, the post-preparation null check leads to rejection. If the descriptor is already null at the initial descriptor-state access, the function attempts an access through that address before reaching any null check.
