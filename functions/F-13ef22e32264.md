# F-13ef22e32264

## Purpose

F-13ef22e32264 initializes an embedded work area in a caller-provided context and processes work until the context’s current-work pointer is observed below the initial work-area boundary. It returns a 32-bit status: zero on completion, or one when a checked dependency reports a nonzero result.

Each iteration selects behavior using signed comparisons of two 32-bit endpoints and a 32-bit probe. Depending on those comparisons, it invokes an unchecked dependency and advances the current-work pointer, retreats that pointer, or performs direction-specific processing after any required mode transition.

**Inferred intent:** the embedded area and pointer movements suggest a work-stack processor with direction-dependent processing modes. The application meaning of the work, endpoints, probe, and modes is not established.

## Behavior

### Initialization and first iteration

The routine retains context plus `0xBC` as the initial work-area boundary. It publishes that address to the current-work field at `0x38` before finishing initialization of the embedded words.

The visible initialization then copies the word at `0x48` to `0xCC`, followed by the word at `0x4C` to `0xD0`. It next stores Input A at `0xC4`, Input B at `0xC8`, Input C at `0xBC`, and Input D at `0xC0`, in that order.

These accesses are unconditional and precede every dependency call. The copies preserve the initialization-time values of `0x48` and `0x4C` in the embedded area; later completion writes to those source fields do not retroactively change the copies.

The first iteration begins without a completion or boundary check. The retained boundary is not recomputed from the mutable current-work field.

This ordering describes the supplied static representation. It does not establish instruction scheduling, atomicity, or safe visibility to concurrent observers.

### Record reads and interval selection

At iteration entry, the routine reads the current-work pointer from `0x38`. It then reads the second endpoint at relative offset `+0x14`, followed by the first endpoint at `+0x04`.

Both endpoints are interpreted as signed 32-bit integers. Their minimum and maximum define an inclusive interval. The routine retains the record value from `+0x00` before evaluating the probe comparisons.

The probe at `+0x0C` is first compared against the lower bound. If it is below that bound, the upper-bound comparison is skipped. Otherwise, a separate probe reference is used for the upper-bound comparison.

For stable record contents, this implements an inclusive signed range test. Under concurrent mutation, the evidence does not establish a single shared probe snapshot for both comparisons.

Endpoint ordering and interval construction use comparisons rather than subtraction. In particular, opposite signed extremes do not require computing an overflowing endpoint difference.

### Outside-range handling

A probe below the lower endpoint or above the upper endpoint selects F-0bf913449711. No explicit arguments are shown, and its result is ignored.

After that dependency returns, the routine reloads the current-work pointer from `0x38`, adds `0x10` bytes, and stores the resulting address back to `0x38`. It then performs the completion check.

The adjusted pointer is the dependency’s resulting pointer value, not necessarily the address used for the iteration’s record reads. No mode transition or direction-specific processing occurs on this branch. Equal endpoints do not override an outside-range result.

### Equal endpoints

When the probe is in range and the endpoints are equal, the routine subtracts `0x10` bytes from the record address captured at iteration entry and stores that address in `0x38`. It then performs the completion check without calling a dependency.

For stable contents, the in-range probe must equal the common endpoint. Unlike outside-range handling, this movement is based on the captured record address rather than a post-call reload.

### Direction selection and mode transition

For an in-range probe with unequal endpoints, the selected direction is:

- **1** when the second endpoint is less than the first.
- **2** when the second endpoint is greater than the first.

The direction is represented locally as a one-byte value. Both possible values are positive and fit in that width.

The mode byte at `0x68` is first compared with the selected direction. A match bypasses both transition dependencies.

For a mismatch, a separate read of the mode byte tests whether it is zero. A nonzero result requires F-ecde43d0a2b1 with the context argument. If that dependency returns nonzero, the routine immediately returns one.

After a zero result from F-ecde43d0a2b1—or when the second mode read was zero—the routine calls F-dbf79ec942b4 with the context and selected direction. A nonzero result immediately returns one.

Thus, with stable mode contents:

- Matching mode: neither transition call.
- Zero mode: F-dbf79ec942b4 only.
- Mismatching nonzero mode: F-ecde43d0a2b1, followed by F-dbf79ec942b4 if the first succeeds.

The routine does not directly assign the mode byte. It does not reread the mode after either dependency to verify that the requested transition occurred. The selected direction remains the one determined from the earlier endpoint reads.

### Completion and repetition

After every non-failing branch, the routine reads the current-work pointer and compares it with the retained initial boundary.

If the pointer is not below the boundary, processing repeats with another current-work read and another set of record accesses. Equality with the boundary does not complete the routine. There is no iteration limit.

If the pointer is below the boundary, the routine writes the iteration’s retained record value to `0x48`, then writes its retained first-endpoint bits to `0x4C`, and returns zero.

These values come from the record read before any dependency calls in that iteration. They are not refreshed after dependencies mutate memory and are not read from the final current-work address.

A pointer below the boundary is not dereferenced during completion. A pointer at or above the boundary will be used for record reads on the next iteration and must therefore identify valid storage.
