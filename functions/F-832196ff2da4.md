# F-832196ff2da4

## Purpose

F-832196ff2da4 applies a mutable descriptor to a selected object slot, updates shared state, and invokes dependencies.

Established behavior has two paths:

- **Selectors 0–4:** default and clip dimensions, copy descriptor fields into the object, calculate an adjusted address and packed configuration, write a selected shared-state bank, and invoke an indirect dependency.
- **Selector 5:** default dimensions without clipping, copy descriptor fields into the object, update special shared-state fields, invoke an indirect dependency, and call F-72bbeb9af70c.

Image-plane or display-plane configuration is inferred intent, not an established external meaning.

The return is a 32-bit word: zero after a supported path completes, or `0xffffffff` for an unsupported ordinary format or selector. Failure is not transactional: descriptor, object, and shared-state writes precede rejection.

The function receives:

1. **Object reference:** writable storage containing a 32-bit dispatch-table reference at offset `0x00`, slot-associated fields, and special bytes at offsets `0x1e4` and `0x1e5`.
2. **Selector:** a signed 32-bit integer. Explicit successful paths exist for 0–5.
3. **Descriptor reference:** caller-supplied readable and writable storage with accessed fields extending through offset `0x4f`. Ownership is unknown.

The supplied representation uses 32-bit address and integer arithmetic, 32-bit words, and eight-bit byte fields. Byte order and actual alignment requirements are not independently established.

Valid execution requires accessible descriptor, object, shared-state, and dispatch-table storage, plus callable dependency entries. No checks enforce these requirements. Object capacity must cover the selector-dependent writes, including writes performed before selector rejection.

## Behavior

### Normalization and common writes

The function first resolves defaults, in this order:

1. Nominal width equal to signed `-1` becomes the current active width.
2. Nominal height equal to `-1` becomes the current active height.
3. Auxiliary width equal to `-1` becomes the current active width.
4. Auxiliary height equal to `-1` becomes the current active height.

For every selector except 5, it then performs horizontal clipping followed by vertical clipping:

- If destination horizontal position plus active width exceeds 319, active width becomes 320 minus horizontal position.
- If destination vertical position plus active height exceeds 239, active height becomes 240 minus vertical position.

These comparisons and arithmetic use signed 32-bit operands. The conclusions require representable signed sums and differences; overflow behavior is not established.

Defaults precede clipping. Consequently, defaulted nominal and auxiliary dimensions retain the pre-clipping dimensions. There is no lower-bound clipping, negative-dimension rejection, or clamp to zero when a destination begins beyond the boundary.

Next, the function captures the shared-state base and clears its 32-bit word at offset `0x3ac`. It then performs the object stores in the layout-table order.

The final payload copy has distinct read ordering: descriptor words `0x44`, `0x48`, and `0x4c` are read first, in that order. Descriptor word `0x40` is then read and stored to the object's relative `0x44`; the three saved words are stored to relative `0x48`, `0x4c`, and `0x50`.

This is not a descriptor snapshot. Later reads can observe earlier writes if storage aliases. The order between operand reads within a single arithmetic expression is not established as an additional guarantee.

### Selector 5

After the common copy:

1. The current descriptor format byte is copied to object offset `0x1e4`.
2. The descriptor format is read for comparison with 8.
3. Shared-state word `0x28` receives `0x100` when that comparison matches, otherwise zero.
4. The dispatch entry at byte offset `0x24` is resolved and called with the object, selector 5, and a reference to descriptor offset `0x40`.

The third argument points into caller-supplied descriptor storage, not a temporary copy. Its ownership remains unknown. The dependency's return value is ignored.

After the call, the descriptor format is read again. Two 32-bit components determine shared-state word `0x2c`:

| Current format | First component | Second component |
|---|---|---|
| 8 | Nominal width with its lowest two bits cleared | Nominal width interpreted as signed, divided by two toward zero, then represented as 32 bits with its lowest two bits cleared |
| 9 or 10 | Nominal width masked with `0x7ffffffe`, then unsigned-left-shifted once | Same as the first component |
| Any other byte | 5 | The descriptor word read from `0x48` during the common copy |

For format 8, the two components use separate nominal-width reads. For formats 9 and 10, the second component reuses the calculated first component.

The stored word is the first component OR the second component unsigned-left-shifted 16 bits. Neither component is independently restricted to 16 bits. Existing upper bits of the first component can therefore contribute to the result.

The shared-state base captured before the callback is reused for this write. Changing the global base reference during the callback does not redirect it.

The function next reads object byte `0x1e5` once:

- **Zero:** select the current descriptor destination position and active dimensions.
- **Nonzero:** select destination position `(0, 0)` and dimensions `(320, 240)`.

It calls F-72bbeb9af70c with ten explicit arguments:

1. Object reference.
2. Zero for the zero-control-byte branch; one otherwise.
3. Descriptor word `0x20`.
4. Descriptor word `0x24`.
5. Descriptor word `0x28`.
6. Descriptor word `0x2c`.
7. Selected horizontal destination position.
8. Selected vertical destination position.
9. Selected active width.
10. Selected active height.

Argument preparation follows the branch-specific reads shown in the supplied representation. In the zero-byte branch, active height is read first, followed by auxiliary height, horizontal position, vertical position, active width, auxiliary width, horizontal source offset, and vertical source offset. In the nonzero branch, auxiliary control and both auxiliary parameters are read first; auxiliary height, auxiliary width, and the two source offsets are then read in that order.

Three local words are also prepared: `(0, 1, 1)` in the zero-byte branch, or the zero-extended auxiliary control byte followed by the two auxiliary parameters otherwise. They are not among the ten explicit arguments. Their possible calling-convention role is **documented_only**.

F-72bbeb9af70c's result is ignored. The function returns zero. No slot-5 format byte is rejected.

### Ordinary format calculations

For selectors other than 5, the current format byte selects a scale:

| Format | Scale |
|---|---:|
| 0 | 1 |
| 1 | 2 |
| 2–5 | 4 |
| 6–7 | 8 |

Any other format returns `0xffffffff` after the common side effects, without ordinary bank writes or dependency calls.

For a supported format, define these unsigned 32-bit quantities:

- **Start:** scale times horizontal source offset.
- **End:** scale times the sum of horizontal source offset and active width.
- **Stride:** scale times nominal width, followed by a logical right shift of one bit.
- **First group:** Start logically right-shifted three bits.
- **Floor end group:** End logically right-shifted three bits.
- **Ceiling end group:** Floor end group, increased by one when End's lowest three bits are nonzero.

The addition inside End is signed before multiplication; its overflow behavior is unresolved. Multiplication by the unsigned scale and subsequent unsigned arithmetic use 32-bit modular results. In particular, Stride is not signed division of a negative nominal width.

The adjusted address is the unsigned 32-bit sum of:

- Descriptor word `0x40`.
- Vertical source offset times Stride.
- First group times four.

For padding, subtract First group from Floor end group using unsigned 32-bit arithmetic:

- If the difference's low two bits are nonzero, padding is four minus that low-two-bit value.
- Otherwise, padding is four if End's low three bits are nonzero, and zero if they are zero.

The control word combines format shifted left eight bits, padding shifted left 24 bits, Start's low three bits, and bit 16 when scale is below eight. The format is reread when constructing this word.

The group count is Ceiling end group minus First group, masked to 16 bits, and stored as a full 32-bit word.

### Ordinary bank writes and callbacks

Selectors 0–4 select bank origins:

| Selector | Shared-state bank origin |
|---|---:|
| 0 | `0x58` |
| 1 | `0x70` |
| 2 | `0x88` |
| 3 | `0xa0` |
| 4 | `0xb8` |

Stores occur in this order:

1. Bank `+0x04`: control word.
2. Bank `+0x10`: group count.
3. Bank `+0x00`: Stride.
4. Bank `+0x0c`: active height OR active width shifted left 16 bits.
5. Bank `+0x14`: vertical destination position OR horizontal destination position shifted left 16 bits.

The active width and horizontal position shifts have **signed 32-bit left operands**. Defined wrapping is not established for negative operands or results outside the signed range. A sufficient arithmetic domain for these shifts is an operand from 0 through 32767. The low operands are read as unsigned 32-bit words and are not masked to 16 bits; their upper bits can contribute when the signed shifts themselves are defined.

Any selector outside 0–5 returns `0xffffffff` at the ordinary selector dispatch. Common writes have already occurred, and supported-format calculations have already been performed. No bank writes or callbacks follow this rejection.

For selectors 0–4, the dispatch entry at offset `0x24` is called with the object, selector, and a reference to a temporary 32-bit word containing the adjusted address.

After that call returns, the descriptor format byte is reread, zero-extended, and interpreted as an address value for a three-target comparison. Two targets are address values 5 and 7. The numeric address of the third symbolic target is not supplied.

If any comparison matches, the dispatch entry at offset `0x40` is resolved and called with the object and selector. The third target must not be assigned value 3. A format byte of 3 triggers this call only if the unresolved target's address equals 3.

Both dependency results are ignored. The function returns zero.

## Side effects

- Defaulting and clipping mutate the descriptor in place.
- Common object stores and shared-state clearing precede format or selector rejection.
- Ordinary bank writes precede the primary callback.
- Slot 5 writes shared-state `0x28` before its callback and `0x2c` afterward.
- Callback mutations can affect subsequent descriptor reads, object-control selection, and dispatch resolution.
- No explicit allocation, release, ownership transfer, rollback, synchronization, or dependency-error propagation appears in this function.

The ordinary callback receives a temporary word whose storage is available during the call; this function establishes no valid later-use lifetime. The slot-5 callback receives caller-supplied descriptor storage. Neither argument establishes ownership, retention permission, or a right to release memory.

Dependencies have no established preservation guarantees. If they invalidate storage that this function subsequently accesses, normal completion is not guaranteed.
