# F-30f6810628f4

## Purpose

F-30f6810628f4 dispatches nine operation selectors against a caller-supplied object. Depending on the selector, it constructs and exposes a shared result, exposes an object-resident result, delegates the operation, or performs an indirect operation before exposing the shared result.

A shared initialization check precedes dispatch, including dispatch of unsupported selectors. An unsupported operation can therefore have initialization-related side effects before returning `0`.

The established behavior consists of visible memory accesses, call ordering, branch conditions, and return propagation. Terms such as “initialization,” “cached field,” “result,” and “cleanup” describe inferred roles; they do not establish application semantics or dependency ownership.

## Interface

### Arguments and return value

The supplied representation uses 32-bit addresses and four-byte scalar values.

| Input | Established use |
|---|---|
| Object address | Base for object-relative accesses and arguments to dependencies. |
| Context value | A 32-bit value compared with an opaque constant for `0x9304` and forwarded for delegated selectors. |
| Operation selector | A 32-bit dispatch value. Recognized values are `0x9301` through `0x9309`. |
| Output-slot address | Address used for a four-byte result assignment on specified paths; also forwarded to the delegated handler. |

The four-byte return value is:

- `0` for an unsupported selector.
- `1` for recognized nondelegated selectors that complete normally.
- The exact return value of F-b315b12019ac for `0x9305`, `0x9306`, and `0x9308`.

A return of `1` does not establish that the output slot received a direct assignment. In particular, `0x9304` has normally returning paths without one.

### Shared storage and temporary areas

The function references a shared flag-bearing object, a gate reference, a shared-buffer pointer, a four-byte default value, initialization arguments, and selector-specific opaque resources. The flag test reads a four-byte word at offset `8` and examines only bit `0`.

Temporary storage includes an eight-byte area used by `0x9301`–`0x9303`, separate four-byte result slots, and four-, twelve-, and fifty-two-byte areas used on other paths. These sizes describe visible storage regions, not dependency-defined object layouts.

### Preconditions and ownership

Addresses must support the accesses performed on the selected path. No direct null checks validate the object, output slot, shared buffer, or indirect-dispatch object.

Requirements are path-dependent: a path without a direct object or output-slot access does not acquire such a requirement merely because other selectors use those addresses. Dependencies may impose additional requirements.

Passing a temporary address does not establish that a dependency avoids retaining or later modifying it. No ownership transfer, allocation, reference counting, release obligation, or returned-value lifetime is established. In particular, exposing a shared result does not establish that it survives later calls.

## Behavior

### Common initialization check

Before dispatch, the function captures the four-byte shared default and initializes its tentative return value to `1`. It then reads the shared flag word.

If bit `0` is set, it skips the gate call and the remaining initialization sequence.

If bit `0` is clear, the observable sequence is:

1. Call F-b255b26284e6 with the gate reference read for that call.
2. Read the global supplying initialization argument 2.
3. Read the global supplying initialization argument 3.
4. Read and capture the shared-buffer pointer.
5. Test the gate call’s return value for nonzero.

The three reads after the gate call occur even when its return value is zero. A zero result skips only the subsequent initialization writes and calls.

For a nonzero result:

- The previously captured default is written to the first four bytes addressed by a fresh read of the shared-buffer pointer.
- Zero is written at offset `4` through the buffer pointer captured before the gate-result test.
- F-804adc29bbfb receives that captured buffer pointer and the two captured initialization arguments, in argument order.
- F-d08d3ca17b81 receives the gate reference read for this later call.

Thus, the first initialization store and the second store use differently obtained pointer values. They address adjacent words if those pointer reads agree; the function does not explicitly enforce that agreement. The default is not refreshed after the gate call.

There is no second flag test and no direct flag-word update. Synchronization, publication, and one-time initialization guarantees remain dependency-defined. Later reads of shared references are not guaranteed to reproduce earlier values.

### Selector `0x9301`: threshold-dependent shared result

F-398e0e9a318a receives the eight-byte temporary’s address and an opaque input-resource address. The function then calls F-c7aad02b0442 with the object, that temporary, and addresses of two four-byte result slots.

The first slot is read and compared with `2` using an unsigned 32-bit comparison.

For a value below `2`:

- F-44362605ab79 receives the temporary’s address; its return value is saved.
- F-9d0ecc5f6adf is called.
- F-c0b020cd3882 receives that return value and the less-than-two resource.
- F-1f62160dfd52 receives the current shared-buffer pointer, the selected resource result, and the saved F-44362605ab79 result.

For a value at least `2`:

- F-44362605ab79 receives the temporary’s address; its return value is saved.
- F-9d0ecc5f6adf is called.
- F-c0b020cd3882 receives that return value and the other resource.
- The first result slot is read again, and this later value overwrites the second result slot.
- F-1f62160dfd52 receives the current shared-buffer pointer, the selected resource result, the saved F-44362605ab79 result, and the overwritten second-slot value.

The later first-slot read need not equal the value used for branch selection. Its address has escaped, and intervening dependencies are not established to preserve it. Branch selection is not reconsidered after those calls.

Both branches next call F-289ec4311c64 on the eight-byte temporary. They then call F-44362605ab79 with the shared-buffer pointer read for that call, assign its four-byte return value to the output slot, and return `1`.

### Selector `0x9302`: shared result using a delayed slot read

The eight-byte temporary receives the captured default in its first four bytes and zero in its next four bytes.

F-c7aad02b0442 receives the object, the temporary, and both four-byte result-slot addresses. F-9d0ecc5f6adf is then called, followed by F-c0b020cd3882 with its result and this selector’s resource.

Only after resource selection does the function read the second result slot. F-1f62160dfd52 receives the current shared-buffer pointer, the selected result, and the value present in that slot at this later read. That value is not guaranteed to remain the value initially supplied by F-c7aad02b0442.

The function then calls F-289ec4311c64 on the temporary, obtains the shared result through F-44362605ab79, directly assigns that return value to the output slot, and returns `1`.

The first result slot is not directly used as an argument after the producer call. This does not rule out dependency-mediated effects from its contents.

### Selector `0x9303`: shared result using two delayed slot reads

The eight-byte temporary is initialized as for `0x9302`, and F-c7aad02b0442 receives the same categories of arguments.

F-0f44a6c02122 then receives the object and an additional four-byte slot’s address. F-9d0ecc5f6adf and F-c0b020cd3882 perform resource selection.

After those intervening calls, the additional slot is read. The second result slot is also read for the ensuing call. F-1f62160dfd52 receives, in order:

1. The current shared-buffer pointer.
2. The selected result.
3. The value read from the additional slot.
4. The value read from the second result slot.

These are values present at their respective reads, not guaranteed unchanged outputs of their earlier producers.

F-289ec4311c64 is then called on the temporary. F-44362605ab79 receives the subsequently read shared-buffer pointer; its return value is assigned to the output slot. The function returns `1`.

### Selector `0x9304`: conditional object-resident result

If the context does not equal the opaque comparison constant, there is no selector-specific call or direct output-slot assignment. The function returns `1`.

For a matching context, the function reads the four-byte field at object offset `0x74`.

- Zero begins reconstruction without calling F-a43850bcdf96.
- Otherwise, F-a43850bcdf96 receives the subobject address at `0x7c`.
- Its return value is compared with a subsequent read of the field at `0x74`.

Equality bypasses reconstruction and directly assigns object address plus `0x94` to the output slot. The comparison uses the post-call field read, not necessarily the earlier nonzero value.

Reconstruction first performs these operations:

- F-40173c838070 receives a four-byte temporary’s address and two zeros.
- F-b304c40f7b39 receives the subobject at `0x78` and the preceding return value.
- F-3cdbb43c2646 receives that four-byte temporary’s address.
- F-fb045f7ae136 receives the fifty-two-byte temporary’s address and zero.
- F-b2077e6b0a6a receives the twelve-byte temporary’s address, the fifty-two-byte temporary’s address, and the subobject at `0x7c`.
- F-e872853778bf receives the twelve-byte temporary’s address.

If F-e872853778bf returns zero:

- F-9d0ecc5f6adf is called.
- F-5710a8628cba receives its result and two opaque resources.
- F-4225f441f48b receives the subobject at `0x94`, the selected result, and two zeros.
- Reconstruction is marked successful.
- Zero is directly written to the field at `0x74`.

If F-e872853778bf returns nonzero:

- F-7c17f91a10c9 receives a separate four-byte temporary’s address, the twelve-byte temporary’s address, an opaque resource, `1`, and `0`.
- F-b304c40f7b39 receives the subobject at `0x78` and that four-byte temporary’s address.
- F-3cdbb43c2646 receives the same temporary’s address.
- F-fb37bbc180ad receives the subobject at `0x78`.

A zero result from this first F-fb37bbc180ad call leaves reconstruction unsuccessful. A nonzero result causes:

- A second call to F-fb37bbc180ad on the same subobject; its return value is discarded.
- A call to F-4d0908b456c1.
- A call to F-4225f441f48b with the subobject at `0x94`, that return value, and two zeros.
- Reconstruction to be marked successful.
- A call to F-46cb7eebe25f with the twelve-byte temporary’s address.
- A direct write of its return value to object offset `0x74`.

No companion, dependency, or ownership relationship between F-7c17f91a10c9 and F-46cb7eebe25f is established.

After either reconstruction outcome, F-9beda7955a36 receives the twelve-byte temporary’s address, followed by an unmapped cleanup dependency receiving the fifty-two-byte temporary’s address.

Successful reconstruction then directly assigns object address plus `0x94` to the output slot. Unsuccessful reconstruction performs no direct output-slot assignment. This does not guarantee preservation of the caller’s value: dependencies may access the slot through aliasing or other unknown means. Earlier changes are not rolled back. Both outcomes return `1`.

### Selectors `0x9305`, `0x9306`, and `0x9308`: delegation

Each calls F-b315b12019ac with the object, context, a selector-specific resource, and output-slot address. Its exact four-byte return value becomes this function’s return value.

For `0x9306`, the function first writes byte value `1` at object offset `0x42`, calls the dependency, and writes byte value `0` there after normal return. It does not save or restore the prior byte value. The final zero write is not established for abnormal exits.

### Selector `0x9307`: combined-value indirect operation

F-59222578e3f0 receives a four-byte temporary’s address. F-b8274406a146 then receives that address and `1`; its return value is saved.

F-d188fd98fcb6 receives the subobject at `0x7c`. The function adds its return value to the saved return value and passes the 32-bit sum and another four-byte temporary’s address to F-dee541b2a059.

F-9d0ecc5f6adf is called, followed by F-682adfd5a561 with that result and `0x80`.

The returned address is treated as an object whose first four bytes identify a dispatch table. The function invokes the entry at byte offset `0x88`, passing the returned object, the current shared-buffer pointer, `8`, and the latter four-byte temporary’s address.

It then obtains the shared result through F-44362605ab79, directly assigns the return value to the output slot, and returns `1`.

There is no explicit overflow, range, or null check. The supplied representation establishes 32-bit addition, but does not independently establish portable signed-overflow semantics.

### Selector `0x9309` and unsupported selectors

For `0x9309`, F-438680ffebfe receives the shared-buffer pointer and the same opaque input-resource address used by `0x9301`. F-44362605ab79 then receives the shared-buffer pointer read for that later call. Its return value is directly assigned to the output slot, and the function returns `1`.

Other selectors return `0` without a selector-specific direct output-slot assignment. Common initialization effects remain possible.

## Side effects

Direct writes comprise shared initialization stores, temporary initialization and slot overwrites, conditional writes at object offset `0x74`, the paired byte writes at `0x42`, and the specified output-slot assignments.

Dependencies may additionally modify shared storage, escaped temporary slots, object fields, or other memory. No general preservation guarantee bounds those effects.

Output assignments occur after the preceding calls on their paths. Aliasing the output slot with object or shared storage can therefore affect observable state. Absence of a direct output assignment is not a promise that the caller’s stored value is unchanged.

No visible rollback, general error translation, or abnormal-exit cleanup mechanism is established. Cleanup ordering describes ordinary control flow only.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Zero gate result.** With flag bit `0` clear, a zero F-b255b26284e6 result still precedes reads of initialization argument 2, initialization argument 3, and the shared-buffer pointer, in that order. Initialization stores and the two subsequent initialization calls are skipped.

2. **Unsupported selector with initialization.** With a clear flag bit and nonzero gate result, initialization stores and calls precede return `0`. There is no selector-specific direct output assignment.

3. **Unsigned boundary.** For `0x9301`, a first-slot comparison value of `1` selects the below-two branch. Values `2` and `0xffffffff` select the other branch.

4. **Changed escaped slot.** Suppose `0x9301` initially compares first-slot value `2`, but an intervening dependency changes that slot to `7`. The selected branch remains the at-least-two branch; its later overwrite places `7`, not `2`, in the second slot.

5. **Delayed result reads.** If an intervening dependency changes the second slot before its read in `0x9302`, the later value is passed to F-1f62160dfd52. The corresponding delayed-read rule applies to both argument slots in `0x9303`.

6. **Context mismatch.** For `0x9304` with nonmatching context, there is no selector-specific direct output assignment, and the return is `1`. Preserving the caller’s stored value additionally requires that common effects do not modify it.

7. **Cached-field comparison.** With matching context, an initially nonzero field and an F-a43850bcdf96 result equal to the subsequently read field bypass reconstruction and directly expose object address plus `0x94`.

8. **Unsuccessful reconstruction.** A nonzero reconstruction probe followed by a zero first F-fb37bbc180ad result still reaches both cleanup calls. No direct output assignment follows; return remains `1`.

9. **Successful nonzero-probe reconstruction.** A nonzero first F-fb37bbc180ad result requires a second call. After the result-subobject update, F-46cb7eebe25f receives the twelve-byte temporary, and its return value is written to offset `0x74` before cleanup and output exposure.

10. **Delegated status and flag.** For normally returning `0x9306`, the direct byte writes surrounding delegation are `1` and then `0`, regardless of the original byte. Any four-byte status returned by F-b315b12019ac is propagated unchanged.
