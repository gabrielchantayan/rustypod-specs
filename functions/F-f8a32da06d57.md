# F-f8a32da06d57

## Purpose

F-f8a32da06d57 updates 32-bit destination words using masks expanded from overlapping pairs of source bytes. Expansion selects 32-bit lookup entries through a **global variable containing the lookup base address**.

The operation always starts with an already prepared destination write. If its outer count requests further processing, each group comprises a first-boundary update, zero or more ordinary updates, and a trailing-boundary update. The trailing result is prepared at the end of a group and written at the beginning of the next outer iteration.

Most blending uses byte-reversed destination values. The first prepared write has a separately supplied conversion mask and is not necessarily ordinary byte reversal.

**Inferred intent:** the expansion, fill word, boundary masks, and strides suggest a packed-mask drawing operation. No particular pixel format, geometry, or rendering interpretation is established.

## Interface

### Explicit inputs

The supplied representation uses ten 32-bit arguments:

| Position | Interpretation | Role |
|---|---|---|
| 1 | Unsigned word | Initial prepared value. Subsequent prepared values come from trailing-boundary calculations. |
| 2 | Signed integer | Number of immediately written words per processing group, with a minimum effective width of one. |
| 3 | Signed integer | Outer count, decremented after each prepared-word write. Processing continues only if the decremented value is positive. |
| 4 | Unsigned word | Low eight bits supply the lookup expansion’s left-shift count. |
| 5 | Signed integer | Byte displacement from the current prepared-word destination address to the next group’s first destination address. |
| 6 | Signed integer | Byte displacement from the retained source cursor to the next group’s first source address. |
| 7 | Opaque word | No visible use. |
| 8 | Opaque word | No visible use. |
| 9 | Unsigned mask | Additional preservation contribution for trailing-boundary updates. |
| 10 | Unsigned mask | Additional preservation contribution for first-boundary updates. |

There is no explicit return value or status result.

### Register-held entry state

Behavior also requires pre-existing state not represented by those arguments:

- The destination cursor for the initial prepared-word write.
- The retained source cursor.
- A 32-bit fill word.
- A 32-bit first-boundary mask.
- A 32-bit trailing-boundary mask.
- A 32-bit initial conversion mask.
- A right-shift control, whose low eight bits are used.

The origin and calling convention for this state are not established.

### Global lookup-base storage and lookup entries

Three distinct entities must not be conflated:

1. **Register-held entry state**, listed above.
2. **Global lookup-base storage**, holding an address used to locate lookup entries.
3. **Lookup-entry memory**, reached through the value read from that global storage.

The lookup base is not established as an entry-time snapshot. **Each table-access operand references the global base storage separately.** Each operand selects an entry at the currently obtained base plus four times an unsigned source byte.

Source indices range from 0 through 255; entry offsets range from 0 through 1020 bytes. Each selected entry is 32 bits wide.

A claim that all lookups use one table requires an explicit stability condition on the global base. Without it, a destination write that aliases the base storage can redirect later lookups.

### Memory and ownership requirements

The initial destination word must be writable regardless of whether any processing group executes.

For each executed group:

- Every destination word read and written must support the corresponding 32-bit accesses.
- Every selected source byte must be readable.
- The global lookup-base storage must be readable for every table-access operand.
- Each selected entry must be readable at the address obtained from that operand’s base value and source byte.

A readable table at entry is insufficient if an earlier write changes the global base or changes a source index.

Displacements between groups are byte displacements. Within a group, successive destination words are four bytes apart and source windows advance by one byte.

No visible bounds, permission, null-pointer, alignment, or overlap checks enforce these requirements. There is no visible allocation, release, ownership transfer, or reference-count operation.

## Behavior

### Numeric conventions

All masks and blend results are 32-bit words. Complements are restricted to those 32 bits.

**Byte reversal** exchanges the four bytes of a numeric 32-bit word: the least significant byte becomes the most significant, and the two middle bytes exchange positions. This does not establish memory endianness.

For a source window containing an earlier byte and its immediately following byte, the expanded mask combines:

- The entry selected by the earlier byte, shifted left using the low eight bits of argument 4.
- The entry selected by the following byte, shifted logically right using the low eight bits of the right-shift control.

The combination is bitwise union. Each entry selection independently references the global base storage; the definition does not assume a common base value for both operands.

The left-shifted entry is represented as signed, while the right-shifted entry is represented as unsigned. Large shift counts and signed left-shift limitations remain qualified under **Uncertainties**.

### Prepared-word write and termination

The first destination operation is a write, without reading the old destination word.

Its stored numeric value combines four contributions from argument 1:

- Bits 8–15 moved to positions 16–23.
- The low byte moved to positions 24–31.
- A logical right shift by eight, intersected with the initial conversion mask.
- The high byte moved to positions 0–7.

These contributions are combined by bitwise union. With conversion mask `0x0000FF00`, the result is ordinary byte reversal. Other masks can admit additional shifted bits or remove the usual middle-byte contribution.

After this write, the outer count is decremented. The representation also forms prospective next-group destination and source addresses before testing whether to continue. These address calculations do not themselves read source bytes, destination contents, the global base, or table entries.

If the decremented count is less than one, processing terminates. Subject to arithmetic qualifications, counts of one, zero, and negative values therefore still cause the initial write but no group processing.

### Group positioning and width

When processing continues, the group starts at:

- The current prepared-word destination address plus argument 5 bytes.
- The retained source cursor plus argument 6 bytes.

The effective group width, \(W\), is argument 2 when that argument exceeds one; otherwise it is one.

A group immediately updates \(W\) destination words and prepares one additional trailing word. Its source windows overlap by one byte. The overlap describes addresses, not cached values: a source byte occurring in successive windows can be read again after an intervening destination write.

### First-boundary update

The first expanded mask uses the group’s first two source bytes. Both table selections reference the global base after the preceding prepared-word write.

After expansion, the first destination word is read and byte-reversed for blending. The replacement combines:

- Expanded-mask bits that are also set in both the fill word and the first-boundary mask.
- Converted old-destination bits permitted by either argument 10 or the portion of the first-boundary mask outside the expanded mask.

The combined result is byte-reversed and written immediately.

Argument 10 contributes to preservation independently of the expanded mask. Fill and preservation contributions may overlap; they are combined by bitwise union rather than required to be mutually exclusive.

### Ordinary updates

If \(W\) exceeds one, the remaining \(W-1\) immediate updates are ordinary updates.

Each uses the next overlapping source window and the next destination word, four bytes farther along. Expansion precedes the destination read. In the byte-reversed blending representation:

- Bits selected by the expanded mask come from the fill word.
- Other bits come from the converted old destination.

The result is byte-reversed and written immediately. These updates do not use the boundary masks or arguments 9 and 10.

Each ordinary expansion references the global base after all preceding writes. A preceding write can therefore change not only source bytes or table entries but also the base used to locate subsequent entries.

### Trailing-boundary update

After the \(W\) immediate writes, the next overlapping source window supplies a trailing expanded mask. The next destination word is read and byte-reversed.

The pending result combines:

- Expanded-mask bits also present in the fill word and trailing-boundary mask.
- Converted old-destination bits permitted by either argument 9 or the portion of the trailing-boundary mask outside the expanded mask.

The initial conversion mask is replaced internally with `0x0000FF00`. The pending result becomes the next prepared word and is written, using ordinary byte reversal, at the beginning of the next outer iteration.

Thus the trailing word is not stored during its boundary calculation, but its prepared write occurs before the next continuation decision. Even the final group’s trailing result is written.

### Progression and counts

For positive initial outer count \(H\), assuming valid arithmetic and memory accesses:

- Processing groups: \(H-1\).
- Prepared-word writes, including the initial write: \(H\).
- Immediate writes per group: \(W\).
- Total destination writes: \(1+(H-1)(W+1)\).

For a group starting at destination address \(D\), immediate words occupy offsets zero through \(4(W-1)\). Its trailing word is at \(D+4W\). The following group starts argument 5 bytes after that trailing address, not after the previous group’s beginning.

For a group starting at source address \(S\), windows range from \((S,S+1)\) through \((S+W,S+W+1)\). The retained source cursor is \(S+W\); the following group starts argument 6 bytes after that cursor, not after the final byte read.

Each group contains \(W+1\) expansions and therefore \(2(W+1)\) global-base references in the supplied expression-level representation. This is not a hardware transaction-count guarantee.

## Side effects

The visible memory sequence is:

1. Write the prepared destination word.
2. If continuation is selected, evaluate the first expansion’s source-byte, global-base, and table-entry accesses.
3. Read and then immediately replace the first destination word.
4. Perform each ordinary expansion, destination read, and destination write in turn.
5. Perform the trailing expansion and destination read.
6. Prepare the trailing replacement and write it at the next prepared-write stage.

Within an expansion, the relative evaluation order of its two table-access operands is unspecified. The representation also does not establish whether an operand reads its source byte before or after reading the global base. Both supply the address needed for that operand’s entry access. No stronger ordering among those component reads is promised.

There is no entry-time snapshot of source data, table entries, or the global base. Consequently:

- A write aliasing source memory can change later source indices.
- A write aliasing lookup-entry memory can change later mask contributions.
- A write aliasing global-base storage can redirect later entry accesses.
- A write aliasing a later destination can change the old value used by that update.

These consequences apply to the initial prepared write as well as subsequent writes. In the absence of aliasing or external changes, the same base can remain effective throughout; that is a condition, not an unconditional guarantee.

No explicit recovery or rollback is shown. An access failure can occur after earlier writes have taken effect. Exact fault behavior is not established.

The final register-preservation contract is unknown. No synchronization or atomicity guarantee is established.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume readable and writable required memory, supported shifts, valid arithmetic, and stable inputs without interfering aliasing.

### Initial write only

With outer count one, initial prepared value `0x11223344`, and conversion mask `0x0000FF00`, the initial destination receives numeric word `0x44332211`.

No source-byte, global-base, lookup-entry, or old-destination read occurs.

With the same inputs except conversion mask zero, the stored numeric word is `0x44330011`. This distinguishes the first conversion from unconditional byte reversal.

### Minimum width

With outer count two and argument 2 equal to zero, there is one group: one first-boundary update followed by one trailing-boundary update. Together with the initial prepared write, there are three destination writes.

Argument 2 equal to one or a negative value produces the same operation counts under otherwise identical valid conditions.

### Ordinary replacement

With outer count two and argument 2 equal to two, there is one first-boundary word, one ordinary word, and one trailing word.

For the ordinary word, an expanded mask of zero preserves its numeric stored value. An expanded mask of `0xFFFFFFFF` replaces it with the byte-reversed fill word.

### Boundary preservation

If the first-boundary mask is zero and argument 10 is `0xFFFFFFFF`, the first-boundary word is preserved regardless of the fill and expanded mask.

The analogous trailing condition uses a zero trailing-boundary mask and argument 9 equal to `0xFFFFFFFF`.

### Base redirection by the initial write

Suppose the initial destination aliases the global lookup-base storage, and the initial conversion writes a valid new base value there. With outer count two, the first expansion must obtain its base through that updated storage, rather than an entry-time saved base.

This example additionally requires readable entries at the newly selected addresses.

### Base redirection between updates

Suppose a first-boundary write replaces the global base storage with another valid base, and group width is two. The following ordinary expansion references the replacement base. Its accesses are not constrained to the table used by the first expansion.

This does not establish an ordering between the two operands within either expansion.

### Cursor-relative displacement

With group width two, the trailing destination is eight bytes beyond the group’s first destination. The following group starts argument 5 bytes beyond that trailing address.

The retained source cursor advances two bytes from the group’s source beginning. Argument 6 applies there, even though the trailing expansion also read the byte three positions beyond that beginning.

- **Count underflow:** decrementing the minimum signed 32-bit outer count overflows a portable signed interpretation. Neither wrapping nor termination is promised for that input.
- **Address arithmetic:** wrapping, invalid prospective pointers, integer-address conversions, and unaligned accesses require execution-environment evidence.
- **Memory endianness:** numeric byte reversal is established; physical byte order is not.
