# F-85ea43423066

## Purpose

F-85ea43423066 resolves an unsigned 32-bit input to a 32-bit result through one of two paths:

- Inputs from 0 through 649 use a fixed-stride table.
- Inputs from 650 through 4,294,967,295 use an external lookup dependency, provided a shared context field is nonzero.

The function distinguishes an unavailable external context from an unsuccessful resolution. An unavailable external context produces zero without invoking the reporting dependency. An unsuccessful resolution invokes that dependency and then produces zero if the dependency returns normally.

Zero is not an unambiguous failure indicator. A selected table entry or external result may itself contain zero, and those values are returned without reporting a failure.

These are established control-flow properties. The interpretation of the input as an identifier, and of the returned word as a resolved value, is inferred intent rather than an established application-level meaning.

## Behavior

### 1. Select the resolution path

The table-path condition combines two unsigned comparisons:

- The input is less than 512; or
- The unsigned result of subtracting 512 is less than 138.

Together, these select exactly inputs 0 through 649.

For inputs below 512, the first comparison succeeds, so the second comparison need not be evaluated. For inputs at least 512, subtraction cannot underflow, and the second comparison accepts 512 through 649.

Consequently:

- 511 and 512 both use the table path.
- 649 is the final table-path input.
- 650 is the first external-path input.
- The maximum unsigned 32-bit input uses the external path.

There is no additional numerical range check on the external path.

### 2. Resolve a table-path input

The selected record address is the table base plus the input multiplied by 24 bytes.

Input zero receives special treatment:

1. The availability-marker read is skipped.
2. The function reads the 32-bit word at offset 0 of record zero.
3. That word is returned directly.

For inputs 1 through 649:

1. The function reads the selected record’s 32-bit marker at offset 8.
2. If the marker is nonzero, it reads the 32-bit word at offset 0 of that record and returns it.
3. If the marker is zero, it proceeds to the unsuccessful-resolution reporting path.

The marker is tested only for equality to zero. No particular positive value, bit pattern, or signed interpretation is required for acceptance.

A zero marker does not cause fallback to the external lookup. Conversely, a nonzero marker permits returning a zero value without reporting an error.

For the accepted table range, multiplying the input by 24 does not overflow a 32-bit unsigned integer. This does not prove that adding the offset to the table base yields a valid address; table placement and extent remain preconditions.

### 3. Check external-context availability

For inputs at least 650, the function reads the 32-bit field at offset 4 from the external-context root.

If the field is zero:

- F-932a35189ea0 is not invoked.
- F-4fc89ec41a6d is not invoked.
- The function returns zero immediately.

This is distinct from attempting an external lookup and obtaining no result.

If the field is nonzero, the function proceeds to prepare local request storage and invoke F-932a35189ea0.

### 4. Prepare and perform the external lookup

The explicit local writes appear in this order:

1. Store the 32-bit value 3.
2. Store the address of the eight-byte scratch region.
3. Store the input in a separate 32-bit local location.

The scratch bytes themselves are not initialized by this function before the call.

F-932a35189ea0 receives:

1. The external-context field value.
2. The address of the local word containing 3.

The context field appears separately in the availability test and in argument evaluation. The supplied representation does not establish a single atomic snapshot spanning those accesses.

The function does not explicitly place the input into the eight-byte scratch region. It would therefore be unsupported to specify that region as an initialized input key.

### 5. Interpret the external lookup result

The return from F-932a35189ea0 is tested for zero.

If it is zero, execution proceeds to the unsuccessful-resolution reporting path.

If it is nonzero:

1. Treat the returned value as an address.
2. Read the pointer-sized field at byte offset 4 from that address.
3. Dereference that pointer and read a 32-bit word.
4. Return the word.

Under the apparent 32-bit address model, the intermediate pointer field occupies four bytes. The essential established behavior is the two-level access: read an address from the lookup result’s offset-4 field, then read the final word through that address.

There is no explicit check that the intermediate pointer is nonzero. There is also no validation of the lookup result beyond its comparison with zero.

A final word equal to zero is returned as a successful-path value. It does not trigger reporting.

### 6. Report unsuccessful resolution

Two conditions reach the reporting path:

- A table-path input other than zero has a zero availability marker.
- F-932a35189ea0 returns zero.

The function invokes F-4fc89ec41a6d with five ordered arguments:

| Argument position | Value |
|---|---:|
| 1 | 8 |
| 2 | 104 |
| 3 | 101 |
| 4 | 0 |
| 5 | 0 |

The dependency’s return value is not used. If it returns normally, F-85ea43423066 returns zero.

The constants are established; their meaning is not. They must not be presented as a particular error category, message identifier, severity, or exception type without additional evidence.

## Side effects

### Reads and their order

The branch-specific data accesses are:

- **Input zero:** read the table record’s value; do not read its marker.
- **Other table inputs:** read the marker before reading the value; do not read the value when the marker is zero.
- **External inputs:** inspect context availability before invoking the lookup; after a nonzero lookup result, read its offset-4 pointer before reading the final word.

The table root is referenced separately for the marker and value accesses. Likewise, the external-context root and field are referenced in both availability checking and lookup argument evaluation.
