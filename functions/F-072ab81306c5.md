# F-072ab81306c5

## Purpose

F-072ab81306c5 conditionally derives a 32-bit value from an object and dispatches that value to one of two output paths selected by a second argument.

The established behavior has three possible outcomes:

- Invoke F-bb06326f64c7 and return a 32-bit value read from the object.
- Invoke F-dee541b2a059 and return the address of an embedded object region.
- Return zero without invoking either output dependency.

The derived value defaults to zero. A nonzero byte in the object enables a calculation involving an indirect call, F-d7be9cfb4000, F-5fd50c3b0d96, and a 32-bit object field.

The apparent intent is to produce alternate representations of a calculated quantity. The quantity’s units, the meanings of the selectors, and the representation formats are not established. In particular, the constants 1000 and 60 do not by themselves establish time-related semantics.

## Interface

### Inputs

The function accepts two 32-bit inputs:

1. **Object address.** Used as the base address for byte, word, pointer, and embedded-region accesses.
2. **Selector.** Compared with two 32-bit global values to choose the output path.

The address-bearing input and return value are represented as 32-bit integers in the supplied evidence. The contract therefore describes a 32-bit address model; it does not establish a portable interface for wider addresses.

## Behavior

### 1. Establish the default value

The function begins with a local 32-bit working value of zero.

It then reads the byte at object offset `0x8a` once. Any nonzero byte enables the calculation. The behavior does not depend on whether that byte would be interpreted as positive or negative.

If the byte is zero, the entire calculation described below is skipped. The working value remains zero, and execution proceeds to selector dispatch.

### 2. Perform the enabled calculation

When the enable byte is nonzero, the following dependency order is established:

1. Resolve the indirect target through object offset `0x20` and the dispatch-table entry at offset `0xc0`.
2. Invoke that target and obtain a 32-bit result.
3. Pass that result and the integer 1000 to F-d7be9cfb4000.
4. Pass the object address and the 32-bit result of F-d7be9cfb4000 to F-5fd50c3b0d96.
5. Obtain a 64-bit result from F-5fd50c3b0d96.
6. Read the 32-bit factor at object offset `0xd0` and calculate the working value.

No explicit arguments are shown for the indirect call. The evidence does not establish an implicit receiver, register arguments, or other calling-context requirements.

For the calculation, let:

- \(H\) be the upper 32 bits of the 64-bit result.
- \(L\) be the lower 32 bits.
- \(M\) be the 32-bit value read at object offset `0xd0`.

The visible arithmetic is:

\[
H + M \times L \times 60
\]

The upper half is extracted by an unsigned 64-bit shift by 32 bits and then converted to a 32-bit integer. The lower half is converted directly to a 32-bit integer. The multiplication and final addition are expressed at 32-bit integer width, not as a 64-bit accumulation.

No overflow check, saturation, clamp, or error branch is visible. Exact behavior for overflowing signed arithmetic and for conversions outside the signed 32-bit range is not established by the supplied representation alone. A portable contract must not silently promise modulo-\(2^{32}\) behavior for those cases.

The factor at offset `0xd0` is read after F-5fd50c3b0d96 returns. Its value must not be assumed to equal its value at function entry: earlier dependencies may modify the object.

### 3. Compare the first selector value

After the optional calculation, the function compares the selector with a first global 32-bit selector value.

If they match:

1. Invoke F-bb06326f64c7 with the object address, the working value, and the address of object offset `0x78`, in that argument order.
2. After the call returns, read the 32-bit word at object offset `0x7c`.
3. Return that word.

The returned word is a post-call memory read. It is not the direct return value of F-bb06326f64c7. The function does not independently establish that this dependency writes the word at `0x7c`.

The second selector global is not consulted on this path.

### 4. Compare the second selector value

Only if the selector does not match the first global does the function compare it with a second global 32-bit selector value.

If they match:

1. Invoke F-dee541b2a059 with the working value and the address of object offset `0x80`, in that argument order.
2. After the call returns, return the address of object offset `0x80`.

The direct return value of F-dee541b2a059 is not used.

### 5. Handle an unmatched selector

If neither comparison matches, the function returns zero without calling either output dependency.

An unmatched selector does **not** bypass the enabled calculation. If the enable byte was nonzero, all three calculation-stage calls occur before the selector is rejected.

### Dispatch precedence and mutable state

The first selector comparison has priority. If both selector globals contain the same value and the input selector matches it, only the first output path executes.

Both selector comparisons occur after the calculation-stage calls. Their values must not be treated as immutable entry-time snapshots. The supplied evidence does not establish that any dependency preserves those globals.

No local loop or retry is visible.
