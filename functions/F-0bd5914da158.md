### Selector progression

Under 32-bit wrapping arithmetic with arithmetic right shift:

| Current selector position | Derived selector |
|---:|---:|
| 1 | 0 |
| 128 | 127 |
| 129 | −128 |
| 256 | −1 |
| 257 | 0 |

The interpreted selector repeats every 256 positions. It is not clamped, and its signed value crosses from 127 to −128.

Position advancement belongs to the iteration, not to successful dispatch. If one iteration returns zero between two nonzero results, the two observed dispatch selectors have a positional gap.

These numerical rules do not establish unrestricted defined signed-language evaluation. For example, position 129 requires multiplying 128 by 16,777,216, whose mathematical result exceeds the maximum signed 32-bit value. Its selector of −128 depends on the stated wrapping-machine interpretation.

Conversely, position 0 produces a subtraction result of −1 and a representable negative product. This illustrates why replacing multiplication with a signed left shift would be an unsound semantic shortcut. The subsequent right shift still needs a specified interpretation.
