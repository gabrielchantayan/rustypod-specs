# F-41fa2f49092f

## Purpose

F-41fa2f49092f selects one of two construction dependencies, supplies temporary argument storage derived in part from a caller-provided configuration record, and conditionally modifies the resulting object before returning its address.

Established behavior includes a context-producing call, a preparation call, flag-controlled construction, a nullable lookup, four conditional object-byte writes, a mode mapping, and an optional final operation. The extended construction path also calls an unidentified external dependency with two temporary-storage addresses and the numerical argument 104. **Copying semantics are not established for that call.**

A construction-and-decoration purpose is **inferred intent**. No particular object, resource, or application domain is established.

This contract describes supplied static evidence. No runtime tests have been performed.

## Acceptance examples

These are conditional static examples, not executed tests. Where an observation depends on unchanged memory, assume no intervening dependency or alias modifies that memory.

1. **Base path.** With `0x04` clear at the first flags read, the request helper receives 544 and F-7f6becd152e6 receives the base-storage address. F-external-01 is not called.

2. **External-call contract.** With `0x04` set, F-external-01 receives extended storage first, base storage second, and 104 third. No equality between the two leading 104-byte regions follows from this call alone.

3. **Extended default.** If configuration offset `0x88` reads as zero after F-external-01 returns, the function stores zero at extended offset `0x6C` and later replaces it with 1250. The separate zero write at extended offset `0x78` occurs between those events.

4. **External mutation affects preparation.** If F-external-01 changes configuration offset `0x88` to 9 before returning, and nothing changes it before the read, the explicit parameter store uses 9. It is not replaced with 1250.

5. **Nonzero parameter.** A read value of `0xFFFFFFFF` remains that exact pattern in the parameter’s explicit preparation writes.

6. **Fresh lookup input.** If construction changes the lookup global, the lookup receives the value observed by the later read, not a required entry-time value.

7. **Lookup packing.** With lookup word `0xA1123456` and mode 4, the temporary word is written as `0xFF563412` before object bytes `0x12`, `0x34`, `0x56`, `0xFF`. Mode processing adds no write.

8. **Mode overwrite.** With that lookup word and mode 2, lookup writes occur first. The temporary word is then overwritten with 2 before object offset `0xE9` receives byte 2.

9. **Lookup miss.** A zero lookup result skips lookup-derived writes. Mode 3 still writes temporary word 1 followed by byte 1 at object offset `0xE9`.

10. **Retained alias.** If an extended-path dependency retains a valid alias and a later observer reads the final temporary word after mode 1 processing, without intervening mutation, it observes numerical zero. This does not establish that such an observer exists.

11. **Changed flags.** An initial flags value of zero selects base construction; a later value of `0x80` triggers the optional final operation.

12. **Construction failure.** A zero candidate invokes F-a817d8d58c10 without reaching lookup or post-construction writes. A normal zero return is not established.
