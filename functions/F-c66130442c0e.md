## Behavior

### Dependency invocation and publication

After that invocation returns, the function writes its result into the caller’s output cell as a 32-bit value. The dependency therefore runs before this function publishes any result.

The function next reads the global source-base value and retains that value for the initialization rounds. A later change to the global does not, by itself, redirect the retained source base. Changes to memory reached through that base can still affect later source reads.

This ordering has two important consequences:

- If F-fab3799b3190 changes the global source-base value, the subsequent read observes the value then present, not a value captured before the call.
- If the output cell overlaps the global source-base storage, publishing the result can change the source base that the function subsequently captures.

No preservation of global state by the dependency is established.

### Six initialization rounds

The function performs six rounds, indexed from 0 through 5. There is no data-dependent early exit in the visible body.

Each round transfers one 4-byte value from the retained source base at a stride of 4 bytes to a destination position at a stride of 8 bytes. It then writes a single zero byte four bytes after that round’s destination-record start.

The source-read offsets are therefore 0, 4, 8, 12, 16, and 20. The corresponding 4-byte destination-write offsets are 0, 8, 16, 24, 32, and 40. The one-byte zero-write offsets are 4, 12, 20, 28, 36, and 44.

The following ordering is established:

1. Publication of the dependency result precedes capture of the global source base.
2. Each round’s 4-byte source read supplies that round’s 4-byte destination write.
3. Each round’s 4-byte destination write precedes its one-byte zero write.
4. Both writes in a round precede the next round’s source transfer.

The representation does not independently establish the machine-level ordering between the source read and the output-cell read used to calculate the same 4-byte destination write. It does establish that both are needed before that write.

### Destination-base rereads

The function does not retain the dependency result as an immutable destination base for all initialization.

Instead, it reads the output cell when calculating the 4-byte destination write and reads it again when calculating the following one-byte write. Across six rounds, the visible body therefore includes twelve destination-base reads from the output cell.

This distinction is observable when storage aliases:

- A 4-byte destination write that changes the output cell can redirect the immediately following one-byte write.
- A one-byte write that changes part of the output cell can redirect a later round.
- The source base remains the captured value even if these writes subsequently change the global storage from which it was captured.

Consequently, the six-record layout is conditional on a stable destination base. It is not an unconditional guarantee for arbitrary overlapping addresses.
