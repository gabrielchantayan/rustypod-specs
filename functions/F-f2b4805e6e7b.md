# F-f2b4805e6e7b

## Purpose

F-f2b4805e6e7b selects direct or buffered handling of four-byte records, updates persistent scheduling state, and reports an output address and count through separate destinations. Buffered handling can request transfers, generate records through arithmetic dependencies, and modify previously generated records.

Paired signed 16-bit components and coefficient-controlled transitions suggest two-channel sample processing. This is **inferred intent**, not an established media format or mathematical specification.

The established contract concerns memory accesses, dependency arguments, publication order, and state transitions. Transfer semantics and exact arithmetic results remain unresolved.

## Behavior

### Configuration and path selection

The pending flag is read first. Only a value of exactly one causes the scheduling counter to be read for configuration eligibility. If that counter is zero, updates occur in this order:

1. Install pending mode.
2. Install pending M.
3. Install the low 16 bits of the pending decrement source.
4. Install pending P.
5. Install pending L as 16 bits.
6. Clear Q as 32 bits.
7. Clear the one-byte pending flag.

Other flag values do not trigger installation. The flag write does not clear adjacent bytes.

Mode exactly `0x3F800000` selects direct handling without a query. Otherwise, F-U2 is called through dispatch-table byte offset `0x0C`, with the state address. A zero result selects direct handling; a nonzero result selects buffered handling.

F-U2 may change state. Subsequent accesses observe those changes. In particular, buffered classification rereads mode; it does not repeat the earlier direct-mode shortcut.

### Direct handling

The routine stores input into the primary cursor, then computes the end address using the subsequently read N and four-byte stride. It reads the preceding record’s first component and stores it at `0x4C`, then reads its second component and stores it at `0x4E`. Finally, it reads M and writes that value through the output-count argument.

The output-address argument is not used as a store destination on this path. This does **not** guarantee preservation of its storage: a state-field, saved-component, or output-count write may overlap it.

N=0 still causes reads at input−4 and input−2. No empty-input shortcut exists. The end address is captured before the saved-component writes, but M is read afterward.

### Buffered entry: global reads and snapshots

Buffered entry has this source-visible order:

1. Store A into the primary cursor.
2. Read a 32-bit threshold global, capturing **T**.
3. Read the unsigned 16-bit scheduling counter and increment it.
4. Store the increment’s low 16 bits into the counter.
5. Read a second 32-bit global and capture its low 16 bits as **C**.
6. Read mode and compare it as signed 32 bits against captured T.

Both globals are read even on buffered paths that perform no arithmetic. They are mutable global inputs, not established constants. Later threshold arguments and coefficient initializations consume the captured values; dependency changes to those globals do not replace the snapshots during this invocation.

The incremented counter is retained for signed comparison with signed L. Its stored bits wrap modulo 65,536: `0x7FFF` advances to a value compared as −32,768; `0xFFFF` advances to zero.

Mode classification is:

- **Lower range:** mode < T.
- **Upper range:** mode ≥ T and mode > `0x3F7FFFFF`.
- **Middle range:** mode ≥ T and mode ≤ `0x3F7FFFFF`.

These are integer comparisons, not established floating-point comparisons. Middle-range reachability depends on captured T.

### Arithmetic-pass access contract

Each generated or updated record involves two dependency calls, first component before second. Every returned result is truncated to 16 bits.

The following boundaries are observable:

- Arguments for the first call are read before that call.
- Its result-store address is obtained from the applicable state-held write cursor **after** the helper returns.
- The first result is stored before second-component arguments are obtained.
- State-held source and destination cursors are reread for the second call; first-call addresses are not reused as record-wide snapshots.
- The second result-store address is likewise obtained after its helper returns.
- After both stores, the applicable write cursor advances four bytes, followed by the primary cursor where that pass consumes primary records.
- Only then are the current signed working coefficient and signed decrement read for the truncated coefficient update.

Consequently, helper changes to cursors, coefficient, decrement, or record memory can affect the same record’s remaining operations. The first result store can also affect later reads through aliasing.

For **F-404297869b7c**, the complementary coefficient is calculated once per record as 32,768 minus the signed working coefficient. Both component calls reuse that complement. Nevertheless, the signed working coefficient is reread for the second call. Each call receives working coefficient, signed component from the separate source stream, cached complement, and signed primary-cursor component.

The separate source-stream address is held locally and advances one record per completed pair; helper changes to state cursors do not retarget it. Its second component is read after the first result store, so the source contents are not snapshotted.

For **F-9afddf23571d**, each component call separately reads the signed working coefficient and its signed source component. Primary-backed calls reread the primary cursor. Retained-backed calls reread the retained-data address and use a locally maintained record index.

For **F-c0b2b2741cab**, the complement is calculated once per record and reused for both calls. Each call receives that complement, a signed primary component, and the signed existing destination component. Destination contents are read before the call, but the returned result is stored using the destination cursor reread afterward.

These rules establish partial ordering across calls and stores, not an unsupported left-to-right evaluation order among arguments to one call.

### Lower-range scheduling

**Counter below L:** write M through the count destination. No explicit output-address store occurs.

**Counter equal to L:** request transfer from input to A, sized N×S. After the call, publish input and then the current N.

**Counter above L:**

- Clear the reported count, set the first write cursor to B, and publish B, in that order.
- Capture a separate source address at A plus N records and request transfer there from input, sized N×S.
- Reset the primary cursor to A and install captured C into the coefficient.
- Generate N records through F-404297869b7c, using the separate source and primary cursor. Add the current N to the reported count.
- Copy the first write cursor into the second write cursor, reinstall captured C, and move the primary cursor backward by the current M records.
- Establish a fresh separate source at A plus the current N records. Generate another N records through F-404297869b7c and add the current N to the count.
- If M is positive, request an M×S transfer from the current primary cursor to the second write cursor; after return, add the then-current M.
- Clear the scheduling counter.

Both arithmetic loop limits reread N. Q is not explicitly cleared. With stable valid state and nonnegative counts, the reported count is 2N+M for positive M, otherwise 2N.

### Upper range before the limit

Publish input, then M. Request an N×S transfer from input to the current primary cursor.

If Q is positive, select min(Q,M), request that count times S from retained storage to input, and advance the local input destination by four times the selected count. That selected count is retained across the call; positivity of Q does not guarantee positivity of the selection when M is invalid.

Next, reread M and Q:

- **Q < M:** retain the difference M−Q locally. If positive, request that many records’ size from the primary cursor to the local input destination. Advance the current primary cursor by the retained difference. Calculate N−M+Q; if positive, request that size from the advanced cursor to retained storage. Store the calculated retained count after the call.
- **Q ≥ M:** retain Q−M locally. If positive, request that size from B plus M records to retained storage. If the subsequently read N is positive, call F-U1 with destination B plus the retained difference and source equal to the current primary cursor. **Only two arguments are visible for this invocation.** Finally, reread N, M, and Q and store N−M+Q.

The two-argument call establishes neither a transfer length nor an ordinary N×S copy.

### Upper range at the limit

Request an N×S transfer from input to A. Publish input, then P.

The routine rereads P and examines Q. If P is less than one, it returns without another transfer. Otherwise, it requests a P×S transfer into input, sourcing retained storage when Q is positive and the current primary cursor otherwise.

Neither Q nor the scheduling counter is explicitly cleared.

### Upper range after the limit

Publish B, set the first write cursor to B, and clear the reported count, in that order. Request an N×S transfer from input to A plus N records. Then install captured C.

The initial production uses F-9afddf23571d:

Set the second write cursor to the first and generate another M primary-backed records, continuing the coefficient progression. Add the then-current M.
- **Q positive:** capture a boundary min(Q,M). Generate retained-backed records from initial index P up to that boundary, then add boundary minus the current P. If the boundary is below the current M, generate primary-backed records up to M and add current M minus the captured boundary. Establish the second write cursor. Generate retained-backed records from an initial index read from M while the index is below the reread Q, then add current Q−M even if this loop was skipped. Capture M for the remaining primary-backed fill; generate until the logical index reaches twice that captured M, adding one to the reported count per record.

The initial retained boundary is captured across calls. Most other M and Q loop limits are reread; the final primary-backed fill specifically retains its M snapshot.

Next, reinstall captured C and combine primary records into existing output using F-c0b2b2741cab:

### Middle-range scheduling

**Counter below L:** publish input, then N.

**Counter equal to L:** request an N×S transfer from input to A. Write P to the count destination, set the first write cursor to B, and publish B. Then request a P×S transfer from input to the current first write cursor. There is no positive-P guard.

**Counter above L:**

- Clear the reported count, set the first write cursor to B plus P records, and publish B plus P records.
- Request an N×S transfer from input to A plus N records.
- Read P as the initial logical index, install captured C, and capture a separate source address at the current primary cursor plus P records.
- Capture N once for the arithmetic limit. Generate through F-404297869b7c until the logical index reaches twice that captured N.
- Add twice the captured N minus the then-current P to the reported count.
- Set the second write cursor to the current first write cursor. Request a P×S transfer from the current primary cursor to that destination.
- After return, add the then-current P and clear the scheduling counter.

Unlike lower-range arithmetic loops, this loop retains its captured N across helper calls. Under stable representable arithmetic, the count becomes 2N even if inconsistent bounds caused the arithmetic loop to skip. The published base is B plus P records, not B.

## Acceptance examples

These are conditional static examples, not executed tests. Numeric outcomes assume valid representable arithmetic, stated nonaliasing, and dependencies preserving relevant state unless specified otherwise.

1. **Direct handling with disjoint output storage.**  
   With mode `0x3F800000`, N=3, and M=2, the primary cursor receives input; components at input+8 and input+10 are saved; the count becomes two. No query or buffered-entry global reads occur. Output-address storage remains unchanged only if it does not overlap any written storage.

2. **Aliased output destinations.**  
   On the same direct path, let both output destinations designate the same writable 32-bit word, disjoint from state and records. The final count write changes that word to two although no store uses the output-address argument as its destination.

3. **Pending configuration precedes dispatch.**  
   Flag one and counter zero install pending fields before selection. A pending direct-mode word bypasses F-U2, provided intervening overlapping writes do not alter that word.

4. **Buffered snapshots survive global changes.**  
   On a lower-range above-limit path, suppose captured C is `0x1234`. If the staging dependency changes the initializer global to `0x5678` without changing relevant state, both arithmetic-pass initializations still install `0x1234`. Captured T likewise remains the threshold argument already obtained at buffered entry.

5. **Mixed cached and reread arithmetic inputs.**  
   Suppose a four-argument record starts with coefficient 100, producing complement 32,668. If the first helper changes the coefficient to −2 and retargets primary and destination cursors, the first result is stored through the changed destination cursor. Subject to that store not changing those fields, the second call uses coefficient −2, complement 32,668, and the changed primary cursor’s second component. Its result-store cursor is read after its own return.

6. **Lower-range production.**  
   With N=4, M=2, and incremented counter above L, two four-record arithmetic passes precede a two-record transfer request. The published base is B, the reported count is ten, and the counter ends at zero.

7. **Middle-range offset output.**  
   If the middle range is reachable, N=4 and P=2 produce six arithmetic records followed by a two-record transfer request. The published base is B+8 and the reported count is eight.

8. **Counter and empty-input boundaries.**  
   Counter `0x7FFF` increments to signed −32,768; `0xFFFF` increments to zero. Configuration eligibility was checked before increment. Separately, direct N=0 still requires readable storage at input−4 and input−2.
