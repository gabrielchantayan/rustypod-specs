# F-c91d89dd342a

## Purpose

F-c91d89dd342a conditionally inspects a 32-bit table entry selected by an argument whose declared representation is pointer-shaped but whose observed use is numeric.

The established behavior is:

- Obtain a context through F-ecd921e533b1.
- Interpret the argument as a signed integer for admission checks.
- For a nonnegative argument, read a signed limit from the context.
- Inspect a table entry only when the argument is strictly below that limit.
- Return normally when the inspected entry is zero.
- When the entry is nonzero, invoke F-ee5919ca4be6 and, if that invocation returns, invoke F-feee9156a257.

The supplied static representation marks F-feee9156a257 as non-returning. Its actual termination mechanism is not established.

A plausible intent is to validate or reject an indexed slot whose contents are nonzero. That interpretation is not necessary to the contract: the meaning of the table, its entries, and the exceptional path remains unknown.

## Interface

### Argument

The function accepts one pointer-shaped argument. It does not directly dereference that argument as an address. Instead, it converts the argument to a signed integer and uses the result in comparisons and table-offset arithmetic.

The observed model uses:

- A signed integer interpretation for the argument.
- Four-byte spacing between table entries.
- A four-byte integer read for the selected entry.
- Pointer-shaped fields and address values represented through integer and pointer conversions.

This is consistent with a 32-bit address and integer model. The original ABI and language-level guarantees for those conversions are not independently established. The contract therefore describes the supplied 32-bit interpretation without claiming portability to wider-pointer environments.

Let **index** mean the argument’s signed 32-bit interpretation.

### Result

There is no explicit return value.

Possible outcomes are:

1. Normal return without reading a table entry.
2. Normal return after reading a zero table entry.
3. Transfer through F-ee5919ca4be6 and then, if it returns, F-feee9156a257.
4. Failure or non-return arising inside a dependency or from an invalid memory access.

No status code or explicit recoverable error result is provided.

### Context layout

F-ecd921e533b1 supplies an integer-valued context address. The function uses these byte offsets relative to that address:

| Offset | Observed role |
|---|---|
| 96, hexadecimal 0x60 | Field containing the table base address |

The limit field is read through a pointer-shaped type but compared by its signed integer representation. Its semantic role is numeric in this function, regardless of its declared representation.

The table consists of entries addressed at four-byte intervals. A selected entry is read as a signed integer, but only zero versus nonzero affects control flow.

### Preconditions

For defined, normally returning execution along an admitted-index path:

A negative argument avoids the limit-field and table reads performed directly by this function, but it does not avoid the initial dependency call.

The function performs no explicit null-context check, table-base check, allocation-size check, or arithmetic-overflow check.

## Behavior

### Initial dependency call

F-ecd921e533b1 is invoked before any argument-based early return.

Consequently, neither a negative argument nor a null-valued argument makes the function a dependency-free no-op. Any effects, failures, or non-returning behavior of F-ecd921e533b1 precede the remaining behavior.

The returned context address is retained for subsequent accesses. The supplied body does not call the provider again or independently reload the context from another location.

### Negative arguments

If the argument’s signed interpretation is negative, the function returns without directly reading either context field or a table entry.

A context-relative address is formed in the supplied representation, but that formation is not itself a read of the table-base field. This distinction matters when identifying memory-access requirements.

In particular, a bit pattern with its high bit set is treated as negative under the observed signed 32-bit interpretation. It is not treated as a large unsigned index.

### Nonnegative arguments and the limit read

For every nonnegative argument, the function reads the field at context offset 100.

This includes an argument with numeric value zero. Although the supplied representation initially compares the argument with null, that preliminary result does not independently reject zero: the nonnegative path replaces it with a comparison against the loaded limit.

After loading the limit, the function proceeds to a table access only when:

- The index is nonnegative.
- The index is less than or equal to the signed limit.
- The index is not equal to the limit.

Together, these conditions admit exactly the signed range:

**0 ≤ index < limit**

The limit is therefore exclusive.

A zero or negative signed limit admits no index. An argument equal to the limit is rejected without reading the table-base field or a table entry. An argument greater than the limit is likewise rejected.

These rejected cases return normally if the preceding dependency call and required limit read have completed normally.

### Table access

For an admitted index, the function next reads the table-base field at context offset 96.

It then reads the four-byte entry at the table base plus four times the index. The argument is therefore an entry selector, not a byte offset.

The observable access order established by the supplied body is:

1. Call F-ecd921e533b1.
2. Read the limit field, for a nonnegative argument.
3. Read the table-base field, only for an admitted index.
4. Read the selected table entry.

No dependency call appears between the limit read and the table-entry read.

The limit alone does not prove that the table has sufficient backing storage. For example, a large positive limit can admit an index whose scaled offset cannot be represented safely or whose selected address is not mapped. The function contains no separate protection against those conditions.

### Zero and nonzero entries

If the selected entry is zero, the function returns normally.

If the selected entry is nonzero:

1. F-ee5919ca4be6 is invoked.
2. If that call returns normally, F-feee9156a257 is invoked.

The entry is not reread between these calls. The supplied body performs no table or context reads after F-ee5919ca4be6 returns.

F-feee9156a257 is statically annotated as non-returning. The evidence does not identify whether it terminates a process, raises an exception, performs a nonlocal transfer, blocks indefinitely, or uses another mechanism. A normal return from that dependency is outside the behavior supported by the annotation.

If F-ee5919ca4be6 itself fails or does not return, the second call is not reached.

## Acceptance examples

These are conditional static acceptance cases, not results of executed tests. Unless stated otherwise, assume the provider returns normally and all required memory accesses and arithmetic are valid.
