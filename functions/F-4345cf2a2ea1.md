# F-4345cf2a2ea1

## Purpose

The supplied static representation describes a routine that performs an ordered sequence of indirect calls, computed-address word stores, and byte reads and writes, followed by an unconditional loop.

No application-level purpose is established. The operations do not establish that the routine initializes an object, serializes data, allocates memory, or controls a device.

This contract describes the visible behavior conditionally: each later operation is reached only if earlier arithmetic, calls, and memory accesses permit execution to continue. The supplied representation reports invalid instruction data and removal of unreachable regions. Its correspondence to executable behavior has not been independently established.

### Widths and arithmetic

Words are 32 bits; bytes are 8 bits. Explicit source-byte reads are unsigned. Byte payload descriptions below identify the eight bits written by the represented operation.

Arithmetic distinctions are material:

- Unsigned shifts are logical; unsigned arithmetic is modulo \(2^{32}\).
- Signed products remain signed operations even when their result is subsequently assigned to an unsigned word.
- A signed left shift by two is not interchangeable with signed multiplication by four. In particular, a negative operand can have a representable fourfold product while its signed left shift is not defined under portable source-language rules.
- Signed overflow, negative signed left shifts, and signed left shifts whose result is not representable do not establish portable results.
- Assigning an unsigned result above the signed maximum to a signed temporary does not establish a portable signed value without an implementation-specific conversion rule.

These issues affect addresses as well as payloads. This contract does not silently replace signed operations with wrapping machine arithmetic. Address conversion, alignment, byte order, signed byte conversion, and fault behavior remain **documented_only** where the representation does not resolve them.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Initial stores.** With A equal to 8 and valid destinations, the first word store writes 8 at address 52. After F-D001 completes, the next writes 8 at address 28.

2. **Signed-shift boundary.** If F-D001’s signed result is −1, multiplication by four would yield representable −4. Nevertheless, F-D002.1’s displayed argument uses a signed left shift by two. Under portable signed-shift rules, this case has no established result; accepting −4 requires an additional execution-model assumption.

3. **Third-input reduction.** With C equal to `0xffffffff`, F-D015.1’s fourth explicit argument is `0x0003ffff`, provided execution reaches that call. The total reduction is fourteen bits, not seven.

4. **Unsigned entry-register extraction.** With R equal to `0x12345678`, its logical right shifts by eight, fifteen, sixteen, and twenty-three yield `0x00123456`, `0x00002468`, `0x00001234`, and `0x24`. The direct byte-store address is therefore 64.

5. **Fresh selector reads.** A source-byte value of 255 selects destination 272. A later read yielding zero selects destination 17, even when both reads use P. Neither equality nor inequality of successive selector values is guaranteed.

6. **Two payloads from U.** If U is `0x12345678`, the first selector-directed byte store writes `0xe0`; the later extraction store writes `0x23`. This assumes the intervening calls complete. Their destinations may differ.

7. **Prefix accounting.** If the finite prefix completes, its explicit data-access trace contains sixteen word writes and six byte writes, with five unsigned byte reads. Completing one loop iteration adds one byte read and one byte write, not another word store.

8. **Initial loop argument.** Every possible F-D040 unsigned result produces H between 0 and 31. Consequently, the first F-D043.1 receives zero as its second explicit argument.

9. **Failure and nontermination.** An invalid first destination has no displayed routine-level recovery path. Conversely, if all operations remain defined, all accesses succeed, and all dependencies return indefinitely, no ordinary completion occurs.
