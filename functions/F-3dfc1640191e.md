# F-3dfc1640191e

## Purpose

F-3dfc1640191e conditionally replaces a caller-supplied 32-bit selector using an object’s stored state and two flag bytes. For certain selectors it also updates an optional byte. One selector reaches an unresolved indirect transfer after that byte update.

The established behavior is a numeric transformation, not a confirmed application-level interpretation. Terms such as “selector,” “stored state,” and “optional byte” describe their roles here; they do not establish an enumeration, ownership model, or domain meaning.

Most paths complete without invoking another function. The path involving the unresolved indirect transfer has only a partially recoverable contract: the preceding reads and writes are established, but the target, its effects, and whether control returns are unknown.

## Interface

### Inputs

The function has three inputs:

| Input | Role |
|---|---|
| Object address | Base address used for the object-relative accesses described below. Not accessed on every path. |
| Selector address | Address of a readable 32-bit integer. Selected paths also require it to be writable. |
| Optional-byte address | Either null or an address used for a single-byte output or input/output, depending on the selector. |

The supplied representation declares no return value. Observable results are memory changes and, on one path, an indirect transfer.

### Preconditions

The selector address must support the initial 32-bit read on every invocation. Further validity requirements are path-dependent:

- An unrecognized selector requires no object or optional-byte access.
- Selectors 0x34 and 0x37 require only a selector write after the initial read.
- Selector 0x35 requires an object flag-byte read and a selector write.
- Selectors 0x33 and 0x36 require the object accesses specified below.
- A non-null optional-byte address must support only the accesses actually reached. Some paths write it without first reading it; selector 0x36 both reads and writes it.

## Behavior

### Initial dispatch

The first established memory operation is a 32-bit read from the selector address. That initial value chooses the branch. Later changes to selector storage do not cause dispatch to restart.

| Initial selector | Selected behavior |
|---|---|
| 0x33 | Resolve through the stored state or the object’s low flag bit |
| 0x34 | Write 4 to the selector |
| 0x35 | Write 4 or 1 according to flag mask 0x20 |
| 0x36 | Copy the stored state, optionally transform a byte, and possibly transfer indirectly |
| 0x37 | Write 4 to the selector |
| Any other 32-bit value | Return without further established memory accesses |

### Selectors 0x34 and 0x37

The function writes the 32-bit value 4 to the selector address and returns.

It does not access the object or optional-byte address on these paths. This remains true when either address would be invalid if dereferenced.

### Selector 0x35

The function reads the byte at object offset 0x18C.

- If mask 0x20 is set, it writes the 32-bit value 4 to the selector.
- Otherwise, it writes the 32-bit value 1.

It then returns. Other bits in that flag byte do not affect this branch. The stored state and optional byte are not accessed.

### Selector 0x33: mask 0x01 clear

The function first reads the byte at object offset 0x18C. If mask 0x01 is clear:

1. It reads the 32-bit stored state at object offset 0xC8.
2. It writes that value to the selector address.
3. It rereads the 32-bit selector.
4. If the reread value is nonzero, it returns.
5. Otherwise, it writes the 32-bit value 1 to the selector and returns.

With stable, nonoverlapping memory, this copies every nonzero stored state unchanged and substitutes 1 for a stored state of zero. Negative values and values outside the recognized dispatch set are not otherwise normalized.

The optional-byte address is not accessed on this path.

The selector reread is part of the represented behavior. It must not be replaced in the contract by an assumption that the value just written is still present.

### Selector 0x33: mask 0x01 set

After reading the flag byte and finding mask 0x01 set, the function writes the 32-bit value 2 to the selector **before** deciding whether to access the stored state.

It then behaves as follows:

- If the optional-byte address is null, it returns immediately. It does not read the stored state.
- If the optional-byte address is non-null, it reads the 32-bit stored state at object offset 0xC8.
- If that state equals 1 or 2, it returns immediately. It neither reads nor writes the optional byte.
- For every other stored-state value, it writes zero to the optional byte without first reading that byte.

After the byte-zero write, it rereads the 32-bit selector. If that value is nonzero, it returns. If it is zero, it writes the 32-bit value 1 and returns.

For ordinary nonoverlapping storage, the selector therefore finishes as 2 on this entire flag-set path. The later reread nevertheless matters: an optional-byte write may overlap selector storage, or memory may otherwise change between accesses.

### Selector 0x36

The established access order is:

1. Read the 32-bit stored state at object offset 0xC8.
2. Write that state to the selector address.
3. Inspect whether the optional-byte address is null.
4. If null, return.
5. Otherwise, read the current optional byte.
6. Read the byte at object offset 0x18D.
7. Compute and write a one-byte result to the optional-byte address.
8. Perform the unresolved indirect transfer.

Unlike selector 0x33 with mask 0x01 clear, this branch does not replace a copied state of zero with 1.

The optional-byte transformation uses bit 2, mask 0x04, of the flag byte at offset 0x18D:

| Optional byte when read | Flag bit 2 | Byte written |
|---|---:|---:|
| Zero | Clear | 0 |
| Zero | Set | 1 |
| Any nonzero value | Clear | 1 |
| Any nonzero value | Set | 0 |

The output byte is always exactly 0 or 1. Other flag bits do not affect it. All nonzero input-byte values take the same branch; the operation is not restricted to an input already encoded as 0 or 1.

The represented masking, shifting, and complement operations select or invert one bit. They do not introduce a signed comparison or a multi-bit byte result.

The indirect transfer occurs for every reached non-null optional-byte case, even if the newly written byte equals its previous value. The writes preceding that transfer are established; their persistence afterward is not.

### Aliasing and access order

The supplied representation does not establish a non-aliasing requirement. Its read/write order therefore matters when storage overlaps.

In particular:

- On selector 0x33 with mask 0x01 set, writing selector value 2 precedes the stored-state read. Overlap may make that read observe changed storage.
- On selector 0x36, the selector write precedes both the optional-byte read and the read at offset 0x18D. Either read may consequently observe a value affected by that write.
- On selector 0x33, the optional-byte zero write precedes the final selector reread when that portion of the path is reached.
- Direct writes through the selector or optional-byte address may alter object fields if those addresses overlap the object.

These observations do not establish that arbitrary overlaps are valid under an original source-language type system or target alignment rules. They establish why a contract must retain the represented access order rather than describe only nonoverlapping final values.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid, stable, nonoverlapping storage.

| Conditions | Required result |
|---|---|

| Selector 0x35; flag byte 0x20 | Selector becomes 4 |

| Selector 0x36; stored state zero; optional-byte address null | Selector becomes zero; no indirect transfer |

For the final three examples, the selector has also received the stored state before the transfer. No post-transfer value is guaranteed.
