# F-2e3766f819a4

## Purpose

No application-level purpose is established. Repeated offsets, address-like values, and character-like constants do not establish text formatting, object initialization, collection management, or a protocol.

### First direct mutations

The following roles describe captured values, not object types:

| Role | Derivation |
|---|---|
| Primary base | A dependency result multiplied by 2²⁵. |
| Shifted base | Another dependency result shifted left by 25 bits. |
| Small base | Twice a captured value formed by shifting a dependency result left eight bits, masking to 15 bits, then shifting logically right six bits. |
| Retained word | An earlier dependency result shifted left eight bits. |
| Final pair | Low and high 32-bit halves of the last represented paired result before direct stores. |

The opening mutations first store the shifted base as a word at the final pair’s high half plus 0x14, then store that high half’s low byte at shifted base plus 9. A word store publishes the primary base at 256 times the final pair’s low half plus 0x54. The shifted-base byte at offset 9 is then overwritten with the shifted base’s low byte.

The primary-base word at offset 0x14 is cleared before reading its byte at offset 5. The small-base word at offset 0x14 is then cleared, and the captured byte is stored, zero-extended, as a word at primary base plus 0x34.

Next, the primary-base word at offset 0x14 is read back. Another clear of small base plus 0x14 precedes two separate byte writes at small base plus 0x15, both using the readback’s low byte.

The readback remains an actual read. It cannot unconditionally be replaced with zero: intervening accesses may alias it, and access-observable memory may distinguish the operations.

### Linked updates and early global accesses

After those two byte writes, the function reads byte storage at absolute address **0x05**, zero-extends it, and captures it as a base. It immediately writes the small base’s low byte to absolute address **0x01**. Computed byte writes then affect the byte-derived base at offset 0x15 and the primary base at offset 0x11.

The retained word is written through the earlier readback at offset 0x54, followed by a zero byte at primary base plus 0x11. Only then does the function capture the word at the byte-derived base plus 0x54 and overwrite that location with the earlier readback. Call the captured word the **saved base**.

Subsequent updates follow offset-0x74 links, publish words at offset 0x54, write the saved base as its own offset-0x24 value, and repeat byte writes at offset 9. 2. Read the word at published value plus 0x74.

## Acceptance examples

These are conditional static review examples, not executed tests.

1. **Initial forwarding.** For first input 0x12345678 and second input 3, the initial invocation receives 0x12345678, 3, and 192. The later staged input-derived argument is 6144.

2. **Overflow-sensitive input.** For second input 0x04000000, a truncating 32-bit six-bit left shift produces zero. This expectation requires confirmation of that execution model.

3. **Store width.** A byte store of 0x123456ab writes 0xab. A byte read subsequently widened to a word yields 171, provided no intervening write changes that location.

4. **Early globals.** The absolute 0x05 byte read precedes the absolute 0x01 byte write. Later computed accesses use the captured byte-derived base, even if the write aliases its original storage.

5. **Publication capture.** If the publication-base global and the 0x60 word store overlap, publication still uses the value captured before the store. Re-reading the global afterward is not equivalent.

6. **Final opening alias.** If absolute 0x3a overlaps the terminal-base offset-0x14 word, that word is read after the calculated byte write. An implementation that captures it before the write violates the represented order.

7. **Three global byte reads.** If an intervening computed write changes 0x67, the copy to 0x21 and the two later payload offset-9 stores can receive different values. Reusing the first read for all three consumers is unacceptable.

8. **Overwritten constants.** An access observer sees the four payload offset-0x20 word writes in order: 0x20, 0x2f, the intervening byte-read value, and 0x20.

9. **Partial failure.** If a late link destination is invalid, earlier mutations have no visible rollback.

10. **Final transfer.** If execution reaches the ending, the final destination receives 0x72 and the three designated captures. A success result, release operation, or ordinary return must not be inferred.
