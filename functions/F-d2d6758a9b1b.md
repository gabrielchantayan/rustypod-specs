# F-d2d6758a9b1b

## Purpose

F-d2d6758a9b1b performs a configuration-driven, state-dispatched computation over caller-addressed 16-bit values. Depending on the reached states, it transforms selectors, reads record components, constructs difference-like contributions, accumulates scaled squares, and invokes dependencies to derive a result or select subsequent states.

**Established static evidence:** The supplied representation contains a dispatcher, unsigned 16-bit loads, 32-bit arithmetic and bitwise operations, global reads, and calls to three dependencies. It contains one explicit return operation and no explicit stores to caller-addressed memory.

**Inferred intent:** The six-byte record stride and squared-contribution accumulation suggest a distance-like calculation. They do not establish an ordinary distance metric, a fixed component count, or a particular normalization.

Unknown configuration prevents a concrete execution path or numerical result from being specified. It does not invalidate the conditional Boolean routing guarantees established below for states 4 and 7.

### Arithmetic and preconditions

The represented computation uses 32-bit signed and unsigned quantities. Component loads are unsigned 16-bit loads, zero-extended for subsequent arithmetic. An explicit mask of 65,535 retains the low 16 bits.

Unsigned operations have modulo-\(2^{32}\) behavior. Signed expressions must not silently be replaced by unbounded integer arithmetic or assumed to wrap without target evidence. Complements, negative constants, and mixed signed/unsigned expressions require their represented 32-bit interpretation.

Under **32-bit arithmetic signed-right-shift semantics**, shifting a signed value right by 31 produces either zero or negative one. This establishes the routing ranges in states 4 and 7 independently of configuration values. The actual target’s shift semantics and the treatment of signed overflow remain unresolved.

Every reached memory read requires accessible storage for a two-byte load at its computed address. There is no local bounds, alignment, overflow, or pointer-validity check. The supplied base need not be accessed at all if execution exits before a reading state.

Each dispatch iteration first reads a common global operand. It then selects a state from the current dispatch token plus a global bias, using the represented 32-bit arithmetic.

Explicit cases cover states zero through eight. State 2 and all unmatched values execute the same fallback behavior. An unmatched value is neither an implicit error nor an exit.

State numbers identify dispatch cases, not their execution order. In particular, the function does not enforce a visit to state 3 before a component-reading state. Before state 3, the retained base is zero rather than the supplied base.

Descriptions of global operands below identify their roles, not immutable snapshots. Separate reads remain separate unless a retained value is explicitly identified. The representation establishes ordering between statement-level stages, but not a general evaluation order among operands within a single expression.

### State 3: selector initialization

The second selector is multiplied by the selector factor and masked to 16 bits; the first selector is then independently multiplied by that factor and masked. These retained selectors are unsigned low-16-bit quantities, not signed 16-bit values.

This state establishes the next dispatch token by XOR-ing the entry-captured initial token with a global operand. It then calls F-870c4fcf7295 with the retained initial seed plus a global offset and the second argument 2,147,483,647.

After that call, it:

- XOR-updates the routing token using a newly read global operand.
- Reads additional seeds and the transition tokens used by the two difference paths.
- Sets the current result to the original first selector, without masking.
- Retains the supplied record base.
- Reads the seed used for the classification-state routing calls.
- Retains the call’s represented secondary output as the refreshed initial-call seed.

Those post-call global reads must not be moved before the call on an unsupported assumption of global preservation.

### State 6: reset and dependency-driven refresh

The component counter and accumulator are reset to zero before any call in this state. Four calls to F-870c4fcf7295 follow; every call has 2,147,483,647 as its second argument.

The dependency-sensitive boundaries are:

1. The first call uses the retained initial-call seed minus a global offset.
2. After call one, the routing token is XOR-updated using a global read.
3. The second call uses another retained seed plus its global offset.
4. The third call follows call two and uses the classification-routing seed plus a separately read offset.
5. After call three, the default-path transition token is XOR-updated, followed by the state-5 transition token.
6. The fourth call uses the accumulation-routing seed minus its global offset.

Thus, the second call’s offset is read after call one, the third call’s offset is read after call two, and the two transition-token updates occur after call three but before call four.

The represented secondary outputs are subsequently assigned as follows: call one supplies the next dispatch token; call two refreshes the second call’s retained seed; call three refreshes the classification-routing seed; call four refreshes the accumulation-routing seed. Their availability across intervening calls requires ABI evidence not supplied here.

### State 7: component-dependent routing

This state computes an arithmetic/bitwise expression from the component counter and several global operands. It also copies both retained masked selectors into working selection fields. It performs no component load.

The routing choice is obtained by interpreting the expression as signed 32-bit, shifting right by 31, and adding one. With arithmetic signed right shifts, the choice is **exactly zero or one**:

- A negative expression produces choice zero.
- A nonnegative expression produces choice one.

The next dispatch token selects between two forms of the routing token, each XOR-ed with a different global operand. Choice zero selects one form; choice one selects the other. This is a Boolean selection under the stated arithmetic model, not an unrestricted interpolation.

Unknown configuration leaves the sign expression, chosen alternative, and any relationship to a component-count limit unresolved.

### State 4: record derivation, classification, and routing

This state derives two record indices from the working selectors using global multiplication, complements, masks, and signed shifts. It also derives a component offset from the counter. These derived values are not established to equal the supplied selectors or the counter.

For a derived record index \(r\) and component offset \(c\), the load address is:

\[
\text{retained base}+6r+2+2c.
\]

The first record index and component offset are established before the first component read. The second index is derived afterward, before the second component read.

The read order is first derived record, then second derived record. Each unsigned 16-bit load is multiplied by the component factor and masked to 16 bits.

**The current result becomes the transformed component from the second read.** This value remains available for return if state 1 is selected next.

The classification expression combines both transformed components with global operands, complemented masks, and signed shifts. Its final operation negates a signed 32-bit sign extraction. With arithmetic signed right shifts, the extracted sign is zero or negative one, so the classification is **exactly zero or one**, regardless of the configuration values.

Two calls to F-870c4fcf7295 then occur:

- The first uses the retained classification-routing seed minus a global offset.
- Only after that call returns is the second offset read; the second call uses the same retained seed minus that offset.

Both calls use 2,147,483,647 as their second argument. Classification one selects the first call’s represented secondary output as the next dispatch token; classification zero selects the second call’s secondary output.

The classification’s Boolean range is established conditionally on the arithmetic model. Its semantic meaning—such as ordering or magnitude comparison—is not.

### State 5: first difference path

This state rereads the selected component from the first derived record, then the second. It does not reuse state 4’s component values.

Each load is unsigned 16-bit, globally multiplied, and masked to 16 bits. **The transformed component from the second read overwrites the current result.** If state 1 follows, that component-derived value is returned.

The pending contribution combines the two transformed values using global scale factors and masks. Each such mask is formed by complementing a 32-bit product and OR-ing with 65,535. Its low 16 bits are therefore ones; its upper bits need not be zero. This is not merely a 16-bit complement.

The resulting arithmetic is difference-like, but ordinary subtraction or absolute difference is not established. The next dispatch token is the retained state-5 transition token XOR-ed with its global operand.

### State 2 and unmatched values: alternative difference path

The fallback path reads the **second** derived record first, then the **first** derived record. Both components undergo global multiplication and low-16-bit masking.

The pending contribution uses a different scale arrangement from state 5, including a global value shifted right by one. Its complement masks are likewise 32-bit masks with their low 16 bits forced to one.

The current result becomes the transformed component from the second read—here, the component from the **first derived record**.

The next dispatch token is the retained default-path transition token XOR-ed with its global operand. Reversing the reads, caching earlier values, or merging this arithmetic with state 5 requires assumptions not supplied by the representation.

### State 0: accumulation

The accumulator is updated by adding the pending contribution’s square, with an intervening global multiplier, and then applying the same outer pair of scale operands. This establishes a scaled squared-contribution pattern, not an ordinary unscaled sum of squares.

After those updates, it reads a routing offset and calls F-870c4fcf7295 with the retained accumulation-routing seed minus that offset and 2,147,483,647. The represented secondary output becomes the next dispatch token.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Immediate exit:** If entry dispatch selects state 1, the result is zero. The common-global read still occurs; no dependency or component read occurs.

2. **Unmasked return:** If state 3 is followed by state 1, the original first selector is returned. A value of 65,537 remains 65,537.

3. **Selector reduction:** With selector factor one, first selectors 1 and 65,537 produce the same retained selector. Their current results after state 3 differ.

4. **Address layout:** Derived index 4 and component offset 1 place a read 28 bytes beyond the retained base, assuming valid target arithmetic and accessible storage.

5. **Component-result assignments:** If state 4 or state 5 completes with transformed second-record component 50,000 and state 1 follows, the return is 50,000. In the fallback path, the corresponding returned component comes from the first derived record because that record is read second.

6. **Read order and repetition:** State 5 reads first record then second; fallback reverses that order. State 4 followed by state 5 performs both pairs of reads rather than sharing a cached pair.

7. **Boolean routing:** With arithmetic signed shifts, a negative state-4 pre-extraction value yields classification one; a negative state-7 pre-extraction value yields choice zero. No configuration can make either choice two under this arithmetic model.

8. **Call-boundary mutation:** If the first state-4 routing call changes the second offset’s global location, the second call uses the subsequently read offset, not a prefetched value.

9. **Retained state-8 operands:** If F-531bdc62ac41 changes the multiplication-factor location, final scaling and complement construction still use the factor captured before that call. Changes to the later-read arithmetic operands can affect the result.

10. **Reset and fallback:** State 6 discards previous counter and accumulator values before its calls. An unmatched dispatch executes the fallback path rather than returning or rejecting.

11. **Masked state-8 result:** After state 8 assigns the result, it lies between zero and 65,535. State 1 returns that value if no intervening result assignment occurs.
