# F-105a84f198fd

No application-level purpose is established. The evidence does not identify an array, device interface, serialization format, or coherent public API.

### Widths and arithmetic

The following notation describes the apparent 32-bit machine interpretation:

- **S(x):** four times the 32-bit bit pattern of x, retaining only the low 32 bits.
- **W(x):** S(x) plus `0x14`, retaining only the low 32 bits.
- **Q:** R times `0x04000000`, plus one, retaining only the low 32 bits.

Thus Q depends only on the low six bits of R. Its possible numeric values are `0x00000001`, `0x04000001`, and successive increments of `0x04000000` through `0xFC000001`.

This interpretation supplies fixed-width bit-pattern semantics, not portable signed-language arithmetic. The representation includes signed multiplication and signed left shifts; their behavior at overflow boundaries is not independently established.

A byte read yields an unsigned value from 0 through 255. A byte write stores only the low eight bits of its supplied value. The 32-bit stores have no established byte order.

### First byte-selected write

It then writes the low eight bits of S(B) to the numeric address b₁ plus `0x11`. This destination lies between `0x11` and `0x110`, inclusive. The read byte is a numeric address component; it is not a full-width pointer read.

The stored byte is four times B modulo 256. Only B’s low six bits affect this payload, and its bottom two bits are zero.

### Second byte-selected write

The second byte write targets b₂ plus `0x11`, again within `0x11` through `0x110`.

The resulting stored byte is exactly original bits 20 through 27 of B. Original bits 28 and 29 remain after the shift but are discarded by byte-width storage; original bits 30 and 31 are removed before the shift.

### Ordering, repeated observations, and aliasing

The two reads from Q are separate operations. Dependencies between them may change the byte at Q, so b₁ and b₂ need not match.

Under the apparent 32-bit arithmetic, neither byte-write destination can numerically equal Q:

- Q is congruent to 1 modulo `0x04000000`.
- Each byte-write destination is between `0x11` and `0x110`.
- No address in that interval has the required congruence.

Consequently, the first byte write cannot directly change the later selector through equality of the displayed addresses. In particular, Q cannot equal `0x41`.

Whether different numeric addresses can refer to the same underlying storage through an unknown memory mapping is unresolved. Such physical aliasing is a mapping-dependent possibility, not a consequence of these address expressions.

The two word-write destinations can coincide. Their four-byte storage ranges may also overlap other accessed memory. Although each word-write start address is divisible by four and Q is not, that does not exclude Q from the bytes covered by a word write.

The byte-write destinations can coincide with each other or overlap a word-written region. Equal destinations do not eliminate either operation.

D-23 receives the captured b₂, not a later read from Q. Changes to Q after the second read do not replace that argument in the displayed dataflow. The captured dependency results likewise remain the values used at their specified later points.

The described order is the displayed access and call order. No atomicity, synchronization, transaction, or cross-thread visibility guarantee is established.

These are conditional static acceptance examples, not executed tests. They assume the apparent 32-bit arithmetic, successful accesses, valid call targets, and returning dependencies except where a failure is explicitly considered.

   If the first read observes 5 and an intervening dependency changes the byte at Q to 7 before the second read, the byte-write destinations are `0x16` and `0x18`. Reusing b₁ for the second destination would contradict the separate read.

6. **Equal destinations retain both operations.**
