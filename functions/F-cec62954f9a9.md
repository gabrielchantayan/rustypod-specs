# F-cec62954f9a9

## Purpose

F-cec62954f9a9 recognizes an action identifier and either dispatches the corresponding handler or suppresses dispatch when a supplied 32-bit value equals a global comparison value.

Its normal return distinguishes **recognized** from **unrecognized**, not successful execution from failed execution:

- **1:** An action matched. Its handler either returned normally or was deliberately not called because the supplied value equaled the applicable global value.
- **0:** None of the ten action comparisons reported equality.

The supplied static representation establishes the dispatch structure. It does not establish the business meaning of the global value, the handlers’ effects, or the comparison dependency’s string and encoding rules.

Consequently, recognition is defined by the comparison dependency’s results rather than an independently established textual equality operation. If that dependency could report equality for more than one target, the earliest matching target wins.

### Global-value observation and suppression

The timing of the global reads is part of the visible behavior:

1. The first comparison, against `HandleSelect`, occurs before the initial read of the global value.
2. Immediately after that comparison returns, the function reads and captures the global value.
3. If the first comparison matched, the supplied representation shows another read of the global for the suppression equality check.
4. If the first comparison did not match, every later recognized action uses the value captured after the first comparison.

For `HandleSelect`, equality with the value read for its suppression check causes an immediate return of 1.

For any later recognized action, equality with the earlier captured value causes an immediate return of 1.

Suppression performs no explicit receiver-table lookup and calls neither a direct handler nor an indirect handler. Comparisons already required to reach that match have nevertheless occurred.

The captured value is not visibly refreshed after comparisons two through ten. Therefore, if those calls modify the global, a later recognized action still uses the earlier captured value. This is not equivalent to consulting the global immediately before every dispatch.

The first-match path has a separate qualification: the representation shows two global-read expressions after the first comparison, with the second supplying its equality test. Whether these correspond to distinct machine loads, and whether a change between them is observable, requires information beyond the supplied representation.

### Indirect dispatch

For a recognized indirect action whose suppression check is unequal:

1. The function reads the receiver’s first word.
2. It uses that word as a table base address.
3. It reads a callable entry at the action-specific byte offset.
4. It invokes that entry with the original receiver and action value.
5. If the call returns normally, it returns 1.

The offsets are **byte offsets**, not entry numbers. The `HandleImageNext` offset is 300 decimal, equal to 0x12C. The visible entries progress in four-byte increments from 0x124 through 0x140.

These facts establish the accessed locations, not the complete table size, table ownership, or validity of intervening and surrounding entries.

The receiver’s first word and selected entry are read only after the comparisons and suppression decision. No earlier table snapshot is visible. A dependency that changes the receiver or its table before those reads can therefore affect which target is loaded.

### Direct dispatch

An unsuppressed `HandlePlay` match calls F-837e9590b5e6 with the receiver and action value.

An unsuppressed `HandlePause` match calls F-134c58443250 with the same argument arrangement.

Neither path explicitly reads a handler-table entry in F-cec62954f9a9. The dependencies may themselves inspect the receiver or other state; their internals are unavailable.

After either call returns normally, this function returns 1.

### Unrecognized input

If all ten comparisons return nonzero, the function returns 0.

That path still includes the global read after the first comparison. It does not perform a suppression equality check, explicitly read the receiver’s first word, or invoke an action handler.

### Integer behavior

Suppression uses equality between the supplied 32-bit action value and a 32-bit global value. There is no visible ordering comparison, range check, normalization, arithmetic adjustment, or narrowing of the action value.

Negative-looking or high-bit-set values are not independently rejected. Their handling depends on equality and, if dispatched, the selected handler.

The table accesses add fixed byte offsets to the receiver-provided base. No overflow or invalid-address handling is visible. Valid address formation is a precondition for defined indirect dispatch; wraparound recovery is not established.
