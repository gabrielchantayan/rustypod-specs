# F-0d7f0c941178

## Purpose

F-0d7f0c941178 selects a lookup table and a 16-bit index from a caller-supplied record, reads a 32-bit table word, and returns that word’s low 16 bits as an unsigned result.

Selection uses two binary distinctions:

- Whether the record’s first byte is zero.
- Whether the second argument is zero.

Each of the four combinations selects a different record field and a different global table-address value. The second argument is not itself a table index: all nonzero values select the same alternative.

The established behavior is a lookup, not a transformation of the record. No record update, table update, allocation, release, or explicit error reporting appears in the supplied evidence. The meaning of the selected values is unknown.

## Interface

### Inputs

**Record address**

An address used to read:

- One byte at offset 0.
- One unsigned 16-bit field at offset 2, 4, 6, or 8, selected as described below.

Offsets are measured in bytes from the supplied address. The function does not inspect the intervening bytes or all four candidate fields.

A record containing all candidate fields occupies at least ten bytes. For one particular invocation, however, the function only directly requires the flag byte and the selected two-byte field to be readable. Whether the surrounding execution environment additionally requires a complete allocated record is outside the supplied evidence.

The record is borrowed for reading. The function contains no explicit transfer of ownership, retention of its address, or release operation.

**Selector**

An integer argument interpreted solely by comparison with zero. Under the represented 32-bit integer model:

- Zero selects one pair of fields and tables.
- Every nonzero value, including negative values, selects the other pair.

There is no distinction among positive nonzero values, negative values, or particular bit patterns beyond zero versus nonzero.

### Output

An unsigned 32-bit return value whose numerical range is **0 through 65,535**, inclusive.

The returned value is the low 16 bits of a selected 32-bit table word. Its upper 16 bits are zero. This differs from returning the complete table word or sign-extending a 16-bit value.

### Required external state

The function reads one of four global values used as table addresses. This contract labels those global address slots **A**, **B**, **C**, and **D**. These are descriptive labels, not additional function dependencies.

For a defined successful lookup:

- The record flag and selected field must be readable.
- The selected global address slot must be readable.
- The computed table address must support a 32-bit read.
- The relevant accesses must satisfy the platform’s alignment and memory-access requirements.

There are no supplied lengths, nullability annotations, validity tags, or table-size arguments.

## Behavior

### Selection

The following table completely specifies the selection decision:

| Record byte at offset 0 | Selector | Unsigned 16-bit index field | Global address slot |
|---|---|---|---|
| Zero | Zero | Offset 8 | C |
| Zero | Nonzero | Offset 4 | D |
| Nonzero | Zero | Offset 6 | A |
| Nonzero | Nonzero | Offset 2 | B |

The flag comparison is an exact zero test. Every nonzero byte follows the same branch, regardless of its magnitude or whether an implementation interprets that byte as a signed character.

Only one index field and one global address slot are selected. The other candidate fields and address slots are not explicitly read by this function.

### Read order

The supplied representation establishes the following logical read sequence:

1. Read the record byte at offset 0.
2. Read the selected unsigned 16-bit record field.
3. Read the selected global table-address value.
4. Read one 32-bit word at the address derived from that value and the index.
5. Return the low 16 bits of that word.

The second argument is a supplied value, not a memory location dereferenced by the function.

This sequence describes the source-facing operations in the supplied evidence. It is not a guarantee of physical bus transactions, compiler instruction scheduling, atomicity, or synchronization. No volatile access qualifiers, memory barriers, or locking operations are shown.

In particular, the final access is represented as a **32-bit read followed by masking**, not as a 16-bit table read. Consequently, the complete four-byte word must be readable even though only half of its bits contribute to the return value.

### Index and address calculation

The selected record field is read as an unsigned 16-bit quantity and widened without sign extension. Denote its numerical value by \(i\), where:

\[
0 \le i \le 65{,}535.
\]

Let \(B\) denote the value read from the selected global address slot. The table word is read at:

\[
B + 8i - 4.
\]

This defines an eight-byte stride between addresses selected by consecutive indices. The function reads only a four-byte word at each selected address; it does not read the entire eight-byte interval.

Important boundary consequences are:

- Index 0 reads at \(B - 4\).
- Index 1 reads at \(B + 4\).
- Index 2 reads at \(B + 12\).
- Index 65,535 reads at \(B + 524{,}276\).

No index is rejected, including zero and the maximum unsigned 16-bit value. In particular, there is no explicit subtraction from the index followed by a bounds check. The negative displacement for index zero is part of the address expression.

Under the represented 32-bit unsigned arithmetic model, the index product is at most 524,280 and does not itself overflow. Combining the base-address value, product, and negative displacement uses unsigned 32-bit arithmetic, so numerical wraparound can occur at the address-space boundaries.

That arithmetic observation does not establish that a wrapped address is valid or portable. Integer-to-pointer conversion, actual address width, pointer provenance requirements, and the validity of the resulting access depend on the execution environment.

### Result extraction

If the selected 32-bit word is \(w\), the returned value is:

\[
w \mathbin{\&} 65{,}535.
\]

Thus:

- Bits 0–15 determine the result.
- Bits 16–31 do not affect the result.
- A low halfword with its top bit set still produces a nonnegative unsigned result.
- No status bit or separate success indication is returned.
