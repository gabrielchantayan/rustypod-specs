# F-1639552314ba

## Purpose

F-1639552314ba constructs and returns a record using one of two paths selected by the initial 16-bit value at the input address.

- An initial value other than 6 selects a 108-byte allocation, followed by explicit field transfers and a helper invocation.
- An initial value of 6 selects a 164-byte allocation, initialization of an interior region, explicit clearing of selected fields, and one or two further helper invocations.

These sizes, accesses, and call sequences are established by the supplied static evidence. Interpreting the result as an object with a particular application-level type is inferred intent, not an established contract.

The function does not explicitly validate pointers, handle allocation failure, or release storage. Its behavior depends materially on callees whose implementations are not supplied.

## Interface

### Inputs

The visible interface has four arguments:

| Argument | Representation | Established use |
|---|---|---|
| Source address | Pointer to storage accessed in 16-bit, 32-bit, and byte units | Supplies the initial selector and subsequent fields; also passed to helpers or retained in the result |
| Auxiliary value | 32-bit value | Written into the result only on the non-6 path |
| Activation control | 32-bit integer | Tested for nonzero only on the 6 path |
| Transfer context | 32-bit value | Forwarded to F-fa06621395af only on the non-6 path |

The activation control is a zero/nonzero condition, not a requirement that the value equal 1. Negative 32-bit values satisfy the nonzero condition.

The source selector is compared with 6 as a 16-bit value. No other selector values receive distinct treatment in this function.

### Output

The result is an address represented as a pointer to 32-bit storage.

- On the non-6 path, the result is the address returned by F-8157a180d901.
- On the 6 path, the result is the address returned by F-576ea5ba1d23 minus 88 bytes.

The second expression is important: the function does not explicitly return the original allocation address on the 6 path. Equality with that address depends on the initializer returning its supplied interior address.

### Address and storage model

The supplied evidence uses a 32-bit machine model: pointers are stored in 32-bit fields, and field offsets are byte offsets unless stated otherwise.

For the descriptions below:

- **S** is the source address.
- **A** is the allocation result for the selected path.
- **B** is the address returned by F-576ea5ba1d23 on the 6 path.

These labels describe addresses, not additional public arguments.

The non-6 path directly reads source storage through offset 99 inclusive. It therefore requires those individually accessed locations to be readable. F-fa06621395af may impose additional requirements. The 6 path directly reads only the selector, but passes S + 2 to F-151ab4bfe553, whose access requirements are unknown.

Valid allocation results, suitable alignment, writable destinations, and valid helper results are prerequisites for ordinary completion. None is checked locally.

## Behavior

### Selection and temporal rules

The function first reads a 16-bit value at S and chooses its path.

That choice is not revisited after allocation or helper calls. Both paths later read the selector again when writing a destination field. Consequently, the value stored in that field need not equal the value that selected the path if the source changes between reads.

The function does not take an atomic snapshot of the source. Fields are read and written at different times, with helper calls interposed. No supplied evidence establishes that those helpers preserve source memory, global state, or already initialized destination fields.

The sequence below describes the order expressed by the supplied static evidence. It does not establish atomicity, cross-thread synchronization, or hardware-level memory ordering.

### Non-6 path

When the initial selector is not 6, the following operations occur in order:

1. Request 108 bytes from F-8157a180d901.
2. Write a 32-bit value obtained from one global location to A + 0.
3. Store S at A + 88 as a 32-bit pointer value.
4. Store the auxiliary value at A + 92.
5. Read and store three 32-bit source fields, in ascending order:

   | Source offset | Destination offset | Width |
   |---|---:|---:|
   | 88 | 96 | 32 bits |
   | 92 | 100 | 32 bits |
   | 96 | 104 | 32 bits |

6. Read the 16-bit selector at S again and write it at A + 4.
7. Invoke F-fa06621395af with destination A + 6, source S + 2, the numeric argument 64, and the transfer-context argument. The visible call also forwards four ambient machine-state values whose meanings are not established.
8. After that call returns, perform these source-to-destination transfers in the listed order:

   | Source offset | Destination offset | Operation |
   |---|---:|---|
   | 68 | 72 | Read and write 32 bits |
   | 72 | 76 | Read 16 bits; store its low 8 bits |
   | 73 | 77 | Read and write one byte |
   | 76 | 78 | Read 16 bits; store its low 8 bits |
   | 78 | 80 | Read and write 16 bits |
   | 80 | 82 | Read and write 16 bits |
   | 82 | 84 | Read and write 16 bits |
   | 84 | 86 | Read and write 16 bits |

9. Return A.

The two narrowing operations preserve only bits 0–7 of their respective 16-bit source values. They do not saturate or validate their inputs. The byte read at source offset 73 is a separate access after the 16-bit read at offset 72.

F-fa06621395af is supplied with addresses and a numeric value consistent with a 64-byte transfer. Its implementation is unavailable, so exact copying, overlap handling, and termination behavior are not established here. In particular, a complete byte-for-byte result for destination offsets 6–69 cannot be asserted solely from this function.

No explicit writes cover destination offsets 70–71 or 79. Their values are not guaranteed; allocation or helper behavior may affect them.

The activation-control argument is not consulted on this path.

### Selector-6 path

When the initial selector is 6, the following operations occur in order:

1. Request 164 bytes from F-8157a180d901.
2. Write a 32-bit value obtained from a different global location to A + 0.
3. Invoke F-576ea5ba1d23 with A + 88.
4. Use its returned address as B.
5. Explicitly write zero to the following locations, in this order:

   | Offset relative to B | Width |
   |---:|---:|
   | 8 | 32 bits |
   | 16 | 32 bits |
   | 20 | 16 bits |
   | 22 | 16 bits |
   | 24 | 32 bits |
   | 28 | 32 bits |
   | 49 | 8 bits |
   | 52 | 32 bits |
   | 56 | 8 bits |
   | 57 | 8 bits |
   | 60 | 32 bits |
   | 64 | 32 bits |
   | 68 | 32 bits |
   | 72 | 32 bits |

6. Read the 16-bit selector at S again and store it at B − 84.
7. Write one zero byte at B − 82.
8. Invoke F-151ab4bfe553 with B and S + 2.
9. If the activation control is nonzero, invoke F-933d555a9096 with B − 88 and a second argument of zero.
10. Return B − 88.

The explicit zeroing is selective, not a blanket initialization of the allocation or interior region. For example, the listed writes do not explicitly clear B + 0 through B + 7 or B + 32 through B + 48.

The zero values describe writes made before F-151ab4bfe553 and, conditionally, F-933d555a9096. They are not guaranteed final field values because either helper may modify the region.

If F-576ea5ba1d23 returns A + 88, then:

- The returned address is A.
- The selector write lands at A + 4.
- The single-byte zero write lands at A + 6.
- The last explicit 32-bit zero write occupies A + 160 through A + 163.

That relationship fits the requested allocation size, but remains conditional on the unavailable helper contract. If the helper returns a different address, subsequent writes and the returned address follow that different address.

The auxiliary value and transfer context have no explicit use on this path.

## Side effects

### Memory and state

Both paths invoke an allocation-like dependency and write to its result without a visible null check.

On the non-6 path, the function explicitly retains the source address inside the result. It also transfers selected source values and invokes a helper with source and destination addresses.

On the 6 path, the function writes the allocation header, then writes through B rather than deriving all later addresses directly from A. Its final helper call is conditional on the activation control.

Two distinct global locations supply the initial 32-bit header values, one per path. The evidence does not establish their meanings, constancy, or ownership implications. The header load occurs after the allocation call, so it is not a pre-allocation snapshot.

No direct write to source storage is visible. Helpers receive source-derived addresses, however, and their mutation behavior is unknown.

### Ownership and lifetime

Allocation requests and returned addresses suggest construction of caller-usable storage. The ownership and release protocol is **documented_only**: no destructor, release operation, reference-count rule, or allocator guarantee is supplied.

Likewise, retaining S on the non-6 path does not establish whether the result borrows, owns, or later dereferences the source. A consumer must obtain that lifetime contract elsewhere.

The function contains no explicit deallocation. This does not prove that its callees never allocate, release, or transfer ownership.

### Errors and abnormal completion

There is no visible error return, status translation, retry, or rollback.

If an allocation or initializer returns an unusable address, the next memory access may fail. If a helper fails to return, later writes and the normal return do not occur. The exact fault or exception mechanism is outside the supplied evidence.

Partial initialization is possible before abnormal termination; no cleanup path is visible.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Ordinary non-6 selection

Given an initial selector of 5 and successful returning dependencies:

- The requested allocation size is 108 bytes.
- The result is the allocation address.
- S and the auxiliary value are written at offsets 88 and 92.
- The transfer helper is called once with destination offset 6, source offset 2, and numeric argument 64.
- Neither F-576ea5ba1d23, F-151ab4bfe553, nor F-933d555a9096 is called.

If helpers leave the relevant fields unchanged, the explicitly assigned destination fields have the values specified above at return.

### Narrowed source values

On the non-6 path, if the 16-bit source read at offset 72 produces hexadecimal 12AB, the write at destination offset 76 stores hexadecimal AB.

The following destination byte at offset 77 comes from a separate byte read at source offset 73. It must not be inferred from a particular byte order without additional platform evidence.

### Selector-6 without activation

Given an initial selector of 6, zero activation control, and normally returning dependencies:

- The requested allocation size is 164 bytes.
- F-576ea5ba1d23 precedes all B-relative zero writes.
- F-151ab4bfe553 runs after the selector and single-byte zero writes.
- F-933d555a9096 is not called.
- The result is B − 88, whether or not that equals A.

### Selector-6 with activation

Under the same conditions but with any nonzero activation control, F-933d555a9096 runs after F-151ab4bfe553 with arguments B − 88 and zero.

No claim that earlier zeroed fields remain zero is justified unless both helpers preserve them.

### Source changes during construction

If the initial selector is non-6 but becomes 6 before its later read, the function remains on the 108-byte path and writes the later selector value at A + 4.

This illustrates two distinct observations, not a consistent-snapshot guarantee.
