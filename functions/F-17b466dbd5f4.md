# F-17b466dbd5f4

## Purpose

F-17b466dbd5f4 performs an ordered mutation and dispatch on a caller-supplied object:

1. Assign the signed integer value −1 to object integer slot `0x111`.
2. Invoke F-e44e3a7f3959 with the original object pointer.
3. After that dependency returns normally, obtain an object-derived indirect target and read two particular global operands.
4. Invoke the selected target with the original object pointer and those global values in fixed argument positions.

The global operands are not anonymous or interchangeable. This contract names their locations **G-081143b0** and **G-081143ac**, preserving the identities of the two supplied address-labelled data locations. Operand **A** is read from G-081143b0; operand **B** is read from G-081143ac.

The established purpose is this observable sequence, not a domain-specific operation. Initialization, reset, or state transition is plausible inferred intent. The evidence does not establish what the object represents, what −1 means, or what either global value signifies.

The assignment concerns an integer value. Describing its representation as all one bits requires an independently established integer representation. Under a 32-bit two’s-complement interpretation, the stored pattern is `0xffffffff`.

No rollback or compensating assignment is represented. A later failure does not change the ordering fact that this assignment preceded the later operation. Whether its effects remain observable after a particular fault or nonlocal exit is a runtime question.

No result from this dependency is visibly used. The function does not visibly copy the object, substitute another pointer, or repeat the −1 assignment after the dependency returns.

### Post-dependency reads and target selection

The post-call timing applies to both global reads, not merely to the selector read. If F-e44e3a7f3959 changes either global value while leaving its subsequent read valid, the argument uses the value read after that call, rather than a value saved before it.

## Acceptance examples

These are conditional static-review criteria, not executed tests.

### Ordered normal path

Given valid storage and normally returning dependencies, the initial assignment precedes F-e44e3a7f3959. Only after that dependency returns are the selector, target expression, and two global operands evaluated for the indirect invocation.

Dispatching before the direct dependency, or capturing either global operand before it, does not preserve this behavior.

### Direct dependency changes both global values

Suppose G-081143b0 initially contains a valid argument value α and G-081143ac initially contains β. F-e44e3a7f3959 changes them to γ and δ, respectively. Assume valid reads and no intervening modifications.

The indirect target receives γ in its second argument position and δ in its third. Passing α and β would incorrectly use pre-call values.

This criterion does not require the read producing γ to occur before the read producing δ.

### Global identities remain significant

Suppose the two globals contain distinguishable values after the direct dependency returns.

The second argument must come from G-081143b0, and the third from G-081143ac. Swapping them violates the invocation contract. If their values happen to match, that coincidence does not make their source locations interchangeable.

### Direct dependency changes the selector

Suppose F-e44e3a7f3959 replaces the first object integer with another valid selector while preserving subsequent access validity.

The indirect target is selected using the replacement selector. A target selected before the dependency call does not satisfy the represented behavior.

### Direct dependency overwrites the initially modified slot

Suppose F-e44e3a7f3959 changes slot `0x111` from −1 to another value.

The wrapper does not restore −1 after the call. Adding such a restoration would introduce an unsupported state change.

### Direct dependency does not return

If F-e44e3a7f3959 never returns normally, the contract does not require the later selector read, global reads, or indirect invocation to occur. The initial assignment is already ordered before the dependency invocation.

### Conditional four-byte layout

Given four-byte integers, 32-bit two’s-complement representation, and valid storage, the initial assignment writes `0xffffffff` beginning at byte offset `0x444`.

Using byte offset `0x111` would confuse an integer index with a byte displacement.

### Evaluation order remains unspecified

Two executions may evaluate the global operands in different orders, provided both reads belong to the post-direct-call invocation evaluation and each value reaches its required argument position.

An acceptance criterion requiring left-to-right operand evaluation, or requiring the entire target expression to precede both global reads, would exceed the supplied evidence.
