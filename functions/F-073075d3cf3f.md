# F-073075d3cf3f

## Purpose

F-073075d3cf3f delegates an operation involving a caller-supplied context and a 32-bit in/out value to F-c9f1dc723c52. If that dependency reports a nonzero result, this function classifies the resulting value using a 16-bit field in the context and returns either an accepted value or zero.

The established behavior is a value-filtering contract. The meanings of the context field, the delegated operation, and the excluded numeric values are not established. Zero is not an unambiguous failure indicator: an accepted value can also be zero.

## Interface

The supplied representation establishes four input positions and a 32-bit unsigned return value.

| Input | Established role |
|---|---|
| First input | A 32-bit address-like context value. Passed to F-c9f1dc723c52 and, conditionally afterward, used to locate a 16-bit field at byte offset `0x6C`. |
| Second input | An uninterpreted 32-bit value passed to F-c9f1dc723c52. This function does not otherwise inspect it. |
| Third input | An uninterpreted 32-bit value with no visible use in this function. It is not passed to the dependency. |
| Fourth input | A 32-bit unsigned initial candidate. Copied into function-local storage that the dependency can access through an address. |

The output is a 32-bit unsigned value. Depending on the selected branch, it is:

- Zero.
- The candidate as it exists after the dependency returns.
- The low 28 bits of that candidate, with the upper four bits cleared.

The dependency receives three arguments, in this order:

1. The first input.
2. The second input.
3. The address of the local 32-bit candidate.

The dependency’s result is represented as a 32-bit signed integer, but this function uses only the distinction between zero and nonzero. Negative and positive nonzero results therefore have the same control-flow effect.

### Context layout

The only directly accessed context member is a 16-bit field beginning at byte offset `0x6C` from the first input’s address. Its comparison is represented as a signed-short comparison, although signedness does not change equality against the positive values 3 and 8.

No other context fields, object extent, ownership rules, or layout details are established.

## Behavior

### Delegation precedes classification

The function initializes its local 32-bit candidate from the fourth input, then calls F-c9f1dc723c52 exactly once.

The local candidate is both initialized input to and potential output from the dependency. Its value after the call is used for every subsequent numeric decision. There is no visible requirement that the dependency modify it, and no visible check that a modification occurred.

If the dependency returns zero, the function returns zero immediately. The candidate’s resulting value does not affect this outcome, and no context-field read is performed by the visible function body.

If the dependency returns nonzero, the function proceeds to context-field classification.

### Classification uses reads made after the dependency returns

The first 16-bit context-field read occurs only after a nonzero dependency result.

If that read equals 3, the function selects the type-3 rule. It does not perform the second context-field read, regardless of whether the candidate is accepted.

If the first read is not 3, the function performs a second 16-bit read from the same field address:

- A second read equal to 8 selects the type-8 rule.
- Any other second-read value selects the remaining-types rule.

The supplied representation contains two distinct field-read expressions on the path where the first comparison fails. The contract must not replace this with an unconditional assumption of one immutable field value.

Under a stable-field assumption, the branch mapping simplifies to:

| Field value | Selected rule |
|---|---|
| 3 | Type-3 rule |
| 8 | Type-8 rule |
| Any other 16-bit value | Remaining-types rule |

If the field changes between the reads, branch selection instead follows the ordered observations above. For example, a first read of 8 followed by a second read of 3 selects the remaining-types rule, not the type-3 rule. This describes the supplied read structure; it does not establish a synchronization or concurrency guarantee.

### Type-3 rule

The type-3 rule uses a 32-bit unsigned subtraction and comparison. Its effect over the full 32-bit candidate domain is:

- Reject candidates from `0x00000FF8` through `0x00000FFF`, inclusive.
- Accept every other candidate unchanged.

Rejection produces zero. Acceptance returns the complete 32-bit candidate.

The subtraction is modulo \(2^{32}\). Consequently, candidates below `0x00000FF8` are accepted: their wrapped subtraction results exceed 7. Treating the subtraction as signed arithmetic or as unbounded mathematical subtraction would give an incorrect contract.

The excluded interval contains exactly eight values.

### Type-8 rule

The type-8 rule first considers only the candidate’s low 28 bits. The upper four bits do not affect either acceptance or the returned value.

- If the low 28 bits equal `0x0FFFFFFF`, the function returns zero.
- Otherwise, the function returns those low 28 bits as a 32-bit unsigned value.

Thus, the accepted result is always between `0x00000000` and `0x0FFFFFFE`, inclusive.

Exactly sixteen distinct 32-bit candidate patterns have all low 28 bits set and are rejected, one for each possible upper nibble. For example, `0x0FFFFFFF`, `0x1FFFFFFF`, and `0xFFFFFFFF` are all rejected.

Other candidates with different upper nibbles can produce identical results. This information loss is explicit behavior, not an inferred decoding convention.

### Remaining-types rule

The remaining-types rule also uses a 32-bit unsigned subtraction and comparison. Its effect is:

- Reject candidates from `0x0000FFF7` through `0x0000FFFF`, inclusive.
- Accept every other candidate unchanged.

The excluded interval contains exactly nine values.

Candidates below `0x0000FFF7` are accepted because subtraction wraps modulo \(2^{32}\). Candidates above `0x0000FFFF` are also accepted.

### No retry or secondary classification

Once a rule is selected, rejecting its candidate leads directly to a zero return. The function does not retry the dependency, try another rule, reread the candidate from caller storage, or report a separate rejection reason.
