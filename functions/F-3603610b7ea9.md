# F-3603610b7ea9

## Purpose

F-3603610b7ea9 conditionally dispatches an input record to a type-specific dependency, then ordinarily performs shared record processing and returns that processing result.

Dispatch requires three conditions: a status dependency succeeds, its output has a nonzero low-order byte, and an identifier obtained from the record matches a global identifier. Passing this gate also triggers two indirect calls before type selection.

Some selected handlers have exceptional completion rules. Five handlers trigger a cleanup/termination sequence when their result is zero. One other handler triggers that sequence when a fresh identifier lookup returns zero, regardless of the handler result.

The supplied static representation establishes these control-flow distinctions. It does not establish application-level meanings for the record, the type codes, the status values, or the indirect operations.

## Interface

### Inputs

The function accepts two arguments:

| Argument | Established representation | Direct use |
|---|---|---|
| Context | Opaque 32-bit value | Forwarded unchanged to a selected handler and to shared final processing. |
| Record | Pointer to storage addressed in 32-bit units | Read directly, passed to dependencies, and potentially passed to an exceptional cleanup dependency. |

The record has at least the following directly accessed fields:

| Byte offset | Width | Interpretation in this function |
|---|---:|---|
| 0 | 32 bits | Opaque value supplied to the conditional shared-record operation. |
| 16 | 16 bits | Type field, interpreted both as signed and unsigned at different stages. |

The initial type read treats the field as a signed 16-bit value and retains that value for a later equality comparison and dependency argument. If dispatch is enabled, a second read treats the same field as an unsigned 16-bit selector.

No record length, alignment requirement, byte order, or broader record layout is supplied. Valid execution requires readable storage for the direct accesses and whatever additional storage the dependencies require.

### Output

The declared result is a 32-bit integer.

On an ordinary path where the record pointer is non-null, the returned value is the result of F-79a086cb6f01. It is not directly the selected handler’s result.

A handler result instead becomes an argument to conditional shared processing. When no handler runs, that argument remains 4.

The representation also contains guarded returns for null record pointers:

- An exceptional path associated with selector 0x0C can return 62.
- Exceptional paths associated with selectors 0x10, 0x1A, 0x3E, 0x40, and 0x42 can return 0.
- If shared final processing is skipped because the record pointer is null, the function returns the retained status: the result of F-c4c0ca1daaf5 on a gate-rejected path, or 62 after the gate has passed.

These are structural branches, not a supported null-input contract. The record is dereferenced before any null check. Consequently, no defined null-input result is established.

## Behavior

### Entry observations and dispatch gate

The function first reads and retains the signed 16-bit type at record byte offset 16. This read precedes all dependency calls.

It initializes:

- A private 32-bit status-output slot to zero.
- A processing-result value to 4.

It then performs the following ordered operations:

1. Calls F-5f5f14cedda3 with the record and retains its integer result.
2. Calls F-c4c0ca1daaf5 with the address of the private status-output slot.
3. Tests the result of F-c4c0ca1daaf5.
4. If that result is zero, tests the low-order eight bits of the status-output slot.
5. Only if those bits are nonzero, reads the 32-bit identifier at byte offset 0x2C from a globally referenced state object and compares it with the retained result of F-5f5f14cedda3.

Dispatch is enabled only if all three tests pass.

The short-circuit order is observable. A nonzero result from F-c4c0ca1daaf5 prevents the output-byte test and global-identifier comparison. A zero output byte prevents the global-identifier comparison.

The identifier from F-5f5f14cedda3 is not refreshed after F-c4c0ca1daaf5. Conversely, the global comparison value is read after that dependency has returned. No assumption is made that either dependency preserves global state.

Failure of any gate condition skips both indirect operations and all type-specific handlers. It does not skip ordinary shared final processing.

### Gate-enabled preliminary operations

When dispatch is enabled, the function:

1. Rereads the record’s type field as an unsigned 16-bit selector.
2. Sets a retained return-status value to 62.
3. Calls F-15643c36365d to obtain an object pointer.
4. Reads that object’s leading dispatch-table pointer and invokes the entry at table byte offset 0x34. The visible argument list contains the object pointer and a 32-bit value read through a global pointer.
5. Calls F-15643c36365d again.
6. Reads the newly obtained object’s leading dispatch-table pointer and invokes the entry at table byte offset 0x38. The supplied representation shows no explicit arguments for this call.
7. Selects a handler using the previously captured unsigned selector.

The two object lookups are distinct. The second must not be treated as a reuse of the first object. The argument value read through the global pointer for the first indirect call must not be assumed stable across preceding calls.

Neither indirect call’s result is used by this function. Their side effects remain observable.

The selector is captured before both indirect calls. Any subsequent modification of the record’s type does not change which handler is selected during this invocation.

### Exceptional completion

For selectors 0x10, 0x1A, 0x3E, 0x40, and 0x42, a handler result of zero activates exceptional completion. Any nonzero result, including a negative 32-bit integer, proceeds to shared processing.

For selector 0x0C, the function calls F-5f5f14cedda3 again after the handler returns. Exceptional completion depends on this new identifier result being zero, not on the handler result and not on the identifier retained for the dispatch gate.

When exceptional completion is activated with a non-null record:

1. F-09ba55c206ac is called with the record.
2. F-feee9156a257 is called.

The supplied representation marks the second dependency as non-returning. Under that annotation, this path does not reach shared final processing and has no normal return value.

The annotation does not establish whether the dependency terminates a process, transfers control, raises an exception, or uses another mechanism. The behavior if it unexpectedly returns is not specified here.

### Shared processing and return

Ordinary paths converge on shared processing.

For a non-null record, the function rereads the type field as signed 16 bits and compares it with the signed type retained at entry.

If they are equal, it calls F-09b5d9827724 with nine ordered arguments:

| Position | Value |
|---:|---|
| 1 | Record pointer |
| 2 | Current 32-bit value at record byte offset 0 |
| 3 | 0 |
| 4 | 4 |
| 5 | 1 |
| 6 | Processing-result value: selected handler result, or 4 |
| 7 | Signed 16-bit type retained at entry |
| 8 | 0 |

The first record word is read at this stage, after the type comparison and after any handler and preliminary indirect calls. It is not an entry snapshot.

If the current type differs from the entry type, this dependency is skipped. The check compares only the two observed values; a temporary type change that is reversed before this comparison is not detected.

After the conditional call, the function calls F-79a086cb6f01 with the original context, the record, and zero. This happens whether or not the type matched. Its integer result is returned.

A return value from F-09b5d9827724 does not affect the visible control flow or returned result.

## Side effects

The direct body writes private working storage but shows no direct assignment to record fields or global state. Record and global mutations may nevertheless occur through any dependency or indirect call.

Observable ordering matters:

- The entry type is read before either initial dependency.
- The global identifier is read only after the preceding gate tests succeed.
- The dispatch selector is read before the preliminary indirect calls.
- Handler selection uses that captured selector.
- The final type comparison and conditional first-word read occur after ordinary handler completion.
- F-79a086cb6f01 occurs after F-09b5d9827724 when the latter is called.

The function performs no visible allocation and no explicit memory copy. Its private status-output slot is passed by address to F-c4c0ca1daaf5; the body does not otherwise expose that address.

Ownership is not established. In particular:

- F-09ba55c206ac must not be described as freeing the record without its own contract.
- F-09b5d9827724 and F-79a086cb6f01 may modify, consume, retain, or release objects; this body alone does not resolve those possibilities.
- Objects returned by F-15643c36365d are used without a visible retain or release operation.
- Any dependency that returns to a later direct record read must leave that read valid for defined execution.

No rollback, retry, or independent error-reporting operation is visible.

## Acceptance examples

These examples are conditional behavioral criteria, not executed tests. They assume valid storage and returning dependencies except where exceptional completion is specified.

1. **Gate dependency reports failure.**  
   If F-c4c0ca1daaf5 returns a nonzero integer, no preliminary indirect call or type handler occurs. If the final type equals the entry type, F-09b5d9827724 receives processing result 4. F-79a086cb6f01 then determines the returned value.

2. **Output slot has only higher bits set.**  
   If F-c4c0ca1daaf5 returns zero and its output is 0x00000100, dispatch remains disabled because the low-order byte is zero. This is not a full-width nonzero test.

3. **Unsigned selector outside the table.**  
   If the gate passes and the selector is 0xFFFF, both preliminary indirect calls occur, but no handler runs. If the final type bits remain 0xFFFF, the equality test succeeds and the retained signed type represents −1.

4. **Selector changes during preliminary calls.**  
   If the captured selector is 0x02 and an indirect dependency changes the record type to 0x04, F-09823da3d75e remains the selected handler. If the final type still differs from the entry type, F-09b5d9827724 is skipped, but F-79a086cb6f01 still runs.

5. **Ordinary handler returns zero.**  
   For selector 0x04, a zero handler result does not activate exceptional completion. With an unchanged type, zero is forwarded as argument six to F-09b5d9827724.

6. **Zero-sensitive handler returns zero.**  
   For selector 0x10, a zero result activates F-09ba55c206ac followed by F-feee9156a257. Under the non-returning annotation, neither shared-processing dependency is subsequently called.

7. **Selector 0x0C uses a fresh identifier.**  
   A nonzero handler result does not prevent exceptional completion if the subsequent F-5f5f14cedda3 result is zero. Conversely, a zero handler result alone does not activate exceptional completion if that fresh identifier is nonzero.

8. **Final result differs from handler result.**  
   If an ordinary handler returns 9 and F-79a086cb6f01 returns −3, the function returns −3. The value 9 is available to conditional shared processing but is not the direct return result.

## Uncertainties

The following are **documented_only**:

- Application meanings of the context, record, selectors, identifiers, and numeric status values.
- Record size, alignment, byte order, and fields beyond the two directly accessed offsets.
- Exact dependency parameter declarations and integer promotion conventions at opaque call boundaries.
- Internal behavior, global mutations, ownership effects, and failure modes of all dependencies.
- Implicit calling-convention details of the indirect calls, especially the entry with no explicit arguments.
- The actual non-return mechanism of F-feee9156a257.
- Behavior following invalid pointers, inaccessible globals, invalid dispatch tables, or dependencies that invalidate subsequently accessed storage.
- Concurrency guarantees and synchronization. No protection against concurrent changes is shown.

A plausible intent is gated message dispatch followed by common completion processing. That interpretation is inferred, not an established semantic label. Likewise, the exceptional sequence may represent disposal and control transfer, but ownership release is not proven.
