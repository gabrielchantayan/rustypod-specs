# F-91678318bed2

## Purpose

F-91678318bed2 selects one of three addresses from a caller-provided descriptor and returns the 32-bit value stored at the selected address.

Selection uses address ordering, not the values stored at those addresses. The function does not compare the three possible return values.

When the second descriptor address is no greater than the third, the selection is consistent with clamping the first address to that interval and then reading the selected location. That is an inferred interpretation, not a validated descriptor invariant. The function does not check that the two apparent bounds are ordered, and its behavior for reversed bounds remains defined by the branch rules below.

## Behavior

### Address selection

The established selection rules are:

| Relationship between compared addresses | Selected address |
|---|---|
| Primary address is less than the second address | Second address |
| Second address is no greater than the primary address, and the third address is less than the primary address | Third address |
| Second address is no greater than the primary address, and the third address is no less than the primary address | Primary address |

The second comparison is conditional. When the primary address is less than the second address, the third address has no effect on the result and is not read from the descriptor.

Equality is significant:

- Equality between the primary and second addresses enters the branch that examines the third address.
- Equality between the primary and third addresses selects the primary address, provided that branch is reached.
- There is no direct comparison between the second and third addresses.

After selection, the function reads one four-byte value from the selected address and returns it unchanged.

### Logical access order

The supplied representation establishes the following source-level evaluation order:

1. Read the descriptor entry at offset 0 and retain that primary address.
2. Read the descriptor entry at offset 4 for comparison with the retained primary address.
3. Depending on that comparison:
   - If the primary address is less than the second address, evaluate the offset-4 descriptor entry again as the address of the return-value read.
   - Otherwise, read the offset-8 descriptor entry for comparison with the retained primary address.
4. If the third address is less than the primary address, evaluate the offset-8 descriptor entry again as the address of the return-value read. Otherwise, use the retained primary address.
5. Read the selected four-byte value and return it.

Thus, the primary descriptor entry is captured once in the supplied representation. The second or third entry can appear both in a comparison and in the later expression that identifies the data address.

This is a source-level access account, not a verified machine-load trace. The supplied material does not establish whether an implementation reuses a previously loaded descriptor entry, performs another physical load, or otherwise transforms ordinary non-volatile accesses. Exact behavior for concurrently changing, volatile, or device-backed descriptor storage is therefore not established.

For a stable descriptor in ordinary readable memory, repeated evaluations of an entry identify the same address.

### Ordered-bound interpretation

If the second address is no greater than the third address, the behavior has the following interpretation:

- A primary address below the interval selects the second address.
- A primary address inside the interval, including its endpoints, selects the primary address.
- A primary address above the interval selects the third address.

This interpretation concerns addresses only. It does not constrain the numerical ordering of the stored 32-bit values.

The endpoint addresses are themselves potentially dereferenced. Nothing establishes that the third address is an exclusive endpoint or a one-past-the-end pointer. A caller using it as such risks an invalid read when that address is selected.

### Reversed bounds

The function does not normalize or reject a descriptor whose second address is greater than its third address.

For stable entries with that ordering:

- If the primary address is below the second address, the function selects the second address without examining the third entry.
- If the primary address is equal to or above the second address, the third address is necessarily below the primary address under a consistent total address order, so the function selects the third address.

Consequently, reversed bounds do not behave like an automatically repaired interval. In particular, a primary address lying between the third and second addresses selects the second address.

### Equality at the second address

Suppose the primary and second addresses are both `0x2000`, and the third address is `0x3000`. The function examines the third entry, selects the primary address, and returns the value at `0x2000`.

Equality does not take the branch that skips the third-entry comparison.

### Equality at the third address

Suppose the primary and third addresses are both `0x3000`, and the second address is `0x2000`. The strict third-address comparison is false. The function selects the retained primary address and returns the value at `0x3000`.

### Reversed bounds

Suppose the second address is `0x3000` and the third address is `0x1000`.

- With primary address `0x2000`, the selected address is `0x3000`; the third entry is not examined.
- With primary address `0x3000`, the selected address is `0x1000`.

### Invalid unselected storage

Conversely, if the selected address is invalid, the contract provides no successful-return guarantee and no defined error value.
