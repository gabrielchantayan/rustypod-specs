# F-583f9e655cae

## Purpose

F-583f9e655cae writes a requested 32-bit value into an owner object and conditionally dispatches an update through a separately obtained context.

The update has two modes:

- **Absolute:** dispatch the requested value.
- **Relative:** dispatch the low 32 bits of the requested value minus a value read from the owner.

Relative mode requires a successful external-value comparison, a nonzero associated-object lookup, and an unsigned bound check. Otherwise, the function selects absolute mode.

A zero relative update is suppressed. An absolute update is dispatched even when its value is zero. The owner write occurs in either case, provided execution reaches that write.

“Position,” “absolute,” “relative,” “preparation,” and “completion” describe apparent roles. The evidence does not establish a unit of measurement or subsystem meaning. The owner write is an observable action, not a guarantee about the field’s value after subsequent dependencies execute.

## Interface

### Inputs and result

The supplied representation uses 32-bit integers and 32-bit address-bearing values.

| Input | Contract |
|---|---|
| Owner address | Identifies storage accessed at byte offsets +0x18 and +0x2c. Required storage and dependency accesses must be valid on the executed path. |
| Requested position | A 32-bit value. Its bits are written to owner +0x2c without a visible range check. |

The function returns a 32-bit integer:

| Path | Result on normal completion |
|---|---|
| Relative mode with zero difference | 0 |
| Context flag bit 0 set | 1 |
| Context flag bit 0 clear, preparation returns zero | 0 |
| Context flag bit 0 clear, preparation returns nonzero | Result of the mode-selected completion dependency |

These results have route-specific meanings. The body does not establish a universal success/failure interpretation.

### Relevant storage

All offsets are in bytes.

| Base | Offset | Observed use |
|---|---:|---|
| Owner | +0x18 | The address of this location is passed to F-e38e6836b640. |
| Owner | +0x2c | A 32-bit field read during mode selection and later written with the requested position. |
| Context | +0x5f8 | A byte read twice when dispatch is required; bit 0 of the second read selects the route. |
| Context | +0x38 | Address supplied to the set-bit route’s update and final dependency. |
| Context | +0x330 | Address supplied to the clear-bit route’s preparation, completion, and final dependency. |
| Associated object | +0x00 | A 32-bit pointer to an indirect dispatch table. |
| Dispatch table | +0x110 | Callable slot used to obtain a 32-bit bound. |

Owner +0x18 is passed as an address; the body does not first load a pointer from that location.

F-50264aad3dd0 supplies the context address. No explicit validity check precedes its use on a dispatching path. A suppressed relative update does not access context fields after obtaining that address.

The associated object returned by the **second** lookup must support the table-pointer read and indirect call. A nonzero first lookup result does not establish that the second result is nonzero, valid, or equal to the first.

### Widths and arithmetic

The owner field, requested position, external comparison value, bound, update value, preparation output slot, and function result are represented as 32-bit quantities.

The initial equality comparison checks equality of the 32-bit values. The bound comparison is explicitly **unsigned and strictly less-than**.

The relative update is:

**(requested position − subtraction-time owner field) modulo 2³²**

There is no visible saturation, underflow rejection, or requirement that the requested position be at least the saved position. The bound check concerns a value read from the owner, not the requested position.

The mode argument has the logical value true for absolute mode and false for relative mode. Its physical calling-convention width is not independently established.

## Behavior

### Initial dependency calls

The function first calls F-50264aad3dd0 and retains its returned context address.

It next calls D-001, an opaque document-local identifier for the external query not mapped by the supplied dependency map.

Both calls precede mode selection, the owner write, and any zero-relative suppression. Suppression therefore does not eliminate these calls or their possible side effects.

### Mode selection and owner reads

Absolute mode is the fallback.

The function compares D-001’s result with a 32-bit read from owner +0x2c.

- If they differ, mode selection ends in absolute mode.
- If they match, F-e38e6836b640 is called with owner +0x18.
- If that lookup returns zero, mode selection ends in absolute mode.
- Otherwise, F-e38e6836b640 is called a second time with owner +0x18.

The second lookup result supplies the object used for indirect dispatch. The function reads that object’s table pointer, obtains the callable slot at table +0x110, and calls it. D-002 denotes this indirect dependency.

After D-002 returns, the function reads owner +0x2c again and compares that value with D-002’s result as unsigned 32-bit quantities.

- If the owner value is not strictly less than the bound, absolute mode is selected.
- If it is strictly less, relative mode is selected. A further read from owner +0x2c supplies the subtrahend used to calculate the relative update.

In absolute mode, the selected update value is the requested position.

These accesses must not be treated as one immutable snapshot. In particular:

- D-001 may affect the field before the initial comparison read.
- Either lookup or D-002 may affect owner state before the bound comparison.
- The bound-comparison read and subtraction read are distinct accesses.
- The two lookups need not return the same object.

No visible dependency guarantee permits collapsing these operations. Differences between adjacent reads without an intervening dependency would require an applicable memory model or another source of state change; neither is established here.

### Dispatch decision and owner write

Dispatch is required if the mode is absolute or the relative update is nonzero.

After determining that condition, the function writes the requested position to owner +0x2c. This write occurs:

- After all mode-selection dependency calls reached on the path;
- After the reads used to choose the mode and update value;
- Before either context-flag read;
- Before any route-specific dependency call.

For a zero relative update, the function returns 0 after the write. It performs no context-flag read and no route-specific call.

For all other updates, execution continues to route selection.

The function performs no explicit rollback of this write. It also does not restore the requested value after later dependencies execute. Consequently, the final field value depends on dependency side effects and any applicable aliasing or external mutation.

### Route selection

When dispatch is required, the function reads the byte at context +0x5f8 twice.

The first read is widened into 32-bit local storage. Its value is not used to choose the route or supplied as an argument to a visible dependency. The second read determines the branch:

- Bit 0 set: use the route based at context +0x38.
- Bit 0 clear: use the route based at context +0x330.

Other bits do not affect the visible decision.

The first and second values need not be assumed equal. The evidence does not establish why both reads occur or their significance under the actual memory model.

Because the owner write occurs first, any aliasing between that write and context storage can affect what these later reads observe.

### Set-bit route

When bit 0 of the second flag read is set, calls occur in this order:

1. F-b7cd573c0b4c, with no explicit arguments shown.
2. F-5ac85e6e59cd, receiving context +0x38, the mode indicator, and the selected 32-bit update.
3. F-d49b39475920, receiving context +0x38.

After these calls return normally, the function returns 1.

No dependency result is inspected on this route. The fixed return value does not establish that the requested operation succeeded inside those dependencies.

### Clear-bit route

When bit 0 of the second flag read is clear, calls and local-state changes occur in this order:

1. F-b7cd573c0b4c is called with no explicit arguments shown.
2. A local 32-bit output slot is initialized to zero.
3. F-1481c91e1611 receives context +0x330, the mode indicator, the selected update, and the output slot’s address.

The provisional function result is zero.

If preparation returns zero, neither completion dependency is called.

If preparation returns nonzero:

- **Absolute mode:** F-7dfd5a3f7778 receives context +0x330, the current 32-bit output-slot value, and the constant 1.
- **Relative mode:** F-b5fab2ae7f9c receives context +0x330 and the previously selected relative update.

The selected completion dependency’s result becomes the function result. Relative completion does not use the output slot as its update argument.

F-d49b39475920 is then called with context +0x330, including when preparation returned zero. Its result is not used. After it returns normally, the selected function result is returned.

The preparation slot is initialized after F-b7cd573c0b4c returns. If preparation returns nonzero without changing the slot, absolute completion receives zero.

## Side effects

### Directly established effects

The function directly performs:

- The path-dependent owner reads described above.
- One write of the requested position to owner +0x2c on every normally completing path.
- Two context-flag byte reads on dispatching paths.
- Associated-object and dispatch-table reads when eligibility checking reaches them.
- Initialization of a local 32-bit slot before passing its address to preparation.

No explicit allocation, deallocation, or ownership transfer appears in the body.

### Dependency effects and ownership limits

Dependencies may modify owner fields, context fields, global state, aliased storage, or object lifetimes. Their preservation and ownership behavior are not established.

The local output address is supplied to F-1481c91e1611. The visible caller subsequently reads that slot only for absolute completion. The body provides no lifetime extension for a retained pointer and no evidence establishing whether retention occurs.

F-b7cd573c0b4c and F-d49b39475920 form an apparent bracket around route-specific work. Treating them as locking, acquisition/release, or transaction operations is inferred intent only. The former has no explicit argument shown; the latter receives a route-specific address.

### Errors and abnormal completion

There is no visible validation, retry, exception handling, or error translation.

A zero preparation result suppresses completion but does not trigger an explicit reversal of the earlier owner write. A zero completion result is returned without an explicit rollback.

Neither statement guarantees the final owner value: preparation, completion, and the final dependency may themselves modify it.

The final dependency is called only after the preceding operations return normally. No cleanup guarantee is established for faults, invalid references, or abnormal dependency termination.

## Acceptance examples

These are conditional static predictions, not executed tests. Unless otherwise specified, all required accesses are valid, dependencies return normally, and relevant owner values remain stable during selection. This stability condition does **not** extend through later dispatch dependencies.

1. **Initial mismatch.**  
   Owner field 10, D-001 result 9, request 12: absolute mode selects 12. No associated-object lookup occurs. The function writes 12 before flag reads and dispatch.

2. **Empty first lookup.**  
   D-001 matches the owner field, but the first lookup returns zero: absolute mode is selected. There is no second lookup or bound call.

3. **Relative update.**  
   Owner field and D-001 both equal 10; lookups provide valid results; bound is 100; request is 15: relative mode selects 5. The function writes 15 before route-specific work.

4. **Suppressed relative zero.**  
   With owner field 10, matching D-001, successful lookups, bound 100, and request 10, the function writes 10 and returns 0. It performs no context-flag read or route-specific call.

5. **Absolute zero still dispatches.**  
   If the initial comparison fails and the request is zero, absolute mode selects zero. The function writes zero before the flag reads and executes the selected route.

6. **Bound equality fails eligibility.**  
   Owner field 100 and bound 100 do not satisfy strict unsigned less-than. Absolute mode is selected, even when the request also equals 100.

7. **Unsigned interpretation matters.**  
   Owner field 0xffffffff is not less than bound 0x7fffffff. This comparison cannot select relative mode.

8. **Decreasing request wraps.**  
   Owner field 10, matching D-001, valid lookups, bound 100, and request 7 select relative update 0xfffffffd. No clamp or underflow rejection occurs.

9. **Request need not be below the bound.**  
   Owner field 10 and bound 100 can qualify for relative mode with request 200. The update is 190.

10. **Preparation returns zero.**  
    On the clear-bit route, preparation returning zero skips both completion dependencies. The final dependency still executes on normal control flow, and the function returns 0. The function performs no explicit rollback of its earlier write; the final field value depends on dependency side effects.

11. **Completion input depends on mode.**  
    If preparation returns nonzero and writes 42 to the output slot, absolute completion receives 42 and constant 1. Relative completion instead receives the selected difference, not 42.

12. **Unchanged preparation output.**  
    If absolute-mode preparation returns nonzero without modifying its output slot, absolute completion receives zero and constant 1.

13. **Second flag read controls routing.**  
    If the first flag read has bit 0 clear but the second has it set, the set-bit route executes. Assuming normal returns, the function returns 1 regardless of the update dependency’s result.

14. **Later mutation is not undone.**  
    Suppose the function writes request 12 and a later route dependency changes owner +0x2c to 99. If no subsequent actor changes it again, it remains 99 on return. The function does not perform a final write restoring 12.
