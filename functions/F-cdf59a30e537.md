# F-cdf59a30e537

## Purpose

F-cdf59a30e537 performs an ordered sequence of indirect calls, transforms dependency-produced words into arguments and address-like values, mutates shared memory through mixed-width accesses, and invokes an unresolved final continuation.

**Established static evidence:** the visible interface has no explicit parameters and no explicit return value. Observable behavior includes dependency invocations, shared-global reads, direct memory reads and writes, and the final invocation. No application-level purpose is established.

**[INFERENCE]** The masks, shifts, and recurring offsets suggest manipulation of packed state. They do not establish a decoder, formatter, allocator, or object constructor. Constants that also represent characters do not establish textual output.

This contract describes the supplied static representation. It does not guarantee successful execution, valid memory mappings, or preservation of unrelated state.

### Arithmetic boundaries

Arithmetic deductions below use a **conditional 32-bit machine-bitvector interpretation**. Under that interpretation, word shifts, multiplication, and address arithmetic retain only the low 32 bits where applicable.

Consequences include:

- A left shift by 8 discards the original high byte.
- A subsequent logical right shift by 8 recovers only the original low 24 bits.
- Two successive 28-bit left shifts produce zero.
- A word shifted left by 16 has zero low 16 bits.
- Masking before shifting is not generally equivalent to masking afterward.

One later extraction masks a previously 16-bit-left-shifted word with `0xFFFF` and shifts right by 5. Under this interpretation, that extraction is zero.

These deductions do not establish portable semantics for signed overflowing multiplication, signed left shifts, pointer conversion, or address wrapping.

### Entry into direct memory mutation

Near the end of ordinary dependency processing, the function derives:

- A base from a word shifted left by 25.
- Another base from a returned word multiplied by `0x02000000`.
- A small index from a returned word shifted left by 8, masked with `0x7FFF`, then shifted right by 6.

Under 32-bit bitvector arithmetic, the small index ranges from 0 through 508 in multiples of four. Twice that index ranges from 0 through 1016 in multiples of eight. Neither range establishes valid memory.

After the last ordinary dependency call, the opening access order is:

1. A 32-bit store at the final paired result’s high-word-derived base plus `0x14`.
2. A byte store at the 25-bit-shift-derived base plus `9`.
3. A 32-bit store at the final low result word multiplied by `0x100`, plus `0x54`.
4. Another byte store at the same `+9` location.
5. A zero word store at the large scaled base plus `0x14`.

The two byte writes have different sources and an intervening word store. Their behavior is not described adequately by the last byte value alone.

The function subsequently clears a field relative to twice the small index, propagates the explicitly read byte into a 32-bit field, and reloads the large base’s `+0x14` word.

That reloaded word is necessarily zero only if intervening accesses neither alias nor otherwise change the cleared field. The loaded word later supplies an address base; a zero value therefore does not cause an early exit.

After capturing that base, the function assigns `0x20` to the fixed word associated with `0x60`. If that write or a subsequent store aliases the global’s storage, it does not by itself replace the already captured base. No second read of this global is visible.

## Acceptance examples

These are conditional static criteria, not executed tests.

### Word truncation

For dependency word `0x12345678`, a 32-bit left shift by 8 produces `0x34567800`. A subsequent logical right shift by 8 produces `0x00345678`.

Acceptance requires preserving the lost high byte rather than reconstructing the original word.

### Mask-before-shift

For low result word `0xAB123456`, masking to 24 bits and shifting left by 6 produces `0x048D1580` under 32-bit arithmetic.

The original high byte must not contribute.

### Explicit byte propagation

If an explicit unsigned byte dereference returns `0xE7`, propagation into a word field writes `0x000000E7`, assuming the accesses succeed.

This criterion does not establish the width of the separate global at `0x05`.

### Unresolved global source width

If an independently supplied declaration establishes an unsigned 8-bit source for the global at `0x05`, its converted base lies in 0–255.

If instead a compatible declaration establishes a wider source holding `0x1234`, the visible unsigned conversion does not itself reduce that value to `0x34`. Acceptance must not impose byte truncation merely from the global’s address.

### Late shared-state selection

Suppose the global at `0x087FBBBC` initially contains one base, but an earlier dependency or aliasing store changes it to another base before the late read.

The repeated `+0x19` and `+0x34` stores must use the value obtained after the final adjusted-base `+0x20` store and before the fixed `0x60` store—not the entry value.

### Captured base reuse

If a later store changes the source global after that read, subsequent shared-state-relative stores still use the captured base, unless execution or the applicable machine model introduces behavior not established here.

An implementation that rereads the global for every repeated group is not equivalent to the visible representation.

### Intermediate writes and aliasing

An access observer must retain the adjusted `+0x20` sequence `0x20`, `0x2F`, byte-derived word, `0x20`, followed by the shared-global read.

Likewise, clearing a word does not justify replacing a later read with zero if an intervening access aliases that word. Its numeric value depends on the actual memory effects and endianness.

### Failure without rollback

If an access fails after earlier stores complete, acceptance must not promise restoration or an explicit returned error code.
