# F-1edad5c79020

## Purpose

F-1edad5c79020 constructs three words of a four-word working record, initializes four auxiliary working locations, and invokes F-438f882ca850 with two adjusted address-like values and two working-storage pointers. If that dependency returns normally, it updates a caller-associated 32-bit word using a signed 16-bit increment read from stack storage **after the return**.

Record construction depends on an incoming condition flag, a 32-bit selector, a reference word, and arithmetic inputs. One branch additionally reads two signed 16-bit fields from an input object.

This contract describes the supplied fragment, not a verified standalone calling convention. The fragment consumes state beyond its four displayed arguments. Supplying only those four arguments does not establish all required inputs.

The arithmetic and storage relationships are established static behavior. Domain interpretations—such as coordinates, bounds, or drawing parameters—are not established.

## Behavior

### Arithmetic widths

The displayed arithmetic uses 32-bit integer values. Each object field and the post-return increment is read as a signed 16-bit value and sign-extended before participating in 32-bit arithmetic.

The representation does not establish behavior for signed arithmetic overflow. The formulas below apply without that ambiguity when their intermediate and final results are representable. Address adjustment has a separate validity qualification under **Uncertainties**.

### Initial record write

Before selecting and constructing the branch-dependent words, the fragment:

- Reads the record’s existing second word.
- Adds the arithmetic addend.
- Writes the result to the fourth record word.

The second word is not assigned by this operation. It must not be treated as zero-initialized or newly produced.

This fourth-word write precedes the reference and object-field reads in the selected branch. If working storage aliases other readable state, that ordering can affect subsequent observations.

### Branch selection

The special branch is selected exactly when:

- The incoming zero-condition flag is set; and
- The branch selector equals zero.

The condition short-circuits: with a clear incoming flag, the selector comparison is not required to choose the general branch. The general branch nevertheless reads the selector for arithmetic use.

The incoming flag’s relationship to any explicit argument is unknown.

### Special branch

The special branch performs these record operations:

1. It samples the reference word and reads the signed 16-bit field at first-argument offset 82.
2. It subtracts the sign-extended field from that reference sample, adds the original second argument, and stores the result in the first record word.
3. It samples the reference word again and reads the signed 16-bit field at offset 84.
4. It adds the sign-extended field to this second sample and stores that intermediate result in the third record word.
5. It adds the original second argument to the third record word.

Thus the resulting values are:

- First word: first reference sample minus the signed field at offset 82, plus the original second argument.
- Third word: second reference sample plus the signed field at offset 84, plus the original second argument.

The two reference reads are distinct. Equal samples must not be assumed.

Within each expression combining a reference read and an object-field read, their relative evaluation order is not established. The first-word store precedes the reads used to form the third word.

### General branch

The general branch applies whenever the special-branch condition is false.

It:

1. Reads the reference word once.
2. Subtracts the third argument, adds the original second argument, and stores the result in the third record word.
3. Takes the selector as the final adjustment.
4. Copies the intermediate third-word value into the first record word.
5. Adds the selector to the third record word.

Consequently:

- First word: reference sample minus the third argument plus the original second argument.
- Third word: that intermediate value plus the selector.

Neither signed object field is read in this branch.

The intermediate third-word write precedes the first-word write, which precedes the final third-word adjustment. This is not an atomic record replacement.

### Auxiliary preparation and call

After record construction, four auxiliary 32-bit working locations are assigned in this order:

1. The value 255.
2. Zero.
3. The first auxiliary source value.
4. The second auxiliary source value.

The two auxiliary source values are read for their respective assignments. The fragment does not establish their domain meaning.

It then makes exactly one explicit call to F-438f882ca850 using the arguments described in **Interface**. It does not consume a dependency return value or test a success indicator.

### Post-return update

After normal return from F-438f882ca850, the fragment:

- Reads the current 32-bit update word.
- Reads the current signed 16-bit increment from its stack location.
- Sign-extends the increment, adds it to the update-word sample, and stores the result at the update-word address.

**Both reads occur after the call. Their relative evaluation order is not established.**

Neither operand may be substituted with an assumed entry-time value. In particular, if the dependency changes the increment’s stack location and returns normally, the final addition uses the value present when that location is read after return.

After the write, the function returns without a specified return value.
